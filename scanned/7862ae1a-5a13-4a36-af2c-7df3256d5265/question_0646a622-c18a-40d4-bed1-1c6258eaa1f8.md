set_state_init_data_entry appends a key/value pair to an in-flight DeterministicStateInit action identified by (promise_idx, action_index). Can action_index desynchronize from the actual position of the DeterministicStateInit action in the promise's action list (e.g. because a promise_batch_action_create_account or promise_batch_action_deploy_contract was interleaved beforehand, shifting indices) such that a data entry a contract intends for its own new account's initial state is instead appended to a different, earlier-created account's init action in the same batch, letting a third party's freshly created account inherit attacker-chosen state entries it never requested? Category: Transaction manipulation. Proof: integration test building a batch with create_account, deploy_contract, state_init, set_state_init_data_entry(action_index=N) in that order, asserting the data entry lands on the DeterministicStateInit action and none other, for several values of N including off-by-one.
