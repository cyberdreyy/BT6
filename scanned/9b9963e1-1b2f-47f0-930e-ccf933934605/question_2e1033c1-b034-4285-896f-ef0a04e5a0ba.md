Target: block_rejection_signer_addrs table and its index block_rejection_signer_addrs_on_block_signature_hash (CREATE_INDEXES_3) in signerdb.rs. Attacker action: as the attacker's own single signer slot is not usable to forge rejections from other signers, instead exploit a restart where this table's rows (tracking which signer addresses rejected a given signer_signature_hash) are dropped by a DROP_SCHEMA_x statement while the aggregate rejection COUNT used for threshold decisions (e.g. transitioning a block to GloballyRejected) is cached only implicitly via this table. Preconditions: a block at height H has accumulated N rejection addresses pre-restart, just below the threshold to flip it to GloballyRejected. Call sequence: restart -> DROP_SCHEMA drops and recreates block_rejection_signer_addrs empty -> the signer's local rejection tally for H resets to 0 -> gossip replay (if any) may or may not resupply all N prior rejections, and if not, the block never reaches GloballyRejected locally even though the network already rejected it. Equality broken: the aggregated rejection tally (and thus GloballyRejected transition) held before restart == the tally held after restart. Impact: Critical - the signer, no longer seeing the block as globally rejected, may treat a fresh (or resubmitted) copy of the same block as still eligible and sign it, contributing a valid signature toward finalizing a block the network already rejected. Proof idea: test that inserts N-1 rejection addr rows for a hash just under threshold, executes a DROP_SCHEMA-equivalent reset, reopens, and asserts the tally and resulting BlockState diverge from the pre-restart state, then drives the signer to sign.
