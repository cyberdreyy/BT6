Target: `Signer::check_submitted_block_proposal` and `submitted_block_proposal: Option<(Sha512Trunc256Sum, Instant)>` (v0/signer.rs). Attacker action: the miner sends a `BlockProposal` that is accepted for node validation, then immediately Bitcoin-forks (or floods with a competing tenure) so the corresponding `BlockValidationResponse` is for a *different* signer_signature_hash than the one recorded in `submitted_block_proposal`. Preconditions: `block_proposal_validation_timeout` configured normally; only one proposal in flight. Call sequence: `handle_block_proposal` sets `submitted_block_proposal = Some((h1, now))` -> attacker's fork makes the node validate a stale request whose response never carries `h1` -> `check_submitted_block_proposal` only clears `submitted_block_proposal` when the *timeout* elapses, but if `block_proposal_validation_timeout` is unreachably large relative to tenure length (operator misconfiguration triggered by attacker's proposal cadence) the field is never cleared. Wedge: while `submitted_block_proposal.is_some()`, new proposals for `h1`'s tenure are still accepted (no proposal gating on this field was found blocking further validation), but the specific rejected-timeout retry `check_submitted_block_proposal` logic never fires an explicit reject for `h1`, leaving it permanently `Unprocessed` in signerdb with no terminal state. Equality: every proposal that was submitted to validation == either has a `valid` field set or times out to a rejection before `block_proposal_validation_timeout` elapses; violated here because the miner never lets a validation response for `h1` arrive. Impact: High — bounded-time guarantee is broken for a single block, converting to permanent liveness loss for that specific proposal (not necessarily the whole tenure). Proof idea: Rust test setting `block_proposal_validation_timeout` to a real value, submitting a proposal, never delivering a `BlockValidationResponse` for its hash, advancing a mocked clock, and asserting `check_submitted_block_proposal` produces a terminal `BlockRejection`/state within the configured timeout.
