Target: `RunLoop::run_one_pass` reward-cycle gating and `ConfiguredSigner::RegisteredSigner`/`NoRegisteredSigners` states (runloop.rs). Attacker action: none miner-specific; but a miner can withhold producing any burn-chain-visible tenure-change activity right at a reward-cycle boundary so that `get_parsed_reward_set` / `get_signer_config` keeps returning `Ok(None)` (empty reward set) for the *new* cycle while the *old* cycle's `ConfiguredSigner` is torn down once `current_reward_cycle_info` advances. Preconditions: reward cycle boundary crossing, previously-registered signer, `self.state == State::NoRegisteredSigners`. Call sequence: `run_one_pass` sets state to `NoRegisteredSigners` and simply logs a warning every pass without any registered `Signer` instance to call `process_event` on, so any `BlockProposal` for the still-canonical prior tenure that straddles the boundary is dropped entirely by the runloop before reaching `Signer::handle_block_proposal`. Wedge: `running_signers` vec stays empty while a valid canonical block at the boundary height needs a decision == no `Signer` instance exists to reach any terminal state at all. Impact: High, temporary liveness loss (bounded by reward-set publication) but attacker-extendable by any signer-set-publication delay a miner can induce alongside their own slot's block withholding. Proof idea: stacks-signer test simulating `get_parsed_reward_set` returning `None` for several passes while pushing `BlockProposal` events, asserting no proposal is silently dropped forever once the reward set becomes available (i.e., it gets replayed/reconsidered), not just skipped.
