# Q3788: getURL embeds identifiers in a URL in entropy.ts

## Question
EmbeddedWalletApi.getURL appends caid and client_id as query parameters; can an attacker capture that URL through getEntropyDetailsFromUser (imported ? account : first eth ?? first solana) and learn identifiers that link a user across apps?

## Target
- File/function: [src/utils/entropy.ts](src/utils/entropy.ts) - getEntropyDetailsFromUser (imported ? account : first eth ?? first solana), getEntropyDetailsFromAccount (address as entropyId + <chain>-address-verifier)
- Entrypoint: provider construction for any embedded wallet
- Attacker controls: which linked account is passed as signingAccount, wallet_index ordering, imported flag
- Exploit idea: Read the generated URL in a context that logs or forwards URLs.
- Invariant to test: User-linkable identifiers must not travel in URLs generated by src/utils/entropy.ts.
- Expected Immunefi impact: Critical - retrieval of sensitive user data: session/identity/provider tokens, key-material handles, or entropy identifiers reach a party that must not hold them.
- Fast validation: Unit test: assert the URL from getEntropyDetailsFromUser (imported ? account : first eth ?? first solana) contains no user-linkable identifier.
