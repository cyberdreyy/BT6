Target: BlockInfo's Serialize/Deserialize round-trip via serde_json (used throughout signerdb.rs block_info column) versus signer_signature_hash() recomputation, specifically for a BlockInfo carrying a NakamotoBlockHeader with a miner_signature field. Attacker action: attacker submits a BlockProposal where two structurally different NakamotoBlockHeader encodings (e.g. differing only in a field the JSON serializer treats as optional-and-omitted-when-default) could serialize to the same JSON but represent different actual blocks. Preconditions: a signed BlockInfo for block A is stored; attacker later proposes block B whose header, if naively round-tripped through the same JSON shape, is indistinguishable from A's stored JSON in some field the signer's conflict-detection SQL (json_extract-based indexes like blocks_valid, blocks_state) inspects. Call sequence: restart -> block_lookup(A) -> serde_json::from_str reconstructs BlockInfo -> .signer_signature_hash() recomputed from the reconstructed block header. Equality: signer_signature_hash() computed on the restart-reconstructed BlockInfo.block == the signer_signature_hash() computed and signed pre-restart (this is literally the PRIMARY KEY of the blocks table, so any mismatch means block_lookup keyed by the pre-restart hash silently returns None). Impact: Critical - if any field is lost/normalized differently by serde_json's round-trip (e.g. an unrecognized-post-upgrade enum variant defaulting via #[serde(other)] or similar), the post-restart hash no longer matches the primary key used to store it, so get_signed_conflicts/block_lookup for the ORIGINAL hash the signer signed returns nothing, opening the door to signing a genuinely conflicting block B at the same height (UNIQUENESS violation). Proof idea: for every BlockInfo the test suite constructs (create_block, create_block_override), assert serde_json::from_str(&serde_json::to_string(&block_info).unwrap()).unwrap().block.header.signer_signature_hash() == block_info.block.header.signer_signature_hash() after passing through insert_block/block_lookup on a real SignerDb instance across a restart.
