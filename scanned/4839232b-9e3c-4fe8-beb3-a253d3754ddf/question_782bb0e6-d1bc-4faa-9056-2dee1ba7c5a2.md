Target: StakingContract::withdraw_all / StakingContract::unstake_all (staking-pool/src/lib.rs). Attacker action: delegator calls unstake_all() then immediately withdraw_all() in the same transaction batch before ping() has run for the new epoch. Preconditions: account.stake_shares>0, last_epoch_height==env::epoch_height(). Call sequence: unstake_all computes receive_amount from the current (possibly stale) share price since internal_ping() returns false when epoch hasn't changed, so total_staked_balance used for the price has not incorporated the latest validator rewards/slashing that nearcore already applied to env::account_locked_balance(). Binding that breaks: SOLVENCY - total_staked_balance == env::account_locked_balance() at the moment the price is computed; if the true locked balance already reflects a slashing event nearcore applied but internal_ping() hasn't run this epoch, receive_amount is computed against a stale, too-high total_staked_balance. Scoped impact: Critical - the unstaking delegator locks in a receive_amount larger than their true share of the pool's real assets, and once withdrawn this NEAR is drawn from other delegators' portions, since last_total_balance is never independently checked against real balance before this withdrawal. Proof idea: cargo test lowering context.locked_amount to simulate slashing without calling ping(), then calling unstake_all()/withdraw() and asserting sum of all get_account_total_balance() now exceeds env::account_balance()+env::account_locked_balance().
