[stacks-signer/src/signerdb.rs] target: `SignerDb::insert_block` (or equivalent block-state persistence function) called from `handle_block_proposal`/`handle_block_validate_response`. Attacker action: attacker crafts a `BlockProposal` whose serialized fields (e.g., an oversized memo/tx list) cause the underlying `rusqlite` write in `insert_block` to fail with a transient I/O error (e.g., simulated disk-full in the test harness) precisely at the moment the in-memory `BlockInfo.state` was already advanced to `LocallyAccepted`/signed, but the DB write recording that signature is what is failed and the error is swallowed/logged rather than propagated to abort the response. Preconditions: any valid proposal reaching the sign decision point. Call sequence: sign logic sets in-memory state -> `signerdb` write errors -> if the write failure is only logged (`warn!`) and not treated as fatal, then on process restart (or on the next `check_latest_block_in_tenure` read) the DB shows no record of this block, and the equivocation guard (one-signature-per-height) is not backed by a durable record. Equality/wedge: This closes on FAIL-CLOSED: the block treated as validated/signed in memory == the block actually durably recorded in signerdb; a failed write must never be silently treated as success. If it is, restart loses the guard and a second conflicting block at the same height could be signed post-restart (Critical safety), but absent restart it can also wedge future `check_pending_block_validations` lookups that expect the row to exist and instead loop retry-forever treating 'not found' as 'not yet decided'. Impact: Critical (equivocation-guard loss across restart) or High (loop-retry wedge) depending on path; name the wedge as the retry-forever branch. Proof idea: Rust test forcing `rusqlite` write to return `Err` from within `insert_block`, asserting the caller either propagates the error and refuses to send a `BlockResponse`, or — if it doesn't — that a restart-simulated fresh `SignerDb` handle can be queried to show the block missing while a `BlockResponse::Accepted` was already broadcast.]
