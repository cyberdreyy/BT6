# Q3783: getURL embeds identifiers in a URL in walletRpc.ts

## Question
EmbeddedWalletApi.getURL appends caid and client_id as query parameters; can an attacker capture that URL through handleWalletApiRpc and learn identifiers that link a user across apps?

## Target
- File/function: [src/embedded/stack/walletRpc.ts](src/embedded/stack/walletRpc.ts) - handleWalletApiRpc, handleEthereumRpc, handleSolanaRpc (method-name echo checks like i.method !== 'personal_sign')
- Entrypoint: provider.request({method, params}) on a TEE (privy-v2) wallet
- Attacker controls: method string, params array contents, response method/data fields
- Exploit idea: Read the generated URL in a context that logs or forwards URLs.
- Invariant to test: User-linkable identifiers must not travel in URLs generated by src/embedded/stack/walletRpc.ts.
- Expected Immunefi impact: Critical - retrieval of sensitive user data: session/identity/provider tokens, key-material handles, or entropy identifiers reach a party that must not hold them.
- Fast validation: Unit test: assert the URL from handleWalletApiRpc contains no user-linkable identifier.
