Transaction::nonce_mode() defaults to NonceMode::Monotonic for TransactionV0 and reads tx.nonce_mode for V1 (core/primitives/src/transaction.rs:211-216). Because nonce_mode is a field INSIDE TransactionV1 (hashed) but DERIVED (not stored) for V0, confirm no code path lets a V0-signed transaction (whose signer never expressed a nonce_mode opinion) be executed under Strict semantics that reject a nonce the signer's own nonce-issuing wallet would have produced as valid, causing legitimate transactions to abort non-deterministically across nodes running different NonceMode interpretations. Scoped impact: Consensus flaws (state-root divergence) if any node path infers nonce_mode differently for V0. Test: apply the same TransactionV0 across two RuntimeConfigStore-resolved views at protocol_version 87 and assert identical NonceMode resolution and identical accept/reject outcome.
