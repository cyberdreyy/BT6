[File scope Critical] `signers-voting.clar`'s `is-novel-aggregate-public-key` computes `(is-eq (default-to reward-cycle (map-get? used-aggregate-public-keys key)) reward-cycle)`, which returns `true` (novel) whenever the key was never used **or** was used exactly for this same `reward-cycle`. Can an attacker (any signer with a single vote's worth of weight, or a miner colluding with a rogue signer weight they legitimately hold) submit the very same `aggregate-public-key` bytes across two *different* rounds within the same reward cycle after a first round's key was already approved and stored via `map-insert aggregate-public-keys reward-cycle key`, since `is-novel-aggregate-public-key` only blocks cross-*cycle* reuse, not cross-*round* reuse within one cycle, and the actual replay guard for 'already approved' is only the `map-insert` idempotency at the bottom (`(err ERR_OUT_OF_VOTING_WINDOW)` from the top-level `asserts!` on `(is-none (map-get? aggregate-public-keys reward-cycle))`)? Preconditions: reward-cycle's aggregate key not yet finalized, round N tally short of threshold. Call sequence: `vote-for-aggregate-public-key` round N with key K partially tallied -> round N+1 with the same key K re-submitted by the same/other signer -> `is-novel-aggregate-public-key` returns true because cycle matches -> tally continues to accumulate weight for K across rounds toward `threshold-weight`. Equality broken: UNIQUENESS - each round's tally should be independently scoped, but weight for the same key can be laundered across rounds since `tally` map keys on `{reward-cycle, round, aggregate-public-key}` yet nothing stops a signer's vote in round N from combining semantically with the same key in round N+1 to reach vote thresholds outside a single round's intent. Impact: Critical because it lets a minority-weight signer's repeated vote for the same key across rounds appear as broader consensus support than actually exists in any single round, corrupting the approved aggregate key downstream signers trust as canonical. Proof idea: Clarity contract test voting with weight < threshold in round 0 for key K, then again in round 1 for the same key K with the same/different low-weight signer, asserting `get-approved-aggregate-key` becomes Some(K) despite no single round crossing 70%.
