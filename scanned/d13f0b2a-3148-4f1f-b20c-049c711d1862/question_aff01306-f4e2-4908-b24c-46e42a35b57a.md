Target: `GlobalStateEvaluator::insert_update` and `reached_agreement` (libsigner/src/v0/signer_state.rs). Attacker action: gossip a `StateMachineUpdate` StackerDB chunk from an address that is not present in `address_weights` (e.g. crafted for a reward-cycle-old address no longer in the current set). Preconditions: `GlobalStateEvaluator` constructed for the current cycle's `address_weights`; attacker controls one miner slot and can push to any signer-message slot they still hold from a prior cycle. Call sequence: `insert_update` returns `false` silently for unknown addresses, so genuinely-current signers' updates keep flowing while stale-cycle noise is dropped, but `self.total_weight` was computed once via `GlobalStateEvaluator::new` at construction and never re-derived if the reward set is refreshed mid-cycle without reconstructing the evaluator. Equality: `total_weight` used by `reached_agreement`/`reached_disagreement` == `total_signing_weight()` of the currently-active `RewardSet`. Impact: Critical — if the evaluator's `total_weight` is stale-low relative to the true reward set, `reached_agreement` can fire on less than the consensus-mandated share, causing the local state machine to capitulate to a miner viewpoint (feeding `capitulate_viewpoint`) that a canonical-weight-respecting evaluator would reject. Proof: Rust test rebuilding `GlobalStateEvaluator` with a stale `address_weights` snapshot, feeding updates summing to less than the true reward-set majority, and asserting `reached_agreement` incorrectly returns true relative to a freshly-constructed evaluator from the current `RewardSet`.
