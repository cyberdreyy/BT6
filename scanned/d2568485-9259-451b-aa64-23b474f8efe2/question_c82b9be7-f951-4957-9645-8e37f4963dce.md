ReceiptManager::append_action_stake (receipt_manager.rs) lets a contract attach a StakeAction with an attacker-chosen public_key to a receipt whose receiver_id is also attacker-chosen. Since is_valid_staking_key (action_validation.rs) only checks the public key format, not ownership, can attacker contract A create a receipt targeting victim validator account V with a StakeAction using A's own public_key, and if V's account_id happens to lack a matching access key check at execution (actions.rs action_stake), does the runtime apply the stake action to V's balance under A's key, letting A seize control of V's locked stake without V having signed anything?
