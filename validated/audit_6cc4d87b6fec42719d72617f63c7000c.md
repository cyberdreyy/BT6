## Analysis

The uncontrolled-recursion bug class in the Thrift advisory (unbounded parser recursion on attacker-controlled input, no depth limit) has a direct structural analog in Base's Merkle Patricia Trie implementation used by the fault-proof program. [1](#0-0) 

### Title
Uncontrolled Recursion in `TrieNode::decode` allows stack-overflow DoS of the fault-proof program via a single malicious trie-node preimage - (File: crates/proof/mpt/src/node.rs)

### Summary
`TrieNode::decode` and its helper `try_decode_leaf_or_extension_payload` recursively call `Self::decode` to parse nested `Extension`/`Branch` RLP structures with no bound on recursion depth. Because inline (non-blinded) child nodes are inlined directly in the same byte buffer whenever their encoded length is under 32 bytes, an attacker who controls a single trie-node preimage (matched only by its own keccak256 hash) can pack an arbitrarily long chain of nested extension nodes into one buffer, driving unbounded native-stack recursion in a single synchronous call.

### Finding Description
`TrieNode::decode` peeks the RLP header and, for a `LEAF_OR_EXTENSION_LIST_LENGTH` (2-element) list, calls `try_decode_leaf_or_extension_payload`, which for an extension-prefixed path recurses via `Self::decode(buf)` to decode the inner "pointer" node [2](#0-1) . The encoder only blinds (replaces with a 32-byte keccak256 commitment requiring a separate oracle round-trip) a child node when its own RLP-encoded length is `>= 32` bytes [3](#0-2) ; smaller nodes are encoded inline in the same buffer. A minimal `Extension { prefix: [], node }` can be encoded in well under 32 bytes, so an attacker can chain thousands of these small extension nodes back-to-back inside a single preimage blob without ever triggering blinding — meaning the entire chain is decoded in one uninterrupted, unbounded recursive call to `Self::decode`.

This recursive decoder is used directly against externally-supplied/untrusted preimage bytes in the fault-proof program's trie providers, e.g. `OracleL1ChainProvider::trie_node_by_hash` [4](#0-3)  and the executor's test/host trie fetchers [5](#0-4) , which only validate that `keccak256(preimage) == requested_hash` before calling `TrieNode::decode(&mut preimage.as_ref())`. Since the attacker (the untrusted party supplying preimage data to the honest program/host, e.g. a dispute-game participant or L1-data-derivation input) fully controls the preimage content — they simply hash whatever bytes they choose — they can trivially construct a preimage that hashes correctly and decodes into a deeply nested `Extension` chain.

Unlike the CBOR parser elsewhere in the codebase, which explicitly enforces `MAX_CBOR_NESTING_DEPTH` [6](#0-5) [7](#0-6) , and unlike the observability-events JSON validator which enforces `MAX_DATA_VALIDATION_DEPTH` [8](#0-7) , `TrieNode::decode` has no equivalent depth guard.

### Impact Explanation
The `base-proof-mpt` crate is the trie backend for `base-proof-executor`, which performs stateless block execution inside the fault-proof program used to compute the provable output root in dispute games. An uncontrolled recursion triggering a native stack overflow crashes the process (the repository's own `crates/utilities/cli/src/sigsegv.rs` acknowledges stack-overflow crashes as a real, handled failure mode [9](#0-8) , confirming this class of crash is not otherwise mitigated at the parser level). A crash of the fault-proof program during dispute resolution prevents it from producing a correct output root, i.e. "node halt" / "wrong provable output root" — a party able to feed a crafted preimage into the program's trie provider can deny the honest program the ability to compute or verify state, undermining the fault-proof game's correctness guarantee.

### Likelihood Explanation
High likelihood of triggering the crash: constructing the malicious preimage requires no cryptographic effort (only choosing arbitrary bytes and taking their keccak256 hash — the "signature" is simply self-consistency, not an external key). The only constraint is preimage size, which is bounded by whatever size limit the surrounding preimage-oracle/hint protocol permits; even a moderately sized buffer (tens of KB) can encode many thousands of 3–5 byte nested extension headers, comfortably exceeding typical native thread stack sizes.

### Recommendation
Add an explicit recursion/nesting-depth counter to `TrieNode::decode` (and the corresponding `open`/`insert`/`delete`/`collapse_if_possible` recursive walks) analogous to `MAX_CBOR_NESTING_DEPTH`, capping decode depth at the maximum theoretically valid MPT depth (bounded by the fixed 64-nibble key length for keccak256-hashed keys, e.g. `MAX_TRIE_DEPTH = 64`), and reject any preimage that would exceed it with a decode error instead of recursing further.

### Proof of Concept
1. Construct `N` (e.g. 50,000) nested `TrieNode::Extension { prefix: Nibbles::from_nibbles([]), node: Box::new(...) }` wrappers around an innermost `TrieNode::Leaf`, each RLP-encoded inline (each < 32 bytes so none get blinded).
2. Encode via `TrieNode::encode` to obtain a single contiguous byte buffer `preimage`.
3. Compute `hash = keccak256(preimage)`.
4. Serve `preimage` as the response to a `trie_node_by_hash(hash)` / preimage-oracle request from the fault-proof program (e.g. as a malicious L1 chain-data or account-proof preimage).
5. When the program calls `TrieNode::decode(&mut preimage.as_ref())` (as in `OracleL1ChainProvider::trie_node_by_hash`), the recursive `Self::decode` calls in `try_decode_leaf_or_extension_payload` recurse `N` times in a single stack frame chain, overflowing the native stack and crashing the process.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}
