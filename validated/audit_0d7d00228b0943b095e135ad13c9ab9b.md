### Title
Missing duplicate-key check on unbounded `savedCallbacks` map lets an unprivileged user hijack another user's in-flight legacy trigger request - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`handler.HandleLegacyUserMessage` stores each incoming user request in the `savedCallbacks` map keyed only by the attacker-suppliable `msg.Body.MessageId`, without ever checking whether that key is already in use by another in-flight request.

### Finding Description
In `core/services/gateway/handlers/capabilities/handler.go`, `HandleLegacyUserMessage` unconditionally overwrites the map entry: [1](#0-0) 

There is no uniqueness/collision check comparable to the ones present in sibling handlers, e.g. the vault handler's `newActiveRequest`, which rejects a request whose ID is already active: [2](#0-1) 

and the v2 HTTP trigger handler's `setupCallback`, which does the same: [3](#0-2) 

The `MessageId` used as the map key comes straight from the message body and is fully attacker-controlled — `Validate()` only checks length/format, and the signature covers `MessageId || Method || DonId || Receiver || Payload`, but places no constraint tying the `MessageId` value to the sender's identity or to prior usage: [4](#0-3) 

Because any unprivileged client reaching the gateway's `ProcessRequest`/`HandleLegacyUserMessage` path can sign an arbitrary message with any `MessageId` (using their own keypair), an attacker can:
1. Observe or guess a `MessageId` used by a victim's in-flight legacy trigger request (e.g. via predictable IDs, or by racing many requests).
2. Submit a legacy message with the same `MessageId`, causing `h.savedCallbacks[msg.Body.MessageId]` to be overwritten with the attacker's own `callback`.
3. When a DON node later responds to that `MessageId` (originally the victim's), `handleWebAPITriggerMessage` looks up and deletes the callback keyed by that ID and delivers the response to whichever callback is currently stored: [5](#0-4) 

This lets the attacker's callback receive the victim's response (cross-user response confusion), while the victim's original request silently hangs until it eventually times out at the gateway (`callback.Wait(ctx)` in `gateway.go`). The relevant TODO in the code even acknowledges the missing allowlist/rate-limiting protections on this path: [6](#0-5) 

### Impact Explanation
This is a concrete cross-user response confusion / request hijack: an unprivileged actor can capture a response meant for another user's legacy trigger request by colliding on `MessageId`, and simultaneously deny the legitimate requester their response. While it does not directly move funds, it breaks the confidentiality/integrity guarantee that a caller's response is delivered only to that caller, and can be leveraged for request-hijack style attacks against gateway-mediated workflow triggers. Severity is medium since it requires the attacker to predict or race a victim's `MessageId`.

### Likelihood Explanation
Likelihood depends on how `MessageId` values are generated by legitimate callers of the legacy interface. If callers use sequential/predictable IDs or short IDs, or if an attacker can race with high volume against a target ID space (limited only by `MessageIdMaxLen` = 128), collision is straightforward with no rate limiting or per-sender allowlist enforced on this handler path, as noted by the in-code TODO.

### Recommendation
Add a duplicate-key check in `HandleLegacyUserMessage` before inserting into `savedCallbacks`, mirroring the pattern used in `vault/handler.go` (`newActiveRequest`) and `v2/http_trigger_handler.go` (`setupCallback`): reject the request with a conflict error (and reply to the caller) instead of silently overwriting an existing entry for the same `MessageId`. Implement the allowlist/rate-limiting mentioned in the TODO to reduce the attack surface for ID prediction/racing.

### Proof of Concept
Conceptual PoC (cannot be executed from static analysis, but the code path is deterministic):
1. Victim sends a legacy message with `MessageId = "X"` via the gateway; `HandleLegacyUserMessage` stores `savedCallbacks["X"] = victimCallback` and forwards the request to DON members.
2. Before the victim's response arrives, attacker signs and submits their own legacy message reusing `MessageId = "X"` (any Method/DonId/Payload of their choosing, signed with attacker's own key — `Validate()` does not check `MessageId` uniqueness or ownership).
3. `savedCallbacks["X"]` is overwritten to `attackerCallback`.
4. A DON node responds referencing `MessageId = "X"` (in response to the victim's original forwarded request); `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds `attackerCallback`, deletes the entry, and delivers the victim's response to the attacker.
5. Victim's `callback.Wait(ctx)` in `gateway.ProcessRequest` never resolves and eventually times out with `RequestTimeoutError`. [7](#0-6) [8](#0-7)

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
