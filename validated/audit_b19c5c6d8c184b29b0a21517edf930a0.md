### Title
Unauthenticated `/readyz?full=true` discloses internal health-check names and error details - ([File: core/web/health_controller.go])

### Summary
`HealthController.Readyz` is mounted at `r.GET("/readyz", hc.Readyz)` in `healthRoutes` with no `auth.Authenticate` wrapper, unlike other privileged routes in `router.go`. When called with the `full` query parameter, it returns a JSON array of per-check `Name` and `Output` (the raw `err.Error()` string) for every failing internal health check, exposing internal service/component names and error text to any unauthenticated caller.

### Finding Description
`healthRoutes(app, api)` registers `r.GET("/readyz", hc.Readyz)` and `r.GET("/public-readyz", hc.PublicReadyz)` directly on the top-level `api` group with no `auth.Authenticate(...)` middleware applied (compare to `/v2/*` routes, `/sessions` DELETE, and `/debug/vars`, which are all wrapped in `auth.Authenticate`) [1](#0-0) . `HealthController.Readyz` calls `checker.IsReady()` to get a `ready` bool and an `errors map[string]error`, and when the request includes a `full` query parameter (any value, e.g. `?full=true`), it builds a `presenters.Check` entry per map key containing `Name` (the internal check/service name) and `Output` (the full `err.Error()` string) and serializes them via `jsonAPIResponse` [2](#0-1) . The `presenters.Check` struct explicitly serializes `Name`, `Status`, and `Output` to JSON [3](#0-2) . This is in stark contrast to the sibling `PublicReadyz` handler, whose doc comment states it is "intended for public load balancer health checks" and "never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints" [4](#0-3) . Since `Readyz` sits on the same unauthenticated route group as `PublicReadyz`, any unauthenticated network client reaching the node's API port can call `GET /readyz?full=true` and receive the detailed check names and error strings that `PublicReadyz` was specifically designed to withhold.

### Impact Explanation
This maps to a Chainlink bounty "Informational Disclosure" class impact: an unauthenticated attacker can learn internal component/service names and detailed error messages (e.g., database connectivity errors, chain/RPC connection errors, or other subsystem failure text) that were deliberately excluded from the public-facing `PublicReadyz` endpoint. This does not by itself grant privilege escalation or fund movement, but it can leak internal architecture/state details useful for further targeted attacks or reveal sensitive configuration details embedded in error strings, depending on what `checker.IsReady()` components report.

### Likelihood Explanation
No credentials, roles, or special access are required — an anonymous network client only needs to send `GET /readyz?full=true`. The route is reachable at the top-level `api` router group before any auth middleware group is applied, is subject only to the general (unauthenticated-tier) rate limiter, and is fully repeatable at will. Likelihood is high given the trivial reproduction (single unauthenticated GET request).

### Recommendation
Restrict full/detailed readiness output on `/readyz` to authenticated/internal callers only — either wrap the `full` query behavior behind `auth.Authenticate`, remove per-check name/output detail from the publicly reachable path, or route the internal `/readyz?full=true` behavior behind a separate internal-only listener/path (mirroring the intent already documented for `PublicReadyz`).

### Proof of Concept
1. In a `httptest`-based integration test for `core/web`, construct the Gin engine via `NewRouter` (or directly mount `healthRoutes`) with a mocked `chainlink.Application` whose `GetHealthChecker()` returns a fake `services.Checker` implementation.
2. Configure the mock `IsReady()` to return `(false, map[string]error{"some-service-check": errors.New("db connection failed: password=leaked-value")})`.
3. Send `httptest.NewRequest("GET", "/readyz?full=true", nil)` with **no** `Authorization` header and no session cookie.
4. Serve the request through the router and assert:
   - HTTP status is `503` (matching `!ready`).
   - Response body is valid JSON:API and contains a `checks` array with an entry whose `attributes.name == "some-service-check"`, `attributes.status == "failing"`, and `attributes.output` contains the full mocked error string `"db connection failed: password=leaked-value"`.
5. Contrast with the same request sent to `GET /public-readyz?full=true`, asserting it returns only a bare `503` status with no per-check JSON body, confirming the intended safe behavior differs from `/readyz`.

```go
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid

func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
```

```go
func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}
```
