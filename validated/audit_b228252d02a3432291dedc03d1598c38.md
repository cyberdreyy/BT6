### Title
Missing sender allowlist enforcement in `HandleLegacyUserMessage` allows any self-signed `MethodWebAPITrigger` message to be forwarded to all DON nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` decodes the payload, checks timestamp freshness, and checks the method name, but never checks that `msg.Body.Sender` (the ECDSA address that produced the signature) belongs to any allowlist before forwarding the request to every DON member via `don.SendToNode`. The only marked TODO comment (`// TODO: apply allowlist and rate-limiting here`) confirms this check is not implemented.

### Finding Description
The request path is: `gateway.ProcessRequest` [1](#0-0)  decodes the JSON-RPC request, calls `msg.Validate()` which only verifies structural fields and recovers the signer address from the ECDSA signature via `ExtractSigner`/`gw_common.ExtractSigner` [2](#0-1)  — it does not check that the recovered signer is a known/registered/allowlisted address, only that the signature is internally self-consistent (i.e., any freshly generated keypair can self-sign and pass `Validate()`).

The request is then routed to `handler.HandleLegacyUserMessage`, which performs payload decoding, a `Timestamp` non-zero check, and a staleness check [3](#0-2) , followed directly by the marked gap and a method-name check [4](#0-3) . No code path in this function inspects `msg.Body.Sender` against `h.donConfig` or any allowlist config. It then builds the request and forwards it to **every** DON member: [5](#0-4) .

The existing test suite explicitly documents this gap with the comment "TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated" [6](#0-5) , and the happy-path test signs the message with `nodes[0].PrivateKey` (an arbitrary test key, not validated against any allowlist) and asserts `don.SendToNode` is invoked [7](#0-6) , confirming any validly self-signed key reaches `SendToNode`.

### Impact Explanation
Any attacker who can send a request to the gateway HTTP endpoint (unauthenticated relative to sender identity — the gateway only checks a self-consistent signature, not sender authorization) can generate a fresh ECDSA keypair, self-sign a `MethodWebAPITrigger` message with an arbitrary `DonId`, and have the gateway forward it to all DON member nodes for execution via `don.SendToNode`. This allows unauthorized consumption of DON capability execution resources (workflow trigger invocation) that should be restricted to allowlisted/subscribed senders — matching a "quota/allowlist bypass leading to unauthorized DON resource consumption" impact class.

### Likelihood Explanation
Preconditions are minimal: the attacker needs no registration, no credentials beyond the ability to generate an ECDSA keypair (free, offline), and network access to the gateway's public HTTP endpoint. The exploit is fully repeatable and requires no race conditions or timing tricks — only a valid, non-stale timestamp and the correct method name, both trivially attacker-controlled.

### Recommendation
Implement the allowlist/rate-limiting check that the `// TODO` comment marks as missing: before forwarding to `don.SendToNode`, verify `msg.Body.Sender` against a configured per-DON allowlist (e.g., `h.donConfig`-derived subscriber list) and apply `h.nodeRateLimiter`-equivalent (or a dedicated per-sender rate limiter) gating, returning `api.UserMessageParseError`/an authorization error response for non-allowlisted senders, consistent with how `handleWebAPIOutgoingMessage` uses `h.nodeRateLimiter.Allow(nodeAddr)` for node-originated messages.

### Proof of Concept
1. In `handler_test.go`, add a test alongside `TestHandlerReceiveHTTPMessageFromClient`:
   - Generate a brand-new ECDSA key (`crypto.GenerateKey()`), unrelated to `nodes[]` or any configured DON member/allowlist entry.
   - Build a `MethodWebAPITrigger` message via `triggerRequest(t, newKey, ...)` with a valid, fresh timestamp.
   - Call `handler.HandleLegacyUserMessage(ctx, msg, cb)`.
   - Assert `don.On("SendToNode", ...)` is invoked once per `h.donConfig.Members` (mirroring the existing "happy case" mock expectations), and that `err` is `nil`.
2. Expected (buggy) result: `SendToNode` is called for every DON member despite the signer never having been registered/allowlisted — proving no allowlist enforcement occurs.
3. After remediation, the same test (with an unallowlisted key) should instead assert `cb.Wait` returns an authorization-error `UserCallbackPayload` and `don.SendToNode` is never called.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func TestHandlerReceiveHTTPMessageFromClient(t *testing.T) {
	handler, _, don, nodes := setupHandler(t)
	ctx := t.Context()
	msg := triggerRequest(t, nodes[0].PrivateKey, []string{"daily_price_update"}, "", "", "")
	codec := api.JsonRPCCodec{}

	t.Run("happy case", func(t *testing.T) {
		// sends to 2 dons
		don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Run(func(args mock.Arguments) {
			nodeReq := nodeRequest(msg)
			require.Equal(t, nodeReq, args.Get(2))
		}).Return(nil).Once()
		don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Run(func(args mock.Arguments) {
			nodeReq := nodeRequest(msg)
			require.Equal(t, nodeReq, args.Get(2))
		}).Return(nil).Once()

		cb := hc.NewCallback()
		err := handler.HandleLegacyUserMessage(ctx, msg, cb)
		require.NoError(t, err)

		resp, err := hc.ValidatedResponseFromMessage(msg)
		require.NoError(t, err)
		err = handler.HandleNodeMessage(ctx, resp, nodes[0].Address)
		require.NoError(t, err)

		r, err := cb.Wait(t.Context())
		require.NoError(t, err)
		require.Equal(t, handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError}, r)
	})
