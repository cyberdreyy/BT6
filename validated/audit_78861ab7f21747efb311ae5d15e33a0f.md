### Title
Message.Validate() performs no timestamp/nonce/freshness check, allowing indefinite replay of previously valid signed gateway requests - ([File: core/services/gateway/api/message.go])

### Summary
`Message.Validate()` only checks field lengths/format and signature validity via `ExtractSigner()`; it never inspects any timestamp or expiry embedded in `MessageId`, so the same signed `Message` bytes remain cryptographically "valid" forever. Replay protection is only incidentally provided by handler-level in-memory `RequestCache` deduplication (keyed by `sender+MessageId`), which is temporary and removed once a response is delivered or the request times out, after which the identical message can be resubmitted and accepted as fresh.

### Finding Description
`Message.Validate()` in [1](#0-0)  validates signature length, `MessageId`/`Method`/`DonId` length and null-suffix constraints, and recovers the signer via `ExtractSigner()`, but it does not check any timestamp, nonce counter, or expiry value carried in `MessageId` or elsewhere in `MessageBody`.

The legacy gateway request path in `gateway.ProcessRequest` calls `msg.Validate()` directly and, if it passes, dispatches to `h.HandleLegacyUserMessage`: [2](#0-1) . There is no separate freshness/anti-replay check performed before or after `Validate()` in this path.

The only anti-replay mechanism in the system is `requestCache.NewRequest`, which rejects a request only if an entry with the same `(sender, MessageId)` key is still present in the in-memory map: [3](#0-2) . Once the request completes (`deleteAndSendOnce` on aggregation or timeout) the entry is deleted from the cache: [4](#0-3) . After deletion, nothing prevents the exact same signature+body bytes from being resubmitted and treated as a brand-new, valid request — `Validate()` will pass identically to the first time, and `NewRequest` will succeed because the cache no longer has that key.

### Impact Explanation
An attacker who has observed one valid signed `Message` (e.g., from a legitimate HTTP request/response they could see, such as their own prior job-config or bridge-related fetch) can resubmit the exact same bytes after the original request has completed (or after a gateway/process restart clears the cache) and have the gateway process it as if freshly authorized by the original sender, re-triggering the sensitive action (e.g., re-fetching job configuration or credential-bearing bridge responses) attributed to that sender. This is a request-binding/freshness weakness rather than a full authentication bypass, since the signature itself is still valid and tied to the original sender — but it breaks the expectation that a captured request cannot be replayed indefinitely.

### Likelihood Explanation
Exploitation requires no privileged access — only possession of one previously valid signed `Message` (signature + body bytes), which is plausible for a network observer or the original requester itself replaying it later. It is trivially repeatable any number of times once the original request has aged out of the `RequestCache` (bounded by `timeout` field) or after node/gateway restarts, since the cache is purely in-memory and non-persistent.

### Recommendation
Add explicit freshness enforcement in `Message.Validate()`: require the `MessageId` (or an added timestamp/nonce field within `MessageBody` that is covered by the signature) to encode a recent, bounded timestamp and reject messages outside an acceptable clock-skew window; additionally, persist recently-seen `(sender, MessageId)` pairs beyond the in-flight response window (e.g., in a durable/longer-lived dedup store) so that resubmission is rejected even after the original request has completed or the process restarted.

### Proof of Concept
1. In `core/services/gateway/api` package, construct a valid `Message` with `Sign()` using a test private key.
2. Call `gateway.ProcessRequest` (as in `TestGateway_ProcessRequest_*` tests) with the raw signed bytes; assert success and that a response is returned.
3. Wait for (or manually trigger) the `RequestCache` entry to be cleaned up (simulate via the cache's timeout callback or by driving a full response cycle so `deleteAndSendOnce` runs).
4. Resubmit the identical raw signed bytes again to `gateway.ProcessRequest` with no changes to `MessageId`/`Signature`.
5. Expected (secure) behavior: request should be rejected as stale/replayed.
6. Actual behavior: `msg.Validate()` succeeds again, `NewRequest` succeeds because the cache no longer contains the key, and the handler processes it as a new legitimate request — demonstrating the replay.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
	codec := api.JsonRPCCodec{}
	timer := time.AfterFunc(c.timeout, func() {
		err := c.deleteAndSendOnce(key, handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(request), ErrorCode: api.RequestTimeoutError})
		if err != nil {
			lggr.Errorw("failed to send timeout response", "error", err)
		}
	})
	c.cache[key] = &pendingRequest[T]{Callback: callback, responseData: responseData, timeoutTimer: timer}
	return nil
}

func (c *requestCache[T]) deleteAndSendOnce(key globalId, callbackResponse handlers.UserCallbackPayload) error {
	c.mu.Lock()
	entry, deleted := c.cache[key]
	delete(c.cache, key)
	c.mu.Unlock()
	if deleted {
		entry.timeoutTimer.Stop()
		return entry.SendResponse(callbackResponse)
	}

	return nil
}
