## Missing Address Validation on L1 SystemConfig Updates Can Halt Base Derivation

Extensive searching of `Thankgod67Ikhide/base--015` shows this codebase is generally very disciplined about zero-address validation: the activation registry's `set_admin` explicitly rejects `Address::ZERO` [1](#0-0) , B20 token transfers/mints/approvals reject zero sender/receiver/spender/approver [2](#0-1) , and the policy registry rejects zero-address policy admins [3](#0-2) .

However, one class of admin-settable address parameters does lack this validation: the `batcher_address` and `unsafe_block_signer` fields decoded from L1 `SystemConfig` `ConfigUpdate` logs.

### Title
Missing zero-address validation on `BatcherUpdate`/`UnsafeBlockSignerUpdate` decoding can halt L2 derivation and unsafe-head gossip - (File: `crates/common/genesis/src/updates/batcher.rs`, `crates/common/genesis/src/updates/signer.rs`)

### Summary
`BatcherUpdate::try_from` and `UnsafeBlockSignerUpdate::try_from` decode an ABI-encoded `address` from an L1 `ConfigUpdate` log with no validation that the decoded address is non-zero, unlike every other admin-address setter in this codebase.

### Finding Description
`BatcherUpdate::try_from` decodes the raw address payload and returns it unconditionally: [4](#0-3) . The same pattern applies to `UnsafeBlockSignerUpdate::try_from` [5](#0-4) . Both `apply()` methods write the value directly into `SystemConfig` without any sanity check [6](#0-5) .

`SystemConfig::update_with_receipts` processes every well-formed `ConfigUpdate` log from the configured `l1_system_config_address` and applies it, independent of prior state [7](#0-6) . This is explicitly in the reachable attack surface ("derivation of attacker-written L1 deposit and system-config data").

Once `SystemConfig.batcher_address` is `Address::ZERO`, the calldata/blob DA sources filter transactions by matching the signer against `batcher_address` [8](#0-7)  and [9](#0-8) . No real signer recovers to `Address::ZERO`, so every subsequent batcher frame is silently rejected at the DA-filtering layer, and the derivation pipeline never advances the safe head again — until (if ever) a corrective `ConfigUpdate` restores a valid batcher address. Similarly, if `unsafe_block_signer` is driven to `Address::ZERO`, the gossip `BlockHandler::block_valid` signature check will reject all subsequently gossipped unsafe blocks because no legitimate signer recovers to the zero address [10](#0-9) .

### Impact Explanation
Once the zero address is committed into `SystemConfig` via a legitimately-formed L1 log, safe-head derivation (and/or unsafe-head gossip acceptance) is bricked for every node that reads the same L1 SystemConfig — a permanent node halt on the affected surface until a further corrective config update is published (which itself depends on the same trusted L1 admin acting correctly). This matches the "node halt" impact category.

### Likelihood Explanation
This requires a compromised or misconfigured L1 SystemConfig owner (the same actor referenced by the original Rubicon-style admin bug class) to emit a `ConfigUpdate` log with a zero address for `batcherHash` or `unsafeBlockSigner`. The Base node's derivation code accepts and applies this value with no defensive check, unlike its own established pattern (`ZeroAdminAddress`, `InvalidReceiver`, `InvalidSender`, zero-admin `createPolicy` rejection) used everywhere else in the repo for admin-settable addresses.

### Recommendation
Add an explicit zero-address check in `BatcherUpdate::try_from` and `UnsafeBlockSignerUpdate::try_from` (or in `SystemConfig::process_config_update_log`) that rejects/skips a `ConfigUpdate` log carrying `Address::ZERO`, mirroring the `ZeroAdminAddress`/`InvalidReceiver` guard pattern already used throughout `crates/common/precompiles`.

### Proof of Concept
1. Deploy/point a test harness at an L1 `l1_system_config_address` as in `crates/common/genesis/src/system/config.rs` tests.
2. Emit a `ConfigUpdate` log of `BATCHER_UPDATE_TYPE` whose payload ABI-encodes `Address::ZERO` (analogous to `test_system_config_update_with_receipts_batcher_address` at [11](#0-10)  but with an all-zero address instead of `0x...beef`).
3. Observe `system_config.batcher_address == Address::ZERO` is accepted without error.
4. Any subsequent legitimate batcher L1 transaction is filtered out by `extract_blob_data`/`load_calldata` (`source.batcher_address` never equals a real recovered signer), so `node.run_until_idle()` derives zero new safe blocks going forward, per the pattern demonstrated in `batcher_key_rotation_accepts_new_batcher` [12](#0-11) .

    pub fn update_with_receipts(
        &mut self,
        receipts: &[Receipt],
        l1_system_config_address: Address,
        ecotone_active: bool,
    ) -> (Vec<SystemConfigUpdateKind>, Vec<SystemConfigUpdateError>) {
        receipts
            .iter()
            .filter(|r| r.status != Eip658Value::Eip658(false))
            .flat_map(|r| &r.logs)
            .filter(|log| {
                let topics = log.topics();
                log.address == l1_system_config_address
                    && !topics.is_empty()
                    && topics[0] == SystemConfigUpdate::TOPIC
            })
            .map(|log| self.process_config_update_log(log, ecotone_active))
            .fold((Vec::new(), Vec::new()), |(mut updates, mut errors), result| {
                match result {
                    Ok(kind) => updates.push(kind),
                    Err(e) => errors.push(e),
                }
                (updates, errors)
            })
    }

/// After a batcher-address rotation committed to L1 via a `ConfigUpdate` log,
/// frames from the old batcher address are silently ignored and frames from
/// the new address are derived normally.
///
/// The rotation is delivered as a real `ConfigUpdate` log in an L1 receipt.
/// The traversal stage reads receipts via `receipts_by_hash` when
/// advancing L1 origin, and calls `update_with_receipts` to update its
/// internal [`SystemConfig`].  Subsequent calls to
/// `DataAvailabilityProvider::next` receive the updated batcher address, so
/// the old batcher's frames are filtered out at the frame-retrieval layer.
///
/// Flow:
///   L1 blocks 1-2: batcher A submits → L2 blocks 1-2 derived
///   L1 block 3:    rotation log only  → system config updated, 0 L2 blocks
///   L1 block 4:    batcher A submits  → IGNORED (0 derived)
///   L1 block 5:    batcher B submits  → DERIVED (1 derived)
///
///
/// [`SystemConfig`]: base_common_genesis::SystemConfig
#[tokio::test]
async fn batcher_key_rotation_accepts_new_batcher() {
    // Use a dedicated L1 system config address so the pipeline's log filter
    // matches our synthetic ConfigUpdate logs.
    let l1_sys_cfg_addr = Address::repeat_byte(0xCC);
    let batcher_a = BatcherConfig {
        encoder: EncoderConfig { da_type: DaType::Calldata, ..EncoderConfig::default() },
        ..BatcherConfig::default()
    };
    let batcher_b_signer =
        PrivateKeySigner::from_bytes(&B256::repeat_byte(0xBB)).expect("valid batcher B signer");
    let batcher_b = batcher_a.clone().with_l1_signer(batcher_b_signer);

    let rollup_cfg = TestRollupConfigBuilder::base_mainnet(&batcher_a)
        .with_l1_system_config_address(l1_sys_cfg_addr)
        .build();
    let mut h = ActionTestHarness::new(L1MinerConfig::default(), rollup_cfg.clone());

    // Build all L2 blocks (1, 2, and 3) upfront from the L1 genesis state.
    // With block_time=2 and L1 block_time=12, all three (timestamps 2,4,6s)
    // stay in epoch 0 (genesis ts=0), so the builder picks the same L1 origin.
    let l1_chain = SharedL1Chain::from_blocks(h.l1.chain().to_vec());
    let mut builder = h.create_l2_sequencer(l1_chain);
    let block1 = builder.build_next_block_with_single_transaction().await;
    let block2 = builder.build_next_block_with_single_transaction().await;
    let block3 = builder.build_next_block_with_single_transaction().await;

    // --- L1 blocks 1-2: batcher A submits → L2 blocks 1-2 derived. ---
    let mut batcher = Batcher::new(ActionL2Source::new(), &h.rollup_config, batcher_a.clone());
    for block in [block1, block2] {
        batcher.push_block(block);
        batcher.advance(&mut h.l1).await;
    }

    // --- L1 block 3: rotation log only, no batch. ---
    // After the traversal processes this block and reads the ConfigUpdate log
    // from its receipts, the pipeline's internal batcher address switches to B.
    h.l1.enqueue_batcher_update(l1_sys_cfg_addr, batcher_b.batcher_address);
    h.l1.mine_block(); // block 3: rotation receipt, no batcher tx

    let (mut node, chain) = h.create_test_rollup_node_from_sequencer(
        &mut builder,
        SharedL1Chain::from_blocks(h.l1.chain().to_vec()),
    );
    node.initialize().await;

    // Drive derivation through blocks 1-2 (batcher A frames derived).
    for _ in 1u64..=2 {
        node.run_until_idle().await;
    }
    assert_eq!(node.l2_safe_number(), 2, "blocks 1-2 derived with batcher A");

    // Step over the rotation block — no batch, but system config updates to B.
    let rotation_derived = node.run_until_idle().await;
    assert_eq!(rotation_derived, 0, "rotation block contains no batch");

    // --- L1 block 4: batcher A submits for L2 block 3 — must be ignored. ---
    {
        let mut source = ActionL2Source::new();
        source.push(block3.clone());
        Batcher::new(source, &h.rollup_config, batcher_a.clone()).advance(&mut h.l1).await;
    }
    chain.push(h.l1.tip().clone());

    let derived_a = node.run_until_idle().await;
    assert_eq!(derived_a, 0, "batcher A frame must be ignored after key rotation");
    assert_eq!(node.l2_safe_number(), 2, "safe head must not advance");

    // --- L1 block 5: batcher B submits for L2 block 3 — must be derived. ---
    {
        let mut source = ActionL2Source::new();
        source.push(block3);
        Batcher::new(source, &h.rollup_config, batcher_b.clone()).advance(&mut h.l1).await;
    }
    chain.push(h.l1.tip().clone());

    let derived_b = node.run_until_idle().await;
    assert_eq!(derived_b, 1, "batcher B frame must be derived after key rotation");
    assert_eq!(node.l2_safe_number(), 3, "safe head advances to 3");
}
