### Title
APR0 withdraw bucket permanently reverts `stopEpoch` after any routine APR update, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.prepareStopEpochWithApr0()` unconditionally reverts with `NotAllowed` whenever `unscaledApr != 0` while `apr0TotalPrincipal != 0`. An unprivileged KYC'd lender can open an APR0 withdraw receipt while the pool APR is 0; the next routine APR change by the manager (a normal, honest operation at every epoch boundary) then makes every subsequent `stopEpoch`/`stopEpochWithDuration` call revert, so the epoch can never close. This is the on-chain analog of CVE-2018-17282's NULL-pointer dereference: a code path assumes a global precondition (APR is still 0 whenever the APR0 bucket is non-empty) that nothing enforces, and dereferences that assumption inside a function on the critical settlement path.

### Finding Description
When a user calls `requestWithdraw` while `unscaledApr == 0`, `_requestWithdrawApr0` records `apr0Users[_user].principal` and increments the global `apr0TotalPrincipal` bucket [1](#0-0) . That bucket is closed in exactly one non-default place — `prepareStopEpochWithApr0`, which the CDO invokes during `stopEpoch`. Before closing it, the function enforces:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol:505-508
// APR0 principal is only valid while APR is 0 for that request lifecycle.
if (unscaledApr != 0) {
  revert NotAllowed();
}
```

`unscaledApr` is mutable at any time via `setAprsWithBuffer`/`setApr` (CDO or manager) [2](#0-1) . There is no guard preventing an APR0 request in the buffer right before the manager sets the next epoch's APR, and no path that clears `apr0TotalPrincipal` without `stopEpoch` succeeding: user-level settlement (`_settleApr0`) only touches `apr0Users[_user]` [3](#0-2) , and the only other decrement is inside `_clearWithdrawClaimForEpoch` with `_isClearingApr0`, which requires `defaultRecoveryFinalized` — unreachable because finalizing a default itself requires a `stopEpoch` that reverts [4](#0-3) .

Sequence:
1. Buffer phase, `unscaledApr == 0` (a supported mode — see `testApr0WithdrawGetsInterestAtStopEpoch`). Attacker (KYC'd lender) calls `cdoEpoch.requestWithdraw(...)`, opening `apr0TotalPrincipal > 0`.
2. Manager honestly sets the next epoch's APR via `setAprsWithBuffer(nonzero, ...)` at `startEpoch` — routine operation.
3. Borrower repays; manager calls `stopEpoch`. Inside, `prepareStopEpochWithApr0` hits `apr0TotalPrincipal != 0 && unscaledApr != 0` and reverts. Every retry reverts. `epochNumber` never increments, `epochEndDate` stays in the past, no default can be declared, no new epoch can start.

The only escape is the manager setting `unscaledApr` back to 0 and re-running `stopEpoch` — which forces the entire pool to settle that epoch at zero yield and leaves the vault frozen until someone diagnoses it.

### Impact Explanation
Temporary freezing of all funds in the vault: total TVL (all active AA/BB tranche principal plus pending withdraw receipts) is locked because `stopEpoch` — the sole function that recalls borrower funds, increments `epochNumber`, enables claims, and gates `startEpoch` — reverts unconditionally. New withdraw claims revert with `NotAllowed` at `epochNumber <= lastWithdrawRequest[_user]` [5](#0-4) . Recovery requires manager intervention and forces a 0-APR settlement, destroying an epoch of yield for all LPs (quantified loss: `expectedEpochInterest` for the frozen epoch).

### Likelihood Explanation
Requires two common conditions: the pool operating at `unscaledApr == 0` for a buffer period (an explicitly supported and tested mode), and the manager later configuring a nonzero APR — which happens at essentially every APR0→normal transition. The attacker only needs to be a whitelisted lender submitting one `requestWithdraw` in that window; cost is the management fee on the requested amount. No privileged collusion, no oracle manipulation.

### Recommendation
Make `prepareStopEpochWithApr0` settle-or-close the APR0 bucket regardless of the current APR instead of reverting: e.g., treat nonzero `unscaledApr` as "APR0 accrues no interest this epoch" by skipping the interest split but still zeroing `apr0TotalPrincipal` and writing `apr0RateByEpoch[epochNumber] = 0` (users keep principal, lose only the APR0 interest). Alternatively, reject new APR0 `requestWithdraw`s once the next epoch's APR has been scheduled nonzero, so the inconsistent state (open APR0 bucket + nonzero APR) can never be reached on the stop path.

### Proof of Concept
Foundry fork PoC (against the existing `IdleCreditVault.t.sol` harness):

```solidity
function testApr0BucketBricksStopEpochAfterAprChange() external {
    // Setup identical to testApr0WithdrawGetsInterestAtStopEpoch:
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0); // unscaledApr = 0

    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _startEpochAndCheckPrices(0);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    _forceLastEpochAprToZero();

    // Attacker: unprivileged KYC'd lender opens an APR0 receipt in the buffer
    cdoEpoch.requestWithdraw(IERC20(AAtranche).balanceOf(address(this)) / 2, address(AAtranche));
    assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

    // Manager honestly configures a normal nonzero APR for the next epoch
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprsWithBuffer(10e18, cdoEpoch.epochDuration(), cdoEpoch.bufferDuration());
    _startEpochAndCheckPrices(1);

    // Borrower fully repays; epoch end reached — stopEpoch is now unusable
    uint256 repay = cdoEpoch.expectedEpochInterest()
        + IdleCreditVault(address(strategy)).pendingWithdraws() + amount;
    deal(defaultUnderlying, borrower, repay);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(10e18, 0); // reverts in prepareStopEpochWithApr0

    // No recovery path: default cannot be reached, claims stay gated,
    // only escape is manager forcing unscaledApr back to 0 (zero-yield settlement).
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0); // succeeds only at 0 APR, destroying epoch yield
}
```

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }
