### Title
Tar entry named `.` (or resolving to extraction root) causes `updateFileMetadata` to overwrite the extraction root directory itself - (File: `commands/helpers/archive/tarzstd/tarzstd_extractor.go`)

### Summary
The `tarzstd` extractor's path-containment check explicitly allows `path == e.dir` to pass without error, and if such an entry is typed as a directory, it is added to the `deferred` map and later has `updateFileMetadata` (lchtimes/lchmod/lchown) applied directly to `e.dir` using attacker-controlled `hdr.Mode`, `hdr.ModTime`, `hdr.Uid`, and `hdr.Gid`. This lets a crafted artifact/cache archive mutate the permissions/ownership/timestamps of the shared extraction root directory itself.

### Finding Description
In `Extract` [1](#0-0) , the guard is:
```go
path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))
...
if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
    return fmt.Errorf(...)
}
```
This is intended to stop path traversal (`../..`) but its second disjunct explicitly *permits* `path == e.dir`. An attacker-supplied tar header with `Name` set to `.`, `./`, or any string that `filepath.Join`/`filepath.Abs` canonicalizes to `e.dir` will pass this check unmolested.

If such an entry's `FileInfo().Mode().IsDir()` is true, the code takes the directory branch [2](#0-1) : it stores `deferred[path] = hdr` (with `path == e.dir`) and calls `os.Mkdir(path, 0777)`, which fails with `IsExist` and is ignored (the root already exists). Then in the deferred-processing loop [3](#0-2) , since the entry is a directory (not a symlink), `updateFileMetadata(path, hdr)` is invoked with `path == e.dir`, applying `lchtimes`, `lchmod`, and `lchown` to `e.dir` using values fully controlled by the archive's header [4](#0-3) .

There is no additional filter anywhere in the call chain (`archive.go`'s `NewExtractor`/`Register` dispatch is generic and does not sanitize header names) that rejects a `.`-named entry before this point [5](#0-4) .

### Impact Explanation
A malicious artifact or cache archive (attacker fully controls both via job scripts/build config through `DownloadArtifacts`/cache restore, which invoke this same `Extract` code) can set the extraction root directory's mode (e.g., `0000`, or world-writable `0777`), mtime, uid, and gid to arbitrary attacker-chosen values. Because this directory is the extraction target passed by the caller (build directory or cache directory), and such directories can be reused across subsequent job/cache restores on the same runner host, corrupting its permissions or ownership degrades isolation guarantees for whatever job or process next relies on that directory's expected state (e.g., unexpected world-writable build root, or a root directory now owned by a different uid on a shared runner, or unreadable directory breaking the next job outright).

### Likelihood Explanation
This is fully user/job-controlled: an attacker only needs to produce a tarzstd-formatted artifact/cache archive (which GitLab CI jobs can construct arbitrarily, e.g. via `tar --transform` tricks or a custom archiver, then have the Runner "download" it as an artifact of their own job, or poison a cache key) containing one entry with `Name: "."` and `Typeflag: tar.TypeDir` plus a chosen `Mode`/`Uid`/`Gid`. It requires no privilege beyond running an ordinary CI job that produces artifacts/cache and a subsequent job (their own or the next pipeline stage) that downloads/extracts them into the same directory. This is deterministic and repeatable.

### Recommendation
Change the containment check to strictly reject `path == e.dir` for any entry that would trigger metadata mutation (or simply disallow `path == e.dir` entirely, since a `.` entry does not need to be materialized — the root directory is always created by the caller beforehand). Concretely, replace:
```go
if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
```
with a check that only allows strictly-nested paths (`strings.HasPrefix(path, e.dir+string(filepath.Separator))`), or explicitly skip processing (including adding to `deferred`) when `path == e.dir`.

### Proof of Concept
Go unit test added to `commands/helpers/archive/tarzstd/tarzstd_extractor_test.go`:
```go
func TestExtractRootDirEntryDoesNotMutateRoot(t *testing.T) {
    dir := t.TempDir()
    before, _ := os.Stat(dir)

    // build a tar+zstd stream with one entry: Name=".", Typeflag=Dir, Mode=0000
    var buf bytes.Buffer
    zw, _ := zstd.NewWriter(&buf)
    tw := tar.NewWriter(zw)
    _ = tw.WriteHeader(&tar.Header{
        Name:     ".",
        Typeflag: tar.TypeDir,
        Mode:     0000,
        Uid:      65534,
        Gid:      65534,
    })
    tw.Close()
    zw.Close()

    r := bytes.NewReader(buf.Bytes())
    ext, _ := NewExtractor(r, int64(r.Len()), dir)
    err := ext.Extract(context.Background())
    require.NoError(t, err)

    after, _ := os.Stat(dir)
    // assert root dir mode/owner unchanged from before extraction
    require.Equal(t, before.Mode(), after.Mode())
}
```
Expected (current, buggy) result: the test fails because `after.Mode()` reflects `0000` (or attacker-chosen mode) instead of the original directory mode, proving `updateFileMetadata` was invoked with `path == e.dir`.

```go
func (e *extractor) updateFileMetadata(path string, hdr *tar.Header) error {
	fi := hdr.FileInfo()

	if err := lchtimes(path, fi.Mode(), time.Now(), fi.ModTime()); err != nil {
		return err
	}

	if err := lchmod(path, fi.Mode()); err != nil {
		return err
	}

	_ = lchown(path, hdr.Uid, hdr.Gid)
	return nil
```
