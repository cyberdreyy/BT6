### Title
Zip extraction has no path-traversal protection, allowing `os.Chtimes` (and file writes) outside the job workspace via crafted `../` entry names - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` in `helpers/archives/zip_extract.go` uses `file.Name` directly for all filesystem operations (`os.Mkdir`, `os.OpenFile`, `os.Symlink`, `lchmod`, and via `processZipExtra` -> `processZipTimestampField` -> `os.Chtimes`) with no confinement check against the extraction directory. The only validation performed, `errorIfGitDirectory`, only checks whether the first path segment is `.git`; it never rejects `..` traversal segments, so a crafted zip entry named e.g. `../outside.txt` passes unblocked and its extra-field timestamp handling calls `os.Chtimes` on a path outside the job workspace.

### Finding Description
In `helpers/archives/zip_extract.go`, `ExtractZipArchive` iterates `archive.File` and for each entry calls `errorIfGitDirectory(file.Name)` (only a warning-producing check, not a hard stop) then `extractZipFile(file)`, which does `os.MkdirAll(filepath.Dir(file.Name), ...)` and creates the file directly using `file.Name` [1](#0-0) . In the second pass it calls `lchmod(file.Name, ...)` and `processZipExtra(&file.FileHeader)` [2](#0-1) .

`processZipExtra` parses the zip "extra field" data and, for a `ZipTimestampFieldType` (0x5455) field, calls `processZipTimestampField`, which directly executes `os.Chtimes(file.Name, acTime, modTime)` using attacker-controlled `file.Name` and attacker-controlled `modTime` bytes from the extra field [3](#0-2) .

The sole path check, `errorIfGitDirectory`/`isPathAGitDirectory` in `path_check_helper.go`, only verifies that the first cleaned path segment equals `.git`; it does not detect or reject `..` segments anywhere in the path, so it provides no defense against traversal such as `../outside.txt` or `../../etc/cron.d/x` [4](#0-3) .

This contrasts with the sibling `tarzstd` extractor, which explicitly resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects the entry if it escapes the target directory `e.dir` [5](#0-4) ; the zip extraction path (`ExtractZipArchive` / `ExtractZipFile`, used from `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) has no equivalent confinement logic at all.

Attacker path: a pipeline author controls artifact/cache zip contents (uploaded via `artifacts:` or restored via cache), so they can craft a zip whose `FileHeader.Name` is `../outside.txt` and whose `Extra` field contains a `ZipTimestampFieldType` block with an attacker-chosen `ModTime`. When the runner extracts this archive during job execution (`ExtractZipFile`/`ExtractZipArchive`), the file is written outside the extraction root (via `extractZipFile`, itself unguarded) and then `os.Chtimes` mutates its timestamps to the attacker-chosen value.

### Impact Explanation
An unprivileged pipeline author can write and set arbitrary mtimes on files outside the intended job workspace (subject to filesystem permissions of the process running the executor), breaking the invariant that "file operations must stay within intended build/cache/artifact roots." Because `extractZipFile` writes/overwrites file content unguarded by the same missing check, the concrete impact is broader than just timestamp mutation — arbitrary file write/overwrite is also possible via the same `..` traversal, and the timestamp mutation described in the question is a real, reachable instance of it.

### Likelihood Explanation
Trivially reproducible by any user able to supply job artifacts or a cache archive that the runner subsequently extracts (`ExtractZipFile`/`ziplegacy` extractor). No special privileges beyond running a CI job are required; only filesystem write permission on the target path (relative to the runner process's working directory/permissions) constrains the blast radius.

### Recommendation
Add a mandatory path-confinement check in `ExtractZipArchive`/`extractZipFile` (and any other zip Name usage including `processZipTimestampField`, `processZipUIDGidField`, `lchmod`) analogous to the `tarzstd` extractor: resolve `filepath.Join(extractionRoot, file.Name)`, `filepath.Abs` it, and reject (fail-closed, not just log) any entry whose resolved path is not a descendant of the extraction root. Extend `path_check_helper.go` (or replace it) to detect `..` traversal, not just `.git` prefixes.

### Proof of Concept
```go
func TestExtractZipFile_PathTraversalTimestamp(t *testing.T) {
    tempDir := t.TempDir()
    outsideFile := filepath.Join(filepath.Dir(tempDir), "outside_marker.txt")
    require.NoError(t, os.WriteFile(outsideFile, []byte("x"), 0o644))
    defer os.Remove(outsideFile)
    origInfo, _ := os.Stat(outsideFile)

    zipPath := filepath.Join(tempDir, "evil.zip")
    f, _ := os.Create(zipPath)
    zw := zip.NewWriter(f)
    fh := &zip.FileHeader{Name: "../outside_marker.txt"}
    fh.SetMode(0o644)
    // craft extra field with ZipTimestampFieldType and attacker chosen ModTime
    var buf bytes.Buffer
    createZipTimestampField(&buf, /* fake FileInfo with chosen mtime */ ...)
    fh.Extra = buf.Bytes()
    w, _ := zw.CreateHeader(fh)
    w.Write([]byte("pwned"))
    zw.Close()
    f.Close()

    wd, _ := os.Getwd()
    os.Chdir(tempDir)
    defer os.Chdir(wd)

    err := ExtractZipFile(zipPath)
    require.NoError(t, err)

    newInfo, err := os.Stat(outsideFile)
    require.NoError(t, err)
    assert.Equal(t, origInfo.ModTime(), newInfo.ModTime(),
        "outside_marker.txt mtime must NOT be changed by zip extraction")
}
```
Expected (current buggy behavior): the assertion fails — `outside_marker.txt`'s mtime is changed (and content overwritten) despite `errorIfGitDirectory` not blocking it, proving the traversal escapes the extraction root.

```go
func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```
