### Title
Single-step activation-registry admin rotation via `setAdmin` allows irrecoverable loss of the network-wide feature-activation admin - (File: crates/common/precompiles/src/activation/storage.rs)

### Summary
The Base-native `ActivationRegistry` precompile exposes `setAdmin(address newAdmin)`, which immediately overwrites the stored admin address in a single transaction with no new-owner confirmation step. This mirrors the reported OpenZeppelin `Ownable.transferOwnership` footgun: if the admin submits (or is coerced/mistakenly submits) an incorrect or inaccessible `newAdmin`, control over the registry is permanently and irrecoverably lost.

### Finding Description
`ActivationRegistryStorage::set_admin` validates the caller is the current admin and that `new_admin` is non-zero, then writes the new admin directly to storage in one step: [1](#0-0) 

This is dispatched directly from ABI calldata via `IActivationRegistry::setAdminCall`: [2](#0-1) 

There is no pending-admin staging, no acceptance step, and no way for the new admin to prove control of the address before the rotation takes effect — unlike the `PolicyRegistry` precompile in the same codebase, which explicitly implements a two-step pattern (`stage_update_admin` → `finalize_update_admin`, with the pending admin required to call `finalize_update_admin` itself before the transfer completes): [3](#0-2) [4](#0-3) 

The `ActivationRegistry` admin is the sole authority that can `activate`/`deactivate` protocol-level features (`PolicyRegistry`, `B20Stablecoin`, `B20Asset`) once Cobalt enables state-backed admin storage, and the same admin is also the only one who can rotate the admin further: [5](#0-4) 

### Impact Explanation
If `setAdmin` is called with a typo'd address, a burn address, or an address whose key is lost, the chain permanently loses the ability to activate or deactivate any Base-native feature gated by this registry (including enabling the `PolicyRegistry` and `B20Stablecoin`/`B20Asset` support) and permanently loses the ability to ever rotate the admin again, since only the current admin can call `set_admin`. There is no recovery path short of a hard-fork/chain-config change, since the admin storage slot is only overridable at genesis/config time, not by any other on-chain mechanism. This constitutes a permanent, irrecoverable loss of a critical governance capability of the chain.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires the legitimate admin (an operationally privileged but still fallible actor) to submit a single malformed transaction, with no confirmation step to catch the mistake before it becomes irreversible — the exact scenario the two-step pattern elsewhere in this same codebase (`PolicyRegistry`) was built to prevent.

### Recommendation
Adopt the same two-step pattern already implemented for `PolicyRegistry` (`stageUpdateAdmin` / `finalizeUpdateAdmin`) for the `ActivationRegistry`'s `setAdmin` flow: require the new admin to explicitly accept the role via a follow-up transaction from the pending address before the rotation takes effect, and emit a distinct "staged" event so operators can verify the pending admin before finalization.

### Proof of Concept
1. Deploy/enable Cobalt so `ActivationAdminConfig::state_enabled == true`.
2. Current admin `A` calls `setAdmin(newAdmin = X)` where `X` is a typo'd address or an address with no known private key (e.g., an address derived from a mis-copied checksum).
3. `set_admin` succeeds in one step (see `crates/common/precompiles/src/activation/storage.rs:149-177`), overwriting `admin` storage immediately with no acceptance from `X`.
4. `A` can no longer call `activate`/`deactivate`/`setAdmin` (its own `require_admin_caller` check now fails), and `X` cannot exercise the role either (unknown key), permanently freezing the feature-activation admin role for the chain's lifetime.

    /// Sets the activation registry admin address.
    pub fn set_admin(
        &mut self,
        new_admin: Address,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }
        if !admin_config.state_enabled {
            return Err(BasePrecompileError::revert(
                IActivationRegistry::AdminStorageNotEnabled {},
            ));
        }
        if new_admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::ZeroAdminAddress {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        self.__initialize()?;
        self.admin.write(new_admin)?;
        self.emit_event(IActivationRegistry::AdminChanged {
            previousAdmin: caller,
            newAdmin: new_admin,
            caller,
        })?;

        Ok(())
    }

    fn finalize_update_admin(&self, storage: &mut S, policy_id: u64) -> Result<()> {
        let packed = self.require_existing_policy(storage, policy_id)?;
        let pending = storage.read_pending_admin(policy_id)?;
        if pending == Address::ZERO {
            return Err(BasePrecompileError::revert(IPolicyRegistry::NoPendingAdmin {}));
        }
        let caller = storage.caller();
        if pending != caller {
            return Err(BasePrecompileError::revert(IPolicyRegistry::Unauthorized {}));
        }
        let previous_admin = packed.admin();
        storage.write_policy_word(policy_id, packed.with_admin(caller).into_u256())?;
        storage.delete_pending_admin(policy_id)?;
        storage.emit_event(
            IPolicyRegistry::PolicyAdminUpdated {
                policyId: policy_id,
                previousAdmin: previous_admin,
                newAdmin: caller,
            }
            .encode_log_data(),
        )?;
        Ok(())
    }
