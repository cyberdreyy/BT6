### Title
`MetaOracle.combine` Uses Relative Staleness Window Without Absolute Clock Check, Allowing Stale Prices to Pass as Trusted — (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

### Summary

The `MetaOracle` in the Sui oracle framework computes its staleness window relative to the most recently added oracle's own stored timestamp (`max_timestamp`), rather than against the current on-chain clock. When all contributing `SimpleOracle` feeds have stale data (e.g., because the oracle operator was offline), the relative window still passes all data as fresh, and `median`/`mean` returns an arbitrarily old price as "trusted."

### Finding Description

`MetaOracle` is the production aggregation layer in `crates/sui-oracle/move/oracle/sources/meta_oracle.move`. It is constructed with a `time_window_ms` parameter intended to reject oracle readings that are too old:

```move
public struct MetaOracle<T> {
    oracle_data: vector<Option<Data<T>>>,
    threshold: u64,
    time_window_ms: u64,
    ticker: String,
    max_timestamp: u64,   // ← set from oracle data, never from Clock
}
``` [1](#0-0) 

When oracles are added, `max_timestamp` is overwritten with the timestamp embedded in the last oracle's stored data:

```move
public fun add_simple_oracle<T: copy + drop + store>(meta_oracle: &mut MetaOracle<T>, oracle: &SimpleOracle) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
    ...
}
``` [2](#0-1) 

The `combine` function then computes the staleness floor as `max_timestamp - time_window_ms` — a window anchored entirely to the oracle data's own timestamps, with no reference to the current on-chain `Clock`:

```move
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>): (vector<T>, vector<address>) {
    let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
    let min_timestamp = max_timestamp - time_window_ms;
    ...
    if (data::timestamp(&oracle_data) > min_timestamp) {
        // accepted as fresh
    }
``` [3](#0-2) 

Neither `combine`, `median`, nor `mean` accepts a `Clock` argument. There is no path in the `MetaOracle` API to compare stored timestamps against the current block time.

The underlying `SimpleOracle.get_latest_data` also returns data unconditionally, with no staleness guard:

```move
public fun get_latest_data<T: store + copy>(oracle: &SimpleOracle, ticker: String): Option<Data<T>> {
    if (!df::exists_(&oracle.id, ticker)) { return option::none() };
    let data: &StoredData<T> = df::borrow(&oracle.id, ticker);
    let StoredData { value, sequence_number, timestamp, identifier } = *data;
    option::some(data::new(value, ticker, sequence_number, timestamp, oracle.address, identifier))
}
``` [4](#0-3) 

### Impact Explanation

Any on-chain protocol that calls `MetaOracle::median` or `MetaOracle::mean` for financial decisions (FX conversion, collateral valuation, liquidation thresholds) will silently receive prices that may be hours or days old whenever the oracle operator is offline. The `MetaOracle` is designed to be the "trusted" aggregation layer, so callers have no reason to re-check the returned timestamp. This matches the **Medium** impact class: harmful smart-contract behavior reachable from public input. [5](#0-4) 

### Likelihood Explanation

The oracle operator's off-chain `DataProvider` loop runs on a configurable `submission_interval`. Any network disruption, process crash, or key rotation that interrupts the operator for longer than `time_window_ms` will leave all `SimpleOracle` objects with stale data. Because `max_timestamp` is derived from that stale data, the `MetaOracle` window slides backward with it and the stale readings pass the filter. [6](#0-5) 

### Recommendation

1. Add a `clock: &Clock` parameter to `combine`, `median`, and `mean`. Replace the relative anchor with an absolute check:
   ```move
   let now = clock::timestamp_ms(clock);
   assert!(max_timestamp + GRACE_PERIOD_MS >= now, EStaleOracle);
   let min_timestamp = now - time_window_ms;
   ```
2. In `SimpleOracle.get_latest_data`, either enforce a staleness bound via a `Clock` parameter, or document clearly that callers must validate `Data::timestamp` themselves before use. [3](#0-2) 

### Proof of Concept

1. Deploy the oracle package and create three `SimpleOracle` objects.
2. Call `submit_data` on each at time T=0 with price P.
3. Wait (or simulate) until the current clock is T=3600000 (1 hour later) without calling `submit_data` again.
4. Construct a PTB that calls:
   ```
   meta_oracle::new(3, 60000, "SUIUSD")   // 60-second window
   meta_oracle::add_simple_oracle(oracle1)
   meta_oracle::add_simple_oracle(oracle2)
   meta_oracle::add_simple_oracle(oracle3)
   meta_oracle::median(meta_oracle)        // returns price P from 1 hour ago
   ```
5. `max_timestamp` = T=0 (from the stored data). `min_timestamp` = T=0 − 60000. All three oracles have timestamp T=0 > min_timestamp, so all pass. `median` returns the 1-hour-old price P with no error or warning.
6. Any downstream financial function (e.g., `simple_fx`) uses P as if it were current. [7](#0-6)
