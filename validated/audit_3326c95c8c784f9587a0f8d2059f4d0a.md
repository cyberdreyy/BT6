### Title
`ExportDKGResult` exposes vault DKG key material to non-admin 'edit'-role users - ([File: core/web/vault_controller.go], [File: core/web/presenters/vault.go])

### Summary
The `/v2/vault/dkg_results/export` route is gated only by `auth.RequiresEditRole`, not `auth.RequiresAdminRole`, and `NewExportDKGResultResource` performs no ownership check before returning the raw hex-encoded `ReportWithResultPackage` for any `instanceId` supplied in the request body. Any authenticated user holding the minimal non-view/non-run role ("edit") can retrieve the full DKG result package for any DKG instance stored in the node's database.

### Finding Description
The route registration in `core/web/router.go` wires the export endpoint with the weakest privileged wrapper available: [1](#0-0) 

`auth.RequiresEditRole` only rejects `UserRoleView` and `UserRoleRun`; any user with `UserRoleEdit` (a role explicitly one tier below `UserRoleAdmin`) passes: [2](#0-1) 

Compare this to `RequiresAdminRole`, which is defined in the same file and strictly checks `user.Role != clsessions.UserRoleAdmin`: [3](#0-2) 

Inside `VaultController.ExportDKGResult`, the handler takes an attacker-supplied `instanceId`, looks it up via `vault.NewVaultORM(...).ReadResultPackage`, and if found, hex-encodes the stored `ReportWithResultPackage` and renders it via `presenters.NewExportDKGResultResource` with no additional authorization, ownership, or ACL check tying the caller to that specific DKG instance: [4](#0-3) 

`NewExportDKGResultResource` itself is a pure data-shaping function — it blindly serializes whatever `hexResult`/`sha` it is given into the JSON:API response, performing no redaction or role check of its own: [5](#0-4) 

Because there is no per-instance owner concept in the `dkg_results` table/ORM (`ReadResultPackage` returns the row purely by `instance_id`, with no user/tenant scoping), any "edit" role user can enumerate or guess `instanceId` values and export the corresponding key material bundle: [6](#0-5) 

### Impact Explanation
The exported bundle (`ReportWithResultPackage`) is the DKG result package used by the vault OCR2 plugin, containing config digest, sequence number, encrypted/attributed shares, and the report package needed to verify and reconstruct the threshold vault key material (the same object `VerifyDKGResult` uses to check TDH2 public-key correspondence). Exposing this to any "edit" role (not admin) user is a scoped credential-export / key-bundle-disclosure issue matching the "key export bundles or node secrets retrieved from a running node" impact class. The severity is somewhat mitigated by the fact that individual recipient shares inside the package are still encrypted to each participant node's own DKG recipient public key (see `vaultcap.VerifyDKGResult`/`dkgrecipientkey`), so this alone may not immediately yield plaintext blockchain private keys; however, it is still an authorization/data-exposure defect: an "edit" user without any special DKG/admin privilege can retrieve DON-wide vault protocol artifacts intended to be restricted to admin operators.

### Likelihood Explanation
Exploitation requires only an authenticated session/API token with `UserRoleEdit` (the codebase's second-weakest role, above `view`/`run`) — no admin, DB, or host access is needed. The request is a single unauthenticated-to-the-resource `POST /v2/vault/dkg_results/export` with a JSON body containing an `instanceId`. This is fully repeatable and requires no timing or race conditions, only knowledge/guessing of a valid `instanceId`.

### Recommendation
Change the route wrapper for both `/v2/vault/dkg_results/export` (and arguably `/v2/vault/dkg_results/verify`, which discloses SHA/verification info) from `auth.RequiresEditRole` to `auth.RequiresAdminRole` in `core/web/router.go`, consistent with other sensitive key-export endpoints in the codebase. Additionally, consider adding explicit audit logging on export access given the sensitivity of the material.

### Proof of Concept
Go handler-level integration test plan (extends `core/web/vault_controller_test.go`):
1. In `setupVaultControllerTests`, create a second HTTP client authenticated as a user with `sessions.UserRoleEdit` (non-admin) using existing `cltest` helpers for creating role-scoped sessions.
2. Seed a DKG result via `orm.WriteResultPackage` as done in `TestVaultController_ExportDKGResult`.
3. Using the edit-role client, `POST /v2/vault/dkg_results/export` with the seeded `instanceId`.
4. Assert `http.StatusOK` is returned and the response body's `hexDKGResultPackage` matches the seeded `ReportWithResultPackage` — proving a non-admin role can retrieve the export bundle.
5. Repeat with a `UserRoleView`/`UserRoleRun` client and assert `http.StatusUnauthorized`, confirming only `view`/`run` are blocked while `edit` (non-admin) succeeds — demonstrating the missing admin-only gate.

```go
		}

	}
}
```

```go
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
```

```go
func (o *orm) ReadResultPackage(ctx context.Context, iid dkgocrtypes.InstanceID) (*dkgocrtypes.ResultPackageDatabaseValue, error) {
	var configDigest []byte
	var seqNr uint64
	var reportWithResultPackage []byte
	var signatures pq.ByteaArray
	var signerOracleIDs []byte

	query := `SELECT config_digest, seq_nr, report_with_result_package, signatures, signer_oracle_ids FROM dkg_results WHERE instance_id = $1;`
	row := o.ds.QueryRowxContext(ctx, query, iid)
	err := row.Scan(&configDigest, &seqNr, &reportWithResultPackage, &signatures, &signerOracleIDs)
	if errors.Is(err, sql.ErrNoRows) {
		return nil, nil
	}
	if err != nil {
		return nil, errors.Wrap(err, "failed to read dkg result")
	}

	var cd types.ConfigDigest
	copy(cd[:], configDigest)

	attributedSigs := make([]types.AttributedOnchainSignature, len(signatures))
	for i := range signatures {
		attributedSigs[i] = types.AttributedOnchainSignature{
			Signature: signatures[i],
			Signer:    commontypes.OracleID(signerOracleIDs[i]),
		}
	}

	value := &dkgocrtypes.ResultPackageDatabaseValue{
		ConfigDigest:            cd,
		SeqNr:                   seqNr,
		ReportWithResultPackage: reportWithResultPackage,
		Signatures:              attributedSigs,
	}

	return value, nil
}
```
