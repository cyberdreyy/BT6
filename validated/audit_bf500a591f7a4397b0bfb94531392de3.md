### Title
Unauthenticated disclosure of internal LOOP plugin Prometheus metrics via GET /plugins/:name/metrics - (File: core/web/loop_registry.go)

### Summary
The route `GET /plugins/:name/metrics`, registered in `loopRoutes` and handled by `LoopRegistryServer.pluginMetricHandler`, is mounted on the base `api` router group without any `auth.Authenticate` middleware, unlike nearly every other sensitive route in `router.go`. Any network client that can reach the node's HTTP port can invoke this handler to proxy and read the internal Prometheus metrics of any registered LOOP plugin.

### Finding Description
In `core/web/router.go`, `NewRouter` mounts `loopRoutes(app, api)` directly on the `api` group (line 91) alongside other route groups, but unlike `debugRoutes` (wrapped with `auth.Authenticate(..., auth.AuthenticateBySession)`, line 181) or `authv2`/`userOrEI` groups, `loopRoutes` itself applies no authentication wrapper: [1](#0-0) 

Inside `loopRoutes`, `r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)` is registered directly on `r`, an unauthenticated group. The handler itself performs no auth/session check: [2](#0-1) 

Given only a valid plugin name (which can be enumerated via the equally unauthenticated `GET /discovery` handler that lists all registered plugin names, `discoveryHandler`, lines 53-81), the handler forwards a request to `http://<loopHostName>:<PrometheusPort>/metrics` on the internal LOOP plugin and returns the raw response body verbatim to the caller with no filtering or redaction. This differs from the node's own root `/metrics` Prometheus endpoint, which is optionally protected by a bearer token check in `prometheusHandler` (`core/web/router.go` lines 677-699) — no equivalent protection exists for the per-plugin metrics proxy.

### Impact Explanation
This is an information-disclosure vulnerability: unauthenticated network clients can retrieve internal LOOP (Loosely Coupled Plugin) telemetry, which may include operational details, internal addresses/ports, counts of job executions, or other Prometheus labels that reveal internal topology and operational state of the node's plugins. This matches the "sensitive data exposure without authentication" bounty class rather than direct fund loss, but it aids reconnaissance for further attacks against the node.

### Likelihood Explanation
No credentials, session, or role are required — only network reachability to the node's configured HTTP port. The attacker only needs a valid plugin name, which is itself unauthenticated and discoverable via the same missing-auth `/discovery` endpoint. This is trivially and repeatably reproducible with a single unauthenticated `curl`/HTTP GET.

### Recommendation
Wrap `loopRoutes` (or at minimum the `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*`, and pprof-symbol routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or token-based) middleware used for `debugRoutes` and `authv2`, so only authenticated operators/admins can access internal plugin telemetry and debug endpoints.

### Proof of Concept
1. Build a `chainlink.Application` test fixture with a `plugins.LoopRegistry` containing one registered plugin (e.g., name `"median"`) with a mocked/stub Prometheus endpoint returning a small metrics payload.
2. Construct the router via `web.NewRouter(app, nil)` and wrap it in `httptest.NewServer`.
3. Issue `GET /plugins/median/metrics` with no `Authorization` header and no session cookie.
4. Assert the response status is `200 OK` and the body equals the plugin's stubbed metrics payload, confirming the route is reachable without any authentication check, contrasting with an equivalent request to an authenticated route (e.g., `/v2/config`) which should return `401`.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
