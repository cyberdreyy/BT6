### Title
Stale OIDC-issued API tokens retain elevated role/access for full UserAPITokenDuration after IdP-side deprovisioning/downgrade - ([File: core/sessions/oidcauth/oidc.go])

### Summary
`FindUserByAPIToken` in `core/sessions/oidcauth/oidc.go` resolves an API token's user role solely from the `oidc_user_api_tokens` table, which caches the `user_role` at the time the token was issued (via `SetAuthToken`). The only validity check is a time-window check (`created_at + UserAPITokenDuration >= now()`); there is no mechanism anywhere in the codebase that re-validates the cached role against the OIDC provider's current claims/groups before that window expires.

### Finding Description
`SetAuthToken` writes the `user.Role` into `oidc_user_api_tokens` at token-creation time [1](#0-0) . `FindUserByAPIToken` later authenticates a request purely by looking up that cached role and checking only the expiry window, never re-querying claims or contacting the OIDC provider: [2](#0-1) . The inline comment claims "sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation" [3](#0-2) , but the actual `reaper.go` implementation only performs a time-based `DELETE FROM oidc_sessions WHERE created_at < $1` on session records - it never touches `oidc_user_api_tokens`, never contacts the IdP, and performs no claims re-validation at all [4](#0-3) . There is no separate "sync.go" analog for OIDC API tokens (unlike LDAP, which has `ldapauth/sync.go`); the OIDC authenticator has no upstream re-check path for issued API tokens whatsoever.

Consequently, once a token is minted with an elevated role (e.g. Admin, via `IDClaimsToUserRole` mapping OIDC group claims at token-issuance time [5](#0-4) ), that role is fixed in the database and used verbatim by `FindUserByAPIToken` for every subsequent API request until the row's `created_at + UserAPITokenDuration` elapses - regardless of any IdP-side group/role change or deprovisioning in the interim.

The route-level `RequiresAdminRole` (or similar role-gating) middleware consumes the `User.Role` value returned by `FindUserByAPIToken`/`AuthenticationProvider` [6](#0-5)  and has no independent means to detect that the cached role diverges from the user's live IdP state, so it cannot stop this.

### Impact Explanation
A user whose OIDC role is downgraded (e.g. Admin → View) or whose account is fully deprovisioned at the IdP retains full use of their previously issued Chainlink node API token, including admin-role-gated routes, for up to `UserAPITokenDuration` after the IdP-side change. This is an unrevoked-credential / stale-authorization issue matching Chainlink's "authentication/authorization bypass" bounty class: an entity that should no longer have elevated access can still perform admin actions (job management, key/config changes, etc.) via the node API.

### Likelihood Explanation
Requires: OIDC auth mode enabled, `UserAPITokenEnabled=true`, and the user previously obtained an API token while still holding an elevated role. No additional exploitation steps are needed beyond continuing to use the already-possessed token after the IdP revokes/downgrades access - this is 100% reproducible and requires no special skill, only possession of a previously valid credential that should have been invalidated.

### Recommendation
On each `FindUserByAPIToken` call (or on a periodic/reaper cadence), re-validate the cached role against the OIDC provider's current claims - e.g., by performing a token introspection/userinfo call against the IdP, or by shortening `UserAPITokenDuration` and layering a background re-sync job (as exists for LDAP via `ldapauth/sync.go`) that walks `oidc_user_api_tokens`, re-fetches group membership, and updates/revokes the cached role/rows when it changes upstream. At minimum, fix the misleading comment and implement the described "UpstreamSyncInterval"-based sync for OIDC tokens.

### Proof of Concept
Go test plan (extending `core/sessions/oidcauth/oidc_test.go`):
1. `setupAuthenticationProvider(t)` to get `oidcAuthProvider` and `db`.
2. Insert a row into `oidc_user_api_tokens` with `user_role = 'admin'` and `created_at = now()` for `testEmail`.
3. Call `FindUserByAPIToken(ctx, apiToken)` and assert it returns `UserRoleAdmin` - confirms token is currently usable with elevated role.
4. Simulate IdP-side downgrade: there is no API in `oidcAuthenticator` to re-check claims, only `UpdateRole`, which returns `clsessions.ErrNotSupported` [7](#0-6) , and no method exists to force re-validation of an existing token against fresh claims.
5. Advance time to just before `UserAPITokenDuration` expiry (e.g., `UserAPITokenDuration - 1s`) and call `FindUserByAPIToken` again - assert it still returns `UserRoleAdmin`, proving the stale elevated role persists with no re-check against the IdP, satisfying the "undeletable/stale elevated access" impact described.
6. Assert (expected to fail against current code, demonstrating the bug) that there is no code path causing `FindUserByAPIToken` to return an error or downgraded role before full `UserAPITokenDuration` elapses when the upstream IdP claims have changed.

func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil

func (oi *oidcAuthenticator) IDClaimsToUserRole(idClaims []string, adminClaim string, editClaim string, runClaim string, readClaim string) (clsessions.UserRole, error) {
	// If defined Admin group name is present in id claims, return UserRoleAdmin
	if slices.Contains(idClaims, adminClaim) {
		return clsessions.UserRoleAdmin, nil
	}
	// Check edit role
	if slices.Contains(idClaims, editClaim) {
		return clsessions.UserRoleEdit, nil
	}
	// Check run role
	if slices.Contains(idClaims, runClaim) {
		return clsessions.UserRoleRun, nil
	}
	// Check view role
	if slices.Contains(idClaims, readClaim) {
		return clsessions.UserRoleView, nil
	}
	// No role group found, error
	return clsessions.UserRoleView, ErrUserNoOIDCGroups
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE created_at < $1", before)
	return err
}
