### Title
Credit vault deployed with `borrower == address(0)` opens deposits whose funds are permanently burned (or forced into default) at the first `startEpoch` - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.initialize` sets `borrower` without a zero-address check, even though `setBorrower` enforces `require(_borrower != address(0))`. The factory `deployCreditVault`/`deployRevolvingCreditVault` path validates `manager` but never validates `strategyData.borrower`. The vault is fully operational for deposits in this state — `IdleCDOEpochVariant._deposit` and `requestWithdraw` only require `isWalletAllowed`, and a vault with `keyring == address(0)` accepts any wallet. When the owner/manager calls `startEpoch`, `sendFundsToBorrower` transfers all vault underlyings to `address(0)`.

### Finding Description
- `IdleCreditVault.initialize` assigns `borrower = _borrower` with no `address(0)` check (`contracts/strategies/idle/IdleCreditVault.sol`, `initialize` at line 124; `setBorrower` at line 190 does check `IS_0`, so the omission in `initialize` is inconsistent).
- `IdleCreditVaultFactory._deployBaseCreditVault` passes `strategyData.borrower` unchecked; only `manager` is validated (`contracts/IdleCreditVaultFactory.sol`, `_deployBaseCreditVault` line 182-193 and `deployCreditVault` line 99).
- `IdleCDOEpochVariant.startEpoch` calls `sendFundsToBorrower`, which does `_transferUnderlyings(_borrower(), _amount)` — transferring the entire vault balance (buffer deposits + interest) to the borrower address (`contracts/IdleCDOEpochVariant.sol`, `startEpoch` line 233-304, `sendFundsToBorrower` line 308-311).
- With `borrower == address(0)`:
  - For tokens that revert on zero-address transfers, the `try/catch` routes to `_handleBorrowerDefault`, pausing the vault and forcing a hard-default recovery flow for funds that were never actually lent.
  - For tokens that accept zero-address transfers (many non-OZ implementations), the depositors' underlyings are permanently burned — full insolvency with tranche prices intact until a write-off/default is declared.

### Impact Explanation
All deposited principal of unprivileged KYC'd lenders is either permanently burned (tokens allowing zero-address transfers → total, irrecoverable loss) or pushed into the hard-default path where recovery depends on the owner supplying `finalizeDefault` funds. This matches the external bug class exactly: a single missing zero-check at initialization produces a vault that appears valid, accepts user funds, and is bricked/insolvent on first use.

### Likelihood Explanation
Requires a privileged deployment error (omitting the borrower), same precondition class as the original OpenQ finding — but the blast radius is far larger: user principal loss rather than wasted gas. The factory path makes the omission plausible since it validates `manager` but silently accepts `borrower == address(0)`, and the vault passes all deposit-side checks (`isWalletAllowed`, pause, flags), so users have no on-chain signal that it is misconfigured until `startEpoch` executes.

### Recommendation
Add `require(_borrower != address(0))` (or `revert Is0()`) in `IdleCreditVault.initialize`, mirroring `setBorrower`. Additionally, validate `strategyData.borrower != address(0)` in `IdleCreditVaultFactory.deployCreditVault` and `deployRevolvingCreditVault` alongside the existing `manager` check. Optionally, have `startEpoch` defensively revert if `_borrower() == address(0)`.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;
import "forge-std/Test.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract BorrowerZeroInitPoC is Test {
    IdleCreditVault strategy;
    IdleCDOEpochVariant cdo;
    address usdc = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;
    address owner = address(0x1);
    address manager = address(0x2);
    address lender = address(0x3);

    function setUp() public {
        vm.createSelectFork("mainnet");
        strategy = new IdleCreditVault();
        // borrower = address(0) accepted by initialize
        strategy.initialize(usdc, owner, manager, address(0), "B", 10e18);
        cdo = new IdleCDOEpochVariant();
        cdo.initialize(0, usdc, owner, owner, address(0), address(strategy), 100000);
        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));
        deal(usdc, lender, 1_000_000e6);
        vm.prank(lender);
        IERC20Detailed(usdc).approve(address(cdo), type(uint256).max);
    }

    function test_DepositThenStartEpochWithZeroBorrower() public {
        // Unprivileged lender deposits normally — all checks pass
        vm.prank(lender);
        cdo.depositAA(1_000_000e6);

        // Owner starts epoch: funds are pushed to address(0)
        // - tokens reverting on zero-transfer -> _handleBorrowerDefault (forced default)
        // - tokens allowing zero-transfer -> principal permanently burned
        vm.prank(owner);
        cdo.startEpoch();

        // Depositor funds are either burned or locked behind a default recovery
        // that requires the owner to supply replacement capital via finalizeDefault.
        assertTrue(cdo.defaulted() || IERC20Detailed(usdc).balanceOf(address(0)) > 0);
    }
}
```

Note: the run command is `forge test --match-test test_DepositThenStartEpochWithZeroBorrower` on a mainnet fork. The exact branch (revert→`defaulted` vs silent burn) depends on whether the underlying ERC20 reverts on zero-address transfers; the zero-check is missing regardless, and the loss path is determined by token choice, which the integrator controls.
