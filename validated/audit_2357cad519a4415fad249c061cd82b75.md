### Title
Signer emits a valid `BlockAccepted` signature for a block already marked `GloballyRejected`, because `BlockInfo::mark_locally_accepted`/`mark_pre_committed` mutate signing fields before the guarded state transition, and callers ignore the transition failure - ([File: stacks-signer/src/v0/signer.rs])

### Summary
The signer's `BlockInfo` state machine is supposed to make `GloballyRejected` (and `GloballyAccepted`) terminal: no further local acceptance is allowed once a block reaches global rejection. `BlockInfo::check_state` correctly encodes this rule, and `move_to` returns an `Err` when the illegal transition is attempted. However, both `mark_pre_committed` and `mark_locally_accepted` set their side-effect fields (`valid`, `approved_time`, `signed_self`) *before* calling `move_to`, and never roll those fields back when `move_to` fails. Worse, the two call sites in `signer.rs` that invoke these functions treat the `Err` as non-fatal once the block `has_reached_consensus()`, and fall straight through to signing and broadcasting an acceptance.

### Finding Description
`BlockInfo::mark_locally_accepted` in [1](#0-0)  unconditionally sets `signed_self` (and `valid`) before calling `self.move_to(BlockState::LocallyAccepted)`. `move_to`/`check_state` in [2](#0-1)  correctly forbid the `GloballyRejected -> LocallyAccepted` transition, but the caller never inspects whether the fields it just wrote are still meaningful.

In `handle_block_pre_commit`, after the pre-commit threshold and conflict checks pass, the code does:
```
if let Err(e) = block_info.mark_locally_accepted(false) {
    if !block_info.has_reached_consensus() {
        warn!(...);
    }
}
...
let accepted = self.create_block_acceptance(&block_info.block);
self.handle_block_signature(stacks_client, sortition_state, &accepted);
self.send_block_response(&block_info.block, accepted.into());
``` [3](#0-2) 
The `Err` path is only used to decide whether to log a warning - execution is never aborted. If `block_info.state` was already `GloballyRejected`, `mark_locally_accepted` returns `Err`, is silently swallowed (since `has_reached_consensus()` is true), and the function still creates and broadcasts a genuine signature (`create_block_acceptance`) over the already-globally-rejected block.

The upstream caller, `handle_block_validate_ok`, has the same pattern for `mark_pre_committed`:
```
if let Err(e) = block_info.mark_pre_committed() {
    if !block_info.has_reached_consensus()
        && block_info.state != BlockState::LocallyAccepted
    {
        warn!(...); return;
    }
}
... insert_block ...
self.send_block_pre_commit(signer_signature_hash.clone());
self.handle_block_pre_commit(stacks_client, sortition_state, &address, signer_signature_hash);
``` [4](#0-3) 
Here too, once `has_reached_consensus()` is true (i.e. the block is already `GloballyAccepted` or `GloballyRejected`), the early return is skipped and the handler proceeds to re-send a pre-commit and re-invoke `handle_block_pre_commit`, feeding directly into the bug above. `mark_pre_committed` itself also sets `valid = Some(true)` unconditionally before the guarded `move_to` call: [5](#0-4) .

This means the "one last look" invariant documented for the signing path - "re-check chainstate before putting a signature over the block" (comment at [6](#0-5) ) - is silently defeated for a block that has already reached the *most final* state of all: global rejection. The signer's own `signerdb` state and the signature it emits become inconsistent: `state == GloballyRejected` yet `signed_self.is_some()` and a fresh valid `BlockAccepted` message has been gossiped.

### Impact Explanation
This is a "rejection recounted as an accept" safety break as defined by the reachable-analog rules: a delayed, otherwise-honest own-validation response (`BlockValidateOk`) or a delayed peer `BlockPreCommit` gossip message arriving after this signer's local `signerdb` has already recorded the block as `GloballyRejected` (because >30% weight rejected it, per `handle_block_rejection` at [7](#0-6) ) causes the vulnerable signer to nonetheless emit and broadcast a fresh, cryptographically valid `BlockAccepted` signature for that block. If the pre-commit weight that had already accumulated before the reject threshold was crossed was close to 70% (entirely plausible, since accept/pre-commit and reject tallies are independent per-signer paths), this signer's late signature can push the block over the acceptance threshold on other signers' views, contradicting the block's already-recorded `GloballyRejected` status. This directly breaks the "aggregated-weight vs verified-accepts" and "rejection recounted as an accept" equalities the scan is looking for, and is Critical because it is a real, standards-conformant signature over a block the network is supposed to have permanently killed.

### Likelihood Explanation
No majority collusion or key compromise is required. The trigger is purely a message-ordering race that a miner can encourage by:
- proposing a block that most signers quickly reject (invalid/conflicting/non-canonical) while a strict subset pre-commits first, and
- naturally-occurring or miner-induced latency in this signer's own `/v3/block_proposal` validation call (`validation_time_ms`) or in gossip delivery of its own pre-commit,
so that `handle_block_validate_ok`/`handle_block_pre_commit` are invoked for this signer only after the block has already reached `GloballyRejected` in its local `signerdb`. This requires only one slot's worth of message-timing manipulation plus normal gossip, matching the in-scope reachable-path constraints.

### Recommendation
Make `BlockInfo::mark_pre_committed` and `mark_locally_accepted` atomic with respect to `move_to`: only set `valid`/`approved_time`/`signed_self`/`signed_group` if `move_to` succeeds (e.g., call `move_to` first and only mutate fields on `Ok`, or roll back on `Err`). Additionally, in `handle_block_validate_ok` and `handle_block_pre_commit`, treat any `Err` from these mark functions as fatal for the *current* signing attempt whenever `block_info.has_reached_consensus()` is true - explicitly `return` rather than falling through to `create_block_acceptance`/`send_block_pre_commit`.

### Proof of Concept
1. Miner proposes block `B`. Several signers with combined weight just under 70% receive it quickly, validate it, and pre-commit (`mark_pre_committed`, stored via `add_block_pre_commit`).
2. A different set of signers, combined weight >30%, reject `B` (invalid/conflicting) faster than the victim signer's own validation response arrives; once total reject weight crosses the "70% acceptance now impossible" bound, every signer including the victim moves its local `BlockInfo` for `B` to `GloballyRejected` via `handle_block_rejection` → `mark_globally_rejected` (`stacks-signer/src/v0/signer.rs:2335`).
3. The victim signer's own delayed `BlockValidateOk` for `B` now arrives. `handle_block_validate_ok` runs: `block_info.valid` was still `None` so the "already processed" guard does not fire; `check_block_against_signer_db_state` passes; `mark_pre_committed()` sets `valid = Some(true)` and fails to `move_to(PreCommitted)` (prev state `GloballyRejected`), but because `has_reached_consensus()` is true the function does not return - it inserts the block, sends a pre-commit, and calls `handle_block_pre_commit` for itself.
4. `handle_block_pre_commit` sees `signed_self.is_none()` and `valid == Some(true)` (forced by step 3), tallies pre-commit weight (already close to 70% from step 1) crossing the threshold, passes the chainstate/conflict re-checks (nothing prevents this since `B`'s chain position is still consistent), and calls `mark_locally_accepted(false)`, which sets `signed_self = Some(now)` and fails `move_to(LocallyAccepted)` (prev state `GloballyRejected`) - the `Err` is swallowed because `has_reached_consensus()` is true.
5. Execution falls through unconditionally to `create_block_acceptance(&block_info.block)` and `send_block_response(..., accepted.into())`: a valid `BlockAccepted` signature over `B` is broadcast, even though this same signer's `signerdb` still records `B` as `GloballyRejected`.

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

    /// Attempt to transition the block state
    pub fn move_to(&mut self, state: BlockState) -> Result<(), String> {
        if !self.check_state(state) {
            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
    }
