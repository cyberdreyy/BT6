### Title
Missing `return` After Email-Extraction Failure Lets OIDC Login Proceed and Create an Authenticated Admin Session With an Empty/Wrong Email - (File: core/sessions/oidcauth/oidc.go)

### Summary
In `oidcAuthenticator.handleTokenExchange`, when the `email` claim cannot be extracted from the verified OIDC ID token, the handler logs the error and writes an HTTP 500 response but does **not** `return`. Execution falls through and continues to compute the RBAC role, insert a new row into `oidc_sessions`, and set the session cookie — completing a full, valid, authenticated login with an empty `user_email` field, exactly the same class of bug as the reported `_getReserves` case where a missing `return` silently propagates a zero/uninitialized value into downstream logic instead of aborting.

### Finding Description
The relevant code: [1](#0-0) 

```go
email, ok := claims["email"].(string)
if !ok {
    oi.lggr.Errorf("Failed to get email from claims. error: %v", err)
    c.String(http.StatusInternalServerError, "Failed to get email from claims")
}
```

Unlike every other error branch in the same function (all of which call `return` immediately after writing an error response, e.g. the `id_token` extraction check, the ID token verification check, and the claims-parsing check), this branch is missing the `return` statement: [2](#0-1) 

As a result, when `!ok` (the `email` claim is absent or not a string in the provider's ID token), the handler continues past this point using `email` set to its zero value (`""`) and proceeds to:
1. Compute the RBAC `role` from `idClaims` via `IDClaimsToUserRole` (unrelated to `email`), [3](#0-2) 
2. Insert a new row into `oidc_sessions` with `user_email = ""` and the resolved `role`, [4](#0-3) 
3. Persist the session cookie (`SessionIDKey`) and return `200 OK` with `Success: true`, overwriting the earlier `500` response that was already written. [5](#0-4) 

This session is fully valid for subsequent requests: `AuthorizedUserWithSession` looks the session up purely by session ID and returns whatever `user_email`/`user_role` was stored, without re-validating that email is non-empty: [6](#0-5) 

That result is trusted directly by both the session-based and GraphQL authentication middlewares to authorize API/UI access: [7](#0-6) [8](#0-7) 

The role-based resolvers (`authenticateUserIsAdmin`, `authenticateUserCanEdit`, etc.) only check `session.User.Role`, not the email, so a session with an empty email but an admin-mapped OIDC group claim still passes admin authorization checks. [9](#0-8) 

### Impact Explanation
An unprivileged actor who can complete the OIDC authorization-code flow (i.e., anyone who can authenticate against the configured external IdP, potentially including self-service/social IdPs or any IdP that omits the `email` claim for some accounts) can obtain a fully valid, cookie-based Chainlink Node session whose `user_email` is stored as an empty string, while the `user_role` is still derived from whatever admin/edit/run/read group claims are present in the token. Because downstream authorization (`authenticateUserIsAdmin`, `authenticateUserCanEdit`, GraphQL mutations) is role-based and does not depend on a non-empty email, this can grant a working administrative session in the node UI/API despite the intended failure path. It also silently corrupts the `oidc_sessions` table with an empty-email session that will be indistinguishable from a "no user" record in any subsequent lookups keyed by email, and returns a misleading `200 Success: true` to the client instead of the intended `500` error (response confusion — two writes to the same `gin.Context`, second overriding the first).

### Likelihood Explanation
Reachability requires only completing the standard OIDC login flow exposed to any user who can reach the node's `/sessions/oidc/*` (or equivalent) HTTP endpoints and is able to authenticate at the external IdP — no special privilege on the Chainlink node itself is required. Whether the `email` claim is actually missing depends on the configured IdP/provider behavior and scope configuration, so exploitability is provider-dependent, but the code path is real and silently reachable whenever email is absent from the ID token claims (e.g., a misconfigured or minimal-scope IdP integration, or an IdP that returns emails only conditionally).

### Recommendation
Add the missing `return` statement immediately after the error response in the `email` extraction check, matching the pattern used by every other error branch in `handleTokenExchange`:

```diff
 email, ok := claims["email"].(string)
 if !ok {
     oi.lggr.Errorf("Failed to get email from claims. error: %v", err)
     c.String(http.StatusInternalServerError, "Failed to get email from claims")
+    return
 }
```

### Proof of Concept
1. Configure the node with OIDC authentication such that the ID token returned by the IdP does not include an `email` claim (or returns a non-string value for it), while the token does include a group claim matching `oi.config.AdminClaim()`.
2. Complete the OAuth2/OIDC authorization code flow against `/sessions/oidc/*` login and callback endpoints as documented in `handleSignIn`/`handleTokenExchange`. [10](#0-9) 
3. In `handleTokenExchange`, the `email` claim assertion fails (`ok == false`); the handler writes a `500` response but does not return.
4. Execution falls through, computes `role = UserRoleAdmin` from the admin group claim, inserts an `oidc_sessions` row with `user_email = ""` and `user_role = admin`, sets the session cookie, and finally overwrites the response with `200 { "success": true }`.
5. Subsequent requests carrying the resulting session cookie are authenticated via `AuthenticateBySession`/`AuthenticateGQL`, which call `AuthorizedUserWithSession` and receive a `User{Email: "", Role: UserRoleAdmin}`; `authenticateUserIsAdmin` passes since only `Role` is checked, granting admin-level GraphQL mutation access despite the intended authentication failure.

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired
func (oi *oidcAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (clsessions.User, error) {
	if len(sessionID) == 0 {
		return clsessions.User{}, errors.New("session ID cannot be empty")
	}
	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc_sessions table for given session ID, user role and email are saved after the id claims is provided and validated
		var foundSession struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundSession,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_sessions WHERE id = $1",
			sessionID, oi.config.SessionTimeout().Duration(),
		); err != nil {
			if errors.Is(err, sql.ErrNoRows) {
				return clsessions.ErrUserSessionExpired
			}
			return err
		}
		if !foundSession.Valid {
			// Sessions expired, purge
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundSession.UserEmail,
			Role:  foundSession.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE id = $1", sessionID); execErr != nil {
				oi.lggr.Errorf("error purging stale OIDC session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func AuthenticateGQL(authenticator Authenticator, lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		ctx := c.Request.Context()
		session := sessions.Default(c)
		sessionID, ok := session.Get(SessionIDKey).(string)
		if !ok {
			return
		}

		user, err := authenticator.AuthorizedUserWithSession(ctx, sessionID)
		if err != nil {
			if errors.Is(err, clsessions.ErrUserSessionExpired) {
				lggr.Warnw("Failed to authenticate session", "err", err)
			} else {
				lggr.Errorw("Failed call to AuthorizedUserWithSession, unable to get user", "err", err)
			}
			return
		}

		ctx = WithGQLAuthenticatedSession(c.Request.Context(), user, sessionID)

		c.Request = c.Request.WithContext(ctx)
	}
}

func authenticateUserIsAdmin(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role != sessions.UserRoleAdmin {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}
