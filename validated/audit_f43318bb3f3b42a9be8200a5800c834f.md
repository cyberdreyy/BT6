### Title
Unbounded token multiplier/interest-rate computation produces `Infinity`/misreported `ui_amount` in RPC token responses - ([File: account-decoder/src/parse_token.rs])

### Summary
`token_amount_to_ui_amount_v3` computes the human-readable `ui_amount` for SPL Token-2022 mints that use the `InterestBearingConfig` or `ScaledUiAmountConfig` extensions without any bounds/sanity checking on the resulting value, similar in class to the reported DeFi bug where an unvalidated fixed/derived numeric factor (slippage tolerance) is applied to compute a value without accounting for extreme inputs. Because Token-2022 mints and their multiplier/rate parameters are created and updated permissionlessly by any unprivileged user, an attacker can create a mint whose extension parameters cause the computed `ui_amount` to overflow to `f64::INFINITY`, which any RPC client querying that mint/account will receive as part of `getTokenAccountBalance`, `getTokenSupply`, or `getAccountInfo`/`getProgramAccounts` with `jsonParsed` encoding.

### Finding Description
`token_amount_to_ui_amount_v3` in `account-decoder/src/parse_token.rs` computes `ui_amount` either via `interest_bearing_config.amount_to_ui_amount(...)` or `scaled_ui_amount_config.amount_to_ui_amount(...)` when the mint carries those Token-2022 extensions: [1](#0-0) 

The unit tests demonstrate that with attacker-chosen extension parameters (e.g. an extreme `current_rate`/`pre_update_average_rate` for interest, or `new_multiplier: f64::INFINITY` for the scaled UI amount extension) combined with `amount = u64::MAX`, the resulting `ui_amount` becomes `Some(f64::INFINITY)` and `ui_amount_string == "inf"`: [2](#0-1) [3](#0-2) 

Both the `InterestBearingConfig` and `ScaledUiAmountConfig` extensions on Token-2022 mints can be initialized and updated by any holder of the corresponding (mint-creator-chosen) authority — there is no protocol-level bound preventing an authority from setting `current_rate`/`multiplier` to arbitrarily large values, and the arithmetic in the UI-amount conversion path performs no clamping to finite/sane bounds before it is placed into `UiTokenAmount.ui_amount`, unlike the raw on-chain `amount`, which remains a correct `u64`.

This value flows directly into JSON-RPC responses through:
- `JsonRpcRequestProcessor::get_token_account_balance` / `get_token_supply` in `rpc/src/rpc.rs` (calls `token_amount_to_ui_amount_v3` directly on bank-state mint/account data): [4](#0-3) 
- `getAccountInfo`/`getProgramAccounts` with `jsonParsed` encoding via `get_parsed_token_account` → `get_additional_mint_data` → `encode_ui_account`: [5](#0-4) [6](#0-5) 

`f64::INFINITY`/`NaN` values are not representable in standard JSON; serde_json silently coerces non-finite floats to `null` on serialization. As a result, any RPC consumer calling these read-only, unprivileged endpoints against such a mint receives `ui_amount: null` (or, depending on serializer configuration, a malformed/ambiguous numeric literal) instead of the true balance/supply — a wrong-data-returned condition stemming from an unbounded/unchecked calculation, analogous in root cause to the reported hardcoded/unvalidated tolerance factor producing incorrect results under extreme conditions.

### Impact Explanation
This is a misreporting bug reachable through standard, permissionless JSON-RPC read endpoints (`getTokenAccountBalance`, `getTokenSupply`, `getAccountInfo`/`getProgramAccounts` with `jsonParsed`). Any wallet, exchange, or downstream service relying on the RPC-reported `ui_amount` for balances/supply of an affected Token-2022 mint would receive `null`/incorrect values instead of the actual amount, which can mislead automated systems that trust the RPC-reported UI amount (e.g., for display, accounting, or trigger logic) — impact is Medium, since raw `amount`/`decimals` remain correct and this does not affect consensus state or fund custody directly, but does corrupt query results served by the validator's public API.

### Likelihood Explanation
Likelihood is Medium: creating a Token-2022 mint and setting an interest-bearing or scaled-ui-amount extension with extreme parameters requires no special privilege — it can be done by any user with the mint/extension authority keys they themselves generate at mint-creation time, and any subsequent RPC query to a public/unprivileged JSON-RPC endpoint for that mint's accounts triggers the miscalculation.

### Recommendation
Clamp/validate the computed `ui_amount` in `token_amount_to_ui_amount_v3` (and the underlying `amount_to_ui_amount` implementations for `InterestBearingConfig`/`ScaledUiAmountConfig`) to finite values before constructing `UiTokenAmount`; when the computed value is non-finite, omit `ui_amount` (already `Option<f64>`) while still returning a well-defined `ui_amount_string` (e.g., an explicit sentinel or error indicator) instead of a value that silently degrades to `null` during JSON serialization, so RPC consumers can distinguish "extension parameters produced an out-of-range value" from "the value is legitimately null."

### Proof of Concept
The existing unit tests already demonstrate the underlying computation producing `Infinity`: [7](#0-6) [8](#0-7) 
An end-to-end PoC would: (1) create an SPL Token-2022 mint with `InitializeScaledUiAmountConfig`/`UpdateMultiplier` (or interest-bearing config) set to an extreme rate/multiplier; (2) mint/hold a large token amount; (3) call `getTokenAccountBalance`/`getTokenSupply`/`getAccountInfo` with `jsonParsed` against a live validator RPC and observe `ui_amount` returned as `null` while the raw `amount` remains correct.

pub fn token_amount_to_ui_amount_v3(
    amount: u64,
    additional_data: &SplTokenAdditionalDataV2,
) -> UiTokenAmount {
    let decimals = additional_data.decimals;
    let (ui_amount, ui_amount_string) = if let Some((interest_bearing_config, unix_timestamp)) =
        additional_data.interest_bearing_config
    {
        let ui_amount_string =
            interest_bearing_config.amount_to_ui_amount(amount, decimals, unix_timestamp);
        (
            ui_amount_string
                .as_ref()
                .and_then(|x| f64::from_str(x).ok()),
            ui_amount_string.unwrap_or("".to_string()),
        )
    } else if let Some((scaled_ui_amount_config, unix_timestamp)) =
        additional_data.scaled_ui_amount_config
    {
        let ui_amount_string =
            scaled_ui_amount_config.amount_to_ui_amount(amount, decimals, unix_timestamp);
        (
            ui_amount_string
                .as_ref()
                .and_then(|x| f64::from_str(x).ok()),
            ui_amount_string.unwrap_or("".to_string()),
        )
    } else {
        let ui_amount = 10_usize
            .checked_pow(decimals as u32)
            .map(|dividend| amount as f64 / dividend as f64);
        (ui_amount, real_number_string_trimmed(amount, decimals))
    };

    pub fn get_token_account_balance(
        &self,
        pubkey: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let account = bank.get_account(pubkey).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;

        if !is_known_spl_token_id(account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token account".to_string(),
            ));
        }
        let token_account = StateWithExtensions::<TokenAccount>::unpack(account.data())
            .map_err(|_| Error::invalid_params("Invalid param: not a Token account".to_string()))?;
        let mint = &Pubkey::from_str(&token_account.base.mint.to_string())
            .expect("Token account mint should be convertible to Pubkey");
        let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
        let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
        Ok(new_response(&bank, balance))
    }

    pub fn get_token_supply(
        &self,
        mint: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;
        if !is_known_spl_token_id(mint_account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token mint".to_string(),
            ));
        }
        let mint = StateWithExtensions::<Mint>::unpack(mint_account.data()).map_err(|_| {
            Error::invalid_params("Invalid param: mint could not be unpacked".to_string())
        })?;

        let interest_bearing_config = mint
            .get_extension::<InterestBearingConfig>()
            .map(|x| (*x, bank.clock().unix_timestamp))
            .ok();

        let scaled_ui_amount_config = mint
            .get_extension::<ScaledUiAmountConfig>()
            .map(|x| (*x, bank.clock().unix_timestamp))
            .ok();

        let supply = token_amount_to_ui_amount_v3(
            mint.base.supply,
            &SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            },
        );
        Ok(new_response(&bank, supply))
    }

                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
