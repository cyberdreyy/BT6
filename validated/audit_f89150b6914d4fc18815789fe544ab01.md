### Title
Signer aggregates peer acceptances and rebroadcasts a block without checking its own validation verdict - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` (the function that tallies peer `BlockResponse::Accepted` signatures toward the 70% signing threshold) never checks `block_info.valid` before counting an incoming peer signature or before calling `broadcast_signed_block`. This is inconsistent with the sibling aggregation path, `handle_block_pre_commit`, which explicitly refuses to progress a block that this signer has not validated or has already marked invalid: `if !block_info.valid.unwrap_or(false) { ... return; }` [1](#0-0) .

### Finding Description
When another signer's `Accepted` signature arrives, `handle_block_signature` recovers the pubkey, checks it belongs to the signer set, and then unconditionally forwards it to `store_and_process_block_signature` [2](#0-1) .

Inside `store_and_process_block_signature`, the signature is stored, the peer's weight is tallied via `compute_signature_signing_weight`, and once the tally reaches `min_weight` the block is moved to `LocallyAccepted` and `broadcast_signed_block` is invoked — using the aggregated peer signature set, not this signer's own signature — with no gate on `block_info.valid` or the block's local rejection state: [3](#0-2) .

By contrast, the parallel aggregation path for pre-commits explicitly enforces that this signer has itself validated the block as `valid == true` before it will act on accumulated peer weight: [4](#0-3) . `BlockState::check_state` also permits the transition `LocallyRejected -> LocallyAccepted` ("re-evaluated" in the documented lifecycle) [5](#0-4) , so a block this signer previously rejected locally is not protected from being flipped to `LocallyAccepted` purely by peer-signature weight, without the check that gates the pre-commit path.

This breaks the intended equality "a signer only helps assemble/relay a signature set for a block it validated as valid" — the signed-vs-validated equality that the rest of the pre-commit/signing pipeline (sections 4 and 5 of the documented flow, `check_block_against_signer_db_state`) is built to preserve [6](#0-5) .

### Impact Explanation
If a signer has rejected a block locally (e.g., `valid == Some(false)`, or has never been asked to validate it because pending responses were drained straight into this function), it can still be driven by other signers' `Accepted` messages into `mark_locally_accepted` and `broadcast_signed_block`/`handle_post_block`, pushing the block to its own node — despite the local validator having deemed the block invalid or unsafe. This does not itself forge a new valid signature (the aggregated signatures still belong to real signers), but it means the local safety checks that are supposed to gate the aggregation-driven auto-forward step (present in the sibling pre-commit path) are absent here, causing invalid/rejected-by-this-signer blocks to be actively relayed to the node as "locally accepted" once peers reach threshold. This falls under the "aggregated-weight vs verified-accepts" equality break called out as in-scope Critical impact class.

### Likelihood Explanation
Reachable by ordinary signer traffic (no majority-signer collusion required): any one-slot miner/gossip path that gets ≥70% weight of *other* signers to legitimately or maliciously accept a block that this particular signer rejected will trigger this signer to relay it, since nothing in `store_and_process_block_signature` re-checks `block_info.valid`/`reject_reason` before broadcasting. The asymmetry with `handle_block_pre_commit` (which does check) strongly suggests this is a missing guard rather than intentional design.

### Recommendation
Add the same validity/rejection-state guard used in `handle_block_pre_commit` to `store_and_process_block_signature` before tallying weight and before calling `mark_locally_accepted`/`broadcast_signed_block` — i.e., bail out (or re-run `check_block_against_signer_db_state`) if `block_info.valid != Some(true)` or the block is already `LocallyRejected`/`GloballyRejected`.

### Proof of Concept
Not independently executed (no filesystem/terminal access in this session; analysis based on static code reading). Conceptual repro: have a signer receive a proposal, validate it as invalid (`block_info.valid = Some(false)`, state `LocallyRejected`), then inject `Accepted` `BlockResponse` messages from enough other signer identities to reach the 70% weight threshold — `store_and_process_block_signature` will mark the block `LocallyAccepted` and call `broadcast_signed_block`/`handle_post_block` without re-checking `valid`.

    /// Handle an observed signature from another signer
    fn handle_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        accepted: &BlockAccepted,
    ) {
        let BlockAccepted {
            signer_signature_hash: block_hash,
            signature,
            metadata,
            ..
        } = accepted;
        debug!(
            "{self}: Received a block-accept signature: ({block_hash}, {signature}, {})",
            metadata.server_version
        );

        // recover public key
        let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
            block_hash.bits(),
            signature,
        ) else {
            debug!("{self}: Received unrecovarable signature. Will not store.";
                   "signature" => %signature,
                   "signer_signature_hash" => %block_hash);

            return;
        };

        // authenticate the signature -- it must be signed by one of the stacking set
        let signer_address = StacksAddress::p2pkh(self.mainnet, &public_key);
        if !self.is_valid_signer(&signer_address) {
            debug!("{self}: Received block acceptance with an invalid signature. Will not store.";
                "signer_public_key" => ?public_key,
                "signer_address" => %signer_address,
                "signer_signature_hash" => %block_hash,
                "signature" => %signature
            );
            return;
        }
        let Some(mut block_info) = self.block_lookup_by_reward_cycle(block_hash) else {
            if let Err(e) = self.signer_db.add_pending_block_signature_response(
                block_hash,
                &signer_address,
                signature,
            ) {
                warn!("{self}: Failed to add pending block signature response: {e:?}");
            }
            return;
        };

        info!("{self}: Received block acceptance";
            "signer_pubkey" => public_key.to_hex(),
            "signer_address" => %signer_address,
            "signer_signature_hash" => %block_hash,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "signer_weight" => self.signer_weights.get(&signer_address).copied().unwrap_or(0),
            "tenure_extend_timestamp" => accepted.response_data.tenure_extend_timestamp,
            "tenure_extend_read_count_timestamp" => accepted.response_data.tenure_extend_read_count_timestamp
        );
        self.store_and_process_block_signature(
            stacks_client,
            sortition_state,
            &mut block_info,
            &signer_address,
            signature,
        );
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
