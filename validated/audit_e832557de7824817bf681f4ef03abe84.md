### Title
Signer-side global-state supermajority check rounds down instead of up, allowing agreement/disagreement decisions with less than the true 70%/30% threshold - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` and `GlobalStateEvaluator::reached_disagreement` compute the supermajority/blocking-minority threshold using floor (truncating) integer division, whereas the canonical block-approval threshold used elsewhere in the codebase (`NakamotoBlockHeader::compute_voting_weight_threshold`) explicitly rounds *up* (ceiling) so that the required weight is never less than the true percentage. This mismatch means the signer global state machine can declare "agreement" (or "disagreement") using a weight that is strictly less than the intended 70%/30% supermajority, whenever `total_weight * 7` (or `* 3`) is not evenly divisible by 10 — which is the common case in practice.

### Finding Description
`libsigner/src/v0/signer_state.rs` defines: [1](#0-0) 

```
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}

pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```

Both use plain integer division (`/ 10`), which truncates. This is the same 70%/30% "supermajority" constant (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`) that the chainstate layer treats with mandatory *ceiling* rounding: [2](#0-1) 

```
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```

This function, used both by chainstate for signature verification and by `stacks-signer/src/v0/signer.rs` for its own block-acceptance/rejection/pre-commit thresholds (`store_and_process_block_signature`, `handle_block_pre_commit`, block-rejection handling), correctly rounds up so the minimum weight required is never below `70%` of `total_weight`: [3](#0-2) 

The `GlobalStateEvaluator`, however, is used for a *different but equally consensus-critical* decision: it determines the protocol version, canonical miner viewpoint, burn view, and transaction replay set that every signer converges to via `determine_global_state`, `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `find_majority_prefix_replay_set` — all of which gate `capitulate_miner_view`/`capitulate_viewpoint` in `stacks-signer/src/v0/signer_state.rs`, i.e., which miner/tenure a signer will actually sign blocks for. [4](#0-3) 

Because `reached_agreement` floors instead of ceiling-rounds, whenever `total_weight * 7 % 10 != 0` the effective threshold is up to `0.9` weight-units lower than the true 70% cutoff. Example: `total_weight = 101` → true 70% = `70.7`, but `reached_agreement(70)` returns `true` (70 ≥ floor(70.7) = 70) even though `70/101 ≈ 69.3%` — a genuinely "not-supermajority" of votes is accepted as agreement. The same applies to `reached_disagreement`'s 30% blocking-minority check.

### Impact Explanation
This breaks the "aggregated-weight vs verified-threshold" equality the protocol relies on: the same nominal 70%/30% supermajority constant is enforced with two different (and inconsistent) rounding rules within the same signer binary — ceiling for block signature/pre-commit thresholds, but floor for global state machine agreement. Signers can converge on (i.e. "agree" on) a current-miner viewpoint, protocol version, or transaction-replay set that a genuine 70% weighted supermajority has not actually endorsed. Since `capitulate_miner_view`/`capitulate_viewpoint` use this weaker threshold to decide which miner a signer treats as canonical, this can cause a signer to capitulate to (and subsequently sign for) a miner/tenure view supported by less than the intended supermajority — i.e., acting on an incorrectly-computed threshold, which falls under "acting on a stale/incorrect reward-set threshold" (High impact class) and can cascade into signing for a non-canonical tenure.

### Likelihood Explanation
This is not a rare edge case requiring an attacker or a majority coalition — it triggers on ordinary reward-cycle weight distributions any time `total_weight * 7` (or `* 3`) is not a multiple of 10, which is the typical case for real-world stacked-amount-derived weights (see `pox_5_make_signer_set` largest-remainder apportionment, which produces essentially arbitrary integer weights). No majority-of-signers compromise, key access, or `auth_token` is needed — this is a straightforward logic/rounding defect present in the mainline code path used by every signer running the current global-state-machine protocol version (`GLOBAL_SIGNER_STATE_ACTIVATION_VERSION = 2`, the currently supported version).

### Recommendation
Change `reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use ceiling division for the agreement threshold (mirroring `NakamotoBlockHeader::compute_voting_weight_threshold`), and floor (or an equivalent strict `>` on the un-rounded value) consistently for the disagreement/blocking-minority threshold, so that "70% agreement" and "30% blocking minority" can never be satisfied by strictly less than the stated percentage of `total_weight`.

### Proof of Concept
1. Construct a `GlobalStateEvaluator` with `total_weight = 101` (e.g., signer weights summing to a value not divisible by 10, easily achieved via ordinary `pox_5_make_signer_set` apportionment).
2. Call `reached_agreement(70)`.
   - True 70% requirement: `70.7`, so `70` should NOT satisfy the threshold.
   - Actual code: `u64::from(101).strict_mul(7) / 10 = 707 / 10 = 70`, so `70 >= 70` → returns `true`.
3. This mirrors the existing regression tests in `libsigner/src/tests/signer_state.rs` (`reached_agreement_no_u32_overflow`) which validate the multiplication overflow fix but do not test/require ceiling-rounding — confirming the floor-division behavior is intentional-but-incorrect relative to `compute_voting_weight_threshold`'s ceiling semantics used everywhere else the same 70% constant is enforced.
