### Title
Stale confirmations from removed multisig members are still counted toward `num_confirmations`, allowing requests to execute below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges requests and confirmations that were *authored* by the removed member; it never scans the `confirmations` map for entries where the removed member had merely *confirmed* a request authored by someone else. Because `confirm()` later checks `confirmations.len() as u32 + 1 >= self.num_confirmations` without re-validating that every counted confirmer is still a live member, a request can be executed with fewer *live* confirmations than `num_confirmations` requires — the same class of bug as the reported `uninstallModule` issue, where state belonging to a de-registered principal (an executor / a multisig member) is not fully invalidated before it is relied upon again.

### Finding Description
`confirm()` [1](#0-0)  validates that the *caller* is a current member via `current_member()` [2](#0-1) , then compares the size of the stored `confirmations` set for the request against `self.num_confirmations` to decide whether to execute. It does not re-check that every account/key already present in that stored set is still a member.

`delete_member()` is the only place that cleans up state when a member is removed: [3](#0-2) 
It removes:
- requests that the removed member *originally authored* (`r.member == member`), and their confirmations,
- the `num_requests_pk` counter for that member,
- the member itself from `self.members`.

It does **not** iterate `self.confirmations` to strip the removed member's entry from requests *authored by other members that the removed member had already confirmed*. Those stale confirmation entries remain in storage tied to the now-non-existent member.

Consequently: if member `M` confirms a pending request `R` (authored by someone else) and is later removed from the multisig via a separate `DeleteMember` request, `R`'s confirmation set still contains `M`'s entry. When another live member subsequently confirms `R`, `confirmations.len()` includes the stale entry from `M`, so the threshold check in `confirm()` can be satisfied with one fewer *actual* live confirmer than `num_confirmations` demands.

This is analogous to the reported bug: an entity that is no longer "installed" (a multisig member, in place of an ERC-7579 executor) still has residual privileged effect on the system's authorization state because the removal path (`delete_member`, analogous to `uninstallModule`) does not fully invalidate state that depends on that entity (`confirmations`, analogous to config/state tied to the executor).

### Impact Explanation
This breaks the core custody/authorization binding of the multisig: `confirmations counted == live members who actually approved`. When it is violated, a `MultiSigRequestAction::Transfer`, `AddKey`, `DeployContract`, or `FunctionCall` request can be executed with fewer genuine, currently-authorized approvals than `num_confirmations` mandates — i.e., "a multisig request executed below threshold," which is explicitly listed as a Critical impact in scope. Since executed actions include `Transfer` and `AddKey`/`AddFullAccessKey`, this can lead directly to unauthorized movement of NEAR held by the multisig account.

### Likelihood Explanation
The precondition is realistic and requires no privileged access beyond being (at the time) a legitimate multisig member: a member confirms a request, is later removed (a routine multisig operation), and the still-pending request they confirmed is later pushed over threshold by remaining members. No attacker needs to compromise a key that isn't theirs — the vulnerability is triggered purely by ordinary multisig lifecycle operations plus one stale confirmation, making it straightforward to encounter, and exploitable by any current members colluding with knowledge of the residual stale confirmation.

### Recommendation
When deleting a member in `delete_member` (`multisig2/src/lib.rs`), also scan/prune the `confirmations` map for **all** requests (not just ones the member authored) and remove the deleted member's entry from each confirmation set, or alternatively re-validate on every `confirm()` call that all confirmers currently present in the stored set are still members (discarding stale entries) before comparing against `num_confirmations`.

### Proof of Concept
1. Multisig has members `A`, `B`, `C`; `num_confirmations = 2`.
2. `A` calls `add_request` to create request `R` (e.g., `Transfer`), then `B` calls `confirm(R)` — `confirmations[R] = {B}` (1 < 2, not executed yet).
3. Separately, `A` and `C` submit and confirm a `DeleteMember { member: B }` request, which executes `delete_member` [3](#0-2) . This removes `B` from `self.members`, but `confirmations[R]` still contains `B`'s entry because `R` was authored by `A`, not `B`.
4. `C` calls `confirm(R)`. In `confirm()` [4](#0-3) , `confirmations.len() as u32 + 1` evaluates to `2 >= num_confirmations(2)`, so `R` executes — even though only `A` (implicitly, as author) and `C` are currently live members who actually approved; `B`'s stale confirmation was counted toward the threshold despite `B` no longer being a member.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Returns current member: either predecessor as account or if it's the same as current account - signer.
    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
