### Title
`propagate_staked_settings` mutates frozen staked banks, bypassing `FREEZE_SETTINGS` enforcement - ([File: programs/marginfi/src/instructions/marginfi_group/propagate_staked_settings.rs])

### Summary
`propagate_staked_settings` is a permissionless instruction (no `Signer` account at all) that overwrites a staked bank's oracle, weights, deposit limit, and other config fields from the group's `StakedSettings` PDA. Unlike `lending_pool_configure_bank_oracle` and `lending_pool_set_fixed_oracle_price`, which both explicitly check `bank.get_flag(FREEZE_SETTINGS)` and refuse to proceed, `propagate_staked_settings` never checks this flag before mutating `bank.config`.

### Finding Description
The instruction's account validation only checks group binding and `ASSET_TAG_STAKED`: [1](#0-0) 

There is no `Signer<'info>` field in `PropagateStakedSettings`, and the handler body proceeds directly to overwrite `bank.config.oracle_keys[0]`, `asset_weight_init`, `asset_weight_maint`, `deposit_limit`, `total_asset_value_init_limit`, `oracle_max_age`, `risk_tier`, and `bank.flags` from the `StakedSettings` account with no `FREEZE_SETTINGS` check: [2](#0-1) 

By contrast, the two comparable admin-config paths for oracle changes explicitly guard against frozen banks: [3](#0-2) [4](#0-3) 

Since `propagate_staked_settings` is documented and designed to be permissionless ("Permissionless ix to propagate a group's staked collateral settings to any bank in that group"), any caller can invoke it on any staked bank in a group at any time, including one an admin has explicitly frozen via `FREEZE_SETTINGS`, and force the bank's oracle/weights/limits to whatever the group's `StakedSettings` currently specifies.

### Impact Explanation
This breaks the invariant that `FREEZE_SETTINGS` durably locks a bank's configuration, an invariant that is explicitly enforced elsewhere in the same file family (`config_bank_oracle.rs`, `set_fixed_oracle_price.rs`). If an admin freezes a staked bank (e.g., to lock in a specific oracle or risk parameters for security/compliance reasons) and later group-level `StakedSettings` are updated to different values, any unprivileged user can re-sync the "frozen" bank to the new settings, defeating the purpose of the freeze and causing an unauthorized state transition on a bank the admin explicitly locked.

### Likelihood Explanation
Fully feasible and repeatable with public accounts only: the caller just needs to supply `marginfi_group`, `staked_settings`, and the target frozen `bank` account metas — no signature or elevated privilege is required by the `PropagateStakedSettings` account struct. Preconditions (group has `StakedSettings`, bank is `ASSET_TAG_STAKED` and `FREEZE_SETTINGS` set) are standard supported bank states.

### Recommendation
Add a check in `propagate_staked_settings` mirroring the other config instructions, e.g. `check!(!bank.get_flag(FREEZE_SETTINGS), MarginfiError::...)` (or an early return before applying any of the field overwrites), so that frozen staked banks reject propagation just as they reject `lending_pool_configure_bank_oracle` and `lending_pool_set_fixed_oracle_price`.

### Proof of Concept
Rust integration test plan:
1. Set up a marginfi group with `StakedSettings` PDA and a staked bank (`ASSET_TAG_STAKED`).
2. As admin, set `FREEZE_SETTINGS` flag on the bank (via the existing admin configure-bank path that sets flags).
3. As admin, update the group `StakedSettings` (different oracle key / weights / deposit_limit than the bank currently has).
4. As an unprivileged/non-admin signer (or with no signer at all, since none is required), call `propagate_staked_settings(marginfi_group, staked_settings, bank)`.
5. Assert: currently the call succeeds and `bank.config` fields (`oracle_keys[0]`, `asset_weight_init/maint`, `deposit_limit`, etc.) are mutated to match the new `StakedSettings` — violating `AUTHZ_HOLDS` (pre/post bank.config equality expected when `FREEZE_SETTINGS` is set).
6. After the fix, assert the same call returns an error and `bank.config` remains unchanged.

pub fn propagate_staked_settings(ctx: Context<PropagateStakedSettings>) -> Result<()> {
    let settings = ctx.accounts.staked_settings.load()?;
    let mut bank = ctx.accounts.bank.load_mut()?;

    let (oracle_before, oracle_after) = (bank.config.oracle_keys[0], settings.oracle);

    bank.config.oracle_keys[0] = settings.oracle;
    bank.config.asset_weight_init = settings.asset_weight_init;
    bank.config.asset_weight_maint = settings.asset_weight_maint;
    bank.config.deposit_limit = settings.deposit_limit;
    bank.config.total_asset_value_init_limit = settings.total_asset_value_init_limit;
    bank.config.oracle_max_age = settings.oracle_max_age;
    bank.config.risk_tier = settings.risk_tier;
    bank.flags &= !STAKED_ORACLE_FLAGS;
    bank.flags |= settings.flags & STAKED_ORACLE_FLAGS;

    // Only validate the oracle info if it has changed
    if oracle_before != oracle_after {
        bank.config
            .validate_oracle_setup(ctx.remaining_accounts, None, None, None)?;
    }
