### Title
Final pubsub notification can be permanently lost because the subscription entry is removed before delivery is confirmed - (File: rpc/src/rpc_pubsub_service.rs)

### Summary
`BroadcastHandler::handle` removes a subscriber's `SubscriptionId` entry from `current_subscriptions` whenever a notification is marked `is_final`, and only *afterwards* attempts to upgrade the notification's `Weak<String>` payload. If the upgrade fails, the subscriber has already been unsubscribed, so the promised final message (e.g. transaction confirmation) can never be delivered — an analog of the SmartEscrow bug where a state-terminating flag (`contractTerminated = true`) is applied before the pending payout to the beneficiary is guaranteed, causing the beneficiary to permanently lose funds that were already due.

### Finding Description
`signatureSubscribe` and other one-shot subscriptions are delivered with `is_final = true` via `check_commitment_and_notify`, which passes `is_final` through to `RpcNotifier::notify`: [1](#0-0) 

`RpcNotifier::notify` stores the serialized JSON payload as an `Arc<String>` in a bounded `recent_items` buffer, but only sends a `Weak` reference through the broadcast channel: [2](#0-1) 

The code comment explicitly acknowledges the payload can already be gone by the time a receiver processes it: *"There is an unlikely case where this can fail: if the last subscription is closed just as the notifier generates a notification for it."* [3](#0-2) 

On the delivery side, `BroadcastHandler::handle` looks up the subscriber's entry, and — critically — removes the entry from `current_subscriptions` (i.e., unsubscribes the client) *before* checking whether the weak reference can still be upgraded to the actual payload: [4](#0-3) 

```rust
if notification.is_final {
    entry.remove();
}
notification
    .json
    .upgrade()
    .ok_or(Error::NotificationIsGone)
    .map(Some)
```

This mirrors the SmartEscrow ordering bug: the "termination" of the subscription state (`entry.remove()`, analogous to `contractTerminated = true`) happens unconditionally, independent of whether the pending value (the final notification payload) is actually deliverable. If the `Weak` reference has already expired (e.g., the buffer of `recent_items` evicted it because other notifications were queued/pushed before this client's websocket task got scheduled to poll the broadcast channel), `upgrade()` returns `None`, the call returns `Err(Error::NotificationIsGone)`, and the subscription is already gone from `current_subscriptions` — the client will never receive the confirmation it subscribed for, and no compensating notification or resubscription occurs.

### Impact Explanation
An unprivileged JSON-RPC pubsub client (e.g., a wallet or bot relying on `signatureSubscribe`) can lose the transaction-confirmation notification it was waiting for, even though the validator generated it. Because `entry.remove()` runs before the payload is confirmed retrievable, the client's subscription is silently and irrecoverably torn down with no notification ever reaching the wire — a case of legitimate pending data being dropped for an unprivileged caller, matching the "wrong data returned" / lost-notification class of impact permitted by the assessment rules.

### Likelihood Explanation
The race depends on the notifier's `recent_items` buffer evicting the `Arc<String>` payload before the specific broadcast receiver task for that client is polled — plausible under load (busy validator generating many notifications, or a client connection lagging on I/O), which the code's own comment concedes is a real (if "unlikely") case. No attacker action beyond an ordinary `signatureSubscribe` call is required; it can also be influenced by generating other subscription traffic to increase the odds of the target's buffered entry being evicted first.

### Recommendation
Reorder the logic in `BroadcastHandler::handle` so the entry is only removed from `current_subscriptions` after successfully upgrading the `Weak` reference and confirming the final payload will be sent, mirroring the report's fix pattern of delivering pending value before finalizing state. Alternatively, size `recent_items` to guarantee retention long enough for all live receivers to observe a final notification before eviction.

### Proof of Concept
1. Client calls `signatureSubscribe` for a transaction and the validator processes it, causing `RpcSubscriptions` to call `notify` with `is_final = true`, storing the JSON as `Arc<String>` in `recent_items` and broadcasting only a `Weak` reference.
2. Before the target client's async task drains the broadcast channel and calls `BroadcastHandler::handle`, enough other notifications are generated across the shared `recent_items` structure that the earlier `Arc<String>` is dropped/evicted.
3. When the client's task finally calls `handle`, `notification.is_final` is `true`, so `entry.remove()` unsubscribes the client from `current_subscriptions` immediately.
4. `notification.json.upgrade()` then fails (`None`), yielding `Err(Error::NotificationIsGone)`; the confirmation payload is never sent to the client, and because the subscription entry was already removed, no further attempt is made to redeliver it — the client is left permanently unaware of the transaction's confirmation status via this subscription.

    fn notify<T>(&self, value: T, subscription: &SubscriptionInfo, is_final: bool)

        T: serde::Serialize,

            let mut buf = buf.borrow_mut();
            buf.clear();
            let notification = Notification {
                jsonrpc: Some(jsonrpc_core::Version::V2),
                method: subscription.method(),
                params: NotificationParams {
                    result: value,
                    subscription: subscription.id(),
                },
            };
            serde_json::to_writer(Cursor::new(&mut *buf), &notification)
                .expect("serialization never fails");
            let buf_str = str::from_utf8(&buf).expect("json is always utf-8");
            Arc::new(String::from(buf_str))
        });

        let notification = RpcNotification {
            subscription_id: subscription.id(),
            json: Arc::downgrade(&buf_arc),
            is_final,
            created_at: Instant::now(),

        // just as the notifier generates a notification for it.
        let _ = self.sender.send(notification);

        self.recent_items.lock().unwrap().push(buf_arc);
    }

    fn handle(&self, notification: RpcNotification) -> Result<Option<Arc<String>>, Error> {
        if let Entry::Occupied(entry) = self
            .current_subscriptions
            .entry(notification.subscription_id)
        {
            increment_sent_notification_stats(
                entry.get().params(),
                &notification,
                &self.sent_stats,
            );

            if notification.is_final {
                entry.remove();
            }
            notification
                .json
                .upgrade()
                .ok_or(Error::NotificationIsGone)
                .map(Some)
        } else {
            Ok(None)
        }
    }
