### Title
Late `depositDuringEpoch` deposits dilute a known stop-epoch interest override - (File: `contracts/IdleCDOEpochVariant.sol`)

### Summary
A KYC-passed user can deposit in the final block before `epochEndDate`, minting tranche shares using only the stale `expectedEpochInterest`. If the manager then settles the epoch with a larger explicit `_interest` amount, the new shares participate in the settlement award as if they had existed for the full epoch. This lets an attacker capture most of a known bonus payment and reduces the payout due to existing tranche holders. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`depositDuringEpoch` is permitted while `isEpochRunning` is true and `block.timestamp < epochEndDate`, provided the owner has enabled mid-epoch deposits and the caller passes wallet validation. [1](#0-0) 

The function computes only the depositor's prorated share of the currently configured fixed-APR interest. [4](#0-3)  It then prices new shares against `expectedFinal`, which is based on the pre-deposit `expectedEpochInterest`, not on any later stop-epoch override. [5](#0-4) 

After expiry, the manager can call `stopEpoch(0, overriddenInterest)`. Values greater than `1` replace `expectedEpochInterest` through `prepareStopEpochWithApr0`; the borrower-funded amount is then added to vault NAV and split across the enlarged tranche supply by `_updateAccounting`. [3](#0-2) [6](#0-5) [7](#0-6) 

Concretely:

1. The pool has 1,000 underlying in AA and a fixed-APR expectation of 100 underlying.
2. The honest borrower or manager publicly prepares an actual settlement of 1,000 underlying of interest.
3. In the last block before `epochEndDate`, an attacker deposits 9,000 underlying.
4. With negligible remaining-time interest, the attacker receives approximately `9000 * 1000 / 1100 = 8181.8` AA shares.
5. The manager stops the epoch with `_interest = 1000`.
6. The resulting 11,000-underlying NAV is split across approximately 9,181.8 shares rather than the original 1,000 shares.

The attacker receives approximately 9,800 underlying in value for a 9,000-underlying deposit, while the original depositor receives approximately 1,198 instead of the approximately 2,000 it would receive without dilution. The attacker therefore captures about 800 underlying of the settlement award.

### Impact Explanation
This is theft of unclaimed yield through share dilution. Existing holders' expected allocation of the realized settlement payment is reduced proportionally to the attacker's newly issued shares, even though the attacker joined after the favorable settlement amount was known or inferable. The broken invariant is fair minting: shares are priced using stale expected interest but immediately participate in a different, larger realized interest amount.

The loss scales with the difference between the public `expectedEpochInterest` used for minting and the eventual `_interest` override. A sufficiently large deposit can transfer most of that excess to the attacker.

### Likelihood Explanation
Likelihood is conditional on the owner enabling `depositDuringEpoch` and on a stop-epoch override becoming predictable before expiry. Such predictability can arise from a visible borrower approval or funding transaction, an announced settlement amount, a queued manager transaction, or off-chain coordination around the end of the epoch.

No privileged role is required for the attacker. The attacker only needs to pass the normal wallet allowlist check and hold enough underlying. [1](#0-0) 

The current guards do not prevent this sequence: donation skimming only isolates raw token donations, `_guarded` only enforces capacity, and the epoch-end check still leaves a final pre-expiry block in which shares can be minted at the stale expectation. [8](#0-7) 

### Recommendation
Prevent `depositDuringEpoch` once settlement parameters can reasonably be known. Options include:

- Add an owner/manager-configurable settlement cutoff and reject deposits when `block.timestamp + cutoff >= epochEndDate`.
- Commit to the stop-epoch interest before the cutoff, and settle only against the committed value.
- Price mid-epoch shares against `max(expectedEpochInterest, finalizedInterest)` once a settlement value has been committed.
- Keep mid-epoch deposits disabled for deployments where the manager may settle discretionary or externally negotiated interest above `expectedEpochInterest`.

Add tests covering a last-block deposit followed by `stopEpoch(0, overriddenInterest)` and verify that the new depositor cannot capture the incremental settlement award.

### Proof of Concept
This PoC can be added to the existing Foundry credit-vault test context in `test/foundry/IdleCreditVault.t.sol`:

```solidity
function testLateDepositDilutesKnownStopEpochInterest() external {
    uint256 initialDeposit = 1_000 * ONE_SCALE;
    uint256 attackDeposit = 9_000 * ONE_SCALE;
    uint256 overrideInterest = 1_000 * ONE_SCALE;

    vm.startPrank(manager);
    cdoEpoch.setEpochParams(365 days, 0);
    IdleCreditVault(address(strategy)).setAprs(10e18, 10e18);
    vm.stopPrank();

    // Victim deposits before the epoch.
    idleCDO.depositAA(initialDeposit);

    vm.startPrank(owner);
    cdoEpoch.setIsAYSActive(false);
    cdoEpoch.setIsDepositDuringEpochDisabled(false);
    vm.stopPrank();

    _startEpochAndCheckPrices(0);

    // 100 underlying is expected under the configured 10% APR.
    assertEq(cdoEpoch.expectedEpochInterest(), 100 * ONE_SCALE);

    // Attacker enters in the last pre-expiry block after the larger
    // settlement amount has become known.
    address attacker = makeAddr("attacker");
    deal(defaultUnderlying, attacker, attackDeposit);

    vm.warp(cdoEpoch.epochEndDate() - 1);
    vm.startPrank(attacker);
    IERC20Detailed(defaultUnderlying).approve(
        address(cdoEpoch),
        attackDeposit
    );
    uint256 attackerShares = cdoEpoch.depositDuringEpoch(
        attackDeposit,
        address(AAtranche)
    );
    vm.stopPrank();

    uint256 victimShares = IERC20(address(AAtranche)).balanceOf(address(this));
    assertApproxEqAbs(attackerShares, 8_181.8 ether, 1e18);

    // Fund and execute the already-known 1,000-underlying settlement.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(
        defaultUnderlying,
        borrower,
        IERC20Detailed(defaultUnderlying).balanceOf(borrower) +
            overrideInterest
    );
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, overrideInterest);

    uint256 price = cdoEpoch.virtualPrice(address(AAtranche));
    uint256 attackerValue = attackerShares * price / ONE_TRANCHE_TOKEN;
    uint256 victimValue = victimShares * price / ONE_TRANCHE_TOKEN;

    // Attacker profits by roughly 800 underlying.
    assertApproxEqAbs(attackerValue, 9_800 * ONE_SCALE, 2 * ONE_SCALE);
    assertGt(attackerValue, attackDeposit);

    // Victim receives roughly 1,198 instead of roughly 2,000 without dilution.
    assertApproxEqAbs(victimValue, 1_198 * ONE_SCALE, 2 * ONE_SCALE);
    assertLt(victimValue, 2_000 * ONE_SCALE);
}
```
