### Title
Miner-controlled activity clock can be refreshed indefinitely by invalid/stale block proposals, wedging the signer's inactivity fallback - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`SortitionData::check_latest_block_in_tenure` treats *any* rejected/stale block proposal from the tenure's own miner as "miner activity" and refreshes `last_activity_time` whenever the tenure's last known block has not yet reached the 70%-weight `signed_group` (group-signature) threshold. Because the refresh condition `info.signed_group.is_none_or(...)` is unconditionally true while `signed_group` is `None`, a single miner (one election "slot", no signer majority needed) can keep re-broadcasting an invalid/conflicting proposal to reset the only clock (`last_activity_time`) that the signer's liveness fallback (`check_miner_inactivity` → `SortitionState::is_timed_out`) relies on to detect an inactive/stalled miner and revert to the prior tenure's miner. This mirrors the ETWAP bug's structure: a tracker that any actor can push in one direction "immediately"/unconditionally, defeating the safety mechanism (redeem cap / inactivity timeout) that depends on it.

### Finding Description
`check_latest_block_in_tenure` runs at proposal arrival, at validate-ok, and at signing time: [1](#0-0) 

When a proposed block's `chain_length` does not exceed the last known block in the tenure, the check fails the proposal (`Ok(false)`), but before returning it unconditionally refreshes `last_activity_time` as long as the tenure's last block has not reached `signed_group` (i.e., has not yet gathered the 70% group signature):

```
if info.signed_group.is_none_or(|signed_time| {
    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
}) {
    signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs());
}
```

`Option::is_none_or` returns `true` unconditionally when `signed_group` is `None`, so the timeout window (`reorg_attempts_activity_timeout`) only applies once a block has actually reached group signature; before that happens, the refresh is unbounded in time.

`last_activity_time` is precisely the clock `SortitionState::is_timed_out` (v1) uses to decide whether the current tenure's miner has gone inactive: [2](#0-1) 

and that decision is the only liveness fallback the signer state machine has, via `check_miner_inactivity`, to revert the active-miner view to the prior tenure's miner when the current miner stalls: [3](#0-2) 

The same helper is reused both for same-tenure blocks and for tenure-change blocks' parent-tenure confirmation, and is invoked from `check_proposal`, `check_block_against_signer_db_state` (validate-ok), and at signing: [4](#0-3) [5](#0-4) 

The equality/guard broken here: `check_miner_inactivity`/`is_timed_out` is supposed to answer "has the current miner genuinely done nothing for `block_proposal_timeout`?" so the network can safely fail over. Instead, the current miner (or anyone with knowledge of its consensus hash/tenure who can gossip a `BlockProposal`, though the miner is the natural actor since it authors and signs the proposal) can keep the "activity" signal alive by repeatedly submitting a proposal it knows will be rejected as stale/conflicting — no valid progress, no signer majority, no other signer's key needed.

### Impact Explanation
This is a liveness wedge: as long as the active miner never lets any of its own tenure's blocks cross the 70% group-signature threshold (e.g., by intentionally under-provisioning weight, network partition among signers, or simply not completing pre-commit→signed progression), it can indefinitely refresh `last_activity_time` for its own tenure using cheap, self-authored, always-rejected proposals. `is_timed_out` then never returns `true`, so `check_miner_inactivity` never triggers `make_miner_state` fallback to the prior sortition's miner. The signer network is stuck waiting on a miner that produces no valid, group-signed block, with no automatic recovery path — matching the "signer wedged into never signing valid blocks" / liveness-wedge impact class.

### Likelihood Explanation
Medium-High: the only requirement is that the acting miner (a single sortition winner — the report's "one-slot" analog) can broadcast a `BlockProposal` for its own tenure with a `chain_length` at or below the last known block, which it can trivially construct (e.g., re-send its own earlier block, or a block one height lower). No signer collusion, majority, or key compromise is required, and the check runs on every proposal arrival, so a small trickle of such proposals is enough to keep resetting the clock before `block_proposal_timeout` elapses.

### Recommendation
Do not let an unbounded, unconditionally-true branch (`signed_group.is_none()`) give indefinite "activity" credit for proposals that fail the confirmation check. Apply the same time-bounded treatment used for the globally-signed case (i.e., always gate the activity refresh by `reorg_attempts_activity_timeout` relative to when the tenure's last accepted/pre-committed block was itself first seen/approved) so that a miner cannot perpetually extend its own inactivity grace period purely by resubmitting stale/conflicting proposals it knows will be rejected.

### Proof of Concept
1. Miner M wins a sortition and starts a tenure, producing block B0 which reaches only `PreCommitted`/`LocallyAccepted` (never 70% group signature) — e.g. due to a signer-weight split or by simply not gathering enough sign responses.
2. M crafts and broadcasts a second `BlockProposal` P for the same tenure with `chain_length <= B0.chain_length` (e.g., duplicate B0 or an even lower height), signed by itself.
3. Each signer receiving P runs `check_latest_block_in_tenure` (via `check_proposal`/`check_block_against_signer_db_state`): the height check fails (`Ok(false)`), but since `B0.signed_group` is `None`, `update_last_activity_time` is called unconditionally — see `stacks-signer/src/chainstate/mod.rs:395-418`.
4. M repeats step 2 at an interval shorter than `block_proposal_timeout`, indefinitely resetting `last_activity_time` for its tenure.
5. `SortitionState::is_timed_out` (`stacks-signer/src/chainstate/v1.rs:55-94`) never observes `elapsed > block_proposal_timeout`, so `check_miner_inactivity` (`stacks-signer/src/v0/signer_state.rs:284-374`) never falls back to the prior tenure's miner, wedging the signer set's active-miner view on a miner producing no valid, group-signed block.

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
