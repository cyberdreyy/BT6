Confirmed: this is an exploitable email/username enumeration oracle exposed via the HTTP API.

### Title
Unauthenticated user email enumeration via distinguishable "Invalid email" vs "Invalid password" error strings returned in HTTP response body - ([File: core/sessions/localauth/orm.go])

### Summary
`CreateSession` returns a distinct error, `"Invalid email"` vs `"Invalid password"`, depending on whether `constantTimeEmailCompare` or `CheckPasswordHash` fails, and `SessionsController.Create` forwards that raw error text verbatim to the HTTP client as a 401 JSON body. This lets any unauthenticated caller of `POST /sessions` enumerate valid emails/usernames registered on the node.

### Finding Description
`CreateSession` in `core/sessions/localauth/orm.go` first looks up the user by email via `FindUser`/`findUser` using a case-insensitive `lower(email) = lower($1)` query [1](#0-0) . If found, it does an email confirmation check with `constantTimeEmailCompare`, and on mismatch returns `pkgerrors.New("Invalid email")` while emitting `audit.AuthLoginFailedEmail` [2](#0-1) . If the email matches but the password check via `utils.CheckPasswordHash` fails, it returns a different literal, `pkgerrors.New("Invalid password")`, with `audit.AuthLoginFailedPassword` [3](#0-2) .

Note that since `FindUser` uses a SQL query rather than an in-memory lookup, an unknown email causes `sql.ErrNoRows` to propagate directly out of `CreateSession` at line 147 (a third, distinct error), and only a genuinely mismatched-but-found row (theoretically unreachable given the exact-match SQL predicate) would trip the `"Invalid email"` branch. In practice, for local auth, the "email not found" case surfaces as a raw DB "no rows" error while "email found + wrong password" surfaces as `"Invalid password"` — these two are already distinguishable strings.

This error is not redacted before reaching the client. `SessionsController.Create` calls `AuthenticationProvider().CreateSession` and passes the returned `err` directly into `jsonAPIError(c, http.StatusUnauthorized, err)` [4](#0-3) . `jsonAPIError` then serializes `err.Error()` into the JSON response body via `models.NewJSONAPIErrorsWith(err.Error())` [5](#0-4) . The `/sessions` POST route is explicitly unauthenticated (only rate-limited), confirming this is reachable pre-auth: `unauth.POST("/sessions", sc.Create)` [6](#0-5) .

There is no middleware, presenter, or redaction layer between `CreateSession`'s error and the HTTP response body that normalizes these messages to a generic "invalid credentials" string. HTTP status code is uniformly 401 in both cases (no status-code oracle), but the JSON body text differs, which is directly observable by an unauthenticated client.

### Impact Explanation
This maps to Chainlink's "informational disclosure" / enumeration class rather than direct account takeover. An unauthenticated attacker can submit arbitrary emails to `POST /sessions` and, by inspecting the response body content, determine which emails correspond to real node operator accounts (distinguishing "unknown user" / "Invalid email" from "Invalid password" for a known user). This does not by itself grant access, bypass auth, or disclose secrets/keys, but it does provide a reconnaissance oracle that narrows subsequent targeted credential-stuffing, phishing, or brute-force attacks against specific, confirmed operator accounts — a real but low/informational severity issue, not a critical auth bypass.

### Likelihood Explanation
Fully unauthenticated, requires zero credentials, and is trivially repeatable: an attacker just needs network access to `POST /sessions` (rate-limited but not blocked, as shown by `TestSessions_RateLimited` allowing 5 attempts before a 429) [7](#0-6) . Rate limiting slows but does not prevent enumeration over time, and each response body is inspectable per request.

### Recommendation
Return a single generic error (e.g., `"invalid credentials"`) for both the "email not found/mismatch" and "wrong password" branches in `CreateSession`, and ensure `SessionsController.Create` (or `jsonAPIError`) does not leak the underlying error text distinguishing these cases to the client, while still emitting the differentiated `AuthLoginFailedEmail`/`AuthLoginFailedPassword` audit events internally for observability. Also normalize the "email not found" `sql.ErrNoRows` path in `FindUser`/`CreateSession` to the same generic message so the timing/content of "unknown email" vs "known email + wrong password" cannot be distinguished by the response body.

### Proof of Concept
Go handler-level integration test (extending `core/web/sessions_controller_test.go`):
1. Create a user via `app.AuthenticationProvider().CreateUser`.
2. Issue `POST /sessions` with `{"email": "<unknown>@test.net", "password": "irrelevant"}` and capture response body/status.
3. Issue `POST /sessions` with `{"email": "<existing-user-email>", "password": "wrongpassword"}` and capture response body/status.
4. Assert both return `401`, but assert that the JSON error body text differs (e.g., contains `sql: no rows` vs `"Invalid password"`), proving the oracle exists.
5. Additionally, a unit test directly on `orm.CreateSession` asserting `err.Error()` strings differ between the "email mismatch/not found" and "wrong password" paths, and that `auditLogger.Audit` is called with `AuthLoginFailedEmail` vs `AuthLoginFailedPassword` respectively — confirming the distinguishable signal originates in `core/sessions/localauth/orm.go` and is not intercepted before reaching the HTTP layer.

func TestSessions_RateLimited(t *testing.T) {
	t.Parallel()

	ctx := t.Context()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(ctx))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	client := clhttptest.NewTestLocalOnlyHTTPClient()
	input := `{"email":"brute@force.com", "password": "wrongpassword"}`

	for range 5 {
		request, err := http.NewRequestWithContext(ctx, http.MethodPost, ts.URL+"/sessions", bytes.NewBufferString(input))
		require.NoError(t, err)

		resp, err := client.Do(request)
		require.NoError(t, err)
		assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
	}

	request, err := http.NewRequestWithContext(ctx, http.MethodPost, ts.URL+"/sessions", bytes.NewBufferString(input))
	require.NoError(t, err)

	resp, err := client.Do(request)
	require.NoError(t, err)
	assert.Equal(t, 429, resp.StatusCode)
}
