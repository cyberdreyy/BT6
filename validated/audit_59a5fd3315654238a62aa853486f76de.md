### Title
Missing sender allowlist/authorization check in `HandleLegacyUserMessage` allows unauthenticated senders to trigger DON-wide execution - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` in the capabilities gateway handler validates only message structure, signature format, and staleness before broadcasting the request to every DON member via `don.SendToNode`. There is no check that the message sender (`msg.Body.Sender`, derived purely from `ExtractSigner()` on a self-generated ECDSA key) is a subscribed/allowlisted address, as explicitly flagged by the `// TODO: apply allowlist and rate-limiting here` comment.

### Finding Description
The request path is: `gateway.ProcessRequest` decodes the JSON-RPC request, and for legacy requests calls `msg.Validate()` [1](#0-0) , which only checks field lengths/format and recovers the signer address from the signature via `ExtractSigner()` [2](#0-1) -there is no lookup against any allowlist or subscription registry. `ProcessRequest` then dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` [3](#0-2) .

Inside `HandleLegacyUserMessage`, the checks performed are: payload decodability, non-zero timestamp, and message-age staleness [4](#0-3) . Immediately after these checks and directly above the method-name check sits the comment `// TODO: apply allowlist and rate-limiting here` [5](#0-4) . No code path checks `msg.Body.Sender` against a DON-level allowlist, subscription table, or per-sender rate limiter before the message is forwarded. The request is converted and sent to every configured DON member: [6](#0-5) .

By contrast, the sibling `vault` handler performs explicit authorization via `h.requestProcessor.ProcessRequest(...)` before dispatching to nodes [7](#0-6) , demonstrating that this handler category is expected to authorize senders but the capabilities `web_api_trigger` legacy path does not.

This gap is also acknowledged directly in the test suite: `handler_test.go` contains the comment `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` at the end of the relevant test [8](#0-7) , and the existing "savedCallbacks stored only when message is valid" test only exercises payload/staleness/method failures, never a sender-not-allowlisted case [9](#0-8) .

Note: `nodeRateLimiter` in this file is applied only to outgoing messages from already-connected DON nodes (`handleWebAPIOutgoingMessage`) [10](#0-9) , not to inbound user-originated `web_api_trigger` requests, so it does not mitigate this issue.

### Impact Explanation
Any party who can reach the gateway's HTTP/JSON-RPC endpoint and generate an ECDSA keypair can sign and submit a `web_api_trigger` legacy message. The handler will forward that message to every node in the DON (`don.SendToNode` for each `h.donConfig.Members`), consuming node/DON compute and capability-execution resources that are meant to be reserved for allowlisted/subscribed senders. This matches an authorization/allowlist-bypass class impact - unauthorized consumption/redirection of subscribed capability execution - rather than fund loss or key disclosure.

### Likelihood Explanation
Preconditions are minimal: the attacker needs no subscription, no prior relationship with the DON, and no privileged credentials-only a freshly generated ECDSA private key to produce a signature that satisfies `Message.Validate()`'s format checks. The request path from `gateway.ProcessRequest` to `HandleLegacyUserMessage` to `don.SendToNode` is a normal, always-reachable request path for the `web_api_trigger` method, making this readily and repeatably exploitable given the missing check is unconditional (there is no partial mitigation on this legacy path).

### Recommendation
Add sender authorization in `HandleLegacyUserMessage` before dispatching to `don.SendToNode`: check `msg.Body.Sender` against a configured allowlist/subscription store (mirroring the pattern used in `vault/handler.go`'s `requestProcessor.ProcessRequest`) and apply a per-sender rate limiter, returning an `api.HandlerError`/unauthorized JSON-RPC error response via `callback.SendResponse` for senders that fail the check, consistent with how other error paths in this function already respond.

### Proof of Concept
Add a table-driven test alongside `handler_test.go`'s existing "savedCallbacks stored only when message is valid" subtest:
1. Construct a `handler` with a `donConfig.Members` list and a mock `handlers.DON`.
2. Generate a fresh, never-registered/never-allowlisted ECDSA key (e.g., via `crypto.GenerateKey()`), sign a valid `web_api_trigger` `TriggerRequestPayload` message with a current timestamp using this key (as done by `triggerRequest` helper in `handler_test.go`).
3. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)`.
4. Assert (expected to fail today, confirming the vulnerability) that `don.SendToNode` is NOT called for any member, or that `cb.Wait()` yields an authorization-error response (e.g., `api.HandlerError`/"unauthorized sender") - currently the mock DON's `SendToNode` will be invoked once per `donConfig.Members` entry with no error, demonstrating the unauthorized forward.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
```

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
```
