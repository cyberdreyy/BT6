### Title
Attacker-controlled SPL Token-2022 scaling/interest extensions cause `token_amount_to_ui_amount_v3` to return an inconsistent, misleading `ui_amount`/`ui_amount_string` pair via RPC token-balance queries - (File: `account-decoder/src/parse_token.rs`)

### Summary
`token_amount_to_ui_amount_v3()`, used by every RPC path that reports SPL token balances (`getTokenAccountBalance`, `getTokenSupply`, `getAccountInfo`/`getProgramAccounts` with `jsonParsed` encoding, and transaction/token-balance reporting), computes a token's UI-friendly balance from raw on-chain data. For Token-2022 mints carrying the permissionless `ScaledUiAmountConfig` or `InterestBearingConfig` extensions, the computed value can overflow to a non-finite `f64` (`inf`/`NaN`). The `ui_amount` field is silently serialized as JSON `null` (because non-finite floats cannot be represented in JSON), while the sibling `ui_amount_string` field still reports the literal string `"inf"`. This produces internally inconsistent, misleading data returned to any unprivileged client, entirely triggerable by any user who creates their own Token-2022 mint (a fully permissionless action) and sets an extreme multiplier/rate.

### Finding Description
`token_amount_to_ui_amount_v3` computes `ui_amount`/`ui_amount_string` differently depending on which extension is present on the mint: [1](#0-0) 

For the default (no extension) path, `10_usize.checked_pow(decimals)` safely returns `None` on overflow, which correctly propagates to `ui_amount: None`. However, for the `interest_bearing_config` and `scaled_ui_amount_config` branches, the UI amount is derived by calling the extension's own `amount_to_ui_amount()` (from the `spl-token-2022-interface` dependency) to get a formatted string, then re-parsing that string with `f64::from_str`. When the underlying computation overflows (e.g., extreme interest rate compounded over a long period, or an extreme `new_multiplier`), the formatted string becomes `"inf"`, which `f64::from_str` happily parses into `Some(f64::INFINITY)`.

This is confirmed by existing tests in the same file: [2](#0-1) [3](#0-2) 

Both the `InterestBearingConfig` (via `pre_update_average_rate`/`current_rate`, set by whoever controls the mint's `rate_authority`) and `ScaledUiAmountConfig` (via `new_multiplier`, set by the mint's `multiplier_authority`) are configured entirely by the token creator/authority when they initialize their own mint - an action requiring no special validator/operator privilege. Any RPC consumer that then queries this mint's supply or any account holding this token via `getTokenAccountBalance`, `getTokenSupply`, or `getAccountInfo`/`getProgramAccounts` with `encoding: "jsonParsed"` will receive a response where:
- `ui_amount` is `null` (because `serde_json` cannot represent non-finite floats and emits `null` for them), even though it internally held `Some(Infinity)`, and
- `ui_amount_string` is the literal text `"inf"`, which is not a valid decimal quantity.

The RPC call sites reachable by any unprivileged JSON-RPC client are: [4](#0-3) [5](#0-4) [6](#0-5) 

### Impact Explanation
This is a decoder-misreporting bug: a JSON-RPC handler returns wrong/inconsistent account data for a query, driven entirely by data an unprivileged user placed on-chain themselves (their own mint's extension configuration). Clients, wallets, and explorers that rely on `ui_amount` (rather than the raw `amount` string) for balance display or accounting will silently see `null`/`"inf"` instead of a real numeric balance, which is a wrong-data-returned condition from a read-only RPC query. It does not crash the validator process or affect consensus, so the severity is best characterized as low/informational relative to the "wrong-slot/fork/account data returned" and "decoder ... misreporting" categories called out for validity - the returned monetary value is misleading/unusable rather than a security-critical or fork-inducing failure.

### Likelihood Explanation
The trigger requires zero special access: any user can permissionlessly create an SPL Token-2022 mint, enable the `ScaledUiAmountConfig` or `InterestBearingConfig` extension, and set an extreme multiplier/rate. Any subsequent unprivileged `getTokenAccountBalance`/`getTokenSupply`/`getAccountInfo(jsonParsed)` query against that mint or any account holding units of it will deterministically reproduce the inconsistent `null`/`"inf"` output, as already demonstrated by the existing overflow test cases in the repository.

### Recommendation
In `token_amount_to_ui_amount_v3`, detect non-finite results explicitly (e.g., check `ui_amount_string == "inf"`/`"-inf"`/`"NaN"` or use a parse that rejects non-finite values) and normalize the output so `ui_amount` and `ui_amount_string` remain consistent - for example, returning `ui_amount: None` (matching the no-extension overflow path) whenever the computed value is not finite, rather than allowing `f64::from_str("inf")` to produce `Some(f64::INFINITY)` that is silently dropped to `null` by the JSON serializer while the string field still claims `"inf"`.

### Proof of Concept
1. Using `spl-token-2022`, create a mint with the `ScaledUiAmountConfig` extension and call `UpdateMultiplier` (or `InterestBearingConfig`'s rate-setting instruction) with an extreme value, e.g. `new_multiplier = f64::INFINITY` or a very large `current_rate` combined with a large elapsed timestamp, as reproduced by the repository's own test: [3](#0-2) 
2. Mint/hold `u64::MAX` (or any nonzero amount) of this token in an account.
3. Call the JSON-RPC `getTokenAccountBalance` (or `getAccountInfo` with `encoding: "jsonParsed"`) against that account: [4](#0-3) 
4. Observe the response contains `"uiAmount": null` while `"uiAmountString": "inf"` - an internally inconsistent, misleading balance report derived purely from unprivileged, user-supplied mint configuration.

pub fn token_amount_to_ui_amount_v3(
    amount: u64,
    additional_data: &SplTokenAdditionalDataV2,
) -> UiTokenAmount {
    let decimals = additional_data.decimals;
    let (ui_amount, ui_amount_string) = if let Some((interest_bearing_config, unix_timestamp)) =
        additional_data.interest_bearing_config
    {
        let ui_amount_string =
            interest_bearing_config.amount_to_ui_amount(amount, decimals, unix_timestamp);
        (
            ui_amount_string
                .as_ref()
                .and_then(|x| f64::from_str(x).ok()),
            ui_amount_string.unwrap_or("".to_string()),
        )
    } else if let Some((scaled_ui_amount_config, unix_timestamp)) =
        additional_data.scaled_ui_amount_config
    {
        let ui_amount_string =
            scaled_ui_amount_config.amount_to_ui_amount(amount, decimals, unix_timestamp);
        (
            ui_amount_string
                .as_ref()
                .and_then(|x| f64::from_str(x).ok()),
            ui_amount_string.unwrap_or("".to_string()),
        )
    } else {
        let ui_amount = 10_usize
            .checked_pow(decimals as u32)
            .map(|dividend| amount as f64 / dividend as f64);
        (ui_amount, real_number_string_trimmed(amount, decimals))
    };
    UiTokenAmount {
        ui_amount,
        decimals,
        amount: amount.to_string(),
        ui_amount_string,
    }
}

    pub fn get_token_supply(
        &self,
        mint: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;
        if !is_known_spl_token_id(mint_account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token mint".to_string(),
            ));
        }
        let mint = StateWithExtensions::<Mint>::unpack(mint_account.data()).map_err(|_| {
            Error::invalid_params("Invalid param: mint could not be unpacked".to_string())
        })?;

        let interest_bearing_config = mint
            .get_extension::<InterestBearingConfig>()
            .map(|x| (*x, bank.clock().unix_timestamp))
            .ok();

        let scaled_ui_amount_config = mint
            .get_extension::<ScaledUiAmountConfig>()
            .map(|x| (*x, bank.clock().unix_timestamp))
            .ok();

        let supply = token_amount_to_ui_amount_v3(
            mint.base.supply,
            &SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            },
        );
        Ok(new_response(&bank, supply))
    }
