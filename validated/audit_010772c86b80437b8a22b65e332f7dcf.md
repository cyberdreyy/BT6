### Title
Improper shell quoting of `TmpProjectDir` in `ProxyExecShell.GetConfiguration` CmdLine construction - ([File: shells/proxy_exec.go])

### Summary
`ProxyExecShell.GetConfiguration` builds the `CmdLine` string using `fmt.Sprintf("%q", ...)` on `info.Build.TmpProjectDir()`, which is Go-syntax quoting, not POSIX/cmd.exe shell quoting. Because `TmpProjectDir()` is derived from `BuildDir`, which can be influenced by the job-controlled `GIT_CLONE_PATH` variable when `custom_build_dir` is enabled, and that path is validated only for traversal (no `..`) and not for shell metacharacters, an attacker can inject shell metacharacters (backticks, `$`, `"`) that are not neutralized by `%q` when the resulting `CmdLine` is later interpreted by a POSIX shell (e.g. via SSH/instance/virtualbox/parallels executors that consume `ShellConfiguration.CmdLine` as a raw command string).

### Finding Description
The relevant code: [1](#0-0) 

`tempDir` is produced with Go's `%q` verb, which escapes for Go string literal syntax (backslash/quote/control-character escaping), not for POSIX shell double-quote syntax. Inside POSIX double quotes, backslash only has special meaning before `$`, `` ` ``, `"`, `\`, and newline — other characters are left literal. Critically, `%q` does **not** escape `` ` `` or `$`, since they are printable ASCII. If `TmpProjectDir()` contains a backtick or a `$(...)`-style sequence, the `%q`-quoted string still contains those characters literally inside the shell double quotes, and a downstream shell (`sh -c "$CmdLine"`) would interpret them as command substitution.

`TmpProjectDir()` is: [2](#0-1) 

`BuildDir` can come from the job-controlled `GIT_CLONE_PATH` CI variable via `getCustomBuildDir`, which only checks path traversal, not shell-metacharacter content: [3](#0-2) 

`ShellConfiguration.CmdLine` is documented as "combination of shell escaped command + args" and is consumed as a raw string by several executors (SSH, instance, VirtualBox, Parallels) rather than as an argv array: [4](#0-3) 

Existing protections (`filepath.Rel`/`strings.HasPrefix(relDir, "..")` traversal check) stop directory-escape attacks but do not sanitize shell metacharacters, and `%q` is the wrong escaping primitive for a value destined for POSIX shell interpretation.

### Impact Explanation
When `custom_build_dir` is enabled and the executor uses the CmdLine-consuming code path (SSH/instance/VirtualBox/Parallels executors with `IsProxyExec()` enabled), a job can set `GIT_CLONE_PATH` containing a backtick or `$(...)` sequence embedded in an otherwise-valid relative path under the builds root, causing the constructed `CmdLine` to execute attacker-supplied shell syntax when the remote/VM shell parses the string — this goes beyond mere argument injection against `proxy-exec` flags and can result in arbitrary command execution in the context that runs the trusted wrapper invocation, undermining the confinement boundary between job-controlled input and the runner's own command construction.

### Likelihood Explanation
Requires: (1) `custom_build_dir` enabled on the runner (a supported, non-default but not unusual configuration), (2) `IsProxyExec()` true (instance/docker-autoscaler style executors), and (3) an executor path where `CmdLine` (not `Arguments`) is what actually gets executed by a shell. Given these preconditions are met by legitimate, documented runner features (not admin misconfiguration in the excluded categories), and the attacker only needs to set a CI/CD variable (`GIT_CLONE_PATH`), the exploit is straightforward and repeatable for any pipeline author on such a runner.

### Recommendation
Do not build `CmdLine` via ad hoc string concatenation with Go's `%q`. Either avoid `CmdLine` entirely for proxy-exec (rely solely on `Command`/`Arguments`, passed as argv, not shell strings) or use a proper POSIX-shell-quoting helper for any path/argument value being interpolated into a `CmdLine` string (the codebase already has `helpers.ShellEscape` / `helpers.PosixShellEscape` used elsewhere in `shells/bash.go`), and additionally reject/sanitize `GIT_CLONE_PATH` values containing shell metacharacters if they can ever reach a shell-interpreted string.

### Proof of Concept
Go unit test sketch for `shells/proxy_exec_test.go`:
```go
func TestProxyExecShell_GetConfiguration_TmpProjectDirInjection(t *testing.T) {
    build := &common.Build{ /* configure BuildDir via GIT_CLONE_PATH containing backtick, e.g. */
        BuildDir: "/builds/proj`touch}}/pwned`",
    }
    info := common.ShellScriptInfo{Build: build, RunnerCommand: "gitlab-runner"}
    shell := &ProxyExecShell{baseShell}
    cfg, err := shell.GetConfiguration(info)
    require.NoError(t, err)
    // Feed cfg.CmdLine to `sh -c` and assert no unexpected command substitution executed
    out, _ := exec.Command("sh", "-c", "echo "+cfg.CmdLine).CombinedOutput()
    assert.NotContains(t, string(out), "pwned")
}
```
Expected: with current `%q`-based implementation, the backtick sequence survives inside the quoted string and is executed by `sh -c`, producing the injected side effect — demonstrating the fix is needed (replace with proper POSIX shell escaping or remove reliance on `CmdLine` string interpolation for `TmpProjectDir`).

func (s *ProxyExecShell) GetConfiguration(info common.ShellScriptInfo) (*common.ShellConfiguration, error) {
	base, err := s.Shell.GetConfiguration(info)
	if err != nil || info.Build == nil || !info.Build.Runner.IsProxyExec() {
		return base, err
	}

	tempDir := fmt.Sprintf("%q", info.Build.TmpProjectDir())

	}, nil

func (b *Build) getCustomBuildDir(rootDir, dir string, customBuildDirEnabled, sharedDir bool) (string, error) {
	if dir == "" {
		return path.Join(rootDir, b.ProjectUniqueDir(sharedDir)), nil
	}

	if !customBuildDirEnabled {
		return "", &BuildError{Inner: fmt.Errorf("setting GIT_CLONE_PATH is not allowed, enable `custom_build_dir` feature"), FailureReason: ConfigurationError}
	}

	// See: https://gitlab.com/gitlab-org/gitlab-runner/-/issues/25913
	relDir, err := filepath.Rel(helpers.ToSlash(rootDir), helpers.ToSlash(dir))
	if err != nil {
		return "", &BuildError{Inner: err, FailureReason: ConfigurationError}
	}
	if strings.HasPrefix(relDir, "..") {
		return "", &BuildError{Inner: fmt.Errorf("the GIT_CLONE_PATH=%q has to be within %q", dir, rootDir), FailureReason: ConfigurationError}
	}

	return path.Clean(dir), nil
}
