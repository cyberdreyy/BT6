### Title
Cross-user capability response hijack via unconditional overwrite of `savedCallbacks[MessageId]` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores a user-supplied `Callback` in `h.savedCallbacks` keyed solely by the caller-controlled `msg.Body.MessageId`, with no check for an existing pending entry before overwriting it. An attacker who submits a `MethodWebAPITrigger` request with the same `MessageId` as a victim's still-pending request can silently replace the victim's callback, causing the DON's eventual response to the victim's request to be delivered to the attacker instead.

### Finding Description
In `handler.go`, `HandleLegacyUserMessage` validates the message and unconditionally writes into the shared map: [1](#0-0) 
There is no `if _, exists := h.savedCallbacks[msg.Body.MessageId]; exists { return error }` guard — the second submitter's `Callback` simply clobbers the first. The comment at line 384 (`// TODO: apply allowlist and rate-limiting here`) confirms no allowlist/authorization gate exists before this path is reached, and `Validate()` in `api/message.go` only checks signature format, length constraints, and derives `Sender` — it never checks whether `MessageId` is already in use or scopes it to `Sender`. [2](#0-1) 
When the DON responds, `handleWebAPITriggerMessage` looks the callback up **only by `MessageId`** — not by `Sender`/requester identity — and delivers the response to whichever `Callback` currently occupies that slot: [3](#0-2) 

This confirms the exploit is real and matches an existing, better design already used elsewhere in the same codebase: `RequestCache` in `common/requestcache.go` keys entries by a composite `globalId{sender, id}` and explicitly rejects a `NewRequest` call when the key already exists (`"request already exists"`): [4](#0-3) 
The `capabilities` handler does not reuse this safer pattern; it uses its own bespoke `savedCallbacks map[string]*savedCallback` keyed by `MessageId` alone, without the sender-scoping or duplicate-rejection that `RequestCache` provides.

Exploit flow: (1) victim B sends a `web_api_trigger` request with `MessageId="X"`, which is written to `h.savedCallbacks["X"]`; (2) before the DON responds, attacker A sends another `web_api_trigger` request also with `MessageId="X"`; since nothing checks for an existing entry, A's `Callback` overwrites B's at line 412; (3) when the DON eventually returns the response for `MessageId="X"`, `handleWebAPITriggerMessage` fetches `h.savedCallbacks["X"]` (now A's callback) and calls `savedCb.SendResponse(...)`, delivering B's capability execution result to A.

### Impact Explanation
This is a cross-user response confusion vulnerability: an unauthenticated/unprivileged caller of the node/gateway API can hijack another user's `web_api_trigger` capability execution result by racing a colliding `MessageId`. Depending on what data flows through `web_api_trigger` (workflow trigger payloads/results), this can leak sensitive response data belonging to another user to an attacker, and simultaneously deny the victim their expected response (their original `Callback` is dropped and never invoked/timed-out via this map, since it's fully replaced).

### Likelihood Explanation
The only precondition is the ability to submit a `web_api_trigger` legacy user message with an attacker-chosen `MessageId` — there is no authentication, allowlist, or per-sender scoping enforced before the map write, as explicitly called out by the TODO comment. The attacker only needs to guess or observe the victim's `MessageId` and win a race before the DON responds (a window that can be up to `CallbackMaxAgeSec`, default 120s), making this practically feasible and repeatable.

### Recommendation
Scope the cache key to `(Sender, MessageId)` instead of `MessageId` alone (mirroring `common.RequestCache`'s `globalId{sender, id}` pattern), and reject the request (return an error to the caller) if an entry already exists for that key rather than silently overwriting it. Consider adopting `common.RequestCache` directly instead of the bespoke `savedCallbacks` map in `capabilities/handler.go`.

### Proof of Concept
Go handler-level integration test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct handler via `NewHandler`.
2. Call `HandleLegacyUserMessage` with victim's signed message, `MessageId="X"`, using a mock `Callback` `cbB` (spy that records calls).
3. Before responding, call `HandleLegacyUserMessage` again with attacker's signed message (different `Sender`), same `MessageId="X"`, using mock `Callback` `cbA`.
4. Assert the second call returns an error and `h.savedCallbacks["X"]` still references `cbB` (i.e., the entry was not overwritten) — this currently fails, proving the vulnerability.
5. Simulate DON response via `HandleNodeMessage` with method `web_api_trigger` and `MessageId="X"`; assert `cbB.SendResponse` is invoked (victim receives own response) and `cbA.SendResponse` is never called.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

type globalId struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
