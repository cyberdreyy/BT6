### Title
Path traversal in legacy zip cache extractor allows writing outside build directory - (File: helpers/archives/zip_extract.go)

### Summary
The `ziplegacy` extractor (the default `Zip`-format extractor registered in `commands/helpers/archive/ziplegacy/zip_legacy_archiver.go:19` and used by `cache-extractor`/`CacheExtractorCommand.Execute` in `commands/helpers/cache_extractor.go:655-663`) extracts zip entries using `file.Name` directly via `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile(file.Name, ...)` in `helpers/archives/zip_extract.go:41-83`, with zero path-confinement validation. Contrast this with the `tarzstd` extractor (`commands/helpers/archive/tarzstd/tarzstd_extractor.go:57-64`), which explicitly checks `strings.HasPrefix(path, e.dir+string(filepath.Separator))` before writing. The zip path lacks this check entirely, and only checks for `.git` directory names (`errorIfGitDirectory`, `helpers/archives/path_check_helper.go:21-31`), which is unrelated to traversal.

### Finding Description
`CacheExtractorCommand.Execute` (`commands/helpers/cache_extractor.go:618-664`) downloads a cache archive (from a URL/env produced by `getCacheDownloadURLAndEnv` in `shells/abstract.go:422-443`, itself driven by `cache.GetAdapter(...).GetGoCloudURL`/`GetDownloadURL`) and calls `archive.NewExtractor(format, f, size, wd)` then `extractor.Extract(ctx)`. For `Format == Zip`, this resolves to the `ziplegacy` extractor (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33`), which calls `zip.NewReader` then `archives.ExtractZipArchive(zr)`.

`ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`) iterates `archive.File` and calls `extractZipFile(file)` (`zip_extract.go:61-83`), which uses `file.Name` — the raw path stored inside the zip entry — verbatim:
- `os.MkdirAll(filepath.Dir(file.Name), 0o777)`
- `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())` for regular files
- `os.Symlink(string(data), file.Name)` for symlink entries

No call resolves `file.Name` relative to a base/root directory, nor validates it stays under that root (unlike the `tarzstd` extractor's explicit `filepath.Abs`/`HasPrefix` chroot check). A zip entry named e.g. `../../../../etc/cron.d/evil` or an absolute path `/home/gitlab-runner/.ssh/authorized_keys` would be written exactly where specified, relative to the process's current working directory (`wd`, obtained via `os.Getwd()` in `cache_extractor.go:626`), not confined to the job's build/cache directory.

The cache archive itself is attacker-controlled: any pipeline author with push/CI access to a project can create a job that runs `cache-archiver`/uploads to `Runner.Cache`, and the raw bytes of the uploaded cache blob are never re-validated on the extraction side — the trust boundary assumes the archive was produced by GitLab Runner's own `Archiver` (which does confine paths, per the comment at `commands/helpers/archive/archive.go:88-89`), but nothing prevents an attacker from crafting/uploading an arbitrary zip blob directly to the cache storage backend under a key they control (e.g. via a job with a known cache key, or via a job that swaps/poisons a shared cache before a later job in the same or another pipeline pulls it), then having a subsequent job (their own, or via shared/protected-branch cache key collision) trigger the vulnerable extraction path.

### Impact Explanation
An attacker-crafted cache archive can achieve arbitrary file write on the runner host/helper container, confined only by the filesystem permissions of the user running the `gitlab-runner-helper` process — this includes writing outside `CI_PROJECT_DIR`/`CI_BUILDS_DIR`, breaking the job workspace confinement invariant. Depending on executor (shell executor on a shared host, or a helper process with elevated filesystem access), this can lead to overwriting arbitrary files reachable by that user (e.g., other jobs' cached data, shared paths, or files under the runner's home directory), i.e., cross-job/host file-write escape from a single job's sandbox.

### Likelihood Explanation
Feasible and repeatable: any unprivileged pipeline author can build a normal job that produces a cache archive; only the archive's zip *contents* need to be malicious (crafted via `archive/zip` directly rather than through the runner's own archiver, then uploaded to the same object storage location the runner would use, or by manipulating a job's own cache before extraction in a later job/retry in the same pipeline). No admin privileges, no leaked keys, and no compromise of GitLab or the cache backend's authorization model are required — only that the entries in the (attacker-supplied) cache blob contain traversal/absolute paths, since the extractor performs no server-side or client-side path validation for the Zip format.

### Recommendation
Add the same path-confinement check used in `tarzstd_extractor.go` (`filepath.Abs(filepath.Join(dir, name))` + prefix check against `dir`) to `helpers/archives/zip_extract.go`'s `extractZipFile`/`ExtractZipArchive`, rejecting or skipping entries whose resolved path escapes the target extraction directory. Also reject absolute paths and symlink entries whose resolved target escapes the root, mirroring the deferred-symlink handling already used by `tarzstd_extractor.go:107-122`.

### Proof of Concept

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

// getCacheDownloadURLAndEnv will first try to generate the GoCloud URL if it's

func getCacheDownloadURLAndEnv(ctx context.Context, build *common.Build, cacheKey string) ([]string, map[string]string, error) {
	adapter := cache.GetAdapter(build.Runner.Cache, build.GetBuildTimeout(), build.Runner.ShortDescription(), fmt.Sprintf("%d", build.JobInfo.ProjectID), cacheKey, build.IsFeatureFlagOn(featureflags.HashCacheKeys))

	// Prefer Go Cloud URL if supported
	goCloudURL, err := adapter.GetGoCloudURL(ctx, false)

	if goCloudURL.URL != nil {
		return []string{"--gocloud-url", goCloudURL.URL.String()}, goCloudURL.Environment, err
	}

	if url := adapter.GetDownloadURL(ctx); url.URL != nil {
		args := []string{"--url", url.URL.String()}
		if headURL := adapter.GetHeadURL(ctx); headURL.URL != nil {
			args = append(args, "--head-url", headURL.URL.String())
		}
		return args, nil, nil
	}

	return []string{}, nil, nil
}
