### Title
Changing the prefunded epoch queue orphans already-prefunded deposits - (File: contracts/IdleCDOEpochVariantPrefunded.sol)

### Summary

`IdleCDOEpochVariantPrefunded.setEpochQueue()` can replace the configured queue without checking whether the old queue has deposits already forwarded to the borrower. The CDO subsequently reads all prefunded state from the newly configured queue, while the old queue’s `epochPrefundedDeposits` remains non-zero forever. Because `deleteRequest()` and `claimDepositRequest()` both refuse to release a prefunded deposit until that old queue is processed, affected users permanently lose access to their deposits. This is the same stale-registry/cache bug class: the mutable component is replaced, but state belonging to the previous component is not migrated or settled.

### Finding Description

`setEpochQueue()` only checks owner-or-manager authorization and assigns `epochQueue`; it does not verify that the previous queue has no prefunded deposits awaiting settlement. [1](#0-0) 

During prefunding, the old queue clears `epochPendingDeposits`, stores the amount in `epochPrefundedDeposits`, and sends the underlying directly to the strategy borrower. [2](#0-1) 

At epoch settlement, the CDO queries only the currently configured `epochQueue` for `prefundedDepositsToProcess()` and calls `processPrefundedDeposits()` only on that same queue. [3](#0-2) 

If the queue is replaced after prefunding, the new queue returns zero, so no AA tranche shares are minted for the old queue and its `epochPrefundedDeposits` are never cleared. On a close-pool stop, `_beforeStopEpoch()` also reads `epochPrefundedDeposits()` only from the new queue, so the principal already sent to the borrower is omitted from the recalled amount. [4](#0-3) 

The old queue cannot recover independently: `processPrefundedDeposits()` accepts calls only from the configured CDO, and `deleteRequest()` reverts while `epochPrefundedDeposits[_requestEpoch]` is non-zero. [5](#0-4) [6](#0-5) 

### Impact Explanation

All users whose deposits were prefunded through the old queue permanently lose their queued deposits. The borrower has already received the underlying, but no tranche shares or epoch price are produced for the users because the CDO settles only the replacement queue.

For a close-pool stop, the loss is additionally retained by the borrower rather than merely left as a pending queue claim: the prefunded principal is not included in `additionalPrincipal`, so the CDO does not include it in the amount requested back.

The affected users are unprivileged queue depositors. The trigger is an authorized queue replacement between `processDepositsToBorrower()` and `stopEpochWithDuration()`, not malicious behavior by the queue depositors.

### Likelihood Explanation

The code explicitly recognizes this as an operational invariant but does not enforce it. A routine queue upgrade, replacement, migration, or temporary clearing of `epochQueue` after prefunding can create the condition. The sequence requires only:

1. Users deposit into the prefunded queue during a running epoch.
2. The manager calls `processDepositsToBorrower()`.
3. The owner or manager changes `epochQueue`.
4. The epoch is stopped with `stopEpochWithDuration()`.

No attacker needs privileged access, control of borrower behavior, an oracle manipulation, or a contract revert.

### Recommendation

Prevent changing `epochQueue` while the current queue reports non-zero `prefundedDepositsToProcess()` or otherwise unsettled prefunded state. If queue replacement must be supported, atomically settle or migrate `epochPrefundedDeposits`, `userDepositsEpochs`, and the related epoch price/claim state from the old queue to the new queue.

At minimum, `setEpochQueue()` should revert when both the current and candidate queues differ and the current queue has pending or prefunded deposits for the unsettled epoch.

### Proof of Concept

A Foundry test can reproduce the issue using the existing prefunded-credit-vault fixture:

```solidity
function testQueueChangeOrphansPrefundedDeposits() public {
  uint256 amount = 10_000 * ONE_SCALE;

  // Existing fixture: prefunded CDO, strategy, queue, manager, borrower.
  // Alice deposits for the next epoch while the current epoch is running.
  deal(address(underlying), alice, amount);
  vm.startPrank(alice);
  underlying.approve(address(queue), amount);
  queue.requestDeposit(amount);
  vm.stopPrank();

  // Manager prefunds the queued deposit to the borrower.
  vm.prank(manager);
  queue.processDepositsToBorrower();

  uint256 queuedEpoch = strategy.epochNumber() + 1;
  assertEq(queue.epochPrefundedDeposits(queuedEpoch), amount);
  assertEq(underlying.balanceOf(borrower), amount);

  // Authorized queue replacement before stopEpochWithDuration.
  IdleCDOEpochQueue replacementQueue = _deployQueueForSameCDO();
  vm.prank(manager);
  prefundedCdo.setEpochQueue(address(replacementQueue));

  // Stop the epoch through the required prefunded path.
  vm.warp(prefundedCdo.epochEndDate() + 1);
  deal(address(underlying), borrower, amount + prefundedCdo.expectedEpochInterest());
  vm.prank(borrower);
  underlying.approve(address(prefundedCdo), type(uint256).max);
  vm.prank(manager);
  prefundedCdo.stopEpochWithDuration(0, 0, 30 days, 0);

  // The replacement queue had nothing to process.
  assertEq(replacementQueue.prefundedDepositsToProcess(), 0);

  // The old queue remains unprocessed and Alice cannot delete or claim.
  assertEq(queue.epochPrefundedDeposits(queuedEpoch), amount);
  assertEq(queue.epochPrice(queuedEpoch), 0);

  vm.prank(alice);
  vm.expectRevert(NotAllowed.selector);
  queue.deleteRequest(queuedEpoch);

  vm.prank(alice);
  vm.expectRevert(NotAllowed.selector);
  queue.claimDepositRequest(queuedEpoch);

  // Alice received no tranche shares and the underlying remains at the borrower.
  assertEq(aaTranche.balanceOf(alice), 0);
  assertEq(underlying.balanceOf(borrower), amount);
}
```

The decisive assertions are that `epochPrefundedDeposits` remains non-zero, `epochPrice` remains unset, both withdrawal paths revert, and the old queue cannot invoke `processPrefundedDeposits()` because only the CDO can call it.

  /// @notice delete a deposit request
  /// @param _requestEpoch epoch of the deposit request
  function deleteRequest(uint256 _requestEpoch) external {
    // if the epoch price is already set, deposits were already processed so
    // the deposit request can't be deleted.
    _checkNotAllowed(epochPrice[_requestEpoch] != 0 || epochPrefundedDeposits[_requestEpoch] != 0);

    uint256 amount = userDepositsEpochs[msg.sender][_requestEpoch];
    if (amount == 0) {
      return;
    }
    // reset user deposit for the epoch
    userDepositsEpochs[msg.sender][_requestEpoch] = 0;
    // update pending deposits
    epochPendingDeposits[_requestEpoch] -= amount;
    // transfer underlyings back to the user
    IERC20Detailed(underlying).safeTransfer(msg.sender, amount);

  function processPrefundedDeposits(uint256 _prefundedMinted) external {
    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    _checkNotAllowed(
      // final prefunded settlement is driven only by stopEpoch on the prefunded variant
      msg.sender != idleCDOEpoch ||
      // prefunded flow is supported only for AA queue
      tranche != _cdo.AATranche() ||
      // queue must be explicitly enabled on the prefunded CDO variant
      !_isPrefundedQueueEnabled()
    );

    uint256 _epoch = _prefundedEpochToProcess(_cdo);
    uint256 _prefunded = epochPrefundedDeposits[_epoch];
    // in prefunded mode stopEpoch must not leave queue-held deposits behind
    // and must pass the minted tranche amount for the prefunded funds
    _checkNotAllowed(epochPendingDeposits[_epoch] != 0 || _prefunded == 0);

    // Save epoch price for the prefunded deposits based on underlyings deposited and tranche tokens minted
    // In case of very small prefunded deposits, it's possible that the tranche minting results in 0 shares due to rounding.
    // This should not block epoch finalization, as the borrower already has the funds and the epoch can be priced at the current virtual price.
    epochPrice[_epoch] = _prefundedMinted == 0 ? _cdo.virtualPrice(tranche) : _prefunded * ONE_TRANCHE / _prefundedMinted;
    epochPrefundedDeposits[_epoch] = 0;
