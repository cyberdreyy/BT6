### Title
Unprivileged LP can force `stopEpoch` to revert and freeze all vault funds by keeping an APR0 withdraw request open while APR is raised - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.prepareStopEpochWithApr0` unconditionally reverts with `NotAllowed` when `unscaledApr != 0` while `apr0TotalPrincipal != 0`. `apr0TotalPrincipal` is attacker-controlled: any KYC-passing user can open an APR0 withdraw request during the buffer phase while `unscaledApr == 0`. If the (honest) manager subsequently raises the APR for the next epoch, every `stopEpoch` call reverts inside `prepareStopEpochWithApr0`, so the epoch cannot be closed and the entire pool TVL is frozen — an analog of CVE-2022-22743's "user trapped, unable to exit" bug class.

### Finding Description
In `requestWithdraw`, when `unscaledApr == 0` and the pool is not closed, the request is routed to `_requestWithdrawApr0`, which increments the global `apr0TotalPrincipal` bucket [1](#0-0) . That bucket is only cleared inside `prepareStopEpochWithApr0` at the end of a successful call [2](#0-1) , but the function reverts earlier whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0` [3](#0-2) . `setApr`/`setAprsWithBuffer` do not check `apr0TotalPrincipal` [4](#0-3) , so an APR change is not blocked. The result is a state in which `stopEpoch` (the only path that increments `epochNumber`, matures withdraw receipts via `epochNumber <= lastWithdrawRequest` gating, and returns borrowed funds) always reverts [5](#0-4) .

Recovery requires the honest manager to set `unscaledApr` back to 0 and run a zero-APR epoch to drain the bucket — after which the attacker can re-request during the next `unscaledApr == 0` buffer, repeating the freeze each APR transition.

### Impact Explanation
Temporary freezing of all user funds: while `apr0TotalPrincipal != 0` and `unscaledApr != 0`, no `stopEpoch` can execute, so pending withdraw receipts never mature (claim gate `epochNumber <= lastWithdrawRequest` stays true), borrower funds cannot be recalled, and all LP capital and yield is locked for at least a full epoch-plus-buffer cycle per incident, repeatable by the attacker each time APR is lifted off zero. Cost to the attacker is only the management fee on a minimal APR0 withdraw request.

### Likelihood Explanation
Requires only that the pool operate in APR0 mode for one buffer period (attacker submits the request) and that the manager later raises APR — a normal operational transition. No privileged action by the attacker, no default, and no oracle manipulation needed. Mitigated by the fact that an honest manager can unfreeze by reverting APR to 0, so the freeze is temporary rather than permanent.

### Recommendation
Instead of reverting in `prepareStopEpochWithApr0` when `unscaledApr != 0`, settle the APR0 bucket at the last recorded `apr0RateByEpoch` / zero rate and zero `apr0TotalPrincipal`, or have `setApr`/`setAprsWithBuffer` revert (or first settle) when `apr0TotalPrincipal != 0`. Alternatively, block new `_requestWithdrawApr0` entries once a non-zero APR is scheduled for the next epoch.

### Proof of Concept
```solidity
// Foundry fork test (scaffold mirrors test/foundry/IdleCreditVault.t.sol helpers)
function testApr0RequestFreezesStopEpochAfterAprRaise() external {
    // Pool running with unscaledApr == 0 (APR0 mode)
    _stopCurrentEpochWithApr(0);              // epoch N ends, APR set to 0
    vm.prank(manager); cdoEpoch.startEpoch(); // optional; request occurs in buffer

    // Attacker (any allowed wallet) deposits and opens a tiny APR0 withdraw request
    uint256 tranches = _depositWithUser(attacker, 1e6);
    _requestWithdrawWithUser(attacker, tranches);   // apr0TotalPrincipal > 0

    // Honest manager raises APR for the next epoch
    vm.prank(manager);
    strategy.setAprsWithBuffer(5e18, cdoEpoch.epochDuration(), cdoEpoch.bufferPeriod());

    // Epoch runs; borrower (honest) repays principal + interest
    vm.warp(block.timestamp + cdoEpoch.epochDuration());
    _repayBorrower();

    // Every stopEpoch now reverts inside prepareStopEpochWithApr0
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0);

    // Victim's older pending withdraw receipt cannot mature: epochNumber never increments
    vm.prank(victim);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.claimWithdrawRequest();

    // Only recovery: manager sets unscaledApr back to 0 and burns a full zero-APR epoch,
    // after which the attacker can repeat during the next unscaledApr == 0 buffer.
}
```

  function setAprsWithBuffer(uint256 _unscaledApr, uint256 _duration, uint256 _buffer) external {
    unscaledApr = _unscaledApr;
    setApr(_duration == 0 ? _unscaledApr : _unscaledApr * (_duration + _buffer) / _duration);
  }

  /// @notice set the fixed apr
  /// @dev only cdo and manager can set the apr. If manager manually set apr from 
  /// here it will not be scaled to include the buffer period
  function setApr(uint256 _apr) public {
    address _cdo = idleCDO;

    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
  }
