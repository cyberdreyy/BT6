### Title
Changing `epochQueue` after prefunding permanently orphans queued deposits - ([File: contracts/IdleCDOEpochVariantPrefunded.sol](contracts/IdleCDOEpochVariantPrefunded.sol))

### Summary
`IdleCDOEpochVariantPrefunded.setEpochQueue()` relies on an off-chain operational invariant: the queue must not be changed between `processDepositsToBorrower()` and `stopEpochWithDuration()`. The invariant is documented but not enforced. An ordinary queued depositor can create prefunded state immediately before, or interleaved with, an honest owner/manager queue migration, causing `stopEpochWithDuration()` to settle only the replacement queue. The old queue retains `epochPrefundedDeposits`, has no `epochPrice`, and its users can neither delete nor claim their deposit requests.

### Finding Description
`setEpochQueue()` only checks owner/manager authorization and writes the new address unconditionally. [1](#0-0) 

Queued deposits are first moved from `epochPendingDeposits` to `epochPrefundedDeposits` and transferred directly to the borrower by `processDepositsToBorrower()`. [2](#0-1)  At that point the deposit is no longer cancellable because `deleteRequest()` reverts whenever `epochPrefundedDeposits[_requestEpoch] != 0`. [3](#0-2) 

The only settlement path is `_afterStopEpochWithDuration()`, which reads the currently configured `epochQueue`, asks that queue for the prefunded amount, mints AA shares to it, and calls `processPrefundedDeposits()`. [4](#0-3)  If the configured queue was replaced after the old queue prefunded, the replacement returns zero and the old queue is never priced or cleared.

The transaction sequence can be accidental rather than malicious:

1. Owner or manager configures queue Q1 and a prefunding window.
2. A KYC-passing user calls `Q1.requestDeposit(amount)` while the epoch is running.
3. Manager calls `Q1.processDepositsToBorrower()`, sending `amount` to the borrower.
4. Owner or manager migrates the CDO to queue Q2 through `setEpochQueue(Q2)` before epoch stop.
5. Manager calls `stopEpochWithDuration()`.
6. `_afterStopEpochWithDuration()` queries Q2, sees no prefunded deposit, and leaves Q1's `epochPrefundedDeposits` set.

An equivalent race is possible during migration itself: a user submits `Q1.requestDeposit()` around the honest `setEpochQueue(Q2)` transaction, and the old queue is subsequently prefunded because `_isPrefundedQueueEnabled()` only checks that the CDO has some queue configured, not that it is still that queue. [5](#0-4) 

### Impact Explanation
Every prefunded deposit in the abandoned queue can be permanently frozen. `claimDepositRequest()` requires `epochPrice[_epoch] != 0`, `epochPendingDeposits[_epoch] == 0`, and `epochPrefundedDeposits[_epoch] == 0`. [6](#0-5)  For the orphaned request, the second condition is true, but the first and third remain false forever.

Restoring the old queue after settlement does not provide a normal recovery path: `processPrefundedDeposits()` can only be invoked by the CDO during its own stop hook, and its epoch calculation targets the current/defaulted epoch rather than the orphaned request epoch. [7](#0-6)  The quantified impact is the full `amount` prefunded by affected users; the borrower has already received those assets, while the users receive neither assets nor tranche shares.

### Likelihood Explanation
The issue requires an owner/manager queue change while prefunded deposits are outstanding, so it depends on an operational sequence rather than a single unprivileged transaction. However, it does not require a privileged attacker, a malicious borrower, oracle manipulation, or borrower default. Queue rotation, emergency configuration changes, or a deposit submitted between the operator's off-chain check and the `setEpochQueue()` transaction can trigger it. The contract explicitly identifies this sequence as an invariant but performs no programmatic check. [1](#0-0) 

### Recommendation
Enforce the invariant in `setEpochQueue()`. Before replacing `epochQueue`, query the old queue and revert if either its pending or prefunded deposits for the epoch being processed are non-zero. If the queue interface is fixed, `prefundedDepositsToProcess()` can be used, but it should be supplemented with a pending-deposit check because it intentionally reverts on raw pending deposits.

A safer pattern is:

```solidity
// contracts/IdleCDOEpochVariantPrefunded.sol
uint256 nextEpoch = IdleCreditVault(strategy).epochNumber() + 1;
_checkNotAllowed(
  oldQueue.epochPendingDeposits(nextEpoch) != 0 ||
  oldQueue.epochPrefundedDeposits(nextEpoch) != 0
);
epochQueue = _epochQueue;
```

Additionally, `processDepositsToBorrower()` should verify that `IdleCDOEpochVariantPrefunded(idleCDOEpoch).epochQueue() == address(this)`, preventing deposits into a queue that was replaced after the user's request.

### Proof of Concept
The following Foundry test uses the existing prefunded-queue fixture and helpers from `test/foundry/IdleCDOEpochVariantPrefunded.t.sol`:

```solidity
// test/foundry/IdleCDOEpochVariantPrefunded.t.sol
function testQueueMigrationAfterPrefundingOrphansDeposit() external {
    uint256 amount = 1e6;
    address user = makeAddr("orphaned-prefund-user");
    uint256 requestEpoch = strategy.epochNumber() + 1;

    vm.prank(manager);
    cdoEpoch.setEpochQueue(address(queue));
    vm.prank(manager);
    queue.setPrefundedDepositWindow(PREFUNDED_DEPOSIT_WINDOW);

    _requestDepositWithUser(user, amount);
    _enterPrefundedWindow(PREFUNDED_DEPOSIT_WINDOW);

    // Existing queue-held funds are prefunded to the borrower.
    vm.prank(manager);
    queue.processDepositsToBorrower();
    assertEq(queue.epochPrefundedDeposits(requestEpoch), amount);

    // Honest migration to a second initialized queue before settlement.
    IdleCDOEpochQueue newQueue = new IdleCDOEpochQueue();
    newQueue.initialize(address(cdoEpoch), owner, true);
    vm.prank(manager);
    cdoEpoch.setEpochQueue(address(newQueue));

    uint256 interest = cdoEpoch.expectedEpochInterest();
    uint256 pendingWithdraw = strategy.pendingWithdraws();
    uint256 toRepay = interest + pendingWithdraw;

    deal(address(underlying), strategy.borrower(), toRepay);
    vm.prank(strategy.borrower());
    underlying.approve(address(cdoEpoch), toRepay);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    uint256 duration = cdoEpoch.epochDuration();
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, interest, duration, 0);

    // The replacement queue was settled, not the queue that owns the request.
    assertEq(newQueue.epochPrefundedDeposits(requestEpoch), 0);
    assertEq(queue.epochPendingDeposits(requestEpoch), 0);
    assertEq(queue.epochPrefundedDeposits(requestEpoch), amount);
    assertEq(queue.epochPrice(requestEpoch), 0);

    // The user cannot cancel because funds were already sent to the borrower.
    vm.prank(user);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    queue.deleteRequest(requestEpoch);

    // The user also cannot claim because the orphaned epoch was never priced.
    vm.prank(user);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    queue.claimDepositRequest(requestEpoch);
}
```

This reproduces permanent freezing of the entire `amount` without making any privileged role malicious: the manager processes an apparently valid prefunding batch and later migrates the queue, while the user merely creates an ordinary queued deposit.

```text
  function processDepositsToBorrower() external {
    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    IdleCreditVault _strategy = IdleCreditVault(strategy);
    // only owner or strategy manager can move queued funds to the borrower
    _checkOnlyOwnerOrManager();
    // prefunded flow is supported only for AA queue
    // queue must be explicitly enabled on the prefunded CDO variant
    _checkNotAllowed(tranche != _cdo.AATranche() || !_isPrefundedQueueEnabled());

    // prefunding can be done only while epoch is running
    if (!_cdo.isEpochRunning()) {
      revert EpochNotRunning();
    }
    // Keep prefunding aligned with the same cutoff enforced for new queued deposits.
    uint256 _prefundedWindow = prefundedDepositWindow;
    _checkNotAllowed(_prefundedWindow == 0 || block.timestamp + _prefundedWindow < _cdo.epochEndDate());

    uint256 _epoch = _strategy.epochNumber() + 1;
    // prefunding can happen only once for an epoch
    _checkNotAllowed(epochPrefundedDeposits[_epoch] != 0);
    uint256 _pending = epochPendingDeposits[_epoch];
    if (_pending == 0) {
      return;
    }
    // Recheck after the cutoff because emergency state or the TVL limit can change while queued.
    IdleCDOEpochVariantPrefunded(idleCDOEpoch).checkPrefunding(_pending);

    // Switch the epoch from "queue-held" to "already at borrower" before transferring funds.
    epochPendingDeposits[_epoch] = 0;
    epochPrefundedDeposits[_epoch] = _pending;
    IERC20Detailed(underlying).safeTransfer(_strategy.borrower(), _pending);
```

```text
  /// @notice delete a deposit request
  /// @param _requestEpoch epoch of the deposit request
  function deleteRequest(uint256 _requestEpoch) external {
    // if the epoch price is already set, deposits were already processed so
    // the deposit request can't be deleted.
    _checkNotAllowed(epochPrice[_requestEpoch] != 0 || epochPrefundedDeposits[_requestEpoch] != 0);

    uint256 amount = userDepositsEpochs[msg.sender][_requestEpoch];
    if (amount == 0) {
      return;
    }
    // reset user deposit for the epoch
    userDepositsEpochs[msg.sender][_requestEpoch] = 0;
    // update pending deposits
    epochPendingDeposits[_requestEpoch] -= amount;
    // transfer underlyings back to the user
    IERC20Detailed(underlying).safeTransfer(msg.sender, amount);
```

```text
  /// @notice Process deposits for prefunded flow (called atomically from stopEpoch on prefunded variant)
  /// @param _prefundedMinted tranche tokens minted in CDO for prefunded amount
  function processPrefundedDeposits(uint256 _prefundedMinted) external {
    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    _checkNotAllowed(
      // final prefunded settlement is driven only by stopEpoch on the prefunded variant
      msg.sender != idleCDOEpoch ||
      // prefunded flow is supported only for AA queue
      tranche != _cdo.AATranche() ||
      // queue must be explicitly enabled on the prefunded CDO variant
      !_isPrefundedQueueEnabled()
    );

    uint256 _epoch = _prefundedEpochToProcess(_cdo);
    uint256 _prefunded = epochPrefundedDeposits[_epoch];
    // in prefunded mode stopEpoch must not leave queue-held deposits behind
    // and must pass the minted tranche amount for the prefunded funds
    _checkNotAllowed(epochPendingDeposits[_epoch] != 0 || _prefunded == 0);

    // Save epoch price for the prefunded deposits based on underlyings deposited and tranche tokens minted
    // In case of very small prefunded deposits, it's possible that the tranche minting results in 0 shares due to rounding.
    // This should not block epoch finalization, as the borrower already has the funds and the epoch can be priced at the current virtual price.
    epochPrice[_epoch] = _prefundedMinted == 0 ? _cdo.virtualPrice(tranche) : _prefunded * ONE_TRANCHE / _prefundedMinted;
    epochPrefundedDeposits[_epoch] = 0;
  }

  /// @notice Get the prefunded deposits amount that the prefunded CDO stop flow must settle
  /// @dev Reverts if the target epoch still has raw pending deposits sitting in the queue

  function prefundedDepositsToProcess() external view returns (uint256 _prefunded) {
    uint256 _epoch = _prefundedEpochToProcess(IdleCDOEpochVariant(idleCDOEpoch));
```
