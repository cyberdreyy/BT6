### Title
Unauthenticated-of-elevated-role but session-authenticated view-role users can read internal runtime metrics via `GET /debug/vars` - ([File: core/web/router.go])

### Summary
`debugRoutes` mounts `expvar.Handler()` behind only `auth.Authenticate(... , auth.AuthenticateBySession)`, with no `auth.RequiresXRole` wrapper, unlike every other sensitive endpoint in `v2Routes` (keys, config, users, chains, etc.) which are explicitly wrapped with `auth.RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole`. Any authenticated user, including the lowest-privilege `view` role, can therefore read all registered `expvar` counters (build info, GC/memstats, command-line args, and any custom counters registered elsewhere in the process).

### Finding Description
`debugRoutes` is defined as:
```go
func debugRoutes(app chainlink.Application, r *gin.RouterGroup) {
	group := r.Group("/debug", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	group.GET("/vars", expvar.Handler())
}
``` [1](#0-0) 

`auth.Authenticate` with `AuthenticateBySession` only validates that a valid session cookie maps to *some* user; it does not check `user.Role` at all — that check only happens in the separate `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrappers defined in `core/web/auth/auth.go`. [2](#0-1) [3](#0-2) 

By contrast, every comparably sensitive route in `v2Routes` (e.g. `/keys/*`, `/config`, `/users`) is explicitly gated by one of these role wrappers. [4](#0-3) [5](#0-4) 

Since `debugRoutes` lacks any such role gate, a `view`-role user (the lowest privilege session role) who authenticates normally via `/sessions` can `GET /debug/vars` and receive whatever is registered in Go's `expvar` package for the process — by default this includes `cmdline` and `memstats`, and potentially any other counters registered elsewhere in the chainlink codebase (build/version info, in-flight request counts, etc.).

### Impact Explanation
This is an information-disclosure issue: it exposes internal runtime/build/memory statistics to any authenticated user regardless of role, rather than restricting it to operators/admins. It does not directly enable fund movement, key disclosure, or authentication bypass — `expvar` here only exposes GC/memory/cmdline data, not secrets or private keys. The impact is limited to internal metric/state disclosure to low-privilege authenticated users, which maps to a low-severity "sensitive information disclosure to authenticated non-privileged user" class rather than a critical node-compromise finding, since no credentials, keys, or unauthorized state-changing actions are exposed via this endpoint.

### Likelihood Explanation
Feasibility is high and reproducible: any user account (even `view` role, the least privileged) can authenticate through the standard session endpoint and immediately issue `GET /debug/vars` — no additional CSRF token, role escalation, or race condition is required, since the route only checks for a valid session, not role.

### Recommendation
Wrap the `/debug/vars` route with `auth.RequiresAdminRole` (or at minimum `RequiresEditRole`), consistent with the rest of the sensitive routes in `v2Routes`, e.g.:
```go
group.GET("/vars", auth.RequiresAdminRole(func(c *gin.Context) { expvar.Handler().ServeHTTP(c.Writer, c.Request) }))
```

### Proof of Concept
1. Build a `gin.Engine` via `NewRouter` (or directly call `debugRoutes` on a test router group) with a mock `chainlink.Application`/`AuthenticationProvider`.
2. Create a session for a user with `Role: clsessions.UserRoleView` and set the session cookie.
3. Issue `httptest.NewRequest("GET", "/debug/vars", nil)` with the session cookie attached.
4. Assert the response status is `200 OK` and the body contains expvar keys (e.g. `"cmdline"`, `"memstats"`).
5. Compare against expected behavior if a `RequiresAdminRole`/`RequiresEditRole` gate were present, which should return `403 Forbidden` for `view`-role sessions.

// Authenticate is middleware which authenticates the request by attempting to
// authenticate using all the provided methods.
func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
