### Title
Self-attested `local_supported_signer_protocol_version` lets a single signer's weight tip a version-threshold bucket that lacks genuine (non-liar) majority support - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::determine_latest_supported_signer_protocol_version` tallies weight per exact claimed version and walks versions descending, accumulating weight cumulatively into lower buckets, then returns the highest version whose cumulative weight crosses `reached_agreement`. Because the claimed `local_supported_signer_protocol_version` is purely self-reported with no verification of actual capability, and because the accumulation credits a single high claim toward every version bucket ≤ that claim, one attacker-controlled signer weight can be exactly the margin that tips a bucket over threshold even though the *honest* (non-attacker) weight for that bucket falls short of the required majority once the attacker's own base weight is (correctly) still counted in the denominator via `total_weight`.

### Finding Description
The equality that should hold is: *"a version is selected as globally active only if a real threshold-weight of signers can actually interpret/execute that version."* The code instead computes: [1](#0-0) 

`protocol_versions` is built purely from `update.local_supported_signer_protocol_version`, an unverified, self-reported field with no cryptographic or behavioral binding to what the sender actually runs. The loop then accumulates `total_weight_support` cumulatively from the highest claimed version downward, so a single high claim contributes to every version bucket at or below it, including buckets the true majority reaches only marginally.

Numeric counterexample (weight units, threshold 70%): total weight = 100, of which attacker = 10, honest-v1-only = 30, honest-v2 = 60. Excluding the attacker, the honest total is 90 and 70% of 90 = 63; honest v2 support (60) does **not** meet a genuine 70% majority excluding the attacker. But because `total_weight` (the denominator in `reached_agreement`) already includes the attacker's base weight, the real cutoff used by the code is 70% of 100 = 70, and the attacker's dishonest credit (10) added to the honest-v2 bucket (60) makes `total_weight_support = 70`, which is `>= reached_agreement`, so version 2 is selected: [2](#0-1) 

`determine_global_state` then unconditionally tags the resulting `SignerStateMachine` with this version: [3](#0-2) 

Compounding this, `LocalStateMachine::update_protocol_version` in the signer adopts whatever version the evaluator returns with **no clamp** against the local signer's own `local_supported_signer_protocol_version`: [4](#0-3) 

Only `try_into_update_message_with_version` clamps *outgoing* gossip content to the local signer's own cap (lines 190-202 of the same file), but that clamp does nothing to prevent the local state machine from *adopting* a globally-agreed version higher than what it locally reported/supports, since `update_protocol_version` writes `active_signer_protocol_version` directly from the evaluator's return value.

Existing guards that were checked and do not close this gap:
- `reached_agreement`/`reached_disagreement` operate on `total_weight`, which includes the lying attacker's weight in the denominator, so the threshold check is not "majority excluding known liars" — there is no way to exclude a liar since lying is undetectable from the message alone.
- `insert_update` only checks that the address is a known weighted signer, not that the claimed version is truthful.
- Nothing in `StateMachineUpdate`/`StateMachineUpdateContent` binds `local_supported_signer_protocol_version` to any verifiable signal of the sender's actual running code.

### Impact Explanation
This breaks the DOMAIN-binding property that a protocol version tag must correspond to a version the interacting signers actually run. Because `determine_latest_supported_signer_protocol_version` and `determine_global_state` are pure deterministic functions of the same gossiped `address_updates` map, *all* signers (honest and attacker) that have received the same gossip arrive at the same (wrong) answer, and `update_protocol_version` in the signer state machine adopts that version with no clamp to the local signer's genuine capability. This can wedge signers who genuinely only support the lower version into operating under a version whose behavior (e.g., `SortitionStateVersion::from_protocol_version`-gated validation logic) their own code path was not intended to run yet, which is a liveness/consistency risk (High) rather than a directly forged/valid signature on an invalid block, since it requires the attacker's weight to land exactly in the margin between the honest bucket weight and the (attacker-inclusive) threshold. It is repeatable for as long as the mixed-version window persists and the attacker keeps gossiping the same lie.

### Likelihood Explanation
Preconditions: a live reward-set cycle where the network is mid-upgrade (mixed real protocol-version support across signers), and the attacker's own weight must be sized so it is the deciding margin between the honest-only bucket weight and the (attacker-inclusive) threshold — a real but narrow precondition. Attacker cost is exactly the stated single-signer-slot weight plus ordinary StackerDB gossip of a `StateMachineUpdate`; no privileged role, no auth token, no other signer's key is needed. It is repeatable every gossip round as long as the margin condition holds.

### Recommendation
- Exclude an address's own weight from the numerator credit for versions the network cannot independently corroborate, or require some form of attestation/verification tied to actual node/software version rather than an arbitrary self-reported `u64`.
- Alternatively, when computing `reached_agreement` for protocol-version selection, recompute a majority bound that is robust to a bounded number of dishonest/liar-weight contributions (e.g., only allow a version to be selected if it would still cross threshold after removing any single address's contribution), removing the single-attacker tipping-point property.
- Clamp `active_signer_protocol_version` adopted in `LocalStateMachine::update_protocol_version` (`stacks-signer/src/v0/signer_state.rs`) to `min(eval_result, local_supported_signer_protocol_version)` so a signer never adopts a version above what it itself is willing/able to run, closing the "blind adoption" half of the bug even if the evaluator briefly returns an inflated version.

### Proof of Concept
Rust test plan (to be added under `libsigner/src/tests/signer_state.rs`):
1. Construct a `GlobalStateEvaluator` with `address_weights`: honest_v1 = 30, honest_v2 = 60, attacker = 10 (total = 100).
2. Insert `StateMachineUpdate`s: honest_v1 address reports `local_supported_signer_protocol_version = 1`; honest_v2 address reports `2`; attacker address reports `2` (lie — attacker does not run v2 logic).
3. Assert baseline: compute the same evaluator with the attacker's update removed and its weight also removed from `address_weights`/`total_weight` (i.e., "genuine majority excluding attacker") — assert `determine_latest_supported_signer_protocol_version()` on this reduced set returns `1` (or `None`), because honest v2 weight (60) does not meet 70% of honest total (90) = 63.
4. Assert on the full set (attacker included): `determine_latest_supported_signer_protocol_version()` returns `2`, demonstrating the attacker's single lying vote tipped the bucket that genuine majority (excluding attacker) does not support.
5. Additionally assert, via `LocalStateMachine::update_protocol_version`, that an honest signer object whose own `local_supported_signer_protocol_version == 1` ends up with `active_signer_protocol_version == 2` in its `SignerStateMachine` after calling `update_protocol_version`, showing the missing clamp adopts a version beyond its own declared/local capability.

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    fn update_protocol_version(
        &mut self,
        stacks_client: &StacksClient,
        eval: &mut GlobalStateEvaluator,
        local_supported_signer_protocol_version: u64,
    ) {
        // Before we ever access eval...we should make sure to include our own local state machine update message in the evaluation
        let Ok(local_update) =
            self.try_into_update_message_with_version(local_supported_signer_protocol_version)
        else {
            return;
        };

        let old_protocol_version = local_update.active_signer_protocol_version;
        eval.insert_update(
            stacks_client.get_signer_address().clone(),
            local_update.clone(),
        );
        // Check if we should update our active protocol version
        let active_signer_protocol_version = eval
            .determine_latest_supported_signer_protocol_version()
            .unwrap_or(old_protocol_version);

        if active_signer_protocol_version != old_protocol_version {
            info!("Signer State: Updating active signer protocol version from {old_protocol_version} to {active_signer_protocol_version}");

                crate::monitoring::SignerAgreementStateChangeReason::ProtocolUpgrade,
            );
            let (burn_block, burn_block_height) = local_update.content.burn_block_view();
            let current_miner = local_update.content.current_miner();
            let tx_replay_set = local_update.content.tx_replay_set();

            *self = Self::Initialized(SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                tx_replay_set,
            });
        }
