### Title
Single-step activation registry admin rotation lacks a two-step transfer, risking permanent loss of feature-activation control - (File: crates/common/precompiles/src/activation/storage.rs)

### Summary
`ActivationRegistryStorage::set_admin` performs a one-shot, irrevocable rotation of the activation-registry admin address in response to a single `setAdmin` transaction, with no propose/accept ("two-step") pattern, unlike the `PolicyRegistry`'s admin-transfer logic in the same codebase which explicitly implements `stage_update_admin` / `finalize_update_admin`.

### Finding Description
`set_admin` validates that the call is non-static, that state-backed admin storage is enabled, and that `new_admin` is non-zero, then immediately requires the current admin as caller and overwrites the `admin` storage slot in one transaction: [1](#0-0) 

The only sanity check on `new_admin` is a zero-address check; there is no mechanism to stage the new admin and require it to claim ownership from that address, so a typo'd, unreachable, or otherwise uncontrolled non-zero address is accepted and immediately becomes the sole authority. Authorization for the admin-only actions is enforced by `require_admin_caller`, which compares `storage.caller()` to `authorized_admin`: [2](#0-1) 

By contrast, the `PolicyRegistry` in the same repository implements the exact two-step pattern recommended in the referenced report — `stage_update_admin` followed by a `finalize_update_admin` call that must originate from the pending admin address — as shown by its test coverage: [3](#0-2) 

This asymmetry indicates the codebase's own convention is two-step admin transfer for critical roles, but the activation registry's `setAdmin`/`admin` mutation path was not brought in line with that convention.

### Impact Explanation
The activation-registry admin is the sole authority permitted to call `activate`/`deactivate` for Base-native precompile features (`PolicyRegistry`, `B20Stablecoin`, `B20Asset`) via `set_activated`, which is gated by the same `require_admin_caller`: [4](#0-3)  and [5](#0-4) . Once `admin` is transferred to an unreachable address in a single step, the chain permanently loses the ability to activate or deactivate these features going forward — an unrecoverable freezing of a core governance control, reachable directly through the public `setAdmin` calldata path dispatched in `activation/dispatch.rs`: [6](#0-5) . Existing feature activation states are unaffected, but any future rollout/rollback of gated features (e.g., activating `B20Asset` or `B20Stablecoin` support, or deactivating a feature found to be buggy) becomes permanently blocked, which can force a chain-level fix (e.g., a hard fork/state override) rather than an on-chain recoverable remedy.

### Likelihood Explanation
This function is only reachable by whoever currently holds the activation-registry admin role (a highly privileged, presumably small set of signers/governance), so it is not exploitable by an arbitrary unprivileged sender — the risk is operational/human error (wrong address, lost key, multisig misconfiguration) rather than external attack, mirroring the acknowledged nature of the original Tracer finding. The codebase already implements the safer two-step pattern for `PolicyRegistry` admin transfer, suggesting the maintainers are aware of and mitigate this risk elsewhere, but the activation registry's admin-only `setAdmin` was not updated to match, so the residual risk here is real but bounded to admin-key operational mistakes.

### Recommendation
Introduce a two-step admin rotation for the activation registry mirroring the `PolicyRegistry`'s `stage_update_admin`/`finalize_update_admin` pattern: add a `pending_admin` slot, have `setAdmin` (or a renamed `stageAdmin`) only stage the candidate, and require a subsequent transaction signed by the pending admin (e.g., `acceptAdmin`/`finalizeAdmin`) to complete the rotation and emit `AdminChanged`. This allows recovery from an incorrect address before the transfer is finalized, consistent with the pattern already used for `PolicyRegistry` admin transfers in this codebase.

### Proof of Concept
1. Current activation-registry admin `A` calls `setAdmin(newAdmin = X)` where `X` is a typo'd/unreachable address (any non-zero address with no known private key).
2. `set_admin` passes the zero-address check, `require_admin_caller` succeeds because caller `A` matches the current stored admin, and `self.admin.write(new_admin)` immediately commits `X` as the new admin: [7](#0-6) .
3. Any subsequent call to `activate`/`deactivate`/`setAdmin` now requires `caller == X`, which can never be satisfied, permanently locking out feature activation control — there is no staged/pending state to revert to, unlike the `PolicyRegistry.admin_transfer_two_step` flow that allows a mis-staged admin to be corrected before finalization: [8](#0-7) .

    /// Sets the activation registry admin address.
    pub fn set_admin(
        &mut self,
        new_admin: Address,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }
        if !admin_config.state_enabled {
            return Err(BasePrecompileError::revert(
                IActivationRegistry::AdminStorageNotEnabled {},
            ));
        }
        if new_admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::ZeroAdminAddress {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        self.__initialize()?;
        self.admin.write(new_admin)?;
        self.emit_event(IActivationRegistry::AdminChanged {
            previousAdmin: caller,
            newAdmin: new_admin,
            caller,
        })?;

        Ok(())
    }

    /// Sets the feature activation state.
    pub fn set_activated(
        &mut self,
        feature: B256,
        to_activated_state: bool,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        // Keep this guard at the shared mutation boundary so `activate`, `deactivate`, and direct
        // `set_activated` callers all get the same static-call behavior after calldata validation.
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        let current_activated_state = self.features.at(&feature).read()?;

        let is_activating_and_already_activated = to_activated_state && current_activated_state;
        let is_deactivating_and_already_deactivated =
            !to_activated_state && !current_activated_state;

        if is_activating_and_already_activated {
            return Err(BasePrecompileError::revert(IActivationRegistry::AlreadyActivated {
                feature,
            }));
        }
        if is_deactivating_and_already_deactivated {
            return Err(BasePrecompileError::revert(IActivationRegistry::FeatureNotActivated {
                feature,
            }));
        }

        if to_activated_state {
            self.__initialize()?;
            self.features.at_mut(&feature).write(true)?;
            self.emit_event(IActivationRegistry::FeatureActivated { feature, caller })?;
        } else {
            self.features.at_mut(&feature).delete()?;
            self.emit_event(IActivationRegistry::FeatureDeactivated { feature, caller })?;
        }

        Ok(())
    }

    /// Returns the effective admin if one is configured and the caller address can be authorized.
    pub fn authorized_admin(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        let caller = self.storage.caller();
        if caller.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        let admin = self.admin(admin_config)?;
        if admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        Ok(admin)
    }

    /// Reverts unless the current caller is the effective activation admin.
    pub fn require_admin_caller(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        let caller = self.storage.caller();
        let admin = self.authorized_admin(admin_config)?;
        if caller != admin {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        Ok(caller)
    }
