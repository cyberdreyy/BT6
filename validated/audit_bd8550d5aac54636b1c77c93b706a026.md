### Title
Unauthenticated `/v2/resume/:runID` endpoint allows any third party to inject the finalization result of a pending async pipeline run - (File: `core/web/router.go`, `core/web/pipeline_runs_controller.go`)

### Summary
The `Tranche`/`SharesCooldown` bug class is: a permissionless "finalize" step lets any caller supply the value that determines the outcome of a request the user already created, rather than enforcing what was chosen/expected at request time. The Chainlink node has a structurally identical pattern: async pipeline tasks (e.g. `BridgeTask`, `ETHTxTask`) suspend a job run and expect an external adapter to later call back into the node to resume it with a result value. That callback is `PipelineRunsController.Resume`, and it is deliberately registered without any authentication middleware.

### Finding Description
`v2Routes` mounts the resume endpoint on the unauthenticated router group: [1](#0-0) 

`PipelineRunsController.Resume` parses only the `runID` path param (which is actually the pipeline task's UUID) and an attacker-supplied JSON body, then directly calls `ResumeJobV2` with whatever value/error the body contains — there is no secret, HMAC, or bridge-identity check tying the caller to the original request: [2](#0-1) 

`ResumeJobV2`/`ResumeRun` then unconditionally writes the caller-supplied result into the task run and restarts the pipeline: [3](#0-2) [4](#0-3) 

The only thing standing between an unprivileged caller and “finalizing” someone else’s pending job run with an arbitrary chosen result is the unguessability of the task UUID passed in the URL. There is no verification that the caller is the specific bridge/adapter that was actually invoked for that task, no signature, and no binding of the result to the original request parameters (analogous to the `SharesCooldown` design, where the `finalize` caller could choose an arbitrary output token instead of the one persisted at request time). The audit event is explicitly labeled `audit.UnauthedRunResumed`, confirming the code path is intentionally permissionless: [5](#0-4) 

### Impact Explanation
If a task UUID is ever leaked, logged, guessed, or observed (e.g., via bridge request logs, network capture of the outbound bridge call, or a compromised/curious external adapter host), any third party can POST/PATCH to `/v2/resume/{taskID}` with an arbitrary payload and force the pipeline to resume with attacker-chosen data. Depending on the job's downstream tasks (e.g., feeding into `ETHTxTask` or contract-writing tasks), this can result in incorrect data being written on-chain, corrupted job results, or premature/incorrect finalization of a job run — the same class of "third party overrides the value the flow was supposed to use" impact described in the report, mapped onto the node's job-run finalization path instead of a token-selection field.

### Likelihood Explanation
The endpoint is unauthenticated by design (bridges have no session/API-key context when calling back), so the only protection is secrecy of the UUID. This is a known, accepted design tradeoff in Chainlink (UUIDs act as bearer tokens), but it is still an "unprivileged-actor analog" to the reported bug: any external party who obtains a valid pending task ID has full, unauthenticated ability to determine the finalization content of that specific job run, with no secondary check tying the result to the original bridge/request.

### Recommendation
Bind resumption to the specific outbound request instead of relying solely on UUID secrecy: e.g., require the bridge to present the `OutgoingToken`/`OutgoingSecret` (already used for external-initiator callbacks, see `core/bridges/external_initiator.go`) or a per-request signed callback token generated when the async task is created, and verify it in `PipelineRunsController.Resume` before accepting the result. This mirrors the report's mitigation of persisting the user's original chosen parameter and enforcing it during permissionless finalization.

### Proof of Concept
1. Create a job with an async `bridge` task (as in `core/services/job/runner_integration_test.go`), which suspends the pipeline run and returns a `PipelineTaskRunID` (UUID) intended only for the target adapter to call back.
2. An attacker who obtains this UUID (via logs, network sniffing of the outbound bridge request, or a curious/compromised adapter operator) sends: `PATCH /v2/resume/<taskID>` with body `{"data": <attacker-chosen value>}`.
3. `PipelineRunsController.Resume` (`core/web/pipeline_runs_controller.go:133-159`) accepts the request with no authentication, calls `ResumeJobV2` → `ResumeRun` (`core/services/pipeline/runner.go:734-757`), which writes the attacker's value into `UpdateTaskRunResult` and restarts the pipeline — finalizing the job run with data the attacker chose rather than what the real adapter would have returned.

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
```

```go
func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
```
