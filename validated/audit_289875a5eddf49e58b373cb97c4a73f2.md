### Title
Race condition (TOCTOU) in Gateway JWT replay-guard allows duplicate authorization of workflow trigger requests - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The Sherlock report's bug class is a missing/late update of a "consumed" state variable (`self.claimed`) that lets an attacker replay the same claim repeatedly. The closest reachable analog in this Chainlink codebase is the `WorkflowMetadataHandler.Authorize` function used to authenticate inbound HTTP Trigger requests from unprivileged clients through the CRE Gateway: it checks whether a JWT `jti` has already been used and records the usage as two **separate, non-atomic** operations against a shared cache, rather than a single atomic check-and-set.

### Finding Description
`Authorize` performs JWT verification and replay protection like this: [1](#0-0) 

The relevant sequence is:
1. `h.jwtCache.isReplay(claims.ID)` — takes an `RLock`, checks presence in the map, releases the lock.
2. Signer/authorized-key lookups happen (no locking related to the JWT cache).
3. `h.jwtCache.recordUsage(claims.ID)` — takes a `Lock` and inserts the `jti` into the map, but only **after** all prior checks succeed.

`isReplay` and `recordUsage` are implemented as independent locked sections: [2](#0-1) 

Because the "check" and the "record" are not performed under one critical section (unlike the vault package's `RequestReplayGuard.CheckAndRecord`, which correctly combines check+insert atomically under a single mutex — [3](#0-2) ), two concurrent `Authorize` calls carrying the identical JWT (same `jti`, same digest) can both pass `isReplay` as `false` before either calls `recordUsage`. Both then proceed as authorized, and both `HandleUserTriggerRequest` calls will forward the same signed request into workflow execution.

This is directly analogous to the vulnerable pattern in `InflationaryVest.vy` where `claimable()`/`claim()` recompute state without properly synchronizing the "has already been consumed" check against the update, permitting the same authorization artifact to be consumed multiple times.

### Impact Explanation
An unprivileged external client can trigger the underlying CRE workflow more than once using a single, otherwise properly-scoped, single-use JWT if it fires the same signed trigger request concurrently (e.g., duplicate HTTP POSTs sent in parallel, or via HTTP retries/proxies that race). This defeats the "single-use" guarantee the JWT is meant to provide (the code and tests explicitly assert JWTs are single-use: "JWT token has already been used" per the negative test in `workflow_metadata_handler_test.go`), leading to duplicate/unauthorized workflow executions from a single authorized request — i.e., a request-impersonation/duplication bypass of the intended one-shot authorization semantics.

### Likelihood Explanation
Likelihood is moderate: it requires the attacker (or client) to send the same signed JWT-bearing request in near-simultaneous parallel requests, which is trivial for any external client to script (no special network position or privileges required — this is a normal unprivileged HTTP client interacting with the internet-facing Gateway's HTTP Trigger endpoint). The race window is small (time between `isReplay` read and `recordUsage` write) but concurrent identical requests are easy to construct deterministically by an attacker who controls request timing.

### Recommendation
Merge the check and the recording of JWT usage into a single atomic operation, protected by one lock, mirroring the pattern already used correctly in `core/capabilities/vault/request_replay_guard.go`'s `CheckAndRecord`. For example, replace `isReplay` + `recordUsage` with a single `checkAndRecord(jti string) error` method that holds the write lock for the entire check-then-insert sequence, and call it immediately after JWT signature/digest verification succeeds (before or atomically with the remaining authorization checks) so that no two concurrent calls can both observe "not yet used."

### Proof of Concept
Not independently reproducible against a live system without code execution access; the race is inferable directly from the source: `isReplay` (RLock/RUnlock) and `recordUsage` (Lock/Unlock) in `workflow_metadata_handler.go` lines 399-412 are separate critical sections invoked non-atomically in `Authorize` (lines 80-108), so two goroutines calling `Authorize` with the same `jti` concurrently can both pass the `isReplay` check before either calls `recordUsage`. A background Devin agent with code-execution access could confirm by writing a concurrency test that calls `WorkflowMetadataHandler.Authorize` from two goroutines simultaneously with an identical JWT and asserting both return success.

```go
func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
```

```go
func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
```

```go
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
```
