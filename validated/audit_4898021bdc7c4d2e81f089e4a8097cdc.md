### Title
Case-Sensitive Bridge Name Uniqueness Check Allows Registering Duplicate Bridge Types With Different Casing - (File: core/web/bridge_types_controller.go)

### Summary
The bridge type registration flow (`BridgeTypesController.Create` calling `ValidateBridgeTypeNotExist`) is intended to reject registration of a bridge whose name already exists, but the uniqueness check is performed on the raw, non-normalized `BridgeName` string, which is stored in a plain, case-sensitive Postgres column (`bridge_types.name`, primary key, no `lower()` index or citext type). This mirrors the reported analog bug class: a case-sensitive uniqueness check that can be bypassed by changing letter case, allowing the same logical bridge/adapter identity to be registered multiple times.

### Finding Description
`ValidateBridgeTypeNotExist` looks up the bridge purely by the requested name: [1](#0-0) 

`orm.FindBridge`/`FindBridges` issue plain equality/`IN` queries with no case normalization: [2](#0-1) 

`CreateBridgeType` inserts the name verbatim: [3](#0-2) 

Critically, `BridgeTypeRequest.Name` is a plain `BridgeName` (`type BridgeName string`) field bound directly via `c.ShouldBindJSON(btr)`: [4](#0-3) 

Standard Go `encoding/json` unmarshaling of a `string`-based type does **not** invoke `ParseBridgeName` (which is the only place that lowercases the name): [5](#0-4) 

`ParseBridgeName` is only used for validation of allowed characters in `ValidateBridgeType`, and its normalized (lowercased) return value is explicitly discarded (`if _, err := bridges.ParseBridgeName(...)`), so the original, unmodified casing from the request continues to flow into `NewBridgeType`, `ValidateBridgeTypeNotExist`, and `CreateBridgeType`: [6](#0-5) [7](#0-6) 

This is unlike the `external_initiators` table and `users` table, which both explicitly enforce case-insensitive uniqueness via `lower(name)`/`lower(email)` unique indexes and normalize input in code: [8](#0-7) [9](#0-8) 

The GraphQL resolver path (`Resolver.CreateBridge`) has the identical flaw — it builds `BridgeTypeRequest{Name: bridges.BridgeName(args.Input.Name)}` directly from the raw GraphQL string with no lowercasing, then calls the same unnormalized `ValidateBridgeTypeUniqueness`/`FindBridge`: [10](#0-9) [11](#0-10) 

As a result, an authenticated user with edit/admin role can register `"MyBridge"` and then `"mybridge"` (or `"MYBRIDGE"`) as two distinct bridge type rows with different URLs, tokens, and confirmation counts, even though the API's uniqueness check message ("Bridge Type X already exists") implies only one instance should exist.

### Impact Explanation
Bridges are the externally-facing adapter registrations that job pipeline `bridge` tasks reference by name at runtime to route external data requests (and payments via `minimum_contract_payment`). Because task-type resolution elsewhere in the codebase normalizes bridge/task names to lowercase (`ParseBridgeName` is used when parsing pipeline task specs), while the bridge registry itself stores/queries names case-sensitively, two differently-cased entries for what pipeline authors intuitively treat as "the same" bridge name can silently diverge: one job may resolve to a bridge pointing at a benign URL/adapter while a superficially identical-looking bridge name is quietly repointed elsewhere, or duplicate registrations can be used to route around administrative expectations that a given bridge name is unique. This is analogous to the reported issue where duplicate registration of the same logical asset under different casing splits functionality/liquidity across multiple records — here it can split job routing/funds-adjacent bridge configuration across multiple divergent bridge definitions that operators believe is a single, uniquely-named entity.

### Likelihood Explanation
Exploitation only requires an authenticated Chainlink node operator UI/API user with edit or admin role (the role required by `authenticateUserCanEdit` for `CreateBridge`, and by admin-auth middleware for the REST bridge_types endpoint) to submit a bridge creation request whose name differs only by case from an existing bridge. No special conditions are needed beyond normal API access already granted to non-admin "edit" role users, making this straightforward to trigger.

### Recommendation
Normalize (e.g., lowercase via `ParseBridgeName`) the incoming bridge name immediately upon deserialization (implement `UnmarshalJSON` on `BridgeName`, or explicitly reassign `btr.Name` to the value returned from `ParseBridgeName` in both `BridgeTypesController.Create` and `Resolver.CreateBridge`) before any uniqueness check or persistence, and/or add a case-insensitive unique index (`lower(name)`) on `bridge_types.name`, consistent with the `external_initiators` and `users` tables.

### Proof of Concept
1. Authenticate as a user with `edit` role.
2. `POST /v2/bridge_types` with `{"name":"HLBTest","url":"https://a.example.com"}` → succeeds, creates bridge `HLBTest`.
3. `POST /v2/bridge_types` with `{"name":"hlbtest","url":"https://b.example.com"}` → `ValidateBridgeTypeNotExist` calls `orm.FindBridge(ctx, "hlbtest")`, which does not match the stored `HLBTest` row (case-sensitive equality), so validation passes and a second, distinct `bridge_types` row `hlbtest` is created pointing at a different URL.
4. `GET /v2/bridge_types` now lists two separate bridge entries for what operators intend to be the same bridge name, differing only by case, each with independent URL/token/confirmations configuration.

// ValidateBridgeTypeNotExist checks that a bridge has not already been created
func ValidateBridgeTypeNotExist(ctx context.Context, bt *bridges.BridgeTypeRequest, orm bridges.ORM) error {
	fe := models.NewJSONAPIErrors()
	_, err := orm.FindBridge(ctx, bt.Name)
	if err == nil {
		fe.Add(fmt.Sprintf("Bridge Type %v already exists", bt.Name))
	}
	if err != nil && !errors.Is(err, sql.ErrNoRows) {
		fe.Add(fmt.Sprintf("Error determining if bridge type %v already exists", bt.Name))
	}
	return fe.CoerceEmptyToNil()
}

// ValidateBridgeType checks that the bridge type has the required field with valid values.
func ValidateBridgeType(bt *bridges.BridgeTypeRequest) error {
	fe := models.NewJSONAPIErrors()
	if len(bt.Name.String()) < 1 {
		fe.Add("No name specified")
	}
	if _, err := bridges.ParseBridgeName(bt.Name.String()); err != nil {
		fe.Merge(err)
	}
	u := bt.URL.String()
	if len(strings.TrimSpace(u)) == 0 {
		fe.Add("URL must be present")
	}
	if bt.MinimumContractPayment != nil &&
		bt.MinimumContractPayment.Cmp(assets.NewLinkFromJuels(0)) < 0 {
		fe.Add("MinimumContractPayment must be positive")
	}
	return fe.CoerceEmptyToNil()
}

// FindBridges looks up multiple bridges in a single query.
// Errors unless all bridges successfully found. Requires at least one bridge.
// Expects all bridges to be unique
func (o *orm) FindBridges(ctx context.Context, names []BridgeName) ([]BridgeType, error) {
	stmt := "SELECT * FROM bridge_types WHERE name IN (?)"
	query, args, err := sqlx.In(stmt, names)
	if err != nil {
		return nil, err
	}

	var bts []BridgeType

	if err = o.ds.SelectContext(ctx, &bts, o.ds.Rebind(query), args...); err != nil {
		return nil, err
	}

	if len(bts) != len(names) {
		return nil, pkgerrors.Errorf("not all bridges exist, asked for %v, exists %v", names, bts)
	}

	return bts, nil
}

			return err

	})

	return pkgerrors.Wrap(err, "CreateBridgeType failed")
}

type BridgeName string

var bridgeNameRegex = regexp.MustCompile("^[a-zA-Z0-9-_]*$")

// ParseBridgeName returns a formatted Task type.
func ParseBridgeName(val string) (BridgeName, error) {
	if !bridgeNameRegex.MatchString(val) {
		return "", fmt.Errorf("task type validation: name %v contains invalid characters", val)
	}

	return BridgeName(strings.ToLower(val)), nil
}

// CreateBridge creates a new bridge.
func (r *Resolver) CreateBridge(ctx context.Context, args struct{ Input createBridgeInput }) (*CreateBridgePayloadResolver, error) {
	if err := authenticateUserCanEdit(ctx); err != nil {
		return nil, err
	}

	var webURL models.WebURL
	if len(args.Input.URL) != 0 {
		rURL, err := url.ParseRequestURI(args.Input.URL)
		if err != nil {
			return nil, err
		}
		webURL = models.WebURL(*rURL)
	}
	minContractPayment := &assets.Link{}
	if err := minContractPayment.UnmarshalText([]byte(args.Input.MinimumContractPayment)); err != nil {
		return nil, err
	}

	btr := &bridges.BridgeTypeRequest{
		Name:                   bridges.BridgeName(args.Input.Name),
		URL:                    webURL,
		Confirmations:          uint32(max(0, args.Input.Confirmations)),
		MinimumContractPayment: minContractPayment,
		UseConnectionManager:   args.Input.UseConnectionManager != nil && *args.Input.UseConnectionManager,
	}

	bta, bt, err := bridges.NewBridgeType(btr)
	if err != nil {
		return nil, err
	}
	orm := r.App.BridgeORM()
	if err = ValidateBridgeType(btr); err != nil {
		return nil, err
	}
	if err = ValidateBridgeTypeUniqueness(ctx, btr, orm); err != nil {
		return nil, err
	}

func ValidateBridgeTypeUniqueness(ctx context.Context, bt *bridges.BridgeTypeRequest, orm bridges.ORM) error {
	_, err := orm.FindBridge(ctx, bt.Name)
	if err == nil {
		return fmt.Errorf("bridge type %v already exists", bt.Name)
	}
	if !errors.Is(err, sql.ErrNoRows) {
		return fmt.Errorf("error determining if bridge type %v already exists", bt.Name)
	}

	return nil
}
