### Title
Vault gateway replay guard allows unprivileged front-running to permanently deny legitimate allowlisted vault requests - ([File: core/capabilities/vault/authorizer.go])

### Summary
The Vault gateway's request-authorization pipeline uses a single global `RequestReplayGuard` keyed only by request digest, without binding "who submitted first" to any authenticated identity. Because the digest is deterministic and derived purely from the request's public fields (`method`, `id`, `params`), and because a legitimate request is fanned out unencrypted to every DON member node and travels over the internet-facing gateway before authorization completes, an unprivileged third party that observes/replays an identical copy of a not-yet-authorized request can win the race to consume the replay-guard slot first. This causes the legitimate owner's original submission to be permanently rejected as `ErrRequestAlreadySeen`, denying the underlying vault operation (secrets create/update/delete/list) until the allowlist entry's expiry — an analog of the PermitSubmitterHook front-running bug, where a signature/digest that is meant to be single-use can be consumed by anyone who observes it before the intended executor.

### Finding Description
`Authorizer.AuthorizeRequest` in [1](#0-0)  calls `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` immediately after either the allowlist-based or JWT-based auth succeeds. The `RequestReplayGuard` is a simple shared map keyed by digest with no notion of caller identity: whichever request reaches `CheckAndRecord` first "wins" the digest, and every subsequent request with the same digest is rejected with `ErrRequestAlreadySeen`, as implemented in [2](#0-1) .

For the allowlist-based path (`req.Auth == ""`, the default/back-compat path), `AllowListBasedAuth.AuthorizeRequest` explicitly does **not** perform replay protection itself — it is documented and tested that "replay protection lives in the generic Authorizer," and the same allowlisted request is accepted repeatedly by `AllowListBasedAuth` alone: [3](#0-2) . The digest that must match is computed purely from the deterministic `req.Digest()` over the JSON-RPC request's `method`/`id`/`params`, as shown in [4](#0-3) , and this exact digest value is published on-chain by the owner via `WorkflowRegistry.AllowlistRequest` prior to submitting the real request, as seen in the test helper [5](#0-4) .

The gateway-side entry point that any internet-facing, unauthenticated client can call is `handler.HandleJSONRPCUserMessage` in [6](#0-5) , which forwards the request to `requestProcessor.ProcessRequest` → `Authorizer.AuthorizeRequest` before any secret-specific authentication of the *caller* (as opposed to the request content) occurs. Once authorized, the exact same request bytes are additionally broadcast, unmodified, to every DON member node via `fanOutToVaultNodes` (`h.don.SendToNode`) — see [7](#0-6)  — giving multiple additional vantage points from which the request's exact byte content becomes observable to non-owners before the transaction fully resolves.

Because the replay-guard slot is consumed on the *first* successful authorization regardless of which client submitted it, an attacker who obtains a byte-identical copy of a soon-to-be-submitted allowlisted request (e.g., by intercepting gateway traffic, running/compromising a relay in front of the gateway, or observing traffic to one of the DON member nodes before the legitimate flow completes) can resubmit that exact request to the gateway ahead of the real owner. Their resubmission passes `AllowListBasedAuth` (since it checks only the digest against the on-chain allowlist, not the sender) and is recorded first by the replay guard. The legitimate owner's subsequent identical submission is then rejected with `ErrRequestAlreadySeen` for the remainder of the allowlisted `ExpiryTimestamp` window (potentially hours), functioning as a persistent denial-of-service against that specific vault operation — directly analogous to the PermitSubmitterHook issue, where a one-time-use artifact (a `permit()` signature there, a request `digest` here) meant to authorize exactly one execution can instead be consumed by an unrelated party to grief the intended executor.

### Impact Explanation
This is a griefing/denial-of-service vulnerability against Vault secret management operations (`vault.secrets.create`, `vault.secrets.update`, `vault.secrets.delete`, `vault.secrets.list`). An unprivileged attacker with no special permissions can prevent a legitimate, correctly-allowlisted workflow owner from ever getting their intended secrets operation processed, for as long as the allowlist entry's expiry window remains (owner-selected, but the tests show windows of an hour or more). This does not directly leak secrets or bypass ownership checks, but it does deny availability of a security-critical operation (e.g., blocking rotation/creation of a secret needed by a running workflow), which is a concrete availability impact on an unprivileged, internet-facing surface.

### Likelihood Explanation
Medium. Exploitation requires the attacker to obtain the exact byte-identical request before/concurrently with the legitimate submission (matching digest requires exact `method`/`id`/`params`). This is plausible because: (1) the request is broadcast unencrypted to all DON member nodes by the gateway before completion, giving multiple observation points; (2) the allowlist digest itself is published on-chain ahead of time by the owner, telling an attacker exactly when and for which owner to watch for a matching request; and (3) the gateway HTTP/WS endpoint accepts requests from any client without per-caller binding in the allowlist auth path. It does not require breaking any cryptography — only network/observation positioning and a race condition, similar in spirit to the mempool front-running described in the original report.

### Recommendation
- Bind replay-guard "consumption" to the authenticated identity/session that is expected to submit the request rather than to the raw digest alone, so a third party replaying an observed request cannot consume the slot on the legitimate owner's behalf.
- Consider reserving the digest only after the DON-side secret write actually succeeds/is durably applied (rather than at gateway-side authorization time), and allow the legitimate owner to retry with a fresh allowlist entry if a race is detected.
- Add sender/session correlation (e.g., require a mutually-authenticated channel or bind the digest reservation to a specific connection) so that `ErrRequestAlreadySeen` cannot be triggered by an unrelated party's copy of the same request.
- Reduce the blast radius by shortening default allowlist expiry windows and/or emitting an explicit conflict signal distinguishable from a legitimate duplicate submission by the same owner.

### Proof of Concept
1. Workflow owner computes `digest = req.Digest()` for an intended `vault.secrets.create` request and allowlists it on-chain via `WorkflowRegistry.AllowlistRequest(digest, expiry)` (see [8](#0-7) ), which makes `digest` and `expiry` publicly readable from the contract.
2. Owner begins constructing/sending the exact JSON-RPC request (same `method`, `id`, `params`) to the gateway's `HandleJSONRPCUserMessage` endpoint [9](#0-8) .
3. An attacker who has obtained a byte-identical copy of that request (e.g., by observing the gateway-to-DON fan-out traffic in [7](#0-6) , or intercepting the wire) resubmits it to the gateway first.
4. `AllowListBasedAuth.AuthorizeRequest` accepts the attacker's copy because it only validates the digest against the on-chain allowlist, not the submitter ( [10](#0-9) ).
5. `Authorizer.AuthorizeRequest`'s `replayGuard.CheckAndRecord(digest, expiresAt)` records the digest as seen for the attacker's submission ( [11](#0-10) ).
6. When the legitimate owner's identical request subsequently reaches the same code path, `CheckAndRecord` returns `ErrRequestAlreadySeen` (as demonstrated by the existing test `TestAuthorizer_RejectsAllowListBasedAuthReplay` [12](#0-11) ), and the owner's request is rejected for the remainder of the allowlist expiry window.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
```

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}

	if !vaulttypes.IsGatewaySecretsMethod(req.Method) {
		return h.sendImmediateUserResponse(ctx, req, callback, api.UnsupportedMethodError, errors.New("this method is unsupported: "+req.Method))
	}

	_, cachedPublicKey := h.getCachedPublicKey()
	authorized, err := h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)
	if err != nil {
		if vaultcap.IsInvalidVaultParamsError(err) {
			return h.sendImmediateUserResponse(ctx, req, callback, api.InvalidParamsError, err)
		}
		h.lggr.Errorw("request not authorized", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "error", err)
		return errors.New("request not authorized: " + err.Error())
	}
	authorizedOwner := authorized.AuthResult.AuthorizedOwner()

	h.lggr.Debugw("handling authorized vault request", "method", req.Method, "requestID", req.ID, "authorizedOwner", authorizedOwner)
```

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}

func TestAuthorizer_RejectsAllowListBasedAuthReplay(t *testing.T) {
	allowListBasedAuth := vaultmocks.NewAuthorizer(t)
	// Use a method without secret identifiers so the owner-binding check is a no-op.
	req := jsonrpc.Request[json.RawMessage]{ID: "1", Method: vaulttypes.MethodPublicKeyGet}
	allowListBasedAuth.EXPECT().AuthorizeRequest(mock.Anything, req).Return(vault.NewAuthResult("", "0xabc", "digest-1", time.Now().Add(time.Minute).Unix()), nil).Twice()

	a := vault.NewAuthorizer(allowListBasedAuth, nil, logger.TestLogger(t))

	authResult, err := a.AuthorizeRequest(t.Context(), req)
	require.NoError(t, err)
	require.Empty(t, authResult.OrgID())
	require.Equal(t, "0xabc", authResult.WorkflowOwner())
	require.Equal(t, "0xabc", authResult.AuthorizedOwner())

	authResult, err = a.AuthorizeRequest(t.Context(), req)
	require.Nil(t, authResult)
	require.ErrorIs(t, err, vault.ErrRequestAlreadySeen)
}
