### Title
`get_token_account_balance` trusts a Mint account's decimals without verifying the mint is owned by a known SPL-Token program - (File: rpc/src/rpc.rs)

### Summary
`get_token_account_balance` validates that the *token account* is owned by a known SPL-Token program, but when it resolves the `mint` field to fetch decimals via `get_mint_owner_and_additional_data`, it discards the returned mint owner and never checks it against `is_known_spl_token_id`. This lets an attacker point a legitimately-owned token account's `mint` field at an arbitrary attacker-controlled account whose bytes merely happen to unpack as a `Mint`, causing fabricated decimals to be reported in the balance response.

### Finding Description
In `rpc/src/rpc.rs`, `get_token_account_balance` performs: [1](#0-0) 

The function checks `is_known_spl_token_id(account.owner())` only for the token account itself, unpacks it to get the embedded `mint` pubkey, then calls `get_mint_owner_and_additional_data(&bank, mint)` and immediately discards the owner with `let (_, data) = ...`, never validating it.

`get_mint_owner_and_additional_data` in `rpc/src/parsed_token_accounts.rs` fetches the mint account from the bank and unpacks it purely by byte layout via `StateWithExtensions::<Mint>::unpack`, with no ownership check: [2](#0-1) 

By contrast, sibling RPC methods that use the same helper explicitly validate the returned mint owner before trusting the decoded data — e.g. `get_token_supply` checks `is_known_spl_token_id(mint_account.owner())` directly, `get_token_largest_accounts` checks `is_known_spl_token_id(&mint_owner)`, and `get_token_program_id_and_mint` does the same: [3](#0-2) [4](#0-3) 

Only `get_token_account_balance` omits this check for the mint side. An attacker can create (via any program they control, e.g. a deployed BPF program or the system program's `Allocate`/`CreateAccount` with an arbitrary `owner` field) an account whose raw bytes happen to unpack as a valid `Mint` (fixed 82-byte base layout: `COption<Pubkey>` mint_authority, `u64` supply, `u8` decimals, `bool` is_initialized, `COption<Pubkey>` freeze_authority, with `is_initialized = 1`) but is NOT owned by any real SPL-Token program. The attacker separately creates a genuine, correctly-owned SPL-Token `Account` (owner = real spl-token program id, valid `TokenAccount` layout) whose `mint` field is set to that fabricated account's pubkey. Calling `getTokenAccountBalance` on this token account passes the token-account-owner check, unpacks the token account successfully, then blindly trusts the attacker-chosen `decimals` (and any interest-bearing/scaled-UI extensions) from the fake mint account to compute `UiTokenAmount`.

### Impact Explanation
This produces a misreported `uiAmount`/`decimals` in the RPC response for `getTokenAccountBalance`, which callers (wallets, exchanges, indexers) rely on to interpret raw token amounts. This falls under the "wrong … account data returned / misreporting" impact category permitted by the audit scope, since it does not require any privileged access — only normal transaction submission (creating accounts/programs) and a single RPC call.

### Likelihood Explanation
Fully feasible for an unprivileged actor: creating token accounts and mint-shaped byte blobs under arbitrary program ownership is standard permissionless on-chain activity (deploy a small program, or use `CreateAccount`/data-write instructions of a program the attacker controls). No validator, leader, or staked-node control is needed, and the exploit requires a single `getTokenAccountBalance` call, well within the one-call rate limit.

### Recommendation
In `get_token_account_balance`, use the mint owner returned from `get_mint_owner_and_additional_data` and reject with `Error::invalid_params` if `!is_known_spl_token_id(&mint_owner)`, mirroring the checks already present in `get_token_supply`, `get_token_largest_accounts`, and `get_token_program_id_and_mint`.

### Proof of Concept
Integration test (add to `rpc/src/rpc.rs` test module alongside existing `test_rpc_token_*` tests):
1. Store a valid SPL-Token `TokenAccount` (owner = `spl_token_interface::id()`) whose `mint` field is set to `fake_mint_pubkey`.
2. Store an account at `fake_mint_pubkey` with `owner = system_program::id()` (or any non-token program) whose data is a byte-for-byte valid `Mint` layout (`mint_authority: COption::None`, `supply: 0`, `decimals: 18` — an attacker-chosen fabricated value, `is_initialized: true`, `freeze_authority: COption::None`).
3. Call `getTokenAccountBalance` on the token account pubkey via `io.handle_request_sync`.
4. Assert either:
   - The RPC call returns an error (`result.get("error").is_some()`) — expected if the fix is applied, since `fake_mint_pubkey`'s owner is not a known SPL-Token id, OR
   - Currently (pre-fix), assert the returned `decimals` equals `18` despite the mint account not being owned by any spl-token program, demonstrating the vulnerability.

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}
