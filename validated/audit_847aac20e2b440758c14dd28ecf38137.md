### Title
Stale confirmations from removed multisig members are still counted toward the approval threshold, allowing request execution below the live-member quorum - (File: `multisig2/src/lib.rs`)

### Summary
`multisig2` (and equally `multisig`) allows a member to be removed via `DeleteMember`/`DeleteKey` while a *different* pending request retains a confirmation that member previously cast. `delete_member` only purges requests/confirmations that were *originated* by the removed member, not confirmations the removed member cast on other requests still open. Because `confirm()` only checks `confirmations.len() + 1 >= num_confirmations` without re-validating that every counted confirmation still belongs to a current member, a request can execute with fewer live-member approvals than the declared threshold — a "confirmations counted versus live members" mismatch, directly mirroring the report's "state trusted once but never revalidated" bug class.

### Finding Description
`confirm()` in `multisig2/src/lib.rs` only requires: [1](#0-0) 
`confirmations.len() as u32 + 1 >= self.num_confirmations` to execute the request, regardless of whether previously-recorded confirmations still belong to current members.

`delete_member()` removes only the requests originated by the deleted member, and clears the `num_requests_pk` counter for that member — but it never scans `confirmations` for entries belonging to that member on *other* still-pending requests: [2](#0-1) 

Concretely:
1. Members `{A, B, C}`, `num_confirmations = 2`.
2. `A` creates request `X` (`add_request`), confirmations = `{}`.
3. `B` calls `confirm(X)` → `confirmations = {B}` (len 1 < 2, not executed).
4. A separate request to `DeleteMember { member: B }` is created and confirmed (e.g., by `A` and `C`), removing `B` from `members`. `delete_member` only clears requests where `r.member == B` (i.e., requests *created* by `B`); request `X` was created by `A`, so it and its confirmation set `{B}` survive untouched. The invariant check `members.len()-1 >= num_confirmations` (`3-1=2 >= 2`) permits the removal.
5. Now members are `{A, C}`, still with `num_confirmations = 2`.
6. `C` calls `confirm(X)`. `current_member()` validates `C` is a live member, and `assert_valid_request` passes. `confirmations.len() (1, still containing "B") + 1 = 2 >= num_confirmations (2)` → `execute_request(X)` runs.

Request `X` executes on the strength of one live approval (`C`) plus one stale, ghost approval from a member (`B`) that no longer exists in `self.members`, even though the contract is nominally a 2-of-2 (or 2-of-3) multisig. This breaks the equality the threshold is supposed to enforce: `num_confirmations` live-member approvals == confirmations actually counted. The identical pattern with the same missing invalidation exists in the legacy `multisig/src/lib.rs::confirm`/`DeleteKey` path: [3](#0-2) [4](#0-3) 

### Impact Explanation
This crosses the "authorisation threshold" boundary explicitly called out as Critical impact: a multisig request is executed below the intended threshold of *live* approvals. Any request pending at the time a member is removed (transfers, `AddKey`/`AddMember` grants, `FunctionCall`s, etc.) can be pushed to execution using one fewer genuine approval than configured, letting a party effectively act with fewer real co-signers than the multisig was set up to require — e.g., moving NEAR out of the account with only 1 of the 2 required *current* signers actually consenting.

### Likelihood Explanation
Requires only that (a) a request is left pending (unconfirmed to completion) by a member who is later removed via a legitimate `DeleteMember`/`DeleteKey` action, and (b) the remaining request is later confirmed by another live member. No compromise of keys, no owner privilege beyond what a legitimate member set already possesses, and no reliance on redeploy or foundation intervention is needed — only normal multisig operational sequencing (adding/removing members while requests are outstanding), which is a routine multisig lifecycle event, not a contrived edge case.

### Recommendation
When removing a member (`delete_member`/`DeleteKey`), also scan `confirmations` for every pending `request_id` and strip the removed member's entry from each confirmation set (not just requests they authored), or re-validate on `confirm()`/execution that every address in a request's confirmation set is still a current member before counting it toward `num_confirmations`.

### Proof of Concept
```rust
// members = {A, B, C}, num_confirmations = 2
let request_x = c.add_request(transfer_request); // signer A
// B confirms X: confirmations[X] = {B}
testing_env!(context_with_member(B));
c.confirm(request_x); // len 1 < 2, stored

// Separately: remove B via DeleteMember (confirmed by A + C)
testing_env!(context_with_member(A));
let del_req = c.add_request(delete_member_b_request);
testing_env!(context_with_member(C));
c.confirm(del_req); // executes DeleteMember{B}; members = {A, C}
                     // request_x and confirmations[X] = {B} are untouched

// C confirms X: confirmations[X].len() (1, "B") + 1 == num_confirmations (2)
testing_env!(context_with_member(C));
c.confirm(request_x); // executes with only 1 live approval (C), stale "B" ghost-counted
```

        self.assert_valid_request(request_id);

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
