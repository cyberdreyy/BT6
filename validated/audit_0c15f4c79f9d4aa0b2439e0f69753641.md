### Title
Speculative connection eviction in the staked-QUIC connection table permits unpaired removal of another peer's connection - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
`SwQos::try_add_connection` (and the equivalent `SimpleQosBanlist`/`SimpleQos` path) prunes a victim entry from the staked `ConnectionTable` *before* it has confirmed that the new connection will actually be admitted. Admission is only checked afterwards, inside `ConnectionTable::try_add_connection`, which enforces the *per-peer* connection cap (`max_connections_per_peer`) independently of the table-wide capacity check that triggered the eviction. A peer that is already at its per-peer connection limit can therefore cause an unrelated, lower-stake peer's connection to be evicted from the table while its own new connection attempt is rejected and closed, producing a net loss of a legitimate connection slot with no compensating gain — the same "unchecked side-effect precedes a failed/no-op insertion" bug class as the `WhitelistRegistry.register()` issue in the report.

### Finding Description
`SwQos::try_add_connection` in <cite repo="EzraCole/agave--001" path="streamer/src/nonblocking/swqos.rs" start="356="365" /> actually at: [1](#0-0) 

first checks only the *table-wide* size:
```
if connection_table_l.total_size >= self.config.max_staked_connections {
    let num_pruned = connection_table_l.prune_random(PRUNE_RANDOM_SAMPLE_SIZE, stake);
    ...
}
```
`prune_random` unconditionally removes a randomly-sampled, lowest-stake *victim* entry (a different peer's connection) whenever the caller's own `stake` is higher than the sampled minimum, as implemented in [2](#0-1) .

Only *after* this destructive eviction does the code attempt to actually admit the new connection, via `cache_new_connection` → `ConnectionTable::try_add_connection` in [3](#0-2) , which separately enforces a **per-peer** cap:
```
let has_connection_capacity = connection_entry.len().checked_add(1)
    .map(|c| c <= max_connections_per_peer).unwrap_or(false);
if has_connection_capacity { ... Some(...) } else {
    if let Some(connection) = connection { connection.close(...); }
    None
}
```
Because the table-wide prune decision and the per-peer capacity check are independent and evaluated at different times, a staked peer that is already holding `max_connections_per_staked_peer` connections and opens one more connection when `staked_connection_table.total_size >= max_staked_connections` will:
1. Trigger `prune_random`, evicting some other (lower-stake) peer's connection from the table — a real side effect (the connection is closed via `Drop`/`CancellationToken::cancel()`).
2. Then fail its own admission in `ConnectionTable::try_add_connection` because it is already at its per-peer cap, causing its new connection to be closed with `CONNECTION_CLOSE_CODE_TOO_MANY`.

The net effect is identical in shape to the Solidity bug: an operation that is supposed to be a no-op/rejection (the caller cannot actually gain a slot) still executes the destructive "remove the minimal entry" step, because the code never verifies that the corresponding "add" will succeed before performing the removal. The same pattern also exists in `SimpleQos::try_add_connection` in [4](#0-3) .

### Impact Explanation
Any staked validator identity (no special privilege beyond holding some non-zero stake, i.e. an "ordinary user" of the TPU QUIC ingest path) can repeatedly open connections up to its per-peer connection limit and then issue additional connection attempts while the staked table is saturated. Each such extra attempt evicts one legitimate, unrelated (and often lower-stake) peer's active connection from the leader's TPU ingest table without the attacker gaining anything, because their own connection is subsequently rejected for exceeding the per-peer cap. This is a remotely triggerable connection-eviction/DoS primitive against the TPU ingest path (`streamer`/QUIC), degrading availability of transaction ingestion for arbitrary other staked peers — falling squarely within the allowed "TPU ingest limits" analog category.

### Likelihood Explanation
The trigger requires only: (a) being a staked peer (any non-zero stake registered in `StakedNodes` qualifies), (b) already holding `max_connections_per_staked_peer` connections to the target leader, and (c) the leader's staked connection table already being near/at `max_staked_connections` (a common condition under normal network load, and one an attacker can help induce by opening many connections). No cryptographic or consensus-level barrier prevents this; it is purely a client-controllable connection pattern over QUIC, making the likelihood high whenever the validator is under connection pressure.

### Recommendation
Perform the per-peer admission check (`has_connection_capacity`) *before* invoking `prune_random`/table-wide eviction, or make eviction conditional on first confirming the new connection can be admitted (e.g., check-then-evict-then-insert atomically under the same lock, or roll back/skip the eviction if the subsequent `ConnectionTable::try_add_connection` call returns `None`). This mirrors the report's remediation of checking the "add" outcome before/around the destructive "remove" step.

### Proof of Concept
1. Configure/observe a leader with `max_connections_per_staked_peer = N` and `max_staked_connections = M`.
2. As staked peer A, open `N` QUIC connections to the leader's TPU (reaching the per-peer cap).
3. Wait until (or induce, via many other staked peers) `staked_connection_table.total_size >= M`.
4. As peer A, open one more QUIC connection. Observe via `streamer` stats (`num_evictions_staked`, `connection_add_failed_staked_node`) that `prune_random` evicted another staked peer's connection (`num_evictions_staked` increments) while peer A's own connection is subsequently closed with `CONNECTION_CLOSE_CODE_TOO_MANY` (admission failure), confirming a connection slot was permanently lost with no corresponding new admission.

    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    pub(crate) fn try_add_connection<F: FnOnce() -> Arc<S>>(
        &mut self,
        key: ConnectionTableKey,
        port: u16,
        client_connection_tracker: ClientConnectionTracker,
        connection: Option<Connection>,
        peer_type: ConnectionPeerType,
        last_update: Arc<AtomicU64>,
        max_connections_per_peer: usize,
        stream_counter_factory: F,
    ) -> Option<(Arc<AtomicU64>, CancellationToken, Arc<S>)> {
        let connection_entry = self.table.entry(key).or_default();
        let has_connection_capacity = connection_entry
            .len()
            .checked_add(1)
            .map(|c| c <= max_connections_per_peer)
            .unwrap_or(false);
        if has_connection_capacity {
            let cancel = self.cancel.child_token();
            let stream_counter = connection_entry
                .first()
                .map(|entry| entry.stream_counter.clone())
                .unwrap_or_else(stream_counter_factory);
            connection_entry.push(ConnectionEntry::new(
                cancel.clone(),
                peer_type,
                last_update.clone(),
                port,
                client_connection_tracker,
                connection,
                stream_counter.clone(),
            ));
            self.total_size += 1;
            Some((last_update, cancel, stream_counter))
        } else {
            if let Some(connection) = connection {
                connection.close(
                    CONNECTION_CLOSE_CODE_TOO_MANY.into(),
                    CONNECTION_CLOSE_REASON_TOO_MANY,
                );
            }
            None
        }
    }
