### Title
`requestWithdraw` remains callable while the vault is paused — ([File: contracts/IdleCDOEpochVariant.sol:739](contracts/IdleCDOEpochVariant.sol))

### Summary
`pause()` is documented as "Pauses deposits", and deposits (`_deposit`, `depositAA/BB`) are correctly gated by `whenNotPaused` [1](#0-0) . However the epoch withdrawal path `requestWithdraw` has no `whenNotPaused` check and no `paused()` check — it only consults the `allowAAWithdrawRequest`/`allowBBWithdrawRequest` flags [2](#0-1) . Those flags are only cleared by `_emergencyShutdown` / `_handleBorrowerDefault` [3](#0-2) , not by a plain `pause()` [4](#0-3) . So a guardian/owner pause does not stop users from burning tranche tokens and booking withdraw receipts — the direct analog of `createBid` being callable while paused.

### Finding Description
In `IdleCDOEpochVariant`, `requestWithdraw` performs several state-mutating steps while only checking the tranche withdraw flags and KYC:

1. `_skimDonatedAssets()` and `_updateAccounting()` (which itself can trigger the default path).
2. Burns the user's tranche tokens and reduces NAV via `_withdrawOps` [5](#0-4) .
3. Mutates `pendingWithdrawFees`, `interestForOverUnderPerformance`, and creates a claim receipt in `IdleCreditVault.requestWithdraw` [6](#0-5) .

Because `pause()` does not touch `allowAAWithdrawRequest`/`allowBBWithdrawRequest`, an unprivileged user can front-run or act during a pause to lock in a withdraw receipt priced with the pre-change parameters — e.g. before the owner raises `fee`, changes `trancheAPRSplitRatio` (which shifts `_calcTrancheInterestShare` and hence `_calcInterestWithdrawRequest`), or updates the strategy APR. The receipt is fixed at request time (`principal + interest - totalFees`), so once booked it cannot be repriced.

### Impact Explanation
An unprivileged KYC'd tranche holder can crystallize a withdrawal at stale, more favorable accounting terms during a pause. Concretely: owner pauses the vault to raise `fee` (performance fee) or change `trancheAPRSplitRatio`; before `unpause`/parameter change completes, the user calls `requestWithdraw` and locks `principal + interest - totalFees` computed with the old fee/split. The loss equals the fee/share differential on the withdrawn amount — a direct transfer of value from remaining tranche holders, quantifiable as `Δ(totalFees)` and `Δ(interest)` on the requested `principal`. It also forces `_updateAccounting` and `_skimDonatedAssets` during a phase the operator explicitly intended frozen, and the fix-now receipt inflates `pendingWithdrawFees`/`interestForOverUnderPerformance` inputs to `startEpoch` accounting.

### Likelihood Explanation
Medium-low: it requires an honest admin pause during a non-epoch phase (the only phase where withdraw requests are open) while a user front-runs a pending parameter change or otherwise exploits the window. No privileged role is needed for the attacker — only a tranche-token holder passing `isWalletAllowed`. The missing guard is unconditional (not configuration-dependent), unlike epoch-state bugs.

### Recommendation
Either add `whenNotPaused` to `requestWithdraw` (and audit `claimWithdrawRequest`/`claimInstantWithdrawRequest` in `IdleCreditVault` for the same gap), or make `pause()` also clear `allowAAWithdrawRequest`/`allowBBWithdrawRequest` the way `_emergencyShutdown` does, restoring them on `unpause`/`restoreOperations`. Apply the same check to any other user-facing mutating entry point reachable while `paused()` is true.

### Proof of Concept
Foundry-style PoC (extend `test/foundry/IdleCreditVault.t.sol`):

```solidity
// Setup: AA/BB deposits done, no epoch running (buffer phase),
// allowAAWithdrawRequest == allowBBWithdrawRequest == true.
uint256 amount = 10_000 * ONE_SCALE;

// Owner pauses only (not emergencyShutdown) to change fee/splitRatio
vm.prank(owner);
idleCDO.pause();
assertTrue(idleCDO.paused());

// Unprivileged user can still burn tranches and book a withdraw receipt
uint256 balBefore = AAtranche.balanceOf(AABuyer);
vm.prank(AABuyer);
uint256 underlyings = cdoEpoch.requestWithdraw(0, address(AAtranche)); // does NOT revert
assertGt(underlyings, 0);
assertLt(AAtranche.balanceOf(AABuyer), balBefore); // tokens burned while paused

// User locked in fees/interest computed with the OLD parameters,
// then owner changes trancheAPRSplitRatio/fee and unpauses — too late.
```

The key assertion is that `requestWithdraw` succeeds under `paused() == true`, while `depositAA` in the same state reverts with `"Pausable: paused"` — inconsistent protection of the same pause flag.

```text
  function _emergencyShutdown(bool isAAWithdrawAllowed) internal override {
    // prevent deposits
    if (!paused()) {
      _pause();
    }
    // Preserve AA requests only if they were already open. This keeps a forced mid-epoch loss or
    // prior emergency from reopening them, while a normal explicit-loss stop can leave them open.
    if (!isAAWithdrawAllowed) {
      allowAAWithdrawRequest = false;
    }
    allowBBWithdrawRequest = false;
    // Persist the emergency state and let authorized forced accounting crystallize the loss.
    skipDefaultCheck = true;
  }
```
