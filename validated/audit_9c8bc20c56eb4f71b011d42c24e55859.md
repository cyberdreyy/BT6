### Title
Unauthenticated disclosure of LOOP plugin service-discovery topology via `GET /discovery` - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` registers `GET /discovery` directly on the shared `api` route group without wrapping it in any `auth.Authenticate` middleware, unlike `debugRoutes`, which explicitly protects `/debug/vars` with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`. Any unauthenticated client can therefore call `LoopRegistryServer.discoveryHandler` and receive the full list of registered LOOP plugin names and their Prometheus scrape targets.

### Finding Description
In `core/web/router.go`, `NewRouter` builds a base `api` group with only rate limiting and session-cookie middleware attached (`api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))`), then calls `debugRoutes(app, api)`, `healthRoutes(app, api)`, `sessionRoutes(app, api)`, `v2Routes(app, api)`, and `loopRoutes(app, api)`.

`debugRoutes` explicitly creates a sub-group requiring session authentication: [1](#0-0) 

`loopRoutes`, however, registers its handlers directly on the passed-in `r *gin.RouterGroup` (the unauthenticated `api` group) with no additional auth wrapper at all: [2](#0-1) 

The handler itself, `LoopRegistryServer.discoveryHandler`, iterates `l.registry.List()` and emits a JSON array of Prometheus `targetgroup.Group` objects, each labeled with `LabelMetaPluginName` set to the plugin's actual name, plus the target host:port for scraping: [3](#0-2) 

Since no `auth.Authenticate*` function guards this route, `gin` dispatches the request straight to `discoveryHandler` for any caller, session or no session, API key or no API key.

### Impact Explanation
An unauthenticated attacker can enumerate all LOOP plugins registered on the node (names, count, and internal scrape target/port topology) via a single unauthenticated GET request. This is an information-disclosure vulnerability that reveals internal architecture/topology of the node's plugin deployment, which can be used to plan further targeted attacks (e.g., probing exposed `/plugins/:name/metrics` or `/plugins/:name/debug/pprof/*` endpoints, which are also unauthenticated per the same `loopRoutes` registration). This matches an information-disclosure impact class under Chainlink's bounty program — disclosure of internal service topology to an unauthenticated party.

### Likelihood Explanation
No preconditions are required: the request is a plain `GET /discovery` with no headers, cookie, or API token, sent to any node exposing the standard web/API port. The bug is fully deterministic and repeatable — every request will succeed as long as the node's web server is reachable, with no rate limiting beyond the generic unauthenticated rate limiter applied to the whole `api` group.

### Recommendation
Wrap the routes registered in `loopRoutes` (`/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol`) with the same authentication middleware used by `debugRoutes` (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` or `auth.AuthenticateByToken`), or, if the discovery endpoint must be reachable by an external Prometheus scraper without session/API credentials, restrict it via a dedicated shared-secret bearer token (similar to the `prometheusHandler` pattern already used for `/metrics` at `core/web/router.go` lines 677-699) rather than leaving it fully open.

### Proof of Concept
Go handler-level integration test plan:
1. Build a test `chainlink.Application` mock/stub with `GetLoopRegistry()` returning a `*plugins.LoopRegistry` pre-populated with at least one named plugin entry (e.g., "median").
2. Call `web.NewRouter(app, nil)` to construct the full `*gin.Engine`, exactly as production code does.
3. Use `httptest.NewServer(router)` to start the server.
4. Send a raw `http.Get(server.URL + "/discovery")` with **no** `Cookie` header and **no** `Authorization`/`X-API-KEY`/`X-API-SECRET` headers.
5. Assert `resp.StatusCode == http.StatusOK`.
6. Read and unmarshal the JSON body into `[]*targetgroup.Group`, and assert it contains an entry with `Labels[web.LabelMetaPluginName] == "median"`.
7. As a control, repeat the same unauthenticated request against `/debug/vars` and assert it returns `401 Unauthorized` (proving the router does correctly gate other informational routes, highlighting the inconsistency for `/discovery`).

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}
