### Title
Global (non-scoped) request-ID reservation in the HTTP Trigger gateway handler lets any authorized caller DoS another workflow's trigger requests for the full callback TTL - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
The `httpTriggerHandler` that processes internet-facing `workflows.execute` requests reserves an in-flight slot keyed **only by the caller-supplied JSON-RPC `id`**, not by workflow ID or caller identity. Any authorized caller can occupy an arbitrary `requestID` at essentially zero cost, and every other caller across every workflow that later submits a request with the same `id` is rejected with `ErrConflict` until the entry expires (default 10 minutes). This mirrors the Fractional buyout bug class: a cheap, unprivileged reservation locks a shared, keyed resource and blocks legitimate use of that key until a multi-minute timeout elapses, with no way for a higher-priority/legitimate request to preempt it.

### Finding Description
`HandleUserTriggerRequest` authorizes the caller against the target workflow via `authorizeRequest` [1](#0-0) , then reserves the request in a single global map keyed by `requestID` in `setupCallback`: [2](#0-1) 

The map `callbacks map[string]savedCallback` is declared without any workflow/owner scoping component in its key [3](#0-2) . Because authorization (`authorizeRequest`) only checks that the caller may trigger *their own* workflow, and the ID collision check happens against the *global* map, any authorized caller for *any* workflow can pre-reserve an `id` value before a victim (using the same `id` for a *different* workflow) submits their request. The victim's legitimate request is then rejected outright: [4](#0-3) 

The reservation is only released when the attacker's own request completes (`HandleNodeTriggerResponse` → `cleanupCallback`) or via the periodic reaper, which uses `CleanUpPeriodMs` as the max age — defaulting to 10 minutes [5](#0-4) : [6](#0-5) 

An attacker can trivially keep the slot alive far longer than 10 minutes by never letting nodes respond (or by targeting a shard where quorum is never reached, or by continuously re-registering with the same `id` immediately after each reap cycle), providing effectively unbounded, cheap denial of a specific request ID across the entire gateway, for any workflow that happens to reuse that same `id`. The existing unit test confirms the collision-rejection mechanic operates across concurrent callers on the same ID [7](#0-6) .

### Impact Explanation
This is directly analogous to the buyout DoS bug class: a low-cost, unprivileged-adjacent action (an authorized caller of *any* workflow, not the target workflow) locks a shared keyed resource (the `requestID` slot) for a multi-minute window, blocking a legitimate caller's workflow execution request whenever an `id` collision occurs. Since callers/clients often use predictable or low-entropy IDs (sequence numbers, idempotency keys tied to business logic, timestamps, etc.), an attacker who can predict or brute-force likely IDs used by a target integration can selectively DoS specific executions of a victim workflow, denying legitimate job/workflow triggers — the on-chain-equivalent "unavailable buyout" impact translated to "unavailable workflow execution trigger."

### Likelihood Explanation
Exploitation requires only that the attacker be authorized to call *some* workflow (their own) on the same Gateway/DON — this is a normal, low-privilege capability, not an operator or node privilege. The attacker needs no special access to the victim's workflow; they only need to guess/predict the `id` value the victim will use. Where clients use structured, low-entropy, or externally observable IDs (common for idempotent request identifiers), collision is practically achievable, making this a realistic, repeatable griefing vector at near-zero cost, matching the "Medium" severity judged in the original report (griefing/DoS with a bounded recovery window, but repeatable).

### Recommendation
- Scope the in-flight-request map key by `(workflowID, requestID)` (or `(workflowOwner, requestID)`) instead of `requestID` alone, so that a collision can only occur within the same workflow/owner namespace, not globally across all workflows.
- Additionally consider binding the reservation to the authenticated caller/key so unrelated authorized identities cannot pre-empt another owner's request namespace at all.
- Consider shortening `CleanUpPeriodMs` for orphaned reservations or adding an active liveness check that releases a slot early once it is provably abandoned (e.g., all shard sends have exhausted retries) rather than only reaping on a fixed TTL.

### Proof of Concept
Conceptual PoC (based on `TestHttpTriggerHandler_HandleUserTriggerRequest`'s existing "duplicate request ID" case, extended to cross-workflow reuse) [7](#0-6) :
1. Attacker (authorized only for `workflowA`) submits `workflows.execute` with `id = "shared-id"` targeting `workflowA`, and ensures the request is never acknowledged by enough nodes to reach quorum (e.g., target a shard configuration where responses never arrive, or exploit node/network conditions), keeping `h.callbacks["shared-id"]` alive.
2. Victim, authorized for a different `workflowB`, submits `workflows.execute` with the same `id = "shared-id"`.
3. `setupCallback` for the victim's request finds `"shared-id"` already present in the global `callbacks` map and returns `ErrConflict` [4](#0-3) , denying the victim's legitimate execution for up to `CleanUpPeriodMs` (10 minutes default), repeatable by the attacker at will.

```go
func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
```

```go
// reapExpiredCallbacks removes callbacks that are older than the maximum age
func (h *httpTriggerHandler) reapExpiredCallbacks(ctx context.Context) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	now := time.Now()
	var expiredCount int
	for reqID, callback := range h.callbacks {
		if now.Sub(callback.createdAt) > time.Duration(h.config.CleanUpPeriodMs)*time.Millisecond {
			h.metrics.IncrementRequestErrors(ctx, jsonrpc.ErrInternal, h.lggr)
			h.cleanupCallback(reqID)
			expiredCount++
		}
	}
	if expiredCount > 0 {
		h.metrics.IncrementPendingRequestsCleanUpCount(ctx, int64(expiredCount), h.lggr)
		h.lggr.Infow("Removed expired callbacks", "count", expiredCount, "remaining", len(h.callbacks))
	}
	h.metrics.RecordPendingRequestsCount(ctx, int64(len(h.callbacks)), h.lggr)
```
