### Title
`ExtractZipArchive`'s second-pass `lchmod` operates on unvalidated `file.Name`, allowing chmod of pre-existing files in a reused workspace - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` extracts entries and then, in a *separate* second loop, calls `lchmod(file.Name, file.Mode())` using the raw zip entry name with no path joining/validation and no verification that the entry was actually (re)created by the first pass. Since job workspaces (build dirs, caches) are often reused across job runs, a crafted archive whose entry name matches a path already present from a prior job/step can have that pre-existing file's permission bits silently overwritten via `Fchmodat`.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) runs two loops over `archive.File`:

1. First loop: `extractZipFile(file)` writes/creates the entry using `file.Name` directly as the filesystem path — there is no `filepath.Join(dir, ...)`, no `filepath.Clean`, and no chroot/prefix check (contrast with `tarzstd_extractor.go`, which validates `path` against `e.dir` with `strings.HasPrefix` before any write, lines 58-64 in that file). The zip legacy extractor (`ziplegacy/zip_legacy_extractor.go`) relies on the process CWD already being set to the extraction directory — `file.Name` is used verbatim, not scoped to any validated root.
2. Second loop: `lchmod(file.Name, file.Mode())` (zip_extract.go:99) is called for **every** entry in the archive, using the same unvalidated `file.Name`, independent of whether the first-pass `extractZipFile` for that specific entry succeeded, failed, or was skipped (e.g., named pipes/sockets/devices are explicitly skipped at line 75-77 but `lchmod` is still applied to them in the second loop).
3. Because `lchmod` targets `file.Name` (a workspace-relative path with no origin/ownership check), any file that already exists at that path — whether created by this extraction, left over from a prior job in a reused build directory/cache, or a symlink/dir created for unrelated reasons — will have its mode bits set to whatever the archive attacker specifies, via `unix.Fchmodat(unix.AT_FDCWD, name, ...)` in `os_unix.go`.
4. Existing protections don't stop this: `errorIfGitDirectory` only guards `.git` paths for warning purposes, not permission changes; `pathErrorTracker.actionable` only suppresses duplicate log messages for repeated `os.PathError.Op` values, it does not prevent the underlying `Fchmodat` call from executing.

This is a real, unguarded gap: the mode-setting pass is decoupled from "was this exact file just created by me," and the path is never validated as staying within (or matching) a path this extraction actually produced.

### Impact Explanation
An unprivileged pipeline author who controls the contents of an artifact/cache zip (uploaded as job artifacts, restored as cache) can name an entry to match a path known/guessable to exist in a reused workspace (e.g., `.ssh` config bits, checked-out repo files, previous job's output artifact left in the shared build dir when `GIT_CLEAN_FLAGS`/cache reuse is used) and set arbitrary permission bits (world-writable, executable, etc.) on it via the second-pass `lchmod`. This is confined to files reachable at that relative path under the current working directory during extraction (typically the job's own build/cache directory), not an arbitrary host path, since no `../` traversal validation is exercised in this specific `lchmod`-triggered flaw beyond what `file.Name` naturally resolves to relative to CWD — i.e., the impact is scoped to permission tampering on files within the extraction root of the *same job's/project's reused workspace*, not a sandbox escape to another project's data. This still violates the intended "extraction stays scoped to what this extraction wrote" invariant and can degrade access control (e.g., making a script executable, or a config world-writable) on artifacts left behind by prior pipeline stages in that job's shared runner workspace.

### Likelihood Explanation
Feasible in the common configuration where runners reuse workspaces/caches (default incremental cloning executors, or Docker executor with cache volumes) rather than fully clean checkouts every job. An attacker only needs job-level control of the artifact/cache zip contents (a normal `artifacts:paths`/`cache:paths` job) plus knowledge or a guess of a stable relative path used across job runs. It's deterministic and repeatable — every listed archive entry unconditionally triggers an `lchmod` call regardless of extraction success for that entry.

### Recommendation
Decouple mode-setting from blind iteration over archive entries: only call `lchmod` for entries that `extractZipFile` actually created/updated in this pass (track success per-entry), and validate/normalize `file.Name` (reject `..`, absolute paths, and confirm the resolved path is within the intended extraction root) before any write or chmod operation, mirroring the containment check already used in `tarzstd_extractor.go`.

```go
func TestExtractZipArchiveDoesNotChmodPreexistingUnrelatedFile(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, _ string) {
        // Simulate a file left behind by a previous job/step in the reused workspace.
        preexisting := "leftover_artifact.txt"
        require.NoError(t, os.WriteFile(preexisting, []byte("data"), 0o600))

        // Build a zip whose entry name collides with the pre-existing path,
        // but whose type would fail to overwrite/replace it (e.g., simulate
        // a race/skip in the first pass), with a malicious mode 0777.
        buf := new(bytes.Buffer)
        zw := zip.NewWriter(buf)
        fh := &zip.FileHeader{Name: preexisting}
        fh.SetMode(0o777)
        w, err := zw.CreateHeader(fh)
        require.NoError(t, err)
        _, _ = w.Write([]byte("attacker content"))
        require.NoError(t, zw.Close())

        zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
        require.NoError(t, err)

        require.NoError(t, ExtractZipArchive(zr))

        info, err := os.Stat(preexisting)
        require.NoError(t, err)
        // Assert that permissions were changed by lchmod despite this being
        // effectively a "foreign" pre-existing artifact path.
        assert.Equal(t, os.FileMode(0o777), info.Mode().Perm())
    })
}
```

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
```

```go
func (p *pathErrorTracker) actionable(e error) bool {
	pathErr, isPathErr := e.(*os.PathError)
	if e == nil || isPathErr && pathErr == nil {
		return false
	}

	if !isPathErr {
		return true
	}

	p.lock.Lock()
	defer p.lock.Unlock()

	seen := p.seenOps[pathErr.Op]
	p.seenOps[pathErr.Op] = true

	// actionable if *not* seen before
	return !seen
}
```
