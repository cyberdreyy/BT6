### Title
Floor-division consensus threshold in `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` lets sub-70% weight force a miner-view capitulation - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` and `reached_disagreement` use plain integer (floor) division to compute the 70%/30% weight thresholds, whereas the consensus-critical block-signature verification path (`NakamotoBlockHeader::compute_voting_weight_threshold`) deliberately rounds the same threshold *up*. For `total_weight` values where `total_weight * 7` is not a multiple of 10, the floor-division threshold in the global state machine evaluator is strictly lower than the true 70% supermajority, letting a signer (or small colluding set) controlling somewhat less than 70% of total weight be treated as having "reached agreement," and controlling somewhat less than 30% be treated as a "blocking minority."

### Finding Description
`compute_voting_weight_threshold` (used to actually verify a block's aggregated signer signatures) computes `ceil(total_weight * 7 / 10)`: [1](#0-0) 

In contrast, `GlobalStateEvaluator::reached_agreement` and `reached_disagreement`, used by the off-chain signer-to-signer global state machine (StackerDB gossip of `StateMachineUpdate`s), use `floor(total_weight * 7 / 10)` and `floor(total_weight * 3 / 10)` respectively: [2](#0-1) 

For example, with `total_weight = 11`: the correct ceiling threshold is `ceil(77/10) = 8` (72.7%), but the floor-based evaluator accepts `floor(77/10) = 7` (63.6%) as "reached agreement." A signer (or a set of colluding signers) controlling 7/11 of the total reward-cycle weight — well under the intended 70% supermajority, and reachable without a majority of *individual signers* if weight is concentrated in a few large stackers — can broadcast a `StateMachineUpdate` claiming a particular miner/tenure as `current_miner`, and this alone will satisfy `reached_agreement` for other signers evaluating the same state.

This evaluator result feeds directly into `LocalStateMachine::capitulate_miner_view`, which is the mechanism honest signers use to update (capitulate) their own view of who the canonical/active miner is: [3](#0-2) 

Here `eval.reached_disagreement(*entry)` gates whether a miner candidate is even considered, and `eval.reached_agreement(*entry)` (when there are zero already-accepted blocks in that tenure) gates whether the candidate is accepted purely on state-machine votes, without any confirmed blocks. Because both checks use the flawed floor-based threshold, a minority (by the intended 70%/30% security margins, though possibly a weight-majority) can cause honest signers to `capitulate_viewpoint` and adopt an attacker-favored `current_miner`, and can also mark an actually-legitimate majority's supported miner as being under a "blocking minority" objection using less than the true 30% blocking weight. This same evaluator/threshold is also used for `determine_latest_supported_signer_protocol_version` and `determine_global_burn_view`, so the identical rounding flaw affects protocol-version rollover and burn-view agreement as well.

### Impact Explanation
This breaks the equality that the signer protocol is designed to enforce: the informal 70%/30% supermajority/blocking-minority guarantee for the gossip-based global state machine used to decide the canonical miner viewpoint diverges from the on-chain 70% threshold used for actual block-signature verification. A signer set (or a small number of large stackers) holding weight strictly less than 70% (but enough to exceed the *floor-rounded* threshold) can force honest, correctly-behaving signers to switch (`capitulate_viewpoint`) their local view of the "current miner" to a miner that has not actually achieved the intended supermajority support. Because `capitulate_miner_view` is one of the mechanisms deciding which tenure/miner a signer will accept proposals from, this can be used to steer honest signers toward signing/validating blocks from a miner that lacks genuine 70% backing — i.e., a form of the "acted on a stale/incorrect threshold, wedging valid signing behavior toward an attacker-favored branch" class of High-severity issue in the given rubric (a signer acting on a manipulated aggregated-weight threshold rather than the verified 70% requirement).

### Likelihood Explanation
The condition depends only on `total_weight` not being an exact multiple that divides evenly by 10 relative to the 7/10 (or 3/10) fraction — this is the common case, not a rare edge case, since reward weights are apportioned via `pox_5_make_signer_set`'s largest-remainder method and rarely land on multiples of 10. No majority of signers and no leaked keys are required; the actor(s) triggering it need only control the weight fraction that satisfies the floor threshold (which, depending on weight distribution, could be materially below 70%), consistent with the "single/low-weight stacker" class of trigger described in the referenced analog report.

### Recommendation
Change `reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use the same ceiling-rounding semantics as `NakamotoBlockHeader::compute_voting_weight_threshold`, so that the off-chain global-state agreement/disagreement thresholds never fall below the intended 70%/30% supermajority bounds guaranteed on-chain. Concretely, reuse `NakamotoBlockHeader::compute_voting_weight_threshold` (or its rounding logic) instead of the raw `strict_mul(..)/10` floor division.

### Proof of Concept
1. Set up a reward cycle where `total_weight = 11` (achievable via ordinary `pox_5_make_signer_set` weight apportionment when stake isn't perfectly divisible).
2. Have a signer/coalition controlling weight `7` (63.6% of total) broadcast a `StateMachineUpdate` (via StackerDB) claiming tenure `T` as `current_miner`.
3. On any honest signer evaluating `GlobalStateEvaluator::reached_agreement(7)` with `total_weight = 11`: `floor(11*7/10) = 7`, so `7 >= 7` is `true` — agreement is (incorrectly) reached, even though the true 70% requirement would need weight `8` (`ceil(77/10) = 8`).
4. This flows into `capitulate_miner_view` (`stacks-signer/src/v0/signer_state.rs:1019-1054`), causing the honest signer to capitulate its local view of `current_miner` to `T` despite lacking genuine 70% support, diverging from the guarantee enforced by `compute_voting_weight_threshold` used for actual block-signature verification.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
