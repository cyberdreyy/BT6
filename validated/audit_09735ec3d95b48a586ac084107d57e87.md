### Title
Unpublisher-Controlled `LegacyDisplay<T>` Bypasses Publisher Proof in `claim`, Permanently Seizing `DisplayCap<T>` — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

---

### Summary

`claim` in `display_registry` accepts any `LegacyDisplay<T>` (`sui::display::Display<T>`) as the sole proof of ownership when minting and binding a `DisplayCap<T>` to the canonical `Display<T>`. Because `LegacyDisplay<T>` carries `key, store` abilities it is freely and publicly transferable. Any actor who acquires one — by purchase, gift, or secondary transfer — can call `claim` while `Display<T>.cap_id` is `none()` and permanently seize exclusive control of the canonical display for type T, locking the legitimate publisher out forever.

---

### Finding Description

`LegacyDisplay<T>` is defined as `sui::display::Display<T>`: [1](#0-0) 

The `key, store` combination means any holder can call `transfer::public_transfer` on it without any module restriction.

`system_migration<T>` creates the canonical `Display<T>` with `cap_id: option::none()` and shares it: [2](#0-1) 

`claim` then accepts any `LegacyDisplay<T>` value, checks only that `cap_id` is still `none()`, mints a fresh `DisplayCap<T>`, fills `cap_id`, and destroys the legacy object: [3](#0-2) 

There is **no publisher check** — no `publisher.from_package<T>()` assertion, no `ctx.sender()` check, nothing tying the `LegacyDisplay<T>` to the type's legitimate owner. Compare with `claim_with_publisher`, which does enforce publisher proof: [4](#0-3) 

`claim` has no equivalent guard.

---

### Impact Explanation

Once `display.cap_id.fill(...)` executes with the attacker's cap ID, the state is permanently corrupted:

- `ECapAlreadyClaimed` prevents any subsequent `claim` or `claim_with_publisher` call, so the legitimate publisher can never reclaim the capability.
- The attacker holds the only `DisplayCap<T>` and can call `set`, `unset`, and `clear` on the canonical shared `Display<T>` for type T indefinitely.
- All wallets, explorers, and dApps reading display metadata for objects of type T will render attacker-controlled values (name, image URL, description, link), enabling phishing and brand hijacking at the protocol level.

This is permanent, irreversible state corruption of the display registry for the affected type.

---

### Likelihood Explanation

The precondition — holding any `LegacyDisplay<T>` — is realistic:

1. Publishers routinely create multiple `LegacyDisplay<T>` objects (the old system has no singleton enforcement).
2. Because `LegacyDisplay<T>` has `store`, it can be listed on any NFT marketplace, sent to team members, or transferred as part of a project sale.
3. The window of vulnerability is the entire period between `system_migration<T>` executing and the legitimate publisher calling `claim` — which could be indefinite if the publisher is unaware of the migration.
4. An attacker can front-run the publisher's `claim` transaction in the same epoch.

---

### Recommendation

Add a publisher proof requirement to `claim`, mirroring `claim_with_publisher`:

```move
public fun claim<T: key>(
    display: &mut Display<T>,
    legacy: LegacyDisplay<T>,
    publisher: &Publisher,       // <-- add
    ctx: &mut TxContext,
): DisplayCap<T> {
    assert!(display.cap_id.is_none(), ECapAlreadyClaimed);
    assert!(publisher.from_package<T>(), ENotValidPublisher);  // <-- add
    let cap = DisplayCap<T> { id: object::new(ctx) };
    display.cap_id.fill(cap.id.to_inner());
    legacy.destroy();
    cap
}
```

This ensures that only the type-owning publisher can exchange a `LegacyDisplay<T>` for the canonical `DisplayCap<T>`, regardless of who currently holds the legacy object.

---

### Proof of Concept

```move
#[test]
fun attacker_steals_display_cap() {
    test_tx!(|registry, scenario| {
        // Step 1: Legitimate publisher creates a LegacyDisplay<MyKeyOnlyType>
        let publisher = new_publisher(scenario);
        let legitimate_legacy = display::new<MyKeyOnlyType>(&publisher, scenario.ctx());

        // Step 2: Publisher transfers the LegacyDisplay to attacker (e.g., marketplace sale)
        transfer::public_transfer(legitimate_legacy, @attacker);

        // Step 3: System migration creates Display<MyKeyOnlyType> with cap_id = none()
        let migration_cap = take_migration_cap(scenario);
        registry.system_migration<MyKeyOnlyType>(
            &migration_cap, vector[], vector[], scenario.ctx(),
        );
        scenario.next_tx(@attacker);

        // Step 4: Attacker calls claim with the purchased LegacyDisplay
        let attacker_legacy = scenario.take_from_address<display::Display<MyKeyOnlyType>>(@attacker);
        let mut display = scenario.take_shared<Display<MyKeyOnlyType>>();
        assert!(display.cap_id().is_none());

        let stolen_cap = display.claim(attacker_legacy, scenario.ctx());

        // Step 5: Attacker now controls the canonical display for MyKeyOnlyType
        assert!(display.cap_id().is_some_and!(|id| id == object::id(&stolen_cap)));
        display.set(&stolen_cap, b"name".to_string(), b"HACKED".to_string());

        // Publisher can no longer claim — ECapAlreadyClaimed would abort
        test_scenario::return_shared(display);
        transfer::public_transfer(stolen_cap, @attacker);
        migration_cap.destroy_system_migration_cap();
        publisher.burn();
    });
}
```
