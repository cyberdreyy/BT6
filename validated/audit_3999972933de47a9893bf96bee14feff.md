### Title
Flash deposit + APR0 withdraw request lets an attacker harvest a pro-rata share of epoch interest at the expense of active lenders and honest withdrawers - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
Analogous to the Morpho "flash supply & withdraw forces a socialized delta" bug: in `IdleCDOEpochVariant`/`IdleCreditVault`, a lender can deposit during the buffer period and call `requestWithdraw` in the same transaction. When the vault APR is 0, that principal enters the `apr0TotalPrincipal` bucket for the current epoch. At the next `stopEpoch`, `prepareStopEpochWithApr0` pays the APR0 bucket a pro-rata share of the *realized* epoch interest and subtracts it from the interest paid to active tranche holders. The attacker's capital was never at risk during the epoch, yet it captures nearly all of the epoch interest, diluting both active LPs and honest APR0 withdrawers who waited a full epoch.

### Finding Description
- During the buffer phase (`isEpochRunning == false`, `epochEndDate + bufferPeriod` not yet passed), `depositAA/depositBB` and `requestWithdraw` are both open to any KYC-passing wallet (`isWalletAllowed`). A user can therefore deposit and immediately request a withdraw atomically.
- `requestWithdraw` calls `IdleCreditVault.requestWithdraw`, which routes to `_requestWithdrawApr0` when `unscaledApr == 0`, incrementing `apr0TotalPrincipal` and tagging the bucket with the *current* `epochNumber` [1](#0-0) [2](#0-1) .
- At `stopEpoch`, `prepareStopEpochWithApr0` computes `_apr0InterestGross = _interestNetOfFees * _principal / (_tvl + _principal)` where `_principal` is `apr0TotalPrincipal` and `_tvl` is the live NAV (which excludes the requester's burned principal). It then does `_expInterest -= _apr0NetInterest`, directly reducing interest credited to active AA/BB holders [3](#0-2) .
- The per-epoch rate `apr0RateByEpoch[epochNumber]` is paid to *everyone* in the bucket, including the flash depositor, on claim via `_settleApr0` [4](#0-3) .
- There is no minimum holding period, no vesting, and no check that APR0 principal was supplied before the request epoch began — the bucket is keyed to the epoch in which the *request* is made, which is the same epoch the deposit was made.
- Net effect mirrors the Morpho delta: funds that sit in the pool for ~zero time are booked as if they earned a full-epoch P2P-equivalent yield, and the cost is socialized onto other participants because the borrower pays a fixed interest envelope.

### Impact Explanation
With flash capital `F >> TVL`, the attacker captures a fraction `F / (TVL + F)` of the epoch's net borrower interest (e.g., depositing 9× TVL captures ~90%). That amount is subtracted 1:1 from `_expInterest` paid to active tranche holders, and honest APR0 withdrawers' `apr0RateByEpoch` is diluted by the same factor. This is a direct theft of yield; the only cost to the attacker is gas plus one epoch of claim latency (capital is returned via `pendingWithdraws` funded by the borrower at `stopEpoch`).

### Likelihood Explanation
Requires (a) the manager to run an epoch with `unscaledApr == 0` (a supported, tested mode) and (b) the attacker to be a KYC-passing lender (`isWalletAllowed`), both within the unprivileged-attacker model. The deposit and request can be done in one transaction during any buffer period, and can be repeated every buffer. No privileged action, timing race, or oracle manipulation is needed.

### Recommendation
Accrue APR0 interest only on principal that was supplied before the epoch in which interest is earned — e.g., require `principalEpoch < epochNumber` for the request to join the current `apr0TotalPrincipal`, or snapshot eligible APR0 principal at `startEpoch`. Alternatively, scale the APR0 interest share by the time the principal was actually live (deposit timestamp vs epoch start), or block same-epoch deposit→withdraw-request flows that add to `apr0TotalPrincipal`.

### Proof of Concept
Foundry fork test sketch (same harness style as `test/foundry/IdleCreditVault.t.sol`):

```solidity
// Setup: manager sets APR 0, honest LP deposits H, epoch 0 runs and stops.
vm.prank(manager);
IdleCreditVault(address(strategy)).setAprs(0, 0);

// Honest user deposits H and stays active through epoch 0
idleCDO.depositAA(H);
_startEpochAndCheckPrices(0);
vm.warp(cdoEpoch.epochEndDate() + 1);
deal(underlying, borrower, cdoEpoch.expectedEpochInterest());
vm.prank(manager);
cdoEpoch.stopEpoch(0, 0);
_forceLastEpochAprToZero(); // simulate apr drop for instant/withdraw-request path

// Attacker: single-tx deposit + withdraw request during buffer (epoch 1 pending)
uint256 F = 9 * H;                       // 9x TVL flash capital
deal(underlying, attacker, F);
vm.startPrank(attacker);
idleCDO.depositAA(F);
cdoEpoch.requestWithdraw(IERC20(AAtranche).balanceOf(attacker), address(AAtranche));
vm.stopPrank();

// Epoch 1 runs; borrower repays poolInterest
_startEpochAndCheckPrices(1);
uint256 poolInterest = 1000 * ONE_SCALE;
vm.warp(cdoEpoch.epochEndDate() + 1);
deal(underlying, borrower, poolInterest + IdleCreditVault(address(strategy)).pendingWithdraws() + F);
vm.prank(manager);
cdoEpoch.stopEpoch(0, poolInterest);

// Attacker claims: gets principal + ~ F/(TVL+F) of epoch net interest
vm.prank(attacker);
cdoEpoch.claimWithdrawRequest();
// assert attacker profit ~= 0.9 * poolInterest (net of fees)
// assert honest APR0 requesters' rateByEpoch diluted by factor TVL/(TVL+F)
```

The key assertion is that `apr0RateByEpoch` is computed over `apr0TotalPrincipal` which includes `F` deposited seconds earlier, and `prepareStopEpochWithApr0` reduced `_expInterest` for active holders by the attacker's captured `_apr0NetInterest`.

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
      _apr0User.principalEpoch = epochNumber;
    }
    _apr0User.principal += _amount;
    // Epoch-level APR0 principal used only to compute stopEpoch APR0 pro-rata interest.
    apr0TotalPrincipal += _amount;
  }
