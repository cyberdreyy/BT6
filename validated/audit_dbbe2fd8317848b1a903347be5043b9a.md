### Title
Stale confirmations from a removed member let a multisig request execute with fewer live confirmers than `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges confirmations for requests that the removed member *created* (`r.member == member`), not confirmations the removed member left as a *confirmer* on requests created by someone else. Those stale entries remain in the `confirmations` map and are counted toward the threshold in `confirm`, allowing a request to execute with fewer than `num_confirmations` currently-valid members.

### Finding Description
The invariant the contract must uphold is: `execute_request` is only reached when `|{m in confirmations(request_id) : m ∈ current members}| >= num_confirmations`. In practice the code checks `confirmations.len() + 1 >= num_confirmations` in `confirm` [1](#0-0) , where `confirmations` is a `HashSet<String>` of member identifiers accumulated over time, without ever being revalidated against the current member set.

`delete_member` is supposed to clean up state tied to a removed member, but it only removes requests/confirmations for requests where the removed member is the **original requester** (`r.member == member`): [2](#0-1) 
It never scans the `confirmations` sets of *other* requests (created by different members) to strip out entries belonging to the member being deleted. `assert_valid_request` also does not re-validate that existing confirmers in the set are still members [3](#0-2) ; it only checks that the *current caller* is a member.

Exploit flow (members A, B, C, D; `num_confirmations = 3`):
1. A calls `add_request` with `receiver_id = bob` (an outside account) and a `Transfer` action — request `X`, `r.member = A`.
2. B calls `confirm(X)` → `confirmations[X] = {B}`.
3. Separately, the group legitimately removes B via a `DeleteMember { member: B }` request (created/confirmed by other members, going through `execute_request` → `delete_member`). Since `X.member == A`, not `B`, `X`'s confirmation set is untouched; `confirmations[X]` still contains `B`, even though B is no longer in `self.members`.
4. C calls `confirm(X)` → `confirmations[X] = {B, C}` (len=2, threshold not yet met since `2+1 < 3`... wait — actually with `len=1` before C confirms, `1+1=2 < 3`, so it just inserts).
5. D calls `confirm(X)` → `len(confirmations)=2`, `2+1=3 >= num_confirmations(3)` → `execute_request` fires, transferring funds to `bob`.

Only **C and D** are live members who actually confirmed; B's stale entry supplies the third "confirmation" even though B was removed from `self.members` before ever contributing a legitimate confirmation to the final threshold check. The transfer to `receiver_id = bob` executes with only 2 live confirmations against a `num_confirmations` of 3.

### Impact Explanation
This breaks the core multisig invariant that an executed request must be approved by `num_confirmations` *currently valid* members. It allows NEAR to leave the multisig account (`receiver_id` set to an arbitrary outside account) with fewer live approvals than configured, i.e., unauthorized execution of a fund-moving request. This matches the Critical category: "a multisig request executed below `num_confirmations` live members."

### Likelihood Explanation
This requires no compromise of keys and no bypass of `current_member()` checks — it relies purely on ordinary contract usage: a member confirms a request, is later removed (a routine operational event for any multisig, e.g. rotating signers or removing a compromised key), and the stale confirmation silently persists on any other still-open request that member touched. Any multisig using `multisig2` that rotates membership while requests are pending is exposed; no special attacker capability beyond normal member behavior is needed to trigger it, and the flaw is deterministic and repeatable across requests/removals.

### Recommendation
In `delete_member`, iterate over all entries in `self.confirmations` (not only requests whose `r.member == member`) and remove the deleted member's identifier string from every confirmation set. Alternatively, revalidate each entry in the confirmation set against `self.members` inside `confirm`/`assert_valid_request` before counting it toward `num_confirmations`.

    // 1. A adds request X: receiver_id = some outside account, Transfer action.
    // 2. B calls confirm(X) -> confirmations[X] = {B}.
    // 3. Execute a DeleteMember{member: B} request via A, C, D (3 confirmations)

    //    (assert this directly: c.get_confirmations(x_id) still includes B's string).
    // 4. C calls confirm(X) -> confirmations[X].len() == 2 ({B, C}).
    // 5. D calls confirm(X) -> triggers execute_request since 2+1 >= 3,
    //    even though only C and D are live members that confirmed.
    // Assert: c.requests.len() == 0 (X executed) while B ∉ c.get_members(),
    //    demonstrating execution with only 2 live confirmers against num_confirmations=3.
}

Run with `cargo test -p multisig2 test_stale_confirmation_after_delete_member`, asserting `c.get_members()` no longer contains `B` at the moment `X` executes, while the number of *live* confirmers on `X` is strictly less than `c.get_num_confirmations()`.

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
