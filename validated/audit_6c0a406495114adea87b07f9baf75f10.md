### Title
Unsupported/arbitrary `req.Method` bypasses method validation and triggers full DON fan-out before erroring - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` validates only `req.ID` (emptiness/length) and never checks `req.Method` against `h.Methods()` before allocating an `activeRequest` and calling `fanOutToNodes`, which broadcasts the raw request to every DON member via `h.don.SendToNode`. The only place `req.Method` is validated is inside `bundler.Bundle`, which is invoked later — either when a node responds (`HandleNodeMessage`) or on request expiry (`removeExpiredRequests`, default 30s) — at which point it returns `errUnknownMethod`.

### Finding Description
`HandleJSONRPCUserMessage` (core/services/gateway/handlers/confidentialrelay/handler.go:349-366) performs:
```go
if req.ID == "" { ... }
if len(req.ID) > 200 { ... }
...
ar, err := h.newActiveRequest(req, callback)   // no method check
...
return h.fanOutToNodes(ctx, l, ar)             // sends to ALL don.Members regardless of req.Method
```
`newActiveRequest` (line 368) only guards against duplicate `req.ID`, not `req.Method`. `fanOutToNodes` (line 618) iterates `h.donConfig.Members` and calls `h.don.SendToNode(sendCtx, node.Address, &ar.req)` for every node unconditionally.

Method validation only occurs inside `bundler.Bundle` (core/services/gateway/handlers/confidentialrelay/bundler.go:118-163), via a `switch req.Method` with `default: return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)`. `Bundle` is only called from `HandleNodeMessage` (after a node actually answers) or from the cleanup goroutine at request expiry (`removeExpiredRequests`, bound by `defaultRequestTimeoutSec = 30`). Thus a bogus method is not rejected until either a node responds or up to 30 seconds elapse.

Additionally, at the routing layer, `multiHandler.getHandler` (core/services/gateway/multihandler.go:80-96) short-circuits method checking entirely when only one handler type is registered:
```go
if len(m.typeToHandler) == 1 {
    for _, handler := range m.typeToHandler {
        return handler, nil
    }
}
```
This means when a DON is configured with a single handler (the typical single-handler-per-DON deployment), the `methodToHandler` map lookup (which would otherwise reject unknown methods) is bypassed altogether, and any `req.Method` string reaches `handler.HandleJSONRPCUserMessage` directly.

The `Methods()` method exists on the handler (`h.Methods()` returns `[MethodSecretsGet, MethodCapabilityExec]`, line 341-343) but is never consulted inside `HandleJSONRPCUserMessage` to reject the request before consuming resources. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Impact Explanation
An unprivileged gateway client can submit JSON-RPC requests with arbitrary/unsupported `Method` values and unique `ID`s. Each such request consumes an `activeRequests` map slot for up to the configured `RequestTimeoutSec` (default 30s) and causes a full fan-out network send (`h.don.SendToNode`) to every DON member node, before ultimately being rejected only at aggregation time. Repeated at volume, this wastes gateway-to-node bandwidth/connections and DON member processing across the whole DON membership for each unprivileged, unauthenticated submission — a resource-exhaustion/amplification vector against DON nodes triggered cheaply by any caller able to reach the gateway. This matches a resource-exhaustion / denial-of-service impact class rather than direct fund loss or key disclosure.

### Likelihood Explanation
Preconditions are minimal: any caller able to reach this DON's gateway handler (no special privilege, no valid method needed) can trigger it. The attack is trivially repeatable — submit N distinct unique `req.ID`s with `req.Method = "bogus"`. It is amplified further if the DON is configured with only a single handler type, since `multiHandler.getHandler` skips the method-to-handler validation entirely in that case, letting any method string reach the handler.

### Recommendation
In `HandleJSONRPCUserMessage`, validate `req.Method` against `h.Methods()` (or equivalently against the same switch used in `bundler.Bundle`) before calling `h.newActiveRequest` and `h.fanOutToNodes`, returning an `UnsupportedMethodError`/`errUnknownMethod`-based response immediately. Additionally, fix `multiHandler.getHandler` to still validate `method` against `methodToHandler` even when only one handler type is registered, rather than unconditionally routing.

### Proof of Concept
Go handler-level test plan (core/services/gateway/handlers/confidentialrelay/handler_test.go):
1. Construct a `handler` with a mock `gwhandlers.DON` (e.g., existing mocks used in `handler_test.go`) that records calls to `SendToNode`.
2. Call `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request[json.RawMessage]{ID: "req-1", Method: "bogus.method"}, callback)`.
3. Assert: today, `don.SendToNode` is invoked once per DON member (`len(donConfig.Members)` calls) — demonstrating fan-out occurs despite the unsupported method.
4. Assert the request is only rejected later — e.g., trigger `removeExpiredRequests` after advancing the fake clock past `requestTimeout`, and observe the error response with `errUnknownMethod` arrives only then, or when `HandleNodeMessage` is invoked with a matching `req.ID`.
5. Expected fix behavior: after adding an explicit method check, `don.SendToNode` call count for an unsupported method should be `0`, and `HandleJSONRPCUserMessage` should return an error synchronously without creating an `activeRequests` entry.

```go
func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}
```

```go
func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
```

```go
func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedCapabilityResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable capability response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedCapabilityResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode capability response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	default:
		return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)
	}
```

```go
func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	// If there's only one handler, return it directly.
	// This preserves backwards compatibility for cases where the method
	// isn't specified on responses (and for cases where only one handler is registered more generally).
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}

	handler, ok := m.methodToHandler[method]
	if !ok {
		return nil, errors.New("no handler found for method " + method)
	}

	return handler, nil
}
```
