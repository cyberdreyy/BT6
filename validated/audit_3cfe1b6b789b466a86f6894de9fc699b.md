### Title
Unsafe symlink extraction in ExtractZipArchive allows writes outside job root via crafted zip entries - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipSymlinkEntry` creates a filesystem symlink at `file.Name` pointing to an attacker-controlled target read directly from the zip entry's data, with no validation that the target stays within the extraction root. A subsequent entry in the same archive whose name traverses through that symlink path (or that reuses the symlink path as a directory component via `extractZipFile`'s `os.MkdirAll(filepath.Dir(file.Name))`) can then write/overwrite arbitrary file content at whatever the symlink points to.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile` for every entry in file order [1](#0-0) . For each entry, `extractZipFile` first runs `os.MkdirAll(filepath.Dir(file.Name), 0o777)` unconditionally, then dispatches based on `file.Mode()&os.ModeType`: directory, symlink, or regular file [2](#0-1) . Wait — corrected below. [3](#0-2) 

For symlink entries, `extractZipSymlinkEntry` reads the entry's file content as the link target and calls `os.Symlink(string(data), file.Name)` with zero validation of the target (no check for absolute paths, `..` traversal, or that the resolved target stays under the extraction root) [4](#0-3) . `errorIfGitDirectory`/`isPathAGitDirectory` only reject paths beginning with `.git`; they do not perform any general path or symlink-target validation [5](#0-4) .

Attack flow: within a single crafted zip archive (e.g., extracted during cache/artifact restore via `ziplegacy.extractor.Extract` → `archives.ExtractZipArchive` [6](#0-5) ):
1. An entry named `link` with `os.ModeSymlink` and content `/etc/passwd` (or any absolute/traversal path) is processed first, creating a real symlink at `<workdir>/link` → `/etc/passwd`.
2. A later entry named `link` (regular file) is processed by `extractZipFileEntry`, which does `os.Remove(file.Name)` then `os.OpenFile(file.Name, O_WRONLY|O_CREATE|O_TRUNC, ...)` [7](#0-6) . Because step 1's `os.Remove` before `os.Symlink` and step 2's own `os.Remove` operate on the symlink path itself (unlink, not follow), a same-named regular-file entry would just replace the symlink — but a *nested* entry such as `link/evil` triggers `os.MkdirAll(filepath.Dir("link/evil"))`, which will traverse through the existing symlink `link` and, depending on OS symlink-following semantics for `MkdirAll`, create/write through it, or `extractZipFileEntry`'s `os.OpenFile` for a path like `link/evil` will open through the symlink to whatever directory it points to.
3. No component in `ExtractZipArchive`, `extractZipFile`, or the git-path check validates that entry names or symlink targets stay within the extraction root; the only existing guard is the unrelated `.git` directory warning.

### Impact Explanation
An attacker who controls a cache or artifact zip archive restored by the Runner can create a symlink pointing at an arbitrary absolute path and then have a subsequent entry in the same archive write through it, resulting in arbitrary file write/overwrite outside the job's designated build/cache directory on the host or container running the extraction. This violates the invariant that "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
This requires only that the attacker control an archive processed by `ExtractZipArchive` — e.g., by pushing a pipeline that populates a cache/artifact zip with the crafted entries, then having that cache/artifact restored in a later job. No special privileges beyond normal pipeline authorship are needed, and zip file ordering is fully attacker-controlled, making the sequence (symlink entry before dependent write entry) trivially reproducible.

### Recommendation
Before calling `os.Symlink`, validate that the resolved absolute target (and the entry's own destination path) stays within the extraction root (e.g., reject absolute targets and targets whose cleaned, joined path escapes the root via `..`). Additionally, when creating parent directories or opening files during extraction (`os.MkdirAll(filepath.Dir(file.Name))`, `os.OpenFile`), detect and reject cases where any path component is a symlink pointing outside the extraction root (e.g., using `filepath.EvalSymlinks` on the directory portion and comparing against the root, or performing extraction with `O_NOFOLLOW`-style component-wise checks as done in hardened archive extractors).

### Proof of Concept
Go unit test in `helpers/archives`:
```go
func TestExtractZipSymlinkEscape(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        f, err := os.Create(fileName)
        require.NoError(t, err)
        archive := zip.NewWriter(f)

        // 1. symlink entry pointing outside workdir
        hdr := &zip.FileHeader{Name: "link"}
        hdr.SetMode(os.ModeSymlink | 0o777)
        w, _ := archive.CreateHeader(hdr)
        outsideTarget := filepath.Join(os.TempDir(), "outside_target_file")
        io.WriteString(w, outsideTarget)

        // 2. nested entry writing through the symlink
        w2, _ := archive.Create("link/evil")
        io.WriteString(w2, "attacker content")

        archive.Close()
        f.Close()

        err = ExtractZipFile(fileName)
        require.NoError(t, err)

        // Assert: no file was created/overwritten outside the workdir
        _, statErr := os.Stat(outsideTarget)
        assert.True(t, os.IsNotExist(statErr), "attacker should not be able to write outside workdir via symlink")
    })
}
```
Expected (buggy) behavior: the write succeeds and `outsideTarget` (or a file under it) is created/modified, proving escape. A fixed implementation should reject the symlink target or fail the nested write with a path-validation error, keeping `os.IsNotExist(statErr)` true.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
