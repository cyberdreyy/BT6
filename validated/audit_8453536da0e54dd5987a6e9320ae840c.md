### Title
`max_timestamp` Overwrite in `add_simple_oracle` Allows Caller-Controlled Time-Window Manipulation to Include Stale Price Data — (`crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

The `MetaOracle` module in the Sui oracle framework aggregates prices from multiple `SimpleOracle` sources and applies a median strategy. The `add_simple_oracle` function is supposed to track the **maximum** timestamp seen across all oracles so that the `combine` function can filter out stale data. However, the implementation unconditionally **overwrites** `max_timestamp` with each oracle's timestamp instead of taking the true maximum. Because the caller of a PTB controls the order in which oracle objects are passed as arguments, an unprivileged user can manipulate which value ends up in `max_timestamp`, thereby controlling the time-window anchor and selectively including stale (potentially manipulated) oracle readings that should have been excluded.

---

### Finding Description

In `add_simple_oracle`:

```move
public fun add_simple_oracle<T: copy + drop + store>(
    meta_oracle: &mut MetaOracle<T>,
    oracle: &SimpleOracle
) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        // BUG: overwrites instead of taking max
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
``` [1](#0-0) 

After all oracles are added, `max_timestamp` holds the timestamp of the **last oracle with data**, not the maximum across all oracles. In `combine`, the staleness filter is:

```move
let min_timestamp = max_timestamp - time_window_ms;
...
if (data::timestamp(&oracle_data) > min_timestamp) {
    // include this oracle's value
};
``` [2](#0-1) 

Because `min_timestamp` is derived from `max_timestamp`, whoever controls the last oracle argument controls the time-window anchor for the entire aggregation.

**Attack path (unprivileged caller):**

1. Suppose three `SimpleOracle` objects exist: `oracle_A` (stale, timestamp `T_old`, price = $9, manipulated), `oracle_B` (fresh, timestamp `T_new`, price = $11), `oracle_C` (fresh, timestamp `T_new`, price = $11).
2. Correct behavior: `max_timestamp = T_new`; `min_timestamp = T_new − time_window`. `oracle_A` is excluded because `T_old ≤ min_timestamp`. Median of [$11, $11] = $11.
3. Attacker passes oracles in PTB order: `oracle_B`, `oracle_C`, **`oracle_A` last**. Now `max_timestamp = T_old`; `min_timestamp = T_old − time_window` (a very old cutoff). All three oracles pass the filter. Median of [$9, $11, $11] = $11 (still safe with 3 oracles).
4. With a configuration of threshold=2 and 3 oracles, or two stale manipulated oracles: median of [$9, $9, $11] = $9. The attacker obtains the manipulated price.

The `trusted_fx` example in the test module shows exactly this pattern — three oracles, threshold=3, caller-supplied order:

```move
let mut meta_oracle = meta_oracle::new<DecimalValue>(3, 60000, string::utf8(b"SUIUSD"));
meta_oracle::add_simple_oracle(&mut meta_oracle, oracle1);
meta_oracle::add_simple_oracle(&mut meta_oracle, oracle2);
meta_oracle::add_simple_oracle(&mut meta_oracle, oracle3);
let trusted_data = meta_oracle::median(meta_oracle);
``` [3](#0-2) 

The caller fully controls `oracle1`, `oracle2`, `oracle3` and their order.

---

### Impact Explanation

Any DeFi protocol that uses `MetaOracle` to price assets (for lending, liquidation, swaps, etc.) and sets `threshold < number_of_oracles` is vulnerable. An attacker can include stale or previously manipulated oracle readings in the median, skewing the computed price. This is the direct Sui analog of M-4: instead of causing price feeds to revert via reentrancy, the attacker exploits argument ordering to manipulate the time-window anchor, achieving the same outcome — the final price is computed from a selectively chosen, potentially manipulated subset of sources.

---

### Likelihood Explanation

The trigger is a standard PTB call with reordered oracle arguments — no special privileges, no reentrancy, no flash loan required. Any user interacting with a protocol that exposes a `MetaOracle`-backed price function can attempt this. The only prerequisite is that at least one `SimpleOracle` has stale data with a favorable (manipulated) price, which can arise naturally from oracle latency or from a prior market manipulation.

---

### Recommendation

Replace the unconditional overwrite in `add_simple_oracle` with a proper maximum:

```move
public fun add_simple_oracle<T: copy + drop + store>(
    meta_oracle: &mut MetaOracle<T>,
    oracle: &SimpleOracle
) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        let ts = data::timestamp(option::borrow(&oracle_data));
        if (ts > meta_oracle.max_timestamp) {
            meta_oracle.max_timestamp = ts;
        };
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
```

This ensures `max_timestamp` is always the most recent timestamp seen, making the time-window anchor independent of argument order.

### Proof of Concept

```move
// Attacker-controlled PTB call
// oracle_stale: timestamp = 100ms, price = $9 (manipulated)
// oracle_fresh1: timestamp = 70_000ms, price = $11
// oracle_fresh2: timestamp = 70_000ms, price = $11
// time_window_ms = 60_000ms, threshold = 2

let mut meta = meta_oracle::new<DecimalValue>(2, 60_000, utf8(b"SUIUSD"));

// Attacker passes oracle_stale LAST
meta_oracle::add_simple_oracle(&mut meta, oracle_fresh1);  // max_timestamp = 70_000
meta_oracle::add_simple_oracle(&mut meta, oracle_fresh2);  // max_timestamp = 70_000
meta_oracle::add_simple_oracle(&mut meta, oracle_stale);   // max_timestamp = 100  ← BUG

// combine: min_timestamp = 100 - 60_000 → underflow abort (if 100 < 60_000)
// OR if time_window_ms = 50:
// min_timestamp = 100 - 50 = 50
// All three oracles pass (timestamps 70_000, 70_000, 100 all > 50)
// Median of [$9, $11, $11] with threshold=2 → passes, median = $11 (3 values)
// With two stale oracles: median of [$9, $9, $11] = $9 ← manipulated price accepted
``` [4](#0-3)
