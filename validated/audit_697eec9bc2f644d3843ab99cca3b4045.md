### Title
`depositDuringEpoch` bypasses the paused state, allowing mid-epoch deposits while the protocol is paused - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
Analogous to the LooksRare finding — where the "max deposits per round" cap was only enforced on the normal path and could be exceeded once a round was started-but-not-drawn during a pause — `IdleCDOEpochVariant.depositDuringEpoch` enforces a list of epoch-state flags but never checks `paused()`. The normal deposit path `_deposit` is gated by `whenNotPaused` (contracts/IdleCDOEpochVariant.sol:644), but `depositDuringEpoch` (line 656) is not, and `_beforeUnpause` (line 635) actively prevents unpausing while an epoch is running. So an owner pause during a running epoch does not stop mid-epoch deposits: the protocol stays paused and `depositDuringEpoch` keeps pulling underlying from KYC'd users.

### Finding Description
`depositDuringEpoch` rejects only when:

```solidity
_checkNotAllowed(
  (_tranche == BBTranche && !isBBDepositEnabled) ||
  isDepositDuringEpochDisabled ||
  skipDefaultCheck ||
  isProgrammableBorrower ||
  isAYSActive ||
  !isEpochRunning || block.timestamp >= epochEndDate ||
  !isWalletAllowed(msg.sender)
);
```

There is no `whenNotPaused` modifier and no `paused()` check in the `_checkNotAllowed` list. Compare with `_deposit`:

```solidity
function _deposit(uint256 _amount, address _tranche) internal override whenNotPaused returns (uint256)
```

Meanwhile `_beforeUnpause` reverts while `isEpochRunning` is true, so once the owner pauses mid-epoch (e.g., in response to an emergency that does not set `skipDefaultCheck` or `defaulted`, such as a Hypernative/security pause or an operational incident), the contract remains paused for the rest of the epoch — yet any allowed wallet can still call `depositDuringEpoch` and push fresh underlying into the pool/borrower flow.

Sequence (mirroring the report):
1. Epoch is running; `isDepositDuringEpochDisabled == false`, APR>0 mode, not AYS, not programmable.
2. Owner pauses the contract mid-epoch for an emergency reason unrelated to default/`skipDefaultCheck`.
3. `paused() == true`; ordinary `depositAA`/`depositBB` revert via `whenNotPaused`.
4. Unpause is blocked by `_beforeUnpause` (`isEpochRunning` still true), so the pause persists.
5. Any KYC-passing lender calls `depositDuringEpoch`, deposits underlying, and is minted tranche shares — deposits proceed even though the protocol is paused.

### Impact Explanation
The pause mechanism is the protocol's emergency circuit breaker; the invariant "while paused, no new funds enter the pool" is broken on the mid-epoch path. Funds deposited during an emergency pause are forwarded into the epoch accounting and (through the strategy) exposed to the borrower — precisely the scenario the pause was meant to freeze. If the pause was triggered because of a borrower-solvency or strategy issue that later materializes into a default/loss (`_handleBorrowerDefault` / `stopEpochWithDuration(_lossAmount)`), the attacker-depositor's capital is lost into the loss waterfall, and conversely a lender can keep dumping capital into a troubled pool and crystallize claims against it. Broken invariant: access/state gating (paused deposits). Loss is realized through the standard loss-socialization path at epoch stop.

### Likelihood Explanation
Requires: (a) the pool operating in a mode where `depositDuringEpoch` is enabled (fixed-APR, non-AYS, non-programmable, `isDepositDuringEpochDisabled == false`), and (b) an owner-triggered pause that does not also set `skipDefaultCheck`/`defaulted` (e.g., a direct `pause()` rather than `emergencyShutdown`/`_emergencyShutdown`). Both conditions are plausible operational configurations; the pause itself is an honest privileged action the attacker merely sequences around, consistent with the threat model.

### Recommendation
Add the paused check to `depositDuringEpoch`, e.g. add `paused()` to the `_checkNotAllowed` clause in `IdleCDOEpochVariant.depositDuringEpoch` (or add `whenNotPaused`), so that every user-facing deposit entry point is uniformly gated by the pause flag — the same fix pattern as the report's recommendation to move the cap check into the shared `_depositETH` path.

### Proof of Concept
Foundry-style PoC against `IdleCDOEpochVariant` (non-prefunded variant, `isDepositDuringEpochDisabled = false`, `isAYSActive = false`, fixed-APR borrower):

```solidity
function test_audit_depositDuringEpochWhilePaused() public {
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount); // seed AA tranche so _trancheTotSupply > 0

    vm.prank(owner);
    cdoEpoch.setIsDepositDuringEpochDisabled(false);

    _startEpochAndCheckPrices(0);          // epoch running
    vm.warp(cdoEpoch.epochEndDate() - cdoEpoch.epochDuration() / 2);

    // Owner pauses mid-epoch (plain pause, not emergencyShutdown -> skipDefaultCheck stays false)
    vm.prank(owner);
    cdoEpoch.pause();
    assertTrue(cdoEpoch.paused());

    // Normal deposit path is blocked
    address user = makeAddr("user");
    deal(defaultUnderlying, user, 1_000 * ONE_SCALE);
    vm.startPrank(user);
    IERC20Detailed(defaultUnderlying).approve(address(cdoEpoch), 1_000 * ONE_SCALE);
    vm.expectRevert();                     // whenNotPaused on _deposit
    cdoEpoch.depositAA(1_000 * ONE_SCALE);

    // Unpause is blocked while the epoch is running
    vm.stopPrank();
    vm.prank(owner);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.unpause();

    // But the mid-epoch path still accepts funds while paused
    vm.prank(user);
    uint256 minted = cdoEpoch.depositDuringEpoch(1_000 * ONE_SCALE, address(AAtranche));
    assertGt(minted, 0);                   // deposit succeeded despite paused() == true
}
```

Caveat: I was unable to verify the exact external `pause()`/`unpause()` entry-point names in this iteration (the grep output returned match counts only, not line contents); if pause is only reachable via `emergencyShutdown` (which sets `skipDefaultCheck`), the pause must instead come from an external pauser such as `HypernativeBatchPauser` or an inherited Pausable path for the PoC to stand. The missing `paused()` check in `depositDuringEpoch` versus `whenNotPaused` on `_deposit` is confirmed at contracts/IdleCDOEpochVariant.sol lines 644 and 656-669.
