### Title
Prefunded deposits can be stranded by changing the settlement queue mid-epoch - (File: contracts/IdleCDOEpochVariantPrefunded.sol)

### Summary
`setEpochQueue` can replace or clear the configured queue after `IdleCDOEpochQueue.processDepositsToBorrower` has already transferred user deposits to the borrower but before `stopEpochWithDuration` settles those deposits. Because settlement is looked up only on the currently configured queue, replacing the queue makes the stop hook see zero prefunded deposits and skip minting/pricing them, permanently locking the deposited funds in an unsettled accounting state.

### Finding Description
During a running prefunded epoch, a user calls `requestDeposit`, and the manager calls `processDepositsToBorrower`; that call moves `epochPendingDeposits` into `epochPrefundedDeposits` and transfers the underlying directly to the borrower. [1](#0-0) 

However, `IdleCDOEpochVariantPrefunded.setEpochQueue` lets the owner or manager replace `epochQueue` at any time, including after funds have been prefunded; the code documents this invariant but does not enforce it. [2](#0-1) 

At epoch stop, `_afterStopEpochWithDuration` queries only the currently configured queue and returns early when that queue reports zero prefunded deposits. [3](#0-2) 

Consequently, the original queue never receives `epochPrice`, its `epochPrefundedDeposits` remains nonzero, `deleteRequest` reverts, and `claimDepositRequest` reverts because deposits remain unsettled. [4](#0-3) [5](#0-4) 

This is analogous to an administrative reorder/update unexpectedly invalidating already-queued user operations: the user's deposit is valid when prefunded, but a later queue-pointer update changes which object the settlement path reads, leaving the user with an unclaimable receipt.

### Impact Explanation
All affected prefunded deposit principal is permanently locked economically: the underlying has already been transferred to the borrower, while no AA tranche shares are minted to the original queue and no withdrawal or cancellation path can clear the stale `epochPrefundedDeposits` entry. The borrower may honestly retain the extra prefunded principal because the skipped settlement also prevents `_mintSharesAtCurrPrice` and `mintStrategyTokens` from accounting for that principal. [6](#0-5) 

### Likelihood Explanation
The issue requires an owner or manager to change or clear `epochQueue` during the narrow window between prefunding and `stopEpochWithDuration`. That role is honest but may make an ordinary configuration change or front-run a pending settlement/claim operation without realizing that the queue has in-flight prefunded state. Since the function itself is unrestricted, no attacker privilege, timing manipulation, or protocol error is required beyond that sequence.

### Recommendation
Prevent `setEpochQueue` from changing or clearing the queue while any prefunded deposit is unsettled. At minimum, `setEpochQueue` should call the current queue and reject when `epochPrefundedDeposits[currentEpoch + 1]` or the equivalent outstanding prefunded balance is nonzero. A stronger design is to bind the prefunded queue once per epoch, record the settlement queue alongside `epochPrefundedDeposits`, and let `stopEpochWithDuration` settle against that immutable queue rather than a mutable global pointer.

### Proof of Concept
Add this test to `test/foundry/IdleCDOEpochVariantPrefunded.t.sol`, which already provides the mainnet-fork fixture, `queue`, `manager`, `_requestDepositWithUser`, and `_enterPrefundedWindow` helpers:

```solidity
function testQueueReplacementAfterPrefundStrandsDeposit() external {
  uint256 amount = 3e6;
  uint256 interest = 1000 * 1e6;
  address user = makeAddr("stranded-user");

  vm.prank(manager);
  cdoEpoch.setEpochQueue(address(queue));
  vm.prank(manager);
  queue.setPrefundedDepositWindow(PREFUNDED_DEPOSIT_WINDOW);

  _requestDepositWithUser(user, amount);
  uint256 requestEpoch = strategy.epochNumber() + 1;

  _enterPrefundedWindow(PREFUNDED_DEPOSIT_WINDOW);

  address borrower = strategy.borrower();
  uint256 borrowerBase = underlying.balanceOf(borrower);

  vm.prank(manager);
  queue.processDepositsToBorrower();

  assertEq(underlying.balanceOf(borrower), borrowerBase + amount);
  assertEq(queue.epochPrefundedDeposits(requestEpoch), amount);

  // Honest but mistimed configuration change before settlement.
  vm.prank(manager);
  cdoEpoch.setEpochQueue(address(0));

  uint256 toRepay = interest + strategy.pendingWithdraws();
  deal(address(underlying), borrower, borrowerBase + amount + toRepay);
  vm.prank(borrower);
  underlying.approve(address(cdoEpoch), borrowerBase + amount + toRepay);

  vm.warp(cdoEpoch.epochEndDate() + 1);
  vm.prank(manager);
  cdoEpoch.stopEpochWithDuration(0, interest, cdoEpoch.epochDuration(), 0);

  // The borrower kept the prefunded principal, while the original queue was never settled.
  assertEq(underlying.balanceOf(borrower), borrowerBase + amount);
  assertEq(queue.epochPrefundedDeposits(requestEpoch), amount);
  assertEq(queue.epochPrice(requestEpoch), 0);
  assertEq(tranche.balanceOf(address(queue)), 0);

  vm.prank(user);
  vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
  queue.claimDepositRequest(requestEpoch);

  vm.prank(user);
  vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
  queue.deleteRequest(requestEpoch);
}
```

  function processDepositsToBorrower() external {
    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    IdleCreditVault _strategy = IdleCreditVault(strategy);
    // only owner or strategy manager can move queued funds to the borrower
    _checkOnlyOwnerOrManager();
    // prefunded flow is supported only for AA queue
    // queue must be explicitly enabled on the prefunded CDO variant
    _checkNotAllowed(tranche != _cdo.AATranche() || !_isPrefundedQueueEnabled());

    // prefunding can be done only while epoch is running
    if (!_cdo.isEpochRunning()) {
      revert EpochNotRunning();
    }
    // Keep prefunding aligned with the same cutoff enforced for new queued deposits.
    uint256 _prefundedWindow = prefundedDepositWindow;
    _checkNotAllowed(_prefundedWindow == 0 || block.timestamp + _prefundedWindow < _cdo.epochEndDate());

    uint256 _epoch = _strategy.epochNumber() + 1;
    // prefunding can happen only once for an epoch
    _checkNotAllowed(epochPrefundedDeposits[_epoch] != 0);
    uint256 _pending = epochPendingDeposits[_epoch];
    if (_pending == 0) {
      return;
    }
    // Recheck after the cutoff because emergency state or the TVL limit can change while queued.
    IdleCDOEpochVariantPrefunded(idleCDOEpoch).checkPrefunding(_pending);

    // Switch the epoch from "queue-held" to "already at borrower" before transferring funds.
    epochPendingDeposits[_epoch] = 0;
    epochPrefundedDeposits[_epoch] = _pending;
    IERC20Detailed(underlying).safeTransfer(_strategy.borrower(), _pending);

  function deleteRequest(uint256 _requestEpoch) external {
    // if the epoch price is already set, deposits were already processed so
    // the deposit request can't be deleted.
    _checkNotAllowed(epochPrice[_requestEpoch] != 0 || epochPrefundedDeposits[_requestEpoch] != 0);

    uint256 amount = userDepositsEpochs[msg.sender][_requestEpoch];
    if (amount == 0) {
      return;
    }
    // reset user deposit for the epoch
    userDepositsEpochs[msg.sender][_requestEpoch] = 0;
    // update pending deposits
    epochPendingDeposits[_requestEpoch] -= amount;
    // transfer underlyings back to the user
    IERC20Detailed(underlying).safeTransfer(msg.sender, amount);
