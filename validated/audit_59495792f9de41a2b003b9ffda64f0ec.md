### Title
Unauthenticated global `savedCallbacks` map allows attacker to exhaust/evict legitimate victim callbacks in `WebAPIHandler` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` accepts any message with a valid self-generated ECDSA signature (no sender allowlist check) and stores it in a single global `savedCallbacks` map keyed by attacker-controlled `MessageId`, bounded only by a global `defaultMaxSavedCallbacks` (20000). Because eviction in `pruneCallbacks` is FIFO-by-creation-time and quota is global rather than per-sender, an attacker can flood the map with self-signed messages to starve or evict legitimate victims' pending callbacks.

### Finding Description
The gateway's user HTTP endpoint (`gateway.ProcessRequest` in `core/services/gateway/gateway.go:218-292`) has no authentication requirement beyond an optional JWT bearer token that is merely forwarded as `auth` to `jsonrpc2.DecodeRequest`; for legacy requests, the only gate is `msg.Validate()` [1](#0-0) , which in turn (`core/services/gateway/api/message.go:54-88`) only checks field lengths and that the signature is well-formed/recoverable — it does **not** check the recovered sender against any DON allowlist [2](#0-1) . Any attacker holding an arbitrary ECDSA keypair can self-sign a message and pass validation.

The request is then routed to `handler.HandleLegacyUserMessage`, which explicitly defers allowlist/rate-limit enforcement via a `TODO` comment: `// TODO: apply allowlist and rate-limiting here` [3](#0-2) . After minimal payload/timestamp/method checks, the handler unconditionally inserts the callback into the single shared map `h.savedCallbacks[msg.Body.MessageId]` [4](#0-3) , keyed entirely by the attacker-controlled `MessageId` field, with no per-sender bucketing or quota.

The only bound on this map's size is `defaultMaxSavedCallbacks = 20000`, enforced by the periodic `pruneCallbacks` routine [5](#0-4) . This function is a global cap: it first removes expired entries by age, and if the map is still over `maxSize`, it sorts *all* remaining entries (regardless of sender) by `createdAt` and deletes the oldest half [6](#0-5) . There is no per-sender isolation anywhere in this flow — the existing test suite even has an explicit unresolved TODO: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` [7](#0-6) .

Exploit flow: an attacker with no DON-allowlist membership generates unique `MessageId`s, signs >20000 distinct legacy `web_api_trigger` messages with any/many throwaway keys, and submits them concurrently to the gateway's user endpoint. Each passes `Validate()` and is stored in `savedCallbacks`. When a legitimate victim's request arrives concurrently (its entry is inserted with its own `createdAt`), a subsequent `pruneCallbacks` cycle (runs every `defaultCallbackPruneIntervalSec` = 30s) sorts the combined pool by age and evicts the oldest half — which, depending on timing, can include the victim's entry before its corresponding node response ever arrives, causing the victim's `callback.Wait()` in `gateway.ProcessRequest` to time out (`response.RequestTimeoutError`) even though nothing was actually wrong with the victim's own request.

### Impact Explanation
This is a cross-user, unauthenticated denial-of-service against the gateway's `WebAPIHandler`: a single unprivileged attacker who never needs allowlist membership can consume the entire global `savedCallbacks` capacity and cause legitimate DON-member/victim requests to be evicted/dropped, resulting in request timeouts for legitimate users sharing the same DON/handler instance. This maps to a "Denial of Service" / quota-bypass class bounty impact — no funds or secrets are directly exposed, but service availability for legitimate users is degraded/denied by an attacker with minimal capability (any ECDSA key, no special role).

### Likelihood Explanation
Preconditions are minimal: the attacker only needs network access to the gateway user HTTP endpoint and the ability to generate ECDSA keypairs to self-sign messages — no DON membership, no valid registered workflow, and no bearer token/allowlist entry is required to reach `HandleLegacyUserMessage` and populate `savedCallbacks`, confirmed by the explicit `// TODO: apply allowlist and rate-limiting here` gap in the code. The attack is trivially automatable and repeatable (just generate many keys/MessageIds and submit concurrently), and the eviction/prune interval is fixed and predictable (`defaultCallbackPruneIntervalSec` = 30s), making timing the flood against a victim's request feasible.

### Recommendation
Enforce sender-scoped quotas before/at insertion into `savedCallbacks` — e.g., reject or rate-limit new callback entries per-sender (using `msg.Body.Sender`) via `h.nodeRateLimiter`-style per-key limiter, cap the number of outstanding callbacks per sender independent of the global cap, and/or require the sender to be part of an allowlist (as already flagged by the code's own `TODO`) before accepting and storing a callback. Additionally, `pruneCallbacks` eviction should not indiscriminately evict oldest entries across all senders; it should prioritize evicting entries from senders that are over their own quota rather than globally oldest entries.

### Proof of Concept
Go handler-level integration test plan (extending `handler_test.go`):
1. Instantiate `handler` with `MaxSavedCallbacks` set to a small value for test speed (e.g., 100) and a `DONConfig` with one member node, mocking `don.SendToNode` to be a no-op.
2. In a loop, generate `MaxSavedCallbacks` distinct throwaway ECDSA keys, build a valid `web_api_trigger` `TriggerRequestPayload` with current timestamp and unique `MessageId`s via the existing `triggerRequest` test helper, and call `handler.HandleLegacyUserMessage` concurrently for all of them, each with its own `handlers.Callback`.
3. Immediately afterward, submit one additional "victim" request signed by a distinct key with a fresh `MessageId` via `HandleLegacyUserMessage`.
4. Manually invoke `handler.pruneCallbacks()` (or wait for the ticker) to force the eviction pass.
5. Assert that `handler.savedCallbacks` under `handler.mu.Lock()` either still contains the victim's `MessageId` (showing per-sender/priority protection) or, on the current implementation, assert (demonstrating the bug) that the victim's entry can be evicted purely due to insertion-order/age when attacker floods exceed capacity — i.e., write the test to show the victim's callback never receives a response (`cb.Wait(ctx)` times out) while 20000 attacker-only entries occupied the map, proving the global quota allows a single attacker to starve legitimate senders.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}
