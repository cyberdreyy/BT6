### Title
Pre-authorization workflow existence oracle allows unauthenticated enumeration of workflowID/owner/name/tag - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`HandleUserTriggerRequest` calls `resolveWorkflowID` before `authorizeRequest`, so an unauthenticated caller reaching the gateway's HTTP/WS trigger endpoint gets a distinct, differentiable error ("Workflow not found...") for nonexistent workflow selectors versus a different error ("Auth failure: ...") for existing-but-unauthorized ones. This lets an attacker enumerate valid `workflowID`s and valid `(workflowOwner, workflowName, workflowTag)` combinations without ever presenting valid credentials.

### Finding Description
`gatewayHandler.HandleJSONRPCUserMessage` (`core/services/gateway/handlers/capabilities/v2/http_handler.go:391-401`) forwards every incoming JSON-RPC request directly to `h.triggerHandler.HandleUserTriggerRequest` with no prior authentication gate [1](#0-0) .

Inside `HandleUserTriggerRequest`, the order of operations is:
1. `validatedTriggerRequest` — only performs structural/format validation, no auth.
2. `resolveWorkflowID` — looks up the workflow by ID or by owner+name+tag in `workflowMetadataHandler`. If not found, it emits `jsonrpc.ErrInvalidRequest` with message `"Workflow not found. 'workflowID' %s is not a valid workflow ID"` or `"Workflow not found. Provide either a valid 'workflowID'..."`.
3. `authorizeRequest` — only runs afterward, calling `h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)`, and on failure emits `"Auth failure: "+err.Error()`. [2](#0-1) 

The two error paths are textually and semantically distinguishable: [3](#0-2) [4](#0-3) 

Because `resolveWorkflowID` runs before any signature/credential check, an attacker with no valid `req.Auth` can submit many `workflowID` values (or owner/name/tag guesses) and use the returned error message to determine which ones exist in the gateway's workflow metadata store, even though they can never successfully trigger execution without valid auth. This is a genuine "existence oracle": "Workflow not found" (pre-auth, doesn't exist) is returned before authorization is ever attempted, so it cannot be conflated with an auth failure that would occur for a real workflow.

### Impact Explanation
This is an information-disclosure / enumeration issue: an unauthenticated network attacker can enumerate valid `workflowID`s and `(workflowOwner, workflowName, workflowTag)` triples served by a gateway node. It does not by itself grant execution, fund movement, or credential access — `authorizeRequest` still gates the actual `Authorize` call and prevents unauthorized job triggering. The scoped impact matches a low/informational "sensitive data exposure" or "identifier confinement" class rather than a critical auth-bypass, since no privileged action or secret is obtained — only existence/ownership metadata about workflows deployed on that gateway.

### Likelihood Explanation
Highly feasible and repeatable: the attacker only needs network access to the gateway's JSON-RPC endpoint (HTTP or WS) and no credentials at all, since `HandleJSONRPCUserMessage` dispatches straight into `HandleUserTriggerRequest` with no upstream auth gate [1](#0-0) . Submitting `workflows.execute` requests with varying `workflowID`/`workflowOwner`/`workflowName`/`workflowTag` values and observing the JSON-RPC error message (`"Workflow not found..."` vs `"Auth failure: ..."`) is a simple scripted enumeration requiring no rate-limit bypass (rate limiting via `checkRateLimit` only happens after resolution and authorization succeed, so guesses that fail resolution aren't even throttled by the per-workflow limiter) [5](#0-4) .

### Recommendation
Reorder the checks so that workflow-existence information is never revealed prior to authorization, or make both failure paths return an identical, generic error (e.g., always `"Auth failure"` or a uniform "Workflow not found or unauthorized" for both nonexistent and existing-but-unauthorized workflows) regardless of which check failed. Concretely: call `authorizeRequest` using only the caller-supplied selector and signature, and only after a successful signature/credential check reveal a specific "workflow not found" distinction; or normalize `resolveWorkflowID`'s not-found error message/code to be indistinguishable from `authorizeRequest`'s failure message/code.

### Proof of Concept
Go table test in `http_trigger_handler_test.go`:
1. Set up a `httpTriggerHandler` with a `workflowMetadataHandler` containing one known workflow (`ownerA/nameA/tagA` → `workflowID_A`) and no auth keys registered (so `Authorize` will always fail for any caller).
2. Case A: send a `workflows.execute` request with `workflowID = workflowID_A` (exists) and invalid/empty `req.Auth`. Assert the returned JSON-RPC error message is the "Auth failure: ..." message (from `authorizeRequest`).
3. Case B: send a `workflows.execute` request with `workflowID = <random nonexistent id>` and the same invalid/empty `req.Auth`. Assert the returned JSON-RPC error message is "Workflow not found..." (from `resolveWorkflowID`).
4. Assert failure: the test should show that Case A and Case B messages/codes differ (currently `ErrInvalidRequest` with distinct message text in both, but distinguishable substrings "Workflow not found" vs "Auth failure"), proving pre-auth existence is oracle-able.
5. Expected fix state: after remediation, assert both cases return byte-identical error `Message` and `Code` fields regardless of whether `workflowID_A` exists, when `req.Auth` is invalid/missing.

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
