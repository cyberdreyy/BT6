Confirmed: the legacy zip extraction path performs no path containment check at all before writing files.

### Title
Zip Slip path traversal in cache archive extraction allows arbitrary file write outside build directory - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` (and its helpers `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`) use `zip.File.Name` verbatim with `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile(file.Name, ...)`/`os.Symlink`/`os.Mkdir`, with no `filepath.Clean` + prefix-containment check against the intended extraction root. `ExtractZipArchive` only checks for `.git` directory entries via `errorIfGitDirectory`, which is unrelated to path traversal, so a crafted `cache.zip` entry name like `../../etc/passwd` or an absolute path is written wherever it resolves.

### Finding Description
The call chain is: `CacheExtractorCommand.Execute` → `download` (fetches `c.File` from the cache URL) → `openArchive` → `archive.NewExtractor("zip", ...)` → `ziplegacy.NewExtractor` → `extractor.Extract` → `archives.ExtractZipArchive(zr)` [1](#0-0) [2](#0-1) .

Critically, the legacy zip `extractor.Extract` ignores `e.dir` entirely (the `dir` argument passed by `archive.NewExtractor`, intended to be the extraction root/working directory) — it never joins `file.Name` with `e.dir`, and never changes into that directory before calling `archives.ExtractZipArchive` [3](#0-2) . Extraction instead resolves each `file.Name` against whatever the current process working directory happens to be (`os.Getwd()` captured earlier in `Execute`) [4](#0-3) .

Inside `ExtractZipArchive`, the only per-entry validation is `errorIfGitDirectory`, which rejects entries starting with `.git`, and is not a path-traversal or path-containment check [5](#0-4) [6](#0-5) . `extractZipFile` then calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and dispatches based on file mode to `extractZipDirectoryEntry` (`os.Mkdir(file.Name, ...)`), `extractZipSymlinkEntry` (`os.Symlink(target, file.Name)`), or `extractZipFileEntry` (`os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)`) — all using the raw, attacker-controlled `file.Name` with no `filepath.Clean`, no rejection of `..` segments, and no rejection of absolute paths, and no verification that the resolved path stays under the extraction root [7](#0-6) .

Because the underlying `archive/zip` package does not sanitize `File.Name` for you (it merely stores whatever string was written into the central directory of the zip), an attacker who controls the contents of a `cache.zip` — e.g., a pipeline author who crafts a job artifact/cache using a custom tool or archive that writes directly to the zip's central directory with a malicious `Name` field, then has GitLab Runner download and extract it via `gitlab-cache` — can place `../../../../home/gitlab-runner/.ssh/authorized_keys` or `/etc/cron.d/pwn` as an entry name. Fastzip (used behind the `FF_USE_FASTZIP` feature flag) internally validates paths and is not vulnerable to this in the same way, but the legacy zip path (the default, non-feature-flagged behavior) has no such protection.

### Impact Explanation
A successful exploit allows writing/overwriting an arbitrary file on the filesystem where `gitlab-runner` (or the executor extracting the cache, e.g. shell executor on the host) runs the `cache-extractor` helper, with content and permissions controlled by the attacker-supplied zip entry. This breaks the "file operations must stay within intended build/cache/artifact roots" invariant and can lead to remote code execution or persistence (e.g., overwriting shell profile files, cron files, SSH authorized_keys) depending on executor type and directory writability.

### Likelihood Explanation
Preconditions: an attacker with normal CI pipeline authorship privileges must be able to produce a zip file whose central directory contains a malicious `Name` entry (`../` sequences or absolute path), and have this be the object retrieved as the cache archive for a later job run through `CacheExtractorCommand.download`/`openArchive`. This is fully attacker-reachable for any pipeline author who controls cache content (cache keys/paths are attacker-influenced CI config, and cache content bytes are fully job-controlled) — the runner does not need to write a well-formed cache.zip itself; it just needs to be told to download and extract one from wherever the cache is stored, and cache backends generally do not re-validate zip entry structure. This is exploitable on every job run that uses zip-format caches through the legacy zip extractor (default path, not fastzip). The exploit is deterministic and repeatable.

### Recommendation
In `helpers/archives/zip_extract.go` (`extractZipFile`, or a wrapper in `ExtractZipArchive`), validate every `file.Name` before performing filesystem operations: reject absolute paths, `filepath.Clean` the joined path against the extraction root directory, and verify with `strings.HasPrefix`/`filepath.Rel` (checking for no leading `..`) that the resolved path stays inside the root before calling `os.MkdirAll`, `os.OpenFile`, `os.Mkdir`, or `os.Symlink`. Additionally, fix `ziplegacy.extractor.Extract` to actually use `e.dir` (join `file.Name` with `e.dir`, or `os.Chdir(e.dir)` before extracting) so extraction is always scoped to the intended directory rather than the ambient process CWD, matching the behavior expected by `archive.NewExtractorFunc`'s `dir` parameter contract [8](#0-7) .

### Proof of Concept

```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    root := t.TempDir()
    outsideMarker := filepath.Join(root, "..", "zip-slip-poc.txt")
    _ = os.Remove(outsideMarker)

    // Build an in-memory zip with a traversal entry
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, err := zw.Create("../zip-slip-poc.txt")
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    // chdir into root to simulate CacheExtractorCommand.Execute's wd
    oldWd, _ := os.Getwd()
    defer os.Chdir(oldWd)
    require.NoError(t, os.Chdir(root))

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert: file must NOT exist outside root
    _, statErr := os.Stat(outsideMarker)
    assert.True(t, os.IsNotExist(statErr), "zip slip wrote a file outside the extraction root: %s", outsideMarker)
}
```
Expected current (vulnerable) behavior: the test fails because `zip-slip-poc.txt` is created one directory above `root`. After the recommended fix (path containment check), the test should pass, either by erroring out the malicious entry or refusing to write outside `root`.

```go
func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
