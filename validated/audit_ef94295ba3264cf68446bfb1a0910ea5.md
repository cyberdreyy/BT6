### Title
Provenance subjects silently omit symlink/non-regular artifact entries that are still archived and delivered - (File: commands/helpers/artifact_metadata.go)

### Summary
`generateSubjects` filters out any file whose `os.FileInfo.Mode().IsRegular()` is false, but `fileArchiver.add` populates the `files` map using `os.Lstat` (not `os.Stat`), so symlinks matched by a job's artifact `paths:` glob are kept in the map with `os.ModeSymlink` set. The zip archivers (`helpers/archives/zip_create.go`) explicitly serialize symlinks into the delivered archive via `createZipSymlinkEntry`, so the artifact a downstream consumer receives contains entries that the SLSA provenance statement never lists as subjects.

### Finding Description
- `fileArchiver.add` (`commands/helpers/file_archiver.go:127-138`) calls `os.Lstat(path)` and stores the result unconditionally in `c.files[path]`, regardless of file type. A pipeline author fully controls which paths are archived through `artifacts.paths` in `.gitlab-ci.yml`, and can trivially create a symlink inside the build directory before the artifact step runs (e.g. `ln -s /etc/passwd link || ln -s some/other/tracked/file link`) and list it (or its containing glob) as an artifact path.
- `artifactStatementGenerator.generateSubjects` (`commands/helpers/artifact_metadata.go:215-218`) does:
  ```go
  for file, fi := range files {
      if !fi.Mode().IsRegular() {
          continue
      }
      ...
  }
  ```
  This unconditionally drops any non-regular entry (symlinks, and, if ever present, devices/pipes/sockets) from the subject list — silently, with no warning and no error.
- Meanwhile, the actual archive contents are produced by `archive.Archiver.Archive(ctx, c.files)` using the **same** `c.files` map (see `commands/helpers/artifacts_uploader.go:124`, `c.files` passed straight to `archiver.Archive`). For the zip family, `helpers/archives/zip_create.go:52-82` explicitly handles `os.ModeSymlink` via `createZipSymlinkEntry`, meaning the symlink *is* written into the uploaded/delivered artifact zip.
- Consequently, when `GenerateArtifactsMetadata` is enabled, the generated in-toto/SLSA statement (`generateStatementToFile`, `artifact_metadata.go:58-104`) has a `Subject` list that is a strict subset of what is actually shipped in the artifact archive: the symlink entry is present in the artifact but absent from the attested subjects.
- No existing check compensates for this: there's no equality/count assertion between `len(subjects)` and `len(files)` before writing the statement, and no filtering of symlinks out of the archive before hashing subjects (the two paths — subject generation and archiving — diverge only in `generateSubjects`).

### Impact Explanation
This breaks the stated invariant "every archived artifact file must be faithfully represented as a subject; no silent omission." A downstream consumer (or a policy engine, e.g. an in-toto/SLSA verifier gating artifact promotion) that trusts the provenance statement to enumerate everything in the artifact will not see the symlink entry, yet it is delivered as part of the artifact bundle. This enables a job author to smuggle content into the delivered artifact (a symlink, whose target may resolve to unexpected content at consumption time, or whose mere presence is unaccounted for) that bypasses attestation-based integrity checks — i.e., an artifact-poisoning / attestation-mismatch scenario as scoped.

### Likelihood Explanation
Fully attacker-reachable with a normal, unprivileged pipeline: any `.gitlab-ci.yml` author can create a symlink in the job workspace and reference it via `artifacts:paths`. No special runner configuration, executor privilege, or admin action is required — only that `--generate-artifacts-metadata` (artifact metadata generation) is enabled for the job, which is a standard, non-privileged feature. The bug is deterministic and 100% reproducible (`fi.Mode().IsRegular()` is false for every symlink `os.Lstat` returns).

### Recommendation
Make subject generation and archival consistent for non-regular files:
- Either resolve symlinks before deciding archive membership and reject/skip symlink artifacts consistently in both `fileArchiver`/archivers and `generateSubjects` (fail closed), or
- Change `generateSubjects` to include a resolved-target hash/subject for symlink entries (and any other non-regular type the archiver actually serializes), so subject count always matches archived entry count, or
- Add a hard invariant check in `generateStatementToFile`: after computing `subjects`, compare the count of subjects to the count of regular *and non-regular-but-archived* entries in `opts.files`, and fail the job (return an error) if they don't match, rather than silently truncating the subject list.

### Proof of Concept
```go
func TestGenerateSubjects_OmitsSymlinkPresentInArchive(t *testing.T) {
    dir := t.TempDir()
    regular := filepath.Join(dir, "real.txt")
    require.NoError(t, os.WriteFile(regular, []byte("data"), 0o644))

    link := filepath.Join(dir, "link.txt")
    require.NoError(t, os.Symlink(regular, link))

    regFi, err := os.Lstat(regular)
    require.NoError(t, err)
    linkFi, err := os.Lstat(link)
    require.NoError(t, err)

    files := map[string]os.FileInfo{
        regular: regFi,
        link:    linkFi,
    }

    g := &artifactStatementGenerator{}
    subjects, err := g.generateSubjects(files)
    require.NoError(t, err)

    // Bug: archive.Archive(ctx, files) via the zip archiver WILL include both
    // entries (regular file + symlink, see helpers/archives/zip_create.go),
    // but generateSubjects silently drops the symlink.
    assert.Len(t, subjects, 1, "subjects should match archived entry count")
    assert.Len(t, files, 2, "archiver will serialize both entries into the artifact")
    // This demonstrates subjects(1) != archived entries(2) — attestation mismatch.
}
```

func (g *artifactStatementGenerator) generateSubjects(files map[string]os.FileInfo) ([]*ita_v1.ResourceDescriptor, error) {
	subjects := make([]*ita_v1.ResourceDescriptor, 0, len(files))

	h := sha256.New()
	br := bufio.NewReader(nil)
	subjectGeneratorFunc := func(file string) (*ita_v1.ResourceDescriptor, error) {
		f, err := os.Open(file)
		if err != nil {
			return &ita_v1.ResourceDescriptor{}, err
		}
		defer f.Close()

		br.Reset(f)
		h.Reset()
		if _, err := io.Copy(h, br); err != nil {
			return &ita_v1.ResourceDescriptor{}, err
		}

		return &ita_v1.ResourceDescriptor{
			Name:   file,
			Digest: map[string]string{"sha256": hex.EncodeToString(h.Sum(nil))},
		}, nil
	}

	for file, fi := range files {
		if !fi.Mode().IsRegular() {
			continue
		}

		subject, err := subjectGeneratorFunc(file)
		if err != nil {
			return nil, err
		}

		subjects = append(subjects, subject)
	}

	return subjects, nil

func createZipSymlinkEntry(archive *zip.Writer, fh *zip.FileHeader) error {
	fw, err := archive.CreateHeader(fh)
	if err != nil {
		return err
	}

	link, err := os.Readlink(fh.Name)
	if err != nil {
		return err
	}

	_, err = io.WriteString(fw, link)
	return err
}

func createZipEntry(archive *zip.Writer, fileName string) error {
	fi, err := os.Lstat(fileName)
	if err != nil {
		logrus.Warningln("File ignored:", err)
		return nil
	}

	fh, err := zip.FileInfoHeader(fi)
	if err != nil {
		return err
	}
	fh.Name = fileName
	fh.Extra = createZipExtra(fi)
	// Set EFS flag to indicate that filenames and comments are UTF-8 encoded
	fh.Flags |= 0x800

	switch fi.Mode() & os.ModeType {
	case os.ModeDir:
		return createZipDirectoryEntry(archive, fh)

	case os.ModeSymlink:
		return createZipSymlinkEntry(archive, fh)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningln("File ignored:", fileName)
		return nil

	default:
		return createZipFileEntry(archive, fh)
	}
