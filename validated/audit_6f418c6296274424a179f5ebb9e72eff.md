### Title
Cross-user response hijack via unvalidated `MessageId` collisions in legacy WebAPI trigger handler's `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`gateway.ProcessRequest` only bounds `jsonRequest.ID` length (≤200 chars) and never checks uniqueness against other in-flight requests [1](#0-0) . The legacy `capabilities` WebAPI-trigger handler stores pending callbacks in `savedCallbacks` keyed only by `msg.Body.MessageId`, with no check that the ID is not already in use, unlike the newer `v2/http_trigger_handler.go` which explicitly rejects reused IDs [2](#0-1) . Two concurrent legacy requests to the same DON/service with the same `MessageId` (one from a victim, one from an unrelated attacker) collide in the same map, letting an attacker silently steal the DON's response intended for the victim.

### Finding Description
`gateway.ProcessRequest` decodes the incoming request, validates only `len(jsonRequest.ID) <= 200`, and routes it to a handler based on service name/DON ID before invoking `HandleLegacyUserMessage` or `HandleJSONRPCUserMessage` with a fresh `handlerscommon.NewCallback()` [3](#0-2) . There is no gateway-level tracking of in-flight IDs across concurrent calls.

Inside `capabilities/handler.go`, `HandleLegacyUserMessage` unconditionally stores the callback under the raw `MessageId` with no existence check: [4](#0-3) 

When a node's response arrives via `HandleNodeMessage` → `handleWebAPITriggerMessage`, it is dispatched to whatever `savedCallbacks[msg.Body.MessageId]` currently holds, and the entry is deleted so only "the first response" is delivered: [5](#0-4) 

The only sender-related check on the node response path is `msg.Body.Sender != nodeAddr`, which validates the *node's* identity, not that the response correlates to the correct original *user* request: [6](#0-5) 

Exploit flow: an attacker who knows/observes a victim's `MessageId` sends a concurrent, independently and validly-signed legacy request (their own request, not impersonating the victim) to the same DON/service with the identical `MessageId`, method `web_api_trigger`. If the attacker's `HandleLegacyUserMessage` call runs after the victim's but before the DON node responds, it overwrites `h.savedCallbacks[id]` with the attacker's own `Callback`. When the legitimate node response for that ID arrives, `handleWebAPITriggerMessage` delivers it to whichever callback is currently stored (the attacker's), and the victim's original callback is orphaned — it will simply hang until pruned by `pruneCallbacks` (`defaultCallbackMaxAgeSec` = 120s) or until the gateway's own request timeout fires, receiving `api.RequestTimeoutError` instead of the real answer. The attacker thus receives the response payload intended for the victim.

This is scoped to requests handled by the same handler instance (same DON/service), since `savedCallbacks` is per-`handler` struct; it does not cross into a literally different service's handler map. But within a single WebAPI-trigger DON, no component enforces `MessageId` uniqueness across concurrently in-flight requests from different, unrelated callers.

### Impact Explanation
An unauthenticated (or minimally-authenticated) caller of the gateway's WebAPI-trigger endpoint can hijack another user's response payload for that request by predicting or observing the victim's request ID and racing a colliding request to the same DON. This is a cross-user response confusion / unauthorized disclosure of another user's data returned by the DON, matching the "cross-user response hijack" bounty impact class.

### Likelihood Explanation
Exploitability requires: (1) knowledge of the victim's exact `MessageId` for an in-flight request (client-chosen strings, often predictable/sequential, or observable through client-side logs, shared UI, or interception), (2) the ability to send a validly signed/well-formed request to the same DON/service, and (3) a timing race to overwrite the map entry before the legitimate node response arrives. No special privilege beyond being any regular gateway user is needed. This is a real race condition but requires the collision to hit before the (typically fast) DON round-trip completes, making it feasible but timing-sensitive and repeatable via automated concurrent requests.

### Recommendation
Enforce request-ID uniqueness before storing a new callback, mirroring the check already present in `v2/http_trigger_handler.go`'s `setupCallback`: in `HandleLegacyUserMessage` (and analogous `HandleJSONRPCUserMessage` paths in `capabilities/handler.go`), check `if _, found := h.savedCallbacks[msg.Body.MessageId]; found` and reject the new request (e.g., with a conflict error) instead of overwriting the existing entry. Consider also enforcing this centrally in `gateway.ProcessRequest` to protect all handlers consistently.

### Proof of Concept
Go test plan (`core/services/gateway/handlers/capabilities/handler_test.go`):
1. Set up the handler with a mocked DON (`don.SendToNode` no-op) as in existing tests (`setupHandler`).
2. Fire `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCallback)` with `MessageId = "shared-id"`.
3. Immediately fire `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCallback)` with the same `MessageId = "shared-id"` (different payload/sender) before any node response arrives.
4. Assert `handler.savedCallbacks["shared-id"]` now references `attackerCallback`, not `victimCallback` (current behavior — no rejection).
5. Simulate the DON node response via `handler.HandleNodeMessage(ctx, resp, nodeAddr)` with `resp.ID = "shared-id"`.
6. Assert `attackerCallback.Wait(ctx)` returns the DON's response payload, while `victimCallback.Wait(ctx)` times out / never receives a response — demonstrating the hijack.
7. After applying the recommended fix, re-run and assert the second `HandleLegacyUserMessage` call returns a conflict error and `victimCallback` still correctly receives the DON's response.

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	var isLegacyRequest = false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonId == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonId
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
	if err != nil {
		return newError(jsonRequest.ID, api.HandlerError, err.Error())
	}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
