## Title
Unprivileged operator can force-inactivate delegators' `pending_inactive` stake via `join_validator_set`, bypassing `delegation_pool` commission accounting and OLC bookkeeping - (File: `aptos-move/framework/aptos-framework/sources/stake.move`)

### Summary
`stake::join_validator_set_internal` contains logic that directly merges all `pending_inactive` coins into `inactive` whenever the pool's lockup has expired and the operator rejoins the validator set: [1](#0-0) 

This mutation of `StakePool.pending_inactive`/`inactive` happens entirely inside `stake.move`, invoked by the pool's **operator** (an unprivileged, non-owner role that only needs `ENOT_OPERATOR` authorization), and completely bypasses `delegation_pool::synchronize_delegation_pool`, which is the only code path that is supposed to reconcile stake-pool level state changes with the delegation pool's per-lockup-cycle share accounting (`observed_lockup_cycle`, `pending_inactive_shares_pool`, `total_coins_inactive`, and operator commission on `pending_inactive`).

### Finding Description
`delegation_pool::calculate_stake_pool_drift` is the single place that detects lockup-cycle-ended and computes the operator's commission share of unresolved `pending_inactive` rewards, by comparing the *live* stake-pool amounts obtained from `stake::get_stake` against the pool's internally tracked `pending_inactive_shares_pool` totals: [2](#0-1) 

and `synchronize_delegation_pool` uses the same drift detection to decide whether to advance `observed_lockup_cycle` and to capture `total_coins_inactive`: [3](#0-2) 

The normal, expected path for `pending_inactive → inactive` migration is `stake.move`'s epoch-transition logic (`update_stake_pool`/`distribute_rewards`), which is followed at the next epoch boundary, after which the delegation pool operator (or anyone) is expected to call `synchronize_delegation_pool` to settle commission and advance the OLC: [4](#0-3) 

However, `join_validator_set_internal` performs the *identical* inactivation merge independently, gated only on `stake_pool.locked_until_secs` having passed, and is callable at will by the pool's operator via the public entry function `join_validator_set`: [5](#0-4) 

Because this merge happens without going through `calculate_stake_pool_drift`, an operator can trigger it *before* anyone calls `synchronize_delegation_pool`. When `synchronize_delegation_pool` is finally invoked afterward, `stake::get_stake` will already report `pending_inactive == 0` and an inflated `inactive` balance, so:
- `commission_pending_inactive` is computed against a `pending_inactive` value that has already been zeroed out, meaning any operator commission that was owed on delegators' unlocked-but-uninactivated rewards can be silently dropped (`pending_inactive > pool_pending_inactive` becomes false because `pending_inactive` is already 0), and
- the delegation pool's own accounting of `pending_inactive_shares_pool` (whose `total_coins` still reflects the pre-merge amount) is now permanently desynchronized from the stake pool's actual `pending_inactive` balance (which is 0), corrupting share-to-coin conversions for any delegator who still holds shares in that shares pool (e.g., `redeem_inactive_shares`, `withdraw_internal`, `get_pending_withdrawal`) until an OLC advance eventually reconciles it - and in the interim those balances/withdrawal computations use inconsistent totals.

The project's own test suite acknowledges this precise sequence occurs ("no rewards yet; expired pending_inactive was inactivated at join time"): [6](#0-5) 

confirming that `stake::join_validator_set` can move delegator `pending_inactive` funds into `inactive` outside of the delegation-pool-aware, commission-preserving path, purely under the control of the operator role (who does not own the underlying stake and has no authority over commission/accounting invariants).

### Impact Explanation
This breaks the "Accounting across active/pending_active/pending_inactive/inactive, rewards, and commission state must preserve value and withdrawal rights" invariant and the "unlock/reactivate/withdraw/synchronize paths must not redirect value or strand it permanently" invariant. An operator (not the owner, not a delegator) can unilaterally force the `pending_inactive → inactive` transition for the entire pool's unlocking stake at a time of their choosing (any time after `locked_until_secs` has elapsed but before anyone synchronizes the delegation pool), which can cause operator commission on `pending_inactive` rewards to be dropped/miscalculated and desynchronizes delegation-pool share-pool totals from actual on-chain balances, corrupting withdrawal/commission accounting for delegators sharing that OLC's `pending_inactive_shares_pool`.

### Likelihood Explanation
High likelihood: the trigger condition (`locked_until_secs` already expired, validator currently `INACTIVE`) is a normal, common state for delegation pools whose validator has left the set, and `join_validator_set` is a standard, permissionless-to-the-operator-role entry function that operators call routinely to rejoin. No special privilege beyond being the pool's registered operator is required, and the operator does not need to coordinate with or have permission from the staker/delegators to trigger it.

### Recommendation
Remove the ad hoc `pending_inactive → inactive` settlement from `join_validator_set_internal`, or require it to route through the same drift-aware reconciliation as `synchronize_delegation_pool`/`calculate_stake_pool_drift` (or force-call `synchronize_delegation_pool` first) so that commission and share-pool totals are always updated atomically with any inactivation of `pending_inactive` stake, and so a delegation pool can never observe `pending_inactive` become 0 outside of a properly-detected `lockup_cycle_ended` transition.

### Proof of Concept
1. Staker creates a `staking_contract`/`delegation_pool` with operator `O` and delegator `D`.
2. `D` calls `unlock` to move stake into `pending_inactive`.
3. Validator (operator `O`) leaves the validator set (`leave_validator_set`), and lockup subsequently expires (`locked_until_secs` passed) - validator is now `INACTIVE`, as demonstrated in the existing test flow.
4. `O` calls `join_validator_set(operator, pool_address)` (a permissionless-to-operator entry function). Per `join_validator_set_internal` lines 1096-1109, this immediately merges all `pending_inactive` into `inactive`, *before* `synchronize_delegation_pool` is called by anyone.
5. `synchronize_delegation_pool` is now called: `calculate_stake_pool_drift` observes `pending_inactive == 0` from `stake::get_stake`, so `commission_pending_inactive` is computed as `0` regardless of rewards that had accrued on that pending_inactive stake, and the delegation pool's `pending_inactive_shares_pool` total (still reflecting pre-merge coin totals) is now stale relative to the stake pool's actual (zeroed) `pending_inactive` balance until the OLC advances - exactly matching the state asserted in the existing test at lines 3213-3221 of `delegation_pool.move`. [6](#0-5)
