### Title
Stale confirmations from removed multisig members are counted toward `num_confirmations`, allowing request execution with fewer than the required live-member confirmations - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` decides execution by comparing `confirmations.len() as u32 + 1 >= self.num_confirmations`, where `confirmations` is a `HashSet<String>` of confirmer identities that is never re-validated against the current `self.members` set. `MultiSigContract::delete_member` only purges requests *originated* by the removed member, not confirmations the removed member left on requests originated by others, so a stale confirmation persists and inflates the count as if it came from a still-current member.

### Finding Description
The invariant the contract must uphold is:
`confirmations.len() == |{ c ∈ confirmations : c is a current element of self.members }|`

i.e. every string stored in the `confirmations: LookupMap<RequestId, HashSet<String>>` set for a request must correspond to an account/key that is still in `self.members` at the moment `confirm` evaluates the threshold.

Tracing the code:
- `confirm` [1](#0-0)  only checks that the *current caller* is a member (`current_member()` via `assert_valid_request`), then reads the stored `confirmations` set and compares `confirmations.len() as u32 + 1 >= self.num_confirmations` — it never re-checks that the previously stored confirmer strings are still members.
- `current_member` [2](#0-1)  gates who can add a fresh confirmation, but does nothing about entries already sitting in the `HashSet`.
- `delete_member` [3](#0-2)  removes outstanding requests where `r.member == member` (i.e., requests the removed member *created*) and clears `num_requests_pk` for that member, but it does **not** scan `self.confirmations` to strip that member's confirmation from requests created by someone else.
- `remove_request` [4](#0-3)  only clears confirmations for the one request being executed/deleted.

Exploit flow (attacker is a legitimate but non-sole member of a shared multisig, e.g. members A, B, Attacker, D, `num_confirmations = 3`):
1. A calls `add_request` to create request R1 (e.g., `Transfer` to Attacker's own account).
2. B calls `confirm(R1)` → `confirmations = {B}` (len 1, < 3, stored not executed).
3. Attacker calls `confirm(R1)` → `confirmations = {B, Attacker}` (len 2, < 3, stored not executed).
4. Separately, the group approves a `DeleteMember { member: Attacker }` request, removing Attacker from `self.members`. This clears requests *created by* Attacker and their `num_requests_pk` entry, but R1's `confirmations = {B, Attacker}` is untouched.
5. D later calls `confirm(R1)`: `confirmations.len() as u32 + 1 == 3 >= num_confirmations(3)` → `execute_request` fires and the `Transfer` promise is scheduled to Attacker's account, even though only B and D are actually current members who confirmed — Attacker's stale confirmation counted despite no longer being a member.

None of the existing guards prevent this: `assert_valid_request` only checks the caller of the current transaction, not the historical confirmers stored in the set; `delete_member`'s cleanup is scoped to requests *authored* by the removed member, not requests they merely confirmed.

### Impact Explanation
This directly matches the enumerated Critical impact "a multisig request executed below `num_confirmations` live members." Funds (NEAR held by the multisig account) can leave the account via a `Transfer`/`FunctionCall`/`AddKey` action approved by a confirmation count that includes a party no longer entitled to vote, effectively lowering the real signing threshold below what the remaining members configured and trusted. This is repeatable for every pending request that a member confirmed prior to being removed, and for every multisig deployed with this contract code.

### Likelihood Explanation
Preconditions: a multisig with more than `num_confirmations` members, an outstanding request confirmed by a member who is later removed via a legitimate `DeleteMember` action (a routine operational event — offboarding a signer, rotating keys, etc.), and one more live confirmation to cross the threshold. No special privilege beyond ordinary membership (which any of the multisig's own participants — including an attacker who is a normal, non-controlling signer — already has) is required, and the flaw is triggered purely by ordinary contract usage/timing, making it highly feasible and repeatable in any long-lived multisig using this contract.

### Recommendation
When evaluating the threshold in `confirm`, filter `confirmations` to only those entries still present in `self.members` before comparing against `num_confirmations` (or equivalently, purge/validate confirmer entries whenever `self.members` changes, e.g. in `delete_member`, by scanning all pending requests' confirmation sets and removing entries for the deleted member).

### Proof of Concept
`cargo test` plan (unit test in `multisig2/src/lib.rs`, using existing `testing_env!`/`VMContextBuilder` helpers already in the file's `#[cfg(test)]` module):
1. Build a `MultiSigContract` with 4 members (A, B, C-as-"attacker", D) and `num_confirmations = 3`.
2. As A, `add_request` a `Transfer` request R1.
3. As B, `confirm(R1)` — assert `c.confirmations.get(&R1).unwrap().len() == 1`.
4. As C, `confirm(R1)` — assert `c.confirmations.get(&R1).unwrap().len() == 2`.
5. As a quorum of A/B/D, `add_request_and_confirm`/`confirm` a `DeleteMember { member: C }` request until it executes; assert `c.get_members()` no longer contains C.
6. Assert (the broken binding, LHS vs RHS) that `c.confirmations.get(&R1).unwrap().len() == 2` still includes C's identity while `c.get_members()` excludes C — i.e. `confirmations.len()` ≠ number of entries in `confirmations` that are also in `c.get_members()`.
7. As D, `confirm(R1)` and assert the request executes (`c.requests.len() == 0`) despite only B and D being live members who confirmed — demonstrating execution below the live-member threshold.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
