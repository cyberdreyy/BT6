### Title
Cross-user response hijacking via attacker-chosen `MessageId` collision in gateway legacy web-API-trigger handler - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The legacy gateway capabilities handler stores per-request callbacks in a single map keyed only by the client-supplied `MessageId` (which is simply the JSON-RPC request `ID`), with no binding to the sender/signer of the request. Any unprivileged client can choose an arbitrary `MessageId`, so two independent, differently-authenticated requests that happen to share the same ID collide in this shared map, letting one requester's response be captured by another requester's callback.

### Finding Description
`ValidatedMessageFromReq` sets `m.Body.MessageId = req.ID` directly from the caller-supplied JSON-RPC request ID with no server-side uniqueness enforcement: [1](#0-0) 

`Message.Validate()` only checks length/format of `MessageId`, not its relationship to the sender: [2](#0-1) 

In `handler.HandleLegacyUserMessage`, the callback for the *current* caller is stored into the single shared `h.savedCallbacks` map keyed purely by this attacker-controlled `MessageId`, overwriting any prior entry with the same key: [3](#0-2) 

When a DON node later responds with the trigger result, `handleWebAPITriggerMessage` looks the callback back up strictly by `MessageId`, deletes it, and forwards the response to whichever callback is currently stored under that key: [4](#0-3) 

This is structurally analogous to the OpenQ bug class: an unprivileged actor supplies a value (there: a malicious ERC20 token address; here: a colliding `MessageId`) into a shared resource (there: the bounty's token list; here: the gateway's global `savedCallbacks` map) that is consumed on behalf of other, legitimate participants without per-participant isolation, corrupting the outcome for a party that did nothing wrong.

### Impact Explanation
If Attacker A submits a `web_api_trigger` request with `MessageId = "X"` immediately after (or racing) legitimate User B's request that also uses `MessageId = "X"` (predictable or guessed IDs, or a client library that doesn't randomize IDs strongly), A's entry overwrites B's in `savedCallbacks`. When the DON node subsequently responds to `X`, that response — which may contain B's trigger result/execution payload — is delivered to A's callback instead of B's. Conversely, B's callback is silently orphaned and never resolves for its own request. This is a cross-user response confusion vulnerability: it can leak another user's response data to an attacker and cause silent request loss for the legitimate user, without breaking any signature check (each request is independently, validly signed by its own sender — signature validation confirms *who signed*, not that the ID was exclusive to them).

### Likelihood Explanation
Exploitability depends on `MessageId` collision, which is entirely attacker-controlled (`req.ID` is chosen by the caller with no server-enforced uniqueness or per-sender namespacing) and only needs to match another in-flight request within the callback lifetime (`CallbackMaxAgeSec`, default 120s). An attacker who can observe or predict another party's chosen ID (e.g., low-entropy/sequential IDs used by some clients, or by simply always sending `MessageId="1"`/a fixed ID and waiting to win the race against victims using default/predictable IDs) has a straightforward path to trigger the collision. This requires no privileged access — just the ability to call the gateway's public trigger endpoint.

### Recommendation
Namespace `savedCallbacks` (and the lookup key sent to/matched against node responses) by both `MessageId` and the sender's verified identity (e.g., key on `(Sender, MessageId)` or embed the sender/signature-derived address into the internally used key), so a collision in the client-chosen `MessageId` field cannot cause one user's saved callback/response to be overwritten or claimed by another user.

### Proof of Concept
1. Legitimate User B sends a signed `web_api_trigger` JSON-RPC request with `id="X"` to the gateway; the handler stores `savedCallbacks["X"] = B's callback` and forwards the message to all DON nodes.
2. Before a node responds, Attacker A sends a separately signed `web_api_trigger` request also using `id="X"`; the handler overwrites `savedCallbacks["X"] = A's callback`.
3. A DON node completes B's original request and replies with `MessageId="X"`; `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds A's callback, deletes the entry, and sends B's response payload to A.
4. B's callback is never invoked and times out/receives nothing, while A receives B's response data. [4](#0-3) [3](#0-2)

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
