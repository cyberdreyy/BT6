### Title
Unauthenticated-role GET `/v2/external_initiators` leaks all External Initiators' `AccessKey` and `OutgoingToken` to any authenticated token (including run-role) - ([File: core/web/router.go])

### Summary
The route `GET /v2/external_initiators` is registered in the `authv2` group with only the generic `auth.Authenticate` middleware and no `auth.RequiresEditRole`/`RequiresViewRole` wrapper, unlike the sibling `POST`/`DELETE` routes on the same resource. The handler `ExternalInitiatorsController.Index` returns `presenters.ExternalInitiatorResource`, which embeds the plaintext `AccessKey` and `OutgoingToken` for every external initiator in the system, so any authenticated caller — including a run-role API token — can dump this credential material.

### Finding Description
In `core/web/router.go`, all other mutating routes for `/v2/external_initiators` are role-gated: [1](#0-0) 
but the `GET` route is left unwrapped, relying solely on the `authv2` group's `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)` middleware, which accepts any valid session or API token regardless of role.

The handler `ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go`) fetches all external initiators and maps them via `presenters.NewExternalInitiatorResource`: [2](#0-1) 

The presenter struct includes both `AccessKey` (the EI's incoming access key, used to authenticate EI-originated webhook calls into the node) and `OutgoingToken` (used by the node to authenticate itself when calling out to the EI): [3](#0-2) 

Note: `OutgoingSecret` and the incoming `Secret` are *not* included in `ExternalInitiatorResource` (only `ExternalInitiatorAuthentication`, used solely in `Create`'s response, includes those) — so the "OutgoingSecret" disclosure claim in the question is not accurate for this endpoint. However, `AccessKey` and `OutgoingToken` are genuinely disclosed and are themselves credential material: `AccessKey` is the EI's authentication key for triggering job runs via `POST /v2/webhook/:name`, and `OutgoingToken` is a secret the node uses to authenticate itself to the EI's callback endpoint.

Because no role check is applied to `Index`, a token with only the `run` role — which the router elsewhere restricts to job-run-triggering endpoints (`auth.RequiresRunRole` on `/replay_from_block`, `/find_lca`, `/jobs/:ID/runs`) — can call `GET /v2/external_initiators` and receive `AccessKey`/`OutgoingToken` for every configured external initiator.

### Impact Explanation
This corresponds to Chainlink's "sensitive data exposure/credential disclosure" bounty class. A run-role token holder gains disclosure of `AccessKey` values, which could be replayed to impersonate an external initiator and trigger `POST /v2/webhook/:name` job runs it was not authorized to invoke, and `OutgoingToken` values that authenticate the node to external systems, enabling forged outbound-call impersonation. The impact is confined to EI credential leakage and downstream job-triggering abuse; it does not directly disclose EI `OutgoingSecret`/incoming `Secret` since those aren't in this presenter.

### Likelihood Explanation
Exploitation only requires possessing any valid API token or session cookie, including one restricted to the `run` role — a low privilege level that the system's own role model (`RequiresRunRole` used elsewhere) treats as far more limited than edit/admin. The call is a single unauthenticated-role `GET` request; no rate limiting beyond the standard authenticated limiter applies, and the endpoint is fully reachable and repeatable.

### Recommendation
Wrap `GET /v2/external_initiators` with `auth.RequiresEditRole` (or at minimum `auth.RequiresViewRole` if such exists) consistent with the `POST`/`DELETE` handlers for the same resource in `core/web/router.go` line 264, and/or strip `AccessKey`/`OutgoingToken` from `presenters.ExternalInitiatorResource` for listing purposes, exposing only non-secret metadata (name, URL, timestamps) to lower-privileged roles.

### Proof of Concept
1. In a Go handler-integration test (extending `core/web/external_initiators_controller_test.go`), create an application with a run-role API token via `cltest`.
2. Seed one or more external initiators via `BridgeORM().CreateExternalInitiator`.
3. Issue `client.Get("/v2/external_initiators?size=50")` authenticated with the run-role token.
4. Assert HTTP 200 (not 401/403) is returned.
5. Parse the JSON:API response into `[]presenters.ExternalInitiatorResource` and assert that `AccessKey` and `OutgoingToken` fields are non-empty and match the seeded values, demonstrating the run-role token received credential material intended for edit/admin-level access only.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
