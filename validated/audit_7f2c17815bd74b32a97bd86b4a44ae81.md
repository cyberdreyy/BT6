### Title
AuditLogger.Headers (including Authorization/API-key values) is embedded verbatim and unredacted in `ConfigController.Show` output, exposing third-party credentials to any authenticated user regardless of role - ([File: core/web/config_controller.go])

### Summary
`ConfigController.Show` returns the full effective/user TOML via `chainlink.GeneralConfig.ConfigTOML()` with no field-level redaction, and the `AuditLogger.Headers` field (a `[]models.ServiceHeader`, e.g. `Authorization: <token>`) is serialized as plain text into that TOML. The route `/v2/config/v2` (and `/v2/config`) is registered under `authv2` with only session/token authentication and no role check, so any authenticated user — including the lowest-privilege "view" role — can read admin-configured secrets such as audit-log webhook bearer tokens.

### Finding Description
`core/web/config_controller.go` `ConfigController.Show` calls `cfg.ConfigTOML()` and returns the resulting TOML string verbatim in the JSON:API response, choosing between `user` and `effective` TOML based on the `userOnly` query parameter [1](#0-0) .

The `AuditLogger` struct in `core/config/toml/types.go` stores `Headers *[]models.ServiceHeader` as part of the regular `Config` (not `Secrets`), and `ServiceHeader.MarshalText` serializes it as `"<Header>: <Value>"` [2](#0-1) [3](#0-2) . A repo test explicitly confirms an `Authorization: token` header round-trips into TOML output unredacted: `Headers = ['Authorization: token', 'X-SomeOther-Header: value with spaces | and a bar+*']` [4](#0-3) .

`generalConfig.ConfigTOML()` simply returns the previously-marshaled `inputTOML`/`effectiveTOML` strings without any redaction step [5](#0-4) .

Route-wise, `/v2/config` and `/v2/config/v2` are mounted in the `authv2` group, which requires only `auth.Authenticate` (token or session) — unlike other admin-sensitive routes in the same file that are wrapped with `auth.RequiresAdminRole`/`auth.RequiresEditRole`/`auth.RequiresRunRole` [6](#0-5) . `ConfigController.Show` itself performs no role check at all. This means any authenticated node user (including the minimal "view" role) can hit this endpoint and receive the admin's configured `AuditLogger.Headers` value — e.g. a bearer token used to authenticate to the audit-log ingestion webhook — in cleartext.

### Impact Explanation
This matches the Chainlink bounty "secret/credential disclosure" impact class: a low-privileged, non-admin authenticated user can exfiltrate a third-party service credential (e.g., audit log webhook `Authorization` bearer token) that the node admin configured and did not intend to share with all users. This credential could be used to impersonate the node's audit stream to a third-party service or pivot further if the token is reused elsewhere.

### Likelihood Explanation
Preconditions: an admin must have configured `AuditLogger.Headers` with a sensitive value (a documented, common practice for authenticating to log-forwarding endpoints), and an attacker needs any valid, low-privilege API token/session (view-role) for the node. Given the endpoint requires no role check beyond authentication, exploitation is a single unauthenticated-to-the-config-content GET request from any authenticated account, making it highly feasible and fully repeatable.

### Recommendation
Redact sensitive fields (in particular `AuditLogger.Headers`, and any other header/URL/API-key-bearing fields) before serialization in `ConfigTOML()`/`TOMLString()`, or restrict `/v2/config` and `/v2/config/v2` to admin-only role via `auth.RequiresAdminRole` in `core/web/router.go`. Preferably do both: apply presenter-level redaction (mask header values, similar to how `Secrets` are redacted) and restrict the endpoint to admin/edit roles only.

### Proof of Concept
1. In a Go test analogous to `TestRendererTable_RenderConfigurationV2` (`core/cmd/renderer_test.go`), configure the app with:
```toml
[AuditLogger]
Enabled = true
ForwardToUrl = 'http://localhost:9898'
Headers = ['Authorization: Bearer super-secret-webhook-key']
```
2. Create a client authenticated only with a "view" role API token (not admin/edit).
3. Call `GET /v2/config/v2` and `GET /v2/config/v2?userOnly=true`.
4. Assert (current behavior, demonstrating the bug): response body contains the literal string `Authorization: Bearer super-secret-webhook-key` in both `effective` and `user` TOML.
5. Expected secure behavior (post-fix): the header value should be redacted (e.g., `Authorization: xxxxx`) or the request should be rejected with `403 Forbidden` for non-admin roles.

```go
func (cc *ConfigController) Show(c *gin.Context) {
	cfg := cc.App.GetConfig()
	var userOnly bool
	if s, has := c.GetQuery("userOnly"); has {
		var err error
		userOnly, err = strconv.ParseBool(s)
		if err != nil {
			jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("invalid bool for userOnly: %w", err))
			return
		}
	}
	var toml string
	user, effective := cfg.ConfigTOML()
	if userOnly {
		toml = user
	} else {
		toml = effective
	}
	jsonAPIResponse(c, ConfigV2Resource{toml}, "config")
```
