### Title
Post-default instant-withdraw requests alias the defaulted epoch index and drain `defaultRecoveryReserve` - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
The external report (CVE-2017-6209) is an out-of-bounds array access driven by attacker-controlled parser input — an index that lands on storage belonging to a different logical object. The closest analog in `IdleCreditVault` is epoch-indexed receipt accounting: `requestInstantWithdraw` writes a brand-new receipt into `instantWithdrawsRequestsByEpoch[user][epochNumber]`, and after `finalizeDefaultRecovery` the current `epochNumber` still equals `defaultRecoveryEpoch`. A post-default request therefore aliases the defaulted epoch's index, and `claimInstantWithdrawRequest` pays it out of `defaultRecoveryReserve` at `defaultRecoveryPrice` — reserve that was sized only for pre-finalization claimants.

### Finding Description
At finalization, `finalizeDefaultRecovery` fixes `defaultRecoveryPrice`, `defaultRecoveryEpoch = epochNumber`, and `defaultRecoveryReserve = recovered + prefunded + prior reserve`, with `totalBasis` including only receipts that existed at that moment (lines 679–708).

`requestInstantWithdraw` has no `defaultRecoveryFinalized` guard (unlike `requestWithdraw`, which branches on it at line 247). A new post-default request mints the receipt and executes: [1](#0-0) 

Since `epochNumber` is only incremented inside `deposit()` when the epoch is running (lines 607–610) — a path unreachable while the CDO is defaulted — `currentEpoch == defaultRecoveryEpoch`, so the attacker's fresh basis is stored under the exact index used by `_claimDefaultedInstantWithdrawRequest`: [2](#0-1) 

`claimInstantWithdrawRequest` (lines 380–393) then routes through `defaultRecoveryFinalized && defaultInstantWithdrawsFinalized`, reads `instantWithdrawsRequestsByEpoch[user][defaultRecoveryEpoch]` — which now includes the attacker's new basis — and pays `(claimBasis * defaultRecoveryPrice) / 1e18` via `_transferDefaultRecovery`, which decrements `defaultRecoveryReserve` directly (lines 912–917).

The broken invariant is the OOB-equivalent "one index, one owner": the defaulted-epoch slot was finalized with a fixed `totalBasis`, but post-default writes keep mutating the same slot, letting new claims consume a reserve they were never priced into.

### Impact Explanation
Direct theft of unclaimed recovery. `defaultRecoveryReserve` is fixed at finalization; every defaulted-claim payout decrements it. An attacker who places a post-default instant-withdraw request of `N` receives `N * defaultRecoveryPrice / 1e18` from that reserve before legitimate claimants call `claimInstantWithdrawRequest`. Once the reserve is drained, honest claimants' `_transferDefaultRecovery` underflows (`defaultRecoveryReserve -= _amount`), so their claims permanently revert. Quantified loss: `min(attackerBasis × recoveryPrice, remaining reserve)`, up to the entire reserve.

### Likelihood Explanation
Requires the attacker to be a tranche-token holder who can trigger the CDO's instant-withdraw path after `finalizeDefaultRecovery` — an unprivileged user action in scope. Preconditions: `defaultRecoveryFinalized` and `defaultInstantWithdrawsFinalized` (i.e., instant receipts were not fully prefunded at default), and a non-zero remaining `defaultRecoveryReserve`. Uncertainty: whether `IdleCDOEpochVariant` gates `requestInstantWithdraw` when `defaulted()` is true could not be confirmed in this pass; the strategy itself performs no such check, so if the CDO exposes the entry point post-default the path is reachable. The corruption also silently inflates `instantWithdrawClaimsByEpoch[defaultRecoveryEpoch]` and `pendingInstantWithdraws`, further desynchronizing the reserve accounting.

### Recommendation
In `requestInstantWithdraw`, mirror `requestWithdraw`: if `defaultRecoveryFinalized`, revert `NotAllowed()` (or route the new receipt into a post-default bucket paid at par via `_transferFundedClaim`, never via `_transferDefaultRecovery`). Additionally, key post-finalization instant receipts to a value other than `defaultRecoveryEpoch` (e.g., `epochNumber + 1` or a dedicated post-default slot) so the finalized epoch index is immutable after `finalizeDefaultRecovery`.
