### Title
`batch_cancel_order` Aborts Entire Batch When Any Single Order Is Already Filled, Contradicting Documented "Skip" Behavior — (File: `crates/sui-framework/packages/deepbook/sources/clob_v2.move`, `crates/sui-framework/packages/deepbook/sources/clob.move`)

---

### Summary

`batch_cancel_order` in both `deepbook::clob` and `deepbook::clob_v2` is documented to *skip* invalid order IDs, but the implementation *aborts* the entire transaction when any order in the batch is no longer present in the user's open-order table (e.g., because it was filled by a counterparty). Any ordinary market participant who fills one of the targeted orders — even legitimately — causes the entire batch cancellation to revert, leaving all remaining orders open and exposing the caller to unintended trades and financial loss.

---

### Finding Description

`batch_cancel_order` iterates over a caller-supplied `vector<u64>` of order IDs and, for each one, executes:

```move
assert!(linked_table::contains(usr_open_orders, order_id), EInvalidOrderId);
``` [1](#0-0) [2](#0-1) 

If the order is absent from `usr_open_orders` — because a counterparty matched it between the time the caller built the transaction and the time it executed — the `assert!` fires and the Move VM aborts the entire transaction. Every order in the batch remains open.

The function's own NatSpec comment directly contradicts this behaviour:

> "Abort if any of the order_ids are not submitted by the sender. **Skip any order_id that is invalid.**" [3](#0-2) [4](#0-3) 

The sibling function `clean_up_expired_orders` in the same file demonstrates the correct pattern — it uses `continue` to skip missing entries rather than aborting:

```move
if (!table::contains(&pool.usr_open_orders, owner)) { continue };
let usr_open_orders = borrow_mut(&mut pool.usr_open_orders, owner);
if (!linked_table::contains(usr_open_orders, order_id)) { continue };
``` [5](#0-4) 

The root cause is identical to M-24: a batch operation that hard-aborts on an already-consumed item instead of silently skipping it, allowing any third party who consumes one item to invalidate the entire batch.

---

### Impact Explanation

When a user submits a batch cancellation to exit multiple positions simultaneously (a common risk-management action), any counterparty who fills even one of those orders causes the entire PTB to revert. The caller:

1. Loses the gas fee for the failed transaction.
2. Retains all N orders as open, including the N−1 that were never filled.
3. Must re-submit individual cancellations, incurring additional latency and gas.
4. Is exposed to adverse price movement during that window, because the orders they intended to cancel remain live on the book.

This constitutes **harmful smart-contract behaviour**: the function silently fails to perform its documented purpose and leaves the caller in a worse financial position than if the function had not been called at all.

---

### Likelihood Explanation

The trigger requires no privilege. Any ordinary SUI holder with a matching order can fill one of the targeted orders — either deliberately (griefing) or incidentally (normal market activity). Because DeepBook is a public, permissionless order book, order fills happen continuously. A user who batches many cancellations faces a non-trivial probability of at least one order being filled in the interval between transaction construction and execution, making this a realistic race condition even without a deliberate attacker.

---

### Recommendation

Replace the hard `assert!` with a conditional `continue`, matching the documented intent and the pattern already used in `clean_up_expired_orders`:

```move
// clob_v2.move  batch_cancel_order — replace line 731
if (!linked_table::contains(usr_open_orders, order_id)) {
    i_order = i_order + 1;
    continue
};
```

Apply the same fix to `clob.move` line 416. Optionally emit an event for each skipped order so callers can observe which IDs were already consumed.

---

### Proof of Concept

1. Alice places five limit sell orders with IDs `[A, B, C, D, E]` on a DeepBook v2 pool.
2. Alice observes the market moving against her and submits `batch_cancel_order([A, B, C, D, E], account_cap)`.
3. Bob, seeing Alice's pending transaction (or simply trading normally), submits a buy order that matches order `E` first.
4. Bob's transaction is sequenced before Alice's (or concurrently on a different shared-object shard).
5. When Alice's transaction executes, `E` is no longer in `usr_open_orders`.
6. `assert!(linked_table::contains(usr_open_orders, E), EInvalidOrderId)` fires.
7. The entire PTB aborts; orders `A`, `B`, `C`, `D` remain open on the book.
8. Alice loses gas and remains exposed to the market with four live sell orders she intended to cancel. [6](#0-5) [7](#0-6)

    public fun batch_cancel_order<BaseAsset, QuoteAsset>(
        pool: &mut Pool<BaseAsset, QuoteAsset>,
        order_ids: vector<u64>,
        account_cap: &AccountCap
    ) {
        let pool_id = *object::uid_as_inner(&pool.id);
        // First group the order ids according to price level,
        // so that we don't have to retrieve the PriceLevel multiple times if there are orders at the same price level.
        // Iterate over each price level, retrieve the corresponding PriceLevel.
        // Iterate over the order ids that need to be canceled at that price level,
        // retrieve and remove the order from open orders of the PriceLevel.
        let owner = account_owner(account_cap);
        assert!(contains(&pool.usr_open_orders, owner), 0);
        let mut tick_index: u64 = 0;
        let mut tick_price: u64 = 0;
        let n_order = vector::length(&order_ids);
        let mut i_order = 0;
        let usr_open_orders = borrow_mut(&mut pool.usr_open_orders, owner);
        let mut canceled_order_events = vector[];

        while (i_order < n_order) {
            let order_id = *vector::borrow(&order_ids, i_order);
            assert!(linked_table::contains(usr_open_orders, order_id), EInvalidOrderId);
            let new_tick_price = *linked_table::borrow(usr_open_orders, order_id);
            let is_bid = order_is_bid(order_id);
            if (new_tick_price != tick_price) {
                tick_price = new_tick_price;
                let (tick_exists, new_tick_index) = find_leaf(
                    if (is_bid) { &pool.bids } else { &pool.asks },
                    tick_price
                );
                assert!(tick_exists, EInvalidTickPrice);
                tick_index = new_tick_index;
            };
            let order = remove_order(
                if (is_bid) { &mut pool.bids } else { &mut pool.asks },
                usr_open_orders,
                tick_index,
                order_id,
                owner
            );
            if (is_bid) {
                let (_is_round_down, balance_locked) = clob_math::unsafe_mul_round(order.quantity, order.price);
                custodian::unlock_balance(&mut pool.quote_custodian, owner, balance_locked);
            } else {
                custodian::unlock_balance(&mut pool.base_custodian, owner, order.quantity);
            };
            let canceled_order_event = AllOrdersCanceledComponent<BaseAsset, QuoteAsset> {
                client_order_id: order.client_order_id,
                order_id: order.order_id,
                is_bid: order.is_bid,
                owner: order.owner,
                original_quantity: order.original_quantity,
                base_asset_quantity_canceled: order.quantity,
                price: order.price
            };
            vector::push_back(&mut canceled_order_events, canceled_order_event);

            i_order = i_order + 1;
        };

        if (!vector::is_empty(&canceled_order_events)) {
            event::emit(AllOrdersCanceled<BaseAsset, QuoteAsset> {
                pool_id,
                orders_canceled: canceled_order_events,
            });
        };
    }
