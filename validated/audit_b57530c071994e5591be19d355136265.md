### Title
Missing allowlist enforcement in `HandleLegacyUserMessage` enables unauthenticated DON-wide capability trigger fan-out - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` accepts any validly-signed `MethodWebAPITrigger` message and forwards it to every node in `h.donConfig.Members` via `don.SendToNode`, with the allowlist check explicitly left as a `TODO` (`// TODO: apply allowlist and rate-limiting here`). Any address capable of generating its own ECDSA keypair can produce a validly-signed message, since the only checks performed are payload decoding, presence of a timestamp, staleness, and method match — none of which validate whether `msg.Body.Sender` is authorized/subscribed for the target workflow/DON.

### Finding Description
The request enters via `gateway.ProcessRequest` in `core/services/gateway/gateway.go`, which for legacy requests calls `msg.Validate()` (signature/format check only) then dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)`. [1](#0-0) 

Inside `HandleLegacyUserMessage`, the checks performed are: JSON payload decoding, `payload.Timestamp == 0`, message staleness via `MaxAllowedMessageAgeSec`, and method equality to `MethodWebAPITrigger`. Immediately after these checks, the code comment states the allowlist/rate-limit step is not implemented, and the function proceeds to convert the message with `common.ValidatedRequestFromMessage(msg)` (which only validates message structure/signature, not sender authorization) and fans it out to every DON member unconditionally: [2](#0-1) 

No lookup of `msg.Body.Sender` against any subscription/workflow allowlist structure exists in this handler or in `HandlerConfig`, `DONConfig`, or the flow leading up to `don.SendToNode`. The rate limiter (`nodeRateLimiter`) that exists on the handler is only invoked in `handleWebAPIOutgoingMessage` (node→gateway path), not in `HandleLegacyUserMessage` (user→gateway path). [3](#0-2) 

Because `msg.Validate()`/signature checks only confirm the message is self-consistently signed by *some* key, not that the key belongs to an allowlisted/subscribed party, any attacker who generates their own keypair and signs a `MethodWebAPITrigger` payload with a fresh timestamp can trigger execution consumption across the full DON membership set.

### Impact Explanation
This allows unauthorized DON-wide capability execution/resource consumption: an attacker with no allowlist membership can force every node in `donConfig.Members` to process a `web_api_trigger` request, matching the "unauthorized job run" / resource-exhaustion impact class. This is not merely a best-practice gap — it is a concretely reachable, unauthenticated fan-out to the full DON with no gating at the code path examined.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to generate an ECDSA keypair (no registration, credential, or role required), craft a `TriggerRequestPayload` with a non-zero, fresh `Timestamp`, sign it, and submit it as a legacy gateway JSON-RPC request with a valid `DonId`. This is fully reproducible and repeatable since the only gating logic (payload well-formedness, staleness window, method name) is trivially satisfiable by an external, unprivileged party.

### Recommendation
Implement the allowlist check before forwarding to `don.SendToNode`: validate `msg.Body.Sender` (extracted via signature) against a per-workflow/per-DON subscriber/allowlist structure, and apply per-sender rate-limiting (e.g., reusing `ratelimit.RateLimiter` keyed by sender) prior to the fan-out loop in `HandleLegacyUserMessage`. Reject unauthenticated/non-allowlisted senders with `api.HandlerError` or an appropriate unauthorized error code, matching the pattern already used for other validation failures in this function.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Set up `handler` via `setupHandler(t)` with `donConfig.Members` containing 2+ mock DON nodes (using `handlermocks.NewDON(t)`).
2. Generate a fresh, non-registered ECDSA keypair (e.g., `crypto.GenerateKey()`) — do NOT add its address to any allowlist/config structure (none exists to add to).
3. Build a `MethodWebAPITrigger` `api.Message` with a valid `webapicap.TriggerRequestPayload` (non-zero `Timestamp` within `MaxAllowedMessageAgeSec`), sign it with the unregistered key via `msg.Sign(privKey)`.
4. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)`.
5. Assert `don.EXPECT().SendToNode(...)` (mock) is invoked once per `donConfig.Members` entry (matching existing pattern in `TestHandlerReceiveHTTPMessageFromClient`), proving fan-out occurred despite the sender having no allowlist membership.
6. Assert no error/rejection response was sent via `cb.Wait(ctx)` indicating unauthorized sender — confirming the absence of allowlist enforcement.
