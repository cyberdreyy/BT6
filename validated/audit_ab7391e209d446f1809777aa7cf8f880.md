Based on my investigation, I found a legitimate analog. GitLab Runner's suspend/resume feature for the Docker executor (used with autoscaler VM isolation) validates job service images once against `allowed_services`/`AllowedImages` when a build is first created, but the resume path never re-runs that check.

### Title
Suspended-and-resumed builds skip `allowed_images`/`allowed_services` re-validation on service containers - (File: executors/docker/services.go, executors/docker/docker.go)

### Summary
When a build is created normally, service images from `.gitlab-ci.yml` are checked against `AllowedServices`/`AllowedImages` in `getServicesDefinitions` via `e.verifyAllowedImage` at [1](#0-0) . When a suspended build is resumed instead, `resumeDependencies` reconstructs runtime state purely from container IDs embedded in the environment key and calls `resumeServices`, which starts the existing service containers without ever calling `verifyAllowedImage` again.

### Finding Description
`resumeServices` iterates `serviceIDs` parsed from the environment key, inspects and starts each container, and appends it to `e.services` — with no allow-list check at all: [2](#0-1) . This is invoked from `resumeDependencies`, the sole caller: [3](#0-2) . Contrast this with the normal creation path, where every service name is explicitly checked: [4](#0-3) .

This mirrors the InitCapital `setPosMode` bug's root cause: state (collateral/wLp there, service containers here) is carried over into a new operational context (new mode / resumed job) without re-checking the same allow-list invariant that is enforced when that state is first established.

### Impact Explanation
If `allowed_services`/`allowed_images` in `config.toml` is tightened (an admin blacklists a previously-allowed service image) between when a job suspends and when it resumes, the resumed job continues running the now-disallowed service container unchecked. Because `EnvironmentKey` is round-tripped through the trace/server and re-supplied by the job payload on resume (`b.Job.SuspendOptions.EnvironmentKey`, see [5](#0-4) ), the check is bypassed for the entire lifetime of the resumed environment, undermining the `allowed_services` control that operators rely on to restrict what images CI jobs can run.

### Likelihood Explanation
This requires the `SuspendableEnvironments` feature flag and VM-isolated autoscaler resume support to be enabled, and requires the allow-list to change between suspend and resume — a narrow but realistic operational scenario (e.g., a security team updates `allowed_services` after an incident while jobs are suspended). No privileged/insecure config or malicious peer is required beyond normal use of a supported feature (suspend/resume), so this doesn't fall under the disqualifying conditions (no privileged containers, docker.sock exposure, or trusted-role compromise needed).

### Recommendation
In `resumeServices` (or in `resumeDependencies` before calling it), re-run `e.verifyAllowedImage` against each resumed service container's actual image (via `ContainerInspect`'s `Config.Image`) using the current `e.Config.Docker.AllowedServices`/internal images, and fail the resume if any service image is no longer allowed — matching the check already performed in `getServicesDefinitions`.

### Proof of Concept
1. Enable `FF_SUSPENDABLE_ENVIRONMENTS` and configure the docker executor with `allowed_services = ["postgres:*"]`.
2. Run a job with `services: [postgres:14]`, which passes the check in `getServicesDefinitions`, then suspend it (`SuspendOnSuccess`/`SuspendOnFailure`), producing an environment key containing the `postgres` service container ID.
3. Before the job resumes, change the runner config to `allowed_services = ["redis:*"]` (removing `postgres`) and reload config.
4. Resume the job (new job carrying the same `EnvironmentKey`). `resumeDependencies` → `resumeServices` restarts the `postgres` container with no call to `verifyAllowedImage`, so the job continues using a service image that is no longer in `allowed_services`.

```go
func (e *executor) getServicesDefinitions() (spec.Services, error) {
	var internalServiceImages []string
	serviceDefinitions := spec.Services{}

	for _, service := range e.Config.Docker.GetExpandedServices(e.Build.GetAllVariables()) {
		internalServiceImages = append(internalServiceImages, service.Name)
		serviceDefinitions = append(serviceDefinitions, service.ToImageDefinition())
	}

	for _, service := range e.Build.Services {
		err := e.verifyAllowedImage(service.Name, "services", e.Config.Docker.AllowedServices, internalServiceImages)
		if err != nil {
			return nil, err
		}

		serviceDefinitions = append(serviceDefinitions, service)
	}
```

```go
func (e *executor) resumeServices(serviceIDs []string) error {
	for _, svcID := range serviceIDs {
		svcInspect, err := e.dockerConn.ContainerInspect(e.Context, svcID)
		if err != nil {
			return fmt.Errorf("service container %s not found: %w", svcID, err)
		}
		if err := e.dockerConn.ContainerStart(e.Context, svcInspect.ID, client.ContainerStartOptions{}); err != nil {
			return fmt.Errorf("service container %s failed to start: %w", svcInspect.ID, err)
		}
		ip, ports, err := e.getContainerIPAndExposedPorts(svcInspect.ID)
		if err != nil {
			return fmt.Errorf("getting service container %s IP and ports: %w", svcInspect.ID, err)
		}
		e.services = append(e.services, &serviceInfo{
			ID:    svcInspect.ID,
			Name:  svcInspect.Name,
			IP:    ip,
			Ports: ports,
		})
	}

	if len(serviceIDs) > 0 {
		e.waitForServices()
	}
```

```go
func (e *executor) resumeDependencies() error {
	envKey, err := common.ParseEnvironmentKey(e.Build.EnvironmentKey())
	if err != nil {
		return err
	}
	fields, err := parseEnvKeyFields(envKey.Fields)
	if err != nil {
		return err
	}

	buildInspect, err := e.dockerConn.ContainerInspect(e.Context, fields.buildContainerID)
	if err != nil {
		return fmt.Errorf("build container %s not found: %w", fields.buildContainerID, err)
	}
	e.buildContainerID = buildInspect.ID
	e.buildContainer = &buildInspect

	helperInspect, err := e.dockerConn.ContainerInspect(e.Context, fields.helperContainerID)
	if err != nil {
		return fmt.Errorf("helper container %s not found: %w", fields.helperContainerID, err)
	}
	e.helperContainer = &helperInspect

	if err := e.createLabeler(); err != nil {
		return err
	}
	if err := e.createPullManager(); err != nil {
		return err
	}
	if err := e.bindDevices(); err != nil {
		return err
	}
	if err := e.bindDeviceRequests(); err != nil {
		return err
	}
	if err := e.createNetworksManager(); err != nil {
		return err
	}
	if buildInspect.HostConfig == nil {
		return fmt.Errorf("build container %s missing host config", fields.buildContainerID)
	}
	if err := e.networksManager.Adopt(e.Context, buildInspect.HostConfig.NetworkMode); err != nil {
		return err
	}
	e.networkMode = buildInspect.HostConfig.NetworkMode

	if err := e.createVolumesManager(); err != nil {
		return err
	}
	if err := e.volumesManager.Adopt(e.Context, buildInspect.Mounts); err != nil {
		return err
	}

	if err := e.resumeServices(fields.serviceContainerIDs); err != nil {
		return err
	}
```
