### Title
EI-only credential authenticated via `AuthenticateExternalInitiator` is treated as `isUser=true` in `PipelineRunsController.Create`, bypassing the intended "EIs not allowed" restriction - ([File: core/web/pipeline_runs_controller.go])

### Summary
`PipelineRunsController.Create` gates integer-ID job runs on `auth.GetAuthenticatedUser(c)` returning `ok=true`, with a comment stating "only users are allowed to run jobs using int IDs - EIs not allowed." However, `auth.AuthenticateExternalInitiator` injects a synthetic `*clsessions.User{Role: UserRoleRun}` into the same `SessionUserKey` gin context slot used by session/token auth, so a request authenticated purely via a valid External Initiator HMAC signature also satisfies `isUser=true`, letting an EI-only credential run arbitrary jobs by integer ID.

### Finding Description
The route `POST /v2/jobs/:ID/runs` is wrapped with: [1](#0-0) 

`auth.Authenticate` tries the given methods in order and stops at the first one that does not return `ErrorAuthFailed`: [2](#0-1) 

`AuthenticateExternalInitiator` is listed first. When a valid EI HMAC signature (`X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret`, matched via `bridges.AuthenticateExternalInitiator`) is presented, this method succeeds and sets **both** `SessionExternalInitiatorKey` and `SessionUserKey` — the latter to a synthetic `User{Role: UserRoleRun}`: [3](#0-2) 

Because the loop breaks on the first success, `AuthenticateByToken` and `AuthenticateBySession` are never even invoked in this case — the state of any session cookie (valid, forged, or expired) is irrelevant once a valid EI signature is presented.

In `PipelineRunsController.Create`, the check is: [4](#0-3) 

`auth.GetAuthenticatedUser` only inspects whether `SessionUserKey` is set to a `*clsessions.User` — it cannot distinguish a real logged-in user from the synthetic EI-derived user: [5](#0-4) 

`auth.RequiresRunRole` (also applied to this route) likewise only checks `user.Role != UserRoleView`, which the synthetic `UserRoleRun` user passes: [6](#0-5) 

So a caller possessing only a valid External Initiator access key/secret pair (no user session, no API token) will have `isUser == true` in `Create`, and if `idStr` parses as an `int32`, `prc.App.RunJobV2(ctx, jobID, nil)` executes — directly contradicting the code's explicit comment that EIs are not allowed to trigger jobs by integer ID.

### Impact Explanation
This is an authorization-bypass / unauthorized-action bug: an External Initiator credential (a low-privilege, narrowly-scoped credential normally intended to trigger only its associated webhook-style job) can be used to run **any** job addressable by integer ID via `RunJobV2`, which can trigger arbitrary pipeline execution including tasks that move funds or interact with external adapters. This maps to Chainlink's "unauthorized job run" / authorization bypass impact class.

### Likelihood Explanation
- Requires possession of one valid External Initiator access key + secret (issued to any restricted EI integration) — no admin, no session, no API token needed.
- Fully reachable via a single unauthenticated-relative-to-users HTTP `POST /v2/jobs/:ID/runs` request with just the two EI headers set.
- Deterministic and repeatable — no timing/race conditions, no reliance on stale-session behavior (the session cookie does not need to be forged at all; it's simply never checked).

### Recommendation
Distinguish EI-derived authentication from real user authentication instead of overloading `SessionUserKey`. Either:
- Do not set `SessionUserKey` in `AuthenticateExternalInitiator`; instead have `RequiresRunRole` explicitly accept `GetAuthenticatedExternalInitiator` as satisfying "run" role separately from `GetAuthenticatedUser`, and have `PipelineRunsController.Create` check `_, isEI := auth.GetAuthenticatedExternalInitiator(c); if isEI { reject }` before/independently of `isUser`.
- Or check `isUser && !isEI` in `Create`, ensuring the synthetic EI user can never take the integer-ID branch.

### Proof of Concept
Go handler-level integration test plan (in `core/web/pipeline_runs_controller_test.go` style):
1. Set up a test app with an `ExternalInitiator` (`bridges.ExternalInitiator`) with known access key/secret, and a job with an integer ID.
2. Send `POST /v2/jobs/<intID>/runs` with headers `X-Chainlink-EA-AccessKey` / `X-Chainlink-EA-Secret` set to the valid EI credentials, and **no** session cookie / API token headers.
3. Assert the response is `200 OK` with a `pipelineRun` resource (i.e., `RunJobV2` was invoked) — demonstrating that `isUser` resolved to `true` and the "EIs not allowed" comment's intent is bypassed.
4. As a control, repeat with `AuthenticateExternalInitiator` failing (bad EI secret) and no session/token — assert `401 Unauthorized` from `auth.Authenticate`, confirming the vulnerability is specific to the EI-success path setting `SessionUserKey`.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionExternalInitiatorKey, ei)

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error

			}

		}

		c.Next()
	}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
