### Title
`IdleClearpoolStrategy` permanently strands new rewards when Clearpool's upgradeable `PoolFactory` changes the reward token — ([File: contracts/strategies/clearpool/IdleClearpoolStrategy.sol](contracts/strategies/clearpool/IdleClearpoolStrategy.sol))

### Summary
`IdleClearpoolStrategy` caches the reward token address (`govToken`) once at `initialize` (line 82), while `redeemRewards` (lines 102–116) claims rewards by dynamically re-fetching the current `PoolFactory` from the `cpToken` pool (`IPoolMaster(pool).factory().withdrawReward(pools)`). Because `PoolFactory` is an upgradeable Clearpool contract, an upgrade can change the token `withdrawReward` distributes (or the value `cpool()` returns). After such a change, the freshly claimed new reward token is pushed to the strategy, but `redeemRewards` only reads and forwards the stale `govToken` balance to the `IdleCDO`. The contract has no sweep/rescue function, so all newly distributed rewards are permanently locked in the strategy.

### Finding Description
- `initialize` stores `govToken = IPoolMaster(_cpToken).factory().cpool()` once; there is no setter and no re-read of `factory().cpool()` in `redeemRewards` (`IdleClearpoolStrategy.sol:82`, `IdleClearpoolStrategy.sol:102-116`). [1](#0-0) [2](#0-1) 
- `redeemRewards` calls `factory().withdrawReward(pools)` on the *current* factory, so post-upgrade the strategy receives `newRewardToken`, then transfers out only `govToken` balance. [3](#0-2) 
- `getRewardTokens` also returns the stale `govToken`, so the `IdleCDO`'s reward-accounting paths (`getContractValue`/`_skimDonatedAssets`-style accounting that rely on `getRewardTokens`) never see the new token — it sits in the strategy forever, mispriced and unclaimable by any tranche holder. [4](#0-3) 
- This is not a donation/skim path: the tokens are legitimately earned yield for the CDO's strategy position that the CDO can never claim. No attacker profit is needed — the invariant broken is "earned strategy yield is delivered to the CDO," i.e. permanent freezing of unclaimed yield.
- The same stale-cache pattern exists in `GearboxStrategy.redeemRewards`, which claims on the farming pool but only ever forwards the hardcoded `GEAR` constant (`contracts/strategies/gearbox/GearboxStrategy.sol:121-136`). [5](#0-4) 

### Impact Explanation
Any rewards distributed in a token other than the cached `govToken` are locked in `IdleClearpoolStrategy` forever (no `onlyOwner` sweep exists — only `setWhitelistedCDO`/`setUniV3Path`-style setters, and none for reward tokens in this contract). Loss = 100% of post-upgrade reward accrual for the pool's entire strategy position, borne by AA/BB tranche holders whose `getContractValue`/`price` no longer reflect the accruing rewards.

### Likelihood Explanation
Likelihood is gated on a third-party upgrade (Clearpool changing `PoolFactory.cpool()` or `withdrawReward` emission token), which is not attacker-controlled — consistent with the source finding's Medium rating. No unprivileged attacker can trigger it; the report class is a latent integration fragility, not an exploitable path.

### Recommendation
Re-read the reward token at claim time instead of caching: `address current = IPoolMaster(cpToken).factory().cpool();` inside `redeemRewards`, or add an `onlyOwner` `setGovToken` setter plus a generic `sweepToken(address)` rescue restricted to non-strategy/non-underlying tokens. Update `getRewardTokens` to reflect the live token.

### Proof of Concept
```solidity
// test/foundry/IdleClearpoolStaleReward.t.sol — fork mainnet
function test_staleGovToken_strandsRewards() public {
    // strategy + idleCDO already deployed & funded, strategy holds cpTokens
    // 1) upgrade/mock PoolFactory so withdrawReward pays NEW_TOKEN, cpool() -> NEW_TOKEN
    vm.prank(factoryOwner); factory.setCpool(NEW_TOKEN);          // upgrade proxy impl if needed
    deal(NEW_TOKEN, address(factory), rewardAmt);

    // 2) CDO calls redeemRewards -> factory.withdrawReward pushes NEW_TOKEN to strategy
    vm.prank(idleCDO); strategy.redeemRewards("");

    // 3) strategy forwarded only stale CPOOL; NEW_TOKEN locked with no rescue path
    assertEq(IERC20(NEW_TOKEN).balanceOf(address(strategy)), rewardAmt);
    assertEq(IERC20(NEW_TOKEN).balanceOf(idleCDO), 0);
}
```
