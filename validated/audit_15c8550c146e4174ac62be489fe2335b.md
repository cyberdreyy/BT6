### Title
Interest rate charged/paid can be manipulated via flash-loaned deposits before permissionless interest accrual - ([File: programs/marginfi/src/state/bank.rs])

### Summary
The external report describes a Yearn vault bug where a strategy owner uses a flash loan to inflate `_totalAssets()` momentarily, reducing the debt-ratio penalty computed as `loss / _totalAssets()`. The marginfi analog is `Bank::accrue_interest`, which computes `utilization_rate = total_liabilities / total_assets` from the bank's *instantaneous* `total_asset_shares`/`total_liability_shares` and then applies the resulting APR retroactively across the *entire* `time_delta` elapsed since `last_update` — exactly the same class of bug: a ratio derived from spot, flash-loan-manipulable balances is used to compute a value (interest/penalty) applied over a much longer, already-elapsed window. [1](#0-0) 

### Finding Description
`accrue_interest` computes:
```
total_assets = get_asset_amount(total_asset_shares)
total_liabilities = get_liability_amount(total_liability_shares)
...
calc_interest_rate_accrual_state_changes(time_delta, total_assets, total_liabilities, ...)
``` [2](#0-1) 

and `calc_interest_rate_accrual_state_changes` derives `utilization_rate = total_liabilities_amount / total_assets_amount`, feeds it into the interest curve, and then multiplies the resulting APR by the *entire* `time_delta` to update `asset_share_value`/`liability_share_value` (simple interest, applied retroactively for the whole elapsed period since the bank was last touched). [3](#0-2) 

Because `total_asset_shares` changes immediately when anyone deposits (new shares are minted at the *current* share value, without moving `asset_share_value`), an attacker can, within one transaction (or one atomic flash loan of external liquidity):
1. Deposit a large flash-loaned amount into the bank, sharply reducing `total_liabilities / total_assets`.
2. Trigger interest accrual for that bank — either by calling the permissionless `lending_pool_accrue_bank_interest` instruction (no signer/authorization requirement other than "not paused") [4](#0-3) [5](#0-4) , or simply by performing any deposit/borrow/repay/withdraw action which internally calls `accrue_interest` with the same spot values.
3. Withdraw the flash-loaned deposit back out.

Since `time_delta` can represent a long stretch of unaccrued time (banks only accrue when someone calls the relevant instructions), the artificially suppressed utilization rate is applied to the *whole* backlog period, permanently reducing the interest that would otherwise have been charged to real borrowers and paid to real depositors for that entire window. If the attacker has an outstanding liability in the same bank, this directly and durably reduces the interest debited against their own debt (`liability_share_value` increases less than it should), which is the same "reduce your own penalty via flash loan" pattern as the Yearn report — except here the manipulated quantity is `utilization_rate` (an analog of `_totalAssets()`), and the "penalty" is the interest owed on the borrower's debt.

This differs from `_reportLoss` mainly in mechanism (interest accrual vs. debt-ratio reduction) but shares the identical root cause: a financial adjustment is computed from a spot balance ratio that is trivially manipulable within a single atomic transaction via deposit/withdraw, and the result is durably written into protocol state (`asset_share_value`, `liability_share_value`) that is not reversed when the manipulated deposit is withdrawn.

### Impact Explanation
- Interest owed by borrowers, interest earned by lenders, and insurance/protocol/group fees collected (`calc_interest_payment_for_period`, all keyed off the same manipulated `utilization_rate`) can all be suppressed for an entire unaccrued period. [6](#0-5) 
- Because the accrual is applied to `asset_share_value`/`liability_share_value` (durable, non-reversible state), the loss is permanent even after the attacker withdraws their temporary deposit — this is a durable financial-state inconsistency, not a transient display issue.
- An attacker with an existing borrow position in the affected bank directly benefits (reduced interest expense) at the expense of depositors who should have earned that interest, and the insurance/protocol fee buckets are also under-collected.
- Difficulty in reaching a large enough manipulation depends on the size of flash-loanable liquidity for the underlying asset versus the bank's outstanding `total_asset_shares`, and on the size of the accrued-but-unapplied `time_delta` (bigger backlog = bigger absolute impact).

### Likelihood Explanation
- `lending_pool_accrue_bank_interest` is fully permissionless (only checks the group is not paused) [7](#0-6) , and deposit/withdraw are also permissionless user actions, so no privileged role is required.
- The mechanism does not even require marginfi's own flash-loan instructions (`lending_account_start_flashloan`/`end_flashloan`); a straightforward multi-instruction transaction (deposit → accrue → withdraw), optionally funded by an external flash loan, suffices.
- The main constraint reducing likelihood is that the manipulation must move `utilization_rate` meaningfully, requiring available liquidity proportional to the bank's TVL, and the benefit scales with how large the un-accrued `time_delta` backlog is — in practice, most active banks are accrued frequently by routine user actions, which would reduce the window of opportunity. This is a plausible but not certain-to-be-profitable exploit; it was not verified end-to-end against the exact instruction call ordering in `deposit.rs`/`borrow.rs` (file reads for those files did not complete during this investigation), so it is presented with the caveat that the precise point at which `accrue_interest` is invoked relative to share-minting inside each instruction should be re-confirmed.

### Recommendation
- Avoid computing interest-rate/fee ratios purely from instantaneous, single-block state (`total_asset_shares`/`total_liability_shares`). Consider a time-weighted or checkpointed utilization measure, or accrue interest using the utilization rate observed at the *start* of the elapsed interval (cached at `last_update`) rather than the rate at the moment accrual is finally triggered.
- Alternatively, bound how much a single deposit/withdraw pair within one slot/transaction can move the utilization rate used for backlog accrual, or force interest to accrue immediately on every deposit/withdraw (checkpointing `total_assets`/`total_liabilities` before any share-minting change takes effect), so a flash-manipulated balance cannot retroactively apply to a large backlog window.
- Long term, audit all financial computations (health checks, discount factors, interest curves, fee collection) that depend on `Bank.total_asset_shares`/`total_liability_shares`/`asset_share_value` for reachability by an attacker who can move these values within a single atomic transaction, and add fuzz/invariant tests (the existing Trident harness already includes an `assert_bank_solvency` invariant [8](#0-7)  that could be extended to check economic manipulability, not just bookkeeping consistency).

### Proof of Concept
Conceptual sequence (single transaction, or wrapped in `lending_account_start_flashloan`/`lending_account_end_flashloan`):
1. Attacker (or an outside flash-loan) deposits a very large amount of the bank's mint into an attacker-controlled marginfi account for the target bank, sharply increasing `total_asset_shares` and thus reducing `total_liabilities / total_assets`.
2. In the same transaction, call `lending_pool_accrue_bank_interest` (permissionless) for that bank, or perform any other action (borrow/repay/withdraw) that triggers `Bank::accrue_interest`. This computes a suppressed `utilization_rate` and applies the correspondingly low `borrowing_rate_apr`/`lending_rate_apr` to the *entire* `time_delta` since the bank's `last_update`, durably updating `asset_share_value` and `liability_share_value`. [9](#0-8) 
3. Withdraw the large deposit back out in the same transaction (or repay the external flash loan).
4. Net effect: the attacker's own outstanding liability in that bank (if any) accrued materially less interest than it should have for the elapsed period, and depositors/insurance/protocol fees were under-credited for the same window — with no reversal once the temporary deposit is withdrawn.

Note: this PoC was reasoned from `Bank::accrue_interest` / `calc_interest_rate_accrual_state_changes` and the permissionless `LendingPoolAccrueBankInterest` instruction; the exact ordering of `accrue_interest` relative to deposit/withdraw share updates inside `programs/marginfi/src/instructions/marginfi_account/deposit.rs` and `borrow.rs` could not be directly confirmed in this session (file reads did not return content), so the feasibility of steps 1–2 happening within a single instruction call (versus requiring two separate instructions in one transaction) should be verified before treating this as fully confirmed.

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;

        debug!("deposit share value: {}\nliability share value: {}\nfees collected: {}\ninsurance collected: {}",
            asset_share_value, liability_share_value, group_fees_collected, insurance_fees_collected);

        self.cache.accumulated_since_last_update = asset_share_value
            .checked_sub(I80F48::from(self.asset_share_value))
            .and_then(|v| v.checked_mul(I80F48::from(self.total_asset_shares)))
            .ok_or_else(math_error!())?
            .into();
        self.cache.interest_accumulated_for = time_delta.min(u32::MAX as u64) as u32;
        self.asset_share_value = asset_share_value.into();

pub fn calc_interest_rate_accrual_state_changes(
    time_delta: u64,
    total_assets_amount: I80F48,
    total_liabilities_amount: I80F48,
    interest_rate_calc: &InterestRateCalc,
    asset_share_value: I80F48,
    liability_share_value: I80F48,
) -> MarginfiResult<InterestRateStateChanges> {
    // If the cache is empty, we need to calculate the interest rates
    let utilization_rate: I80F48 = total_liabilities_amount
        .checked_div(total_assets_amount)
        .ok_or_else(math_error!())?;
    debug!(
        "Utilization rate: {}, time delta {}s",
        utilization_rate, time_delta
    );
    let interest_rates = interest_rate_calc.calc_interest_rate(utilization_rate)?;

    debug!("{:#?}", interest_rates);

    let ComputedInterestRates {
        lending_rate_apr,
        borrowing_rate_apr,
        group_fee_apr,
        insurance_fee_apr,
        protocol_fee_apr,
        ..
    } = interest_rates;

    Ok(InterestRateStateChanges {
        new_asset_share_value: calc_accrued_interest_payment_per_period(
            lending_rate_apr,
            time_delta,
            asset_share_value,
        )
        .ok_or_else(math_error!())?,
        new_liability_share_value: calc_accrued_interest_payment_per_period(
            borrowing_rate_apr,
            time_delta,
            liability_share_value,
        )
        .ok_or_else(math_error!())?,
        insurance_fees_collected: calc_interest_payment_for_period(
            insurance_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        group_fees_collected: calc_interest_payment_for_period(
            group_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        protocol_fees_collected: calc_interest_payment_for_period(
            protocol_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
    })
}

pub fn lending_pool_accrue_bank_interest(
    ctx: Context<LendingPoolAccrueBankInterest>,
) -> MarginfiResult {
    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = &ctx.accounts.group.load()?;

    bank.accrue_interest(
        clock.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    // TODO see if we can recycle some things like the InterestRateCalc from accrue to save some CU
    bank.update_bank_cache(group)?;

    Ok(())
}

pub fn assert_bank_solvency(trident: &mut Trident, bank_pk: Pubkey, tolerance: I80F48) {
    let bank = trident
        .get_account_with_type::<Bank>(&bank_pk, None)
        .expect("bank account must deserialize");

    let asset_share_value = from_wrapped(bank.asset_share_value.value);
    let liability_share_value = from_wrapped(bank.liability_share_value.value);
    let total_asset_shares = from_wrapped(bank.total_asset_shares.value);
    let total_liability_shares = from_wrapped(bank.total_liability_shares.value);

    let total_deposits = total_asset_shares
        .checked_mul(asset_share_value)
        .expect("total_deposits overflow");
    let total_liabilities = total_liability_shares
        .checked_mul(liability_share_value)
        .expect("total_liabilities overflow");

    let outstanding_fees = from_wrapped(bank.collected_group_fees_outstanding.value)
        + from_wrapped(bank.collected_insurance_fees_outstanding.value)
        + from_wrapped(bank.collected_program_fees_outstanding.value);

    let vault_balance = I80F48::from_num(token_balance(trident, bank.liquidity_vault));
    let net_vault = vault_balance - outstanding_fees;
    let net_book = total_deposits - total_liabilities;

    let drift = (net_vault - net_book).abs();

    invariant!(
        drift <= tolerance,
        "bank solvency drift > {tolerance} units. bank: {bank_pk}\n  vault_balance: {vault_balance}\n  outstanding_fees: {outstanding_fees}\n  net_vault (vault - fees): {net_vault}\n  total_deposits: {total_deposits}\n  total_liabilities: {total_liabilities}\n  net_book (deposits - liabs): {net_book}\n  drift: {drift}"
    );
}
