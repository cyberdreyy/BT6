### Title
Local-auth API tokens never expire (no `UserAPITokenDuration` enforcement) — residual, unbounded credential grant analogous to the residual-allowance bug class - ([File: core/sessions/localauth/orm.go])

### Summary
Chainlink node supports three interchangeable `AuthenticationProvider` implementations for the node's HTTP API: `local`, `ldap`, and `oidc`. All three implement `FindUserByAPIToken`, which is the lookup used by `AuthenticateByToken` (the entry point for `X-API-KEY`/`X-API-SECRET` header authentication on every API request). The LDAP and OIDC providers explicitly bound the lifetime of the API token using the `UserAPITokenDuration` config setting and return `ErrUserSessionExpired` once the configured duration has elapsed. The `local` provider's implementation performs no such check at all — once a token is created it remains a valid, unbounded credential indefinitely.

### Finding Description
`AuthenticateByToken` in [1](#0-0)  looks up the user purely via `authr.FindUserByAPIToken(ctx, token.AccessKey)` and then verifies the secret, treating `clsessions.ErrUserSessionExpired` as an expected sentinel for a stale/expired token.

The LDAP provider correctly implements this contract with a duration check: [2](#0-1) 
and the OIDC provider similarly enforces `UserAPITokenDuration`, as shown by its accompanying tests that assert an expired token returns `sessions.ErrUserSessionExpired`: [3](#0-2) [4](#0-3) 

The `local` provider, however, implements `FindUserByAPIToken` as a plain lookup with no expiry predicate whatsoever: [5](#0-4) 

There is no `created_at`/expiry column check, no comparison against `UserAPITokenDuration()`, and no code path in `localauth/orm.go` that ever invalidates a token except explicit `DeleteAuthToken` (only triggered by the user explicitly revoking the token via `DeleteAPIToken`, as seen in `core/web/user_controller.go:289-329`). This is the direct structural analog of the reported "residual allowance" bug: a grant of access (`_maxSendAmount`/allowance in the original report; here, the API token secret) that is intended to be time/scope-bounded is instead left outstanding indefinitely because the enforcing check present in sibling implementations (LDAP/OIDC — analogous to the `_approve` reset step) is simply missing in the `local` path.

### Impact Explanation
For any Chainlink node configured with `AuthenticationMethod = 'local'` (the documented default per `docs/CONFIG.md` and all `WebServer` config templates), once an API token/secret pair is generated for a user (admin, edit, run, or read role), that credential authenticates indefinitely regardless of the `UserAPITokenDuration` setting an operator may have configured, expecting it to apply uniformly. If a local-auth API token is ever leaked (e.g., via a CI secret, log line, compromised script, or old backup), the residual, non-expiring credential grants persistent unauthorized API access — including job/spec management, bridge management, and other privileged operations tied to the user's role — with no automatic revocation path other than manual `DeleteAuthToken`. This mirrors the original report's core risk: an allowance/grant that should be time-bound or reset is left outstanding, expanding the blast radius of any future compromise of the credential holder.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: `local` is the default and most commonly deployed `AuthenticationMethod`, API tokens are a first-class, documented mechanism (`UserController.NewAPIToken`) intended for long-lived programmatic access, and `UserAPITokenDuration` exists in config specifically to bound such access — creating an expectation (violated only for local auth) that tokens expire. No attacker action beyond obtaining a leaked/stolen token is required to exploit the residual validity.

### Recommendation
Enforce `UserAPITokenDuration` in `core/sessions/localauth/orm.go`'s `FindUserByAPIToken`, matching the pattern already used in `ldapauth` and `oidcauth`: track token creation time and reject (returning `sessions.ErrUserSessionExpired`) once the configured duration has elapsed, purging or requiring token regeneration analogous to the LDAP/OIDC reaper flows.

### Proof of Concept
Not applicable as a runtime exploit against production infrastructure; the finding is a structural code-review issue confirmed by direct comparison of the three `AuthenticationProvider` implementations of `FindUserByAPIToken`:
- `core/sessions/localauth/orm.go:48-53` — no expiry check.
- `core/sessions/ldapauth/ldap.go:235-279` — enforces `UserAPITokenDuration`.
- `core/sessions/oidcauth/oidc.go` (tested in `oidc_test.go:100-126`) — enforces `UserAPITokenDuration`.

Concretely: create a local-auth user API token via `POST /v2/user/tokens` (`UserController.NewAPIToken`), wait past the configured `UserAPITokenDuration`, then authenticate with the same token via `X-API-KEY`/`X-API-SECRET` headers against any endpoint protected by `AuthenticateByToken`. Unlike LDAP/OIDC configurations, the local-auth request will still succeed because `FindUserByAPIToken` performs no duration check.

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

// ListUsers will load and return all active users in applicable LDAP groups, extended with local admin users as well
func (l *ldapAuthenticator) ListUsers(ctx context.Context) ([]sessions.User, error) {
	// For each defined role/group, query for the list of group members to gather the full list of possible users
	users := []sessions.User{}
	var err error

	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		l.lggr.Errorf("error in LDAP dial: %v", err)
		return users, errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	// Query for list of uniqueMember IDs present in Admin group
	adminUsers, err := l.ldapGroupMembersListToUser(conn, l.config.AdminUserGroupCN(), sessions.UserRoleAdmin)
	if err != nil {
		l.lggr.Errorf("error in ldapGroupMembersListToUser: %v", err)
		return users, errors.New("unable to list group users")
	}
	// Query for list of uniqueMember IDs present in Edit group
	editUsers, err := l.ldapGroupMembersListToUser(conn, l.config.EditUserGroupCN(), sessions.UserRoleEdit)
	if err != nil {
		l.lggr.Error("error in ldapGroupMembersListToUser: ", err)
		return users, errors.New("unable to list group users")
	}
	// Query for list of uniqueMember IDs present in Run group
	runUsers, err := l.ldapGroupMembersListToUser(conn, l.config.RunUserGroupCN(), sessions.UserRoleRun)
	if err != nil {
		l.lggr.Error("error in ldapGroupMembersListToUser: ", err)
		return users, errors.New("unable to list group users")
	}
	// Query for list of uniqueMember IDs present in Read group
	readUsers, err := l.ldapGroupMembersListToUser(conn, l.config.ReadUserGroupCN(), sessions.UserRoleView)
	if err != nil {
		l.lggr.Error("error in ldapGroupMembersListToUser: ", err)
		return users, errors.New("unable to list group users")
	}

	// Aggregate full list
	users = append(users, adminUsers...)
	users = append(users, editUsers...)
	users = append(users, runUsers...)

func TestORM_DeleteAuthToken(t *testing.T) {
	ctx := t.Context()

	// Init OIDC authenticator
	db, oidcAuthProvider := setupAuthenticationProvider(t)

	// Create a token for a test user

	err = oidcAuthProvider.DeleteAuthToken(ctx, &user)

	// Verify token is deleted - FindUserByAPIToken should fail
	_, err = oidcAuthProvider.FindUserByAPIToken(ctx, apiToken)
