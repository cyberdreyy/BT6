### Title
Unchecked native NEAR transfer in `internal_withdraw` lets a validator-slashing/gas failure permanently burn a delegator's unstaked balance - (File: `staking-pool/src/internal.rs`)

### Summary
`internal_withdraw` deducts the delegator's `unstaked` balance and the pool's `last_total_balance` and then fires `Promise::new(account_id).transfer(amount)` with no `.then()` callback and no `is_promise_success()` check, unlike every other value-moving promise in this codebase.

### Finding Description
The reported bug class is "a state-mutating value transfer whose result is never checked, so the accounting proceeds as if the transfer succeeded." In `staking-pool/src/internal.rs`, `internal_withdraw` does: [1](#0-0) 
It decrements `account.unstaked`, persists the account, logs, fires `Promise::new(account_id).transfer(amount)`, and decrements `self.last_total_balance` — all without attaching a callback that verifies the transfer's outcome.

This is inconsistent with the rest of the same repository, which treats every outbound NEAR transfer as fallible and reconciles state only after confirmation:
- `lockup/src/foundation.rs` `termination_withdraw` attaches `.then(ext_self_foundation::on_withdraw_unvested_amount(...))` and only finalizes state in the callback based on `is_promise_success()`: [2](#0-1)  and [3](#0-2) 
- `lockup/src/owner_callbacks.rs` `on_staking_pool_withdraw` similarly only adjusts `deposit_amount` after confirming success via `is_promise_success()`: [4](#0-3) 
- `lockup-factory/src/lib.rs` and `staking-pool-factory/src/lib.rs` both roll back (refund) via a callback when a downstream promise fails: [5](#0-4) [6](#0-5) 

`internal_withdraw` breaks this pattern: it commits the debit (`account.unstaked -= amount`, `self.last_total_balance -= amount`) synchronously and unconditionally, before NEAR runtime confirms the transfer receipt executed. If the `transfer` action's receipt fails (e.g., the account no longer exists, exceeds gas/data limits, or any other receipt-level failure not caught at the call site), the yoctoNEAR is refunded to the *contract account* balance, not to the delegator, yet the delegator's `unstaked` ledger entry and the pool's `last_total_balance` have already been permanently reduced. The equality that should hold — `sum(accounts[*].unstaked) + total_staked_balance == last_total_balance == funds actually redeemable by delegators` — is broken: recorded claims fall below the NEAR the contract could still deliver, and the specific delegator's recorded claim is deleted despite never receiving the funds.

### Impact Explanation
This matches the "accounting value diverging from reality where another party settles on it" category: the delegator's on-chain claim (`unstaked` balance) is destroyed while the actual value transfer did not reach them. Reward/fee distribution (`internal_ping`) computes future rewards from `last_total_balance`, so an erroneous decrement here also corrupts subsequent reward accounting for all delegators, and the affected delegator's funds are frozen (in this case, permanently, since there is no follow-up mechanism to detect or retry the failed transfer).

### Likelihood Explanation
This requires no privileged access and no cooperation from the foundation, an owner, or a multisig member — an ordinary delegator simply calls `withdraw`/`withdraw_all` on the staking pool. The triggering condition is a transfer receipt failure, which is an intrinsic risk of any unguarded `Promise::new(...).transfer(...)`, the same risk category the external SafeERC20 report flags for unguarded `token.transfer()`. Whether such a receipt failure is easy to induce deliberately is uncertain from static review alone; NEAR generally reduces (but does not eliminate) transfer-failure surface compared to ERC-20 return-value quirks, so likelihood is lower than the original Solidity finding, though the structural defect (no reconciliation callback) is real and directly analogous.

### Recommendation
Mirror the pattern already used elsewhere in this codebase (`lockup/src/foundation.rs::termination_withdraw`, `lockup/src/owner_callbacks.rs::on_staking_pool_withdraw`): attach a `.then()` callback to the `Promise::new(account_id).transfer(amount)` call in `internal_withdraw`, and only commit `account.unstaked -= amount` / `self.last_total_balance -= amount` after confirming `is_promise_success()`; on failure, restore the account's `unstaked` balance instead of leaving the debit permanent.

### Proof of Concept
1. Delegator calls `withdraw(amount)` (or `withdraw_all`), which invokes `internal_withdraw`.
2. `internal_withdraw` immediately does `account.unstaked -= amount; self.internal_save_account(...); Promise::new(account_id).transfer(amount); self.last_total_balance -= amount;` with no `.then()` callback: [7](#0-6) 
3. If the transfer receipt to `account_id` fails for any runtime-level reason, the yoctoNEAR returns to the staking-pool contract's own balance, but the delegator's `unstaked` field and `last_total_balance` remain decremented — the delegator has no recorded claim left and never received the NEAR, while the pool silently retains the funds with no compensating ledger entry.

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }

    pub fn on_withdraw_unvested_amount(
        &mut self,
        amount: WrappedBalance,
        receiver_id: AccountId,
    ) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        if withdraw_succeeded {
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} succeeded.",
                    amount.0, receiver_id
                )
                    .as_bytes(),
            );
            // Decreasing lockup amount after withdrawal.
            self.lockup_information.termination_withdrawn_tokens += amount.0;
            let unvested_amount = self.get_terminated_unvested_balance().0;
            if unvested_amount > amount.0 {
                // There is still unvested balance remaining.
                let remaining_balance = unvested_amount - amount.0;
                self.vesting_information =
                    VestingInformation::Terminating(TerminationInformation {
                        unvested_amount: remaining_balance.into(),
                        status: TerminationStatus::ReadyToWithdraw,
                    });
                env::log(
                    format!(
                        "Termination Step: There is still terminated unvested balance of {} remaining to be withdrawn",
                        remaining_balance
                    )
                        .as_bytes(),
                );
                if self.get_account_balance().0 == 0 {
                    env::log(b"The withdrawal is completed: no more balance can be withdrawn in a future call");
                }
            } else {
                self.foundation_account_id = None;
                self.vesting_information = VestingInformation::None;
                env::log(b"Vesting schedule termination and withdrawal are completed");
            }
        } else {
            self.set_termination_status(TerminationStatus::ReadyToWithdraw);
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} failed",
                    amount.0, receiver_id,
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
    }

    pub fn on_staking_pool_withdraw(&mut self, amount: WrappedBalance) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        self.set_staking_pool_status(TransactionStatus::Idle);

        if withdraw_succeeded {
            {
                let staking_information = self.staking_information.as_mut().unwrap();
                // Due to staking rewards the deposit amount can become negative.
                staking_information.deposit_amount.0 = staking_information
                    .deposit_amount
                    .0
                    .saturating_sub(amount.0);
            }
            env::log(
                format!(
                    "The withdrawal of {} from @{} succeeded",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        } else {
            env::log(
                format!(
                    "The withdrawal of {} from @{} failed",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
    }

    /// Callback after a lockup was created.
    /// Returns the promise if the lockup creation succeeded.
    /// Otherwise refunds the attached deposit and returns `false`.
    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }

    /// Callback after a staking pool was created.
    /// Returns the promise to whitelist the staking pool contract if the pool creation succeeded.
    /// Otherwise refunds the attached deposit and returns `false`.
    pub fn on_staking_pool_create(
        &mut self,
        staking_pool_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> PromiseOrValue<bool> {
        assert_self();

        let staking_pool_created = is_promise_success();

        if staking_pool_created {
            env::log(
                format!(
                    "The staking pool @{} was successfully created. Whitelisting...",
                    staking_pool_account_id
                )
                .as_bytes(),
            );
            ext_whitelist::add_staking_pool(
                staking_pool_account_id,
                &self.staking_pool_whitelist_account_id,
                NO_DEPOSIT,
                gas::WHITELIST_STAKING_POOL,
            )
            .into()
        } else {
            self.staking_pool_account_ids
                .remove(&staking_pool_account_id);
            env::log(
                format!(
                    "The staking pool @{} creation has failed. Returning attached deposit of {} to @{}",
                    staking_pool_account_id,
                    attached_deposit.0,
                    predecessor_account_id
                ).as_bytes()
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            PromiseOrValue::Value(false)
        }
    }
