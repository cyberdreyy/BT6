### Title
Stale member confirmations remain counted toward the approval threshold after `DeleteMember`, allowing a request to execute with fewer than `num_confirmations` live members - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` decides whether to execute a request purely by counting entries in the request's `confirmations: HashSet<String>` against `self.num_confirmations`, without re-validating that every account/key already present in that set is still a current member. `delete_member` only purges confirmations/requests that were *authored* by the removed member; it never scans other requests' confirmation sets to strip out that member's prior approvals. A member's confirmation therefore continues to count toward the threshold even after that member has been removed from `self.members`, letting a request execute with fewer live approving members than `num_confirmations` requires.

### Finding Description
The intended invariant is that a request only executes once at least `num_confirmations` **current** members have approved it:
`|{m ∈ confirmations(request) : m ∈ members}| ≥ num_confirmations`.

The implementation instead checks the raw cardinality of the stored confirmations set: [1](#0-0) 

`delete_member` cleans up only requests where the removed member is the *signer* of the request (`r.member == member`); it does not touch `confirmations` entries the removed member left on *other* still-pending requests: [2](#0-1) 

Because `confirm` never re-checks membership of previously-recorded confirmers (`assert_valid_request` only validates that the *caller* is a current member), a confirmation recorded by a member who is later removed keeps "counting" toward the threshold: [3](#0-2) 

Concrete break of the binding: with 4 members `[A, B, C, D]` and `num_confirmations = 3`:
1. `A` calls `add_request_and_confirm` on a malicious `Transfer` request `R` (1 confirmation: `A`).
2. `B` calls `confirm(R)` (2 confirmations: `A, B`), then `R` is one confirmation short of execution.
3. Separately, `A`, `C`, `D` confirm and execute a `DeleteMember { member: B }` request (a legitimate, unrelated offboarding action), which succeeds via `execute_request` → `delete_member`. This removes `B` from `self.members` but leaves `B`'s confirmation on `R` untouched, since `R` was authored by `A`, not `B`.
4. `C` now calls `confirm(R)`. `confirmations.len() (2) + 1 == 3 >= num_confirmations (3)` is true, so `R` executes — even though only `A` and `C` are still live members backing it; `B`'s stale confirmation supplied the missing vote.

### Impact Explanation
This is a `multisig request executed below threshold`, explicitly listed as a Critical impact: a transfer, `DeployContract`, `AddKey`, or any other privileged action can be pushed through with fewer live, currently-authorized approvers than `num_confirmations` mandates, undermining the entire K-of-N custody guarantee of the contract.

### Likelihood Explanation
The precondition is realistic and routine for a multisig: member rotation/offboarding (`DeleteMember`) happening while other requests are mid-flight is an expected operational pattern, not an edge case requiring any privileged foundation role. Any member who already confirmed a pending request before being removed silently continues to "vote" on it after removal, and no code path revalidates or expires their confirmation.

### Recommendation
In `confirm` (and ideally in `get_confirmations`/execution counting generally), filter the stored confirmations against `self.members` before comparing to `num_confirmations`, e.g. compute `confirmations.iter().filter(|m| self.members.contains(m)).count()`. Additionally, `delete_member` should proactively strip the removed member's entry from every request's `confirmations` set (not just requests it authored) to keep stored state consistent with live membership.

### Proof of Concept
```rust
// members: A, B, C, D ; num_confirmations = 3
let request_id = /* A */ c.add_request_and_confirm(transfer_request.clone()); // confirmations = {A}
/* switch to B */ c.confirm(request_id); // confirmations = {A, B}

// Separately: A, C, D remove B via DeleteMember (unrelated legitimate request)
let del_id = /* A */ c.add_request_and_confirm(MultiSigRequest {
    receiver_id: current_account_id(),
    actions: vec![MultiSigRequestAction::DeleteMember { member: b_member.clone() }],
});
/* C confirms */ c.confirm(del_id);
/* D confirms */ c.confirm(del_id); // executes, B removed from self.members

// R's confirmations set still contains B, unaffected by delete_member
assert!(c.get_confirmations(request_id).contains(&b_member.to_string()));

/* C confirms transfer_request */
c.confirm(request_id); // confirmations.len()=2 + 1 = 3 >= num_confirmations(3) -> executes
// Executed with only A and C as live approving members, i.e. 2 of 4 current members,
// even though num_confirmations == 3.
```

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
