This confirms the vulnerability. `ExtractZipArchive` never resolves or validates `file.Name` against the extraction directory — notice that `e.dir` (the target directory) isn't even passed into `archives.ExtractZipArchive(zr)` at all in `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33`, and `extractZipFile`/`extractZipFileEntry`/`extractZipSymlinkEntry`/`extractZipDirectoryEntry` in `helpers/archives/zip_extract.go:12-83` operate directly on `file.Name` with `os.Mkdir`, `os.OpenFile`, `os.Symlink`, and `os.MkdirAll(filepath.Dir(file.Name), ...)` with zero path confinement, unlike `tarzstd`'s explicit `filepath.Abs(filepath.Join(e.dir, hdr.Name))` + `strings.HasPrefix(path, e.dir+string(filepath.Separator))` check at `commands/helpers/archive/tarzstd/tarzstd_extractor.go:57-64`.

### Title
ZIP extraction path traversal / arbitrary file write due to missing directory-confinement check - (helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` extracts each `zip.File` using its raw `file.Name` with no path sanitization or confinement to the intended extraction root, unlike the `tarzstd` extractor which resolves paths to absolute form and rejects any that escape the target directory. A crafted ZIP entry with `..` traversal segments or an absolute path can therefore write, overwrite, or symlink files anywhere the runner process has permission to write, both for cache restores and artifact downloads.

### Finding Description
The call chain is `commands.CacheExtractorCommand`/`ArtifactsDownloaderCommand` → `archive.NewExtractor(archive.Zip, ...)` → `ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33`) → `archives.ExtractZipArchive(zr)` (`helpers/archives/zip_extract.go:85-110`). Critically, `ziplegacy.extractor` even holds a `dir` field (the intended extraction root) that is stored but never used or passed to `ExtractZipArchive` — the function signature only takes the `*zip.Reader`, so the target directory is entirely disconnected from extraction.

Inside `ExtractZipArchive`, each entry only gets a `.git`-directory check (`errorIfGitDirectory`, in `helpers/archives/path_check_helper.go`) before being handed to `extractZipFile` (`helpers/archives/zip_extract.go:61-83`), which calls:
- `os.MkdirAll(filepath.Dir(file.Name), 0o777)` — creates parent directories at `file.Name`'s literal path,
- `os.Mkdir(file.Name, ...)` for directory entries,
- `os.OpenFile(file.Name, ...)` for regular files,
- `os.Symlink(string(data), file.Name)` for symlink entries.

None of these resolve `file.Name` against a base directory or check that the resolved path stays within it, contrary to the `tarzstd` extractor's guarantee at `commands/helpers/archive/tarzstd/tarzstd_extractor.go:57-64`, which computes `path := filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it if `!strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir`. A ZIP entry named `../../../../etc/cron.d/x` (relative traversal, works regardless of CWD since Go's `os` file calls resolve relative to the process's current working directory, which for these commands is the extraction dir passed via `-C`/`--dir` argument handling elsewhere) or an absolute path like `/etc/cron.d/x` (Unix) or `C:\Windows\...` (Windows, since Go's `os` functions accept OS-native absolute paths on their respective platform) will be extracted or written literally with no rejection.

Existing protections reviewed: `errorIfGitDirectory` only blocks `.git`-prefixed entries and is unrelated to traversal; `lchmod`/`processZipExtra` operate after extraction and don't validate paths either. There is no equivalent of the tarzstd `HasPrefix` check anywhere in `helpers/archives/zip_extract.go`.

### Impact Explanation
An attacker who controls the contents of a cache or artifact zip (e.g., by naming files with `../` traversal or absolute paths in a job that populates the cache/artifacts, then having that cache/artifact restored in another job/stage/pipeline run on the same runner host) can write or overwrite arbitrary files outside the job's workspace, including symlink creation via `extractZipSymlinkEntry`. This matches the scoped impact: host file write outside workspace, potentially persisting across job cancellation/cleanup since the write lands outside any workspace directory the runner cleans up.

### Likelihood Explanation
Fully reachable by an unprivileged pipeline author: caches/artifacts are user-controlled content (a `.zip` produced by any job, including one crafted by hand-editing archive bytes or via a custom build step that runs `zip` with `../` filenames or bypasses normal archiving tools to inject crafted entries directly). It requires the cache/artifact to be later extracted (`CacheExtractorCommand`/`ArtifactsDownloaderCommand`), which is the normal, automatic runner workflow — no special privilege needed, and it is fully repeatable.

### Recommendation
Add the same confinement logic used in `tarzstd_extractor.go` to zip extraction: pass the extraction `dir` into `ExtractZipArchive`/`extractZipFile`, compute `path := filepath.Abs(filepath.Join(dir, file.Name))` for every entry, and reject with an error if `!strings.HasPrefix(path, dir+string(filepath.Separator)) && path != dir`, before performing any `Mkdir`/`OpenFile`/`Symlink` operation. This should also cover the `extractZipSymlinkEntry` symlink target itself.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir()
    outsideTarget := filepath.Join(outsideDir, "pwned")

    // Build a malicious zip with a traversal entry name.
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    relPath, _ := filepath.Rel(tmpDir, outsideTarget)
    w, _ := zw.Create(relPath) // e.g. "../<outsideDirBase>/pwned"
    _, _ = w.Write([]byte("owned"))
    zw.Close()

    origWD, _ := os.Getwd()
    _ = os.Chdir(tmpDir)
    defer os.Chdir(origWD)

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = archives.ExtractZipArchive(zr)
    // Expect: extraction should fail/refuse to write outside tmpDir
    assert.Error(t, err)
    _, statErr := os.Stat(outsideTarget)
    assert.True(t, os.IsNotExist(statErr), "file should not have been written outside extraction root")
}
```
Currently this test fails (no error, and `outsideTarget` exists with contents `"owned"`), confirming the missing confinement check; after applying the tarzstd-style path-prefix guard, the test should pass.
