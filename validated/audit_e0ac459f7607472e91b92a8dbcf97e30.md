### Title
Stale Oracle Price Accepted as Fresh via Relative-Only Time Window in `MetaOracle.combine()` — (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

`MetaOracle.combine()` validates oracle data freshness by computing a floor timestamp relative to the **last oracle's own stored timestamp** (`max_timestamp`), never comparing against the current on-chain `Clock`. During any period of oracle-operator downtime, all `SimpleOracle` objects retain their last-written stale prices. Because the freshness window is anchored to those stale timestamps rather than to wall-clock time, every stale data point passes the window check and is returned as "trusted" data. Any protocol that uses `MetaOracle` for price-sensitive decisions will silently consume arbitrarily old prices.

---

### Finding Description

`SimpleOracle.submit_data` records the current `Clock` timestamp when an oracle operator pushes a price update: [1](#0-0) 

`MetaOracle.add_simple_oracle` reads the latest stored data and overwrites `max_timestamp` with the **last-added oracle's stored timestamp** — not the current clock, and not even the true maximum across all oracles: [2](#0-1) 

`MetaOracle.combine()` then derives the freshness floor as:

```move
let min_timestamp = max_timestamp - time_window_ms;
```

and accepts any oracle entry whose stored timestamp exceeds that floor: [3](#0-2) 

There is no `Clock` parameter anywhere in `MetaOracle`. The struct carries no reference to current time: [4](#0-3) 

**Consequence**: if all oracle operators are offline for, say, 6 hours, every `SimpleOracle` holds a price stamped 6 hours ago. When `add_simple_oracle` is called for each oracle, `max_timestamp` is set to that 6-hour-old timestamp. `min_timestamp` becomes `(T_stale − time_window_ms)`, which is also 6 hours in the past. Every oracle's 6-hour-old price satisfies `timestamp > min_timestamp` and is included. The `threshold` quorum check passes, and `median()` returns a `TrustedData` value carrying a price that is 6 hours stale — indistinguishable from a fresh reading.

A secondary defect compounds this: `add_simple_oracle` unconditionally overwrites `max_timestamp` with each successive oracle's timestamp rather than taking the running maximum. If oracles are added in non-monotone order, `max_timestamp` may be *less* than some earlier oracle's timestamp, making the window even less restrictive.

---

### Impact Explanation

Any on-chain protocol that calls `MetaOracle.median()` (or `combine()`) to price assets, collateral, or conditional orders will receive a stale price that passes all internal freshness checks. The protocol has no way to detect the staleness because `TrustedData` carries no timestamp field and `MetaOracle` exposes no current-time comparison. Depending on the consuming protocol, this enables:

- Executing trades or conditional orders (analogous to the external report's Stop-Loss/Stop-Open orders) at prices that diverged significantly from the real market during the downtime window.
- Liquidating or protecting positions based on a price that no longer reflects market reality.

This constitutes **harmful smart-contract behavior** under the Medium/High impact gate.

---

### Likelihood Explanation

Oracle-operator downtime is a realistic, low-probability event (network issues, key rotation, infrastructure failure). The window of exploitability is the entire duration of the downtime — any transaction submitted while oracles are stale will silently use the stale price. No privileged access is required; any ordinary SUI holder can submit a transaction that invokes a `MetaOracle`-consuming function.

---

### Recommendation

Pass the current `Clock` into `combine()` (and therefore into `median()`) and reject any oracle entry whose stored timestamp is older than `clock::timestamp_ms(clock) - time_window_ms`:

```move
fun combine<T: copy + drop>(
    meta_oracle: MetaOracle<T>,
    clock: &Clock,
): (vector<T>, vector<address>) {
    let now_ms = clock::timestamp_ms(clock);
    let min_timestamp = now_ms - meta_oracle.time_window_ms;
    // ... filter on data::timestamp(&oracle_data) > min_timestamp
}
```

Additionally, fix `add_simple_oracle` to track the true maximum timestamp:

```move
if (option::is_some(&oracle_data)) {
    let ts = data::timestamp(option::borrow(&oracle_data));
    if (ts > meta_oracle.max_timestamp) {
        meta_oracle.max_timestamp = ts;
    };
};
```

### Proof of Concept

**Setup**: Three `SimpleOracle` objects, each last updated at `T_stale = now − 6 hours`. `time_window_ms = 60_000` (60 s).

**Step 1** — Oracle operators go offline; no new `submit_data` calls are made.

**Step 2** — Six hours later, an unprivileged user submits a PTB that calls `trusted_fx` (or any equivalent consumer):

```move
let mut meta = meta_oracle::new<DecimalValue>(3, 60_000, b"SUIUSD".to_string());
meta_oracle::add_simple_oracle(&mut meta, oracle1); // max_timestamp ← T_stale
meta_oracle::add_simple_oracle(&mut meta, oracle2); // max_timestamp ← T_stale
meta_oracle::add_simple_oracle(&mut meta, oracle3); // max_timestamp ← T_stale
let trusted = meta_oracle::median(meta);
// trusted.value == 6-hour-old price, no abort, no staleness signal
``` [5](#0-4) 

**Step 3** — Inside `combine()`:
- `max_timestamp = T_stale`
- `min_timestamp = T_stale − 60_000`
- All three oracle entries have `timestamp == T_stale > min_timestamp` → all included
- `threshold` (3) is met → `median()` returns the 6-hour-old price as trusted [3](#0-2) 

**Result**: The consuming protocol uses a price that is 6 hours stale, with no on-chain indication of staleness, directly mirroring the external report's scenario where a stop order executes at a price anchored to a stale reference point after downtime.

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
```
