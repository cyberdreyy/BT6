The design pattern across all callers (`vault/handler.go`, `confidentialrelay/handler.go`, `capabilities/handler.go`, `http_trigger_handler.go`) is: the `Callback` object is created and bound to a specific request ID at creation time via a map (`activeRequests[req.ID]`, `savedCallbacks[msg.Body.MessageId]`, `h.callbacks[requestID]`), and node/user responses are routed to the correct `Callback` instance through *map lookups keyed by the request ID*, not by trusting any ID embedded inside the payload. `SendResponse` itself is a one-shot delivery primitive (`sent.CompareAndSwap`) for whatever payload the already-ID-resolved caller constructs — it has no independent notion of "the id inside a signed payload" to compare against, because ID resolution happens one layer up, before `SendResponse` is ever invoked.

### Title
No exploitable ID-mismatch vulnerability in `callback.SendResponse`

### Summary
`SendResponse` in `core/services/gateway/handlers/common/callback.go` is a bare single-use channel-send primitive; it does not accept or inspect a request ID, and it is only ever invoked after the caller (vault, confidentialrelay, capabilities, or v2 http-trigger handlers) has already resolved the correct `Callback` instance for a specific request via a map keyed by that request's ID.

### Finding Description
`SendResponse` at [1](#0-0)  takes a `handlers.UserCallbackPayload` and pushes it onto a per-instance channel, guarded only by a one-time `sent` flag. It has no `id` field or parameter to validate. The claim that it "tolerates a mismatch between the id inside a signed payload and the id of the request being answered" doesn't hold because the function is never given two IDs to compare — routing to the correct `Callback` instance is performed entirely by the caller before `SendResponse` is invoked.

Concretely:
- In the vault handler, callbacks are looked up by `resp.ID` via `h.getActiveRequest(resp.ID)` at [2](#0-1) , and only the matched `activeRequest`'s embedded `Callback` is used to send.
- In the confidential relay handler, `ar.SendResponse(payload)` is called only after CAS-claiming a specific `activeRequest` retrieved by its own request ID, and it is deleted from `h.activeRequests[ar.req.ID]` afterward, per [3](#0-2) .
- In the capabilities handler, callbacks are saved per `msg.Body.MessageId` at [4](#0-3) .
- In the v2 http-trigger handler, `h.callbacks[resp.ID]` is looked up before calling `saved.SendResponse` at [5](#0-4) .

In each case, the "invariant" the audit question asks about (signed id == served request id) is enforced by the *map-lookup-by-ID* pattern in the caller, not inside `SendResponse`. There is no code path where an attacker-controlled ID inside a `RawResponse` payload can cause `SendResponse` to deliver a response through a `Callback` instance bound to a *different* request — the callback is already bound to exactly one request by construction, and each handler's map lookup guarantees that node/user responses are only routed to the `Callback` for the same ID they arrived tagged with.

### Impact Explanation
None. No cross-user response splicing, credential disclosure, or authorization bypass is achievable purely through `SendResponse`'s lack of ID validation, since ID matching is a property of the map-based routing performed by every caller before `SendResponse` is reached.

### Likelihood Explanation
Not applicable — the described attack primitive does not exist in this code path as designed.

### Recommendation
No change required to `SendResponse`. If the reviewer's concern is about response-routing correctness in a specific handler (e.g., possible ID confusion in the vault, confidentialrelay, or v2 http-trigger request-ID-to-callback maps themselves), that would need to be raised against the specific map-lookup/keying logic in those handler files rather than against `SendResponse`.

### Proof of Concept
Not applicable — no reproducible PoC demonstrates cross-request response delivery via `SendResponse`, since the function has no ID field to manipulate and callers already gate routing by ID via map lookups.

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
	aggResp, err := agg.CollectAndAggregate(resp, nodeAddr)
	if err != nil {
		return err
	}
	if aggResp == nil {
		h.lggr.Debugw("Not enough responses to aggregate", "requestID", resp.ID, "nodeAddress", nodeAddr, "shard", shard.donID)
		return nil
	}
	rawResp, err := json.Marshal(aggResp)
	if err != nil {
		return errors.New("failed to marshal response: " + err.Error())
	}

	err = saved.SendResponse(handlers.UserCallbackPayload{
		RawResponse: rawResp,
		ErrorCode:   api.NoError,
	})
	if err != nil {
		return err
	}
