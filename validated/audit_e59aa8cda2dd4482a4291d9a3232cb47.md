### Title
`TranchesChainlinkOracle.latestRoundData()` returns hardcoded `roundId`/`updatedAt`/`answeredInRound` of 0, breaking integrator staleness checks - (File: contracts/strategies/morpho/TranchesChainlinkOracle.sol)

### Summary
`TranchesChainlinkOracle` implements the Chainlink `IAggregatorV3Minimal` interface so that Idle tranche tokens can be used as collateral in Morpho-style markets and other integrators. Its `latestRoundData()` returns a fresh `answer` (`cdo.virtualPrice(collateralToken)`) but hardcodes `roundId`, `startedAt`, `updatedAt`, and `answeredInRound` to `0`. This is the same defect class as the external `MagicLpAggregator` report: any integrator that performs the standard `updatedAt` freshness check will always compute `0 < block.timestamp - threshold` and revert, making the oracle permanently unusable for them.

### Finding Description
In `TranchesChainlinkOracle.sol#L29-L31`:

```solidity
function latestRoundData() external view returns (uint80, int256, uint256, uint256, uint80) {
    return (0, int256(cdo.virtualPrice(collateralToken)), 0, 0, 0);
}
```

`virtualPrice` is a live view on the CDO — the answer is always "fresh" — but `updatedAt = 0` claims the data was last updated at the Unix epoch. Standard integrator code such as:

```solidity
(, int256 price, , uint256 updatedAt, ) = feed.latestRoundData();
require(updatedAt > block.timestamp - 1 hours, "stale feed");
```

will revert on every call, unconditionally. The `IAggregatorV3Minimal` interface the contract implements explicitly advertises these return fields as "Chainlink's `latestRoundData` return values" (`contracts/interfaces/morpho/IAggregatorV3Minimal.sol#L10-L15`), so integrators have every reason to treat them as valid Chainlink semantics. The repo's own `IdleUsualStrategy.getChainlinkPrice()` (`contracts/strategies/usual/IdleUsualStrategy.sol#L164-L172`) demonstrates the expected pattern — it consumes `updatedAt` from an external feed and reverts on staleness, which is exactly the check that would always fail against `TranchesChainlinkOracle`.

### Impact Explanation
Any lending market, vault, or aggregator that wires `TranchesChainlinkOracle` as the price feed for an Idle tranche collateral and performs a freshness/`answeredInRound` sanity check will have every price-dependent operation (borrow, liquidate, withdraw collateral valuation) revert permanently. For an already-deployed market that validated the feed once at creation (e.g., checking `answeredInRound >= roundId` or a non-zero `updatedAt`), the market can be created but then all borrow/liquidation calls freeze, temporarily locking user funds supplied to that market until the oracle is swapped. Loss scope is the collateral/loan value gated behind any such integration for the duration it takes the integrator to migrate to a corrected feed.

### Likelihood Explanation
High for the affected integration path: the revert is unconditional and requires no attacker action — `updatedAt` is always `0`, so any staleness threshold fails 100% of the time. The only mitigating factor is that the primary intended consumer (`MorphoChainlinkOracleV2`, per the interface natspec) reads only `answer`, so the bug only manifests on integrators that additionally validate round metadata — a common Chainlink-integration pattern, as evidenced by the codebase's own `getChainlinkPrice`.

### Recommendation
Populate the round metadata truthfully instead of hardcoding zeros. At minimum return `block.timestamp` for `updatedAt`/`startedAt` and a non-zero round id / `answeredInRound`, e.g.:

```solidity
return (uint80(1), int256(cdo.virtualPrice(collateralToken)), block.timestamp, block.timestamp, uint80(1));
```

Alternatively, document prominently (on the contract and in the interface) that only `answer` is meaningful, so integrators do not rely on the zeroed fields.

### Proof of Concept
Foundry test against a deployed `TranchesChainlinkOracle` instance:

```solidity
function testIntegratorStalenessCheckReverts() public {
    TranchesChainlinkOracle oracle = new TranchesChainlinkOracle(address(trancheToken));

    (uint80 roundId, int256 answer, , uint256 updatedAt, uint80 answeredInRound) =
        oracle.latestRoundData();

    // answer is live and sane
    assertGt(answer, 0);
    // metadata is hardcoded
    assertEq(roundId, 0);
    assertEq(updatedAt, 0);
    assertEq(answeredInRound, 0);

    // standard integrator freshness check -> always reverts
    vm.expectRevert("stale price feed");
    this.checkFresh(oracle);
}

function checkFresh(TranchesChainlinkOracle oracle) external view {
    (, , , uint256 updatedAt, ) = oracle.latestRoundData();
    if (updatedAt < block.timestamp - 1 hours) revert("stale price feed");
}
```

`updatedAt` is `0` while `block.timestamp` is post-epoch, so `checkFresh` reverts on every call regardless of when it is invoked.
