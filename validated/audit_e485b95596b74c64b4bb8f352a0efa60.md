## Analysis

The report describes a bug class where error messages leak implementation details (library names, versions, internal diagnostics) to end users. Searching the codebase, most gateway/plugin error paths in this repo already sanitize user-facing errors (e.g., `errorMsg := userFacingError(ierr, "failed to handle get secret request")` in `core/services/ocr2/plugins/vault/plugin.go`, and `message = internalErrorMessage` in `core/capabilities/confidentialrelay/handler.go`). However, the node-side Vault gateway handler does not follow this pattern.

### Title
Vault Gateway Handler Leaks Raw Internal Error Strings to Unauthenticated Gateway Callers - (File: core/capabilities/vault/gw_handler.go)

### Summary
`GatewayHandler.errorResponse` in `core/capabilities/vault/gw_handler.go` places the raw `err.Error()` string directly into the JSON-RPC response sent back over the gateway to the calling client, with no redaction or generic-message substitution, unlike other handlers in the same codebase (e.g., the confidential relay handler and the OCR2 vault plugin, which both use sanitized/generic messages for internal errors).

### Finding Description
`GatewayHandler.errorResponse` builds the wire error message directly from the internal `error` value: `Message: err.Error()` [1](#0-0) . This function is invoked from every code path in `HandleGatewayMessage`, including `getMasterPublicKey`, `requestProcessor.ProcessRequest`, and the `handleSecretsCreate/Update/Delete/List` handlers [2](#0-1) .

The errors that flow into this path are frequently wrapped errors originating from underlying library calls rather than sanitized, user-safe messages:
- `MasterPublicKeyFromSecretsService` wraps errors from `hex.DecodeString` and `tdh2easy.PublicKey.Unmarshal` (e.g. `"failed to decode vault public key: %w"`, `"failed to unmarshal vault public key: %w"`) [3](#0-2) .
- `processCreateSecretsRequest`/`processUpdateSecretsRequest`/etc. wrap raw `encoding/json` unmarshal errors into `InvalidVaultParamsError` [4](#0-3) .
- `handlePublicKeyGet` wraps `secretsService.GetPublicKey` errors with `fmt.Errorf("failed to get public key: %w", err)` [5](#0-4) .

All of these ultimately surface as `resp.Error.Message` in the JSON-RPC response returned to the gateway (and from there to the requesting external caller), as confirmed by the test assertions that check exact error strings such as `"request not authorized: not allowlisted"` [6](#0-5) .

By contrast, sibling components in the same codebase deliberately avoid this pattern: the OCR2 vault reporting plugin uses `userFacingError(err, fallback)` to only pass through explicitly-marked `userError` messages and otherwise return a generic fallback string, logging full details only server-side [7](#0-6) ; and the confidential relay gateway handler substitutes a generic `internalErrorMessage` for internal errors instead of the raw `err.Error()` [8](#0-7) .

### Impact Explanation
An unprivileged/unauthenticated actor sending malformed or edge-case requests through the internet-facing gateway to the Vault node handler can trigger error paths that echo internal library error text (e.g., `tdh2easy` unmarshal failures, hex-decode failures, JSON unmarshal errors, or internal wrapper text like "failed to stamp authorized request params") back in the response. This is dependency-fingerprinting/reconnaissance information disclosure consistent with the reported bug class, though it does not by itself grant authentication bypass, secret disclosure, or fund movement — the impact is limited to information leakage that could aid further targeted attacks.

### Likelihood Explanation
High likelihood of triggering: any external, unauthenticated caller of the gateway's Vault JSON-RPC endpoint can supply malformed params, invalid public key material, or requests that fail authorization/validation, all of which are directly reachable from `HandleGatewayMessage` without requiring any special privilege, and the code path unconditionally forwards `err.Error()`.

### Recommendation
Adopt the same pattern already used elsewhere in this codebase: classify errors as user-facing vs. internal (as `userFacingError`/`logUserErrorAware` do in `core/services/ocr2/plugins/vault/plugin.go`, or as `internalErrorMessage` does in `core/capabilities/confidentialrelay/handler.go`), and have `GatewayHandler.errorResponse` in `core/capabilities/vault/gw_handler.go` return only a generic, non-sensitive message for internal/wrapped library errors while logging the full error server-side via `h.lggr`/`reqLggr`. Preserve detailed wrapped error text (`%w` from `hex`, `json`, `tdh2easy`, etc.) exclusively in logs, not in the JSON-RPC `Error.Message` field returned to the gateway/caller.

### Proof of Concept
1. Send a `MethodSecretsCreate`/`MethodSecretsUpdate` JSON-RPC request through the gateway with `EncryptedValue` or key material that fails `tdh2easy` unmarshal/decoding, or trigger `getMasterPublicKey` before the master key is provisioned.
2. Observe the JSON-RPC response's `error.message` field, which — per `gw_handler.go`'s `errorResponse` — contains the raw wrapped error text (e.g., `"failed to get vault public key: ..."`, `"failed to decode vault public key: ..."`, `"failed to unmarshal vault public key: ..."`), directly derived from internal library call failures rather than a generic message.

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)
		}

// MasterPublicKeyFromSecretsService loads the vault master public key from a secrets service.
func MasterPublicKeyFromSecretsService(ctx context.Context, secretsService vaulttypes.SecretsService) (*tdh2easy.PublicKey, error) {
	resp, err := secretsService.GetPublicKey(ctx, &vaultcommon.GetPublicKeyRequest{})
	if err != nil {
		return nil, fmt.Errorf("failed to get vault public key: %w", err)
	}
	if resp == nil || resp.PublicKey == "" {
		return nil, errors.New("vault public key is unavailable")
	}

	masterPublicKeyBytes, err := hex.DecodeString(resp.PublicKey)
	if err != nil {
		return nil, fmt.Errorf("failed to decode vault public key: %w", err)
	}

	masterPublicKey := &tdh2easy.PublicKey{}
	if err := masterPublicKey.Unmarshal(masterPublicKeyBytes); err != nil {
		return nil, fmt.Errorf("failed to unmarshal vault public key: %w", err)
	}
	return masterPublicKey, nil

func userFacingError(err error, fallback string) string {
	if errors.Is(err, &userError{}) {
		return err.Error()
	}

	return fallback
}

func logUserErrorAware(l logger.Logger, msg string, err error, keysAndValues ...any) {
	keysAndValues = append(keysAndValues, "error", err)
	lggr := l.Helper(1)
	if errors.Is(err, &userError{}) {
		lggr.Debugw(msg, keysAndValues...)
		return
	}

	lggr.Errorw(msg, keysAndValues...)
}

func (h *Handler) errorResponse(
	ctx context.Context,
	gatewayID string,
	req *jsonrpc.Request[json.RawMessage],
	errorCode int64,
	err error,
) *jsonrpc.Response[json.RawMessage] {
	h.lggr.Errorw("request error", "errorCode", errorCode, "err", err)
	h.metrics.requestInternalError.Add(ctx, 1, metric.WithAttributes(
		attribute.String("gateway_id", gatewayID),
		attribute.Int64("error_code", errorCode),
	))

	message := err.Error()
	if errorCode == jsonrpc.ErrInternal {
		message = internalErrorMessage
	}
