Confirmed: `delete_member` in `multisig2/src/lib.rs` only removes requests *created* by the deleted member and their `num_requests_pk` entry — it never scrubs that member's `confirmations` entries from *other* requests where they were merely a confirmer. This creates a stale-confirmation/live-member divergence, matching the analog category "confirmations counted versus live members."

### Title
Stale confirmations from removed multisig members count toward execution threshold - (multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` cleans up only the requests originated by the removed member, but leaves that member's confirmation entries intact on any other pending request they had previously confirmed. `confirm()` counts confirmations purely by set size (`confirmations.len() as u32 + 1 >= self.num_confirmations`) without checking that every confirming identity is still a current member, so a stale confirmation from a now-removed member still counts toward the threshold.

### Finding Description
`confirm()` at [1](#0-0)  checks membership only for the *current* caller via `current_member()`, then decides execution solely from `confirmations.len()`. `delete_member` at [2](#0-1)  removes requests keyed by the deleted member as the *request signer* (`r.member == member`) and clears `num_requests_pk`, but never iterates `confirmations` to strip the deleted member's votes from requests they only confirmed (not created). The binding that should hold is: `confirmations recorded for request R ⊆ {current live members}`. After a member is removed, this binding breaks — a stale confirmation from a non-member remains counted.

### Impact Explanation
This lets a request reach the "K confirmations" threshold with fewer than K *live* signers, i.e., a multisig request executed below the intended live threshold — the exact "Critical" impact class listed ("a multisig request executed below threshold"). An attacker scenario: member A confirms a Transfer/AddKey request (1 of K confirmations), is later removed via `DeleteMember` (e.g., legitimately offboarded), and the remaining members unknowingly need only K-1 more live confirmations to hit `confirmations.len()+1 >= num_confirmations`, executing an action that was never actually approved by K live members.

### Likelihood Explanation
Requires no privileged action by an attacker beyond being (or having been) a legitimate member who confirms a request before being removed — a plausible operational sequence (member turnover, key rotation, or compromised-key removal) rather than a contrived edge case. It does not require redeploy, foundation action, or a victim key beyond normal multisig member lifecycle events already supported by the contract's own `DeleteMember` action.

### Recommendation
In `delete_member`, iterate all pending `requests`/`confirmations` and remove the deleted member's entry from every confirmation set (not just requests they signed), or alternatively, have `confirm()`/execution filter confirmations against current `self.members` before comparing count to `num_confirmations`.

### Proof of Concept
1. Deploy multisig2 with members `[A, B, C, D]`, `num_confirmations = 3`.
2. `A` calls `add_request_and_confirm(Transfer{...})` → confirmations = `{A}`.
3. Separately, `B` and `A` are both confirmers is not required; instead: members vote to `DeleteMember{A}` via a separate request (requires 3 confirmations, executes, `A` removed from `members`) — this only cleans requests where `A` was the *signer*, not the Transfer request confirmation set, which still contains `A`.
4. `B` calls `confirm(transfer_request_id)` → confirmations = `{A, B}`, len+1=3 ≥ 3.
5. `C` (or `B` again with a different key context) is not even needed — the third confirmation slot is effectively already filled by the stale `A` entry, so the Transfer executes with only 2 live confirmations (`A`-stale + `B`) instead of 3, breaking the K-of-N custody guarantee.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
