### Title
Stale confirmations from removed multisig members are counted toward quorum, allowing request execution below threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only purges pending requests that were *created* by the removed member; it does not scan and purge that member's *confirmations* recorded on other members' pending requests. `confirm` later counts the size of the stored confirmation set without re-validating that every entry is still a current member. As a result, a member who is removed from the multisig can still contribute a "ghost" confirmation that counts toward the `num_confirmations` threshold, letting a request execute with fewer live confirmers than the configured K-of-N quorum.

### Finding Description
In `execute_request`, `MultiSigRequestAction::DeleteMember` calls `delete_member`: [1](#0-0) 

`delete_member` only removes requests where `r.member == member` (i.e. requests the removed member originally *added*), and clears the confirmation set for those specific requests. It never iterates over `self.confirmations` for requests added by *other* members to strip out the removed member's vote from that request's confirmation `HashSet<String>`.

`confirm` then decides whether to execute purely from the stored set's cardinality: [2](#0-1) 

```rust
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
}
```

There is no check that every string in `confirmations` still corresponds to an entry in `self.members` (`UnorderedSet<MultisigMember>`, checked only via `current_member()` for the *caller*, not for historical entries).

The binding that should hold is:
```
confirmations_counted(request) == confirmations_from_current_members(request)
```
After a `DeleteMember` execution, this equality is broken for any request that the deleted member had already confirmed but did not create: `confirmations_counted(request)` still includes the removed member's vote even though that member is no longer in `self.members`.

### Impact Explanation
This breaks the multisig's core K-of-N guarantee: a request (which can be `Transfer`, `AddKey`, `AddMember`, `DeleteMember`, `FunctionCall`, `DeployContract`, etc.) can be executed with fewer than `num_confirmations` *live, currently-authorized* signers. This falls under "Critical — a multisig request executed below threshold," since it allows moving funds or changing multisig membership/keys with an effectively lowered quorum, undermining the authorization boundary the contract is meant to enforce.

### Likelihood Explanation
This requires no attacker privilege beyond normal multisig operation: it can occur any time a member is removed while they have an outstanding confirmation on another pending request (a routine sequence — e.g. offboarding a team member who had already confirmed a pending transfer). No malicious insider, redeploy, or victim key compromise is needed; it is a straightforward ordering of legitimate multisig actions (`confirm` then later `DeleteMember`, then further `confirm`s reaching the stale-inflated count).

### Recommendation
When removing a member in `delete_member`, iterate over `self.confirmations` for *all* pending requests (not only ones created by that member) and remove the member's entry from each confirmation set. Alternatively, in `confirm`, before counting, filter `confirmations` to only those entries still present in `self.members` (and persist the filtered set), so the quorum check only counts votes from currently active members.

### Proof of Concept
Assume multisig initialized with 4 members `A, B, C, D` and `num_confirmations = 3`.

1. `A` calls `add_request(R)` (a `Transfer` request) — `R.member = A`, confirmations = `{}`.
2. `B` calls `confirm(R)` → confirmations = `{B}` (1 < 3, not yet executed).
3. `C` calls `confirm(R)` → confirmations = `{B, C}` (2 < 3, not yet executed).
4. Separately, a `DeleteMember { member: B }` request is created and confirmed by the required quorum, executing `delete_member(promise, B)`:
   - `delete_member` only looks for requests where `r.member == B` (i.e. requests *created* by B). `R` was created by `A`, so it is untouched — `B`'s entry stays in `R`'s confirmation set (`{B, C}`).
   - `B` is removed from `self.members` and its access key is deleted (`multisig2/src/lib.rs` lines 356-379).
5. `D` calls `confirm(R)`:
   - `confirmations.len() as u32 + 1` = `2 + 1 = 3 >= num_confirmations (3)` → `execute_request(R)` runs.
   - The transfer executes even though only `C` and `D` are actual live confirmers among current members — `B`'s stale confirmation (from a now-removed member) was counted to reach the threshold. [3](#0-2) [1](#0-0)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
