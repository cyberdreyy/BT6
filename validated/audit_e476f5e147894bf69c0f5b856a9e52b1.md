### Title
APR0 withdraw receipt permanently reverts `stopEpoch` after a routine APR change, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
The external report is a NULL-pointer dereference crash (DoS) in Bento4. The closest on-chain analog is a state-dereference that always reverts: `IdleCreditVault.prepareStopEpochWithApr0` unconditionally reverts when `apr0TotalPrincipal != 0` and `unscaledApr != 0`. An unprivileged KYC'd lender can open a dust APR0 withdraw request; once the (honest) manager sets a non-zero APR mid-epoch, every `stopEpoch`/`stopEpochWithDuration` call reverts in `IdleCDOEpochVariant._stopEpoch` before the try/catch, so the epoch can never close and borrower-held principal cannot be recalled.

### Finding Description
`requestWithdraw` routes requests into the APR0 bucket only when `unscaledApr == 0`, incrementing `apr0TotalPrincipal` via `_requestWithdrawApr0`. `prepareStopEpochWithApr0` reverts with `NotAllowed` whenever `apr0TotalPrincipal != 0 && unscaledApr != 0` [1](#0-0) . The only paths that clear `apr0TotalPrincipal` are `prepareStopEpochWithApr0` itself (line 540) and the default-claim path `_clearWithdrawClaimForEpoch` (line 827), which requires `defaultRecoveryFinalized`. Because `_stopEpoch` calls `prepareStopEpochWithApr0` outside the `try this.getFundsFromBorrower` block, the revert bubbles up and `_handleBorrowerDefault` is never reached [2](#0-1) . `setApr`/`setAprsWithBuffer` can be called by the honest manager (or CDO) at any time and set `unscaledApr` directly [3](#0-2) .

Attack sequence:
1. Pool runs an epoch with `unscaledApr == 0` (a supported mode; `_requestWithdrawApr0` exists specifically for it).
2. Attacker (KYC-passing lender) deposits, then calls `requestWithdraw` on the CDO with a minimal tranche amount → `apr0TotalPrincipal = dust`, `pendingWithdraws` increases.
3. During the same epoch, the manager calls `setAprsWithBuffer(newApr, ...)` with `newApr != 0` — a routine, honest configuration change for the next period (or the CDO itself sets it via `_setScaledApr` after a prior stop while a new APR0 request exists — same precondition).
4. At `epochEndDate`, `stopEpoch`/`stopEpochWithDuration` always reverts at `prepareStopEpochWithApr0`. No code path remains to settle or delete the attacker's request (there is no user-facing cancel for a strategy-level request; the queue's `deleteWithdrawRequest` only covers queue-held requests before processing).

### Impact Explanation
Permanent freezing of all LP and queue funds: while `unscaledApr != 0` and `apr0TotalPrincipal != 0`, the epoch state machine cannot advance, borrower repayment cannot be pulled, withdraw claims cannot be funded, and `_handleBorrowerDefault` cannot trigger because the revert happens before the try/catch. The attacker risks only a dust receipt (its tranche tokens are already burned/minted as a receipt). Recovery requires the manager to set APR back to 0 and successfully stop the epoch — i.e., the protocol is bricked until a specific config rollback, and if that path is unavailable or the borrower meanwhile fails to repay, the freeze becomes permanent insolvency. At minimum this is temporary freezing of 100% of vault TVL induced by a dust-cost unprivileged action.

### Likelihood Explanation
Medium. It requires (a) a pool operating at APR 0, which the codebase explicitly supports (`_requestWithdrawApr0`, `apr0RateByEpoch`), and (b) an APR change while an APR0 request is open — a normal managerial operation (`setApr` is callable any time by manager). The attacker's only cost is one dust withdraw request plus KYC. The revert is deterministic, not conditional on rounding or timing.

### Recommendation
In `prepareStopEpochWithApr0`, do not hard-revert on `unscaledApr != 0`. Either settle the open APR0 bucket at a zero rate (write `apr0RateByEpoch[epochNumber] = 0`, zero `apr0TotalPrincipal`, and let `_settleApr0` migrate principal to `settledPrincipal`), or snapshot `unscaledApr` per request epoch so a mid-epoch APR change cannot invalidate outstanding receipts. Alternatively, gate `setApr`/`setAprsWithBuffer` to revert (or epoch-transition only) while `apr0TotalPrincipal != 0`, so the inconsistent state is unreachable.

### Proof of Concept
```solidity
// test/foundry/Apr0StopEpochBrick.t.sol — run against mainnet-forked pool in APR0 mode
function testApr0ReceiptBricksStopEpoch() external {
    // pool is configured with unscaledApr == 0; epoch is running
    // attacker: KYC'd lender deposits 1 wei worth of tranches and requests withdraw
    deal(address(underlying), attacker, 1);
    vm.startPrank(attacker);
    underlying.approve(address(cdoEpoch), 1);
    uint256 tr = cdoEpoch.depositAA(1);
    cdoEpoch.requestWithdraw(tr, address(tranche));
    vm.stopPrank();
    assertGt(strategy.apr0TotalPrincipal(), 0);

    // honest manager updates APR for the next period mid-epoch
    vm.prank(manager);
    strategy.setAprsWithBuffer(5e18, 30 days, bufferPeriod); // unscaledApr != 0 now

    // epoch ends; every stop path reverts in prepareStopEpochWithApr0
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(address(underlying), borrower, type(uint120).max);
    vm.prank(borrower); underlying.approve(address(cdoEpoch), type(uint256).max);

    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpochWithDuration(5e18, 0, 30 days, 0);

    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 1); // even the recall-everything close path reverts

    // vault remains in running epoch forever; borrower funds unrecoverable via CDO
    assertTrue(cdoEpoch.isEpochRunning());
}
```

  function setAprsWithBuffer(uint256 _unscaledApr, uint256 _duration, uint256 _buffer) external {
