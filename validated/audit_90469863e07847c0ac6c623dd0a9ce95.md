### Title
Zip extraction path traversal (zip-slip) due to missing containment check — divergent from tarzstd extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`helpers/archives/zip_extract.go` extracts zip entries using `file.Name` directly in `os.Mkdir`, `os.OpenFile`, and `os.Symlink` calls with no path canonicalization or containment check against the target extraction directory, unlike `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, which explicitly joins against a `dir` root and rejects any resolved path that escapes it via a `strings.HasPrefix` check. The only path validation present in the zip path is `errorIfGitDirectory`, which merely warns about `.git` paths and does not prevent `../` traversal.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates zip entries and calls `extractZipFile(file)` for each, which dispatches to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, or `extractZipFileEntry` — all of which use `file.Name` verbatim: [1](#0-0) [2](#0-1) 

There is no `filepath.Abs`/`filepath.Join` against a fixed extraction root, and no `HasPrefix`/containment check anywhere in this file. The only guard, `errorIfGitDirectory`, only checks whether the first path component is `.git`, unrelated to traversal: [3](#0-2) 

By contrast, `tarzstd`'s extractor computes `path = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and explicitly rejects any path that does not have `e.dir` as prefix: [4](#0-3) 

This zip extraction code is reachable from job-controlled artifact/cache zip archives via `ziplegacy`'s extractor, which is a thin wrapper directly calling `archives.ExtractZipArchive`: [5](#0-4) 

This is registered via the generic `archive.Register`/`archive.NewExtractor` mechanism keyed by `Format` (`Zip`, `ZipZstd`), used by commands such as `commands/helpers/cache_extractor.go` and `commands/helpers/artifacts_downloader.go` — both of which extract archives whose contents (file names inside the zip) originate from cache/artifact data that, depending on configuration/history, can be attacker (job)-influenced, since a job can create arbitrary cache/artifact zip content with a `zip.FileHeader.Name` field containing `../` sequences (this is the classic "zip-slip" vector). Note: `fastzip`'s extractor (`commands/helpers/archive/fastzip/zip_fastzip_extractor.go`) delegates to the third-party `saracen/fastzip` library, which is a separate code path not audited here; the divergence in question is specifically between the runner's own zip path (`ziplegacy` → `helpers/archives/zip_extract.go`) and the runner's own tar/zstd path.

The two subsystems therefore implement genuinely divergent containment logic: tarzstd enforces containment, plain zip extraction does not, confirming the premise of the question — there is no single shared canonicalization+containment function used by both.

### Impact Explanation
If the `ziplegacy` zip extractor is selected (e.g., for `Zip`/`ZipZstd` format extraction of cache or artifacts), a crafted zip archive with entries named like `../../../../home/user/.ssh/authorized_keys` or `../../etc/cron.d/x` can write files outside the intended build/cache directory on the extracting host, when that extraction runs with the runner/job process's filesystem privileges (e.g., shell executor, or extraction happening in a mounted volume in Docker executor). This directly violates the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Exploitability depends on whether the `ziplegacy` extractor path is actually selected at runtime rather than `fastzip` (need to verify format registration/selection order, which was not fully confirmed here due to iteration limits). If `ziplegacy` is used (e.g., as a fallback or explicitly configured), the attack is straightforward and fully reproducible: any job can push a cache or artifact zip with crafted entry names, no special privileges required beyond normal CI job authoring capability.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: compute the resolved absolute path against a fixed extraction root and reject entries whose resolved path is not prefixed by that root (or use `filepath.IsLocal`/equivalent), for directory, file, and symlink target entries alike (symlink targets must also be validated, not just the link path itself). Ideally, factor this into a single shared containment helper used by all extractors (zip, tarzstd, fastzip wrapper) so the invariant the question asks about actually exists in the codebase.

### Proof of Concept
Go test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideMarker := filepath.Join(tmpDir, "..", "zip_slip_pwned")
    defer os.Remove(outsideMarker)

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../zip_slip_pwned")
    w.Write([]byte("pwned"))
    zw.Close()

    wd, _ := os.Getwd()
    os.Chdir(tmpDir)
    defer os.Chdir(wd)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := ExtractZipArchive(zr)
    assert.NoError(t, err) // currently succeeds

    _, statErr := os.Stat(outsideMarker)
    assert.NoError(t, statErr, "file was written outside extraction directory: zip-slip succeeded")
}
```
Differential companion test: run an equivalent `../` payload through `tarzstd.extractor.Extract` with `dir=tmpDir` and assert it returns an error containing `"cannot be extracted outside of chroot"`, demonstrating the divergence — tarzstd rejects, zip silently writes outside root.

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```
