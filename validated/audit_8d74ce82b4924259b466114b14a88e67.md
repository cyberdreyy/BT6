### Title
Symlink-target validation missing in tarzstd extractor allows cross-archive path traversal write outside `e.dir` - ([File: commands/helpers/archive/tarzstd/tarzstd_extractor.go])

### Summary
The tarzstd extractor validates only that a tar entry's *own* path stays under `e.dir` via a textual `filepath.Abs`+`strings.HasPrefix` check, but never validates or restricts the target (`hdr.Linkname`) of symlink entries before calling `os.Symlink` [5](#0-4) . Because `restore_cache` and `download_artifacts` both extract into the same persistent job build directory across separate `Extract()` invocations [2](#0-1) , an attacker-controlled cache/artifact archive can plant an unrestricted symlink in one extraction, and a later extraction's regular-file entry can traverse through that symlink to write outside `e.dir`.

### Finding Description
In `Extract`, the path check at lines 57-64 only verifies that the *entry's own destination path* is textually under `e.dir`; when the entry is a symlink it is deferred and later created with `os.Symlink(hdr.Linkname, path)` at line 114 with **no check whatsoever on `hdr.Linkname`** — the symlink can point to any absolute or relative path, including outside `e.dir` entirely. Within a single archive this specific chained attack (symlink then file-through-symlink) is naturally blocked because symlink creation is deferred to after the main loop, so a regular-file entry named `<symlink>/payload` in the same archive causes `os.MkdirAll` to create a real directory before the symlink is later attempted, causing `os.Symlink` to fail. However, `restore_cache` and `download_artifacts` are executed as separate shell stages, each invoking a fresh helper process (`cache-extractor` / `artifacts-downloader`) with a new `extractor` instance, both using `wd = FullProjectDir()` as `e.dir` [6](#0-5) [7](#0-6) . So a symlink planted (and persisted to disk) by a first `Extract()` call survives into a second, independent `Extract()` call that operates on the same directory tree. In the second call, an entry named e.g. `planted/payload` passes the textual prefix check (it only looks at the literal joined string), then `os.MkdirAll(filepath.Dir(path))` calls `os.Stat` on `e.dir/planted`, which follows the symlink and returns the *target's* directory info, so `MkdirAll` short-circuits and does nothing; `os.Create(path)` at line 88 then resolves the `planted` component through the symlink at the OS level and creates `payload` inside the symlink's target — which can be anywhere the job process has write access, entirely outside `e.dir`.

### Impact Explanation
A pipeline author who controls both a cache archive and an artifact archive consumed by the same job (or two archives extracted sequentially into the same build directory) can write arbitrary regular files to any location writable by the job/helper process outside the intended job root — e.g., overwriting files in shared writable paths, or elsewhere in the container/host filesystem depending on the executor's mount layout and job user privileges. This breaks the file-operations-stay-within-root invariant.

### Likelihood Explanation
Feasible and repeatable: the attacker needs control over the contents of two archives extracted into the same build directory during the same job (their own cache push and their own/dependency's artifact upload, or a fallback cache key plus artifacts), which are both standard, unprivileged, user-controlled inputs. `restore_cache` runs before `download_artifacts` in `prepare()` [8](#0-7) , giving a deterministic ordering to plant the symlink first and traverse it second.

### Recommendation
Validate `hdr.Linkname` similarly to entry paths before creating symlinks (reject absolute paths and any target that resolves outside `e.dir`), and additionally re-validate the fully-resolved (symlink-following) real path of each entry's parent directory at extraction time (e.g., using `filepath.EvalSymlinks` on the existing portion of the path, or opening intermediate directories with `O_NOFOLLOW`/`openat`-style safe-join helpers) rather than relying solely on textual prefix comparison of an unresolved path.

### Proof of Concept
Go integration test in `commands/helpers/archive/tarzstd`:
1. Create dir `e.dir`, and a second sibling dir `outside` (not under `e.dir`).
2. Build tar+zstd archive A containing a single symlink entry `planted` -> `../outside` (or an absolute path to `outside`).
3. Call `NewExtractor(...).Extract(ctx)` with archive A into `e.dir`; assert `e.dir/planted` is a symlink pointing outside `e.dir`.
4. Build tar+zstd archive B containing one regular file entry `planted/payload` with known content.
5. Call `NewExtractor(...).Extract(ctx)` with archive B into the same `e.dir`.
6. Assert either: (a) extraction fails with a chroot-violation error, or (b) `outside/payload` does NOT exist and no file was written outside `e.dir` — verifying invariant; currently the test would show `outside/payload` exists with attacker content, proving the escape.

//nolint:gocognit
func (r *Runner) prepare(ctx context.Context) error {
	if err := r.section(ctx, "get_sources", r.config.GetSources.Run); err != nil {
		return fmt.Errorf("fetching sources: %w", err)
	}

	// Reload so KEY=VALUE entries appended by pre_clone_script / post_clone_script flow into downstream stages.
	if hasCacheSources(r.config.CacheExtract) {
		r.loadGitlabEnv()
		_ = r.section(ctx, "restore_cache", func(ctx context.Context, e *env.Env) error {
			for _, cache := range r.config.CacheExtract {
				if len(cache.Sources) == 0 {
					continue
				}
				if err := cache.Run(ctx, e); err != nil {
					r.logWarningf("Failed to restore cache %q: %v", cache.Sources[0].Key, err)
				}
			}
			return nil
		})
	}

	if len(r.config.ArtifactExtract) > 0 {
		r.loadGitlabEnv()
		_ = r.section(ctx, "download_artifacts", func(ctx context.Context, e *env.Env) error {
			for _, artifact := range r.config.ArtifactExtract {
				if err := artifact.Run(ctx, e); err != nil {
					r.logWarningf("Failed to download artifact %q: %v", artifact.ArtifactName, err)
				}
			}
			return nil
		})
	}

	return nil
}
