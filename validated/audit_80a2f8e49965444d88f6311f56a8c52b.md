## Title
Operator-controlled beneficiary can permanently strand a staker's already-unlocked stake in `staking_contract::distribute_internal` - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`distribute_internal` withdraws all inactive/pending_inactive coins from the stake pool up front and then loops over every shareholder of the internal `distribution_pool`, calling `aptos_account::deposit_coins` for each one in a single all-or-nothing transaction [1](#0-0) . If any single recipient in that loop cannot accept the deposit, the whole transaction aborts, rolling back the withdrawal for every other recipient too — this is structurally the same "one uncooperative party blocks distribution to everyone else" pattern as the ERC-1155 gas-griefing report, except the failure mode here is a hard `abort` from `aptos_account::deposit_coins` rather than an out-of-gas revert.

### Finding Description
`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has not registered for the coin type and has explicitly opted out of unsolicited transfers via `can_receive_direct_coin_transfers` / `set_allow_direct_coin_transfers` [2](#0-1) [3](#0-2) .

In `staking_contract::distribute_internal`, the distribution pool's `shareholders()` are iterated in a `while` loop and, for each one, `aptos_account::deposit_coins(recipient, ...)` is called, with the operator's share redirected to `beneficiary_for_operator(operator)` [4](#0-3) . The operator alone controls this beneficiary address via `set_beneficiary_for_operator`, which performs no validation that the new beneficiary can actually receive APT [5](#0-4) . This is in sharp contrast to `vesting::set_beneficiary`, which explicitly guards against this exact scenario by requiring `assert_account_is_registered_for_apt(new_beneficiary)` "so distribute() wouldn't fail and block all other accounts from receiving APT" [6](#0-5)  — `staking_contract::set_beneficiary_for_operator` has no such check.

Because `distribute_internal` is invoked not just from the permissionless `distribute` entry function but also from `unlock_stake`, `update_commision`, `request_commission`, and `switch_operator` [7](#0-6) , once the operator's beneficiary is (deliberately or accidentally) an address that rejects the deposit, every one of these staker-facing entry points becomes permanently unusable for that staking contract. The staker cannot withdraw their own inactive/pending_inactive stake, cannot switch away from the malicious operator (since `switch_operator` also forces `distribute_internal` on the old operator's contract first), and cannot adjust commission — all because coins already withdrawn from the stake pool (`stake::withdraw_with_cap`) cannot be returned to it, and the deposit to the operator's beneficiary keeps aborting.

### Impact Explanation
This breaks the "unlock/withdraw paths must not strand value permanently" invariant. An operator (who legitimately controls only their own beneficiary setting) can trap the staker's already-unlocked/inactive stake indefinitely by pointing their beneficiary at an address that has called `set_allow_direct_coin_transfers(false)` and never registered for `AptosCoin`. This is not "malicious peer/node behavior" or governance-privileged — it's a permissionless operator action against a staker who has no way to remedy it (the staker cannot change the operator's beneficiary, and every remediation path itself calls `distribute_internal`). This qualifies as a permanent, non-recoverable loss of claim rights for the staker under the required impact list.

### Likelihood Explanation
Requires only that (a) the operator is malicious or sets an incorrect/adversarial beneficiary and (b) `features::operator_beneficiary_change_enabled()` is on. No special privileges beyond the operator role (already required to interact with the staking contract) and no assumption that the attacker holds the staker's role. Given operators are often distinct, less-trusted entities from stakers in `staking_contract`/`vesting` setups, this is a realistic operational scenario, not a contrived edge case.

### Recommendation
Mirror the safeguard already present in `vesting::set_beneficiary`: require `aptos_account::assert_account_is_registered_for_apt(new_beneficiary)` (or equivalently `can_receive_direct_coin_transfers`) inside `staking_contract::set_beneficiary_for_operator` before allowing the change. Additionally/alternatively, make `distribute_internal` resilient to a single failing recipient (e.g., skip/queue the failed distribution instead of aborting the whole loop) so that one uncooperative recipient cannot block distribution to all other shareholders.

### Proof of Concept
1. Staker creates a staking contract with `operator` via `staking_contract::create_staking_contract`.
2. `operator` calls `aptos_account::set_allow_direct_coin_transfers(operator_beneficiary_signer, false)` on a fresh, never-APT-registered address `B` they control.
3. `operator` calls `staking_contract::set_beneficiary_for_operator(operator, B)` [5](#0-4) .
4. Stake pool accrues commission/rewards; any call to `distribute`, `unlock_stake`, `request_commission`, `update_commision`, or `switch_operator` triggers `distribute_internal`, which withdraws the pool's inactive stake and then tries `aptos_account::deposit_coins(B, ...)` for the operator's redeemed commission shares [8](#0-7) .
5. `deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` because `B` is unregistered and has opted out [9](#0-8) , reverting the entire transaction.
6. The staker's inactive stake (and any future unlock/withdraw/switch-operator attempt) is now permanently blocked as long as `B` remains in this non-accepting state — a condition entirely controlled by the operator.

Note: I was unable to fully verify with a locally-run Move unit test (no execution environment available here) whether AptosCoin's fungible-asset migration path in `coin::deposit`/`coin::is_account_registered` alters this exact abort behavior versus the legacy `CoinStore` path; the specs I found (`aptos_account.spec.move`) confirm the `deposit_coins` abort condition assuming `CoinStore`/registration semantics, but the current file's exact runtime branch for fully-migrated `AptosCoin` primary-fungible-store accounts should be independently confirmed before treating this as fully proven at the FA-migrated state.

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

        // Record a distribution for the staker.
        add_distribution(
            operator,
            staking_contract,
            staker_address,
            amount,
        );

        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            UnlockStake { pool_address, operator, amount, commission_paid }
        );
    }

    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
