### Title
Tranche shares minted on declared deposit amount instead of actual received, breaking fair mint for fee-on-transfer underlying - (File: contracts/IdleCDO.sol)

### Summary
`IdleCDO.depositAA`/`depositBB` pull `_amount` of underlying from the caller and mint tranche tokens through `_mintSharesAtCurrPrice(_amount, ...)`, which prices the mint on the caller-supplied `_amount` rather than the balance actually received. If the underlying token charges a fee on transfer (e.g. USDT/USDC enabling their dormant fee), the CDO receives less than `_amount` but mints shares as if it received the full amount, inflating `lastNAV`/`lastNAV*` accounting and diluting all other tranche holders.

### Finding Description
The deposit path in `IdleCDO.sol` performs:

```solidity
IERC20Detailed(token).safeTransferFrom(msg.sender, address(this), _amount);
...
_minted = _mintSharesAtCurrPrice(_amount, msg.sender, _tranche);
```

`_mintSharesAtCurrPrice` computes `_minted = _amount * ONE_TRANCHE_TOKEN / _tranchePrice(_tranche)` and `_mintShares` then adds `_amount` to the tranche's saved NAV [1](#0-0) . No `balanceOf` delta is measured. The same assumption propagates downstream: `TrancheWrapper._deposit` forwards the user-supplied `amount` to `depositAA`/`depositBB` [2](#0-1) , and `BaseStrategy.deposit` / `IdleCreditVault` deposit paths likewise trust the declared amount [3](#0-2) . IdleCDO underlyings are stablecoins (USDC/USDT-class), which carry a currently-disabled but activatable transfer fee.

### Impact Explanation
Violates the fair-mint invariant: a depositor receives tranche tokens (and the NAV is updated) for underlying the contract never received. The shortfall is socialized — on the next deposit/withdraw/harvest, `_virtualPriceAux` observes a lower real NAV than `lastNAV` and books a loss absorbed by BB holders first, then AA [4](#0-3) . Quantified loss equals `feeBps * _amount` per deposit, repeatable each epoch deposit.

### Likelihood Explanation
Requires the underlying token to enable a transfer fee (a future USDT/USDC configuration change, not attacker-controlled), so likelihood is conditional but the mechanism is deterministic once active. Any KYC-passing lender can exploit it on every deposit. No existing guard (default checks, skim, epoch gating) measures the received delta, so nothing blocks it.

### Recommendation
Measure the actual received amount in `IdleCDO._deposit` (and equivalently in `TrancheWrapper._deposit`, `IdleTokenWrapper._deposit`, `BaseStrategy.deposit`, and `IdleCreditVault` deposit paths):

```solidity
uint256 balBefore = IERC20Detailed(token).balanceOf(address(this));
IERC20Detailed(token).safeTransferFrom(msg.sender, address(this), _amount);
_amount = IERC20Detailed(token).balanceOf(address(this)) - balBefore;
```

Then call `_mintSharesAtCurrPrice` with the measured amount.

import "forge-std/Test.sol";
import {IdleCDO} from "../contracts/IdleCDO.sol";

contract FeeOnTransferToken {
    mapping(address => uint256) public balanceOf;
    mapping(address => mapping(address => uint256)) public allowance;
    uint256 public feeBps = 100; // 1% fee, mimics USDT fee-on-transfer
    function decimals() external pure returns (uint8) { return 6; }
    function approve(address s, uint256 a) external returns (bool) { allowance[msg.sender][s] = a; return true; }
    function transferFrom(address f, address t, uint256 a) external returns (bool) {
        allowance[f][msg.sender] -= a;
        balanceOf[f] -= a;
        balanceOf[t] += a - a * feeBps / 10_000;
        return true;
    }
    function mint(address to, uint256 a) external { balanceOf[to] += a; }
}

contract FeeOnTransferPoC is Test {
    function testDepositMintsOnUnreceivedAmount() public {
        // Setup: deploy IdleCDO with FeeOnTransferToken as `token`,
        // whitelisted attacker (allowAARequests enabled).
        FeeOnTransferToken t = new FeeOnTransferToken();
        address attacker = makeAddr("attacker");
        t.mint(attacker, 1_000_000e6);

        vm.startPrank(attacker);
        t.approve(address(cdo), type(uint256).max);
        uint256 minted = cdo.depositAA(1_000_000e6);
        vm.stopPrank();

        // CDO received 990_000e6 but minted shares + NAV for 1_000_000e6
        assertEq(t.balanceOf(address(cdo)), 990_000e6);
        // minted == 1_000_000e6 * ONE_TRANCHE_TOKEN / price → 1e24-ish
        // On withdrawal, attacker redeems more underlying than exists for him,
        // shortfall socialized to other tranche holders via _virtualPriceAux loss.
    }
}
