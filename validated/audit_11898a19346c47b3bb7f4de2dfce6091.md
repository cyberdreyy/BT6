### Title
Withdraw-receipt "epoch traversal": a lender escapes a `stopEpochWithDuration` loss haircut by issuing a new 1-wei withdraw request, then claims the haircutted receipt at par - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault` routes each user to the loss-adjusted claim path solely via `lastWithdrawRequest[_user]`, which is overwritten on every new `requestWithdraw`. A lender whose receipt was haircut in a loss epoch can request a dust withdraw in the next epoch, wait one epoch, and claim the entire aggregated `withdrawsRequests[_user]` — including the haircutted basis — at par through `_claimFundedWithdrawRequest`. This is the on-chain analog of CVE-2024-40348's directory traversal: an attacker-controlled index lets the caller walk out of the restricted "loss-adjusted" branch into the unrestricted "fully funded" branch.

### Finding Description
When `stopEpochWithDuration` realizes a loss, `collectWithdrawFunds` stores `lossRecoveryPriceByEpoch[epochNumber]` and clears `pendingWithdraws`, but each user's claim basis remains in `withdrawsRequests[_user]` and `withdrawsRequestsByEpoch[_user][epoch]` [1](#0-0) . The haircut is only applied in `_claimLossAdjustedWithdrawRequest`, which reads the loss epoch exclusively from `lastWithdrawRequest[_user]` [2](#0-1) . `requestWithdraw` unconditionally sets `lastWithdrawRequest[_user] = epochNumber` and piles onto `withdrawsRequests[_user]` without checking that the user holds an unclaimed, haircutted receipt [3](#0-2) . After re-requesting, `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]] == 0`, so the loss path is skipped and `_claimFundedWithdrawRequest` pays `normalAmount = withdrawsRequests[_user]` in full via `_transferFundedClaim` once `epochNumber > lastWithdrawRequest[_user]` (or immediately on a closed pool where `epochEndDate == 0`) [4](#0-3) . No guard (`_settleApr0`, `_hasWithdrawRequest`, receipt-book reconciliation) detects that part of that basis was only funded at `lossRecoveryPrice`.

### Impact Explanation
The attacker receives `claimBasis_lossEpoch × (1 − lossRecoveryPrice)` more underlying than entitled, paid from the strategy's funded underlying reserve collected for all pending receipts. Other loss-epoch claimants and funded receipt holders are left under-collateralized — direct theft / insolvency of the claim pool. Cost to the attacker is a dust re-request plus owning a small tranche position (a KYC-passing lender can do this; any holder of tranche tokens post-loss can acquire dust exposure). In the closed-pool mode (`epochEndDate == 0`) the exploit is immediate, no epoch wait required.

### Likelihood Explanation
Requires only: (a) a `stopEpochWithDuration` loss that leaves `lossRecoveryPrice > 0` (partial funding), (b) the attacker holding a pending receipt in that epoch, and (c) the ability to re-request withdraw — allowed while epochs run, and always possible in a closed pool. All attacker actions are unprivileged lender actions; owner/borrower/manager remain honest. The fix relies on users not re-requesting, which is an ordinary, encouraged action.

### Recommendation
In `requestWithdraw`, either revert when the user's last request epoch has a nonzero `lossRecoveryPriceByEpoch` that hasn't been claimed, or preserve the haircut: maintain a per-epoch claim mapping consumed in order, e.g. make `_claimFundedWithdrawRequest` exclude epochs with a nonzero `lossRecoveryPriceByEpoch`, or snapshot `lossEpoch` per user at request time so `lastWithdrawRequest` cannot be overwritten to skip it. At minimum, check `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]] != 0` and force settlement of the loss-adjusted receipt before accepting a new request.

### Proof of Concept
Foundry fork PoC (schematic; use the repo's existing fork setup with a live `IdleCDOEpochVariant` + `IdleCreditVault` pair):

```solidity
// test/Fork_LossClaimTraversal.t.sol
function test_escapeLossHaircut() public {
    // Setup: epoch running, attacker is a KYC'd lender holding tranche tokens.
    uint256 req = 1000e6; // attacker withdraw request basis
    vm.prank(attacker);
    cdo.requestWithdraw(req);              // epoch E: withdrawsRequestsByEpoch[attacker][E] = req

    // Honest manager stops epoch E with a partial loss: borrower funds only 50%.
    vm.prank(manager);
    cdo.stopEpochWithDuration(loss, duration); // -> collectWithdrawFunds(0.5*pendingBasis)
    // lossRecoveryPriceByEpoch[E] = 0.5e18; pendingWithdraws = 0; strategy holds 500e6

    // Epoch E+1 starts. Attacker deposits dust tranche amount and re-requests withdraw.
    vm.prank(manager); cdo.startEpoch(...);
    vm.prank(attacker); cdo.depositAA(1);           // or reuse residual tranche balance
    vm.prank(attacker); cdo.requestWithdraw(1);     // lastWithdrawRequest[attacker] = E+1

    // Epoch E+1 ends fully funded (or pool closed -> epochEndDate == 0, claim immediate).
    vm.prank(manager); cdo.stopEpoch(...);

    // Attacker claims: loss path skipped (price[E+1]==0), funded path pays full basis.
    uint256 balBefore = underlying.balanceOf(attacker);
    vm.prank(attacker); cdo.claimWithdrawRequest();
    // Assert: received ~req + dust at par instead of req*0.5
    assertGt(underlying.balanceOf(attacker) - balBefore, req * 6e17 / 1e18);
    // Assert: strategy's funded reserve is drained below obligations to other claimants.
}
```

Key assertions: `withdrawsRequests[attacker]` still contains the epoch-E haircutted basis, `lossRecoveryPriceByEpoch[E+1] == 0` so `_claimLossAdjustedWithdrawRequest` returns 0, and `_claimFundedWithdrawRequest` pays the aggregate at par from strategy-held underlyings earmarked for other receipt holders.

  function collectWithdrawFunds(uint256 _amount) external {
    _onlyIdleCDO();
    uint256 pendingBasis = pendingWithdraws;
    if (_amount < pendingBasis) {
      // Legacy receipts do not have per-epoch ownership data, so they can only be fully funded.
      if (!defaultRecoveryInitialized) revert NotAllowed();
      uint256 lossRecoveryPrice = _amount * RECOVERY_FULL / pendingBasis;
      // Avoid storing a zero price, which is indistinguishable from "no loss-adjusted epoch".
      if (lossRecoveryPrice == 0) revert NotAllowed();
      pendingWithdraws = 0;
      lossRecoveryPriceByEpoch[epochNumber] = lossRecoveryPrice;
    } else {
      // A plain implementation upgrade may leave legacy normal receipts pending. Their next
      // successful stop can fully fund the aggregate before lazy initialization occurs.
      pendingWithdraws = pendingBasis - _amount;
    }
    if (_amount != 0) {
      underlyingToken.safeTransferFrom(idleCDO, address(this), _amount);
    }
  }

  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
  }
