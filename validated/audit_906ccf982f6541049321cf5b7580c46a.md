### Title
Zip archive extraction allows path traversal via unsanitized `zip.File.Name` - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile`/`extractZipFileEntry` in `helpers/archives/zip_extract.go` write extracted files directly to `file.Name` with no path cleaning, no `filepath.Join` against a destination root, and no `filepath.Abs`/`HasPrefix` confinement check. This is in stark contrast to `tarzstd_extractor.go`, which joins entry names against `e.dir` and rejects any resulting path that escapes that root.

### Finding Description
`ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`) iterates `archive.File` and calls `extractZipFile(file)` for every entry, only checking `errorIfGitDirectory(file.Name)` (`helpers/archives/path_check_helper.go:21-31`), which merely blocks `.git`-prefixed paths and does nothing about `../` traversal or absolute paths.

`extractZipFile` (`helpers/archives/zip_extract.go:61-83`) does:
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
```
using `file.Name` verbatim (via `extractZipFileEntry`, lines 41-59). There is no `filepath.Join(dir, file.Name)`, no `filepath.Clean`, and no confinement check.

The zip entry point that actually matters for the runner's cache/artifact extraction is `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`:
```go
type extractor struct {
	r    io.ReaderAt
	size int64
	dir  string
}
func (e *extractor) Extract(ctx context.Context) error {
	zr, err := zip.NewReader(e.r, e.size)
	...
	return archives.ExtractZipArchive(zr)
}
```
Note that `e.dir` is stored but **never used** — it is not joined with entry names before calling `archives.ExtractZipArchive`. Compare this to `commands/helpers/archive/tarzstd/tarzstd_extractor.go:57-64`, which does the join + chroot validation:
```go
path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))
...
if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
	return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir)
}
```
The zip path has no equivalent logic anywhere in `helpers/archives/zip_extract.go` or `ziplegacy/zip_legacy_extractor.go`. Whatever mechanism positions the process's CWD at the intended extraction directory (e.g. `os.Chdir` in the calling command before invoking `Extract`), a `file.Name` value such as `../../../etc/cron.d/evil` will resolve relative to that CWD via normal OS path semantics and land outside the intended directory — there is no code path that rejects it.

### Impact Explanation
An attacker who controls the contents of a cache or artifact zip consumed by `gitlab-runner` (e.g. via cache/artifact poisoning, or supplying a crafted artifact) can have `ExtractZipArchive` write arbitrary files to arbitrary paths reachable by the runner process's permissions, escaping the job's cache/build directory. This can lead to unauthorized file write/overwrite outside the job workspace (e.g. overwriting files in parent directories of the extraction root, or anywhere writable by the runner user), matching the scoped impact of unauthorized file write outside job root.

### Likelihood Explanation
The zip extraction path (`ExtractZipFile`/`ExtractZipArchive`) is reached whenever the runner extracts a zip-format cache or artifact (`ziplegacy` extractor), which is exactly the "legacy zip" code path used for cache/artifact restore. Since cache and artifact contents (including file names inside the archive) are attacker-influenced in normal pipeline usage (an unprivileged pipeline author controls what gets zipped and uploaded as an artifact, or can poison a shared cache key), crafting a `zip.File.Name` with `../` segments is straightforward and repeatable with any standard zip-writing library that permits such names (Go's `archive/zip` does not prevent writing them).

### Recommendation
Add path confinement in the zip extraction path analogous to `tarzstd_extractor.go`: extraction must be routed through the destination root (`dir`) with `filepath.Join(dir, file.Name)`, `filepath.Clean`/`filepath.Abs`, and a `strings.HasPrefix(path, dir+separator)` (or `filepath.Rel` based) check that rejects any entry resolving outside the root before any `os.Mkdir`/`os.OpenFile`/`os.Symlink` call. This should be enforced inside `helpers/archives/zip_extract.go` (`extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`) by threading a destination-root parameter through `ExtractZipArchive`, and `ziplegacy/zip_legacy_extractor.go` should actually use its `e.dir` field rather than discarding it.

### Proof of Concept
Go unit test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
	tmpRoot := t.TempDir()
	extractDir := filepath.Join(tmpRoot, "job")
	require.NoError(t, os.MkdirAll(extractDir, 0o755))

	// build malicious zip in memory with entry "../../evil.txt"
	buf := &bytes.Buffer{}
	zw := zip.NewWriter(buf)
	w, _ := zw.Create("../../evil.txt")
	_, _ = w.Write([]byte("pwned"))
	require.NoError(t, zw.Close())

	oldWd, _ := os.Getwd()
	defer os.Chdir(oldWd)
	require.NoError(t, os.Chdir(extractDir))

	zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
	require.NoError(t, err)
	require.NoError(t, ExtractZipArchive(zr))

	// Assert file did NOT escape tmpRoot
	escapedPath := filepath.Join(tmpRoot, "evil.txt")
	_, statErr := os.Stat(escapedPath)
	assert.False(t, os.IsNotExist(statErr) == false, "path traversal wrote file outside extraction root: %s", escapedPath)
}
```
Expected (buggy) result: the assertion fails because `evil.txt` is created at `tmpRoot/evil.txt`, two levels above `extractDir`, proving the traversal. After applying the recommended chroot check (mirroring `tarzstd_extractor.go`), extraction should instead return an error like `"... cannot be extracted outside of chroot ..."` and no file should be created outside `extractDir`.
