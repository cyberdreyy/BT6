### Title
Unbounded recursive decoding of untrusted MPT nodes can crash the fault-proof program via stack overflow - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` recursively decodes nested trie nodes (`Branch` and `Extension`) with no depth limit, similar in shape to the HtmlUnit `CVE-2023-2798` recursion issue where unrestricted recursion over attacker-supplied content causes a stack overflow. This decoder is used by the fault-proof program to reconstruct Merkle Patricia Trie state from preimages fetched via the preimage oracle, which is attacker-influenced data during dispute-game execution.

### Finding Description
`TrieNode::decode` dispatches on the RLP header: if the header is a list of length 17 it decodes a `Branch` by recursively decoding a `Vec<Self>` (17 child `TrieNode`s), and if the list length is 2 it decodes a `Leaf`/`Extension` via `try_decode_leaf_or_extension_payload`, which itself recursively calls `Self::decode` for extension children: [1](#0-0) [2](#0-1) 

Nothing in this decode path bounds the recursion depth: an inner list item is only required to be a valid RLP list header (17 or 2 elements) to be treated as another `Branch`/`Extension` node and decoded via a fresh recursive call to `TrieNode::decode`/`Vec::<Self>::decode`. The type's own documentation notes that in a *canonical* trie, nodes larger than 32 bytes should be blinded with a keccak256 hash rather than embedded inline, but the decoder does not enforce this invariant — it will happily decode arbitrarily deep chains of inline (unblinded) `Branch`/`Extension` nodes if they are present in the input bytes: [3](#0-2) 

Each additional recursion level only costs a small, fixed number of bytes (a two‑item or seventeen‑item RLP list header plus mostly-empty (`0x80`) branch slots), so a modest-size preimage (tens of KB) can encode thousands of nesting levels, each consuming a stack frame.

This `TrieNode` decoding path is the core trie-node representation used throughout the `proof/mpt` crate that backs the fault-proof program's state/storage trie walking (`crates/proof/proof/src/l1/chain_provider.rs`, `crates/proof/proof/src/l2/chain_provider.rs`, `crates/proof/proof/src/eip2935.rs`), where trie node bytes are retrieved from the preimage oracle. In the permissionless dispute-game/fault-proof flow, the bytes behind a given preimage key are supplied by whichever party is executing the program against untrusted/adversarial preimage data (this is the "fault-proof program and MPT" path called out as in-scope). A malicious participant can therefore construct a preimage whose bytes decode as a deeply nested chain of inline `Branch`/`Extension` nodes.

### Impact Explanation
If a party responsible for running the fault-proof program (e.g. a challenger or verifying node) is fed a maliciously crafted, deeply-nested (but otherwise well-formed) MPT node preimage, `TrieNode::decode`'s unbounded recursion will exhaust the call stack and crash the process with a stack overflow (equivalent CWE-400/CWE-787 to the HtmlUnit advisory). This halts the specific execution of the fault-proof program, which can prevent a party from computing/verifying the output root for a dispute game, i.e. denial of service against the on-chain dispute resolution path and potentially a wrong/absent provable output root if the crash happens for the honest party while an adversary continues, undermining the security guarantees of the fault-proof system.

### Likelihood Explanation
The bug is reachable purely through data content: an attacker only needs to control the bytes of a single preimage that the fault-proof program will decode as a `TrieNode`. Constructing a deeply nested chain of minimal `Branch`/`Extension` RLP list headers requires no cryptographic work and is cheap in preimage size, making exploitation straightforward wherever `TrieNode::decode` is applied to attacker-influenced preimage bytes.

### Recommendation
Add an explicit recursion/depth counter (or convert the decoder to an iterative/worklist algorithm) in `TrieNode::decode`/`try_decode_leaf_or_extension_payload`, bounded by the maximum possible trie depth (e.g. 64 nibbles for a 32-byte key, plus a small safety margin), and reject any input that would require deeper nesting. Additionally, consider enforcing the documented invariant that inline (non-blinded) nodes must be ≤32 bytes, which would make it impossible to encode more than one level of unblinded nesting per input node.

### Proof of Concept
Construct nested RLP bytes representing:
```
Branch(children = [Extension(path, Branch(children=[Extension(path, Branch(...)), Empty×16]))..., Empty×16])
```
i.e., repeatedly wrap a `Branch` node (17-item list, 16 `0x80` empty slots + 1 nested `Extension`/`Branch`) thousands of times within a single buffer of a few tens of KB, then call:
```rust
TrieNode::decode(&mut bytes.as_slice())
```
Each nesting level adds one stack frame to the recursive `decode`/`Vec::<TrieNode>::decode` call chain; with enough levels (bounded only by available buffer size, not an explicit depth check), the process overflows its stack and crashes, matching the `TrieNode::decode` implementation at: [1](#0-0)

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}
