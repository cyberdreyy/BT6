### Title
`bt.Show` route lacks `RequiresEditRole` and leaks bridge `OutgoingToken` to view-role sessions - ([File: core/web/router.go], [File: core/web/bridge_types_controller.go], [File: core/web/presenters/bridges.go])

### Summary
The `authv2.GET("/bridge_types/:BridgeName", bt.Show)` route is registered without the `auth.RequiresEditRole` middleware that wraps `Create`, `Update`, and `Destroy`, so any authenticated session/API token — including a view-role account — can call it. `BridgeTypesController.Show` serializes the bridge with `presenters.NewBridgeResource`, which unconditionally includes the `OutgoingToken` field, disclosing the secret used to authenticate outbound calls to the external adapter.

### Finding Description
`core/web/router.go` registers the bridge_types routes in the `authv2` group; `Index` and `Show` are mounted as plain `authv2.GET(...)` handlers while `Create`, `Update`, and `Destroy` are wrapped with `auth.RequiresEditRole` (mirroring the pattern seen consistently for other mutating routes in the file). This means `Show` only requires passing session/API-key authentication (any role), not edit privilege.

`BridgeTypesController.Show` at [1](#0-0)  looks up the bridge by name and returns it via `presenters.NewBridgeResource(bt)` without any redaction. `NewBridgeResource` unconditionally copies `b.OutgoingToken` into the JSON response field `outgoingToken` (no `omitempty`, no role check): [2](#0-1) .

`IncomingToken` is not persisted on `bridges.BridgeType` (only a hash is stored), so it is not exposed via `Show` — that field is only populated transiently on `Create` from the freshly generated token (`resource.IncomingToken = bta.IncomingToken` at [3](#0-2) ). The `OutgoingToken`, however, is a persisted secret used to authenticate the node to the external adapter, and `FindBridge`/`Show`/`NewBridgeResource` returns it in plaintext to any caller who can reach the endpoint.

### Impact Explanation
Any authenticated caller with only view privileges (or any lower-privileged API token that can pass the generic `authv2` authentication middleware) can call `GET /v2/bridge_types/{BridgeName}` for a bridge they did not create and receive its `OutgoingToken` in the JSON response. This token is used by the node to authenticate itself to the external adapter, so its disclosure lets the attacker impersonate the node to that external system (submit spoofed job results, poison data feeding oracle jobs, or abuse rate-limited/paid external adapter accounts). This is a credential/secret disclosure crossing a role boundary — matching a "sensitive data exposure / unauthorized secret disclosure" bounty impact class.

### Likelihood Explanation
Exploitation only requires a valid view-role session or API token — a low, commonly granted privilege level in multi-user Chainlink node deployments (Chainlink supports admin/edit/run/view roles for GUI/API access). No special timing or race condition is needed; a single GET request to a known or guessable bridge name is sufficient, and it is fully repeatable.

### Recommendation
Wrap the `Show` (and consider `Index`) route with the same `auth.RequiresEditRole` middleware used for `Create`/`Update`/`Destroy`, or redact `OutgoingToken` from `BridgeResource` for non-edit-role callers (e.g., only populate it for editor/admin roles or omit it entirely from read responses, similar to how `IncomingToken` is only surfaced once at creation time).

### Proof of Concept
Go handler-level integration test plan (using existing `cltest` test harness patterns from `core/web/bridge_types_controller_test.go`):
1. Create an application and a bridge type via an edit/admin-role client (`POST /v2/bridge_types`), capturing the persisted `OutgoingToken`.
2. Create a second HTTP client authenticated with a view-role-only session/API token.
3. As the view-role client, issue `GET /v2/bridge_types/{BridgeName}` for the bridge created in step 1.
4. Assert the request succeeds (200 OK) — proving no role check blocked it.
5. Parse the JSON response and assert `data.attributes.outgoingToken` equals the value captured in step 1 (or simply assert it is non-empty), demonstrating secret disclosure to a caller lacking edit privileges.
6. As a control, repeat `POST/PATCH/DELETE /v2/bridge_types/...` with the same view-role client and assert these correctly return `401/403` due to `RequiresEditRole`, confirming the asymmetry is specific to `Show`.

```go
// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
```
