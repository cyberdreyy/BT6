### Title
Unauthenticated APR override while `idleCDO` is unset lets any EOA zero lender yield or force a default - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.setApr` deliberately skips its caller check when `idleCDO == address(0)`, treating the pre-wiring setup state as an open "default credential" window. Because `setAprs` and `setAprsWithBuffer` write `unscaledApr` and then delegate to `setApr`, any unprivileged address can rewrite both the scaled and unscaled APR between `initialize` and `setWhitelistedCDO`. This mirrors CVE-2025-56157: a shipped default configuration that leaves a privileged surface reachable by unauthenticated callers.

### Finding Description
In `contracts/strategies/idle/IdleCreditVault.sol:225-235`:

```solidity
function setApr(uint256 _apr) public {
    address _cdo = idleCDO;
    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
}
```

`initialize` (line 124) stores `_apr` into `lastApr`/`unscaledApr` but cannot set `idleCDO` — that only happens later via `setWhitelistedCDO` (line 954), which is a separate `onlyOwner` transaction. During that window the `msg.sender` gate is fully disabled, so `setApr`, `setAprs`, and `setAprsWithBuffer` are callable by anyone. `IdleCDOEpochVariant.startEpoch` reads `strategy.getApr()`/expected interest from `lastApr`, so the injected value propagates into `expectedEpochInterest` for the whole epoch.

Two concrete attack paths from the buffer phase (before the first `startEpoch`):

1. **Yield theft**: attacker calls `setAprs(0, 0)`. `expectedEpochInterest` is computed as 0 at epoch start, so at `stopEpoch` the borrower only returns principal. Lenders' entire epoch yield is permanently lost — no guard restores the APR mid-epoch and the loss is already crystallized into tranche prices.
2. **Forced default / fund freezing**: attacker calls `setApr(20e18)` (the `DEFAULT_MAX_APR` cap is the only bound). `expectedEpochInterest` inflates far above the honest borrower's planned repayment; the borrower's `stopEpoch` funding `transferFrom` fails, pushing the pool into `_handleBorrowerDefault`, pausing the CDO and haircutting all pending receipts and active NAV via `finalizeDefaultRecovery`.

### Impact Explanation
Any EOA can permanently destroy one full epoch of lender interest (bounded by `maxApr`, default 20% APR on total NAV) or force the pool into the default path, freezing lender funds and imposing the default-recovery haircut on all tranche holders. Loss is quantifiable: `NAV * min(injectedApr, maxApr) * (epochDuration + bufferPeriod) / YEAR`.

### Likelihood Explanation
Requires the deployment/upgrade window where `idleCDO` is still zero. This window necessarily exists in every deployment because `initialize` cannot set `idleCDO` and `setWhitelistedCDO` is a separate owner call; it also exists if a strategy is repurposed before wiring. The attack is front-runnable by anyone monitoring mempool/deployment, costs only gas, and the corrupted APR survives until an owner/manager notices and overwrites it — but any epoch started while the bad value is live locks in the damage.

### Recommendation
Remove the unauthenticated branch: require `msg.sender == owner()` (or the deployer factory) when `idleCDO == address(0)`, or set `idleCDO` atomically inside `initialize`/`setWhitelistedCDO` in the same transaction so no open window exists. Alternatively gate `setAprs`/`setAprsWithBuffer` behind `onlyOwner || onlyIdleCDO || manager` unconditionally.

import "forge-foundry/Test.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";

contract SetAprOpenWindowPoC is Test {
    // Deploy strategy + CDO via IdleCreditVaultFactory-equivalent setup,
    // but DO NOT call strategy.setWhitelistedCDO(cdo) yet.

    function test_AnyoneCanZeroAprBeforeWiring() public {
        IdleCreditVault strategy = IdleCreditVault(STRATEGY);
        assertEq(strategy.idleCDO(), address(0));
        uint256 aprBefore = strategy.lastApr();
        assertGt(aprBefore, 0);

        address attacker = address(0xBEEF);
        vm.prank(attacker);
        strategy.setAprs(0, 0); // no revert: idleCDO unset

        assertEq(strategy.lastApr(), 0);
        assertEq(strategy.unscaledApr(), 0);

        // Wire the CDO and run a normal epoch as honest owner/manager/borrower.
        // startEpoch computes expectedEpochInterest = 0 from lastApr;
        // at stopEpoch the borrower repays only principal.
        // Assert: idleCDO.expectedEpochInterest() == 0 and
        // AA/BB tranche prices gain no interest -> full epoch yield lost.
    }

    function test_AnyoneCanForceDefaultViaMaxApr() public {
        IdleCreditVault strategy = IdleCreditVault(STRATEGY);
        vm.prank(address(0xBEEF));
        strategy.setApr(strategy.maxApr()); // 20e18 default cap

        // After setWhitelistedCDO + startEpoch, expectedEpochInterest is
        // inflated to the 20% APR bound; the honest borrower's stopEpoch
        // funding transfer fails -> _handleBorrowerDefault, pause, and
        // recovery haircut for all receipt holders.
    }
}
