### Title
Unauthenticated request flooding exhausts confidentialrelay handler memory and DON fan-out capacity due to missing request-admission rate limiting - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` accepts any JSON-RPC request with a unique, non-empty `req.ID` (≤200 chars) and immediately reserves a slot in the shared `h.activeRequests` map via `newActiveRequest`, then fans the request out to every DON node via `fanOutToNodes`, with no allowlist, authentication, or rate-limit check gating admission. The handler's `globalNodeRateLimiter`/`perNodeRateLimiters` are only consulted inside `HandleNodeMessage` (node → gateway responses), never on the user-request admission path, so an unauthenticated caller can flood distinct request IDs to grow `h.activeRequests` unbounded and force full-DON fan-out per request, exhausting per-handler memory and node-facing send capacity shared with legitimate callers.

### Finding Description
The reachable path is: external caller → gateway HTTP endpoint → `gateway.ProcessRequest` (`core/services/gateway/gateway.go`) → `multiHandler.HandleJSONRPCUserMessage` → `confidentialrelay.handler.HandleJSONRPCUserMessage` [1](#0-0) . `ProcessRequest` only decodes the raw JSON-RPC request and resolves a handler/DON by service name or legacy DON ID before directly invoking `HandleJSONRPCUserMessage`; there is no authentication, signature verification, or allowlist check performed in this generic dispatch code prior to calling the handler [2](#0-1) .

Inside `confidentialrelay/handler.go`, `HandleJSONRPCUserMessage` only validates that `req.ID` is non-empty and ≤200 characters, then unconditionally calls `h.newActiveRequest` and `h.fanOutToNodes`: [3](#0-2) 

`newActiveRequest` takes `h.mu` and inserts a new `*activeRequest` into the single shared `h.activeRequests` map keyed by `req.ID`, with no cap on map size and no rate-limiter check: [4](#0-3) 

`fanOutToNodes` then sends the request to every DON member concurrently: [5](#0-4) 

By contrast, `h.globalNodeRateLimiter` and `h.perNodeRateLimiters` (constructed from `cresettings.Default.GatewayConfidentialRelayGlobalRate`/`...PerNodeRate` in `NewHandler`) are only consulted in `HandleNodeMessage`, which processes node → gateway responses, not user-request admission: [6](#0-5) 

This contrasts with the sibling `vault` and `capabilities/v2` handlers, which perform authorization (`requestProcessor.ProcessRequest` / JWT-based `authorizeRequest`) and rate limiting (`checkRateLimit`) before creating an active request or dispatching to nodes [7](#0-6) [8](#0-7) . `confidentialrelay/handler.go` has neither: any caller reaching this handler can generate unlimited distinct `req.ID`s, each reserving a map slot until it expires after `requestTimeout` (default 30s) or is force-cleared by the periodic sweep, and each causing an immediate send attempt to all DON nodes.

### Impact Explanation
This is a resource-exhaustion / denial-of-service vector: an attacker can grow `h.activeRequests` without bound (bounded only by wall-clock request rate and `requestTimeout`), consuming gateway memory, and can force repeated full-DON fan-out sends that consume node-facing bandwidth/connections and the node rate-limiter budget (`perNodeRateLimiters`) intended to protect legitimate subscribed users' request/response processing on `HandleNodeMessage`. This matches Chainlink's "Denial of Service" bounty impact class for a gateway/node component — degrading or disabling relay availability for legitimate DON members and their in-flight vault/relay requests.

### Likelihood Explanation
No credentials, authorization, or DON allowlist membership are required: this is reachable from `gateway.ProcessRequest`, which does not perform any auth check before invoking `HandleJSONRPCUserMessage` for method-routed requests. The attacker only needs to submit distinct, syntactically valid JSON-RPC requests (unique `ID`, method matching `Methods()` i.e. `MethodSecretsGet`/`MethodCapabilityExec`) at whatever rate the HTTP endpoint allows, which is trivially scriptable and fully repeatable.

### Recommendation
Add request-admission controls to `HandleJSONRPCUserMessage` before `newActiveRequest`/`fanOutToNodes`: (1) enforce `h.globalNodeRateLimiter.Allow(ctx)` (or a dedicated user-facing rate limiter) on request admission, not only in `HandleNodeMessage`; (2) bound `len(h.activeRequests)` and reject/backpressure when at capacity; (3) consider requiring caller authentication/allowlisting (similar to `vault`'s `requestProcessor.ProcessRequest` or the HTTP trigger handler's JWT-based `authorizeRequest`) before reserving state or fanning out to DON nodes.

### Proof of Concept
Go handler-level test plan (in `core/services/gateway/handlers/confidentialrelay`):
1. Build a `handler` via `setupHandler(t, N)` with a mocked `DON` whose `SendToNode` always returns `nil`.
2. In a loop, call `h.HandleJSONRPCUserMessage(ctx, req, cb)` with `req.ID` set to a fresh UUID each iteration and `Method: MethodCapabilityExec`/valid params, without ever calling `HandleNodeMessage`.
3. Assert that every call succeeds (`require.NoError`) and `len(h.activeRequests)` (via exported/test accessor or `h.getActiveRequest` per id) grows linearly with iteration count, with no rejection based on `globalNodeRateLimiter`.
4. Assert `don.AssertNumberOfCalls(t, "SendToNode", N*iterations)` to show fan-out occurs for every flooded request.
5. Contrast by calling `HandleNodeMessage` many times from an unrecognized `nodeAddr` and observing the `perNodeRateLimiters`/`globalNodeRateLimiter` gate that path (returns early, "no pending request" or rate-limited), demonstrating rate limiting exists only on the node-response path and never gates `newActiveRequest`/admission on the user-request path.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
