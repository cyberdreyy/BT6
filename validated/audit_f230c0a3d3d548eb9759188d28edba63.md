### Title
Permanent denial of staking-contract distributions via self-inflicted un-registration of a recipient in `distribute_internal` - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::distribute_internal` withdraws all unlocked stake, then pays out every entry of the internal `distribution_pool` in one atomic loop that always processes `shareholders()[0]` first via `aptos_account::deposit_coins`. Any recipient in that pool (the staker or the operator/beneficiary) can make their own account reject direct coin transfers, which causes `deposit_coins` to abort. Because the loop always targets index 0 and the whole call is atomic, this permanently blocks payout to every other shareholder sharing that pool, not just the offending account — closely mirroring the external report's pattern of a single, reachable call permanently blocking an ongoing distribution until funds/parameters are fixed.

### Finding Description
`distribute_internal` iterates the `distribution_pool` and, for each shareholder, calls `redeem_shares` (mutating pool state) and then `aptos_account::deposit_coins` to actually pay them: [1](#0-0) 

`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the target account is not registered for the coin type AND has explicitly disabled direct transfers via `can_receive_direct_coin_transfers`: [2](#0-1) 

Any account can permissionlessly flip that flag off for itself: [3](#0-2) 

`distribution_pool.shareholders()[0]` is always selected first in the payout loop; there is no way to skip a failing recipient and continue with the rest. Because Move transactions are atomic, if `deposit_coins` aborts, the entire `distribute_internal` call (including the earlier `redeem_shares` mutation and the `stake::withdraw_with_cap` withdrawal) is rolled back. Since the same recipient will occupy index 0 on every subsequent call (their un-redeemed share remains), every future invocation of `distribute` (public, callable by anyone), `unlock_stake`, `request_commission`, and `switch_operator` — all of which route through `distribute_internal` — will deterministically hit the same recipient and abort again: [4](#0-3) [5](#0-4) [6](#0-5) 

The staker and operator/beneficiary share the same `distribution_pool` for a given staker/operator pair (populated by `add_distribution` from `unlock_stake` for the staker and `request_commission_internal` for the operator). This means either party can grief the other's withdrawal rights by disabling their own direct-transfer acceptance, since the abort blocks the shared pool's entire payout path, not just their own entry. The same underlying `distribute()` call is also reused by the `vesting` module (`distribute`, `admin_withdraw`, `terminate_vesting_contract`), so a shareholder/beneficiary in a vesting contract can similarly brick fund release for the contract: [7](#0-6) [8](#0-7) 

### Impact Explanation
This falls under "Permanent lock or non-recoverable loss of claim rights in stake, delegation, commission, beneficiary, or vesting flows." Once a recipient in the shared `distribution_pool` disables direct-transfer acceptance (or, in the un-registered-account case, refuses to ever `coin::register`), all further distributions for that staking contract (including the counterparty's legitimately owed principal/commission) are permanently blocked, because the payout loop cannot skip the stuck index-0 entry and the operation is all-or-nothing. This can strand funds that were already unlocked/withdrawn from the stake pool logically (via `stake::withdraw_with_cap`) but never actually delivered, indefinitely.

### Likelihood Explanation
The trigger is fully unprivileged: any account (staker, operator, or a beneficiary) needs only to call the standard, permissionless `aptos_account::set_allow_direct_coin_transfers(account, false)` on their own address before ever registering for `AptosCoin`. No special role or capability is required, and `distribute` is explicitly a public entry function callable by anyone, meaning the griefing condition is trivially reachable in normal operation (e.g., a disgruntled operator wanting to block a staker's withdrawal, or vice versa).

### Recommendation
Change `distribute_internal`'s payout loop so a failing transfer to one recipient cannot block payouts to the rest: e.g., attempt `deposit_coins` per-recipient inside a mechanism that does not abort the whole transaction (or pre-check `coin::is_account_registered`/`can_receive_direct_coin_transfers` and, if false, re-queue/skip that recipient's share into a separate "unclaimed" pool that they can claim later once registered), rather than relying on all-or-nothing atomic iteration keyed off a single shared pool.

### Proof of Concept
1. Staker creates a staking contract with an operator via `staking_contract::create_staking_contract`.
2. Operator (or staker) calls `aptos_account::set_allow_direct_coin_transfers(&operator_signer, false)` on their own account before it is registered for `AptosCoin`.
3. Stake accrues rewards; operator calls `request_commission` (adds operator as a distribution-pool shareholder via `add_distribution`), or staker calls `unlock_stake` (adds staker as a shareholder).
4. Once the lockup expires, anyone calls `staking_contract::distribute(staker, operator)`.
5. `distribute_internal`'s loop reaches the disabled account as `recipients[0]`, calls `aptos_account::deposit_coins`, which aborts at [9](#0-8) 
6. The whole transaction reverts; the stuck entry remains at index 0 of `distribution_pool.shareholders()`. All subsequent calls to `distribute`, `unlock_stake`, `request_commission`, or `switch_operator` for this staker/operator pair fail identically, permanently blocking payout of both parties' funds until the disabled account re-enables direct transfers (which the attacker controls and can refuse to do).

        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

        // Record a distribution for the staker.
        add_distribution(
            operator,
            staking_contract,
            staker_address,
            amount,
        );

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

        // the vesting contract's account.
