### Title
APR0 withdraw request permanently wedges `stopEpoch` if APR is raised mid-epoch, forcing all future epochs to run at zero interest - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
An unprivileged lender who calls `requestWithdraw` while the vault APR is 0 lands principal in the APR0 bucket (`apr0TotalPrincipal`). At `stopEpoch`, `prepareStopEpochWithApr0` reverts with `NotAllowed` whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0`. If the manager raises the APR for the next epoch — a normal, honest operation — every subsequent `stopEpoch` reverts until the APR is returned to 0. The user-crafted sequence (deposit → APR0 withdraw request) converts a routine APR change into an infinite-revert loop on the epoch state machine, the direct analog of CVE-2017-5973's descriptor-sequence infinite loop.

### Finding Description
`requestWithdraw` routes requests into the APR0 bucket whenever `unscaledApr == 0`:

```solidity
if (unscaledApr == 0 && !isClosed) {
  _requestWithdrawApr0(_amount, _user);   // contracts/strategies/idle/IdleCreditVault.sol:285-286
}
```

`_requestWithdrawApr0` increments the global `apr0TotalPrincipal` (line 576). At epoch end, `IdleCDOEpochVariant._stopEpoch` calls `prepareStopEpochWithApr0`, which hard-reverts:

```solidity
if (_principal == 0) { return ...; }
if (unscaledApr != 0) {
  revert NotAllowed();                    // contracts/strategies/idle/IdleCreditVault.sol:506-508
}
```

`stopEpoch` itself sets the *new* epoch APR later in the same call, so the revert is driven by the *current* `unscaledApr` — which the manager may legitimately have raised mid-epoch via `setAprs`/`setApr` (allowed for `manager` per lines 206-235). Once any APR0 principal is pending, an honest APR raise makes the epoch un-stoppable. The only recovery is to set `unscaledApr` back to 0, meaning the epoch that should have accrued the new APR is forced to settle at zero interest.

### Impact Explanation
- **Broken invariant**: solvency/fair yield — borrower interest due for the epoch is forfeited.
- **Quantified loss**: `expectedEpochInterest` for the affected epoch(s), i.e. `TVL * apr * epochDuration / 365 days`. Any unprivileged lender with a dust-sized APR0 request (e.g. 1 wei of principal) can pin the vault at APR 0 for as long as the manager wants a non-zero APR, or permanently freeze the running epoch if APR must stay non-zero.
- This is more than gas DoS: it directly destroys lender yield or freezes all pending withdrawals while the wedge persists.

### Likelihood Explanation
- Attacker cost is minimal: deposit during buffer, wait for (or predict) an APR-0 epoch configuration, call `requestWithdraw`. APR0 vaults are a supported mode (`apr0Users`, `apr0RateByEpoch` exist specifically for it).
- Trigger requires only an honest manager APR change, which is routine. The bug triggers without any malicious privileged action.
- Note: recovery is possible by restoring APR to 0, so impact is forfeited yield / temporary freezing rather than permanent loss — matching a Medium-severity analog.

### Recommendation
Settle the APR0 bucket at the APR recorded at request time instead of gating on the live `unscaledApr`, e.g. store `apr0RateByEpoch`/`principalEpoch` per request epoch and remove the `unscaledApr != 0` revert in `prepareStopEpochWithApr0`. Alternatively, snapshot the APR into the APR0 bucket at request time so mid-epoch APR changes cannot invalidate pending receipts.

### Proof of Concept
Foundry fork PoC (adapt harness from `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testPocApr0Wedge() external {
  // 1. Configure vault at APR 0, deposit as user
  vm.prank(manager);
  IdleCreditVault(address(strategy)).setAprs(0, 0);
  idleCDO.depositAA(10_000 * ONE_SCALE);

  // 2. Start epoch; user requests withdraw while APR == 0 → apr0TotalPrincipal > 0
  _startEpochAndCheckPrices(0);
  cdoEpoch.requestWithdraw(aaTranche.balanceOf(address(this)) / 2, address(aaTranche));
  assertGt(strategy.apr0TotalPrincipal(), 0);

  // 3. Honest manager raises APR for next epoch mid-epoch
  vm.prank(manager);
  IdleCreditVault(address(strategy)).setAprs(4e18, 4e18);

  // 4. stopEpoch reverts forever while APR != 0 → epoch frozen / yield forfeited
  vm.warp(cdoEpoch.epochEndDate() + 1);
  vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
  vm.prank(manager);
  cdoEpoch.stopEpoch(4e18, 0);

  // 5. Only unblockable by forcing APR back to 0 → expectedEpochInterest lost
  vm.prank(manager);
  IdleCreditVault(address(strategy)).setAprs(0, 0);
  vm.prank(manager);
  cdoEpoch.stopEpoch(0, 0); // settles at zero interest
}
```

Caveat: whether this wedge is already acknowledged in prior audits is uncertain from index alone; the revert is explicit in code at `contracts/strategies/idle/IdleCreditVault.sol:506-508` and the attacker path at lines 285-294.
