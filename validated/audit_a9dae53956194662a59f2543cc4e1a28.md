## Analog Found

### Title
`AccountState::to_word` silently truncates out-of-range `local_sequence`/`local_epoch`/`lock_union`/`default_eoa_expiry` because the width invariant is only a `debug_assert!` - (File: crates/execution/eip8130/src/account_config.rs)

### Summary
The reported Well/Basin bug is a class of "packed bit-field storage encoder trusts an invariant (value fits in N bits) without an enforced check, so an out-of-range value is silently truncated instead of rejected/reverted." Base's `AccountState::to_word()` in the EIP-8130 `AccountConfiguration` native mirror exhibits the same pattern: it packs `multichain_sequence` (64 bits), `local_sequence`/`local_epoch` (uint32 fields), `lock_union`/`default_eoa_expiry` (uint48 fields), `flags` and `default_eoa_scope` into one 32-byte word using raw byte-slice copies, and only *documents and `debug_assert!`s* that the sub-fields fit their declared widths — a check compiled out in release builds.

### Finding Description
`to_word()` packs multiple logical fields into a single storage word by slicing native-width integers down to their EIP-8130-declared bit width: [1](#0-0) 

The comment explicitly states the invariant: "`local_sequence`/`local_epoch` must fit in `uint32`, `lock_union` and `default_eoa_expiry` in `uint48` (their storage field widths); higher bytes are dropped," and that this is enforced only via `debug_assert!`, which "only guard[s] hand-constructed misuse." In a release build (the configuration node operators actually run), these assertions are no-ops, so if any caller ever constructs (or a future code path derives) an `AccountState` with `local_sequence`, `local_epoch` outside `uint32` range, or `lock_union`/`default_eoa_expiry` outside `uint48` range, `to_word()` will silently drop the high bytes via `b[..].copy_from_slice(&x.to_be_bytes()[N..])` rather than erroring — exactly the LibLastReserveBytes failure mode (shift/truncate instead of bounds-checked revert).

This is architecturally analogous to the general packed-storage layer used across Base's precompiles, `crates/common/precompile-storage/src/packing.rs`, which *does* correctly bounds-check packed writes (`Word::insert_into_word` returns an error if `offset + bytes > 32`), confirming the project's own pattern for safe packing. `account_config.rs`'s hand-rolled `to_word()` bypasses that shared, checked packing infrastructure and reintroduces the unchecked-truncation anti-pattern the shared library was built to prevent.

### Impact Explanation
`AccountState` governs EIP-8130 account nonce/epoch tracking (`local_sequence`, `local_epoch`, `multichain_sequence`), account lock state (`lock_union`), and the default EOA actor's expiry/scope (`default_eoa_expiry`, `default_eoa_scope`) — security-critical fields for a native account-abstraction transaction type. If any code path (e.g. batched account-change application in `apply.rs`) ever produces a value that exceeds the declared width for `local_sequence`/`local_epoch` (32 bits) or `lock_union`/`default_eoa_expiry` (48 bits) before calling `to_word()`, the persisted storage word will contain silently-wrapped/truncated values. Depending on which field is affected this could: reset/desynchronize a channel sequence counter (enabling nonce confusion or replay-adjacent bugs), corrupt the account lock union bitmask (silently unlocking/misconfiguring policy locks), or truncate an actor's expiry timestamp (causing incorrect actor-expiration prematurely or — worse — wrapping to a valid-looking, unintended timestamp), any of which is an "unauthorized operation" against account state reachable from ordinary EIP-8130 transaction senders.

### Recommendation
Replace the `debug_assert!`-only invariant in `AccountState::to_word()` with a real, release-mode-enforced check (e.g. return a `Result`/`BasePrecompileError` or use `try_into()` against `u32`/aliased `U48`-equivalent bounds) before slicing bytes, mirroring the checked pattern already used in `base_precompile_storage::packing::Word::insert_into_word`/`extract_from_word`. Additionally, audit every call site in `apply.rs`/`authorize.rs` that mutates `local_sequence`, `local_epoch`, `lock_union`, and `default_eoa_expiry` to confirm each mutation is bounds-checked (saturating/checked-add or explicit range validation) prior to any `to_word()` call, closing the gap the comment currently assumes is already closed.

    /// Packs this state into its raw storage word — the exact inverse of
    /// [`Self::from_word`].
    ///
    /// `local_sequence`/`local_epoch` must fit in `uint32`, `lock_union` and
    /// `default_eoa_expiry` in `uint48` (their storage field widths); higher
    /// bytes are dropped. Values sourced from [`Self::from_word`] or ABI decoding
    /// always satisfy this, so the `debug_assert!`s only guard hand-constructed
    /// misuse.
    #[must_use]
    pub fn to_word(&self) -> U256 {
        debug_assert!(
            self.local_sequence >> 32 == 0,
            "local_sequence exceeds uint32 storage width"
        );
        debug_assert!(self.local_epoch >> 32 == 0, "local_epoch exceeds uint32 storage width");
        debug_assert!(self.lock_union >> 48 == 0, "lock_union exceeds uint48 storage width");
        debug_assert!(
            self.default_eoa_expiry >> 48 == 0,
            "default_eoa_expiry exceeds uint48 storage width"
        );
        let mut b = [0u8; 32];
        b[24..32].copy_from_slice(&self.multichain_sequence.to_be_bytes());
        b[20..24].copy_from_slice(&self.local_sequence.to_be_bytes()[4..]); // uint32: low 4 bytes
        b[16..20].copy_from_slice(&self.local_epoch.to_be_bytes()[4..]); // uint32: low 4 bytes
        b[15] = self.flags;
        b[9..15].copy_from_slice(&self.lock_union.to_be_bytes()[2..]); // uint48: low 6 bytes
        b[3..9].copy_from_slice(&self.default_eoa_expiry.to_be_bytes()[2..]); // uint48: low 6 bytes
        b[1..3].copy_from_slice(&self.default_eoa_scope.to_be_bytes()); // uint16: 2 bytes
        U256::from_be_bytes(b)
    }
