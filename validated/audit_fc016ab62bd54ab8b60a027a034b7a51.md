### Title
Signer overrides its own locally-rejected verdict on group-signature threshold — rejection recounted as acceptance ([File: stacks-signer/src/v0/signer.rs])

### Summary
`store_and_process_block_signature` marks a block `LocallyAccepted` purely from aggregated peer-signature weight, without checking whether *this* signer had already marked the same block `LocallyRejected` (i.e. `valid = Some(false)`) after its own chainstate/conflict checks. `BlockInfo::mark_locally_accepted(true)` deliberately skips setting `valid` and the state-transition guard (`check_state`) explicitly permits `LocallyRejected -> LocallyAccepted`. As a result, a signer's own rejection of an invalid/non-canonical/conflicting block can be silently overwritten and the signer will broadcast the block as accepted once the observed accept-signature weight crosses threshold.

### Finding Description
`BlockInfo::mark_locally_accepted` has two branches keyed on `group_signed`: [1](#0-0) 
When `group_signed = true` (the path used purely because enough *other* signers' weight has accumulated), the function never re-asserts `self.valid = Some(true)`, never re-runs any chainstate/conflict re-check, and simply calls `move_to(BlockState::LocallyAccepted)`.

The state machine explicitly allows this transition even from `LocallyRejected`: [2](#0-1) 
`LocallyRejected | LocallyAccepted` are mutually reachable from each other as long as neither side is a *global* terminal state — so a block this signer already rejected (after running `check_block_against_state`/`check_block_against_signer_db_state`, e.g. for being non-canonical, malformed, or conflicting with an already-signed sibling) can freely flip back to `LocallyAccepted`.

The call site that drives this transition is `store_and_process_block_signature`, invoked from `handle_block_signature` whenever a `BlockAccepted` message arrives from any peer whose signature recovers to a valid signer address: [3](#0-2) 
Note the flow:
1. The peer's raw signature is unconditionally stored via `add_block_signature` (line ~2456), *before* any check of this signer's own `block_info.valid`/`block_info.state`.
2. If the signer address is a peer that hasn't sent a pre-commit yet, the code takes an "outdated peer" fallback and returns — but the signature is already durably stored regardless of that branch.
3. Later, `total_signature_weight` is computed purely from `get_block_signatures` (i.e. every raw signature ever stored for this hash, including this and any earlier accepted stragglers), compared to `min_weight` — nowhere in this function is `block_info.valid` or `block_info.state == LocallyRejected` consulted.
4. Once `total_signature_weight >= min_weight`, the code unconditionally calls `block_info.mark_locally_accepted(true)` and then `self.broadcast_signed_block(...)` — re-broadcasting the assembled signature set for the block and handing it toward the node.

Contrast this with the only other path that produces this signer's *own* signature — `handle_block_pre_commit`'s `SIGN` branch — which re-checks `check_block_against_signer_db_state`, `get_signed_conflicts`, `reorg_permit_stands`, and freshness *every time* before signing (documented in `docs/signer-flows.md` section 5). `store_and_process_block_signature`'s group-threshold path has no equivalent re-check: it treats "enough stored signatures" as sufficient proof, bypassing the very safety checks that caused this signer to reject the block in the first place.

This breaks the "signed vs validated" / "rejection recounted as accept" invariant: a block this signer's own state machine determined was invalid, non-canonical, or in conflict with an already-signed sibling is nevertheless re-marked `LocallyAccepted` and rebroadcast by this same signer, solely because other parties' accept messages (genuine or stale/outdated-peer fallback signatures, which per the design are also stored unconditionally as bearer instruments — see `docs/signer-flows.md` note that "rejection... does not clear a conflict... only staleness or node-derived death... clears a conflict") pushed the tallied weight over threshold.

### Impact Explanation
This is a **Critical** analog: a signer ends up signing/re-broadcasting acceptance of a block it had itself locally rejected as invalid, non-canonical, or conflicting, without re-running any of the conflict/reorg/chainstate checks that gate its own signing path. This directly matches the target impact "a signer signing an invalid, non-canonical, or conflicting block" / "a rejection recounted as acceptance."

### Likelihood Explanation
The trigger path requires only: (a) this signer previously rejected a block (a routine, frequently-hit local state, e.g. via a reorg/conflict check or stale timestamp), and (b) subsequently receiving `BlockAccepted` gossip messages from other signers/peers whose signatures recover to valid signer addresses and whose combined recorded weight crosses the 70% threshold. No special privileges, majority-key compromise, or auth-token access are needed by the reporting node itself — it is purely a missing local re-validation gate inside `store_and_process_block_signature`/`mark_locally_accepted(true)`.

### Recommendation
Before calling `block_info.mark_locally_accepted(true)` in `store_and_process_block_signature`, re-check `block_info.valid`/`block_info.state`: if the block is currently `LocallyRejected` (or `valid == Some(false)`), re-run the same conflict/chainstate checks used in `handle_block_pre_commit`'s `SIGN` branch (`check_block_against_signer_db_state`, `get_signed_conflicts`/`reorg_permit_stands`/freshness) before allowing the transition, or refuse to move a `LocallyRejected` block back to `LocallyAccepted` purely on aggregated third-party signature weight.

### Proof of Concept
1. Signer S receives a block proposal B that is non-canonical/conflicting; `check_block_against_state`/`handle_block_validate_reject` runs, `block_info.mark_locally_rejected()` sets `valid = Some(false)`, state = `LocallyRejected`, S broadcasts a `BlockRejection`.
2. Attacker (miner/gossip) causes other signers (or resends previously-observed genuine `BlockAccepted` messages) to reach S as `BlockResponse::Accepted` for the same `signer_signature_hash`.
3. Each arrives at `handle_block_signature` → `store_and_process_block_signature`; signatures are stored via `add_block_signature` regardless of S's local `valid=Some(false)` state.
4. Once accumulated weight ≥ `min_weight`, S calls `mark_locally_accepted(true)` — moving B from `LocallyRejected` to `LocallyAccepted` without re-validation — and calls `broadcast_signed_block`, re-emitting S's participation in pushing B forward despite S's own earlier rejection verdict.     pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

        }

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }
