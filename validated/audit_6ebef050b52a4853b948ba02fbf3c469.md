### Title
Minted-interest `stopEpoch` mints unbacked AA fee shares for historically accrued (unfunded) `unclaimedFees`, diluting tranche holders - ([File: contracts/IdleCDOEpochVariant.sol](contracts/IdleCDOEpochVariant.sol))

### Summary
In minted-interest mode, `stopEpoch` converts the entire `unclaimedFees` balance into AA tranche shares for `feeReceiver`/`owner` via `_mintSharesAtCurrPrice`, but only mints `_grossInterest` strategy tokens as backing. `unclaimedFees` can carry management fees accrued but never funded in prior epochs, so shares are minted against assets that were never received — the credit-vault analog of the Surge bug where fee balances are credited without matching supply-side backing.

### Finding Description
The non-minted fee path caps the payout to cash actually available: `uint256 _availableForFees = _grossInterest > _pendingWithdrawFees ? _grossInterest - _pendingWithdrawFees : 0; if (_fees > _availableForFees) _fees = _availableForFees;`. The minted-interest branch has no such cap — it mints shares for the full `_fees = unclaimedFees`: [1](#0-0) 

`unclaimedFees` is not limited to the current epoch's earnings. `_accrueManagementFee` checkpoints management fees on every `_updateAccounting` regardless of whether interest covers them, and unfunded fees persist (confirmed by `testStopEpochCarriesManagementFeesAboveGrossInterest`): [2](#0-1) [3](#0-2) 

On a later minted-interest epoch, `_strategy.mintStrategyTokens(_grossInterest)` adds only the current epoch's gross interest to NAV backing (line 430), while `_mintSharesAtCurrPrice(_fees, ...)` mints AA shares for `unclaimedFees` including the stale, unfunded portion. `unclaimedFees -= _fees` then zeroes the debt, so `getContractValue() = strategyTokenBalance - 0` no longer reflects any fee liability — the shortfall is silently socialized onto all tranche holders via NAV dilution. Like the Surge report, an accounting claim is converted into a token claim without the asset side ever being funded.

### Impact Explanation
Insolvency / direct dilution: feeReceiver and owner receive AA tranche tokens whose redemption value exceeds real vault assets by the carried-fee amount. When they redeem, or when remaining LPs withdraw, the last withdrawers cannot be paid in full (loss equal to the unfunded `unclaimedFees` minted as shares). This is a fair-mint/burn invariant violation: shares in circulation exceed underlying backing.

### Likelihood Explanation
Requires: (1) at least one epoch where accrued management fee exceeds gross interest — trivially reached in any low-APR/APR0 epoch or a short epoch, since management fee accrues on NAV per time regardless of performance; and (2) a subsequent epoch run with `isInterestMinted = true` (required anyway for programmable borrowers). No malicious action is needed — honest `manager.stopEpoch` calls trigger it, and any unprivileged LP is harmed while an unprivileged observer can verify `AAtranche.totalSupply() * priceAA + ... > strategyTokenBalance`. The minted branch simply lacks the `_availableForFees` guard that the cash branch already implements.

### Recommendation
Apply the same funding cap in the minted branch: only mint shares for `min(unclaimedFees, _grossInterest)` (net of `_pendingWithdrawFees` handling), and leave the unfunded remainder accrued in `unclaimedFees` instead of zeroing it, so `getContractValue` continues to reflect the unpaid liability.

### Proof of Concept
Foundry fork PoC sketch (patterned on `testStopEpochCarriesManagementFeesAboveGrossInterest` at `test/foundry/IdleCreditVault.t.sol:1100`):

```solidity
// Epoch 1: management fee > gross interest -> carried unclaimedFees
_setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, mgmtFeeRate); // fee=0 perf, mgmtFee=2%
idleCDO.depositAA(10_000 * ONE_SCALE);
_startEpochAndCheckPrices(0);
deal(underlying, borrower, 100 * ONE_SCALE); // low interest
vm.warp(cdoEpoch.epochEndDate() + 1);
vm.prank(manager); cdoEpoch.stopEpoch(0, 100 * ONE_SCALE);
uint256 carried = cdoEpoch.unclaimedFees(); // mgmtFee - 100, e.g. ~100e18
assertGt(carried, 0);

// Enable minted interest, run epoch 2 with interest == 0 (apr0 / minted mode)
vm.prank(owner); cdoEpoch.setIsInterestMinted(true);
_startEpochAndCheckPrices(1);
vm.warp(cdoEpoch.epochEndDate() + 1);
uint256 supplyPre = IERC20(address(AAtranche)).totalSupply();
uint256 stratPre  = strategyToken.balanceOf(address(cdoEpoch));
vm.prank(manager); cdoEpoch.stopEpoch(0, 0);

// Bug: shares minted for full unclaimedFees incl. `carried`,
// but strategyToken backing only grew by grossInterest (0).
uint256 sharesMinted = IERC20(address(AAtranche)).totalSupply() - supplyPre;
assertGt(sharesMinted, carried * ONE_TRANCHE_TOKEN / cdoEpoch.priceAA() - 1);
// NAV claim now exceeds real assets -> insolvency for last withdrawer
assertGt(cdoEpoch.lastNAVAA() + cdoEpoch.lastNAVBB(),
         strategyToken.balanceOf(address(cdoEpoch)));
```

Key assertion: `lastNAVAA + lastNAVBB` (sum of tranche claims) exceeds `strategyToken.balanceOf(cdo)` by ~`carried`, i.e., fee shares exist with no corresponding assets — the exact ERC-20-style accounting mismatch from the Surge report.
