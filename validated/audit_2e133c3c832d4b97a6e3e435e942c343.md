### Title
Instant withdrawals bypass withdrawal management fees - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`requestWithdraw` applies `_totalWithdrawFees` to ordinary withdrawal receipts, but the instant-withdrawal branch returns early with the full tranche value and does not accrue any fee in `pendingWithdrawFees`. The instant receipt is similarly removed from live NAV and can remain pending until the next epoch funding or `instantWithdrawDeadline`, so the fee-free path leaks protocol revenue.

### Finding Description
Both paths calculate `principal` from the current tranche price and then burn the tranche position. In instant mode, `requestInstantWithdraw` receives gross `principal`, `_withdrawOps` removes that full amount from NAV, and the function returns before `_calcInterestWithdrawRequest`, `_totalWithdrawFees`, or `pendingWithdrawFees` execute. [1](#0-0) 

The ordinary path instead deducts `totalFees` from `principal + interest`, records the deduction in `pendingWithdrawFees`, and later pays those fees from borrower-funded epoch proceeds. [2](#0-1) [3](#0-2) 

Instant receipts are not immediately paid at request time. `requestInstantWithdraw` adds the full amount to `instantWithdrawsRequests` and `pendingInstantWithdraws`, while funding is collected separately through `collectInstantWithdrawFunds`. [4](#0-3) [5](#0-4) 

### Impact Explanation
When instant withdrawals are enabled by an APR decrease, any KYC-passed tranche holder can obtain an instant receipt for 100% of current tranche value without contributing withdrawal-management fees. If an instant receipt remains pending for `T` seconds, the expected management fee is:

```solidity
expectedFee = principal * managementFee * T / (365 days * FULL_ALLOC);
```

No equivalent amount is added to `pendingWithdrawFees`, so fee recipients lose that revenue while the borrower must still fund the gross instant claim. [6](#0-5) [7](#0-6) 

### Likelihood Explanation
The trigger is an APR decrease satisfying `lastEpochApr > currentApr + instantWithdrawAprDelta`, which is a normal configuration state rather than privileged misconduct. Once that condition exists, a tranche holder only calls `requestWithdraw`. [8](#0-7) 

Existing tests intentionally exercise this path and assert that both `pendingInstantWithdraws` and the user receipt equal the unmodified tranche value. [9](#0-8) 

### Recommendation
Calculate and deduct the appropriate instant-withdrawal management fee before calling `requestInstantWithdraw`, using a duration that reflects how long the receipt remains outside live NAV, such as the remaining buffer plus `instantWithdrawDelay`. Add the deducted amount to `pendingWithdrawFees` or another fee accrual that survives instant funding and default accounting.

```solidity
uint256 principal = _underlyings;
uint256 instantFee = _calculateManagementFee(
    principal,
    _instantWithdrawManagementFeeDuration()
);

_underlyings = principal - instantFee;
pendingWithdrawFees += instantFee;

creditVault.requestInstantWithdraw(_underlyings, msg.sender);
_withdrawOps(_amount, principal, _tranche);
return _underlyings;
```

If instant withdrawals are deliberately fee-free, document that exception explicitly and update the withdrawal-fee accounting comments and user-facing quote helpers.

### Proof of Concept
```solidity
function testInstantWithdrawBypassesWithdrawalManagementFee() external {
    uint256 amount = 10_000 * ONE_SCALE;
    uint256 mgmtFeeRate = 1_000; // 1% annualized

    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    _setManagementFee(mgmtFeeRate);

    uint256 trancheAmount = idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);

    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(
        0,
        initialProvidedApr - (cdoEpoch.instantWithdrawAprDelta() + 1),
        _expectedFundsEndEpoch()
    );

    uint256 principal =
        trancheAmount * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;

    uint256 requested = cdoEpoch.requestWithdraw(trancheAmount, address(AAtranche));

    // Vulnerable behavior: receipt is gross principal and no withdrawal fee is booked.
    assertEq(requested, principal);
    assertEq(cdoEpoch.pendingWithdrawFees(), 0);
    assertEq(
        IdleCreditVault(address(strategy)).instantWithdrawsRequests(address(this)),
        principal
    );

    // Expected behavior would deduct a fee for the time the receipt remains pending.
    uint256 expectedFee = _calcManagementFee(
        principal,
        mgmtFeeRate,
        cdoEpoch.instantWithdrawDelay()
    );
    assertGt(expectedFee, 0);
}
```

  /// @notice Calculate total fees charged on a withdrawal request.
  /// @param _principal Principal leaving live NAV.
  /// @param _interest Projected interest for the requested principal.
  /// @return Total management and performance fees to subtract from principal plus projected interest.
  function _totalWithdrawFees(uint256 _principal, uint256 _interest) private view returns (uint256) {
    uint256 _mgmtFee = _calculateManagementFee(_principal, _withdrawRequestManagementFeeDuration());
    // When interest covers management fees, interest - netGain equals management fee plus performance fee.
    return _mgmtFee >= _interest ?
      _mgmtFee :
      _interest - _netGainAfterFees(_interest, _mgmtFee);
  }
