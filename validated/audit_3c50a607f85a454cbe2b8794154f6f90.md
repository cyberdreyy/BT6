### Title
Zero or negative Chainlink price can permanently block USD0++ epoch settlement - ([File: contracts/strategies/usual/IdleUsualStrategy.sol](contracts/strategies/usual/IdleUsualStrategy.sol))

### Summary
`IdleUsualStrategy.getChainlinkPrice` validates only `updatedAt` and then casts the signed Chainlink `answer` directly to `uint256` without checking `answer > 0`. [1](#0-0)  A zero answer passes this check and later causes `IdleCDOUsualVariant.stopEpoch` to revert through division by zero. [2](#0-1)  A negative answer can instead overflow during multiplication or produce an enormous unsigned price. [3](#0-2) 

### Finding Description
The strategy retrieves a signed Chainlink answer and checks only whether the round is fresh:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
return uint256(answer) * 1e10;
``` [3](#0-2) 

During the running epoch, deposits and withdrawals are disabled. [4](#0-3)  After maturity, `stopEpoch` is the only path that re-enables withdrawals, but it uses the raw returned `_oraclePrice` as the denominator when calculating the senior-tranche target NAV. [2](#0-1) 

Therefore:

- `answer == 0` returns `0`, and `lastNAVAA * oneToken / _oraclePrice` reverts.
- `answer < 0` is cast to `uint256`; for sufficiently negative values, multiplication by `1e10` overflows and reverts.
- A moderately negative value that survives scaling is interpreted as an enormous positive USD price rather than invalid data.

Although `setOraclePrice` clamps the stored value to the USD0++ floor price, `stopEpoch` continues to use the unclamped local `_oraclePrice` for its accounting calculation. [5](#0-4) [6](#0-5) 

### Impact Explanation
While the feed reports a fresh zero or sufficiently negative answer, `stopEpoch` cannot complete. Because `startEpoch` disabled both withdrawal flags inside the paused epoch, all senior and junior funds remain locked until a later valid oracle round permits settlement. [4](#0-3)  This is a temporary freezing of 100% of funds locked in the epoch; if the feed never supplies another valid round, the settlement failure is permanent absent an implementation upgrade or other external recovery action.

A surviving negative value can additionally bypass the `_oraclePrice >= oneToken` check and mark the epoch settled with withdrawals enabled while the intended junior-to-senior compensation is skipped. [7](#0-6) 

### Likelihood Explanation
The issue requires the external USD0++ feed to return a fresh non-positive answer. Chainlink asset feeds normally return positive prices, so ordinary market operation does not trigger it. No special protocol privilege is required for the resulting freeze, however: once such an answer is published, every honest owner call to `stopEpoch` deterministically reverts. The existing freshness check and floor-price clamp do not prevent the failure because neither validates the signed `answer` used as the divisor.

### Recommendation
Validate the signed answer before casting and scaling it:

```solidity
(, int256 answer,, uint256 updatedAt,) =
    IOracle(USD0ppOracle).latestRoundData();

require(updatedAt > block.timestamp - 24 hours, "Stale price");
require(answer > 0, "Invalid price");

return uint256(answer) * 1e10;
```

This change should be made in `contracts/strategies/usual/IdleUsualStrategy.sol:getChainlinkPrice`. [8](#0-7) 

Optionally, validate round completeness with `roundId != 0`, `answeredInRound >= roundId`, and `startedAt != 0`. A defensive `_oraclePrice > 0` check in `stopEpoch` would provide an additional layer before the division. [6](#0-5) 

### Proof of Concept
Add this test to `test/foundry/IdleUsualStrategy.t.sol`. It uses the existing mainnet fork setup, deposits into both tranches, starts the epoch, mocks a fresh zero Chainlink answer, and shows that settlement—and therefore withdrawal re-enablement—cannot complete:

```solidity
function testStopEpochRevertsOnZeroOraclePrice() external {
    uint256 amount = 10_000 * ONE_SCALE;

    idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _transferBurnedTrancheTokens(address(this), false);

    IdleCDOUsualVariant _idleCDO = IdleCDOUsualVariant(address(idleCDO));

    vm.prank(owner);
    _idleCDO.startEpoch(0);

    vm.mockCall(
        0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB,
        abi.encodeWithSignature("latestRoundData()"),
        abi.encode(
            uint80(1),
            int256(0),
            block.timestamp,
            block.timestamp,
            uint80(1)
        )
    );

    vm.expectRevert(stdError.divisionError);
    vm.prank(owner);
    _idleCDO.stopEpoch();

    assertTrue(_idleCDO.isEpochRunning());
    assertFalse(_idleCDO.allowAAWithdraw());
    assertFalse(_idleCDO.allowBBWithdraw());
}
```

  /// @notice get the chainlink price of usd0++ and scale it to 18 decimals
  function getChainlinkPrice() public view returns (uint256) {
    // Oracle it is not updated frequently but only if there is a deviation of 50 bips from 
    // the last reported value.There is also a 24 hours hearbeat. So we check that the last round 
    // is not older than 24 hours
    (,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
    require(updatedAt > block.timestamp - 24 hours, "Stale price");
    // scale the answer to 18 decimals
    return uint256(answer) * 1e10;

    _strategy.setOraclePrice(_oraclePrice);

    // we unpause redeems only
    allowAAWithdraw = true;
    allowBBWithdraw = true;
    // set epoch as not running
    isEpochRunning = false;

    // if usd0++ price is 1$ or more then junior doesn't owe anything to senior
    if (_oraclePrice >= oneToken) {
      return;
    }
    // if price is less than 1$ we calculate how much junior should give to senior considering 1 usd0++ = 1$
    // eg price is 0.9$, lastNAVAA is 100 usd0++ (ie 90$) and targetAATVL should be 100$ so 100 / 0.9 = 111.11 usd0++
    // so we do lastNAVAA * (1 / oraclePrice) = 100 * (1 / 0.9) = 111.11
    uint256 targetAATVL = lastNAVAA * oneToken / _oraclePrice;

    // we increase the lastNAVAA so that the senior tranche is at par with 1$
    lastNAVAA += targetAATVL - lastNAVAA;

    // this will cause the next updateAccounting call to account a loss which will be absorbed by the junior tranche
    _updateAccounting();
