### Title
Confidential Relay gateway handler allows unauthenticated request-ID squatting that DOSes a legitimate user's capability request - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

### Summary
The `confidentialrelay` gateway handler deduplicates incoming JSON-RPC requests using a global, client-supplied `req.ID` as the sole key, with no per-owner/per-caller scoping and no binding to the request payload. Because the ID is fully attacker-controlled and checked before any authorization or ownership binding, a malicious client can pre-register a request with an ID a victim is about to use, causing the victim's legitimate request to be rejected — the same "front-run the replay-prevention key" pattern described in the external report.

### Finding Description
`HandleJSONRPCUserMessage` immediately calls `newActiveRequest`, which stores the pending request keyed only by the raw `req.ID` in a handler-wide map, before any authorization/ownership check ties the ID to a specific caller: [1](#0-0) [2](#0-1) 

If an entry already exists for that ID, the request is rejected outright with `"request ID already exists"`, regardless of which caller originally created the entry or whether the payloads match: [3](#0-2) 

This is confirmed directly by the existing test, which shows that a second `HandleJSONRPCUserMessage` call reusing the same `ID` (regardless of caller identity) fails: [4](#0-3) 

This mirrors the `_deduplicateOrder` flaw in the report: replay-prevention is anchored on an attacker-controllable identifier (there, `benefactor+nonce`; here, the raw JSON-RPC `ID`) rather than being scoped to the caller or bound to the full request content. An entry only leaves the map via `removeExpiredRequests`, so the squatted ID blocks the legitimate caller for the full expiry window and can be continuously re-squatted.

By contrast, the vault gateway handler in this same codebase avoids exactly this class of bug: it runs authorization first and then rewrites the request ID to be owner-prefixed (`authorizedOwner + RequestIDSeparator + originalRequestID`) before using it as the active-request dedup key, so collisions require the *same* authorized owner: [5](#0-4) 

The confidential relay handler lacks this owner-prefixing step entirely — dedup happens on the raw client-supplied ID at message entry, before any authorization takes place.

### Impact Explanation
Any client able to reach the gateway's confidential-relay JSON-RPC endpoint can deny service to another caller's request simply by guessing or observing the target request ID and submitting a request with that same ID first (front-running, or simply racing on predictable/sequential IDs used by workflow clients). The victim's legitimate request is rejected with `"request ID already exists"`, and the attacker can repeat this indefinitely to sustain a denial of service against a specific workflow/caller's capability execution requests.

### Likelihood Explanation
Exploitability only requires the ability to send a JSON-RPC user message to the gateway with a chosen `ID` before the victim's request lands — no privileged role, node compromise, or special network position is needed beyond ordinary racing/front-running against a public-facing endpoint, which is explicitly in scope per the rules (internet-facing gateway message-envelope handling). If request IDs used by clients are sequential or otherwise guessable (a common pattern), likelihood is high.

### Recommendation
Scope the active-request dedup key to the authenticated/authorized caller identity (e.g., prefix or namespace the ID by the resolved caller/workflow owner, similar to the pattern already used in `core/capabilities/vault/gateway_vault_request_processor.go`), and perform this binding before storing the entry in `activeRequests`. Alternatively/additionally, base dedup on a digest of the full request payload rather than (or in addition to) the raw client-supplied `ID`.

### Proof of Concept
1. Attacker sends `HandleJSONRPCUserMessage` with `ID: "victim-id"` and arbitrary `Method`/`Params` to the confidential relay gateway handler.
2. `newActiveRequest` succeeds and stores the entry under key `"victim-id"`.
3. Victim's legitimate request with the same `ID: "victim-id"` arrives shortly after and is rejected with `"request ID already exists: victim-id"`, as demonstrated by `TestConfidentialRelayHandler_DuplicateRequestID` ( [4](#0-3) ).
4. Attacker repeats this for each new ID the victim attempts, sustaining a DOS until the entry expires and is cleaned up, at which point the attack can be repeated.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func TestConfidentialRelayHandler_DuplicateRequestID(t *testing.T) {
	t.Parallel()
	h, cb, don, _ := setupHandler(t, 4)
	don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)

	params := json.RawMessage(`{"workflow_id":"wf1"}`)
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "req-dup",
		Method: MethodCapabilityExec,
		Params: &params,
	}

	err := h.HandleJSONRPCUserMessage(t.Context(), req, cb)
	require.NoError(t, err)

	cb2 := common.NewCallback()
	err = h.HandleJSONRPCUserMessage(t.Context(), req, cb2)
	require.ErrorContains(t, err, "request ID already exists")
}
