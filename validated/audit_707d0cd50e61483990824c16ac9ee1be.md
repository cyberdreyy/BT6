### Title
Zip-slip path traversal in `extractZipDirectoryEntry`/`extractZipFile` due to missing root-containment validation - (File: `helpers/archives/zip_extract.go`)

### Summary
`extractZipDirectoryEntry`, `extractZipFileEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` write to `file.Name` (and `filepath.Dir(file.Name)` via `os.MkdirAll`) with zero canonicalization or root-containment check. Because there is no validation step at all — only a single write path — any separator form (`..`, absolute paths, `\` vs `/`, or mixed forms) reaches `os.Mkdir`/`os.OpenFile`/`os.Symlink` unmodified, so a crafted archive can extract outside the intended job/cache/artifact directory.

### Finding Description
`ExtractZipArchive` iterates `archive.File` entries and, for each, calls `extractZipFile`, which does: [1](#0-0) 

The only check performed before extraction is `errorIfGitDirectory`, which only rejects `.git`-prefixed paths and is purely a warning/best-effort filter, not a security boundary: [2](#0-1) 

The three entry writers themselves perform no `filepath.Clean`, no `filepath.Rel`/`filepath.IsAbs` check against a root directory, and no comparison between a "validated" name and the name actually used to write: [3](#0-2) 

Because `file.Name` (attacker-controlled, taken directly from the zip's central directory entry) is passed straight to `os.Mkdir`, `os.MkdirAll(filepath.Dir(...))`, `os.OpenFile`, and `os.Symlink`, an entry name containing `../../etc/cron.d/x`, an absolute path (`/etc/x` or `C:\Windows\x`), or mixed separators (`..\\../x`, `..\/x`) is not rejected and resolves relative to the process's current working directory at extraction time — which is the job/cache/artifact working directory, but escapes it via `..` traversal handled transparently by the OS path resolver.

This differs from the specific "two-step canonicalization mismatch" framing in the question (there is no second, divergent validation step to bypass), but the underlying invariant — "validation and final write must canonicalize to the same in-root path" — is violated in the strongest possible way: there is no validation at all, so *any* separator form, including deliberately mixed ones, is a valid escape vector, not merely by exploiting an inconsistency between two checks.

### Impact Explanation
An attacker who controls the contents of a cache or artifact zip archive consumed by `ExtractZipArchive`/`ExtractZipFile` (e.g. via `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`, used for cache/artifact extraction) can write or overwrite arbitrary files relative to the extraction working directory, including outside the intended cache/artifact root, on any executor where the runner helper process directly performs zip extraction with this code path. This can lead to file overwrite in the build host/container filesystem outside the intended sandboxed root, matching the "path-root escape leading to stronger-context overwrite" impact.

### Likelihood Explanation
Preconditions: the job or a party who can influence cache/artifact content supplies a zip archive whose entries contain `..` segments, absolute paths, or mixed-separator equivalents, and this archive is extracted via the legacy zip extractor path in `helpers/archives/zip_extract.go` (used by `ziplegacy.extractor.Extract` for cache/artifact restore). This is fully attacker-controlled (archive bytes are job/cache/artifact content) and requires no special privilege beyond being able to produce a cache/artifact for the job — i.e., a normal pipeline author. It is repeatable and deterministic.

Note: I could not fully confirm whether the currently default extraction path uses `fastzip`-based extraction (`commands/helpers/archive/fastzip/zip_fastzip_extractor.go`) instead of the legacy `zip_extract.go` path for all runner versions/configurations, which may have its own path-sanitization behavior (fastzip commonly guards against zip-slip). This should be verified, since if the legacy path (`ziplegacy`) is only a fallback, exploitability depends on how/when that fallback is selected.

### Recommendation
Before performing any of `os.Mkdir`, `os.MkdirAll`, `os.OpenFile`, or `os.Symlink` in `extractZipFile`/`extractZipDirectoryEntry`/`extractZipFileEntry`/`extractZipSymlinkEntry`, canonicalize `file.Name` (convert all separators, `filepath.Clean`) and verify via `filepath.Rel`/`filepath.IsAbs` (similar to the existing `helpers/path/windows_path.go` `Contains` logic) that the resulting path stays within the intended extraction root; reject or skip entries that resolve outside that root, and also validate symlink targets to prevent writing outside the root through a symlink+relative-write combination.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go` style:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    dir := t.TempDir()
    root := filepath.Join(dir, "root")
    require.NoError(t, os.MkdirAll(root, 0o755))

    // build in-memory zip with an entry escaping root via mixed separators
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("..\\../escaped.txt") // mixed separators
    w.Write([]byte("pwned"))
    zw.Close()

    origWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(root))
    defer os.Chdir(origWd)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the file was NOT written outside root
    _, err = os.Stat(filepath.Join(dir, "escaped.txt"))
    assert.True(t, os.IsNotExist(err), "zip-slip: file escaped extraction root")
}
```
Expected (buggy) result: the assertion fails because `escaped.txt` is created one level above `root`, proving the path-root escape.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
