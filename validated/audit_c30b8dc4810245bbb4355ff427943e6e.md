### Title
`check_parent_tenure_choice` trusts a possibly-stale local SignerDB tally instead of the node-supplied `nakamoto_blocks` list, allowing a >1-block tenure reorg to be signed - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`SortitionData::check_parent_tenure_choice` decides whether a reorged tenure had "more than one globally accepted block" by calling `signer_db.get_globally_accepted_block_count_in_tenure`, a purely local tally maintained by this individual signer [1](#0-0) . The node's own RPC response for the same tenure (`TenureForkingInfo`) already carries the authoritative `nakamoto_blocks: Option<Vec<NakamotoBlock>>` list of every block actually mined/accepted in that tenure [2](#0-1) , but this field is never consulted by the reorg-permission logic. If the local SignerDB is stale about a specific tenure (e.g., because the signer missed a group/global acceptance broadcast during a burnchain stall or reload), the local count can under-report, letting a genuinely multi-block tenure pass the "at most one block" gate.

### Finding Description
The intended safety property is: *reorg-allowed decision == every reorged tenure had at most one globally accepted block* (ground truth). The code implements this equality using `signer_db.get_globally_accepted_block_count_in_tenure(&tenure.consensus_hash)` [3](#0-2) , which reflects only what this individual signer has locally recorded as globally accepted, not the node's canonical chainstate. The same `get_tenure_forking_info` RPC call that supplies `tenure.first_block_mined` (used later for the timing check at lines 225-245) also supplies `tenure.nakamoto_blocks`, the node's authoritative list of blocks processed in that tenure [4](#0-3) , but `check_parent_tenure_choice` never reads it.

Path: `SortitionsView::check_proposal` → `validate_tenure_change_payload` → `SortitionData::check_parent_tenure_choice` → early-exit gate using `signer_db.get_globally_accepted_block_count_in_tenure` → (if ≤1 locally known) → timing check against `get_first_approved_block_in_tenure`'s `approved_time` → `record_superseded_tenure` → `mark_tenure_superseded` [5](#0-4) .

If, due to a burnchain stall/fork, this signer's local DB only ever recorded one block of tenure T as globally accepted (missing a second block that was in fact globally accepted according to the node's own `nakamoto_blocks` for T), the `> 1` guard is bypassed. The code then proceeds to check only the timing of the *first* known block via `get_first_approved_block_in_tenure` [6](#0-5)  and, if that first block's approval arrived close enough to the next burn block, marks the entire tenure (including the second, unknown-to-this-signer block) as superseded and returns `Ok(true)` [7](#0-6) . This signer then signs a `BlockResponse` accepting a tenure-change block that reorgs a tenure the ground truth (node's `nakamoto_blocks`) shows had two globally accepted blocks — a `ReorgNotAllowed` bypass.

### Impact Explanation
This breaks canonicity/chain-safety: a signer would sign a tenure-change block that orphans a tenure the protocol rule (at most one globally accepted block) was meant to protect, contributing its signature weight toward a deeper reorg than permitted. If multiple signers independently suffer the same local staleness (plausible, since all of them derive their local tally from block-response gossip that can be missed identically during the same burn stall), the reorg could accumulate enough signatures to be finalized, splitting the canonical chain. This matches the Critical category: "a signer signing an invalid, non-canonical, or conflicting block."

### Likelihood Explanation
Requires: (1) a real burnchain stall/fork that causes a signer's local SignerDB to miss a global-acceptance update for the second block of a tenure — an organic/naturally occurring condition, not requiring elevated privilege; (2) an attacker who wins the next sortition and proposes a tenure-change block reorging that tenure, timed so that the *first* block's approval-to-sortition gap is under `first_proposal_burn_block_timing` — achievable with a single miner slot and normal proposal gossip, no majority-signer or node-operator access needed. This is repeatable any time a burn stall creates staleness windows and the attacker can win a slot immediately after.

### Recommendation
Base the "more than one block" check on the node-supplied ground truth (`tenure.nakamoto_blocks`) from `get_tenure_forking_info` rather than (or in addition to, taking the max/union of) the local `signer_db` tally, so a locally stale record cannot understate the true block count of the reorged tenure. If `tenure.nakamoto_blocks` is `None` or the RPC is unreliable, fail closed (reject the reorg) rather than defaulting to the local count.

#[test]
fn stale_local_db_undercounts_globally_accepted_blocks_allows_bad_reorg() {
    // 1. Build a SortitionData `self` whose parent_tenure_id != prior_sortition (a reorg attempt).
    // 2. Mock StacksClient::get_tenure_forking_info to return a TenureForkingInfo for tenure T with:
    //      first_block_mined = Some(block1_id)
    //      nakamoto_blocks = Some(vec![block1, block2])   // ground truth: 2 globally accepted blocks
    // 3. Seed SignerDb so that only block1 is recorded as GloballyAccepted for T
    //    (simulating a burn stall where the signer never observed block2's acceptance).
    // 4. Set local_block_info.approved_time for block1 such that
    //    sortition_state_received_time - approved_time < first_proposal_burn_block_timing.
    // 5. Call sortition_data.check_parent_tenure_choice(&mut signer_db, &client, &timing).
    //
    // Ground truth equality: tenure T had 2 globally accepted blocks -> reorg MUST be Ok(false).
    // Bug: signer_db.get_globally_accepted_block_count_in_tenure(&T) returns 1 (stale),
    // so the function proceeds past the `> 1` gate and returns Ok(true).
    assert_eq!(
        result.unwrap(),
        false,
        "check_parent_tenure_choice must reject reorg of a tenure with >1 globally accepted block per ground truth (node's nakamoto_blocks), but returned true due to stale local tally"
    );
}

impl TenureForkingInfo {
    fn from_snapshot(
        sn: &BlockSnapshot,
        sortdb: &SortitionDB,
        chainstate: &StacksChainState,
        tip_block_id: &StacksBlockId,
    ) -> Result<Self, ChainError> {
        let (first_block_mined, nakamoto_blocks) = if !sn.sortition {
            (None, None)
        } else {
            // is this a nakamoto sortition?
            let epoch = SortitionDB::get_stacks_epoch(sortdb.conn(), sn.block_height)?.ok_or_else(
                || {
                    warn!(
                        "Failed to lookup stacks epoch for processed snapshot height {}",
                        sn.block_height
                    );
                    ChainError::InvalidChainstateDB
                },
            )?;
            if epoch.epoch_id < StacksEpochId::Epoch30 {
                (
                    StacksChainState::get_stacks_block_header_info_by_consensus_hash(
                        chainstate.db(),
                        &sn.consensus_hash,
                    )?
                    .map(|header| header.index_block_hash()),
                    None,
                )
            } else {
                (
                    NakamotoChainState::get_nakamoto_tenure_start_block_header(
                        &mut chainstate.index_conn(),
                        tip_block_id,
                        &sn.consensus_hash,
                    )?
                    .map(|header| header.index_block_hash()),
                    Some(
                        chainstate
                            .nakamoto_blocks_db()
                            .get_nakamoto_blocks_in_tenure(&sn.consensus_hash)?,
                    ),
                )
            }
        };
        Ok(TenureForkingInfo {
            burn_block_hash: sn.burn_header_hash.clone(),
            burn_block_height: sn.block_height,
            sortition_id: sn.sortition_id.clone(),
            parent_sortition_id: sn.parent_sortition_id.clone(),
            consensus_hash: sn.consensus_hash.clone(),
            was_sortition: sn.sortition,
            first_block_mined,
            nakamoto_blocks,
        })
    }
