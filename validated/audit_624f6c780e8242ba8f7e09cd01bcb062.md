### Title
Late node responses are attributed by request ID alone, allowing a stale response to be merged into a subsequently created request that reuses the same ID - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`activeRequests` is keyed only by the client-supplied `req.ID` string, and `HandleNodeMessage` resolves the target `*activeRequest` via `getActiveRequest(resp.ID)` with no per-instance generation token. Once `removeExpiredRequests` (or any completion path) deletes an entry, a brand-new `activeRequest` can immediately be created for the same ID, and any response that was actually addressed to the deleted (expired) request but arrives late is merged into the new request's response set, because nothing ties the response to the specific request instance it was solicited for.

### Finding Description
`HandleJSONRPCUserMessage` accepts a client/attacker-supplied `req.ID` with only length/emptiness checks [1](#0-0) . `newActiveRequest` only rejects reuse while an entry for that ID is still present in the map, guarded by `h.mu` [2](#0-1) . Deletion happens in `sendResponseAndClearRequest`, which is invoked from three independent completion paths — direct node-triggered completion, quorum-grace forwarding, and `removeExpiredRequests` — all racing on `ar.completed.CompareAndSwap` and then deleting the map entry under `h.mu.Lock()` [3](#0-2) .

`HandleNodeMessage` resolves the target object purely by string ID via `getActiveRequest`, then calls `ar.addResponseForNode` on whatever object currently occupies that map slot [4](#0-3) . There is no generation/epoch/nonce carried in the `activeRequest` struct to distinguish "request instance N for ID Z" from "request instance N+1 for ID Z" [5](#0-4) .

`removeExpiredRequests` snapshots expired `*activeRequest` pointers under `RLock`, releases the lock, and then does potentially slow work (bundling, callback dispatch) before finally deleting the entry via `sendResponseAndClearRequest` [6](#0-5) . This creates a window where: (1) request Z expires and is queued for cleanup, (2) cleanup eventually deletes Z from `activeRequests`, (3) a caller immediately resubmits a new request with the same ID Z, succeeding because the map slot is now empty, creating a distinct new `*activeRequest` object, and (4) a late in-flight node response for the *original* Z (sent before expiry, delayed in transit or delayed by the node) arrives and is routed by `getActiveRequest("Z")` to the *new* object, merging stale data into a logically unrelated request's response set and bundle.

### Impact Explanation
Because attribution is solely by the mutable string key and not by a stable per-request instance identifier, a stale/late node response intended for one logical request can be folded into the bundle of a different, later request that happens to reuse the same ID. This breaks the "isolation of per-request state across cleanup/reuse boundary" invariant: the resulting bundle sent to the enclave (and ultimately whatever payload is returned via `sendResponseAndClearRequest`/`ar.SendResponse`) for the new request can be contaminated with a response that was never actually produced in answer to the new request's parameters. In the confidential relay context (`MethodSecretsGet`, `MethodCapabilityExec`), this constitutes a violation of per-request response integrity/isolation, and where IDs are not strictly namespaced per caller session, it also opens the potential for one party's stale response fragment to be incorporated into an unrelated request's bundle, corresponding to a cross-request response leakage/confusion issue.

### Likelihood Explanation
Exploitation requires only unauthenticated ability to submit confidential relay requests (already a precondition in this codebase), no privileged access. The attacker must: submit request with ID `Z`, allow it to reach `requestTimeout` so `removeExpiredRequests` schedules it, and race a slow/delayed node response for `Z` against a second `HandleJSONRPCUserMessage("Z", ...)` call timed to land in the narrow window right after `sendResponseAndClearRequest` deletes the old entry. This is a genuine timing race (narrow, on the order of the goroutine scheduling delay between map delete and the next `getActiveRequest` lookup), so it is not trivially deterministic, but it is fully reproducible under controlled test conditions (fake clock + synchronization points), and repeatable by an attacker who controls request cadence and can induce network delay on a node response (e.g. via a slow read on their own leg of the relay, or by choosing timing empirically). No cryptographic or node-side misbehavior is required — a normal, honest node's delayed response is sufficient.

### Recommendation
Bind each `activeRequest` to a unique, immutable generation identifier (e.g., a monotonically increasing counter or random nonce) separate from the client-supplied `req.ID`, and have `HandleNodeMessage`/`addResponseForNode` verify that the response corresponds to the exact generation of the `activeRequest` object it was dispatched to (for example, capture the specific `*activeRequest` pointer/generation at fan-out time in the per-node send path rather than re-resolving by ID at response time, or store `(ID, generation)` tuples in `activeRequests` and reject responses whose generation doesn't match the current occupant). Alternatively, delay ID reuse (quarantine an ID for at least `nodeSendTimeout` after deletion) so a straggling response can no longer be routed to a newly created request with the same ID.

### Proof of Concept

2. Submit request R1 with ID `"Z"`, params P1, via `HandleJSONRPCUserMessage`; do not deliver any node responses yet.
3. Advance the fake clock past `requestTimeout` and call `h.removeExpiredRequests(ctx)` but intercept/delay it (e.g., via a hook or by controlling goroutine scheduling with a channel) so it is mid-flight (past `copiedResponses`, before `sendResponseAndClearRequest` deletes the map entry) — or, more simply, call `removeExpiredRequests` synchronously to completion, then immediately:
4. In parallel: (a) call `h.HandleNodeMessage(ctx, respForZ, nodeAddr)` with a response encoding data uniquely identifying P1 (the old request), and (b) call `h.HandleJSONRPCUserMessage(ctx, reqWithID_Z_andParamsP2, callback2)` to create a new request R2 for the same ID, racing them via goroutines with a `sync.WaitGroup`/barrier so the node message is delivered right after (a) `newActiveRequest` succeeds for R2.
5. Assert that: `callback2`'s eventually-received bundle/response does NOT contain any content derived from P1's node response (i.e., the response payload attributable to R1 must never appear associated with R2's callback), and that `h.activeRequests["Z"]` after resolution correctly reflects only R2's own collected responses (verifiable by inspecting bundler input via a spy `relayBundler`).

type activeRequest struct {
	req       jsonrpc.Request[json.RawMessage]
	responses map[string]*jsonrpc.Response[json.RawMessage]
	mu        sync.Mutex
	completed atomic.Bool

	// graceStarted is set the first time the request holds F+1 signed responses, so
	// the grace deadline is armed once per request rather than moved forward by every
	// later response. graceDeadline is guarded by mu and is only meaningful once
	// graceStarted is set.
	graceStarted  atomic.Bool
	graceDeadline time.Time

	createdAt time.Time
	gwhandlers.Callback
}

func (ar *activeRequest) addResponseForNode(nodeAddr string, resp *jsonrpc.Response[json.RawMessage]) bool {
	ar.mu.Lock()
	defer ar.mu.Unlock()
	_, exists := ar.responses[nodeAddr]
	if exists {
		return false
	}

	ar.responses[nodeAddr] = resp
	return true
}

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := logger.With(h.lggr, "method", er.req.Method, "requestID", er.req.ID)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
