### Title
Zip Slip / Path Traversal in ziplegacy Extractor via Unvalidated `zip.File.Name` - (File: `helpers/archives/zip_extract.go`, `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`)

### Summary
The ziplegacy zip extractor (`extractor.Extract` in `zip_legacy_extractor.go`) delegates directly to `archives.ExtractZipArchive`, which writes each `zip.File` entry using `file.Name` verbatim — via `os.Mkdir`, `os.Symlink`, and `os.OpenFile` — with no `filepath.Join` against an extraction root and no containment check. This is in stark contrast to the sibling `tarzstd` extractor, which explicitly joins entries to `e.dir`, resolves an absolute path, and rejects any path escaping the root. A job that controls the bytes of a cache archive (via `CacheExtractorCommand.File`/upload-then-download cycle) can therefore craft zip entries with `../`-relative or absolute names to write files outside the intended cache/build directory.

### Finding Description
`extractZipFileEntry`, `extractZipDirectoryEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` operate directly on `file.Name`: [1](#0-0) 

`extractZipFile` only creates parent directories with `filepath.Dir(file.Name)` and dispatches to these functions — again with no join against any root directory and no `..`/absolute-path rejection: [2](#0-1) 

`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` unconditionally for every entry, with no path validation step: [3](#0-2) 

Crucially, the ziplegacy `extractor` struct carries a `dir` field intended to scope extraction, but `Extract` never uses it — it passes only the raw `zip.Reader` to `ExtractZipArchive`, so the target directory is never joined with entry names at all: [4](#0-3) 

Compare this to `tarzstd`'s extractor, which computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path lacking the `e.dir` prefix — the exact containment check that is missing here: [5](#0-4) 

**Reachability**: `CacheExtractorCommand.Execute` downloads `c.File` (a job/pipeline-controlled cache blob, or a locally-cached file) then calls `archive.NewExtractor(format, f, size, wd)` and `extractor.Extract(ctx)`: [6](#0-5) 

Since cache archives are produced from the job's own cache paths and typically round-tripped through GitLab's cache storage under the job's control (the job author decides what gets cached, and the zip is later re-extracted by Runner in a later job run on the same or another job on the same host), a job can substitute/craft a cache zip payload containing entries like `../../../tmp/poc` or `/etc/cron.d/x`. When such a payload is extracted via the ziplegacy path, `os.OpenFile`/`os.Mkdir`/`os.Symlink` operate on that literal (possibly absolute or traversal) path, writing outside `wd`.

No allowlist, path validation, or containment check exists anywhere in `ExtractZipArchive` or its helpers to stop this, unlike the equivalent tar+zstd path.

### Impact Explanation
A job that controls zip archive contents used for cache extraction (extracted via the ziplegacy zip path) can write arbitrary files to arbitrary paths on the Runner host filesystem (subject to OS permissions of the Runner/helper process), including outside the job workspace. Depending on the executor (particularly shell executor or any executor where the helper/cache-extractor process runs with meaningful host filesystem permissions), this can lead to file overwrite outside the workspace and potential follow-on code execution via cron/profile/authorized_keys style files, matching the scoped impact.

### Likelihood Explanation
Preconditions: an unprivileged pipeline author can control the content of a cache archive that a Runner (using the ziplegacy zip extractor for `archive.Zip`/`archive.ZipZstd` formats) later extracts. The attack requires only fabricating a normal zip (`archive/zip` from Go's stdlib) with a malicious `Name` field — no special privileges, no cryptographic bypass, and it is fully repeatable. The main uncertainty is which extractor backend (`fastzip` vs `ziplegacy`) is selected by default for a given Runner build/config, since both are registered for `archive.Zip`; but the ziplegacy path itself, whenever selected/reachable, is proven vulnerable end-to-end.

### Recommendation
In `helpers/archives/zip_extract.go`, thread the target directory through `ExtractZipArchive`/`extractZipFile`/`extractZip*Entry` (matching `tarzstd`'s approach): join `file.Name` with the extraction root via `filepath.Join`, resolve with `filepath.Abs`, and reject any entry whose resolved path does not have the root directory as a prefix (also reject absolute names in the zip and symlink targets that escape the root). Update `ziplegacy.extractor.Extract` to actually pass `e.dir` into the extraction call instead of discarding it.

### Proof of Concept
```go
func TestZipLegacyExtractor_PathTraversal(t *testing.T) {
    workDir := t.TempDir()
    outsideMarker := filepath.Join(os.TempDir(), "poc_outside_marker")
    defer os.Remove(outsideMarker)

    // Build malicious zip with a traversal entry.
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    f, err := zw.Create("../../../../../../tmp/poc_outside_marker")
    require.NoError(t, err)
    _, err = f.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    r := bytes.NewReader(buf.Bytes())
    ext, err := ziplegacy.NewExtractor(r, int64(r.Len()), workDir)
    require.NoError(t, err)

    err = ext.Extract(context.Background())
    require.NoError(t, err)

    // Assert file was written outside workDir.
    _, statErr := os.Stat(outsideMarker)
    assert.NoError(t, statErr, "expected escaped file to exist outside workDir")
}
```
Expected result: the file lands at `/tmp/poc_outside_marker` (outside `workDir`), demonstrating the missing containment check.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
