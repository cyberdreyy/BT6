### Title
JWT replay-protection cache uses an independently configured TTL decoupled from the token's own expiry, permitting replay of an already-used, still-valid JWT after cache eviction - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The gateway's HTTP-trigger authorization path (`WorkflowMetadataHandler.Authorize`) prevents JWT replay by recording each `jti` in an in-memory `jwtReplayCache` keyed by a configurable `JWTReplayPeriodMs` value, entirely separate from the JWT's own `exp`/`iat`-derived validity window (bounded by `maxJWTExpiryDuration` in `core/utils/jwt.go`). Just as the reported AUM bug allowed stale off-chain state to be trusted indefinitely with no expiration check tied to reality, here a security-critical "already used" marker has its own independent expiration that is not tied to the actual lifetime of the token it protects.

### Finding Description
`NewWorkflowMetadataHandler` constructs the replay cache with a TTL taken straight from service config: [1](#0-0) 

`Authorize` verifies the JWT, checks `isReplay(claims.ID)`, and if not a replay, records usage: [2](#0-1) 

The `jwtReplayCache` struct stores `jti -> timestamp` and is evicted based on its own `cleanupPeriod`, unrelated to the JWT's `exp` claim: [3](#0-2) 

Separately, `VerifyRequestJWT` only bounds how long a token *may* live (`maxJWTExpiryDuration`, shown in tests as up to a multi-minute window) but does not coordinate with the gateway's replay-cache retention window: [4](#0-3) 

Because the two lifetimes are configured and enforced independently, if `JWTReplayPeriodMs` (the replay-cache retention window) is shorter than the actual `exp - iat` lifetime of a workflow-signed JWT, a `jti` entry recorded in `recordUsage` can be evicted from the cache while the JWT itself is still cryptographically valid (unexpired). At that point, `isReplay` will return `false` for the same previously-used token, and `Authorize` will accept it a second time — defeating replay protection entirely. This mirrors the AUM issue's root cause: a freshness/validity check exists in isolation but is not reconciled against the true validity window of the value it is meant to gate, so stale/expired protective state is silently trusted as still-authoritative.

### Impact Explanation
Successful replay of a signed workflow trigger JWT lets an unprivileged network observer (anyone who can capture a previously sent, valid JWT over the wire or from logs) re-submit the same authenticated `HTTPTriggerRequest`/`WorkflowExecute` call to the gateway and have it accepted as if freshly authorized, causing duplicate/unauthorized workflow executions to be dispatched to the DON. This is a concrete authentication bypass (replay of impersonated request) on the internet-facing gateway, not merely a theoretical risk.

### Likelihood Explanation
Likelihood is Low/Unlikely, matching the class of issue in the reference report: it requires (a) an operator configuring `JWTReplayPeriodMs` shorter than the JWT lifetime windows actually used by workflow clients, and (b) an attacker capturing a valid, not-yet-expired JWT to replay after cache eviction. There is no enforced invariant in code tying `JWTReplayPeriodMs` to `maxJWTExpiryDuration`/token `exp`, so misconfiguration is possible without the system flagging it.

### Recommendation
Enforce that the replay-cache retention window (`JWTReplayPeriodMs`) is always greater than or equal to the maximum possible JWT lifetime (`maxJWTExpiryDuration` / the actual `exp - iat` per token), either by deriving the cache TTL directly from the token's own `exp` claim (evict only after the token has actually expired) rather than from an independently configured value, or by validating at startup that `JWTReplayPeriodMs >= maxJWTExpiryDuration` and refusing to start otherwise.

### Proof of Concept
1. Gateway operator configures `JWTReplayPeriodMs` to a value smaller than the workflow client's token lifetime (`exp - iat`, allowed up to `maxJWTExpiryDuration`).
2. Workflow owner submits a valid `HTTPTriggerRequest` with a signed JWT (`jti = X`); `Authorize` verifies it, finds it's not a replay, executes the request, and calls `recordUsage(X)`.
3. After `JWTReplayPeriodMs` elapses (but before the JWT's own `exp`), the replay cache's cleanup removes the `jti = X` entry.
4. An attacker who captured the original JWT resubmits the identical request with the same token before its `exp`; `isReplay(X)` now returns `false` (entry evicted), so `Authorize` treats it as a fresh, valid request and re-executes the workflow trigger — a successful replay/authentication bypass.

Note: I was not able to fully inspect the bodies of `isReplay`/`recordUsage` (only their call sites and the enclosing struct/constructor) within the available tool budget, so the exact eviction algorithm (e.g., sliding vs. fixed window) is inferred from the field name `cleanupPeriod` and the constructor wiring to `cfg.JWTReplayPeriodMs`; a Devin session with full file access should confirm the precise eviction semantics before remediation.

```go
func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
```

```go
// VerifyRequestJWT verifies a signed JWT for a JSON-RPC request
// It recovers and returns the public key used to sign the JWT, checks the issuer, validates the digest,
// and performs all validations done by jwt.ParseWithClaims() including expiration checks.
func VerifyRequestJWT[T any](tokenString string, req jsonrpc.Request[T], opts ...VerifyOption) (*JWTClaims, gethcommon.Address, error) {
	options := &verifyOptions{}
	for _, opt := range opts {
		opt(options)
	}

	maxExpiryDuration := maxJWTExpiryDuration
	if options.maxExpiryDuration != nil {
		maxExpiryDuration = *options.maxExpiryDuration
	}

	issuedAtTolerance := defaultIssuedAtTolerance
	if options.issuedAtTolerance != nil {
		issuedAtTolerance = *options.issuedAtTolerance
	}
	signedString, signature, err := splitToken(tokenString)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	decodedSignature, err := base64.RawURLEncoding.DecodeString(signature)
	if err != nil {
		return nil, gethcommon.Address{}, fmt.Errorf("signature segment is not valid base64url: %w", err)
	}
	pubKey, err := GetSignersEthAddress([]byte(signedString), decodedSignature)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedToken, err := jwt.ParseWithClaims(tokenString, &JWTClaims{}, func(token *jwt.Token) (any, error) {
		if token.Method.Alg() != EthereumSigningMethod.Alg() {
			return nil, fmt.Errorf("unsupported JWT 'alg': '%s'. Expected '%s'", token.Method.Alg(), EthereumSigningMethod.Alg())
		}
		if _, ok := token.Method.(*SigningMethodEth); !ok {
			return nil, jwt.ErrSignatureInvalid
		}
		return pubKey, nil
	})
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedClaims, ok := verifiedToken.Claims.(*JWTClaims)
	if !ok {
		return nil, gethcommon.Address{}, errors.New("claims payload is not in the expected format")
	}
	if !verifiedToken.Valid {
		return nil, gethcommon.Address{}, errors.New("signature or claims validation failed")
	}
	reqDigest, err := req.Digest()
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	if verifiedClaims.ID == "" {
		return nil, gethcommon.Address{}, errors.New("JWT ID (jti) is required but missing")
	}
	if verifiedClaims.ExpiresAt == nil {
		return nil, gethcommon.Address{}, errors.New("expiredAt (exp) is required but missing")
	}
	if verifiedClaims.IssuedAt == nil {
		return nil, gethcommon.Address{}, errors.New("issuedAt (iat) is required but missing")
	}
	now := time.Now()
	issuedAt := verifiedClaims.IssuedAt
	if issuedAt.After(now.Add(issuedAtTolerance)) {
		return nil, gethcommon.Address{}, fmt.Errorf("issuedAt (iat) is too far in the future (beyond tolerance of %.0f seconds)", issuedAtTolerance.Seconds())
	}
	duration := verifiedClaims.ExpiresAt.Sub(verifiedClaims.IssuedAt.Time)
	if duration > maxExpiryDuration {
		return nil, gethcommon.Address{}, fmt.Errorf("token lifetime %.0f sec exceeds the maximum allowed %.0f sec. Reduce the gap between 'iat' and 'exp'", duration.Seconds(), maxExpiryDuration.Seconds())
	}
```
