### Title
Unsynchronized map read in `WorkflowMetadataHandler.Authorize` races with concurrent metadata resync - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize`, which authorizes every inbound HTTP-trigger request from an unprivileged client against the gateway, reads `h.authorizedKeys[workflowID]` without holding `h.mu`, while the periodic `syncMetadata` goroutine reassigns `h.authorizedKeys` (and the related `workflowIDToRef`/`workflowRefToID`/`workflowShards` maps) under `h.mu.Lock()` every `MetadataAggregationIntervalMs`. This is a genuine, unprivileged-client-reachable check/use race between an authorization-data read and a concurrent authorization-data write.

### Finding Description
`Authorize` is called directly from `httpTriggerHandler.authorizeRequest`, which is invoked for every JSON-RPC `workflowExecute`/HTTP-trigger request coming from an external, unauthenticated client through the gateway [1](#0-0) . Inside `Authorize`, the function reads the shared map `h.authorizedKeys` with no lock at all: [2](#0-1) 

Meanwhile, `syncMetadata` — run on a periodic ticker (`MetadataAggregationIntervalMs`) — fully replaces `h.authorizedKeys`, `h.workflowIDToRef`, `h.workflowRefToID`, and `h.workflowShards` while holding `h.mu.Lock()`: [3](#0-2) [4](#0-3) 

Because `Authorize` never takes `h.mu` (neither read nor write lock), a concurrent write to `h.authorizedKeys` from `syncMetadata` while `Authorize` is reading it is a data race on the map header in Go's memory model. This is unprivileged-client-reachable because the read path is triggered by any external caller hitting the gateway's HTTP-trigger endpoint, and the write path fires automatically on a fixed timer independent of any request.

### Impact Explanation
A concurrent unsynchronized map read/write in Go can, at best, silently observe a torn/stale value (e.g., authorizing against an in-flight-replaced key set, so a signer that was authorized microseconds ago under the "old" map or the "new" map may get an inconsistent accept/reject decision), and at worst can crash the process (`fatal error: concurrent map read and map write`), since Go's runtime actively detects concurrent unsynchronized map access and panics irrecoverably (not a recoverable panic). Given `Authorize` runs on every inbound gateway request, an attacker sending a high volume of HTTP-trigger requests during the periodic metadata sync window can reliably trigger this race, causing gateway process crashes — a denial-of-service condition on the internet-facing gateway from an unprivileged actor.

### Likelihood Explanation
`syncMetadata` runs unconditionally on a fixed interval as long as the handler is started, so the race window recurs continuously. `Authorize` executes for every incoming request from any external client that can reach the gateway's `workflowExecute`/HTTP-trigger endpoint — no privilege or prior registration is required to send a request (only to be *authorized* by it). Triggering the race merely requires sending trigger requests at a rate likely to overlap with the periodic sync tick, which is trivial for a remote unauthenticated actor.

### Recommendation
Take `h.mu.RLock()`/`RUnlock()` around the map reads in `Authorize` (and any other unguarded reads of `authorizedKeys`/`workflowIDToRef`/`workflowRefToID`/`workflowShards`), matching the locking discipline already used by `syncMetadata` and `WorkflowShards`. Consider using `sync/atomic.Pointer` to snapshot the whole metadata set so reads never need to block on the sync goroutine, or ensure the entire read/decision sequence in `Authorize` occurs under a single `RLock`.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (h *WorkflowMetadataHandler) runTicker(period time.Duration, fn func(ctx context.Context)) {
	h.wg.Go(func() {
		ctx, cancel := h.stopCh.NewCtx()
		defer cancel()
		ticker := time.NewTicker(period)
		defer ticker.Stop()
		for {
			select {
			case <-ticker.C:
				fn(ctx)
			case <-ctx.Done():
				return
			}
		}
	})
}
