### Title
Internal DB/query error details leaked to unauthenticated caller via wrapped `finding external initiator` error - (File: core/web/auth/auth.go)

### Summary
`AuthenticateExternalInitiator` returns `errors.Wrap(err, "finding external initiator")` for any non-`sql.ErrNoRows` error from `store.FindExternalInitiator`, and this wrapped error is passed unmodified to `jsonAPIError`, which serializes `err.Error()` directly into the JSON response body sent back to the (still unauthenticated) client.

### Finding Description
In `AuthenticateExternalInitiator` (core/web/auth/auth.go:119-151), the only error normalized to the generic `auth.ErrorAuthFailed` is `sql.ErrNoRows`. Any other error returned by `store.FindExternalInitiator` (e.g., a DB connection error, context deadline error, or a database driver error triggered by malformed/oversized header values causing a query failure) is wrapped with `errors.Wrap(err, "finding external initiator")` and returned as-is at line 132. [2](#0-1) 

This error propagates up through the `Authenticate` middleware loop: since it is not `auth.ErrorAuthFailed`, the loop breaks and the error is passed straight to `jsonAPIError(c, http.StatusUnauthorized, err)`. [3](#0-2) 

`jsonAPIError` checks only whether the error is a `*models.JSONAPIErrors`; since the wrapped error is a plain `*errors.withMessage`, it falls through to `c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))`, embedding the full wrapped string (`"finding external initiator: <underlying driver/db error>"`) in the HTTP response body returned to the caller. [1](#0-0) 

No middleware or presenter downstream redacts this — the response is sent directly as the HTTP body with a 401 status.

### Impact Explanation
This matches Chainlink's internal error / information disclosure impact class: an unauthenticated caller (anyone able to send crafted EI-auth headers) can potentially force a non-`ErrNoRows` database error and receive back raw driver/query error text in the JSON response, which could reveal internal implementation details such as query fragments, column/table hints, or driver-specific error strings. This does not by itself grant authentication bypass or fund movement but is a genuine internal information leak to an unauthenticated party.

### Likelihood Explanation
Requires the attacker to actually trigger a non-`ErrNoRows` error from `FindExternalInitiator` in `core/bridges/orm.go` — e.g. a DB-layer error (connection failure, encoding error, oversized/invalid characters causing a driver-level error) rather than a simple "not found." This is a lower-likelihood/opportunistic condition (it depends on transient DB behavior or on being able to reliably provoke a query failure via crafted header input), but it requires zero privileges/credentials — only the ability to send unauthenticated HTTP requests with EI headers — making it low-effort to attempt repeatedly.

### Recommendation
In `AuthenticateExternalInitiator`, do not propagate the wrapped underlying error to the client. Log the wrapped error server-side (e.g., via `logger`) and return a generic error such as `auth.ErrorAuthFailed` (or a new generic "internal error" sentinel with a fixed message) for any error case, mirroring the pattern already used for `sql.ErrNoRows`. Ensure `jsonAPIError` callers in this auth path never receive raw internal error objects.

### Proof of Concept
Go handler-level test plan:
1. Implement a mock `Authenticator` (or use `core/bridges/mocks` if it supports custom return errors) whose `FindExternalInitiator` returns a non-`sql.ErrNoRows` error, e.g. `errors.New("pq: connection reset by peer")`.
2. Build a `gin.Engine` wiring `auth.Authenticate(store, auth.AuthenticateExternalInitiator)` in front of a dummy handler, as done in existing auth tests.
3. Send an HTTP request with `static.ExternalInitiatorAccessKeyHeader` / `static.ExternalInitiatorSecretHeader` set to arbitrary values.
4. Assert the response status is 401 and, critically, assert that the response JSON body's error message does NOT contain "connection reset", "pq:", or any substring from the underlying mock error — only a fixed generic string (e.g., matching `auth.ErrorAuthFailed.Error()`).
5. Currently, this test would fail because `strings.Contains(body, "finding external initiator: pq: connection reset by peer")` is true, demonstrating the leak.

	_ = c.Error(err).SetType(gin.ErrorTypePublic)

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}
