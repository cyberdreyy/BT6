### Title
Miner-controlled "activity" reset via `update_last_activity_time` lets a single leader indefinitely suppress the inactivity fallback to the prior tenure - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`check_latest_block_in_tenure` treats a rejected, conflicting/lower proposal as valid "miner activity" and refreshes `last_activity_time` whenever the tenure's last signed block has no `signed_group` timestamp (i.e., was only locally, not globally, accepted). Because that "no signed_group" condition can persist indefinitely (a block that a fraction of signers locally accepted but that never became globally accepted), a single miner can keep resetting its own inactivity clock forever by repeatedly sending stale/invalid conflicting proposals, defeating the `block_proposal_timeout` liveness mechanism that is supposed to let signers fall back to the prior tenure's miner.

### Finding Description
`check_latest_block_in_tenure` rejects a proposal that doesn't confirm enough blocks, but before returning `false` it decides whether to still count the attempt as "miner activity": [1](#0-0) 

```
if info.signed_group.is_none_or(|signed_time| {
    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
}) {
    ...
    signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
    ...
}
return Ok(false);
``` [2](#0-1) 

`Option::is_none_or` returns `true` unconditionally when `signed_group` is `None`. `signed_group` is only set once the block is observed as globally accepted (i.e. the whole signer set signed and the node processed it). A block that only a subset of signers locally accepted (`signed_self` set, `signed_group` never set) leaves this condition permanently `true`, with **no time bound at all** — the `reorg_attempts_activity_timeout` window only applies to the `Some(signed_time)` branch.

This activity timestamp is exactly what `is_timed_out` (v1/v2) uses to decide whether the current miner has gone inactive and signers should fall back to the prior tenure: [3](#0-2) [4](#0-3) 

So a single leader (the tenure's own miner, or any actor who can get a same-tenure proposal signed by even one signer without it ever reaching global acceptance) can periodically re-broadcast an already-rejected or stale conflicting proposal at or below the pinned height. Each rejection still calls `update_last_activity_time`, resetting the clock used by `is_timed_out`, so `elapsed > block_proposal_timeout` never becomes true and `check_miner_inactivity` (`stacks-signer/src/v0/signer_state.rs`, lines 282-374) never falls back to the prior sortition's miner.

### Impact Explanation
This breaks the liveness guard described in `docs/signer-flows.md` section 8 (`check_miner_inactivity` → fall back to prior tenure) and matches the "High" impact class: a signer set gets wedged into never reverting from a stalled/uncooperative miner, because the miner can keep the tenure's activity timer artificially fresh forever with garbage/rejected proposals instead of producing valid blocks. This is a liveness DoS triggerable by the one-slot miner alone (no majority-of-signers collusion needed — only a locally-accepted, never-globally-accepted block from any prior legitimate signing round is enough to leave `signed_group` unset).

### Likelihood Explanation
The condition (`signed_group` unset while `signed_self` is set) is a routine occurrence any time a tenure's block reaches local (not global) acceptance — e.g. the pre-commit/signature round completes for some signers but the block is never pushed to/announced by the node (network hiccup, minority partition, or a miner intentionally withholding the block). Once in that state, the miner only needs to keep resubmitting a conflicting/duplicate proposal within the `block_proposal_timeout` cadence, a cheap and entirely miner/gossip-controlled action.

### Recommendation
Bound the "no `signed_group`" branch with the same `reorg_attempts_activity_timeout` (or a similarly finite window measured from `signed_self`) instead of granting it unconditional/indefinite activity credit, so a locally-but-not-globally accepted block cannot be used to freeze the inactivity timer forever.

### Proof of Concept
1. Miner M proposes block B at height h in tenure T; a subset of signers locally accept B (`signed_self` set) but B never reaches global acceptance (e.g., M never gives the assembled signature to any node, or a partition drops the announcement) — `signed_group` remains `None` for `get_tenure_last_block_info`'s row.
2. M repeatedly re-broadcasts B (or any conflicting/lower proposal at height ≤ h) at an interval shorter than `block_proposal_timeout`.
3. Each time, `check_latest_block_in_tenure` rejects the proposal (`Ok(false)`) but hits the `signed_group.is_none_or(...)` branch and calls `update_last_activity_time`, resetting the clock read by `is_timed_out`.
4. `check_miner_inactivity` never observes `elapsed > block_proposal_timeout`, so signers never fall back to the prior tenure's miner even though M produces no new valid, globally accepted blocks — wedging the tenure indefinitely until the next burn block, entirely at M's discretion.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    /// Check if the sortition identified by the ConsensusHash is timed out based on
    /// the blocks within the signer db and the block proposal timeout
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        signer_db: &SignerDb,
        eval: &GlobalStateEvaluator,
        local_address: &StacksAddress,
        timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = signer_db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) =
            signer_db.get_burn_block_received_time_from_signers(eval, sortition, local_address)?
        else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = signer_db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };
        if elapsed > timeout {
            info!("Sortition has timed out";
                "sorition" => %sortition,
                "timeout" => %timeout.as_secs(),
                "elapsed" => %elapsed.as_secs()
            )
        }
        Ok(elapsed > timeout)
    }
