### Title
`getTokenAccountBalance` / `jsonParsed` account decoding trusts an SPL token account's embedded `mint` pubkey without verifying the referenced account is owned by a known SPL Token program - (File: `rpc/src/parsed_token_accounts.rs`)

### Summary
The external report flags that `PoolFactory.deployPool()` lets a caller supply an unvalidated `quoteToken`/oracle pair that downstream code implicitly trusts. The analogous pattern exists in agave's JSON-RPC token-parsing path: `get_additional_mint_data()` and `get_mint_owner_and_additional_data()` in `rpc/src/parsed_token_accounts.rs` fetch whatever account is referenced by a token account's `mint` field and blindly unpack its raw bytes as an SPL `Mint`, without ever checking that the referenced account is actually owned by `spl_token` or `spl_token_2022`. This "trust the embedded reference without checking its authenticity" is the exact bug class from the report, just applied to a token-account's `mint` pointer instead of a pool's `quoteToken`/oracle pointer.

### Finding Description
`get_additional_mint_data()` unconditionally calls `StateWithExtensions::<Mint>::unpack(data)` on the data of whatever account is at the `mint` pubkey read out of a token account, with no ownership/program check: [1](#0-0) 

`get_mint_owner_and_additional_data()`, used by `get_parsed_token_accounts()` (backing `getTokenAccountsByOwner`/`getProgramAccounts` with `jsonParsed` encoding) and by `RpcClient::get_token_account_balance()` (backing `getTokenAccountBalance`), likewise fetches `bank.get_account(mint)` and hands its data straight to `get_additional_mint_data()`, again without checking `mint_account.owner()`: [2](#0-1) 

`get_parsed_token_account()` (used for `getAccountInfo`/`getMultipleAccounts`/simulation results with `jsonParsed`) has the same omission: [3](#0-2) 

By contrast, the sibling `getTokenSupply` handler in `rpc/src/rpc.rs` *does* perform the missing check before parsing a mint: [4](#0-3) 

and the SVM's own token-balance computation (`SvmTokenInfo::unpack_token_account`) also verifies `*mint_account.owner() != program_id` before trusting the mint data: [5](#0-4) 

So the RPC "parsed token account" path is the outlier: it treats an arbitrary pubkey's raw bytes as authoritative `Mint` state as long as the bytes happen to satisfy `StateWithExtensions::<Mint>::unpack`, regardless of which program actually owns/controls that account. A token account's `mint` field is fully attacker-chosen at mint-creation time, and once a mint account is closed (e.g. via a Token-2022 `MintCloseAuthority` extension) its address can later be reused by a completely different, attacker-controlled program with crafted data that still parses as a valid `Mint` (including forged `InterestBearingConfig`/`ScaledUiAmountConfig` extensions).

### Impact Explanation
This falls under "decoder ... misreporting" / "wrong ... account data returned" from a single, unprivileged JSON-RPC call. A wallet or dApp calling `getTokenAccountBalance`, `getAccountInfo`/`getMultipleAccounts` with `encoding: jsonParsed`, or `getTokenAccountsByOwner`/`getProgramAccounts` with `jsonParsed` on a legitimate, unrelated token account can be shown a fabricated `decimals`/`uiAmount`/interest-bearing or scaled-UI-amount multiplier if the mint account at the recorded `mint` pubkey has since been closed and its address reoccupied with attacker-crafted, non-token-program-owned data that still satisfies the `Mint` unpack format. The raw on-chain `amount` (base units) is unaffected, but the human-facing UI amount/decimals returned by the RPC node is wrong, which is exactly the kind of trust-in-unauthenticated-reference problem the external report describes for pool quote tokens/oracles.

### Likelihood Explanation
Reaching this requires: (1) the mint address's original private key (available only to whoever originally created that mint, i.e., a fully permissionless action any user can perform for their own token), (2) the mint being closable (e.g., Token-2022 `MintCloseAuthority`) or otherwise becoming a zero-lamport/purged account, and (3) crafting replacement account data (via any program the same actor controls) that parses cleanly as `Mint` layout. All of these are achievable by an ordinary, unprivileged user for a mint they themselves created, then later reused by other parties' token accounts still referencing that mint pubkey — a single unprivileged RPC call by a third party (no elevated role) then returns the misreported data.

### Recommendation
Before calling `StateWithExtensions::<Mint>::unpack()`, verify the fetched mint account's owner is a known SPL token program, mirroring the check already used in `get_token_supply()` (`is_known_spl_token_id(mint_account.owner())`) and in `SvmTokenInfo::unpack_token_account()` (`*mint_account.owner() != program_id`). Apply this check inside `get_additional_mint_data()`/`get_mint_owner_and_additional_data()` in `rpc/src/parsed_token_accounts.rs` so all `jsonParsed`-encoding RPC paths are consistently protected.

### Proof of Concept
1. Attacker creates SPL Token-2022 mint `M` with the `MintCloseAuthority` extension, decimals=9, and mints tokens into token account `A` (owned by anyone).
2. Time passes; `A` continues to be used/held by third parties who periodically query `getTokenAccountBalance(A)` or `getAccountInfo(A, {encoding: "jsonParsed"})`.
3. Attacker sets mint `M` supply to 0 and calls `CloseAccount` on `M` via its close authority, draining its lamports to zero so it is eventually purged from `AccountsDb` (this exact edge case is acknowledged in code comments about "zero-lamport `AccountSharedData::Default()`" reuse, see `rpc/src/rpc.rs:2319-2331`).
4. Using the same keypair for `M`, the attacker (via `CreateAccount`) reinitializes account `M` under a program they control, writing bytes that satisfy `StateWithExtensions::<Mint>::unpack` (e.g. base `Mint` fields plus a forged `ScaledUiAmountConfig` extension with a large multiplier), while `M` is now owned by the attacker's own program, not `spl_token_2022`.
5. A third party queries `getTokenAccountBalance(A)` (or `getAccountInfo`/`getTokenAccountsByOwner` with `jsonParsed`) on the unrelated, legitimate account `A`. `get_mint_owner_and_additional_data`/`get_additional_mint_data` fetches `M`, skips any owner check, successfully unpacks the forged bytes as `Mint`, and returns the attacker-controlled `decimals`/`ScaledUiAmountConfig`, producing a manipulated `uiAmount`/`uiAmountString` for `A` even though `A`'s actual on-chain state is untouched.

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })

impl SvmTokenInfo {
    fn unpack_token_account<CB: TransactionProcessingCallback>(
        account_loader: &mut AccountLoader<CB>,
        account: &AccountSharedData,
        index: usize,
    ) -> Option<Self> {
        let program_id = *account.owner();
        let generic_token::Account {
            mint,
            owner,
            amount,
        } = generic_token::Account::unpack(account.data(), &program_id)?;

        let mint_account = account_loader.load_account(&mint)?;
        if *mint_account.owner() != program_id {
            return None;
        }

        let generic_token::Mint { decimals, .. } =
            generic_token::Mint::unpack(mint_account.data(), &program_id)?;

        Some(Self {
            account_index: index.try_into().ok()?,
            mint,
            amount,
            owner,
            program_id,
            decimals,
        })
    }
