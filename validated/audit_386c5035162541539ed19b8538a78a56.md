### Title
Missing role-based authorization on `/debug/vars` allows any authenticated view-role user to read expvar internals - ([File: core/web/router.go])

### Summary
The `debugRoutes` function wires the standard library's `expvar.Handler()` behind `auth.Authenticate(..., auth.AuthenticateBySession)` only, with no `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrapper, unlike virtually every other privileged route in `v2Routes`. Any user who can obtain a valid session — including one created for the lowest-privilege `UserRoleView` — can hit `GET /debug/vars` and receive Go's expvar output (process `cmdline`, full `runtime.MemStats`, and any other vars registered via `expvar.Publish` anywhere in the binary or its dependencies).

### Finding Description
`debugRoutes` in `core/web/router.go` registers the route as: [1](#0-0) 
This only calls `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, which merely verifies the session cookie maps to *some* valid user and sets `SessionUserKey` in the context — it performs no role check: [2](#0-1) 
Compare this to how role-sensitive routes elsewhere in `v2Routes` are wrapped, e.g. `auth.RequiresRunRole(rc.ReplayFromBlock)`, `auth.RequiresAdminRole(uc.Index)`, etc. `RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole` in `core/web/auth/auth.go` (lines 200-255) explicitly check `user.Role` and return 401/403 for insufficient roles — none of these wrappers are applied to `/debug/vars`. As a result any session established for any role (`UserRoleView`, `UserRoleRun`, `UserRoleEdit`, `UserRoleAdmin`) passes the check and reaches `expvar.Handler()`, which returns all process-wide expvar state (goroutine/memory stats via `memstats`, `cmdline`, and any custom vars registered elsewhere in the process) in JSON form.

### Impact Explanation
This is an authorization/least-privilege gap: a `view`-role session (the intended read-only, lowest-trust role in Chainlink's session role model) can read internal runtime/process telemetry that is not exposed by any other `view`-permitted endpoint. This falls into Chainlink's "information disclosure of node internals to a low-privilege authenticated user" impact class — it does not grant a fund-moving or key-disclosure primitive by itself (no key material is published via `expvar.Publish` in this codebase per search), but it violates the stated authorization invariant that a `view` role should not access admin-only debug internals, and could aid further reconnaissance (heap size, GC pressure, process command line/flags).

### Likelihood Explanation
Trivial and fully repeatable: it only requires a valid `view`-role session cookie (the lowest privilege authenticated credential in the system) and a single `GET /debug/vars` request. No additional bypass, timing, or race condition is needed — the route simply lacks any role wrapper.

### Recommendation
Wrap the `/debug/vars` route with `auth.RequiresAdminRole` (or at minimum `auth.RequiresEditRole`), consistent with the treatment of other sensitive introspection endpoints (`/v2/log`, `/v2/config`, pprof-style debug endpoints), e.g.:
```go
group.GET("/vars", auth.RequiresAdminRole(func(c *gin.Context) { expvar.Handler().ServeHTTP(c.Writer, c.Request) }))
```

### Proof of Concept
Go handler-level integration test (pattern following existing `core/web` route tests using `cltest.NewApplication`/`cltest.NewClientAndRenderer` and `cltest.MustNewUser`):
1. Create app/router via `web.NewRouter(app, nil)`.
2. Create a user with `Role: sessions.UserRoleView` and authenticate to obtain a session cookie (`POST /sessions`).
3. Issue `GET /debug/vars` with that session cookie.
4. Assert current (buggy) behavior: `http.StatusOK` and body contains `"memstats"` — demonstrating the invariant violation ("view role should not see admin-only debug internals").
5. After fix, assert `http.StatusForbidden` for `UserRoleView` and `UserRoleRun`, and `http.StatusOK` for `UserRoleAdmin` only.

```go
func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}
```
