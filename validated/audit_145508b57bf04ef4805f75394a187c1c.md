### Title
Miner-refreshable `last_activity_time` lets a single miner indefinitely suppress the inactivity fallback, wedging the signer set on a stalled tenure - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
The signer's inactivity/fallback mechanism (`SortitionState::is_timed_out`) is meant to detect a miner that has gone silent and let the signer set fall back to the prior tenure's miner so the chain can keep moving. The timer it checks (`last_activity_time`) is refreshed not only by genuine progress, but also by `check_latest_block_in_tenure` whenever the *current* miner resubmits a stale/non‑advancing (duplicate or lower‑height) proposal for its own tenure while that tenure holds only a pre‑commit (never a full signature). A single miner that controls the current sortition slot can therefore keep re-sending the same stale proposal to itself forever, perpetually resetting the clock the timeout depends on, and permanently block the signer set's only escape hatch from a stalled tenure.

### Finding Description
`check_latest_block_in_tenure` in `stacks-signer/src/chainstate/mod.rs` treats certain non‑advancing proposals as "miner activity" and stamps `last_activity_time`: [1](#0-0) 

and, for the pre-commit-only case: [2](#0-1) 

`SortitionState::is_timed_out` (both v1 and v2) uses exactly this timestamp, falling back to the burn-block receive time only if it was never set, and only bypasses the check entirely once a block has actually been **signed** (not merely pre-committed) in the tenure: [3](#0-2) [4](#0-3) 

The fallback machinery this guards is documented as the chain's recovery mechanism for a dead/inactive miner: [5](#0-4) 

Putting these together: before any block has been fully **signed** in a tenure (i.e., while the tenure's best block is only `PreCommitted`), the *current* miner — who alone can produce valid proposals for its own tenure — can repeatedly resubmit the same (or another) proposal that does not advance the chain length. Each resubmission satisfies `is_fresh_pre_commit` and re-stamps `last_activity_time`, so `elapsed > block_proposal_timeout` never becomes true and `is_timed_out` never fires. This is a single-miner-controlled input (no other signer's key, no majority, no auth token) that continuously resets the very safeguard meant to detect that miner's own inactivity/stalling, keeping the signer state machine locked onto a miner that never lets a block reach the 70% signature threshold.

This mirrors the reported bug class: a guard meant to bound/limit repeated cheap operations (there: pointer-dereference loop guard; here: inactivity timeout) can be perpetually reset by the attacker cheaply resending the same trivial input, defeating the safeguard's entire purpose without ever completing the operation the safeguard exists to force forward.

### Impact Explanation
This is a liveness wedge: the signer set can be kept from ever falling back to a legitimate alternative miner, because the current miner alone controls whether its own inactivity timer ever elapses. The tenure — and therefore the chain — stalls as long as the miner keeps sending cheap, non-advancing proposals, with no majority of signers, no key compromise, and no auth token required. This matches the "High — a signer wedged into never signing valid blocks" impact category: signers cannot fall back and sign a valid block from the correct (prior) miner while this condition holds.

### Likelihood Explanation
Likelihood is moderate-to-high for a misbehaving or economically motivated miner: it requires only the ability to win a sortition slot and resend one crafted/duplicate `BlockProposal` periodically (well within `reorg_attempts_activity_timeout` and `tenure_last_block_proposal_timeout`), which is ordinary miner-loop behavior already exercised elsewhere in the codebase (miners routinely resend proposals until accumulating enough response weight, per `handle_block_proposal`'s own documented rationale). No cooperation from other signers or the wider network is needed.

### Recommendation
Decouple the inactivity clock from proposals that do not represent forward progress or a genuinely fresh pre-commit event distinct from prior activity: e.g., only refresh `last_activity_time` on the *first* observation of a given pre-committed block (not on every resend of the same/duplicate proposal), or bound the total extension the pre-commit-activity path can grant relative to the original burn-block arrival time, so a miner cannot indefinitely defer the inactivity fallback purely by resubmitting stale proposals.

### Proof of Concept
1. Miner M wins the current sortition and proposes block N (tenure-start).
2. A quorum of signers validate and pre-commit to N (`BlockState::PreCommitted`), but M deliberately prevents the pre-commit weight from reaching the 70% signing threshold (e.g., by not disseminating the proposal to enough signers, or by racing a duplicate proposal so votes split), so N is never actually signed.
3. Shortly before `tenure_last_block_proposal_timeout`/`block_proposal_timeout` would elapse, M resends the same (or a duplicate, non-advancing) `BlockProposal` for its own tenure.
4. `check_latest_block_in_tenure` sees `is_fresh_pre_commit == true` and calls `signer_db.update_last_activity_time(...)`, per [6](#0-5) .
5. Repeat step 3–4 indefinitely (well within the timeout window each time). `SortitionState::is_timed_out` never reports timed out because `elapsed` is measured from the continuously refreshed `last_activity_time`, per [7](#0-6) .
6. `check_miner_inactivity` therefore never falls back to the prior tenure's miner, and the tenure stalls indefinitely with no block ever reaching the signature threshold.

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

            return Ok(false);
        };

                "sorition" => %sortition,
