### Title
Email/password/MFA-state enumeration via distinguishable authentication error messages - (File: core/sessions/localauth/orm.go)

### Summary
`orm.CreateSession` returns distinct, literal error strings ("Invalid email", "Invalid password", a serialized WebAuthn challenge JSON, or "MFA Error") depending on which authentication check fails. `SessionsController.Create` forwards this error verbatim as the HTTP 401 response body via `jsonAPIError`, which calls `err.Error()` and embeds it in the JSON response. This allows an unauthenticated attacker to distinguish "email does not exist" from "email exists, wrong password" from "email exists, MFA required" purely by inspecting the response body.

### Finding Description
The request path is: `POST /sessions` → `SessionsController.Create` (`core/web/sessions_controller.go:29-68`) → `sc.App.AuthenticationProvider().CreateSession(ctx, sr)` at line 56 → `orm.CreateSession` (`core/sessions/localauth/orm.go:144-230`).

Inside `CreateSession`:
- If the email doesn't match a found user via constant-time compare, it returns `pkgerrors.New("Invalid email")` (line 156).
- If the password check fails, it returns `pkgerrors.New("Invalid password")` (line 161).
- If the user has WebAuthn/MFA enabled and no challenge response was submitted, it returns the marshaled WebAuthn challenge JSON as the error text (line 198), which differs in content/length from both prior cases.
- If MFA verification fails, it returns `pkgerrors.New("MFA Error")` (line 210).

Back in `sessions_controller.go:57-60`, this error is passed directly to `jsonAPIError(c, http.StatusUnauthorized, err)`. In `core/web/helpers.go:21-29`, `jsonAPIError` checks if the error is a `*models.JSONAPIErrors` (it isn't, since these are plain `pkgerrors.New` errors), and falls through to `c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))` — embedding the literal error text in the JSON body returned to the client.

The one mitigation present is the ordering comment at line 152-153 ("Do email and password check first to prevent extra database look up for MFA tokens leaking") — this only prevents an extra timing side-channel for MFA status, but does nothing to prevent the primary text-based enumeration between "Invalid email" and "Invalid password" and MFA-challenge-JSON responses. There is no normalization of the outward-facing error message across these three states.

### Impact Explanation
An unauthenticated attacker can query `POST /sessions` with candidate emails and observe whether the response body says "Invalid email" (account doesn't exist) versus "Invalid password" (account exists) versus a WebAuthn challenge JSON (account exists and has MFA enabled). This constitutes account/email enumeration, which is a precursor to targeted credential-stuffing, phishing, or brute-force attacks against known-valid accounts, and further reveals which accounts have MFA enabled (a valuable targeting signal for attackers deciding whether to attempt MFA bypass or session-fixation attacks). This maps to Chainlink's bounty impact class of "information disclosure aiding further attack" (sensitive information disclosure precursor).

### Likelihood Explanation
No preconditions or credentials are required — the endpoint is unauthenticated by design (it's the login endpoint). The attack requires only sending two HTTP requests and diffing the response bodies, and is fully repeatable/scriptable at scale for enumeration campaigns.

### Recommendation
Normalize all authentication-failure responses returned from `CreateSession`/`SessionsController.Create` to a single generic message and status code (e.g., "invalid credentials") for the "user not found", "wrong password", and generic failure cases, while still allowing the MFA-challenge flow to proceed through a distinct, intentional mechanism if that flow is desired to be visible (or better, only reveal the MFA challenge after successful email+password authentication is already implied by design — reconsider whether exposing "account requires MFA" is acceptable pre-auth, since revealing this at all differentiates from non-existent accounts). At minimum, wrap the "Invalid email" and "Invalid password" error paths in `orm.CreateSession` to return the same sentinel error/message before it reaches `jsonAPIError`.

func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}

	// Load all valid MFA tokens associated with user's email
	uwas, err := o.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		// There was an error with the database query
		lggr.Errorf("Could not fetch user's MFA data: %v", err)
		return "", pkgerrors.New("MFA Error")
	}

	// No webauthn tokens registered for the current user, so normal authentication is now complete
	if len(uwas) == 0 {
		lggr.Infof("No MFA for user. Creating Session")
		session := sessions.NewSession()
		_, err = o.ds.ExecContext(ctx, "INSERT INTO sessions (id, email, last_used, created_at) VALUES ($1, $2, now(), now())", session.ID, user.Email)
		o.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": sr.Email})
		return session.ID, err
	}

	// Next check if this session request includes the required WebAuthn challenge data
	// if not, return a 401 error for the frontend to prompt the user to provide this
	// data in the next round trip request (tap key to include webauthn data on the login page)
	if sr.WebAuthnData == "" {
		lggr.Warnf("Attempted login to MFA user. Generating challenge for user.")
		options, webauthnError := sessions.BeginWebAuthnLogin(user, uwas, sr)
		if webauthnError != nil {
			lggr.Errorf("Could not begin WebAuthn verification: %v", webauthnError)
			return "", pkgerrors.New("MFA Error")
		}

		if jsonError != nil {
			lggr.Errorf("Could not serialize WebAuthn challenge: %v", jsonError)
			return "", pkgerrors.New("MFA Error")
		}

		return "", pkgerrors.New(string(j))
	}

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
