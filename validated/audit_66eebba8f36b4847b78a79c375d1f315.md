## Title
Stale confirmations from removed multisig members are not purged, allowing requests to execute below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` in `multisig2/src/lib.rs` only removes pending *requests that were created by* the removed member; it never scrubs that member's *confirmations* recorded on other, still-pending requests. Because `confirm` counts entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set without checking that each entry still corresponds to a current member, a member who confirmed a request and was later removed from the multisig continues to count toward `num_confirmations`. This lets a request execute (e.g. a `Transfer`) with fewer live, currently-authorized confirmations than the configured threshold — the same class of bug as the reported "vote count not reset" issue, here breaking the confirmations-vs-live-members binding instead of a governance vote count.

### Finding Description
`confirm()` computes the threshold purely from the size of the stored `HashSet<String>` of confirmer identifiers: [1](#0-0) 

`delete_member()` removes the departing member from `self.members` and deletes only the *requests* they authored, but does not touch the `confirmations` entries recorded by that member on requests created by *other* members: [2](#0-1) 

There is no re-validation in `confirm()` (or elsewhere) that every string in the stored confirmation set still corresponds to a member in `self.members`. `assert_valid_request()` only checks that the *current* caller is a member, not that previously-recorded confirmers still are: [3](#0-2) 

This breaks the intended equality: `len(confirmations_recorded_on_request) == number_of_currently_authorized_confirmers`. Once a member is removed, their historical confirmation on an unrelated pending request silently continues to satisfy the threshold.

### Impact Explanation
This directly matches the "Critical" bucket: a multisig request (e.g. a fund `Transfer`, `AddKey`, or `DeployContract`) can be executed with a confirmation count that includes a stale, no-longer-authorized member, i.e. executed below the genuine live-member threshold. Any pending, under-threshold request created before a member removal becomes exploitable to push through with fewer real confirmations than `num_confirmations` mandates.

### Likelihood Explanation
Medium-to-High: no special privilege is needed beyond being a current multisig member proposing/confirming ordinary requests; the only "setup" required is for a member removal (a routine multisig operation, e.g. rotating a compromised or departing key) to occur while another request is still pending with that member's earlier confirmation attached. No malicious deployment, foundation action, or victim key is required — this can be triggered purely through the contract's own public `add_request`, `confirm`, and `DeleteMember` action flow.

### Recommendation
When executing `DeleteMember`, iterate over **all** pending requests' confirmation sets (not just those the member authored) and remove the departing member's identifier from each. Alternatively, at confirmation-count time in `confirm()`, filter/recompute the confirmation set to only include entries where `self.members.contains(...)` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request` with a `Transfer` action to an attacker-controlled `receiver_id` → `request_id = 0` (unconfirmed).
3. `B` calls `confirm(0)` → confirmations = `{B}` (1 < 3).
4. `C` calls `confirm(0)` → confirmations = `{B, C}` (2 < 3), request stays pending.
5. Members separately pass a `DeleteMember { member: B }` request (reaching the real threshold of 3 with `A, C, D`), which executes `delete_member` — `B` is removed from `self.members`, but request `0`'s `confirmations` set `{B, C}` is untouched because request `0` was authored by `A`, not `B`.
6. `D` calls `confirm(0)` → `confirmations.len() + 1 == 3 >= num_confirmations`, so `remove_request`/`execute_request` fires and the `Transfer` executes — even though only `C` and `D` are actually current members that approved it; `B`'s stale confirmation supplied the third "vote." [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
