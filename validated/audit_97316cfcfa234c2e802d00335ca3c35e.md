## Title
Unprotected, front-runnable global fee-state initialization allows attacker to seize permanent program-wide fee admin/wallet control - (File: `programs/marginfi/src/instructions/marginfi_group/init_global_fee_state.rs`)

### Summary
The `init_global_fee_state` instruction initializes the program-wide, singleton `FeeState` PDA (seeded only by the constant `FEE_STATE_SEED`, so there is exactly one such account for the whole program) and sets `global_fee_admin` and `global_fee_wallet` directly from caller-supplied arguments, with no check that the caller is a legitimate/authorized deployer. This is the exact bug class described in the zAuction report: an unprotected, callable-by-anyone initializer for a singleton configuration object that can be front-run in the mempool before the intended deployer's transaction lands.

### Finding Description
The instruction handler and its accounts struct contain no authorization check on who may call it: [1](#0-0) 

`InitFeeState` only requires a generic fee-paying `Signer` (`payer`), and the PDA is derived purely from the fixed seed `FEE_STATE_SEED` — there is no relation to an upgrade authority, a hardcoded admin pubkey, or any prior on-chain state: [2](#0-1) 

Inside the handler, `admin_key` and `fee_wallet` are taken verbatim from instruction arguments supplied by the caller and written into the account with load_init(): [3](#0-2) 

The program entrypoint exposes this with the comment "(Runs once per program)" but enforces nothing at the instruction level beyond Anchor's `init` constraint (which merely prevents re-initializing the same PDA — exactly analogous to zAuction's `require(!initialized)` guard, which only prevents *double*-initialization, not *unauthorized first* initialization): [4](#0-3) 

Once set, `global_fee_admin` is the sole authority accepted by `has_one = global_fee_admin` in every subsequent fee-state management instruction, e.g. `edit_global_fee_state`, which can freely redirect `global_fee_wallet`, change `program_fee_rate`/`program_fee_fixed`, and set `pause_delegate_admin`: [5](#0-4) 

Because there is only one `FeeState` PDA per deployed program, whoever wins the race to call `init_global_fee_state` first becomes the permanent `global_fee_admin`/`global_fee_wallet` for the entire protocol (all groups derive `fee_state_cache` from this account on `marginfi_group_initialize`, as seen in the earlier context of `initialize.rs`, lines 21-32). This is directly analogous to the zAuction `init()` front-running bug: a single unprotected, one-time initializer for a global configuration object.

### Impact Explanation
An attacker who observes the program deployment (or fee-state re-initialization on a fresh cluster/testnet/new program ID) can front-run the legitimate deploy script's `init_global_fee_state` call with their own transaction, supplying their own `admin_key` and `fee_wallet`. This grants the attacker permanent control of:
- `global_fee_admin` — the sole signer accepted for all future `edit_global_fee_state` calls (fee rates, fee wallet, pause delegate admin).
- `global_fee_wallet` — the destination for all protocol-level program fees collected across every marginfi group/bank on the program.

This is a durable, program-wide authorization bypass with direct financial effect: all subsequent protocol fee revenue is redirected to an attacker-controlled wallet, and the attacker can arbitrarily inflate/deflate `program_fee_rate`/`program_fee_fixed`, since only they can call the edit function afterward. The legitimate team would need to detect the takeover (transaction reverts on a second init attempt) and redeploy the program under a new address to recover — the same detectable-after-the-fact scenario noted in the original zAuction report.

### Likelihood Explanation
Likelihood is highest at initial mainnet deployment and any time the fee-state account must be (re)created (new program ID from an upgrade requiring redeploy, or a new environment). Solana transactions are visible in the mempool/leader schedule before confirmation, making a front-run of a single, low-compute instruction call (with no special account dependency besides the PDA and a `System` payer) straightforward for any bot monitoring for this instruction discriminator against the marginfi program ID.

### Recommendation
Require the initializer to prove privileged authority instead of trusting caller-supplied arguments, e.g.:
- Constrain the `payer`/caller in `InitFeeState` to equal the program's upgrade authority (via `bpf_loader_upgradeable` program-data account check), or
- Hardcode the expected initial admin pubkey in the program and assert `admin_key == EXPECTED_ADMIN` (or that `payer.key() == EXPECTED_ADMIN`) before allowing initialization, or
- Perform the fee-state initialization as part of the program's deployment/migration tooling using a privileged, one-time multisig-gated instruction rather than an open instruction reachable by any signer.

### Proof of Concept
1. Deploy/upgrade the marginfi program such that the `FeeState` PDA (`seeds = [FEE_STATE_SEED]`) does not yet exist.
2. Attacker monitors the mempool/RPC for the legitimate team's `init_global_fee_state` transaction (or simply races immediately after deployment, since the instruction is public and requires no special permission).
3. Attacker submits their own `init_global_fee_state(admin_key = attacker, fee_wallet = attacker_wallet, ...)` transaction with only a throwaway `payer` signer, landing first.
4. The `FeeState` PDA is now permanently initialized with `global_fee_admin = attacker` and `global_fee_wallet = attacker_wallet`.
5. The legitimate team's subsequent `init_global_fee_state` call fails (`AccountAlreadyInUse`/Anchor `init` error), confirming the takeover; attacker now exclusively passes the `has_one = global_fee_admin` check in `edit_global_fee_state` and can redirect fees / edit program-wide fee parameters going forward.

// Runs once per program to init the global fee state.
use anchor_lang::prelude::*;
use marginfi_type_crate::{
    constants::FEE_STATE_SEED,
    types::{FeeState, WrappedI80F48},
};

#[allow(unused_variables)]
pub fn initialize_fee_state(
    ctx: Context<InitFeeState>,
    admin_key: Pubkey,
    fee_wallet: Pubkey,
    bank_init_flat_sol_fee: u32,
    liquidation_flat_sol_fee: u32,
    order_init_flat_sol_fee: u32,
    program_fee_fixed: WrappedI80F48,
    program_fee_rate: WrappedI80F48,
    liquidation_max_fee: WrappedI80F48,
    order_execution_max_fee: WrappedI80F48,
) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_init()?;
    fee_state.global_fee_admin = admin_key;
    fee_state.global_fee_wallet = fee_wallet;
    fee_state.key = ctx.accounts.fee_state.key();
    fee_state.bank_init_flat_sol_fee = bank_init_flat_sol_fee;
    fee_state.bump_seed = ctx.bumps.fee_state;
    fee_state.program_fee_fixed = program_fee_fixed;
    fee_state.program_fee_rate = program_fee_rate;
    fee_state.liquidation_max_fee = liquidation_max_fee;
    fee_state.liquidation_flat_sol_fee = liquidation_flat_sol_fee;
    fee_state.order_execution_max_fee = order_execution_max_fee;
    fee_state.order_init_flat_sol_fee = order_init_flat_sol_fee;

    Ok(())
}

#[derive(Accounts)]
pub struct InitFeeState<'info> {
    /// Pays the init fee
    #[account(mut)]
    pub payer: Signer<'info>,

    #[account(
        init,
        seeds = [
            FEE_STATE_SEED.as_bytes()
        ],
        bump,
        payer = payer,
        space = 8 + FeeState::LEN,
    )]
    pub fee_state: AccountLoader<'info, FeeState>,

    pub system_program: Program<'info, System>,
}
