### Title
Zip extraction path traversal via unsanitized `zip.File.Name` — no chroot/containment check like `tarzstd` extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` (and its callers `ExtractZipFile` and `ziplegacy.extractor.Extract`) pass the raw `file.Name` from the zip central directory straight into `os.MkdirAll`, `os.OpenFile`, `os.Symlink`, and `os.Mkdir` with no path normalization or containment check. Unlike `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, which explicitly resolves each entry to an absolute path and rejects it if it falls outside `e.dir` (chroot check), the zip path has no equivalent guard.

### Finding Description
`extractZipFile` in `helpers/archives/zip_extract.go` (lines 61–83) does:
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
extractZipFileEntry(file) // os.OpenFile(file.Name, ...)
extractZipSymlinkEntry(file) // os.Symlink(data, file.Name)
```
`file.Name` comes directly from the zip archive's central directory and is attacker-controlled content, e.g. `../../../etc/passwd` or an absolute path like `/etc/passwd`. There is no call to `filepath.Abs`, `filepath.Clean`, or a `strings.HasPrefix` containment check against the intended extraction directory, in contrast to the `tarzstd` extractor which does:
```go
path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))
if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
    return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir)
}
```
`ExtractZipArchive` only checks for a `.git` directory collision (`errorIfGitDirectory`) — an unrelated guard, not a path-containment one. `ExtractZipFile` is invoked for legacy zip-format cache/artifact extraction via `ziplegacy.extractor.Extract`, which is reachable by the `gitlab-runner-helper` cache-extractor/artifacts-extractor path when a job's cache or artifact archive uses the legacy zip format. Since these archives originate from job-controlled or cache-key-collision-controlled data, a crafted entry name lets extraction write files anywhere the runner-helper process has permission to write, confined only by the process's own filesystem permissions/cwd, not by any Runner-enforced boundary.

### Impact Explanation
An unprivileged job that controls a cache/artifact zip archive (custom cache key colliding with another project/job, or supplying its own artifact download that gets re-extracted) can write or overwrite arbitrary files reachable by the runner-helper process outside the intended build/cache directory. On a shared runner host this can corrupt other jobs'/projects' cache or checkout state, or overwrite files in directories writable by the runner user, violating the invariant that "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
This is straightforwardly triggerable: a job can produce its own cache/artifact archive (via `cache: paths` naming a symlink/traversal target, or a `--file` archive path fed to the legacy zip extractor) with a crafted `zip.File.Name`. No special privileges are required beyond normal pipeline authorship, and the missing check is unconditional — every entry is vulnerable, not just an edge case.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: resolve each `file.Name` against the target extraction directory with `filepath.Abs(filepath.Join(dir, file.Name))`, reject entries whose resolved path does not have `dir` as a prefix, and apply the same check before creating symlinks (also validate symlink targets don't point outside `dir`). This requires plumbing the extraction root directory into `ExtractZipArchive`/`extractZipFile` (currently these functions assume the process cwd is the target dir and perform no validation).

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    dir := t.TempDir()
    outside := filepath.Join(t.TempDir(), "outside.txt") // sibling dir, not descendant of dir

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    rel, _ := filepath.Rel(dir, outside)
    w, _ := zw.Create(rel) // e.g. "../xxxx/outside.txt"
    _, _ = w.Write([]byte("pwned"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    prevWD, _ := os.Getwd()
    _ = os.Chdir(dir)
    defer os.Chdir(prevWD)

    err := archives.ExtractZipArchive(zr)
    require.NoError(t, err) // current code does not error

    _, statErr := os.Stat(outside)
    require.NoError(t, statErr, "file was written outside the extraction directory")
}
```
Expected (fixed) behavior: `ExtractZipArchive` should return an error (or skip the entry) and `outside.txt` must not exist, matching `tarzstd`'s chroot-violation behavior.
