### Title
Interest rate config changes are not preceded by `accrue_interest`, causing retroactive misapplication of new rates over the full elapsed period - ([File: programs/marginfi/src/instructions/marginfi_group/configure_bank.rs])

### Summary
`lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only` mutate `bank.config.interest_rate_config` (and other rate-affecting fields) directly, without first calling `bank.accrue_interest()`. Because `accrue_interest` always uses the *current* interest-rate config to compute the entire elapsed `time_delta` since `last_update`, any config change applies retroactively to the whole unaccrued period rather than only to time going forward. This is the same bug class as quill's `stabilityPoolYieldSplit` issue: "must accrue before changing" a value that feeds a period-based accrual calculation.

### Finding Description
`configure()` in [1](#0-0)  updates `self.config.interest_rate_config` in place with no prior interest accrual. The same is true of the dedicated curve-admin path in [2](#0-1) , which updates `bank.config.interest_rate_config` and immediately validates it, again with no accrual step beforehand.

`accrue_interest` computes state changes for the whole elapsed window using whatever `interest_rate_config` is present *at call time*: [3](#0-2) 

The `ir_calc` (built from `self.config.interest_rate_config`) is applied uniformly across `time_delta`, which is `current_timestamp - self.last_update` — i.e., the entire period since the bank was last touched, which could span the moment before *and* after an admin's config change: [4](#0-3) 

Since `lending_pool_accrue_bank_interest` is permissionless and callable by anyone at any time [5](#0-4) , any user interaction (deposit/borrow/withdraw/repay, which all call `bank.accrue_interest` first, e.g. [6](#0-5) ) that lands after an admin config change but before the next accrual will settle the *entire* stale period at the *new* rate, not the rate that was actually in force for most of that period.

This directly parallels the reported issue: interest-rate-affecting state is changed without first "flushing" the pending accrual computed under the old parameters, so the value used to price the pending period retroactively changes.

### Impact Explanation
Depositors and borrowers are unprivileged parties whose share values (and therefore withdrawable/repayable amounts) are computed by the permissionless `accrue_interest` mechanic. If a bank has gone untouched for a period and the admin raises or lowers `interest_rate_config` (rates, fee splits, etc.), the next accrual — which can be triggered by any unprivileged user, or implicitly by any subsequent deposit/borrow/withdraw/repay — will apply the new rate retroactively over the whole stale window. This misprices the borrower's owed interest and the lender's earned interest for a period during which the old rate was actually agreed/active, i.e. an exploitable misvaluation of principal via the accounting path, not merely a display/cache issue. Depending on the direction of the change, this can transfer value between depositors/borrowers/fee recipients that does not correspond to the rate schedule that was actually in effect, and integrations that price share value assuming spot-rate consistency (analogous to the wrapped SP token repricing risk in the referenced report) would be affected.

### Likelihood Explanation
This requires no attacker action beyond ordinary permissionless interaction with a stale bank right after an admin-side rate change — which is a normal operational sequence (config updates happen periodically, and banks are frequently untouched for a while between user interactions). The condition is trivially reachable: any bank whose last update predates a `lending_pool_configure_bank` / `lending_pool_configure_bank_interest_only` call, followed by any of the four common user actions or a bare `lending_pool_accrue_bank_interest` call, exhibits the retroactive mispricing.

### Recommendation
Mirror the quill fix: call `bank.accrue_interest(...)` (and `update_bank_cache`) at the start of `lending_pool_configure_bank`, `lending_pool_configure_bank_interest_only`, and any other admin path that mutates `interest_rate_config` or other rate/fee-affecting fields, *before* applying the new configuration. This ensures `last_update` is bumped and all pending interest is settled under the old rates, so the new configuration only affects periods strictly after the change.

### Proof of Concept
1. Bank B has `last_update = T0`. No user or permissionless accrual has touched it since.
2. At `T1` (e.g., 30 days later), the group admin calls `lending_pool_configure_bank_interest_only` (or `lending_pool_configure_bank`) to raise `interest_rate_config`'s borrowing rate significantly. This directly mutates `bank.config.interest_rate_config` via `configure()`/`update()` with no accrual in between, per [1](#0-0) .
3. At `T2` (shortly after), any unprivileged user calls `lending_pool_accrue_bank_interest` (or performs a deposit/withdraw/borrow/repay, which invokes `accrue_interest` internally).
4. `accrue_interest` computes `time_delta = T2 - T0` (spanning the whole pre- and post-config-change window) and applies the *new* (higher) borrowing rate over that entire span, per [7](#0-6) , instead of applying the old rate for `[T0, T1]` and the new rate for `[T1, T2]`.
5. Borrowers are charged interest at the new rate for the ~30 days that the old rate was actually supposed to apply, incorrectly transferring value to lenders/fee recipients (or vice-versa if the rate was lowered) relative to the intended, time-consistent accrual schedule.

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;

pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

pub fn calc_interest_rate_accrual_state_changes(
    time_delta: u64,
    total_assets_amount: I80F48,
    total_liabilities_amount: I80F48,
    interest_rate_calc: &InterestRateCalc,
    asset_share_value: I80F48,
    liability_share_value: I80F48,
) -> MarginfiResult<InterestRateStateChanges> {
    // If the cache is empty, we need to calculate the interest rates
    let utilization_rate: I80F48 = total_liabilities_amount
        .checked_div(total_assets_amount)
        .ok_or_else(math_error!())?;
    debug!(
        "Utilization rate: {}, time delta {}s",
        utilization_rate, time_delta
    );
    let interest_rates = interest_rate_calc.calc_interest_rate(utilization_rate)?;

    debug!("{:#?}", interest_rates);

    let ComputedInterestRates {
        lending_rate_apr,
        borrowing_rate_apr,
        group_fee_apr,
        insurance_fee_apr,
        protocol_fee_apr,
        ..
    } = interest_rates;

    Ok(InterestRateStateChanges {
        new_asset_share_value: calc_accrued_interest_payment_per_period(
            lending_rate_apr,
            time_delta,
            asset_share_value,
        )
        .ok_or_else(math_error!())?,
        new_liability_share_value: calc_accrued_interest_payment_per_period(
            borrowing_rate_apr,
            time_delta,
            liability_share_value,
        )
        .ok_or_else(math_error!())?,
        insurance_fees_collected: calc_interest_payment_for_period(
            insurance_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        group_fees_collected: calc_interest_payment_for_period(
            group_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        protocol_fees_collected: calc_interest_payment_for_period(
            protocol_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
    })
}

pub fn lending_pool_accrue_bank_interest(
    ctx: Context<LendingPoolAccrueBankInterest>,

    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = &ctx.accounts.group.load()?;

        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
