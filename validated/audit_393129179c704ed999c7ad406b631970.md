### Title
Unbounded Recursion in MPT `OrderedListWalker::fetch_leaves` / `TrieNode::decode` Allows Attacker-Controlled L1 Data to Crash the Fault-Proof Program - ([File: crates/proof/mpt/src/list_walker.rs])

### Summary
The fault-proof program's Merkle Patricia Trie (MPT) walker recursively opens blinded trie nodes fetched from the (attacker-influenced) preimage oracle with no depth bound, analogous to the Fast-DDS `DDSSQLFilter` recursive-parser stack exhaustion (CVE-2026-22591). A maliciously constructed L1 receipts/transactions trie with a long chain of single-child extension/branch nodes causes unbounded native-stack recursion inside `OrderedListWalker::fetch_leaves` and `TrieNode::decode`, which can crash the FPVM process before it produces an output.

### Finding Description
`OrderedListWalker::hydrate` decodes the root trie node and calls `Self::fetch_leaves`, which recurses into every `Branch`/`Extension` child, re-fetching blinded preimages from the oracle and recursing again with no depth limit: [1](#0-0) 

Each preimage node is itself parsed by `TrieNode::decode`, which recursively decodes list elements for `Branch` nodes and recurses for `Extension` payloads, again with no depth bound: [2](#0-1) [3](#0-2) 

The blinded-node preimages that drive this recursion come from `OracleL1ChainProvider::trie_node_by_hash`, which fetches raw bytes from the preimage oracle and feeds them directly into `TrieNode::decode` without any depth or size sanity check, and `receipts_by_hash`/`block_info_and_transactions_by_hash` invoke `OrderedListWalker::try_new_hydrated` on the `receipts_root`/`transactions_root` taken from an L1 header supplied via the oracle: [4](#0-3) [5](#0-4) 

Unlike the CBOR attestation parser elsewhere in the repo, which explicitly caps recursion at `MAX_CBOR_NESTING_DEPTH = 64`, the MPT decode/walk path has no analogous limit: [6](#0-5) [7](#0-6) 

A grep across `crates/proof/mpt/` confirms there is no `MAX_DEPTH`/depth-tracking constant guarding this recursion.

### Impact Explanation
In a dispute-game/fault-proof context, the honest challenger's off-chain fault-proof program derives L1 chain data (headers, receipts, transactions) using this trie walker. Because dispute-game participants provide the underlying preimage data that the program consumes (the "L1 data" whose MPT is walked), a dispute-game participant can craft a pathological receipts/transactions trie — a long chain of degenerate extension/branch nodes each pointing to exactly one blinded child — whose preimages are supplied through the preimage oracle. Walking or decoding this trie drives `fetch_leaves`/`TrieNode::decode` into deep, unbounded native recursion, exhausting the call stack of the fault-proof program process. This crashes/halts the program before it can compute an output root, preventing the honest party from producing a correct claim in the dispute game — a node/process halt in the fault-proof program that can block correct output-root computation, matching the "fault-proof program and MPT" and "wrong provable output root / node halt" categories in scope.

### Likelihood Explanation
Likelihood is high given attacker control: constructing such a degenerate trie only requires standard RLP encoding knowledge and does not require breaking any hash function — an attacker simply builds a long chain of extension nodes (or branch nodes with one live child) whose combined RLP resolves to the legitimate `receipts_root`/`transactions_root`... 

However, note an important caveat: unlike the DDSSQLFilter bug (where the attacker directly controls the filter expression string sent over the wire), here the attacker must produce a trie whose root hash matches the real `receiptsRoot`/`transactionsRoot` of an L1 block, i.e., a preimage collision on keccak256 for an adversarially shaped tree — which is not feasible in practice for existing block roots. The truly attacker-controlled path would need to be a case where the trie root itself is not pinned to a known committed hash, or where the recursion depth is driven by input the attacker fully controls without needing a hash collision (e.g., if a similar unbounded-recursion decode is reachable on attacker-supplied dispute-game bond data or L2 withdrawal proof MPT paths). This significantly weakens the practical exploitability of this specific instance and should be validated against exactly which trie roots (deposit-derived or otherwise) are attacker-forgeable versus committed to a trusted root.

### Recommendation
Add an explicit recursion/depth bound (mirroring `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`) to both `TrieNode::decode` and `OrderedListWalker::fetch_leaves`, rejecting tries deeper than the maximum possible legitimate MPT depth (bounded by key length in nibbles, e.g., 64 for 32-byte keys), and convert the recursive traversal to an explicit iterative worklist/stack with a bounded size to avoid native stack exhaustion regardless of the depth check.

### Proof of Concept
Conceptual PoC (not verified against a live root-hash preimage attack):
1. Construct a chain of `TrieNode::Extension` nodes, each wrapping a single-child `Extension`/`Branch`, nested to a depth of tens of thousands of levels, RLP-encoded and blinded via `keccak256` at each level per `TrieNode::blind`.
2. Populate the preimage oracle (`CommsClient`) with these preimages keyed by their keccak256 hashes.
3. Supply the outermost blinded hash as the `receipts_root` (or `transactions_root`) that `OracleL1ChainProvider::receipts_by_hash` walks via `OrderedListWalker::try_new_hydrated`.
4. Observe that `fetch_leaves` (crates/proof/mpt/src/list_walker.rs:86-127) recurses once per trie level, exhausting the process stack and crashing the fault-proof program before it emits an output.

Note: step 3 requires the attacker to control or forge the committed root hash for this trie, which is the main open question limiting real-world exploitability of this exact code path — a background engineering session with full codebase/tooling access would be needed to confirm whether any in-scope caller passes an attacker-forgeable (non-committed) root into `OrderedListWalker`.

    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }

    fn try_decode_leaf_or_extension_payload(buf: &mut &[u8]) -> TrieNodeResult<Self> {
        // Decode the path and value of the leaf or extension node.
        let path = Bytes::decode(buf).map_err(TrieNodeError::RLPError)?;
        let Some(first_byte) = path.first() else {
            return Err(TrieNodeError::InvalidNodeType);
        };
        let first_nibble = first_byte >> NIBBLE_WIDTH;
        let first = match first_nibble {
            PREFIX_EXTENSION_ODD | PREFIX_LEAF_ODD => Some(first_byte & 0x0F),
            PREFIX_EXTENSION_EVEN | PREFIX_LEAF_EVEN => None,
            _ => return Err(TrieNodeError::InvalidNodeType),
        };

        // Check the high-order nibble of the path to determine the type of node.
        match first_nibble {
            PREFIX_EXTENSION_EVEN | PREFIX_EXTENSION_ODD => {
                // Extension node
                let extension_node_value = Self::decode(buf).map_err(TrieNodeError::RLPError)?;
                Ok(Self::Extension {
                    prefix: unpack_path_to_nibbles(first, path[1..].as_ref()),
                    node: Box::new(extension_node_value),
                })
            }
            PREFIX_LEAF_EVEN | PREFIX_LEAF_ODD => {
                // Leaf node
                let value = Bytes::decode(buf).map_err(TrieNodeError::RLPError)?;
                Ok(Self::Leaf { prefix: unpack_path_to_nibbles(first, path[1..].as_ref()), value })
            }
            _ => Err(TrieNodeError::InvalidNodeType),
        }
    }

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
}
