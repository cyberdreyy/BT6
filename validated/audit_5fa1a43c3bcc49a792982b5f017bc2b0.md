## Finding: Stale confirmations from removed members still count toward execution threshold

### Title
Confirmations from deleted multisig members remain counted toward the execution threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges confirmations for requests that were *created by* the removed member; it does not scrub that member's confirmation entries from other pending requests they had previously confirmed. `confirm()` later counts these stale entries toward `num_confirmations`, so a request can execute with fewer live-member approvals than the configured threshold intends.

### Finding Description
The threshold check compares the size of a request's confirmation set to `num_confirmations`: [1](#0-0) 

`delete_member` only removes requests and confirmations for requests that were **added by** the member being deleted: [2](#0-1) 

```rust
let request_ids: Vec<u32> = self
    .requests
    .iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
```

This filter matches only `r.member == member` — i.e., the *creator* of the request — and does not scan `confirmations` maps of requests created by *other* members that this member may have already confirmed. Consequently, if member `A` confirms request `X` (created by member `B`), and `A` is subsequently removed via a `DeleteMember` request, `A`'s entry remains inside `confirmations[X]`. Membership itself is checked only at confirm-time via `current_member()`, so `A`'s prior signature is never invalidated once recorded.

This is the same class of bug as the Nouns Builder quorum issue: a value (`confirmations.len()`) that is supposed to represent "current members who approved" is computed/accumulated at different points in time and never revalidated against the live member set (`self.members`) before being used to authorize an action.

### Impact Explanation
This breaks the intended binding: `confirmations counted == confirmations from current, live members`. In effect, `X` live confirmations plus stale confirmations from removed members can reach `num_confirmations` even though fewer than `num_confirmations` *current* members actually approved the request. Since `execute_request` can perform `Transfer`, `AddKey`, `DeleteMember`, `FunctionCall`, etc., a request (e.g., a `Transfer` of contract funds) could be executed below the intended K-of-N threshold of currently trusted members — a multisig request executed below threshold, matching the Critical impact category in scope.

### Likelihood Explanation
Requires no privileged actor beyond normal multisig operation: any member combination that (a) creates/confirms a request, (b) later has one confirming member removed via a normal `DeleteMember` request, and (c) still has enough stale + fresh confirmations to reach the threshold on a pre-existing pending request. This is a realistic sequence in ordinary multisig lifecycle management (member rotation) and does not require compromising a key, social engineering, or a malicious deployment.

### Recommendation
When executing `DeleteMember`, iterate over `confirmations` for **all** pending requests (not only ones created by that member) and remove the deleted member's entry from each confirmation set, or alternatively re-validate at `confirm()`/execution time that every entry in a request's confirmation set still corresponds to a current member of `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `B` calls `add_request` to create request `X` (e.g., `Transfer` of funds to an attacker-controlled account).
3. `A` calls `confirm(X)` → confirmations = `{A}`.
4. Separately, members confirm and execute a `DeleteMember { member: A }` request, removing `A` from `self.members`. Note: `delete_member` only cleans up requests where `r.member == A` (i.e., requests A created) — request `X` was created by `B`, so its confirmation set `{A}` survives untouched.
5. `C` calls `confirm(X)` → confirmations = `{A, C}`, len 2 + 1 = 3 ≥ `num_confirmations` (3) → request executes.
6. Only `B` (creator, implicitly not counted unless confirmed) and `C` are live members that acted on `X`; `A`'s stale confirmation from before removal was counted, so the transfer executed with effectively 2 live confirmations against a nominal 3-of-4 threshold. [3](#0-2) [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
