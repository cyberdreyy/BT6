## Finding

### Title
Operator can permanently freeze a staker's principal and rewards by setting an unregistered/opted-out beneficiary that poisons `distribute_internal`'s all-or-nothing payout loop - (File: aptos-move/framework/aptos-framework/sources/staking_contract.move)

### Summary
`staking_contract::distribute_internal` pays out every pending recipient (staker + operator/beneficiary) in a single atomic loop with no per-recipient fault isolation, exactly like the Hubble `processWithdrawals` bug. Unlike `vesting::set_beneficiary`, which explicitly validates that a new beneficiary is registered for APT to avoid this exact class of bug, `staking_contract::set_beneficiary_for_operator` performs no such check. Because every stake-management entrypoint (`unlock_stake`, `request_commission`, `switch_operator`) unconditionally calls `distribute_internal` first, an operator can permanently trap a staker's funds by pointing their beneficiary at an address that will make `aptos_account::deposit_coins` abort.

### Finding Description
`distribute_internal` withdraws all potential withdrawable stake and loops over every shareholder in the `distribution_pool`, redirecting the operator's payout to its beneficiary and depositing coins to each recipient in turn: [1](#0-0) 

The recipient set always includes both the staker (`add_distribution(..., staker_address, amount)`) and the operator/beneficiary (`add_distribution(..., operator, commission_amount)`) once any commission is owed: [2](#0-1) 

`aptos_account::deposit_coins` aborts if the recipient address is not yet registered for the coin type and has opted out of direct coin transfers via `set_allow_direct_coin_transfers(false)`: [3](#0-2) 

`staking_contract::set_beneficiary_for_operator` lets the operator repoint its beneficiary to *any* address with **no registration check**: [4](#0-3) 

This is in stark contrast to `vesting::set_beneficiary`, which the framework authors explicitly hardened against this exact bug class with a comment acknowledging the risk: [5](#0-4) 

Because `distribute_internal` reverts entirely if any single deposit fails, and because `unlock_stake` (line 691), `request_commission` (line 625), and `switch_operator` (line 785) all call `distribute_internal` unconditionally before doing anything else, a poisoned beneficiary blocks every one of these entrypoints: [6](#0-5) 

Critically, `switch_operator` — the staker's only mechanism to escape a malicious operator without a full unstake — itself calls `distribute_internal` on the *old* operator's contract before removing it, so this path is blocked too. There is no admin/staker override in `staking_contract.move` analogous to `vesting::set_beneficiary` to redirect a bad beneficiary; only the operator that created the poison can call `set_beneficiary_for_operator` again, and a malicious operator simply won't.

### Impact Explanation
Once an operator has any positive commission (the normal, intended case for staking contracts) and sets its beneficiary to an address that is unregistered for `AptosCoin` and has `allow_arbitrary_coin_transfers = false` (achievable via a sponsored/fee-payer transaction with zero APT balance), every future call to `distribute`, `unlock_stake`, `request_commission`, and `switch_operator` on that staking contract aborts permanently. The staker's principal and rewards become permanently locked in the underlying stake pool with no recovery path — matching the "Permanent lock or non-recoverable loss of claim rights" and "Operator ... beneficiary payout ... traps value" impact categories.

### Likelihood Explanation
Any operator onboarded by a staker (a normal, expected relationship, not a privileged admin role) can perform this attack unilaterally at any time by calling one entry function (`set_beneficiary_for_operator`) with an address they control that is deliberately kept unregistered and opted out. No collusion, no timing dependency, and no special privileges beyond the operator role that stakers routinely grant are required.

### Recommendation
Mirror the fix already present in `vesting::set_beneficiary`: require `staking_contract::set_beneficiary_for_operator` to validate that `new_beneficiary` is registered for `AptosCoin` (e.g., via `aptos_account::assert_account_is_registered_for_apt`) before accepting the change. Additionally, make `distribute_internal` resilient to individual payout failures (e.g., skip/park a failing recipient's shares instead of reverting the whole distribution), so that one poisoned recipient cannot block payouts to all others, consistent with recommendation #1–3 from the referenced Hubble report.

### Proof of Concept
1. Staker creates a staking contract with `operator` and a positive `commission_percentage`.
2. `operator` calls `staking_contract::set_beneficiary_for_operator(operator, evil_addr)` where `evil_addr` is a freshly derived address that has never registered for `AptosCoin`.
3. Using a fee-payer/sponsored transaction (no APT required at `evil_addr`), the attacker submits `aptos_account::set_allow_direct_coin_transfers(evil_signer, false)` from `evil_addr`, which only requires the `Account` resource to exist, not any coin balance.
4. Stake pool accrues rewards; operator's commission becomes non-zero, so `evil_addr` (as `beneficiary_for_operator(operator)`) is added implicitly as a shareholder resolution target in `distribute_internal`.
5. Staker calls `unlock_stake`, `request_commission`, or `switch_operator` — all first call `distribute_internal`, which tries `aptos_account::deposit_coins(evil_addr, coins)`, hits the `!coin::is_account_registered` branch, calls `can_receive_direct_coin_transfers(evil_addr)` which returns `false`, and the whole transaction aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. The staker cannot withdraw, cannot force commission distribution, and cannot switch away from the malicious operator — funds are permanently stuck.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Allows an operator to change its beneficiary. Any existing unpaid commission rewards will be paid to the new
    /// beneficiary. To ensures payment to the current beneficiary, one should first call `distribute` before switching
    /// the beneficiary. An operator can set one beneficiary for staking contract pools, not a separate one for each pool.
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
