### Title
MetaOracle Staleness Check Uses Relative Oracle Timestamps Instead of Current Block Time, Allowing Arbitrarily Stale Prices to Pass Validation — (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

The `MetaOracle::combine()` function in the Sui oracle framework validates price freshness by comparing each oracle's stored timestamp against a `min_timestamp` derived from the **most recently added oracle's own timestamp** (`max_timestamp - time_window_ms`). It never consults the current block time (`clock::timestamp_ms`). As a result, if all oracle operators stop updating simultaneously, arbitrarily old price data passes the staleness filter and is returned as trusted output to any downstream protocol calling `MetaOracle::median()`.

---

### Finding Description

The `MetaOracle` struct aggregates data from multiple `SimpleOracle` instances and is intended to filter out stale readings via a `time_window_ms` parameter. The flow is:

**Step 1 — `add_simple_oracle` sets `max_timestamp` to the last oracle's stored timestamp:**

```move
// meta_oracle.move lines 38-44
public fun add_simple_oracle<T: copy + drop + store>(meta_oracle: &mut MetaOracle<T>, oracle: &SimpleOracle) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
```

`max_timestamp` is set to the timestamp embedded in the oracle's stored `StoredData`, which was written at the time the oracle operator last called `submit_data`. It is **not** the current block time.

**Step 2 — `combine` computes `min_timestamp` relative to `max_timestamp`, not the clock:**

```move
// meta_oracle.move lines 51-68
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>): (vector<T>, vector<address>) {
    let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
    let min_timestamp = max_timestamp - time_window_ms;   // ← relative to oracle data, not clock
    ...
    if (data::timestamp(&oracle_data) > min_timestamp) {  // ← never checks current time
        vector::push_back(&mut values, *data::value(&oracle_data));
    };
    ...
}
```

The check `data::timestamp(&oracle_data) > min_timestamp` only verifies that each oracle's reading is within `time_window_ms` of the **most recently added oracle's reading**. It does not verify that any reading is within `time_window_ms` of the **current time**.

Compare with `submit_data`, which correctly uses the clock:

```move
// simple_oracle.move line 90
timestamp: clock::timestamp_ms(clock),
```

The clock is available and used at write time, but the staleness guard in `combine` ignores it entirely.

---

### Impact Explanation

Any Move protocol that calls `MetaOracle::median()` to obtain a trusted price (e.g., for collateral valuation, liquidation thresholds, or settlement) will silently receive arbitrarily old data whenever all oracle operators have stopped updating. The `time_window_ms` parameter, which callers expect to bound price age relative to the present, instead only bounds the spread between oracle readings relative to each other. A price that is hours or days old passes the check as long as all oracles are equally stale.

This matches the "harmful smart-contract behavior" impact class in the HackenProof gate: downstream DeFi protocols built on this framework can be made to execute liquidations, mints, or settlements at prices that no longer reflect market reality, causing direct fund loss to users.

---

### Likelihood Explanation

No privileged action is required to trigger the stale-price path. An ordinary user calling any protocol function that internally constructs a `MetaOracle`, calls `add_simple_oracle`, and then calls `median()` will receive stale data whenever oracle operators have not updated recently. Oracle liveness failures (network outages, operator downtime) are realistic and recurring events. The broken check provides no protection in exactly the scenario it is designed for.

---

### Recommendation

Pass the `Clock` object into `combine` (or into `median`) and compare each oracle's timestamp against the current block time:

```move
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, clock: &Clock): (vector<T>, vector<address>) {
    let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp: _ } = meta_oracle;
    let now_ms = clock::timestamp_ms(clock);
    ...
    if (now_ms - data::timestamp(&oracle_data) <= time_window_ms) {
        vector::push_back(&mut values, *data::value(&oracle_data));
    };
    ...
}
```

This mirrors the correct pattern used in `submit_data` and matches the Pyth/Chainlink best practice of checking `block.timestamp - updatedAt <= heartbeat`.

---

### Proof of Concept

1. Oracle operator calls `submit_data` at chain time `T = 1_000_000 ms`, storing price `P` with `timestamp = 1_000_000`.
2. One hour passes. Chain time is now `T_now = 4_600_000 ms`. Oracle operator has not updated.
3. A user calls a protocol that does:
   ```move
   let meta = meta_oracle::new(1, 60_000 /*60 s window*/, ticker);
   meta_oracle::add_simple_oracle(&mut meta, oracle); // max_timestamp = 1_000_000
   let result = meta_oracle::median(meta);            // min_timestamp = 940_000
   // oracle timestamp 1_000_000 > 940_000 → passes
   // result.value = P (1-hour-old price)
   ```
4. `combine` computes `min_timestamp = 1_000_000 - 60_000 = 940_000`. The oracle's timestamp `1_000_000 > 940_000`, so the data is accepted.
5. The protocol receives price `P` — which is 1 hour old — as if it were fresh, with no error or warning.

The current time `4_600_000` is never consulted. The staleness guard is entirely ineffective against oracle liveness failures. [1](#0-0) [2](#0-1) [3](#0-2)

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
