### Title
BridgeType.OutgoingToken (webhook credential) disclosed unredacted in bridge list/show responses to any authenticated view-role user - ([File: core/web/presenters/bridges.go])

### Summary
`BridgeResource.OutgoingToken` is serialized in every JSON API response returned by the bridge controller endpoints (Index/Show/Update/Destroy/Create), including to any session or API-token holder authenticated via the `authv2` group. Unlike `IncomingToken`, which has a `json:"incomingToken,omitempty"` tag and is only ever populated on `Create`, `OutgoingToken` has no `omitempty` tag and is unconditionally populated from the stored plaintext value on every call to `NewBridgeResource`.

### Finding Description
`presenters.BridgeResource` is defined as: [1](#0-0) 

`NewBridgeResource` unconditionally copies `b.OutgoingToken` (plaintext, stored as-is in the `bridge_type` table per `core/bridges/bridge_type.go`) into the resource on every construction: [2](#0-1) 

`BridgeTypesController.Index` and `Show` call `presenters.NewBridgeResource(bridge)` for every bridge returned, with no redaction of `OutgoingToken`: [3](#0-2) 

`BridgeType.OutgoingToken` is a real credential — it is generated at bridge creation time (`utils.NewSecret(24)`) and stored in plaintext in the DB, used by the node to authenticate outgoing webhook requests to the external adapter: [4](#0-3) 

By contrast, `IncomingToken` is correctly protected: the DB only stores `IncomingTokenHash` + `Salt` (never the plaintext token), and the presenter's `IncomingToken` field is `omitempty` and only manually set in `Create` from the ephemeral `BridgeTypeAuthentication` returned at creation time — it is never populated from `NewBridgeResource` for Index/Show/Update/Destroy. So the specific claim about `IncomingToken` leaking in list/show responses is **not substantiated** — only `OutgoingToken` leaks.

Since the bridge routes (`GET /v2/bridge_types`, `GET /v2/bridge_types/:name`) sit in the `authv2` group which enforces authentication but not role-based authorization for read (non-admin-wrapped) routes, any authenticated caller with only `view` role — including a restricted API token — can retrieve every bridge's `outgoingToken` in plaintext via the list/show endpoints.

### Impact Explanation
This matches the Chainlink bounty "sensitive credential disclosure" impact class: a low-privilege (`view`-role) authenticated user can read the plaintext `outgoingToken` for every configured bridge. This token authenticates the node's outbound requests to external adapters; leaking it could allow the low-privilege user to impersonate the node to the external adapter (spoof calls, poison bridge data flowing into job runs) or otherwise abuse the adapter integration outside the node's control — an authorization/credential-disclosure issue impacting confidentiality of bridge secrets and integrity of external-adapter interactions.

### Likelihood Explanation
Trivial and fully reproducible: any authenticated principal with `view` role (a valid session cookie or a `view`-role API token) can call `GET /v2/bridge_types` or `GET /v2/bridge_types/:name` and receive `outgoingToken` in the JSON body for every existing bridge. No special preconditions beyond having any valid low-privilege credential.

### Recommendation
Remove/redact `OutgoingToken` from `presenters.BridgeResource` in read paths (Index/Show), or add `json:"outgoingToken,omitempty"` and only populate it on creation/update responses to the same degree `IncomingToken` is handled — ideally never returning it after initial issuance, and instead supporting a rotate/reveal-once flow. If some legitimate use case needs it echoed back, gate that behind an explicit edit/admin-role check.

### Proof of Concept
Go handler-level integration test (in `core/web/bridge_types_controller_test.go` style):
1. Seed a bridge via `CreateBridgeType` with a known `OutgoingToken` value.
2. Create an authenticated `view`-role session/API token client (using existing `cltest` helpers for view-role client).
3. `GET /v2/bridge_types` and `GET /v2/bridge_types/:name` using the view-role client.
4. Assert response status 200.
5. Parse JSON API response into `presenters.BridgeResource` and assert `OutgoingToken` field is non-empty and equals the known seeded value — demonstrating the leak (expected/fixed behavior: this field should be empty/omitted for a view-role caller).

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")

// the name of the adapter and its URL.
type BridgeType struct {
	Name                   BridgeName
	URL                    models.WebURL
	Confirmations          uint32
	IncomingTokenHash      string
	Salt                   string
	OutgoingToken          string
	MinimumContractPayment *assets.Link
	CreatedAt              time.Time
	UpdatedAt              time.Time
	UseConnectionManager   bool `json:"useConnectionManager"`
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
