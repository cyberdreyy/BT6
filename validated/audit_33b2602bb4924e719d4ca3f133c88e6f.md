### Title
Unsynchronized Concurrent Map Access on `registeredWorkflows` in Web API Trigger Handler Causes Node Crash - (File: `core/capabilities/webapi/trigger/trigger.go`)

### Summary
`triggerConnectorHandler.processTrigger()`, invoked on every inbound gateway message from an unprivileged external sender, iterates over the shared `h.registeredWorkflows` map without holding `h.mu`, while `RegisterTrigger()` and `UnregisterTrigger()` mutate the same map under `h.mu.Lock()`. A concurrent registration/unregistration during trigger processing causes Go's runtime to fatally crash the process with "concurrent map iteration and map write" — an unrecoverable, node-wide denial of service triggered purely by external, unprivileged input timing.

### Finding Description
`processTrigger` is called from `HandleGatewayMessage`, the entry point for messages arriving from the gateway on behalf of arbitrary external senders (identified only by an address extracted from the message body, with no authentication beyond gateway routing): [1](#0-0) 

Inside `processTrigger`, the handler ranges directly over the mutable map `h.registeredWorkflows` with no lock held at all: [2](#0-1) 

Meanwhile, `RegisterTrigger` and `UnregisterTrigger` — called whenever a workflow (re)registers this trigger capability (a routine operation that happens on workflow creation, update, restart, or deletion) — write to the very same map while holding `h.mu`: [3](#0-2) [4](#0-3) 

This mirrors the reported bug class in structure: a state-scanning loop over an unbounded, externally-influenceable/changing collection (here, workflows registered by any workflow owner on the node) that is reachable directly from an unprivileged actor's request (`HandleGatewayMessage`), without the safety accounting (here, lock protection) that the mutating paths rely on. In Go, a concurrent unsynchronized map read (iteration) racing with a map write does not merely produce incorrect results — it triggers `fatal error: concurrent map iteration and map write`, which is a **fatal, unrecoverable runtime crash of the entire process** (not a panic that can be caught by `recover()`).

### Impact Explanation
Any external sender able to route a `web_api_trigger`-method message through the gateway to this node can invoke `processTrigger` at will. If that call races with a legitimate `RegisterTrigger`/`UnregisterTrigger` call (which occurs naturally whenever any workflow on the node using this trigger type starts, restarts, or is removed), the node process crashes fatally. This is a full denial-of-service of the entire Chainlink node (all jobs/workflows on that node), not just the web API trigger feature, and requires no privileged access — only the ability to send a gateway message and the ordinary operational churn of workflow (re)registration.

### Likelihood Explanation
Likelihood is timing-dependent but realistic: nodes running CRE/workflow engines with the web-api-trigger capability will routinely register/unregister triggers (deployments, upgrades, workflow lifecycle events) while simultaneously processing external trigger traffic. An attacker only needs to send trigger messages repeatedly to increase the probability of overlapping with a registration/unregistration event; over time on a busy node this race becomes likely to be hit.

### Recommendation
Acquire `h.mu` (as an `RLock`, converting it to a `sync.RWMutex`) for the duration of the read/iteration in `processTrigger`, matching the locking discipline already used in `RegisterTrigger` and `UnregisterTrigger`. Additionally, take a defensive copy of the map (or the relevant entries) under the lock before releasing it and performing the blocking channel sends (`trigger.ch <- tr`), so the lock is not held across potentially blocking operations.

### Proof of Concept
1. Start a node with `triggerConnectorHandler` (`NewTrigger`) wired to the gateway connector.
2. Continuously register/unregister a webapi trigger from goroutine A via `RegisterTrigger`/`UnregisterTrigger` (simulating normal workflow lifecycle churn).
3. From goroutine B, repeatedly call `HandleGatewayMessage` with a valid `MethodWebAPITrigger` message (simulating an external gateway sender), so `processTrigger` iterates `h.registeredWorkflows` concurrently with goroutine A's map mutations.
4. Run with `go test -race` or under sustained load: the process terminates with `fatal error: concurrent map iteration and map write`, crashing the entire node — demonstrable without any authentication or special privilege beyond sending a gateway message.

func (h *triggerConnectorHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) error {
	msg, err := hc.ValidatedMessageFromReq(req)
	if err != nil {
		h.lggr.Errorw("error validating message from request", "err", err, "request", req)
		return nil
	}
	body := &msg.Body
	sender := ethCommon.HexToAddress(body.Sender)
	var payload webapicap.TriggerRequestPayload
	err = json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw("error decoding payload", "err", err)
		err = h.sendResponse(ctx, gatewayID, body, ghcapabilities.TriggerResponsePayload{Status: "ERROR", ErrorMessage: fmt.Errorf("error %s decoding payload", err.Error()).Error()})
		if err != nil {
			h.lggr.Errorw("error sending response", "err", err)
		}
		return nil
	}

	switch body.Method {
	case ghcapabilities.MethodWebAPITrigger:
		resp := h.processTrigger(ctx, gatewayID, body, sender, payload)
		var response ghcapabilities.TriggerResponsePayload
		if resp == nil {
			response = ghcapabilities.TriggerResponsePayload{Status: "ACCEPTED"}
		} else {
			response = ghcapabilities.TriggerResponsePayload{Status: "ERROR", ErrorMessage: resp.Error()}
			h.lggr.Errorw("Error processing trigger", "gatewayID", gatewayID, "body", body, "response", resp)
		}
		err = h.sendResponse(ctx, gatewayID, body, response)
		if err != nil {
			h.lggr.Errorw("Error sending response", "body", body, "response", response, "err", err)
		}
		return nil

func (h *triggerConnectorHandler) UnregisterTrigger(ctx context.Context, req capabilities.TriggerRegistrationRequest) error {
	h.mu.Lock()
	defer h.mu.Unlock()
	workflow, ok := h.registeredWorkflows[req.TriggerID]
	if !ok {
		return fmt.Errorf("triggerId %s not registered", req.TriggerID)
	}

	close(workflow.ch)
	delete(h.registeredWorkflows, req.TriggerID)
	return nil
}
