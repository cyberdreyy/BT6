### Title
`multiHandler.getHandler` single-handler fallback bypasses the method allowlist, routing arbitrary `Method` values into `confidentialrelay.handler` - ([File: core/services/gateway/multihandler.go])

### Summary
When a DON has only one registered handler type, `multiHandler.getHandler` returns that handler unconditionally without checking `methodToHandler`, so `HandleJSONRPCUserMessage` is invoked for any attacker-supplied `req.Method` string. `confidentialrelay.handler.HandleJSONRPCUserMessage` performs no method allowlist check of its own (it only validates `req.ID`), so the bypass reaches the DON fan-out logic (`fanOutToNodes`) for any method name.

### Finding Description
`multiHandler.getHandler` is the single method-routing gate between an unprivileged gateway client's JSON-RPC request and the concrete handler implementation: [1](#0-0) 

When `len(m.typeToHandler) == 1`, it returns the sole handler for *any* `method` value, completely skipping the `m.methodToHandler` lookup that is the actual allowlist built from each handler's `Methods()`: [2](#0-1) 

This routes into `handler.HandleJSONRPCUserMessage` in `confidentialrelay/handler.go`, which only validates the request ID length/emptiness — it never checks `req.Method` against `h.Methods()` (`MethodSecretsGet`, `MethodCapabilityExec`): [3](#0-2) 

From there, the request is unconditionally registered as an active request and fanned out to every DON member node via `fanOutToNodes`: [4](#0-3) 

So an attacker (already authenticated at the gateway signature layer per the threat model, but with no special role) can send a JSON-RPC request with an arbitrary `Method` string (e.g., `"not-a-real-method"`) to a DON configured with a single handler, and it will be forwarded to relay nodes exactly as if it were a legitimate `secrets_get`/`capability_exec` call, bypassing the intended method allowlist enforced by `methodToHandler`.

### Impact Explanation
This is an allowlist bypass at a defined authorization boundary: the `methodToHandler` map exists specifically to restrict which JSON-RPC methods reach which handler, and the single-handler fast path defeats that restriction entirely. Concretely, it lets an unprivileged sender cause DON-wide fan-out and consume rate-limit/resource budget for arbitrary method names, and any downstream logic that relies on `getHandler` enforcing the method allowlist (e.g., preventing non-relay methods from reaching `confidentialrelay`) is silently bypassed. This matches the "allowlist/quota bypass" impact class.

### Likelihood Explanation
Highly likely to be triggered whenever a DON is configured with exactly one handler type (a common, arguably default, configuration), which is the documented common case per the code comment "for cases where only one handler is registered more generally." No special privileges beyond being a normal signed gateway sender are required, and the request is trivial to construct (any JSON-RPC request with an arbitrary `Method` field).

### Recommendation
Remove the single-handler shortcut in `getHandler`, or restrict it so it still validates `method` against that handler's own `Methods()` list before returning it, e.g.:
```go
if len(m.typeToHandler) == 1 {
    for _, handler := range m.typeToHandler {
        if _, ok := m.methodToHandler[method]; !ok {
            return nil, errors.New("no handler found for method " + method)
        }
        return handler, nil
    }
}
```
Additionally, defense-in-depth: `confidentialrelay.handler.HandleJSONRPCUserMessage` should itself validate `req.Method` against `h.Methods()` before creating an active request and fanning out to nodes.

### Proof of Concept
Go table test in `core/services/gateway/multihandler_test.go` (or extend `gateway_internal_test.go`):
1. Construct a fake `handlers.Handler` (mock) whose `Methods()` returns `[]string{"secrets_get"}`.
2. Call `NewMultiHandler` with a single `config.Handler` entry so `typeToHandler` has exactly one handler.
3. Call `getHandler("not-a-real-method")` and assert it returns the handler (no error) — proving the bypass — instead of the expected `"no handler found for method not-a-real-method"` error.
4. As an integration check, call `multiHandler.HandleJSONRPCUserMessage(ctx, jsonrpc.Request{Method:"not-a-real-method", ID:"1"}, callback)` and assert it reaches the mock handler's `HandleJSONRPCUserMessage` rather than being rejected.
5. Repeat with two registered handler types to confirm the allowlist is correctly enforced in the multi-handler case (`methodToHandler` path), highlighting the single-handler-only regression.

func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	// If there's only one handler, return it directly.
	// This preserves backwards compatibility for cases where the method
	// isn't specified on responses (and for cases where only one handler is registered more generally).
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}

	handler, ok := m.methodToHandler[method]
	if !ok {
		return nil, errors.New("no handler found for method " + method)
	}

	return handler, nil
}

		return err
	}

}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
