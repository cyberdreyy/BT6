## Title
Unbounded recursive `TrieNode::decode` in the fault-proof MPT allows stack-overflow DoS via crafted trie node data - (File: `crates/proof/mpt/src/node.rs`)

## Summary
CVE-2020-12723 is a stack/buffer overflow in Perl's regex engine caused by unbounded recursive descent (`S_study_chunk`) over attacker-controlled input with no depth limit. Base's `base-proof-mpt` crate implements the exact same bug class: `TrieNode::decode` is a self-recursive RLP parser with **no depth counter at all**, unlike the sibling CBOR parser in `base-proof-tee-registrar`, which explicitly bounds recursion via `MAX_CBOR_NESTING_DEPTH`.

## Finding Description
`TrieNode::decode` recurses into itself for every Branch/Extension node it encounters, with no depth argument or limit: [1](#0-0) 

The Extension/Leaf path further recurses through `try_decode_leaf_or_extension_payload`, which calls `Self::decode(buf)` again for an inline (non-blinded) child node, with no bound on how many times this can nest: [2](#0-1) 

Contrast this with the CBOR/COSE attestation parser elsewhere in the proof stack, which is functionally analogous (recursive-descent decoder over untrusted bytes) but was explicitly hardened with a depth guard after presumably recognizing this exact risk class: [3](#0-2) 

`TrieNode::decode` has no equivalent check. The crate's own documentation states the *encoding* convention that nodes longer than 32 bytes get blinded into a separate hash reference, which implicitly bounds nesting depth for genuinely-generated state tries: [4](#0-3) 

However, this is only an encoding-side convention — nothing in `decode()` enforces that an inline (non-blinded) child must be ≤32 bytes or that recursion terminates within a bounded number of levels. Any caller that hands `TrieNode::decode` a byte buffer whose cryptographic binding to a real Ethereum state root is not independently and correctly verified is exposed to attacker-controlled recursion depth.

This routine is the trie backend for the Base fault-proof program (`base-proof-executor`'s `TrieDB`, used by `StatelessL2Builder`/`FaultProofDriver`), reached whenever the executor opens an account or storage slot during stateless block replay in the dispute-game/fault-proof flow: [5](#0-4) 

## Impact Explanation
A crafted, deeply-nested-but-encoding-valid `TrieNode` blob (nested Extension nodes each carrying a tiny inline child) drives `TrieNode::decode` into thousands of recursive stack frames with a comparatively small input buffer, exhausting the native call stack and crashing the process (SIGSEGV / abort) executing the fault-proof program. Because this crate's `TrieDB`/`StatelessL2Builder` sit directly on the fault-proof dispute-resolution critical path, a crash here can halt witness generation or dispute-game execution — a node-halt class impact for a dispute-game participant, consistent with the rules' explicit inclusion of "the fault-proof program and MPT" as an in-scope reachable surface.

## Likelihood Explanation
Exploitability is bounded by whether the caller cryptographically verifies that the fetched bytes are the genuine preimage of the requested trie-node hash before calling `decode`. In the production preimage-oracle path this hash binding is generally enforced upstream (e.g. `check_preimage` in the ZK witness store), which limits an external attacker's ability to substitute arbitrary bytes for a real, committed state root. The root defect, however, is in the shared decoder itself: `TrieNode::decode` provides zero defense-in-depth against deep recursion regardless of caller, unlike the project's own CBOR parser, which was hardened against precisely this pattern. Any future or existing caller (including offline/disk-backed or RPC-sourced trie providers within the proof stack) that does not itself perform strict hash verification before decoding inherits an unbounded-recursion stack-overflow primitive.

## Recommendation
Add an explicit depth parameter/limit to `TrieNode::decode` (and `try_decode_leaf_or_extension_payload`), mirroring the `MAX_CBOR_NESTING_DEPTH` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`, and return a decode error once a small, protocol-justified maximum (e.g., 64, matching the fixed nibble-path length used elsewhere in this module) is exceeded, independent of whether the caller performs hash verification.

## Proof of Concept
Construct an RLP buffer representing a chain of `N` nested Extension nodes, each with a 1-nibble path and an inline (non-blinded, <32-byte) child that is itself another Extension node, terminating in a Leaf. For large `N` (thousands), calling `TrieNode::decode(&mut buf.as_slice())` recurses `N` times through `decode` → `try_decode_leaf_or_extension_payload` → `decode` → ..., exhausting the native stack, analogous to the `stack_overflow` recursion test already present in this codebase's SIGSEGV handler tests: [6](#0-5)

    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
