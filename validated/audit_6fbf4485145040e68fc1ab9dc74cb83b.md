### Title
Global state machine's supermajority check floors the threshold instead of rounding up, allowing "agreement" below the canonical block-approval threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` / `reached_disagreement` compute the 70%/30% supermajority boundary with a plain floor division (`total_weight * THRESHOLD / 10`), while the canonical, protocol-defining threshold used to actually approve a Nakamoto block, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly rounds the same fraction **up**. For total weights that are not exact multiples of 10, these two formulas disagree by exactly one weight unit, letting the signer's gossip-based global state machine "agree" on a view (current miner, burn view, tx-replay set, protocol version) using strictly less weight than what the node/chainstate requires to approve a block.

### Finding Description
`reached_agreement` in `libsigner/src/v0/signer_state.rs:171-175` computes: [1](#0-0) 
```
u64::from(vote_weight) >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
```
This truncates (floors) the fractional threshold.

The canonical, block-approval-defining threshold in `stackslib/src/chainstate/nakamoto/mod.rs:1194-1207` instead explicitly computes a **ceiling**: [2](#0-1) 
```
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```
This asymmetry is the same class of bug as the referenced report: a fractional remainder from an integer division is silently dropped in one code path (`reached_agreement`) while a sibling code path performing the conceptually identical "supermajority of total weight" calculation (`compute_voting_weight_threshold`) correctly accounts for it via a ceiling adjustment.

Concretely, for `total_weight = 11` and `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`:
- `reached_agreement`: `11*7/10 = 77/10 = 7` (floor) → weight `7` (63.6%) is treated as having reached global agreement.
- `compute_voting_weight_threshold`: `77 % 10 != 0` → `ceil = 1` → threshold `8` (72.7%).

So a weight of `7/11` is accepted as "global agreement" by the signer's state machine even though it is below the actual 70%-rounded-up block-approval bar used elsewhere in the protocol. `reached_agreement` gates `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which determines the agreed-upon `current_miner`/`MinerState` and `tx_replay_set`): [3](#0-2) [4](#0-3) 

These `GlobalStateEvaluator` results are consumed by `stacks-signer/src/v0/signer.rs` and `stacks-node/src/nakamoto_node/stackerdb_listener.rs` to decide which miner/tenure/burn-view a signer treats as the accepted global consensus view, i.e. inputs that affect subsequent block-validation and signing decisions.

### Impact Explanation
**High** — a rounding inconsistency between the signer's own "global agreement" threshold and the canonical block-approval threshold means the signer's state machine can lock onto a `current_miner`/burn-view/tx-replay-set "global state" using less than the true required supermajority weight. Signers that sync to this weaker-threshold "global state" are acting on a value that has not actually cleared the real approval bar used by `compute_voting_weight_threshold` — i.e., acting on an incorrectly/leniently computed threshold, which is exactly the "acting on a stale/incorrect threshold" high-impact category. The magnitude is bounded to at most one weight unit's worth of discrepancy per boundary crossing (same low-magnitude nature as the referenced report), but it is deterministic and reachable purely from normal weight distributions plus legitimate gossiped `StateMachineUpdate`s — no majority collusion or key compromise required, only a specific (and fairly common) total-weight/threshold remainder.

### Likelihood Explanation
**High** for triggering the discrepancy itself: any reward set whose `total_weight * 7` is not a multiple of 10 produces this off-by-one floor/ceil mismatch, and this recomputation happens continuously as `GlobalStateEvaluator` re-evaluates state on every gossiped `StateMachineUpdate`. It requires no attacker action beyond ordinary signer participation (or a single miner triggering state updates that shift weight distributions near the boundary), consistent with the "one-slot miner plus gossip" reachability bar.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the same ceiling semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, have `signer_state.rs` call into a single shared threshold function) so that the signer's global-state consensus bar is never lower than the canonical block-approval bar. Add a proptest asserting `GlobalStateEvaluator`'s threshold and `compute_voting_weight_threshold` agree for all `total_weight` values.

### Proof of Concept
1. Build a reward set / `GlobalStateEvaluator` with `total_weight = 11` (e.g., signer weights `[7,2,1,1]`) and `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (confirmed value, `libsigner/src/tests/signer_state.rs:715-718`).
2. Gossip `StateMachineUpdate`s from signers summing to weight `7` (63.6% of 11) all agreeing on the same `current_miner`/burn view.
3. `GlobalStateEvaluator::reached_agreement(7)` returns `true` (`11*7/10 = 7`), so `determine_global_state()` returns this view as the agreed global state, even though `NakamotoBlockHeader::compute_voting_weight_threshold(11)` returns `8`, meaning the equivalent block-approval check would reject the same `7/11` weight as insufficient (as validated by the existing unit test `test_compute_voting_weight_threshold`, `stackslib/src/chainstate/nakamoto/tests/mod.rs:4096-4123`, which encodes the ceiling behavior).
4. This demonstrates the signer's internal "global consensus" bar is measurably lower than the canonical approval bar for the same nominal 70% threshold.

    /// Check if the supplied vote weight crosses the global agreement threshold.

    /// Check if the supplied vote weight crosses the blocking minority threshold.

        u64::from(vote_weight)
