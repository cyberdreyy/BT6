### Title
Unauthenticated `MethodPublicKeyGet` fan-out path lacks request-level rate limiting, allowing unbounded gateway→vault-node load - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` intentionally skips authorization for `vaulttypes.MethodPublicKeyGet` and returns the cached master public key with no credentials required, which is correct since the key is meant to be public. However, when the cache is empty (cold start / not yet warmed by the 1-minute refresh ticker), each unique `req.ID` bypasses the cache and calls `h.fanOutToVaultNodes`, forwarding a JSON-RPC request to every DON member with no per-caller rate limit or quota on the inbound side.

### Finding Description
In `HandleJSONRPCUserMessage` [1](#0-0) , the `MethodPublicKeyGet` branch is reached before any call to `h.requestProcessor.ProcessRequest` (the authorization/allowlist/JWT check used for all other vault methods at line 436). This is an explicit design choice, confirmed by the code comment "Public key requests don't require authorization... Note we cache this value quite aggressively so don't need to worry about DoS."

The only gate against repeated invocation is `newActiveRequest`, which rejects a request only if the exact same `req.ID` is already in-flight [2](#0-1) . Since `req.ID` is attacker-controlled and only bounded by a 200-character length check [3](#0-2) , an attacker can trivially generate unlimited unique IDs. On cache miss, `handlePublicKeyGet` calls `h.fanOutToVaultNodes`, which sends the request to every member of `h.donConfig.Members` via `h.don.SendToNode` [4](#0-3) [5](#0-4) .

The gateway's entrypoint `gateway.ProcessRequest` calls `h.HandleJSONRPCUserMessage` directly with no per-caller/user rate limiter wrapping this call for the vault handler [6](#0-5) , unlike the HTTP-trigger capability handler which explicitly applies `h.userRateLimiter.AllowErr(ctx)` before dispatching work to nodes [7](#0-6) . The vault handler only has `h.nodeRateLimiter`, which throttles *node→gateway* responses in `HandleNodeMessage` [8](#0-7) , not inbound user requests. There is no equivalent inbound gate for `MethodPublicKeyGet`.

### Impact Explanation
This does not disclose any secret — the master public key is intentionally public, so there is no confidentiality violation. The scoped impact is resource exhaustion: repeated cache-miss fan-out (at cold start, right after a handler restart, or during any window where the cache is momentarily empty, e.g. before the first `fetchVaultPublicKey` ticker tick fires) lets an unauthenticated caller trigger unlimited `SendToNode` calls to every vault DON member per unique `req.ID`. This matches a DoS/availability class of impact rather than an authentication/authorization bypass, since the "protection" here is only the informal aggressive caching assumption stated in the code comment, not an enforced rate limiter.

### Likelihood Explanation
Preconditions are minimal: zero credentials, and only a narrow timing window (before cache is warm) is required for the fan-out path to trigger repeatedly; once the cache populates (either from the periodic 1-minute ticker `tickerVaultPublicKeyRefresh` or from a successful `tryCachePublicKeyResponse` after any earlier fan-out), subsequent identical-cache requests are served synchronously without contacting nodes. This limits the exploitation window primarily to gateway restarts or the initial ~1 minute after startup, or any period the cache value is nil (e.g., before the first successful `tryCachePublicKeyResponse`). Within that window, the attack is fully repeatable and trivial (just vary `req.ID`).

### Recommendation
Add an inbound-side rate limiter/gate for `MethodPublicKeyGet` requests (e.g., an IP- or connection-scoped `limits.GateLimiter`, similar to `writeMethodsEnabled`/`signedResponseRequestIDEnabled`) that caps the number of concurrent/cache-miss `fanOutToVaultNodes` invocations per time window, independent of `req.ID` uniqueness. Alternatively, deduplicate concurrent in-flight public-key fetches (single-flight pattern) so that multiple cache-miss requests within the same window collapse into a single fan-out to the DON, rather than one fan-out per unique `req.ID`.

### Proof of Concept
Go unit test plan (extending `core/services/gateway/handlers/vault/handler_test.go`):
1. Construct a `handler` via `newHandlerWithAuthorizer` with a mock `DON` and no pre-populated `cachedPublicKeyGetResponse`/`cachedPublicKeyObject` (simulating cold start).
2. Set up `mockDon.On("SendToNode", ...)` to count invocations without ever returning a completing node response (so the cache never gets populated during the test).
3. In a loop, call `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request{ID: uuid.New().String(), Method: vaulttypes.MethodPublicKeyGet}, callback)` N times (e.g., N=1000) with distinct IDs.
4. Assert that `mockDon.SendToNode` was called `N * len(donConfig.Members)` times — demonstrating unbounded fan-out with no request-level cap.
5. Document (via a failing/aspirational assertion or a `// TODO` style test) that no `GateLimiter`/`RateLimiter` currently exists to cap this, contrasting with `handleSecretsCreate`/`Update`/`Delete` which check `h.writeMethodsEnabled` before fanning out, and with `http_trigger_handler.checkRateLimit` which enforces `userRateLimiter.AllowErr` before dispatch.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
