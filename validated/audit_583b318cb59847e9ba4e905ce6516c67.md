### Title
Stale `fee_state_cache.global_fee_wallet` after `edit_global_fee_state` causes permissionless account-closing/fee flows to revert until `propagate_fee_state` is called - (File: `programs/marginfi/src/instructions/marginfi_group/propagate_fee_state.rs`)

### Summary
The reported Spartan bug is a class of "authority/config value cached in a secondary account is not refreshed when the source of truth is updated, causing dependent authorization/validation checks against the stale cache to fail." Marginfi has a structurally identical pattern: `MarginfiGroup.fee_state_cache.global_fee_wallet` is a cached copy of `FeeState.global_fee_wallet`, and several instructions validate a caller-supplied `global_fee_wallet` account against this cached value rather than the live `FeeState` account.

### Finding Description
`MarginfiGroup` stores a `fee_state_cache: FeeStateCache` that duplicates fields from the singleton `FeeState` PDA, including `global_fee_wallet`: [1](#0-0) 

This cache is populated at group creation and only refreshed via the permissionless `propagate_fee_state` instruction, which copies the live `FeeState` values into the group: [2](#0-1) 

Multiple instructions authorize/validate a passed-in `global_fee_wallet` account against this cached copy instead of the live `FeeState`: [3](#0-2) [4](#0-3) 

The global fee admin can change `FeeState.global_fee_wallet` via `edit_global_fee_state` (confirmed by the existence of that admin-only instruction and the `FeeState` account holding `global_fee_wallet`, per `type-crate/src/types/fee_state.rs` and `programs/marginfi/src/lib.rs`), but this change does not automatically propagate to every `MarginfiGroup`'s `fee_state_cache`. Each group must have `propagate_fee_state` invoked against it individually to pick up the new wallet. Until that happens, any permissionless flow (e.g. `admin_close_account`, `transfer_to_new_account_pda`) that requires the caller to supply the *new* (correct, live) `global_fee_wallet` account will revert with `MarginfiError::InvalidGlobalFeeWallet` / `InvalidFeeAta`, because the on-chain check compares against the group's stale cached wallet, not the current `FeeState`.

### Impact Explanation
This is a functional-availability/inconsistency issue, not a fund-loss/authorization-bypass bug: permissionless maintenance operations (closing eligible dormant accounts, migrating accounts via `transfer_to_new_account_pda`) will revert for any group that hasn't had `propagate_fee_state` re-run after the global fee admin rotates the fee wallet. This can leave rent/fees temporarily undeliverable to the new wallet and blocks the permissionless cleanup/migration paths across every marginfi group until each is individually refreshed — a scaling/operational hazard as the number of groups grows, mirroring the Spartan finding's core defect (a duplicated authority/config value going stale after an update, breaking a dependent, otherwise-correct function).

### Likelihood Explanation
Likelihood is moderate: it requires the global fee admin to change `global_fee_wallet` (a normal, expected operational action) and for at least one group's `propagate_fee_state` to lag behind, which is entirely plausible since propagation is a separate, permissionless-but-manual step (as evidenced by the dedicated CLI `PropagateFee` command). No malicious actor is needed to trigger the DoS — normal operational lag is sufficient.

### Recommendation
Either (a) validate `global_fee_wallet` directly against the live `FeeState` account in `admin_close_account` and `transfer_to_new_account_pda` (passing `FeeState` in as an account) instead of the group's cache, or (b) make `edit_global_fee_state` require/trigger propagation to all affected code paths, or (c) accept either the cached or the live wallet as valid destinations until propagation catches up, so permissionless flows do not revert during the propagation lag window.

### Proof of Concept
1. Global fee admin calls `edit_global_fee_state` to rotate `FeeState.global_fee_wallet` from `W_old` to `W_new`.
2. `MarginfiGroup.fee_state_cache.global_fee_wallet` for group `G` still holds `W_old` because `propagate_fee_state` has not yet been called for `G` (this is a separate, permissionless transaction that must be run per-group, per `programs/marginfi/src/instructions/marginfi_group/propagate_fee_state.rs`).
3. Any caller attempts `admin_close_account` on a dormant, eligible `MarginfiAccount` under group `G`, supplying the correct/current `global_fee_wallet = W_new` (the only account that legitimately represents the protocol's fee wallet going forward).
4. The Anchor constraint `global_fee_wallet.key() == group.load()?.fee_state_cache.global_fee_wallet` fails because the cache still holds `W_old`, and the instruction reverts with `MarginfiError::InvalidGlobalFeeWallet` (`programs/marginfi/src/instructions/marginfi_account/admin_close.rs:65-71`), even though the caller supplied the objectively correct destination account.
5. The same failure mode applies to `transfer_to_new_account_pda`'s `InvalidFeeAta` check (`programs/marginfi/src/instructions/marginfi_account/transfer_account.rs:187-193`).
6. The revert persists until someone calls `propagate_fee_state` for group `G` specifically — direct analog of the Spartan `grantFunds` revert until `setIncentiveAddresses` is called.

```rust
pub fn propagate_fee(ctx: Context<PropagateFee>) -> Result<()> {
    let mut group = ctx.accounts.marginfi_group.load_mut()?;
    let fee_state = ctx.accounts.fee_state.load()?;

    group.fee_state_cache.global_fee_wallet = fee_state.global_fee_wallet;
    group.fee_state_cache.program_fee_fixed = fee_state.program_fee_fixed;
    group.fee_state_cache.program_fee_rate = fee_state.program_fee_rate;

    let clock = Clock::get()?;
    group.fee_state_cache.last_update = clock.unix_timestamp;
```
