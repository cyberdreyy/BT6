### Title
Attacker-controlled `whitelist_account_id` at deterministic-address lockup creation lets any unprivileged caller squat a victim's lockup address with an attacker-approved staking-pool whitelist - (File: `lockup-factory/src/lib.rs`)

### Summary
`LockupFactory::create` is a `#[payable]` method callable by any account, and it lets the caller freely choose both `owner_account_id` (naming a victim as the lockup's owner with no signature or consent from that victim) and an optional `whitelist_account_id` that replaces the canonical `self.whitelist_account_id`. Because the lockup account address is derived purely from `sha256(owner_account_id)`, an attacker can pre-create the deterministic lockup account for any target owner, injecting a hostile whitelist contract that will approve any staking pool as "canonical," before the legitimate creator (e.g. the NEAR Foundation) ever does so.

### Finding Description
The broken binding: the lockup's `staking_pool_whitelist_account_id` field, consulted by `select_staking_pool`/`deposit_and_stake` in the deployed lockup contract, is asserted by the protocol's documented guarantee to equal the canonical whitelist contract (`lockup/README.md`: "The staking pool contract and the account have to be approved by the whitelisting contract to prevent tokens from being lost, locked, or stolen"). In `create`, this value is instead attacker-suppliable: [1](#0-0) 

There is no check binding `env::predecessor_account_id()` to `owner_account_id`, and no check that `whitelist_account_id` (when supplied) matches `self.whitelist_account_id`. The lockup account address is fully deterministic from the owner alone: [2](#0-1) 

Because NEAR account creation (`create_account()`) fails if the account already exists, an attacker can front-run: call `create(owner_account_id = victim, whitelist_account_id = Some(hostile_whitelist), ...)` with only `MIN_ATTACHED_BALANCE` before the rightful creator (e.g. the Foundation, deploying a real vesting lockup for that same `owner_account_id`) submits their transaction. The rightful creator's later `create` call then fails at `create_account()`, and `on_lockup_create` simply refunds their deposit: [3](#0-2) 

The permanently-squatted deterministic address is now a lockup naming the victim as owner but governed by `hostile_whitelist`, which will report any staking pool as approved — exactly the setup the "fast validation" describes: create with a hostile whitelist, then select an arbitrary pool. Existing guards do not catch this: `assert_self()` only protects the callback, `is_promise_success()` only decides refund-vs-log, and there is no `assert_owner`/`assert_called_by_foundation` on `create` itself — it is deliberately permissionless (`#[payable]`, no owner check), and `whitelist_account_id` customization is an intentionally tested feature (`test_create_lockup_with_custom_whitelist_success`) with no restriction tying it to the caller-equals-owner case.

### Impact Explanation
The lockup deployed at the victim's canonical deterministic address has parameters (whitelist, vesting schedule, lockup timestamps) that its rightful creator never chose, matching the Critical category "a lockup deployed with parameters its rightful creator never chose." Any NEAR subsequently sent to or staked from that address by the named owner or a well-meaning party who assumes the address is the victim's legitimate/official lockup would be routed through the hostile whitelist to an attacker-approved staking pool. The rightful creator's own deposit is not permanently lost (it is refunded on account-creation failure), but the intended lockup for that owner can never be created at the expected address, and the substituted contract is one the protocol's canonical whitelist invariant does not govern.

### Likelihood Explanation
The attack requires only the `MIN_ATTACHED_BALANCE` (3.5 NEAR) and knowledge of a target `owner_account_id` that the attacker expects a legitimate lockup will later be created for (e.g. observable from the Foundation's typical employee-onboarding pattern), plus a self-deployed whitelist contract that always approves. No privileged role, key, or victim action is required to execute the squat itself; it is repeatable for any number of target owner account IDs at minimal, one-time cost per target.

### Recommendation
Restrict `whitelist_account_id` customization: either remove the parameter and always use `self.whitelist_account_id`, or require `assert_called_by_foundation`/an explicit allow-list of permitted custom whitelist contracts, and/or require `env::predecessor_account_id() == owner_account_id.as_ref()` when a non-canonical whitelist is supplied so only the account that will actually be bound as owner can opt into a non-canonical whitelist for its own lockup.

### Proof of Concept
```rust
// lockup-factory/src/tests (extend existing test module)
#[test]
fn test_hostile_whitelist_squat_before_legit_creator() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    const LOCKUP_DURATION: u64 = 63036000000000000;
    let lockup_duration: WrappedTimestamp = LOCKUP_DURATION.into();

    // Attacker (not the intended owner, not the Foundation) squats the
    // deterministic address for `account_tokens_owner()` with a hostile whitelist.
    context.predecessor_account_id = String::from("attacker.near");
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(
        account_tokens_owner(),           // victim named as owner, no consent
        lockup_duration,
        None,
        None,
        None,
        Some(custom_whitelist_account_id()), // attacker-controlled "whitelist"
    );

    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    assert!(contract.on_lockup_create(
        lockup_account(),
        ntoy(30).into(),
        String::from("attacker.near"),
    ));

    // Foundation later attempts the legitimate lockup for the same owner at
    // the same deterministic address -> create_account fails (already exists).
    context.predecessor_account_id = foundation_account_id().as_ref().to_string();
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(account_tokens_owner(), lockup_duration, None, None, None, None);

    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Failed); // squatted address
    let result = contract.on_lockup_create(
        lockup_account(),
        ntoy(35).into(),
        foundation_account_id().as_ref().to_string(),
    );
    assert_eq!(result, false); // Foundation's legitimate creation is blocked;
    // `lockup_account()` remains bound to attacker-chosen `custom_whitelist_account_id()`
    // instead of the canonical `whitelist_account_id()`, breaking the invariant that
    // staking_pool_whitelist_account_id at that address equals self.whitelist_account_id.
}
```

    pub fn create(

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =

        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.

            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
