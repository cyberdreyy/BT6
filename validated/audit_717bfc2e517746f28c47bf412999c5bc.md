### Title
Unauthenticated exposure of LOOP plugin pprof profiling/heap-dump and metrics proxy endpoints - ([File: core/web/router.go])

### Summary
`loopRoutes` is registered directly on the `api` base group in `NewRouter` without any `auth.Authenticate(...)` wrapper, unlike every other sensitive route group (`debugRoutes`, `sessionRoutes`, `v2Routes`, and the `metricRoutes` mounted inside `authv2`). This leaves `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` reachable by any unauthenticated client.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the `api` group with only rate limiting and session middleware (no auth) at [1](#0-0) , then calls the route-registration functions in this order: [2](#0-1) .

Every one of the sibling functions that registers sensitive functionality explicitly wraps its group with `auth.Authenticate`:
- `debugRoutes` gates `/debug/vars` behind `auth.Authenticate(..., auth.AuthenticateBySession)`: [3](#0-2) 
- `sessionRoutes` gates `DELETE /sessions`: [4](#0-3) 
- `v2Routes` gates the entire `/v2` authenticated group, and even mounts `metricRoutes` (pprof) inside `authv2` under the comment "Debug routes accessible via authentication": [5](#0-4) [6](#0-5) 

By contrast, `loopRoutes` registers directly on the raw `r` (`api`) group with no auth middleware at all: [7](#0-6) .

The handlers behind these routes are implemented in `core/web/loop_registry.go`:
- `pluginPPROFHandler` proxies arbitrary pprof profile requests (including CPU profile duration via `seconds`, heap dumps, goroutine dumps) to the internal LOOP plugin process and returns the raw bytes to the caller: [8](#0-7) 
- `pluginPPROFPOSTSymbolHandler` similarly proxies to `/debug/pprof/symbol`: [9](#0-8) 
- `pluginMetricHandler` proxies to the plugin's internal `/metrics` endpoint: [10](#0-9) 

Because `loopRoutes` is called with the same `api` group used by other functions but is the only one omitting the `auth.Authenticate` wrapper, any unauthenticated network client to the node can request `GET /plugins/:name/debug/pprof/heap` or `/goroutine?debug=2` and receive a full memory/heap dump of the LOOP plugin process proxied back through the node — without any session cookie, API token, or role check. This directly contradicts the pattern established elsewhere in the same file (e.g. `metricRoutes` is explicitly placed inside the authenticated `authv2` group specifically because pprof/debug data is considered sensitive), indicating this is a wiring gap rather than an intentional design decision.

### Impact Explanation
Heap and goroutine pprof dumps of a running Go process routinely contain in-memory secrets — private keys (OCR/VRF/ETH signing material held in memory by the LOOP plugin), authentication tokens, and internal state. Unauthenticated retrieval of this data by any external network client constitutes a key/secret disclosure vulnerability. The CPU-profile pprof endpoint (`seconds` query param) also lets an unauthenticated attacker force long-running proxied requests against the internal plugin, providing a resource-exhaustion/DoS vector, all without needing any credential.

### Likelihood Explanation
No credentials are required — a raw, unauthenticated HTTP client that can reach the node's web server can hit these routes directly. The only precondition is that at least one LOOP plugin is registered in `app.GetLoopRegistry()` (`p, ok := l.registry.Get(pluginName)`), which is standard for nodes running LOOP-based relayers/plugins. The request is trivially repeatable (simple `GET` requests), requires no special network position, and is exploitable by the lowest-privilege attacker class (unauthenticated API client).

### Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `v2Routes`/`debugRoutes`, or mount it as a sub-group of `authv2` (consistent with how `metricRoutes` is deliberately nested inside `authv2` for the same class of debug/pprof data). At minimum apply `auth.RequiresAdminRole` given the sensitivity of heap/goroutine dumps and metrics proxying.

### Proof of Concept
Go handler-level integration test plan:
1. Build the router via `NewRouter` with a test `chainlink.Application` that has a registered LOOP plugin in its `LoopRegistry`.
2. Issue `httptest` requests without any `Authorization` header or session cookie:
   - `GET /discovery`
   - `GET /plugins/<name>/metrics`
   - `GET /plugins/<name>/debug/pprof/heap`
   - `POST /plugins/<name>/debug/pprof/symbol`
3. Assert response status is `200 OK` (or proxied plugin response) rather than `401 Unauthorized`, proving no auth gate is enforced.
4. Code-review style unit test: inspect the registered `gin.RouterGroup`/`gin.HandlersChain` for these routes (e.g., via `engine.Routes()` and matching `Handler` count) and assert `len(handlers) >= 2` (auth middleware + handler); the assertion fails today because `len(handlers) == 1`, confirming the missing auth wrapper.

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
```
