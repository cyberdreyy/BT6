### Title
ETH sent to `ConvexStrategyETH.receive` is permanently unrecoverable - (File: contracts/strategies/convex/ConvexStrategyETH.sol)

### Summary
`ConvexStrategyETH` exposes an unrestricted `receive() external payable {}` hook, so any EOA or contract can send native ETH to the strategy. The only recovery helper in the base strategy is `transferToken`, which moves ERC20 balances via `IERC20Detailed.safeTransfer` and cannot move ETH. The sole ETH-consuming path unwraps the contract’s current WETH balance and redeposits only that freshly unwrapped amount into Curve, leaving pre-existing ETH untouched. [1](#0-0) [2](#0-1) 

### Finding Description
The ETH-handling flow is asymmetric: `_depositInCurve` calls `IWETH9(WETH).withdraw(_balance)`, which triggers `receive()`, and then passes exactly `{value: _balance}` to `add_liquidity`. Any ETH already held before that WETH unwrap remains in the contract because `_depositArray`/the forwarded value are derived only from `_weth.balanceOf`, not `address(this).balance`. Since `receive` has no sender gate and the contract has no native-asset sweep or refund path, a direct ETH transfer becomes a permanent balance rather than being routed into the vault accounting. [1](#0-0) [3](#0-2) 

### Impact Explanation
An unprivileged direct ETH sender loses 100% of the transferred amount; for example, a 1 ETH transfer leaves `address(strategy).balance == 1 ether` with no callable path that can return it or account for it as strategy NAV. This is a permanent freezing/loss of funds rather than a donation to tranche holders, because neither `price()` nor the Curve deposit logic consumes the stranded balance. [1](#0-0) [4](#0-3) 

### Likelihood Explanation
The issue requires a user/contract to send ETH directly to the strategy, which is an unusual interaction, but it needs no privileged role, no epoch state, no default sequence, and no third-party oracle condition: `receive()` accepts the payment unconditionally. This is lower likelihood than a user-facing deposit bug, but the loss is total once triggered. [5](#0-4) 

### Recommendation
Gate `receive()` to only accept the WETH contract during `WETH.withdraw`, e.g. `require(msg.sender == WETH)`, or remove ETH acceptance entirely and redesign `_depositInCurve` to avoid needing a bare `receive`. If arbitrary ETH must remain receivable, add an owner-only native sweep that cannot spend the transient WETH-unwrap liquidity mid-flow. [1](#0-0) [2](#0-1)

// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ConvexStrategyETH} from "../contracts/strategies/convex/ConvexStrategyETH.sol";

contract ConvexStrategyETHLockedEthTest is Test {
    function test_DirectEthTransferIsStuck() public {
        ConvexStrategyETH strategy = new ConvexStrategyETH();
        address sender = makeAddr("sender");
        vm.deal(sender, 1 ether);

        vm.prank(sender);
        (bool ok,) = address(strategy).call{value: 1 ether}("");
        assertTrue(ok);
        assertEq(address(strategy).balance, 1 ether);
        assertEq(sender.balance, 0);

        // The only rescue hook is ERC20-only; there is no ETH sweep/refund selector.
        (bool sweepExists,) = address(strategy).call(
            abi.encodeWithSignature("sweepETH(address)", sender)
        );
        assertFalse(sweepExists);
        assertEq(address(strategy).balance, 1 ether);
    }
}
