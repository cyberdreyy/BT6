### Title
Permissionless `harvest` lets an attacker set `amountOutMinimum = 0` on reward swaps and sandwich them - (File: contracts/IdleCDO.sol / contracts/strategies/convex/ConvexBaseStrategy.sol)

### Summary
All reward-token swaps in the CDO/strategy stack accept a minimum-amount-out parameter that is supplied by the `harvest` caller via `_extraData` / `_minAmounts`. Since `harvest` is permissionless and nothing enforces a non-zero floor, an unprivileged attacker can call `harvest` themselves with all min-outs set to 0 and sandwich the reward swaps in a single bundled transaction, extracting value that belongs to tranche holders.

### Finding Description
`IdleCDO._sellReward` passes `_minAmount` straight into Uniswap V3 `ExactInputParams.amountOutMinimum` — [1](#0-0) . `_minAmount` is a parameter forwarded from the harvest call data, and the function only early-returns when the sell amount is 0, not when the floor is 0. The same pattern exists in `ConvexBaseStrategy.redeemRewards`, where the caller-decoded values `_minAmountsWETH[i]`, `_minDepositToken`, and `_minLpToken` are passed as `amountOutMin` to `swapExactTokensForTokens` and to `_depositInCurve` — [2](#0-1) . There is no guard like `require(_minAmount > 0)` anywhere in the swap path. Because `harvest` is externally callable (it must be, since keepers/users trigger it) and the min-outs are caller-chosen, an attacker does not even need to win a mempool sandwich — they can atomically: (1) buy up `curveLpToken`/`WETH`/deposit token to move the pools, (2) call `harvest` with zeroed min-outs so the strategy sells all accrued `convexRewards` at the manipulated price, (3) sell back, pocketing the difference. Reward token balances are material (CRV/CVX/etc. accumulated between harvests) and the loss flows directly into a lower strategy `price()`/NAV for tranche holders.

### Impact Explanation
Direct theft of yield: all accrued reward tokens for a harvest cycle are sold at an attacker-controlled price. The extracted value equals roughly the full slippage bandwidth the attacker creates, bounded only by pool liquidity; on deep reward balances this can be a large fraction of one harvest cycle's rewards. The loss is socialized into `totalLpTokensLocked`/`price()` and therefore borne by all tranche holders, breaking the fair-mint/fair-value invariant of the NAV accounting in `_virtualPriceAux`.

### Likelihood Explanation
High when rewards are pending. Requirements are minimal: any EOA can call `harvest` and craft `_extraData`/`_minAmounts` with zeros — the honest keeper flow is irrelevant because the attacker initiates the call themselves inside a bundle (no frontrunning competition needed). The only mitigation is that reward balances may be small between frequent harvests, capping per-attack profit. No existing guard (skim, default check, epoch gating, KYC) applies — `onlyWhitelistedCDO`/`onlyIdleCDO` on `redeemRewards` is satisfied because the call legitimately flows through `harvest`.

### Recommendation
Enforce a non-zero lower bound on min-outs: either require `_minAmount > 0` (reverting when the caller passes 0), or compute the floor internally from an on-chain price (e.g. `getAmountsOut` quoted immediately before the swap multiplied by a configured slippage bps). Alternatively restrict `harvest` (or at least the min-out parameters) to a trusted keeper role so users cannot inject `amountOutMinimum = 0`.

### Proof of Concept
A reproducible Foundry mainnet-fork PoC would:
1. Fork mainnet at a block where a deployed `IdleCDO` using `ConvexBaseStrategy` has claimable CRV/CVX rewards (or donate reward tokens to the strategy to simulate accrual).
2. As an unprivileged EOA, flash-swap the reward→WETH pool to push the price up.
3. Call `IdleCDO.harvest(..., _extraData)` with `abi.encode(new uint256[](rewards.length), new bool[](rewards.length), 0, 0)` so every `swapExactTokensForTokens` runs with `amountOutMin = 0` and `_depositInCurve(0)`.
4. Swap back; assert attacker profit > 0 and `strategy.price()` / CDO `getContractValue()` dropped versus the fair-price harvest baseline (run a control harvest with honest min-outs and diff the NAV).

Caveat: the exact `harvest` signature/permissioning in `IdleCDO.sol` was not fully re-verified line-by-line within this pass; the finding holds provided `harvest` is externally callable and forwards caller-supplied min-outs into `_sellReward`/`redeemRewards`, which the indexed code strongly indicates.
