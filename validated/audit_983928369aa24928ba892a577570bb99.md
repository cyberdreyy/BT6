### Title
Unprivileged vault user can permanently block `stopEpoch` by keeping the programmable borrower's ERC4626 vault illiquid, freezing all LP funds and unreachable default path - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
The CVE-2014-8559 analog is a liveness deadlock: a lock held in the wrong order makes forward progress impossible. Here, `ProgrammableBorrower.onStopEpoch` reverts with `StopEpochVaultLiquidityUnavailable` when the ERC4626 vault has nominal share value but insufficient withdrawable liquidity, and that revert propagates out of `IdleCDOEpochVariant._stopEpoch` before the `try/catch` that would trigger `_handleBorrowerDefault`. Any unprivileged user of the external ERC4626 vault (e.g., a MetaMorpho depositor or a borrower in its underlying markets) can keep the vault illiquid indefinitely, so `stopEpoch` — the only path to end an epoch, recall funds, or declare default — reverts forever. All LP tranche funds are frozen with no escape hatch.

### Finding Description
`IdleCDOEpochVariant._stopEpoch` calls the borrower hook before attempting the `transferFrom` pull:

- `contracts/IdleCDOEpochVariant.sol:395-403` — `onStopEpoch` is invoked outside any try/catch; a revert aborts the entire transaction and no state (including `defaulted`) is written.
- `contracts/strategies/idle/ProgrammableBorrower.sol:239-253` — the hook computes `shortfall = _amountRequired - onHand`. If `shortfall > _currentVaultAssets()` it returns `true` (letting the CDO's pull fail → orderly default). But if `shortfall <= _currentVaultAssets()` — the share price still values the position — it attempts `vault.withdraw(shortfall, ...)` and reverts `StopEpochVaultLiquidityUnavailable` on failure.

The gap: `convertToAssets` counts allocated-but-illiquid assets (MetaMorpho supplies into Morpho markets whose cash can be fully borrowed or withdrawn), while `vault.withdraw` reverts on insufficient market liquidity. So there exists a durable state where shares are "worth" enough to skip the early-`true` return, yet every withdraw reverts.

Sequence for an unprivileged attacker (a user of the programmable borrower's ERC4626 vault — explicitly in scope):

1. Epoch is running; pool funds sit in the vault via `_depositToVault`.
2. Attacker drains the vault's withdrawable liquidity (redeem own shares, or borrow all available cash in the underlying Morpho markets — a standard, permissionless action).
3. Manager calls `stopEpoch`/`stopEpochWithDuration` at `epochEndDate`. `onStopEpoch` sees `shortfall <= _currentVaultAssets()`, calls `vault.withdraw`, reverts → whole `stopEpoch` reverts. `defaulted` is never set, `isEpochRunning` stays true.
4. Every retry reverts identically as long as the attacker maintains illiquidity (cheap for a Morpho borrower who keeps the market at ~0 liquidity, or sustainable by repeatedly withdrawing as liquidity returns).
5. Escape routes are all blocked: `emergencyExitVault` (`ProgrammableBorrower.sol:361-371`) calls `vault.redeem`, which reverts for the same reason; `finalizeDefault`/`postDefaultRequests` are unreachable because `defaulted` is never set; `restoreOperations` can't help mid-epoch (`IdleCDOEpochVariant.sol:626`).

Because the failure happens inside the hook rather than in the CDO's `try this.getFundsFromBorrower` block, the "covered but illiquid" case is a hard revert rather than a default — the code's own comment frames this as "retryable," assuming failures are transient, but nothing enforces transience.

### Impact Explanation
Permanent freezing of the entire pool NAV: AA/BB tranche holders cannot request or claim withdrawals, the epoch can never close, and the default/recovery waterfall (`_handleBorrowerDefault`, `finalizeDefaultRecovery`, `DefaultDistributor`) can never start. The attacker needs no privileges and no capital at risk beyond maintaining vault illiquidity (e.g., interest on a Morpho borrow they can collateralize externally). This is the deadlock analog: an ordering assumption ("illiquidity is transient") lets an external party hold the vault "lock" forever.

### Likelihood Explanation
Requires a programmable-borrower deployment whose sleeve vault's underlying markets can be fully drained — precisely the MetaMorpho/Morpho configuration this contract targets, where market liquidity legitimately reaches zero. The attack is permissionless, repeatable each block (or sustained via a borrow position), and griefs all LPs with no profitability requirement; a competing borrower or extortionist has direct motive. Manager/owner honesty doesn't help — no privileged call bypasses the hook.

### Recommendation
Bound the retry assumption: in `onStopEpoch`, treat a covered-but-failed `vault.withdraw` the same as uncovered — return `true` so IdleCDO's `transferFrom` fails and `_handleBorrowerDefault` runs (the LP loss waterfall then engages via the normal default path). Alternatively, add a `stopEpoch` escape (e.g., after N failed attempts or a deadline lapse, manager may force default without the hook), and/or have `onStopEpoch` use `maxWithdraw`/`maxRedeem` rather than `convertToAssets` for the coverage check so priced-but-illiquid shares route to default immediately.

// SPDX-License-Identifier: MIT
// Foundry fork test: mainnet, MetaMorpho-style vault whose underlying
// Morpho markets can be driven to zero liquidity.
function testStopEpochDeadlockByVaultIlliquidity() external {
    // Setup: programmable borrower pool, epoch running, funds in vault.
    idleCDO.depositAA(10_000 * oneScale);
    _startEpochAndCheckPrices(0);
    vm.prank(revolvingBorrower);
    programmableBorrower.borrow(1_000 * oneScale);

    // Attacker (any EOA / vault user) drains all withdrawable liquidity:
    // redeem own MetaMorpho shares or borrow all cash in underlying Morpho markets.
    // After this: vault.convertToAssets(pbShares) still >> shortfall,
    // but vault.maxWithdraw(pb) < shortfall.
    _drainMorphoMarketLiquidity();

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Every stopEpoch reverts inside onStopEpoch; defaulted never set.
    vm.prank(manager);
    vm.expectRevert(ProgrammableBorrower.StopEpochVaultLiquidityUnavailable.selector);
    cdoEpoch.stopEpoch(0, 1);   // close-pool sentinel also fails

    vm.prank(manager);
    vm.expectRevert(ProgrammableBorrower.StopEpochVaultLiquidityUnavailable.selector);
    cdoEpoch.stopEpoch(0, 0);

    // No escape: emergency exit hits the same illiquidity.
    vm.prank(owner);
    vm.expectRevert();
    programmableBorrower.emergencyExitVault(0);

    // State frozen: epoch running, not defaulted, recovery unreachable.
    assertTrue(cdoEpoch.isEpochRunning());
    assertFalse(cdoEpoch.defaulted());
    // Attacker re-tries ad infinitum by keeping liquidity drained;
    // LP principal + interest permanently locked.
}
