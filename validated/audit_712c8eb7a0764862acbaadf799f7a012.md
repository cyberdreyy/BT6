### Title
Client-controlled `MessageId` overwrites in-flight callback map without ownership check enabling cross-user response hijacking - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The reported defiProtocol bug is a Checks-Effects-Interactions (CEI) violation: `settleAuction()` performed an externally-triggerable side effect (`withdrawBounty()`/token transfer) before finalizing internal state (`auctionOngoing = false`), letting an attacker re-enter and mutate shared state (`pendingWeights`) mid-flight, resulting in state/response confusion that benefits the attacker. The closest analog in this codebase's internet-facing gateway path is in `handler.HandleLegacyUserMessage` [1](#0-0) , where an unprivileged, gateway-facing user request writes into a shared `savedCallbacks` map keyed by an attacker-supplied `msg.Body.MessageId`, with no check for whether that key is already in use by another in-flight (victim) request.

### Finding Description
`HandleLegacyUserMessage` is the entry point for user-submitted trigger requests forwarded through the Gateway to DON nodes. After basic payload/timestamp/method validation, it unconditionally stores the callback for the current request under the message's own `MessageId`: [2](#0-1) 

There is no check that `h.savedCallbacks[msg.Body.MessageId]` is empty before overwriting it. Later, when a node responds via `HandleNodeMessage` → `handleWebAPITriggerMessage`, the response is matched purely by `MessageId` and delivered to whichever callback is currently stored under that key, then the entry is deleted: [3](#0-2) 

This is structurally the same class of defect as the reported issue: a state map (`pendingWeights` / `savedCallbacks`) is mutated based on an operation whose completion/effects are not exclusively controlled by the party who initiated it, and the "checks" (verifying the key is free / verifying `auctionOngoing`) are missing or performed too late relative to the "effects" (writing new state / sending the transfer). Here, if `MessageId` is attacker-influenced or predictable/collidable, a malicious unprivileged client can send a second `HandleLegacyUserMessage` request using the same `MessageId` as a victim's pending request while it is still in flight (i.e., before the victim's DON response arrives and the entry is deleted). The `savedCallbacks` entry — and therefore the `handlers.Callback` (HTTP connection/response channel) that will ultimately receive the DON's response — is silently overwritten with the attacker's own callback.

### Impact Explanation
If exploitable, this results in cross-user response confusion: the attacker's HTTP connection would receive the response body intended for the victim's webhook/trigger request (or vice versa), potentially disclosing data returned by the DON pipeline run that was meant for another caller. This falls under the explicitly accepted impact category "cross-user response confusion" per the validation rules. It is reachable from an unprivileged client via the internet-facing Gateway handler path, matching the CEI/state-overwrite root cause of the reported finding.

### Likelihood Explanation
Exploitability is contingent on two open questions I could not fully resolve within the available index:
1. Whether `MessageId` is attacker-controlled/predictable at the point it reaches this handler (i.e., whether the Gateway's ingress path assigns a fresh, unpredictable ID per request or trusts a client/DON-supplied value), and
2. The exact concurrency window (whether callback pruning/aging via `pruneCallbacks` and per-request expected round-trip time make collision practically feasible).

Given the size-limited index available to Ask, I was not able to definitively trace the full HTTP-ingress-to-`HandleLegacyUserMessage` call chain and confirm the origin/uniqueness guarantees of `MessageId`. This should be verified in a full checkout (a Devin session) before treating this as confirmed-exploitable; it is reported here as the strongest structurally-matching, in-scope analog found.

### Recommendation
- Before writing to `h.savedCallbacks[msg.Body.MessageId]`, check (under the existing mutex) whether an entry already exists for that key; if so, reject the new request (or generate/require a server-assigned unique ID rather than trusting client input) instead of silently overwriting the prior callback.
- Ensure `MessageId` values used to key `savedCallbacks` are generated or validated server-side to be unique per in-flight request, not solely derived from client-controlled message content.
- Consider binding the callback to additional request-origin metadata (e.g., a check that the responding/overwriting caller is authorized) analogous to applying Checks-Effects-Interactions: validate exclusivity of the resource ("checks") before mutating shared state ("effects").

### Proof of Concept
Conceptual (not confirmed against a running instance, since the exact HTTP ingress code for constructing `msg.Body.MessageId` from a client request was not reachable in the indexed subset):
1. Victim submits a legitimate request that reaches `HandleLegacyUserMessage`, which stores `savedCallbacks[victimMessageId] = victimCallback` and forwards it to DON members.
2. Before the DON responds, attacker submits a second request causing `HandleLegacyUserMessage` to run with the same `MessageId` value (`victimMessageId`), overwriting the map entry: `savedCallbacks[victimMessageId] = attackerCallback`.
3. When a DON node later responds with `MethodWebAPITrigger` and that `MessageId`, `handleWebAPITriggerMessage` looks up `savedCallbacks[msg.Body.MessageId]`, finds `attackerCallback`, and delivers the victim's response data to the attacker's connection. [4](#0-3) [5](#0-4)

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
