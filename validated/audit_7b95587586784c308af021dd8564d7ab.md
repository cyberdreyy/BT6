### Title
Symlinked directory entries in zip archives allow write-through-symlink path escape during extraction - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` and its helper `extractZipFile` create files and directories using the raw, attacker-controlled `file.Name` from the zip archive with no validation that the resolved path stays within the extraction root, and `extractZipSymlinkEntry` creates symlinks pointing to arbitrary attacker-supplied targets with no restriction. A crafted archive containing a symlink entry followed by a nested-path entry can cause `os.MkdirAll(filepath.Dir(file.Name), ...)` and the subsequent file write to traverse through that symlink to a location outside the intended extraction directory.

### Finding Description
`extractZipFile` (helpers/archives/zip_extract.go:61-83) computes `filepath.Dir(file.Name)` and calls `os.MkdirAll` on it directly, then dispatches based on `file.Mode()`:
- For `os.ModeSymlink` entries, `extractZipSymlinkEntry` (lines 22-39) reads the link target from the entry's file content and calls `os.Symlink(string(data), file.Name)` with **no validation** that the target is inside the extraction root — the target can be an arbitrary absolute path.
- For regular file entries, `extractZipFileEntry` (lines 41-59) opens `file.Name` for writing via `os.OpenFile`.

There is no zip-slip / path-confinement check anywhere in `ExtractZipArchive` (lines 85-110) — contrast this with `commands/helpers/archive/tarzstd/tarzstd_extractor.go` (lines 57-64), which explicitly computes an absolute path and rejects it if it doesn't have the destination-directory prefix. No equivalent check exists in `zip_extract.go`.

Because `archive.File` entries are processed in file order (a single pass in the first loop at lines 88-96), an attacker can:
1. Include an entry named `linked-dir` with `os.ModeSymlink`, whose content is an absolute path to a directory outside the extraction root (e.g., another job/project's shared cache path).
2. Include a subsequent entry named `linked-dir/evil` (a regular file).

When entry 2 is processed, `extractZipFile` calls `os.MkdirAll(filepath.Dir("linked-dir/evil"), 0o777)` → `os.MkdirAll("linked-dir", ...)`. Since `linked-dir` already exists as a symlink to the external target, `MkdirAll` treats it as satisfying the directory requirement (Go's `os.MkdirAll` treats an existing symlink-to-directory as success) and does not error. `extractZipFileEntry` then opens `linked-dir/evil` for writing, which the OS resolves through the symlink, writing the attacker's file content into the external directory outside the extraction root.

`errorIfGitDirectory` / `path_check_helper.go` only guards against `.git` directory entries, not general path escape or symlink target validation, so it does not stop this.

### Impact Explanation
On a host where multiple jobs/projects share a filesystem for cache extraction (a documented shared-runner/shared-cache-mount scenario, not admin misconfiguration but a normal multi-tenant deployment topology), an unprivileged pipeline author who controls the contents of a cache or artifact zip can write arbitrary file content into another tenant's directory reachable via that symlink target. This violates the "file operations must stay within intended build/cache/artifact roots" invariant and constitutes a cross-project write, e.g., planting malicious files (build scripts, `.git/hooks`, etc.) into a neighboring project's cache path.

### Likelihood Explanation
Feasibility is high and fully attacker-controlled: cache/artifact archives are typically populated from job-defined paths and can, in some flows, be attacker-shaped (e.g., custom cache paths, or an artifact the job itself creates before packaging, if the runner's own archiver doesn't restrict symlink targets — note: `CreateZipArchive`/`file_archiver.go` path validation is a separate concern from extraction; this finding is about the extractor accepting any pre-built zip, including one crafted outside the normal archiver, e.g., downloaded from a remote cache and fed to `ExtractZipFile`). The extraction logic itself performs no target or path validation, so exploitation only requires control over the zip's entry list/content, which is standard for a cache/artifact zip consumed by `ExtractZipArchive`. Precondition of a shared filesystem across tenants' cache paths is required for the cross-tenant impact, but the underlying path-confinement bug is unconditional.

### Recommendation
In `extractZipFile`/`extractZipSymlinkEntry` (helpers/archives/zip_extract.go):
- Before creating any parent directories or writing entries, resolve `file.Name` to an absolute path against the extraction root and reject entries whose resolved path escapes the root (mirroring the check in `commands/helpers/archive/tarzstd/tarzstd_extractor.go:58-64`).
- For symlink entries, validate that the resolved symlink target (if relative, joined with the entry's directory) does not escape the extraction root, and reject/skip absolute-path symlink targets pointing outside the root.
- When creating parent directories via `os.MkdirAll`, use `os.Lstat` on each existing path segment to detect pre-existing symlinks and refuse to traverse through them if they point outside the root.

### Proof of Concept
```go
func TestExtractZipArchive_SymlinkDirEscape(t *testing.T) {
    outsideDir := t.TempDir() // simulates another tenant's cache dir
    extractionRoot := t.TempDir()

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)

    // 1. symlink entry "linked-dir" -> outsideDir (absolute path)
    hdr := &zip.FileHeader{Name: "linked-dir"}
    hdr.SetMode(os.ModeSymlink)
    w, _ := zw.CreateHeader(hdr)
    w.Write([]byte(outsideDir))

    // 2. nested file entry through the symlinked dir
    fw, _ := zw.Create("linked-dir/evil")
    fw.Write([]byte("attacker-controlled content"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    os.Chdir(extractionRoot)
    defer os.Chdir(wd)

    err := ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the file did NOT land in outsideDir (i.e., extraction stayed confined)
    _, err = os.Stat(filepath.Join(outsideDir, "evil"))
    assert.True(t, os.IsNotExist(err), "file must not be written outside extraction root via symlink")
}
```

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

	}

}
