### Title
Legacy zip extractor ignores the assigned extraction root and applies zero path confinement, allowing absolute/drive/traversal paths to escape - (File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go)

### Summary
`ziplegacy.extractor.Extract` receives a `dir` (the intended extraction root) but never uses it: it calls `archives.ExtractZipArchive(zr)` with no root argument at all [1](#0-0) . Downstream, `ExtractZipArchive` writes every entry using the raw `file.Name` straight into filesystem calls (`os.Mkdir`, `os.OpenFile`, `os.Symlink`) with no `filepath.Join` against any root and no absolute-path/`..`/drive-letter rejection [2](#0-1) .

### Finding Description
The `archive.Extractor` interface and `NewExtractor` contract state "the extractor will extract files to the directory provided" [3](#0-2) , and the `dir` field is stored on the `ziplegacy` extractor struct [4](#0-3) . However `Extract` never reads `e.dir` — it just builds a `zip.Reader` and hands it to `archives.ExtractZipArchive(zr)`, which has no knowledge of any target directory [5](#0-4) .

`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)`, which does `os.MkdirAll(filepath.Dir(file.Name), ...)` and then, depending on entry type, `os.Mkdir(file.Name, ...)`, `os.Symlink(data, file.Name)`, or `os.OpenFile(file.Name, ...)` — always using `file.Name` verbatim, with no `filepath.Join(dir, file.Name)`, no `filepath.Clean`, no prefix check against a root [2](#0-1) . The only defensive check present, `errorIfGitDirectory`, only rejects entries whose first path segment is `.git`; it does nothing against absolute paths, drive-qualified paths (e.g. `C:\...` on Windows), UNC paths (`\\server\share\...`), or `../` traversal segments [6](#0-5) .

By contrast, the sibling `tarzstd` extractor demonstrates the correct pattern: it computes `path := filepath.Abs(filepath.Join(e.dir, hdr.Name))` and explicitly rejects any path that doesn't have `e.dir` as prefix ("cannot be extracted outside of chroot") [7](#0-6) . The legacy zip path has no equivalent of this check at all — it is strictly worse than "insufficient path cleaning": it performs no root confinement whatsoever, and the destination is effectively the process's current working directory (or wherever the raw entry name resolves to), not the caller-supplied `dir`. This is confirmed by the existing unit test, which extracts an archive via `ExtractZipFile` and then checks for the output file relative to the process CWD (`os.Stat("temporary_file.txt")`), not relative to any extraction directory [8](#0-7) .

Exploit flow: an attacker (pipeline author) crafts a job artifact/cache zip archive whose zip entry `Name` field is an absolute path (e.g. `/home/gitlab-runner/.ssh/authorized_keys` or, on Windows, `C:\Users\...\...` or `\\?\C:\...`) or a `../../` relative traversal. When Runner's cache/artifact extraction routes this into the legacy zip codepath (`archive.Zip` via `ziplegacy.NewExtractor`), the write lands at the attacker-chosen absolute location instead of being confined to the assigned build/cache directory, because neither `Extract` nor `ExtractZipArchive` ever validates or joins against the intended root.

### Impact Explanation
A job under attacker control (through a poisoned cache or artifact archive consumed by a later job/stage, or a runner processing its own job's cache/artifact restore) can write or overwrite arbitrary files outside the intended build/cache root on the executor host or container filesystem — e.g., overwriting files in another job's workspace, tampering with shared runner state, or planting files at attacker-chosen absolute paths reachable by the runner process. This matches the scoped impact of cross-job state tampering / stronger-context file overwrite.

### Likelihood Explanation
This is highly feasible and repeatable: any pipeline author can produce a custom zip file (bypassing GitLab's own archive creation) and have Runner treat it as a job artifact or cache to be restored, since Runner extracts cache/artifact archives without additional validation of member names beyond the trivial `.git` check. No privileged access, admin misconfiguration, or race condition is required — a single crafted zip is sufficient, and the legacy zip extractor path is a registered, reachable code path (`archive.Zip` format) invoked identically to other supported archive formats.

### Recommendation
Fix `archives.ExtractZipArchive` (and its caller `ziplegacy.extractor.Extract`) to take and honor the extraction root: join every `file.Name` against `dir` via `filepath.Join`, resolve to an absolute path, and reject/skip any entry whose resolved path does not have the root as a strict prefix (mirroring the check already implemented in `tarzstd_extractor.go`). Apply the same confinement to symlink targets (`file.Name` and the destination of `os.Symlink`) to also block symlink-based escapes.

### Proof of Concept
Go unit test to add near `helpers/archives/zip_extract_test.go` / `commands/helpers/archiver_test.go`:
```go
func TestZipLegacyExtract_AbsolutePathEscape(t *testing.T) {
    // Build a zip archive with an absolute-path entry name.
    outsideDir := t.TempDir()
    maliciousPath := filepath.Join(outsideDir, "pwned.txt")

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, err := zw.Create(maliciousPath) // absolute path as entry name
    require.NoError(t, err)
    _, err = w.Write([]byte("attacker content"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    // Assigned extraction root - attacker should be confined here.
    assignedRoot := t.TempDir()

    extractor, err := archive.NewExtractor(archive.Zip, bytes.NewReader(buf.Bytes()), int64(buf.Len()), assignedRoot)
    require.NoError(t, err)
    err = extractor.Extract(context.Background())

    // Expected (fixed) behavior: error, or file confined under assignedRoot.
    _, statErr := os.Stat(maliciousPath)
    assert.True(t, os.IsNotExist(statErr),
        "absolute-path entry must not be written outside the assigned root; got err=%v", err)
}
```
Expected result on the current code: the test fails because `pwned.txt` is created at `maliciousPath` (outside `assignedRoot`), confirming the root-escape. After applying the recommended fix (joining against `dir` and rejecting out-of-root paths), the assertion passes.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
