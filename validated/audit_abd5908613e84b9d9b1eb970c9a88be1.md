### Title
Path traversal via zip UID/GID extra field enables `os.Lchown` outside job workspace - (`File: helpers/archives/zip_extra_unix.go`)

### Summary
`ExtractZipArchive` extracts every entry using the raw `file.Name` from the zip's central directory without any path-traversal sanitization, and `processZipUIDGidField` subsequently calls `os.Lchown(file.Name, ...)` on that same unsanitized name. A malicious job can supply an artifact/cache zip containing an entry whose `Name` is `../../../etc/cron.d/x` (or similar) with a `0x7875` extra field, causing both file writes and an `Lchown` call outside the intended extraction directory.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)`, which does `os.MkdirAll(filepath.Dir(file.Name), ...)` and then creates/writes the file at `file.Name` directly [1](#0-0) . The only validation performed anywhere in this path is `errorIfGitDirectory`, which only checks whether the first path segment is `.git`, and is purely advisory (it logs a warning via `tracker.actionable`, but does not block extraction or abort the entry) [2](#0-1) . There is no `filepath.Clean`/`filepath.Rel`-based check to ensure the resolved path stays within a target root, and no check for `..` segments or absolute paths.

In the second pass, `processZipExtra` is called on every file, dispatching to `processZipUIDGidField` for `0x7875` extra fields, which parses the UID/GID and calls `os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))` — again using the raw, unsanitized `file.Name` [3](#0-2) [4](#0-3) . Since `ExtractZipArchive` provides `fileName` values directly from the archive's `FileHeader.Name` with no sandboxing, an attacker-controlled zip (uploaded as a job artifact or cache and later extracted by the runner or by another job pulling that artifact/cache) can specify `Name = "../../../etc/cron.d/x"`. Because `extractZipFile` runs first for that entry (creating/overwriting the file content at the traversal path via `os.MkdirAll` + `os.OpenFile`), and then `processZipUIDGidField` runs `os.Lchown` on the very same traversal path, both the file content and its ownership outside the workspace are attacker-controlled.

`ExtractZipFile`/`ExtractZipArchive` are the general zip-extraction primitives; whether this is reachable depends on which extraction commands the runner exposes, and this snapshot of the repo did not surface a caller with additional path validation prior to invoking `ExtractZipArchive` (the artifact/cache extractor commands under `commands/helpers/` reference this indirectly). This part of the call chain (specifically confirming there is no additional sandboxing wrapper at the artifact-extractor command layer) could not be fully verified given tool budget — but nothing within `helpers/archives` itself performs path containment.

### Impact Explanation
If reachable without additional path validation upstream, this allows a job to write files and change file ownership (via `Lchown`) outside the intended extraction directory, potentially corrupting or planting files on the host/runner filesystem (e.g., cron directories, other users' home directories) and modifying ownership of arbitrary files reachable by the runner process's privileges. This matches "host file ownership modification and job-workspace escape."

### Likelihood Explanation
Any pipeline author can control artifact/cache filenames since these are packaged from job-produced files, and with tooling (or a custom zip writer) a job could produce a `.zip` with a crafted `FileHeader.Name` containing `../` sequences and a synthetic `0x7875` extra field. Feasibility is high for anyone who can craft a raw zip byte stream (not merely `zip -r` on a normal file layout, which would not normally emit such names, but a custom build using `archive/zip` directly can). Whether this is truly exploitable end-to-end depends on unverified upstream behavior (e.g., whether GitLab Runner's artifact/cache extraction commands add a sandbox/chroot or `filepath.Clean`+containment check before calling `ExtractZipArchive`); this could not be confirmed with the available tool calls.

### Recommendation
Add a path-containment check for every `file.Name` before any file-system operation in `extractZipFile` and before `processZipUIDGidField`/`processZipTimestampField` run: resolve the target path with `filepath.Join(destRoot, file.Name)`, clean it, and reject/skip entries whose resolved path is not still prefixed by `destRoot` (i.e., detect and reject `..` traversal and absolute paths), consistent with how `errorIfGitDirectory` today only warns instead of blocking.

### Proof of Concept
```go
func TestExtractZipFilePathTraversalLchown(t *testing.T) {
    tempDir := t.TempDir()
    outsideDir := t.TempDir() // sibling dir simulating "outside the sandbox"
    traversalTarget := filepath.Join(outsideDir, "evil.txt")

    archivePath := filepath.Join(tempDir, "evil.zip")
    f, _ := os.Create(archivePath)
    zw := zip.NewWriter(f)

    relTraversal, _ := filepath.Rel(tempDir, traversalTarget) // e.g. "../<outsideDir>/evil.txt"
    fh := &zip.FileHeader{Name: relTraversal, Method: zip.Deflate}
    fh.SetMode(0o644)
    // Craft 0x7875 extra field with attacker UID/GID
    var buf bytes.Buffer
    binary.Write(&buf, binary.LittleEndian, ZipExtraField{Type: ZipUIDGidFieldType, Size: 10})
    binary.Write(&buf, binary.LittleEndian, ZipUIDGidField{1, 4, 1234, 4, 5678})
    fh.Extra = buf.Bytes()

    w, _ := zw.CreateHeader(fh)
    w.Write([]byte("payload"))
    zw.Close()
    f.Close()

    // Extract while cwd is tempDir, simulating job workspace
    oldWd, _ := os.Getwd()
    os.Chdir(tempDir)
    defer os.Chdir(oldWd)

    err := ExtractZipFile(archivePath)
    require.NoError(t, err)

    // Assert file was NOT created outside tempDir/workspace
    _, statErr := os.Lstat(traversalTarget)
    assert.True(t, os.IsNotExist(statErr), "file should not exist outside workspace, path traversal occurred")
}
```
Expected (buggy) behavior: `traversalTarget` exists and its ownership was changed via `Lchown` to UID 1234/GID 5678, demonstrating the escape. Expected (fixed) behavior: extraction rejects/skips the entry and no file is created outside the workspace root.

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
```

```go
func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
```

```go
func processZipExtra(file *zip.FileHeader) error {
	if len(file.Extra) == 0 {
		return nil
	}

	r := bytes.NewReader(file.Extra)
	for {
		field, data, err := readZipExtraField(r)
		if err == io.EOF {
			break
		} else if err != nil {
			return err
		}

		switch field.Type {
		case ZipUIDGidFieldType:
			err = processZipUIDGidField(data, file)
		case ZipTimestampFieldType:
			err = processZipTimestampField(data, file)
		}
		if err != nil {
			return err
		}
	}

	return nil
}
```
