### Title
Path traversal in cache-archiver `--alternate-file` via unsanitized `AlternateKey` when `FF_HASH_CACHE_KEYS` is enabled - ([File: functions/concrete/builder/builder.go])

### Summary
When a pipeline author sets `FF_HASH_CACHE_KEYS=true` (a job-variable-controllable feature flag) and a crafted `cache.key` containing `../` segments, `builder.buildCacheArchive`/`buildCacheSources` compute `AlternateKey` as the raw, un-sanitized `humanKey` instead of the sanitized/hashed form. `stages.CacheArchive.alternateArchivePath` → `cacheArchivePath` then does `filepath.Join(e.CacheDir, AlternateKey, "cache.zip")`, which can resolve outside `CacheDir`, and this path is passed to `cache-archiver --alternate-file`, which can rename an existing local file onto that path via `os.Rename`.

### Finding Description
- In `functions/concrete/builder/builder.go` `cacheKey()` (lines 570-603): when `featureflags.HashCacheKeys` is ON, `humanKey = rawKey` directly, **skipping `cachekey.Sanitize`** entirely (the sanitizer bypass is intentional, since the primary key is then hashed). `resolvedKey` (used as `stages.CacheArchive.Key`) is `sha256(humanKey)` — safe, hex-only, no traversal possible.
- In `buildCacheArchive()` (lines 339-398) and `buildCacheSources()` (lines 237-336), the **alternate** key is computed as:
  ```go
  alternateResolved := humanKey
  if !b.isFeatureFlagOn(featureflags.HashCacheKeys) {
      alternateResolved = fmt.Sprintf("%x", sha256.Sum256([]byte(humanKey)))
  }
  ``` [1](#0-0) 
  When the FF is ON, `alternateResolved` is left as the **raw, unsanitized `humanKey`** (no hashing, no `cachekey.Sanitize`). This becomes `stages.CacheArchive.AlternateKey`.
- `cacheArchivePath` in `functions/concrete/run/stages/cache_archive.go` performs no validation:
  ```go
  func cacheArchivePath(e *env.Env, key string) string {
      absPath := filepath.Join(e.CacheDir, key, "cache.zip")
      rel, err := filepath.Rel(e.WorkingDir, absPath)
      ...
  }
  ``` [2](#0-1) 
  If `AlternateKey` contains `../../../etc/cron.d/x`, `filepath.Join` collapses the traversal and `absPath` escapes `CacheDir`.
- `CacheArchive.Run` invokes `cache-archiver --file <primary> --alternate-file <alternate>` whenever `AlternateKey != "" && AlternateKey != Key` [3](#0-2) .
- `commands/helpers/cache_archiver.go`'s `tryRenameAlternateFile()` calls `os.Rename(c.AlternateFile, c.File)` when the primary file doesn't yet exist locally and the alternate does [4](#0-3) . This only fires if a file happens to already exist at the crafted alternate path, but `createZipFile`'s `os.MkdirAll(filepath.Dir(filename), 0o700)` for `c.File` is scoped to the sanitized primary path, not the alternate — so the primary write path stays safe, but the traversal exists specifically for the `--alternate-file` value construction and rename source.
- `FF_HASH_CACHE_KEYS` is documented as settable per-job via `.gitlab-ci.yml` `variables:` unless the runner admin locks it under `[runners.feature_flags]` in `config.toml` [5](#0-4) . This is not a privileged action — it is one of the flags GitLab explicitly documents as pipeline-configurable [6](#0-5) .
- Existing tests (`TestSanitizeInvariants` in `cache/cachekey/cachekey_test.go`) confirm `cachekey.Sanitize` guarantees no `..` segments survive — but this guarantee is **bypassed** for `AlternateKey` under `FF_HASH_CACHE_KEYS=true`, which the question's premise anticipated but which only manifests through the alternate-key code path, not the primary `Key` field.

### Impact Explanation
An unprivileged pipeline author who can set job variables (`FF_HASH_CACHE_KEYS=true` and a crafted `cache.key`) can make Runner compute a `--alternate-file` argument for `cache-archiver`/`cache-extractor` that resolves outside `CacheDir`/`WorkingDir`. This violates the invariant that cache file operations stay within `CacheDir`. The concrete write primitive (`os.Rename` in `tryRenameAlternateFile`) is conditioned on a file already existing at the crafted path and on the primary not existing — a narrower exploitation window than an unconditional arbitrary-write, but it still represents a real violation of the "file operations must stay within intended cache root" invariant and could be used to relocate/rename existing build-agent files or corrupt state outside the job's cache/working directories on shared/reused executors.

### Likelihood Explanation
Preconditions: the runner must not lock `FF_HASH_CACHE_KEYS` via `[runners.feature_flags]` in `config.toml` (the default is unlocked/job-overridable). Given that, any pipeline author with `.gitlab-ci.yml` edit rights can set both the FF and a malicious `cache.key` value with no further privilege, making this fully reachable by a standard unprivileged pipeline author on such runners. This is not a purely theoretical or admin-only issue — it is directly reachable through documented, pipeline-configurable inputs.

### Recommendation
Always run the alternate key candidate through `cachekey.Sanitize` (or hash it) regardless of the `FF_HASH_CACHE_KEYS` setting before assigning it to `AlternateKey`/`altKey` in `buildCacheArchive` and `buildCacheSources`. At minimum, `cacheArchivePath` should validate that the resolved absolute path remains a descendant of `e.CacheDir` (mirroring the `strings.HasPrefix(fullPath, basePath+"/")` check already used in `cache/cache.go`'s `GetAdapter`) and refuse/skip the archive step otherwise.

func TestBuildCacheArchive_AlternateKeyTraversal(t *testing.T) {
    job := baseJob()
    job.Cache = []spec.Cache{

    require.Len(t, config.CacheArchive, 1)

    assert.False(t, strings.Contains(ak, ".."), "AlternateKey must not contain '..' segments, got %q", ak)
}
```

```go
func TestCacheArchivePath_AlternateKeyEscape(t *testing.T) {

    s := CacheArchive{Key: "abc", AlternateKey: "../../../etc/cron.d/x"}

func (c *CacheArchiverCommand) tryRenameAlternateFile() {
	if c.AlternateFile == "" || c.AlternateFile == c.File {
		return
	}

	_, err := os.Stat(c.File)
	if err == nil {
		logrus.Debugln("Primary cache file already exists locally, skipping rename from alternate")
		return
	}
	if !errors.Is(err, fs.ErrNotExist) {
		logrus.WithError(err).Warningln("Failed to stat primary cache file")
		return
	}

	if _, err := os.Stat(c.AlternateFile); err != nil {
		logrus.Debugln("Alternate cache file not found locally, nothing to rename")
		return
	}

	if err := os.MkdirAll(filepath.Dir(c.File), 0o700); err != nil {
		logrus.WithError(err).Warningln("Failed to create directory for cache file rename")
		return
	}

	if err := os.Rename(c.AlternateFile, c.File); err != nil {
		logrus.WithError(err).Warningln("Failed to rename alternate cache file to primary")
		return
	}

	logrus.Infoln("Renamed alternate cache file to primary")
}
```
