### Title
`SortitionData::validate_tenure_change_payload` (v1) uses `get_last_globally_accepted_block` instead of `get_last_signed_block`, letting a duplicate tenure-change block bypass `DuplicateBlockFound` when only a locally-accepted block exists - ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
`SortitionData::validate_tenure_change_payload` in `chainstate/v1.rs` checks for an existing block in the current tenure by calling `signer_db.get_last_globally_accepted_block(...)`, whereas the v2 implementation in `chainstate/v2.rs` uses `signer_db.get_last_signed_block(...)`, which additionally covers `LocallyAccepted` blocks. Because `get_last_signed_block` was introduced specifically to fix a documented regression where a locally-accepted (signed but not yet globally-accepted) block could be missed and a competing tenure-change proposal wrongly accepted, the v1 path retains exactly that flaw.

### Finding Description
The equality being violated is: "at most one tenure-change block may carry this signer's signature per tenure." `validate_tenure_change_payload` is supposed to enforce this by rejecting a second tenure-start proposal for a tenure where the signer already put a signature (local or global) on a prior block.

- v1: `stacks-signer/src/chainstate/v1.rs` lines 505-518 queries `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)` and only raises `RejectReason::DuplicateBlockFound` if a `GloballyAccepted` block exists in that tenure. [1](#0-0) 
- v2: `stacks-signer/src/chainstate/v2.rs` lines 340-357 queries `signer_db.get_last_signed_block(&block.header.consensus_hash)`, whose doc comment explicitly states blocks are "considered signed if it is locally or globally accepted," and the surrounding comment explains this was chosen because "we already confirmed... check we are not reorging the tenure blocks. Only blocks we have signed (locally or globally accepted) count here." [2](#0-1) 
- `get_last_signed_block`'s doc explicitly contrasts with `get_last_globally_accepted_block`, confirming it was added to close this exact gap. [3](#0-2) 
- A dedicated regression test exists for v2 only — `check_tenure_change_rejects_when_locally_accepted_block_exists` in `stacks-signer/src/chainstate/tests/v2.rs` — whose comment states: "previously, the check used `get_last_globally_accepted_block`, which would miss blocks in `LocallyAccepted` or `PreCommitted` state and incorrectly allow a duplicate tenure change." [4](#0-3)  No equivalent test exists in `stacks-signer/src/chainstate/tests/v1.rs`, and the v1 code was never updated to match.
- The project's own documentation (`docs/signer-flows.md`) states the asymmetry plainly: "v2 counts locally or globally accepted blocks (`get_last_signed_block`); v1 counts only globally accepted ones (`get_last_globally_accepted_block`)." [5](#0-4) 

Attack flow: a miner (attacker) wins a sortition slot, proposes a first tenure-change block for tenure T; the victim signer (running v1) locally accepts it (`mark_locally_accepted`), putting a signature on it, but it doesn't yet reach global 70% threshold. The attacker (or any miner) then proposes a second, different tenure-change block for the same tenure T. `validate_tenure_change_payload` (v1) queries `get_last_globally_accepted_block(T)`, finds `None` (since the existing block is only `LocallyAccepted`), skips the `DuplicateBlockFound` rejection, and the proposal proceeds toward signing. This produces two blocks in the same tenure T each carrying (or eligible to carry) the same signer's signature — a uniqueness violation.

The docs note a partial mitigation: "Because the duplicate check never runs again, a block that crosses the pre-commit threshold long after it was proposed relies on section 5's own-tenure conflict guard to cover the same ground" — meaning `check_latest_block_in_tenure`/`confirms_latest_block_in_same_tenure`, which are re-run at validate-ok and signing time, may still catch a genuine same-tenure conflict independent of `validate_tenure_change_payload`. [6](#0-5)  However, this guard operates on the *same* tenure logic that itself relies on `get_tenure_last_block_info`/`get_last_signed_block` semantics (per `docs/signer-flows.md` lines 396-397, referencing `get_last_signed_block`), which is a mod.rs-level (version-agnostic) function — so whether v1's `check_latest_block_in_tenure` fully backstops this specific gap in `validate_tenure_change_payload` could not be independently confirmed from the available context; I was unable to fully trace `check_latest_block_in_tenure` in `chainstate/mod.rs` within the available searches to conclusively determine if it always re-runs before signing for the tenure-change case in v1's own pipeline, or whether it's bypassed the same way.

### Impact Explanation
If exploitable end-to-end (i.e., if the "section 5" backstop does not independently close this exact gap for v1 signers), this breaks the **uniqueness/non-conflicting-signature safety property**: a signer could sign two different tenure-change (tenure-starting) blocks for the same tenure, one of which is necessarily non-canonical. Aggregated across signers this constitutes the "Critical" category described — a signer signing a conflicting block within a tenure, undermining chain safety guarantees the signer protocol is meant to enforce. This would be repeatable per-tenure as long as a v1 signer exists and a locally-accepted-but-not-globally-accepted window occurs.

### Likelihood Explanation
Preconditions are narrow and require external validation I could not confirm:
1. The signer must actually be negotiated to protocol v1. The observed `SUPPORTED_SIGNER_PROTOCOL_VERSION` constant is `2` [7](#0-6) , and v1 code exists but I could not confirm from available context whether v1 is still an actively negotiable/reachable code path in current deployments, or legacy/deprecated code retained for backward compatibility with older signers. If v1 is unreachable in practice (e.g., only used for backward-compat with peers who have since upgraded, or gated off), the practical likelihood is much lower.
2. Requires a natural race window where a block is locally-but-not-globally accepted — a routine occurrence during block signing rounds, not attacker-controlled but exploitable opportunistically by any miner slot holder.
3. Requires confirming that the "own-tenure conflict guard" (validate-ok/signing-time re-check) does not independently prevent the double-signature in v1's pipeline — unconfirmed.

### Recommendation
Change `chainstate/v1.rs`'s `validate_tenure_change_payload` to call `signer_db.get_last_signed_block(&block.header.consensus_hash)` instead of `get_last_globally_accepted_block`, matching v2's semantics, and add a v1-side regression test mirroring `check_tenure_change_rejects_when_locally_accepted_block_exists` in `stacks-signer/src/chainstate/tests/v2.rs`.

    /// Return the last signed block in a tenure (identified by its consensus hash).
    /// A block is considered signed if it is locally or globally accepted. Blocks that
    /// have only been pre-committed are excluded, because a pre-commit does not put a
    /// signature over the block and may be safely superseded by a competing proposal.
    ///
    /// This answers "what is the tenure's signed tip?", a different question from
    /// [`SignerDb::has_signed_block_in_tenure`]'s "does a signature bind us to this tenure?",
    /// which is why the predicates deliberately differ on rejected blocks (see there).
    pub fn get_last_signed_block(
        &self,
        tenure: &ConsensusHash,
    ) -> Result<Option<BlockInfo>, DBError> {
        let query = "SELECT block_info FROM blocks WHERE consensus_hash = ?1 AND state IN (?2, ?3) ORDER BY stacks_height DESC LIMIT 1";
        let args = params![
            tenure,
            &BlockState::GloballyAccepted.to_string(),
            &BlockState::LocallyAccepted.to_string(),
        ];
        let result: Option<String> = query_row(&self.db, query, args)?;

        try_deserialize(result)
    }

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}
