### Title
Silent Reward Shortfall in `withdraw_rewards` Silently Underpays Stakers - (File: `crates/sui-framework/packages/sui-system/sources/staking_pool.move`)

### Summary

The `withdraw_rewards` function in `StakingPool` silently caps the reward payout to the available `rewards_pool` balance when a shortfall exists, without tracking or crediting the difference to the staker. Any ordinary SUI holder who calls `request_withdraw_stake` during a shortfall condition permanently loses the uncredited portion of their earned rewards with no recovery path.

### Finding Description

In `staking_pool.move`, `withdraw_rewards` computes the staker's entitled reward amount from the exchange rate, then silently clamps it to whatever is actually in `rewards_pool`:

```move
// This may happen when we are withdrawing everything from the pool and
// the rewards pool balance may be less than reward_withdraw_amount.
// TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
pool.rewards_pool.split(reward_withdraw_amount)
``` [1](#0-0) 

The `TODO` comment confirms the developers themselves do not fully understand the root cause of the shortfall. The caller (`request_withdraw_stake`) receives the silently-reduced balance and joins it with the principal:

```move
let rewards_withdraw = pool.withdraw_rewards(...);
let total_sui_withdraw_amount = principal_withdraw_amount + rewards_withdraw.value();
...
principal_withdraw.join(rewards_withdraw);
principal_withdraw
``` [2](#0-1) 

No shortfall is recorded anywhere. The staker's `StakedSui` object is consumed and destroyed; there is no object or mapping that tracks the uncredited difference. The shortfall amount remains stranded in `rewards_pool` and is silently redistributed to remaining stakers or locked indefinitely.

The shortfall arises because `sui_balance` (the accounting field) and `rewards_pool` (the actual `Balance<SUI>`) can diverge. `process_pending_stake_withdraw` can drive `sui_balance` to zero via an underflow path while the actual `rewards_pool` balance is non-zero but smaller than what the exchange-rate arithmetic promises:

```move
pool.sui_balance = if (pool.sui_balance >= pool.pending_total_sui_withdraw) {
    pool.sui_balance - pool.pending_total_sui_withdraw
} else {
    let diff = pool.pending_total_sui_withdraw - pool.sui_balance;
    if (!pool.is_inactive()) {
        pool.extra_fields.add(UnderflowSuiBalance {}, diff);
    };
    0
};
``` [3](#0-2) 

### Impact Explanation

Any ordinary SUI holder who stakes and later calls `request_withdraw_stake` (or the public `sui_system::request_withdraw_stake` entry point) during a shortfall epoch receives fewer SUI rewards than the exchange rate entitles them to. The difference is permanently unrecoverable because:

1. The `StakedSui` object is destroyed on withdrawal — there is no re-entry point.
2. No shortfall mapping or debt record is written.
3. The stranded SUI in `rewards_pool` is silently absorbed by the pool, effectively redistributing it to other stakers or locking it.

This matches the **Medium** allowed impact: *harmful smart-contract behavior* — stakers receive less than their entitled rewards with no recovery path.

### Likelihood Explanation

The condition is reachable by any ordinary SUI holder without any privileged access. The existing test suite explicitly demonstrates the shortfall scenario:

```move
// insufficient pool token balance
assert_eq!(pool.pool_token_balance(), 86666666666);
assert_eq!(pool.pending_pool_token_withdraw_amount(), 100000000000);
assert!(pool.pool_token_balance() < pool.pending_pool_token_withdraw_amount());
``` [4](#0-3) 

The test confirms the pool token balance (86,666,666,666) can fall below the pending pool token withdraw amount (100,000,000,000) — a ~13% shortfall — which directly causes `withdraw_rewards` to cap the payout. This is not a 1-MIST rounding artifact; it is a structurally significant divergence that the developers acknowledge but have not resolved (the `TODO` comment).

### Recommendation

Track the shortfall per staker. When `reward_withdraw_amount` is capped, record the difference in a `Table<address, u64>` (or dynamic field keyed by staker address) so the staker can claim the remainder once the pool is replenished. Alternatively, assert that `rewards_pool.value() >= reward_withdraw_amount` and abort rather than silently underpaying, forcing the protocol to resolve the accounting divergence explicitly before allowing withdrawals.

### Proof of Concept

1. A validator's staking pool accumulates rewards over multiple epochs.
2. Due to the `process_pending_stake_withdraw` underflow path, `sui_balance` diverges from the actual `rewards_pool` balance.
3. The existing test (`rewards_distribution_tests.move`, lines 1012–1018) shows `pool_token_balance` (86,666,666,666) < `pending_pool_token_withdraw_amount` (100,000,000,000).
4. A staker calls `sui_system::request_withdraw_stake` with their `StakedSui` object.
5. `withdraw_rewards` computes `reward_withdraw_amount` from the exchange rate — a value larger than `rewards_pool.value()`.
6. Line 439 silently clamps the payout: `reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value())`.
7. The staker receives principal + capped rewards. The shortfall (entitled rewards minus actual rewards) is never recorded and cannot be claimed.
8. The `StakedSui` object is destroyed; the staker has no recourse. [5](#0-4) [6](#0-5)

public(package) fun request_withdraw_stake(
    pool: &mut StakingPool,
    staked_sui: StakedSui,
    ctx: &TxContext,
): Balance<SUI> {
    // stake is inactive and the pool is not preactive - allow direct withdraw
    // the reason why we exclude preactive pools is to avoid potential underflow
    // on subtraction, and we need to enforce `pending_stake_withdraw` call.
    if (staked_sui.stake_activation_epoch > ctx.epoch() && !pool.is_preactive()) {
        let principal = staked_sui.into_balance();
        pool.pending_stake = pool.pending_stake - principal.value();
        return principal
    };

    let (pool_token_withdraw_amount, mut principal_withdraw) = pool.withdraw_from_principal(
        staked_sui,
    );
    let principal_withdraw_amount = principal_withdraw.value();

    let rewards_withdraw = pool.withdraw_rewards(
        principal_withdraw_amount,
        pool_token_withdraw_amount,
        ctx.epoch(),
    );
    let total_sui_withdraw_amount = principal_withdraw_amount + rewards_withdraw.value();

    pool.pending_total_sui_withdraw = pool.pending_total_sui_withdraw + total_sui_withdraw_amount;
    pool.pending_pool_token_withdraw =
        pool.pending_pool_token_withdraw + pool_token_withdraw_amount;

    // If the pool is inactive or preactive, we immediately process the withdrawal.
    if (pool.is_inactive() || pool.is_preactive()) pool.process_pending_stake_withdraw();

    // TODO: implement withdraw bonding period here.
    principal_withdraw.join(rewards_withdraw);
    principal_withdraw
}

fun process_pending_stake_withdraw(pool: &mut StakingPool) {
    pool.sui_balance = if (pool.sui_balance >= pool.pending_total_sui_withdraw) {
        pool.sui_balance - pool.pending_total_sui_withdraw
    } else {
        let diff = pool.pending_total_sui_withdraw - pool.sui_balance;
        // While this key is expected to be removed in the next call to `process_pending_stake`,
        // we do not call `process_pending_stake` for inactive pools — skip the bookkeeping.
        if (!pool.is_inactive()) {
            pool.extra_fields.add(UnderflowSuiBalance {}, diff);
        };
        0
    };

    pool.pool_token_balance = if (pool.pool_token_balance >= pool.pending_pool_token_withdraw) {
        pool.pool_token_balance - pool.pending_pool_token_withdraw
    } else {
        0
    };

    pool.pending_total_sui_withdraw = 0;
    pool.pending_pool_token_withdraw = 0;
}

fun withdraw_rewards(
    pool: &mut StakingPool,
    principal_withdraw_amount: u64,
    pool_token_withdraw_amount: u64,
    epoch: u64,
): Balance<SUI> {
    let exchange_rate = pool.pool_token_exchange_rate_at_epoch(epoch);
    let total_sui_withdraw_amount = exchange_rate.get_sui_amount(pool_token_withdraw_amount);
    let mut reward_withdraw_amount = if (total_sui_withdraw_amount >= principal_withdraw_amount) {
        total_sui_withdraw_amount - principal_withdraw_amount
    } else 0;

    // This may happen when we are withdrawing everything from the pool and
    // the rewards pool balance may be less than reward_withdraw_amount.
    // TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
    reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
    pool.rewards_pool.split(reward_withdraw_amount)
}
