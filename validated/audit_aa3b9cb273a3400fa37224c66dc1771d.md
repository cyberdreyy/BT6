### Title
Dst escrow with malformed short `parameters` bricks both private and public withdrawal - (File: `contracts/EscrowDst.sol`, `contracts/libraries/ImmutablesLib.sol`, `contracts/BaseEscrowFactory.sol`)

### Summary
Any address calling `createDstEscrow` fully controls the `Immutables.parameters` bytes with no length enforcement. If `parameters.length` is between `0x20` (32) and `0x3f` (63) — e.g. 33 bytes — `protocolFeeAmountCd()` succeeds (requires ≥32 bytes) but `integratorFeeAmountCd()` always reverts with `IndexOutOfRange` (requires ≥64 bytes). Since `EscrowDst._withdraw` calls both decoders unconditionally before any zero-check, every call to `withdraw` and `publicWithdraw` on that escrow instance reverts.

### Finding Description
`createDstEscrow` computes the CREATE2 salt from `immutables.hashMem()` and deploys/funds the clone strictly based on `token`, `amount`, and `safetyDeposit`, without validating `dstImmutables.parameters` at all: [1](#0-0) 

The escrow is funded correctly (native/ERC20 balance checks only look at `token`/`amount`/`safetyDeposit`), so a 33-byte `parameters` blob does not prevent successful, fully-funded deployment.

`ImmutablesLib` enforces minimum lengths per field via explicit reverts: [2](#0-1) 

`EscrowDst._withdraw` (used by both `withdraw` and `publicWithdraw`) unconditionally decodes both fee amounts before any conditional gating on their value: [3](#0-2) 

With `parameters.length == 33`: `protocolFeeAmountCd()` (needs `≥0x20`) succeeds, but `integratorFeeAmountCd()` (needs `≥0x40`) always reverts with `IndexOutOfRange`, regardless of secret validity, caller, or timing. Because both `withdraw` (private) and `publicWithdraw` (public) route through the same `_withdraw`, both paths are bricked identically — the public path provides no fallback.

`cancel()` is unaffected since it doesn't touch `parameters`/fees, so funds are eventually recoverable — but only back to the `taker`, not to the `maker`: [4](#0-3) 

### Impact Explanation
The maker can never receive destination funds through this escrow via the intended withdrawal mechanism, even with a valid secret and correct timing — violating the stated invariant that "a funded escrow with a known secret should be finalizable via public withdrawal." Recovery is only possible via `cancel()` (funds go to `taker`, not `maker`) or eventually `rescueFunds`, both of which do not fulfill the swap as intended. This matches "temporary freezing of funds during the live swap lifecycle" (High) rather than permanent loss, since cancellation/rescue paths remain functional and the source-side escrow can still be cancelled to refund the maker separately.

### Likelihood Explanation
`createDstEscrow` is fully permissionless and takes attacker-supplied `Immutables` directly, with the address/parameters entirely determined by whoever calls it and funds the deposit — no on-chain cross-check exists against the source-chain `SrcEscrowCreated`/`DstImmutablesComplement` data. Any party controlling that call (typically the resolver/taker) can trivially trigger this by using a truncated `parameters` blob. This does rely on the destination-escrow creator supplying malformed data (rather than an on-path system deriving it), and the protocol's documented security model depends on off-chain verification of escrow immutables before secret release, which limits (but does not eliminate) practical exploitation against a careful maker.

### Recommendation
- Add explicit `parameters.length` validation in `createDstEscrow` (require exactly the expected length, e.g. `0x80` bytes for the 4 fee fields) before deployment.
- In `EscrowDst._withdraw`, avoid unconditionally decoding `integratorFeeAmountCd`/`protocolFeeAmountCd` when not structurally guaranteed; or make `ImmutablesLib` fee getters tolerant of short/empty `parameters` (treat as zero) instead of reverting, if zero-fee escrows are a supported configuration.

### Proof of Concept
1. Attacker (or malicious resolver) calls `createDstEscrow` with `dstImmutables.parameters` set to a 33-byte blob (e.g., `abi.encodePacked(uint256(protocolFeeAmount), uint8(0))`), paying the correct `safetyDeposit`/`amount` in `msg.value`/ERC20 transfer.
2. Escrow deploys and is funded successfully — `token`/`amount`/`safetyDeposit` checks pass, `parameters` length is never checked.
3. Maker/anyone learns the secret; after `DstWithdrawal` start, taker calls `withdraw(secret, immutables)` → reverts with `IndexOutOfRange` from `integratorFeeAmountCd()`.
4. After `DstPublicWithdrawal` start, any access-token holder calls `publicWithdraw(secret, immutables)` → reverts identically.
5. Only `cancel()` (after `DstCancellation`) succeeds, returning `amount` and `safetyDeposit` to `taker`, not `maker`.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    /**

    function integratorFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
