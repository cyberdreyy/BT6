### Title
RPC jsonParsed token decoding trusts mint data without verifying mint-account ownership, diverging from SVM's owner-checked balance reporting - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`rpc/src/parsed_token_accounts.rs::get_additional_mint_data` (used by `get_parsed_token_account`, `get_parsed_token_accounts`, and `get_token_account_balance`/`get_mint_owner_and_additional_data` in `rpc/src/rpc.rs`) unpacks whatever account is referenced by a token account's `mint` field as an SPL `Mint`, without checking that this mint account is actually owned by the same token program as the token account. In contrast, `svm/src/transaction_balances.rs::SvmTokenInfo::unpack_token_account` explicitly rejects the pairing when `*mint_account.owner() != program_id`. This produces two different, non-equivalent decodings (decimals/ui_amount) for the same on-chain state depending on which API path is queried.

### Finding Description
`SvmTokenInfo::unpack_token_account` (used to populate pre/post token balances that end up in transaction metadata) performs a strict ownership check before trusting the referenced mint's `decimals`: [1](#0-0) 

By contrast, the RPC jsonParsed decoding path fetches the mint account purely by pubkey and calls `get_additional_mint_data`, which only attempts `StateWithExtensions::<Mint>::unpack(data)` — it never checks `mint_account.owner()` against the token account's owning program: [2](#0-1) [3](#0-2) 

The same unchecked pattern is reused by `get_mint_owner_and_additional_data`, which backs `getTokenAccountBalance`, `getTokenAccountsByOwner`, `getTokenAccountsByDelegate`, and `getProgramAccounts` (jsonParsed): [4](#0-3) [5](#0-4) 

Given the stated precondition — a token account (owned by a real SPL token program, so it passes `is_known_spl_token_id`/`PARSABLE_PROGRAM_IDS` gating on the account itself) whose embedded `mint` pubkey references an account that is *not* owned by that same token program but whose raw bytes still happen to unpack as a valid `Mint` layout — the two code paths produce different results for identical on-chain state:
- `SvmTokenInfo::unpack_token_account` returns `None` for that account (owner mismatch), so it is silently excluded from `pre_token_balances`/`post_token_balances` in transaction metadata.
- `get_parsed_token_account`/`get_token_account_balance` happily decode the mismatched mint's `decimals` field and report a `tokenAmount`/`UiTokenAmount` with those (potentially attacker-chosen) decimals to any RPC/jsonParsed caller.

This is a parse-fidelity/cross-API-consistency bug entirely within Agave's own account-decoder/RPC code, independent of the SPL token program's own instruction-level validation.

### Impact Explanation
Different downstream integrators (an indexer/explorer reading transaction metadata's token balances vs. a wallet calling `getTokenAccountBalance`/`getAccountInfo?encoding=jsonParsed` for the very same account) can be shown inconsistent `decimals`/`uiAmount` for the identical on-chain account, because one path (SVM balances) filters the account out while the other (RPC jsonParsed) reports a value derived from an untrusted, wrongly-owned "mint". This matches the "misreporting program, authority, amount, decimals, or token owner to downstream integrators" / parse-fidelity category called out in the audit scope.

### Likelihood Explanation
The precondition is limited to an unprivileged attacker being able to create/keep a valid-owner token account whose `mint` field points at an account not owned by the token program while that account's raw bytes still unpack as a `Mint` (e.g., a repurposed/closed mint address, or any account whose 82-byte-plus contents coincidentally match the Mint layout). This is purely account-data manipulation reachable via ordinary transactions and standard read-only RPC calls (`getAccountInfo`, `getTokenAccountBalance`, `getTokenAccountsByOwner`, `getProgramAccounts`), i.e. within the allowed one-call attacker model, with no validator/leader/gossip control needed.

### Recommendation
Add the same ownership check used in `SvmTokenInfo::unpack_token_account` to `get_additional_mint_data`/`get_mint_owner_and_additional_data` in `rpc/src/parsed_token_accounts.rs`: verify the fetched mint account's `owner()` equals the token account's owning program id (or the expected token program id being queried) before trusting its `Mint::unpack` result; on mismatch, return an error (or omit `tokenAmount`) instead of silently decoding.

### Proof of Concept
Rust integration test sketch (extending the existing `test_token_parsing`/`get_token_account_balance` test harness in `rpc/src/rpc.rs`):
1. Store a token account (owner = `spl_token::id()`) whose `mint` field is set to pubkey `M`.
2. Store account `M` with `owner = system_program::id()` (not the token program) but with data bytes that unpack via `spl_token_interface::state::Mint::unpack` to `decimals = 9`.
3. Call `get_token_account_balance`/`getAccountInfo` with `encoding=jsonParsed` for the token account and assert the returned `tokenAmount.decimals == 9` (demonstrating the RPC path trusts the mismatched mint).
4. Separately, run the SVM `collect_balances`/`SvmTokenInfo::unpack_token_account` path (via `svm/src/transaction_balances.rs` test utilities) on the same accounts and assert it returns `None` (excludes the token balance).
5. Assert these two outcomes diverge (one produces `decimals = 9`/a `TransactionTokenBalance`, the other produces nothing), proving the cross-API inconsistency.

impl SvmTokenInfo {
    fn unpack_token_account<CB: TransactionProcessingCallback>(
        account_loader: &mut AccountLoader<CB>,
        account: &AccountSharedData,
        index: usize,
    ) -> Option<Self> {
        let program_id = *account.owner();
        let generic_token::Account {
            mint,
            owner,
            amount,
        } = generic_token::Account::unpack(account.data(), &program_id)?;

        let mint_account = account_loader.load_account(&mint)?;
        if *mint_account.owner() != program_id {
            return None;
        }

        let generic_token::Mint { decimals, .. } =
            generic_token::Mint::unpack(mint_account.data(), &program_id)?;

        Some(Self {
            account_index: index.try_into().ok()?,
            mint,
            amount,
            owner,
            program_id,
            decimals,
        })
    }

/// Analyze a mint Pubkey that may be the native_mint and get the mint-account owner (token
/// program_id) and decimals
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}

        &self,
        pubkey: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);

            .expect("Token account mint should be convertible to Pubkey");
        let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
        let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
