### Title
Multisig `confirm` counts stale confirmations from removed members, allowing requests to execute below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` in `multisig2/src/lib.rs` decides whether to execute a pending request purely by comparing the *size* of the stored confirmation set to `num_confirmations`. `delete_member` only purges confirmations for requests that the removed member itself *created* (`r.member == member`), not confirmations that member previously *gave* on requests created by other members. A confirmation recorded by a member who is later removed therefore remains counted forever, letting a request execute with fewer genuinely live confirmations than `num_confirmations` requires.

### Finding Description
`confirm()` computes the executed/not-executed decision as: [1](#0-0) 
```
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
} else {
    confirmations.insert(member.to_string());
    ...
}
```
The `confirmations` HashSet is keyed by `member.to_string()` and its cardinality is trusted as "number of live members who approved," but nothing re-validates that every entry in the set still corresponds to a current member of `self.members` at execution time.

`delete_member` is the only place that scrubs confirmation state, and it scrubs by *request owner*, not by *confirmer*: [2](#0-1) 
```
fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
    ...
    let request_ids: Vec<u32> = self
        .requests
        .iter()
        .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
        .collect();
    for request_id in request_ids {
        self.confirmations.remove(&request_id);
        self.requests.remove(&request_id);
    }
    self.num_requests_pk.remove(&member.to_string());
    self.members.remove(&member);
    ...
}
```
This only removes/invalidates requests *created by* the removed member. If the removed member had instead confirmed a request created by a *different* member (a request that hasn't yet reached the threshold), that confirmation entry stays in `self.confirmations` untouched — it is never removed, and `self.members.remove(&member)` does not cascade into the confirmations map.

The binding that should hold is: `confirmations.len()` (votes counted toward execution) == number of *currently live* members who approved. After a member is removed while their stale confirmation remains on an unrelated pending request, this equality breaks: `confirmations.len()` includes at least one vote from an account that is no longer a member, so a request can cross the `num_confirmations` threshold using fewer live approvals than the configured K.

### Impact Explanation
This crosses the "confirmations counted versus live members" boundary described as Critical: "a multisig request executed below threshold." A transfer, `AddKey`, `DeployContract`, or `AddMember`/`DeleteMember` action can be executed with fewer than `num_confirmations` currently-authorized approvers, effectively lowering the K-of-N security guarantee of the multisig without any of the remaining members explicitly re-approving with the reduced threshold.

### Likelihood Explanation
This requires only ordinary multisig usage, no owner/foundation/redeploy assumption, and no malicious validator: any legitimate member confirms an unrelated pending request, is later removed as a member for an unrelated (legitimate) reason via `DeleteMember`, and the stale confirmation remains countable. A remaining member (possibly colluding with, or simply following, normal operational flow) then confirms the same stale request and it executes with only one live approver instead of the required K. Because member removal is a normal administrative action (e.g., rotating multisig membership), the preconditions are easily reachable in practice, not merely theoretical.

### Recommendation
When executing `delete_member` (and any other removal path), iterate the confirmations of *every* outstanding request and strip the entry belonging to the removed member, not just requests the removed member created. Alternatively, at `confirm()` time, re-validate that every account/key in the stored `confirmations` set is still contained in `self.members` before counting `confirmations.len()`, discarding stale entries (and persisting the cleanup) prior to the threshold comparison.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C}` and `num_confirmations = 2`.
2. `B` calls `add_request` to create request `R` (e.g., a `Transfer`). `confirmations[R] = {}`.
3. `A` calls `confirm(R)`. Since `0 + 1 < 2`, it does not execute; `confirmations[R] = {"A"}`.
4. Separately, members `B` and `C` submit and confirm a `DeleteMember { member: A }` request, which succeeds (`members.len()-1 = 2 >= num_confirmations = 2`) and calls `delete_member(promise, A)`. Because `R` was created by `B`, not `A`, the filter `r.member == member` does not match `R`, so `confirmations[R]` is left untouched as `{"A"}`; `A` is removed from `self.members` and its access key deleted.
5. `C` (a genuinely live member) calls `confirm(R)`. `assert_valid_request` succeeds because `C` is a current member. `confirmations.len() (1) + 1 = 2 >= num_confirmations (2)` → `R` executes, even though only `C` is a currently valid confirming member; `A`'s vote counted toward the K=2 threshold despite `A` no longer being a multisig member.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
