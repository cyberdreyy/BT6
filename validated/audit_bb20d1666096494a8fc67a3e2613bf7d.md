### Title
Unrestricted Index route discloses `OutgoingToken` external-initiator callback credential to any authenticated role - ([File: core/web/external_initiators_controller.go], [File: core/web/presenters/external_initiators.go])

### Summary
The `GET /v2/external_initiators` route is registered without any role restriction (`auth.RequiresEditRole`/`RequiresAdminRole`), unlike `Create` and `Destroy` which require edit role, so any authenticated user (including a view-role user) can list external initiators. `presenters.ExternalInitiatorResource`, returned by `ExternalInitiatorsController.Index`, includes the `OutgoingToken` field, which is one of the two secrets generated in `bridges.NewExternalInitiator` used by the node to authenticate its outbound callback to the external initiator.

### Finding Description
`core/web/router.go` registers the external-initiator routes as: [1](#0-0) 
Note `GET /external_initiators` has no `auth.RequiresEditRole`/`RequiresAdminRole` wrapper, while `POST` and `DELETE` do. Any session/API token that passes `auth.Authenticate` (view role included) can call `Index`.

`ExternalInitiatorsController.Index` builds the response using `presenters.NewExternalInitiatorResource`: [2](#0-1) 

That presenter serializes the `OutgoingToken` field directly from the DB-loaded `bridges.ExternalInitiator` struct: [3](#0-2) 

`OutgoingToken` (along with `OutgoingSecret`, which is *not* included in `ExternalInitiatorResource`) is generated once in `bridges.NewExternalInitiator` and is meant to be used by the node itself to authenticate outbound calls to the external initiator's URL: [4](#0-3) 

The existing test `TestExternalInitiatorsController_Index` explicitly asserts that `OutgoingToken` is returned in the Index/paginated response for every listed initiator: [5](#0-4) 

So the invariant stated in the question ("secrets never leave except at creation time to the creator") is violated for `OutgoingToken` specifically: it is persisted in the DB (`bridges/orm.go` `CreateExternalInitiator`/`ExternalInitiators`) and re-served on every subsequent `Index` call to any authenticated caller, not only to the creator at creation time. `OutgoingSecret`, `HashedSecret`, and `Salt` are correctly excluded from `ExternalInitiatorResource` — only `OutgoingToken` is exposed.

### Impact Explanation
This matches the Chainlink bounty "credential/secret disclosure" impact class. A low-privileged, view-role authenticated user (no edit/admin role required, since `Index` has no role guard) can enumerate all external initiators and harvest their `OutgoingToken` values. If the external initiator's callback endpoint validates only the outgoing token (bearer-token style) for requests coming "from" the Chainlink node, an attacker holding the harvested token could impersonate the node's outbound callback channel to that external initiator, potentially triggering unintended external-initiator-side actions attributed to the node. The scope is limited to whatever the external initiator does with that token (this repo does not control the external initiator's server-side validation logic), but the token itself is unambiguously leaked beyond its intended recipient (the creator at creation time).

### Likelihood Explanation
Low barrier: any authenticated session/API token with at least view privileges (the lowest role that can pass `auth.Authenticate`) can call `GET /v2/external_initiators` since no role check is present on that route, unlike the sibling `Create`/`Destroy` routes which do enforce `RequiresEditRole`. This is trivially repeatable — a single GET request returns every initiator's `outgoingToken` in the paginated JSON:API response.

### Recommendation
- Restrict `GET /v2/external_initiators` to require at least edit/admin role (`auth.RequiresEditRole` or stricter), consistent with `Create`/`Destroy`, so view-role sessions cannot enumerate initiator credentials.
- Remove `OutgoingToken` (and any other outbound secret) from `presenters.ExternalInitiatorResource`/`NewExternalInitiatorResource` entirely; it should only ever be returned once, in `ExternalInitiatorAuthentication`, at creation time via `Create`.
- If external tooling depends on retrieving `OutgoingToken` later, provide a dedicated, admin-only, audited endpoint rather than exposing it via the general list endpoint.

### Proof of Concept
Go handler-level integration test plan (extends existing `core/web/external_initiators_controller_test.go`):
1. Start `TestApplication` with `ExternalInitiatorsEnabled = true`.
2. Insert an external initiator via `cltest.MustInsertExternalInitiatorWithOpts` with a known `OutgoingToken`.
3. Create an HTTP client authenticated with a view-role-only session/token (`app.NewHTTPClient` configured for view role, or directly call `ExternalInitiatorsController.Index` bypassing any edit-role middleware to demonstrate no guard exists).
4. Call `GET /v2/external_initiators`.
5. Assert `http.StatusOK` (not `403 Forbidden`), and parse the response into `[]presenters.ExternalInitiatorResource`.
6. Assert `externalInitiators[0].OutgoingToken == eiFoo.OutgoingToken` — proving the secret is disclosed to a caller who should only have view privileges.
7. Additionally, add a presenter-level unit test on `presenters.NewExternalInitiatorResource` that asserts the returned struct/JSON has no `outgoingToken` field (post-fix), failing today because `OutgoingToken` is populated.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
```
