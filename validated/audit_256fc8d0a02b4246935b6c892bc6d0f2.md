### Title
Unstaked balance is debited without checking the withdrawal transfer's success - ([File: staking-pool/src/internal.rs])

### Summary
`internal_withdraw` in `staking-pool/src/internal.rs` fires `Promise::new(account_id).transfer(amount)` and immediately, unconditionally decrements the user's `account.unstaked` balance and the contract's `self.last_total_balance`, with no `.then()` callback and no `is_promise_success()` check on the transfer outcome. [1](#0-0) 

### Finding Description
`internal_withdraw` decrements the account's ledger (`account.unstaked -= amount`, persisted via `internal_save_account`) and the global `last_total_balance` before/alongside dispatching a bare `Promise::new(account_id).transfer(amount)`, with no callback attached to verify the transfer actually succeeded: [1](#0-0) 

This is inconsistent with every other cross-contract call pattern in the same codebase, where a `.then()` callback checks `is_promise_success()` before committing state changes — e.g. `on_staking_pool_withdraw`, `on_staking_pool_deposit`, `on_withdraw_unvested_amount`, `on_lockup_create`, and `on_staking_pool_create` all gate ledger mutation on the promise result: [2](#0-1) [3](#0-2) [4](#0-3) 

In `internal_withdraw`, the ledger update happens synchronously in the same function call regardless of what happens to the `transfer` action's receipt, which is processed asynchronously as a separate receipt. If that transfer action fails on-chain (e.g., the destination account no longer exists, or any other receipt-level failure), the deposit for the transfer is refunded back to the staking-pool contract's own balance — but the code has already deducted `amount` from `account.unstaked` and from `self.last_total_balance` as though the withdrawal was delivered.

The custody binding broken here is: `sum(account.unstaked across all accounts) + staked balance` should equal the actual NEAR balance held by the contract (`last_total_balance`/on-chain balance). After a failed transfer, the on-chain NEAR balance retains the refunded amount, but the internal ledger has already recorded it as paid out, so the recorded claim (0 for that withdrawal) diverges from the NEAR actually available (still held by the contract, not attributed to the user).

### Impact Explanation
If a withdrawal transfer fails post-dispatch, the user's `unstaked` balance and the contract's `last_total_balance` are permanently decremented as if the withdrawal succeeded, but the corresponding NEAR is never delivered to the user. The user loses the withdrawn amount from their recorded balance with no recourse to re-claim it, and the leftover NEAR sits in the contract unattributed — a case of funds effectively frozen from the affected user's perspective and an accounting value (`last_total_balance`) diverging from the real underlying balance that other participants (e.g. depositors relying on `last_total_balance`/`get_account_total_balance`) settle on.

### Likelihood Explanation
No attacker interaction is required to trigger the underlying flaw — it is simply the unchecked-success pattern in `internal_withdraw`, matching the reported bug class in the external report (unchecked external call whose failure silently desyncs recorded state from delivered value). The precondition (transfer action failing after being dispatched) is outside attacker control in the common case, which is why this is flagged as an analog rather than a fully attacker-triggerable exploit; still, it is a concrete deviation from the safe pattern used everywhere else in this codebase for withdrawal/transfer callbacks.

### Recommendation
Attach a `.then()` callback to the `Promise::new(account_id).transfer(amount)` in `internal_withdraw`, check `is_promise_success()` in that callback, and only commit the `account.unstaked -= amount` / `last_total_balance -= amount` state changes (or roll them back / re-credit the account) based on the actual promise result, consistent with the pattern already used in `on_staking_pool_withdraw` and the other callback-gated flows in this repository.

### Proof of Concept
Not independently reproducible from the indexed contents alone — the analog is derived from static code inspection of `internal_withdraw`. Note: due to index size limits, I was not able to fully retrieve `staking-pool/src/lib.rs`'s `withdraw` entry point in this pass to confirm there is no additional guard before calling `internal_withdraw`; a Devin session with full repository access should verify this and construct an on-chain repro (e.g. simulate a receipt-level transfer failure) before treating this as fully confirmed.

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }

    pub fn on_staking_pool_withdraw(&mut self, amount: WrappedBalance) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        self.set_staking_pool_status(TransactionStatus::Idle);

        if withdraw_succeeded {
            {
                let staking_information = self.staking_information.as_mut().unwrap();
                // Due to staking rewards the deposit amount can become negative.

                    .saturating_sub(amount.0);
            }
            env::log(
                format!(
                    "The withdrawal of {} from @{} succeeded",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        } else {
            env::log(
                format!(
                    "The withdrawal of {} from @{} failed",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
    }

    /// Called after the foundation tried to withdraw the terminated unvested balance.
    pub fn on_withdraw_unvested_amount(
        &mut self,
        amount: WrappedBalance,
        receiver_id: AccountId,
    ) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        if withdraw_succeeded {
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} succeeded.",
                    amount.0, receiver_id
                )
                    .as_bytes(),
            );
            // Decreasing lockup amount after withdrawal.
            self.lockup_information.termination_withdrawn_tokens += amount.0;
            let unvested_amount = self.get_terminated_unvested_balance().0;
            if unvested_amount > amount.0 {
                // There is still unvested balance remaining.
                let remaining_balance = unvested_amount - amount.0;
                self.vesting_information =
                    VestingInformation::Terminating(TerminationInformation {
                        unvested_amount: remaining_balance.into(),
                        status: TerminationStatus::ReadyToWithdraw,
                    });
                env::log(
                    format!(
                        "Termination Step: There is still terminated unvested balance of {} remaining to be withdrawn",
                        remaining_balance
                    )
                        .as_bytes(),
                );
                if self.get_account_balance().0 == 0 {
                    env::log(b"The withdrawal is completed: no more balance can be withdrawn in a future call");
                }
            } else {
                self.foundation_account_id = None;
                self.vesting_information = VestingInformation::None;
                env::log(b"Vesting schedule termination and withdrawal are completed");
            }
        } else {
            self.set_termination_status(TerminationStatus::ReadyToWithdraw);
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} failed",
                    amount.0, receiver_id,
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
    }
