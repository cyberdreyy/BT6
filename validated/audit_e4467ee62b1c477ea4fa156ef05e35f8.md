### Title
Unquoted heredoc delimiter in `DotEnvVariables` lets attacker-controlled variable values execute as shell commands - (File: shells/bash.go)

### Summary
`BashWriter.DotEnvVariables` writes a map of variable name/value pairs into a temp file using an **unquoted** heredoc (`cat << EOF ... EOF`), while the accompanying escaping helper `helpers.DotEnvEscape` only escapes backslashes, double quotes, and newlines — it never escapes `$` or backticks. Because the heredoc delimiter is not quoted (it is `<<EOF`, not `<<'EOF'`), bash performs parameter expansion, command substitution, and backtick substitution on the heredoc body when the generated script runs, turning attacker-controlled variable *values* (data that is supposed to stay literal) into executable shell syntax.

The replacer escapes `\`, `"`, `\n`, and `\r`, but leaves `$` and `` ` `` completely untouched. Because the heredoc is started with `cat << EOF` (no quotes around `EOF`), bash treats the body as subject to normal expansion rules: `$(...)`, `` `...` ``, and `$VAR` are all expanded/executed at the moment the enclosing script line runs (i.e., during script generation/execution by the runner-invoked shell), not merely written as literal text into the resulting dotenv file.

This directly violates the stated invariant that "runner-generated shell commands, env files, temp paths, and cleanup paths must treat attacker text as data, not executable syntax." Any code path that populates the `variables` map passed to `DotEnvVariables` with attacker-influenced strings (for example, values sourced from a job's dotenv report artifact, which GitLab CI explicitly allows a pipeline author to populate with arbitrary key=value content via `artifacts:reports:dotenv`) will have those values evaluated for command substitution the moment this fragment executes, rather than being written verbatim to the file as the function's contract implies.

Other quoting choices in the same file were reviewed and are not similarly flawed: `Command`/`Variable`/`ExportRaw`/`SourceEnv` all route values through `b.escape` (either `ShellEscape` or `PosixShellEscape`), both of which correctly quote/escape `$`, backticks, and other shell metacharacters. `DotEnvVariables` is the outlier because it uses a bespoke escaper (`DotEnvEscape`) intended for godotenv-file syntax, not shell syntax, while embedding the result inside a live, unquoted shell heredoc.

### Impact Explanation
If an attacker (a normal pipeline author) can influence any value that ends up in the `variables` map fed to `DotEnvVariables` — e.g., through a dotenv-format artifact/report whose content the job controls — they can inject `$(...)`/backtick command substitutions that execute in the context of the runner-generated script at the point the heredoc is written. Depending on where in the pipeline this fragment is emitted (e.g., while preparing environment for a later, potentially more trusted stage or job), this can amount to command execution in a stronger context than the originating job's own build stage, matching the "stronger-context command execution" impact class.

### Likelihood Explanation
The flaw itself is deterministic and always reachable whenever `DotEnvVariables` is invoked with any value containing `$(`, backticks, or `$VARNAME` — no race conditions or timing issues are needed. Exploitability hinges on whether a pipeline author can control input to the `variables` map (e.g. via dotenv report artifacts, which is a standard, unprivileged GitLab CI feature). Given the ubiquity of dotenv-report variable injection into downstream jobs, this is realistically triggerable by any unprivileged pipeline author who defines a `.gitlab-ci.yml` job producing a dotenv artifact with a value like `FOO=$(malicious-command)`.

### Recommendation
Quote the heredoc delimiter (`cat << 'EOF'` instead of `cat << EOF`) so the shell treats the body as a completely literal block with no expansion, matching how `ShellEscape`/`PosixShellEscape` are used elsewhere in this file. Alternatively, replace the heredoc approach with the same `printf '%s' ... > file` + `b.escape(...)` pattern already used in `Variable()` for file-backed variables, ensuring `$`, backticks, and other shell metacharacters are neutralized consistently with the rest of `BashWriter`.

### Proof of Concept
Go unit test targeting `BashWriter.DotEnvVariables` (or an integration test that runs the generated script through `bash`):

```go
func TestDotEnvVariables_NoCommandSubstitution(t *testing.T) {
    build := &common.Build{ /* minimal build fixture */ }
    w := NewBashWriter(build, "bash")

    vars := map[string]string{
        "MALICIOUS": "$(touch /tmp/pwned)",
    }
    dotEnvFile := w.DotEnvVariables("test.env", vars)

    script := w.Finish(false)

    // Execute the generated script and assert /tmp/pwned was NOT created,
    // and that the resulting dotenv file contains the literal string
    // "$(touch /tmp/pwned)" rather than an empty command-substitution result.
    cmd := exec.Command("bash", "-c", script)
    require.NoError(t, cmd.Run())

    _, err := os.Stat("/tmp/pwned")
    assert.True(t, os.IsNotExist(err), "command substitution executed — heredoc was not literal")

    content, _ := os.ReadFile(dotEnvFile)
    assert.Contains(t, string(content), `$(touch /tmp/pwned)`)
}
```
Expected result on the current code: `/tmp/pwned` is created (proving command execution), demonstrating the vulnerability. After applying the quoted-heredoc fix, the file should be unmodified and the literal string preserved.

func (b *BashWriter) DotEnvVariables(baseFilename string, variables map[string]string) string {
	dotEnvFile := b.TmpFile(baseFilename)

	var sb strings.Builder
	fmt.Fprintf(&sb, "cat << EOF > %s\n", dotEnvFile)
	sb.WriteString(helpers.DotEnvEscape(variables))
	sb.WriteString("EOF\n")

	b.Line(sb.String())

	return dotEnvFile
}

func DotEnvEscape(variables map[string]string) string {
	var sb strings.Builder

	// Sort variables to get deterministic output
	keys := make([]string, 0, len(variables))
	for key := range variables {
		keys = append(keys, key)
	}
	sort.Strings(keys)

	for _, key := range keys {
		if !isValidDotEnvKey(key) {
			// Skip invalid keys
			continue
		}

		value := variables[key]
		fmt.Fprintf(&sb, "%s=\"%s\"\n", key, escapeDotEnvValue(value))
	}

	return sb.String()
}
