### Title
Malformed short `parameters` in `createDstEscrow` bricks both private and public withdraw, letting a malicious taker permanently deny the maker's destination payout - (File: `contracts/EscrowDst.sol`, `contracts/BaseEscrowFactory.sol`, `contracts/libraries/ImmutablesLib.sol`)

### Summary
`createDstEscrow` accepts `dstImmutables` fully from `msg.sender` (the taker/resolver) with no validation on the `parameters` field's length or content [3](#0-2) . `EscrowDst._withdraw`, used by both `withdraw()` (private) and `publicWithdraw()` (public), unconditionally calls `immutables.integratorFeeAmountCd()` and `immutables.protocolFeeAmountCd()` [4](#0-3) , which revert with `IndexOutOfRange()` if `parameters.length` is under `0x40`/`0x20` bytes [5](#0-4) . Since the escrow's CREATE2 salt is `hashMem(immutables)` (including `parameters`) [6](#0-5) , every subsequent call must resupply the exact same short `parameters` to pass `onlyValidImmutables`, so the revert is deterministic and unavoidable for both the private taker path and the public access-token-holder path.

### Finding Description
A taker calling `createDstEscrow` can set `dstImmutables.parameters` to any bytes value, e.g. a 32-byte blob containing only a fake `protocolFeeAmount` word, or even empty bytes. The factory only validates `msg.value`/token transfer amounts, not `parameters` structure [7](#0-6) . Because `_withdraw` is shared by both `withdraw` and `publicWithdraw`, decoding failure blocks both the private-taker path and the public any-access-token-holder path identically [8](#0-7) . The only remaining exits are `cancel()` and `rescueFunds()`, both of which pay out to `immutables.taker` — i.e., back to the same party who deployed the malformed escrow — not to the maker [2](#0-1) [1](#0-0) .

This lets a malicious taker fund a destination escrow that looks correctly collateralized (balance checks pass), induce the maker to reveal the secret (or let the secret leak via the source-side withdrawal), and then never let the maker collect the destination tokens: the fee-decoding revert blocks withdrawal permanently for that fixed immutables tuple, and after the cancellation timelock the taker reclaims the deposited destination-side funds via `cancel()`.

### Impact Explanation
This produces at minimum a temporary freeze of the maker's expected destination payout for the entire withdrawal window (private + public), and functionally allows the taker to redirect the escrowed destination funds back to themselves via `cancel()` once the secret has already been used/exposed on the source chain — meeting the "Temporary freezing of funds" / potential fund-theft impact bar described for this bounty, without requiring any admin, governance, or whitelisted-resolver privilege: `createDstEscrow` has no access control tying `msg.sender` to a privileged role.

### Likelihood Explanation
Trivial to trigger: any address funding `createDstEscrow` fully controls the `parameters` bytes and can simply supply fewer than 64/32 bytes. No special timing, race condition, or privileged capability is required — only intent by the depositing taker.

### Recommendation
Validate `dstImmutables.parameters.length` (e.g., require exactly `0x80` bytes, or the packed layout expected by `ImmutablesLib`) inside `createDstEscrow` before deploying the clone, and/or make `_withdraw` degrade gracefully (treat missing/short fee fields as zero fees) instead of reverting, so a malformed `parameters` blob cannot brick both withdrawal paths.

### Proof of Concept
1. Attacker (taker) calls `createDstEscrow` with `dstImmutables.parameters = abi.encode(uint256(x))` (32 bytes only), matching `msg.value`/token transfer to the required `amount + safetyDeposit`.
2. Escrow deploys successfully; balance checks in `createDstEscrow` pass since they only check raw amounts, not `parameters` content [3](#0-2) .
3. After `DstWithdrawal` timelock, taker or maker calls `withdraw(secret, immutables)` → reverts `IndexOutOfRange()` in `integratorFeeAmountCd` [9](#0-8) .
4. After `DstPublicWithdrawal` timelock, any access-token holder calls `publicWithdraw(secret, immutables)` → same revert, since it calls the same `_withdraw` internal function [10](#0-9) .
5. After `DstCancellation` timelock, only `immutables.taker` can call `cancel()`, reclaiming `immutables.amount` and the safety deposit for themselves — the maker never receives the destination funds [2](#0-1) .

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;

        }
