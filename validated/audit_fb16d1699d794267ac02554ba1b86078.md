## Analysis

The FortaStaking bug reduces to a single invariant: **an unprivileged, self-directed account-state change taken before interacting with the protocol should never permanently trap value that the protocol later tries to push to that account (or to co-participants sharing the same accounting flow).** I looked at `stake`, `delegation_pool`, `staking_contract`, and `vesting` for a case where a mandatory push-payment inside a shared accounting loop can be made to abort forever by one participant's own account configuration.

`aptos_framework::vesting::distribute` iterates over **every** shareholder of a `VestingContract` and pushes their share via `aptos_account::deposit_coins`: [1](#0-0) 

`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient account already exists, is not yet registered for the coin, and has opted out of unsolicited transfers: [2](#0-1) 

Any account can flip that opt-out flag on itself, fully unprivileged, at any time: [3](#0-2) 

Because `distribute()` loops over **all** shareholders in one atomic transaction and aborts entirely if any single `deposit_coins` call fails, one shareholder who (a) has an existing account, (b) has never registered a CoinStore<AptosCoin>, and (c) calls `set_allow_direct_coin_transfers(false)` on themselves, permanently blocks distribution for **every other shareholder** of that vesting contract — this is the same class of bug as the ERC1155 “soft-stuck” report: a self-inflicted, pre-interaction account state that silently passes at some point but permanently breaks a later mandatory transfer step, except here it also traps funds belonging to *other, uninvolved* parties.

This also blocks `terminate_vesting_contract`, which calls `distribute()` unconditionally before running its own termination logic, so even the admin cannot terminate/recover the pool: [4](#0-3) 

I did not find an equivalent unbounded-loop-over-shareholders push-payment pattern in `staking_contract.move` (its `distribution_pool` only ever has at most staker + operator as recipients per pool, so a self-DoS there only affects that one participant, not third parties) or in `delegation_pool.move` (withdrawals there are pull-based via `withdraw`, not a push loop over all delegators), so `vesting.move::distribute` is the strongest analog found with a genuinely different-account impact.

### Title
Unprivileged shareholder can permanently block fund distribution for all co-shareholders of a vesting contract - (File: aptos-move/framework/aptos-framework/sources/vesting.move)

### Summary
`vesting::distribute` pays out every shareholder of a `VestingContract` in a single atomic loop using `aptos_account::deposit_coins`. If a shareholder's account exists but is not yet registered for `AptosCoin` and has direct coin transfers disabled (a fully self-service, unprivileged setting), the deposit to that shareholder aborts, which reverts the entire `distribute()` call and therefore blocks distribution to **all** other shareholders sharing that vesting contract, indefinitely.

### Finding Description
`distribute()` fetches all shareholders of the `grant_pool` and, in one loop, calls `aptos_account::deposit_coins` for each recipient's share: [5](#0-4) 

`aptos_account::deposit_coins` will `assert!(can_receive_direct_coin_transfers(to), ...)` whenever the target account exists but has not registered a `CoinStore<CoinType>`: [6](#0-5) 

`can_receive_direct_coin_transfers` is controlled purely by the target account itself via `set_allow_direct_coin_transfers`, which is an unrestricted, unprivileged entry function callable by any signer on their own account: [3](#0-2) 

Any shareholder (or a beneficiary address set for them) who has an account but has never received/registered `AptosCoin`, and who calls `set_allow_direct_coin_transfers(signer, false)`, will cause `deposit_coins` to abort the moment `distribute()` tries to pay them. Since Move aborts revert the whole transaction, this also reverts the payouts already computed for every *other* shareholder in the `grant_pool`, because they are all processed inside the same `for_each_ref` loop before any funds are actually transferred out for the batch.

Because `terminate_vesting_contract` unconditionally calls `distribute()` before its own logic runs, this also prevents the admin from ever terminating the contract and recovering the remaining grant to the withdrawal address: [7](#0-6) 

### Impact Explanation
This permanently locks vested/reward funds belonging to *other, innocent* shareholders in the same vesting contract — not just the account that made the configuration change. It also removes the admin's ability to terminate the contract and sweep funds to the withdrawal address, since `terminate_vesting_contract` itself calls the broken `distribute()`. This matches the "Permanent lock or non-recoverable loss of claim rights ... in vesting flows" impact category, and affects value belonging to accounts other than the one that triggered the condition — a high-severity, unprivileged griefing vector on shared vesting pools.

### Likelihood Explanation
Triggering the precondition requires no special privilege: any of the vesting contract's own shareholders (whose accounts already exist on-chain but haven't registered `AptosCoin`, e.g., accounts created for governance/other purposes) can call the public `set_allow_direct_coin_transfers` entry function on themselves at any time before their first vesting distribution. Multi-shareholder vesting contracts (as explicitly supported and tested, e.g. `create_vesting_contract` with multiple shareholders) are the normal, intended usage pattern for Aptos-Labs/foundation-style vesting.

### Recommendation
In `distribute()`, isolate each shareholder's payout so a single failing recipient cannot revert payouts to others — e.g., wrap each `aptos_account::deposit_coins` call so failures are caught/skipped (leaving that shareholder's share pending) rather than aborting the whole loop, or pre-validate that all recipients can accept the transfer before committing to distribute, or fall back to a pull-based withdrawal per shareholder instead of a push loop.

### Proof of Concept
1. Admin creates a vesting contract with shareholders `A` and `B` via `create_vesting_contract`.
2. Shareholder `A`'s account exists (e.g., created earlier for an unrelated reason) but has never registered `CoinStore<AptosCoin>`.
3. `A` calls `aptos_account::set_allow_direct_coin_transfers(A_signer, false)` — a fully permissionless action on `A`'s own account. [8](#0-7) 
4. Time passes; `vest(contract_address)` unlocks vested stake for both `A` and `B`.
5. Anyone calls `distribute(contract_address)`. The loop reaches `A`'s payout, `aptos_account::deposit_coins` asserts `can_receive_direct_coin_transfers(A) == false` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. [1](#0-0) 
6. The whole `distribute()` transaction reverts, so `B`'s already-vested and computed share is never paid either. Every future call to `distribute()` (and `terminate_vesting_contract()`, which calls `distribute()` first) fails identically, permanently freezing both `A`'s and `B`'s funds in the vesting contract.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };
