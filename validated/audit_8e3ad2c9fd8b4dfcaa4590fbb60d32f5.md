### Title
Non-constant-time token comparison in `Session.withAuthorization` enables timing side-channel attack on session tokens - (File: session/session.go)

### Summary
`Session.withAuthorization` authenticates session requests using the Go `!=` string comparison operator instead of a constant-time comparison. Because Go's native string inequality check short-circuits on the first mismatching byte, an attacker who can send repeated HTTP requests to a session endpoint can use response-timing differences to incrementally recover the session `Token` byte-by-byte, bypassing the intended random-token authorization scheme.

### Finding Description
`withAuthorization` performs the authorization check as: [1](#0-0) 

`s.Token != r.Header.Get("Authorization")` uses Go's built-in string comparison, which compares bytes sequentially and returns as soon as a mismatch is found. This creates a data-dependent timing signal correlated with how many leading bytes of the attacker-supplied header match the real `Token`.

The session server is reachable over the network: it is started by `RunCommand.setupSessionServer` and bound to `config.SessionServer.ListenAddress` (e.g. `[::]:8093`), which per the runner's own documentation is a network-facing endpoint that GitLab (and, depending on network topology/firewalling, potentially other network-adjacent parties) connects to. [2](#0-1) 

The routes protected by this check — `proxyHandler` (arbitrary access to any registered service proxy for that job) and `execHandler` (interactive terminal/exec access to the job's container) — are registered behind `withAuthorization`: [3](#0-2) 

The `Token` is a 32-character random value generated once per session via `generateToken`/`helpers.GenerateRandomUUID(32)`: [4](#0-3) 

There is no `crypto/subtle.ConstantTimeCompare` (or equivalent HMAC-based comparison) anywhere in the session package, so the mismatch-timing leak is unmitigated. An attacker who can reach the session's `Endpoint` (a per-session, guessable-format URL of the form `/session/<uuid>`) and send crafted `Authorization` header values many times can, in principle, use statistical timing analysis to determine correct-byte-prefix length and progressively brute-force the token faster than pure random guessing over the 32-byte keyspace, since each byte position can be validated independently.

### Impact Explanation
If successfully exploited, an attacker recovers a valid session `Token` for a job they do not own and can then call the unauthenticated-to-them `proxyHandler` (reach the job's service containers) or `execHandler` (open an interactive terminal into another user's/project's build container) — impersonating a session that isn't theirs, in violation of the invariant that "Job, session, trace, and backend auth state must not let one job impersonate another."

### Likelihood Explanation
Exploitability is constrained by real-world factors: the session server listens on TLS (self-signed cert generated by `certificate.X509Generator`), each session normally lives only for the duration of a job plus `session_timeout` (default 1800s), and network timing side-channels are noisy and typically require large numbers of samples/statistical averaging to extract a reliable signal, especially over anything but a very low-latency/low-jitter LAN path. The `Endpoint` also needs to be known to the attacker, which requires it to leak outside of the encrypted GitLab-to-Runner channel that normally carries it. These factors make this a real but non-trivial-to-exploit weakness rather than an easily reproducible remote exploit; it is nonetheless a legitimate defect since the code contains no timing-safe comparison at all for a secret token used to gate command execution.

### Recommendation
Replace the direct string comparison with a constant-time comparison, e.g.:
```go
import "crypto/subtle"

if subtle.ConstantTimeCompare([]byte(s.Token), []byte(r.Header.Get("Authorization"))) != 1 {
    ...
}
```
Additionally consider using an HMAC-based comparison (compare hashes of the token rather than raw bytes) to further reduce any residual timing signal, and ensure token length is normalized before comparison to avoid length-based side channels.

### Proof of Concept
Go unit test sketch (session/session_test.go):
```go
func TestWithAuthorization_TimingSafety(t *testing.T) {
    sess, _ := NewSession(nil)
    handlerCalled := false
    h := sess.withAuthorization(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        handlerCalled = true
    }))

    req := httptest.NewRequest("GET", sess.Endpoint+"/exec", nil)
    req.Header.Set("Authorization", "wrong-token-of-same-length")
    rr := httptest.NewRecorder()
    h.ServeHTTP(rr, req)

    assert.False(t, handlerCalled)
    assert.Equal(t, http.StatusUnauthorized, rr.Code)
    // Assertion for the actual bug: measure comparison uses subtle.ConstantTimeCompare
    // by statically checking session.go no longer uses `!=` on secret token,
    // or by benchmarking response latency distributions for prefix-matching vs
    // non-matching tokens of equal length and confirming no statistically
    // significant timing difference (t-test on sampled latencies).
}
```
A full PoC would run a benchmark client sending thousands of requests with tokens sharing increasing correct-byte prefixes against a local (loopback, to minimize network jitter) instance of the session server, and use a statistical test (e.g., Welch's t-test) on response latencies to show a detectable correlation between prefix-match length and timing — confirming the comparison is not constant-time.

		return
	}

	// Create a wrapper function that handles the error from findSessionByURL
	findSessionWrapper := func(url string) *session.Session {
		sess, err := mr.buildsHelper.findSessionByURL(url)
		if err != nil {
			mr.log().WithError(err).WithField("url", url).Warn("Failed to find session by URL")
			return nil
		}
		return sess
	}

	var err error
	mr.sessionServer, err = session.NewServer(

			ListenAddress:    config.SessionServer.ListenAddress,
			ShutdownTimeout:  config.GetShutdownTimeout(),
		},
		mr.log(),
		certificate.X509Generator{},
		findSessionWrapper,
	)
	if err != nil {
		mr.log().WithError(err).Fatal("Failed to create session server")
	}
