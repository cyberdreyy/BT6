### Title
Unbounded copy-out of the SPL-token secondary index lets any account creator make `getTokenAccountsByOwner`/`getProgramAccounts` (indexed path) prohibitively expensive for a victim owner - (File: accounts-db/src/accounts_index/secondary.rs)

### Summary
The `StrategyRegistry` bug let anyone push cheap entries into an array keyed by an arbitrary victim wallet, which was later copied wholesale from storage to memory on the victim's legitimate call. The equivalent pattern exists in Agave's SPL-token secondary index: any unprivileged account creator can insert entries keyed by an **arbitrary owner/mint pubkey** they do not control, and a later single JSON-RPC read for that pubkey copies the entire, attacker-inflated key set out of the index in one unbounded operation before any size limiting is applied.

### Finding Description
When the validator is run with the `SplTokenOwner` (or `ProgramId`/`SplTokenMint`) secondary index enabled, `AccountsIndex::update_secondary_indexes` inserts a mapping from the token account's `owner` field (attacker-controlled account data, not the creator's identity) into the shared `SecondaryIndex`: [1](#0-0) 

The insertion path itself, `SecondaryIndex::insert`, has no cap on the number of inner keys that can accumulate under one outer key: [2](#0-1) 

Because the indexed value (`owner` for `SplTokenOwner`, or `program_id` for `ProgramId`) is attacker-supplied account data, any address can create large numbers of token accounts whose `owner` field is set to a victim pubkey the attacker does not control — analogous to `deploySpareSubAccount(address _wallet)` letting anyone allocate subaccounts under someone else's wallet.

When any client later performs a legitimate read for that owner (e.g. `getTokenAccountsByOwner`), the RPC path resolves to `get_filtered_indexed_accounts` → `Bank::get_filtered_indexed_accounts` → `AccountsDb::index_scan_accounts`: [3](#0-2) 

The critical step is `self.accounts_index.get_index_key_pubkeys(&index_key)`, which fully materializes the associated key set into a new `Vec<Pubkey>` in one shot: [4](#0-3) [5](#0-4) 

`SecondaryIndexEntry::keys()` (used by `RwLockSecondaryIndexEntry`) copies the *entire* `HashSet<Pubkey>` for that key out to a `Vec` before any filtering, byte-limit, or `do_load` occurs: [6](#0-5) 

After this unbounded copy, `index_scan_accounts` iterates every returned pubkey and performs a full `do_load` (an account-data load) for each one — with no early exit tied to the byte-size limit that later paths (`get_filtered_indexed_accounts` in `rpc.rs`) intend to enforce; the byte limit is only checked while accumulating already-loaded accounts, not before the enumeration/loading step itself: [7](#0-6) [8](#0-7) 

This mirrors the reported bug exactly: an unprivileged actor fills a collection keyed by someone else's identity at low, refundable cost (rent-exempt token accounts can later be closed to recover most lamports), and a single, ordinary call by/about the victim then forces an unbounded copy-and-load of that entire collection.

### Impact Explanation
A validator running with `--account-index spl-token-owner` (or `program-id`) is exposed to a single low-rate RPC call (`getTokenAccountsByOwner`/indexed `getProgramAccounts`) becoming disproportionately expensive: the `Vec<Pubkey>` allocation and subsequent full per-pubkey `do_load` scale linearly with the number of junk accounts an attacker planted under the victim's key, with no cap. This can degrade or stall the RPC-serving thread pool for a single request, which is within scope as "unbounded cost for a single low-rate call" against an unprivileged JSON-RPC handler / account-decoding read path.

### Likelihood Explanation
Requires the operator to have enabled a secondary account index (`SplTokenOwner`, `SplTokenMint`, or `ProgramId`) — a supported, documented configuration, not a bootstrap-only or mocked scenario. Creating many token accounts with an arbitrary `owner` field is a normal, permissionless SPL Token operation requiring only rent-exempt lamports (recoverable). No special privilege or multi-validator coordination is needed; a single victim-facing RPC call triggers the unbounded work.

### Recommendation
Bound the cost of `SecondaryIndex::get`/`keys()` and the subsequent scan: enforce `byte_limit_for_scans` (or a max-entries cap) at the point the reverse-index key list is materialized in `get_index_key_pubkeys`, rather than only after loading accounts; alternatively, cap the number of inner keys tracked per outer key (mirroring the suggested "cap spare items at a reasonable number" mitigation from the reported bug) and/or reject/paginate secondary-index scans whose candidate key count exceeds a configurable threshold before performing any `do_load` calls.

### Proof of Concept
1. Start a validator/test-validator with `--account-index spl-token-owner`.
2. As an unprivileged actor, repeatedly create SPL Token accounts, setting the `owner` field of each account's data to a fixed victim pubkey `V` (no signature from `V` is required to set this field; it's account data written by the token program at creation).
3. Each creation calls `AccountsIndex::update_secondary_indexes` → `SecondaryIndex::insert(V, new_token_account_pubkey)`, growing the `HashSet<Pubkey>` behind `V` in `program_id_index`/`spl_token_owner_index` without bound.
4. Any client then calls `getTokenAccountsByOwner(V, ...)`. This resolves to `get_filtered_indexed_accounts` → `index_scan_accounts`, which calls `get_index_key_pubkeys(&IndexKey::SplTokenOwner(V))`, copying the full (attacker-inflated) key set to a `Vec<Pubkey>`, then performs `do_load` for every entry before filters/byte-limits reduce the result — demonstrating a single request whose cost scales with attacker-controlled prior state rather than with any per-call limit.

    pub(crate) fn update_secondary_indexes(
        &self,
        pubkey: &Pubkey,
        account: &impl ReadableAccount,
        account_indexes: &AccountSecondaryIndexes,
    ) {
        if account_indexes.is_empty() {
            return;
        }

        let account_owner = account.owner();
        let account_data = account.data();

        if account_indexes.contains(&AccountIndex::ProgramId)
            && account_indexes.include_key(account_owner)
        {
            self.program_id_index.insert(account_owner, pubkey);
        }
        // Note because of the below check below on the account data length, when an
        // account hits zero lamports and is reset to AccountSharedData::Default, then we skip
        // the below updates to the secondary indexes.
        //
        // Skipping means not updating secondary index to mark the account as missing.
        // This doesn't introduce false positives during a scan because the caller to scan
        // provides the ancestors to check. So even if a zero-lamport account is not yet
        // removed from the secondary index, the scan function will:
        // 1) consult the primary index via `get(&pubkey, Some(ancestors), max_root)`
        // and find the zero-lamport version
        // 2) When the fetch from storage occurs, it will return AccountSharedData::Default
        // (as persisted tombstone for snapshots). This will then ultimately be
        // filtered out by post-scan filters, like in `get_filtered_spl_token_accounts_by_owner()`.

        self.update_spl_token_secondary_indexes::<spl_generic_token::token::Account>(
            &spl_generic_token::token::id(),
            pubkey,
            account_owner,
            account_data,
            account_indexes,
        );

    /// Inserts `inner_key` into `key`'s map.
    pub fn insert(&self, key: &Pubkey, inner_key: &Pubkey) {
        // Note: Always lock the reverse index first, so we synchronize with remove().
        // Pre-size to 1 to avoid push() over-allocating an empty Vec to capacity 4.
        let reverse_index_entry = self
            .reverse_index
            .entry(*inner_key)
            .or_insert_with(|| RwLock::new(Vec::with_capacity(1)));
        let mut outer_keys = reverse_index_entry.write().unwrap();

        // Now insert into the index.
        // Note, we do this get()-then-unwrap instead of calling entry() directly, because
        // get() is a read lock whereas entry() is a write lock.  We assume `key` already has
        // a map created, so optimize for the common case and only take a read lock.
        self.index
            .get(key)
            .unwrap_or_else(|| self.index.entry(*key).or_default().downgrade())
            .insert_if_not_exists(inner_key, &self.stats.num_inner_keys);

        if !outer_keys.contains(key) {
            outer_keys.push(*key);
        }

        // explicitly drop the locks so we don't hold them while reporting metrics
        drop(outer_keys);
        drop(reverse_index_entry);

        if self.stats.last_report.should_update(1000) {
            datapoint_info!(
                self.metrics_name,
                ("num_secondary_keys", self.index.len(), i64),
                (
                    "num_inner_keys",
                    self.stats.num_inner_keys.load(Ordering::Relaxed),
                    i64
                ),
                ("num_reverse_index_keys", self.reverse_index.len(), i64),
            );
        }
    }

    pub(crate) fn index_scan_accounts<F>(
        &self,
        ancestors: &Ancestors,
        bank_id: BankId,
        index_key: IndexKey,
        mut scan_func: F,
        config: &ScanConfig,
    ) -> ScanResult<bool>
    where
        F: FnMut(Option<(&Pubkey, AccountSharedData, Slot)>),
    {
        let key = match &index_key {
            IndexKey::ProgramId(key) => key,
            IndexKey::SplTokenMint(key) => key,
            IndexKey::SplTokenOwner(key) => key,
        };
        if !self.account_indexes.include_key(key) {
            // the requested key was not indexed in the secondary index, so do a normal scan
            let used_index = false;
            self.scan_accounts(ancestors, bank_id, scan_func, config)?;
            return Ok(used_index);
        }

        // Register this scan so that slots needed by the scan are not cleaned out from under us.
        let scan_guard = ScanGuard::try_new(&self.scan_tracker, bank_id, || self.max_root())
            .ok_or(ScanError::SlotRemoved {
                slot: ancestors.max_slot(),
                bank_id,
            })?;

        // If the scan's ancestors are all rooted, drop them and scan roots only
        // Scan Guard max root must be used as the scan guard guarantees that
        // the account state as of max root is persisted in the database
        let max_root_ancestors = Ancestors::from(vec![scan_guard.max_root()]);
        let ancestors = if scan_guard.should_use_ancestors(ancestors) {
            ancestors
        } else {
            &max_root_ancestors
        };

        for pubkey in self.accounts_index.get_index_key_pubkeys(&index_key) {
            if config.is_aborted() {
                break;
            }
            if let Some((account, slot)) = self.do_load(
                ancestors,
                &pubkey,
                LoadHint::Unspecified,
                PopulateReadCache::False,
            ) {
                scan_func(Some((&pubkey, account, slot)));
            }
        }

    pub async fn get_filtered_indexed_accounts(
        &self,
        bank: &Arc<Bank>,
        index_key: &IndexKey,
        program_id: &Pubkey,
        filters: Vec<RpcFilterType>,
        sort_results: bool,
    ) -> ScanResult<Vec<KeyedAccountSharedData>> {
        let bank = Arc::clone(bank);
        let index_key = index_key.to_owned();
        let program_id = program_id.to_owned();
        let byte_limit_for_scans = self.config.scan_results_limit_bytes;
        let mut accounts = self
            .runtime
            .spawn_blocking(move || {
                bank.get_filtered_indexed_accounts(
                    &index_key,
                    |account| {
                        // The program-id account index checks for Account owner on inclusion.
                        // However, due to the current AccountsDb implementation, an account may
                        // remain in storage as a zero-lamport AccountSharedData::Default() after
                        // being wiped and reinitialized in later updates. We include the redundant
                        // filters here to avoid returning these accounts.
                        account.owner().eq(&program_id)
                            && filters
                                .iter()
                                .all(|filter_type| filter_allows(filter_type, account))
                    },
                    byte_limit_for_scans,
                )
            })
            .await
            .expect("Failed to spawn blocking task")?;
        if sort_results {
            // Avoid copying pubkeys (using Ord::cmp(a, b) silences clippy::unnecessary_sort_by).
            accounts.sort_unstable_by(|(addr_a, _), (addr_b, _)| Ord::cmp(addr_a, addr_b));
        }
        Ok(accounts)
    }
