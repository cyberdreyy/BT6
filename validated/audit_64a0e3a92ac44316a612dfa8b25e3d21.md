### Title
Stale confirmations from removed multisig members still count toward `num_confirmations`, allowing execution below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm()` counts entries in the `confirmations` `HashSet` for a request without verifying that each entry still belongs to a current member. `delete_member()` only purges requests *authored* by the removed member; it does not purge that member's *confirmation* entries left behind on other pending requests. Consequently, a request can execute with fewer live-member approvals than `num_confirmations` requires, exactly the "confirmations counted vs. live members" custody-binding failure described by the bug-class hint (analogous to the analog report's "value taken vs. value actually available/entitled").

### Finding Description
`confirm()` only checks the *size* of the confirmations set against `self.num_confirmations`, and only validates that the *caller* of `confirm()` is a current member — it never re-validates the members recorded in the existing `confirmations` set: [1](#0-0) 

`delete_member()` removes the deleted member from `self.members` and deletes only the *requests the member itself created*; it does not scan `self.confirmations` to strip the member's prior confirmations from other still-pending requests: [2](#0-1) 

Sequence:
1. Multisig has members `A, B, C` with `num_confirmations = 2`.
2. `A` creates request `R1` (e.g., a `Transfer`). `B` calls `confirm(R1)`; since `confirmations.len()+1 = 1 < 2`, `B`'s public identity is stored in `confirmations[R1] = {B}` [3](#0-2) .
3. Separately (via a different, legitimately-approved `DeleteMember{B}` request), `B` is removed from `self.members`. `delete_member()` only removes requests where `r.member == B` (i.e., requests *B authored*) — `R1` was authored by `A`, so its confirmations set `{B}` is left untouched [4](#0-3) .
4. `C` calls `confirm(R1)`. `confirmations.len() as u32 + 1 == 2 >= num_confirmations`, so `R1` executes via `execute_request()` [5](#0-4) .

At execution time, only one *live* member (`C`) actually approved `R1`; `B`'s stale confirmation — from an account no longer a member — is what pushed the count to the threshold. The equality that should hold, `confirmations counted == live members who approved`, is broken: `R1` executes with 1 live approval against a nominal 2-of-N policy.

### Impact Explanation
This directly matches the Critical impact category "a multisig request executed below threshold." Any pending request that has already collected one or more confirmations before one of those confirmers is removed becomes executable with strictly fewer live approvals than configured, undermining the entire K-of-N security guarantee of the contract (which can hold and move NEAR, deploy code, add/delete keys, etc. per `MultiSigRequestAction`) [6](#0-5) .

### Likelihood Explanation
Member turnover (adding/removing multisig members/keys) is a normal, expected multisig operation, and pending requests routinely persist across such changes since `add_request`/`confirm` don't require completing in the same block as membership changes. Any combination of "a request has ≥1 confirmation" followed by "one of those confirmers is later removed" reproduces the bug — no privileged or out-of-scope actor beyond ordinary members carrying out documented multisig actions is required.

### Recommendation
When removing a member in `delete_member()`, iterate `self.confirmations` and strip the removed member's entry from every pending request's confirmation set (not just requests it authored), or alternatively re-validate at `confirm()` time (and at threshold-check time) that every recorded confirming identity in the set is still `self.members.contains(...)` before counting it toward `num_confirmations`.

### Proof of Concept
```rust
// members = {A, B, C}, num_confirmations = 2
let mut c = MultiSigContract::new(members(), 2);

// (as A) create R1: Transfer to some receiver
testing_env!(context_with_member(A));
let r1 = c.add_request(transfer_request());

// (as B) confirm R1 -> confirmations[r1] = {B}; 1 < 2, no execution yet
testing_env!(context_with_member(B));
c.confirm(r1);

// (as A, C via separate already-confirmed request) DeleteMember{B} executes,
// removing B from self.members but NOT from confirmations[r1]
testing_env!(context_with_member(A));
let r2 = c.add_request(delete_member_request(B));
testing_env!(context_with_member(C));
c.confirm(r2); // executes DeleteMember{B} (2-of-2 confirmations for r2)

// (as C) confirm R1 -> confirmations[r1].len()+1 == 2 >= 2 -> R1 EXECUTES
// even though B is no longer a member; only C is a live approver.
testing_env!(context_with_member(C));
c.confirm(r1); // Transfer executes with only 1 live confirmation
```

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
