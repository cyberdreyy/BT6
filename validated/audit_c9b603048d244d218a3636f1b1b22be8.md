### Title
Permanent lock of `TreasuryCap` and `UpgradeCap` in `BridgeTreasury.waiting_room` with no withdrawal mechanism — (File: `crates/sui-framework/packages/bridge/sources/treasury.move`)

### Summary

`bridge::bridge::register_foreign_token` is an unrestricted `public fun` that irrevocably deposits a coin creator's `TreasuryCap<T>` and `UpgradeCap` into the bridge's `waiting_room` and `treasuries` bags. No corresponding cancellation or withdrawal function exists anywhere in the bridge package. If bridge governance never issues an `AddTokenOnSui` committee message for that token, the caps are permanently trapped, stripping the coin creator of all supply-management and package-upgrade authority over their coin.

### Finding Description

`bridge::bridge::register_foreign_token` is declared `public fun` with no caller restriction:

```move
public fun register_foreign_token<T>(
    bridge: &mut Bridge,
    tc: TreasuryCap<T>,
    uc: UpgradeCap,
    metadata: &CoinMetadata<T>,
) {
    load_inner_mut(bridge).treasury.register_foreign_token<T>(tc, uc, metadata)
}
``` [1](#0-0) 

Inside `treasury::register_foreign_token`, the two caps are consumed and stored in the bridge's internal bags:

```move
self.waiting_room.add(type_name::into_string(type_name), registration); // holds UpgradeCap
self.treasuries.add(type_name, tc);                                      // holds TreasuryCap
``` [2](#0-1) 

The only path that ever removes an entry from `waiting_room` is `add_new_token`, which is `public(package)` and reachable only through `execute_system_message` — a path that requires a quorum of bridge-committee ECDSA signatures: [3](#0-2) 

There is no `cancel_registration`, `withdraw_registration`, or any other function that returns the caps to the registrant. The entire `BridgeTreasury` struct exposes no removal path for `waiting_room` or `treasuries` entries: [4](#0-3) 

### Impact Explanation

A coin creator who calls `register_foreign_token` and is subsequently ignored by governance (token rejected, governance inactive, or committee quorum never reached) suffers:

1. **Permanent loss of `TreasuryCap<T>`** — the sole object authorising `coin::mint` and `coin::burn` for that coin type. The coin's supply is frozen forever.
2. **Permanent loss of `UpgradeCap`** — the sole object authorising package upgrades. The coin package can never be patched or upgraded.
3. **No recourse** — because `BridgeTreasury` has no withdrawal function and the `Bridge` shared object is not upgradeable by the registrant, the state is irreversible without a bridge-package upgrade signed by the bridge committee.

This constitutes harmful smart-contract behaviour and a permanent lock of capability objects reachable from public input, matching the Medium/High tier of the allowed impact gate.

### Likelihood Explanation

- `register_foreign_token` is `public fun` — any ordinary SUI holder who owns a freshly minted coin's `TreasuryCap` and `UpgradeCap` can trigger this.
- The bridge primer confirms the design: governance approval is a separate, asynchronous step that may never arrive.
- The `waiting_room` bag has no size limit and no expiry, so stale registrations accumulate indefinitely.
- The `FIXME` comment in the source (`// FIXME: add test`) signals the registration path is under-tested, increasing the chance the missing withdrawal was overlooked. [5](#0-4) 

### Recommendation

Add a `cancel_registration<T>` function (callable only by the original registrant, verified via `TxContext::sender` matched against a stored registrant address in `ForeignTokenRegistration`) that:

1. Removes the `ForeignTokenRegistration` from `waiting_room`.
2. Removes the `TreasuryCap<T>` from `treasuries`.
3. Returns both objects to the caller.
4. Emits a `TokenRegistrationCancelledEvent`.

Alternatively, store the registrant address in `ForeignTokenRegistration` at registration time and enforce that only that address can cancel, preventing griefing.

### Proof of Concept

```
// Step 1 — Attacker/coin-creator publishes a coin package and obtains TreasuryCap + UpgradeCap.
// Step 2 — Calls the unrestricted public entry:
sui client ptb \
  --move-call 0xb::bridge::register_foreign_token<MY_PKG::my_coin::MY_COIN> \
      @<BRIDGE_SHARED_ID> \
      @<TREASURY_CAP_ID> \
      @<UPGRADE_CAP_ID> \
      @<COIN_METADATA_ID>

// Result: TreasuryCap and UpgradeCap are now inside BridgeTreasury.waiting_room
//         and BridgeTreasury.treasuries respectively.

// Step 3 — Governance never issues AddTokenOnSui for this token.
// Step 4 — Coin creator attempts to mint/burn/upgrade — all fail because
//           the caps are inaccessible inside the bridge shared object.
// No function exists to retrieve them. State is permanently corrupted.
```

The broken invariant: every `TreasuryCap<T>` and `UpgradeCap` deposited into `BridgeTreasury` via `register_foreign_token` must be either promoted to `supported_tokens` (governance path) **or** returnable to the registrant (missing cancellation path). Currently only the first path exists. [6](#0-5) [1](#0-0)

public(package) fun register_foreign_token<T>(
    self: &mut BridgeTreasury,
    tc: TreasuryCap<T>,
    uc: UpgradeCap,
    metadata: &CoinMetadata<T>,
) {
    // Make sure TreasuryCap has not been minted before.
    assert!(coin::total_supply(&tc) == 0, ETokenSupplyNonZero);
    let type_name = type_name::with_defining_ids<T>();
    let address_bytes = hex::decode(ascii::into_bytes(type_name::address_string(&type_name)));
    let coin_address = address::from_bytes(address_bytes);
    // Make sure upgrade cap is for the Coin package
    // FIXME: add test
    assert!(
        object::id_to_address(&package::upgrade_package(&uc)) == coin_address,
        EInvalidUpgradeCap,
    );
    let registration = ForeignTokenRegistration {
        type_name,
        uc,
        decimal: coin::get_decimals(metadata),
    };
    self.waiting_room.add(type_name::into_string(type_name), registration);
    self.treasuries.add(type_name, tc);

    event::emit(TokenRegistrationEvent {
        type_name,
        decimal: coin::get_decimals(metadata),
        native_token: false,
    });
}
