### Title
Stale confirmations from removed multisig members still count toward execution threshold - (File: multisig2/src/lib.rs)

### Summary
`confirm()` in `MultiSigContract` counts confirmations stored in the `confirmations: LookupMap<RequestId, HashSet<String>>` map without verifying that each confirming member is still present in `self.members`. `delete_member()` only removes requests *authored* by the removed member; it does not purge that member's confirmations recorded on requests authored by *other* members. This lets a request execute using a confirmation from an account/key that has since been kicked out of the multisig.

### Finding Description
The binding that should hold is: `confirmations counted at execution == confirmations from currently live members`. This is broken as follows:
- `confirm()` ( [1](#0-0) ) inserts `member.to_string()` into the request's confirmation set and later checks `confirmations.len() as u32 + 1 >= self.num_confirmations` to decide whether to execute, with no re-check against `self.members`.
- `delete_member()` ( [2](#0-1) ) deletes requests where `r.member == member` (the request's *creator*), but never iterates all requests to strip the departing member's entry out of other requests' `confirmations` sets.

Consequently, if member M confirms a request created by member A, and M is subsequently removed via `DeleteMember`, M's confirmation on A's request remains stored and still counts toward `num_confirmations` when the remaining members confirm and trigger `execute_request()` ( [3](#0-2) ).

### Impact Explanation
This can allow a request (e.g., `Transfer`, `AddKey`/full access key, `DeployContract`, `FunctionCall`) to execute with fewer *live* confirmations than the configured threshold `num_confirmations`, effectively moving funds or granting access with authorization below the intended K-of-N threshold. This matches "a multisig request executed below threshold" — a Critical-impact class per the given rules.

### Likelihood Explanation
Requires only: (1) a pending request exists that a member confirmed, (2) that confirming member is later removed via a legitimate `DeleteMember` request (a normal governance action, not requiring compromise), and (3) the request is left pending/confirmed further by remaining members. No privileged access beyond normal multisig membership rotation is required, and membership changes are a routine, expected operation in this contract.

### Recommendation
When executing `delete_member()`, iterate all pending `requests`/`confirmations` and remove the departing member's `to_string()` entry from every confirmation set (not just requests it created), or alternatively re-validate at `confirm()`/`execute_request()` time that every string in the confirmations set still corresponds to a member in `self.members` before counting it toward the threshold.

### Proof of Concept
1. Multisig initialized with members `{A, B, C}` and `num_confirmations = 2`.
2. Member A calls `add_request` to create a `Transfer` request (request_id = 0); not yet confirmed by A implicitly (using `add_request`, no auto-confirm).
3. Member C calls `confirm(0)` — `confirmations = {C}`, size 1 < 2, request stays pending ( [4](#0-3) ).
4. Members confirm a separate `DeleteMember { member: C }` request and it executes, calling `delete_member()`. Since request 0 was created by A (not C), it is not filtered out by `r.member == member` (line 365), so request 0 and its `confirmations = {C}` survive untouched.
5. Member B calls `confirm(0)`. `confirmations.len() + 1 = 2 >= num_confirmations (2)` → `execute_request()` runs the Transfer, even though C is no longer a member and only B is a genuinely live confirming member besides the (uncounted) creator. [1](#0-0) [2](#0-1)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
