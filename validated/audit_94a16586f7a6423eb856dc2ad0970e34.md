Based on the investigation, the strongest local analog to the ERC20 "fail-without-revert" / "batch griefing" bug class is in `vesting.move`'s `distribute()` function, which loops over all shareholders and calls `aptos_account::deposit_coins` for each — a single failing deposit aborts the whole transaction and blocks distributions to every other shareholder.

### Title
Unprivileged shareholder can grief `distribute()` for all other shareholders by opting out of direct coin transfers - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute()` iterates over every shareholder of a vesting contract in a single loop and calls `aptos_account::deposit_coins` for each one's share [1](#0-0) . `aptos_account.move` defines a `DirectTransferConfig` that lets any account holder disable receiving direct/unregistered coin transfers, aborting with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` [2](#0-1) . Because `deposit_coins` is called inside a `for_each_ref` loop with no per-shareholder error isolation, any single shareholder can flip their own transfer-acceptance flag off and cause every `distribute()` call to abort, permanently blocking reward/vested-token withdrawal for all other shareholders in that vesting contract until the misbehaving account is somehow worked around (there is no per-shareholder skip/retry logic).

### Finding Description
`distribute()` is a public, unprivileged entry function (any account can call it) [3](#0-2) . It withdraws all currently-withdrawable stake from the underlying stake pool and then attempts to pay out every shareholder's proportional share in one atomic loop: `shareholders.for_each_ref(|shareholder| { ... aptos_account::deposit_coins(recipient_address, share_of_coins); })` [4](#0-3) .

`set_beneficiary` only validates that a *newly set beneficiary* is registered for APT via `assert_account_is_registered_for_apt` [5](#0-4) , but this check is not re-verified at distribution time, and more importantly it does nothing to prevent a shareholder (or beneficiary) from later disabling direct-transfer acceptance on their own account via `aptos_account::set_allow_direct_coin_transfers`-style toggling of `DirectTransferConfig.allow_arbitrary_coin_transfers` (confirmed present in `aptos_account.move`) [6](#0-5) . If any shareholder's `CoinStore<AptosCoin>` was never explicitly registered and they have opted out of arbitrary/direct transfers, `deposit_coins` to that address aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. Since this call happens mid-loop inside `distribute()`, the abort propagates and reverts the *entire* transaction — including the withdrawal already taken from the stake pool and the payouts to all well-behaved shareholders.

This is the direct structural analog of the ERC20 report's core lesson: unvalidated/unsafe external calls inside a payout loop where one bad/uncooperative party can block payouts to everyone else. Here it's not silent-failure-without-revert (Move aborts are always reverting), but the opposite failure mode with the same effect — an abort inside a shared iteration blocks unrelated, honest shareholders' claim rights indefinitely, since `distribute()` has no per-recipient try/catch or skip mechanism.

### Impact Explanation
Any single shareholder (no elevated privileges required, and they need not even be malicious — merely have disabled direct transfers, e.g. for spam protection reasons) can permanently or semi-permanently deny distribution to every other shareholder of the same vesting contract, freezing already-vested/reward-unlocked funds that are sitting withdrawable in the stake pool. `terminate_vesting_contract` and `admin_withdraw` are also blocked because `terminate_vesting_contract` unconditionally calls `distribute()` first [7](#0-6) , so this griefing also stalls contract termination and admin recovery of remaining grant funds. This is a claim-rights/lockup impact affecting potentially many shareholders' vested/reward balances, which meets the "permanent lock or non-recoverable loss of claim rights in ... vesting flows" bar.

### Likelihood Explanation
Likelihood is high: `set_allow_direct_coin_transfers`-style toggling in `aptos_account.move` is a standard, unprivileged, publicly documented user feature (opt out of unsolicited token transfers), not an attack primitive by itself — meaning it can be triggered accidentally by a legitimate shareholder protecting themselves from spam, or deliberately by a malicious shareholder solely to grief co-shareholders. No special setup, timing, or governance action is required; the shareholder only needs to call the standard opt-out function once.

### Recommendation
Do not let a single recipient's failure in `distribute()` abort the whole batch. Either: (1) wrap each `aptos_account::deposit_coins` call so a failure is caught/skipped and the corresponding share is instead retained/queued for the individual shareholder to claim on their own (pull-payment pattern), or (2) require/verify at `distribute()` time (not just at `set_beneficiary` time) that recipients are registered/opted-in for APT, and if not, route their share to an escrow the shareholder can claim later rather than aborting the transaction for all participants.

1. Admin creates a vesting contract with shareholders A and B via `create_vesting_contract` [8](#0-7) .
2. Shareholder B calls the direct-transfer opt-out function on their own account (standard, unprivileged action) after vesting starts.
3. Time passes; rewards/vested tokens accumulate and become withdrawable via `vest()`/`unlock_rewards()` [9](#0-8) .
4. Anyone calls `distribute(contract_address)`. The loop reaches shareholder B, `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, and the entire transaction (including shareholder A's payout) reverts [10](#0-9) .
5. Shareholder A's funds remain permanently stuck (withdrawable-but-undistributable) until B re-enables direct transfers — which B, as a hostile actor, has no incentive to do.

    /// Unlock any vested portion of the grant.
    public entry fun vest(contract_address: address) acquires VestingContract {
        // Unlock all rewards first, if any.
        unlock_rewards(contract_address);

        // Unlock the vested amount. This amount will become withdrawable when the underlying stake pool's lockup
        // expires.
        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        // Short-circuit if vesting hasn't started yet.
        if (vesting_contract.vesting_schedule.start_timestamp_secs > timestamp::now_seconds()) {
            return
        };

        // Check if the next vested period has already passed. If not, short-circuit since there's nothing to vest.
        let vesting_schedule = &mut vesting_contract.vesting_schedule;
        let last_vested_period = vesting_schedule.last_vested_period;
        let next_period_to_vest = last_vested_period + 1;
        let last_completed_period =
            (timestamp::now_seconds() - vesting_schedule.start_timestamp_secs) / vesting_schedule.period_duration;
        if (last_completed_period < next_period_to_vest) {
            return
        };

        // Calculate how much has vested, excluding rewards.
        // Index is 0-based while period is 1-based so we need to subtract 1.
        let schedule = &vesting_schedule.schedule;
        let schedule_index = next_period_to_vest - 1;
        let vesting_fraction = if (schedule_index < schedule.length()) {
            schedule[schedule_index]
        } else {
            // Last vesting schedule fraction will repeat until the grant runs out.
            schedule[schedule.length() - 1]
        };
        let total_grant = vesting_contract.grant_pool.total_coins();
        let vested_amount = fixed_point32::multiply_u64(total_grant, vesting_fraction);
        // Cap vested amount by the remaining grant amount so we don't try to distribute more than what's remaining.
        vested_amount = min(vested_amount, vesting_contract.remaining_grant);
        vesting_contract.remaining_grant -= vested_amount;
        vesting_schedule.last_vested_period = next_period_to_vest;
        unlock_stake(vesting_contract, vested_amount);

        emit(
            Vest {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                staking_pool_address: vesting_contract.staking.pool_address,
                period_vested: next_period_to_vest,
                amount: vested_amount,
            },
        );
    }

    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });
