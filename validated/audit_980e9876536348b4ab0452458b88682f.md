### Title
Zero-underlying write-off requests are treated as valid, letting any fulfiller steal escrowed tranche tokens for free - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary
`createWriteOffRequest` rejects a zero `amount` of tranche tokens but never validates `underlyingsRequested`. A request with deposited tranches and `underlyings == 0` is stored as a fully valid request. `fullfillWriteOffRequest` then only requires `_underlyings >= currentRequest.underlyings`, so any unprivileged wallet can pass `_underlyings = 0`, pay nothing, and receive the entire escrowed tranche balance. This mirrors CVE-2018-12551: a malformed/empty entry (blank password line → empty user; zero-underlying request → free tranches) is silently accepted as valid input and grants the attacker the protected asset.

### Finding Description
In `createWriteOffRequest` only `amount == 0` is rejected; `underlyingsRequested` is unchecked and added verbatim to `userRequests[msg.sender].underlyings`. [1](#0-0) 

In `fullfillWriteOffRequest` the validity check is: [2](#0-1) 

When `currentRequest.underlyings == 0`, the condition `_underlyings < currentRequest.underlyings` can never revert for `_underlyings = 0`. The fulfiller therefore:
- transfers `0` underlyings in (`safeTransferFrom` of 0 is a no-op success),
- pays `0` exit fee,
- sends `0` to the lender,
- receives `_tranches` (the full escrowed tranche balance) for free. [3](#0-2) 

Tranche tokens are the real claim on vault underlyings (redeemable via `requestWithdraw`/`claimWithdrawRequest` in `IdleCDOEpochVariant`), so this is direct theft of escrowed principal, not a cosmetic issue.

### Impact Explanation
Any fulfiller (an unprivileged EOA; the function is explicitly callable "by any wallet") can drain all escrowed tranche tokens from a request whose `underlyings` field is 0. Loss = full `currentRequest.tranches` value at the current tranche price, for zero payment. A zero-`underlyings` request can arise from a lender fat-fingering `underlyingsRequested = 0`, from a UI bug, or from a request created for bookkeeping where the lender later tops up `tranches` via a second `createWriteOffRequest` call (amounts and underlyings are accumulated independently), so escrowed tranche value can far exceed a "mistake-sized" amount. Broken invariant: one receipt one payout — the escrow pays out the deposited asset without receiving the requested consideration.

### Likelihood Explanation
Likelihood is moderate-low: it requires a lender to create (or accumulate to) a request with `underlyings == 0`, which is a user error rather than attacker-controlled state. However, the contract offers no guard at all — there is no `underlyingsRequested == 0` check, no slippage/minimum-price check, and `fullfillWriteOffRequest` is permissionless, so once such a malformed request exists, theft is atomic, unconditional, and free for the attacker. Existing guards (nonReentrant, epoch-running check, `WrongRequest` revert) do not stop it because the check itself treats the malformed entry as valid — the exact CVE-2018-12551 pattern.

### Recommendation
Revert in `createWriteOffRequest` when `underlyingsRequested == 0` (a write-off with zero asking price is never economically meaningful), and/or require in `fullfillWriteOffRequest` that `currentRequest.underlyings > 0` and `_underlyings > 0`. Optionally also revert when `underlyingsRequested` exceeds the current tranche value to bound malformed entries.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVaultWriteOffEscrow} from "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract ZeroUnderlyingWriteOffTest is Test {
    // fork mainnet at a block where an epoch is running on the credit vault
    IdleCDOEpochVariant cdo = IdleCDOEpochVariant(0x...);           // live IdleCDOEpochVariant
    IdleCreditVaultWriteOffEscrow escrow =
        IdleCreditVaultWriteOffEscrow(0x...);                     // live escrow proxy
    IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
    IERC20Detailed underlying = IERC20Detailed(escrow.underlying());

    address lender = makeAddr("lender");
    address fulfiller = makeAddr("fulfiller");

    function testFulfillerStealsTranchesForFree() public {
        require(cdo.isEpochRunning(), "epoch must be running");

        uint256 trancheAmt = 100e18;
        deal(address(tranche), lender, trancheAmt);

        // Lender creates a malformed request: deposits tranches, asks for 0 underlyings
        vm.startPrank(lender);
        tranche.approve(address(escrow), trancheAmt);
        escrow.createWriteOffRequest(trancheAmt, 0); // succeeds: no underlyingsRequested check
        vm.stopPrank();

        // Fulfiller pays nothing and takes all escrowed tranche tokens
        vm.prank(fulfiller);
        escrow.fullfillWriteOffRequest(lender, trancheAmt, 0);

        assertEq(tranche.balanceOf(fulfiller), trancheAmt, "fulfiller got tranches for free");
        assertEq(underlying.balanceOf(lender), 0, "lender received nothing");
        assertEq(tranche.balanceOf(address(escrow)), 0);
    }
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```
