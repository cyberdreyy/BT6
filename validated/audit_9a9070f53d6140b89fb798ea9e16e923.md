### Title
Ignored `mark_locally_accepted` state-transition failure lets a signer broadcast a block its own DB state already marked `GloballyRejected` - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` unconditionally proceeds to persist the block and broadcast it to the node even when the preceding call to `block_info.mark_locally_accepted(true)` returns an `Err`, mirroring the "unchecked low-level call" pattern from the external report: a critical operation's result is discarded, and execution continues as if it had succeeded.

### Finding Description
`BlockInfo::mark_locally_accepted` first unconditionally sets `signed_group` and only afterward attempts the guarded transition via `move_to`/`check_state`: [1](#0-0) 
`check_state` explicitly forbids moving into `LocallyAccepted` from a terminal `GloballyRejected` state: [2](#0-1) 

In `store_and_process_block_signature`, when this call fails, the error is only logged, and — critically — is suppressed entirely once `has_reached_consensus()` is true (i.e. exactly the case where the transition failed because the block is already `GloballyRejected`). The function then unconditionally calls `insert_block` and `broadcast_signed_block` regardless of whether the mark succeeded: [3](#0-2) 

Because `signed_group` was already set before the (failed) `move_to` call, the persisted `BlockInfo` now records a signed-group timestamp on a block whose `state` field is still `GloballyRejected` — an internally inconsistent record — and the block is pushed to the node via `broadcast_signed_block` → `handle_post_block` → `stacks_client.post_block(block)`, regardless of the local rejection verdict: [4](#0-3) 

This race is reachable because acceptance and rejection weights are tallied from two independent DB tables/tallies (`get_block_signatures` for accept weight, `get_block_rejection_signer_addrs` for reject weight) with no cross-check preventing the same signer address from contributing weight to both tallies: [5](#0-4) [6](#0-5) 

Normally the 70%/30% complementary thresholds mathematically prevent both an accept-consensus and a reject-consensus from being reached on the same block, since accept-weight and reject-weight are meant to be disjoint subsets of `total_weight`. A single equivocating signer (one slot) that emits *both* a `BlockAccepted` and a `BlockRejected` message for the same block breaks that disjointness assumption: its weight is counted once in each independent tally, letting reject-consensus be locked in first (setting `state = GloballyRejected`), and a later-processed accept message from the same crossing-the-threshold set trigger `mark_locally_accepted`, whose `Err` is then silently dropped by the caller.

### Impact Explanation
This breaks the intended equality that a locally recorded `GloballyRejected` verdict is terminal and can never be followed by this signer broadcasting/pushing the same block forward. The unconditional `insert_block`+`broadcast_signed_block` call after an ignored `Err` means:
- The persisted `BlockInfo` becomes inconsistent (`signed_group` set while `state == GloballyRejected`), corrupting the local ground truth used by every other check in the state machine (`has_reached_consensus`, `is_locally_finalized`, etc.).
- The signer still relays a fully-signed block to its own node (`handle_post_block`) after having locally treated the block as globally rejected, which can help push a block that this signer's own tally says should be dead, undermining the "the block is dead: globally rejected" guarantee described for the state machine and creating divergent views across the signer set on whether the block is canonical.

This matches the report's "Critical" bucket: a rejection can be effectively bypassed/recounted toward acceptance being pushed to the node, i.e., a signature/action taken on a block that this signer's own consensus decision says is invalid/non-canonical.

### Likelihood Explanation
Requires only a single misbehaving signer (its own key, one slot) sending both a `BlockRejected` and a `BlockAccepted` message for the same `signer_signature_hash`, plus ordinary gossip timing so the rejection is processed (and locks `GloballyRejected`) before the delayed acceptance crosses the local signer's independently-computed 70% threshold. No majority collusion or other signer's key is needed — only the equivocator's own weight is double-counted across the two independent tallies.

### Recommendation
- Make `mark_locally_accepted`'s (and the other `mark_*`) `Err` result authoritative: on failure, `store_and_process_block_signature` (and its sibling `store_and_process_block_rejection`) must return immediately without calling `insert_block` or `broadcast_signed_block`, instead of only conditionally logging.
- Prevent a single signer address from contributing weight to both the accept and reject tallies for the same block: cross-check/evict a signer's earlier accept when a rejection for the same address+block arrives (and vice versa), or reject/ignore a second conflicting vote from the same address for the same `signer_signature_hash`.
- Reorder `mark_locally_accepted` so `signed_group`/`signed_self`/`valid`/`approved_time` are only set after `move_to` succeeds, so a failed transition never leaves partially-mutated, DB-persisted state.

### Proof of Concept
1. Signer set has total weight 100, threshold `min_weight = 70` (per `compute_voting_weight_threshold`, `stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`).
2. A malicious signer M (weight 5) proposes/gossips both a `BlockRejected` message and a `BlockAccepted` message for the same block B, signed with its own key.
3. Honest rejecters totaling weight 26 plus M's reject message (5) reach `total_reject_weight = 31 ≥ total_weight - min_weight + 1 = 31` in `store_and_process_block_rejection`, so `block_info.mark_globally_rejected()` succeeds and `state` becomes `GloballyRejected` (`stacks-signer/src/v0/signer.rs:2313-2341`).
4. Shortly after (gossip re-ordering / delayed message), honest accepters totaling weight 65 plus M's earlier accept message (5) reach `total_signature_weight = 70 ≥ min_weight` in `store_and_process_block_signature` (`stacks-signer/src/v0/signer.rs:2494-2514`).
5. `block_info.mark_locally_accepted(true)` is called; `move_to(LocallyAccepted)` fails because `state == GloballyRejected` (`stacks-signer/src/signerdb.rs:280-341`), returning `Err`.
6. Because `block_info.has_reached_consensus()` is `true`, the `warn!` is skipped entirely (`stacks-signer/src/v0/signer.rs:2528-2532`), and execution falls through to `insert_block` and `broadcast_signed_block` (`stacks-signer/src/v0/signer.rs:2533-2537`), causing the node to receive a `post_block` call for a block this signer's own DB state had already recorded as globally rejected.

        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

    /// Attempt to transition the block state
    pub fn move_to(&mut self, state: BlockState) -> Result<(), String> {
        if !self.check_state(state) {
            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
    }

    fn broadcast_signed_block(
        &mut self,
        stacks_client: &StacksClient,
        mut block: NakamotoBlock,
        addrs_to_sigs: &HashMap<StacksAddress, MessageSignature>,
    ) {
        #[cfg(any(test, feature = "testing"))]
        self.test_pause_block_broadcast(&block);

        // collect signatures for the block
        let signatures: Vec<_> = self
            .signer_addresses
            .iter()
            .filter_map(|addr| addrs_to_sigs.get(addr).cloned())
            .collect();

        block.header.signer_signature_hash();
        block.header.signer_signature = signatures;

        self.handle_post_block(stacks_client, &block);
    }

    /// Attempt to post a block to the stacks-node and handle the result
    pub fn handle_post_block(&mut self, stacks_client: &StacksClient, block: &NakamotoBlock) {
        #[cfg(any(test, feature = "testing"))]
        if self.test_skip_block_broadcast(block) {
            return;
        }
        let block_hash = block.header.signer_signature_hash();
        match stacks_client.post_block(block) {
            Ok(accepted) => {
                debug!("{self}: Block {block_hash} accepted by stacks node: {accepted}");
                if let Err(e) = self
                    .signer_db
                    .set_block_broadcasted(&block_hash, get_epoch_time_secs())
                {
                    warn!("{self}: Failed to set block broadcasted for {block_hash}: {e:?}");
                }
            }
            Err(e) => {
                warn!("{self}: Failed to broadcast block {block_hash} to the node: {e}")
            }
        }
    }
