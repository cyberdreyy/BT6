### Title
Re-proposal of an already GloballyAccepted block with `signed_self`/`valid` unset causes repeated wasted validation submissions - ([File: stacks-signer/src/v0/signer.rs])

### Summary
When a signer learns a block is `GloballyAccepted` purely via a `NewBlock` event (`mark_globally_accepted` called directly, without ever validating or signing the block itself), `globally_approved_and_responded()` returns `false` because it requires `signed_self.is_some() || valid == Some(false)`. Repeated re-proposals of that exact block then fall through `should_reevaluate_block` into a full fresh re-evaluation, re-submitting the already-finalized block for node validation on every repeat, consuming this signer's single concurrent-validation slot (`submitted_block_proposal`).

### Finding Description
`BlockInfo::globally_approved_and_responded` is defined as: [1](#0-0) 
This gate is only `true` when the signer itself signed (`signed_self.is_some()`) or explicitly marked the block invalid (`valid == Some(false)`). It does **not** account for the case where `state == GloballyAccepted` was reached purely via the `NewBlock`/chain-tip path, which calls `mark_globally_accepted()` directly without setting `signed_self` or `valid`: [2](#0-1) 

In `should_reevaluate_block`, when `globally_approved_and_responded()` is `false`, and `should_reevaluate_reject_reason` is `false` (no reject reason, since the signer never rejected it), and `state != PreCommitted`, the code calls `determine_response(block_info)`. With `valid == None`, this cannot produce a response, so it falls into the `is_pending` branch. Since this signer never submitted the block for validation itself, `has_pending_block_validation` is `false`, and the function falls through to `return true` at the end, forcing a full re-evaluation: [3](#0-2) 

Back in `handle_block_proposal`, a `true` return causes a brand-new `BlockInfo::from(block_proposal.clone())` to be constructed (discarding the terminal `GloballyAccepted` state), run through `check_block_against_state`, and — if `submitted_block_proposal` is free — resubmitted to the node for validation via `submit_block_for_validation`, occupying the signer's one concurrent-validation slot: [4](#0-3) [5](#0-4) 

This can be repeated indefinitely because each re-proposal reconstructs a fresh `BlockInfo` (again with `valid=None`, `signed_self=None`), so the same non-gating condition recurs every time, and each cycle re-occupies the slot until the node responds.

### Impact Explanation
This breaks the intended fail-fast/liveness guarantee that a `GloballyAccepted` block should never re-consume validation resources. A single attacker (a miner who wins one slot and can gossip the identical `BlockProposal` for an already-finalized block) can repeatedly force a targeted signer to re-submit that block for validation, occupying `submitted_block_proposal` and delaying/blocking that signer from validating a concurrently queued, genuinely new distinct proposal. This is a temporary, per-signer liveness degradation (the signer cannot validate other pending proposals while its slot is wasted), matching the "High - liveness" category described, though the window is narrow (only signers that learned acceptance via `NewBlock` without self-validating/signing are affected, and it resolves once the node's validation response for the re-submission arrives and updates `valid`/`signed_self`).

### Likelihood Explanation
Preconditions: target signer has `block_info.state == GloballyAccepted`, `signed_self == None`, `valid == None` — reachable via the `NewBlock` event path at [2](#0-1) , e.g. when the signer's own validation response never arrived/was skipped but it observed the chain tip advance. Attacker cost is a single miner slot plus gossip of the identical block proposal (no majority-signer collusion, no auth token, no local access needed). Repeatable each time the attacker re-broadcasts the same `BlockProposal`. Feasibility depends on the target signer being in this specific narrow state, which is plausible but not guaranteed for every signer at every block.

### Recommendation
Extend the terminal/no-op check to short-circuit any `GloballyAccepted` or `GloballyRejected` block regardless of `signed_self`/`valid`, e.g. change `should_reevaluate_block` (or `globally_approved_and_responded`) to also return early whenever `block_info.has_reached_consensus()` is `true`, rather than requiring `signed_self.is_some() || valid == Some(false)`. This ensures a block already in a terminal global state is never re-submitted for validation, independent of how this signer learned of that state.

    ) -> bool {
        let signer_signature_hash = block_info.block.header.signer_signature_hash();
        if block_info.globally_approved_and_responded() {
            info!("{self}: received a block proposal for a globally accepted block to which we have already responded. Ignoring.";
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_info.block.block_id(),
                "block_height" => block_info.block.header.chain_length,
                "burn_height" => block_proposal.burn_height,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "timestamp" => block_info.block.header.timestamp,
                "signed_group" => block_info.signed_group,
                "signed_self" => block_info.signed_self,
                "valid" => ?block_info.valid
            );
            return false;
        }
        if !should_reevaluate_reject_reason(block_info) {
            if block_info.state == BlockState::PreCommitted {
                // We validated this block but haven't signed it. Signing requires the
                // pre-commit threshold and the conflict checks in `handle_block_pre_commit`.
                // Re-broadcast our pre-commit and re-run that evaluation instead of
                // responding with a signature directly, so a re-proposed block can't
                // bypass those checks.
                info!(
                    "{self}: received a block proposal for a block we have pre-committed to but not signed. Re-evaluating the pre-commit.";
                    "signer_signature_hash" => %signer_signature_hash,
                    "block_id" => %block_info.block.block_id(),
                    "block_height" => block_info.block.header.chain_length,
                    "burn_height" => block_proposal.burn_height,
                    "consensus_hash" => %block_info.block.header.consensus_hash
                );
                self.send_block_pre_commit(signer_signature_hash.clone());
                let address = self.stacks_address.clone();
                self.handle_block_pre_commit(
                    stacks_client,
                    sortition_state,
                    &address,
                    &signer_signature_hash,
                );
                return false;
            }
            if let Some(block_response) = self.determine_response(block_info) {
                self.send_block_response(&block_info.block, block_response);
                return false;
            } else {
                let is_pending = self
                    .signer_db
                    .has_pending_block_validation(&signer_signature_hash)
                    .unwrap_or_else(|e| {
                        warn!("{self}: Failed to load pending block validations: {e:?}");
                        false
                    });
                if is_pending {
                    debug!(
                        "{self}: received a block proposal for a block for which we is already pending validation. Do nothing.";
                        "signer_signature_hash" => %block_info.block.header.signer_signature_hash(),
                        "block_id" => %block_info.block.block_id()
                    );
                    return false;
                } else {
                    info!(
                        "{self}: received a block proposal for this block before, but we do not have a pending validation for it.";
                        "reject_reason" => ?block_info.reject_reason,
                        "signer_signature_hash" => %signer_signature_hash,
                        "block_id" => %block_info.block.block_id(),
                        "block_height" => block_info.block.header.chain_length,
                        "burn_height" => block_proposal.burn_height,
                        "consensus_hash" => %block_info.block.header.consensus_hash
                    );
                }
            }
        } else {
            info!(
                "{self}: received a block proposal for this block before, but our rejection reason allows us to reconsider";
                "reject_reason" => ?block_info.reject_reason,
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_proposal.block.block_id(),
                "block_height" => block_proposal.block.header.chain_length,
                "burn_height" => block_proposal.burn_height,
                "consensus_hash" => %block_proposal.block.header.consensus_hash
            );
        }
        true
    }
