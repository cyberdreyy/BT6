Unauthenticated exposure of LOOP plugin pprof and metrics endpoints - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers `/plugins/:name/metrics` and `/plugins/:name/debug/pprof/*profile` directly on the base `api` router group without any `auth.Authenticate` wrapper, unlike sibling route groups (`debugRoutes`, `sessionRoutes`, `v2Routes`) which explicitly require session or token authentication. This allows any unauthenticated network client to retrieve LOOP plugin pprof and metrics dumps.

### Finding Description
In `NewRouter`, the top-level `api` group is created with only rate-limiting and session middleware — no authentication is enforced at that level [1](#0-0) . `loopRoutes` is then called with this unauthenticated `api` group and registers handlers directly on `r` with no auth wrapper: [2](#0-1) 

Compare this to `debugRoutes`, which explicitly wraps its `/debug/vars` route in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [3](#0-2) , and `sessionRoutes`/`v2Routes`, which create separate authenticated sub-groups for protected endpoints [4](#0-3) [5](#0-4) .

The handlers themselves perform no authentication check either. `pluginMetricHandler` looks up the plugin by name from the URL and proxies to the plugin's internal Prometheus port, returning the raw response body to the caller [6](#0-5) . `pluginPPROFHandler` similarly proxies to the plugin's internal `/debug/pprof/<profile>` endpoint and streams the response back unauthenticated [7](#0-6) . Neither handler nor the routing layer performs any session/token check, so any network client that can reach the node's HTTP API can request heap dumps, goroutine dumps, CPU profiles, or full-text metrics of any registered LOOP plugin by name.

### Impact Explanation
This maps to Chainlink's information-disclosure impact class: unauthenticated leakage of in-process memory (heap/goroutine profiles) and internal metrics for LOOP plugins. Heap and goroutine dumps can contain sensitive in-memory data (e.g., decrypted keys, internal state, request/response bodies cached in memory), and Prometheus metrics can reveal internal topology/operational details useful for further attacks. This is a confidentiality violation of the node's authentication boundary, though it does not directly enable fund movement or job/key mutation.

### Likelihood Explanation
No preconditions or credentials are required — the endpoints are reachable by any client able to send an HTTP GET to the node's web server, provided at least one LOOP plugin is registered (`l.registry.Get(pluginName)` must resolve). This is fully unauthenticated, repeatable, and trivially reproducible.

### Recommendation
Wrap the `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or an equivalent internal-only/token-based check), consistent with how `debugRoutes` protects `/debug/vars`. If these endpoints are meant to be scraped only by an internal Prometheus instance, restrict them to an authenticated group or a separate internal-only listener, not the public `api` group.

### Proof of Concept
1. Build a `*gin.Engine` via `NewRouter` with a mock `chainlink.Application` whose `GetLoopRegistry()` returns a registry containing one registered plugin (e.g., name `"x"`).
2. Using `httptest.NewRecorder()` and `httptest.NewRequest("GET", "/plugins/x/debug/pprof/heap", nil)`, call `engine.ServeHTTP(rec, req)` without setting any `Authorization` header or session cookie.
3. Assert `rec.Code == http.StatusOK` (or a proxied response) rather than `http.StatusUnauthorized`, demonstrating the endpoint is reachable without authentication.
4. Repeat for `GET /plugins/x/metrics` and confirm the same unauthenticated access.
5. As a control, issue an unauthenticated `GET /debug/vars` and confirm it correctly returns `401 Unauthorized`, showing the inconsistency between route groups.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
