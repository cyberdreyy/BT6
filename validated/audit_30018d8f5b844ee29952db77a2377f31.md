### Title
Alpenglow epoch inflation reward budget is fixed at epoch start and never corrected downward after VAT burn reduces capitalization - ([File: runtime/src/block_component_processor/vote_reward/epoch_inflation_account_state.rs])

### Summary
This is the same bug class as the Autonolas `checkpoint()` issue: a per-epoch spending ceiling is pre-computed from a *predicted* value (here, `epoch_start_capitalization + additional_rewards`) and persisted before the epoch's actual outcome is known. When the actual, realized value used to derive the ceiling later turns out to be lower than predicted (in Autonolas: lower blended inflation at year boundaries; in agave: capitalization reduced by VAT burn to the incinerator during epoch freeze), the code has no corrective/downward-adjustment path. It simply keeps and pays out against the stale, higher pre-committed ceiling, permanently over-crediting rewards relative to what the actual inflation schedule should allow for that epoch.

### Finding Description
`EpochInflationState::new_from_bank` computes `max_possible_validator_reward` at the *start* of a new epoch using a capitalization prediction: [1](#0-0) 

This is invoked from `process_new_epoch` with `epoch_start_capitalization = parent_capitalization` and `additional_rewards = epoch_rewards` (the total PER stake+commission rewards about to be distributed for the *previous* epoch, added to `epoch_start_capitalization` as a forward-looking estimate of what capitalization will become): [2](#0-1) 

This pre-committed `max_possible_validator_reward` is stored on-chain (`EpochInflationAccountState::set_state`) and later read back verbatim as the epoch's inflation-reward ceiling (`epoch_inflation_rewards`) when actually calculating and paying out validator rewards for that epoch — there is no re-derivation from the *actual* end-of-epoch capitalization: [3](#0-2) 

The problem: between the epoch-start prediction and the epoch's actual settlement, capitalization can *decrease* relative to what was assumed — specifically, VAT (validator activation tax / burn-per-epoch, see `vat_to_burn_per_epoch` in `SlotParams`) lamports get transferred to the incinerator and burned at the epoch boundary (on `freeze()`), which reduces capitalization *after* the reward budget was already fixed using the higher pre-burn value. This is exactly analogous to Autonolas: inflation rate decreasing mid-epoch at a year boundary produces a lower *actual* `maxBond` than the pre-credited prediction, but the code only adjusts `effectiveBond` upward (`if incentives[4] > curMaxBond`), never downward.

Here, the equivalent one-directional/no-correction behavior is demonstrated directly by an existing repo test, whose very name confirms the pre-committed (higher, pre-burn) budget is used regardless of the post-burn reality: [4](#0-3) 
The test explicitly asserts `recorded_payout > recalculated_ceiling` (the payout that was pre-committed exceeds what the post-burn capitalization-based ceiling would allow), and then confirms the system pays out the higher `recorded_budget`/`recorded_payout` anyway: [5](#0-4) 

### Impact Explanation
Each epoch in which VAT burn (or any other capitalization-reducing event between epoch-start prediction and epoch settlement) occurs, the validator/staker inflation reward ceiling used for that epoch is the *stale, higher* pre-epoch estimate rather than one reflecting the actual reduced capitalization. Because `calculate_epoch_inflation_rewards` computes rewards as `validator_rate * capitalization * epoch_duration_in_years` (see `runtime/src/bank.rs:2966-2977`), any capitalization decrease that occurs after the prediction is baked in should have lowered the reward ceiling proportionally; instead the ceiling silently stays inflated. This results in validators/stakers being paid more OLAS-equivalent lamports (newly minted inflation) than the intended schedule dictates for that epoch — a real, systemic over-issuance of SOL supply, repeating every epoch where such capitalization reductions occur (not just at rare "year boundary" events as in the Autonolas case, since VAT burn happens routinely at epoch boundaries once Alpenglow/VAT is active).

### Likelihood Explanation
This triggers automatically, with no attacker action required, any time an Alpenglow epoch boundary combines (a) the epoch-start reward-budget snapshot and (b) a capitalization-reducing event (VAT burn to incinerator) that occurs after the snapshot but before/at freeze. The repository's own regression test (`test_alpenglow_partitioned_rewards_use_epoch_start_budget_after_burn`) demonstrates this is a reproducible condition in the current design, not a hypothetical edge case — the test title and assertions indicate the maintainers are aware of and have accepted this behavior as "by design" (to avoid penalizing early-epoch voters), which mirrors the Autonolas report's discovery that the underlying assumption ("actual always ≥ predicted") does not universally hold and is not corrected when violated.

### Recommendation
Because the existing test (`test_alpenglow_partitioned_rewards_use_epoch_start_budget_after_burn`) documents this as intentional behavior chosen to avoid under-rewarding early-epoch voters, this is very likely an accepted design trade-off rather than an unnoticed bug — similar to how the Autonolas developers explicitly commented that the reverse case "has to always be true" without adding a corrective branch. If a fix is desired, mirror the Autonolas mitigation pattern: track the pre-committed epoch-start budget and the post-settlement realized ceiling, and when the realized capitalization-based ceiling is lower than what was already pre-committed, cap the actual payout (or record the delta so it is subtracted from a future epoch's inflation allowance) instead of unconditionally honoring the stale higher figure.

### Proof of Concept
The existing repository test constitutes an executable PoC of this exact scenario: [6](#0-5) 
It: (1) records the epoch-start `max_possible_validator_reward` budget via `EpochInflationAccountState`, (2) pushes vote credits so the maximum possible payout is earned, (3) calls `bank.freeze()` which burns VAT lamports to the incinerator, reducing capitalization, (4) recomputes the "true" post-burn ceiling via `calculate_epoch_inflation_rewards` and asserts it is *strictly less* than the already-recorded payout, and (5) asserts the system still pays out the full pre-burn `recorded_payout`/`recorded_budget`, proving the downward correction never occurs.

    #[test]
    fn test_alpenglow_partitioned_rewards_use_epoch_start_budget_after_burn() {
        let validator_keypairs = vec![genesis_utils::ValidatorVoteKeypairs::new_rand()];
        let GenesisConfigInfo {
            mut genesis_config, ..
        } = genesis_utils::create_genesis_config_with_alpenglow_vote_accounts(
            1_000_000_000 * LAMPORTS_PER_SOL,
            &validator_keypairs,
            vec![100 * LAMPORTS_PER_SOL],
        );
        genesis_config.epoch_schedule = EpochSchedule::new(SLOTS_PER_EPOCH);
        let features_to_deactivate = crate::slot_params::slot_time_feature_ids().to_vec();
        deactivate_features(&mut genesis_config, &features_to_deactivate);

        let (bank, bank_forks) =
            Bank::new_for_tests(&genesis_config).wrap_with_bank_forks_for_tests();
        let bank = Bank::new_from_parent_with_bank_forks(
            bank_forks.as_ref(),
            bank,
            SlotLeader::default(),
            SLOTS_PER_EPOCH,
        );
        assert_eq!(bank.epoch(), 1);

        let recorded_budget = EpochInflationAccountState::new_from_bank(&bank)
            .and_then(|state| state.inflation_rewards_for_epoch(bank.epoch()))
            .expect("epoch-start inflation budget must be persisted");
        // Alpenglow rewards are rounded down once per slot, so this is the largest
        // payout that can actually have been recorded during the epoch.
        let recorded_payout = recorded_budget / SLOTS_PER_EPOCH * SLOTS_PER_EPOCH;

        let vote_pubkey = validator_keypairs[0].vote_keypair.pubkey();
        let mut vote_account = bank.get_account(&vote_pubkey).unwrap();
        let VoteStateVersions::V4(mut vote_state) = vote_account
            .deserialize_data::<VoteStateVersions>()
            .unwrap()
        else {
            panic!("unexpected vote state version");
        };
        let last_credits = vote_state
            .epoch_credits
            .last()
            .map(|(_epoch, final_credits, _initial_credits)| *final_credits)
            .unwrap_or_default();
        vote_state
            .epoch_credits
            .push((bank.epoch(), last_credits + recorded_payout, last_credits));
        vote_account
            .serialize_data(&VoteStateVersions::V4(vote_state))
            .unwrap();
        bank.store_account(&vote_pubkey, &vote_account);

        // Freezing burns the VAT transferred to the incinerator at the epoch
        // boundary, reducing capitalization after the reward budget was fixed.
        bank.freeze();
        let recalculated_ceiling =
            bank.calculate_epoch_inflation_rewards(bank.capitalization(), bank.epoch());
        assert!(
            recorded_payout > recalculated_ceiling,
            "the test must reproduce a payout above the post-burn ceiling: \
             recorded_payout={recorded_payout}, recalculated_ceiling={recalculated_ceiling}"
        );

        let bank = Bank::new_from_parent(
            bank,
            SlotLeader::default(),
            SLOTS_PER_EPOCH.saturating_mul(2),
        );
        assert_eq!(bank.epoch(), 2);

        let epoch_rewards = bank.get_epoch_rewards_sysvar();
        let EpochRewardStatus::Active(EpochRewardPhase::Calculation(calculation_status)) =
            &bank.epoch_reward_status
        else {
            panic!("{:?} not active calculation", bank.epoch_reward_status);
        };
        let stake_rewards = calculation_status
            .all_stake_rewards
            .enumerated_rewards_iter()
            .map(|(_index, reward)| reward.inflation.stake_reward)
            .sum::<u64>();
        assert_eq!(epoch_rewards.total_rewards, recorded_budget);
        assert_eq!(
            epoch_rewards.distributed_rewards + stake_rewards,
            recorded_payout,
            "every recorded reward lamport must still be paid"
        );
    }
