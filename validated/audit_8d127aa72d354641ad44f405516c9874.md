### Title
Vault allowlist authorizations (`AllowlistRequest` digests) cannot be revoked once submitted, letting a stale/mistaken authorization remain exploitable until arbitrary self-chosen expiry - (File: `core/capabilities/vault/allow_list_based_auth.go`)

### Summary
The Vault gateway's `AllowListBasedAuth` mirrors the `approvedHashes` pattern from the external report: a workflow owner authorizes a specific request by its digest (`WorkflowRegistryOwnerAllowlistedRequest{RequestDigest, Owner, ExpiryTimestamp}`), and the node/gateway trusts any incoming request matching that digest until it expires. There is no function, on the node side or in the syncer, to revoke/invalidate an already-submitted allowlisted digest before its expiry — exactly the missing capability flagged in the original finding.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` computes the digest of an incoming JSON-RPC request and checks it against the list of allowlisted requests synced from the `WorkflowRegistry` contract, honoring it as long as `time.Now() <= ExpiryTimestamp`: [1](#0-0) 

The only place where allowlisted entries are removed is time-based pruning in the syncer's periodic reconciliation loop — there is no revoke/cancel path: [2](#0-1) 

The `WorkflowRegistrySyncer` interface itself only exposes read access to allowlisted requests, with no corresponding "remove" or "revoke" method: [3](#0-2) 

Once a request is allowlisted on-chain via `AllowlistRequest(requestDigest, expiryTimestamp)` — as exercised in both the changeset tooling and the system-test helper — the owner has no way to undo it: [4](#0-3) [5](#0-4) 

The `ExpiryTimestamp` is caller-supplied (a `uint32` unix timestamp) and can be set arbitrarily far in the future — deployment tests set it to 48 hours out, and it is not bounded by any minimum/maximum in the node-side authorization logic: [6](#0-5) 

### Impact Explanation
This is the same bug class as the `approvedHashes` finding: an authorization bound to a hash/digest, once granted, has no revocation path and remains valid until a self-chosen expiry. In this codebase, that authorization directly gates execution of sensitive Vault operations (`SecretsCreate`, `SecretsDelete`, `SecretsList`) through the gateway on behalf of a workflow owner. If a workflow owner's allowlist submission is made in error, is the product of a compromised signing/CI pipeline, or is later discovered to correspond to a malicious/incorrect request body (e.g., a `CreateSecrets` request with attacker-controlled ciphertext, or a `DeleteSecrets` request targeting the wrong identifiers), the owner cannot invalidate that grant — anyone who can reproduce the exact JSON-RPC request (and thus its digest) can still have it executed by the gateway/node until the `ExpiryTimestamp` elapses, potentially hours or days later. This constitutes an allowlist-bypass-style standing authorization that cannot be revoked, enabling unauthorized secret writes/deletes for the affected owner during the outstanding window.

### Likelihood Explanation
Moderate. It requires that an owner (or a script/pipeline acting for them) has already allowlisted a request digest that later turns out to be unwanted — a realistic operational scenario (mis-issued CI job, leaked/replayed request body, or a compromised build step calling `AllowlistRequest`). Given `ExpiryTimestamp` is attacker/operator-controlled and unbounded, the exposure window can be made arbitrarily large.

### Recommendation
Add a revocation mechanism symmetric to `AllowlistRequest`, e.g. an owner-gated `RevokeAllowlistedRequest(requestDigest)` on the `WorkflowRegistry` contract that removes/zeroes the entry, and extend `WorkflowRegistrySyncer` and `AllowListBasedAuth` to react to revocation events (or re-sync state) so a revoked digest is rejected immediately rather than waiting for `ExpiryTimestamp`. Additionally, consider bounding `ExpiryTimestamp` to a sane maximum window so the blast radius of an un-revoked allowlist entry is limited.

### Proof of Concept
1. A workflow owner calls `AllowlistRequest(requestDigest, expiry)` on `WorkflowRegistry` for a `CreateSecrets`/`DeleteSecrets` request, as done in the test helper: [7](#0-6) 
2. The owner later determines the request body (and hence digest) was incorrect or malicious (e.g., wrong secret payload, replayed from an untrusted source).
3. There is no exposed contract function, syncer method, or node API to remove this entry from the allowlist; `syncAllowlistedRequests` only drops entries once `ExpiryTimestamp` passes: [8](#0-7) 
4. Until expiry, any party able to submit the exact matching JSON-RPC request to the gateway will have it authorized by `allowListBasedAuth.AuthorizeRequest` and executed by the vault node, since only presence + expiry are checked: [9](#0-8)

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
```

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
```

var UserAllowlistRequestOp = operations.NewOperation(
	"user-allowlist-request-op",
	semver.MustParse("1.0.0"),
	"User Allowlist Request in WorkflowRegistry V2",
	func(b operations.Bundle, deps WorkflowRegistryOpDeps, input UserAllowlistRequestOpInput) (UserAllowlistRequestOpOutput, error) {
		// Execute the transaction using the strategy
		operation, _, err := deps.Strategy.Apply(func(opts *bind.TransactOpts) (*types.Transaction, error) {
			tx, err := deps.Registry.AllowlistRequest(opts, input.RequestDigest, input.ExpiryTimestamp)
			if err != nil {
				return nil, fmt.Errorf("failed to call AllowlistRequest: %w", err)
			}
			return tx, nil
		})
		if err != nil {
			return UserAllowlistRequestOpOutput{}, fmt.Errorf("failed to execute AllowlistRequest: %w", err)
		}
		if operation != nil {
			deps.Env.Logger.Infof("Created MCMS proposal for AllowlistRequest on chain %d", input.ChainSelector)
		} else {
			deps.Env.Logger.Infof("Successfully user allowlisted request on chain %d", input.ChainSelector)
		}
		return UserAllowlistRequestOpOutput{
			Success:         true,
			MCMSOperation:   operation,
			RegistryAddress: deps.Registry.Address(),
		}, nil
	},
)
