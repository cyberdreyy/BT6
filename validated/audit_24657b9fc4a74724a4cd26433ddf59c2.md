### Title
Unauthenticated pprof/heap dump disclosure via `/plugins/:name/debug/pprof/*profile` route - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers LOOP plugin pprof-proxy endpoints (`/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol`, `/plugins/:name/metrics`) on the base `api` router group without wrapping them in any `auth.Authenticate` middleware, unlike `debugRoutes` and `metricRoutes` which explicitly require session/token authentication. Any unauthenticated caller can hit these routes and have the node proxy a live pprof profile/heap/goroutine dump request to the internal LOOP plugin process.

### Finding Description
In [1](#0-0) , `debugRoutes`, `healthRoutes`, `sessionRoutes`, `v2Routes`, and `loopRoutes` are all mounted on the same `api` group, but only some are internally protected. `debugRoutes` explicitly wraps its subgroup with `auth.Authenticate(...)`: [2](#0-1) . Likewise the equivalent pprof group used for the node's own process, `metricRoutes`, is only invoked inside the authenticated `authv2` group: [3](#0-2) .

In contrast, `loopRoutes` is registered directly on the unauthenticated `api` group with no auth middleware at all: [4](#0-3) . The handler `pluginPPROFHandler` looks up the named LOOP plugin in the registry and proxies the request straight to that plugin's internal pprof endpoint: [5](#0-4) , returning the raw response body back to the caller with `gc.Data(http.StatusOK, ...)` in `doRequest` ( [6](#0-5) ).

Because the `api` group only applies rate limiting and session-store middleware ( [7](#0-6) ), no credential of any kind is required to reach `pluginPPROFHandler`/`pluginMetricHandler`. Any external, unauthenticated client can request full CPU/heap/goroutine profiles of a running LOOP plugin process.

### Impact Explanation
An unauthenticated attacker can trigger CPU/heap/goroutine profile captures of a LOOP plugin process (e.g. `GET /plugins/{name}/debug/pprof/heap` or `/profile`). Heap and goroutine dumps commonly contain in-memory secrets, keys, and internal state of the plugin process, and `/profile` with a large `seconds` parameter can also be used to induce sustained CPU load (a resource-exhaustion/DoS vector) since the timeout is attacker-influenced via the `seconds` query parameter (`pprofURLVals`). This matches a sensitive-data-disclosure / unauthenticated-internals-exposure impact class.

### Likelihood Explanation
No credentials are needed — the route is exposed on the default unauthenticated `api` group. The only precondition is that at least one LOOP plugin is registered in `l.registry` (true whenever LOOP plugins, e.g. for external adapters/relayers, are enabled — a common production configuration) and that the plugin name is known or guessed via the also-unauthenticated `/discovery` endpoint, which lists registered plugin names. This makes the attack trivially repeatable with a single unauthenticated HTTP request.

### Recommendation
Wrap `loopRoutes` in the same `auth.Authenticate(...)` (and appropriate role, e.g. `auth.RequiresAdminRole`) middleware used for `debugRoutes`/`metricRoutes`, consistent with how the node's own pprof/debug endpoints are gated, before registering the `/plugins/:name/...` routes.

### Proof of Concept
Go handler-level integration test:
1. Build an application with a fake/mock LOOP plugin registered in the loop registry (or use existing test helpers around `NewLoopRegistryServer`).
2. Build the router via `web.NewRouter(app, nil)` and start an `httptest.Server`.
3. Issue `GET {server}/plugins/{name}/debug/pprof/heap` with no session cookie and no API token/header.
4. Assert response status is `200 OK` with a valid pprof payload body, instead of the expected `401 Unauthorized`.
5. Repeat for `/plugins/{name}/metrics` and `/plugins/{name}/debug/pprof/profile?seconds=1` to confirm the same unauthenticated access, contrasting with a parallel test against `/debug/vars` (via `debugRoutes`) which correctly returns `401` without a session cookie.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
