### Title
Gateway user-facing HTTP endpoint has no message replay protection — `api.Message.Validate()` lacks timestamp/nonce check - ([File: core/services/gateway/api/message.go], [File: core/services/gateway/gateway.go], [File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
Unlike the node-side handshake in `ConnectionManager.StartHandshake` which enforces `DonId`+`GatewayId`+`Timestamp`+`Signature` freshness checks, the user-facing gateway HTTP path (`gateway.ProcessRequest` → `Message.Validate()` → `Handler.HandleLegacyUserMessage`) has no generic replay protection. `Message.Validate()` checks only signature format, ID/method/DonId length, and null-byte suffixes, with no timestamp or nonce field at all.

### Finding Description
`gateway.ProcessRequest` decodes the request, calls `msg.Validate()` for legacy requests, and dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)`. [1](#0-0)  `Message.Validate()` only validates signature length/format, ID/Method/DonId length and null-byte suffixes, and extracts the signer — there is no timestamp or nonce field on `MessageBody` at all. [2](#0-1) 

The only staleness check that exists anywhere on the user path is implemented ad hoc inside the capabilities handler, one layer down, by unmarshalling the opaque `Payload` into a `TriggerRequestPayload` and comparing its embedded `Timestamp` field against `MaxAllowedMessageAgeSec`: [3](#0-2) . This is not a property of `Message`/`Message.Validate()`, is specific to the `MethodWebAPITrigger` payload shape, and — critically — it is an age *bound*, not a replay/nonce check: any signed message that is still within `MaxAllowedMessageAgeSec` of "now" is accepted as many times as it is resubmitted. There is no tracking of already-consumed `MessageId`s to reject duplicates. The only place `MessageId` is stored is `h.savedCallbacks[msg.Body.MessageId]`, which is simply overwritten on each new call and pruned purely by age (`pruneCallbacks`), not used for duplicate detection. [4](#0-3) [5](#0-4) 

Consequently, an attacker who observes one valid signed user `Message` (e.g., from logs or a non-TLS intermediary) can resubmit the exact same bytes to the gateway HTTP endpoint repeatedly within the freshness window, and each resubmission is re-validated as authentic (`Message.Validate()` has no notion of "already seen") and re-dispatched to the DON via `don.SendToNode` for every member, causing duplicate execution attributed to the original signer. [6](#0-5) 

### Impact Explanation
This maps to Chainlink's "request impersonation / unauthorized action attributed to another user" bounty class: an attacker with no privileges beyond having observed a single signed message can trigger duplicate execution of the victim's capability request (e.g., duplicate `web-api-trigger` events sent to a workflow DON) without ever having the victim's private key. Depending on what the triggered capability does downstream (e.g., driving workflow execution, external actions), this can cause duplicate side effects billed/attributed to the victim.

### Likelihood Explanation
Feasibility is moderate-to-high: it requires only observing one legitimate signed `Message` (via logs, a shared proxy, browser history, non-TLS network path, or any place a JSON-RPC request/response is exposed) and replaying it verbatim before `MaxAllowedMessageAgeSec` elapses. No signing key, credentials, or elevated role is needed — this is purely a replay of already-valid bytes, and it is repeatable any number of times within that staleness window (and, for handler methods that don't implement any payload-level timestamp check at all, e.g. `HandleLegacyUserMessage`/dummy or other non-trigger handlers, indefinitely).

### Recommendation
Add a generic anti-replay mechanism at the `api.Message`/gateway level rather than relying on ad hoc, capability-specific payload timestamp checks: include a mandatory timestamp (and/or nonce) field in `MessageBody` covered by the signature, validate freshness generically in `Message.Validate()` (mirroring `network.AuthHeaderElems.Timestamp` handling used in `ConnectionManager.StartHandshake`), and maintain a short-lived seen-`MessageId` (or seen-signature) cache per DON/handler to reject duplicate submissions even within the freshness window.

### Proof of Concept
Go table/handler-level test plan (in `core/services/gateway/handlers/capabilities/handler_test.go` style, extending `TestHandlerReceiveHTTPMessageFromClient`):
1. Build a valid `triggerRequest` message signed once (`msg := triggerRequest(t, nodes[0].PrivateKey, ..., "", "", "")`), call `handler.HandleLegacyUserMessage(ctx, msg, cb1)` and assert it is forwarded to `don.SendToNode` for all members and produces a successful response.
2. Without changing anything (simulate an attacker who captured the request/response), call `handler.HandleLegacyUserMessage(ctx, msg, cb2)` again with the exact same bytes (same `MessageId`, same signature) — assert current behavior: `don.SendToNode` is invoked again (duplicate execution) and a new success response is returned, rather than the call being rejected as a duplicate/replay.
3. Advance a fake clock past `MaxAllowedMessageAgeSec` and resubmit — assert it is now rejected as "stale message" (confirming the only existing check is age-based, not identity/replay-based).
4. Add an assertion that no dedup/nonce store rejects step 2, demonstrating the missing generic replay protection at the `api.Message`/`gateway.ProcessRequest` layer.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}
