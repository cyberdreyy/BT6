### Title
FeeVault fee recipient can retroactively steal previously-accrued fees by rotating `feeRecipient` before `claimFees()` is called - ([File: v3/src/core/FeeVault.sol])

### Summary
`FeeVault.claimFees()` pays out the *entire* unclaimed `accruedFees` balance held in the shared `IFeeCalculator` to whichever address currently holds `feeRecipient`, rather than to the address(es) that held `feeRecipient` during the periods the fees were actually earned. Because `setFeeRecipient()` can be called at any time and fee accrual (`accruedFees`) is tracked only per-vault and not per-recipient-period, a new fee recipient can be assigned after profitable snapshots have accrued and then claim fees that rightfully belong to the prior recipient.

### Finding Description
`DelayedFeeCalculator._accrueFees()` accumulates `vaultAccruals.accruedFees` purely as a function of the vault's snapshot history (TVL/performance), with no association to who was `feeRecipient` at the time each snapshot became active: [1](#0-0) .

When fees are eventually claimed, `BaseFeeCalculator.claimFees()` simply drains the entire `vaultAccruals.accruedFees` bucket for `msg.sender` (the vault) and returns it to be paid to whoever calls `FeeVault.claimFees()`: [2](#0-1) .

`FeeVault.claimFees()` is gated only by `onlyFeeRecipient`, which checks the *current* value of `feeRecipient` storage, not who was the recipient when the fees accrued: [3](#0-2) [4](#0-3) .

`setFeeRecipient()` can reassign this address at any time, with no restriction tied to unclaimed-fee state, and no snapshot/checkpoint of "fees owed to the old recipient" is taken before the switch: [5](#0-4) .

This is the exact analog of the reported bug: rewards/fees are calculated based on activity during a past period, but paid out based on the *current* holder of a role (`owner()`/`feeRecipient`) rather than the holder during the period the fees were earned. Just as the `Rewards` contract used `VaultTokenized(vault).owner()` at distribution time instead of the owner during the epoch, `FeeVault` uses `feeRecipient` at claim time instead of tracking who was entitled to fees accrued in each period.

### Impact Explanation
Any address entitled to `feeRecipient`-earned fees for a vault loses those unclaimed fees the moment the vault authority rotates `feeRecipient` before the fees are claimed — funds are misdirected to the new recipient rather than lost outright, but from the original recipient's perspective this is a full loss/theft of legitimately earned, unclaimed fee income. This matches an Immunefi "loss of funds" impact for the party who performed/earned the fee but never gets paid, since `claimFees()` unconditionally zeroes `accruedFees` and transfers the full balance to the new `msg.sender`.

### Likelihood Explanation
No privileged protocol-wide role is required beyond the ordinary vault-level authority who is normally permitted to call `setFeeRecipient()` (an action that is part of ordinary vault administration, analogous to a vault owner/curator transferring vault ownership in the original report). The only precondition is that fees have accrued (via `submitSnapshot`/`_accrueFees`) but not yet been claimed when `setFeeRecipient` is called — a very ordinary and likely timing window (e.g., fee recipient sold/transferred, multisig rotation, or intentional front-running of a recipient change to intercept unclaimed fees).

### Recommendation
Checkpoint fee accrual to the fee recipient at the time of the switch: in `setFeeRecipient()`, first call `feeCalculator.claimFees(...)` (or an internal accrual/settlement hook) to flush/pay out `accruedFees` to the *current* `feeRecipient` before updating storage to the new address, so that fees earned under a prior recipient can never be swept by a subsequently assigned recipient.

### Proof of Concept
1. Deploy `DelayedFeeCalculator` + a `FeeVault`-derived vault with `feeRecipient = A`.
2. Have the vault's accountant call `submitSnapshot` with a profitable `averageValue`/`highestProfit`, then warp past `DISPUTE_PERIOD` so the snapshot becomes active and `_accrueFees` would credit `vaultAccruals.accruedFees` on the next touch.
3. Before `A` calls `claimFees()`, the vault authority calls `setFeeRecipient(B)`.
4. `B` calls `FeeVault.claimFees()`. Assert: `A`'s expected fee balance is 0, while `B` receives the entire `accruedFees` amount that was earned while `A` was the recipient, and `A` calling `claimFees()` afterward reverts with `Aera__CallerIsNotFeeRecipient`/`Aera__NoFeesToClaim`.

    function _accrueFees(
        VaultSnapshot storage vaultSnapshot,
        VaultAccruals storage vaultAccruals,
        uint256 lastFeeAccrualCached
    ) internal returns (uint256 protocolFeesEarned, uint256 vaultFeesEarned) {
        uint256 snapshotTimestamp = vaultSnapshot.timestamp;
        if (lastFeeAccrualCached >= snapshotTimestamp || vaultSnapshot.finalizedAt > block.timestamp) {
            // nothing to accrue
            return (0, 0);
        }

        // pending snapshot has become active, accrue fees
        (uint256 vaultPerformanceFeeEarned, uint256 protocolPerformanceFeeEarned) = _calculatePerformanceFees(
            vaultAccruals.fees.performance, vaultSnapshot.highestProfit, vaultSnapshot.lastHighestProfit
        );

        (uint256 vaultTvlFeeEarned, uint256 protocolTvlFeeEarned) = _calculateTvlFees(
            vaultAccruals.fees.tvl, vaultSnapshot.averageValue, snapshotTimestamp, lastFeeAccrualCached
        );

        // Effects: update the vault's state
        vaultSnapshot.lastHighestProfit = vaultSnapshot.highestProfit;
        vaultSnapshot.lastFeeAccrual = uint32(snapshotTimestamp);
        vaultAccruals.accruedFees += (vaultPerformanceFeeEarned + vaultTvlFeeEarned).toUint112();
        vaultAccruals.accruedProtocolFees += (protocolPerformanceFeeEarned + protocolTvlFeeEarned).toUint112();

        // Effects: delete the pending snapshot
        vaultSnapshot.averageValue = 0;
        vaultSnapshot.highestProfit = 0;
        vaultSnapshot.timestamp = 0;
        vaultSnapshot.finalizedAt = 0;

        protocolFeesEarned = protocolPerformanceFeeEarned + protocolTvlFeeEarned;
        vaultFeesEarned = vaultPerformanceFeeEarned + vaultTvlFeeEarned;
    }

    /// @inheritdoc IFeeCalculator
    function claimFees(uint256 feeTokenBalance) external virtual returns (uint256, uint256, address) {
        // Effects: hook called before claiming fees
        _beforeClaimFees();

        VaultAccruals storage vaultAccruals = _vaultAccruals[msg.sender];

        uint256 vaultEarnedFees = vaultAccruals.accruedFees;
        uint256 protocolEarnedFees = vaultAccruals.accruedProtocolFees;
        uint256 claimableProtocolFee = Math.min(feeTokenBalance, protocolEarnedFees);
        uint256 claimableVaultFee;
        unchecked {
            claimableVaultFee = Math.min(feeTokenBalance - claimableProtocolFee, vaultEarnedFees);
        }

        // Effects: update accrued fees
        unchecked {
            vaultAccruals.accruedProtocolFees = uint112(protocolEarnedFees - claimableProtocolFee);
            vaultAccruals.accruedFees = uint112(vaultEarnedFees - claimableVaultFee);
        }

        return (claimableVaultFee, claimableProtocolFee, protocolFeeRecipient);
    }

    /// @inheritdoc IFeeVault
    function claimFees() external onlyFeeRecipient returns (uint256 feeRecipientFees, uint256 protocolFees) {
        address protocolFeeRecipient;

        // Interactions: claim the fees
        (feeRecipientFees, protocolFees, protocolFeeRecipient) =
            feeCalculator.claimFees(FEE_TOKEN.balanceOf(address(this)));

        // Requirements: check that the fee recipient has earned fees
        require(feeRecipientFees != 0, Aera__NoFeesToClaim());

        // Interactions: transfer the fees to the fee recipient
        FEE_TOKEN.safeTransfer(msg.sender, feeRecipientFees);
        // Log the fees claimed event
        emit FeesClaimed(msg.sender, feeRecipientFees);

        if (protocolFees != 0) {
            // Interactions: transfer the protocol fees to the protocol fee recipient
            FEE_TOKEN.safeTransfer(protocolFeeRecipient, protocolFees);
            // Log the protocol fees claimed event
            emit ProtocolFeesClaimed(protocolFeeRecipient, protocolFees);
        }
    }
