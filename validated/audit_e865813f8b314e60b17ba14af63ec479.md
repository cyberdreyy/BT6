### Title
Uncapped JSON-parsed re-decoding cost per program/account notification tied to attacker-controlled SPL-Token-2022 account size - ([File: rpc/src/rpc_subscriptions.rs])

### Summary
`filter_account_result` and `filter_program_results` call `get_parsed_token_account`/`get_parsed_token_accounts` (and, for non-token owners, `encode_ui_account`) on every bank-commitment notification without any explicit per-notification byte/CPU budget independent of the underlying account's data length. An attacker who owns one account under a known SPL-token program can grow its data (e.g. via SPL-Token-2022 extensions) and cheaply touch it every slot to force full `jsonParsed` re-decoding on each notification tick of a single `programSubscribe`/`accountSubscribe`.

### Finding Description
`account_subscribe`/`program_subscribe` notifications are delivered via `check_commitment_and_notify`, which on every commitment-slot tick invokes `filter_account_result` or `filter_program_results` [1](#0-0) . For accounts owned by a known SPL token program with `UiAccountEncoding::JsonParsed`, these functions call `get_parsed_token_account`/`get_parsed_token_accounts`, which unconditionally invoke `encode_ui_account` with `JsonParsed` encoding regardless of account size [2](#0-1) [3](#0-2) [4](#0-3) .

`encode_ui_account`'s `JsonParsed` branch calls `parse_account_data_v3`, whose cost scales with `account.data()` length and the number/size of SPL-Token-2022 extensions packed into it [5](#0-4) . Unlike the `Binary`/`Base58` path, which enforces `MAX_BASE58_BYTES` (128 bytes) before encoding [6](#0-5) , there is no equivalent length/cost guard for the `JsonParsed` branch. The `filter_allows` pre-filter in `filter_program_results` only tests `RpcFilterType` predicates (memcmp/dataSize) supplied by the *subscriber*, not by the account owner, and does nothing to bound the cost of decoding an owner-triggered notification for a directly `accountSubscribe`d pubkey (`filter_account_result` has no filter step at all).

Once a subscription exists, notification delivery is driven by bank-commitment ticks (once per slot roughly), not by any further RPC rate limit on the subscriber. Thus a single `programSubscribe`/`accountSubscribe` call (itself subject to the described subscribe-rate-limit) results in one full `jsonParsed` decode of the entire account payload on every slot in which the account changes, and the cost of that decode is controlled entirely by the attacker via the size/extension-density of the account they own.

### Impact Explanation
This falls under "unbounded cost for a single low-rate call": a single subscription forces the validator's RPC subsystem to repeatedly perform CPU work proportional to attacker-chosen account data size (up to the network's maximum account data size) on every commitment tick, with no independent cap. This does not crash the validator or corrupt consensus state, but it creates a sustained, size-driven CPU cost per notification that is not bounded by any explicit limit in `filter_account_result`/`filter_program_results`/`get_parsed_token_accounts`, unlike the `Binary` encoding path which is explicitly capped at `MAX_BASE58_BYTES`.

### Likelihood Explanation
Feasible with the stated single-attacker, single-subscription preconditions: attacker needs one account owned by a known SPL-token program (`is_known_spl_token_id`) with maximal Token-2022 extension data, one `programSubscribe`/`accountSubscribe` with `jsonParsed` encoding, and repeated cheap writes to their own account (e.g. a memo-transfer toggle or balance change) once per slot. No elevated privileges, no additional RPC calls beyond the single subscribe, and no cooperating peers are required. The actual account size an attacker can afford is bounded by rent-exemption cost for the chosen size, which limits — but does not eliminate — the achievable amplification; this economic bound was not independently verified in this pass and would need confirmation via a live rent-cost calculation for a maximal-extension Token-2022 account.

### Recommendation
Add an explicit, size-independent cost/byte cap to the `JsonParsed` decode path analogous to `MAX_BASE58_BYTES`: e.g., skip or truncate `parse_account_data_v3`/`get_parsed_token_account(s)` for accounts whose data length exceeds a fixed threshold, falling back to `Base64`/`Base64Zstd` encoding (as already done on parse failure), and/or throttle per-subscription notification work based on measured decode time rather than solely on slot cadence.

### Proof of Concept
Rust invariant test (to be added near `rpc/src/rpc_subscriptions.rs` tests, using `filter_account_result`/`filter_program_results` directly):
1. Construct a minimal SPL-Token-2022 `Account` (no extensions) and a maximal one (fill with the full extension set, e.g. `ImmutableOwner`, `MemoTransfer`, `TransferFeeAmount`, `CpiGuard`, etc., matching the largest supported `ExtensionType::try_calculate_account_len`), both owned by `spl_token_2022_interface::id()`.
2. Call `filter_account_result(Some((account, slot)), &params_with_json_parsed, last_notified_slot, bank)` for both accounts and measure wall-clock/CPU time of `parse_account_data_v3`/`encode_ui_account` via `std::time::Instant` or `Measure`.
3. Assert that the maximal-extension case's decode time is bounded by a fixed multiplier (e.g. 2x) of the minimal case, or that a fixed cap short-circuits large accounts — expected failure of this assertion in the current code because no cap exists, decode time scales linearly (or worse) with extension count/data size.
4. Repeat for `filter_program_results` with a `Vec` containing the single attacker account, confirming `get_parsed_token_accounts` performs the same unbounded per-call decode.

fn filter_account_result(
    result: Option<(AccountSharedData, Slot)>,
    params: &AccountSubscriptionParams,
    last_notified_slot: Slot,
    bank: Arc<Bank>,
) -> (Option<UiAccount>, Slot) {
    // If the account is not found, `last_modified_slot` will default to zero and
    // we will notify clients that the account no longer exists if we haven't already
    let (account, last_modified_slot) = result.unwrap_or_default();

    // If last_modified_slot < last_notified_slot this means that we last notified for a fork
    // and should notify that the account state has been reverted.
    let account = (last_modified_slot != last_notified_slot).then(|| {
        if is_known_spl_token_id(account.owner())
            && params.encoding == UiAccountEncoding::JsonParsed
        {
            get_parsed_token_account(&bank, &params.pubkey, account, None)
        } else {
            encode_ui_account(&params.pubkey, &account, params.encoding, None, None)
        }
    });
    (account, last_modified_slot)
}

fn filter_program_results(
    accounts: Vec<(Pubkey, AccountSharedData)>,
    params: &ProgramSubscriptionParams,
    last_notified_slot: Slot,
    bank: Arc<Bank>,
) -> (impl Iterator<Item = RpcKeyedAccount> + use<>, Slot) {
    let accounts_is_empty = accounts.is_empty();
    let encoding = params.encoding;
    let filters = params.filters.clone();
    let keyed_accounts = accounts.into_iter().filter(move |(_, account)| {
        filters
            .iter()
            .all(|filter_type| filter_allows(filter_type, account))
    });
    let accounts = if is_known_spl_token_id(&params.pubkey)
        && params.encoding == UiAccountEncoding::JsonParsed
        && !accounts_is_empty
    {
        let accounts = get_parsed_token_accounts(bank, keyed_accounts);
        Either::Left(accounts)
    } else {
        let accounts = keyed_accounts.map(move |(pubkey, account)| RpcKeyedAccount {
            pubkey: pubkey.to_string(),
            account: encode_ui_account(&pubkey, &account, encoding, None, None),
        });
        Either::Right(accounts)
    };
    (accounts, last_notified_slot)
}

pub fn get_parsed_token_account(
    bank: &Bank,
    pubkey: &Pubkey,
    account: AccountSharedData,
    // only used for simulation results
    overwrite_accounts: Option<&HashMap<Pubkey, AccountSharedData>>,
) -> UiAccount {
    let additional_data = get_token_account_mint(account.data())
        .and_then(|mint_pubkey| {
            account_resolver::get_account_from_overwrites_or_bank(
                &mint_pubkey,
                bank,
                overwrite_accounts,
            )
        })
        .and_then(|mint_account| get_additional_mint_data(bank, mint_account.data()).ok())
        .map(|data| AccountAdditionalDataV3 {
            spl_token_additional_data: Some(data),
        });

    encode_ui_account(
        pubkey,
        &account,
        UiAccountEncoding::JsonParsed,
        additional_data,
        None,
    )
}

pub fn get_parsed_token_accounts<I>(
    bank: Arc<Bank>,
    keyed_accounts: I,
) -> impl Iterator<Item = RpcKeyedAccount>
where
    I: Iterator<Item = (Pubkey, AccountSharedData)>,
{
    let mut mint_data: HashMap<Pubkey, AccountAdditionalDataV3> = HashMap::new();
    keyed_accounts.filter_map(move |(pubkey, account)| {
        let additional_data = get_token_account_mint(account.data()).and_then(|mint_pubkey| {
            mint_data.get(&mint_pubkey).cloned().or_else(|| {
                let (_, data) = get_mint_owner_and_additional_data(&bank, &mint_pubkey).ok()?;
                let data = AccountAdditionalDataV3 {
                    spl_token_additional_data: Some(data),
                };
                mint_data.insert(mint_pubkey, data);
                Some(data)
            })
        });

        let maybe_encoded_account = encode_ui_account(
            &pubkey,
            &account,
            UiAccountEncoding::JsonParsed,
            additional_data,
            None,
        );
        if let UiAccountData::Json(_) = &maybe_encoded_account.data {
            Some(RpcKeyedAccount {
                pubkey: pubkey.to_string(),
                account: maybe_encoded_account,
            })
        } else {
            None
        }
    })
}
