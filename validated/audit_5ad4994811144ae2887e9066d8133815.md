## Finding: Confirmed — Beneficiary Redirection Is Lost For Unresolved Commission Distributions After `switch_operator`/`switch_operator_with_same_commission`

### Summary
`switch_operator` (and its wrapper `switch_operator_with_same_commission`) does force a `distribute_internal` call before moving the `StakingContract` to the new operator's key, but that call only flushes stake that is *already* matured (`inactive`, or `pending_inactive` whose lockup has expired). Any commission that was requested via `request_commission_internal` but whose underlying stake is still locked (`pending_inactive`, lockup not yet expired) is **not** paid out at switch time — it remains recorded as unredeemed shares in `staking_contract.distribution_pool`, keyed to the *old_operator* address. Because the `distribution_pool` lives inside the `StakingContract` struct, it moves intact to the new map entry under `new_operator`. When `distribute` is later called (by anyone), `distribute_internal` is invoked with `operator = new_operator`, and its beneficiary-redirection check `if (recipient == operator) { recipient = beneficiary_for_operator(operator) }` only matches the *current* operator, not the stale `old_operator` recorded in the pool. The old operator's already-earned commission is therefore paid directly to the old operator's own address instead of to the beneficiary they had registered via `set_beneficiary_for_operator`.

### Finding Description
`switch_operator` at [1](#0-0)  removes the `StakingContract` for `old_operator`, calls `distribute_internal` (correctly passing `old_operator` at this point) and `request_commission_internal`, then re-inserts the *same* struct under `new_operator`.

`distribute_internal` at [2](#0-1)  only withdraws `inactive + pending_inactive` via `stake::withdraw_with_cap`, and `withdraw_with_cap` caps the actual amount returned to what has genuinely matured — `pending_inactive` is only merged into `inactive` if the validator is `VALIDATOR_STATUS_INACTIVE` and the lockup has expired: [3](#0-2) . If the pool is still an active validator or the lockup has not expired, the coins are not withdrawn, so `distribute_internal` returns without fully draining shares in `distribution_pool` (any unmatched shares remain recorded for `old_operator`).

Once the `StakingContract` (carrying its `distribution_pool` with the leftover `old_operator` share) is re-keyed to `new_operator`, subsequent calls to `distribute(staker, new_operator)` invoke `distribute_internal(staker, new_operator, staking_contract)`. The recipient-to-beneficiary redirect logic is: [4](#0-3) 
Since `recipient == old_operator` but the function's `operator` parameter is now `new_operator`, the condition `recipient == operator` is false, so the funds are deposited directly to `old_operator`'s address rather than being redirected to `beneficiary_for_operator(old_operator)`.

### Impact Explanation
The old operator's beneficiary — an address explicitly set via `set_beneficiary_for_operator` at [5](#0-4)  to receive commission payouts — loses its claim on commission that was accrued and requested prior to a `switch_operator` call, whenever the underlying stake had not yet fully matured (locked past the current lockup cycle) at switch time. The payment silently reroutes to the old operator's own account instead of the beneficiary. This is triggered entirely by the unprivileged `staker` calling `switch_operator_with_same_commission`/`switch_operator`, and the payout is later triggered by anyone calling the permissionless `distribute` entry function.

### Likelihood Explanation
This requires a specific but realistic timing window: commission must have been requested (`request_commission`/`request_commission_internal`) shortly before the lockup expires, and the staker switches operator within that window. Given commission requests and operator switches are both routine staker-controlled entry points, and lockup cycles are ~30 days on mainnet, this window is not contrived — it's a natural race between a staker-initiated switch and an operator's already-requested, not-yet-matured commission.

### Recommendation
`distribute_internal` should not rely on the fresh `operator` parameter for beneficiary redirection; it should look up the recipient's own `beneficiary_for_operator(recipient)` for every shareholder that is itself an operator-type recipient, not just the current map key. Alternatively, `switch_operator` should fully settle (or reject switching until) all pending distribution-pool shares for `old_operator` are resolved, or record the correct beneficiary address directly into the distribution pool entry (at `add_distribution` time) instead of resolving beneficiary lazily at `distribute_internal` time based on the current operator argument.

### Proof of Concept
1. Staker creates a staking contract with `operator_1`, contract joins validator set.
2. `operator_1` calls `set_beneficiary_for_operator(beneficiary_1)`.
3. Rewards accrue; `request_commission` is called, moving commission into `pending_inactive` via `stake::unlock_with_cap` and recording a distribution share for `operator_1` in `distribution_pool` (see [6](#0-5) ).
4. Before the lockup cycle expires (so the `pending_inactive` coins have not matured into `inactive`), staker calls `switch_operator_with_same_commission(operator_1, operator_2)`. The forced `distribute_internal` inside `switch_operator` withdraws 0 (or partial) coins because `withdraw_with_cap` caps to genuinely `inactive` value, leaving the `operator_1` share pending in `distribution_pool`.
5. Time passes until lockup expires; anyone calls `distribute(staker, operator_2)`.
6. `distribute_internal` runs with `operator = operator_2`; the leftover share for `operator_1` is redeemed and paid directly to `operator_1`'s account address instead of `beneficiary_1`, because `recipient (operator_1) != operator (operator_2)` skips the `beneficiary_for_operator` redirect at [7](#0-6) .
7. Assertion `beneficiary_1` balance increased by the pre-switch commission amount fails — the beneficiary's claim was bypassed.

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }

    /// Withdraw from `pool_address`'s inactive stake with the corresponding `owner_cap`.
    public fun withdraw_with_cap(
        owner_cap: &OwnerCapability, withdraw_amount: u64
    ): Coin<AptosCoin> acquires StakePool, ValidatorSet {
        assert_reconfig_not_in_progress();
        let pool_address = owner_cap.pool_address;
        assert_stake_pool_exists(pool_address);
        let stake_pool = borrow_global_mut<StakePool>(pool_address);
        // There's an edge case where a validator unlocks their stake and leaves the validator set before
        // the stake is fully unlocked (the current lockup cycle has not expired yet).
        // This can leave their stake stuck in pending_inactive even after the current lockup cycle expires.
        if (get_validator_state(pool_address) == VALIDATOR_STATUS_INACTIVE
            && timestamp::now_seconds() >= stake_pool.locked_until_secs) {
            let pending_inactive_stake =
                coin::extract_all(&mut stake_pool.pending_inactive);
            coin::merge(&mut stake_pool.inactive, pending_inactive_stake);
        };

        // Cap withdraw amount by total inactive coins.
        withdraw_amount = min(withdraw_amount, coin::value(&stake_pool.inactive));
        if (withdraw_amount == 0) return coin::zero<AptosCoin>();

        event::emit(WithdrawStake { pool_address, amount_withdrawn: withdraw_amount });

        coin::extract(&mut stake_pool.inactive, withdraw_amount)
    }
