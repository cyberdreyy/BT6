No key-format validation exists anywhere in this repo's Go source for `variable.Key`/secret `variableKey` before it's used to build the file-based-variable path.

### Title
Unsanitized secret `variableKey` used as file-variable name enables path traversal / cross-job file overwrite - ([File: common/secrets.go])

### Summary
`handleSecret` builds a `spec.Variable{Key: variableKey, File: secret.IsFile()}` directly from the pipeline-author-controlled `secrets:` map key with no sanitization. When `File` is true, shell writers (`shells/bash.go` `Variable()`/`TmpFile()`, `shells/powershell.go` `Variable()`/`TmpFile()`) join this raw key onto the job's temporary-variables directory using `path.Join`/`path.Clean` without rejecting `..` or path separators, so a crafted key can make the on-disk write target escape the job's variables directory.

### Finding Description
`handleSecret` (`common/secrets.go:116-146`) sets `variable.Key = variableKey` verbatim — `variableKey` is the map key of the `secrets:` block, i.e., attacker/pipeline-author-controlled input, with no format check anywhere in the repo (no regex/identifier validation for secret or variable keys was found in `common/`, `shells/`, or elsewhere).

That `Variable` (with `File: true`, the default per `Secret.IsFile()` at `common/spec/spec.go:678-684`) is later rendered by the shell writers:
- `shells/bash.go:211-213` `TmpFile(name)` → `cleanPath(path.Join(b.TemporaryPath, name))`, and `cleanPath`/`Absolute` (`shells/bash.go:361-366`) only special-case `IsAbs`/`$PWD` prefix, otherwise `path.Join("$PWD", dir)`.
- `shells/bash.go:229-241` `Variable()` then does `printf '%s' <value> > <variableFile>` and `export KEY=<variableFile>` — a raw file write to whatever path `TmpFile` produced.
- `shells/powershell.go:438-457` does the analogous `[System.IO.File]::WriteAllText(...)` write.

`path.Join`/`filepath.Join` call `Clean`, which resolves `..` lexically. Because `TemporaryPath` in real deployments is typically an absolute path such as `/builds/<concurrent-id>/<namespace>/<project>.tmp` (shell executor, `executors/shell/shell.go:31-60` makes `DefaultBuildsDir`/`DefaultCacheDir` absolute), a key like `"../../../../otherproject/.git/hooks/post-checkout"` collapses via `Clean` to an absolute path outside the intended `TemporaryPath` (Go's `path.Clean` only clamps excess `..` at the filesystem root, not at `TemporaryPath`). No component of the write path is validated to remain under `TemporaryPath` before the shell script performs the write. Existing protections that could stop this — checkout/cache overwrite guards, path validation, masking — are all no-ops here: masking only affects log output, and there is no path-confinement check in `TmpFile`/`cleanPath`/`Absolute` or in `handleSecret`.

### Impact Explanation
On a shell executor host running multiple concurrent jobs (a normal, non-privileged, documented Runner configuration — not admin-misconfiguration), a job whose pipeline defines a crafted `secrets:` key can cause the runner to write attacker-controlled secret content to an arbitrary absolute path reachable by the `gitlab-runner` OS user, including another job's checkout, cache, or helper state files under the shared `/builds` (or configured builds/cache root) tree. This is a cross-job file overwrite / unauthorized file write outside the job's own root, matching the scoped impact.

### Likelihood Explanation
Preconditions: shell executor (or any executor where the file-variable write happens on a shared filesystem visible to other jobs) with concurrent job execution enabled, and the ability for a pipeline author to define a `secrets:` block with an attacker-chosen key. Whether this is actually reachable end-to-end depends on whether GitLab's server-side (Rails) CI-lint enforces a strict identifier pattern on `secrets:` keys before the payload is ever sent to Runner — that enforcement lives outside this repository and could not be verified here. Within the Runner codebase itself, however, there is no independent, defense-in-depth check on `variableKey`/`Variable.Key`, so if the upstream key format restriction is ever bypassed, weakened, or not applied uniformly (e.g., a different job-submission path, custom executor, or future config schema change), the Runner has no safety net.

### Recommendation
In `handleSecret` (`common/secrets.go`), or centrally in `spec.Variable`/`shells` file-variable writers, validate/sanitize `Key` before treating it as a file name component: reject keys containing `/`, `\`, or `..`, or explicitly use `filepath.Base` and re-verify the resulting joined path (via `filepath.Rel`/prefix check) stays within `TemporaryPath` before performing any write, in both `BashWriter.TmpFile`/`Variable` and `PsWriter.TmpFile`/`Variable`.

### Proof of Concept
Go unit test extending `Test_BashWriter_Variable` (`shells/bash_test.go`):
```go
func Test_BashWriter_Variable_PathTraversal(t *testing.T) {
    w := BashWriter{TemporaryPath: "/builds/proj.tmp"}
    v := spec.Variable{Key: "../../../other_proj/.git/hooks/post-checkout", Value: "evil", File: true}
    w.Variable(v)
    out := w.String()
    // Assert the write target is confined to TemporaryPath.
    assert.NotContains(t, out, "other_proj", "file write escaped job's TemporaryPath via traversal in Key")
}
```
Expected today: the produced script contains a `printf ... > "/builds/other_proj/.git/hooks/post-checkout"` line, i.e., the assertion fails, proving the path is not confined. A fuzz test over `variableKey` strings (containing `../`, absolute paths, `\` on Windows) through `handleSecret` → `TmpFile` should assert `strings.HasPrefix(resultPath, TemporaryPath)` always holds. func (r *defaultSecretsResolver) handleSecret(variableKey string, secret spec.Secret) (*spec.Variable, error) {
	sr, err := r.secretResolverRegistry.GetFor(secret)
	if err != nil {
		r.logger.Warningln(fmt.Sprintf("Not resolved: %v", err))
		return nil, nil
	}

	r.logger.Println(fmt.Sprintf("Using %q secret resolver...", sr.Name()))

	value, err := sr.Resolve()
	if errors.Is(err, ErrSecretNotFound) {
		if !r.featureFlagOn(featureflags.EnableSecretResolvingFailsIfMissing) {
			err = nil
		} else {
			err = fmt.Errorf("%w: %v", err, variableKey)
		}
	}
	if err != nil {
		return nil, err
	}

	variable := &spec.Variable{
		Key:    variableKey,
		Value:  value,
		File:   secret.IsFile(),
		Masked: true,
		Raw:    true,
	}

	return variable, nil
}

func (b *BashWriter) Variable(variable spec.Variable) {
	if variable.File {
		variableFile := b.TmpFile(variable.Key)
		b.Linef("mkdir -p %q", helpers.ToSlash(b.TemporaryPath))
		b.Linef("printf '%%s' %s > %q", b.escape(variable.Value), variableFile)
		b.Linef("export %s=%q", b.escape(variable.Key), variableFile)
	} else {
		if b.isTmpFile(variable.Value) {
			variable.Value = b.cleanPath(variable.Value)
		}
		b.Linef("export %s=%s", b.escape(variable.Key), b.escape(variable.Value))
	}
}
