## Title
Confirmations from removed multisig members remain counted toward the execution threshold, allowing a request to execute with fewer live members than `num_confirmations` requires - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` removes a departing member from `self.members` and deletes only the *requests that member itself originally submitted* [1](#0-0) . It never scrubs that member's *confirmations* recorded on other, still-pending requests that were submitted by different members. `confirm()` counts entries in the `confirmations` set purely by size/membership against `self.num_confirmations`, without re-validating that every signer stored in that set is still a current member [2](#0-1) . As a result, a stale confirmation from a since-removed member is treated as equivalent to a confirmation from a live member, letting a request execute (moving funds, adding/removing keys, deploying contracts, etc.) with fewer *actual* live-member approvals than the configured threshold.

### Finding Description
The intended binding is:

```
count(confirmations[request_id]) >= num_confirmations  ⇒  count(live members who confirmed) >= num_confirmations
```

The code breaks this equality. Walk through the state machine:

1. Member A adds a pending request R (not yet confirmed enough). `add_request` stores `MultiSigRequestWithSigner { member: A, ... }` and creates an empty confirmation set for R [3](#0-2) .
2. Member B calls `confirm(R)`. `confirm` looks up `current_member()`, and since B is currently in `self.members`, `B.to_string()` is inserted into `confirmations[R]` [2](#0-1) [4](#0-3) .
3. Before R reaches the confirmation threshold, the multisig (via a separate, already-executed `DeleteMember` request) removes member B. `delete_member` is invoked:
   ```rust
   fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
       ...
       // delete outstanding requests by public_key
       let request_ids: Vec<u32> = self
           .requests
           .iter()
           .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
           .collect();
       for request_id in request_ids {
           self.confirmations.remove(&request_id);
           self.requests.remove(&request_id);
       }
       self.num_requests_pk.remove(&member.to_string());
       self.members.remove(&member);
       ...
   }
   ``` [5](#0-4) 

   This filter only matches requests whose `.member` field equals the member being deleted — i.e., requests *B originated*. Request R was originated by A, not B, so R is not in `request_ids`, and B's confirmation entry inside `confirmations[R]` is never removed. `self.members.remove(&member)` removes B from the member set, but the stale confirmation string for B persists in `confirmations[R]`.

4. Later, another live member C confirms R. `confirm` re-checks only that C (the *current* signer) hasn't already confirmed, and that `confirmations.len() as u32 + 1 >= self.num_confirmations` [2](#0-1) . It never iterates the existing confirmation set to verify every prior signer (here, B) is still `self.members.contains(...)`. So the stale B confirmation plus the new C confirmation can trip `num_confirmations`, and `execute_request(R)` fires — dispatching a `Transfer`, `AddKey`, `FunctionCall`, etc. [6](#0-5) .

This is the same bug class as the report: a value computed at one point in time (the confirmation set snapshot) is trusted later without being refreshed against the current authoritative state (`self.members`), exactly analogous to stale emission indexes being trusted for reward calculation instead of being refreshed against the live market state.

### Impact Explanation
This is **Critical**: a multisig request (including `Transfer`, `AddKey` with full access permission, `DeployContract`, `FunctionCall`) can be executed with confirmations that do not correspond to `num_confirmations` *currently live* members. A member who has been intentionally removed (e.g., for being compromised or having left the organization) retains latent authorization power over any request that was pending at the time of their removal and that they had already confirmed. This directly breaks the multisig's core custody guarantee — the threshold `K` of `N` — since `K` confirming principals no longer all belong to the currently authorized `N`. Funds can move, or a full-access key can be added to the contract, with authorization effectively below the configured threshold.

### Likelihood Explanation
Requires no privileged access beyond being (or having been) a legitimate multisig member — precisely the kind of party the multisig is meant to constrain by both count and set membership. The scenario (a member confirms a request, is later removed for cause, and the pending request is later pushed over threshold by remaining members) is a normal, expected sequence of multisig operations, not a contrived edge case, making this readily reachable in production usage of the deployed `multisig2` contract.

### Recommendation
When executing `delete_member`, iterate over **all** pending requests' confirmation sets (not just those authored by the removed member) and strip the removed member's identifier from each. Alternatively, in `confirm()` (and ideally also when computing whether the threshold is met), filter/re-validate the confirmation set against `self.members` before comparing its size to `self.num_confirmations`, so that only confirmations from currently live members count toward execution.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. A calls `add_request(R)` (e.g., `Transfer` of the account's balance to an outside address). `requests[R].member = A`, `confirmations[R] = {}`.
3. B calls `confirm(R)` → `confirmations[R] = {B}` (2 short of threshold, no execution).
4. Separately, a fully-confirmed `DeleteMember{ member: B }` request executes: `self.members` becomes `{A, C, D}`; `delete_member` scans `requests` for entries with `.member == B` — R is not touched (it was authored by A) — so `confirmations[R]` still equals `{B}`.
5. C calls `confirm(R)` → `confirmations[R] = {B, C}`, size 2, still below 3 — but assume `num_confirmations` was 2 instead of 3 for a tighter PoC, or add one more live confirmer, D, calling `confirm(R)` → size becomes 3, `confirm` executes `R` via `execute_request` [7](#0-6) .
6. The transfer executes with confirmations `{B, C, D}` even though B is no longer a member — i.e., only 2 of the 3 confirmations come from currently authorized members, one confirmation-count short of the true, live threshold.

    pub fn add_request(&mut self, request: MultiSigRequest) -> RequestId {
        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(
                "Predecessor must be a member or transaction signed with key of given account",

            .get(&current_member.to_string())
            .unwrap_or(0)

            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);

            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,

                        )

                    }
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name,
                    args.into(),
                    deposit.into(),
                    Gas::from(gas.0),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);

                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
