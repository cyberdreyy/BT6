## Analysis: Tenure-wide reorg permit voids double-sign protection for non-globally-accepted conflicting blocks

I traced the "signed vs validated" / one-block-per-height equivocation guard through `stacks-signer/src/chainstate/mod.rs`, `stacks-signer/src/v0/signer.rs`, and `stacks-signer/src/signerdb.rs`. I found a scope mismatch between the check that *grants* a reorg permit and the check that *consumes* it, but I was not able to fully read the bodies of `get_first_approved_block_in_tenure` and `get_globally_accepted_block_count_in_tenure` (only located their declarations) before running out of tool budget, so the exact counting semantics of those two helpers are not 100% confirmed from source, only inferred from their names/usage and doc comments.

### Title
Tenure-scoped reorg permit excludes signed-but-not-globally-accepted conflicting blocks it never evaluated - (File: stacks-signer/src/chainstate/mod.rs, stacks-signer/src/signerdb.rs, stacks-signer/src/v0/signer.rs)

### Summary
`check_parent_tenure_choice` decides whether to sanction a miner reorging away from a prior tenure, gated on that tenure having at most one *globally accepted* block [1](#0-0) . If permitted, the whole tenure (keyed only by `consensus_hash`) is recorded as superseded [2](#0-1) . But the double-sign guard that later consults this permit, `get_signed_conflicts`, returns *every* block in that tenure that was ever signed (`signed_self` or `signed_group` set) — a broader set than "globally accepted", including `LocallyAccepted` blocks that reached the 70% pre-commit/signature threshold but were never confirmed processed by the node — and blankets all of them with the same `superseded_by` annotation via a plain `consensus_hash` join [3](#0-2) . `reorg_permit_stands`, which decides whether to actually exclude a conflict, only checks whether the *permitting sortition* is still canonical — it has no notion of which specific block the timing analysis was performed against [4](#0-3) .

### Finding Description
The equality the codebase relies on to prevent equivocation is: "a signer must not sign a second block at a height/tenure where it (or the quorum) already signed a conflicting one, unless that specific conflict is provably dead or its replacement was explicitly sanctioned." The sanctioning mechanism (`check_parent_tenure_choice`) only inspects the tenure's *first* mined block and the tenure's *globally accepted* block count (`> 1` blocks it) [5](#0-4) . It never inspects blocks that reached the 70% signature threshold but are stuck at `LocallyAccepted` (e.g., a node relay delay or crash before the aggregated block was posted) — those are invisible to `get_globally_accepted_block_count_in_tenure` by construction (the docs elsewhere confirm reaching 70% only marks a block *locally* accepted; global acceptance is a separate node-confirmed event) [6](#0-5) .

Once the reorg is sanctioned for that one (globally-accepted) block, `mark_tenure_superseded` records the permit against the *tenure*, not the specific block [7](#0-6) . `get_signed_conflicts` then LEFT JOINs `superseded_tenures` purely on `consensus_hash`, so any other signed block in that same tenure — including a different, never-evaluated `LocallyAccepted` block at a *different, possibly higher* height — is silently annotated as "permitted" too [8](#0-7) . `reorg_permit_stands` then excludes it outright as long as the permitting sortition is canonical, with no re-derivation of whether *that particular* block's replacement was ever actually sanctioned [4](#0-3) .

### Impact Explanation
If a tenure T produces two blocks — block@h (globally accepted, satisfies the `<=1` count) and block@h+1 (reached 70% pre-commit weight and was signed by this and other signers, but never confirmed globally accepted, e.g. due to a relay hiccup) — and a miner then proposes a competing tenure U whose "first" reorged tenure information only reflects T's first/globally-accepted block, `check_parent_tenure_choice` can sanction the reorg and mark all of T as superseded. From that point, `reorg_permit_stands` will unconditionally exclude *both* block@h and block@h+1 as conflicts for any new proposal in U, even though block@h+1's replacement was never evaluated by the timing rule at all. A signer that already signed block@h+1 (contributing to a 70%-weight signature set that could still surface later if the node processes it, per the doc's "rejection/pendency does not clear a conflict" invariant) can then also sign a conflicting block at height h+1 in tenure U. This is a direct break of the "at most one signed block per height" equivocation guard — a Critical-class outcome (a signer signing a conflicting block) per the rules of this exercise.

### Likelihood Explanation
Triggering the underlying reorg-permit path requires only a one-slot miner: it is normal, permitted behavior for a miner to reorg off a tenure whose sole globally-accepted block was proposed "late" relative to the next sortition (this is the intended feature this code implements, documented in `docs/signer-flows.md` section 8). The additional condition needed for the impact — a second, `LocallyAccepted`-but-not-globally-accepted block existing in the same tenure at the time of the reorg — is a plausible, network-timing-dependent (not attacker-controlled with certainty) condition, but not implausible: it can arise from ordinary node/relay delay or a `BlockPreCommit` race that lets the 70% pre-commit/signature threshold reached moments before a competing sortition/tenure switch. No majority-signer collusion or other signer's key is required; only the honest quorum's own prior votes and the timing window are involved. Confidence in the exact reachability is moderate: I confirmed the query/data-model layer but could not read `get_first_approved_block_in_tenure`/`get_globally_accepted_block_count_in_tenure`'s bodies to rule out additional guards there that might restrict `first_block_mined` selection or the accepted-block count to also cover `LocallyAccepted` states.

### Recommendation
- Scope `mark_tenure_superseded`/the resulting `get_signed_conflicts` exclusion to the specific block(s) that were actually evaluated for reorg-timing legitimacy, not the entire tenure by `consensus_hash`.
- Change the pre-permit guard in `check_parent_tenure_choice` to count all *signed* blocks (any block with `signed_self`/`signed_group` set, matching the definition used by `get_signed_conflicts`) rather than only `GloballyAccepted` ones, so a tenure with any quorum-endorsed block beyond the first cannot be blanket-sanctioned.
- Alternatively, have `reorg_permit_stands`/`get_signed_conflicts` re-derive per-conflict whether *that block's own* replacement was sanctioned (e.g., by recording the specific `signer_signature_hash` or height covered by the permit) instead of keying solely off the superseded tenure's `consensus_hash`.

### Proof of Concept
Not independently reproducible from the index alone (would require a running signer/node harness). The reasoning chain is: (1) tenure T produces block@h (globally accepted) and block@h+1 (70%-signed, `LocallyAccepted`, never confirmed by node); (2) miner proposes tenure U reorging off T's parent; (3) `check_parent_tenure_choice` sees `get_globally_accepted_block_count_in_tenure(T) == 1`, checks only block@h's timing, and sanctions the reorg, calling `mark_tenure_superseded(T, ...)` [9](#0-8) ; (4) a later proposal in U at height h+1 triggers `get_signed_conflicts`, which returns block@h+1 annotated with the same `superseded_by` record as block@h [3](#0-2) ; (5) `reorg_permit_stands` returns true for both, so the signer signs U's block@h+1 without ever having its replacement legitimacy evaluated by the timing rule [10](#0-9) .

    pub fn get_signed_conflicts(
        &self,
        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,
    ) -> Result<Vec<SignedConflictInfo>, DBError> {
        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,
                MAX(COALESCE(b.signed_self, 0), COALESCE(b.signed_group, 0)) AS last_endorsed,
                st.superseded_by_consensus_hash, st.superseded_by_burn_block_hash
            FROM blocks b
            LEFT JOIN superseded_tenures st ON st.consensus_hash = b.consensus_hash
            WHERE (b.signed_self IS NOT NULL OR b.signed_group IS NOT NULL)
                AND b.stacks_height >= ?1
                AND b.signer_signature_hash != ?2
            ORDER BY b.stacks_height DESC";
        let args = params![
            u64_to_sql(height)?,
            excluded_signer_signature_hash.to_string(),
        ];
        query_rows(&self.db, query, args)
    }
