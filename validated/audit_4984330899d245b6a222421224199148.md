### Title
Missing future-timestamp bound allows freshness/staleness check bypass in gateway `HandleLegacyUserMessage` - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The report's bug class is a flawed time-window arithmetic check reachable by an unprivileged actor, which can be trivially defeated at its edge case. The closest analog reachable from an unprivileged client request in this repo is the message-freshness check performed by the internet-facing gateway's `capabilities` handler on `web_api_trigger` requests, `HandleLegacyUserMessage`, which only bounds messages from being *too old* but never bounds them from being *in the future*, and performs the check using unsigned integer subtraction with an attacker-controlled operand.

### Finding Description
`HandleLegacyUserMessage` is the entry point the gateway's `capabilities` handler uses for legacy webhook/web-API-trigger requests coming straight from an unprivileged client through `gateway.ProcessRequest`: [1](#0-0) 

The handler decodes an attacker-supplied JSON payload containing a `Timestamp` field, then performs the only freshness check on it: [2](#0-1) 

The check is:
```go
if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
    // reject as stale
}
```
This only rejects `payload.Timestamp` values that are older than `now - MaxAllowedMessageAgeSec`. It never validates an upper bound, so a client can set `Timestamp` to any value in the future (e.g. `now + 10 years`) and the condition will never be true, permanently defeating the staleness/freshness guard for that message. This mirrors the report's core defect class: a time-derived boundary check with an asymmetric edge case an unprivileged caller can exploit by choosing an adversarial input value, similar to how a staker could always keep `passedDays == 0` to avoid a code path.

In addition, the subtraction is unsigned (`uint`), so if `MaxAllowedMessageAgeSec` (an operator-configured value) were ever comparable in magnitude to the current unix time, the subtraction would wrap around; this is not attacker-triggerable under realistic configuration but is a code smell consistent with the same "unchecked integer truncation/arithmetic on time values" bug class flagged in the report.

### Impact Explanation
The freshness check is the only defense in this legacy code path against replaying/using very old signed messages for `web_api_trigger` (per the `TODO: apply allowlist and rate-limiting here` comment, no allowlist or additional rate limiting is applied here yet). By supplying a future timestamp, an unprivileged client bypasses the intended message-age boundary entirely, undermining the freshness/anti-replay assumption for messages routed to DON member nodes via `don.SendToNode`. This weakens the gateway's message-envelope validation guarantees on an internet-facing entry point, though the actual blast radius is bounded by the fact that the message is still ordinarily forwarded and processed only if it otherwise validates (`common.ValidatedRequestFromMessage`, `msg.Validate()`).

### Likelihood Explanation
High for triggerability: the `Timestamp` field is a plain caller-controlled JSON field in `webapicap.TriggerRequestPayload`, requiring no authentication beyond reaching the public gateway HTTP endpoint, and the missing upper-bound check is unconditional (no config combination fixes it).

### Recommendation
Add an explicit upper-bound check rejecting timestamps that are in the future beyond a small clock-skew tolerance, e.g.:
```go
now := uint(time.Now().Unix())
ts := uint(payload.Timestamp)
if now > h.config.MaxAllowedMessageAgeSec && now-h.config.MaxAllowedMessageAgeSec > ts {
    // too old
}
if ts > now+allowedClockSkewSec {
    // too far in the future
}
```
Also guard the subtraction against underflow, and consider using signed `int64` duration arithmetic instead of raw `uint` subtraction for clarity and safety.

### Proof of Concept
1. Send a JSON-RPC "legacy" request to the gateway's public HTTP endpoint targeting a DON with `web_api_trigger` payload where `Timestamp = time.Now().Unix() + 315360000` (10 years in the future).
2. `HandleLegacyUserMessage` computes `uint(time.Now().Unix()) - MaxAllowedMessageAgeSec > uint(payload.Timestamp)`; since `payload.Timestamp` is far larger than `time.Now().Unix()`, the condition is always `false`, so the "stale message" branch never triggers regardless of how the message is actually used/replayed later.
3. The request proceeds to be forwarded to all DON members via `don.SendToNode`, with the freshness guarantee effectively disabled for attacker-chosen future timestamps. [3](#0-2) 

**Note on scope confidence:** I was not able to fully trace whether any additional freshness/replay check exists downstream (e.g., at the DON node side) that would further mitigate this specific gap; the index does not show such a check being applied before `don.SendToNode` in this file. If a stronger validation exists elsewhere in the request pipeline that I could not locate via search, it may reduce the severity of this finding.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
