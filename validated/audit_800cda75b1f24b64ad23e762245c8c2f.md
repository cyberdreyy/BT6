### Title
Unauthenticated DoS via panic in `normalizeHex` triggered by omitting the "0x" prefix on `workflowID`/`workflowOwner` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateHexInput` only bounds `len(input)` to the *maximum length including the `0x` prefix* (66 for `workflowID`, 42 for `workflowOwner`) but does not require the `0x` prefix to actually be present. An attacker can submit a workflowID/workflowOwner of exactly the max length with no `0x` prefix (e.g., 66 hex chars for workflowID), which passes `validateHexInput`, but then in `normalizeHex` the computed pad count `expectedHexLength-len(hexStr)` becomes negative, and `strings.Repeat` panics.

### Finding Description
`validateHexInput` checks: [1](#0-0) 

It rejects inputs longer than `expectedLength` (which includes the 2-character `0x` prefix), and calls `hex.DecodeString` after trimming an *optional* `0x` prefix — it never enforces that the prefix is present. A 66-character lowercase hex string with no `0x` prefix (e.g. 33 raw bytes hex-encoded, even length, valid hex) satisfies `len(input) <= 66` and decodes successfully, so `validateWorkflowID`/`validateWorkflowOwner` pass it through: [2](#0-1) 

This validated string then flows into `resolveWorkflowID` → `normalizeHex`: [3](#0-2) 

Since there's no `0x` prefix to strip, `hexStr` retains its full 66-character length, while `expectedHexLength = workflowIDLength-2 = 64`. The pad count `expectedHexLength-len(hexStr)` evaluates to `64-66 = -2`, and `strings.Repeat("0", -2)` panics with `"strings: negative Repeat count"`. The same applies to `workflowOwner` with `workflowOwnerLength=42` (`expectedHexLength=40`), reachable via the owner/name/tag lookup branch of `resolveWorkflowID`: [4](#0-3) 

This code path is reached directly from `HandleUserTriggerRequest`, which is invoked from `gatewayHandler.HandleJSONRPCUserMessage` for every incoming, unauthenticated user JSON-RPC trigger request (authorization/signature checks happen *after* `resolveWorkflowID`, at `authorizeRequest`, so the panic occurs before any authentication of the caller): [5](#0-4) [6](#0-5) 

No `recover()` wraps this call chain in the reviewed files (only test files use `recover()` in this package), so an unrecovered panic here will propagate and, per Go semantics, crash the whole process unless caught by an outer framework-level recovery that is not visible in this code path.

Regarding the second half of the question (workflow-ID collision from padding): the intended design of `normalizeHex` is canonicalization — shorter valid hex strings are zero-padded to the canonical 32-byte/20-byte representation, and this is a deliberate normalization to the numeric value, not an exploitable collision between distinct legitimate workflow IDs (a short and its zero-padded canonical form represent the same value by design). I found no evidence this can be used to make one workflow's request resolve to a *different, distinct* workflow's registered ID.

### Impact Explanation
An unauthenticated caller of `HandleUserTriggerRequest` (via the gateway's HTTP/JSON-RPC trigger endpoint) can send a single malformed `workflowID` or `workflowOwner` (max-length hex string missing the `0x` prefix) to trigger a Go runtime panic inside gateway request-handling code, before authentication of the request occurs. This matches the Denial-of-Service bounty class: repeated exploitation can crash/restart the gateway process, disrupting HTTP trigger delivery for all workflows served by that gateway node.

### Likelihood Explanation
No special privileges or credentials are required — only the ability to send a JSON-RPC `workflows.execute` request to the gateway with a crafted `WorkflowSelector.WorkflowID` (or `WorkflowOwner`) field. The malformed input is trivial to construct (any max-length hex string without the `0x` prefix) and the bug is deterministic and repeatable on every request.

### Recommendation
In `validateHexInput`, require the `0x` prefix to be present (reject inputs that don't start with `0x`), and/or in `normalizeHex`, guard against `len(hexStr) > expectedHexLength` by returning an error instead of computing a negative `strings.Repeat` count (e.g., `if len(hexStr) > expectedHexLength { return "", fmt.Errorf(...) }`), propagating that error back to `resolveWorkflowID` as a user-facing invalid-request error rather than allowing a panic.

```go
    overLength := strings.Repeat("a", 66)
    require.NoError(t, validateHexInput(overLength, workflowIDLength))

        _ = normalizeHex(overLength, workflowIDLength)
    })
```

```go
func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}
```

```go
// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}
```

```go
func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
```
