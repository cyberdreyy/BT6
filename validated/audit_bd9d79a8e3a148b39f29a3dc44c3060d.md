### Title
Unauthenticated exposure of LOOP plugin discovery/metrics/pprof routes bypasses the auth/role gating applied to every other route group - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the bare `api` `*gin.RouterGroup` with no `auth.Authenticate(...)` wrapper, unlike every neighboring group (`debugRoutes`, `sessionRoutes`, `v2Routes`). This lets any unauthenticated client reach a proxy that forwards profiling (`pprof`) requests into the internal LOOP plugin process.

### Finding Description
`NewRouter` builds a single `api` `*gin.RouterGroup` and calls `debugRoutes(app, api)`, `sessionRoutes(app, api)`, `v2Routes(app, api)`, and `loopRoutes(app, api)` on it [1](#0-0) .

- `debugRoutes` wraps its `/debug` group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` before exposing `expvar` [2](#0-1) .
- `v2Routes` wraps `authv2` with `auth.Authenticate(...)` plus per-route `auth.RequiresEditRole`/`auth.RequiresAdminRole`/`auth.RequiresRunRole`, and even nests the node's own `/debug/pprof/*` (via `metricRoutes(authv2)`) inside that authenticated, role-gated group [3](#0-2) [4](#0-3) .
- `loopRoutes`, in contrast, calls `r.GET`/`r.POST` directly on the bare `api` group with zero auth middleware: [5](#0-4) .

The handlers backing these routes are in `core/web/loop_registry.go`. `pluginPPROFHandler` builds `pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)` using the attacker-supplied wildcard `profile` path segment, and forwards the request (with attacker-controlled `debug`, `gc`, `seconds` query parameters) to the internal LOOP plugin's own pprof server, returning the raw response body to the caller [6](#0-5) . `pluginMetricHandler` similarly proxies `/metrics` for any registered plugin name without any authentication check [7](#0-6) .

Because the whole `api` group already runs on the node's public listener (same port/interface as authenticated `/v2/*` endpoints) and these routes carry no `auth.Authenticate`/role wrapper, an unauthenticated attacker with only network access to the node's HTTP port can invoke `GET /discovery`, `GET /plugins/<name>/metrics`, `GET /plugins/<name>/debug/pprof/<profile>?debug=2&seconds=N`, and `POST /plugins/<name>/debug/pprof/symbol` freely, unlike the equivalent core-node pprof endpoints which require session/token auth plus admin role.

### Impact Explanation
`pprof` profiles (heap, goroutine with `debug=2`, CPU `profile`) can capture in-memory secrets and stack traces of the LOOP plugin process (e.g., median/relayer plugins), and `/discovery` + `/metrics` reveal internal topology (plugin names, ports, hostnames) that is otherwise gated behind authentication for the core node's own debug/metrics routes. This is an unauthenticated information-disclosure path enabled purely by a route-registration inconsistency: the LOOP routes lack the `auth.RequiresXRole`/`auth.Authenticate` wrapper that every structurally equivalent group in the same file enforces, so the codebase's own invariant ("every route enforces the minimum role it declares") is violated for this group specifically.

### Likelihood Explanation
No credentials, session, API token, or role are required — only network reachability to the node's configured web server port, which is the same port serving the rest of the (mostly authenticated) API. The routes are unconditionally registered whenever `NewRouter` builds the engine, so this is reachable in any default deployment.

### Recommendation
Wrap `loopRoutes`' router group with the same `auth.Authenticate(...)` middleware used by `debugRoutes`/`v2Routes` (or, if `/discovery` and `/plugins/*` must remain reachable by an external, unauthenticated Prometheus scraper, bind them to a separate internal-only listener/port rather than the public `api` group, and add role gating for the pprof proxy endpoints specifically since they are far more sensitive than a `/metrics` scrape target).

### Proof of Concept
```go
func TestLoopRoutesLackAuthMiddleware(t *testing.T) {
    app := cltest.NewApplication(t)
    router, err := web.NewRouter(app, nil)
    require.NoError(t, err)

    for _, ri := range router.Routes() {
        if ri.Path == "/discovery" || strings.HasPrefix(ri.Path, "/plugins/") {
            // Compare handler chain length/content against an authenticated
            // route (e.g. "/v2/jobs") registered in the same file.
            assert.NotContains(t, ri.Handler, "RequiresEditRole")
            assert.NotContains(t, ri.Handler, "RequiresAdminRole")
        }
    }

    // Handler-level integration check: unauthenticated request succeeds
    client := app.NewHTTPClient(nil) // no session/token set
    resp, cleanup := client.Get("/discovery")
    defer cleanup()
    cltest.AssertServerResponse(t, resp, http.StatusOK) // succeeds without auth

    resp2, cleanup2 := client.Get("/v2/jobs")
    defer cleanup2()
    cltest.AssertServerResponse(t, resp2, http.StatusUnauthorized) // requires auth
}
```
Expected: `/discovery` (and `/plugins/:name/...`) return `200 OK` for an unauthenticated client while `/v2/jobs` returns `401`, confirming the structural gap.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
