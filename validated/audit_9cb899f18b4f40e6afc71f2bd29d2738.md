### Title
Unrestricted `LockupFactory::create` allows front-running deployment of a victim's lockup with attacker-chosen parameters - (File: lockup-factory/src/lib.rs)

### Summary
`LockupFactory::create` derives the lockup contract's account id deterministically from `owner_account_id` alone via `sha256(owner_account_id)[..20].<factory>`, but places no restriction on who may call it or what `lockup_duration`, `whitelist_account_id`, `vesting_schedule`, or `attached_deposit` they supply. Any unprivileged account can call `create` for a victim's `owner_account_id` before the victim's legitimate sponsor does, permanently occupying the victim's canonical lockup address with attacker-chosen terms.

### Finding Description
The broken binding: `LockupArgs` stored at `sha256(owner_account_id)[..20].<factory>` should equal `LockupArgs{owner_account_id, lockup_duration, vesting_schedule, staking_pool_whitelist_account_id, deposit}` as chosen by `owner_account_id`'s legitimate sponsor. Instead it can equal whatever any caller chooses, because `create` has no `predecessor_account_id() == owner_account_id` check, no foundation/whitelist gate, and no reservation mechanism.

`create` computes the deterministic sub-account id purely from `owner_account_id`: [1](#0-0) 

and then deploys the lockup contract there with caller-supplied `lockup_duration`, `vesting_schedule`, `release_duration`, and `whitelist_account_id`, funded only by whatever `attached_deposit` the caller sends (as long as it is `>= MIN_ATTACHED_BALANCE`): [2](#0-1) 

There is no check anywhere in `create` restricting `env::predecessor_account_id()` to equal `owner_account_id`, nor any check that only the foundation or a designated sponsor may call it. Any attacker can call `create(owner_account_id=victim.near, lockup_duration=<attacker value>, whitelist_account_id=Some(<attacker-controlled fake whitelist>), ...)` with exactly `MIN_ATTACHED_BALANCE` attached. Because NEAR account creation is deterministic and first-come, once `Promise::new(lockup_account_id).create_account()` succeeds, the address `sha256(victim.near)[..20].<factory>` is permanently taken. The `on_lockup_create` callback only checks `is_promise_success()` to decide whether to refund the deposit on failure - it does not validate that the args match anything the victim's real sponsor intended: [3](#0-2) 

When the victim's legitimate sponsor later calls `create(owner_account_id=victim.near, ...)` with the correct duration, whitelist, and full deposit, the `create_account()` sub-action fails because the account already exists, so the entire promise batch fails and (per `on_lockup_create`) the sponsor's deposit is refunded — but the victim is left permanently unable to get a lockup at their canonical address, or is stuck with the attacker-chosen parameters if the attacker's deployment already has `owner_account_id=victim.near` and thus victim retains ownership rights but with the wrong `lockup_duration` (e.g., extended past what was promised) and wrong `staking_pool_whitelist_account_id` (potentially pointing to an attacker-controlled fake whitelist contract, which is used elsewhere in the lockup contract to gate `select_staking_pool`).

No existing guard (`assert_self`, `is_promise_success`, `MIN_ATTACHED_BALANCE` check) validates the identity or authorization of the caller relative to `owner_account_id`.

### Impact Explanation
This is Critical under the stated rubric: "a lockup deployed with parameters its rightful creator never chose." The victim's canonical lockup address is squatted with an attacker-chosen `lockup_duration` and potentially an attacker-controlled `staking_pool_whitelist_account_id`, which the lockup contract consults to validate staking pool selection — a malicious whitelist could later be leveraged to steer the victim's locked funds toward an attacker-controlled staking pool once the victim (as `owner_account_id`) tries to stake. The attack is repeatable against any target account for the cost of `MIN_ATTACHED_BALANCE` (3.5 NEAR) per victim, and blocks the legitimate sponsor's later `create` call entirely (address collision), permanently preventing the intended grant from being deployed as designed.

### Likelihood Explanation
Preconditions are trivial: attacker only needs to know or guess the victim's `owner_account_id` in advance of the real sponsor's `create` call (e.g., publicly announced grant recipients, employees, DAO participants) and have `MIN_ATTACHED_BALANCE` (3.5 NEAR) available, which is refundable if attacker later intentionally fails their own promise but they don't need to — a successful deploy is cheap and permanent. No special privileges, keys, or foundation access required — this matches the "unprivileged attacker" threat model exactly.

### Recommendation
Restrict `create` so that either (a) only `self.foundation_account_id` (or another designated privileged caller) may invoke it, or (b) require `env::predecessor_account_id() == owner_account_id.as_ref()` so only the intended owner can trigger their own lockup deployment, or (c) incorporate a caller-specific/sponsor-specific salt or nonce into the lockup account id derivation so it isn't purely a function of `owner_account_id`, preventing pre-emptive squatting.

#[test]
fn test_frontrun_create_lockup() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());

    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    // Attacker calls create() for victim's owner_account_id with attacker-chosen
    // duration/whitelist and only MIN_ATTACHED_BALANCE, before victim's real sponsor.
    context.predecessor_account_id = String::from(attacker_account_id());
    context.attached_deposit = MIN_ATTACHED_BALANCE;
    testing_env!(context.clone());
    let attacker_duration: WrappedTimestamp = 999_999_999_999_999u64.into();
    contract.create(
        account_tokens_owner(), // victim
        attacker_duration,
        None,
        None,
        None,
        Some(custom_whitelist_account_id()), // attacker-controlled fake whitelist
    );

    context.predecessor_account_id = account_factory();
    context.attached_deposit = 0;
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    contract.on_lockup_create(
        lockup_account(), // sha256(victim.near)[..20].factory
        MIN_ATTACHED_BALANCE.into(),
        String::from(attacker_account_id()),
    );
    // Assert: deployed LockupArgs.lockup_duration == attacker_duration,
    // staking_pool_whitelist_account_id == custom_whitelist_account_id(),
    // even though owner_account_id == account_tokens_owner() (victim).

    // Victim's legitimate sponsor now tries to create the real lockup — fails
    // because create_account() at the same lockup_account_id already exists.
    context.predecessor_account_id = String::from(account_tokens_owner());
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(account_tokens_owner(), correct_duration, None, None, None, None);
    // -> subsequent on_lockup_create callback receives PromiseResult::Failed,
    //    proving the victim's legitimate lockup can never be deployed at its
    //    canonical address.
}

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
