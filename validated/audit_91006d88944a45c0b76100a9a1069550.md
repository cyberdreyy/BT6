Based on my investigation, the closest reachable analog to the RocketPool "repeated cheap action resets a delay that blocks a critical recovery path" bug class is the miner-inactivity/last-activity mechanism in the signer's chainstate module.

### Title
Miner-controlled "activity" timestamp reset lets a stalled tenure indefinitely suppress the signer's fallback-to-prior-miner mechanism - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`check_latest_block_in_tenure` calls `signer_db.update_last_activity_time` whenever the current miner submits a conflicting/lower-height `BlockProposal`, as long as the tenure's last *signed* block has not yet reached group (70%) signature weight from this signer's point of view (`info.signed_group.is_none()`). Because this predicate is unconditionally true (not time-boxed) whenever `signed_group` is `None`, a miner whose block never crosses the group-signature threshold can indefinitely refresh `last_activity_time` by repeatedly gossiping cheap, non-advancing `BlockProposal` messages, each one counted as legitimate "miner activity" rather than being penalized. This starves `SortitionState::is_timed_out`, which drives `check_miner_inactivity`'s fallback to the prior valid miner.

### Finding Description
`get_tenure_last_block_info` returns the last block this signer ever put a signature over (`signed_self` or `signed_group`), regardless of whether the group ever reached the 70% signing threshold [1](#0-0) .

`check_latest_block_in_tenure` treats any proposal that does not exceed that block's height as a "reorg attempt," and only refrains from crediting it as activity once `signed_group` has both been set *and* aged past `reorg_attempts_activity_timeout`: [2](#0-1) 

Note the guard: `info.signed_group.is_none_or(|signed_time| signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs())`. If `signed_group` is `None` — i.e. this signer signed the block (`signed_self`) but the group never reached 70% signature weight — the condition is always `true`, with no expiry. Every subsequent conflicting proposal from the miner re-triggers `update_last_activity_time`.

That timestamp is exactly what gates the fallback-to-prior-miner path: [3](#0-2) 

and the analogous v2 check [4](#0-3) , both feeding `check_miner_inactivity`, the only place a signer reverts `current_miner` to the prior tenure when the active miner stalls [5](#0-4) .

`check_latest_block_in_tenure` is invoked at proposal arrival, at validate-ok, and at signing time, per `docs/signer-flows.md` section 7, so the miner has multiple opportunities per proposal to hit this branch.

### Impact Explanation
This is a liveness wedge: as long as a miner's block sits signed by this signer (`signed_self` set) but never accumulates the 70% group signature weight — which a malicious/faulty miner can arrange simply by proposing something a meaningful minority of signers reject or never gossip acceptance for — the miner can keep resubmitting cheap, non-advancing proposals to indefinitely refresh `last_activity_time`. This suppresses `is_timed_out`, so `check_miner_inactivity` never falls back to the previously valid miner, and the tenure/network can be stalled well past `block_proposal_timeout` without producing a new valid block. This matches the "signer wedged into never signing valid blocks" / liveness-wedge impact category, directly analogous to RocketPool's repeated cheap `stake()` resetting the deposit-delay clock that blocks `unstake()`.

### Likelihood Explanation
The mechanism is reachable by a single miner (one sortition-slot holder) using only ordinary gossip messages (`BlockProposal`) it is already entitled to send, and does not require control of another signer's key, majority signing power, or local/auth-token access. It does, however, require the block to remain below the 70% signature threshold indefinitely (e.g. because a meaningful minority of signers are unavailable, slow, or refuse to sign) — a condition the miner cannot fully control on its own, which bounds how easily this can be forced in a healthy signer set. This makes it a real but conditional liveness concern rather than a trivially-triggerable one.

### Recommendation
Bound the `signed_group.is_none()` branch by a fixed timeout measured from when the block was first locally accepted (`signed_self`) or first proposed, rather than leaving it open-ended. This mirrors the existing, correctly time-boxed handling of the `Some(signed_time)` case and prevents a miner from converting "no group signature yet" into an unlimited activity-refresh window.

### Proof of Concept
1. Miner M wins a sortition slot and proposes block N.
2. A meaningful minority of signers (short of 30%) reject or never gossip their acceptance of N, so N is `signed_self` by this signer but never reaches the 70% group threshold; `signed_group` stays `None`.
3. M repeatedly re-gossips conflicting/lower-height `BlockProposal`s (or re-proposes N) for the tenure.
4. Each one hits `check_latest_block_in_tenure`'s `info.signed_group.is_none()` branch, calling `update_last_activity_time` with no expiry (`stacks-signer/src/chainstate/mod.rs:403-417`).
5. `SortitionState::is_timed_out` never reports the tenure as inactive because `elapsed` since `last_activity_time` never exceeds `block_proposal_timeout`.
6. `check_miner_inactivity` never reverts `current_miner` to the prior valid miner, stalling block production for as long as M keeps up the low-cost proposal stream.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    pub fn check_miner_inactivity(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<(), SignerChainstateError> {
        let Self::Initialized(ref mut state_machine) = self else {
            // no inactivity if the state machine isn't initialized
            return Ok(());
        };

        let MinerState::ActiveMiner { ref tenure_id, .. } = state_machine.current_miner else {
            // no inactivity if there's no active miner
            return Ok(());
        };

        let version = SortitionStateVersion::from_protocol_version(
            state_machine.active_signer_protocol_version,
        );
        let is_timed_out = SortitionState::is_timed_out(
            &version,
            tenure_id,
            db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )?;

        if !is_timed_out {
            return Ok(());
        }

        // the tenure timed out, try to see if we can use the prior tenure instead
        let CurrentAndLastSortition { last_sortition, .. } =
            client.get_current_and_last_sortition()?;
        let Some(last_sortition) = last_sortition
            .and_then(|val| SortitionData::try_from(val).ok())
            .map(|data| SortitionState::new(version, data))
        else {
            warn!("Signer State: Current miner timed out due to inactivity, but could not find a valid prior miner. Allowing current miner to continue");
            return Ok(());
        };

        let sortition_data = last_sortition.data();
        // If we already reverted to the last sortition miner, don't time it out as it means we have already timed out the current sorititon miner
        // as there is no other miner available.
        if &sortition_data.consensus_hash == tenure_id {
            warn!("Signer State: Last sortition miner has timed out, but no prior valid miner. Allowing last sortition miner to continue");
            return Ok(());
        }

        // Only revert to the prior miner if its tenure is the canonical Stacks tip's
        // tenure. A miner only continues (extends) a tenure it won, so if the canonical
        // tip is in some other tenure due to a Bitcoin reorg orphaning the prior
        // sortition's tenure, the prior miner's node has already stopped mining and
        // will never propose again.
        let stacks_tip_ch = client.get_peer_info()?.stacks_tip_consensus_hash;
        if sortition_data.consensus_hash != stacks_tip_ch {
            warn!(
                "Signer State: Current miner timed out due to inactivity, but the canonical stacks tip is not in the prior miner's tenure, so the prior miner cannot continue it. Allowing current miner to continue";
                "stacks_tip_consensus_hash" => %stacks_tip_ch,
                "prior_sortition_consensus_hash" => %sortition_data.consensus_hash,
            );
            return Ok(());
        }

        if !last_sortition.is_tenure_valid(db, client, proposal_config, eval)? {
            warn!("Signer State: Current miner timed out due to inactivity, but prior miner is not valid. Allowing current miner to continue");
            return Ok(());
        }
        let new_active_tenure_ch = &sortition_data.consensus_hash;
        let inactive_tenure_ch = tenure_id.clone();
        state_machine.current_miner = Self::make_miner_state(
            sortition_data.clone(),
            client,
            db,
            proposal_config.tenure_last_block_proposal_timeout,
        )?;
        info!(
            "Signer State: Current tenure timed out, setting the active miner to the prior tenure";
            "inactive_tenure_ch" => %inactive_tenure_ch,
            "new_active_tenure_ch" => %new_active_tenure_ch
        );

        crate::monitoring::actions::increment_signer_agreement_state_change_reason(
            crate::monitoring::SignerAgreementStateChangeReason::InactiveMiner,
        );

        Ok(())
    }
