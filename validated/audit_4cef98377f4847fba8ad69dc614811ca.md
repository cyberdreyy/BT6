### Title
`AuthenticateByToken` leaks raw database error strings to unauthenticated callers via `jsonAPIError` - ([File: core/web/auth/auth.go])

### Summary
`AuthenticateByToken` only maps `sql.ErrNoRows` and `sessions.ErrUserSessionExpired` to the generic `auth.ErrorAuthFailed`; any other error returned by `FindUserByAPIToken` is returned unmodified and ultimately serialized into the HTTP 401 response body by `jsonAPIError`, exposing raw internal error text to an unauthenticated client.

### Finding Description
`AuthenticateByToken` reads `X-API-KEY`/`X-API-SECRET` from an unauthenticated request and calls `authr.FindUserByAPIToken(ctx, token.AccessKey)`: [1](#0-0) 

Only `sql.ErrNoRows` and `clsessions.ErrUserSessionExpired` are normalized to `auth.ErrorAuthFailed`; every other error (`return err`) propagates unmodified up through `Authenticate`: [2](#0-1) 

The middleware then calls `jsonAPIError(c, http.StatusUnauthorized, err)`, which serializes `err.Error()` directly into the JSON response body sent to the caller: [3](#0-2) 

The concrete implementation, `orm.FindUserByAPIToken`, executes `SELECT * FROM users WHERE token_key = $1` via `sqlutil.DataSource.GetContext`: [4](#0-3) 

Any driver/scan/context error other than "no rows" (e.g., connection failures, context deadline exceeded, encoding/type errors, driver-level Postgres errors) is returned as-is and will be echoed to the client. No middleware or role check intercepts this path since it occurs before authentication succeeds, and no wrapping/generalization is applied to sanitize the message before it reaches `jsonAPIError`.

### Impact Explanation
This is a low-to-moderate severity information disclosure: an unauthenticated attacker can trigger conditions that surface raw database/driver error text (e.g., Postgres error codes/messages, timeout/connection state, potentially echoed portions of malformed input) in the 401 response body. It does not directly leak credentials/secrets (the query only touches `token_key`, and a match failure returns `sql.ErrNoRows`, which is already normalized), but it violates the "secret confinement"/error hygiene invariant and can aid reconnaissance (DB engine/version fingerprinting, backend health/state, internal error formatting) for further attacks. This falls under Chainlink's "informational disclosure of non-critical internal data" bounty class rather than a direct fund-loss or auth-bypass class.

### Likelihood Explanation
No credentials are required — the endpoint is reachable by any unauthenticated client sending `X-API-KEY`/`X-API-SECRET` headers. Triggering a non-`ErrNoRows` DB error reliably (e.g., forcing a connection pool exhaustion, context cancellation, or an encoding error on the token value) is less trivial than a simple wrong-token request, but is realistically achievable (e.g., extremely long/invalid-UTF8 header values, or under transient DB load/timeout conditions) and is fully repeatable once such a condition is found or induced.

### Recommendation
In `AuthenticateByToken` (`core/web/auth/auth.go`), do not return the raw `err` from `FindUserByAPIToken` to the HTTP layer. Log the detailed error server-side and return a generic `auth.ErrorAuthFailed` (or a new generic internal-error sentinel mapped to a non-leaking message) for any error path, mirroring the pattern already used for `sql.ErrNoRows`/`ErrUserSessionExpired`. Apply the same treatment to `AuthenticateExternalInitiator`'s `errors.Wrap(err, "finding external initiator")` path, which has the same leakage issue.

### Proof of Concept
Go unit test plan (in `core/web/auth/auth_test.go`):
1. Create a mock `Authenticator` (already available via `sessions/mocks`) where `FindUserByAPIToken` returns a distinctive non-`sql.ErrNoRows`, non-`ErrUserSessionExpired` error, e.g. `errors.New("pq: connection reset by peer, dsn=postgres://internal-host:5432/db")`.
2. Build a `gin.Context` with a `httptest.ResponseRecorder`, set `X-API-KEY`/`X-API-SECRET` headers to any non-empty values.
3. Call `auth.Authenticate(mockAuthr, auth.AuthenticateByToken)` handler function directly.
4. Assert response status is 401.
5. Assert response body (JSON `errors[0].detail`) equals/contains the raw mock error string (e.g., `"pq: connection reset by peer, dsn=postgres://internal-host:5432/db"`), demonstrating the raw internal error is leaked verbatim to the unauthenticated caller — the assertion should currently pass, proving the vulnerability; after the fix, the assertion should be changed to expect a generic message and no longer contain the raw error text.

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}
```

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
```
