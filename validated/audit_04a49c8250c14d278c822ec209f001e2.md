### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges pending requests and confirmation records that were *created* by the removed member. It does not scan or clean confirmation entries the removed member left on *other* requests that they merely confirmed. Because `confirm()` counts entries in the stored `HashSet<String>` without verifying each entry still corresponds to a current member, a removed member's stale confirmation can still push a pending request over the `num_confirmations` threshold, letting a request execute with fewer live signers than required.

### Finding Description
The binding this contract is supposed to enforce is:

`live confirmations on request R == confirmations from accounts/keys that are still members at execution time`

`confirm()` checks membership only for the *caller* of the current call, and then simply compares the size of the persisted confirmation set against `num_confirmations`: [1](#0-0) 

`delete_member()` (invoked from `MultiSigRequestAction::DeleteMember` in `execute_request`) removes the member and cleans up:
- requests **added by** that member (`r.member == member`), and their confirmation sets,
- the `num_requests_pk` counter for that member.

It never inspects the `confirmations` map for requests **added by other members** where the removed member may have already voted: [2](#0-1) 

So if member `M` confirms a request `R` created by a different member, and `M` is later removed via a `DeleteMember` action, `R`'s stored confirmation set still contains `M`'s entry. `M` is no longer in `self.members`, but their old vote still counts in `confirmations.len()` when a live member later calls `confirm(R)`, potentially reaching `num_confirmations` with fewer than `num_confirmations` *currently valid* signers.

### Impact Explanation
This breaks the "confirmations counted versus live members" custody binding for a threshold-gated multisig that directly custodies NEAR and controls keys/contract code. A request such as `MultiSigRequestAction::Transfer` (executed via `execute_request`, see the `Transfer` arm) can be released with effectively fewer independent live approvals than `num_confirmations` mandates, i.e. a multisig request executed below the configured threshold. This is a Critical-severity impact per the custody-binding scope (funds movement authorized below the required threshold).

### Likelihood Explanation
No foundation/owner/redeploy/social-engineering step is required beyond the multisig's own normal operation: any legitimate `DeleteMember` request (itself passed by the same threshold, which is standard multisig lifecycle, e.g. rotating out a compromised/departing key holder) followed by ordinary use of pre-existing pending requests triggers the flaw. It requires only:
1. A request `R` created by member `A`.
2. Member `M` confirms `R` before being removed.
3. Members execute a `DeleteMember { member: M }` request.
4. A live member confirms `R`, reaching threshold using `M`'s stale vote.

This is a realistic operational sequence (member rotation with in-flight requests), not a contrived edge case, so likelihood is Medium-High.

### Recommendation
When executing `DeleteMember`, iterate over all entries in `self.confirmations` (not just requests added by the removed member) and remove the removed member's string key from every confirmation `HashSet`. Alternatively, validate at `confirm()` time (or at execution time before comparing to `num_confirmations`) that every entry in the confirmation set still exists in `self.members`, discarding/ignoring stale entries when computing whether the threshold is met.

### Proof of Concept
1. Deploy `multisig2` with `num_confirmations = 3` and members `{A, B, C, D}` (4 members total, satisfies the `members.len() >= num_confirmations` invariant even after one removal).
2. `A.add_request(R)` — creates request `R` targeting a `Transfer` action; `confirmations[R] = {}`. [3](#0-2) 
3. `B.confirm(R)` → `confirmations.len()==0, +1=1 < 3` → inserted, `confirmations[R] = {B}`.
4. `C.confirm(R)` → `confirmations.len()==1, +1=2 < 3` → inserted, `confirmations[R] = {B, C}`.
5. Separately, members pass a `DeleteMember{member: C}` request (via its own add_request/confirm cycle reaching threshold), which calls `delete_member`. Since `R` was added by `A` (not `C`), `R` and its confirmations are left untouched: `confirmations[R]` still equals `{B, C}` even though `C` is no longer in `self.members`. [4](#0-3) 
6. `D.confirm(R)` → `confirmations.len()==2 ("B","C"), +1=3 >= num_confirmations(3)` → `execute_request(R)` runs the `Transfer`, even though the only currently-valid live confirmers are `B` and `D` (2 of 4 remaining members), one short of the intended 3-of-n threshold. [1](#0-0) 

This demonstrates a request executed below the actual live-member threshold, i.e., NEAR moved out of the multisig without the required number of currently-authorized approvals.

        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(

            .unwrap_or(0)
            + 1;
        assert(
            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
