### Title
Global-state quorum check `reached_agreement` uses floor rounding while the block-signature threshold uses ceiling rounding, letting sub-70% signer weight be treated as global consensus - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The signer's two independent implementations of the "70% supermajority" quorum check use different rounding rules. `NakamotoBlockHeader::compute_voting_weight_threshold` (used to gate an actual block *signature*) rounds the 70% threshold **up**, while `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` (used to determine the signer set's agreed-upon `SignerStateMachine` — the source of truth for `current_miner`, `tenure_id`, `parent_tenure_id`, burn view, protocol version, and tx-replay-set) rounds the same 70% threshold **down**. When `total_weight` is not a multiple of 10, this lets a coalition with strictly less than the intended 70% weight be recognized as having "reached global agreement," while the block-signing path elsewhere in the same codebase would correctly refuse to treat that same weight as sufficient.

### Finding Description
`NakamotoBlockHeader::compute_voting_weight_threshold` explicitly rounds up so that a fraction just under 70% is rejected: [1](#0-0) 

This ceiling-rounded threshold is what governs actual block-signature acceptance (`verify_signer_signatures`) and is reused directly in `stacks-signer/src/v0/signer.rs` for pre-commit weight, signature-acceptance weight, and rejection weight tallies: [2](#0-1) [3](#0-2) 

The unit test `test_compute_voting_weight_threshold` confirms the round-up behavior (e.g. total=511 → threshold=358, not 357): [4](#0-3) 

By contrast, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement`, which is used to decide the *global signer state machine* (a completely independent 70%-supermajority decision), performs plain integer division with no ceiling adjustment: [5](#0-4) 

`reached_agreement` gates every part of `determine_global_state`, `determine_latest_supported_signer_protocol_version`, and `determine_global_burn_view` — i.e., it decides which `current_miner`/`tenure_id`/`parent_tenure_id`/burn view/protocol-version/tx-replay-set the signer treats as the network's agreed truth: [6](#0-5) 

That `SignerStateMachine` is then used, without any further "was this really 70%?" check, as the basis for validating (or rejecting) block proposals in `GlobalStateView::check_proposal`: [7](#0-6) [8](#0-7) 

Concretely: for `total_weight = 11`, `compute_voting_weight_threshold(11) = ceil(77/10) = 8`, but `reached_agreement` only needs `floor(77/10) = 7`. A subgroup of signers whose combined weight is 7/11 (≈63.6%) — a real majority of weight but *below* the 70% supermajority the protocol design (and the block-signature check) actually enforces — is enough for `determine_global_state()` to "lock in" a `current_miner`/`tenure_id`/`parent_tenure_id` view. Any weight total not evenly divisible by 10 (the vast majority of real reward-set weight distributions) exhibits this same off-by-one gap between the two supposedly-equal 70% checks.

This is the direct structural analog of the referenced report: two code paths are meant to enforce the *same* threshold (the linked report's `defenderQuote` vs `contractQuote` slippage bound; here, the block-signature 70% threshold vs the global-state 70% threshold), but one of them computes the bound in a way that is weaker than intended, so the "protective" check does not actually protect against the scenario it is supposed to guard.

### Impact Explanation
Because the global-state quorum can lock in with less weight than the true 70% supermajority, a set of signers whose views diverge from the *actual* canonical chain state (e.g., because of gossip lag, a forked burn view, or a stale `parent_tenure_last_block`) can cause other signers to adopt an incorrect `SignerStateMachine` as ground truth. `GlobalStateView::check_proposal` then rejects proposals that build on the real canonical tenure (because `tenure_id`/`parent_tenure_id`/`current_miner_pkh` won't match) or accepts a stale view of "who the miner is." This falls under the High-impact category of "a signer wedged into never signing valid blocks [or] acting on a stale reward set/threshold," since valid, canonical block proposals from the real miner can be rejected en masse by signers that have converged (via the weaker floor-rounded threshold) on a stale/incorrect global state.

### Likelihood Explanation
The bug does not require any single actor to control a majority of stake — it only requires that `total_weight` not be an exact multiple of 10 (essentially the common case for real reward sets) and that some ordinary, non-malicious weight split of "who agrees with what" straddles the gap between `floor(0.7*total_weight)` and `ceil(0.7*total_weight)`. A single miner (with gossip access to publish its own tenure/miner data through the normal proposal/StackerDB channels) can, at the margin, benefit from or be harmed by which side of that off-by-one gap the signer set falls on, and the discrepancy is deterministic and reproducible for any given weight distribution — it is a structural rounding bug present on every `determine_global_state`/`determine_global_burn_view` call whenever `total_weight % 10 != 0`.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` (and its complement `reached_disagreement`) use the same ceiling-rounding formula as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by sharing the exact same helper function, so that "70% agreement" means the identical numeric bound everywhere in the codebase. `reached_disagreement`'s complement should likewise be derived from the same shared threshold constant instead of independently re-deriving `10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`.

### Proof of Concept
1. Configure a reward set with `total_weight = 11` (e.g., signer weights summing to 11, such as `[4, 4, 3]` or 11 signers of weight 1).
2. Have signers with combined weight `7` broadcast a `StateMachineUpdate` agreeing on state machine view `S1` (e.g., a stale `current_miner`/`tenure_id`), while the remaining weight `4` reflects the actual canonical view `S2`.
3. Call `GlobalStateEvaluator::determine_global_state()` (as exercised by `check_block_against_global_state`) — per `reached_agreement`, `7 >= floor(11*7/10) = 7`, so `S1` is returned as the agreed global state, even though `NakamotoBlockHeader::compute_voting_weight_threshold(11) = 8` would correctly refuse to treat weight 7 as sufficient for an actual block signature.
4. A block proposal built on the real canonical tenure (`S2`) is then evaluated against `S1` in `GlobalStateView::check_proposal` and rejected with `ConsensusHashMismatch`/`InvalidMiner`, even though the true supermajority (weight 8/11) required by the protocol was never reached for `S1`.     /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
