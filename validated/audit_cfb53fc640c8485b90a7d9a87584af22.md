### Title
Missing owner-binding check on `DeleteSecrets` allows an authorized-but-different actor to delete another owner's vault secrets - (File: `core/capabilities/vault/validator.go`, `core/capabilities/vault/gw_handler.go`)

### Summary
The original report describes a class of bug where a privileged/authorized actor's request is processed without verifying that the actor is actually the intended target of the action, letting the actor act on someone else's resource. The Vault gateway/node pipeline in this repo has the same structural gap: for `SecretsDelete` requests, the authorization layer verifies *that* the caller is authorized to submit a specific request, but never verifies *whose* secrets (`id.Owner`) the request is allowed to touch, unlike the parallel `SecretsList` and `SecretsCreate`/`SecretsUpdate` paths which do enforce this binding.

### Finding Description
Vault requests flow through `GatewayVaultRequestProcessor.ProcessRequest` → `authorizeAndStamp`, which calls `Authorizer.AuthorizeRequest` to get an `AuthResult` containing `AuthorizedOwner()` [1](#0-0) . For the allowlist-based authorizer, authorization succeeds when the request's digest matches a digest an owner previously allowlisted on-chain via the workflow registry [2](#0-1) ; the "owner" that comes back is whoever allowlisted that digest — not necessarily the owner referenced inside the request's payload.

For `SecretsCreate`/`SecretsUpdate`, this is safe because `validateWriteRequest` calls `EnsureRightLabelOnSecret`, which cryptographically checks that each `EncryptedSecret.Id.Owner` matches the TDH2 ciphertext label baked in at encryption time [3](#0-2) , so an attacker cannot forge a create/update for another owner's data even if their own request gets authorized.

For `SecretsList`, the node handler explicitly overrides whatever owner the client supplied with the authorized owner before querying the secrets service: `r.Owner = authResult.AuthorizedOwner()` [4](#0-3) .

For `SecretsDelete`, however, neither protection exists. `ValidateDeleteSecretsRequest` only validates the *format* of each `id.Owner` (non-empty, alphanumeric, length limits) — it never compares `id.Owner` to the `AuthResult.AuthorizedOwner()` [5](#0-4) . And `handleSecretsDelete` passes the client-supplied `DeleteSecretsRequest` — including its per-item `Owner` fields — straight to `h.secretsService.DeleteSecrets` with no owner override, unlike its sibling `handleSecretsList` [6](#0-5) .

Because delete has no cryptographic (ciphertext-label) or handler-level (owner override) binding, the only thing preventing cross-owner deletion is that the exact byte-for-byte request (including the victim's owner ID in `Ids[]`) must have been digest-allowlisted. Digest allowlisting is a self-service, owner-controlled action performed via `WorkflowRegistry.AllowlistRequest` [7](#0-6)  — an actor authorizes *their own* submitted request, and nothing stops that request's `Ids[].Owner` fields from naming a different owner's secrets. The processor's `authorizeAndStamp` derives `AuthorizedOwner()` purely from who allowlisted the digest, not from the payload contents [8](#0-7) .

### Impact Explanation
An actor who can get a `SecretsDelete` request digest allowlisted for their own address (a normal, unprivileged, self-service action) can craft the request's `Ids[]` to reference a different owner's secret identifiers. Because `ValidateDeleteSecretsRequest` and `handleSecretsDelete` never check `id.Owner == AuthorizedOwner()`, the vault node will delete secrets belonging to another workflow owner. This is destructive, irreversible data loss of another user's private/encrypted vault secrets, directly analogous to the original report's "unprivileged/self-authorized actor spends another user's balance because a required identity binding check is missing."

### Likelihood Explanation
Likelihood is moderate: the attacker only needs to know (or guess/enumerate) a victim's secret identifiers (`Key`/`Namespace`/`Owner`), which are not inherently secret (identifiers, unlike secret values, are used in `ListSecretIdentifiers` responses and workflow configuration), and needs to be able to self-allowlist a request through the normal workflow-registry flow available to any workflow owner. No special/privileged role or node-operator access is required, in contrast to the higher-difficulty checks (`create`/`update`/`list`) that already close this gap.

### Recommendation
- In `ValidateDeleteSecretsRequest` (or in `handleSecretsDelete`), require that every `id.Owner` in `DeleteSecretsRequest.Ids` equals `authResult.AuthorizedOwner()`, mirroring the override already done in `handleSecretsList` (`gw_handler.go:343`).
- More robustly, perform this binding check centrally in `authorizeAndStamp`/`ProcessRequest` for all mutating methods (create, update, delete) so that owner-binding is enforced uniformly and cannot be forgotten on a new method in the future — this mirrors the original report's long-term recommendation to "identify and document all actions privileged/authorized accounts can take" and enforce checks consistently rather than per-handler.
- Add a regression test asserting that a `SecretsDelete` request authorized for owner A but containing `Ids[].Owner == B` is rejected.

### Proof of Concept
1. Attacker (owner `A`) crafts a `DeleteSecretsRequest` with `RequestId` and `Ids: [{Key: "victim-secret", Namespace: "main", Owner: "B"}]` where `B` is a victim workflow owner whose secret identifier the attacker has learned.
2. Attacker computes the JSON-RPC request digest and calls `WorkflowRegistry.AllowlistRequest` from their own address `A`, allowlisting that exact digest for themselves (a standard, unprivileged self-service call) — see `allowlistRequest` helper pattern [7](#0-6) .
3. Attacker sends the request through the gateway. `allowListBasedAuth.AuthorizeRequest` finds the digest allowlisted for owner `A` and returns `AuthResult{workflowOwner: "A"}` [9](#0-8) .
4. `ValidateDeleteSecretsRequest` only validates format of `Owner: "B"`, not that it equals `"A"` [10](#0-9) .
5. `handleSecretsDelete` forwards the request as-is to `secretsService.DeleteSecrets`, deleting victim `B`'s secret [11](#0-10) .

**Note on verification limits**: I could not inspect the internal `SecretsService.DeleteSecrets` implementation (outside the indexed vault package) to confirm there is no secondary owner check performed deeper in the storage layer; if such a check exists there, it would mitigate this finding. This should be verified directly in a full checkout of the repository, e.g. via a Devin session, since the codebase index used here may not include every file.

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

func (r *RequestValidator) ValidateDeleteSecretsRequest(ctx context.Context, request *vaultcommon.DeleteSecretsRequest) error {
	if request.RequestId == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(request.Ids)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(request.Ids) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, id := range request.Ids {
		if id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}
		if err := r.ValidateSecretIdentifier(ctx, id.Key, id.Owner, id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}

		_, ok := uniqueIDs[vaulttypes.KeyFor(id)]
		if ok {
			return errors.New("duplicate secret ID found at index " + strconv.Itoa(idx) + ": " + id.String())
		}

		uniqueIDs[vaulttypes.KeyFor(id)] = true
	}
	return nil
}

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}

	}
