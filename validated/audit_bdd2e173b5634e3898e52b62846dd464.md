### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges *requests* that were originally added by the deleted member. It never removes that member's *confirmations* recorded on requests added by other members. Because `confirm()` counts entries in the stored `confirmations: LookupMap<RequestId, HashSet<String>>` against the *current* `num_confirmations` without checking that each confirming identity is still a live member, a request can be executed using a confirmation cast by an account/key that has since been removed from the multisig.

### Finding Description
`confirm()` reads the `HashSet<String>` of confirmations for a request and executes it once `confirmations.len() as u32 + 1 >= self.num_confirmations`: [1](#0-0) 

Confirmations are keyed by `member.to_string()`, i.e. by the serialized `MultisigMember` (an `AccessKey{public_key}` or `Account{account_id}`), not by a live reference to the members set: [2](#0-1) 

`delete_member` removes the member from `self.members`, deletes the member's access key on-chain, and purges only the requests that member *authored* (`r.member == member`): [3](#0-2) 

It does **not** scan `self.confirmations` to strip the deleted member's string entry from confirmation sets on requests *authored by other members*. Those stale entries remain permanently embedded in the `HashSet<String>` for any pending request.

Binding that should hold: `count(confirmations on request R) == count(distinct *live* members who confirmed R)`. After `delete_member`, this becomes `count(confirmations on request R) > count(distinct live members who confirmed R)` for any request R that the removed member had previously confirmed (but did not author) before being deleted. When a genuinely live member subsequently calls `confirm(R)`, the threshold check `confirmations.len() + 1 >= self.num_confirmations` uses the inflated count including the dead entry, so the request can be executed with fewer live confirmations than `num_confirmations` actually requires.

### Impact Explanation
This breaks the core authorization guarantee of the multisig: a request (which can include `Transfer`, `FunctionCall`, `AddKey`, `DeployContract`, etc.) can be executed with fewer *live, currently-authorized* confirmations than the configured threshold `num_confirmations`. This is a multisig request executed below threshold, matching the Critical impact category (funds/actions authorized by fewer than the required threshold of live signers).

### Likelihood Explanation
Likelihood is moderate to high in any operationally realistic multisig lifecycle: member rotation (removing compromised, departed, or rekeyed signers) is a standard operational practice, and any pending request confirmed by a member prior to their removal leaves an exploitable stale confirmation. No malicious deployment or foundation action is required beyond ordinary member-removal governance, which is an in-scope, expected multisig operation, not a special privileged bypass.

### Recommendation
When removing a member in `delete_member`, iterate over `self.confirmations` and strip the removed member's `to_string()` entry from every request's confirmation set (not just delete requests the member authored). Alternatively, change `confirm()`/execution to re-validate, at confirmation-count time, that every entry in the stored confirmation set still corresponds to a currently live member (filter `self.members.contains(...)` before counting), rather than trusting the raw `HashSet<String>` length.

### Proof of Concept
1. Initialize `MultiSigContract::new(members, num_confirmations=3)` with members `[A, B, C, D]`.
2. `A` calls `add_request(...)` to create request `R` (transfer funds), `A`'s confirmation counted implicitly is not auto-added unless `add_request_and_confirm` is used — assume `A` calls `add_request_and_confirm`, giving `R` 1 confirmation from `A`.
3. `B` calls `confirm(R)` → confirmations = `{A, B}` (2/3).
4. Members vote to remove `B` via `DeleteMember{member: B}` request (a separate, valid multisig action) — `delete_member` removes `B` from `self.members` and deletes `B`'s requests, but leaves `B`'s confirmation string on `R`'s `HashSet` untouched: `confirm()` code path shows confirmations are never scrubbed on delete, see `delete_member` at [4](#0-3) .
5. `C` (a live member) calls `confirm(R)`. `confirmations.len() as u32 + 1 = 3 >= self.num_confirmations (3)` — the check in [5](#0-4)  passes and `R` executes, even though only `A` and `C` are currently live members who confirmed — one fewer live confirmer than the configured threshold of 3.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
