### Title
Unbounded `activeRequests` growth via unthrottled `newActiveRequest` ingress path enables memory/lock-contention DoS - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`(h *handler) HandleJSONRPCUserMessage` calls `h.newActiveRequest` for every incoming user request with only an ID-emptiness/length check, with no per-caller, per-owner, or global concurrency/rate limit on how many distinct `req.ID` entries can be inserted into `h.activeRequests`. The only rate limiters (`globalNodeRateLimiter`, `perNodeRateLimiters`) are applied exclusively inside `HandleNodeMessage`, i.e. on responses coming back from DON nodes, not on the ingress path that creates map entries.

### Finding Description
The reachable path is: gateway HTTP endpoint `httpserver.handleRequest` [1](#0-0)  → `gateway.ProcessRequest`, which routes the decoded JSON-RPC request straight to `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` [2](#0-1)  → `(h *handler) HandleJSONRPCUserMessage` in the confidential relay handler, which only checks that `req.ID` is non-empty and ≤200 chars before calling `h.newActiveRequest(req, callback)` and fanning the request out to all DON members: [3](#0-2) .

`newActiveRequest` itself only rejects a duplicate `req.ID`; it performs no quota check against the caller, no global cap on `len(h.activeRequests)`, and takes `h.mu.Lock()` unconditionally to insert into the map: [4](#0-3) .

The only rate limiters constructed by `NewHandler` (`globalNodeRateLimiter`, `perNodeRateLimiters`) are wired solely into `HandleNodeMessage`, which processes responses from DON nodes, not the ingress creation path: [5](#0-4) . This is confirmed by `TestConfidentialRelayHandler_RateLimitedNode`, which exercises rate limiting only against `HandleNodeMessage` calls, never against repeated `HandleJSONRPCUserMessage` calls with fresh IDs [6](#0-5) .

Entries are only removed by `removeExpiredRequests`, which sweeps `h.activeRequests` under `h.mu.RLock()` once per `defaultCleanUpPeriod` (1s) and evicts entries only after `h.requestTimeout` (default 30s) has elapsed: [7](#0-6) . An attacker who can reach `HandleJSONRPCUserMessage` faster than this eviction cadence can grow `h.activeRequests` without bound, since duplicate-ID rejection is trivially bypassed by using a fresh ID per request.

Every other lifecycle path (`getActiveRequest`, `sendResponseAndClearRequest`, `forwardGracedRequests`, `removeExpiredRequests`) also serializes on the same single `h.mu` mutex [8](#0-7) [9](#0-8) , so as the map grows, lock hold time for the periodic sweep and for legitimate concurrent `newActiveRequest`/`getActiveRequest` calls from other users of the same DON increases, degrading availability for all callers of that DON's confidential relay handler.

### Impact Explanation
This maps to a node/service availability degradation (Denial of Service) impact class: growth of `h.activeRequests` consumes gateway memory proportional to attacker-supplied request volume, and contention on the single `h.mu` mutex used by both the hot ingress path and the periodic sweep/response paths degrades or blocks legitimate confidential-relay requests from other callers sharing the same DON handler instance, until process resources are exhausted or requests time out.

### Likelihood Explanation
The only precondition is the ability to reach the gateway's confidential relay HTTP endpoint with syntactically valid JSON-RPC requests carrying unique `req.ID` values (≤200 chars) — no signature verification or authorization gate exists in this handler's `HandleJSONRPCUserMessage` before `newActiveRequest` is invoked, so even an unauthenticated/low-privilege caller can trigger it. The attack requires only sending requests faster than the 30-second default `requestTimeout` eviction window, which is trivially achievable and fully repeatable/scriptable.

### Recommendation
Add a bound on `len(h.activeRequests)` (global and/or per-caller/owner) enforced in `newActiveRequest`, rejecting or rate-limiting new request creation once the cap is reached; additionally apply a rate limiter (per caller identity if available, otherwise global) on the ingress path in `HandleJSONRPCUserMessage` before allocating a new `activeRequest`, mirroring the pattern already used for the vault and HTTP-trigger handlers' `userRateLimiter`.

### Proof of Concept
Go handler-level test plan (extend `handler_test.go`):
1. Construct the handler via `NewHandler`/`setupHandler` with a small DON (as in existing tests).
2. In a loop of N (e.g. 100,000) iterations, call `h.HandleJSONRPCUserMessage(ctx, req, callback)` with a fresh, monotonically incrementing `req.ID` each time and a no-op callback, without waiting for any node response.
3. After the loop, assert `len(h.activeRequests) == N` (via a test-only accessor or `getActiveRequest` probing), demonstrating unbounded growth.
4. Assert that no error/rejection is ever returned to the caller and that no cap/backpressure mechanism triggers, i.e. `newActiveRequest` never returns anything other than the "duplicate ID" error even under massive concurrent unique-ID load — proving the missing reject/cap mechanism.
5. Optionally measure and assert increasing latency of `removeExpiredRequests`/`h.mu` acquisition as N grows, to demonstrate contention impact on concurrently-issued legitimate requests.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}
