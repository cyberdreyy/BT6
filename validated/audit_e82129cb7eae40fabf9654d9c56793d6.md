### Title
Unbounded per-caller request fan-out in confidential relay `HandleJSONRPCUserMessage`/`fanOutToNodes` allows DON send-capacity exhaustion via distinct request IDs - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`HandleJSONRPCUserMessage` only validates that `req.ID` is non-empty and ≤200 characters before creating an `activeRequest` and calling `fanOutToNodes`, which sends the request to every DON member concurrently. There is no per-caller/per-owner/per-subscription quota — only `globalNodeRateLimiter` and `perNodeRateLimiters` keyed by DON node address, which are applied in `HandleNodeMessage` (inbound node responses), not on the outbound path from `HandleJSONRPCUserMessage`/`fanOutToNodes`.

### Finding Description
`HandleJSONRPCUserMessage` (core/services/gateway/handlers/confidentialrelay/handler.go:349-366) validates only `req.ID != ""` and `len(req.ID) <= 200`. It then calls `newActiveRequest` (handler.go:368-383), whose only uniqueness check is that the same `req.ID` string is not already active (`h.activeRequests[req.ID] != nil`) — trivially bypassed by using distinct IDs. `fanOutToNodes` (handler.go:618-652) then unconditionally does `group.Go` for every DON member and calls `h.don.SendToNode(sendCtx, node.Address, &ar.req)` for each, with no gate checking who the caller is or how many requests that caller has already issued.

The only rate limiters present, `globalNodeRateLimiter` and `perNodeRateLimiters` (handler.go:183-184, 232-244), are consulted exclusively in `HandleNodeMessage` when processing responses coming back from DON nodes (handler.go:395-406) — they do not gate the inbound-from-user fan-out path at all. There is no per-owner/per-subscription limiter analogous to the `userRateLimiter`/`PerWorkflow.HTTPTrigger.RateLimit` seen in the sibling `v2/http_handler.go` gateway handler for HTTP triggers. Thus any caller able to reach `HandleJSONRPCUserMessage` with distinct 200-char-or-shorter IDs can generate unlimited concurrent `SendToNode` calls to every DON member, consuming node websocket send capacity and per-node token-bucket budget shared with legitimate callers.

### Impact Explanation
This matches a Denial-of-Service / resource-exhaustion impact class: an unprivileged caller can flood every member of a DON with attacker-originated relay requests, consuming shared per-node/global send capacity (`perNodeRateLimiters`, `globalNodeRateLimiter` on the inbound-node side) and DON node processing resources, degrading or denying service to legitimate subscribers of the same DON who share that finite capacity. This is scoped to availability degradation for the confidential relay method group, not a direct fund-loss or credential-disclosure bug.

### Likelihood Explanation
Feasibility is high: the attacker needs only reachability to the gateway's `HandleJSONRPCUserMessage` entry point for the `confidentialrelay` handler's methods (`MethodSecretsGet`, `MethodCapabilityExec`) with a validly-formed request and a fresh random/incrementing ID under 200 characters each time — no privileged role, subscription ownership, or special credential is required beyond whatever base signature/format check gateway ingress applies before dispatch. It's fully repeatable at machine speed, bounded only by the attacker's own outbound throughput and, indirectly, by `activeRequests` map memory growth until entries expire via `removeExpiredRequests` after `requestTimeout`.

### Recommendation
Add a per-caller (per-owner, per-subscription, or per-API-key/identity, depending on what identity is available at this layer) rate limiter or in-flight-request cap in `HandleJSONRPCUserMessage`/`newActiveRequest`, mirroring the `userRateLimiter` pattern already used in `core/services/gateway/handlers/capabilities/v2/http_handler.go` (`cresettings.Default.PerWorkflow.HTTPTrigger.RateLimit`). Reject or throttle new `activeRequest` creation once a caller's outstanding/recent request count exceeds a configured threshold, independent of `req.ID` uniqueness.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
