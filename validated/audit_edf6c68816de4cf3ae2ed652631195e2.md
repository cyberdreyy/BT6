### Title
Missing non-negative/zero validation on job-controlled resource limit overwrites - (File: executors/kubernetes/util.go, executors/kubernetes/overwrites.go)

### Summary
`createResourceList` in `executors/kubernetes/util.go` accepts any string that `resource.ParseQuantity` can parse (including `"0"` and negative values like `"-1"`) with no floor/sign validation, and the only check applied earlier in `evaluateMaxResourceOverwrite` (`executors/kubernetes/overwrites.go`) is an upper-bound comparison (`cmp == 1` rejected), never a lower-bound/sign check. A job that sets `KUBERNETES_CPU_LIMIT=0` (or a negative quantity) can pass through both layers and reach `api.ResourceList` used to build the pod's container resources.

### Finding Description
The overwrite pipeline is: `createOverwrites` → `evaluateMaxBuildResourcesOverwrite`/`evaluateMaxHelperResourcesOverwrite`/`evaluateMaxPodResourcesOverwrite`/`evaluateMaxServiceResourcesOverwrite` → `evaluateMaxResourceListOverwrite` → `evaluateMaxResourceOverwrite` → `createResourceList` ( [1](#0-0) , [2](#0-1) ).

`evaluateMaxResourceOverwrite` parses both the admin-configured max (`maxResource`) and the job-supplied `overwriteValue` via `resource.ParseQuantity`, then only rejects the overwrite if `rOverwriteValue.Cmp(rMaxResource) == 1` (overwrite greater than max): [3](#0-2) 

A job variable such as `KUBERNETES_CPU_LIMIT=0` or `KUBERNETES_CPU_LIMIT=-1` parses successfully as a valid `resource.Quantity`, and since `0` or a negative value is always `Cmp`-less-than any positive `maxCPU`, the check never triggers `overwriteTooHighError`. The value is accepted and returned as the new resource string.

That string then flows into `createResourceList`, which only checks for parse errors, not for negative/zero bounds, before inserting the quantity directly into `api.ResourceList`: [4](#0-3) 

No other check in this path (`overwriteRegexCheck`, `evaluateOverwrite`, etc.) validates sign or floor value; those functions govern string pattern matching and upper bound only, not resource-value semantics.

### Impact Explanation
An admin who sets `KUBERNETES_CPU_LIMIT_OVERWRITE_MAX_ALLOWED` (or memory/ephemeral-storage equivalents) intends to cap CI job resource usage on a shared Kubernetes node. Kubernetes/container-runtime semantics treat a CPU limit of `0` in `resources.limits.cpu` as effectively unbounded in some runtime configurations (no CFS quota programmed), and it is not universally rejected by API-server validation the way negative values are. A job author can therefore submit `KUBERNETES_CPU_LIMIT=0` and bypass the admin's intended cap, allowing that job's container to consume unbounded CPU on the shared node, degrading or starving other projects' jobs scheduled on the same node — a concrete resource-exhaustion/DoS impact matching the scoped invariant "runner-enforced resource constraints must not be bypassable by job input."

Negative values (`-1`) are more likely to be caught by Kubernetes API server admission validation (which typically rejects negative resource quantities), so the primary exploitable case is the zero-value bypass rather than negative values; but Runner-side code does not defend against either.

### Likelihood Explanation
Preconditions: the shared-runner administrator must have configured a max-allowed resource overwrite policy (`*OverwriteMaxAllowed`), which is a documented and commonly-recommended way to allow limited per-job overwrites while capping abuse. Given that, any unprivileged pipeline author with `.gitlab-ci.yml` control (or CI/CD variables) can set `KUBERNETES_CPU_LIMIT: "0"` with no special privilege, making this trivially reachable and repeatable for every job run against that runner.

### Recommendation
In `evaluateMaxResourceOverwrite` (executors/kubernetes/overwrites.go), reject overwrite values whose parsed quantity `Sign() <= 0` (i.e., zero or negative) before accepting them, in addition to the existing upper-bound check. Alternatively/complementarily, add the same floor check inside `createResourceList` (executors/kubernetes/util.go) so it independently refuses to place non-positive quantities into `api.ResourceList` regardless of caller, returning a `resourceQuantityError`-style error for `cpu`/`memory`/`ephemeralStorage` values that are `<= 0`.

func (o *overwrites) evaluateMaxResourceOverwrite(
	fieldName,
	value,
	maxResource,
	overwriteValue string,
	logger buildlogger.Logger,
) (string, error) {
	if maxResource == "" {
		logger.Debugln("setting allowing overrides for", fieldName, "is empty, disabling override.")
		return value, nil
	}

	if overwriteValue == "" {
		return value, nil
	}

	var rMaxResource, rOverwriteValue resource.Quantity
	var err error

	if rMaxResource, err = resource.ParseQuantity(maxResource); err != nil {
		return value, fmt.Errorf("parsing resource limit: %q", err.Error())
	}

	if rOverwriteValue, err = resource.ParseQuantity(overwriteValue); err != nil {
		return value, fmt.Errorf("parsing resource limit: %q", err.Error())
	}

	cmp := rOverwriteValue.Cmp(rMaxResource)
	if cmp == 1 {
		return "", &overwriteTooHighError{
			resource:  fieldName,
			max:       maxResource,
			overwrite: overwriteValue,
		}
	}

	logger.Println(fmt.Sprintf("%q overwritten with %q", fieldName, overwriteValue))

	return overwriteValue, nil
}

func createResourceList(cpu, memory, ephemeralStorage string) (api.ResourceList, error) {
	var rCPU, rMem, rStor resource.Quantity
	var err error

	parse := func(s string) (resource.Quantity, error) {
		var q resource.Quantity
		if s == "" {
			return q, nil
		}
		if q, err = resource.ParseQuantity(s); err != nil {
			return q, err
		}
		return q, nil
	}

	if rCPU, err = parse(cpu); err != nil {
		return api.ResourceList{}, &resourceQuantityError{resource: "cpu", value: cpu, inner: err}
	}

	if rMem, err = parse(memory); err != nil {
		return api.ResourceList{}, &resourceQuantityError{resource: "memory", value: memory, inner: err}
	}

	if rStor, err = parse(ephemeralStorage); err != nil {
		return api.ResourceList{}, &resourceQuantityError{
			resource: "ephemeralStorage",
			value:    ephemeralStorage,
			inner:    err,
		}
	}

	l := make(api.ResourceList)

	q := resource.Quantity{}
	if rCPU != q {
		l[api.ResourceCPU] = rCPU
	}
	if rMem != q {
		l[api.ResourceMemory] = rMem
	}
	if rStor != q {
		l[api.ResourceEphemeralStorage] = rStor
	}

	return l, nil
}
