### Title
ConvexStrategyETH accepts native ETH but has no `transferETH`/rescue path — ETH sent to the strategy is permanently locked - (File: contracts/strategies/convex/ConvexStrategyETH.sol)

### Summary
`ConvexStrategyETH` exposes an unguarded `receive() external payable {}` so any EOA or contract can send native ETH to the strategy (accidentally, via refund paths, or via `selfdestruct`). While `ConvexBaseStrategy` provides an owner-only ERC20 rescue (`transferToken`), there is no equivalent native-token rescue. Any ETH balance held by the contract is permanently frozen — it cannot be wrapped to WETH, deposited into Curve, or transferred out.

### Finding Description
The bug-class analog to "missing `transferETH`" maps onto the strategy/rescue surface:

- `ConvexStrategyETH._depositInCurve` unwraps WETH to ETH and calls `add_liquidity{value: _balance}` with the full ETH balance, so ETH is deliberately part of the contract's flow, and `receive()` accepts it (`contracts/strategies/convex/ConvexStrategyETH.sol:35`).
- `ConvexBaseStrategy.transferToken` is the only rescue mechanism and uses `IERC20Detailed(_token).safeTransfer` — it cannot move ETH (`contracts/strategies/convex/ConvexBaseStrategy.sol:423-429`).
- No other function sends ETH out of the contract (no `call{value:...}`, no WETH-wrap of `address(this).balance`). `redeemRewards` / `_depositInCurve` consume ETH only when it comes from the WETH unwrap inside the same transaction.

Concrete stuck-ETH scenario (running epoch, standard mode, no privileged attacker):

1. `redeemRewards` is called by the whitelisted CDO during harvest. `_depositInCurve` unwraps the full WETH balance to ETH and calls `add_liquidity`. If the Curve pool reverts partway in a way that leaves ETH unspent (or the pool returns change), the ETH sits in the strategy. More directly:
2. Any unprivileged user can `send ETH → ConvexStrategyETH` (the bare `receive()` accepts it), or force-send via `selfdestruct`. That ETH is now permanently locked: `transferToken` reverts on `address(0)`/ETH pseudo-address (SafeERC20 call to non-contract fails or transfers ERC20 only), and nothing else moves ETH.

Note also that step 1 is worse than the UXD case: ETH left in the strategy from a prior harvest gets *accidentally swept* into the next `add_liquidity{value: _balance}` call, so donated/mistaken ETH is silently absorbed into LP tokens owned by the strategy share-holders — but if it arrives while no harvest ever happens again (e.g., strategy shut down), it is bricked forever.

### Impact Explanation
Permanent freezing of native-token value held by the strategy. The invariant "no funds left at the end of each tx" (`@dev` note in `ConvexBaseStrategy.sol:19`) is broken for ETH because there is no path to extract or wrap it. Loss equals the full ETH balance sent/left in the contract. Unlike the UXDGovernor report (which could rely on governance upgrading), recovery here requires a contract upgrade; if the deployed instance is not upgradeable, the ETH is unrecoverable.

### Likelihood Explanation
Medium-low. The contract only *needs* ETH transiently inside `_depositInCurve`, but the permissionless `receive()` makes accidental/forced ETH balance accumulation realistic: user mistakes, `selfdestruct` donations (ETH can be force-sent regardless of code), and Curve pools returning ETH change. There is no guard (e.g., `require(msg.sender == WETH)` as in `LidoCDOTrancheGateway.sol:99-101`) restricting who may send ETH.

### Recommendation
Either restrict the receive path or add a rescue path:

1. Restrict `receive()` to the WETH contract only: `require(msg.sender == WETH, "only-weth")` — this blocks all accidental sends (but not `selfdestruct`).
2. Add an owner-only `transferETH(address _to, uint256 _amount)` function (mirroring `transferToken`) or wrap leftover `address(this).balance` back into WETH at the end of `_depositInCurve`.
3. Optionally add a `sweep()` that wraps any ETH balance to WETH so it joins the normal rewards flow.

### Proof of Concept

```solidity
// test: ETH sent to ConvexStrategyETH is stuck
function testStuckETH() external {
    ConvexStrategyETH strat = ConvexStrategyETH(payable(address(strategy)));

    // unprivileged sender sends ETH directly (receive() accepts)
    address sender = makeAddr("sender");
    vm.deal(sender, 1 ether);
    vm.prank(sender);
    (bool ok,) = address(strat).call{value: 1 ether}("");
    assertTrue(ok);
    assertEq(address(strat).balance, 1 ether);

    // owner tries to rescue via transferToken -> reverts (ETH is not ERC20)
    vm.prank(owner);
    vm.expectRevert();
    strat.transferToken(address(0), 1 ether, owner);

    // no function exists to move ETH; balance remains
    assertEq(address(strat).balance, 1 ether);
}
```
