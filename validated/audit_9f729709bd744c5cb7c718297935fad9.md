### Title
Process-group-based `ForceKill` can be bypassed by a job process that forks into a new session (setsid) before termination - ([File: helpers/process/killer_unix.go])

### Summary
`osKillWait.KillAndWait` (`helpers/process/killer.go`) delegates termination entirely to `unixKiller.Terminate`/`ForceKill`, which send `SIGTERM`/`SIGKILL` to the negative PID of the job's original process (i.e. to its process group) rather than to individual descendants. A job script that traps `SIGTERM` and forks a child which calls `setsid`/re-execs into a new session detaches that child from the original process group before the group-wide signal is delivered, so neither the graceful `SIGTERM` nor the forced `SIGKILL` reaches it.

### Finding Description
`setProcessGroup` in `helpers/process/job_unix.go` sets `Setpgid: true` on the job's `exec.Cmd`, making the job's own PID the process group ID (PGID). `unixKiller.getPID` in `helpers/process/killer_unix.go` returns `-Pid`, and both `Terminate()` and `ForceKill()` call `syscall.Kill(-Pid, SIG...)`, which per `kill(2)` semantics signals every process that still belongs to that PGID.

A process only remains part of that PGID as long as it hasn't called `setsid()`/`setpgid()` to move itself to a new group. A job script that:
1. Installs a `SIGTERM` trap on entry,
2. Forks a child and has it call `setsid` (or double-forks and re-execs, the classic daemonizing pattern) to move into a brand-new session/PGID,
3. Lets the trap handler simply exit after detaching,

produces a descendant that is no longer a member of the original PGID by the time `osKillWait.KillAndWait` (`helpers/process/killer.go:66-92`) sends `SIGTERM`. `KillAndWait` waits up to `gracefulKillTimeout` (`GracefulTimeout`, 10 minutes) for `waitCh`, then calls `ForceKill()`, which sends `SIGKILL` to the same now-stale PGID, and waits up to `forceKillTimeout` before giving up. Since the daemon is in a different PGID, neither signal is ever delivered to it, and it survives the entire kill sequence.

There is no other cleanup mechanism in this code path (e.g. cgroup-based freezing, PID-namespace containment, or recursive `/proc` child enumeration) to catch detached descendants — the only enforcement is the PGID-based `syscall.Kill`.

### Impact Explanation
On executors where the job runs directly on host process space (shell, ssh, custom executors on a shared host) an unprivileged pipeline author can leave an arbitrary long-running process (e.g., a backdoor listener, resource-consuming daemon, or persistence mechanism) running on the runner host well after the job is cancelled/times out and after Runner has reported the job as terminated. This violates the assumption that `ForceKill`/`KillAndWait` terminate the whole job subtree, letting a "cancelled" job's payload continue to run and consume resources or maintain access on a multi-tenant host.

### Likelihood Explanation
This requires only shell-level scripting ability inside the job (`trap`, `setsid`, fork/exec), which any pipeline author on a shell/ssh/custom executor already has. It is fully deterministic and repeatable — no race condition or timing luck is required beyond the trap handler completing the `setsid` call before the `SIGTERM` is processed, which is trivially achievable.

### Recommendation
Do not rely solely on PGID-based signaling for job termination. Track and kill/reap all descendant PIDs recursively (e.g., walk `/proc/<pid>/task/*/children` or maintain a process tree), or run jobs inside a dedicated Linux namespace/cgroup (`cgroup.kill`, PID namespace) so that a full subtree kill is enforced by the kernel regardless of `setsid` calls, rather than by the mutable process-group membership.

### Proof of Concept
Go integration test extending `helpers/process/killer_integration_test.go`:
```go
func TestKillAndWait_EscapesViaSetsid(t *testing.T) {
    script := `
trap 'echo trapped' TERM
( setsid sh -c 'while true; do sleep 1; done' & )
sleep 30
`
    cmd := exec.Command("sh", "-c", script)
    // start via the runner's Commander/osCmd wrapper with Setpgid: true,
    // capture the daemon's PID by writing it to a temp file inside setsid subshell.

    waitCh := make(chan error, 1)
    go func() { waitCh <- cmd.Wait() }()

    kw := NewOSKillWait(logger, 200*time.Millisecond, 200*time.Millisecond)
    err := kw.KillAndWait(commander, waitCh)

    // assert KillAndWait returned (job "terminated")
    require.Error(t, err) // KillProcessError, since job process itself may also linger in trap

    // assert the detached daemon PID (read from temp file) is still alive
    daemonPID := readPIDFromFile(t)
    require.NoError(t, syscall.Kill(daemonPID, 0), "daemon should still be alive after ForceKill")
}
```
Expected assertion: the `setsid`-detached daemon process remains signallable (`kill(pid, 0)` succeeds) after both the graceful and force-kill windows in `KillAndWait` have elapsed, proving it escaped both `SIGTERM` and `SIGKILL`. [1](#0-0) [2](#0-1) [3](#0-2)

```go
// KillAndWait will take the specified process and terminate the process and
// wait util the waitCh returns or the graceful kill timer runs out after which
// a force kill on the process would be triggered.
func (kw *osKillWait) KillAndWait(command Commander, waitCh chan error) error {
	process := command.Process()
	if process == nil {
		return ErrProcessNotStarted
	}

	log := kw.logger.WithFields(logrus.Fields{
		"PID": process.Pid,
	})

	processKiller := newProcessKiller(log, command)
	processKiller.Terminate()

	select {
	case err := <-waitCh:
		return err
	case <-time.After(kw.gracefulKillTimeout):
		processKiller.ForceKill()

		select {
		case err := <-waitCh:
			return err
		case <-time.After(kw.forceKillTimeout):
			return &KillProcessError{pid: process.Pid}
		}
	}
}
```

```go
func (pk *unixKiller) Terminate() {
	if pk.cmd.Process() == nil {
		return
	}

	err := syscall.Kill(pk.getPID(), syscall.SIGTERM)
	if err != nil {
		pk.logger.Warn("Failed to terminate process:", err)

		// try to kill right-after
		pk.ForceKill()
	}
}

func (pk *unixKiller) ForceKill() {
	if pk.cmd.Process() == nil {
		return
	}

	err := syscall.Kill(pk.getPID(), syscall.SIGKILL)
	if err != nil {
		pk.logger.Warn("Failed to force-kill:", err)
	}
}

// getPID will return the negative PID (-PID) which is the process group. The
// negative symbol comes from kill(2) https://linux.die.net/man/2/kill `If pid
// is less than -1, then sig is sent to every process in the process group whose
// ID is -pid.`
func (pk *unixKiller) getPID() int {
	return pk.cmd.Process().Pid * -1
}
```
