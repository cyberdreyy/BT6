### Title
Post-default withdraw requests pay 1:1 out of the fixed `defaultRecoveryReserve`, draining funds reserved for haircut-bearing defaulted claimants - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
After `finalizeDefaultRecovery`, the vault's entire recovered underlying is isolated in `defaultRecoveryReserve`, sized exactly to pay all defaulted-epoch receipt claims at `defaultRecoveryPrice`. However, `requestWithdraw` still accepts new requests post-finalization: it burns the CDO's strategy tokens, mints the user a receipt, and records `postDefaultRequests[_user]`, without adding any underlying to the reserve. `_claimPostDefaultWithdrawRequest` then pays that request 1:1 out of `defaultRecoveryReserve`, so each post-default claim consumes reserve that was accounted for other claimants — an out-of-bounds-style "read/write past the validated region" analog to CVE-2023-3732: an index/epoch path that was never validated against the finalized recovery boundary.

### Finding Description
- `finalizeDefaultRecovery` computes `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` and stores `defaultRecoveryReserve = reserveAmount` (lines 686-692). The reserve is the sole backing for `pendingBasis` claims (defaulted receipts) plus active-NAV recovery.
- In `requestWithdraw`, when `defaultRecoveryFinalized` is true, the vault mints a receipt and sets `postDefaultRequests[_user] = _amount` (lines 247-257). No underlying is pulled and `defaultRecoveryReserve` is not increased — the burned CDO strategy tokens were already repriced to the recovery ratio, so their backing is already inside the same reserve.
- `_claimPostDefaultWithdrawRequest` calls `_transferDefaultRecovery(_user, amount)` (lines 760-767), which does `defaultRecoveryReserve -= amount` and transfers the full amount at par (lines 912-917).
- Result: every post-default claim is paid at 100% while the reserve was only provisioned to cover `recoveryPrice`-haircut claims. An unprivileged tranche holder (or the queue/any user routing through the CDO's `requestWithdraw`) can claim post-default at par and leave the reserve undercollateralized: later defaulted-epoch claimants' `_transferDefaultRecovery` calls underflow/revert or the reserve is exhausted, permanently freezing their unclaimed recovery.

Broken invariant: isolation and sufficiency of the recovery reserve ("one receipt, one haircut-priced payout"). Existing guards do not stop it — `_transferDefaultRecovery` has no solvency check, and the only request-time guard (`_hasWithdrawRequest`/`postDefaultRequests != 0`) merely rate-limits the attacker to one claim.

### Impact Explanation
Direct theft of unclaimed yield / insolvency: post-default claimants extract underlying at par from a reserve sized only for haircut claims. Quantified loss equals `sum(postDefaultRequests)` paid out beyond provisioning; defaulted receipt holders and active tranche recovery are shorted by the same amount, and their claims revert once `defaultRecoveryReserve` underflows.

### Likelihood Explanation
Requires a defaulted-and-finalized pool (honest borrower default, honest owner/manager finalization) — a reachable terminal state — plus the CDO still routing `requestWithdraw` post-default, which the strategy code explicitly supports (the `defaultRecoveryFinalized` branch exists solely for that path). The attacker is any tranche-token holder, fitting the unprivileged-attacker model. Residual uncertainty: whether `IdleCDOEpochVariant.requestWithdraw` reverts when `defaulted()` is true could not be fully verified in this pass; if it does, post-default requests can still be opened in the window between pool default and `finalizeDefaultRecovery` only if the guard ordering permits, which narrows but does not necessarily eliminate the path.

### Recommendation
Either (a) revert `requestWithdraw` once `defaultRecoveryFinalized` is set and route all post-default exits through the recovery claim path at `defaultRecoveryPrice`, or (b) fund the reserve at request time by pulling the corresponding underlying from the CDO/`recoverySource`, or haircut `postDefaultRequests` claims by `defaultRecoveryPrice` in `_claimPostDefaultWithdrawRequest` so payouts never exceed per-unit provisioning.

### Proof of Concept
Foundry fork PoC sketch (not executed — index-level analysis only):

```solidity
// After borrower default and CDO.finalizeDefault(...)/strategy.finalizeDefaultRecovery(...)
// defaultRecoveryReserve = R, defaultRecoveryPrice = p < 1e18.
uint256 reservePre = strategy.defaultRecoveryReserve();

// Attacker: tranche holder. CDO applies virtualPrice haircut so _amount is post-haircut.
vm.prank(attacker);
cdo.requestWithdraw(attackerTrancheBal, address(AAtranche)); // -> strategy.requestWithdraw(_amount, attacker, _principal)

// postDefaultRequests[attacker] == _amount, reserve unchanged
assertEq(strategy.defaultRecoveryReserve(), reservePre);

// Attacker claims at par from the same reserve
vm.prank(address(cdo));
strategy.claimWithdrawRequest(attacker); // via CDO claim path
// underlying received = _amount (1:1), reserve -= _amount
assertEq(strategy.defaultRecoveryReserve(), reservePre - _amount);

// Honest defaulted claimant with claimBasis b now finds reserve < b * p / 1e18
// -> _transferDefaultRecovery underflows (0.8.10 checked math) -> permanent freeze.
```
