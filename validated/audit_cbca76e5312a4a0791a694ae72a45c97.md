### Title
Unprivileged ERC4626 vault donation inflates `totalInterestDueNow`, minting unbacked epoch interest and draining the pool - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
The bug-class analog is a "fault-probe" on the interest-verification step: `stopEpoch` in minted-interest, programmable-borrower mode unconditionally trusts `ProgrammableBorrower.totalInterestDueNow()`, which measures "vault interest" as the raw delta between `vault.convertToAssets(shares)` and a stored principal baseline. Any unprivileged user of the external ERC4626 vault can inject a donation into the vault, causing the probe to report phantom interest. Because programmable mode forbids the `_interest > 1` override, the `maxApr` sanity check that bounds minted interest is skipped entirely, so the phantom value is minted into tranche prices with no cash backing. The attacker (also a tranche holder and vault shareholder) withdraws real liquidity at the inflated price and recovers the donation by redeeming vault shares.

### Finding Description
In `IdleCDOEpochVariant.stopEpoch`, the interest figure comes from `IProgrammableBorrower(_borrower()).totalInterestDueNow()` whenever `isProgrammableBorrower` is set (contracts/IdleCDOEpochVariant.sol:1001-1005). `totalInterestDueNow` (contracts/strategies/idle/ProgrammableBorrower.sol:330-334) computes `vaultInterest` via `_vaultNetInterest` (lines 337-347) as `bufferedVaultDelta + (_currentVaultAssets() + epochWithdrawnFromVault) - (epochStartVaultAssets + epochDepositedToVault)`, where `_currentVaultAssets()` is a live `convertToAssets` read (lines 546-549). A direct transfer of the underlying into the external vault therefore counts 1:1 as "interest".

In minted mode (`isInterestMinted`, required for programmable borrowers per `_checkProgrammableBorrowerMode`), `_amountToPullFromBorrower` is `0` (IdleCDOEpochVariant.sol:374-376): no cash is pulled, and the interest is credited purely by minting strategy tokens / inflating `virtualPrice`. The only bound on minted interest, `_grossInterest <= _calcInterestWithApr(getContractValue(), maxApr) + pendingWithdrawFees` (line 379), is guarded by `if (_mintInterest && _interest > 1)`, but `_resolveStopEpochInterest` reverts whenever `_interest > 1` for programmable borrowers (line 1003), so the cap can never fire. `_skimDonatedAssets` (line 355) only sweeps donations sent to the CDO contract, not to the external vault. Nothing in `onStopEpoch` validates that the reported interest is backed by realized borrower repayment or real vault yield.

### Impact Explanation
Direct theft / insolvency. Each underlying donated to the vault mints ~1 unit of unbacked pool interest, raising `virtualPrice` for both tranches. The attacker holds tranche tokens, then calls `requestWithdraw`/`claimWithdrawRequest` to extract real underlying at the inflated price. The donation is recovered via `vault.redeem`, so net cost is bounded by the vault's other shareholders' dilution. The pool is left holding phantom "interest" claims, so later withdrawers are haircutted or frozen — solvency and fair mint/burn invariants are broken. Loss is bounded by pool TVL (attacker can repeat each epoch).

### Likelihood Explanation
Requires a deployment in programmable-borrower mode with an ERC4626 vault that accepts direct donations (standard for most ERC4626s, including donation-susceptible or low-virtual-shares vaults). The attacker only needs to be an allowed vault user and a tranche-token holder — both unprivileged roles per the threat model. No privileged call is needed; the manager calls `stopEpoch` as usual and unwittingly executes the inflation.

### Recommendation
- In `ProgrammableBorrower._vaultNetInterest`, distinguish donated assets from yield — e.g., track vault share price deltas or use shares-acquired accounting (`epochDepositedToVault` measured in shares), so unrequested balance increases can't count as interest.
- In `IdleCDOEpochVariant.stopEpoch`, apply the `maxApr` bound unconditionally to `totalInterestDueNow()` in minted mode, not only on the `_interest > 1` path.
- Optionally require `stopEpoch` to verify that minted interest does not exceed borrower-repayable amounts (`borrowerInterestOwedNow + bufferInterest`) minus a configured allowance for genuine vault yield.

### Proof of Concept
```solidity
// Foundry fork PoC sketch (test/foundry/ProgrammableBorrowerDonation.t.sol)
// Mode: isProgrammableBorrower = true, isInterestMinted = true.
function testVaultDonationInflatesMintedInterest() external {
    // 1. attacker (KYC'd lender) deposits 10_000 underlying as AA, honest LPs deposit more
    vm.startPrank(attacker);
    idleCDO.depositAA(10_000 * ONE_SCALE);
    vm.stopPrank();

    // 2. manager starts epoch; ProgrammableBorrower parks idle cash in the ERC4626 vault
    vm.prank(manager);
    cdoEpoch.startEpoch();  // -> onStartEpoch deposits idle balance, snapshots epochStartVaultAssets

    // 3. attacker acquires vault shares, then donates D underlying directly to the vault,
    //    inflating convertToAssets for all shareholders including ProgrammableBorrower
    deal(underlying, attacker, DONATION);
    vm.startPrank(attacker);
    IERC20(underlying).transfer(address(externalVault), DONATION);
    vm.stopPrank();

    // 4. warp to epoch end; manager calls stopEpoch(0, 0).
    //    totalInterestDueNow() now includes DONATION as phantom vault interest.
    //    minted mode pulls 0 cash; virtualPrice is inflated by ~DONATION.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    uint256 navPre = cdoEpoch.getContractValue();
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    assertGt(cdoEpoch.getContractValue(), navPre + DONATION - epsilon);

    // 5. attacker requests + claims withdraw at the inflated price, draining real cash
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(0, cdoEpoch.AATranche());
    // after one epoch / or instant path, claim:
    vm.prank(attacker);
    cdoEpoch.claimWithdrawRequest();

    // 6. attacker redeems vault shares to recover the donation
    vm.prank(attacker);
    externalVault.redeem(externalVault.balanceOf(attacker), attacker, attacker);

    // 7. invariant broken: honest LPs' remaining claims exceed real pool balance
    assertLt(underlying.balanceOf(address(cdoEpoch)) + queuedClaims,
             honestClaimsOutstanding); // insolvency
}
```
