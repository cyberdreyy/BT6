### Title
Windows `Path().Contains` performs case-sensitive comparison, allowing case-varied `dir` to bypass `IsHostMountedVolume` host-mount protection - ([File: executors/docker/internal/volumes/parser/windows_path.go])

### Summary
`windowsPath.Contains` (used by `IsHostMountedVolume` via `volumeParser.Path().Contains(parsedVolume.Destination, dir)`) never case-folds path segments before doing prefix comparison, even though Windows/NTFS paths are case-insensitive. A build directory (`dir`) that differs only in letter case from an admin-configured host-mounted volume destination will be reported as *not* contained, silently bypassing the host-mount protection check.

### Finding Description
`IsHostMountedVolume` in `executors/docker/internal/volumes/utils.go:21-45` iterates configured `volumes`, parses each with `volumeParser.ParseVolume`, and calls `volumeParser.Path().Contains(parsedVolume.Destination, dir)` to decide if the job's build/cache `dir` falls inside a host-mounted volume destination. For the Windows executor, `Path()` returns the internal `windowsPath` type, whose `Contains` implementation is: [2](#0-1) 

`convert` strips the drive-letter colon, replaces `\`/`:` with `/`, and runs `gopath.Clean`, but it never lower-cases (or upper-cases) the path. `windowsParser.ParseVolume` itself is case-insensitive by regex design (`(?i)` flag, confirmed by the "case insensitive disk mount" test case), so a volume spec like `C:\Data:C:\Data` and a build dir `c:\data\subdir` both parse successfully, but `Contains("C:/Data/", "c:/data/subdir/")` does a case-sensitive `strings.HasPrefix` and returns `false` because `"C:/Data/"` (after convert, without lowercasing) does not match `"c:/data/subdir/"` byte-for-byte.

Since NTFS/Windows paths are case-insensitive, the manually-computed "real" containment (using case-insensitive comparison, which is how the OS/Docker actually resolves these paths) would be `true`, while `IsHostMountedVolume` returns `(false, nil)` — exactly the under-reporting condition described in the fuzz target.

### Impact Explanation
On Windows Docker executors, if a job can influence the effective build/cache directory (e.g., via `GIT_CLONE_PATH`/custom build directory feature) with a case variant of an admin-configured host-mounted volume path, the host-mount collision check is silently bypassed. This can let a job's build directory resolve to the same host location as a protected host-mounted volume without the guard rejecting it, enabling unintended host file overwrite/read within that host-mounted directory — matching the scoped impact.

### Likelihood Explanation
This requires: (1) a Windows Docker executor with `Docker.Volumes` configured to bind-mount a host path, and (2) the attacker being able to make the job's build/cache directory match that host path with different letter casing. The second condition depends on whether the deployment allows job-controlled build directory customization; where that is permitted, the bypass is straightforward and deterministic (not probabilistic), and is directly reproducible via a unit test on `windowsPath.Contains`/`IsHostMountedVolume` without needing an actual Windows host, since the path logic is implemented in pure Go strings (the `!windows` build-tag file is used for cross-platform testing, per the `//go:build !windows` file already found at `executors/docker/internal/volumes/parser/windows_path.go:1`). [3](#0-2) 

### Recommendation
Normalize case in `windowsPath.convert` (e.g., `strings.ToLower`) before comparison in both `Contains` and `IsRoot`/`IsAbs` where relevant, so that Windows path containment checks are case-insensitive, matching actual filesystem semantics.

func (p *windowsPath) Contains(basePath, targetPath string) bool {
	return strings.HasPrefix(p.convert(targetPath, true), p.convert(basePath, true))
}

// convert absolute path to a regular and absolute forward-slash based path,
// useful only for comparisons.
//
// c:\hello\world -> /c/hello/world/
// \\server_name/hello -> /server_name/hello/
func (p *windowsPath) convert(pathname string, dir bool) string {
	if len(pathname) > 1 && pathname[1] == ':' {
		pathname = pathname[:1] + pathname[2:]
	}
	pathname = strings.NewReplacer("\\", "/", ":", "/").Replace(pathname)
	pathname = gopath.Clean("/" + pathname)

	if dir && !strings.HasSuffix(pathname, "/") {
		return pathname + "/"
	}
	return pathname
}
