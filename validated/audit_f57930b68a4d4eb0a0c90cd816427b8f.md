This confirms the analog exists: `grant_role_unchecked` gates all future `DefaultAdmin` role grants via `ensure_role_admin_mutations_available`, which reverts as `AccessControlUnauthorizedAccount` whenever `role_member_count(DefaultAdmin) == 0` [1](#0-0) , and the golden tests confirm no admin means every `grantRole` call — even the init-time factory call, which runs with the factory's own address as caller through `route(..., true, ...)` — reverts once `role_member_count(DefaultAdmin) == 0` [2](#0-1) .

### Title
Token creator setting `initialAdmin = address(0)` in `createB20` permanently bricks all admin-gated B-20 token functions - (File: crates/common/precompiles/src/b20_factory/logic/v1.rs)

### Summary
`FactoryV1::init_asset_token` / `init_stablecoin` only grant the `DefaultAdmin` role when the caller-supplied `initialAdmin` field is non-zero, and this field is consumed exactly once at token creation with no factory-level validation.

### Finding Description
When an unprivileged caller (the "B-20 token creator") invokes `createB20`, the ABI parameters `B20AssetCreateParams`/`B20StablecoinCreateParams` carry an `initialAdmin` address [3](#0-2) . `TokenCreateParams::decode` copies this straight into `CommonParams.initial_admin` with no non-zero check, and `TokenCreateParams::validate()` only validates decimals/currency fields — never `initial_admin` [4](#0-3) . `init_asset_token` then grants `DefaultAdmin` conditionally:

```
if !common.initial_admin.is_zero() {
    token.grant_role_unchecked(B20TokenRole::DefaultAdmin.id(), common.initial_admin, ...)?;
}
``` [5](#0-4) 

If `initialAdmin` is `address(0)` (accidentally or maliciously), no account ever receives `DefaultAdmin`, and `role_member_count(DefaultAdmin)` stays `0`. Every subsequent attempt to fix this — including via `initCalls` executed atomically at creation time with the factory itself as caller [6](#0-5)  — routes through `grant_role`, which first calls `ensure_role_admin_mutations_available`:

```
if token.accounting().role_member_count(admin_role)? == U256::ZERO {
    return Err(... AccessControlUnauthorizedAccount { account: caller, neededRole: admin_role });
}
``` [1](#0-0) 

This guard reverts unconditionally once the admin count is zero, regardless of caller — including the factory's own privileged `initCalls` path — as confirmed by `golden_grant_role_unprivileged_no_admin_reverts` [2](#0-1) . This is structurally identical to the report's `callOnDepositCallback`/`escrowImplementation` bug class: a creation-time parameter chosen by an unprivileged deployer, with no downstream validation, that — if set to a "false"/zero value — permanently disables a critical capability of the created contract instance with no recovery path.

### Impact Explanation
Once deployed with `initialAdmin = address(0)`, the token is permanently admin-less: `pause`, `updateSupplyCap`, `updatePolicy`, `setRoleAdmin`, minting-role management, and any other `DefaultAdmin`-gated function become permanently unreachable for the lifetime of that deterministic token address, since the address is derived from `(caller, salt)` and re-deploying at the same slot is blocked by `TokenAlreadyExists` [7](#0-6) . Any funds/roles already deposited or minted into that token become permanently un-administrable (e.g. an unpausable, uncappable token whose policy can never be changed), matching "permanent freezing of funds"/loss of control for that token instance.

### Likelihood Explanation
`createB20` is directly callable by any unprivileged EOA once the relevant `ActivationFeature` (B20Asset/B20Stablecoin) is activated [8](#0-7) ; the caller fully controls `initialAdmin` and there is no validation rejecting the zero address, so triggering the bug requires only a single mis-set (or malicious) transaction — no special privilege needed.

### Recommendation
Reject `createB20` when `initialAdmin == address(0)` in `TokenCreateParams::validate()` (mirroring the existing `decimals`/`currency` validation), or unconditionally grant `DefaultAdmin` and treat a zero address as an explicit "no admin, transfer via initCalls" opt-in that is separately enforced (e.g. require at least one `grantRole(DefaultAdmin, ...)` init call before finalizing token creation).

### Proof of Concept
1. Caller invokes `createB20(ASSET, salt, B20AssetCreateParams{ initialAdmin: address(0), ... }, [])`.
2. `init_asset_token` skips `grant_role_unchecked(DefaultAdmin, ...)` because `initial_admin.is_zero()` [5](#0-4) .
3. Token is deployed; `role_member_count(DefaultAdmin) == 0`.
4. Any later `grantRole`/`pause`/`updateSupplyCap`/`updatePolicy` call — from any address, including a follow-up `initCalls`-style privileged call — reverts with `AccessControlUnauthorizedAccount` via `ensure_role_admin_mutations_available` [1](#0-0) .
5. The token at this deterministic address is permanently stuck with no admin, confirmed by golden test `golden_grant_role_unprivileged_no_admin_reverts` [2](#0-1) .

impl TokenCreateParams {
    /// Decodes ABI-encoded creation parameters for `variant`.
    pub fn decode(variant: B20Variant, params: &Bytes) -> Result<Self> {
        match variant {
            B20Variant::Stablecoin => {
                let p = IB20Factory::B20StablecoinCreateParams::abi_decode_validate(params)
                    .map_err(Self::invalid_params)?;
                Ok(Self::Stablecoin {
                    common: CommonParams { version: p.version, initial_admin: p.initialAdmin },
                    init: B20StablecoinInit {
                        name: p.name,
                        symbol: p.symbol,
                        supply_cap: B20FactoryStorage::DEFAULT_SUPPLY_CAP,
                        currency: p.currency,
                    },
                })
            }
            B20Variant::Asset => {
                let p = IB20Factory::B20AssetCreateParams::abi_decode_validate(params)
                    .map_err(Self::invalid_params)?;
                Ok(Self::Asset {
                    common: CommonParams { version: p.version, initial_admin: p.initialAdmin },
                    init: B20AssetInit {
                        name: p.name,
                        symbol: p.symbol,
                        supply_cap: B20FactoryStorage::DEFAULT_SUPPLY_CAP,
                        multiplier: INITIAL_MULTIPLIER,
                        decimals: p.decimals,
                    },
                })
            }
        }
    }

    /// Returns the shared token creation parameter version.
    pub const fn version(&self) -> u8 {
        match self {
            Self::Stablecoin { common, .. } | Self::Asset { common, .. } => common.version,
        }
    }

    /// Validates variant-specific invariants after the shared version check.
    ///
    /// Each arm owns its own rules. Version is checked first by the caller (`check_version`)
    /// so that version errors always take precedence over field-level errors.
    pub fn validate(&self) -> Result<()> {
        match self {
            Self::Stablecoin { init, .. } => Self::validate_stablecoin(init),
            Self::Asset { init, .. } => Self::validate_asset(init),
        }
    }

    /// Validates stablecoin initialization fields.
    pub const fn validate_stablecoin(_init: &B20StablecoinInit) -> Result<()> {
        // Currency validation is delegated to `B20StablecoinStorage::initialize`, which rejects
        // empty values with `MissingRequiredField` and non-A-Z values with `InvalidCurrency`.
        Ok(())
    }

    /// Validates asset-token initialization fields.
    pub fn validate_asset(init: &B20AssetInit) -> Result<()> {
        if init.decimals < B20AssetStorage::MIN_DECIMALS
            || init.decimals > B20AssetStorage::MAX_DECIMALS
        {
            return Err(BasePrecompileError::revert(IB20Factory::InvalidDecimals {
                decimals: init.decimals,
            }));
        }
        Ok(())
    }
