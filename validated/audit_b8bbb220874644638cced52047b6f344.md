## Local Aptos-Native Analog Found

### Title
Permissionless `distribute()` reward-payout loops abort entirely and permanently strand stake/vesting rewards when a single shareholder opts out of direct coin transfers - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`, `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
The external report's bug class is "iterate over N entities, but a single entity in an unexpected state causes a hard error that should instead have been scoped to that one entity." The Aptos analog is in the reward/commission distribution loops of `staking_contract::distribute_internal` and `vesting::distribute`: both iterate over **all** shareholders/recipients in a single atomic transaction and call `aptos_account::deposit_coins` for each. `deposit_coins` can unconditionally abort for one specific recipient (an account that exists but is not registered for `AptosCoin` and has opted out of unsolicited transfers), and because Move aborts revert the whole transaction, that one recipient's state permanently blocks payout to every other shareholder in the same pool, forever, with no self-healing skip.

### Finding Description
`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the target account exists, is not yet registered for the coin type, and has disabled `allow_arbitrary_coin_transfers` via the `DirectTransferConfig` resource: [1](#0-0) 

This function is called inside a `while`-loop over **all** pending recipients of a staking contract's distribution pool: [2](#0-1) 

and inside a `for_each_ref` loop over **all** shareholders of a vesting contract, called from the permissionless entry functions `distribute` / `distribute_many`: [3](#0-2) [4](#0-3) 

Just like `ExpectedWithdrawals` in the external report returned a hard error for the whole call because of one validator's non-standard withdrawal-credential prefix instead of skipping that validator, these Move loops abort the entire distribution transaction because of one recipient's account configuration instead of skipping that recipient and paying everyone else. Unlike the beacon-chain case (read-only view function), here the effect is on a **state-mutating, value-moving** entry point: coins are already extracted from the stake pool via `stake::withdraw_with_cap` before the loop runs, and the whole transaction — extraction included — reverts on abort, so no partial progress is ever committed.

Any shareholder (an ordinary, unprivileged vesting-contract beneficiary or a staking-contract recipient) can put themselves into the "not registered + opted out" state on their own account using the standard, unprivileged `DirectTransferConfig` toggle defined in the same module: [5](#0-4) 

Because this check only fires for accounts that are *not yet registered* for `AptosCoin`, the practical severity depends on whether such accounts still exist under the current APT/FungibleAsset model (e.g., accounts that were created via low-level `account::create_account` rather than `aptos_account::create_account`, or that never previously received APT and are added as a vesting beneficiary/shareholder by address only). I could not fully verify, from the indexed portion of `coin.move`, whether the FungibleAsset migration guarantees every account is always "registered" for `AptosCoin` by the time `distribute()` runs — this is the one open question that would need to be confirmed in a live/Devin session before treating this as fully proven.

### Impact Explanation
If reachable (i.e., a shareholder/recipient address exists in the pool without `AptosCoin` registration and has direct-transfer opt-out set), the impact matches the required "permanent lock / non-recoverable loss of claim rights" category exactly:
- All other shareholders in the same `vesting_contract_address`'s grant pool, and the admin's dust remainder, become permanently unable to call `distribute`/`distribute_many`/`admin_withdraw` (which itself calls `withdraw_stake` → `staking_contract::distribute`), because the offending shareholder is never removed from `grant_pool`'s shareholder table when the transaction aborts.
- Similarly, in `staking_contract::distribute_internal`, the staker and operator/beneficiary share one `distribution_pool`; if either becomes "unregistered + opted out," neither commission nor principal can ever be withdrawn from that staking contract again.
- Funds already earned (rewards, commission, vested principal) become stuck in the underlying stake pool / resource account indefinitely — a durable stranding of value, not merely a transient DoS.

### Likelihood Explanation
Reaching the "not registered for AptosCoin" precondition requires either (a) an account that never went through `aptos_account::create_account`/`register_apt`, or (b) semantics of the primary-fungible-store migration that leave some addresses "unregistered" from `coin::is_account_registered<AptosCoin>`'s point of view. I was not able to confirm this precondition definitively with the available index, so likelihood is uncertain pending further investigation of `coin.move`'s FA-migration registration logic — this is the key gap a follow-up session should close before this is escalated as a confirmed, fully proven bug.

### Recommendation
- In both `staking_contract::distribute_internal` and `vesting::distribute`, do not let a single recipient's `deposit_coins` failure abort the whole loop. Wrap each deposit so a failure re-queues/skips just that recipient's shares (e.g., re-buy them back into the pool or hold them in an escrow entry) rather than reverting the entire distribution.
- Alternatively, require/verify that every recipient added to a distribution/grant pool is already coin-registered at add-time, so `deposit_coins`'s conditional-abort branch is provably unreachable for pool members.

### Proof of Concept
Conceptual repro (pending confirmation of the registration precondition):
1. Employee `E` is added as a shareholder to a vesting contract via `create_vesting_contract`, at an address that is known but has never received APT and has no `CoinStore<AptosCoin>`/primary store.
2. `E` (or anyone controlling that account) calls the account's `DirectTransferConfig` toggle to set `allow_arbitrary_coin_transfers = false`.
3. Admin/anyone calls `vest()` then `distribute(contract_address)` once funds are unlocked.
4. The `for_each_ref` loop in `distribute` reaches `E`, calls `aptos_account::deposit_coins(E, ...)`, which hits the `can_receive_direct_coin_transfers` check and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. The whole transaction reverts; the withdrawn stake is never delivered to any shareholder, and every future call to `distribute`/`distribute_many` for this contract fails the same way, permanently. [6](#0-5) [7](#0-6)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun distribute_many(contract_addresses: vector<address>) acquires VestingContract {
        let len = contract_addresses.length();

        assert!(len != 0, error::invalid_argument(EVEC_EMPTY_FOR_MANY_FUNCTION));

        contract_addresses.for_each_ref(|contract_address| {
            let contract_address = *contract_address;
            distribute(contract_address);
        });
