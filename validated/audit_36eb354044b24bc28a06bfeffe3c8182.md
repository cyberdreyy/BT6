### Title
Unauthenticated disclosure of plugin Prometheus metrics via `/plugins/:name/metrics` - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers `/discovery`, `/plugins/:name/metrics`, and the plugin pprof endpoints directly on the base `api` route group with no authentication middleware, unlike every other sensitive endpoint in `v2Routes` which is wrapped in `auth.Authenticate(...)`. Any unauthenticated caller can enumerate plugin names via `/discovery` and then fetch the raw Prometheus metrics text for that plugin via `/plugins/:name/metrics`.

### Finding Description
In `core/web/router.go`, the `NewRouter` function builds an `api` route group with only rate limiting and session middleware applied (`core/web/router.go` lines 78-85), then calls `loopRoutes(app, api)` (line 91) alongside `debugRoutes`, `healthRoutes`, `sessionRoutes`, and `v2Routes`. `loopRoutes` itself registers:

```go
func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}
```
(`core/web/router.go` lines 230-236)

None of these routes are wrapped with `auth.Authenticate(...)` or any role check, in stark contrast to `v2Routes` which explicitly groups every sensitive route behind `authv2 := r.Group("/v2", auth.Authenticate(...))` (`core/web/router.go` lines 245-248) and `debugRoutes`, which wraps `/debug/vars` in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (`core/web/router.go` line 181).

`discoveryHandler` (`core/web/loop_registry.go` lines 53-81) returns a JSON list of Prometheus service-discovery target groups including each registered plugin's name (`LabelMetaPluginName`) and its metrics path (`pluginMetricPath`, line 237-239: `/plugins/%s/metrics`). `pluginMetricHandler` (`core/web/loop_registry.go` lines 96-128) takes the `:name` path parameter, looks it up in the in-memory `LoopRegistry`, and if found, proxies a plain HTTP GET to the internal plugin's `/metrics` endpoint and streams the raw response body back with `gc.Data(http.StatusOK, "text/plain", b)` — no session/token/role check is performed anywhere in this call path.

Because the whole `api` gin group has no default authentication requirement (auth is opt-in per-route via explicit middleware groups elsewhere), and `loopRoutes` never opts in, both endpoints are reachable by a completely unauthenticated caller.

### Impact Explanation
This falls under information disclosure of internal node/plugin runtime metrics (label sets, plugin build/version info, request counts, error counts, timing histograms, and any custom metric labels a LOOP plugin exposes) to an unauthenticated outsider. While metrics data alone is not typically fund-critical, it can leak internal topology, plugin versions/configuration fingerprints, and operational cardinality that aids further targeted attacks against a node, and it is a concrete confidentiality violation of node-operator infrastructure that should require authentication like every comparable admin/debug route (`/debug/vars`, `/v2/*`). Additionally, the sibling pprof handlers (`pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) registered in the same unauthenticated group expose profiling/symbol data through the same missing-auth pattern, compounding the exposure.

### Likelihood Explanation
No preconditions or credentials are required — a plain unauthenticated HTTP client can hit the node's web server. The attacker only needs network reachability to the node's API port (same reachability as any other unauthenticated route such as `/health`). The flow is fully repeatable: `GET /discovery` to enumerate plugin names, then `GET /plugins/<name>/metrics` to retrieve the metrics body.

### Recommendation
Wrap `loopRoutes` (and at minimum the plugin metrics/pprof endpoints) with the same authentication middleware used elsewhere, e.g. `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, and consider gating discovery/metrics/pprof behind `auth.RequiresAdminRole` similar to other operational/debug endpoints (`/debug/vars`, `metricRoutes`). If external Prometheus scraping without session cookies is required, use a dedicated bearer-token scheme analogous to `prometheusHandler`'s token check (`core/web/router.go` lines 677-699).

### Proof of Concept
Go handler-level integration test plan (mirroring `core/web/loop_registry_test.go`):
1. Build a test `chainlink.Application` with a `LoopRegistry` containing at least one registered plugin (e.g., name `"test-plugin"`) with a valid `EnvCfg.PrometheusPort`, and stand up a local test HTTP server on that port that returns a fixed body like `# HELP test_metric ...` for `/metrics`.
2. Call `web.NewRouter(app, nil)` to build the full `gin.Engine`, or directly call `loopRoutes(app, router.Group("/"))` on a fresh `gin.Engine`.
3. Using a plain `http.Client` (no cookies, no `Authorization` header, no API token), issue `GET /discovery` and assert `200 OK` with a JSON body containing `"test-plugin"` in the `__meta_plugin_name` label.
4. Using the same unauthenticated client, issue `GET /plugins/test-plugin/metrics` and assert `200 OK` with a body equal to the fixture metrics text, proving no auth check gated the request.
5. As a negative control, issue `GET /v2/jobs` with the same unauthenticated client and assert `401 Unauthorized`, demonstrating the double standard between `v2Routes` (authenticated) and `loopRoutes` (unauthenticated). [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5)

```go
// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}
```

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```
