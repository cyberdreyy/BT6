## #Vulnerability found for this question.

### Title
Unchecked possible zero/burn address when authorizing a new nonce account authority - (File: `programs/system/src/system_instruction.rs`)

### Summary
The `authorize_nonce_account` instruction handler in `programs/system/src/system_instruction.rs` accepts an arbitrary new `nonce_authority: &Pubkey` and writes it into nonce account state without any sanity check that it is a non-default (non-zero) or otherwise unusable public key. This mirrors the reported `UmamiPriceFeed.sol` bug class: a privileged setter (`setGov`) that is gated by the *current* privilege holder (`onlyGov`) but performs no validation on the incoming address, allowing the contract/account to become permanently locked if the new address has no corresponding private key.

### Finding Description
`authorize_nonce_account` is defined at [1](#0-0) . It checks that the account is writable and that the current signer set satisfies `Versions::authorize`, but performs no check on the value of `nonce_authority` itself — it is accepted verbatim and stored into the nonce `Data::authority` field.

This is directly exercised by the existing unit test `authorize_inx_ok`, which sets the new authority to `Pubkey::default()` and the call succeeds without error: [2](#0-1) .

The CLI-level command builder that ordinary users invoke (`authorize-nonce-account`) similarly passes the user-supplied `new_authority` straight through with no zero-address guard, and the CLI's own tests explicitly build such a command with `Pubkey::default()` as the new authority: [3](#0-2)  and [4](#0-3) .

Once the nonce authority is set to `Pubkey::default()` (or any pubkey without a known private key), all subsequent operations on that nonce account require a signer matching `data.authority`:
- `withdraw_nonce_account` requires `check_signer(&data.authority)` before funds can be withdrawn: [5](#0-4) .
- `authorize_nonce_account` itself requires the current authority to be among the transaction `signers` (via `Versions::authorize`), so the authority can never again be changed either: [1](#0-0) .

Since nobody possesses a private key for `Pubkey::default()` (analogous to Ethereum's zero address), the nonce account becomes permanently locked: its lamports can never be withdrawn and its authority can never be reassigned.

### Impact Explanation
This is a fund/state-lock vulnerability reachable from an ordinary user's transaction (no special privilege required — the caller only needs to currently be the nonce authority, which is the normal owner of the account). A single mistaken or maliciously-crafted `AuthorizeNonceAccount` instruction (e.g., from a compromised/malicious dApp or CLI misuse) permanently bricks the nonce account and locks any lamports held in it, with no recovery path, mirroring the "can lock the contract" impact described in the reported analog.

### Likelihood Explanation
Moderate: this requires either user error (accidentally supplying a default/zero pubkey, e.g. via an unset variable in a wallet or SDK integration) or a malicious front-end/dApp tricking a user into signing an `AuthorizeNonceAccount` instruction with an attacker-chosen unusable pubkey. There is no on-chain incentive check preventing it, and the code path is fully reachable by any nonce-account authority through a standard transaction.

### Recommendation
Add a sanity check in `authorize_nonce_account` (and ideally in the CLI-level `parse_authorize_nonce_account`/`process_authorize_nonce_account`) rejecting `Pubkey::default()` (and potentially other well-known unusable pubkeys such as the system program id) as a new nonce authority, returning `InstructionError::InvalidArgument` if the check fails.

### Proof of Concept
1. Create and initialize a nonce account with authority `A` (a normal keypair the user controls).
2. As `A`, submit `system_instruction::authorize_nonce_account(&nonce_pubkey, &A, &Pubkey::default())`. This instruction succeeds, as demonstrated by the existing test `authorize_inx_ok` at [2](#0-1) .
3. Attempt to withdraw lamports from the nonce account or re-authorize it again — both require a signer matching `data.authority == Pubkey::default()`, which is unattainable since no private key exists for the default pubkey. The account and any lamports in it are now permanently inaccessible.

```rust
pub(crate) fn authorize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Authorize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }
    match account
        .get_state::<Versions>()?
        .authorize(signers, *nonce_authority)
    {
        Ok(versions) => account.set_state(&versions),
        Err(AuthorizeNonceError::Uninitialized) => {
            ic_msg!(
                invoke_context,
                "Authorize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
        Err(AuthorizeNonceError::MissingRequiredSignature(account_authority)) => {
            ic_msg!(
                invoke_context,
                "Authorize nonce account: Account {} must sign",
                account_authority
            );
            Err(InstructionError::MissingRequiredSignature)
        }
    }
}
```

```rust
    default_signer: &DefaultSigner,

    let nonce_account = pubkey_of_signer(matches, "nonce_account_pubkey", wallet_manager)?.unwrap();
    let new_authority = pubkey_of_signer(matches, "new_authority", wallet_manager)?.unwrap();
    let memo = matches.value_of(MEMO_ARG.name).map(String::from);
    let (nonce_authority, nonce_authority_pubkey) =
        signer_of(matches, NONCE_AUTHORITY_ARG.name, wallet_manager)?;

    let payer_provided = None;
    let signer_info = default_signer.generate_unique_signers(
        vec![payer_provided, nonce_authority],
        matches,
        wallet_manager,
    )?;
    let compute_unit_price = value_of(matches, COMPUTE_UNIT_PRICE_ARG.name);

    Ok(CliCommandInfo {
        command: CliCommand::AuthorizeNonceAccount {
            nonce_account,
            nonce_authority: signer_info.index_of(nonce_authority_pubkey).unwrap(),
            memo,
            new_authority,
            compute_unit_price,
        },
        signers: signer_info.signers,
    })
}
```
