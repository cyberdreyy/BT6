### Title
`vesting::distribute` and `terminate_vesting_contract` permanently DoS all shareholders of a vesting contract if any single shareholder opts out of direct coin transfers - ([File: aptos-move/framework/aptos-framework/sources/vesting.move])

### Summary
`vesting::distribute` iterates over every shareholder of the vesting contract's `grant_pool` and calls `aptos_account::deposit_coins` for each one in a single atomic transaction, with no error handling. `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has called `set_allow_direct_coin_transfers(false)` on their own account and has not yet registered a `CoinStore<AptosCoin>`. Because Move has no try/catch and the loop makes no isolation between shareholders, any single shareholder can put their account into this state and permanently block `distribute()` (and therefore `terminate_vesting_contract`, which calls `distribute()` internally) for the entire vesting contract, freezing the vested/reward funds of every other shareholder. This is the exact "fail-unsafe batch external call" pattern described in the RootManager.propagate report, reproduced natively in Move without any bridge/AMB involved.

### Finding Description
`distribute()` withdraws all currently-withdrawable stake and pays it out to every shareholder of `vesting_contract.grant_pool` in a single loop: [1](#0-0) 

Each iteration calls `aptos_account::deposit_coins(recipient_address, share_of_coins)` without any guard around whether the recipient can actually receive the funds. `deposit_coins` itself aborts if the account has opted out of unregistered coin transfers: [2](#0-1) 

and any account can freely flip this flag via the fully permissionless, unprivileged entry function: [3](#0-2) 

Because Move transactions are atomic and there is no try/catch equivalent, an abort on any single shareholder's deposit call unwinds the entire `distribute()` transaction, including the coin withdrawal and share redemption for every other shareholder that had already succeeded in that same loop iteration set. `terminate_vesting_contract` calls `distribute()` as its very first step, so it is equally blocked: [4](#0-3) 

There is no code path that removes a poisoned shareholder from `grant_pool` or otherwise bypasses a single failing recipient — `distribute()` must succeed for *all* shareholders or it succeeds for *none*. The framework's own Move Prover annotations acknowledge this exact defect class without fixing it: `// TODO: Can't handle abort in loop.` on `distribute`, and the batch wrappers `vest_many`/`distribute_many` are marked `pragma verify = false` for the same reason: [5](#0-4) 

This is the direct Aptos-native analog of `RootManager.propagate`: a loop over independent "recipients" (there: chain AMBs; here: vesting shareholders) where one participant's failure reverts the entire batch, and there is no fail-safe (try/catch or per-iteration isolation) to prevent it.

### Impact Explanation
Any shareholder in a vesting contract (not necessarily the admin — an ordinary employee/grantee added by the admin) can unilaterally and permanently prevent `distribute()` (and thus `terminate_vesting_contract`/`admin_withdraw`, which depend on it) from ever succeeding again for that contract, by calling `set_allow_direct_coin_transfers(false)` on their own account and never registering a `CoinStore<AptosCoin>`/re-enabling transfers. This traps the vested principal and staking rewards of every other shareholder in the same contract with no recovery path available to the admin or the other shareholders — matching the "Permanent lock or non-recoverable loss of claim rights ... in vesting flows" impact category, since only the attacker's own voluntary action can unblock the contract.

### Likelihood Explanation
High likelihood: `set_allow_direct_coin_transfers` is a standard, fully permissionless entry function available to any account, requires no special privilege or capital, and the griefing shareholder needs only to be one of the (potentially many) grantees an admin already added to the vesting contract. No governance or admin cooperation is required to trigger the DoS.

### Recommendation
`vesting::distribute` (and the analogous `staking_contract::distribute`) should not let a single recipient's failed deposit abort the whole distribution. Wrap each `aptos_account::deposit_coins` call so a non-receivable recipient's share is instead held back (e.g., accumulated into a per-shareholder claimable/escrow balance, or skipped and left in the pool for a later pull-based withdrawal) rather than reverting the entire transaction. Since Move lacks try/catch, this requires either: (1) pre-checking `aptos_account::can_receive_direct_coin_transfers` and `coin::is_account_registered` for each shareholder and diverting funds to a pull-based claim mechanism when the check fails, or (2) switching the whole distribution flow to a pull model where each shareholder calls their own withdrawal function instead of one function pushing funds to all shareholders atomically.

### Proof of Concept
1. Admin creates a vesting contract with shareholders `S1` (attacker) and `S2` via `create_vesting_contract`.
2. `S1` calls `aptos_account::set_allow_direct_coin_transfers(false)` (a normal unprivileged call) and never registers `CoinStore<AptosCoin>`/never calls `coin::register<AptosCoin>`.
3. Time passes, rewards/vesting accrue on the underlying stake pool and become withdrawable.
4. Anyone calls `vesting::distribute(contract_address)` (or `distribute_many`): the loop reaches `S1`, calls `aptos_account::deposit_coins(S1, share_of_coins)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` since `S1` is unregistered and has opted out.
5. The whole transaction reverts — `S2`'s share (and `S1`'s own share) are never paid out. `terminate_vesting_contract`, which begins with a call to `distribute()`, fails identically.
6. As long as `S1` keeps the direct-transfer opt-out and stays unregistered, no shareholder in the contract, including the admin's ability to terminate, can ever succeed — permanently trapping value in the vesting contract.

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
