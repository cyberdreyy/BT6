### Title
Signer accepts a block proposal whose parent is a same-height sibling, not the actual highest known block in the tenure - (File: stackslib/src/net/api/postblock_proposal.rs)

### Summary
`check_block_builds_on_highest_block_in_tenure` only compares `parent_header.anchored_header.height()` against `highest_header.anchored_header.height()`, never checking that `parent_header`'s block ID/hash actually equals `highest_header`'s. If two distinct Nakamoto blocks exist at the same height in the same tenure (an equivocation), a `BlockProposal` naming the non-canonical sibling as `parent_block_id` passes this check.

### Finding Description
The function at [1](#0-0)  first fetches the tenure's highest known header via `NakamotoChainState::find_highest_known_block_header_in_tenure`, then independently looks up the header for the proposal's `parent_block_id` via `NakamotoChainState::get_block_header`. The only comparison performed between these two headers is a height equality check: [2](#0-1) 

There is no comparison of `parent_header.consensus_hash`/block ID against `highest_header`'s block ID. Consequently, if the chainstate has two known headers at the same height within the same tenure (one canonical `highest_header`, one non-canonical sibling `X` produced by an equivocating miner), an attacker can submit a `BlockProposal` whose `parent_block_id` is `X`'s ID instead of the canonical highest header's ID, and this check will pass purely because the heights match. The call site `check_block_has_valid_parent` ( [3](#0-2) ) relies on this height-only guarantee to conclude the parent is legitimate, so a signer running `validate` on this proposal can proceed to sign a block that does not actually extend the canonical tip of the tenure.

### Impact Explanation
This breaks the canonicity/uniqueness safety property: a signer can be induced to sign a Nakamoto block built on a non-canonical, forked sibling parent rather than the true highest block in the tenure. If enough signers are independently fooled the same way (each need only receive the crafted proposal and validate it locally — no coordination needed), this can produce a genuine two-block fork at a single height, i.e., exactly the Critical-severity "signer signing a non-canonical/conflicting block" impact category.

### Likelihood Explanation
This requires a pre-existing equivocation: two distinct Nakamoto blocks already known to chainstate at the same height in the same tenure, which the question specifies as a given precondition (achievable by an attacker winning a single miner slot and gossiping conflicting blocks/proposals). Given that precondition, the exploit needs no privileged role, no majority of signers, and no auth token — a single crafted `BlockProposal` referencing the sibling's block ID as `parent_block_id` is sufficient, and the flaw is deterministic and repeatable each time such a same-height sibling is available.

### Recommendation
In `check_block_builds_on_highest_block_in_tenure`, after fetching both headers, require exact identity, not just height equality — compare `parent_header.index_block_hash(...)` (or equivalent unique block ID) against `highest_header`'s block ID, rejecting the proposal with `InvalidParentBlock`/`NonCanonicalTenure` unless they match exactly.

### Proof of Concept
Rust test plan (in the postblock_proposal/signer validation test module):
1. Set up chainstate with tenure `T`, and directly insert two Nakamoto block headers at height `N` in tenure `T`: `highest_header` (canonical, returned by `find_highest_known_block_header_in_tenure`) and `sibling_header` (equivocated, same height, different block ID).
2. Construct a `NakamotoBlockProposal` whose block's parent points to `sibling_header`'s block ID.
3. Call `check_block_builds_on_highest_block_in_tenure(chainstate, sortdb, &T, &sibling_header.block_id())`.
4. Assert (current behavior, demonstrating the bug): the call returns `Ok(())` even though `sibling_header.block_id() != highest_header.block_id()`.
5. Assert (expected/fixed behavior): the call should return `Err(BlockValidateRejectReason { reason_code: InvalidParentBlock, .. })` because the parent is not the actual highest header, despite matching its height.

    fn check_block_builds_on_highest_block_in_tenure(
        chainstate: &StacksChainState,
        sortdb: &SortitionDB,
        tenure_id: &ConsensusHash,
        parent_block_id: &StacksBlockId,
    ) -> Result<(), BlockValidateRejectReason> {
        let Some(highest_header) = NakamotoChainState::find_highest_known_block_header_in_tenure(
            chainstate, sortdb, tenure_id,
        )
        .map_err(|e| BlockValidateRejectReason {
            reason_code: ValidateRejectCode::ChainstateError,
            reason: format!("Failed to query highest block in tenure ID: {:?}", &e),
            failed_txid: None,
        })?
        else {
            warn!(
                "Rejected block proposal";
                "reason" => "Block is not a tenure-start block, and has an unrecognized tenure consensus hash",
                "consensus_hash" => %tenure_id,
            );
            return Err(BlockValidateRejectReason {
                reason_code: ValidateRejectCode::NoSuchTenure,
                reason: "Block is not a tenure-start block, and has an unrecognized tenure consensus hash".into(),
                failed_txid: None,
            });
        };
        let Some(parent_header) =
            NakamotoChainState::get_block_header(chainstate.db(), parent_block_id).map_err(
                |e| BlockValidateRejectReason {
                    reason_code: ValidateRejectCode::ChainstateError,
                    reason: format!("Failed to query block header by block ID: {:?}", &e),
                    failed_txid: None,
                },
            )?
        else {
            warn!(
                "Rejected block proposal";
                "reason" => "Block has no parent",
                "parent_block_id" => %parent_block_id
            );
            return Err(BlockValidateRejectReason {
                reason_code: ValidateRejectCode::UnknownParent,
                reason: "Block has no parent".into(),
                failed_txid: None,
            });
        };
        if parent_header.anchored_header.height() != highest_header.anchored_header.height() {
            warn!(
                "Rejected block proposal";
                "reason" => "Block's parent is not the highest block in this tenure",
                "consensus_hash" => %tenure_id,
                "parent_header.height" => parent_header.anchored_header.height(),
                "highest_header.height" => highest_header.anchored_header.height(),
            );
            return Err(BlockValidateRejectReason {
                reason_code: ValidateRejectCode::InvalidParentBlock,
                reason: "Block is not higher than the highest block in its tenure".into(),
                failed_txid: None,
            });
        }
        Ok(())
    }
