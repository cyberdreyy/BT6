No vulnerability found for this question.

**Analysis:**

The premise of the question is invalid on two independent grounds.

**1. `predecessor_id` is not attacker-forgeable.** A `Receipt`'s `predecessor_id` is not an arbitrary field an "attacker" can set. It is derived either from the verified signer of a `SignedTransaction` (checked via signature/nonce/access-key in `verify_and_charge_tx_ephemeral`) or from the executing contract account itself when it creates a promise. An unprivileged attacker who does not control `victim.near`'s private key and does not control code already deployed on `victim.near` has no path to produce a receipt where `predecessor_id == victim.near`. The scenario in the question ("craft a receipt whose predecessor_id is victim.near") is not reachable by an ordinary client under the stated threat model. [1](#0-0) 

**2. The `actor_id` promotion in `action_create_account` is by design, not a permission escalation.** `action_create_account` only promotes `*actor_id = account_id.clone()` after successfully validating that `account_id` is a legitimate sub-account of `predecessor_id` (or a valid top-level account created by the registrar) — the `CreateAccountNotAllowed`/`CreateAccountOnlyByRegistrar` checks guard this exactly. [2](#0-1) 

This mirrors documented protocol semantics: "if the first action in the action list is `CreateAccount`, `predecessor_id` becomes `receiver_id` for the rest of the actions... This gives permission by another account to act on the newly created account." [3](#0-2) 

Since `CreateAccount` only succeeds when `account_id` is validly under the *true* `predecessor_id`'s namespace, the entity that is authorized to create `account_id` (i.e., the real predecessor) is exactly the entity granted `actor_id == account_id` for subsequent actions in that same receipt via `check_actor_permissions`. This does not let an actor exceed the true predecessor's authority — it only lets the legitimate creator (verified namespace owner) act on the account it just created, which is the intended NEP behavior enabling account-factory patterns. [4](#0-3) 

Existing tests (`test_create_account_with_transfer_and_full_key`, `test_account_factory`) exercise exactly this pattern of `CreateAccount` followed by `AddKey`/`Transfer` in the same receipt and confirm it is expected, safe behavior, not a bypass of authorization. [5](#0-4) 

No code path allows an attacker to inject a forged `predecessor_id`, and the actor promotion never exceeds the verified predecessor's namespace authority. There is no reachable exploit for an unprivileged attacker.

pub(crate) fn action_create_account(
    fee_config: &RuntimeFeesConfig,
    account_creation_config: &AccountCreationConfig,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    account_id: &AccountId,
    predecessor_id: &AccountId,
    result: &mut ActionResult,
) {
    if account_id.is_top_level() {
        if account_id.len() < account_creation_config.min_allowed_top_level_account_length as usize
            && predecessor_id != &account_creation_config.registrar_account_id
        {
            // A short top-level account ID can only be created registrar account.
            result.result = Err(ActionErrorKind::CreateAccountOnlyByRegistrar {
                account_id: account_id.clone(),
                registrar_account_id: account_creation_config.registrar_account_id.clone(),
                predecessor_id: predecessor_id.clone(),
            }
            .into());
            return;
        } else {
            // OK: Valid top-level Account ID
        }
    } else if !account_id.is_sub_account_of(predecessor_id) {
        // The sub-account can only be created by its root account. E.g. `alice.near` only by `near`
        result.result = Err(ActionErrorKind::CreateAccountNotAllowed {
            account_id: account_id.clone(),
            predecessor_id: predecessor_id.clone(),
        }
        .into());
        return;
    } else {
        // OK: Valid sub-account ID by proper predecessor.
    }

    *actor_id = account_id.clone();
    *account = Some(Account::new(
        Balance::ZERO,
        Balance::ZERO,
        AccountContract::None,
        fee_config.storage_usage_config.num_bytes_account,
    ));

pub(crate) fn check_actor_permissions(
    action: &Action,
    account: &Option<Account>,
    actor_id: &AccountId,
    account_id: &AccountId,
) -> Result<(), ActionError> {
    match action {
        Action::DeployContract(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::WithdrawFromGasKey(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
        }
        Action::DeleteAccount(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
            let account = account.as_ref().unwrap();
            if !account.locked().is_zero() {
                return Err(ActionErrorKind::DeleteAccountStaking {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
        Action::CreateAccount(_)
        | Action::FunctionCall(_)
        | Action::Transfer(_)
        | Action::TransferToGasKey(_) => (),
        Action::Delegate(_) | Action::DelegateV2(_) => (),
        Action::DeterministicStateInit(_) => (),
    };
    Ok(())
}
