### Title
Zip extraction writes to absolute/OS paths without confinement check - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipFileEntry`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`) use `file.Name` verbatim in `os.MkdirAll`, `os.OpenFile`, `os.Mkdir`, and `os.Symlink` with no validation that the name is relative or confined to any target directory. The only path-related check present, `errorIfGitDirectory`, only rejects entries starting with `.git`; it does nothing to reject absolute paths or `..` traversal.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for every entry [1](#0-0) . `extractZipFile` immediately does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to file/dir/symlink handlers that call `os.OpenFile`, `os.Mkdir`, or `os.Symlink` directly on `file.Name` [2](#0-1) . None of these functions join `file.Name` against a target/output directory, nor do they call `filepath.IsAbs` or otherwise reject absolute names. The single guard applied per-entry, `errorIfGitDirectory`, only matches a `.git` prefix after `filepath.Clean` and is unrelated to path confinement [3](#0-2) .

Critically, the `ziplegacy` extractor wraps `zip.NewReader` and calls `archives.ExtractZipArchive(zr)` directly, ignoring its own `dir` field entirely — `e.dir` is stored on the struct but never used to change directory, chroot, or prefix paths before extraction [4](#0-3) . This confirms there is no confinement layer above `ExtractZipArchive` that would reject or rebase an absolute `file.Name` before it reaches `os.MkdirAll`/`os.OpenFile`.

Since `zip.File.Name` is taken directly from the archive's central directory metadata, an attacker who supplies a job artifact/cache archive (fully attacker-controlled bytes, e.g., via artifact upload/download or cache restore paths that route through zip extraction) can craft an entry named `/etc/cron.d/evil` or, on Windows, `C:\Windows\...`. Because no check rejects `filepath.IsAbs(file.Name)`, `filepath.Dir("/etc/cron.d/evil")` returns `/etc/cron.d` and `os.MkdirAll` will silently succeed (directory already exists with correct permissions in the typical case), after which `os.OpenFile` writes the file content directly to `/etc/cron.d/evil` on the host running the extraction process — outside of any job workspace/root.

### Impact Explanation
A single crafted zip entry with an absolute path name allows writing an arbitrary file to an arbitrary path on the filesystem of the process performing extraction (runner helper binary), with the permissions of that process. This breaks the workspace-confinement invariant directly and without requiring `../` traversal sequences, and could lead to file overwrite/creation outside the build/cache/artifact root depending on the privileges of the runner process and executor (e.g., shell executor running as the gitlab-runner user with write access to sensitive paths, or a helper image with elevated mounts in Docker/Kubernetes executors).

### Likelihood Explanation
Feasibility is high with respect to reachability: any attacker who can supply a zip payload processed by `ExtractZipArchive`/`ExtractZipFile` (cache archive restore, artifact download+extract, or any custom zip consumption path such as `ziplegacy`) can trivially construct such an archive using the standard `archive/zip` package (Go's writer does not prevent writing absolute names into the header). The actual host-level impact depends on the OS-level permissions of the extracting process for the specific absolute path chosen (e.g. writing to `/etc/cron.d` typically requires root, but arbitrary absolute paths writable by the runner's own user, e.g. `~/.ssh/authorized_keys` expressed as an absolute path, are plausible targets), so exploitability for actually damaging targets depends on the deployment's privilege model, while the missing input-validation bug itself is unconditionally present and reproducible.

### Recommendation
Add an explicit path-safety check at the top of `extractZipFile` (and mirrored in the tar extraction path if similarly unguarded) that rejects entries where `filepath.IsAbs(file.Name)` is true, and additionally validate that `filepath.Clean(filepath.Join(baseDir, file.Name))` remains within `baseDir` (guarding against `..` traversal as a related but distinct issue) before any `MkdirAll`/`OpenFile`/`Symlink` call. Reject or skip such entries with a clear error/log rather than silently succeeding, similar to the existing `errorIfGitDirectory` pattern.

### Proof of Concept
```go
func TestExtractZipArchive_RejectsAbsolutePath(t *testing.T) {
    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    // Craft an entry with an absolute path name
    absName := "/tmp/gitlab-runner-poc-absolute-write"
    _ = os.Remove(absName) // ensure clean state
    w, err := zw.Create(absName)
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = archives.ExtractZipArchive(zr)

    // Expected (secure) behavior: extraction should error or skip the entry
    _, statErr := os.Stat(absName)
    assert.True(t, os.IsNotExist(statErr),
        "absolute-path zip entry must not be written outside any workspace root")
    _ = err
}
```
Currently, running this against `ExtractZipArchive` results in the file being created at `/tmp/gitlab-runner-poc-absolute-write` (assertion fails), confirming no rejection of OS-absolute `zip.File.Name` values.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
