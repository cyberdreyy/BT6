### Title
Global state-machine agreement threshold rounds down while block-approval threshold rounds up, letting a signer accept a burn-view/miner/tx-replay-set consensus that a supermajority-consistent node would reject - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority threshold with integer floor division, while `NakamotoBlockHeader::compute_voting_weight_threshold` (used for the actual block-signature/approval threshold) computes the same 70% with a ceiling. For the same `total_weight`, these two "70%" thresholds can differ by 1 weight unit, so a signer can conclude a global-state item (burn view, current miner, active protocol version, tx replay set) has reached supermajority agreement using a weight total that the node's consensus-critical threshold would still consider insufficient.

### Finding Description
`reached_agreement` in [1](#0-0)  is:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```

This computes `floor(total_weight * 7 / 10)` and checks `vote_weight >= floor`.

The consensus-critical block-approval threshold, by contrast, is computed with a ceiling in `compute_voting_weight_threshold`: [2](#0-1) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```

For any `total_weight` where `total_weight * 7` is not a multiple of 10 (e.g. `total_weight = 11`: `7*11=77`, `floor=7`, `ceil=8`), the two "70%" thresholds diverge by exactly 1 weight unit. `reached_agreement` will report agreement is reached once `vote_weight == 7`, while the node-side (and the signer's own block-acceptance path, which explicitly calls `compute_voting_weight_threshold` — see [3](#0-2)  and [4](#0-3) ) requires `vote_weight >= 8` for the equivalent 70% supermajority.

`reached_agreement` is the sole supermajority predicate used by `GlobalStateEvaluator::determine_global_state`, `determine_latest_supported_signer_protocol_version`, and `determine_global_burn_view`: [5](#0-4)  and [6](#0-5) . This evaluator is populated purely from gossiped `StateMachineUpdate` StackerDB chunks written by other signers (see `StackerDBListener::new`, which builds a `GlobalStateEvaluator` directly from chunk contents: [7](#0-6) ), so any one signer/miner reading the same gossiped set of updates reaches the identical (off-by-one) conclusion — this is not something requiring a majority to trigger; it is a deterministic rounding bug that fires whenever `total_weight * 7 mod 10 != 0`, which is the common case for real-world weight distributions.

Root cause is purely a floor-vs-ceiling mismatch between two independently reimplemented "70%" computations that are supposed to encode the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` semantics.

### Impact Explanation
This breaks the equality between "signer's locally-evaluated global-state agreement" and "chain's/other-signers' verified consensus threshold." A signer can:
- decide `active_signer_protocol_version`, `current_miner`, `burn_block`/`burn_block_height`, or `tx_replay_set` has reached global agreement at a weight level that is one unit below the supermajority the rest of the protocol (and the node's `verify_signer_signatures`/`compute_voting_weight_threshold`) requires,
- act on that state (e.g., switch to a "new" current miner view, or adopt a burn view / tx replay set) prematurely, based on a boundary weight that does not actually constitute a true 70% supermajority under the canonical (ceiling-based) definition.

This falls in the "signer wedged/acting on stale or incorrectly-thresholded consensus state" class (High impact per the rules): a signer can act on a global-state decision (miner view, burn view, protocol version, tx replay set) that is not actually backed by the canonical 70% threshold, which can desynchronize its local state machine from the rest of the network and from the node's own threshold checks, undermining the integrity of the state-machine-update/gossip layer that gates which miner/blocks the signer will consider valid.

### Likelihood Explanation
Likelihood is high for triggering the divergence itself: it occurs deterministically whenever `total_weight * 7` is not a multiple of 10, which happens for the overwhelming majority of possible `total_weight` values (9 out of 10 residues). No majority collusion, secret key, or malicious StackerDB write is needed — it is purely an arithmetic inconsistency between two threshold formulas that is hit under totally ordinary operating conditions of a live reward cycle whenever weights fall on a non-exact-multiple-of-10/7 total.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the same rounding convention (ceiling) as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by having one call the other (or by extracting a single shared `compute_voting_weight_threshold`-style helper) so that "70% supermajority" and "30% blocking minority" always mean the identical weight cutoff everywhere in the codebase, eliminating any possibility of divergent floor/ceiling semantics between the gossip-driven global-state evaluator and the block-approval consensus path.

### Proof of Concept
Using the existing regression harness pattern in `libsigner/src/tests/signer_state.rs` (which already fixes `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD == 7`, see [8](#0-7) ):

1. Set `total_weight = 11`.
2. `NakamotoBlockHeader::compute_voting_weight_threshold(11)` → `(11*7)/10 + ceil = 7 + 1 = 8` (per [9](#0-8)  style tests such as [10](#0-9)  which confirms round-up behavior, e.g. `compute_voting_weight_threshold(511) == 358` not `357`).
3. `evaluator_with_total_weight(11).reached_agreement(7)` → `7 >= floor(11*7/10) = floor(7.7) = 7` → `true`.
4. Thus with exactly 7 units of weight reporting the same `StateMachineUpdate` content, `GlobalStateEvaluator` (used purely from gossiped StackerDB chunks) declares global agreement reached, while the canonical block-approval threshold formula used elsewhere in the same codebase requires 8 units for the equivalent 70% supermajority — a concrete, deterministic threshold mismatch exploitable by ordinary gossip traffic with no majority or privileged access required.

    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
