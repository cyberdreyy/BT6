### Title
Legacy gateway handler forwards HTTP triggers to the whole DON without allowlist/sender enforcement — `// TODO: apply allowlist and rate-limiting here` - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
This is analogous to the reported "commented check that can influence a process of claiming" pattern: the gateway's legacy user-message path for the web-api-trigger capability has an explicit `TODO` marker where an allowlist/sender/rate-limit check should exist but does not, meaning any unprivileged client that can reach the gateway's public HTTP endpoint can have its request forwarded to the entire DON without a gateway-side ownership or sender check.

### Finding Description
`handler.HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` validates payload structure, timestamp freshness, and method name, but immediately before forwarding the request to every DON member it contains only a comment marking missing security controls: [1](#0-0) 

The comment `// TODO: apply allowlist and rate-limiting here` sits directly above the method check and the loop that broadcasts the validated request to `h.donConfig.Members`, with no call to any allowlist/sender-authorization function analogous to the commented "require" in the reported bug — the enforcement point exists in the code path (right where the TODO is) but is not implemented/wired in, so the gateway performs no allowlist or per-sender authorization before fanning the message out to the DON.

Downstream, node-side sender authorization does exist in `webapiTrigger.processTrigger` (`core/capabilities/webapi/trigger/trigger.go`), which checks `trigger.allowedSenders[sender.String()]` before dispatching the event: [2](#0-1) 

However, this only protects the workflow-level dispatch to `trigger.ch`. Every DON node still receives and processes the raw forwarded message (with its `savedCallbacks` bookkeeping, rate limiting only at the node-to-gateway leg via `nodeRateLimiter` for outgoing messages, not for incoming legacy trigger fan-out), and the accompanying test file confirms the gap is known and untested: [3](#0-2) 

### Impact Explanation
Because the gateway itself performs no allowlist/rate-limiting check before broadcasting an unauthenticated-at-the-gateway-layer request to all DON members, an unprivileged external client can flood every node in the DON with `web_api_trigger` messages, consuming `savedCallbacks` capacity, CPU, and node bandwidth, independent of whether any individual node's `allowedSenders` list would eventually reject the sender at the workflow layer. This is a gateway-level allowlist/quota bypass reachable directly from an unprivileged client HTTP request, matching the requested class of "concrete... allowlist or quota bypass."

### Likelihood Explanation
High: `HandleLegacyUserMessage` is invoked directly by external client messages received by the gateway's public HTTP interface; the missing check is unconditional (not gated behind any config flag) and is reachable by any caller who can reach the gateway.

### Recommendation
Implement the allowlist/rate-limiting check referenced by the `TODO` in `core/services/gateway/handlers/capabilities/handler.go` before the DON fan-out loop — validating the message sender/topic against the gateway's own allowlist and applying per-sender rate limiting at the gateway layer, rather than relying solely on the node-side `allowedSenders` check in `core/capabilities/webapi/trigger/trigger.go`.

### Proof of Concept
1. Send a well-formed `web_api_trigger` message (valid payload, timestamp, and signature) to the gateway's legacy HTTP endpoint using an arbitrary/unregistered sender key.
2. Observe in `HandleLegacyUserMessage` that the request passes payload/timestamp/method validation and is forwarded via `don.SendToNode` to every member in `h.donConfig.Members` — no allowlist or gateway-level rate-limit check rejects it, confirmed by the code path at [1](#0-0)  and the still-open test gap noted at [3](#0-2) .
3. Repeat at volume to demonstrate the gateway does not throttle or reject unauthorized senders before broadcasting to the full DON.
