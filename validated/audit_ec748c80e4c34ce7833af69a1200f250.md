### Title
Missing allowlist/subscription authorization check in `HandleLegacyUserMessage` allows unauthorized broadcast of `web_api_trigger` requests to all DON nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`(h *handler).HandleLegacyUserMessage` decodes the payload, checks timestamp and method, calls `common.ValidatedRequestFromMessage`, and then broadcasts the request to every DON member via `don.SendToNode` — with no allowlist, subscription, or per-user quota check anywhere in the path. The code contains an explicit `// TODO: apply allowlist and rate-limiting here` marker directly above the method check, confirming the control is not implemented.

### Finding Description
The relevant flow in `HandleLegacyUserMessage` [1](#0-0)  is:
1. Decode `webapicap.TriggerRequestPayload` from `body.Payload`.
2. Reject empty/zero `Timestamp` and stale messages based on `h.config.MaxAllowedMessageAgeSec`.
3. `// TODO: apply allowlist and rate-limiting here` immediately precedes the method check [2](#0-1) .
4. Validate the method equals `MethodWebAPITrigger`.
5. Convert message to a JSON-RPC request via `common.ValidatedRequestFromMessage` (this only validates message/signature structure, not sender authorization).
6. Save a callback keyed by `msg.Body.MessageId`.
7. Loop over `h.donConfig.Members` and call `don.SendToNode(ctx, member.Address, req)` for every member, unconditionally [3](#0-2) .

At no point is `msg.Body.Sender` checked against any allowlist, subscription store, or per-user quota structure. A `grep` across `core/services/gateway/handlers/**` confirms there is no allowlist implementation invoked from this handler (the only "allowlist" hits in that directory are in an unrelated `vault` test file). The `Handler` interface docstring in `core/services/gateway/handlers/handler.go` also does not mandate authorization in `HandleLegacyUserMessage`; the DON interface `SendToNode` is a pure network send with no authorization gate. `common.ValidatedRequestFromMessage` only performs structural/signature validation to produce a routable JSON-RPC request, not authorization against a subscriber registry. This confirms that any address that can produce a validly-signed `api.Message` with `Method == "web_api_trigger"` and a non-stale timestamp will have its request forwarded to every configured DON node, regardless of whether that address holds a Functions/Capabilities subscription or is on any allowlist.

However, it's important to note this `capabilities` package handler is the generic Web API Trigger/Target/Compute/WorkflowSyncer capabilities gateway handler, not the dedicated Chainlink Functions gateway handler (which historically lives under a Functions-specific handler package with its own `Allowlist`/`Subscription` checks against on-chain subscription data). I could not locate any code in this repository that ties `HandleLegacyUserMessage` in this file to Functions subscription billing/balance accounting — the payload type here is `webapicap.TriggerRequestPayload` used generically for Workflow/Capabilities web API triggers, not a Functions-specific request with subscription IDs. There is no evidence in the codebase that this specific handler path is billed against Functions subscriber balances.

### Impact Explanation
Within the scope of this handler, an unprivileged sender who can produce a validly-signed gateway message triggers a broadcast of their request to all DON nodes with no authorization check, which is a legitimate authorization/allowlist bypass matching a "unauthorized job/DON request execution" impact class for the generic Capabilities Web API Trigger handler. However, the specific claim in the question — that this causes charges against *another Functions subscriber's* balance/subscription — is not substantiated in this file or its surrounding call graph; no subscription/balance accounting logic is present in this handler or reachable from it.

### Likelihood Explanation
Any address able to compute a valid signature over an `api.Message` (this is attacker-controlled, since it is any EOA signing its own request, not impersonation of another party) and set `Method = "web_api_trigger"` can reach this path once it passes the gateway's own message ingestion/signature verification layer (outside this file). Preconditions per the prompt (no allowlist/subscription entry for sender) are trivially satisfiable by any unprivileged party.

### Recommendation
Implement the allowlist/subscription/quota check called out by the `// TODO: apply allowlist and rate-limiting here` comment before invoking `don.SendToNode`: validate `msg.Body.Sender` against the DON's configured allowlist/subscription registry and apply per-user rate limiting, rejecting unauthorized senders with an appropriate JSON-RPC error response before any broadcast occurs.

### Proof of Concept
Go handler-level test plan:
1. Construct `handler` via `NewHandler` with a `donConfig.Members` list of N mock members and a stub `handlers.DON` whose `SendToNode` records every call.
2. Build a valid `api.Message` with `Body.Method = MethodWebAPITrigger`, a well-formed `webapicap.TriggerRequestPayload` with a fresh `Timestamp`, and a valid signature from an arbitrary EOA not present in any allowlist/subscription data structure (none exists in this package to seed).
3. Call `h.HandleLegacyUserMessage(ctx, msg, callback)`.
4. Assert `SendToNode` was invoked exactly `len(donConfig.Members)` times despite the sender having no prior authorization record — demonstrating the missing check named by the TODO comment.

Note: because no Functions-specific subscription/balance model is present in this file, this PoC only demonstrates unauthorized broadcast/authorization bypass at the generic Capabilities gateway handler level, not direct fund/subscription-balance drain of another Functions subscriber — the latter claim in the question could not be verified against this codebase given available context.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
