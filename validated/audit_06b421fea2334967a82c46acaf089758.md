### Title
Unauthenticated LDAP bind with empty password treated as successful login - ([File: core/sessions/ldapauth/ldap.go])

### Summary
`ldapAuthenticator.CreateSession`, invoked from `POST /sessions` for LDAP-backed nodes, forwards the client-supplied password directly into `conn.Bind()` with no check that the password is non-empty. Per LDAP protocol semantics (RFC 4513 §5.1.2), a simple bind with a valid DN and an empty password is an "unauthenticated bind," which many directory servers accept without error; the code treats `err == nil` from `Bind` as proof the credentials matched, letting an attacker log in as any known email with no password.

### Finding Description
`CreateSession` obtains a connection via `l.ldapClient.CreateEphemeralConnection()` (backed by `newLDAPClient`/`ldapClient.CreateEphemeralConnection` in `core/sessions/ldapauth/client.go`), then does: [1](#0-0) 
```
escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
    ...
    returnErr = errors.New(...)
}
```
There is no check that `sr.Password` (attacker-controlled, from the `POST /sessions` JSON body) is non-empty or non-whitespace before it is passed to `conn.Bind`. If the directory server permits unauthenticated binds (the RFC 4513 default behavior for many LDAP implementations when a valid DN and zero-length password are supplied), `conn.Bind` returns `nil`, and the code proceeds to `FindUser`, assigns the matched user's real role, and issues a valid session (`INSERT INTO ldap_sessions ...`) plus an `AuthLoginSuccessNo2FA` audit event — all without verifying any actual secret. [2](#0-1) 

The same unchecked pattern also exists in `TestPassword`: [3](#0-2) 

`client.go`'s `newLDAPClient`/`CreateEphemeralConnection` itself only performs the fixed, config-supplied read-only root bind and is not where the user-supplied password reaches `Bind`; the exploitable check-omission is in `ldap.go`'s `CreateSession`/`TestPassword`, which consume the connection produced by `newLDAPClient`. [4](#0-3) 

### Impact Explanation
An unauthenticated attacker who knows (or can guess/enumerate) a valid user email can obtain a fully valid `ldap_sessions` entry with that user's real role (including Admin, if the target account is an LDAP admin-group member), by submitting an empty password to `POST /sessions`. This is a full authentication bypass leading to node takeover matching the "Critical - node takeover" impact class, contingent on the directory server's handling of unauthenticated binds.

### Likelihood Explanation
Exploitability depends entirely on whether the configured upstream LDAP/AD server permits unauthenticated (empty-password) simple binds — a common but not universal server-side default/config. The application code itself performs no defense-in-depth check to reject empty passwords before delegating to the directory, so on any deployment where the LDAP server allows unauthenticated binds (still common, e.g. many OpenLDAP defaults unless `disallow bind_anon` is set), this is trivially and repeatably exploitable with a single unauthenticated HTTP request containing a known email and empty password.

### Recommendation
In `CreateSession` and `TestPassword` (`core/sessions/ldapauth/ldap.go`), reject requests with an empty or whitespace-only password before calling `conn.Bind`, e.g.:
```go
if strings.TrimSpace(sr.Password) == "" {
    return "", errors.New("unable to log in with LDAP server. Check credentials")
}
```
This enforces the invariant regardless of the upstream directory's bind policy.

### Proof of Concept
Table-driven unit test plan for `ldapAuthenticator.CreateSession` (using the existing `mocks.LDAPClient`/`LDAPConn` mocks referenced in `core/sessions/ldapauth/ldap_test.go`):
1. Configure the mock `LDAPConn.Bind` to return `nil` (simulating a directory that accepts unauthenticated bind) whenever called with a non-empty DN and an empty-string password.
2. Call `CreateSession(ctx, sessions.SessionRequest{Email: "known@user.com", Password: ""})` and assert that it currently returns a valid session ID — demonstrating the bypass.
3. Repeat with `Password: "   "` (whitespace).
4. After applying the fix, assert both cases return an error and `conn.Bind` is never invoked (use a mock expectation asserting `Bind` was not called for empty/whitespace passwords).

func newLDAPClient(config config.LDAP) LDAPClient {
	return &ldapClient{config}
}

// CreateEphemeralConnection returns a valid, active LDAP connection for upstream Search and Bind queries
func (l *ldapClient) CreateEphemeralConnection() (LDAPConn, error) {
	conn, err := ldap.DialURL(l.config.ServerAddress())
	if err != nil {
		return nil, fmt.Errorf("failed to Dial LDAP Server: %w", err)
	}
	// Root level root user auth with credentials provided from config
	bindStr := l.config.BaseUserAttr() + "=" + l.config.ReadOnlyUserLogin() + "," + l.config.BaseDN()
	if err := conn.Bind(bindStr, l.config.ReadOnlyUserPass()); err != nil {
		return nil, fmt.Errorf("unable to login as initial root LDAP user: %w", err)
	}
	return conn, nil
}
