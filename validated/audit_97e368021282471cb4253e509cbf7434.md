### Title
`store_and_process_block_signature` broadcasts the block to the node even when the local `mark_locally_accepted` state transition fails - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`store_and_process_block_signature` checks the `Result` returned by `block_info.mark_locally_accepted(true)` but discards the error unconditionally instead of aborting on failure, then proceeds to persist and broadcast the block regardless of whether the local consensus record actually reflects "accepted."

### Finding Description
Once accumulated signature weight reaches the 70% threshold, the signer calls:

```
if let Err(e) = block_info.mark_locally_accepted(true) {
    if !block_info.has_reached_consensus() {
        warn!("{self}: Failed to mark block as locally accepted: {e:?}");
    }
}
let _ = self.signer_db.insert_block(block_info).map_err(|e| {...});
self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
``` [1](#0-0) 

`mark_locally_accepted` returns `Result<(), String>` from the `BlockInfo::move_to` state machine, which enforces that `LocallyAccepted` is unreachable from a terminal `GloballyRejected`/`GloballyAccepted` state: [2](#0-1) 

The `Err(e)` branch only *logs a warning* (and only if `has_reached_consensus()` is false); it never `return`s. Execution falls through unconditionally to `self.signer_db.insert_block(...)` and `self.broadcast_signed_block(...)` — this is structurally identical to `timeLockERC20` calling `transferFrom` and continuing regardless of the return value: a state-mutation's success/failure signal is observed but not used to gate the subsequent externally-visible action (here, pushing a fully-signed block to the stacks-node via `handle_post_block` → `stacks_client.post_block`). [3](#0-2) [4](#0-3) 

The guard `if block_info.signed_group.is_some() { return; }` earlier in the function is meant to prevent re-processing a block that has already reached a decision, but `signed_group` is only set by `mark_locally_accepted`/`mark_globally_accepted` — a block that reached `GloballyRejected` via `mark_globally_rejected` (the >30% rejection path) never sets `signed_group`, so that early-return guard does not fire for a block that is already locally known to be rejected: [5](#0-4) [6](#0-5) 

Consequently, if this signer's local `BlockInfo` for a given `signer_signature_hash` is already `GloballyRejected` (recorded via `mark_globally_rejected` after `handle_block_rejection` observed >30% rejecting weight) and a subsequent (possibly delayed/out-of-order/gossip-replayed) `BlockResponse::Accepted` message pushes the locally tracked acceptance weight over the 70% threshold, `mark_locally_accepted` will return `Err` (invalid transition `GloballyRejected -> LocallyAccepted`), the warning is suppressed because `has_reached_consensus()` is true, and the code still calls `broadcast_signed_block`, submitting the block (with whatever signature set was gathered) to the node for adoption — despite this signer's own bookkeeping saying the block was globally rejected.

### Impact Explanation
This breaks the equality between "the signer's recorded consensus decision" and "the action the signer actually takes": a block the signer has already recorded as globally rejected can still be pushed to the node's `/v3/blocks` endpoint for adoption, i.e., a rejection is not honored and an accept-path action (broadcast) proceeds anyway. If the node accepts the pushed block (it independently checks signature validity/weight, not the signer's local decision history), this manifests as a rejection being effectively overridden/recounted as an accepted broadcast from this signer's perspective — matching the Critical impact class ("a rejection recounted as an accept").

### Likelihood Explanation
Reaching this exact race requires the local peer-message tallies for accept and reject weight to both cross their respective thresholds for the *same* `block_info` before the second one is observed and short-circuited by the `signed_group.is_some()` guard — which, as shown, does **not** trigger for the `GloballyRejected` path. This is plausible under normal gossip/timing conditions (out-of-order or replayed `BlockResponse` messages, or signers flipping votes across re-evaluation per the documented `LocallyAccepted <-> LocallyRejected` transitions) and requires no majority-key compromise, only ordinary message delivery a single miner/gossip participant can influence by timing/replaying `BlockResponse` traffic. However, full confirmation that the accept/reject weight sums can concurrently satisfy both thresholds (i.e., that the underlying `add_block_signature`/rejection-weight bookkeeping permits double-counted or overlapping weight across a vote flip) requires tracing `handle_block_response`/`handle_block_rejection`/`store_and_process_block_rejection` in full, which was not fully retrievable within the available search budget — this is noted as an area of residual uncertainty.

### Recommendation
Make the `mark_locally_accepted` result authoritative: on `Err`, `return` immediately rather than only logging (unless the failure is due to an idempotent already-`LocallyAccepted`/`GloballyAccepted` re-entry), so that a block already resolved to `GloballyRejected` can never fall through into `insert_block` + `broadcast_signed_block`. Additionally, gate the early-return check in `store_and_process_block_signature` on the block's terminal state (`state == GloballyRejected || state == GloballyAccepted`) rather than solely on `signed_group.is_some()`.

### Proof of Concept
Conceptual reproduction path (single miner + gossip-controlled message ordering, no majority key needed):
1. Signer S receives enough `BlockResponse::Rejected` weight (>30%) for block `B` first, driving its local `BlockInfo` for `B` to `GloballyRejected` via `handle_block_rejection` → `mark_globally_rejected`.
2. A delayed/replayed `BlockResponse::Accepted` message (attacker-controllable timing via StackerDB gossip ordering) subsequently arrives for the same `B`, and the cumulative locally-tracked accept weight (from `get_block_signatures`) crosses the 70% threshold in `store_and_process_block_signature`.
3. The `signed_group.is_some()` early-return does not trigger (never set on the reject path), so the function proceeds, calls `mark_locally_accepted(true)`, which returns `Err` since `GloballyRejected -> LocallyAccepted` is an invalid transition per `check_state`.
4. The error is logged only if `!has_reached_consensus()`, which is false here, so no warning is even emitted, and execution falls through to `insert_block` and `broadcast_signed_block`, causing this signer to push a supposedly-globally-rejected block to its node.

    /// Attempt to post a block to the stacks-node and handle the result
    pub fn handle_post_block(&mut self, stacks_client: &StacksClient, block: &NakamotoBlock) {
        #[cfg(any(test, feature = "testing"))]
        if self.test_skip_block_broadcast(block) {
            return;
        }
        let block_hash = block.header.signer_signature_hash();
        match stacks_client.post_block(block) {
            Ok(accepted) => {
                debug!("{self}: Block {block_hash} accepted by stacks node: {accepted}");
                if let Err(e) = self
                    .signer_db
                    .set_block_broadcasted(&block_hash, get_epoch_time_secs())
                {
                    warn!("{self}: Failed to set block broadcasted for {block_hash}: {e:?}");
                }
            }
            Err(e) => {
                warn!("{self}: Failed to broadcast block {block_hash} to the node: {e}")
            }
        }
    }

    /// Mark this block as valid and the appropriate timestamps if they aren't already set, and attempt to mark it as locally accepted.
    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Mark this block's signed group time if not already set and attempt to mark it as globally accepted.
    pub fn mark_globally_accepted(&mut self) -> Result<(), String> {
        self.signed_group.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::GloballyAccepted)
    }

    /// Mark this block as invalid and attempt to mark it as locally rejected
    pub fn mark_locally_rejected(&mut self) -> Result<(), String> {
        self.valid = Some(false);
        self.move_to(BlockState::LocallyRejected)
    }

    /// Attempt to mark the block as globally rejected
    pub fn mark_globally_rejected(&mut self) -> Result<(), String> {
        self.move_to(BlockState::GloballyRejected)
    }

    /// Return the block's signer signature hash
    pub fn signer_signature_hash(&self) -> Sha512Trunc256Sum {
        self.block.header.signer_signature_hash()
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
