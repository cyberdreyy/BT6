## Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing requests to execute below the required number of live confirmations - (File: `multisig2/src/lib.rs`, also present in `multisig/src/lib.rs`)

### Summary
The bug reported for the LAO (votes surviving ragequit/ragekick) maps to a concrete equivalent in this repo's multisig contracts: a member's `confirm()` call is recorded as a string in a `confirmations: LookupMap<RequestId, HashSet<String>>` set per request [1](#0-0) . When a member is removed via `DeleteMember`, `delete_member()` only purges requests that member itself *created*, filtering on `r.member == member` [2](#0-1) . It never scrubs that member's entries from the `confirmations` set of requests *created by other members* that they had already confirmed. `confirm()` later checks the threshold purely by counting set length (`confirmations.len() as u32 + 1 >= self.num_confirmations`) without validating that every entry still belongs to a current member [3](#0-2) . This breaks the binding "confirmations counted == live members confirming," letting a request execute with fewer live confirmations than `num_confirmations` requires.

### Finding Description
`add_request` records the creator as `member` on `MultiSigRequestWithSigner` and initializes an empty confirmation set [4](#0-3) . Any current member can call `confirm`, which inserts `member.to_string()` into the `confirmations` set for that request, and once `confirmations.len() + 1 >= num_confirmations` the request is executed [5](#0-4) .

`delete_member` is the only place that removes a departing member's footprint, but it does so by request *ownership*, not by confirmation *participation*:
```rust
let request_ids: Vec<u32> = self
    .requests
    .iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
``` [2](#0-1) 

If the removed member had confirmed a request created by someone else, that confirmation string remains inside the `HashSet<String>` for that request forever, because no code path re-checks `self.members.contains(...)` for entries already recorded in `confirmations`. `assert_valid_request` only checks that the *current caller* is a member [6](#0-5) ; it does not revalidate historical confirmers.

The identical pattern exists in the legacy `multisig/src/lib.rs`: `DeleteKey` removes only requests whose `signer_pk` matches the deleted key [7](#0-6) , leaving that key's confirmations on other pending requests intact, and `confirm` counts confirmations the same way [8](#0-7) .

### Impact Explanation
This crosses the "confirmations counted versus live members" custody binding explicitly in scope: a multisig request can be executed with fewer live confirmations than the configured threshold, because a removed member's stale confirmation still counts. Since multisig requests include `Transfer`, `AddKey`, `FunctionCall`, etc. [9](#0-8) , this can result in a transfer of NEAR, or an unauthorized key/permission grant, executed below the intended K-of-N threshold — a Critical-severity outcome per the rules ("a multisig request executed below threshold").

### Likelihood Explanation
No privileged action beyond ordinary multisig operation is required beyond what the multisig membership itself already permits (creating requests, confirming, and later removing a member via the normal `DeleteMember`/`DeleteKey` governance flow). Any pending request that received a partial confirmation from a member who is later removed remains exploitable — the remaining members only need to reach `num_confirmations - 1` additional live confirmations to trigger execution, effectively lowering the real threshold by however many stale confirmations exist from removed members.

### Recommendation
When removing a member (`delete_member` in `multisig2/src/lib.rs`, `DeleteKey` in `multisig/src/lib.rs`), iterate over all outstanding `confirmations` entries (not just requests created by that member) and remove the departing member's string/pubkey from every confirmation set. Alternatively, validate at `confirm()`/execution time that every entry in a request's confirmation set still corresponds to a current member of `self.members` before counting it toward the threshold.

### Proof of Concept
1. Deploy `multisig2` with members `{Alice, Bob, Carol}` and `num_confirmations = 2` [10](#0-9) .
2. Alice calls `add_request` to create request `X` (e.g., `Transfer` to an attacker-controlled account) — `X.member == Alice`, `confirmations[X] = {}` [11](#0-10) .
3. Bob calls `confirm(X)` — `confirmations[X] = {Bob}`, `1 < 2` so it doesn't execute yet [3](#0-2) .
4. Members later remove Bob via a `DeleteMember { member: Bob }` request that reaches `num_confirmations`. `delete_member` runs, but since request `X` was created by Alice (`r.member == Alice != Bob`), it is not filtered out and `confirmations[X] = {Bob}` survives untouched [12](#0-11) .
5. Alice (still a live member, but now the multisig has only `{Alice, Carol}` = 2 members with `num_confirmations = 2`) calls `confirm(X)`. `confirmations[X].len() + 1 = 1 + 1 = 2 >= 2`, so request `X` executes and the transfer is sent — even though only Alice, a single live member, actually approved it in real time; Bob's stale confirmation from before his removal was the deciding vote [13](#0-12) .

    /// Add request for multisig.
    pub fn add_request(&mut self, request: MultiSigRequest) -> RequestId {
        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(
                "Predecessor must be a member or transaction signed with key of given account",
            )
        });
        // track how many requests this key has made
        let num_requests = self
            .num_requests_pk
            .get(&current_member.to_string())
            .unwrap_or(0)
            + 1;
        assert(
            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();

            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
