### Title
`updateAccounting()` permanently clears the emergency `skipDefaultCheck` state, reopening `depositDuringEpoch` during an emergency-shutdown epoch - (File: contracts/IdleCDO.sol)

### Summary
The external bug: `forget_cached_acl()` unconditionally clears `ACL_DONT_CACHE`, a state meant to be constant, so callers that only meant to flush the cache silently drop the opt-out flag. The analog: `IdleCDO._forceUpdateAccounting()` sets `skipDefaultCheck = true` to bypass the default check and then unconditionally writes `skipDefaultCheck = false`, even when the flag was a pre-existing persistent emergency state set by `_emergencyShutdown()`. In `IdleCDOEpochVariant`, `skipDefaultCheck` is the only guard preventing `depositDuringEpoch` after an emergency shutdown (the function is not `whenNotPaused`), so a single owner/guardian `updateAccounting()` call — the intended way to crystallize losses during an emergency — silently reopens mid-epoch deposits.

### Finding Description
`IdleCDOEpochVariant._emergencyShutdown()` persists the emergency by setting `skipDefaultCheck = true` (line 614), with the explicit comment "Persist the emergency state and let authorized forced accounting crystallize the loss." `restoreOperations()` confirms this flag is the dedicated gate: "Clearing the emergency flag intentionally restores only the dedicated depositDuringEpoch path" (lines 624-625), and `depositDuringEpoch` reverts on `skipDefaultCheck` (line 661) while lacking a `whenNotPaused` modifier, so pause alone does not block it.

`IdleCDO._forceUpdateAccounting()` (IdleCDO.sol:921-927) does:

```solidity
skipDefaultCheck = true;
_updateAccounting();
skipDefaultCheck = false;
```

It restores `false` instead of restoring the prior value. `IdleCDOEpochVariant.updateAccounting()` (line 157) is callable by owner or guardian precisely during an emergency to crystallize losses. After that single call, `skipDefaultCheck` is `false` while `isEpochRunning` remains `true` and `block.timestamp < epochEndDate`, so every `depositDuringEpoch` gate that still passes (KYC via `isWalletAllowed`, `isDepositDuringEpochDisabled == false`, `isAYSActive == false`, non-programmable borrower) is satisfied — the emergency opt-out has been wiped, exactly like `ACL_DONT_CACHE` being wiped by `forget_cached_acl()`.

### Impact Explanation
A KYC-passing lender (in-scope attacker) can call `depositDuringEpoch` while the pool is in emergency shutdown mid-epoch, after a loss has been crystallized by the forced accounting. The mint price `(amount + trancheInterest) * supply / expectedFinal` is computed against post-loss NAVs, so the attacker buys tranche shares at the depressed post-loss price. Their underlying is forwarded to the borrower (line 732). On `finalizeDefault`, recovery is distributed with "one aggregate multiplier" over active gross backing (lines 187-189), so the attacker's cheaply acquired shares dilute the recovery reserve claimed by honest LPs — direct theft of recovery funds proportional to how depressed the post-loss price is. In a non-default emergency the attacker can likewise mint discounted shares against a NAV the operator explicitly froze, then exit after `restoreOperations`, siphoning value from existing holders.

### Likelihood Explanation
Triggering requires only the intended, documented operational sequence: guardian calls `emergencyShutdown()` mid-epoch, then owner/guardian calls `updateAccounting()` to crystallize the loss — the exact flow `_emergencyShutdown` was built for. No privileged actor misbehaves; the helper itself drops the persistent state. Any KYC'd wallet can then deposit before `epochEndDate`. The attacker's cost is only their deposit principal, and profit scales with the size of the crystallized loss and subsequent recovery.

### Recommendation
Restore the previous value instead of forcing `false` in `_forceUpdateAccounting`:

```solidity
bool prev = skipDefaultCheck;
skipDefaultCheck = true;
_updateAccounting();
skipDefaultCheck = prev;
```

Same class of fix as the kernel patch: the general-purpose helper must not invalidate a state it does not own.

### Proof of Concept
Foundry fork PoC outline:

```solidity
// setup: non-programmable, non-AYS epoch variant, isDepositDuringEpochDisabled = false,
// attacker is a Keyring/KYC-passing wallet
idleCDO.depositAA(...);                 // honest LPs fund the pool
cdoEpoch.startEpoch();                  // epoch running, deposits paused

vm.prank(guardian);
idleCDO.emergencyShutdown();            // skipDefaultCheck = true, paused

vm.prank(owner);
idleCDO.updateAccounting();             // crystallize loss; BUG: skipDefaultCheck reset to false
assertFalse(idleCDO.skipDefaultCheck());// emergency state lost

// attacker deposits mid-epoch at the depressed post-loss price
deal(underlying, attacker, amount);
vm.startPrank(attacker);
underlying.approve(address(idleCDO), amount);
uint256 minted = cdoEpoch.depositDuringEpoch(amount, address(AAtranche)); // succeeds
vm.stopPrank();

// borrower defaults; recovery is split over all active claims pro rata
// attacker claims a share of finalizeDefault recovery despite depositing post-loss
```

Key checks to assert: `depositDuringEpoch` reverts before `updateAccounting()` (proving `skipDefaultCheck` was the gate), succeeds after, and the attacker's share of `finalizeDefault` recovery exceeds their fair post-loss contribution, measured by comparing honest LP recovery per unit NAV before vs. after the attacker deposit.
