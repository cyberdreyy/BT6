The `KaminoWithdraw` accounts struct enforces `liquidity_vault` and `liquidity_vault_authority` via Anchor `seeds`/`bump` constraints tied directly to the bank's stored `liquidity_vault_bump`/`liquidity_vault_authority_bump`, in addition to a `has_one = liquidity_vault` check against the bank record itself [1](#0-0) . This means the vault used in the CPI-boundary transfer (`cpi_transfer_obligation_owner_to_destination`, which moves funds from `liquidity_vault` to the caller-supplied `destination_token_account`) is cryptographically pinned to the bank's canonical PDA at the runtime level, not resolved via any off-chain/test helper like `find_bank_vault_pda` that could be bypassed [2](#0-1) . The `find_bank_vault_pda` function in `programs/marginfi/src/utils/general.rs` is a plain PDA-derivation helper used by clients/tests to compute the expected address off-chain [3](#0-2) ; it does not perform any fee-adjusted amount conversion and is not itself part of the on-chain authorization path — the actual security boundary is the `seeds`/`bump`/`has_one` Anchor constraints on the `liquidity_vault` account.

The only genuinely attacker-controlled account is `destination_token_account`, which is documented as intentionally caller-controlled (the withdrawal recipient) and is not a "vault" in the fee/insurance/liquidity family sense [4](#0-3) . The optional accounts (`obligation_farm_user_state`, `reserve_farm_state`) only affect the Kamino farms CPI and have no bearing on vault PDA selection [5](#0-4) . Fee-adjusted conversion helpers like `calculate_pre_fee_spl_deposit_amount` operate on deposit paths for Token-2022 transfer-fee accounting and are unrelated to vault PDA resolution in `kamino_withdraw` [6](#0-5) . There is no reachable path where an unprivileged caller can substitute a foreign-family vault (fee/insurance vault in place of liquidity vault, or vice versa) because the seeds constraint hard-binds the account to the specific bank and vault type at the Anchor account-validation layer, before any instruction logic executes.

    pub fn cpi_transfer_obligation_owner_to_destination(&self, amount: u64) -> MarginfiResult {

        Ok(())

pub fn calculate_pre_fee_spl_deposit_amount(
    mint_ai: AccountInfo,
    post_fee_amount: u64,
    epoch: u64,
) -> MarginfiResult<u64> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(post_fee_amount);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    match mint.get_extension::<TransferFeeConfig>() {
        Ok(transfer_fee_config) => {
            let epoch_fee = transfer_fee_config.get_epoch_fee(epoch);
            let pre_fee_amount = calculate_pre_fee_amount(epoch_fee, post_fee_amount).unwrap();
            Ok(pre_fee_amount)
        }
        Err(_) => Ok(post_fee_amount),
    }
}
