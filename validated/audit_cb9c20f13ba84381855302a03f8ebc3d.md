## Finding

The `WorkflowMetadataHandler.Authorize` function contains a genuine check-then-act race condition analogous to the lodestar duplicate-aggregate bug: the "already seen" check and the "record as seen" write are two separate, non-atomic critical sections, allowing the same one-time-use JWT to authorize two concurrent HTTP-trigger requests.

### Title
Race condition in JWT replay-guard allows a single-use JWT to authorize duplicate workflow executions - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize` checks `jwtCache.isReplay(claims.ID)` and later calls `jwtCache.recordUsage(claims.ID)`, but these are two independent lock acquisitions with unrelated work (authorized-key lookup) executed in between, rather than a single atomic check-and-record operation.

### Finding Description
`Authorize` is reached from `httpTriggerHandler.HandleUserTriggerRequest` → `authorizeRequest` → `WorkflowMetadataHandler.Authorize`, which any unprivileged HTTP-trigger caller reaches by POSTing a signed JWT request to the CRE gateway. [1](#0-0) 

Internally, replay protection is implemented via `jwtReplayCache`, whose `isReplay` and `recordUsage` each take/release the mutex independently: [2](#0-1) 

Because `isReplay` (RLock) and `recordUsage` (Lock) are separate critical sections with the authorized-key map lookup executed in between, two goroutines that call `Authorize` concurrently with the same JWT `jti` can both observe `isReplay == false` before either calls `recordUsage`. Both then proceed past the replay check, both pass owner/signer checks (same request digest, same signer), and both are treated as validly authorized. This is the same class of bug fixed upstream in lodestar — a check performed on stale state before a delayed/duplicated write, allowing a construct meant to be single-use to be accepted twice. By contrast, the vault package's `RequestReplayGuard.CheckAndRecord` correctly performs the check and insert under one lock: [3](#0-2)  — demonstrating the correct pattern that `jwtReplayCache` fails to follow.

### Impact Explanation
A successful race lets an unprivileged client cause `setupCallback`/`sendWithRetries` to be invoked twice for what was intended to be a single-use, digest-bound authorization token, resulting in duplicate workflow trigger executions being dispatched to the DON for the same signed request. This is an unauthorized/duplicate job-run condition originating purely from a race in server-side replay-guard bookkeeping, reachable from an unauthenticated network client via the gateway HTTP-trigger path.

### Likelihood Explanation
Exploitation only requires firing two requests with the same valid, signer-issued JWT nearly simultaneously (e.g., two parallel HTTP connections) — no privileged access, valid signer key ownership aside (which the attacker already needs to obtain a signed JWT in the first place, same as for a single legitimate request). The race window is real but narrow (time between `isReplay` RLock release and `recordUsage` Lock acquisition, including the authorized-key map lookup), making it opportunistic rather than deterministic.

### Recommendation
Merge `isReplay` + `recordUsage` into a single atomic "check-and-record" operation under one lock (mirroring `RequestReplayGuard.CheckAndRecord` in `core/capabilities/vault/request_replay_guard.go`), so that only one caller can win the race and mark the `jti` as used.

### Proof of Concept
1. Obtain a validly signed JWT for a workflow-execute request (as any legitimate authorized signer would produce for a single request).
2. Fire two concurrent `HandleUserTriggerRequest` calls (or two concurrent gateway HTTP POSTs) using the identical JWT/request pair.
3. Both goroutines call `WorkflowMetadataHandler.Authorize` at nearly the same time; both call `jwtCache.isReplay(claims.ID)` before either calls `jwtCache.recordUsage(claims.ID)`.
4. Both requests pass authorization and are forwarded via `setupCallback`/`sendWithRetries`, resulting in two workflow executions triggered from what should be a single-use signed request — where the existing tests only cover the sequential case (`TestWorkflowMetadataHandler_Authorize/JWT replay protection`, `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler_test.go:1193-1217`) and do not exercise concurrent calls.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
