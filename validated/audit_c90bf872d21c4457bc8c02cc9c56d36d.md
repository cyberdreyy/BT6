### Title
Unauthenticated pprof/metrics proxy for LOOP plugins allows memory-disclosure - ([File: core/web/router.go], [File: core/web/loop_registry.go])

### Summary
`loopRoutes(app, api)` is registered directly on the outer `api` group in `NewRouter` with no `auth.Authenticate` wrapper, unlike every other sensitive route group (`debugRoutes`, `sessionRoutes`, `v2Routes`, and the node's own `metricRoutes`, which is deliberately mounted under `authv2`). This leaves `GET /plugins/:name/debug/pprof/*profile`, `POST /plugins/:name/debug/pprof/symbol`, `GET /plugins/:name/metrics`, and `GET /discovery` reachable by any unauthenticated client.

### Finding Description
In `core/web/router.go`, the route registration sequence is: [1](#0-0) 
`debugRoutes`, `sessionRoutes`, and `v2Routes` all wrap their sensitive handlers in `auth.Authenticate(...)` groups (see `debugRoutes` at line 181, `sessionRoutes` at line 216, and `authv2` at line 245), and the node's own `net/http/pprof` handlers are deliberately placed inside the authenticated `authv2` group via `metricRoutes(authv2)` at line 446. In sharp contrast, `loopRoutes` registers its handlers directly on the unauthenticated `r` (`api`) group with zero middleware: [2](#0-1) 

`pluginPPROFHandler` in `core/web/loop_registry.go` takes the `:name` and `*profile` path params directly from the unauthenticated request, looks up the plugin in the registry, and proxies the request verbatim to the plugin's internal `/debug/pprof/<profile>` endpoint, returning the raw response body to the caller: [3](#0-2) [4](#0-3) 

Since no `auth.Authenticate`/`auth.RequiresAdminRole` wrapper exists anywhere on this path from `engine` → `api` → `loopRoutes`, any network client that can reach the node's HTTP API can call `GET /plugins/<name>/debug/pprof/heap` (or `/goroutine`, `/allocs`, etc.) with zero credentials and receive a full heap/goroutine dump proxied from the named LOOP plugin process.

### Impact Explanation
LOOP plugin processes (median/relayer/etc. LOOPPs) can hold sensitive in-memory material relevant to their operation (decrypted signing material, RPC credentials, transient job data) depending on plugin type; regardless of exact contents, exposing raw heap/goroutine/allocs dumps of a backend process to an unauthenticated network caller is a memory-disclosure vulnerability that matches Chainlink's "sensitive data exposure / unauthorized information disclosure" bounty class, and could act as a stepping stone toward oracle identity/key compromise if the targeted plugin process holds such secrets in memory.

### Likelihood Explanation
No preconditions beyond network reachability to the node's HTTP API are required — the attacker needs no session, no API token, and no role. The plugin name is discoverable via the equally-unauthenticated `GET /discovery` endpoint or `GET /plugins/:name/metrics`, which list registered plugins. This is trivially repeatable and scriptable.

### Recommendation
Wrap `loopRoutes` in the same authenticated group used for other administrative/debug endpoints, e.g. register it as `authv2`-style with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` plus `auth.RequiresAdminRole`, mirroring how `metricRoutes(authv2)` protects the node's own pprof handlers.

### Proof of Concept
Add a handler-level integration test in `core/web` (alongside existing router tests) that:
1. Builds the router via `NewRouter` with a test app containing a registered fake plugin (via `plugins.LoopRegistry`).
2. Issues `GET /plugins/testplugin/debug/pprof/heap` with no `Authorization` header / no session cookie.
3. Asserts the current (vulnerable) behavior returns `200 OK` with a pprof payload — and after the fix, asserts it returns `401 Unauthorized` before any proxying occurs.
4. Repeat for `/plugins/:name/metrics` and `/discovery` to confirm they also require authentication once fixed.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
