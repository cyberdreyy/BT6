### Title
Path traversal / arbitrary file write via zip legacy extractor ignoring `dir` and not validating `zip.File.Name` - (File: helpers/archives/zip_extract.go)

### Summary
The legacy zip extractor (`ziplegacy`) receives a `dir` (the job's `wd`) but never uses it: `extractor.Extract` calls `archives.ExtractZipArchive(zr)` with no directory argument, and `extractZipFile`/`extractZipSymlinkEntry`/`extractZipFileEntry` operate directly on `file.Name` via `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile`/`os.Symlink`. There is no join against `dir` and no path-containment check, unlike `fastzip` which passes `e.dir` straight into `fastzip.NewExtractorFromReader` for confinement.

### Finding Description
`ArtifactsDownloaderCommand.Execute` computes `wd` via `os.Getwd()` and passes it into `archive.NewExtractor(format, f, size, wd)` [1](#0-0) . For the `zip` format this resolves to `ziplegacy.NewExtractor`, which stores `dir` in the `extractor` struct but its `Extract` method discards it entirely, calling only `archives.ExtractZipArchive(zr)` [2](#0-1) . Contrast with `fastzip`'s extractor, which forwards `e.dir` into `fastzip.NewExtractorFromReader(e.r, e.size, e.dir, opts...)`, letting the well-audited `fastzip` library perform path confinement [3](#0-2) .

Inside `ExtractZipArchive`, each `zip.File` is passed to `extractZipFile(file)`, which does:
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
case os.ModeSymlink: err = extractZipSymlinkEntry(file)
default: err = extractZipFileEntry(file)
``` [4](#0-3) 

`extractZipFileEntry` writes with `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` [5](#0-4) , and `extractZipSymlinkEntry` creates a symlink at `file.Name` pointing at attacker-controlled target data read from the zip entry itself [6](#0-5) . None of these functions join `file.Name` against `dir`/`wd`, and there is no check that the resolved path stays a descendant of any root — the only path-related check present is `errorIfGitDirectory`, which only warns about `.git` directory entries and is unrelated to traversal/absolute-path confinement [7](#0-6) .

Because `ExtractZipArchive` operates purely on `file.Name` as given by the archive, a crafted zip whose entries contain absolute paths (`/etc/passwd`, `C:\Windows\...`) or `../` traversal sequences will cause `os.MkdirAll`/`os.OpenFile`/`os.Symlink` to create or overwrite files anywhere the runner process has write permission, entirely outside `wd`. Since Go's `os` calls operate on whatever path string is given (relative paths resolve against the process CWD, not `wd`, and absolute paths bypass CWD entirely), the "confinement to `wd`" invariant is not enforced anywhere in this code path.

### Impact Explanation
An unprivileged pipeline author who controls a job's artifacts (a `.gitlab-ci.yml` job producing/uploading a `zip`-formatted artifact, or otherwise able to have the runner's `artifacts-downloader` (ziplegacy path) extract an attacker-crafted zip) can achieve arbitrary file write/overwrite on the runner host filesystem, limited only by the OS-level permissions of the runner process. This can lead to overwriting files outside the job workspace, planting symlinks to sensitive paths, or trampling other jobs'/system files if the runner process has broader write access (e.g., shared shell executor host, or elevated runner service account) — a direct violation of the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
This is straightforward and fully attacker-reachable without special privileges: any pipeline author can supply an artifact zip with crafted entry names. Whether the "legacy" zip extractor path is actually selected depends on runtime feature flags/configuration (the codebase also supports `fastzip`, which is properly confined), but the `ziplegacy` package and its call path (`ArtifactsDownloaderCommand.Execute` → `archive.NewExtractor(Zip, ...)` → `ziplegacy.extractor.Extract` → `archives.ExtractZipArchive` → `extractZipFile`) exists and is reachable and unguarded whenever selected. The exploit is deterministic and repeatable (same crafted zip triggers the same overwrite each run).

### Recommendation
- Make `ziplegacy.extractor.Extract` actually use `e.dir`: change file target resolution in `helpers/archives/zip_extract.go` to `filepath.Join(dir, file.Name)` for all of `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`, and `extractZipFile` (and `lchmod`/`processZipExtra` calls in `ExtractZipArchive`), threading `dir` through the call chain (`ExtractZipArchive(archive *zip.Reader, dir string)`).
- After joining, validate the resulting cleaned path is a descendant of `dir` (reject absolute `file.Name`, reject any entry whose joined+cleaned path escapes `dir`, e.g. via `filepath.Clean` + `strings.HasPrefix` check with proper separator handling, or use `filepath.Rel` and reject if the result starts with `..`).
- For symlinks, additionally validate/restrict the symlink target (`data` in `extractZipSymlinkEntry`) so it cannot point outside `dir`, mirroring protections that should exist for tar/fastzip extraction.

### Proof of Concept
Go unit test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideFile := filepath.Join(t.TempDir(), "pwned.txt") // sibling dir, outside tmpDir

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    // absolute-path-like traversal entry
    rel, _ := filepath.Rel(tmpDir, outsideFile)
    f, _ := zw.Create(rel) // e.g. "../<tmp2>/pwned.txt"
    f.Write([]byte("attacker data"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    os.Chdir(tmpDir)
    defer os.Chdir(wd)

    err := ExtractZipArchive(zr) // current signature has no dir param
    require.NoError(t, err)

    // Assert file was written OUTSIDE tmpDir - proving escape
    assert.FileExists(t, outsideFile)
}
```
Expected (buggy) result: `outsideFile` exists, proving the write escaped the intended extraction root. After the fix (joining against `dir` and rejecting escaping paths), the test should instead assert an error is returned and `outsideFile` does NOT exist.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
