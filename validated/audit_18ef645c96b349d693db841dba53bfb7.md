### Title
Raw ANSI/control bytes in job script commands are not escaped by `EscapeForPosix`, allowing terminal/log spoofing in trace-section headers - (File: functions/script_legacy/internal/trace_section.go)

### Summary
`TraceSectionWriter.writeSectionStart` builds the section header line by concatenating the fixed `ansiBoldGreen`/`ansiResetTrace` constants with the attacker-controlled `command` string and passing the result through `w.escape()`. When the writer is configured in POSIX mode (`posixMode == true`), `escape()` calls `EscapeForPosix`, which only escapes backticks, quotes, backslash, `$`, and a handful of shell metacharacters — it does not neutralize control bytes such as `0x1b` (ESC). As a result, raw ANSI/OSC escape sequences embedded in a job's multi-line `script` entry are emitted verbatim inside the `section_start:...\r\e[0K...` line, between the fixed markers, letting a pipeline author manipulate terminal rendering to hide or spoof log content.

### Finding Description
The call path is exactly as described: `script_legacy.Run` → `ScriptGenerator.GenerateScript` → `CommandProcessor.ProcessCommand` (functions/script_legacy/internal/command_processor.go:30) → `shouldUseTraceSection` (line 45-47, true when `traceSections && isMultiline(command)`) → `TraceSectionWriter.WriteSection` (trace_section.go:42-48) → `writeSectionStart` (trace_section.go:52-62) → `w.escape` (trace_section.go:86-92).

`writeSectionStart` builds:
```
command = w.escape(ansiBoldGreen + commandPrefix + command + ansiResetTrace)
```
`escape()` branches on `posixMode`:
```go
func (w *TraceSectionWriter) escape(input string) string {
	if w.posixMode {
		return EscapeForPosix(input)
	}
	return "$'" + EscapeForAnsiC(input) + "'"
}
``` [1](#0-0) 

`EscapeForAnsiC` (escape.go:14-50) is safe: any byte `< 0x20`, `== 0x7F`, or `> 0x7F` (which includes ESC, `0x1b`) is hex-escaped via `\xNN`, explicitly to "prevent ANSI escape sequences (ESC = 0x1B) from manipulating terminal." [2](#0-1) 

`EscapeForPosix` (escape.go:55-82), used when `posixMode` is true, only escapes `` ` " \ $ `` and quotes/wraps if any of a fixed metacharacter set is present; the `default:` branch for every other rune — including raw ESC `0x1b`, BEL `0x07`, and CSI bytes — just writes the rune through unchanged:
```go
default:
    buf.WriteRune(r)
``` [3](#0-2) 

Since the command text is wrapped only in POSIX double quotes (which do not interpret or block control bytes), the resulting `printf '%s\n' ... "$COMMAND_WITH_RAW_ESC"` will emit the attacker's raw escape bytes literally to the trace stream, sitting between the fixed `ansiClear`/`ansiBoldGreen` prefix and before the trailing `ansiResetTrace` — i.e., inside the section-start line that GitLab's log renderer parses for section boundaries and coloring.

None of the existing checks (masking, log-line formatting in `CommandFormatter`, or the `EscapeForAnsiC` hex-escaping) apply in POSIX mode; the safe hex-escaping logic exists but is bypassed entirely by the POSIX code path.

### Impact Explanation
An unprivileged pipeline author who supplies a multi-line `script:` command containing raw ESC/CSI/OSC sequences (e.g., `\x1b[2J` to clear scroll-back, `\x1b]0;...\x07` to rewrite the terminal title, or cursor-repositioning sequences) can have those bytes injected unescaped into the trace-section header line whenever the runner uses POSIX-mode escaping for trace sections. This lets a job overwrite/hide previously rendered log lines or spoof section boundaries in terminals/tools that render the raw job trace, potentially concealing injected or malicious commands from a CI log reviewer relying on a raw/terminal view of the log (masked-value or malicious-log spoofing, matching the scoped impact).

### Likelihood Explanation
Preconditions are: (1) `FF_SCRIPT_SECTIONS`/`trace_sections` enabled, (2) a multi-line script step (fully job-author controlled), and (3) the section writer running in POSIX escaping mode (`posixMode == true`, corresponding to shells such as `sh`/`dash`/BusyBox — a common runner/shell configuration, e.g., Alpine-based images). All three are attacker/environment-controllable or common in practice; no privileged action is required. This is straightforward to trigger deterministically and repeatably by any pipeline author able to author `.gitlab-ci.yml` `script` entries.

### Recommendation
Make `EscapeForPosix` neutralize control bytes the same way `EscapeForAnsiC` does — hex/octal-escape or strip bytes `< 0x20`, `0x7F`, and non-ASCII bytes (or reuse the same ANSI-C quoting path for section-start content regardless of `posixMode`) before embedding job-controlled command text into the `section_start` header. At minimum, strip/escape ESC (`0x1b`) and other C0 control bytes in `writeSectionStart`'s POSIX branch before concatenation.

### Proof of Concept
```go
func TestWriteSection_PosixMode_EscapesRawEsc(t *testing.T) {
    w := NewTraceSectionWriter(false /*checkForErrors*/, true /*posixMode*/)
    var buf strings.Builder
    malicious := "echo one\n\x1b[2Jecho two\x1b]0;spoofed-title\x07"
    w.WriteSection(&buf, 0, malicious)
    out := buf.String()

    // Assert no raw ESC byte (0x1b) leaks outside the fixed ansi constants.
    stripped := strings.ReplaceAll(out, ansiBoldGreen, "")
    stripped = strings.ReplaceAll(stripped, ansiResetTrace, "")
    stripped = strings.ReplaceAll(stripped, ansiClear, "")
    if strings.ContainsRune(stripped, 0x1b) {
        t.Fatalf("unescaped ESC byte found in trace section output: %q", out)
    }
}
```
Expected result on the current code: the test **fails** — `EscapeForPosix` passes the raw `0x1b` bytes through unchanged in `writeSectionStart`, whereas the equivalent test with `posixMode=false` (AnsiC path) passes because `EscapeForAnsiC` hex-escapes them.

```go
func EscapeForPosix(s string) string {
	if s == "" {
		return "''"
	}

	var buf strings.Builder
	needsQuoting := false

	for _, r := range s {
		switch r {
		case '`', '"', '\\', '$':
			buf.WriteRune('\\')
			buf.WriteRune(r)
			needsQuoting = true
		case ' ', '!', '#', '%', '&', '(', ')', '*', '<', '=', '>', '?', '[', '|':
			buf.WriteRune(r)
			needsQuoting = true
		default:
			buf.WriteRune(r)
		}
	}

	if needsQuoting {
		return `"` + buf.String() + `"`
	}

	return buf.String()
}
