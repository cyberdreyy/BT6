Given the rules' stated scope (an equality break like signed-vs-validated, one-per-height, or a liveness wedge), I did examine the actual signing-safety machinery to see if a real bug exists there, but found the opposite of a gap:

- `handle_block_pre_commit` in `stacks-signer/src/v0/signer.rs` re-runs `check_block_against_signer_db_state` and `get_signed_conflicts` right before signing, specifically to prevent placing a second signature on a conflicting block at the same or higher height, across *any* tenure [1](#0-0) .
- Staleness/liveness of a conflict is derived fresh from the node every time via `conflict_still_blocks`, rather than cached, specifically to avoid both over-blocking (liveness wedge) and under-blocking (double-sign) [2](#0-1) .
- `get_signed_conflicts` in `signerdb.rs` explicitly only returns blocks that were actually signed (`signed_self`/`signed_group`), never merely pre-committed blocks, preserving the signed-vs-validated distinction [3](#0-2) .
- `check_latest_block_in_tenure` / `get_tenure_last_block_info` deliberately only consult signed blocks (not pre-commits) when deciding whether a proposal confirms enough of the chain, which is covered by dedicated tests (`pre_committed_block_does_not_veto_replacement`) [4](#0-3) .
- `validate_tenure_change_payload` rejects a second tenure-start block once a block has already been globally accepted in that tenure, closing the "one block per tenure at proposal time" gap, and the doc notes explicitly which gap (crossing pre-commit threshold long after proposal) is covered by the separate own-tenure conflict guard rather than left open [5](#0-4) [6](#0-5) .
- Node-side, `postblock_proposal.rs`'s `validate()` independently checks tenure validity, parent linkage, contiguous height, and timestamp bounds before any signer ever sees an "Ok" verdict [7](#0-6) .

None of this exposes a reachable equality break or wedge a one-slot miner could trigger; the code paths are extensively tested for exactly the double-sign/conflicting-block scenarios the rules describe (e.g. `signer_refuses_to_sign_second_sibling_tenure_start`, `fresh_conflict_in_another_tenure_blocks_signing`) [8](#0-7) [9](#0-8) .
