### Title
Zip Slip: `ExtractZipFile`/`ExtractZipArchive` write files using unsanitized zip entry names, allowing path traversal into sibling build/cache directories - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile`, `extractZipDirectoryEntry`, `extractZipFileEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` use `file.Name` from the zip archive directly as a filesystem path with no cleaning, no rejection of absolute paths, and no rejection of `..` traversal segments. The only path check performed is `errorIfGitDirectory`, which solely blocks `.git` prefixes and has nothing to do with traversal protection.

### Finding Description
`ExtractZipFile` (helpers/archives/zip_extract.go:112-119) opens the archive and delegates to `ExtractZipArchive`, which iterates `archive.File` and for every entry calls `extractZipFile(file)` [1](#0-0) .

Inside `extractZipFile`, the code does:
- `os.MkdirAll(filepath.Dir(file.Name), 0o777)` — creates parent directories for whatever path is encoded in the entry name, with no cleaning or bounds check.
- `extractZipDirectoryEntry`/`extractZipFileEntry`/`extractZipSymlinkEntry` then call `os.Mkdir`, `os.OpenFile`, or `os.Symlink` directly against `file.Name` [2](#0-1) .

The only sanity check applied per-entry is `errorIfGitDirectory`, implemented in `helpers/archives/path_check_helper.go`, which only checks whether the first path component (after `filepath.Clean`) equals `.git` — it does not detect or block `..` segments, absolute paths (e.g. `/etc/...` or `C:\...`), or symlink targets pointing outside the extraction root [3](#0-2) .

Go's `archive/zip` package (as used here via `zip.OpenReader`/`zip.NewReader`) does not itself sanitize `File.Name` for path traversal — that responsibility is left to the caller. Since no `filepath.Clean`, no rejection of entries starting with `/` or containing `..`, and no verification that the resolved destination stays within the intended extraction root are performed anywhere in this file, a crafted zip archive with entries such as `../../sibling-job/build/malicious.sh` or an absolute path can be written outside the intended job directory.

An attacker-controlled archive reaches this code via the artifact/cache download-and-extract path used by the Runner (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go` calls `archives.ExtractZipArchive` directly with no path confinement inside `Extract()` itself) [4](#0-3) . Notably, the `extractor.dir` field captured in `NewExtractor` is never referenced inside `Extract()`, so whatever directory confinement exists (if any) must come entirely from the process's current working directory at call time rather than from any path-joining/validation logic in the zip extraction code itself. This means the zip-entry-name sanitization that should stop `../` traversal is simply absent from the extraction logic that is supposed to enforce the "must stay within intended build/cache/artifact roots" invariant.

### Impact Explanation
Any job whose CI configuration causes it to download and extract an attacker-influenced artifact or cache zip (e.g., a cache/artifact populated by an earlier stage under attacker control, or a zip artifact fetched from a public/attacker-controlled source and referenced by pipeline configuration) can have file-write side effects outside its own job directory. On a shared runner host (or a runner reusing filesystem paths across concurrent jobs), this allows cross-job or cross-project file tampering — e.g., overwriting scripts, hook files, or configuration in a sibling job's build/cache directory — violating the "one job restore must not modify another job directory" invariant.

### Likelihood Explanation
Exploitability requires: (1) attacker control of zip content (fully achievable — CI users control cache/artifact contents produced in their own pipeline, or a job configured to fetch/extract a zip whose bytes an attacker influences), and (2) the runner extracting that zip without any additional external sandboxing/chroot per job. Given the code has no `filepath.Clean`/traversal check at all, crafting a malicious zip with `../` entries is trivial and 100% repeatable. The main uncertainty is how strongly host/container isolation (working-directory scoping, chroot, or containerized executors) mitigates the reachable blast radius in a given executor configuration; on shell executors or executors sharing a build root across jobs, the traversal is directly actionable.

### Recommendation
In `helpers/archives/zip_extract.go`, before creating any file, directory, or symlink, canonicalize the target path relative to the extraction root and reject any entry whose cleaned, joined path escapes that root (i.e., verify with `filepath.Rel`/prefix-check against the root after `filepath.Clean`). Reject entries with absolute paths and entries containing `..` path segments that resolve outside the root. Also validate symlink targets (`extractZipSymlinkEntry`) so that the destination cannot point outside the extraction root. Apply the same root-confinement check for both the file being created and (for symlinks) the target being written.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    root := t.TempDir()
    jobDir := filepath.Join(root, "job-a")
    siblingDir := filepath.Join(root, "job-b")
    require.NoError(t, os.MkdirAll(jobDir, 0o755))
    require.NoError(t, os.MkdirAll(siblingDir, 0o755))

    // Build a malicious zip whose entry escapes jobDir via "../"
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    f, _ := zw.Create("../job-b/pwned.txt")
    _, _ = f.Write([]byte("owned"))
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    wd, _ := os.Getwd()
    defer os.Chdir(wd)
    require.NoError(t, os.Chdir(jobDir))

    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert: the sibling job directory must NOT contain the attacker's file
    _, statErr := os.Stat(filepath.Join(siblingDir, "pwned.txt"))
    assert.True(t, os.IsNotExist(statErr), "zip slip: file escaped into sibling job directory")
}
```
Expected (current, buggy) result: the assertion fails because `pwned.txt` is written into `job-b`, proving the path-traversal/zip-slip write into a sibling directory.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
