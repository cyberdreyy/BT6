### Title
Missing per-sender allowlist/quota check before accepting `MethodWebAPITrigger` requests allows unauthenticated eviction and fan-out abuse - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` accepts any incoming `MethodWebAPITrigger` message that passes basic payload decoding, timestamp freshness, and `common.ValidatedRequestFromMessage`, but performs no allowlist or per-sender/per-token rate limiting before saving a callback and fanning the request out to every DON member. The code explicitly marks this gap with a TODO comment.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go` lines 218-276) decodes the incoming JSON-RPC request and, for legacy requests, calls `msg.Validate()` (structural validation only — no sender authentication/authorization) before dispatching to `h.HandleLegacyUserMessage`. There is no caller-identity or credential check performed anywhere in this path prior to reaching the handler. [1](#0-0) 

Inside `HandleLegacyUserMessage`, the checks performed are: JSON payload decoding, `payload.Timestamp != 0`, and a staleness check against `MaxAllowedMessageAgeSec`. [2](#0-1)  Immediately after these checks the code has the comment `// TODO: apply allowlist and rate-limiting here` followed directly by the method check and `common.ValidatedRequestFromMessage(msg)`, with no allowlist, quota, or per-sender rate-limiter call in between. [3](#0-2) 

`common.ValidatedRequestFromMessage` only checks that `MessageId`, `Method` are non-empty and marshals the message — it performs no authentication or sender-identity verification. [4](#0-3) 

After passing these checks, the handler unconditionally stores the callback under `msg.Body.MessageId` and forwards the request to **every** DON member: [5](#0-4) 

Note that `nodeRateLimiter` (`ratelimit.RateLimiter`) exists on the handler struct but is only used in `handleWebAPIOutgoingMessage`, which processes **node-originated** messages (`HandleNodeMessage`), not user-originated `HandleLegacyUserMessage` traffic. [6](#0-5)  There is no equivalent rate limiter keyed by user/sender/API-token applied in `HandleLegacyUserMessage`.

Because there is no per-sender/per-token quota, any client capable of reaching the gateway's user HTTP endpoint (no operator/admin/node credential required — this is the "user" side of the gateway, distinct from the node-authenticated connection manager side) can submit unlimited distinct `MessageId`s and have each one accepted, saved into `h.savedCallbacks`, and broadcast to all DON members.

### Impact Explanation
Each accepted message consumes an entry in `h.savedCallbacks`, which is bounded only by `pruneCallbacks`' `MaxSavedCallbacks` eviction policy (oldest-first). An attacker sending requests faster than the prune interval/threshold can force premature eviction of other users' in-flight callbacks, causing legitimate users' requests to silently time out (cross-user DoS via state eviction). Additionally, every accepted message is unconditionally forwarded to all DON nodes (`don.SendToNode` for each member), meaning an unauthenticated/low-priv attacker can generate unbounded fan-out load against the entire DON — a resource-exhaustion/DoS vector reachable without any credential. This matches Chainlink's bounty impact class of "Denial of Service" / unauthorized resource consumption via allowlist/quota bypass, not a fund-loss or key-disclosure bug.

### Likelihood Explanation
High feasibility: the only precondition is network access to the gateway's user-facing HTTP port and the ability to craft a syntactically valid JSON-RPC/legacy `api.Message` with a fresh `Timestamp` and `MethodWebAPITrigger`/unique `MessageId` — no signature, API key, or allowlist entry is required by this function. This is fully repeatable and scriptable (increment `MessageId` per request).

### Recommendation
Implement the allowlist/rate-limiting called out in the TODO before line 384: enforce a per-sender (e.g., keyed on `msg.Body.Sender`/API token or source IP) allowlist check and a `ratelimit.RateLimiter`-based quota (mirroring `nodeRateLimiter` but scoped to users) prior to accepting the message into `savedCallbacks` and forwarding it to DON members. Reject over-quota or non-allowlisted senders with a distinct `ErrorCode` (e.g., `RateLimitExceeded`) instead of silently proceeding.

### Proof of Concept
Go test plan in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` via `NewHandler` with a mock `handlers.DON` (asserting `SendToNode` is called for every configured member) and a mock `handlers.Callback`.
2. Loop N times (N > default/small `MaxSavedCallbacks` used in test config) generating a fresh `api.Message` with a unique `MessageId`, `Method: MethodWebAPITrigger`, valid `Timestamp`, and no signature/sender allowlist entry.
3. Call `h.HandleLegacyUserMessage(ctx, msg, callback)` for each and assert:
   - No error is returned and `don.SendToNode` is invoked for each DON member for every message (proving unauthenticated acceptance/fan-out).
   - After N calls exceeding `MaxSavedCallbacks`, trigger `pruneCallbacks()` and assert that callbacks from an earlier "legitimate" batch (saved before the attacker flood) are evicted from `h.savedCallbacks`, demonstrating cross-sender eviction caused purely by volume with no credential check.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}
