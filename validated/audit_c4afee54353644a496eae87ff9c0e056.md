## Finding: Zip extraction does not validate/contain `file.Name`, and the `dir` field on `ziplegacy.extractor` is stored but never enforced

### Title
Zip extraction path traversal / missing directory containment (Zip Slip) - ([File: helpers/archives/zip_extract.go], [File: helpers/archives/zip_extra_unix.go], [File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go])

### Summary
`ziplegacy.extractor` stores `dir` on the struct but `Extract` never uses it — it just calls `archives.ExtractZipArchive(zr)` with no directory argument at all. [1](#0-0)  Inside `ExtractZipArchive`, every file operation (`os.MkdirAll`, `os.OpenFile`, `os.Symlink`, `os.Lchown`) is performed directly against the raw `file.Name` from the zip header, with no path-traversal check (`..`/absolute path) and no joining against any extraction root. [2](#0-1) [3](#0-2) 

### Finding Description
The confirmed call chain is `ziplegacy.NewExtractor(r, size, dir)` → `extractor.Extract(ctx)` → `archives.ExtractZipArchive(zr)` → `extractZipFile(file)` (and later `processZipExtra`/`processZipUIDGidField`). The `dir` value is only stored on the struct, never passed downstream: [4](#0-3) 

`extractZipFile` builds parent directories and writes/removes/symlinks using `file.Name` verbatim: [5](#0-4) 

There is no check that `filepath.Clean(file.Name)` stays under any root, and no rejection of absolute paths or `..` segments — the only path-based check present is `errorIfGitDirectory`, which only detects a leading `.git` component, not traversal. [6](#0-5) [7](#0-6) 

`processZipUIDGidField` (in `zip_extra_unix.go`) similarly calls `os.Lchown(file.Name, uid, gid)` directly from attacker-supplied extra-field UID/GID values, with the same unvalidated `file.Name`. [3](#0-2) 

Whether this is actually exploitable depends on how "containment" is achieved in practice: the real code has no chroot/path-join containment at all — the only thing that keeps extraction inside the intended directory is that the *process's current working directory* happens to already be the target directory when `os.MkdirAll`/`os.OpenFile` (which resolve relative paths against CWD) are called. I confirmed this in the `cache-extractor` caller: `wd, _ := os.Getwd()` is captured and passed as `dir` to `archive.NewExtractor(format, f, size, wd)`, but `wd` is otherwise unused beyond being passed to the (no-op, for zip) extractor constructor — the extraction genuinely relies on the process already being chdir'd into the correct directory before `Execute` runs. [8](#0-7) 

Given that, a zip entry with `Name = "../sibling-job/secret"` or `Name = "../../etc/foo"` is not blocked by any code path — `filepath.Dir(file.Name)` and the subsequent `os.OpenFile`/`os.Symlink`/`os.Lchown` will resolve relative to CWD and can write or chown files outside the intended extraction directory, up to filesystem permission limits of the runner/job process.

### Impact Explanation
On shared/shell/docker executors where multiple jobs' build directories are siblings on the same filesystem (a supported, non-privileged-admin-misconfiguration scenario, since this is the ordinary "concurrent=N" runner setup, not `privileged: true` or `docker.sock` exposure), a malicious job that provides a crafted cache or artifact zip (cache and artifact contents are fully attacker-controlled — a job can set arbitrary `cache`/`artifacts` paths and content) can write files, symlinks, or change ownership (`Lchown`) outside its own job directory. This breaks the "file operations must stay within intended build/cache/artifact roots" invariant and can corrupt or tamper with another job's workspace/cache directory on the same host, or write to arbitrary paths reachable by the job process's permissions.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: any job author can produce a cache/artifact archive with crafted entry names and Unix-extra UID/GID fields (standard zip metadata, easily fabricated), since GitLab Runner accepts and later extracts these artifacts without validating `file.Name`. Legacy zip extraction (`ziplegacy`) is used as a fallback path (`fastzip` is the primary path in many configurations), but is still reachable and registered via `commands/helpers/archive/archive.go`'s `Register`/`NewExtractor` mechanism, and `helpers/archives/zip_extract.go`'s `ExtractZipArchive`/`ExtractZipFile` are shared with other extraction call sites, so exposure is not limited to one exotic configuration. This is fully reproducible with a deterministic, repeatable PoC (no timing/race dependency).

### Recommendation
In `helpers/archives/zip_extract.go`, validate and normalize every `file.Name` before use: reject absolute paths, reject entries whose `filepath.Clean(file.Name)` resolves outside of a designated root (join with the intended root and verify `strings.HasPrefix(resolved, root+separator)`), and apply the same check before the `Lchown` call in `processZipUIDGidField` in `zip_extra_unix.go`/`zip_extra_windows.go`. Additionally, thread an actual `dir` parameter through `ziplegacy.extractor.Extract` → `archives.ExtractZipArchive(zr, dir)` so containment does not depend on incidental CWD state, and have `extractZipFile` join `dir` with the cleaned relative name.

### Proof of Concept
Go unit test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpJobA := t.TempDir()
    // sibling dir representing another job's workspace
    tmpParent := filepath.Dir(tmpJobA)
    outside := filepath.Join(tmpParent, "jobB-secret")

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    // entry name traverses out of tmpJobA
    rel, _ := filepath.Rel(tmpJobA, outside)
    w, _ := zw.Create(rel) // e.g. "../jobB-secret"
    _, _ = w.Write([]byte("pwned"))
    _ = zw.Close()

    wd, _ := os.Getwd()
    _ = os.Chdir(tmpJobA)
    defer os.Chdir(wd)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert file was NOT written outside tmpJobA
    _, statErr := os.Stat(outside)
    assert.True(t, os.IsNotExist(statErr), "file escaped intended extraction root: %s", outside)
}
```
Expected current (buggy) behavior: `outside` file exists with content `"pwned"`, proving escape from the intended `tmpJobA` root — the assertion fails, demonstrating the vulnerability. A parallel test can add a `ZipUIDGidFieldType` extra field and assert `os.Lchown` is not invoked on paths outside `tmpJobA`.

```go
func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
```
