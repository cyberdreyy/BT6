### Title
Unbounded growth of `activeRequests` map in Gateway Vault handler enables memory-exhaustion DoS from unauthenticated/external requests - (File: `core/services/gateway/handlers/vault/handler.go`)

### Summary
The gateway-side Vault handler tracks every in-flight user request in an in-memory map `activeRequests` keyed by `req.ID`, with no cap on the number of concurrent entries. Entries are only removed by a time-based sweep (`removeExpiredRequests`) that runs every 5 seconds and evicts requests older than `requestTimeout` (default 30s). Any external caller can create unlimited distinct entries — the only requirement is a unique, ≤200-character request ID — mirroring the reported `activeWorkerIds` bug class: an unprivileged actor can grow a globally-shared collection with no size limit, at no protocol cost, until code that iterates/holds it becomes expensive or the process runs out of memory.

### Finding Description
`HandleJSONRPCUserMessage` validates only that `req.ID` is non-empty and ≤200 characters [1](#0-0) . For `MethodPublicKeyGet` — a method explicitly documented as requiring **no authorization** — a cache miss causes `newActiveRequest` to be called and a new map entry created for every unique request ID supplied by the caller [2](#0-1) . For all other vault methods, `newActiveRequest` is likewise called after authorization succeeds [3](#0-2) , but there is still no limit on how many concurrent requests any single authorized caller (or the aggregate of all callers) may have in flight.

`newActiveRequest` only rejects a request if the exact same `req.ID` already exists; it never checks the total size of `h.activeRequests` before inserting [4](#0-3) . The map is only pruned by `removeExpiredRequests`, invoked on a fixed 5-second ticker, which walks the whole map and evicts entries whose age exceeds `requestTimeout` (default 30s) [5](#0-4) [6](#0-5) .

Because eviction is purely time-based (not count-based), an attacker who submits requests faster than the 30-second timeout / 5-second sweep can drain can keep the map growing indefinitely, exactly analogous to the reported Solidity bug where `activeWorkerIds` grows unbounded because registration has no array-size cap and removal only happens via `deregister`/quorum time rather than a hard limit.

### Impact Explanation
Each entry retains the full request object, a per-node response map, and a callback, and it also triggers a synchronous fan-out to every DON node (`fanOutToVaultNodes` for non-cached methods) [7](#0-6) . Sustained abuse increases the gateway's memory footprint and the number of in-flight node round-trips proportional to the number of unique, still-unexpired request IDs the attacker can generate, which is unbounded on the gateway side. This can degrade gateway/vault-DON performance for all legitimate users, and in the worst case cause out-of-memory conditions on the gateway process — a direct DoS impact class matching the reported analog ("cause gas-grief / OOG errors" translated to "cause memory-grief / OOM on the internet-facing gateway").

### Likelihood Explanation
The `MethodPublicKeyGet` path is reachable with zero authorization until the public key response is first cached, and thereafter is mitigated by caching — narrowing but not eliminating the exposure window (e.g., at gateway startup or if the cache is ever invalidated/never populated). For all other vault methods, an attacker only needs a single valid authorization (e.g., one allow-listed workflow owner or one valid JWT) to submit an effectively unlimited number of concurrently-tracked requests with distinct IDs, since there is no per-owner or global cap on `len(h.activeRequests)`.

### Recommendation
Enforce an explicit upper bound on `len(h.activeRequests)` (and optionally a per-caller/per-owner sub-limit), rejecting new requests once the limit is reached, similar to the `MaxSavedCallbacks`-based eviction already implemented in the capabilities gateway handler's `savedCallbacks` map [8](#0-7) . Consider shortening the cleanup interval relative to `requestTimeout` or adding count-based eviction (oldest-first) in `removeExpiredRequests`.

### Proof of Concept
1. Do not populate/cache the vault public key (or catch the gateway at startup before the periodic `fetchVaultPublicKey` warms the cache).
2. Send a burst of `HandleJSONRPCUserMessage` calls with method `vaulttypes.MethodPublicKeyGet` and unique `req.ID`s (each ≤200 chars) faster than the 5-second prune tick / 30-second timeout.
3. Each call inserts a new entry into `h.activeRequests` via `newActiveRequest` without any check on total map size [4](#0-3) , and each triggers a fan-out request to all DON nodes.
4. Repeat indefinitely; `activeRequests` grows without bound between prune cycles, consuming gateway memory and DON node bandwidth.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}
