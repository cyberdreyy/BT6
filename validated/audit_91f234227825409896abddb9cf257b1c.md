### Title
Vesting `distribute()` reverts entirely for all shareholders when any single beneficiary opts out of direct coin transfers - ([File: aptos-move/framework/aptos-framework/sources/vesting.move])

### Summary
`vesting::distribute` withdraws all currently-withdrawable stake from the vesting contract's stake pool in one transaction and then iterates over every shareholder, unconditionally calling `aptos_account::deposit_coins` to push their share to them (or their beneficiary). `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is unregistered for `AptosCoin` and has disabled direct transfers via `set_allow_direct_coin_transfers(false)`. Since the loop over shareholders is inside a single atomic transaction with no isolation or skip-on-failure logic, one unprivileged shareholder/beneficiary disabling direct transfers on their own account permanently blocks `distribute()` for the entire vesting contract — locking every other shareholder's vested funds — directly analogous to the reported MultiStrategyVault issue where one paused strategy blocks withdrawal of all funds.

### Finding Description [1](#0-0) 

`distribute()` calls `withdraw_stake` to pull all withdrawable coins out of the underlying `staking_contract`/stake pool into a single `Coin<AptosCoin>` object, then loops `shareholders.for_each_ref` to split and deposit a proportional share to each shareholder's (or their beneficiary's) address via `aptos_account::deposit_coins`.

`aptos_account::deposit_coins` behavior: [2](#0-1) 

If `to` is not already registered for `CoinType` and `can_receive_direct_coin_transfers(to)` returns false (the account owner explicitly called `set_allow_direct_coin_transfers(false)`), the call aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. This is a legitimate, fully unprivileged self-service configuration any account holder can set on their own account, and is independent of the vesting admin.

Because the shareholder loop in `distribute()` has no per-recipient error handling (Move transactions are all-or-nothing, and there is no `try`/skip mechanism), a single such unregistered-and-opted-out shareholder or beneficiary causes the whole `distribute()` transaction to abort every time it is invoked — for as long as that account remains unregistered and opted out. Since `distribute()` is `public entry` and callable by anyone (staker, admin, or any third party) for any contract address, but its success/failure is entirely gated on every shareholder's coin-acceptance state, the other shareholders cannot extract their already-unlocked/withdrawable vested stake or rewards from the shared vesting contract.

This mirrors the reported bug class exactly: a single unprivileged party's local/legitimate state (a "paused" recipient) blocks a shared multi-party withdrawal path with no mechanism to exclude that party and let others withdraw.

### Impact Explanation
This permanently strands vested stake and rewards for all shareholders of a multi-shareholder `VestingContract` whenever any one shareholder (or a beneficiary assigned by the admin via `set_beneficiary`) is unregistered for `AptosCoin` and opts out of direct transfers. Given `vesting.move` explicitly supports up to `MAXIMUM_SHAREHOLDERS = 30` shareholders per contract (grant pools created via `vesting::create_vesting_contract`), this can freeze the withdrawal path for the entire pool, not just the affected party — a permanent lock/non-recoverable loss of claim rights on vested balances until governance/framework intervention, matching the "Stake And Lockup Gate" criteria (permanent lock of claim rights across shared vesting flows).

### Likelihood Explanation
Reachable entirely with unprivileged actions: any shareholder can call the standard framework function to disable direct coin transfers on their own account (and simply never call `coin::register<AptosCoin>`), which is a normal, legitimate self-custody action, not an attack requiring special privileges. It could also occur accidentally (e.g. a shareholder disables direct transfers for unrelated reasons, or a beneficiary account was never registered for APT). No cooperation from the vesting admin, operator, or other shareholders is needed to trigger the freeze, and there is no existing mitigation (no retry-skipping, no per-shareholder pull-based claim as fallback).

### Recommendation
Change `distribute()` (and `admin_withdraw`) to a pull-based/fault-tolerant model:
- Wrap each `aptos_account::deposit_coins` call so a failure for one shareholder does not abort the whole loop (e.g., check `coin::is_account_registered` / `can_receive_direct_coin_transfers` first and, if the recipient cannot accept, hold their share in an escrow/claimable balance under the vesting contract instead of aborting), or
- Provide a separate `claim`-style entry function so each shareholder/beneficiary withdraws their own share individually, removing the shared atomicity that lets one recipient block all others.

### Proof of Concept
1. Admin creates a `VestingContract` with shareholders A, B, C via `vesting::create_vesting_contract`. [3](#0-2) 
2. Shareholder C (unprivileged) calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own account and never calls `coin::register<AptosCoin>`.
3. Time passes; stake vests and lockup expires so funds become withdrawable in the stake pool.
4. Anyone calls `vesting::distribute(contract_address)`.
   - `withdraw_stake` pulls the withdrawable coins out of the stake pool.
   - The `shareholders.for_each_ref` loop reaches shareholder C and calls `aptos_account::deposit_coins(C, share)`.
   - Because C is unregistered and opted out, this call aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. [4](#0-3) 
5. The entire transaction reverts (Move atomicity), so shareholders A and B receive nothing even though their shares would have succeeded, and this repeats on every subsequent call to `distribute()` until C either registers for `AptosCoin` or re-enables direct transfers — actions outside A's and B's control.

```text
    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }
```
