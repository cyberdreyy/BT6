### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing a request to execute below the required number of live-member approvals - ([File: multisig2/src/lib.rs])

### Summary
`multisig2/src/lib.rs`'s `delete_member` only purges requests that were *originated* by the removed member, but never scrubs that member's *confirmations* cast on other, still-pending requests. `confirm` then counts `confirmations.len()` (a raw string set) against `num_confirmations` without checking that every recorded confirmer is still a current member. This lets a request execute with fewer live-member approvals than `num_confirmations` requires, breaking the multisig's core authorization invariant.

### Finding Description
`confirm` decides whether to execute a request purely by comparing the size of the stored `confirmations: HashSet<String>` to `self.num_confirmations`: [1](#0-0) 

`delete_member` removes the member from `self.members` and deletes only the requests that member *created* (`r.member == member`), plus resets `num_requests_pk` for that member. It never touches `self.confirmations` entries for requests created by *other* members that this member had previously confirmed: [2](#0-1) 

`assert_valid_request`/`confirm` only validates that the *caller* confirming right now is a current member (via `current_member()`), never re-validating the members already recorded in the stored `confirmations` set: [1](#0-0) [3](#0-2) 

This breaks the intended equality: `confirmations.len() == number of distinct *live* members who confirmed`. After a member is removed, its stale confirmation string remains in any request it had confirmed but did not create, and continues to count toward the threshold as if it were a live approver.

### Impact Explanation
This is a Critical-severity authorization-threshold bypass: a multisig configured for `k`-of-`n` approval can execute an action (e.g. `Transfer`, `AddKey`, `DeployContract`, `FunctionCall`) with fewer than `k` currently-authorized approvers, because one of the "approvals" belongs to an account/key that has since been removed from the multisig. This matches the in-scope Critical impact "a multisig request executed below threshold."

### Likelihood Explanation
This requires no privileged access beyond being an ordinary multisig member — it is triggered purely by the normal, documented sequence of confirming a request and later removing a member via `DeleteMember`, both of which are standard multisig operations reachable by any member with the right key/account. No malicious deployment, redeploy, or foundation/owner intervention is needed; it is an intrinsic bug in the bookkeeping of `confirm`/`delete_member`.

### Recommendation
When a member is deleted, iterate `self.confirmations` for *all* active requests (not just ones the member created) and remove the deleted member's entry from each confirmation set. Alternatively, when counting confirmations in `confirm`, filter `confirmations` to only those entries that are still contained in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. `A.add_request_and_confirm(R)` where `R` is a `Transfer` request — `confirmations[R] = {A}`.
3. `B.confirm(R)` — `confirmations[R] = {A, B}` (2 < 3, not yet executed).
4. Members `A, C, D` submit and confirm a separate `DeleteMember { member: B }` request (3 confirmations reached, executes) — `B` is removed from `self.members`; per `delete_member` (multisig2/src/lib.rs:355-379) only requests *created* by `B` are purged, so `confirmations[R]` still contains `B`'s entry.
5. `C.confirm(R)` — now `confirmations[R].len() + 1 == 3 >= num_confirmations`, so `execute_request(R)` runs and the transfer is executed, even though only `A` and `C` are still live members who actually approved it (2 live approvals vs. the required 3), with `B`'s stale, post-removal confirmation making up the difference.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
