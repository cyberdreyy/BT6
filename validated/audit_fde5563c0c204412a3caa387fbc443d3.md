### Title
Stale confirmations from deleted multisig members are still counted toward `num_confirmations`, allowing execution below threshold - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` removes a departing member from `self.members` and cleans up only the requests *that member itself created* (`request_ids` filtered by `r.member == member`), but never removes that member's confirmations recorded on requests created by *other* members. `confirm()` blindly trusts the size of the stored `confirmations` set against `num_confirmations`, so a confirmation cast by a member who has since been removed continues to count toward the threshold.

### Finding Description
The binding that should hold is: `confirmations counted for request R == confirmations from members who are members at the time R is executed`. This binding is broken because of an incomplete cleanup path.

In `delete_member` [3](#0-2) :
```
let request_ids: Vec<u32> = self
    .requests
    .iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
```
This filter matches on `r.member`, i.e. the member who *added* the request (`MultiSigRequestWithSigner.member`, set in `add_request` [4](#0-3) ). It has no relationship to who has *confirmed* a given request. Confirmations are tracked in a separate `confirmations: LookupMap<RequestId, HashSet<String>>` keyed independently by `request_id`, populated by any member who calls `confirm()` — including on requests they did not create.

Consequently, if member A confirms a request R that was created by member B, and A is later removed via `DeleteMember`, R's confirmation set (containing A's serialized identity) is untouched — because R's creator is B, not A, so R is not in `delete_member`'s filtered `request_ids`. A's stale confirmation remains in `self.confirmations.get(&R)`.

When subsequent live members confirm R, `confirm()` at [5](#0-4)  does `confirmations.len() as u32 + 1 >= self.num_confirmations` — it never checks that each pre-existing entry in the set is still `self.members.contains(...)`. The stale entry from the removed A is counted exactly the same as a valid, live confirmation.

### Impact Explanation
This lets a request execute (e.g. `Transfer`, `AddKey`/full-access-key grant, `FunctionCall`, `DeleteMember`, `AddMember`) with fewer *live* member confirmations than `num_confirmations` requires. For example, with `num_confirmations = 3` and 4 members {A, B, C, D}: A creates request R; B confirms R (2/3); A is compromised and removed via a separate, properly-confirmed `DeleteMember` request (this cleans requests created by A, but R was created by A itself — actually to demonstrate the more general case, consider member A confirms a request R created by B, then A is deleted, then C confirms R: 2 stored confirmations (A stale + C) reach the 3-confirmation-equivalent bar with only 2 truly live confirmers (B/creator + C), letting the multisig execute a transfer or key-management action with fewer live signers than the configured threshold — a critical violation of the k-of-n custody guarantee (funds moved, or a full-access key added, by fewer than k live parties).

### Likelihood Explanation
No privileged access is required beyond normal, legitimate multisig operation: any member confirming a request before being removed, followed by a routine, properly-authorized `DeleteMember` action (which itself doesn't scan for the departing member's confirmations elsewhere), reaches this state. It does not require compromising the removed member's key after removal — the confirmation was already legitimately cast while they were a member; the bug is that the record isn't invalidated when membership ends. This is a normal churn scenario (member offboarding) rather than a contrived attack path, making it fairly likely to occur in practice.

### Recommendation
When deleting a member, scan `self.confirmations` for *all* request IDs (not just ones the member created) that contain the departing member's identity string and remove that entry from each confirmation set (not necessarily removing the whole request). Alternatively, at `confirm()` execution time, filter the stored confirmation set down to entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. B calls `add_request` to create transfer request `R`.
3. A calls `confirm(R)` → `confirmations[R] = {A}` (1/3).
4. Via a separate, fully-confirmed `DeleteMember { member: A }` request, A is removed. `delete_member` only inspects requests where `r.member == A` (requests *created* by A) — `R` was created by B, so its confirmation set `{A}` is left untouched.
5. C calls `confirm(R)` → `confirmations[R] = {A, C}`, size 2, `2 + 1 >= 3` → request executes.
6. `R` (e.g., a `Transfer` or `AddKey` with full access) executes with only B (creator, implicitly trusted by system design) and C as live confirmers, plus a stale confirmation from removed member A — one fewer live confirmation than the configured `num_confirmations = 3` threshold.     pub fn add_request(&mut self, request: MultiSigRequest) -> RequestId {
        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(
                "Predecessor must be a member or transaction signed with key of given account",
            )
        });
        // track how many requests this key has made
        let num_requests = self
            .num_requests_pk
            .get(&current_member.to_string())
            .unwrap_or(0)
            + 1;
        assert(
            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
