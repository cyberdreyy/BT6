### Title
Unbounded per-mint bank lookups in `get_parsed_token_accounts` allow single-call RPC resource exhaustion via getTokenAccountsByOwner - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`get_parsed_token_accounts` (rpc/src/parsed_token_accounts.rs:52-88) caches parsed mint metadata in a per-call `HashMap<Pubkey, AccountAdditionalDataV3>` with no size limit and no cap on how many distinct mints it will resolve. Because the map is keyed by mint, an attacker who owns N token accounts spread across N distinct self-created mints forces N separate `bank.get_account` + SPL `Mint` unpack calls (via `get_mint_owner_and_additional_data`, parsed_token_accounts.rs:92-108) inside a single `getTokenAccountsByOwner` request with `jsonParsed` encoding.

### Finding Description
`RpcSol::get_token_accounts_by_owner` in `rpc/src/rpc.rs` fetches all token accounts owned by the requested pubkey and, for `UiAccountEncoding::JsonParsed`, feeds them through `get_parsed_token_accounts`. That function iterates the keyed accounts and, for each account, extracts the mint via `get_token_account_mint` and looks it up in the local `mint_data` map: [1](#0-0) 

On a cache miss it calls `get_mint_owner_and_additional_data`, which performs `bank.get_account(mint)` followed by `StateWithExtensions::<Mint>::unpack` in `get_additional_mint_data`: [2](#0-1) [3](#0-2) 

Because the `mint_data` map is created fresh per call (line 59) and is only populated (never pre-sized, never capped, never evicted), the number of bank lookups/unpacks scales linearly with the number of *distinct mints* among the accounts returned for the queried owner - which is entirely attacker-controlled since the attacker creates both the token accounts and the mints. There is no per-request cap on the number of distinct mints resolved, and no size limit is enforced before entering this loop for the `jsonParsed` encoding path.

### Impact Explanation
This is a resource-exhaustion condition scoped to the JSON-RPC service: a single unprivileged `getTokenAccountsByOwner` call with `jsonParsed` encoding can force an arbitrary (attacker-chosen) number of extra bank account lookups and SPL mint unpack/allocation operations on the node handling the request, increasing CPU and memory usage in proportion to attacker-created state rather than to any fixed per-request bound. This matches the "non-RPC remote resource exhaustion / RPC crashes" impact category — a sufficiently large N can cause elevated latency or resource pressure on the RPC service for that single call.

### Likelihood Explanation
Feasibility depends entirely on the attacker being willing to pre-fund and pre-create N token accounts and N SPL mints (rent cost only, no self-harm), which is achievable by any unprivileged actor with enough SOL (or trivially on devnet/testnet with airdrops). The exploit requires exactly one RPC call once the accounts exist, so it is not excluded by the "requires repeated calls / unfiltered scan" rule — the call is filtered to a single owner, and the amplification comes from the number of distinct mints under that owner's accounts, which is fully attacker-controlled. However, the severity is bounded by how many accounts the attacker is willing/able to pay rent for, and by any external RPC rate-limiting/timeout enforced by node operators (not present in this code path).

### Recommendation
Bound the work done per `getTokenAccountsByOwner`/`getTokenAccountsByDelegate` (jsonParsed) call — e.g., enforce a maximum number of returned accounts (or distinct mints resolved) before falling back to a non-parsed encoding or returning an RPC error, similar to existing caps used elsewhere in `rpc.rs` (e.g., `MAX_MULTIPLE_ACCOUNTS`/`MAX_GET_PROGRAM_ACCOUNT_FILTERS`); alternatively short-circuit and return an error once `mint_data.len()` exceeds a fixed threshold within `get_parsed_token_accounts`.

```rust
#[test]
fn test_unbounded_mint_lookups() {
    let bank = Arc::new(create_test_bank());
    let owner = Pubkey::new_unique();
    const N: usize = 50_000;

    let mut keyed_accounts = Vec::with_capacity(N);
    for _ in 0..N {
        let mint = Pubkey::new_unique();
        // create + store a valid mint account in `bank` for `mint`
        create_and_store_mint_account(&bank, &mint);
        let token_account_pubkey = Pubkey::new_unique();
        let token_account = build_token_account(owner, mint); // AccountSharedData
        keyed_accounts.push((token_account_pubkey, token_account));
    }

    let start = std::time::Instant::now();
    let results: Vec<_> = get_parsed_token_accounts(bank.clone(), keyed_accounts.into_iter()).collect();
    let elapsed = start.elapsed();

    assert_eq!(results.len(), N);
    // No cap exists today: this call performs N separate bank.get_account + Mint::unpack
    // operations. Assert a cap should exist, e.g.:
    // assert!(N <= MAX_DISTINCT_MINTS_PER_REQUEST);
    println!("elapsed for {N} distinct mints: {:?}", elapsed);
}
```
Expected observation: wall-clock time and allocation count scale linearly with N with no request-level cap, confirming the absence of any bound on `mint_data` growth in `get_parsed_token_accounts`.

```rust
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}
```

```rust
fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
```
