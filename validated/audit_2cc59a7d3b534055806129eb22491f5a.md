### Title
Donation into the programmable borrower's ERC4626 vault mints phantom epoch interest, extracting real funds from vault co-depositors through the CDO stopEpoch flow - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` computes epoch interest from the raw `convertToAssets` valuation of its ERC4626 share position (`_vaultNetInterest`, `totalInterestDueNow`). There is no share-supply normalization, no cap on per-epoch yield, and no isolation of donated assets inside the external vault. A direct token sender / ordinary vault depositor can inflate the vault's share price with a donation, fabricating "vault interest" that `IdleCDOEpochVariant._stopEpoch` then treats as real, payable epoch interest.

### Finding Description
The external advisory's bug class is "a crafted repository makes a privileged component execute attacker-influenced payloads" — here the analog is a crafted ERC4626 state making a trusted hook (`onStopEpoch` / `totalInterestDueNow`) emit attacker-influenced interest:

- `_vaultNetInterest` computes `netDelta = bufferedVaultDelta + _currentVaultAssets() + epochWithdrawnFromVault - epochStartVaultAssets - epochDepositedToVault`, where `_currentVaultAssets() = vault.convertToAssets(vault.balanceOf(this))` (`ProgrammableBorrower.sol:337-349, 545-549`).
- `totalInterestDueNow()` adds this phantom interest to the borrower-facing amount (`ProgrammableBorrower.sol:330-334`).
- `IdleCDOEpochVariant._stopEpoch` resolves `_interest = IProgrammableBorrower(_borrower()).totalInterestDueNow()`, then calls `onStopEpoch` which executes `vault.withdraw(shortfall, address(this), address(this))` to cover the inflated amount, and finally `getFundsFromBorrower` pulls those assets into the CDO (`IdleCDOEpochVariant.sol:395-410`, `ProgrammableBorrower.sol:239-253`). In minted mode the CDO additionally calls `_strategy.mintStrategyTokens(_grossInterest)`, minting strategy tokens backed by the fabricated yield (`IdleCDOEpochVariant.sol:428-433`).

The only donation guard, `_skimDonatedAssets`, applies to raw underlying sitting on the IdleCDO contract; it cannot see value donated *inside* the external ERC4626.

### Impact Explanation
An attacker holding tranche tokens (a permitted, KYC-passing LP) deposits into the same ERC4626 vault, donates `D` underlying to it, and lets the epoch stop:

- If the attacker holds a small fraction `f` of vault shares and a large fraction `p` of the tranche pool, the donation raises PB's share value by `(1-f)·D`, while `totalInterestDueNow` credits the full `D` as interest (baseline is per-share: the delta equals the total price move on PB's shares, i.e. `(1-f)D`, so credited interest is `(1-f)D`; the attacker recovers `f·D` by redeeming their own vault shares). Pool receives `(1-f)·D` in real assets pulled from the vault — assets economically belonging to *all* vault shareholders — and distributes it to tranche holders. The attacker's net position: `−D (donation) + f·D (redeem) + p·(1−f)·D (tranche yield)`, i.e. profit `≈ (p − f)·D`, stolen from the other ERC4626 depositors whose share value was partially siphoned through PB into pool yield. In minted-interest mode the same path mints `D`-backed strategy tokens whose underlying is only partially funded, silently diluting honest tranche holders when the phantom backing fails to materialize — an insolvency vector quantified by `D − (1−f)D` shortfall per stop.
- A cheaper variant: the attacker donates during the *buffer* period; `bufferedVaultDelta` captures `currentVaultAssets − bufferStartVaultAssets` at `onStartEpoch` (`ProgrammableBorrower.sol:206-210`) and carries the phantom gain into the next epoch's `totalInterestDueNow`.

### Likelihood Explanation
Requires only: a pool configured with `isProgrammableBorrower`, an ERC4626 vault with outside depositors (the design's stated purpose — "keep undrawn capital parked inside an ERC4626 vault"), and an attacker who is simultaneously a vault depositor and tranche holder. No privileged role involved; `onStartEpoch`/`onStopEpoch`/`totalInterestDueNow` are called unconditionally by the honest manager every epoch. Profit is bounded by `(p−f)·D`, so the attack pays off whenever the attacker's tranche share exceeds their vault share — realistic when the vault is large relative to the pool.

### Recommendation
Account for vault PnL using internal share-based bookkeeping rather than raw `convertToAssets` deltas: snapshot `shares` and an initial share-price baseline, cap credited vault interest by an APR bound (`principal × maxApr × elapsed / YEAR`), or use a TWAP/historical share price. Alternatively deduct externally-attributable deposits/donations via `previewRedeem`-style checks, and treat abrupt `convertToAssets` jumps above a threshold as suspect at `onStartEpoch`/`onStopEpoch`.

### Proof of Concept
```solidity
// test/foundry/DonationInflatedVaultInterest.t.sol
// Fork-style setup mirroring ProgrammableBorrowerCreditVault.t.sol:
// pool with programmable borrower, minted or cash interest mode, attacker is AA holder.

function testDonationInflatesEpochInterest() external {
    uint256 poolDeposit = 1_000_000e6;
    uint256 donation    = 50_000e6;

    // Attacker takes a small position in the external ERC4626 vault
    underlying.mint(attacker, 10_000e6 + donation);
    vm.startPrank(attacker);
    underlying.approve(address(vault), type(uint256).max);
    vault.deposit(10_000e6, attacker);          // f << 1
    vm.stopPrank();

    idleCDO.depositAA(poolDeposit);             // attacker also holds most tranches
    vm.prank(manager); cdoEpoch.startEpoch();

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Donation: inflates convertToAssets for PB's shares -> phantom vaultInterestAccrued
    vm.prank(attacker);
    underlying.transfer(address(vault), donation);

    uint256 phantom = programmableBorrower.vaultInterestAccrued();
    uint256 due     = programmableBorrower.totalInterestDueNow();
    assertGt(phantom, 0);
    assertApproxEqAbs(due, phantom + borrowerInterest, 1);

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    // Pool pulled ~donation*(1-f) in real assets funded by other vault depositors,
    // and/or minted strategy tokens backed by fabricated yield.
    assertApproxEqAbs(cdoEpoch.lastEpochInterest(), phantom, 1);
}
```
