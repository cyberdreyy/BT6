### Title
Queued dust deposits can temporarily block prefunded epoch settlement - (File: `contracts/IdleCDOEpochQueue.sol`)

### Summary
An unprivileged, KYC-approved lender can queue a minimal AA deposit immediately before the prefunding cutoff. After the cutoff, `processDepositsToBorrower()` refuses to move the queued deposit, while `stopEpochWithDuration()` refuses to settle the epoch because raw pending deposits still exist. The result is a temporary epoch freeze until the owner or manager disables/replaces the configured queue or the attacker voluntarily deletes the request.

### Finding Description
`requestDeposit()` accepts AA queue deposits only while `block.timestamp + prefundedDepositWindow < epochEndDate`, and records the contribution in `epochPendingDeposits[nextEpoch]`. [1](#0-0) 

`processDepositsToBorrower()` uses the same cutoff to move pending queue deposits to the borrower and convert them into `epochPrefundedDeposits`. Once `block.timestamp + prefundedDepositWindow >= epochEndDate`, it reverts. [2](#0-1) 

During settlement, `IdleCDOEpochVariantPrefunded._afterStopEpochWithDuration()` unconditionally queries `prefundedDepositsToProcess()` when `epochQueue` is configured. [3](#0-2) 

That query reverts whenever the target epoch still has any nonzero `epochPendingDeposits`. [4](#0-3) 

Only the depositor can delete an unprocessed deposit request; owner and manager have no function that clears or refunds another user’s `userDepositsEpochs` entry. [5](#0-4) 

Thus, an attacker can submit a 1-wei deposit in the last block before the cutoff. If no manager transaction processes it in that same block, all later processing attempts are cutoff-blocked and every later `stopEpochWithDuration()` attempt reverts.

### Impact Explanation
The affected epoch cannot complete through the normal prefunded settlement path. Borrower repayment, interest accounting, and withdrawals remain temporarily frozen while `epochQueue` points to the blocked queue.

The freeze covers the vault’s outstanding strategy-token principal and epoch interest. It is temporary rather than permanent because the owner or manager can call `setEpochQueue(address(0))` when no prefunded deposits have already been sent to the borrower, after which the attacker’s queue-held deposit can be deleted or refunded independently. No borrower default is required.

### Likelihood Explanation
Likelihood is moderate:

- The attacker only needs to satisfy `isWalletAllowed`, which is the ordinary KYC lender requirement. [6](#0-5) 
- The attack costs one queued deposit and can use the smallest supported underlying unit.
- It requires submitting near the cutoff before the manager processes the queue.
- A manager transaction in the same pre-cutoff block can neutralize that particular attempt.
- Recovery requires a privileged operational change, so the freeze is not permanent under the stated honest-owner assumption.

### Recommendation
Separate the deposit-acceptance cutoff from the operator-processing cutoff. `requestDeposit()` should stop accepting deposits sufficiently before the last timestamp at which `processDepositsToBorrower()` remains callable, or the latter should remain callable up to `epochEndDate`.

Alternatively, add an owner/manager emergency cancellation path for queue-held, non-prefunded deposits that refunds `userDepositsEpochs` and decrements `epochPendingDeposits`. Any such path must reject epochs that already have `epochPrefundedDeposits` or `epochPrice` set.

### Proof of Concept
The following regression test can be added to `test/foundry/IdleCDOEpochVariantPrefunded.t.sol`, using the existing prefunded fixture:

```solidity
function testQueuedDustDepositBlocksEpochSettlementAfterCutoff() external {
    uint256 dust = 1;
    address attacker = makeAddr("attacker");

    vm.prank(manager);
    cdoEpoch.setEpochQueue(address(queue));

    vm.prank(manager);
    queue.setPrefundedDepositWindow(PREFUNDED_DEPOSIT_WINDOW);

    uint256 requestEpoch = strategy.epochNumber() + 1;

    // Last valid queue-deposit timestamp: still strictly before the cutoff.
    vm.warp(cdoEpoch.epochEndDate() - PREFUNDED_DEPOSIT_WINDOW - 1);
    _requestDepositWithUser(attacker, dust);

    // Move to the cutoff. New deposits and prefunding are now rejected.
    vm.warp(cdoEpoch.epochEndDate() - PREFUNDED_DEPOSIT_WINDOW);

    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    queue.processDepositsToBorrower();

    // Give the borrower enough approved liquidity for the normal settlement.
    uint256 toRepay =
        cdoEpoch.expectedEpochInterest() +
        strategy.pendingWithdraws();
    deal(address(underlying), strategy.borrower(), toRepay);
    vm.prank(strategy.borrower());
    underlying.approve(address(cdoEpoch), toRepay);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(
        cdoEpoch.lastEpochApr(),
        0,
        cdoEpoch.epochDuration(),
        0
    );

    assertTrue(cdoEpoch.isEpochRunning(), "epoch was not frozen");
    assertEq(
        queue.epochPendingDeposits(requestEpoch),
        dust,
        "dust deposit was unexpectedly processed"
    );
}
```

  function _afterStopEpochWithDuration() internal override {
    address _queue = epochQueue;
    if (_queue == address(0)) return;

    IIdleCDOEpochQueuePrefunded _epochQueue = IIdleCDOEpochQueuePrefunded(_queue);
    uint256 _prefunded = _epochQueue.prefundedDepositsToProcess();
    if (_prefunded == 0) return;
    // A zero post-loss AA price cannot safely mint new shares into the same tranche token.
    _checkNotAllowed(priceAA == 0);

    // Prefunded deposits already reached the borrower, so they must join AA even if stop defaulted.
    // Mint tranche shares at the post-stop price and mirror the same amount in strategy tokens,
    // so the queue can later distribute shares to users at the epoch price.
    uint256 _prefundedMinted = _mintSharesAtCurrPrice(_prefunded, _queue, AATranche);
    IdleCreditVault(strategy).mintStrategyTokens(_prefunded);
    // Finalize the prefunded epoch in the queue by storing the epoch price and clearing state.
    _epochQueue.processPrefundedDeposits(_prefundedMinted);
