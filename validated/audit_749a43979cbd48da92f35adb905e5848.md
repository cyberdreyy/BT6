### Title
Rewards emitted while `_totalSupply == 0` are stranded in `StakingRewards` — `depositReward` does not revert on empty staking supply - (File: contracts/StakingRewards.sol)

### Summary
`StakingRewards` (the tranche-token staking rewards contract that `IdleCDO` funds via `depositReward`, replacing Synthetix's `notifyRewardAmount`) uses the classic MasterChef/Synthetix snapshot pattern. When `_totalSupply == 0`, `rewardPerToken()` returns `rewardPerTokenStored` unchanged, but the `updateReward` modifier still advances `lastUpdateTime` to `lastTimeRewardApplicable()`. Every second the stream runs with zero stakers permanently skips that slice of the emission — it is never accrued to anyone and sits unclaimable in the contract until the owner rescues it via `recoverERC20`.

### Finding Description [1](#0-0)  shows `rewardPerToken()` short-circuiting to the stored value when `_totalSupply == 0`. [2](#0-1)  shows `updateReward` unconditionally setting `lastUpdateTime = lastTimeRewardApplicable()`, discarding the elapsed interval instead of carrying it forward. [3](#0-2)  shows `depositReward` setting `rewardRate = reward / rewardsDuration` and `periodFinish = block.timestamp + rewardsDuration` with no `_totalSupply > 0` check, and it is callable by the honest `rewardsDistribution` (the `IdleCDO`) at any time, including before the first `stake`. `recoverERC20` ( [4](#0-3) ) only blocks recovering the staking token, so stranded `rewardsToken` is recoverable by the owner — making this temporary freezing/unclaimable yield rather than permanent loss, but the `rewardRate` already burned into `periodFinish` still short-changes stakers who arrive later. `DelegateStakingRewardsIDLE.sol` ( [5](#0-4) ) contains the identical pattern.

### Impact Explanation
Any reward emission queued while no tranche tokens are staked is partially or fully forfeited by legitimate stakers: if `depositReward` lands `T` seconds before the first stake, `rewardRate * T` worth of reward tokens vest to nobody. Up to the entire `reward` amount (default `rewardsDuration = 1 days`, so a full day of emissions) can be burned relative to the intended distribution. Broken invariant: fair reward distribution — tokens are debited from the funder but credited to no beneficiary.

### Likelihood Explanation
High at initialization: rewards are routinely deposited when the staking contract is fresh and `_totalSupply == 0` (the exact "queued before first deposit" condition from the source report). It recurs whenever the last staker exits mid-period — an unprivileged staker's `withdraw` can push `_totalSupply` to 0, after which all remaining emission is silently dropped. No attacker is required, and no privileged misbehavior is needed; existing guards (`onlyRewardsDistribution`, `nonReentrant`, `whenNotPaused`) do not address supply.

### Recommendation
Revert in `depositReward` when `_totalSupply == 0` (mirroring the recommended `require(totalSupply() > 0)`), or — to avoid breaking reward top-ups before staking opens — leave `lastUpdateTime` frozen (or roll `periodFinish` forward) while supply is zero so the unaccrued interval is not consumed. Apply the same fix to `DelegateStakingRewardsIDLE.depositReward`.

### Proof of Concept
Foundry PoC (place in `test/foundry/`; requires mainnet state only for real tokens — two `ERC20` mocks suffice, so no fork needed, or fork mainnet and use real IDLE/tranche tokens):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;
import "forge-std/Test.sol";
import {StakingRewards} from "../../contracts/StakingRewards.sol";
import {ERC20Mock} from "../mocks/ERC20Mock.sol"; // any mintable ERC20 mock

contract ZeroSupplyRewardsTest is Test {
    StakingRewards sr;
    ERC20Mock rewardsToken;
    ERC20Mock stakingToken;
    address rewardsDistribution = address(0xCD0); // stand-in for IdleCDO
    address alice = address(0xA11CE);

    function setUp() public {
        rewardsToken = new ERC20Mock();
        stakingToken = new ERC20Mock();
        sr = new StakingRewards();
        sr.initialize(rewardsDistribution, address(rewardsToken), address(stakingToken), address(this), true);

        stakingToken.mint(alice, 100e18);
        rewardsToken.mint(rewardsDistribution, 1_000e18);
        vm.prank(rewardsDistribution);
        rewardsToken.approve(address(sr), type(uint256).max);
    }

    function testRewardsLostWhileSupplyIsZero() public {
        // Rewards queued before ANYONE stakes -> totalSupply == 0
        vm.prank(rewardsDistribution);
        sr.depositReward(address(0), 1_000e18);

        // Half the rewardsDuration elapses with zero stakers
        vm.warp(block.timestamp + 12 hours);

        // Alice stakes; her userRewardPerTokenPaid snapshots the (unchanged) stored value,
        // but lastUpdateTime was already advanced past the empty interval.
        vm.startPrank(alice);
        stakingToken.approve(address(sr), 100e18);
        sr.stake(100e18);
        vm.stopPrank();

        // Remaining half period accrues normally
        vm.warp(block.timestamp + 12 hours + 1);

        uint256 earned = sr.earned(alice);
        // ~500e18 was emitted into nothing and is unclaimable
        assertLt(earned, 600e18);
        assertGt(1_000e18 - earned, 400e18);

        sr.getReward();
        // stranded balance remains in contract, retrievable only via owner recoverERC20
        assertEq(rewardsToken.balanceOf(address(sr)), 1_000e18 - earned);
    }
}
```

Note: the stranded tokens are recoverable by the honest owner via `recoverERC20`, so the practical impact is unclaimable/temporarily frozen yield rather than permanent theft — same severity profile as the source finding.

```text
  function depositReward(address, uint256 reward) external onlyRewardsDistribution updateReward(address(0)) {
    if (shouldTransfer) {
      rewardsToken.safeTransferFrom(msg.sender, address(this), reward);
    }

    if (block.timestamp >= periodFinish) {
      rewardRate = reward / rewardsDuration;
    } else {
      uint256 remaining = periodFinish - block.timestamp;
      uint256 leftover = remaining * rewardRate;
      rewardRate = (reward + leftover) / rewardsDuration;
    }

    // Ensure the provided reward amount is not more than the balance in the contract.
    // This keeps the reward rate in the right range, preventing overflows due to
    // very high values of rewardRate in the earned and rewardsPerToken functions;
    // Reward + leftover must be less than 2^256 / 10^18 to avoid overflow.
    uint balance = rewardsToken.balanceOf(address(this));
    require(rewardRate <= balance / rewardsDuration, "Provided reward too high");

    lastUpdateTime = block.timestamp;
    periodFinish = block.timestamp + rewardsDuration;

    emit RewardAdded(reward);
  }
```
