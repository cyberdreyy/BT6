## Analog Found

### Title
Cross-tenant request-ID collision in the HTTP Trigger gateway handler due to a global callback map keyed only by client-supplied `requestID` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The reported Solana bug is a classic "missing discriminator in a shared routing key" bug: the `ResolverConfig` PDA is derived only from `(emitter_chain, emitter_address)` and omits `asset_mint`, so two independent, mutually untrusted bridge instances can collide on the same PDA and hijack/delete each other's routing state. The same bug class exists in chainlink's internet-facing CRE Gateway HTTP trigger path: the pending-callback map that routes DON responses back to the originating unprivileged HTTP caller is keyed **only by the caller-supplied `requestID`**, with no workflow/tenant/owner discriminator baked into the key, unlike the sibling vault gateway handler which explicitly prefixes the ID with the authorized owner to avoid exactly this problem.

### Finding Description
`httpTriggerHandler` stores pending requests in a single process-wide map: [1](#0-0) 

The request ID is fully controlled by the unprivileged HTTP caller and is validated only for emptiness and absence of `/`: [2](#0-1) 

`setupCallback` inserts into this map using the raw `requestID` as the sole key, with no workflowID/workflowOwner component mixed in: [3](#0-2) 

And `HandleNodeTriggerResponse`, which processes DON node responses and delivers them to the waiting HTTP caller, looks the callback up purely by `resp.ID`: [4](#0-3) 

This is structurally identical to the Solana bug: the map/PDA key omits the discriminator (mint / workflow-owner) that should scope the entry to a single tenant. Any unprivileged caller authorized against *their own* workflow (`authorizeRequest` only checks the caller can invoke `workflowID`, not that they "own" the ID namespace) can pick any `requestID` string of their choosing for their own request. If that string collides with an in-flight `requestID` chosen by a different, unrelated workflow/tenant, `setupCallback` returns a `ErrConflict` for whichever request arrives second — meaning an attacker can pre-empt/deny a victim's legitimate request simply by racing to register the same `requestID` first, entirely across tenant/workflow boundaries, with zero relationship to the victim's workflow.

By contrast, the codebase's own vault gateway handler recognizes this exact class of bug and mitigates it by stamping the authorized owner into the ID before any map insertion happens, so that no two distinct owners can ever collide on the same key: [5](#0-4) 

and the more general `requestcache.go` used by other gateway handlers keys explicitly on `{sender, id}` rather than `id` alone: [6](#0-5) 

The HTTP trigger handler does not follow either of these patterns — it is the outlier that reproduces the "shared key missing discriminator" bug class from the report.

### Impact Explanation
Any unauthenticated/unprivileged HTTP caller who can invoke `HandleUserTriggerRequest` for some workflow they are entitled to call can supply an arbitrary `requestID`. Because the callback map is global and not partitioned by workflow/tenant, this allows:
- **Cross-tenant denial of service**: an attacker can squat on a `requestID` (e.g. a commonly-used idempotency-style value) before a legitimate, unrelated caller's request with the same ID arrives, causing the legitimate request to be rejected with `ErrConflict` ("requestID has already been used").
- The severity is bounded by the fact that `setupCallback` rejects rather than silently overwrites an existing entry (unlike the Solana `init_if_needed` overwrite), so full response hijacking is not directly demonstrated here — but the missing per-tenant discriminator is the same root-cause bug class, and it does produce request/response confusion and an unprivileged-actor-triggerable denial of service across tenant boundaries in an internet-facing gateway handler.

### Likelihood Explanation
Exploitation only requires being able to send a normal, authorized HTTP trigger request with a chosen `Id` value — no special privileges, no node compromise, and no dependency on mocked-only code. `requestID` is entirely attacker-controlled and validated only for emptiness/`/` character, so colliding with a target's predictable or observed `requestID` (e.g., from logs, shared conventions, or brute force over a small ID space during a race window) is realistic for an unprivileged actor.

### Recommendation
Scope the `callbacks` map key (and the response lookup key) by tenant, e.g. prefix or combine `requestID` with the authorized `workflowOwner`/`workflowID` (as `authorizeRequest`/`resolveWorkflowID` already resolve before `setupCallback` is called), mirroring the pattern already used in `core/capabilities/vault/gateway_vault_request_processor.go` (`authorizedOwner + Separator + originalRequestID`) and `core/services/gateway/handlers/common/requestcache.go` (`globalId{sender, id}`). This ensures request IDs from different workflows/tenants can never collide in the shared map.

### Proof of Concept
Conceptual PoC (no code execution available in this environment):
1. Attacker (owner A, valid auth for workflow A) sends `HandleUserTriggerRequest` with `req.ID = "shared-id-123"` for workflow A and holds it in-flight (e.g., a workflow with a slow-to-respond shard).
2. Victim (owner B, valid auth for an unrelated workflow B) sends a legitimate request with `req.ID = "shared-id-123"`.
3. `setupCallback` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:402-405`) finds the key already present in the global `h.callbacks` map and returns `jsonrpc.ErrConflict` to the victim, denying their legitimate, unrelated request — despite the two requests belonging to completely different workflows/owners.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// Build one response aggregator per shard the workflow is assigned to.
	assigned := h.workflowMetadataHandler.WorkflowShards(workflowID)
	if len(assigned) == 0 {
		// this shouldn't happen because we checked it in authorizeRequest()
		h.handleUserError(ctx, requestID, jsonrpc.ErrInternal, fmt.Sprintf("Workflow %s is not assigned to any DONs", workflowID), callback)
		return nil, errors.New("workflow is not assigned to any shards")
	}

	aggregators := make(map[string]*aggregation.IdenticalNodeResponseAggregator, len(assigned))
	for _, shard := range assigned {
		// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
		threshold := (len(shard.members)+shard.f)/2 + 1
		agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
		if err != nil {
			return nil, errors.New("failed to create response aggregator: " + err.Error())
		}
		aggregators[shard.donID] = agg
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:            callback,
		requestStartTime:    requestStartTime,
		createdAt:           time.Now(),
		responseAggregators: aggregators,
		doneCh:              doneCh,
	}
	return doneCh, nil

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

type pendingRequest[T any] struct {

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
