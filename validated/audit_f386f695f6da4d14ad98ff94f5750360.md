Confirmed. This is a real, concrete analog of the reported bug class ("confirmations counted versus live members"), reachable in `multisig2/src/lib.rs`'s `delete_member` function.

### Title
Removing a multisig member does not purge that member's confirmations on other members' pending requests, allowing execution below the intended live-member threshold - (File: multisig2/src/lib.rs)

### Summary
`delete_member` only deletes requests **created by** the removed member, but leaves that member's `confirm()` votes cast on requests created by other members intact in the `confirmations` map. `confirm()`'s threshold check counts the size of this `HashSet<String>` regardless of whether every entry corresponds to a current, live member. As a result, a request can execute once `confirmations.len() + 1 >= num_confirmations` even though the actual number of *live* members who confirmed it is strictly less than `num_confirmations`.

### Finding Description
In `multisig2/src/lib.rs`, `delete_member` [1](#0-0)  removes the member from `self.members` and deletes only requests where `r.member == member` (i.e., requests the removed member *authored*):

```rust
let request_ids: Vec<u32> = self.requests.iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
``` [2](#0-1) 

It never scans `self.confirmations` for entries where the removed member's identity string appears as a *confirmer* on requests authored by someone else. Those stale confirmations remain stored under the still-live `request_id`.

`confirm()` then trusts the raw size of the confirmation set as a stand-in for "number of live members who approved":
```rust
let mut confirmations = self.confirmations.get(&request_id).unwrap();
...
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
}
``` [3](#0-2) 

There is no re-validation that every member id in `confirmations` is still contained in `self.members` before counting it. This breaks the intended custody binding: `confirmations counted == confirmations from live members`. After a member is removed, that equality no longer holds for any request the removed member had previously confirmed but did not author.

The same class of gap (member removal not scrubbing that member's confirmation votes cast on other requests) exists in the older `multisig/src/lib.rs` implementation as well, where `DeleteKey` only purges requests whose `signer_pk` (author) matches the removed key [4](#0-3) , leaving `confirmations` entries made by that key on other members' requests untouched.

### Impact Explanation
This matches the "Critical" bucket: "a multisig request executed below threshold." A `Transfer`, `AddKey`, `FunctionCall`, `DeployContract`, etc. can execute with fewer live, currently-authorized signers approving it than `num_confirmations` mandates, because a removed (e.g., compromised or malicious) member's stale vote is still counted toward quorum. This is an authorization-threshold violation: NEAR (or contract control) can move/change under a lower effective bar than configured.

### Likelihood Explanation
This does not require any unprivileged external attacker — it requires only that a member (or previously-legitimate signer who is later removed for cause, e.g. suspected compromise or malice) casts a confirmation on a pending request before being removed. This is a realistic, foreseeable operational sequence (member creates/confirms requests routinely; membership changes happen after compromise/departure), and it directly reduces the effective live-signer threshold with no additional cost or race condition needed once the member is deleted — the stale vote persists indefinitely until the request is separately deleted or executed.

### Recommendation
When a member is removed, iterate `self.confirmations` for all pending `request_id`s and strip the removed member's identity string from each `HashSet`, not merely delete requests where that member was the *author*. Alternatively, in `confirm()`, when counting confirmations, filter the stored set of confirmer identities against `self.members` before comparing against `num_confirmations`, so only confirmations from currently-live members count toward quorum.

### Proof of Concept
1. Deploy `multisig2` with members `[A, B, C, D]`, `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R` (e.g. `Transfer` to an attacker-controlled account).
3. `B` calls `confirm(R)` → `confirmations = {B}` (1 of 3, not executed).
4. `C` calls `confirm(R)` → `confirmations = {B, C}` (2 of 3, not executed).
5. The group later discovers `C` is compromised/malicious and votes it out: someone creates a `DeleteMember{C}` request, and `A`, `B`, `D` confirm it (3 confirmations of live members, meeting the current `num_confirmations = 3`), triggering `delete_member(C)` per [5](#0-4) .
   - This removes `C` from `self.members` and deletes any requests *authored* by `C`, but request `R` (authored by `A`) is untouched, and its `confirmations` set still contains `C`.
6. Now only `D` (a genuinely live member) calls `confirm(R)`. `confirmations.len()` is still `2` (`B`, stale `C`), so `2 + 1 >= 3` is true, and `execute_request` runs the `Transfer` from step 2.
7. Result: request `R` executed with only 2 live-member confirmations (`B`, `D`) instead of the required 3, because a removed member's stale confirmation counted toward quorum — the multisig's threshold guarantee is broken.

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
