## Title
Signer emits a fresh acceptance signature for a block already at `GloballyRejected` consensus — `Signer::handle_block_pre_commit` ignores `mark_locally_accepted` failure ([File: stacks-signer/src/v0/signer.rs])

### Summary
`Signer::handle_block_pre_commit` reaches the pre-commit-threshold "sign" branch and unconditionally calls `create_block_acceptance` / `handle_block_signature` / `send_block_response` even when the preceding `block_info.mark_locally_accepted(false)` call **fails** because the block has already reached the terminal `GloballyRejected` state. The failure is swallowed (only a suppressed `warn!`), and the code falls through to sign and broadcast an acceptance anyway. This is the direct analog of the reported "`kick_token` does not respect the listing lock" bug class: an operation that must respect a previously-established terminal/locked state instead proceeds to mutate/act on it because the guard is only used for logging, not for control flow.

### Finding Description
`BlockInfo::mark_locally_accepted` mutates `valid`, `approved_time`, and `signed_self` *before* attempting the state transition via `move_to`: [1](#0-0) 

`move_to`/`check_state` correctly forbids `GloballyRejected → LocallyAccepted` (global states are terminal against each other): [2](#0-1) 

But because the field mutations happen unconditionally before the `move_to` check, `block_info.valid`/`signed_self` are altered even when the transition is rejected. Critically, the caller does not treat that rejection as a hard stop: [3](#0-2) 

```rust
if let Err(e) = block_info.mark_locally_accepted(false) {
    if !block_info.has_reached_consensus() {
        warn!("{self}: Failed to mark block as locally accepted: {e:?}",);
    }
}
self.signer_db.insert_block(&block_info) ...;
let accepted = self.create_block_acceptance(&block_info.block);
self.handle_block_signature(stacks_client, sortition_state, &accepted);
self.send_block_response(&block_info.block, accepted.into());
```

There is no `return` on the `Err` path. When `has_reached_consensus()` is true (i.e., the block's `state` is already `GloballyAccepted` or `GloballyRejected`), the warning is deliberately suppressed — but execution still falls through to `create_block_acceptance`, which produces a **real ECDSA signature** over `signer_signature_hash` with the signer's private key, and then broadcasts it via `send_block_response`.

`handle_block_pre_commit` never checks `block_info.has_reached_consensus()` before this signing branch; its only pre-flight checks are `signed_self.is_some()`, `valid.unwrap_or(false)`, `min_weight > commit_weight`, `check_block_against_signer_db_state`, and the signed-conflict scan (`get_signed_conflicts`), none of which look at whether *this exact block* already reached a terminal global verdict: [4](#0-3) [5](#0-4) 

`get_signed_conflicts` only returns blocks that carry a signature (`signed_self`/`signed_group`); a block that was globally *rejected* without ever being signed by anyone is invisible to that conflict scan, so it provides no protection here.

A `GloballyRejected` verdict on the block is reachable independently of this signer's own vote, via peer rejection messages tallied in `store_and_process_block_rejection`: [6](#0-5) 

Meanwhile, `BlockPreCommit` weight is accumulated from `block_pre_commits`, a table that is never retracted when a pre-committing signer later rejects the same block (pre-commit carries no signature, so `add_block_rejection_signer_addr`'s only guard is against an existing *signature*, not an existing pre-commit): [7](#0-6) [8](#0-7) 

Because pre-commits and rejections are tracked on independent, non-retracting tallies, both the ≥70% pre-commit weight and the >30% rejection weight can be crossed for the same block (overlapping signer weight counted on both sides), letting the block reach `GloballyRejected` in this signer's DB while late-arriving/gossip-delayed `BlockPreCommit` messages for the same block continue to push this signer's local pre-commit tally over threshold afterward.

A parallel, symmetric flaw exists for `mark_locally_rejected` a few lines earlier in the same function — it is also not gated on the block's terminal state, so a late pre-commit-threshold recheck failure (`check_block_against_signer_db_state`) can cause this signer to broadcast a rejection for a block already `GloballyAccepted`: [9](#0-8) 

The same swallow-and-continue pattern also appears in the pre-commit-marking path of `handle_block_validate_ok`, which re-broadcasts a stale pre-commit and re-invokes `handle_block_pre_commit` whenever `has_reached_consensus()` is true, feeding the same vulnerable path: [10](#0-9) 

### Impact Explanation
This breaks the "signed vs validated" / "rejection recounted as an accept" equality explicitly called out as Critical: a signer produces and broadcasts a **valid** acceptance signature over a block whose global (consensus) fate was already decided as `GloballyRejected` by the signer set. That signature can be relayed and, combined with other signers' pre-commit weight that similarly outlives their later-recorded rejections, contributes to conflicting/duplicate tallies for a block the network already discarded — undermining the terminal-state guarantee the `BlockState` machine (`docs/signer-flows.md` §2, `BlockInfo::check_state`) is designed to provide.

### Likelihood Explanation
No majority collusion, forged keys, or node access is required. All that is needed is ordinary gossip/network delay causing a `BlockPreCommit` message to arrive at a signer *after* that signer's local DB already recorded `GloballyRejected` for the same block (driven entirely by other signers' independently-arriving `BlockRejection` messages). This mirrors exactly the "communication delays between nodes/shards" trigger described in the analog report, and is plausible under ordinary asynchronous message delivery among honest signers — no attacker intent needed.

### Recommendation
Add an explicit terminal-state guard at the top of `handle_block_pre_commit` (and symmetrically before the `mark_locally_rejected` branch), returning immediately if `block_info.has_reached_consensus()` is true, mirroring the `token.assert_not_locked()` fix pattern from the referenced report:
```rust
if block_info.has_reached_consensus() {
    debug!("{self}: block already reached consensus; ignoring pre-commit");
    return;
}
```
Additionally, `mark_locally_accepted`/`mark_locally_rejected` should not mutate `valid`/`approved_time`/`signed_self` before `move_to` succeeds — the state-transition check should gate the field mutations, not just the returned `Result`, so a failed transition never leaves inconsistent fields to be persisted or acted upon.

### Proof of Concept
1. Signer S validates block B, sends its own `BlockPreCommit` (state → `PreCommitted`).
2. Signers holding >30% weight (who never signed B) send `BlockRejection` for B; S processes these via `store_and_process_block_rejection`, crossing the rejection threshold and calling `mark_globally_rejected()` — S's local `block_info.state` becomes `GloballyRejected`. `block_info.valid` remains `Some(true)` from the earlier validation.
3. A `BlockPreCommit` from another (overlapping-weight) signer that pre-committed earlier but has not yet had its later rejection processed by S arrives late (gossip delay), pushing S's local `get_block_pre_committers` weight tally for B over the ≥70% threshold.
4. `handle_block_pre_commit` on S passes `signed_self.is_some()` (false), `valid.unwrap_or(false)` (true), the weight check, `check_block_against_signer_db_state` (no chain-tip conflict detected), and the `get_signed_conflicts` scan (B never had a signature, so invisible to it).
5. `block_info.mark_locally_accepted(false)` fails at `move_to` (GloballyRejected→LocallyAccepted disallowed), but `valid`/`signed_self` are already mutated; the `Err` is swallowed because `has_reached_consensus()` is true.
6. Execution falls through unconditionally to `create_block_acceptance(&block_info.block)`, producing a real signature, followed by `handle_block_signature` and `send_block_response(BlockAccepted)` — S broadcasts a valid acceptance for a block already at `GloballyRejected` consensus.

        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(

            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
