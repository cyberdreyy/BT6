### Title
Unbounded zstd/tar decompression allows disk-exhaustion (decompression bomb) via cache/artifact extraction - ([File: commands/helpers/archive/tarzstd/tarzstd_extractor.go])

### Summary
`extractor.Extract` in `commands/helpers/archive/tarzstd/tarzstd_extractor.go` streams every regular file entry from a zstd-compressed tar archive straight to disk via `io.Copy(f, tr)` with no per-file or cumulative decompressed-size cap. Because zstd (like gzip) can achieve extreme compression ratios on repetitive data, a small uploaded cache/artifact archive can expand to many times its size on disk during extraction, exhausting the shared host's disk.

### Finding Description
The extraction loop reads each tar header, creates the target file, and copies the entire decompressed stream unconditionally: [1](#0-0) 

There is no check against `hdr.Size`, no running total of bytes written, and no configurable quota anywhere in this function. The only enforced limits in the cache pipeline are on the **compressed upload size** (`MaxUploadedArchiveSize`, checked before upload in `CacheArchiverCommand.uploadArchiveIfNeeded`): [2](#0-1) 

That limit only guards the *archiver's own* upload of its own output — it does nothing to constrain what `CacheExtractorCommand.Execute` will decompress when pulling down a cache object (which could originate from a malicious job that wrote directly to the presigned/GoCloud cache URL, or an artifact uploaded by the job to be later downloaded and extracted by another stage): [3](#0-2) 

Path-traversal is checked (`strings.HasPrefix(path, e.dir+...)`), but no equivalent check exists for decompressed volume. An attacker who controls job cache/artifact content (a normal, unprivileged CI job author) can produce a highly compressible payload (e.g., a multi-GB all-zero file) that compresses to a tiny zstd/tar archive, well within any compressed-size limit, then have the runner (or a later job/stage sharing the same host/volume) extract it, writing gigabytes to disk uncontrolled.

### Impact Explanation
On a shared runner host (shell executor, or docker executor with shared cache/build volumes across concurrently scheduled jobs), extraction of one job's crafted cache/artifact can fill the disk, causing `ENOSPC` failures for other tenants' concurrently running or queued jobs on the same host — a concrete, attacker-triggerable multi-tenant denial of service via disk exhaustion, matching the scoped impact.

### Likelihood Explanation
Feasible and repeatable with an unprivileged job: the attacker only needs to control CI job content (cache/artifact contents), which is standard job-author capability. Highly compressible payloads (e.g., zero-filled files) are trivial to construct and compress extremely well with zstd, so the compressed-size limits enforced elsewhere (`MaxUploadedArchiveSize`) do not prevent this.

### Recommendation
Enforce a maximum cumulative (and optionally per-file) decompressed size during extraction in `Extract`, tracking bytes written via `io.Copy` (e.g., using `io.CopyN` in a loop or wrapping the writer with a counting/limiting writer) and aborting with an error once a configurable quota is exceeded. Apply the same guard to the other tar/zip extractors (`fastzip`, `ziplegacy`) for consistency.

### Proof of Concept
Go test plan:
1. Create a large (e.g., 4 GiB) all-zero temp file.
2. Archive it with `tar` + `zstd` (via `tarzstd` archiver or `zstd` CLI) — resulting archive should be only a few KB.
3. Call `tarzstd.NewExtractor(archiveReader, archiveSize, tmpDir).Extract(ctx)`.
4. Assert that `Extract` returns an error (e.g., "decompressed size limit exceeded") before writing the full 4 GiB, rather than succeeding and consuming disk space equal to the uncompressed size.
5. Currently, the test would show `Extract` succeeding and writing the full 4 GiB to `tmpDir`, confirming the missing quota enforcement.

func (c *CacheArchiverCommand) uploadArchiveIfNeeded(size int64) {
	if c.URL == "" && c.GoCloudURL == "" {
		logrus.Infoln(
			"No URL provided, cache will not be uploaded to shared cache server. " +
				"Cache will be stored only locally.")
		return
	}

	if c.MaxUploadedArchiveSize != 0 && size > c.MaxUploadedArchiveSize {
		logrus.Infoln(fmt.Sprintf("Cache archive size (%d) is too big (Limit is set to %d). "+
			"Cache will be stored only locally.", size, c.MaxUploadedArchiveSize))
		return
	}
