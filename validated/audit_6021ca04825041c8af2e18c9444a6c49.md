### Title
Unauthenticated MethodPublicKeyGet requests bypass per-request coalescing, allowing unbounded DON fan-out per unique request ID before/without cache population - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`HandleJSONRPCUserMessage` explicitly skips `h.requestProcessor.ProcessRequest` for `vaulttypes.MethodPublicKeyGet` because "Public key requests don't require authorization" [1](#0-0) . When `getCachedPublicKey()` returns `nil` (cache not yet populated, or perpetually empty if node fetches keep failing), every request — regardless of how many distinct/duplicate attacker-chosen `req.ID`s are supplied — creates a brand-new `activeRequest` via `newActiveRequest` and independently calls `fanOutToVaultNodes`, which sends the request to every DON member node with no coalescing of concurrent in-flight identical `public_key.get` fetches. There is no per-caller or global ingress rate limiter in this handler path prior to that fan-out.

### Finding Description
The request path is: `gateway.ProcessRequest` → `handler.HandleJSONRPCUserMessage` [2](#0-1)  → for `MethodPublicKeyGet`, cache check via `getCachedPublicKey()`, and on cache miss, `h.newActiveRequest(req, callback)` followed by `h.handlePublicKeyGet(ctx, ar)` [3](#0-2) .

`newActiveRequest` only rejects a request if the exact same `req.ID` string is already an in-flight key in `h.activeRequests`; since the attacker fully controls `req.ID` (up to 200 chars, checked at line 407), supplying unique IDs each time trivially avoids that guard [4](#0-3) . `handlePublicKeyGet` re-checks the cache and, on miss, unconditionally calls `fanOutToVaultNodes`, which loops over `h.donConfig.Members` and calls `h.don.SendToNode` for every member for every such request [5](#0-4) [6](#0-5) .

There is no request-coalescing (e.g., a single "in-flight fetch" future that all callers wait on) and no rate limiter gating ingress of `MethodPublicKeyGet` before fan-out — `h.nodeRateLimiter` only throttles inbound node *responses* in `HandleNodeMessage`, not outbound fan-out volume [7](#0-6) . Other gateway handlers in this codebase (e.g., the HTTP trigger handler) do apply an explicit `userRateLimiter.AllowErr` check per caller before dispatching to nodes [8](#0-7) , but the vault handler's `MethodPublicKeyGet` branch has no analogous check, consistent with the "cache aggressively, don't need to worry about DoS" comment at line 416 assuming the cache is populated quickly and reliably.

The practical exposure window is bounded in the common case: `fetchVaultPublicKey` runs on a periodic 1-minute ticker and at first successful DON response the cache is populated and stays populated indefinitely (no TTL expiry logic in `getCachedPublicKey`) [9](#0-8) [10](#0-9) . However, if the vault DON is slow/unavailable to answer `public_key.get` (e.g., quorum not reached, node errors), the cache miss window can persist, during which each attacker request causes a full fan-out to all DON members, and each occupies a slot in `h.activeRequests` until `removeExpiredRequests` clears it after `requestTimeout` (default 30s).

### Impact Explanation
This is a genuine, unauthenticated resource-exhaustion vector: an attacker can force the gateway to broadcast to every DON member node for every uniquely-IDed `public_key.get` request as long as the cache remains unpopulated, and can keep many entries alive in `h.activeRequests` concurrently (bounded only by `requestTimeout`, default 30s, and the 200-character ID length cap — no numeric cap on total concurrent entries). This maps to a DoS/availability impact against the gateway and DON nodes, not a secret-disclosure or authorization-bypass issue. It does not grant any privilege escalation, credential exposure, or cross-user data access — the public key is not secret and is intended to be public. This is scoped to a DoS/availability class, not a critical secret-disclosure or authorization-bypass class.

### Likelihood Explanation
Preconditions: no credentials required (public endpoint by design), attacker only needs the gateway to be reachable, and needs the vault public key cache to be unpopulated (startup window, or during DON key-fetch failures). Under normal steady-state operation (cache populated on periodic 1-minute refresh and never expired), the window is narrow, limiting practical impact to boot-time or DON-outage scenarios. This is fully repeatable during that window by any unauthenticated client, requiring only distinct `req.ID` values in the JSON-RPC payload.

### Recommendation
Add single-flight coalescing for concurrent `MethodPublicKeyGet` cache-miss fetches (e.g., only allow one in-flight upstream fetch at a time, with all concurrent callers subscribing to its result instead of each triggering an independent `fanOutToVaultNodes`), and/or apply a lightweight ingress rate limiter (global, not per-owner, since there is no owner) specifically for `MethodPublicKeyGet` before fan-out, mirroring the `userRateLimiter` pattern used in `http_trigger_handler.go`. Also consider bounding the total size of `h.activeRequests` or adding a dedicated cap for public-key-get entries.

### Proof of Concept
Go handler-level test plan (extends `core/services/gateway/handlers/vault/handler_test.go`):
1. Construct a `handler` via `newHandlerWithAuthorizer` with a mock `gwhandlers.DON` and a `donConfig.Members` list of N nodes; do not pre-populate `cachedPublicKeyGetResponse`/`cachedPublicKeyObject`.
2. Spawn M (e.g., 50) goroutines concurrently, each building a `jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, ID: uuid.New().String()}` and a fresh `handlerscommon.NewCallback()`, then calling `handler.HandleJSONRPCUserMessage(ctx, req, callback)`.
3. Assert on the mock DON's `SendToNode` call count: current code will show `SendToNode` invoked `M * N` times (one full fan-out per request) — assert this to demonstrate lack of coalescing; a fixed implementation should show only 1 fan-out event serving all M waiting callers once the (mocked) DON response arrives.
4. Additionally assert `len(handler.activeRequests)` grows to M concurrently-registered entries before any node response arrives, showing unbounded per-caller registration in the cache-miss window.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) getCachedPublicKey() ([]byte, *tdh2easy.PublicKey) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	if h.cachedPublicKeyGetResponse == nil {
		return nil, nil
	}
	copied := make([]byte, len(h.cachedPublicKeyGetResponse))
	copy(copied, h.cachedPublicKeyGetResponse)
	cachedPublicKeyCopy := *h.cachedPublicKeyObject
	return copied, &cachedPublicKeyCopy
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}
