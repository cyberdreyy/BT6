### Title
Missing allowlist/authorization enforcement in `HandleLegacyUserMessage` allows any signed message to trigger full DON execution - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` only validates payload structure, timestamp freshness, and method name before forwarding the request to every DON member via `don.SendToNode`. The explicit `// TODO: apply allowlist and rate-limiting here` at line 384 confirms no subscription/allowlist authorization check exists, so any client capable of producing a structurally valid, freshly-timestamped `api.Message` (any ECDSA keypair can self-sign it — there's no requirement the signer be a known/authorized address) can trigger DON-wide job execution.

### Finding Description
The gateway's `ProcessRequest` in `core/services/gateway/gateway.go` (lines 250-269) routes any legacy request with a `DonId` through `msg.Validate()` [1](#0-0)  and then calls `h.HandleLegacyUserMessage(ctx, msg, callback)`. `Message.Validate()` in `core/services/gateway/api/message.go` (lines 54-88) only checks field lengths/null-byte suffixes and that the signature can be used to `ExtractSigner()` — it does not check the recovered signer against any allowlist, subscription, or authorized-sender registry [2](#0-1) . Inside `HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go` lines 341-421), the checks performed are: payload JSON decoding, non-zero timestamp, timestamp freshness (`MaxAllowedMessageAgeSec`), and `msg.Body.Method == MethodWebAPITrigger`. Immediately after these checks, the code comment states `// TODO: apply allowlist and rate-limiting here` (line 384), and then unconditionally proceeds to `common.ValidatedRequestFromMessage(msg)` and iterates `h.donConfig.Members`, invoking `don.SendToNode(ctx, member.Address, req)` for every DON node (lines 416-419) [3](#0-2) . Since any attacker can generate their own ECDSA keypair and self-sign a well-formed message (as shown in the test helper `triggerRequest` in `handler_test.go`, which just does `msg.Sign(key)` with an arbitrary private key) [4](#0-3) , signature validity alone provides no authorization guarantee — it only proves message integrity, not that the sender holds any Functions subscription or is on an allowlist. The handler's own test suite acknowledges this gap explicitly: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` [5](#0-4) , and none of the existing tests assert any allowlist/subscription enforcement before `don.SendToNode` is called (the "happy case" test expects `SendToNode` to be invoked for any validly-signed message) [6](#0-5) .

### Impact Explanation
This matches the "unauthorized job run" bounty impact class: an unauthenticated/unauthorized gateway client can force a full DON of oracle nodes to execute a workflow trigger (`web_api_trigger`) with attacker-controlled topics/params, consuming DON compute resources and potentially chaining into downstream fund-moving or contract-writing capabilities without ever being tied to a paying/authorized Functions subscription or workflow allowlist entry.

### Likelihood Explanation
No preconditions beyond network reachability to the gateway's legacy JSON-RPC endpoint are required. The attacker needs no credentials, subscription, or allowlist membership — they can generate their own keypair, self-sign, and forward the request. The request is trivially repeatable and requires no privileged access; the vulnerability is deterministic and always reachable since the check is entirely absent, not just misconfigured.

### Recommendation
Implement the referenced TODO before dispatching to `don.SendToNode`: verify the recovered signer (`msg.Body.Sender`) against a subscription/allowlist registry (e.g., Functions subscription owner list or workflow-registry allowlist, similar to the `AllowListBasedAuth`/`Authorizer` pattern already used in `core/capabilities/vault`), and apply per-sender rate limiting, rejecting unauthorized senders with an appropriate error response before any `don.SendToNode` call.

### Proof of Concept
Add a handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a fresh, never-before-seen ECDSA keypair unrelated to any node/subscription allowlist config (unlike `nodes[0].PrivateKey` used in existing tests, use `crypto.GenerateKey()` for an unauthorized signer).
2. Build a `triggerRequest` with this key, a valid `MethodWebAPITrigger`, and current timestamp.
3. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)`.
4. Assert that `don.SendToNode` mock is invoked (`don.AssertCalled(t, "SendToNode", ...)`) despite the signer never being registered/allowlisted anywhere in `HandlerConfig`/`donConfig`, demonstrating that authorization is bypassed.
5. Contrast with an expected fix where the same test should assert `don.AssertNotCalled(t, "SendToNode", ...)` and instead expect an `api.HandlerError`/`Unauthorized` response via the callback.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
