### Title
Stale confirmations from deleted multisig members still count toward execution threshold - (File: multisig2/src/lib.rs)

### Summary
`delete_member` fails to purge a removed member's confirmation from requests they did not create but had previously confirmed, letting `confirm()` execute a request using fewer live-member confirmations than `num_confirmations` requires.

### Finding Description
The multisig's core safety invariant is: a request executes only once `num_confirmations` *current* members have confirmed it. `confirm` enforces this purely by set cardinality: [1](#0-0) 

`delete_member` is supposed to remove a member and clean up their state, but its cleanup is scoped only to requests the member authored (`r.member == member`), not requests they confirmed: [2](#0-1) 

Because `confirmations` is a bare `HashSet<String>` with no membership revalidation, if member `M` confirms a request `R` created by a different member, and `M` is later removed via `DeleteMember`, `R`'s confirmation set still contains `M`'s (now-invalid) entry. `confirm` only checks whether the *caller* is currently a member (via `current_member()`), never re-validates the existing entries in the set: [3](#0-2) 

So `R` can later be executed with `confirmations.len()+1 >= num_confirmations` where one of the counted confirmations belongs to an account/key that is no longer a member — breaking the binding "confirmations counted == live members who confirmed."

### Impact Explanation
This lets a multisig request (including `Transfer`, `AddKey`, `FunctionCall`, or another `DeleteMember`/`AddMember`) execute with fewer genuine, currently-authorized confirmations than the configured threshold `num_confirmations`. This is a multisig request executed below threshold, directly matching the Critical impact category (funds moved, or authorization bypassed, by fewer entitled parties than required).

### Likelihood Explanation
This requires no privileged action beyond normal multisig operation: any pending request that has been confirmed by a member who is later removed (a routine event — offboarding, key rotation, compromise response) leaves a live stale confirmation. Any remaining member(s) can then push that request over threshold using the stale entry, without the removed member's continued participation. No redeploy, victim key, or social engineering is needed — only ordinary sequencing of legitimate operations (confirm, then remove that confirmer, then confirm again by others).

### Recommendation
When removing a member in `delete_member`, iterate over *all* outstanding requests' confirmation sets (not just requests created by that member) and remove the deleted member's identity string from each. Alternatively, when checking the threshold in `confirm`, only count entries in `confirmations` that correspond to current `members` (filter `confirmations` against `self.members` before comparing length to `num_confirmations`).

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C}`, `num_confirmations = 2`.
2. `B` calls `add_request(R)` (request `R`, not confirmed by creator by default since `add_request` doesn't auto-confirm).
3. `A` calls `confirm(R)` → `confirmations[R] = {A}` (below threshold 2, not yet executed).
4. Members collectively pass a separate request removing `A` as a member: `DeleteMember { member: A }`. `delete_member` only scans requests where `r.member == A` (requests *A* created) — `R` was created by `B`, so it is untouched; `confirmations[R]` still equals `{A}`.
5. `C` (still a legitimate member) calls `confirm(R)`. Check: `confirmations.len() (1) + 1 >= num_confirmations (2)` → true → `R` executes.
6. `R` executes with confirmations from `{A, C}`, but `A` is no longer a member at execution time — only one genuinely live member (`C`) authorized this in real time, one fewer than the configured `num_confirmations = 2`.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
