### Title
Node response misattribution via request-ID reuse after request completion - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`activeRequest` objects are keyed solely by the caller-supplied `req.ID` in `h.activeRequests`, with no per-instance token distinguishing one logical request from a later one that reuses the same ID. A node response that was delayed in flight for an already-completed and cleared request can be attributed by `HandleNodeMessage`/`getActiveRequest` to a brand-new, unrelated `activeRequest` that happens to reuse the same `req.ID`, binding the stale response (and the data/secrets it carries) to the wrong caller's `Callback`.

### Finding Description
`newActiveRequest` [1](#0-0)  constructs a fully-initialized `activeRequest` struct before inserting it into `h.activeRequests[req.ID]` under `h.mu.Lock()`, so there is no window where a reader can observe a *partially* constructed object — Go guarantees the struct literal is fully built before the map write is visible. That specific hypothesis in the question (partial-initialization race) does not hold.

However, a related and real race exists around **ID reuse**. `sendResponseAndClearRequest` [2](#0-1)  first CAS-claims completion, then calls `ar.SendResponse(payload)`, and only *afterwards* deletes the entry from `h.activeRequests` under `h.mu.Lock()`. Once deleted, `newActiveRequest`'s duplicate-ID check [3](#0-2)  will happily let a new request with the identical `req.ID` be registered.

The map key is just the raw string `req.ID` supplied by the caller in `HandleJSONRPCUserMessage` [4](#0-3) , with no per-caller/session namespace and no per-instance nonce embedded in the map key or in the request forwarded to nodes. `HandleNodeMessage` looks up an `activeRequest` purely by `resp.ID`: [5](#0-4) .

Exploit flow:
1. Request A is created with `req.ID = "X"` (by any caller, e.g. the victim), fanned out to DON nodes via `fanOutToNodes` [6](#0-5) .
2. Request A reaches quorum/expires and is completed and removed from `h.activeRequests` via `sendResponseAndClearRequest`.
3. Before all of the DON's node responses for the *original* request A have arrived (e.g. one node is slow due to ordinary network latency), a new request B with the **same** `req.ID = "X"` is submitted (attacker-controlled, since `req.ID` is caller-supplied and not scoped per user) and successfully registered because the map slot is now free.
4. The late node response for request A (still carrying `resp.ID == "X"` and possibly containing secret/result data intended for request A's caller) arrives at `HandleNodeMessage`, which resolves it to request B's `activeRequest` and folds it into B's bundle via `addResponseForNode`/`copiedResponses`/`h.bundler.Bundle` [7](#0-6) .
5. If this stray response contributes to reaching quorum/being forwarded, request B's `Callback` (a different, potentially attacker-controlled caller) receives data originating from request A's node computation.

No signature/session check ties a node response back to the exact request instance beyond the reused string ID, and no existing validation in `HandleNodeMessage` rejects this.

### Impact Explanation
This is cross-user response confusion: data computed/signed by DON nodes for one caller's confidential relay request (e.g. `MethodSecretsGet`) can be attributed to a different caller's request if they collide on `req.ID` timing, potentially leaking secrets or capability-execution results to an unintended requester. This matches the bounty impact class "cross-user response confusion / attacker-controlled data returned to another user."

### Likelihood Explanation
Exploitability requires: (a) two requests to the same DON handler using an identical `req.ID` string, and (b) the first request completing/clearing before all of its fanned-out node responses arrive, with a new request registered in that gap. Since `req.ID` is fully caller-controlled and not namespaced per caller/session, an attacker who can predict or collide with another caller's ID convention (e.g., low-entropy or sequential IDs) and who races their own request submission against natural network delay of DON node responses can trigger this. This is a timing-dependent race rather than a deterministic bug, and requires knowledge/coincidence of another caller's `req.ID`, which lowers but does not eliminate practical likelihood.

### Recommendation
Bind each `activeRequest` to a unique, gateway-generated internal correlation token (not just the client-supplied `req.ID`) that is embedded in the message forwarded to nodes and validated on the response path, so a stale response cannot be matched to a differently-instantiated request that happens to reuse the same external ID. Alternatively, delay releasing a `req.ID` slot in `h.activeRequests` (tombstone it) for at least `nodeSendTimeout` after clearing, rejecting/ignoring node responses for tombstoned IDs, and reject new requests reusing a tombstoned ID until the tombstone expires.

### Proof of Concept
Go handler-level integration test plan:
1. Configure a `handler` with a fake `don.DON` and fake clock, DON with `F=1`, 3 members.
2. Submit request A (`req.ID="dup"`) with callback A; have two nodes respond (reaching completion) so `sendResponseAndClearRequest` fires and `h.activeRequests` no longer contains "dup" — but do not yet deliver the third node's response for A.
3. Immediately submit request B (`req.ID="dup"`) with callback B and a different `Method`/payload; assert it is registered successfully (no "already exists" error).
4. Deliver the delayed third node response tagged `resp.ID="dup"` (originally meant for A) via `HandleNodeMessage`.
5. Assert: callback B does NOT receive any bundle component derived from the delayed node response meant for A, and/or that the delayed response is dropped rather than folded into B's active request — i.e., `ar.responses` for B must never contain the node entry that was sent in reply to A's original `req` payload.
6. Run under `go test -race` with goroutines stress-creating/clearing/reusing the same ID concurrently to confirm no response is ever delivered to a `Callback` other than the one registered for its own request lifecycle instance.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
