## Confirmed: MessageId is fully client-controlled and unauthenticated as a uniqueness key

`api.Message.Body.MessageId` is an arbitrary client-supplied string (max 128 bytes, non-empty, no trailing null), validated only for format — not uniqueness or ownership — in `Validate()`. [1](#0-0) 

The signature over the message covers `MessageId`, `Method`, `DonId`, `Receiver`, and `Payload`, so it authenticates the *sender's* identity but does nothing to prevent two different (unprivileged, unrelated) senders from independently choosing the same `MessageId` value. [2](#0-1) 

### Title
Cross-user response hijack via unauthenticated, attacker-chosen MessageId collision in gateway capabilities handler - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The gateway's web API capabilities handler stores each inbound user request's response callback in a shared map keyed solely by the client-supplied, unauthenticated `MessageId`, without checking for a pre-existing entry before overwriting it. Any unprivileged client can choose a `MessageId` already in flight for another user and thereby capture (or clobber) that user's pending trigger response, analogous to the report's underlying bug class: state belonging to one unprivileged party can be silently overwritten/hijacked by another unprivileged party due to a missing "already exists / already claimed" guard on a client-influenced key.

### Finding Description
`HandleLegacyUserMessage` unconditionally does:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [3](#0-2) 

There is no check whether `msg.Body.MessageId` already has an active `savedCallback` before overwriting the map entry, unlike the sibling `confidentialrelay` handler, which explicitly rejects a duplicate ID:
```go
if h.activeRequests[req.ID] != nil {
    h.lggr.Errorw("request id already exists", "requestID", req.ID)
    return nil, errors.New("request ID already exists: " + req.ID)
}
``` [4](#0-3) 

Because `MessageId` is entirely client-chosen and only constrained by length/format in `Message.Validate()` (not uniqueness, not tied to sender identity) [5](#0-4) , a second unprivileged client (User B) can submit a `web_api_trigger` request using the exact same `MessageId` that a legitimate User A is already awaiting a response for. This overwrites User A's `savedCallback` entry with User B's callback in the shared `h.savedCallbacks` map.

When any DON node subsequently responds for that `MessageId`, `handleWebAPITriggerMessage` looks the callback up purely by `MessageId` and delivers the (first-arriving) response to whichever callback currently occupies that slot:
```go
func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
    h.mu.Lock()
    savedCb, found := h.savedCallbacks[msg.Body.MessageId]
    delete(h.savedCallbacks, msg.Body.MessageId)
    h.mu.Unlock()
    if found {
        codec := api.JsonRPCCodec{}
        return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
    }
    return nil
}
``` [6](#0-5) 

There is no verification that the sender who registered the callback matches the sender of the incoming node response's original request, nor any per-sender namespacing of the `MessageId` key space. This is the same root-cause pattern as the external report: a lack of a "state already owned/claimed" check on a shared, externally-influenceable identifier allows one unprivileged party to consume or divert state/output belonging to another unprivileged party.

### Impact Explanation
If User B wins the race (submits their identical-`MessageId` request after User A's, before A's node response arrives), User A's HTTP callback slot is silently overwritten. When the DON eventually responds to A's original triggered request, that response is delivered to User B's HTTP connection instead of User A's, i.e., cross-user response confusion/disclosure of another user's trigger output to an unrelated unprivileged actor. Conversely, User A's own callback (now orphaned) never receives a response and eventually times out. This is a request/response integrity and confidentiality violation reachable purely from unauthenticated/unprivileged internet-facing gateway traffic, matching the "cross-user response confusion" acceptance criterion.

### Likelihood Explanation
Exploitation requires no special privilege — any client capable of sending a signed message to the gateway's legacy web API endpoint can pick an arbitrary `MessageId`. The only obstacle is winning a timing race against the real request's DON round-trip, which is plausible given typical DON response latencies (network + node processing) versus the near-instant local map write. No allowlist, sender-binding, or per-sender ID uniqueness check currently prevents this.

### Recommendation
- Before inserting into `h.savedCallbacks`, check for an existing, non-expired entry for the same `MessageId` and reject the new request (mirroring the `confidentialrelay` handler's `activeRequests[req.ID] != nil` guard) rather than silently overwriting.
- Additionally, namespace the callback key by `(Sender, MessageId)` rather than `MessageId` alone, so that even legitimately reused IDs across different senders cannot collide.
- When delivering a node's response in `handleWebAPITriggerMessage`, verify the response's originating sender/DonId matches what was recorded at registration time before invoking `SendResponse`.

### Proof of Concept
1. User A sends a signed `web_api_trigger` legacy message with `Body.MessageId = "X"` to the gateway; `HandleLegacyUserMessage` stores A's callback under key `"X"` in `h.savedCallbacks`.
2. Before the DON node responds, User B sends their own signed legacy message using the same `Body.MessageId = "X"` (a distinct, independently signed message — signature validity does not depend on ID uniqueness across senders, only on the signer matching the given payload, per `Message.Validate`/`ExtractSigner`).
3. `HandleLegacyUserMessage` executes the unconditional map write, replacing A's `savedCallback` with B's.
4. The DON node eventually responds to A's original request with method `web_api_trigger` and `MessageId = "X"`.
5. `handleWebAPITriggerMessage` looks up `"X"` in `savedCallbacks`, finds B's callback, and calls `savedCb.SendResponse(...)`, delivering A's response payload to B's HTTP connection. A's request times out with no response.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

// Message signatures are over the following data:
//  1. MessageId aligned to 128 bytes
//  2. Method aligned to 64 bytes
//  3. DonId aligned to 64 bytes

//  5. Payload (raw bytes before parsing)
func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
