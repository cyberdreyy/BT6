### Title
Attacker-forced large-data L1 deposits are admitted into L2 blocks with no cost/gas correlation to their calldata size, enabling sequencer/verifier DoS - ([File: crates/consensus/derive/src/attributes/stateful.rs])

### Summary
Base derives `TransactionDeposited` events emitted on L1 into mandatory-inclusion L2 deposit transactions via `derive_deposits`/`Deposits::decode`/`Deposits::unmarshal_v0`, then unconditionally force-includes them into `BasePayloadAttributes.transactions` with `no_tx_pool: true` in `StatefulAttributesBuilder::prepare_payload_attributes`. Neither the decode path nor the block-gas admission path (`execute_transaction` / `execute_transaction_without_commit`) bounds a deposit's calldata size relative to the attacker-declared `gas_limit` field that is copied verbatim from the L1 log. This reproduces the OptimismPortal `depositTransaction()` griefing pattern (only `gasLimit ≥ 21_000` is meaningful upstream) inside the Base derivation/execution stack that this repo owns.

### Finding Description
`Deposits::unmarshal_v0` in [1](#0-0)  copies the L1-emitted `gasLimit` (u64) and the remaining opaque bytes as `tx.input` with no upper bound on `data.len()` relative to `gas_limit`. `derive_deposits` in [2](#0-1)  collects every decoded deposit from L1 receipts with no size cap, and `prepare_payload_attributes` force-appends them into the block's transaction list with `no_tx_pool: Some(true)` at [3](#0-2) , bypassing the builder-side `ResourceLimits` (`tx_data_limit`, `block_data_limit`) that only apply to pool-selected transactions in `is_tx_over_limits` ( [4](#0-3) ).

At block-execution admission time, the reserved-gas pre-check in `execute_transaction` uses only the attacker-declared `tx.gas_limit()` (which can be a minimal value like 21,000) against the block's remaining gas budget, independent of the deposit's actual `input` length: [5](#0-4) . Only later, deep in `handle_deposit`, is the true data-driven `intrinsic_gas` computed and compared to `tx.gas_limit`, but by then the failure path just marks the deposit "failed" while leaving the oversized transaction embedded in the L2 block: [6](#0-5) . This mirrors the same disconnect the external report calls out in `OptimismPortal.depositTransaction()`: gas admission is checked against a fixed floor/attacker-declared value, not against the cost that the calldata actually imposes downstream.

### Impact Explanation
An L1 depositor (an unprivileged, in-scope actor per the "depositor" class) who can get `TransactionDeposited` events with large `opaqueData` included in L1 receipts (e.g. by looping calls to the deposit contract or crafting one large-calldata deposit) forces the Base derivation pipeline to unconditionally decode and embed that oversized deposit transaction into the *mandatory* portion of the next L2 block, with `no_tx_pool: true` overriding all builder-configured DA/size limits. The sequencer and every verifying node must decode, buffer, RLP/SSZ-encode, hash, gossip, and permanently store the resulting oversized block/transaction, while the block-gas accounting only reserves the attacker's tiny declared `gas_limit` (e.g. 21,000) rather than gas proportional to the payload size. This is a resource-exhaustion/griefing vector against block builders and verifying nodes stemming directly from untrusted derivation of L1 deposit data, which is explicitly one of the in-scope reachable classes.

### Likelihood Explanation
Likelihood is moderate-to-high for any deployment where the L1 portal itself does not independently bound `gasLimit` against `data.length` (this is exactly the gap the external report describes for `OptimismPortal.sol`, which is out of scope for this repo but is the origin of the untrusted data this repo trusts). Given that gap on L1, exploitation from this repo's side requires no privileged access — only ordinary L1 deposit transactions/calldata that get included in L1 receipts, which the derivation pipeline processes automatically and without additional validation.

### Recommendation
- In `Deposits::unmarshal_v0` / `Deposits::decode` (`crates/consensus/protocol/src/deposits.rs`), reject or cap opaque-data length that is disproportionate to the declared `gas_limit` (e.g., enforce that `gas_limit` covers at least the calldata's intrinsic cost, mirroring `intrinsic_gas` used in `handle_deposit`), rather than deferring that check to execution time after the oversized tx is already embedded in the block.
- In `StatefulAttributesBuilder::prepare_payload_attributes` (`crates/consensus/derive/src/attributes/stateful.rs`), apply a maximum per-deposit and cumulative deposit-data size bound before force-including deposits, independent of builder-configured `ResourceLimits` (since those are bypassed via `no_tx_pool`).
- In `execute_transaction`'s reserved-gas pre-check (`crates/common/evm2/src/executor.rs`), account for calldata-driven intrinsic cost — not just the raw declared `gas_limit` — when reserving block gas for deposit transactions, so a deposit cannot reserve disproportionately little gas relative to its embedded data size.

### Proof of Concept
1. An attacker submits (or repeatedly submits) L1 transactions that call the deposit contract with `gasLimit = 21_000` and multi-hundred-KB/MB `data`, producing `TransactionDeposited` log(s) with correspondingly large `opaqueData`.
2. `derive_deposits` (crates/consensus/derive/src/attributes/stateful.rs:286-311) decodes every such log via `Deposits::decode`/`unmarshal_v0` with no size cap and returns them as raw `Bytes`.
3. `prepare_payload_attributes` (stateful.rs:217-239) appends them to `txs` and sets `no_tx_pool: Some(true)`, guaranteeing inclusion regardless of any `ResourceLimits.tx_data_limit`/`block_data_limit` configured on the builder.
4. `execute_transaction` (crates/common/evm2/src/executor.rs:256-277) reserves only `tx.gas_limit()` (21,000) against the block gas budget — the check passes even though the transaction carries megabytes of calldata.
5. `handle_deposit` (crates/common/evm2/src/registry.rs:86-93) computes the real `intrinsic_gas` from the large `input`, finds `tx.gas_limit < intrinsic`, and marks the deposit "failed" — but the full oversized transaction remains part of the produced/verified L2 block, having already been decoded, hashed, and stored by every node that processes it.

impl Deposits {
    /// Unmarshals a deposit transaction from the opaque data.
    pub fn unmarshal_v0(
        tx: &mut TxDeposit,
        to: Address,
        data: &[u8],
    ) -> Result<(), DepositDecodeError> {
        if data.len() < 32 + 32 + 8 + 1 {
            return Err(DepositDecodeError::UnexpectedOpaqueDataLen(data.len()));
        }

        let mut offset = 0;

        let raw_mint: [u8; 16] = data[offset + 16..offset + 32].try_into().map_err(|_| {
            DepositDecodeError::MintDecode(Bytes::copy_from_slice(&data[offset + 16..offset + 32]))
        })?;
        tx.mint = u128::from_be_bytes(raw_mint);
        offset += 32;

        // uint256 value
        tx.value = U256::from_be_slice(&data[offset..offset + 32]);
        offset += 32;

        // uint64 gas
        let raw_gas: [u8; 8] = data[offset..offset + 8].try_into().map_err(|_| {
            DepositDecodeError::GasDecode(Bytes::copy_from_slice(&data[offset..offset + 8]))
        })?;
        tx.gas_limit = u64::from_be_bytes(raw_gas);
        offset += 8;

        // uint8 isCreation
        // isCreation: If the boolean byte is 1 then dep.To will stay nil,
        // and it will create a contract using L2 account nonce to determine the created address.
        if data[offset] == 0 {
            tx.to = TxKind::Call(to);
        } else {
            tx.to = TxKind::Create;
        }
        offset += 1;

        // The remainder of the opaqueData is the transaction data (without length prefix).
        // The data may be padded to a multiple of 32 bytes
        let tx_data_len = data.len() - offset;

        // Remaining bytes fill the data
        tx.input = Bytes::copy_from_slice(&data[offset..offset + tx_data_len]);

        Ok(())
    }

async fn derive_deposits(
    block_hash: B256,
    receipts: &[Receipt],
    deposit_contract: Address,
) -> Result<Vec<Bytes>, PipelineEncodingError> {
    let mut global_index = 0;
    let mut res = Vec::new();
    for r in receipts {
        if Eip658Value::Eip658(false) == r.status {
            continue;
        }
        for l in &r.logs {
            let curr_index = global_index;
            global_index += 1;
            if l.data.topics().first().is_none_or(|i| *i != Deposits::EVENT_ABI_HASH) {
                continue;
            }
            if l.address != deposit_contract {
                continue;
            }
            let decoded = Deposits::decode(block_hash, curr_index, l)?;
            res.push(decoded);
        }
    }
    Ok(res)
}

    pub fn is_tx_over_limits(
        &self,
        tx: &TxResources,
        limits: &ResourceLimits,
    ) -> Result<(), TxnExecutionError> {
        // Check per-transaction DA size limit (always enforced, operator-configured)
        if let Some(da_limit) = limits.tx_data_limit
            && tx.da_size > da_limit
        {
            return Err(TxnExecutionError::TransactionDASizeExceeded(tx.da_size, da_limit));
        }

        // Check block DA size limit (always enforced, operator-configured)
        let total_da_bytes_used = self.cumulative_da_bytes_used.saturating_add(tx.da_size);
        if let Some(da_limit) = limits.block_data_limit
            && total_da_bytes_used > da_limit
        {
            return Err(TxnExecutionError::BlockDASizeExceeded {
                total_da_used: self.cumulative_da_bytes_used,
                tx_da_size: tx.da_size,
                block_da_limit: da_limit,
            });
        }

        // Post Jovian: the tx DA footprint must be less than the block gas limit (protocol-enforced)
        if let Some(da_footprint_gas_scalar) = limits.da_footprint_gas_scalar {
            let tx_da_footprint =
                total_da_bytes_used.saturating_mul(da_footprint_gas_scalar as u64);
            if tx_da_footprint > limits.block_da_footprint_limit.unwrap_or(limits.block_gas_limit) {
                return Err(TxnExecutionError::DAFootprintLimitExceeded {
                    total_da_used: total_da_bytes_used,
                    tx_da_size: tx.da_size,
                    da_footprint: tx_da_footprint,
                });
            }
        }

        // Check gas limit. EIP-8130 meters payer authentication gas on top of the declared
        // gas_limit, so it is reserved against the block gas budget in addition to gas_limit.
        if self.cumulative_gas_used.saturating_add(tx.gas_limit).saturating_add(tx.payer_auth)
            > limits.block_gas_limit
        {
            return Err(TxnExecutionError::TransactionGasLimitExceeded {
                cumulative_gas_used: self.cumulative_gas_used,
                tx_gas_limit: tx.gas_limit.saturating_add(tx.payer_auth),
                block_gas_limit: limits.block_gas_limit,
            });
        }

        // executing it. For an EIP-8130 transaction the reservation adds the payer's worst-case
        // authentication gas (metered on top of the sender-signed gas limit), matching the
        // reference `reserved_block_gas`. Pre-Regolith deposits are exempt (matching the reference's

        let mut reserved_gas = tx.gas_limit();

            let payer_auth =
                IntrinsicGas::max_payer_auth_cost(signed).map_err(HandlerError::external)?;
            reserved_gas = reserved_gas.saturating_add(payer_auth);
        }
        let block_gas_limit = self.evm.block().gas_limit.saturating_to::<u64>();
        let block_available_gas = block_gas_limit.saturating_sub(self.gas_used);

        if reserved_gas > block_available_gas && (is_regolith || !is_deposit) {
            return Err(HandlerError::external(BlockGasLimitExceeded {
                transaction_gas_limit: reserved_gas,
