### Title
Out-of-bounds indexing panic in `parse_token` (and sibling instruction parsers) when parsing attacker-controlled `CompiledInstruction.accounts` indices via `getTransaction`/`getBlock` with `jsonParsed` encoding - (File: `transaction-status/src/parse_token.rs`)

### Summary
`parse_token` and its helper `parse_signers` validate only the *count* of account indices in a token instruction via `check_num_token_accounts`/`check_num_accounts`, never validating that the individual index *values* are within bounds of `account_keys`. Because a `CompiledInstruction.accounts` byte can be any `u8` value (0-255) chosen by the transaction sender, an attacker can submit a transaction whose SPL-Token instruction has enough account entries to pass the count check but whose byte values are out of range of the account key list, causing a slice/index panic when later decoded through `getTransaction`/`getBlock` with `encoding=jsonParsed`.

### Finding Description
`check_num_token_accounts` (`transaction-status/src/parse_token.rs:963-965`) simply forwards to `check_num_accounts`, which only checks `accounts.len() >= num`; it never checks that any index in `accounts` is `< account_keys.len()`. Every branch of `parse_token` (e.g. `InitializeAccount` at `transaction-status/src/parse_token.rs:92-103`, `Transfer` at lines 159-179, and all the others in the same match, plus `parse_reallocate_instruction` in `transaction-status/src/parse_token/extension/reallocate.rs:8-14`) then does `account_keys[instruction.accounts[i] as usize]`, and `parse_signers` (`transaction-status/src/parse_token.rs:937-961`) does the same for signer indices.

`AccountKeys`'s `Index` implementation (from `solana-message`) performs standard Rust slice indexing, which panics on out-of-range access. Since a `CompiledInstruction`'s `accounts` field is just raw bytes chosen by whoever constructs the transaction (no on-chain or sanitization-time enforcement that every index is `< account_keys.len()` specifically for downstream *parsing* logic — SVM execution itself would fail such an instruction at runtime, but the transaction can still be included and confirmed with an error status), an attacker can craft a transaction with an SPL-Token instruction whose `accounts` vector has, say, 4 entries (satisfying `check_num_token_accounts(&accounts, 4)`) where one entry is `u8::MAX` (255), far beyond `account_keys.len()`.

Once this transaction lands on-chain (even failing at runtime with an error status, which is fine because RPC still stores and serves it), an unprivileged client issuing a single `getTransaction`/`getBlock` call with `encoding: "jsonParsed"` triggers the decode path: `rpc/src/rpc.rs` `get_transaction` (`rpc/src/rpc.rs:1768-1846`) calls `confirmed_tx_with_meta.encode(...)` outside of `spawn_blocking` (the blocking retrieval from blockstore is wrapped, but the encode/parse step is not), which flows into `VersionedTransactionWithStatusMeta::encode` (`transaction-status/src/lib.rs:522-548`) → `encode_with_meta` → `parse_ui_instruction` (`transaction-status/src/lib.rs:113-126`) → `parse()` → `parse_token`, indexing `account_keys` with the attacker-chosen out-of-range value and panicking.

### Impact Explanation
A single unprivileged RPC call (`getTransaction` or `getBlock` with `jsonParsed` encoding) against a previously-confirmed, attacker-crafted transaction causes a Rust panic in the async task handling that RPC request. This is a decoder panic reachable from one low-rate read call satisfying the disclosed scope ("decoder panic and misreporting" / crash of the RPC-serving task from a single unprivileged read call). The panic occurs in the async future driving `get_transaction` (`rpc/src/rpc.rs:1768`), which is not wrapped in `catch_unwind` in the reachable path found in this repo.

### Likelihood Explanation
Preconditions are fully within reach of an unprivileged attacker: (1) construct and submit a transaction whose token-program `CompiledInstruction.accounts` has the required minimum length but contains an out-of-range index (e.g. `u8::MAX`); (2) the transaction need only be included/confirmed on-chain — it can fail at runtime, since `check_num_token_accounts` and the downstream indexing are purely used by the RPC-side decoder, not by SVM execution; (3) issue one `getTransaction`/`getBlock` call with `jsonParsed` encoding referencing that signature/slot. This is deterministic and repeatable, requiring no special privileges, staking, or leader control.

### Recommendation
Add bounds checking wherever `instruction.accounts[i]` / `account_keys[instruction.accounts[i] as usize]` is used in `transaction-status/src/parse_token.rs`, `parse_token/extension/*.rs`, `parse_bpf_loader.rs`, `parse_stake.rs`, `parse_vote.rs`, and the generic helpers in `transaction-status/src/lib.rs` (`make_ui_partially_decoded_instruction`, `parse_ui_instruction`). Extend `check_num_accounts` (or add a new helper) to also validate `accounts.iter().all(|&i| (i as usize) < account_keys.len())`, returning `ParseInstructionError::InstructionNotParsable` on failure instead of indexing directly; alternatively use `account_keys.get(idx)` and propagate an error/fallback to the raw/partially-decoded representation on `None`.

### Proof of Concept
```rust
// transaction-status/src/parse_token.rs (add to #[cfg(test)] mod test)
#[test]
fn test_parse_token_out_of_range_index_does_not_panic() {
    use solana_message::compiled_instruction::CompiledInstruction;

    // Only 2 account keys exist, but the instruction claims to reference
    // account index 255 (u8::MAX), while still satisfying the minimum
    // count check for e.g. CloseAccount (requires 3 accounts).
    let account_keys_raw = vec![Pubkey::new_unique(), Pubkey::new_unique()];
    let account_keys = AccountKeys::new(&account_keys_raw, None);

    let mut data = vec![9u8]; // TokenInstruction::CloseAccount discriminant
    let compiled_instruction = CompiledInstruction {
        program_id_index: 0,
        accounts: vec![0, 1, u8::MAX], // count=3 passes check_num_token_accounts, but index 255 is OOB
        data,
    };

    // Expectation: parse_token should return an Err, not panic.
    let result = parse_token(&compiled_instruction, &account_keys);
    assert!(result.is_err(), "parse_token must not panic on OOB account index");
}
```
Extend equivalently for `parse_bpf_loader`, `parse_stake`, and `parse_vote` with analogous OOB `accounts` indices, and add an integration test that builds a full `VersionedTransactionWithStatusMeta` with such an instruction and calls `.encode(UiTransactionEncoding::JsonParsed, ...)` to confirm no panic propagates out of the `getTransaction` code path. fn parse_signers(
    map: &mut Map<String, Value>,
    last_nonsigner_index: usize,
    account_keys: &AccountKeys,
    accounts: &[u8],
    owner_field_name: &str,
    multisig_field_name: &str,
) {
    if accounts.len() > last_nonsigner_index + 1 {
        let mut signers: Vec<String> = vec![];
        for i in accounts[last_nonsigner_index + 1..].iter() {
            signers.push(account_keys[*i as usize].to_string());
        }
        map.insert(
            multisig_field_name.to_string(),
            json!(account_keys[accounts[last_nonsigner_index] as usize].to_string()),
        );
        map.insert("signers".to_string(), json!(signers));
    } else {
        map.insert(
            owner_field_name.to_string(),
            json!(account_keys[accounts[last_nonsigner_index] as usize].to_string()),
        );
    }
}

    }

pub fn parse_ui_instruction(
    instruction: &CompiledInstruction,
    account_keys: &AccountKeys,
    stack_height: Option<u32>,
) -> UiInstruction {
    let program_id = &account_keys[instruction.program_id_index as usize];
    if let Ok(parsed_instruction) = parse(program_id, instruction, account_keys, stack_height) {
        UiInstruction::Parsed(UiParsedInstruction::Parsed(parsed_instruction))
    } else {
        UiInstruction::Parsed(UiParsedInstruction::PartiallyDecoded(
            make_ui_partially_decoded_instruction(instruction, account_keys, stack_height),
        ))
    }
}

    pub async fn get_transaction(
        &self,
        signature: Signature,
        config: Option<RpcEncodingConfigWrapper<RpcTransactionConfig>>,
    ) -> Result<Option<EncodedConfirmedTransactionWithStatusMeta>> {
        self.check_if_transaction_history_enabled()?;

        let config = config
            .map(|config| config.convert_to_current())
            .unwrap_or_default();
        let encoding = config.encoding.unwrap_or(UiTransactionEncoding::Json);
        let max_supported_transaction_version = config.max_supported_transaction_version;
        let commitment = config.commitment.unwrap_or_default();
        check_is_at_least_confirmed(commitment)?;

        let confirmed_bank = self.bank(Some(CommitmentConfig::confirmed()));
        let confirmed_transaction = self
            .runtime
            .spawn_blocking({
                let blockstore = Arc::clone(&self.blockstore);
                let confirmed_bank = Arc::clone(&confirmed_bank);
                move || {
                    if commitment.is_confirmed() {
                        let highest_confirmed_slot = confirmed_bank.slot();
                        blockstore.get_complete_transaction(signature, highest_confirmed_slot)
                    } else {
                        blockstore.get_rooted_transaction(signature)
                    }
                }
            })
            .await
            .expect("Failed to spawn blocking task");

        let encode_transaction =
                |confirmed_tx_with_meta: ConfirmedTransactionWithStatusMeta| -> Result<EncodedConfirmedTransactionWithStatusMeta> {
                    Ok(confirmed_tx_with_meta.encode(encoding, max_supported_transaction_version).map_err(RpcCustomError::from)?)
                };

        match confirmed_transaction.unwrap_or(None) {
            Some(mut confirmed_transaction) => {
                if commitment.is_confirmed()
                    && confirmed_bank // should be redundant
                        .status_cache_ancestors()
                        .contains(&confirmed_transaction.slot)
                {
                    if confirmed_transaction.block_time.is_none() {
                        let r_bank_forks = self.bank_forks.read().unwrap();
                        confirmed_transaction.block_time = r_bank_forks
                            .get(confirmed_transaction.slot)
                            .map(|bank| bank.clock().unix_timestamp);
                    }
                    return Ok(Some(encode_transaction(confirmed_transaction)?));
                }

                if confirmed_transaction.slot
                    <= self
                        .block_commitment_cache
                        .read()
                        .unwrap()
                        .highest_super_majority_root()
                {
                    return Ok(Some(encode_transaction(confirmed_transaction)?));
                }
            }
            None => {
                if let Some(bigtable_ledger_storage) = &self.bigtable_ledger_storage {
                    return bigtable_ledger_storage
                        .get_confirmed_transaction(&signature)
                        .await
                        .unwrap_or(None)
                        .map(encode_transaction)
                        .transpose();
                }
            }
        }

        Ok(None)
    }
