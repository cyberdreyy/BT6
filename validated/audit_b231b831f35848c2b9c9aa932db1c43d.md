## Analog Found

The report's core bug class — trusting a caller/attacker-influenced address as if it were validated state (of a specific expected type/owner) before using its returned values in a derived computation — maps to a JSON-RPC account-decoding path in `rpc/src/parsed_token_accounts.rs`.

### Title
Missing mint-owner validation in `get_parsed_token_account` allows misreported token decimals/UI amounts - (File: `rpc/src/parsed_token_accounts.rs`)

### Summary
`get_parsed_token_account`, used to build `jsonParsed` account encodings for RPC methods such as `getAccountInfo`, `getProgramAccounts`, `getTokenAccountsByOwner/ByDelegate`, and account-subscription notifications, extracts a "mint" pubkey embedded in a token account's raw bytes and then fetches and trusts that account's data to compute `decimals`/`ui_amount` — without ever checking that the referenced mint account is actually owned by a known SPL Token program, unlike sibling RPC handlers that do enforce this check.

### Finding Description
`get_parsed_token_account` reads the mint pubkey directly out of the token account's data via `get_token_account_mint`, resolves the corresponding account, and unconditionally parses its bytes as an SPL `Mint` via `get_additional_mint_data`: [1](#0-0) 

The helper `get_additional_mint_data` calls `StateWithExtensions::<Mint>::unpack(data)` directly on whatever bytes are found at that address, with **no check that the account's owner is `spl_token_interface::id()` or `spl_token_2022_interface::id()`**: [2](#0-1) 

This is inconsistent with the analogous logic in `rpc/src/rpc.rs`, where `get_token_account_balance`, `get_token_supply`, `get_token_largest_accounts`, and `get_token_program_id_and_mint` all explicitly call `is_known_spl_token_id(...)` on the mint/account owner before trusting parsed mint data: [3](#0-2) [4](#0-3) 

`get_mint_owner_and_additional_data` itself even returns the discovered `mint_account.owner()` precisely so that callers can validate it — but `get_parsed_token_account` never performs that validation before using the returned `SplTokenAdditionalDataV2` (decimals, `interest_bearing_config`, `scaled_ui_amount_config`) to compute the UI-facing balance shown to RPC clients via `encode_ui_account`.

### Impact Explanation
If the address referenced by a token account's `mint` field does not resolve to a genuine, owner-validated `Mint` account (e.g., an account that used to be a Mint and was later closed/reassigned, or any account whose raw bytes happen to satisfy `StateWithExtensions::<Mint>::unpack`), the RPC layer will silently compute and report an incorrect `decimals`/`ui_amount`/`ui_amount_string` for that token account in `jsonParsed` responses — a decoder misreporting of account data to any unprivileged RPC caller, without requiring any special access.

### Likelihood Explanation
Exploitability is bounded by the fact that, under normal token-program semantics, `InitializeAccount` (and CPI equivalents) enforce that the `mint` field of a legitimately-created token account points to an account actually owned by the Token program at creation time. The risk materializes primarily through corner cases such as reused/reassigned mint addresses or stale/edge account states, so this is best treated as a missing defense-in-depth check rather than a directly weaponizable primitive in all cases — but it is a genuine gap relative to the validation pattern the codebase already applies elsewhere for the identical data.

### Recommendation
In `get_additional_mint_data`/`get_parsed_token_account`, validate that the resolved mint account's owner is a known SPL Token program id (mirroring the `is_known_spl_token_id` checks already used in `rpc/src/rpc.rs`) before trusting its unpacked `Mint` fields for computing `decimals`/`ui_amount`.

### Proof of Concept
1. Call any `jsonParsed`-encoding RPC method (e.g. `getAccountInfo`, `getProgramAccounts`) on a token account whose embedded `mint` field resolves to an account that is not owned by a recognized SPL Token program id.
2. `get_token_account_mint` extracts the mint pubkey purely from byte offset 0..32 of the token account's data with no owner check. [5](#0-4) 
3. `get_parsed_token_account` fetches that account and feeds its raw bytes into `get_additional_mint_data`, which unpacks it as a `Mint` with no ownership validation, then uses the resulting decimals to compute the displayed token balance via `encode_ui_account`.

pub fn get_parsed_token_account(
    bank: &Bank,
    pubkey: &Pubkey,
    account: AccountSharedData,
    // only used for simulation results
    overwrite_accounts: Option<&HashMap<Pubkey, AccountSharedData>>,
) -> UiAccount {
    let additional_data = get_token_account_mint(account.data())
        .and_then(|mint_pubkey| {
            account_resolver::get_account_from_overwrites_or_bank(
                &mint_pubkey,
                bank,
                overwrite_accounts,
            )
        })
        .and_then(|mint_account| get_additional_mint_data(bank, mint_account.data()).ok())
        .map(|data| AccountAdditionalDataV3 {
            spl_token_additional_data: Some(data),
        });

    encode_ui_account(
        pubkey,
        &account,
        UiAccountEncoding::JsonParsed,
        additional_data,
        None,
    )
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}

    pub fn get_token_account_balance(
        &self,
        pubkey: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let account = bank.get_account(pubkey).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;

        if !is_known_spl_token_id(account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token account".to_string(),
            ));
        }
        let token_account = StateWithExtensions::<TokenAccount>::unpack(account.data())
            .map_err(|_| Error::invalid_params("Invalid param: not a Token account".to_string()))?;
        let mint = &Pubkey::from_str(&token_account.base.mint.to_string())
            .expect("Token account mint should be convertible to Pubkey");
        let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
        let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
        Ok(new_response(&bank, balance))
    }
