### Title
Gateway `web_api_trigger` legacy user messages are forwarded to every DON node without any allowlist/authentication check on the message signer - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The gateway `HandleLegacyUserMessage` path for the `web_api_trigger` capability (analogous to the report's unchecked `params.data`/no-input-validation-before-privileged-action pattern) accepts a message from any internet-facing HTTP client, validates only structural fields and a self-supplied ECDSA signature, and then broadcasts the request to *every* node in the target DON — with an explicit `// TODO: apply allowlist and rate-limiting here` marking the missing authorization check.

### Finding Description
The gateway HTTP endpoint decodes an incoming request and, for legacy (DON-addressed) messages, only performs structural validation via `Message.Validate()`: [1](#0-0) 

`Message.Validate()` checks field lengths/format and calls `ExtractSigner()`, which merely recovers *whatever* address signed the payload — it does not check that address against any allowlist, workflow owner registry, or DON member list: [2](#0-1) 

Any caller can generate a throwaway ECDSA key, sign an arbitrary `MessageBody` (with `Method: "web_api_trigger"`), and the message passes `Validate()` successfully — signing only requires *a* valid keypair, not an *authorized* one.

The request is then routed to `handler.HandleLegacyUserMessage` in the capabilities package. This function checks payload shape, a timestamp freshness window, and the method name, but the code explicitly documents that the allowlist check is not yet implemented, then unconditionally forwards the message to **all** DON members: [3](#0-2) 

This is structurally the same bug class as the External Report: a value that should be constrained/validated before being handed to a downstream privileged operation (there: `params.data` fed into `Base.swap()`; here: an unauthenticated/unauthorized `web_api_trigger` message fed into `don.SendToNode` for every DON member) is instead accepted from an untrusted, unprivileged caller with only superficial structural checks, because the actual authorization gate is a known-missing TODO.

### Impact Explanation
Because there is no allowlist check between message validation and dispatch to DON nodes, any unprivileged internet client that can reach the gateway HTTP endpoint can inject `web_api_trigger` events addressed to any known `DonId`/topic, causing:
- Unauthorized triggering of workflow execution paths gated on `web_api_trigger` (an "unauthorized job run" analog), since nodes receiving the forwarded request will process it as a legitimate trigger from the gateway.
- Resource exhaustion / DoS on the gateway and DON nodes, since attackers can flood arbitrary distinct `message_id`s to grow `savedCallbacks` and multiply `SendToNode` calls to every DON member per request, with only pruning (time/size based) as a backstop — not authorization.

The severity depends on what downstream capability/workflow logic does with trigger events it receives without gateway-side authorization (i.e., whether the workflow engine itself re-validates the actual triggering identity), which is not visible from this file alone.

### Likelihood Explanation
High reachability: this is the standard, documented public entry point (`gateway.ProcessRequest` → `HandleLegacyUserMessage`) for `web_api_trigger` requests, requires no privileged credentials, and the missing allowlist is an explicit `TODO` in the shipped code rather than a theoretical gap — meaning the control is confirmed absent, not merely unverified.

### Recommendation
Implement the sender allowlist/authorization check called out in the TODO before forwarding to DON nodes — validate the recovered signer (`msg.Body.Sender`) against a known set of authorized senders/workflow owners (mirroring the `allowListBasedAuth`/workflow-registry-syncer pattern already used for the Vault gateway handler) and apply per-sender rate limiting, rejecting unauthorized or unrecognized signers before any `don.SendToNode` call.

### Proof of Concept
Not independently executed against a live deployment; based on static code reading:
1. Generate an arbitrary ECDSA keypair (no registration/allowlisting required).
2. Construct a `MessageBody{Method: "web_api_trigger", DonId: "<any configured DON>", Payload: <valid TriggerRequestPayload JSON with fresh Timestamp>}`, sign it with the throwaway key (`msg.Sign(privateKey)`), producing a message that passes `Message.Validate()`.
3. Submit as a legacy JSON-RPC request to the gateway HTTP endpoint (`gateway.ProcessRequest`).
4. Observe that `HandleLegacyUserMessage` (per the code at `core/services/gateway/handlers/capabilities/handler.go:384-420`) forwards the request to every member of `donConfig.Members` via `don.SendToNode`, with no check that the throwaway signer is an authorized sender — confirming the missing allowlist gate described by the `TODO` comment.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
