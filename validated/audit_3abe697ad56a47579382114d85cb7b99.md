### Title
Native ETH sent to `ConvexStrategyETH` is accepted but permanently unrecoverable - (File: contracts/strategies/convex/ConvexStrategyETH.sol)

### Summary
The ETH-based Convex strategy has an unrestricted `receive()` and no native-token sweep, while its only rescue path transfers ERC20 tokens. Any direct ETH transfer to the strategy is therefore stranded outside LP accounting and cannot be recovered by the honest owner. [1](#0-0) [2](#0-1) 

### Finding Description
`ConvexStrategyETH` defines `receive() external payable {}` with no sender restriction, so an unprivileged EOA or contract can send ETH directly to the strategy. The ETH is not the strategy token: the strategy account value is Curve LP `curveLpToken`, and `_depositInCurve` only consumes the WETH balance it unwraps in that call. There is no function that forwards `address(this).balance` to a recipient; `transferToken` is `onlyOwner` but executes `IERC20Detailed(_token).safeTransfer(_to, value)`, which cannot move native ETH. The result is a permanent native-token lock rather than an ERC20 leftover that `transferToken` can rescue. [3](#0-2) [4](#0-3) 

### Impact Explanation
A mistaken direct ETH transfer, or ETH left behind by an ETH-refunding interaction, becomes permanently locked in the strategy. The loss is the full native amount sent or left, and it is not socialized into tranche NAV because ETH is not `curveLpToken` or a strategy share. This is phase-independent: it does not depend on buffer/running/stopped/defaulted epoch state, fixed-APR/APR0 mode, minted interest, instant withdrawals, or programmable borrowing. [3](#0-2) 

### Likelihood Explanation
Likelihood is user-error dependent rather than attacker-driven extraction. The normal WETH path uses `balanceOf(address(this))`, unwraps that exact WETH amount, and passes `{value: _balance}` to Curve, so routine deposits are not expected to strand ETH. However the bare `receive()` still accepts accidental transfers and ETH dust/refunds, and no privileged rescue can release native ETH even though the owner is honest. [3](#0-2) [2](#0-1) 

### Recommendation
Reject unsolicited ETH outside the internal WETH unwrap flow, e.g. gate `receive()` to `WETH`, or add an owner-only native rescue that sends `address(this).balance` to a nonzero destination. If a native rescue is added, keep it separate from ERC20 `transferToken` and emit an event so stranded ETH remains distinguishable from strategy assets. [1](#0-0) [2](#0-1)

// test/foundry/ConvexStrategyETHNativeLock.t.sol
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";

interface IERC20Rescue {
    function transferToken(address token, uint256 value, address to) external;
    function owner() external view returns (address);
}

contract ConvexStrategyETHNativeLockTest is Test {
    // Reproducible on a mainnet fork against a live ConvexStrategyETH proxy.
    // CONVEX_STRATEGY_ETH must point to the ETH-pool variant with unrestricted receive().
    function test_directEthIsLocked() public {
        address strategy = vm.envAddress("CONVEX_STRATEGY_ETH");
        address sender = makeAddr("directEthSender");
        uint256 amount = 1 ether;

        uint256 pre = strategy.balance;
        vm.deal(sender, amount);
        vm.prank(sender);
        (bool ok,) = strategy.call{value: amount}("");
        assertTrue(ok, "receive() accepts unsolicited ETH");
        assertEq(strategy.balance, pre + amount, "ETH is now held by strategy");

        address owner = IERC20Rescue(strategy).owner();
        vm.prank(owner);
        try IERC20Rescue(strategy).transferToken(address(0), amount, sender) {
            // Even if this low-level token call did not revert, ERC20 rescue cannot
            // represent native ETH. There is no native sweep function to call.
        } catch {}

        assertEq(strategy.balance, pre + amount, "native ETH remains locked");
    }
}
