### Title
Unpermissioned `migrate_v1_to_v2` Grants `DisplayCap<T>` to Any `LegacyDisplay<T>` Holder Without Type-Ownership Check — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

### Summary
`migrate_v1_to_v2<T>` accepts any `LegacyDisplay<T>` by value and unconditionally issues a fresh `DisplayCap<T>` via `new_display`. Because `sui::display::Display<T>` carries `store`, it is publicly transferable. Any address that receives a `LegacyDisplay<T>` — regardless of whether they ever held the `Publisher` for `T` — can call this function, obtain the canonical `DisplayCap<T>` for type `T`, and permanently prevent the legitimate type owner from ever claiming their own capability.

### Finding Description
`migrate_v1_to_v2` is a public function with no caller restriction:

```move
// display_registry.move:149-159
public fun migrate_v1_to_v2<T: key>(
    registry: &mut DisplayRegistry,
    legacy: LegacyDisplay<T>,
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    let (mut display, cap) = new_display<T>(registry, ctx);  // no auth check
    display.fields = *legacy.fields();
    legacy.destroy();
    (display, cap)
}
```

`new_display` creates the one-and-only derived `Display<T>` for the registry and binds `cap_id` to the newly minted `DisplayCap<T>`. After this call:
- `derived_object::exists` returns `true` for `DisplayKey<T>`, so no second `Display<T>` can ever be created.
- `display.cap_id` is `some(attacker_cap_id)`, so `claim` and `claim_with_publisher` both abort on `ECapAlreadyClaimed`.

The legitimate type owner is permanently locked out of managing their own display.

The precondition — that no `Display<T>` yet exists in the registry — is realistic: the system snapshot migration is performed type-by-type by the `SystemMigrationCap` holder, so there is a window (or permanent gap for types never system-migrated) where the registry entry is absent.

### Impact Explanation
- **Unauthorized `DisplayCap<T>` creation**: an attacker who never held `Publisher` for `T` obtains the sole capability authorizing `set`, `unset`, and `clear` on the canonical `Display<T>`.
- **Permanent state corruption**: the legitimate type owner can never reclaim authority over their display; `cap_id` is irrevocably bound to the attacker's object.
- **Display metadata hijack**: the attacker can set arbitrary `name`, `link`, `image`, `description` fields, enabling phishing, brand impersonation, or silent metadata poisoning for all objects of type `T` across every client that resolves display via the registry.

This satisfies the Critical gate: *state corruption from unauthorized object creation* — an unprivileged actor creates a `DisplayCap<T>` they are not entitled to, corrupting the registry's ownership invariant for type `T`.

### Likelihood Explanation
`LegacyDisplay<T>` has `store`, so it circulates freely: it can be sold on marketplaces, stored in shared objects, or accidentally transferred. Any of these paths delivers a `LegacyDisplay<T>` to an attacker. The attack requires a single public transaction with no special resources beyond possession of the object.

### Recommendation
Add a type-ownership check inside `migrate_v1_to_v2`, mirroring `new_with_publisher`:

```move
public fun migrate_v1_to_v2<T: key>(
    registry: &mut DisplayRegistry,
    publisher: &Publisher,          // add Publisher proof
    legacy: LegacyDisplay<T>,
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    assert!(publisher.from_package<T>(), ENotValidPublisher);
    let (mut display, cap) = new_display<T>(registry, ctx);
    display.fields = *legacy.fields();
    legacy.destroy();
    (display, cap)
}
```

Alternatively, derive the authorized migrator from the `LegacyDisplay<T>` object's original creator address if that metadata is available, or require both a `Publisher` and the `LegacyDisplay<T>`.

```move
module attacker::exploit;

use sui::display_registry::{Self, DisplayRegistry};
use sui::display::Display as LegacyDisplay;
use sui::transfer;

public entry fun steal_display_cap<T: key>(
    registry: &mut DisplayRegistry,

    // Legitimate owner can never call claim() or claim_with_publisher() again.
    display.share();
    transfer::public_transfer(cap, ctx.sender());
}
```

Steps:
1. Obtain any `LegacyDisplay<T>` (e.g., buy on a marketplace, receive a transfer).
2. Confirm no `Display<T>` exists in the registry yet for type `T`.
3. Call `steal_display_cap<T>(registry, legacy_display)`.
4. Assert `DisplayCap<T>` is returned and `display.cap_id()` equals the attacker's cap ID.
5. Call `display_registry::set` with the attacker's cap to overwrite display fields — succeeds.
6. Legitimate type owner calls `claim_with_publisher` — aborts with `ECapAlreadyClaimed`.

```text
fun new_display<T>(
    registry: &mut DisplayRegistry,
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    let key = DisplayKey<T>();
    assert!(!derived_object::exists(&registry.id, key), EDisplayAlreadyExists);
    let cap = DisplayCap<T> { id: object::new(ctx) };
    let display = Display<T> {
        id: derived_object::claim(&mut registry.id, key),
        fields: vec_map::empty(),
        cap_id: option::some(cap.id.to_inner()),
    };
    (display, cap)
}
```
