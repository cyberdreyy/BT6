### Title
Zip extraction (`ExtractZipArchive`/`extractZipFile`) lacks path-containment checks against the extraction root, unlike `tarzstd` extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` and its helpers `extractZipFile`, `extractZipFileEntry`, and `extractZipSymlinkEntry` use `zip.File.Name` verbatim (via `os.MkdirAll(filepath.Dir(file.Name))`, `os.Create`/`os.OpenFile(file.Name)`, `os.Symlink(...,file.Name)`) with only a `.git`-directory check (`errorIfGitDirectory`), no `filepath.Abs`/prefix containment check against the target directory. This is inconsistent with `tarzstd`'s extractor, which explicitly resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path not prefixed by `e.dir` (`chroot` enforcement).

### Finding Description
`helpers/archives/zip_extract.go` defines `extractZipFile` at lines 61-83, which calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, or `extractZipFileEntry`, all operating directly on `file.Name` with no transformation relative to a target directory and no rejection of `..`/absolute paths. [1](#0-0) 
`ExtractZipArchive` (lines 85-110) iterates `archive.File`, checking only `errorIfGitDirectory(file.Name)` (which merely detects `.git` path components, see `helpers/archives/path_check_helper.go` lines 13-19), then calls `extractZipFile(file)` directly. [2](#0-1) 

By contrast, `tarzstd`'s `extractor.Extract` computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and enforces `strings.HasPrefix(path, e.dir+string(filepath.Separator))`, rejecting any traversal outside the chroot directory `e.dir` with an explicit error. [3](#0-2) 

The reachable call chain is: `CacheExtractorCommand.Execute` obtains the working directory `wd` and constructs the extractor via `archive.NewExtractor(format, f, size, wd)` [4](#0-3)  → for the `Zip`/`ZipZstd` format, this resolves by default to `ziplegacy.NewExtractor` (registered in `ziplegacy`'s `init()`, only overridden by `fastzip.NewExtractor` when `FF_USE_FASTZIP` is enabled) [5](#0-4)  → `ziplegacy.extractor.Extract` opens the zip reader and calls `archives.ExtractZipArchive(zr)`, discarding the `e.dir` field entirely (it is never passed into `ExtractZipArchive`). [6](#0-5) 

Because `ExtractZipArchive` never receives or uses a target directory, and never normalizes/validates `file.Name`, an entry such as `../../../../tmp/evil` or an absolute path is written using `file.Name` as-is relative to the process's current working directory, with no containment check.

### Impact Explanation
An unprivileged CI job author who can control the content of a cache archive that will later be extracted by `CacheExtractorCommand` (or artifacts extracted through the same zip path) using the default (non-fastzip) zip format can supply a crafted zip file with an entry name containing `../` traversal or an absolute path. When extracted, this can write or overwrite arbitrary files anywhere the runner process has write permission (subject to OS/user permissions), which is a path-traversal/arbitrary file write outside the intended job/cache extraction root — differing from the `tarzstd` extractor's explicit chroot enforcement for equivalent input.

### Likelihood Explanation
Preconditions: the cache/artifact configuration must use the zip format via the `ziplegacy` extractor path (this is the default unless `FF_USE_FASTZIP` is enabled, per `commands/helpers/archiver.go` init logic), and the attacker must control the archive content that will be extracted for their own job (their own cache upload, or a cache/artifact reused across jobs they control). Given zip is the historically default cache/artifact format and `ziplegacy.NewExtractor` is registered unconditionally while `fastzip.NewExtractor` is opt-in via feature flag, this is readily reachable and repeatable — an attacker just needs to run a job that populates and then later extracts a crafted cache archive.

### Recommendation
Pass the intended extraction root into `ExtractZipArchive`/`extractZipFile` (mirroring `ziplegacy.extractor.dir`) and apply the same containment check used by `tarzstd`: resolve `filepath.Abs(filepath.Join(dir, file.Name))` and reject any path where the resolved absolute path is not prefixed by `dir + separator` (or equal to `dir`), for both regular files and symlink targets/destinations, before performing any `MkdirAll`/`Create`/`Symlink` operation.

### Proof of Concept
Add a differential unit test in `helpers/archives/zip_extract_test.go` (or `commands/helpers/archiver_test.go` using `OnEachArchiver`) that:
1. Creates a zip archive with a single entry named `../evil.txt` (or `../../../../tmp/evil`).
2. Calls `ziplegacy.NewExtractor(reader, size, dir).Extract(ctx)` with `dir` set to a temp directory, and asserts that the file was NOT created outside `dir` — expect this assertion to currently FAIL (bug reproduced), i.e., the file gets created outside `dir`.
3. Performs the same test using `tarzstd.NewExtractor(reader, size, dir).Extract(ctx)` with an equivalent tar entry named `../evil.txt`, and asserts `Extract` returns an error containing `"cannot be extracted outside of chroot"` — expect this to PASS, demonstrating the inconsistency.
4. Assert `os.Stat(filepath.Join(filepath.Dir(dir), "evil.txt"))` succeeds for the zip case (proving write escaped `dir`) and fails/no-op for the tar case.

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
```
