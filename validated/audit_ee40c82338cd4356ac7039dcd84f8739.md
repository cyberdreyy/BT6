### Title
Signature Malleability in `BlockRejection` Enables Cross-Context Reason-Code Forgery Attributed to a Legitimate Signer - (File: `libsigner/src/v0/messages.rs`)

### Summary
`BlockRejection::hash()` computes the signed digest over only `signer_signature_hash` and `chain_id`, leaving `reason`, `reason_code`, `metadata`, and — critically — `response_data` (which carries `reject_reason`, `failed_txid`, `tenure_extend_timestamp`, etc.) entirely outside the signature's commitment. `verify()`/`recover_public_key()` therefore only prove "this signer rejected block H on this chain," not which reason or auxiliary data they attached. This mirrors the reported bug class: a security-relevant "envelope" (here, the reason/response data) sits unprotected next to a value that receivers use to authenticate and attribute trust (the recovered signer identity), letting an attacker splice untrusted content behind a valid signature. [1](#0-0) 

### Finding Description
`BlockRejection::hash()` builds the structured-data digest from only `self.signer_signature_hash` and `self.chain_id`: [2](#0-1) 

`recover_public_key()`/`verify()` operate on this same narrow digest: [3](#0-2) 

Both `signer_signature_hash` (the block hash being rejected — public once any block proposal is broadcast) and `chain_id` (fixed per network) are values an attacker can always know in advance, without needing the rejecting signer's private key. Consequently, any signature that a legitimate signer `A` has ever published over a given `(signer_signature_hash, chain_id)` pair remains valid for **any** other `reason` / `reason_code` / `response_data` combination bound to that same pair. A malicious signer `C` (a legitimate, weighted member of the signer set, but without `A`'s key) can:
1. Observe one authentic `BlockRejection` from `A` for block hash `H` (any reason).
2. Construct a new `BlockRejection` for the same `H`/`chain_id`, but with an attacker-chosen `reason_code`/`response_data` (e.g., swap in `RejectCode::ValidationFailed(ValidateRejectCode::ProblematicTransaction)` and an arbitrary `response_data.failed_txid`), reusing `A`'s stolen signature bytes verbatim.
3. Publish this forged message through `C`'s own StackerDB slot. This succeeds because the *outer* StackerDB chunk-level signature (`SlotMetadata::sign`/`verify`, which does bind the full byte content via `data_hash`) is signed by `C`'s own key over `C`'s own slot — it has no notion that the *inner* `BlockRejection.signature` claims to be authored by someone else. [4](#0-3) 

On the consuming side, `handle_block_rejection` recovers the pubkey from the *inner* (weak) signature and only checks that it belongs to *some* valid signer — it never confirms the recovered identity matches the slot/writer the chunk was actually read from: [5](#0-4) 

This lets `C` inject a forged rejection that the local state machine and monitoring attribute to `A`, using `A`'s real signer weight, for a `reason_code`/`response_data.failed_txid` that `A` never actually endorsed.

The node-side `stackerdb_listener.rs` uses the same weak, content-decoupled signature to attribute rejected-transaction weight per `failed_txid`/`reason_code` bucket: [6](#0-5) 

Here it *does* additionally check `rejected_pubkey != signer_pubkey` against the slot's expected owner, which blocks cross-slot impersonation in this particular listener. However, the signer-to-signer path in `stacks-signer/src/v0/signer.rs` (`handle_block_rejection`) has no equivalent slot-to-identity binding check — it accepts any recovered pubkey that is merely a member of the valid signer set, and then uses that recovered address (not the slot writer) for `store_and_process_block_rejection`.

### Impact Explanation
This breaks the equality between "the reason/response data attributed to signer A" and "what signer A actually validated/signed." A single non-majority signer can:
- Forge a `failed_txid`/`ValidateRejectCode::ProblematicTransaction` attribution onto another signer's real weight, corrupting the per-txid weighted rejection tallies (`compute_reject_code_signing_weight`, `failed_txids` in the node listener) used to decide whether a transaction should be excluded from future blocks — this is a miscounted/misattributed rejection, not requiring a majority of signers.
- Potentially manipulate which `RejectReasonPrefix` category crosses the 30%/70% thresholds that drive miner-invalidation and rejection-count logic in `store_and_process_block_rejection`, since the reason category used for weight bucketing is taken from the forged (unsigned) `response_data.reject_reason`/`reason_code`, not from data the impersonated signer actually attested to.

This falls under "a rejection recounted/misattributed" — a concrete safety-relevant miscount achievable by a single signer with no special access beyond normal StackerDB write ability to their own slot.

### Likelihood Explanation
Any legitimate signer's rejection for a given block is broadcast in plaintext over StackerDB and is trivially observable by every other signer (and node). Reusing the raw signature bytes across a differently-populated `BlockRejection` struct requires no cryptographic effort — it is a pure copy-paste of the `signature` field into a new struct with different `reason`/`reason_code`/`response_data`. The only requirement is that the attacking signer be a legitimate signer able to write to their own StackerDB slot, which is a normal operating condition, not a majority-compromise scenario.

### Recommendation
Extend `BlockRejection::hash()` (and the analogous domain for `BlockAccepted`/`BlockResponseData` if applicable) to include `reason`, `reason_code`, `metadata`, and all fields of `response_data` (including `failed_txid`) in the signed digest, so the signature commits to the entire semantic content of the rejection rather than only `signer_signature_hash`/`chain_id`. Additionally, in `stacks-signer/src/v0/signer.rs::handle_block_rejection`, tie the recovered public key to the StackerDB slot the message chunk was read from (as `stacks-node/src/nakamoto_node/stackerdb_listener.rs` partially does), rather than only checking set membership via `is_valid_signer`.

### Proof of Concept
1. Signer `A` legitimately rejects block with `signer_signature_hash = H` on mainnet (`chain_id = CHAIN_ID_MAINNET`) with `reason_code = RejectCode::ValidationFailed(ValidateRejectCode::InvalidBlock)`; this produces `sig = A.sign(hash(H, chain_id))`, broadcast in `A`'s StackerDB slot per [7](#0-6) .
2. Malicious signer `C` observes this broadcast, extracts `H`, `chain_id`, and the raw `sig` bytes.
3. `C` builds a new `BlockRejection { signer_signature_hash: H, chain_id, signature: sig, reason_code: RejectCode::ValidationFailed(ValidateRejectCode::ProblematicTransaction), response_data: BlockResponseData { failed_txid: Some(<victim_txid>), .. }, .. }`. Because `hash()`/`verify()` only cover `H`/`chain_id` [8](#0-7) , `rejection.verify(&A_pubkey)` and `rejection.recover_public_key()` both succeed and resolve to `A`.
4. `C` wraps this in `SignerMessage::BlockResponse(BlockResponse::Rejected(rejection))`, serializes it, and writes it into `C`'s own StackerDB slot with a valid outer `StackerDBChunkData` signature from `C`'s own key.
5. Any receiver processing this via `handle_block_rejection` in `stacks-signer/src/v0/signer.rs` recovers pubkey `A`, confirms `A` is a valid signer via `is_valid_signer`, and calls `store_and_process_block_rejection` attributing `A`'s weight to the forged `ProblematicTransaction`/`victim_txid` rejection [9](#0-8)  — even though `A` never rejected on that basis.

    pub fn hash(&self) -> Sha256Sum {
        let domain_tuple = make_structured_data_domain("block-rejection", "1.0.0", self.chain_id);
        let data = Value::buff_from(self.signer_signature_hash.as_bytes().into()).unwrap();
        structured_data_message_hash(data, domain_tuple)
    }

    /// Sign the block rejection and set the internal signature field
    fn sign(&mut self, private_key: &StacksPrivateKey) -> Result<(), String> {
        let signature_hash = self.hash();
        self.signature = private_key.sign(signature_hash.as_bytes())?;
        Ok(())
    }

    /// Verify the rejection's signature against the provided signer public key
    pub fn verify(&self, public_key: &StacksPublicKey) -> Result<bool, String> {
        if self.signature == MessageSignature::empty() {
            return Ok(false);
        }
        let signature_hash = self.hash();
        public_key
            .verify(&signature_hash.0, &self.signature)
            .map_err(|e| e.to_string())
    }

    /// Recover the public key from the rejection signature
    pub fn recover_public_key(&self) -> Result<StacksPublicKey, &'static str> {
        if self.signature == MessageSignature::empty() {
            return Err("No signature to recover public key from");
        }
        let signature_hash = self.hash();
        StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            signature_hash.as_bytes(),
            &self.signature,
        )
    }

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// Handle an observed rejection from another signer
    fn handle_block_rejection(
        &mut self,
        rejection: &BlockRejection,
        sortition_state: &mut Option<SortitionsView>,
    ) {
        debug!("{self}: Received a block-reject signature: {rejection:?}");

        let block_hash = &rejection.signer_signature_hash;
        let signature = &rejection.signature;

        // recover public key
        let Ok(public_key) = rejection.recover_public_key() else {
            debug!("{self}: Received block rejection with an unrecovarable signature. Will not store.";
               "signer_signature_hash" => %block_hash,
               "signature" => %signature
            );
            return;
        };

        // authenticate the signature -- it must be signed by one of the stacking set
        let signer_address = StacksAddress::p2pkh(self.mainnet, &public_key);
        if !self.is_valid_signer(&signer_address) {
            debug!("{self}: Received block rejection with an invalid signature. Will not store.";
                "signer_public_key" => ?public_key,
                "signer_address" => %signer_address,
                "signer_signature_hash" => %block_hash,
                "signature" => %signature
            );
            return;
        }

        let Some(mut block_info) = self.block_lookup_by_reward_cycle(block_hash) else {
            if let Err(e) = self.signer_db.add_pending_block_rejection_response(
                block_hash,
                &signer_address,
                (&rejection.response_data.reject_reason).into(),
            ) {
                warn!("{self}: Failed to add pending block rejection response: {e:?}");
            }
            return;
        };

        info!("{self}: Received block rejection";
            "signer_pubkey" => public_key.to_hex(),
            "signer_signature_hash" => %block_hash,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "reject_reason" => ?rejection.response_data.reject_reason,
        );

        self.store_and_process_block_rejection(
            sortition_state,
            &mut block_info,
            &signer_address,
            (&rejection.response_data.reject_reason).into(),
        );
