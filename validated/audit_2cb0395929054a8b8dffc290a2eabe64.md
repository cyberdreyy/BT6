### Title
Unbounded recursive MPT node decoding causes stack-exhaustion DoS in the fault-proof program - (File: crates/proof/mpt/src/list_walker.rs, crates/proof/mpt/src/node.rs)

### Summary
`TrieNode::decode` and `OrderedListWalker::fetch_leaves` recursively decode/traverse Merkle Patricia Trie nodes with no depth limit, mirroring the CVE-2018-16646 pattern (Poppler `Parser::getObj()` recursing without bound on crafted input). An attacker who controls the L1 data that the fault-proof program derives from (transaction/receipt trie preimages resolved through the preimage oracle during a dispute game) can construct a deeply chained sequence of blinded `Extension`/`Branch` nodes that forces unbounded native-stack recursion.

### Finding Description
`TrieNode::decode` recursively calls itself when decoding an `Extension` node's inner pointer, and `Vec::<Self>::decode` recurses through `Branch` children: [1](#0-0) [2](#0-1) 

Separately, `OrderedListWalker::fetch_leaves`, used to hydrate a derivable ordered list (e.g. the L1 transactions/receipts trie consumed during derivation), recurses through `Branch`/`Extension` chains and re-fetches/decodes each blinded child via the trie provider, again without any recursion-depth cap: [3](#0-2) 

Neither `TrieNode::decode` nor `fetch_leaves` enforces a maximum trie depth or iteration bound; a chain of `Extension { node: Blinded }` entries (or nested `Branch` with a single populated slot pointing to another `Branch`) can be made arbitrarily deep by an attacker who controls the L1 preimages resolved into the fault-proof program's trie provider, causing each level to consume additional native stack frames.

### Impact Explanation
The fault-proof program derives L2 outputs from attacker-observable/attacker-influenced L1 chain data (transaction/receipt/deposit tries). Crafting a maliciously deep trie forces `fetch_leaves`/`TrieNode::decode` into unbounded recursion, exhausting the native stack of the fault-proof program (or any host process using this crate to walk untrusted preimages). This can crash the process computing the provable output root during a dispute game, matching the CVE's DoS class ("node halt" / inability to produce the correct provable output).

### Likelihood Explanation
Reachability requires only that an attacker can get their L1 data (deposit transactions, receipts, or other derivable trie contents) included and later resolved as MPT preimages during derivation/fault-proof execution — no privileged role or sequencer/builder cooperation is needed, satisfying the "attacker-written L1 deposit and system-config data" reachability class. Building a chain of nested extension/branch nodes of sufficient depth is a straightforward, low-cost construction.

### Recommendation
Add an explicit recursion/iteration depth bound (matching the maximum possible MPT depth for the given key space, e.g. 64 nibble levels for 32-byte keys) in both `TrieNode::decode` and `OrderedListWalker::fetch_leaves`, returning an error instead of recursing further once the bound is exceeded. Consider converting the recursive `fetch_leaves` traversal into an explicit stack-based (heap-allocated work list) iterative implementation to remove native-stack dependence entirely.

### Proof of Concept
Construct trie preimages as a chain: `Extension_0 -> Blinded(hash(Extension_1))`, `Extension_1 -> Blinded(hash(Extension_2))`, ..., for N (e.g. tens of thousands) levels, each preimage inserted into the `TrieProvider`'s preimage map. Call `OrderedListWalker::try_new_hydrated` (or directly `TrieNode::decode`) with the root pointing at `Extension_0`; the resulting recursive calls in `fetch_leaves`/`TrieNode::decode` will exhaust the native stack before reaching the terminal leaf, crashing the process.

Note: I was unable to find any independent depth-limiting logic elsewhere in the `mpt` crate or in the fault-proof program's call sites that would cap trie depth before invoking these functions; if such a guard exists outside the indexed portion of the codebase (e.g., in a caller not covered by the index), it would mitigate this finding — this should be verified in a full repository checkout.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }
