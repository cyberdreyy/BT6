### Title
Instant withdrawals bypass upfront management fees - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
An allowed tranche holder can use the instant-withdrawal branch of `requestWithdraw` to redeem the full current tranche value without paying the upfront management fee charged to ordinary withdrawal receipts. When the honest manager lowers the pool APR by more than `instantWithdrawAprDelta`, the function returns before `_totalWithdrawFees` is evaluated, creating an unprivileged fee-bypass path analogous to avoiding a swap’s taker fee through an alternative liquidity route.

### Finding Description
`requestWithdraw` first converts tranche tokens to underlying at the current tranche price. If instant withdrawals are enabled and `lastEpochApr > currentApr + instantWithdrawAprDelta`, it calls `requestInstantWithdraw` and performs `_withdrawOps` for the unmodified underlying amount. [1](#0-0) 

For an ordinary withdrawal request, execution continues to `_calcInterestWithdrawRequest`, calculates `totalFees`, deducts those fees from the receipt, and records them in `pendingWithdrawFees`. [2](#0-1) 

The fee includes an upfront management fee over the withdrawal receipt’s expected settlement duration. [3](#0-2) 

That duration is one epoch plus the remaining buffer period when the request is made during the buffer. [4](#0-3) 

By contrast, `IdleCreditVault.requestInstantWithdraw` mints the user a receipt equal to the full requested amount and adds the entire amount to `pendingInstantWithdraws`; no fee or pending-fee accounting is applied. [5](#0-4) 

### Impact Explanation
The protocol loses the upfront management fee that an equivalent normal withdrawal request is designed to collect. With a 1% annualized management fee, a 30-day epoch, and a 5-day remaining buffer, the bypassed fee is approximately:

```text
principal * 1% * 35 days / 365 days
≈ principal * 0.0009589
```

Thus, an instant request for 1,000,000 underlying avoids approximately 958.9 underlying in management fees. Because `requestWithdraw` returns before `pendingWithdrawFees += totalFees`, the fee is neither collected nor accrued.

### Likelihood Explanation
The path requires an honest APR reduction sufficient to satisfy `lastEpochApr > currentApr + instantWithdrawAprDelta` while instant withdrawals are enabled. Any wallet passing `isWalletAllowed` and holding tranche tokens can then call `requestWithdraw`; no privileged role, borrower cooperation, oracle manipulation, default, or malformed input is required. [6](#0-5) 

### Recommendation
Apply the same fee policy consistently before branching into instant or ordinary withdrawal handling. If instant withdrawals are intentionally charged a shorter settlement duration, calculate a dedicated instant-withdrawal management fee and deduct it from `_underlyings` before `requestInstantWithdraw`; otherwise route the amount through equivalent `_totalWithdrawFees` accounting and increase `pendingWithdrawFees` before creating the instant receipt.

### Proof of Concept
The following Foundry scenario can be added to the existing `IdleCreditVault.t.sol` environment. The manager remains honest and only performs the normal epoch transition and APR update; the unprivileged allowed user chooses the instant-withdrawal route.

```solidity
function testInstantWithdrawBypassesUpfrontManagementFee() external {
    uint256 depositAmount = 1_000_000 * ONE_SCALE;
    uint256 mgmtFeeRate = 1_000; // 1% annualized

    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, mgmtFeeRate);

    uint256 mintedAA = idleCDO.depositAA(depositAmount);
    _transferBurnedTrancheTokens(address(this), true);

    _startEpochAndCheckPrices(0);

    // Honest manager ends the epoch and lowers APR enough to activate
    // the instant-withdrawal branch.
    _stopEpochAndCheckPrices(0, initialProvidedApr / 2, _expectedFundsEndEpoch());

    uint256 principal =
        mintedAA * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;
    uint256 expectedMgmtFee = _calcManagementFee(
        principal,
        mgmtFeeRate,
        cdoEpoch.epochDuration() + cdoEpoch.bufferPeriod()
    );

    uint256 requested =
        cdoEpoch.requestWithdraw(mintedAA, address(AAtranche));

    // The user receives a receipt for the full principal and no fee is booked.
    assertEq(requested, principal);
    assertEq(cdoEpoch.pendingWithdrawFees(), 0);
    assertEq(
        IdleCreditVault(address(strategy)).instantWithdrawsRequests(address(this)),
        principal
    );
    assertGt(expectedMgmtFee, 0);

    // Fund fulfillment with fresh buffer deposits, then claim the full amount.
    _depositWithUser(makeAddr("instant-funder"), depositAmount, true);
    _startEpochAndCheckPrices(1);

    uint256 balanceBefore = underlying.balanceOf(address(this));
    cdoEpoch.claimInstantWithdrawRequest();

    assertEq(
        underlying.balanceOf(address(this)) - balanceBefore,
        principal
    );
}
```

An equivalent normal request would return `principal + projectedInterest - _totalWithdrawFees(...)`, with the management-fee component recorded in `pendingWithdrawFees`; the instant path returns and pays the full principal without that deduction.

  /// @notice Calculate total fees charged on a withdrawal request.
  /// @param _principal Principal leaving live NAV.
  /// @param _interest Projected interest for the requested principal.
  /// @return Total management and performance fees to subtract from principal plus projected interest.
  function _totalWithdrawFees(uint256 _principal, uint256 _interest) private view returns (uint256) {
    uint256 _mgmtFee = _calculateManagementFee(_principal, _withdrawRequestManagementFeeDuration());
    // When interest covers management fees, interest - netGain equals management fee plus performance fee.
    return _mgmtFee >= _interest ?
      _mgmtFee :
      _interest - _netGainAfterFees(_interest, _mgmtFee);

  function requestInstantWithdraw(uint256 _amount, address _user) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // increase the instant withdraw requests for the user
    instantWithdrawsRequests[_user] += _amount;
    uint256 currentEpoch = epochNumber;
    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"
    // from old funded instant receipts.
    instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
    pendingInstantWithdraws += _amount;
