### Title
Web API capabilities gateway handler forwards every signed user request to all DON nodes with no allowlist or rate-limit check - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The `MasterSpotter.HandleTokenMintAndSwap` report describes a handler that decodes an event but never implements the intended access-control/processing logic ("TODO handle?"). The direct analog in this codebase is the WebAPI capabilities gateway handler's `HandleLegacyUserMessage`, which decodes and validates the incoming message's signature/schema but explicitly skips the allowlist and rate-limiting step it is supposed to perform, marked with a literal `// TODO: apply allowlist and rate-limiting here` comment, before broadcasting the request to every node in the DON.

### Finding Description
`handler.HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` processes externally-supplied `api.Message` payloads reaching the gateway from unprivileged clients. It unmarshals the payload, checks the timestamp for staleness, and then hits: [1](#0-0) 

immediately followed by unconditionally forwarding the request to every DON member: [2](#0-1) 

The only validation performed before this fan-out is `msg.Validate()` (via `common.ValidatedRequestFromMessage`), which checks structural constraints and ECDSA signature recovery of the sender address (`m.Body.Sender`), but does not check that sender against any DON-specific allowlist or apply per-sender rate limiting: [3](#0-2) [4](#0-3) 

This is consistent with the test suite's own explicit acknowledgment that this control is missing: [5](#0-4) 

By contrast, sibling gateway handlers (`vault`, `confidentialrelay`) do implement authorization/rate-limiting explicitly — e.g. the vault gateway handler calls `AuthorizeRequest` before processing, and confidentialrelay enforces per-node rate limiters: [6](#0-5) [7](#0-6) 

showing that this handler is the outlier lacking the intended control.

### Impact Explanation
Any client able to reach the gateway's HTTP endpoint and craft a validly-signed (any ECDSA keypair works — signature verification just recovers whatever address signed it, it does not check DON membership) `web_api_trigger` legacy message can have it forwarded to every node of the target DON, with no allowlist restricting which senders/workflow owners may trigger, and no rate limiting bounding request volume from a single sender. This can be used to flood DON nodes with attacker-controlled trigger requests (resource exhaustion / DoS against node capability processing) or to trigger workflow executions that should be restricted to permitted callers, since the fan-out to `don.SendToNode` happens unconditionally once basic structural/signature validation passes.

### Likelihood Explanation
High for reachability: `ProcessRequest` in `core/services/gateway/gateway.go` routes any incoming legacy (DonId-bearing) JSON-RPC request straight to the resolved handler's `HandleLegacyUserMessage` without any allowlist gate at the gateway layer itself: [8](#0-7) 
Combined with the handler's own missing allowlist/rate-limit step, an unprivileged network client only needs a valid EC keypair to sign the message body — no privileged credential, node key, or DON membership check is required to reach the fan-out.

### Recommendation
Implement the allowlist and rate-limiting check called out by the TODO comment in `HandleLegacyUserMessage` before saving the callback and forwarding to DON members — mirror the pattern used in the vault (`Authorizer.AuthorizeRequest`) and confidentialrelay (`globalNodeRateLimiter`/`perNodeRateLimiters`) handlers so that only allowlisted senders can trigger `web_api_trigger` and per-sender/global request volume is bounded.

### Proof of Concept
1. Generate an arbitrary ECDSA keypair (not registered with the DON in any way).
2. Construct an `api.Message` with `Body.Method = "web_api_trigger"`, a valid `Body.DonId`, a fresh `Timestamp` in the trigger payload, and a valid `webapicap.TriggerRequestPayload`.
3. Sign the message with the arbitrary keypair via `Message.Sign`.
4. Submit the request through the gateway's HTTP endpoint so it reaches `gateway.ProcessRequest` → `handler.HandleLegacyUserMessage`.
5. Observe that despite the sender being unknown/unauthorized, the message passes `msg.Validate()` (signature recovers to an arbitrary but well-formed address) and is forwarded via `don.SendToNode` to every DON member — confirming no allowlist or rate-limit rejection occurs, as also demonstrated by the handler test's explicit `// TODO: Validate Senders and rate limit check` comment at `core/services/gateway/handlers/capabilities/handler_test.go:365`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}
