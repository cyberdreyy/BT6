### Title
Zip extraction follows attacker-created symlinks allowing arbitrary out-of-root file writes - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipSymlinkEntry` creates a filesystem symlink from an attacker-controlled zip entry's link target with no validation that the target stays within the extraction root, and `ExtractZipArchive` processes entries strictly in zip order (not symlinks-last). A subsequent entry named e.g. `link/payload` is then written via `extractZipFileEntry`'s `os.OpenFile`, which follows the pre-created symlink through its path component, letting an attacker redirect the write to an arbitrary directory outside the workspace.

### Finding Description
`extractZipSymlinkEntry` reads the link target directly from the zip entry's file data and calls `os.Symlink(string(data), file.Name)` with no check that `data` (the target) resolves inside the extraction directory: [1](#0-0) 

`extractZipFileEntry` then opens `file.Name` for writing with `os.OpenFile(..., O_WRONLY|O_CREATE|O_TRUNC, ...)`. If `file.Name` contains a path component that is a symlink (created by a prior entry in the same archive), the OS will transparently follow it when resolving the path, so the write lands wherever the symlink points: [2](#0-1) 

`ExtractZipArchive` iterates `archive.File` in a single pass, in the order entries appear in the zip, calling `extractZipFile` (which dispatches to the symlink/dir/regular-file handlers) for every entry with no reordering to defer symlinks: [3](#0-2) 

This is the same class of bug the tarzstd extractor was fixed against (deferring symlink creation), but no equivalent protection exists here — there is no check anywhere in `zip_extract.go`/`path_check_helper.go` that validates a symlink's target or the resolved final path stays under the intended extraction root; the only existing guard (`errorIfGitDirectory`) only rejects `.git`-prefixed entry names, not symlink escapes.

Exploit flow: attacker crafts a zip with entry `link` of type symlink whose link data is an absolute or relative path pointing outside the workspace (e.g. a directory the runner process can write to, such as `/tmp` or a path traversal like `../../../somewhere`), followed by entry `link/payload` (regular file) containing attacker content. `ExtractZipArchive` processes `link` first via `extractZipSymlinkEntry`, creating the symlink on disk, then processes `link/payload` via `extractZipFileEntry`, whose `os.OpenFile` call follows the `link` symlink and writes `payload`'s content into the attacker-chosen external directory.

### Impact Explanation
An attacker who controls artifact/cache zip content can write attacker-controlled file content to arbitrary writable locations on the host outside the job's build/workspace root, limited only by filesystem permissions of the runner process. This violates the invariant that "file operations must stay within intended build/cache/artifact roots" and can lead to file corruption, planting of files in unexpected locations reachable by later jobs or host processes, or overwriting files the runner process has write access to.

### Likelihood Explanation
This requires only the ability to control artifact archive content (a normal pipeline author uploading a crafted artifact/cache zip), and relies on the archive being extracted through the legacy zip path (`helpers/archives/zip_extract.go`'s `ExtractZipFile`/`ExtractZipArchive`), which is used by the `ziplegacy` extractor path reachable from `commands/helpers/artifacts_downloader.go` via `archive.NewExtractor`. No special privileges are needed beyond normal job/pipeline control, and the exploit is fully deterministic/repeatable given the same zip ordering is preserved by Go's `archive/zip` reader.

### Recommendation
- Defer symlink entry creation until after all regular file/dir entries are processed (mirroring the tarzstd approach), or process entries in two passes: create real files/directories first, symlinks last.
- Validate symlink targets: reject or rewrite symlink entries whose target (after resolving relative to the entry's directory) would resolve outside the extraction root.
- Before every file write in `extractZipFileEntry` (and directory creation in `extractZipDirectoryEntry`), verify that no path component of `file.Name` already exists as a symlink pointing outside the root (e.g., use `filepath.EvalSymlinks` on the parent, or open with `os.O_NOFOLLOW`/`openat`-style relative-root primitives), and abort/skip the entry if it would escape.
- Apply the same path-confinement check already partially done for `.git` (`errorIfGitDirectory`) more generally to reject any entry name or resolved symlink path that escapes the target directory.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Create a temp directory `outsideDir` outside the extraction working directory.
2. Build a zip archive with:
   - Entry `"link"` as a symlink (`FileHeader.SetMode(os.ModeSymlink|0777)`) whose file content (link data) is the absolute path to `outsideDir`.
   - Entry `"link/payload.txt"` as a regular file with attacker content, e.g. `"pwned"`.
3. Call `ExtractZipFile(archivePath)` from within a clean working directory.
4. Assert that `filepath.Join(outsideDir, "payload.txt")` now exists and contains `"pwned"` — proving the write escaped the working directory via the symlink.
5. Expected secure behavior: extraction should either fail/skip the `link/payload.txt` entry or the file should NOT exist under `outsideDir`; test should assert `os.Stat(filepath.Join(outsideDir, "payload.txt"))` returns `os.ErrNotExist` once the fix is applied.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```
