Nothing in `delete_member` scrubs a removed member's confirmation entries from requests they merely *confirmed* (as opposed to requests they *created*), so a stale, phantom confirmation from an ousted member persists and is counted by `confirmations.len()` when checking `>= self.num_confirmations` in `confirm()`.

### Title
Multisig requests can execute below the live-member quorum using stale confirmations from removed members - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` in [1](#0-0)  decides whether to execute a request purely from the size of the `confirmations: HashSet<String>` stored for that `request_id`. `delete_member` in [2](#0-1)  only purges confirmations for requests the removed member *originated* (`r.member == member`), not confirmations that member cast on requests created by others. Consequently a confirmation cast by a member who is later removed remains in the set and keeps counting toward `num_confirmations`, letting a request execute with fewer than `num_confirmations` *currently valid* members.

### Finding Description
The intended custody binding is: **confirmations counted == confirmations from live members**, i.e. `confirmations.len() >= num_confirmations` should only be true when at least `num_confirmations` of those entries belong to accounts/keys still in `self.members`.

`confirm()` never re-checks the membership of the accounts already present in the stored `confirmations` set — it only validates that the *new* caller is a current member via `current_member()` / `assert_valid_request` ( [3](#0-2) ). The threshold check itself is: [4](#0-3) 

`delete_member` removes the departing member from `self.members` and deletes only requests where that member is the *original signer* (`r.member == member`): [5](#0-4) 

It does not scan `self.confirmations` for entries where the removed member merely *confirmed* someone else's request. That confirmation string remains in the `HashSet<String>` for that request forever, and is still counted by `confirmations.len()` in the next `confirm()` call.

### Impact Explanation
This breaks the "confirmations counted vs. live members" custody binding. A request (including a `Transfer` action moving NEAR out of the multisig account) can be executed with fewer than `num_confirmations` currently-authorized signers, because one or more of the counted confirmations belong to members who have since been removed. This is a direct instance of the Critical impact category "a multisig request executed below threshold," matching the RocketPool analog where votes of kicked members still counted toward quorum.

### Likelihood Explanation
No special privilege beyond normal multisig membership churn is required — member turnover (adding/removing members) is a routine, expected multisig operation supported by `AddMember`/`DeleteMember`. Any request that collects partial confirmations before a member-set change becomes exploitable purely by timing: confirm partially, remove a confirmer through an unrelated `DeleteMember` request, then let the remaining conspirators supply just enough additional confirmations to reach the (unchanged) numeric threshold, even though fewer real current members approved it.

### Recommendation
When counting confirmations in `confirm()` (and when exposing `get_confirmations`), filter the stored confirmation set to only those entries whose corresponding `MultisigMember` is still present in `self.members` before comparing against `num_confirmations`. Alternatively, have `delete_member` (and any membership-changing action) iterate all outstanding requests and strip the departing member's confirmation from every request's confirmation set, not just requests they originated.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D, E], num_confirmations = 3)`.
2. Member `B` creates request `R1` (e.g. `Transfer { amount }` to an attacker-controlled `receiver_id`) via `add_request`.
3. `A` calls `confirm(R1)` → `confirmations = {A}` (len 1, `1+1 < 3`, not executed).
4. Separately, `C`, `D`, `E` reach quorum (3 confirmations) on a `DeleteMember { member: A }` self-request, executing `delete_member(A)`. Per `delete_member`, only requests where `r.member == A` (i.e., requests A originated) are purged — `R1` (originated by `B`) is untouched, so `confirmations = {A}` for `R1` survives even though `A` is no longer in `self.members`.
5. `B` calls `confirm(R1)` → `confirmations.len() + 1 = 2` (still `<3`), inserts `B` → `confirmations = {A, B}`.
6. `C` (a legitimate remaining member) calls `confirm(R1)` → `confirmations.len() + 1 = 3 >= num_confirmations` → `execute_request` fires the `Transfer`, moving funds out, even though only `B` and `C` — two real, live members — ever consented; the third "vote" is the phantom confirmation from the removed member `A`, exactly one short of the intended 3-live-member threshold.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));

        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************

        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
