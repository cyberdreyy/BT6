### Title
Stale confirmations from removed multisig members still count toward the execution threshold, allowing a request to execute below the configured `num_confirmations` - (File: multisig2/src/lib.rs, multisig/src/lib.rs)

### Summary
When a multisig member is deleted (`DeleteMember` in `multisig2`, `DeleteKey` in `multisig`), the contract only purges pending *requests that member originally created*. It does **not** purge that member's confirmations recorded on *other* pending requests they merely confirmed. Because `confirm()` counts confirmations purely by size of the stored `HashSet` against `num_confirmations`, without re-validating that every entry in that set is still a live member, a removed member's stale confirmation can still push a still-pending request over the execution threshold — moving funds with fewer live-member approvals than the configured threshold requires.

### Finding Description
In `multisig2/src/lib.rs`, `delete_member` only cleans up requests whose *creator* (`r.member`) equals the removed member: [1](#0-0) 

It never scans `self.confirmations` for entries containing the removed member's identity on *other* requests. `confirm()` then determines execution purely from the stored confirmation set size vs. `num_confirmations`, with no re-check that all counted confirmers are still in `self.members`: [2](#0-1) 

The equality the contract is supposed to maintain is:

```
confirmations_counted(request) == live_members_who_confirmed(request)
```

After a `DeleteMember` action removes a member who had already confirmed some *other* pending request (one they didn't create), that equality breaks: `confirmations_counted(request)` still includes the removed member, while `live_members_who_confirmed(request)` no longer does. If the remaining live confirmations plus this stale one reach `num_confirmations`, `execute_request` runs (including `Transfer`) with fewer authorized live signers than the threshold demands: [3](#0-2) 

The same pattern exists in the older key-based `multisig` contract: `DeleteKey` only removes requests created by that key (`r.signer_pk == pk`), not that key's confirmations on other requests: [4](#0-3) [5](#0-4) 

This is the same bug class as the reported issue: a shared/derived value (resolution deadline / here, confirmation count) is not kept consistent with the entity it's supposed to gate (a specific incident / here, current live membership), so a stale piece of state improperly satisfies a check it should no longer satisfy.

### Impact Explanation
This crosses an authorization/threshold boundary explicitly called out as Critical impact: "a multisig request executed below threshold." A `Transfer`, `AddKey`/`AddMember`, `FunctionCall`, or `DeployContract` request can execute having received confirmation from fewer *currently authorized* members than `num_confirmations` requires, because a removed member's earlier confirmation is still counted. This can result in NEAR being moved, or contract control changed, by a set of signers that no longer meets the configured threshold — i.e., NEAR moved by a party not entitled to it under the multisig's own security policy.

### Likelihood Explanation
No privileged action beyond the multisig's normal operation is required to trigger this: it only requires (1) a member confirms a pending request they didn't create, (2) that member is later removed via a legitimate `DeleteMember`/`DeleteKey` request (e.g., as part of routine membership rotation or revoking a suspected-compromised key), and (3) the original request is later confirmed by remaining members. Steps 1–3 are all ordinary multisig usage; no exploit of a separate bug or attacker-controlled deployment is needed, only the ordering of otherwise normal member/request operations. Because member rotation and long-lived pending requests are both expected features of this contract, the precondition is realistic, not purely theoretical.

### Recommendation
When removing a member (`delete_member` / `DeleteKey`), iterate over `self.confirmations` for *all* pending requests and strip the removed member's entry from each confirmation set (not only requests they created). Alternatively, when counting confirmations in `confirm()`, filter the stored confirmation set to only those entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C}` and `num_confirmations = 2`.
2. `A` calls `add_request` with a `Transfer` action to an attacker-controlled account (request `R`, not auto-confirmed).
3. `B` calls `confirm(R)` → `confirmations[R] = {B}` (1 confirmation, below threshold, so `R` stays pending) — see `confirm()` at [2](#0-1) .
4. Members legitimately decide to revoke `B` (e.g., suspected key compromise) and pass a `DeleteMember { member: B }` request with confirmations from `A` and `C` (reaching threshold 2). `delete_member` executes: it removes `B` from `self.members` and deletes any *requests B created*, but `R` was created by `A`, so `R` and its confirmation set `{B}` are left untouched — see `delete_member()` at [1](#0-0) .
5. Now only `{A, C}` are live members, yet `R.confirmations == {B}` still exists.
6. `A` calls `confirm(R)`. Since `confirmations.len() (1) + 1 == num_confirmations (2)`, `execute_request(R)` runs and the `Transfer` to the attacker executes — authorized effectively by only one live member (`A`) plus one stale, removed member (`B`), instead of two live members as the threshold requires.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(","),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name,
                    args.into(),
                    deposit.into(),
                    Gas::from(gas.0),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
