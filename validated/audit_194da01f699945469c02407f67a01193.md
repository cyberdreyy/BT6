### Title
Miner-controlled activity-timer refresh lets a single miner defeat the inactivity timeout, wedging signers on a stalled tenure — ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`check_latest_block_in_tenure` treats *any* conflicting/reorg-attempt block proposal — even one that is ultimately rejected and never signed — as "miner activity" and refreshes a per-tenure `last_activity_time` counter in `SignerDb`. That counter is the sole input to the inactivity check (`SortitionState::is_timed_out`) that decides whether the signer set should fall back from a stalled/malicious miner to the prior valid tenure. Because the counter can be refreshed by proposals the miner alone controls, with no other signer cooperation and no real chain progress required, a single miner can keep its own tenure "active" forever and prevent the fallback mechanism from ever triggering — a liveness wedge analogous to the reported `TimeLockStrategy` bug, where any attacker-controlled transfer (regardless of legitimacy) refreshes the accumulator that gates the protective mechanism.

### Finding Description
`check_latest_block_in_tenure` [1](#0-0)  is invoked at proposal arrival, at validate-ok, and at signing time. When a proposed block does not advance beyond the tenure's last *signed* block, the code does not just reject it — it also calls `update_last_activity_time` on the proposal's own tenure, as long as that last signed block hasn't yet reached quarter-timeout freshness expiry: [2](#0-1) 

Separately, if no block has been signed yet in the tenure but the signer has locally *pre-committed* (validated + willing-to-sign, but never reached the group signature threshold) to a block at that height, any conflicting re-proposal at the same or lower height is also counted as activity: [3](#0-2) 

Crucially, `mark_pre_committed`/`get_last_accepted_block` reflects this *individual* signer's own local validation state, not a group quorum — a single signer sets `approved_time` on its own DB record as soon as it validates and pre-commits, regardless of whether other signers ever join in. So the "is_fresh_pre_commit" branch can be triggered purely by the local signer's own state plus a miner-controlled re-proposal, no majority of signers required.

`update_last_activity_time`/`get_last_activity_time` are simple upsert/read helpers with no validity or rate constraints of their own: [4](#0-3) 

The inactivity check that gates miner fallback reads exactly this counter, and explicitly documents that once *any* block is signed in the tenure the timeout can never fire — but before that point, it relies entirely on `last_activity_time`: [5](#0-4) [6](#0-5) 

`check_miner_inactivity` in the state machine uses `is_timed_out` as the sole trigger to fall back to the prior tenure's miner; if it never returns true, the fallback branch is unreachable: [7](#0-6) 

**Attack path:** A miner proposes a tenure-start block `B1`. A signer validates and locally pre-commits to `B1` (setting `approved_time`), but the group never reaches the 70% pre-commit/signature threshold (e.g., because the miner deliberately withholds propagation to enough other signers, or a network partition/minority of colluding-but-not-majority signers stall it — no majority is needed by the attacker, only enough friction to prevent *this signer's* group threshold). The miner, entirely on its own and without any other signer's cooperation, key, or a majority, repeatedly re-proposes a competing/duplicate block `B2` at the same height. Every re-proposal runs `check_latest_block_in_tenure`, which — because `B1` is still a "fresh pre-commit" from this signer's own perspective — calls `update_last_activity_time` on the tenure. As long as re-proposals arrive more often than `block_proposal_timeout`, `is_timed_out` never returns true, so `check_miner_inactivity` never falls back to the prior (valid) tenure's miner.

### Impact Explanation
This is a liveness wedge that matches the "signer wedged" impact class: the signer's inactivity/fallback safety valve — the only mechanism by which the signer set abandons a stalled or misbehaving miner's tenure in favor of a still-canonical prior miner — can be permanently suppressed by the miner alone, purely by generating cheap, locally-rejected re-proposals. This can stall the network's block production indefinitely without requiring the miner to ever produce a signable block, and requires operator/governance-level intervention to recover, mirroring the "requires intervention from the smart contract owner" outcome in the referenced report.

### Likelihood Explanation
The mechanism is triggered by ordinary code paths already exercised on every proposal (`check_latest_block_in_tenure` runs on every arrival, validate-ok, and signing evaluation), and the "activity" refresh requires only the local signer's own pre-commit record plus miner-controlled re-proposals — no cooperation from other signers, no majority stake, and no special timing beyond re-proposing faster than `block_proposal_timeout`. The main precondition (the tenure's first block staying pre-committed but never signed) is a state the miner or a small number of network/signer-side stragglers can plausibly cause or prolong.

### Recommendation
Decouple "did the miner attempt something" from "should the inactivity clock be reset." Only refresh `last_activity_time` on evidence of real progress (e.g., group pre-commit/signature weight increasing, or a genuinely new/higher block), not merely on receipt of a conflicting/duplicate re-proposal that the local signer alone pre-committed to. Alternatively, bound the number of "activity credits" that can be produced from proposals a single miner submits without ever crossing a quorum threshold, so a miner cannot unilaterally keep its own tenure "alive" forever.

### Proof of Concept
1. Miner proposes tenure-start block `B1` at height H for tenure T.
2. Signer S validates `B1` OK and calls `mark_pre_committed` (stamps `approved_time`), per the pre-commit flow in `stacks-signer/src/v0/signer.rs` (`handle_block_validate_ok` → `check_block_against_signer_db_state` → `mark_pre_committed`).
3. The group never reaches the pre-commit/signature threshold for `B1` (e.g., insufficient peer propagation).
4. Miner repeatedly submits `B2` (a competing/duplicate proposal at height ≤ H, same tenure T) faster than `tenure_last_block_proposal_timeout`/`block_proposal_timeout`.
5. Each `B2` arrival runs `SortitionData::check_latest_block_in_tenure(T, B2, ...)`; since `B1` is a fresh `PreCommitted` block (`stacks-signer/src/chainstate/mod.rs:422-448`), `update_last_activity_time(T, now)` is called every time.
6. `SortitionState::is_timed_out(T, ...)` (`chainstate/v1.rs:52-93` / `v2.rs:45-89`) never exceeds `block_proposal_timeout` because `last_activity_time` keeps advancing.
7. `check_miner_inactivity` (`v0/signer_state.rs:284-316`) never falls back to the prior tenure's miner, even though tenure T never produces a signed block — wedging block production on tenure T indefinitely.

        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }

    /// Update the tenure (identified by consensus_hash) last activity timestamp
    pub fn update_last_activity_time(
        &mut self,
        tenure: &ConsensusHash,
        last_activity_time: u64,
    ) -> Result<(), DBError> {
        debug!("Updating last activity for tenure"; "consensus_hash" => %tenure, "last_activity_time" => last_activity_time);
        self.db.execute("INSERT OR REPLACE INTO tenure_activity (consensus_hash, last_activity_time) VALUES (?1, ?2)", params![tenure, u64_to_sql(last_activity_time)?])?;
        Ok(())
    }

    /// Get the last activity timestamp for a tenure (identified by consensus_hash)
    pub fn get_last_activity_time(&self, tenure: &ConsensusHash) -> Result<Option<u64>, DBError> {
        let query =
            "SELECT last_activity_time FROM tenure_activity WHERE consensus_hash = ? LIMIT 1";
        let Some(last_activity_time_i64) = query_row::<i64, _>(&self.db, query, &[tenure])? else {
            return Ok(None);
        };
        let last_activity_time = u64::try_from(last_activity_time_i64).map_err(|e| {
            error!("Failed to parse db last_activity_time as u64: {e}");
            DBError::Corruption
        })?;
        Ok(Some(last_activity_time))
    }

    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);

            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

            return Ok(false);
        };

                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
