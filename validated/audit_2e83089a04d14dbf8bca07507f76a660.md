### Title
Stale Chainlink USD0++ price at `stopEpoch` misprices the junior→senior parity transfer, letting a tranche holder extract value — (File: contracts/IdleCDOUsualVariant.sol)

### Summary
`IdleCDOUsualVariant.stopEpoch()` computes the senior (AA) top-up `targetAATVL = lastNAVAA * oneToken / _oraclePrice` using a single Chainlink read that is only required to be fresh within a 24h heartbeat, while the feed itself updates only on a ~50 bps deviation. Any gap between the real USD0++ market price and the reported oracle price directly shifts USD0++ between junior and senior tranche holders. A tranche holder (KYC-passed lender / tranche-token holder) positioned on the favored side captures the discrepancy as a risk-free transfer from the other tranche.

### Finding Description
The USD0++ variant runs a single epoch: deposits mint AA/BB tranche tokens 1:1 against USD0++; during the running epoch deposits and withdrawals are paused (`startEpoch`, `contracts/IdleCDOUsualVariant.sol:46-67`). At `stopEpoch` the owner fetches `IdleUsualStrategy.getChainlinkPrice()` and stores it via `setOraclePrice` (`contracts/IdleCDOUsualVariant.sol:77-78`). If the price is below `$1`, `lastNAVAA` is inflated to `lastNAVAA / _oraclePrice` and `_updateAccounting()` books the difference as a loss absorbed entirely by BB holders (`contracts/IdleCDOUsualVariant.sol:93-99`, and the loss branch in `_virtualPriceAux` at lines 152-168). Withdrawals are then re-enabled (`allowAAWithdraw = allowBBWithdraw = true`).

`getChainlinkPrice()` only enforces `updatedAt > block.timestamp - 24 hours` (`contracts/strategies/usual/IdleUsualStrategy.sol:164-172`), and its own comment states the feed updates only on a 50 bps deviation or the 24h heartbeat. Because the wealth transfer between tranches is computed from this single point-in-time value rather than the true market price, a stale answer misprices the insurance payout:

- **Oracle underreports (real price > reported):** `targetAATVL` is too large; AA holders redeem more USD0++ than needed for true $1 parity. The excess is booked as a loss to BB holders — a direct transfer to AA holders.
- **Oracle overreports (real price < reported, e.g., price dropped after the last update but under deviation, or dropped and the reported round is still within heartbeat):** `targetAATVL` is too small; BB holders escape part of the obligation they owe AA, effectively keeping USD0++ that should have compensated seniors for the depeg.

An attacker (any KYC-passed lender / tranche-token holder) observes the market price of USD0++ diverging from `USD0ppOracle`'s last reported answer, takes or keeps the tranche position on the favored side before the honest owner's `stopEpoch` call, and redeems after withdrawals are re-enabled. The profit equals the oracle-vs-market discrepancy applied to the entire AA NAV, net of nothing — there are no mint/redeem fees gating the transfer (`fee` only applies to gains, and the parity transfer is booked as a loss, `contracts/IdleCDOUsualVariant.sol:136-138`).

Broken invariant: fair mint/burn / loss waterfall — the junior→senior redistribution is supposed to bring AA to true $1 parity, but it uses an oracle value known to lag the market by up to the deviation threshold plus heartbeat lag.

### Impact Explanation
Direct theft of funds between tranche holders. The magnitude is `lastNAVAA * (1/oraclePrice - 1/truePrice)`; conservatively bounded by the feed's deviation threshold (~0.5%) per epoch, but larger if the USD0++ price moves quickly within a heartbeat window (the feed has no on-chain bound tighter than 24h freshness). With a large AA NAV this is a meaningful absolute loss borne by one tranche class, and it requires no privileged access.

### Likelihood Explanation
- The Chainlink USD0++ feed is explicitly documented in-code as low-frequency (50 bps deviation, 24h heartbeat), so stale readings at `stopEpoch` are expected, not exceptional.
- The trigger is an honest, scheduled owner call; the attacker only needs to hold the correct tranche side, which can be established cheaply in the buffer phase (or via tranche-token transfer between whitelisted wallets) once the oracle/market gap is observable.
- No guard exists: `setOraclePrice` only floors at `USD0pp.getFloorPrice()` (`contracts/strategies/usual/IdleUsualStrategy.sol:155-161`), which constrains a crash but not a stale mid-range value; there is no secondary price check, no TWAP, and no deviation bound against the price at epoch start (`priceAtStartEpoch` is recorded at line 63 but never compared).

### Recommendation
Sanity-bound the price used for the parity transfer:
- Compare `getChainlinkPrice()` against a second source (e.g., a DEX TWAP such as Uniswap/Curve USD0++ pool) and revert or clamp if deviation exceeds a threshold (e.g., 25–50 bps).
- At minimum, bound `abs(_oraclePrice - priceAtStartEpoch)` change application per stopEpoch, or allow a permissionless `setOraclePrice(getChainlinkPrice())` refresh window so the value used is the freshest round, and cap the junior→senior transfer to a configurable `maxParityTopUpBps` so a stale reading cannot transfer more than the intended coverage.

### Proof of Concept
Foundry fork test (mainnet fork so `USD0ppOracle`, `USD0pp`, and the strategy are live). Sketch — extend `test/foundry/IdleUsualStrategy.t.sol`:

```solidity
function testStaleOracleParityArb() external {
    IdleCDOUsualVariant _cdo = IdleCDOUsualVariant(address(idleCDO));
    IdleUsualStrategy _strat = IdleUsualStrategy(_cdo.strategy());

    uint256 amount = 1_000_000 * ONE_SCALE;
    // attacker takes AA side; victim holds BB
    uint256 mintedAA = idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);

    vm.prank(owner);
    _cdo.startEpoch(100);
    vm.warp(block.timestamp + 100);

    // Real USD0++ market recovered to $1.00 (e.g. Curve pool quote),
    // but Chainlink last reported 0.90 within the 24h heartbeat / <50bps-deviation window.
    // Emulate the stale reported round:
    vm.mockCall(
        _strat.USD0ppOracle(),
        abi.encodeWithSelector(IOracle.latestRoundData.selector),
        abi.encode(uint80(1), int256(0.90e8), uint256(0), block.timestamp - 1 hours, uint80(1))
    );

    uint256 lastNAVAA = _cdo.lastNAVAA();

    vm.prank(owner);
    _cdo.stopEpoch(); // honest owner call; uses stale 0.90

    // AA NAV inflated by 1/0.90 -> ~11.11% extra usd0++ pulled from BB NAV
    uint256 expectedAATVL = lastNAVAA * ONE_SCALE / 0.90e18;
    assertEq(_cdo.lastNAVAA(), expectedAATVL);

    // attacker redeems: receives ~11.1% more USD0++ than deposited
    uint256 received = idleCDO.withdrawAA(0);
    assertGt(received, amount * 1111 / 1000);
    // victim BB absorbs the full over-payment as loss
}
```

On a live fork the same flow works without `mockCall` whenever the reported round deviates from the executable market price; the mock only fixes the stale round deterministically. The key assertion — `lastNAVAA` is scaled by `1/stalePrice` and the delta is booked as a BB loss in `_updateAccounting` — follows directly from `contracts/IdleCDOUsualVariant.sol:93-99`.
