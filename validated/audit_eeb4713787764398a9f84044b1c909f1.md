### Title
Global signer-state consensus threshold `reached_agreement` floors the 70% weight requirement instead of rounding up, diverging from `compute_voting_weight_threshold` - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70%-weight quorum needed to settle the signer set's shared view of the current miner, burn view, active protocol version, and tx-replay set using plain floor integer division, while the semantically-equivalent quorum used for actually approving/rejecting a block signature, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly rounds the same fraction *up*. The two computations are meant to encode the same "70% of signer weight" rule but silently diverge whenever `total_weight * 7` is not a multiple of 10, letting the global-state agreement threshold be satisfied with one weight unit less than the block-signing threshold requires.

### Finding Description
`compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs` is the canonical, node-and-signer-shared definition of the 70% approval threshold, and it deliberately rounds up (ceiling) so the vault/protocol favors itself (requiring at least, not less than, 70%): [1](#0-0) 

This function is used both by the node when validating a block's aggregated signatures (`verify_signer_signatures`) and by the signer when deciding pre-commit/acceptance/rejection thresholds: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

However, `GlobalStateEvaluator::reached_agreement` — the function that decides whether the signer set has reached consensus on the shared global state machine (current miner, burn view, protocol version, tx-replay set) — computes the same 70% fraction with plain integer (floor) division and no ceiling correction: [6](#0-5) 

`reached_agreement` gates three consensus-relevant decisions:
- Which signer protocol version is "supported" globally: [7](#0-6) 
- The agreed global burn view: [8](#0-7) 
- The agreed `SignerStateMachine` (including `current_miner`, i.e. who the active miner is and what tenure they build on) and the transaction-replay set: [9](#0-8) 

Per `docs/signer-flows.md`, this miner-view state machine (including `parent_tenure_last_block`) is explicitly called out as "the equality key for global agreement" and "consensus-visible": [10](#0-9) 

Concretely, for `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (i.e. 70%, expressed as sevenths of ten) and `total_weight = 13`:
- `compute_voting_weight_threshold(13)`: `13*7=91`, `91 % 10 = 1` (non-zero remainder) → `ceil = 1` → threshold `= 91/10 + 1 = 10`.
- `reached_agreement` with `vote_weight = 9`: `9 >= (13*7)/10 = 91/10 = 9` (floor) → **true**.

So a coalition holding only 9/13 (≈69.2%) of signer weight — strictly below the intended 70% — is treated by `reached_agreement` as having reached global agreement, while the block-signature threshold used elsewhere for the same 70% rule would require 10/13 (≈76.9%) and reject the same 9-weight tally as insufficient. This is exactly the EIP-4626-style bug class: two functions computing what should be one canonical rounding direction for a threshold diverge, and the "vault" (here, the protocol's safety margin) is not favored — the weaker, rounded-down check is used for a state machine used to reason about consensus.

### Impact Explanation
The affected function does not gate a signature or block acceptance directly (that path correctly uses `compute_voting_weight_threshold`), so this is not itself a signature/block-approval equivocation. But it directly gates the **shared miner-view / global state machine** that governs which miner a signer will treat as canonical and what tenure/parent block it is building on (`current_miner`, `parent_tenure_last_block`), the active signer protocol version, and the transaction-replay set (used to decide whether to replay certain transactions). Because this off-by-one systematically requires strictly less real weight than the documented/intended 70% supermajority, a set of signers just under the true 70%-weight quorum can force the signer network to "agree" on:
- which miner/tenure is canonical (affecting subsequent block validation logic that depends on the state machine, e.g. `parent_tenure_last_block`),
- the active protocol version (affecting which message formats/consensus rules signers apply),
- the transaction-replay set.

If honest, correctly-weighted decisions diverge from this artificially-lowered threshold, different signers can end up with inconsistent views of "the" global state (some computing agreement, some not, depending on which nodes are counted at what point), degrading the safety margin the 70% supermajority is meant to guarantee and creating a path toward acting on a threshold that is weaker than intended — consistent with the "acting on a stale/threshold" High-impact category in the rules, though it stops short of directly producing an invalid signed block.

### Likelihood Explanation
This requires no majority, no key compromise, and no interaction beyond normal signer gossip of `StateMachineUpdate` messages, which any set of signers (including a minority near — but below — 70% weight) sends as part of ordinary operation. The divergence triggers deterministically whenever `total_weight * 7` is not a multiple of 10, which is the common case for typical signer-weight distributions (it only avoids the bug when the total weight happens to be a multiple of 10, or more generally when `total_weight * 7 % 10 == 0`). This makes the bug's trigger condition (a coalition landing exactly on the floor value) a matter of accumulating weight over time via ordinary voting/gossip, not an attack requiring privileged access.

### Recommendation
Make `reached_agreement` (and, for consistency, review `reached_disagreement`, which — verified algebraically — already happens to be consistent with the ceiling-based approval threshold via the floor/ceiling complement identity) use the same ceiling-rounding logic as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by calling that shared function directly instead of re-implementing the arithmetic:
```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let threshold = NakamotoBlockHeader::compute_voting_weight_threshold(self.total_weight)
        .unwrap_or(self.total_weight); // fail safe: require unanimity on error
    u64::from(vote_weight) >= u64::from(threshold)
}
```
This removes the duplicated/divergent rounding logic and guarantees that "70% global agreement" always means at least the same weight that the node/signer block-approval path requires.

### Proof of Concept
1. Configure (or observe) a reward-cycle signer set whose total signing weight is `13` and where `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (the compile-time constant used throughout the codebase for the 70% supermajority).
2. Compute the canonical block-approval threshold: `NakamotoBlockHeader::compute_voting_weight_threshold(13)` → `13*7 = 91`; `91 % 10 = 1` → `ceil = 1` → returns `10`. This is the number of weight units required, per `stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`, to approve a block or reach block-level consensus anywhere else in the signer (`stacks-signer/src/v0/signer.rs:1298`, `2309`, `2498`).
3. Have signers whose combined weight equals `9` (< 10, i.e. below the true 70% quorum, ≈69.2%) submit `StateMachineUpdate` messages agreeing on the same miner/state view.
4. Call `GlobalStateEvaluator::reached_agreement(9)` on a `total_weight = 13` evaluator: `9 >= (13*7)/10 = 91/10 = 9` (integer floor) → returns `true`.
5. Any of `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, or `determine_global_state` (`libsigner/src/v0/signer_state.rs:56-158`) will therefore report "global agreement reached" on a value backed by only 9/13 weight, even though the same 9/13 weight would be rejected as insufficient by `compute_voting_weight_threshold`/`verify_signer_signatures` used for the actual block-signing quorum. This demonstrates the rounding-direction inconsistency: the global-state-machine agreement check silently accepts a weight tally that the block-approval logic in the same codebase would reject as under-threshold.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }
