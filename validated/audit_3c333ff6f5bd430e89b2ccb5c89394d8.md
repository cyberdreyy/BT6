### No Vulnerability found for this question.

**Reasoning:**

`ValidateBridgeTypeNotExist` performs a non-transactional existence check via `orm.FindBridge` before `Create` calls `orm.CreateBridgeType` [1](#0-0) [2](#0-1) . This is a textbook TOCTOU window, but the actual `INSERT` in `CreateBridgeType` targets the `bridge_types` table keyed by `name` [3](#0-2) , and Chainlink's schema defines `name` as the primary key of `bridge_types` (standard schema going back to `0001_initial.sql`), so a concurrent duplicate insert is rejected by the database with a unique-constraint violation regardless of what the pre-check observed. That means two racing POST requests for the same bridge name can both pass `ValidateBridgeTypeNotExist`, but only one `CreateBridgeType` insert will actually succeed — the loser gets a Postgres unique-violation error and `jsonAPIError` returns `http.StatusInternalServerError` (note: the `pgErr` conflict-detection block at lines 87-97 is actually dead/buggy code since the function already returns on `CreateBridgeType` error at line 84, but that only affects the error message/status code returned, not whether a duplicate row is persisted) [4](#0-3) .

So the underlying uniqueness invariant is enforced by the database primary key, not solely by the racy validation function — the "invariant to test" in the prompt (guard enforced by a transactional/unique constraint) is actually satisfied here at the DB layer, even though the pre-check itself is not atomic with the insert.

Furthermore, `bridge_types` rows only store bridge configuration (URL, incoming/outgoing tokens used to authenticate calls to external adapters) [5](#0-4) ; there is no code path here that submits or signs an EVM transaction with node-held keys. The claimed "Critical — unauthorized transaction submission signed by node-held EVM keys" impact has no connection to this function; at most a race could cause a spurious 500 error for the losing request, not data corruption, duplicate persisted bridges, or fund movement. This does not meet the bar for a concrete, exploitable finding under the stated impact class.

// ValidateBridgeTypeNotExist checks that a bridge has not already been created
func ValidateBridgeTypeNotExist(ctx context.Context, bt *bridges.BridgeTypeRequest, orm bridges.ORM) error {
	fe := models.NewJSONAPIErrors()
	_, err := orm.FindBridge(ctx, bt.Name)
	if err == nil {
		fe.Add(fmt.Sprintf("Bridge Type %v already exists", bt.Name))
	}
	if err != nil && !errors.Is(err, sql.ErrNoRows) {
		fe.Add(fmt.Sprintf("Error determining if bridge type %v already exists", bt.Name))
	}
	return fe.CoerceEmptyToNil()
}

func (o *orm) CreateBridgeType(ctx context.Context, bt *BridgeType) error {
	stmt := `INSERT INTO bridge_types (name, url, confirmations, incoming_token_hash, salt, outgoing_token, minimum_contract_payment, use_connection_manager, created_at, updated_at)
	VALUES (:name, :url, :confirmations, :incoming_token_hash, :salt, :outgoing_token, :minimum_contract_payment, :use_connection_manager, now(), now())
	RETURNING *;`
	err := o.transact(ctx, false, func(tx *orm) error {
		stmt, err := tx.ds.PrepareNamedContext(ctx, stmt)
		if err != nil {
			return err
		}
		defer stmt.Close()
		return stmt.GetContext(ctx, bt, bt)
	})

	return pkgerrors.Wrap(err, "CreateBridgeType failed")
}
