### Title
Revoking one's own EIP-8130 `self` actor (or all actors) with no "last-actor" safety check permanently locks the account and freezes all its funds - ([File: crates/execution/eip8130/src/apply.rs])

### Summary
The EIP-8130 `AccountChangeApplier::revoke_actor` / `revoke_actor_with_account_state` path lets a signed `RevokeActor` config-change unconditionally clear any actor on an account — including the account's own `self` actor — with no check that another authorized actor remains. This is the same bug class as the reported "no unclaimed-rewards guard before an irreversible state-clearing operation": the contract lets an unprivileged, authorized caller execute an operation that destroys the only record needed to ever act on the account again, with no revert to stop a user from permanently locking themselves out.

### Finding Description
`revoke_actor_with_account_state` clears `actor_config`/policy slots for the target actor, and for the `self` id sets `DEFAULT_EOA_REVOKED` (a monotonic, never-cleared flag) [1](#0-0) . Neither this function nor its caller `apply_config_change_with_account_state` verifies that the account retains any authorized actor before applying a `RevokeActor` change: the only guard present is the `AccountIsLocked` check (which only blocks changes on already-locked accounts) [2](#0-1) . `revoke_actor` dispatches straight into this unconditional clear for both the `self` and non-self actor cases [3](#0-2) .

By contrast, the codebase's own B20 precompile explicitly recognizes this exact failure mode for role-based admin removal and hard-blocks it: `renounce_role`/`revoke_role` revert with `LastAdminCannotRenounce` when the caller is the sole holder of `DefaultAdmin`, and `renounce_last_admin` requires an explicit, dedicated call path with its own `NotSoleAdmin` guard [4](#0-3) . No equivalent guard exists for EIP-8130 actor revocation, even though revoking the last actor is functionally identical in effect — permanently removing the only entity able to authorize future transactions from the account.

A user can trigger this in a single signed EIP-8130 transaction: authorize a scoped actor, then in a later `RevokeActor` change (or via `renounce`-style self-service usage) revoke the `self` k1 actor without having installed any other admin-scoped actor. Because `DEFAULT_EOA_REVOKED` is documented as "once set it is never cleared (monotonic)" [5](#0-4) , there is no recovery path once the last authorizing actor is gone.

### Impact Explanation
An account with no remaining authorized actor can never again authenticate a sender/payer for that account under `TransactionAuthorizer::authorize_and_apply` [6](#0-5) , and delegation requires an admin actor to sign off [7](#0-6) , so a fully-revoked account can no longer be repaired even via delegation. Any ETH or tokens held by the account become permanently unspendable — a direct, irreversible freezing of funds, matching the report's "forever lose access" impact class.

### Likelihood Explanation
Medium: this requires a single self-inflicted, unprivileged EIP-8130 transaction with no revert-based safety net, mirroring the reported bug's likelihood rationale (front-end tooling may sequence calls correctly, but a user interacting directly, via a misconfigured wallet, or via a buggy actor-management UI can revoke their last actor without any on-chain protection). The codebase's own precedent (`LastAdminCannotRenounce`/`NotSoleAdmin` in B20) shows the project is aware such guards are needed for exactly this kind of "remove the last controller" operation, but the EIP-8130 revoke path lacks the analogous check.

### Recommendation
Add a "cannot revoke the last remaining authorized actor" invariant to `revoke_actor_with_account_state` / `apply_config_change_with_account_state`, analogous to B20's `LastAdminCannotRenounce`/`NotSoleAdmin`: before clearing an actor (especially the `self` actor when `DEFAULT_EOA_REVOKED` would become set), verify at least one other live, non-expired admin-scoped actor remains authorized on the account, and revert with a dedicated error otherwise. Alternatively, require an explicit two-step "renounce last actor" entry point that only a caller who understands the consequence can invoke, mirroring `renounce_last_admin`.

### Proof of Concept
1. Create/import an EIP-8130 account whose only authorized actor is the inline k1 `self` actor (default state, `DEFAULT_EOA_REVOKED` unset).
2. Submit a signed `AccountChange::ConfigChange` batch containing a single `RevokeActor` op for `self_actor_id(account)`, authorized under the current live actor per `ConfigChangeAuthorizer::authorize_with_account_state`.
3. `AccountChangeApplier::apply_config_change_with_account_state` reaches the `ChangeType::RevokeActor` arm and calls `revoke_actor_with_account_state`, which is not `is_self=false`/`default_eoa_revoked()`-gated against "last remaining actor" and unconditionally calls `disable_inline_self(state)`, setting `DEFAULT_EOA_REVOKED` [8](#0-7) .
4. No other actor was ever authorized, so the account now has zero live actors. Any subsequent EIP-8130 transaction attempting to authenticate `sender`/`payer` for this account fails permanently, and delegation cannot repair it because it also requires an admin actor's signature. The account's balance is now permanently frozen — confirmed by the unit test `authorize_self_k1_enables_inline_and_revoke_disables`, which shows the revoke unconditionally sets `default_eoa_revoked()` with no last-actor check [9](#0-8) .

    pub fn revoke_actor_with_account_state(
        storage: &mut AccountConfigurationStorage<'_>,
        account: Address,
        actor_id: B256,
        state: &mut AccountState,
    ) -> Result<u32, ApplyError> {
        let config = storage.actor_config_slot(account, actor_id)?;
        let is_self = actor_id == AccountConfigurationStorage::self_actor_id(account);
        if config.authenticator != Address::ZERO {
            Self::revoke_explicit_actor(storage, account, actor_id, config)?;
            // Defense-in-depth: an explicit self actor is necessarily non-k1, and
            // `authorize_actor_with_account_state`/`apply_create` already set
            // DEFAULT_EOA_REVOKED and zeroed the inline scope/expiry when it was
            // installed. Re-assert that invariant here (a no-op on the in-tree
            // install paths) instead of depending on the authorize path, so a
            // future direct `set_actor_config` writer cannot leave a live inline
            // secp256k1 home behind an explicit self entry. `state` is already
            // loaded and flushed by the caller, so this adds no storage access.
            // This clears a populated explicit `actor_config`, so it is not the
            // discounted inline-self shape.
            if is_self {
                Self::disable_inline_self(state);
            }
            return Ok(0);
        }
        if !is_self || state.default_eoa_revoked() {
            // Idempotent: the actor is already absent — no explicit `actor_config`
            // entry, and either a non-self id or a self whose inline secp256k1 key
            // is revoked. Mirrors `_applyRevoke`'s `if (!_isAuthorized(...)) return;`
            // (eip-8130 #100): no state change and no `ActorRevoked` event. All
            // three conservatively reset-priced revoke slots (`actor_config` and
            // both policy slots) are empty for an absent actor, so the whole revoke
            // is discounted.
            return Ok(3);
        }

        // The inline self's `actor_config` slot is always empty (a zero-to-zero
        // reset no-op). Its two policy slots are written verbatim at authorize
        // time and may be zero even when the self is policy-gated (`slice_policy`
        // permits a zero manager and/or commitment), so a zero slot is likewise a
        // no-op. Count each actually-empty slot from the raw storage before
        // `clear_policy` zeroes them; only the non-zero slots stay at the
        // conservative reset price. The gate bit is not a reliable proxy here.
        let mut empty_slots = 1; // `actor_config`
        if storage.get_policy_manager(account, actor_id)?.is_zero() {
            empty_slots += 1;
        }
        if storage.get_policy_commitment(account, actor_id)?.is_zero() {
            empty_slots += 1;
        }
        storage.clear_actor_config(account, actor_id)?;
        storage.clear_policy(account, actor_id)?;
        Self::disable_inline_self(state);
        AccountConfigurationEvents::emit_actor_revoked(storage, account, actor_id)?;
        Ok(empty_slots)

    #[test]
    fn authorize_self_k1_enables_inline_and_revoke_disables() {
        with_storage(|acc| {
            let self_id = AccountConfigurationStorage::self_actor_id(ACCOUNT);
            // Account starts with the inline self live (flag unset, all-zero inline).
            let scoped = ungated(K1, Eip8130Constants::SCOPE_OPERATOR);
            AccountChangeApplier::authorize_actor(acc, ACCOUNT, self_id, scoped, &[]).unwrap();
            let state = acc.get_account_state(ACCOUNT).unwrap();
            assert!(!state.default_eoa_revoked());
            assert_eq!(state.default_eoa_scope, Eip8130Constants::SCOPE_OPERATOR);
            // No explicit actor_config slot is used for the k1 self.
            assert!(acc.actor_config_slot(ACCOUNT, self_id).unwrap().is_empty());

            // Upsert: re-authorizing a live self rescopes the inline config in
            // place (no prior revoke required).
            let rescoped = ungated(K1, Eip8130Constants::SCOPE_SELF_PAYER);
            AccountChangeApplier::authorize_actor(acc, ACCOUNT, self_id, rescoped, &[]).unwrap();
            let state = acc.get_account_state(ACCOUNT).unwrap();
            assert!(!state.default_eoa_revoked());
            assert_eq!(state.default_eoa_scope, Eip8130Constants::SCOPE_SELF_PAYER);

            // Revoke sets the flag and clears the inline config.
            AccountChangeApplier::revoke_actor(acc, ACCOUNT, self_id).unwrap();
            let state = acc.get_account_state(ACCOUNT).unwrap();
            assert!(state.default_eoa_revoked());
            assert_eq!(state.default_eoa_scope, 0);
        });
    }

    fn renounce_role(
        &self,
        token: &mut B20AssetToken<S, A>,
        caller: Address,
        role: B256,
        confirmation: Address,
    ) -> Result<()> {
        if confirmation != caller {
            return Err(BasePrecompileError::revert(IB20::AccessControlBadConfirmation {}));
        }
        if role == B20TokenRole::DefaultAdmin.id()
            && token.accounting().has_role(role, caller)?
            && token.accounting().role_member_count(role)? == U256::ONE
        {
            return Err(BasePrecompileError::revert(IB20::LastAdminCannotRenounce {}));
        }
        self.revoke_role_unchecked(token, role, caller, caller)
    }

    fn renounce_last_admin(&self, token: &mut B20AssetToken<S, A>, caller: Address) -> Result<()> {
        let admin_role = B20TokenRole::DefaultAdmin.id();
        B20Guards::ensure_role(token, caller, admin_role)?;
        if token.accounting().role_member_count(admin_role)? != U256::ONE {
            return Err(BasePrecompileError::revert(IB20::NotSoleAdmin {}));
        }
        self.revoke_role_unchecked(token, admin_role, caller, caller)?;
        token
            .accounting_mut()
            .emit_event(IB20::LastAdminRenounced { previousAdmin: caller }.encode_log_data())
    }
