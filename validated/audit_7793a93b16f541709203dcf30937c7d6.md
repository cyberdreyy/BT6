### Title
Path Traversal in `pluginPPROFHandler` allows forwarding pprof-proxy requests to arbitrary paths on the internal LOOP plugin listener - ([File: core/web/loop_registry.go])

### Summary
`pluginPPROFHandler` builds the proxied backend URL by directly concatenating the unvalidated `profile` wildcard route parameter into a `fmt.Sprintf` string, with no sanitization of `..` sequences. Combined with the fact that `loopRoutes` (unlike every other route group in `router.go`) is registered on the base `api` group with no authentication middleware at all, this endpoint is reachable without credentials and can redirect the internally-proxied request to any path on the target plugin's local HTTP listener.

### Finding Description
The route is registered as a raw gin wildcard: [1](#0-0) 

Unlike `debugRoutes` (wrapped in `auth.Authenticate(...)`) and `metricRoutes` (only mounted under `authv2`, which requires token/session auth), `loopRoutes(app, api)` is invoked directly on the `api` group which only has rate-limiting and session-store middleware — no `auth.Authenticate*` call wraps it: [2](#0-1) 

In the handler itself, the wildcard param `profile` (captured by gin's `*profile` pattern, which includes the leading `/` and is not `path.Clean`-normalized by gin's router — dot-segments are matched as literal path bytes) is spliced directly into the proxy URL with no validation: [3](#0-2) 

Because gin's httprouter-based tree does not resolve `..` segments during route matching (it only does so for redirect/`CleanPath` computation, not to alter registered wildcard param values), a request to `/plugins/valid-plugin/debug/pprof/../../otherendpoint` matches the route with `name=valid-plugin` and `profile="/../../otherendpoint"` verbatim. This literal string is substituted into `fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)`, producing `http://<loopHost>:<port>/debug/pprof//../../otherendpoint`. This URL is passed unmodified to `http.NewRequestWithContext` and then `http.DefaultClient.Do` in `doRequest`, so the raw, uncleaned path is sent over the wire to the plugin's internal HTTP listener (`p.EnvCfg.PrometheusPort`, bound to `loopHostName`, normally "localhost"), where the plugin's own HTTP server/mux resolves the dot-segments and may route the request outside the intended `/debug/pprof` namespace.

There is no allowlist, no `filepath.Clean`, no rejection of `..`/encoded traversal characters, and — critically — no authentication requirement on this route path at all, which is stricter than the question's precondition ("view-role or unauthenticated").

### Impact Explanation
The proxy is intended to expose only the plugin's pprof debug surface (`/debug/pprof/*`) on the plugin's internal, otherwise-unexposed HTTP listener. With unrestricted path concatenation, an unauthenticated attacker can retarget the proxied backend request to any path served by that internal listener beyond `/debug/pprof`, potentially reaching other internal endpoints the plugin process exposes on the same port (e.g., other debug/admin routes a given LOOP plugin implementation might register on its Prometheus/debug HTTP server) that were never meant to be reachable from outside the node. This constitutes an authorization/isolation bypass of the intended internal-only listener boundary and information-disclosure risk depending on what the target plugin exposes on that port, matching Chainlink's "unauthorized access to internal/administrative functionality" impact class.

### Likelihood Explanation
No credentials or role are required — the route has no auth middleware attached (`loopRoutes(app, api)` bypasses every `auth.Authenticate*` wrapper used elsewhere in `router.go`), and constructing a traversal URL is trivial for any network client that can reach the node's HTTP API. The only precondition is that at least one LOOP plugin is registered (`l.registry.Get(pluginName)` must succeed) so a valid `:name` exists. This is fully repeatable and requires no special client (curl with `--path-as-is` sends literal dot-segments).

### Recommendation
1. Enforce authentication (and at minimum `RequiresEditRole`/`RequiresAdminRole`, consistent with `metricRoutes`) on the `/plugins/*` routes in `loopRoutes`.
2. Validate/sanitize `gc.Param("profile")` before use: reject any value containing `..`, restrict to an explicit allowlist of known pprof sub-paths (`cmdline`, `profile`, `symbol`, `trace`, `allocs`, `block`, `goroutine`, `heap`, `mutex`, `threadcreate`, or the empty index), or use `path.Clean`/`filepath.Clean` and verify the result still begins with `/debug/pprof/` before constructing the proxied URL.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
