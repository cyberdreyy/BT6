### Title
Signer re-enters the pre-commit/signing pipeline for an already `GloballyRejected` block after a stale `BlockValidationResponse::Ok` — `handle_block_validate_ok` fails to gate on a failed `mark_pre_committed` (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`BlockInfo::mark_pre_committed`/`mark_locally_accepted` mutate fields (`valid`, `approved_time`, `signed_group`) *before* calling the fallible `move_to(...)` state-transition check, and the two call sites in `signer.rs` (`handle_block_validate_ok` and `store_and_process_block_signature`) do not uniformly roll back or abort when that transition fails. This is the exact analog of the Netty bug: an operation performs an unconditional side effect (`retain()` / here, field mutation) ahead of a fallible step, and the error branch fails to treat "target already in a terminal state" (closed channel / `GloballyRejected` block) as a reason to stop, instead falling through to actions that assume success.

### Finding Description
`BlockInfo::mark_pre_committed` (`stacks-signer/src/signerdb.rs:272-277`) does:
```rust
pub fn mark_pre_committed(&mut self) -> Result<(), String> {
    self.valid = Some(true);
    self.approved_time.get_or_insert(get_epoch_time_secs());
    self.move_to(BlockState::PreCommitted)
}
```
`self.valid = Some(true)` and `approved_time` are set *unconditionally*, before `move_to` is even evaluated — mirroring `data.retain()` being applied before `writeInbound` in the Netty report. `move_to`/`check_state` (`signerdb.rs:313-341`) only permits `PreCommitted` from `Unprocessed`; any other prior state (including the terminal `GloballyRejected`) makes `move_to` return `Err`, but the `valid`/`approved_time` mutation has already happened and is never rolled back — analogous to the missing `data.release()` in the Netty fix.

In `handle_block_validate_ok` (`stacks-signer/src/v0/signer.rs:1961-1970`):
```rust

    if !block_info.has_reached_consensus()

    {
        warn!("{self}: Failed to mark block as approved: {e:?}",);

self.signer_db.insert_block(&block_info)...
self.send_block_pre_commit(signer_signature_hash.clone());
let address = self.stacks_address.clone();
self.handle_block_pre_commit(stacks_client, sortition_state, &address, signer_signature_hash);
```
`has_reached_consensus()` (`signerdb.rs:344-349`) is true for `GloballyAccepted` **or `GloballyRejected`**. If the block is already `GloballyRejected` (the equality/wedge the flow chart in `docs/signer-flows.md:349-387` calls "finalizes the block as globally rejected", produced by `store_and_process_block_rejection` → `mark_globally_rejected`, `signer.rs:2335`), then `mark_pre_committed()` fails (state stays `GloballyRejected`), **but** the guard `!has_reached_consensus() && state != LocallyAccepted` evaluates to `false`, so the function does **not** return. It falls through to `insert_block` (persisting `valid = Some(true)` on a record whose `state` is still `GloballyRejected` — an inconsistent record), then unconditionally calls `send_block_pre_commit` and `handle_block_pre_commit` for **this signer's own address** on a block the signer set has already terminally rejected.

`handle_block_pre_commit` (`signer.rs:1250-1403`) re-loads the (now-mutated) `block_info`, sees `signed_self.is_none()` and `valid == Some(true)` (set by the failed `mark_pre_committed` call), and proceeds through the pre-commit weight tally and the chainstate/conflict re-checks. Note `check_block_against_signer_db_state`'s chainstate re-check (`docs/signer-flows.md:389-448`) checks tenure/height consistency, not whether the block itself already reached `GloballyRejected` — it has no additional guard for a block already terminally decided by rejection. If the weight/conflict checks pass, the flow reaches `SIGN: mark_locally_accepted, handle_block_signature, broadcast acceptance` (`docs/signer-flows.md:268`) — this signer would broadcast an *acceptance signature* for a block that has already been finalized as `GloballyRejected` by the signer set.

This is reachable by ordinary network timing (a delayed `BlockValidationResponse::Ok` for a proposal that the rest of the signer set has already rejected past the >30% blocking threshold) — it needs only: (1) a miner's proposal, (2) normal gossip driving `store_and_process_block_rejection` to `GloballyRejected` before this signer's own `/v3/block_proposal` validation returns, and (3) that stale `Ok` response arriving afterward. No majority collusion or other signer's key is required to *trigger* the race; it is the existing signer's own logic that mishandles the already-decided case.

The identical unconditional-mutation-before-fallible-transition pattern also exists in `store_and_process_block_signature` (`signer.rs:2528-2537`), where `mark_locally_accepted(true)`'s error is only logged (never gates), and `broadcast_signed_block` is called regardless of whether the transition to `LocallyAccepted` actually succeeded.

### Impact Explanation
This breaks the "rejection vs. re-entry" equality the state machine is meant to guarantee: once a block reaches `GloballyRejected` (a terminal state, `has_reached_consensus() == true`), no further local action should treat it as pending/valid. The buggy fallthrough lets a stale, out-of-order validation response resurrect a terminally-rejected block into the pre-commit/signing pipeline, potentially producing this signer's acceptance signature and pre-commit broadcast for a block the group already rejected — a rejection recounted/undermined as a still-live proposal, matching the "Critical" impact bucket (signer signing a conflicting/rejected block) described in the rules. It also corrupts the persisted `BlockInfo` (`valid = Some(true)` with `state = GloballyRejected`), which other logic (e.g., `has_signed_block_in_tenure`, conflict computations in `get_signed_conflicts`) reads and could misinterpret.

### Likelihood Explanation
Moderate. It requires only ordinary asynchronous timing — a slow/late `/v3/block_proposal` validation response racing against the rest of the signer set's rejection tally reaching >30% blocking weight — not any signer majority, secret key, or auth token. A miner that intentionally stalls its own validation endpoint (or exploits normal node latency) while other signers reject the same proposal for a legitimate reason (e.g., a chainstate conflict) can reliably arrange this race.

### Recommendation
In `handle_block_validate_ok`, unconditionally `return` (do not fall through to `insert_block`/`send_block_pre_commit`/`handle_block_pre_commit`) whenever `mark_pre_committed()` returns `Err`, regardless of `has_reached_consensus()`/`state == LocallyAccepted`; only skip the *warning log* for the harmless already-decided cases, not the early return. Symmetrically, make `store_and_process_block_signature` return early (without calling `broadcast_signed_block`) when `mark_locally_accepted` fails. Additionally, change `mark_pre_committed`/`mark_locally_accepted`/`mark_globally_accepted` to perform the `move_to` check *first* and only mutate `valid`/`approved_time`/`signed_group` on success, so a failed transition never leaves inconsistent fields behind — the direct fix analog of moving `data.release()` to only fire when `writeInbound` did not take ownership.

### Proof of Concept
1. Miner proposes block `B` at height `h`.
2. Signer `S`'s local `/v3/block_proposal` submission for `B` is slow (e.g., node under load or artificially stalled by the miner's node).
3. The rest of the signer set independently sends `BlockResponse::Rejected` for `B` (e.g., due to a `SortitionViewMismatch`/chainstate conflict each of them independently detects); their rejections accumulate on `S` via `handle_block_rejection` → `store_and_process_block_rejection`, crossing `total_reject_weight.saturating_add(min_weight) > total_weight` and calling `block_info.mark_globally_rejected()` (`signer.rs:2335`), setting `B`'s state to `GloballyRejected` in `S`'s `signer_db`.
4. `S`'s stalled node validation for `B` finally returns `BlockValidateOk`. `handle_block_validate_ok` is invoked (`signer.rs:1888`).
5. `block_info.valid.is_some()` check (line 1932) does not stop this (valid is still `None` at this point, since the block was rejected by peers, not locally). `check_block_against_signer_db_state` may or may not flag a conflict; assume it passes (no other conflicting signed block exists yet).
6. `block_info.mark_pre_committed()` fails because `state == GloballyRejected` (`check_state` in `signerdb.rs:319-328` forbids `GloballyRejected -> PreCommitted`), but `valid` is now `Some(true)` and `approved_time` is set.
7. Guard `!block_info.has_reached_consensus() && block_info.state != BlockState::LocallyAccepted` evaluates `false` (since `has_reached_consensus()` is `true`), so execution does **not** return.
8. `S` persists the corrupted record, sends its own `BlockPreCommit` for `B`, and calls `handle_block_pre_commit` for its own address, re-entering the sign path for a block already `GloballyRejected` by the group. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

    pub fn mark_pre_committed(&mut self) -> Result<(), String> {
        self.valid = Some(true);
        self.approved_time.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::PreCommitted)
    }

    /// Mark this block as valid and the appropriate timestamps if they aren't already set, and attempt to mark it as locally accepted.
    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Mark this block's signed group time if not already set and attempt to mark it as globally accepted.
    pub fn mark_globally_accepted(&mut self) -> Result<(), String> {
        self.signed_group.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::GloballyAccepted)
    }

    /// Mark this block as invalid and attempt to mark it as locally rejected
    pub fn mark_locally_rejected(&mut self) -> Result<(), String> {
        self.valid = Some(false);
        self.move_to(BlockState::LocallyRejected)
    }

    /// Attempt to mark the block as globally rejected
    pub fn mark_globally_rejected(&mut self) -> Result<(), String> {
        self.move_to(BlockState::GloballyRejected)
    }

    /// Return the block's signer signature hash
    pub fn signer_signature_hash(&self) -> Sha512Trunc256Sum {
        self.block.header.signer_signature_hash()
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

    /// Attempt to transition the block state
    pub fn move_to(&mut self, state: BlockState) -> Result<(), String> {
        if !self.check_state(state) {
            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
    }

            Ok(true) => (),
