### Title
Vault losses are silently absorbed below zero instead of being socialized, letting early withdrawers exit at inflated tranche prices - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary

In programmable-borrower mode, `IdleCDOEpochVariant` trusts a single integer returned by `IProgrammableBorrower.totalInterestDueNow()` as the source of truth for epoch PnL. That function clamps net vault PnL at zero: when the ERC4626 vault sleeve loses more than the accrued interest, the excess principal loss is never reported to the CDO, never routed through `stopEpochWithDuration(_lossAmount)`/`previewLossAdjustedWithdrawFunds`, and never burned into tranche prices. An unprivileged user of the programmable borrower's ERC4626 vault (an allowed attacker role) who can depress `convertToAssets` — e.g., a first-depositor share-inflation/donation attack on a freshly configured vault, or any vault-native loss event — causes the pool to keep quoting pre-loss prices while real backing is short.

### Finding Description

`_resolveStopEpochInterest` returns `IProgrammableBorrower(_borrower()).totalInterestDueNow()` verbatim, with the comment "Programmable borrowers are always the source of truth for epoch interest." [1](#0-0) 

Inside `totalInterestDueNow`, losses are netted against gains and clamped to zero:

```solidity
uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
return totalGain > loss ? totalGain - loss : 0;
``` [2](#0-1) 

The loss itself (`_vaultNetInterest` → `earnedAssets < principalAssets`) is computed but only ever consumed to offset interest — nothing propagates a negative delta to the CDO. [3](#0-2) 

On the CDO side, `_stopEpoch` uses the resolved value only as `_expectedInterest`/`_grossInterest`; in minted mode (`isInterestMinted`, forced true for programmable borrowers) `_amountToPullFromBorrower` is 0 and the contract mints strategy tokens equal to `_grossInterest`. When `_grossInterest == 0` nothing is minted and `_updateAccounting` revalues tranches against `lastNAVAA`/`lastNAVBB` — which still reflect pre-loss principal, because the vault shortfall lives on the borrower contract and the CDO's strategy-token balance is unchanged. [4](#0-3) [5](#0-4) 

There is no path that converts a vault-side principal deficit into `_lossAmount` for `previewLossAdjustedWithdrawFunds`/BB-first burn: `stopEpochWithDuration` requires an explicit `_lossAmount` argument, and the honest manager is not expected to quantify an external vault loss the protocol itself never surfaces. The existing guards don't help: `_skimDonatedAssets` only handles raw CDO donations, `onStopEpoch` happily returns `true` when `shortfall <= _currentVaultAssets()` even though `convertToAssets` is the very value being manipulated, and `onDefault` intentionally avoids reading the vault price. [6](#0-5) 

### Impact Explanation

Broken invariant: solvency / fair mint-burn. Tranche prices and withdrawal-receipt pricing (`requestWithdraw` → `_trancheToUnderlyings` at `_tranchePrice`) continue to value 1 tranche token at the pre-loss price while the vault position backing it is worth less. A KYC-passing lender who requests and claims withdrawal after the loss exits at par; the residual deficit is concentrated on the remaining LPs (BB first in a real default waterfall, but here no waterfall ever runs). Loss equals the vault principal shortfall net of accrued interest — up to the entire vault sleeve. If the borrower subsequently cannot cover `transferFrom`, the pool falls into `_handleBorrowerDefault` with real, unaccounted bad debt; if liquidity still exists, it is a silent wealth transfer from late withdrawers to early ones.

### Likelihood Explanation

Requires a programmable-borrower deployment whose ERC4626 vault can lose value or whose `convertToAssets` can be moved by an unprivileged vault user — the attacker role explicitly allowed by scope. The trigger needs only sequencing around the honest manager's `stopEpoch` call during a running epoch; no privileged role misbehaves. The clamped reporting path is unconditional in `totalInterestDueNow`.

### Recommendation

Return a signed net PnL (or `(interest, loss)` pair) from the programmable borrower and route a positive `loss` through the existing `stopEpochWithDuration(_lossAmount)`/`previewLossAdjustedWithdrawFunds` path so principal deficits burn BB-first into tranche prices instead of being clamped to zero. Additionally, treat `convertToAssets` as untrusted for liquidity purposes: keep the on-hand balance check in `onStopEpoch`, but do not let a covered-on-paper shortfall suppress loss reporting.

### Proof of Concept

Foundry fork sketch (mode: programmable borrower, `isInterestMinted = true`):

```solidity
// Setup: owner deploys ProgrammableBorrower with fresh MockERC4626 vault V,
// isProgrammableBorrower = true, isInterestMinted = true.

// 1) Inflate/attack the vault sleeve as an unprivileged vault user.
//    First-depositor style: attacker deposits 1 wei into V, then donates
//    X underlying directly to V so V.convertToAssets misprices subsequent
//    deposits (or use a vault that can take a real loss).
vault.deposit(1, attacker);
underlying.transfer(address(vault), DONATION); // skew share price

// 2) KYC'd LP deposits and epoch starts; idle cash parked via onStartEpoch ->
//    _depositToVault(balance, 0) with no min-shares check, so the borrower
//    sleeve mints fewer shares than the real value transferred.
idleCDO.depositAA(DEPOSIT);
vm.prank(manager); cdoEpoch.startEpoch();

// 3) Warp past epochEndDate. Vault position redeems for less than
//    epochStartVaultAssets; loss > any accrued interest.
vm.warp(cdoEpoch.epochEndDate() + 1);

// 4) Honest manager stops the epoch. totalInterestDueNow() clamps the net
//    negative vault delta to 0; no _lossAmount is ever passed.
vm.prank(manager); cdoEpoch.stopEpoch(0, 0);
assertEq(cdoEpoch.lastEpochInterest(), 0);

// 5) Tranche prices still reflect pre-loss NAV even though real vault backing
//    is short by L = loss. An attacker LP exits at inflated price.
cdoEpoch.requestWithdraw(attackerShares, address(aaTranche));
// ... next epoch, claim pays full receipt while remaining LPs' claims are
// unbacked: pendingWithdraws reserve + remaining NAV > real vault assets.
assertLt(realBacking, trancheClaimsOutstanding); // insolvency gap == L
```

Key assertion: `cdoEpoch.virtualPrice(aaTranche)` after `stopEpoch` is unchanged while `programmableBorrower.vaultSharesBalance()` converts to less than the recorded epoch principal — the deficit is never socialized.

  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
