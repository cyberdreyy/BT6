### Title
Unauthenticated DoS via negative `strings.Repeat` count in `normalizeHex` when workflowID/workflowOwner hex strings omit the `0x` prefix - (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
`validateHexInput` bounds only the raw input length (`len(input) > expectedLength`) and does not require or account for the `0x` prefix, while `normalizeHex` unconditionally computes `expectedHexLength-len(hexStr)` assuming the prefix was present and stripped. An attacker can submit a `workflowID` or `workflowOwner` that is valid hex, has no `0x` prefix, and is exactly at (or near) `expectedLength` characters, causing `normalizeHex` to call `strings.Repeat` with a negative count, which panics.

### Finding Description
`validateHexInput` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:260-276`) only checks `len(input) > expectedLength` before trimming an optional `"0x"` prefix and validating with `hex.DecodeString`. It does not require the prefix to be present, and does not check the length of the *decoded/trimmed* hex string separately from the raw input length.

`normalizeHex` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:326-333`) assumes the prefix has already been accounted for:
```go
hexStr := strings.TrimPrefix(input, "0x")
expectedHexLength := length - 2
paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
```

Because `workflowIDLength = 66` includes 2 characters for `"0x"`, `expectedHexLength` is `64`. If an attacker submits a `workflowID` consisting of exactly 66 lowercase hex characters **without** the `"0x"` prefix (e.g., 66 hex digits, all decodable as valid hex since 66 is even), `validateHexInput` passes: `len(input) == 66 <= 66` and `hex.DecodeString` succeeds on the 66-character string. In `normalizeHex`, since there is no `"0x"` prefix to strip, `hexStr` remains 66 characters long, so `expectedHexLength - len(hexStr) = 64 - 66 = -2`. `strings.Repeat` panics on a negative count (`"strings: negative Repeat count"`).

The same applies to `workflowOwner` with `workflowOwnerLength = 42` (`expectedHexLength = 40`): a 42-character prefix-less hex string passes `validateWorkflowOwner`, then panics in `normalizeHex` at `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:347`.

Reachability trace: `HandleUserTriggerRequest` (line 88) calls `validatedTriggerRequest` (which runs `validateWorkflowFields` → `validateWorkflowID`/`validateWorkflowOwner`, both passing on the crafted input) at line 89, then calls `resolveWorkflowID` at line 94 — **before** `authorizeRequest` at line 99. `resolveWorkflowID` calls `normalizeHex` directly on the unauthenticated, attacker-supplied `WorkflowID` (line 339) or `WorkflowOwner` (line 347). No authentication or authorization check occurs before this point, confirming the pre-auth reachability described in the question. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

I was unable to fully confirm within this session whether the panic is recovered by a wrapping HTTP/goroutine-level `recover()` in the gateway request-handling stack (e.g., in `http_handler.go` or the request dispatch loop). If no such recovery mechanism exists, the panic propagates and can crash the gateway process (a Go panic in a goroutine that is not recovered terminates the entire process by default). This is a material uncertainty that should be verified by tracing the goroutine that calls `HandleUserTriggerRequest` and checking for `recover()` wrappers around it.

### Impact Explanation
If unrecovered, this is a pre-authentication, unauthenticated denial-of-service: a single crafted HTTP/gateway trigger request can crash the gateway node process, aligning with Chainlink's "Denial of Service" bounty impact class reachable without any credentials, since it occurs before `authorizeRequest`. If a recover mechanism exists at a higher layer (goroutine or per-request), the impact would be reduced to a single failed request/goroutine rather than a full process crash — this distinction could not be confirmed with certainty in this session.

### Likelihood Explanation
No preconditions are required: the attacker only needs to send one JSON-RPC trigger request over the gateway with `workflow.workflowID` (or `workflowOwner`) set to a lowercase hex string of exactly `workflowIDLength` (66) or `workflowOwnerLength` (42) characters that lacks the `0x` prefix. This is trivially and repeatably reproducible.

### Recommendation
In `normalizeHex`, validate that `len(hexStr) <= expectedHexLength` before calling `strings.Repeat`, and return an error (propagated as a user-facing 4xx validation error) instead of silently computing a possibly negative repeat count. Additionally, tighten `validateHexInput` to require the `0x` prefix explicitly (or compute its length bound against the stripped hex string rather than the raw input), so the two functions share a consistent notion of "expected length."

### Proof of Concept

2. Call `validateHexInput(workflowIDNoPrefix, workflowIDLength)` and assert it returns `nil` (demonstrating the check passes unexpectedly).
3. Call `normalizeHex(workflowIDNoPrefix, workflowIDLength)` directly and assert that it panics (use `require.Panics(t, func() { normalizeHex(...) })`) — confirming the crash.
4. Repeat with `workflowOwnerNoPrefix := strings.Repeat("a", 42)` against `workflowOwnerLength`.
5. Handler-level integration test: send a `workflows.execute` JSON-RPC request through `HandleUserTriggerRequest` with `Workflow.WorkflowID` set to the 66-char prefix-less hex string (no `Auth` needed since it panics pre-auth) and assert the call does not panic / crashes the goroutine, but instead returns a validation error response with `jsonrpc.ErrInvalidRequest`.
6. After the fix, re-run steps 2-5 and assert `normalizeHex`/`validateHexInput` reject the prefix-less or over-length input instead of panicking.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}
```

// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}
```
