### Title
Lockup address squatting via deterministic account ID lets an attacker deploy a lockup with attacker-chosen parameters for a victim's owner account - (File: lockup-factory/src/lib.rs)

### Summary
`LockupFactory::create` derives the lockup contract's account ID deterministically from `sha256(owner_account_id)` and allows *any* caller (not just the intended sponsor) to trigger deployment as long as they attach `MIN_ATTACHED_BALANCE`. An attacker can therefore pre-empt a victim's canonical lockup address, choosing `lockup_duration=0` and `lockup_timestamp=None`, causing the deployed `LockupContract::get_locked_amount` to return `0` immediately, and permanently blocking the legitimate sponsor from ever deploying the real, correctly-parameterized lockup at that address.

### Finding Description
The broken binding: `lockup_account_id_deployed_for(owner) == lockup_account_id_intended_by(sponsor)` should only ever be created once, with parameters chosen by the sponsor/foundation who is entitled to fund `owner`'s grant. Instead, `create` computes: [1](#0-0) 

with no check on `env::predecessor_account_id()` — any unprivileged caller can invoke `create(owner_account_id=victim, lockup_duration=0, lockup_timestamp=None, ...)` and, provided they attach `MIN_ATTACHED_BALANCE`, deploy a lockup contract at `sha256(victim)[..20] + "." + factory`: [2](#0-1) 

The factory unconditionally injects `TransfersInformation::TransfersEnabled{transfers_timestamp: TRANSFERS_STARTED}` regardless of the caller's real authorization: [3](#0-2) 

Once deployed, `LockupContract::get_locked_amount` computes `lockup_timestamp = max(transfers_timestamp + lockup_duration, lockup_timestamp.unwrap_or(0))`. With `lockup_duration=0` and `transfers_timestamp` fixed at `TRANSFERS_STARTED` (already in the past), `lockup_timestamp <= block_timestamp` holds immediately, and with no `release_duration`/vesting, the function returns `0`: [4](#0-3) 

Because NEAR account names are globally unique and `create_account()` on an existing account fails, once the attacker's malicious lockup occupies `victim`'s deterministic address, any subsequent legitimate `create` call by the real sponsor for the same `owner_account_id` fails at `create_account()`, is caught by `is_promise_success()` in `on_lockup_create`, and the sponsor's deposit is simply refunded: [5](#0-4) 

No guard (`assert_owner`, `assert_called_by_foundation`, or any allow-list check on `owner_account_id` vs. `predecessor_account_id`) exists in `create` to prevent this. The attacker permanently deploys "a lockup deployed with parameters its rightful creator never chose" at the victim's canonical address — the sponsor can never deploy the intended real lockup there again.

### Impact Explanation
The victim's canonical lockup address is permanently squatted with an attacker-chosen, effectively-unlocked (`lockup_duration=0`) contract, and the legitimate sponsor/foundation can never deploy the intended lockup with the correct vesting/lockup schedule at that address — this matches the explicitly listed Critical category "an account whitelisted or a lockup deployed with parameters its rightful creator never chose." The attack is repeatable against any not-yet-claimed owner account and costs the attacker only `MIN_ATTACHED_BALANCE` (3.5 NEAR) plus gas per victim address, which they can later reclaim (e.g., by withdrawing via `get_liquid_owners_balance`/`transfer` as owner of their own malicious contract, since `owner_account_id` was set to the victim's name but the attacker controls the deployment — though the actual owner-permission checks inside the lockup itself would still require signing as `victim`, so the attacker cannot withdraw the deposited 3.5 NEAR themselves without the victim's key). Regardless, the funds a real sponsor would have delivered to `victim` can never be locked with the intended schedule at that address.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: the victim's canonical lockup address must simply be unclaimed (true for any account that hasn't yet received a lockup), and the attacker needs only `MIN_ATTACHED_BALANCE` (3.5 NEAR) and gas to call `create`. There is no allow-list, whitelist, or ownership check restricting who can call `create` for a given `owner_account_id`, making this trivially and repeatably exploitable against any target address before its legitimate sponsor acts.

### Recommendation
Restrict `LockupFactory::create` so that the lockup for a given `owner_account_id` can only be created by an authorized caller (e.g., `self.foundation_account_id` or an explicit allow-list), or require the `predecessor_account_id` to match/attest to `owner_account_id`'s consent. Alternatively, make the lockup account ID depend on a value the sponsor controls (e.g., a nonce or explicit sponsor-provided suffix) rather than purely `sha256(owner_account_id)`, so squatting a specific victim's address is not possible.

    #[payable]
    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }

    pub fn get_locked_amount(&self) -> WrappedBalance {
        let lockup_amount = self.lockup_information.lockup_amount;
        if let TransfersInformation::TransfersEnabled {
            transfers_timestamp,
        } = &self.lockup_information.transfers_information
        {
            let lockup_timestamp = std::cmp::max(
                transfers_timestamp
                    .0
                    .saturating_add(self.lockup_information.lockup_duration),
                self.lockup_information.lockup_timestamp.unwrap_or(0),
            );
            let block_timestamp = env::block_timestamp();
            if lockup_timestamp <= block_timestamp {
                let unreleased_amount =
                    if let &Some(release_duration) = &self.lockup_information.release_duration {
                        let end_timestamp = lockup_timestamp.saturating_add(release_duration);
                        if block_timestamp >= end_timestamp {
                            // Everything is released
                            0
                        } else {
                            let time_left = U256::from(end_timestamp - block_timestamp);
                            let unreleased_amount = U256::from(lockup_amount) * time_left
                                / U256::from(release_duration);
                            // The unreleased amount can't be larger than lockup_amount because the
                            // time_left is smaller than total_time.
                            unreleased_amount.as_u128()
                        }
                    } else {
                        0
                    };

                let unvested_amount = match &self.vesting_information {
                    VestingInformation::VestingSchedule(vs) => self.get_unvested_amount(vs.clone()),
                    VestingInformation::Terminating(terminating) => terminating.unvested_amount,
                    // Vesting is private, so we can assume the vesting started before lockup date.
                    _ => U128(0),
                };
                return std::cmp::max(
                    unreleased_amount
                        .saturating_sub(self.lockup_information.termination_withdrawn_tokens),
                    unvested_amount.0,
                )
                .into();
            }
        }
        // The entire balance is still locked before the lockup timestamp.
        (lockup_amount - self.lockup_information.termination_withdrawn_tokens).into()
    }
