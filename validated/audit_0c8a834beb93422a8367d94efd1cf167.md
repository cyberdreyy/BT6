### Title
APR-0 withdraw receipt permanently bricks `stopEpoch` once APR is changed, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
A lender that calls `requestWithdraw` while `unscaledApr == 0` leaves a non-zero `apr0TotalPrincipal` bucket in `IdleCreditVault`. If the honest manager later configures a non-zero APR for the next epoch, `prepareStopEpochWithApr0` reverts with `NotAllowed` *before* clearing `apr0TotalPrincipal`, so every subsequent `stopEpoch` / `stopEpochWithDuration` reverts. Funds can only be unfrozen if the manager sets the APR back to 0 — the bucket can never be cleared while APR ≠ 0.

### Finding Description
`requestWithdraw` routes requests made while `unscaledApr == 0` into `_requestWithdrawApr0`, which accrues `apr0TotalPrincipal` [1](#0-0) . At `stopEpoch`, `prepareStopEpochWithApr0` reverts whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0` [2](#0-1) . The clearing line `apr0TotalPrincipal = 0` sits *after* the revert [3](#0-2) , so the revert is self-perpetuating. Normal claims do not help: `_claimFundedWithdrawRequest` calls `delete apr0Users[_user]` but never decrements the global `apr0TotalPrincipal` [4](#0-3) . The only other decrement is `_clearWithdrawClaimForEpoch`, reachable only on the default-finalization path — which itself requires a `stopEpoch` that will revert [5](#0-4) . Even the default flow (`stopEpoch(0,0)`) is blocked because it goes through the same `prepareStopEpochWithApr0` gate.

The attacker is an ordinary KYC-passing lender making a legal `requestWithdraw` during an APR-0 epoch; the trigger is an honest manager `setAprs`/`stopEpoch` sequence, which is routine operation.

### Impact Explanation
All TVL (AA + BB tranche holders' principal and accrued yield) is frozen for as long as the pool runs with APR ≠ 0. No deposit, withdraw-claim funding, or epoch rollover can complete because `stopEpoch` is the only state transition that funds pending receipts and rolls `epochNumber` [6](#0-5) . Recovery requires the manager to restore `unscaledApr == 0` — i.e., the pool cannot operate with nonzero yield until every APR0 receipt epoch is stopped, and if management intends a nonzero APR product the freeze is effectively permanent for that configuration. Quantified loss: the entire `getContractValue()` plus `pendingWithdraws` is locked.

### Likelihood Explanation
Requires two conditions: (1) the vault operates an epoch with `unscaledApr == 0` (an explicitly supported mode with dedicated `apr0Users`/`apr0RateByEpoch` machinery and tests such as `testApr0WithdrawGetsInterestAtStopEpoch`), and (2) any user requests a withdraw in that epoch — economically free for any tranche holder. The APR change is a normal manager action (`setAprs`), not attacker-controlled or exotic. Caveat I could not fully verify within the search budget: whether `setAprs`/`stopEpochWithDuration` entry points in `IdleCDOEpochVariant` unconditionally invoke `prepareStopEpochWithApr0` on every stop path; the 40 matches of `apr0TotalPrincipal`/`unscaledApr` in `IdleCreditVault.sol` plus calls gated by `_onlyIdleCDO()` strongly indicate all stop paths route through it, but a stop variant that skips the call would narrow the impact.

### Recommendation
In `prepareStopEpochWithApr0`, do not revert when `unscaledApr != 0`. Either settle the outstanding APR0 principal bucket at the last recorded `apr0RateByEpoch` (or zero interest) and then clear `apr0TotalPrincipal`, or move the `apr0TotalPrincipal = 0` reset ahead of the APR check so a stale bucket cannot wedge the epoch machine. Also decrement `apr0TotalPrincipal` inside `_claimFundedWithdrawRequest`/`_settleApr0` when a user's APR0 principal is claimed or settled, so the global bucket cannot outlive its per-user entries.

### Proof of Concept
```solidity
// Foundry fork PoC (extend test/foundry/IdleCreditVault.t.sol harness)
function testPocApr0BlocksStopEpochForever() external {
    // Setup: vault configured in APR0 mode
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    // Attacker: ordinary KYC'd lender deposits and requests withdraw while APR == 0
    uint256 amount = 1000 * ONE_SCALE;
    deal(defaultUnderlying, attacker, amount);
    vm.startPrank(attacker);
    IERC20Detailed(defaultUnderlying).approve(address(idleCDO), amount);
    idleCDO.depositAA(amount);
    cdoEpoch.requestWithdraw(0, cdoEpoch.AATranche());
    vm.stopPrank();
    assertGt(strategy.apr0TotalPrincipal(), 0);

    // Honest manager configures a non-zero APR for the next epoch
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(10e18, 10e18);

    // Epoch end: every stopEpoch path now reverts -> all funds frozen
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0);

    // Attacker claiming their own receipt does NOT clear apr0TotalPrincipal
    // (claimFundedWithdrawRequest deletes apr0Users but not the global bucket)
    vm.prank(attacker);
    cdoEpoch.claimWithdrawRequest();
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0); // still bricked
}
```
