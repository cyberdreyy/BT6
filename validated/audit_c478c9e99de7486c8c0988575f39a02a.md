### Title
Unauthenticated MessageId collision in `dummyHandler` causes cross-user callback overwrite and response misdelivery - ([File: core/services/gateway/handlers/handler.dummy.go])

### Summary
`dummyHandler.HandleLegacyUserMessage` stores the pending user callback keyed only by the attacker-supplied `msg.Body.MessageId`, with no check for an existing in-flight entry, before forwarding the request to DON nodes. `HandleNodeMessage` then delivers whichever node response matches that key to whatever callback is currently stored, so a second request using the same `MessageId` silently overwrites the first requester's callback and receives the first requester's response (or vice versa).

### Finding Description
`dummyHandler.HandleLegacyUserMessage` performs: [1](#0-0) 
with no `found`/duplicate check before overwriting `d.savedCallbacks[msg.Body.MessageId]`. This mirrors the pattern in the capabilities handler at [2](#0-1) , which the question uses as the baseline comparison — and indeed `dummyHandler` has the identical unguarded overwrite, with no locking granularity or ownership check that would prevent it.

The `MessageId` is fully attacker-controlled: for legacy requests it is the `message_id` field set inside the client-signed `api.Message.Body` before hashing/signing, and for JSON-RPC requests it is copied directly from `jsonRequest.ID`/`req.ID` supplied by the caller: [3](#0-2) 
The gateway's `ProcessRequest` entrypoint accepts these unauthenticated/self-signed messages (any Ethereum key holder can sign; there is no per-DON allowlist enforced in this handler) and routes them straight to `HandleLegacyUserMessage`/`HandleJSONRPCUserMessage`: [4](#0-3) 

`HandleNodeMessage` matches purely by `msg.Body.MessageId` and blindly delivers to whatever `savedCallbacks` entry currently occupies that key: [5](#0-4) 
Because the map key collision is possible across distinct callers (nothing ties `MessageId` to a session, connection, or user identity), a second request with the same `MessageId` sent before the first node response returns will replace the first caller's callback. When the node reply for that ID arrives, it is delivered to the second caller's callback — resulting in cross-user response delivery. No error is surfaced to either caller; the first caller's connection simply never gets a response (or gets the second caller's response depending on timing), and `HandleLegacyUserMessage` returns `nil` on success in both cases.

The `dummyHandler` is a real, production-wireable handler type (`DummyHandlerType = "dummy"`) registered in the handler factory switch, not test-only scaffolding: [6](#0-5) [7](#0-6) 
Any DON/service configured with `Name = "dummy"` in its handler list is affected.

### Impact Explanation
This is a cross-user response confusion vulnerability: an unauthenticated (or minimally-privileged, self-signing) attacker can cause the gateway to deliver another user's DON response to the attacker's own connection, or cause a victim to receive a response tied to the attacker's request, by racing two requests with a colliding `MessageId`. This matches the "cross-user response confusion" bounty impact class — data intended for one caller is exposed/delivered to a different, unrelated caller through the gateway.

### Likelihood Explanation
- No special privilege is required: the attacker needs only the ability to sign gateway messages with any private key (or send any JSON-RPC request) — a capability freely available to any external client of the gateway's user-facing endpoint.
- The attacker fully controls the `MessageId` value, so producing a collision (either two requests from the attacker, or the attacker guessing/reusing a victim's known/predictable ID) is trivial and repeatable.
- The only extra requirement is timing: the second colliding request must be sent before the DON node responds to the first — feasible given typical DON round-trip request latency (the gateway waits for a full node round trip before deleting the map entry).

### Recommendation
Reject or error out `HandleLegacyUserMessage`/`HandleJSONRPCUserMessage` when a `savedCallbacks` entry already exists for the given `MessageId` (return an explicit "duplicate message ID" error to the caller) instead of silently overwriting it, mirroring the fix needed in the capabilities handler. Additionally, consider binding callback lookups to a value derived from message uniqueness/signature (e.g., a composite key including a per-connection nonce or sender identity) rather than the raw attacker-chosen `MessageId` alone.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/handler_dummy_test.go`:
1. Construct a `dummyHandler` with a mock `DON` whose `SendToNode` records the outgoing request but sends no immediate reply.
2. Create `callback1 := hc.NewCallback()` and call `HandleLegacyUserMessage(ctx, msg1{MessageId: "dup"}, callback1)`; assert `d.savedCallbacks["dup"].Callback == callback1`.
3. Create `callback2 := hc.NewCallback()` and call `HandleLegacyUserMessage(ctx, msg2{MessageId: "dup"}, callback2)` with no error returned; assert `d.savedCallbacks["dup"].Callback == callback2` (i.e., `callback1` was silently discarded, no error/warning surfaced).
4. Simulate a node response for `MessageId: "dup"` via `HandleNodeMessage`; assert that `callback2.Wait(ctx)` receives the response while `callback1.Wait(ctx)` times out/never resolves — demonstrating the first caller's request context is dropped and, depending on payload origin, the wrong caller's data can be exchanged.

func (d *dummyHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return err
	}
	msg.Body.MessageId = resp.ID
	err = msg.Validate()
	if err != nil {
		return err
	}
	if nodeAddr != msg.Body.Sender {
		return fmt.Errorf("node address %s does not match message sender %s", nodeAddr, msg.Body.Sender)
	}
	d.mu.Lock()
	savedCb, found := d.savedCallbacks[msg.Body.MessageId]
	delete(d.savedCallbacks, msg.Body.MessageId)
	d.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(&msg), ErrorCode: api.NoError})
	}
	return nil
}
