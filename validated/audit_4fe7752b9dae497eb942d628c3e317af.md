### Title
APR0 withdraw request permanently vetoes APR increases and can brick `stopEpoch` - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
A single unprivileged withdraw request made while `unscaledApr == 0` writes the attacker's principal into `apr0TotalPrincipal`. `prepareStopEpochWithApr0` then hard-reverts (`NotAllowed`) on every `stopEpoch` as long as `unscaledApr != 0` while that bucket is non-zero. Because `apr0TotalPrincipal` is only cleared at the end of the same reverting function, the revert is terminal: the epoch can never be stopped under any non-zero APR. The bug-class analog to CVE-2017-14696 is a crafted request (a 1-wei APR0 withdraw) that turns an accounting guard into a protocol-wide denial of service / yield freeze.

### Finding Description
The relevant flow:

1. `IdleCDOEpochVariant.requestWithdraw` (contracts/IdleCDOEpochVariant.sol:739) calls `IdleCreditVault.requestWithdraw`, which routes APR0 requests into `_requestWithdrawApr0` (contracts/strategies/idle/IdleCreditVault.sol:567), doing `apr0Users[_user].principal += _amount` and `apr0TotalPrincipal += _amount`.
2. At `stopEpoch`, the CDO calls `prepareStopEpochWithApr0` (IdleCreditVault.sol:490). When `apr0TotalPrincipal != 0`, the check `if (unscaledApr != 0) revert NotAllowed();` (line 506) fires.
3. `apr0TotalPrincipal = 0` is only executed at line 540, *after* the revert. There is no other code path that decrements or clears it — `_settleApr0` only clears per-user `principal`, never the global bucket.

So once any lender requests a withdraw during an APR0 epoch, two outcomes exist:

- **Manager raises the APR** (e.g., new borrower terms, normal operation): every `stopEpoch` reverts permanently. `epochNumber` never increments, so `claimWithdrawRequest` reverts for everyone via `epochNumber <= lastWithdrawRequest` (IdleCreditVault.sol:326), deposits/`startEpoch` stall, and all vault funds are frozen indefinitely.
- **Manager keeps APR at 0** to settle the bucket: the attacker can simply re-request a dust APR0 withdraw each epoch (cost = gas; principal is fully reclaimable via `claimWithdrawRequest`), pinning the pool at `unscaledApr == 0` forever and destroying all lender yield.

The invariant broken is liveness/fair yield: an unprivileged requester gains a perpetual veto over the honest manager's APR configuration. Nothing stops it — `requestWithdraw` has no minimum amount, KYC (`isWalletAllowed`) is the only gate, and `_ensureDefaultRecoveryInitialized` does not apply. Attacker loses nothing: their principal sits in `apr0Users` and pays out at claim.

### Impact Explanation
- Worst case (manager requires positive APR): permanent freeze of all vault TVL and all pending withdraw receipts — `stopEpoch` cannot execute, epoch accounting halts, no claims settle.
- Alternatively: permanent suppression of the pool to 0% APR, i.e., theft of all future yield for all LPs at ~zero cost to the attacker. One epoch of suppressed yield on, e.g., $1M TVL at a 10% target APR ≈ $274/day of foregone interest, repeatable indefinitely.

### Likelihood Explanation
Requires only a KYC-passing wallet and an epoch where `unscaledApr == 0` (APR0 mode is a first-class supported configuration — `setAprs(0,0)`, bootstrap periods, and the dedicated APR0 accounting/tests all exist). The attack transaction is an ordinary `requestWithdraw` of any dust amount. No privileged role, no default, no timing race needed; the re-request grief can be chained each epoch.

### Recommendation
Do not revert `stopEpoch` on the APR0/nonzero-APR mismatch. Either:
- settle the APR0 bucket at the APR that was in effect at request time (track APR per `principalEpoch`), or
- treat APR0 principal as ordinary `withdrawsRequests` once `unscaledApr` becomes non-zero, migrating `apr0TotalPrincipal` into the normal pending bucket and clearing it, so `stopEpoch` is unconditionally executable.

### Proof of Concept
Foundry fork test sketch (extends `test/foundry/IdleCreditVault.t.sol` helpers):

```solidity
function testApr0DustRequestBricksStopEpochOnAprRaise() external {
    // Pool currently in APR0 mode
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    // Attacker: KYC'd lender deposits and requests a dust withdraw
    address attacker = makeAddr('attacker');
    _depositWithUser(attacker, 1 * ONE_SCALE, true);          // tiny deposit
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(1, address(AAtranche));          // apr0TotalPrincipal > 0

    _startEpochAndCheckPrices(0);

    // Honest manager restores a positive APR for the next epoch
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(initialProvidedApr, 0);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.prank(manager);
    vm.expectRevert();                                        // NotAllowed
    cdoEpoch.stopEpoch(initialProvidedApr, 0);
    // epochNumber never bumps: all claimWithdrawRequest calls revert,
    // apr0TotalPrincipal can never be cleared -> permanent freeze,
    // or forced APR0 epoch every epoch via re-requested dust withdraws.
}
```
