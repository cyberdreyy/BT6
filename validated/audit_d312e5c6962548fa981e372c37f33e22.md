### Title
Single-signature `has_signed_block_in_tenure` guard permanently suppresses timeout, wedging a minority signer into never falling back to the prior miner - ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
`SortitionState::is_timed_out` unconditionally returns `false` for any signer that has individually signed even one block in a tenure, regardless of whether that block ever reached the network-wide signature threshold. An attacker who wins one miner slot can get a single signer to sign one early block and then withhold all further proposals, permanently exempting that signer from the inactivity-timeout fallback while every other (non-signing) signer correctly times out and switches to the prior-tenure miner.

### Finding Description
The equality the guard depends on is: "if this signer signed a block in tenure T, T cannot be abandoned." In `is_timed_out`, this is implemented purely as a local check on `db.has_signed_block_in_tenure(sortition)` [1](#0-0) , without verifying that the signed block ever reached the global signing threshold (i.e., was globally accepted). The comment at lines 60-67 explicitly rationalizes the design by distinguishing an unsigned "pre-commit" from an actual signature, but never distinguishes an *individually* signed vote from a *threshold-reached* signed block [2](#0-1) .

Attack flow:
1. Attacker wins a miner slot and proposes a single, fully valid tenure-change block for tenure T.
2. One honest signer A validates and signs it normally (`has_signed_block_in_tenure(T)` becomes `true` for A's local `SignerDb` only — this is a per-signer local record, not a network-wide fact).
3. The attacker withholds all further block proposals for T, stalling the tenure.
4. In `check_proposal`, for signer A: `SortitionState::is_timed_out(&cur_sortition, ...)` returns `Ok(false)` forever (line 69-71), so `cur_sortition.miner_status` stays `Valid` for A.
5. Every other signer B, having never signed a block in T, has `has_signed_block_in_tenure` = `false`, so once `block_proposal_timeout` elapses their `is_timed_out` returns `true`, marking `cur_sortition.miner_status = InvalidatedBeforeFirstBlock` (lines 144-163), letting them accept the fallback proposal from `last_sortition` via the `ProposedBy::LastSortition` branch (lines 301-316).
6. For signer A, `cur_sortition.miner_status` is still `Valid`, so the same fallback proposal from `last_sortition` hits the guard `if self.cur_sortition.miner_status != InvalidatedBeforeFirstBlock { return Err(RejectReason::NotLatestSortitionWinner) }` (lines 304-315) and is rejected.

The result: signer A is permanently stuck endorsing the stalled tenure T (and rejecting the network's fallback tenure), while the rest of the signer set converges on the prior miner. Existing guards do not prevent this because `is_timed_out`'s exemption is keyed solely on a *local, individual* act of signing, not on whether that signature ever became part of a canonical, threshold-confirmed block.

### Impact Explanation
This breaks the bounded-liveness guarantee of the inactivity-timeout/fallback mechanism for the affected signer: signer A is wedged into never being able to switch away from an abandoned tenure and never signs the network's actual fallback tenure (High, liveness). It borders on Critical if signer A is later coerced or independently proposed a conflicting block for the resumed/failed-over tenure at the same block height as the majority's fallback tenure, since A's local state machine treats that as the "current" valid tenure and would sign a competing block, producing a chain split/uniqueness violation at that height. The bug is deterministic and repeatable per tenure and does not require compromising A's key or getting any majority — only one attacker-controlled miner slot and one honest signer's routine early signature.

### Likelihood Explanation
Preconditions are minimal and match ordinary honest-signer behavior: an attacker only needs to win one sortition slot (their own BTC) and propose one syntactically/semantically valid tenure-change block, which any live signer will sign as a matter of course. No majority of signers, no compromised keys, no local host access, and no auth_token are needed — only crafting one BlockProposal and then going silent. This is fully repeatable across tenures and does not depend on any race condition; it is a deterministic consequence of the guard's semantics.

### Recommendation
Change the exemption in `is_timed_out` to require that the signed block reached global/threshold acceptance (e.g., check `signer_db.get_last_globally_accepted_block` or an equivalent globally-accepted marker for the tenure) rather than merely `has_signed_block_in_tenure`, which only reflects this signer's individual, possibly non-quorate vote. If only a pre-quorum individual signature exists, the tenure should still be eligible to time out and fall back like any other signer's view.

### Proof of Concept
```rust
// stacks-signer/src/chainstate/tests/v1.rs (conceptual addition)
#[test]
fn minority_signer_wedged_after_single_signature() {
    let mut db_a = SignerDb::new(...); // signer A's local db
    let mut db_b = SignerDb::new(...); // signer B's local db
    let tenure_ch: ConsensusHash = ...;

    // Both signers observe the tenure's burn block.
    db_a.insert_burn_block(...).unwrap();
    db_b.insert_burn_block(...).unwrap();

    // Only signer A signs one early block in tenure T (attacker's single valid proposal).
    db_a.record_signed_block_in_tenure(&tenure_ch, &block).unwrap();

    // Advance time past block_proposal_timeout, miner then withholds further proposals.
    advance_time(block_proposal_timeout + Duration::from_secs(1));

    // Signer A never times out; signer B does.
    assert_eq!(SortitionState::is_timed_out(&tenure_ch, &db_a, block_proposal_timeout).unwrap(), false);
    assert_eq!(SortitionState::is_timed_out(&tenure_ch, &db_b, block_proposal_timeout).unwrap(), true);

    // Feed both a fallback-tenure proposal (from last_sortition / prior miner).
    let fallback_proposal = build_fallback_block_proposal();
    let result_a = sortitions_view_a.check_proposal(&client, &mut db_a, &fallback_proposal, false, ReplayTransactionSet::none());
    let result_b = sortitions_view_b.check_proposal(&client, &mut db_b, &fallback_proposal, false, ReplayTransactionSet::none());

    assert_eq!(result_a, Err(RejectReason::NotLatestSortitionWinner)); // A stuck on stalled tenure
    assert!(result_b.is_ok()); // B correctly falls back
}
```
