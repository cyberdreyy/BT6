### Title
Cross-user response confusion via colliding client-controlled `message_id` in `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Finding Description
`handler.HandleLegacyUserMessage` stores the caller's response `Callback` keyed only by the attacker-controlled `msg.Body.MessageId`: [1](#0-0) 

`MessageId` is a plain client-supplied string field in `MessageBody` that is included in, but not derived from, the signature — any sender can sign a message with any `MessageId` value of their choosing, including one they observed in someone else's request/response (echoed back in JSON-RPC responses): [2](#0-1) [3](#0-2) 

`Validate()` only checks length/format constraints and recovers the signer into `Body.Sender`; it never checks that `MessageId` is unique or bound to the sender: [4](#0-3) 

Because `savedCallbacks` is a flat `map[string]*savedCallback` keyed by `MessageId` alone, a second `HandleLegacyUserMessage` call using the same `MessageId` (from a different sender) simply overwrites the map entry before the DON has responded: [5](#0-4) 

When a DON node's response for that `MessageId` arrives, `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks[msg.Body.MessageId]` and delivers the response to whichever callback is currently stored — with no re-validation that the response's sender/receiver matches the original requester connection: [6](#0-5) 

Exploit flow: victim sends a `web_api_trigger` request with `message_id=X`; gateway stores `savedCallbacks[X] = victimCallback` and forwards to DON nodes. Before any node responds, attacker (any low-priv gateway client who can sign messages, e.g. from an allow-listed key or by observing `X` in a prior echoed response) sends their own `HandleLegacyUserMessage` request with the same `message_id=X`, overwriting `savedCallbacks[X] = attackerCallback`. When the DON node responds (echoing `MessageId=X`), the response is routed to whichever callback is currently in the map — the attacker's — so the attacker's HTTP connection (`callback.SendResponse`) receives the DON's trigger acknowledgment/response tied to the victim's original request, while the victim's connection never receives a response (times out). This violates request/response binding: a response is delivered to a sender other than the one whose request produced it.

### Impact Explanation
This is a cross-user response confusion vulnerability: an unprivileged/low-privilege gateway client can hijack the DON's response meant for another user's request by MessageId collision. Depending on payload content (trigger acknowledgment status, execution metadata), this can leak information about another user's request/trigger flow to an unauthorized party and causes denial-of-response for the victim. This maps to the "unauthorized action on another user's request / attacker-controlled data returned to another user" bounty impact class.

### Likelihood Explanation
Preconditions: attacker only needs the ability to send signed `HandleLegacyUserMessage`/gateway HTTP requests (any registered gateway client key, or an allow-listed low-privilege sender) and knowledge of a target `MessageId` (observable since it's echoed in prior responses/requests, or predictable if callers use sequential/simple IDs). No admin, operator, or DON-compromise is required. It requires timing (attacker's overwrite must land after victim's insert and before the DON node responds) but is fully reproducible in a unit/integration test using two `HandleLegacyUserMessage` calls with the same `MessageId` and controlled timing (no live race needed to prove the vulnerable code path).

### Recommendation
- Scope `savedCallbacks` keys by `(Sender, MessageId)` (or a server-generated internal ID) instead of `MessageId` alone, so a collision by a different signer cannot overwrite another sender's entry.
- Reject/queue (instead of overwrite) `HandleLegacyUserMessage` calls when an active `MessageId` already exists in `savedCallbacks`, returning an error to the second caller.
- Validate on the response path (`handleWebAPITriggerMessage`) that the responding message's `Receiver`/session matches the original stored request's sender before dispatching to the callback.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build `victimMsg := triggerRequest(t, victimKey, ..., messageID="X")` and `attackerMsg := triggerRequest(t, attackerKey, ..., messageID="X")` (same `MessageId`, different signing keys).
2. Call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCb)`.
3. Before sending any DON response, call `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCb)`.
4. Assert `handler.savedCallbacks["X"]` now stores `attackerCb`'s handler (only one entry survives).
5. Simulate the DON node response for `MessageId=X` via `handler.HandleNodeMessage`.
6. Assert `attackerCb.Wait(ctx)` returns the response payload while `victimCb.Wait(ctx)` times out/never resolves — demonstrating the response intended for the victim's request is delivered to the attacker's callback instead.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
