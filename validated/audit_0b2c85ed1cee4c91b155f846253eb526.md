### Title
Unauthenticated log-line forgery lets job script content spoof step markers and suppress/forge trace output - (File: executors/kubernetes/container_entrypoint_forwarder.go)

### Summary
`entrypointLogForwarder.commandStatus` distinguishes runner-injected step markers from arbitrary job stdout using a purely syntactic heuristic — a fixed-length timestamp string followed by a space and JSON containing `command_exit_code` or `script`. There is no authentication, secret token, or separate channel that ties a marker line to the runner itself, so any stdout content the job produces that matches this shape is treated as a trusted control signal.

### Finding Description
`Write`/`writeLine` in `executors/kubernetes/container_entrypoint_forwarder.go` split the container's combined stdout stream into lines and feed each into `commandStatus` [1](#0-0) . `commandStatus` only checks that the first `len(containerLoggerTimeStampFormat)` bytes parse as a valid RFC3339Nano-like timestamp and that the remainder of the line is JSON containing `command_exit_code` or `script` [2](#0-1) . `StageCommandStatus.TryUnmarshal` performs no further validation beyond "is this valid, non-empty JSON" [3](#0-2) .

The comment on `commandStatus` itself acknowledges the design problem: "we understand if the logs coming in are part of a step_command or 'something else'" — i.e., the control-plane markers and the job's own stdout share the exact same stream and are disambiguated only by shape, not by origin [4](#0-3) . A job step's script executes as a subprocess of the entrypoint and inherits the same stdout that the entrypoint uses to emit its own JSON status markers, so job-controlled `echo` output is byte-for-byte indistinguishable from a legitimate marker once it matches the timestamp+JSON pattern.

An attacker who controls job script content can trivially produce a matching line, e.g.:
```
echo "$(date -u +%Y-%m-%dT%H:%M:%S.%9NZ) {\"command_exit_code\":0}"
```
This produces a real, valid timestamp (satisfying `time.Parse`) followed by valid JSON with `command_exit_code` set, so `TryUnmarshal` returns `true` and `IsExited()` returns `true`, forcing `lf.paused = false` regardless of the forwarder's actual internal state [5](#0-4) . Conversely, echoing a line with a crafted `"script"` field spoofs `BuildStage()` and forces `lf.paused = true`, silently dropping all subsequent lines until a real (or another forged) exit marker arrives [6](#0-5) .

No existing check stops this: there is no shared secret, sequence number, dedicated file descriptor, or out-of-band channel separating runner-authored markers from job-authored stdout — the only gate is "does this line look like a marker," which the attacker fully controls.

### Impact Explanation
A job step can forge an early "exited" marker to prematurely resume forwarding (causing duplicate/out-of-order log content in the trace), or forge a step-start marker to prematurely pause forwarding and suppress all subsequent legitimate output from the trace — including runner-injected diagnostic or exit-status lines for later steps. This is a trace-integrity/log-suppression issue: an unprivileged job author can hide or corrupt what appears in the CI job trace, undermining the invariant that trace content faithfully reflects what happened during job execution.

### Likelihood Explanation
This requires only that the job runs on the Kubernetes executor using the attach/logs-based step execution path (the "steps"/entrypoint execution model referenced by `container_entrypoint_forwarder.go`), and that the attacker controls script content for a step — both are standard, low-privilege capabilities of any pipeline author. Producing a valid timestamp string is trivial with `date` (or any language's time-formatting call) inside the job script, and no randomness or secret is needed to match the format check, making this fully deterministic and repeatable.

### Recommendation
Do not disambiguate control markers from job output using content shape alone. Options:
- Emit runner-authored markers on a separate stream/file descriptor not shared with the job script's stdout (already partially done via separate log files elsewhere in the codebase — apply the same separation here).
- If markers must share the stream, prefix them with an unguessable per-job nonce/secret known only to the runner and entrypoint, and require `commandStatus` to verify that prefix before treating the line as a marker.
- Alternatively, have the entrypoint write markers to a dedicated fd/pipe that is never connected to the executed step's stdout, eliminating job-controlled input from the control channel entirely.

### Proof of Concept
Go unit test extending `container_entrypoint_forwarder_test.go`:
```go
func TestEntrypointLogForwarder_JobCanForgeStepMarker(t *testing.T) {
    sink := &bytes.Buffer{}
    lf := &entrypointLogForwarder{Sink: &nopCloser{sink}, paused: true} // simulate: runner currently suppressing output during a real step

    ts := time.Now().UTC().Format(containerLoggerTimeStampFormat)
    // attacker-controlled job stdout forging an "exited" marker
    forged := []byte(ts + ` {"command_exit_code":0}` + "\n")

    _, err := lf.Write(forged)
    require.NoError(t, err)

    // BUG: paused flips to false purely because job output matched the marker shape,
    // even though no genuine runner marker was ever emitted.
    require.False(t, lf.paused, "job-controlled stdout should not be able to toggle forwarding state")
}
```
Expected (buggy) result: `lf.paused` becomes `false` after processing attacker-supplied job output, confirming that arbitrary job stdout can spoof control-plane state without any runner involvement.

func (lf *entrypointLogForwarder) commandStatus(p []byte) (shells.StageCommandStatus, bool) {
	cmdStatus := shells.StageCommandStatus{}

	// check if the first part resembles a timestamp
	if len(p) < len(containerLoggerTimeStampFormat) ||
		p[len(containerLoggerTimeStampFormat)] != ' ' {
		return cmdStatus, false
	}

	line := string(p)
	ts := line[:len(containerLoggerTimeStampFormat)]
	_, err := time.Parse(containerLoggerTimeStampFormat, ts)

	if err != nil {
		return cmdStatus, false
	}

	// the actual log line starts after the timestamp + a space
	line = line[len(containerLoggerTimeStampFormat)+1:]

	ok := cmdStatus.TryUnmarshal(line)
	return cmdStatus, ok
}

// TryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It wil return true only if the unmarshalled struct has all of its required fields be non-nil.
// It's safe to use the struct only if this method returns true.
func (c *StageCommandStatus) TryUnmarshal(line string) bool {
	var status stageCommandExitStatusImpl
	err := status.tryUnmarshal(line)
	if err != nil {
		return false
	}

	if status.isEmpty() {
		return false
	}

	status.applyTo(c)

	return true
}

func (c StageCommandStatus) IsExited() bool {
	return c.CommandExitCode != nil
}

func (c StageCommandStatus) BuildStage() common.BuildStage {
	if c.Script == nil {
		return ""
	}

	// When using `powershell/pwsh`, script contains only the script name without its extension being executed.
	// When using `bash` shell, script contains the script absolute path. We therefore need to extract the script name.
	split := strings.Split(*c.Script, "/")
	stage := split[len(split)-1]

	return common.BuildStage(stage)
}
