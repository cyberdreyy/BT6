### Title
Stale confirmations from removed multisig members allow executing requests below the confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm` counts confirmations purely by the size of the `confirmations` set stored per request, without validating that each confirming entry still corresponds to a current member of the multisig. `delete_member` only purges requests *originated* by the removed member and that member's `num_requests_pk` entry — it does not scan and strip that member's stale confirmation from any *other* still-pending request. As a result, a request confirmed in part by a member who is later removed can still be executed once enough total (stale + live) confirmations accumulate, even though fewer than `num_confirmations` currently valid members actually approved it.

### Finding Description
The invariant the contract is supposed to enforce is: `count(confirmations from members that are currently valid) >= num_confirmations` before executing any `MultiSigRequest` (including `Transfer`, `AddKey`, `FunctionCall`, etc.).

In `confirm`, the check is purely a set-size comparison: [1](#0-0) 

The confirmation set stores members by `member.to_string()` with no re-validation against `self.members` at execution time. When `delete_member` removes a member, it only removes requests whose `r.member == member` (i.e. requests that member *originated*) and clears that member's `num_requests_pk` bookkeeping — it does not iterate `self.confirmations` to strip that member's stale confirmation entries from requests originated by *other* members: [2](#0-1) 

`remove_request` (called both by `confirm` on execution and by `delete_request`) also never validates confirmer membership — it only manipulates `num_requests_pk` for the request's original submitter: [3](#0-2) 

Consequently, a confirmation recorded by an account that is later removed from `self.members` remains counted toward the threshold for any request it confirmed before removal, as long as that request is not deleted or already executed.

### Impact Explanation
This breaks the authorization binding "requests execute only when `num_confirmations` *current* members approved them." A request such as `Transfer` can be executed with confirmations that include a member no longer part of the multisig, meaning fewer than the configured threshold of *live* members actually authorized the action. This falls under the Critical impact category "a multisig request executed below threshold," since NEAR can be moved (or keys added/removed, or arbitrary `FunctionCall`s executed) by only `num_confirmations - 1` (or fewer) currently trusted parties.

### Likelihood Explanation
This requires no privileged action from the attacker beyond being a former member (already an in-scope allowed actor per the rules: "an account trusted as a pool or whitelist versus the code and arguments that trust was granted for" — analogous to a member trusted to confirm requests continuing to have influence after being untrusted). The scenario naturally occurs in normal operational flow: a pending request outstanding at the time a member is offboarded (e.g., due to key compromise or team departure) retains that member's confirmation weight. No malicious collusion or edge-case timing manipulation beyond ordinary request lifecycle is needed — only that a request remain unconfirmed/unexecuted when a confirming member is removed.

### Recommendation
When executing a request (i.e., in `confirm`, before comparing `confirmations.len()` against `num_confirmations`), filter the stored confirmations against the current `self.members` set and only count confirmations from members still present. Additionally, `delete_member` should proactively purge the removed member's confirmation entry from every request in `self.confirmations`, not just requests it originated, mirroring how `remove_request` already targets originator-only bookkeeping. Compute the executing threshold as `count(confirmations ∩ current members) >= num_confirmations`.

### Proof of Concept
1. Multisig deployed with members `{A, B, C}` and `num_confirmations = 3`. [4](#0-3) 
2. `A` calls `add_request_and_confirm(R1)` for `MultiSigRequestAction::Transfer { amount }` — `confirmations(R1) = {A}`.
3. `B` calls `confirm(R1)` — `confirmations(R1) = {A, B}` (2 < 3, not yet executed), per the counting logic in `confirm`. [1](#0-0) 
4. Separately, the multisig (via its own governance flow reaching threshold) executes a `DeleteMember { member: B }` request. `delete_member` removes `B` from `self.members` and cleans up only requests `B` itself originated — `R1` (originated by `A`) is untouched, so `confirmations(R1)` still contains `B`. [2](#0-1) 
5. `C` calls `confirm(R1)`. The set size becomes `{A, B, C}.len() + 1 semantics` → `2 + 1 >= 3` triggers `remove_request` and `execute_request`, transferring funds — even though `B` is no longer a valid member, so only `A` and `C` (2 live members) actually authorized the transfer against a 3-of-N threshold. [5](#0-4)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
