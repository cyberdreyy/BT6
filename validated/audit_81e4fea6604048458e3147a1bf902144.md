### Title
Zip extraction in `ExtractZipArchive` writes files at absolute/traversal `file.Name` paths with no destination-root confinement - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipFile`/`ExtractZipArchive` in `helpers/archives/zip_extract.go` extract each `zip.File` using `file.Name` directly with `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Symlink`, and `os.Mkdir(file.Name, ...)`, with the only pre-write check being a `.git` directory guard. Neither the legacy zip extractor CLI helper (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) nor its callers (`ArtifactsDownloaderCommand.Execute`, `CacheExtractorCommand.Execute`) validate that `file.Name` stays within the intended extraction directory (`wd`/`dir`) before delegating to `ExtractZipArchive`.

### Finding Description
The call chain is: `ArtifactsDownloaderCommand.Execute` / `CacheExtractorCommand.Execute` (`commands/helpers/artifacts_downloader.go:131`, `commands/helpers/cache_extractor.go:655`) → `archive.NewExtractor(format, f, size, wd)` → `ziplegacy.NewExtractor` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:20`) → `extractor.Extract` (`zip_legacy_extractor.go:26-32`) → `archives.ExtractZipArchive(zr)` (`helpers/archives/zip_extract.go:85-110`).

Critically, the `dir` parameter passed into `ziplegacy.NewExtractor` is stored on the `extractor` struct (`zip_legacy_extractor.go:13-21`) but is **never used**: `Extract` calls `archives.ExtractZipArchive(zr)` without passing `e.dir` at all [1](#0-0) . `ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipFileEntry`, `extractZipSymlinkEntry`, `extractZipDirectoryEntry`) then operate purely on `file.Name` from the zip header, calling `os.MkdirAll(filepath.Dir(file.Name), 0o777)`, `os.OpenFile(file.Name, ...)`, `os.Symlink(data, file.Name)`, `os.Mkdir(file.Name, ...)` [2](#0-1) . The only validation performed is `errorIfGitDirectory(file.Name)`, which merely warns/skips `.git` paths and is not fail-closed for other cases [3](#0-2) [4](#0-3) . There is no `filepath.Clean`, no check that the resolved path is a descendant of `dir`/`wd`, and no rejection of absolute paths or `../` traversal sequences anywhere in this path.

Both CLI entrypoints resolve `wd` via `os.Getwd()` and pass it into `archive.NewExtractor(format, f, size, wd)` [5](#0-4) [6](#0-5) , giving the (false) impression that extraction is confined to `wd`. In reality, for the `zip`/legacy-zip format the `dir` argument is silently dropped before reaching `ExtractZipArchive`, so a crafted zip entry with `file.Name = "/etc/cron.d/x"` or `"../../../../tmp/x"` writes wherever the extracting process's permissions allow, relative to the process's actual CWD (or absolute paths) rather than the intended `dir`.

The artifact/cache content (`c.File` in `CacheExtractorCommand`, or the downloaded artifacts archive in `ArtifactsDownloaderCommand`) is attacker-influenced: cache archives are produced from `CacheArchiverCommand`/job cache paths, and artifacts archives are produced by the job itself and uploaded to GitLab, then downloaded and extracted by the Runner during a later job/pipeline run on the same executor/host without server-side re-validation of entry names in this path.

### Impact Explanation
On shell/SSH/exec-style executors (and any executor where the "helper" extraction binary runs directly on the host or with host-adjacent filesystem access, as opposed to sandboxed container filesystems), a job that controls the contents of its own artifacts/cache zip can cause the Runner's `artifacts-downloader`/`cache-extractor` helper process to write or overwrite arbitrary files reachable by that process's user (e.g., outside `CI_PROJECT_DIR`, into other projects' build directories on a shared runner host, or over files like cron entries, shell profile files, SSH `authorized_keys`, etc., subject to OS permissions of the runner/user account). This breaks the "File operations must stay within intended build/cache/artifact roots" invariant and is a classic zip-slip / arbitrary-file-write vulnerability, not merely a theoretical one, since the confinement parameter (`dir`) exists in the API but is not enforced by the zip codepath.

### Likelihood Explanation
Preconditions: an unprivileged pipeline author can control the exact bytes of an artifact or cache zip uploaded from a job (trivial — jobs create/upload their own artifact/cache archives, or an attacker with `--file` control over the CLI helper as described can supply a hand-crafted zip directly). No special runner configuration is required beyond a shared or persistent host-adjacent runner (shell/ssh/custom executors, or docker executors with host-mounted build dirs) where the same OS-level user later extracts the malicious archive. This is reliably reproducible: any zip containing a `zip.File.Name` of `/absolute/path` or `../traversal` will hit `extractZipFile`/`extractZipFileEntry` with no root check.

### Recommendation
Enforce destination-root confinement in `helpers/archives/zip_extract.go`: thread the target `dir` through `ExtractZipFile`/`ExtractZipArchive` (currently dropped in `ziplegacy.extractor.Extract`), and for every `file.Name`, compute `filepath.Join(dir, file.Name)`, `filepath.Clean` it, and verify (e.g., via `filepath.Rel` or a prefix check with a trailing separator) that the result is still inside `dir` before calling `os.MkdirAll`, `os.OpenFile`, `os.Symlink`, or `os.Mkdir`; reject (fail-closed, not just warn) any entry with an absolute path or that resolves outside `dir`, mirroring the confinement `archive.NewArchiver`'s doc comment already promises for archiving. Also validate symlink targets don't escape the root.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go` (or a new test):
```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    dir := t.TempDir()
    outsideMarker := filepath.Join(t.TempDir(), "pwned")

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    // Absolute path escape attempt
    f, _ := zw.Create(outsideMarker) // or use "../../pwned" relative traversal
    _, _ = f.Write([]byte("pwned"))
    _ = zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    origWD, _ := os.Getwd()
    _ = os.Chdir(dir)
    defer os.Chdir(origWD)

    err := ExtractZipArchive(zr)

    // Expect fail-closed behavior:
    assert.Error(t, err)
    _, statErr := os.Stat(outsideMarker)
    assert.True(t, os.IsNotExist(statErr), "file must not be written outside extraction root")
}
```
Expected current result: the file at `outsideMarker` (or resolved traversal path) is created and `ExtractZipArchive` returns `nil`, demonstrating the missing confinement; after the fix, the function must return a non-nil error and the outside file must not exist.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
