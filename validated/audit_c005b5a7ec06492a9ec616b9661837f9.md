### Title
TOCTOU race between `jwtReplayCache.isReplay` and `recordUsage` allows JWT reuse for multiple workflow executions - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` checks `h.jwtCache.isReplay(claims.ID)` and, only after the authorized-key lookup succeeds, calls `h.jwtCache.recordUsage(claims.ID)`. These are two separate lock acquisitions on `jwtReplayCache.mu` rather than a single atomic check-and-set, so concurrent requests carrying the same JWT `jti` can all pass the replay check before any of them records usage.

### Finding Description
`isReplay` takes an `RLock`, reads the map, and releases the lock [1](#0-0) . `recordUsage` is called separately afterward, only once authorization succeeds, taking a full `Lock` [2](#0-1) . In `Authorize`, the sequence is: verify JWT → `isReplay` check → authorized-key lookup → `recordUsage` [3](#0-2) . Because the check and the write are not combined into one atomic critical section (e.g., a single `Lock`-protected "check-then-insert" operation), N parallel requests bearing the identical signed JWT (same `jti`) can each observe `isReplay == false` before any of them completes `recordUsage`, letting all N pass authorization concurrently.

### Impact Explanation
A single valid signed JWT intended to authorize one workflow-trigger invocation can be used to trigger the same workflow execution multiple times in parallel, defeating the intended one-time-use / replay-protection invariant (`Please generate a new one with new id (jti)`). This matches Chainlink's "unauthorized job run" bounty impact class, since it allows request-binding bypass and duplicate/unauthorized workflow executions from a single signed authorization.

### Likelihood Explanation
The attacker only needs one valid signed JWT for a workflow trigger (no elevated privileges, matching the "unprivileged attacker holding one valid signed JWT" precondition) and the ability to fire concurrent HTTP/gateway requests, which is trivial and fully attacker-controlled. The race window is small but deterministically exploitable by firing many parallel requests, and does not depend on any timing outside attacker's control other than normal goroutine scheduling.

### Recommendation
Merge the replay-check and usage-record into one atomic operation under a single `Lock` (not `RLock`) — e.g., add a `checkAndRecord(jti string) bool` method on `jwtReplayCache` that takes the write lock once, checks for existence, and inserts if absent, returning whether it was already present. Call this single atomic method in `Authorize` instead of the separate `isReplay` + `recordUsage` calls, ideally performing the reservation before the authorized-key lookup (and rolling back/deleting the entry if the key lookup subsequently fails) to prevent races while avoiding permanently blocking legitimate retries after an unauthorized signer error.

### Proof of Concept
Go test plan:
1. Construct a `WorkflowMetadataHandler` with a `jwtReplayCache` and a valid `authorizedKeys` entry for a test `workflowID`/signer.
2. Generate one valid JWT (fixed `jti`) signed by an authorized key, wrapped in a `jsonrpc.Request`.
3. Spawn `N` (e.g., 50) goroutines each calling `h.Authorize(workflowID, token, req)` concurrently with the same token/`req`, run with `go test -race`.
4. Collect results; count how many calls return `err == nil` (i.e., authorization success).
5. Assertion: expect exactly 1 success; current implementation will show more than 1 success under concurrent load, demonstrating the TOCTOU race and confirming the vulnerability.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
