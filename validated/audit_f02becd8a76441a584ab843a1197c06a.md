### Title
Unbounded per-request scan cost in filtered `getProgramAccounts` (secondary index) due to full account-data materialization before content filters are applied - ([File: accounts-db/src/accounts.rs], [File: accounts-db/src/utils.rs])

### Finding Description
`Bank::get_filtered_program_accounts` / `Bank::get_filtered_indexed_accounts` delegate to `Accounts::load_by_program_with_filter` and `Accounts::load_by_index_key_with_filter` respectively [1](#0-0) . Both routes rely on `Accounts::load_while_filtering`, which is only invoked *after* the scan callback has already produced a fully materialized `AccountSharedData` for the candidate (`some_account_tuple: Option<(&Pubkey, AccountSharedData, Slot)>`), and only then applies the owner check and the caller-supplied `filter` closure (`filter_allows`, which evaluates `Memcmp`/`DataSize`) [2](#0-1) .

The materialization itself is an unconditional full data copy: storage-backed reads go through `get_account_shared_data`, which allocates and copies the entire account payload (`create_account_shared_data`/`AccountSharedData::create_from_existing_shared_data`) regardless of whether the account will ultimately match the filter [3](#0-2) [4](#0-3) .

For the secondary-index path (`load_by_index_key_with_filter`), the only cost guard present, `accumulate_and_check_scan_result_size` / `byte_limit_for_scan`, is applied *after* `filter(account)` has already run and only accumulates bytes for accounts that passed the filter (`if use_account && accumulate_and_check_scan_result_size(...)`) [5](#0-4) . There is no limit on the number of bytes/accounts *scanned and materialized* while walking all entries under the given `IndexKey` (ProgramId / SplTokenOwner / SplTokenMint) before the filter rejects them.

At the RPC layer, `getProgramAccounts` with a highly-selective `memcmp`/`dataSize` filter and a secondary index enabled routes to exactly this code: `RpcSolPimplData::get_filtered_program_accounts` calls `self.get_filtered_indexed_accounts(...)` when `AccountIndex::ProgramId` (or the owner/mint index for SPL Token accounts) is enabled [6](#0-5) . This narrows the *set of accounts scanned* to those sharing the indexed key (owner/mint), but does not narrow by the memcmp/dataSize predicate itself — every account under that key must be fully copied out of storage before the filter can reject it, since filtering requires inspecting the account's raw bytes.

### Impact Explanation
An attacker who controls an indexed owner/mint (e.g., creates their own SPL-Token mint or program) can seed many large accounts (up to `MAX_PERMITTED_DATA_LENGTH`) under that key, plus one small matching target, then issue a single `getProgramAccounts` call with a highly selective filter. The validator will fully copy every non-matching large account's data via `create_account_shared_data` before the filter discards it, so the wall-clock/memory cost of one RPC call scales with total bytes stored under the attacker-controlled index key rather than with the size of the (tiny) matched result set. This is a single-call, unbounded-cost issue consistent with the "unbounded cost for a single low-rate call" impact category.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs normal transaction-fee-paying account creation (allowed precondition — "writing on-chain data that is later returned through those APIs") to seed large accounts under an owner/mint they control, then a single `getProgramAccounts` RPC call. No validator/operator control or multiple calls are required; the cost is deterministic and reproducible each time the request is repeated.

### Recommendation
Apply a scan-time byte/account budget (not just a post-filter result-size budget) in `load_by_index_key_with_filter`/`load_by_program_with_filter`, aborting the scan once a configurable amount of raw data has been materialized regardless of filter outcome. Where possible, support filter evaluation against a bounded byte window (e.g., only the `memcmp` offset+length) without fully copying the entire account payload for large accounts, similar in spirit to the partial-read logic already used in `AppendVec::get_account_shared_data`.

### Proof of Concept
Integration test outline (accounts-db/runtime):
```rust
#[test]
fn test_filtered_scan_cost_scales_with_candidate_bytes_not_matches() {
    // 1. Enable AccountIndex::ProgramId (or SplTokenOwner) for the test bank.
    // 2. Store N large accounts (e.g. 10MB each) owned by `program_id`
    //    (or with SPL token owner/mint = attacker-controlled key), none matching a memcmp filter.
    // 3. Store 1 small matching account under the same owner/mint.
    // 4. Time bank.get_filtered_indexed_accounts(&IndexKey::ProgramId(program_id), filter, None)
    //    where `filter` only accepts the 1 small account.
    // 5. Assert wall time / bytes copied (instrument create_account_shared_data call count or
    //    use a custom allocator/counter) grows linearly with N * 10MB, not with the 1 matched result,
    //    demonstrating cost is proportional to scanned candidates, not matches.
}
```
Expected assertion: total bytes copied via `create_account_shared_data` during the scan is approximately `N * 10MB + small_account_size`, violating the invariant that per-request cost should be proportional to matched results only.

    /// return an `AccountSharedData` for an account at `offset`.
    /// This fn can efficiently return exactly what is needed by a caller.
    /// This is on the critical path of tx processing for accounts not in the read or write caches.
    pub fn get_account_shared_data(&self, offset: usize) -> Option<AccountSharedData> {
        let mut buf = MaybeUninit::<[u8; PAGE_SIZE]>::uninit();
        let bytes_read = read_into_buffer(
            &self.file,
            self.len() as FileSize,
            offset as FileSize,
            unsafe { &mut *buf.as_mut_ptr() },
        )
        .ok()?;
        // SAFETY: we only read the initialized portion.
        let valid_bytes =
            ValidSlice(unsafe { slice::from_raw_parts(buf.as_ptr() as *const u8, bytes_read) });
        let (meta, next) = Self::get_type::<StoredMeta>(valid_bytes, 0)?;
        let (account_meta, next) = Self::get_type::<AccountMeta>(valid_bytes, next)?;
        let (_hash, next) = Self::get_type::<ObsoleteAccountHash>(valid_bytes, next)?;
        let data_len = meta.data_len;
        let remaining_bytes_for_data = bytes_read - next;
        Some(if remaining_bytes_for_data >= data_len as usize {
            // we already read enough data to load this account
            let (data, next) = Self::get_slice(valid_bytes, next, meta.data_len as usize)?;
            let stored_size = next;
            let account = StoredAccountMeta {
                meta,
                account_meta,
                data,
                offset,
                stored_size,
            };
            // data is within `buf`, so just allocate a new vec for data
            create_account_shared_data(&account)
        } else {
            // not enough was read from file to get `data`
            assert!(data_len <= MAX_PERMITTED_DATA_LENGTH, "{data_len}");
            let mut data = Vec::with_capacity(data_len as usize);
            let slice = data.spare_capacity_mut();
            // Note here `next` is a 0-based offset from the beginning of this account.
            // SAFETY: `read_into_buffer` will only write to uninitialized memory.
            let bytes_read = read_into_buffer(
                &self.file,
                self.len() as FileSize,
                (offset + next) as FileSize,
                unsafe {
                    slice::from_raw_parts_mut(slice.as_mut_ptr() as *mut u8, data_len as usize)
                },
            )
            .ok()?;
            if bytes_read < data_len as usize {
                // eof or otherwise couldn't read all the data
                return None;
            }
            // SAFETY: we've just checked that `bytes_read` is at least `data_len`.
            unsafe { data.set_len(data_len as usize) };
            AccountSharedData::create_from_existing_shared_data(
                account_meta.lamports,
                Arc::new(data),
                account_meta.owner,
                account_meta.executable,
                account_meta.rent_epoch,
            )
        })
