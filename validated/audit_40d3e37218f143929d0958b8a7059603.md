### Title
Unbounded recursion in `TrieNode` MPT decoding/traversal allows fault-proof program crash via attacker-supplied preimages - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode`, `TrieNode::open`, `TrieNode::insert`, `TrieNode::delete`, and `OrderedListWalker::fetch_leaves` are all naturally recursive functions that follow `Extension`/`Branch`/`Blinded` node chains with **no maximum recursion/nesting depth check**, in contrast to the `CborItem::read_at` parser (`crates/proof/tee/registrar/src/cbor.rs:95-100`) which explicitly bounds nesting via `MAX_CBOR_NESTING_DEPTH`. CVE-2019-9070 demonstrates the same root-cause class: a recursive parser without a depth limit that corrupts/over-reads memory once recursion grows unbounded under attacker control.

### Finding Description
`TrieNode::decode` recurses into itself for `Extension` node payloads [1](#0-0) , and `TrieNode::open`/`insert`/`delete`/`unblind` recurse across separately-fetched preimages whenever a `Blinded` node is encountered [2](#0-1) [3](#0-2) [4](#0-3) . `OrderedListWalker::fetch_leaves` similarly recurses through `Branch`/`Extension`/`Blinded` chains while walking L1 receipts/transactions tries [5](#0-4) .

These trie nodes and their preimages are sourced from an untrusted oracle/host during fault-proof execution: `OracleL1ChainProvider::trie_node_by_hash` and `OracleL2ChainProvider::trie_node_by_hash` decode raw bytes fetched from the preimage oracle directly into `TrieNode` with no size/depth validation beyond RLP structural checks [6](#0-5) [7](#0-6) . In the dispute-game/fault-proof model, the preimage data is supplied by the party being challenged (the host), so a dispute-game participant fully controls the shape of the trie and can chain an arbitrarily long sequence of `Blinded`→preimage→`Extension`/`Blinded` nodes (or long `Extension`/`Leaf`/`Extension` decode chains within a single payload) to drive unbounded recursion depth in the trie-walking code, since nothing in `crates/proof/mpt` enforces a `MAX_DEPTH`-style bound (confirmed absent via repository-wide search of the crate).

### Impact Explanation
Unbounded recursion in a native (non-FPVM) execution of the fault-proof program leads to native stack exhaustion, crashing the process performing state verification during dispute resolution. Because this code underlies `base-proof-mpt`, used by `base-proof-executor`/`base-proof-proof` to resolve L1/L2 chain data and produce state during the interactive fault-proof program, a crash here constitutes a proof-program halt, potentially preventing correct resolution of a dispute game (an honest party being unable to compute a provable output root, or the challenged program halting instead of completing verification) — matching the accepted "node halt" / "wrong provable output root" impact classes for the fault-proof program and MPT reachable surface.

### Likelihood Explanation
Likelihood is Medium-High: any dispute-game participant supplying preimages already controls raw trie-node bytes served through the preimage oracle, and crafting nested `Extension`/`Blinded` chains requires no cryptographic breaks — only providing crafted RLP bytes and matching keccak preimages, both of which the untrusted host is expected to be able to construct for the hashes it advertises.

### Recommendation
Add an explicit recursion/nesting depth bound (mirroring `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`) to `TrieNode::decode`, `open`, `insert`, `delete`, `unblind`, and `OrderedListWalker::fetch_leaves`, returning a decode/traversal error once a sane maximum trie depth (e.g., 64 nibbles, matching real account/storage trie key lengths) is exceeded, rather than allowing indefinite native recursion driven by untrusted preimage data.

### Proof of Concept
1. As the challenged party in a fault-proof dispute, respond to preimage hints (`HintType::L1BlockHeader`/`L1Receipts`/`L1Transactions`) with a header whose `receipts_root` or `transactions_root` points to a crafted node.
2. Serve a chain of RLP-encoded `TrieNode::Extension` nodes (or repeated `Blinded` commitments resolving to further `Extension`/`Branch` nodes) many thousands of levels deep via `debug_dbGet`/preimage oracle responses.
3. When the fault-proof program calls `OracleL1ChainProvider::receipts_by_hash`/`block_info_and_transactions_by_hash`, `OrderedListWalker::hydrate`→`fetch_leaves` (or `TrieNode::decode`/`open`) recurses once per level with no depth cap, exhausting the native call stack and crashing the proof program before it can produce a verifiable state root.

    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
