### Title
Missing zip-slip path validation lets archive entries (used via `processZipTimestampField`/`os.Chtimes` and file writes) escape the extraction root - ([File: helpers/archives/zip_extra.go], [File: helpers/archives/zip_extract.go])

### Summary
`processZipTimestampField` (helpers/archives/zip_extra.go:50-68) calls `os.Chtimes(file.Name, ...)` using the raw, attacker-supplied `zip.FileHeader.Name` with no path sanitization. The same unsanitized `file.Name` is also used directly for `os.MkdirAll`, `os.OpenFile`, `os.Remove`, and `os.Symlink` in `extractZipFile`/`extractZipFileEntry`/`extractZipSymlinkEntry` (helpers/archives/zip_extract.go:12-83), so the timestamp write is one symptom of a broader missing zip-slip guard in the whole extractor.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` and, for every entry, first extracts content via `extractZipFile(file)` and then, in a second pass, calls `lchmod(file.Name, ...)` and `processZipExtra(&file.FileHeader)`. The only path check present anywhere in this pipeline is `errorIfGitDirectory` (helpers/archives/path_check_helper.go:13-31), which only rejects paths whose first cleaned component is `.git` — it does nothing to prevent `..` traversal or absolute paths. There is no `filepath.Clean`, no check that the resolved path stays under a fixed extraction root, and no rejection of entries starting with `../` or `/`.

`processZipExtra` (helpers/archives/zip_extra.go:96-122) dispatches on the `ZipTimestampFieldType` extra field to `processZipTimestampField`, which reads a `Flags`/`ModTime` pair from attacker-controlled `Extra` bytes and, if bit 0 of `Flags` is set, calls `os.Chtimes(file.Name, acTime, modTime)` (zip_extra.go:61-65) — again using the same unsanitized `file.Name`. On Windows, `processZipUIDGidField` is stubbed to a no-op (zip_extra_windows.go:14-17), so UID/GID extras are dropped, but this has no bearing on the timestamp path, which runs unconditionally on all platforms.

Because `file.Name` is never validated to stay within the intended destination directory, a crafted zip entry with `Name = "../victim/file"` (or a deeper `../../..` sequence) will, during the first extraction pass, have its parent directories created via `os.MkdirAll(filepath.Dir(file.Name), ...)` and its content written via `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` — i.e., the entry's *content* already escapes the extraction root before `processZipTimestampField` even runs. The subsequent `os.Chtimes` call on that same escaped path is consistent with, and rides on, this pre-existing zip-slip: it does not introduce a new write primitive but does allow mtime corruption of any file the extraction path traversal can reach, in addition to the content overwrite already performed.

### Impact Explanation
Within a single execution context, a crafted archive (cache/artifact zip) can write arbitrary file content and set arbitrary mtimes outside the intended extraction directory, for any path reachable by relative traversal from the extraction root and writable by the process's OS user. Whether this reaches a *different project's* persisted cache/artifact files depends entirely on the runner's on-disk layout and isolation model for that execution context (e.g., whether cache/build directories for different projects share a common writable parent under the same OS user/container). Where that precondition holds, this is genuine cross-tenant persistent-state corruption (both content and mtimes); where jobs run in fully isolated per-job container filesystems with no shared host-mounted cache/build volumes, the traversal is confined to the job's own sandbox and does not cross project boundaries.

### Likelihood Explanation
Reaching this code only requires an attacker to control the contents of an archive that Runner extracts via `ExtractZipArchive`/`ExtractZipFile` (e.g., a cache or artifact zip they can influence, or a legacy zip cache), which is a normal, unprivileged CI capability. No masking, overwrite guard, or path-containment check currently exists in this code path (only the unrelated `.git` check), so the traversal is trivially reproducible in any environment where the extraction root is shared with other tenants' persistent storage on the same filesystem/OS-user boundary.

### Recommendation
Add path-containment validation for every zip entry before any filesystem operation (`Mkdir`, `OpenFile`, `Symlink`, `Chtimes`, `lchmod`): compute `filepath.Join(destRoot, file.Name)`, reject entries whose cleaned resulting path is not equal to or under `destRoot` (guard against `..`, absolute paths, and symlink component tricks), and apply this check once in `ExtractZipArchive`/`extractZipFile` so it also protects `processZipExtra`/`processZipTimestampField`, `lchmod`, and the tar/zstd extraction paths equivalently.

### Proof of Concept
```go
func TestExtractZipArchive_RejectsPathTraversalOnChtimes(t *testing.T) {
    tmpDir := t.TempDir()
    extractRoot := filepath.Join(tmpDir, "job-workspace")
    require.NoError(t, os.MkdirAll(extractRoot, 0o777))
    victimDir := filepath.Join(tmpDir, "victim")
    require.NoError(t, os.MkdirAll(victimDir, 0o777))
    victimFile := filepath.Join(victimDir, "cached-artifact")
    require.NoError(t, os.WriteFile(victimFile, []byte("original"), 0o644))
    origInfo, _ := os.Stat(victimFile)
    origModTime := origInfo.ModTime()

    // Build a zip with Name="../victim/cached-artifact" and a ZipTimestampField extra
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    fh := &zip.FileHeader{Name: "../victim/cached-artifact"}
    fh.SetMode(0o644)
    // append ZipTimestampFieldType extra with Flags=1 and an attacker chosen ModTime
    var extra bytes.Buffer
    tsField := ZipTimestampField{Flags: 1, ModTime: uint32(time.Now().Add(48 * time.Hour).Unix())}
    tsHeader := ZipExtraField{Type: ZipTimestampFieldType, Size: uint16(binary.Size(&tsField))}
    binary.Write(&extra, binary.LittleEndian, &tsHeader)
    binary.Write(&extra, binary.LittleEndian, &tsField)
    fh.Extra = extra.Bytes()
    w, _ := zw.CreateHeader(fh)
    w.Write([]byte("malicious"))
    zw.Close()

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    require.NoError(t, os.Chdir(extractRoot))
    err := ExtractZipArchive(r)
    require.NoError(t, err)

    // Assert victim file outside extraction root was NOT modified (content and mtime)
    victimInfo, _ := os.Stat(victimFile)
    assert.Equal(t, origModTime, victimInfo.ModTime(), "mtime of file outside extraction root must not change")
    content, _ := os.ReadFile(victimFile)
    assert.Equal(t, "original", string(content), "content outside extraction root must not change")
}
```
Expected result today (without a fix): both assertions fail — the victim file's content is overwritten and its mtime is set to the attacker-chosen `ModTime`, demonstrating the traversal reaches outside `extractRoot` via `extractZipFileEntry` and `processZipTimestampField`'s unchecked use of `file.Name`. func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
