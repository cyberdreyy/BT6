### Title
APR0 withdraw receipt permanently bricks `stopEpoch` once APR is set non-zero - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.prepareStopEpochWithApr0` reverts with `NotAllowed` whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0`. `apr0TotalPrincipal` is only reset inside that same function *after* the revert, so the revert is self-perpetuating: once a single APR0 withdraw request exists and the APR becomes non-zero, `stopEpoch` can never succeed again and the epoch is frozen forever.

### Finding Description
When a user calls `requestWithdraw` while `unscaledApr == 0`, the request is routed to `_requestWithdrawApr0`, which increments `apr0TotalPrincipal` (`IdleCreditVault.sol:567-577`). The only places that ever decrease or zero `apr0TotalPrincipal` are:

- `prepareStopEpochWithApr0`, which first reverts if `unscaledApr != 0` (`IdleCreditVault.sol:506-508`) and only zeroes the bucket at the end (`IdleCreditVault.sol:540`).
- `_clearWithdrawClaimForEpoch` with `_isClearingApr0`, reachable only on the defaulted-claim path after `finalizeDefaultRecovery` (`IdleCreditVault.sol:821-831`).

`unscaledApr` can be set non-zero by the manager at any time via `setAprs`/`setAprsWithBuffer` (`IdleCreditVault.sol:206-220`) with no check on `apr0TotalPrincipal`. Every `stopEpoch`/`stopEpochWithDuration` call goes through `_strategy.prepareStopEpochWithApr0` (`IdleCDOEpochVariant.sol:362`), so once the state `(apr0TotalPrincipal > 0, unscaledApr > 0)` is reached, all future `stopEpoch` calls revert — regardless of `_interest` (including the `_interest == 1` "request all funds back" escape hatch and loss-adjusted `stopEpochWithDuration`). There is no admin function to clear `apr0TotalPrincipal`, and `claimWithdrawRequest` cannot run because claims require `epochNumber` to advance past `lastWithdrawRequest`, which only `stopEpoch`/`deposit` can do.

### Impact Explanation
An unprivileged lender deposits any amount (dust suffices), requests a withdraw during an APR0 phase, and waits. When the honest manager later raises the APR (normal operations) — via `setAprs` or a successful interim `stopEpoch` setting `_newApr != 0` — the vault enters a terminal state: every `stopEpoch` reverts, `epochEndDate` can never be cleared, borrower funds can never be recalled, pending withdraw receipts can never be funded, and all LP principal plus accrued interest (the entire pool TVL) is permanently locked in the vault/borrower. This is permanent freezing of all user funds, not a gas/DoS-only issue.

### Likelihood Explanation
The trigger requires only an ordinary sequence: an APR0 epoch (a supported, tested configuration — see `testApr0WithdrawGetsInterestAtStopEpoch`), one dust-sized `requestWithdraw` by any tranche holder, and one subsequent honest APR change by the manager. No malicious privileged action, no oracle manipulation, no exotic timing. The revert is deterministic and unrecoverable.

### Recommendation
Do not hard-revert on the `apr0TotalPrincipal != 0 && unscaledApr != 0` combination. Options:

- In `prepareStopEpochWithApr0`, treat a non-zero `unscaledApr` as "APR0 bucket earns zero interest": skip the interest split, still close the bucket (`apr0TotalPrincipal = 0`), and let receipts settle as principal-only.
- Alternatively, block APR changes while `apr0TotalPrincipal != 0` inside `setAprs`/`setAprsWithBuffer`, and have `stopEpoch` settle/clear the bucket before applying `_newApr`.
- Also consider allowing `stopEpoch` to close the APR0 bucket even when the epoch ends with a loss or `_interest == 1`, so no combination of honest parameters can strand it.

### Proof of Concept
```solidity
// Foundry fork PoC (test/foundry style, reusing IdleCreditVault.t.sol helpers)
function testApr0PoisonFreezesStopEpoch() external {
    // configure APR0 pool
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    idleCDO.depositAA(10_000 * ONE_SCALE);
    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    _forceLastEpochAprToZero();

    // attacker: dust APR0 withdraw request in the buffer window
    address attacker = makeAddr("attacker");
    _depositWithUser(attacker, 1, true);
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(1, address(AAtranche));
    assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

    // honest manager sets a non-zero APR before the next epoch stop
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(initialProvidedApr, initialProvidedApr);

    _startEpochAndCheckPrices(1);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, type(uint256).max); // borrower fully funds

    // every stopEpoch variant reverts: prepareStopEpochWithApr0 hits NotAllowed
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0);

    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 1); // even the "recall everything" path reverts

    // apr0TotalPrincipal is never cleared -> permanent freeze of the whole pool
}
```
