This confirms the vulnerability. Each `Write(p)` call flowing through the `timestamper.Logger` (and `masker`) is split into **multiple separate calls** to the underlying writer (`l.w.Write(header)`, then `l.w.Write(content)`, potentially several times for multi-line input), and `internal.NewSync` only wraps the *outer* chain created per-`Stream()` call — it does not synchronize across the multiple independent chains that different goroutines create when calling `BuildLogger.Stream()` concurrently. All chains ultimately converge on the single shared `l.base`, which delegates to `common.Trace.Write()` [1](#0-0)  — and that mutex only guarantees atomicity of *one physical Write() call*, not of the multi-call sequence (header+body, or prefix+content+suffix) that constitutes one logical log line.

### Title
Concurrent per-service log/health-check streams can interleave at sub-line granularity, corrupting workload attribution in job trace - (File: executors/docker/services.go, common/buildlogger/build_logger.go, helpers/service/logger.go)

### Summary
`waitForServices` launches one goroutine per service via `waitForServiceContainer` [2](#0-1)  and, independently, `captureContainersLogs`/`captureContainerLogs` launches one streaming goroutine per service using `stdcopy.StdCopy` into an `InlineServiceLogWriter` [3](#0-2) . Each of these goroutines obtains its own writer chain via `BuildLogger.Stream()`, but all chains funnel down to the same shared trace sink, and the synchronization primitive (`internal.NewSync`) only protects a single chain instance, not the multi-call sequence a logical write is broken into by `masker`/`timestamper`/`InlineServiceLogWriter`.

### Finding Description
- `Logger.Stream()` builds a fresh wrap chain per call: `timestamper -> tokensanitizer -> urlsanitizer -> masker -> internal.NewSync -> l.base` [4](#0-3) . The `internal.NewSync` mutex is local to that one chain instance; it prevents two writers to the *same* `io.WriteCloser` chain object from interleaving, but two *different* `Stream()` calls create two different chain objects that both write to the same `l.base` without a shared lock between them.
- `l.base` wraps the job's `common.Trace`, whose `Write()` does hold a mutex [1](#0-0) , but this mutex is only acquired per individual `Write()` syscall-equivalent call. It does not make a *sequence* of writes atomic.
- `timestamper.Logger.Write()` issues multiple separate `l.w.Write()` calls for a single input buffer: a header write via `writeHeader()`, then one or more content writes per line via `writeLines()`/`buffer()` [5](#0-4) . Similarly `InlineServiceLogWriter.Write()` issues three separate `sink.Write()` calls per line: prefix, content, suffix [6](#0-5) .
- Because `waitForServices` fans out one goroutine per service (`go func(service *serviceInfo) { e.waitForServiceContainer(...) }`) [7](#0-6) , and `captureContainersLogs` fans out one streaming goroutine per service concurrently [8](#0-7) , multiple services' output can reach `l.base` at effectively the same time through independently-locked chains.
- The result: between two physical `Write()` calls belonging to one logical message (e.g., between a service's `[service:foo]` prefix write and its content write, or between a timestamp header write and its line-body write), another goroutine's write for a *different* service can be interleaved into the shared trace stream. Each individual call is thread-safe at the `common.Trace` mutex level, but the ordering/atomicity of the full logical unit is not guaranteed across chains.
- Existing protections reviewed: `internal.NewSync` (per-chain only, insufficient across chains), `common.Trace.mutex` (per-call only, insufficient for multi-call units), `InlineServiceLogWriter` prefixing (does not re-verify boundary integrity, assumes atomic underlying writes). None of these actually serialize the full logical write across concurrently-running per-service goroutines.

### Impact Explanation
An attacker-controlled service or job process (multiple services, or a service plus job output line racing a health-check failure buffer flush) can cause interleaved log fragments in the job trace. Concretely this can: (a) attach one service's output content under another service's `[service:name]` prefix, misattributing which container produced sensitive output, undermining log-based auditing/ownership guarantees, and (b) split apart secret-masking boundaries — since `masker`/`tokensanitizer` operate per-chain and match phrases across writer-internal state, an interleaved byte sequence at the shared sink can defeat expectations about which stream a given byte belongs to, though the masking match state itself is per-chain (not globally corrupted) so token masking itself is not bypassed by this issue — the primary concrete impact is output/log integrity and workload-attribution corruption (mislabeled or garbled service logs), which is a real but moderate impact (matches "output tampering" from the scoped Immunefi impact, rather than direct secret exfiltration).

### Likelihood Explanation
Highly reproducible: any job with two or more services (`CI_DEBUG_SERVICES: "true"` enables `captureContainersLogs`), or with `WaitForServicesTimeout` set low enough to trigger multiple simultaneous health-check-failure buffer flushes in `waitForServiceContainer`, will exercise this code path routinely. No special privilege beyond normal `.gitlab-ci.yml` authoring (declaring `services:`) is needed. The race window is small but given production log volumes and frequent CI runs, byte interleaving under load is a realistic, timing-dependent occurrence — reproducible with a targeted Go test using concurrent writers.

### Recommendation
Introduce a single shared mutex (or single writer goroutine with a channel) around the entire logical write path from `l.base` outward — i.e., make `internal.NewSync` wrap `l.base` itself once, globally, rather than being recreated per `Stream()` call, so that all concurrently created chains contend for the *same* lock before writing to the shared sink. Alternatively, require callers (`waitForServiceContainer`, `captureContainerLogs`) to pre-render each logical unit (prefix+content+suffix, or header+line) into a single `[]byte` buffer and issue exactly one `Write()` call per logical unit to the shared writer, so `common.Trace`'s existing per-call mutex is sufficient to guarantee atomicity.

func TestConcurrentStreamsDoNotInterleave(t *testing.T) {
    trace := &common.Trace{Writer: &syncBuf /* capturing buffer */}
    logger := buildlogger.New(trace, logrus.NewEntry(logrus.New()), buildlogger.Options{Timestamping: true})

    var wg sync.WaitGroup
    for i := 0; i < 2; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            w := logger.Stream(buildlogger.StreamStartingServiceLevel, buildlogger.Stdout)
            defer w.Close()
            marker := fmt.Sprintf("SERVICE-%d-MARKER\n", id)
            for j := 0; j < 1000; j++ {
                w.Write([]byte(marker))
            }
        }(i)
    }
    wg.Wait()

    // assert every emitted line matches exactly one marker pattern in full,
    // with no interleaved bytes from the other marker.
    for _, line := range strings.Split(syncBuf.String(), "\n") {
        assert.True(t, isPureMarker(line, "SERVICE-0-MARKER") || isPureMarker(line, "SERVICE-1-MARKER") || line == "")
    }

// captureContainerLogs tails (i.e. reads) logs emitted to stdout or stdin from
// processes in the specified container, and redirects them to the specified
// sink, which can be any io.Writer (e.g. this process's stdout, a file, a log
// aggregator). The logs are streamed as they are emitted, rather than batched
// and written when we disconnect from the container (or it is stopped). The
// specified sink is closed when the source is completely drained.
func (e *executor) captureContainerLogs(ctx context.Context, cid, containerName string, sink io.WriteCloser) error {
	source, err := e.dockerConn.ContainerLogs(ctx, cid, client.ContainerLogsOptions{
		ShowStderr: true,
		ShowStdout: true,
		Timestamps: true,
		Follow:     true,
	})
	if err != nil {
		return fmt.Errorf("failed to open log stream for container %s: %w", containerName, err)
	}

	e.BuildLogger.Debugln("streaming logs for container " + containerName)
	go func() {
		defer source.Close()
		defer sink.Close()

		// Using stdcopy assumes service containers are run with TTY=false. If
		// containers are started with TTY=true, io.Copy should be used instead.
		if _, err := stdcopy.StdCopy(sink, sink, source); err != nil {
			if err != io.EOF && !errors.Is(err, context.Canceled) {
				e.BuildLogger.Warningln(fmt.Sprintf(
					"error streaming logs for container %s: %s",
					containerName,
					err.Error(),
				))
			}
		}
		e.BuildLogger.Debugln("stopped streaming logs for container " + containerName)
	}()
	return nil
}

func (l *Logger) writeLines(p []byte) (n int, err error) {
	idx := bytes.IndexByte(p, '\n')
	if idx == -1 {
		return n, err
	}

	if l.buf.Len() > 0 {
		_, err := l.w.Write(l.buf.Bytes())
		if err != nil {
			return 0, err
		}

		l.buf.Reset()

		nn, err := l.w.Write(p[:idx+1])
		n += nn
		if err != nil {
			return n, err
		}
	}

	for {
		idx := bytes.IndexByte(p[n:], '\n')
		if idx == -1 {
			return n, err
		}

		if err := l.writeHeader(l.w); err != nil {
			return n, err
		}

		nn, err := l.w.Write(p[n : n+idx+1])
		n += nn
		if err != nil {
			return n, err
		}
	}
}

func (sw *InlineServiceLogWriter) Write(p []byte) (int, error) {
	n := 0

	for n < len(p) {
		end := bytes.IndexByte(p[n:], '\n')
		if end < 0 {
			end = len(p[n:])
		}

		if _, err := sw.sink.Write(sw.prefix); err != nil {
			return n, err
		}

		nn, err := sw.sink.Write(p[n : n+end])
		n += nn
		if len(p[n:]) > 0 && err == nil {
			n++
		}
		if err != nil {
			return n, err
		}

		if _, err := sw.sink.Write(sw.suffix); err != nil {
			return n, err
		}
	}

	return n, nil
}
