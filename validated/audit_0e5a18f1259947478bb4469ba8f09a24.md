### Title
RPC `jsonParsed` token-account decoding trusts an unauthenticated "mint" account reference for decimals/scaling data - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
The reported bug class is that `VaultFactory` authenticates the top-level `Vault` contract but never authenticates the sub-components (`TwabController`, `PrizePool`) it composes with, letting an attacker plug in malicious sub-components while the top-level object still looks "official." The equivalent pattern exists in agave's RPC token-account JSON-parsing path: the code authenticates the *token account itself* (by requiring its owner to be a known SPL Token/Token-2022 program id), but then blindly trusts the *mint* pubkey embedded inside that account's raw data to fetch decimals/interest-bearing/scaled-UI-amount configuration, without ever verifying that the referenced mint account is itself owned by that same (or any legitimate) token program.

### Finding Description
`get_token_account_mint` in `account-decoder/src/parse_token.rs` extracts a "mint" `Pubkey` directly from the first 32 bytes of arbitrary account data, gated only by `Account::valid_account_data` (a length/discriminant check, not an ownership check): [1](#0-0) 

That mint pubkey is then used in `rpc/src/parsed_token_accounts.rs` to look up whatever account currently sits at that address in the bank and unpack it as an SPL `Mint`, extracting `decimals`, `interest_bearing_config`, and `scaled_ui_amount_config` used to compute the reported UI amount — with no check that this mint account is owned by the same token program (or any token program) as the account being parsed: [2](#0-1) [3](#0-2) [4](#0-3) 

This is the same trust-boundary gap as the `VaultFactory` bug: the "container" (`Vault`/token account) is validated as authentic, but the "component" it references (`PrizePool`/`TwabController` vs. the `mint` account) is not validated to be an authentic instance of the same trusted family before its data is used to compute values shown to users.

This path is reachable by any unprivileged user issuing a single `programSubscribe`/`getProgramAccounts`/`getTokenAccountsByOwner` request with `jsonParsed` encoding against a known SPL Token program id, since `filter_program_results` (used by pubsub program subscriptions) invokes `get_parsed_token_accounts` whenever `is_known_spl_token_id(&params.pubkey)` is true: [5](#0-4) 

### Impact Explanation
An attacker can create/own an arbitrary account at address `M` (owned by any program they control) whose raw bytes happen to unpack as a valid `spl_token_2022_interface::state::Mint` (a small, easily satisfiable byte layout), with attacker-chosen `decimals`, or attacker-chosen `InterestBearingConfig`/`ScaledUiAmountConfig` extension data. If any SPL token account exists (or is created) whose embedded mint field points at `M`, every RPC client that fetches or subscribes to that token account with `jsonParsed` encoding will have its `tokenAmount.uiAmount`/`uiAmountString`/`decimals` computed from the attacker-controlled mint data rather than from a genuinely authenticated mint. This is a wrong-account-data-returned / decoder-misreporting condition served to unprivileged RPC/pubsub consumers, matching the "wrong ... account data returned" and "decoder panic and misreporting" acceptance criteria — it can cause wallets/front-ends to display fabricated balances or scaling factors for accounts that otherwise look legitimately owned by the real SPL Token program.

### Likelihood Explanation
The precondition (crafting arbitrary account data that unpacks as a `Mint` struct) is trivial and fully within an unprivileged user's control, and no more than a single JSON-RPC/pubsub call (`getAccountInfo`, `getTokenAccountsByOwner`, `getProgramAccounts`, or `programSubscribe` with `encoding: jsonParsed`) is needed to trigger the misreporting once such an account/mint pair exists on-chain. The remaining uncertainty is whether the on-chain SPL Token/Token-2022 program (an out-of-scope dependency) independently prevents `InitializeAccount`-style instructions from referencing a mint that is not owned by the same token program; that on-chain enforcement question could not be verified against the token-program source within this review, but it does not change the fact that the agave-side decoding logic itself performs no such cross-check before trusting the mint data.

### Recommendation
In `get_mint_owner_and_additional_data`/`get_additional_mint_data` (`rpc/src/parsed_token_accounts.rs`), verify that the resolved mint account's owner matches a known SPL token program id (`is_known_spl_token_id`) — and ideally matches the same specific token-program id as the account being parsed — before using its unpacked `Mint` data (decimals, interest-bearing config, scaled-UI-amount config) to compute displayed token amounts. If the mint's owner is not a recognized token program, the parser should fall back to raw/unparsed encoding or surface an explicit "unparsable"/"unverified mint" result rather than silently trusting the data.

### Proof of Concept
1. As an unprivileged user, create account `M` (owned by an arbitrary program, e.g. the System Program via `CreateAccount` with custom `space`/`owner`) whose data bytes are laid out to satisfy `StateWithExtensions::<Mint>::unpack` (fixed-size `Mint` struct: `mint_authority`, `supply`, `decimals`, `is_initialized=true`, `freeze_authority`, plus optional Token-2022 extension TLVs such as `InterestBearingConfig`/`ScaledUiAmountConfig` with attacker-chosen rates/timestamps).
2. Create/point a real SPL Token or Token-2022 account `A` (owned by the genuine token program) whose embedded `mint` field (bytes 0..32) equals `M`'s address. (Whether the on-chain token program itself blocks this is the one unverified dependency-level assumption noted above.)
3. Call `getAccountInfo(A, {"encoding":"jsonParsed"})`, `getTokenAccountsByOwner`, or `programSubscribe(<token_program_id>, {"encoding":"jsonParsed"})`.
4. Observe that `get_mint_owner_and_additional_data`/`get_additional_mint_data` unpack `M` and feed its attacker-controlled `decimals`/`interest_bearing_config`/`scaled_ui_amount_config` into `token_amount_to_ui_amount_v3`, producing a `tokenAmount.uiAmount`/`uiAmountString` in the RPC response that does not correspond to any authentic, program-validated mint — with no ownership check ever performed on `M`, per: [4](#0-3)

pub fn get_parsed_token_accounts<I>(
    bank: Arc<Bank>,
    keyed_accounts: I,
) -> impl Iterator<Item = RpcKeyedAccount>
where
    I: Iterator<Item = (Pubkey, AccountSharedData)>,
{
    let mut mint_data: HashMap<Pubkey, AccountAdditionalDataV3> = HashMap::new();
    keyed_accounts.filter_map(move |(pubkey, account)| {
        let additional_data = get_token_account_mint(account.data()).and_then(|mint_pubkey| {
            mint_data.get(&mint_pubkey).cloned().or_else(|| {
                let (_, data) = get_mint_owner_and_additional_data(&bank, &mint_pubkey).ok()?;
                let data = AccountAdditionalDataV3 {
                    spl_token_additional_data: Some(data),
                };
                mint_data.insert(mint_pubkey, data);
                Some(data)
            })
        });

        let maybe_encoded_account = encode_ui_account(
            &pubkey,
            &account,
            UiAccountEncoding::JsonParsed,
            additional_data,
            None,
        );
        if let UiAccountData::Json(_) = &maybe_encoded_account.data {
            Some(RpcKeyedAccount {
                pubkey: pubkey.to_string(),
                account: maybe_encoded_account,
            })
        } else {
            None
        }
    })
}

/// Analyze a mint Pubkey that may be the native_mint and get the mint-account owner (token
/// program_id) and decimals
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}

    let accounts_is_empty = accounts.is_empty();
    let encoding = params.encoding;
