## Finding: Closing a lending balance silently discards accrued emissions rewards

### Title
Unclaimed emissions rewards are lost when closing a balance via `lending_account_close_balance` - (File: `programs/marginfi/src/state/marginfi_account.rs`)

### Summary
`BankAccountWrapper::close_balance` resets the entire `Balance` struct to `Balance::empty_deactivated()` without settling or paying out any accrued `emissions_outstanding` first, and without checking that `emissions_outstanding` is zero before allowing the close. The program even defines a dedicated error for this exact scenario, `MarginfiError::CannotCloseOutstandingEmissions`, but that error is never referenced by any instruction handler, meaning the guard was never wired in.

### Finding Description
Each `Balance` slot tracks `emissions_outstanding`, described as "Unclaimed emissions rewards for this position." [1](#0-0) 

When a user closes a balance via `lending_account_close_balance`, the instruction locates the balance, calls `bank_account.close_balance(in_receivership)`, and then re-sorts/updates the account — no reference to `emissions_outstanding` anywhere in this path. [2](#0-1) 

Inside `close_balance`, the only checks performed are that liability and asset amounts are zero; there is no check on `emissions_outstanding`. The balance is then wiped via `balance.close()`. [3](#0-2) 

`Balance::close()` simply overwrites the whole struct with `Self::empty_deactivated()`, which hard-codes `emissions_outstanding: WrappedI80F48::from(I80F48::ZERO)` — discarding whatever value was previously accrued. [4](#0-3) [5](#0-4) 

The codebase already anticipated this exact failure mode: `MarginfiError::CannotCloseOutstandingEmissions` ("Cannot close balance because of outstanding emissions") exists in the error enum, but a repository-wide search shows it is only referenced in `errors.rs` itself (definition + `From<u32>` mapping) and in a test-utility string constant — it is never `check!`-ed or returned by any instruction, including `lending_account_close_balance`. [6](#0-5) [7](#0-6) 

This mirrors the report's bug class: a routine, permissionless account-state-clearing operation overwrites/erases a field that should represent a durable, redeemable reward balance, causing the user to permanently lose value they had already earned — exactly as `migrateToVault` overwrote `rewardsAccrued` without settling it first. Here, `close_balance` overwrites `emissions_outstanding` without settling it first, and only requires a full withdraw/repay of principal to be reachable (per the developer docs, "Set `withdraw_all` to true... this is the only way to close a Balance"). [8](#0-7) 

### Impact Explanation
A user (or an integrator wrapping user accounts) who has accrued emissions on a position and then fully withdraws/repays and closes that balance permanently loses those unclaimed emissions — there is no way to recover the value once the `Balance` slot is zeroed and its bank_pk cleared. This is a direct, unprivileged loss of user funds/rewards with no attacker required; it can happen in normal usage any time a user or automation closes a balance without first harvesting emissions (assuming emissions harvesting is a separate step from this close instruction).

### Likelihood Explanation
Likelihood is high for any campaign that offers emissions and any user who follows the documented pattern of fully withdrawing (`withdraw_all = true`) and then closing balances to free up slots (the account only has 16 balance slots, `MAX_LENDING_ACCOUNT_BALANCES = 16`, so closing unused slots is a normal maintenance action). No special privileges or attacker setup are needed — the loss occurs for any legitimate, well-intentioned user interaction. [9](#0-8) 

### Recommendation
Before zeroing the balance in `close_balance`, either (a) require `emissions_outstanding.is_zero_with_tolerance(...)` and return `MarginfiError::CannotCloseOutstandingEmissions` if non-zero (wiring up the already-defined error), forcing the user to claim/settle emissions first, or (b) automatically settle/transfer the outstanding emissions to the user's emissions destination before deactivating the slot.

### Proof of Concept
1. User deposits into a bank that has an active emissions campaign; over time `Balance.emissions_outstanding` accrues a positive value for that balance (per `type-crate/src/types/user_account.rs:299-302`).
2. User calls `lending_account_withdraw` with `withdraw_all = true`, bringing `asset_shares`/`liability_shares` to zero but leaving the `Balance` (and its accrued `emissions_outstanding`) on the account, consistent with the documented behavior that only `withdraw_all`/`repay all` can enable a subsequent close.
3. User (or anyone with authority) calls `lending_account_close_balance` (`programs/marginfi/src/instructions/marginfi_account/close_balance.rs:19-57`).
4. `BankAccountWrapper::close_balance` (`programs/marginfi/src/state/marginfi_account.rs:1739-1799`) passes the zero-asset/zero-liability checks and calls `balance.close()`.
5. `Balance::close()` (`programs/marginfi/src/state/marginfi_account.rs:1485-1489`) overwrites the balance with `empty_deactivated()`, which hard-codes `emissions_outstanding = 0` (`type-crate/src/types/user_account.rs:347-360`), permanently discarding the previously accrued rewards with no compensating claim/settlement step and no error raised, despite `MarginfiError::CannotCloseOutstandingEmissions` existing specifically for this case.

    pub fn close_balance(&mut self, in_receivership: bool) -> MarginfiResult<()> {
        let balance = &mut self.balance;
        let bank = &mut self.bank;

        let current_liability_amount =
            bank.get_liability_amount(balance.liability_shares.into())?;
        let current_asset_amount = bank.get_asset_amount(balance.asset_shares.into())?;

        check!(
            current_liability_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing debt"
        );

        check!(
            current_asset_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing assets"
        );

        let asset_shares: I80F48 = balance.asset_shares.into();
        let liability_shares: I80F48 = balance.liability_shares.into();
        // Counters are incremented in `*_balance_internal` when shares cross
        // `ZERO_AMOUNT_THRESHOLD` upward; match that condition so we don't
        // double-decrement positions that already crossed downward earlier.
        let had_assets = asset_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);
        let had_liabs = liability_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);

        balance.close()?;
