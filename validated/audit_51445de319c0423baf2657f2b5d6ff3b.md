## Finding [1](#0-0) 

### Title
Lockup Factory `create()` lets an unprivileged funder substitute an arbitrary "whitelist" contract that later gates staking-pool delegation of the entire locked balance - (File: `lockup-factory/src/lib.rs`)

### Summary
`LockupFactory::create()` accepts an optional `whitelist_account_id` parameter from any unprivileged caller who merely attaches the minimum deposit. If supplied, this arbitrary account ID is baked into the newly deployed `LockupContract` as its `staking_pool_whitelist_account_id`, completely replacing the Foundation-controlled whitelist that is supposed to vet which staking pools can safely receive delegated funds.

### Finding Description
`create()` in `lockup-factory/src/lib.rs` is `payable` and callable by anyone; the only guard is a minimum-deposit check: [2](#0-1) 

It then resolves the whitelist to embed in the deployed lockup, defaulting to the factory's own trusted whitelist **only if the caller does not supply one**: [3](#0-2) 

This value is placed directly into `LockupArgs.staking_pool_whitelist_account_id`, which is passed unchanged into the lockup's `new()` initializer: [4](#0-3) 

The lockup contract only validates that the supplied account ID is syntactically well-formed — it never checks that it is the real, Foundation-deployed whitelist contract: [5](#0-4) 

Once deployed, the owner's entire ability to safely delegate the locked NEAR balance depends on this single stored account ID. `select_staking_pool()` queries whatever contract is stored there and trusts its `true`/`false` answer unconditionally: [6](#0-5) [7](#0-6) 

The binding that is broken: `staking_pool_whitelist_account_id` is supposed to equal the Foundation's audited whitelist contract (`whitelist/src/lib.rs`, whose `add_staking_pool`/`add_factory` are gated by `assert_called_by_foundation`, see [8](#0-7) ). Instead, `create()` lets the funding party (not the Foundation, not even necessarily the owner) set it to any account, including one the funder deployed themselves that unconditionally answers `is_whitelisted() == true`. The lockup contract has no way to distinguish this from the genuine whitelist.

### Impact Explanation
Because the substituted contract can be programmed to affirm any `staking_pool_account_id` as whitelisted, the owner's `select_staking_pool` / `deposit_and_stake` flow — which exists specifically to prevent delegation to unvetted staking pools that could swallow funds — is defeated for this specific lockup instance. An attacker who funds (or convinces someone to fund) a lockup with a poisoned `whitelist_account_id` can cause the entire locked/vested NEAR balance to be staked into an attacker-controlled "staking pool" contract that never honors unstake/withdraw, resulting in the locked NEAR being permanently diverted to the attacker. This is a "wrongly whitelisted or wrongly parameterised deployment" leading to NEAR moved by a party not entitled to it — a Critical-severity outcome.

### Likelihood Explanation
No privileged role is required to trigger the root cause: any account able to call `create()` with the minimum deposit (3,500 NEAR minimum attached balance per `MIN_ATTACHED_BALANCE`) can set the poisoned whitelist at deployment time; the owner and Foundation have no visibility into or approval step over this parameter. The subsequent step (owner selecting a pool that the poisoned whitelist "approves") occurs through the contract's normal intended workflow rather than any redeploy or key compromise, mirroring exactly the class of issue described in the reference report (an address trusted implicitly by downstream custody logic without independent verification).

### Recommendation
Do not allow the caller of `create()` to override `staking_pool_whitelist_account_id` with an arbitrary account. Either always use the factory's configured `whitelist_account_id`, or restrict the override to a Foundation-curated set of alternate whitelist accounts (verified via `is_factory_whitelisted`-style registry) rather than accepting any caller-supplied `ValidAccountId`.

### Proof of Concept
1. Attacker deploys a trivial contract `fake-whitelist.near` whose `is_whitelisted(staking_pool_account_id)` always returns `true`.
2. Attacker (or a compromised/careless funding party) calls:
   `lockup-factory.create({"owner_account_id":"victim.near","lockup_duration":"...","whitelist_account_id":"fake-whitelist.near"})` with the required deposit — see `create()` at [9](#0-8) .
3. The factory deploys `victim.near`'s lockup with `staking_pool_whitelist_account_id = "fake-whitelist.near"` (see the `LockupArgs` construction at lines 140-157 above), instead of the genuine Foundation whitelist.
4. Later, the owner calls `select_staking_pool("attacker-pool.near")`; the lockup queries `fake-whitelist.near`, which returns `true` (`lockup/src/owner.rs:29-40`), so `on_whitelist_is_whitelisted` accepts it (`lockup/src/owner_callbacks.rs:7-25`).
5. The owner deposits and stakes the full locked NEAR balance into `attacker-pool.near`, a contract the attacker controls that never permits withdrawal — the locked NEAR is now under the attacker's control instead of following the intended lockup/vesting schedule.

    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =

        let mut foundation_account: Option<AccountId> = None;

            foundation_account = Some(self.foundation_account_id.clone());

            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

    /// Selects staking pool contract at the given account ID. The staking pool first has to be
    /// checked against the staking pool whitelist contract.
    pub fn select_staking_pool(&mut self, staking_pool_account_id: AccountId) -> Promise {
        self.assert_owner();
        assert!(
            env::is_valid_account_id(staking_pool_account_id.as_bytes()),
            "The staking pool account ID is invalid"
        );
        self.assert_staking_pool_is_not_selected();
        self.assert_no_termination();

        env::log(
            format!(
                "Selecting staking pool @{}. Going to check whitelist first.",
                staking_pool_account_id
            )
            .as_bytes(),
        );

        ext_whitelist::is_whitelisted(
            staking_pool_account_id.clone(),
            &self.staking_pool_whitelist_account_id,
            NO_DEPOSIT,
            gas::whitelist::IS_WHITELISTED,
        )
        .then(ext_self_owner::on_whitelist_is_whitelisted(
            staking_pool_account_id,
            &env::current_account_id(),
            NO_DEPOSIT,
            gas::owner_callbacks::ON_WHITELIST_IS_WHITELISTED,
        ))
    }

    /// Called after a given `staking_pool_account_id` was checked in the whitelist.
    pub fn on_whitelist_is_whitelisted(
        &mut self,
        #[callback] is_whitelisted: bool,
        staking_pool_account_id: AccountId,
    ) -> bool {
        assert_self();
        assert!(
            is_whitelisted,
            "The given staking pool account ID is not whitelisted"
        );
        self.assert_staking_pool_is_not_selected();
        self.assert_no_termination();
        self.staking_information = Some(StakingInformation {
            staking_pool_account_id,
            status: TransactionStatus::Idle,
            deposit_amount: 0.into(),
        });
        true
    }

    /// Adds the given staking pool account ID to the whitelist.
    /// Returns `true` if the staking pool was not in the whitelist before, `false` otherwise.
    /// This method can be called either by the NEAR foundation or by a whitelisted factory.
    pub fn add_staking_pool(&mut self, staking_pool_account_id: AccountId) -> bool {
        assert!(
            env::is_valid_account_id(staking_pool_account_id.as_bytes()),
            "The given account ID is invalid"
        );
        // Can only be called by a whitelisted factory or by the foundation.
        if !self
            .factory_whitelist
            .contains(&env::predecessor_account_id())
        {
            self.assert_called_by_foundation();
        }
        self.whitelist.insert(&staking_pool_account_id)
    }
