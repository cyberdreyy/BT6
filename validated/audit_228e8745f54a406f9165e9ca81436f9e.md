### Title
Rounding mismatch between `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` lets a signer act on a stale/under-met consensus threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The report's core complaint is that `PumpV1` performs unchecked math assuming a uniform 18-decimal scale, and separately assumes a `bool` return where none exists — two different places computing/relying on "the same" quantity use inconsistent conventions, producing a wrong threshold/amount. The stacks-signer codebase has a direct analog: two independent implementations of "70% weight threshold" use different rounding rules, so a signer's local view of global consensus can register "agreement reached" at a weight strictly below the value the authoritative Nakamoto consensus rule (and the signer's own block-acceptance/rejection code) requires.

### Finding Description
The authoritative weight threshold used for actual block-signature consensus is `NakamotoBlockHeader::compute_voting_weight_threshold`, which explicitly rounds **up**: [1](#0-0) 

This same ceiling formula is what `stacks-signer/src/v0/signer.rs` uses to decide whether a block has been globally accepted or rejected via signatures/rejections: [2](#0-1) [3](#0-2) 

However, `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` — the functions that determine consensus on the **signer protocol version**, the **global burn view**, the **global state machine** (including which miner/tenure is canonical), and the **tx replay set** — use plain integer (floor) division instead of the ceiling adjustment: [4](#0-3) 

For any `total_weight` where `total_weight * 7` is not a multiple of 10 (e.g. `total_weight = 11` → real threshold `ceil(7.7) = 8`, but `reached_agreement` accepts at `vote_weight = 7`, since `77 / 10 = 7`), the two "70%" thresholds diverge by one weight unit. This function gates safety-relevant decisions such as:
- `determine_latest_supported_signer_protocol_version` (which protocol/validation rules a signer applies)
- `determine_global_burn_view` and `determine_global_state` (which burn view / current-miner / tx-replay-set the signer treats as canonical)
- `capitulate_miner_view` (whether the signer switches its local view of the canonical miner/tenure) [5](#0-4) [6](#0-5) 

Once `LocalStateMachine::capitulate_miner_view`/`update_protocol_version` accept these under-threshold "global" conclusions, the signer's tenure-validity checks and block-proposal checks (`is_tenure_valid`, `check_block_against_global_state`) operate on a state machine that has not actually accumulated the real (ceiling) 70% weight required by consensus, i.e. the signer is "acting on a stale/insufficiently-verified threshold" relative to the very rule (`compute_voting_weight_threshold`) that governs actual block-signature finality.

### Impact Explanation
This falls under the "High" impact class: a signer acting on a threshold that is inconsistent with the protocol's real, authoritative threshold. Concretely, a signer can capitulate its view of the canonical miner/tenure, or its consensus about the tx-replay-set/protocol version, one weight-unit earlier than the true supermajority is present. Because this local "consensus" gates which proposals a signer will validate and pre-commit/sign, it weakens the guarantee that a signer only follows a miner-tenure view once a true 70% supermajority genuinely agrees — an off-by-one erosion of the safety margin the protocol relies on for tenure-view convergence.

### Likelihood Explanation
The discrepancy occurs mechanically whenever `total_weight * NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` is not a multiple of 10, which is the common case for any signer set whose total weight is not a multiple of 10 (arbitrary stacking-weight distributions across signers virtually guarantee this). No majority collusion is required to trigger the underlying rounding bug — it is a deterministic arithmetic inconsistency baked into two independently maintained threshold implementations, only requiring ordinary gossip of `StateMachineUpdate` messages from signers whose weight sums land in the gap between floor and ceiling.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` share the exact same ceiling-rounding logic as `NakamotoBlockHeader::compute_voting_weight_threshold` (ideally by calling a single shared function from both `stackslib` and `libsigner`), so that "global agreement" as computed by the signer state machine can never be satisfied with less weight than the chainstate-enforced signature threshold requires.

### Proof of Concept
1. Configure a reward set whose signers' weights sum to a `total_weight` such that `total_weight * 7 % 10 != 0` (e.g., `total_weight = 11`, weights split e.g. 7/4).
2. Real threshold per `compute_voting_weight_threshold(11)` = `ceil(77/10)` = `8`.
3. Have signers gossip `StateMachineUpdate` messages such that the accumulated weight in `determine_global_state`/`determine_latest_supported_signer_protocol_version`/`capitulate_miner_view` for a given (miner, burn view) reaches `7` (still short of the true `8`).
4. `GlobalStateEvaluator::reached_agreement(7)` returns `true` (`7 >= 11*7/10 = 7`), even though `NakamotoBlockHeader::compute_voting_weight_threshold(11)` requires `8`.
5. The signer capitulates its local view of the canonical miner/tenure (or protocol version/replay set) at `7/11` weight instead of the required `8/11`, and proceeds to validate/sign blocks under that prematurely-converged view.

        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0

            1
        };

            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
