### Title
Unauthorized account-migration griefing via unchecked `new_authority` in `transfer_to_new_account_pda` — ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
The Lens `LensV2Migration` bug allowed a party with mint access to permanently break another party's expected on-chain migration path by squatting the deterministic identifier (handle) that migration relies on. The same root cause — an unprivileged actor being able to pre-occupy a deterministic address that another party expects to control, with no consent check from the address owner — is reachable in marginfi-v2's `transfer_to_new_account_pda` instruction, where the `new_authority` account is completely unchecked and not required to sign.

### Finding Description
`transfer_to_new_account_pda` lets the holder of *any* existing (non-frozen, non-flashloan, non-receivership) `MarginfiAccount` migrate it to a brand-new PDA-derived account under an arbitrary `new_authority` chosen entirely by the caller: [1](#0-0) 

`new_authority` is declared as `UncheckedAccount<'info>` with the comment "WARN: New authority is completely unchecked," and it is never required to be a `Signer`: [2](#0-1) 

The new account's address is a PDA deterministically derived from `(MARGINFI_ACCOUNT_SEED, group, new_authority, account_index, third_party_id)`: [3](#0-2) 

This is the exact same PDA derivation formula used by the permissionless `marginfi_account_initialize_pda` instruction that a legitimate user calls (with themselves as signing `authority`) to create their *own* canonical account: [4](#0-3) [5](#0-4) 

Because `new_authority` is not a signer in `transfer_to_new_account_pda`, any existing account holder can pick a victim's public key, a "canonical" `account_index` (e.g., `0`) and `third_party_id`, and force-migrate their own (possibly leveraged/liquidatable) account into the PDA slot that the victim — or a third-party integrator relying on the canonical `(authority, account_index=0)` PDA — would otherwise expect to create cleanly via `marginfi_account_initialize_pda`. Once occupied, Anchor's `init` constraint means any subsequent legitimate `marginfi_account_initialize_pda` call from the victim for that same `(account_index, third_party_id)` will permanently revert with "already in use," exactly mirroring the Lens `batchMigrateProfiles()` revert-on-duplicate-mint failure mode described in the report.

Additionally, the transferred account is stamped with `new_account.authority = new_authority` (the victim), so the victim is handed unsolicited control (and on-chain association) over the old account's `lending_account`, `emissions_destination_account`, and `account_flags` state without ever consenting: [6](#0-5) [7](#0-6) 

### Impact Explanation
Any unprivileged wallet holding a `MarginfiAccount` (trivial precondition — anyone can create one) can:
1. Permanently deny a specific victim address the ability to ever initialize its canonical PDA-derived `MarginfiAccount` for a chosen `account_index`/`third_party_id` (durable freeze of that specific account slot, no recovery path since `init` PDA collisions are irreversible).
2. Silently attach unsolicited financial state (existing lending/liability positions, emissions destination, account flags) to the victim's authority key without the victim's signature — an unauthorized state change tied to a real financial position.
3. This is especially damaging for third-party CPI integrations that rely on a fixed, well-known `third_party_id`/`account_index` convention (as documented in `lib.rs`) to deterministically locate a user's canonical marginfi account; an attacker can pre-squat that canonical slot for a targeted user, breaking the integration path for that user permanently.

### Likelihood Explanation
High feasibility: no privileged role, oracle, or governance access is required — only ownership of any ordinary, unfrozen `MarginfiAccount` (which any user can create for near-zero cost) and knowledge of the victim's public key (always public) and the target `account_index`/`third_party_id` convention (published/well-known for canonical or third-party integrations). The instruction is fully permissionless and reachable exactly as documented.

### Recommendation
Require `new_authority` to be a `Signer` in `TransferToNewAccountPda` (and `TransferToNewAccount`), so that account transfers require explicit consent from the receiving authority — mirroring the signer requirement already enforced in `MarginfiAccountInitializePda`. If a signer-less "gift" flow is intentionally desired, add an explicit off-chain/handshake or allow-list mechanism (e.g., a nonce or pre-registered acceptance PDA) that only the intended new authority can create in advance, analogous to Lens's off-chain handle-collision check added to `ProfileCreationProxy`.

### Proof of Concept
1. Victim `V` intends to later call `marginfi_account_initialize_pda(account_index=0, third_party_id=None)` to get their canonical account at PDA `P = derive_pda(group, V, 0, None)`.
2. Attacker `A` creates any ordinary `MarginfiAccount` via `marginfi_account_initialize` (keypair-based), depositing/borrowing arbitrary amounts.
3. Attacker calls `transfer_to_new_account_pda` with `authority = A` (signs), `new_authority = V` (not required to sign), `account_index = 0`, `third_party_id = None`. This succeeds because `new_authority` has no signer or ownership check — see `TransferToNewAccountPda` accounts struct at [8](#0-7) .
4. The PDA `P` is now initialized, owned/authorized to `V`, holding `A`'s old lending/liability balances (per `initialize_migrated_account`).
5. `V` later attempts `marginfi_account_initialize_pda(account_index=0, third_party_id=None)`; the `init` constraint on `marginfi_account` fails with "already in use" (as demonstrated for the duplicate-init case in the existing test suite: [9](#0-8) ), permanently blocking `V` from creating a clean canonical account at that index.

#[derive(Accounts)]
#[instruction(account_index: u16, third_party_id: Option<u16>)]
pub struct TransferToNewAccountPda<'info> {
    #[account(
        constraint = (
            !group.load()?.is_protocol_paused()
        ) @ MarginfiError::ProtocolPaused
    )]
    pub group: AccountLoader<'info, MarginfiGroup>,

    #[account(
        mut,
        has_one = group @ MarginfiError::InvalidGroup,
        constraint = {
            let a = old_marginfi_account.load()?;
            account_not_frozen_for_authority(&a, authority.key())
        } @ MarginfiError::AccountFrozen,
        constraint = {
            let a = old_marginfi_account.load()?;
            let g = group.load()?;
            is_signer_authorized(&a, g.admin, authority.key(), false, false)
        } @ MarginfiError::Unauthorized
    )]
    pub old_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    #[account(
        init,
        payer = fee_payer,
        space = 8 + std::mem::size_of::<MarginfiAccount>(),
        seeds = [
            MARGINFI_ACCOUNT_SEED.as_bytes(),
            group.key().as_ref(),
            new_authority.key().as_ref(),
            &account_index.to_le_bytes(),
            &third_party_id.unwrap_or(0).to_le_bytes(),
        ],
        bump
    )]
    pub new_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    pub authority: Signer<'info>,

    #[account(mut)]
    pub fee_payer: Signer<'info>,

    /// CHECK: WARN: New authority is completely unchecked
    pub new_authority: UncheckedAccount<'info>,

    /// CHECK: Validated against group fee state cache
    #[account(mut)]
    pub global_fee_wallet: UncheckedAccount<'info>,

    /// Instructions sysvar for CPI validation
    /// CHECK: Standard sysvar account
    #[account(address = solana_instructions_sysvar::id())]
    pub instructions_sysvar: UncheckedAccount<'info>,

    pub system_program: Program<'info, System>,
}

#[tokio::test]
async fn marginfi_account_create_pda_duplicate_fails() -> anyhow::Result<()> {
    let test_f = TestFixture::new(None).await;

    let authority = test_f.payer();
    let account_index = 0;
    let third_party_id = None;

    // Derive PDA for the marginfi account
    let (marginfi_account_pda, _bump) = MarginfiAccount::derive_pda(
        &test_f.marginfi_group.key,
        &authority,
        account_index,
        third_party_id,
        &marginfi::ID,
    );

    let accounts = marginfi::accounts::MarginfiAccountInitializePda {
        marginfi_group: test_f.marginfi_group.key,
        marginfi_account: marginfi_account_pda,
        authority: authority,
        fee_payer: authority,
        instructions_sysvar: solana_instructions_sysvar::id(),
        system_program: system_program::id(),
    };

    let init_marginfi_account_pda_ix = Instruction {
        program_id: marginfi::ID,
        accounts: accounts.to_account_metas(Some(true)),
        data: marginfi::instruction::MarginfiAccountInitializePda {
            account_index,
            third_party_id,
        }
        .data(),
    };

    // First transaction should succeed
    let tx1 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix.clone()],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res1 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx1)
        .await;

    assert!(res1.is_ok());

    // Second transaction with same parameters should fail
    let tx2 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res2 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx2)
        .await;

    assert!(res2.is_err(), "Duplicate account creation should fail");

    Ok(())
}
