### Title
HTTP Trigger callback map keyed solely by client-supplied request ID enables cross-workflow request-ID squatting DoS - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
The Gateway's HTTP Trigger handler stores in-flight requests in a single map keyed only by the caller-supplied JSON-RPC `id`, with no binding to the requesting workflow or owner. Any authorized-but-unprivileged caller can pre-register an arbitrary `id` value before the intended workflow owner does, causing the legitimate request with the same `id` to be rejected. This is the same root-cause pattern as the LamboFactory report: a globally shared, attacker-influenceable keyspace lets an unprivileged actor pre-occupy a slot that a victim's subsequent, legitimate call needs, producing denial of service instead of normal processing.

### Finding Description
`httpTriggerHandler` maintains a single, DON/handler-wide map: [1](#0-0) 

`setupCallback` registers a new entry keyed purely by the client-controlled `req.ID`. If an entry already exists for that exact `id`, the request is rejected with a conflict error, regardless of which workflow or owner is making the call: [2](#0-1) 

The only validation applied to the caller-chosen `id` is that it is non-empty and does not contain `/`: [3](#0-2) 

`setupCallback` is reached after `authorizeRequest`, which only checks that the caller is authorized for *their own* workflow selector, not that the `id` they picked is reserved for them: [4](#0-3) 

Because the map is keyed only by `id` — with no workflow ID / owner component mixed in — an authorized caller for **workflow A** can submit a request with `id = "X"` and thereby occupy that slot for the entire handler. If a different, legitimate caller for **workflow B** independently uses the same `id = "X"` (predictable/sequential IDs, timestamp-based IDs, or client-side counters are common), their request hits the `found` branch and is rejected with `jsonrpc.ErrConflict`, exactly mirroring how a pre-created Uniswap pair causes `LamboFactory.createLaunchPad` to permanently revert for the intended deployer.

The occupied entry is only released when: (a) the attacker's own request completes/aggregates a response, (b) `reapExpiredCallbacks` sweeps it after `CleanUpPeriodMs`, or (c) `MaxTriggerRequestDurationMs` elapses: [5](#0-4) [6](#0-5) 

An attacker can trivially re-squat the same `id` again right after expiry, turning a bounded-duration collision into an indefinitely repeatable, low-cost targeted denial of service against any workflow owner whose request-ID scheme is guessable.

### Impact Explanation
A workflow's legitimate HTTP trigger invocation can be denied service (`ErrConflict`) by any other authorized-but-unrelated caller who merely guesses or reuses the same request `id`, without needing any privilege over the victim's workflow. Since HTTP triggers initiate workflow executions, this can block execution of a targeted workflow for as long as the attacker is willing to keep re-squatting the ID, which is comparable in effect (though not fully "permanent") to the LamboFactory DoS: an unprivileged party can prevent a specific victim operation from succeeding by exploiting a shared, insufficiently-scoped identifier space.

### Likelihood Explanation
Exploitation requires the attacker to already be an authorized caller for *some* workflow that uses the HTTP trigger handler (a low bar, since it only requires normal JWT-based authorization for their own workflow) and to know or predict the victim's chosen request `id`. Many clients use sequential, timestamp-derived, or otherwise low-entropy IDs, making prediction realistic in numerous real-world integration patterns. The attack is race-based (attacker must land its request slightly before the victim's) but can be repeated cheaply and continuously.

### Recommendation
Scope the in-flight request key by workflow identity in addition to the client-supplied `id` (e.g., `(workflowID, requestID)` or `(workflowOwner, requestID)`), so that a caller can only collide with their own outstanding requests, not with other workflows' request IDs. Alternatively, bind the callback map key to an internally-generated identifier (e.g., derived from `workflowID` + `req.ID`) before performing the "already in-flight" check, ensuring the check cannot be used to squat identifiers belonging to a different, unrelated workflow.

### Proof of Concept
1. Attacker becomes an authorized caller for `workflowA` (any workflow they control) that exposes the HTTP trigger capability.
2. Attacker predicts/guesses the `id` a victim's client will next use for `workflowB` (e.g., a sequential counter such as `"1001"`).
3. Attacker sends a `workflows.execute` JSON-RPC request for `workflowA` with `id = "1001"`, which is accepted and stored in `httpTriggerHandler.callbacks["1001"]` via `setupCallback` at [2](#0-1) .
4. Before the entry expires or completes, the victim sends their legitimate request for `workflowB` with `id = "1001"`.
5. `setupCallback` finds the existing entry and returns `jsonrpc.ErrConflict` ("requestID: 1001 has already been used...") to the victim, denying them service even though they had no relationship to the attacker's request or workflow.
6. Attacker repeats steps 2–4 after each expiry window to sustain the denial of service.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)

// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}

// reapExpiredCallbacks removes callbacks that are older than the maximum age
func (h *httpTriggerHandler) reapExpiredCallbacks(ctx context.Context) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	now := time.Now()
	var expiredCount int
	for reqID, callback := range h.callbacks {
		if now.Sub(callback.createdAt) > time.Duration(h.config.CleanUpPeriodMs)*time.Millisecond {
			h.metrics.IncrementRequestErrors(ctx, jsonrpc.ErrInternal, h.lggr)
			h.cleanupCallback(reqID)
			expiredCount++
		}
	}
	if expiredCount > 0 {
		h.metrics.IncrementPendingRequestsCleanUpCount(ctx, int64(expiredCount), h.lggr)
		h.lggr.Infow("Removed expired callbacks", "count", expiredCount, "remaining", len(h.callbacks))
	}
	h.metrics.RecordPendingRequestsCount(ctx, int64(len(h.callbacks)), h.lggr)
}
