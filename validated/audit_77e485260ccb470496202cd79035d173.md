### Title
pprof debug endpoints mounted under authv2 lack any role gate, allowing any authenticated view/run-role user to dump heap/goroutine profiles - ([File: core/web/router.go])

### Summary
`metricRoutes` mounts the full `net/http/pprof` handler set (`/v2/debug/pprof/*`) directly on the `authv2` route group, which only requires successful authentication (session or API token) via `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`. Unlike every other sensitive endpoint in `v2Routes` (keys export/import, users, transfers, etc.), none of the pprof routes are wrapped in `auth.RequiresEditRole` or `auth.RequiresAdminRole`, so a user with the lowest privilege role (`UserRoleView`) can reach heap/goroutine/profile dumps.

### Finding Description
`v2Routes` builds `authv2` with only an authentication check, no role check: [1](#0-0) 

At the end of the group, `metricRoutes(authv2)` is called with a comment "Debug routes accessible via authentication": [2](#0-1) 

`metricRoutes` mounts pprof's `Index`, `Cmdline`, `Profile`, `Symbol`, `Trace`, and the `allocs/block/goroutine/heap/mutex/threadcreate` profile handlers with no additional middleware: [3](#0-2) 

Comparing to every other route in the same block, they are consistently wrapped in `auth.RequiresEditRole` or `auth.RequiresAdminRole` (e.g. key export/import, user management, transfers): [4](#0-3) [5](#0-4) 

The role-check middlewares (`RequiresRunRole`, `RequiresEditRole`, `RequiresAdminRole`) only inspect `user.Role` when explicitly invoked as a wrapper around the handler: [6](#0-5) 

Since `metricRoutes` never calls any of these, `auth.Authenticate` alone (which succeeds for any valid session/API-token regardless of role, including `UserRoleView`) is sufficient to reach `pprof.Handler("heap")`, `pprof.Handler("goroutine")`, etc.

`net/http/pprof`'s heap/goroutine profile output can include raw memory contents and stack traces of running goroutines, which in an in-process Go application can capture byte slices containing decrypted key material, session tokens, or other secrets currently resident in memory (e.g., ETH/OCR/CSA/VRF/P2P private keys unlocked in the KeyStore, or session cookies), depending on process state at capture time.

### Impact Explanation
This matches Chainlink's "unauthorized access / privilege escalation leading to sensitive information disclosure" impact class: a low-privileged authenticated user (view role — normally read-only, with no key/job management rights) can extract full-process memory/goroutine dumps that a properly role-gated system would restrict to admin only. Successful extraction of key material or session tokens from a heap dump could enable further compromise, including transaction signing or account takeover, extending impact beyond simple information disclosure.

### Likelihood Explanation
Very high feasibility: the only precondition is possession of *any* valid, currently-authenticated credential (session cookie or API token) for a node user, even the lowest `view` role, which is a "normal use" credential level (many operators grant view-only tokens to monitoring/read-only integrations). The endpoints are simple unauthenticated-by-role `GET` requests (`/v2/debug/pprof/heap`, `/goroutine`, etc.) with no additional guard, gate, or rate-limit beyond the generic authenticated rate limiter, so the attack is trivially repeatable.

### Recommendation
Wrap all routes registered in `metricRoutes` with `auth.RequiresAdminRole` (consistent with other sensitive debug/administrative operations such as `/log` PATCH and key export/import), e.g.:
```go
func metricRoutes(r *gin.RouterGroup) {
    pprofGroup := r.Group("/debug/pprof")
    pprofGroup.GET("/", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Index)))
    ...
}
```
Ensure the same gate is applied to `/cmdline`, `/profile`, `/symbol` (GET/POST), `/trace`, `/allocs`, `/block`, `/goroutine`, `/heap`, `/mutex`, `/threadcreate`.

### Proof of Concept
Go handler-level integration test plan (using the existing web test harness pattern, e.g. `cltest.NewApplication`/`web.Router` setup used in other `core/web/*_test.go` files):
1. Create a test application and a user with `sessions.UserRoleView`.
2. Authenticate as that view-role user via `POST /sessions` to obtain a session cookie (or create an API token scoped to a view-role user).
3. Issue `GET /v2/debug/pprof/heap` and `GET /v2/debug/pprof/goroutine` using that session/token.
4. Assert current behavior: HTTP 200 with a valid pprof profile body returned (expected/secure behavior should be HTTP 403 "Forbidden", matching the `RequiresAdminRole` rejection format used elsewhere, e.g. see `TestUserController` / `TestETHKeysController_RequiresAdmin`-style tests in `core/web/*_test.go`).
5. Optionally, unlock an ETH key in the app's keystore before the request and scan the returned heap dump bytes for the private key hex value to confirm secret material is present in the dump (demonstrates concrete secret-confinement violation, not just endpoint reachability).
6. After applying the recommended fix (wrapping with `auth.RequiresAdminRole`), re-run the same test and assert HTTP 403 for the view-role session while an admin-role session still receives HTTP 200.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
