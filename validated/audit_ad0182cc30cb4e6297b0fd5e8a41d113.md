The reported bug class (a rate applied retroactively to an entire period even though it changed mid-period) has a direct analog in marginfi-v2's bank interest/fee accrual mechanism.

### Title
Fee/Interest Rate Config Changes Are Applied Retroactively to the Entire Elapsed Period in `accrue_interest` - (File: `programs/marginfi/src/state/bank.rs`)

### Summary
`Bank::accrue_interest` computes interest and fees for the *entire* `time_delta` elapsed since `self.last_update` using the interest-rate/fee configuration that is active **at the moment `accrue_interest` executes**, not the configuration(s) that were active during each sub-interval of that elapsed time. `lending_pool_configure_bank_interest_only` and `lending_pool_configure_bank` mutate `bank.config.interest_rate_config` (which encodes `insurance_ir_fee`, `insurance_fee_fixed_apr`, `protocol_ir_fee`, `protocol_fixed_fee_apr`, and the curve `points`) directly, in-place, without first calling `accrue_interest` to settle/checkpoint the period under the old rates.

### Finding Description
`accrue_interest` in [1](#0-0)  computes `time_delta` from `self.last_update` to `current_timestamp` and passes the *current* `InterestRateCalc` (built from `self.config.interest_rate_config` via `create_interest_rate_calculator`) into `calc_interest_rate_accrual_state_changes` for the whole `time_delta` at once — there is no segmentation by historical rate.

`InterestRateConfigImpl::update`, invoked from the config-mutation instructions, overwrites the fee/curve fields directly on the bank's live config: [2](#0-1) .

Both `lending_pool_configure_bank_interest_only` (callable by `delegate_curve_admin`) and `configure()` (called from `lending_pool_configure_bank`, admin) apply this `update()` directly to `bank.config.interest_rate_config` without accruing interest first: [3](#0-2)  and [4](#0-3) .

Since `accrue_interest` is only run lazily, on the next user interaction (deposit/withdraw/borrow/repay) or via the permissionless `lending_pool_accrue_bank_interest` instruction ( [5](#0-4) ), any time gap between "last accrual" and "config change" plus "next accrual" is charged entirely at the rate in effect at accrual time — exactly the TermMax `_accruedPeriodInterest` bug pattern: the whole period is priced with the latest rate rather than being split at the moment the rate changed.

### Impact Explanation
This affects the shared `asset_share_value` / `liability_share_value` and the `collected_insurance_fees_outstanding` / `collected_group_fees_outstanding` / `collected_program_fees_outstanding` fields, which apply to *every* depositor and borrower in the bank simultaneously, not just to the admin performing the change. If a curve/fee admin lowers `protocol_ir_fee`/`insurance_ir_fee`/`protocol_fixed_fee_apr` right before triggering (or letting someone else permissionlessly trigger) `accrue_interest`, the entire backlog of unaccrued interest — which could span a long stale period for a low-activity bank — is retroactively charged at the lower fee rate, under-collecting protocol/insurance fees for that whole period; the inverse (raising rates then accruing) over-charges borrowers/lenders for a period during which the old, lower rate should have applied. Because bank interest compounds for all users at once (`guides/ADMIN/COLLECTING_FEES.md`), this creates a systemic misallocation between the protocol/insurance vaults and depositors/borrowers, matching the original finding's "incorrect fee calculation / unfair fund distribution" impact.

### Likelihood Explanation
Likelihood scales with how frequently `insurance_ir_fee`, `protocol_ir_fee`, `protocol_fixed_fee_apr`/`insurance_fee_fixed_apr`, or curve `points` are changed relative to how long a bank goes without an `accrue_interest` call. Low-traffic banks (per the docs, banks "might compound just a few times per week") are most exposed, since a longer stale `time_delta` amplifies the mispriced interval. `lending_pool_accrue_bank_interest` is explicitly permissionless, so anyone can trigger the mispriced accrual immediately after (or race to trigger it right before) a rate change to capture the discrepancy.

### Recommendation
Force an `accrue_interest` (checkpoint) call as part of `lending_pool_configure_bank_interest_only` and `lending_pool_configure_bank`/`configure()` before applying any change to `interest_rate_config`, so that `self.last_update` is advanced and prior interest is settled under the old rates before the new rates take effect. This ensures each period's interest is computed with the rate that was actually in effect during that period, consistent with how the TermMax fix (PR 4/PR 5) segmented `accruedPeriodInterest()` by rate-change timestamps.

### Proof of Concept
1. Bank has `total_liability_shares`/`total_asset_shares` > 0 and has gone N days without any interaction (`last_update` is N days stale).
2. Admin/`delegate_curve_admin` calls `lending_pool_configure_bank_interest_only` to lower `protocol_ir_fee`/`insurance_ir_fee`/`protocol_fixed_fee_apr` (or raise them, depending on desired direction of exploitation) — this only calls `InterestRateConfigImpl::update`, no accrual occurs: [6](#0-5) .
3. Anyone calls the permissionless `lending_pool_accrue_bank_interest` instruction: [7](#0-6) .
4. `accrue_interest` computes `time_delta = current_timestamp - last_update` (the full N days) and applies the *new* fee rates to that entire `time_delta`, instead of splitting it at the moment the config changed: [8](#0-7) .
5. Result: protocol/insurance fees collected for the N-day period reflect the new rate for the whole period, not a time-weighted blend of old and new rates — an accounting misvaluation identical in mechanism to the reported TermMax vulnerability.

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;

pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

    Ok(())

pub fn lending_pool_accrue_bank_interest(
    ctx: Context<LendingPoolAccrueBankInterest>,

    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = &ctx.accounts.group.load()?;

        clock.unix_timestamp,

        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
