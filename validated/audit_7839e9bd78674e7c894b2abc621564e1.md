### Title
Response-map key collision on reused `req.ID` allows cross-user relay response confusion - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`h.activeRequests` is keyed solely by the client-supplied `req.ID` string with no binding to sender/connection identity, and completed requests are deleted from the map immediately in `sendResponseAndClearRequest`. A stray/delayed node response bearing the same `ID` as a just-completed request can be matched to a *new*, unrelated request that reused that ID, and gets merged into that new caller's bundle via `addResponseForNode`/`Bundle`.

### Finding Description
`newActiveRequest` (`core/services/gateway/handlers/confidentialrelay/handler.go:368-383`) only rejects an ID if it is *currently* present in `h.activeRequests`; it does nothing to bind the ID to the submitting connection/sender: [1](#0-0) 

`sendResponseAndClearRequest` deletes the entry from `h.activeRequests` the instant a request completes (line 668), which immediately frees that `ID` for reuse by any other caller: [2](#0-1) 

`HandleNodeMessage` looks up the pending request purely `by resp.ID` (line 408) and, if found, folds the node's response straight into that request's bundle via `addResponseForNode`/`Bundle` (lines 408-429), with no check that the response actually corresponds to the request that is currently occupying that ID slot: [3](#0-2) 

Exploit flow:
1. Attacker/User A sends `HandleJSONRPCUserMessage` with `req.ID = "X"`. `fanOutToNodes` sends it to all DON members.
2. A's request completes (reaches quorum, or times out) and `sendResponseAndClearRequest` deletes `activeRequests["X"]` at line 668.
3. Immediately after, User B (different sender) sends a request with the same `ID = "X"`. `newActiveRequest` succeeds because the map slot is free, and a new `activeRequest` is created for B under key `"X"`.
4. A slow/duplicate node reply for A's original request (still in flight from step 1's fan-out, e.g. a delayed websocket delivery) arrives at `HandleNodeMessage` carrying `resp.ID = "X"`. The handler resolves `ar := h.getActiveRequest("X")`, which now returns **B's** `activeRequest`, and the stray response is merged into B's bundle.
5. Because the bundler (`core/services/gateway/handlers/confidentialrelay/bundler.go`) performs no correlation between the response payload and the specific request context beyond `req.Method`/`ID` fields already stripped by the map lookup, and per the bundler's own documented trust model it "forwards every per-node signed response it collected... without verifying signatures, checking signer membership" (bundler.go:25-37), A's stray signed response for A's method/secret can be included as one of the responses attributed to B's request.

This is not merely a "second caller silently fails" issue (that path is otherwise safe — the caller gets an explicit error and no request object is created); the exploitable part is the deletion-then-reuse race that lets an in-flight node response addressed to a completed request be attributed to a brand-new, different request from a different sender before the DON returns a genuine response for the same ID collision.

### Impact Explanation
This is a cross-user response/data confusion within the gateway's request routing layer: a fragment of one user's DON relay response (which may reflect secrets or capability-execution results scoped to user A's workflow) can be blended into the bundle ultimately forwarded toward the enclave/response path associated with user B's request under the same ID. While the final trust decision is deferred to the enclave (per the bundler's documented model), the gateway itself has already lost request isolation guarantees, which is a correctness/isolation violation matching a "sensitive data exposure / cross-user request confusion" class issue rather than fund loss or full node compromise.

### Likelihood Explanation
Exploitability requires: (1) the ability to submit gateway JSON-RPC user messages with attacker-chosen `req.ID` values (available to any unprivileged/unauthenticated gateway client per the threat model), (2) predicting or guessing an ID recently used by a victim (feasible if IDs are sequential/predictable, or via racing many collisions since IDs are only 1–200 chars with no server-side uniqueness enforcement across time), and (3) a timing window between a request's deletion from `activeRequests` and the last in-flight node response for it draining — which is realistic given `fanOutToNodes` uses independent per-node sends with up to `nodeSendTimeout` (default 10s) and network jitter. This is race-dependent and needs precise timing, making it a lower-but-non-trivial likelihood; it is repeatable since an attacker can churn requests with a fixed ID rapidly to widen the race window.

### Recommendation
Bind `activeRequests` keys to more than the raw client-supplied ID — e.g., a composite key of `(senderAddress/connectionID, req.ID)`, or a server-generated internal correlation ID that is never reused, and validate on `HandleNodeMessage` that the node's response corresponds to the same request object that was actually sent to that node (e.g., by tracking which node addresses a given internal request was fanned out to, and rejecting responses from nodes not part of that fan-out set for the current occupant of the ID slot).

### Proof of Concept
Go handler-level test plan in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` with a fake `clockwork.Clock` and a mock `gwhandlers.DON`/`gwhandlers.Callback`.
2. Call `HandleJSONRPCUserMessage` for request A with `ID = "X"`, from callback A.
3. Drive quorum by calling `HandleNodeMessage` with enough signed responses to reach `earlyNeed`/`minQuorum`, causing `forwardBundle`→`sendResponseAndClearRequest` to fire and delete `activeRequests["X"]`.
4. Immediately call `HandleJSONRPCUserMessage` for request B with the same `ID = "X"`, different callback B; assert it succeeds and a new `activeRequest` for B is registered.
5. Call `HandleNodeMessage` again with `resp.ID = "X"` from a node address that was part of A's fan-out but had not yet replied (simulating a delayed response to A) and with a payload only valid/interpretable as A's data.
6. Assert that this response is merged into B's `activeRequest.responses` (reachable via `h.getActiveRequest("X")` returning B's object) and appears in the eventual bundle delivered to callback B — demonstrating the response intended for A's request context is delivered under B's `SendResponse` callback, violating isolation between A and B.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

	copiedResponses := ar.copiedResponses()
	// Bundle readiness counts decodable signed responses, while the enclave remains
	// responsible for signature and quorum verification. A collected response cannot
	// be replaced by a later response from the same node.
	summary, err := h.bundler.Bundle(ar.req, copiedResponses, l)
	if err != nil {
		l.Errorw("failed to build relay response bundle", "error", err)
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, err))
	}
	return h.forwardBundleOrTerminateIfReady(ctx, l, ar, summary, len(h.donConfig.Members)-summary.Total(), false)

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
