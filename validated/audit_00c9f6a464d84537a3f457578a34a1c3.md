### Title
APR0 withdraw receipt permanently bricks `stopEpoch` after an APR change — unprivileged depositor freezes all vault funds - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`prepareStopEpochWithApr0` reverts whenever `apr0TotalPrincipal != 0` and the vault's current `unscaledApr` is non-zero, and it reverts *before* clearing `apr0TotalPrincipal`. An unprivileged, KYC-passing lender can deposit while APR is 0 and file a `requestWithdraw`, which stores principal in the APR0 bucket. If the honest manager later raises the APR (a routine action), every subsequent `stopEpoch` call reverts, freezing the entire pool. This mirrors CVE-2016-1571's bug class: an unprivileged actor arms an edge-case state that later triggers a fatal check inside a privileged routine.

### Finding Description
- `requestWithdraw` routes to `_requestWithdrawApr0` when `unscaledApr == 0`, which increments the global `apr0TotalPrincipal` and records `apr0Users[_user].principal`/`principalEpoch` [1](#0-0) [2](#0-1) 
- On every `stopEpoch`, the CDO calls `prepareStopEpochWithApr0`. With a non-empty APR0 bucket it enforces `if (unscaledApr != 0) revert NotAllowed();` at lines 506–508, and only clears `apr0TotalPrincipal = 0` at line 540 — i.e., after the revert, the bucket can never be drained through this path [3](#0-2) 
- The only other decrements of `apr0TotalPrincipal` are inside `_clearWithdrawClaimForEpoch` under default-claim clearing (lines 823–828), which is unreachable without a borrower default [4](#0-3) 
- There is no "settle at claim" path for the global bucket: `_settleApr0` only moves per-user principal and never touches `apr0TotalPrincipal` [5](#0-4) 

### Impact Explanation
Once `apr0TotalPrincipal > 0` and `unscaledApr != 0`, `stopEpoch` always reverts, so `epochNumber` never advances, `pendingWithdraws` are never funded, and no withdraw request can ever be claimed — the epoch-end gate in `_claimFundedWithdrawRequest` (`epochNumber <= lastWithdrawRequest[_user]` → revert) stays closed forever [6](#0-5) . All LP principal is frozen. Recovery requires the honest manager to set APR back to 0, stop an epoch, and only then raise APR again — a temporary freeze of 100% of TVL (and effectively permanent if the APR change was a deliberate configuration migration, e.g., vault graduation to fixed APR). Loss quantification: entire pool NAV frozen for the duration.

### Likelihood Explanation
The attacker only needs to be a KYC-passing lender who deposits and requests withdrawal during a legitimately-configured APR=0 window (a supported vault mode per the APR0 test suite). The trigger — the manager raising APR while a pending APR0 receipt exists — is a plausible honest operational action and is not gated on pending requests: `setAprs` performs no `apr0TotalPrincipal` check. No default, loss, or privileged misbehavior is required.

### Recommendation
In `prepareStopEpochWithApr0`, settle the outstanding APR0 bucket at zero interest (or at the realized rate) instead of reverting when `unscaledApr != 0`, or move the `apr0TotalPrincipal = 0` reset before the APR check so a one-time stop clears the bucket. Alternatively, revert `setAprs` / APR updates while `apr0TotalPrincipal != 0`, or settle APR0 receipts lazily at claim time so the global bucket never blocks the epoch state machine.

  function prepareStopEpochWithApr0(uint256 _interest) external returns (uint256 _expInterest, uint256 _adjPendingWithdrawFees) {
    _onlyIdleCDO();
    IIdleCDOEpochVariant _cdo = IIdleCDOEpochVariant(idleCDO);
    uint256 _pendingFees = _cdo.pendingWithdrawFees();
    uint256 _tvl = _cdo.getContractValue();
    _expInterest = _interest > 1 ? _interest : _cdo.expectedEpochInterest();
    _adjPendingWithdrawFees = _pendingFees;
    // Principal currently waiting for withdraw that was requested while APR was 0,
    // net of the upfront management fee charged at request time.
    uint256 _principal = apr0TotalPrincipal;

    // Fast path: no APR0 accounting needed.
    if (_principal == 0) {
      return (_expInterest, _adjPendingWithdrawFees);
    }
    // APR0 principal is only valid while APR is 0 for that request lifecycle.
    if (unscaledApr != 0) {
      revert NotAllowed();
    }

    uint256 _apr0NetInterest;
    // APR0 allocation is computed only when stopEpoch receives a real override interest.
    // _expectedInterest == 1 is the "request all funds back" sentinel and is handled in IdleCDO.
    if (_expInterest > 1 && _expInterest > _pendingFees) {
      // Remove already booked withdraw fees from the interest base before splitting.
      uint256 _interestNetOfFees = _expInterest - _pendingFees;
      // Total principal used for the pro-rata split:
      // IdleCDO TVL (which excludes APR0 requested principal) + APR0 principal bucket.
      uint256 _totalPrincipalForSplit = _tvl + _principal;
      if (_totalPrincipalForSplit != 0) {
        // APR0 users get a pro-rata share of realized interest.
        uint256 _apr0InterestGross = _interestNetOfFees * _principal / _totalPrincipalForSplit;
        if (_apr0InterestGross != 0) {
          // Same fee model as normal withdraw interest.
          uint256 _apr0Fee = _apr0InterestGross * _cdo.fee() / FULL_ALLOC;
          _apr0NetInterest = _apr0InterestGross - _apr0Fee;
          _adjPendingWithdrawFees += _apr0Fee;
          _expInterest -= _apr0NetInterest;
        }
      }
    }

    // Finalize one-epoch APR0 interest for current epoch only.
    if (_apr0NetInterest != 0) {
      // Funds owed to withdraw requesters increase by APR0 net interest.
      pendingWithdraws += _apr0NetInterest;
      // Save per-epoch net rate; each APR0 request accrues exactly once on its request epoch.
      apr0RateByEpoch[epochNumber] = (_apr0NetInterest * 1e18) / _principal;
    }
    // Close current APR0 bucket so it cannot accrue again on later stopEpoch calls.
    apr0TotalPrincipal = 0;
  }

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
      _apr0User.principalEpoch = epochNumber;
    }
    _apr0User.principal += _amount;
    // Epoch-level APR0 principal used only to compute stopEpoch APR0 pro-rata interest.
    apr0TotalPrincipal += _amount;
  }
