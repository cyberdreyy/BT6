### Title
Minimum-fee validation lets vault creators zero out the protocol's performance fee by supplying a dust management fee - (File: contracts/IdleCreditVaultFactory.sol)

### Summary
`IdleCreditVaultFactory._checkMinimumFees` is meant to guarantee the protocol earns a minimum fee on every vault deployed through the factory, mirroring the `takerFee + makerFee >= minNetFee` invariant in the external report. The check is a disjunction:

```solidity
function _checkMinimumFees(CreditVaultParams memory cvParams) internal pure {
  if (cvParams.fees < MIN_PERFORMANCE_FEE && cvParams.managementFee < MIN_MANAGEMENT_FEE) revert FeesTooLow();
}
``` [1](#0-0) 

So any `CreditVaultParams` with `managementFee >= MIN_MANAGEMENT_FEE (500)` is accepted even when `fees == 0`. The treasury's revenue share is applied via the global `feeSplit` to the performance `fee` configured in `cv.setFeeParams(par.feeReceiver, par.fees, feeSplit, par.managementFee)`, while `managementFee` accrues to the creator-chosen `feeReceiver` [2](#0-1) . A fee pair of `(fees = 0, managementFee = 500)` passes the guard yet leaves the treasury's split of performance fees at zero — exactly the "fee pair that should be rejected is accepted" failure mode, letting a creator run a vault that pays no protocol performance fee.

### Finding Description
`deployCreditVault` and `deployRevolvingCreditVault` are permissionless: any EOA supplies `CreditVaultParams` including `feeReceiver`, `fees`, and `managementFee` [3](#0-2) . Both paths gate on `_checkMinimumFees`, which requires only that *one* of the two fee parameters meets its individual floor. Because `managementFee` satisfies the check on its own, the creator can set `fees = 0` (and `feeReceiver = attacker`) so the `feeSplit`-based treasury share — the protocol's actual per-vault revenue — is nil. The test suite itself codifies the acceptance of `(fees = 0, managementFee = 500)` [4](#0-3) , confirming the guard behaves as written. No other guard recovers the treasury share: `feeSplit` is applied on top of `fees`, so `fees = 0` means zero protocol revenue regardless of `feeSplit` [5](#0-4) . The revolving-vault path is equally exposed (`_checkMinimumFees` at line 133) [6](#0-5) .

### Impact Explanation
The protocol's minimum-fee invariant is broken: a creator deploys a fully functional credit vault while the treasury receives 0% of yield. On a vault managing `N` underlying at `apr` APR, the protocol loses `N * apr * MIN_PERFORMANCE_FEE / FULL_ALLOC * feeSplit / FULL_ALLOC` per epoch (e.g. ~2.5% of gross interest at `DEFAULT_FEE_SPLIT = 50_000` [7](#0-6) ), for the vault's entire lifetime, since `setFeeParams` post-deploy is owner-gated and the factory hands ownership to treasury with the zero-fee config already set [8](#0-7) .

### Likelihood Explanation
Deployment is permissionless and the bypass requires only choosing `(fees = 0, managementFee >= 500)` — no privileged role, no timing, no capital. Every creator is economically incentivized to minimize the performance fee and route `managementFee` to their own `feeReceiver`.

### Recommendation
Enforce the protocol-earning leg independently rather than accepting either minimum: require `cvParams.fees >= MIN_PERFORMANCE_FEE` unconditionally (management fee is the creator's own revenue and should not count toward the protocol floor), or compute the treasury's effective share and check `fees * feeSplit / FULL_ALLOC >= MIN_PROTOCOL_FEE`. Apply the same fix to both `deployCreditVault` and `deployRevolvingCreditVault` via `_checkMinimumFees`.

### Proof of Concept
Foundry-style PoC (extends the existing `IdleCreditVaultFactory.t.sol` harness):

```solidity
function testFeeBypassManagementFeeOnly() external {
  vm.warp(100 days);
  MockFactoryERC20 underlying = new MockFactoryERC20("Mock USDC", "mUSDC", 6);
  IdleCreditVaultFactory factory = _deployFactory();
  IdleCDOEpochVariant impl = new IdleCDOEpochVariant();

  IdleCreditVaultFactory.CreditVaultParams memory p = _makeCreditVaultParams(attacker);
  p.fees = 0;            // protocol performance fee bypassed
  p.managementFee = 500; // dust fee to creator's own feeReceiver passes the check
  p.implementation = address(impl);
  p.underlying = address(underlying);

  IdleCreditVaultFactory.AncillaryParams memory anc = IdleCreditVaultFactory.AncillaryParams({
    keyring: address(0), queueImplementation: address(0),
    prefundedDepositWindow: 0, writeOffImplementation: address(0)
  });

  vm.prank(attacker); // unprivileged creator
  factory.deployCreditVault(p, _makeStrategyData(address(new IdleCreditVault()),
    address(underlying), address(factory), "Std", 12e18), anc);

  // deployed cv has fee() == 0 -> treasury share (feeSplit * fee) is 0 forever
}
```

Uncertainty note: I could not fully read `_calculateManagementFee`/`setFeeParams` internals in `IdleCDOCreditVault.sol` to confirm whether `managementFee` is also split with the treasury; if it is split, the severity drops since treasury still earns `feeSplit` of the management fee. The guard's structure and the factory test intentionally allowing `fees = 0` still make the disjunctive minimum the strongest analog of the wrong fee-pair check.
