### Title
GET /v2/bridge_types/:BridgeName accessible to any authenticated role (no RequiresEditRole/RequiresRunRole guard), disclosing bridge URL and OutgoingToken secret - (File: core/web/router.go)

### Summary
`GET /v2/bridge_types/:BridgeName` is registered at [1](#0-0)  without any `auth.Requires*Role` wrapper, unlike sibling `POST/PATCH/DELETE /bridge_types*` routes which are wrapped with `auth.RequiresEditRole`. Any authenticated user, including the lowest-privilege `view` role, can call this endpoint and receive a `BridgeResource` containing the bridge's `URL` and `OutgoingToken` via `BridgeTypesController.Show` and `presenters.NewBridgeResource`.

### Finding Description
`v2Routes` mounts `bridge_types` routes under `authv2`, which only requires successful authentication (session or token) via `auth.Authenticate(...)`, not any particular role: [2](#0-1) . `bt.Show` and `bt.Index` are left unguarded while `Create`, `Update`, and `Destroy` require `auth.RequiresEditRole`. `BridgeTypesController.Show` looks up the bridge and returns it via `presenters.NewBridgeResource(bt)` with no role check inside the handler itself: [3](#0-2) . `NewBridgeResource` populates `OutgoingToken` directly from the stored `BridgeType.OutgoingToken` field (a plaintext secret persisted on creation) along with the bridge `URL`: [4](#0-3) . The `OutgoingToken` is a genuine secret generated at bridge creation (`utils.NewSecret(24)`) and stored in plaintext (unlike `IncomingToken`, which is hashed): [5](#0-4) . `auth.RequiresRunRole`/`RequiresEditRole` explicitly block `UserRoleView` from other sensitive routes, confirming `view` is intended to be the lowest, most restricted role: [6](#0-5) , but no equivalent check exists on `Show`/`Index`.

### Impact Explanation
A `view`-role session or API token (the least privileged authenticated role in Chainlink's RBAC model) can read any bridge's `URL` and plaintext `OutgoingToken`. This matches the Chainlink bounty impact class of "secret/credential disclosure" — exposure of bridge adapter configuration and an authentication secret to an unauthorized/low-privilege principal. This is a bridge configuration/credential disclosure, not fund movement or full node compromise, so the impact is scoped to bridge configuration secrecy rather than key material for signing.

### Likelihood Explanation
Trivial and fully repeatable: requires only a valid `view`-role session or API token (the minimum privilege obtainable by a legitimate low-trust operator user, not requiring admin/host access), and one `GET /v2/bridge_types/:BridgeName` (or `/v2/bridge_types`) request. No race conditions, timing, or special preconditions are needed.

### Recommendation
Wrap `authv2.GET("/bridge_types", ...)` and `authv2.GET("/bridge_types/:BridgeName", ...)` with `auth.RequiresEditRole` (or a new `RequiresViewRoleWithRedaction` variant) at core/web/router.go:269 and 271, consistent with the other bridge mutation routes; alternatively, redact `OutgoingToken` from `presenters.NewBridgeResource` for non-edit/admin roles.

### Proof of Concept
Go handler-level integration test plan (mirroring `core/web/bridge_types_controller_test.go`):
1. Create an app via `cltest.NewApplication`, create a bridge with `app.BridgeORM().CreateBridgeType` (has known `OutgoingToken`).
2. Create a user/session with `clsessions.UserRoleView` (see how `cltest` builds HTTP clients with specific roles, e.g. `app.NewHTTPClient(&user)` where user.Role = UserRoleView).
3. `GET /v2/bridge_types/<bridgeName>` using the view-role client.
4. Assert response status is `200 OK` (currently succeeds) and response JSON `data.attributes.outgoingToken` equals the bridge's known `OutgoingToken` and `data.attributes.url` equals the bridge URL — proving the secret is exposed to a `view` user.
5. Contrast with `POST /v2/bridge_types` using the same view-role client and assert `401/403`, confirming inconsistent enforcement between mutating and read endpoints.

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
