### Title
Missing owner authentication and per-owner quota enforcement in confidential-relay `HandleJSONRPCUserMessage` allows unlimited DON execution via request ID rotation - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

### Summary
`HandleJSONRPCUserMessage` in the confidential-relay handler performs no signature/owner verification and no per-owner quota check before fanning the request out to the entire DON. The only gate on a new request is a request-ID collision check, which is trivially bypassed by using a fresh `req.ID` on every call, letting any caller repeatedly trigger full DON execution with no cost accounting tied to an authenticated identity.

### Finding Description
`HandleJSONRPCUserMessage` only validates the length/emptiness of `req.ID`, then calls `newActiveRequest` and `fanOutToNodes`: [1](#0-0) 

`newActiveRequest` rejects only an exact duplicate `req.ID` already tracked in `h.activeRequests`; it performs no owner/sender extraction, no signature verification, and no lookup into any per-owner rate limiter or quota store: [2](#0-1) 

The handler does define rate limiters, but they are exclusively for DON member nodes replying back to the gateway (`globalNodeRateLimiter`, `perNodeRateLimiters`, keyed by `nodeAddr`), enforced only in `HandleNodeMessage`, not on the inbound user request path: [3](#0-2) [4](#0-3) 

`activeRequest.addResponseForNode` (the function named in the question) is likewise scoped to deduplicating a single DON node's response inside one already-admitted request — it keys on `nodeAddr`, not on any verified caller/owner identity, and has nothing to do with ingress quota: [5](#0-4) 

`fanOutToNodes` is invoked unconditionally after `newActiveRequest` succeeds, sending the request to every member of the DON: [6](#0-5) 

This contrasts with other gateway handlers in the same codebase that do implement an owner-scoped authorization/quota step before dispatch, e.g. the v2 HTTP trigger handler's `authorizeRequest` and `checkRateLimit` calls prior to sending to nodes: [7](#0-6) 

Because the confidential-relay handler has no equivalent step, an attacker can send JSON-RPC requests with an arbitrary, unique `req.ID` on every call (any string ≤200 chars not already active) and trigger a full DON fan-out (`don.SendToNode` to every member) each time, with no verified owner identity ever recorded or checked against a quota.

### Impact Explanation
Every accepted request causes a fan-out send to all DON members and consumes DON node execution resources (`fanOutToNodes`), plus gateway resources tracking `activeRequests` until timeout/grace/expiry. Since there is no per-owner authentication or quota gate, an unprivileged internet client can generate unlimited billable/attributable DON executions by rotating `req.ID`, matching the "unpaid/unauthorized DON execution beyond the caller's entitlement" impact class (rate limit / quota bypass, High).

### Likelihood Explanation
No credentials, keys, or privileged access are required beyond being able to reach the gateway's JSON-RPC user-message endpoint for the confidential-relay method — the same reachable entrypoint the question specifies. The only "check" (`req.ID` uniqueness) is defeated by simply using a new ID string per request, which is a one-line change to any request generator, making this fully repeatable and low-effort.

### Recommendation
Add an owner-authentication step (verify a signature or JWT bound to `req` and extract a stable owner/sender identity) in `HandleJSONRPCUserMessage` before `newActiveRequest`/`fanOutToNodes`, and enforce a per-owner (not per-request-ID, not per-node) rate limiter/quota keyed on that verified identity — mirroring the `authorizeRequest`/`checkRateLimit` pattern already used in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`. Reject or queue requests exceeding the owner's quota prior to any `don.SendToNode` call.

### Proof of Concept
Handler-level Go test plan (in `core/services/gateway/handlers/confidentialrelay/handler_test.go` style):
1. Construct a `handler` via `NewHandler` with a mocked `gwhandlers.DON` (`SendToNode` mock) and a small `donConfig.Members` set.
2. Send N `jsonrpc.Request[json.RawMessage]` calls to `HandleJSONRPCUserMessage`, each with a distinct random `req.ID` and no signature/auth payload attached, all "from" the same simulated externally-owned key (no owner field is even threaded through, so this is implicit).
3. Assert that `don.SendToNode` is invoked for every one of the N requests (i.e., `N * len(Members)` total sends), with no error returned for request N+1 despite exceeding any reasonable owner-level quota.
4. Assert (negative check) that there is no rate-limiter or quota structure keyed on an owner/signer value anywhere in `handler` — only `globalNodeRateLimiter` and `perNodeRateLimiters` keyed by DON node address exist, confirmed by inspecting `h.perNodeRateLimiters` keys equal `donConfig.Members` addresses, not any caller identity.
5. Expected result confirming the bug: all N fan-outs succeed with no quota-related rejection, demonstrating unbounded DON execution triggerable by ID rotation alone.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
