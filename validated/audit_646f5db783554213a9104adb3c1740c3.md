### Title
FinishWebAuthnLogin discards updated credential from ValidateLogin, permanently disabling WebAuthn sign-count clone/replay detection - (File: core/sessions/webauthn.go)

### Summary
`FinishWebAuthnLogin` calls `webAuthn.ValidateLogin(waUser, sessionData, credential)` but discards the returned updated `*webauthn.Credential` (which contains the authenticator's new `SignCount`), keeping only `err`. Because the updated sign count is never written back to the `web_authns.public_key_data` column, the stored credential's sign count never advances, so a captured assertion can be replayed indefinitely without ever tripping the WebAuthn clone-detection check.

### Finding Description
The login flow is: `SessionsController.Create` (core/web/sessions_controller.go:56) → `orm.CreateSession` (core/sessions/localauth/orm.go:144) → `sessions.FinishWebAuthnLogin` (core/sessions/webauthn.go:133-162). In `FinishWebAuthnLogin`, the stored credential is loaded via `duoWebAuthUserFromUser`/`LoadWebAuthnCredentials`, which unmarshals `WebAuthn.PublicKeyData` from the `web_authns` table (core/sessions/webauthn.go:208-218, core/sessions/localauth/orm.go:130-139). The library call:
```go
_, err = webAuthn.ValidateLogin(waUser, sessionData, credential)
return err
```
at core/sessions/webauthn.go:160-161 only propagates `err`. The go-webauthn library's `ValidateLogin` returns an updated `*webauthn.Credential` with the authenticator-reported sign counter so callers can persist it and detect cloned authenticators (when a replayed assertion presents a sign count ≤ the last stored value). Since the updated credential is discarded (`_`) and there is no subsequent call in `CreateSession` or elsewhere in `core/sessions/localauth/orm.go` that updates `web_authns.public_key_data` after a successful login (only `AddCredentialToUser`, used during registration, writes to that column), the stored sign count is frozen at its registration-time value forever. Consequently `ValidateLogin`'s clone-detection comparison (`storedSignCount vs. newSignCount`) is effectively neutralized on every login, since storedSignCount never changes and only needs to be non-decreasing relative to itself, not relative to prior replayed attempts.

An attacker who captures one valid `protocol.CredentialAssertionResponse` payload (e.g., via XSS, a malicious browser extension, or MITM before TLS is established/pinned) can submit the identical `WebAuthnData` to `/sessions` repeatedly. Each time, `ValidateLogin` is passed the same stored credential (with stale sign count) and validates the (identical) signature and sign-count relationship successfully, minting a fresh session cookie every time.

### Impact Explanation
This is an authentication-bypass / credential-replay vulnerability: WebAuthn's core anti-cloning/anti-replay guarantee is defeated, allowing an attacker holding one captured MFA assertion to log in as the victim user repeatedly rather than only once. This matches Chainlink's "authentication bypass" bounty impact class, since it undermines a second authentication factor that node operators rely on to protect the node UI/API.

### Likelihood Explanation
Requires the attacker to first capture a single valid signed WebAuthn assertion for a target account (e.g. XSS in the operator UI, malicious browser extension, or a MITM before/without proper TLS). No operator/admin/database access is needed. Once captured, replay is straightforward and fully repeatable since the persisted sign count never changes across logins, so there is no diminishing window — the same captured request works indefinitely until the credential is revoked or the user's session/browser state changes.

### Recommendation
Persist the updated credential returned by `ValidateLogin` back to the `web_authns` table (update `public_key_data` with the new `SignCount`) after a successful login, and have `orm.CreateSession` update storage using the returned credential from `sessions.FinishWebAuthnLogin`, e.g. change `FinishWebAuthnLogin` to return `(*webauthn.Credential, error)` and add an ORM method (e.g., `UpdateWebAuthn`) called on success.

### Proof of Concept
1. In `core/sessions/localauth/orm_test.go` extend `TestORM_WebAuthn`: register a credential with `SignCount: N` via `AddCredentialToUser`.
2. Perform a full `BeginWebAuthnLogin`/`FinishWebAuthnLogin` cycle using a test authenticator that increments and signs with `SignCount: N+1`, succeeding once.
3. Query `orm.GetUserWebAuthn` afterward and assert the stored `SignCount` is still `N` (unchanged), proving no persistence occurs.
4. Replay the exact same `sr.WebAuthnData` (same signature, same `SignCount: N+1`) a second time through `CreateSession`/`FinishWebAuthnLogin` and assert it again returns `nil` error (login succeeds), demonstrating unlimited replay of a single captured assertion. func FinishWebAuthnLogin(user User, uwas []WebAuthn, sr SessionRequest) error {
	webAuthn, err := webauthn.New(&webauthn.Config{
		RPDisplayName: "Chainlink Operator",       // Display Name
		RPID:          sr.WebAuthnConfig.RPID,     // Generally the domain name
		RPOrigin:      sr.WebAuthnConfig.RPOrigin, // The origin URL for WebAuthn requests
	})

	if err != nil {
		return pkgerrors.Wrapf(err, "failed to create webAuthn structure with RPID: %s and RPOrigin: %s", sr.WebAuthnConfig.RPID, sr.WebAuthnConfig.RPOrigin)
	}

	credential, err := protocol.ParseCredentialRequestResponseBody(strings.NewReader(sr.WebAuthnData))
	if err != nil {
		return err
	}

	userLoginIndexKey := user.Email + "-authentication"
	sessionData, err := sr.SessionStore.GetWebauthnSession(userLoginIndexKey)
	if err != nil {
		return err
	}

	waUser, err := duoWebAuthUserFromUser(user, uwas)
	if err != nil {
		return err
	}

	_, err = webAuthn.ValidateLogin(waUser, sessionData, credential)
	return err
}

func (o *orm) GetUserWebAuthn(ctx context.Context, email string) ([]sessions.WebAuthn, error) {
	var uwas []sessions.WebAuthn
	err := o.ds.SelectContext(ctx, &uwas, "SELECT email, public_key_data FROM web_authns WHERE LOWER(email) = $1", strings.ToLower(email))
	if err != nil {
		return uwas, err
	}
	// In the event of not found, there is no MFA on this account and it is not an error
	// so this returns either an empty list or list of WebAuthn rows
	return uwas, nil
}

func (sc *SessionsController) Create(c *gin.Context) {
	defer sc.App.WakeSessionReaper()
	ctx := c.Request.Context()
	sc.App.GetLogger().Debugf("TRACE: Starting Session Creation")

	session := sessions.Default(c)
	var sr clsessions.SessionRequest
	if err := c.ShouldBindJSON(&sr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("error binding json %w", err))
		return
	}

	// Does this user have 2FA enabled?
	userWebAuthnTokens, err := sc.App.AuthenticationProvider().GetUserWebAuthn(ctx, sr.Email)
	if err != nil {
		sc.App.GetLogger().Errorf("Error loading user WebAuthn data: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// If the user has registered MFA tokens, then populate our session store and context
	// required for successful WebAuthn authentication
	if len(userWebAuthnTokens) > 0 {
		sr.SessionStore = sc.sessions
		sr.WebAuthnConfig = sc.App.GetWebAuthnConfiguration()
	}

	sid, err := sc.App.AuthenticationProvider().CreateSession(ctx, sr)
	if err != nil {
		jsonAPIError(c, http.StatusUnauthorized, err)
		return
	}
