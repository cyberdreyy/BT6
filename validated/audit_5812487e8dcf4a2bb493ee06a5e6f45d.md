### Title
Stale confirmations from a deleted member are still counted toward quorum, allowing execution with fewer live-member confirmations than `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges outstanding `requests`/`confirmations` entries for requests the removed member *created* (`r.member == member`), but never scans other requests to strip that member's confirmation string from their `confirmations` set. Because `confirm` only checks `confirmations.len() as u32 + 1 >= self.num_confirmations` without re-validating that every entry in the set is still a current member, a stale confirmation from an already-removed member can be counted toward quorum, letting a request execute with fewer live members having actually confirmed than `num_confirmations` requires.

### Finding Description
The invariant that should hold is: at the moment a request executes, `|{ m in confirmations[request_id] : m ∈ current members }| == |confirmations[request_id]| == num_confirmations` (i.e. every counted confirmer is a live member). The code breaks this equality.

`confirm()` bumps and checks quorum purely off the size of the stored `HashSet<String>` for the request: [1](#0-0) 

`delete_member()` only removes requests where the removed member is the *requester* (`r.member == member`); it does not walk other requests' confirmation sets to remove that member's confirmation string where they acted as a *confirmer* rather than requester: [2](#0-1) 

Concretely: member A creates request R (`add_request`). Member B (holding the restricted function-call key installed by `add_member` with `MULTISIG_METHOD_NAMES`, i.e. only `add_request,delete_request,confirm,add_and_confirm_request`) calls `confirm(R)`; B's identity string is inserted into `confirmations[R]`. Separately, the multisig quorum executes a `DeleteMember { member: B }` action, removing B from `self.members` and deleting its access key — but since B did not create R, `delete_member` never touches `confirmations[R]`, so `{B}` remains stored there. Later, two other live members confirm R via ordinary `confirm` calls; the second call sees `confirmations.len() == 2` (B + one live member) `+ 1 == 3 >= num_confirmations (3)` and executes the request via `remove_request` + `execute_request`, even though only 2 currently-live members actually confirmed.

`assert_valid_request` and `current_member` only validate the *caller* of the current `confirm` invocation is a member; they never re-validate the *existing* entries already stored in the confirmations set: [3](#0-2) [4](#0-3) 

No other guard (`assert_self_request`, `assert_one_action_only`) checks confirmer liveness either, so the stale entry silently inflates the quorum count.

### Impact Explanation
This directly matches the Critical category "a multisig request executed below `num_confirmations` live members." Any request queued against the multisig — including `Transfer`, `FunctionCall`, `AddKey`/full-access-key grants, or further `DeleteMember`/`AddMember` actions — can be pushed to execution with one fewer genuine live confirmer than configured, using only the standard restricted `confirm` method every function-call member already has access to. This directly moves NEAR (or grants a full access key that can move NEAR) out of the multisig account controlled by fewer than the configured threshold of live signers, undermining the entire security guarantee of the multisig.

### Likelihood Explanation
The precondition is simply: a member confirms a request they did not create, and is later removed via a normal `DeleteMember` action (itself a routine multisig operation, e.g. rotating access keys), while that earlier request is still pending. This is a plausible, low-cost, ordinary operational sequence for any multisig with churn in its member/key set (which is a first-class supported feature via `AddMember`/`DeleteMember`), requiring no special privileges beyond the restricted function-call key that `add_member` installs, and is fully repeatable across requests and accounts.

### Recommendation
When counting confirmations toward quorum in `confirm()` (or when deleting a member in `delete_member()`), filter `confirmations[request_id]` to only entries still present in `self.members`, either by re-validating membership of every stored confirmer at count time, or by having `delete_member` iterate all `confirmations` entries (not just requests authored by the removed member) and strip the removed member's string from every set.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
