### Title
Any single shareholder/delegator can permanently DoS `vesting::distribute` (and `staking_contract::distribute_internal`) by opting out of direct coin transfers - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
Both `vesting::distribute` and `staking_contract::distribute_internal` withdraw the entire pool's unlocked stake in one call and then loop over *all* shareholders/recipients, pushing funds to each via `aptos_account::deposit_coins`. That helper aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has disabled direct coin transfers and is not already registered for the coin type. Because Move transactions are atomic and there is no per-recipient isolation (no try/catch, no skip-and-continue), a single unprivileged shareholder/delegator who calls `aptos_account::set_allow_direct_coin_transfers(false)` can make the shared distribution call abort every time, blocking payout to *every other* shareholder as well.

### Finding Description
`vesting::distribute` ( [1](#0-0) ) withdraws all currently-withdrawable stake once via `withdraw_stake`, then iterates every shareholder in the vesting pool and calls `aptos_account::deposit_coins(recipient_address, share_of_coins)` for each one in a single `for_each_ref` loop.

`aptos_account::deposit_coins` ( [2](#0-1) ) asserts `can_receive_direct_coin_transfers(to)` when the recipient isn't already registered for the coin, aborting with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` otherwise. Any account holder can flip this flag off at any time via the public entry `set_allow_direct_coin_transfers`, and this ability is completely unprivileged and independent of the vesting/staking-contract admin, operator, or other shareholders.

Since Move aborts revert the whole transaction, any single shareholder who opts out of direct transfers (accidentally or maliciously) causes `distribute()`/`distribute_many()` to abort for the *entire* vesting contract, not just that shareholder's share. The same shared-loop-then-deposit pattern exists in `staking_contract::distribute_internal`, which loops over `distribution_pool.shareholders()` and deposits to each including the operator/beneficiary ( [3](#0-2) ), and this function is also invoked internally by `unlock_stake`, `request_commission`, `switch_operator`, and `update_commision` before they can proceed ( [4](#0-3) , [5](#0-4) ), meaning a single opted-out recipient can also block the staker/operator from unlocking, requesting commission, or switching operators.

This is conceptually the same bug class as the external report: a shared payout path assumes every recipient can always receive the native asset, and the lack of a fallback/guard for a recipient that can't (or chooses not to) receive it breaks the payout path for everyone sharing that flow — the difference here being it's an intentional, permissionless "opt-out" flag rather than a missing `receive()`.

### Impact Explanation
This breaks the "unlock/reactivate/withdraw/distribute must not strand value" invariant for vesting and staking-contract flows. A single shareholder in a `VestingContract` (which can have many independent shareholders sharing one pool and one distribution transaction) can permanently freeze reward and vested-grant distribution for all other shareholders, and can freeze admin's ability to `terminate_vesting_contract` (which itself calls `distribute` first) or `admin_withdraw` after termination — since `distribute` is called unconditionally inside `terminate_vesting_contract` ( [6](#0-5) ). Similarly, in `staking_contract`, one distribution-pool member (staker, operator, or a beneficiary who previously received a partial unlock) opting out can block the staker's `unlock_stake`, `switch_operator`, `update_commision`, and `request_commission`. Funds already withdrawn from the stake pool but undistributed are effectively locked in the vesting/staking-contract account with no other administrative or per-recipient bypass path in the code, matching the "permanent lock or non-recoverable loss of claim rights" impact criterion.

### Likelihood Explanation
High: `set_allow_direct_coin_transfers` is a public, unprivileged entry function callable by any account holder at any time, requiring no special role, and does not require coordination with the vesting admin, staker, or operator. Any shareholder wanting to grief co-shareholders (or an account that simply forgot it had toggled this setting off) can trigger the condition trivially and it persists until the same account re-enables transfers.

### Recommendation
Do not let a single recipient's registration/opt-out state block payouts to others sharing the same pool:
- In `vesting::distribute` and `staking_contract::distribute_internal`, wrap each per-recipient deposit so failures for one shareholder don't abort the loop (e.g., check `coin::is_account_registered` / `can_receive_direct_coin_transfers` up front and skip/queue that shareholder's share into a claimable balance instead of pushing it), or
- Add a pull-based claim function so each shareholder/recipient withdraws their own share independently instead of relying on one shared push-based transaction, isolating one account's opt-out from affecting others.

### Proof of Concept
1. Admin creates a vesting contract with shareholders A and B via `create_vesting_contract`.
2. Attacker (shareholder A) calls `aptos_account::set_allow_direct_coin_transfers(false)` from their own account — fully permissionless, no special role required.
3. Time passes; rewards/vested tokens accumulate and become withdrawable.
4. Anyone (including B or admin) calls `vesting::distribute(contract_address)`.
5. The loop reaches shareholder A; `aptos_account::deposit_coins` calls `can_receive_direct_coin_transfers(A)` which returns false, causing `assert!` to abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. The entire `distribute` transaction reverts, so shareholder B receives nothing despite B being fully cooperative, and this state persists indefinitely as long as A leaves the opt-out flag set — including blocking `terminate_vesting_contract`/`admin_withdraw` which internally call `distribute` first.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
