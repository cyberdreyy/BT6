### Title
Prefunded queue deposits lose the entire epoch interest they generated — shares minted at post-stop price for principal only - ([File: contracts/IdleCDOEpochVariantPrefunded.sol](contracts/IdleCDOEpochVariantPrefunded.sol))

### Summary
In the prefunded-queue flow, user deposits are transferred to the borrower *during* the running epoch via `IdleCDOEpochQueue.processDepositsToBorrower()`, so that principal earns yield for the whole epoch. However, when the epoch is settled, `_afterStopEpochWithDuration()` mints AA shares to the queue with `_mintSharesAtCurrPrice(_prefunded, _queue, AATranche)` — i.e. at the *post-stop* price, which already embeds the epoch interest. Depositors therefore receive shares worth only their original principal (`epochPrice = _prefunded / _prefundedMinted`), exactly like the Carousel rollover bug where users were minted shares for `queue[index].assets` instead of their profit-inclusive entitled amount. The interest their prefunded money produced is redistributed to pre-existing AA holders instead of the depositors who funded it.

### Finding Description
- `IdleCDOEpochQueue.processDepositsToBorrower()` moves `epochPendingDeposits` to the borrower while the epoch is running (`IdleCDOEpochQueue.sol:149-179`), so prefunded principal participates in lending for the entire remaining epoch.
- At `stopEpochWithDuration`, `IdleCDOEpochVariantPrefunded._afterStopEpochWithDuration()` calls `_mintSharesAtCurrPrice(_prefunded, _queue, AATranche)` and stores `epochPrice = _prefunded * ONE_TRANCHE / _prefundedMinted` (`IdleCDOEpochVariantPrefunded.sol:72-88`, `IdleCDOEpochQueue.sol:270`).
- Because the mint happens *after* `_updateAccounting()` has already priced in the epoch gain, each minted share is worth ~`priceAA(post-stop)`. The queue's implied price is exactly the post-stop price, so `claimDepositRequest` returns shares redeemable for `_prefunded` underlyings — principal only.
- Compare with the correct treatment in `depositDuringEpoch` (`IdleCDOEpochVariant.sol:719-725`): a mid-epoch depositor is minted `(_amount + trancheInterest) * _trancheTotSupply / expectedFinal`, i.e. principal **plus its prorated share of epoch interest**. Prefunded depositors, who committed funds for strictly *longer* than a mid-epoch depositor, receive strictly *less* — zero interest.
- The missing interest is not burned; it inflates `priceAA`/`expectedEpochInterest` accrual to incumbent AA holders, who capture yield generated by capital they never supplied.

### Impact Explanation
Direct, quantifiable loss of yield for every prefunded depositor: `loss ≈ prefundedAmount * apr * timePrefunded / YEAR`, up to a full epoch's interest at the pool APR. For a 1M USDC prefunded deposit at 10% APR prefunded for the whole epoch, the depositor forfeits ~the entire epoch interest while old AA holders receive it. Broken invariant: fair mint/burn — shares are minted at a price that already includes interest the new capital itself produced.

### Likelihood Explanation
Certain whenever the prefunded queue is used and the epoch is profitable (the normal case). Only requires an honest manager calling `processDepositsToBorrower()` then `stopEpochWithDuration`. No guard prevents it: `checkPrefunding` only checks `defaulted || skipDefaultCheck || priceAA == 0`. Note the flow is intentionally written to mint at post-stop price so prefunded deposits can still join AA on default — the interest loss is the unhandled side effect in the non-default path.

### Recommendation
Mint prefunded shares using the pre-gain price, i.e. credit the prefunded amount with its share of epoch interest before minting — analogous to `depositDuringEpoch`'s `(_amount + trancheInterest) / priceEnd` formula. Concretely, compute `shares = _prefunded * _trancheTotSupply / expectedFinalPrefundedBasis` where the basis uses lastNAV (pre-interest) plus the prefunded deposit's own interest, or snapshot the AA price at prefunding time (`processDepositsToBorrower`) and mint at that price at stop.

### Proof of Concept
Foundry fork scenario (mirroring `test/foundry/IdleCDOEpochQueue.t.sol` prefunded tests):

```solidity
// Epoch N running, AA price = 1.0, apr = 10%
// user deposits into AA queue during running epoch
queue.requestDeposit(1_000e6); // userDepositsEpochs[user][N+1] = 1_000e6

// manager prefunds mid-epoch
vm.prank(manager);
queue.processDepositsToBorrower(); // 1_000e6 -> borrower

// epoch ends profitably: borrower repays principal + interest
// stopEpochWithDuration -> _updateAccounting -> priceAA = 1.05
// _afterStopEpochWithDuration mints shares at priceAA = 1.05
vm.prank(manager);
cdoEpoch.stopEpochWithDuration(...);

// queue epochPrice = 1.05 -> user claims shares worth 1_000e6 only
vm.prank(user);
queue.claimDepositRequest(epoch);
uint256 shares = AAtranche.balanceOf(user);
// redeemable value == 1_000e6, but the deposit earned ~interest
// assert shares * cdoEpoch.virtualPrice(AA) / 1e18 < 1_000e6 + userExpectedInterest
```

Expected: user's claimable value equals principal only; the interest accrued on the prefunded 1,000 USDC during the epoch is captured by incumbent AA holders via the higher `priceAA`.
