### Title
Global un-namespaced request-ID registry lets any authorized caller squat/collide another user's in-flight `requestID`, causing denial-of-service and response-routing confusion in the HTTP trigger gateway handler - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
The Chakra bug is caused by a shared, unscoped `nonce_manager` mapping keyed only by `msg.sender`/`from_address` that is mutated by any external caller, so nonces computed by two independent components (handler and settlement contracts) desynchronize and different users'/handlers' identifiers collide. The Chainlink gateway's HTTP trigger capability handler has the same root-cause shape: an identifier chosen entirely by the (unprivileged, per-request) caller — the JSON-RPC `req.ID` — is used as the sole key into a single global, un-namespaced map (`h.callbacks`) shared across *every* workflow and workflow owner served by the gateway node, with no server-side scoping by workflow ID/owner.

### Finding Description
`httpTriggerHandler` stores in-flight requests in one process-wide map keyed purely by the caller-supplied `requestID`: [1](#0-0) 

`setupCallback` only checks for a *global* collision on that string, not a (workflowID, requestID) or (workflowOwner, requestID) tuple: [2](#0-1) 

`validateRequestID` only rejects empty IDs or IDs containing `/`; it performs no per-owner scoping and does not require unpredictability (e.g., a UUID) — the ID space is fully attacker-chosen and can be as small as `"1"`: [3](#0-2) 

Because authorization (`authorizeRequest`) only proves the caller controls *some* registered workflow, not that its `requestID` is unique across the whole gateway, any authenticated workflow owner can pick the same `requestID` a victim (a different, unrelated workflow owner) is concurrently using. When the collision happens, `setupCallback` rejects the second submitter with a `Conflict` error: [4](#0-3) 

Node responses are also routed purely by this same un-namespaced key in `HandleNodeTriggerResponse`, with correctness relying entirely on `resp.ID` matching the registered map entry and the responding node belonging to the expected shard: [5](#0-4) 

This mirrors the Chakra flaw precisely: a shared counter/identifier namespace that is supposed to uniquely correlate a caller's request end-to-end is instead a single flat mapping that any caller (not just the legitimate owner of that ID) can write into, causing cross-caller interference. The confidential relay handler exhibits the identical pattern (`h.activeRequests` keyed only by `req.ID` with no owner scoping): [6](#0-5) 

### Impact Explanation
An unprivileged caller who is authorized for *their own* workflow can deliberately pick `requestID` values that are likely to be used by other, unrelated workflow owners (e.g. sequential/simple IDs, or IDs learned/guessed from other tenants), and hold them open across the `MaxTriggerRequestDurationMs` window. Any legitimate request from a different owner using the same ID during that window is rejected with `jsonrpc.ErrConflict`, denying that owner's workflow execution — a direct availability impact scoped to the internet-facing gateway trigger path, achievable by any authenticated-but-unrelated caller with no privilege escalation required. This is the same class of impact the external report flags as high severity: a shared, caller-mutable identifier namespace intended to isolate per-user/per-handler state instead allows one party to disrupt another party's identifier space.

### Likelihood Explanation
Likelihood is high for the DoS variant: it requires no special access beyond being able to submit any authorized HTTP trigger request (which is the gateway's normal, internet-facing entry point), and the `requestID` values are entirely user-controlled and validated only for emptiness and absence of `/`.

### Recommendation
Scope the `callbacks` (and analogous `activeRequests`) map key by an unforgeable, owner/workflow-bound tuple instead of the raw caller-supplied `requestID`, e.g. key by `(authorizedWorkflowOwner, workflowID, requestID)` or by the already-computed `executionIDWithTriggerIndex` (which incorporates the workflow ID), so that request-ID collisions can only occur within a single workflow/owner's own namespace, never across owners.

### Proof of Concept
1. Register two unrelated workflows `W1` (owner A) and `W2` (owner B) on the gateway.
2. Owner A sends `HandleUserTriggerRequest` with `req.ID = "1"` for `W1`; the callback is registered in the global `h.callbacks["1"]` map (see `setupCallback`, [7](#0-6) ).
3. Before A's request completes, owner B — with valid auth only for `W2` — sends `req.ID = "1"` for `W2`. `setupCallback` finds `h.callbacks["1"]` already present and rejects B's own request with `jsonrpc.ErrConflict`, purely due to the ID collision with A's unrelated workflow, even though B never had any relationship to `W1`. This demonstrates that the identifier space intended to be per-request is actually shared and mutable across unrelated tenants, exactly like the Chakra `nonce_manager[from_address]` being globally mutable across unrelated handlers.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// Build one response aggregator per shard the workflow is assigned to.
	assigned := h.workflowMetadataHandler.WorkflowShards(workflowID)
	if len(assigned) == 0 {
		// this shouldn't happen because we checked it in authorizeRequest()
		h.handleUserError(ctx, requestID, jsonrpc.ErrInternal, fmt.Sprintf("Workflow %s is not assigned to any DONs", workflowID), callback)
		return nil, errors.New("workflow is not assigned to any shards")
	}

	aggregators := make(map[string]*aggregation.IdenticalNodeResponseAggregator, len(assigned))
	for _, shard := range assigned {
		// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
		threshold := (len(shard.members)+shard.f)/2 + 1
		agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
		if err != nil {
			return nil, errors.New("failed to create response aggregator: " + err.Error())
		}
		aggregators[shard.donID] = agg
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:            callback,
		requestStartTime:    requestStartTime,
		createdAt:           time.Now(),
		responseAggregators: aggregators,
		doneCh:              doneCh,
	}
	return doneCh, nil
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
