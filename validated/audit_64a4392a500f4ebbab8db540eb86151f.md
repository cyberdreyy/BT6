**Reasoning summary:**

`VMLogic::read_and_parse_account_id` reads the raw bytes once, and depending on `config.limit_config.account_id_validity_rules_version` either wraps them unvalidated (`AccountId::new_unvalidated`, for V0/V1) or validates+parses them (V2). [1](#0-0) 

The exact same `AccountId` value (same underlying bytes, no re-derivation/transformation) is what's used for the `sir` gas-accounting check and passed straight into `create_action_receipt`, i.e. it is the value stored as `receiver_id` on the outgoing receipt. [2](#0-1) 

When the receipt is later dispatched, `validate_receipt` re-validates `receiver_id` with `AccountId::validate`, and the code comment explicitly documents that this re-check exists specifically to catch the legacy bypass in `read_and_parse_account_id`. [3](#0-2) 

Critically, none of these validation paths ever transform or reinterpret the byte string into a *different* account id — they only accept or reject the same literal string. `account_id_validity_rules_version`/`PROTOCOL_VERSION` is resolved once per chunk/block via `RuntimeConfigStore` and applied consistently to every node executing that block, so there is no scenario where "receiver used for gas accounting" and "receiver used by the executor" diverge to two different existing accounts for the same byte sequence — at worst, a receipt created via the legacy unvalidated path can later fail `validate_receipt`'s stricter check (receipt rejected/invalid), which is a known, intentionally-handled backward-compatibility case, not a receiver-identity confusion. Therefore there is no reachable authorization-escalation or fund-diversion path here. [4](#0-3)

    fn read_and_parse_account_id(&mut self, ptr: u64, len: u64) -> Result<AccountId> {
        let buf = get_memory_or_register!(self, ptr, len)?;
        self.result_state.gas_counter.pay_base(utf8_decoding_base)?;
        self.result_state.gas_counter.pay_per(utf8_decoding_byte, buf.len() as u64)?;

        let account_id_str = String::from_utf8(buf.into_owned()).map_err(|_| HostError::BadUTF8)?;

        match self.config.limit_config.account_id_validity_rules_version {
            near_primitives_core::config::AccountIdValidityRulesVersion::V0
            | near_primitives_core::config::AccountIdValidityRulesVersion::V1 =>
            {
                #[allow(deprecated)]
                Ok(AccountId::new_unvalidated(account_id_str))
            }
            near_primitives_core::config::AccountIdValidityRulesVersion::V2 => account_id_str
                .parse()
                .map_err(|_| VMLogicError::HostError(HostError::InvalidAccountId)),
        }
    }
