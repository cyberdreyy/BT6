### Title
Unauthenticated `/health` (and `/health.txt`) leaks raw internal error strings from health checks - ([File: core/web/health_controller.go])

### Summary
The `/health` and `/health.txt` endpoints are registered without any authentication middleware, and `HealthController.Health` always includes per-check error output (`err.Error()`) regardless of query parameters, unlike `Readyz` which gates detail behind `?full`. Any internal service's health-check error text (e.g. DB connectivity, RPC pool, pipeline runner errors) is echoed verbatim to any anonymous caller in JSON, HTML, or plaintext form.

### Finding Description
`healthRoutes` in `core/web/router.go` registers `GET /health` and `GET /health.txt` directly on the base `api` group, with no `auth.Authenticate(...)` wrapper, unlike `/v2/*` or `/debug/*` routes which require session/token/admin auth. [1](#0-0) 

`HealthController.Health` calls `checker.IsHealthy()` and, for every failing check, sets `output = err.Error()` unconditionally (no `full` query gate as in `Readyz`), then serializes these into the JSON API response, an HTML `<pre>` block via `WriteHTMLTo`, or plaintext via `writeTextTo`. [2](#0-1) 

Health checks are populated from arbitrary registered services (`HealthReporter.HealthReport()`), including the pipeline runner and any ORM/DB-backed service; whatever error text those components produce (which may include connection strings, hostnames, file paths, or other internal details depending on the underlying driver/library) is exposed as-is with no redaction or sanitization step in the controller. [3](#0-2) 

### Impact Explanation
This is unauthenticated disclosure of internal error content to any network-reachable caller, potentially including internal hostnames, file paths, or connection details embedded in error strings from DB/pipeline/service health checks — an information disclosure that aids further attacks (reconnaissance) against the node's internal infrastructure, matching a low/informational-to-medium disclosure impact class rather than direct fund/key compromise.

### Likelihood Explanation
No credentials or preconditions are required beyond network reachability to the node's web server (default installs expose this route unauthenticated), and any failing internal service surfaces its error text automatically and repeatably whenever a health check fails.

### Recommendation
Require the same treatment as `PublicReadyz`/`Readyz`: gate detailed per-check `Output` behind authentication (or remove it entirely from the unauthenticated `/health` response, keeping only aggregate status), and/or sanitize error strings before including them in the health payload so internal details (DSNs, hostnames, paths) are never echoed to anonymous callers.

### Proof of Concept
1. In `core/web/health_controller_test.go`, add a test using `mocks.Checker` where `IsHealthy()` returns `(false, map[string]error{"PipelineRunner": errors.New("dial tcp postgres://user:pass@internal-db-host:5432: connect refused")})`.
2. Build the app with `app.HealthChecker = healthChecker` (unauthenticated `NewHTTPClient`, no session/token set).
3. `GET /health` with `Accept: application/json`, `Accept: text/html`, and `Accept: text/plain` respectively.
4. Assert response status is `200`/`207` (no auth challenge/401), and that the response body for each content type contains the substring `postgres://user:pass@internal-db-host` — demonstrating the sensitive string is returned to an unauthenticated caller.

	switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEHTML, gin.MIMEPlain) {

		break // default

		}

		}
		return
	}

func (r *runner) HealthReport() map[string]error {
	runnerHealth := map[string]error{r.Name(): r.Healthy()}

	service, isService := r.btORM.(services.HealthReporter)
	if !isService {
		return runnerHealth
	}

	services.CopyHealth(runnerHealth, service.HealthReport())

	return runnerHealth
}
