### Title
Unauthenticated pprof/metrics debug routes exposed via `loopRoutes` on the node API listener - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the top-level `api` group with no `auth.Authenticate` wrapper and no role check, unlike every other route group (`debugRoutes`, `sessionRoutes`, `v2Routes`) which are explicitly gated by `auth.Authenticate(...)`. This leaves plugin-level pprof/metrics debug endpoints reachable by any unauthenticated HTTP client on the default node API port (`:6688`).

### Finding Description
In `NewRouter`, the shared `api` group only applies rate limiting and session middleware, not authentication: [1](#0-0) 

`debugRoutes` explicitly wraps `/debug/vars` with `auth.Authenticate(...)`: [2](#0-1) 

`v2Routes` wraps its debug/pprof group (`metricRoutes`) inside the `authv2` block, which requires `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`: [3](#0-2) [4](#0-3) 

By contrast, `loopRoutes` is called directly on the base `api` group with no authentication middleware whatsoever: [5](#0-4) [6](#0-5) 

`loopRoutes` registers `GET /plugins/:name/debug/pprof/*profile` (backed by `loopRegistry.pluginPPROFHandler`) and `POST /plugins/:name/debug/pprof/symbol`, mirroring the standard Go `net/http/pprof` handler behavior used elsewhere in `metricRoutes` (`pprof.Cmdline`, `pprof.Profile`, `pprof.Handler("heap")`, `pprof.Handler("goroutine")`, etc.), but for LOOP (Local Out-Of-Process) plugin processes. Since no session cookie, API token, or role check is required to reach these handlers, an unauthenticated client that can reach the node API listener can pull goroutine stacks, heap profiles, and CPU/execution traces for any named plugin, and potentially command-line data, directly.

### Impact Explanation
Exposing pprof-class debug endpoints without authentication allows extraction of process memory contents (heap dumps), goroutine stacks (which can contain in-flight secrets, keys, or credentials held in memory by plugin processes), and profiling data — a Critical server credential/key disclosure class impact matching the target's described exploit ("node memory, goroutine dumps or command lines containing key passwords").

### Likelihood Explanation
No credentials, session, or role are required — only network reachability to the node API port, satisfying the "unauthenticated HTTP client" attacker model exactly. The routes are always registered whenever `NewRouter` builds the engine (`loopRoutes(app, api)` is unconditional), making this reliably reachable and repeatable with a single unauthenticated `GET` request.

### Recommendation
Wrap `loopRoutes` registrations with the same `auth.Authenticate(...)` (and ideally `auth.RequiresAdminRole`) guard used for `debugRoutes`/`metricRoutes`, consistent with the stated invariant that debug endpoints must require the highest role and never be reachable unauthenticated.

### Proof of Concept
1. Build the router via `NewRouter` with a test `chainlink.Application` and no session/token in the request.
2. Send `GET /plugins/testplugin/debug/pprof/heap` and `GET /plugins/testplugin/debug/pprof/goroutine?debug=2` with no `Cookie` or `X-API-KEY`/`X-API-SECRET` headers.
3. Assert response status is `200` (profile data returned) rather than `401 Unauthorized`, contrasted with an equivalent request to `/v2/plugins/:name/debug/pprof` style endpoint under `authv2`/`metricRoutes`, which correctly returns `401` without credentials.
4. Repeat for `POST /plugins/testplugin/debug/pprof/symbol` and `GET /discovery`, confirming both return data without authentication.

```go
func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}
```
