### Title
Post-default `requestWithdraw` mints receipts including phantom epoch interest, letting a lender overdraw `defaultRecoveryReserve` - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
The CVE analog is a validation/misinterpretation flaw: an encoding (here, a withdraw request made in a state where it should carry no interest) is accepted and interpreted under rules meant for a different state. After `finalizeDefaultRecovery`, `IdleCreditVault.requestWithdraw` still lets the CDO mint a post-default receipt sized `principal + interest - fees`, even though a defaulted pool accrues no interest and the receipt is paid 1:1 from the fixed `defaultRecoveryReserve`. The interest component is therefore an unbacked claim on recovery funds earmarked for defaulted-epoch claimants.

### Finding Description
In `IdleCreditVault.requestWithdraw`, once `defaultRecoveryFinalized` is set, the post-default branch does:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol:247-257
if (defaultRecoveryFinalized) {
  if (_hasWithdrawRequest(_user) || instantWithdrawsRequests[_user] != 0 || postDefaultRequests[_user] != 0) {
    revert NotAllowed();
  }
  _burn(msg.sender, _amount);
  _mint(_user, _amount);
  postDefaultRequests[_user] = _amount;
  return;
}
```

The comment at line 252-253 assumes `_amount` is "an already-haircut amount" equal to principal only. But `_amount` is computed in `IdleCDOEpochVariant.requestWithdraw` (`contracts/IdleCDOEpochVariant.sol:772-776`) as `principal + interest - totalFees`, where `interest` comes from `_calcInterestWithdrawRequest` (lines 856-878). That function only short-circuits when `epochDuration == 0` — nothing zeroes it on default, and `unscaledApr`/`epochDuration` retain their last configured values. Worse, `_forceUpdateAccounting` after `finalizeDefaultRecovery` shrinks `lastNAVAA`/`lastNAVBB` to the recovery-adjusted NAV, so `_interest = _amount * totTrancheInterest / _trancheBal` (line 870) is divided by a haircut-denominator, *amplifying* the phantom interest relative to the live tranche balance.

The resulting `postDefaultRequests[_user]` receipt is then paid 1:1 in `_claimPostDefaultWithdrawRequest` → `_transferDefaultRecovery` (lines 760-767, 912-917), which decrements `defaultRecoveryReserve` by the full inflated amount with no check that the claim fits the reserve's per-claim basis.

### Impact Explanation
`defaultRecoveryReserve` is a finite pool sized at finalization as `recovered + prefunded + reserve` against `totalBasis` of defaulted claims (`finalizeDefaultRecovery`, lines 686-692). Every phantom-interest wei minted into a post-default receipt is paid out of this reserve at par, directly stealing recovery funds owed to defaulted-epoch withdraw requesters and active LPs. An attacker (any KYC-passed tranche holder with no pending request) requests a withdraw after finalization, claims immediately via `claimWithdrawRequest`, and extracts `principal + interest - fees` where the `interest` portion was never part of the recovery basis. Repeating with fresh addresses drains the reserve faster than legitimate claimants can claim, producing quantifiable theft of recovery proceeds — up to the full reserve if the residual NAV/interest ratio is large enough.

### Likelihood Explanation
- Requirements: a finalized borrower default (`defaultRecoveryFinalized == true`), attacker holds tranche tokens (any KYC'd lender), `allowAAWithdrawRequest`/`allowBBWithdrawRequest` still enabled, and nonzero `epochDuration` + positive stored `unscaledApr` (the normal configuration).
- No privileged role is needed; the attacker only calls `requestWithdraw` and `claimWithdrawRequest`.
- No guard stops it: the post-default branch only checks for pre-existing requests, `_skimDonatedAssets` and `_updateAccounting` don't revert post-default, and `_transferDefaultRecovery` has no basis check.
- Caveat I could not fully verify within index limits: whether `IdleCDOEpochVariant` zeroes `epochDuration`/`unscaledApr` or blocks `requestWithdraw` when `defaulted()` is true via `_checkNotAllowed` in `_updateAccounting` or the allow-flags. If defaulted pools force `epochDuration = 0` or disable withdraw-request flags at finalization, the phantom interest collapses and the bug reduces to dust-level rounding. Confirm by checking `finalizeDefault`/`_forceUpdateAccounting` side effects on `epochDuration` and the allow-flags.

### Recommendation
In `IdleCreditVault.requestWithdraw` post-default branch, additionally require the passed amount to equal the CDO's burned principal (or have the CDO pass `principal` separately and use it instead of `_amount`). Alternatively, short-circuit `_calcInterestWithdrawRequest` when `IdleCreditVault.defaultRecoveryFinalized()` or `defaulted()` is true so post-default receipts are principal-only, matching the documented "already-haircut amount" invariant.

### Proof of Concept
Foundry fork sketch (extend `test/foundry/IdleCreditVault.t.sol` harness):

```solidity
function testPostDefaultWithdrawInflatesReceipt() external {
  // deposit AA/BB, run epoch, borrower defaults
  idleCDO.depositAA(100_000 * ONE_SCALE);
  idleCDO.depositBB(100_000 * ONE_SCALE);
  _startEpochAndCheckPrices(0);
  vm.warp(cdoEpoch.epochEndDate() + 1);
  _checkDefault();                          // borrower fails to repay

  // manager finalizes recovery with partial funds
  _finalizeDefaultRecovery(recoveredAmount, recoverySource);

  // attacker: fresh KYC'd lender with AA balance, no prior requests
  address attacker = makeAddr('attacker');
  _depositWithUser(attacker, 50_000 * ONE_SCALE, true); // pre-default deposit path or acquire tranches

  uint256 reserveBefore = IdleCreditVault(strategy).defaultRecoveryReserve();
  uint256 principal = IERC20Detailed(address(AAtranche)).balanceOf(attacker)
      * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;

  vm.prank(attacker);
  uint256 receipt = cdoEpoch.requestWithdraw(0, address(AAtranche));
  // BUG: receipt > principal -> includes phantom post-default interest
  assertGt(receipt, principal, 'receipt inflated by interest on defaulted pool');

  vm.prank(attacker);
  cdoEpoch.claimWithdrawRequest();
  // attacker drained reserve for more than haircut principal; legitimate
  // defaulted-epoch claimants' reserve is now short by (receipt - principal)
  assertLt(IdleCreditVault(strategy).defaultRecoveryReserve(), reserveBefore - principal);
}
```

Run against a mainnet fork of a deployed IdleCreditVault/IdleCDOEpochVariant pair with `forge test --match-test testPostDefaultWithdrawInflatesReceipt --fork-url $RPC`.
