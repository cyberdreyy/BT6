## Title
Confirmations from a removed multisig member remain counted toward `num_confirmations`, allowing a request to execute below the live-member threshold - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
When a key/member is removed from the multisig, only requests **created** by that key are purged along with their confirmations. Requests created by *other* members that were merely **confirmed** by the removed key retain that stale confirmation in the `confirmations` set. That stale confirmation still counts toward `num_confirmations` in `confirm()`, so a request can later execute with fewer live-member approvals than the configured threshold.

### Finding Description
`confirm()` in both `multisig/src/lib.rs` and `multisig2/src/lib.rs` only checks the size of the `confirmations` set for a request against `num_confirmations` — it never validates that every entry in that set still corresponds to a currently active member/key: [1](#0-0) 

When a key is removed via `MultiSigRequestAction::DeleteKey`, the cleanup logic only removes requests where the removed key is the **request's original signer** (`r.signer_pk == pk`) — i.e. requests the removed key *created*: [2](#0-1) 

It does not scan the `confirmations` map for entries where the removed key merely *confirmed* someone else's still-pending request. The equivalent logic in `multisig2/src/lib.rs`'s `delete_member` has the identical gap — it filters `requests` by `r.member == member` (the creator) only, leaving `confirmations` entries from that member on other requests untouched: [3](#0-2) 

The binding that should hold is: `confirmations counted in confirm() == confirmations from currently live members`. After a member is removed, this equality breaks — a stale confirmation from a now-removed member remains counted, so `confirmations.len()` can reach `num_confirmations` while the number of *live* members who approved is strictly less than `num_confirmations`.

### Impact Explanation
This lets a request execute (transferring funds, adding/deleting keys, changing `num_confirmations`, etc.) with fewer live approvals than the multisig's configured threshold, effectively lowering the m-of-n security guarantee without any of the remaining threshold members having actually approved. This matches the Critical impact category "a multisig request executed below threshold."

### Likelihood Explanation
This requires no attacker privilege beyond being a normal multisig member at the time confirmation is cast — the only precondition is the normal, expected operational event of removing a member/key (e.g., offboarding, key rotation, compromise response) while a request that member had previously confirmed is still pending. This is a routine, foreseeable sequence, not a contrived edge case.

### Recommendation
When removing a key/member (`DeleteKey` in `multisig/src/lib.rs`, `DeleteMember`/`delete_member` in `multisig2/src/lib.rs`), also scan all entries of `self.confirmations` and strip the removed key/member from every confirmation set (not just requests it created), or re-validate at `confirm()` time / execution time that every confirming key/member is still active before counting it toward `num_confirmations`.

### Proof of Concept
1. Multisig has members A, B, C with `num_confirmations = 2`.
2. A calls `add_request` creating request `R` (e.g., a `Transfer`). `R.signer_pk/member = A`.
3. B calls `confirm(R)` → `confirmations[R] = {B}` (1 < 2, not yet executed) — per [4](#0-3) .
4. Members later execute a legitimate `DeleteKey`/`DeleteMember` request removing B (key rotation/offboarding). Cleanup only purges requests where `signer_pk/member == B`; since `R` was created by A, `R` and `confirmations[R] = {B}` remain untouched, per the filter shown at [5](#0-4) .
5. A later calls `confirm(R)` → `confirmations[R] = {B, A}`, size 2 ≥ `num_confirmations` (2), so `R` executes via `execute_request`, per [6](#0-5) .
6. Result: `R` executed with only one live member's (A's) genuine approval plus one stale confirmation from removed member B — below the intended 2-live-member threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
