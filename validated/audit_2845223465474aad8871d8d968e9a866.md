## Analysis: Unbounded Recursive MPT Node Decoding (Stack Exhaustion)

The CVE-2020-1898 bug class—recursive deserialization with no depth limit, leading to stack exhaustion—has a direct analog in this codebase's Merkle Patricia Trie (MPT) implementation, which is squarely in the fault-proof program's reachable surface.

### Title
Unbounded recursion depth in `TrieNode::decode` allows stack exhaustion during fault-proof state trie traversal - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` recursively calls itself when decoding nested `Extension` nodes, and has no depth limit. Because RLP-encoded child nodes smaller than 32 bytes are embedded directly (unblinded) inside their parent rather than referenced by hash, an attacker who controls the *shape* of a storage/account trie can cause many levels of `Extension`→`Extension` nesting to be materialized and recursively decoded from a single preimage blob, without any additional hash-authenticated lookups gating each recursion step.

### Finding Description
`TrieNode::decode` peeks the RLP header and, for a 2-element list matching `LEAF_OR_EXTENSION_LIST_LENGTH`, calls `try_decode_leaf_or_extension_payload`, which for an extension node recurses via `Self::decode(buf)`: [1](#0-0) 

This mirrors the encode side, where a child node is embedded directly (not hashed/blinded) whenever its RLP length is under 32 bytes: [2](#0-1) 

The top-level `decode` entry point that is invoked from preimage-oracle-backed providers has no recursion-depth counter or bound at all: [3](#0-2) 

This function is called directly on attacker-influenceable oracle preimage bytes in the fault-proof program's L1 and L2 chain providers: [4](#0-3) [5](#0-4) 

The other trie operations (`open`, `insert`, `delete`, `unblind`, `collapse_if_possible`) are also mutually recursive with no depth bound: [6](#0-5) [7](#0-6) 

Unlike other decoders in this codebase that impose explicit bounds — e.g., the EIP-8130 call-phase decoder capping `MAX_CALL_PHASES_PER_TX`, or the CBOR parser used for TEE attestation enforcing `MAX_CBOR_NESTING_DEPTH` — the MPT node decoder has no analogous cap: [8](#0-7) [9](#0-8) 

### Impact Explanation
The fault-proof program runs inside a constrained execution environment (Cannon/RISC-V-style) with a much smaller stack than a native host process. A crafted or naturally-deep account/storage trie decoded via `TrieNode::decode` (or traversed via `open`/`insert`/`delete`) with sufficiently deep extension-node nesting can exhaust that stack, causing the fault-proof program to crash rather than compute a valid output root. This directly threatens the "wrong provable output root" / "node halt" outcomes called out as in-scope impacts: a party can no longer produce (or the honest party cannot verify) a claim during dispute resolution, corrupting the correctness or availability of the dispute game.

### Likelihood Explanation
Reaching this path requires constructing a state/storage trie shape (via ordinary contract deployment/storage writes, which is available to any depositor or transaction sender) that produces many chained short `Extension` nodes, and then having the fault-proof program traverse or decode that trie during dispute-game execution. Since none of the recursive trie functions cap depth, and unblinded (embedded, non-hash-gated) sub-nodes let a single preimage encode multiple nesting levels at once, this is plausible without requiring any hash preimage forgery — only shaping legitimately-controlled account/storage data.

### Recommendation
Add an explicit recursion/iteration depth bound to `TrieNode::decode`, `open`, `insert`, `delete`, `unblind`, and `collapse_if_possible` (e.g., threading a `depth: usize` counter and erroring past a fixed maximum, similar to `MAX_CBOR_NESTING_DEPTH` in the CBOR parser or `MAX_CALL_PHASES_PER_TX` in the EIP-8130 decoder), and/or convert the recursive decode into an explicit iterative walk with a bounded work stack.

### Proof of Concept
Construct nested `TrieNode::Extension` values in Rust, each wrapping the next with a node whose RLP length stays under 32 bytes (so it is embedded rather than blinded per the `blinded_length`/encode logic at `crates/proof/mpt/src/node.rs:509-537`), to arbitrary depth N, `encode()` the outermost node into a byte buffer, and feed that buffer to `TrieNode::decode`. Because `try_decode_leaf_or_extension_payload` recurses via `Self::decode(buf)` with no depth check (`crates/proof/mpt/src/node.rs:452-461`), increasing N will eventually overflow the stack of the calling thread; in the fault-proof program's more constrained stack this occurs at a much smaller N than in a native test harness.

        match self {

                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),

                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
