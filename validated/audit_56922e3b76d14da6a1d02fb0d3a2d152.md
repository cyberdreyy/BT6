### Title
Unauthenticated pprof dump exposure via LOOP plugin proxy route - ([File: core/web/loop_registry.go])

### Summary
The route `GET /plugins/:name/debug/pprof/*profile` is registered directly on the base `api` router group without any authentication middleware, unlike every other sensitive route in the router (which are wrapped in `auth.Authenticate(...)` groups). This lets any unauthenticated client fetch a raw pprof dump (heap, goroutine, etc.) proxied from a running LOOP plugin process.

### Finding Description
In `core/web/router.go`, `loopRoutes(app, api)` is called directly on the unauthenticated `api` group (which only has rate limiting and session-cookie middleware attached, not an authentication requirement): [1](#0-0) 
Compare this to how the node's own pprof endpoints are protected: `metricRoutes(authv2)` is only mounted inside the `authv2` group which requires `auth.Authenticate(...)` with token or session auth: [2](#0-1) [3](#0-2) 

The plugin route registration itself has no auth wrapper at all: [4](#0-3) 

The handler `pluginPPROFHandler` looks up the named plugin in the registry and forwards the request unauthenticated to the plugin's internal pprof HTTP server, returning the raw response body to the caller: [5](#0-4) [6](#0-5) 

No auth/role check exists anywhere in this call chain (`gc.Param`, `l.registry.Get`, `l.doRequest`), so an unauthenticated attacker who can reach the node's HTTP listener can request `/plugins/<name>/debug/pprof/heap`, `/goroutine`, `/profile`, etc., and receive a 200 with the plugin process's raw pprof dump. Such dumps can contain stack traces, goroutine data, and potentially in-memory secrets/config held by the LOOP plugin process (e.g., a relayer or oracle plugin), violating secret confinement.

### Impact Explanation
This is an information-disclosure vulnerability: an unauthenticated remote party can extract memory/goroutine/heap profiling data from a LOOP plugin process running inside the node's infrastructure. Depending on what the specific plugin holds in memory (RPC endpoint URLs, credentials, private key material processed transiently, internal state), this could leak sensitive configuration or key-adjacent data, corresponding to Chainlink's "informational/sensitive data disclosure" bounty class. It does not by itself grant fund movement or job execution, but bypasses the "authentication middleware protects sensitive debug endpoints" invariant that is explicitly enforced everywhere else in the router (`metricRoutes` behind `authv2`).

### Likelihood Explanation
No credentials, roles, or preconditions are required beyond network reachability to the node's API listener (same reachability needed for the `/discovery` and `/plugins/:name/metrics` endpoints, which are also unauthenticated by design for Prometheus scraping — but pprof is materially more sensitive than metrics). Any registered LOOP plugin name is enough (plugin names are discoverable via the equally unauthenticated `/discovery` endpoint, which lists `__meta_plugin_name` labels). This makes the finding fully repeatable and low-effort to exploit against any node exposing its web server (including default configurations where WebServer HTTP port is reachable).

### Recommendation
Require authentication on the LOOP plugin pprof and pprof-symbol routes, consistent with how `metricRoutes` is protected. E.g., register `/plugins/:name/debug/pprof/*profile` and `/plugins/:name/debug/pprof/symbol` under an `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`-wrapped group (and likely `auth.RequiresAdminRole`, since pprof access is highly sensitive), while leaving `/discovery` and `/plugins/:name/metrics` as-is if they must remain accessible for Prometheus scraping without a session/token.

### Proof of Concept
Extend `core/web/loop_registry_test.go`'s `TestLoopRegistry` (or add a new test) using the existing `mockLoopImpl` scaffolding:
1. Set up the app and register a mock LOOP plugin exactly as in `TestLoopRegistry` (lines 59-97), using `app.GetLoopRegistry().Register("mockLoopImpl")` and running a mock HTTP server that serves real `net/http/pprof` handlers on `loop.EnvCfg.PrometheusPort` (mirroring what the mock LOOP's internal debug server would expose), or wrap the loop's own pprof mux if the mock provides one.
2. Use `client := app.NewHTTPClient(nil)` — note `NewHTTPClient` in `cltest` typically does not attach auth headers when passed `nil`, i.e., simulating an unauthenticated caller — to issue `client.Get("/plugins/mockLoopImpl/debug/pprof/heap")` and `client.Get("/plugins/mockLoopImpl/debug/pprof/goroutine")`.
3. Assert `resp.StatusCode == http.StatusOK` (via `cltest.AssertServerResponse(t, resp, http.StatusOK)`) and that the response body is non-empty and pprof-format (e.g., starts with pprof gzip magic bytes or contains expected pprof text markers for the `debug=1` text format).
4. As a control, verify that hitting an authenticated-only debug endpoint (`/v2/debug/pprof/heap` under `authv2`) with the same unauthenticated client returns 401/403, demonstrating the asymmetry: the LOOP-plugin-specific pprof passthrough route is reachable without auth while the node's own pprof route is not.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
