### Title
Unpermissioned `migrate_v1_to_v2` Allows Any `LegacyDisplay<T>` Holder to Permanently Seize Display Control for Type T — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

---

### Summary

`migrate_v1_to_v2<T>` accepts any `LegacyDisplay<T>` as sole authorization to create the canonical V2 `Display<T>` in the `DisplayRegistry` and issue the matching `DisplayCap<T>`. Because `sui::display::Display<T>` carries the `store` ability, it is freely transferable via `public_transfer`. Any address that receives a `LegacyDisplay<T>` — regardless of whether they are the publisher of `T` — can call `migrate_v1_to_v2`, claim the derived-object slot, and permanently hold the `DisplayCap<T>`. The legitimate publisher is then forever locked out: `new_display` aborts with `EDisplayAlreadyExists`, and `claim_with_publisher` aborts with `ECapAlreadyClaimed`.

---

### Finding Description

`LegacyDisplay<T>` is `sui::display::Display<T>`, declared with `key, store`: [1](#0-0) 

Because it has `store`, any holder may call `transfer::public_transfer` to send it to an arbitrary address. The V1 creation gate (`display::new<T>`) requires a `Publisher`, but that gate is only at creation time; it does not prevent subsequent transfer.

`migrate_v1_to_v2` performs no publisher check whatsoever: [2](#0-1) 

It delegates directly to `new_display<T>`, which only checks that no `Display<T>` already exists in the registry: [3](#0-2) 

`new_display` immediately sets `cap_id` to `some(cap.id.to_inner())`, so after the call the cap slot is filled. Every other creation path that could give the publisher a second chance is now blocked:

- `new_with_publisher` → calls `new_display` → aborts `EDisplayAlreadyExists`. [4](#0-3) 
- `claim_with_publisher` → aborts `ECapAlreadyClaimed` because `cap_id` is already `some`. [5](#0-4) 

Contrast with every other authorized creation path: `new` requires `internal::Permit<T>` (system-only), `new_with_publisher` requires `publisher.from_package<T>()`, and `system_migration` requires `&SystemMigrationCap`. Only `migrate_v1_to_v2` uses a pure bearer-token model with no publisher verification. [6](#0-5) 

---

### Impact Explanation

An attacker who obtains a `LegacyDisplay<T>` (by any means: purchase, gift, contract interaction, or accidental transfer) can:

1. Call `migrate_v1_to_v2(registry, legacy, ctx)` — no publisher check.
2. Receive `(Display<T>, DisplayCap<T>)` — the attacker now owns the sole, deterministic V2 display object for type `T`.
3. Call `display.share()` to publish it.
4. Use `DisplayCap<T>` to set arbitrary `name`, `image_url`, `link`, and other display fields for every object of type `T` across all UIs that consume the registry.

The legitimate publisher is permanently excluded: the derived-object slot is consumed, `cap_id` is filled, and no recovery path exists. This is permanent state corruption of the `DisplayRegistry`'s derived-object record and a permanent loss of display governance for the type.

---

### Likelihood Explanation

The prerequisite is possession of a `LegacyDisplay<T>`. This is realistic because:

- V1 displays were routinely transferred to multisigs, DAOs, contracts, or secondary addresses.
- `public_transfer` is callable by anyone holding the object; no special permission is needed.
- The window is open for every type whose V1 display was ever transferred and whose V2 slot has not yet been claimed.

---

### Recommendation

Add a `Publisher` parameter to `migrate_v1_to_v2` and assert `publisher.from_package<T>()`, mirroring the guard already present in `new_with_publisher` and `claim_with_publisher`. Alternatively, require both the `LegacyDisplay<T>` and a `&Publisher` so that possession of the legacy object alone is insufficient.

---

### Proof of Concept

```move
// Attacker module
module attacker::exploit;

use sui::display_registry::{Self, DisplayRegistry};
use sui::display::Display as LegacyDisplay;
use sui::transfer;

/// Called by attacker after receiving legacy_display via public_transfer
public fun seize<T: key>(
    registry: &mut DisplayRegistry,
    legacy: LegacyDisplay<T>,   // obtained via public_transfer, no publisher needed
    ctx: &mut TxContext,
) {
    // No publisher check in migrate_v1_to_v2 — succeeds for any holder
    let (display, cap) = display_registry::migrate_v1_to_v2(registry, legacy, ctx);
    display_registry::share(display);
    // Attacker now holds DisplayCap<T>; publisher is permanently locked out
    transfer::public_transfer(cap, ctx.sender());
}
```

The legitimate publisher calling `new_with_publisher<T>` or `claim_with_publisher` after this transaction will abort unconditionally, confirming permanent loss of display control.

fun new_display<T>(
    registry: &mut DisplayRegistry,
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    let key = DisplayKey<T>();
    assert!(!derived_object::exists(&registry.id, key), EDisplayAlreadyExists);
    let cap = DisplayCap<T> { id: object::new(ctx) };
    let display = Display<T> {
        id: derived_object::claim(&mut registry.id, key),
        fields: vec_map::empty(),
        cap_id: option::some(cap.id.to_inner()),
    };
    (display, cap)
}
