## Title
Destination escrow `_withdraw` can be permanently DoS'd by attacker-controlled fee amounts in `createDstEscrow`, causing maker fund loss - (File: `contracts/BaseEscrowFactory.sol`, `contracts/EscrowDst.sol`)

### Summary
`createDstEscrow` lets the taker (any unprivileged caller) supply arbitrary `Immutables`, including the packed `parameters` field that encodes `protocolFeeAmount` and `integratorFeeAmount`. Unlike the source-chain path, there is no check that `protocolFeeAmount + integratorFeeAmount < amount`. `EscrowDst._withdraw` later computes `immutables.amount - integratorFeeAmount - protocolFeeAmount` with unchecked-by-guard subtraction, which reverts on underflow if the fees exceed the amount — the exact same root cause as the reported `VoteKickPolicy._endVote()` underflow (unvalidated “reward total ≤ locked amount” invariant).

### Finding Description
On the source chain, `BaseEscrowFactory._postInteraction` explicitly guards against this by reverting when fees are too large: [1](#0-0) 

But `createDstEscrow` takes the full `Immutables` struct — including the `parameters` bytes that later decode into `protocolFeeAmount`/`integratorFeeAmount` — directly from `msg.sender` (the taker/resolver) with no equivalent validation: [2](#0-1) 

`EscrowDst._withdraw` then unconditionally subtracts both fee amounts from `immutables.amount`: [3](#0-2) 

If a malicious taker sets `integratorFeeAmount + protocolFeeAmount >= immutables.amount` when calling `createDstEscrow`, every future call to `_withdraw` — whether via the private `withdraw` (only callable by the same taker) or `publicWithdraw` (any access-token holder) — reverts due to Solidity 0.8 checked-arithmetic underflow at line 92. The maker can never receive destination funds. `cancel()`, however, does not decode or use the fee fields at all: [4](#0-3) 

so once the `DstCancellation` timelock is reached, the same taker who deployed the escrow calls `cancel()` and receives back the full `immutables.amount` plus the safety deposit.

### Impact Explanation
The attack lets a taker permanently block the maker's destination-chain withdrawal while independently claiming the maker's source-chain funds by revealing the secret directly on `EscrowSrc` (which is validated against its own, separately-hashed immutables and is unaffected by the dst-side fee corruption). The maker loses source-chain funds and never receives destination-chain funds; the taker recovers their own deposited principal via `cancel()`. This is a direct theft of user funds in the live swap lifecycle, matching the Critical bounty impact ("direct theft of user funds at rest or in motion... caused by these production contracts").

### Likelihood Explanation
High. `createDstEscrow` is a public, permissionless entry point intended to be called by takers/resolvers with self-chosen `Immutables`; no privileged role is required, and no on-chain check ties the destination `parameters` (fee amounts) to any source-chain commitment. Any taker can trivially construct `parameters` where `protocolFeeAmount + integratorFeeAmount >= amount`.

### Recommendation
Add the same guard used on the source path to `createDstEscrow` (or to `_withdraw`), e.g.:
```solidity
if (dstImmutables.protocolFeeAmount() + dstImmutables.integratorFeeAmount() >= dstImmutables.amount) revert InvalidFeeAmounts();
```
placed in `createDstEscrow` before deployment, mirroring the check already present in `BaseEscrowFactory._postInteraction` (line 92).

### Proof of Concept
1. Taker (Bob) computes `dstImmutables` for a swap of `amount = 100` DAI to maker Alice.
2. Bob sets `parameters = abi.encode(protocolFeeAmount = 60, integratorFeeAmount = 50, protocolFeeRecipient, integratorFeeRecipient)` (sum = 110 > 100).
3. Bob calls `escrowFactory.createDstEscrow{value: safetyDeposit}(dstImmutables, srcCancellationTimestamp)` — succeeds, no fee-sum validation.
4. Bob reveals the secret only on the source chain, calling `EscrowSrc.withdraw(secret, srcImmutables)` and receives Alice's source tokens.
5. Anyone calling `EscrowDst.withdraw`/`publicWithdraw` on the destination escrow always reverts: `100 - 60 - 50` underflows.
6. After `DstCancellation` timelock elapses, Bob calls `EscrowDst.cancel(dstImmutables)`, receiving back the full `100` DAI + safety deposit.
7. Result: Alice loses her source-chain funds and receives nothing on the destination chain.

```text
     * @notice See {IEscrowFactory-createDstEscrow}.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
```
