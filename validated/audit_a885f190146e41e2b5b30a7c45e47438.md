### Title
Allowed-image check in instance executor validates un-expanded image name while `createVMTunnel` creates the VM from a variable-expanded value - ([File: executors/instance/instance.go], [File: executors/internal/autoscaler/acquisition.go])

### Summary
`executors/instance/instance.go`'s `Prepare` calls `common.VerifyAllowedImage` against the **raw, unexpanded** `options.Build.Image.Name` [1](#0-0) . Later, when `MapJobImageToVMImage` is true, `acquisitionRef.createVMTunnel` takes that same job-supplied image name and runs it through `options.Build.GetAllVariables().ExpandValue(image)` *after* the allow-list check already passed, then feeds the result straight into `nc.Create(ctx, image, &slot)` [2](#0-1) . The value that is actually validated and the value that is actually used to create the nesting VM are not the same string.

### Finding Description
The check-then-use sequence is:
1. `instance.go` `Prepare` (lines 47-66) validates `options.Build.Image.Name` — the literal string as submitted in job config, before any `$VAR` substitution — against `options.Config.Instance.AllowedImages` via `common.VerifyAllowedImage`, which uses `doublestar.Match(allowedImage, options.Image)` glob matching on that literal string [3](#0-2) .
2. Control then passes (via `environment.Prepare`) into `acquisitionRef.createVMTunnel`, which independently re-reads `options.Build.Image.Name`, assigns it to `image` when `ref.mapJobImageToVMImage` is true, and only then expands job variables into it: `image = options.Build.GetAllVariables().ExpandValue(image)` [4](#0-3) .
3. The expanded `image` — not the string that was checked — is passed to `nc.Create(ctx, image, &slot)` to instantiate the nesting VM [5](#0-4) .

Because glob wildcards such as `*` in an admin-configured allow pattern (e.g. `myorg/*`) match arbitrary literal substrings — including a literal `$VAR` token that has not yet been substituted — a pipeline author can craft `image.Name` so it passes the allow-list check as raw text, but expands via a job-controlled CI variable into a completely different final string once `ExpandValue` runs. The check in `instance.go` has no visibility into the variables that will later be substituted, and the value used in `createVMTunnel` is never re-validated with `VerifyAllowedImage` after expansion.

This differs from how the docker executor closes this exact gap: `executors/docker/docker.go`'s `expandImageName` explicitly expands the image name **before** calling `verifyAllowedImage`, so the check and the used value are always the same string [6](#0-5) . The instance executor does the opposite ordering across two different files/modules, decoupling validation from usage.

### Impact Explanation
An unprivileged pipeline author on a runner configured with `VMIsolation.Enabled` and `MapJobImageToVMImage:true` and a restrictive `Instance.AllowedImages` allow-list can get the allow-list check to pass on a crafted literal string, then use ordinary job variables to substitute in an arbitrary final VM image reference at `nc.Create` time — bypassing the administrator's image restriction. This is exactly the invariant the question flags: "image/service selection restrictions enforced by admin config must not be bypassable through variable expansion tricks distinct from the literal image field checked by `common.VerifyAllowedImage`."

### Likelihood Explanation
Requires the instance executor with VM isolation enabled and `Instance.AllowedImages` configured with non-`*` glob patterns (a realistic hardening configuration, since an empty/`*` allow-list imposes no restriction anyway per `common.VerifyAllowedImage`'s "by default allow to override" branch) [7](#0-6) . Any pipeline author who can set `image:` and CI/CD variables — which is standard, unprivileged capability — can attempt the bypass. It is fully deterministic and repeatable once the allow pattern is known or guessed.

### Recommendation
Perform the allow-list check on the **expanded** image name, at the same point the expanded value is consumed (mirroring the docker executor's `expandImageName` pattern): move/duplicate the `VerifyAllowedImage` call into `acquisitionRef.createVMTunnel` (or pass the already-expanded value back into `instance.go`) so validation and VM creation always operate on the identical, fully-expanded string.

### Proof of Concept
Go test sketch in `executors/internal/autoscaler` (or an integration test spanning `executors/instance` + `executors/internal/autoscaler`):
```go
func TestCreateVMTunnel_AllowListBypassViaVariableExpansion(t *testing.T) {
    // Runner config: Instance.AllowedImages = []string{"myorg/*"}
    // Job: options.Build.Image.Name = "myorg/$PAYLOAD"
    // Job variable: PAYLOAD -> "..private-other-project-vm-image"
    //
    // Step 1: assert common.VerifyAllowedImage(VerifyAllowedImageOptions{
    //     Image: "myorg/$PAYLOAD", AllowedImages: []string{"myorg/*"},
    // }, logger) == nil   // passes allow-list check on literal string

    // Step 2: call acquisitionRef.createVMTunnel with a fake nestingapi.Client
    // capturing the "image" argument passed to nc.Create.
    //
    // Assert: capturedImage == "myorg/..private-other-project-vm-image"
    // (i.e., final image differs materially from any pattern-approved value,
    // proving the checked string and the used string diverge)
}
```
Expected assertion failure to fix: the image string passed to `nc.Create` should never diverge from a string that has independently passed `VerifyAllowedImage` after full variable expansion.

func VerifyAllowedImage(options VerifyAllowedImageOptions, logger buildlogger.Logger) error {
	for _, allowedImage := range options.AllowedImages {
		ok, _ := doublestar.Match(allowedImage, options.Image)
		if ok {
			return nil
		}
	}

func (e *executor) expandImageName(imageName string, allowedInternalImages []string) (string, error) {
	defaultDockerImage := e.ExpandValue(e.Config.Docker.Image)
	if imageName != "" {
		image := e.ExpandValue(imageName)
		allowedInternalImages = append(allowedInternalImages, defaultDockerImage)
		err := e.verifyAllowedImage(image, "images", e.Config.Docker.AllowedImages, allowedInternalImages)
		if err != nil {
			return "", err
		}
		return image, nil
	}
