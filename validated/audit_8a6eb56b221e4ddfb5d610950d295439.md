### Title
Longest-common-prefix replay-set aggregation only explores truncations of the top-weight candidate, silently dropping a valid majority-supported transaction-replay prefix - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::find_majority_prefix_replay_set` is the fallback path used by `determine_global_state` to compute the network-agreed transaction replay set when no single replay set has an outright 70% majority. It picks a single "initial candidate" — the replay set carried by the highest-weight signer entry — and only ever examines *truncations of that one candidate's own sequence*. If that top-weight entry's sequence shares no common prefix with the sequence that the remaining weight actually agrees on, the loop truncates straight past any valid non-empty majority prefix and lands on the empty prefix, which trivially "wins" because `starts_with(&[])` is always true. The function then returns "no replay set enforced" even though a specific, non-empty prefix genuinely commands ≥70% weight.

### Finding Description
`find_majority_prefix_replay_set` at [1](#0-0)  first checks for exact agreement, then, on failure, sorts candidate replay sets by weight descending and picks the top one as the sole basis for prefix search: [2](#0-1) 

The loop only pops elements off `candidate_prefix`, which was seeded exclusively from `sorted_sets.first()` — the single heaviest replay-set entry. No other observed replay set is ever used to seed a candidate prefix. Consequently:

- If the heaviest entry's sequence is disjoint from the sequence the remaining weight actually agrees on, every truncation step checks only prefixes of the *wrong* sequence.
- Once the heaviest entry's own sequence is exhausted (popped to empty), `starts_with(&[])` matches every entry, so the sum of *all* weights trivially reaches the 70% threshold, and the function returns the empty set — silently discarding a real, non-empty majority-supported prefix that a correct LCP search would have found.

This is invoked from `determine_global_state`, which is what individual signers use to compute the network's agreed `tx_replay_set` from other signers' `StateMachineUpdate` broadcasts: [3](#0-2) 

Existing regression tests only exercise cases where all competing replay sets share a common leading element (e.g. `[A,B]` vs `[A,C]`, or `[A,B,C]` vs `[A,B,D]`), so the top-weight candidate always happens to be part of the winning family: [4](#0-3) [5](#0-4) 

None of the tests cover the case where the heaviest individual entry is *unrelated* to the sequence the rest of the weight agrees on — exactly the case that breaks the algorithm.

### Impact Explanation
The transaction-replay set is a safety mechanism that constrains which transactions a block must replay after a chain fork. A signer that incorrectly computes "no replay set is required" (because this LCP search missed the real majority prefix) will validate/sign blocks that omit the mandatory replay transactions that the rest of the network's weight actually agreed to enforce — a `SignerStateMachine` divergence that causes the affected signer to approve a non-canonical block relative to the group's true consensus. This falls into the Critical bucket described by the scan rules: a signer signing/approving a block that does not match the state the rest of the signer set has actually reached agreement on.

### Likelihood Explanation
No majority collusion or crafted messages are required. Signers derive their individual `replay_transactions` value from real chain-fork observations (`get_forked_txs_from_fork_info` / `compute_forked_txs_set_in_same_cycle` in `stacks-signer/src/v0/signer_state.rs`), so a Bitcoin reorg naturally causes different signers to observe different fork depths and propose different replay sequences at different points in time. A miner that triggers reorgs (which miners routinely influence via block-commit placement) can readily produce exactly this kind of partitioned weight distribution — one large but "wrong" candidate and several smaller entries that share a real prefix — pushing an honest signer's local aggregation into the buggy empty-prefix fallback.

### Recommendation
Rework `find_majority_prefix_replay_set` to search prefixes across *all* observed replay sets (or all realizable prefixes derivable from the full set of candidates), not just truncations of the single highest-weight entry — e.g., enumerate every distinct prefix length across all candidate sequences, compute supporting weight for each, and select the longest prefix that reaches the 70% threshold, falling back to empty only when no non-empty prefix qualifies.

### Proof of Concept
Using `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD == 7` (70% threshold), construct 5 signer weights summing to 100 and replay-set updates:

- Signer1, weight 25: replay set `[Z]`
- Signer2, weight 24: replay set `[A, X]`
- Signer3, weight 24: replay set `[A, Y]`
- Signer4, weight 22: replay set `[A, W]`
- Signer5, weight 5: replay set `[Q]`

Call `GlobalStateEvaluator::determine_global_state()` (which internally calls `find_majority_prefix_replay_set` at [6](#0-5) ):

1. No entry alone reaches 70% (`[Z]`=25 max), so the exact-match loop fails.
2. `sorted_sets.first()` picks `[Z]` (weight 25, the single heaviest entry).
3. Support for `[Z]` = 25 < 70 → truncate. Since `[Z]` has length 1, `candidate_prefix` becomes `[]`.
4. Support for `[]` = 25+24+24+22+5 = 100 ≥ 70 → function returns the **empty** replay set.

The correct answer is `[A]`, supported by Signer2+Signer3+Signer4 = 24+24+22 = 70, exactly meeting the 70% threshold — a valid, non-empty majority-supported prefix that the algorithm never even considers because it is not a prefix of the heaviest single entry `[Z]`.

    /// Find the longest common prefix of replay sets that has majority support.
    /// This implements the longest common prefix (LCP) strategy where if one signer's replay set
    /// is [A,B,C] and another is [A,B], we should use [A,B] as the replay set.
    /// Order matters for transaction replay - [A,B] and [B,A] have no common prefix.
    fn find_majority_prefix_replay_set(
        &self,
        tx_replay_sets: &HashMap<ReplayTransactionSet, u32>,
    ) -> Option<ReplayTransactionSet> {
        if tx_replay_sets.is_empty() {
            return None;
        }

        // First, try to find an exact match that reaches agreement
        for (replay_set, weight) in tx_replay_sets {
            if self.reached_agreement(*weight) {
                return Some(replay_set.clone());
            }
        }

        // No exact agreement found, find longest common prefix with majority support

        // Sort replay sets by weight (descending), then deterministically by length and content
        let mut sorted_sets: Vec<_> = tx_replay_sets.iter().collect();
        sorted_sets.sort_by(|(set_a, weight_a), (set_b, weight_b)| {
            // Primary: weight descending
            let weight_cmp = weight_b.cmp(weight_a);
            if weight_cmp != Ordering::Equal {
                return weight_cmp;
            }
            // Secondary: length descending (longer sequences first)
            let len_cmp = set_b.0.len().cmp(&set_a.0.len());
            if len_cmp != Ordering::Equal {
                return len_cmp;
            }
            // Tertiary: compare transaction IDs for determinism
            for (lhs, rhs) in set_a.0.iter().zip(&set_b.0) {
                let ord = lhs.txid().cmp(&rhs.txid());
                if ord != Ordering::Equal {
                    return ord;
                }
            }
            Ordering::Equal
        });

        // Start with the most supported replay set as initial candidate
        if let Some((initial_set, _)) = sorted_sets.first() {
            let mut candidate_prefix = initial_set.0.clone();
            let mut total_supporting_weight = 0u32;

            // Find all sets that support the current candidate prefix
            for (replay_set, weight) in tx_replay_sets {
                if replay_set.0.starts_with(&candidate_prefix) {
                    total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                }
            }

            // If the initial candidate already has majority support, return it
            if self.reached_agreement(total_supporting_weight) {
                return Some(ReplayTransactionSet::new(candidate_prefix));
            }

            // Otherwise, iteratively truncate the prefix until we find majority support
            while !candidate_prefix.is_empty() {
                // Remove the last transaction from the prefix
                candidate_prefix.pop();

                // Recalculate supporting weight for the shorter prefix
                total_supporting_weight = 0u32;
                for (replay_set, weight) in tx_replay_sets {
                    if replay_set.0.starts_with(&candidate_prefix) {
                        total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                    }
                }

                // If this prefix has majority support, return it
                if self.reached_agreement(total_supporting_weight) {
                    return Some(ReplayTransactionSet::new(candidate_prefix));
                }
            }
        }

        // If no common prefix with majority support is found, return None
        None
    }
}

/// Case: [A,B,C] vs [A,B,D] should find common prefix [A,B]
fn test_replay_set_partial_prefix_match() {
    let mut state_test = SignerStateTest::new(5);

    // Signer 0, 1: [A,B,C] (40% weight)
    state_test.update_signers(
        &[0, 1],
        vec![
            state_test.tx_a.clone(),
            state_test.tx_b.clone(),
            state_test.tx_c.clone(),
        ],
    );

    // Signers 2, 3, 4: [A,B,D] (60% weight)
    state_test.update_signers(
        &[2, 3, 4],
        vec![
            state_test.tx_a.clone(),
            state_test.tx_b.clone(),
            state_test.tx_d.clone(),
        ],
    );

    let transactions = state_test.get_global_replay_set();

    // Should find [A,B] as the longest common prefix with majority support
    assert_eq!(transactions.len(), 2);
    assert_eq!(transactions[0], state_test.tx_a);
    assert_eq!(transactions[1], state_test.tx_b);
}
