### Title
Legacy zip extractor performs no path confinement, enabling path traversal during cache/artifact restore - (File: helpers/archives/zip_extract.go, invoked from commands/helpers/archive/ziplegacy/zip_legacy_extractor.go: Extract)

### Summary
`ziplegacy.extractor.Extract` receives a target directory (`e.dir`) but never uses it; it delegates directly to `archives.ExtractZipArchive`, which writes every zip entry using the raw `file.Name` from the archive with no path-confinement check, no `..` traversal check, and no absolute-path rejection. This is exploitable by any user who controls the contents of a cache or artifact archive consumed by `cache-extractor`/artifact restore, since Go's `archive/zip` reader does not sanitize entry names on read.

### Finding Description
`ziplegacy.extractor.Extract` (commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33) stores the target `dir` in the extractor struct at construction but the `Extract` method never references `e.dir` — it just calls `archives.ExtractZipArchive(zr)`. [1](#0-0) 

`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` and calls `extractZipFile(file)` for each entry, using `file.Name` as the literal filesystem path for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.Mkdir(file.Name, ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(data, file.Name)`. [2](#0-1) [3](#0-2) 

The only entry-name validation applied is `errorIfGitDirectory`, which only checks whether the first path component is `.git`; it does not detect `..` segments, absolute paths, or symlink targets escaping the directory. [4](#0-3) 

This is in stark contrast to the sibling `tarzstd` extractor, which explicitly resolves each entry against the target directory and rejects any path outside of it: `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` followed by `if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) ...`. [5](#0-4) 

Go's `archive/zip` package does not sanitize `File.Name` on read — it is the caller's responsibility, which the tar/tarzstd path fulfills but the zip path does not.

Reachable path: `commands/helpers/cache_extractor.go: CacheExtractorCommand.Execute` downloads/opens the cache archive and calls `archive.NewExtractor(format, f, size, wd)` then `extractor.Extract(...)`, where `wd` is the job's working directory. [6](#0-5) 
When `format` resolves to the legacy zip extractor (registered via `archive.Register(archive.Zip, NewArchiver, NewExtractor)` in ziplegacy, the default unless `FF_USE_FASTZIP` is enabled to override it), no path confinement to `wd` is applied at all. [7](#0-6) [8](#0-7) 

An attacker who controls a project's cache key/content (any pipeline author, since caches are per-project/per-key and often shared across jobs/branches) can produce a zip whose entries contain names such as `../../../../home/gitlab-runner/.bash_profile`, `../../../tmp/some-helper-consumed-file`, or an absolute path, causing `extractZipFile` to write attacker bytes outside the build directory into locations that later helper binaries, generated env files, or temp scripts trust.

### Impact Explanation
This allows an unprivileged pipeline author to overwrite arbitrary files reachable by the runner/helper process outside the intended cache/build root, using only a poisoned cache/artifact zip archive. Concrete impacts include overwriting helper-consumed temp files or env files that are later read as trusted input by subsequent job stages, corrupting or replacing files used across jobs on the same shared runner host (e.g., shared cache directories, other projects' checkouts if paths coincide), and potential secret exposure or elevated influence over later build steps if a helper script or environment file is clobbered with attacker content before it's consumed.

### Likelihood Explanation
Precondition: the runner must not be forcing `FF_USE_FASTZIP=true` (its default state historically varies by version/config), or the `.zip`/legacy zip codepath must otherwise be selected for cache or artifact extraction (also used to decompress `zstd` format regardless of `FF_USE_FASTZIP` unless overridden, per the registration comment in commands/helpers/archiver.go). An attacker only needs the ability to populate a project cache/artifact (any CI job author) with a crafted zip; no privileged access or admin misconfiguration is required. This is trivially repeatable and deterministic — feasibility is high, since Go's `archive/zip` reader will faithfully return `..`-containing or absolute-path entry names without modification.

### Recommendation
Add path-confinement validation identical to the tarzstd extractor: for every zip entry, resolve `filepath.Join(e.dir, file.Name)`, verify (via `filepath.Abs` + `strings.HasPrefix`) the resolved path stays within `e.dir`, and reject symlink targets (`Linkname`/`file.Name` data payload for zip symlinks) that point outside `e.dir`. Reject absolute paths and any Windows drive-letter/UNC forms as well. Apply this check in `extractZipFile`/`ExtractZipArchive` (helpers/archives/zip_extract.go), and thread `dir` through `ziplegacy.extractor.Extract` so it is actually enforced instead of being an unused struct field.

### Proof of Concept
Go unit test (in `helpers/archives/zip_extract_test.go` or `commands/helpers/archiver_test.go`):
1. Build a zip in memory using `archive/zip.Writer` with one entry named `../outside/pwned.txt` containing attacker-controlled bytes.
2. Create a `t.TempDir()` `out` and a sibling directory `outside` (e.g. `filepath.Join(t.TempDir(), "sub")` as `out`, with `filepath.Dir(out)/outside` as the traversal target).
3. Call `ziplegacy.NewExtractor(reader, size, out)` then `Extract(ctx)`.
4. Assert: `os.Stat(filepath.Join(filepath.Dir(out), "outside", "pwned.txt"))` succeeds and its content matches the attacker payload — proving the file was written outside `out`.
5. Compare against a parallel test using `tarzstd.NewExtractor` with the same traversal entry, asserting it returns the `"cannot be extracted outside of chroot"` error instead — demonstrating the missing check is specific to the zip path.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
