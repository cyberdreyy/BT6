### Title
Non-tenure-start block proposal can claim a canonical tenure different from its actual parent's tenure - (File: `stackslib/src/net/api/postblock_proposal.rs`)

### Summary
`NakamotoBlockProposal::check_block_has_valid_parent` never confirms that a non-tenure-start block's `header.consensus_hash` matches the tenure its `header.parent_block_id` actually belongs to. It only checks that the parent's height equals the *height* of the highest known block in the tenure named by the proposal, which can be satisfied by a parent from a completely different (but also canonical) tenure of equal height.

### Finding Description
`check_block_has_valid_parent` branches on `block.is_wellformed_tenure_start_block()`. For the non-tenure-start branch it calls: [1](#0-0) 

passing `&block.header.consensus_hash` (the proposal's own, attacker-controlled claim of which tenure it belongs to) directly as `tenure_id` into `check_block_builds_on_highest_block_in_tenure`. That helper only performs a height comparison between the parent header and the "highest known block header in `tenure_id`": [2](#0-1) 

It never verifies that `parent_header.consensus_hash` (the parent's *actual* tenure) equals `tenure_id`. Separately, `check_block_has_valid_tenure` is invoked only to confirm that `block.header.consensus_hash` names a tenure that is on the canonical Bitcoin fork - not that it is the same tenure the parent belongs to: [3](#0-2) [4](#0-3) 

Because a non-tenure-start block by definition carries no `TenureChange` transaction, the implicit invariant is that its `consensus_hash` must equal its parent's `consensus_hash` (i.e., it continues the *same* tenure as its parent). Nothing in this file enforces that equality. An attacker who controls a single miner slot can:
1. Observe two canonical tenures, A and B, whose tip blocks are both at chain height `N`.
2. Build (or reuse) a real block from tenure B at height `N` as `parent_block_id`.
3. Craft a non-tenure-start block header with `consensus_hash = A` (a different, but still canonical, tenure) and `parent_block_id` pointing at tenure B's tip.
4. Submit as a `BlockProposal`.

`check_block_has_valid_tenure` passes because A is canonical. `check_block_builds_on_highest_block_in_tenure(tenure_id=A, parent_block_id=B's tip)` looks up "highest known header in tenure A" (height N) and compares it only to the height of the supplied parent (also N, but from tenure B) - the comparison is height-only, so it passes despite the parent not actually belonging to tenure A.

### Impact Explanation
If no other stage of `validate()` re-derives or checks the tenure lineage of `parent_block_id` against `block.header.consensus_hash` for the `NoTenureChange` case, the signer will sign a block whose declared tenure (embedded in its header and thus in `signer_signature_hash`) does not match the tenure its state was actually built from. This is a canonicity violation of the exact class called out as Critical: a signer signs a non-canonical/conflicting block, since the block's committed tenure metadata is decoupled from its true parent lineage, which is exploitable to create conflicting/forked chain states that both carry valid signer signatures.

### Likelihood Explanation
Requires only: (a) a single miner slot to craft and gossip a `BlockProposal` (no majority-signer or privileged access needed), and (b) two canonical tenures whose tips coincide in height - a condition that recurs naturally whenever a tenure is extended/replaced or short empty tenures occur, which is common in normal chain operation. The attack is a single crafted HTTP proposal to `/v3/block_proposal`, requiring no auth_token and no other signer's key, and is repeatable whenever the height-coincidence precondition recurs.

### Recommendation
In `check_block_builds_on_highest_block_in_tenure` (or in `check_block_has_valid_parent` before calling it for the non-tenure-start branch), additionally fetch `parent_header.consensus_hash` and require it to equal `tenure_id` (i.e., `block.header.consensus_hash`) for non-tenure-start blocks, rejecting with `ValidateRejectCode::NonCanonicalTenure`/`InvalidParentBlock` if they diverge, rather than relying on a height-only comparison.

### Proof of Concept
Rust test sketch (extending existing tests in `stackslib/src/net/api/postblock_proposal.rs` / nakamoto test harness):
```rust
// Build tenure A ending at height N, and tenure B (a sibling canonical tenure) also ending at height N.
let tenure_a_tip = /* highest header in tenure A, height N */;
let tenure_b_tip = /* highest header in tenure B, height N */;

// Craft a non-tenure-start block: consensus_hash = tenure A's hash,
// but parent_block_id = tenure B's tip block id.
let mut block = make_non_tenure_start_block();
block.header.consensus_hash = tenure_a_hash;
block.header.parent_block_id = tenure_b_tip.index_block_hash();

let result = NakamotoBlockProposal::check_block_has_valid_parent(&chainstate, &sortdb, &block);

// Current (vulnerable) behavior: Ok(()) because heights match (both N).
// Expected (fixed) behavior: Err(BlockValidateRejectReason { reason_code: NonCanonicalTenure/InvalidParentBlock, .. })
// because tenure_b_tip.consensus_hash != tenure_a_hash.
assert!(result.is_err(), "block whose parent belongs to a different tenure than its declared consensus_hash must be rejected");
```

    fn check_block_builds_on_highest_block_in_tenure(
        chainstate: &StacksChainState,
        sortdb: &SortitionDB,
        tenure_id: &ConsensusHash,
        parent_block_id: &StacksBlockId,
    ) -> Result<(), BlockValidateRejectReason> {
        let Some(highest_header) = NakamotoChainState::find_highest_known_block_header_in_tenure(
            chainstate, sortdb, tenure_id,
        )
        .map_err(|e| BlockValidateRejectReason {
            reason_code: ValidateRejectCode::ChainstateError,
            reason: format!("Failed to query highest block in tenure ID: {:?}", &e),
            failed_txid: None,
        })?
        else {
            warn!(
                "Rejected block proposal";
                "reason" => "Block is not a tenure-start block, and has an unrecognized tenure consensus hash",
                "consensus_hash" => %tenure_id,
            );
            return Err(BlockValidateRejectReason {
                reason_code: ValidateRejectCode::NoSuchTenure,
                reason: "Block is not a tenure-start block, and has an unrecognized tenure consensus hash".into(),
                failed_txid: None,
            });
        };
        let Some(parent_header) =
            NakamotoChainState::get_block_header(chainstate.db(), parent_block_id).map_err(
                |e| BlockValidateRejectReason {
                    reason_code: ValidateRejectCode::ChainstateError,
                    reason: format!("Failed to query block header by block ID: {:?}", &e),
                    failed_txid: None,
                },
            )?
        else {
            warn!(
                "Rejected block proposal";
                "reason" => "Block has no parent",
                "parent_block_id" => %parent_block_id
            );
            return Err(BlockValidateRejectReason {
                reason_code: ValidateRejectCode::UnknownParent,
                reason: "Block has no parent".into(),
                failed_txid: None,
            });
        };
        if parent_header.anchored_header.height() != highest_header.anchored_header.height() {
            warn!(
                "Rejected block proposal";
                "reason" => "Block's parent is not the highest block in this tenure",
                "consensus_hash" => %tenure_id,
                "parent_header.height" => parent_header.anchored_header.height(),
                "highest_header.height" => highest_header.anchored_header.height(),
            );
            return Err(BlockValidateRejectReason {
                reason_code: ValidateRejectCode::InvalidParentBlock,
                reason: "Block is not higher than the highest block in its tenure".into(),
                failed_txid: None,
            });
        }
        Ok(())
    }

                failed_txid: None,

        }
        Ok(())
    }
