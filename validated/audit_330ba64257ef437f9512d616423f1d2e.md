### Title
Unrestricted `LockupFactory::create` lets any account squat a victim's deterministic lockup address with attacker-chosen schedule terms - (File: `lockup-factory/src/lib.rs`)

### Summary
`LockupFactory::create` is a public, unauthenticated `#[payable]` method that accepts `owner_account_id`, `lockup_duration`, `lockup_timestamp`, `vesting_schedule`, `release_duration`, and `whitelist_account_id` directly from the caller, with no check that the caller is the NEAR Foundation or any other authorized grantor. Because the resulting lockup account name is deterministically derived only from `owner_account_id`, any unprivileged attacker can pre-create (front-run) the lockup contract for a victim's account with arbitrary, attacker-chosen schedule/whitelist parameters, permanently occupying that address before the legitimate grantor can deploy the correct lockup.

### Finding Description
The broken binding: `lockup_terms(owner_account_id) == grantor_intended_terms(owner_account_id)` should always hold, but the code allows `lockup_terms(owner_account_id) == attacker_chosen_terms` for any `owner_account_id` the attacker names.

`create` computes the target account deterministically from only the owner id: [1](#0-0) 

and then builds the `LockupArgs` (including `lockup_duration`, `lockup_timestamp`, `vesting_schedule`, `release_duration`, `staking_pool_whitelist_account_id`) entirely from the caller-supplied parameters: [2](#0-1) 

There is no `assert_called_by_foundation`, owner check, or any restriction on who may call `create`, aside from the deposit-size check `assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, ...)`: [3](#0-2) 

Because a NEAR account name (`lockup_account_id`) can only be created once, an attacker can call `create(victim_owner_account_id, attacker_lockup_duration, attacker_lockup_timestamp, attacker_vesting_schedule, attacker_release_duration, attacker_whitelist_account_id)` with the required `MIN_ATTACHED_BALANCE` before the legitimate grantor does. This deploys a lockup contract at the victim's canonical, deterministic address whose schedule fields were chosen entirely by the attacker instead of the grantor. When the legitimate grantor later attempts the correct `create` call for the same `owner_account_id`, `create_account()` fails because the account already exists, the whole batched promise fails, and `on_lockup_create`'s failure branch simply refunds the deposit to whoever called it: [4](#0-3) 

The refund path itself is not exploitable for fund theft (it returns to the correct `predecessor_account_id`), but it confirms the legitimate lockup can never be created at that address afterward — the attacker-parameterized contract is permanent. No guard in `assert_self`, `is_promise_success`, or elsewhere restricts who may invoke `create` or validates that schedule parameters originate from a trusted grantor.

### Impact Explanation
The victim's real grant is permanently prevented from being deployed with its intended terms at its canonical account, and the tokens end up locked under a schedule (`lockup_duration`, `release_duration`, `lockup_timestamp`, `vesting_schedule`, `staking_pool_whitelist_account_id`) chosen unilaterally by an unrelated attacker rather than the grantor. This matches the Critical category "a lockup deployed with parameters its rightful creator never chose." Depending on the attacker's chosen parameters, this can also permanently freeze the funds deposited into that lockup (e.g., an extremely long `lockup_duration`/`release_duration`), or restrict staking to a malicious whitelist contract the attacker controls, since `staking_pool_whitelist_account_id` is also attacker-controlled. The attack is repeatable against any `owner_account_id` the attacker can predict/target before the legitimate grantor acts.

### Likelihood Explanation
The only precondition is possessing `MIN_ATTACHED_BALANCE` (3,500,000,000,000,000,000,000,000 yoctoNEAR ≈ 3.5 NEAR) and knowledge of the intended `owner_account_id` (typically known in advance, e.g., published grant recipients). No special privileges, keys, or contract ownership are required — `create` is callable by any account. The attacker's own deposited funds remain locked in the squatted contract (cost = deposit + gas), but the disruption to the legitimate grantor's process is permanent and cheap to repeat for any number of target accounts.

### Recommendation
Restrict `create` to be callable only by the trusted grantor (e.g., `assert_eq!(env::predecessor_account_id(), self.foundation_account_id)`), or otherwise ensure schedule parameters cannot be supplied by arbitrary third parties for a given `owner_account_id`. If self-service lockup creation must remain public, decouple the deterministic account-naming scheme from `owner_account_id` alone (e.g., derive it from a per-grant nonce/hash committed to by the foundation) so third parties cannot pre-empt a specific victim's canonical lockup address.

// cargo test in lockup-factory, extending tests in lib.rs
#[test]
fn test_attacker_squats_victim_lockup_address() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    // Attacker calls create() naming the VICTIM as owner_account_id,
    // but with attacker-chosen duration/whitelist (no foundation check exists).
    context.predecessor_account_id = String::from("attacker.near");
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    let attacker_duration: WrappedTimestamp = 1u64.into(); // near-instant / or huge freeze value
    contract.create(
        account_tokens_owner(), // victim owner id
        attacker_duration,
        None,
        None,
        None,
        Some(custom_whitelist_account_id()), // attacker-controlled whitelist
    );

    // Simulate success: attacker's lockup is now deployed at the deterministic
    // address for account_tokens_owner(), with attacker-chosen terms.
    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    assert!(contract.on_lockup_create(
        lockup_account(),
        ntoy(30).into(),
        String::from("attacker.near"),
    ));

    // Legitimate grantor now tries to create the REAL lockup for the same owner
    // with the correct intended schedule -> create_account() collides, fails.
    context.predecessor_account_id = String::from(account_tokens_owner());
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    let intended_duration: WrappedTimestamp = 63036000000000000u64.into(); // 24 months, grantor-intended
    contract.create(account_tokens_owner(), intended_duration, None, None, None, None);

    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Failed); // account collision
    let res = contract.on_lockup_create(
        lockup_account(),
        ntoy(35).into(),
        String::from(account_tokens_owner()),
    );
    // Assert both sides of the broken binding:
    // lockup_terms(owner) == attacker_duration/whitelist, NOT intended_duration/whitelist
    assert_eq!(res, false); // grantor's intended lockup creation failed/refunded
    // The account at lockup_account() permanently holds attacker's terms,
    // not the grantor-intended terms — invariant violated.
}

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
