### Title
Missing role-based authorization on `GET /v2/bridge_types/:BridgeName` exposes bridge URL and outgoing token to any authenticated user - ([File: core/web/router.go], [File: core/web/bridge_types_controller.go])

### Summary
The `bridge_types/:BridgeName` `Show` route is registered without any `auth.RequiresXRole` wrapper, unlike its sibling `Create`/`Update`/`Destroy` routes on the same resource. Any authenticated user — including a low-privilege "view" role session or API token — can call this endpoint and receive the bridge's `URL` and plaintext `OutgoingToken` in the JSON response.

### Finding Description
In `v2Routes`, the bridge type routes are defined as: [1](#0-0) 

`bt.Create`, `bt.Update`, and `bt.Destroy` are wrapped with `auth.RequiresEditRole`, but `bt.Show` (and `bt.Index`) are not gated by any role check — they are reachable by anyone who passes the outer `authv2` group's `auth.Authenticate(... auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware, which only verifies that the caller is *authenticated*, not that they hold a sufficient role: [2](#0-1) 

`BridgeTypesController.Show` fetches the bridge from the ORM and serializes it via `presenters.NewBridgeResource`, with no role-based field filtering: [3](#0-2) 

`BridgeResource` includes `URL` and `OutgoingToken` unconditionally (no redaction based on caller role): [4](#0-3) 

The `bridges.BridgeType` struct returned by `FindBridge` stores `IncomingTokenHash` (a salted hash, not the plaintext incoming token) and `OutgoingToken` in plaintext: [5](#0-4) 

Because `BridgeType.IncomingTokenHash` is never mapped into `BridgeResource.IncomingToken` (that field is only populated transiently at `Create` time from `BridgeTypeAuthentication`), the plaintext incoming token is not disclosed by `Show`. However, `OutgoingToken` is stored and returned in plaintext, and the bridge `URL` (which can contain embedded credentials or point to internal infrastructure) is always returned as well — with no role check gating access to any of this.

### Impact Explanation
An unprivileged authenticated user (view-role session or restricted API token) can enumerate/guess a bridge name and retrieve the bridge's `OutgoingToken` and internal `URL` via a simple `GET /v2/bridge_types/:BridgeName`. This matches the "sensitive information disclosure" / "unauthorized secret disclosure" bounty impact class — the outgoing token is a credential used by the bridge adapter integration, and the URL may reveal internal network topology or embedded credentials.

### Likelihood Explanation
Highly feasible and fully repeatable: it requires only a valid, low-privilege authenticated session/token (view role) and knowledge of an existing bridge name (bridge names are visible via the equally unguarded `GET /v2/bridge_types` index route, `authv2.GET("/bridge_types", paginatedRequest(bt.Index))`, which also lacks role enforcement). No timing races, no admin credentials, no host access needed.

### Recommendation
Wrap `bt.Show` (and `bt.Index`) with an appropriate role requirement, e.g. `auth.RequiresEditRole(bt.Show)` or a new minimum-role guard consistent with the sensitivity of `OutgoingToken`/`URL`, and additionally consider redacting `OutgoingToken` from `BridgeResource` for non-privileged roles, or excluding it entirely from `Show`/`Index` responses if it's only needed at creation time.

### Proof of Concept
Go handler-level integration test plan (mirroring existing patterns in `core/web/bridge_types_controller_test.go`):
1. Set up test app with a fixed bridge created via admin-role client (`bt.Create`), capturing the returned `OutgoingToken` from `orm.CreateBridgeType`.
2. Create a second client authenticated with `sessions.ViewRole` (or a view-scoped API token).
3. As the view-role client, issue `GET /v2/bridge_types/<bridgeName>` and assert `http.StatusOK` (currently succeeds because no role wrapper blocks it).
4. Parse the JSON:API response into `presenters.BridgeResource` and assert that `OutgoingToken` equals the value stored in the DB (proving disclosure) and that `URL` matches the bridge's configured URL.
5. Expected secure behavior: the request should be rejected with `403 Forbidden` for view role, or `OutgoingToken`/`URL` should be redacted in the response for non-edit/admin roles.

```go
// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
```
