### Title
Sensitive API user management actions (`Create`, `UpdateRole`, `Delete`) do not emit audit log events - ([File: core/web/user_controller.go])

### Summary
In `core/web/user_controller.go`, the handlers that create, promote/demote, or delete API users omit calls to the audit logger, while comparable sensitive actions in the same controller (password reset, API token creation/deletion) do emit audit events.

### Finding Description
The `UserController` exposes handlers for administrative user management. Several of them call `u.App.GetAuditLogger().Audit(...)` after a sensitive state change succeeds or fails, e.g. `UpdatePassword` emits `audit.PasswordResetSuccess`/`audit.PasswordResetAttemptFailedMismatch` [1](#0-0) , `NewAPIToken` emits `audit.APITokenCreated`/`audit.APITokenCreateAttemptPasswordMismatch` [2](#0-1) , and `DeleteAPIToken` emits `audit.APITokenDeleted`/`audit.APITokenDeleteAttemptPasswordMismatch` [3](#0-2) .

In contrast, the equally (or more) sensitive `Create` function, which creates a brand-new API user with an admin-configurable role, contains no audit call at all after successfully calling `AuthenticationProvider().CreateUser` [4](#0-3) . Likewise, `UpdateRole`, which escalates or de-escalates a user's permission level (e.g. to `admin`), returns success with no audit event emitted after `AuthenticationProvider().UpdateRole` succeeds [5](#0-4) . `Delete`, which removes an API user and purges sessions, similarly emits no audit event on success or failure [6](#0-5) .

I searched `core/logger/audit/audit_types.go` for existing "User"-related audit event constants and found none, confirming that no dedicated audit event type exists for user creation, role change, or deletion — this is a genuine gap in the audit event catalog, not merely a missed call to an existing constant.

### Impact Explanation
This maps to the reported bug class (sensitive state-changing actions that don't emit events for off-chain/monitoring consumers) but translates in this Go codebase to the operator's audit trail rather than a blockchain event log. Because `Create`, `UpdateRole`, and `Delete` bypass the audit logger, an administrator (or operations/SOC team relying on the audit log for security monitoring) has no record of who created a new admin-level API user, who escalated a user's role to `admin`, or who deleted an account. This weakens detection of privilege-escalation abuse by a compromised or malicious admin session, and complicates incident forensics after a credential compromise.

### Likelihood Explanation
These handlers are reachable by any authenticated admin-role API session via the standard `/v2/users` HTTP routes (`POST`, `PATCH`, `DELETE`) [7](#0-6) . Since role/user management is a routine admin operation, the missing audit trail is triggered on every legitimate use, and — more importantly — on every illegitimate use by an attacker who has obtained admin session/API-token access, with no corresponding audit signal generated.

### Recommendation
Add audit log calls analogous to the existing pattern in the same file:
- In `Create`, call `u.App.GetAuditLogger().Audit(audit.UserCreated, map[string]any{"user": user.Email, "role": user.Role})` after successful creation.
- In `UpdateRole`, call `u.App.GetAuditLogger().Audit(audit.UserRoleUpdated, map[string]any{"user": request.Email, "newRole": request.NewRole, "changedBy": sessionUser.Email})` after success.
- In `Delete`, call `u.App.GetAuditLogger().Audit(audit.UserDeleted, map[string]any{"user": email, "deletedBy": sessionUser.Email})` after success.

This requires adding the corresponding new event constants to `core/logger/audit/audit_types.go`, since none currently exist for these actions.

### Proof of Concept
1. Authenticate as an admin user.
2. `POST /v2/users` with `{"email":"attacker@evil.com","password":"...","role":"admin"}` — new admin user created, no audit entry.
3. `PATCH /v2/users` with `{"email":"someuser@example.com","newRole":"admin"}` — privilege escalation, no audit entry.
4. `DELETE /v2/users/:email` — account removed, no audit entry.
5. Compare against `POST /v2/user/tokens` or `PATCH /v2/user/password`, which do produce `audit.APITokenCreated` / `audit.PasswordResetSuccess` entries in the audit log for the same class of sensitive action.

// UpdateRole changes role field of a specified API user.
func (u *UserController) UpdateRole(c *gin.Context) {
	ctx := c.Request.Context()
	type updateUserRequest struct {
		Email   string `json:"email"`
		NewRole string `json:"newRole"`
	}

	var request updateUserRequest
	if err := c.ShouldBindJSON(&request); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	// Don't allow current admin user to edit self
	sessionUser, ok := webauth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}
	if strings.EqualFold(sessionUser.Email, request.Email) {
		jsonAPIError(c, http.StatusBadRequest, errors.New("can not change state or permissions of current admin user"))
		return
	}

	// In case email/role is not specified try to give friendlier/actionable error messages
	if request.Email == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("email flag is empty, must specify an email"))
		return
	}
	if request.NewRole == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("new-role flag is empty, must specify a new role, possible options are 'admin', 'edit', 'run', 'view'"))
		return
	}
	_, err := clsession.GetUserRole(request.NewRole)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("new role does not exist, possible options are 'admin', 'edit', 'run', 'view'"))
		return
	}

	user, err := u.App.AuthenticationProvider().UpdateRole(ctx, request.Email, request.NewRole)
	if err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		jsonAPIError(c, http.StatusInternalServerError, errors.Wrap(err, "error updating API user"))
		return
	}

	jsonAPIResponse(c, presenters.NewUserResource(user), "user")
}

// Delete deletes an API user and any sessions by email
func (u *UserController) Delete(c *gin.Context) {
	ctx := c.Request.Context()
	email := c.Param("email")

	// Attempt find user by email
	user, err := u.App.AuthenticationProvider().FindUser(ctx, email)
	if err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		jsonAPIError(c, http.StatusBadRequest, errors.Errorf("specified user not found: %s", email))
		return
	}

	// Don't allow current admin user to delete self
	sessionUser, ok := webauth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}
	if strings.EqualFold(sessionUser.Email, email) {
		jsonAPIError(c, http.StatusBadRequest, errors.New("can not delete currently logged in admin user"))
		return
	}

	if err = u.App.AuthenticationProvider().DeleteUser(ctx, email); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		u.App.GetLogger().Errorw("Error deleting API user", "err", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("error deleting API user"))
		return
	}

	jsonAPIResponse(c, presenters.NewUserResource(user), "user")
}
