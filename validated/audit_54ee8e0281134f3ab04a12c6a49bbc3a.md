### Title
Per-sender rate limiter bypass via unnormalized `body.Sender` string key vs. checksum-normalized allowlist key - ([File: core/capabilities/webapi/trigger/trigger.go])

### Summary
In `triggerConnectorHandler.processTrigger`, the allowlist check normalizes the sender address via `ethCommon.HexToAddress(body.Sender).String()` (checksummed canonical form), but the rate limiter uses the raw, unnormalized `body.Sender` string as the map key. An attacker who controls the raw hex casing of the `Sender` field in a signed gateway `Message` can vary that string per request (lowercase, uppercase, mixed-case, differently-zero-padded hex) while still passing the allowlist check and while `ethCommon.HexToAddress` produces the same canonical `sender` for the allowlist/topic checks — but each distinct raw string spawns a new per-sender rate-limiter bucket, defeating the per-sender quota.

### Finding Description
`HandleGatewayMessage` derives `sender := ethCommon.HexToAddress(body.Sender)` [1](#0-0)  and passes both `body` (with the raw string) and `sender` (normalized `common.Address`) into `processTrigger`. Inside `processTrigger`, the allowlist check uses the normalized value: `trigger.allowedSenders[sender.String()]` [2](#0-1) , but the very next check calls `trigger.rateLimiter.Allow(body.Sender)` using the raw, attacker-supplied string instead of the normalized `sender.String()` [3](#0-2) .

The `RateLimiter.Allow` implementation keys its per-sender token bucket map directly off the string argument with no normalization: `senderLimiter, ok := rl.perSender[sender]` [4](#0-3)  (the `ratelimit` package used by trigger.go, `github.com/smartcontractkit/chainlink-common/pkg/ratelimit`, follows the same per-sender map keying pattern demonstrated here).

Because Go's `ethCommon.HexToAddress` parses hex case-insensitively and normalizes internally to a fixed 20-byte `Address`, `sender.String()` will be identical (EIP-55 checksummed) regardless of the casing/padding the attacker used in the raw JSON `Sender` field. So an attacker holding one valid signing key can:
1. Compute a valid signature for the message body (signature covers the flattened body bytes including whatever `Sender` string was placed there).
2. Send N requests where `body.Sender` differs only in hex letter casing (e.g. `0xABCDEF...`, `0xabcdef...`, `0xAbCdEf...`) for the same underlying address.
3. Each variant passes `allowedSenders[sender.String()]` (since it normalizes), but each is treated as a distinct rate-limiter bucket key, so the per-sender RPS/burst limit never accumulates across variants — only the (typically much higher) global limiter constrains it.

This assumes the signature-body binding does not reject case variation — the `Message` signature is computed over the raw serialized body bytes, so different casing of `Sender` does produce a different signed payload and thus a different valid signature for the *same* private key (the signer can freely choose the casing when constructing and signing the message, since standard ECDSA signing operates over whatever bytes are hashed). No additional check was found in `core/services/gateway/api/message.go` that enforces canonical (single-case) formatting of `body.Sender` before rate limiting; only `msg.Validate()` runs to check general well-formedness, and the normalized address is only used for the allowlist and downstream `TriggerEventID` computation, not for the rate limiter key.

### Impact Explanation
This allows a holder of one valid signing key (matching an entry in `allowedSenders`) to bypass the per-sender rate limit entirely by rotating hex casing across requests, since the allowlist check normalizes but the rate limiter does not. This maps to the "quota/allowlist bypass" impact class — enabling trigger-flooding/DoS against a workflow's trigger channel (`trigger.ch`, buffered at `defaultSendChannelBufferSize` = 1000 [5](#0-4) ) and unrestricted repeated invocation of `events.EmitTriggerExecutionStarted`/workflow triggering beyond intended per-sender throttling, only bounded by the (typically much higher) global rate limit.

### Likelihood Explanation
Requires only possession of one valid signing key already present in a workflow's `allowedSenders` list (an unprivileged capability the audited threat model explicitly grants: "attacker holds any valid signing key"). No additional privilege, secret, or race condition is needed — simply varying casing of a hex string in a JSON field before signing and resending. This is trivial and fully repeatable per request.

### Recommendation
Normalize the rate-limiter key the same way the allowlist key is normalized: call `trigger.rateLimiter.Allow(sender.String())` instead of `trigger.rateLimiter.Allow(body.Sender)` in `processTrigger` [6](#0-5) , and likewise use the canonical `sender.String()` (or `sender.Hex()`) consistently wherever a sender identity is used as a map/lookup key (including `TriggerEventID := body.Sender + payload.TriggerEventId` at line 111, which should also use the canonical address to avoid similar identity-confusion issues in execution-ID generation).

### Proof of Concept
Go unit test plan in `core/capabilities/webapi/trigger/trigger_test.go` (or new test file):
1. Register a trigger via `RegisterTrigger` with `AllowedSenders: []string{"<checksummed address>"}`, `AllowedTopics: []string{"topic1"}`, and a tight `RateLimiter` config (e.g. `PerSenderRPS: 1, PerSenderBurst: 1`).
2. Construct N (>2) valid signed `jsonrpc.Request` messages for `MethodWebAPITrigger`, each with the *same* signing key and same logical sender address, but with `Body.Sender` set to different casings of the same hex string (lowercase, uppercase, EIP-55 checksummed) and valid signatures over each respective body.
3. Call `HandleGatewayMessage` for each message in quick succession.
4. Assert: with the current code, all N requests succeed / are accepted (`ACCEPTED` response, `trigger.ch` receives N events) despite `PerSenderBurst=1`, demonstrating rate-limit bypass.
5. After applying the fix (`Allow(sender.String())`), assert only the first request is accepted and subsequent ones return `Status: "ERROR"` with a rate-limited message, regardless of casing variation.

func (rl *RateLimiter) Allow(sender string) (senderAllow bool, globalAllow bool) {
	rl.mu.Lock()
	senderLimiter, ok := rl.perSender[sender]
	if !ok {
		senderLimiter = rate.NewLimiter(rate.Limit(rl.config.PerSenderRPS), rl.config.PerSenderBurst)
		rl.perSender[sender] = senderLimiter
	}
	rl.mu.Unlock()
