Based on my review, marginfi's fee-accounting design differs fundamentally from the pattern described in the report. In `lending_account_deposit` (`programs/marginfi/src/instructions/marginfi_account/deposit.rs`), the shares credited to a user are always tied to `deposit_amount`, and any Token-2022 transfer fee is deducted by the SPL token program itself (via `calculate_pre_fee_spl_deposit_amount`/`transfer_checked_with_fee`) — the vault receives exactly `deposit_amount`, matching the shares minted, so nothing is stranded inside the program's custody. [1](#0-0) 

Similarly, interest/origination fees are never silently retained mid-transaction; they are recorded in explicit tracked fields (`collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, `collected_program_fees_outstanding`) and later swept out via the permissionless `lending_pool_collect_bank_fees` instruction. [2](#0-1) 

For the wrapped-integration withdraw paths (Drift/JupLend/Kamino), any rounding "dust" either stays inside the external protocol's own accounting (e.g., Drift's `scaled_balance` buffer) rather than in a marginfi-controlled vault, or is proven unreachable (JupLend), and this is explicitly verified by fuzz invariants asserting the intermediary/liquidity vaults return to their pre-transaction balances. [3](#0-2) [4](#0-3) 

There is no marginfi code path where the program pulls a full amount from a user, forwards only a fee-reduced portion to an underlying protocol, and leaves the residual difference held by the program with no tracking or withdrawal path — the bug class described in the P2P Yield Proxy report does not have a reachable analog in this codebase.

    // Handle potential dust case where remaining shares are worth less than 1 underlying unit.
    //
    // NOTE: Unlike Drift (which has reachable dust due to double-rounding in its
    // assets → scaled_balance → assets conversion), this case is UNREACHABLE in JupLend
    // under normal operation because:
    //
    // - JupLend uses single-level math: shares = floor(assets * 1e12 / price)
    // - Minimum shares = 1 (u64 integer, not fractional)
    // - Exchange price >= 1e12 (starts at 1:1, only increases with yield)
    // - Therefore: floor(1 * 1e12 / 1e12) = 1 (always at least 1 underlying)
    //
    // Drift's dust is reachable because it uses multi-step rounding:
    // 1. assets → scaled_balance (floor + variable precision per token)
    // 2. scaled_balance + 1 (round up for safety)
    // 3. scaled_balance → assets (floor again)
    // This cascading rounding can produce 0 tokens from small positions.
    //
    // This defensive code exists for potential edge cases:
    // - Socialized loss reducing JupLend's exchange price below 1e12
    // - Future protocol changes affecting share/price invariants
    //
    // If we can guarantee that JupLend's exchange price never drops below 1e12, this branch is dead code.
