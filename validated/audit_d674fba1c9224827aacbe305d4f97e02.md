### Title
Zip archive two-pass extraction lets duplicate-named entries redirect `Chtimes`/`chmod` metadata calls onto an attacker-chosen symlink target outside the extraction root - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` extracts every entry in a first loop, then in a second loop applies `lchmod` and `processZipExtra` (`Chtimes`/`Lchown`) to every entry using the *original* `FileHeader`, without re-checking what currently occupies `file.Name` on disk. A zip with two entries sharing the same `Name` — first a regular file, then a symlink pointing outside the workspace — lets the symlink win the first pass, and the second pass then runs metadata operations for the *regular-file* entry against that now-symlinked path.

### Finding Description
`archive/zip.Reader.File` does not deduplicate or reorder entries with identical `Name` values, so a crafted zip can contain entry A (regular file at path `P`) followed by entry B (symlink at the same path `P`, with attacker-controlled link target, e.g. an absolute path or `../../` escape) [1](#0-0) .

First loop: `extractZipFileEntry` writes the regular file for A at `P`; `extractZipSymlinkEntry` then removes `P` and replaces it with a symlink for B [2](#0-1) . After the first loop, `P` is a symlink to an attacker-chosen target.

Second loop iterates `archive.File` again in the same order and, for entry A's `FileHeader` (still describing a regular file named `P`), calls `lchmod(P, A.Mode())` and `processZipExtra(&A.FileHeader)` [3](#0-2) .

- `lchmod` on Linux only special-cases `mode&os.ModeSymlink != 0`; since A's mode is a regular file, it falls through and calls `unix.Fchmodat(..., flags=0)`, i.e. it **follows** the symlink now sitting at `P` and chmods whatever B's symlink points to [4](#0-3) .
- `processZipTimestampField` calls `os.Chtimes(file.Name, ...)`, which always follows symlinks (no `L`-variant is used), so if A carried a Unix timestamp extra field, the target of B's symlink gets its mtime rewritten [5](#0-4) .
- `processZipUIDGidField` uses `os.Lchown`, which does **not** follow symlinks, so ownership changes are not affected by this path [6](#0-5) .

No code re-verifies, before the second pass, that `file.Name` still refers to the file type that was actually extracted for that specific entry; the metadata operations are keyed purely on the stale `FileHeader`.

### Impact Explanation
An attacker who controls a zip that gets extracted by `ExtractZipArchive` (cache/artifact extraction) can force `os.Chtimes` (any OS) and `chmod` via `Fchmodat` (Linux) to operate on an arbitrary filesystem path reachable by a symlink, instead of the intended extraction-root file — subject only to the OS permissions of the process user. This is an out-of-tree metadata write (mtime/permission bits) on a shared filesystem, matching the "cross-project file corruption via entry-order TOCTOU under shared extraction roots" scope when caches/artifacts of multiple jobs/projects extract into a common root under the same OS user.

### Likelihood Explanation
Feasible and fully attacker-controlled: duplicate `Name` values in a zip are valid per the zip format and Go's `archive/zip` parser does not reject or dedupe them, and symlink target content is arbitrary text controlled by the attacker in `extractZipSymlinkEntry`. The only requirement is that the attacker can supply/influence the cache or artifact zip content extracted by Runner (a normal CI job author can trivially produce such an archive as a cache/artifact). The bug is deterministic given entry ordering, not a race condition, so it is fully repeatable.

### Recommendation
In the second pass, verify the on-disk file type still matches `file.FileHeader.Mode()` before applying `lchmod`/`Chtimes`/`Lchown` (e.g., `os.Lstat(file.Name)` and compare mode types, skipping or erroring on mismatch). Alternatively, merge metadata application into the first extraction pass immediately after each entry is written, and use symlink-safe syscalls throughout (`Chtimes` has no safe variant in the standard library, so an `Lstat`-based mode check before calling it is necessary) so a later entry can never redirect metadata operations belonging to an earlier entry.

### Proof of Concept
Go test in `helpers/archives`:
1. Build an in-memory zip with two `zip.FileHeader` entries sharing `Name = "victim"`: entry A as a regular file with content and a Unix timestamp extra field (`ZipTimestampFieldType`) set to a known `modTime`; entry B as a symlink (`Mode = os.ModeSymlink`) whose body is the string `"../outside/target"` (a file created ahead of time outside the extraction directory).
2. Call `ExtractZipArchive` with this archive rooted in a temp extraction directory.
3. Assert:
   - `os.Lstat(filepath.Join(tmpDir, "victim"))` reports a symlink (confirms B won the first pass).
   - `os.Stat("../outside/target")`'s `ModTime()` equals A's `modTime` (proves `Chtimes` followed the symlink and modified the external target instead of failing/no-oping).
   - (Linux only) the external target's permission bits equal A's `Mode().Perm()` (proves `chmod` followed the symlink).
4. A passing/correct implementation should leave the external target file's mtime/permissions unmodified, or should error out instead of silently writing outside the extraction root.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
```

func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```

func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
