### Title
Loss-adjusted withdraw receipts are paid in full after a later request overwrites `lastWithdrawRequest` (index-hijack of the haircut lookup) — ([contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`IdleCreditVault` records the epoch of each normal withdraw request per user (`withdrawsRequestsByEpoch[user][epoch]`) but tracks only a single scalar `lastWithdrawRequest[user]` as the lookup key for loss-adjusted payouts. When a `stopEpochWithDuration` loss haircuts pending receipts (`collectWithdrawFunds` stores `lossRecoveryPriceByEpoch[epochNumber]` and zeroes `pendingWithdraws`), a user who makes **any subsequent withdraw request** overwrites `lastWithdrawRequest`. The loss-adjusted claim path then reads `lossRecoveryPriceByEpoch[newEpoch] == 0` and returns early, while the haircut epoch-N basis remains inside `withdrawsRequests[user]` and is paid **at par** by `_claimFundedWithdrawRequest`. The vault only collected `basis * lossRecoveryPrice` from the borrower, so the difference is drained from funds backing other users — a direct solvency break.

This mirrors CVE-2022-36041: an index derived from attacker-controlled input writes/reads the wrong accounting slot, corrupting the payout ledger.

### Finding Description
- `requestWithdraw` writes per-epoch basis and sets `lastWithdrawRequest[_user] = currentEpoch` (`IdleCreditVault.sol:282-294`).
- `collectWithdrawFunds` on partial funding stores `lossRecoveryPriceByEpoch[epochNumber]` and clears `pendingWithdraws`, but does **not** reduce `withdrawsRequests[_user]` (`IdleCreditVault.sol:411-430`).
- `_claimLossAdjustedWithdrawRequest` uses `lossEpoch = lastWithdrawRequest[_user]` as the only index into `lossRecoveryPriceByEpoch` (`IdleCreditVault.sol:789-800`). If the user's *latest* request epoch has no haircut entry, it returns 0 — the older haircut epoch's entry is never reachable again.
- `claimWithdrawRequest` then falls through to `_claimFundedWithdrawRequest`, which requires only `epochNumber > lastWithdrawRequest[_user]` and pays the full aggregate `withdrawsRequests[_user]` (which still includes the epoch-N haircut basis) at par (`IdleCreditVault.sol:301-350`).
- `_transferFundedClaim` only shields `defaultRecoveryReserve`; it happily spends any other underlying sitting in the vault (`IdleCreditVault.sol:897+`).

Broken invariant: loss waterfall / one-receipt-one-payout — a haircut pending receipt must never be paid above `lossRecoveryPriceByEpoch`.

### Impact Explanation
Attacker gain = `(1 − lossRecoveryPrice) × attackerBasis` per claim. The vault collected only `attackerBasis × lossRecoveryPrice` for that receipt, so the excess is paid out of underlying belonging to active LPs and other claimants — direct theft/unrecoverable insolvency proportional to the realized loss size and the attacker's share of pending withdrawals. Repeating across epochs amplifies it.

### Likelihood Explanation
Requires a `stopEpochWithDuration` stop with `_lossAmount > 0` while pending receipts exist (manager-driven, honest). Any pending withdrawer — an unprivileged KYC'd tranche holder — then only needs to call `cdoEpoch.requestWithdraw` again in the next epoch and `claimWithdrawRequest` after it matures. No privileged collusion, no oracle manipulation; the trigger sequence is ordinary user behavior, so incidental triggering is also plausible.

### Recommendation
Track the loss-adjusted epoch explicitly instead of inferring it from `lastWithdrawRequest`. Either:
- iterate/record the user's haircut epoch (e.g. store `lossEpoch` in per-user data or scan `withdrawsRequestsByEpoch` keys the user owes), or
- in `_clearWithdrawClaimForEpoch`/request path, when `lossRecoveryPriceByEpoch[lastWithdrawRequest]` was superseded, split `withdrawsRequests[_user]` into per-epoch pieces and pay each with its own recovery price (par for non-loss epochs).
At minimum, revert in `requestWithdraw` when the user still has an unclaimed loss-adjusted receipt.

### Proof of Concept
Foundry fork PoC (sketch, against `test/foundry/IdleCreditVault.t.sol` harness):

```solidity
function testLossHaircutBypassedByLaterRequest() external {
    // epoch 0: deposit, run, stop -> epoch 1 buffer
    uint256 minted = idleCDO.depositAA(100_000 * ONE_SCALE);
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, apr, _expectedFundsEndEpoch());

    // attacker requests withdraw in epoch 1
    uint256 basis = cdoEpoch.requestWithdraw(minted / 2, address(AAtranche));
    uint256 lossEpoch = strategy.epochNumber(); // == 1

    _startEpochAndCheckPrices(1);

    // borrower funds only 50% of pending -> lossRecoveryPriceByEpoch[1] = 0.5e18
    // (via cdoEpoch.stopEpochWithDuration(apr, interest, duration, lossAmount)
    //  where previewLossAdjustedWithdrawFunds gives pendingToFund = basis/2)
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(underlying, borrower, fundsNeeded);
    cdoEpoch.stopEpochWithDuration(apr, interest, duration, lossAmount);
    assertEq(strategy.lossRecoveryPriceByEpoch(lossEpoch), 5e17);

    // epoch 2 buffer: attacker requests again -> lastWithdrawRequest = 2
    uint256 basis2 = cdoEpoch.requestWithdraw(1, address(AAtranche));

    _startEpochAndCheckPrices(2);
    _stopEpochAndCheckPrices(2, apr, _expectedFundsEndEpoch()); // epoch 3, epoch-2 request funded at par

    // claim: lossRecoveryPriceByEpoch[2] == 0 -> skip; withdrawsRequests
    // still contains basis + basis2 -> paid fully at par
    uint256 balPre = underlying.balanceOf(attacker);
    cdoEpoch.claimWithdrawRequest();
    assertEq(underlying.balanceOf(attacker) - balPre, basis + basis2);
    // vault only received basis*0.5 + basis2 -> paid basis*0.5 too much,
    // draining funds owed to other claimants / active NAV
}
```

```text
    _onlyIdleCDO();
    uint256 pendingBasis = pendingWithdraws;
    if (_amount < pendingBasis) {
      // Legacy receipts do not have per-epoch ownership data, so they can only be fully funded.
      if (!defaultRecoveryInitialized) revert NotAllowed();
```

```text
  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
```
