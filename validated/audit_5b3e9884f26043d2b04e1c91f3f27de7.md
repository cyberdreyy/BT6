### Title
Unvalidated mint-account ownership in JSON-parsed SPL token RPC responses allows misreporting of token balances/decimals — ([File: rpc/src/parsed_token_accounts.rs])

### Summary
Several `jsonParsed`-encoding RPC code paths resolve a token account's "mint" field to fetch the referenced mint account and derive `decimals`/extension config for UI display, but they never verify that the fetched mint account is actually owned by a legitimate SPL Token / Token-2022 program. This mirrors the report's root cause — trusting a referenced address to hold expected code/state without checking it actually does — allowing a stale/repurposed mint address to make the RPC report fabricated balances/decimals for an otherwise legitimate, unchanged token account.

### Finding Description
`get_mint_owner_and_additional_data` fetches the mint account and immediately unpacks its data as an SPL `Mint` via `get_additional_mint_data`, without checking that the account is owned by a known token program: [1](#0-0) 

`get_additional_mint_data` blindly calls `StateWithExtensions::<Mint>::unpack(data)` on whatever bytes are stored at that address: [2](#0-1) 

This helper is used, without any owner check on the returned mint account, by:
- `get_parsed_token_account`/`get_parsed_token_accounts` (backs `getAccountInfo`, `getMultipleAccounts`, `getProgramAccounts`, `getTokenAccountsByOwner` with `encoding: jsonParsed`, and account/program subscriptions): [3](#0-2) 
- `get_token_account_balance` (backs `getTokenAccountBalance`), which discards the returned mint owner (`let (_, data) = ...`) and never validates it: [4](#0-3) 

By contrast, sibling code paths in the same file *do* perform this validation — `get_token_supply` checks `is_known_spl_token_id(mint_account.owner())` directly, and `get_token_largest_accounts` / `get_token_program_id_and_mint` check `is_known_spl_token_id(&mint_owner)` on the value returned by `get_mint_owner_and_additional_data`: [5](#0-4) [6](#0-5) 

The SVM's own internal token-balance collector also demonstrates the correct pattern, explicitly rejecting a mint whose owner doesn't match the token account's program: [7](#0-6) 

This is the same class of bug as the external report: code that consumes a user/account-referenced address (a token's "mint" field / an ERC-20 token address) and performs privileged-looking operations (decoding as `Mint` / transferring as ERC-20) without verifying the referenced address currently holds the expected program/code.

### Impact Explanation
A legitimately-created (unmodified) SPL token account's raw `amount` is a fixed integer; the human-readable `uiAmount`/decimals come entirely from whatever is currently stored at the account's `mint` field address. If that mint address is later repurposed (e.g., a Token-2022 mint using the `MintCloseAuthority` extension is closed to zero lamports and the same address is recreated under attacker control with crafted "Mint-shaped" data and arbitrary decimals/extension fields), subsequent unprivileged calls to `getTokenAccountBalance`, `getAccountInfo`/`getMultipleAccounts`/`getProgramAccounts`/`getTokenAccountsByOwner` with `encoding: jsonParsed`, or account/program-subscription notifications will report a wrong (attacker-chosen) `uiAmount`/decimals/extension state for that token account, without the account's actual raw balance changing. This is a wrong-account-data-returned condition triggered by a single low-cost RPC query, matching the stated acceptance criteria.

### Likelihood Explanation
Reaching this requires only unprivileged actions: creating a Token-2022 mint with the `MintCloseAuthority` extension, using it as a real token account's mint, closing the mint once its supply is 0, and recreating an account at the same address with fabricated data — all standard token-2022/system-program operations, no validator or protocol privilege needed. The RPC call itself (`getTokenAccountBalance`/`getAccountInfo` with `jsonParsed`) is a single unauthenticated request.

### Recommendation
In `get_mint_owner_and_additional_data` (and callers `get_parsed_token_account`, `get_parsed_token_accounts`, `get_token_account_balance`), verify `is_known_spl_token_id(mint_account.owner())` (and ideally that it matches the token account's own owning program) before trusting the unpacked `Mint` data, mirroring the checks already used in `get_token_supply` and `get_token_program_id_and_mint`, and the ownership check in `svm/src/transaction_balances.rs::unpack_token_account`.

### Proof of Concept
1. Create a Token-2022 mint `M` with the `MintCloseAuthority` extension and decimals = 9; create token account `A` with `mint = M`, mint 100 tokens to `A` (raw amount = 100 * 10^9).
2. Burn all supply of `M` to 0, then close `M` via the extension's close instruction, reclaiming all lamports (account `M` is purged from state, same pubkey still under attacker's keypair control).
3. Recreate account at pubkey `M` (same address) owned by an attacker-controlled program, writing bytes matching `spl_token_2022_interface::state::Mint`'s packed layout with `decimals = 0` (or any arbitrary value) and no extensions.
4. Call `getTokenAccountBalance(A)` or `getAccountInfo(A, {"encoding":"jsonParsed"})` against the RPC node — the returned `uiAmount`/`decimals` will reflect the attacker-chosen decimals from the bogus re-created account at `M`, misreporting `A`'s actual token balance, even though `A`'s raw on-chain `amount` field never changed.

pub fn get_parsed_token_accounts<I>(
    bank: Arc<Bank>,
    keyed_accounts: I,
) -> impl Iterator<Item = RpcKeyedAccount>
where
    I: Iterator<Item = (Pubkey, AccountSharedData)>,
{
    let mut mint_data: HashMap<Pubkey, AccountAdditionalDataV3> = HashMap::new();
    keyed_accounts.filter_map(move |(pubkey, account)| {
        let additional_data = get_token_account_mint(account.data()).and_then(|mint_pubkey| {
            mint_data.get(&mint_pubkey).cloned().or_else(|| {
                let (_, data) = get_mint_owner_and_additional_data(&bank, &mint_pubkey).ok()?;
                let data = AccountAdditionalDataV3 {
                    spl_token_additional_data: Some(data),
                };
                mint_data.insert(mint_pubkey, data);
                Some(data)
            })
        });

        let maybe_encoded_account = encode_ui_account(
            &pubkey,
            &account,
            UiAccountEncoding::JsonParsed,
            additional_data,
            None,
        );
        if let UiAccountData::Json(_) = &maybe_encoded_account.data {
            Some(RpcKeyedAccount {
                pubkey: pubkey.to_string(),
                account: maybe_encoded_account,
            })
        } else {
            None
        }
    })
}

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}

impl SvmTokenInfo {
    fn unpack_token_account<CB: TransactionProcessingCallback>(
        account_loader: &mut AccountLoader<CB>,
        account: &AccountSharedData,
        index: usize,
    ) -> Option<Self> {
        let program_id = *account.owner();
        let generic_token::Account {
            mint,
            owner,
            amount,
        } = generic_token::Account::unpack(account.data(), &program_id)?;

        let mint_account = account_loader.load_account(&mint)?;
        if *mint_account.owner() != program_id {
            return None;
        }

        let generic_token::Mint { decimals, .. } =
            generic_token::Mint::unpack(mint_account.data(), &program_id)?;

        Some(Self {
            account_index: index.try_into().ok()?,
            mint,
            amount,
            owner,
            program_id,
            decimals,
        })
    }
