## Title
Missing zero-address validation in `set_beneficiary_for_operator` permanently locks staker's unlocked stake and commission - (File: aptos-move/framework/aptos-framework/sources/staking_contract.move)

### Summary
`staking_contract::set_beneficiary_for_operator` lets an operator set their commission-payout beneficiary to any address, including `@0x0`, with no validation. [1](#0-0)  Unlike `vesting::set_beneficiary`, which explicitly requires `assert_account_is_registered_for_apt(new_beneficiary)` before accepting a new beneficiary, `staking_contract::set_beneficiary_for_operator` and its `delegation_pool` analog perform no such check. [2](#0-1) [3](#0-2) 

### Finding Description
`distribute_internal` (invoked by the permissionless `distribute()` entry function and internally by `switch_operator`) iterates over all shareholders of a `StakingContract`'s `distribution_pool`, redeeming shares and paying out via `aptos_account::deposit_coins`, and specifically redirects the operator's own share to `beneficiary_for_operator(operator)`. [4](#0-3) 

`aptos_account::deposit_coins` auto-creates the recipient account via `account::create_account` if it does not already exist. [5](#0-4)  Account creation aborts if the target address equals a reserved address, explicitly including `@vm_reserved` (i.e. `0x0`). [6](#0-5) 

Because `set_beneficiary_for_operator` never validates `new_beneficiary`, an operator can set their beneficiary to `@0x0`. From that point on:
- Every call to `distribute()` for that staking contract will iterate the distribution pool, reach the operator's redirected recipient (`@0x0`), and abort inside `aptos_account::deposit_coins` → `account::create_account(@0x0)`.
- `switch_operator` calls `distribute_internal` first (to force-pay any already-inactive stake) before it can change the operator, so it also aborts under the same condition. [7](#0-6) 

Since Move transactions revert entirely on abort, the staker's own redeemed shares (which may be processed earlier in the same loop) are rolled back along with everything else — there is no partial success. The staker who owns the underlying stake has no code path left to force a payout or replace the operator once this state is set, because both recovery paths (`distribute`, `switch_operator`) share the same vulnerable `distribute_internal` call.

### Impact Explanation
This permanently traps the staker's already-unlocked/inactive stake and rewards inside the `StakingContract`'s `distribution_pool`, with no available recovery path in the module, because both the normal payout function (`distribute`) and the operator-replacement function (`switch_operator`) are blocked by the same abort. This satisfies "Permanent lock or non-recoverable loss of claim rights in stake ... commission ... flows" and "Operator commission ... payout ... corruption that ... traps value," since the root cause is entirely in `staking_contract.move`/`aptos_account.move` and affects the staker, a party distinct from the operator who triggered the state.

### Likelihood Explanation
Likelihood is limited by two factors I could not fully rule out without deeper tracing:
1. `set_beneficiary_for_operator` is gated by `features::operator_beneficiary_change_enabled()`, so it requires this feature flag to be active. [8](#0-7) 
2. I was unable to fully verify (due to iteration limits) whether `request_commission_internal`, which is also called by `switch_operator` before `distribute_internal`, has any separate zero-address-safe payout path that could bypass the lock, or whether the trigger requires the operator to be adversarial rather than merely careless (any operator, without any special privilege over the staker's funds, can call this function for themselves).

Given that `set_beneficiary_for_operator` is callable by any operator signer with no cross-checks against the staking pool, and the trigger is a single low-cost transaction, likelihood is plausible but not fully confirmed as guaranteed-exploitable without further live testing.

### Recommendation
Add the same validation used in `vesting::set_beneficiary` to `staking_contract::set_beneficiary_for_operator` and `delegation_pool::set_beneficiary_for_operator`: reject `new_beneficiary == @0x0` and/or require `assert_account_is_registered_for_apt(new_beneficiary)` before committing the change. Additionally, consider hardening `distribute_internal` to skip/handle failed payouts to a single shareholder without reverting the entire batch, so that one corrupted beneficiary cannot block payouts to all other shareholders.

### Proof of Concept
1. Staker creates a staking contract with `operator` via `create_staking_contract`. [9](#0-8) 
2. `operator` calls `set_beneficiary_for_operator(operator, @0x0)` — succeeds with no validation. [1](#0-0) 
3. Stake becomes unlocked/inactive for the staker (via `unlock_stake` + epoch progression).
4. Anyone calls `distribute(staker, operator)`; `distribute_internal` reaches the operator's redirected recipient `beneficiary_for_operator(operator) == @0x0`, and `aptos_account::deposit_coins(@0x0, ...)` aborts inside `account::create_account(@0x0)` because `@0x0 == @vm_reserved`. [10](#0-9) 
5. Staker attempts to route around this via `switch_operator`, but it calls `distribute_internal` first and hits the identical abort, leaving the staker with no way to retrieve their unlocked funds. [11](#0-10) 

**Note on confidence**: I could not execute this scenario live (no test/terminal access in this mode), so this analysis is based on static code tracing. I recommend a Devin session with Move test execution to confirm the exact abort behavior end-to-end (particularly whether `request_commission_internal` inside `switch_operator` might independently revert first, and whether `features::operator_beneficiary_change_enabled()` is enabled by default on mainnet), and to check whether an equivalent lock exists in `delegation_pool.move`'s commission distribution path.

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
