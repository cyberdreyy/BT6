### Title
`depositDuringEpoch` executes while the vault is paused — mid-epoch deposits bypass `pause()` (File: contracts/IdleCDOEpochVariant.sol)

### Summary
The external report's bug class — a public function that is not restricted during a paused contract state — maps directly onto `IdleCDOEpochVariant.depositDuringEpoch`. Every ordinary deposit path in the vault is gated by `whenNotPaused` (`_deposit` at `contracts/IdleCDOEpochVariant.sol:644`), but `depositDuringEpoch` (lines 656–733) has no `paused()` check and no `whenNotPaused` modifier. Its `_checkNotAllowed` guard rejects on `skipDefaultCheck`, `isDepositDuringEpochDisabled`, `isProgrammableBorrower`, `isAYSActive`, `!isEpochRunning`, etc. — but `paused()` is never consulted. A plain `pause()` (or `unpause()`-blocked state) therefore does not stop mid-epoch deposits: funds are pulled from the caller, strategy tokens are minted, and underlying is forwarded to the borrower while the contract is paused.

### Finding Description
- `pause()` at `contracts/IdleCDOEpochVariant.sol:518` (inherited `IdleCDOCreditVault.pause`) only calls `_pause()`. It does **not** set `skipDefaultCheck`, `isDepositDuringEpochDisabled`, or clear `isEpochRunning`.
- `_emergencyShutdown` (lines 602–615) sets `skipDefaultCheck = true`, which *does* block `depositDuringEpoch` — so the developers clearly intend mid-epoch deposits to be halted in an emergency. But the lighter-weight `pause()` leaves a gap: the check list at lines 658–669 contains `skipDefaultCheck` yet omits `paused()`.
- `_beforeUnpause` (lines 634–637) blocks `unpause()` while `isEpochRunning || skipDefaultCheck`, showing that a paused-during-epoch state is a real, persistent configuration — not a transient one.
- Result: while paused with an epoch running and `skipDefaultCheck == false`, any KYC-allowed wallet calls `depositDuringEpoch(amount, tranche)`. The function mints shares via `_mintShares`, calls `IdleCreditVault(strategy).mintStrategyTokens(_amount)`, and transfers underlying to `_borrower()` (lines 724–732) — a full state-changing deposit succeeding in a paused contract, exactly the SimpleShares `distribute` analog.

### Impact Explanation
Pause is the guardian's tool to halt deposits when suspicious activity or a borrower concern is detected without triggering the full emergency/default machinery. Because `depositDuringEpoch` is unguarded:
- An unprivileged, KYC-passed lender (explicitly an allowed attacker role) can keep pushing underlying to the borrower while the vault is paused, defeating the pause's purpose of stopping value inflow.
- If the guardian paused because of an impending borrower failure, the attacker deposits into a doomed epoch; the resulting loss is socialized across all tranche holders per the BB-first waterfall, diluting existing holders' recovery. The minted shares are priced on `expectedFinal` NAV computed from `expectedEpochInterest`, so a default after the deposit transfers part of the loss onto pre-existing holders who could not exit (requests are only selectively enabled).
- Quantified worst case: any amount up to the deposit cap can be pushed in; loss borne by existing holders equals `attackerDeposit × lossFraction` that would otherwise have fallen entirely on the attacker.

### Likelihood Explanation
Requires (a) an epoch running with `isDepositDuringEpochEnabled` and `isAYSActive == false` and a non-programmable borrower, and (b) owner/guardian calling `pause()` rather than `emergencyShutdown()` during the epoch. `pause()` is a documented, distinct action ("Pauses deposits", guardian-callable), so configuration (b) is a legitimate operational state. The attacker then needs only `isWalletAllowed(msg.sender)` — a KYC-passing lender, an in-scope attacker class. Likelihood is moderate: it needs the specific epoch+pause configuration, but no privileged misbehavior and no race.

### Recommendation
Add `whenNotPaused` to `depositDuringEpoch` (or add `paused()` to the `_checkNotAllowed` clause at lines 658–669). If mid-epoch deposits are intentionally allowed during a plain pause, document that explicitly and ensure guardian playbooks use `emergencyShutdown()` whenever inflow must stop; otherwise the pause flag should uniformly block all deposit paths, matching `_deposit`'s `whenNotPaused` guard.

### Proof of Concept
Reproducible Foundry test (fork setup as in `test/foundry/IdleCreditVault.t.sol`, e.g. `testRestoreOperationsDuringEpochOnlyRestoresMidEpochDeposits` at lines 5010–5053):

```solidity
function testDepositDuringEpochWhilePaused() external {
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    vm.startPrank(owner);
    cdoEpoch.setIsAYSActive(false);
    cdoEpoch.setIsDepositDuringEpochDisabled(false);
    vm.stopPrank();
    _startEpochAndCheckPrices(0);           // epoch running

    vm.prank(owner);                        // or guardian
    cdoEpoch.pause();                       // plain pause: skipDefaultCheck stays false
    assertTrue(cdoEpoch.paused());

    address user = makeAddr('paused-depositor');
    deal(defaultUnderlying, user, 1_000 * ONE_SCALE);
    _kycUser(user);                          // isWalletAllowed == true
    vm.startPrank(user);
    underlying.approve(address(cdoEpoch), 1_000 * ONE_SCALE);
    // BUG: succeeds despite paused() == true; underlying sent to borrower
    cdoEpoch.depositDuringEpoch(1_000 * ONE_SCALE, address(AAtranche));
    vm.stopPrank();
}
```

Contrast with `idleCDO.depositAA`, which reverts `Pausable: paused` in the same state (see `testEmergencyShutdown` at `test/foundry/IdleCreditVault.t.sol:5000-5003`).

Note: I was unable to fully verify the KYC-helper wiring (`isWalletAllowed`/Keyring setup) in the test harness within the iteration budget, but `depositDuringEpoch` explicitly checks `isWalletAllowed(msg.sender)`, so the PoC must whitelist the attacker address the same way other tests whitelist depositors.
