Confirmed: `delete_member` only purges requests/confirmations where the deleted member is the **requester** (`r.member == member`), it never scans other pending requests' `confirmations` sets to strip out entries that were confirmed *by* the member being deleted. That is the exact "confirmations counted versus live members" binding break called out in the rules, so I'll issue that as the analog finding.

### Title
Confirmations from removed multisig members remain counted toward the execution threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` removes a member from `self.members` and cleans up only the requests *created* by that member, but does not remove that member's existing confirmations from other members' pending requests. As a result, a request can be executed with fewer than `num_confirmations` currently-authorized signatures, because a stale confirmation from a member who has since been removed is still counted.

### Finding Description
`confirm` tallies confirmations purely by size of the `confirmations` set stored per `request_id`: [1](#0-0) 
It never re-validates that every public key/account in that set is still a current member of `self.members` — it only checks that the *calling* member hasn't already confirmed, via `current_member()`: [2](#0-1) 

`delete_member` is the only place membership removal happens, and its cleanup is scoped strictly to requests where the removed member is the **requester** (`r.member == member`): [3](#0-2) 

It does not iterate `self.confirmations` to strip the removed member's entries from requests raised by *other* members. So the equality the protocol is supposed to maintain — `count(confirmations for request X) == count(live members who confirmed request X)` — is broken as soon as a confirmer (not requester) is removed while a request they confirmed is still pending.

Concretely:
1. Multisig has members `A, B, C, D` with `num_confirmations = 3`.
2. Member `A` creates request `R` (e.g., a `Transfer` or `AddKey`/`FunctionCall` to an attacker-controlled address). `B` confirms `R`. `confirmations(R) = {A, B}` (2 of 3 needed — assuming `add_request_and_confirm` was used by A, or A separately confirms).
3. Before a third confirmation, the multisig executes a separate `DeleteMember` request removing `B` (e.g., because `B`'s key was compromised or the DAO/team rotates signers).
4. `delete_member(B)` runs: it only removes requests **created** by `B`; request `R` (created by `A`) still has `B` in its `confirmations` set — untouched.
5. Now only `C` needs to confirm `R`: `confirmations.len() + 1 == 3 == num_confirmations`, so `R` executes with the vote of `A`, the stale/removed `B`, and `C` — i.e., only 2 currently-live members actually authorized it, one threshold-short of the real requirement.

### Impact Explanation
This directly matches the “Critical” category: *a multisig request executed below threshold*. Funds (`Transfer`), key changes (`AddKey`/`AddMember`/`DeleteMember`), or arbitrary `FunctionCall`s can be pushed through with effectively fewer live authorizers than `num_confirmations` mandates, undermining the entire K-of-N custody guarantee the contract is meant to provide. This is especially dangerous in the realistic scenario where a member is removed specifically *because* their key was compromised — an attacker holding that compromised key could have pre-confirmed malicious requests before removal, and those confirmations remain valid toward execution even after the member is purged.

### Likelihood Explanation
Requires normal contract operation (no special privilege beyond being one of the legitimate members) plus a timing sequence: an outstanding confirmed-but-not-executed request coexisting with a `DeleteMember` action. This is a foreseeable and even common operational pattern (member rotation, off-boarding, compromised-key response) rather than a contrived edge case, and `REQUEST_COOLDOWN`/`active_requests_limit` do nothing to prevent it since requests can remain pending indefinitely until executed or explicitly deleted.

### Recommendation
When deleting a member in `delete_member`, iterate over `self.confirmations` (not just `self.requests` filtered by requester) and remove the member's entry from every request's confirmation set, in addition to removing requests the member itself created. Alternatively, validate at `confirm`-time that every entry in the stored `confirmations` set is still `self.members.contains(...)` before counting it toward the threshold.

### Proof of Concept
Not independently executed against a live/test environment; the flow above is derived directly from reading `confirm`, `current_member`, and `delete_member` in [4](#0-3) , which shows no code path clears a removed member's confirmations from requests they did not themselves create. A concrete reproduction would extend the existing `test_multi_3_of_n`-style tests in `multisig2/src/lib.rs` to: create+confirm a request with 2-of-3 members, execute a `DeleteMember` request removing the second confirmer, then have the third member call `confirm` and observe the original request executes despite only 2 still-live members having approved it.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Returns current member: either predecessor as account or if it's the same as current account - signer.
    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    /// Add member to the list. Adds access key if member is key based.
    fn add_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        self.members.insert(&member.clone().into());
        match member {
            MultisigMember::AccessKey { public_key } => promise.add_access_key(
                public_key.into(),
                DEFAULT_ALLOWANCE,
                env::current_account_id(),
                MULTISIG_METHOD_NAMES.to_string(),
            ),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
