### Title
Unbounded memory allocation via zstd decompression bomb in `simulateTransaction` account overwrites - (File: `account-decoder-client-types/src/lib.rs`)

### Summary
`UiAccountData::decode` decompresses attacker-supplied `Base64Zstd`-encoded account data into an unbounded `Vec<u8>` with no length cap, using `zstd::stream::read::Decoder::read_to_end`. This path is reachable from `simulateTransaction` account overwrites, which call `UiAccount::to_account_shared_data`/`to_account`, allowing a single request to trigger gigabyte-scale allocation from a small payload (a "zstd bomb").

### Finding Description
`UiAccountData::decode` handles the `Base64Zstd` encoding by base64-decoding the client-supplied blob and piping it through `zstd::stream::read::Decoder::new(...).read_to_end(&mut data)` with `data` starting as an empty `Vec` and no maximum size enforced anywhere in the loop: [1](#0-0) 

This is invoked by `UiAccount::to_account_shared_data` and `UiAccount::to_account`, which simply call `self.data.decode()` and wrap whatever comes out into an `AccountSharedData`/`Account` with no size validation: [2](#0-1) 

The RPC's `simulateTransaction` handler supports client-supplied `accounts` overwrites, which are looked up ahead of the bank state via `account_resolver::get_account_from_overwrites_or_bank`: [3](#0-2) 

These overwrite accounts are constructed from client `UiAccount` JSON supplied in the `simulateTransaction` request params (deserialized into `UiAccountData`, including the `Base64Zstd` variant), and decoded via `to_account_shared_data` before being injected into `AccountOverrides` used for simulation (`AccountOverrides::set_account`/`get`) as shown in the `svm/src/account_overrides.rs` structure that simulate_transaction populates: [4](#0-3) 

A crafted `Base64Zstd` blob that is small (compressed) but decompresses to a very large output (a zstd "bomb") will cause `read_to_end` to keep growing `data` (a `Vec<u8>`) without any check against account-size limits (e.g., `MAX_PERMITTED_DATA_LENGTH`) until decompression completes or the process runs out of memory. Nothing in `decode()`, `to_account_shared_data()`, or the RPC account-overwrite deserialization path enforces a cap on the decompressed length before or during decompression.

### Impact Explanation
A single `simulateTransaction` call with one crafted account override can force the RPC-serving thread to allocate an attacker-controlled, effectively unbounded amount of memory, potentially exhausting available memory and causing the validator's JSON-RPC service (and possibly the whole process, depending on OS OOM behavior) to become unresponsive or crash. This is an unbounded-cost-for-a-single-low-rate-call scenario, matching the "RPC DoS via unbounded resource consumption from one request" bounty category.

### Likelihood Explanation
The precondition is minimal: an RPC node with `simulateTransaction` enabled and account-overwrite support (a standard, widely deployed feature), reachable by any unprivileged client with a single call. Constructing a highly compressible zstd payload that decompresses to gigabytes from a tiny base64 string is a well-known, easily reproducible technique requiring no special access. The attack is fully repeatable at will.

### Recommendation
Enforce a hard cap on decompressed size before/while decompressing `Base64Zstd` data in `UiAccountData::decode` — e.g., use a bounded reader (limit `read_to_end` via `Read::take(MAX_PERMITTED_DATA_LENGTH)`) or check compressed-to-decompressed ratio limits, and reject/short-circuit decoding as soon as the cap (matching the runtime's maximum account data length) is exceeded, returning `None`/an error rather than continuing to allocate.

### Proof of Concept
```rust
// account-decoder-client-types/src/lib.rs (test module)
#[test]
fn test_base64_zstd_bomb_is_rejected_or_capped() {
    // Build a highly compressible payload (e.g. 2 GiB of zeros) and compress it.
    let huge_zeros = vec![0u8; 2 * 1024 * 1024 * 1024]; // 2 GiB
    let mut encoder = zstd::stream::write::Encoder::new(Vec::new(), 0).unwrap();
    encoder.write_all(&huge_zeros).unwrap();
    let compressed = encoder.finish().unwrap();
    // compressed should be tiny (a few KB) due to the zero-fill.
    let encoded_blob = BASE64_STANDARD.encode(&compressed);

    let ui_data = UiAccountData::Binary(encoded_blob, UiAccountEncoding::Base64Zstd);

    // Expected: decode() should either return None (rejected) or a Vec bounded
    // by a documented maximum (e.g. MAX_PERMITTED_DATA_LENGTH), never the full
    // 2 GiB allocation.
    let decoded = ui_data.decode();
    assert!(
        decoded.is_none() || decoded.unwrap().len() <= MAX_PERMITTED_DATA_LENGTH as usize,
        "zstd bomb was fully decompressed without a size cap"
    );
}
```
This test currently fails against the existing implementation because `decode()` will fully materialize the 2 GiB `Vec<u8>` with no cap, demonstrating the unbounded-allocation vulnerability.

use {
    solana_account::AccountSharedData, solana_pubkey::Pubkey, solana_sdk_ids::sysvar,
    std::collections::HashMap,

/// Encapsulates overridden accounts, typically used for transaction
/// simulations. Account overrides are currently not used when loading the
/// durable nonce account or when constructing the instructions sysvar account.
#[derive(Default)]
pub struct AccountOverrides {
    accounts: HashMap<Pubkey, AccountSharedData>,
}

impl AccountOverrides {
    /// Insert or remove an account with a given pubkey to/from the list of overrides.
    fn set_account(&mut self, pubkey: &Pubkey, account: Option<AccountSharedData>) {
        match account {
            Some(account) => self.accounts.insert(*pubkey, account),
            None => self.accounts.remove(pubkey),
        };
    }

    /// Sets in the slot history
    ///
    /// Note: no checks are performed on the correctness of the contained data
    pub fn set_slot_history(&mut self, slot_history: Option<AccountSharedData>) {
        self.set_account(&sysvar::slot_history::id(), slot_history);
    }

    /// Gets the account if it's found in the list of overrides
    pub(crate) fn get(&self, pubkey: &Pubkey) -> Option<&AccountSharedData> {
        self.accounts.get(pubkey)
    }
}
