### Title
Unauthenticated exposure of internal plugin metrics and pprof debug endpoints - ([File: core/web/router.go])

### Summary
The `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes are registered via `loopRoutes` on the base `api` group with no authentication middleware, unlike every route under `v2Routes` which requires `auth.Authenticate` and role checks (`RequiresAdminRole`, etc.). This allows any anonymous caller to enumerate registered LOOP plugin names and pull their Prometheus metrics and pprof profiling data through the node's proxy.

### Finding Description
`loopRoutes` is invoked in `NewRouter` on the plain `api` group with no auth middleware: [1](#0-0) 
This contrasts with `v2Routes`, where sensitive endpoints (e.g. `/v2/nodes`, `/v2/chains`) are wrapped in `authv2 := r.Group("/v2", auth.Authenticate(...))` plus role wrappers such as `auth.RequiresAdminRole`: [2](#0-1) 

`pluginMetricHandler` looks up the plugin by name and, if found, proxies a GET to `http://{loopHostName}:{p.EnvCfg.PrometheusPort}/metrics`, returning the response body verbatim to the caller; if not found it returns a 404 with the plugin name reflected: [3](#0-2) 

The pprof proxy handlers (`pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) behave the same way, forwarding to `/debug/pprof/*` on the plugin's internal port with no auth check: [4](#0-3) 

However, the specific claim in the question — that this allows **enumeration of the numeric `PrometheusPort` values** — is not supported by the code. `p.EnvCfg.PrometheusPort` (assigned via `freeport.Take(1)` in `plugins/loop_registry.go`) is used only server-side to build the outbound request URL; it is never written into any HTTP response body or header returned to the client: [5](#0-4) 
A 200 response only proves that a plugin with that name is registered and its `/metrics` (or pprof) endpoint responded — it discloses the plugin's *name* and its metrics/profile *content*, not the port number itself. The `/discovery` endpoint does return `exposedPromPort`/plugin group targets as `hostname:port` pairs for Prometheus service discovery, but that host is `discoveryHostName` (external, meant for scraping) and refers to the node's own exposed port, not the internal per-plugin `loopHostName:PrometheusPort` addresses used by `pluginMetricHandler`. So "port-forwarding confirms each port's existence" is true only in the sense of confirming plugin-name existence and forwarding success — it does not reveal the numeric port to the attacker, and thus does not constitute a "full internal network map."

### Impact Explanation
The real, verifiable issue is that these routes bypass the authentication/authorization boundary applied everywhere else in `v2Routes` (`auth.Authenticate`, `RequiresAdminRole`, `RequiresRunRole`, etc.). This is an unauthenticated information-disclosure surface: any anonymous network caller can enumerate registered plugin names and read their Prometheus metrics and full pprof profiles/heap dumps/goroutine traces (which can contain internal state, memory contents, or other operationally sensitive data). This is a genuine confidentiality-boundary violation matching a "sensitive information disclosure" bounty class, but it is **not** equivalent to disclosing internal port numbers or building a full internal network map, since the port values are never returned to the caller.

### Likelihood Explanation
No credentials are required — any unauthenticated HTTP client reaching the node's web port can hit these routes directly, since `loopRoutes` is mounted before any auth middleware is applied and no group-level `auth.Authenticate` wraps it, unlike `v2Routes`. Exploitability is high and trivially repeatable (simple GET requests); the only precondition is that at least one LOOP plugin is registered.

### Recommendation
Wrap `loopRoutes` (or at minimum `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol`, and arguably `/plugins/:name/metrics`) with the same `auth.Authenticate(...)` / role-based middleware used for `authv2`, restricting access to admin or at least authenticated operator sessions, matching the security posture applied to `/v2/nodes` and `/v2/chains`. Additionally, do not conflate this with "port enumeration" in any fix rationale — the actual gap is missing authentication on the proxy routes, not port disclosure.

### Proof of Concept
Go handler-level integration test plan (using `httptest` + `gin`):
1. Build a `gin.Engine` via `NewRouter` (or directly call `loopRoutes`) with a mocked `chainlink.Application` whose `GetLoopRegistry()` returns a `plugins.LoopRegistry` with one registered plugin (`Register("pluginA")`).
2. Issue `GET /plugins/pluginA/metrics` with **no** `Authorization` header or session cookie and assert:
   - Response status is `200 OK` (not `401 Unauthorized`), proving lack of authentication versus e.g. `GET /v2/nodes` without credentials returning `401`.
3. Issue `GET /plugins/doesnotexist/metrics` unauthenticated and assert `404 Not Found` with the reflected plugin name — confirming plugin-name enumeration is possible without credentials.
4. Issue `GET /plugins/pluginA/debug/pprof/heap` unauthenticated and assert `200 OK` with pprof binary payload returned, proving unauthenticated access to a plugin's profiling data.
5. To disprove the port-disclosure claim: assert that none of the above response bodies/headers contain the plugin's `EnvCfg.PrometheusPort` value (compare with the value retrievable only via `LoopRegistry.Get`), confirming the vulnerability is unauthenticated data-proxy access, not port-number leakage.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
