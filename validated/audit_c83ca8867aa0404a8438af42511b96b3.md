### Title
Group/program/insurance fees can be permanently stranded when a bank is closed with outstanding `collected_*_fees_outstanding` - (File: `programs/marginfi/src/instructions/marginfi_group/close_bank.rs`)

### Summary
`lending_pool_close_bank` validates that a bank has no open positions, zero shares, and zero emissions before allowing an admin to close it, but it does not validate that `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, and `collected_program_fees_outstanding` are zero. These fields represent interest/fees already accrued in the bank's accounting but not yet swept from the `liquidity_vault` into the `insurance_vault`/`fee_vault`/global fee ATA via `LendingPoolCollectBankFees`.

### Finding Description
Fees accrue into three "outstanding" counters on the `Bank` account whenever interest (and origination fees) accrue: `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, `collected_program_fees_outstanding`. [2](#0-1) 
These are only actually moved out of `liquidity_vault` into the `insurance_vault`, `fee_vault`, and the program's `fee_ata` by the permissionless `LendingPoolCollectBankFees` instruction, which reads them straight off the live `Bank` account. [3](#0-2) 

`lending_pool_close_bank` closes the `Bank` account (`close = admin`) once position counts, total shares, and emissions are all zero — but it performs no check on the three `collected_*_fees_outstanding` fields. [4](#0-3) 
If a bank reaches a state where `total_asset_shares`/`total_liability_shares` are zero (e.g., all depositors and borrowers have exited/repaid, satisfying the close checks) while it still has nonzero outstanding fee counters (accrued during the bank's lifetime but not yet collected), the admin can close the bank immediately. Because the `Bank` account data — which is the only place `collected_*_fees_outstanding` are recorded — is destroyed by the `close = admin` Anchor constraint, that fee-accounting information is irrecoverably lost, and `LendingPoolCollectBankFees` can no longer be invoked (its accounts constraint requires loading the `Bank` account). Any real tokens still sitting in the `liquidity_vault` corresponding to that outstanding fee balance become effectively stuck: they are not attributable to any depositor's live shares (those are zero) and the accounting record needed to move them to the fee/insurance vaults no longer exists.

This mirrors the referenced Backd bug class: an admin action that removes/destroys the record a fee-sweep mechanism depends on, performed before that fee-sweep mechanism runs, permanently silos already-accrued fees.

### Impact Explanation
This results in a durable freeze/loss of protocol/group/insurance fee revenue with real financial effect: legitimately earned interest fees (insurance, group, and program cuts) become permanently unclaimable once the bank account backing their accounting is closed. This is a value-loss issue to the group admin, program (global fee wallet), and the insurance fund, though it requires the specific sequence where fees accrue and are not swept before the last depositor/borrower exits and the admin closes the bank. Severity is best characterized as Medium, consistent with the judged severity of the analogous Backd finding (loss of otherwise-recoverable yield rather than a full protocol compromise).

### Likelihood Explanation
Likelihood is moderate: closing a bank already requires an unusual, low-activity state (all positions, shares, and emissions at zero), and `LendingPoolCollectBankFees` is permissionless, so in practice a careful admin (or any third party) could call it first. However, nothing in the program enforces this ordering, and interest continues to accrue via `accrue_interest` up until the moment the bank is closed, so if the admin closes a bank immediately after the last user's shares hit zero without also calling `LendingPoolCollectBankFees` in the same or a prior transaction, any nonzero outstanding fee balances at that moment are stranded.

### Recommendation
In `lending_pool_close_bank`, add explicit checks (mirroring the existing zero-share/zero-emissions checks) that `bank.collected_insurance_fees_outstanding`, `bank.collected_group_fees_outstanding`, and `bank.collected_program_fees_outstanding` are all zero (within `ZERO_AMOUNT_THRESHOLD`) before allowing the bank to close, e.g.:
```rust
check!(
    I80F48::from(bank.collected_insurance_fees_outstanding).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
        && I80F48::from(bank.collected_group_fees_outstanding).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
        && I80F48::from(bank.collected_program_fees_outstanding).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
    MarginfiError::BankCannotClose
);
```
Alternatively/additionally, require `LendingPoolCollectBankFees` to be invoked as part of (or immediately prior to, in the same instruction) `lending_pool_close_bank`, so outstanding fees are always swept out before the `Bank` account (and its fee-accounting fields) are destroyed.

### Proof of Concept
1. Admin creates a bank (`CLOSE_ENABLED_FLAG` set) and users deposit/borrow, causing interest to accrue and `bank.collected_group_fees_outstanding` / `collected_insurance_fees_outstanding` / `collected_program_fees_outstanding` to become nonzero, per the interest-accrual flow described in `guides/ADMIN/COLLECTING_FEES.md`. [2](#0-1) 
2. All borrowers repay and all depositors withdraw, bringing `total_asset_shares`, `total_liability_shares`, `lending_position_count`, and `borrowing_position_count` to zero — satisfying the checks in `lending_pool_close_bank` — while `collected_*_fees_outstanding` remain nonzero (interest fees accrue independent of principal being fully withdrawn, and `LendingPoolCollectBankFees` has not yet been called).
3. Admin calls `lending_pool_close_bank` (`programs/marginfi/src/instructions/marginfi_group/close_bank.rs`), which passes all existing checks and closes the `Bank` account, returning rent to `admin`. [1](#0-0) 
4. `LendingPoolCollectBankFees` can no longer be called for this bank since it requires loading the now-closed `Bank` account; any tokens in the `liquidity_vault` attributable to the outstanding fee balances are stuck and unrecoverable through normal fee-collection flows. [5](#0-4)

pub fn lending_pool_close_bank(ctx: Context<LendingPoolCloseBank>) -> MarginfiResult {
    let mut group = ctx.accounts.group.load_mut()?;
    // Note: Groups created prior to 0.1.2 have a non-authoritative count here, so subtraction
    // without saturation could reduce the count below zero.
    group.banks = group.banks.saturating_sub(1);

    let bank = ctx.accounts.bank.load()?;

    // banks created prior to 0.1.4 can never be closed because we cannot guarantee an accurate
    // position count for those banks.
    check!(
        bank.get_flag(CLOSE_ENABLED_FLAG),
        MarginfiError::BankCannotClose,
        "Only banks created in 0.1.4 and later can close"
    );
    check!(
        bank.lending_position_count == 0 && bank.borrowing_position_count == 0,
        MarginfiError::BankCannotClose,
        "Only banks with no open positions can close"
    );
    check!(
        I80F48::from(bank.total_asset_shares).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
            && I80F48::from(bank.total_liability_shares)
                .is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
        MarginfiError::BankCannotClose
    );
    check!(
        I80F48::from(bank.emissions_remaining).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
        MarginfiError::BankCannotClose
    );

    drop(bank);

    // Bank will now be closed by anchor

    Ok(())
}

pub fn lending_pool_collect_bank_fees<'info>(
    mut ctx: Context<'info, LendingPoolCollectBankFees<'info>>,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;

    // Validate the program fee ata is correct
    {
        let mint = &bank.mint;
        let global_fee_wallet = &ctx.accounts.fee_state.load()?.global_fee_wallet;
        let token_program_id = &ctx.accounts.token_program.key();
        let program_fee_ata = &ctx.accounts.fee_ata.key();
        let ata_expected =
            get_associated_token_address_with_program_id(global_fee_wallet, mint, token_program_id);
        check!(
            program_fee_ata.eq(&ata_expected),
            MarginfiError::InvalidFeeAta
        );
    }

    let LendingPoolCollectBankFees {
        liquidity_vault_authority,
        insurance_vault,
        fee_vault,
        token_program,
        liquidity_vault,
        fee_ata,
        ..
    } = ctx.accounts;

    let maybe_bank_mint =
        utils::maybe_take_bank_mint(&mut ctx.remaining_accounts, &bank, token_program.key)?;

    let mut available_liquidity = I80F48::from_num(liquidity_vault.amount);

    let (insurance_fee_transfer_amount, new_outstanding_insurance_fees) = {
        let outstanding = I80F48::from(bank.collected_insurance_fees_outstanding);
        let transfer_amount = min(outstanding, available_liquidity).int();

        (
            transfer_amount.int(),
            outstanding
                .checked_sub(transfer_amount)
                .ok_or_else(math_error!())?,
        )
    };

    bank.collected_insurance_fees_outstanding = new_outstanding_insurance_fees.into();
