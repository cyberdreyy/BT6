### Title
Unbounded `size` query parameter in `JobsController.Index` bypasses intended 1000-row pagination cap, enabling resource-exhaustion / accelerated bulk exfiltration - ([File: core/web/jobs_controller.go])

### Summary
`JobsController.Index` only forces a page size of 1000 when the `size` query parameter is absent; when a caller explicitly supplies `size`, the value is parsed by `ParsePaginatedRequest` with no upper bound, only requiring `size >= 1`. Any authenticated view-role/API-token caller can request an arbitrarily large `size` (e.g. `size=10000000`) to retrieve the entire job set in a single request, bypassing the documented default pagination limit and increasing DB/memory load per request.

### Finding Description
`JobsController.Index` (`core/web/jobs_controller.go`) checks `if c.Query("size") == "" { size = 1000 }`, applying the 1000-row default only when no `size` param is present at all: [1](#0-0) . The actual `size`/`page`/`offset` values passed in come from `ParsePaginatedRequest` (`core/web/api.go`), which validates only that `size >= 1` and imposes no maximum: [2](#0-1) . Because `size` is fully attacker-controlled once supplied, a caller can pass `?size=1000000` (or any large integer) and it is forwarded directly to `jc.App.JobORM().FindJobs(ctx, offset, size)`, which will attempt to return every job spec in one response instead of being capped at 1000: [3](#0-2) . No additional clamping/validation exists between the router and this handler to cap `size` before it reaches the ORM query.

### Impact Explanation
This does not grant access to any job data the caller isn't already authorized to view/read-role callers can already page through all jobs, just more slowly, so this is not a privilege escalation or cross-user data leak. The concrete impact is (a) bypass of the intended default pagination quota, letting a caller pull the full job list (including job spec details returned via `presenters.JobResource`) in a single request rather than many, and (b) increased ability to place resource-exhaustion load on the node (large DB fetch scan + serialization of the full job set) from a low-privileged caller, which is best characterized as a quota-bypass / potential availability (DoS-adjacent) issue rather than a data-confidentiality breach.

### Likelihood Explanation
Trivial to trigger: it only requires an authenticated caller with view/read role or a valid API token capable of hitting `GET /v2/jobs`, and a single request with a large `size` query parameter. No special timing, race condition, or privileged access is needed, and it's fully repeatable.

### Recommendation
Enforce a hard maximum page size (e.g., cap `size` at 1000) inside `ParsePaginatedRequest` (or specifically in `JobsController.Index`) regardless of whether the caller supplies an explicit `size` value, rejecting or clamping any value above the maximum instead of only defaulting when `size` is unset.

### Proof of Concept
1. Seed the JobORM/mock with N > 1000 jobs (e.g. 2000) in a `JobsController` handler-level test using `cltest.NewJobPipelineV2`/`web.Router` setup similar to existing tests in `core/web/jobs_controller_test.go`.
2. Perform `GET /v2/jobs?size=2000` authenticated as a view-role user/API token.
3. Assert the response returns 2000 job resources (not capped at 1000), demonstrating the default cap is bypassed once `size` is explicitly provided.
4. Additionally unit-test `ParsePaginatedRequest("100000000", "1")` in `core/web/api_test.go` and assert it currently succeeds with `size == 100000000`, confirming no upper bound is enforced.

func (jc *JobsController) Index(c *gin.Context, size, page, offset int) {
	// Temporary: if no size is passed in, use a large page size. Remove once frontend can handle pagination
	if c.Query("size") == "" {
		size = 1000
	}

	jobs, count, err := jc.App.JobORM().FindJobs(c.Request.Context(), offset, size)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}
	var resources []presenters.JobResource
	for _, individualJob := range jobs {
		resources = append(resources, *presenters.NewJobResource(individualJob))
	}

	paginatedResponse(c, "jobs", size, page, resources, count, err)

func ParsePaginatedRequest(sizeParam, pageParam string) (int, int, int, error) {
	var err error
	page := 1
	size := PaginationDefault

	if sizeParam != "" {
		if size, err = strconv.Atoi(sizeParam); err != nil || size < 1 {
			return 0, 0, 0, fmt.Errorf("invalid size param, error: %w", err)
		}
	}

	if pageParam != "" {
		if page, err = strconv.Atoi(pageParam); err != nil || page < 1 {
			return 0, 0, 0, fmt.Errorf("invalid page param, error: %w", err)
		}
	}

	offset := (page - 1) * size
	return size, page, offset, nil
}
