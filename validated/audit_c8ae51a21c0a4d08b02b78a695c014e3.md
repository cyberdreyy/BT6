### Title
Stale confirmations from removed multisig members allow requests to execute below the intended confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` only purges pending requests and confirmations that were *authored* by the removed member. It does not scrub confirmation entries the removed member left on *other* members' pending requests. `confirm()` then counts confirmations purely by set size (`confirmations.len() + 1 >= self.num_confirmations`) without re-validating that every entry in the confirmation set still corresponds to a live member. As a result, a stale confirmation from a member who has since been removed still counts toward the threshold, letting the remaining members execute a request (e.g. a `Transfer`) with fewer *live* member approvals than `num_confirmations` requires.

### Finding Description
The binding that must hold is:
```
confirmations_counted_for_request == number_of_confirmations_from_currently_live_members
```

`delete_member` in [1](#0-0)  removes:
- outstanding requests *authored by* the deleted member, and their confirmation sets,
- the `num_requests_pk` entry for the deleted member,
- the member itself and its access key.

It never iterates over `self.confirmations` to strip the deleted member's string identifier from confirmation sets belonging to requests authored by *other* members. Those confirmation `HashSet<String>` entries (keyed by `MultisigMember::to_string()`, see [2](#0-1) ) are left untouched.

`confirm()` in [3](#0-2)  only checks that the *current caller* is a live member (`assert_valid_request` → `current_member()` at [4](#0-3) ) and that the caller hasn't already confirmed. It then compares `confirmations.len() as u32 + 1 >= self.num_confirmations` to decide whether to execute the request — it never re-checks that the *existing* entries in the confirmation set are still members. So a confirmation added before removal keeps counting forever.

### Impact Explanation
This breaks the multisig's core custody guarantee: a request (including `Transfer`, `AddKey`, `FunctionCall`, etc.) can be executed with fewer distinct *live* member approvals than `num_confirmations`. Example with `num_confirmations = 3` and members `{A, B, C, D}`:
1. `D` and `C` confirm a `Transfer` request `X` authored by `A` (confirmation set = `{D, C}`, count 2).
2. Members execute a separate `DeleteMember { member: D }` request (reaching 3 confirmations from `A, B, C`), removing `D` — but `delete_member` does not touch request `X`'s confirmation set because `X` was authored by `A`, not `D`.
3. `B` confirms `X`. `confirmations.len() + 1 == 3 >= num_confirmations`, so `X` executes — funds move — even though only `B` and `C` are actually live members who approved; `D`'s stale confirmation was counted as the third vote.

This directly matches "a multisig request executed below threshold," which is a Critical-severity custody-binding violation: the funds move (or a privileged action like `AddKey`/`FunctionCall` executes) despite fewer live approvals than the contract's own security parameter guarantees.

### Likelihood Explanation
No compromised owner or attacker privileges beyond being an ordinary (still-valid) member are required — this can be triggered by any coalition of currently-valid members who are aware that a removed member left an unconsumed confirmation on a pending request. It is a deterministic consequence of the two independent code paths (`delete_member` cleanup vs. `confirm` counting), not a probabilistic race condition, so it is reliably reproducible whenever a member is removed while they hold outstanding confirmations on requests authored by others.

### Recommendation
In `delete_member`, iterate over all entries of `self.confirmations` (not just requests authored by the removed member) and remove the deleted member's string key from every confirmation `HashSet`. Alternatively, in `confirm()`, before counting, filter the confirmation set to only those entries still present in `self.members` (recomputing the effective count from live members only), and persist the filtered set.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
