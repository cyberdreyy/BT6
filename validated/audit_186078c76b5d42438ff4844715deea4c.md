### Title
`depositAARef`/`depositBBRef` referral deposit path bypasses KYC check and donation skim, leaving unstrategized principal that is later swept to `feeReceiver` - (File: contracts/IdleCDO.sol)

### Summary
The Fission bug class is "a sibling field bypasses validation applied to the primary field": `PodSpec` was sanitized but the standalone `container` blob was merged via a different function that never sanitized. The direct analog here is the deposit surface: the sanctioned path `depositAA`/`depositBB` → `IdleCDOEpochVariant._deposit(uint256,address)` enforces `isWalletAllowed` and calls `_skimDonatedAssets()` before accounting, but the inherited referral entrypoints `depositAARef`/`depositBBRef` route into `IdleCDO._deposit(uint256,address,address)` — a parallel implementation that performs neither check and only forwards funds to the strategy when `directDeposit` is set.

### Finding Description
`IdleCDOEpochVariant._deposit` (2-arg) is the validated path: it rejects non-allowlisted wallets and skims raw underlying donations before minting [1](#0-0) . `IdleCDOCreditVault._deposit` (2-arg) additionally always pushes the deposit into the strategy via `IIdleCDOStrategy(strategy).deposit(_amount)` [2](#0-1) .

The 3-arg `IdleCDO._deposit` is the unsanitized sibling: it calls `_guarded`, `_updateCallerBlock`, `_checkDefault`, `_updateAccounting`, mints shares, and deposits to the strategy only `if (directDeposit)` — no `isWalletAllowed`, no `_skimDonatedAssets` [3](#0-2) . `depositAARef`/`depositBBRef` are `external virtual` entrypoints on `IdleCDO` [4](#0-3)  and are not overridden in `IdleCDOCreditVault` (which defines only `depositAA`/`depositBB`) [5](#0-4)  or in `IdleCDOEpochVariant`, so they remain reachable on the epoch-variant proxy.

Two consequences:

1. **KYC bypass.** Any non-allowlisted EOA can deposit during the buffer phase via `depositAARef`, defeating `isWalletAllowed`/`KeyringIdleWhitelist` gating [6](#0-5) .
2. **Principal stranded and skimmed to `feeReceiver`.** Credit-vault deployments do not set `directDeposit` (the dedicated 2-arg path deposits to the strategy unconditionally precisely because the inherited path does not). A `depositAARef` deposit therefore leaves the underlying as a raw `token` balance on the CDO. Shares are minted correctly since `getContractValue()` counts the raw balance [7](#0-6) . But the very next call to any guarded entrypoint — another deposit, `requestWithdraw`, `startEpoch`, `stopEpoch`, `updateAccounting` — executes `_skimDonatedAssets()`, which sweeps the *entire* raw underlying balance to `feeReceiver` [8](#0-7) . The minted tranche tokens become unbacked: NAV drops by the deposit amount while supply is unchanged, diluting all holders. If the depositor's principal exceeds BB NAV this can push `_updateAccounting` into the `Default()`/emergency path. A symmetric variant: an attacker who front-runs a victim's `depositAARef` with a dust donation causes the donation to be crystallized as tranche gain (and fee'd) instead of skimmed, breaking donation isolation.

### Impact Explanation
- Direct theft of deposited principal: funds routed through `depositAARef` are treated as a donation on the next interaction and transferred in full to `feeReceiver`. The depositor's tranche tokens plus all existing holders absorb the hole — loss equals the full deposit amount.
- Donation-isolation invariant broken: `_skimDonatedAssets` exists precisely to prevent unsolicited transfers from being crystallized as tranche gains [9](#0-8) ; the ref path crystallizes them instead.
- Access invariant broken: permissionless deposits bypass the Keyring whitelist that every other user entrypoint enforces.

### Likelihood Explanation
Any EOA can call `depositAARef` while the pool is unpaused (buffer phase, or after `restoreOperations`). The only precondition for the fund-loss scenario is `directDeposit == false`, which matches the credit-vault design where the 2-arg path deposits to the strategy itself. No privileged action is required; the skimming that destroys the principal is triggered by the next ordinary user or manager call, which is guaranteed to happen.

### Recommendation
Override `depositAARef`/`depositBBRef` in `IdleCDOCreditVault` (or `IdleCDOEpochVariant`) to revert, or override the 3-arg `_deposit` to delegate to the 2-arg path so `isWalletAllowed`, `_skimDonatedAssets`, and the unconditional strategy deposit all apply. Equivalently, move `_skimDonatedAssets` inside `_updateAccounting`/the shared mint path so every merge path is covered — mirroring the upstream fix that moved sanitization into `MergeContainer` itself.

### Proof of Concept
```solidity
// test/foundry/RefDepositBypass.t.sol — run against the repo's existing fork setup
// (borrower, manager, keyringPolicyId, ONE_SCALE helpers as in IdleCreditVault.t.sol)
function testDepositAARefBypassesKycAndDonatesPrincipal() external {
    uint256 amount = 10_000 * ONE_SCALE;
    address evil = makeAddr("nonKycDepositor");

    // victim deposits through the sanctioned path (KYC'd)
    idleCDO.depositAA(amount);

    // non-allowlisted attacker deposits via the inherited ref path — no isWalletAllowed check
    deal(defaultUnderlying, evil, amount);
    vm.startPrank(evil);
    IERC20Detailed(defaultUnderlying).approve(address(idleCDO), amount);
    uint256 minted = idleCDO.depositAARef(amount, address(0)); // succeeds despite no credential
    vm.stopPrank();
    assertGt(minted, 0, "KYC bypass: non-allowlisted deposit succeeded");

    // underlying sits raw on the CDO (directDeposit == false), counted in NAV
    assertEq(underlying.balanceOf(address(cdoEpoch)), amount, "principal not sent to strategy");

    // next ordinary interaction skims the 'donation' to feeReceiver
    uint256 feePre = underlying.balanceOf(cdoEpoch.feeReceiver());
    idleCDO.depositBB(1); // any skim-triggering call
    assertEq(underlying.balanceOf(cdoEpoch.feeReceiver()) - feePre, amount, "principal swept to feeReceiver");

    // CDO NAV is now short `amount` vs outstanding tranche supply
    assertLt(
        cdoEpoch.getContractValue(),
        idleCDO.virtualPrice(address(AAtranche)) * AAtranche.totalSupply() / ONE_SCALE + 1,
        "tranche supply unbacked after skim"
    );
}
```

Caveat: I could not verify within the indexed code whether a later refactor added a `depositAARef` override or disabled the selector in the epoch-variant initializer; the finding holds if neither exists, which the available source indicates.

    _updateAccounting();

    _minted = _mintSharesAtCurrPrice(_contractTokenBalance(_token) - _preBal, msg.sender, _tranche);
