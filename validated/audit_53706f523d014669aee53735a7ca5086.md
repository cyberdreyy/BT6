### Title
`get_supply` computes `circulating = total_supply - non_circulating_supply.lamports` from two sequential, non-atomic reads of a live bank, allowing a stale/inconsistent supply figure (or an unchecked-subtraction wraparound) to be returned - (File: `rpc/src/rpc.rs`)

### Summary
The reported Nouns bug is a classic TOCTOU pattern: a proportional-share calculation reads one piece of state (`totalSupply`), performs work that can take time or yield to other execution, and then combines it with a second piece of state (`balanceOf`) read afterward, without ever re-validating that both values describe the same consistent snapshot. `JsonRpcRequestProcessor::get_supply` in `rpc/src/rpc.rs` reproduces the same shape: it calls `self.calculate_non_circulating_supply(&bank)` (an async, `spawn_blocking` full accounts-index scan that can take a non-trivial amount of time) and only *afterwards* reads `bank.capitalization()`, then combines the two with a plain, non-saturating subtraction.

### Finding Description
`get_supply` is implemented as: [1](#0-0) 

The sequence is:
1. `let non_circulating_supply = self.calculate_non_circulating_supply(&bank).await...` — this runs a full stake-program account scan via `spawn_blocking` [2](#0-1)  and then sums balances for every matched account with `bank.get_balance(pubkey)` [3](#0-2) .
2. Only after that scan completes does the code read `let total_supply = bank.capitalization();` [4](#0-3) .
3. Finally it computes `circulating: total_supply - non_circulating_supply.lamports` with a plain (non-saturating) subtraction [5](#0-4) .

When `config.commitment` resolves to a bank that is still being actively written to (e.g. `processed`/unrooted commitment, which returns a live, not-yet-frozen bank via `self.bank(config.commitment)`), `capitalization` is a running atomic counter that changes as transactions land on that same bank (`bank.capitalization()`), while the non-circulating balance sum was captured moments earlier from a scan over the accounts index. These two reads are not from a single atomic snapshot: the scan can observe one point in time for a set of stake-account balances, while `capitalization()` is sampled at a later point in time after more transactions (inflation credits, stake account creation/closure, deposits/withdrawals) have mutated the bank. This is directly analogous to Nouns' `quit()` reading `totalSupply` before external calls and balances after, where the two values no longer describe the same consistent state.

Because the final subtraction is a plain `-` rather than `saturating_sub`, if between the two reads the non-circulating lamport sum ends up (even momentarily, from the scan's perspective) larger than the `capitalization()` value later sampled, the subtraction underflows. Notably, the sibling code path for the same computation in `rpc/src/rpc_service.rs` already guards against exactly this by using `saturating_sub`: [6](#0-5) , which suggests the underflow risk was recognized elsewhere but the `get_supply` RPC handler in `rpc.rs` was not similarly hardened.

### Impact Explanation
This is an unprivileged, single-JSON-RPC-call (`getSupply`) path reachable by any client. The consequence is either:
- A misreported `circulating` field (wrong account/state data returned to the caller) if the subtraction wraps in release mode (`u64::MAX`-scale bogus value), or
- A panic/thread abort in the RPC handler if the binary is built with overflow checks enabled, which is a crash triggerable by a single unprivileged request.

Both outcomes match the "wrong-slot/fork/account data returned" and "decoder panic and misreporting" acceptance criteria for this scan, since the root cause is state read at inconsistent points combined without validation — the same bug class as the external report.

### Likelihood Explanation
Likelihood is low-to-medium, similar to the Nouns finding's own "Medium" rating: it requires the queried bank to still be actively mutating (unrooted/processed-commitment bank) and specific concurrent balance/capitalization changes to non-circulating stake accounts landing in the window between the scan and the `capitalization()` read. This window is real (a full `get_program_accounts`/index scan under `spawn_blocking` is not instantaneous) but the precise imbalance needed to force underflow requires particular transaction timing, which is not guaranteed on every call. No special privileges are required to trigger the query itself.

### Recommendation
Capture `total_supply = bank.capitalization()` and any dependent per-account balances "atomically" relative to each other before performing the scan, or re-read/re-validate capitalization consistency after the scan and clamp the subtraction with `saturating_sub` (as already done in `rpc_service.rs`'s `calculate_circulating_supply_async`). At minimum, mirror the `rpc_service.rs` fix in `rpc/src/rpc.rs::get_supply` so the subtraction cannot underflow, and consider sampling `bank.capitalization()` once, before invoking `calculate_non_circulating_supply`, to reduce (though not fully eliminate, given bank mutability) the inconsistency window.

### Proof of Concept
Conceptual PoC (cannot be fully driven from a static index scan, but the code paths establish the primitive):
1. Client repeatedly issues `getSupply` against a validator's `processed`-commitment bank while a stream of transactions concurrently funds/creates/closes locked stake accounts and mints/burns lamports affecting `bank.capitalization()`.
2. `calculate_non_circulating_supply` begins its stake-account scan, summing `bank.get_balance(pubkey)` for currently-known non-circulating accounts [7](#0-6) .
3. Before the scan's result is combined, additional transactions land on the bank that increase locked/non-circulating balances without an equally-timed increase reflected in the later-read `bank.capitalization()` value (e.g., a rent/inflation credit path, or a stake account transitioning to locked-in status with lamports moved in) — this is the state-mutation analog to Bob's stETH transfer landing mid-`quit()`.
4. `get_supply` then executes `total_supply - non_circulating_supply.lamports` [5](#0-4)  using the now-stale `total_supply` relative to the freshly summed `non_circulating_supply.lamports`, producing either an underflow panic or a wrapped/garbage `circulating` value in the RPC response.

    async fn get_supply(
        &self,
        config: Option<RpcSupplyConfig>,

        let bank = self.bank(config.commitment);
        let non_circulating_supply =

        let total_supply = bank.capitalization();

                .iter()
                .map(|pubkey| pubkey.to_string())
                .collect()
        };

        Ok(new_response(
            &bank,
            RpcSupply {
                total: total_supply,
                circulating: total_supply - non_circulating_supply.lamports,
                non_circulating: non_circulating_supply.lamports,
                non_circulating_accounts,
            },
        ))
    }

pub fn calculate_non_circulating_supply(bank: &Bank) -> ScanResult<NonCirculatingSupply> {
    debug!("Updating Bank supply, epoch: {}", bank.epoch());
    let mut non_circulating_accounts_set: HashSet<Pubkey> = HashSet::new();

    for key in non_circulating_accounts() {
        non_circulating_accounts_set.insert(key);
    }
    let withdraw_authority_list = withdraw_authority();

    let clock = bank.clock();
    let stake_accounts = if bank
        .rc
        .accounts
        .accounts_db
        .account_indexes
        .contains(&AccountIndex::ProgramId)
    {
        bank.get_filtered_indexed_accounts(
            &IndexKey::ProgramId(stake::program::id()),
            // The program-id account index checks for Account owner on inclusion. However, due to
            // the current AccountsDb implementation, an account may remain in storage as a
            // zero-lamport Account::Default() after being wiped and reinitialized in later
            // updates. We include the redundant filter here to avoid returning these accounts.
            |account| account.owner() == &stake::program::id(),
            None,
        )?
    } else {
        bank.get_program_accounts(&stake::program::id())?
    };

async fn calculate_circulating_supply_async(bank: &Arc<Bank>) -> Result<u64, SupplyCalcError> {
    let total_supply = bank.capitalization();
    let bank = Arc::clone(bank);
    let non_circulating_supply =
        tokio::task::spawn_blocking(move || calculate_non_circulating_supply(&bank))
            .await
            .expect("Failed to spawn blocking task")
            .map_err(|e| SupplyCalcError::Scan(e.to_string()))?;

    Ok(total_supply.saturating_sub(non_circulating_supply.lamports))
