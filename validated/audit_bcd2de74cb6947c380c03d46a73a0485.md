### Title
Renounced `owner()` causes permanent fee loss / permanent `stopEpoch` freeze while fees keep accruing - (File: contracts/IdleCDOCreditVault.sol)

### Summary
`IdleCDOCreditVault` (and its `IdleCDOEpochVariant` epoch path) splits every fee payment between `feeReceiver` and `owner()` via `_feeReceiverAmount`. `setFeeParams` enforces `feeReceiver != address(0)`, but nothing prevents `renounceOwnership()` (inherited unchanged from `OwnableUpgradeable` via `GuardedLaunchUpgradable`) from setting `owner()` to `address(0)`. Management fees and performance fees continue accruing into `unclaimedFees`/`pendingWithdrawFees` after renunciation, and the owner share is still transferred (`_transferFeeUnderlyings`) or minted (`_mintSharesAtCurrPrice(..., owner(), AATranche)` in `IdleCDOEpochVariant.stopEpoch`) to the zero address. Depending on the underlying token this either permanently burns the owner share or reverts `stopEpoch` forever, freezing all user funds.

### Finding Description
`GuardedLaunchUpgradable` inherits `OwnableUpgradeable` and never overrides or disables `renounceOwnership()` [1](#0-0) . After an honest owner renounces (e.g., to make the CDO trustless), `owner()` returns `address(0)` while fees keep accruing through `_accrueManagementFee` [2](#0-1) . On fee settlement, `_transferFeeUnderlyings` still sends `_amount - feeReceiverAmount` to `owner()` [3](#0-2) , and in minted-interest mode `stopEpoch` mints the owner share of `unclaimedFees` as AA tranches to `owner()` unconditionally [4](#0-3) . The `feeReceiver` cannot be `address(0)` because `setFeeParams` reverts [5](#0-4) , but no equivalent guard exists for `owner()`, and no code path redirects the owner share when `owner() == address(0)`.

### Impact Explanation
Two outcomes, both loss/freeze-class:

- If the underlying ERC20 reverts on `transfer`/mint to `address(0)` (OpenZeppelin `_mint` and most `ERC20._transfer` implementations do; `IdleCDOTranche` inherits OZ `ERC20Upgradeable`), then `stopEpoch` (minted-interest path) or any fee settlement (`_transferFeeUnderlyings`) reverts **permanently**. Once the owner renounces, no privileged role can fix `feeReceiver`/`owner()` — `setFeeParams` and `restoreOperations` are owner-gated — so the epoch can never be stopped and the full CDO TVL plus `unclaimedFees` are frozen forever.
- If the underlying permits transfers to `address(0)`, the owner share `(unclaimedFees + pendingWithdrawFees) * (FULL_ALLOC - feeSplit) / FULL_ALLOC` is burned while `unclaimedFees` is decremented, i.e., a direct, permanent loss of accrued yield.

### Likelihood Explanation
Low likelihood, mirroring the source report: it requires the honest owner to call the publicly reachable `renounceOwnership()` while `feeSplit < 100%` or `managementFee > 0`. It needs no attacker action — any ordinary user transaction (`stopEpoch`, harvest fee settlement) triggers the loss. Since the owner is a multisig in practice, renounce is unlikely but is an explicitly supported Ownable flow with no guard, and the failure mode is irreversible once triggered.

### Recommendation
When `owner() == address(0)`, route 100% of fees to `feeReceiver` (or vice-versa if `feeReceiver` were ever zero): in `_transferFeeUnderlyings` and in the minted-fee branch of `stopEpoch`, compute the owner share only if `owner() != address(0)` and assign it to the counterparty. Alternatively, override `renounceOwnership()` to revert, or force it to set `feeSplit = FULL_ALLOC` first.

### Proof of Concept
Foundry-style test against `IdleCDOEpochVariant` (minted-interest mode shows the freeze; set `setIsInterestMinted(false)` to show the burn/transfer revert):

```solidity
function testRenouncedOwnerFreezesEpochStop() public {
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);                       // ordinary lender deposits

    _setFeeParams(TL_MULTISIG, 10_000, 50_000, 1_000); // 10% perf fee, 50/50 split, 1% mgmt fee

    vm.startPrank(manager);
    cdoEpoch.setEpochParams(365 days, 0);
    IdleCreditVault(address(strategy)).setApr(initialProvidedApr);
    cdoEpoch.startEpoch();
    vm.stopPrank();

    // Honest owner renounces to make the CDO trustless
    vm.prank(owner);
    cdoEpoch.renounceOwnership();
    assertEq(cdoEpoch.owner(), address(0));

    // Fees keep accruing via _accrueManagementFee / pendingWithdrawFees
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.warp(cdoEpoch.epochEndDate());

    // Minted-interest path: _mintSharesAtCurrPrice(ownerShare, address(0), AATranche)
    // reverts in OZ ERC20Upgradeable._mint -> stopEpoch can never succeed
    vm.prank(manager);
    vm.expectRevert(); // "ERC20: mint to the zero address" / transfer to zero
    cdoEpoch.stopEpoch(initialProvidedApr, 0);

    // No privileged role can recover: setFeeParams/restoreOperations are onlyOwner
    vm.expectRevert();
    cdoEpoch.setFeeParams(TL_MULTISIG, 10_000, FULL_ALLOC, 1_000);

    // unclaimedFees remain > 0, NAV still reduced, all user funds frozen
    assertGt(cdoEpoch.unclaimedFees(), 0);
    assertTrue(cdoEpoch.isEpochRunning());
}
```

For the burn variant (token allowing zero-address transfers): set `setIsInterestMinted(false)` and `feeSplit = 0`; after `stopEpoch`, the entire fee amount is `safeTransfer`ed to `address(0)` while `unclaimedFees` is zeroed [6](#0-5)  — a quantified loss equal to `unclaimedFees + pendingWithdrawFees`.
