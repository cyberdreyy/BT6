### Title
Zip symlink extraction restores unsanitized, potentially absolute/escaping link targets verbatim - ([File: helpers/archives/zip_create.go], [File: helpers/archives/zip_extract.go])

### Summary
`createZipSymlinkEntry` stores the raw output of `os.Readlink(fh.Name)` as the zip entry payload with no validation, and `extractZipSymlinkEntry` calls `os.Symlink(string(data), file.Name)` on that raw payload with no validation either. Neither function restricts the link target to be relative and contained within the extraction root, so a symlink target created in job A's workspace (fully attacker-controlled by the job's own script) is faithfully reproduced as a symlink in job B's workspace when the artifact is later consumed as a dependency/cache.

### Finding Description
`createZipEntry` in [1](#0-0)  dispatches symlinks to `createZipSymlinkEntry`, which reads the link target with `os.Readlink(fh.Name)` and writes it verbatim into the zip entry body without checking whether it is absolute or points outside the archived directory: [2](#0-1) .

On the consuming side, `extractZipFile` dispatches symlink entries to `extractZipSymlinkEntry`, which reads the stored bytes and calls `os.Symlink(string(data), file.Name)` directly, again with no validation of the target: [3](#0-2) . `ExtractZipArchive` only tracks/logs `os.PathError`s for warning suppression and checks for `.git` directories; it performs no symlink-target sanitization: [4](#0-3) .

The zip archiver/extractor used for artifacts and cache (`ziplegacy`) calls these functions directly with no additional path/target validation layer in between: [5](#0-4) [6](#0-5) .

Attacker path: a pipeline author lists a path in `artifacts:paths` that is a symlink created by their own job script pointing to an absolute path (e.g. `/builds/other-namespace/other-project`, a shared cache mount, or another absolute host-visible path reachable by the runner's OS user). `CreateZipArchive` archives that symlink with its literal absolute target. When a different job (same or different project, via `dependencies:` or artifact download) extracts that archive, `extractZipSymlinkEntry` recreates a symlink with that same absolute target inside the second job's workspace, without any check that the target stays within the extraction root.

### Impact Explanation
Once job B's workspace contains a symlink whose target is an absolute path outside its own root, any subsequent job step (script command, cache upload, next-stage tooling) that reads or writes through that symlink operates on the pointed-to location instead of job B's intended sandboxed root. Depending on filesystem sharing between jobs on the same runner host/user (shared runner cache directories, shared build root layouts, executor reuse), this allows cross-job/cross-project artifact poisoning: job B can be tricked into reading data from, or writing data into, a path associated with job A or a shared host location, violating the invariant that cross-project artifact consumption must not grant filesystem access outside the consuming job's own root.

### Likelihood Explanation
This requires: (1) an artifact/cache zip created by job A containing a symlink with an absolute or `..`-escaping target (trivially achievable by the job's own script, since `artifacts:paths` accepts any path the job creates, including symlinks), and (2) that archive being consumed by another job via `dependencies:`/cache/cross-project artifact download, which is a standard, commonly used GitLab CI feature. No special runner privileges or admin misconfiguration are needed to create the malicious archive entry; the actual severity of *dereferencing* the resulting symlink depends on the executor's filesystem layout, but the Runner-side flaw — creating the symlink at all, with an unsanitized target — is unconditional and reproducible with a plain unit test.

### Recommendation
In `extractZipSymlinkEntry` (and ideally also as a defensive check in `createZipSymlinkEntry`), validate the symlink target before calling `os.Symlink`: reject or rewrite targets that are absolute paths, and reject targets whose resolved path (relative to `file.Name`'s directory) escapes the extraction root (e.g., using `filepath.IsAbs` and a `filepath.Rel`/prefix check against the root directory passed to the extractor). Apply the same containment check used (or that should be used) for zip-slip prevention on `file.Name` itself to the symlink's target data.

### Proof of Concept
Go test in `helpers/archives`:
```go
func TestZipSymlinkEscapesRoot(t *testing.T) {
    root := t.TempDir()
    outside := t.TempDir()

    // Simulate job A: create a symlink pointing outside its own root
    linkPath := filepath.Join(root, "escape")
    require.NoError(t, os.Symlink(outside, linkPath))

    var buf bytes.Buffer
    require.NoError(t, os.Chdir(root))
    require.NoError(t, CreateZipArchive(&buf, []string{"escape"}))

    // Simulate job B: extract into a different sandboxed root
    jobBRoot := t.TempDir()
    require.NoError(t, os.Chdir(jobBRoot))
    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    require.NoError(t, ExtractZipArchive(zr))

    target, err := os.Readlink(filepath.Join(jobBRoot, "escape"))
    require.NoError(t, err)
    // Assert the extracted symlink does NOT point outside jobBRoot
    require.True(t, strings.HasPrefix(target, jobBRoot),
        "symlink target %q escapes job B root %q", target, jobBRoot)
}
```
Expected current (buggy) behavior: the assertion fails because `target` equals `outside`, proving the symlink escapes job B's sandboxed root.

```go
func createZipSymlinkEntry(archive *zip.Writer, fh *zip.FileHeader) error {

	}

	return err
}
```

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
```
