## Local Analog Found

### Title
Operator commission shares are mis-taxed and redirected to the new operator after `switch_operator` — (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::switch_operator` reassigns a `StakingContract` (including its `distribution_pool`) from an old operator's key to a new operator's key while leaving any still-unpaid commission shares owned by the old operator address inside the same `distribution_pool`. `update_distribution_pool`, which is later invoked (via `add_distribution`/`distribute_internal`) whenever the pool's total value changes, identifies "the operator" purely by address equality against whichever operator is *currently* keyed in the `StakingContract`. Since the old operator no longer equals the new operator's address, the old operator's un-withdrawn commission position is misclassified as an ordinary staker's principal and taxed again — with the "unpaid commission" transferred as shares to the new operator, who never earned it.

### Finding Description
`request_commission_internal` buys the operator (by address) shares into `staking_contract.distribution_pool` representing commission owed but not yet inactive/withdrawn: [1](#0-0) 

`switch_operator` removes the `StakingContract` entry keyed by `old_operator`, forces a `distribute_internal` + `request_commission_internal` (which only pays out whatever stake has actually become inactive — any pending/locked commission remains as shares owned by `old_operator` inside the pool), then changes `stake::set_operator_with_cap` and re-inserts the *same* `StakingContract` object (same `distribution_pool`, same shares) under the `new_operator` key: [2](#0-1) 

Subsequently, any call that changes the pool's total value — e.g. `add_distribution` (staker unlocking more stake) or `distribute_internal` — invokes `update_distribution_pool` with the *new* operator address as the `operator` parameter: [3](#0-2) 

`update_distribution_pool` iterates every shareholder in the pool and taxes anyone whose address is not equal to the passed-in `operator` on the growth in their share value, transferring the "unpaid commission" portion of that growth to `operator`: [4](#0-3) 

Because `old_operator`'s previously-earned, still-locked commission shares remain in the pool under the `old_operator` address, and `operator` in this call is now `new_operator`, the condition `shareholder != operator` (line 1016) evaluates true for `old_operator`. Any subsequent appreciation of the pool's `total_coins` (caused by new stake being unlocked into the same distribution pool, or by further reward accrual reflected via `add_distribution`/`distribute`) causes `old_operator`'s already-vested commission balance to be taxed again at the *new* commission rate, and those shares are moved to `new_operator` — a party that did nothing to earn them.

### Impact Explanation
This corrupts operator-commission share accounting: value legitimately earned and vested to the old operator (recorded as their commission shares in `distribution_pool`, per the module's own documented accounting model) is silently redirected to the new operator. This falls squarely under "Operator commission ... share-accounting corruption that credits the wrong account or traps value." The old operator has no recourse — the module does not track per-shareholder "role" beyond raw address equality against the current operator field, so the old operator's earned commission is permanently and non-recoverably reduced whenever the pool subsequently grows before the old operator's `distribute()` withdraws their pending shares in full.

### Likelihood Explanation
`switch_operator` is a normal, unprivileged (staker-triggered, not requiring any elevated system role) entry function intended for routine operator rotation. Any staker who wants to change operators while the old operator still has unpaid/locked commission (a very common situation, since commission only becomes inactive/withdrawable after the stake pool's lockup period), followed by any subsequent stake unlock or distribution event, triggers the mis-taxation automatically — no attacker-controlled timing tricks beyond the standard operator-switch + unlock/distribute sequence are needed.

### Recommendation
`update_distribution_pool` (and the broader `distribution_pool` design) should not rely on comparing shareholder address to the *current* operator field to determine which shares are "commission" versus "staker principal." Instead, commission shares should be tracked with an immutable marker (e.g., snapshotting/finalizing an old operator's earned commission into a separate payout entry immediately at `switch_operator` time rather than leaving it inside a pool that will keep being re-taxed under a different operator identity), or `switch_operator` should fully settle (force-distribute or otherwise externally record) all of the old operator's already-bought-in commission shares before the `distribution_pool` is reused for the new operator.

### Proof of Concept
1. Staker creates a staking contract with `operator1`, `commission_percentage = 10`.
2. Stake pool earns rewards; `operator1` (or staker) calls `request_commission`, which buys `operator1` commission shares into `distribution_pool` via `request_commission_internal` (this commission is not yet inactive/withdrawable due to lockup). [1](#0-0) 
3. Staker calls `switch_operator(old_operator=operator1, new_operator=operator2, new_commission_percentage=X)`. `distribute_internal`/`request_commission_internal` pay out only what is already inactive; `operator1`'s pending commission shares remain in the (same) `distribution_pool`, which is now stored under `operator2`'s key. [2](#0-1) 
4. Staker calls `unlock_stake` (or waits for more rewards) then triggers `add_distribution`/`distribute`, both of which call `update_distribution_pool(distribution_pool, updated_total_coins, operator2, new_commission_percentage)`. [4](#0-3) 
5. Because `operator1 != operator2`, `operator1`'s previously earned commission shares are treated as staker principal: their appreciation is taxed and those shares are transferred to `operator2`, who receives commission never earned, while `operator1` permanently loses part of the already-vested payout.

Note: I could not execute this in a live Move test environment (read-only analysis), so the exact numeric magnitude of value diverted was not empirically measured — the trace above is derived directly from the cited control flow and share-accounting logic in `staking_contract.move`.

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
