### Title
Stale cached admin role in `oidc_user_api_tokens` allows continued admin-level API access for up to `UserAPITokenDuration` after OIDC role demotion - ([File: core/sessions/oidcauth/oidc.go])

### Summary
`FindUserByAPIToken` resolves a user's role solely from the `oidc_user_api_tokens.user_role` column, which is set once at `SetAuthToken`/`CreateAndSetAuthToken` time and never re-verified against the authoritative OIDC identity provider on subsequent requests. `RequiresAdminRole` trusts this cached role directly, so a token issued while the user was an admin continues to grant admin access after the user's upstream OIDC group membership is downgraded, until the token naturally expires per `UserAPITokenDuration`.

### Finding Description
`AuthenticateByToken` (`core/web/auth/auth.go:78-112`) calls `authr.FindUserByAPIToken(ctx, token.AccessKey)` and sets the returned `User` (including `.Role`) directly into the Gin context via `c.Set(SessionUserKey, &user)`. [1](#0-0) 

In the OIDC authenticator, `FindUserByAPIToken` builds the `User.Role` exclusively from the cached `user_role` column of `oidc_user_api_tokens`, based on a plain expiry check (`created_at + duration >= now()`), with no call back to the OIDC provider or the `users`/upstream role source: [2](#0-1) 

The `RequiresAdminRole` middleware then authorizes purely off this cached role: [3](#0-2) 

The in-code comment on `FindUserByAPIToken` claims "sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation," but the actual `core/sessions/oidcauth/reaper.go` only deletes stale `oidc_sessions` rows by creation timestamp — it performs no upstream OIDC role query and does not touch `oidc_user_api_tokens` at all: [4](#0-3) 

This is unlike the LDAP driver, which has a real `sync.go` background job (`LDAPServerStateSyncer.Work`) that re-queries the upstream LDAP group membership and issues `UPDATE ldap_sessions/ldap_user_api_tokens SET user_role = ...` to keep cached roles current: [5](#0-4) 

No equivalent mechanism exists for OIDC API tokens. There is no server-to-server OIDC introspection call in this codebase (OIDC role determination only happens once, during the interactive `handleTokenExchange` login-callback flow via `IDClaimsToUserRole`), so once an API token is minted with `UserRoleAdmin`, that role is baked into the DB row and served on every subsequent `FindUserByAPIToken` call until the row's TTL lapses or is deleted via `DeleteAuthToken`.

### Impact Explanation
An account demoted from admin to view (or any lower role) upstream retains full admin-level API access via a previously issued token for up to `UserAPITokenDuration` (default `240h` = 10 days per `docs/CONFIG.md`), enabling continued execution of admin-only actions (e.g., job/key management, config-sensitive routes gated by `RequiresAdminRole`) after the demotion is intended to take effect. This matches a privilege-escalation / stale-authorization bounty class: role is not re-verified per request, violating the stated invariant.

### Likelihood Explanation
Requires only that: (1) OIDC API tokens are enabled (`UserApiTokenEnabled`), (2) the attacker already possesses a legitimately issued API token/secret pair from before demotion, and (3) the demotion occurs before token expiry. No additional privilege or exploitation technique is needed beyond replaying the existing `X-API-KEY`/`X-API-SECRET` headers — this is fully reproducible and deterministic given the code path shown above.

### Recommendation
`FindUserByAPIToken` (and `AuthorizedUserWithSession`) for the OIDC driver should not trust the cached `user_role` as authoritative beyond a short window. Either: (a) re-verify the role against a fresh identity-provider check/claims re-validation on each authenticated request or at a bounded cache TTL much shorter than `UserAPITokenDuration`; or (b) implement a genuine upstream OIDC role-sync reaper (analogous to `core/sessions/ldapauth/sync.go`) that periodically re-derives role from the IdP (e.g., via refresh token / userinfo endpoint) and updates `oidc_user_api_tokens.user_role`, invalidating/downgrading stale tokens promptly upon role change, and force-revoke tokens on demotion via an explicit admin action (`DeleteAuthToken`) hook triggered by the demotion event.

### Proof of Concept
Go unit test plan (in `core/sessions/oidcauth/oidc_test.go`):
1. Set up a test DB with `oidcauth.NewTestOIDCAuthenticator`.
2. Create a user with `UserRoleAdmin`, call `CreateAndSetAuthToken` to insert a row into `oidc_user_api_tokens` with `user_role = 'admin'`.
3. Simulate demotion: directly update the "authoritative" source (in this codebase there is none reachable from `FindUserByAPIToken`) — demonstrate by asserting that no code path exists to propagate a role change into `oidc_user_api_tokens` short of `DeleteAuthToken`/`SetAuthToken` being called again.
4. Call `FindUserByAPIToken(ctx, token.AccessKey)` and assert it still returns `Role: UserRoleAdmin` (unchanged), proving staleness.
5. Handler-level integration test: wrap a dummy handler with `auth.RequiresAdminRole`, authenticate using `AuthenticateByToken` with the old admin token, and assert the request succeeds (200) even though the "current" role should be `view`, confirming `RequiresAdminRole` never re-checks against a fresh role source.

// FindUserByAPIToken retrieves a possible stored user and role from the oidc_user_api_tokens table store
func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE created_at < $1", before)
	return err
}
