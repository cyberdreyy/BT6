### Title
Programmable borrower withdraw-reserve snapshot misses APR0 interest added at stopEpoch, leaving pending receipts unbacked and forcing a default - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
The external bug is a "snapshot vs in-flight claims" mismatch: `receiveMigrateToNative()` burns `totalSupply()` without accounting for pending failed bridge messages that can still mint tokens afterward. The analog in this codebase is `ProgrammableBorrower.onStartEpoch()`, which snapshots `epochPendingWithdraws = _pendingWithdraws` once at epoch start and uses it as the sole liquidity reserve in `availableToBorrow()`. `IdleCreditVault.prepareStopEpochWithApr0()` can increase `pendingWithdraws` after that snapshot (APR0 interest is folded into pending receipts at stop time — see the comment "Pending withdraws may be increased during APR0 settlement"), so the borrower can legitimately draw, during the epoch, cash that `stopEpoch` will later need to pull for pending receipt funding. [1](#0-0) [2](#0-1) 

### Finding Description
In minted-interest programmable mode, `stopEpoch` pulls only cash for withdraw requests: `_amountToPullFromBorrower = _mintInterest ? 0 : _expectedInterest`, then calls `onStopEpoch(_amountToPullFromBorrower + _pendingWithdraws, ...)` and `getFundsFromBorrower(... + _pendingWithdraws)`, where `_pendingWithdraws` is read *after* `prepareStopEpochWithApr0` inflates it. [3](#0-2) 

`ProgrammableBorrower` only reserved the start-of-epoch `pendingWithdraws` value: `epochPendingWithdraws` is set in `onStartEpoch` and `availableToBorrow()` returns `totalAssets - epochPendingWithdraws`. [4](#0-3)  An unprivileged KYC'd lender creates the mismatch by making an APR0 withdraw request during the buffer (`requestWithdraw` routes to `_requestWithdrawApr0` when `unscaledApr == 0`); its epoch interest is only added to `pendingWithdraws` inside `prepareStopEpochWithApr0`, long after the reserve snapshot. [5](#0-4) 

At `onStopEpoch`, if the drawn-out shortfall exceeds the vault sleeve (`shortfall > _currentVaultAssets()`), the hook returns `true` and lets the CDO's `transferFrom` fail, falling into `_handleBorrowerDefault`. [6](#0-5) [7](#0-6) 

### Impact Explanation
Direct insolvency/permanent freezing: the unreserved APR0-interest portion of `pendingWithdraws` cannot be pulled from the borrower contract, so `getFundsFromBorrower` reverts and `_handleBorrowerDefault` pauses deposits, disables withdraw requests and marks `defaulted`. Pending receipt holders are haircut via `defaultRecoveryPrice`/`_claimDefaultedWithdrawRequest` instead of paid at par, and all LPs are frozen until `finalizeDefault`. Quantified loss equals the APR0 interest folded into `pendingWithdraws` (up to `apr0RateByEpoch`-driven interest on `apr0TotalPrincipal`), plus default-associated haircuts for every other claimant. [8](#0-7) [9](#0-8) 

### Likelihood Explanation
Requires a programmable-borrower pool (`isInterestMinted`) configured with `unscaledApr == 0`, one APR0 withdraw request in the buffer, and the honest borrower drawing near `availableToBorrow()` — all normal, intended operations; the attacker only needs to place the APR0 request. The honest borrower borrowing within the documented reserve is a sequencing precondition, not malicious behavior.

### Recommendation
Make the reserve dynamic instead of a start-of-epoch snapshot: recompute the reserved amount at stop time, e.g. have `availableToBorrow()` add a bound on pending-receipt interest growth (or have `IdleCreditVault` expose projected `pendingWithdraws` including unsettled APR0 interest, as `previewLossAdjustedWithdrawFunds`/`prepareStopEpochWithApr0` do), or restrict `borrow()` so `totalAssets - borrow` always covers `IdleCreditVault.pendingWithdraws()` plus the worst-case APR0 interest on `apr0TotalPrincipal` for the remaining epoch.

### Proof of Concept
Foundry fork sketch (modeled on `test/foundry/ProgrammableBorrowerEpochInvariant.t.sol` and APR0 tests in `test/foundry/IdleCreditVault.t.sol`):

```solidity
// Setup: IdleCDOEpochVariant in programmable mode (isProgrammableBorrower,
// isInterestMinted = true) with ProgrammableBorrower as _borrower, MockEpochInvariantVault as vault.

// 1. Manager sets next-epoch APR to 0 so withdraw requests enter the APR0 bucket.
// 2. LP deposits AA during buffer; pool runs one epoch; stopEpoch(apr=0) sets unscaledApr == 0.
// 3. Attacker (KYC'd LP): cdoEpoch.requestWithdraw(amount, AAtranche)
//    -> IdleCreditVault._requestWithdrawApr0: apr0Users[attacker].principal = amount,
//       pendingWithdraws += amount (principal only, no interest yet).
// 4. Manager calls startEpoch():
//    -> onStartEpoch(strategy.pendingWithdraws()) stores epochPendingWithdraws = principal only.
// 5. Honest borrower calls borrowerContract.borrow(availableToBorrow()) — draws everything
//    except the stale principal-only reserve.
// 6. Warp to epochEndDate + 1. Manager calls stopEpoch(0, 0):
//    -> prepareStopEpochWithApr0 adds APR0 interest to pendingWithdraws;
//    -> _pendingWithdraws = principal + apr0Interest > reserved amount;
//    -> onStopEpoch: shortfall > _currentVaultAssets() (borrowed away) -> return true;
//    -> getFundsFromBorrower(principal + apr0Interest) transferFrom fails -> catch ->
//       _handleBorrowerDefault: defaulted = true, paused, withdraw requests disabled.
// Assert: cdoEpoch.defaulted() == true; attacker receipt and all LP positions frozen,
// payable only via finalizeDefault haircut — loss >= apr0Interest.
```

Key checks: `strategy.pendingWithdraws()` increases between `onStartEpoch` and `stopEpoch` while `programmableBorrower.epochPendingWithdraws()` stays at the snapshot, and `onStopEpoch`'s `shortfall > _currentVaultAssets()` branch lets the underfunded pull cascade into a default.

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);

  function _claimDefaultedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, defaultEpoch, true);
    if (claimBasis == 0) return amount;

    // pendingWithdraws stores the claim basis owed by the borrower, including APR0 interest.
    pendingWithdraws -= claimBasis;
    // Only receipt principal exists as strategy tokens. APR0 interest is included in claimBasis
    // but was never minted as a user strategy-token receipt.
    _burn(_user, burnAmount);
    amount = (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL;
    _transferDefaultRecovery(_user, amount);
  }
