### Title
Confidential relay gateway handler fans out unauthenticated JSON-RPC requests to all DON nodes with no signer/allowlist check - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` in `core/services/gateway/handlers/confidentialrelay/handler.go` only validates `req.ID` (non-empty, ≤200 chars) before calling `newActiveRequest` and `fanOutToNodes`, performing no signer, `req.Auth`, or allowlist check on the request itself. This differs from the sibling `vault` handler, which explicitly calls `h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)` to authorize the request before creating an active request.

### Finding Description
`HandleJSONRPCUserMessage` [1](#0-0)  performs only ID-format checks, then unconditionally calls `h.newActiveRequest(req, callback)` [2](#0-1)  — which only enforces req.ID uniqueness in the `activeRequests` map — and immediately fans the raw request out to every DON member via `h.don.SendToNode` in `fanOutToNodes` [3](#0-2) . There is no check of `req.Auth`, no signature verification, and no allowlist/authorization call comparable to the vault handler's `requestProcessor.ProcessRequest` [4](#0-3) .

The code comments explicitly document this as an intentional design choice: the gateway does not verify request authenticity itself and defers all trust decisions to the enclave running on each node — e.g. "the enclave remains responsible for signature and quorum verification" [5](#0-4)  and "The gateway makes no trust decision; the enclave verifies signatures and reaches quorum" [6](#0-5) . Verification of the actual request content/signature happens downstream in the enclave/node, not in this handler.

Critically, unlike `HandleNodeMessage`, which applies `globalNodeRateLimiter` and `perNodeRateLimiters` before processing node responses [7](#0-6) , there is no rate limiting or authorization gate anywhere in the inbound `HandleJSONRPCUserMessage` → `newActiveRequest` → `fanOutToNodes` path. Any caller reaching the gateway's HTTP endpoint (`gateway.ProcessRequest` routes JSON-RPC requests straight into `h.HandleJSONRPCUserMessage` based only on service name/DON ID, with no per-request auth gate at that layer either [8](#0-7) ) can submit arbitrary unique-ID requests for `MethodSecretsGet`/`MethodCapabilityExec`, and each one will be dispatched to every node in the DON, consuming: gateway memory (one `activeRequest` entry, timers, goroutines per request), network sends to every node, and per-node/enclave processing cycles — all before any signature or allowlist check occurs.

### Impact Explanation
This enables unauthenticated resource exhaustion / request-flooding of an entire confidential-relay DON: an attacker with no prior relationship to the DON (no signer, no `req.Auth`) can cause the gateway to create unbounded `activeRequest` entries and fan out network calls to every DON member for each crafted unique `req.ID`, consuming gateway memory/goroutines and node/enclave processing capacity. This matches a Denial-of-Service / resource-exhaustion impact class rather than direct fund loss, since actual authorization/signature enforcement is deferred to the enclave, but the gateway itself has no gate to prevent flooding prior to that point.

### Likelihood Explanation
High feasibility and full repeatability: the attacker needs only network access to the gateway's public JSON-RPC endpoint and the ability to generate unique `req.ID` values (e.g., UUIDs) — no credentials, keys, or prior enrollment with the DON are required. `newActiveRequest`'s only defense is ID uniqueness [2](#0-1) , which is trivially bypassed by rotating IDs, and there is no per-caller rate limiter guarding the ingress path.

### Recommendation
Add an authorization/authentication check on `req.Auth` (or equivalent signer/allowlist verification) in `HandleJSONRPCUserMessage` before calling `newActiveRequest`/`fanOutToNodes`, mirroring the vault handler's `requestProcessor.ProcessRequest` pattern. Additionally, apply an inbound rate limiter (analogous to `globalNodeRateLimiter`/`perNodeRateLimiters` used for node responses) to the user-request ingress path to bound per-caller and global request volume before fan-out.

### Proof of Concept
Go handler-level test plan for `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` via `NewHandler` with a mocked `don` (mock `SendToNode` capturing call count) and a valid `donConfig` with several members.
2. Build a `jsonrpc.Request[json.RawMessage]{ID: uuid.New().String(), Method: MethodCapabilityExec, Params: <arbitrary json>}` with `Auth` left empty/unset, and no `Sig`/authenticating field.
3. Call `handler.HandleJSONRPCUserMessage(ctx, req, callback)` and assert:
   - `err == nil` (no authorization error returned),
   - `h.don.SendToNode` was invoked once per DON member (fan-out occurred),
   - `h.activeRequests[req.ID]` exists (active request was created).
4. Repeat with N distinct random `req.ID`s in a loop to demonstrate unbounded active-request creation/fan-out with no auth and no per-caller throttling, confirming absence of any allowlist or rate-limit gate on the ingress path.

	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
