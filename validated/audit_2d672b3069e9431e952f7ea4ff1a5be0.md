### Title
Unauthenticated `/readyz?full=1` leaks internal health-check names and raw error strings - (File: core/web/router.go, core/web/health_controller.go)

### Summary
The `/readyz` route is registered in `healthRoutes` with no authentication middleware, and `HealthController.Readyz` returns per-subsystem check names plus raw `err.Error()` output whenever the `full` query parameter is present. This lets any unauthenticated internet client retrieve internal error text (e.g., DB/RPC connection errors, DSNs, internal paths) that the node's own `PublicReadyz` variant was explicitly built to avoid exposing.

### Finding Description
`healthRoutes` mounts `/readyz` on the same `api` router group as `/public-readyz`, both without any `auth.Authenticate` wrapper — the group only has rate limiting and cookie sessions applied, not authentication: <cite repo="Noahgrantyt/chainlink--018" path="core/web/router.go" start="220="228" /> is invalid; correct citation below. [1](#0-0) 

The route registration happens on the shared `api` group, which is not authenticated: [2](#0-1) 

`HealthController.Readyz` checks readiness, then if the `full` query parameter is present (any value, including empty), it iterates all health-check errors and serializes each check's name and `err.Error()` string into the JSON response body: [3](#0-2) 

By contrast, `PublicReadyz` was explicitly documented and implemented to never return per-check details "to avoid leaking internal service state on publicly reachable endpoints," regardless of query parameters: [4](#0-3) 

This confirms that the codebase authors treated full health-check output as sensitive and specifically engineered `PublicReadyz` as the safe alternative for public exposure — yet `/readyz` (the non-"public" variant) remains reachable by the same unauthenticated caller and is not restricted to internal-only use (e.g., no separate internal-only listener, no auth middleware, no IP allowlist in this router). The existing test suite confirms `/readyz` is called via a plain unauthenticated HTTP client in `TestHealthController_Readyz`, and only status code is asserted (no auth boundary), while `TestHealthController_PublicReadyz` explicitly asserts that `?full=true` yields an empty body on the public endpoint but does not perform the equivalent assertion for `/readyz` itself: [5](#0-4) [6](#0-5) 

Any health check's `Error()` string (e.g., from a database connection pool, RPC client, or relayer) could embed connection details, hostnames, internal paths, or other diagnostic data not intended for external disclosure, since check authors write these strings assuming an operator-only audience.

### Impact Explanation
This is an information-disclosure vulnerability: an unauthenticated remote attacker can enumerate internal subsystem names and their raw error text via `GET /readyz?full=1`. Depending on what individual health checks include in their error messages (DB DSNs, RPC endpoints, chain IDs, internal hostnames/paths), this could aid further attacks by revealing internal topology or configuration details. It maps to Chainlink's "sensitive information disclosure" bounty class — not a direct fund-loss or key-leak issue, but a real internal-state leak to any internet client, exactly the risk `PublicReadyz` was created to prevent for its own endpoint.

### Likelihood Explanation
No preconditions or credentials are required — the endpoint is reachable by anyone who can send an HTTP GET request to the node, and the vulnerable code path (`if _, ok := c.GetQuery("full"); !ok { return }`) triggers on any request with a `full` query parameter. This is fully repeatable and trivially scriptable.

### Recommendation
Restrict the detailed (`full=1`) branch of `Readyz` to authenticated/internal callers only (e.g., require `auth.Authenticate` on `/readyz` or move the detailed variant behind the internal-only listener), or have `Readyz` behave like `PublicReadyz` and never emit per-check names/output regardless of query parameters on the externally reachable route. Alternatively, sanitize/redact error strings before including them in the JSON output so they cannot carry sensitive internal data.

### Proof of Concept
1. In a test similar to `TestHealthController_Readyz`, inject a `mocks.Checker` whose `IsReady()` returns `false` and an errors map containing `{"DB": errors.New("dial tcp: connect to postgres://user:secretpw@10.0.0.5:5432/db failed")}`.
2. Start the app and issue `client.Get("/readyz?full=true")` with no authentication headers.
3. Assert the response status is `503` and parse the JSON body; assert that a check with `name == "DB"` exists and its `output` field contains the injected error string (e.g., `assert.Contains(t, body, "secretpw")`).
4. Compare against the same scenario on `/public-readyz?full=true`, which the existing test already shows returns an empty body — demonstrating the discrepancy in information exposure between the two endpoints for identical unauthenticated access.

// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid

func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func TestHealthController_PublicReadyz(t *testing.T) {
	t.Parallel()
	var tt = []struct {
		name   string
		ready  bool
		status int
	}{
		{
			name:   "not ready",
			ready:  false,
			status: http.StatusServiceUnavailable,
		},
		{
			name:   "ready",
			ready:  true,
			status: http.StatusOK,
		},
	}
	for _, tc := range tt {
		t.Run(tc.name, func(t *testing.T) {
			t.Parallel()
			app := cltest.NewApplicationWithKey(t)
			healthChecker := new(mocks.Checker)
			healthChecker.On("Start").Return(nil).Once()
			healthChecker.On("IsReady").Return(tc.ready, nil)
			healthChecker.On("Close").Return(nil).Once()

			app.HealthChecker = healthChecker
			require.NoError(t, app.Start(t.Context()))

			client := app.NewHTTPClient(nil)

			// Base path returns status only, no body.
			resp, cleanup := client.Get("/public-readyz")
			t.Cleanup(cleanup)
			assert.Equal(t, tc.status, resp.StatusCode)
			body, err := io.ReadAll(resp.Body)
			require.NoError(t, err)
			assert.Empty(t, body)

			// ?full=true must NOT expose per-check details on this endpoint.
			respFull, cleanupFull := client.Get("/public-readyz?full=true")
			t.Cleanup(cleanupFull)
			assert.Equal(t, tc.status, respFull.StatusCode)
			bodyFull, err := io.ReadAll(respFull.Body)
			require.NoError(t, err)
			assert.Empty(t, bodyFull)
		})
	}
}
