### Title
Local tx-replay state (`tx_replay_scope`/`tx_replay_set`) is never persisted and unconditionally resets on signer restart, silently dropping replay protection - (`stacks-signer/src/v0/signer.rs`, `stacks-signer/src/v0/signer_state.rs`)

### Summary
`Signer::tx_replay_scope` is a plain in-memory `ReplayScopeOpt` field that is hard-coded to `None` every time a `Signer` is constructed [1](#0-0) , and `LocalStateMachine::new` always starts from `Self::Uninitialized`/`place_holder` (empty `tx_replay_set`) and calls `bitcoin_block_arrival` with `expected_burn_block: None` [2](#0-1) . Because the whole fork/replay-inference block is gated by `if let Some(expected_burn_block) = expected_burn_block`, restart re-initialization never re-derives an in-progress replay, and the normal per-burn-block re-derivation can't recover it either since it only fires on a *new* discrepancy relative to the freshly-initialized (post-restart) burn tip. The result: any signer process restart while `tx_replay_scope: Some(_)`/a non-empty `tx_replay_set` was in effect permanently and silently clears both, so `ReplayState::infer_state` yields `Unset` instead of `InProgress` after restart.

### Finding Description
`ReplayState::infer_state` computes signer intent to enforce transaction replay from two pieces of state: the persisted-ish/broadcast `tx_replay_set` (`SignerStateMachine::tx_replay_set`) and the purely local `tx_replay_scope: ReplayScopeOpt` field on `Signer` [3](#0-2) . `ReplayScope`/`ReplayScopeOpt` do not derive `Serialize`/`Deserialize` and are never written to `SignerDb`; only the `SignerStateMachine.tx_replay_set` is gossiped/stored via `StateMachineUpdate` messages, not the `scope`. On process start, `Signer::new` sets `tx_replay_scope: None` unconditionally [4](#0-3) , and `LocalStateMachine::new` seeds `tx_replay_set` from `place_holder` (empty) and calls `bitcoin_block_arrival(.., None, &mut None, ..)` [5](#0-4) [6](#0-5) .

Inside `bitcoin_block_arrival`, the entire replay-scope inference/fork-handling logic is inside `if let Some(expected_burn_block) = expected_burn_block { ... }` [7](#0-6) . Since initialization passes `None`, this block is skipped entirely on startup, so the freshly initialized `tx_replay_set` stays empty and `tx_replay_scope` stays `None` even though, before the restart, the equivalent state was `InProgress(set, scope)`.

Subsequently, when a real new burn block arrives post-restart, `handle_pending_update`/`bitcoin_block_arrival` is invoked with `tx_replay_scope = &mut self.tx_replay_scope` (still `None`) [8](#0-7) . `ReplayState::infer_state` short-circuits to `Some(Unset)` because `tx_replay_set.is_empty()` [9](#0-8) . `handle_possible_bitcoin_fork` is only able to detect a *new* fork by diffing the freshly-initialized `prior_state_machine.burn_block` (which now equals the current node tip, established at restart) against the newly-arriving burn block, so an already-in-progress replay from before the restart produces no discrepancy and is never re-derived. The failsafe path (`handle_possible_replay_failsafe`) also only clears existing `InProgress` state, it cannot re-create one, and it isn't reached anyway once `infer_state` already returned `Unset`. The result is a permanent loss of the replay obligation: `ReplayState::infer_state` after restart returns `Unset` where it should return `InProgress(set, scope)`, breaking the equality the question posits should hold.

### Impact Explanation
`tx_replay_set` is the mechanism by which a signer enforces that a miner replays transactions orphaned by a bitcoin fork rather than silently dropping them from the canonical chain; it feeds `NakamotoBlockProposal::tx_replay_hash` checks in `stacks_block_arrival`/proposal validation [10](#0-9) . After the state silently resets, the signer no longer requires or checks for the replay set on newly proposed blocks, i.e. it stops applying a validation constraint it should still be applying — a rejection condition becomes an unconditional acceptance from that signer's perspective for the remainder of the affected reward cycle/fork window. This matches the "losing the equivocation/replay guard on restart" High-severity bucket in the rules; depending on how many signers restart during the same replay window and how the node-side validation gate (`validate_with_replay_tx`) composes with the signer's local check, this can also contribute to the Critical bucket ("a rejection recounted as acceptance") if the node relies on signers, rather than the node itself, to enforce the replay-set requirement — I was not able to fully verify the node-side (postblock_proposal) enforcement path within this investigation's scope, so I report this at the confirmed High level for the signer-side guarantee.

### Likelihood Explanation
The only precondition is a signer process restart (crash, upgrade, or operator restart) while a bitcoin-fork tx-replay window is active (`tx_replay_scope: Some(_)`, `tx_replay_set` non-empty) — an ordinary operational event, not something requiring attacker privilege, majority signer weight, or local host access. It is deterministic and 100% reproducible given the precondition: every restart during a replay window loses the state, every time, with no code path to recover it.

### Recommendation
Persist `tx_replay_set` and `tx_replay_scope` in `SignerDb` (e.g., alongside the existing `signer_states`/`block_validated_by_replay_txs` tables), keyed by reward cycle, and have `LocalStateMachine::new`/`Signer::new` load this persisted state at startup instead of assuming `None`/empty. Alternatively, make replay-scope re-derivation unconditional at startup by running the fork-detection logic against the actual current node/burn-chain history rather than gating it behind a `Some(expected_burn_block)` that is never supplied during initialization.

### Proof of Concept
```rust
// stacks-signer/src/v0/signer_state.rs (test module)
#[test]
fn restart_drops_replay_state_silently() {
    // 1. Build a ReplayTransactionSet + ReplayScope representing "in progress" state
    let scope = ReplayScope {
        fork_origin: NewBurnBlock { burn_block_height: 100, consensus_hash: ConsensusHash([1; 20]) },
        past_tip:    NewBurnBlock { burn_block_height: 99,  consensus_hash: ConsensusHash([2; 20]) },
    };
    let replay_set = ReplayTransactionSet::new(vec![/* some StacksTransaction */]);

    // BEFORE restart: infer_state must report InProgress
    let before = ReplayState::infer_state(&replay_set, &Some(scope.clone()));
    assert!(matches!(before, Some(ReplayState::InProgress(_, _))));

    // 2. Simulate process restart: fresh Signer::new() semantics -> tx_replay_scope = None,
    //    LocalStateMachine::new() -> place_holder tx_replay_set = ReplayTransactionSet::none()
    let mut post_restart_scope: ReplayScopeOpt = None; // Signer::new() hard-codes this
    let post_restart_set = ReplayTransactionSet::none(); // place_holder()

    // AFTER restart: infer_state now reports Unset, even though the on-disk/broadcast
    // world still expects an in-progress replay
    let after = ReplayState::infer_state(&post_restart_set, &post_restart_scope);
    assert!(matches!(after, Some(ReplayState::Unset)));

    // Equality violated: decisions/view before restart (InProgress) != after restart (Unset)
    assert_ne!(
        std::mem::discriminant(&before.unwrap()),
        std::mem::discriminant(&after.unwrap())
    );
}
```
This directly demonstrates the broken equality: the same logical replay state (`replay_set` non-empty, `scope: Some(_)`) is correctly inferred as `InProgress` before a restart, but after simulating the restart-time defaults used by `Signer::new`/`LocalStateMachine::new` (`tx_replay_scope: None`, `tx_replay_set: ReplayTransactionSet::none()`), `infer_state` reports `Unset`, confirming that a real signer restart silently drops the replay-protection guard with no recovery path in `bitcoin_block_arrival`.

```rust
/// Represents the scope of Tx Replay in terms of burn block boundaries.
#[derive(Debug, Clone)]
pub struct ReplayScope {
    /// The burn block where the fork that originated the transaction replay began.
    pub fork_origin: NewBurnBlock,
    /// The canonical burn chain tip at the time the transaction replay started.
    pub past_tip: NewBurnBlock,
}

/// Optional `TxReplayScope`, representing the potential absence of a replay scope.
pub type ReplayScopeOpt = Option<ReplayScope>;

/// Represents the Tx Replay state
pub enum ReplayState {
    /// No replay has started yet, or the previous replay was cleared.
    Unset,
    /// A replay is currently in progress, with an associated transaction set and scope.
    InProgress(ReplayTransactionSet, ReplayScope),
}

impl ReplayState {
    /// Infers the appropriate `ReplayState` based on the contents of the replay transaction set
    /// and the optional scope.
    ///
    /// # Arguments
    ///
    /// * `replay_set` - A reference to a set of transactions intended for replay.
    /// * `scope_opt` - An optional scope defining the boundaries or context for the replay.
    ///
    /// # Returns
    ///
    /// * `Some(ReplayState::Unset)` if the `replay_set` is empty.
    /// * `Some(ReplayState::InProgress)` if the `replay_set` is non-empty and a `scope` is provided.
    /// * `None` if the `replay_set` is non-empty but no `scope` is provided.
    ///   - Possibly caused by the scope being a local state in the `Signer` struct, which is not persisted.
    fn infer_state(replay_set: &ReplayTransactionSet, scope_opt: &ReplayScopeOpt) -> Option<Self> {
        if replay_set.is_empty() {
            return Some(Self::Unset);
        }

        scope_opt
            .as_ref()
            .map(|scope| Self::InProgress(replay_set.clone(), scope.clone()))
    }
}
```
