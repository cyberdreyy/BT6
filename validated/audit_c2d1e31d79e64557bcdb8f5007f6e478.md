## Title
V1 signer accepts a duplicate `BlockFound` tenure-change for a tenure with a locally-accepted-but-not-globally-accepted block, breaking tenure-start uniqueness - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
`SortitionsView::validate_tenure_change_payload` in `stacks-signer/src/chainstate/v1.rs` guards against a duplicate tenure-start block by querying `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)`, which only returns blocks that have already reached global (majority) acceptance. A block the signer has locally accepted (i.e., already signed) but that has not yet crossed the global-acceptance threshold is invisible to this check, so a second, conflicting `BlockFound` tenure-change proposal for the same tenure passes `check_proposal` and gets signed. The v2 code path (`stacks-signer/src/chainstate/v2.rs`) fixes exactly this gap by using `get_last_signed_block` instead, and has a regression test (`check_tenure_change_rejects_when_locally_accepted_block_exists`) proving the fix; v1 has no equivalent guard or test.

### Finding Description
The invariant the signer must maintain is: for any given tenure (`consensus_hash`), at most one tenure-start block may ever be signed by this signer. `validate_tenure_change_payload` enforces this by looking up whatever block this signer has already committed a signature to in that tenure and rejecting a new `BlockFound` proposal if one exists: [1](#0-0) 

`get_last_globally_accepted_block` is keyed on a block having reached network-wide (majority-signer) acceptance, not on whether *this* signer has locally signed it. Between the point where a signer locally accepts (signs) a block and the point where that block accumulates enough other signers' signatures to become globally accepted, `get_last_globally_accepted_block` returns `None` for that tenure. If a miner (or attacker controlling the winning miner slot for that sortition) submits a second `BlockFound` proposal for the same `consensus_hash` during this window, `validate_tenure_change_payload` sees no globally-accepted block, `last_in_current_tenure` is `None`, `DuplicateBlockFound` never fires, and the rest of `check_proposal` (parent-tenure checks, pubkey checks, bitvec checks) can pass, letting the signer sign a second, conflicting tenure-start block for the same tenure.

By contrast, v2's `validate_tenure_change_payload` uses `get_last_signed_block`, which (per the docstring and the `check_tenure_change_rejects_when_locally_accepted_block_exists` test in `stacks-signer/src/chainstate/tests/v2.rs`) is deliberately designed to catch both locally- and globally-accepted blocks, only excluding merely pre-committed (unsigned) blocks: [2](#0-1) [3](#0-2) 

This asymmetry means the exact "duplicate tenure-start block" equivocation guard that v2 explicitly regression-tests against was never ported to v1's `validate_tenure_change_payload`. The attacker's proposal/message is simply a second, well-formed `BlockProposal` carrying a `TenureChangePayload` with `cause = BlockFound` for the same `tenure_consensus_hash` and a valid `prev_tenure_consensus_hash`/parent chain, differing only in its transaction set (e.g., different included transactions) from the block already locally accepted. No majority of signers, no compromised keys, and no auth_token are required — this is purely a gap in the v1 chainstate validation logic that a single miner-slot holder can trigger by gossiping a second proposal before the first block reaches global acceptance.

### Impact Explanation
This breaks the **uniqueness** safety property (Critical): two distinct, signer-signed tenure-start blocks can exist for one tenure under the v1 protocol path. If enough other signers similarly race the timing window (each one signs whichever of the two proposals it sees first, believing no conflicting block exists yet), the signer set can be split across two mutually exclusive tenure-start blocks for the same tenure, producing a chain fork/equivocation that the node-side or the rest of the signer protocol was not designed to arbitrate cleanly. This falls squarely in the "signer signing a conflicting block" Critical category, and it is a v1-specific instance of a bug that was already identified and fixed for v2.

### Likelihood Explanation
Preconditions: attacker only needs to win a single miner slot (their own BTC) for the tenure in question, and gossip a second `BlockProposal`/tenure-change tx before the first proposed block finishes accumulating enough independent signer signatures to reach global acceptance — a normal, short window that exists in every tenure start under v1. No majority-signer collusion, no node compromise, no auth_token access, and no local host access are needed. The exploit is repeatable every tenure the attacker wins under v1 signer deployments, since it exploits a structural gap in `validate_tenure_change_payload`, not a one-off timing fluke.

### Recommendation
In `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload`, replace the call to `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)` with the same broader lookup v2 uses (`signer_db.get_last_signed_block(&block.header.consensus_hash)`, or equivalent), so that any block this signer has already signed (locally or globally accepted) in the tenure blocks a second conflicting `BlockFound` proposal, while still allowing replacement of merely pre-committed (unsigned) blocks.

### Proof of Concept
Port `check_tenure_change_rejects_when_locally_accepted_block_exists` from `stacks-signer/src/chainstate/tests/v2.rs` (lines 756-850) into `stacks-signer/src/chainstate/tests/v1.rs`, adapted to `v1::SortitionsView::check_proposal`:

1. Build the same test harness (`setup_test_environment`-equivalent for v1, using `SortitionsView`/`SortitionState` from `crate::chainstate::v1`).
2. Insert a `BlockInfo` for the current tenure's `consensus_hash` and call `mark_locally_accepted(false)` (simulating a signed-but-not-yet-globally-accepted block), then `signer_db.insert_block(...)`.
3. Construct a second `NakamotoBlock` with a `TenureChangePayload` (`cause = TenureChangeCause::BlockFound`) plus a coinbase tx, for the same `consensus_hash`, signed by the miner.
4. Call `sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block, ..., ReplayTransactionSet::none())`.
5. Assert on both sides of the equality:
   - **v2 (existing)**: asserts `matches!(result, Err(RejectReason::DuplicateBlockFound))` — passes today.
   - **v1 (new test)**: same assertion `matches!(result, Err(RejectReason::DuplicateBlockFound))` — this **fails** with current v1 code (returns `Ok(())` or a different error), demonstrating the equality violation and confirming a second signable tenure-start block is accepted for a tenure already locally-accepted-but-not-globally-accepted.     fn validate_tenure_change_payload(
        &self,
        proposed_by: &ProposedBy,
        tenure_change: &TenureChangePayload,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
    ) -> Result<(), RejectReason> {
        // Check that the tenure change's prev_tenure matches the sortition's known parent tenure.
        // This catches block commits with bad parent_block_ptr (e.g., vtxindex=0 exploit).
        let parent_tenure_id = &proposed_by.state().data.parent_tenure_id;
        if &tenure_change.prev_tenure_consensus_hash != parent_tenure_id {
            warn!(
                "Block commit parent tenure mismatch: the block commit's parent_block_ptr does not correspond to the actual parent tenure";
                "committed_parent_tenure" => %parent_tenure_id,
                "actual_parent_tenure" => %tenure_change.prev_tenure_consensus_hash,
                "consensus_hash" => %block.header.consensus_hash,
                "signer_signature_hash" => %block.header.signer_signature_hash(),
            );
            return Err(RejectReason::InvalidParentBlock);
        }

        // Ensure that the tenure change block confirms the expected parent block
        let confirms_expected_parent = SortitionData::check_tenure_change_confirms_parent(
            tenure_change,
            block,
            signer_db,
            client,
            self.config.tenure_last_block_proposal_timeout,
            self.config.reorg_attempts_activity_timeout,
        )
        .map_err(SignerChainstateError::from)?;
        if !confirms_expected_parent {
            return Err(RejectReason::InvalidParentBlock);
        }
        // now, we have to check if the parent tenure was a valid choice.
        let is_valid_parent_tenure = proposed_by.state().data.check_parent_tenure_choice(
            signer_db,
            client,
            &self.config.first_proposal_burn_block_timing,
        )?;
        if !is_valid_parent_tenure {
            return Err(RejectReason::ReorgNotAllowed);
        }
        let last_in_current_tenure = signer_db
            .get_last_globally_accepted_block(&block.header.consensus_hash)
            .map_err(|e| {
                SignerChainstateError::from(ClientError::InvalidResponse(e.to_string()))
            })?;
        if let Some(last_in_current_tenure) = last_in_current_tenure {
            warn!(
                "Miner block proposal contains a tenure change, but we've already signed a block in this tenure. Considering proposal invalid.";
                "proposed_block_consensus_hash" => %block.header.consensus_hash,
                "proposed_block_signer_signature_hash" => %block.header.signer_signature_hash(),
                "last_in_tenure_signer_signature_hash" => %last_in_current_tenure.block.header.signer_signature_hash(),
            );
            return Err(RejectReason::DuplicateBlockFound);
        }
        Ok(())
    }

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}
