### Title
Cache/artifact zip extraction only warns—but still writes—into `.git/` paths, allowing persistence of a malicious git hook - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` calls `errorIfGitDirectory(file.Name)` purely to decide whether to print a warning; the returned error is never used to skip or abort extraction of that entry. As a result, a job-supplied cache/artifact zip containing an entry like `.git/hooks/pre-commit` is extracted into the workspace unconditionally, letting an attacker plant an executable git hook that will run when a later job (reusing the same workspace/`.git` directory) performs git operations.

### Finding Description
In `helpers/archives/zip_extract.go`: [1](#0-0) 

For every zip entry, `errorIfGitDirectory(file.Name)` is invoked (defined in `helpers/archives/path_check_helper.go`) which flags any path whose first path segment is `.git`: [2](#0-1) 

The returned `*os.PathError` is fed into `tracker.actionable(err)` solely to gate whether `printGitArchiveWarning("extract")` is logged (with repeat-suppression via `pathErrorTracker`, see `helpers/archives/path_error_tracker.go`). Critically, the loop body does not `continue` or otherwise skip the entry — `extractZipFile(file)` on the next line is called unconditionally for every file, including ones under `.git/`. `extractZipFile` then creates parent directories via `os.MkdirAll` and writes the file content via `extractZipFileEntry`, with no allowlist/denylist enforcement of destination paths and no check that the resolved path stays outside `.git/`: [3](#0-2) 

Because cache/artifact zips are attacker-controlled (a pipeline author can name artifact/cache entries however they like when producing the archive in a prior job or via `artifacts:paths`/cache config), an attacker can include an entry named `.git/hooks/pre-commit` with executable permission bits set in the zip header. On extraction into a workspace that has git-strategy set to `fetch` (i.e., the `.git` directory persists across job runs rather than being wiped/cloned fresh), this overwrites/creates the hook file. A subsequent job on the same runner/workspace performing any git operation that triggers `pre-commit` (e.g., `git commit`, or GitLab Runner's own git operations that invoke hooks) executes the attacker's payload.

### Impact Explanation
This allows persistent command execution that survives the boundary of the job that planted it, executing in the context of subsequent jobs sharing the same workspace — a real breach of the invariant that cache/artifact extraction must not write into version-control-sensitive paths that alter execution behavior of later git commands. The warning-only behavior gives operators a false sense that this is merely a "warning" concern, when it is actually a write primitive into `.git/`.

### Likelihood Explanation
Preconditions are realistic and common: GitLab Runner's default `GIT_STRATEGY` for many executors is `fetch`, which reuses the same `.git` directory across job runs on the same runner/workspace (concurrency=1 same runner, or shared build dirs). An unprivileged pipeline author fully controls artifact/cache zip contents (file names, paths, permission bits) via standard CI job definitions. No special access is required — this is trivially reproducible by any job author who can define `artifacts:paths` or push to `cache`.

### Recommendation
In `ExtractZipArchive`, when `errorIfGitDirectory` returns a non-nil error for an entry, skip extraction of that entry (`continue`) instead of merely logging a warning, or return a fatal error aborting the whole extraction. Apply the same fix symmetrically to any other entry-processing loop (chmod/extra processing) so no `.git`-relative path is ever created, modified, or chmod'd by archive extraction.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go` style:
1. Create a temp dir, `os.Chdir` into it.
2. Build an in-memory `zip.Writer` with an entry named `.git/hooks/pre-commit`, mode `0o755`, content `#!/bin/sh\necho pwned`.
3. Call `ExtractZipArchive` on the resulting `*zip.Reader`.
4. Assert: `os.Stat(".git/hooks/pre-commit")` should return `os.ErrNotExist` (expected/fixed behavior) — currently it will succeed and `os.ReadFile` will return the attacker payload, proving the bug.
5. Additionally assert file is executable (`FileMode&0o111 != 0`) to confirm hook-execution viability.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
