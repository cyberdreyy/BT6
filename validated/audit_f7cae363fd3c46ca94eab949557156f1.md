### Title
Staking while `paused == true` inflates `total_staked_balance` without any on-chain stake, decoupling it from `account_locked_balance()` - (File: `staking-pool/src/internal.rs`)

### Summary
`internal_stake` unconditionally increases `self.total_staked_balance` and `self.total_stake_shares` for any depositor, while `internal_restake` (called right after, from every `stake`/`stake_all`/`deposit_and_stake` entrypoint) is a no-op whenever `self.paused == true`. Once the pool owner has paused staking (a legitimate maintenance action that unstakes the pool's on-chain locked balance), any unprivileged account can keep calling `stake()`/`stake_all()`/`deposit_and_stake()` to grow `total_staked_balance` and mint itself "stake" shares, permanently decoupling the contract's internal accounting from the actual `env::account_locked_balance()` on the validator account.

### Finding Description
The invariant under test is:
`total_staked_balance == "amount actually staked/locked on the validator account" (reflected by env::account_locked_balance())`, outside of a mid-restake promise window.

Code path:
- `stake(amount)` in `staking-pool/src/lib.rs` calls `internal_ping()`, then `internal_stake(amount)`, then `internal_restake()`: [1](#0-0) 
- `internal_stake` unconditionally does `self.total_staked_balance += stake_amount; self.total_stake_shares += num_shares;` with no check of `self.paused`: [2](#0-1) 
- `internal_restake`, which is the only place that would actually issue a `Promise::stake` to increase the validator's on-chain locked balance, returns immediately when `self.paused`: [3](#0-2) 
- `pause_staking` (owner-only) sets `self.paused = true` and issues `Promise::new(env::current_account_id()).stake(0, ...)`, which drives the real validator locked balance toward `0` over subsequent epochs: [4](#0-3) 
- No entrypoint (`stake`, `stake_all`, `deposit_and_stake`) checks `self.paused` before calling `internal_stake`, so staking is not actually blocked while paused; only the on-chain re-stake action is skipped.

Exploit flow:
1. Owner calls `pause_staking()` for legitimate maintenance. The real locked balance on the validator account drains to 0 over the unstaking delay.
2. While `paused == true`, an unprivileged attacker (or anyone) with unstaked balance calls `stake(amount)` / `stake_all()` / `deposit_and_stake()`. `internal_stake` credits them `stake_shares` and bumps `total_staked_balance`, while `internal_restake` no-ops, so no `Promise::stake` is ever sent.
3. Repeating this (deposit + stake, any number of times, any number of accounts) grows `total_staked_balance` arbitrarily far above the real `account_locked_balance()`, which stays at (or trends to) 0.
4. When the owner later calls `resume_staking()`, `internal_restake()` fires a single `Promise::new(...).stake(self.total_staked_balance, ...)` for the now-inflated figure, attempting to lock an amount of NEAR the contract does not actually hold as rewards — this is picked up by `internal_ping`'s `assert!(total_balance >= self.last_total_balance, ...)` only if the contract balance truly lacks the funds, but the accounting divergence (`total_staked_balance` vs. real locked/available balance) has already been recorded, shares already minted, and other depositors, indexers or integrators can act on the inflated `total_staked_balance` / `get_account_staked_balance` values in the interim.

No existing guard prevents this: `assert_owner` isn't relevant since staking is not owner-gated; `internal_ping`'s balance assertion only fires on a ping computing `total_balance < last_total_balance`, which does not happen here because `last_total_balance` is only touched by `internal_deposit`/`internal_withdraw`/`internal_ping`, not by `internal_stake` — staking amounts move between `account.unstaked` and `total_staked_balance` without touching `last_total_balance`, so no assertion catches the drift. The U256 rounding pair in `num_shares_from_staked_amount_rounded_down`/`staked_amount_from_num_shares_rounded_down` only protects share-price monotonicity, not the paused/locked-balance relationship.

### Impact Explanation
This corrupts the pool's core accounting value (`total_staked_balance`, and per-account `staked_balance` derived from shares) so that it diverges from the real NEAR held/locked by the validator, matching the High-severity category "an accounting value diverging from reality where another party settles on it." Any account that staked during the paused window is credited shares/staked balance backed by nothing on-chain; when the pool resumes and eventually distributes real rewards via `internal_ping`, these phantom shares dilute genuine stakers' rewards, and if enough phantom balance accumulates, the pool cannot actually stake or later unstake/withdraw the claimed amount, freezing funds relative to the reported (over-stated) balances. It's repeatable across any number of accounts and stake calls for the entire duration the pool remains paused.

### Likelihood Explanation
The only precondition is that the pool owner (a normal, legitimate maintenance action documented in the contract itself: "Pausing is useful for node maintenance") has paused the pool at some point — the attacker does not need owner privileges, only needs unstaked balance in their own account (achievable via a normal `deposit()`), and can call `stake`/`stake_all`/`deposit_and_stake` freely, at zero extra cost beyond gas and the deposit they already control. This is a common operational scenario (any staking pool undergoing maintenance) with no other unusual conditions required, making it highly feasible and fully repeatable per attacker, per epoch, across accounts.

### Recommendation
Block staking-related state changes while paused: add `assert!(!self.paused, "Staking is paused")` (or equivalent) at the top of `stake`, `stake_all`, and `deposit_and_stake` in `staking-pool/src/lib.rs`, or inside `internal_stake` in `staking-pool/src/internal.rs`, so `total_staked_balance` cannot be incremented without a corresponding successful on-chain restake.

### Proof of Concept
```rust
// staking-pool/src/lib.rs (tests module) - conceptual cargo test using the existing Emulator harness
#[test]
fn test_stake_while_paused_inflates_total_staked_balance() {
    let mut emulator = Emulator::new(
        owner(),
        "KuTCtARNzxZQ3YvXDeLjx83FDqxv2SdQTSbiq876zR7".to_string(),
        zero_fee(),
    );

    // Owner pauses the pool (legitimate maintenance action).
    emulator.update_context(owner(), 0);
    emulator.contract.pause_staking();
    emulator.simulate_stake_call(); // drives locked_amount toward 0 via the stake(0,...) promise

    // Binding under test, recorded BEFORE the exploit:
    let before_total_staked = emulator.contract.total_staked_balance;
    let before_locked = emulator.locked_amount; // proxy for env::account_locked_balance()
    assert!(before_total_staked <= before_locked || before_locked == 0);

    // Attacker deposits and stakes while paused == true.
    let deposit_amount = ntoy(1_000_000);
    emulator.update_context(attacker(), deposit_amount);
    emulator.contract.deposit_and_stake();

    // No promise for on-chain restake was scheduled (internal_restake no-ops while paused),
    // so real locked balance stays at emulator.locked_amount (unchanged, e.g. 0),
    // while total_staked_balance grew by deposit_amount.
    let after_total_staked = emulator.contract.total_staked_balance;
    let after_locked = emulator.locked_amount;

    assert_eq!(after_total_staked, before_total_staked + deposit_amount);
    assert_eq!(after_locked, before_locked); // unchanged: no Promise::stake was sent

    // Invariant violated: total_staked_balance now exceeds the real locked balance
    // outside of any mid-restake window.
    assert!(after_total_staked > after_locked,
        "Invariant total_staked_balance <= account_locked_balance() is broken while paused");
}
```
This demonstrates that `internal_stake` (`staking-pool/src/internal.rs:70-122`) increments `total_staked_balance`/`total_stake_shares` even though `internal_restake` (`staking-pool/src/internal.rs:9-22`) performed no on-chain staking action, breaking the claimed binding without requiring any check that currently exists in `stake`, `stake_all`, or `deposit_and_stake` (`staking-pool/src/lib.rs:229-287`).

    pub(crate) fn internal_restake(&mut self) {
        if self.paused {
            return;
        }
        // Stakes with the staking public key. If the public key is invalid the entire function
        // call will be rolled back.
        Promise::new(env::current_account_id())
            .stake(self.total_staked_balance, self.stake_public_key.clone())
            .then(ext_self::on_stake_action(
                &env::current_account_id(),
                NO_DEPOSIT,
                ON_STAKE_ACTION_GAS,
            ));
    }
