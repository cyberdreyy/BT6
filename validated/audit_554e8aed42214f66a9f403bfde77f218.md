### Title
Docker executor's `resumeDependencies` blindly attaches to any container ID in the EnvironmentKey without validating runner/system ownership - (File: `executors/docker/docker.go`)

### Summary
`executors/docker/docker.go:1515-1577` (`resumeDependencies`) parses `e.Build.EnvironmentKey()` via `common.ParseEnvironmentKey` and `parseEnvKeyFields`, then directly calls `e.dockerConn.ContainerInspect` on `fields.buildContainerID` and `fields.helperContainerID` and adopts them into the current job's executor state, with **no check that `envKey.RunnerID`/`envKey.SystemID` match the current runner/host**. This is in contrast to the autoscaler executor's `validateEnvKey` (`executors/internal/autoscaler/executor.go:190-208`), which explicitly rejects a key whose `RunnerID`/`SystemID` don't match the current runner before trusting any embedded fields.

### Finding Description
`parseEnvKeyFields` (`executors/docker/environment_key_fields.go:32-52`) only checks that `build-container-id` and `helper-id` are non-empty strings — it performs no ownership/ACL check tying the IDs to the job/runner that is resuming. The docker executor's `resumeDependencies` (`executors/docker/docker.go:1515-1536`) then trusts these IDs completely:

```go
envKey, err := common.ParseEnvironmentKey(e.Build.EnvironmentKey())
...
fields, err := parseEnvKeyFields(envKey.Fields)
...
buildInspect, err := e.dockerConn.ContainerInspect(e.Context, fields.buildContainerID)
...
helperInspect, err := e.dockerConn.ContainerInspect(e.Context, fields.helperContainerID)
e.helperContainer = &helperInspect
```

Unlike the autoscaler path, there is no equivalent of `validateEnvKey`'s `key.RunnerID != runnerID` / `key.SystemID != systemID` guard here, so `resumeDependencies` will attach to *any* container ID reachable via the local Docker daemon, provided it can be parsed out of an `EnvironmentKey` string.

However, the actual reachability of this bug depends on whether an unprivileged attacker can control the `EnvironmentKey` string that ends up in their own job's `SuspendOptions.EnvironmentKey` (`common/spec/spec.go` `SuspendOptions`, consumed via `common.Build.EnvironmentKey()` at `common/build.go:282-287`). Based on the code available in this repository, that value is:
- produced by the runner itself in `common.Build.suspendEnvironment` (`common/build.go:289-308`), which calls the executor's own `Suspend()` and serializes the result with the runner's *own* `RunnerID`/`SystemID`,
- sent to GitLab via `trace.SetEnvironmentKey` (`network/trace.go`), and
- returned back to the runner as part of a subsequent job payload for retry/resume.

There is no code in this repository exposing a way for a pipeline author's job script, CI YAML, or job variables to directly set/overwrite `SuspendOptions.EnvironmentKey` for their own job before it reaches `resumeDependencies`. The value is round-tripped through the GitLab backend, which is a trust boundary outside this repo's scope (server-side authorization of trace updates), and forging it would require either backend compromise or a currently-undemonstrated way to inject arbitrary trace-update payloads — both are excluded by the rules ("external service compromise alone", "GitLab-admin compromise").

### Impact Explanation
If the `EnvironmentKey` string were attacker-controllable (which is not demonstrated to be possible from within this repo), the missing `RunnerID`/`SystemID` check in `resumeDependencies` would let a job attach to and interact with a foreign helper/build container on the same Docker host, potentially exposing secrets injected into that container's environment. As it stands, this is a defense-in-depth gap relative to the autoscaler executor's equivalent code path, not a demonstrated, independently-reachable exploit for an unprivileged GitLab user.

### Likelihood Explanation
Low/unproven. The precondition — attacker-controlled `EnvironmentKey` on their own job — is not shown to be achievable through any interface reachable by a normal GitLab user or pipeline author in this codebase; the field is generated and routed exclusively through the runner and GitLab backend. Absent that control, `parseEnvKeyFields`/`resumeDependencies` are only ever invoked with a key the runner itself produced.

### Recommendation
Regardless of the current reachability question, add the same ownership check that `executors/internal/autoscaler/executor.go`'s `validateEnvKey` performs to the Docker executor's `resumeDependencies`: verify `envKey.RunnerID == e.Config.ID` and `envKey.SystemID == e.Config.GetSystemID()` before trusting `fields.buildContainerID`/`fields.helperContainerID`. This closes the defense-in-depth gap even if the upstream trust assumption about `SuspendOptions.EnvironmentKey` is ever violated (e.g., a future code path exposes it to less-trusted input).

func parseEnvKeyFields(fields url.Values) (envKeyFields, error) {
	k := envKeyFields{
		buildContainerID:  fields.Get(envKeyBuildContainerIDField),
		helperContainerID: fields.Get(envKeyHelperIDField),
	}
	if k.buildContainerID == "" {
		return envKeyFields{}, fmt.Errorf("%s is required", envKeyBuildContainerIDField)
	}
	if k.helperContainerID == "" {
		return envKeyFields{}, fmt.Errorf("%s is required", envKeyHelperIDField)
	}
	if raw := fields.Get(envKeyServiceIDsField); raw != "" {
		k.serviceContainerIDs = strings.Split(raw, ",")
		for _, id := range k.serviceContainerIDs {
			if id == "" {
				return envKeyFields{}, fmt.Errorf("%s contains an empty ID", envKeyServiceIDsField)
			}
		}
	}
	return k, nil
}

func validateEnvKey(envKey string, runnerID int64, systemID string) (string, url.Values, error) {
	key, err := common.ParseEnvironmentKey(envKey)
	if err != nil {
		return "", nil, err
	}

	if key.RunnerID != runnerID {
		return "", nil, errors.New("environment key was not issued by this runner")
	}
	if key.SystemID != systemID {
		return "", nil, errors.New("environment key was not issued by this machine")
	}

	data, executorFields, err := parseEnvKeyFields(key.Fields)
	if err != nil {
		return "", nil, fmt.Errorf("environment key fields: %w", err)
	}

	return data.acqKey, executorFields, nil

func (b *Build) EnvironmentKey() string {
	if !b.IsFeatureFlagOn(featureflags.SuspendableEnvironments) {
		return ""
	}
	return b.Job.SuspendOptions.EnvironmentKey
}

func (b *Build) suspendEnvironment(ctx context.Context, executor Executor) (string, error) {
	se, ok := executor.(SuspendableExecutor)
	if !ok {
		b.logger.Warningln("Job environment suspension not supported by executor")
		return "", errors.New("executor does not support suspend/resume")
	}
	fields, err := se.Suspend(ctx)
	if err != nil {
		b.logger.Warningln("Job environment suspension failed:", err.Error())
		return "", fmt.Errorf("suspending environment: %w", err)
	}
	envKey := EnvironmentKey{
		RunnerID: b.Runner.ID,
		SystemID: b.Runner.GetSystemID(),
		Fields:   fields,
	}
	s := envKey.String()
	b.logger.Infoln("Job environment suspended:", s)
	return s, nil
}
