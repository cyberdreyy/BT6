### Title
JWT Replay-Cache Check-and-Record Race Allows Reuse of a Single-Use HTTP Trigger JWT - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize` is meant to enforce that each JWT (identified by its `jti` claim) can authorize exactly one HTTP trigger request. The check (`isReplay`) and the mark-as-used step (`recordUsage`) are two separate, non-atomic operations, protected by independent lock acquisitions rather than a single atomic check-and-set. This mirrors the root cause of the reported `TrufVesting.claimable` bug: a "have I already consumed this allowance" check that does not durably/atomically reflect prior consumption before it can be reused, letting an unprivileged caller re-derive the same allowed action repeatedly.

### Finding Description
`Authorize` is the gateway-side authorization function for the internet-facing HTTP Trigger capability, invoked for every unprivileged, unauthenticated (pre-JWT-check) HTTP trigger request that reaches the gateway: [1](#0-0) 

The flow is:
1. `claims, signer, err := utils.VerifyRequestJWT(token, *req)` — verifies signature/expiry.
2. `if h.jwtCache.isReplay(claims.ID) { ... return error }` — read-only check against the map [2](#0-1) .
3. Authorized-key lookup for the workflow.
4. `h.jwtCache.recordUsage(claims.ID)` — only now is the jti marked used [3](#0-2) .

`isReplay` and `recordUsage` take independent `RWMutex` locks on the underlying map: [4](#0-3) 

Because the "already used" check and the "mark used" write are not combined into one atomic compare-and-set, two (or more) concurrent HTTP trigger requests carrying the identical JWT can both pass `isReplay` before either calls `recordUsage`. This is structurally the same class of bug as `TrufVesting.claimable`: a state read used to gate a single-use grant is evaluated without accounting for concurrent/in-flight consumption, so the same one-time credential can be "claimed" more than once.

### Impact Explanation
A JWT is supposed to authorize exactly one trigger invocation per the code's own comment/error message ("JWT token has already been used. Please generate a new one with new id (jti)"). By racing two requests with the same token, an unprivileged HTTP client (any external caller reaching the gateway's HTTP Trigger capability) can cause the DON to accept and dispatch the trigger to workflow nodes more than once for a single signed authorization, bypassing the intended single-use replay protection. Since the HTTP Trigger path is what starts workflow executions (potentially ones that move funds or perform privileged on-chain actions), duplicate acceptance of one credential is a request-impersonation/replay-bypass primitive analogous to the disclosed contract bug's "repeat the same claim to extract more than entitled."

### Likelihood Explanation
Exploitation only requires firing two requests with the same signed JWT in close time proximity (well within normal network jitter/latency), which is trivial for any client capable of reaching the gateway HTTP endpoint — no special privileges, node access, or wallet key beyond a validly issued JWT are needed. The race window is small but real given `isReplay`/`recordUsage` are two separate lock sections instead of one atomic operation, and gateway handling for a given request typically also performs authorized-key lookups and DON dispatch work between the two calls, widening the window.

### Recommendation
Merge `isReplay` and `recordUsage` into a single atomic check-and-set operation performed under one write-lock acquisition, e.g.:
```go
func (cache *jwtReplayCache) checkAndRecord(jti string) bool {
    cache.mu.Lock()
    defer cache.mu.Unlock()
    if _, exists := cache.cache[jti]; exists {
        return false // already used
    }
    cache.cache[jti] = time.Now()
    return true
}
```
Call this once in `Authorize` immediately after successful signature verification (or right before returning success) instead of using the separate `isReplay` + `recordUsage` calls, closing the TOCTOU window.

### Proof of Concept
Conceptual PoC (Go pseudo-test) demonstrating the race, based on `WorkflowMetadataHandler.Authorize`:
```go
func TestJWTReplayRace(t *testing.T) {
    h := NewWorkflowMetadataHandler(...)
    h.authorizedKeys[workflowID] = map[gateway.AuthorizedKey]struct{}{key: {}}

    token, req := signValidJWT(t, jti, signer) // single valid JWT/request pair

    var wg sync.WaitGroup
    results := make([]error, 2)
    for i := 0; i < 2; i++ {
        wg.Add(1)
        go func(idx int) {
            defer wg.Done()
            _, results[idx] = h.Authorize(workflowID, token, req)
        }(i)
    }
    wg.Wait()

    // Expectation: exactly one of results should be non-nil (rejected as replay).
    // Under the race, both can return nil (both authorized), proving double-use
    // of a single-use JWT.
}
```

```go
func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
```

```go
func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
```
