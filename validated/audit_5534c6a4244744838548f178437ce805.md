### Title
`getSupply`/`getLargestAccounts` bypass the operator-configured `scan_results_limit_bytes` guard, causing unbounded-size stake-account scan and deserialization - (File: `runtime/src/non_circulating_supply.rs`)

### Summary
`calculate_non_circulating_supply` calls `bank.get_filtered_indexed_accounts(&IndexKey::ProgramId(stake::program::id()), ..., None)` with the `byte_limit_for_scan` hard-coded to `None`, unlike the sibling RPC helper `JsonRpcRequestProcessor::get_filtered_indexed_accounts` (used by `getProgramAccounts`) which passes `self.config.scan_results_limit_bytes`. Because `getSupply` and `getLargestAccounts` both route through `calculate_non_circulating_supply`, the size guard that operators can enable via `--accounts-index-scan-results-limit-mb` is silently bypassed for these two endpoints.

### Finding Description
The call chain is: RPC `getSupply` → `JsonRpcRequestProcessor::get_supply` → `JsonRpcRequestProcessor::calculate_non_circulating_supply` → `runtime::non_circulating_supply::calculate_non_circulating_supply` → `bank.get_filtered_indexed_accounts(index_key, filter, None)`. [1](#0-0) [2](#0-1) [3](#0-2) 

The generic RPC scan path (`get_filtered_indexed_accounts`, used by `getProgramAccounts`) explicitly threads `self.config.scan_results_limit_bytes` through to `bank.get_filtered_indexed_accounts`, and that limit is enforced inside `Accounts::load_by_index_key_with_filter` via `accumulate_and_check_scan_result_size`, which aborts the scan (`ScanError::Aborted`) once the accumulated (pubkey+account) byte total exceeds the configured limit. [4](#0-3) [5](#0-4) 

`calculate_non_circulating_supply`, however, never receives or forwards the operator's configured limit — it is a free function that takes only `&Bank`, so it cannot see `JsonRpcConfig::scan_results_limit_bytes` and passes `None` unconditionally. This means even if an operator explicitly hardens the node with `--accounts-index-scan-results-limit-mb` specifically to bound the cost of index scans, `getSupply` and `getLargestAccounts` (both of which call this function) remain fully unbounded. [6](#0-5) [7](#0-6) 

An account's `owner` field is freely settable at creation time via the System Program's `CreateAccount`/`Assign` instructions (only the new account's keypair must sign, not the target owner program), so an unprivileged client can write arbitrary numbers of accounts with `owner == stake::program::id()` that are indexed under the `ProgramId` secondary index without any interaction from the real Stake program. These accounts do not need to contain valid `StakeStateV2` data — `deserialize_data::<StakeStateV2>().unwrap_or_default()` silently falls back to a default on failed deserialization, so garbage data is safely tolerated and does not panic, but every single indexed account is still fully loaded into memory as part of the unbounded `Vec<KeyedAccountSharedData>` and deserialization is attempted. [8](#0-7) 

### Impact Explanation
A single `getSupply` (or `getLargestAccounts` with a `filter`) RPC call triggers a scan over every account currently owned by the Stake program in the `ProgramId` secondary index, with no byte-size cap regardless of node configuration, in contrast to `getProgramAccounts` which is bounded when the operator sets the limit. If an attacker has previously written a very large number of stake-program-owned accounts on-chain (a one-time cost paid by the attacker in rent-exempt lamports and transaction fees, not by the query itself), a single subsequent `getSupply` call forces the validator's RPC-serving thread to load and iterate the entire result set, causing unbounded memory allocation and CPU time proportional to attacker-controlled on-chain data volume for one low-rate query — this matches the "unbounded cost for a single low-rate call" impact category.

### Likelihood Explanation
Feasible: the only precondition is that the validator has the `AccountIndex::ProgramId` secondary index enabled (common on RPC nodes serving `getProgramAccounts`), and that the attacker has previously created/funded a large number of stake-program-owned accounts, an activity requiring no special privilege beyond paying rent and fees. The exploit itself is a single `getSupply` call, satisfying the "≤1 call per CLUSTER_SLOT_TIME_TARGET/2" constraint, and is fully repeatable at will once the on-chain accounts exist.

### Recommendation
Thread an explicit `byte_limit_for_scan: Option<usize>` parameter into `calculate_non_circulating_supply` (and its caller `JsonRpcRequestProcessor::calculate_non_circulating_supply`) so that `self.config.scan_results_limit_bytes` is honored the same way it is for `get_filtered_indexed_accounts`, ensuring `getSupply` and `getLargestAccounts` are covered by the same operator-configured scan-size guard.

### Proof of Concept
Integration test plan (Rust, in `runtime/src/non_circulating_supply.rs` or `rpc/src/rpc.rs` test module):
1. Build a `Bank` with `AccountSecondaryIndexes { indexes: {AccountIndex::ProgramId} }` enabled, as done in `test_get_filtered_indexed_accounts_limit_exceeded` (`runtime/src/bank/tests.rs:3470-3502`).
2. Store `N` (e.g., 100_000) accounts owned by `stake::program::id()`, each containing arbitrary (non-`StakeStateV2`) data of realistic size (e.g., `StakeStateV2::size_of()` bytes filled with zero/garbage), similar to `test_calculate_non_circulating_supply` (`runtime/src/non_circulating_supply.rs:450-512`) but scaled up.
3. Call `bank.get_filtered_indexed_accounts(&IndexKey::ProgramId(program_id), filter, Some(small_limit))` directly and assert it returns `Err(ScanError::Aborted(_))`, confirming the guard works when a limit is supplied.
4. Call `calculate_non_circulating_supply(&bank)` (the unmodified function, which hard-codes `None`) and assert that it succeeds and returns all `N` accounts regardless of the configured/would-be limit, and measure wall-clock time/memory to show it scales linearly with `N` and is unbounded by any single-call budget — proving the bypass.
5. Recommended assertion after fix: `calculate_non_circulating_supply(&bank, Some(limit))` (or equivalent) returns `Err`/aborts once the same `N` accounts exceed `limit`, matching the behavior in step 3.

    /// Accumulate size of (pubkey + account) into sum.
    /// Return true iff sum > 'byte_limit_for_scan'
    fn accumulate_and_check_scan_result_size(
        sum: &AtomicUsize,
        account: &AccountSharedData,
        byte_limit_for_scan: &Option<usize>,
    ) -> bool {
        if let Some(byte_limit_for_scan) = byte_limit_for_scan.as_ref() {
            let added = Self::calc_scan_result_size(account);
            sum.fetch_add(added, Ordering::Relaxed)
                .saturating_add(added)
                > *byte_limit_for_scan
        } else {
            false
        }
    }

    fn maybe_abort_scan(
        result: ScanResult<Vec<KeyedAccountSharedData>>,
        config: &ScanConfig,
    ) -> ScanResult<Vec<KeyedAccountSharedData>> {
        if config.is_aborted() {
            ScanResult::Err(ScanError::Aborted(
                "The accumulated scan results exceeded the limit".to_string(),
            ))
        } else {
            result
        }
    }

    pub fn load_by_index_key_with_filter<F: Fn(&AccountSharedData) -> bool>(
        &self,
        ancestors: &Ancestors,
        bank_id: BankId,
        index_key: &IndexKey,
        filter: F,
        byte_limit_for_scan: Option<usize>,
    ) -> ScanResult<Vec<KeyedAccountSharedData>> {
        let sum = AtomicUsize::default();
        let config = ScanConfig::default().recreate_with_abort();
        let mut collector = Vec::new();
        let result = self
            .accounts_db
            .index_scan_accounts(
                ancestors,
                bank_id,
                *index_key,
                |some_account_tuple| {
                    Self::load_while_filtering(&mut collector, some_account_tuple, |account| {
                        let use_account = filter(account);
                        if use_account
                            && Self::accumulate_and_check_scan_result_size(
                                &sum,
                                account,
                                &byte_limit_for_scan,
                            )
                        {
                            // total size of results exceeds size limit, so abort scan
                            config.abort();
                        }
                        use_account
                    });
                },
                &config,
            )
            .map(|_| collector);
        Self::maybe_abort_scan(result, &config)
    }
