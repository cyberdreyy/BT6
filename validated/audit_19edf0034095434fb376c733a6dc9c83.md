The code explicitly implements fail-closed timeout handling, and the claimed wedge does not exist.

`check_submitted_block_proposal` in `stacks-signer/src/v0/signer.rs` tracks exactly one `(signer_signature_hash, Instant)` pair in `self.submitted_block_proposal`. When `block_submission.elapsed() >= self.block_proposal_validation_timeout`, it looks up the block by that exact `proposal_signer_sighash`, and if consensus hasn't already been reached, it calls `create_block_rejection(RejectReason::ConnectivityIssues(...), &block_info.block)`, marks it `mark_locally_rejected`, and broadcasts the rejection via `send_block_response`. [1](#0-0) 

`check_pending_block_validations` (called both after every event loop pass and right after `handle_block_validate_response`) only pops the oldest pending entry via `get_and_remove_pending_block_validation()` and looks up `block_lookup(&signer_sig_hash)` for that *same* hash before submitting — there is no code path where a `BlockValidateOk` for one `signer_signature_hash` gets attributed to a different pending block. [2](#0-1) 

`handle_block_validate_response` matches strictly on `block_validate_response.signer_signature_hash()` when removing the pending-validation row, and dispatches `Ok`/`Reject` verdicts to `handle_block_validate_ok`/`handle_block_validate_reject`, which operate on the block keyed by that hash — never on a stale lookup keyed by reward cycle. [3](#0-2) 

There is also an integration test (`block_validation_response_timeout`) that explicitly drives this exact scenario — stalling the node's validation, waiting past `block_proposal_validation_timeout`, and asserting the signer emits a `BlockResponse::Rejected` with `RejectCode::ConnectivityIssues` for the correct `signer_signature_hash`, and never accepts. [4](#0-3) 

The node-side `NakamotoBlockProposal::validate` timeout (`block_proposal_validation_timeout_secs`, `block_proposal_max_tx_execution_time_secs`) is independent and only affects when the node's `spawn_validation_thread` returns a `BlockValidateReject`/`Ok` to the signer over the callback channel; it does not create any cross-hash confusion on the signer side. [5](#0-4)

    /// Check the current tracked submitted block proposal to see if it has timed out.
    /// Broadcasts a rejection and marks the block locally rejected if it has.
    fn check_submitted_block_proposal(&mut self) {
        let Some((proposal_signer_sighash, block_submission)) =
            self.submitted_block_proposal.take()
        else {
            // Nothing to check.
            return;
        };
        if block_submission.elapsed() < self.block_proposal_validation_timeout {
            // Not expired yet. Put it back!
            self.submitted_block_proposal = Some((proposal_signer_sighash, block_submission));
            return;
        }
        // For mutability reasons, we need to take the block_info out of the map and add it back after processing
        let mut block_info = match self.signer_db.block_lookup(&proposal_signer_sighash) {
            Ok(Some(block_info)) => {
                if block_info.has_reached_consensus() {
                    // The block has already reached consensus.
                    return;
                }
                block_info
            }
            Ok(None) => {
                // This is weird. If this is reached, its probably an error in code logic or the db was flushed.
                // Why are we tracking a block submission for a block we have never seen / stored before.
                error!("{self}: tracking an unknown block validation submission.";
                    "signer_signature_hash" => %proposal_signer_sighash,
                );
                return;
            }
            Err(e) => {
                error!("{self}: Failed to lookup block in signer db: {e:?}",);
                return;
            }
        };
        // We cannot determine the validity of the block, but we have not reached consensus on it yet.
        // Reject it so we aren't holding up the network because of our inaction.
        warn!(
            "{self}: Failed to receive block validation response within {} ms. Rejecting block.", self.block_proposal_validation_timeout.as_millis();
            "signer_signature_hash" => %proposal_signer_sighash,
        );
        let rejection = self.create_block_rejection(
            RejectReason::ConnectivityIssues(
                "failed to receive block validation response in time".to_string(),
            ),
            &block_info.block,
        );
        block_info.reject_reason = Some(rejection.response_data.reject_reason.clone());
        if let Err(e) = block_info.mark_locally_rejected() {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally rejected: {e:?}");
            }
        };
        self.send_block_response(&block_info.block, rejection.into());

        self.signer_db
            .insert_block(&block_info)
            .unwrap_or_else(|e| self.handle_insert_block_error(e));
    }

    fn spawn_validation_thread(
        self,
        sortdb: SortitionDB,
        mut chainstate: StacksChainState,
        receiver: Box<dyn ProposalCallbackReceiver>,
        connection_opts: &ConnectionOptions,
    ) -> Result<JoinHandle<()>, std::io::Error> {
        let timeout_secs = connection_opts.block_proposal_validation_timeout_secs;
        let max_tx_execution_time_secs = connection_opts.block_proposal_max_tx_execution_time_secs;
        let max_tx_analysis_time_secs = connection_opts.block_proposal_max_tx_analysis_time_secs;
        let max_tx_mem_bytes = connection_opts.block_proposal_max_tx_mem_bytes;
        let auth_token = connection_opts.auth_token.clone();
        thread::Builder::new()
            .name("block-proposal".into())
            .spawn(move || {
                let result = self
                    .validate(
                        &sortdb,
                        &mut chainstate,
                        timeout_secs,
                        max_tx_execution_time_secs,
                        max_tx_analysis_time_secs,
                        max_tx_mem_bytes,
                        auth_token,
                    )
                    .map_err(|reason| BlockValidateReject {
                        signer_signature_hash: self.block.header.signer_signature_hash(),
                        reason_code: reason.reason_code,
                        reason: reason.reason,
                        failed_txid: reason.failed_txid,
                    });
                receiver.notify_proposal_result(result);
            })
    }
