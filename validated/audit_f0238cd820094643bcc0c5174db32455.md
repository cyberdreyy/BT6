# APTOS STAKE-LOCKUP REVIEW — Analysis Result

## Title
`switch_operator` re-keys a `distribution_pool` still holding the old operator's unresolved commission shares, causing `update_distribution_pool`/`distribute_internal` to re-tax and misdirect that commission to the new operator - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

## Summary
`switch_operator` moves the entire `StakingContract` struct — including its `distribution_pool` (`Pool`) — from the `old_operator` key to the `new_operator` key inside `Store.staking_contracts` [1](#0-0) . Before the re-key, it calls `distribute_internal` and `request_commission_internal` with `old_operator` explicitly [2](#0-1) , but `request_commission_internal` only *unlocks* the commission into `pending_inactive` state and records a share for `old_operator` in the pool — it does not, and cannot, wait for the lockup to fully expire and pay it out [3](#0-2) . That unresolved share entry, keyed by `old_operator`'s address inside the `Pool`, survives the re-key and is now attached to a `StakingContract` reachable only via the `new_operator` key.

## Finding Description
Once the lockup expires, anyone can call the unprivileged `distribute(staker, new_operator)` entry function [4](#0-3) , which invokes `distribute_internal` with `operator = new_operator`. Inside, `update_distribution_pool` is called with this same `new_operator` value and iterates every shareholder in the pool, exempting only `shareholder != operator` from commission extraction [5](#0-4) :

```
if (shareholder != operator) {
    ... unpaid_commission = (current_worth - previous_worth) * commission_percentage / 100;
    pool_u64::transfer_shares(distribution_pool, shareholder, operator, shares_to_transfer);
};
```

Since the stale share entry is keyed by `old_operator`, and `old_operator != new_operator`, the pool treats the old operator's already-committed commission as if it were an ordinary staker/rewards contribution. Any reward growth accrued on that pending-inactive balance between the `switch_operator` call and the final `distribute` call is taxed *again*, at the *new* (post-switch) `commission_percentage`, and the resulting shares are transferred to `new_operator` — silently diverting part of `old_operator`'s already-earned, already-unlocked commission to the new operator.

Separately, in the payout loop of `distribute_internal`, the beneficiary-redirect check also keys off the live `operator` parameter [6](#0-5) :

```
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
```

Because the stale shareholder is `old_operator` while `operator` in this call is `new_operator`, this comparison fails, so `old_operator`'s remaining commission bypasses `beneficiary_for_operator(old_operator)` entirely and is paid to the raw `old_operator` account rather than the beneficiary address `old_operator` had configured via `set_beneficiary_for_operator` [7](#0-6) .

The root cause is that the `Pool`'s notion of "which shareholder is the operator (exempt from commission / eligible for beneficiary redirect)" is derived purely from the `operator` argument passed at call time (i.e., whichever address currently keys the `StakingContract` in the `SimpleMap`), rather than from the identity that actually earned each specific share entry.

## Impact Explanation
This falls under "Operator commission, beneficiary payout, or share-accounting corruption that credits the wrong account" from the Required Impacts. A portion of the old operator's legitimately earned, already-unlocked commission (unlocked via `request_commission_internal` during the switch) is:
1. Taxed a second time using the new operator's commission rate and transferred as extra shares to `new_operator`, and
2. When eventually paid out, sent to `old_operator`'s bare account instead of the beneficiary address `old_operator` configured, breaking the beneficiary abstraction for that specific residual amount.

This is a genuine accounting corruption bug in production commission-distribution logic, not merely an event/display mismatch.

## Likelihood Explanation
This triggers under normal (non-malicious) operation: it only requires (a) a staker calling `switch_operator`/`switch_operator_with_same_commission` while the old operator has commission that was just unlocked via `request_commission_internal` inside the switch but hasn't yet cleared the pool's lockup period to become `inactive`, and (b) the standard, permissionless `distribute` call once the lockup expires. No attacker-controlled transaction ordering of `distribute_internal`/`request_commission_internal` is actually required — the vulnerable window arises intrinsically from the lockup delay between "unlock" and "inactive/withdrawable," which is unavoidable in every switch that has a nonzero pending commission. The existing regression test `test_operator_can_set_beneficiary` only exercises the case where no commission is pending at switch time (a fully-flushed distribution pool before `switch_operator` is called) [8](#0-7) , so this scenario is not covered by existing tests.

## Recommendation
`update_distribution_pool`'s commission-exemption/beneficiary-redirect logic should not rely on comparing shareholder identity to the *current* `operator` argument. Instead, either:
- Immediately and fully resolve (pay out or convert to a non-commission-bearing claim) any operator-owned shares in the `distribution_pool` before allowing `switch_operator` to re-key the `StakingContract`, or
- Track, per shareholder entry, whether that entry represents "operator commission already finalized" (exempt from future commission taxation and eligible for beneficiary lookup against the *original* operator address), independent of whichever address currently occupies the `operator` role for that pool.

## Proof of Concept
Conceptual Move test, following the pattern of `test_operator_can_set_beneficiary` [9](#0-8) :

1. `setup_staking_contract(staker, operator1, INITIAL_BALANCE, commission=10)`; `operator1` sets a beneficiary via `set_beneficiary_for_operator`.
2. `stake::end_epoch()` to accrue rewards.
3. Call `request_commission(operator1, staker, operator1)` — this unlocks `commission_1` into `pending_inactive` and records a share for `operator1` in `distribution_pool` (do **not** call `distribute` yet, so the funds stay `pending_inactive`, not `inactive`).
4. Immediately call `switch_operator(staker, operator1, operator2, new_commission=50)`. Inside, `distribute_internal`/`request_commission_internal` run against `operator1` but the `pending_inactive` `commission_1` cannot be withdrawn yet (lockup not expired), so the `operator1`-keyed share persists in the pool, which is now re-keyed to `operator2`.
5. `stake::end_epoch()` several times so the pending-inactive stake accrues further reward growth, then `stake::fast_forward_to_unlock(pool_address)` so it becomes `inactive`.
6. Call unprivileged `distribute(staker, operator2)`.
7. Assert: `operator1`'s beneficiary balance reflects only `commission_1` as computed at step 3 (pre-switch), with **no** deduction from subsequent reward growth on that entry; and assert `operator2`'s balance/shares do **not** include any extra amount skimmed from `operator1`'s pending commission entry. The current implementation will fail this assertion, since `update_distribution_pool` skims additional commission (at the new 50% rate) from `operator1`'s share into `operator2`, and pays the remainder directly to `operator1`'s raw address instead of `operator1`'s beneficiary.

```text
    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }
```

```text
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);

            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
```

```text
    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
```
