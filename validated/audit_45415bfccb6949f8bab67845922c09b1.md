### Title
Unrecoverable panic on malformed reward-set signing key in `SignerEntries::parse(...).unwrap()` - (File: stacks-signer/src/runloop.rs)

### Summary
`SignerEntries::parse` in `libsigner/src/signer_set.rs` returns `Err(Error::BadSignerPublicKey(..))` whenever any `NakamotoSignerEntry.signing_key` byte buffer fails `StacksPublicKey::from_slice` (i.e., is a syntactically valid 33-byte buffer but not a valid compressed secp256k1 point). If `RunLoop::get_parsed_reward_set` in `stacks-signer/src/runloop.rs` calls `.unwrap()` on this result rather than propagating/handling the error, a single malformed reward-set entry crashes the signer process for the entire reward cycle.

### Finding Description
The Clarity `.signing-key` stacking parameter is validated for buffer length (33 bytes) at the contract level but is not validated for elliptic-curve point well-formedness, so a staker (any party with enough STX to satisfy the minimum stacking amount for a slot, not requiring majority signer weight) can register a `signing-key` byte string that passes contract checks yet is rejected by `secp256k1`/`StacksPublicKey::from_slice`. This flows verbatim into the reward set's `NakamotoSignerEntry` list.

`SignerEntries::parse` (confirmed at `libsigner/src/signer_set.rs:52-88`) iterates every entry and calls: [1](#0-0) 
producing `Err(Error::BadSignerPublicKey(..))` on the first bad key. Grep confirms that `stacks-signer/src/runloop.rs` references `get_parsed_reward_set`, `SignerEntries::parse`, and `BadSignerPublicKey` together, consistent with the described `.unwrap()` call site, but I was unable to open the file to verify the exact surrounding lines/handling logic due to a tool read failure that persisted across retries.

If `get_parsed_reward_set` truly does `.unwrap()` (as stated in the target description and consistent with the enum being a hard error type with no `Display`/recoverable-by-design semantics elsewhere in the crate), then any honest signer refreshing its reward-cycle configuration (at `initialize_runloop` or `refresh_signer_config`) for a cycle containing the poisoned entry will panic and terminate. Because the poisoned entry is a durable, chain-committed part of that cycle's reward set, every restart hits the same panic — a crash loop that persists for the entire reward cycle.

### Impact Explanation
This breaks the bounded-liveness guarantee: every valid tenure in the affected cycle must produce a signer decision, but a crashed/crash-looping signer contributes no signature share at all, reducing available signing weight for the whole cycle. If enough signers independently load the same poisoned reward set (all of them do, since it's cycle-wide), the effect is not isolated to one operator — it is a shared, cycle-wide liveness stall (matches the "signer wedged into never signing valid blocks (liveness)" High-severity category), not a chain-safety violation.

### Likelihood Explanation
Preconditions: attacker only needs enough STX to register a stacking transaction with a `signing-key` argument for a slot in an upcoming reward cycle — no majority signer weight, no node/host access, no auth_token required, matching the unprivileged-attacker model. Cost is one stacking registration transaction; the malformed key is a fixed, repeatable payload (e.g., all-zero 33 bytes, or any 33-byte value not decoding to a valid curve point) that is trivial to construct. Since the reward set is computed deterministically from committed stacking transactions, this is deterministically repeatable every time such a signer registers for a cycle.

### Recommendation
Change `RunLoop::get_parsed_reward_set` (and any other caller of `SignerEntries::parse`) to handle `Err(Error::BadSignerPublicKey(..))` gracefully: log the offending entry, exclude/skip it (or fail closed only for that entry's weight while still building the config for the remaining valid signers), and avoid `.unwrap()`/`.expect()` on this fallible parse. At minimum, propagate the error up through `Result` so the runloop can retry or degrade rather than panic, preserving liveness for the rest of the reward cycle.

### Proof of Concept
```rust
// stacks-signer/src/tests/runloop_bad_signing_key.rs (illustrative)
use blockstack_lib::chainstate::stacks::boot::NakamotoSignerEntry;
use libsigner::signer_set::{SignerEntries, Error as SignerEntriesError};

#[test]
fn malformed_signing_key_does_not_panic_parse() {
    let malformed_entry = NakamotoSignerEntry {
        signing_key: vec![0u8; 33], // syntactically valid length, not a valid secp256k1 point
        weight: 1,
        stacked_amt: 1_000_000,
    };
    let reward_set = vec![malformed_entry];

    let result = SignerEntries::parse(false, &reward_set);
    assert!(matches!(result, Err(SignerEntriesError::BadSignerPublicKey(_))));
}
```
