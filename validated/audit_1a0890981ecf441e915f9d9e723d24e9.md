### Title
View-role (and any authenticated) user can read bridge `OutgoingToken` via unrestricted GET /v2/bridge_types/:BridgeName - ([File: core/web/router.go, core/web/bridge_types_controller.go, core/web/presenters/bridges.go])

### Summary
The `GET /v2/bridge_types/:BridgeName` route is registered with only session/token authentication and no role check, unlike the sibling `Create`, `Update`, and `Destroy` routes which are wrapped in `auth.RequiresEditRole`. `BridgeTypesController.Show` returns a `presenters.BridgeResource` whose `OutgoingToken` field is serialized unconditionally (no `omitempty`, no redaction), so any authenticated user regardless of role — including the minimally-privileged `view` role — can retrieve the plaintext outgoing token used by the node to authenticate to the external bridge/adapter.

### Finding Description
In `v2Routes` (`core/web/router.go`), the bridge routes are:
```
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
```
`Show` (and `Index`) have no role wrapper, so only base `Authenticate` (session or token) applies — any valid session/token, including a user created with `sessions.UserRoleView`, is authorized.

`BridgeTypesController.Show` (`core/web/bridge_types_controller.go`) looks up the bridge by name and returns `presenters.NewBridgeResource(bt)` unmodified. `bridges.BridgeType.OutgoingToken` is the plaintext secret stored in the DB (as opposed to `IncomingTokenHash`+`Salt`, which are hashed). `presenters.BridgeResource` defines `OutgoingToken string \`json:"outgoingToken"\`` with no `omitempty` or redaction logic, while `IncomingToken` is explicitly commented as "only provided when creating a Bridge" and has `omitempty` — showing the codebase's own intent was to keep `IncomingToken` restricted to creation-time exposure, but no equivalent protection exists for `OutgoingToken` on `Show`/`Index`, nor any role gating.

The `auth.RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` middleware functions are the only places that reject `UserRoleView`; since `Show` uses none of them, the role check is entirely absent for this route.

### Impact Explanation
This discloses the bridge's `OutgoingToken`, a credential the Chainlink node uses to authenticate itself when calling out to the external adapter/bridge service. An attacker holding only a `view`-role session or API token (the lowest privilege level intended for read-only monitoring) can retrieve this secret and use it to impersonate the node to the external bridge, matching the "sensitive data exposure / credential disclosure" bounty class.

### Likelihood Explanation
Trivial and fully repeatable: it requires only a valid authenticated session/token of any role (the lowest, `view`, suffices) and a single `GET /v2/bridge_types/:BridgeName` request with a known or enumerable bridge name (bridge names are also listable via the equally unrestricted `GET /v2/bridge_types` index endpoint). No additional exploitation steps or timing are required.

### Recommendation
Wrap the `Show` (and `Index`) bridge routes with at least `auth.RequiresEditRole` (matching `Create`/`Update`/`Destroy`), or alternatively redact `OutgoingToken` in `presenters.NewBridgeResource` for callers below edit/admin role, similar to how `IncomingToken` is only populated on creation.

### Proof of Concept
Go handler-level integration test in `core/web/bridge_types_controller_test.go`:
1. Start `cltest.NewApplication`, create a `bridges.BridgeType` via `app.BridgeORM().CreateBridgeType` with a known non-empty `OutgoingToken`.
2. Create a user/session (or API token) with `sessions.UserRoleView` (see helper patterns used in `core/web/auth/auth_test.go`) and build an HTTP client authenticated as that user (rather than `app.NewHTTPClient(nil)`'s default admin/edit-role client).
3. Call `client.Get("/v2/bridge_types/" + bt.Name.String())`.
4. Assert `resp.StatusCode == http.StatusOK` and parse into `presenters.BridgeResource`; assert `resource.OutgoingToken == bt.OutgoingToken` (non-empty, matching the seeded secret) — demonstrating the view-role user obtained the raw token instead of a redaction/rejection (expected: `403 Forbidden` or a redacted `OutgoingToken`).

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
