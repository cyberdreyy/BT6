### Title
Unauthenticated step-status marker parsing allows job-controlled stdout to forge command status lines - ([File: executors/kubernetes/container_entrypoint_forwarder.go])

### Summary
`entrypointLogForwarder.commandStatus` (`executors/kubernetes/container_entrypoint_forwarder.go:91-113`) decides whether a line is a trusted "step status" marker purely by syntactic shape: a 30-byte string that `time.Parse`s as `containerLoggerTimeStampFormat`, followed by a space, followed by JSON matching `shells.StageCommandStatus`. There is no secret, nonce, or out-of-band channel distinguishing a wrapper-emitted marker from arbitrary job stdout, so a job script's own `echo` output can satisfy the check deterministically.

### Finding Description
`commandStatus` requires `p[len(containerLoggerTimeStampFormat)] == ' '` and that `p[:len(containerLoggerTimeStampFormat)]` parse via `time.Parse(containerLoggerTimeStampFormat, ts)` [1](#0-0) . The remainder of the line is handed to `shells.StageCommandStatus.TryUnmarshal`, which succeeds for any JSON object containing `command_exit_code` and/or `script` [2](#0-1) . If `commandStatus` returns `ok=true`, `writeLine` treats the line as authoritative: it toggles `lf.paused` (pausing/resuming forwarding of subsequent lines to the trace `Sink`) and, critically, always drops that line instead of writing it to the Sink [3](#0-2) .

The question's framing (that an attacker needs `time.Parse`'s fractional-second leniency to "coincidentally" land a space at the fixed offset) is not actually necessary to achieve exploitation: since the forwarder inspects the raw combined stdout/stderr stream of the running step (mixing the runner-injected wrapper's own status echoes with the job script's real output), an attacker who controls job commands (e.g. via `echo`) controls the *entire* byte sequence of a line, not just a suffix. They can trivially construct a compliant 30-byte timestamp by construction (e.g. `0001-01-01T00:00:00.000000000Z`, which is exactly `len(containerLoggerTimeStampFormat)` bytes and parses without error), append a space, and append arbitrary JSON such as `{"command_exit_code":0,"script":"build_script"}`. No coincidence, fuzzing, or exploitation of parser leniency is required — the check simply has no authentication factor at all.

### Impact Explanation
A job author can forge `StageCommandStatus` lines that cause `entrypointLogForwarder` to: (1) pause forwarding (`BuildStage() != ""`), suppressing subsequent real job output from reaching the trace/log sink, effectively hiding output from the pipeline log; or (2) forge an "exited" status (`IsExited()==true`) to resume forwarding early, potentially causing step-boundary confusion in whatever consumes step transitions. This matches the scoped impact: forged step transition / trace suppression, reachable purely through job-controlled stdout content.

### Likelihood Explanation
Precondition: attacker only needs to be a normal pipeline author using the Kubernetes executor with the attach/exec-based log processor that routes step-script stdout/stderr through `entrypointLogForwarder`. Crafting the marker line requires no secret, no timing, no race — a single `echo` statement with a fixed, hardcoded 30-character timestamp plus JSON payload deterministically triggers the code path every time. This makes it fully repeatable and does not depend on any "leniency" fuzzing search.

### Recommendation
Do not rely on syntactic shape alone to distinguish trusted wrapper markers from job output. Options: (a) emit wrapper status lines on a separate, job-inaccessible file descriptor/stream rather than mixing them into job stdout/stderr; (b) prefix wrapper markers with an unguessable per-job/per-step random token (generated by the runner, not derivable from job config) that is verified before treating a line as a status marker; (c) if markers must share the stream, HMAC or otherwise authenticate the marker payload using a runner-side secret unknown to the job.

### Proof of Concept
```go
func TestEntrypointLogForwarder_JobCanForgeStatusLine(t *testing.T) {
    sink := &bytes.Buffer{}
    lf := &entrypointLogForwarder{Sink: nopWriteCloser{sink}}

    // Attacker-controlled line: fixed, always-parseable timestamp + forged JSON.
    forged := "0001-01-01T00:00:00.000000000Z {\"command_exit_code\":0,\"script\":\"build_script\"}\n"

    n, err := lf.Write([]byte(forged))
    require.NoError(t, err)
    require.Equal(t, len(forged), n)

    // The forged line must NOT be forwarded to the trace sink...
    require.Empty(t, sink.String())
    // ...and the forwarder's paused state was toggled by attacker-controlled input.
    require.False(t, lf.paused) // IsExited() branch set paused=false, proving line was accepted as a real status marker
}
```
Expected assertions: the forged line is absorbed (not written to `Sink`) and `lf.paused`/step-state changes based solely on job-controlled stdout content, confirming lack of authentication on the marker channel.

func (lf *entrypointLogForwarder) writeLine(p []byte) error {
	cmdStatus, ok := lf.commandStatus(p)
	if ok {
		if cmdStatus.IsExited() {
			lf.paused = false
		} else if cmdStatus.BuildStage() != "" {
			lf.paused = true
		}
	}

	if lf.paused || ok {
		return nil
	}

	_, err := lf.Sink.Write(p)
	return err
}

// TryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It wil return true only if the unmarshalled struct has all of its required fields be non-nil.
// It's safe to use the struct only if this method returns true.
func (c *StageCommandStatus) TryUnmarshal(line string) bool {
	var status stageCommandExitStatusImpl
	err := status.tryUnmarshal(line)
	if err != nil {
		return false
	}

	if status.isEmpty() {
		return false
	}

	status.applyTo(c)

	return true
}
