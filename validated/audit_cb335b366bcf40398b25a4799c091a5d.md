### Title
Truncated zip extra-field read silently zero-pads UID/GID data, causing unintended `os.Lchown` target - ([File: helpers/archives/zip_extra.go])

### Summary
`readZipExtraField` performs a single `r.Read(data)` call on a `bytes.Reader` without checking the returned byte count against `field.Size`, so a crafted zip "extra" field whose declared `Size` exceeds the remaining bytes in the buffer causes a silent short read. The resulting fixed-length `data` slice is only partially overwritten and the rest stays zero-initialized, yet `binary.Read` in `processZipUIDGidField` still succeeds against this zero-padded slice and calls `os.Lchown` with a corrupted (potentially all-zero/root) UID/GID.

### Finding Description
`readZipExtraField` allocates `data := make([]byte, field.Size)` and calls `r.Read(data)` exactly once, returning without checking `n` against `len(data)`: [1](#0-0) 

`processZipExtra` iterates extra fields from `bytes.NewReader(file.Extra)` (an in-memory reader fully derived from attacker-supplied `zip.FileHeader.Extra`), calling `readZipExtraField` and then dispatching by `field.Type`: [2](#0-1) 

`bytes.Reader.Read` follows the standard io.Reader contract: if the requested length exceeds the remaining unread bytes but remaining bytes are still > 0, it returns `n = remaining`, `err = nil` (a legitimate partial/short read). Because `data` was zero-allocated via `make`, any unread tail bytes remain `0x00`.

`processZipUIDGidField` then wraps this (possibly truncated) `data` in a fresh `bytes.NewReader(data)` and calls `binary.Read`, which only requires `len(data)` to equal the encoded struct size (11 bytes: `Version`+`UIDSize`+`UID`+`GIDSize`+`Gid`). Since `field.Size` (attacker-controlled, from the crafted extra field header) determines `len(data)`, `binary.Read` succeeds even though the actual bytes copied from the archive were fewer — the UID/Gid fields end up zero-padded/garbage relative to what the attacker intended to encode, and the code proceeds to call `os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))`: [3](#0-2) 

No length/consistency check exists anywhere in this path (no `io.ReadFull`, no `n == len(data)` check), so a malformed-but-parseable extra field silently proceeds instead of erroring out, violating the intended invariant that truncated extra-field data must be rejected.

### Impact Explanation
The extracted file's ownership can be silently set via `os.Lchown` to a UID/GID value that does not match any value the attacker actually encoded in full — most simply `0/0` if the truncation zeroes out the `UID`/`Gid` sub-fields while leaving `Version=1, UIDSize=4, GIDSize=4` intact in the surviving prefix bytes. This is a data-integrity/unintended-ownership bug in archive extraction (used for artifacts/cache zip handling), matching the scoped impact of "unintended ownership change from corrupted-but-parseable input." Actual privilege impact is bounded by the OS: `Lchown` to arbitrary UIDs (e.g., 0) will only succeed if the runner process has the privilege to chown to that UID (e.g., running as root); otherwise it fails with `EPERM` and `processZipExtra`/extraction aborts with an error. Either way, the code path incorrectly proceeds on corrupted input rather than validating it, which is the underlying logic flaw being reported.

### Likelihood Explanation
This is fully feasible to trigger: an attacker only needs to control the raw zip bytes fed into `archive/zip`, e.g. via a crafted artifact/cache zip archive processed by `commands/helpers` extraction code (`helpers/archives/zip_extract.go`), which calls `processZipExtra` for each `zip.FileHeader`. `zip.FileHeader.Extra` is populated by the Go standard library directly from the local/central directory "extra field" bytes in the zip, which are attacker-controlled in a crafted archive. The precondition (`field.Size` larger than the remaining extra-field bytes) is simple to construct and doesn't require exploiting any other guard, since there is no size/consistency validation anywhere in `readZipExtraField` or its callers.

### Recommendation
Replace the single `r.Read(data)` with `io.ReadFull(r, data)` in `readZipExtraField` (or explicitly check `n == len(data)` and return an error otherwise) so that any short read is treated as a hard parse error rather than silently producing a zero-padded/truncated buffer. Additionally, `processZipUIDGidField`/`processZipTimestampField` should not proceed when the input `data` length doesn't exactly correspond to bytes that were verifiably read from the source.

### Proof of Concept
```go
func TestReadZipExtraField_ShortReadNotSilentlyAccepted(t *testing.T) {
    // Craft an extra field header claiming Size=11 (ZipUIDGidField size)
    // but only provide 3 actual payload bytes: Version=1, UIDSize=4, GIDSize=4.
    var buf bytes.Buffer
    binary.Write(&buf, binary.LittleEndian, ZipExtraField{Type: ZipUIDGidFieldType, Size: 11})
    buf.Write([]byte{1, 4, 4}) // only 3 of the 11 declared bytes present

    r := bytes.NewReader(buf.Bytes())
    field, data, err := readZipExtraField(r)
    require.NoError(t, err) // BUG: no error even though only 3/11 bytes were available
    require.Equal(t, uint16(11), field.Size)
    require.Equal(t, 11, len(data))
    // data[3:11] are zero-padded, not real archive content
    require.Equal(t, make([]byte, 8), data[3:11])

    file := &zip.FileHeader{Name: "victim"}
    err = processZipUIDGidField(data, file)
    // BUG: succeeds with UID=0, Gid=0 (garbage/zero), instead of erroring on truncated input
    require.NoError(t, err)
}
```
Expected (fixed) behavior: `readZipExtraField` should return an error (e.g., `io.ErrUnexpectedEOF`) when fewer than `field.Size` bytes are available, so `processZipExtra` aborts extraction of that entry instead of calling `os.Lchown` with corrupted UID/GID data.

func readZipExtraField(r io.Reader) (field ZipExtraField, data []byte, err error) {
	err = binary.Read(r, binary.LittleEndian, &field)
	if err != nil {
		return
	}

	data = make([]byte, field.Size)
	_, err = r.Read(data)
	if err != nil {
		return
	}
	return
}

func processZipExtra(file *zip.FileHeader) error {
	if len(file.Extra) == 0 {
		return nil
	}

	r := bytes.NewReader(file.Extra)
	for {
		field, data, err := readZipExtraField(r)
		if err == io.EOF {
			break
		} else if err != nil {
			return err
		}

		switch field.Type {
		case ZipUIDGidFieldType:
			err = processZipUIDGidField(data, file)
		case ZipTimestampFieldType:
			err = processZipTimestampField(data, file)
		}
		if err != nil {
			return err
		}
	}

func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
