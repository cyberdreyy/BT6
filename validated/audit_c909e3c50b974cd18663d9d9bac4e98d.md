### Title
Unbounded recursion during MPT `TrieNode` traversal causes stack-exhaustion crash of the fault-proof program - (File: crates/proof/mpt/src/node.rs)

### Summary
`TrieNode`'s decode, `open`, `insert`, `delete`, and `list_walker`'s `fetch_leaves` are all recursive functions that walk a Merkle Patricia Trie whose nodes are fetched on demand from the preimage oracle by keccak256 hash. None of these recursive walks enforce a maximum depth. This is the same bug class as CVE-2016-4571 (`mxml_write_node` unbounded recursion on attacker-controlled tree structure causing stack-consumption DoS), but here the "document" is a chain of MPT nodes supplied through the fault-proof program's preimage oracle.

### Finding Description
`TrieNode::open` recurses through `Blinded -> unblind -> open` and `Extension -> node.open`, `TrieNode::insert`/`delete` recurse similarly, and `OrderedListWalker::fetch_leaves` recurses through `Branch`/`Extension` children, unblinding hashes as it goes: [1](#0-0) [2](#0-1) 

The only requirement enforced by the preimage layer is that returned bytes hash to the requested key — the oracle client/server and `CachingOracle` never validate structural depth, only length/hash correctness of individual reads: [3](#0-2) [4](#0-3) 

Because the preimage oracle only checks `keccak256(value) == key` per individual fetch, a dispute-game participant (the untrusted host side of the oracle, or a party supplying preimages during offline/hint-based execution) can construct an artificial hash-linked chain of `Extension`/`Blinded` nodes with **zero relationship to real Ethereum state** — each level is just `rlp([empty-or-short-path, blinded_hash_of_next_level])`, and each level's bytes are chosen so their hash equals the parent's declared child hash. This chain can be made arbitrarily long (thousands of levels), since the only cost to the attacker is computing keccak256 hashes, not producing a genuine state proof. `TrieDBProvider`/`TrieProvider` implementations (e.g. `crates/proof/executor/src/db/traits.rs`) feed exactly this kind of untrusted, hash-chained data into `TrieNode::open`, `unblind`, and `fetch_leaves`: [5](#0-4) 

When the fault-proof program (`base-proof-executor`/`base-proof-mpt`, used for computing/validating output roots in the dispute game) walks such a crafted trie to resolve an account or storage slot, each level triggers one more native-stack frame of recursion with no depth cap, eventually exhausting the thread stack and crashing the process — directly analogous to `mxml_write_node`'s crafted-XML stack-consumption DoS.

### Impact Explanation
A stack-overflow crash of the fault-proof program during dispute-game execution halts the honest party's ability to compute/verify the correct output root for that step, which can stall or invalidate an on-chain dispute resolution and, depending on which side is executing the vulnerable trie walk, tilt the outcome of the fault-proof game (wrong provable output root / node halt). This satisfies the required "concrete... node halt... or wrong provable output root" impact bar for the fault-proof program surface explicitly listed as in-scope.

### Likelihood Explanation
Constructing a deep hash-chain of fabricated `Extension`/`Blinded` nodes only requires computing keccak256 hashes locally and does not require breaking any cryptographic assumption or controlling real L1/L2 state — any party able to supply preimage data reachable by the fault-proof program's `TrieProvider` (e.g., a dispute-game participant feeding hints/preimages) can build the malicious chain offline and hand it to the on-demand node walker. The likelihood is bounded mainly by whatever length limits, if any, exist on individual preimage payloads or hint responses — no depth/length guard was found in `node.rs`, `list_walker.rs`, or the preimage oracle plumbing during this review.

### Recommendation
Add an explicit maximum recursion/traversal depth (bounded by the real max MPT depth, e.g. 64 nibbles for 32-byte keys) to `TrieNode::open`, `insert`, `delete`, `unblind`-following code, and `OrderedListWalker::fetch_leaves`, returning a `TrieNodeError` once the bound is exceeded instead of recursing further. Alternatively/additionally, convert these recursive walks to explicit iterative loops with a heap-allocated work stack so unbounded "depth" only consumes heap memory (bounded/limited) rather than native stack.

### Proof of Concept
Conceptual construction (not runnable without the fault-proof program harness, which this review did not have access to run):
1. Build `N` (e.g. 100,000) `TrieNode::Extension { prefix: empty, node: Box::new(Blinded{ next_hash }) }` levels, where level `i`'s RLP bytes hash (via `keccak256`) to `next_hash` referenced by level `i-1`, terminating in a `TrieNode::Leaf`.
2. Register each level's RLP bytes as a preimage in the oracle/host keyed by its own hash (satisfies the oracle's only check: `keccak256(value) == key`).
3. Have `TrieDBProvider::trie_node_by_hash` / `TrieNode::open` (as used by `crates/proof/executor/src/db/mod.rs::get_trie_account`) resolve a path through this chain.
4. Each `Extension`/`Blinded` level adds one recursive stack frame in `TrieNode::open`/`unblind`; with `N` large enough, the fault-proof program's thread stack overflows and the process crashes. [6](#0-5) [7](#0-6)

    /// Unblinds the [`TrieNode`] if it is a [`TrieNode::Blinded`] node.
    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.
                *self = Self::Empty;
            } else {
                *self = fetcher
                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }

    /// Walks down the trie to a leaf value with the given key, if it exists. Preimages for blinded
    /// nodes along the path are fetched using the `fetcher` function, and persisted in the inner
    /// [`TrieNode`] elements.
    ///
    /// ## Takes
    /// - `self` - The root trie node
    /// - `path` - The nibbles representation of the path to the leaf node
    /// - `fetcher` - The preimage fetcher for intermediate blinded nodes
    ///
    /// ## Returns
    /// - `Err(_)` - Could not retrieve the node with the given key from the trie.
    /// - `Ok(None)` - The node with the given key does not exist in the trie.
    /// - `Ok(Some(_))` - The value of the node
    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }

                Ok(vec![(prefix.to_vec().into(), value.clone())].into())

    /// Get the data corresponding to the currently set key from the host. Return the data in a new
    /// heap allocated `Vec<u8>`
    async fn get(&self, key: PreimageKey) -> PreimageOracleResult<Vec<u8>> {
        trace!(target: "oracle_client", key = %key, "Requesting data from preimage oracle");

        let length = self.write_key(key).await?;

        if length == 0 {
            return Ok(Default::default());
        }

        let mut data_buffer = alloc::vec![0; length];

        trace!(target: "oracle_client", key = %key, "Reading data from preimage oracle");

        // Grab a read lock on the preimage channel to read the data.
        self.channel.read_exact(&mut data_buffer).await?;

        trace!(target: "oracle_client", key = %key, "Successfully read data from preimage oracle");

        Ok(data_buffer)
    }

    pub fn get_trie_account(
        &mut self,
        address: &Address,
        block_number: u64,
    ) -> TrieDBResult<Option<TrieAccount>> {
        // Send a hint to the host to fetch the account proof.
        self.hinter
            .hint_account_proof(*address, block_number)
            .map_err(|e| TrieDBError::Provider(e.to_string()))?;

        // Fetch the account from the trie.
        let hashed_address_nibbles = Nibbles::unpack(keccak256(address.as_slice()));
        let Some(trie_account_rlp) = self.root_node.open(&hashed_address_nibbles, &self.fetcher)?
        else {
            return Ok(None);
        };

        // Decode the trie account from the RLP bytes.
        TrieAccount::decode(&mut trie_account_rlp.as_ref())
            .map_err(TrieNodeError::RLPError)
            .map_err(Into::into)
            .map(Some)
    }
