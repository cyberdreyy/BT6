## Finding

Confirmed: `staking_contract::set_beneficiary_for_operator` lacks the exact registration check that `vesting::set_beneficiary` deliberately added to prevent this class of bug, creating a DoS/permanent-lock analog to the `.transfer()`-gas-limit issue in the external report.

### Title
Unregistered/opted-out operator beneficiary permanently blocks `staking_contract::distribute_internal`, freezing staker withdrawals - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` pays every shareholder in a staking contract's `distribution_pool` (including the operator's commission, redirected to `beneficiary_for_operator`) via `aptos_account::deposit_coins`, in a single loop, within one atomic transaction. [1](#0-0) 
`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is not registered for the coin and has opted out of direct transfers (`can_receive_direct_coin_transfers` false). [2](#0-1) 

The `vesting` module explicitly guards against exactly this scenario: `set_beneficiary` calls `assert_account_is_registered_for_apt(new_beneficiary)` with a comment stating this is required "so `distribute()` wouldn't fail and block all other accounts from receiving APT if one beneficiary is not registered." [3](#0-2) 

`staking_contract::set_beneficiary_for_operator`, however, sets `new_beneficiary` with no such check at all. [4](#0-3) 

### Finding Description
Any operator can call `set_beneficiary_for_operator` to point their commission payouts at an address they control that has:
1. Not registered a `CoinStore<AptosCoin>`, and
2. Opted out of arbitrary direct coin transfers via `DirectTransferConfig` (`allow_arbitrary_coin_transfers = false`).

Once this "poisoned" beneficiary is set, every call path that forces `distribute_internal` — `distribute`, `request_commission`, `unlock_stake`, `switch_operator`, and `update_commission_percentage` — will attempt to pay the operator's commission share to that beneficiary via `aptos_account::deposit_coins`, which aborts. [5](#0-4) [6](#0-5) 

Because Move transactions are atomic, the abort reverts the entire call, including the `stake::withdraw_with_cap` that had already run within `distribute_internal`. [7](#0-6) 
This means the staker's own `unlock_stake`/withdrawal path — which unconditionally forces `distribute_internal` first — is permanently blocked as well, even though the staker never granted the operator control over their principal, only over commission.

### Impact Explanation
An operator (a role that only should control commission/voting, not the staker's principal) can permanently freeze the staker's ability to unlock or distribute any stake in that staking contract, by poisoning their own beneficiary address. This traps the staker's active/pending-inactive/inactive stake balances indefinitely, matching the "Permanent lock or non-recoverable loss of claim rights in stake ... beneficiary ... flows" and "wrong-role control ... without already holding that role" impact categories, since the operator escalates a commission-routing privilege into a DoS over the staker's own withdrawal rights.

### Likelihood Explanation
Low complexity and requires no special privilege beyond being the operator on a staking contract (a role every staker must grant to someone to run a validator). Setting up the poisoned beneficiary only needs: creating an unregistered account and calling `coin::disable_direct_transfer` (or the aptos_account equivalent to set `allow_arbitrary_coin_transfers = false`) on it, then calling `set_beneficiary_for_operator`, gated behind `features::operator_beneficiary_change_enabled()`.

### Recommendation
Add the same guard used in `vesting::set_beneficiary` to `staking_contract::set_beneficiary_for_operator`: require `aptos_account::assert_account_is_registered_for_apt(new_beneficiary)` (or equivalently ensure `can_receive_direct_coin_transfers`/registration) before accepting the new beneficiary, and/or make `distribute_internal` resilient to a single failing recipient (e.g., skip/queue failed payouts instead of aborting the whole distribution).

### Proof of Concept
1. Staker creates a staking contract with `operator` via `staking_contract::create_staking_contract`, with nonzero `commission_percentage`.
2. `operator` creates address `B`, ensures it's unregistered for `AptosCoin` and calls the direct-transfer opt-out so `can_receive_direct_coin_transfers(B) == false`.
3. `operator` calls `staking_contract::set_beneficiary_for_operator(operator, B)`.
4. Stake pool earns rewards (epoch advances).
5. Staker calls `staking_contract::unlock_stake(staker, operator, amount)` — this internally calls `distribute_internal`, which tries `aptos_account::deposit_coins(B, commission_coins)` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. Every subsequent call to `distribute`, `request_commission`, `unlock_stake`, `switch_operator`, `update_commission_percentage` on this staking contract aborts identically, leaving the staker unable to withdraw their stake until the operator's beneficiary becomes willing to register — a condition the staker cannot force.

Note: I could not execute this end-to-end in a test harness within this session (no filesystem/terminal access here); the trace above is derived directly from reading the cited source, and a Devin session with test execution would be needed to produce a runnable Move unit test confirming the abort in practice.

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };
