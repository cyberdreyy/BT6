### Title
Uncontrolled recursion in the fault-proof MPT trie walker over attacker-influenced L1/L2 receipt and transaction tries - (File: crates/proof/mpt/src/list_walker.rs / crates/proof/mpt/src/node.rs)

### Summary
`base-proof-mpt`'s trie traversal routines (`OrderedListWalker::fetch_leaves` and `TrieNode::open`/`insert`/`delete`/`unblind`) are implemented with unbounded native recursion, one stack frame per trie level/blinded-node hop, with no depth counter or iteration cap. These routines are driven directly by `OracleL1ChainProvider::receipts_by_hash` / `block_info_and_transactions_by_hash` [1](#0-0)  and by the analogous L2 chain provider, which build an `OrderedListWalker` over a receipts/transactions root taken from an L1/L2 header and hydrate it entirely from oracle-fetched preimages [2](#0-1) . This is conceptually the same bug class as CVE-2023-29001: a data structure walk recurses on attacker/environment-supplied structure without any bound on depth, risking a stack overflow that crashes the process performing the walk.

### Finding Description
`OrderedListWalker::fetch_leaves` recurses once per `Branch`/`Extension` hop and once more per `Blinded` node resolved via the preimage oracle, with no depth tracking: [3](#0-2) 

Likewise, `TrieNode::open`, `insert`, `delete`, and `unblind` in the sibling `node.rs` module are all directly recursive with no depth guard, resolving `Blinded` nodes via `fetcher.trie_node_by_hash` and recursing back into themselves: [4](#0-3) [5](#0-4) 

The recursion depth is entirely determined by the shape of the trie that the fetcher/oracle returns, which in turn is derived from the preimage data supplied to the fault-proof program's `CommsClient`/preimage oracle. Every `TrieNode::Blinded` variant is resolved through `TrieProvider::trie_node_by_hash`, i.e., an untrusted or adversarial (or simply malformed/faulty) preimage source, before recursing again — this is functionally the same class of defect as the Contiki-NG bug: recursion depth is a function of externally supplied routing/pointer structure, and there is no validation step that bounds how deep that structure may nest before invoking the recursive resolver again.

Nothing in `OracleL1ChainProvider`/`OracleL2ChainProvider` or in `OrderedListWalker`/`TrieNode` imposes a maximum trie depth, a maximum extension-chain length, or converts the recursive traversal to an iterative one with an explicit stack and depth cap.

### Impact Explanation
The fault-proof program (`crates/proof/proof`) is the component that produces the provable output root during a dispute game. If a party controlling the preimage data supplied to this program (directly reachable from a dispute-game participant submitting/serving preimages, or from a chain whose L1 receipts/transactions trie has been crafted with a deeply skewed shape — e.g., many chained single-child `Extension`/`Branch` nodes) can force `fetch_leaves`/`TrieNode::open` to recurse deeply enough, the recursion can exhaust the thread stack and crash the fault-proof program before it can compute an output root. This falls squarely within the accepted impact categories: node halt / inability to produce a provable output root for the dispute-game path. Because Rust does not guarantee tail-call optimization for these recursive match-based functions and no explicit recursion-depth limit exists, a sufficiently deep/attacker-shaped trie is a plausible vector for stack exhaustion, matching the acceptance criteria "wrong provable output root" / "node halt."

### Likelihood Explanation
The likelihood depends on how much freedom an adversary has over the concrete shape (not just the root hash) of the L1 receipts/transactions trie or over the preimage data the fault-proof program consumes. A well-formed Ethereum MPT over hashed keys has bounded depth (~64 nibbles), which would generally cap recursion; however, `OrderedListWalker`/`TrieNode` are generic and unbounded, do not enforce hashed-key balance invariants, and are also reused elsewhere (e.g., ordered lists with raw, non-hashed indices) where an adversary with control over the underlying data (e.g., a malicious/faulty preimage server in the dispute-game preimage-serving protocol, or a very large receipts list crafted to skew the RLP-index trie) could realistically increase recursion depth well beyond what a balanced trie would produce. I could not fully verify from the indexed code whether an upstream depth cap (e.g., enforced during dispute-game preimage validation) exists elsewhere in the pipeline to mitigate this before reaching `OrderedListWalker`; this uncertainty should be resolved by review of the preimage-oracle/proof crates outside what was retrieved.

### Recommendation
- Convert `OrderedListWalker::fetch_leaves` and `TrieNode::open`/`insert`/`delete`/`unblind` to iterative traversals using an explicit heap-allocated worklist/stack instead of native recursion, or add an explicit maximum-depth counter that errors out (returning `TrieNodeError`/`OrderedListWalkerError`) once a sane bound (e.g., 64–128 levels, matching the maximum possible hashed-key MPT depth) is exceeded.
- Apply the same bound uniformly across all trie-node recursive helpers (`open`, `insert`, `delete`, `collapse_if_possible`, `unblind`) in `crates/proof/mpt/src/node.rs`.
- Add fuzz/property tests that construct adversarial, deeply nested `Extension`/`Branch` chains via a custom `TrieProvider` and assert the traversal returns an error rather than overflowing the stack.

### Proof of Concept
Construct a custom `TrieProvider` whose `trie_node_by_hash` always resolves to a `TrieNode::Extension` pointing to another `TrieNode::Blinded { commitment: next_hash }`, chaining N such extensions before terminating in a `TrieNode::Leaf`. Feed the resulting root hash into `OrderedListWalker::try_new_hydrated` (as `OracleL1ChainProvider::receipts_by_hash` does with `header.receipts_root`) [6](#0-5) . Because each hop causes one recursive call into `fetch_leaves` [7](#0-6) , increasing N until it exceeds the available stack size demonstrates a crash (SIGSEGV/stack overflow) of the process performing the trie walk, analogous to the recursive-call exhaustion in the referenced Contiki-NG CVE.

        // Send a hint for the block's receipts, and walk through the receipts trie in the header to

            .into_iter()
            .map(|(_, rlp)| {

                Ok(envelope.as_receipt().expect("Infallible").clone())
            })
            .collect::<Result<Vec<_>, _>>()
            .map_err(OracleProviderError::Rlp)?;

        Ok(receipts)

    /// Hydrates the [`OrderedListWalker`]'s iterator with the leaves of the derivable list. If
    /// `Self::inner` is [Some], this function will fail fast.
    pub fn hydrate(&mut self, fetcher: &F) -> OrderedListWalkerResult<()> {
        // Do not allow for re-hydration if `inner` is `Some` and still contains elements.
        if self.inner.is_some() && self.inner.as_ref().map(|s| s.len()).unwrap_or_default() > 0 {
            return Err(OrderedListWalkerError::AlreadyHydrated);
        }

        // Get the preimage to the root node.
        let root_trie_node = Self::get_trie_node(self.root, fetcher)?;

        // With small lists the iterator seems to use 0x80 (RLP empty string, unlike the others)
        // as key for item 0, causing it to come last. We need to account for this, pulling the
        // first element into its proper position.
        let mut ordered_list = Self::fetch_leaves(&root_trie_node, fetcher)?;
        if !ordered_list.is_empty() {
            if ordered_list.len() <= EMPTY_STRING_CODE as usize {
                // If the list length is < 0x80, the final element is the first element.
                let first = ordered_list.pop_back().expect("Cannot be empty");
                ordered_list.push_front(first);
            } else {
                // If the list length is > 0x80, the element at index 0x80-1 is the first element.
                let first =
                    ordered_list.remove((EMPTY_STRING_CODE - 1) as usize).expect("Cannot be empty");
                ordered_list.push_front(first);
            }
        }

        self.inner = Some(ordered_list);
        Ok(())
    }

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }

    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }
