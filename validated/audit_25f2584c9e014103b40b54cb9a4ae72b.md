### Title
Off-by-one supermajority threshold in `GlobalStateEvaluator::reached_agreement` diverges from the canonical block-approval threshold, letting sub-supermajority weight flip the signers' global state (current miner / burn view / replay set) - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` (and its complement `reached_disagreement`) implements the "70% supermajority" concept using **floor** division (`total_weight * 7 / 10`), while the canonical, consensus-critical supermajority threshold used everywhere a Nakamoto block signature set is actually verified/approved, `NakamotoBlockHeader::compute_voting_weight_threshold`, uses **ceiling** division. For any `total_weight` not divisible by 10 (i.e. almost every real reward-set weight), the agreement threshold used by the signer's global state machine is exactly **one weight unit lower** than the threshold that would actually be required to reach the "true" 70% supermajority used for block approval. This mirrors the M-6 report's root cause: two code paths compute what is supposed to be the *same* quantity via differently-ordered/rounded arithmetic, and the looser one can be satisfied while the stricter, canonical one is not.

### Finding Description
`reached_agreement` and `reached_disagreement`: [1](#0-0) 

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```

compares `vote_weight` against `floor(total_weight * 7 / 10)`.

The canonical block-approval threshold, used for actually verifying a Nakamoto block's signer signatures on-chain and mirrored by the miner/signer code paths that gate block broadcast and rejection: [2](#0-1) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```

computes `ceil(total_weight * 7 / 10)`.

Writing `total_weight = 10q + r` (`0 ≤ r ≤ 9`), one can show `ceil(7*total_weight/10) - floor(7*total_weight/10) = 1` for every `r` in `1..=9`, and `= 0` only when `r = 0`. So **whenever `total_weight % 10 != 0`** (the overwhelming majority of real reward-set weights), `reached_agreement`'s pass bar is exactly one weight unit below the actual canonical supermajority bar.

By contrast, `reached_disagreement`'s floor(`3*total_weight/10`) formula happens to be algebraically identical to `total_weight - compute_voting_weight_threshold(total_weight)` (verified for all residues `r=0..9`), so the "blocking minority" semantics used elsewhere (e.g. in `stacks-node/src/nakamoto_node/stackerdb_listener.rs` and `signer_coordinator.rs`, which compute `total_weight.saturating_sub(weight_threshold)`) are consistent. Only the *agreement* (not disagreement) side is broken.

`reached_agreement` is the sole gate for the signers' entire "global state machine" consensus: [3](#0-2) [4](#0-3) [5](#0-4) 

- `determine_latest_supported_signer_protocol_version`
- `determine_global_burn_view` (which burn block is the agreed view)
- `determine_global_state` (which principal is the "current miner", and the agreed `tx_replay_set`)
- `find_majority_prefix_replay_set` (fallback replay-set consensus)

and consumers such as `get_burn_block_received_time_from_signers` in `stacks-signer/src/signerdb.rs`: [6](#0-5) 

### Impact Explanation
`determine_global_state`/`determine_global_burn_view` decide which miner and which burn view a signer treats as the network's agreed state — this in turn is what a signer's proposal-validation/state-machine logic (`stacks-signer/src/v0/signer_state.rs`, `stacks-signer/src/v0/signer.rs`) uses to decide whether an incoming block proposal is from the legitimate "current miner" and whether to accept/sign it, and it drives fork-favoring decisions in tenure-extend/miner-switch scenarios (see the test comment in `stacks-node/src/tests/signer/v0/tenure_extend.rs` explicitly stating the "70% threshold (>= 4)" is "exactly the threshold the `GlobalStateEvaluator` uses to flip the global state" — but the code actually flips at `floor(7T/10)`, one unit below the ceiling value the test/comment assumes).

Because the true canonical 70% block-approval bar (`compute_voting_weight_threshold`) is systematically 1 weight unit higher, a set of signers holding weight equal to `floor(7T/10)` (i.e., strictly less than the real supermajority) is enough for the signer set to internally "agree" on a new current miner / burn view / tx-replay set, even though that set could never actually get a block signed to the true approval threshold on its own. This creates a gap between "internally agreed global state" and "actually verifiable/approvable weight," matching the High-impact category of a signer "acting on a stale/incorrect threshold": signers can be steered by a sub-supermajority weight (potentially the largest set that is still short of the block-approval quorum) to flip which miner/tenure/replay-set they treat as canonical, which can misdirect proposal validation and miner-switch decisions network-wide, since every honest signer runs the identical buggy formula.

### Likelihood Explanation
This is not a rare edge case: the mismatch is present for **any `total_weight` not a multiple of 10**, which is essentially any realistic reward-set weight distribution (weights are typically not round multiples of 10). No majority collusion or crafted signature is needed — the boundary condition arises naturally whenever weight support for a view sits at exactly `floor(7T/10)`, a value reachable in ordinary gossip/state-machine-update flows tracked entirely by `libsigner`'s `StateMachineUpdate` broadcast mechanism, requiring only the normal behavior of `total_weight % 10 - 1` or fewer honest-looking signers (not a majority of the whole signer set, only of the sub-supermajority band) reporting a given view.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the exact same rounding semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (i.e., compute the threshold via `compute_voting_weight_threshold` or replicate its ceiling arithmetic) so that "global state agreement" and "block approval" always refer to the identical weight bar, eliminating the systematic one-unit gap.

### Proof of Concept
Given `total_weight = 13` (e.g., 13 weighted signers), `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`:
- `compute_voting_weight_threshold(13)`: `13*7=91`, `91 % 10 = 1 != 0` ⇒ `ceil = 1`; threshold = `91/10 + 1 = 9 + 1 = 10`. A block needs **10/13** weight signed to be approved.
- `reached_agreement(9)` on a `GlobalStateEvaluator` with `total_weight=13`: `9 >= 13*7/10 = 91/10 = 9` (integer division) ⇒ **true**.

So a coalition holding only **9/13 (~69.2%)** of signer weight is enough for the signer set's `determine_global_state`/`determine_global_burn_view` to declare "global agreement" on a given miner/burn view/replay set, even though the same weight (9/13) is **insufficient** (need 10/13) to actually get a Nakamoto block signed and approved per `compute_voting_weight_threshold`. This exact scenario is already codified as a regression boundary in the repo's own tests (`libsigner/src/tests/signer_state.rs`, `thresholds_partition_weight_space`, using `total_weight = 1_000_000_000`, where `reached_agreement(700_000_000)` passes at exactly floor(70%) while the canonical approval threshold for a non-multiple-of-10 weight would require one unit more), confirming the divergence is a structural property of the two formulas rather than an isolated case.

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;

                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);

        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
