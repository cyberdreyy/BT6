### Title
Zero-address `new_authority` in `transfer_to_new_account`/`transfer_to_new_account_pda` permanently freezes migrated account funds - (File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs)

### Summary
Both account-migration instructions accept `new_authority` as a completely unchecked, non-signing account with no validation that it is a valid, non-default `Pubkey`. This mirrors the reported Gearbox `onBehalfOf` bug class: a critical "owner" field is never checked against the zero address before being persisted as the controlling authority of a financial account.

### Finding Description
`transfer_to_new_account` and `transfer_to_new_account_pda` both take `new_authority` as an `UncheckedAccount`, explicitly annotated by the developers as unchecked: [1](#0-0) [2](#0-1) 

This key is passed straight into `initialize_migrated_account`, which sets it as the `authority` field of the brand-new `MarginfiAccount` that inherits the old account's entire `lending_account` (all deposit/borrow positions): [3](#0-2) [4](#0-3) 

Simultaneously, the old account is irreversibly disabled and its balances zeroed out, with `migrated_to` set and `ACCOUNT_DISABLED` flag applied, and the code explicitly prevents re-migration: [5](#0-4) [6](#0-5) 

Nowhere in either instruction handler or in the `#[derive(Accounts)]` constraints is `new_authority` checked to be non-default (`Pubkey::default()`, i.e. the all-zero address). Since `Pubkey::default()` has no corresponding private key, an account created with this authority can never again be operated on by any signer-gated instruction (deposit, withdraw, borrow, repay, close, etc., all of which require `authority: Signer<'info>` matching `marginfi_account.authority`).

### Impact Explanation
If `new_authority` is set to the zero address (accidentally or via a compromised/malicious front-end, or a buggy CPI integrator that fails to populate this account), the entire position (all deposits and liabilities) migrated from the old account becomes permanently locked in the new account: no key can ever sign as its authority, so it cannot be used to withdraw collateral, repay debts, or be closed via the normal signer-gated instruction path. This is a durable freeze with direct financial effect (loss of all migrated collateral, and any liabilities left unrepaid). This impact is comparable to, or worse than, the original Gearbox report because unlike a benign no-op position (`onBehalfOf == msg.sender` fallback risk), marginfi's migration flow explicitly *destroys* the source account (`ACCOUNT_DISABLED`, zeroed balances, `migrated_to` locked) before the destination's usability is verified.

### Likelihood Explanation
The instruction is reachable by any authorized account owner (or CPI integrator building the transfer instruction) without special privileges — `new_authority` is a fully attacker/caller-controlled parameter with zero validation. This can occur through UI/integration bugs (e.g., an uninitialized or default `Pubkey` being passed) as easily as intentional misuse, and there is no on-chain guard preventing it, making the bug trivially triggerable given only the standard signer requirements already present in the instruction (`authority` and `fee_payer`).

### Recommendation
Add an explicit constraint in both `TransferToNewAccount` and `TransferToNewAccountPda` account structs (or at the top of `transfer_to_new_account`/`transfer_to_new_account_pda`) requiring `new_authority.key() != Pubkey::default()`, returning a dedicated error (e.g. `MarginfiError::InvalidAuthority`) if violated, mirroring the recommended fix in the referenced report.

### Proof of Concept
1. Account owner (or an integrator building the CPI/transaction on the owner's behalf) calls `transfer_to_new_account_pda` with `new_authority = Pubkey::default()`.
2. The instruction succeeds: `old_marginfi_account` is disabled, its `lending_account` zeroed, and `migrated_to` set to the newly created PDA per [7](#0-6) .
3. The new account, PDA-derived using `new_authority.key().as_ref()` per [8](#0-7) , now holds the full lending position but has `authority = Pubkey::default()`.
4. No subsequent instruction (deposit/withdraw/repay/close) can succeed against this account because every such instruction requires a `Signer` matching `marginfi_account.authority`, which is unattainable for the zero address — the funds are permanently frozen.

fn initialize_migrated_account(

    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,

    new_account.account_flags = old_account.account_flags;

    new_account.indexer_flags = old_account.indexer_flags;

}
