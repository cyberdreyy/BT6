### Title
Cross-user callback hijack via duplicate MessageId overwrite in savedCallbacks map - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`(*handler).HandleLegacyUserMessage` stores each pending request's response callback in `savedCallbacks` keyed only by the client-supplied `Body.MessageId`, with no uniqueness check or binding to `Body.Sender`. An unauthenticated client can submit a second `web_api_trigger` request with the same `MessageId` (different signer/payload) to silently overwrite the first requester's callback, so the first requester never gets a response and the second requester instead receives whatever DON node response arrives for that `MessageId`.

### Finding Description
The gateway's `ProcessRequest` routes any legacy HTTP request with a valid signature format to `h.HandleLegacyUserMessage` (see `core/services/gateway/gateway.go`), which after basic payload/timestamp/method validation unconditionally does:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
```
at `core/services/gateway/handlers/capabilities/handler.go:411-414`. There is no check for an existing entry, and the map key is `msg.Body.MessageId` alone — not `(Sender, MessageId)`. `MessageId` is entirely attacker-supplied (part of the signed `MessageBody`, validated only for length/format in `api.Message.Validate()`), so two different signers can choose the identical `MessageId`. When node responses arrive, `handleWebAPITriggerMessage` looks the callback up strictly by `msg.Body.MessageId` and routes the first node response received to whichever callback currently occupies that slot, then deletes the entry. Since request 1's callback is asynchronously overwritten by request 2's callback before any node responds, requester 1's callback is lost (never invoked, eventually times out via the gateway's `callback.Wait(ctx)` deadline) and requester 2 receives the DON's response to whichever payload the DON actually processed (which could be request 1's response payload, since the DON was already sent request 1's original signed request and may still deliver it). No existing check (auth middleware, signature verification, or handler logic) prevents two independently signed requests from sharing the same `MessageId`; signature verification only proves who sent each individual message, it does not enforce ID uniqueness across senders.

### Impact Explanation
This breaks per-request isolation of an unauthenticated public API: one caller can suppress another caller's response (denial of service) and, depending on timing, receive response data intended for the other caller's request/payload. This matches Chainlink's bounty impact class for cross-user response confusion / unauthorized access to another user's request/response data via a public-facing gateway endpoint.

### Likelihood Explanation
The precondition is trivial: any unauthenticated network client that can reach the gateway's HTTP endpoint and knows a valid `DonId` for a configured DON can perform this. No special key, allowlist membership, or elevated role is required to send a signed legacy message — signatures only need to be valid over the attacker's own arbitrary key pair, not over any privileged identity. The race is easy to win by choosing the same `MessageId` string and firing both requests in quick succession before the first DON response returns (order of magnitude: DON round trip time, commonly hundreds of ms or more), making this reliably reproducible.

### Recommendation
Key `savedCallbacks` by a value that is guaranteed collision-free and bound to the requester, e.g. a server-generated UUID or `(Sender, MessageId)` composite key, or reject/return an error when `HandleLegacyUserMessage` is called with a `MessageId` that already has a live entry in `savedCallbacks` for a different sender.

### Proof of Concept
Handler-level Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build two `triggerRequest` messages with the same `MessageId` (e.g. `"dup-id"`) but signed by two different private keys (`nodes[0].PrivateKey` vs. a second unrelated key) and different payloads.
2. Call `handler.HandleLegacyUserMessage(ctx, msg1, cb1)` then immediately `handler.HandleLegacyUserMessage(ctx, msg2, cb2)`.
3. Assert `handler.savedCallbacks["dup-id"].Callback` now refers to `cb2`, i.e. `cb1`'s entry was silently discarded.
4. Simulate one DON node response for `"dup-id"` via `handler.HandleNodeMessage`/`handleWebAPITriggerMessage`, and assert `cb2.Wait(ctx)` receives the response while `cb1.Wait(ctx)` times out/never resolves — demonstrating cross-sender callback hijack.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
