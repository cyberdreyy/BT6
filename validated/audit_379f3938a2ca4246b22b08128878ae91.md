### Title
JWT replay-guard is marked "used" before the workflow trigger request is actually delivered, permanently burning valid requests on downstream failure - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`httpTriggerHandler.HandleUserTriggerRequest` records a signed JWT's `jti` as "used" inside `authorizeRequest` — a step that runs *before* rate limiting, callback setup, and the actual fan-out of the trigger request to DON nodes. If any of those later steps fail, the workflow owner's signed request is discarded, but the JWT has already been permanently consumed for the replay-cache window, leaving the legitimate request unrecoverable without minting an entirely new JWT.

### Finding Description
`HandleUserTriggerRequest` executes the following ordered pipeline: [1](#0-0) 

1. `validatedTriggerRequest` / `resolveWorkflowID`
2. `authorizeRequest` → `workflowMetadataHandler.Authorize`
3. `checkRateLimit`
4. `setupCallback`
5. `sendWithRetries` (actual delivery to DON nodes)

Inside `Authorize`, once the JWT signature and authorized-signer checks pass, the `jti` claim is immediately committed to the replay cache via `h.jwtCache.recordUsage(claims.ID)`, *before* the request has been rate-limited, queued, or sent to any node: [2](#0-1) 

If the subsequent `checkRateLimit` call fails (e.g., per-workflow rate limit exceeded), the function returns an error and the trigger is never queued or sent to any node: [3](#0-2) 

Likewise, `setupCallback` can fail if the workflow isn't assigned to any shard yet, and `sendWithRetries`/`sendToShard` can time out without reaching any node if the overall `MaxTriggerRequestDurationMs` elapses: [4](#0-3) [5](#0-4) 

In every one of these failure paths, the JWT's `jti` was already recorded as used in step 2, so the workflow owner cannot resubmit the identical signed request — the gateway will reject it with "JWT token has already been used" for the duration of the replay cache window, even though the corresponding trigger was never actually delivered to any DON node. This is structurally identical to the reported bug class: a piece of persistent state (`pendingWithdrawalsRequests[hash]` / `jti` usage) is durably committed as a marker of "request accepted" before the action it gates (`withdrawQueue.push` / node delivery) is guaranteed to occur, so failures between the marker-write and the actual action leave the caller's legitimate, correctly-signed request permanently stranded.

### Impact Explanation
This is a self-inflicted denial-of-service on legitimate, unprivileged workflow owners rather than a privilege-escalation bug: a workflow owner whose otherwise-valid, correctly-signed trigger request is rate-limited, hits a shard-assignment race, or times out during node delivery loses that request entirely and must mint a brand-new JWT (a new `jti`) to retry, since the original token is now unusable for the configured `JWTReplayPeriodMs` window. Under load or during shard reassignment this can cause a burst of workflow executions to be silently dropped without the user having any way to safely retry the same signed intent.

### Likelihood Explanation
This will reliably reproduce whenever `checkRateLimit`, `setupCallback`, or `sendWithRetries` fails after `authorizeRequest` succeeds — which is an expected, non-adversarial occurrence under normal rate-limiting or transient node connectivity issues, not a contrived edge case.

### Recommendation
Move the JWT replay-cache commit (`recordUsage`) to occur only after the request has been durably queued (i.e., after `setupCallback` succeeds and the request has been successfully handed off to `sendWithRetries`), or make the "used" marker reversible/rolled back on any downstream failure prior to `sendToShard` succeeding, so that a client whose request never reached the DON is not permanently penalized for a `jti` it can no longer reuse.

### Proof of Concept
1. Register a workflow and generate a signed JWT for a `workflows.execute` HTTP-trigger request, as in `registerWorkflow` / `createTestJWTToken` in `http_trigger_handler_test.go`.
2. Ensure the per-workflow rate limiter (`h.userRateLimiter`) is already saturated for that workflow/owner scope so `checkRateLimit` returns `limits.ErrorRateLimited`.
3. Call `HandleUserTriggerRequest` with the valid JWT — `authorizeRequest` succeeds and calls `Authorize`, which invokes `jwtCache.recordUsage(claims.ID)` at workflow_metadata_handler.go:105; `checkRateLimit` then fails and the function returns an error without ever calling `setupCallback` or `sendWithRetries`.
4. Retry the identical request with the same JWT — `Authorize` now returns `"JWT token has already been used..."` (workflow_metadata_handler.go:87-90), even though the original request was never sent to any DON node, confirming the request is unrecoverably lost until the owner issues a new signed JWT. func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}

func (h *httpTriggerHandler) sendWithRetries(ctx context.Context, legacyExecutionID, executionIDWithTriggerIndex string, req *jsonrpc.Request[json.RawMessage], workflowID string, doneCh <-chan struct{}) error {
	if doneCh == nil {
		return errors.New("doneCh cannot be nil")
	}

	assigned := h.workflowMetadataHandler.WorkflowShards(workflowID)
	if len(assigned) == 0 {
		// this shouldn't happen because we checked it in authorizeRequest()
		h.callbacksMu.Lock()
		saved, exists := h.callbacks[req.ID]
		if exists {
			h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, fmt.Sprintf("Workflow %s is not assigned to any DONs", workflowID), saved.Callback)
			h.cleanupCallback(req.ID)
		}
		h.callbacksMu.Unlock()
		return fmt.Errorf("workflow %s not assigned to any shard", workflowID)
	}

	// Create a context that will be cancelled when the max request duration is reached
	maxDuration := time.Duration(h.config.MaxTriggerRequestDurationMs) * time.Millisecond
	ctxWithTimeout, cancel := context.WithTimeout(ctx, maxDuration)
	defer cancel()

	// Run one send loop per assigned shard in parallel.
	errCh := make(chan error, len(assigned))
	for _, shard := range assigned {
		h.wg.Go(func() {
			errCh <- h.sendToShard(ctxWithTimeout, shard, legacyExecutionID, executionIDWithTriggerIndex, req, doneCh)
		})
	}

	var combinedErr error
	for range assigned {
		if err := <-errCh; err != nil {
			combinedErr = errors.Join(combinedErr, err)
		}
	}
	return combinedErr

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
