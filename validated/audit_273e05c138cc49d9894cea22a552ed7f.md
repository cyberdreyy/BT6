### Title
Unchecked ERC20 `transfer()` return value permanently burns claimees' airdrop allocations - (File: contracts/MerkleClaim.sol)

### Summary
`MerkleClaim.claim()` and `MerkleClaim.sweep()` call `IERC20Upgradeable(token).transfer(...)` directly and ignore the boolean return value. For ERC20 tokens that signal failure by returning `false` instead of reverting, `claim()` marks `hasClaimed[to] = true` before the failed transfer, permanently destroying the claimee's allocation while the tokens remain in the contract.

### Finding Description
In `contracts/MerkleClaim.sol`, the `claim` function sets the claimed flag at line 63 and then performs an unchecked raw transfer at line 66:

```solidity
// Set address to claimed
hasClaimed[to] = true;

// Transfer tokens to claimee
IERC20Upgradeable(token).transfer(to, amount);
``` [1](#0-0) 

If the distributed `token` (set arbitrarily at `initialize`, line 40) returns `false` on failure rather than reverting — the exact non-compliant EIP-20 behavior described in the external report — the call succeeds, `hasClaimed[to]` is already `true`, and the claimee can never retry (`AlreadyClaimed()` revert at line 54). The same unchecked pattern exists in `sweep` (line 74), though `sweep` is gated to `TL_MULTISIG`. The token is a free parameter chosen at initialization, so nothing constrains the distribution to strictly compliant tokens; elsewhere in the codebase (e.g. `IdleCreditVault.sol`, `IdleCDOEpochQueue.sol`, `IdleCreditVaultWriteOffEscrow.sol`) `SafeERC20.safeTransfer` is used consistently, making this an outlier.

### Impact Explanation
Permanent freezing/destruction of unclaimed tokens: an eligible claimee's entire `amount` allocation is lost with no recovery path — the contract still holds the tokens, the claimee is recorded as claimed, and only the multisig `sweep` (after 60 days) can recover them, which is not guaranteed. Loss is quantified as the claimee's full merkle allocation, and applies to every claimee of the misbehaving token.

### Likelihood Explanation
Medium. Requires the configured `token` to be a non-reverting, `false`-returning ERC20 (or to fail transfers for some recipients, e.g. fee-on-transfer or blocklist tokens that return false). Since `initialize` accepts any token address and the contract is explicitly designed to distribute arbitrary ERC20s, the condition is plausible. No attacker action is required — the claimee's own legitimate claim triggers the loss.

### Recommendation
Use `SafeERC20Upgradeable.safeTransfer` (or check the return value with `require`) in both `claim` (line 66) and `sweep` (line 74), consistent with the rest of the codebase.

### Proof of Concept
```solidity
// SPDX-License-Identifier: AGPL-3.0-only
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {MerkleClaim} from "../contracts/MerkleClaim.sol";

contract FalseReturningToken {
    mapping(address => uint256) public balanceOf;
    constructor() { balanceOf[msg.sender] = 1_000_000e18; }
    function transfer(address, uint256) external pure returns (bool) {
        return false; // non-compliant: fails silently instead of reverting
    }
    // funds moved into MerkleClaim via direct mint-style helper for test
    function seed(address to, uint256 amt) external { balanceOf[to] = amt; }
}

contract MerkleClaimUncheckedTransferTest is Test {
    MerkleClaim claim;
    FalseReturningToken token;
    address claimee = address(0xA11CE);
    uint256 amount = 100e18;

    function setUp() public {
        token = new FalseReturningToken();
        claim = new MerkleClaim();
        // leaf = keccak256(bytes.concat(keccak256(abi.encode(to, amount))))
        bytes32 leaf = keccak256(bytes.concat(keccak256(abi.encode(claimee, amount))));
        claim.initialize(leaf, address(token));
        token.seed(address(claim), amount); // contract holds the allocation
    }

    function testClaimBurnsAllocation() public {
        bytes32[] memory proof = new bytes32[](0); // leaf is the root, empty proof
        claim.claim(claimee, amount, proof);

        // claimee received nothing, but is marked as claimed
        assertEq(token.balanceOf(claimee), 0);
        assertTrue(claim.hasClaimed(claimee));
        // tokens are still stuck in the contract
        assertEq(token.balanceOf(address(claim)), amount);
        // retry is impossible
        vm.expectRevert(MerkleClaim.AlreadyClaimed.selector);
        claim.claim(claimee, amount, proof);
    }
}
```
