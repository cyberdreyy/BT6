### Title
Zip extraction ignores target directory and allows zip-slip path traversal via absolute/`..` entry names - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` writes every zip entry using `file.Name` verbatim, with no confinement check against a target directory, no rejection of absolute paths, and no rejection of `../` traversal segments. The `ziplegacy.extractor.Extract` wrapper (which is what `cache-extractor` and `artifacts-downloader` invoke for zip archives) accepts a `dir` parameter but discards it entirely, calling `archives.ExtractZipArchive(zr)` with no directory join or containment check at all — unlike the sibling `tarzstd` extractor, which explicitly resolves each entry with `filepath.Join(e.dir, hdr.Name)` and rejects any path that escapes `e.dir` (`strings.HasPrefix(path, e.dir+string(filepath.Separator))` check).

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` and calls `extractZipFile(file)` for every entry, which does: [1](#0-0) 
`extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), ...)` and then, depending on entry type, `os.Mkdir(file.Name, ...)`, `os.Symlink(data, file.Name)`, or `os.OpenFile(file.Name, ...)` — all using the raw zip entry name with no `filepath.Clean`, no rejection of absolute paths, and no verification that the resolved path stays under any target root: [2](#0-1) 

The only path-name check present is `errorIfGitDirectory`, which only detects `.git` paths for a warning, not a security boundary: [3](#0-2) 

Critically, the caller `ziplegacy.extractor.Extract` receives a `dir` field at construction time but never uses it — it just opens the zip reader and calls `archives.ExtractZipArchive(zr)` directly: [4](#0-3) 

This is in stark contrast to the tar+zstd extractor in the same package family, which explicitly builds `path = filepath.Join(e.dir, hdr.Name)` and rejects entries that escape `e.dir`: [5](#0-4) 

Both `cache-extractor` and `artifacts-downloader` obtain `wd` via `os.Getwd()` and pass it as the `dir` argument to `archive.NewExtractor`, believing it constrains extraction to `wd`: [6](#0-5) [7](#0-6) 
For the zip format, that `dir` is silently dropped by `ziplegacy.extractor.Extract`, so the containment guarantee the callers assume simply does not exist for zip archives — only relying on whatever the process's current working directory happens to be, with no path validation at all.

Attacker path: a pipeline author controls the files/paths that get archived into `cache.zip` or `artifact.zip` for their job (cache paths, artifact paths, and file names inside the job's build directory are all attacker-controlled). By crafting a `zip.File` entry with `Name` set to an absolute path (e.g. `/root/.bashrc`) or a relative-with-traversal path (e.g. `../../../etc/foo`) — which the Go `archive/zip` writer/reader permits, since it does not enforce any naming convention — the corresponding `cache-extractor`/`artifacts-downloader` helper invocation, or the runner's own cache/artifact restore step in a later job/stage, will write attacker bytes to that resolved path when the archive is later extracted. Symlink entries (`extractZipSymlinkEntry`) compound this: a symlink can be planted pointing outside the intended tree, and a subsequent "regular file" entry sharing that name can then write through the symlink to an arbitrary target.

### Impact Explanation
Because the extraction path is fully attacker-controlled and unconfined, an attacker can overwrite or create files outside the intended cache/artifact/build root that helper binaries, shell wrapper scripts, or env files consume as trusted input later in the job or a subsequent job on the same runner/host (e.g. overwriting env files sourced by the shell, temp scripts executed by the runner, or files under the runner's working tree read by later stages). This matches the "secret exposure or stronger-context execution" impact class: attacker-controlled content can land in a location trusted by a later, more-privileged step, and be treated as legitimate configuration/data.

### Likelihood Explanation
Preconditions are low: any unprivileged pipeline author who can define `cache:` or `artifacts:` paths for their own job can construct a malicious zip archive with crafted entry names (this can be done with any zip-manipulation tool, bypassing the Runner's own archiver since the attacker only needs to control the bytes that are downloaded and passed into `ExtractZipArchive` — e.g. by hand-crafting a cache/artifact blob, or via any legacy zip cache/artifact path). It is fully repeatable and deterministic — a crafted zip with an absolute or `..`-containing entry will always be extracted verbatim by the current code, with no rejecting validation anywhere in the path.

### Recommendation
Thread a target root directory through `ExtractZipArchive`/`extractZipFile` (mirroring the `tarzstd` extractor), resolve every entry as `filepath.Join(root, file.Name)`, reject entries whose cleaned resolved path is not `root` or does not have `root+separator` as a prefix, and reject/neutralize absolute paths and symlink targets that point outside `root`. Fix `ziplegacy.extractor.Extract` to actually pass and enforce `e.dir` instead of discarding it.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Build a `zip.Writer` with one entry named `"../evil.txt"` (or `"/tmp/evil-abs.txt"` on Unix) with attacker content.
2. Call `ExtractZipArchive` (or `ExtractZipFile`) from within a temp "sandbox" working directory.
3. Assert `err != nil` (extraction should be rejected) OR assert that no file was created outside the sandbox directory (e.g. `os.Stat(filepath.Join(sandbox, "..", "evil.txt"))` returns `os.IsNotExist`).
Currently this test would fail: the file is created one directory above the sandbox, proving the traversal.

Additionally, an integration-level PoC: exercise `ziplegacy.NewExtractor(r, size, dir)` with a crafted zip containing a `..`-escaping entry, call `Extract(ctx)`, and assert the escaped file was **not** written under `dir`'s parent — again currently fails because `dir` is ignored entirely.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func (e *extractor) Extract(ctx context.Context) error {
	zr, err := zip.NewReader(e.r, e.size)
	if err != nil {
		return err
	}

func (c *ArtifactsDownloaderCommand) Execute(cliContext *cli.Context) {
	log.SetRunnerFormatter()

	wd, err := os.Getwd()
	if err != nil {
		logrus.Fatalln("Unable to get working directory")
	}

	if c.URL == "" {
		logrus.Warningln("Missing URL (--url)")
	}
	if c.Token == "" {
		logrus.Warningln("Missing runner credentials (--token)")
	}
	if c.ID <= 0 {
		logrus.Warningln("Missing build ID (--id)")
	}
	if c.ID <= 0 || c.Token == "" || c.URL == "" {
		logrus.Fatalln("Incomplete arguments")
	}

	// Create temporary file
	file, err := os.CreateTemp(c.StagingDir, "artifacts")
	if err != nil {
		logrus.Fatalln(err)
	}
	_ = file.Close()
	defer func() { _ = os.Remove(file.Name()) }()

	// Download artifacts file
	err = c.doRetry(func(retry int) error {
		return c.download(file.Name(), retry)
	})
	if err != nil {
		logrus.Fatalln(err)
	}

	f, size, format, err := openArchive(file.Name())
	if err != nil {
		logrus.Fatalln(err)
	}
	defer f.Close()

	extractor, err := archive.NewExtractor(format, f, size, wd)
	if err != nil {
		logrus.Fatalln(err)
	}

	// Extract artifacts file
	err = extractor.Extract(context.Background())
	if err != nil {
		logrus.Fatalln(err)
	}
