### Title
Global signer state machine uses floor-rounded 70% agreement threshold while block-signature consensus uses ceiling-rounded threshold, letting the group's `current_miner`/burn-view/protocol-version consensus be finalized below the real supermajority - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority threshold with integer floor division (`total_weight * 7 / 10`, compared with `>=`), while the block-signature approval threshold used everywhere else in the protocol - `NakamotoBlockHeader::compute_voting_weight_threshold` - computes the same nominal 70% with ceiling rounding. These two thresholds are supposed to represent the *same* supermajority requirement but disagree for any `total_weight` where `total_weight * 7` is not a multiple of 10, letting the global state machine "lock in" `current_miner` / burn-view / protocol version / tx-replay-set agreement with strictly less real weight than the block-approval threshold that later validates the resulting block.

### Finding Description
`compute_voting_weight_threshold` (the threshold actually enforced by node/chainstate block-signature verification and by the signer's own block accept/reject bookkeping) rounds *up*: [1](#0-0) 

This is used consistently for the real 70%-signature acceptance threshold, both in chainstate signature verification and in the signer's `store_and_process_block_signature` / `store_and_process_block_rejection` / `handle_block_pre_commit`: [2](#0-1) [3](#0-2) 

In contrast, `GlobalStateEvaluator::reached_agreement`, which decides whether the signer set has reached consensus on the *global state machine view* (current miner, burn-block view, active protocol version, and transaction-replay set), rounds *down*: [4](#0-3) 

For `total_weight = 11` (a realistic reward-cycle weight distribution): the ceiling threshold `compute_voting_weight_threshold(11)` requires `⌈77/10⌉ = 8`, but `reached_agreement` accepts once `vote_weight >= ⌊77/10⌋ = 7`. Any `total_weight` where `total_weight*7 % 10 != 0` produces this same off-by-one gap (this covers the majority of possible weight totals; only multiples of 10 avoid it). This is exactly the ERC4626-style rounding-direction defect from the report: the same nominal "70%" is computed with two different rounding conventions in two code paths that are meant to be equivalent gates, and the looser one is used to finalize state.

`reached_agreement` drives:
- `determine_latest_supported_signer_protocol_version` (which protocol version the group is "on")
- `determine_global_burn_view` (which burn block the group agrees is the tip)
- `determine_global_state` (the group's agreed `current_miner`/`MinerState::ActiveMiner`, including `parent_tenure_last_block`)
- `find_majority_prefix_replay_set` / `get_global_tx_replay_set` (which transactions are considered replay-locked) [5](#0-4) 

Because the group-level agreement gate is looser than the real signature-approval gate, a `current_miner`/burn-view/replay-set "consensus" can be recorded by the evaluator with a coalition that would *not* qualify to actually get a Nakamoto block signed by the same signer set under `compute_voting_weight_threshold`. Signers use this global state to decide who the active miner is and to validate proposals against that miner's tenure (`chainstate/v1.rs::validate_tenure_change_payload`, `chainstate/v2.rs::validate_tenure_change_payload`), so a miner that lacks the real >=70% supermajority can nonetheless be treated as "the" agreed active miner, and replay-set membership can be finalized with the same too-small coalition.

`reached_disagreement` has the mirror-image problem on the blocking-minority (>30%) side: [6](#0-5) 

using `10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` (i.e. 3) with floor division and strict `>`, which is not necessarily the exact complement of the ceiling-based `compute_voting_weight_threshold` used for real block rejection accounting (`total_weight - min_weight`, as computed in `store_and_process_block_rejection`/`signer_coordinator.rs`). The comment/regression tests in `libsigner/src/tests/signer_state.rs` even document u32-overflow fixes for this exact multiplier arithmetic, confirming this threshold math is a known-fragile area, but they only test for overflow, not for consistency with `compute_voting_weight_threshold`. [7](#0-6) 

### Impact Explanation
This breaks the "approved coalition vs. real threshold" equality that the whole signer-consensus design assumes: the group state machine (which miner is "active", which burn view is canonical, which protocol version is active, and which transactions are replay-locked) can be finalized by `reached_agreement` with less than the true 70% weight required by `compute_voting_weight_threshold` to actually get a block signed. Since signers rely on this global state to decide which miner's blocks to validate/sign against (via `MinerState::ActiveMiner` and the tenure-parent checks in `chainstate/v1.rs`/`v2.rs`), a minority coalition just below the real threshold (but at/above the floor threshold) can force the rest of the honest set's local view of "current miner" or "burn view" to converge on a value that a genuine 70% supermajority never actually endorsed. This is the "acting on a stale/incorrectly-computed reward set/threshold" class of High-severity impact: it does not itself forge a block signature, but it lets an attacker with sub-threshold weight tilt which miner/tenure/replay-set the signer set treats as agreed, which downstream feeds into block validation and signing decisions.

### Likelihood Explanation
No majority is required to trigger the discrepancy - the gap exists purely from arithmetic (any `total_weight` not a multiple of 10, e.g. 11, 13, 17, 101, 3000/... any oddly-partitioned reward-cycle weight sum). All that is needed is a coalition sized exactly at the floor threshold (e.g. weight 7 out of 11) sending honest-looking `StateMachineUpdate` gossip messages that a single "one-slot miner" class of actor can already produce; no other signer's key or majority collusion is required to *create* the discrepancy, only ordinary weight distribution in the reward set. This makes the condition likely to occur in practice whenever reward-cycle weights aren't neatly divisible by 10.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` use the exact same ceiling-based formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (ideally by calling that function directly, or duplicating its `ceil` logic), so that "global agreement" can never be declared with less weight than what the chain's own block-signature verification would require, and so `reached_disagreement`'s blocking-minority is the exact complement (`total_weight - compute_voting_weight_threshold(total_weight) + 1`, or equivalent) of that same threshold.

### Proof of Concept
1. Configure a reward set with `total_weight = 11` (e.g., 11 signers of weight 1, or any weighted distribution summing to 11).
2. Node/chainstate-side approval threshold: `NakamotoBlockHeader::compute_voting_weight_threshold(11)` = `⌈77/10⌉ = 8`.
3. `GlobalStateEvaluator::reached_agreement(7)`: `7 >= 77/10 (=7, floor)` → `true`.
4. A coalition holding exactly weight 7 (well below the real 8-weight/70%+ needed to sign a block) can push a `StateMachineUpdate` (e.g. a `MinerState::ActiveMiner` claim, or burn-view claim) that causes `determine_global_state`/`determine_global_burn_view` to record group-wide "agreement" on that view.
5. This agreed view is exposed via `determine_global_state()` and used elsewhere in the signer to decide validation/signing behavior against the "current miner," despite never having reached the actual 70% (8/11) threshold that would be required for a block from that miner to be legitimately signed by the same set.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Determine what the global burn view is if there is one
    pub fn determine_global_burn_view(&self) -> Option<(&ConsensusHash, u64)> {
        let mut burn_blocks = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();

            let entry = burn_blocks
                .entry((burn_block, burn_block_height))
                .or_insert_with(|| 0);
            *entry += weight;
            if self.reached_agreement(*entry) {
                return Some((burn_block, burn_block_height));
            }
        }
        None
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

/// Regression for the same u32-overflow class as `reached_agreement_no_u32_overflow`,
/// but on the disagreement path. Here the multiplier is `10 - threshold = 3`,
/// so the wrap point is `total_weight > u32::MAX / 3 ≈ 1_431_655_765`, well
/// above the agreement wrap point (≈ 613M). The agreement test uses
/// `total_weight = 1_000_000_000` and so doesn't cover this path.

/// At `total_weight = 2_000_000_000`, the buggy `total_weight * 3` wrapped to
/// 1_705_032_704 and `/ 10` landed at 170_503_270. That made ~8.5% of total

fn reached_disagreement_no_u32_overflow() {
    let evaluator = evaluator_with_total_weight(2_000_000_000);

    // One past the pre-fix wrap value (~8.5% of total). Must not count as a
    // blocking minority.
    assert!(
        !evaluator.reached_disagreement(170_503_271),
        "~8.5% of total_weight must not satisfy the >30% disagreement check"

        "exactly 30% must not satisfy the strict > threshold"
    );

    assert!(
        evaluator.reached_disagreement(600_000_001),

    );
}
