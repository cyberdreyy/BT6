### Title
Zip Slip path traversal in `ExtractZipArchive` allows `lchmod`/`Lchown` (and prior write) outside extraction root - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` and the helper functions it calls (`extractZipFile`, `extractZipFileEntry`, `extractZipSymlinkEntry`, `lchmod`, `processZipUIDGidField`) use `zip.File.Name` verbatim, with no path validation against the intended extraction root. A zip entry whose `Name` contains `../` sequences (or is an absolute path) causes writes, `chmod` (via `lchmod`/`unix.Fchmodat`), and `chown` (via `os.Lchown`) to be performed on a path outside the sandbox, i.e. classic "Zip Slip".

### Finding Description
`ExtractZipArchive` iterates `archive.File` and, for every entry, calls `extractZipFile(file)` which does:
- `os.MkdirAll(filepath.Dir(file.Name), 0o777)` [1](#0-0) 
- `os.Mkdir(file.Name, ...)`, `os.Symlink(data, file.Name)`, or `os.OpenFile(file.Name, ...)` depending on entry type [2](#0-1) 

None of these apply `filepath.Clean`/`filepath.Abs` checks against a sandbox root, nor do they reject entries whose cleaned name starts with `..` or `/`. The only pre-check performed, `errorIfGitDirectory`, only detects a leading `.git` path component — it is not a traversal guard [3](#0-2) .

After the initial write pass, a second loop calls `lchmod(file.Name, file.Mode())` [4](#0-3) . `lchmod` passes `name` straight into `unix.Fchmodat(unix.AT_FDCWD, name, ...)` with no path check [5](#0-4) . Likewise `processZipExtra` → `processZipUIDGidField` calls `os.Lchown(file.Name, uid, gid)` on the same unsanitized name [6](#0-5) .

Because the write (`os.OpenFile`/`os.Symlink`/`os.Mkdir`) already happened on the escaped path in the first pass, the subsequent `lchmod`/`Lchown` calls are simply continuing to operate on a file that already exists outside the intended root — they don't add a new escape vector but they do confirm the escape is fully realized (content + permissions + ownership all land outside sandbox).

Regarding part (b) of the proposed invariant (no mode bits above 0777 ever applied): this is **not** violated. `lchmod` calls `mode.Perm()` before passing to `Fchmodat`, and `os.FileMode.Perm()` masks the value to `ModePerm` (`0777`), so setuid/setgid/sticky bits from the zip entry's mode can never reach the syscall. That part of the fuzz invariant already holds by construction.

### Impact Explanation
A malicious zip (a GitLab artifact or cache archive built and uploaded by an attacker-controlled job, later downloaded/extracted by Runner in another job or by the same job) with an entry name like `../../../../home/gitlab-runner/.ssh/authorized_keys` or an absolute path can cause Runner to create/overwrite files, set permissions, and (on unix with matching extra fields) chown files outside the build/cache directory. This breaks the "file operations must stay within intended build/cache/artifact roots" invariant and can lead to build-directory escape, config tampering, or privilege-adjacent file corruption on the executor host, depending on Runner process privileges.

### Likelihood Explanation
Precondition: attacker only needs to control the contents of an artifact/cache zip that Runner later extracts via `ExtractZipFile`/`ExtractZipArchive` (a normal, frequently-exercised code path for any job using `artifacts`/`cache`). No special privileges are required beyond authoring a CI job — a standard "normal GitLab user" job author scenario. The vulnerability is deterministic and trivially repeatable with a crafted zip.

### Recommendation
Before performing any filesystem operation on `file.Name` (mkdir, symlink, open, chmod, chown), resolve it against the destination root and reject/clean entries that escape it, e.g.:
```go
target := filepath.Join(destRoot, file.Name)
if !strings.HasPrefix(filepath.Clean(target)+string(os.PathSeparator), filepath.Clean(destRoot)+string(os.PathSeparator)) {
    return fmt.Errorf("illegal file path in archive: %s", file.Name)
}
```
Apply this check once in `ExtractZipArchive`/`extractZipFile` and reuse the validated path for `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`, `lchmod`, and `processZipUIDGidField` (or reject the whole entry before any operation).

### Proof of Concept
Go unit test (`helpers/archives/zip_extract_test.go`):
```go
func TestExtractZipArchive_ZipSlip(t *testing.T) {
    tmpDir := t.TempDir()
    outside := filepath.Join(t.TempDir(), "escaped.txt") // sibling dir, outside tmpDir
    require.NoError(t, os.Chdir(tmpDir))

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    relPath, _ := filepath.Rel(tmpDir, outside) // e.g. "../xxx/escaped.txt"
    fh := &zip.FileHeader{Name: relPath}
    fh.SetMode(0644)
    w, err := zw.CreateHeader(fh)
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    _ = ExtractZipArchive(zr)

    // Assert the file was NOT created outside tmpDir
    _, statErr := os.Stat(outside)
    assert.True(t, os.IsNotExist(statErr), "zip slip: file escaped extraction root")
}
```
Fuzz variant: generate random `file.Name` strings containing `../` sequences and random `os.FileMode` (including `ModeDir`, `ModeSymlink`), feed through `ExtractZipArchive`, and assert every resulting file/chmod/chown target (tracked via a stubbed/mocked `unix.Fchmodat`/`os.Lchown`/`os.OpenFile`) resolves under the sandbox root. The fuzzer will find escaping paths (invariant a violated); it will not find mode bits above `0777` (invariant b holds).

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
}

func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
