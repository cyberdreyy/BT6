### Title
Unauthenticated Request-ID Squatting in Gateway Handlers Enables Persistent Zero-Cost Denial-of-Service - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
The reported Particle Exchange bug is a pure griefing attack: an attacker cheaply occupies shared contract state (a lien) so that a legitimate user's later call reverts, with no direct economic gain to the attacker. The same class exists in Chainlink's gateway handlers: `activeRequests` maps keyed purely by the attacker-controlled JSON-RPC `req.ID` are shared across all callers of a handler, and at least one entry point (`MethodPublicKeyGet` in the vault handler, and the entire confidential-relay handler) allows an **unauthenticated** caller to reserve an arbitrary `req.ID` slot, which then causes any subsequent legitimate (and even successfully authorized) request using that same ID to be rejected outright.

### Finding Description
In `core/services/gateway/handlers/vault/handler.go`, `HandleJSONRPCUserMessage` handles `MethodPublicKeyGet` **before any authorization check**, explicitly noting "Public key requests don't require authorization": [1](#0-0) 

It then reserves a slot in the handler-wide `activeRequests` map keyed solely by the client-supplied `req.ID`: [2](#0-1) 

For authenticated methods (`SecretsCreate/Update/Delete/List`), authorization happens first, but the very same unscoped `newActiveRequest` call happens afterward, so a legitimate, already-authorized request fails if an attacker has pre-occupied the same `req.ID`: [3](#0-2) 

The confidential-relay handler is worse: `HandleJSONRPCUserMessage` performs **no authorization at all** before reserving the ID: [4](#0-3) [5](#0-4) 

In both handlers, the only validation on `req.ID` is non-emptiness and a 200-character length cap — there is no per-user/per-owner namespacing: [6](#0-5) 

An occupied slot is only released when the request completes, times out (`requestTimeout`, default 30s), or the periodic sweep runs: [7](#0-6) 

This mirrors the NFT-grief root cause: cheap/free access to shared mutable state (`lien` / `activeRequests[ID]`) lets an unprivileged actor block a legitimate party's operation on that same state, with no requirement that the attacker gain anything.

### Impact Explanation
An attacker with no vault/relay credentials can:
1. Send an unauthenticated `MethodPublicKeyGet` (vault) or any confidential-relay request with `req.ID = "<target-id>"`.
2. Occupy `activeRequests["<target-id>"]` for up to `requestTimeout` seconds, and indefinitely by refreshing before expiry.
3. Cause any legitimate request (even one that later passes authorization) using the same ID to be immediately rejected with `"request ID already exists"`, without ever reaching the vault nodes.

This is a pure availability grief: no funds or secrets are directly compromised, but a targeted user's job/secret/relay request can be persistently denied at zero cost to the attacker, exactly the severity profile that was ultimately accepted (Low/Medium) in the referenced report.

### Likelihood Explanation
The attack is entirely free (no auth, no rate-limit-consuming write operation) and requires only that the attacker know or predict the victim's `req.ID`. Since IDs are plain client-chosen strings (not server-generated nonces) with no per-owner scoping, collision is possible whenever an application uses predictable/deterministic IDs (e.g., idempotency keys, workflow-execution-derived IDs) — a pattern explicitly exercised in the handler's own tests using sequential IDs "1", "2": [8](#0-7) 

### Recommendation
- Namespace `activeRequests` by authenticated caller identity (e.g., `authorizedOwner + "/" + req.ID`) rather than by the raw client-supplied ID, so distinct users/owners cannot collide.
- Require authorization to occur, and bind the resulting identity, before any `req.ID` slot is reserved — including for `MethodPublicKeyGet` and the confidential-relay handler, which currently reserve slots pre-authorization/unauthenticated.
- Consider rejecting reservation collisions only when the previous holder cannot be shown to be the same authorized identity, rather than a global first-come-first-served map.

### Proof of Concept
1. Attacker (no auth) sends: `{"method":"vault_publicKeyGet","id":"victim-id","params":{}}` to the gateway. This hits `HandleJSONRPCUserMessage` → `newActiveRequest` at `core/services/gateway/handlers/vault/handler.go:420` and `:466-481`, succeeding without any credential check, inserting `activeRequests["victim-id"]`.
2. Victim's legitimate, correctly authorized request `{"method":"vault_secretsCreate","id":"victim-id",...}` arrives shortly after. It passes `requestProcessor.ProcessRequest` (`handler.go:436`) but fails at `newActiveRequest` (`handler.go:447`, `:469-472`) with `"request ID already exists: victim-id"`, and the victim's request never reaches the vault DON.
3. Attacker repeats step 1 every `<requestTimeout` seconds to sustain the block indefinitely, at zero cost.
4. The identical pattern (with no authorization step whatsoever) applies to `core/services/gateway/handlers/confidentialrelay/handler.go:349-383` for `MethodSecretsGet`/`MethodCapabilityExec`.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
