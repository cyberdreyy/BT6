### Title
Uncapped "locally-accepted-only" activity refresh lets a single miner indefinitely block the signers' inactivity-fallback, wedging the chain - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`check_latest_block_in_tenure` refreshes a tenure's `last_activity_time` whenever a conflicting, rejected block proposal arrives, so that a merely slow-but-honest miner isn't prematurely timed out. That refresh is correctly time-bounded (`reorg_attempts_activity_timeout`) only when the tenure's last block is *globally* accepted (`signed_group` is `Some`). When the last block is only *locally* accepted (`signed_group == None`), the code refreshes activity with **no time bound at all**, via `Option::is_none_or` short-circuiting to `true`. A miner who never lets a block reach global (70%) consensus in a tenure can keep resending cheap, self-signed, conflicting proposals forever and each one resets `last_activity_time`, so `is_timed_out`/`check_miner_inactivity` never fires and the signer set can never fall back to the prior miner — stalling the chain, at zero cost to the miner, using only gossip (no majority, no other signer's key).

### Finding Description
`SortitionData::check_latest_block_in_tenure` looks up the tenure's currently-known "last accepted block" (`get_tenure_last_block_info`, which returns any block whose `signed_self` or `signed_group` timestamp is still fresh) and, when a newly proposed block does not exceed its height, decides whether to treat the rejected proposal as legitimate "miner activity": [1](#0-0) 

The guard is:
```rust
if info.signed_group.is_none_or(|signed_time| {
    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
}) {
    // ... update_last_activity_time ...
}
```
`Option::is_none_or` evaluates to `true` immediately whenever `signed_group` is `None` — it never evaluates the time predicate in that case. So:
- If the last block in the tenure is **globally** accepted (`signed_group = Some(t)`), the refresh is capped: it only counts as activity within `reorg_attempts_activity_timeout` of the global-acceptance time. This exact cap is the fix validated by the test `reorg_attempts_activity_timeout_exceeded` [2](#0-1) .
- If the last block is only **locally** accepted (`signed_group = None`, i.e. this signer, or some signer subset, signed it but the network never reached 70% global consensus for it), the refresh has **no cap whatsoever**. Any later conflicting proposal — arriving seconds or weeks later — still refreshes `last_activity_time` via `signer_db.update_last_activity_time`.

`update_last_activity_time` is the sole input (besides `has_signed_block_in_tenure`) to `is_timed_out`, used identically by both protocol versions: [3](#0-2) [4](#0-3) 

`check_miner_inactivity` is the only mechanism by which the signer set falls back to the prior tenure when the current miner is unresponsive/malicious: [5](#0-4) 

A block only ever reaches `LocallyAccepted` (not `GloballyAccepted`) when signature weight crossed 70% for *this* signer's local bookkeeping but the block was never adopted by the node (e.g. a network/signer split, or a miner who deliberately proposes two conflicting siblings so different signer subsets accept different blocks and neither reaches the network-wide 70%/`NewBlock` observation) — exactly the scenario the `signed_conflicts`/pre-commit machinery in section 5 of the flow doc is built to reason about. The refresh in `check_latest_block_in_tenure` has no analogous protection.

The cost to the miner is essentially zero: producing a conflicting block header only requires the miner's own signing key (which they already hold as the sortition winner for the tenure) and no burn spend, no node validation success, and no cooperation from any other party — the same "grab with no payment, refreshed indefinitely" pattern as the referenced report's `Witch.grab`/`buy` — here the "grab" is holding `current_miner` status via `last_activity_time`, refreshed for free forever as long as `signed_group` never gets set for the tenure.

### Impact Explanation
This breaks the liveness guarantee the timeout mechanism exists to provide: `check_miner_inactivity`/`is_timed_out` is supposed to guarantee that an unresponsive or misbehaving miner is eventually abandoned so the network can fall back to a prior valid miner and keep producing blocks. With the uncapped `None` branch, a single miner (one slot, no majority, no other party's keys) can indefinitely suppress that fallback by periodically broadcasting cheap conflicting/inferior proposals, wedging block production for the tenure. This matches the "High — a signer wedged... acting on a stale... threshold" liveness class in scope: the signer never re-evaluates whether the current miner is dead, and the state machine cannot recover on its own.

### Likelihood Explanation
Likelihood is moderate-to-high in an adversarial setting: it requires only (a) getting a block into `LocallyAccepted` state without it reaching global acceptance in the tenure (achievable by proposing conflicting siblings distributed so different signer subsets accept different blocks, or simply by network conditions that prevent 70% global convergence), and (b) periodically re-broadcasting any conflicting, lower/equal-height, self-signed proposal (cost: one signature, no node validation success required to trigger the refresh) at intervals shorter than `block_proposal_timeout`. No majority of signers, no other signer's key, and no auth_token/local access are needed — only the mining key for the current tenure, which the sortition winner already legitimately possesses.

### Recommendation
Apply the same `reorg_attempts_activity_timeout` (or an equivalent bound) to the `signed_group.is_none()` branch, e.g. by falling back to `signed_self` (or `approved_time`) as the anchor when `signed_group` is absent, so that "locally accepted but never globalized" blocks stop counting as fresh activity after a bounded window, just as globally accepted ones do:
```rust
let counts_as_activity = match info.signed_group {
    Some(signed_time) => signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs(),
    None => info.signed_self.is_some_and(|t| t + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()),
};
```

### Proof of Concept
1. Miner M wins tenure T and proposes two conflicting sibling blocks B1/B2 at the same height (or a block that a subset of signers signs while the rest reject/split), so that some signers reach `LocallyAccepted` on B1 (`signed_self` set) but the network never reaches 70% global weight (`signed_group` stays `None`, `mark_globally_accepted` never fires — see `stacks-signer/src/v0/signer.rs:690-729` for how `signed_group`/global acceptance is only set on `NewBlock` from the node).
2. `get_tenure_last_block_info` for tenure T therefore returns B1 with `signed_group = None` on the affected signers (`stacks-signer/src/chainstate/mod.rs:317-364`).
3. M periodically (interval < `block_proposal_timeout`) broadcasts new conflicting or stale-height proposals for T over StackerDB.
4. Each arrival re-enters `check_latest_block_in_tenure`; since `info.signed_group.is_none_or(...)` short-circuits `true`, `update_last_activity_time` fires every time, with no expiry (`stacks-signer/src/chainstate/mod.rs:403-417`, `stacks-signer/src/signerdb.rs:2249-2257`).
5. `is_timed_out` (`v1.rs:52-94`, `v2.rs:46-89`) never observes `elapsed > block_proposal_timeout`, so `check_miner_inactivity` (`v0/signer_state.rs:284-315`) never falls back to the prior tenure — tenure T's block production stalls indefinitely while M pays no cost beyond broadcasting signed headers.

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
