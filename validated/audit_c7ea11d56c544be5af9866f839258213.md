### Title
Cross-user callback hijack via MessageId collision in `web_api_trigger` requests - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores each user's callback in `h.savedCallbacks` keyed solely by the attacker-supplied `msg.Body.MessageId`, with no per-sender namespacing and no collision check. Any client able to reach the gateway's user HTTP endpoint with a validly-signed message can choose an arbitrary `MessageId` (any string ≤128 bytes not ending in a null byte), so an attacker who sends a request with the same `MessageId` as a pending victim request overwrites the victim's callback entry, causing the victim's node response to be delivered to the attacker instead.

### Finding Description
`ProcessRequest` in `core/services/gateway/gateway.go` decodes the incoming JSON-RPC request, calls `msg.Validate()` (signature-format/length checks only — see `core/services/gateway/api/message.go` `Validate()`), and then calls `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `Validate()` never enforces `MessageId` uniqueness or ties it to the sender — it is fully attacker-controlled data taken from the request body [2](#0-1) .

In `HandleLegacyUserMessage`, after payload/timestamp/method checks, the handler unconditionally stores the callback keyed only by `msg.Body.MessageId`, silently overwriting any existing entry with the same key:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [3](#0-2) 

When the node eventually responds with `MethodWebAPITrigger`, `handleWebAPITriggerMessage` looks up and deletes the entry by the same `MessageId` and forwards the response to whichever `Callback` is currently stored:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
return savedCb.SendResponse(...)
``` [4](#0-3) 

Exploit flow: attacker sends request A with `MessageId = X` (any low-privilege signer works — there is no admin/role check anywhere in this path, only signature-format validation). Before node A responds, attacker/victim sends request B also with `MessageId = X`. The second `h.savedCallbacks[X] = &savedCallback{...}` write replaces the first callback. When the DON node responds to request A (still keyed under the same MessageId at the node/DON layer, since the gateway forwarded A's original message and DON responses reference the original `MessageId`), the gateway looks up `savedCallbacks[X]`, finds the attacker's (overwritten) callback object, and delivers what was originally the first request's flow/response to that callback's HTTP connection. No check exists comparing `msg.Body.Sender` between the save and lookup, and no per-sender/message uniqueness constraint exists on the map key.

### Impact Explanation
This breaks the per-request isolation of the gateway's legacy user-message callback mechanism: an attacker can cause a response intended for one HTTP caller to be delivered to a different HTTP connection under attacker's control. This maps to a "cross-user response confusion" / information disclosure impact, potentially leaking response payloads (which may include data derived from external HTTP calls made on behalf of a workflow) to an unauthorized party. The severity is bounded by what data flows through `web_api_trigger` responses.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs a valid signing key (no special role/admin permission) able to produce a validly-signed `Message` with a `MethodWebAPITrigger` body, and needs to guess/know or race the `MessageId` of a target in-flight request. If `MessageId`s are attacker/client-chosen (not server-generated random UUIDs) or predictable, this is trivially and repeatably exploitable by simply sending a competing request with the same ID during the small window where the first request awaits a DON response (default `CallbackMaxAgeSec` is 120s, giving a wide race window) [5](#0-4) . If MessageIds are always cryptographically random and unguessable client-side, exploitability is reduced to a race with a known/observed ID, but the code contains no defense-in-depth check regardless.

### Recommendation
- Namespace `savedCallbacks` keys by `(sender, MessageId)` instead of `MessageId` alone, so that only the original sender can be matched to the resulting node response.
- Alternatively/additionally, reject `HandleLegacyUserMessage` calls when `msg.Body.MessageId` already exists in `h.savedCallbacks` (return a conflict error) rather than silently overwriting.
- Store and verify `msg.Body.Sender` (the recovered signer) in `savedCallback` and validate it matches on lookup in `handleWebAPITriggerMessage` before invoking `SendResponse`.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Create a `handler` via `NewHandler`, stub `don.SendToNode`, and two mock `handlers.Callback` objects (`callbackA`, `callbackB`) each recording whether `SendResponse` was invoked and with what payload.
2. Call `h.HandleLegacyUserMessage(ctx, msgA, callbackA)` where `msgA.Body.MessageId = "X"`, signed by keyA.
3. Immediately call `h.HandleLegacyUserMessage(ctx, msgB, callbackB)` where `msgB.Body.MessageId = "X"` (same ID), signed by keyB.
4. Simulate the DON node response for the original request A (a `*api.Message` with `Body.MessageId = "X"`, `Method: MethodWebAPITrigger`) via `h.HandleNodeMessage(...)`.
5. Assert: `callbackB.SendResponse` was invoked (receiving what was meant for A's flow) while `callbackA.SendResponse` was never called — demonstrating that request A's original submitter never gets a response and B's callback receives whatever the map resolves to, confirming the overwrite/hijack.
6. Additionally assert `len(h.savedCallbacks) == 1` after both `HandleLegacyUserMessage` calls to directly show the overwrite of the map entry keyed by `MessageId`.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
