### Title
Rounding-direction mismatch between `GlobalStateEvaluator::reached_agreement` and the consensus-critical `compute_voting_weight_threshold` lets a signer capitulate to a non-canonical miner view below the true 70% supermajority - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The signer-side "global agreement" check used to determine the current-miner/burn-view/protocol-version consensus among gossiped `StateMachineUpdate` messages rounds the 70% threshold **down**, while the chain-consensus-critical block-approval threshold used by the node and by the signer's own block-signing path rounds the same 70% threshold **up**. This creates an equality mismatch analogous to the GVault `convertToShares`/`convertToAssets` rounding-direction bug: two formulas that are supposed to represent the same "supermajority" concept diverge by up to 1 unit of weight whenever `total_weight * 7` is not a multiple of 10.

### Finding Description
The consensus-critical threshold, used both by the node (`verify_signer_signatures`) and mirrored in the signer's own block-acceptance path (`store_and_process_block_signature`, `handle_block_pre_commit`), computes a strict ceiling: [1](#0-0) 

```
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
```

This is used inside `store_and_process_block_signature` and `handle_block_pre_commit` in `stacks-signer/src/v0/signer.rs` to decide when to sign/broadcast a block, matching the node's canonical check exactly. [2](#0-1) [3](#0-2) 

However, the separate `GlobalStateEvaluator::reached_agreement` function — which is used to determine the *global signer state* (active protocol version, global burn view, and, critically, the agreed `current_miner`/`MinerState`) from peers' gossiped `StateMachineUpdate` messages — uses plain integer division, i.e. a **floor**, not a ceiling: [4](#0-3) 

```
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
```

For any `total_weight` where `total_weight * 7` is not divisible by 10 (e.g. `total_weight = 3`: `3*7=21`, `ceil=3`, `floor=2`), `reached_agreement` returns `true` for a vote weight that is strictly less than the true 70% supermajority required by `compute_voting_weight_threshold`/`verify_signer_signatures`. The existing regression tests explicitly document and pin down this "supermajority constant is 7" boundary behavior for `reached_agreement`/`reached_disagreement`, and separately for `compute_voting_weight_threshold`, but never assert that the two computations agree with each other: [5](#0-4) [6](#0-5) 

`reached_agreement` feeds `determine_global_state`, which sets the `current_miner` (`MinerState::ActiveMiner`), the global burn view, and the active protocol version: [7](#0-6) 

That global state is in turn consumed by `LocalStateMachine::capitulate_viewpoint` / `capitulate_miner_view`, which can flip a signer's local view of the current miner (and mark the current sortition's miner as `SortitionMinerStatus::InvalidatedBeforeFirstBlock`) based on `eval`/`GlobalStateEvaluator`: [8](#0-7) [9](#0-8) 

### Impact Explanation
Because `reached_agreement`'s floor-based threshold can be satisfied by strictly less than the ceiling-based 70% required for actual block approval, a signer can be induced to treat a `current_miner`/burn-view/replay-set state as the agreed "global state" and capitulate its local view to it, even though the underlying weighted support has not reached the true supermajority that `verify_signer_signatures`/`compute_voting_weight_threshold` would require to actually approve a block. This can cause a signer to switch its `current_miner` viewpoint (and invalidate the actual current sortition's miner status) on the strength of less-than-70% support, which is a divergence between "aggregated weight" and "verified accepted" — the equality the report class targets. In the worst case this steers a signer toward treating a non-canonical/attacker-favored miner or burn view as the agreed global state, misaligning its block-signing behavior with the network's actual canonical view (a liveness/coordination wedge, and a precursor to signing on the wrong tenure).

Note: the actual block-signature threshold check in `store_and_process_block_signature`/`handle_block_pre_commit` independently calls `compute_voting_weight_threshold` (the correct ceiling), so this specific bug does **not** by itself allow a signer to produce a signature over an under-supported block. Its confirmed blast radius is confined to the `GlobalStateEvaluator`-driven state machine (`current_miner`, burn view, protocol version, replay-set agreement), not the final signature-count gate.

### Likelihood Explanation
The divergence is deterministic and triggers automatically whenever `total_weight * 7 mod 10 != 0` — which is common for realistic weight distributions (any `total_weight` not a multiple of 10). No majority of signers, secret keys, or elevated access is required to trigger the *rounding gap itself*: it is a pure off-by-one baked into every evaluation of `reached_agreement`/`reached_disagreement`, exercised continuously as signers process gossiped `StateMachineUpdate`s. What is uncertain from static review alone is the exact set of downstream conditions (proximity of vote_weight to the boundary, gossip timing) needed to make this the deciding factor in an actual capitulation event; that requires runtime/integration testing beyond what static code reading can establish.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` use the same ceiling semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, have both call a single shared threshold function) so that "global agreement" among signers can never be reached with less weight than the chain-consensus-critical 70% supermajority. Add a cross-crate test asserting `GlobalStateEvaluator::reached_agreement(w)` and `NakamotoBlockHeader::compute_voting_weight_threshold(total) <= w` agree for all boundary values of `total_weight`.

### Proof of Concept
With `total_weight = 3` (three signers with weight 1 each), `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`:
- `compute_voting_weight_threshold(3)` = ceil(21/10) = `3` (all three signers required).
- `GlobalStateEvaluator::reached_agreement(2)` = `2 >= floor(21/10) = 2` → `true`.

Thus two out of three signers' `StateMachineUpdate`s agreeing on a `current_miner`/burn-view is enough for `determine_global_state` to return that state as the "global state" via `reached_agreement`, even though `verify_signer_signatures`/`compute_voting_weight_threshold` would require all three signers' weight to approve a block under the same nominal 70% rule. This lets `capitulate_viewpoint` switch a signer's local miner view based on 66.6% instead of the intended 100%(≥70% ceil) supermajority for that weight distribution.

                burn_block_height,
                current_miner: current_miner.clone().into(),

                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

                found_state_view = Some(state_machine);

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
