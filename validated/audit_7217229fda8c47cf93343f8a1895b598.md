### Title
RPC `jsonParsed` token decoding trusts a token account's embedded `mint` field without verifying the referenced account is owned by an SPL Token program, allowing misreported balances/decimals - (File: `rpc/src/parsed_token_accounts.rs`)

### Summary
The Uniswap report flags a pattern of trusting an externally-supplied address (a pool) to actually be what it claims to be, without independently verifying it against the source of truth (the Uniswap factory) before using its returned data. The analogous pattern in agave is in the RPC layer's `jsonParsed` token-account encoding path: it extracts a `mint` pubkey from account data and then unpacks whatever account lives at that pubkey as an SPL `Mint`, without verifying that account is actually owned by a legitimate SPL Token program, unlike the sibling code path in `rpc.rs` that does perform this check.

### Finding Description
`get_token_account_mint` in `account-decoder/src/parse_token.rs` (lines 166-170) extracts the first 32 bytes of arbitrary account data as a "mint" pubkey whenever the data merely satisfies `Account::valid_account_data` — a lightweight structural check, not an ownership check. [1](#0-0) 

This is consumed by `get_parsed_token_account` and `get_parsed_token_accounts` in `rpc/src/parsed_token_accounts.rs`, which resolve the extracted mint pubkey to an on-chain account via `bank.get_account`/`get_account_from_overwrites_or_bank`, and then pass that account's raw data straight into `get_additional_mint_data`, which calls `StateWithExtensions::<Mint>::unpack(data)` to derive `decimals`/extension configs — again with no check that the resolved account's `owner()` is actually `spl_token`/`spl_token_2022`: [2](#0-1) [3](#0-2) [4](#0-3) 

This is the same bug class as the report: a value obtained from untrusted/attacker-influenced data (the `mint` field inside a token account) is used to fetch a second account, and that second account's contents are trusted to be a legitimate instance of the expected type (a `Mint`) purely because it happens to structurally decode — mirroring how the Overlay feed trusted a supplied pool's `token0()`/`token1()` return values without checking the pool was a genuine Uniswap pool. Notably, a sibling code path in `rpc/src/rpc.rs`, `get_token_program_id_and_mint`, does perform the missing validation via `is_known_spl_token_id(&mint_owner)` before proceeding [5](#0-4) , confirming that the check is expected/available but is not applied in the `parsed_token_accounts.rs` path used for `jsonParsed` encoding of individual accounts (`getAccountInfo`, `getProgramAccounts`, `getTokenAccountsByOwner`/`ByDelegate`, and account-subscription notifications via `rpc_subscriptions.rs`).

### Impact Explanation
Because the resolved "mint" account's ownership is never validated, an attacker can create/control an account at the pubkey referenced by a token account's `mint` field whose raw bytes happen to unpack successfully as an SPL `Mint` (attacker chooses `decimals`, authorities, etc., since these are plain byte fields with no cryptographic binding to a real token program). When an unprivileged client queries that token account through `jsonParsed` encoding, the RPC node will report a `UiTokenAmount` computed using the attacker-chosen decimals/extension configuration instead of the real mint's values — a decoder misreporting condition (wrong data returned to a query, without any consensus-state mutation) that falls squarely within the accepted impact categories (decoder panic/misreporting, wrong data returned to a single low-rate call).

### Likelihood Explanation
The path is reachable by any unprivileged RPC caller supplying `encoding: jsonParsed` in `getAccountInfo`, `getProgramAccounts`, `getTokenAccountsByOwner`, `getTokenAccountsByDelegate`, or via `accountSubscribe`/`programSubscribe` notifications, none of which require special permissions. Whether normal SPL Token/Token-2022 accounts can ever legitimately reference a "mint" that is not owned by the token program depends on on-chain initialization guarantees enforced by the SPL Token program itself (which are out of this repo's control); the RPC-side code has no independent verification and relies entirely on that external invariant holding, which is precisely the trust assumption the reported bug class warns against.

### Recommendation
In `rpc/src/parsed_token_accounts.rs`, before treating a resolved "mint" account's data as a `Mint`, verify `mint_account.owner()` matches a known SPL Token program id (`is_known_spl_token_id`), mirroring the check already performed in `get_token_program_id_and_mint` in `rpc/src/rpc.rs`. If the owner check fails, omit `additional_data` (fall back to raw/base64 encoding or omit parsed amount fields) rather than silently using untrusted decimals.

### Proof of Concept
Not confirmed independently; reachability and exact exploitability depend on verifying (a) that `StateWithExtensions::<Mint>::unpack` does not itself enforce any binding to a genuine SPL Token program beyond structural layout, and (b) that it is possible under the SPL Token program's own `InitializeAccount` logic to end up with a `mint` field pointing to a non-token-program-owned account, or that a subsequent account replacement (e.g., account closed/reused) at that mint pubkey changes its owner after the token account was created. These on-chain program invariants (spl-token/spl-token-2022) are outside this repo and were not independently re-verified in the index; a Devin session with full repo/tool access would be needed to construct and run a concrete end-to-end PoC.

pub fn get_parsed_token_accounts<I>(
    bank: Arc<Bank>,
    keyed_accounts: I,
) -> impl Iterator<Item = RpcKeyedAccount>
where
    I: Iterator<Item = (Pubkey, AccountSharedData)>,
{
    let mut mint_data: HashMap<Pubkey, AccountAdditionalDataV3> = HashMap::new();
    keyed_accounts.filter_map(move |(pubkey, account)| {
        let additional_data = get_token_account_mint(account.data()).and_then(|mint_pubkey| {
            mint_data.get(&mint_pubkey).cloned().or_else(|| {
                let (_, data) = get_mint_owner_and_additional_data(&bank, &mint_pubkey).ok()?;
                let data = AccountAdditionalDataV3 {
                    spl_token_additional_data: Some(data),
                };
                mint_data.insert(mint_pubkey, data);
                Some(data)
            })
        });

        let maybe_encoded_account = encode_ui_account(
            &pubkey,
            &account,
            UiAccountEncoding::JsonParsed,
            additional_data,
            None,
        );
        if let UiAccountData::Json(_) = &maybe_encoded_account.data {
            Some(RpcKeyedAccount {
                pubkey: pubkey.to_string(),
                account: maybe_encoded_account,
            })
        } else {
            None
        }
    })
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })

/// Analyze a passed Pubkey that may be a Token program id or Mint address to determine the program
/// id and optional Mint
fn get_token_program_id_and_mint(
    bank: &Bank,
    token_account_filter: TokenAccountsFilter,
) -> Result<(Pubkey, Option<Pubkey>)> {
    match token_account_filter {
        TokenAccountsFilter::Mint(mint) => {
            let (mint_owner, _) = get_mint_owner_and_additional_data(bank, &mint)?;
            if !is_known_spl_token_id(&mint_owner) {
                return Err(Error::invalid_params(
                    "Invalid param: not a Token mint".to_string(),
                ));
            }
            Ok((mint_owner, Some(mint)))
        }
        TokenAccountsFilter::ProgramId(program_id) => {
            if is_known_spl_token_id(&program_id) {
                Ok((program_id, None))
            } else {
                Err(Error::invalid_params(
                    "Invalid param: unrecognized Token program id".to_string(),
                ))
            }
        }
    }
}
