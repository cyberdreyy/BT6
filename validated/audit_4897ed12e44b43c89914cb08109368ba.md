### Title
Unauthenticated allowlist bypass in `HandleLegacyUserMessage` allows any keypair to trigger workflow execution on all DON nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` only validates message structure (payload decode, timestamp freshness, method) but explicitly skips authorization, as marked by the `// TODO: apply allowlist and rate-limiting here` comment, before forwarding the request to every DON member via `don.SendToNode`. Any party who can produce a validly-formatted, self-signed `api.Message` (via `msg.Validate()` in `gateway.go`) can trigger `MethodWebAPITrigger` for arbitrary DON members with no check on `msg.Body.Sender`'s identity or subscription/allowlist status.

### Finding Description
The request path is: `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) decodes the raw JSON-RPC request, and for legacy requests (`msg.Body.DonId != ""`) only calls `msg.Validate()` [1](#0-0)  — which is a structural/signature-format validation, not a sender authorization check — then dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` [2](#0-1) .

Inside `HandleLegacyUserMessage`, the checks performed are: payload JSON decoding, `payload.Timestamp` non-zero, and message staleness [3](#0-2) . Immediately after, the code contains the explicit gap: `// TODO: apply allowlist and rate-limiting here`, followed only by a method-name check (`msg.Body.Method != MethodWebAPITrigger`) [4](#0-3) . No code anywhere in this function inspects `msg.Body.Sender` against any allowlist, subscription table, or per-workflow authorization list. The function then unconditionally builds the request and loops over all `h.donConfig.Members`, calling `don.SendToNode` for each: [5](#0-4) .

The only gate before reaching this function is `msg.Validate()`, which — based on the codebase's `common.ValidatedRequestFromMessage`/message validation helpers referenced elsewhere in this file — verifies the message is well-formed and that the signature matches the claimed sender address (i.e., proves possession of a keypair), but does not check that the sender address is a member of any subscription/allowlist for the target DON or workflow. Since ECDSA keypairs are free to generate, this "signature exactness" check alone provides no authorization guarantee — it only proves self-consistency of the message, not that the sender is entitled to trigger the target capability. This matches the described precondition: attacker controls any ECDSA keypair, no subscription required.

### Impact Explanation
This allows an unprivileged attacker who can reach the gateway's user-facing HTTP API to submit a self-signed legacy `web_api_trigger` message and have it delivered to every node of a target DON, invoking `MethodWebAPITrigger` capability execution as if it were an authorized trigger event. This corresponds to Chainlink's "unauthorized job run / unauthorized capability execution" bounty impact class — an attacker can consume/trigger workflow execution capacity that legitimate access control (allowlisting/subscriptions) is intended to restrict to specific senders, potentially resulting in resource exhaustion, unauthorized invocation of another user's registered trigger workflow logic, or abuse of the WebAPI trigger capability pipeline DON-wide.

### Likelihood Explanation
Feasibility is high and repeatable: the attacker needs only to generate an ECDSA keypair (no registration, subscription, or gateway-side credential), craft a valid legacy `api.Message` with `Method=MethodWebAPITrigger`, a fresh `MessageId`, a payload with a non-zero, fresh `Timestamp`, and a matching self-signature so that `msg.Validate()` in `gateway.go` succeeds. This can be repeated for arbitrary DON IDs configured on the gateway, with each request fanned out to all `donConfig.Members`. The TODO comment is direct evidence this control was never implemented, and no other function in this file or in `gateway.go`'s legacy path substitutes for it.

### Recommendation
Implement the missing authorization check before forwarding to `don.SendToNode`: maintain and consult a per-DON/per-workflow allowlist or subscription map keyed by `msg.Body.Sender`, rejecting (with `api.UnauthorizedError` or similar) any `MethodWebAPITrigger` message whose sender is not registered/subscribed for the target workflow/DON, in addition to enforcing rate-limiting per sender (not just the existing `nodeRateLimiter` which is keyed by node address for outgoing node messages, not incoming user messages).

### Proof of Concept
Add a table-driven test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build a `handler` via `NewHandler` with a `donConfig` containing several `Members`, and a mock `handlers.DON` (`don.SendToNode`) using `gomock`.
2. Construct a valid `api.Message` with `Body.Method = MethodWebAPITrigger`, a fresh `MessageId`, valid `payload.Timestamp`, and a signature produced from a locally-generated ECDSA key that is NOT present in any expected allowlist/subscription fixture.
3. Call `h.HandleLegacyUserMessage(ctx, msg, callback)`.
4. Assert that `don.SendToNode` is NOT called for any member (expect zero `SendToNode` invocations) and that the callback receives an authorization/unauthorized error response, instead of the current behavior where the mock records `SendToNode` invoked once per `h.donConfig.Members` entry.
5. As a control case, repeat with a sender address present in a hypothetical allowlist fixture and assert `SendToNode` IS called for all members — demonstrating the fix differentiates authorized vs. unauthorized senders, which the current implementation does not.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
