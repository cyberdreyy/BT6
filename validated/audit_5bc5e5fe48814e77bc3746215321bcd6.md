### Title
Owner's reward fee (`owners_fee`) is credited into `total_staked_balance` without minting matching owner shares when rounding truncates `num_shares` to 0 - (File: staking-pool/src/internal.rs)

### Summary
In `internal_ping`, the owner's fee share of accrued staking rewards is computed as `num_shares_from_staked_amount_rounded_down(owners_fee)`. When `owners_fee` is smaller than the value of one stake share (i.e. it rounds down to 0 shares), the guarded block that mints shares to the owner is skipped, yet `self.total_staked_balance += owners_fee` still executes unconditionally. This inflates `total_staked_balance` (and therefore the share price for everyone) without minting the owner any shares, so that epoch's fee accrues to all existing shareholders proportionally instead of the owner.

### Finding Description
Binding: `staked_amount_from_num_shares_rounded_down(owner.stake_shares)_after - staked_amount_from_num_shares_rounded_down(owner.stake_shares)_before` should equal the `owners_fee` accrued to the owner for that epoch. In `internal_ping` [1](#0-0) , the code computes `owners_fee = reward_fee_fraction.multiply(total_reward)`, then `num_shares = num_shares_from_staked_amount_rounded_down(owners_fee)`. If `num_shares > 0`, shares are minted to the owner's account and `total_stake_shares` grows; the code then increases `self.total_staked_balance += owners_fee` regardless of whether `num_shares` was 0, with the comment explicitly stating this happens "no matter whether the owner received any shares or not" [2](#0-1) .

When `owners_fee` is less than the current share price (`total_staked_balance / total_stake_shares`), `num_shares_from_staked_amount_rounded_down` truncates to 0 [3](#0-2) , so the owner-share-minting block is skipped, but `total_staked_balance` is still incremented by `owners_fee`. Since `total_stake_shares` is unchanged in that case, the per-share value of every existing shareholder's stake increases at the owner's expense — the owner's `stake_shares` stays flat while the aggregate value backing all shares grows by `owners_fee`, so the owner's actual claim (`staked_amount_from_num_shares_rounded_down(owner.stake_shares)`) only grows in proportion to whatever shares the owner already holds (possibly zero), not by the full `owners_fee`. The `num_shares > 0` check that gates share minting does not gate the `total_staked_balance` increment, so no existing guard (`assert_owner`, `internal_ping`'s balance assert, or the rounding pair) prevents this divergence — this is a structural gap in the accounting, not a guarded invariant.

Any account holder calling any pool method (`deposit`, `stake`, `unstake`, `withdraw`, `ping`) triggers `internal_ping()` once per new epoch, so this occurs automatically whenever an epoch boundary is crossed with a small reward and/or small `reward_fee_fraction`, and is exercisable by any unprivileged caller simply by transacting against the pool across epochs — no special privilege is required to trigger it.

### Impact Explanation
Each epoch where this rounding occurs, the owner's fee for that epoch is not credited to the owner but is instead smeared across `total_staked_balance` and thus benefits all existing delegators proportionally, permanently. This is a misattribution of rewards ("rewards or owner fees attributed to the wrong party") matching the High severity category. No NEAR leaves the contract and the total accounted balance (`total_staked_balance`) still matches actual on-chain balance, but the *internal* allocation between owner and delegators diverges from the intended fee split, and this divergence compounds epoch over epoch as long as `owners_fee` stays below one share's value (typical for pools with small `reward_fee_fraction` or small absolute rewards, e.g. near the minimum-stake or low-participation pools).

### Likelihood Explanation
No special attacker setup is required beyond normal use of the pool: any unprivileged account can interact with any staking pool (deposit/stake/unstake/withdraw) across multiple epochs. The rounding-to-zero condition depends on the pool's `reward_fee_fraction` and the size of per-epoch rewards relative to the current share price, both of which are common for small pools or pools with tiny fee fractions, so this is readily triggered by ordinary usage over time rather than needing an adversarial input. It is repeatable every epoch that meets the rounding condition.

### Recommendation
Track fractional/undistributed owner fee remainders (e.g., accumulate `owners_fee` that failed to mint whole shares in a persisted counter) and mint the owner shares once the accumulated remainder exceeds one share's value, or accrue the un-minted `owners_fee` in an explicit "pending owner fee" balance rather than folding it silently into `total_staked_balance`. Alternatively, gate the `self.total_staked_balance += owners_fee` line so it only executes when `num_shares > 0`, and route any un-mintable dust back into `remaining_reward` for delegators only when explicitly intended, rather than defaulting to owner-fee dilution.

### Proof of Concept
```rust
// staking-pool/src/tests.rs (unit test using testing_env!)
#[test]
fn test_owner_fee_rounds_to_zero_dilutes_owner() {
    let mut context = VMContextBuilder::new().build();
    testing_env!(context.clone());
    let mut contract = StakingContract::new(
        owner_account(),
        stake_public_key(),
        RewardFeeFraction { numerator: 1, denominator: 1000 }, // tiny fee fraction
    );

    // Establish an initial total_staked_balance and total_stake_shares via a stake() call
    // from some delegator so that share price = total_staked_balance / total_stake_shares > owners_fee.
    // e.g. total_staked_balance = 10_000 NEAR, total_stake_shares = 10_000 (price = 1 yocto/share)

    let owner_shares_before = contract.internal_get_account(&owner_account()).stake_shares;
    let total_staked_before = contract.total_staked_balance;

    for epoch in 1..=50 {
        // simulate tiny reward each epoch such that
        // owners_fee = reward_fee_fraction.multiply(total_reward) < 1 share's value
        context.epoch_height = epoch;
        context.account_locked_balance += tiny_reward_amount; // e.g. 100 yoctoNEAR
        testing_env!(context.clone());
        contract.internal_ping();
    }

    let owner_shares_after = contract.internal_get_account(&owner_account()).stake_shares;
    let total_staked_after = contract.total_staked_balance;

    // Binding check: owner's shares should NOT have grown (num_shares rounded to 0 every epoch)
    assert_eq!(owner_shares_after, owner_shares_before);
    // But total_staked_balance grew by the sum of all owners_fee amounts credited without shares
    assert!(total_staked_after > total_staked_before);
    // Owner's claim value did not increase by the accrued owners_fee total
    let owner_claim_after = contract.staked_amount_from_num_shares_rounded_down(owner_shares_after);
    assert!(owner_claim_after < total_staked_after - total_staked_before /* sum of owners_fee */);
}
```
This demonstrates that `owner.stake_shares` remains flat across many epochs while `total_staked_balance` grows by the accrued `owners_fee`, confirming the binding (owner's claim growth == owners_fee accrued) is broken.

    pub(crate) fn num_shares_from_staked_amount_rounded_down(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        (U256::from(self.total_stake_shares) * U256::from(amount)
            / U256::from(self.total_staked_balance))
        .as_u128()
    }
