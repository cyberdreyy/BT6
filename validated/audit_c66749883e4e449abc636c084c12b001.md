### Title
Removed member's stale confirmation still counts toward `num_confirmations`, allowing a request to execute with fewer live-member confirmations than required - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges requests whose *creator* (`MultiSigRequestWithSigner.member`) equals the member being removed; it never scans the `confirmations: LookupMap<RequestId, HashSet<String>>` map to strip that member's vote from other requests they merely **confirmed**. A member who confirmed some other member's pending request and is later removed via `DeleteMember` leaves a "ghost" confirmation behind that still counts toward the `num_confirmations` threshold, letting a request execute using fewer than `num_confirmations` actual live members.

### Finding Description
The broken binding: for any executed request, `confirmations_count(request) == count(distinct current, live members who confirmed)`. The code path breaks this because:

- `add_request` stamps the request with the creator's identity in `MultiSigRequestWithSigner.member` [1](#0-0) .
- `confirm` inserts the caller's identity string into `confirmations: HashSet<String>` for that request, independent of `request.member` [2](#0-1) .
- `delete_member` filters requests to purge **only** by `r.member == member` (i.e. requests the removed member *created*), and only clears `num_requests_pk` for that member. It never inspects or cleans `self.confirmations` entries the removed member placed on requests created by *other* members: [3](#0-2) .
- `assert_valid_request` and `current_member` only validate the identity of the *current caller*, never re-validate previously stored confirmation entries in the `HashSet<String>` against the live member set [4](#0-3) .

Exploit flow:
1. Multisig has members `{A, B, C, D}`, `num_confirmations = 3`.
2. Member `A` creates request `R` (e.g. `Transfer`) via `add_request`; `R.member = A`.
3. Member `C` calls `confirm(R)` — `confirmations[R] = {C}` (count 1, below threshold, not executed).
4. Separately, members confirm and execute a `DeleteMember{ member: C }` request. `delete_member` removes `C` from `self.members`, deletes `num_requests_pk[C]`, and deletes only requests where `r.member == C` — `R` was created by `A`, so it is untouched, and `confirmations[R]` still contains `"C"`.
5. `C` is now fully removed (key/account no longer a member; `current_member()` for `C` returns `None`).
6. Member `B` calls `confirm(R)` → `confirmations[R] = {C, B}`, count 2. Member `D` calls `confirm(R)` → count 3 == `num_confirmations`, so `remove_request` + `execute_request` fire and `R`'s `Transfer` action is executed.

Only two *live* members (`B`, `D`) actually approved `R` after `C`'s removal, plus `C`'s stale pre-removal vote — the request executes with 2 live confirmations, not 3. No existing guard (`assert_valid_request`, `current_member`, `assert_self_request`) checks that entries already present in the `confirmations` set still belong to current members.

### Impact Explanation
This directly satisfies the specified Critical category: "a multisig request executed below `num_confirmations` live members." Any action reachable through `execute_request` — `Transfer`, `AddKey` (adding a full-access key), `DeployContract`, `FunctionCall`, `AddMember`/`DeleteMember` — can be pushed through with one fewer genuine approval than intended, because a removed (possibly maliciously acting, since removal often follows loss of trust) member's earlier vote is never invalidated. This is repeatable for every pending request the departing member had confirmed but not created, and for every subsequent member removal event. The blast radius is the full balance/authority controlled by the multisig account, since `Transfer`/`AddKey`/`FunctionCall` can move funds or grant new access with an under-quorum approval.

### Likelihood Explanation
No special privilege beyond ordinary multisig membership is required — this is a design flaw inherent to legitimate multisig operation, not requiring an owner, foundation, or key compromise. It reliably triggers whenever: (a) a member confirms a request they didn't create, (b) that member is later removed via a normal `DeleteMember` request while the other request is still outstanding, and (c) enough remaining members confirm to reach the original count including the stale entry. Both conditions are common in real multisig workflows (partial confirmations pending while membership changes, e.g. removing a compromised or departing signer). Cost to trigger is just normal multisig transaction fees; no attacker cost beyond being a legitimate participant in normal multisig operations.

### Recommendation
In `delete_member`, besides purging requests created by the removed member, iterate all remaining requests' confirmation sets and remove the departing member's identity string from every entry (or re-validate confirmation set membership against `self.members` at `confirm` time before counting `confirmations.len()`). The simplest robust fix is to filter each `HashSet<String>` in `self.confirmations` to only count/keep identities still present in `self.members` before comparing against `num_confirmations` in `confirm`.

### Proof of Concept
```rust
// multisig2/src/lib.rs test module (illustrative)
#[test]
fn test_removed_member_stale_confirmation_still_counts() {
    // members(): [alice, bob, access_key1, access_key2(TEST_KEY)]
    // Treat: A = alice, B = bob, C = access_key1 (key "Eg2jts..."), D = access_key2 (TEST_KEY)
    let amount = 1_000;

    // A creates request R (as alice)
    testing_env!(context_with_account(alice(), amount));
    let mut c = MultiSigContract::new(members(), 3);
    let request = MultiSigRequest {
        receiver_id: bob(),
        actions: vec![MultiSigRequestAction::Transfer { amount: amount.into() }],
    };
    let request_id = c.add_request(request);

    // C (access_key1) confirms R -> confirmations = {C}, count 1 < 3
    testing_env!(context_with_key(
        PublicKey::from("Eg2jtsiMrprn7zgKKUk79qM1hWhANsFyE6JSX4txLEuy".parse().unwrap()),
        amount
    ));
    c.confirm(request_id);
    assert_eq!(c.confirmations.get(&request_id).unwrap().len(), 1);

    // Remove C via DeleteMember request, confirmed by alice, bob, D (TEST_KEY)
    let c_member = MultisigMember::AccessKey {
        public_key: PublicKey::from("Eg2jtsiMrprn7zgKKUk79qM1hWhANsFyE6JSX4txLEuy".parse().unwrap()),
    };
    testing_env!(context_with_account(alice(), amount));
    let del_req_id = c.add_request(MultiSigRequest {
        receiver_id: alice(),
        actions: vec![MultiSigRequestAction::DeleteMember { member: c_member.clone() }],
    });
    c.confirm(del_req_id); // alice confirms (1)
    testing_env!(context_with_account(bob(), amount));
    c.confirm(del_req_id); // bob confirms (2)
    testing_env!(context_with_key(PublicKey::try_from(TEST_KEY.to_vec()).unwrap(), amount));
    c.confirm(del_req_id); // D confirms (3) -> executes delete_member(C)

    // Binding check #1: R still exists, and C's stale confirmation is still present
    assert_eq!(c.requests.len(), 1); // R untouched (created by alice, not C)
    let confs = c.confirmations.get(&request_id).unwrap();
    assert!(confs.contains(&c_member.to_string())); // STALE vote from removed member still counted
    assert_eq!(confs.len(), 1);

    // Only 2 more LIVE confirmations should be required to reach num_confirmations=3,
    // instead of 3 genuinely live confirmations.
    testing_env!(context_with_account(bob(), amount));
    c.confirm(request_id); // live confirmation #1 (bob) -> count 2 (C stale + bob)
    testing_env!(context_with_key(PublicKey::try_from(TEST_KEY.to_vec()).unwrap(), amount));
    c.confirm(request_id); // live confirmation #2 (D) -> count 3, EXECUTES

    // Binding check #2 (violated): request executed with only 2 live confirmations (bob, D)
    // instead of num_confirmations = 3 live members.
    assert_eq!(c.requests.len(), 0); // executed
}
```
This demonstrates the equality `confirmations_count == live_member_confirmations` fails: the request executes after only 2 genuinely live confirmations plus 1 stale confirmation from a member removed via `DeleteMember`.

        self.assert_valid_request(request_id);

            .unwrap_or_else(|| env::panic_str("Must be validated above"));

        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {

            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over

        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    /// Add member to the list. Adds access key if member is key based.
    fn add_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        self.members.insert(&member.clone().into());
        match member {
            MultisigMember::AccessKey { public_key } => promise.add_access_key(
                public_key.into(),
                DEFAULT_ALLOWANCE,
                env::current_account_id(),
                MULTISIG_METHOD_NAMES.to_string(),
            ),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }

    /// Prevents access to calling requests and make sure request_id is valid - used in delete and confirm
    fn assert_valid_request(&mut self, request_id: RequestId) {
        // request must come from key added to contract account
        assert(
            self.current_member().is_some(),
            "Caller (predecessor or signer) is not a member of this multisig",
        );
        // request must exist
        assert(
            self.requests.get(&request_id).is_some(),
            "No such request: either wrong number or already confirmed",
        );
        // request must have
        assert(
            self.confirmations.get(&request_id).is_some(),
            "Internal error: confirmations mismatch requests",
        );
    }
