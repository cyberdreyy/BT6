### Title
`EscrowDst._withdraw()` underflow-revert on maker fee amounts causes maker's revealed secret to be leaked without payout, enabling theft of source-chain funds - (File: contracts/EscrowDst.sol)

### Summary
`BaseEscrowFactory.createDstEscrow()` lets any caller (the resolver/taker) supply arbitrary `Immutables.parameters` (protocol/integrator fee amounts) with no validation against `immutables.amount`. `EscrowDst._withdraw()` then computes `immutables.amount - integratorFeeAmount - protocolFeeAmount` with Solidity 0.8 checked arithmetic. If the fee sum exceeds `amount`, every `withdraw`/`publicWithdraw` call permanently reverts — the same unguarded-subtraction root cause as the Sandclock `totalUnderlyingMinusSponsored()` finding, where a value combination that "has been considered elsewhere" (checked in `_postInteraction`) was not checked in the sibling code path.

### Finding Description
In the source-escrow path, `_postInteraction` explicitly guards against this exact condition: [1](#0-0) 

But `createDstEscrow` builds `Immutables` straight from caller-supplied `dstImmutables` (including the ABI-encoded `parameters` blob that `ImmutablesLib` later decodes as `protocolFeeAmount`/`integratorFeeAmount`) with **no equivalent check**: [2](#0-1) 

`EscrowDst._withdraw()` then performs the unguarded subtraction: [3](#0-2) 

`protocolFeeAmount`/`integratorFeeAmount` are decoded from the same `parameters` bytes the caller passed into `createDstEscrow`: [4](#0-3) 

Because these values are baked into the `Immutables` struct hashed into the escrow's CREATE2 salt (`immutables.hashMem()` at `contracts/BaseEscrowFactory.sol:178`), they cannot be corrected later — every subsequent `withdraw`/`publicWithdraw` call for that clone will use the identical bad numbers and revert.

### Impact Explanation
This is a Medium/High-scope match ("smart contract unable to operate because required token/native balances can be broken by an unprivileged actor" / "theft of coins/tokens meant for transaction fees ... temporary freezing of funds during the live swap lifecycle"), but it also has a Critical tail-risk: when the maker submits `withdraw(secret, immutables)` and the transaction reverts due to the underflow, the plaintext `secret` is exposed in the calldata of the (failed but broadcast/mined) transaction before any payout occurs. Any observer — including the resolver who is `immutables.taker` on the **source chain** — can now call `EscrowSrc.withdraw`/`withdrawTo` with that secret and claim the maker's original funds: [5](#0-4) 
Meanwhile the maker permanently cannot withdraw on the destination side (every call reverts), and once `DstCancellation` elapses, only the taker can reclaim the destination-side balance via `cancel()`, which pays the full amount back to `immutables.taker`, not the maker: [6](#0-5) 
Net effect: the maker loses their source-chain funds (claimed by the resolver using the leaked secret) and never receives destination-chain funds, while the resolver recovers their own escrowed tokens — an unprivileged-actor-triggerable fund loss for the counterparty, matching the report's "malfunction" pattern.

### Likelihood Explanation
The taker/resolver who calls `createDstEscrow` fully controls the `dstImmutables.parameters` payload; nothing on-chain cross-checks these fee fields against the `DstImmutablesComplement.parameters` emitted during `_postInteraction` on the source chain. A resolver (or anyone funding the destination escrow, since funds come from `msg.sender`) can trivially set `protocolFeeAmount + integratorFeeAmount >= amount` at deployment time, and the condition is deterministic and always reproducible for that escrow instance — no privileged role, race condition, or governance action is required.

### Recommendation
Add a check identical in spirit to the `_postInteraction` guard inside `createDstEscrow` (or inside `EscrowDst._withdraw`) before committing to the immutables/salt:
```solidity
uint256 integratorFeeAmount = dstImmutables.integratorFeeAmount();
uint256 protocolFeeAmount = dstImmutables.protocolFeeAmount();
if (integratorFeeAmount + protocolFeeAmount >= dstImmutables.amount) revert InvalidFeeAmounts();
```
placed in `createDstEscrow` before `_deployEscrow` is called, mirroring the existing `_postInteraction` check.

### Proof of Concept
1. Resolver calls `createDstEscrow(dstImmutables, srcCancellationTimestamp)` with `dstImmutables.amount = 1000`, and `parameters` encoding `protocolFeeAmount = 600`, `integratorFeeAmount = 500` (sum = 1100 > 1000). Resolver funds the ERC20 transfer via `safeTransferFrom(msg.sender, escrow, 1000)`. [2](#0-1) 
2. After `DstWithdrawal` stage begins, maker submits `withdraw(secret, immutables)`; `_withdraw` computes `1000 - 500 - 600` → reverts with a panic (arithmetic underflow). [3](#0-2) 
3. The `secret` from the reverted transaction's calldata is now public; the resolver (or any watcher) immediately calls `EscrowSrc.withdraw(secret, srcImmutables)` on the source chain to claim the maker's locked source tokens. [7](#0-6) 
4. After `DstCancellation`, the resolver calls `EscrowDst.cancel()`, recovering their own destination tokens plus safety deposit, while the maker receives nothing on the destination chain and lost their source-chain funds. [6](#0-5)

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    /**
     * @notice Returns the integrator fee amount from the immutables (calldata version).
     * @param immutables The immutables to extract the fee from.
     * @return ret The integrator fee amount.
     */
    function integratorFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x40) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(add(parameters.offset, 0x20))
        }
    }
