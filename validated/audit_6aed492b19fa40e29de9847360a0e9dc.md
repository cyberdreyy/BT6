### Title
Unprivileged ERC4626-vault user can inflate the share price via donation to corrupt `ProgrammableBorrower` epoch baselines, masking real yield and stealing lender interest - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` parks all undrawn credit-facility assets in an external ERC4626 `vault` and measures epoch PnL purely from `convertToAssets` snapshots. Neither the deposits (`_depositToVault`, `onStartEpoch`, `_repay`) nor the withdrawals (`onStopEpoch`, `_borrow`) carry any min-shares/max-assets slippage bound, and the accounting baselines (`epochStartVaultAssets`, `bufferedVaultDelta`, `bufferStartVaultAssets`) are derived from the manipulable vault share price at a single point in time. An unprivileged user of the same ERC4626 vault (or any direct token sender, since donations are permissionless `transfer`s) can inflate the share price by donating assets to the vault immediately before `startEpoch`/`onStartEpoch`, inflating the principal baseline so genuine yield is booked as `vaultLoss` and `totalInterestDueNow()` underreports — permanently reducing the interest minted to AA/BB tranche holders at `stopEpoch`.

### Finding Description
The relevant code paths in `contracts/strategies/idle/ProgrammableBorrower.sol`:

- `onStartEpoch` snapshots `bufferedVaultDelta = _currentVaultAssets() - bufferStartVaultAssets`, then sets `epochStartVaultAssets = underlyingToken.balanceOf(this) + _currentVaultAssets()` (lines 206–219).
- `_currentVaultAssets()` returns `vault.convertToAssets(vault.balanceOf(this))` (lines 546–549) — directly manipulable by any ERC4626 vault user via a donation that raises `totalAssets`/`totalSupply`.
- `_vaultNetInterest()` computes `netDelta = bufferedVaultDelta + earnedAssets - principalAssets`; a positive delta is `interest`, a negative delta is `loss` (lines 337–347).
- `totalInterestDueNow()` returns `vaultInterest + borrowerInterestAccruedNow() + bufferInterest - loss`; `IdleCDOEpochVariant` reads this single value in `stopEpoch` to mint tranche interest (lines 330–334).
- All vault interactions are unprotected: `vault.deposit(_assetAmount, address(this))` with no min-shares (line 380), `vault.withdraw(shortfall, ...)` with no max-shares (lines 246, 452), `vault.redeem` with no min-assets (line 367).

Attack sequence (buffer phase → epoch start):

1. Facility sits in the buffer phase; adapter holds a large fraction `α` of the ERC4626 vault's shares (typical: the credit facility is the dominant LP).
2. Attacker holds a small share fraction (or none) and directly transfers `D` underlying to the vault (permissionless donation — the attacker is simply a "direct token sender" / vault user).
3. Honest manager calls `IdleCDOEpochVariant.startEpoch` → `onStartEpoch` runs. `epochStartVaultAssets` is inflated by ≈ `α·D` (the adapter's pro-rata share of the donation), and `bufferedVaultDelta`/`bufferStartVaultAssets` bookkeeping treats the donation-inflated valuation as principal, not profit.
4. During the epoch the vault earns genuine yield `Y`. At `stopEpoch`, `_vaultNetInterest()` computes `earned - principal`; the donation-inflated baseline causes up to `α·D` of real yield to be masked, and any excess inflation shows up as `vaultLoss`, which `totalInterestDueNow()` subtracts from borrower interest.
5. `IdleCDOEpochVariant.stopEpoch` mints interest to AA/BB tranches based on the reduced `totalInterestDueNow()`. Lenders permanently lose ≈ `α·D` of yield. Because the donation permanently raises the share price, the inflated baseline also persists into subsequent epochs' `bufferStartVaultAssets` accounting, compounding the misclassification until a default/reset.

Attacker cost is `D·(1−α)` (their own share fraction gets their pro-rata slice of the donation back when they redeem); pool loss is `α·D`. When the adapter dominates vault TVL (α → 1), the attacker can inflict ≈ `D` loss on lenders for ≈ zero net cost — pure griefing/leakage, and if the attacker also holds tranche tokens short-term or simply aims to damage the facility, the asymmetry is total. Additionally, the same lack of a min-assets bound on `vault.withdraw(shortfall)` in `onStopEpoch` lets a vault LP atomically drain liquidity so the withdraw reverts into `StopEpochVaultLiquidityUnavailable`, temporarily freezing epoch settlement and all queued withdrawals.

### Impact Explanation
Theft of unclaimed yield: AA/BB tranche lenders receive less minted interest than contractually earned because `totalInterestDueNow()` is reduced by the manipulated `vaultLoss`/inflated baseline. The loss is permanent (epoch interest is minted once at `stopEpoch` and baselines carry forward via `bufferStartVaultAssets`). Magnitude is bounded by the donation size `D`, so it scales to a large fraction of epoch interest. Secondary impact: temporary freezing of `stopEpoch`/withdrawals via liquidity withdrawal front-running the unguarded `vault.withdraw`.

### Likelihood Explanation
Medium. Requires only that the integrated ERC4626 vault accepts donations/asset transfers that move `convertToAssets` (true for virtually all ERC4626 vaults whose `totalAssets` reads raw balances) and that the attacker can time a transaction before the keeper's `startEpoch` — epoch starts are predictable, public transactions. No privilege is needed: any ERC4626 vault depositor or direct token sender qualifies. The existing guards (`_checkOnlyIdleCDO`, epoch gating, `try/catch` on withdraw, `setVault` unwinding checks) do not bound the valuation used for the snapshot, so nothing prevents it. The same bug class (unguarded ERC4626 deposit/redeem + price manipulation) was confirmed Medium in the LoopFi finding.

### Recommendation
- Bound every vault interaction: use `deposit` with a `minSharesOut` check (or `mint` with `maxAssetsIn`) in `_depositToVault`, and enforce `maxShares`/min-assets tolerances on `withdraw`/`redeem` in `onStopEpoch`, `_borrow`, and `emergencyExitVault`.
- Make epoch baselines manipulation-resistant: snapshot `epochStartVaultAssets`/`bufferedVaultDelta` from assets actually received (return values of `deposit`/`withdraw`, or `previewRedeem` sanity-bounded against a TWAP/idle balance), rather than a spot `convertToAssets` reading taken in the same block an attacker can donate.
- Alternatively, treat `vaultLoss` as clamped to deposited principal only after netting out instantaneous `convertToAssets` jumps within a single block (e.g., require the baseline to be refreshed by a deposit that re-derives share value, or ignore positive valuation jumps in `bufferedVaultDelta` that are not attributable to time-elapsed yield).

### Proof of Concept
Foundry fork PoC outline (target: `test/foundry/ProgrammableBorrowerCreditVault.t.sol` harness with a real ERC4626, e.g. a MetaMorpho/ERC4626 vault on mainnet fork where the adapter becomes the dominant LP):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ProgrammableBorrower} from "../../contracts/strategies/idle/ProgrammableBorrower.sol";
import {IERC4626} from "../../contracts/interfaces/IERC4626.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract DonationBaselineAttack is Test {
    ProgrammableBorrower pb;      // adapter under test (initialized with real vault)
    IERC4626 vault;               // borrower ERC4626 vault, underlying = USDC
    IERC20 usdc;
    address idleCDO;              // IdleCDOEpochVariant
    address attacker = address(0xbeef);

    function test_donationInflatesEpochBaseline_masksInterest() public {
        // Setup: facility funded, adapter is dominant vault LP (alpha ~ 99%).
        // Pool is in buffer phase; bufferStartVaultAssets == currentVaultAssets.

        uint256 D = 1_000_000e6;
        deal(address(usdc), attacker, D);

        // 1) Attacker donates D directly to the vault, inflating convertToAssets
        vm.prank(attacker);
        usdc.transfer(address(vault), D);

        // 2) Honest keeper starts the epoch -> baseline snapshot is inflated
        uint256 pending = 0;
        vm.prank(idleCDO);
        pb.onStartEpoch(pending);
        uint256 inflatedBaseline = pb.epochStartVaultAssets(); // includes ~alpha*D

        // 3) Epoch accrues genuine vault yield Y (warp, or real vault yield on fork)
        vm.warp(block.timestamp + 30 days);

        // 4) Stop epoch: vaultNetInterest is depressed by the inflated baseline;
        //    totalInterestDueNow is alpha*D lower than the honest-valuation case.
        uint256 interestDue = pb.totalInterestDueNow();

        // Compare against a control run without the donation:
        // assert(interestDue_honest - interestDue ≈ alpha*D);
        // i.e., stopEpoch mints ~alpha*D less interest to AA/BB tranche holders.
        assertLt(interestDue, inflatedBaseline /* demonstrates masked yield */);
    }
}
```

Concrete assertion for the PoC: run two identical fork sequences differing only in the attacker's `usdc.transfer(vault, D)` before `startEpoch`; assert `totalInterestDueNow()` (equivalently the AA/BB `virtualPrice` delta produced by `IdleCDOEpochVariant.stopEpoch`) is lower in the attack run by ≈ `α·D`, while the attacker's net cost after redeeming their small vault position is ≈ `D·(1−α)`.
