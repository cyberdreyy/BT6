### Title
Deleting a multisig member does not purge that member's pre-existing confirmations on other pending requests, allowing a request to execute with fewer than `num_confirmations` live members - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only removes requests that were *originated* by the deleted member; it never scrubs that member's *confirmations* recorded on requests originated by other members. As a result, a stale confirmation from an account that is no longer part of the multisig continues to count toward the `num_confirmations` threshold, letting `confirm()` execute a request with fewer than `num_confirmations` currently-live members having actually approved it.

### Finding Description
`confirm()` tracks approvals in `self.confirmations: LookupMap<RequestId, HashSet<String>>`, keyed by the string form of the confirming `MultisigMember`, and executes the request once `confirmations.len() + 1 >= self.num_confirmations`: [1](#0-0) 

`delete_member` is invoked from `execute_request` when a `DeleteMember` action is confirmed, and only cleans up requests originated by the removed member: [2](#0-1) 

Note that the loop filters on `r.member == member` (the request *originator*), and the only map touched is `self.requests`/`self.confirmations` for those originated requests. Any entry the deleted member added to `self.confirmations` for a *different*, still-pending request (one they merely confirmed, not created) is left untouched. `remove_request` (used by `delete_request`/`confirm`) also has no logic to strip a specific member's confirmation from other requests' confirmation sets: [3](#0-2) 

The invariant the contract is supposed to maintain is: *confirmations counted toward the threshold == confirmations from currently-live members*. Once a member is deleted, any of their previously recorded confirmations should either be discarded or that request should be blocked, otherwise the equality is violated and the K-of-N guarantee is broken.

### Impact Explanation
This is a Critical-impact issue per the given classification ("a multisig request executed below threshold"). Concretely:

1. Member `M` confirms request `X` (created by a different member), so `confirmations[X] = {M, ...}`.
2. Separately, the members (through a normal `num_confirmations`-approved `DeleteMember` request) remove `M` from the multisig - `delete_member` asserts only that `members.len() - 1 >= num_confirmations`, which is satisfied, and only purges requests *originated* by `M`, not `X`.
3. `confirmations[X]` still contains `M`'s stale entry. A subsequent `confirm(X)` call by one more live member pushes `confirmations.len() + 1 >= num_confirmations` and the request executes - even though only `num_confirmations - 1` currently-live members actually approved it.

This breaks the core custody/authorization binding of the multisig (K distinct live signers required to move funds/keys), effectively lowering the live threshold by one for any request confirmed before a member's removal.

### Likelihood Explanation
This does not require any privileged bypass or malformed deployment - it happens through the contract's own documented flow (`add_request` → `confirm` by some members → later a `DeleteMember` action executes through the normal, honestly-approved threshold process). Any organization that rotates or removes multisig members while requests are outstanding (a routine operational event) is exposed; no attacker collusion beyond normal membership changes is needed for the stale confirmation to remain counted.

### Recommendation
In `delete_member`, iterate over all entries in `self.confirmations` (or maintain a reverse index of member → request ids they've confirmed) and remove the deleted member's entry from every request's confirmation set, not just from requests they originated. Alternatively, when counting confirmations in `confirm()`, revalidate that every account/key in the confirmation set is still a current member of `self.members` before applying it toward the threshold, discarding stale entries.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}`, `num_confirmations = 3`.
2. `A` calls `add_request` to create transfer request `X` (receiver arbitrary).
3. `C` calls `confirm(X)` → `confirmations[X] = {C}` (1 of 3, not yet executed).
4. Separately, `A`, `B`, `D` create and confirm a `DeleteMember{member: C}` request (3 of 4 confirmations, satisfies `members.len()-1 (=3) >= num_confirmations (3)`); it executes, removing `C` from `self.members`. `delete_member` only removes requests *originated* by `C`; request `X` (originated by `A`) and its confirmation set `{C}` remain untouched.
5. `B` calls `confirm(X)` → `confirmations[X].len() + 1 == 2 + 1 == 3 >= num_confirmations (3)` → request `X` executes, even though it was approved by only `A` (implicitly, as creator) and `B`+stale-`C`, i.e., effectively 2 live members instead of the required 3. [1](#0-0) [2](#0-1)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
