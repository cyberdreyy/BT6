This confirms the vulnerability. The `tarzstd` extractor explicitly resolves each entry with `filepath.Join(e.dir, hdr.Name)` and rejects paths that escape `e.dir` via `filepath.Abs` + `strings.HasPrefix` [1](#0-0) , but the zip legacy extractor never does this: `extractor.dir` is stored but never referenced anywhere in `Extract` [2](#0-1) . `archives.ExtractZipArchive` iterates `archive.File` and passes `file.Name` straight into `extractZipFile`, which calls `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile(file.Name, ...)` with the operating-system's own relative-path resolution against the current working directory, with no join against a root, no `filepath.Abs`, and no `HasPrefix`/traversal check [3](#0-2) [4](#0-3) . The only sanitization applied is `errorIfGitDirectory`, which only detects a leading `.git` path component and is unrelated to path traversal [5](#0-4) .

Both `artifacts-downloader` and `cache-extractor` call `os.Getwd()` and pass it as `dir` to `archive.NewExtractor`, then just call `extractor.Extract(ctx)` [6](#0-5) [7](#0-6) . Because zip extraction resolves paths relative to the process CWD (the job's working directory, effectively `dir`) rather than confining to it, an entry name like `../../other-project/workspace/evil.sh` or an absolute path will resolve outside that directory when extracted — the exact same class of bug tarzstd already fixed with its explicit chroot check.

### Title
Zip extractor writes files outside job/cache root due to missing path-containment check - (File: helpers/archives/zip_extract.go)

### Summary
`archives.ExtractZipArchive`/`extractZipFile`, used by the legacy zip extractor (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`), never validates or joins `zip.File.Name` against the extraction root directory (`extractor.dir`), unlike the `tarzstd` extractor which enforces `filepath.Abs` + `strings.HasPrefix` chroot confinement. An attacker who controls the contents of an artifact/cache zip archive can craft entry names containing `../` traversal sequences (or absolute paths) to write files outside the intended extraction directory.

### Finding Description
`extractZipFile` computes only `filepath.Dir(file.Name)` for `MkdirAll` and then opens `file.Name` directly with `os.OpenFile`/`os.Symlink`/`os.Mkdir` — no root directory is ever joined in [8](#0-7) . `ExtractZipArchive` simply loops `archive.File` and calls `extractZipFile(file)` for every entry with no path check besides the unrelated `.git` guard [9](#0-8) . The legacy zip extractor's `Extract` method receives `e.dir` at construction time (from `NewExtractor(r, size, dir)`) but never passes it to `archives.ExtractZipArchive(zr)` [10](#0-9) , so `dir` is dead data for zip extraction. Both `commands/helpers/artifacts_downloader.go` (artifact restore) and `commands/helpers/cache_extractor.go` (cache restore) reach this code path directly with `os.Getwd()` as `dir`, calling `extractor.Extract(context.Background())` on attacker-supplied archive bytes [11](#0-10) [12](#0-11) . This contrasts directly with the `tarzstd` extractor's explicit `filepath.Join(e.dir, hdr.Name)` + `filepath.Abs` + `HasPrefix` boundary check that rejects any entry resolving outside `e.dir` [1](#0-0) , proving the containment check is a known, intentional pattern that is simply absent for zip.

### Impact Explanation
An unprivileged job that produces an artifact or cache archive (its own job output, later restored by a subsequent job/pipeline on the same runner host/executor) can embed a zip entry named with `../` traversal or an absolute path. When that archive is downloaded and extracted by `artifacts-downloader` or `cache-extractor` in a later job, `os.OpenFile`/`os.Mkdir`/`os.Symlink` will write/overwrite files outside the job's working directory — e.g., into a sibling project's checkout, shared build/cache root, or other runner-managed paths on the same host/executor. This is a cross-project file write / build state poisoning vulnerability limited to zip-format artifacts/caches (the `ZipZstd` format uses the same `NewExtractor`, so it is affected too).

### Likelihood Explanation
Feasible and fully attacker-controlled: any pipeline author can control artifact/cache paths and, since the archiver builds the zip stream from the job's file listing, can also directly forge a raw zip via `zip.Writer` (bypassing the runner-side archiver) since the artifact upload endpoint accepts the archive bytes, not validated per-entry names before storage. As long as the crafted zip is later restored via `ArtifactsDownloaderCommand.Execute` or `CacheExtractorCommand.Execute` on a shared host/executor (shell/docker executors reusing a build root), the traversal write is deterministic and repeatable with a simple unit test.

### Recommendation
Apply the same containment logic used in `tarzstd_extractor.go` to the zip path: pass `extractor.dir` into `archives.ExtractZipArchive` (or a new variant), and for every `file.Name`, compute `path := filepath.Join(dir, file.Name)`, verify via `filepath.Abs` + `strings.HasPrefix(path, dir+string(filepath.Separator))` (or `filepath.Rel` + check for `..` prefix) before any `MkdirAll`/`OpenFile`/`Symlink` call, rejecting or skipping entries that escape the root.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
