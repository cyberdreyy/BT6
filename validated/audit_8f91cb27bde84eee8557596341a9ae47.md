### Title
Stale node response merged into ID-reused activeRequest without method/binding check enables cross-request bundle contamination - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`h.getActiveRequest(resp.ID)` in `HandleNodeMessage` binds an incoming node response to an `activeRequest` using only the `resp.ID` string, with no check that `resp.Method` matches `ar.req.Method` (the method of the request currently occupying that ID slot). Because `req.ID` is fully attacker/caller-controlled and the `activeRequests` map is a single shared namespace for the whole handler (not scoped per-caller), a stale/late node response belonging to a completed request can be merged into a newer, different-method (or different-caller) request that later reused the same ID.

### Finding Description
`newActiveRequest` only rejects an ID that is *currently* present in `h.activeRequests`: [1](#0-0) . Once a request completes, `sendResponseAndClearRequest` deletes it from the map, freeing the ID for reuse: [2](#0-1) .

`HandleNodeMessage` looks up the active request purely by `resp.ID`, with no comparison of `resp.Method` to `ar.req.Method` before calling `ar.addResponseForNode` and `h.bundler.Bundle(ar.req, ...)`: [3](#0-2) . `addResponseForNode` dedups only on `nodeAddr`, not on method or any per-request token: [4](#0-3) .

`bundler.Bundle` then decodes every collected response strictly according to `ar.req.Method` (the *current* occupant's method), never checking the individual response's own `Method` field: [5](#0-4) . If a stale response (e.g., originally answering `MethodSecretsGet` for ID `X`) arrives after a new `MethodCapabilityExec` request registers under the same ID `X`, it is merged into the new request's response set and blindly `json.Unmarshal`'d into the new method's expected result type. Only a hard decode failure is filtered out (marked "undecodable"); any accidental structural compatibility between the two result schemas would let contaminated content silently enter the bundle sent back through `forwardBundle` to the enclave/subscriber.

The `activeRequests` map is also not namespaced per authenticated caller — any two unrelated unprivileged callers hitting the same DON/service can pick colliding IDs, so this is not limited to a single caller reusing their own ID; a genuine cross-caller race is possible if IDs happen to collide (deliberately, by a low-privilege attacker probing for common/likely ID values, or accidentally).

I could not confirm the exact field-level structural overlap between `SignedSecretsResponseResult` and `SignedCapabilityResponseResult` (defined in the external `chainlink-common` module, not indexed here), so I cannot conclusively prove that a cross-method decode would *silently succeed* rather than fail as "undecodable." This is the key open uncertainty for full exploitability of "wrong-content delivery"; the missing `resp.Method`/binding check itself, however, is confirmed and reproducible regardless of that schema detail.

### Impact Explanation
If the schemas overlap enough for a cross-method unmarshal to succeed, this results in delivery of a bundle containing signed relay data that does not correspond to the requesting subscriber's actual request (cross-user/cross-request response confusion), which matches the "attacker-controlled data returned to another user" / cross-user confidential data exposure class. Even absent silent decode success, the missing binding check is a structural defect: request completion is asserted purely by string ID equality without validating that the response actually answers the request the caller is waiting on, which is the exact invariant the question asks about and which the code does not enforce. The final enclave-side signature verification (noted in code comments) is the actual trust boundary and may catch a wrong-payload response before it is acted upon, which limits worst-case impact but is not itself a gateway-level defense the question is scoped to.

### Likelihood Explanation
Exploitability requires: (1) attacker-controlled or accidentally-colliding `req.ID` across two different-method (or different-caller) requests submitted in quick succession, and (2) a genuine timing race — a node response for the first request must still be in flight when it lands after the second request registers. This is a narrow race window dependent on node/network latency and is not fully attacker-controlled (the attacker cannot force a specific node's stale reply to arrive at a specific instant), making it opportunistic rather than reliably reproducible on demand, though repeatable attempts over time increase the chance of a hit.

### Recommendation
Bind node responses to the exact originating request, not just its ID: store the expected `Method` (and ideally a random per-registration nonce/generation counter) in `activeRequest` at `newActiveRequest`, and in `HandleNodeMessage` reject/drop any `resp` whose `Method` does not match `ar.req.Method` before calling `addResponseForNode`/`Bundle`. Additionally consider incrementing a generation counter each time an ID is reused so that responses tagged with a stale generation are dropped even for same-method collisions.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Submit `req1 := {ID: "X", Method: MethodSecretsGet}`; complete it via enough signed node responses so it is deleted from `h.activeRequests` (confirm with `h.getActiveRequest("X") == nil`).
2. Immediately submit `req2 := {ID: "X", Method: MethodCapabilityExec}` with a fresh callback `cb2`.
3. Deliver a `HandleNodeMessage` call using a node address that has not yet responded to `req2`, with a response whose `ID == "X"` and `Result` shaped as a `SignedSecretsResponseResult` (simulating a straggler reply to `req1`).
4. Assert either: (a) the handler logs/rejects this response due to method mismatch (after fix), or (b) currently (pre-fix) the response is accepted into `req2`'s `responses` map (`ar.addResponseForNode` returns `true`), and `Bundle` either marks it `undecodable` or — the vulnerable case — successfully decodes it into a `SignedCapabilityResponseResult`, producing contaminated content in `cb2`'s eventual bundle.
5. Assert that after the fix, a response count / bundle composition for `req2` never includes entries whose underlying node response `Method` differs from `MethodCapabilityExec`.

func (ar *activeRequest) addResponseForNode(nodeAddr string, resp *jsonrpc.Response[json.RawMessage]) bool {
	ar.mu.Lock()
	defer ar.mu.Unlock()
	_, exists := ar.responses[nodeAddr]
	if exists {
		return false
	}

	ar.responses[nodeAddr] = resp
	return true
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

	copiedResponses := ar.copiedResponses()
	// Bundle readiness counts decodable signed responses, while the enclave remains
	// responsible for signature and quorum verification. A collected response cannot
	// be replaced by a later response from the same node.
	summary, err := h.bundler.Bundle(ar.req, copiedResponses, l)
	if err != nil {
		l.Errorw("failed to build relay response bundle", "error", err)
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, err))
	}
	return h.forwardBundleOrTerminateIfReady(ctx, l, ar, summary, len(h.donConfig.Members)-summary.Total(), false)

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}

func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedCapabilityResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable capability response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedCapabilityResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode capability response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	default:
		return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)
	}
}
