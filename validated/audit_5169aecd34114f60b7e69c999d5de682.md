### Title
Unbounded growth of the `vote_accounts` map allows a single `getVoteAccounts` RPC call to incur unbounded CPU/allocation cost - (File: rpc/src/rpc.rs)

### Summary
The `getVoteAccounts` JSON-RPC method iterates and fully decodes every entry in `Bank::vote_accounts()`, a map that grows unboundedly because any unprivileged user can create a new vote account for the cost of a rent-exempt deposit. There is no limit on the number of vote accounts that can exist, and no pagination/limit parameter on the RPC method, so a single call's cost scales linearly (and non-trivially, due to per-account VoteStateView decoding) with however many vote accounts have ever been created network-wide.

### Finding Description
`JsonRpcRequestProcessor::get_vote_accounts` calls `bank.vote_accounts()` and then does a `.iter().filter_map(...)` over the entire resulting `VoteAccountsHashMap`, decoding a `vote_state_view()` and building an `RpcVoteAccountInfo` (including bounded epoch-credits history) for every single account, with no limit on the number of entries processed: [1](#0-0) 

`Bank::vote_accounts()` simply returns the full in-memory map maintained by the `StakesCache`: [2](#0-1) 

That cache is populated by `StakesCache::check_and_store`, which upserts *any* account owned by the vote program with a validly-sized, initialized `VoteStateVersions` blob into the `vote_accounts` map — this does not require any stake delegation, and any user can trigger it simply by creating and initializing a vote account (a permissionless operation that only costs the rent-exempt minimum balance for the vote state size): [3](#0-2) 

The `vote_account::VoteAccounts::insert` path shows entries are simply inserted with no cap on total count: [4](#0-3) 

While `MAX_RPC_VOTE_ACCOUNT_INFO_EPOCH_CREDITS_HISTORY` bounds the per-account `epoch_credits` returned, it does not bound the *number of vote accounts* iterated, and there's no limit/pagination parameter accepted by `RpcGetVoteAccountsConfig` (aside from `vote_pubkey`, which is optional and does not reduce the scan cost since filtering happens inside the iterator, after the map is already built): [5](#0-4) 

This is directly analogous to the reported bug class: an externally, permissionlessly growable collection ("pools" in the external report; vote accounts here) with no upper bound, that is fully iterated within a single request/transaction ("claimCalculation"/"getCurrentShareRaw" in the report; `getVoteAccounts` here), leading to unbounded per-call cost.

### Impact Explanation
Because the total number of vote accounts on a live cluster can grow without bound (limited only by the economic cost of rent-exempt deposits, which is a modest, one-time, recoverable cost since accounts can later be closed for a refund), a single `getVoteAccounts` call can be made arbitrarily expensive in CPU time and memory allocation for the RPC node serving it, degrading or denying RPC service availability to legitimate clients on that node. This does not crash the validator's core consensus path, but can significantly degrade or deny RPC responsiveness from a single, unprivileged, single-shot call.

### Likelihood Explanation
Low-to-medium: an attacker must first spend real capital to create a large number of vote accounts (each requiring the rent-exempt deposit for `VoteStateV4::size_of()`), which is a real but recoverable cost (the deposit can later be reclaimed by closing the vote account). Once created, a single `getVoteAccounts` call is enough to trigger the full unbounded scan/decode cost repeatedly at no further cost to the attacker.

### Recommendation
Add server-side pagination/limit and/or a maximum vote-account count cap to `getVoteAccounts` (and any other RPC surface that iterates the full `vote_accounts` map), similar to the existing `MAX_GET_INFLATION_REWARD_ADDRESSES`/`MAX_GET_PROGRAM_ACCOUNT_FILTERS` bounds already used elsewhere in `rpc/src/rpc.rs`, so a single request's cost cannot scale unboundedly with the number of vote accounts ever created.

### Proof of Concept
1. Using a funded keypair, repeatedly execute `CreateAccount` + `VoteInit`/`VoteInitV2` instructions (as done in `cli/src/vote.rs::process_create_vote_account`, lines 911-1007) to create a large number (e.g., tens of thousands) of minimally-funded vote accounts.
2. Each created vote account is permissionlessly upserted into the bank's `vote_accounts` map via `StakesCache::check_and_store` (`runtime/src/stakes.rs` lines 117-135) — no delegated stake is required.
3. Issue a single `getVoteAccounts` JSON-RPC request against the target validator/RPC node.
4. Observe that `JsonRpcRequestProcessor::get_vote_accounts` (`rpc/src/rpc.rs` lines 1155-1246) must iterate, decode, and allocate a response entry for every one of the created vote accounts in that single call, causing CPU/memory usage that scales with the total number of vote accounts created, degrading RPC responsiveness for that call and potentially for others sharing the same RPC threadpool.

    fn get_vote_accounts(
        &self,
        config: Option<RpcGetVoteAccountsConfig>,
    ) -> Result<RpcVoteAccountStatus> {
        let config = config.unwrap_or_default();

        let filter_by_vote_pubkey = if let Some(ref vote_pubkey) = config.vote_pubkey {
            Some(verify_pubkey(vote_pubkey)?)
        } else {
            None
        };

        let bank = self.bank(config.commitment);
        let commission_rate_in_basis_points = bank
            .feature_set
            .is_active(&agave_feature_set::commission_rate_in_basis_points::id());
        let vote_accounts = bank.vote_accounts();
        let epoch_vote_accounts = bank
            .epoch_vote_accounts(bank.get_epoch_and_slot_index(bank.slot()).0)
            .ok_or_else(Error::invalid_request)?;
        let delinquent_validator_slot_distance = config
            .delinquent_slot_distance
            .unwrap_or(DELINQUENT_VALIDATOR_SLOT_DISTANCE);
        let (current_vote_accounts, delinquent_vote_accounts): (
            Vec<RpcVoteAccountInfo>,
            Vec<RpcVoteAccountInfo>,
        ) = vote_accounts
            .iter()
            .filter_map(|(vote_pubkey, (activated_stake, account))| {
                if let Some(filter_by_vote_pubkey) = filter_by_vote_pubkey
                    && *vote_pubkey != filter_by_vote_pubkey
                {
                    return None;
                }

                let vote_state_view = account.vote_state_view();
                let last_vote = vote_state_view.last_voted_slot().unwrap_or(0);
                let num_epoch_credits = vote_state_view.num_epoch_credits();
                let epoch_credits = vote_state_view
                    .epoch_credits_iter()
                    .skip(
                        num_epoch_credits
                            .saturating_sub(MAX_RPC_VOTE_ACCOUNT_INFO_EPOCH_CREDITS_HISTORY),
                    )
                    .map(Into::into)
                    .collect();

                Some(RpcVoteAccountInfo {
                    vote_pubkey: vote_pubkey.to_string(),
                    node_pubkey: vote_state_view.node_pubkey().to_string(),
                    activated_stake: *activated_stake,
                    commission: if commission_rate_in_basis_points {
                        // Derive percent from native bps, clamping to u8::MAX.
                        let bps = vote_state_view.inflation_rewards_commission();
                        bps.div_ceil(100).min(u8::MAX as u16) as u8
                    } else {
                        vote_state_view.commission()
                    },
                    inflation_rewards_commission_bps: Some(if commission_rate_in_basis_points {
                        vote_state_view.inflation_rewards_commission()
                    } else {
                        vote_state_view.commission() as u16 * 100
                    }),
                    root_slot: vote_state_view.root_slot().unwrap_or(0),
                    epoch_credits,
                    epoch_vote_account: epoch_vote_accounts.contains_key(vote_pubkey),
                    last_vote,
                })
            })
            .partition(|vote_account_info| {
                if bank.slot() >= delinquent_validator_slot_distance {
                    vote_account_info.last_vote > bank.slot() - delinquent_validator_slot_distance
                } else {
                    vote_account_info.last_vote > 0
                }
            });

    pub fn insert(
        &mut self,
        pubkey: Pubkey,
        new_vote_account: VoteAccount,
        calculate_stake: impl FnOnce() -> u64,
    ) -> Option<VoteAccount> {
        let vote_accounts = Arc::make_mut(&mut self.vote_accounts);
        match vote_accounts.entry(pubkey) {
            Entry::Occupied(mut entry) => {
                // This is an upsert, we need to update the vote state and move the stake if needed.
                let (stake, old_vote_account) = entry.get_mut();

                if let Some(staked_nodes) = self.staked_nodes.get_mut() {
                    let old_node_pubkey = old_vote_account.node_pubkey();
                    let new_node_pubkey = new_vote_account.node_pubkey();
                    if new_node_pubkey != old_node_pubkey {
                        // The node keys have changed, we move the stake from the old node to the
                        // new one
                        Self::do_sub_node_stake(staked_nodes, *stake, old_node_pubkey);
                        Self::do_add_node_stake(staked_nodes, *stake, *new_node_pubkey);
                    }
                }

                // Update the vote state
                Some(mem::replace(old_vote_account, new_vote_account))
            }
            Entry::Vacant(entry) => {
                // This is a new vote account. Use the caller-provided stake for the initial
                // cache entry.
                let (stake, vote_account) = entry.insert((calculate_stake(), new_vote_account));
                if let Some(staked_nodes) = self.staked_nodes.get_mut() {
                    Self::do_add_node_stake(staked_nodes, *stake, *vote_account.node_pubkey());
                }
                None
            }
        }
