## Title
Cross-workflow response cross-talk via requestID reuse and un-scoped callbacks map key - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The `httpTriggerHandler` keys its in-flight request state solely by the client-supplied `requestID` string, with no binding to the workflow ID or session that created it [1](#0-0) . Because `cleanupCallback` immediately frees the ID for reuse the instant a shard reaches quorum [2](#0-1) , a straggler node response for the just-completed request can be delivered into a brand-new, unrelated request that reused the same ID, causing the wrong caller to receive data/quorum votes belonging to a different workflow execution.

### Finding Description
`setupCallback` only rejects a `requestID` if it is currently *in-flight* in `h.callbacks`; it performs no durable/quarantine tracking of previously used IDs [3](#0-2) . As soon as one shard's `IdenticalNodeResponseAggregator` reaches quorum, `HandleNodeTriggerResponse` calls `h.cleanupCallback(resp.ID)`, which deletes the map entry and closes `doneCh`, immediately freeing that `requestID` for reuse by anyone [4](#0-3) .

Because threshold-based quorum (`(N+F)//2+1`) does not require *all* nodes to respond, when quorum is reached for request A there can still be up to `F`-ish node responses for A "in flight" over the network [5](#0-4) . If a new request B reuses the same `requestID` X before those stragglers arrive, `HandleNodeTriggerResponse` will look up `h.callbacks[X]`, find B's freshly-created `savedCallback` (new `responseAggregators`, new `doneCh`, and B's `Callback`), and route the late A response into it purely based on `nodeAddr -> shard.donID` membership — a check that is global/per-shard, not per-request and not workflow-aware [6](#0-5) . If that node's shard is also assigned to workflow B, the stale A response is accepted into B's aggregator as a legitimate vote (`agg.CollectAndAggregate`) [7](#0-6) . Enough coincidental/stale votes carrying A's response digest can drive B's aggregator to quorum using A's data, and `saved.SendResponse` will deliver workflow A's result to workflow B's actual requester via `saved.Callback`, which is now bound to B [8](#0-7) . At minimum, the stale vote silently pollutes B's aggregator state for that node address until the node's genuine response for B arrives (which self-heals per-node via `nodeToResponse` bookkeeping in the aggregator), but the cross-request/cross-workflow write into another caller's live aggregator and doneCh is itself the isolation violation.

No auth/role check protects against this because the flaw is purely in server-side per-request state indexing — the `requestID` is caller-chosen and there is no requirement it be unique across time, and no verification that a node's response for ID X actually corresponds to the workflow currently registered under X.

### Impact Explanation
This is a cross-user/cross-workflow response confusion: a caller (B) can receive callback data/aggregation votes attributable to a different, unrelated workflow execution (A), violating per-request isolation. In the worst case this leaks another workflow's node response content to an unrelated requester, matching the "cross-user response confusion" bounty class. It requires favorable timing/shard overlap rather than always being reliably reproducible with attacker-controlled payload content, since aggregation still needs enough colliding response digests to reach threshold within B's aggregator.

### Likelihood Explanation
The attacker only needs unauthenticated/low-privilege ability to submit signed gateway trigger requests with a chosen `requestID`, submit request A, then immediately resubmit the same ID as request B. Actual exploitation to full data leakage additionally requires: (1) at least one straggler node response for A still in flight when B's callback is set up, and (2) that node's shard also assigned to workflow B (higher likelihood when few shards/DONs exist, e.g., single-shard deployments, which is common). Partial impact (aggregator vote pollution for one node) is reliably reproducible with just tight timing; full misdelivery of a wrong response is timing/topology-dependent, lowering but not eliminating real-world likelihood.

### Recommendation
Bind callback state to more than the bare `requestID`: derive the callback map key from `(requestID, workflowID)` or from the previously-generated `legacyExecutionID`/`executionIDWithTriggerIndex`, and validate incoming node responses against the workflow/execution context that node was actually sent, not just shard membership. Additionally, quarantine recently-used `requestID`s for a grace period after `cleanupCallback` (e.g., track a short-lived "recently completed" set) so late node responses for a retired ID are dropped instead of being matched against a newly reused ID.

### Proof of Concept
Go table/integration test outline (extending `TestHttpTriggerHandler_HandleNodeTriggerResponse` in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler_test.go`):
1. Configure a handler with a single shard shared by two distinct workflows, workflowA and workflowB, threshold=3, N=4 (so 1 straggler node remains after quorum).
2. Submit `HandleUserTriggerRequest` for workflowA with `req.ID = "X"`.
3. Deliver 3 of 4 node responses for A (quorum reached) — verify `cleanupCallback` fires and `h.callbacks["X"]` no longer contains A's entry.
4. Before delivering the 4th (straggler) node response for A, submit `HandleUserTriggerRequest` for workflowB reusing `req.ID = "X"`, and drive its own node responses to just below B's threshold.
5. Deliver the straggler A response for `req.ID = "X"` and assert it is accepted into B's aggregator (`err == nil`, no "callback not found"), demonstrating cross-request contamination — the test should assert either (a) B's `saved.responseAggregators` vote count for that node reflects A's stale content, or (b) if driven to threshold, that B's callback (`callback.Wait`) receives `RawResponse` equal to A's response payload instead of B's own, proving misdelivery.

```go
// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}
```

```go
func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
	aggResp, err := agg.CollectAndAggregate(resp, nodeAddr)
	if err != nil {
		return err
	}
```

```go
func (agg *IdenticalNodeResponseAggregator) CollectAndAggregate(
	resp *jsonrpc.Response[json.RawMessage],
	nodeAddress string) (*jsonrpc.Response[json.RawMessage], error) {
	if resp == nil {
		return nil, errors.New("response cannot be nil")
	}
	if nodeAddress == "" {
		return nil, errors.New("node address cannot be empty")
	}

	key, err := resp.Digest()
	if err != nil {
		return nil, fmt.Errorf("error generating digest for response: %w", err)
	}

	// Check if the node already submitted a different response
	if oldKey, exists := agg.nodeToResponse[nodeAddress]; exists && oldKey != key {
		if nodes, ok := agg.responses[oldKey]; ok {
			nodes.Remove(nodeAddress)
			// Clean up empty response groups
			if len(nodes) == 0 {
				delete(agg.responses, oldKey)
			}
		}
	}

	if _, ok := agg.responses[key]; !ok {
		agg.responses[key] = make(StringSet)
	}
	agg.responses[key].Add(nodeAddress)
	agg.nodeToResponse[nodeAddress] = key

	if len(agg.responses[key]) >= agg.threshold {
		return resp, nil
	}

	return nil, nil
```
