### Title
Path traversal via symlink in workflow artifact file fetcher - (File: core/services/workflows/syncer/v2/fetcher.go)

### Summary
The reported HackerOne issue is a classic static-file-server symlink path-traversal: a base-directory containment check is performed on the raw request path, but the file server then follows a symlink located inside the served directory to read/serve a file located outside the intended root. `newFileFetcher` in `core/services/workflows/syncer/v2/fetcher.go` implements the same anti-pattern for Chainlink's CRE workflow artifact fetcher.

### Finding Description
`NewFetcherFunc` builds a `file://`-scheme fetcher whose inner closure `newFileFetcher` is responsible for reading workflow binary/config artifacts from a configured `basePath`: [1](#0-0) 

The containment check only does a **string prefix comparison** on `filepath.Clean(u.Path)`/`filepath.Join(basePath, fullPath)`: [2](#0-1) 

It never calls `filepath.EvalSymlinks` or otherwise resolves the real, final path before deciding whether it is inside `basePath`. It then calls `os.ReadFile(fullPath)` directly, which transparently follows any symlink encountered on the path — including a symlink that resides *inside* `basePath` but whose target points *outside* of it. As long as the symlinked file name/path itself lexically starts with `basePath+separator`, the prefix check passes even though the data actually returned comes from an arbitrary location on disk.

The `req.URL` value driving `fullPath` originates from the `BinaryURL`/`ConfigURL` fields of an on-chain `WorkflowRegistered` event, which are supplied verbatim by the (unprivileged) workflow owner when registering a workflow: [3](#0-2) [4](#0-3) 

The existing regression tests only verify the `../../../etc/passwd`-style traversal is rejected; they do not cover symlink-based escape, confirming the containment logic is purely lexical: [5](#0-4) 

### Impact Explanation
If a node operator enables the local/dev `file://` artifact fetcher (allowed by config validation, which explicitly permits the `file` scheme) and the artifact directory (`basePath`) contains, or an attacker can otherwise cause the creation of, a symlink pointing outside that directory, an unprivileged workflow-owner-controlled `BinaryURL`/`ConfigURL` can be crafted to reference that symlink path and cause the node to read and treat arbitrary files on the node's filesystem (secrets, keys, other workflow artifacts) as workflow binary/config content. This is a disclosure/confused-deputy primitive rather than remote code execution by itself, matching the Medium severity of the original report.

### Likelihood Explanation
This requires: (1) the node operator to configure `WorkflowFetcher.URL`/an equivalent `file://` fetcher (which is explicitly allowed per `WorkflowFetcherConfig.ValidateConfig`), and (2) a symlink already present under `basePath` pointing outside of it. Because the fetcher's containment check is purely a string prefix over the cleaned/joined path with no `EvalSymlinks` resolution, any such symlink is silently followed. The `basePath+string(filepath.Separator)` prefix check is otherwise identical in structure to the vulnerable pattern from the reported `public` npm module, so the root cause is directly analogous, though real-world exploitability depends on the operator's directory layout/deployment mode (the `file://` fetcher appears intended mainly for local/dev CRE usage rather than the default production gateway-based fetch path).

### Recommendation
In `newFileFetcher` (core/services/workflows/syncer/v2/fetcher.go), resolve the final path with `filepath.EvalSymlinks` (or `os.Lstat`-walk each path component) before performing the `basePath` containment check, and re-verify containment against the resolved real path, not the lexical one. Reject the request if `EvalSymlinks` fails or the resolved path escapes `basePath`.

### Proof of Concept
1. Configure a node with the local file-based workflow fetcher, e.g. `WorkflowFetcher.URL = "file:///var/chainlink/artifacts"`.
2. As an unprivileged workflow owner, ensure/rely on a symlink existing at `/var/chainlink/artifacts/evil -> /etc/passwd` (or any path an attacker can otherwise get placed under the served directory, e.g. via a previous artifact write primitive).
3. Register a workflow on-chain with `BinaryURL = "file:///var/chainlink/artifacts/evil"`.
4. When the node calls `FetchWorkflowArtifacts`, `newFileFetcher` computes `fullPath = /var/chainlink/artifacts/evil`, which passes the `strings.HasPrefix(fullPath, basePath+separator)` check, and `os.ReadFile` follows the symlink, returning the contents of `/etc/passwd` (or any file the symlink target points to) as if it were the workflow binary.

```go
func newFileFetcher(basePath string, lggr logger.Logger) types.FetcherFunc {
	return func(ctx context.Context, messageID string, req ghcapabilities.Request) ([]byte, error) {
		select {
		case <-ctx.Done():
			return nil, ctx.Err()
		default:
		}

		// the incoming request URL is expected to be a relative path or a path within the basePath
		if req.URL == "" {
			return nil, errors.New("request URL cannot be empty")
		}
		u, err := url.Parse(req.URL)
		if err != nil {
			return nil, fmt.Errorf("invalid URL: %w", err)
		}
		// Confidential workflows register with HTTP URLs (for the enclave).
		// Extract the filename so the file fetcher can find the local copy.
		if u.Scheme == "http" || u.Scheme == "https" {
			u.Path = filepath.Base(u.Path)
			if u.Path == "." || u.Path == "/" {
				return nil, errors.New("HTTP URL has no filename in path")
			}
		}
		fullPath := filepath.Clean(u.Path)

		// ensure that the incoming request URL is either relative or absolute but within the basePath
		if !filepath.IsAbs(fullPath) {
			// If it's not absolute, we assume it's relative to the basePath
			fullPath = filepath.Join(basePath, fullPath)
		}
		if !strings.HasPrefix(fullPath, basePath+string(filepath.Separator)) && fullPath != basePath {
			return nil, fmt.Errorf("request URL %s is not within the basePath %s", fullPath, basePath)
		}

		lggr.Debugw("Fetching file", "messageID", messageID, "path", fullPath, "workflowID", req.WorkflowID)

		data, err := os.ReadFile(fullPath)
		if err != nil {
			return nil, fmt.Errorf("failed to read file: %w", err)
		}
		return data, nil
	}
```
