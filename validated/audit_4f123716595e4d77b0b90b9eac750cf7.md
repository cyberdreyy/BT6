### Title
Zip legacy extractor path traversal via unsanitized `zip.File.Name` — no chroot/dir confinement - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive`/`extractZipFile` in `helpers/archives/zip_extract.go` write archive entries using the raw `file.Name` from the zip with no join against or validation against a destination root, and the `dir` field passed to `ziplegacy.NewExtractor` is stored but never used in `extractor.Extract` in `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`. This is inconsistent with the `tarzstd` extractor, which explicitly resolves each entry with `filepath.Join(e.dir, hdr.Name)` and rejects paths that escape `e.dir` via a `strings.HasPrefix` check.

### Finding Description
The call chain is: `ArtifactsDownloaderCommand.Execute` (or the cache extractor equivalent) → `archive.NewExtractor(format, f, size, wd)` → `ziplegacy.NewExtractor(r, size, dir)` → `extractor.Extract(ctx)` → `archives.ExtractZipArchive(zr)` → `extractZipFile(file)` → `os.OpenFile(file.Name, ...)`. [1](#0-0) [2](#0-1) [3](#0-2) 

`extractor.dir` is stored on the struct but `Extract` never references `e.dir`; it only builds `zip.NewReader` and calls `archives.ExtractZipArchive(zr)`, passing no root at all. [4](#0-3) 

Inside `extractZipFile`, the code does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then `os.OpenFile(file.Name, ...)` directly using the attacker-supplied `zip.File.Name` string, with no `filepath.Join` against a root, no `filepath.Abs`, and no prefix check. [5](#0-4) 

Compare this to `tarzstd_extractor.go`, which computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and then enforces `strings.HasPrefix(path, e.dir+string(filepath.Separator))`, rejecting any entry that would escape `e.dir`. [6](#0-5) 

The zip path has no equivalent guard. `errorIfGitDirectory` only checks for `.git` directory names to warn about overwriting Git metadata — it is unrelated to path traversal and does not block `../` sequences.

Because the extractor is invoked with the process's current working directory as `wd` (set to the job's working directory) but that value is silently dropped, a `zip.File.Name` value such as `../../../other-project/workspace/evil.sh` (or an absolute path like `/etc/cron.d/x`) is passed straight into `os.OpenFile`/`os.MkdirAll`, causing writes relative to the current working directory rather than any enforced root — since Go's `os.OpenFile` honors `..` segments and absolute paths verbatim.

The attacker-controlled input is the artifact/cache zip content itself: a job author fully controls the artifact or cache archive uploaded by their own job (via `artifacts:paths`, `artifacts:name`, cache keys, etc., or by hand-crafting the zip using the `zip.Writer` API which does not sanitize the `Name` field). When that archive is later downloaded and extracted by `ArtifactsDownloaderCommand` or the cache extractor on a subsequent job/pipeline (potentially on a shared runner host/executor), the malicious entry name causes writes outside the intended extraction root.

### Impact Explanation
On shared runner hosts/executors (e.g., shell executor, or any executor where the working directory tree for different jobs/projects share a filesystem namespace), a job can craft a zip artifact/cache with an entry name containing `../` traversal or an absolute path to write files outside its own job/cache root — e.g., into another project's checkout directory, into the runner's cache directory for another job, or into shared helper/state paths. This is a path/file-write confinement violation exactly matching the "File operations must stay within intended build/cache/artifact roots" invariant, and is the pattern the `tarzstd` extractor already defends against but the zip legacy extractor does not.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged job author's control: they only need to be able to trigger an artifact upload or cache save whose content is later extracted via the zip/zipzstd format path (`archive.Zip`/`archive.ZipZstd`, which are registered to `ziplegacy.NewExtractor`), and have that archive extracted later (their own subsequent job, or a downstream job/pipeline on the same host, depending on GitLab cache/artifact sharing scope and runner scheduling). Crafting a zip entry with a `..`-containing name is a standard, well known zip-slip technique and can be done directly with Go's `archive/zip` writer since it does not validate `Name`. This is a straightforward, repeatable, well-understood class of bug (CWE-22 "zip slip").

### Recommendation
In `helpers/archives/zip_extract.go`, thread the destination directory (`dir`) through `ExtractZipArchive`/`extractZipFile` (mirroring `ziplegacy.extractor.dir`, which is currently unused) and, for every `file.Name`, compute `path := filepath.Join(dir, file.Name)`, verify with `filepath.Abs` + `strings.HasPrefix(path, dir+string(filepath.Separator))` (or equivalent) that the resolved path stays within `dir`, and reject/skip entries that fail the check — matching the guard already implemented in `commands/helpers/archive/tarzstd/tarzstd_extractor.go`. Also normalize/reject zip entries with absolute paths.

### Proof of Concept
```go
func TestZipLegacyExtractor_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir()

    // Build a malicious zip with an entry escaping tmpDir via traversal.
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    relTraversal, _ := filepath.Rel(tmpDir, filepath.Join(outsideDir, "evil.txt"))
    w, err := zw.Create(relTraversal) // e.g. "../<outsideDirBase>/evil.txt"
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    oldWd, _ := os.Getwd()
    defer os.Chdir(oldWd)
    require.NoError(t, os.Chdir(tmpDir))

    r := bytes.NewReader(buf.Bytes())
    ext, err := ziplegacy.NewExtractor(r, int64(r.Len()), tmpDir)
    require.NoError(t, err)
    err = ext.Extract(context.Background())
    require.NoError(t, err)

    // Assert the malicious file landed OUTSIDE tmpDir (in outsideDir),
    // proving no chroot confinement is enforced.
    escaped := filepath.Join(outsideDir, "evil.txt")
    _, statErr := os.Stat(escaped)
    require.NoError(t, statErr, "expected file to escape extraction root, confirming missing path confinement")
}
```
Expected result today: the assertion passes (file escapes), demonstrating the missing chroot/path-confinement check. After applying the recommended fix (join + prefix check like `tarzstd`), `Extract` should instead return an error and the file must not be created outside `tmpDir`.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
