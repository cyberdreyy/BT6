### Title
Unauthenticated forwarding of attacker-controlled POST body to internal plugin pprof symbol endpoint - (File: core/web/loop_registry.go)

### Summary
The `/plugins/:name/debug/pprof/symbol` route and its sibling loop routes (`/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`) are registered on the bare `api` group with no authentication middleware, unlike every other sensitive route group in `router.go`. This lets any unauthenticated network caller forward requests, including a POST body, to the internal LOOP plugin's pprof endpoints.

### Finding Description
In `core/web/router.go`, `loopRoutes(app, api)` is invoked directly on the top-level `api` group (which only carries rate limiting and cookie-session middleware), whereas comparable route groups explicitly wrap themselves with `auth.Authenticate(app.AuthenticationProvider(), ...)` — e.g. `debugRoutes` at [2](#0-1) , `sessionRoutes`'s authenticated group at [3](#0-2) , and `authv2` at [4](#0-3) . Notably, `metricRoutes` (the node's own `/debug/pprof/*`) is intentionally mounted only inside `authv2` at [5](#0-4) , confirming the project's intent that pprof-style debug endpoints require authentication — but the LOOP-plugin equivalent bypasses this.

`pluginPPROFPOSTSymbolHandler` reads the request body verbatim and forwards it via `doRequest` to `http://<loopHostName>:<PrometheusPort>/debug/pprof/symbol` with no auth/allowlist check on the caller or the forwarded body: [6](#0-5) . Any unauthenticated caller can hit this endpoint, causing the node to act as an open proxy into the internal plugin process's pprof debug interface (also reachable via GET for `/debug/pprof/*profile` through `pluginPPROFHandler`).

### Impact Explanation
This allows unauthenticated internal service reconnaissance and use of the node as a proxy to reach the internal LOOP plugin's Go pprof debug interface (symbol resolution, profiling, goroutine dumps depending on `*profile`), which can leak internal memory addresses/symbol names and process state, aiding further attacks. It matches an "unauthorized access to internal/administrative functionality" class rather than direct key/fund theft.

### Likelihood Explanation
No credentials, tokens, or session cookies are required — any network client that can reach the node's HTTP API can exploit this immediately and repeatedly, provided at least one plugin is registered in `LoopRegistry` (any node running a LOOP plugin, e.g. common EVM/Solana/Median LOOPPs).

### Recommendation
Wrap `loopRoutes` (or at least the pprof-forwarding handlers) with the same authentication middleware used elsewhere, e.g. `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, and consider requiring `auth.RequiresAdminRole` given the debug/reconnaissance nature of pprof data, consistent with how `metricRoutes` is protected inside `authv2`.

### Proof of Concept
Go handler-level integration test using `httptest`:
1. Build a `gin.Engine` calling `loopRoutes(app, api)` on an unauthenticated group (mirroring `NewRouter`'s wiring), with a mock `LoopRegistry` containing one plugin pointing `EnvCfg.PrometheusPort` at a local `httptest.Server` that echoes the POST body and records the `Authorization`/session headers received.
2. Send `POST /plugins/testplugin/debug/pprof/symbol` with body `0x1234` and no auth headers/cookies.
3. Assert response is `200 OK` and body equals what the backend echoed (proving the request was forwarded and the response returned unauthenticated).
4. Assert the backend mock received no forwarded authentication artifacts, confirming `doRequest` performs no allowlist/auth check before proxying.
5. Repeat for `GET /plugins/:name/debug/pprof/heap` via `pluginPPROFHandler` to show the same gap applies to all loop pprof routes.

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
