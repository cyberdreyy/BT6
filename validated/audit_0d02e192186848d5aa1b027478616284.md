### Title
Single-step activation registry admin rotation via `setAdmin` allows irreversible loss of control over precompile activation switches - ([File: crates/common/precompiles/src/activation/storage.rs])

### Summary
The `ActivationRegistryStorage::set_admin` function in the Base activation-registry precompile performs a **single-step** admin change: the caller supplies `new_admin`, and if the caller is the current admin, the address is written directly to storage with no staging/confirmation step, unlike the `PolicyRegistry` precompile in the same codebase, which implements a proper two-step `stageUpdateAdmin` / `finalizeUpdateAdmin` flow for the same class of privileged address.

### Finding Description
`set_admin` validates static-call rejection, state-backed-admin enablement, and a non-zero `new_admin`, then calls `require_admin_caller` and immediately overwrites the `admin` storage slot with the caller-supplied value in one transaction: [1](#0-0) 

This is dispatched directly from ABI calldata via the `setAdmin` selector in `dispatch.rs`, reachable by any signed transaction from the current admin address: [2](#0-1) 

By contrast, the `PolicyRegistry` precompile in the same repository implements the exact 2-step pattern recommended for this bug class (stage → finalize, with the pending admin confirming acceptance): [3](#0-2) [4](#0-3) 

This asymmetry confirms the activation registry's `setAdmin` is the analog of the reported one-step `changeOwner` pattern: there is no `pendingAdmin`/`finalizeUpdateAdmin`-equivalent mechanism for the activation registry admin, no check that `new_admin != current admin`, and no confirmation from the new admin before the slot is overwritten.

The activation registry admin is a critical address: it single-handedly gates `activate`/`deactivate` of core Base features — `PolicyRegistry`, `B20Stablecoin`, and `B20Asset` — via `require_admin_caller`: [5](#0-4) [6](#0-5) 

### Impact Explanation
If the current activation admin submits a `setAdmin` transaction with a mistyped, unreachable, or otherwise uncontrolled address (e.g., a contract without the ability to call precompiles, or a burned key), the mistake is irreversible in a single transaction. Because the admin storage slot is the sole authority for activating/deactivating `B20Stablecoin`, `B20Asset`, and `PolicyRegistry` features, losing legitimate admin control permanently freezes the ability to activate or deactivate these Base-native precompile features going forward — i.e., a permanent, unrecoverable loss of governance over which precompiles are enabled on the chain. This matches the "permanent freezing of [protocol] function" impact class from the source report, adapted to Base's precompile activation model rather than fund custody.

### Likelihood Explanation
The likelihood is bounded by requiring the current legitimate admin to make the error (human/operational mistake, or a signing/tooling bug that produces the wrong `newAdmin` calldata argument), the same precondition as in the original Y2K `TimeLock.changeOwner` finding. No additional attacker action is required beyond the admin's own single mis-issued transaction; there's no time window, confirmation, or two-key check to catch it before the change becomes final.

### Recommendation
Adopt the same two-step admin transfer pattern that the `PolicyRegistry` precompile already implements elsewhere in the codebase (`stageUpdateAdmin` / `finalizeUpdateAdmin`): add a `pending_admin` storage slot, have `setAdmin` (or a renamed `stageAdmin`) only stage the candidate, and require a new `finalizeAdmin`/`acceptAdmin` call from the pending admin address to actually overwrite the effective `admin` storage slot, mirroring: [4](#0-3) 

### Proof of Concept
1. Current activation admin `A` sends a transaction with calldata `setAdmin(newAdmin=X)` to the activation registry precompile at `0x8453...0001` where `state_enabled == true`. [7](#0-6) 
2. `set_admin` passes all guards (`is_static` false, `state_enabled` true, `X` non-zero, caller == current admin) and writes `X` directly into the `admin` slot in the same transaction, with no pending/confirmation step: [8](#0-7) 
3. If `X` is mistyped or is an address that can never issue a transaction as that admin (e.g., a contract lacking any code path to call `activate`/`deactivate`/`setAdmin`), no account can ever again call `require_admin_caller` successfully. [5](#0-4) 
4. All subsequent `activate`/`deactivate`/`setAdmin` calls permanently revert with `Unauthorized`, permanently freezing the ability to toggle `PolicyRegistry`, `B20Stablecoin`, and `B20Asset` activation state — confirmed by the existing rotation test showing the old admin is locked out immediately after any `setAdmin` call, with no recovery path: [9](#0-8)

    /// Sets the activation registry admin address.
    pub fn set_admin(
        &mut self,
        new_admin: Address,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }
        if !admin_config.state_enabled {
            return Err(BasePrecompileError::revert(
                IActivationRegistry::AdminStorageNotEnabled {},
            ));
        }
        if new_admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::ZeroAdminAddress {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        self.__initialize()?;
        self.admin.write(new_admin)?;
        self.emit_event(IActivationRegistry::AdminChanged {
            previousAdmin: caller,
            newAdmin: new_admin,
            caller,
        })?;

        Ok(())
    }

    /// Reverts unless the current caller is the effective activation admin.
    pub fn require_admin_caller(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        let caller = self.storage.caller();
        let admin = self.authorized_admin(admin_config)?;
        if caller != admin {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        Ok(caller)
    }

#[test]
fn golden_stage_and_finalize_update_admin() {
    let mut s = fresh();
    let id = create(&mut s, ADMIN, ADMIN, PolicyType::ALLOWLIST);
    // Stage ADMIN2 as pending.
    let (rev, _) = call_policy(
        &mut s,
        ADMIN,
        IPolicyRegistry::stageUpdateAdminCall { policyId: id, newAdmin: ADMIN2 }.abi_encode(),
    );
    assert!(!rev);
    let (_, pending) = call_policy(
        &mut s,
        OUTSIDER,
        IPolicyRegistry::pendingPolicyAdminCall { policyId: id }.abi_encode(),
    );
    assert_eq!(
        pending,
        Bytes::from(IPolicyRegistry::pendingPolicyAdminCall::abi_encode_returns(&ADMIN2))
    );
    assert_eq!(
        s.get_events(registry()).last().unwrap().topics()[0],
        IPolicyRegistry::PolicyAdminStaged::SIGNATURE_HASH
    );
    // Finalize by the pending admin.
    let (rev, _) = call_policy(
        &mut s,
        ADMIN2,
        IPolicyRegistry::finalizeUpdateAdminCall { policyId: id }.abi_encode(),
    );
    assert!(!rev);
    let (_, admin) = call_policy(
        &mut s,
        OUTSIDER,
        IPolicyRegistry::policyAdminCall { policyId: id }.abi_encode(),
    );
    assert_eq!(admin, Bytes::from(IPolicyRegistry::policyAdminCall::abi_encode_returns(&ADMIN2)));
    assert_eq!(
        s.get_events(registry()).last().unwrap().topics()[0],
        IPolicyRegistry::PolicyAdminUpdated::SIGNATURE_HASH
    );
    assert_root("stage_finalize_admin", s, ROOT_STAGE_FINALIZE_ADMIN);
