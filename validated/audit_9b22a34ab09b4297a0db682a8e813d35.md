### Title
Bridge `OutgoingToken` credential is disclosed to view-role users via BridgeResource JSON serialization - ([File: core/web/presenters/bridges.go])

### Summary
`presenters.NewBridgeResource` unconditionally copies `bridges.BridgeType.OutgoingToken` (a plaintext bridge credential) into the `BridgeResource.OutgoingToken` JSON field, which has no `omitempty` tag, unlike `IncomingToken`. Any handler that serializes a `BridgeResource` — including `BridgeTypesController.Show`, `Index`, `Update`, and `Destroy` — returns this secret to any caller authorized to hit those read/write routes, including low-privileged "view" role sessions or read-scoped API tokens.

### Finding Description
`core/bridges/bridge_type.go` shows that `BridgeType` (the persisted/queried struct) stores `IncomingTokenHash` (a salted hash, never plaintext) but stores `OutgoingToken` in plaintext: [1](#0-0) 

`presenters.NewBridgeResource` builds the API response and explicitly sets `OutgoingToken: b.OutgoingToken` with no redaction, while the code comment right above acknowledges that `IncomingToken` is meant to be creation-only and is deliberately left unset here: [2](#0-1) 

`BridgeTypesController.Show` (reachable via `GET /v2/bridge_types/:BridgeName`) fetches the bridge from the ORM and passes it straight into `presenters.NewBridgeResource`, then serializes the result to the caller with no filtering of `OutgoingToken`: [3](#0-2) 

The same unredacted resource is also returned by `Index` (`GET /v2/bridge_types`), `Update`, and `Destroy`: [4](#0-3) [5](#0-4) 

While `IncomingToken` is safe from leakage via `Show`/`Index`/`Update`/`Destroy` because the ORM-loaded `BridgeType` never carries the plaintext incoming token (only its hash), `OutgoingToken` is stored and returned in plaintext with no equivalent protection or `omitempty` marking, meaning it is exposed on every read of bridge metadata to any principal permitted to call these routes (as low as view-role/read-scoped tokens per the router's role wrapper).

### Impact Explanation
This is a credential/secret disclosure to a low-privileged reader: `OutgoingToken` is a bridge authentication credential distinct from admin-only secrets, and its exposure to view-role sessions or restricted API tokens breaks the intended secret-confinement invariant (the codebase's own comment shows intent that bridge tokens should not be casually re-exposed after creation). This corresponds to the Chainlink bounty "key/secret disclosure" impact class, scoped to bridge credentials rather than node private keys.

### Likelihood Explanation
Trivially reachable: any authenticated session/API token with "view" (read) role can call `GET /v2/bridge_types/:BridgeName` or `GET /v2/bridge_types` and receive `OutgoingToken` in every response, with no additional exploitation steps, race conditions, or timing needed. It is fully repeatable for every bridge in the node.

### Recommendation
Remove `OutgoingToken` from `presenters.BridgeResource` for read-oriented responses (`Show`, `Index`), or mark it `omitempty` and only populate it at creation time analogous to `IncomingToken`, so that subsequent reads never re-expose the plaintext credential. If `OutgoingToken` must remain visible to operators, restrict its exposure to admin/editor roles rather than view-role sessions.

### Proof of Concept
Go handler-level test plan:
1. Create a bridge via `BridgeTypesController.Create` with a known `OutgoingToken` (capture the generated value from the ORM-persisted `BridgeType`).
2. Using a session/API-token client with only "view" role, call `GET /v2/bridge_types/:BridgeName` against `BridgeTypesController.Show`.
3. Parse the JSON response and assert that `data.attributes.outgoingToken` is present and equals the value stored in the DB — demonstrating the leak.
4. Repeat against `GET /v2/bridge_types` (`Index`) to show the same field is present in list responses too.
5. Expected (fixed) behavior: `outgoingToken` should be absent (or empty) from `Show`/`Index` responses for non-privileged roles.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// Update can change the restricted attributes for a bridge
func (btc *BridgeTypesController) Update(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")
	btr := &bridges.BridgeTypeRequest{}

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := c.ShouldBindJSON(btr); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if err := ValidateBridgeType(btr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := orm.UpdateBridgeType(ctx, &bt, btr); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	btc.App.GetAuditLogger().Audit(audit.BridgeUpdated, map[string]any{
		"bridgeName":                   bt.Name,
		"bridgeConfirmations":          bt.Confirmations,
		"bridgeMinimumContractPayment": bt.MinimumContractPayment,
		"bridgeURL":                    bt.URL,
	})

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
