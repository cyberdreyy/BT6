### Title
Fail-open tenure-tip lookup lets a signer sign a stale/non-canonical block when the node is transiently unreachable, especially after a signerdb reset - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`SortitionData::check_latest_block_in_tenure` is the shared chainstate gate that answers "does this proposal confirm the tenure's actual tip?". When it cannot resolve the tip locally (no fresh signed/pre-committed block recorded in `signerdb`), it falls back to asking the node via `client.get_tenure_tip(tenure_id)`. If that RPC call fails for *any* reason, the function does not fail closed — it logs a warning and returns `Ok(true)`, i.e. it assumes the proposal is higher than the tenure tip and lets it pass. [1](#0-0) [2](#0-1) 

### Finding Description
The comment on `check_latest_block_in_tenure` explains that the fail-open behavior is "safe" *only* because the proposal must still pass through the stacks-node's own `/v3/block_proposal` validation endpoint, which acts as the real backstop: [1](#0-0) 

That justification holds at proposal-arrival time (`check_proposal`), where the node's own validation runs immediately afterward. However, the exact same function is reused, via `check_block_against_signer_db_state`, at two *later* points in the signer's flow where no such node-side re-validation follows:

- After a `BlockValidateOk` response, as the last recheck before broadcasting a pre-commit (`handle_block_validate_ok`).
- At the moment a block crosses the pre-commit weight threshold, as the *final* recheck immediately before the signer produces its actual signature (`handle_block_pre_commit`). [3](#0-2) [4](#0-3) 

At this second call site, `check_block_against_signer_db_state` is documented as the very last gate before a signature leaves the box (see `docs/signer-flows.md` section 5, "Order matters here: the chainstate re-check runs first..."). Yet if `client.get_tenure_tip` errors here — a transient RPC/network hiccup with the *local* stacks-node, a node restart, or a slow node under load — the check silently passes instead of blocking the signature: [2](#0-1) 

This is architecturally inconsistent with the sibling guard used in the same signing path, `conflict_still_blocks`, which explicitly fails *closed* ("Leaving the conflict in place") on every RPC error: [5](#0-4) [6](#0-5) 

The exposure is worst exactly in the liveness-guard-loss scenario the task rules call out: `get_tenure_last_block_info` (the local-first check that would normally avoid the network call entirely) only finds a conflicting tip if `signerdb` still has a recorded signed/pre-committed block for that tenure. On a fresh signer instance, or a signer whose database was reset/rebuilt, this local record does not exist, so the function *must* fall through to the network call — and now a coincident node hiccup makes the "no signed tip found" and "node unreachable, assume higher" branches combine to let a stale or conflicting block sail through the very check meant to catch it. [7](#0-6) [8](#0-7) 

### Impact Explanation
If this fail-open path is hit at the pre-commit-threshold signing recheck instead of at proposal time, the signer can produce and broadcast a real signature (`mark_locally_accepted` → `handle_block_signature`) over a block that does not actually confirm the tenure's canonical tip — i.e. a stale or reorg-conflicting block — without the node's `/v3/block_proposal` backstop having been consulted against current state at that moment. This breaks the "approved-parent vs canonical" equality the whole `check_latest_block_in_tenure` mechanism exists to enforce, and matches the High-severity criterion explicitly listed: a signer "losing the equivocation guard on restart." A signature produced under this condition is not automatically recoverable and could contribute toward a conflicting block reaching the 70% signature threshold.

### Likelihood Explanation
This does not require a majority of signers, another signer's key, or the auth_token — it only requires an ordinary transient RPC failure between an individual signer and its own local stacks-node (restart, timeout, brief network blip) landing at the narrow window between pre-commit-threshold crossing and signature, combined with the signer lacking a locally recorded conflicting block (freshly joined/restarted signer, or one whose `signerdb` state for that tenure has expired/is empty). Node hiccups and signer restarts are operationally common events, not adversary-controlled cryptographic breaks, which raises realistic likelihood despite requiring a specific timing coincidence.

### Recommendation
Change `check_latest_block_in_tenure`'s error handling for `client.get_tenure_tip` to fail closed (reject / hold, consistent with `conflict_still_blocks`) when invoked from the post-validation and pre-commit-threshold signing recheck paths (`check_block_against_signer_db_state`), since those paths have no subsequent node-side validation backstop. If the "assume higher" behavior must be preserved for the proposal-arrival path (where it is justified by the node validation that follows), split the function so that the assumption is scoped only to that call site, and the signing-time recheck always fails closed on lookup failure.

### Proof of Concept
1. Restart a signer (or point a fresh signer instance at a tenure it has no `signerdb` history for), so `SortitionData::get_tenure_last_block_info` and `get_last_accepted_block` both return `None` for the tenure in question — see the early-return conditions in `check_latest_block_in_tenure`. [9](#0-8) 
2. A block proposal for that tenure reaches the pre-commit threshold; `handle_block_pre_commit` calls `check_block_against_signer_db_state`, which calls `check_latest_block_in_tenure`, which must fall through to `client.get_tenure_tip(tenure_id)`. [10](#0-9) 
3. Simulate/trigger a transient failure of that RPC call (node restart mid-request, connection reset, timeout). The function logs "Assuming proposal is higher than the parent tenure for now" and returns `Ok(true)`. [2](#0-1) 
4. `check_block_against_signer_db_state` returns `None` (no rejection), the pre-commit-threshold code path proceeds to `mark_locally_accepted` and broadcasts a signature, without the block ever having been re-validated against the node's actual current tip at signing time. [11](#0-10)

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

        // A block we have only pre-committed to must NOT veto this proposal, but, similar to above
        // this should still count as activity for the miner.
        let last_accepted_block = signer_db
            .get_last_accepted_block(tenure_id)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;
        if let Some(info) = last_accepted_block {
            let is_fresh_pre_commit = info.state == BlockState::PreCommitted
                && info.approved_time.is_some_and(|approved_time| {
                    approved_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
                        > get_epoch_time_secs()
                });
            if is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length {
                info!(
                    "Miner's block proposal conflicts with a block we have only pre-committed to. Counting it as miner activity, but not rejecting the proposal.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "pre_committed_signer_signature_hash" => %info.block.header.signer_signature_hash(),
                    "pre_committed_chain_length" => info.block.header.chain_length,
                );
                if let Err(e) = signer_db
                    .update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
                {
                    warn!("Failed to update last activity time: {e}");
                }
            }
        }
