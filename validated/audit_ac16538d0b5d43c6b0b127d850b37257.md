### Title
Uncontrolled recursion via blinded-node chains in fault-proof MPT `TrieNode::open` causes stack exhaustion - (File: crates/proof/mpt/src/node.rs)

### Summary
The libxml2 CVE is a class of "uncontrolled recursion on attacker-supplied graph-like data" bug. In `base--022`'s fault-proof Merkle Patricia Trie implementation, `TrieNode::open` recurses through `Self::Blinded` nodes by calling `self.unblind(fetcher)` and then re-invoking `self.open(path, fetcher)` on the *same* path, without any depth counter or recursion-depth cap.

### Finding Description
`TrieNode::open` handles the `Blinded` variant like this: [1](#0-0) 
`unblind` fetches the preimage for a commitment via the `TrieProvider` (preimage oracle) and replaces `self` with whatever `TrieNode::decode` produces for that preimage: [2](#0-1) 
`TrieNode::decode` will itself yield another `Self::Blinded` node whenever the top-level RLP payload is exactly 32 bytes: [3](#0-2) 
Because preimages are supplied out-of-band through the `TrieProvider`/preimage-oracle interface during fault-proof execution, a dispute-game participant that controls what preimages are served for requested hashes can construct a long chain of preimages, each of which decodes to a bare 32-byte value (i.e., another `Blinded` commitment) rather than terminating in a `Leaf`/`Extension`/`Branch`. Each link in the chain causes one more recursive call to `open` (`unblind` → `open` again), with no bound on the chain length or recursion depth. `insert` has the analogous pattern for `Blinded` nodes: `self.unblind(fetcher)?; self.insert(path, value, fetcher)`. [4](#0-3) 

Unlike branch/extension traversal (which is naturally bounded by the fixed nibble-path length of a 32-byte key), the blinded-chain recursion is *not* bounded by path length at all — it is bounded only by how many distinct preimages the oracle is willing to serve, which is attacker/dispute-participant controlled.

### Impact Explanation
The fault-proof program (op-program-equivalent) executes trie operations against L1/L2 preimage data supplied by a dispute-game participant during the interactive/one-shot fault-proof execution. If a sufficiently deep chain of "blinded-of-blinded" preimages is crafted and made reachable from a required storage/account trie path, `TrieNode::open`/`insert` will recurse until the process stack is exhausted, causing a segmentation fault / crash of the fault-proof program. Because the fault-proof program's job is to compute the correct claim/output root for a dispute game, crashing it means the honest party cannot produce a valid execution trace, potentially resulting in an incorrect provable output root being accepted (if the honest challenger cannot respond) — i.e., a chain-halting/wrong-output-root condition within the scope explicitly called out by the prompt ("the fault-proof program and MPT").

### Likelihood Explanation
This requires: (1) the ability to make the fault-proof program request a chain of blinded nodes, and (2) the attacker/dispute participant controlling what the preimage oracle returns for those hash lookups — both of which are realistic capabilities for a dispute-game participant since they supply preimages. However, I could not fully verify within the available tool budget whether the `TrieProvider`/preimage-oracle glue code that feeds `unblind` enforces any depth limit upstream (e.g., in the executor or preimage-fetching KV store), nor whether a full end-to-end path from an untrusted preimage to a repeatedly-nested `Blinded` structure is reachable given how `open`/`insert` are invoked in the executor. This is a **plausible analog by bug class**, not a proven exploit chain confirmed end-to-end.

### Recommendation
Add an explicit recursion-depth counter (analogous to `MAX_CBOR_NESTING_DEPTH` already used elsewhere in this codebase, e.g. `crates/proof/tee/registrar/src/cbor.rs`) to `TrieNode::open`, `TrieNode::insert`, and `TrieNode::unblind`'s recursive call sites, and reject with an error once a sane maximum trie/blinded-chain depth is exceeded, rather than relying solely on path length to bound recursion.

### Proof of Concept
Not independently reproduced. A hypothetical PoC would require: constructing a chain of N preimages `P_1..P_N` where `P_i` RLP-decodes to exactly a 32-byte value (making `TrieNode::decode` return `Blinded { commitment: hash(P_{i+1}) }`), registering all of them with the fault-proof program's preimage oracle, and pointing a trie path traversal at `P_1`; calling `TrieNode::open` (or `insert`) on the root would then recurse N times via [1](#0-0)  until the process stack overflows.

    /// Unblinds the [`TrieNode`] if it is a [`TrieNode::Blinded`] node.
    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.
                *self = Self::Empty;
            } else {
                *self = fetcher
                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }
