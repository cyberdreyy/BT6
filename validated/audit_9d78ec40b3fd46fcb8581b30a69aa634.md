### Title
Old Operator Sets Can Approve New Cross-Chain Commands After Operatorship Transfer — (`crates/sui-axelar-cgp/move/sources/validators.move`)

### Summary

The `validate_proof` function in the Sui Axelar CGP Move package accepts proofs from any of the past 16 operator sets without distinguishing whether the signing set is the *current* one. After an operatorship transfer, old operators (with superseded stake distributions) can still call the public `process_commands` entry function to inject new `approveContractCall` approvals into the shared `AxelarValidators` object, bypassing the current operator set's authority.

### Finding Description

`validate_proof` in `validators.move` enforces only a retention window check:

```move
assert!(operators_epoch != 0 && epoch - operators_epoch < OLD_KEY_RETENTION, EInvalidOperators);
```

It returns `true` whenever the weight threshold is met, regardless of whether the signing operators belong to the current epoch or a past one. [1](#0-0) 

In the original Axelar Solidity reference, `validateProof` returns `currentOperators = operatorsEpoch == epoch`, and only a proof from the **current** operator set sets `currentOperators = true`. The Move port omits this distinction entirely — `validate_proof` returns `true` for any valid proof within the retention window. [2](#0-1) 

In `gateway.move`, the return value is used as `allow_operatorship_transfer`, but `approveContractCall` commands are processed unconditionally for every valid proof — there is no guard that restricts `approveContractCall` to the current operator set:

```move
let mut allow_operatorship_transfer = validate_proof(validators, to_sui_signed(*&data), proof);
...
if (cmd_selector == &SELECTOR_APPROVE_CONTRACT_CALL) {
    validators::add_approval(validators, ...);   // no current-operator check
    continue
}
``` [3](#0-2) 

`process_commands` is a public `entry fun` callable by any Sui address with no access control: [4](#0-3) 

### Impact Explanation

After operatorship is transferred (e.g., Alice's weight is reduced from 0.5 to 0.25 in the new epoch), Alice can reuse her old private key to sign a new `approveContractCall` batch under the old operator set (epoch N-1, still within the 16-epoch retention window). She submits this to `process_commands`, which passes `validate_proof` and stores the approval in `AxelarValidators.approvals`. Any caller can then invoke `take_approved_call` to consume the approval and execute the cross-chain command — including commands that mint or unlock tokens — without the current operator set's consent.

This constitutes **bridge message forgery**: an old operator set, whose authority has been explicitly revoked by an operatorship transfer, can still inject and execute new cross-chain approvals under the superseded stake distribution. [5](#0-4) [6](#0-5) 

### Likelihood Explanation

The attack requires only knowledge of an old operator private key (which the operator already possesses) and the ability to submit a Sui transaction — both trivially available to any former operator. No privileged access, malicious validator, or governance quorum is needed. The window is up to 16 operatorship epochs wide.

### Recommendation

`validate_proof` must return whether the signing set is the **current** operator set, mirroring the original Axelar Solidity design:

```move
// Return true only if operators_epoch == current epoch
let is_current = operators_epoch == epoch;
// ... validate signatures ...
return is_current  // or abort if threshold not met
```

Then in `process_commands`, `approveContractCall` commands should only be processed when the proof is from the current operator set (i.e., `validate_proof` returns `true`). Commands signed by old operators before the transfer can be allowed only if a timestamp or sequence-number bound is recorded at transfer time.

### Proof of Concept

**Setup (Epoch 1):**
- Operators: `[Alice]`, weights: `[100]`, threshold: `10`
- `epoch_for_hash[hash(Alice, 100, 10)] = 1`, `currentEpoch = 1`

**Operatorship transfer (Epoch 2):**
- New operators: `[Alice, Bob]`, weights: `[25, 75]`, threshold: `50`
- `epoch_for_hash[hash(Alice,Bob,25,75,50)] = 2`, `currentEpoch = 2`
- Alice's solo weight (25) is now below threshold (50) — she cannot approve alone under the new set.

**Attack (still Epoch 2):**
1. Alice constructs a new `approveContractCall` batch (e.g., minting tokens to her address).
2. She signs it with her old key and submits a proof referencing the Epoch-1 operator set `{Alice, [100], 10}`.
3. `validate_proof` checks: `operators_epoch (1) != 0` and `2 - 1 = 1 < 16` → passes.
4. Alice's weight (100) ≥ threshold (10) → `validate_proof` returns `true`.
5. `add_approval` stores the approval in `AxelarValidators.approvals`.
6. Alice (or anyone) calls `take_approved_call` to execute the cross-chain command.

Alice has successfully approved a new cross-chain command using her revoked old operator authority, bypassing the current stake distribution. [7](#0-6) [1](#0-0)

    public(package) fun validate_proof(
        validators: &AxelarValidators,
        approval_hash: vector<u8>,
        proof: vector<u8>
    ): bool {
        // Turn everything into bcs bytes and split data.
        let mut proof = bcs::new(proof);
        let (operators, weights, threshold, signatures) = (
            bcs::peel_vec_vec_u8(&mut proof),
            bcs::peel_vec_u128(&mut proof),
            bcs::peel_u128(&mut proof),
            bcs::peel_vec_vec_u8(&mut proof)
        );

        let operators_length = vector::length(&operators);
        let operators_epoch = *vec_map::get(
            epoch_for_hash(validators),
            &operators_hash(&operators, &weights, threshold)
        );
        let epoch = epoch(validators);

        assert!(operators_epoch != 0 && epoch - operators_epoch < OLD_KEY_RETENTION, EInvalidOperators);

        let (i, mut weight, mut operator_index) = (0, 0, 0);
        let total_signatures = vector::length(&signatures);

        while (i < total_signatures) {
            let mut signature = *vector::borrow(&signatures, i);
            normalize_signature(&mut signature);

            let signed_by: vector<u8> = ecdsa::secp256k1_ecrecover(&signature, &approval_hash, 0);
            while (operator_index < operators_length && &signed_by != vector::borrow(&operators, operator_index)) {
                operator_index = operator_index + 1;
            };

            // assert!(operator_index == operators_length, 0); // EMalformedSigners

            weight = weight + *vector::borrow(&weights, operator_index);
            if (weight >= threshold) { return true };
            operator_index = operator_index + 1;
        };

        abort ELowSignaturesWeight
    }
