### Title
Log Poller checkpoint can be force-advanced by a run-role-only credential via `POST /v2/lp_skip_to_block`, silently dropping unprocessed on-chain events - ([File: core/web/router.go], [File: core/web/lp_skip_controller.go])

### Summary
`LPSkipController.LPSkipToBlock` performs a destructive operation — it forces the LogPoller to jump its processing checkpoint forward to an attacker-supplied block number — yet the route is registered in `v2Routes` in `core/web/router.go` behind `auth.RequiresRunRole`, the lowest privilege tier intended only for triggering job runs, rather than `RequiresEditRole`/`RequiresAdminRole`. A holder of a run-only API credential can therefore skip past unfinalized or unconsumed logs for any configured EVM chain, causing downstream consumers (OCR, Keepers, log-based jobs) to silently miss on-chain events that should have triggered pipeline runs.

### Finding Description
`LPSkipController.LPSkipToBlock` in `core/web/lp_skip_controller.go` [1](#0-0)  accepts a JSON body with `blockNumber`, `family`, and `chain-id`, validates only that `blockNumber >= 2` and that `family == "evm"`, then calls `c.App.LPSkipToBlock(ctx, request.Family, request.ChainID, request.BlockNumber)` which reprograms the LogPoller to "start processing from the new block on next tick." There is no check that the target block is finalized, no check that pending/unconsumed logs before that block have been fully processed, and no chain-state validation beyond the relayer existing.

The HTTP route for this controller is wired in `v2Routes` of `core/web/router.go`, mapped to `POST /v2/lp_skip_to_block`. Per the audit target, this route is gated only by `auth.RequiresRunRole` — the same minimal role used for job-run-triggering endpoints — rather than the edit/admin role tier used elsewhere in the router for state-mutating administrative operations. Because `RequiresRunRole` is designed to permit only "run a job" style actions for restricted API tokens, granting it access to an operation that rewrites core chain-indexing state is an authorization-tier mismatch: any credential intended only to trigger runs can instead corrupt the LogPoller's processing checkpoint for any chain, with no confirmation, dry-run, or safety check against unconsumed logs.

### Impact Explanation
An attacker holding only a run-role API credential (e.g., a restricted external-initiator-style token meant for triggering runs) can silently advance the LogPoller checkpoint past logs that have not yet been consumed by dependent services (OCR observation triggers, Keeper upkeep checks, log-triggered pipeline runs). This can cause missed on-chain events that gate financial pipeline execution — for example dropped OCR round observations or missed upkeep-trigger logs — without any error, alert, or rollback path, since the controller reports success unconditionally once `App.LPSkipToBlock` returns. This matches the "unauthorized action causing loss of funds / missed critical on-chain event processing" bounty impact class, given the destructive, non-reversible nature of the checkpoint jump combined with insufficient role gating.

### Likelihood Explanation
Exploitation requires only a valid run-role credential (the lowest authenticated tier) and one HTTP POST with attacker-chosen `blockNumber`/`chain-id` — no special preconditions, timing, or race are needed, making this trivially repeatable by any run-role holder or anyone who obtains a leaked run-only API token.

### Recommendation
Move `/v2/lp_skip_to_block` out of the `RequiresRunRole` group in `core/web/router.go` and gate it with `auth.RequiresEditRole` (or `RequiresAdminRole`) consistent with other destructive/administrative chain-state routes. Additionally, add a safety check in `LPSkipController.LPSkipToBlock` / the underlying `Application.LPSkipToBlock` to refuse skipping past unconsumed or unfinalized logs unless an explicit `force` flag is supplied.

### Proof of Concept
1. Handler-level integration test in `core/web`: start the app/router with a session authenticated only as `sessions.UserRoleRun` (or the equivalent run-only API token fixture used in `lp_skip_controller_test.go`).
2. Seed a chain's LogPoller with pending/unconsumed logs below a target block (via test DB fixtures).
3. Issue `POST /v2/lp_skip_to_block` with `{"blockNumber": <N above pending logs>, "family": "evm", "chain-id": "<test chain>"}` using the run-role session.
4. Assert current behavior: request succeeds (200) and `LPSkipToBlockResponse` is returned, and the LogPoller checkpoint moves forward, orphaning the pending logs.
5. Assert expected/fixed behavior: with role gating corrected to `RequiresEditRole`, the same run-role request should receive `401/403 Unauthorized`, while an edit/admin-role session succeeds — table-test both role tiers against the route to confirm minimum-role enforcement.

func (c *LPSkipController) LPSkipToBlock(gctx *gin.Context) {
	var request LPSkipToBlockRequest
	if err := gctx.ShouldBindJSON(&request); err != nil {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, err)
		return
	}
	if request.BlockNumber < 2 {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.Errorf("block number must be >= 2: %v", request.BlockNumber))
		return
	}

	if request.Family == "" {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.New("chain family was not provided"))
		return
	}
	if request.Family != relay.NetworkEVM {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.Errorf("unsupported chain family %q, only %s is supported", request.Family, relay.NetworkEVM))
		return
	}

	if strings.TrimSpace(request.ChainID) == "" {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.New("chain-id was not provided"))
		return
	}

	ctx := gctx.Request.Context()
	if err := c.App.LPSkipToBlock(ctx, request.Family, request.ChainID, request.BlockNumber); err != nil {
		if errors.Is(err, chainlink.ErrNoSuchRelayer) {
			jsonAPIError(gctx, http.StatusBadRequest, err)
			return
		}
		jsonAPIError(gctx, http.StatusInternalServerError, err)
		return
	}
