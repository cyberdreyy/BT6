### Title
Unsanitized `AlternateKey` in `CacheArchive.Run` allows path traversal via `cacheArchivePath` when `FF_HASH_CACHE_KEYS` is enabled - (File: functions/concrete/run/stages/cache_archive.go)

### Summary
`builder.buildCacheArchive` computes `stages.CacheArchive.AlternateKey` differently depending on `FF_HASH_CACHE_KEYS`: when the flag is ON, `AlternateKey` is set to the raw (unsanitized) `humanKey`/`rawKey` derived from the job's `cache.key`, while the primary `Key` is always a SHA-256 hex digest and therefore inherently safe. `CacheArchive.Run` passes this unsanitized `AlternateKey` into `alternateArchivePath` → `cacheArchivePath(e, key)`, which does a bare `filepath.Join(e.CacheDir, key, "cache.zip")` with no traversal check, letting a `../`-laden cache key escape `CacheDir`.

### Finding Description
In [1](#0-0) , `cacheKey` computes `humanKey`/`resolvedKey` as follows:
- If `FF_HASH_CACHE_KEYS` is ON: `humanKey = rawKey` (the raw, attacker-controlled `cache.key` after variable expansion, **not** passed through `cachekey.Sanitize`), and `resolvedKey = sha256(humanKey)` — a safe 64-char hex string.
- If OFF: `humanKey = cachekey.Sanitize(rawKey)` (traversal-safe), and `resolvedKey = humanKey`.

In `buildCacheArchive` [2](#0-1) , the alternate key is computed as:
```
alternateResolved := humanKey
if !b.isFeatureFlagOn(featureflags.HashCacheKeys) {
    alternateResolved = fmt.Sprintf("%x", sha256.Sum256([]byte(humanKey)))
}
```
When the flag is ON, `alternateResolved` is simply `humanKey` — the **raw, unsanitized** `rawKey` — since sanitization is only applied in the `!FF` branch of `cacheKey`. This becomes `archive.AlternateKey` unless it happens to equal `resolvedKey` (essentially never, since one is raw text and the other a hash).

This `AlternateKey` then flows into `CacheArchive.Run` [3](#0-2) , which calls `s.alternateArchivePath(e)` → `cacheArchivePath(e, s.AlternateKey)` [4](#0-3) :
```go
func cacheArchivePath(e *env.Env, key string) string {
	absPath := filepath.Join(e.CacheDir, key, "cache.zip")
	rel, err := filepath.Rel(e.WorkingDir, absPath)
	...
}
```
`filepath.Join` calls `Clean`, collapsing `..` segments arithmetically against `e.CacheDir` with no bound check that the result remains under `e.CacheDir`. A `cache.key` such as `../../../../tmp/evil` (directly in `.gitlab-ci.yml` or via an expanded CI variable, e.g. `key: $USER_CONTROLLED_KEY`) is attacker-controlled input reaching this join unsanitized only in the `AlternateKey` path — the primary `Key` path is safe because it is always a hash in this mode.

The `--alternate-file` argument is then passed to the `cache-archiver` helper binary [5](#0-4) , which will write the produced cache archive to that traversed path.

### Impact Explanation
This lets a pipeline author (unprivileged w.r.t. Runner) cause the `cache-archiver` helper to write the alternate cache zip file outside the intended `CacheDir`/build directory sandbox, into an arbitrary path reachable from the job's working directory context (subject to OS filesystem permissions of the job user). This is a genuine confinement-boundary violation of "File operations must stay within intended build/cache/artifact roots," concretely reproducible whenever `FF_HASH_CACHE_KEYS=true` (or its evolving default state) and a job supplies `cache.key` with `../` sequences.

### Likelihood Explanation
- Precondition: `FF_HASH_CACHE_KEYS` enabled (this flag is being migrated toward becoming default per `CHANGELOG.md`/docs references, so its exposure window is real and growing).
- Trigger: any job author sets `cache: key: "../../../whatever"` or `cache: key: $CI_VAR` with a variable value containing traversal sequences — fully attacker-controlled, no special privilege needed.
- No mitigating check exists on this specific path: `cachekey.Sanitize` is only invoked in the FF-off branch of `cacheKey`, and `cacheArchivePath` performs no post-hoc containment check (no `strings.HasPrefix` against `CacheDir`, no `filepath.EvalSymlinks`/rel-then-check pattern).
- This is easily and deterministically repeatable — not reliant on races, timing, or privileged actors.

### Recommendation
Apply the same `cachekey.Sanitize` treatment to the `AlternateKey`/alternate `humanKey` value as is applied to the primary key in the FF-off branch, regardless of `FF_HASH_CACHE_KEYS` state, before using it to build any `cacheArchivePath`. Additionally, harden `cacheArchivePath` itself to enforce containment (e.g., resolve the absolute path and verify it is still rooted under `e.CacheDir` via `filepath.Rel`/prefix check, rejecting or sanitizing keys that would escape), so the guarantee doesn't depend solely on upstream key construction being correct for both the primary and alternate code paths.

### Proof of Concept
Go unit test in `functions/concrete/builder` (or `stages`) asserting containment for both `Key` and `AlternateKey` across FF states:
```go
func TestCacheArchive_AlternateKeyTraversal(t *testing.T) {
    for _, ffOn := range []bool{true, false} {
        cache := spec.Cache{Key: "../../../../tmp/evil", Paths: []string{"foo"}}
        b := builder{
            meta: spec.Job{Cache: []spec.Cache{cache}},
            opts: options{isFeatureFlagOn: func(f string) bool { return ffOn && f == featureflags.HashCacheKeys }},
            variables: /* stub provider */,
        }
        archives, err := b.buildCacheArchive()
        require.NoError(t, err)
        require.Len(t, archives, 1)

        primaryPath := cacheArchivePath(&env.Env{CacheDir: "/cache"}, archives[0].Key)
        altPath := cacheArchivePath(&env.Env{CacheDir: "/cache"}, archives[0].AlternateKey)

        assert.True(t, strings.HasPrefix(primaryPath, "/cache"), "primary key escaped CacheDir: %s", primaryPath)
        assert.True(t, strings.HasPrefix(altPath, "/cache"), "alternate key escaped CacheDir (FF=%v): %s", ffOn, altPath)
    }
}
```
Expected current result: the assertion fails for `ffOn == true` because `altPath` resolves to something like `/tmp/evil/cache.zip`, outside `/cache`, proving the traversal. After applying the fix (sanitizing `AlternateKey` or hardening `cacheArchivePath`), both assertions should pass for both flag states.

func (b *builder) cacheKey(name string) (string, string, []string, error) {
	// Virtual-root prefix prevents a leading / or .. in JobName/Ref from producing an unexpected key,
	// especially under FF_HASH_CACHE_KEYS=on where humanKey is used unsanitized.
	rawKey := path.Join("/", b.meta.JobInfo.Name, b.meta.GitInfo.Ref)[1:]
	if name != "" {
		rawKey = b.variables.ExpandValue(name)
	}

	var warnings []string
	var humanKey string
	if b.isFeatureFlagOn(featureflags.HashCacheKeys) {
		humanKey = rawKey
	} else {
		sanitized, err := cachekey.Sanitize(rawKey)
		switch {
		case err != nil:
			warnings = append(warnings, err.Error())
		case sanitized != rawKey:
			warnings = append(warnings, fmt.Sprintf("cache key %q sanitized to %q", rawKey, sanitized))
		}
		humanKey = sanitized
	}

	if humanKey == "" {
		return "", "", warnings, fmt.Errorf("empty cache key")
	}

	resolvedKey := humanKey
	if b.isFeatureFlagOn(featureflags.HashCacheKeys) {
		resolvedKey = fmt.Sprintf("%x", sha256.Sum256([]byte(humanKey)))
	}

	return humanKey, resolvedKey, warnings, nil
}

func cacheArchivePath(e *env.Env, key string) string {
	absPath := filepath.Join(e.CacheDir, key, "cache.zip")
	rel, err := filepath.Rel(e.WorkingDir, absPath)
	if err != nil {
		return absPath
	}
