## Analysis

The Atlas report is about a mismatch between what was verified/simulated and what actually happens on execution. The strongest analog in this NEAR contract set is in the multisig contract: **confirmations recorded on a request are not synchronized with the live set of keys on the account**, so a stale confirmation from a since-removed key can still count toward the quorum needed to execute a request.

### Title
Stale confirmations from revoked (deleted) keys still count toward multisig quorum, allowing a request to execute below the effective live-signer threshold - (File: `multisig/src/lib.rs`)

### Summary
`MultiSigContract::confirm` counts confirmations stored in `self.confirmations` without verifying that each confirming public key is still a valid access key on the account. When a key is removed via `MultiSigRequestAction::DeleteKey`, the code only purges requests that were *originally added by* that key; it does not remove that key's confirmations from other, still-pending requests it had previously confirmed. As a result, a request can later execute using a mix of live and revoked-key confirmations, breaking the equality `confirmations_counted == live_member_confirmations`.

### Finding Description
`confirm()` reads the `confirmations` set for a request and executes once `confirmations.len() + 1 >= num_confirmations`: [1](#0-0) 

The only cleanup of confirmations tied to a deleted key happens inside the `DeleteKey` action, and it is scoped to requests whose **original signer** (`signer_pk`) equals the deleted key — not to requests that key merely *confirmed*: [2](#0-1) 

So if key `B` confirms a request `R` that was originally added by key `A`, and `B`'s key is later removed via a separate `DeleteKey` request, `R`'s confirmation set still contains `B`'s public key. `assert_valid_request` never re-validates that stored confirmers are still authorized keys — it only checks that the *caller* of `confirm`/`delete_request` is the account itself: [3](#0-2) 

Consequently a later legitimate confirmer can push `R` over the `num_confirmations` threshold even though one of the counted confirmations belongs to a key no longer present on the account.

### Impact Explanation
This breaks the threshold-enforcement invariant that a multisig request should only execute once it has been approved by `num_confirmations` **currently live** keys. In the scenario above, with `num_confirmations = 2` and keys `{A, B, C}`:
1. `A` calls `add_request` for `R` (e.g. `Transfer`, `AddKey`, or `FunctionCall`).
2. `B` calls `confirm(R)` → `confirmations = {B}` (1 < 2, not yet executed).
3. Governance removes `B` via a `DeleteKey` request (a normal, legitimate multisig action) — `R` survives untouched since `R.signer_pk == A`, not `B`.
4. `C` calls `confirm(R)` → `confirmations = {B, C}`, `len() == 2 >= num_confirmations` → `execute_request` fires.

`R` executes with the approval of only one genuinely live key (`C`), effectively satisfying a 2-of-N threshold with 1 live signature plus a stale one — "a multisig request executed below threshold," which is a Critical-severity outcome for a custody contract that gates transfers, key management, and arbitrary function calls behind this quorum.

### Likelihood Explanation
This requires no attacker exploit of cryptography — only ordinary contract usage: an outstanding unconfirmed/under-threshold request plus a routine key-rotation (`DeleteKey`) event, which is an expected operational action for any multisig (e.g., revoking a compromised or departing signer's key). Any organization that rotates keys while requests are in flight is exposed, and the flaw is entirely internal to `execute_request`/`confirm`'s bookkeeping, not dependent on any external contract behavior.

### Recommendation
When executing `DeleteKey`, iterate over **all** entries in `self.confirmations` (not just requests where `signer_pk == pk`) and remove the deleted public key from every confirmation set; alternatively, revalidate at `confirm()`/execution time that every public key in a request's confirmation set is still present in the account's live access key list before allowing it to count toward `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new(2)` with 3 full-access keys `A`, `B`, `C` on the account.
2. As `A`, call `add_request` with a `Transfer` action to some `receiver_id`.
3. As `B`, call `confirm(request_id)` — confirmations set becomes `{B}` (below threshold, no execution).
4. As any signer, submit and confirm a separate `DeleteKey { public_key: B }` request (threshold 2 reached on that separate request, so `B` gets deleted on-chain) — this only cleans up requests where `signer_pk == B`; the pending transfer request from step 2 is untouched because `signer_pk == A`.
5. As `C`, call `confirm(request_id)` on the original transfer request — `confirmations.len() + 1 == 2 >= num_confirmations`, so `execute_request` runs and the transfer executes, even though `B`'s key no longer exists on the account and only `C` is a currently-live confirming signer. [4](#0-3)

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
