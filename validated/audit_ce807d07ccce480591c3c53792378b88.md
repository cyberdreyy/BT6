### Title
View-role users can read a bridge's OutgoingToken secret via GET /v2/bridge_types/:BridgeName - ([File: core/web/bridge_types_controller.go])

### Summary
The `Show`, `Index`, `Update`, and `Destroy` handlers for bridge types are registered without any `RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole` wrapper, unlike `Create`. Since `presenters.BridgeResource.OutgoingToken` is serialized unconditionally (no `omitempty`, no redaction), any authenticated user—including one with only the `view` role—can retrieve a bridge's `OutgoingToken` secret by calling `GET /v2/bridge_types/:BridgeName`.

### Finding Description
The route is registered as:
```go
authv2.GET("/bridge_types/:BridgeName", bt.Show)
``` [1](#0-0) 

This sits inside the `authv2` group, which only requires the request to pass one of `auth.AuthenticateByToken` / `auth.AuthenticateBySession` (i.e., be *any* logged-in user or API-token holder), with no additional role check:
```go
authv2 := r.Group("/v2", auth.Authenticate(app.AuthenticationProvider(),
    auth.AuthenticateByToken,
    auth.AuthenticateBySession,
))
``` [2](#0-1) 

Compare this to `Create`, `Update`, and `Destroy`, which are explicitly wrapped with `auth.RequiresEditRole`:
```go
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
``` [3](#0-2) 

`BridgeTypesController.Show` fetches the bridge from the ORM and serializes it directly through `presenters.NewBridgeResource`, with no field filtering based on caller role:
```go
bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
...
jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
``` [4](#0-3) 

`presenters.BridgeResource` marshals `OutgoingToken` unconditionally (no `omitempty` tag, unlike `IncomingToken`):
```go
IncomingToken          string       `json:"incomingToken,omitempty"`
OutgoingToken          string       `json:"outgoingToken"`
``` [5](#0-4) 

and `NewBridgeResource` copies it straight from the DB row:
```go
func NewBridgeResource(b bridges.BridgeType) *BridgeResource {
	return &BridgeResource{
		...
		OutgoingToken:          b.OutgoingToken,
		...
	}
}
``` [6](#0-5) 

`RequiresEditRole` would reject `view` and `run` role users, but since `Show` bypasses this wrapper entirely, `GetAuthenticatedUser`/role checks are never invoked for this route:
```go
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		...
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			...jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
``` [7](#0-6) 

The existing test `TestBridgeController_Show` confirms `resource.OutgoingToken` is not asserted/redacted and the handler returns it as-is to any authenticated client: [8](#0-7) 

### Impact Explanation
`OutgoingToken` is a bridge adapter credential (`core/bridges/bridge_type.go`) used to authenticate outbound requests to the external adapter; disclosing it to a lower-privileged (`view`-role) user lets that user impersonate the node to the external adapter or replay the secret elsewhere. This matches the "sensitive data exposure / secret confinement violation" bounty class — a view-only credential holder obtaining a secret intended only for edit/admin-level operators. Note `Index` (`GET /v2/bridge_types`) has the same missing role guard and same exposure across all bridges.

### Likelihood Explanation
Preconditions are minimal: any valid session or API token for a user with the lowest privilege role (`view`) is sufficient — no edit/run/admin privilege needed. The request is a single unauthenticated-with-respect-to-role `GET /v2/bridge_types/:BridgeName` (or `/v2/bridge_types` for all bridges), fully repeatable and requires no special conditions beyond having any authenticated account and knowing/enumerating a bridge name.

### Recommendation
Wrap `bt.Show` (and `bt.Index`) with `auth.RequiresEditRole` (or a redacting presenter that omits `OutgoingToken`/`IncomingToken` for non-edit roles), consistent with `Create`/`Update`/`Destroy`. Alternatively, always redact `OutgoingToken` in `NewBridgeResource` for `Show`/`Index` responses and only expose it (or a masked variant) to edit/admin roles.

### Proof of Concept
Handler-level Go test:
1. In `core/web/bridge_types_controller_test.go`, add `TestBridgeTypesController_Show_ViewRoleCanReadOutgoingToken`.
2. Create an app, create a bridge via `app.BridgeORM().CreateBridgeType` with a known `OutgoingToken` (e.g., `"secret-outgoing-token"`).
3. Create an HTTP client authenticated as a user with `clsessions.UserRoleView` (reuse pattern from `client.Get` with a view-role session cookie/token, similar to existing role-based tests in `core/web/*_test.go` that construct sessions with specific `Role`).
4. `resp, cleanup := client.Get("/v2/bridge_types/" + bt.Name.String())`.
5. Assert `resp.StatusCode == http.StatusOK` (currently succeeds because no role check exists).
6. Parse the JSON:API response into `presenters.BridgeResource` and assert `resource.OutgoingToken == "secret-outgoing-token"`, demonstrating disclosure.
7. Expected fix behavior: after wrapping the route with `RequiresEditRole`, the same view-role request should return `http.StatusUnauthorized` and no `OutgoingToken` should be present in the response body.

func TestBridgeController_Show(t *testing.T) {
	t.Parallel()

	app := cltest.NewApplication(t)
	require.NoError(t, app.Start(t.Context()))

	client := app.NewHTTPClient(nil)

	bt := &bridges.BridgeType{
		Name:          bridges.MustParseBridgeName(testutils.RandomizeName("showbridge")),
		URL:           cltest.WebURL(t, "https://testing.com/bridges"),
		Confirmations: 0,
	}
	ctx := t.Context()
	require.NoError(t, app.BridgeORM().CreateBridgeType(ctx, bt))

	resp, cleanup := client.Get("/v2/bridge_types/" + bt.Name.String())
	t.Cleanup(cleanup)
	assert.Equal(t, http.StatusOK, resp.StatusCode, "Response should be successful")

	var resource presenters.BridgeResource
	cltest.ParseJSONAPIResponse(t, resp, &resource)
	assert.Equal(t, bt.Name.String(), resource.Name, "should have the same name")
	assert.Equal(t, bt.URL.String(), resource.URL, "should have the same URL")
	assert.Equal(t, bt.Confirmations, resource.Confirmations, "should have the same Confirmations")

	resp, cleanup = client.Get("/v2/bridge_types/nosuchbridge")
	t.Cleanup(cleanup)
	assert.Equal(t, http.StatusNotFound, resp.StatusCode, "Response should be 404")
}
