## Title
Any unrelated `NewBlock` event clears the signer's active transaction-replay set, letting a single-slot miner strip replay protection mid-tenure — ([File: stacks-signer/src/v0/signer_state.rs])

### Summary
`LocalStateMachine::stacks_block_arrival` unconditionally checks *every* incoming `NewBlock` event against the signer's currently active `tx_replay_set`, and wipes that replay set whenever the arriving block's `signer_signature_hash` was not recorded as "validated by our replay set" — before it even checks whether the block belongs to the relevant tenure. This mirrors the reported bug class of "a mutable protocol parameter used inconsistently across two points in the flow, letting whoever controls timing distort the outcome" (there, an admin swapping the payout calculator mid-draw; here, a single-slot miner's ordinary block arrival wiping the mid-tenure replay-safety state).

### Finding Description
`tx_replay_set` is part of the signer's `SignerStateMachine`, and is treated as consensus-visible state: it feeds `GlobalStateEvaluator::determine_global_state` and is aggregated across signers via majority-prefix agreement. [1](#0-0) 

`stacks_block_arrival` is the function that updates this local state whenever the node reports processing a new Stacks block: [2](#0-1) 

The replay-clearing branch executes for **every** `NewBlock` event, independent of whether the arriving block has any relationship to the current active-miner tenure the replay set was scoped to protect. Only *after* this unconditional check does the function gate the remaining (parent-tenure) update logic on tenure/consensus-hash and height equality: [3](#0-2) 

So the sequence is: `get_was_block_validated_by_replay_tx(signer_signature_hash, replay_set_hash)` is looked up keyed only on the specific arriving block's hash and the *current* replay-set hash. Any block whose hash was never inserted into `block_validations_by_replay_tx` under that exact replay hash returns `Ok(None)`, and the log message and code path explicitly clear the replay set:

```rust
Ok(None) => {
    info!("Signer State: got a new block during replay that wasn't validated by our replay set. Clearing the local replay set.");
    prior_state_machine.tx_replay_set = ReplayTransactionSet::none();
}
```

A single-slot miner only has to win one sortition and produce *any* ordinary block that the node accepts and emits as `NewBlock` — nothing about that block needs to be "the" replay-relevant block. Because the check runs before the tenure/consensus-hash equality gate, a block from an unrelated tenure (e.g. a block belonging to a different, non-current tenure that the node processes/announces, such as one delivered during catch-up, a delayed announcement, or simply the signer's own miner producing its next ordinary block without including any replay transactions) is sufficient to trip the `Ok(None)` branch and wipe `tx_replay_set`.

This breaks the intended equality/safety guarantee that transaction replay (mandated after a Bitcoin fork to prevent transactions from being silently dropped/duplicated across the reorg) stays enforced until `replay_tx_exhausted` is genuinely observed for a block *actually produced against that replay set*. Instead, replay protection can be discharged by unrelated chain activity that a single miner (who only needs one winning slot to produce ordinary blocks) can supply.

### Impact Explanation
Once `tx_replay_set` is cleared prematurely, the local state machine — and, if enough signers observe similar arrivals and converge, the majority-agreed global state — stops requiring the outstanding replay transactions to be re-included. This causes signers to subsequently pre-commit/sign blocks that omit transactions that were supposed to be replayed to preserve chain-state equivalence across the fork, i.e. a signer ends up signing a block that does not carry the transactions the replay mechanism exists to guarantee. This is a Critical-class outcome under the given rubric: a signer signing a block whose contents are inconsistent with what the (still-required) replay obligation demanded, silently discarding the safety net the replay set was introduced to provide.

### Likelihood Explanation
Triggering the bug requires nothing beyond normal operation of a single miner's winning slot — no majority of signers, no key compromise, and no auth-token access. Any ordinary block that the miner produces and gets accepted by the node during an active replay window (a window that itself is created by a routine Bitcoin fork) is sufficient, because the check in `stacks_block_arrival` fires on the raw `signer_signature_hash` lookup with no relevance/tenure gating.

### Recommendation
Scope the replay-set-clearing check in `stacks_block_arrival` to only consider blocks that are actually relevant to the tenure/miner context the replay set was established for (i.e., perform the tenure/consensus-hash relevance check *before* deciding whether to touch `tx_replay_set`, not after), so that unrelated block arrivals cannot discharge an outstanding replay obligation.

### Proof of Concept
1. Trigger a Bitcoin fork that requires transaction replay (as in the existing `tx_replay.rs` test flow), so all signers populate `tx_replay_set` with the transactions that must be replayed. [4](#0-3) 
2. While replay is still outstanding, have the current miner produce and get accepted an ordinary block whose `signer_signature_hash` was never registered via `get_was_block_validated_by_replay_tx` against the active replay hash (e.g. any block not built through the replay-tx submission path).
3. Observe the signer log "got a new block during replay that wasn't validated by our replay set. Clearing the local replay set." and confirm via `wait_for_replay_set_eq`/state inspection that `tx_replay_set` becomes empty on the affected signer(s), despite the replay transactions never having actually been replayed. [5](#0-4)

    /// Handle a new stacks block arrival
    pub fn stacks_block_arrival(
        &mut self,
        ch: &ConsensusHash,
        height: u64,
        block_id: &StacksBlockId,
        signer_signature_hash: &Sha512Trunc256Sum,
        db: &SignerDb,
        txs: &Vec<StacksTransaction>,
    ) -> Result<(), SignerChainstateError> {
        // set self to uninitialized so that if this function errors,
        //  self is left as uninitialized.
        let prior_state = std::mem::replace(self, Self::Uninitialized);
        let mut prior_state_machine = match prior_state {
            // if the local state machine was uninitialized, just initialize it
            LocalStateMachine::Initialized(signer_state_machine) => signer_state_machine,
            LocalStateMachine::Uninitialized => {
                // we don't need to update any state when we're uninitialized for new stacks block
                //  arrivals
                return Ok(());
            }
            LocalStateMachine::Pending { update, prior } => {
                // This works as long as the pending updates are only burn blocks,
                //  but if we have other kinds of pending updates, this logic will need
                //  to be changed.
                match &update {
                    StateMachineUpdate::BurnBlock(..) => {
                        *self = LocalStateMachine::Pending { update, prior };
                        return Ok(());
                    }
                }
            }
        };

        if let Some(replay_set_hash) = NakamotoBlockProposal::tx_replay_hash(
            &prior_state_machine.tx_replay_set.clone_as_optional(),
        ) {
            match db.get_was_block_validated_by_replay_tx(signer_signature_hash, replay_set_hash) {
                Ok(Some(BlockValidatedByReplaySet {
                    replay_tx_exhausted,
                    ..
                })) => {
                    if replay_tx_exhausted {
                        // This block was validated by our current state machine's replay set,
                        // and the block exhausted the replay set. Therefore, clear the tx replay set.
                        info!("Signer State: Incoming Stacks block exhausted the replay set, clearing the tx replay set";
                            "signer_signature_hash" => %signer_signature_hash,
                        );
                        prior_state_machine.tx_replay_set = ReplayTransactionSet::none();
                    }
                }
                Ok(None) => {
                    info!("Signer State: got a new block during replay that wasn't validated by our replay set. Clearing the local replay set.";
                        "txs" => ?txs,
                    );
                    prior_state_machine.tx_replay_set = ReplayTransactionSet::none();
                }
                Err(e) => {
                    warn!("Signer State: Failed to check if block was validated by replay tx";
                        "err" => ?e,
                        "signer_signature_hash" => %signer_signature_hash,
                    );
                }
            }
        }
