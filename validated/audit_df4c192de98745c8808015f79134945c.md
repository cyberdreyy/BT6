### Title
Cross-user response hijack via unconditional `savedCallbacks` overwrite keyed only by `MessageId` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` stores the caller's `Callback` in `h.savedCallbacks[msg.Body.MessageId]` without checking whether an entry for that `MessageId` already exists, unlike `common.requestCache.NewRequest`, which keys entries by `(sender, id)` and explicitly rejects collisions. Because the map is keyed by `MessageId` alone, a second request that reuses an in-flight `MessageId` — even signed by a different sender — silently overwrites the first caller's saved callback, so the DON's later response to the *original* request is routed to the *second* caller's callback while the original caller's channel is orphaned.

### Finding Description
`HandleLegacyUserMessage` validates the payload/method and then unconditionally writes: [1](#0-0) 

into `h.savedCallbacks`, a `map[string]*savedCallback` keyed only by `msg.Body.MessageId`: [2](#0-1) 

There is no allowlist/authorization check at this point (explicitly a TODO): [3](#0-2) 

When a node later responds, `HandleNodeMessage` -> `handleWebAPITriggerMessage` looks the entry up strictly by `msg.Body.MessageId` (not by original sender), deletes it, and forwards the response to whichever callback is currently stored: [4](#0-3) [5](#0-4) 

Contrast this with `common.requestCache`, used by other handlers, which combines sender and message ID into the cache key and rejects duplicates: [6](#0-5) 

Exploit flow: attacker (any party able to sign a legacy gateway message — signature verification only proves *a* valid key, not authorization, and no allowlist is enforced yet) sends `msg1` and the victim's gateway request also lands with the same `MessageId` (either the attacker predicts/guesses a victim's in-flight `MessageId`, or races two of their own sessions to demonstrate the same primitive flaw). The second `HandleLegacyUserMessage` call overwrites `h.savedCallbacks[MessageId]` with the attacker's `callback2`, orphaning `callback1`. When the DON responds to the *original* request (still tagged with the same `MessageId`), `handleWebAPITriggerMessage` delivers that response to `callback2` instead of `callback1`. The original caller's `gw.ProcessRequest` call (waiting on `callback.Wait(ctx)` in `gateway.go`) times out, and the attacker instead receives the response payload bound to the original message.

### Impact Explanation
This is a request-binding/isolation violation: cross-user response confusion causes (a) denial-of-service — the original requester's callback is orphaned and only resolves via the request-timeout path — and (b) a response-hijack in which an unrelated party's response payload is delivered to the attacker instead. This maps to Chainlink's "unauthorized action on another user's job/request" / cross-user response confusion impact class. Since `web_api_trigger`/`web_api_target` payloads can include data derived from the DON's HTTP/workflow trigger results, the attacker may obtain data intended for the original requester.

### Likelihood Explanation
Feasibility hinges entirely on the attacker's ability to select or guess an in-flight victim `MessageId`; the gateway itself performs no authentication of "who may submit for this DON" beyond a valid ECDSA signature (the allowlist/rate-limiting TODO is not implemented), so submitting a colliding message costs the attacker nothing but generating any signed message with that `MessageId`. If client `MessageId` generation is predictable (sequential counters, timestamps, or workflow-derived identifiers) the attack is trivially repeatable; if fully random/high-entropy, exploitation requires prediction/brute force, which the audit prompt explicitly allows as a precondition, but is not a proven current condition here (client-side ID generation was not part of the code inspected).

### Recommendation
Key `savedCallbacks` by `(sender, MessageId)` (as `common.requestCache` already does) instead of `MessageId` alone, and reject/queue a call to `HandleLegacyUserMessage` if an entry for that composite key already exists (returning an error to the caller instead of silently overwriting). Additionally, validate on `HandleNodeMessage` that the response's implied sender/receiver context matches the entry that was stored, not just the `MessageId`.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build the test handler via `setupHandler(t)` as existing tests do.
2. Craft `msg1` signed by `nodes[0].PrivateKey` (or any key) with `MessageId = "dup-id"`; create `cb1 := hc.NewCallback()`; call `handler.HandleLegacyUserMessage(ctx, msg1, cb1)`.
3. Craft `msg2` — a *different* signer/session — with the same `MessageId = "dup-id"`; create `cb2 := hc.NewCallback()`; call `handler.HandleLegacyUserMessage(ctx, msg2, cb2)` before either resolves.
4. Assert via `handler.mu.Lock(); require.Equal(t, cb2, handler.savedCallbacks["dup-id"].Callback)` that the overwrite occurred.
5. Deliver a `HandleNodeMessage` response corresponding to `msg1`'s `MessageId`/`DonId`/method (`MethodWebAPITrigger`).
6. Assert `cb2.Wait(...)` returns the response (hijack) while `cb1.Wait(...)` times out / never receives a response, proving `callback1.SendResponse` is never invoked and `callback2.SendResponse` receives the response meant for the original caller.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

type globalId struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
