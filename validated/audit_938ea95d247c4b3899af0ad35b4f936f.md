### Title
Unquoted heredoc delimiter in `BashWriter.DotEnvVariables` lets `$()`/backtick command substitution in a dotenv-report value execute during script generation - ([File: helpers/shell_escape.go], [shells/bash.go])

### Summary
`escapeDotEnvValue` in `helpers/shell_escape.go` only escapes `\`, `"`, `\n`, `\r`, leaving `$` and `` ` `` untouched. `BashWriter.DotEnvVariables` in `shells/bash.go` writes these values into an **unquoted** heredoc (`cat << EOF … EOF`, not `<< 'EOF'`), so bash performs parameter/command substitution on the heredoc body when the generated stage script is executed. A value like `$(touch /tmp/pwned)` or a backtick payload will therefore run as a shell command at script-execution time, not merely be stored as inert text in the resulting `.env` file.

### Finding Description
`escapeDotEnvValue` (`helpers/shell_escape.go:139-144`) is a `strings.NewReplacer` that escapes only backslash, double quote, newline, and carriage return — explicitly modeled on what the `godotenv` parser needs unescaped, not on what bash's heredoc expansion needs neutralized (`helpers/shell_escape.go:136-138`). `DotEnvEscape` (`helpers/shell_escape.go:146-167`) wraps each value in literal double quotes (`KEY="value"`) using this replacer, with no `$`/backtick escaping.

`BashWriter.DotEnvVariables` (`shells/bash.go:247-258`) embeds that output between an unquoted heredoc marker:
```go
fmt.Fprintf(&sb, "cat << EOF > %s\n", dotEnvFile)
sb.WriteString(helpers.DotEnvEscape(variables))
sb.WriteString("EOF\n")
```
Because the delimiter `EOF` is not quoted (it would need to be `<< 'EOF'` or `<< "EOF"` to suppress expansion), bash treats the heredoc body as it would a double-quoted string: `$var`, `${var}`, `$(cmd)`, and backtick command substitution are all expanded before the text is written to `dotEnvFile`. Since the double quotes inside the heredoc body (`KEY="..."`) are literal characters written to the output file and have no special meaning to the *outer* shell parsing the heredoc, they do nothing to stop expansion of `$(...)` inside them.

This is reachable whenever a job's `artifacts:reports:dotenv` values (or values consumed as `dotenv` variables from a dependency job) flow into `DotEnvVariables` while generating the bash stage script that later `source`s/exports them — an unprivileged pipeline author fully controls the report file content produced by their own job script (e.g. `echo "KEY=\$(touch /tmp/pwned)" >> report.env`), so this is attacker-controlled input reaching this sink.

Existing checks reviewed:
- `isValidDotEnvKey` only validates the **key**, not the value — no protection for value content.
- `escapeDotEnvValue` was clearly designed to satisfy the dotenv-parser's *unescaping* rules (per the comment referencing `godotenv`'s parser), not to be safe inside an unquoted bash heredoc — it never considered `$`/backtick.
- No other quoting/escaping occurs before the heredoc is written into the generated script by `BashWriter.Finish`, which itself further wraps the whole script body in `eval` (`shells/bash.go:436-440`), meaning the heredoc's command substitution executes as part of the job's own script evaluation with the job's privileges (no privilege escalation, but arbitrary command execution beyond the intended "assign a variable" semantics is possible with attacker-controlled effects).

### Impact Explanation
An unprivileged pipeline author can get arbitrary shell commands executed while their own job script runs (during heredoc expansion), effectively achieving code execution outside the narrow "variable value substitution" contract the dotenv report mechanism is supposed to provide. Within the scoped impact (file read/write/delete outside intended build/cache/artifact roots), since the command runs with the same privileges and working directory as the job itself, this only lets the job do what it could already do by writing an arbitrary shell script in `script:` — it does not cross an isolation boundary between jobs, projects, or escape the executor sandbox. The practical impact is therefore limited to the job's own execution context; there is no elevation of privilege or exfiltration path beyond what the job could already achieve, because the injected commands run with the same permissions/filesystem access as the rest of the job's script.

### Likelihood Explanation
Trivially reproducible: any pipeline author who sets an `artifacts:reports:dotenv` value equal to `$(command)` or a backtick payload will observe the command run when the generated script is executed. No special configuration, executor, or privilege is required beyond defining a `dotenv` artifact/report, which is standard, documented CI functionality available to all pipeline authors.

### Recommendation
Escape `$` and backtick (and ideally also switch to a quoted heredoc delimiter, `<< 'EOF'`, as defense in depth) in `escapeDotEnvValue`/`DotEnvVariables` so that dotenv values can never trigger shell expansion when the heredoc is evaluated. Concretely: add `` "$", "\\$" `` and `` "`", "\\`" `` to the `strings.NewReplacer` in `helpers/shell_escape.go:139-144`, and/or change `shells/bash.go:251` to `cat << 'EOF' > %s` (quoted delimiter disables all expansion inside the heredoc), whichever preserves the intended dotenv semantics without breaking legitimate values containing literal `$`.

### Proof of Concept
```go
// helpers/shell_escape_test.go (new case) or shells/bash_test.go
func TestDotEnvVariables_NoCommandInjection(t *testing.T) {
    variables := map[string]string{"KEY": "$(touch /tmp/pwned)"}
    w := NewBashWriter(testBuild(t), "bash") // build fixture as used elsewhere in bash_test.go
    dotEnvFile := w.DotEnvVariables("report.env", variables)
    script := w.Finish(false)

    _ = os.Remove("/tmp/pwned")
    cmd := exec.Command("bash", "-c", script)
    _ = cmd.Run()

    _, err := os.Stat("/tmp/pwned")
    assert.True(t, os.IsNotExist(err), "command substitution must not execute; /tmp/pwned should not exist")

    content, _ := os.ReadFile(dotEnvFile)
    assert.Contains(t, string(content), `KEY="$(touch /tmp/pwned)"`, "value should be stored literally, not expanded")
}
```
Expected (current, vulnerable) behavior: `/tmp/pwned` is created because bash expands `$(...)` while writing the unquoted heredoc. Expected (fixed) behavior: the assertion `os.IsNotExist(err)` passes and the literal `$(...)` string is preserved in the dotenv file. [1](#0-0) [2](#0-1)

var escapeDotEnvValue = strings.NewReplacer(

	"\"", "\\\"", // Escape double quotes
	"\n", "\\n", // Escape newlines
	"\r", "\\r", // Escape carriage returns

func DotEnvEscape(variables map[string]string) string {
	var sb strings.Builder

	// Sort variables to get deterministic output
	keys := make([]string, 0, len(variables))
	for key := range variables {
		keys = append(keys, key)
	}
	sort.Strings(keys)

	for _, key := range keys {
		if !isValidDotEnvKey(key) {
			// Skip invalid keys
			continue
		}

		value := variables[key]
		fmt.Fprintf(&sb, "%s=\"%s\"\n", key, escapeDotEnvValue(value))
	}

	return sb.String()
}

func (b *BashWriter) DotEnvVariables(baseFilename string, variables map[string]string) string {
