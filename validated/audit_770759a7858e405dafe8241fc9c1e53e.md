### Title
GET /v2/bridge_types/:BridgeName discloses plaintext OutgoingToken to any authenticated caller regardless of role - ([File: core/web/bridge_types_controller.go])

### Summary
`BridgeTypesController.Show` (and `Index`) build the response with `presenters.NewBridgeResource`, which copies `bridges.BridgeType.OutgoingToken` into the JSON field `outgoingToken` with no `omitempty`/redaction and no role check performed in the handler itself. Any caller who can reach `GET /v2/bridge_types/:BridgeName` (or enumerate via `GET /v2/bridge_types`) receives the bridge's outbound credential/token in cleartext.

### Finding Description
`BridgeTypesController.Show` looks up the bridge by name and serializes it directly: [1](#0-0) 

The presenter used for this serialization always includes the raw `OutgoingToken` value with no redaction: [2](#0-1) 

Note the comment on `IncomingToken` ("only provided when creating a Bridge") shows the intent was for `IncomingToken` to be hidden after creation via `omitempty`, but no equivalent protection exists for `OutgoingToken` — it lacks `omitempty` and is populated unconditionally from the stored bridge record in both `Show` and `Index`: [3](#0-2) 

Because the handler performs no role/ownership check before returning the full resource, and the presenter performs no field-level redaction, any client capable of authenticating to the API at all (any valid session or API token, including view/restricted roles) and reaching this route obtains the bridge's outbound token — the credential used by the node to authenticate to the external adapter. The route reachability/role-wrapper gap described in the question (no editor/admin-only wrapper at the route registration) compounds this, but the root cause is independent of that: even with a valid session of any role, the response body itself leaks the secret in plaintext because the presenter never redacts it.

### Impact Explanation
This is a credential/secret disclosure (SECRET_CONFINEMENT violation): a low-privileged, non-admin API consumer can obtain the `OutgoingToken` used by the Chainlink node to authenticate to an external adapter/bridge. An attacker with this token can call the external adapter directly, potentially triggering unauthorized computations, consuming adapter's paid resources/quota, or using it as a stepping-stone against the external adapter's own authorization model. This maps to Chainlink's "secret/key disclosure" bounty impact class.

### Likelihood Explanation
Preconditions are minimal: any valid API session or API token (even one intended to have only view/run privileges) plus knowledge of a bridge name — which is itself trivially obtainable via the unrestricted `GET /v2/bridge_types` `Index` endpoint that returns the same unredacted resource for every bridge, one page at a time. The exploit is a simple two-step GET sequence, fully repeatable, requiring no timing or race conditions.

### Recommendation
Redact `OutgoingToken` (and confirm `IncomingToken`) from `presenters.BridgeResource` for all read paths (`Index`, `Show`) — only return it (if at all) on `Create`/`Update` responses to the creating/authorized caller, or omit it entirely from JSON responses and expose bridge outbound auth only through internal ORM lookups used by the adapter-calling task, never via the HTTP API. Additionally enforce that bridge_types routes are gated by an edit/admin role wrapper at `core/web/router.go`, consistent with other sensitive resource routes.

### Proof of Concept
1. Handler-level Go test using existing test harness in `core/web/bridge_types_controller_test.go`:
   - As an admin/edit-role client, `POST /v2/bridge_types` with a body containing `outgoingToken: "secret-token-value"`.
   - Using a client authenticated with a view-role session (or restricted API token), issue `GET /v2/bridge_types` and assert the returned resource for the created bridge exposes `outgoingToken: "secret-token-value"` in the JSON body.
   - Then issue `GET /v2/bridge_types/:BridgeName` with the same view-role client and assert the response JSON `data.attributes.outgoingToken` equals `"secret-token-value"`.
   - Expected (failing) assertion: the test should assert the token field is empty/absent/redacted for non-privileged callers; current behavior returns the plaintext token, demonstrating the vulnerability.

```go
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
```

```go
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
```
