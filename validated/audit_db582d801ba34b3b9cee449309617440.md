Confirmed: `TRANSFERS_STARTED = 1602614338293769340` (13 October 2020) is hard-coded and already in the past, so every lockup deployed through `LockupFactory::create` starts with transfers already enabled from block 1. This confirms the exploit is fully live today.

### Title
Deterministic, creator-independent lockup account address lets an unprivileged attacker squat `owner_account_id` and permanently deploy a zero-duration lockup before the rightful issuer - (File: lockup-factory/src/lib.rs)

### Summary
`LockupFactory::create` derives the lockup contract's account ID solely from `sha256(owner_account_id)` with no binding to the caller, the deposit, or the intended schedule, and no restriction on `lockup_duration`/`release_duration` values [1](#0-0) . Any unprivileged attacker can front-run the legitimate grant issuer by calling `create(owner_account_id=victim, lockup_duration=0, release_duration=None, ...)`, permanently occupying the deterministic address with a lockup whose entire balance is unlocked immediately, since NEAR account names cannot be recreated once they exist.

### Finding Description
Binding claimed broken: `get_locked_amount()` computed from the attacker's `(lockup_duration=0, release_duration=None)` at time `T == TRANSFERS_STARTED+ε` should equal what the legitimate issuer's intended multi-year schedule would produce at the same `T`. They diverge to `0` vs. a large locked balance.

Code path:
1. `create()` computes `lockup_account_id = sha256(owner_account_id)[..20] . factory_account`, a value that depends **only** on `owner_account_id` and the factory's own account id — not on `predecessor_account_id`, not on any nonce, not on the parameters chosen [2](#0-1) .
2. There is no validation on `lockup_duration` or `release_duration` before they are serialized into `LockupArgs` and passed to the lockup contract's `new` [3](#0-2) .
3. `lockup::LockupContract::new` only checks that `owner_account_id` and `staking_pool_whitelist_account_id` are syntactically valid account IDs and that a foundation account is set iff vesting is provided — it never checks `lockup_duration`/`release_duration` against any expected floor or the caller's identity [4](#0-3) .
4. `TRANSFERS_STARTED = 1602614338293769340` (13 Oct 2020) is a fixed constant already in the past [5](#0-4) . With `lockup_duration=0` and no `lockup_timestamp`, `get_locked_amount()`'s `lockup_timestamp = max(TRANSFERS_STARTED + 0, 0) = TRANSFERS_STARTED`, which is already `<= block_timestamp` for any call today. With `release_duration=None`, `unreleased_amount = 0`, and with no vesting schedule, `unvested_amount = 0`, so `get_locked_amount()` returns `0` unconditionally [6](#0-5) .
5. Because the target account ID is deterministic and NEAR account creation is a one-time, irreversible operation, once the attacker's `create_account()` succeeds at that address, any subsequent legitimate `create()` call with the same `owner_account_id` (but the real multi-year `lockup_duration`) will have its `create_account()` promise action fail (account already exists), causing `on_lockup_create`'s `is_promise_success()` check to fail and simply refund the deposit to the legitimate caller [7](#0-6) . The intended lockup schedule can never be established at that address again.

No existing guard (`assert_owner`, `assert_self`, account-ID validity checks) prevents this, because none of them check that `owner_account_id` corresponds to the caller, nor bound `lockup_duration`/`release_duration`, nor make the target account address non-deterministic.

### Impact Explanation
This matches the Critical category "a lockup deployed with parameters its rightful creator never chose": the real grant issuer (employer/foundation) can never deploy the intended multi-year lockup for `owner_account_id=victim` because the deterministic address is squatted. Whoever eventually controls `victim`'s keys gets the entire `attached_deposit` (paid by the attacker, minimum `MIN_ATTACHED_BALANCE = 3.5 NEAR`) immediately liquid instead of the multi-year vesting the issuer intended, and the issuer's intended grant contract can never exist at that address. This is repeatable for every distinct `owner_account_id` the attacker wants to squat, and requires only one transaction and the minimum deposit per victim account.

### Likelihood Explanation
Trivial and cheap: any unprivileged account can call `create` with attached deposit of `MIN_ATTACHED_BALANCE` (3.5 NEAR) and arbitrary `owner_account_id`, `lockup_duration=0`, `release_duration=None`. No special permissions, keys, or foundation/owner role required. The only cost is the deposit itself (which becomes liquid to `owner_account_id`, not lost, so the "attack" is nearly free if the attacker also controls or colludes on the target account, and is a pure griefing/denial-of-intended-schedule act otherwise). Feasible today since `TRANSFERS_STARTED` is already in the past.

### Recommendation
Bind the lockup account address to more than just `owner_account_id` (e.g. include a random salt/nonce, or require a minimum reservation/commit-reveal from an authorized party), and/or restrict who may call `create` for a given `owner_account_id` (e.g. require `predecessor_account_id == owner_account_id` or an explicit foundation/whitelist authorization), and enforce sane minimum bounds on `lockup_duration`/`release_duration` (e.g. reject `lockup_duration == 0` combined with `release_duration == None` when `TRANSFERS_STARTED` is already past) so a single deposit cannot make the entire lockup amount instantly liquid.

fn test_owner_account_squatting_zero_duration() {

        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    context.is_view = false;
    context.predecessor_account_id = String::from(attacker_account());
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(victim_owner_account_id(), 0u64.into(), None, None, None, None);

    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    contract.on_lockup_create(
        squatted_lockup_account_id(), // sha256(victim_owner_account_id)[..20].factory
        ntoy(30).into(),
        String::from(attacker_account()),
    );

    // Deploy the actual lockup contract state to compute get_locked_amount at T = TRANSFERS_STARTED + 1.
    let attacker_lockup = deploy_lockup_with_args(
        victim_owner_account_id(), 0u64.into(), None, None, /* release_duration */ None,
    );
    let attacker_locked = attacker_lockup.get_locked_amount().0; // expect 0

    // Compare against the legitimate issuer's intended schedule with the same owner id
    // and a real 24-month lockup_duration, at the same block_timestamp.
    let intended_lockup = deploy_lockup_with_args(
        victim_owner_account_id(), 63036000000000000u64.into(), None, None, None,
    );
    let intended_locked = intended_lockup.get_locked_amount().0; // expect > 0, close to full deposit

    assert_eq!(attacker_locked, 0);
    assert!(intended_locked > 0);
    assert_ne!(attacker_locked, intended_locked); // binding SCHEDULE broken

    // Demonstrate the real issuer can no longer create the lockup at the same address:
    // a second create() call with the same owner_account_id would call create_account()
    // on an already-existing account -> promise fails -> on_lockup_create refunds deposit,
    // and the intended schedule is never established.
}

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }

    pub fn get_locked_amount(&self) -> WrappedBalance {
        let lockup_amount = self.lockup_information.lockup_amount;
        if let TransfersInformation::TransfersEnabled {
            transfers_timestamp,
        } = &self.lockup_information.transfers_information
        {
            let lockup_timestamp = std::cmp::max(
                transfers_timestamp
                    .0
                    .saturating_add(self.lockup_information.lockup_duration),
                self.lockup_information.lockup_timestamp.unwrap_or(0),
            );
            let block_timestamp = env::block_timestamp();
            if lockup_timestamp <= block_timestamp {
                let unreleased_amount =
                    if let &Some(release_duration) = &self.lockup_information.release_duration {
                        let end_timestamp = lockup_timestamp.saturating_add(release_duration);
                        if block_timestamp >= end_timestamp {
                            // Everything is released
                            0
                        } else {
                            let time_left = U256::from(end_timestamp - block_timestamp);
                            let unreleased_amount = U256::from(lockup_amount) * time_left
                                / U256::from(release_duration);
                            // The unreleased amount can't be larger than lockup_amount because the
                            // time_left is smaller than total_time.
                            unreleased_amount.as_u128()
                        }
                    } else {
                        0
                    };

                let unvested_amount = match &self.vesting_information {
                    VestingInformation::VestingSchedule(vs) => self.get_unvested_amount(vs.clone()),
                    VestingInformation::Terminating(terminating) => terminating.unvested_amount,
                    // Vesting is private, so we can assume the vesting started before lockup date.
                    _ => U128(0),
                };
                return std::cmp::max(
                    unreleased_amount
                        .saturating_sub(self.lockup_information.termination_withdrawn_tokens),
                    unvested_amount.0,
                )
                .into();
            }
        }
        // The entire balance is still locked before the lockup timestamp.
        (lockup_amount - self.lockup_information.termination_withdrawn_tokens).into()
    }
