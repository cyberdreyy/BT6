### Title
`extractZipFile` performs no path-containment validation, allowing zip-slip write outside extraction root - (File: helpers/archives/zip_extract.go)

### Summary
Unlike the tar+zstd extractor in this same codebase, which explicitly resolves each entry to an absolute path and rejects it with `"cannot be extracted outside of chroot"` if it escapes the target directory, `extractZipFile` and its callers `extractZipDirectoryEntry`/`extractZipSymlinkEntry`/`extractZipFileEntry` use `file.Name` directly with no root-containment check at all. The only check performed anywhere in `ExtractZipArchive` is `errorIfGitDirectory`, which only rejects `.git`-prefixed entries and is unrelated to path traversal.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and for each entry calls `extractZipFile(file)` [1](#0-0) . `extractZipFile` does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to directory/symlink/file handlers that call `os.Mkdir(file.Name, ...)`, `os.Symlink(string(data), file.Name)`, or `os.OpenFile(file.Name, ...)` [2](#0-1) . None of these paths call `filepath.Abs`, `filepath.Join` against a fixed root, or verify a `strings.HasPrefix(path, root+sep)` invariant — `file.Name` (attacker-controlled zip entry name) is used verbatim as an OS path.

The only validation applied before extraction is `errorIfGitDirectory`, which merely detects a leading `.git` path component and logs a warning (it does not abort extraction, since `tracker.actionable` returning true only triggers a log, and extraction proceeds regardless) [3](#0-2) [4](#0-3) . This check also has no bearing on `..` traversal or absolute paths.

Compare this to the sibling `tarzstd` extractor, which contains the exact containment check that is missing here: it computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it if `!strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir` [5](#0-4) . `extractZipFile` has no equivalent join-against-root/prefix-check logic whatsoever — it isn't a case of inconsistent separator normalization between two checks (the "mixed separator bypass" framed by the question), it's that there is no containment check to bypass in the first place.

As for the specific "separator normalization" angle: `zip.Reader.File[i].Name` in Go's standard library is not canonicalized against `..` segments or backslashes by the runtime purely because the writer is untrusted — Go's `archive/zip` package does not sanitize `Name` for extraction safety; that responsibility is left to the caller. Since GitLab Runner's `extractZipFile` performs no `filepath.Clean`, `filepath.Join`-to-root, or prefix check at all, an entry name like `../../etc/passwd` (forward slash, which zip format always uses per the ZIP spec) is passed straight into `os.MkdirAll(filepath.Dir(file.Name), ...)` and then `os.OpenFile(file.Name, ...)`, writing outside the intended extraction directory. On Windows, backslash-separated or drive-absolute names would behave according to `path/filepath` behavior on that GOOS, but the vulnerability doesn't require mismatched separator handling between "validation" and "write" — there is no path-restriction validation stage to diverge from.

### Impact Explanation
Any job that consumes attacker-influenced zip archive content via `ExtractZipFile`/`ExtractZipArchive` (i.e., cache/artifact extraction using the legacy zip extractor `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) can write or overwrite arbitrary files on the runner's build/cache filesystem outside the intended extraction root, including symlink creation to arbitrary targets via `extractZipSymlinkEntry`. This matches the scoped impact: "path-root escape leading to stronger-context overwrite." [6](#0-5) 

### Likelihood Explanation
Preconditions are minimal and match an unprivileged threat model: a job author controls cache/artifact contents that are later extracted by Runner (e.g., a job that produces a crafted zip as a cache/artifact, later restored in the same or a different job/pipeline stage using the legacy zip extractor). No special runner configuration, admin privilege, or executor-specific trust boundary is required. This is a straightforward, repeatable zip-slip pattern.

### Recommendation
In `extractZipFile` (and before dispatching to the directory/symlink/file entry handlers), resolve the destination path relative to the extraction root the same way `tarzstd_extractor.go` does: compute `absPath := filepath.Abs(filepath.Join(root, file.Name))` and reject the entry if `!strings.HasPrefix(absPath, root+string(filepath.Separator)) && absPath != root`. Apply this uniformly before `os.MkdirAll`, `os.Mkdir`, `os.Symlink`, and `os.OpenFile` calls, and additionally validate symlink targets (`extractZipSymlinkEntry`'s link data) against the same root to prevent symlink-based escapes.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Build an in-memory zip via `archive/zip` with an entry named `../evil.txt` (and a variant `..\\evil.txt` to probe separator handling).
2. Extract with `ExtractZipFile`/`ExtractZipArchive` into a temp extraction root `root`.
3. Assert: `evil.txt` should NOT exist outside `root` (e.g., in `root`'s parent directory) — expected/fixed behavior is `extractZipFile` returns an error or the file lands under `root`.
4. With the current unfixed code, assert (to prove the bug) that `os.Stat(filepath.Join(filepath.Dir(root), "evil.txt"))` succeeds, demonstrating escape from the extraction root.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
