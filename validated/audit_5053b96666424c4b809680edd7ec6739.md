### Title
DKG/Vault result export endpoint gated with `RequiresEditRole` exposes raw DKG secret material to non-admin edit-role users - ([File: core/web/vault_controller.go])

### Finding Description
`VaultController.ExportDKGResult` reads the stored DKG result package from the vault ORM and returns the **raw hex-encoded** `ReportWithResultPackage` plus its SHA-256 to the caller: [1](#0-0) . This is the actual DKG/vault secret material described as high-sensitivity in the threat model — not a redacted or metadata-only view.

The route `POST /vault/dkg_results/export` is wired up in `core/web/router.go` and, per the question's stated (and codebase-consistent) gating, protected with `auth.RequiresEditRole`, not `auth.RequiresAdminRole`. The two middleware functions differ meaningfully in `core/web/auth/auth.go`: `RequiresEditRole` allows any user whose role is not `UserRoleView` or `UserRoleRun` — i.e., it accepts both `UserRoleEdit` and `UserRoleAdmin` [2](#0-1) , whereas `RequiresAdminRole` strictly requires `UserRoleAdmin` [3](#0-2) .

Because the export handler is reachable by any authenticated `edit`-role session or API token, an edit-role user — who is not an admin and has no legitimate need to exfiltrate raw DKG result packages — can retrieve the complete vault/DKG secret material for any known `instanceId` simply by knowing/guessing the instance ID (no ownership check is performed on the DKG instance either; `ReadResultPackage` is looked up purely by `InstanceID` with no per-user scoping) [4](#0-3) .

### Impact Explanation
This maps to the Chainlink bounty "sensitive key/secret material disclosure" impact class. The exported artifact is the DKG result/report package tied to the Vault OCR2 plugin's secret-sharing protocol; disclosing it to a lower-trust role than intended undermines the confidentiality guarantee of the DKG/vault subsystem and could aid reconstruction/verification attacks against vault secrets by a user who should only have "edit" (job/config management) privileges, not access to cryptographic secret material.

### Likelihood Explanation
Precondition is possession of a valid edit-role session or API token — a role explicitly weaker than admin and commonly granted to operational/CI users who manage jobs/bridges but are not meant to handle vault key material. No additional bypass is required: the request is a single authenticated `POST` with a valid `instanceId`, fully repeatable, and requires no interaction from the DKG protocol participants.

### Recommendation
Gate `/vault/dkg_results/export` (and any other endpoint returning raw vault/DKG secret material) with `auth.RequiresAdminRole` instead of `auth.RequiresEditRole` in `core/web/router.go`, consistent with the sensitivity of the data returned by `VaultController.ExportDKGResult`.

### Proof of Concept
1. In `core/web/vault_controller_test.go`, set up an authenticated test client with a user of role `sessions.UserRoleEdit` (not `UserRoleAdmin`).
2. Seed a DKG result package via the vault ORM for a known `instanceId`.
3. `POST /v2/vault/dkg_results/export` with `{"instanceId": "<known>"}` using the edit-role session/token.
4. Assert HTTP 200 (not 403) and that the JSON response's `data.attributes` contains the hex-encoded `ReportWithResultPackage`/SHA fields, confirming raw secret material is returned to an edit-role (non-admin) caller — demonstrating the gap versus an intended admin-only invariant.

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
