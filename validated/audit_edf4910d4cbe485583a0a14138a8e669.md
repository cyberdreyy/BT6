### Title
Permanent `stopEpoch` DoS via residual `apr0TotalPrincipal` after APR is set non-zero - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.prepareStopEpochWithApr0` reverts whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0`. Any user can seed `apr0TotalPrincipal` with a dust APR-0 withdraw request while the vault runs at `unscaledApr == 0`; once the honest manager (or `startEpoch` via `setAprsWithBuffer`) sets a non-zero APR, every subsequent `stopEpoch`/`stopEpochWithDuration` call reverts permanently, freezing all vault funds.

### Finding Description
In `requestWithdraw`, when `unscaledApr == 0` and the pool is not closed, `_requestWithdrawApr0` adds the requested amount to `apr0TotalPrincipal` [1](#0-0) . The only place `apr0TotalPrincipal` is cleared is at the end of `prepareStopEpochWithApr0` [2](#0-1) . However, that function reverts earlier if `apr0TotalPrincipal != 0 && unscaledApr != 0` [3](#0-2) .

Nothing else decrements `apr0TotalPrincipal`: `_settleApr0` only moves per-user fields [4](#0-3) , and `_claimFundedWithdrawRequest` deletes `apr0Users[_user]` without touching the global bucket [5](#0-4) . Since `prepareStopEpochWithApr0` is called unconditionally at the top of `stopEpoch`'s settlement path [6](#0-5) , the revert bricks every epoch transition.

### Impact Explanation
Once the invariant `apr0TotalPrincipal == 0 || unscaledApr == 0` is violated, `stopEpoch`/`stopEpochWithDuration` can never succeed: borrower principal and interest cannot be recalled, withdraw requests cannot be funded, and the pool cannot be closed or defaulted. All lender funds (entire TVL plus pending withdraw receipts) are permanently frozen. The trigger is a 1-wei withdraw request costing the attacker nothing, while the enabling APR change is a routine, honest manager operation (`setAprs`, `setAprsWithBuffer`, or the CDO's own APR configuration at `startEpoch`) [7](#0-6) .

### Likelihood Explanation
Requires the vault to run in APR-0 mode at the time of the attacker's request (a supported configuration, exercised by the queue tests), and a later transition to a non-zero APR — a normal operational action. An attacker can also simply pre-seed the bucket and wait, since the freeze persists until governance notices; no race or privileged cooperation is needed. The attacker can even grief retroactively: the dust request need only exist in one epoch.

### Recommendation
Do not revert on the mixed state. Either:
- Settle/expire the outstanding APR0 bucket instead of reverting: e.g., compute `apr0RateByEpoch[epochNumber] = 0`, set `apr0TotalPrincipal = 0`, and let users claim principal at par, or
- Snapshot `unscaledApr` per APR0 request epoch and only apply the APR0 split when it is still 0, otherwise settling principal without interest.

Additionally, allow `apr0TotalPrincipal` to be reduced when APR0 users fully claim settled principal, so stale buckets cannot outlive their accounting purpose.

### Proof of Concept
Foundry fork PoC (against the IdleCreditVault test harness in `test/foundry/IdleCreditVault.t.sol`, using an APR-0 vault):

```solidity
function testPocApr0StopEpochDos() external {
    // Vault configured with unscaledApr == 0 (APR0 mode).
    // 1) Attacker deposits a dust amount and requests withdraw in buffer epoch.
    address attacker = makeAddr('attacker');
    deal(defaultUnderlying, attacker, 1e6);
    vm.startPrank(attacker);
    IERC20Detailed(defaultUnderlying).approve(address(idleCDO), type(uint256).max);
    idleCDO.depositAA(1);                       // dust deposit
    idleCDO.requestWithdraw(1, address(AAtranche)); // seeds apr0TotalPrincipal
    vm.stopPrank();
    assertEq(strategy.apr0TotalPrincipal(), 1);

    // Honest lenders deposit real TVL.
    _depositWithUser(makeAddr('lp'), 1_000_000e6);

    // 2) Honest manager/owner moves the vault to a normal fixed APR.
    //    (or startEpoch is invoked with a configured non-zero APR via setAprsWithBuffer)
    vm.prank(strategy.manager());
    strategy.setAprs(10e18, 10e18);             // unscaledApr != 0 now

    // 3) Any stopEpoch path now reverts forever -> funds frozen.
    vm.prank(manager);
    cdoEpoch.startEpoch();
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 0);

    // The APR0 bucket cannot be cleared: users can only claim principal,
    // which never decrements apr0TotalPrincipal; every future stopEpoch reverts.
}
```

The revert originates at `prepareStopEpochWithApr0` [8](#0-7) , invoked from `stopEpoch` [6](#0-5) .

    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }
