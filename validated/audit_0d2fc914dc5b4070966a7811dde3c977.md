### Title
Zip archive extraction lacks path-traversal validation, allowing writes outside the extraction directory - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile`/`extractZipFileEntry` use `zip.File.Name` verbatim in `filepath.Dir`, `os.MkdirAll`, `os.OpenFile`, `os.Mkdir`, and `os.Symlink` calls without ever verifying that the resolved path stays within the intended extraction root. The only content check performed (`errorIfGitDirectory`) only detects `.git` paths and merely logs a warning; it does not block or sanitize `../` traversal segments. This affects any code path that calls `ExtractZipArchive`/`ExtractZipFile`, including cache/artifact extraction via `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and, for each entry, calls `extractZipFile(file)`: [1](#0-0) 
`extractZipFile` derives the parent directory directly from the attacker-controlled `file.Name` and creates it with `os.MkdirAll`, then dispatches to file/dir/symlink handlers, all of which write using the raw `file.Name`: [2](#0-1) [3](#0-2) 

The only validation applied before extraction is `errorIfGitDirectory`, which checks whether the first path component is `.git` — it has nothing to do with traversal and only produces a warning log, not an extraction abort: [4](#0-3) [5](#0-4) 

Nowhere in this file (or in `path_check_helper.go` / `path_error_tracker.go`) is `filepath.Clean`, `filepath.Rel`, or a "must remain within base directory" check performed against `file.Name`. Since the standard library `archive/zip` reader does not sanitize `File.Name` for traversal sequences either, a crafted entry name such as `../../../../home/gitlab-runner/.bashrc` (or an absolute path) will be used as-is by `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and `os.OpenFile(file.Name, ...)`, writing outside the current extraction working directory.

This code is reachable from the legacy zip extractor used for cache/artifact extraction: `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`'s `Extract()` calls `zip.NewReader` on attacker-influenced archive bytes and passes the result straight to `archives.ExtractZipArchive` with no path filtering: [6](#0-5) 

Cache archives and artifact archives are attacker-influenced: a pipeline author fully controls the *contents* (including the file list/names) of an artifact they generate and upload, and the cache archive is likewise built from files the job creates before upload, and later downloaded/extracted by the same or later job on the runner. If the archive is built by third-party unzip/zip tools or crafted directly (e.g., via a raw multipart/artifact upload API call bypassing the runner's own archiver) an entry name with traversal segments can be included, since Go's `archive/zip` package does not reject such names on read.

### Impact Explanation
If exploited, a job's extraction step (cache restore / artifact download extraction) can write attacker-controlled file content to arbitrary paths reachable by the `gitlab-runner` process user outside the job's build/cache directory — e.g., into shell rc files, cron directories, or other locations under that user's write permissions — enabling persistence or code execution outside the intended executor/workspace confinement, violating the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Feasibility depends on how the caller invokes extraction and whether the current working directory is reliably scoped and whether any additional path validation exists upstream (e.g., in the artifact/cache download commands that call into this extractor) that was not visible in this file. Within `helpers/archives/zip_extract.go` and its direct callers examined (`ziplegacy` extractor), no such traversal check exists. The existing test suite (`helpers/archives/zip_extract_test.go`) only exercises benign filenames and `.git` paths — there is no test validating rejection of `../` sequences, which supports that this path is unguarded at this layer. Whether an unprivileged pipeline author can actually get a `../`-containing name into a cache/artifact zip that reaches this extractor (as opposed to the archive being built exclusively by GitLab Runner's own `zip_create.go`, which may already normalize names) is not fully verifiable from this file alone, and the archiver side was not inspected in this pass — that is a residual uncertainty.

### Recommendation
Add a path-confinement check in `extractZipFile` (or centrally in `ExtractZipArchive`) that: (1) rejects absolute paths, (2) uses `filepath.Clean` on `file.Name`, and (3) verifies the cleaned path does not start with `..` or escape the extraction root (e.g., compare against `filepath.Join(root, "")` with `filepath.Rel` and reject if the result starts with `..`). Treat any violation as a fatal error for that entry (abort extraction), not a suppressed warning like `errorIfGitDirectory` currently does.

### Proof of Concept
```go
// helpers/archives/zip_extract_traversal_test.go
func TestExtractZipFile_PathTraversalRejected(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        f, err := os.Create(fileName)
        require.NoError(t, err)
        zw := zip.NewWriter(f)
        entry, err := zw.Create("../../../../tmp/pwned.txt")
        require.NoError(t, err)
        _, err = entry.Write([]byte("attacker content"))
        require.NoError(t, err)
        require.NoError(t, zw.Close())
        f.Close()

        cwd, _ := os.Getwd()
        err = ExtractZipFile(fileName)

        // Expected (fixed) behavior: extraction fails or is confined
        require.Error(t, err)
        _, statErr := os.Stat("/tmp/pwned.txt")
        assert.True(t, os.IsNotExist(statErr), "file must not be created outside workspace: %s", cwd)
    })
}
```
Currently, running this against the unmodified code creates `/tmp/pwned.txt` and returns no error, demonstrating the traversal write succeeds; after the recommended fix, the extraction should abort/skip the entry and the assertion should pass.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
