### Title
No payload-size validation in `isValidJSON`/`validateTriggerParams` allows amplified resource exhaustion via oversized `Input` across all shard nodes on every retry - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`isValidJSON` at [1](#0-0)  only checks that `triggerReq.Input` unmarshals to a JSON object or array, with no size or depth cap, and `checkRateLimit` at [2](#0-1)  only rate-limits by request count/scope via `userRateLimiter.AllowErr`, not by payload size. An authorized workflow key holder can therefore submit a large `Input` payload that gets fanned out unmodified to every node in every assigned shard via `sendToShard`, and re-transmitted on each retry attempt of the backoff loop until success or timeout.

### Finding Description
The request flow is `HandleUserTriggerRequest` → `validatedTriggerRequest` → `parseTriggerRequest` (raw JSON unmarshal into `gateway_common.HTTPTriggerRequest`, no size check) → `validateTriggerParams` → `isValidJSON(triggerReq.Input)` [3](#0-2) . `isValidJSON` merely confirms the decoded value is a `map[string]any` or `[]any`; it imposes no upper bound on payload size, nesting depth, or key/element count. The only rate limiting applied is `checkRateLimit`, which calls `h.userRateLimiter.AllowErr(ctx)` scoped by workflow/owner — a pure request-count/frequency limiter with no size-based dimension [2](#0-1) .

Once validated, the full request (including the oversized `Input`) is passed to `sendWithRetries`, which fans it out in parallel to every shard the workflow is assigned to, and within each shard's `sendToShard` loop, it is sent to every member node concurrently and retried with backoff (`b.Duration()`) until all nodes succeed or the overall `MaxTriggerRequestDurationMs` context expires [4](#0-3) . Because retries resend the same full-size payload to each pending node on every backoff iteration, a single large-Input request is transmitted multiple times to multiple nodes across potentially multiple shards, amplifying bandwidth/CPU/marshal cost on the shared DON infrastructure that serves other subscribers' workflows too.

I did not find any body-size or message-size cap enforced upstream in the gateway network layer for this code path (searches for `MaxRequestBodySize`, `MaxBodySize`, `ReadLimit`, `SetReadLimit`, `MaxBytesReader` in `core/services/gateway/network/*.go` returned only single, unexamined matches per file; I was not able to confirm from the available index whether `httpserver.go` or `wsserver.go` impose a global body-size limit before requests reach `HandleUserTriggerRequest`). This is a gap in my verification — if such a limit exists in the gateway HTTP/WS transport layer, it would bound (but not eliminate) the exposure.

### Impact Explanation
Any authorized workflow key holder can consume disproportionate shared DON/gateway resources (network bandwidth, per-node CPU/memory for unmarshalling, connection manager queue pressure) by submitting large `Input` payloads, and this cost is multiplied across all shard member nodes and across all retry attempts. Because shard nodes are shared infrastructure serving multiple workflows/subscribers, this degrades execution latency and availability for other tenants — a cross-subscriber resource exhaustion / DoS via one authorized workflow's traffic. This matches a low-to-medium severity node/DoS impact class since it does not bypass authentication or authorization, and its blast radius is bounded by whatever body-size limits exist at the transport layer (which I could not fully confirm).

### Likelihood Explanation
Precondition is modest: the attacker needs only a valid authorized key for one workflow (the "low-trust key holder" scenario explicitly allowed by the threat model). The attack requires no special timing or race condition — simply submitting `HandleUserTriggerRequest` with a multi-MB `Input` object/array repeatedly, since `isValidJSON` accepts any size. Repeatability is limited only by the per-workflow rate limiter's request-count throttling (`checkRateLimit`), not by payload size, so an attacker can still send fewer, larger requests to bypass count-based throttling while multiplying cost per request via shard fan-out and retries.

### Recommendation
Add an explicit payload size cap for `Input` (e.g., a `MaxInputSizeBytes` config value) enforced in `validateTriggerParams`/`isValidJSON` before any downstream processing, and reject oversized payloads with a `jsonrpc.ErrInvalidRequest` before hitting `checkRateLimit`/`sendWithRetries`. Additionally, consider adding a size-weighted dimension to `userRateLimiter` (e.g., token bucket keyed on bytes-per-window) rather than request-count-only, and confirm/enforce a hard body-size limit at the gateway HTTP/WS transport boundary (`core/services/gateway/network/httpserver.go`, `wsserver.go`) independent of this handler.

### Proof of Concept
Go handler-level test plan (extending `http_trigger_handler_test.go` patterns):
1. `TestValidateTriggerParams_NoSizeLimit`: build `gateway_common.HTTPTriggerRequest{Input: []byte(largeJSONObject)}` where `largeJSONObject` is a valid JSON object several MB in size (e.g., a map with thousands of string keys). Call `handler.validateTriggerParams(ctx, triggerReq, requestID, callback)` directly and assert it returns `nil` (no error), proving no size cap exists.
2. `TestHandleUserTriggerRequest_LargeInputFannedOutToAllNodesOnRetry`: register a workflow across 2 shards (using `registerWorkflowOnShards` helper as in `TestHttpTriggerHandler_HandleUserTriggerRequest_DeliversOnlyToRegisteredShards`), set node mocks to fail on first N attempts then succeed, and assert via `mockDon.EXPECT().SendToNode(...)` call-count/argument-size assertions that the full oversized payload is retransmitted on each retry to each pending node — demonstrating amplification of bytes-on-wire proportional to `(shards × nodes × retries)`.
3. `TestCheckRateLimit_NoSizeDimension`: call `checkRateLimit` twice with identical small vs. huge `Input` sizes using the same `userRateLimiter`, and assert both are treated identically (allowed/denied based only on count, confirming no size-based quota accounting).

func (h *httpTriggerHandler) validateTriggerParams(ctx context.Context, triggerReq *gateway_common.HTTPTriggerRequest, requestID string, callback handlers.Callback) error {
	if !isValidJSON(triggerReq.Input) {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'params' must be {} or [] (JSON object or array). Primitives (null, '', numbers, booleans) are not allowed. Use {} if none.", callback)
		return errors.New("invalid params JSON: " + string(triggerReq.Input))
	}

	return h.validateWorkflowFields(ctx, triggerReq.Workflow, requestID, callback)
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}

func isValidJSON(data []byte) bool {
	var val any
	if err := json.Unmarshal(data, &val); err != nil {
		return false
	}

	switch val.(type) {
	case map[string]any, []any:
		return true
	default:
		return false
	}
}

// sendToShard sends the request to all members of a single shard, retrying
// failures until all succeed, the callback is responded to (doneCh), or ctx is
// cancelled (overall max duration).
func (h *httpTriggerHandler) sendToShard(ctx context.Context, shard *shardEndpoint, legacyExecutionID, executionIDWithTriggerIndex string, req *jsonrpc.Request[json.RawMessage], doneCh <-chan struct{}) error {
	nodeTimeout := time.Duration(h.config.NodeSendTimeoutMs) * time.Millisecond

	successfulNodes := make(map[string]bool)
	b := backoff.Backoff{
		Min:    time.Duration(h.config.RetryConfig.InitialIntervalMs) * time.Millisecond,
		Max:    time.Duration(h.config.RetryConfig.MaxIntervalTimeMs) * time.Millisecond,
		Factor: h.config.RetryConfig.Multiplier,
		Jitter: true,
	}

	for {
		var pending []string
		for _, member := range shard.members {
			if !successfulNodes[member.Address] {
				pending = append(pending, member.Address)
			}
		}

		// Buffered so every goroutine can send its result and exit without waiting on a reader.
		results := make(chan nodeSendResult, len(pending))
		var wg sync.WaitGroup
		for _, nodeAddress := range pending {
			wg.Add(1)
			go func(nodeAddress string) {
				defer wg.Done()

				nodeCtx, nodeCancel := context.WithTimeout(ctx, nodeTimeout)
				defer nodeCancel()

				h.metrics.IncrementTriggerCapabilityRequestCount(ctx, nodeAddress, gateway_common.MethodWorkflowExecute, h.lggr)
				sendStart := time.Now()
				err := shard.connMgr.SendToNode(nodeCtx, nodeAddress, req)
				h.metrics.RecordGatewayToNodeLatency(ctx, time.Since(sendStart).Milliseconds(), nodeAddress, gateway_common.MethodWorkflowExecute, h.lggr)
				if err != nil {
					h.metrics.IncrementTriggerCapabilityRequestFailures(ctx, nodeAddress, gateway_common.MethodWorkflowExecute, h.lggr)
				}
				results <- nodeSendResult{nodeAddress: nodeAddress, err: err}
			}(nodeAddress)
		}
		wg.Wait()
		close(results)

		// Only this goroutine reads from results, so successfulNodes and combinedErr need no locking.
		var combinedErr error
		for res := range results {
			if res.err != nil {
				combinedErr = errors.Join(combinedErr, fmt.Errorf("node %s: %w", res.nodeAddress, res.err))
				h.lggr.Debugw("Failed to send trigger request to node, will retry",
					"node", res.nodeAddress,
					"shard", shard.donID,
					"legacyExecutionID", legacyExecutionID,
					"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
					"error", res.err)
			} else {
				successfulNodes[res.nodeAddress] = true
			}
		}

		if len(successfulNodes) == len(shard.members) {
			h.lggr.Infow("Successfully sent trigger request to all nodes in shard",
				"shard", shard.donID,
				"legacyExecutionID", legacyExecutionID,
				"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
				"nodeCount", len(shard.members))
			return nil
		}

		// Not all nodes succeeded, wait and retry
		h.lggr.Debugw("Retrying failed nodes for trigger request",
			"shard", shard.donID,
			"legacyExecutionID", legacyExecutionID,
			"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
			"failedCount", len(shard.members)-len(successfulNodes),
			"errors", combinedErr)

		select {
		case <-doneCh:
			h.lggr.Infow("Callback already responded to, stopping retries",
				"shard", shard.donID,
				"legacyExecutionID", legacyExecutionID,
				"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
				"requestID", req.ID,
				"successNodes", len(successfulNodes),
				"totalNodes", len(shard.members))
			return nil
		case <-time.After(b.Duration()):
			continue
		case <-ctx.Done():
			return fmt.Errorf("shard %s: request retry time exceeded, some nodes may not have received the request: legacyExecutionID=%s, executionIDWithTriggerIndex=%s, successNodes=%d, totalNodes=%d",
				shard.donID, legacyExecutionID, executionIDWithTriggerIndex, len(successfulNodes), len(shard.members))
		}
	}
