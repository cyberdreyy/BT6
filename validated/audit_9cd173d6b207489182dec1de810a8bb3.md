### Title
Multisig request can execute with confirmations from removed members, bypassing the confirmation threshold - ([File: multisig2/src/lib.rs])

### Summary
`delete_member` in the multisig2 contract removes a member's own outstanding requests but does not purge that member's existing confirmations from *other* pending requests. A confirmation cast by a member before removal remains counted toward `num_confirmations` even after the member is deleted, letting a request execute with fewer live-member approvals than the configured threshold `K`.

### Finding Description
`confirm()` tracks approvals in a `HashSet<String>` keyed by `member.to_string()` and executes the request once `confirmations.len() + 1 >= self.num_confirmations`: [1](#0-0) 

When a member is removed via the `DeleteMember` action, `delete_member` only cleans up requests that were *originated* by the removed member (`r.member == member`) and their `num_requests_pk` entry: [2](#0-1) 

It never scans `self.confirmations` to strip the removed member's entry from confirmation sets of requests raised by *other* members. So if member `A` confirmed request `R` (raised by `B`) before `A` is deleted from the multisig (via a separate, properly-approved `DeleteMember{member: A}` request), `R`'s confirmation set still contains `A`'s string identity. A subsequent `confirm()` call by any remaining live member `C` only checks that `C` hasn't already confirmed and that `len()+1 >= num_confirmations`; it never re-validates that the existing entries in `confirmations` still belong to current `self.members`: [3](#0-2) 

The equality this contract is expected to preserve is:
`confirmations counted toward execution == confirmations from accounts that are currently members`.
After a `DeleteMember` action, this breaks to:
`confirmations counted == (confirmations from current members) + (stale confirmations from removed members)`,
so a request can execute with only `K-1` (or fewer) genuinely live approvals.

### Impact Explanation
This crosses the "multisig request executed below threshold" boundary called out as Critical: an attacker (or colluding minority) who can get one confirmation cast before being removed can later have a single remaining collaborator complete an otherwise `K`-of-`N` guarded action (transfer, `AddKey`, `DeployContract`, etc.) using the leftover stale confirmation to make up the count. This effectively moves NEAR (or executes privileged actions) with fewer independent authorizations than the multisig's configured security threshold guarantees.

### Likelihood Explanation
Requires no privileged access beyond being (at some point) a legitimate multisig member who confirms a request and is later removed, and one remaining live member to complete confirmation later — a plausible operational sequence (e.g., key rotation, offboarding a team member) rather than a contrived attack, so likelihood is realistic in normal multisig lifecycle usage, not merely theoretical.

### Recommendation
When executing `DeleteMember`, iterate all pending `requests`/`confirmations` entries and remove the deleted member's identity string from every confirmation set (not only requests it originated), or alternatively re-validate at `confirm()`/execution time that every entry in a request's confirmation set still belongs to `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy multisig2 with members `[A, B, C]`, `num_confirmations = 2`.
2. `A` calls `add_request_and_confirm(R)` where `R` is a `Transfer` action to an attacker-controlled account → `confirmations[R] = {A}`.
3. Separately, members `B` and `C` approve and execute a `DeleteMember{member: A}` request (a normal 2-of-3 governance action) — `A` is removed from `self.members`, but per `delete_member` logic, `R` (raised by `A`... note: to keep `R` alive it should be raised by `B` or `C`, not `A`, so that `delete_member`'s originator-only cleanup does not delete it). Re-run: have `B` raise and confirm `R` instead of `A`, so `confirmations[R] = {A, B}` after `A` also confirms it.
4. `B` and `C` then execute `DeleteMember{member: A}` — `A` is removed; `R` survives because its originator is `B`, and `confirmations[R]` still contains `A`.
5. `C` calls `confirm(R)`. `confirmations.len()+1 = 3 >= 2`, so `R` executes with `A`'s stale confirmation plus `C`'s live one, transferring funds despite `A` no longer being a member — only `B` (implicit, via `confirmations[R]` add) and `C` truly authorized post-removal, but the code accepted a confirmation from a non-member.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
