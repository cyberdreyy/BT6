### Title
Local signature-rejection can be overridden by peer signatures without re-validation, allowing a signer to co-sign an already-invalidated block - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` (the handler that tallies *other* signers' `BlockAccepted` signatures) never checks the local signer's own validity verdict (`block_info.valid`) or re-runs `check_block_against_signer_db_state` before it tallies weight, calls `block_info.mark_locally_accepted(true)`, and broadcasts the assembled signature set to the node. Every other path that puts a signature over a block — `handle_block_pre_commit` (pre-commit threshold) and `handle_block_validate_response` — explicitly re-checks chainstate consistency immediately before signing or advancing state, precisely because time passes and the chain can change between validation and signature. `store_and_process_block_signature` is the one path that skips this check.

### Finding Description
The event flow is:

1. A signer proposes/validates a block and may reject it locally (`mark_locally_rejected`, `valid = Some(false)`), stored via `signer_db.insert_block`. [1](#0-0) 
2. Later, this signer's `handle_block_signature` receives *other* signers' `BlockAccepted` messages for the same `signer_signature_hash`. The recovered signer's identity is verified (`is_valid_signer`), and `store_and_process_block_signature` is invoked. [2](#0-1) 
3. Inside `store_and_process_block_signature`, the code stores the incoming signature, checks only `block_info.signed_group.is_some()` (already-broadcast guard) — **not** `block_info.valid` — tallies weight from `get_block_signatures`, and once weight ≥ threshold calls `block_info.mark_locally_accepted(true)` and `broadcast_signed_block`. [3](#0-2) 

Per `docs/signer-flows.md`, the state machine's own documented invariant is that "local state is reachable from anything not yet global," i.e. `LocallyRejected -> LocallyAccepted` is a legal transition in `BlockInfo::check_state`. [4](#0-3)  Combined with the missing `valid`/chainstate re-check in `store_and_process_block_signature`, a signer that locally rejected a block (e.g. because it failed `check_block_against_signer_db_state` — non-canonical parent, conflicting sibling, stale tenure, etc.) will still count enough external signatures toward the group threshold, flip the block to `LocallyAccepted`, and **broadcast the aggregated signature set to the stacks-node** via `broadcast_signed_block`, contributing its own visibility/relay of an invalid/conflicting block into the network path that ultimately pushes it to `POST /v3/block_proposal` consumers and staging.

This breaks the "signed vs validated" equality that every other signature-producing path enforces: `handle_block_pre_commit` re-runs `check_block_against_signer_db_state` right before signing and will reject instead if state changed, [5](#0-4)  and `handle_block_validate_ok` does the same before pre-committing. [6](#0-5)  `store_and_process_block_signature` has no equivalent gate.

### Impact Explanation
If reachable, this lets the local signer relay/accept-as-locally-accepted a block it had already determined to be invalid or conflicting, purely on the basis of a majority (or a supermajority quorum) of other signers signing — i.e., a signer's own rejection is silently discarded and superseded by peer signatures without a fresh consistency check. This maps to the "a rejection recounted as an accept" / "signer signing an invalid/non-canonical/conflicting block" impact class the rules define as Critical.

### Likelihood Explanation
I was not able to fully confirm this within the available iterations. Two things remain unverified due to tool-call exhaustion:
- The exact semantics of `BlockInfo::check_state`/`mark_locally_accepted` — whether the implementation actually permits `LocallyRejected -> LocallyAccepted` in code (only the doc comment was found, not the enforcing function body).
- Whether `mark_locally_accepted` internally re-derives/re-checks anything I haven't seen (I could not retrieve the function bodies for `mark_locally_accepted`, `mark_locally_rejected`, and `check_state` before running out of iterations).

If `check_state` in fact forbids `LocallyRejected -> LocallyAccepted` (i.e., a rejected block is a dead end locally), this finding is invalid — `mark_locally_accepted` would simply error and (per the `unwrap_or_else`/`has_reached_consensus` guard pattern used elsewhere) the code would just log a warning and still proceed to `broadcast_signed_block` regardless of the error (note line 2528-2532 discards the error unless `!has_reached_consensus()`, and then only warns — it does not return/abort broadcasting). That last point is significant: even if `mark_locally_accepted` returns an `Err`, the current code does **not** bail out of `store_and_process_block_signature`; it falls through to `broadcast_signed_block` unconditionally. [7](#0-6)  That fall-through means the broadcast happens regardless of whether the local mark-accepted succeeded, independent of the `check_state` question above.

### Recommendation
- In `store_and_process_block_signature`, check `block_info.valid` (and/or re-run `check_block_against_signer_db_state`) before tallying/accepting threshold-crossing peer signatures, mirroring the re-check already done in `handle_block_pre_commit` and `handle_block_validate_ok`.
- Make the `mark_locally_accepted` error path abort the broadcast rather than only warning, so a failed state transition cannot be silently overridden by continuing to `broadcast_signed_block`.

### Proof of Concept
Not independently reproduced. The described flow requires: (1) the local signer locally rejects a block via a chainstate/conflict check (`mark_locally_rejected`), then (2) a sufficient set of other signers' `BlockAccepted` messages (which, under the crafted-analog rules, could stem from a stale/racing majority state rather than a genuinely colluding majority) arrive and are processed by `handle_block_signature` → `store_and_process_block_signature` for the same block hash, driving weight past `compute_voting_weight_threshold` without the local rejection ever being reconsidered against current chainstate. Confirming this end-to-end requires inspecting `BlockInfo::mark_locally_accepted`/`check_state` in `signerdb.rs`, which I was unable to retrieve before the tool budget was exhausted.

**Confidence caveat:** Because the enforcing `check_state`/`mark_locally_accepted` implementation could not be retrieved, I cannot state with certainty that this is exploitable rather than blocked by an internal state-machine guard. I recommend a Devin session with full repository access to read `stacks-signer/src/signerdb.rs` (`BlockInfo::check_state`, `mark_locally_accepted`, `mark_locally_rejected`) to conclusively confirm or refute this analog before treating it as validated.

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }

Canonical paths shown; the exact rule in `BlockInfo::check_state` is: either
local state is reachable from anything not yet global, `PreCommitted` only from
`Unprocessed`, and each global state is unreachable from the other.

Timestamps: `approved_time` is stamped at pre-commit _or_ local acceptance
(first wins), `signed_self` only when we sign, `signed_group` when the group
threshold is observed.

> `mark_locally_accepted`, `mark_globally_accepted`, `mark_locally_rejected`,
