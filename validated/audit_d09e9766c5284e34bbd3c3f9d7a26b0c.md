## Analysis Summary

Reducing the external report to its core invariant: **a caller-facing entry point can skip a security-critical step (nonce accounting) when routed through an indirect/aliased identity path.** The Aptos-native analog I found is in `aptos_framework::staking_contract`, where the beneficiary-redirection check in `distribute_internal()` is keyed off the *current* operator address rather than the *actual recipient identity* recorded in the distribution pool, so a former operator's pending commission bypasses their configured beneficiary once `switch_operator()` has been called. [1](#0-0) 

### Title
Beneficiary redirection is bypassed for a former operator's already-recorded commission distribution after `switch_operator()` - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`distribute_internal()` redirects a distribution-pool payout to `beneficiary_for_operator(operator)` only when the recorded shareholder address equals the `operator` parameter passed into the function. After `switch_operator()`, the `StakingContract` (including its `distribution_pool`) is re-keyed to the *new* operator, but a commission distribution recorded for the *old* operator remains a shareholder entry under the old operator's address. When that distribution is later paid out (via the now permissionless `distribute()` entry function), `operator` refers to the new operator, so `recipient == operator` is `false` for the old operator's entry, and the funds are sent directly to the old operator's raw address instead of their configured beneficiary.

### Finding Description
`switch_operator()` calls `request_commission_internal()` before re-keying the contract to the new operator: [2](#0-1) 

`request_commission_internal()` records the unlocked commission as a distribution owed to `operator` (i.e., the *old* operator at that point in the call) inside the staking contract's shared `distribution_pool`: [3](#0-2) 

That same `distribution_pool` object is then carried over and stored under the *new* operator's key in `Store.staking_contracts`: [4](#0-3) 

Because the commission was unlocked from the stake pool but had not yet cleared the pool's lockup period, it remains an un-redeemed shareholder entry (keyed by the *old* operator's address) inside the pool. Later, when the lockup expires and anyone permissionlessly calls `distribute(staker, new_operator)` — or a staker calls `unlock_stake`/`request_commission` for the new operator, which internally calls `distribute_internal` first — the function is invoked with `operator = new_operator`: [5](#0-4) 

Inside `distribute_internal`, the loop iterates all shareholders of the pool, including the stale entry recorded for the old operator, and only substitutes the beneficiary when `recipient == operator`: [1](#0-0) 

Since `recipient` here is the *old* operator's address and `operator` is the *new* operator's address, this check is always false for the stale entry, so `aptos_account::deposit_coins` sends the funds straight to the old operator's account address, completely skipping the `beneficiary_for_operator()` lookup that the old operator had configured via `set_beneficiary_for_operator`: [6](#0-5) 

### Impact Explanation
This breaks the beneficiary-payout invariant required for stake/commission flows: a commission payout that should be routed to the operator's designated beneficiary (per `Required Impacts`: "Operator commission, beneficiary payout ... corruption that credits the wrong account") is instead credited to the operator's own raw address. This is significant for operators who rely on beneficiary redirection specifically because their operator key is a hot/automated node-signing key that they don't want holding funds (a common operational security pattern), or because the operator address itself is a custodial/cold-storage-separated setup. The mis-delivered funds land in an account the beneficiary configuration was explicitly designed to avoid, and the trigger (calling `distribute()`) is fully permissionless and requires no special role.

### Likelihood Explanation
The trigger sequence relies only on standard, unprivileged staking contract usage:
1. Staker creates a staking contract with `operator1` and non-zero commission.
2. `operator1` calls `set_beneficiary_for_operator(operator1, beneficiary1)`.
3. Staker calls `switch_operator()`/`switch_operator_with_same_commission()` to move to `operator2`, which internally calls `request_commission_internal()` for `operator1`, unlocking pending commission and recording it in the shared `distribution_pool` under `operator1`'s address.
4. Once the stake pool's lockup period naturally expires, anyone (no signer/role check) calls `distribute(staker_address, operator2)`.

No abnormal timing or race condition is required — this is a straightforward and reachable sequence of publicly documented function calls.

### Recommendation
In `distribute_internal`, do not use the function's `operator` parameter to decide beneficiary substitution. Instead, persist a mapping from each historical operator's distribution-pool shareholder entry to the operator address that entry actually belongs to, or record the resolved beneficiary at the time the distribution is created (in `add_distribution`/`request_commission_internal`) rather than resolving `beneficiary_for_operator` lazily at withdrawal time using the *current* operator's identity.

### Proof of Concept
1. `staker` calls `create_staking_contract(staker, operator1, voter, principal, commission_percentage=10, seed)`.
2. `operator1` calls `staking_contract::set_beneficiary_for_operator(operator1, beneficiary1)`.
3. Validator joins validator set, epoch(s) pass, pool accrues rewards.
4. `staker` calls `staking_contract::switch_operator_with_same_commission(staker, operator1, operator2)`. Internally this calls `request_commission_internal` for `operator1`, unlocking commission and creating a `distribution_pool` shareholder entry keyed to `operator1`'s address (see `staking_contract.move:791-805`, `637-661`).
5. Fast-forward past the stake pool's lockup expiration (`stake::fast_forward_to_unlock`).
6. Anyone calls `staking_contract::distribute(staker_address, operator2)`.
7. Observe: the unlocked commission amount is deposited directly to `operator1`'s address, not to `beneficiary1`, even though `beneficiary_for_operator(operator1) == beneficiary1` at all times — confirming the beneficiary redirect in `distribute_internal` (`staking_contract.move:895-898`) never triggers for `operator1`'s entry once the contract has been re-keyed to `operator2`. [7](#0-6)

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
