### Title
Network-level errors from presigned cache URL requests leak the full signed URL (including signature query parameters) into job trace output - (File: commands/helpers/cache_extractor.go)

### Summary
When a GET request to a presigned cache URL fails at the network level (before any HTTP response is received), `getCache` wraps the raw `*url.Error` returned by `http.Client.Get` without ever passing it through `url_helpers.CleanURL`. This raw error—whose `Error()` string embeds the complete request URL, including query-string signature parameters—propagates unmodified through `download`, `doRetry`, and the retry-loop logging into `warningln(err)`, which prints it to the job's stdout/trace.

### Finding Description
`downloadPresignedSequential` calls `c.getCache(selectedURL)` with the full, unredacted presigned URL: [1](#0-0) 

`getCache` only sanitizes the URL for the *success* path (`cleanedURL := url_helpers.CleanURL(selectedURL)` is computed later, only after a response is obtained). On failure of `c.getClient().Get(rawURL)` itself (e.g. connection reset, DNS failure, TLS error, or an unroutable host), the raw `*url.Error` from `net/http` is wrapped as-is: [2](#0-1) 

`net/http`'s `*url.Error.Error()` formats as `"<Op> \"<URL>\": <Err>"`, so `URL` there is the exact request URL passed to `Get`, including the raw query string with the presigned signature — this string is never passed through `CleanURL` anywhere on this failure path.

That error flows up through `download` unmodified (no wrapping/redaction in `download`, `handlePresignedURL`, or `downloadPresignedSequential`): [3](#0-2) 

It reaches `doRetry`, which is type-checked only for `retryableErr` to decide whether to retry, and logs the *raw* error via `logrus.WithError(err).Warningln("Retrying...")` on every retry attempt, then returns the same raw error once retries are exhausted: [4](#0-3) 

Finally, `Execute` calls `warningln(err)` on the returned error, which logs it via `logrus.Warningln(args)` directly to the job's captured output: [5](#0-4) 

No existing check intervenes: `CleanURL` is only applied to `selectedURL`/`cleanedURL` used in the "Downloading … from …" success-path log line, not to the error value returned from `getClient().Get()`. This is exactly the gap the question describes.

### Impact Explanation
A presigned S3/GCS/Azure cache URL contains a time-limited but fully capable signature (typically valid for GET, sometimes with broader scope depending on how the signing was configured). If it leaks into job trace output, anyone who can view that job's log (which may include other project members, or in shared/log-forwarding contexts, differently-privileged users) can reuse the URL to fetch — or in some signing schemes tamper with — the cache object directly from the storage backend, bypassing Runner/GitLab Rails authorization for that resource. This matches the scoped impact: cross-project/user exfiltration of a cache-bucket signature.

### Likelihood Explanation
This is straightforwardly triggerable by an unprivileged pipeline author: configure a job to use a cache with a presigned backend, and cause the download request to fail after the URL is generated by GitLab but before the response headers are read — e.g., by influencing network conditions the job's runner reaches (transient connectivity issues, a MITM/reset, or, if the runner network policy allows, forcing a bad response). No special runner privilege or admin misconfiguration is required beyond ordinary presigned-cache usage, and the retry loop (default `Retry: 2`) makes the raw error print multiple times (once per "Retrying..." log line) plus once at final failure, increasing exposure odds within a single job run.

### Recommendation
Sanitize network-level errors before they leave `getCache`/`downloadPresignedSequential`/`tryPresignedParallelDownload`/`presignedRangeFetchChunk`. Specifically, wrap or rewrite errors returned by `http.Client.Get`/`Do` so any embedded URL is passed through `url_helpers.CleanURL` (or replaced with a generic descriptor) before being returned as `retryableErr`, and ensure `retry_helper.go`'s `logrus.WithError(err).Warningln("Retrying...")` and `warningln` never emit an unsanitized `*url.Error`. A general approach: implement an error-transform step that detects `*url.Error` and rebuilds it with `CleanURL(e.URL)` substituted for the raw URL before wrapping/logging.

### Proof of Concept
```go
func TestGetCache_LeaksPresignedURLOnNetworkError(t *testing.T) {
    // Start a listener then immediately close it to force a connection-refused/reset error,
    // simulating a mid-request network failure against a "presigned" URL with a signature query.
    ln, _ := net.Listen("tcp", "127.0.0.1:0")
    addr := ln.Addr().String()
    ln.Close() // now nothing is listening -> connection refused

    signedURL := fmt.Sprintf("http://%s/bucket/cache.zip?X-Amz-Signature=SUPERSECRETSIG&X-Amz-Expires=3600", addr)

    c := &CacheExtractorCommand{
        URL: signedURL,
        retryHelper: retryHelper{Retry: 0, RetryTime: 0},
    }
    c.File = filepath.Join(t.TempDir(), "cache.zip")

    r, w, _ := os.Pipe()
    origStdout := os.Stdout
    os.Stdout = w
    defer func() { os.Stdout = origStdout }()

    err := c.doRetry(c.download)

    w.Close()
    out, _ := io.ReadAll(r)

    require.Error(t, err)
    require.Contains(t, err.Error(), "X-Amz-Signature=SUPERSECRETSIG") // demonstrates leak in returned error
    require.NotContains(t, string(out), "X-Amz-Signature=SUPERSECRETSIG",
        "presigned signature must never appear in job trace/log output")
}
```
Expected (current) behavior: the assertion on `err.Error()` passes (confirming the signature is embedded in the raw error), and if `warningln(err)` is exercised in an `Execute`-level test capturing stdout, the signature also appears in captured trace output — demonstrating the leak described in the finding.

func (c *CacheExtractorCommand) getCache(rawURL string) (*http.Response, error) {
	resp, err := c.getClient().Get(rawURL)
	if err != nil {
		return nil, retryableErr{err: err}
	}

	if resp.StatusCode == http.StatusNotFound {
		_ = resp.Body.Close()
		return nil, os.ErrNotExist
	}

	return resp, retryOnServerError(resp)
}

func (r *retryHelper) doRetry(handler func(int) error) error {
	err := handler(0)

	for retry := 1; retry <= r.Retry; retry++ {
		if _, ok := err.(retryableErr); !ok {
			return err
		}

		time.Sleep(r.RetryTime)
		logrus.WithError(err).Warningln("Retrying...")

		err = handler(retry)
	}

	return err
}
