### Title
`IdleLeveragedEulerStrategy.price()` reverts when the Euler position is undercollateralized, permanently DOSing all deposit/withdraw/harvest paths - ([File: contracts/strategies/euler/IdleLeveragedEulerStrategy.sol](contracts/strategies/euler/IdleLeveragedEulerStrategy.sol))

### Summary
Analogous to the NOYA `TVLHelper.getTVL` undercollateralized-connector revert, `IdleLeveragedEulerStrategy.price()` computes net position value with an unsigned subtraction `eToken.balanceOfUnderlying(this) - dToken.balanceOf(this)`. If debt ever exceeds collateral the subtraction underflows and `price()` reverts. Since `price()` is the `_strategyPrice()` used inside `IdleCDO.getContractValue()`, which is called by `_updateAccounting()` inside `_deposit`, `_withdraw`, `harvest`, `virtualPrice` and every epoch/withdraw-request entry point, a single undercollateralized leveraged position bricks the entire CDO.

### Finding Description
In `contracts/strategies/euler/IdleLeveragedEulerStrategy.sol:108-116`:

```solidity
function price() public view override returns (uint256 _price) {
    uint256 _totalSupply = totalSupply();
    uint256 _tokenValue = eToken.balanceOfUnderlying(address(this)) - dToken.balanceOf(address(this));
    if (_totalSupply == 0) {
        _price = oneToken;
    } else {
        _price = ((_tokenValue - _lockedTokens()) * EXP_SCALE) / _totalSupply;
    }
}
```

Both subtractions revert on underflow:

1. `eToken.balanceOfUnderlying - dToken.balanceOf` reverts when `debt > collateral` (undercollateralized / liquidatable account, or during a sharp collateral price drop before Euler liquidators act).
2. `_tokenValue - _lockedTokens()` reverts when the unlocked net value is below the locked harvested rewards.

The same unchecked subtraction exists in `_setMintPrice()` at lines 118-122, used by `IdleCDOLeveregedEulerVariant.getContractValueForMint()` (contracts/IdleCDOLeveregedEulerVariant.sol:65-78).

The call chain that becomes unusable:

- `IdleCDO._deposit` → `_checkDefault()` → `_strategyPrice()` → `strategy.price()` → revert (contracts/IdleCDO.sol:234-264, 566-570)
- `IdleCDO._updateAccounting` → `getContractValue()` → `_strategyPrice()` → `price()` → revert (contracts/IdleCDO.sol:178-187, 273-284)
- `virtualPrice`, `getApr`, `getCurrentAARatio`, `harvest` — all revert.

### Impact Explanation
While the Euler account is undercollateralized every state-changing user entry point reverts: `depositAA/depositBB`, `withdrawAA/withdrawBB`, `harvest`, and `updateAccounting`. This is a permanent/temporary freezing of all user funds — unlike the intended `Default()` revert path, the reversion happens inside the view before `_checkDefault` can even compare prices, so the protocol cannot gracefully distribute the loss through `_updateAccounting`/`_emergencyShutdown` without a contract upgrade or external rescue of the Euler position. Tranche holders' funds are frozen for as long as `debt >= collateral`, i.e. until the position is liquidated on Euler or manually unwound.

### Likelihood Explanation
The strategy maintains a leveraged self-borrow position on Euler targeting a fixed `targetHealthScore` (line 47). A fast adverse price move of the collateral asset, interest accrual pushing `dToken.balanceOf` above `eToken.balanceOfUnderlying`, or partial liquidation can put the account at or below zero net collateral before the rebalancer (an EOA keeper, not a protocol guarantee) reacts. No malicious privileged role is needed — it is a market condition affecting a real on-chain position the strategy itself created.

### Recommendation
Make `price()` and `_setMintPrice()` non-reverting when net value is non-positive, matching how the credit vault handles insolvent states via the `Default` flow:

```solidity
uint256 collateral = eToken.balanceOfUnderlying(address(this));
uint256 debt = dToken.balanceOf(address(this));
uint256 _tokenValue = collateral > debt ? collateral - debt : 0;
```

(and similarly clamp `_tokenValue` at `_lockedTokens()`). Returning `0` lets `_checkDefault()`/`_virtualPriceAux` observe the loss, trigger `Default()` or the junior-loss waterfall in a controlled way, and leaves `updateAccounting` callable to crystallize the loss instead of an uncontrolled panic revert.
