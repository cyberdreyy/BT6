### Title
FASTZIP_EXTRACTOR_CONCURRENCY job variable bypasses the 0-128 clamp and flows unbounded into fastzip extractor worker count - (File: commands/helpers/archive/fastzip/zip_fastzip_extractor.go)

### Summary
The extraction concurrency value used by `fastzip.NewExtractorFromReader` is read directly from `os.Getenv(FASTZIP_EXTRACTOR_CONCURRENCY)` inside the `artifacts-downloader`/cache-extractor helper subprocess, not from the clamped `Concurrency` field computed in `functions/concrete/builder/builder.go`. The struct field is explicitly documented as unused, and the actual value forwarded to the helper subprocess is the raw job-variable environment value with no upper bound, only a "must be at least 1" lower-bound check performed by the `fastzip` library itself.

### Finding Description
`getExtractorOptionsFromEnvironment` in `commands/helpers/archive/fastzip/zip_fastzip_extractor.go` (lines 48-61) parses `FASTZIP_EXTRACTOR_CONCURRENCY` with `strconv.ParseInt` and passes it straight to `fastzip.WithExtractorConcurrency`, with no ceiling check. [1](#0-0) 

Separately, `functions/concrete/builder/builder.go` computes a clamped value (`variables.DefaultIntClamp(b.variables, "FASTZIP_EXTRACTOR_CONCURRENCY", 0, 0, 128)`) and stores it in `stages.ArtifactDownload.Concurrency` / `stages.CacheExtract.Concurrency`. [2](#0-1) 

However, `functions/concrete/run/stages/artifact_download.go` explicitly documents and confirms that this clamped field is dead: `Concurrency int json:"concurrency,omitempty" // unused for now, because artifacts-download uses env vars directly`. The actual invocation, `e.RunnerCommand(ctx, e.HelperEnvs(nil), args...)`, never passes the clamped value at all. [3](#0-2) [4](#0-3) 

The subprocess's environment is built in `env.Command`, which layers `os.Environ()` (the runner process's own environment) with `e.Env` and `e.GitLabEnv` (the job's CI/CD variables, which the pipeline author fully controls) and any explicit `extra` map: [5](#0-4) 

`HelperEnvs` only adds TLS/PATH/TMPDIR entries; it does not filter, clamp, or strip user-set `FASTZIP_EXTRACTOR_CONCURRENCY` from the environment. [6](#0-5) 

Consequently, a pipeline author who sets the CI/CD job variable `FASTZIP_EXTRACTOR_CONCURRENCY` (e.g., to 100000, not merely 128) will have that raw value inherited into the `artifacts-downloader`/`cache-extractor` helper process's environment unmodified, since it is a plain job variable and the intended 0-128 clamp is applied only to a struct field that is never actually used to configure the extractor. The only remaining check is fastzip's own lower bound ("concurrency must be at least 1"), confirmed by `options_test.go`'s test cases, with no observed upper bound enforced anywhere in this call path. [7](#0-6) 

### Impact Explanation
Setting a very large `FASTZIP_EXTRACTOR_CONCURRENCY` causes `fastzip.NewExtractorFromReader` to spawn a correspondingly large number of concurrent goroutines/file-descriptor-holding workers while extracting a many-small-entry zip artifact/cache archive. On shell/shared-host executors where the helper subprocess runs directly on the host (not inside a resource-limited container), this can exhaust host-wide file descriptors or OS threads, degrading or starving sibling jobs from other projects scheduled concurrently on the same runner host — matching the scoped "noisy-neighbor" impact. Note that for containerized executors (Docker/Kubernetes) where helper processes run inside per-job containers with their own PID/FD namespaces and (optionally) cgroup limits, the blast radius is contained to that job's own container unless the administrator has left helper container resource limits unset.

### Likelihood Explanation
No admin action is required to trigger this: any pipeline author can set an ordinary CI/CD variable, which is a normal, expected input surface. The precondition is a shared, multi-tenant, non-containerized (shell-executor-like) runner host without OS-level ulimits capping FDs/processes per job — a very common configuration. The exploit is straightforward and deterministic: define a numeric `FASTZIP_EXTRACTOR_CONCURRENCY` far above 128 and use dependencies/artifacts or cache with many small files.

### Recommendation
Enforce the intended 0-128 clamp at the point the value is actually consumed — inside `getExtractorOptionsFromEnvironment` (and the analogous archiver options function) in `commands/helpers/archive/fastzip/zip_fastzip_extractor.go` / `zip_fastzip_archiver.go` — rather than (or in addition to) the currently-dead clamp in `builder.go`. Reject or clamp values outside `[1, 128]` before calling `fastzip.WithExtractorConcurrency`/`WithArchiverConcurrency`.

func getExtractorOptionsFromEnvironment() ([]fastzip.ExtractorOption, error) {
	var opts []fastzip.ExtractorOption

	if val := os.Getenv(extractorConcurrency); val != "" {
		concurrency, err := strconv.ParseInt(val, 10, 64)
		if err != nil {
			return nil, fmt.Errorf("fastzip extractor concurrency: %w", err)
		}

		opts = append(opts, fastzip.WithExtractorConcurrency(int(concurrency)))
	}

	return opts, nil
}

func (e *Env) Command(ctx context.Context, name string, env map[string]string, args ...string) error {
	environ := os.Environ()
	for k, v := range e.Env {
		environ = append(environ, k+"="+v)
	}
	for k, v := range e.GitLabEnv {
		environ = append(environ, k+"="+v)
	}
	for k, v := range env {
		environ = append(environ, k+"="+v)
	}

	cmd := gracefulexitcmd.New(ctx, e.GracefulExitDelay, name, args...)
	cmd.Dir = e.WorkingDir
	cmd.Env = environ
	cmd.Stdout = e.Stdout
	cmd.Stderr = e.Stderr

	return normalizeExitError(cmd.Run(), cmd.ProcessState)
}

func (e *Env) HelperEnvs(existing map[string]string) map[string]string {
	e.resolveBundle()

	env := make(map[string]string)
	for k, v := range existing {
		env[k] = v
	}

	if e.bundledCACerts != "" {
		if _, ok := env["SSL_CERT_FILE"]; !ok {
			env["SSL_CERT_FILE"] = e.bundledCACerts
		}
		// libcurl (used by bundled git) ignores SSL_CERT_FILE; GIT_SSL_CAINFO
		// is what it honors. Per-host http.<host>.sslCAInfo from
		// CI_SERVER_TLS_CA_FILE still takes precedence.
		if _, ok := env["GIT_SSL_CAINFO"]; !ok {
			env["GIT_SSL_CAINFO"] = e.bundledCACerts
		}
	}

	if e.bundledGit != "git" {
		gitBinDir := filepath.Dir(e.bundledGit)
		if path, ok := env["PATH"]; ok {
			env["PATH"] = gitBinDir + ":" + path
		} else {
			env["PATH"] = gitBinDir + ":" + os.Getenv("PATH")
		}
	}

	// Helper subprocess scratch follows the runner's, not the
	// process-level TMPDIR / ARCHIVER_STAGING_DIR.
	if e.TmpDir != "" {
		if _, ok := env["TMPDIR"]; !ok {
			env["TMPDIR"] = e.TmpDir
		}
		if _, ok := env["ARCHIVER_STAGING_DIR"]; !ok {
			env["ARCHIVER_STAGING_DIR"] = e.TmpDir
		}
	}

	return env
}

func TestExtractorOptionFromEnv(t *testing.T) {
	tests := map[string]struct {
		value string
		err   string
	}{
		extractorConcurrency: {"-1", "concurrency must be at least 1"},
	}

	for option, tc := range tests {
		t.Run(fmt.Sprintf("%s=%s", option, tc.value), func(t *testing.T) {
			defer tempEnvOption(option, tc.value)()

			archiveTestDir(t, func(archiveFile string, dir string, err error) {
				require.NoError(t, err)

				f, err := os.Open(archiveFile)
				require.NoError(t, err)
				defer f.Close()

				fi, err := f.Stat()
				require.NoError(t, err)

				extractor, err := NewExtractor(f, fi.Size(), dir)
				require.NoError(t, err)

				err = extractor.Extract(t.Context())
				require.Error(t, err)
				require.Contains(t, err.Error(), tc.err)
			})
		})
	}
}
