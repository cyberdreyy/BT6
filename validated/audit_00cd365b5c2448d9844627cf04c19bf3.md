### Title
Unauthenticated LOOP plugin pprof endpoint allows attacker-controlled CPU/goroutine profiling and internal data exposure - ([File: core/web/router.go])

### Summary
The `/plugins/:name/debug/pprof/*profile` and `/plugins/:name/debug/pprof/symbol` routes are registered on the base `api` router group without any `auth.Authenticate` middleware, unlike all comparable debug/admin routes elsewhere in `router.go`. This lets any unauthenticated caller invoke `LoopRegistryServer.pluginPPROFHandler`, forwarding attacker-controlled `seconds`/`debug`/`gc` query parameters to the internal LOOP plugin's pprof server.

### Finding Description
`loopRoutes(app, api)` is called in `NewRouter` at [3](#0-2)  directly on `api`, the top-level group that only has rate-limiting and session middleware attached ( [4](#0-3) ), not `auth.Authenticate`. Inside `loopRoutes`, `r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)` and the symbol POST route are registered with no auth middleware at all: [2](#0-1) .

By contrast, every other debug/administrative capability in this file is explicitly gated: `debugRoutes` wraps `/debug/vars` with `auth.Authenticate(..., auth.AuthenticateBySession)` ( [5](#0-4) ), and the node's own `/debug/pprof/*` handlers registered via `metricRoutes(authv2)` are placed inside the authenticated `authv2` group ( [6](#0-5) ).

`pluginPPROFHandler` takes the `:name` and `*profile` path params and query values straight from the unauthenticated request and forwards them to the internal LOOP plugin's pprof HTTP endpoint: [7](#0-6) . The `seconds` query parameter directly controls the timeout/duration of the forwarded request via `pprofURLVals`, which sets `timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second` when `seconds` is supplied: [8](#0-7) . `doRequest` then performs the outbound request with that attacker-supplied timeout and streams the plugin's raw pprof response body back to the (unauthenticated) caller: [9](#0-8) .

No `auth.Authenticate`, session check, or role check exists anywhere on this code path, so any unauthenticated network client that can reach the node's API port can trigger long CPU/goroutine profiling on a LOOP plugin process and receive the profile data (call stacks, function names, potentially sensitive symbol data) in the response.

### Impact Explanation
This matches a "Denial of Service" and "Information Exposure" impact class: an unauthenticated actor can (1) force the LOOP plugin process to spend CPU/time performing profiling for a duration they control via `seconds` (bounded loosely by `PPROFOverheadSeconds` overhead but otherwise attacker-chosen), which is repeatable and can be issued concurrently for resource exhaustion, and (2) obtain internal call-stack/goroutine/symbol information about the plugin process, which is valuable internal reconnaissance data not meant to be exposed pre-auth.

### Likelihood Explanation
No credentials, session, or role are required — the endpoint is reachable by anyone who can send an HTTP GET to the node's web server on the API port. This is trivially reproducible and repeatable (each request is independent), so likelihood is high assuming the endpoint is network-reachable (i.e., not otherwise firewalled off), which is the same reachability assumption as any other route in this same router.

### Recommendation
Wrap `loopRoutes(app, api)` (or at minimum the `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol` routes) with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, consistent with how `metricRoutes` and `debugRoutes` are protected. Consider also applying a role check (e.g., `auth.RequiresAdminRole`) given the sensitivity of profiling data, and enforce a hard maximum on the `seconds` parameter server-side regardless of authentication.

### Proof of Concept
1. In a Go test (e.g., extending `core/web/loop_registry_internal_test.go`), construct a `LoopRegistryServer` with a stub/mocked registry containing one registered plugin and a `doRequest`/httptest backend simulating the plugin's pprof server.
2. Build the router via `NewRouter` (or directly register `loopRoutes` on a bare `gin.Engine`) without any session/token in the request.
3. Issue `httptest.NewRequest("GET", "/plugins/testplugin/debug/pprof/profile?seconds=30", nil)` through the engine's `ServeHTTP`.
4. Assert: (a) the response status is not 401/403 (no auth rejection), (b) the forwarded request to the internal plugin URL is observed (e.g., via a spy `http.Client`/httptest server capturing the `GET .../debug/pprof/profile?seconds=30` call), and (c) the response body returned to the unauthenticated caller matches the plugin's simulated pprof payload — confirming forwarding occurred pre-auth.
5. Contrast with a request to an authenticated route (e.g., `/v2/jobs`) without a session, which should return 401, to demonstrate the asymmetry in protection.

```go
func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
