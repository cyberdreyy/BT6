### No vulnerability found for this question.

The `delete_member` filter in `multisig2/src/lib.rs` selects requests to purge by comparing the request's originating `member` field (set once at `add_request` time to the caller identity returned by `current_member()`) against the `member` being deleted, using `MultisigMember`'s derived `PartialEq`: <cite repo="ThankGod76/core-contracts--004" path="multisig2/src/lib.rs" start="361="366" /> [1](#0-0) 

This comparison is on `r.member`, i.e. who *created* the request (an `AccountId` or `PublicKey` wrapped in `MultisigMember`), not on `request.receiver_id` (the transfer/action target account) at all. `receiver_id` never enters the `delete_member` filter condition: [2](#0-1) [3](#0-2) 

`MultisigMember` is an enum with `AccountId` or `PublicKey` payloads and standard structural equality, so `r.member == member` is exact — an `Account{alice}` never equals `Account{bob}` or any `AccessKey{...}`, and the value being deleted is the same `MultisigMember` value passed into `execute_request`/`delete_member` from the confirmed `DeleteMember{member}` action itself: [4](#0-3) [5](#0-4) 

The `member` field on a stored request is fixed at creation via `current_member()` and is never mutated by `confirm` (confirmations are tracked separately in the `confirmations` set, keyed by request id, not by rewriting `r.member`): [6](#0-5) [7](#0-6) 

So the binding "member deletion touches exactly that member's requests" holds: the filter's key is the *authoring member identity*, an exact enum equality unrelated to `receiver_id`. There is no code path where an unrelated member's requests get deleted, or where a deleted member's requests survive, based on `receiver_id` values. The premise of the question — that `receiver_id != current_account_id()` somehow confuses the member-equality filter — does not correspond to any actual logic in `delete_member`; `receiver_id` is only used later in `execute_request` to construct the outgoing `Promise`, a separate code path guarded by `assert_self_request` for privileged actions like `AddMember`/`DeleteMember`/`AddKey`/`SetNumConfirmations`: [8](#0-7) [9](#0-8)

    pub fn add_request(&mut self, request: MultiSigRequest) -> RequestId {
        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(
                "Predecessor must be a member or transaction signed with key of given account",
            )
        });
        // track how many requests this key has made
        let num_requests = self
            .num_requests_pk
            .get(&current_member.to_string())
            .unwrap_or(0)
            + 1;
        assert(
            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
