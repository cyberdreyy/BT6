### Title
Origination fee is capitalized into borrower debt and accrues compounding interest even though it is never disbursed to the borrower - (File: `programs/marginfi/src/instructions/marginfi_account/borrow.rs`)

### Summary
When a borrow origination fee is configured on a bank (`protocol_origination_fee` in `InterestRateConfig`), `lending_account_borrow` charges the borrower's liability shares for `amount_pre_fee + origination_fee`, but only transfers `amount_pre_fee` out of the liquidity vault to the borrower. The `origination_fee` amount is simultaneously credited to `collected_group_fees_outstanding`/`collected_program_fees_outstanding` for withdrawal to the group/program fee wallets. Because the fee is baked into the borrower's `liability_shares` (the same principal that is multiplied by `liability_share_value` on every future `accrue_interest` call), the borrower keeps paying interest on money that was never lent to them and that the protocol has already recorded as earned/collectible fee income. This is the same bug class as the reported "Users Have to Pay Interest on the Borrowing Fee" issue in `BorrowerOperations.sol`.

### Finding Description
In `lending_account_borrow` [1](#0-0) , when `origination_fee_rate` is non-zero, the code computes:
```
origination_fee = amount_pre_fee * origination_fee_rate
share_amount = bank_account.borrow(amount_pre_fee + origination_fee)
```
This increases the user's `liability_shares` by an amount corresponding to `amount_pre_fee + origination_fee` [1](#0-0) .

Immediately after, only `amount_pre_fee` (not including the fee) is transferred out of the liquidity vault to the borrower's token account via `withdraw_spl_transfer` [2](#0-1) .

Separately, the origination fee amount is credited to `collected_group_fees_outstanding` and (if a program fee rate is set) split into `collected_program_fees_outstanding` [3](#0-2) . These `*_fees_outstanding` fields are the amounts that `LendingPoolCollectBankFees` later sweeps from the `liquidity_vault` into the `fee_vault`/global fee wallet, per the fee documentation [4](#0-3) .

Because the fee is folded into `liability_shares` rather than tracked purely as a one-time outstanding fee, it becomes part of the principal that `accrue_interest` compounds on every future interaction: `total_liabilities = total_liability_shares * liability_share_value`, and `liability_share_value` is grown by the borrowing APR every period [5](#0-4) [6](#0-5) . This mirrors exactly the Liquity `BorrowerOperations.sol` bug class: the fee is minted/credited to the protocol immediately, yet it also remains part of the borrower's outstanding debt and keeps accruing interest indefinitely.

Test code confirms this behavior is intentional/by-design in the current codebase — the origination fee is added to `liabilityShares` and is expected to persist as debt [7](#0-6) , and `programs/marginfi/tests/user_actions/borrow.rs` explicitly asserts "the user still gains debt which includes the origination fee" [8](#0-7) .

### Impact Explanation
Every borrower on any bank where `protocol_origination_fee` is set to a non-zero value pays ongoing compounding interest on an amount they never received (the fee itself), in addition to the one-time fee already deducted at borrow time. The fee value is simultaneously double-booked: once as protocol revenue in `collected_group_fees_outstanding`/`collected_program_fees_outstanding` (to be swept out via `LendingPoolCollectBankFees`), and again as part of the user's compounding liability. This inflates borrower debt over time beyond what is economically justified, silently increasing borrower interest cost and, at scale, artificially increasing `total_liability_shares`/utilization figures used elsewhere in health and rate calculations. Per the project's own admin guide, the origination fee is "historically always zero" [9](#0-8) , so today's real-world financial impact is nil, but the fee rate is configurable per-bank by the Delegate Curve Admin via `ConfigureBankLiteCurve` at any time [10](#0-9) , so the flaw is immediately live and affects all unprivileged borrowers as soon as any group enables a non-zero origination fee.

### Likelihood Explanation
Likelihood is currently low because the origination fee defaults to zero everywhere observed in tests/config (e.g., `protocolOriginationFee: 0` default) [11](#0-10) , and the admin guide states it has "historically always been zero." However, the code path is fully implemented, exercised in tests, and reachable by any group/curve admin turning on a non-zero rate, at which point every ordinary borrower using that bank is affected without any special permissions or attacker action required.

### Recommendation
Track the origination fee separately from the borrower's `liability_shares` so that it does not compound with future interest. Concretely: keep the borrower's liability increase strictly at `amount_pre_fee`, and post the origination fee directly to `collected_group_fees_outstanding` / `collected_program_fees_outstanding` (as is already partially done) without also including it in `bank_account.borrow()`'s liability-share calculation. If the fee must remain reflected as debt owed by the borrower for accounting simplicity, it should be stored in a non-interest-bearing field and repaid before/independently of interest-bearing principal, analogous to the recommendation in the referenced report to track borrowing fees separately from debt that accrues interest.

### Proof of Concept
1. Configure a bank with `protocol_origination_fee = 1%` (as done in `tests/specs/basic/08_borrow.spec.ts`) [12](#0-11) .
2. User borrows `X` tokens. `lending_account_borrow` computes `origination_fee = X * 1%` and calls `bank_account.borrow(X + origination_fee)`, increasing the user's `liability_shares` by an amount corresponding to `X * 1.01` [1](#0-0) .
3. Only `X` is transferred to the user's wallet; `X * 1%` is recorded in `collected_group_fees_outstanding`/`collected_program_fees_outstanding` [3](#0-2) .
4. As time passes and any transaction triggers `accrue_interest`, `liability_share_value` grows via `calc_accrued_interest_payment_per_period` applied to the full `total_liability_shares` (which includes the fee-inflated shares from step 2) [6](#0-5) , so the user is charged compounding interest on the `1%` fee portion indefinitely, in addition to the fee already collected once by the protocol.

## How Fees Are Collected
