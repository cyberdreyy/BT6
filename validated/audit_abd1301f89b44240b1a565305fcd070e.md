### Title
Miner tenure-inactivity liveness wedge via self-refreshed `last_activity_time` on rejected reorg proposals - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`check_latest_block_in_tenure` in `stacks-signer/src/chainstate/mod.rs` refreshes a tenure-keyed activity timestamp (`update_last_activity_time`) whenever a rejected/inferior block proposal for that tenure arrives, as long as it is within `reorg_attempts_activity_timeout` of the last signed/pre-committed block. Because this refresh is triggered purely by the arrival of a proposal from the tenure's single miner — not by that proposal ever being valid or reaching consensus — the sole miner for a tenure can keep resubmitting cheap, doomed reorg-attempt proposals indefinitely to keep resetting the clock that `check_miner_inactivity`/`is_timed_out` uses to decide whether to fall back to the prior, healthy miner. This mirrors the `LendingAssetVault` bug class: a party who does not control the "victim" state (the rest of the signer set waiting to fall back) can refresh a timestamp keyed by a shared identifier (`consensus_hash`) that gates the victim's only recovery path, indefinitely freezing/wedging that recovery.

### Finding Description
`SortitionState::is_timed_out` (`stacks-signer/src/chainstate/v1.rs:55-80`, mirrored in `v2.rs`) computes tenure timeout from `last_activity` — which is `db.get_last_activity_time(sortition)` if present, else the burn-block receive time: [1](#0-0) 

`get_last_activity_time`/`update_last_activity_time` in `stacks-signer/src/signerdb.rs` store a single timestamp keyed only by `consensus_hash` (the tenure), with no association to whether the triggering proposal was valid, canonical, or later accepted: [2](#0-1) 

The refresh path is `check_latest_block_in_tenure` (`stacks-signer/src/chainstate/mod.rs:376-478`). When an incoming proposal fails the height check against the tenure's already-signed/pre-committed block, the function still calls `update_last_activity_time` for the *rejected* proposal's consensus hash, as long as the existing signed/pre-committed block's signature is still "fresh" (within `reorg_attempts_activity_timeout`): [3](#0-2) 

This activity counter feeds directly into `check_miner_inactivity` (`stacks-signer/src/v0/signer_state.rs:284-374`), which is the *only* mechanism that lets the signer set abandon a stalled/misbehaving miner and fall back to the prior tenure's miner: [4](#0-3) 

The intended design (per `docs/signer-flows.md` section 8 and the code comments) is that a *bounded* number of reorg attempts, each within `reorg_attempts_activity_timeout` of the last endorsement, should count toward activity so a "slow" miner is not unfairly abandoned. But the refresh has no cap on repetitions and is not tied to eventual success: as long as each successive rejected proposal arrives before `reorg_attempts_activity_timeout` elapses since the previous timestamp, `last_activity_time` is pushed forward again and again, resetting the `block_proposal_timeout` window used by `is_timed_out` each time. A single miner (the only actor who can submit proposals into a tenure, i.e. exactly the "one-slot" actor allowed by the rules) can therefore submit a steady drip of cheap, guaranteed-to-be-rejected reorg proposals (spaced just under `reorg_attempts_activity_timeout` apart) to perpetually refresh its own tenure's activity clock and prevent `is_timed_out` from ever returning true — even though the miner is doing nothing but building/broadcasting invalid or inferior proposals and never gets a legitimate block signed.

This is the same equality-breaking pattern as the analog: `update_last_activity_time` is the "deposit" resetting a shared clock; `is_timed_out`/`check_miner_inactivity` is the "withdraw" check gated on that same clock not having been refreshed since the intended timeout. A party who benefits from delay (the misbehaving/stalled miner) is exactly the party who can trigger the refresh, at effectively zero cost (a rejected proposal, not a signed block), on every pass.

### Impact Explanation
This is a liveness wedge: the signer set can be kept perpetually pinned to a stalled/misbehaving miner's tenure, unable to ever exercise the `check_miner_inactivity` fallback to the prior miner, because the fallback's only gating signal (`last_activity_time`) is continuously and cheaply refreshable by the very miner whose inactivity is meant to be detected. No majority collusion or other signer's key is required — a single miner (one slot) repeatedly proposing doomed reorg attempts is sufficient. This matches the "High" impact class: a signer (the whole signer set, in effect) wedged into never falling back / never signing valid blocks from a legitimate replacement miner, stalling tenure progress indefinitely while the illegitimate miner controls the slot.

### Likelihood Explanation
Likelihood is Medium-to-High for a griefing/stalling miner: submitting a rejected block proposal is far cheaper than winning a sortition or producing a valid block, and the attack only requires timing successive (deliberately invalid/inferior) proposals inside the `reorg_attempts_activity_timeout` window (default 200s per `DEFAULT_REORG_ATTEMPTS_ACTIVITY_TIMEOUT_MS` in `stacks-signer/src/config.rs`). No special privileges beyond being the current tenure's miner (a single-slot role reachable by anyone who wins a sortition, or by a miner that refuses to build validly) are needed.

### Recommendation
Cap how many times / for how long a rejected or pre-committed-only proposal can refresh `last_activity_time` for a given tenure — e.g., bound the total extension to a fixed multiple of `block_proposal_timeout` from the tenure's original burn-block receipt time, or require that at least one *validated* (non-provably-invalid) proposal be seen before granting another activity extension, so `is_timed_out` cannot be held off indefinitely by an unbounded stream of doomed reorg attempts.

### Proof of Concept
1. Miner M wins tenure T's sortition; a prior signed block exists in the previous tenure (or M signs an initial block, matching the "has_signed_block_in_tenure" fresh-window described in `get_tenure_last_block_info`).
2. M sends a reorg-attempt proposal that fails `check_latest_block_in_tenure`'s height check while the existing signature is still fresh (`< tenure_last_block_proposal_timeout`/`reorg_attempts_activity_timeout` old); this hits the branch at `chainstate/mod.rs:403-417`, calling `update_last_activity_time(T, now)`.
3. Before `block_proposal_timeout` elapses (per `is_timed_out`) but before `reorg_attempts_activity_timeout` elapses since the last refresh, M repeats step 2 with another doomed proposal.
4. `get_last_activity_time(T)` keeps advancing; `is_timed_out` (`chainstate/v1.rs:55-80`) never becomes true; `check_miner_inactivity` (`v0/signer_state.rs:284-316`) never reverts to the prior valid miner; the tenure stalls indefinitely under M's control. [5](#0-4) [1](#0-0) [6](#0-5)

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

    /// Update the tenure (identified by consensus_hash) last activity timestamp
    pub fn update_last_activity_time(
        &mut self,
        tenure: &ConsensusHash,
        last_activity_time: u64,
    ) -> Result<(), DBError> {
        debug!("Updating last activity for tenure"; "consensus_hash" => %tenure, "last_activity_time" => last_activity_time);
        self.db.execute("INSERT OR REPLACE INTO tenure_activity (consensus_hash, last_activity_time) VALUES (?1, ?2)", params![tenure, u64_to_sql(last_activity_time)?])?;
        Ok(())
    }

    /// Get the last activity timestamp for a tenure (identified by consensus_hash)
    pub fn get_last_activity_time(&self, tenure: &ConsensusHash) -> Result<Option<u64>, DBError> {
        let query =
            "SELECT last_activity_time FROM tenure_activity WHERE consensus_hash = ? LIMIT 1";
        let Some(last_activity_time_i64) = query_row::<i64, _>(&self.db, query, &[tenure])? else {
            return Ok(None);
        };
        let last_activity_time = u64::try_from(last_activity_time_i64).map_err(|e| {
            error!("Failed to parse db last_activity_time as u64: {e}");
            DBError::Corruption
        })?;
        Ok(Some(last_activity_time))
    }

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

        // A block we have only pre-committed to must NOT veto this proposal, but, similar to above
        // this should still count as activity for the miner.
        let last_accepted_block = signer_db
            .get_last_accepted_block(tenure_id)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;
        if let Some(info) = last_accepted_block {
            let is_fresh_pre_commit = info.state == BlockState::PreCommitted
                && info.approved_time.is_some_and(|approved_time| {
                    approved_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
                        > get_epoch_time_secs()
                });
            if is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length {
                info!(
                    "Miner's block proposal conflicts with a block we have only pre-committed to. Counting it as miner activity, but not rejecting the proposal.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "pre_committed_signer_signature_hash" => %info.block.header.signer_signature_hash(),
                    "pre_committed_chain_length" => info.block.header.chain_length,
                );
                if let Err(e) = signer_db
                    .update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
                {
                    warn!("Failed to update last activity time: {e}");
