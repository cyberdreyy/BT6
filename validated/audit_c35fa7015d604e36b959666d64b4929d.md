### Title
Attacker-controlled `MessageId` collision causes cross-user callback overwrite and response hijacking in `HandleLegacyUserMessage` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` stores each incoming user's `handlers.Callback` in `h.savedCallbacks` keyed only by the client-supplied `msg.Body.MessageId`, with no uniqueness check against existing in-flight entries. Because `MessageId` is fully attacker-controlled (it comes from the JSON-RPC request `ID` field, only length-validated), an unauthenticated caller can submit a request using the same `MessageId` as another victim's concurrent in-flight request, silently overwriting the victim's saved callback and causing the victim's eventual DON response to be delivered to the attacker instead.

### Finding Description
The gateway's `ProcessRequest` in `core/services/gateway/gateway.go` decodes the JSON-RPC request, calls `msg.Validate()` (which only checks length/format, not uniqueness) at [1](#0-0) , then dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` with a fresh per-request `handlers.Callback` at [2](#0-1) .

Inside `HandleLegacyUserMessage`, after minimal payload/timestamp/method validation, the handler unconditionally stores the new callback into the shared map keyed by the caller-supplied `MessageId`, overwriting any prior entry without checking whether one already exists: [3](#0-2) 

There is no server-side generation or uniqueness enforcement of `MessageId` anywhere in this path — the comment on line 384 even notes `// TODO: apply allowlist and rate-limiting here`, confirming this gap is a known incompleteness. `msg.Body.MessageId` is set directly from the JSON-RPC request's client-chosen `ID` in `common.ValidatedMessageFromReq`, up to 200 characters, with no per-DON/global dedup: [4](#0-3) 

When a DON node later responds, `HandleNodeMessage` -> `handleWebAPITriggerMessage` looks up and deletes the callback purely by `MessageId` and invokes whichever callback is currently stored, without any secondary binding to the original requester's session/identity: [5](#0-4) 

Exploit flow:
1. Victim sends a legitimate legacy request with `MessageId = "X"`; handler stores `savedCallbacks["X"] = victimCallback` and forwards the request to all DON members.
2. Before the DON responds, attacker sends their own crafted legacy request also using `MessageId = "X"`; handler overwrites `savedCallbacks["X"] = attackerCallback`.
3. When the DON node responds (its response echoes back the message id it received, `X`, per `ValidatedMessageFromResp` setting `msg.Body.MessageId = resp.ID`), the gateway looks up `savedCallbacks["X"]`, finds `attackerCallback`, and delivers the (possibly victim-triggered) response to the attacker. The victim's HTTP call blocks until `callback.Wait(ctx)` times out, receiving `RequestTimeoutError` instead of their real answer while the attacker receives the response.

### Impact Explanation
This is cross-user response confusion: an unprivileged, unauthenticated gateway client can hijack another user's response tied to a webapi trigger request by winning a `MessageId` collision race, and can also deny/discard the legitimate caller's response entirely. Depending on payload content, this can leak content that traversed the DON pipeline for another user's request, constituting attacker-controlled data returned to another user in violation of per-request isolation.

### Likelihood Explanation
The only precondition is being an unauthenticated caller of the gateway's legacy JSON-RPC endpoint capable of sending two requests with a chosen, colliding `MessageId` — trivial to satisfy since `MessageId` is entirely client-supplied and only constrained by length (`<=200` chars, no null suffix). The window is a race (the attacker's request must land after the victim's callback registration but before the DON's response arrives), but is easily and repeatedly winnable given typical DON round-trip latencies (seconds) versus attacker request latency (milliseconds), and the attacker can retry across arbitrary IDs/timings at low cost with no rate limiting on this specific check ("TODO: apply allowlist and rate-limiting here").

### Recommendation
Enforce server-side uniqueness on `MessageId` insertion into `savedCallbacks`: reject (or generate/salt) new registrations when an unexpired entry already exists for that key (`h.mu.Lock(); if _, exists := h.savedCallbacks[id]; exists { return error }`), and/or bind the saved callback with an internal, non-attacker-controlled request nonce that is not solely derived from client input, so a collision cannot silently overwrite a different caller's callback.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. `setupHandler(t)` to build a handler with mocked DON.
2. Build `msgVictim` via `triggerRequest` helper with `MessageId = "collide-1"`, signed by node/victim key.
3. Call `handler.HandleLegacyUserMessage(ctx, msgVictim, victimCallback)`.
4. Build `msgAttacker` with the same `MessageId = "collide-1"` (different payload/topics), signed by attacker.
5. Call `handler.HandleLegacyUserMessage(ctx, msgAttacker, attackerCallback)`.
6. Assert `handler.savedCallbacks["collide-1"].Callback == attackerCallback` (not `victimCallback`).
7. Simulate DON response via `handler.HandleNodeMessage(ctx, resp, nodeAddr)` with `resp.ID = "collide-1"`.
8. Assert `attackerCallback.Wait(ctx)` receives the response while `victimCallback.Wait(ctx)` times out/never resolves — proving the response was hijacked away from the original caller.

	savedCb, found := h.savedCallbacks[msg.Body.MessageId]

// ValidatedMessageFromReq validated and extracts a legacy Gateway Message
// from params field of JSON-RPC request
func ValidatedMessageFromReq(req *jsonrpc.Request[json.RawMessage]) (*api.Message, error) {
	if req.Version != "2.0" {
		return nil, errors.New("incorrect jsonrpc version")
	}
	if req.Method == "" {
		return nil, errors.New("empty method field")
	}
	if req.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var m api.Message
	err := json.Unmarshal(*req.Params, &m)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal request params: %w", err)
	}
	m.Body.Method = req.Method
	m.Body.MessageId = req.ID
	err = m.Validate()
	if err != nil {
		return nil, err
	}
	return &m, nil
}
