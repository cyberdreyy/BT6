### Title
Unauthenticated `/health` and `/health.txt` endpoints leak internal service topology, chain IDs, and live diagnostic error strings - ([File: core/web/health_controller.go])

### Summary
The `Health` handler on `HealthController` is mounted without any authentication middleware and always returns the full list of internal health-check names (e.g. `EVM.1399100`, `Mercury.WSRPCPool`, `TelemetryManager`, `WorkflowStore`, `CRE.DispatcherWrapper`) plus raw error output for failing checks, to any unauthenticated caller. This goes well beyond a simple up/down boolean and reveals node internals and live connectivity diagnostics.

### Finding Description
`healthRoutes` registers `/health`, `/health.txt`, `/readyz`, and `/public-readyz` on the `api` route group in `NewRouter`, which is only wrapped by rate limiting and session middleware — not `auth.Authenticate` or `auth.AuthenticateGQL`. [1](#0-0) [2](#0-1) 

`HealthController.Health` always calls `checker.IsHealthy()` and, regardless of any query parameter, builds a full list of `presenters.Check` entries containing the check `Name` and, for failing checks, the raw `err.Error()` string as `Output`. This is returned as JSON, HTML, or plaintext depending on `Accept` header / `.txt` suffix — there is no "minimal" mode for `/health` (that logic only exists for `PublicReadyz`, whose doc comment explicitly states its purpose is to avoid "leaking internal service state on publicly reachable endpoints" — implying `/health` itself is not similarly hardened). [3](#0-2) [4](#0-3) 

Test fixtures confirm the actual response content includes internal service/component names and chain IDs such as `BridgeStatusReporter`, `CRE`, `CRE.DispatcherWrapper`, `EVM.1399100.*`, `Mercury.WSRPCPool`, `TelemetryManager`, `WorkflowStore`, and — critically — live diagnostic text like `"Listener connected = false, receiving heads = false"` when a check is failing. [5](#0-4) [6](#0-5) 

No auth middleware, presenter redaction, or role check intercepts this path; the only variance is via the unauthenticated `?failing` query param, which merely filters output rather than restricting information.

### Impact Explanation
An unauthenticated network caller can fingerprint a node's enabled features/plugins (CRE workflows, Mercury/data-streams, LLO transmission, telemetry, EVM chain IDs configured), and can observe live infrastructure health such as RPC head-listener disconnects. This enables reconnaissance for targeted attacks (e.g., timing exploitation of stale price feeds during a detected RPC outage window, or targeting a node known to run specific plugins). This maps to a low/informational "internal state and topology disclosure" class rather than direct fund loss or key compromise, since no secrets, API keys, or credentials are exposed — only service names, chain IDs, and generic connectivity error text.

### Likelihood Explanation
Trivial and fully unauthenticated: a plain `GET /health` or `GET /health.txt` from any network position that can reach the node's web port returns this data every time, with no preconditions, tokens, or session required. It is fully repeatable and deterministic.

### Recommendation
Apply the same minimization already implemented for `PublicReadyz` to `/health`/`/health.txt` when accessed without authentication — e.g., gate the detailed check list (names + error output) behind `auth.Authenticate`, and expose only an aggregate boolean/status code on the public route, moving the detailed variant to an authenticated-only path (as already done for `/readyz?full=true`, which likewise should be reviewed for the same reason).

### Proof of Concept
Go handler-level integration test (extending `core/web/health_controller_test.go`):
1. Start `cltest.NewApplicationWithKey(t)` with a mocked `Checker` returning one failing check with a distinctive error message and one passing check with a distinctive name.
2. Using `app.NewHTTPClient(nil)` (no session/auth), issue `client.Get("/health")` and `client.Get("/health.txt")`.
3. Assert `resp.StatusCode == http.StatusMultiStatus`.
4. Parse body and assert it contains the check `Name` fields (internal component identifiers) and the failing check's `Output` error string, e.g. assert `strings.Contains(body, "EVM.1399100.HeadTracker.HeadListener")` and `strings.Contains(body, "Listener connected = false")`.
5. Assert no `Authorization`/session cookie was required to obtain this response (client created via `NewHTTPClient(nil)`), demonstrating unauthenticated disclosure of internal service names and diagnostic detail beyond a simple boolean.

```go
// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid

func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
```

```go
func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}
```
