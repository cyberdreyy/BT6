### Title
Command injection via unquoted heredoc terminator in `BashWriter.DotEnvVariables` - ([File: shells/bash.go])

### Summary
`BashWriter.DotEnvVariables` writes dotenv key/value pairs into the generated build script using an **unquoted** heredoc (`cat << EOF ... EOF`). Because the heredoc delimiter is not quoted, bash performs parameter expansion and command substitution on the heredoc body, but `helpers.DotEnvEscape` only escapes backslashes, double quotes, `\n` and `\r` — it never neutralizes `$` or backticks. A dotenv value containing `$(...)` or `` `...` `` therefore executes as shell code when the runner-generated script runs, not merely when the value is later sourced.

### Finding Description
`shells/bash.go` `DotEnvVariables`: [1](#0-0) 
builds:
```
cat << EOF > <tmpfile>
KEY="VALUE"
EOF
```
The `EOF` terminator is unquoted. Per POSIX/bash semantics, an unquoted heredoc delimiter enables parameter expansion, command substitution, and arithmetic expansion inside the heredoc body — this happens irrespective of any literal quote characters written inside the body, since heredoc body quoting rules are governed solely by whether the delimiter itself is quoted (e.g. `<< 'EOF'` or `<< \EOF` would disable expansion; `<< EOF` does not).

`helpers.DotEnvEscape`: [2](#0-1) 
only escapes `\`, `"`, `\n`, `\r` (matching godotenv's own unescape rules for round-tripping into a `.env` file), but it does not escape `$` or `` ` ``. An attacker-controlled dotenv VALUE (or the raw bytes making up a `report:dotenv` artifact key/value pair that Runner previously parsed and is now re-emitting for a downstream job/stage) can therefore contain `$(malicious command)` and have it substituted by the shell that executes the runner-generated script, at the moment the heredoc is written — i.e. arbitrary command execution in the job's shell context, driven purely by data the pipeline author controls (their own `report:dotenv` artifact contents), independent of the value ever being `source`d afterward.

The `isValidDotEnvKey` check only restricts the *key* (`^[A-Za-z_][A-Za-z0-9_]*$`) and does nothing to constrain the *value*, so the value remains fully attacker-controlled ASCII/text with `$(...)`/backticks intact.

### Impact Explanation
An unprivileged pipeline author who controls a `report:dotenv` artifact (or any code path that funnels a map of variables through `DotEnvVariables`) can achieve command execution inside the shell process that runs the generated build/prepare script on the runner's executor for the *current* build — the same execution context as their own job commands. Since the job already runs its own commands in that same shell (shell executor: on the host; docker/kubernetes executor: inside the job's container), the practical severity is limited to the job's own execution context in most executors, but it does demonstrate a real injection primitive: variable values that are supposed to be inert data end up being executed as shell code at script-generation/heredoc-write time, which is a genuine escape from intended data/command separation within `BashWriter`.

### Likelihood Explanation
Fully attacker-controlled and trivially reproducible: any job can emit a `report:dotenv` artifact (or, more directly, any variable value flowing through the dotenv round-trip) containing a value like `` VAR=`touch /tmp/pwned` `` or `VAR=$(id)`. No special permissions beyond authoring a normal `.gitlab-ci.yml` job are required.

### Recommendation
Quote the heredoc delimiter (`cat << 'EOF' > <tmpfile>` or `<< \EOF`) so the heredoc body is treated as a literal, non-expanding block, matching the documented behavior of `escapeDotEnvValue`, which was clearly written assuming no shell expansion occurs inside the heredoc. Alternatively, stop using an unquoted heredoc entirely and write the file via `printf '%s' <escaped-content> > file` using the existing `b.escape()` (ANSI-C/POSIX quoting) helpers, which already correctly neutralize `$` and backticks.

### Proof of Concept
Go unit test in `shells/bash_test.go`:
```go
func TestDotEnvVariables_NoCommandSubstitution(t *testing.T) {
    w := &BashWriter{TemporaryPath: "/tmp"}
    vars := map[string]string{
        "PWNED": "$(touch /tmp/should_not_execute)",
    }
    script := w.DotEnvVariables("dotenv", vars)

    // Assert the heredoc delimiter is quoted, preventing expansion.
    assert.Contains(t, script, "cat << 'EOF'")
    assert.NotContains(t, script, "cat << EOF")
}
```
Runtime PoC: a job with
```yaml
job:
  script:
    - echo 'PWNED=$(touch /tmp/pwned)' > report.env
  artifacts:
    reports:
      dotenv: report.env
downstream:
  needs: [job]
  script:
    - echo done
```
Before the fix, `/tmp/pwned` is created inside `downstream`'s script-generation heredoc write, even though `PWNED` is never referenced/sourced by any script command — proving code execution purely from re-emitting the dotenv value through `DotEnvVariables`.

func (b *BashWriter) DotEnvVariables(baseFilename string, variables map[string]string) string {
	dotEnvFile := b.TmpFile(baseFilename)

	var sb strings.Builder
	fmt.Fprintf(&sb, "cat << EOF > %s\n", dotEnvFile)
	sb.WriteString(helpers.DotEnvEscape(variables))
	sb.WriteString("EOF\n")

	b.Line(sb.String())

	return dotEnvFile
}

var escapeDotEnvValue = strings.NewReplacer(
	"\\", "\\\\", // Escape backslashes
	"\"", "\\\"", // Escape double quotes
	"\n", "\\n", // Escape newlines
	"\r", "\\r", // Escape carriage returns
).Replace

func DotEnvEscape(variables map[string]string) string {
	var sb strings.Builder

	// Sort variables to get deterministic output
	keys := make([]string, 0, len(variables))
	for key := range variables {
		keys = append(keys, key)
	}
	sort.Strings(keys)

	for _, key := range keys {
		if !isValidDotEnvKey(key) {
			// Skip invalid keys
			continue
		}

		value := variables[key]
		fmt.Fprintf(&sb, "%s=\"%s\"\n", key, escapeDotEnvValue(value))
	}

	return sb.String()
}
