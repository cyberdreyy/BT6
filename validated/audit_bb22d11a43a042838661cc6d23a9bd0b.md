### Title
Cross-user response confusion via MessageId collision in `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores each pending user request in a single map `h.savedCallbacks` keyed only by the user-supplied, signature-covered `MessageId`, with no binding to the sender's identity. [2](#0-1)  Because `MessageId` is fully attacker-chosen (it's part of the signed message body and `Message.Validate()` performs no uniqueness check across users), an unprivileged external caller can pick a `MessageId` that collides with another user's in-flight request, overwriting that entry in the shared map. [3](#0-2)  When the DON node later replies for the original (victim) request with the same `MessageId`, `handleWebAPITriggerMessage` looks the callback up purely by `MessageId` and delivers the victim's response payload to whichever callback currently occupies that slot — the attacker's. [4](#0-3) 

### Finding Description
The check in `HandleNodeMessage` — `if msg.Body.Sender != nodeAddr` — only verifies that the responding connector matches the claimed node address; it never re-validates that the `MessageId` in the node's response still belongs to the request that created it. [5](#0-4)  The actual routing key for delivering trigger responses to external users is `msg.Body.MessageId`, used to index into the process-wide (per-DON) `map[string]*savedCallback`:
- On the way in, `HandleLegacyUserMessage` does `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` unconditionally — no check for an existing (unexpired) entry, and no association with the requester's address. [2](#0-1) 
- On the way out, `handleWebAPITriggerMessage` does `savedCb, found := h.savedCallbacks[msg.Body.MessageId]`, and if found, sends the node's response straight to that callback, with no verification that the callback still corresponds to the same original requester or request payload. [4](#0-3) 

`MessageId` is chosen by the caller and is part of the data signed via `msg.Sign()`; `Message.Validate()` only enforces length/format constraints (1–128 bytes, no trailing null), never uniqueness against other in-flight requests. [1](#0-0)  Consequently:

1. Victim (address A) submits a legacy `web_api_trigger` request with `MessageId = "X"`. Gateway stores `savedCallbacks["X"] = victimCallback` and forwards the signed request to all DON members. [6](#0-5) 
2. Before any node responds, attacker (address B, an unprivileged client with only their own signing key) submits their own legacy request also using `MessageId = "X"`. This is accepted by `Validate()` and `HandleLegacyUserMessage` overwrites `savedCallbacks["X"] = attackerCallback`.
3. A DON node subsequently responds to the victim's original request (method `web_api_trigger`, echoing `MessageId = "X"`). `HandleNodeMessage`'s only check — `msg.Body.Sender != nodeAddr` — passes because it's a legitimate node responding as itself; it says nothing about which user's request this response belongs to. [7](#0-6) 
4. `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds the attacker's callback (due to the overwrite), and delivers the victim's response payload to the attacker. [8](#0-7) 

This is a genuine cross-user callback/response confusion rooted in the absence of a binding between the `savedCallback` entry and the original requester's identity (e.g., `Sender`) or the specific request payload — matching the audit question's core concern, even though the map is keyed by `MessageId` and delivery happens via `handleWebAPITriggerMessage`, not `handleWebAPIOutgoingMessage` (the latter has no `savedCallbacks` interaction at all).

### Impact Explanation
An unprivileged gateway client can cause another user's `web_api_trigger` response (which may contain workflow execution results, HTTP response bodies fetched on the victim's behalf, or other trigger-specific data) to be delivered to the attacker's own HTTP connection instead of the legitimate requester, and simultaneously deny/starve the victim of their response. This is a cross-user information disclosure / response hijack matching the "unauthorized action on another user's job" / "attacker-controlled data returned to another user" bounty impact class.

### Likelihood Explanation
Exploitability requires only: (1) knowledge or guessability of a victim's chosen `MessageId` (many client scripts and tests use fixed/default IDs like `"12345"`, increasing collision likelihood in practice; see `core/scripts/gateway/web_api_trigger/invoke_trigger.go` and `trigger_test.go` defaults), and (2) timing the attacker's request between the victim's request submission and the node's response — feasible because `CallbackMaxAgeSec` defaults to 120 seconds, giving a generous race window. [9](#0-8)  No node compromise or elevated privilege is needed; any address able to sign and submit a legacy gateway request suffices.

### Recommendation
Bind `savedCallbacks` entries to the originating request more strongly than `MessageId` alone: key by a composite of `(Sender, MessageId)` or reject/queue new registrations that would overwrite an existing unexpired entry for a different `Sender`. Additionally consider embedding an unpredictable, gateway-generated component (e.g., a UUID) in the correlation key rather than trusting the fully user-controlled `MessageId`, and verify in `handleWebAPITriggerMessage` that the node's response is being matched against the same `Sender` who created the callback.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build handler + mock DON as in `setupHandler`.
2. Create `victimMsg := triggerRequest(t, victimKey, ...)` and `attackerMsg := triggerRequest(t, attackerKey, ...)` both using the same `MessageId` (`"12345"`, the default used by the test helper) but different signing keys/senders.
3. `victimCb := hc.NewCallback(); err := handler.HandleLegacyUserMessage(ctx, victimMsg, victimCb)` — asserts `SendToNode` called for DON members with victim's request.
4. `attackerCb := hc.NewCallback(); err = handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCb)` — this overwrites `savedCallbacks["12345"]`.
5. Simulate node responding to the victim's original request: `resp, _ := hc.ValidatedResponseFromMessage(victimMsg); err = handler.HandleNodeMessage(ctx, resp, nodes[0].Address)`.
6. Assert: `attackerCb.Wait(ctx)` returns the victim's payload (`codec.EncodeLegacyResponse(victimMsg)`), while `victimCb.Wait(ctx)` times out / never resolves — proving cross-user delivery: `require.Equal(t, handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(victimMsg), ErrorCode: api.NoError}, attackerResult)`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
