### Title
Unauthenticated attacker can trigger raw internal error disclosure via `MethodSecretsCreate`/`MethodSecretsUpdate` public-key retrieval failure - ([File: core/capabilities/vault/gw_handler.go])

### Summary
In `GatewayHandler.HandleGatewayMessage`, when `h.getMasterPublicKey(ctx)` fails for `MethodSecretsCreate`/`MethodSecretsUpdate` requests, the raw Go error (potentially wrapping internal vault/DKG/secrets-service failure details) is sent verbatim to the caller through `gatewayErrorResponse` → `errorResponse`, before any authorization check runs. Any unauthenticated gateway client can trigger this by sending a `MethodSecretsCreate`/`MethodSecretsUpdate` message while the master public key is not yet cached (e.g., shortly after node/handler startup, or whenever the underlying `secretsService.GetPublicKey` call fails).

### Finding Description
`HandleGatewayMessage` handles `MethodSecretsCreate`/`MethodSecretsUpdate` by first calling `h.getMasterPublicKey(ctx)` (core/capabilities/vault/gw_handler.go:189) — this happens *before* `h.requestProcessor.ProcessRequest` runs, which is where authorization/allowlist/JWT checks are performed (core/capabilities/vault/gateway_vault_request_processor.go:233, `authorizeAndStamp`). This means the public-key retrieval failure path is reachable by any caller who can send a gateway message, with zero authentication or authorization required.

`getMasterPublicKey` falls back to `MasterPublicKeyFromSecretsService` (core/capabilities/vault/gateway_vault_request_processor.go:293-311) which wraps underlying errors with `fmt.Errorf("failed to get vault public key: %w", err)`, `"vault public key is unavailable"`, `"failed to decode vault public key: %w"`, or `"failed to unmarshal vault public key: %w"`. Whatever the wrapped `err` is (the concrete error returned by `secretsService.GetPublicKey`, whose implementation is defined in `core/capabilities/vault/capability.go` and could include DKG/vault-service internal failure detail) gets threaded straight through to the wire.

When `getMasterPublicKey` returns an error, `gw_handler.go:191` calls `h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)`, which (core/capabilities/vault/gw_handler.go:263-273) forwards to `h.errorResponse(...)`. `errorResponse` places `err.Error()` directly into the JSON-RPC `WireError.Message` field with no redaction, generalization, or scrubbing (core/capabilities/vault/gw_handler.go:401-409):
```go
Error: &jsonrpc.WireError{
    Code:    api.ToJSONRPCErrorCode(errorCode),
    Message: err.Error(),
},
```
There is no sanitization layer between the internal error and the wire response for this code path — `gatewayErrorResponse` only special-cases `InvalidVaultParamsError` for wrapping (adds a static prefix), but for any other error (including the public-key failure) it passes the raw `err` to `errorResponse` unmodified.

### Impact Explanation
This matches the Chainlink bounty "information disclosure" class: internal implementation/error details (potentially including underlying vault/DKG/secrets-service failure state) are returned to an unauthenticated caller in a raw, unredacted string. While the current concrete error strings I can confirm in this code (`"failed to get vault public key"`, `"vault public key is unavailable"`, decode/unmarshal failures) are relatively generic, they wrap arbitrary errors returned by `secretsService.GetPublicKey`/underlying DKG/vault capability implementation via `%w`, meaning any more detailed internal error text produced deeper in the vault/DKG stack (e.g., connectivity, share-count, threshold, or configuration-specific messages) would be exposed verbatim to an unauthenticated caller. This is a genuine violation of the stated invariant that error responses must redact vault/DKG internal state, even though I could not confirm from the available files that DON member addresses specifically flow into these error strings.

### Likelihood Explanation
Trivial and repeatable: no credentials, signature, or allowlist membership are needed because the failure occurs strictly before `ProcessRequest`/`AuthorizeRequest` is invoked. An attacker only needs to send a syntactically valid `MethodSecretsCreate` or `MethodSecretsUpdate` JSON-RPC gateway message. The most reliable trigger window is immediately after handler startup before `cachedMasterPublicKey` is populated, but any transient failure of the underlying secrets/DKG public-key retrieval reopens the window (the cache is only set on success, so retrieval is retried — and thus re-exposed — on every subsequent request until it succeeds).

### Recommendation
- In `gatewayErrorResponse` (or a new wrapper specifically for the public-key retrieval failure), replace the raw `pkErr` with a generic, fixed message (e.g., `"vault temporarily unavailable"`) for the wire response, while logging the detailed `pkErr` server-side only (as `errorResponse` already does via `reqLggr`/`Errorw`).
- More broadly, audit `errorResponse`'s `err.Error()` usage across all call sites in `gw_handler.go` (`handleSecretsCreate`, `handleSecretsUpdate`, `handleSecretsDelete`, `handleSecretsList`, `handlePublicKeyGet`) to ensure no internally-wrapped error from `secretsService`/DKG/vault internals is ever forwarded to the wire without going through an explicit allowlist of safe, generic error codes/messages.

func (h *GatewayHandler) getMasterPublicKey(ctx context.Context) (*tdh2easy.PublicKey, error) {
	h.mu.RLock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		h.mu.RUnlock()
		return &cachedCopy, nil
	}
	h.mu.RUnlock()

	publicKey, err := MasterPublicKeyFromSecretsService(ctx, h.secretsService)
	if err != nil {
		return nil, err
	}

	h.mu.Lock()
	defer h.mu.Unlock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		return &cachedCopy, nil
	}
	h.cachedMasterPublicKey = publicKey
	cachedCopy := *publicKey
	return &cachedCopy, nil
}

func (h *GatewayHandler) errorResponse(
	ctx context.Context,
	gatewayID string,
	req *jsonrpc.Request[json.RawMessage],
	errorCode api.ErrorCode,
	err error,
) *jsonrpc.Response[json.RawMessage] {
	h.requestLogger(req, gatewayID).Errorw("gateway handler error response", "errorCode", errorCode, "error", err)
	h.metrics.requestInternalError.Add(ctx, 1, metric.WithAttributes(
		attribute.String("gateway_id", gatewayID),
		attribute.String("error", errorCode.String()),
	))

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Error: &jsonrpc.WireError{
			Code:    api.ToJSONRPCErrorCode(errorCode),
			Message: err.Error(),
		},
	}
}

// MasterPublicKeyFromSecretsService loads the vault master public key from a secrets service.
func MasterPublicKeyFromSecretsService(ctx context.Context, secretsService vaulttypes.SecretsService) (*tdh2easy.PublicKey, error) {
	resp, err := secretsService.GetPublicKey(ctx, &vaultcommon.GetPublicKeyRequest{})
	if err != nil {
		return nil, fmt.Errorf("failed to get vault public key: %w", err)
	}
	if resp == nil || resp.PublicKey == "" {
		return nil, errors.New("vault public key is unavailable")
	}

	masterPublicKeyBytes, err := hex.DecodeString(resp.PublicKey)
	if err != nil {
		return nil, fmt.Errorf("failed to decode vault public key: %w", err)
	}

	masterPublicKey := &tdh2easy.PublicKey{}
	if err := masterPublicKey.Unmarshal(masterPublicKeyBytes); err != nil {
		return nil, fmt.Errorf("failed to unmarshal vault public key: %w", err)
	}
	return masterPublicKey, nil
