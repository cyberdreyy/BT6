The bad-debt report concerns a **lending protocol** where debt positions can become undercollateralized after liquidation, leaving unrepayable debt that drains protocol liquidity. This repository is not a lending protocol — it is a fully-collateralized escrow/HTLC swap system where every escrow's required balance (token amount + safety deposit) is verified atomically at deployment time before the swap becomes active.

Specifically:
- On the source chain, `BaseEscrowFactory._postInteraction` reverts with `InsufficientEscrowBalance` if the deployed clone doesn't hold the exact `makingAmount` and `safetyDeposit` immediately after deployment [1](#0-0) .
- On the destination chain, `createDstEscrow` requires `msg.value` to exactly match the expected native amount, and reverts otherwise, before pulling the ERC20 amount via `safeTransferFrom` [2](#0-1) .

There is no notion of partial collateralization, credit extension, or under-funded positions that persist in state — each escrow is a 1:1 funded vault or it simply never gets created/activated. Withdraw/cancel paths only move funds that are already verified to be present, so there's no "bad debt" state where a party owes more than what's escrowed and liquidity becomes permanently stuck due to a shortfall. This root cause class (uncollateralized debt accrual with no repayment mechanism) has no reachable analog in the escrow/factory, Merkle-invalidation, fee-routing, clone-deployment, or zkSync code paths of this repository.

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }
```
