### Title
Zip archive extraction lacks path-traversal sanitization, allowing writes outside the job workspace - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`) use `zip.File.Name` directly in `filepath.Dir`, `os.MkdirAll`, `os.Mkdir`, `os.OpenFile`, and `os.Symlink` without any cleaning or containment check against the extraction root. The only existing content check, `errorIfGitDirectory`, only rejects paths starting with `.git` and does nothing to stop `..` traversal or absolute paths, so a crafted cache/artifact zip can write files anywhere the runner process has permission to write.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` and, for each entry, calls `extractZipFile(file)`, which does: [1](#0-0) 
`filepath.Dir(file.Name)` is passed straight to `os.MkdirAll(..., 0o777)` with no `filepath.Clean`/`filepath.Rel`/prefix check against a sandbox root. The three per-entry extractors then also use `file.Name` unsanitized: [2](#0-1) [3](#0-2) 

The only validation performed before extraction is `errorIfGitDirectory`, which checks whether the first path segment is `.git` — it does not detect or reject `..` segments or absolute paths: [4](#0-3) 

`ExtractZipArchive` is invoked with attacker-controlled zip contents from at least the legacy zip extractor used for cache/artifact restoration: [5](#0-4) 

A pipeline author who controls the contents of a cache or artifact zip (e.g. via `cache:paths`/`artifacts:paths` in `.gitlab-ci.yml`, or a maliciously crafted upstream cache) can create a `zip.File` whose `Name` is `../../etc/cron.d/x`, `../../../home/gitlab-runner/.ssh/authorized_keys`, or (on platforms where `zip.File.Name` is not forced relative, or via crafted headers) an absolute path. When the runner restores that cache/artifact by extracting the zip in the job's working directory, `os.MkdirAll(filepath.Dir(file.Name), 0o777)` will create parent directories outside the workspace and the subsequent `os.OpenFile`/`os.Symlink` will write/overwrite the target file, breaking the confinement invariant that job-controlled archives must stay inside the job root.

### Impact Explanation
Successful exploitation lets an unprivileged pipeline author write or overwrite arbitrary files on the host filesystem underneath the runner process's working-directory tree and beyond, limited only by the OS-level permissions of the user running the job (e.g., the `gitlab-runner` user for shell executor, or the container's write permissions for container executors sharing a host path). This can lead to persistence (cron jobs, SSH authorized_keys, shell profile files), corruption of other jobs' data if caches/workspaces share a parent directory, or clobbering of arbitrary writable files — a concrete violation of the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Feasibility is high and fully reproducible: the attacker only needs to control the *contents* of a cache or artifact archive, which is a normal, unprivileged capability of any pipeline author (via `cache:paths`, symlinked directories, or a custom zip crafted outside the normal `CreateZipArchive` flow, e.g. supplying a pre-built cache artifact through `artifacts:reports`/cache restore endpoints or a compromised/soft-linked source tree). Because `CreateZipArchive` (the packing side) typically writes relative, workspace-scoped names, exploitation more realistically requires the attacker to supply a zip whose entries were not produced by GitLab Runner's own archiver (e.g., a cache blob restored from an external/self-managed cache storage, or a maliciously altered artifact reused across pipeline stages within the same project) — but nothing in `ExtractZipArchive` itself verifies that entries are safe, so any such zip is exploitable deterministically and repeatably on every extraction.

### Recommendation
In `extractZipFile` (and before any per-entry action), resolve each entry against the extraction root and reject entries that escape it:
1. Compute `target := filepath.Join(root, file.Name)`.
2. Verify `strings.HasPrefix(filepath.Clean(target), filepath.Clean(root)+string(os.PathSeparator))` (or use `filepath.Rel` and check for a leading `..`).
3. Reject/skip entries with absolute paths or `..` segments, following the same "actionable"/warning pattern already used for `.git` detection (`errorIfGitDirectory`), so behavior stays consistent with existing error-tracking (`tracker.actionable`).
4. Apply this validation to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, and `extractZipFileEntry` before calling `os.Mkdir`/`os.Symlink`/`os.OpenFile`.

```go
func TestExtractZipFile_PathTraversalRejected(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        f, err := os.Create(fileName)
        require.NoError(t, err)
        defer f.Close()

        w := zip.NewWriter(f)
        entry, err := w.Create("../../tmp/pwned_by_zip_traversal")
        require.NoError(t, err)
        _, err = entry.Write([]byte("pwned"))
        require.NoError(t, err)
        require.NoError(t, w.Close())
        f.Close()

        err = ExtractZipFile(fileName)
        // With current code this succeeds (no error) and the file is written
        // outside the sandbox; after the fix, extraction of this entry must
        // be rejected/skipped and the file must not exist outside the root.
        _, statErr := os.Stat("/tmp/pwned_by_zip_traversal")
        assert.True(t, os.IsNotExist(statErr), "traversal entry must not be written outside sandbox root")
        _ = os.Remove("/tmp/pwned_by_zip_traversal") // cleanup if test fails pre-fix
    })
}
```
Expected assertion: after the fix, `os.Stat("/tmp/pwned_by_zip_traversal")` returns `IsNotExist`; on current code, the file is created, proving the bug.

```go
func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	}
	return

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)

	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```

```go
func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
```
