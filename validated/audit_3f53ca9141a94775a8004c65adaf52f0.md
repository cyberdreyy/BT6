### Title
Unauthenticated allowlist/rate-limit bypass on `MethodWebAPITrigger` allows quota-consuming fan-out to all DON members - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` only validates message structure, signature well-formedness, and timestamp freshness before forwarding a `MethodWebAPITrigger` request to every DON member via `don.SendToNode`. There is no allowlist or subscription check gating the sender, confirmed explicitly by the `// TODO: apply allowlist and rate-limiting here` comment at line 384 with no code enforcing it anywhere in the call path.

### Finding Description
The request path is: gateway.ProcessRequest (`core/services/gateway/gateway.go:267-269`) decodes the JSON-RPC request, calls `msg.Validate()` [1](#0-0) , then dispatches directly to `h.HandleLegacyUserMessage(ctx, msg, callback)` [2](#0-1) .

`msg.Validate()` only checks field lengths/format and recovers the signer address from the ECDSA signature over the message body via `ExtractSigner` — it does not check the recovered address against any DON/workflow allowlist; any keypair can produce a validly-signed message [3](#0-2) .

Inside `HandleLegacyUserMessage`, the checks performed are: payload JSON decoding, non-zero timestamp, and staleness window [4](#0-3) . Immediately after these checks, the explicit TODO comment confirms no allowlist/rate-limit enforcement exists at this call site [5](#0-4) . The method then proceeds to build a request and fan it out to every DON member unconditionally: [6](#0-5) 

The only rate limiting present in this file, `h.nodeRateLimiter`, is applied in `handleWebAPIOutgoingMessage` keyed by `nodeAddr` for outgoing (node→gateway) HTTP-egress messages, not for incoming user trigger submissions [7](#0-6) . This confirms no per-sender or per-workflow-owner throttling exists for `MethodWebAPITrigger` submissions.

An attacker only needs any ECDSA keypair (no registration, no allowlist entry, no subscription) to produce a validly-signed `api.Message` with `Method: web_api_trigger`, a fresh timestamp, and a valid `TriggerRequestPayload`. Every such message is forwarded to all `h.donConfig.Members`, consuming DON compute and (via `handleWebAPIOutgoingMessage`/`sendHTTPMessageToClient`) node HTTP egress resources that are meant to be reserved for allowlisted/subscribed workflow owners.

### Impact Explanation
This matches a resource-exhaustion / quota-bypass class impact: an unauthenticated or non-subscribed actor can force unlimited processing and HTTP fan-out work onto every member node of a DON, degrading service for or consuming compute/egress quota intended for legitimately allowlisted/subscribed users, and enabling amplification (1 signed request → N node deliveries → N HTTP requests to arbitrary external URLs, since `payload.URL`/method/headers eventually flow into `network.HTTPRequest` for outgoing messages).

### Likelihood Explanation
Highly likely/trivial to exploit: the attacker needs no credentials beyond generating a local ECDSA key to sign the message body per `Message.Sign` [8](#0-7) , and no allowlist entry, subscription, or prior registration is checked anywhere between the gateway entrypoint and the fan-out. It is fully repeatable and scriptable (loop of N signed requests with distinct message IDs), each independently accepted since the only per-message checks are timestamp freshness and JSON schema validity.

### Recommendation
Implement the allowlist/rate-limiting check at the marked TODO location in `HandleLegacyUserMessage`, before the fan-out loop: verify `msg.Body.Sender` (populated during `Validate()`) against a workflow/DON allowlist (analogous to `allowListBasedAuth.AuthorizeRequest` used elsewhere) and apply a per-sender rate limiter (similar to `h.nodeRateLimiter`, but keyed by sender address) prior to calling `don.SendToNode`.

### Proof of Concept
Go handler-level integration test plan (extending `core/services/gateway/handlers/capabilities/handler_test.go`):
1. `setupHandler(t)` to obtain `handler`, mocked `don`.
2. Generate an arbitrary/unregistered ECDSA key not present in `h.donConfig` allowlist or any node config.
3. Build N (`N > 1`) distinct `triggerRequest(t, arbitraryKey, topics, MethodWebAPITrigger, "", payload)` messages with unique `MessageId`s.
4. Assert `don.On("SendToNode", ...)` is invoked `N * len(donConfig.Members)` times, once per message per DON member, with no error returned and no allowlist-rejection error code (`api.UserMessageParseError`/`api.UnsupportedMethodError`) in the callback response.
5. Confirm `cb.Wait` returns a successful (non-error) callback payload for each of the N attacker-submitted requests, demonstrating unrestricted fan-out to all DON members despite the sender never being registered in `h.donConfig` or any allowlist.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
