### Title
Masker's `[MASKED]` fast-path in `tokensanitizer` desynchronizes prefix-matching state, leaking `glpat-`/token secrets in cleartext - (File: `common/buildlogger/build_logger.go`, `common/buildlogger/internal/tokensanitizer/token_masker.go`, `common/buildlogger/internal/masker/masker.go`)

### Summary
`Logger.wrap` chains sanitizers so that `masker` processes bytes first and forwards its output to `urlsanitizer` then `tokensanitizer`. When `masker` replaces a matched CI mask phrase with the literal `[MASKED]` bytes as an isolated `Write` call, `tokenSanitizer.Write`'s fast path (`bytes.Equal(p, mask)`) forwards that call downstream without reconciling its own in-progress `m.matching` counter from a partially-matched `glpat-`-style prefix. This desynchronizes the token state machine and causes the true, unrelated secret suffix that should have been masked by `tokensanitizer` to be emitted in cleartext.

### Finding Description
`Logger.wrap` (`common/buildlogger/build_logger.go:213-224`) builds the chain in this actual processing order (outer to inner, since "last added filter is first to process"): `masker` → `urlsanitizer` → `tokensanitizer` → `timestamper` → base writer, exactly as the docstring states [1](#0-0) .

`masker.masker.Write` scans the stream for a configured mask phrase (from `Options.MaskPhrases`, populated from masked CI/CD variables). When a phrase match completes, it calls `m.Write(mask)` recursively, which — due to the fast path `if bytes.Equal(p, mask) { return m.next.Write(p) }` — is forwarded to the next writer as an **isolated** `Write([]byte("[MASKED]"))` call [2](#0-1) [3](#0-2) .

`tokenSanitizer.Write` has the identical fast path at the very top of its function: if the whole buffer equals `[MASKED]`, it forwards immediately to `m.next.Write(p)` [4](#0-3) . This bypass does **not** check or flush `m.matching`, the counter tracking how many bytes of a `glpat-`/token prefix have already been matched from a prior `Write` call [5](#0-4) . Consequently:

1. If `masker` splits a real token (e.g. `glpat-SECRETVALUE`) so that a fragment of the `glpat-` prefix (e.g. `"gl"`) is sent to `tokensanitizer` first, `m.matching` becomes non-zero (partial prefix match pending, nothing yet written downstream).
2. `masker` then sends the isolated `[MASKED]` chunk for its own matched phrase (which can be a totally unrelated masked variable value that merely happens to contain a substring like `"pat-"`) — `tokenSanitizer` forwards this untouched, leaving `m.matching` stuck at its old value.
3. The remaining real secret bytes (e.g. `"SECRETVALUE\n"`) arrive next. Because `m.matching` no longer reflects the actual byte stream (the interposed `[MASKED]` broke the contiguous match), the prefix comparison fails; `tokenSanitizer` then flushes the previously withheld prefix bytes (`"gl"`) and writes the **entire remaining secret value in cleartext**, since it never recognizes a valid `glpat-`+alphabet token anymore.

The result: `tokensanitizer`'s default `glpat-` masking (`DefaultTokenPrefixes`, always active) is defeated whenever an unrelated masked CI variable's value happens to overlap positionally with the `glpat-` prefix window of a genuine token elsewhere in the same combined trace write. No existing check (the `bytes.Equal(p, mask)` fast paths in both `masker` and `tokensanitizer`) accounts for cross-layer partial-match state, so the "layers must not desynchronize" invariant is broken.

### Impact Explanation
A genuine secret protected by `tokensanitizer`'s default `glpat-` (or other configured prefix) masking can be emitted in cleartext in the job trace/log, exposing it to anyone with trace access (e.g. project members with job log visibility), even though masking is configured. The attacker does not need to know the secret's value in advance — corrupting `tokensanitizer`'s prefix state machine only requires controlling an unrelated masked-phrase value (a masked CI/CD variable) that shares a short substring with the fixed, publicly known `glpat-` prefix (e.g. `"pat-"`), which is trivial to arrange.

### Likelihood Explanation
Preconditions are realistic for the stated attacker: an unprivileged pipeline author who can (a) define/use a masked CI variable whose value happens to contain a short substring overlapping `glpat-` (e.g. `"pat-"`, `"lpat"`, `"at-"`) and (b) cause both that variable's value and a real `glpat-`-prefixed secret to be printed in the same trace stream chunk (a very common accidental occurrence — CI scripts routinely echo tokens/variables for debugging). The bug is purely deterministic/positional, not timing-dependent, so it is 100% repeatable once the byte layout is known, and requires no privileged access beyond ordinary job/variable configuration.

### Recommendation
In `tokenSanitizer.Write` (and the analogous fast path in `masker.masker.Write`), do not unconditionally short-circuit on `bytes.Equal(p, mask)` when `m.matching > 0`. Either:
- flush the pending `m.prefix[:m.matching]` bytes to `next` *before* forwarding the `[MASKED]` chunk, and reset `m.matching` to 0, or
- track pending state across the interposed write instead of allowing it to persist unmodified into the subsequent unrelated data chunk.
More generally, restructure the chain so isolated `[MASKED]` writes from an outer layer always reset/flush inner layers' partial-match counters before being passed through.

// wrap wraps the underlying writer with "filters". Order here somewhat
// matters, and the order they're instantiated in is the reverse order in which
// writes are processed, e.g. last added filter is the first to process data.
//
// order:
// - sync writer to ensure that multiple writes cannot happen concurrently
// - mask phrases (masker.New)
// - mask sensitive URL parameters (urlsanitizer.New)
// - mask secrets with a prefixed token (tokentanitizer.New)
// - split log lines and add timestamps (timestamper.New)
func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {
		w = timestamper.New(w, timestamper.StreamType(streamType), uint8(streamID), true)
	}

	w = tokensanitizer.New(w, l.maskTokenPrefixes)
	w = urlsanitizer.New(w)
	w = masker.New(w, l.maskPhrases)
	w = internal.NewSync(w)

	return w
}
