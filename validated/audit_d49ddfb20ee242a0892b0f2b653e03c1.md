### Title
Permissionless `new_currency<T>` Allows Front-Running Currency Registration and Unauthorized `TreasuryCap` Acquisition — (File: `crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

---

### Summary

`coin_registry::new_currency<T: key>` is declared `public` with only a non-enforced `/* internal */` comment on the type constraint. Any caller can invoke it for any type `T` with the `key` ability before the legitimate module owner does. The function immediately claims the deterministic `CurrencyKey<T>()` slot in the shared `CoinRegistry` and returns an unrestricted `TreasuryCap<T>` to the caller, permanently blocking the legitimate owner from registering their currency and granting the attacker an unauthorized minting capability.

---

### Finding Description

`new_currency` is the single-step registration path for non-OTW coin types:

```move
public fun new_currency<T: /* internal */ key>(
    registry: &mut CoinRegistry,
    decimals: u8,
    symbol: String,
    ...
    ctx: &mut TxContext,
): (CurrencyInitializer<T>, TreasuryCap<T>) {
    assert!(!registry.exists<T>(), ECurrencyAlreadyExists);
    ...
    let treasury_cap = coin::new_treasury_cap(ctx);
    let currency = Currency<T> {
        id: derived_object::claim(&mut registry.id, CurrencyKey<T>()),
        ...
    };
    (CurrencyInitializer { currency, ... }, treasury_cap)
}
``` [1](#0-0) 

The `/* internal */` annotation on `T: key` is a comment, not a Move language constraint. The Move type system imposes no restriction preventing an external caller from supplying any type `T` with the `key` ability as the type parameter. The sole guard is `!registry.exists<T>()`, which only prevents a second registration — it does not verify that the caller has any relationship to the type `T`.

Inside the function, `coin::new_treasury_cap` is `public(package)` and therefore callable only from within the `sui` framework package:

```move
public(package) fun new_treasury_cap<T>(ctx: &mut TxContext): TreasuryCap<T> {
    TreasuryCap {
        id: object::new(ctx),
        total_supply: balance::create_supply_internal(),
    }
}
``` [2](#0-1) 

Because `coin_registry` is part of the same `sui` package, it can call `new_treasury_cap` freely. The resulting `TreasuryCap<T>` is fully functional: `create_supply_internal` produces a `Supply<T>` with value 0 that can be grown without bound via `balance::increase_supply`, enabling unlimited minting of `Coin<T>`. [3](#0-2) 

The deterministic slot is claimed via `derived_object::claim`:

```move
id: derived_object::claim(&mut registry.id, CurrencyKey<T>()),
``` [4](#0-3) 

`derived_object::claim` aborts with `EObjectAlreadyExists` if the `(registry_id, CurrencyKey<T>())` pair has already been reserved:

```move
assert!(!df::exists(parent, Claimed(id)), EObjectAlreadyExists);
df::add(parent, Claimed(id), ClaimedStatus::Reserved);
``` [5](#0-4) 

Once an attacker claims the slot, every subsequent call to `new_currency<T>` by the legitimate owner aborts at `ECurrencyAlreadyExists` (line 183), and every call to `migrate_legacy_metadata<T>` aborts at `ECurrencyAlreadyRegistered` (line 704). The slot is permanently occupied. [6](#0-5) 

**Why the OTW path is not affected:** `new_currency_with_otw<T: drop>` requires a One-Time Witness value (`sui::types::is_one_time_witness`), which can only be produced once, in the `init` function of the module that defines `T`. OTW types carry `drop` but not `key`, so they cannot be passed to `new_currency<T: key>`. The two-step OTW flow (`new_currency_with_otw` → `finalize_registration`) is therefore not reachable by this attack. [7](#0-6) 

The vulnerable path is the non-OTW `new_currency` function, which is the designated registration route for types with the `key` ability.

---

### Impact Explanation

An attacker who front-runs the victim's `new_currency<T>` call:

1. **Permanently blocks registration.** The `CurrencyKey<T>()` slot is claimed; the legitimate owner can never register `T` in the `CoinRegistry`.
2. **Acquires an unauthorized `TreasuryCap<T>`.** The attacker can mint unlimited `Coin<T>` tokens, inflating supply and stealing value from any holders of `T`-denominated assets.
3. **Acquires `MetadataCap<T>`.** After calling `finalize` on the hot-potato `CurrencyInitializer<T>`, the attacker controls all metadata (name, symbol, icon) for the currency.

This satisfies the Critical impact criterion: *direct fund theft from unauthorized object creation* (`TreasuryCap<T>` for a type the attacker does not own).

---

### Likelihood Explanation

- The `CoinRegistry` is a shared object at `0xc`; any transaction can pass it as `&mut CoinRegistry`.
- The type `T` is public information visible on-chain as soon as the victim's package is published.
- The attacker only needs to submit a transaction with the same type argument before the victim's transaction is sequenced.
- No special capability, key, or privileged role is required.

---

### Recommendation

1. **Change `new_currency` to `public(package)`** and expose a separate entry point that requires a witness or capability proving the caller controls type `T` (e.g., a `TreasuryCap<T>` or a module-level witness struct).
2. **Alternatively**, add a publisher-proof check: require the caller to supply a `Publisher` object (from `sui::package`) whose package matches the defining package of `T`, mirroring the pattern used by `sui::display::new`.
3. **Document the invariant** that `new_currency` must only be called from the module that defines `T`, and enforce it in code rather than in a comment.

---

### Proof of Concept

```
1. Victim publishes package P containing:
       public struct VCOIN has key { id: UID }

2. Victim prepares PTB:
       coin_registry::new_currency<P::vcoin::VCOIN>(registry, 6, "VC", "VictimCoin", "", "", ctx)
       → finalize(initializer, ctx)

3. Attacker observes the pending transaction and submits first:
       coin_registry::new_currency<P::vcoin::VCOIN>(registry, 6, "FAKE", "Fake", "", "", ctx)
       → finalize(initializer, ctx)   // resolves the hot potato

4. Attacker's transaction is sequenced first.
   - derived_object::claim(registry.id, CurrencyKey<VCOIN>()) succeeds.
   - Attacker receives TreasuryCap<VCOIN> and MetadataCap<VCOIN>.
   - Currency<VCOIN> is shared with attacker-controlled metadata.

5. Victim's transaction aborts: ECurrencyAlreadyExists (registry.exists<VCOIN>() == true).

6. Attacker calls coin::mint(&mut treasury_cap, 1_000_000_000_000, ctx)
   → mints 1 trillion Coin<VCOIN> with no supply cap.
```
