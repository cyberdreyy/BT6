### Title
Attacker-controlled MessageId collision overwrites in-flight victim callback in savedCallbacks map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` stores pending user callbacks keyed only by `msg.Body.MessageId` in `h.savedCallbacks`, without checking for an existing in-flight entry or scoping the key by sender. Since `MessageId` is attacker-chosen (taken directly from the JSON-RPC request `ID` field, not server-generated), any unauthenticated caller can submit a request whose `MessageId` collides with another user's currently in-flight `MessageId`, silently overwriting the victim's saved callback.

### Finding Description
In `gateway.go`'s `ProcessRequest`, the message ID comes straight from the untrusted request: `msg.Body.MessageId` is populated by `g.codec.DecodeJSONRequest` from `jsonRequest.ID` [1](#0-0) , and only length/null-byte checks are applied via `msg.Validate()` [2](#0-1)  — there is no uniqueness or collision check against messages currently in flight. The message is signed, so `Sender` is authenticated [3](#0-2) , but `Sender` is never used to disambiguate the callback key in this handler.

`HandleLegacyUserMessage` then does an unconditional map write:
```
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [4](#0-3) 

There is no "already exists" check — a second request with the same `MessageId` (even from a different, unrelated signer) simply overwrites the map entry, dropping the reference to the first (victim's) `callback`. When node responses later arrive, `HandleNodeMessage` → `handleWebAPITriggerMessage` looks up and deletes the entry solely by `msg.Body.MessageId` [5](#0-4) , so only the most recently registered (attacker's) callback will ever receive a response; the original victim's `callback.Wait(ctx)` in `gateway.go` will time out [6](#0-5) .

Notably, the codebase already has a hardened pattern for this exact problem: `common.RequestCache` keys pending requests by `globalId{sender, id}` and explicitly rejects duplicates with `"request already exists"` [7](#0-6) , and it's used by other handlers (e.g., vault, http_trigger v2). The capabilities `handler.go` does not use this shared cache and instead reimplements its own unscoped, non-colliding-unsafe map.

### Impact Explanation
An unauthenticated (or minimally authenticated, signature-only) attacker who can guess or predict/observe a victim's in-flight `MessageId` can hijack or DoS that victim's capability-trigger request: the victim's HTTP call to the gateway (`ProcessRequest` → `HandleLegacyUserMessage` → `callback.Wait`) will hang until `RequestTimeoutError`, effectively denying the victim's web API trigger execution. Because the callback is looked up only by `MessageId` (not by sender), if the attacker's request happens to reach the same DON nodes with the same `MessageId`, node responses intended for either request are dispatched to whichever callback remains registered, causing cross-user response confusion. This matches the "cross-user response hijack / DoS of a legitimate user's request" bounty impact class.

### Likelihood Explanation
Exploitability requires only the ability to send a signed `HandleLegacyUserMessage`-shaped gateway request with an attacker-chosen `MessageId` — signing keys can belong to any registered/allowed sender (not necessarily privileged), and there is no requirement to be the victim or share credentials. `MessageId` values are often predictable/enumerable (e.g., short-lived UUIDs, sequential IDs, or reused client conventions), and the race window is the full round trip time to the DON (potentially hundreds of ms to seconds), which is easily exploitable. This is repeatable on every request cycle since no de-duplication or "already exists" check exists.

### Recommendation
Scope `savedCallbacks` by `(sender, MessageId)` similar to `common.RequestCache`'s `globalId{sender, id}` key, and reject (rather than silently overwrite) new requests whose key already has a live, unexpired entry, returning an explicit `"request already exists"` style error to the second caller. Consider migrating this handler to reuse `common.RequestCache` directly instead of maintaining a separate, less-safe map.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct two signed `api.Message`s with the same `MessageId` and `MethodWebAPITrigger`, one signed by "victim" key, one by "attacker" key, both targeting the same `donConfig`.
2. Call `h.HandleLegacyUserMessage(ctx, victimMsg, victimCallback)` (do not resolve yet — mock `don.SendToNode` to not synchronously respond).
3. Call `h.HandleLegacyUserMessage(ctx, attackerMsg, attackerCallback)` with the same `MessageId`.
4. Assert `len(h.savedCallbacks)` still has only one entry keyed by `MessageId`, and that it is the attacker's callback, not the victim's — i.e. `h.savedCallbacks[msg.Body.MessageId].Callback != victimCallback`.
5. Simulate `HandleNodeMessage` with `MethodWebAPITrigger` response for that `MessageId` and assert `attackerCallback.SendResponse` is invoked while `victimCallback.Wait` times out / never receives a response — demonstrating the current (vulnerable) overwrite behavior, which should be replaced by an explicit rejection per the recommended fix.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response

		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

type globalId struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
