**Analysis:**

The claim mischaracterizes how `synchronize_delegation_pool` computes commission versus how it handles `add_stake` fee redemption for `NULL_SHAREHOLDER`.

1. `calculate_stake_pool_drift` is called *first*, and computes `commission_active` strictly from the drift between the real stake-pool `active` balance and `pool.active_shares.total_coins()` *as it stood before the NULL_SHAREHOLDER redemption* [1](#0-0) . Since `pending_active`/fee coins were already included in that pre-redemption `total_coins()` snapshot (from when `add_stake` bought shares for `NULL_SHAREHOLDER`), the fee amount is excluded from the commission calculation - commission is levied only on genuine reward drift, not on the fee.

2. Only *after* commission is computed does `synchronize_delegation_pool` conditionally redeem `NULL_SHAREHOLDER`'s shares via `redeem_active_shares(pool, NULL_SHAREHOLDER, MAX_U64)`, but only when `pending_active == 0` [2](#0-1) .

3. Immediately afterward, `pool.active_shares.update_total_coins(active - commission_active)` *overwrites* `total_coins` with the true, freshly-computed value derived directly from the real stake-pool balance minus the already-calculated commission [3](#0-2) . This is what implements the refund mechanism explicitly documented in the module header: "`add_stake` fees are always refunded... First synchronization after this epoch ends will distribute accumulated fees to the rest of the pool as refunds" [4](#0-3) .

4. Operator/beneficiary commission is bought using `commission_active` — a value computed independently of, and prior to, the NULL_SHAREHOLDER redemption [5](#0-4) . The redeemed fee value flows into `total_coins`, which raises share price for all *existing* shareholders (delegators and any operator shares already held), but does not add extra shares or extra coin value specifically to the operator's beneficiary.

5. This is confirmed by the framework's own unit test `test_add_stake_single`, which asserts that after synchronization the delegator gets back exactly the fee amount, and `NULL_SHAREHOLDER`'s shares are zeroed with no commission inflation observed [6](#0-5) .

`synchronize_delegation_pool` being callable by anyone is intentional (it merely reflects on-chain stake-pool state into the delegation pool's accounting, it doesn't let a caller redirect value) [7](#0-6) . No unprivileged caller can cause add_stake-fee-derived value to be misattributed as operator/beneficiary commission — the commission and fee-refund calculations are structurally independent.
