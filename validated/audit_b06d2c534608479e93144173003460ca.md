### Title
Missing role-based authorization on transaction detail/list endpoints allows view-role users to read full transaction data - ([File: core/web/router.go])

### Summary
The `/v2/transactions/evm`, `/v2/transactions/evm/:TxHash`, `/v2/transactions`, `/v2/transactions/:TxHash`, `/v2/tx_attempts`, and `/v2/tx_attempts/evm` routes are registered under `authv2` with only generic session/token authentication and no `auth.RequiresEditRole`/`auth.RequiresRunRole`/`auth.RequiresAdminRole` wrapper, unlike almost every other sensitive route in the file. Any authenticated user, including one with the lowest `UserRoleView` role, can therefore call `TransactionsController.Show`/`Index` and `TxAttemptsController.Index` to retrieve full on-chain transaction details (from/to address, nonce, gas limit/price, raw signed tx hex, encoded payload) for any transaction the node has ever sent, including ones submitted via admin-only actions like `/transfers/evm`.

### Finding Description
In `v2Routes` (`core/web/router.go`), routes are registered as: [1](#0-0) 
Compare this to the sibling `/transfers/evm` POST route, which is explicitly gated with `auth.RequiresAdminRole(ets.Create)`: [2](#0-1) 
The only middleware in front of `authv2` (and hence these transaction routes) is generic authentication that accepts any valid session or API token regardless of role: [3](#0-2) 
`auth.Authenticate` only verifies the requester is *some* valid user (session or token) — it does not check role at all: [4](#0-3) 
Role checks only happen when a route is explicitly wrapped with `RequiresRunRole`, `RequiresEditRole`, or `RequiresAdminRole`, e.g.: [5](#0-4) 
Since none of the transaction/tx_attempt routes use any of these wrappers, `TransactionsController.Show` executes for any authenticated user: [6](#0-5) 
and `TxAttemptsController.Index` similarly has no role gate: [7](#0-6) 
Both return `presenters.EthTxResource`, which includes sensitive fields — `From`, `To`, `GasLimit`, `GasPrice`, `Hash`, `Hex` (raw signed transaction), `Nonce`, `Value`, `Data` (encoded payload) — with no redaction based on caller role: [8](#0-7) [9](#0-8) 

An attacker with only a view-role session or API token can therefore GET `/v2/transactions/evm/:TxHash` for any transaction hash (which can be enumerated via `/v2/transactions/evm` index, itself also unguarded) and obtain the raw signed transaction, sender/receiver addresses, nonce, and gas parameters for transactions submitted through admin-only flows (e.g., `/v2/transfers/evm`), exposing node key-usage and operational fund-movement patterns to an unprivileged user.

### Impact Explanation
This is an authorization-exactness gap (missing least-privilege enforcement) resulting in disclosure of sensitive operational data — node hot-wallet addresses, transaction counterparties, nonces, and raw signed transactions — to a low-privilege ("view") authenticated user who should not have visibility into transaction execution details reserved for edit/admin roles. This maps to Chainlink's bounty impact class of unauthorized information disclosure / broken access control (sensitive data exposure to unprivileged authenticated users), not fund loss directly, since view-role users cannot cause the tx to be broadcast, but do gain intelligence about admin-initiated transfers and wallet usage patterns.

### Likelihood Explanation
This requires only a valid, already-provisioned `view`-role session or API token — the lowest privilege authenticated credential the node issues (`clsessions.UserRoleView`). No additional exploitation steps, race conditions, or misconfiguration are needed: a single unauthenticated-role-check-bypassing GET request to `/v2/transactions/evm/:TxHash` or `/v2/tx_attempts` succeeds every time given a valid TxHash (obtainable via the also-unguarded `/v2/transactions/evm` index route or via out-of-band knowledge of a hash). This is fully repeatable and requires no privilege escalation vulnerability elsewhere in the code — only possession of a `view` role account, which by design in Chainlink nodes is meant to be a restricted, read-limited role.

### Recommendation
Wrap the transaction and tx-attempt routes with an explicit role check consistent with other sensitive read/list endpoints, e.g.:
```go
authv2.GET("/transactions/evm", auth.RequiresEditRole(paginatedRequest(txs.Index)))
authv2.GET("/transactions/evm/:TxHash", auth.RequiresEditRole(txs.Show))
authv2.GET("/transactions", auth.RequiresEditRole(paginatedRequest(txs.Index)))
authv2.GET("/transactions/:TxHash", auth.RequiresEditRole(txs.Show))
authv2.GET("/tx_attempts", auth.RequiresEditRole(paginatedRequest(tas.Index)))
authv2.GET("/tx_attempts/evm", auth.RequiresEditRole(paginatedRequest(tas.Index)))
```
Additionally, consider redacting `Hex` (raw signed tx) and `Data` fields from `EthTxResource` for lower-privileged roles, since raw signed transactions can reveal calldata for sensitive operations.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/evm_transactions_controller_test.go` / `core/web/evm_tx_attempts_controller_test.go`):
1. Set up a test app via `cltest.NewApplicationEVMDisabled`/`setupEthTxsControllerTests`-style helper, seed a `txmgr.Tx`/`TxAttempt` (simulating one created by an admin-only `/transfers/evm` call) with distinct `FromAddress`, `ToAddress`, `SignedRawTx`.
2. Create two authenticated HTTP clients via `cltest.NewTestClient`/session helpers: one with `clsessions.UserRoleAdmin`, one with `clsessions.UserRoleView`.
3. As the view-role client, issue `GET /v2/transactions/evm/<hash>` and `GET /v2/tx_attempts`.
4. Assert current (vulnerable) behavior: HTTP 200 with full `EthTxResource` JSON body containing `from`, `to`, `nonce`, `gasLimit`, `rawHex` fields — i.e., no 401/403 is returned despite the view role.
5. After applying the fix (wrapping routes with `auth.RequiresEditRole`), re-run the same requests as the view-role client and assert HTTP 401/"Unauthorized", while an edit/admin-role client still receives HTTP 200 with the resource.

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (tc *TransactionsController) Show(c *gin.Context) {
	hash := common.HexToHash(c.Param("TxHash"))

	ethTxAttempt, err := tc.App.TxmStorageService().FindTxAttempt(c, hash)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("Transaction not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewEthTxResourceFromAttempt(*ethTxAttempt), "transaction")

// Index returns paginated transaction attempts
func (tac *TxAttemptsController) Index(c *gin.Context, size, page, offset int) {
	attempts, count, err := tac.App.TxmStorageService().TxAttempts(c, offset, size)
	ptxs := make([]presenters.EthTxResource, len(attempts))
	for i, attempt := range attempts {
		ptxs[i] = presenters.NewEthTxResourceFromAttempt(attempt)
	}
	paginatedResponse(c, "transactions", size, page, ptxs, count, err)

func NewEthTxResourceFromAttempt(txa txmgr.TxAttempt) EthTxResource {
	tx := txa.Tx

	r := NewEthTxResource(tx)
	r.JAID = NewJAID(txa.Hash.String())
	r.GasPrice = txa.TxFee.GasPrice.ToInt().String()
	r.Hash = txa.Hash
	r.Hex = hexutil.Encode(txa.SignedRawTx)

	if txa.Tx.ChainID != nil {
		r.EVMChainID = *sqlutil.New(txa.Tx.ChainID)
		r.JAID = NewPrefixedJAID(r.ID, txa.Tx.ChainID.String())
	}

	if tx.Sequence != nil {
		r.Nonce = strconv.FormatInt(int64(*tx.Sequence), 10)
	}
	if txa.BroadcastBeforeBlockNum != nil {
		r.SentAt = strconv.FormatInt(*txa.BroadcastBeforeBlockNum, 10)
	}
	return r
