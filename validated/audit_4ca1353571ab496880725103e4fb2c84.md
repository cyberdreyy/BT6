### Title
requestID squatting causes cross-user denial of service via global (non-namespaced) callback map - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`h.callbacks` in `httpTriggerHandler` is a single global map keyed only by the caller-supplied `requestID` string, with no scoping to workflow or owner. [1](#0-0)  An attacker who is authorized for their own workflow A can submit a `workflows.execute` request whose `id` matches a value they predict a victim (e.g. a client using sequential/timestamp IDs) will use, winning the `setupCallback` race and causing the victim's later, legitimate request with the same `id` to fail with `jsonrpc.ErrConflict`. [2](#0-1) 

### Finding Description
`HandleUserTriggerRequest` validates the request, resolves the workflow, authorizes the caller against *their own* workflow, checks rate limits, then calls `setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)`. [3](#0-2)  `validateRequestID` only rejects empty IDs or IDs containing `/`; it does not scope or namespace the ID by workflow/owner. [4](#0-3)  `setupCallback` checks for existence in the single global `h.callbacks` map and, if present, calls `handleUserError(..., jsonrpc.ErrConflict, ...)` and returns an error without ever creating the callback. [2](#0-1) 

Because authorization is performed against the *attacker's own* workflow (via `authorizeRequest`/`workflowMetadataHandler.Authorize`) [5](#0-4) , the attacker needs no privilege on the victim's workflow at all — they only need to be authorized for any workflow of their own and correctly predict/observe the exact `requestID` string the victim will submit next. If the attacker's request with that ID arrives first, it occupies the slot in `h.callbacks`; when the victim's genuine request with the same `requestID` arrives, `setupCallback` sees `found == true` and unconditionally returns `ErrConflict` to the victim, regardless of workflow — the victim's execution never runs.

Regarding the second part of the question (whether the attacker's `reqWithAuthorizedKey`-marshaled request could appear to be, or be confused with, the victim's expected response): this is not exploitable. The `Callback` object bound to a given request is a per-connection object created by the specific caller's session (`common.Callback`, a single-use channel) [6](#0-5) , and `HandleNodeTriggerResponse` routes node responses back through `saved.Callback` — the callback captured from whichever request won the `setupCallback` race (the attacker's own) — not the victim's connection. [7](#0-6)  The attacker's own `workflowID`, shards, and `AuthorizedKey` are used to build and dispatch the request, so responses are aggregated and delivered only to the attacker's own session, never impersonating or leaking the victim's data or key. This half of the question is invalid.

### Impact Explanation
This is a targeted, single-request denial-of-service: an attacker authorized only for their own workflow can silently deny a specific victim execution attempt by squatting a predictable `requestID` before the victim submits it. Impact is scoped to individual request delivery failure (the victim receives `ErrConflict` and the execution never starts) rather than broader compromise, data leakage, or fund movement. This matches a scoped "Denial of Service" bounty class rather than authentication/authorization bypass or data disclosure, since no cross-user response/data confusion is achievable (see above).

### Likelihood Explanation
Requires the attacker to (a) hold authorization for at least one workflow of their own (a low bar, since authorization is workflow-specific and the attacker doesn't need any privilege on the victim's workflow), and (b) accurately predict/observe the exact `requestID` value the victim's client will use before the victim's request is submitted — feasible against clients with deterministic (sequential/timestamp-based) ID generation, as noted in the question's precondition. The race is winnable trivially since there is no per-user or per-workflow namespacing of IDs and no additional binding check in `setupCallback`. [2](#0-1) 

### Recommendation
Namespace the callback map key by workflow/owner in addition to the raw `requestID` (e.g., key on `workflowID + "/" + requestID` or a hash including the authorized owner) so that IDs are only unique within a given workflow/owner's own namespace, preventing cross-workflow ID collisions. Alternatively, bind `requestID` uniqueness to the resolved `workflowID` inside `setupCallback` before checking for conflicts, so an attacker's own workflow ID collision cannot block a different workflow's identically-named request.

### Proof of Concept
Go unit test in `http_trigger_handler_test.go`:
1. Construct an `httpTriggerHandler` with two distinct authorized workflows, A (attacker) and B (victim), each properly registered via `workflowMetadataHandler`.
2. Attacker calls `HandleUserTriggerRequest` with `req.ID = "predictable-id"` and `Workflow` fields pointing to workflow A, using a valid attacker callback; assert `setupCallback` succeeds (no error, entry created in `h.callbacks["predictable-id"]`).
3. Victim then calls `HandleUserTriggerRequest` with `req.ID = "predictable-id"` (same ID) but `Workflow` fields pointing to workflow B, using a distinct victim callback.
4. Assert: the victim's call returns an error, and the victim's callback receives a `jsonrpc.ErrConflict` response via `SendResponse` (verify `UserCallbackPayload.ErrorCode`/`RawResponse` contains `"has already been used"`), and that the victim's request never reaches `sendWithRetries`/`sendToShard` (no calls to workflow B's shard `connMgr.SendToNode`).
5. Additionally assert that the attacker's callback (not the victim's) is the one still present in `h.callbacks`, demonstrating that a same-owner-namespace check is missing and cross-workflow squatting succeeds.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
	aggResp, err := agg.CollectAndAggregate(resp, nodeAddr)
	if err != nil {
		return err
	}
	if aggResp == nil {
		h.lggr.Debugw("Not enough responses to aggregate", "requestID", resp.ID, "nodeAddress", nodeAddr, "shard", shard.donID)
		return nil
	}
	rawResp, err := json.Marshal(aggResp)
	if err != nil {
		return errors.New("failed to marshal response: " + err.Error())
	}

	err = saved.SendResponse(handlers.UserCallbackPayload{
		RawResponse: rawResp,
		ErrorCode:   api.NoError,
	})
	if err != nil {
		return err
	}

type Callback struct {
	ch chan handlers.UserCallbackPayload

	sent       atomic.Bool
	waitCalled atomic.Bool
}

func (c *Callback) SendResponse(payload handlers.UserCallbackPayload) error {
	if !c.sent.CompareAndSwap(false, true) {
		return errors.New("response already sent: each callback can only be used once")
	}
	// The channel is initialized with a buffer size of 1,
	// so this send will not block.
	c.ch <- payload
	return nil
}
