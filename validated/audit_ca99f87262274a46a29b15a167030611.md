### Title
Unbounded recursion in `OrderedListWalker::fetch_leaves` over attacker-derivable L1 MPT nodes can stack-overflow the fault-proof program - (File: `crates/proof/mpt/src/list_walker.rs`)

### Summary
`OrderedListWalker::fetch_leaves` recursively descends Branch/Extension/Blinded trie nodes to collect an ordered list's leaves (used to derive L1 transactions and receipts lists inside the fault-proof program). The recursion depth is bounded only by the depth of the MPT supplied by the (untrusted, preimage-oracle-backed) `TrieProvider`, with no depth limit — unlike the CBOR/attestation parser elsewhere in the codebase (`crates/proof/tee/registrar/src/cbor.rs`), which explicitly enforces `MAX_CBOR_NESTING_DEPTH` before recursing.

### Finding Description
`fetch_leaves` recurses once per `Branch`/`Extension` hop and once more per `Blinded` (hashed) child, fetching each preimage via `fetcher.trie_node_by_hash` before recursing again: [1](#0-0) 

This function is invoked from `hydrate`, which is the entry point used by the fault-proof program's L1/L2 chain providers to derive the ordered transactions/receipts lists from a block header's `transactions_root`/`receipts_root`: [2](#0-1) 

In the fault-proof program flow, the MPT root comes from an L1 block header and the node preimages are supplied by the preimage oracle, which is populated (over the untrusted preimage protocol) based on data claimed by the party running the proof. This class of bug — recursion/iteration depth driven by attacker-influenced/attacker-controlled data with no explicit bound — mirrors the reported analog: unbounded iteration driven by data an adversarial party can grow arbitrarily (here, an artificially deep MPT constructed via many single-branch hops or Blinded nodes) rather than a fixed protocol-imposed bound.

By contrast, the codebase elsewhere treats exactly this class of risk as something requiring an explicit guard: the Nitro attestation CBOR parser rejects nesting past `MAX_CBOR_NESTING_DEPTH` before recursing further, precisely because it decodes externally-supplied, structurally-recursive data. `fetch_leaves` decodes an analogous externally-derived recursive structure without any equivalent bound.

### Impact Explanation
If a malicious prover (or a party controlling the preimages fed into the fault-proof program's `TrieProvider`) can supply a pathologically deep MPT for the derivable transactions/receipts list (e.g. via chained `Blinded`/`Extension`/single-child `Branch` nodes), unbounded recursion in `fetch_leaves` can exhaust the call stack of the proof program. Because the fault-proof program is the component that recomputes/validates the provable L2 output root from L1 data during dispute resolution, a stack overflow here would crash/halt that program before it can produce a correct (or any) output root — directly matching the accepted impact class "node halt" / "wrong provable output root" for the fault-proof/MPT surface named in scope.

### Likelihood Explanation
The likelihood depends on whether the specific proof backend (e.g. a zkVM or native execution environment) enforces its own stack-depth ceiling independent of this code, and whether attacker-controlled MPT shapes of the required depth are reachable through the actual preimage-oracle protocol used in production (which may impose its own preimage-count/size limits). I could not fully verify these interacting bounds from the indexed code (the preimage oracle client/server enforcement and the specific proof backend's stack limits were not inspected here), so this should be treated as a plausible but unconfirmed high-severity finding requiring runtime/backend verification.

### Recommendation
Add an explicit maximum recursion/traversal depth to `OrderedListWalker::fetch_leaves` (mirroring the `MAX_CBOR_NESTING_DEPTH` pattern used in `crates/proof/tee/registrar/src/cbor.rs`), returning a typed `OrderedListWalkerError`/`TrieNodeError` once the bound is exceeded instead of recursing further. Alternatively, convert the traversal to an explicit iterative worklist (a `Vec`/`VecDeque` stack of pending nodes) so traversal depth is decoupled from the Rust call stack, and independently cap the total number of preimages fetched per hydration.

### Proof of Concept
Not directly executable from static analysis alone. Conceptually: construct an MPT preimage set where the root is a `Branch` node whose single non-empty slot is a `Blinded` commitment to another `Branch`/`Extension` node, repeated to a depth sufficient to overflow the proof program's stack (depth required depends on the runtime's stack size and per-frame cost of `fetch_leaves`), then supply this as the `transactions_root`/`receipts_root` preimage chain to a `TrieProvider` backing an `OrderedListWalker::hydrate` call inside the fault-proof program.

    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }
