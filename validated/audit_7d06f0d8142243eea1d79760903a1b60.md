### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - ([File: core/services/gateway/network/httpserver.go])

### Summary
`isAllowedOrigin` implements wildcard host matching (`*.real.com`) using `strings.HasSuffix(originHost, allowedHost)` without requiring a dot boundary before the suffix, so a host like `fakereal.com` or `evilxreal.com` is treated as a subdomain of `real.com` and accepted as an allowed CORS origin.

### Finding Description
In `isAllowedOrigin`, when an allowed origin entry starts with `*.`, the code strips the `*.` prefix and then does a raw suffix check: [1](#0-0) 

`allowedHost` becomes `real.com` (from `*.real.com`), and `strings.HasSuffix(originHost, allowedHost)` returns `true` for any `originHost` that ends with the literal string `real.com`, including hosts that are not subdomains at all, such as `fakereal.com`, `evilnotreal.com`, or `xreal.com`. There is no check that the character preceding the matched suffix in `originHost` is a `.` (i.e., no domain-boundary anchoring).

This function is invoked directly from the request handler: [2](#0-1) 

An unauthenticated network client can send an HTTP `GET`/`OPTIONS` request to the gateway's HTTP endpoint with `Origin: http://fakereal.com` (or `https://xreal.com`) when the gateway operator has configured `CORSAllowedOrigins` containing `*.real.com`. The server will reflect `Access-Control-Allow-Origin: http://fakereal.com` back to the attacker-controlled origin, satisfying the CORS check on the browser side for that specific attacker domain, even though it is not a legitimate subdomain of `real.com`.

### Impact Explanation
This is an allowlist bypass matching the Chainlink bounty "allowlist/quota bypass" impact class: an attacker-registered domain that merely shares a suffix with an allowed wildcard domain (e.g., squatting `fakereal.com` when `*.real.com` is allowed) can have its cross-origin requests to the gateway HTTP endpoint accepted by the browser's CORS policy, enabling cross-origin reads of gateway responses from a victim's browser context. The gateway response could include data intended only for legitimate origins. Note that `Access-Control-Allow-Credentials` is not set in this handler, which limits (but does not eliminate) the practical severity for credentialed requests; the vulnerability remains a genuine CORS-origin-validation defect for non-credentialed cross-origin data exposure and for any additional data returned by `ProcessRequest`.

### Likelihood Explanation
No authentication is required to exploit this—only the ability to register/control a domain that lexically ends with the allowed wildcard's base domain (e.g., `fakereal.com` vs `*.real.com`), and knowledge that `CORSAllowedOrigins` contains such a wildcard entry (often discoverable via public docs/config or trial-and-error probing with `OPTIONS`/`Origin` headers). This is fully repeatable and requires no special privileges, matching the "unauthenticated network client, knowledge of an allowed wildcard domain" precondition exactly.

### Recommendation
Anchor the wildcard suffix match to a domain boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This ensures `originHost` must either equal the base domain or be a proper subdomain (preceded by a `.`), preventing suffix-squatting domains like `fakereal.com` from matching `*.real.com`.

### Proof of Concept
Add a table-driven Go test for `isAllowedOrigin` in `core/services/gateway/network`:
```go
func TestIsAllowedOrigin_WildcardBoundary(t *testing.T) {
    s := &httpServer{
        config: &HTTPServerConfig{CORSAllowedOrigins: []string{"http://*.real.com"}},
        lggr:   logger.Test(t),
    }
    assert.False(t, s.isAllowedOrigin("http://fakereal.com"))   // should NOT match
    assert.False(t, s.isAllowedOrigin("http://xreal.com"))      // should NOT match
    assert.True(t, s.isAllowedOrigin("http://sub.real.com"))    // legit subdomain, should match
    assert.True(t, s.isAllowedOrigin("http://real.com"))        // base domain itself, optional per policy
}
```
Currently, the first two assertions fail (return `true`) demonstrating the bypass; after applying the boundary-anchored fix, they correctly return `false`.
