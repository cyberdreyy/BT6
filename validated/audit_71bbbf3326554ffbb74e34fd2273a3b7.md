### Title
`parse_config` recurses on attacker-controlled deeply-nested JSON causing RPC stack-overflow crash - ([File: account-decoder/src/parse_config.rs])

### Finding Description
`parse_config` deserializes the raw `Config` program account bytes into a `ConfigKeys`/`ValidatorInfo` string and then calls `serde_json::from_str::<serde_json::Value>(&validator_info.config_data)` unconditionally on the "info" string with no depth or size limit [1](#0-0) . The only length restriction on validator-info JSON, `MAX_VALIDATOR_INFO = 576`, is defined in `account-decoder/src/validator_info.rs` but is enforced solely client-side in the CLI's `check_total_length`, never on-chain [2](#0-1) . Since the Config program account is created through the ordinary System-program `CreateAccount`/allocate path and then populated by the Config program instruction, an unprivileged client can allocate an account of any size up to the runtime's max account data length, set `ConfigKeys.keys[0]` to `validator_info::id()`, and write a `config_data` string consisting of thousands of nested `[` characters followed by matching `]`. When any client subsequently issues a single `getAccountInfo`/`getProgramAccounts` request with `encoding=jsonParsed`, the RPC calls `parse_account_data_v3`, which dispatches to `parse_config` for accounts owned by the Config program (`ParsableAccount::Config`) [3](#0-2) . `serde_json::Value` deserialization is recursive with no built-in recursion-depth guard, so a sufficiently deep nested array/object drives the parser to exhaust the stack and abort the process (Rust stack overflow is not a catchable `panic`/`Result` — it is an unconditional process abort), rather than returning the `Result<ConfigAccountType, ParseAccountError>` that the function signature promises.

### Impact Explanation
A single, unprivileged, correctly-signed transaction that writes attacker-controlled bytes into a Config-program account, followed by one ordinary `getAccountInfo(encoding=jsonParsed)` RPC call, crashes the RPC node process via stack overflow — a real process abort, not a recoverable error. This matches the "RPC/validator process crash caused by a single call" bounty category.

### Likelihood Explanation
The attack requires no special privileges: any keypair can create and fund a Config account, embed the crafted `config_data`, and then any client (including the attacker) can trigger the crash with one standard `getAccountInfo` call. No stake, gossip, leader, or peer control is needed, and the client-side 576-byte cap in `cli/src/validator_info.rs::check_total_length` does not apply because the account can be written directly via the config-program instruction/API without going through the CLI helper. The bug is deterministic and repeatable against any RPC node that serves `jsonParsed` encoding for that account.

### Recommendation
Bound the depth/size of untrusted JSON parsed in `parse_config` — e.g., cap `config_data.len()` before calling `serde_json::from_str`, or parse with a depth-limited/streaming JSON parser (or `serde_json`'s `Deserializer` configured with a recursion limit) and reject data exceeding a sane bound (mirroring `MAX_VALIDATOR_INFO`) with `ParseAccountError` rather than proceeding to unrestricted recursive parsing.

### Proof of Concept
```rust
// account-decoder/src/parse_config.rs (add to `mod test`)
#[test]
fn test_parse_config_deeply_nested_json_stack_overflow() {
    let n = 100_000usize; // depth sufficient to overflow default thread stack
    let mut nested = String::with_capacity(n * 2);
    nested.push_str(&"[".repeat(n));
    nested.push_str(&"]".repeat(n));

    let validator_info = ValidatorInfo { info: nested };
    let info_pubkey = solana_pubkey::new_rand();
    let account = create_config_account(
        vec![(validator_info::id(), false), (info_pubkey, true)],
        &validator_info,
        10,
    );

    // Run in a child thread with a fixed stack size to reliably reproduce the abort,
    // or run under `cargo test` directly and observe SIGSEGV / stack overflow abort
    // instead of a returned Result.
    let result = std::panic::catch_unwind(|| {
        parse_config(account.data(), &info_pubkey)
    });
    // Expectation for a fixed implementation: returns Err(..) or Ok(..), never aborts.
    assert!(result.is_ok(), "parse_config must not abort the process on deeply nested JSON");
}
```
Note: stack overflow aborts bypass `catch_unwind`; the practical PoC is to run this test (or an equivalent fuzz target feeding increasing `N` into `parse_config`) as a separate process/binary and observe the process terminating with SIGSEGV/stack-overflow rather than returning a `Result`, confirming the crash.
