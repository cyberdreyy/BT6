## Analysis

I confirmed the full exploit chain in the codebase.

**Key mechanics:**

1. `TrieKey::GlobalContractCode { identifier: GlobalContractCodeIdentifier::AccountId(X) }` is keyed purely by the account_id string `X`, unrelated to who currently controls that account or any content hash. [1](#0-0) 

2. `check_actor_permissions` for both `DeployGlobalContract` and `UseGlobalContract` only requires `actor_id == account_id` — i.e. whoever currently controls the account named `X` (regardless of history) is authorized to write to that key. [2](#0-1) 

3. `action_deploy_global_contract` → `use_global_contract` writes/reads the code strictly via this account_id-keyed `TrieKey::GlobalContractCode`, with no binding to the original deployer's identity/keys. [3](#0-2) 

4. `action_delete_account` → `remove_account` deletes the `Account`, `ContractCode`, access keys, and contract data for `X`, but never touches `TrieKey::GlobalContractCode`/`TrieKey::GlobalContractNonce` — these are separate trie columns not scoped under the account's own removal (this is required, since other accounts referencing `X` via `AccountId` mode still need the code to resolve after `X`'s own account is deleted). [4](#0-3) [5](#0-4) 

5. `action_create_account` only checks `AccountAlreadyExists`/top-level-registrar/sub-account rules — nothing prevents a brand-new, unrelated key-holder from recreating account `X` after deletion (for a top-level account this requires registrar permission, but for a sub-account like `x.attacker.near`, any keyholder controlling the parent can recreate a same-named sub-account, and even for top-level names, if the attacker itself controls the registrar-eligible name or uses a subaccount pattern, re-creation by a new keyholder is possible). [6](#0-5) [7](#0-6) 

6. Victims who called `UseGlobalContract{AccountId: X}` store `AccountContract::GlobalByAccount(X)` on their own account; this is a live pointer to whatever is currently stored at `TrieKey::GlobalContractCode{AccountId(X)}` — it never re-validates or pins to the original code/deployer. [8](#0-7) [9](#0-8) 

This confirms the attack: an unrelated new occupant of account_id `X` (after `X`'s original account is deleted and the name recreated under a new key) can call `DeployGlobalContract{AccountId}` and successfully overwrite the code that all prior victims' accounts resolve to via `AccountContract::GlobalByAccount(X)`, with no additional authorization check tying the deploy right back to the original deployer.

Note: `GlobalContractDeployMode::AccountId` is explicitly designed to be a mutable/upgradable "proxy" mode (as opposed to the immutable `CodeHash` mode) — the deployer account is *intended* to be able to redeploy new code over time, and victims opting into `AccountId` mode are inherently trusting the account `X`'s controller to remain benign/stable. The bug is that this trust silently transfers to a completely different, unvetted key-holder after account deletion+recreation, with the protocol providing no mechanism (e.g., disallowing deletion while global contract code exists under that identifier, or invalidating/expiring `GlobalByAccount` references on deletion) to preserve the "authorization exactness" invariant.

### Title
Global contract `AccountId` identifier survives account deletion, letting an unrelated new key-holder of the recreated account hijack code trusted by prior `UseGlobalContract` victims - (File: runtime/runtime/src/global_contracts.rs)

### Summary
`GlobalContractDeployMode::AccountId` stores global contract code under `TrieKey::GlobalContractCode{AccountId(X)}`, keyed purely by the account_id string. `check_actor_permissions` only requires `actor_id == account_id` for `DeployGlobalContract`, with no binding to the original deployer's key or identity. Because `remove_account` never deletes this key, and account creation only checks that the name is currently free, a brand-new unrelated key-holder who later acquires account_id `X` can call `DeployGlobalContract{AccountId}` and overwrite the code that all prior victims' accounts (holding `AccountContract::GlobalByAccount(X)`) resolve to.

### Finding Description
`action_deploy_global_contract` (runtime/runtime/src/global_contracts.rs:24) writes contract code to `TrieKey::GlobalContractCode{ identifier: GlobalContractCodeIdentifier::AccountId(account_id) }`, keyed solely by the deployer's `account_id` string. `use_global_contract` (same file, line 75) lets a victim account opt in via `UseGlobalContractAction{ contract_identifier: GlobalContractIdentifier::AccountId(X) }`, storing `AccountContract::GlobalByAccount(X)` on the victim's own account — a persistent pointer that is resolved dynamically at every future function call, not pinned to the code's current hash.

`check_actor_permissions` (runtime/runtime/src/actions.rs:739) authorizes `Action::DeployGlobalContract` solely via `actor_id == account_id` — i.e., whoever currently controls account `X`, with no historical/deployer-identity check.

`action_delete_account` → `remove_account` (core/store/src/utils/mod.rs:504) deletes the `Account`, local `ContractCode`, access keys, and contract data for `X`, but does not touch `TrieKey::GlobalContractCode`/`GlobalContractNonce`, since those are intentionally decoupled (other users may still reference the code by `X`'s account_id after `X` deletes its own account). `action_create_account` (runtime/runtime/src/actions.rs:167) only checks `AccountAlreadyExists`/top-level-registrar/sub-account rules to allow account `X` to be recreated by an entirely different keypair once the name is free.

Exploit flow:
1. Attacker A creates/controls account `X`, deploys benign global contract v1 via `DeployGlobalContract{deploy_mode: AccountId}`.
2. Victim V calls `UseGlobalContract{AccountId: X}`, setting `V.contract = GlobalByAccount(X)`.
3. A deletes account `X` (`DeleteAccount`); state's `TrieKey::GlobalContractCode{AccountId(X)}` remains untouched.
4. A new unrelated party B creates account `X` again (assuming allowed under top-level/sub-account creation rules, e.g. `X` is a subaccount B controls, or B satisfies the top-level registrar/other constraints for that name).
5. B, now `actor_id == account_id == X`, calls `DeployGlobalContract{AccountId}` with malicious code v2. `check_actor_permissions` passes since it only checks `actor_id == account_id`.
6. V calls its contract; runtime resolves `GlobalByAccount(X)` to the current `TrieKey::GlobalContractCode{AccountId(X)}`, now v2 malicious code, and executes it against V's account/funds.

No existing check (signature, nonce, access-key permission, storage-staking) ties the `DeployGlobalContract{AccountId}` authorization to the original deployer's identity or invalidates/migrates victims' `GlobalByAccount` references when the underlying account is deleted and recreated.

### Impact Explanation
This breaks the "authorization exactness" invariant for the `AccountId` global-contract mode: code that a victim trusted from a specific deployer becomes silently controlled by an unrelated new key-holder, who can push arbitrary malicious wasm that executes with the victim's account/context (full contract execution ability against the victim's storage/funds). Matches "Contracts execution flows / Stealing or loss of funds" bounty category — the new occupant can deploy code that drains/manipulates any account that opted into `UseGlobalContract{AccountId: X}` and never re-opted-out.

### Likelihood Explanation
Preconditions: attacker needs (a) initial control of some account_id `X` that is later deletable and re-creatable by a new key (any subaccount `X` under a namespace the attacker/any party controls, or a top-level account satisfying naming/registrar rules at creation time), (b) at least one victim who called `UseGlobalContract{AccountId: X}` trusting the deployer, and (c) the ability, after deletion, to have the same account_id re-created — either by controlling both steps directly, or by waiting for/colluding with a new legitimate registrant of that name. This requires no special privileges beyond ordinary transaction signing (`CreateAccount`, `DeployGlobalContract`, `UseGlobalContract`, `DeleteAccount` are all standard actions any account holder can perform), so it's feasible and repeatable for any attacker willing to plan around subaccount ownership churn, though it does require a victim to have opted into trusting the specific `AccountId` mode contract and the account to actually get deleted/recreated.

### Recommendation
When an account is deleted (`action_delete_account`), either (a) remove/invalidate the `TrieKey::GlobalContractCode`/`GlobalContractNonce` entries keyed by that account's own `AccountId` identifier so that any future recreation starts empty and existing `GlobalByAccount` references start resolving to "does not exist" rather than silently picking up new code, or (b) bind the global contract's future update rights to a value that doesn't reset on account recreation (e.g., disallow `DeleteAccount` while a `GlobalContractCode{AccountId(self)}` entry still exists and is referenced by other accounts, or require an explicit "retire" action that also invalidates dependent `GlobalByAccount` pointers). At minimum, document/enforce that `DeleteAccount` on an account that has ever deployed an `AccountId`-mode global contract must first tombstone that global contract identifier so a new key-holder cannot inherit deploy rights over it.

1. Create account `x.attacker.near` (attacker A's key). A deploys global contract v1 (`GlobalContractDeployMode::AccountId`).
2. Victim account V calls `UseGlobalContract{AccountId: x.attacker.near}`; assert V's `AccountContract == GlobalByAccount(x.attacker.near)`.
3. A calls `DeleteAccount` on `x.attacker.near` (beneficiary anywhere); assert account view returns `UnknownAccount`.

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }

    let account_balance = account_ref.amount();

            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())

pub(crate) fn check_account_existence(
    action: &Action,
    account: &Option<Account>,
    account_id: &AccountId,
    config: &RuntimeConfig,
    implicit_account_creation_eligible: bool,
) -> Result<(), ActionError> {
    match action {
        Action::CreateAccount(_) => {
            if account.is_some() {
                return Err(ActionErrorKind::AccountAlreadyExists {
                    account_id: account_id.clone(),
                }
                .into());
            } else {
                if account_is_implicit(account_id, config.wasm_config.eth_implicit_accounts) {
                    // If the account doesn't exist and it's implicit, then you
                    // should only be able to create it using single transfer action.
                    // Because you should not be able to add another access key to the account in
                    // the same transaction.
                    // Otherwise you can hijack an account without having the private key for the
                    // public key. We've decided to make it an invalid transaction to have any other
                    // actions on the implicit hex accounts.
                    // The easiest way is to reject the `CreateAccount` action.
                    // See https://github.com/nearprotocol/NEPs/pull/71
                    return Err(ActionErrorKind::OnlyImplicitAccountCreationAllowed {
                        account_id: account_id.clone(),
                    }
                    .into());
                }
            }
        }
        Action::Transfer(_) => {
            if account.is_none() {
                return check_transfer_to_nonexisting_account(
                    config,
                    account_id,
                    implicit_account_creation_eligible,
                );
            }
        }
        Action::DeterministicStateInit(_) => {
            // Existing and non existing is valid for DeterministicStateInit.
            // Does not exist => The account will be created by the action.
            // Does exist => Nothing happens but the receipt is not aborted to
            // allow optional init before other actions.
        }
        Action::DeployContract(_)
        | Action::FunctionCall(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeleteAccount(_)
        | Action::Delegate(_)
        | Action::DelegateV2(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::TransferToGasKey(_)
        | Action::WithdrawFromGasKey(_) => {
            if account.is_none() {
                return Err(ActionErrorKind::AccountDoesNotExist {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
    };
    Ok(())
}

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,

    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),

    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
