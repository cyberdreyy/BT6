### Title
Stale confirmations from removed multisig members allow request execution below the live confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`delete_member` removes a departing member and cleans up requests *they created*, but it never removes that member's confirmation entries from other still-pending requests. `confirm` and `assert_valid_request` only validate that the caller confirming right now is a current member; they never re-validate the members already recorded in a request's confirmation set. As a result, a request can reach `num_confirmations` and execute even though one or more of the votes counted came from an account that is no longer a multisig member — i.e., the request is executed below the real, live threshold.

### Finding Description
The binding that should hold is: `confirmations.len() (live members only) == num_confirmations required`. In practice the code only enforces `confirmations.len() (including stale, ex-member votes) >= num_confirmations`.

Walkthrough:
1. Multisig has members `{A, B, C}`, `num_confirmations = 3`.
2. Member `D` (created by `C`, say) creates request `X`; `A` and `B` confirm it (`confirmations = {A, B}`), leaving it one confirmation short.
3. Separately, a request to `DeleteMember { member: A }` is confirmed and executed. `delete_member` ( [1](#0-0) ) removes `A` from `self.members`, deletes `A`'s *own* outstanding requests, and clears `A`'s `num_requests_pk` entry — but it does **not** touch the confirmation sets of requests created by other members, so `X`'s stored confirmations still contain `A`.
4. `C` now confirms `X`. In `confirm` ( [2](#0-1) ), the check is only `!confirmations.contains(&member.to_string())` for the new caller; there's no re-validation that `A` (already in the set) is still a member. `confirmations.len() as u32 + 1 (>= 3)` is satisfied by `{A, B, C}`, so `X` executes.
5. But `A` is no longer a member — only `B` and `C` are live confirmers plus the executor. The request executed with effectively 2 live members' worth of authority under a threshold that was supposed to require 3 currently-trusted signers.

`assert_valid_request` ( [3](#0-2) ) confirms only that the *current caller* is a member and that the request/confirmation records exist — it does not iterate the existing confirmation set to strip or reject stale members.

### Impact Explanation
This breaks the multisig authorization guarantee: the number of confirmations counted no longer equals the number of *live, currently-trusted* members who approved the action. An account that has been deliberately removed (e.g., because a key was compromised, an employee left, or the account is no longer trusted) can still contribute a binding "vote" toward transfers, key additions, contract upgrades, or further membership changes on the multisig account. This is a Critical-class issue per the scope's own definition: "a multisig request executed below threshold."

### Likelihood Explanation
This requires no privileged action from the attacker beyond normal request/confirm calls that any member can already make; it triggers naturally whenever member removal happens while other requests are pending — a realistic, common operational sequence (e.g., removing a member for security reasons while unrelated requests are queued). No redeploy, foundation action, or victim key is needed beyond the legitimate multisig membership-change workflow that this contract explicitly supports.

### Recommendation
When a member is deleted, either (a) purge or invalidate confirmations from that member across *all* pending requests (not just requests they authored), or (b) at confirmation-count time in `confirm`, recompute the confirmation count by filtering the stored confirmation set down to only entries that are still present in `self.members`, using that filtered count against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C]`, `num_confirmations = 3`.
2. `C.add_request_and_confirm(request X)` — some non-membership action, e.g. `Transfer`. `confirmations(X) = {C}`.
3. `A.confirm(X)` → `confirmations(X) = {C, A}` (still short of 3).
4. Separately, submit and fully confirm a `DeleteMember{member: A}` request (using `B` and `C`, or any valid combination not including `A`), which executes and removes `A` from `self.members`; `X`'s confirmation set is untouched, still `{C, A}`.
5. `B.confirm(X)` → `confirmations(X).len() + 1 == 3 >= num_confirmations(3)` → `execute_request(X)` runs, even though `A` is no longer a member and only `B` and `C` are currently live/trusted signers.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
