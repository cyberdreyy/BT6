### Title
Zip extraction follows attacker-planted symlinks via `os.MkdirAll` before entry-type dispatch, enabling writes outside extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` unconditionally before checking whether the current entry is a symlink, directory, or regular file. Because `os.MkdirAll` internally uses `os.Stat` (which follows symlinks) to decide whether a path component already exists, a previously-extracted malicious symlink entry can be silently treated as a valid existing directory, causing subsequent file entries whose path traverses that symlink to be written through it to an attacker-chosen location.

### Finding Description
`ExtractZipArchive` iterates `archive.File` in the exact order stored in the archive and calls `extractZipFile` per entry with no re-validation of previously created path components: [1](#0-0) 

`extractZipFile` creates all parent directories for `file.Name` via `os.MkdirAll` before the entry-type switch runs: [2](#0-1) 

`extractZipSymlinkEntry` creates a symlink at an attacker-chosen path pointing to an attacker-chosen target with no validation that the target stays within the extraction root: [3](#0-2) 

Exploit flow: an attacker crafts a zip archive with ordered entries `x` (type symlink, content `/tmp/target` or any absolute/relative path outside the job workspace) followed by `x/payload` (regular file). On the first entry, `extractZipSymlinkEntry` creates `x` as a symlink to the attacker's target. On the second entry, `extractZipFile("x/payload")` calls `os.MkdirAll(filepath.Dir("x/payload"))` = `os.MkdirAll("x", ...)`. Since `x` already exists as a symlink to a directory, `os.Stat("x")` (which `MkdirAll` uses) resolves through the symlink, sees a directory, and returns success without creating anything or erroring. Execution then proceeds to `extractZipFileEntry`, which does `os.Remove("x/payload")` and `os.OpenFile("x/payload", O_WRONLY|O_CREATE|O_TRUNC, ...)` — both operations transparently traverse the symlink and write into the attacker's target directory outside the intended extraction root.

The only pre-existing input validation in this file is `errorIfGitDirectory`, which only rejects `.git`-prefixed paths and has no bearing on symlink traversal or path containment: [4](#0-3) 

There is no `filepath.Clean`/`filepath.Rel`/prefix-containment check, no symlink-target validation, and no re-verification that intermediate path components remain plain directories (not symlinks) across the loop in `ExtractZipArchive`. This is a variant of the classic "Zip Slip" vulnerability using an attacker-planted intermediate symlink instead of `../` path segments to escape the extraction root.

### Impact Explanation
A job author who controls a cache/artifact zip archive consumed by the runner (e.g., during cache restore or artifact extraction, which invoke `ExtractZipFile`/`ExtractZipArchive`) can write arbitrary file contents to any writable path on the runner host filesystem reachable by the extracting process, subject only to OS permissions of the runner process. This is a cross-directory file write outside the job root and can persistently poison shared runner host state (e.g., overwrite files under other jobs' workspace roots, shared cache directories, or other writable host paths) if the runner process has permission to write there.

### Likelihood Explanation
The precondition — attacker control of the full ordered entry list and contents of a zip archive processed by the runner — is realistic for any job author supplying or influencing artifacts/cache archives that get extracted via `ExtractZipArchive`/`ExtractZipFile` in `helpers/archives/zip_extract.go`. No authentication or privilege beyond being a pipeline author is required, and the exploit is deterministic and repeatable: any zip with a symlink entry preceding a nested file entry that traverses it will reproduce the behavior, since `os.MkdirAll`'s symlink-following `Stat` check is a well-defined, stable Go standard-library behavior.

### Recommendation
Before calling `os.MkdirAll(filepath.Dir(file.Name), ...)` in `extractZipFile`, verify (e.g., via `os.Lstat` walking each path component, or by tracking previously-extracted symlink paths within `ExtractZipArchive`) that no path component of `file.Name` is a symlink; reject/skip the entry if it is. Additionally validate that symlink targets created by `extractZipSymlinkEntry` resolve to locations within the extraction root (reject absolute paths and targets containing `..` that escape the root), and re-verify path containment (`filepath.Clean` + prefix check against the extraction root) for every entry, not just `.git` paths.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`-style:
```go
func TestExtractZipArchive_SymlinkTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir() // simulates attacker target outside extraction root
    zipPath := filepath.Join(tmpDir, "evil.zip")

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)

    // Entry 1: symlink "x" -> outsideDir
    hdr := &zip.FileHeader{Name: "x"}
    hdr.SetMode(os.ModeSymlink | 0o777)
    w, _ := zw.CreateHeader(hdr)
    _, _ = w.Write([]byte(outsideDir))

    // Entry 2: file "x/payload"
    hdr2 := &zip.FileHeader{Name: "x/payload"}
    hdr2.SetMode(0o644)
    w2, _ := zw.CreateHeader(hdr2)
    _, _ = w2.Write([]byte("attacker content"))

    _ = zw.Close()

    extractDir := filepath.Join(tmpDir, "extract")
    _ = os.Mkdir(extractDir, 0o755)
    prevWd, _ := os.Getwd()
    _ = os.Chdir(extractDir)
    defer os.Chdir(prevWd)

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := ExtractZipArchive(r)
    require.NoError(t, err)

    // Assert the file did NOT land inside outsideDir (fails today, proving the bug)
    _, statErr := os.Stat(filepath.Join(outsideDir, "payload"))
    assert.True(t, os.IsNotExist(statErr), "payload should not be written outside extraction root via symlink traversal")
}
```
Expected today: the assertion fails because `outsideDir/payload` is created with content "attacker content", proving the write escapes the extraction root through the planted symlink.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
