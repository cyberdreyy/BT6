### Title
Unfreed shared-allocator memory leaked on `AllocationFailure` in `ExternalWorker::check_batch` / `check_resolve_pubkeys` - (File: core/src/banking_stage/consume_worker.rs)

### Summary
`check_batch` allocates a `CheckResponse` region from the shared `rts_alloc::Allocator` before calling `check_resolve_pubkeys`, which itself allocates one `SharablePubkeys` sub-region per transaction that has resolved address-lookup-table addresses [3](#0-2) [4](#0-3) . If any of these per-transaction `pubkeys_allocation` calls fails, `check_resolve_pubkeys` returns `Err(ExternalConsumeWorkerError::AllocationFailure)` via the `?` operator [5](#0-4) , which propagates through `check_batch`'s own `?` at the call site [6](#0-5) , so the `WorkerToPackMessage` is **never sent**.

Per the shared-memory ownership contract documented in `scheduler-bindings`, the external pack process only learns which regions to free from the contents of the message it receives back from agave [7](#0-6) . Because the response message carrying the offsets of both the `CheckResponse` region and any already-written `resolved_pubkeys` sub-allocations is dropped on the error path, those allocations become permanently unreachable/unfreeable by the pack process — a genuine memory leak in the shared bump allocator.

### Finding Description
The leak chain is:
1. `allocate_check_response_region` allocates a `CheckResponse` array sized to `message.batch.num_transactions` [8](#0-7) .
2. For each transaction requiring ALT resolution, `check_resolve_pubkeys` allocates a `SharablePubkeys` region and writes its offset into `response.resolved_pubkeys` [9](#0-8) .
3. If any later allocation in that loop fails (`ok_or(ExternalConsumeWorkerError::AllocationFailure)?`), the function returns `Err` immediately, discarding the partially-populated `responses` array and all prior successful sub-allocations [4](#0-3) .
4. `check_batch` propagates this error via its own `?` and never reaches `self.sender.try_write(response)` [10](#0-9) , so the pack process is never told the offsets to free.
5. `run`/`iterate`/`process_message` propagate the error all the way out of the worker's run loop, terminating that worker thread [11](#0-10) .

This mirrors the CVE-2017-6888 pattern: an error path in parsing/processing untrusted input abandons already-made allocations instead of releasing (or, here, communicating for release) them, causing memory to leak.

### Impact Explanation
Each leaked allocation permanently consumes space in the fixed-capacity shared-memory bump allocator (`rts_alloc`, capped at 4096-byte allocations per the documented constraint) [12](#0-11) . Repeated triggering — which becomes easier as the allocator itself fills up with prior leaks, since `AllocationFailure` is exactly the out-of-memory condition — leaks CheckResponse and SharablePubkeys regions cumulatively. This degrades/exhausts the shared allocator over time (denial of service against the leader's external-scheduler check pipeline) and, separately, unconditionally kills the affected `ExternalWorker::run` thread on the very first occurrence, which is a crash of leader-side transaction-checking capacity triggered purely by allocator exhaustion under attacker-influenced load (many ALT-heavy transactions in flight).

### Likelihood Explanation
This code path is guarded by `#[cfg(unix)]` and only active when the validator operator has opted into the external "unstable" pack/scheduler architecture (`agave-unstable-api` feature) — this is not the default production banking-stage path. Triggering it requires the shared allocator to actually be near exhaustion (many transactions in flight with ALT resolution requested), which is influenced by aggregate load rather than a single crafted transaction. Given the current default agave deployment does not enable this scheduler, likelihood in the general fleet is low, but it is deterministically reachable once the feature is enabled.

### Recommendation
On any allocation failure inside `check_resolve_pubkeys`, free all previously-allocated `pubkeys_allocation` regions for the current batch (and the `CheckResponse` region itself) before returning `Err`, or restructure the function to allocate a single upfront reservation and never partially fail after successful sub-allocations. Additionally, `check_batch`/`process_message`/`iterate`/`run` should not treat `AllocationFailure` as an unrecoverable, thread-terminating error — it should degrade gracefully (e.g., respond with a "not included" reason) rather than kill the worker and abandon all its accounting.

### Proof of Concept
Not independently reproducible from the index alone: exploitation requires driving the external `rts_alloc` shared allocator into an out-of-memory state via a high volume of ALT-referencing transactions routed through the (non-default, `agave-unstable-api`-gated) external scheduler's `CHECK` path with `LOAD_ADDRESS_LOOKUP_TABLES` set, at which point any subsequent `check_batch` call whose `check_resolve_pubkeys` sub-allocation fails will leak the batch's `CheckResponse`/`SharablePubkeys` allocations and terminate the worker thread, per the code paths cited above.

        pub fn run(
            mut self,
            mut receiver: shaq::spsc::Consumer<PackToWorkerMessage>,
        ) -> Result<(), ExternalConsumeWorkerError> {
            let mut should_drain_executes = false;
            let mut did_work = false;
            let mut last_empty_time = Instant::now();
            let mut sleep_duration = STARTING_SLEEP_DURATION;

            while !self.exit.load(Ordering::Relaxed) {
                match self.iterate(&mut receiver, &mut should_drain_executes)? {
                    IterationResult::ProcessedMessage => {
                        did_work = true;
                    }
                    IterationResult::Idle => {
                        let now = Instant::now();

                        if did_work {
                            last_empty_time = now;
                        }
                        did_work = false;
                        let idle_duration = now.duration_since(last_empty_time);
                        sleep_duration = backoff(idle_duration, &sleep_duration);
                    }
                }
            }

            Ok(())
        }

        fn iterate(
            &mut self,
            receiver: &mut shaq::spsc::Consumer<PackToWorkerMessage>,
            should_drain_executes: &mut bool,
        ) -> Result<IterationResult, ExternalConsumeWorkerError> {
            self.allocator.clean_remote_free_lists();
            if receiver.is_empty() {
                receiver.sync();
                *should_drain_executes = false;
            }

            match receiver.try_read() {
                Some(message) => {
                    self.sender.sync();

                    // Process message, if bank is unavailable enable draining for the
                    // remainder of the current batch (i.e. what our `receiver.sync()`
                    // fetched).
                    *should_drain_executes |=
                        self.process_message(message, *should_drain_executes)?;

                    // Publish our send & read offsets.
                    self.sender.commit();
                    receiver.finalize();

                    Ok(IterationResult::ProcessedMessage)
                }
                None => Ok(IterationResult::Idle),
            }
        }

        /// Return true if fetching a bank for execution timed out.
        fn process_message(
            &mut self,
            message: &PackToWorkerMessage,
            should_drain_executes: bool,
        ) -> Result<bool, ExternalConsumeWorkerError> {
            if !Self::validate_message(message) {
                return self
                    .return_unprocessed_message(
                        message,
                        agave_scheduler_bindings::processed_codes::INVALID,
                    )
                    .map(|()| false);
            }

            self.metrics
                .count_metrics
                .num_messages_processed
                .fetch_add(1, Ordering::Relaxed);

            if message.flags & pack_message_flags::EXECUTE != 0 {
                self.execute_batch(message, should_drain_executes)
            } else {
                self.check_batch(message).map(|()| false)
            }
        }
