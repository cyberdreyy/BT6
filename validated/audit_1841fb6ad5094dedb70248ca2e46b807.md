## Title
Operator commission share-dilution across `switch_operator`: new operator can siphon old operator's already-earned commission via `update_distribution_pool` - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::switch_operator` can leave the old operator's address as a **non-operator shareholder** inside the `staking_contract.distribution_pool` that is transferred to the new operator's key. Every subsequent invocation of `update_distribution_pool` (triggered by permissionless calls to `distribute`, `add_distribution`/`request_commission`, or `add_stake`) taxes *any shareholder that is not the current `operator` parameter* on the growth of their share value, redirecting that "commission" to the current operator. Because the old operator is now such a non-operator shareholder, the epoch rewards accrued on their still-locked (pending_inactive) commission get repeatedly skimmed and transferred to the new operator, permanently and silently diverting value that rightfully belongs to the old operator (or their beneficiary). [1](#0-0) 

### Finding Description
`switch_operator` performs, in order:
1. `distribute_internal(staker, old_operator, ...)` — pays out any already fully-inactive distribution.
2. `request_commission_internal(old_operator, staking_contract)` — computes commission accrued up to the switch point, calls `add_distribution(old_operator, staking_contract, old_operator, commission_amount)` (which buys `old_operator` shares in `distribution_pool`), and calls `stake::unlock_with_cap` to start unlocking it (moves it into `pending_inactive`, not yet withdrawable).
3. Only **after** that, `staking_contract.commission_percentage` is overwritten with `new_commission_percentage`, and the whole `StakingContract` struct (including its `distribution_pool`, which still holds `old_operator`'s pending-inactive commission shares) is re-keyed under `new_operator`. [2](#0-1) [3](#0-2) 

From this point on, `old_operator` is simply a shareholder recorded by address in `distribution_pool`, but the "operator" identity tracked by the contract has moved to `new_operator`. Any later call that invokes `update_distribution_pool` — `add_distribution` (from `request_commission`/`request_commission_internal`), `distribute_internal` (permissionless `distribute` entry function), or `add_stake` indirectly through commission logic — passes `new_operator` as the `operator` parameter: [4](#0-3) 

Inside `update_distribution_pool`, the loop explicitly exempts only the address equal to the passed-in `operator` from commission taxation; every *other* shareholder (which now includes `old_operator`) has commission computed on the delta between their previous and current worth and has shares forcibly transferred to `operator` (i.e. `new_operator`): [5](#0-4) 

Since `old_operator`'s balance in `distribution_pool` is not staker principal but already-earned, pending-inactive commission that continues to earn epoch rewards while unlocking, this appreciation is not real "new rewards owed to the staker" — it is the old operator's own money. The bug taxes it a second time at the *new* operator's commission rate and hands the skimmed shares to `new_operator`, who did nothing to earn them.

The trigger requires no special privilege: `distribute` is explicitly permissionless ("does not need to be restricted to just the staker or operator"), and `request_commission`/`add_stake` are callable by the staker or operator as part of normal contract usage. [6](#0-5) 

### Impact Explanation
This is a share-accounting corruption that credits the wrong account: value belonging to the old operator (or, if `set_beneficiary_for_operator` was used, their beneficiary) is transferred into the new operator's share balance and eventually paid out to the new operator/beneficiary instead. Because the diversion happens automatically on every subsequent `update_distribution_pool` invocation while the old operator's shares remain unredeemed (which can span multiple epochs if the lockup hasn't elapsed), the loss compounds over time and cannot be recovered by the old operator — the funds are gone once transferred and distributed to `new_operator`.

### Likelihood Explanation
`switch_operator` is a standard, expected staker action, and having unpaid/unlocked commission still in flight at the moment of a switch is a normal and even documented scenario per the accompanying `pending_attribution_snapshot` view function's comments ("In operator-switch scenarios, the previous operator may still have a non-zero pending attribution"). Any subsequent permissionless `distribute` call, or the new operator's own routine `request_commission`, will trigger the mistaxation without any adversarial setup beyond timing a `switch_operator` while commission is still pending_inactive.

### Recommendation
Before moving `distribution_pool` to the new operator key in `switch_operator`, either:
- Fully drain/settle `old_operator`'s outstanding shares from `distribution_pool` (forcing the pending-inactive commission to be tracked and paid independently of the operator-exemption logic), or
- Change `update_distribution_pool`'s exemption check from "shareholder != operator" to a set of addresses that includes both the current operator and any legacy operator(s) still holding unredeemed distribution shares, so their balances are never taxed by a differently-keyed operator's commission rate.

### Proof of Concept
1. Staker creates a staking contract with `operator1`, `commission_percentage = 10`.
2. Epoch rewards accrue; `operator1` (or staker) calls `request_commission`, computing a commission amount and adding a distribution entry `distribution_pool[operator1] = shares`, then `stake::unlock_with_cap` moves that commission into `pending_inactive` (not yet withdrawable, still earning rewards).
3. Staker calls `switch_operator(old_operator=operator1, new_operator=operator2, new_commission_percentage=X)`. Internally: `distribute_internal` pays out any already-inactive balance; `request_commission_internal(operator1, ...)` adds a fresh distribution entry for any newly accrued commission and re-locks it; then the whole `StakingContract` (with `distribution_pool` still containing `operator1`'s pending_inactive shares) is moved under key `operator2`.
4. One or more epochs pass; the pool's `pending_inactive` stake (which includes `operator1`'s locked commission) earns rewards.
5. Anyone calls `distribute(staker, operator2)` (permissionless) or `operator2` calls `request_commission(operator2, staker, operator2)`. This invokes `update_distribution_pool(distribution_pool, updated_total_coins, operator2, commission_percentage)`.
6. Inside, `operator1` is iterated as a shareholder `!= operator2`, so `unpaid_commission = (current_worth - previous_worth) * commission_percentage / 100` is computed on `operator1`'s balance and transferred as shares from `operator1` to `operator2`.
7. When `operator1`'s remaining shares are eventually redeemed via `distribute`, `operator1` receives less than the commission amount they were originally credited, with the difference having been paid to `operator2` — verifiable by comparing `pending_attribution_snapshot(staker, operator2, operator1)` before and after step 6, and comparing final payouts against the amounts originally recorded via `AddDistribution` events for `operator1`. [7](#0-6)

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
