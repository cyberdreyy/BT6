### Title
Unauthenticated exposure of LOOP plugin pprof/heap profiling endpoint enabling in-memory secret disclosure - ([File: core/web/loop_registry.go])

### Finding Description
`LoopRegistryServer.pluginPPROFHandler` reads `gc.Param("name")` and `gc.Param("profile")`, looks up the plugin in the registry, then proxies a raw GET request to the plugin's internal `/debug/pprof/<profile>` endpoint (e.g. `heap`, `goroutine`, `allocs`) and streams the response body back verbatim to the caller via `gc.Data(http.StatusOK, "text/plain", b)`. [1](#0-0) . There is no authentication, authorization, or session check performed inside the handler itself, nor any redaction of the returned data.

The router wires this handler in via `loopRoutes(app, api)`, called alongside `debugRoutes`, `healthRoutes`, `sessionRoutes`, and `v2Routes` on the `api` group. That group only applies rate limiting and attaches a cookie session store (`sessions.Sessions(...)`) — it does not itself enforce authentication. [2](#0-1) . Authentication in this router is applied explicitly per-route where required, as shown for the GraphQL endpoint which wraps its handler with `auth.AuthenticateGQL(...)` [3](#0-2) . No equivalent `auth.Authenticate(...)` wrapper is present around the plugin pprof routes registered by `loopRoutes`, and the handler code contains an explicit comment acknowledging the endpoint forwards to an "internal" plugin process, implying the author assumed a trusted network boundary rather than enforcing authentication in code — this is a real, code-level authorization gap, not merely a deployment misconfiguration, since the vulnerable code path (`pluginPPROFHandler`) itself has zero credential checks.

An attacker with zero credentials can send `GET /plugins/<name>/debug/pprof/heap` and the handler will proxy the request to the plugin, returning a full heap dump (or goroutine/allocs profile) of the LOOP plugin process, which can contain private keys, API tokens, or other secrets resident in memory.

### Impact Explanation
This matches the Chainlink bounty "sensitive data exposure / secret disclosure" impact class: an anonymous network client can extract a heap or goroutine dump of a LOOP plugin process, potentially exposing private keys, credentials, or other secrets held in memory, violating the "secrets never leave" invariant.

### Likelihood Explanation
Preconditions are minimal: network access to the node's web server port and knowledge (or brute-forcing) of the LOOP plugin name via the discovery/metrics endpoints in the same file (`discoveryHandler`, `pluginMetricHandler`), which are similarly unauthenticated in this file. No credentials, tokens, or prior authentication are required, making this trivially repeatable by any unauthenticated client that can reach the API port.

### Recommendation
Wrap the `/plugins/:name/debug/pprof/*` and `/plugins/:name/metrics` route registrations in `loopRoutes` with the same `auth.Authenticate(app.AuthenticationProvider(), ...)` middleware used for other sensitive routes (e.g., GraphQL), or otherwise restrict these endpoints to only be reachable from a trusted internal network/loopback, enforced in code rather than relying on deployment topology.

### Proof of Concept
1. In a test file under `core/web`, construct a `gin.Context` with a `httptest.ResponseRecorder`, set `Param("name")` to a registered plugin name and `Param("profile")` to `"heap"`.
2. Instantiate `LoopRegistryServer` with a fake `plugins.LoopRegistry` containing one registered plugin pointing at a local `httptest.Server` that serves a fake `/debug/pprof/heap` response.
3. Call `pluginPPROFHandler(gc)` directly (bypassing the full router/middleware chain, mirroring how `loopRoutes` wires it with no explicit auth middleware).
4. Assert the response status is `200 OK` and the body contains the fake heap-dump payload, with no `401`/`403` returned and no session/auth token supplied — demonstrating the handler alone enforces no access control.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
