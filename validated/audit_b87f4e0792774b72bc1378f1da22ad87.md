### Title
ETH sent to `ConvexStrategyETH` is permanently locked — open `receive()` with no ETH withdrawal path — ([File: contracts/strategies/convex/ConvexStrategyETH.sol](contracts/strategies/convex/ConvexStrategyETH.sol))

### Summary
`ConvexStrategyETH` declares an unrestricted `receive() external payable {}`, so any EOA or contract can send ETH directly. The contract (and its `ConvexBaseStrategy` parent) contains no code path that reads `address(this).balance` for purposes other than the internally-managed `WETH.withdraw → add_liquidity` flow, and no sweep/rescue function — grep for `address(this).balance`, `payable`, `call{`, `sendValue` across `ConvexBaseStrategy.sol` returns zero matches. ETH delivered via a plain transfer or `selfdestruct` is therefore unrecoverable.

### Finding Description
- `ConvexStrategyETH.sol:35` — `receive() external payable {}` accepts ETH from any sender with no `msg.sender` check.
- ETH is only consumed in `_depositInCurve` (`ConvexStrategyETH.sol:23-33`), where the contract unwraps its own WETH balance (`_weth.withdraw(_balance)`) and passes `{value: _balance}` to `add_liquidity`. That value is strictly the just-unwrapped WETH amount — any pre-existing stray ETH in `address(this).balance` is never included in `_depositArray` or forwarded.
- `ConvexBaseStrategy` exposes deposit/withdraw/reward-harvest logic but no ETH rescue or sweep; no `onlyOwner`-gated ETH recovery exists either, so even honest privileged roles cannot retrieve the funds.

By contrast, the other `receive()` in scope, `LidoCDOTrancheGateway.sol:99-101`, guards with `require(msg.sender == wethToken, "only-weth")`, so it rejects stray ETH — `ConvexStrategyETH` has no such guard.

### Impact Explanation
Any ETH transferred to the strategy address (mistaken deposit, leftover from a WETH unwrap executed by an external helper, or deliberate `selfdestruct` funding) is permanently frozen. `selfdestruct` even allows forced funding without hitting `receive()`. Loss equals the full ETH amount sent, with zero recovery mechanism — the same "stuck value forever" impact as the external `TokenVesting` report. This is a permanent-freeze-of-value bug, matching the accepted impact class.

### Likelihood Explanation
Low. It requires an unprivileged user to send raw ETH to the strategy by mistake (or maliciously via `selfdestruct` to burn their own funds, which benefits no one). No attacker profit is possible — the bug class only yields locked/donated value, not theft or insolvency of vault funds. Since `_depositInCurve` only ever forwards the exact WETH-unwrap amount, stray ETH does not corrupt share pricing or cause insolvency; impact is limited to the sender's own funds.

### Recommendation
Gate the receiver like the Lido gateway does, or remove ETH acceptance and only allow WETH's `withdraw` to deliver ETH:

```solidity
// contracts/strategies/convex/ConvexStrategyETH.sol
receive() external payable {
    require(msg.sender == WETH, "only-weth");
}
```

Alternatively, add an owner-gated `sweepETH()` or fold `address(this).balance` into `_depositInCurve` so stray ETH is deployed into the Curve pool rather than stranded.

### Proof of Concept
Foundry fork test (drop into `test/foundry/`):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ConvexStrategyETH} from "../../contracts/strategies/convex/ConvexStrategyETH.sol";

contract StuckETHTest is Test {
    ConvexStrategyETH strategy;
    address attacker = address(0xBEEF);

    function setUp() public {
        // deploy ConvexStrategyETH on mainnet fork (ctor args per ConvexBaseStrategy)
        strategy = new ConvexStrategyETH();
        vm.deal(attacker, 10 ether);
    }

    function testETHLockedForever() public {
        vm.prank(attacker);
        (bool ok,) = address(strategy).call{value: 1 ether}("");
        assertTrue(ok);                       // unrestricted receive() accepts it
        assertEq(address(strategy).balance, 1 ether);

        // No function on the contract moves ETH out:
        // - _depositInCurve only forwards the WETH-unwrap amount
        // - no sweep/rescue exists in ConvexStrategyETH or ConvexBaseStrategy
        // Any attempted recovery call reverts / does not exist.
        // => 1 ether permanently frozen.
    }
}
```

Note: `selfdestruct`-funded ETH bypasses even a `receive()` guard, so the durable fix is consuming `address(this).balance` in `_depositInCurve` or providing a privileged sweep; the `only-weth` guard alone stops accidental plain transfers but not forced funding.
