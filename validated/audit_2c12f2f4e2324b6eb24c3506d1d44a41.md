### Title
Stale confirmations from removed multisig members let a request execute below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` counts confirmations stored in `self.confirmations` against `self.num_confirmations` without verifying that every recorded confirmer is still a current member of `self.members`. `delete_member` only purges pending *requests originally added* by the removed member; it never scans `self.confirmations` to strip that member's confirmation from *other* pending requests it had merely confirmed. A request can therefore be executed once "confirmations.len()+1 >= num_confirmations" even though one or more of the counted confirmations belong to accounts/keys that are no longer members, meaning fewer live members than the configured threshold actually approved the action.

### Finding Description
`confirm` only checks membership of the *current* caller, then compares the stored confirmation-set size against the threshold: [1](#0-0) 

`delete_member` removes the departing member from `self.members` and deletes only the requests that member itself submitted (`r.member == member`), clearing confirmations for those requests. It does **not** iterate `self.confirmations` to remove the departing member's confirmation entries from other, still-pending requests that the member confirmed but did not create: [2](#0-1) 

Because of this, the binding that should hold — "number of confirmations from members currently in `self.members`" `>= num_confirmations` — is broken. The comparison in `confirm` instead uses the raw historical `HashSet<String>` size, which can include identifiers of accounts/keys already removed from `self.members`.

### Impact Explanation
This is a Critical-impact issue per the rubric: "a multisig request executed below threshold." A malicious or compromised member can pre-confirm an arbitrary request (e.g. `Transfer`, `AddKey`, `FunctionCall`) before being removed from the multisig (removal can happen for unrelated, legitimate reasons — e.g. rotating out a compromised or departing signer). After removal, only `num_confirmations - 1` *live* members need to confirm to trigger execution, because the stale confirmation from the removed member is still counted. Funds can be moved, keys added, or contract code deployed with fewer genuinely authorizing current members than the multisig's own `num_confirmations` parameter implies.

### Likelihood Explanation
Any current member can trigger the vulnerable path unprivileged relative to the multisig's own trust model: add/confirm a request, then rely on (or wait for) a normal, independently-justified `DeleteMember` action to remove that member later. No special privileges beyond ordinary member rights are needed, and the flaw is purely in `confirm`/`delete_member`'s bookkeeping, not in any external actor.

### Recommendation
When removing a member in `delete_member`, iterate all entries of `self.confirmations` (not just requests the member originated) and strip the removed member's identifier from every confirmation set; alternatively, revalidate at `confirm` time that every string in the stored confirmation set still corresponds to a member in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with members `{A, B, C}` and `num_confirmations = 2`.
2. Member `B` calls `add_request` with a malicious `Transfer` action to an attacker-controlled `receiver_id` → `request_id = R`.
3. Member `A` calls `confirm(R)` → `confirmations[R] = {A}` (1 confirmation, below threshold, so it stays pending) per [3](#0-2) .
4. Independently, `B` and `C` submit and confirm a `DeleteMember { member: A }` request (a normal governance action, e.g. rotating out `A`'s key). `delete_member` removes `A` from `self.members` but only clears confirmations for requests where `r.member == A` (requests A originated), leaving `confirmations[R] = {A}` untouched, per [4](#0-3) .
5. Now members are `{B, C}`, `num_confirmations` still `2`. `C` calls `confirm(R)`. `confirmations[R].len() (1) + 1 = 2 >= num_confirmations (2)` succeeds and `execute_request` runs the malicious `Transfer`, even though only one live member (`C`) actually endorsed request `R` — the threshold of 2 live confirmations was never truly met.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
