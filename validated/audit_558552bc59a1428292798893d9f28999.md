### Title
Non-ErrNoRows database errors from `FindExternalInitiator` are echoed verbatim in the 401 response body - ([File: core/web/auth/auth.go])

### Summary
`AuthenticateExternalInitiator` wraps any non-`sql.ErrNoRows` error from `store.FindExternalInitiator` with `pkgerrors.Wrap(err, "finding external initiator")` and returns it as the auth failure. `Authenticate` passes this error directly to `jsonAPIError`, which calls `err.Error()` and places the full message as the `detail` field of the JSON:API error response sent to the client, rather than a generic message.

### Finding Description
`AuthenticateExternalInitiator` in `core/web/auth/auth.go`: [1](#0-0) 
only maps `sql.ErrNoRows` to the generic `auth.ErrorAuthFailed`; any other error returned by the underlying ORM call (`SELECT * FROM external_initiators WHERE access_key = $1`, see `core/bridges/orm.go` lines 262-267, and identical implementations in `core/sessions/localauth/orm.go` lines 364-372, `core/sessions/ldapauth/ldap.go` lines 615-620, `core/sessions/oidcauth/oidc.go` lines 571-576) is wrapped with `"finding external initiator"` and propagated up as-is.

`Authenticate` then forwards that error unchanged to `jsonAPIError`: [2](#0-1) 

`jsonAPIError` writes `err.Error()` directly into the JSON response body's `detail` field with no redaction: [3](#0-2) 

An unauthenticated attacker controls the `X-Chainlink-EA-AccessKey` header value sent to any endpoint protected by `AuthenticateExternalInitiator`. If the underlying driver/database returns any error other than `sql.ErrNoRows` (e.g., a Postgres data-type/length error for a malformed `access_key` value, a connection-level error, a context-canceled/timeout error, etc.), that raw driver error text — potentially including the attacker-supplied `access_key` value echoed back by Postgres in a data-type-violation message, or internal connection/DSN details — is returned verbatim in the HTTP 401 body.

### Impact Explanation
This is an information-disclosure issue: internal database error strings (potentially including the caller's own submitted access-key value, SQL fragments, or connection state) are returned to an unauthenticated caller in the auth-failure response. It does not by itself grant authentication bypass, privilege escalation, or fund movement — the value that could be echoed is the value the attacker themself supplied, and the actual `hashed_secret`/salt columns are never included in the error text since the query only fails at the row-fetch stage. Concrete impact is limited to minor information disclosure (e.g., DB error format/fingerprinting, confirming DB backend behavior) rather than a full credential leak, since Chainlink does not attach an `access_key` value from the datastore into error text — the underlying `sql.Rows.Scan`/driver error would need to embed the attacker's own submitted value or infrastructure details.

### Likelihood Explanation
Low likelihood of a *high-severity* leak in practice: triggering a non-`ErrNoRows` DB-level error from unauthenticated input requires an edge case (e.g., a malformed access-key value that Postgres rejects with a type-conversion error, or a transient DB outage/timeout), not a routinely reachable code path from an attacker's perspective. The identical pattern is repeated across `bridges/orm.go`, `sessions/localauth/orm.go`, `sessions/ldapauth/ldap.go`, and `sessions/oidcauth/oidc.go`, so the pattern is broad but the trigger conditions (non-`ErrNoRows` DB failure) are not attacker-controllable at will beyond malformed input causing a driver-level parse/type error.

### Recommendation
In `AuthenticateExternalInitiator` (and symmetrically in `AuthenticateByToken`, which already does the right thing for token lookup at line 98 by directly returning `err`), do not propagate wrapped internal errors to the HTTP layer. Log the wrapped error server-side (e.g., via the request logger) and return a generic `auth.ErrorAuthFailed` (or a new distinct internal-error sentinel mapped to a generic "internal server error") to the caller instead of `pkgerrors.Wrap(err, "finding external initiator")`. Ensure `jsonAPIError`/`Authenticate` never places raw upstream error text into the JSON:API `detail` field for auth failures.

### Proof of Concept
Go handler-level integration test plan:
1. Build a mock `Authenticator` (implementing the interface at `core/web/auth/auth.go` lines 40-45) whose `FindExternalInitiator` returns a non-`sql.ErrNoRows` error containing a marker string, e.g. `errors.New("pq: invalid input syntax for type uuid: \"attacker-controlled-value\"")`.
2. Wire this mock into `auth.Authenticate(mockAuthr, auth.AuthenticateExternalInitiator)` as gin middleware, mounted on a test route.
3. Send an HTTP request with `X-Chainlink-EA-AccessKey: attacker-controlled-value` and no valid secret.
4. Assert the response status is 401 and parse the body as `models.JSONAPIErrors`.
5. Assert `result.Errors[0].Detail` does NOT contain `"attacker-controlled-value"`, `"finding external initiator"`, or any driver-specific string, and instead equals the generic auth-failure message (`auth.ErrorAuthFailed.Error()`).
6. Currently, this test fails because `jsonAPIError` echoes `"finding external initiator: pq: invalid input syntax for type uuid: \"attacker-controlled-value\""` in the response body, confirming the disclosure.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// the JSON value of errors.

// This is duplicated code, but we plan to deprecate and remove the JSONAPI

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
