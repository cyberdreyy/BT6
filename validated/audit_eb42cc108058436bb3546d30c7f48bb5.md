## Finding

### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing requests to execute below the required K-of-N approval - (File: `multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` (in `multisig2`) and the `DeleteKey` action (in `multisig`) only purge pending requests that were *originated* by the removed member, but never scan the `confirmations` map to strip that member's already-recorded approvals from *other* pending requests they had previously confirmed. Because `confirm()` counts confirmations purely by set length without re-validating that every entry in the set still belongs to a current member, a stale confirmation from a removed member is counted as a live approval, letting a request execute with fewer real member approvals than `num_confirmations` requires.

### Finding Description
The confirmation-counting logic in `confirm()` treats the size of the `confirmations` `HashSet` as the number of valid approvals: [1](#0-0) [2](#0-1) 

When a member is removed via `DeleteMember`, `delete_member` only removes requests where `r.member == member` (i.e., requests the removed member *created*) and clears `num_requests_pk`; it never iterates `self.confirmations` to remove the removed member's confirmation string from *other* requests they had merely confirmed: [3](#0-2) 

The equivalent behavior exists in the original `multisig` contract's `DeleteKey` action, which likewise only deletes requests authored by the removed key, not confirmations they added elsewhere: [4](#0-3) 

As a result the invariant `confirmations.len() == number of distinct still-live members who approved` can be violated: `confirmations.len()` can include one or more members who have since been deleted. `confirm()` never re-checks each historical confirmer's membership status before comparing the set length to `num_confirmations`: [5](#0-4) 

### Impact Explanation
This breaks the core multisig security guarantee that any state-changing action (`Transfer`, `AddKey`, `FunctionCall`, `AddMember`/`DeleteMember`, contract upgrade via `DeployContract`) requires `K` live, authorized approvals. With a stale confirmation counted, a request can execute with only `K-1` (or fewer) genuinely live approving members, which is exactly the "a multisig request executed below threshold" Critical-impact case: funds can be transferred, access keys added, or the contract's own membership/threshold manipulated by fewer real approvers than configured.

### Likelihood Explanation
This requires no privileged access beyond being (or having been) a normal multisig member — the exact roles the multisig is meant to constrain. The steps needed (create a request, get partial confirmations, remove one confirmer as a routine member-rotation `DeleteMember` action, then have one more live member push the count over threshold) are ordinary multisig operations that would plausibly occur during normal member turnover, not an exotic attack chain.

### Recommendation
When a member is removed (`delete_member` / `DeleteKey`), iterate all pending requests' `confirmations` sets and remove any confirmation entry belonging to the removed member/key, decrementing effectively the count so subsequent `confirm()` calls recompute against only currently-live members. Alternatively, when checking whether the threshold is met in `confirm()`, filter the confirmations set to only those entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request_and_confirm(request_X)` (e.g., a `Transfer`) → `confirmations[X] = {A}`.
3. `B` calls `confirm(request_X)` → `confirmations[X] = {A, B}` (2 < 3, not yet executed).
4. Members `A`, `C`, `D` submit and confirm a separate request `Y = DeleteMember{member: B}`, reaching 3/4 and executing `delete_member(B)`. This removes `B` from `self.members` but does not touch `confirmations[X]`, which still contains `B`.
5. `C` calls `confirm(request_X)`. `confirmations[X].len()` is 2, `+1 = 3 >= num_confirmations(3)` → `execute_request` fires the `Transfer` (or any other action), even though only `A` and `C` are genuinely live members who approved — one fewer than the configured `K=3` threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
