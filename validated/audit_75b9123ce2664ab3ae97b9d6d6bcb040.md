### Title
Rounding mismatch between `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` weakens the intended 70% supermajority for global state/miner-view agreement - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The signer's global state machine and the node/signer block-signing logic both claim to implement the same "70% weight supermajority" rule (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`), but they round the same fractional threshold in two different, non-equivalent ways. This is directly analogous to the SKALE bug class: two values that "should be calculated from one another" (a 70%-weight threshold) diverge because of independent rounding, breaking an equality the protocol relies on.

### Finding Description
The canonical 70% threshold used to decide whether a Nakamoto block has enough signer weight to be valid is computed with **ceiling** division: [1](#0-0) 

```
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```

This exact function is used both by node-side signature verification (`verify_signer_signatures`) and by the signer itself for pre-commit/signature/rejection tallying: [2](#0-1) [3](#0-2) 

By contrast, `GlobalStateEvaluator` — used to determine the signer-set's agreed protocol version, agreed burn view, and agreed current-miner/global state machine — computes the "same" 70%/30% thresholds with **floor** division instead: [4](#0-3) 

```
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
```

For any `total_weight` where `total_weight * 7` is not a multiple of 10 (e.g. `total_weight = 11`: ceil-threshold = 8, floor-threshold = 7), `reached_agreement` fires at a strictly lower weight than the value that `compute_voting_weight_threshold` would require for the equivalent decision. `reached_agreement` gates:
- `determine_latest_supported_signer_protocol_version` (which protocol version the signer set treats as active),
- `determine_global_burn_view`,
- `determine_global_state` (the agreed `SignerStateMachine`, i.e. the agreed current miner / tenure view),

all consumed by `capitulate_viewpoint` in `stacks-signer/src/v0/signer_state.rs`, which is the mechanism a signer uses to overwrite its own local view of "who the current miner is" with the group's view. A miner-controlled or gossip-triggerable weight distribution (`total_weight`) can therefore make the signer set converge on (and individual signers capitulate to) a "global" miner/tenure view backed by only ~64% of weight while the code and design intend a genuine 70% supermajority — the same kind of quantity (`total_weight * 7/10`) computed two different ways and drifting apart, exactly the SKALE "different rounding errors on values that should agree" pattern.

### Impact Explanation
This does not directly forge a signature over an invalid block (block signature counting itself uses the ceil-based `compute_voting_weight_threshold` consistently in `store_and_process_block_signature`/`handle_block_pre_commit`/`store_and_process_block_rejection`), so it does not meet the strict "Critical" bar by itself. However, it degrades the "High" liveness/safety guard: a signer can be made to adopt (capitulate to) a *miner state machine* / *parent-tenure-last-block* view that has sub-70% (but super-60%) support, weakening the equivocation/reorg-timing guards described in `docs/signer-flows.md` section 8, which are explicitly built on the assumption that a "threshold view" means the intended supermajority. Because `parent_tenure_last_block` and `current_miner` in the state machine are consensus-visible fields other signers key off of, a weakened quorum for adopting them can push part of the signer set onto a divergent miner view earlier than protocol-intended, increasing exposure to the very tenure/reorg race conditions the pre-commit and conflict-guard machinery in `handle_block_pre_commit` (`stacks-signer/src/v0/signer.rs:1250-1345`) is designed to prevent.

### Likelihood Explanation
Triggering the divergence requires no majority or privileged access: it only requires the naturally-occurring reward-set weight distribution (`total_weight`) to be a value where `total_weight * 7 mod 10 != 0`, which is common for arbitrary signer counts/weights and not attacker-controlled at all — it is a systemic rounding bug present on most reward cycles, not an edge case requiring special crafting.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` call the same `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling-based) function used everywhere else instead of re-deriving the 70%/30% split with independent floor arithmetic, so that "70% agreement" means the identical weight value in every part of the signer for a given `total_weight`.

### Proof of Concept
1. Configure/observe a reward cycle where the sum of signer weights is `total_weight = 11` (or any value where `total_weight * 7` is not divisible by 10).
2. `compute_voting_weight_threshold(11)` (used by `store_and_process_block_signature`, `handle_block_pre_commit`, node's `verify_signer_signatures`) returns `8` — an actual block requires ≥8/11 weight to be signed/accepted.
3. `GlobalStateEvaluator::reached_agreement` for the same `total_weight = 11` returns `true` once accumulated weight reaches `7` (`(11*7)/10 = 7`), a full unit of weight lower.
4. If 7 out of 11 weight's worth of signers broadcast matching `StateMachineUpdate`s (a normal, permissionless gossip event, no majority key or majority collusion required beyond honest signers reporting their own view), `determine_global_state`/`determine_global_burn_view` will report "global agreement reached" and any signer running `capitulate_viewpoint` will overwrite its local miner view to match it — despite this not meeting the 70% supermajority the rest of the codebase enforces for block signing.

        // `last_index` is used to prevent out-of-order signatures

        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set

            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),

                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(

                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }
