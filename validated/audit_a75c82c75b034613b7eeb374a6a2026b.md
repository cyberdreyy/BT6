### Title
Unpriced write-off requests allow anyone to seize escrowed tranche tokens for zero underlying - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol])

### Summary
`createWriteOffRequest` rejects zero tranche collateral but permits `underlyingsRequested == 0`. [1](#0-0) 

Any unprivileged fulfiller can then call `fullfillWriteOffRequest` with zero underlying because fulfillment only requires `_underlyings >= currentRequest.underlyings`. [2](#0-1) 

The request is deleted, the fulfiller contributes and receives zero underlying, the seller receives zero underlying, and all escrowed tranche tokens are transferred to the fulfiller. [3](#0-2) 

### Finding Description
A lender calls `createWriteOffRequest(amount, 0)` while an epoch is running. [4](#0-3) 

The function escrows `amount` tranche tokens and records a request whose underlying purchase price is zero because there is no check on `underlyingsRequested`. [5](#0-4) 

`fullfillWriteOffRequest` is intentionally callable by any wallet, and its validation accepts exact tranche collateral plus an underlying payment greater than or equal to the recorded zero price. [6](#0-5) 

Fulfillment does not require an active epoch, so an attacker can execute the free purchase immediately after observing the request. [7](#0-6) 

After deleting the request, the escrow calls `safeTransferFrom(msg.sender, address(this), 0)`, calculates a zero exit fee, sends zero underlying to the lender, and sends `_tranches` to the attacker. [3](#0-2) 

### Impact Explanation
An unprivileged fulfiller can steal the entire tranche-token collateral escrowed in a zero-priced request without paying any underlying. [7](#0-6) 

The loss equals the full `tranches` amount stored in `userRequests[_user]`, while the lender receives `_underlyings - _totFee == 0`. [3](#0-2) 

This breaks the escrow’s exchange invariant that deposited tranche collateral is released only in return for the lender-requested underlying payment. [8](#0-7) 

### Likelihood Explanation
The exploit requires the lender to submit a malformed zero-price request, which is a plausible input error because the contract validates only `amount == 0`. [1](#0-0) 

Once the request exists, fulfillment is permissionless and carries no timing restriction, so an attacker can monitor the mempool or chain state and fulfill it before the lender deletes it. [9](#0-8) 

### Recommendation
Reject zero-priced requests when they are created:

```solidity
// contracts/IdleCreditVaultWriteOffEscrow.sol
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

This should be added to `createWriteOffRequest` before the tranche-token transfer so malformed requests cannot escrow collateral. [1](#0-0) 

Optionally, also require `currentRequest.underlyings != 0` in `fullfillWriteOffRequest` as defense-in-depth for requests created before the fix. [2](#0-1) 

### Proof of Concept
The following Foundry test extends `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol` and demonstrates that a zero-price request lets an arbitrary attacker receive all escrowed tranche tokens for no payment. [10](#0-9) 

```solidity
function testZeroPricedWriteOffRequestCanBeSeized() external {
    address attacker = makeAddr("attacker");
    uint256 escrowedTranches = 10_000e18;

    uint256 sellerTranchesBefore = tranche.balanceOf(LP);
    uint256 attackerTranchesBefore = tranche.balanceOf(attacker);

    // User error: tranche collateral is escrowed with a zero underlying price.
    vm.prank(LP);
    escrow.createWriteOffRequest(escrowedTranches, 0);

    (uint256 storedTranches, uint256 storedUnderlyings) =
        escrow.userRequests(LP);
    assertEq(storedTranches, escrowedTranches);
    assertEq(storedUnderlyings, 0);

    // Any unprivileged account can fulfill the request with zero underlying.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, escrowedTranches, 0);

    (storedTranches, storedUnderlyings) = escrow.userRequests(LP);
    assertEq(storedTranches, 0);
    assertEq(storedUnderlyings, 0);

    // Attacker obtains all escrowed tranche collateral; LP receives zero underlying.
    assertEq(
        tranche.balanceOf(attacker) - attackerTranchesBefore,
        escrowedTranches
    );
    assertEq(sellerTranchesBefore - tranche.balanceOf(LP), escrowedTranches);
}
```

The existing tests establish that `LP` has tranche tokens and has approved the escrow in `setUp`. [11](#0-10)

  /// @notice create a write-off request by depositing tranche tokens and setting the amount of underlyings requested
  /// @param amount of tranche tokens to deposit
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
