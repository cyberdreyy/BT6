I've confirmed the vulnerability. Here's the analog found in the `MultiSigContract` (multisig2):

### Title
Removed multisig member's stale confirmation is counted toward threshold, allowing request execution below live-member quorum - (File: `multisig2/src/lib.rs`)

### Summary
The `delete_member` function in `multisig2/src/lib.rs` removes a member from the multisig's member set and purges only the requests *originated* by that member, but it never scans the `confirmations` map to strip that member's confirmation from *other* pending requests they had previously confirmed. This is analogous to the Augur `preemptiveDisputeCrowdsourcer` bug: a state-changing event (member removal / dispute-chain reset) invalidates a cached trust binding (a live confirmation / a tentative winning outcome) that is never reset, and a later legitimate call (`confirm` / `contributeToTentative`) silently reuses the stale, now-invalid reference as if it were still valid.

### Finding Description
`confirm()` at [1](#0-0)  counts entries in the `confirmations` `HashSet<String>` for a request and executes once `confirmations.len() as u32 + 1 >= self.num_confirmations`. The set is only mutated by `confirm` (insertion) and `remove_request`/`delete_member` (bulk removal only for requests the removed member itself created), never by scanning other requests' confirmation sets: [2](#0-1) 

Because `delete_member` filters `self.requests` by `r.member == member` (the *originator*) only, a confirmation string previously inserted by a member who is later removed remains in `self.confirmations` for any request *originated by someone else*. `current_member()` correctly prevents the removed member from confirming new requests going forward [3](#0-2) , but it does not retroactively invalidate confirmations they already cast. The binding that should hold is: `count(live confirmations) == count(confirmations in set)`. After a `DeleteMember` action executes while a stale confirmation from that member sits in another request's set, this becomes `count(live confirmations) < count(confirmations in set)`.

### Impact Explanation
This allows a `MultiSigRequest` (e.g. a `Transfer`, `AddKey`, `FunctionCall`) to execute with fewer live/current member confirmations than `num_confirmations` requires, because a stale confirmation from a since-removed member is counted toward quorum. This directly matches the Critical impact category: "a multisig request executed below threshold."

### Likelihood Explanation
This requires no privileged action beyond normal multisig operation: any member adds a request and it is confirmed by fewer than `num_confirmations` members (one of whom is later removed via a normal `DeleteMember` execution), after which the remaining members can push the request over threshold using the ghost confirmation. Member removal via `DeleteMember` is a documented, expected multisig operation, not a compromise of the foundation or a victim key, so likelihood is realistic in the normal member-churn flow of a multisig wallet.

### Recommendation
In `delete_member`, iterate all entries in `self.confirmations` (not only requests originated by the removed member) and remove the removed member's identifier from every confirmation set, mirroring how `preemptiveDisputeCrowdsourcer` should be reset in `disavowCrowdsourcers`.

### Proof of Concept
1. Initialize multisig with members `A, B, C, D` and `num_confirmations = 3`.
2. `B` calls `add_request` creating `request_id = 1` (empty confirmations).
3. `A` calls `confirm(1)` → `confirmations[1] = {A}` (1 < 3, not executed).
4. Members `B, C, D` submit and confirm a `DeleteMember { member: A }` self-request; it executes via `execute_request` → `delete_member` [2](#0-1) . `A` is removed from `self.members`; `confirmations[1]` is untouched and still contains `A`.
5. `C` calls `confirm(1)` → `confirmations[1] = {A, C}`, len=2, `2+1 >= 3`? No.
   Actually with `D` confirming next: `confirmations.len()==2`, `2+1>=3` → true → `execute_request` runs `confirm(1)` from `D`.
6. Request 1 executes having only 2 live confirmations (`C`, `D`) plus the stale ghost entry from removed member `A`, one below the configured `num_confirmations = 3` of currently live members.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
