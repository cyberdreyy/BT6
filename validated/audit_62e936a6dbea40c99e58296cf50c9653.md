### Title
Hardcoded Maker address in destination escrow causes permanent loss of funds for multisig wallets - (`contracts/BaseEscrowFactory.sol`)

### Summary
The protocol deterministically sets the recipient of funds on the destination chain to the Maker's address from the source chain. If the Maker is a multisig wallet or a smart contract, the funds will be sent to the same address on the destination chain. However, most multisig wallets (like Gnosis Safe) and contracts do not automatically exist at the same address across different chains, leading to a permanent loss of funds as no one can access the destination address.

### Finding Description
In `BaseEscrowFactory.sol`, the `_postInteraction` function is responsible for preparing the metadata (`immutables`) for both the source and destination escrows. When defining the Maker's address for the destination chain, it uses the source chain's `order.maker` (or `order.receiver` if specified) [1](#0-0) .

These `immutables` are then used to deploy the `EscrowDst` contract [2](#0-1) . When the swap is finalized via `EscrowDst.withdraw` or `EscrowDst.publicWithdraw`, the tokens are transferred to `immutables.maker` [3](#0-2) .

Because the `maker` address is fixed to the source-chain address during the order filling process, a Maker using a multisig wallet on Ethereum will have their funds sent to that same address on the destination chain (e.g., ZkSync or BSC). If the multisig has not been deployed via a cross-chain factory to the exact same address, the funds are effectively burned.

### Impact Explanation
This leads to the **permanent freezing/loss of user funds** during the live swap lifecycle. A Maker who is a contract/multisig will lose 100% of the `takingAmount` if they cannot control the same address on the destination chain. This fits the "High" impact criteria of the 1inch Smart-Contract Bounty Gate.

### Likelihood Explanation
The likelihood is **Medium**. While many users are EOAs, institutional users and DAOs frequently use multisig wallets (like Gnosis Safe) to interact with DeFi protocols. These users are at high risk when performing cross-chain swaps if the protocol does not allow specifying a chain-specific recipient address.

### Recommendation
Allow the Maker to specify a `destinationRecipient` address in the Fusion order or the `ExtraDataArgs` that is independent of their source-chain address. The `BaseEscrowFactory` should use this provided address for the `immutables.maker` field in the `DstImmutablesComplement`.

### Proof of Concept
1. A Maker (a Gnosis Safe multisig at `0x123...` on Ethereum) signs a cross-chain swap order to receive USDC on ZkSync.
2. A Resolver fills the order. The `BaseEscrowFactory` on Ethereum emits `SrcEscrowCreated` with `dstImmutablesComplement.maker` set to `0x123...` [4](#0-3) .
3. The Resolver calls `createDstEscrow` on ZkSync using these immutables.
4. Once the secret is revealed, `EscrowDst.withdraw` is called.
5. The contract executes `_uniTransfer(token, 0x123..., amount)` [5](#0-4) .
6. Since `0x123...` on ZkSync is an empty address (the multisig was not/cannot be deployed there with the same address), the USDC is now stuck forever.

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```
