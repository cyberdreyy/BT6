### Title
Cross-user response hijacking via attacker-chosen `MessageId` correlation key in the WebAPI gateway handler - (File: core/services/gateway/api/jsonrpccodec.go, core/services/gateway/handlers/capabilities/handler.go)

### Summary
The gateway's legacy request/response correlation key (`msg.Body.MessageId`) is taken verbatim from the caller-supplied JSON-RPC `id`/`message_id` field via `JsonRPCCodec.DecodeJSONRequest`/`EncodeLegacyRequest`, and is used as the sole map key for pending callbacks in `handler.savedCallbacks`. Because this map is shared across all concurrent user connections to a DON and is not scoped by sender, an attacker who submits a signed request with the same `MessageId` as a victim's in-flight request can overwrite the victim's callback entry and receive the victim's response instead.

### Finding Description
The flow is:
1. `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) decodes the raw JSON-RPC body and calls `codec.DecodeJSONRequest`, which sets `msg.Body.MessageId = request.ID` directly from client-supplied JSON [1](#0-0) . `EncodeLegacyRequest` similarly forwards `msg.Body.MessageId` as the wire ID with no server-side regeneration [2](#0-1) .
2. `msg.Validate()` only checks length/format and derives `Sender` from the signature — it does not bind `MessageId` uniqueness to `Sender` [3](#0-2) .
3. `handler.HandleLegacyUserMessage` stores the caller's callback keyed purely by `msg.Body.MessageId` in a handler-wide shared map: `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` [4](#0-3) . The handler explicitly documents a missing sender check with a TODO: `// TODO: apply allowlist and rate-limiting here` and further `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` [5](#0-4) [6](#0-5) .
4. On the response path, `handleWebAPITriggerMessage` looks the callback up (and deletes it) solely by `msg.Body.MessageId`, with no verification that the response corresponds to the same requester that registered the callback: `savedCb, found := h.savedCallbacks[msg.Body.MessageId]` [7](#0-6) . The same unscoped, last-write-wins pattern exists in `handlers/handler.dummy.go` (`d.savedCallbacks[msg.Body.MessageId] = ...` / lookup by `msg.Body.MessageId` only) [8](#0-7) .

Exploit flow: Victim sends a legitimate signed request with `MessageId = X` and blocks on `callback.Wait` inside `gateway.ProcessRequest` [9](#0-8) . Before the DON responds, the attacker — using any of their own externally-owned keys — submits a distinct signed request that also sets `MessageId = X`. Because `EncodeLegacyRequest`/`DecodeJSONRequest` never generate or validate uniqueness/ownership of this ID, `h.savedCallbacks[X]` is silently overwritten with the attacker's callback. When the DON eventually responds to the victim's original request (still correlated by `X`), `handleWebAPITriggerMessage` delivers that response to whichever callback currently occupies `savedCallbacks[X]` — the attacker's — returning the victim's data to the attacker's HTTP connection.

### Impact Explanation
This is a genuine cross-user response confusion bug: an unauthenticated/unprivileged internet client can redirect another user's gateway response to itself by racing a duplicate `MessageId`. Depending on which capability is routed through this handler pattern (e.g., `web_api_trigger`/compute/workflow payloads carrying user data or secrets), this can leak confidential response content to an unauthorized requester, matching the "cross-user response confusion" / credential-disclosure impact class. I was only able to conclusively verify this exact `savedCallbacks`-by-`MessageId` pattern in `core/services/gateway/handlers/capabilities/handler.go` and `core/services/gateway/handlers/handler.dummy.go`; whether the vault-specific handler (`core/services/gateway/handlers/vault/handler.go`) shares the identical unscoped correlation logic (which would elevate this to disclosure of vault/DKG secrets as hypothesized in the question) could not be confirmed within the available context and would need direct inspection of that file.

### Likelihood Explanation
Exploitation requires no special privilege — any internet client capable of signing a gateway message with its own key can attempt the race. It requires winning a timing race against a victim's in-flight request using a guessable or observed `MessageId` (predictable IDs, replayed IDs from logs/errors, or simply flooding with common IDs like sequential counters or empty/short strings increase the odds), which is feasible but probabilistic rather than deterministic without additional information about the victim's chosen ID.

### Recommendation
Generate the correlation key server-side (e.g., a UUID minted by the gateway when a request is admitted) instead of trusting the caller-supplied JSON-RPC `id`, and scope `savedCallbacks` entries by `(Sender, MessageId)` rather than `MessageId` alone. Reject requests whose `MessageId` collides with an already-active entry for a different sender instead of silently overwriting it, and verify on the response path that the responding correlation matches the original requester before dispatching the payload to a callback.

### Proof of Concept
Go handler-level test plan (extends `TestHandlerReceiveHTTPMessageFromClient` in `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Build `msgA` signed by victim key with `MessageId = "shared-id"` and call `handler.HandleLegacyUserMessage(ctx, msgA, cbA)`.
2. Before feeding a node response for `msgA`, build `msgB` signed by a distinct attacker key, also with `MessageId = "shared-id"`, and call `handler.HandleLegacyUserMessage(ctx, msgB, cbB)`.
3. Assert `handler.savedCallbacks["shared-id"]` now references `cbB` (attacker), not `cbA`.
4. Feed a node response corresponding to `msgA` (i.e., `hc.ValidatedResponseFromMessage(msgA)`) into `handler.HandleNodeMessage`.
5. Assert that `cbB.Wait(ctx)` (attacker's callback) returns the response payload built from `msgA` (victim's data), while `cbA.Wait(ctx)` never receives a response (times out) — demonstrating cross-user response delivery.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageId] = &savedCallback{msg.Body.MessageId, callback}
	don := d.don
	d.mu.Unlock()
	params, err := json.Marshal(msg)
	if err != nil {
		return err
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}

func (d *dummyHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return err
	}
	msg.Body.MessageId = resp.ID
	err = msg.Validate()
	if err != nil {
		return err
	}
	if nodeAddr != msg.Body.Sender {
		return fmt.Errorf("node address %s does not match message sender %s", nodeAddr, msg.Body.Sender)
	}
	d.mu.Lock()
	savedCb, found := d.savedCallbacks[msg.Body.MessageId]
	delete(d.savedCallbacks, msg.Body.MessageId)
	d.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(&msg), ErrorCode: api.NoError})
	}
	return nil
}
