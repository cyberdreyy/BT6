### Title
Unauthenticated-role bridge secret enumeration via unrestricted `GET /v2/bridge_types` - ([File: core/web/router.go])

### Summary
The `/v2/bridge_types` index route is registered inside `authv2` (session/token authentication only) without any role wrapper such as `auth.RequiresEditRole`, unlike every mutating bridge route. `BridgeTypesController.Index` returns paginated `BridgeResource` objects that always include the plaintext `OutgoingToken` secret for every bridge, so any authenticated user regardless of role (view, run, edit) can page through and dump all bridges' `OutgoingToken` values in bulk.

### Finding Description
`v2Routes` wires bridge routes as: `authv2.GET("/bridge_types", paginatedRequest(bt.Index))` and `authv2.GET("/bridge_types/:BridgeName", bt.Show)` with no role check, while `Create`, `Update`, and `Destroy` are wrapped with `auth.RequiresEditRole`. `authv2` itself only enforces that the caller is authenticated via token or session (`auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)`), it does not enforce a minimum role. `BridgeTypesController.Index` calls `btc.App.BridgeORM().BridgeTypes(ctx, offset, size)` and maps every row through `presenters.NewBridgeResource(bridge)`, which sets `OutgoingToken: b.OutgoingToken` directly from the DB model with no redaction based on caller role. Because the route accepts pagination parameters (`size`, `page`), an authenticated low-privilege (view-role) user can request a large `size` and retrieve every configured bridge's `OutgoingToken` in one or a few requests — a secret intended to authenticate the node to external adapters/bridges.

### Impact Explanation
This maps to Chainlink's "sensitive information disclosure" bounty class: bulk exposure of `OutgoingToken` secrets used to authenticate outbound requests to bridge/external adapter endpoints, obtainable by any authenticated user irrespective of assigned role (view/run), rather than only edit/admin as intended by the role model elsewhere in the same file (`Create`/`Update`/`Destroy` correctly require edit role, and `Show` for a single bridge has the identical gap).

### Likelihood Explanation
Minimal precondition: any valid authenticated session or API token (including the lowest "view" role) is sufficient — no edit/admin privilege required. The request is a single unauthenticated-role GET with a `size` query parameter; fully repeatable and trivially scriptable.

### Recommendation
Wrap `authv2.GET("/bridge_types", paginatedRequest(bt.Index))` and `authv2.GET("/bridge_types/:BridgeName", bt.Show)` with an appropriate role check (at minimum `auth.RequiresEditRole`, consistent with the mutating bridge routes), or redact `OutgoingToken` in `presenters.NewBridgeResource` for callers below edit role.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/bridge_types_controller_test.go`):
1. Create a session/API token for a user with role `view` (lowest privilege) using existing test helpers (e.g. `cltest.CreateUserWithRole` or `cltest.NewViewOnlyHTTPClient`).
2. Seed one or more bridges via `bridges.ORM.CreateBridgeType` with distinct `OutgoingToken` values.
3. Issue `client.Get("/v2/bridge_types?size=1000")` using the view-role client.
4. Assert response status is `200 OK` (currently succeeds) and that the JSON body contains the plaintext `outgoingToken` field for each bridge — demonstrating the disclosure.
5. Add a regression assertion that the request should instead return `401`/`403` for view-role callers, or that `outgoingToken` is empty/omitted, to validate the fix once the role wrapper/redaction is applied.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}
