### Title
`PsWriter.RmDir` recursively deletes through reparse points during `FF_ENABLE_JOB_CLEANUP`, allowing a job to escape `RootDir` on Windows shells - ([File: shells/powershell.go])

### Summary
When `FF_ENABLE_JOB_CLEANUP` is enabled and `GIT_STRATEGY` is `clone`/`empty`, `AbstractShell.writeCleanupBuildDirectoryScript` emits `w.RmDir(info.Build.FullProjectDir())`, whose PowerShell implementation runs a bare `Remove-Item -Force -Recurse $path`. `FullProjectDir()` returns the raw `b.BuildDir` string that was validated only once, string-wise, against `RootDir` at `StartBuild` time (`getCustomBuildDir`), with no re-validation and no symlink/reparse-point check at cleanup time. A job script (unprivileged, on a Windows-based shell/custom/instance/ssh executor) can replace the build directory with an NTFS junction/reparse point pointing outside `RootDir` before the job ends; PowerShell's documented `Remove-Item -Recurse` behavior on reparse points then recurses into and deletes the *target* directory's contents rather than merely unlinking the reparse point.

### Finding Description
- `Build.FullProjectDir()` simply returns `helpers.ToSlash(b.BuildDir)` with no containment check at call time: [1](#0-0) .
- Path containment is enforced only once, in `getCustomBuildDir`, purely via string comparison (`filepath.Rel`) when `StartBuild` runs — it does not resolve symlinks and is never re-checked afterward: [2](#0-1) .
- At end-of-job cleanup, if `FF_ENABLE_JOB_CLEANUP` is on and the git strategy is `clone`/`empty`, the abstract shell emits an unconditioned `RmDir` on the (unrevalidated) `FullProjectDir()`: [3](#0-2) .
- The PowerShell `RmDir` implementation performs a direct `Remove-Item -Force -Recurse` on the path with no reparse-point/symlink safety handling: [4](#0-3) .
- Notably, the code base is aware of the exact hazard: `RmFilesRecursive`/`RmDirsRecursive` deliberately avoid `Remove-Item -Recurse` and use `Get-ChildItem`-based enumeration instead, citing "a known issue" with `Remove-Item -Recurse` on reparse points (Microsoft docs Example 4): [5](#0-4) . This mitigation was never applied to `RmDir`, which is exactly the function used for whole-build-directory cleanup.

Exploit flow: an attacker-controlled job script (running under the Windows-based shell/custom/instance/ssh executor with `pwsh`/`powershell`), with `FF_ENABLE_JOB_CLEANUP=1` and default `GIT_STRATEGY=clone`, deletes its own `$CI_PROJECT_DIR` and replaces it with an NTFS junction (`mklink /J` or `New-Item -ItemType Junction`, which does not require any elevated privilege) pointing at another directory (e.g. a sibling project directory or a shared path under `builds_dir`). At job end, the generated cleanup script executes `Remove-Item -Force -Recurse <path>`, which — due to the documented PowerShell recursion-through-reparse-point behavior — deletes the contents of the *junction target* instead of merely unlinking the junction.

This differs from the Bash writer, where `rm -r -f path` on a symlinked directory only unlinks the symlink itself and does not recurse into the target, so this issue is specific to the PowerShell code path.

### Impact Explanation
A single unprivileged pipeline job can cause deletion of files outside its own `BuildDir`/`RootDir`, including another concurrent or previously-run project's build directory (or any directory a junction can target on the host). This is a persistent, host-level, multi-tenant disruption: shared-host/static-runner deployments explicitly using `FF_ENABLE_JOB_CLEANUP` for hygiene (per the docs recommendation) are directly exposed, and the damage occurs during the mandatory cleanup stage, surviving job cancellation.

### Likelihood Explanation
Preconditions: Windows-based executor using PowerShell/pwsh shell, `FF_ENABLE_JOB_CLEANUP` enabled (opt-in, off by default), default/`clone`/`empty` git strategy, and the ability for the job process to create an NTFS junction (no special privilege required, unlike true symlinks which need `SeCreateSymbolicLinkPrivilege` or Developer Mode). Given junctions require no elevated rights, this is straightforwardly reproducible by any pipeline author whose job runs as a normal user on such a runner. The feature flag is opt-in but is explicitly documented as a security-hardening recommendation for shared static runners, making affected environments a realistic target population.

### Recommendation
- In `PsWriter.RmDir`, detect and refuse to recurse through reparse points: check `(Get-Item $path -Force).LinkType` (or `Attributes -band [IO.FileAttributes]::ReparsePoint`) before deleting; if the path is a reparse point, remove only the link itself (non-recursive) rather than `Remove-Item -Recurse`.
- Alternatively, replace the direct `Remove-Item -Force -Recurse` with the same safe enumeration pattern already used in `RmFilesRecursive`/`RmDirsRecursive`.
- Additionally, re-validate at cleanup-script-generation time (or via a runtime check embedded in the generated script) that the resolved target of `BuildDir` is still contained within `RootDir`, rather than relying solely on the one-time `StartBuild` string check.

### Proof of Concept
Integration test outline (Windows, pwsh):
1. Configure a build with `Runner.Shell = "pwsh"`, `FF_ENABLE_JOB_CLEANUP=1`, default `GIT_STRATEGY` (clone).
2. Job script: after checkout, `Remove-Item -Recurse -Force $env:CI_PROJECT_DIR; New-Item -ItemType Junction -Path $env:CI_PROJECT_DIR -Target $targetDir` where `$targetDir` is a directory outside `RootDir` pre-populated with a marker file.
3. Run the build to completion (cleanup stage executes `writeCleanupBuildDirectoryScript` → `RmDir`).
4. Assert: `$targetDir`'s marker file no longer exists (proving contents outside `RootDir` were deleted), while a `rm -rf`/Bash equivalent test on Linux with a symlink in place of `$CI_PROJECT_DIR` shows the target directory's contents remain intact (only the symlink is removed) — demonstrating the Windows-specific nature of the bug.

func (b *Build) getCustomBuildDir(rootDir, dir string, customBuildDirEnabled, sharedDir bool) (string, error) {
	if dir == "" {
		return path.Join(rootDir, b.ProjectUniqueDir(sharedDir)), nil
	}

	if !customBuildDirEnabled {
		return "", &BuildError{Inner: fmt.Errorf("setting GIT_CLONE_PATH is not allowed, enable `custom_build_dir` feature"), FailureReason: ConfigurationError}
	}

	// See: https://gitlab.com/gitlab-org/gitlab-runner/-/issues/25913
	relDir, err := filepath.Rel(helpers.ToSlash(rootDir), helpers.ToSlash(dir))
	if err != nil {
		return "", &BuildError{Inner: err, FailureReason: ConfigurationError}
	}
	if strings.HasPrefix(relDir, "..") {
		return "", &BuildError{Inner: fmt.Errorf("the GIT_CLONE_PATH=%q has to be within %q", dir, rootDir), FailureReason: ConfigurationError}
	}

	return path.Clean(dir), nil
}

func (p *PsWriter) RmFilesRecursive(path string, name string) {
	resolvedPath := p.resolvePath(path)
	p.IfDirectory(path)
	p.Linef(
		// `Remove-Item -Recurse` has a known issue (see Example 4 in
		// https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.management/remove-item)
		"Get-ChildItem -Path %s -Filter %s -Recurse | ?{ -not $_.PSIsContainer } | ForEach-Object { Remove-Item -Force $_.FullName }",
		resolvedPath, psQuoteVariable(name),
	)
	p.EndIf()
}

func (p *PsWriter) RmDirsRecursive(path string, name string) {
	resolvedPath := p.resolvePath(path)
	p.IfDirectory(path)
	p.Linef(
		// `Remove-Item -Recurse` has a known issue (see Example 4 in
		// https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.management/remove-item)
		"Get-ChildItem -Path %s -Filter %s -Recurse | ?{ $_.PSIsContainer } | ForEach-Object { Remove-Item -Recurse -Force $_.FullName }",
		resolvedPath, psQuoteVariable(name),
	)
	p.EndIf()
}
