### Title
Unauthenticated gRPC `InitForcefulShutdown`/`InitGracefulShutdown` Allows Any Local Client to Terminate the Wrapped Runner Process - (File: `helpers/runner_wrapper/api/server/server.go`, `commands/wrapper.go`)

### Summary
The `gitlab-runner wrapper` subcommand starts a gRPC server, by default on `tcp://localhost:7777`, that exposes `InitGracefulShutdown` and `InitForcefulShutdown` RPCs with no authentication, authorization, or token check of any kind. [1](#0-0) [2](#0-1)  Any process able to reach that listener can immediately terminate the wrapped `gitlab-runner` process, analogous to the reported `kill()` issue: a security-relevant, state-altering operation is reachable by an unauthenticated caller.

### Finding Description
`RunnerWrapperCommand.Execute` opens a listener via `createListener()`, which supports either a `unix` socket or a `tcp` address, defaulting to `tcp://localhost:7777` when `--grpc-listen` is not overridden. [3](#0-2)  It then registers a gRPC `ProcessWrapper` service (`CheckStatus`, `InitGracefulShutdown`, `InitForcefulShutdown`) on that listener without any interceptor, TLS client-cert check, or shared-secret validation. [4](#0-3)  The RPC handlers directly call `wrapper.InitiateForcefulShutdown()` / `wrapper.InitiateGracefulShutdown()`, which send a termination signal to the wrapped process with no caller identity check. [5](#0-4)  The underlying `Wrapper.InitiateForcefulShutdown`/`InitiateGracefulShutdown` implementation only checks whether a process has been initialized (`p == nil`), not who is calling it. [6](#0-5) 

This is a structural analog to the reported `kill()` bug: a state-mutating, disruptive action (shutdown/termination) is reachable without any authorization gate, and the impact is immediate loss of availability of the protected component.

### Impact Explanation
Any entity able to open a TCP connection to the listen address can force-terminate the wrapped GitLab Runner process, causing the runner service to stop processing jobs — a denial-of-service against the CI worker managed by this wrapper. Because `InitForcefulShutdown` requires no confirmation, cooldown, or identity check, one unauthenticated RPC call is sufficient to disrupt the service, matching the "single call, wide blast radius" pattern described in the external report.

### Likelihood Explanation
By default the listener binds to `localhost:7777`, so exploitation without modification requires the attacker to already have some form of local network access to the host (e.g., another local process/user, or a container sharing the same network namespace) — I could not fully verify from the available files whether the `wrapper` subcommand is used in any deployment mode (e.g., a shared/multi-tenant container or Kubernetes sidecar) where `localhost` is reachable by less-trusted co-located processes; docs describing this command's deployment model were not found in the indexed `docs/` content. If an operator configures `--grpc-listen` to bind on a non-loopback interface (an admin-chosen configuration), the endpoint becomes remotely reachable by anyone with network access — but per the disqualification rules, "admin-chosen insecure settings" are out of scope. On the default binding, exploitation is limited to local reachability, and a local attacker with equivalent access could often already terminate the process via OS-level signals in many configurations, which reduces (but does not necessarily eliminate) the marginal risk added by this unauthenticated RPC, depending on process/user separation on the host.

### Recommendation
Given the uncertainty about deployment context and default network exposure, I cannot confirm this rises to the same severity/reachability bar as the original `kill()` report without further verification of how `wrapper` is deployed in practice (e.g., whether it is exposed inside shared network namespaces or containers where the caller and the runner process run as different, less-privileged principals). If pursuing a fix regardless: add authentication (shared token/mTLS) to the `ProcessWrapper` gRPC service, or restrict the default listener strictly to a Unix domain socket protected by filesystem permissions instead of `tcp://localhost`.

### Proof of Concept
Not fully verifiable within the current investigation: exploitation would require confirming a real deployment scenario where an unprivileged principal can reach `localhost:7777` (or a configured TCP address) but cannot already send OS signals to the wrapped process. I was unable to locate such a deployment scenario in the indexed docs, so I cannot assert this meets the "concrete impact + realistic likelihood" bar required by the objective without that confirmation.

func (c *RunnerWrapperCommand) createListener() (net.Listener, error) {
	uri, err := url.ParseRequestURI(c.GRPCListen)
	if err != nil {
		return nil, fmt.Errorf("%w: %w", errFailedToParseGRPCAddress, err)
	}

	switch uri.Scheme {
	case "unix":
		return net.Listen("unix", uri.Path)
	case "tcp":
		return net.Listen("tcp", uri.Host)
	default:
		return nil, fmt.Errorf("%w: %s", errUnsupportedGRPCAddressScheme, uri.Scheme)
	}
}

func (w *Wrapper) InitiateGracefulShutdown(req api.InitGracefulShutdownRequest) error {
	w.lock.RLock()
	p := w.process
	w.lock.RUnlock()

	if p == nil {
		return api.ErrProcessNotInitialized
	}

	w.log.Info("Initiating graceful shutdown of the process")

	err := p.Signal(gracefulShutdownSignal)
	if err != nil {
		return fmt.Errorf("could not send graceful shutdown signal: %w", err)
	}

	if req.ShutdownCallbackDef().URL() != "" {
		w.log.
			WithField("target", req.ShutdownCallbackDef().URL()).
			WithField("method", req.ShutdownCallbackDef().Method()).
			Debug("Registering shutdown callback")

		w.setShutdownCallback(api.NewShutdownCallback(w.log, req.ShutdownCallbackDef()))
	}

	w.setStatus(api.StatusInShutdown)

	return nil
}

func (w *Wrapper) InitiateForcefulShutdown() error {
	w.lock.RLock()
	p := w.process
	w.lock.RUnlock()

	if p == nil {
		return api.ErrProcessNotInitialized
	}

	w.log.Info("Initiating forceful shutdown of the process")

	err := w.forcefulShutdown(p)
	if err != nil {
		return fmt.Errorf("could not send forceful shutdown signal: %w", err)
	}

	w.setStatus(api.StatusInShutdown)

	return nil
}
