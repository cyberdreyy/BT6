### Title
Stale confirmations from removed multisig members are still counted toward the approval threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` counts entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set for a request to decide whether `num_confirmations` has been reached [1](#0-0) . When a member is removed via `DeleteMember`, `delete_member` only purges confirmations for requests that the removed member itself authored; it never scans other outstanding requests to strip that member's confirmation entry [2](#0-1) . As a result, a confirmation cast by a member who is later removed keeps counting toward the threshold on any other still-open request, allowing that request to execute with fewer *live* member approvals than `num_confirmations` requires.

### Finding Description
The intended binding is: `confirmations recorded for a request == approvals from currently-authorized members`, and a request should only execute once `num_confirmations` *live* members have approved it.

`confirm` re-validates that the caller is a *current* member via `current_member()`, which checks `self.members.contains(&member)` [3](#0-2) . This correctly gates who can *add* a new confirmation. However, it never re-validates the *existing* entries already stored in the `confirmations` set for the request before comparing `confirmations.len() as u32 + 1 >= self.num_confirmations` [4](#0-3) .

`delete_member`, invoked through `DeleteMember` inside `execute_request`, only removes requests authored by the removed member (and their confirmation sets, since the whole request is deleted) [5](#0-4) [6](#0-5) . It does not iterate over `self.requests`/`self.confirmations` for requests authored by *other* members to strip the removed member's `member.to_string()` entry from their `HashSet<String>`. Any pending request that the now-removed member had previously confirmed retains that confirmation indefinitely.

Consequently, once a member is removed, the effective number of *live* approvals needed to execute any request they had already confirmed is `num_confirmations - 1`, not `num_confirmations`. This breaks the "confirmations counted vs live members" custody binding directly called out as an in-scope class of bug.

### Impact Explanation
This is Critical impact per the rules: "a multisig request executed below threshold." A `Transfer`, `FunctionCall`, `AddKey` (full access key), or `DeployContract` request can be executed with fewer live-member confirmations than `num_confirmations` mandates, because a stale confirmation from a removed member is still counted. This can lead to unauthorized movement of NEAR/wNEAR held by the multisig account, or unauthorized privileged actions (e.g. adding a full access key), effectively circumventing the K-of-N authorization guarantee the contract is supposed to provide.

### Likelihood Explanation
The scenario does not require any bug in usage or a malicious deployment — it arises from the contract's normal, documented lifecycle: members are added, requests are created/confirmed over time, and members are later removed (e.g., due to key rotation, off-boarding, or a compromised member being kicked out) via the standard `DeleteMember` action, which is explicitly supported by the contract. Any multisig that has ever removed a member while other requests were pending is exposed. No special privilege beyond being (or having been) a legitimate multisig member is required to have contributed the now-stale confirmation; the party benefiting from the stale confirmation can be a member who was intentionally removed for wrongdoing.

### Recommendation
When deleting a member in `delete_member`, iterate over all outstanding `requests`/`confirmations` entries and remove the deleted member's identifier from every confirmations `HashSet`, not just from requests they authored. Alternatively, when counting confirmations in `confirm`/before executing, filter the confirmations set to only entries whose member is still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `num_confirmations = 3` and members `{A, B, C, D, E}` [7](#0-6) .
2. Member `A` calls `add_request_and_confirm` with a `Transfer` request to account `A` (1 confirmation: A) [8](#0-7) .
3. Member `B` calls `confirm(request_id)` (2 confirmations: A, B) — still short of threshold 3.
4. The remaining members submit and confirm a separate `DeleteMember { member: A }` request and it executes, removing `A` from `self.members` [5](#0-4) [9](#0-8) . The Transfer request from step 2 is untouched because it was authored by `A`... to avoid that edge case, have the Transfer request instead be authored by `B` and confirmed by `A` and `B` (so it is not among "requests by public_key == A" and is not deleted).
5. After `A` is removed, `confirmations.get(&request_id)` for the Transfer request still contains `{A, B}` (2 entries) even though `A` is no longer in `self.members`.
6. Member `C` calls `confirm(request_id)`. `confirmations.len() as u32 + 1 = 3 >= num_confirmations (3)` succeeds and the Transfer executes and funds move, even though only 2 currently-live members (`B`, `C`) actually approved it — one fewer than the configured 3-of-5 threshold requires [1](#0-0) .

    pub fn add_request(&mut self, request: MultiSigRequest) -> RequestId {
        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(
                "Predecessor must be a member or transaction signed with key of given account",
            )
        });
        // track how many requests this key has made
        let num_requests = self
            .num_requests_pk
            .get(&current_member.to_string())
            .unwrap_or(0)
            + 1;
        assert(
            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    /// Add request for multisig and confirm with the pk that added.
    pub fn add_request_and_confirm(&mut self, request: MultiSigRequest) -> RequestId {
        let request_id = self.add_request(request);

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
