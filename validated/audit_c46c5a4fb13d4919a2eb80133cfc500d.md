## Analysis

The reported bug class — an ownership/authority transfer function that fails to validate the new address, risking a permanent lockout of privileged functionality — has a direct analog in marginfi-v2's admin-transfer instructions. Unlike Solidity's `Ownable.sol`, which at least checks `_newOwner != address(0)`, the marginfi-v2 program equivalents perform **no validation whatsoever** on the incoming `Pubkey` when reassigning admin authorities.

### Title
Unvalidated Admin/Authority Transfer Can Permanently Lock Out Group and Global Fee State Admin Functions - (File: `programs/marginfi/src/state/marginfi_group.rs`, `programs/marginfi/src/instructions/marginfi_group/edit_global_fee.rs`)

### Summary
`MarginfiGroupImpl::update_admin` and the sibling `update_*_admin` setters unconditionally overwrite the corresponding admin field with whatever `Pubkey` is supplied via `marginfi_group_configure`, with no check that the value is non-default/non-zero or otherwise a plausible signer. The same pattern exists in `edit_fee_state` (`edit_global_fee.rs`) for the global `FeeState.global_fee_admin` and `pause_delegate_admin`. If the current admin issues a transfer with a mistaken value (e.g., `Pubkey::default()`, a burn address, or an unintended key with no known private key), the group or the entire program's fee state becomes permanently un-administrable.

### Finding Description
`configure()` in `programs/marginfi/src/instructions/marginfi_group/configure.rs` accepts `Option<Pubkey>` for `new_admin` and seven other delegate-admin roles, and applies them via `MarginfiGroupImpl` setters: [1](#0-0) 

The setter itself contains no validation: [2](#0-1) 

The same unchecked-overwrite pattern applies to `emode_admin`, `delegate_curve_admin`, `delegate_limit_admin`, `delegate_flow_admin`, `metadata_admin`, and `risk_admin` setters in the same file.

Separately, `edit_fee_state` performs the equivalent unchecked overwrite for the *global*, singleton `FeeState.global_fee_admin` and `pause_delegate_admin`: [3](#0-2) [4](#0-3) 

There is only one `FeeState` PDA per program deployment, gated by `has_one = global_fee_admin`: [5](#0-4) 

In both cases (`MarginfiGroup.admin` and `FeeState.global_fee_admin`), no code path checks that the new value is not `Pubkey::default()` (Solana's zero-pubkey analog to `address(0)`) or otherwise a key nobody controls. Because `Pubkey::default()` has no known private key, no signer can ever satisfy `Signer<'info>` checks or `has_one = admin`/`has_one = global_fee_admin` constraints against it afterward.

### Impact Explanation
- For `MarginfiGroup.admin`: setting it to a zero/burn/unreachable key permanently locks the group out of `marginfi_group_configure`, bank admin operations gated on `admin`, and any instruction relying on `has_one = admin`, since the group's own account (a PDA-less regular account created at group init, admin field mutable only by itself) can never be signed for again by a legitimate party. This mirrors the original report's "whole protocol locked out of its permissioned functionalities."
- For `FeeState.global_fee_admin`: since `FeeState` is a program-wide singleton (`seeds = [FEE_STATE_SEED]`), losing this admin key blocks `edit_global_fee_state`, `config_group_fee`, and pause/fee management for the **entire program**, not just one group — a broader blast radius than the group-level admin.
- Impact is a durable freeze/DoS of privileged administration with no recovery path once triggered (score consistent with the original report's Impact: 5).

### Likelihood Explanation
This requires an admin-signed transaction with an incorrect argument (e.g., a copy/paste, script bug, or governance-supplied wrong value) — the same "mistake in the transfer" scenario as the original finding. It cannot be triggered by an unprivileged attacker directly, only by admin error, consistent with the original report's low likelihood (Likelihood: 1). This is not a validator/peer-only or purely theoretical issue; it directly affects an authority field with financial/administrative consequences reachable through a real, currently-shipped instruction.

### Recommendation
Add an explicit guard in `update_admin` (and the other `update_*_admin` setters) and in `edit_fee_state` rejecting `new_admin == Pubkey::default()` (and optionally other known-unusable keys), returning a descriptive `MarginfiError` instead of silently applying the value. Consider a two-step "propose/accept" admin-transfer pattern (as used in some referenced ecosystem programs, e.g. Kamino's `GlobalConfig.pending_admin`) to require the new admin to actively claim the role, eliminating single-transaction irrecoverable mistakes entirely.

### Proof of Concept
1. Current group admin calls `marginfi_group_configure` with `new_admin = Some(Pubkey::default())` (or any keypair-less/burn address) — instruction succeeds with no error, as seen in `configure()`/`update_admin()`.
2. `MarginfiGroup.admin` is now `Pubkey::default()`. No subsequent transaction can satisfy `Signer` + `has_one = admin` for this group; all admin-only instructions (`configure`, `lending_pool_configure_bank`, etc.) permanently fail with `Unauthorized`.
3. Equivalently, calling `edit_global_fee_state` with `admin = Some(Pubkey::default())` bricks `global_fee_admin` for the single program-wide `FeeState` PDA, blocking `edit_global_fee_state`/`config_group_fee` protocol-wide, as reflected in the account constraints here: [5](#0-4)
