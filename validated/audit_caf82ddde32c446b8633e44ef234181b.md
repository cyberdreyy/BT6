### Title
Symlink-based workspace escape lets a job read arbitrary host files into its cache archive - (File: commands/helpers/file_archiver.go)

### Summary
`fileArchiver.process` and `fileArchiver.findRelativePathInProject` validate that a candidate cache/artifact path resolves to a location under `c.wd` using purely lexical `filepath.Abs`/`filepath.Rel` string comparisons. Neither function calls `filepath.EvalSymlinks` or otherwise resolves symlinked path components, so a job that creates a symlink inside its own workspace pointing outside it (e.g. `workspace/link -> /etc`) can have `link/passwd` accepted as a lexically-valid, in-workspace relative path even though it dereferences to a file outside `c.wd`.

### Finding Description
`fileArchiver.process` (commands/helpers/file_archiver.go:65-101) computes `absolute = filepath.Abs(match)` and `relative = filepath.Rel(c.wd, absolute)`, then only rejects the path if `relative` has a `".."+Separator` prefix: [1](#0-0) 
This check is purely syntactic. If `match` is `link/passwd` where `link` is a symlink created inside the job workspace pointing to `/etc`, `filepath.Abs`/`filepath.Rel` never dereference the symlink — they operate on path strings — so `relative` becomes `link/passwd`, which does not start with `..`, and the check passes. The same lexical-only resolution exists in `findRelativePathInProject` (commands/helpers/file_archiver.go:191-222), used by `processPath` for glob-expanded `--path`/`CACHE_PATHS` entries: [2](#0-1) 

The accepted relative path `link/passwd` is stored in `c.files` via `add()`, which calls `os.Lstat(path)` on the *symlink-inclusive* path (so `Lstat` on `link/passwd` follows the intermediate directory symlink `link` and stats the real target `/etc/passwd`) at commands/helpers/file_archiver.go:127-138: [3](#0-2) 

`CacheArchiverCommand.createZipFile` then calls `archive.NewArchiver(..., c.wd, ...).Archive(ctx, c.files)` (commands/helpers/cache_archiver.go:229-238). Looking at the archiver implementations (e.g. `tarzstd_archiver.Archive`), the outside-of-chroot guard is also purely lexical: it does `path, err := filepath.Abs(name)` and checks `strings.HasPrefix(path, a.dir+Separator)`: [4](#0-3) 
Since `filepath.Abs("link/passwd")` = `c.wd/link/passwd`, this string still has the `a.dir` prefix even though the real file is `/etc/passwd`, so the archiver's own guard also doesn't stop it. It then does `os.Open(path)` at line 110, which follows the symlinked directory component and opens `/etc/passwd`, copying its contents into the tar/zip stream.

No component in this chain (`process`, `findRelativePathInProject`, `add`, or the archivers' chroot guard) calls `filepath.EvalSymlinks` to resolve intermediate symlinked directories before doing the containment check. This matches a known project pitfall documented in the codebase's own `AGENTS.md` about `filepath.Walk` and symlink traversal requiring `EvalSymlinks` resolution — but that guidance was not applied to the cache-archiver path-containment checks.

### Impact Explanation
An unprivileged job can read arbitrary files reachable from the executor's filesystem namespace (host files in shell executor, or files outside the designated build directory in other executors) into the cache archive it uploads, then download that cache with a subsequent job/pipeline it controls — resulting in unauthorized file disclosure of files outside the job's intended cache/build root. This directly violates the stated invariant that "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
Preconditions are minimal and fully job-controlled: the job merely needs to run `ln -s /etc link` in its workspace before the cache-archiver step runs (this is standard behavior after `script:` execution, before `cache:` upload) and declare `cache: paths: ["link/passwd"]`. This requires no special executor privileges beyond the ability to create a symlink in the workspace, which is available in every executor type. The exploit is deterministic and repeatable per job run.

### Recommendation
In `fileArchiver.process` and `findRelativePathInProject`, resolve the path with `filepath.EvalSymlinks` (or walk each path component checking `os.Lstat` for `os.ModeSymlink` and resolving/rejecting symlinks that point outside `c.wd`) before computing `relative`/`rel`, and re-verify the resolved real path is still under `c.wd`. Apply the same real-path resolution in the archivers' chroot-containment checks (e.g. `tarzstd_archiver.Archive`, other archiver implementations) so that even if a symlinked entry itself is legitimately included (for storing as a symlink), its target being opened for content copy must be checked, and any intermediate directory symlink used to reach a file must not escape `dir`.

### Proof of Concept
```go
func TestFileArchiver_SymlinkedDirEscapesWorkspace(t *testing.T) {
    wd := t.TempDir()
    outside := t.TempDir()
    secret := filepath.Join(outside, "secret.txt")
    require.NoError(t, os.WriteFile(secret, []byte("host-secret"), 0o644))

    // job creates a symlink inside its workspace pointing outside
    link := filepath.Join(wd, "link")
    require.NoError(t, os.Symlink(outside, link))

    origWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(wd))
    defer os.Chdir(origWd)

    c := &fileArchiver{Paths: []string{"link/secret.txt"}}
    require.NoError(t, c.enumerate())

    // Assert: no entry in c.files should resolve (via EvalSymlinks) outside wd.
    for name := range c.files {
        abs := filepath.Join(wd, name)
        real, err := filepath.EvalSymlinks(abs)
        require.NoError(t, err)
        assert.True(t, strings.HasPrefix(real, wd+string(filepath.Separator)),
            "file %q resolves to %q which escapes workspace %q", name, real, wd)
    }
}
```
Expected current (buggy) behavior: `c.files` contains `"link/secret.txt"`, and the assertion fails because it resolves to `outside/secret.txt`. After the fix (symlink-aware containment check), `processPath` should reject the entry and `c.files` should be empty, making the assertion loop vacuously pass (or the test should additionally assert `len(c.files) == 0`).

```go
func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

	if err == nil {
		// Process path only if it lives in our build directory
		if !strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			excluded, rule := c.isExcluded(relative)
			if excluded {
				c.exclude(rule)
				return false
			}

			err = c.add(relative)
		} else {
			err = errors.New("not supported: outside build directory")
		}
	}
```

```go
func (c *fileArchiver) add(path string) error {
	// Always use slashes
	path = filepath.ToSlash(path)

	// Check if file exist
	info, err := os.Lstat(path)
	if err == nil {
		c.files[path] = info
	}

	return err
}
```
