### Title
APR0 withdrawal interest rounding leaves funded yield permanently unclaimable - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.prepareStopEpochWithApr0()` adds the aggregate APR0 interest allocation to `pendingWithdraws`, but stores only a floored per-principal rate; each user later floors that rate again when claiming, leaving part of the funded interest unassigned and unclaimable. [1](#0-0) [2](#0-1) 

### Finding Description
APR0 requests place the post-fee request amount into `apr0TotalPrincipal` rather than `withdrawsRequests`. [3](#0-2) [4](#0-3) 

During `stopEpoch`, the strategy calculates `_apr0InterestGross`, subtracts performance fees, adds `_apr0NetInterest` to `pendingWithdraws`, and saves `apr0RateByEpoch[epochNumber] = _apr0NetInterest * 1e18 / _principal`. [5](#0-4) [1](#0-0) 

That rate is already rounded down, and `_settleApr0()` rounds down each user's share again with `(_principal * _rate) / 1e18`. [6](#0-5) 

`collectWithdrawFunds()` funds the full aggregate `pendingWithdraws`, including the entire `_apr0NetInterest`, while the aggregate of user payouts can be smaller. [7](#0-6) [8](#0-7) 

For example, with two APR0 principals of `1`, active TVL of `1`, and override interest of `2`, `_apr0NetInterest` is `1`, the stored rate is `0.5e18`, and both users receive zero APR0 interest, permanently leaving `1` funded unit outside every claim. [9](#0-8) [10](#0-9) 

### Impact Explanation
Each affected APR0 epoch can strand up to approximately one underlying unit per claimant, and this can repeat across an unbounded number of epochs and users. [9](#0-8) [10](#0-9) 

No claimant receives the residual because claim amounts are computed from per-user principal and the floored epoch rate rather than from the remaining funded balance. [11](#0-10) 

The only generic escape is the privileged `transferToken()` rescue function, which does not preserve recipient-level accounting and cannot be invoked by affected users. [12](#0-11) 

### Likelihood Explanation
The issue requires only an APR0 epoch, at least two withdrawal requesters, and an interest allocation whose scaled rate is not exactly representable; all are ordinary protocol states and do not depend on privileged misconduct. [13](#0-12) 

### Recommendation
Track APR0 interest per requester directly or maintain an explicit remainder bucket for each epoch so the sum of claims equals `_apr0NetInterest`; alternatively, sweep the remainder to `feeReceiver` or assign it deterministically to the final claimant, rather than leaving it unaccounted for in the strategy. [14](#0-13) 

### Proof of Concept

Add this test to `test/foundry/IdleCreditVault.t.sol`:

```solidity
function testApr0InterestRoundingLocksFundedShare() public {
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, 0);
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    address user1 = makeAddr("apr0-dust-user1");
    address user2 = makeAddr("apr0-dust-user2");

    // Active TVL = 1; APR0 principal bucket = 2.
    idleCDO.depositAA(1);
    _depositWithUser(user1, 1, true);
    _depositWithUser(user2, 1, true);

    vm.prank(user1);
    uint256 principal1 = cdoEpoch.requestWithdraw(0, address(AAtranche));
    vm.prank(user2);
    uint256 principal2 = cdoEpoch.requestWithdraw(0, address(AAtranche));

    assertEq(principal1, 1);
    assertEq(principal2, 1);
    assertEq(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 2);
    assertEq(cdoEpoch.getContractValue(), 1);

    _startEpochAndCheckPrices(0);

    // interest=2, tvl=1, apr0Principal=2:
    // apr0Net = floor(2 * 2 / 3) = 1
    // rate = floor(1e18 / 2) = 0.5e18
    // user interest = floor(1 * 0.5e18 / 1e18) = 0 each.
    uint256 poolInterest = 2;
    uint256 apr0Net = 1;
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, 4);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, poolInterest);

    assertEq(
        IdleCreditVault(address(strategy)).apr0RateByEpoch(0),
        0.5e18
    );

    uint256 pendingFundedAmount = 3;
    uint256 user1Before = underlying.balanceOf(user1);
    vm.prank(user1);
    cdoEpoch.claimWithdrawRequest();
    uint256 user1Paid = underlying.balanceOf(user1) - user1Before;

    uint256 user2Before = underlying.balanceOf(user2);
    vm.prank(user2);
    cdoEpoch.claimWithdrawRequest();
    uint256 user2Paid = underlying.balanceOf(user2) - user2Before;

    assertEq(user1Paid, 1);
    assertEq(user2Paid, 1);
    assertEq(user1Paid + user2Paid, 2);

    // pendingWithdraws was funded with principal1 + principal2 + apr0Net = 3.
    uint256 lockedApr0Interest = pendingFundedAmount - user1Paid - user2Paid;
    assertEq(lockedApr0Interest, apr0Net);
    assertEq(underlying.balanceOf(address(strategy)), 2); // active interest plus stranded APR0 dust
}
```
