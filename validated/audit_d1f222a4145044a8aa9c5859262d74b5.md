### Title
pprof debug endpoints exposed to view-role authenticated users without admin role check - ([File: core/web/router.go])

### Summary
`metricRoutes` mounts the full `net/http/pprof` handler set (`/`, `/cmdline`, `/profile`, `/symbol`, `/trace`, `/allocs`, `/block`, `/goroutine`, `/heap`, `/mutex`, `/threadcreate`) under the `authv2` route group with no `auth.RequiresAdminRole`/`auth.RequiresEditRole`/`auth.RequiresRunRole` wrapper. Any authenticated user, including one with only the lowest `UserRoleView` role, can therefore reach `GET /v2/debug/pprof/heap`, `/v2/debug/pprof/cmdline`, `/v2/debug/pprof/trace`, etc.

### Finding Description
`v2Routes` builds `authv2` as a group requiring only `auth.Authenticate` with `AuthenticateByToken`/`AuthenticateBySession` [1](#0-0) . Every sensitive endpoint in that group is explicitly wrapped with a role-check middleware such as `auth.RequiresAdminRole`, `auth.RequiresEditRole`, or `auth.RequiresRunRole` (e.g. key export/import/delete routes) [2](#0-1) . However, `metricRoutes(authv2)` is called directly with no such wrapper [3](#0-2) , and `metricRoutes` itself registers the raw `net/http/pprof` handlers unconditionally [4](#0-3) .

The role middleware in `core/web/auth/auth.go` shows `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` are the only mechanisms that gate access based on `clsessions.UserRoleView`/`Run`/`Edit`/`Admin` [5](#0-4) . Since `metricRoutes` doesn't use any of these wrappers, a user authenticated with the lowest privilege `UserRoleView` (via valid session or API token) passes `auth.Authenticate` and reaches the pprof handlers directly — `pprof.Handler("heap").ServeHTTP` will dump the full Go heap, which can contain decrypted private keys, session tokens, or other secrets held in process memory, and `pprof.Cmdline`/`pprof.Trace` expose process command-line/execution trace data.

### Impact Explanation
This matches an authorization-bypass / sensitive-information-disclosure class: a low-privileged authenticated principal can obtain a live heap dump of the node process, which chainlink nodes hold decrypted keystore material and session/API secrets in memory during normal operation. This could allow extraction of key material without needing edit/admin/run role, an authorization exactness violation relative to how every other sensitive endpoint in the same route group is protected.

### Likelihood Explanation
The attacker only needs any valid authenticated principal on the node — the lowest role (`UserRoleView`) is sufficient, obtainable via a legitimate but restricted account or a valid API token created for view-only monitoring purposes. No additional preconditions (no admin, no host access, no misconfiguration) are required; the request is a simple `GET /v2/debug/pprof/heap` against the always-mounted route.

### Recommendation
Wrap `metricRoutes(authv2)` (or the group it creates internally) with `auth.RequiresAdminRole`, consistent with the sensitivity of exposing raw process memory/profiling data, e.g. change the pprof group registration to apply `auth.RequiresAdminRole` on each handler or group-level middleware in `metricRoutes`.

### Proof of Concept
Go handler-level integration test plan (using the existing router/test harness under `core/web`):
1. Build a test app and router via the existing `web.NewRouter` test helper used in `core/web/*_test.go`.
2. Create a user/session with `clsessions.UserRoleView`.
3. Issue `GET /v2/debug/pprof/heap` (and `/v2/debug/pprof/cmdline`) with the view-role session/token.
4. Assert current behavior returns `200 OK` with pprof payload (proving the vulnerability), and after the fix, assert `403 Forbidden` (matching `RequiresAdminRole` behavior seen in existing tests for endpoints like `/v2/keys/eth/import`).
5. Repeat with `UserRoleEdit`/`UserRoleRun` to confirm they too should be rejected once fixed, matching admin-only exclusivity elsewhere in `v2Routes`.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
