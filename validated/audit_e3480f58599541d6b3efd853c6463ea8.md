### Title
Staker Permanently Loses Rewards When `rewards_pool` Is Insufficient — (`File: crates/sui-framework/packages/sui-system/sources/staking_pool.move`)

---

### Summary

`withdraw_rewards` silently caps the reward payout to the available `rewards_pool` balance, but `request_withdraw_stake` still records the **full** `pool_token_withdraw_amount` as consumed. The staker's pool tokens are burned in their entirety while they receive fewer SUI rewards than those tokens entitle them to. The shortfall is permanently lost to the withdrawing staker and redistributed to remaining stakers via a skewed exchange rate.

---

### Finding Description

`withdraw_rewards` (lines 424–441) computes the entitled reward, then silently clamps it:

```move
// TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
pool.rewards_pool.split(reward_withdraw_amount)
```

It returns a `Balance<SUI>` that may be **less** than the amount the pool tokens represent.

The caller `request_withdraw_stake` (lines 176–185) uses the returned (capped) value for the SUI accounting, but uses the **full** `pool_token_withdraw_amount` for the pool-token accounting:

```move
let rewards_withdraw = pool.withdraw_rewards(
    principal_withdraw_amount,
    pool_token_withdraw_amount,
    ctx.epoch(),
);
let total_sui_withdraw_amount = principal_withdraw_amount + rewards_withdraw.value(); // capped

pool.pending_total_sui_withdraw = pool.pending_total_sui_withdraw + total_sui_withdraw_amount;
pool.pending_pool_token_withdraw =
    pool.pending_pool_token_withdraw + pool_token_withdraw_amount; // full, uncapped
```

At epoch boundary, `process_pending_stake_withdraw` (lines 374–395) subtracts:
- `pending_total_sui_withdraw` (the capped, smaller SUI amount) from `pool.sui_balance`
- `pending_pool_token_withdraw` (the full pool-token amount) from `pool.pool_token_balance`

The pool-token balance shrinks by more than the SUI balance shrinks proportionally. The exchange rate stored for the new epoch therefore favors remaining stakers, while the withdrawing staker has permanently forfeited the reward delta.

This is the direct Sui analog of the external report: `safeRewardTransfer` returns less than requested but the caller resets `user.accClaim = 0` assuming full payment. Here, `withdraw_rewards` returns less than calculated but the caller records the full pool-token burn.

---

### Impact Explanation

Any ordinary SUI holder who has staked SUI and calls `request_withdraw_stake` when the pool's `rewards_pool` balance is below the calculated reward amount will:

1. Have their `StakedSui` object destroyed (pool tokens fully consumed).
2. Receive fewer SUI rewards than their pool tokens entitle them to.
3. Have no recourse — the shortfall stays in the pool and is redistributed to remaining stakers.

This is a permanent, irreversible loss of staking rewards for the withdrawing staker, constituting harmful smart-contract behavior reachable from a public, unprivileged transaction.

---

### Likelihood Explanation

The developer comment `// TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.` on line 438 confirms the condition is observed in production. The test suite (`rewards_distribution_tests.move`, lines 1012–1018) explicitly exercises a scenario where `pool.pool_token_balance() < pool.pending_pool_token_withdraw_amount()`, which is a related condition arising from safe-mode epochs causing missing exchange-rate entries. Any epoch in which safe mode is active, or in which rounding causes `rewards_pool` to fall slightly below the calculated entitlement, triggers the loss.

---

### Recommendation

`withdraw_rewards` should return both the actual amount transferred **and** the originally calculated amount, so the caller can record only the pool tokens that correspond to the SUI actually paid out:

```move
// Option A: return (actual_reward, entitled_pool_tokens_to_burn)
// Option B: abort if rewards_pool < reward_withdraw_amount (enforce invariant)
// Option C: record pending_pool_token_withdraw proportionally to actual SUI paid
```

At minimum, `request_withdraw_stake` must not record the full `pool_token_withdraw_amount` when `rewards_withdraw.value() < reward_withdraw_amount`. The pool-token burn must be proportional to the SUI actually received.

---

### Proof of Concept

1. Validator pool has `sui_balance = 200 SUI`, `rewards_pool = 5 SUI`, `pool_token_balance = 100`.
2. Exchange rate implies 1 pool token = 2 SUI (100 SUI principal + 100 SUI rewards / 100 tokens).
3. Staker holds a `StakedSui` representing 50 pool tokens, entitled to 100 SUI (50 principal + 50 rewards).
4. Staker calls `request_withdraw_stake`.
5. `withdraw_rewards` calculates `reward_withdraw_amount = 50 SUI`, but `rewards_pool.value() = 5 SUI`, so it caps and returns 5 SUI.
6. `total_sui_withdraw_amount = 50 + 5 = 55 SUI` → `pending_total_sui_withdraw += 55`.
7. `pending_pool_token_withdraw += 50` (full amount, uncapped).
8. At epoch boundary: `pool.sui_balance -= 55`, `pool.pool_token_balance -= 50`.
9. Staker received 55 SUI instead of 100 SUI. The 45 SUI shortfall remains in `rewards_pool` and accrues to remaining stakers. The staker's pool tokens are fully destroyed with no recourse. [1](#0-0) [2](#0-1) [3](#0-2)

```text
fun process_pending_stake_withdraw(pool: &mut StakingPool) {
    pool.sui_balance = if (pool.sui_balance >= pool.pending_total_sui_withdraw) {
        pool.sui_balance - pool.pending_total_sui_withdraw
    } else {
        let diff = pool.pending_total_sui_withdraw - pool.sui_balance;
        // While this key is expected to be removed in the next call to `process_pending_stake`,
        // we do not call `process_pending_stake` for inactive pools — skip the bookkeeping.
        if (!pool.is_inactive()) {
            pool.extra_fields.add(UnderflowSuiBalance {}, diff);
        };
        0
    };

    pool.pool_token_balance = if (pool.pool_token_balance >= pool.pending_pool_token_withdraw) {
        pool.pool_token_balance - pool.pending_pool_token_withdraw
    } else {
        0
    };

    pool.pending_total_sui_withdraw = 0;
    pool.pending_pool_token_withdraw = 0;
}
```

```text
fun withdraw_rewards(
    pool: &mut StakingPool,
    principal_withdraw_amount: u64,
    pool_token_withdraw_amount: u64,
    epoch: u64,
): Balance<SUI> {
    let exchange_rate = pool.pool_token_exchange_rate_at_epoch(epoch);
    let total_sui_withdraw_amount = exchange_rate.get_sui_amount(pool_token_withdraw_amount);
    let mut reward_withdraw_amount = if (total_sui_withdraw_amount >= principal_withdraw_amount) {
        total_sui_withdraw_amount - principal_withdraw_amount
    } else 0;

    // This may happen when we are withdrawing everything from the pool and
    // the rewards pool balance may be less than reward_withdraw_amount.
    // TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
    reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
    pool.rewards_pool.split(reward_withdraw_amount)
}
```
