### Title
Parallel cache range downloads splice bytes from different object versions without version pinning - (File: commands/helpers/cache_extractor.go)

### Summary
`getCacheDownloadURLAndEnv` in `shells/abstract.go` only generates the cache URL/env arguments passed to the `cache-extractor` helper; the actual multi-chunk fetch happens in `handleGoCloudURL`/`tryPresignedParallelDownload`/`downloadParallel` in `commands/helpers/cache_extractor.go`. When `FF_USE_PARALLEL_CACHE_TRANSFER` is enabled with `CACHE_CONCURRENCY > 1`, the object's metadata (size, ETag/Last-Modified) is fetched once, but each subsequent range chunk fetch does not pin to that specific object version, so concurrent overwrites of the object between/among chunk fetches can produce a locally reconstructed archive whose bytes come from two different uploads.

### Finding Description
`handleGoCloudURL` fetches `attrs` once via `selectedBucket.Attributes(ctx, selectedObjectName)` (`commands/helpers/cache_extractor.go:468`), then for objects larger than one chunk calls `selectedBucket.NewRangeReader(ctx, selectedObjectName, offset, length, nil)` per chunk inside `fetchChunk` (`commands/helpers/cache_extractor.go:494-496`). The `nil` options passed to `NewRangeReader` mean no conditional/If-Match/generation constraint tying the read to the specific object version whose `attrs.ETag`/`attrs.Size` were captured earlier.

The same pattern exists for presigned URLs: `tryPresignedParallelDownload` captures `ETag`/`Last-Modified`/`Content-Length` from a single-byte probe request (`commands/helpers/cache_extractor.go:264-285`), then `presignedRangeFetchChunk` (`commands/helpers/cache_extractor.go:337-354`) issues independent `GET` requests with only a `Range` header — no `If-Match` header carrying the previously observed `ETag` is ever set.

`transfer.ParallelRangeDownload` (`helpers/transfer/parallel_download.go:91-113`) then fires `concurrency` chunk fetches concurrently via goroutines and writes each chunk directly to its byte offset with `WriteAt` (`downloadParallel`, `commands/helpers/cache_extractor.go:514-551`). There is no verification after the parallel download completes that all chunks belonged to a single, consistent object version (e.g., re-checking ETag/attrs after assembly). If the underlying object is overwritten mid-download (a new PUT with different content but the same key/path), some chunks will be served from the old version and others from the new version, because different HTTP/GoCloud range requests can independently hit whichever version is current server-side at the time they execute — object storage backends (S3, GCS, Azure Blob) do not guarantee this consistency for unconditioned GET Range requests.

Preconditions for the object to change mid-download:
- `FF_USE_PARALLEL_CACHE_TRANSFER` enabled and `CACHE_CONCURRENCY > 1` (opt-in feature flag/config, but attacker-controllable at the job level via CI variables per docs: `docs/configuration/advanced-configuration.md:1508-1522`).
- The same cache key/object path must be written to while another job is downloading it. Cache keys, fallback keys, and paths are fully attacker-controlled via `.gitlab-ci.yml` (`cacheOptions.Key`, `FallbackKeys`, `CACHE_FALLBACK_KEY`, see `shells/abstract.go:285-335`), so an attacker who controls two concurrent job runs (or, if `Shared: true` cache is configured, two cooperating/differently-privileged projects sharing the runner cache) can trigger a race: job A starts a large cache restore, job B concurrently overwrites the same cache object with attacker content.

None of the existing checks stop this:
- `isLocalCacheFileUpToDate` only prevents *skipping* a download when local file is newer; it does not protect against mid-flight object replacement.
- ETag/Last-Modified are only used for the "up to date" freshness heuristic and logging, not for consistency enforcement across chunk fetches.
- There is no post-download verification that recomputes/re-checks object identity/ETag for the just-downloaded bytes.

### Impact Explanation
The spliced/mixed archive is written to `c.File` and subsequently extracted into the job's cache directory (via `--file` and the extraction step referenced from `shells/abstract.go:337-393`). Because the mixture of two versions of an archive (e.g. two different ZIP/TAR streams) is likely to be structurally invalid, the most common outcome is extraction failure/corruption (a denial-of-service on cache restore for that job). However, a more concrete risk exists: an attacker who fully controls both cache-object versions (their own key, their own uploads) can attempt to craft version A's central directory/headers and version B's file-data such that the local archive extractor reads header/metadata from one version while raw file bytes come from the other — this is the classic archive-splicing vector for corrupting the restored cache contents (cache poisoning of their own project's cache, or of any consumer sharing that cache path if `Shared` caching across projects is enabled). The most reliably demonstrable, in-scope impact is: cache corruption/poisoning where the invariant "all restored cache bytes must come from one bound object version" is violated.

### Likelihood Explanation
Requires the feature flag `FF_USE_PARALLEL_CACHE_TRANSFER` and `CACHE_CONCURRENCY > 1` (attacker/job-controllable environment variables per docs), a cache object larger than one chunk, and two overlapping job executions writing/reading the same cache key on the same runner cache backend within the multi-second window of a parallel chunked download. All are within reach of an unprivileged pipeline author: they can set the feature flag and concurrency via job variables, control cache keys/paths, and schedule two jobs to run concurrently against the same key (or race a `cache:push` job against a `cache:pull` job). This is deterministically reproducible with a test harness that swaps backend content between chunk fetches.

### Recommendation
Pin all chunk range reads to the specific object version identified at the start of the download:
- For GoCloud backends, pass conditional options to `NewRangeReader` if the driver supports generation/ETag pinning (e.g., S3 `IfMatch`, GCS object generation), or at minimum re-fetch `Attributes` after the parallel download completes and abort/retry if ETag/size/ModTime changed.
- For presigned URL chunk fetches, set an `If-Match: <ETag>` header (captured from the initial probe) on every `presignedRangeFetchChunk` request, and treat a `412 Precondition Failed` response as a fatal, retryable error rather than silently accepting mismatched bytes.
- After `downloadParallel` finishes writing all chunks, verify final content length matches `contentLength` and, where possible, verify a checksum/ETag of the assembled file before renaming it into place and before extraction.

### Proof of Concept
Go integration test plan (extending existing tests such as `TestCacheExtractorPresignedParallelTransferAlternate` in `commands/helpers/cache_extractor_test.go`):
1. Stand up an `httptest.Server` serving a presigned-URL-style cache endpoint that supports Range requests.
2. On the first Range request (chunk 0), respond with bytes from "version A" payload and ETag `"A"`.
3. Concurrently (or after chunk 0 is served but before remaining chunks), swap the server's underlying payload/ETag to "version B" content of the same total length but different bytes, without changing `Content-Length`.
4. Run `CacheExtractorCommand.Execute` with `FF_USE_PARALLEL_CACHE_TRANSFER=true`, `Concurrency: 4`, `ChunkSize` small enough to force multiple chunks.
5. Assert: the resulting local file at `c.File` should NOT contain a mixture of version A and version B bytes; either the download must fail/retry (expected fix behavior) or, under the current code, assert that the test demonstrates the bug by showing the reconstructed file contains bytes from both payloads (proving the invariant "all restored cache bytes must come from one bound object version" is violated).

Note: I could not execute this test in the current environment; the analysis above is based on static code review of `commands/helpers/cache_extractor.go` and `helpers/transfer/parallel_download.go`. I was unable to fully confirm whether any GoCloud driver-level generation pinning exists implicitly for S3/GCS beyond what's shown, since the underlying `gocloud.dev/blob` driver internals are outside this repository's indexed code. func (b *AbstractShell) extractCacheOrFallbackCachesWrapper(
	ctx context.Context,
	w ShellWriter,
	info common.ShellScriptInfo,
	initialCacheConfig cacheConfig,
	cacheOptions spec.Cache,
) {
	// the "default" cache key
	cacheConfigs := []cacheConfig{initialCacheConfig}

	build := info.Build
	buildVars := build.GetAllVariables()
	addCacheConfig := func(key string, keyChecks ...func(s string) bool) {
		if key == "" {
			return
		}
		cc, warning, err := newCacheConfig(build, key, keyChecks...)
		if warning != "" {
			w.Warningf("%s", warning)
		}
		if err != nil {
			w.Noticef("Skipping cache extraction due to %v", err)
			return
		}
		if cc != nil {
			cacheConfigs = append(cacheConfigs, *cc)
		}
	}

	// the fallback cache keys from the cache config
	for _, cacheKey := range cacheOptions.FallbackKeys {
		addCacheConfig(buildVars.ExpandValue(cacheKey))
	}

	// the fallback key from CACHE_FALLBACK_KEY
	blockProtectedFallback := func(key string) bool {
		const blockedSuffix = "-protected"
		trimmedKey := strings.TrimRight(key, ". ")
		allowed := !strings.HasSuffix(trimmedKey, blockedSuffix)
		if !allowed {
			w.Warningf("CACHE_FALLBACK_KEY %q not allowed to end in %q", key, blockedSuffix)
		}
		return allowed
	}
	addCacheConfig(buildVars.Value("CACHE_FALLBACK_KEY"), blockProtectedFallback)

	// Execute cache-extractor command. Failure is not fatal.
	b.guardRunnerCommand(w, info.RunnerCommand, "Extracting cache", func() {
		b.addExtractCacheCommand(ctx, w, info, cacheConfigs, cacheOptions.Paths)
	})
}

func getCacheDownloadURLAndEnv(ctx context.Context, build *common.Build, cacheKey string) ([]string, map[string]string, error) {
	adapter := cache.GetAdapter(build.Runner.Cache, build.GetBuildTimeout(), build.Runner.ShortDescription(), fmt.Sprintf("%d", build.JobInfo.ProjectID), cacheKey, build.IsFeatureFlagOn(featureflags.HashCacheKeys))

	// Prefer Go Cloud URL if supported
	goCloudURL, err := adapter.GetGoCloudURL(ctx, false)

	if goCloudURL.URL != nil {
		return []string{"--gocloud-url", goCloudURL.URL.String()}, goCloudURL.Environment, err
	}

	if url := adapter.GetDownloadURL(ctx); url.URL != nil {
		args := []string{"--url", url.URL.String()}
		if headURL := adapter.GetHeadURL(ctx); headURL.URL != nil {
			args = append(args, "--head-url", headURL.URL.String())
		}
		return args, nil, nil
	}

	return []string{}, nil, nil
}

func (c *CacheExtractorCommand) tryPresignedParallelDownload() (done bool, err error) {
	selectedURL := c.selectPresignedURL()

	req, reqErr := http.NewRequest(http.MethodGet, selectedURL, nil)
	if reqErr != nil {
		return false, nil
	}
	req.Header.Set("Range", "bytes=0-0")

	resp, doErr := c.getClient().Do(req)
	if doErr != nil || resp == nil {
		return false, nil
	}

	if resp.StatusCode != http.StatusPartialContent {
		if resp.StatusCode == http.StatusOK {
			logrus.Infoln("Presigned URL did not honor Range request, using sequential download")
		}
		_ = resp.Body.Close()
		return false, nil
	}

	contentLength, ok := transfer.ParseContentRangeTotal(resp.Header.Get("Content-Range"))
	if !ok {
		_ = resp.Body.Close()
		return false, nil
	}

	date, _ := time.Parse(http.TimeFormat, resp.Header.Get("Last-Modified"))
	if isLocalCacheFileUpToDate(c.File, date) {
		_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, transfer.RangeProbeBodyMaxDiscard))
		_ = resp.Body.Close()
		logrus.Infoln(filepath.Base(c.File), "is up to date")
		return true, nil
	}

	chunkSize := c.effectiveParallelChunkSize()
	if contentLength <= int64(chunkSize) {
		_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, transfer.RangeProbeBodyMaxDiscard))
		_ = resp.Body.Close()
		return false, nil
	}

	_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, transfer.RangeProbeBodyMaxDiscard))
	_ = resp.Body.Close()

	cleanedURL := url_helpers.CleanURL(selectedURL)
	err = c.downloadParallel(contentLength, date, resp.Header.Get("ETag"), cleanedURL, headersToCacheMetadata(resp.Header), c.presignedRangeFetchChunk(selectedURL))
	return true, err

func (c *CacheExtractorCommand) presignedRangeFetchChunk(rawURL string) func(offset, length int64) (io.ReadCloser, error) {
	return func(offset, length int64) (io.ReadCloser, error) {
		req, err := http.NewRequest(http.MethodGet, rawURL, nil)
		if err != nil {
			return nil, err
		}
		req.Header.Set("Range", fmt.Sprintf("bytes=%d-%d", offset, offset+length-1))
		resp, err := c.getClient().Do(req)
		if err != nil {
			return nil, err
		}
		if resp.StatusCode != http.StatusOK && resp.StatusCode != http.StatusPartialContent {
			_ = resp.Body.Close()
			return nil, fmt.Errorf("range request failed: %s", resp.Status)
		}
		return resp.Body, nil
	}
}

func ParallelRangeDownload(contentLength, chunkSize int64, concurrency int, dest io.WriterAt, fetchChunk FetchChunk) error {
	chunkSize, concurrency, err := normalizeParallelDownloadInputs(contentLength, chunkSize, concurrency)
	if err != nil {
		return err
	}
	chunks := parallelDownloadRanges(contentLength, chunkSize)

	worker := &parallelRangeWorker{dest: dest, fetchChunk: fetchChunk}
	sem := make(chan struct{}, concurrency)
	var wg sync.WaitGroup

	for _, cnk := range chunks {
		wg.Add(1)
		sem <- struct{}{}
		go func(offset, length int64) {
			defer wg.Done()
			defer func() { <-sem }()
			worker.downloadChunk(offset, length)
		}(cnk.offset, cnk.length)
	}
	wg.Wait()
	return worker.firstErr
}
