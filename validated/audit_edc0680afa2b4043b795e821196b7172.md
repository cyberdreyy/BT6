### Title
Zip extraction allows symlink-based directory traversal to write files outside extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipSymlinkEntry` writes attacker-controlled symlink targets to disk with no validation that the target stays within the extraction root, and `extractZipFile`/`extractZipFileEntry` never verify that the parent directories of a later entry are real directories rather than symlinks. An archive can therefore plant a symlinked "directory" entry and then extract a file entry whose path traverses through that symlink, causing the runner to write attacker-controlled content to an arbitrary path on the host filesystem outside the intended extraction directory.

### Finding Description
`extractZipSymlinkEntry` (helpers/archives/zip_extract.go:22-39) reads the symlink target directly from the archive and calls `os.Symlink(string(data), file.Name)` with no check that the target resolves inside the extraction root: [1](#0-0) 

`extractZipFile` (helpers/archives/zip_extract.go:61-83) calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` before dispatching to the type-specific handler. `MkdirAll` follows symlinks when checking whether a path component already exists as a directory, so if an earlier archive entry created `dir` as a symlink to an arbitrary location, `MkdirAll(filepath.Dir("dir/passwd"))` succeeds as a no-op without validating that `dir` is a real, in-root directory: [2](#0-1) 

`extractZipFileEntry` (helpers/archives/zip_extract.go:41-59) then does `_ = os.Remove(file.Name)` (leaf only, error ignored) followed by `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)`. Because the path's directory component is a symlink and the OS resolves it transparently, this `OpenFile` call actually creates/truncates a file at the symlink's resolved target directory, not inside the extraction root: [3](#0-2) 

No lstat/containment check exists anywhere in this file (or in `ExtractZipArchive`, helpers/archives/zip_extract.go:85-110) to detect that an intermediate path component is a symlink escaping the destination: [4](#0-3) 

This code path is reachable from cache/artifact restoration via `ziplegacy.extractor.Extract`, which calls `archives.ExtractZipArchive` directly on the caller-provided zip reader with no additional path sanitation layered on top: [5](#0-4) 

Since cache archives (and legacy artifact archives using this extractor) are built from job-controlled content, a pipeline author fully controls the zip entries, their order, names, and symlink targets that reach this extraction code on the runner host.

### Impact Explanation
An unprivileged pipeline author can craft a cache/artifact zip archive that: (1) creates an entry named e.g. `dir` with type symlink pointing to an arbitrary absolute path (e.g. `/etc` or any writable-by-runner-user location), then (2) creates a regular file entry named `dir/payload`. On extraction, `MkdirAll` treats `dir` as already existing (via symlink resolution) and `extractZipFileEntry` writes/truncates a file at the resolved target (e.g., `/etc/payload`), i.e., arbitrary file creation/overwrite outside the job workspace, limited to paths writable by the runner process's OS user.

### Likelihood Explanation
The precondition is straightforward and fully attacker-controlled: standard zip archives support symlink entries via the Unix mode bits in the external file attributes, and Go's `archive/zip` writer/reader used here processes entries in file order, exactly as required (symlink entry for a "directory" placed before a file entry using it as a path prefix). No special runner privileges, admin cooperation, or race condition is needed — this is a deterministic, repeatable path, not a TOCTOU race, since the symlink is fully established before the file entry is processed.

### Recommendation
Before creating or writing any archive entry, validate that no component of the resolved (symlink-following) path escapes the extraction root: use `filepath.EvalSymlinks` (or manually walk `filepath.Dir(file.Name)` component by component with `os.Lstat`) and reject/skip entries whose resolved parent is a symlink or is outside the destination directory. Additionally, validate symlink targets written by `extractZipSymlinkEntry` to ensure the resolved target stays within the extraction root, and reject entries with such attempted escapes rather than silently succeeding.

### Proof of Concept
Go test in `helpers/archives/zip_extract_test.go`:
1. Build an in-memory zip with two entries in order: `"link"` (mode `os.ModeSymlink`, content = absolute path to a temp "outside" directory created by the test, e.g. `/tmp/outside`), then `"link/pwn.txt"` (regular file, content `"pwned"`).
2. Extract into a fresh, empty temp "root" directory via `ExtractZipArchive`.
3. Assert that `/tmp/outside/pwn.txt` does NOT exist (i.e., extraction must fail or the file must land only within the root), and that no file was written outside the root directory.
4. Current code fails this assertion: `/tmp/outside/pwn.txt` is created with content `"pwned"`, proving the escape.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
