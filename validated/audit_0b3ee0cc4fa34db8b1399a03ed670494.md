### Title
Parser differential between the lenient `AttestationVerifier::verify` path and the strict `NitroCose` payload validator allows a Nitro attestation content-injection / signature-scope mismatch - (File: `crates/proof/tee/nitro-verifier/src/verify.rs`)

### Summary
This finding is analogous to the ruby-saml `CVE-2025-66567` bug class: two different CBOR/COSE parsers derive different structural interpretations of the same signed bytes, and only one of the two enforces strict, canonical decoding. In this codebase there are two independent CBOR decoders for AWS Nitro attestation documents:

1. The lenient path: `AttestationReport::parse` ( [1](#0-0) ) decodes the COSE envelope and then decodes the payload straight into `AttestationDocument` via `ciborium::de::from_reader` with no pre-validation of the raw bytes. This struct is a plain `serde::Deserialize` derive ( [2](#0-1) ), and `AttestationVerifier::verify` builds the on-chain `VerifierJournal` directly from it ( [3](#0-2) ).
2. The strict path: `NitroCose::parse_sign1` / `NitroCose::validate_payload_structure` in the registrar crate performs a byte-exact CBOR walk that explicitly rejects duplicate top-level keys, duplicate PCR indices, trailing bytes, and non-canonical encodings before any `serde`/`ciborium` deserialization happens ( [4](#0-3) , [5](#0-4) ).

The registrar's own code comments confirm the two parsers disagree on the same bytes: *"raw CBOR rejects duplicates/trailing bytes that deserialization would collapse or miss"* ( [6](#0-5) ), and a dedicated test proves it: *"Strict COSE rejects trailing bytes that `AttestationReport::parse` accepts"* ( [7](#0-6) ).

### Finding Description
`AttestationVerifier::verify` — the entry point that produces the `VerifierJournal` consumed on-chain by `INitroEnclaveVerifier`/`NitroValidator.sol` ( [8](#0-7)  and [9](#0-8) ) — trusts a Serde/ciborium decode of the attestation payload with no prior structural validation. Serde map deserialization for duplicate keys is last-value-wins (not rejected), and ciborium accepts trailing bytes after a top-level CBOR item as long as the outer array bounds it correctly, and tolerates non-canonical length encodings that a hand-rolled walker (used elsewhere in the same codebase, in `registrar/src/cbor.rs`) explicitly rejects.

Because `Self::verify_cose_signature` signs over `report.cose.sig_structure()` — built from the raw `protected`/`payload` byte slices extracted by `CoseSign1::from_bytes` ( [10](#0-9) ) — the signature covers the whole payload byte-string as a monolithic blob. The vulnerability is that the *content* extracted from that same blob (`module_id`, `pcrs`, `certificate`, `cabundle`, `user_data`, `nonce`) is derived by a decoder (`ciborium`/`serde`) whose behavior on ambiguous, duplicate, or non-canonically-encoded CBOR maps is not proven identical to what the registrar's strict walker (or the on-chain Solidity `NitroValidator._parsePcrs`/`decodeAttestationTbs`, which the strict walker is explicitly designed to mirror per its own doc comment: *"Minimal CBOR walker matching `NitroValidator`..."*, [11](#0-10) ) would produce. A signer (AWS Nitro hardware, or any entity able to get a signed COSE_Sign1 blob accepted) can therefore craft a single signed payload containing duplicate/ambiguous CBOR map entries (e.g., two `pcrs` maps, or a `pcrs` map with duplicate PCR indices) that:
- `AttestationVerifier::verify` (lenient) decodes into one set of PCR/cert/moduleId values and emits a `VerifierJournal` reflecting those values, while
- the strict, Solidity-mirroring walker `NitroCose::validate_payload_structure` would have rejected the same bytes outright, or a canonical decoder would extract a *different* value for the duplicated field (e.g., first-vs-last occurrence).

Since `AttestationVerifier::verify`'s only guard on this class of manipulation is `validate_attestation_content` (M-02), which explicitly documents this gap itself: *"PCR duplicate detection requires a raw CBOR walk (maps collapse duplicates); callers that need that should validate the payload bytes separately"* ( [12](#0-11) ), any caller of `AttestationVerifier::verify` that does not separately call `NitroCose::validate_payload_structure` first inherits the same class of parser-differential risk that CVE-2025-66567 describes for SAML/XML: the security decision (which PCR/cert values are "the" trusted values baked into the journal) is made by a parser more permissive than the canonical reference parser the on-chain contract is built against.

### Impact Explanation
If `AttestationVerifier::verify` is the code path used to produce the SNARK/zk journal that is ultimately checked on-chain by the `INitroEnclaveVerifier`/`NitroValidator` contract (per the Solidity-aligned ABI types in `types.rs`), a crafted-but-validly-signed attestation could cause the emitted `VerifierJournal.pcrs`/`moduleId`/`certs` fields to diverge from what the pinned on-chain reference parser (`NitroValidator.sol`, which the strict `NitroCose` walker is built to match) would have accepted or computed for the identical bytes. This is the same "signature wrapping"/parser-differential root cause as the SAML CVE: the signature validates over the raw byte blob, but the *interpreted* security-relevant fields differ depending on which decoder reads them. Depending on how the journal is consumed downstream (e.g., registering a TEE enclave's PCR0/signer identity for privileged Base operations), this could permit registering an enclave identity or PCR set that the canonical parser would have rejected — a concrete authentication-bypass-class outcome for TEE-based attestation trust, matching the Critical severity of the class in the report.

### Likelihood Explanation
Exploitability depends on whether any production entry point calls `AttestationVerifier::verify` directly on attacker/enclave-controlled bytes without first running them through `NitroCose::validate_payload_structure` (as `AttestationPlanner::prepare_registration_plan` correctly does). From the code available, the registrar's `planner.rs` is careful to layer the strict walker in front of `ciborium` decoding, but the standalone `AttestationVerifier::verify` in the `nitro-verifier` crate exposes the lenient path as its own public, documented "entry point for end-to-end Nitro attestation verification" and does not itself apply the strict pre-validation. I could not fully verify within this session whether every current caller of `AttestationVerifier::verify` (e.g., an SP1/RISC Zero zkVM guest referenced by `ZkCoProcessorType`) reuses the registrar's strict pre-check or not — the grep for callers only turned up the registrar crate and the crate's own tests, so likelihood is uncertain without confirming the zk-guest integration code, which may live outside what was indexed.

### Recommendation
Concept-level guidance (no plan requested, per instructions): `AttestationVerifier::verify` should call the same strict, canonical CBOR structural validation (`NitroCose::validate_payload_structure`-equivalent checks: duplicate-key rejection, trailing-byte rejection, canonical-length rejection) on the raw payload bytes *before* handing them to `ciborium`/`serde`, exactly as `AttestationPlanner::prepare_registration_plan` already does. This removes the two-parser disagreement and makes the "lenient" `AttestationVerifier::verify` path as strict as the registrar path and the on-chain `NitroValidator.sol` reference decoder it is meant to mirror.

### Proof of Concept
Not independently constructible within this session without executing the Rust test suite, but the codebase's own test directly demonstrates the differential: feeding the fixture attestation with one trailing `0x00` byte appended causes `AttestationPlanner::prepare_registration_plan` (strict path) to return `Err(PlannerError::Cose(_))`, while the same bytes are documented and tested to be accepted by `AttestationReport::parse`/`AttestationVerifier::verify` (lenient path) — see the test comment *"Strict COSE rejects trailing bytes that `AttestationReport::parse` accepts"* at [13](#0-12) . Extending this same technique to duplicate CBOR map keys inside the `pcrs`/top-level payload map (which `validate_payload_structure` explicitly tests for and rejects at [14](#0-13) ) but which `ciborium`'s serde-derived `BTreeMap`/struct decode would silently collapse via last-value-wins, is the concrete construction path for the parser-differential PoC, though full end-to-end validation of the downstream journal-consumption trust impact would require access to the on-chain `NitroValidator.sol` contract and the zk-guest integration code, which were not available in this indexed session.

impl CoseSign1 {
    /// Parses a `COSE_Sign1` structure from raw CBOR bytes.
    ///
    /// Handles the optional CBOR tag 18 (`COSE_Sign1`) per RFC 8152.
    /// The input is expected to be a CBOR array of 4 elements:
    /// `[protected, unprotected, payload, signature]`.
    pub fn from_bytes(bytes: &[u8]) -> Result<Self> {
        let value: CborValue = ciborium::de::from_reader(bytes)
            .map_err(|e| VerifierError::Cbor(format!("`COSE_Sign1`: {e}")))?;

        // Unwrap optional CBOR tag 18 (`COSE_Sign1`).
        let array = match value {
            CborValue::Tag(18, inner) => match *inner {
                CborValue::Array(a) => a,
                _ => return Err(VerifierError::CoseFormat("tagged value is not an array".into())),
            },
            CborValue::Array(a) => a,
            _ => return Err(VerifierError::CoseFormat("expected array or tag 18".into())),
        };

        if array.len() != 4 {
            return Err(VerifierError::CoseFormat(format!(
                "expected 4 elements, got {}",
                array.len()
            )));
        }

        let mut iter = array.into_iter();
        let protected = Self::extract_bytes(iter.next().unwrap(), "protected")?;
        // Skip unprotected header (element 1) — we don't use it.
        let _unprotected = iter.next().unwrap();
        let payload = Self::extract_bytes(iter.next().unwrap(), "payload")?;
        let signature = Self::extract_bytes(iter.next().unwrap(), "signature")?;

        Ok(Self { protected, payload, signature })
    }

        // 1. Parse attestation report.
        let report = AttestationReport::parse(&input.attestationReport)?;

        // 2. Validate attestation content (M-02).
        Self::validate_attestation_content(&report.doc)?;

        // 3. Extract and verify certificate chain.
        let cert_chain_der = report.cert_chain_der();
        let chain = CertChain::from_der(&cert_chain_der)?;

        let trusted_prefix_len = input.trustedCertsPrefixLen as usize;
        let (certs, cert_expiries) =
            chain.verify_chain(trusted_prefix_len, report.doc.timestamp)?;

        // 4. Verify COSE signature against the leaf certificate's public key.
        let leaf_pk_bytes = chain.leaf_public_key()?;
        let sig_structure = report.cose.sig_structure()?;
        Self::verify_cose_signature(leaf_pk_bytes, &sig_structure, &report.cose.signature)?;

        // 5. Build the journal.
        let pcrs = report
            .doc
            .pcrs
            .iter()
            .map(|(&index, value)| Pcr { index, value: Bytes48::from(value) })
            .collect::<Vec<_>>();

        Ok(VerifierJournal {
            result: VerificationResult::Success,
            trustedCertsPrefixLen: input.trustedCertsPrefixLen,
            timestamp: report.doc.timestamp,
            certs,
            certExpiries: cert_expiries,
            userData: Self::optional_bytes(&report.doc.user_data),
            nonce: Self::optional_bytes(&report.doc.nonce),
            publicKey: Self::optional_bytes(&report.doc.public_key),
            pcrs,
            moduleId: report.doc.module_id,
        })
    }

    /// Validates payload CBOR structure: no trailing bytes, PCR duplicate/index rules, cabundle
    /// limits.
    pub fn validate_payload_structure(payload: &[u8]) -> PlannerResult<()> {
        let root =
            CborItem::read(payload, 0)?.require_major(CBOR_MAJOR_MAP, "attestation payload")?;
        if root.end != payload.len() {
            return Err(PlannerError::Cose("trailing data after attestation payload".into()));
        }

        let mut offset = root.content_start;
        let mut item_count = 0u64;
        let mut seen_keys = BTreeSet::new();
        loop {
            if !root.indefinite && item_count == root.value {
                break;
            }
            if root.indefinite {
                if offset >= payload.len() {
                    return Err(PlannerError::Cose(
                        "indefinite attestation payload map missing break".into(),
                    ));
                }
                if payload[offset] == CBOR_BREAK {
                    break;
                }
            }

            let key = CborItem::read(payload, offset)?
                .require_major(CBOR_MAJOR_TEXT_STRING, "attestation payload key")?;
            let value = CborItem::read(payload, key.end)?;
            let value_end = value.end;
            let key_text = std::str::from_utf8(&payload[key.content_start..key.end])
                .map_err(|_| PlannerError::Cose("attestation payload key is not UTF-8".into()))?;
            if Self::is_known_attestation_key(key_text) && !seen_keys.insert(key_text) {
                return Err(PlannerError::Cose(format!(
                    "duplicate attestation payload key: {key_text}"
                )));
            }

            match key_text {
                "pcrs" => Self::validate_pcrs(payload, value)?,
                "cabundle" => Self::validate_cabundle(payload, value)?,
                "certificate" => {
                    let certificate = value.require_major(CBOR_MAJOR_BYTE_STRING, "certificate")?;
                    let len = certificate.end - certificate.content_start;
                    if len == 0 || len > MAX_CABUNDLE_CERT_BYTES {
                        return Err(PlannerError::Cose(format!(
                            "certificate must be between 1 and {MAX_CABUNDLE_CERT_BYTES} bytes, got {len}"
                        )));
                    }
                }
                _ => {}
            }

            offset = value_end;
            item_count += 1;
        }

        if root.indefinite {
            if offset >= payload.len() || payload[offset] != CBOR_BREAK {
                return Err(PlannerError::Cose(
                    "indefinite attestation payload map missing break".into(),
                ));
            }
        } else if offset != root.end {
            return Err(PlannerError::Cose("attestation payload map length mismatch".into()));
        }

        Ok(())
    }

    fn validate_pcrs(payload: &[u8], pcrs: CborItem) -> PlannerResult<()> {
        let pcrs = pcrs.require_major(CBOR_MAJOR_MAP, "pcrs")?;
        if !pcrs.indefinite && pcrs.value > MAX_PCRS as u64 {
            return Err(PlannerError::Cose(format!(
                "PCR count {} out of range (must be at most {MAX_PCRS})",
                pcrs.value
            )));
        }

        let mut seen = BTreeSet::new();
        let mut offset = pcrs.content_start;
        let mut count = 0u64;
        loop {
            if Self::container_done(payload, pcrs, offset, count, "pcrs")? {
                break;
            }
            if count >= MAX_PCRS as u64 {
                return Err(PlannerError::Cose(format!(
                    "attestation pcrs has more than {MAX_PCRS} entries"
                )));
            }
            let key = CborItem::read(payload, offset)?.require_major(CBOR_MAJOR_UINT, "pcr key")?;
            if key.value >= MAX_PCRS as u64 {
                return Err(PlannerError::Cose(format!(
                    "PCR index {} out of range (must be 0-{})",
                    key.value,
                    MAX_PCRS - 1
                )));
            }
            if !seen.insert(key.value) {
                return Err(PlannerError::Cose(format!("duplicate PCR index {}", key.value)));
            }
            let value = CborItem::read(payload, key.end)?
                .require_major(CBOR_MAJOR_BYTE_STRING, "pcr value")?;
            offset = value.end;
            count += 1;
        }
        Ok(())
    }
