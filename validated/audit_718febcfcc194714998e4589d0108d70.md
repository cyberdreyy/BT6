### Title
Deleted Multisig Member's Stale Confirmations Are Still Counted Toward Execution Threshold - ([File: multisig2/src/lib.rs])

### Summary
The bug class in the report is a validation result cached at one context (mempool acceptance at height `H+1`) being trusted later at a different, invalid context (`H+2`) without re-validation. The direct analog here is `multisig2`'s `confirm`/`delete_member` logic: a confirmation recorded by a member is never invalidated when that member is later removed from the multisig, so a stale "confirmation" from a no-longer-live member is still counted toward `num_confirmations` when a *different* member later triggers execution.

### Finding Description
`confirm` counts `confirmations.len()` (a set of member identifiers who approved a request) against `self.num_confirmations` without checking that every entry in `confirmations` still corresponds to a current member: [1](#0-0) 

`delete_member` only purges *requests originally submitted by* the removed member (`r.member == member`); it does not scan `self.confirmations` for other, still-pending requests that the removed member had already confirmed: [2](#0-1) 

Concretely:
1. Members `A, B, C, D` exist with `num_confirmations = 3`.
2. Member `X` (some other member, say `B`) creates `add_request` for a `Transfer`. `A` confirms it (`confirmations = {A}`, 1/3).
3. The multisig executes a `DeleteMember{member: A}` request (via a separate, properly-authorized request) — this only removes requests where `r.member == A` (i.e., requests A *authored*), leaving the pending Transfer request's `confirmations = {A}` untouched, even though `A` is no longer a member.
4. `C` and `D` (now the only two other live members besides the removed `A`) confirm the same pending Transfer request. `confirmations.len() = 3` (`A, C, D`) `>= num_confirmations (3)`, so `execute_request` fires — even though only 2 *live* members (`C`, `D`) actually approved it.

This breaks the custody binding "confirmations counted versus live members": the equality that should hold is `count(confirmations ∩ live_members) >= num_confirmations`, but the code checks `count(confirmations) >= num_confirmations` where `confirmations` can contain stale (removed) members.

### Impact Explanation
This allows a `MultiSigRequest` (including `Transfer`, `FunctionCall`, `AddKey`/`AddMember`, `DeployContract`) to execute with fewer live-member approvals than the configured threshold `K`. This is a direct violation of "a multisig request executed below threshold" — Critical impact per the rules, since it can move NEAR or authorize privileged actions (adding keys/members) without the required quorum of currently-trusted signers.

### Likelihood Explanation
The only requirement is that a member who has an outstanding confirmation on some request is later removed via a normal `DeleteMember` governance action (a routine operation, e.g., offboarding an employee/rotating a compromised key) while a separate request is mid-flight. No privileged bypass, redeploy, or malicious validator is needed beyond the normal, documented `DeleteMember` action. The remaining members exploiting or simply not noticing the stale confirmation is a realistic scenario in any long-lived multisig account with request/member churn — this is a plausible sequence of ordinary operations, not a contrived edge case.

### Recommendation
When deleting a member (`delete_member`), iterate over all `self.requests` and remove the deleted member from any `confirmations` set they appear in (not just their own authored requests), or alternatively, in `confirm`, filter `confirmations` to only those entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}`, `num_confirmations = 3`.
2. `B.add_request(Transfer{...})` → `request_id = 1`.
3. `A.confirm(1)` → `confirmations[1] = {A}`.
4. Separately, run and confirm a `DeleteMember{member: A}` request to completion (removing `A` from `self.members`); note request 1's confirmation set is untouched since `remove_request`/`delete_member`'s cleanup only targets requests authored by `A`.
5. `C.confirm(1)` → `confirmations[1] = {A, C}` (2/3).
6. `D.confirm(1)` → `confirmations[1].len() == 3 >= num_confirmations`, so `execute_request` runs the `Transfer` — approved by only 2 live members (`C`, `D`) plus one stale, removed member (`A`). [1](#0-0) [2](#0-1)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
