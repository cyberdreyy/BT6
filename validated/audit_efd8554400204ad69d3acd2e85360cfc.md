Confirmed: `withdraw`, `publicWithdraw`, and `cancel` are all `onlyCaller(immutables.taker.get())`-gated [1](#0-0) , and `rescueFunds` is also `onlyCaller(immutables.taker.get())` [2](#0-1) . That means the destination escrow's "taker" role—self-selected by the same unprivileged account that called `createDstEscrow`—is the only party who can ever pull funds out of a malformed clone; the maker has no direct-recovery path at all.

### Title
Unprivileged `createDstEscrow` caller can craft a sub-64-byte `parameters` blob that makes `EscrowDst.withdraw()`/`publicWithdraw()` permanently revert in `ImmutablesLib`, freezing the maker's destination payout - (File: `contracts/EscrowDst.sol`, `contracts/libraries/ImmutablesLib.sol`)

### Summary
`BaseEscrowFactory.createDstEscrow` performs no length validation on the attacker-supplied `dstImmutables.parameters` blob before deploying and funding the destination clone. `EscrowDst._withdraw` unconditionally calls `ImmutablesLib.integratorFeeAmountCd()` (requires `length >= 0x40`) and `protocolFeeAmountCd()` (requires `length >= 0x20`) on that same blob. If `parameters.length` is 31 bytes (or any value `< 0x40`), every `withdraw`/`publicWithdraw` call for that specific escrow instance reverts with `IndexOutOfRange`, even though the clone was correctly funded with the destination tokens and safety deposit.

### Finding Description
`createDstEscrow` is a fully public, unprivileged entrypoint - unlike the source-side `postInteraction` path, which requires the resolver to be whitelisted [3](#0-2) . It only checks that `msg.value` matches the required native amount and that the correct ERC20 amount is transferred in; it never checks `dstImmutables.parameters.length` [3](#0-2) .

The `Immutables.parameters` field is documented as being used "only" by `EscrowDst.withdraw()` [4](#0-3) . `EscrowDst._withdraw` decodes fee data straight out of that blob before doing anything else: [5](#0-4) 

`ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd` explicitly revert with `IndexOutOfRange` if the blob is shorter than `0x40`/`0x20` bytes respectively: [6](#0-5) 

Because `immutables.hash()` incorporates `keccak256(parameters)` [7](#0-6) , the exact same malformed `parameters` blob used at deployment must be re-supplied on every subsequent call to pass `onlyValidImmutables`. There is no way to "fix" the blob after the fact — the escrow is permanently bound to the broken parameters it was created with.

Since `withdraw`, `publicWithdraw`, `cancel`, and `rescueFunds` are all gated by `onlyCaller(immutables.taker.get())` [1](#0-0) [2](#0-1) , and `taker` is a field the caller of `createDstEscrow` fully controls (no check that `msg.sender == dstImmutables.taker.get()`), the creator of the malformed clone is also the only account who can ever act on it. The maker (who is supposed to receive the payout via `withdraw`) has no way to intervene at all — `withdraw`/`publicWithdraw` always revert before reaching the maker transfer at line 93, regardless of who calls, because the fee-decoding revert happens unconditionally inside `_withdraw` before the `onlyValidSecret`/transfer logic even matters.

### Impact Explanation
This fits the "Temporary freezing of funds during the live swap lifecycle" High-impact bucket: a correctly-funded destination escrow (real dst tokens + safety deposit, verified via the balance semantics of `createDstEscrow`) becomes permanently non-withdrawable for its intended lifetime. The maker cannot ever claim the destination payout for that swap instance — every `withdraw`/`publicWithdraw` attempt during the withdrawal/public-withdrawal window reverts with `IndexOutOfRange` before the secret/transfer logic runs. The funds are only recoverable by the escrow's self-declared `taker` via `cancel()` (after the cancellation timelock) or `rescueFunds()` (after the rescue delay) — never by the maker, meaning the specific cross-chain swap this escrow was meant to service cannot complete as designed.

### Likelihood Explanation
High. `createDstEscrow` has no privilege gate and no length check on `parameters`; any account with enough tokens/native currency to fund a legitimate-looking escrow can trivially set `parameters` to a 31-byte (or any `<0x40`-byte) blob. No race condition, timing, or special permissions are required.

### Recommendation
Validate `dstImmutables.parameters.length` in `BaseEscrowFactory.createDstEscrow` (e.g., require it to be exactly `0x80` bytes, matching the four ABI-encoded fee fields, or `0` if fees are intentionally disabled with a corresponding branch in `_withdraw`) before deploying/funding the clone, so malformed blobs are rejected at creation time rather than causing an unrecoverable revert at withdrawal time.

### Proof of Concept
1. Attacker (unprivileged) calls `createDstEscrow(dstImmutables, srcCancellationTimestamp)` with `dstImmutables.parameters = bytes` of length 31, `dstImmutables.taker = attacker`, and correctly funds `msg.value`/ERC20 transfer to satisfy `InsufficientEscrowBalance` checks.
2. The clone deploys successfully; `escrow.balance`/token balance checks pass since parameters length is unrelated to fund checks.
3. Once the `DstWithdrawal` window opens, anyone (attacker as `taker`, or via `publicWithdraw` after `DstPublicWithdrawal`) calls `withdraw(secret, dstImmutables)` with the identical `dstImmutables` (required to pass `onlyValidImmutables`).
4. `_withdraw` calls `immutables.integratorFeeAmountCd()`, which checks `parameters.length < 0x40` (31 < 64) and reverts with `ImmutablesLib.IndexOutOfRange()` before any transfer happens.
5. This revert is deterministic and occurs for every call with these immutables — the maker's expected payout is unreachable for the life of this escrow instance, resolvable only by the attacker-controlled `taker` via `cancel()`/`rescueFunds()`.

        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function hash(IBaseEscrow.Immutables calldata immutables) internal pure returns(bytes32 ret) {
        // Compute the EIP-712 hash for the immutables struct
        bytes calldata parameters = immutables.parameters;
        assembly ("memory-safe") {
            let ptr := mload(0x40)

            // Copy immutables.parameters to memory and compute its hash
            calldatacopy(ptr, parameters.offset, parameters.length)
            let parametersHash := keccak256(ptr, parameters.length)

            // Copy the immutables struct to memory, patch `parameters` and compute its hash
            calldatacopy(ptr, immutables, IMMUTABLES_SIZE)
            mstore(add(ptr, IMMUTABLES_LAST_WORD), parametersHash)
            ret := keccak256(ptr, IMMUTABLES_SIZE)
        }
    }
