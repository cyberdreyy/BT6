### Title
Write-off requests with `underlyingsRequested == 0` let any fulfiller extract escrowed tranche tokens for free - (contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` never validates that `underlyingsRequested` is non-zero, and `fullfillWriteOffRequest` is callable by any wallet with a check that only rejects *underpaying* (`_underlyings < currentRequest.underlyings`). A request recorded with `underlyings == 0` can therefore be fulfilled with `_underlyings == 0`: the fulfiller pays nothing and still receives all escrowed tranche tokens, while the lender receives nothing back.

### Finding Description
This is the on-chain analog of an unsanitized input reaching a privileged action (SQLi bug class): a user-controlled field (`underlyingsRequested`) is stored without validation and later drives the asset-exchange branch.

- `createWriteOffRequest` only reverts on `amount == 0`; `underlyingsRequested` can be `0` and is accumulated into `userRequests[msg.sender].underlyings` and `pendingUnderlyings` [1](#0-0) .
- `fullfillWriteOffRequest` reverts only when `currentRequest.tranches != _tranches` or `_underlyings < currentRequest.underlyings`. With `underlyings == 0`, passing `_underlyings == 0` satisfies both checks [2](#0-1) .
- The request is deleted, the fulfiller's `safeTransferFrom` pulls 0 underlying, the fee on 0 is 0, the user is sent `_underlyings - _totFee = 0`, and the fulfiller receives `_tranches` escrowed tranche tokens [3](#0-2) .

The attacker is an unprivileged "write-off fulfiller" — a role explicitly intended to be permissionless (`@dev this function can be called by any wallet`). No privileged actor misbehavior is required; the only precondition is a victim request whose `underlyings` field is 0, which the contract itself permits the lender to create (including via repeated top-ups, where a lender may deposit tranches first and decide a price later, leaving `underlyings == 0` in the interim).

### Impact Explanation
Direct theft: the fulfiller receives `currentRequest.tranches` tranche tokens (redeemable/claimable against the vault at tranche value) in exchange for 0 underlying. The victim loses the full value of the escrowed tranches and cannot recover it because `userRequests[_user]` is deleted, so `deleteWriteOffRequest` can no longer return the tranches [4](#0-3) . The broken invariant is fair exchange: one escrowed position, one agreed payout. Loss equals the tranche value of the victim's escrowed balance.

### Likelihood Explanation
The attack is permissionless and front-runnable: any EOA can monitor `createWriteOffRequest` transactions/events, detect `underlyingsRequested == 0`, and fulfill before the lender tops up a price or deletes the request. The contract makes zero-priced requests trivially creatable (only the tranche `amount` is checked), so the vulnerable state is reachable through normal use — e.g., a lender batching tranche deposits before pricing, or a UI default of 0. No epoch-phase dependence beyond `isEpochRunning` at creation time; fulfillment is unrestricted by epoch state.

### Recommendation
- Revert in `createWriteOffRequest` when `underlyingsRequested == 0` (or when the accumulated `underlyings` is 0), symmetric to the `amount == 0` check [5](#0-4) .
- Additionally, in `fullfillWriteOffRequest`, require `currentRequest.underlyings != 0` and consider requiring the fulfiller to be the `borrower` or an allowlisted party if third-party fulfillment is not a strict requirement.

### Proof of Concept
Foundry fork-style PoC outline:

```solidity
// Assume: IdleCDOEpochVariant epoch running; victim holds tranche tokens.
IdleCreditVaultWriteOffEscrow escrow = ...;
IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
IERC20Detailed underlying = IERC20Detailed(escrow.underlying());

// 1. Victim creates a request depositing tranches but forgetting pricing (0 underlyings).
vm.startPrank(victim);
tranche.approve(address(escrow), victimTranches);
escrow.createWriteOffRequest(victimTranches, 0);
vm.stopPrank();

// 2. Attacker fulfiller front-runs and fulfills with 0 underlyings.
uint256 attackerTranchePre = tranche.balanceOf(attacker);
uint256 victimUnderlyingPre = underlying.balanceOf(victim);
vm.prank(attacker);
escrow.fullfillWriteOffRequest(victim, victimTranches, 0);

// 3. Attacker got all tranches for free; victim got nothing and the request is gone.
assertEq(tranche.balanceOf(attacker) - attackerTranchePre, victimTranches);
assertEq(underlying.balanceOf(victim) - victimUnderlyingPre, 0);
(uint256 t, uint256 u) = escrow.userRequests(victim);
assertEq(t, 0);
assertEq(u, 0);
```

Reproduces on a mainnet fork using the existing `test/foundry` harness style: start an epoch on an `IdleCDOEpochVariant` deployment, seed a KYC-passing lender with tranche tokens, then run steps 1–3.

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }
```

  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
  }
```

  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }
