### Title
`GlobalStateEvaluator::reached_agreement`/`reached_disagreement` compute the 70% threshold with floor rounding, diverging from the canonical ceil-rounded consensus threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The node/chainstate 70%-of-weight approval threshold used to gate an actual Nakamoto block signature (`NakamotoBlockHeader::compute_voting_weight_threshold`, and its mirrored copy used by the miner-side StackerDB listener and the pre-commit path in `stacks-signer/src/v0/signer.rs`) is computed with ceiling rounding, so it always requires *at least* `ceil(total_weight*7/10)` weight. The signer's `GlobalStateEvaluator`, which is used to determine "global agreement" among signers on burn-view, active-miner, protocol version, and the transaction-replay set, uses a different, floor-rounded formula for the same nominal 70% threshold. This creates two different thresholds for what is conceptually the same "supermajority" quantity in the same protocol.

### Finding Description
The canonical/consensus threshold, used by the chain to accept a block's aggregated signatures, is: [1](#0-0) 
which computes `ceil(total_weight * 7 / 10)` — e.g. for `total_weight = 511`, the threshold is `358` (verified by the existing unit test at [2](#0-1) ). This exact function is re-used consistently elsewhere in the signer/miner code path that actually gates whether a block gets signed/broadcast, e.g. in the miner-side listener at [3](#0-2)  and in the signer's own pre-commit/acceptance tallying at [4](#0-3)  and [5](#0-4) .

In contrast, `GlobalStateEvaluator::reached_agreement`, used to determine the signer network's *global state* (active miner, burn view, supported protocol version, and importantly the enforced transaction-replay set), computes the threshold with plain integer (floor) division instead of ceiling: [6](#0-5) 
For `total_weight = 511` this yields a threshold of `357` (floor of `357.7`), one unit lower than the canonical `358` used everywhere else for the same nominal "70%" concept. The companion `reached_disagreement` function has the analogous floor-rounding issue for the 30% blocking-minority side: [7](#0-6) 

`reached_agreement` gates `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and — critically — `determine_global_state`'s selection of the agreed `SignerStateMachine` (current miner / burn view) and the agreed `tx_replay_set`: [8](#0-7) 
and its exact-match/longest-common-prefix fallback logic in `find_majority_prefix_replay_set`: [9](#0-8) 

This means a set of colluding/malicious signers (or even honest signers reporting divergent-but-plausible state updates) holding, e.g., `357/511` weight — which is *below* the canonical `358/511` supermajority — can make every other honest signer's `GlobalStateEvaluator` conclude that "global agreement" on a particular `current_miner`, burn view, or `tx_replay_set` has been reached, when the real consensus-critical threshold used for block signing has not actually been met by that same weight. Because these `determine_global_*` calls only require inserting a `StateMachineUpdate` per signer address (gossip messages that any single signer set member can broadcast), and no majority of key material is needed to *produce* the update, a minority just below the true consensus threshold can trigger a state conclusion the true protocol threshold would reject. This is a direct analog of the reported bug class: two computations of nominally the same ratio, one rounded down and one rounded up, producing an exploitable equality mismatch between "declared/observed agreement" and "true consensus threshold."

### Impact Explanation
Reaching a false "global state" agreement based on the mis-computed threshold can steer signers' locally-tracked state machine (miner selection and, notably, the enforced `tx_replay_set`) using a weight that is one unit short of the real supermajority. Since `tx_replay_set` and `current_miner` feed directly into how a signer evaluates block proposals and casts its vote (validity/acceptance), a signer can be nudged into accepting or rejecting blocks based on a "consensus" state that does not actually meet the canonical 70% bar — i.e., an observed acceptance/agreement is recounted as met when it should not be. This falls under "a rejection/acceptance recounted incorrectly" / equality-break impact category (Critical), because it can lead a signer to act (sign, or refuse to sign) based on a falsely-declared global agreement.

### Likelihood Explanation
The discrepancy is only exploitable at specific weight totals where `floor(total_weight*7/10) < ceil(total_weight*7/10)`, i.e., whenever `total_weight*7` is not a multiple of `10` (the common case for most `total_weight` values, as shown by the round-up test case for `511`). No majority of signers or private-key compromise is required — only enough gossiped `StateMachineUpdate` weight to sit between the floor and ceil thresholds, which is a single weight-unit's worth of signers/stackers, well within reach of a modest minority.

### Recommendation
Change `reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use the same ceiling-rounding formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (or call that function directly) so that the signer's notion of "global agreement" threshold is identical, bit-for-bit, to the canonical consensus threshold used to gate block signing.

### Proof of Concept
For `total_weight = 511`:
- Canonical threshold (`compute_voting_weight_threshold`): `ceil(511*7/10) = 358` — confirmed by existing test [2](#0-1) .
- `GlobalStateEvaluator::reached_agreement(357)`: `357 >= floor(511*7/10) = floor(357.7) = 357` → `true`, at [10](#0-9) .

So with exactly `357` weight of gossiped `StateMachineUpdate`s (1 unit less than the canonical `358` supermajority), `determine_global_state` will report agreement on a `current_miner`/`tx_replay_set`, while the same weight would fail the canonical block-signing threshold check in `stackslib/src/chainstate/nakamoto/mod.rs`/`stacks-signer/src/v0/signer.rs`.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

    /// Find the longest common prefix of replay sets that has majority support.
    /// This implements the longest common prefix (LCP) strategy where if one signer's replay set
    /// is [A,B,C] and another is [A,B], we should use [A,B] as the replay set.
    /// Order matters for transaction replay - [A,B] and [B,A] have no common prefix.
    fn find_majority_prefix_replay_set(
        &self,
        tx_replay_sets: &HashMap<ReplayTransactionSet, u32>,
    ) -> Option<ReplayTransactionSet> {
        if tx_replay_sets.is_empty() {
            return None;
        }

        // First, try to find an exact match that reaches agreement
        for (replay_set, weight) in tx_replay_sets {
            if self.reached_agreement(*weight) {
                return Some(replay_set.clone());
            }
        }

        // No exact agreement found, find longest common prefix with majority support

        // Sort replay sets by weight (descending), then deterministically by length and content
        let mut sorted_sets: Vec<_> = tx_replay_sets.iter().collect();
        sorted_sets.sort_by(|(set_a, weight_a), (set_b, weight_b)| {
            // Primary: weight descending
            let weight_cmp = weight_b.cmp(weight_a);
            if weight_cmp != Ordering::Equal {
                return weight_cmp;
            }
            // Secondary: length descending (longer sequences first)
            let len_cmp = set_b.0.len().cmp(&set_a.0.len());
            if len_cmp != Ordering::Equal {
                return len_cmp;
            }
            // Tertiary: compare transaction IDs for determinism
            for (lhs, rhs) in set_a.0.iter().zip(&set_b.0) {
                let ord = lhs.txid().cmp(&rhs.txid());
                if ord != Ordering::Equal {
                    return ord;
                }
            }
            Ordering::Equal
        });

        // Start with the most supported replay set as initial candidate
        if let Some((initial_set, _)) = sorted_sets.first() {
            let mut candidate_prefix = initial_set.0.clone();
            let mut total_supporting_weight = 0u32;

            // Find all sets that support the current candidate prefix
            for (replay_set, weight) in tx_replay_sets {
                if replay_set.0.starts_with(&candidate_prefix) {
                    total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                }
            }

            // If the initial candidate already has majority support, return it
            if self.reached_agreement(total_supporting_weight) {
                return Some(ReplayTransactionSet::new(candidate_prefix));
            }

            // Otherwise, iteratively truncate the prefix until we find majority support
            while !candidate_prefix.is_empty() {
                // Remove the last transaction from the prefix
                candidate_prefix.pop();

                // Recalculate supporting weight for the shorter prefix
                total_supporting_weight = 0u32;
                for (replay_set, weight) in tx_replay_sets {
                    if replay_set.0.starts_with(&candidate_prefix) {
                        total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                    }
                }

                // If this prefix has majority support, return it
                if self.reached_agreement(total_supporting_weight) {
                    return Some(ReplayTransactionSet::new(candidate_prefix));
                }
            }
        }

        // If no common prefix with majority support is found, return None
        None
    }
