### Title
Unbounded rooted-slot traversal in `RpcClient::get_blocks` due to `filter` (not `take_while`) on `Blockstore::rooted_slot_iterator` - ([File: rpc/src/rpc.rs])

### Summary
`JsonRpcRequestProcessor::get_blocks` bounds only `end_slot - start_slot` via `MAX_GET_CONFIRMED_BLOCKS_RANGE`, but the actual slot collection uses `.filter(|&slot| slot <= end_slot && ...)` on the iterator returned by `Blockstore::rooted_slot_iterator`, instead of `.take_while(...)`. Because `Iterator::filter` never terminates early on predicate failure, a single `getBlocks` call with an old `start_slot` forces `RootedSlotIterator::next` to walk every rooted slot from `start_slot` up to the validator's current chain tip, fetching a `SlotMeta` from RocksDB and cloning its `NextSlots` for each one, regardless of how small the requested `[start_slot, end_slot]` range is.

### Finding Description
`JsonRpcRequestProcessor::get_blocks` computes `end_slot` and rejects requests where `end_slot - start_slot > MAX_GET_CONFIRMED_BLOCKS_RANGE` [1](#0-0) . This check only limits the *width* of the requested range, not the number of live rooted slots that must be traversed to reach it. The finalized-block collection then does:

```rust
let mut blocks: Vec<_> = self
    .blockstore
    .rooted_slot_iterator(max(start_slot, lowest_blockstore_slot))
    .map_err(|_| Error::internal_error())?
    .filter(|&slot| slot <= end_slot && slot <= highest_super_majority_root)
    .collect();
``` [2](#0-1) 

`Iterator::filter` combined with `.collect()` repeatedly calls `.next()` on the `Filter` adapter, which internally loops on the underlying iterator (equivalent to `find()`) until a match is found or the underlying iterator returns `None`. Since `RootedSlotIterator` yields monotonically increasing slots, once the traversal passes `end_slot` every subsequent item also fails the predicate — but the loop does not stop there; it must keep pulling from the underlying `RootedSlotIterator` until *that* iterator itself is exhausted, which only happens at the current chain tip [3](#0-2) . Each such pull to `RootedSlotIterator::next` performs a `blockstore.is_root` check, a `blockstore.meta()` RocksDB fetch, and a clone of the `NextSlots` `SmallVec` [4](#0-3) .

Consequently, a request with `start_slot = 0` (or any old slot) and a small, range-legal `end_slot` (e.g., `start_slot + MAX_GET_CONFIRMED_BLOCKS_RANGE`) still causes the RPC thread to synchronously iterate and clone/fetch metadata for every rooted slot from `start_slot` all the way to `highest_super_majority_root` — not just the requested window — because the `filter` never short-circuits. There is no `take_while` or explicit break once `slot > end_slot` is observed.

This is reachable by an unprivileged client with a single `getBlocks(start_slot, end_slot)` JSON-RPC call, and no existing guard (commitment check, `MAX_GET_CONFIRMED_BLOCKS_RANGE`, or `lowest_blockstore_slot` check) prevents it, since none of them bound the number of rooted slots between `start_slot` and the current tip.

### Impact Explanation
A single unprivileged RPC call can force the validator's JSON-RPC processing to perform O(N) RocksDB lookups and SmallVec clones, where N is the number of rooted slots between the (attacker-chosen, arbitrarily old) `start_slot` and the current `highest_super_majority_root` — potentially millions of slots on a long-lived validator with a full rooted chain from genesis. This violates the bounded-cost-per-request invariant and matches the "unbounded cost for a single low-rate call" RPC DoS category: the call ties up an RPC worker thread and generates sustained CPU/IO/memory load proportional to total chain height rather than to the requested/allowed range.

### Likelihood Explanation
Fully feasible with no privileges: the attacker needs only to call `getBlocks` (or `getBlocksWithLimit`, which has the analogous pattern) once, with `start_slot` set far below the current root, on any long-running validator/RPC node that has accumulated a large, unbroken rooted chain (the normal, expected state of a mature validator). It requires no on-chain writes, no gossip/peer access, and is well within the "one call per `CLUSTER_SLOT_TIME_TARGET / 2`" constraint since it's a single request.

### Recommendation
Replace the `.filter(...)` with a `.take_while(|&slot| slot <= end_slot && slot <= highest_super_majority_root)` (or an explicit loop that breaks once `slot > end_slot`), so the underlying `RootedSlotIterator` is only advanced across the requested `[start_slot, end_slot]` window rather than to the chain tip.

### Proof of Concept
Integration test plan (Rust, in `rpc/src/rpc.rs` test module or `ledger` tests):
1. Build a `Blockstore` with a long unbroken rooted chain from slot 0 to slot `N` (e.g., `N = 1_000_000`) using `fill_blockstore_slot_with_ticks` + `set_roots`, mirroring the existing `test_rooted_slot_iterator` setup [5](#0-4) .
2. Construct a `JsonRpcRequestProcessor` (or directly call `Blockstore::rooted_slot_iterator(0)` chained with the same `.filter` pattern used in `get_blocks`) and issue a request with `start_slot = 0`, `end_slot = Some(MAX_GET_CONFIRMED_BLOCKS_RANGE)` (a small, range-legal value far less than `N`).
3. Instrument/count calls to `Blockstore::meta` (or wrap it) and assert that the number of `meta()` invocations is bounded by `end_slot - start_slot + 1`, **not** by `N`.
4. Expected (buggy) result: the call count / wall-clock time scales with `N` (chain tip), not with the small requested range, demonstrating the unbounded-cost defect. After applying the `take_while` fix, the same test should show call count bounded by `end_slot - start_slot + 1`.

impl Iterator for RootedSlotIterator<'_> {
    type Item = (Slot, Option<SlotMeta>);

    fn next(&mut self) -> Option<Self::Item> {
        // Clone b/c passing the closure to the map below requires exclusive access to
        // `self`, which is borrowed here if we don't clone.
        let (rooted_slot, slot_skipped) = self
            .next_slots
            .iter()
            .find(|x| self.blockstore.is_root(**x))
            .map(|x| (Some(*x), false))
            .unwrap_or_else(|| {
                let mut iter = self
                    .blockstore
                    .rooted_slot_iterator(
                        // First iteration the root always exists as guaranteed by the constructor,
                        // so this unwrap_or_else cases won't be hit. Every subsequent iteration
                        // of this iterator must thereafter have a valid `prev_root`
                        self.prev_root,
                    )
                    .expect("Database failure, couldn't fetch rooted slots iterator");
                iter.next();
                (iter.next(), true)
            });

        let slot_meta = rooted_slot
            .map(|r| {
                self.blockstore
                    .meta(r)
                    .expect("Database failure, couldn't fetch SlotMeta")
            })
            .unwrap_or(None);

        if let Some(ref slot_meta) = slot_meta {
            self.next_slots.clone_from(&slot_meta.next_slots);
        }

        if slot_meta.is_none() && slot_skipped {
            warn!("Rooted SlotMeta was deleted in between checking is_root and fetch");
        }

        rooted_slot.map(|r| {
            self.prev_root = r;
            if slot_skipped {
                (r, None)
            } else {
                (r, slot_meta)
            }
        })
    }

               /     |

        // Fork 1, ending at slot 3
        let last_entry_hash = Hash::default();
        let fork_point = 1;
        let mut fork_hash = Hash::default();
        for slot in 0..=3 {
            let parent = { if slot == 0 { 0 } else { slot - 1 } };
            let last_entry_hash = fill_blockstore_slot_with_ticks(
                &blockstore,
                ticks_per_slot,
                slot,
                parent,
                last_entry_hash,
            );

            if slot == fork_point {
                fork_hash = last_entry_hash;
            }
        }

        // Fork 2, ending at slot 4
        let _ =

            .unwrap()

            .collect();

    }
