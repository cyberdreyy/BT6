### Title
Paused deposits are bypassed via `depositDuringEpoch` - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
The epoch-variant CDO gates ordinary deposits behind `whenNotPaused` inside `_deposit` (`contracts/IdleCDO.sol:234`, `contracts/IdleCDOEpochVariant.sol:644`), but the parallel deposit entrypoint `depositDuringEpoch` (`contracts/IdleCDOEpochVariant.sol:656`) enforces only its own flag/KYC checks and never checks `paused()`. When the contract is paused while an epoch is running (a state the code permits — `_beforeUnpause` at line 635 blocks unpausing during an epoch, and nothing blocks pausing during one), a KYC'd attacker can still deposit, mint tranche tokens at the discounted mid-epoch price, and push fresh funds to the borrower.

### Finding Description
`depositDuringEpoch` reverts only on: BB deposits disabled, `isDepositDuringEpochDisabled`, `skipDefaultCheck`, programmable borrower, AYS active, epoch not running / `epochEndDate` passed, or wallet not allowed (lines 658-669). `paused()` is absent. It then mints shares with `_minted = (_amount + trancheInterest) * _trancheTotSupply / expectedFinal` (line 724) — i.e., it grants shares backed by *expected future interest* that only materializes if the borrower repays — calls `mintStrategyTokens`, and forwards the underlyings to the borrower (lines 728-732).

This mirrors the reported EigenLayer issue exactly: the pause bit is checked on the "primary" path (`_deposit`/`deregisterOperator`) but a second public entrypoint reaches the same effect without the pause check.

### Impact Explanation
Pause is the emergency brake used to halt user fund flows when something is wrong — e.g., the guardian/owner suspects borrower insolvency or mispriced epoch interest but cannot yet prove default (a `stopEpoch`/default path sets `skipDefaultCheck`, which *does* block this function; a bare `pause()` does not). In that window the attacker deposits `X` underlying and mints `X + trancheInterest` worth of tranche tokens (line 724). If the borrower then fails to repay, the interest portion of the minted shares is unbacked and the loss is socialized across honest tranche holders — direct dilution/theft quantified by `trancheInterest` per deposit, plus forced exposure of attacker funds now locked in the borrower. Even absent default, the pause's protective intent (freeze state) is defeated: accounting, `expectedEpochInterest`, and borrower balances change while frozen.

### Likelihood Explanation
Requires: (a) mid-epoch deposits enabled (`isDepositDuringEpochDisabled` is `true` by default, line 86, but owners enable it for pools that want rolling liquidity), (b) fixed-APR, non-AYS, non-programmable mode, (c) an honest pause during a running epoch, and (d) attacker passing `isWalletAllowed` KYC (explicitly an allowed attacker class). No privileged action by the attacker is needed; timing is the only constraint.

### Recommendation
Add `paused()` to the `_checkNotAllowed` condition in `depositDuringEpoch` (line 658), or refactor so both `_deposit` and `depositDuringEpoch` funnel through a single internal function that performs the pause check once — the same fix as checking the pause bit inside the internal `_deregister` in the source report.

### Proof of Concept
Foundry fork PoC sketch:

```solidity
// Setup: epoch CDO, fixed APR, isDepositDuringEpochDisabled=false, KYC'd attacker.
// 1. Honest user deposits during buffer; owner calls startEpoch() -> isEpochRunning = true.
// 2. Guardian/owner calls pause() (suspected borrower trouble) -> paused() == true.
// 3. Attacker: cdo.depositAA(amount) -> reverts (whenNotPaused in _deposit).  // control
// 4. Attacker: cdo.depositDuringEpoch(amount, AATranche) -> SUCCEEDS.
//    - minted = (amount + trancheInterest) * supply / expectedFinal  (> amount at price 1)
//    - underlyings forwarded to borrower, expectedEpochInterest increased.
// 5. Simulate borrower non-repayment; attacker redeems/holds shares minted partly
//    against unbacked expected interest -> honest holders' NAV diluted by trancheInterest.
assertGt(minted, amount * 1e18 / priceAA); // attacker minted above current price
```

Key unchecked assumptions (couldn't fully verify in remaining budget): whether `pause()` during a running epoch is reachable in deployed configs, and the exact quantification of `trancheInterest` — both are straightforward to confirm in the PoC.
