### Title
Zip-slip in `ExtractZipArchive` allows unprivileged CI job to `os.Lchown` arbitrary host paths via traversal `file.Name` + `0x7875` UID/GID extra field - (File: helpers/archives/zip_extra_unix.go)

### Summary
`archives.ExtractZipArchive` extracts every `zip.File` entry using its raw, attacker-supplied `file.Name` with no path sanitization (no `filepath.Clean`/`..`-rejection/root-containment check), only guarding against `.git` paths. Because `processZipExtra` -> `processZipUIDGidField` subsequently calls `os.Lchown(file.Name, UID, Gid)` using that same unsanitized name, a crafted cache/artifact zip with a traversal path (e.g. `../../../../shared-volume/svc-account-file`) plus a `0x7875` extra field lets an unprivileged job change ownership of a file outside the job workspace to attacker-chosen UID/GID.

### Finding Description
`ExtractZipArchive` [1](#0-0)  iterates `archive.File` entries and calls `extractZipFile(file)` using `file.Name` directly for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.Mkdir`, `os.Symlink`, and `os.OpenFile` [2](#0-1) . The only path-related guard is `errorIfGitDirectory`, which merely checks whether the first path component is `.git`, and logs a warning rather than blocking extraction [3](#0-2) . There is no `filepath.Clean`, no rejection of `..` segments, and no verification that the resolved path stays under the extraction root.

In the second pass, `ExtractZipArchive` calls `processZipExtra(&file.FileHeader)` [4](#0-3) , which parses attacker-controlled `Extra` bytes and, for a `0x7875` field, calls `processZipUIDGidField(data, file)` [5](#0-4) . That function decodes the attacker-supplied UID/GID and calls `os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))` directly on the unsanitized `file.Name` [6](#0-5) .

Because file extraction with a traversal name (e.g. `../../../../shared-volume/svc-account-file`) will, if the target path/parent already exists on the host (or is creatable), write/overwrite that file and set attacker-chosen ownership on it via `Lchown`, this violates the "file operations must stay within intended build/cache/artifact roots" invariant. This code path is reachable from `ExtractZipFile` [7](#0-6)  and from the cache/artifact legacy zip extractor `ziplegacy.extractor.Extract`, which calls `archives.ExtractZipArchive(zr)` directly on job-supplied archive bytes [8](#0-7) .

### Impact Explanation
An unprivileged pipeline author who controls cache/artifact zip contents can chown an arbitrary host-reachable path (relative to the extraction working directory, e.g. escaping into a shared volume mounted into the job container) to an attacker-chosen UID/GID. This is a genuine ownership-manipulation primitive outside the job root, matching the scoped impact of "unauthorized ownership change enabling privilege confusion for a subsequently-run process bound to that UID/GID" — but note actual severity is bounded by executor isolation: in Docker/Kubernetes executors the traversal target is confined to whatever filesystem is visible/writable inside the job's own container mount namespace (typically no meaningful external escape), whereas in the shell executor on a shared host this could reach genuinely shared paths.

### Likelihood Explanation
Feasibility is high and fully attacker-controlled: crafting a zip with a `..`-containing `file.Name` and a `0x7875` extra field requires no special privilege, only the ability to author a cache/artifact archive consumed by the runner (e.g. via `.gitlab-ci.yml` cache/artifacts config or job-controlled build steps that produce an archive later restored). The write must also succeed against normal OS permission checks (the job process's effective UID must have write access to the traversal target), and any parent directories must exist or be creatable via `os.MkdirAll`, so the exploitable blast radius is constrained to paths the job's own process UID already can write to — reducing, but not eliminating, real-world impact since many CI executors run job processes as root or with broad filesystem access inside their container/host.

### Recommendation
Sanitize every `file.Name` before use in `extractZipFile`, `lchmod`, and `processZipExtra`/`processZipUIDGidField`: reject entries whose cleaned path is absolute or contains `..` segments that escape the intended extraction root, or resolve the destination via `filepath.Join(destRoot, file.Name)` and verify with `filepath.Rel`/prefix-check that the result stays within `destRoot` before performing any `Mkdir`, `OpenFile`, `Symlink`, `Chtimes`, or `Lchown` operation; fail (not warn-and-continue) the extraction of such entries.

func TestExtractZipArchive_ZipSlipLchown(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir() // simulate "shared-volume" outside intended root
    outsideFile := filepath.Join(outsideDir, "svc-account-file")
    require.NoError(t, os.WriteFile(outsideFile, []byte("preexisting"), 0o644))
    infoBefore, _ := os.Stat(outsideFile)
    statBefore := infoBefore.Sys().(*syscall.Stat_t)

    // Build malicious entry with traversal name relative to tmpDir
    relTraversal, _ := filepath.Rel(tmpDir, outsideFile) // e.g. "../../.../svc-account-file"

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    hdr := &zip.FileHeader{Name: relTraversal, Method: zip.Store}
    ugField := ZipUIDGidField{Version: 1, UIDSize: 4, UID: 1234, GIDSize: 4, Gid: 1234}
    var extra bytes.Buffer
    _ = binary.Write(&extra, binary.LittleEndian, &ZipExtraField{Type: ZipUIDGidFieldType, Size: uint16(binary.Size(&ugField))})
    _ = binary.Write(&extra, binary.LittleEndian, &ugField)
    hdr.Extra = extra.Bytes()
    w, _ := zw.CreateHeader(hdr)
    _, _ = w.Write([]byte("evil"))
    _ = zw.Close()

    prevWd, _ := os.Getwd()
    _ = os.Chdir(tmpDir)
    defer os.Chdir(prevWd)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    _ = ExtractZipArchive(zr) // pre-fix: succeeds, no error blocking traversal

    infoAfter, _ := os.Stat(outsideFile)
    statAfter := infoAfter.Sys().(*syscall.Stat_t)

    // Pre-fix this assertion fails: ownership was changed to attacker UID/GID.
    assert.Equal(t, statBefore.Uid, statAfter.Uid, "ownership outside root must not change")
    assert.Equal(t, statBefore.Gid, statAfter.Gid, "ownership outside root must not change")

Expected: on the vulnerable code, the traversal path resolves outside `tmpDir`, the file's content is overwritten and its UID/GID become `1234`/`1234`, causing the assertions to fail — demonstrating the bug. 	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {

		}
	}

	return nil
}

func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
