### Title
Stale confirmations from removed members are still counted toward the multisig execution threshold - (`multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` executes a request once `confirmations.len() as u32 + 1 >= self.num_confirmations`, where `confirmations` is a `HashSet<String>` keyed by member identity [2](#0-1) . `delete_member` only purges confirmations for requests that were *created* by the removed member; it never scans other pending requests to strip that member's existing confirmation entries [1](#0-0) . As a result, a confirmation given by a member while they were still part of the multisig remains in the tally after that member is removed, letting a request execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
The intended custody binding is: `confirmations counted == confirmations from current live members`, i.e. a request should only execute once `num_confirmations` *current* members have approved it.

`add_request` creates an empty `HashSet<String>` in `self.confirmations` for the new request [3](#0-2) . Any current member can call `confirm`, which inserts their identity string into that set, or executes the request once the size threshold is met [2](#0-1) .

`delete_member` is the only place membership changes are reconciled against outstanding state. It removes requests *authored by* the deleted member and clears their `num_requests_pk` entry, but it does not iterate `self.confirmations` to remove the deleted member's identity from confirmation sets belonging to *other* members' requests:
```rust
fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
    ...
    let request_ids: Vec<u32> = self
        .requests
        .iter()
        .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
        .collect();
    for request_id in request_ids {
        self.confirmations.remove(&request_id);
        self.requests.remove(&request_id);
    }
    self.num_requests_pk.remove(&member.to_string());
    self.members.remove(&member);
    ...
}
``` [4](#0-3) 

So any confirmation the removed member left on a request created by *someone else* survives untouched in `self.confirmations`, and continues to count toward `num_confirmations` in the `confirm` check [5](#0-4) .

Before/after the removal call:
- Before: `confirmations[R] = {A}`, live members = `{A, B, C}`, `num_confirmations = 2`. `A`'s confirmation is valid because `A` is live.
- After `delete_member(A)` executes: `members = {B, C}`, but `confirmations[R]` is untouched and still `= {A}`.
- Now `B.confirm(R)` computes `confirmations.len() as u32 + 1 == 2 >= num_confirmations(2)`, and `R` executes — even though only one *live* member (`B`) ever approved it.

### Impact Explanation
This lets a multisig request execute below the effective live-member threshold — a removed member's stale approval substitutes for a live one. Since `MultiSigRequestAction` includes `Transfer`, `DeployContract`, `AddKey`/`AddMember`, and `FunctionCall` [6](#0-5) , this can result in NEAR transfers, contract redeployments, or new access-key/member grants being authorized with fewer genuine current-member confirmations than intended, i.e. "a multisig request executed below threshold" (Critical).

### Likelihood Explanation
Requires: (1) a request pending confirmation, partially confirmed by a member who is later removed, and (2) the remaining members confirming without noticing the stale entry. Membership removal via `DeleteMember` is a normal multisig operation (e.g. rotating out a departing signer or a compromised key), so the precondition is realistic and doesn't require any single privileged/malicious actor at exploit time — the vulnerable state arises from ordinary multisig lifecycle operations combined with pending requests.

### Recommendation
In `delete_member` (and the analogous `DeleteKey` handling in the legacy `multisig/src/lib.rs`), iterate all entries in `self.confirmations` and remove the departing member's identity from every set, not just requests they authored. Alternatively, recompute confirmation validity at `confirm`-time by filtering the stored confirmation set against `self.members` before comparing its length to `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new([A, B, C], 2)`.
2. `A` calls `add_request(R)` then `confirm(R)` → `confirmations[R] = {A}`.
3. Members execute a separate, fully-confirmed `DeleteMember{A}` request → `delete_member` runs, removing `A` from `members`, but `confirmations[R]` remains `{A}` since `R` was not authored by `A`.
4. `B` calls `confirm(R)` → `confirmations.len() as u32 + 1 == 2 >= num_confirmations (2)` → `execute_request(R)` runs with only one live confirmation (`B`), fulfilling the threshold using `A`'s stale, now-invalid approval.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {

                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());

                    args.into(),
                    deposit.into(),
                    Gas::from(gas.0),

                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {

                    return PromiseOrValue::Value(true);

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,

            self.requests.remove(&request_id);

        }
