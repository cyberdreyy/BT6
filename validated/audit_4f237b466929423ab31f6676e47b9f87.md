### Title
Zip cache/artifact extraction (`ExtractZipArchive`) has no path-containment check, unlike `tarzstd`'s extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`archives.ExtractZipArchive` writes every zip entry using the raw `file.Name` from the archive (`os.Mkdir`, `os.Symlink`, `os.OpenFile`) with no `filepath.Join` against a base directory and no check that the resolved path stays inside any root. By contrast, `tarzstd`'s `extractor.Extract` explicitly computes `path = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it unless it has the `e.dir` prefix. Since `CACHE_COMPRESSION_FORMAT`/format selection for cache/artifact extraction is attacker-influenceable via job variables, choosing the zip path removes an existing, format-specific containment control.

### Finding Description
- `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`'s `extractor.Extract` accepts a `dir` field (set from `NewExtractor(r, size, dir)`), but that field is never used — it calls `archives.ExtractZipArchive(zr)` directly, dropping `dir` entirely. [1](#0-0) 
- `archives.ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)`, which uses `file.Name` unmodified for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.Mkdir(file.Name, ...)`, `os.Symlink(..., file.Name)`, and `os.OpenFile(file.Name, ...)` — no join with a caller-supplied base directory, no `filepath.Abs`, and no prefix check. [2](#0-1) 
- In contrast, `tarzstd`'s extractor computes an absolute path relative to `e.dir` and explicitly rejects any entry whose resolved path escapes `e.dir` via `strings.HasPrefix(path, e.dir+separator)`. [3](#0-2) 
- `archive.NewExtractor(format, r, size, dir)` is format-generic and routes to whichever extractor is registered for the format, meaning the containment guarantee is entirely dependent on which extractor implementation is invoked, not on any shared/central check. [4](#0-3) 
- `CACHE_COMPRESSION_FORMAT` is a job-settable environment/CLI flag on `CacheArchiverCommand.CompressionFormat` (`env:"CACHE_COMPRESSION_FORMAT"`), confirming this is attacker-influenceable input from job configuration (used for the archiver side; the corresponding extractor command resolves format symmetrically for extraction, per the `archive.Format` abstraction). [5](#0-4) 
- The only protections present in the zip path are `errorIfGitDirectory` (blocks `.git` directory entries) and a warning-suppression tracker (`newPathErrorTracker`) — neither of these validates path containment or rejects `../` traversal or absolute paths. [6](#0-5) 

Exploit flow: an attacker who can influence `CACHE_COMPRESSION_FORMAT` (or otherwise cause the zip extraction path to be selected) supplies a cache archive containing an entry with a relative path such as `../../etc/cron.d/evil` or an absolute path. When routed through `ziplegacy`/`archives.ExtractZipArchive`, the file is written wherever `file.Name` resolves relative to the process's current working directory (or as an absolute path if `file.Name` is absolute, since none of these os.* calls forbid absolute paths), with no containment check — whereas the same content through `tarzstd` would be rejected with `"cannot be extracted outside of chroot"`.

### Impact Explanation
This is a path-traversal / arbitrary file write during cache (and correspondingly artifact, if zip is used there too) extraction. An attacker-crafted cache archive selected with the zip format can write files outside the intended build/cache directory on the job's filesystem (subject to executor sandboxing and file permissions), which violates the invariant that "file operations must stay within intended build/cache/artifact roots." The severity is bounded by whatever host/container permissions the runner process has, but the containment control itself is bypassable purely by format choice for identical malicious archive content.

### Likelihood Explanation
This is trivially reachable by any pipeline author: they only need to (a) cause cache/artifact extraction to use the zip codepath (default zip format is already the fallback in `createZipFile`'s `default:` case, and `CACHE_COMPRESSION_FORMAT` is user-settable) and (b) supply a malicious cache archive containing traversal-crafted entry names, which is fully attacker-controlled since the cache content originates from job-controlled files/paths. No special privileges are required beyond normal job authorship. The bug is deterministic and 100% repeatable.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go` / `ExtractZipArchive`: thread the target base directory through `ExtractZipArchive`/`ExtractZipFile`, compute `path := filepath.Abs(filepath.Join(dir, file.Name))` for every entry, and reject any entry where `path` does not have `dir+string(filepath.Separator)` as a prefix (and isn't equal to `dir`), returning an error instead of extracting. Apply the same fix to `extractZipSymlinkEntry`'s symlink target validation to prevent symlink-based escapes as well. Ensure `ziplegacy.extractor.Extract` actually passes and uses its `dir` field instead of discarding it.

```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideMarker := filepath.Join(filepath.Dir(tmpDir), "pwned_by_zip")
    defer os.Remove(outsideMarker)

    // Build a malicious zip in memory with an entry that escapes tmpDir.
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../pwned_by_zip")
    _, _ = w.Write([]byte("evil"))
    _ = zw.Close()

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    origWd, _ := os.Getwd()
    _ = os.Chdir(tmpDir)
    defer os.Chdir(origWd)

    err = archives.ExtractZipArchive(zr)
    // Compare against tarzstd behavior: tarzstd's extractor.Extract() would return
    // an error like "cannot be extracted outside of chroot".
    // For zip, assert the traversal actually occurred (proving the missing guard):
    _, statErr := os.Stat(outsideMarker)
    assert.NoError(t, statErr, "file was written outside the intended directory via zip extraction")
}
```
This test demonstrates that identical traversal content that `tarzstd_extractor.go` (lines 56-64) would reject is instead written outside the target directory when extracted through `archives.ExtractZipArchive`, confirming the format-dependent containment gap.

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
