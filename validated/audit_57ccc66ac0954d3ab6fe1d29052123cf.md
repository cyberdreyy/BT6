## Analog Found: Griefing DoS in `vesting::distribute` / `staking_contract::distribute_internal` via one recipient's `DirectTransferConfig`

### Title
Single malicious shareholder can permanently block reward/vesting distribution to all other shareholders in `vesting::distribute` - (`aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
The external report's root cause is a shared, atomic "push" payout loop where one recipient's forced revert aborts the whole transaction, denying funds to everyone (including the innocent counter-party) and permanently trapping the associated debt/stake. The same pattern exists in Aptos's `vesting::distribute` (and, more narrowly, in `staking_contract::distribute_internal`), both of which iterate over multiple shareholders in a single atomic transaction and call `aptos_account::deposit_coins`, which can be made to abort by any shareholder controlling their own account state.

### Finding Description
`vesting::distribute` withdraws all currently-withdrawable stake for a vesting contract and pays every shareholder in one loop: [1](#0-0) 

Each payout goes through `aptos_account::deposit_coins`, which, for a recipient account that is not yet registered for the coin type, checks `can_receive_direct_coin_transfers` and **aborts** if the account has opted out of arbitrary coin transfers: [2](#0-1) 

`can_receive_direct_coin_transfers` is controlled entirely by the recipient via the unprivileged, publicly-callable `set_allow_direct_coin_transfers`: [3](#0-2) 

Any shareholder — including one who is otherwise a completely legitimate, unprivileged participant in the vesting contract — can therefore:
1. Ensure their account has no `CoinStore`/primary store registered for the distributed `CoinType`.
2. Call `set_allow_direct_coin_transfers(&signer, false)` on their own account.
3. Wait to be included as a shareholder in `vesting_contract.grant_pool` (this is set by the admin at contract creation and cannot be changed afterward per the module's own admin-flow documentation) or in a `staking_contract`'s `distribution_pool` (which is populated by any unlock/commission accrual event, not by opt-in).

Once armed, any subsequent call to `distribute(contract_address)` (a `public entry` function callable by *anyone*, per its own doc comment "Allow anyone to distribute already unlocked funds") aborts inside the `for_each_ref` loop over all shareholders as soon as it reaches the malicious address: [4](#0-3) 

The identical push-payment-in-a-shared-loop structure also exists in `staking_contract::distribute_internal`, which iterates `distribution_pool.shareholders()` (staker + operator/beneficiary) and calls `aptos_account::deposit_coins` for each: [5](#0-4) 

This exactly mirrors the external report's bug class: a payment made via unconditional push inside a shared/looped payout path, where a receiver-controlled abort condition (there: a reverting fallback/blacklist; here: `DirectTransferConfig.allow_arbitrary_coin_transfers = false` combined with no prior coin registration) causes the entire transaction — and thus payouts owed to *other, non-malicious* parties — to permanently fail, with no pull-based fallback or per-recipient isolation.

### Impact Explanation
- In `vesting::distribute`, one malicious shareholder can permanently prevent unlocking/withdrawal of vested stake and rewards for **all other shareholders** of the same vesting contract, since `distribute()` (and hence `withdraw_stake`/`terminate_vesting_contract`, which calls `distribute` first) will always abort at that shareholder's iteration.
- Because Move has no try/catch and the loop makes an unconditional deposit call, there is no way to skip the poisoned recipient and continue; the coins remain locked in the vesting contract's account indefinitely, and the vesting contract's forward progress (subsequent `vest()`/`distribute()` calls) is blocked as unlocked stake keeps accumulating in a state that can never be flushed to shareholders.
- The equivalent path in `staking_contract::distribute_internal` affects at least the staker/operator pair sharing a single stake pool; a malicious staker (or beneficiary) can block their own operator's commission payout, or vice versa.
- This satisfies the "Permanent lock or non-recoverable loss of claim rights in stake, delegation, commission, beneficiary, or vesting flows" and "share-accounting corruption that... traps value" criteria, since the accrued distribution amounts are computed and would be deducted from the pool's shares but the coins can never actually be moved out via the only exposed entry point.

### Likelihood Explanation
The precondition (calling `set_allow_direct_coin_transfers(false)` and avoiding prior coin registration) is fully unprivileged and requires no special role — any account address that is designated a shareholder by the vesting admin, or that becomes staker/operator in a staking contract, can trigger this at any time before the first `distribute()` call. The `distribute` function itself is intentionally `public entry` and callable by anyone, so the malicious shareholder does not even need to be the one triggering the call — it fires automatically for whichever caller invokes `distribute`/`vest`/`terminate_vesting_contract`/`admin_withdraw` (all of which internally call `distribute`).

### Recommendation
- Replace the atomic push-loop in `vesting::distribute` and `staking_contract::distribute_internal` with a pull-based model: credit each shareholder's owed amount into a per-account claimable ledger, and let each shareholder withdraw independently via their own transaction.
- If a push model must be kept, wrap each individual `aptos_account::deposit_coins` call so that a failure for one recipient does not abort the whole loop — e.g., skip a recipient whose deposit would fail (based on `can_receive_direct_coin_transfers` combined with registration status) and route their share into a separately claimable holding balance instead of aborting the entire distribution.

### Proof of Concept
1. Shareholder `S` is added to a vesting contract's `grant_pool` by the admin via `create_vesting_contract` (unprivileged from `S`'s perspective — no consent is required to be listed).
2. Before any rewards/vesting periods unlock, `S` calls `aptos_account::set_allow_direct_coin_transfers(S_signer, false)` and never registers/receives `AptosCoin` directly so `coin::is_account_registered<AptosCoin>(S)` is false.
3. Time passes; rewards accrue and `vest()`/`unlock_rewards()` unlock stake into the pending_inactive/inactive state.
4. Anyone calls `vesting::distribute(contract_address)`.
5. The `for_each_ref` loop over `grant_pool.shareholders()` reaches `S`, calls `aptos_account::deposit_coins(S, ...)`, which hits the `assert!(can_receive_direct_coin_transfers(to), ...)` check at [6](#0-5)  and aborts.
6. The entire `distribute` transaction reverts — no shareholder (including honest ones) receives their share, and this repeats for every future call to `distribute`, `terminate_vesting_contract`, or `admin_withdraw` until `S`'s config is somehow reversed (which `S` unilaterally controls and has no incentive to do).

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
    /// receive.
    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
