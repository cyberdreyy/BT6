### Title
Stale confirmations from removed multisig members allow a request to execute below the live-member threshold - (File: multisig2/src/lib.rs)

### Summary
`confirm()` executes a pending request once `confirmations.len() + 1 >= num_confirmations`, but `delete_member()` only purges requests that were *created* by the removed member — it never scans the `confirmations` map to strip that member's votes from other members' pending requests. A confirmation cast by a member who is later removed therefore keeps counting toward the threshold on any request they confirmed but did not create, letting a request execute with fewer live approvals than `num_confirmations` requires.

### Finding Description
The invariant the contract is supposed to maintain is:

`confirmations.len() (executed request) == number of currently-live members who approved it`

`confirm()` checks this purely by set cardinality: [1](#0-0) 

`delete_member()` is the only place that cleans up state when a member is removed, and it filters requests by `r.member == member`, i.e. only requests that member originally *created* via `add_request`: [2](#0-1) 

Nothing iterates `self.confirmations` (a `LookupMap<RequestId, HashSet<String>>`) to remove the departing member's entry from requests created by *other* members. The threshold check at member-removal time only guarantees `members.len() - 1 >= num_confirmations`, i.e. that there are still enough total members — it says nothing about existing stale confirmations already stored for pending requests: [3](#0-2) 

So a confirmation recorded by member B on request R (created by A) survives B's removal, and continues to count when a later, still-live member confirms R.

### Impact Explanation
This breaks the "a multisig request executed below threshold" custody binding explicitly called out as Critical: a request can execute a `Transfer`, `AddKey`, `AddMember`/`DeleteMember`, `FunctionCall`, etc. having received strictly fewer than `num_confirmations` approvals from members who are actually part of the multisig at execution time. This can be used to move NEAR or add/delete keys/members with an effectively lower approval bar than configured, defeating the K-of-N guarantee that is the entire purpose of the contract.

### Likelihood Explanation
No privileged actor is required. Any set of members that includes one member who will later be removed can pre-position: have the soon-to-be-removed member confirm a request early (a normal, permitted action), then have that member removed through a legitimate `DeleteMember` execution, and finally obtain one fewer live confirmation than `num_confirmations` to trigger execution. This only requires ordinary multisig member actions already exposed by the contract's public API (`add_request`, `confirm`, and a `DeleteMember` request), no owner/foundation/redeploy assumption, and no interaction with external contracts.

### Recommendation
When removing a member in `delete_member()`, iterate all pending requests' confirmation sets (not just requests created by that member) and remove the departing member's entry from each. Alternatively, when counting confirmations in `confirm()`, filter the stored confirmation set down to entries that are still `self.members.contains(..)` before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C], num_confirmations = 2)`.
2. `A` calls `add_request(R)` where `R.member == A` (request created by A, e.g. `Transfer`).
3. `B` calls `confirm(R)` → `confirmations[R] = {B}` (`1 < 2`, not yet executed) — see `confirm()` logic at `multisig2/src/lib.rs:294-315`.
4. Separately, `A` and `C` confirm a `DeleteMember{ member: B }` request and it executes, calling `delete_member()` (`multisig2/src/lib.rs:356-379`). This only removes requests where `r.member == B`; `R` (created by `A`) is untouched, so `confirmations[R]` still equals `{B}`.
5. Members are now `{A, C}`, `num_confirmations` unchanged at `2`.
6. `C` calls `confirm(R)`. In `confirm()`, `confirmations.len() (1, containing stale "B") + 1 = 2 >= num_confirmations (2)` → `R` executes via `execute_request`, even though only `C` is an actual live approver besides the request creator `A` never confirming — the second "confirmation" came from a member that no longer exists in `self.members`.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
