### Title
Allowlist-based Vault auth authenticates by content digest only, allowing a race-to-submit impersonation of the allowlisted owner - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Finding Description
`allowListBasedAuth.AuthorizeRequest` computes `req.Digest()` over the JSON-RPC method+params and checks it against the on-chain `WorkflowRegistry` allowlist populated via `GetAllowlistedRequests` [1](#0-0) . If the digest matches an allowlisted entry, it returns an `AuthResult` bound to `allowlistedRequest.Owner`, with no check tying the *caller* of the gateway to that owner — the only inputs are the wire bytes of `method`+`params` [2](#0-1) . The unit test explicitly documents this: calling `AuthorizeRequest` twice with byte-identical requests succeeds both times with `// Same request is still authorized here; replay protection lives in the generic Authorizer.` [3](#0-2) . The only thing that prevents a second submission of the same digest from being processed is `authorizer.replayGuard.CheckAndRecord`, a single in-memory, first-come-first-served map keyed purely on digest string [4](#0-3) [5](#0-4) . This guard has no notion of "sender" at all — whichever request (real owner's or attacker's byte-identical copy) reaches `CheckAndRecord` first wins the single-use slot; the second, legitimate submission is rejected with `ErrRequestAlreadySeen`.

This is a deliberate, documented tradeoff of the allow-list auth mode (kept "for backwards compatibility" for clients that don't yet send `req.Auth`) [6](#0-5) : the security model here binds authorization to *possession of the exact preimage bytes* that were pre-committed on-chain by the workflow owner via `WorkflowRegistry.AllowlistRequest(requestDigest, expiry)` — it does not, and by design cannot, further verify that the specific HTTP/gateway caller submitting those bytes is the same entity that originally allowlisted them, since no signature, session, or sender identity accompanies allow-list-based requests.

### Impact Explanation
If an attacker can reconstruct or observe the exact `method`+`params` bytes of a not-yet-submitted allowlisted request (e.g., leaked via logs, a public gateway echo, or any channel outside TLS-protected client-to-gateway transport), they can submit that exact byte sequence to the gateway before the legitimate owner does. Because `AuthorizeRequest` accepts any submitter presenting matching digest bytes and only the replay guard enforces "first submission wins," the attacker's request is processed as the allowlisted owner, and the real owner's subsequent submission is rejected as a replay. This corresponds to Chainlink's "request impersonation" / authentication-bypass bounty class — the attacker executes a `vault.secrets.*` action attributed to another user's `workflowOwner` identity, potentially creating/updating/deleting/listing the victim's secrets.

### Likelihood Explanation
Exploitability is gated by a strong precondition that the audit prompt itself calls out: the attacker must already know the exact wire bytes of the request (including encrypted ciphertext values for create/update, or exact params for list/delete) before/at the same time the legitimate owner submits it, and must win a race against the real submission. `EncryptedSecrets` payloads are TDH2-encrypted client-side and not derivable by the attacker; the only realistic leak vector for the full byte sequence is an out-of-band channel (logs, a response echo, or network observation) which is largely outside the code under audit and overlaps with excluded threat classes (network-layer/host-level/log-access). Within `allow_list_based_auth.go`/`authorizer.go` alone, no bug independent of this precondition exists — the code behaves exactly as documented and tested. No credential, signature, or session is required by design, but the digest-preimage secrecy assumption is the actual control, and its violation is an operational/precondition issue rather than a code defect in the audited function.

### Recommendation
For the allow-list path, consider binding authorization additionally to a request-scoped nonce or session token issued out-of-band to the true submitter (not derivable from public method/params alone), or shorten the default allowlist window and treat the first-successful-submission-wins semantics as an accepted risk documented for API consumers. At minimum, document explicitly that allow-list-based auth security depends on the request body (especially `request_id`/ciphertext) never being disclosed prior to submission, and that this mode should be deprecated in favor of the JWT-based auth path (`jwtBasedAuth.AuthorizeRequest`), which binds the digest to a signed, tenant-scoped token rather than raw content match.

### Proof of Concept
```go
// core/capabilities/vault/allow_list_based_auth_test.go
func TestAllowListBasedAuth_RaceReplaySameDigestNoIdentityBinding(t *testing.T) {
    lggr := logger.TestLogger(t)
    owner := common.Address{1, 2, 3}
    req := makeListSecretsRequest(t, "123", "b") // byte-identical requests, no identity field

    digest, err := req.Digest()
    require.NoError(t, err)
    digestBytes, err := hex.DecodeString(digest)
    require.NoError(t, err)
    expiry := time.Now().UTC().Unix() + 100
    allowlisted := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{
        {RequestDigest: [32]byte(digestBytes), Owner: owner, ExpiryTimestamp: uint32(expiry)},
    }
    mockSyncer := syncerv2mocks.NewWorkflowRegistrySyncer(t)
    mockSyncer.On("GetAllowlistedRequests", mock.Anything).Return(allowlisted)

    auth := NewAllowListBasedAuth(lggr, mockSyncer)

    // "attacker" reconstructs identical bytes and submits first via the generic Authorizer
    authorizer := NewAuthorizer(auth, nil, lggr).(*authorizer)
    attackerResult, err := authorizer.AuthorizeRequest(t.Context(), req)
    require.NoError(t, err)
    require.Equal(t, owner.Hex(), attackerResult.AuthorizedOwner()) // attacker authorized as owner

    // real owner submits the same (legitimate) bytes afterward — rejected as replay
    _, err = authorizer.AuthorizeRequest(t.Context(), req)
    require.ErrorIs(t, err, ErrRequestAlreadySeen)

    // Confirms AuthorizeRequest alone (allow_list_based_auth.go) cannot distinguish
    // the true owner from a byte-identical replaying third party; only
    // authorizer.replayGuard.CheckAndRecord's per-digest single-use map decides who "wins".
}
```
Expected assertions: first caller with matching bytes is authorized as `owner.Hex()` regardless of identity; second (even if it's the true owner) is rejected via `ErrRequestAlreadySeen`, confirming the replay guard — not `AuthorizeRequest` — is the sole and insufficient defense against sender-identity impersonation.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
