### Title
Vault write-method disablement gate runs after authorization side effects (replay-guard digest recording) are already committed - ([File: core/services/gateway/handlers/vault/handler.go])

### Finding Description
In `HandleJSONRPCUserMessage`, for `MethodSecretsCreate`/`Update`/`Delete`, the handler first calls `h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)` [1](#0-0) , which internally calls `authorizeAndStamp` → `authorizer.AuthorizeRequest`. That call unconditionally records the request digest in the replay guard via `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` and only after that succeeds stamps the owner-prefixed request ID (`authorizedOwner + RequestIDSeparator + originalRequestID`) into `req.ID` and the request params [2](#0-1) [3](#0-2) .

Only after `ProcessRequest` returns successfully does the handler dispatch to `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete`, each of which performs the `h.writeMethodsEnabled.AllowErr(ctx)` gate check as the *first* statement in the function body [4](#0-3) . If the gate rejects (write methods administratively disabled via `cresettings.Default.GatewayVaultManagementEnabled`), the handler returns an `UnsupportedMethodError` to the user without ever forwarding the request to vault nodes via `fanOutToVaultNodes`.

Because `RequestReplayGuard.CheckAndRecord` is a one-shot, digest-keyed set with no rollback path, the digest recorded during the (now-discarded) `ProcessRequest` call remains marked "seen" until it naturally expires [5](#0-4) . There is no code path that un-records the digest when the subsequent gate check fails. Consequently, when the caller resends the exact same (identically signed/authenticated) request after write methods are re-enabled, `AuthorizeRequest` will call `CheckAndRecord` again with the same digest and return `ErrRequestAlreadySeen`, causing the legitimate resend to be rejected as a "replay" even though the original request never actually reached the vault DON.

### Impact Explanation
This is a self/request-availability impact rather than cross-user compromise: an authenticated (allowlisted or JWT) vault client that submits a create/update/delete request while `GatewayVaultManagementEnabled` is administratively false will have its request's replay-guard digest consumed with no side effect ever executed. When the same request is legitimately resubmitted after the feature flag is re-enabled, it is spuriously rejected as a replay until the guard entry naturally expires (`authResult.ExpiresAt()`). This matches "request binding/authorization exactness" defects and constitutes a denial-of-service against a legitimate write request rather than data/key disclosure or role escalation.

### Likelihood Explanation
Fully reachable by any authenticated allowlisted or JWT-authorized vault caller — no operator/admin privilege is required, only that `GatewayVaultManagementEnabled` be (temporarily) disabled by node operators, which is an intended administrative control, not a misconfiguration. The sequence (send while disabled, then resend identical payload once enabled) is deterministic and trivially repeatable in a unit test.

### Recommendation
Move the `writeMethodsEnabled.AllowErr(ctx)` check to occur before `h.requestProcessor.ProcessRequest` is invoked in `HandleJSONRPCUserMessage` (or pass the gate result into `ProcessRequest`/`authorizeAndStamp` so authorization and replay-guard recording are skipped entirely when write methods are disabled). Alternatively, make replay-guard recording reversible/transactional so that when downstream processing (e.g., the write-methods gate) rejects the request, the previously recorded digest is removed from `RequestReplayGuard`.

### Proof of Concept
Go handler-level test plan in `core/services/gateway/handlers/vault/handler_test.go`:
1. Construct a `handler` via `newHandlerWithAuthorizer` with a limits factory where `cresettings.Default.GatewayVaultManagementEnabled` is initially `false` (disabled) and can be flipped to `true` mid-test (use a fake `limits.Factory`/`GateLimiter` that is mutable, similar to existing test helpers in `handler_test.go`).
2. Build a signed/allowlisted `MethodSecretsCreate` JSON-RPC request with a fixed request ID and payload.
3. Call `h.HandleJSONRPCUserMessage(ctx, req, callback)`. Assert the callback receives `api.UnsupportedMethodError` (write methods disabled) and that `fanOutToVaultNodes`/`don.SendToNode` was never invoked.
4. Flip the gate limiter to enabled (`GatewayVaultManagementEnabled = true`).
5. Resend the identical `req` (same ID, params, auth) via `h.HandleJSONRPCUserMessage`.
6. Assert expectation: the request should be processed and forwarded to `don.SendToNode` (success path), not rejected with `errors.New("request not authorized: " + err.Error())` wrapping `ErrRequestAlreadySeen`. As implemented today, this second call is expected to fail authorization due to `ErrRequestAlreadySeen` from `RequestReplayGuard.CheckAndRecord`, demonstrating the bug.

func (h *handler) handleSecretsCreate(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	err := h.writeMethodsEnabled.AllowErr(ctx)
	if errors.Is(err, limits.ErrorNotAllowed{}) {
		l.Warnw("secrets write method called but write methods are disabled", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.UnsupportedMethodError, errors.New("vault write methods(create/update/delete) are disabled: "+err.Error()), nil))
	} else if err != nil {
		l.Errorw("error checking if write methods are enabled", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("error checking if write methods are enabled: "+err.Error()), nil))
	}

	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
