## Analysis

The external report's core bug-class is: **a transfer to one recipient can silently or permanently fail, and because the transfer function's failure semantics aren't handled defensively, other parties' funds can get stuck.** In Aptos Move the analog is a Move abort — if a distribution loop pays multiple recipients from a single shared pool and pushes coins with a call that can abort, one poisoned recipient aborts the *entire* transaction, blocking payout to everyone else sharing that pool.

`staking_contract.move`'s `distribute_internal` implements exactly this pattern: it withdraws **all** potential withdrawable stake for a staker/operator pool in one shot, then iterates over every shareholder in the `distribution_pool` (which holds both the staker's own unlocked-stake entries and every historical operator's commission entries) and unconditionally calls `aptos_account::deposit_coins` for each one: [1](#0-0) 

`aptos_account::deposit_coins`/`transfer_coins` will abort if the recipient has never registered a `CoinStore<AptosCoin>` **and** has explicitly opted out of arbitrary/direct coin transfers via `set_allow_direct_coin_transfers(false)`: [2](#0-1) [3](#0-2) 

Commission distributions for an operator are redirected to whatever address the operator sets via `set_beneficiary_for_operator`, which is a fully unprivileged, operator-controlled action requiring no staker consent: [4](#0-3) 

Because `distribute_internal` is invoked internally from `unlock_stake`, `request_commission`, `switch_operator`, and the public `distribute` entry function, any one un-payable entry left in the shared `distribution_pool` will cause **every** future call touching that pool to abort — including the staker's own attempts to unlock/withdraw their principal: [5](#0-4) [6](#0-5)

### Title
Permanent lock of staker funds via un-payable operator beneficiary in `staking_contract::distribute_internal` - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`distribute_internal` pays out **all** shareholders of a `staking_contract`'s shared `distribution_pool` (staker's unlocked principal + every past/current operator's commission) in a single atomic loop. An operator can point their commission payout at a "poison" beneficiary address that is guaranteed to abort on `coin::deposit` (an account that exists but has never registered `CoinStore<AptosCoin>` and has called `set_allow_direct_coin_transfers(false)`). Because the loop is all-or-nothing, this single un-payable entry permanently blocks payout of the *entire* pool, including the staker's own unrelated unlocked stake.

### Finding Description
- `request_commission_internal` adds the operator (or its beneficiary) as a distribution-pool shareholder for the accrued commission amount: [7](#0-6) 
- `set_beneficiary_for_operator` lets the operator redirect their commission payouts to an arbitrary address without staker approval, gated only by a feature flag, not by any receivability check: [8](#0-7) 
- `distribute_internal` withdraws the pool's *entire* withdrawable balance and then iterates over `distribution_pool.shareholders()`, calling `aptos_account::deposit_coins` for each one in turn, redeeming shares and extracting coins before the deposit: [1](#0-0) 
- `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the target is not registered for `AptosCoin` and has opted out of direct transfers: [2](#0-1) 
- Since Move transactions are atomic, one abort anywhere in the loop reverts the whole `distribute_internal` call — undoing the withdrawal from the stake pool and leaving the poisoned share still present in `distribution_pool`. Every future call path that internally calls `distribute_internal` (`unlock_stake`, `request_commission`, `switch_operator`, and the public `distribute` entry function) will hit the same poisoned entry and abort again, indefinitely: [5](#0-4) [6](#0-5) 

This is the direct Move analog of the ERC20 report: a payout to one recipient that cannot be satisfied (here, via Move abort instead of a mis-typed boolean return) permanently strands funds belonging to other, unrelated parties sharing the same accounting structure.

### Impact Explanation
The staker's own already-unlocked/inactive stake becomes permanently unwithdrawable once a malicious or careless operator poisons the shared `distribution_pool` with an un-payable beneficiary. This is a **permanent, non-recoverable loss of the staker's claim rights to their own principal and rewards** — the staker never authorized the operator's choice of beneficiary and has no code path to evict or bypass the bad entry, since the withdrawal, commission, and operator-switch functions all route through the same `distribute_internal`.

### Likelihood Explanation
Triggering the condition requires only unprivileged, permissionless actions: (1) create/control an ordinary account, leave it unregistered for `AptosCoin`, and call `set_allow_direct_coin_transfers(false)` on it (any account can do this to itself), and (2) as the operator of a `staking_contract`, call `set_beneficiary_for_operator` pointing at that poisoned address (also unprivileged, requires only the `operator_beneficiary_change_enabled` feature to be on and no staker consent). No admin/governance privilege or race condition is needed, and once set, the DoS is permanent for that pool's staker.

### Recommendation
Make `distribute_internal` resilient to individual payout failures: catch/skip un-payable recipients (e.g., fall back to depositing into an escrow/claimable balance, or use `coin::deposit`-safe patterns that don't abort the whole batch), or validate at `set_beneficiary_for_operator` time that the new beneficiary can currently receive `AptosCoin` (and re-validate/limit future opt-outs), so no single shareholder can block payouts to the rest of the pool.

### Proof of Concept
1. Staker creates a `staking_contract` with `operator` O, stakes X APT.
2. O's stake pool earns rewards; O calls `staking_contract::request_commission`, which buys O into `distribution_pool`.
3. Before that commission is distributed, O calls `staking_contract::set_beneficiary_for_operator(O, evil)`, where `evil` is an account that exists, has never called `coin::register<AptosCoin>`, and has called `aptos_account::set_allow_direct_coin_transfers(evil_signer, false)`.
4. Staker later calls `unlock_stake` or `distribute` to withdraw their own unlocked principal. `distribute_internal` withdraws the pool balance, then in its shareholder loop reaches `evil`'s redeemed commission share and calls `aptos_account::deposit_coins(evil, ...)`, which aborts.
5. The entire transaction reverts; the staker's principal remains locked in the stake pool, and every subsequent attempt to unlock/withdraw/distribute for this staker/operator pair aborts the same way, permanently.

                pool_address,
                accumulated_rewards,

            }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
    /// receive.
    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
