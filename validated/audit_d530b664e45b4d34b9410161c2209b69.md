### Title
Multisig executes requests below the configured confirmation threshold due to stale confirmations from removed members - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` counts confirmations purely by set size (`confirmations.len() as u32 + 1 >= self.num_confirmations`) without verifying that every account/key that already confirmed is still a live member. When a member is removed via `DeleteMember`, `delete_member` only purges requests that member *created*, not confirmations that member left on *other* pending requests. Those stale confirmations remain in the `confirmations` set and continue to count toward the threshold, letting a request execute with fewer live-member confirmations than `num_confirmations` requires. [1](#0-0) [2](#0-1) 

### Finding Description
The binding that must hold is: `confirmations counted == confirmations by current live members`. The contract keeps a `HashSet<String>` of confirming member identities per `request_id` in `self.confirmations` [3](#0-2) .

`confirm()` decides whether to execute a request solely from the size of this set:
```
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
} else { ... }
``` [4](#0-3) 

`delete_member()`, invoked when a `DeleteMember` action executes, cleans up *only* the requests that the removed member originally created:
```
let request_ids: Vec<u32> = self
    .requests
    .iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
...
self.members.remove(&member);
``` [5](#0-4) 

It never scans `self.confirmations` for *other* pending requests (created by someone else) that the removed member had already confirmed. Those requests keep the removed member's identity string in their confirmation set, and `confirm()` has no check that a confirming identity is still in `self.members`. This is exactly analogous to the report's root cause: a value used to decide an outcome (vote/confirmation tally) can diverge from the correct "live" source of truth (current checkpoint/current membership) in one code path but not another, and the discrepancy is never reconciled.

### Impact Explanation
This breaks the core custody guarantee of the multisig: `confirmations >= num_confirmations` is supposed to mean "at least `num_confirmations` *current* members approved," but a stale confirmation from a now-removed member can supply one of the required signatures. A `Transfer` or `FunctionCall` request (moving NEAR, deploying code, adding a full-access key, etc.) can therefore be executed with fewer live-member confirmations than the configured `K` requires — matching the explicitly listed Critical impact "a multisig request executed below threshold."

### Likelihood Explanation
This requires only ordinary multisig operations, no key compromise or malicious insider collusion: any pending request that has partial confirmations, followed by a normal `DeleteMember` action removing one of those confirmers, followed by one more ordinary confirmation from a remaining member, is enough to trigger execution below the true live threshold. Multisigs that periodically rotate members (a routine operation) while other requests are in flight are naturally exposed.

### Recommendation
In `confirm()`, validate that every entry in the request's confirmation set still belongs to `self.members` (or recompute the count only over currently valid members) before comparing against `num_confirmations`. Alternatively, in `delete_member()`, iterate over all entries in `self.confirmations` (not just requests created by the removed member) and strip the removed member's identity from every confirmation set, decrementing effectively so a stale approval can never satisfy the threshold.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. `A.add_request(R1 = Transfer{...})`; `A.confirm(R1)` → confirmations = `{A}`.
3. `B.confirm(R1)` → confirmations = `{A, B}` (1 short of threshold 3).
4. Separately, members create and confirm `R2 = DeleteMember{member: B}` to completion (3 confirmations from A, C, D as required) → `delete_member` executes, removing `B` from `self.members`, but `R1` was not created by `B`, so its confirmation set `{A, B}` is left untouched in storage [6](#0-5) .
5. `C.confirm(R1)` → `confirmations.len() as u32 + 1 == 3 >= num_confirmations (3)` is true, so `execute_request(R1)` runs the `Transfer` even though only `A` and `C` are still live members — one fewer live confirmation than the configured `K = 3`. [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
