### Title
Zip-slip path traversal in legacy zip extractor allows writes outside the job's intended extraction root - (File: `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`)

### Finding Description
`extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33`) receives a `dir` field set from `archive.NewExtractor(format, f, size, wd)` (called from `commands/helpers/cache_extractor.go:655` and `commands/helpers/artifacts_downloader.go:131`), but that `dir` is never used — `Extract` calls `archives.ExtractZipArchive(zr)` with no directory argument at all. [1](#0-0) 

`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry, which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then writes via `os.OpenFile(file.Name), os.Symlink, os.Mkdir` — all using `file.Name` verbatim, with no `filepath.Clean`/join against a root and no rejection of `..` segments or absolute paths. [2](#0-1) [3](#0-2) 

The only path-related check present is `errorIfGitDirectory`, which only detects a leading `.git` path component to warn about `.git` overwrite — it performs no traversal/absolute-path validation whatsoever. [4](#0-3) [5](#0-4) 

Because `os.OpenFile`/`os.MkdirAll` resolve relative paths against the process's current working directory (which the runner sets to the job's build directory before invoking `cache-extractor`/`artifacts-downloader`, per `commands/helpers/cache_extractor.go:626` and `commands/helpers/artifacts_downloader.go:91`), a `zip.File.Name` containing `../../` sequences (or an absolute path) resolves outside the intended `wd` root. Note this is distinct from the fastzip path (`commands/helpers/archive/fastzip/zip_fastzip_extractor.go:33-46`), which delegates to the `saracen/fastzip` library and passes `e.dir` correctly — that library is expected to sanitize/join paths against the destination directory internally, so this bug is specific to the legacy (`FF_USE_FASTZIP=false`) code path.

### Impact Explanation
An unprivileged pipeline author who controls the contents of a cache or artifact archive (e.g. via `cache:paths`, `artifacts:paths`, or by crafting a raw zip uploaded as a cache/artifact) can embed entries with names like `../../sibling-project/.git-cache-ci-vars`, `../../../etc/passwd`, or paths that reach into a sibling job's checked-out workspace on a shared shell/host runner. When `FF_USE_FASTZIP` is disabled, `cache-extractor`/`artifacts-downloader` will write those files outside the job's build directory. This is a real file-write path-traversal (zip-slip) rather than merely a documented admin-trust issue, since it's exploitable purely via job-controlled archive content, not via admin misconfiguration.

### Likelihood Explanation
Preconditions are realistic and attacker-controlled: `FF_USE_FASTZIP` is disabled (either by default in older runner configs or explicitly), and the attacker supplies/controls a cache or artifact archive (any job author can shape cache/artifact contents, and on shared/self-hosted runners with predictable build directory layouts, sibling job paths may be guessable, e.g. `builds/<runner-token-prefix>/<concurrency-id>/<namespace>/<project>`). The Go standard library `archive/zip` package does not sanitize `File.Name`, so a crafted zip with `..`-laden names is straightforward to construct with `archive/zip.Writer`. This is fully reproducible via a self-contained Go unit test.

### Recommendation
In `helpers/archives/zip_extract.go`, thread the destination directory through `ExtractZipArchive`/`extractZipFile` (mirroring what `zip_legacy_extractor.go` already receives as `e.dir`), and for every `file.Name`: resolve `target := filepath.Join(dir, file.Name)`, then verify `target` is still within `dir` (e.g. `strings.HasPrefix(filepath.Clean(target)+string(filepath.Separator), filepath.Clean(dir)+string(filepath.Separator))` or use `filepath.Rel` and reject any result starting with `..` or being absolute) before performing `MkdirAll`/`OpenFile`/`Symlink`/`Mkdir`. Reject or skip entries that fail this check, similar to how `errorIfGitDirectory` currently only warns for `.git` paths. Also update `zip_legacy_extractor.go`'s `Extract` to actually pass `e.dir` into `ExtractZipArchive`.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpRoot := t.TempDir()
    extractDir := filepath.Join(tmpRoot, "job-a")
    require.NoError(t, os.MkdirAll(extractDir, 0o755))

    victimDir := filepath.Join(tmpRoot, "job-b") // sibling "victim" job workspace
    require.NoError(t, os.MkdirAll(victimDir, 0o755))

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    w, err := zw.Create("../job-b/.env")
    require.NoError(t, err)
    _, err = w.Write([]byte("CI_JOB_TOKEN=leaked"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    // chdir into extractDir to emulate cache-extractor's `wd`
    oldWd, _ := os.Getwd()
    defer os.Chdir(oldWd)
    require.NoError(t, os.Chdir(extractDir))

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    err = archives.ExtractZipArchive(zr) // current signature; ideally would take extractDir

    // Expected (secure) behavior: file must NOT exist outside extractDir
    _, statErr := os.Stat(filepath.Join(victimDir, ".env"))
    assert.True(t, os.IsNotExist(statErr), "zip-slip: file was written into sibling directory")
}
```
Running this test against the current code demonstrates the file is created at `job-b/.env` (outside `job-a`), proving the traversal; after applying the recommended path-containment check, the test should assert `os.IsNotExist(statErr) == true`.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
