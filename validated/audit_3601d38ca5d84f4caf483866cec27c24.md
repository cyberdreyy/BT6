## Finding

### Title
Stale confirmations from removed multisig members are not purged, allowing requests to execute below the live-member confirmation threshold - (File: `multisig2/src/lib.rs`, also `multisig/src/lib.rs`)

### Summary
The multisig contracts (`multisig2/src/lib.rs` and the legacy `multisig/src/lib.rs`) count confirmations toward the `num_confirmations` (K-of-N) threshold from a `HashSet` that is never cleaned of a member's votes once that member is removed from the multisig — unless the removed member happens to be the *creator* of the pending request. This lets a request execute with fewer currently-authorized approvals than the configured threshold requires, i.e. `confirmations_counted != confirmations_from_live_members`.

### Finding Description
`confirm()` treats a request as approved once `confirmations.len() as u32 + 1 >= self.num_confirmations`: [1](#0-0) 

Membership removal is handled by `delete_member()`, which only purges requests and confirmations for requests that the *removed* member itself created (`r.member == member`); it does not scan other pending requests to strip confirmations that the removed member previously cast on requests created by someone else: [2](#0-1) 

Because `assert_valid_request()`/`confirm()` never re-validates that entries already present in a request's `confirmations` set still belong to current members — it only checks that the *caller* is a current member via `current_member()` — a stale confirmation left behind by a removed member is counted forever toward the threshold: [3](#0-2) 

The legacy `multisig/src/lib.rs` has the identical pattern: `DeleteKey` only removes requests where `r.signer_pk == pk` (the deleted key's own requests), leaving that key's confirmations on other members' requests intact: [4](#0-3) [5](#0-4) 

### Impact Explanation
This breaks the core custody guarantee of the multisig: "K of N *current* members must approve before funds move." A `Transfer`, `FunctionCall`, `DeployContract`, or `AddKey` request can be executed with fewer than K live approvals, because a departed/removed member's stale vote is still tallied. This is a "multisig request executed below threshold" scenario, matching the Critical impact category — NEAR can be moved, or a full-access key/contract code can be deployed, by a set of currently-authorized members smaller than the governance-mandated K.

### Likelihood Explanation
This requires no special privilege beyond normal multisig operation: any request that received a confirmation from a member who is later removed (e.g., an employee offboarded, a compromised key rotated out, or a member removed "for cause") remains in the confirmations tally for that specific request as long as the request itself isn't deleted. Since `add_request`/`confirm` allow requests to sit un-executed indefinitely (only bounded by `active_requests_limit` and `REQUEST_COOLDOWN` for `delete_request`), an attacker or negligent operator merely needs a pending request confirmed by a soon-to-be-removed member and then gathers the remaining confirmations from current members to complete execution below the intended threshold.

### Recommendation
When removing a member (`delete_member` in `multisig2`, `DeleteKey` in `multisig`), iterate over **all** pending requests (not just those created by the removed member) and strip the removed member's entry from each request's confirmations set. Alternatively, validate at `confirm()`-execution time that every entry in the `confirmations` set still corresponds to a current member before counting it toward the threshold.

### Proof of Concept
1. Initialize `multisig2` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `B` calls `add_request_and_confirm(transfer_request)` → confirmations = `{B}`.
3. `C` calls `confirm(request_id)` → confirmations = `{B, C}` (2/3).
4. Members `A, B, D` execute a separate, properly-threshold-approved `DeleteMember { member: C }` request. `delete_member()` only removes requests where `r.member == C` — the transfer request was created by `B`, so it and its confirmations set `{B, C}` remain untouched (`multisig2/src/lib.rs:361-371`).
5. `A` calls `confirm(request_id)` → `confirmations.len() (2) + 1 = 3 >= num_confirmations (3)` → `execute_request` runs the `Transfer`.
6. Result: the transfer executed with only `B` and `A` as currently valid members (2 of 4 live members), while `C`'s stale vote from before removal was counted, bypassing the intended 3-of-N live-member threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
