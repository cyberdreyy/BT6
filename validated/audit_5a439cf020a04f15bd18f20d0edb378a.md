### Title
Uncontrolled recursion in `TrieNode::decode` causes stack exhaustion in the fault-proof program - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode::decode` (and its helper `try_decode_leaf_or_extension_payload`) recursively calls itself once per nested `Extension` node with no depth bound, mirroring the unbounded recursion in Wireshark's `dissect_daap_one_tag` (CVE-2017-9617). A dispute-game participant supplying a single crafted trie-node preimage in response to a hint can drive this recursion to stack-overflow depth, crashing the fault-proof program.

### Finding Description
`TrieNode::decode` in [1](#0-0)  peeks the RLP header and, for a 2-item list, calls `try_decode_leaf_or_extension_payload`, which for an `Extension` node calls `Self::decode(buf)` again on the embedded child: [2](#0-1) 

Per Ethereum's MPT rules, a child node is only "blinded" (hashed) if its RLP encoding exceeds 32 bytes; smaller children are embedded inline and decoded directly without any external preimage fetch, as documented in [3](#0-2)  and implemented in `blind()`: [4](#0-3) . Because each such embedding takes only a few bytes (a 1-byte RLP list header + a 1–2 byte encoded path), an attacker can nest thousands of `Extension` levels inside a single byte blob, all decoded in one `TrieNode::decode(&mut preimage)` call — no additional oracle round-trips are needed. This is analogous to the CBOR walker in the same repo, `CborItem::read_at`, which explicitly caps recursion with `MAX_CBOR_NESTING_DEPTH = 64` [5](#0-4)  — no equivalent bound exists for `TrieNode`.

`TrieNode::decode` is the function used by every `TrieProvider` implementation that turns oracle-supplied preimage bytes into trie nodes during proof execution, e.g.:
- L1 chain provider: [6](#0-5) 
- L2 chain provider: [7](#0-6) 
- In-memory execution trie DB: [8](#0-7) 

In the preimage-oracle model used by the fault dispute game, the byte blob supplied for a given hash key only needs to satisfy `keccak256(blob) == key`; the attacker is free to choose the blob's internal structure. A dispute-game participant defending or attacking a claim can therefore respond to a trie-node hint with a deeply self-nested `Extension` chain, matching only its own computed hash, and the fault-proof program will recurse through `TrieNode::decode` until the native stack is exhausted.

### Impact Explanation
Stack exhaustion in the fault-proof program during dispute-game execution causes the verifier process to abort/crash rather than reach a correct (or even incorrect-but-defined) verdict on the disputed claim. This is a node/verifier halt during a critical on-chain security process (dispute resolution), matching the accepted "node halt" / "wrong provable output root" impact class — an attacker can prevent the honest challenger's program from producing a valid response during the interactive proof, undermining the fault-proof's ability to correctly resolve disputes.

### Likelihood Explanation
Likelihood is high for any dispute-game participant: constructing the malicious preimage requires no cryptographic break, just choosing bytes and computing their own hash key, then supplying that data in response to the relevant preimage hint (`HintType::L1BlockHeader`/receipts/transactions/state hints as seen in [9](#0-8) ). No privileged access is required beyond normal participation in the interactive fault-proof game.

### Recommendation
Add an explicit recursion/nesting depth bound to `TrieNode::decode`/`try_decode_leaf_or_extension_payload` (analogous to `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`), rejecting RLP blobs whose embedded (non-blinded) `Extension`/`Branch` nesting exceeds a small bound consistent with legitimate MPT encodings (which naturally terminate quickly since embedding requires <32-byte RLP). Alternatively, convert the recursive descent into an explicit iterative loop with a bounded work stack.

### Proof of Concept
1. Build innermost node `L0 = Leaf { prefix: [k], value: v }` (small, RLP < 32 bytes).
2. For `i in 1..=N`, wrap: `Li = Extension { prefix: [single nibble], node: Box::new(L(i-1)) }`, keeping each intermediate RLP encoding under 32 bytes so it stays embedded (never blinded) per `blind()`'s 32-byte rule [4](#0-3) .
3. Encode `LN` to bytes, `preimage = encode(LN)`, `key = keccak256(preimage)`.
4. Supply `preimage` as the oracle response for `key` when the fault-proof program requests it (e.g., via `OracleL1ChainProvider::trie_node_by_hash` / `OracleL2ChainProvider::trie_node_by_hash`).
5. The program calls `TrieNode::decode(&mut preimage.as_ref())`, recursing `N` times through `Self::decode` inside `try_decode_leaf_or_extension_payload`; for sufficiently large `N` (bounded only by preimage size, not depth), this overflows the stack and crashes the verifier process before any DAO/consensus check on the trie's semantic validity occurs.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}
