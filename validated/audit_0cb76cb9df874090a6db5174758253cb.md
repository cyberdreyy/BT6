### Title
Stale confirmations from a removed member allow a multisig request to execute below the intended live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`multisig2`'s `delete_member` only purges pending requests/confirmations that the removed member *originated* (`r.member == member`), but never scrubs that member's confirmation entries recorded on requests they merely *confirmed*. `confirm()` later counts `confirmations.len()` against `num_confirmations` with no check that each confirmer is still a current member, so a confirmation cast by an account/key that has since been removed still counts toward the K-of-N threshold.

### Finding Description
`confirm()` blindly compares the size of the stored confirmation set to `num_confirmations`: [1](#0-0) 

`delete_member()` cleans up only requests where `r.member == member` (i.e. requests the deleted member *added*), and removes `num_requests_pk` for that member, but does nothing to any `confirmations` entries the member left on *other* pending requests they confirmed but did not originate: [2](#0-1) 

Because `confirm()` never re-validates that each `String` in the `confirmations: LookupMap<RequestId, HashSet<String>>` set still corresponds to a member in `self.members`, a confirmation recorded by an account that is later removed remains valid and fills a threshold slot forever.

The binding this breaks is: `confirmations from CURRENT members >= num_confirmations`. In reality the check enforced is `confirmations.len() (including stale/removed members) >= num_confirmations`, i.e. `confirmations_recorded ≠ confirmations_from_live_members`.

### Impact Explanation
This lets a request execute (including `Transfer`, `FunctionCall`, `AddKey`/full-access-key grants, `DeployContract`, etc.) with fewer *live* confirming members than the configured `num_confirmations` policy requires. That is a multisig request executed below threshold — matching the Critical impact class (funds moved, or privileged actions like adding a full-access key or deploying new contract code, authorized by fewer than K live parties). Any remaining member who colludes with (or simply benefits from) a stale confirmation left by a member who was later removed can push a request through with one fewer live signer than intended, defeating the K-of-N security guarantee the contract advertises.

### Likelihood Explanation
No privileged actor, redeploy, or victim key is required — only ordinary multisig membership churn (adding/confirming a request, later removing one of its confirmers via a separate, otherwise-legitimate `DeleteMember` request) combined with a remaining member choosing to finalize the stale request. This is a realistic operational sequence for any long-lived multisig that rotates members, and requires no special exploit beyond correct-looking multisig usage.

### Recommendation
When removing a member in `delete_member`, iterate all pending requests' confirmation sets and strip any entry matching the removed member (not just requests originated by them). Alternatively, in `confirm()` (and at execution time), filter/re-validate the confirmation set against `self.members` before comparing its length to `num_confirmations`, so only confirmations from currently-live members count toward the threshold.

### Proof of Concept
1. Initialize with `num_confirmations = 3`, members `{A, B, C, D}` (4 members, satisfies `len - 1 >= num_confirmations` for later removal).
2. `A` calls `add_request` (not `add_request_and_confirm`) to create request `R` (e.g. `Transfer` to an attacker-controlled account). `R` starts with 0 confirmations.
3. `B` and `C` each call `confirm(R)` → `confirmations = {B, C}` (2/3, not yet executed).
4. Separately, members confirm a `DeleteMember{member: B}` request to threshold and it executes: `delete_member` runs, but since `B` did not *originate* `R` (`A` did), `R`'s confirmation set is left untouched — `confirmations = {B, C}` still contains removed member `B`.
5. `D` (a live member) calls `confirm(R)`. `confirmations.len() as u32 + 1 == 3 >= num_confirmations (3)`, so `R` executes via `execute_request`.
6. Result: `R` was authorized by only two currently-live confirmers (`C`, `D`) plus a stale confirmation from removed member `B`, executing a 3-of-N-gated action (e.g. `Transfer`, `AddKey`, or `FunctionCall`) with effectively 2 live confirmations — below the intended live-member threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
