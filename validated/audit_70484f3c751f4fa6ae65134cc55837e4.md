### Title
Missing sender/DON allowlist check in `handler.HandleLegacyUserMessage` allows any signer to trigger broadcast to a victim DON's nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` in the legacy `web_api_trigger` capabilities handler validates only message structure, timestamp freshness, and cryptographic well-formedness of the signature via `common.ValidatedRequestFromMessage`/`msg.Validate()`, but never checks that `msg.Body.Sender` is an authorized/allowlisted signer for the target `DonId`. As a result, any holder of an arbitrary ECDSA keypair can sign a `TriggerRequestPayload` and have it forwarded to every member of any configured DON via `don.SendToNode`.

### Finding Description
The method reads and JSON-decodes `body.Payload` into `webapicap.TriggerRequestPayload`, checks `payload.Timestamp` for staleness, and rejects unsupported methods, but the only remaining gate before dispatch is the comment marking the missing control: `// TODO: apply allowlist and rate-limiting here` [1](#0-0) . Immediately after, `common.ValidatedRequestFromMessage(msg)` only converts/validates the wire format (signature recoverability + structural validation), not sender authorization, and the code proceeds to fan the request out to every configured DON member: [2](#0-1) .

The `handlers.DON` and `config.DONConfig` types used by this handler carry no allowlist/authorized-sender concept at all — `DONConfig` only has `DonId`, `Members`, `F`, and `Handlers`, with no per-sender or per-workflow authorization list [3](#0-2) . Upstream in `gateway.ProcessRequest`, the only checks performed before calling `HandleLegacyUserMessage` are that a handler exists for the DON ID and `msg.Validate()` succeeds — again, no sender authorization [4](#0-3) .

This contrasts with the newer v2 HTTP trigger path, which implements `WorkflowMetadataHandler.Authorize`, checking the JWT signer against a per-workflow `authorizedKeys` map before dispatch [5](#0-4) . The legacy handler lacks an equivalent check entirely.

The existing test suite confirms the exploit path works with any signed message from a keypair unrelated to any allowlist: `triggerRequest` signs a `TriggerRequestPayload` with an arbitrary `*ecdsa.PrivateKey` and calls `msg.Sign(key)` [6](#0-5) , and `TestHandlerReceiveHTTPMessageFromClient` shows that a valid signature alone results in `don.SendToNode` being invoked for all DON members [7](#0-6) . Nothing in this flow checks whether the signer is one of the DON's members or an authorized workflow sender.

### Impact Explanation
Any attacker with an arbitrary ECDSA keypair (no DON membership, no subscription, no prior authorization) can POST a signed `web_api_trigger` request to the gateway's legacy endpoint targeting any known `DonId`, causing the gateway to broadcast an attacker-controlled trigger payload to every node in that DON via `don.SendToNode`. This is unauthorized capability/trigger execution using another workflow's DON resources — it can spoof trigger events into workflows that never authorized this sender, and can be used for resource exhaustion (flooding DON nodes with crafted triggers), matching the "unauthorized job run / request impersonation" bounty class.

### Likelihood Explanation
Feasibility is high and repeatable: the only precondition is knowledge of a valid `DonId` (these can be discovered via configuration/service enumeration) and the ability to generate an ECDSA keypair and sign a well-formed `TriggerRequestPayload` with a fresh timestamp — both are trivial and require no privileged access, matching the "unprivileged attacker" threat model exactly.

### Recommendation
Before dispatching to `don.SendToNode`, `HandleLegacyUserMessage` must verify `msg.Body.Sender` against a configured allowlist of authorized senders for the target DON/workflow (mirroring the `WorkflowMetadataHandler.Authorize` model used in the v2 handler), and add per-sender rate-limiting as the existing TODO comment indicates. Reject the request with `api.UserMessageParseError`/an authorization error code if the sender is not allowlisted.

### Proof of Concept
Extend `handler_test.go`:
1. Reuse `setupHandler(t)` to construct the handler with `nodes` fixture representing legitimate DON members.
2. Generate a fresh, unregistered key: `attackerKey, _ := crypto.GenerateKey()` (not in `nodes`, not in any allowlist).
3. Call `msg := triggerRequest(t, attackerKey, []string{"daily_price_update"}, "", "", "")` to sign a valid `TriggerRequestPayload` targeting `donID := "workflow_don_1"`.
4. Set up `don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)` expectations for each DON member.
5. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)` and assert `err == nil` and that `don.SendToNode` was invoked once per DON member (via `mock.AssertExpectations` / call count), demonstrating that the message was forwarded despite `attackerKey`'s address never appearing in `nodes`, `h.donConfig.Members`, or any allowlist.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil

func triggerRequest(t *testing.T, key *ecdsa.PrivateKey, topics []string, methodName, timestamp, payload string) *api.Message {
	messageID := "12345"
	if methodName == "" {
		methodName = MethodWebAPITrigger
	}
	if timestamp == "" {
		timestamp = strconv.FormatInt(time.Now().Unix(), 10)
	}
	donID := "workflow_don_1"
	var payloadJSON []byte
	if payload == "" {
		ts, err := strconv.ParseInt(timestamp, 10, 64)
		require.NoError(t, err)
		reqPayload := webapicap.TriggerRequestPayload{
			TriggerId:      "web-api-trigger@1.0.0",
			TriggerEventId: "action_1234567890",
			Timestamp:      ts,
			Topics:         topics,
			Params: webapicap.TriggerRequestPayloadParams(map[string]any{
				"bid": "101",
				"ask": "102",
			}),
		}
		payloadJSON, err = json.Marshal(reqPayload)
		require.NoError(t, err)
	} else {
		payloadJSON = []byte(payload)
	}
	msg := &api.Message{
		Body: api.MessageBody{
			MessageId: messageID,
			Method:    methodName,
			DonId:     donID,
			Payload:   json.RawMessage(payloadJSON),
		},
	}
	err := msg.Sign(key)
	require.NoError(t, err)
	err = msg.Validate()
	require.NoError(t, err)
	return msg
}
