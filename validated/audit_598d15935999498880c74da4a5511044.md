## Title
Global-state agreement threshold uses floor rounding while the canonical block-signature threshold uses ceiling rounding, letting the signer state machine "reach agreement" below the true 70% supermajority - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% quorum with **floor** (truncating) integer division, while the canonical node/consensus-enforced threshold, `NakamotoBlockHeader::compute_voting_weight_threshold`, computes the same 70% quorum with **ceiling** division. The two are supposed to represent the identical supermajority requirement but disagree by exactly one weight unit whenever `total_weight * 7` is not a multiple of 10 — which is the common case given arbitrary per-signer weights. This is the same rounding-direction bug class as the reported `compute_fee_earned`/`fixed_mul_ceil` issue: one code path rounds in the "generous" direction, letting a sub-quorum weight be treated as quorum.

### Finding Description
The canonical threshold used everywhere a block's signer-signature weight is checked against consensus (both by the node and by the signer when tallying signatures) is: [1](#0-0) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```
i.e. `ceil(total_weight * 7 / 10)`. This is used both by `verify_signer_signatures` [2](#0-1)  and by the signer's own signature/rejection/pre-commit tallying in `stacks-signer/src/v0/signer.rs` [3](#0-2) .

However, the `GlobalStateEvaluator` — which determines the signer's *local belief* of the global consensus state (active protocol version, global burn view, and crucially the `current_miner` used to accept/reject block proposals) — uses a different, floor-rounded formula: [4](#0-3) 

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
```
i.e. `vote_weight >= floor(total_weight * 7 / 10)`, with no ceiling adjustment.

The repo's own test suite proves the discrepancy for `total_weight = 511`: the canonical threshold is `358` [5](#0-4) , but `reached_agreement`'s formula (`511*7/10 = 357.7` truncated) yields `357` — one unit less.

`reached_agreement` gates `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which sets `current_miner`, `burn_block`, and `tx_replay_set`) [6](#0-5) . `determine_global_state`'s output feeds `GlobalStateView::check_proposal`, which is the authority a signer uses to decide whether a proposed block's miner/tenure/consensus-hash is the legitimate one to validate and sign: [7](#0-6) .

### Impact Explanation
Because `reached_agreement` requires one less unit of weight than the chain-enforced 70% supermajority, a signer can lock in `current_miner`/burn-view/protocol-version/replay-set "agreement" using a set of `StateMachineUpdate` gossip messages whose combined weight is below the true quorum used everywhere else in the protocol (`compute_voting_weight_threshold`). Since different signers may receive updates in different order/subsets, this off-by-one-slot inconsistency between the two threshold formulas is exactly the kind of equality break the rules target ("aggregated-weight vs verified-accepts" / "approved-parent vs canonical"): a signer can settle on an `ActiveMiner`/tenure view — and subsequently validate and sign block proposals against it via `check_proposal` — using a weight tally that would not itself satisfy the canonical, ceil-rounded threshold enforced elsewhere in the same signer and in `verify_signer_signatures`. This can wedge or split the signer network's view of the canonical miner at reward-set weight totals where `total_weight * 7 mod 10 != 0` (the common case), a High-severity liveness/consistency issue (acting on a threshold that is stale/inconsistent with the actual required quorum).

### Likelihood Explanation
No majority collusion or extra privileges are required — this is a deterministic arithmetic inconsistency triggered by ordinary weight totals reachable via normal reward-set assignment (weights are arbitrary integers summing to at most `reward_slots`, so `total_weight * 7` is a multiple of 10 only in special cases). It manifests purely through legitimate `StateMachineUpdate` gossip received via StackerDB in the normal course of protocol operation.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` (and, for symmetry, `reached_disagreement`) use the same ceiling-rounded formula as `NakamotoBlockHeader::compute_voting_weight_threshold`, e.g. reuse `compute_voting_weight_threshold` directly instead of re-implementing the 70% calculation with floor division in `libsigner/src/v0/signer_state.rs`.

### Proof of Concept
1. Construct a reward set where `total_weight = 511` (achievable with ordinary per-signer weight assignments).
2. Have signers whose combined weight is `357` submit `StateMachineUpdate`s agreeing on the same `current_miner`/burn view.
3. `GlobalStateEvaluator::reached_agreement(357)` returns `true` (`357 >= 511*7/10 = 357`), so `determine_global_state` finalizes this view [8](#0-7) .
4. Meanwhile, `NakamotoBlockHeader::compute_voting_weight_threshold(511)` requires `358` [5](#0-4)  — one unit more than what was actually used to "agree" on the miner/view.
5. Any signer basing block-proposal validation on this state (`GlobalStateView::check_proposal`) is now acting on a view that has not met the same supermajority bar the rest of the protocol enforces, producing a split/stale view between signer subsets at this weight boundary.

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }
