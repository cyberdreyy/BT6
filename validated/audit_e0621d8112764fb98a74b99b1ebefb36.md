### Title
Zip-slip path traversal in zip extraction allows writes outside job workspace - (File: `helpers/archives/zip_extract.go`)

### Summary
`extractZipFile`/`extractZipFileEntry` write archive entries using the raw, attacker-controlled `zip.File.Name` with no path sanitization or confinement to an extraction root, unlike the sibling tar+zstd extractor which explicitly validates paths stay under its `dir`. Because artifact/cache downloads feed attacker-influenced zip archives into this code via `ExtractZipFile`/`ExtractZipArchive`, a crafted entry name containing `../` segments can write files outside the intended working directory.

### Finding Description
`extractZipFile` computes the parent directory purely from the entry name and creates it unconditionally: `os.MkdirAll(filepath.Dir(file.Name), 0o777)` [1](#0-0) . `extractZipFileEntry` then opens/writes the file at that same raw name: `os.Remove(file.Name)` followed by `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())` [2](#0-1) . `extractZipDirectoryEntry` and `extractZipSymlinkEntry` have the same pattern using `os.Mkdir(file.Name, ...)` and `os.Symlink(string(data), file.Name)` [3](#0-2) . None of these functions call `filepath.Clean`, reject `..` segments, or verify the resolved path stays under any root. `ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` directly for every entry with no such check [4](#0-3) .

Contrast this with `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, which explicitly joins entry names against its extraction directory and rejects anything resolving outside it: `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name)); ... if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir { return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir) }` [5](#0-4) . The zip path lacks this guard entirely, and worse, the legacy zip extractor accepts a `dir` parameter but never uses it when delegating to `archives.ExtractZipArchive`: `func (e *extractor) Extract(ctx context.Context) error { zr, err := zip.NewReader(e.r, e.size); ... return archives.ExtractZipArchive(zr) }` — `e.dir` is stored in the struct but not passed or applied [6](#0-5) .

The reachable path for an unprivileged job: `commands/helpers/cache_extractor.go`'s `Execute` gets `wd` via `os.Getwd()` and constructs the extractor with `archive.NewExtractor(format, f, size, wd)`, then calls `extractor.Extract(...)` [7](#0-6) ; `commands/helpers/artifacts_downloader.go` follows the identical pattern for artifacts [8](#0-7) . Neither performs an `os.Chdir` into `wd` nor otherwise enforces confinement before invoking the ziplegacy extractor — the confinement is expected to come from within the extractor, and for zip it does not exist. A job author (or a compromised upstream cache/artifact server acting on the job's cache key) fully controls the archive content that reaches this code, including zip entry names such as `../../etc/foo` or `../shared-vol/payload`.

### Impact Explanation
An unprivileged CI job that controls its own cache/artifact archive (or its cache key/content, later downloaded as a zip by `cache-extractor`/`artifacts-downloader`) can craft entries with `../` segments to write or overwrite files outside the job's working directory — including into paths shared with other containers via a mounted volume, or files later read/executed by the runner helper or other jobs on the same host/executor. This breaks the "file operations must stay within intended build/cache/artifact roots" invariant and can be leveraged to plant files at higher-privilege-visible locations depending on volume/mount configuration.

### Likelihood Explanation
Highly feasible and fully attacker-controlled: any job that pushes a cache or artifact can shape the zip file names, since `.gitlab-ci.yml` cache/artifact paths are user-specified and archive creation/consumption round-trips job-controlled files/names. Exploitation requires only crafting entry names in a zip (a well-known "zip slip" pattern) and no additional privilege. This is reproducible deterministically in a unit test.

### Recommendation
In `helpers/archives/zip_extract.go`, before acting on any `file.Name`, clean the path and verify the resolved destination stays within the intended extraction root, mirroring the tarzstd extractor's chroot check (`filepath.Join(root, file.Name)` then reject if it escapes `root` via `filepath.Rel`/`strings.HasPrefix` checks). Reject or skip entries whose names are absolute, contain `..` after cleaning, or resolve outside the root, and apply the same check for directory and symlink entries. Additionally, wire an actual extraction root (`dir`) through `ExtractZipArchive`/`ExtractZipFile` and have `commands/helpers/archive/ziplegacy` pass and enforce its `dir` parameter instead of ignoring it.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpDir := t.TempDir()
    root := filepath.Join(tmpDir, "workspace")
    require.NoError(t, os.MkdirAll(root, 0o755))

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    for _, name := range []string{"../../etc/foo", "../shared-vol/payload"} {
        w, err := zw.Create(name)
        require.NoError(t, err)
        _, err = w.Write([]byte("evil"))
        require.NoError(t, err)
    }
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    cwd, _ := os.Getwd()
    require.NoError(t, os.Chdir(root))
    defer os.Chdir(cwd)

    err = ExtractZipArchive(zr) // should confine to root or return an error
    // Expected (currently fails): no file exists outside root
    _, statErr := os.Stat(filepath.Join(tmpDir, "etc", "foo"))
    assert.True(t, os.IsNotExist(statErr), "path traversal escaped extraction root")
    _, statErr2 := os.Stat(filepath.Join(tmpDir, "shared-vol", "payload"))
    assert.True(t, os.IsNotExist(statErr2), "path traversal escaped extraction root")
}
```
With the current implementation, both assertions fail because `../../etc/foo` and `../shared-vol/payload` are created relative to the CWD, outside `root`.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
