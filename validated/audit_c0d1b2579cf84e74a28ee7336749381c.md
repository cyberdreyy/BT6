### Title
Missing role-gate on pprof debug endpoints allows any authenticated (including view-role) user to dump process heap/goroutine data - ([File: core/web/router.go])

### Summary
`metricRoutes` mounts Go's `net/http/pprof` handlers directly on the `authv2` route group without any `auth.RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole` wrapper, so any user who can authenticate via session or API token — including the lowest-privileged `UserRoleView` — can call `GET /v2/debug/pprof/heap`, `/v2/debug/pprof/goroutine`, or `POST /v2/debug/pprof/symbol`. These handlers dump raw process memory/stack data that can contain key material, bridge credentials, or other secrets held in memory.

### Finding Description
In `core/web/router.go`, `v2Routes` builds `authv2` with only session/token authentication (no role check): [1](#0-0) 

Deep inside that block, `metricRoutes(authv2)` is invoked to attach the pprof group: [2](#0-1) 

`metricRoutes` itself registers all pprof endpoints with plain handlers and zero role wrapper: [3](#0-2) 

Compare this to every other sensitive endpoint in the same `authv2` block (e.g. key export, job creation, transfers), all of which are wrapped in `auth.RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole`: [4](#0-3) 

The `auth.Authenticate` middleware only validates that the caller has a valid session or API token; it does not check `user.Role`. The role-check middlewares are defined separately and must be explicitly applied per-route: [5](#0-4) 

Since `pprofGroup.GET("/heap", ...)`, `/goroutine`, and `POST /symbol` have no such wrapper, a `UserRoleView` session or API token — the minimum authenticated role in this system — is sufficient to reach the raw `net/http/pprof` handlers and pull a full heap dump or goroutine stack trace of the running `chainlink` node process.

### Impact Explanation
A heap or goroutine dump of a live Chainlink node process can contain private key material (ETH/OCR/CSA/P2P keys held in memory), database connection strings/credentials, bridge external adapter credentials, and other in-memory secrets, depending on what's resident at capture time. This maps to Chainlink's "sensitive information disclosure" bounty class — a view-role (least privileged) authenticated user can extract secrets they should have no access to, violating the intended role-exactness of the RBAC model where view users should only have read access to non-sensitive resources.

### Likelihood Explanation
The only precondition is possessing any valid authenticated credential recognized by `auth.Authenticate` (session cookie or API token) — no elevated role, admin access, or special condition is required. This is trivially and repeatably exploitable by any low-privilege user account (e.g. a view-only operator or a token issued for read-only integrations).

### Recommendation
Wrap all `metricRoutes` handlers (`/debug/pprof/*`, including `heap`, `goroutine`, `profile`, `trace`, `symbol`, `cmdline`, `allocs`, `block`, `mutex`, `threadcreate`) with `auth.RequiresAdminRole` (or at minimum `RequiresEditRole`), consistent with how other sensitive administrative endpoints in `v2Routes` are protected. Alternatively, gate pprof exposure entirely behind a separate build/config flag so it isn't reachable via the standard authenticated API surface at all.

### Proof of Concept
Add a handler-level integration test in `core/web/auth/auth_test.go` style:
1. Boot the app via `cltest.NewApplicationEVMDisabled(t)` and `web.Router(t, app, nil)` as done in `TestRBAC_Routemap_Run`.
2. Create a view-role test user: `u := &cltest.User{Role: sessions.UserRoleView}`, `client := app.NewHTTPClient(u)`.
3. Call `resp, cleanup := client.Get("/v2/debug/pprof/heap?debug=1")`.
4. Assert `resp.StatusCode == http.StatusOK` (not 401/403), confirming the missing role gate.
5. Repeat for `GET /v2/debug/pprof/goroutine?debug=1` and `POST /v2/debug/pprof/symbol`, expecting 200 in all cases for a view-role user.
6. Add these three routes to the `routesRolesMap` table in `auth_test.go` with `viewOnlyAllowed: false` to catch regressions once fixed, and verify the existing `TestRBAC_Routemap_*` tests fail against current code (confirming the gap) and pass after adding the role wrapper.

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
