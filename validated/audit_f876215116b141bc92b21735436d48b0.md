### Title
Revoked OIDC user API tokens remain valid because `FindUserByAPIToken` trusts cached `oidc_user_api_tokens` data without any actual revocation/re-validation mechanism - ([File: core/sessions/oidcauth/oidc.go])

### Summary
`FindUserByAPIToken` authenticates solely against the cached `user_email`/`user_role` columns in `oidc_user_api_tokens`, unlike `FindUser`, which validates the caller against the live `users` table. The code comment claims cached tokens are "synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation," but `core/sessions/oidcauth/reaper.go` only purges stale `oidc_sessions` by creation time and never touches `oidc_user_api_tokens` or re-checks upstream group membership, so a de-provisioned/revoked OIDC user's API token keeps working for its full `UserAPITokenDuration()`.

### Finding Description
`AuthenticateByToken` (`core/web/auth/auth.go:78-112`) calls `authr.FindUserByAPIToken(ctx, token.AccessKey)` to authenticate any request bearing `X-API-KEY`/`X-API-SECRET` headers. In the OIDC driver, `FindUserByAPIToken` (`core/sessions/oidcauth/oidc.go:298-338`) only checks:
- Does a row exist in `oidc_user_api_tokens` for `token_key`?
- Is `created_at + UserAPITokenDuration >= now()`?

It never re-queries the `users` table or the identity provider to confirm the cached `user_email`/`user_role` are still valid, in contrast to `FindUser` (`core/sessions/oidcauth/oidc.go:279-295`), which does `SELECT * FROM users WHERE lower(email) = lower($1)` and fails if the user row is gone. The in-line comment at line 305-307 asserts a sync mechanism exists ("sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation"), but the only reaper present for OIDC, `sessionReaper.Work`/`deleteStaleSessions` in `core/sessions/oidcauth/reaper.go:37-49`, exclusively issues `DELETE FROM oidc_sessions WHERE created_at < $1` — it never inspects `oidc_user_api_tokens`, never queries the OIDC provider, and never revokes tokens for users whose upstream group membership changed. [3](#0-2) [4](#0-3) 

Because the token's validity is purely a function of `token_key` existence + a static TTL window, once a token is minted via `SetAuthToken` (`core/sessions/oidcauth/oidc.go:511-548`), it remains fully authenticatable for its entire `UserAPITokenDuration()` regardless of whether the underlying user's OIDC group membership, employment, or account has since been revoked/deleted. `DeleteAuthToken` exists but is an operator/admin-only action, not an automatic consequence of upstream de-provisioning.

### Impact Explanation
A user whose OIDC identity/group membership is revoked out-of-band retains a live, working API credential that authenticates as their cached role (potentially Admin/Edit) for up to `UserAPITokenDuration()`, since there is no mechanism in this codebase that shortens or invalidates that window based on upstream state. This is a continued-authorization/authentication-soundness failure: a "deleted" identity is still fully authenticatable and can call any role-gated API route (job management, key/bridge access, etc.) depending on the cached role — matching the "authentication bypass / role bypass via stale credential" bounty class.

### Likelihood Explanation
Preconditions: the attacker must have obtained a valid `oidc_user_api_tokens` credential while still a legitimate user (e.g., before being off-boarded/revoked upstream), and `UserAPITokenEnabled()`/OIDC auth must be configured. No admin/host access is needed post-issuance — the attacker simply continues sending the previously-issued API key/secret. This is fully reproducible: it requires no timing race or privileged action, just the passage of time after revocation and before the token's own TTL expiry (there being no other invalidation path in this code).

### Recommendation
In `FindUserByAPIToken`, re-validate the cached email/role against the current `users`/upstream source of truth (or at minimum add a genuine periodic reaper job that deletes/invalidates `oidc_user_api_tokens` rows for users no longer present in the authoritative group claim), rather than trusting the cached role indefinitely for the full TTL window. Alternatively, shorten `UserAPITokenDuration()` drastically and add an actual sync job (matching the `UpstreamSyncInterval` config's stated purpose) that periodically re-checks each cached token's user against the OIDC provider/local `users` table and deletes rows for revoked identities.

### Proof of Concept
Go integration test plan (in `core/sessions/oidcauth/oidc_test.go`):
1. Configure a test `oidcAuthenticator` with `UserAPITokenEnabled()=true` and a short `UserAPITokenDuration` (e.g., 24h).
2. Call `SetAuthToken` for a synthetic user `revoked@example.com` with role `UserRoleAdmin`, capturing the returned `auth.Token`.
3. Simulate out-of-band revocation: delete/alter any local users-table row that would represent `revoked@example.com`'s presence (or simply note none exists, since OIDC users aren't stored locally) — no update is made to `oidc_user_api_tokens`.
4. Call `oi.FindUserByAPIToken(ctx, token.AccessKey)` directly, or invoke `auth.AuthenticateByToken(ginCtx, oi)` with the token headers set.
5. Assert `FindUserByAPIToken` returns a valid `clsessions.User{Email: "revoked@example.com", Role: UserRoleAdmin}` and `AuthenticateByToken` succeeds (`err == nil`, `SessionUserKey` set with Admin role) — demonstrating continued privileged access with no upstream re-check, before any TTL-based expiry and with no reaper job ever inspecting `oidc_user_api_tokens`.

		if errors.Is(err, sql.ErrNoRows) {
			return clsessions.User{}, errors.New("user not found")
		}

		oi.lggr.Errorf("error searching users table: %v", err)
		return clsessions.User{}, errors.New("error finding user")
	}

	return foundUser, nil
}

func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE created_at < $1", before)
	return err
