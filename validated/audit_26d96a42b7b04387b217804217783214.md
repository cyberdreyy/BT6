### Title
Unsigned `reject_reason` in `BlockRejection` lets a single signer forge another signer's rejection cause, poisoning the `ReorgNotAllowed` miner-invalidation tally - (File: `libsigner/src/v0/messages.rs`, `stacks-signer/src/v0/signer.rs`)

### Summary
`BlockRejection`'s application-level signature only covers `signer_signature_hash` + `chain_id`, never the `reason`, `reason_code`, or `response_data.reject_reason` fields [1](#0-0) . Any party who has observed a genuine, publicly-broadcast rejection from victim signer S2 for block hash H can splice that same signature onto a new `BlockRejection` for the same H but with an arbitrary `reason_code`/`reject_reason`, and rebroadcast it inside their own legitimately-signed StackerDB chunk (they only need to own their own slot, not S2's). `handle_block_rejection` recovers the public key solely from this under-scoped signature and, once it recovers to a known signer, trusts the forged `reject_reason` completely [2](#0-1) .

### Finding Description
`BlockRejection::hash()` builds the signed digest from only `self.signer_signature_hash` (via a structured-data domain "block-rejection"), and `sign`/`verify`/`recover_public_key` all operate over that same restricted hash [3](#0-2) . The `reason`, `reason_code`, and `response_data` (which carries `reject_reason`) are plain fields on the struct that are never part of the signed payload, yet they are fully attacker-controllable in transit/reconstruction.

`handle_block_rejection` recovers the signer's public key purely from `rejection.recover_public_key()`, derives `signer_address`, and — provided `is_valid_signer(&signer_address)` passes — unconditionally stores whatever `reject_reason` accompanies that signature via `store_and_process_block_rejection` [4](#0-3) . `store_and_process_block_rejection` persists `(block_hash, signer_address, reject_reason)` and then computes `total_reorg_reject_weight` specifically filtered by `RejectReasonPrefix::ReorgNotAllowed` using `compute_reject_code_signing_weight` [5](#0-4) . If that weight crosses the complement of the acceptance threshold, the local `SortitionsView`'s current sortition is marked `SortitionMinerStatus::InvalidatedBeforeFirstBlock` [6](#0-5) .

Because the outer StackerDB chunk-level signature (`StackerDBChunkData.sig`, verified against slot ownership in `validate_received_chunk`) only proves *who broadcast the chunk*, not that the *contents faithfully represent S2's original vote*, an attacker who legitimately owns their own slot can:
1. Observe S2's real rejection of block H for reason X (e.g. `ValidationFailed(BadTransaction)`), broadcast publicly on StackerDB.
2. Build a new `BlockRejection` struct with the same `signer_signature_hash = H`, same `signature` bytes (which still verify, since the signed digest is unchanged), but `reason_code`/`response_data.reject_reason = ReorgNotAllowed`.
3. Wrap it in a chunk signed with the attacker's own private key and their own slot, and push it via StackerDB.

Every other signer that ingests this chunk will recover S2's pubkey from `rejection.recover_public_key()`, treat the vote as coming from S2, and tally S2's weight toward `ReorgNotAllowed`, even though S2 never voted for that reason.

This breaks the "signed vs validated" equality invoked by the rules: what S2 actually signed (a rejection for reason X) is not what the state machine records and acts on (a rejection for reason `ReorgNotAllowed`) — a cross-context reuse of a valid signature to misattribute intent.

### Impact Explanation
Per `store_and_process_block_rejection`, once `total_reorg_reject_weight.saturating_add(min_weight) > total_weight`, the signer marks the current sortition's miner as `InvalidatedBeforeFirstBlock` [7](#0-6) . A miner wrongly marked invalid because of forged reason tallies is a liveness wedge: the tenure the miner was legitimately running gets treated as compromised, stalling block production until the network times out and a new tenure/miner starts. This matches the rules' High-impact bucket ("a signer wedged into never signing valid blocks ... or losing the equivocation guard on restart" — here, a live miner is incorrectly locked out). The gate is explicitly limited to signer protocol versions that do not use global state (`!uses_global_state()`), so the practical blast radius is scoped to legacy/pre-global-state deployments, but the logic path itself is unconditionally reachable by any single signer who can observe one genuine rejection broadcast for the target block.

### Likelihood Explanation
The attack requires only: (a) owning one's own StackerDB signer slot (a normal, single, low-weight participant — no majority or other signer's key needed), and (b) having observed any one legitimate rejection from any other signer for the target block hash, which is public by construction (StackerDB messages are broadcast to the whole signer set and observers). No cryptographic breaking is needed — the forged message reuses an existing valid signature verbatim because the signed digest is deliberately narrow. This is directly analogous to the external report's root cause: attacker-controlled data (`file` in the XSS PoC; `reason_code`/`reject_reason` here) is trusted and acted upon without being bound to the value that was actually authenticated (HTML-escaping of `file`; signing of `reject_reason`).

### Recommendation
Include `reason_code` (or the full `response_data`) in the signed digest used by `BlockRejection::hash()`, so that any tampering with the rejection reason invalidates the signature. Alternatively/additionally, at the point of tallying reason-specific weight (`compute_reject_code_signing_weight` for `ReorgNotAllowed`), require the same reason to have been independently corroborated by the local node's own validation of that peer's claim, rather than trusting an unauthenticated field embedded in an otherwise validly-signed envelope.

### Proof of Concept
1. Signer S2 (legitimate, weight w2) rejects proposed block with `signer_signature_hash = H` for a real reason, e.g. `ValidationFailed(BadTransaction)`, and broadcasts a correctly signed `BlockRejection { signer_signature_hash: H, reason_code: ValidationFailed(BadTransaction), signature: σ, ... }` over StackerDB. σ is computed as `sign(hash())` where `hash()` only depends on `H` and `chain_id` [8](#0-7) .
2. Attacker A (owns their own slot) observes this broadcast chunk and extracts σ and H.
3. A constructs `BlockRejection { signer_signature_hash: H, reason_code: RejectCode::from(RejectReason::ReorgNotAllowed), reason: "...", signature: σ, chain_id: same, metadata: ..., response_data: BlockResponseData { reject_reason: RejectReason::ReorgNotAllowed, ... } }`. Because `hash()` is unaffected by `reason_code`/`response_data`, `rejection.verify(&S2_pubkey)`/`recover_public_key()` still succeeds and returns S2's key [9](#0-8) .
4. A wraps this forged `BlockRejection` in `SignerMessage::BlockResponse(BlockResponse::Rejected(...))`, serializes it, and signs the outer `StackerDBChunkData` with A's own private key for A's own slot — this passes `validate_received_chunk`'s slot-ownership check because A owns that slot [10](#0-9) .
5. Every other signer processing this chunk calls `handle_block_rejection`, recovers S2's address from σ, passes `is_valid_signer`, and calls `store_and_process_block_rejection(..., signer_address = S2, reject_reason = ReorgNotAllowed)` [11](#0-10) , crediting S2's weight toward the `ReorgNotAllowed` bucket regardless of what S2 actually voted.
6. Repeating this for each rejecting signer whose real rejection A can observe lets A accumulate `total_reorg_reject_weight` toward the invalidation threshold, ultimately triggering `SortitionMinerStatus::InvalidatedBeforeFirstBlock` on a miner that no quorum of signers actually flagged for reorg [7](#0-6) .

(Note: this path is gated by `!determine_active_signer_protocol_version()?.uses_global_state()`, so it applies to legacy/non-global-state protocol versions; I was unable to fully trace every caller/version gate for `uses_global_state()` within the available iterations, so the exact set of deployed configurations where this is reachable should be verified further.)

    pub fn hash(&self) -> Sha256Sum {
        let domain_tuple = make_structured_data_domain("block-rejection", "1.0.0", self.chain_id);
        let data = Value::buff_from(self.signer_signature_hash.as_bytes().into()).unwrap();

    /// Sign the block rejection and set the internal signature field
    fn sign(&mut self, private_key: &StacksPrivateKey) -> Result<(), String> {
        let signature_hash = self.hash();
        self.signature = private_key.sign(signature_hash.as_bytes())?;
        Ok(())
    }

    /// Verify the rejection's signature against the provided signer public key
    pub fn verify(&self, public_key: &StacksPublicKey) -> Result<bool, String> {
        if self.signature == MessageSignature::empty() {
            return Ok(false);
        }
        let signature_hash = self.hash();
        public_key
            .verify(&signature_hash.0, &self.signature)
            .map_err(|e| e.to_string())
    }

    /// Recover the public key from the rejection signature
    pub fn recover_public_key(&self) -> Result<StacksPublicKey, &'static str> {
        if self.signature == MessageSignature::empty() {
            return Err("No signature to recover public key from");
        }
        let signature_hash = self.hash();
        StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            signature_hash.as_bytes(),
            &self.signature,
        )
    }

    /// Handle an observed rejection from another signer
    fn handle_block_rejection(
        &mut self,
        rejection: &BlockRejection,
        sortition_state: &mut Option<SortitionsView>,
    ) {
        debug!("{self}: Received a block-reject signature: {rejection:?}");

        let block_hash = &rejection.signer_signature_hash;
        let signature = &rejection.signature;

        // recover public key
        let Ok(public_key) = rejection.recover_public_key() else {
            debug!("{self}: Received block rejection with an unrecovarable signature. Will not store.";
               "signer_signature_hash" => %block_hash,
               "signature" => %signature
            );
            return;
        };

        // authenticate the signature -- it must be signed by one of the stacking set
        let signer_address = StacksAddress::p2pkh(self.mainnet, &public_key);
        if !self.is_valid_signer(&signer_address) {
            debug!("{self}: Received block rejection with an invalid signature. Will not store.";
                "signer_public_key" => ?public_key,
                "signer_address" => %signer_address,
                "signer_signature_hash" => %block_hash,
                "signature" => %signature
            );
            return;
        }

        let Some(mut block_info) = self.block_lookup_by_reward_cycle(block_hash) else {
            if let Err(e) = self.signer_db.add_pending_block_rejection_response(
                block_hash,
                &signer_address,
                (&rejection.response_data.reject_reason).into(),
            ) {
                warn!("{self}: Failed to add pending block rejection response: {e:?}");
            }
            return;
        };

        info!("{self}: Received block rejection";
            "signer_pubkey" => public_key.to_hex(),
            "signer_signature_hash" => %block_hash,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "reject_reason" => ?rejection.response_data.reject_reason,
        );

        self.store_and_process_block_rejection(
            sortition_state,
            &mut block_info,
            &signer_address,
            (&rejection.response_data.reject_reason).into(),

        // signature is valid! store it

            block_hash,
            signer_address,
            reject_reason,

            Err(e) => {
                warn!("{self}: Failed to save block rejection signature: {e:?}",);
