### Title
Malicious/unregistered operator beneficiary can permanently brick `staking_contract::distribute` and freeze staker funds - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::distribute_internal` pays out **every** shareholder in a staking contract's `distribution_pool` (staker, operator/beneficiary) inside a single atomic `while` loop using `aptos_account::deposit_coins`. `deposit_coins` reverts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is unregistered for `AptosCoin` and has opted out of direct transfers via `aptos_account::set_allow_direct_coin_transfers(false)`. Since the operator's beneficiary is freely chosen by the operator via `set_beneficiary_for_operator` and can be any address (including one that never registers for `AptosCoin` and has disabled direct transfers), a single "poisoned" beneficiary makes the whole distribution transaction abort — this is the on-chain analog of the USDC-blacklist issue: one recipient's un-payable state bricks payouts for unrelated, unprivileged parties.

### Finding Description [1](#0-0) 

`distribute_internal` withdraws all inactive/pending_inactive stake from the pool and then loops over `distribution_pool.shareholders()`, redeeming shares and calling `aptos_account::deposit_coins(recipient, ...)` for each one, redirecting the operator's payout to `beneficiary_for_operator(operator)`: [2](#0-1) 

The beneficiary is set unilaterally by the operator with no validation that the address is capable of receiving `AptosCoin`: [3](#0-2) 

`aptos_account::deposit_coins` aborts for any recipient that (a) doesn't already have a `CoinStore<CoinType>` and (b) has explicitly opted out of direct transfers: [4](#0-3) 

Any account owner can call `set_allow_direct_coin_transfers(account, false)` on their own address at any time — a fully unprivileged, self-controlled action: [5](#0-4) 

Because Move transactions are atomic, when the loop aborts on one recipient, the entire `distribute_internal` call reverts — including the withdrawal of stake from the pool for every *other* shareholder in the same distribution pool (i.e., the staker). Crucially, `distribute_internal` is not only invoked by the standalone `distribute()` entry function but is also the mandatory first step of `request_commission`, `unlock_stake`, and (per code comments) `switch_operator`, all of which "force distribution of any already inactive stake" before proceeding: [6](#0-5) [7](#0-6) 

Since `stake::withdraw_with_cap` for a `staking_contract` pool is only reachable through `distribute_internal` (the staker never holds the pool's `OwnerCapability` directly — it is held by the `StakingContract` resource), there is no alternate withdrawal path once the beneficiary payout starts reverting.

### Impact Explanation
Once the operator's commission distribution share becomes non-zero (via `request_commission_internal`/`unlock_stake`, which is invoked automatically by many entry points) and the current beneficiary for that operator cannot accept a direct `AptosCoin` deposit, **every** subsequent call to `distribute`, `unlock_stake`, or `request_commission` for that staker/operator pair aborts. This traps:
- The staker's already-unlocked/inactive principal and rewards (no other function can extract them from the underlying stake pool).
- The operator's own pending commission.

This satisfies the "Stake And Lockup Gate": permanent lock / non-recoverable loss of claim rights in a staking_contract flow, and "share-accounting corruption... traps value," triggered without the attacker (a malicious or careless beneficiary/operator) needing any privileged role over the staker's funds.

### Likelihood Explanation
Low-to-moderate likelihood, similar in profile to the referenced Sherlock finding: it requires a specific state (beneficiary account unregistered for `AptosCoin` + direct-transfer opt-out) to exist at the moment a distribution is attempted. This can occur:
- Accidentally, if an operator sets a beneficiary address that has never interacted with `AptosCoin` and that address's owner opts out of unsolicited coin transfers for privacy/spam reasons.
- Maliciously, if the operator (who is otherwise a semi-trusted but not fully-privileged party relative to the staker) deliberately sets such a beneficiary to grief the staker, or a beneficiary address itself is controlled by an attacker colluding with a compromised/malicious operator.

Given commission flows happen every time `unlock_stake`/`request_commission` run, and beneficiaries are operator-controlled and not staker-controlled, this is a realistic denial-of-withdrawal vector.

### Recommendation
- Wrap the per-recipient `aptos_account::deposit_coins` call in `distribute_internal` so a single recipient's inability to receive funds does not abort the whole distribution (e.g., skip/queue that recipient's amount, or fall back to the staker/withdrawal_address, or use `coin::deposit`-with-try-semantics/`option`-based dispatch).
- Alternatively, validate at `set_beneficiary_for_operator` time that the new beneficiary can currently receive `AptosCoin` (registered or accepts direct transfers), and/or allow the staker (not just the operator) to force-reset a bricked beneficiary given a grace period.

### Proof of Concept
1. Staker `S` creates a staking contract with operator `O` and 10% commission via `create_staking_contract`.
2. `O` calls `set_beneficiary_for_operator(O, B)` where `B` is a fresh address with no `CoinStore<AptosCoin>`.
3. `B`'s controller calls `aptos_account::set_allow_direct_coin_transfers(B, false)` (fully unprivileged, self-controlled action).
4. The pool earns rewards; `O` or anyone calls `request_commission`/`unlock_stake`, which invokes `distribute_internal`, which tries `aptos_account::deposit_coins(B, ...)` for the commission share and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. From this point on, every call to `distribute`, `request_commission`, and `unlock_stake` for the `(S, O)` pair reverts, because they all invoke `distribute_internal` first, permanently freezing `S`'s unlocked stake inside the pool.

Note: I was not able to fully trace `switch_operator`/`switch_operator_with_same_commission` in this session (the relevant lines rendered blank in the tool output), so I cannot confirm with certainty whether switching away from the poisoned operator also calls `distribute_internal` and would likewise be blocked, or whether it offers an escape hatch. This should be verified with a full read of `aptos-move/framework/aptos-framework/sources/staking_contract.move` lines ~745-810 before finalizing severity, since if `switch_operator` bypasses `distribute_internal` (or forgives the frozen distribution), the impact would be reduced from "permanent" to "partial/recoverable."

    /// This also triggers paying commission to the operator for accounting simplicity.
    public entry fun unlock_stake(
        staker: &signer, operator: address, amount: u64
    ) acquires Store, BeneficiaryForOperator {
        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

        // Record a distribution for the staker.
        add_distribution(
            operator,
            staking_contract,
            staker_address,
            amount,
        );

        // Request to unlock the distribution amount from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            UnlockStake { pool_address, operator, amount, commission_paid }
        );
    }

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
