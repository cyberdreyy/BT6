### Title
One-step `ActivationRegistryStorage::set_admin` permanently locks out the activation registry admin on a typo, matching the OwnableImpl lockout class - ([File: crates/common/precompiles/src/activation/storage.rs])

### Summary
The Base activation registry precompile (`0x8453...0001`) rotates its admin in a single transaction via `set_admin`, validating only that the new admin is non-zero, with no staged/confirmed second step. This is the same single-step ownership-transfer anti-pattern flagged in the external report for `OwnableImpl.transferOwnership()`.

### Finding Description
`ActivationRegistryStorage::set_admin` writes `new_admin` directly to storage after checking it is non-zero and that the caller is the current admin — there is no pending-admin staging or acceptance step: [1](#0-0) 

This is reachable from a single signed transaction through the precompile's ABI dispatcher via `setAdmin(address)`: [2](#0-1) 

Once a non-zero (even incorrect) address is written to the `admin` storage slot, the effective-admin resolution logic permanently prefers it over the static fallback — the fallback is only consulted when the stored admin is zero: [3](#0-2) 

By contrast, the codebase already implements the fix recommended by the source report (a two-step stage/finalize admin transfer) for the Policy Registry's per-policy admin: [4](#0-3) 
and for `IPolicyRegistry::stageUpdateAdminCall` / `finalizeUpdateAdminCall`: [5](#0-4) 
The `ActivationRegistryStorage` admin, however, was not brought in line with that two-step pattern.

### Impact Explanation
The activation registry admin is the sole gate controlling activation/deactivation of the `B20Stablecoin`, `B20Asset`, and `PolicyRegistry` precompile features on chain: [6](#0-5) 
If the legitimate admin mistakenly transfers admin rights to an incorrect address (typo, wrong key, compromised/unavailable key) via `setAdmin`, no on-chain recovery path exists: the stored non-zero admin permanently overrides the static fallback (`admin()`'s zero-check gate), and `require_admin_caller` will reject every future admin-only call, including a further `setAdmin` call to fix it: [7](#0-6) 
Recovery would require a hard fork / chain-spec change to override the static fallback config, since the precompile itself offers no in-protocol correction mechanism. This permanently freezes the ability to activate emergency killswitch behavior (e.g., deactivating a compromised B20 asset/stablecoin feature) for as long as the wrong admin address is in the storage slot.

### Likelihood Explanation
This requires the current, legitimate activation-registry admin to submit a `setAdmin` transaction with a mistaken address — the same operational-error scenario described in the source report. It does not require an attacker; it is a governance/operational hazard reachable by a single admin-signed transaction, matching the constraint that this analog must be reachable via a single signed transaction to the precompile dispatch path.

### Recommendation
Convert `ActivationRegistryStorage::set_admin` to a two-step process: introduce a `pendingAdmin` slot and require the newly designated admin to call a `finalizeSetAdmin`/`acceptAdmin` function (analogous to `stage_update_admin`/`finalize_update_admin` already implemented for the Policy Registry) before the `admin` slot is overwritten. This mirrors the existing, already-adopted mitigation pattern in the same codebase.

### Proof of Concept
1. Admin `A` is the current state-backed admin of `ActivationRegistryStorage` (`admin_config.state_enabled = true`).
2. `A` calls `setAdmin(newAdmin=X)` where `X` is mistyped/unintended, via `IActivationRegistry::setAdminCall` dispatched at `crates/common/precompiles/src/activation/dispatch.rs:92-95`.
3. `set_admin` (storage.rs:148-177) validates only `X != 0`, confirms caller `== A`, and writes `X` to the `admin` slot in one step — no confirmation from `X` is required.
4. From this point, `admin(admin_config)` (storage.rs:105-113) returns `X` because the stored slot is non-zero, permanently overriding the static fallback.
5. Neither `A` nor anyone else who controls `X`'s private key exists to call `activate`/`deactivate`/`setAdmin` again; `require_admin_caller` (storage.rs:237-244) rejects every subsequent caller except `X`.
6. The activation registry's admin function is permanently bricked absent a hard fork changing the static chain-config fallback, since the on-chain resolution logic never falls back once the slot is non-zero.

    ///
    /// When state-backed admin storage is disabled, this always returns the static fallback. When
    /// state-backed admin storage is enabled, a non-zero storage value wins; a zero storage value
    /// falls back to the static chain-config admin so Cobalt can replay historical Beryl activation
    /// transactions before the first admin rotation.
    ///
    /// [`Address::ZERO`] here means "no admin is set": it is not a valid admin address.
    /// Configuration-time validation rejects `Some(Address::ZERO)`, so in a correctly
    /// constructed chain spec the zero return always means `activation_admin_address` was
    /// `None`. Callers must not treat the zero return as a meaningful admin address.
    pub fn admin(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        if admin_config.state_enabled {
            let stored_admin = self.stored_admin()?;
            if !stored_admin.is_zero() {
                return Ok(stored_admin);
            }
        }
        Ok(admin_config.fallback.unwrap_or(Address::ZERO))
    }

    /// Sets the activation registry admin address.
    pub fn set_admin(
        &mut self,
        new_admin: Address,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }
        if !admin_config.state_enabled {
            return Err(BasePrecompileError::revert(
                IActivationRegistry::AdminStorageNotEnabled {},
            ));
        }
        if new_admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::ZeroAdminAddress {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        self.__initialize()?;
        self.admin.write(new_admin)?;
        self.emit_event(IActivationRegistry::AdminChanged {
            previousAdmin: caller,
            newAdmin: new_admin,
            caller,
        })?;

        Ok(())
    }

    /// Returns the effective admin if one is configured and the caller address can be authorized.
    pub fn authorized_admin(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        let caller = self.storage.caller();
        if caller.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        let admin = self.admin(admin_config)?;
        if admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        Ok(admin)
    }

    /// Reverts unless the current caller is the effective activation admin.
    pub fn require_admin_caller(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        let caller = self.storage.caller();
        let admin = self.authorized_admin(admin_config)?;
        if caller != admin {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
        }
        Ok(caller)
    }
