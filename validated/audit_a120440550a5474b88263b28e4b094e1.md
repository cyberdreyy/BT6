### Title
Front-running griefing of `createDstEscrow` via deterministic CREATE2 salt collision - (File: contracts/BaseEscrowFactory.sol)

### Summary
`BaseEscrowFactory.createDstEscrow` is a fully public, unauthenticated function that deploys a destination escrow clone using `Clones.cloneDeterministic` with a `salt` derived solely from the `dstImmutables` calldata passed by the caller. Since the salt does not incorporate `msg.sender`, any unprivileged actor can observe a pending, legitimate `createDstEscrow` transaction in the mempool, copy its exact calldata, and front-run it. This causes the deterministic CREATE2 address to already contain code when the legitimate transaction executes, making it revert and preventing the resolver from performing the operation, matching the exact root cause described in the Baton report.

### Finding Description
`createDstEscrow` computes the deployment salt purely from the immutables struct: [1](#0-0) 

```
function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
    ...
    bytes32 salt = immutables.hashMem();
    address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
    ...
}
```
and `_deployEscrow` simply calls the CREATE2-based `cloneDeterministic`: [2](#0-1) 

No access control (no whitelist, no `msg.sender == taker` requirement, no access-token gate) restricts who may call `createDstEscrow`; anyone providing valid `dstImmutables` and matching `msg.value`/token approval can invoke it. Because `salt = immutables.hashMem()` is derived entirely from public, replayable calldata (orderHash, hashlock, maker, taker, token, amount, safetyDeposit, timelocks), an attacker can:
1. Observe a pending `createDstEscrow` transaction from the legitimate resolver in the mempool.
2. Copy the exact `dstImmutables`/`srcCancellationTimestamp` calldata and resubmit it with higher gas, funding it themselves with the required native/token amount.
3. Get mined first, deploying the deterministic clone at the same address the legitimate resolver's transaction targets.
4. When the legitimate resolver's original transaction executes, `Clones.cloneDeterministic` reverts because a contract already exists at the computed CREATE2 address, causing the legitimate transaction to fail entirely.

This mirrors the Baton `create`/`cloneDeterministically` issue: the salt is attacker-predictable/replayable and not bound to `msg.sender`, enabling a public front-running griefing vector on a factory `create2` deployment.

### Impact Explanation
This fits the Medium bounty category: "smart contract unable to operate because required token/native balances can be broken by an unprivileged actor." The legitimate resolver's `createDstEscrow` call is forced to revert whenever an unprivileged attacker races to deploy the same deterministic address first, wasting the resolver's gas and delaying/disrupting destination-escrow creation for that specific cross-chain swap leg. Because `immutables.timelocks.setDeployedAt(block.timestamp)` is recomputed at call time, a retry in a later block produces a different salt/address, so the DoS is temporary rather than a permanent freeze, consistent with the medium severity in the source report.

### Likelihood Explanation
Medium: the attack is trivial to execute (mempool copy + front-run, no special privileges needed), but the attacker has little direct financial incentive since they must supply the same native/token funding amount as the legitimate resolver to make the front-run transaction succeed, and they gain no extra funds or escrow control beyond what the copied immutables dictate (e.g., `taker` remains as encoded in the copied immutables, not the attacker).

### Recommendation
Bind the CREATE2 salt (or an additional field checked at deployment) to `msg.sender`, or require `msg.sender == dstImmutables.taker.get()` in `createDstEscrow` before deployment, so that copied calldata from another address cannot compute the same salt/address and front-run the legitimate caller.

### Proof of Concept
1. Resolver Bob submits `createDstEscrow(dstImmutables, srcCancellationTimestamp)` with `msg.value` covering `safetyDeposit (+ amount if native)`.
2. Attacker Mallory observes this pending transaction, copies `dstImmutables` and `srcCancellationTimestamp` verbatim, and submits an identical call with higher gas price and equivalent `msg.value`/token approval.
3. Mallory's transaction is mined first; `_deployEscrow` succeeds, deploying the clone at `Create2.computeAddress(immutables.hash(), _PROXY_DST_BYTECODE_HASH)`.
4. Bob's original transaction is mined next; `cloneDeterministic` reverts because the same address already has code, reverting Bob's whole transaction and wasting his gas. [1](#0-0) [2](#0-1)

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    /**
     * @notice Deploys a new escrow contract.
     * @param salt The salt for the deterministic address computation.
     * @param value The value to be sent to the escrow contract.
     * @param implementation Address of the implementation.
     * @return escrow The address of the deployed escrow contract.

    function _deployEscrow(bytes32 salt, uint256 value, address implementation) internal virtual returns (address escrow) {
        escrow = implementation.cloneDeterministic(salt, value);
    }
```
