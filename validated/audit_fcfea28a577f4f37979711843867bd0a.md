### Title
`IdleCreditVault.setBorrower` can strand active pool principal with the previous borrower - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.setBorrower` changes the borrower at any time without checking whether pool principal has already been transferred to the current borrower. [1](#0-0)  At epoch start, the CDO sends its surplus underlying to the borrower currently configured in the strategy. [2](#0-1)  At epoch stop or pool close, it instead pulls repayment from the then-current borrower. [3](#0-2)  If the owner rotates borrowers while the old borrower holds the epoch funds, the repayment source changes after custody moved, causing the close-pool pull to fail and the default path to run. [4](#0-3) 

### Finding Description
The external Alchemix issue is an exact analog: an administrative pointer is switched without first ensuring that the old integration/counterparty has no remaining custody of user assets. Here, `setBorrower` only rejects the zero address and does not check `isEpochRunning`, `epochEndDate`, or any borrower-exposure flag. [1](#0-0) 

During `startEpoch`, `sendFundsToBorrower` transfers underlying to the address returned by the strategy's current borrower configuration. [2](#0-1)  During `stopEpoch`, `getFundsFromBorrower` performs `transferFrom` from the newly configured borrower, not from the address that originally received the principal. [5](#0-4)  There is no migration path that moves the old borrower's outstanding principal to the new borrower.

### Impact Explanation
A normal unprivileged depositor can create the exposed position; the triggering privileged action can be an ordinary operational borrower rotation rather than malicious behavior. If `owner` calls `setBorrower` after `startEpoch`, then a close-pool `stopEpoch(0, 1)` attempts to recover principal plus interest from the new borrower. Without a voluntary repayment and allowance from the new borrower, the transfer fails and `_handleBorrowerDefault` permanently stops the normal epoch state machine, prevents new withdrawal requests, and marks the vault defaulted. [6](#0-5) 

The affected amount can be the full borrower-held pool principal, e.g. 10,000 underlying units in the PoC. Recovery requires switching back or arranging manual repayment/approval from the original borrower; until then, lender principal and pending claims are frozen in the default/recovery flow.

### Likelihood Explanation
The function is owner-only, so the likelihood is lower than a fully unprivileged trigger. However, the invariant is easy to violate operationally because neither `setBorrower` nor the surrounding epoch state prevents rotation after custody has moved. [1](#0-0)  The codebase already applies this safer pattern to `ProgrammableBorrower.setBorrower`, which rejects changes while accounting is active or borrower debt remains outstanding, showing that the same risk is recognized on the programmable path. [7](#0-6) 

### Recommendation
Prevent `IdleCreditVault.setBorrower` while the configured borrower can still hold pool funds. The strongest fix is an explicit `borrowerExposure`/`principalOutstanding` ledger set when funds are sent to the borrower and cleared only after a successful full principal recall; `setBorrower` should revert while it is nonzero. At minimum, gate rotation on a successfully completed close-pool state rather than merely `!isEpochRunning`, because ordinary epoch stops can leave principal outstanding with the existing borrower.

### Proof of Concept
This Foundry test can be added to `test/foundry/IdleCreditVault.t.sol` in the existing `IdleCreditVault` test context:

```solidity
function testBorrowerRotationDuringEpochFreezesPrincipal() external {
    IdleCreditVault vault = IdleCreditVault(address(strategy));
    address newBorrower = makeAddr("newBorrower");
    uint256 amount = 10_000 * ONE_SCALE;

    // An unprivileged/KYC'd depositor creates the pool position.
    idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);

    uint256 oldBorrowerBefore = IERC20Detailed(defaultUnderlying).balanceOf(borrower);

    // Normal epoch start sends pool custody to the currently configured borrower.
    _toggleEpoch(true, 0, 0);
    assertTrue(cdoEpoch.isEpochRunning());
    assertEq(
        IERC20Detailed(defaultUnderlying).balanceOf(borrower) - oldBorrowerBefore,
        amount
    );

    // Operational borrower rotation succeeds even though borrower still holds principal.
    vm.prank(owner);
    vault.setBorrower(newBorrower);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Close-pool recall now targets newBorrower, not the address that received funds.
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 1);

    assertTrue(cdoEpoch.defaulted());
    assertFalse(cdoEpoch.isEpochRunning());
    assertEq(
        IERC20Detailed(defaultUnderlying).balanceOf(borrower),
        oldBorrowerBefore + amount,
        "pool principal remains with old borrower"
    );
}
```

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();

    // deposits should be already prevented
    if (!paused()) {
      _pause();

    // stop the current epoch
    isEpochRunning = false;

    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

  /// @notice Set the real borrower allowed to draw and repay funds.
  /// @dev Owner or manager. This is only allowed while the facility is idle with no borrower-side
  /// principal or interest exposure left to reconcile.
  /// @param _borrower borrower EOA or controller address
  function setBorrower(address _borrower) external {
    _checkOnlyOwnerOrManager();
    if (_borrower == address(0)) revert InvalidAddress();
    // Reassigning the borrower is unsafe while an epoch is active or while the previous borrower
    // still owes principal / interest, because repayment rights would move to a different address.
    if (epochAccountingActive || borrowerPrincipal != 0 || borrowerInterestAccrued != 0 || borrowerInterestDebt != 0) {
      revert NotAllowed();
    }
    borrower = _borrower;
    emit BorrowerSet(_borrower);
