### Title
Stale cached LDAP role/session grants a demoted or revoked user continued elevated access - ([File: core/sessions/ldapauth/ldap.go])

### Summary
The LDAP authentication provider caches a user's `email` + `role` locally in `ldap_sessions` and `ldap_user_api_tokens` at login/token-issuance time, but `AuthorizedUserWithSession` and `FindUserByAPIToken` authorize every subsequent request purely from this local cache instead of re-validating the user's current role against the LDAP directory. Reconciliation with the upstream source of truth only happens via a separate, opt-in background syncer (`LDAPServerStateSyncer`) whose `UpstreamSyncInterval` defaults to `'0s'` (disabled — the sync only runs once, at node startup). This is structurally the same root cause as the reported liquidation-config bug: once a privilege-relevant parameter (leverage tier / user role) changes, the code path that authorizes subsequent actions keeps using the value that was valid when the record was created, instead of applying the up-to-date configuration.

### Finding Description
`AuthorizedUserWithSession` reads role directly from the `ldap_sessions` table without contacting LDAP: [1](#0-0) 

`FindUserByAPIToken` does the same for `ldap_user_api_tokens`: [2](#0-1) 

The package-level doc comment claims "This sync happens for every auth endpoint hit, and via the defined sync interval," but neither `AuthorizedUserWithSession` nor `FindUserByAPIToken` invoke any sync/reconciliation logic — they only run a local SQL query against cached role data: [3](#0-2) 

The actual reconciliation with the upstream LDAP directory (which updates or purges stale roles/sessions) lives in `LDAPServerStateSyncer.Work`, gated by `UpstreamSyncInterval`: [4](#0-3) [5](#0-4) 

The default configuration disables the periodic timer entirely (`Work` fires once at startup only): [6](#0-5) 

The role-repair logic itself only runs inside `Work`'s upstream sync transaction: [7](#0-6) 

### Impact Explanation
If an operator demotes a user's LDAP group membership (e.g. removes them from `NodeAdmins`) or fully deactivates the account, any session cookie or API token issued to that user *before* the change continues to authorize requests at the old (higher) role for the full remainder of `SessionTimeout` (default 15m) or `UserAPITokenDuration` (default 240h/10 days), because `AuthorizedUserWithSession`/`FindUserByAPIToken` never re-check LDAP and the reconciling syncer is disabled by default. This is a session/role authorization bypass: a user whose privileges were revoked keeps elevated access (e.g., admin-only endpoints) for up to 10 days by default. Given default config, this is not merely theoretical — it's the out-of-the-box behavior.

### Likelihood Explanation
Likelihood is Medium: it requires the LDAP-based authentication method to be enabled (`WebServer.AuthenticationMethod = 'ldap'`), and requires the operator to actually revoke/demote a user upstream while that user still holds a live, un-expired session or API token. This is a realistic offboarding/role-change scenario for any node operator using LDAP-based RBAC — no attacker action is needed beyond continuing to use credentials obtained before revocation, i.e., an "unprivileged" (now-revoked) actor simply keeps making authenticated requests as before.

### Recommendation
Either (a) make `AuthorizedUserWithSession` and `FindUserByAPIToken` trigger a synchronous, rate-limited LDAP re-check (matching the doc comment's claim that sync happens "for every auth endpoint hit") before trusting the cached role, or (b) enforce a safe non-zero default for `UpstreamSyncInterval` and clearly document that a `'0s'` value leaves stale roles/sessions valid until manual restart. At minimum, shrink the trust window by re-validating role/active-status against LDAP on every privileged (e.g., admin-role-required) request rather than solely relying on the local cache populated at login/token-creation time.

### Proof of Concept
1. Configure `WebServer.AuthenticationMethod = 'ldap'` with default `[WebServer.LDAP] UpstreamSyncInterval = '0s'`.
2. User `alice@example.com` is a member of the `NodeAdmins` LDAP group; she logs in, and `ldap_sessions` caches `user_role = admin` for her session ID (or she creates a long-lived API token, cached in `ldap_user_api_tokens`).
3. Operator removes `alice` from `NodeAdmins` in the upstream LDAP directory (revoking admin access).
4. Because `UpstreamSyncInterval` is `'0s'`, `LDAPServerStateSyncer.run()` never fires again after node startup.
5. Alice continues calling admin-only endpoints using her existing session cookie/API token; `AuthorizedUserWithSession`/`FindUserByAPIToken` return `Role: admin` straight from the local cache, and `RequiresAdminRole` grants access, for up to `SessionTimeout`/`UserAPITokenDuration` — despite her upstream admin role having been revoked. // FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

func (l *ldapAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (sessions.User, error) {
	if len(sessionID) == 0 {
		return sessions.User{}, errors.New("session ID cannot be empty")
	}
	// Query the ldap_sessions table for given session ID, user role and email are cached so
	// no further upstream LDAP query is performed
	var foundSession struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	if err := l.ds.GetContext(ctx, &foundSession,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_sessions WHERE id = $1",
		sessionID, l.config.SessionTimeout().Duration(),
	); err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	if !foundSession.Valid {
		// Sessions expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE id = $1", sessionID); execErr != nil {
			l.lggr.Errorf("error purging stale ldap session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	return sessions.User{
		Email: foundSession.UserEmail,
		Role:  foundSession.UserRole,
	}, nil
}

	// If enabled, start a background task that calls the Sync/Work function on an

	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {

		go l.run()

		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}

	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
