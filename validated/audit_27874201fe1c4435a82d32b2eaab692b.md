### Title
Zip extraction follows attacker-planted symlinks to write files outside the job workspace ("Zip-Slip via symlink") - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipSymlinkEntry` creates a symlink on disk using the raw, unvalidated symlink target taken directly from the zip entry's data, and `extractZipFile`/`extractZipFileEntry` never check whether an intermediate path component of a later entry is a symlink before writing through it. An attacker who controls a zip's contents (e.g. an artifact/cache archive) can order a symlink entry before a file entry that shares the symlink's name as a path prefix, causing the final write to land outside the extraction root.

### Finding Description
`ExtractZipArchive` iterates `archive.File` sequentially and calls `extractZipFile(file)` for each entry [1](#0-0) . For a symlink-typed entry, `extractZipSymlinkEntry` reads the entry's data and calls `os.Symlink(string(data), file.Name)` with **no validation** that the target (`string(data)`) stays inside the extraction root [2](#0-1) . The target is fully attacker-controlled zip payload content — nothing normalizes or rejects an absolute path like `/etc` or `/host/...`.

For a subsequent regular-file entry whose `file.Name` uses the symlink's name as a directory prefix (e.g. `evil/payload`), `extractZipFile` first does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` [3](#0-2) . `os.MkdirAll` follows symlinks when checking whether the directory already exists (via `Lstat`/`Stat` semantics), so if `evil` is a symlink to an existing directory outside the workspace, `MkdirAll` silently succeeds without creating anything new. Then `extractZipFileEntry` executes `os.Remove(file.Name)` followed by `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` [4](#0-3)  — both operations resolve `evil/payload` through the symlink, so the actual file write lands at `<symlink-target>/payload` on the host or a sibling tenant's directory, not inside the job workspace.

The only existing path check in this pipeline is `errorIfGitDirectory`, which only rejects paths whose first component is literally `.git` [5](#0-4) ; it does nothing to detect or block symlink-based directory traversal. `pathErrorTracker.actionable` only deduplicates repeated `*os.PathError` log messages by `Op` — it has no bearing on path safety and does not block or alter execution [6](#0-5) . No component of the pipeline calls `os.Lstat` on intermediate path segments to verify they are plain directories confined to the extraction root before writing through them.

### Impact Explanation
An unprivileged pipeline author who controls the contents of an extracted zip (build artifacts downloaded and re-extracted, or any user-supplied zip fed into `ExtractZipFile`/`ExtractZipArchive`) can plant a symlink entry pointing at an arbitrary host path and a follow-up file entry to write attacker-controlled bytes through that symlink. This can overwrite or create files outside the job's sandboxed workspace — e.g., on the runner host filesystem or in a sibling tenant's cache/workspace directory when extraction happens in a shared filesystem context — matching the scoped impact of host file write/overwrite and potential cross-tenant workspace corruption.

### Likelihood Explanation
The exploit requires only the ability to author a zip file with attacker-chosen entries, which any pipeline author already has for artifacts and caches consumed by the Runner's extraction code. The ordering requirement (symlink entry before the dependent file entry) is trivially satisfiable by controlling entry order when building the zip. No additional privilege, race condition, or admin misconfiguration is needed — this is a straightforward, deterministic, and repeatable extraction-time logic bug.

### Recommendation
Before creating a symlink in `extractZipSymlinkEntry`, validate that the resolved target stays within the extraction root (reject absolute paths and any target whose cleaned, resolved path escapes the root). Before every `os.MkdirAll`/write in `extractZipFile`/`extractZipFileEntry`, verify each path component with `os.Lstat` to ensure no component is a symlink that would redirect the operation outside the intended extraction directory (or use a "jailed" path-resolution helper that resolves symlinks against a fixed root and rejects escapes), aborting/skipping the entry when an escape is detected. This is the same "zip-slip" family of fix already required for `file.Name` traversal (`../..`) and should be applied consistently to symlink targets and symlink-typed intermediate directories.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Build a zip with an entry `"evil"` of type `os.ModeSymlink` whose data is an absolute path to a temp directory outside the extraction working directory (e.g. `t.TempDir()` representing a "host"/"other tenant" directory).
2. Add a second entry `"evil/payload"` containing attacker bytes.
3. Call `ExtractZipFile(zipName)` from within a separate extraction working directory.
4. Assert that `<hostDir>/payload` was created/overwritten with the attacker's bytes (`os.ReadFile` equals expected content), proving the write escaped the extraction root — despite no file named `evil/payload` existing inside the intended working directory.
5. Add a comparison assertion using `os.Lstat` on `"evil"` (or intended parent) confirming it is a symlink, demonstrating that the current code performs no check to reject this before writing through it.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}

func (p *pathErrorTracker) actionable(e error) bool {
	pathErr, isPathErr := e.(*os.PathError)
	if e == nil || isPathErr && pathErr == nil {
		return false
	}

	if !isPathErr {
		return true
	}

	p.lock.Lock()
	defer p.lock.Unlock()

	seen := p.seenOps[pathErr.Op]
	p.seenOps[pathErr.Op] = true

	// actionable if *not* seen before
	return !seen
}
