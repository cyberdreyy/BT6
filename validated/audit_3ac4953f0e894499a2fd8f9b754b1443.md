### Title
Unbounded recursive descent in `TrieNode::decode` allows stack-exhaustion crash via crafted MPT preimages in the fault-proof program - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode::decode` recursively decodes RLP-encoded Merkle-Patricia-Trie nodes with **no depth limit**, mirroring the CVE-2021-41737 bug class (an unbounded recursive-descent parser that a crafted input drives into stack exhaustion). Any party that can supply an arbitrary preimage matching a keccak256 key requested by the fault-proof program (L1/L2 trie traversal in a dispute game) can nest `Extension` nodes inside a single preimage blob to drive unbounded native-stack recursion in the node/challenger process executing the fault-proof program off-chain.

### Finding Description
`TrieNode::decode` in [1](#0-0)  dispatches on the RLP header: for a 2-element list it treats it as a Leaf/Extension node and calls `try_decode_leaf_or_extension_payload`, which for an `Extension` prefix directly recurses via `Self::decode(buf)` on the remaining bytes of the *same* buffer [2](#0-1) .

Critically, this recursive call operates on whatever bytes are present in the already-fetched preimage — it is not limited to following a 32-byte hash reference to a new preimage. An `Extension` node's "value" slot can itself be an embedded RLP list (i.e., another `Extension`/`Leaf`/`Branch` encoded directly, without being blinded to a hash), so a single preimage can be crafted to contain thousands of nested `Extension` levels, each adding one stack frame to `TrieNode::decode` → `try_decode_leaf_or_extension_payload` → `TrieNode::decode` → ... with no depth counter or recursion-depth check anywhere in the type (contrast with `crates/proof/tee/registrar/src/cbor.rs`, which explicitly guards CBOR nesting with `MAX_CBOR_NESTING_DEPTH` [3](#0-2) , and with EIP-8130 decoding which enforces `MAX_CALL_PHASES_PER_TX` [4](#0-3) ).

`TrieNode::decode` is the entry point used by every `TrieProvider` implementation that resolves fault-proof preimages, including the untrusted, attacker-influenced oracle sources used during dispute-game execution:
- `OracleL1ChainProvider::trie_node_by_hash` [5](#0-4) 
- `OracleL2ChainProvider::trie_node_by_hash` [6](#0-5) 

Because a preimage is only bound to its key by a keccak256 hash check (content-addressed), an adversarial dispute-game party who knows a hash that the honest fault-proof program will request can supply *any* byte string hashing to that key — including a maliciously nested `Extension` chain — as long as they can get that value accepted into the preimage oracle before the honest party consumes it.

### Impact Explanation
A stack overflow in the process executing the fault-proof program (the challenger/proposer/verifier node performing off-chain trace generation for a dispute game) crashes that process (SIGSEGV/abort). If timed against a dispute-game response deadline, this can prevent the honest party from producing/verifying the required output in time, undermining the correctness of the fault-proof game and potentially leading to a wrong provable output root prevailing or an availability failure of the verifying node — impacts explicitly in scope ("node halt", "wrong provable output root").

### Likelihood Explanation
Exploitation requires an adversarial party in a dispute game to control (or race to supply) the preimage bytes for a hash the honest program will fetch, and to know the specific hash in advance so a matching malicious preimage can be crafted — this is a real but non-trivial precondition (content-addressing constrains which bytes can be substituted). It is nonetheless a genuine reachable defect: the recursion has literally no depth bound, unlike comparable decoders elsewhere in this codebase.

### Recommendation
Add an explicit recursion-depth (or iterative-with-explicit-stack) bound to `TrieNode::decode`/`try_decode_leaf_or_extension_payload`, analogous to `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`, and/or rewrite the extension-chain walk to be iterative rather than recursive so a crafted preimage cannot drive unbounded native call-stack growth.

### Proof of Concept
Construct a single RLP blob representing nested 2-element `Extension` lists: `rlp([path_1, rlp([path_2, rlp([path_3, ... rlp([path_n, blinded_leaf_hash])])])])`, where each `path_i` is a valid odd/even extension-prefix nibble string. Store this blob under its keccak256 hash in the preimage oracle so `TrieNode::decode` is invoked on it via `trie_node_by_hash`. Each nesting level costs only a few bytes of RLP overhead, so tens of thousands of levels fit comfortably within realistic preimage size limits, driving `TrieNode::decode`'s recursion deep enough to overflow the native stack of the process executing the fault-proof program.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
