### Title
Unauthenticated LOOP plugin pprof endpoint discloses process memory/goroutine dumps - ([File: core/web/router.go])

### Summary
The `/plugins/:name/debug/pprof/*profile` route (and its `symbol` POST counterpart) registered by `loopRoutes` in `core/web/router.go` is mounted on the base `api` router group without any authentication middleware, unlike every other sensitive route (`/debug/vars`, `/v2/*`, `sessions`). `LoopRegistryServer.pluginPPROFHandler` forwards the request unmodified to the target LOOP plugin's internal pprof server and returns the raw profile bytes to the caller.

### Finding Description
`NewRouter` builds an `api` group with only rate limiting and session middleware attached, and calls `loopRoutes(app, api)` directly (`core/web/router.go:87-91`). Inside `loopRoutes`, `r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)` and `r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)` are registered with no `auth.Authenticate(...)` wrapper (`core/web/router.go:230-236`). Compare this to `debugRoutes`, which wraps `/debug/vars` in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (`core/web/router.go:180-183`), and `metricRoutes` (the node's own pprof), which is only mounted inside the session/token-authenticated `authv2` group (`core/web/router.go:445-446`).

`pluginPPROFHandler` (`core/web/loop_registry.go:150-166`) takes the `:name` and `*profile` path params plus query params (`debug`, `gc`, `seconds`), looks up the plugin in the LOOP registry, builds a URL to the plugin's internal `/debug/pprof/<profile>` endpoint, and calls `doRequest`, which performs the HTTP GET and streams the response body back to the caller with `gc.Data(http.StatusOK, ...)`. No caller identity/session/token check occurs anywhere in this path, so any unauthenticated network client that can reach the node's HTTP listener can request `heap`, `goroutine`, `profile`, `allocs`, etc. for any registered LOOP plugin.

### Impact Explanation
This matches the Chainlink bounty "sensitive information disclosure" class: an unauthenticated request can retrieve heap/goroutine dumps of a LOOP plugin process. Plugin processes (e.g., relayer/medianizer LOOPs) may hold private key material, signed payloads, or other sensitive data in memory; a heap or goroutine dump could leak this. The impact is limited to what happens to reside in the target plugin's memory at scrape time, but no credential of any kind is required to trigger the dump remotely.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only network reachability to the Chainlink node's HTTP API (no session cookie, API token, or role) and knowledge of a registered plugin name (enumerable via the also-unauthenticated `/discovery` and `/plugins/:name/metrics` endpoints on the same route group). The request is a single unauthenticated `GET /plugins/<name>/debug/pprof/heap`, fully repeatable and requires no special conditions on the node's configuration beyond having LOOP plugins registered.

### Recommendation
Wrap `loopRoutes` (or at minimum the pprof-forwarding routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `authv2`/`metricRoutes`, and consider requiring an admin role (`auth.RequiresAdminRole`) given the sensitivity of raw memory dumps, mirroring how `/debug/vars` and the node's own `/debug/pprof/*` are protected.

### Proof of Concept
Go handler-level integration test plan (in `core/web` test package, alongside `loop_registry_internal_test.go`):
1. Build the full router via `NewRouter` (or the test harness used in existing `core/web` route tests) with a `LoopRegistry` containing a fake registered plugin (`p.EnvCfg.PrometheusPort` pointing to a local `httptest.Server` that serves a canned pprof-like body on `/debug/pprof/heap`).
2. Issue `httptest.NewRequest("GET", "/plugins/<name>/debug/pprof/heap", nil)` with no `Authorization` header, no session cookie.
3. Serve it through the router and assert: response status is `200` and the body equals the canned upstream body — demonstrating profile data is returned with zero credentials, in contrast to hitting `/v2/build_info` or `/debug/vars` without credentials, which should return `401`.
4. Add a comparison assertion: same unauthenticated request to `/debug/pprof/heap` (the node's own, `metricRoutes`) returns `401`, highlighting the inconsistency confirming the vulnerability is specific to the LOOP plugin forwarder.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
