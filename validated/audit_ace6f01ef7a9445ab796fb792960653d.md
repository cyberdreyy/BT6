**Analysis:**

The `vest` function is deliberately permissionless — anyone can call `vest(contract_address)` for any vesting contract, just like `vest_many`, `unlock_rewards`, and `distribute`. This is intentional design: since Move entry functions can't take arbitrary "caller-benefits" redirection here, calling this function only advances internal contract state; it never lets the caller redirect funds to themselves. [1](#0-0) 

The suspected overflow/over-unlock scenario doesn't hold up because of two independent safeguards in the code:

1. **Only one period is advanced per call, not all elapsed periods.** Even if `fast_forward` skips far beyond `last_completed_period`, the function computes `next_period_to_vest = last_vested_period + 1` and only checks `last_completed_period >= next_period_to_vest` as a gate — it does not multiply the vesting fraction by the number of elapsed periods. Each call vests exactly one period's fraction (or the last schedule fraction repeated), and `last_vested_period` increments by exactly 1 per successful call. [2](#0-1) 

2. **The vested amount is explicitly capped by `remaining_grant`, and `remaining_grant` is monotonically decremented.** `vested_amount = min(vested_amount, vesting_contract.remaining_grant); vesting_contract.remaining_grant -= vested_amount;` guarantees `remaining_grant` can never go negative, and the sum of all vested amounts across any number of calls can never exceed the original `remaining_grant`. Once `remaining_grant` reaches 0, subsequent calls vest 0. [3](#0-2) 

This matches the framework's own test coverage (`test_vest`, `test_last_vest_should_distribute_remaining_amount`), which explicitly fast-forwards through multiple periods and asserts that `remaining_grant` decreases exactly by the vested amount each call, never going negative or exceeding the schedule. [4](#0-3) 

Additionally, unlocked funds go into the vesting contract's own stake pool (`pending_inactive`) and are later distributed pro-rata to shareholders via `grant_pool` shares in `distribute` — not to the caller of `vest`. So even a repeated/malicious call pattern by an unprivileged account cannot redirect, steal, or over-mint value; it can at most just be a "free" service call that advances legitimate vesting on schedule. [5](#0-4) 

The stated invariant ("vested amount never exceeds remaining_grant") is enforced directly by the `min()` cap and decrement pattern, and there is no path by which an unprivileged caller can bypass this or redirect the unlocked stake to their own benefit.

        let last_vested_period = vesting_schedule.last_vested_period;

            return

        // Calculate how much has vested, excluding rewards.
        // Index is 0-based while period is 1-based so we need to subtract 1.
        let schedule = &vesting_schedule.schedule;
        let schedule_index = next_period_to_vest - 1;
        let vesting_fraction = if (schedule_index < schedule.length()) {
            schedule[schedule_index]
        } else {
            // Last vesting schedule fraction will repeat until the grant runs out.
            schedule[schedule.length() - 1]
        };
        let total_grant = vesting_contract.grant_pool.total_coins();
        let vested_amount = fixed_point32::multiply_u64(total_grant, vesting_fraction);

        vesting_contract.remaining_grant -= vested_amount;

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });
