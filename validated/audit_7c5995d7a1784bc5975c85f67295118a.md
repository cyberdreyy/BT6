### Title
Unauthenticated `PATCH /v2/resume/:runID` allows any anonymous caller to inject arbitrary results/errors into any suspended pipeline run - ([File: core/web/router.go])

### Summary
The Chainlink node registers the pipeline run "resume" endpoint on an unauthenticated router group, guarded only by knowledge of a `runID` UUID. This is directly analogous to `RewardsDistributor::triggerRoot`: a state-mutating function that is reachable by any unprivileged caller and whose only "access control" is possession of an opaque value (there, matching root candidate hashes; here, guessing/leaking a UUID), allowing an attacker to corrupt/override run state repeatedly.

### Finding Description
`v2Routes` mounts `PipelineRunsController.Resume` on `unauthedv2 := r.Group("/v2")` with no auth middleware at all: [1](#0-0) 

Compare this to every other mutating route in the same function, which is wrapped in `authv2` (session/token auth) or `userOrEI` (external-initiator/token/session auth with `RequiresRunRole`): [2](#0-1) 

The handler itself performs no authentication or ownership check — it parses the `runID` from the URL, decodes an attacker-supplied JSON body into a `pipeline.ResumeRequest`, and directly calls `App.ResumeJobV2` with the attacker-controlled value/error: [3](#0-2) 

`ResumeJobV2` forwards straight to the pipeline runner, which updates the task run's `output`/`error` in the DB and, if the run was suspended, resumes/restarts pipeline execution with that attacker-supplied value: [4](#0-3) [5](#0-4) [6](#0-5) 

Like `triggerRoot`, which lets anyone repeatedly overwrite `root.value`/`root.lastUpdatedAt` because the only "authorization" is matching a public/derivable value (`rootCandidateA == rootCandidateB`), `Resume` lets anyone repeatedly overwrite a suspended task run's result because the only "authorization" is knowing the `runID` UUID — there is no binding to the external initiator, bridge, or user that actually owns that run. The route is explicitly named `UnauthedRunResumed` in the audit log, confirming this is a deliberately unauthenticated code path rather than an oversight in a stray route: [7](#0-6) 

### Impact Explanation
An attacker who obtains or guesses a pending `runID` (e.g., leaked in logs, UI, webhook callback URLs, or via enumeration/timing) can:
- Inject a forged bridge/adapter result or error into a suspended job run, corrupting downstream task outputs (e.g., poisoning a median/aggregation task feeding an on-chain report), analogous to the report's "overwrite root value" impact.
- Repeatedly call the same endpoint to resume/restart a run with different payloads, since nothing prevents replays or resets the resumable state after first use in the way the report's `triggerRoot` could be replayed because `rootCandidateA`/`B` were never cleared.
- Cause denial-of-service on legitimate bridge callbacks by resuming (and thus finalizing) the task before the legitimate adapter responds, similarly to how repeated `triggerRoot` calls block/"unpause" claims by racing legitimate state transitions.

### Likelihood Explanation
Likelihood depends on `runID` (a UUID) confidentiality. Since it is not cryptographically bound to caller identity (unlike the `AccessKey`/`Secret` pair required by `AuthenticateExternalInitiator`) and is deliberately left unauthenticated for legitimate async bridge/webhook adapters to call back, any leak of a UUID (through logs, response bodies, browser history, or a compromised low-trust component) grants a fully unprivileged attacker write access to that specific pipeline run's outcome. This mirrors the report's classification of the bug as exploitable by "anyone" without special privileges.

### Recommendation
- Bind the resume capability to the entity that owns/created the corresponding pending task (e.g., require a per-run secret/HMAC token issued when the async task was created, verified in constant time, similar to `bridges.AuthenticateExternalInitiator`), rather than relying solely on UUID secrecy.
- Ensure a task can only be resumed once (or make it idempotent per issued token) so repeated/racing resume calls cannot be used to overwrite results after a first legitimate completion.
- Rate-limit and audit-log failed/duplicate resume attempts distinctly from successful ones to detect brute-force guessing of `runID`.

### Proof of Concept
1. Create (or observe) a webhook/bridge job whose pipeline contains an async/bridge task, causing a `pipeline_task_runs` row with a `RunStatusSuspended` state and a task UUID (`runID`).
2. Obtain the `runID` (e.g., via logs, leaked response, or brute force since it's a UUID with no rate limiting tied to the resume endpoint's own auth).
3. Send `PATCH /v2/resume/<runID>` with an attacker-chosen JSON body (`{"error": "..."}` or `{"data": {...}}`) without any credentials — the route has no auth middleware:
```
core/web/router.go:243  unauthedv2.PATCH("/resume/:runID", prc.Resume)
```
4. `PipelineRunsController.Resume` decodes the body and calls `App.ResumeJobV2`, which updates `pipeline_task_runs.output`/`error` and resumes/restarts the run with the attacker's payload, regardless of who legitimately owns that run.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
