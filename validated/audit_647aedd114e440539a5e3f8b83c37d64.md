### Title
Signer global-state agreement threshold uses floor rounding while the canonical block-approval threshold uses ceiling, letting a signer adopt an unapproved miner/state below the true supermajority - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The signer's `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` compute the 70% supermajority threshold with plain integer (floor) division, while the canonical, on-chain-enforced threshold computed by `NakamotoBlockHeader::compute_voting_weight_threshold` (used in `verify_signer_signatures`, the function that actually validates a block's signer signatures) rounds the same threshold **up**. For any `total_weight` where `total_weight * 7` is not a multiple of 10 (the common case), the two thresholds differ by exactly one unit of signer weight. This lets the signer's local StackerDB-gossip-driven "global state" (current miner, burn view, active protocol version, tx replay set) flip to a new value one weight-unit *before* the actual 70% supermajority required by consensus is reached.

### Finding Description
`GlobalStateEvaluator::reached_agreement` computes the threshold as: [1](#0-0) 

and `reached_disagreement` mirrors this with `10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`: [2](#0-1) 

Both divide by 10 with truncation (floor), never rounding up.

Meanwhile, the canonical threshold used to actually validate that a Nakamoto block has enough signer signatures (`verify_signer_signatures`) is computed with an explicit ceiling adjustment: [3](#0-2) 

and this ceiling behavior is confirmed by the repo's own test (`total_weight=511` → `357` floor vs `358` ceil): [4](#0-3) 

`reached_agreement` (floor) is the function driving `determine_global_state`, which decides the signer's adopted view of the active miner, burn block view, active protocol version, and replay set from weighted StackerDB gossip updates: [5](#0-4) 

That adopted `current_miner` is then used directly to accept or reject block proposals in `GlobalStateView::check_proposal`: [6](#0-5) 

Because `reached_agreement`'s floor-rounded threshold is strictly lower (by up to 1 weight unit) than the ceiling-rounded threshold the network actually enforces for block-signature acceptance, a signer can conclude that global consensus on a new active miner/tenure/burn-view/protocol-version has been reached at a total supporting weight that would be **insufficient** to satisfy the canonical 70% supermajority rule enforced by `compute_voting_weight_threshold`/`verify_signer_signatures`. This breaks the equality that should hold between "the weight the signer accepts as globally agreed" and "the weight the protocol actually requires for a supermajority."

### Impact Explanation
This is a genuine equality break between two representations of the same protocol constant (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`) computed with different rounding in two places that must stay consistent: the signer's own state-machine agreement gate and the chain's block-signature-acceptance gate. A signer can switch its notion of the currently active miner/tenure one weight-unit below the true supermajority, then sign block proposals for that miner based on `check_proposal`'s `current_miner` check — i.e., signing/approving blocks for a tenure that has not actually reached the canonical 70% ceiling-rounded threshold enforced elsewhere in the protocol. This is a Critical-class analog: it lets a signer act on/sign for a state transition (miner switch) that was never truly approved by a genuine supermajority, i.e., a rejection-vs-acceptance/threshold miscount in the signer's own consensus logic.

### Likelihood Explanation
The discrepancy is systemic, not attacker-crafted: it occurs whenever `total_weight * 7 mod 10 != 0`, which is the case for roughly 9 out of 10 possible total-weight values (any reward set whose total weight isn't a multiple of 10). No majority collusion or privileged key is needed — any set of ordinary signer weight-updates gossiped over StackerDB that lands exactly on the floor-threshold boundary (one weight unit below the true ceiling threshold) will trigger `determine_global_state` to "lock in" a value that the on-chain block-acceptance rule would not yet honor.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same ceiling-rounding logic as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, have both call a single shared threshold function) so the signer's local agreement gate can never be satisfied by less weight than the canonical on-chain supermajority requires.

### Proof of Concept
1. Configure/observe a reward set whose total signer weight is e.g. `511` (any value where `total_weight * 7 % 10 != 0`).
2. Per `compute_voting_weight_threshold`, the canonical supermajority requirement is `358` [7](#0-6) .
3. Via normal StackerDB gossip, accumulate `StateMachineUpdate`s (e.g., proposing a new active miner) from signers whose combined weight is `357` (satisfies `reached_agreement`'s floor threshold `(511*7)/10 = 357` per `libsigner/src/v0/signer_state.rs:171-175`) but is one unit short of the real `358` requirement.
4. `determine_global_state` (`libsigner/src/v0/signer_state.rs:101-144`) returns this as the adopted `SignerStateMachine`, updating `current_miner`.
5. `GlobalStateView::check_proposal` (`stacks-signer/src/chainstate/v2.rs:111-135`) then accepts/validates block proposals against this prematurely-adopted miner state, even though the network-level `verify_signer_signatures` threshold for that same weight distribution would require `358`, one unit more than what the signer's own gate demanded.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
