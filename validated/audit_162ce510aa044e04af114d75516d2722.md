### Title
Stale/incremental allowlist sync in `workflowRegistry.syncAllowlistedRequests` allows a revoked authorization to remain valid until its original expiry - ([File: core/services/workflows/syncer/v2/workflow_registry.go])

### Summary
The Napier report describes an attacker exploiting the window between an authoritative state change (LST/LRT price drop) and its propagation into the protocol's local accounting to redeem funds under stale, more-favorable terms. The Vault capability's allowlist-based authorization (`AllowListBasedAuth`) has an analogous stale-cache window: local node state (`workflowRegistry.allowListedRequests`) is refreshed from the on-chain `WorkflowRegistry` only on a periodic ticker, and previously-synced entries are dropped **only** when their own `ExpiryTimestamp` elapses [1](#0-0) , never when the underlying on-chain permission is revoked/replaced before its natural expiry.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` authorizes a `jsonrpc.Request` purely by matching its digest against the syncer's in-memory `GetAllowlistedRequests()` snapshot and checking `ExpiryTimestamp` against wall-clock time [2](#0-1) . That in-memory snapshot is maintained by `syncAllowlistedRequests`, which on each tick fetches only `newAllowListedRequests` from the chain, keeps every previously-cached, non-expired request, and appends the new ones: [3](#0-2) 

There is no code path in this loop that removes a previously-synced `WorkflowRegistryOwnerAllowlistedRequest` in response to an on-chain revocation/replacement event - the only pruning condition is `ExpiryTimestamp > now`. Combined with `allowListBasedAuthRetryInterval` (3s) × `allowListBasedAuthRetryCount` (10) = up to 30s of retrying against whatever is currently cached [4](#0-3) , a node's authorization decision for a given request digest is driven entirely by whatever was last synced, with no mechanism shown to reconcile an on-chain revocation ahead of the recorded expiry.

This mirrors the Napier bug class precisely: an unprivileged actor (a workflow owner who requested and received an allowlisted digest) can act on a locally-cached permission that is stale relative to the authoritative on-chain source, and successfully authorize a Vault Create/Update/Delete-secret request (`vaulttypes.MethodSecretsCreate` etc., see `gw_handler_test.go`) even after that permission should no longer be honored, as long as the syncer has not yet reconciled the revocation and the cached `ExpiryTimestamp` has not yet elapsed.

### Impact Explanation
If the on-chain registry supports revoking/superseding an owner-allowlisted request ahead of its expiry (e.g. because a workflow was redeployed, a key was compromised, or an operator intervened), a node relying on `allowListBasedAuth` will continue to accept the stale digest for CreateSecrets/UpdateSecrets/DeleteSecrets vault operations until its cached copy naturally expires, since no removal reconciliation exists in `syncAllowlistedRequests`. This is a concrete allowlist-bypass window that lets a request that should be de-authorized still execute vault secret writes, which is unauthorized-action impact on the internet-facing Vault gateway path.

### Likelihood Explanation
The likelihood is moderate and depends on two external facts not fully verifiable from the indexed snippets alone: (1) whether the on-chain `WorkflowRegistry` contract exposes an explicit removal/revocation instruction distinct from natural `ExpiryTimestamp` elapsing, and (2) the exact semantics of `getAllowlistedRequests`'s incremental fetch (count-based delta vs. full resync). The code as written clearly only prunes by expiry, so if a revocation mechanism exists on-chain, this cache-staleness bypass is directly reachable by any workflow owner holding a previously-issued digest, with no additional privilege required.

### Recommendation
Have `syncAllowlistedRequests` perform a full reconciliation against the authoritative on-chain state each tick (or process explicit revocation events) instead of only appending new entries and pruning by local expiry, so that on-chain revocations are reflected in `allowListedRequests` promptly. Alternatively, re-verify the specific request digest directly against the chain (or a short-TTL cache) at authorization time rather than trusting a snapshot that can only grow monotonically between reconciliations.

### Proof of Concept
1. Workflow owner obtains an on-chain allowlisted request with `ExpiryTimestamp` set far in the future (e.g., 24h) and gets it synced into node's `allowListedRequests` cache [5](#0-4) .
2. Operator/owner revokes this permission on-chain (assuming a revoke path exists in the registry contract) before the 24h expiry.
3. `syncAllowlistedRequests`'s next tick fetches only `newAllowListedRequests`; the revoked entry is not removed because it is still non-expired, so it remains in `w.allowListedRequests`.
4. Attacker/owner submits `Tranche`-analog vault requests (`vaulttypes.MethodSecretsCreate`/Update/Delete) using the still-cached digest; `allowListBasedAuth.AuthorizeRequest` matches the stale entry and authorizes the request [6](#0-5) , even though the on-chain permission was revoked.

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
		}

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
