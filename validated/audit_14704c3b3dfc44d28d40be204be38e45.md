### Title
Cross-user response hijacking via attacker-controlled `MessageId` collision in `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Finding Description
`handleWebAPITriggerMessage` correlates a DON node's response to a waiting HTTP caller purely by `msg.Body.MessageId`, with no binding to the original sender/address: [1](#0-0) 

The map is populated in `HandleLegacyUserMessage`, which stores the caller's `callback` under `msg.Body.MessageId` **without checking whether an entry already exists** for that ID: [2](#0-1) 

`MessageId` is fully attacker-controlled: `Message.Validate()` only enforces a length bound (1–128 bytes) and a "no trailing null byte" rule — it does not enforce randomness or uniqueness: [3](#0-2) 

Because the message signature is computed over `MessageId || Method || DonId || Receiver || Payload` (see `GetRawMessageBody`), any signer (attacker's own valid key) can freely choose an arbitrary `MessageId`, including one already in flight for another caller, and produce a validly-signed message for that ID: [4](#0-3) 

Exploit flow:
1. User A calls the gateway HTTP endpoint, which routes through `gateway.ProcessRequest` → `HandleLegacyUserMessage`, storing A's callback under `savedCallbacks["X"]` and forwarding the signed request to all DON members.
2. Before the DON responds, the attacker submits their own signed `HandleLegacyUserMessage` request to the same DON (`DonId` is a public, non-secret routing field) reusing `MessageId = "X"`. This unconditionally overwrites `savedCallbacks["X"]` with the attacker's callback.
3. When a node's response for ID `"X"` arrives (which is simply the DON's echo of the original triggering message body, per `handleWebAPITriggerMessage` / `codec.EncodeLegacyResponse(msg)`), `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks["X"]` — delivering the response to whichever callback is currently registered, i.e., the attacker's, not user A's. User A's request will instead time out (or, if the race is reversed, A could receive the attacker's response).

This is not stopped by any existing check: `HandleNodeMessage` only verifies that the responding node's address matches the message's `Sender` field, which validates *node* identity, not which *user* request the response is destined for: [5](#0-4) 

The existing test suite documents the "first response wins, others dropped" behavior but does not test for cross-caller isolation when two different signers race the same `MessageId`: [6](#0-5) 

### Impact Explanation
An unauthenticated (but message-signing-capable) attacker can hijack another in-flight legacy gateway trigger response by racing a duplicate, attacker-chosen `MessageId` on the same DON before the legitimate response returns. This breaks the isolation invariant between concurrent gateway users: the victim's request silently fails/times out and the DON's echoed response (which reflects the original request's payload/topics/params) is delivered to the attacker's HTTP connection instead of the rightful caller — a cross-user response confusion/disclosure that matches Chainlink's "unauthorized access to another user's data/response" bounty impact class.

### Likelihood Explanation
Exploitability requires only: (1) ability to sign and submit gateway requests (any keyholder, not privileged), (2) knowledge of the target `MessageId` — which for many client implementations may be predictable/sequential/observable — and (3) winning a race window between the victim's request submission and the DON's response. No authentication bypass, admin access, or node compromise is required, only a timing race with a guessable or leaked identifier, which is a realistic scenario given `MessageId` values are visible to anyone if reflected anywhere (logs, error messages, or if clients use non-random schemes).

### Recommendation
Bind `savedCallbacks` entries to `(Sender, MessageId)` rather than `MessageId` alone, and reject (rather than silently overwrite) `HandleLegacyUserMessage` calls whose `MessageId` already has a live, un-expired entry from a different sender. Additionally, verify on response delivery in `handleWebAPITriggerMessage` that the response's underlying originating sender matches the sender recorded when the callback was saved.

### Proof of Concept
Add a handler-level Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build handler via `setupHandler(t)`.
2. Craft `msgA := triggerRequest(t, userAKey, ..., messageID="X", ...)`, call `handler.HandleLegacyUserMessage(ctx, msgA, cbA)`.
3. Before responding, craft `msgB := triggerRequest(t, attackerKey, ..., messageID="X", ...)` with different payload/topics, call `handler.HandleLegacyUserMessage(ctx, msgB, cbB)`.
4. Assert `handler.savedCallbacks["X"]` now equals the callback saved for `msgB` (overwritten), not `cbA`.
5. Simulate node response for the original message A (`hc.ValidatedResponseFromMessage(msgA)`), call `handler.HandleNodeMessage`.
6. Assert `cbB.Wait()` receives the response containing `msgA`'s payload (attacker receives victim's data) while `cbA.Wait()` times out — proving isolation is broken.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

// Message signatures are over the following data:
//  1. MessageId aligned to 128 bytes
//  2. Method aligned to 64 bytes
//  3. DonId aligned to 64 bytes
//  4. Receiver (in hex) aligned to 42 bytes
//  5. Payload (raw bytes before parsing)
func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
