### Title
Missing signature-linkage check in `urlResolver.Resolve` allows attacker-controlled CA chain injection - ([File: helpers/tls/ca_chain/helpers.go])

### Summary
`urlResolver.Resolve` in `helpers/tls/ca_chain/resolver_url.go` fetches an "issuer" certificate from the `IssuingCertificateURL` (AIA extension) embedded in a peer's TLS certificate and appends it to the chain without ever verifying that the fetched certificate's public key actually signed the previous certificate in the chain. `decodeCertificate` will happily parse and return a certificate object out of PEM, DER, or a PKCS7 blob whose Subject/Issuer are entirely attacker-chosen, and this object flows straight into `defaultBuilder.certificates` via `addCertificate`.

### Finding Description
`decodeCertificate` (`helpers/tls/ca_chain/helpers.go:46-75`) attempts PEM decode, then `x509.ParseCertificate`, then falls back to `pkcs7.Parse`, returning `p.Certificates[0]` on success. None of these paths validate that the returned certificate relates in any way to the certificate that requested it — they only require the bytes to be a syntactically valid X.509/PKCS7 structure. [1](#0-0) 

This decoder is invoked from `urlResolver.fetchIssuerCertificate`, which fetches attacker-controllable bytes from `cert.IssuingCertificateURL[0]` (a URL taken directly from the peer's certificate, i.e., from a TLS endpoint the attacker/job can control, e.g. a self-hosted registry, GitLab instance URL configured in job/runner config, or any HTTPS URL a job interacts with that ends up in a `tls.ConnectionState`). [2](#0-1) 

`urlResolver.Resolve` then appends the returned `newCert` directly onto the `certs` slice and only checks `isSelfSigned(newCert)` to decide whether to continue looping — it never calls `certificate.CheckSignatureFrom(newCert)` (or equivalent) to confirm `newCert` is cryptographically the issuer of the previous certificate in the chain: [3](#0-2) 

The resulting `certs` slice — potentially containing an unrelated, attacker-supplied certificate — is passed to `verifyResolver.Resolve` (`resolver_verify.go`), which only checks whether the **last** certificate in the slice can be verified against the system root store via `cert.Verify(x509.VerifyOptions{})`, and if that fails with `x509.UnknownAuthorityError` it simply returns the chain unchanged rather than rejecting it: [4](#0-3) 

Finally, `defaultBuilder.addCertificate` deduplicates by signature hash and appends every certificate from the resolved chain into `b.certificates`, with no chain-linkage validation at this layer either: [5](#0-4) 

So the invariant "certificates appended to the chain must cryptographically chain to the leaf" is not enforced anywhere in this pipeline for the intermediate certificates fetched via AIA URL — only for the very last certificate's relationship to the system root pool, and even that check is skipped/ignored on failure.

### Impact Explanation
`defaultBuilder.String()` serializes `b.certificates` into a PEM bundle that is fed into an executor's TLS configuration (as the resolved CA chain for a peer connection, e.g. used by `network/client.go`). An attacker who controls a TLS endpoint the Runner connects to (via `IssuingCertificateURL` pointing at attacker infrastructure) can inject an arbitrary, well-formed but unrelated certificate object into this chain string. The practical impact is limited by the fact that `defaultBuilder.certificates` is only used to build a diagnostic/definitive CA bundle for TLS setup, not to directly extend trust decisions made independently by Go's `crypto/tls`/`crypto/x509` verification (which already succeeded via `tls.VerifiedChains` before this code runs) — real certificate trust decisions for the actual connection have already happened via the standard TLS handshake and `tls.ConnectionState.VerifiedChains` before `BuildChainFromTLSConnectionState` is even called. This code only augments/re-serializes an already-verified chain for logging/CA-bundle purposes, so the unrelated injected certificate does not itself grant the attacker code execution, secret exfiltration, or the ability to bypass sandboxing/authentication for another job — it can pollute the constructed CA-chain string/log output with foreign certificate data.

### Likelihood Explanation
The precondition (attacker serves a TLS certificate with a fetchable `IssuingCertificateURL` and controls the content served at that URL) is realistic for any job/runner configuration where the Runner connects to an attacker-influenced HTTPS endpoint (self-hosted registry, custom GitLab URL, git remote, etc.) and `resolveFullChain` is enabled. The missing `CheckSignatureFrom` check is straightforward and reliably triggerable — no timing races or privilege escalation needed to reach `decodeCertificate`/`urlResolver.Resolve`.

### Recommendation
In `urlResolver.Resolve`, after decoding `newCert`, verify that it actually issued `certificate` before appending it, e.g.:
```go
if err := certificate.CheckSignatureFrom(newCert); err != nil {
    return nil, fmt.Errorf("fetched issuer certificate does not verify signature of previous certificate: %w", err)
}
```
Reject the fetched certificate (and abort/stop the loop) rather than appending it if this check fails. Additionally, `verifyResolver.Resolve` should pass the already-collected intermediates via `x509.VerifyOptions{Intermediates: ...}` so the full chain linkage is actually validated end-to-end, not just the last hop against system roots.

### Proof of Concept
Go unit test targeting `urlResolver.Resolve` with a mocked `fetcher`/`decoder`:
```go
func TestResolve_RejectsUnrelatedIssuerCert(t *testing.T) {
    leaf := loadCertWithIssuingURL(t, "http://attacker.example/ca.crt")
    unrelatedCert := loadUnrelatedValidCert(t) // valid, self-signed, but NOT leaf's actual issuer

    mockFetcher := &mockFetcher{data: unrelatedCert.Raw}
    r := &urlResolver{
        logger:    logrus.New(),
        fetcher:   mockFetcher,
        decoder:   decodeCertificate,
        loopLimit: defaultURLResolverLoopLimit,
    }

    result, err := r.Resolve([]*x509.Certificate{leaf})

    // Expected (fixed) behavior: err != nil or len(result) == 1 (unrelated cert not appended)
    // Current (buggy) behavior: len(result) == 2, result[1] == unrelatedCert
    require.True(t, err != nil || len(result) == 1,
        "unrelated issuer certificate must not be appended to the chain without signature verification")
}
```
Assertion: with the current code, `result` contains the unrelated certificate and no error is returned, demonstrating the missing linkage check. After adding `CheckSignatureFrom`, the test should fail fast with an error and the unrelated cert must not be present in `result`.

func (r *urlResolver) fetchIssuerCertificate(cert *x509.Certificate) (*x509.Certificate, error) {
	log := prepareCertificateLogger(r.logger, cert).
		WithField("method", "fetchIssuerCertificate")

	issuerURL := cert.IssuingCertificateURL[0]

	log.WithField("issuerURL", issuerURL).Debug("Fetching issuer certificate")
	data, err := r.fetcher.Fetch(issuerURL)
	if err != nil {
		log.
			WithError(err).
			WithField("issuerURL", issuerURL).
			Warning("Remote certificate fetching error")

		return nil, fmt.Errorf("remote fetch failure: %w", err)
	}

	newCert, err := r.decoder(data)
	if err != nil {
		log.
			WithError(err).
			Warning("Certificate decoding error")

		return nil, fmt.Errorf("decoding failure: %w", err)
	}

	if newCert == nil {
		log.Debug("Issuer certificate file decoded properly but did not include any certificates")
		return nil, nil
	}

	preparePrefixedCertificateLogger(log, newCert, "newCert").
		Debug("Appending the certificate to the chain")

	return newCert, nil
```

func (r *verifyResolver) Resolve(certs []*x509.Certificate) ([]*x509.Certificate, error) {
	if len(certs) < 1 {
		return certs, nil
	}

	lastCert := certs[len(certs)-1]

	if isSelfSigned(lastCert) {
		return certs, nil
	}

	prepareCertificateLogger(r.logger, lastCert).
		Debug("Verifying last certificate to find the final root certificate")

	verifyChains, err := r.verifier(lastCert)
	if err != nil {
		_, ok := err.(x509.UnknownAuthorityError)
		if ok {
			prepareCertificateLogger(r.logger, lastCert).
				WithError(err).
				Warning("Last certificate signed by unknown authority; will not update the chain")

			return certs, nil
		}

		return nil, fmt.Errorf("error while verifying last certificate from the chain: %w", err)
	}
```

func (b *defaultBuilder) addCertificate(certificate *x509.Certificate) {
	signature := hex.EncodeToString(certificate.Signature)
	if b.seenCertificates[signature] {
		return
	}

	b.seenCertificates[signature] = true
	b.certificates = append(b.certificates, certificate)
}
