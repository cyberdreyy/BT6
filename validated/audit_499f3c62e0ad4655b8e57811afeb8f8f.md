### Title
Missing role check on `GET /v2/external_initiators` exposes external-initiator `AccessKey` and `OutgoingToken` credentials to view-role users - ([File: core/web/router.go])

### Summary
The route `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` is wired without any `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, unlike its sibling `POST`/`DELETE` routes on the same resource. Any authenticated user — including the lowest-privileged `view` role — can call this endpoint and receive every configured external initiator's `AccessKey` and `OutgoingToken`.

### Finding Description
In `core/web/router.go` the external-initiator routes are: [1](#0-0) 
`Create` and `Destroy` require `auth.RequiresEditRole`, but `Index` only sits behind the generic `authv2` group, which requires only authentication (`auth.AuthenticateByToken`/`auth.AuthenticateBySession`), not any specific role: [2](#0-1) 

`ExternalInitiatorsController.Index` loads all external initiators from the ORM and serializes them with `presenters.NewExternalInitiatorResource`: [3](#0-2) 

That presenter includes `AccessKey` (the incoming credential used by `auth.AuthenticateExternalInitiator` to authenticate external-initiator-triggered job runs) and `OutgoingToken` (a credential sent by the node to the external initiator's webhook): [4](#0-3) 

Note: `Index` returns `ExternalInitiatorResource`, not `ExternalInitiatorAuthentication` — so `OutgoingSecret` and the session `Secret` (used as `IncomingToken`'s pair) are *not* included in this response; only `AccessKey` and `OutgoingToken` are exposed. The question's premise about `OutgoingSecret`/`IncomingToken` fields being leaked is not accurate for this specific endpoint, but the actual leaked fields (`AccessKey`, `OutgoingToken`) are still credential material that should be admin/edit-role-gated, matching the same class of issue.

### Impact Explanation
A `view`-role (or any authenticated, non-edit/admin) user can enumerate all external initiators' names, URLs, and `AccessKey`/`OutgoingToken` values via a simple authenticated GET request, bypassing the intended edit/admin role gate that protects creation/deletion of these same resources. This is a credential/secret disclosure to an under-privileged authenticated party, matching the Chainlink bounty "key or secret disclosure" / "authorization bypass" impact class, since these fields are meant to be visible only to users who can also manage (create/destroy) external initiators.

### Likelihood Explanation
Fully deterministic and trivially reproducible: it requires only a valid `view`-role session/API token (the lowest privilege tier) and a single unauthenticated-role-checked GET request. No timing, race, or special configuration is needed; any node with configured external initiators is affected.

### Recommendation
Wrap `authv2.GET("/external_initiators", ...)` with `auth.RequiresEditRole` (or at minimum `auth.RequiresRunRole` if broader read access is intentional), consistent with the `POST`/`DELETE` handlers on the same resource. Additionally, consider whether `AccessKey`/`OutgoingToken` need to be returned at all in list responses, versus only shown once at creation time.

### Proof of Concept
Go handler-integration test plan (modeled after existing `core/web/external_initiators_controller_test.go`):
1. Set up test app/router as done in existing EI controller tests.
2. Create an external initiator via an edit/admin-role client (`POST /v2/external_initiators`), capturing the returned `AccessKey`/`OutgoingToken`.
3. Create a second HTTP client authenticated with a `UserRoleView` session/token.
4. Issue `GET /v2/external_initiators` with the view-role client.
5. Assert response status is `200 OK` (not `401`/`403`).
6. Parse JSON body and assert the `externalInitiators` array contains the previously created initiator's `name`, `url`, `accessKey`, and `outgoingToken` fields matching step 2's values, proving the view-role user obtained EI credentials it should not have access to.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
