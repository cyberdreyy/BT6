### Title
Cross-workflow requestID collision causes permanent DoS in `httpTriggerHandler.setupCallback` - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
The gateway's `httpTriggerHandler` keys in-flight trigger requests by a single global map, `h.callbacks`, indexed only by the client-supplied JSON-RPC `id` (`requestID`), with no scoping to workflow, owner, or authorized signer. Any authorized caller of *any* workflow trigger can pre-occupy an arbitrary `requestID` and cause any other caller's `workflows.execute` request using that same `requestID` value to fail — directly analogous to the reported Solana bug, where an attacker pre-creates a uniquely-keyed resource (an ATA) to block a legitimate depositor whose transaction uses Anchor's `init` constraint (fails if the account already exists).

### Finding Description
In `HandleUserTriggerRequest`, the request flow is: parse → resolve workflow → `authorizeRequest` (JWT signer must be in that specific workflow's `AllowedSenders`) → rate limit → `setupCallback`. [1](#0-0) 

Crucially, `setupCallback` checks and inserts into `h.callbacks` using only `requestID` (the JSON-RPC `req.ID` provided by the caller) as the key — a map shared across **all workflows** served by this gateway handler instance, not scoped per-workflow or per-signer: [2](#0-1) 

If the key already exists, the request is rejected with `jsonrpc.ErrConflict` and a "has already been used" message — this mirrors Anchor's `init` constraint failing when the ATA already exists in the reported bug: [3](#0-2) 

The only requirement to reach `setupCallback` is that the caller passes `authorizeRequest`, which validates a signed JWT against a workflow's `AllowedSenders` set: [4](#0-3) 

Because `AllowedSenders` is workflow-specific and can list multiple authorized keys (any workflow builder can add multiple external senders as allowed callers of the same webhook/trigger), an attacker only needs to be **an authorized sender of some workflow** — not necessarily the same workflow as the victim — to submit a request with a `requestID` value they suspect (or know) a victim will use for a *different* workflow's request, occupying the slot first. There is no per-workflow or per-signer partitioning of the `callbacks` map, so `requestID` collisions across unrelated workflows and unrelated callers are possible and unhandled beyond the blunt conflict rejection.

`requestID` validation only checks for non-empty and absence of `/`: [5](#0-4) 

There is no per-caller/per-workflow namespacing to prevent one caller's chosen ID from blocking a different caller's request with the same ID, even though the underlying execution is scoped by `workflowID` elsewhere (e.g., `legacyExecutionID`/`executionIDWithTriggerIndex` are derived from `workflowID + requestID`, but the collision check in `setupCallback` happens *before* that scoping is applied to the map key). [6](#0-5) 

### Impact Explanation
This is a request-level, targeted Denial of Service: an authorized (but otherwise unprivileged, non-owner) caller of any workflow served by the gateway can deny a specific `requestID` to any other workflow's caller for as long as the entry remains in `h.callbacks` (until `reapExpiredCallbacks` purges it after `CleanUpPeriodMs`). This matches the "Medium" impact class of the reference report: no funds are stolen or permanently locked, but a specific request is guaranteed to fail with a conflict error, degrading availability/reliability of the gateway trigger for legitimate integrations that use predictable or idempotency-style request IDs (a common external-system pattern this API's own error message ironically nudges toward: "Use a new unique request 'id' for each request"). Repeated abuse could also be used to continuously block a targeted client's known ID scheme.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to be an authorized sender for at least one workflow reachable via the same gateway/shard (which is a low bar in multi-tenant CRE/Workflow deployments, since being "authorized" only means being one of potentially many `AllowedSenders` on some workflow), and requires guessing or knowing the victim's chosen `requestID` value (feasible if the victim uses deterministic/sequential/idempotency IDs, a common practice). It does not require compromising the target workflow's own authorization.

### Recommendation
Scope the in-flight-request key in `h.callbacks` by `(workflowID, requestID)` (or by `(authorizedKey.PublicKey, requestID)`) instead of `requestID` alone, so that collisions can only occur within the same workflow/caller namespace rather than globally across all workflows served by the gateway. Update `setupCallback`, `cleanupCallback`, and `HandleNodeTriggerResponse` map key derivation for consistency, and ensure the node-side response routing key still matches the scoped key used internally.

### Proof of Concept
Not independently verified in a running environment; the concrete concurrency PoC below is derived directly from reading the code paths above, analogous in structure to the reported PoC (attacker races to occupy a shared key before the victim):
1. Attacker registers/holds an authorized signer key for `workflowA` (any workflow they are permitted to call, e.g., because a workflow author added multiple allowed senders).
2. Attacker learns or predicts the `requestID` value ("R123") that a victim will use to call `workflowB`.
3. Attacker sends a valid, JWT-signed `workflows.execute` request for `workflowA` with `id = "R123"` slightly before the victim's request for `workflowB`.
4. Victim's subsequent request to `workflowB` with the same `id = "R123"` hits `setupCallback`'s existing-key check and is rejected via `handleUserError(..., jsonrpc.ErrConflict, "requestID: R123 has already been used...")`, confirmed by the exact code path cited above. [2](#0-1)

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
