### Title
A dust-sized APR0 withdraw request permanently bricks `stopEpoch` after any APR change — ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
Mirroring the `mintDepositInQueue` relayer-fee bug (a parameter changed between queueing and processing makes every execution revert), `prepareStopEpochWithApr0()` enforces an invariant that reverts whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0`. Any lender can open an APR0 withdraw request with a dust amount during the buffer period; a subsequent legitimate APR change by the manager then makes every `stopEpoch`/`stopEpochWithDuration` call revert, halting the epoch state machine until the APR is forced back to 0.

### Finding Description
`requestWithdraw` routes requests into the APR0 bucket whenever `unscaledApr == 0`, incrementing the global `apr0TotalPrincipal` with no minimum size: [1](#0-0) [2](#0-1) 

On epoch end, the CDO calls `prepareStopEpochWithApr0`, which reverts if APR is no longer 0 while APR0 principal is pending: [3](#0-2) 

Critically, this revert fires *before* the `_interest == 1` pool-close sentinel is handled in `IdleCDOEpochVariant.stopEpoch`, so even the emergency "repay everything and close" path is blocked: [4](#0-3) 

`apr0TotalPrincipal` is only cleared inside the reverting function (line 540) or via default-claim clearing in `_clearWithdrawClaimForEpoch` (which requires default finalization, i.e., a borrower default). So the only recovery is the manager setting `unscaledApr` back to 0 — i.e., a user's dust request forces protocol APR policy. The repo's own test `testApr0InvariantRevertsIfAprChangesAfterApr0Request` confirms the revert exists but treats it purely as an invariant check, not as the user-triggered freeze it enables. [5](#0-4) 

### Impact Explanation
Temporary freezing of all funds in the vault: no `stopEpoch` can execute (including the close-pool `_interest == 1` path), so no new epoch can start, deposits/withdrawals stay locked in the epoch state machine, and pending withdraw requesters cannot reach a claimable state. The freeze persists for as long as the manager wants a nonzero APR — if the pool is meant to permanently migrate to a fixed APR, the freeze is effectively permanent for that configuration. Loss is the full contract value for the duration of the freeze (DoS with funds locked, accepted impact class: temporary freezing).

### Likelihood Explanation
Trigger cost is near zero: the attacker only needs to be a KYC-passed lender, deposit, and call `requestWithdraw` with a minimal amount while `unscaledApr == 0` (a legitimate, supported mode — APR0 pools exist precisely for this). The enabling manager action (raising APR between epochs) is a normal, honest operation identical in spirit to the relayer-fee update in the reference report. No malicious privilege is required.

### Recommendation
Do not hard-revert `stopEpoch` on the APR0/APR mismatch. Options: (a) settle the outstanding APR0 bucket at the current epoch's rate (`apr0RateByEpoch[epochNumber]`) even when `unscaledApr != 0`, since the requests were made under APR0 terms; or (b) move the invariant check to `requestWithdraw`/APR-setter side — e.g., revert `setAprs` to nonzero while `apr0TotalPrincipal != 0` with a clear error, or force-settle the bucket on APR change — so the epoch state machine itself can never be bricked. A minimum request size would only reduce, not eliminate, the griefing vector.

// test/foundry/IdleCreditVault.Apr0StopEpochDoS.t.sol
// Fork test mirroring testApr0InvariantRevertsIfAprChangesAfterApr0Request
function testApr0DustRequestBricksStopEpoch() external {
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0); // APR0 mode

    // Attacker (KYC'd lender) deposits and requests withdraw of dust
    uint256 amount = 10000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    _forceLastEpochAprToZero(); // simulate APR0 epoch interest

    cdoEpoch.requestWithdraw(1, address(AAtranche)); // dust-sized APR0 request
    assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

    _startEpochAndCheckPrices(1);

    // Honest manager raises APR (legitimate parameter change)
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(1e18, 1e18);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, type(uint256).max);

    // Every stopEpoch path reverts, including pool-close (_interest == 1)
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 0);

    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 1); // close-pool path also bricked

    // Only recovery: manager forced to restore APR to 0 — a dust request dictates APR policy
}

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
      _apr0User.principalEpoch = epochNumber;
    }
    _apr0User.principal += _amount;
    // Epoch-level APR0 principal used only to compute stopEpoch APR0 pro-rata interest.
    apr0TotalPrincipal += _amount;
