The reported pattern (transfer shares to a fresh address to reset/bypass an unbonding timer) does not have a viable analog in this codebase. Aera's `ProvisionerV2`/`MultiDepositorVault` implement a comparable lock (`userUnitsRefundableUntil`) for sync deposits, but it is enforced at two independent layers that together prevent the exact bypass described:

1. `MultiDepositorVault._update` blocks any transfer where `from` is locked (`!IProvisionerV2(provisioner).areUserUnitsLocked(from)`), except mint (`from == 0`) and burn (`to == 0`) paths [1](#0-0) .
2. The burn exception is specifically re-guarded at the provisioner level: `redeem()` and `withdraw()` (the sync-redeem functions that burn units) explicitly `require(userUnitsRefundableUntil[msg.sender] < block.timestamp, Aera__UnitsLocked())` before calling `exit` [2](#0-1) .

Because the lock is set on the **receiver** of newly minted units in `_syncDeposit` (`userUnitsRefundableUntil[receiver] = refundableUntil`) [3](#0-2) , and because that same receiver is blocked from transferring locked units to any other address, there is no ordinary-user path to move newly-minted, still-locked units to a fresh address and then unlock/withdraw early. `requestRedeem`'s `safeTransferFrom` of vault units also flows through the same `_update` hook, so async redemption of locked units is blocked identically [4](#0-3) .

No alternate public function (`cancelRequest`, `refundRequest`, `solveRequestsDirect`, `solveRequestsVault`) burns or transfers a *locked* depositor's own units without first requiring that same lock check, since those flows only move units that were already escrowed to the provisioner *before* the lock check would apply, or they operate on the provisioner's own escrowed balance rather than a locked user's balance. This is a materially different design from the Hubble `unbondShares()` bug, where the timer was keyed to balance-based unbonding state that could be reset simply by moving tokens to an address with no recorded unbond entry — Aera's lock is enforced as a hard transfer-level invariant, not a resettable per-balance timer.
