### Title
Signer-side global-state agreement threshold uses floor rounding while the canonical block-approval threshold uses ceiling rounding, letting a signer's "current miner"/burn-view/replay-set consensus be reached with less than the true 70% supermajority - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` in `libsigner/src/v0/signer_state.rs` computes the 70% supermajority threshold as `floor(total_weight * 7 / 10)`, while the canonical block-signature approval threshold, `NakamotoBlockHeader::compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs`, computes the *same nominal* 70% threshold as `ceil(total_weight * 7 / 10)`. This is exactly the analog of the Panoptic finding: two code paths independently compute what should be a single consistent quantity ("70% of total_weight") using different rounding directions on integer division, so their results can diverge by 1 weight unit whenever `total_weight * 7` is not evenly divisible by 10.

### Finding Description
`compute_voting_weight_threshold` (used for actual `NakamotoBlockHeader` signature verification and mirrored in `stacks-signer/src/v0/signer.rs` for pre-commit/rejection/acceptance tallying) rounds up: [1](#0-0) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```

In contrast, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement`, used by every signer to decide the *global state* (active protocol version, global burn view, current miner, transaction-replay set — see `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, `determine_global_state`, `find_majority_prefix_replay_set`), floors instead of ceiling: [2](#0-1) 

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```

Both functions are meant to represent the identical concept - "has a 7/10 (70%) supermajority of `total_weight` been reached" - and both use the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant, but one computes `ceil(total_weight*7/10)` and the other `floor(total_weight*7/10)`. Whenever `total_weight` is not a multiple of 10, these two thresholds differ by exactly 1, exactly the same class of divergence as `[A]-[B]` vs `A-B` not being equal that the Panoptic report flags for fee accounting: two independently-rounded computations of what should be one invariant quantity.

Concretely, for `total_weight = 13`: `ceil(13*7/10) = ceil(9.1) = 10`, but `floor(13*7/10) = 9`. A signer's `GlobalStateEvaluator` will call `reached_agreement(9)` `true` (9 ≥ 9), declaring global consensus on e.g. "current miner" or "burn view" with only 9/13 ≈ 69.2% weight support - one weight unit short of the 70% supermajority (10/13 ≈ 76.9%) that the canonical block-approval path (`compute_voting_weight_threshold`, used for `verify_signer_signatures` and all signature tallying in `stacks-signer/src/v0/signer.rs`) requires.

### Impact Explanation
`determine_global_state` drives which miner/tenure a signer's state machine treats as the legitimately agreed "current miner," which burn view is globally accepted, and which transaction-replay set is in force (see usage sites `libsigner/src/v0/signer_state.rs:102-158`, and its callers in `stacks-signer/src/signerdb.rs` and `stacks-node/src/nakamoto_node/stackerdb_listener.rs`, which construct `GlobalStateEvaluator` from the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`). Because this "global state" gate is weaker (floor) than the block-signing gate (ceil) that ultimately governs consensus-critical signature counting, a signer can flip its notion of the canonical current miner/tenure/replay set with less real supermajority support than the protocol's nominal 70% bar, i.e. the signer is "acting on a stale/threshold" mismatch between two supposedly-identical 70% checks. This falls under the High-impact category of a signer acting on a threshold computed inconsistently with the canonical one, which can misalign its downstream tenure/miner validation decisions relative to what a true 70% supermajority would have decided.

### Likelihood Explanation
No majority collusion or attacker action is required — the divergence is deterministic and purely a function of `total_weight` (sum of registered signer weights for the reward cycle). It manifests automatically whenever `total_weight` is not a multiple of 10 (i.e. `total_weight * 7 mod 10 != 0`, true for the large majority of possible total-weight values, since 7 and 10 are coprime), which can occur naturally from the `pox_5_make_signer_set` / `make_signer_set` weight-apportionment logic (`stackslib/src/chainstate/nakamoto/signer_set.rs`, `stackslib/src/chainstate/stacks/boot/mod.rs`) depending on real-world stacking distribution. Every signer runs into this on every reward cycle whose `total_weight` isn't a multiple of 10.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same rounding convention (ceiling) as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by having both call a single shared threshold-computation helper instead of maintaining two independent implementations of the "70%" arithmetic.

### Proof of Concept
```rust
// total_weight = 13, NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7
let canonical_threshold =
    NakamotoBlockHeader::compute_voting_weight_threshold(13).unwrap(); // = 10 (ceil(9.1))

let evaluator = GlobalStateEvaluator {
    address_weights: HashMap::new(),
    address_updates: HashMap::new(),
    total_weight: 13,
};
assert!(evaluator.reached_agreement(9));      // floor(9.1) == 9 -> true
assert_eq!(canonical_threshold, 10);          // but canonical approval needs 10
// => GlobalStateEvaluator declares "global state agreement" at 9/13 weight,
//    one unit below the 10/13 the block-signing path treats as the true 70% bar.
