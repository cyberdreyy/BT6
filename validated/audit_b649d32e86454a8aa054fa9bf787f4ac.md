### Title
BridgeType `OutgoingToken` credential disclosed to any authenticated user via unrestricted `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` - ([File: core/web/router.go])

### Summary
The `authv2` route group only requires authentication (session or API token), not a minimum role, for `GET /v2/bridge_types` (Index) and `GET /v2/bridge_types/:BridgeName` (Show). Both handlers serialize the bridge's `OutgoingToken` secret into the JSON API response via `presenters.NewBridgeResource`, so any authenticated user — including one with the lowest `view` role — can read every bridge's `OutgoingToken`.

### Finding Description
In `core/web/router.go`, the bridge routes are registered as:
```go
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
``` [1](#0-0) 

Unlike `Create`, `Update`, and `Destroy` which are wrapped with `auth.RequiresEditRole`, the `Index` and `Show` handlers are reachable by anyone who passes the `authv2` group's authentication middleware alone (`auth.AuthenticateByToken` or `auth.AuthenticateBySession`), which enforces authentication only, not role. `auth.RequiresEditRole`/`RequiresAdminRole` checks exist in `core/web/auth/auth.go` but are simply not applied to these two routes. [2](#0-1) 

Both `BridgeTypesController.Index` and `.Show` build their response with `presenters.NewBridgeResource(bt)`:
```go
resources = append(resources, *presenters.NewBridgeResource(bridge))
...
jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
``` [3](#0-2) 

`NewBridgeResource` unconditionally copies the persisted plaintext `OutgoingToken` field into the resource, and `BridgeResource.OutgoingToken` is tagged `json:"outgoingToken"` with no `omitempty`/redaction:
```go
OutgoingToken          string       `json:"outgoingToken"`
...
OutgoingToken:          b.OutgoingToken,
``` [4](#0-3) 

`BridgeType.OutgoingToken` is stored as plaintext (unlike `IncomingTokenHash`, which is hashed) in `core/bridges/bridge_type.go`:
```go
type BridgeType struct {
	...
	IncomingTokenHash      string
	Salt                   string
	OutgoingToken          string
	...
}
``` [5](#0-4) 

Note that `IncomingToken` is not actually leaked by these two endpoints: `BridgeType` never stores the plaintext incoming token (only `IncomingTokenHash`), so `NewBridgeResource` leaves `BridgeResource.IncomingToken` empty, and its `omitempty` json tag hides it. `IncomingToken` is only populated in the `Create` response from the one-time `BridgeTypeAuthentication.IncomingToken` value, which is expected/intended behavior. The actual exposure is limited to `OutgoingToken`.

The existing test suite confirms `outgoingToken` is present in every `BridgeResource` JSON serialization by design, and integration tests (`TestBridgeTypesController_Index`, `TestBridgeController_Show`) never check that `OutgoingToken` is redacted for low-privilege callers. [6](#0-5) 

### Impact Explanation
Any authenticated user, including one whose account is provisioned with only the `view` role, can enumerate all configured bridges via `GET /v2/bridge_types` and read every bridge's `OutgoingToken` in plaintext, or target a specific bridge via `GET /v2/bridge_types/:BridgeName`. The `OutgoingToken` is a credential used by the bridge/external-adapter to authenticate callbacks back into the Chainlink node, so its disclosure to low-privilege users constitutes exposure of a bridge secret beyond the intended trust boundary (matches a credential/secret disclosure impact class).

### Likelihood Explanation
Exploitation requires only a valid session or API token with the lowest privilege role (`view`) — no edit/run/admin role or special preconditions are needed. The vulnerable endpoints are simple unauthenticated-role GET requests, fully repeatable, and require no timing or race conditions.

### Recommendation
Redact `OutgoingToken` from `BridgeResource` in `Index`/`Show` responses for non-privileged roles (e.g., only include it for `edit`/`admin` roles, or omit it entirely from list/show responses and expose it only through a dedicated, role-restricted endpoint), or wrap `authv2.GET("/bridge_types", ...)` and `authv2.GET("/bridge_types/:BridgeName", ...)` with `auth.RequiresEditRole` similar to the mutation routes.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/bridge_types_controller_test.go`):
1. Create an application (`cltest.NewApplication`), create a bridge type via `app.BridgeORM().CreateBridgeType` with a known `OutgoingToken`.
2. Create a user/API token with `clsessions.UserRoleView` (view-only role) and authenticate the test HTTP client as that user (mirroring pattern in `core/web/auth/auth_test.go`).
3. Call `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` as the view-role client.
4. Assert response status `200 OK` (not `401`/`403`), then parse the JSON API response into `presenters.BridgeResource` and assert `resource.OutgoingToken` equals the bridge's actual `OutgoingToken` value — demonstrating the secret is disclosed to a view-role identity, contradicting the invariant that bridge credentials should never leave in responses to low-privilege roles.

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
