### Title
Permissionless `lending_pool_emissions_deposit` donations are sandwichable, letting an attacker steal a share of the donation from genuine bank depositors - ([File: programs/marginfi/src/instructions/marginfi_group/configure_bank.rs])

### Summary
`lending_pool_emissions_deposit` lets **anyone** transfer tokens directly into a bank's `liquidity_vault` and instantaneously raise `asset_share_value` for every existing depositor of that bank, exactly the "stepwise donation raises the pool's per-share value" pattern described in the external report. Because the transfer and the resulting step-change in `asset_share_value` happen atomically and are visible/predictable ahead of confirmation, an attacker can front-run a legitimate emissions donation with a large deposit and back-run it with an immediate withdrawal, capturing a pro-rata slice of funds donated by someone else without having provided any real liquidity duration — diluting the payout that should have gone to genuine long-term depositors.

### Finding Description
The instruction is explicitly documented and implemented as permissionless: [1](#0-0) 

Its core logic transfers `amount` of the bank's mint into the `liquidity_vault` and recomputes `asset_share_value` as `(total_assets + amount) / total_asset_shares` — a single stepwise increase applied to whatever `total_asset_shares` exists at the instant the instruction executes: [2](#0-1) 

This is structurally identical to the Balancer `UpliftOnlyExample` bug: a "donation" is added to the pool and immediately re-priced into all current LP shares (`asset_share_value`) rather than vested or time-weighted. Tests confirm the pro-rata, instantaneous nature of the re-pricing: [3](#0-2) 

There is no lockup, minimum holding period, or timelock on ordinary `lending_account_deposit`/`lending_account_withdraw` that would prevent a user from depositing immediately before and withdrawing immediately after an emissions-deposit transaction lands. Because Solana supports MEV via transaction ordering/bundles (e.g., Jito), and this instruction is permissionless and its calldata (amount, bank) is visible before confirmation, an attacker can:
1. Observe (or anticipate, since emissions campaigns run on a predictable schedule per `guides/USER/EMISSIONS.md`) an incoming `lending_pool_emissions_deposit` call funded by a third party (protocol/keeper distributing incentives).
2. Front-run it with a large `lending_account_deposit` into the same bank, inflating their share of `total_asset_shares` just before the donation lands.
3. Let the donation raise `asset_share_value` for all current shares, including the attacker's freshly minted ones.
4. Back-run with an immediate `lending_account_withdraw`, extracting a share of the donated funds proportional to their (momentary) share of the pool — funds that should have accrued to genuine long-term depositors.

### Impact Explanation
This allows value redirection away from legitimate long-term lenders/depositors of a bank toward an opportunistic actor who never provided real liquidity duration, mirroring the "stealing of funds from LP providers" impact in the source report. The magnitude scales with the ratio of the donation size to the pool's existing `total_asset_shares` and with how much capital/flash liquidity the attacker can temporarily inject — the same amplification dynamic illustrated in the report's whale examples.

### Likelihood Explanation
Likelihood depends on (a) donations being sizeable relative to the bank's total deposits and (b) an attacker being able to time deposit/withdraw around the donation transaction. Given Solana's public mempool/leader-schedule dynamics and the fact this instruction, deposits, and withdrawals are all fully permissionless and instantaneous with no cooldown, this is a realistic, low-friction attack for any bank receiving a meaningful `lending_pool_emissions_deposit` from a third party.

### Recommendation
Vest or time-weight the effect of `lending_pool_emissions_deposit` on `asset_share_value` instead of applying it as an instant, atomic step (e.g., stream the donation's effect over a cooldown window, or gate eligibility for the raised share value based on a minimum deposit duration), so instantaneous deposit-then-withdraw cannot capture donated value disproportionate to actual time-weighted participation.

### Proof of Concept
1. Bank B has `total_asset_shares` corresponding to $100 of real deposits from long-term LPs, `asset_share_value = 1.0`.
2. A keeper/third party prepares a transaction calling `lending_pool_emissions_deposit(bank=B, amount=$50)` to reward existing depositors (as in `emissions_same_bank_deposit_updates_asset_share_value` test) [4](#0-3) .
3. Attacker submits (or bundles ahead of) a `lending_account_deposit` of $100 into bank B immediately before the emissions-deposit transaction, doubling `total_asset_shares` to represent $200.
4. Emissions-deposit lands: `asset_share_value` rises by `50 / 200 = 25%` instead of the `50%` it would have risen for the original $100 pool — attacker's fresh $100 position is now worth $125.
5. Attacker immediately withdraws, netting a $25 profit that came out of the $50 that should have gone entirely to the original depositors (who now only received $25 of the intended $50 donation instead of the full amount).

```rust
/// Permissionlessly deposit same-mint emissions directly into the bank liquidity vault,
/// increasing depositor value through asset share value.
pub fn lending_pool_emissions_deposit(
    ctx: Context<LendingPoolEmissionsDeposit>,
    amount: u64,
) -> MarginfiResult {
    if amount == 0 {
        return Ok(());
    }

    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = ctx.accounts.group.load()?;

    utils::validate_bank_state(&bank, utils::InstructionKind::FailsIfPausedOrReduceState)?;

    // Reject mints with non-zero transfer fees or active transfer hooks.
    let mint_ai = ctx.accounts.mint.to_account_info();
    check!(
        !utils::nonzero_fee(mint_ai.clone(), clock.epoch)?,
        MarginfiError::InvalidTransfer
    );
    check!(
        !utils::has_transfer_hook(mint_ai)?,
        MarginfiError::InvalidTransfer
    );

    let total_asset_shares = I80F48::from(bank.total_asset_shares);
    check!(
        total_asset_shares > I80F48::ZERO,
        MarginfiError::EmissionsUpdateError
    );

    bank.accrue_interest(
        clock.unix_timestamp,
        &group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.key(),
            TransferChecked {
                from: ctx.accounts.emissions_funding_account.to_account_info(),
                to: ctx.accounts.liquidity_vault.to_account_info(),
                authority: ctx.accounts.depositor.to_account_info(),
                mint: ctx.accounts.mint.to_account_info(),
            },
        ),
        amount,
        ctx.accounts.mint.decimals,
    )?;

    let total_assets = bank.get_asset_amount(total_asset_shares)?;
    let updated_total_assets = total_assets
        .checked_add(I80F48::from_num(amount))
        .ok_or_else(math_error!())?;

    bank.asset_share_value = updated_total_assets
        .checked_div(total_asset_shares)
        .ok_or_else(math_error!())?
        .into();

```

```rust
#[tokio::test]
async fn emissions_same_bank_deposit_updates_asset_share_value() -> anyhow::Result<()> {
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;

    let usdc_bank = test_f.get_bank(&BankMint::Usdc);

    let emissions_funding = test_f.usdc_mint.create_token_account_and_mint_to(50).await;

    let depositor_a = test_f.create_marginfi_account().await;
    let depositor_b = test_f.create_marginfi_account().await;

    let depositor_a_usdc = test_f.usdc_mint.create_token_account_and_mint_to(40).await;
    let depositor_b_usdc = test_f.usdc_mint.create_token_account_and_mint_to(60).await;

    let depositor_a_amount = 40;
    depositor_a
        .try_bank_deposit(
            depositor_a_usdc.key,
            usdc_bank,
            depositor_a_amount as f64,
            None,
        )
        .await?;

    let depositor_b_amount = 60;
    depositor_b
        .try_bank_deposit(
            depositor_b_usdc.key,
            usdc_bank,
            depositor_b_amount as f64,
            None,
        )
        .await?;

    let bank_before = usdc_bank.load().await;
    let shares_before = I80F48::from(bank_before.total_asset_shares);
    let share_value_before = I80F48::from(bank_before.asset_share_value);

    let liquidity_vault_before =
        TokenAccountFixture::fetch(test_f.context.clone(), bank_before.liquidity_vault)
            .await
            .balance()
            .await;

    let emissions_deposit = 50;
    usdc_bank
        .try_emissions_deposit(native!(emissions_deposit, "USDC"), emissions_funding.key)
        .await?;

    let bank_after = usdc_bank.load().await;
    let shares_after = I80F48::from(bank_after.total_asset_shares);
    let share_value_after = I80F48::from(bank_after.asset_share_value);

    let liquidity_vault_after =
        TokenAccountFixture::fetch(test_f.context.clone(), bank_after.liquidity_vault)
            .await
            .balance()
            .await;

    let asset_shares_value_multiplier =
        1.0 + emissions_deposit as f64 / (depositor_a_amount + depositor_b_amount) as f64;

    assert_eq!(shares_after, shares_before);

    // Should be equal, zero liabilities are present
    assert_eq!(
        share_value_before
            .checked_mul(I80F48::from_num(asset_shares_value_multiplier))
            .unwrap(),
        share_value_after
    );
    assert_eq!(
        liquidity_vault_after - liquidity_vault_before,
        native!(emissions_deposit, "USDC")
    );
    assert_eq!(I80F48::from(bank_after.emissions_remaining), I80F48::ZERO);
```
