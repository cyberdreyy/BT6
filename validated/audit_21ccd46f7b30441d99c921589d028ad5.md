### Title
Unbounded claim lets any attacker redirect a holder’s default recovery payout - ([File: contracts/DefaultDistributor.sol](contracts/DefaultDistributor.sol))

### Summary
`DefaultDistributor.claim()` lets any caller redeem the caller’s entire `trancheToken` balance and choose any payout recipient. A lender who has approved the distributor can therefore be front-run or replayed after acquiring more tranche tokens: the attacker calls `claim(attacker)`, causing the victim’s tranches to be surrendered while the underlying recovery payment goes to the attacker.

### Finding Description
The claim function reads `tranche.balanceOf(msg.sender)`, pulls the full balance from `msg.sender`, and transfers `trancheBal * rate / ONE_TRANCHE` underlying to an attacker-controlled `_to` argument. [1](#0-0)  There is no nonce, recipient authorization, amount parameter, deadline, or `hasClaimed` marker restricting a holder’s approval to one intended claim. [1](#0-0)  The contract is intended to distribute a fixed underlying pool at a rate set once owner activates claims. [2](#0-1) 

Concretely, in the default-distribution phase, a victim approves `trancheToken` to the distributor and plans to call `claim(victim)`. An unprivileged attacker observes the allowance and calls `claim(attacker)`. The distributor transfers the victim’s tranches into the contract but sends the underlying recovery to the attacker. If the victim retains the allowance and later receives another tranche balance, the same authorization can be exercised again.

### Impact Explanation
This is direct theft of a defaulted tranche holder’s recovery payout. The victim loses the full approved `trancheToken` balance, while the attacker receives that balance multiplied by the configured redemption `rate`. [1](#0-0)  If the rate is par, a victim holding `1,000e18` tranche tokens loses `1,000` underlying units; the attacker needs only gas and the ability to submit the call.

### Likelihood Explanation
Approval-first interaction makes this reachable by any EOA or contract, including an unrelated tranche holder or mempool observer. No privileged role, borrower default action, oracle manipulation, liquidity shortage, or contract pause is required; the only prerequisite is that claims are active and the victim has nonzero `trancheToken` balance and distributor allowance. The unrestricted recipient field also makes accidental or opportunistic theft possible even without mempool front-running if a holder leaves a standing approval and later obtains tranches.

### Recommendation
Bind each redemption to the token holder and intended recipient. At minimum, remove the `_to` parameter and pay `msg.sender`, or require `to == msg.sender`. Prefer an explicit amount and an owner-signed permit or EIP-712 authorization containing holder, distributor, recipient, amount, nonce, deadline, and chain ID. Alternatively, have the holder transfer tranches to the distributor in one function that immediately pays the same holder, so no reusable allowance can be invoked by a third party.

### Proof of Concept
A Foundry fork PoC can deploy or instantiate `DefaultDistributor`, fund it with underlying, activate the rate, and show that an attacker steals a victim’s recovery:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../contracts/DefaultDistributor.sol";
import "../contracts/mocks/MockERC20.sol";

contract DefaultDistributorClaimRedirectTest is Test {
    MockERC20 underlying;
    MockERC20 tranche;
    DefaultDistributor distributor;

    address owner = address(0xA11CE);
    address victim = address(0xB0B);
    address attacker = address(0xBAD);

    function testAttackerRedirectsVictimClaim() public {
        underlying = new MockERC20("Underlying", "UND", 18);
        tranche = new MockERC20("Tranche", "TRN", 18);
        distributor = new DefaultDistributor(
            address(underlying),
            address(tranche),
            owner
        );

        underlying.mint(address(distributor), 1_000e18);
        tranche.mint(victim, 1_000e18);

        vm.prank(owner);
        distributor.setIsActive(true); // rate = 1 underlying / 1 tranche

        // Victim grants the approval needed to claim.
        vm.prank(victim);
        tranche.approve(address(distributor), type(uint256).max);

        uint256 attackerUnderlyingBefore = underlying.balanceOf(attacker);

        // Any third party can consume the victim's full balance and choose itself as recipient.
        vm.prank(attacker);
        distributor.claim(attacker);

        assertEq(tranche.balanceOf(victim), 0);
        assertEq(tranche.balanceOf(address(distributor)), 1_000e18);
        assertEq(
            underlying.balanceOf(attacker) - attackerUnderlyingBefore,
            1_000e18
        );
    }
}
```
