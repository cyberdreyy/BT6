### Title
Workflow existence oracle via distinguishable "Workflow not found" vs "Auth failure" errors in `HandleUserTriggerRequest` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`HandleUserTriggerRequest` resolves a workflow selector (`resolveWorkflowID`) before verifying that the caller is authorized on that workflow (`authorizeRequest`). Because the two failure paths return distinguishable error messages/codes to the caller, any party able to submit a syntactically valid but self-signed JWT trigger request can determine whether a given `workflowOwner`/`workflowName`/`workflowTag` (or `workflowID`) combination exists, without being an authorized signer for it.

### Finding Description
In `HandleUserTriggerRequest`, the call order is `validatedTriggerRequest` → `resolveWorkflowID` → `authorizeRequest` → `checkRateLimit`: [1](#0-0) 

`resolveWorkflowID` looks up the workflow purely from attacker-supplied selector fields, with no authentication/authorization check, and reports a distinct error when the selector doesn't map to any registered workflow: [2](#0-1) 

Only after a workflow is found does `authorizeRequest` verify the JWT and check that the signer is an authorized key for that specific workflow, returning a differently-worded error ("Auth failure: ...") on failure: [3](#0-2) 

Both paths use the same JSON-RPC error code (`jsonrpc.ErrInvalidRequest`), but the message text differs ("Workflow not found..." vs "Auth failure: ..."). Because JWT/ECDSA request signing only requires the attacker to control their own keypair (not the target workflow's key) — `VerifyRequestJWT` just checks the signature is valid and recovers the signer, then `Authorize` separately checks that the signer is in the workflow's authorized-key set — [4](#0-3)  an attacker with no relationship to a target workflow can submit self-signed requests using guessed `workflowOwner`/`workflowName`/`workflowTag` combinations and, purely from the returned error string, learn whether that combination exists ("Workflow not found") versus exists but they're unauthorized ("Auth failure"). This confirms/denies the existence of workflows belonging to other users before any authorization check succeeds.

### Impact Explanation
This is an information-disclosure / cross-user boundary issue: it lets an unprivileged caller enumerate valid `workflowOwner`/`workflowName`/`workflowTag` triples (and via the `workflowID` path, valid workflow IDs) belonging to other users. It does not expose secrets, keys, or move funds, and does not bypass authorization for execution — `checkRateLimit`, `setupCallback`, and message dispatch to nodes are never reached without passing `authorizeRequest`. Impact is limited to reconnaissance value for targeting a specific victim's workflow (e.g., for subsequent signature-forgery or social-engineering attempts), which fits a low-severity "cross-user response confusion / information disclosure" bounty class rather than authentication/authorization bypass.

### Likelihood Explanation
Feasibility is high: the attacker only needs the ability to send gateway JSON-RPC `workflows.execute` trigger requests with a self-generated ECDSA key to produce a validly-formed (but unauthorized) JWT — no special role or existing authorization on any workflow is required. The enumeration is fully repeatable and automatable across many selector guesses since each request yields an immediately distinguishable error message.

### Recommendation
Return a uniform, generic error (same JSON-RPC code and message, e.g. "Unauthorized") for both "workflow not found" and "auth failure" cases reachable from unauthenticated/unauthorized selectors, and avoid revealing whether the ambiguity is due to a missing workflow or a rejected signer. Alternatively, perform JWT/signature verification before or independent of workflow-existence disclosure so that failure to resolve a workflow and failure to authorize produce identical externally-visible responses.

### Proof of Concept
Table-driven Go test in `http_trigger_handler_test.go`:
1. Register one workflow (`workflowID`, `workflowOwner`, `workflowName`, `workflowTag`) with an authorized key via `createTestMetadataHandler`.
2. Case A: send `HandleUserTriggerRequest` with the real `workflowOwner`/`workflowName`/`workflowTag` but a JWT signed by a *different*, unauthorized private key → assert callback error message contains `"Auth failure"`.
3. Case B: send with a random/guessed `workflowOwner`/`workflowName`/`workflowTag` combination not registered, signed by the same attacker key → assert callback error message contains `"Workflow not found"`.
4. Assert the two error strings/codes are distinguishable (not identical), demonstrating the enumeration oracle exists without the attacker ever passing `authorizeRequest`.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
