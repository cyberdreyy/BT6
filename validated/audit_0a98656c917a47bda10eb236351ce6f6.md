### Title
Permissionless `LockupFactory::create` allows account squatting via deterministic address with attacker-chosen `staking_pool_whitelist_account_id` - (File: lockup-factory/src/lib.rs)

### Summary
`LockupFactory::create` derives the lockup's account ID solely from `sha256(owner_account_id)[..20]` and imposes no restriction on who may call it or on the `whitelist_account_id` argument. An unprivileged attacker can call `create(owner_account_id=<victim>, ..., whitelist_account_id=Some(<attacker_fake_whitelist>))` before the legitimate issuer's call, permanently deploying a lockup at the victim's deterministic address with `staking_pool_whitelist_account_id` pointing to an attacker-controlled contract.

### Finding Description
The binding that should hold is: for the lockup deployed at `sha256(owner_account_id)[..20].<factory>`, `staking_pool_whitelist_account_id == self.whitelist_account_id` (the factory's official whitelist), whenever the caller does not explicitly and legitimately override it. This binding is broken because `create` accepts an arbitrary `whitelist_account_id: Option<ValidAccountId>` from *any* caller, with no check that the caller is `self.foundation_account_id` or the `owner_account_id` itself: [1](#0-0) [2](#0-1) 

The account ID is fully deterministic from `owner_account_id` alone, with no dependency on `env::predecessor_account_id()`: [3](#0-2) 

Exploit flow:
1. Attacker deploys a fake whitelist contract exposing `is_whitelisted` that unconditionally returns `true`, and (optionally) a fake staking pool contract.
2. Attacker calls `create(owner_account_id=<victim>, lockup_duration=..., lockup_timestamp=None, vesting_schedule=None, release_duration=None, whitelist_account_id=Some(<attacker_fake_whitelist>))` with the minimum deposit (`MIN_ATTACHED_BALANCE`), before the legitimate issuer's call lands.
3. `Promise::new(lockup_account_id).create_account().deploy_contract(...).transfer(...).function_call("new", LockupArgs{owner_account_id: victim, staking_pool_whitelist_account_id: attacker_fake_whitelist, ...})` succeeds, permanently occupying the deterministic address with `owner_account_id = victim` but `staking_pool_whitelist_account_id` pointing at the attacker's fake whitelist.
4. When the legitimate issuer later calls `create(owner_account_id=<victim>, ..., whitelist_account_id=None)`, `create_account()` on the already-existing account fails; the whole promise batch fails, and `on_lockup_create`'s `is_promise_success()` check refunds the issuer's deposit rather than landing funds in the account: [4](#0-3) 
5. The victim, believing this is their legitimate lockup (since `owner_account_id` matches them and they pass `assert_owner`), later calls `select_staking_pool`, which queries `is_whitelisted` on the attacker's fake whitelist rather than the foundation's official one: [5](#0-4) 
6. The fake whitelist approves an attacker-controlled staking pool, and the victim's subsequent `deposit_and_stake` sends NEAR into that pool: [6](#0-5) 

No existing guard prevents this: `create` has no `assert_called_by_foundation`-style check, no requirement that `predecessor_account_id == owner_account_id`, and no check that the deterministic account doesn't already exist before attempting deployment (the failure is only detected post-hoc via the promise-success callback, which merely refunds the deposit — it does not prevent or undo the attacker's prior successful deployment).

### Impact Explanation
This lets an attacker permanently deploy a lockup contract "owned" by a victim with parameters (specifically `staking_pool_whitelist_account_id`) the victim/rightful issuer never chose — this matches the explicitly listed Critical category "a lockup deployed with parameters its rightful creator never chose." Once the victim later interacts with this contract via `select_staking_pool`/`deposit_and_stake`, NEAR moved into the attacker-controlled staking pool is a party the victim never entitled it to. This is repeatable against any target `owner_account_id` the attacker chooses to front-run, for the cost of `MIN_ATTACHED_BALANCE` (3.5 NEAR) per squat attempt.

### Likelihood Explanation
The attack requires only: (1) knowledge of an intended future grant recipient's account ID (often public/predictable for known grantees), (2) the ability to deploy two trivial contracts (fake whitelist, fake pool), and (3) `MIN_ATTACHED_BALANCE` NEAR to front-run the legitimate `create()` call. No privileged role, key compromise, or foundation cooperation is needed — the attacker only needs to submit their transaction before the legitimate issuer's. This is a plausible front-running scenario given `create` is a fully public, unauthenticated method.

### Recommendation
Restrict `LockupFactory::create` to be callable only by `self.foundation_account_id` (or another explicitly authorized principal), and/or restrict the `whitelist_account_id` override so it can only be set by the foundation. Additionally, consider requiring `owner_account_id == env::predecessor_account_id()` for self-service creation flows, and have `on_lockup_create` positively verify (e.g., via a stored pending-creation record keyed by `lockup_account_id`) that the deployed contract matches the caller's intended parameters, rejecting/flagging cases where the account already existed prior to the call.

    #[payable]
    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
