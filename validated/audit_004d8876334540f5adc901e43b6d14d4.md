### Title

### Summary
`ValueRef::new` ( [1](#0-0) ) computes `hash: hash(value)` using `near_primitives_core::hash::hash`, the identical function used at deploy time in `global_contracts.rs` to compute `GlobalContractIdentifier::CodeHash(hash(&contract_code))` ( [2](#0-1) ). The value stored under `TrieKey::GlobalContractCode` is the raw `code` bytes exactly as received (`state_update.set(trie_key, global_contract_data.code().to_vec())`, [3](#0-2) ), so `value_hash()` returned by `get_ref` in `GlobalContractAccessExt::hash` ( [4](#0-3) ) is `hash(code)` — the same value that `CodeHash(hash(&code))` mode would produce for identical bytes.

### Finding Description
There is no divergence: `value_hash()` is not a Merkle/trie-structural hash but is precisely `CryptoHash::hash_bytes`/`hash()` applied to the raw value bytes stored at that trie key, per `ValueRef::new` ( [5](#0-4) ). Since global contract code is stored unmodified (no wrapping, compression, or borsh-serialization) under `TrieKey::GlobalContractCode`, the "value" hashed by the trie machinery is byte-for-byte identical to the `code` argument passed to `near_primitives::hash::hash(&contract_code)` at deploy time for the `CodeHash` mode ( [2](#0-1) ). Therefore for identical bytes deployed under `AccountId` mode vs `CodeHash` mode, `GlobalContractAccessExt::hash` returns the same `CryptoHash` in both cases, and `RuntimeContractIdentifier::resolve` ( [6](#0-5)  ) consistently uses this single resolved hash for both VM cache keying and any host-exposed introspection value — there is no dual-hash inconsistency to exploit.

### Impact Explanation
N/A — no divergence exists between the two hashing paths, so there is no cache/metering desynchronization, no state-root divergence, and no exploitable authorization or fund-theft vector.

### Recommendation
No fix needed for this specific claim. (General note: `ValueRef.hash` in principle is a hash-of-raw-value used generically across all trie values, and its equivalence to `near_primitives::hash::hash` output is a design invariant rather than incidental; if this coupling ever changes — e.g., a future change makes trie value hashing use a different hash function or wraps stored bytes — this would need re-auditing, but no such change exists in this codebase.)

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }
