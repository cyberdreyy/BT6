### Title
Unauthenticated `/shutdown` HTTP Endpoint in `SignerEventReceiver` Permits Remote Denial-of-Signing (Liveness Wedge) - (File: `libsigner/src/events.rs`)

### Summary
The signer's own HTTP event-receiver server, which accepts pushed events (block proposals, burn blocks, StackerDB chunks) from the connected `stacks-node`, exposes a `/shutdown` route that any TCP client reaching the bound port can hit with zero authentication, permanently killing the event-receiver thread and cutting the signer off from all future block proposals.

### Finding Description
`SignerEventReceiver::next_event` dispatches incoming HTTP requests purely by URL path, with no credential check anywhere in the branch: [1](#0-0) 

Unlike the node-side `/v3/block_proposal` endpoint, which is documented as requiring the `Authorization` header to match `connection_options.auth_token`: [2](#0-1) 

...the signer's inbound HTTP listener (the socket the node "POSTs" events to) performs no such check before honoring `POST /shutdown`. Any request to that URL immediately sets the stop signal and returns `EventError::Terminated`: [3](#0-2) 

This is the exact same mechanism the library itself uses internally to gracefully shut the receiver down via `SignerStopSignaler::send`, which crafts and posts that very request over a plain unauthenticated TCP connection: [4](#0-3) 

Once `next_event` returns `Err(EventError::Terminated)`, the event-receiver thread's main loop (spawned in `Signer::spawn`) exits, and there is no retry/rebind logic to bring it back up — a signer process must be manually restarted to resume receiving proposals: [5](#0-4) 

Sample configs bind this listener to a wildcard interface by default (`endpoint = "0.0.0.0:30000"` in the signer config, matched by the node's `events_observer.endpoint`), so absent an operator-added firewall/reverse-proxy rule, the port is reachable from the network: [6](#0-5) 

### Impact Explanation
This breaks the liveness guarantee "a signer wedged into never signing valid blocks." An attacker who can reach the signer's event-listener port (e.g., any peer with network access to that socket — no `auth_token`, no signer private key, no majority of signers required) sends a single unauthenticated `POST /shutdown`. The event-receiver thread terminates and is never restarted automatically, so the signer stops receiving `BlockProposal`, `BlockValidateResponse`, `BurnBlockEvent`, and `StackerDBChunksEvent` pushes from its node entirely. That signer can no longer approve or reject any subsequent block proposal until an operator notices and manually restarts the process — directly analogous to the reported "unauthenticated session termination" bug class (CWE-306) in the external advisory, but here landing on the consensus-critical signing pipeline rather than an MCP session.

### Likelihood Explanation
Likelihood is high wherever the operator has not independently firewalled the event-receiver port: the attack is a single unauthenticated HTTP POST, requires no cryptographic material, no majority collusion, and reuses the exact request format the library itself emits for legitimate shutdowns (trivial to reconstruct from the public source). This is not a flooding/volumetric DoS — one request is sufficient and permanent until manual restart.

### Recommendation
Require the same `auth_token`/`auth_password` bearer credential used for node↔signer communication to be validated on all `SignerEventReceiver` HTTP routes, and reject `/shutdown` (and other non-`/status` routes) from unauthenticated callers. Alternatively, restrict `/shutdown` to loopback-only connections, or replace it with an in-process (non-network) stop mechanism so the stop signal cannot be triggered remotely at all.

### Proof of Concept
```
# Given a signer bound at 0.0.0.0:30000 (as in sample/conf configs), from any
# network location that can reach that port:
BODY="shutdown"
printf 'POST /shutdown HTTP/1.1\r\nHost: <signer-ip>:30000\r\nConnection: close\r\nContent-Length: %d\r\nContent-Type: text/plain\r\n\r\n%s' \
  "${#BODY}" "$BODY" | nc <signer-ip> 30000
```
This mirrors `SignerStopSignaler::send` exactly (`libsigner/src/events.rs:382-393`) and causes the target signer's event-receiver thread to exit permanently, per the unauthenticated branch at `libsigner/src/events.rs:443-445`.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
