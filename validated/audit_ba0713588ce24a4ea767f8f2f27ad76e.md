### Title
Path traversal in `newCacheConfig`'s alternate cache key bypasses key sanitization when `FF_HASH_CACHE_KEYS` is enabled - (File: shells/abstract.go)

### Summary
`newCacheConfig` disables `cachekey.Sanitize` (which normally clamps `../` traversal to a virtual root) whenever `FF_HASH_CACHE_KEYS` is on, but still feeds the *raw, unsanitized* `humanKey` into `cacheAlternateKey`/`getArchivePath` to build `AlternateArchiveFile`. This lets an attacker-controlled cache key (from `cache:key`, `cache:fallback_keys`, or `CACHE_FALLBACK_KEY`) place the resulting `cache.zip` path outside `build.CacheDir`.

### Finding Description
In [1](#0-0) , when `FF_HASH_CACHE_KEYS` is enabled, `sanitizer` is replaced with an identity function (`func(s string) (string, error) { return s, nil }`), so `humanKey` is never passed through `cachekey.Sanitize`, which is the only component that resolves `../` traversal against a virtual root ( [2](#0-1) ).

The primary `ArchiveFile` is safe because it's built from `hashedKey = sha256(humanKey)` — a fixed-format hex digest with no traversal characters ( [3](#0-2) ).

However, `AlternateArchiveFile` is built from `alternateKey`, and `cacheAlternateKey` returns the **raw, unsanitized `humanKey` itself** when hashing is enabled (the "downgrade compatibility" branch): [4](#0-3) 

This raw key is passed straight into `getArchivePath`, which does `path.Join(build.CacheDir, key, "cache.zip")` and then makes it relative to `build.BuildDir` (unless `FF_USE_POWERSHELL_PATH_RESOLVER` is set): [5](#0-4) 

Because `path.Join`/`filepath.Rel` only *clean* paths (collapsing `..` arithmetically) rather than *confining* them to a root, a cache key such as `../../../../some/other/path` — fully attacker-controlled via `.gitlab-ci.yml` `cache.key`, `cache.fallback_keys`, or the `CACHE_FALLBACK_KEY` variable, all of which are expanded via `build.GetAllVariables().ExpandValue` — resolves to a path outside `build.CacheDir`, landing anywhere reachable relative to `build.BuildDir`. The `keyChecks` validators (e.g. `blockProtectedFallback` in `extractCacheOrFallbackCachesWrapper`, [6](#0-5) ) only run against `humanKey` for suffix rejection, not against traversal content, and do not apply at all to the derived `alternateKey`/`AlternateArchiveFile`.

The resulting `AlternateArchiveFile` path is subsequently used unchecked to fetch/write the "alternate" cache blob during extraction/upload (`getAlternateCacheDownloadURL`, `addExtractCacheCommand`), so the traversal-controlled path is actually acted upon by the cache-extractor/archiver helper invoked in the job script.

### Impact Explanation
An unprivileged pipeline author can cause the `cache.zip` file written/read for the "alternate" (legacy/hashed-downgrade) cache path to land outside the intended `CacheDir`, anywhere reachable via relative traversal from `build.BuildDir` on the runner's filesystem (build directory, other concurrent jobs' cache/build directories sharing the same base builds path, or other locations writable by the job/helper). This is the exact "cache local paths colliding with other trusted runner state" scenario in the question — the isolation invariant "cache files must stay isolated from artifact and build-state paths" is broken because the safety mechanism (`cachekey.Sanitize`) is silently disabled for this derived path whenever the feature flag is toggled on.

### Likelihood Explanation
Preconditions: `FF_HASH_CACHE_KEYS=true` must be set (this is a runner feature-flag environment/CI variable, commonly settable by a pipeline author via `variables:` in `.gitlab-ci.yml` unless explicitly restricted by the runner admin), and a `.gitlab-ci.yml` job that uses `cache:` with an attacker-chosen key or fallback key containing `../` sequences (or an equivalent `CACHE_FALLBACK_KEY` value). Both are ordinary, user-controlled CI inputs, requiring no special runner/project privileges, and the bug is deterministically reproducible on every cache extraction/upload for that job.

### Recommendation
Never bypass `cachekey.Sanitize` for the value used to build a filesystem path. Specifically:
- Always sanitize the raw key with `cachekey.Sanitize` (or an equivalent traversal-clamping function) before it is used to compute `AlternateArchiveFile`, regardless of `FF_HASH_CACHE_KEYS`.
- After computing `ArchiveFile`/`AlternateArchiveFile`, verify (e.g., via `filepath.Rel` + reject any leading `..` component, or `strings.HasPrefix` against the cleaned `CacheDir`) that the final path is actually contained within `build.CacheDir` before use, and fail the cache operation otherwise.

### Proof of Concept
Go unit test targeting `newCacheConfig` in `shells/abstract_test.go`:
```go
func TestNewCacheConfig_AlternateKeyTraversalEscapesCacheDir(t *testing.T) {
    build := &common.Build{ /* ... CacheDir: "cache", BuildDir: "/builds/proj" ... */ }
    build.Runner.RunnerSettings.FeatureFlags = map[string]bool{featureflags.HashCacheKeys.Name: true}

    cc, _, err := newCacheConfig(build, "../../../../etc/passwd-like-traversal")
    require.NoError(t, err)

    // AlternateArchiveFile should stay within CacheDir but escapes it.
    cleaned := filepath.Clean(filepath.Join(build.BuildDir, cc.AlternateArchiveFile))
    assert.True(t, strings.HasPrefix(cleaned, filepath.Join(build.BuildDir, build.CacheDir)),
        "AlternateArchiveFile escaped CacheDir: %s", cleaned)
}
```
Expected (current/buggy) result: the assertion fails, proving `cleaned` lies outside `CacheDir`, confirming the traversal escape. After the fix (sanitizing the alternate key and/or enforcing a containment check), the assertion should pass.

```go
func Sanitize(cacheKey string) (string, error) {
	if cacheKey == "" {
		return "", nil
	}

	// Decode percent-encoded chars and normalise separators, then
	// resolve traversals against a virtual root so ".." can never
	// escape beyond the root.
	cleaned := path.Clean("/" + normaliser.Replace(cacheKey))

	// Strip the leading "/" we added, split into segments, then walk
	// backwards trimming trailing whitespace from the rightmost
	// segments—dropping any that become empty.
	parts := strings.Split(cleaned[1:], "/")
	n := len(parts)
	for n > 0 {
		parts[n-1] = strings.TrimRightFunc(parts[n-1], unicode.IsSpace)
		if parts[n-1] != "" {
			break
		}
		n--
	}

	key := strings.Join(parts[:n], "/")

	if key == "" {
		return "", fmt.Errorf("cache key %q could not be sanitized", cacheKey)
	}

	return key, nil
```
