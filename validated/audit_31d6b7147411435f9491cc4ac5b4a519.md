### Title
Unsafe `int64`→`uint` cast in stale-message freshness check bypasses replay protection - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The `web_api_trigger` legacy-message handler on the Gateway performs an unchecked, signed-to-unsigned type cast on an attacker-controlled `Timestamp` field when deciding whether an incoming request is "stale." A negative or crafted `Timestamp` value wraps around during the `uint()` conversion, defeating the intended freshness/replay check.

### Finding Description
`HandleLegacyUserMessage` unmarshals the client-supplied JSON payload into `webapicap.TriggerRequestPayload` and then evaluates staleness using an unsafe cast: [1](#0-0) [2](#0-1) 

The staleness comparison is:
```go
if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
    // reject as stale
}
```
`payload.Timestamp` originates from `body.Payload`, which is JSON supplied by an unprivileged client and is only checked for `== 0` beforehand — there is no bounds check preventing negative values before the cast is applied. Casting a negative (or otherwise crafted) signed integer to Go's `uint` produces a very large unsigned value via two's-complement wraparound, so `uint(payload.Timestamp)` can be made larger than `uint(time.Now().Unix())-MaxAllowedMessageAgeSec` regardless of the real elapsed time, causing the "stale message" branch to be skipped.

This is the same bug class flagged in the external report — using raw Go type conversions (`uint(x)`, `int32(x)`, etc.) without first validating that the source value fits/is semantically valid for the destination type — applied here to a value that gates an internet-facing gateway handler’s message-freshness/anti-replay control, reachable directly from `gateway.ProcessRequest` → `h.HandleLegacyUserMessage`: [3](#0-2) 

### Impact Explanation
The freshness check is the mechanism that limits how long a previously-signed `web_api_trigger` request can be replayed against DON nodes. Signature validity is enforced separately (`msg.Validate()` in the gateway) but is orthogonal to freshness — a validly-signed request that is very old should be rejected by this check. Bypassing the check via the unsafe cast allows a validly-signed but stale trigger message to be treated as fresh and forwarded to all DON members, undermining the intended anti-replay protection for the web API trigger capability.

### Likelihood Explanation
The `Timestamp` field is fully attacker-controlled JSON input parsed directly from the incoming message body before any range validation, and the vulnerable code path is reached unconditionally for every `web_api_trigger` legacy message, making this straightforward to trigger from any unprivileged client able to reach the Gateway's HTTP-facing `ProcessRequest` entrypoint.

### Recommendation
Validate `payload.Timestamp` is non-negative (and within a sane bound) before converting, and perform the comparison using signed arithmetic (`int64`) throughout instead of casting to `uint`:
```go
now := time.Now().Unix()
if payload.Timestamp <= 0 || now-int64(h.config.MaxAllowedMessageAgeSec) > payload.Timestamp {
    // reject as stale/invalid
}
```
More generally, replace ad-hoc `uint(...)`/`int32(...)` casts across the gateway/handler code with range-checked conversions (as is already done correctly in `system-tests/lib/conversions/ints.go`'s `MustSafeUint32`/`MustSafeInt64` helpers) wherever the source value originates from external, unprivileged input.

### Proof of Concept
1. Send a legacy `web_api_trigger` message to the Gateway (`gateway.ProcessRequest`) with a validly-signed body whose JSON payload sets `"timestamp": -1` (or another negative value).
2. `json.Unmarshal` populates `payload.Timestamp` with the negative value.
3. In `HandleLegacyUserMessage`, `uint(payload.Timestamp)` wraps to a value near `math.MaxUint64`, which is always greater than `uint(time.Now().Unix()) - h.config.MaxAllowedMessageAgeSec`.
4. The "stale message" branch is skipped even though the request should be rejected, and the request is forwarded to all DON members via `don.SendToNode`. [4](#0-3)

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(

				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}
