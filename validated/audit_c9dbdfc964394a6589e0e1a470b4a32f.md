### Title
Stale confirmations from removed multisig members remain counted toward the execution threshold - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member()` in `multisig2/src/lib.rs` removes a departing member from `self.members` and deletes only the requests that member itself created, but never scans or purges that member's confirmation entries recorded on *other* still-pending requests. Since `confirm()` only checks `confirmations.len()` against `num_confirmations` without re-validating that every recorded confirmer is a current member, a confirmation cast by an account that has since been removed still counts toward the K-of-N threshold.

### Finding Description
`confirm()` adds the caller's identity string to the request's `confirmations: HashSet<String>` and executes the request once `confirmations.len() as u32 + 1 >= self.num_confirmations` [1](#0-0) . `delete_member()` is the only place confirmations get cleaned up in relation to membership changes, and it purges confirmations solely for `request_ids` where `r.member == member` (i.e., requests the removed member authored) — it does not touch `self.confirmations` entries where the removed member merely confirmed a request authored by someone else [2](#0-1) . `assert_valid_request()`, used by both `confirm()` and `delete_request()`, only checks that the *caller* is currently a member; it performs no re-validation of existing confirmation entries [3](#0-2) .

This breaks the intended binding: `confirmations counted == confirmations from live members`. Concretely:
1. Member A creates request R (e.g., `Transfer` or `AddKey`) targeting some receiver.
2. Member B confirms R, adding `"B"` to `confirmations[R]`.
3. Before threshold is reached, the multisig (via a separate, unrelated, legitimately-executed request) removes B as a member via `DeleteMember { member: B }` — `delete_member()` only clears requests *authored by B*, so `confirmations[R]` still contains B's confirmation string.
4. Remaining members continue confirming R. When `confirmations.len() + 1 >= num_confirmations`, R executes — but one of the counted confirmations came from an account that is no longer a multisig member at all.

### Impact Explanation
This allows a request to execute with genuinely fewer *current* member confirmations than `num_confirmations` requires — a stale/former member's approval is silently reused to help clear the K-of-N threshold. Since `execute_request` can perform `Transfer`, `AddKey` (full access key), `AddMember`, or arbitrary `FunctionCall` actions, this can result in a transaction executed below the intended threshold, matching the "multisig request executed below threshold" critical-impact category — funds or key control could move out of the account with insufficient live authorization.

### Likelihood Explanation
Requires: (a) a request pending confirmation, (b) at least one confirming member subsequently removed via a legitimate `DeleteMember` request, and (c) the remaining confirmations reaching threshold afterward without the stale one being purged. This is a normal operational sequence for any multisig that rotates membership (e.g., removing a compromised or departing signer) while other requests are in flight — no attacker-controlled deployment or malicious node is required, only ordinary multisig member turnover.

### Recommendation
When removing a member in `delete_member()`, iterate over `self.confirmations` (not just `self.requests`) and remove the departing member's identity string from every request's confirmation set, not only from requests that member authored. Alternatively, revalidate at `confirm()`/execution time that all recorded confirmers in `confirmations[request_id]` are still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
```
1. new(members = [A, B, C, D], num_confirmations = 3)
2. A: add_request(Transfer{...}) -> request_id = R   // A auto-counts? no, add_request alone doesn't confirm
3. B: confirm(R)                                     // confirmations[R] = {B}
4. A: add_request_and_confirm(DeleteMember{member: B}) 
   C: confirm(...)                                   // executes, B removed from members
      -> delete_member(B) only purges requests authored by B; R is untouched, confirmations[R] still = {B}
5. C: confirm(R)                                      // confirmations[R] = {B, C}, len=2, 2+1 < 3, not yet
6. D: confirm(R)                                      // len=2 -> 2+1 >= 3 -> executes R
   Effective live-member approvals for R: only C and D (B is no longer a member) = 2 confirmations,
   yet num_confirmations = 3 was reported satisfied.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
