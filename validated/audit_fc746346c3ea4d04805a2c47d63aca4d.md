## Title
Unvalidated fee amounts in `createDstEscrow` cause permanent underflow revert in `EscrowDst._withdraw`, freezing maker funds - (File: `contracts/BaseEscrowFactory.sol` / `contracts/EscrowDst.sol`)

### Summary
`createDstEscrow` lets the taker/resolver supply arbitrary `protocolFeeAmount` and `integratorFeeAmount` values inside `Immutables.parameters` without any validation against `immutables.amount`. `EscrowDst._withdraw` later computes `immutables.amount - integratorFeeAmount - protocolFeeAmount` unchecked; if the fee sum exceeds `amount`, every withdrawal (private and public) permanently reverts on underflow, exactly mirroring the Velar root cause where an unchecked fee subtraction that can exceed the principal renders the position (here, the escrow) permanently unable to settle via the normal path.

### Finding Description
On the source path, `BaseEscrowFactory._postInteraction` explicitly guards against fees exceeding the swap amount: [1](#0-0) 

However, `createDstEscrow` builds the destination `Immutables` directly from caller-supplied calldata (`dstImmutables`), including the `parameters` field that encodes `protocolFeeAmount`/`integratorFeeAmount`, and performs no equivalent check: [2](#0-1) 

The only checks performed are `msg.value == nativeAmount` and the cancellation-timestamp ordering — nothing constrains `protocolFeeAmount + integratorFeeAmount` relative to `immutables.amount`.

`EscrowDst._withdraw` then unconditionally subtracts both fee amounts from `immutables.amount`: [3](#0-2) 

Actually the correct citation: [4](#0-3) 

Since Solidity ≥0.8 reverts on underflow, once `integratorFeeAmount + protocolFeeAmount > immutables.amount`, the line `uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;` reverts unconditionally for `withdraw`, `publicWithdraw` — for every caller, forever, because `immutables` (including the bad fee values) are fixed at deployment and hashed into the deterministic address (`ImmutablesLib.hashMem`), so they cannot be corrected later: [5](#0-4) 

This is the same bug class as the referenced Velar report: an unchecked fee/funding subtraction that can exceed the principal amount, causing a permanent revert on the intended settlement path and forcing resolution through a fallback path (there: liquidation; here: `cancel()`/`rescueFunds`) that benefits the funder (taker) at the expense of the counterparty (maker).

### Impact Explanation
The maker never receives the destination tokens they are owed: `withdraw`/`publicWithdraw` always revert once the fee sum exceeds the escrow amount, and the only recovery path is `cancel()` after `DstCancellation`, which returns the entire `amount` to the taker, not the maker: [6](#0-5) 
This is a temporary freezing of the maker's expected funds during the live swap lifecycle (the destination tokens sit unclaimable from deployment until cancellation, at minimum, and are ultimately redirected away from the maker), matching the bounty's High-severity category for temporary freezing of funds during the live swap lifecycle.

### Likelihood Explanation
The taker/resolver fully controls the `Immutables.parameters` payload passed to `createDstEscrow` — this is a normal, unprivileged, permissionless entry point explicitly listed in the audit scope ("destination escrow creation"). No signature or off-chain component enforces `protocolFeeAmount + integratorFeeAmount <= amount` on-chain for the destination side (only the source `_postInteraction` path has this guard), so a resolver can trivially trigger this either by a bug in their own tooling or deliberately to grief a maker.

### Recommendation
Add the same guard used in `_postInteraction` to `createDstEscrow`:
```solidity
if (immutables.protocolFeeAmount() + immutables.integratorFeeAmount() >= immutables.amount) revert InvalidFeeAmounts();
```
before deploying the escrow, so malformed fee parameters cannot be locked into an unrecoverable clone.

### Proof of Concept
1. Resolver calls `createDstEscrow` with `dstImmutables.amount = 100` and `parameters` encoding `protocolFeeAmount = 60`, `integratorFeeAmount = 60` (sum 120 > 100), funding the required `msg.value`/token transfer.
2. `BaseEscrowFactory.createDstEscrow` performs no fee-vs-amount check and deploys the clone: [2](#0-1) 
3. After `DstWithdrawal` time, maker (or anyone with access token via `publicWithdraw`) calls `withdraw(secret, immutables)`; `_withdraw` computes `100 - 60 - 60`, which underflows and reverts, permanently blocking all withdrawal attempts: [4](#0-3) 
4. The maker can never obtain the destination tokens; eventually, after `DstCancellation`, the taker calls `cancel()` and reclaims the full `amount` back, leaving the maker without the swap proceeds they were promised.

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
```

```text
    function hashMem(IBaseEscrow.Immutables memory immutables) internal pure returns(bytes32 ret) {
        // Compute the EIP-712 hash for the immutables struct
        // Patch the last word (bytes parameters) in the struct with the hash of it
        bytes memory parameters = immutables.parameters;
        assembly ("memory-safe") {
            let parametersHash := keccak256(add(parameters, 0x20), mload(parameters))
            let patchLocation := sub(add(immutables, IMMUTABLES_SIZE), 0x20)
            let backup := mload(patchLocation)

            // Patch the last word with the hash of parameters to compute the EIP-712 hash
            mstore(patchLocation, parametersHash)
            ret := keccak256(immutables, IMMUTABLES_SIZE)

            mstore(patchLocation, backup) // Restore the original value
        }
    }
```
