### Title
`masking.db` and its derived key file are created world-readable (0666/0644) inside a directory the runner itself makes accessible to other OS users, letting a non-owning user read and decrypt masked secret material - (File: `commands/helpers/internal/store/store_unix.go`)

### Summary
`openFile` in `store_unix.go` creates `masking.db` with mode `0666`, and `Store.Open` in `store.go` writes the companion key-derivation file (`runner<sha256(pathname)>`) with mode `0644`. Both live in `RUNNER_TEMP_PROJECT_DIR`, which `bootstrap()` in `commands/helpers/proxy_exec.go` creates with `os.MkdirAll(dst, 0o777)` specifically so a different OS user (the "job user" in runner's user-isolation model) can access it. Because both files are readable by anyone who can traverse that directory, a non-owning local user can read the ciphertext store and both halves of the encryption key without going through the runner process at all.

### Finding Description
`Store.Open` (`commands/helpers/internal/store/store.go:29-77`) builds the store path as `dir/masking.db` and a sibling key file `dir/runner<hex(sha256(pathname))>`. The key file is written with `os.WriteFile(keyPath, generateKey(), 0o644)` [1](#0-0) , and the store file itself is opened/created via `openFile`, which explicitly sets `0666` on first creation [2](#0-1) .

`deriveEncryptionKey` reads the first 32 bytes of the store file (`key1`) and the entire key file (`key2`) and XORs them to produce the actual ChaCha20-Poly1305 key [3](#0-2) . Both inputs to this derivation are plaintext files on disk with permissive modes — there is no reliance on file-descriptor-only access or in-memory-only secrets.

The directory these files live in, `RUNNER_TEMP_PROJECT_DIR`, is created by `bootstrap()` with `os.MkdirAll(dst, 0o777)` [4](#0-3) . This directory is deliberately world-writable/traversable because the runner's job-user-isolation feature intentionally runs the job as a different OS user than the process that wrote the helper/store files — that's the entire point of the `0o777` mode. This means the directory access control that would normally prevent a random local user from reaching these files is intentionally relaxed to support the isolation model, and the file-level permissions (`0666`/`0644`) provide no additional restriction on top of that.

Consequently, once any local user (e.g., a different job's isolated OS user, or any account with access to the shared temp hierarchy) can enter that directory, they can:
1. `os.ReadFile` the store file to get `key1` (first 32 bytes) and all ciphertext lines.
2. `os.ReadFile` the key file to get `key2`.
3. XOR them to recover the real ChaCha20-Poly1305 key, exactly as `deriveEncryptionKey` does.
4. Decrypt every masked value ever added via `Store.Add`, entirely outside the job process and its intended masking boundary.

No existing check mitigates this: there's no ACL restriction, no ownership check on the key/store files beyond default process umask-independent explicit chmod calls, and no ephemeral/in-memory-only key handling.

### Impact Explanation
An unprivileged local user who has access to the shared job-temp directory hierarchy (which the runner's own isolation feature is designed to allow, since it deliberately runs helper output/key files with permissions readable by a different job UID) can fully recover the plaintext of every value passed to `AddMask`/`Store.Add` for that job — i.e., all secrets the runner is supposed to keep masked in logs/traces. This defeats the confidentiality guarantee of the masking store independent of the runner process, satisfying the described scoped impact: unauthorized file access to (and full decryption of) protected secret material off the intended path.

### Likelihood Explanation
This is fully attacker-triggerable with only the capabilities already granted by the runner's own job-user-isolation design: any distinct OS user that the runner intentionally permits into the shared `0o777` temp directory (which is the explicit purpose of that permission) can reach and read `masking.db` and its key file with a plain `os.ReadFile`, no privilege escalation, no race, no additional exploit primitive required. It is deterministic and repeatable for every job that uses this proxy-exec/masking store path.

### Recommendation
- Restrict the store file mode to `0600` (owner-only) in `openFile`, and only chmod when needed for the intended accessing UID rather than defaulting to `0666`.
- Restrict the key file write in `Store.Open` to `0600` instead of `0644`.
- If the job-user-isolation model requires cross-UID access to these files, use per-user ACLs (e.g., POSIX ACLs or a supplementary group) to grant read access explicitly to the job UID rather than making the file/directory world-readable.
- Avoid keeping the two encryption-key halves as ordinary readable files; consider deriving/holding one half only in memory (passed via an already-open, unlinked file descriptor or environment inherited only by the intended child process) so a third-party OS user cannot statically read it from disk.

### Proof of Concept
```go
package store_test

import (
    "os"
    "os/exec"
    "path/filepath"
    "testing"

    "gitlab.com/gitlab-org/gitlab-runner/commands/helpers/internal/store"
)

func TestMaskingDBWorldReadable(t *testing.T) {
    dir := t.TempDir()

    s, err := store.Open(dir)
    if err != nil {
        t.Fatalf("open store: %v", err)
    }
    if err := s.Add("super-secret-value"); err != nil {
        t.Fatalf("add: %v", err)
    }
    s.Close()

    pathname := filepath.Join(dir, "masking.db")
    info, err := os.Stat(pathname)
    if err != nil {
        t.Fatalf("stat: %v", err)
    }

    // Assert the file is world-readable (mode bits include 0004).
    if info.Mode().Perm()&0o004 == 0 {
        t.Fatalf("expected masking.db to be world-readable, got mode %v", info.Mode().Perm())
    }

    // Simulate a different unprivileged OS user reading the file directly,
    // bypassing the Store API entirely.
    cmd := exec.Command("su", "nobody", "-c", "cat "+pathname)
    out, err := cmd.CombinedOutput()
    if err != nil {
        t.Fatalf("expected unprivileged read to succeed, got error: %v, output: %s", err, out)
    }
    if len(out) == 0 {
        t.Fatalf("expected non-empty ciphertext read by unprivileged user")
    }
}
```
Expected assertions: the file mode includes the world-read bit, and a process running as a different unprivileged user (`nobody`) can read the raw store bytes directly from disk without going through `Store.List`/the runner process — demonstrating the boundary bypass. Combined with reading the sibling key file (also world-readable) and running `deriveEncryptionKey`'s XOR logic, the same unprivileged user can fully decrypt the recovered ciphertext.

func deriveEncryptionKey(f *os.File, keyPath string) ([]byte, error) {
	var key1 [32]byte
	if _, err := io.ReadFull(f, key1[:]); err != nil {
		return nil, err
	}

	key2, err := os.ReadFile(keyPath)
	if err != nil {
		return nil, err
	}

	if len(key2) < len(key1) {
		return nil, fmt.Errorf("key1 and key2 not the same size")
	}

	for i := 0; i < len(key1); i++ {
		key1[i] ^= key2[i]
	}

	return key1[:], nil
}
```

func openFile(pathname string) (*os.File, error) {
	// Check if file exists before opening
	_, err := os.Stat(pathname)
	isNewFile := os.IsNotExist(err)

	f, err := os.OpenFile(pathname, os.O_APPEND|os.O_RDWR|os.O_CREATE, 0666)
	if err != nil {
		return nil, err
	}

	// Only chmod if we just created the file
	if isNewFile {
		if err := os.Chmod(pathname, 0666); err != nil {
			f.Close()
			return nil, err
		}
	}

	return f, nil
}
```
