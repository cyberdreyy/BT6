### Title
Post-default withdraw receipts paid 1:1 drain the shared `defaultRecoveryReserve`, stealing recovery from defaulted-epoch claimants - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault` settles three different claim generations out of one pool of underlyings. After `finalizeDefaultRecovery`, the `defaultRecoveryReserve` is sized exactly to cover the pre-default claim basis at `defaultRecoveryPrice`, yet `_claimPostDefaultWithdrawRequest` also debits that same reserve at par for receipts minted *after* finalization. Because post-default payouts were never part of `totalBasis`, each post-default claim replays value that was reserved for defaulted-epoch receipt holders, so later defaulted claimants find the reserve empty and their claims permanently underfunded. This is the vault analog of the CVE-2020-14302 class: an endpoint (`claimWithdrawRequest`) accepts repeated invocations that re-consume a shared, already-allocated resource (`defaultRecoveryReserve`) without a matching allocation.

### Finding Description
In `finalizeDefaultRecovery` (line 686-692) the reserve is fixed to `reserveAmount = _recoveredAmount + prefundedReserve + defaultRecoveryReserve` and the per-unit payout is `defaultRecoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis`, where `totalBasis = activeBasis + pendingBasis` covers only claims that existed at finalization. After this, a KYC'd lender can call `requestWithdraw` (lines 247-257): the CDO passes an already-haircut `_amount`, the vault mints a receipt and records `postDefaultRequests[_user]`. On `claimWithdrawRequest`, `_claimPostDefaultWithdrawRequest` (lines 760-767) zeroes the request, burns the receipt and calls `_transferDefaultRecovery`, which does `defaultRecoveryReserve -= _amount` (line 915) and transfers the full `_amount` at par.

The reserve invariant is therefore broken: the reserve must satisfy `Σ defaulted claims = totalBasis * recoveryPrice / RECOVERY_FULL ≈ reserveAmount` plus all active-LP tranche redemptions at the recovery-priced `virtualPrice`, but post-default claims consume it at 1:1 with zero basis contribution. Each post-default claim of amount `A` removes `A` units that were implicitly promised to pre-default claimants. When recovery is below par (`recoveryPrice < RECOVERY_FULL`, the normal outcome of a default), the arithmetic guarantees insolvency: aggregate obligations strictly exceed `reserveAmount`, so the last defaulted-epoch claimants' `_transferDefaultRecovery` calls either revert on underflow or pay less than `claimBasis * defaultRecoveryPrice`.

### Impact Explanation
Direct theft / permanent freezing of unclaimed yield. A post-default withdrawer extracts `A` underlying at par from a reserve that belongs pro-rata to defaulted receipt holders; equivalently, `Σ(postDefaultRequests)` worth of recovery is unpayable, permanently freezing that portion of defaulted claims. The quantified loss equals the total post-default request volume (up to the full reserve in the worst case). This mirrors the CVE's "same state accepted multiple times": each call to the claim endpoint re-spends the fixed recovery allocation because no accounting entry was reserved for the new claimant class.

### Likelihood Explanation
Requires a borrower default with partial recovery (`recoveryPrice < RECOVERY_FULL`) and at least one lender requesting withdrawal after `defaultRecoveryFinalized`. Both are reachable through normal, unprivileged flows: `requestWithdraw` post-default is explicitly supported (it mints `postDefaultRequests` rather than reverting), and `claimWithdrawRequest` is callable by any receipt holder via the CDO. Honest privileged roles only perform the standard default/finalize sequence; the attacker is an ordinary KYC-passing lender sequencing around those calls. First-come-first-served ordering makes exploitation trivial once a default is finalized.

### Recommendation
Do not pay post-default requests from `defaultRecoveryReserve` unless the reserve was provisioned for them. Options: (a) fund post-default receipts exclusively from new borrower repayments routed through a separate, non-reserve balance, enforced by transferring via `_transferFundedClaim` (which already refuses to touch the reserve, lines 897-907); or (b) apply `defaultRecoveryPrice` to post-default claims too, paying `postDefaultRequests[_user] * defaultRecoveryPrice / RECOVERY_FULL`, and add post-default basis into `totalBasis` at finalization. Add an invariant check in `finalizeDefaultRecovery`/`_transferDefaultRecovery` that cumulative default-reserve payouts never exceed `reserveAmount`.

### Proof of Concept
Foundry fork PoC (against `test/foundry/IdleCreditVault.t.sol` harness):

```solidity
// Setup: users U1 (LP, deposited, requests withdraw in epoch N),
// pool defaults in epoch N, manager finalizes recovery with
// recoveredAmount < totalBasis  => defaultRecoveryPrice < RECOVERY_FULL.

// 1) Recovery finalized
vm.prank(manager); // via CDO path
cdoEpoch.finalizeDefault(...); // strategy.finalizeDefaultRecovery(recovered, source)
uint256 reserve = strategy.defaultRecoveryReserve();

// 2) Post-default attacker request (allowed: no revert path)
vm.prank(attacker); // KYC-passing lender holding tranche tokens
cdoEpoch.requestWithdraw(trancheAmt, address(tranche)); // mints postDefaultRequests
uint256 postAmt = strategy.postDefaultRequests(attacker);

// 3) Attacker claims at par from the recovery reserve
uint256 balPre = underlying.balanceOf(attacker);
vm.prank(attacker);
cdoEpoch.claimWithdrawRequest();
assertEq(underlying.balanceOf(attacker) - balPre, postAmt); // paid 1:1
assertEq(strategy.defaultRecoveryReserve(), reserve - postAmt);

// 4) Honest defaulted claimant U1 now cannot receive full claimBasis * price
vm.prank(U1);
vm.expectRevert(); // underflow in defaultRecoveryReserve or shortfall
cdoEpoch.claimWithdrawRequest();
```

The assertions show `postAmt` was paid at par from a reserve never provisioned for it, and the honest defaulted claimant's haircutted payout becomes unpayable — quantified loss `postAmt` transferred from defaulted claimants to the post-default claimer.
