### Title
Unbounded recursive descent into attacker-supplied MPT preimages allows a fault-dispute-game participant to stall or crash the proof program - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`base-proof-mpt`'s `TrieNode::open`/`insert`/`delete` and `OrderedListWalker::fetch_leaves` recursively unblind and descend into trie nodes fetched from a `TrieProvider` (an oracle backed by preimages supplied during fault-proof execution) with no maximum recursion/depth bound, analogous to OctoRPKI's unbounded certificate-chain traversal (CVE-2021-3908 / GHSA-g5gj-9ggf-9vmq).

### Finding Description
`TrieNode::open` recurses through `Extension`/`Blinded` nodes: on a `Blinded` node it calls `self.unblind(fetcher)` (fetching the preimage keyed by `commitment`) and then recurses on `self.open(path, fetcher)`; on an `Extension` node whose `prefix` matches the query path it recurses into the child node after unblinding it. [1](#0-0) 

Nothing in the decoder enforces that an `Extension` node's `prefix` be non-empty. `try_decode_leaf_or_extension_payload` accepts any decoded `path`/nibble prefix, including a zero-length one, for both `Leaf` and `Extension` variants: [2](#0-1) 

Because a zero-length extension prefix trivially satisfies `path.slice(..prefix.len()) == *prefix` for any path, an attacker who controls the preimage-oracle data (the party supplying preimages/hints to the fault-proof program, i.e. an untrusted dispute-game participant) can chain arbitrarily many `Extension{prefix: [], node: Blinded(next_hash)}` nodes, each unblinding to the next via `unblind`: [3](#0-2) 

Each hop consumes zero path nibbles, so the recursion depth is *not* bounded by the fixed 64-nibble account/storage key length the way a well-formed MPT is. The same unbounded-recursion pattern also exists in `insert`/`delete` (which follow `Blinded`/`Extension` nodes the same way) and in `OrderedListWalker::fetch_leaves`, which recursively unblinds and descends `Branch`/`Extension` chains when reconstructing the transactions/receipts ordered list: [4](#0-3) 

The `TrieProvider` trait that supplies preimages is a simple `trie_node_by_hash(hash) -> TrieNode` lookup with no depth accounting anywhere in the call chain: [5](#0-4) 

This is the same bug class as OctoRPKI: a hierarchical, externally-suppliable data structure (RPKI certificate chain there; MPT extension-node chain here) is walked with recursion that has no maximum-depth guard, so an adversarial data provider can make traversal (here, the fault-proof program's state/storage/receipts/transaction trie reads) run for as long as they can supply preimages, exhausting the call stack or looping effectively without termination.

Notably, other parts of this same codebase *do* explicitly bound similar recursive/hierarchical structures against exactly this bug class — e.g. `PolicyRegistryV2::validate_composite_child_policies` rejects composite children that are themselves composite, capping policy-authorization recursion at depth 1 [6](#0-5) , and EIP-8130 delegate authentication explicitly rejects nested delegate authenticators ("Delegation is depth-1 only") [7](#0-6) . The MPT walker has no equivalent guard.

### Impact Explanation
The fault-proof program (`base-proof-executor`/`base-proof-mpt`) is the component that computes the disputed output root during an interactive fault dispute game; it consumes preimages supplied by (or hinted from) an untrusted party during that dispute. If a dispute-game participant can supply a maliciously long chain of zero-length-prefix extension/blinded nodes as "preimages," the honest proof program attempting to open/insert/delete or reconstruct an ordered list against that data can be driven into deep, unbounded recursion, causing a stack overflow (process crash / halt of the proof program) or, at minimum, unbounded computation that prevents the program from completing in the fault-proof's fixed compute/step budget. Either outcome can prevent the honest party's proof from being computed/verified, resulting in a wrong provable output root prevailing in the dispute game or the proof program being unable to serve its designated function — a concrete, Medium-severity availability/integrity impact on the fault-proof path, mirroring the "node halt" / "wrong provable output root" impact classes called out in the validation criteria.

### Likelihood Explanation
Reaching this requires the attacker to control (or influence) the preimages resolved by the `TrieProvider`/oracle during fault-proof execution — i.e., act as a dispute-game participant supplying data to the honest party's derivation of state proofs. Constructing the malicious node chain itself is cheap (no cryptographic work beyond one keccak256 per hop to produce a valid blinding commitment for each crafted node), so the cost to an attacker scales linearly with the depth they wish to force, while the victim's recursive call stack scales the same way. This is a real, reachable path for any actor participating in a dispute game, but I was not able to fully confirm within the available context whether a depth or resource guard exists further up the stack (e.g. in `base-proof-host`, `caching_oracle.rs`, or the on-chain fault-proof VM step limit) that might mitigate unbounded native-stack recursion before it becomes exploitable; a search for `MAX_DEPTH`/`depth`/`recursion` in `crates/proof/**` returned no explicit depth-limiting logic in the MPT or its callers, but the interaction with the surrounding proof-VM's step/gas metering was not verifiable with the tools available.

### Recommendation
Add an explicit maximum recursion/unblind depth to `TrieNode::open`, `insert`, `delete`, and `OrderedListWalker::fetch_leaves` (e.g., bound to the maximum legitimate MPT depth for 32-byte keys, ~64, plus a small margin), returning a `TrieNodeError` when exceeded. Additionally, consider rejecting `Extension` nodes with an empty `prefix` at decode time (`try_decode_leaf_or_extension_payload`), since a zero-nibble extension is never produced by a well-formed, canonically-encoded trie and only serves to enable this class of chain.

### Proof of Concept
Conceptual construction (cannot be executed without running the crate directly, but the code path is deterministic):
1. Build a chain of `n` `TrieNode::Extension { prefix: Nibbles::from_nibbles([]), node: Box::new(TrieNode::Blinded { commitment: hash_of_next }) }` nodes, where each node's RLP encoding is the preimage for the previous node's `commitment` (computed via `TrieNode::blind`, i.e. `keccak256(rlp_encode(node))`), terminating in a real `Leaf`.
2. Register all `n` preimages with a `TrieProvider` implementation (mirroring `TrieNodeProvider` used in the crate's own tests, e.g. `crates/proof/mpt/src/list_walker.rs` test helpers).
3. Call `TrieNode::from_hash(root).open(&path, &provider)` (or drive an `OrderedListWalker::hydrate`) with the root set to the outermost extension's blinded commitment.
4. Observe that `open`'s recursive `Blinded`→`unblind`→`Extension`→`open` cycle executes `n` times before reaching the leaf, with `n` bounded only by how many preimages the (attacker-controlled) provider is willing to supply — for sufficiently large `n` this overflows the native call stack.

    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.

                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }

    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

    fn try_decode_leaf_or_extension_payload(buf: &mut &[u8]) -> TrieNodeResult<Self> {
        // Decode the path and value of the leaf or extension node.
        let path = Bytes::decode(buf).map_err(TrieNodeError::RLPError)?;
        let Some(first_byte) = path.first() else {
            return Err(TrieNodeError::InvalidNodeType);
        };
        let first_nibble = first_byte >> NIBBLE_WIDTH;
        let first = match first_nibble {
            PREFIX_EXTENSION_ODD | PREFIX_LEAF_ODD => Some(first_byte & 0x0F),
            PREFIX_EXTENSION_EVEN | PREFIX_LEAF_EVEN => None,
            _ => return Err(TrieNodeError::InvalidNodeType),
        };

        // Check the high-order nibble of the path to determine the type of node.
        match first_nibble {
            PREFIX_EXTENSION_EVEN | PREFIX_EXTENSION_ODD => {
                // Extension node
                let extension_node_value = Self::decode(buf).map_err(TrieNodeError::RLPError)?;
                Ok(Self::Extension {
                    prefix: unpack_path_to_nibbles(first, path[1..].as_ref()),
                    node: Box::new(extension_node_value),
                })
            }
            PREFIX_LEAF_EVEN | PREFIX_LEAF_ODD => {
                // Leaf node
                let value = Bytes::decode(buf).map_err(TrieNodeError::RLPError)?;
                Ok(Self::Leaf { prefix: unpack_path_to_nibbles(first, path[1..].as_ref()), value })
            }
            _ => Err(TrieNodeError::InvalidNodeType),
        }
    }

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }
