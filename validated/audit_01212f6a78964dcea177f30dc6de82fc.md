### Title
Multisig executes requests below live-member threshold due to stale confirmations from deleted members - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm` in `multisig2/src/lib.rs` decides whether to execute a request purely by comparing the *size* of the stored `confirmations` `HashSet<String>` to `self.num_confirmations`, without verifying that every entry in that set still corresponds to a current member of `self.members`. `delete_member` only purges requests and confirmations that were *originated by* the removed member; it never scrubs that member's confirmation entries from other, still-pending requests. This breaks the binding `confirmations recorded == confirmations from currently-live members`, allowing a request to execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
- `confirm()` counts confirmations and executes once the threshold is met: `if confirmations.len() as u32 + 1 >= self.num_confirmations { ... self.execute_request(request) }` [1](#0-0) 
- `delete_member()` removes a member and only cleans up requests where `r.member == member` (i.e. requests the removed member *authored*), then removes that member from `self.members`: [2](#0-1) 
- It does **not** scan `self.confirmations` for entries keyed by the removed member's identity on requests authored by *other* members, so a prior confirmation from a now-deleted member remains stored in the `confirmations` set for still-pending requests.
- `assert_valid_request()` / `current_member()` only check that the *caller confirming right now* is a live member; they never re-validate the *existing* confirmers already stored in the set: [3](#0-2)  and [4](#0-3) 
- As a result, `confirmations.len()` (recorded claims of approval) can diverge from the number of approvals actually held by currently-live members — the exact custody-binding class called out in the prompt ("confirmations counted versus live members").

The equivalent v1 contract has the identical pattern: `DeleteKey` only removes requests/confirmations where `r.signer_pk == pk` [5](#0-4) , and `confirm()` counts `confirmations.len()` the same way [6](#0-5) .

### Impact Explanation
This allows a `MultiSigRequestAction::Transfer` or `FunctionCall` (or any other action) to be executed on the multisig account with only `num_confirmations - 1` (or fewer) live-member approvals, because one "confirmation" slot is filled by a stale entry belonging to a member who has since been removed. This is a direct instance of the Critical category "a multisig request executed below threshold," since NEAR/wNEAR can be transferred, keys added, or contracts deployed by the multisig account despite the currently-authorized signer set never reaching the required quorum.

### Likelihood Explanation
The precondition is a normal operational sequence, not an edge case requiring privileged access, a redeploy, or foundation involvement:
1. A request is created and partially confirmed by some members (below threshold).
2. Membership changes over time (turnover is expected for any long-lived multisig) and a member who already confirmed the pending request is later removed via a separate, properly-threshold-confirmed `DeleteMember` request.
3. `delete_member` only checks `self.members.len() - 1 >= self.num_confirmations` [7](#0-6) , so removal succeeds whenever there are more members than the confirmation threshold — a common configuration (e.g., 4 members, 3-of-4).
4. The original pending request is still sitting in `self.requests`/`self.confirmations` untouched, carrying the stale confirmation.
5. Any subsequent live member confirms, and the size check in `confirm()` treats the stale entry as valid, executing the request with one fewer live approver than the policy requires.

No attacker needs elevated privilege beyond being a normal remaining member; this is a latent state-management bug reachable through ordinary contract usage.

### Recommendation
When deleting a member in `delete_member`, iterate `self.confirmations` (not just `self.requests` filtered by `r.member == member`) and remove the deleted member's identity string from every request's confirmation set, not only from requests they authored. Alternatively, have `confirm()` (and any pre-execution check) filter the stored confirmation set against `self.members` before comparing its length to `num_confirmations`, so stale entries from removed members are never counted toward the threshold.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. `A` calls `add_request_and_confirm(request_X)` (Transfer action) → confirmations for `request_X` = `{A}` (count 1).
3. `B` calls `confirm(request_X)` → confirmations = `{A, B}` (count 2, below threshold 3, request stays pending).
4. Members `A`, `C`, `D` create and confirm a separate `DeleteMember { member: B }` request (3 confirmations reached, passes `members.len()-1 (3) >= num_confirmations (3)` check) → `B` is removed from `self.members`; only requests authored by `B` are purged — `request_X` (authored by `A`) and its confirmation set `{A, B}` remain untouched.
5. `C` (a still-live, distinct member) calls `confirm(request_X)`: `confirmations.len() (2) + 1 >= num_confirmations (3)` → true → `execute_request(request_X)` runs, transferring funds.
6. Result: `request_X` executed with confirmations `{A, B, C}`, but `B` is no longer a member — only `A` and `C` are live approvers, i.e., 2 out of 3 required, one short of the mandated threshold. This is Transfer of funds authorized below the configured multisig quorum.

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
