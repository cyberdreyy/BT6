### Title
View-role users can enumerate all configured chain node RPC URLs (with embedded API keys) via GET /v2/nodes - ([File: core/web/nodes_controller.go])

### Summary
The `/v2/nodes` route is registered under the generic `authv2` group, which is gated only by role-agnostic session/token authentication (`auth.Authenticate`), with no `RequiresEditRole`/`RequiresAdminRole` wrapper. `nodesController.Index` serializes each node's full TOML `Config` string — which includes the raw `URL`/`HTTPURL`/`WSURL` fields as configured by the node operator — directly into the JSON:API response with no redaction.

### Finding Description
The route wiring in [1](#0-0)  shows `nodes.GET("", paginatedRequest(nodesController.Index))` and `nodes.GET("/:network", ...)` are attached to the `authv2` group with no additional role check, unlike sibling routes such as VRF key export/import which use `auth.RequiresAdminRole`/`auth.RequiresEditRole` (see e.g. [2](#0-1) ). This means any authenticated session — including a view-role user — can call this endpoint.

`nodesController.Index` fetches `types.NodeStatus` records and converts them via `presenters.NewNodeResource`, which copies `node.Config` (the raw TOML config, including URL fields) verbatim into the response body: [3](#0-2)  and [4](#0-3) . There is no filtering, masking, or redaction of the `URL`/`HTTPURL`/`WSURL` values before this TOML string is placed in the `config` JSON attribute. Node configuration test fixtures confirm the `Config` field literally contains the node's URL string, e.g. `assert.Equal(t, "Name = 'first'\nURL = 'https://solana1.example'\n...", n1.Config)` in [5](#0-4) , and the JSON-API marshaling test shows `config` is exposed as a plain string field in the response body: [6](#0-5) .

If an operator configures an EVM/Solana/etc. RPC endpoint URL containing an embedded API key (e.g., `https://mainnet.infura.io/v3/<API_KEY>` or an Alchemy URL with a query-string key), that full URL — including the key — is returned as part of `config` to any authenticated caller regardless of role, since only base `Authenticate` (not a role check) gates this route.

### Impact Explanation
This is a credential/secret disclosure to a lower-privileged authenticated principal (view role) that should not have access to sensitive RPC provider credentials. Exposure of Infura/Alchemy (or similar) API keys embedded in RPC URLs could allow the view-role user to exfiltrate and reuse the operator's third-party RPC provider credentials outside the node (e.g., to consume the operator's RPC quota, incur costs, or probe the provider account), which falls under Chainlink's "sensitive information disclosure" / "secret confinement" bounty impact class.

### Likelihood Explanation
Preconditions are minimal: any authenticated node API user, including one with only the view role, can trigger this by issuing `GET /v2/nodes` (or `/v2/nodes/:network`, or `/v2/chains/:network/:ID/nodes`). No special role escalation or additional bypass is needed — the vulnerability stems from the route lacking any role gate beyond generic authentication, combined with the presenter's lack of redaction. This is trivially and repeatably exploitable by any view-role credential holder.

### Recommendation
- Add role gating to the nodes/chains listing routes consistent with other sensitive-data endpoints (e.g., `auth.RequiresEditRole` or a new `RequiresAdminRole` wrapper) if node configuration/URLs are considered sensitive.
- Independently, redact credentials embedded in node URLs before including them in `presenters.NodeResource.Config` / `presenters.ChainResource.Config` — e.g., strip userinfo, sensitive query parameters, or known API-key path segments before TOML-serializing node configs for API responses.

### Proof of Concept
1. In a handler/integration test (modeled on `Test_SolanaChainsController_Index` / `TestShell_IndexEVMNodes`), configure a node with `URL = "https://mainnet.infura.io/v3/SECRETAPIKEY123"`.
2. Start a test application with a session/token belonging to a user with only the view role (not edit/admin).
3. Issue `client.Get("/v2/nodes")` using that view-role session.
4. Assert `resp.StatusCode == http.StatusOK` (i.e., the request is not rejected due to insufficient role).
5. Parse the JSON:API body into `[]presenters.NodeResource` and assert `strings.Contains(nodes[0].Config, "SECRETAPIKEY123")` is `true`, proving the raw API key is returned unredacted to a view-role caller.
6. Expected (fixed) behavior: either the request should be rejected with `403 Forbidden` for view-role callers, or `nodes[0].Config` should have the API key/query-string redacted (e.g., `strings.Contains(..., "SECRETAPIKEY123")` should be `false`).

```go
func (n *nodesController[R]) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")
	network := c.Param("network")

	var nodes []types.NodeStatus
	var count int
	var err error

	relayers := n.relayers
	if network != "" {
		relayers = relayers.List(chainlink.FilterRelayersByType(network))
	}

	ctx := c.Request.Context()
	if id == "" {
		// fetch all nodes
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size)
	} else {
		// fetch nodes for chain ID
		// backward compatibility
		var rid types.RelayID
		err = rid.UnmarshalString(id)
		if err != nil {
			rid.ChainID = id
			rid.Network = network
		}
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size, rid)
	}

	resources := make([]R, 0, len(nodes))
	for _, node := range nodes {
		res := n.newResource(node)
		resources = append(resources, res)
	}

	paginatedResponse(c, "node", size, page, resources, count, err)
```

```go
type NodeResource struct {
	JAID
	ChainID string `json:"chainID"`
	Name    string `json:"name"`
	Config  string `json:"config"` // TOML
	State   string `json:"state"`
}

// NewNodeResource returns a new NodeResource for node.
func NewNodeResource(node types.NodeStatus) NodeResource {
	return NodeResource{
		JAID:    NewPrefixedJAID(node.Name, node.ChainID),
		ChainID: node.ChainID,
		Name:    node.Name,
		State:   node.State,
		Config:  node.Config,
	}
}
```
