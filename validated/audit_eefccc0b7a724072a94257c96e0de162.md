### Title
`getTokenAccountBalance`/`getTokenSupply` silently return a misleading `UiTokenAmount` when the interest-bearing/scaled-UI amount conversion fails - (File: `account-decoder/src/parse_token.rs`)

### Summary
The Reserve Protocol finding describes a `price()` function that, instead of reverting on failure to fetch a value, returns a sentinel/degenerate value (`(0, FIX_MAX)`) that the caller (`collateralShortfall()`) does not validate before using it in a downstream financial calculation, corrupting the result. The Agave analog is `token_amount_to_ui_amount_v3()` in `account-decoder/src/parse_token.rs`, which is used directly by the unprivileged JSON-RPC handlers `get_token_account_balance` and `get_token_supply` in `rpc/src/rpc.rs`. When the SPL Token-2022 interest-bearing or scaled-UI-amount conversion fails (returns `None`), the code does not propagate an error to the RPC caller; it silently substitutes a degenerate value and returns success.

### Finding Description
`token_amount_to_ui_amount_v3()` computes `ui_amount`/`ui_amount_string` for interest-bearing or scaled-UI mints by calling `interest_bearing_config.amount_to_ui_amount(...)` or `scaled_ui_amount_config.amount_to_ui_amount(...)`, both of which return `Option<String>`: [1](#0-0) 

If either call returns `None` (the conversion failed, e.g., due to internal overflow/invalid state), the code does not surface an error. Instead it silently converts the failure into `ui_amount: None` and `ui_amount_string: "".to_string()` — a value set that is indistinguishable from other valid-but-non-representable states, and is returned to the caller as if the RPC call succeeded: [2](#0-1) 

This is invoked, without any additional validation of the returned `UiTokenAmount`, directly inside the unprivileged JSON-RPC handlers `get_token_account_balance` and `get_token_supply`: [3](#0-2) 

These RPC methods are reachable by any unprivileged client via a single request (`getTokenAccountBalance` / `getTokenSupply`) and are wired up in `rpc_accounts::AccountsData`: [4](#0-3) 

Just as `collateralShortfall()` in the Reserve Protocol trusted a price value without checking whether it represented a real fetch failure, these RPC handlers trust the `UiTokenAmount` produced by `token_amount_to_ui_amount_v3()` without checking whether the amount conversion actually succeeded, silently returning `success` with a misleading empty/`None` amount instead of an error.

### Impact Explanation
This is a decoder misreporting issue: a client querying `getTokenAccountBalance` or `getTokenSupply` for an SPL Token-2022 mint with an interest-bearing or scaled-UI-amount extension can receive a response with `ui_amount: null` and `ui_amount_string: ""` while the RPC call itself reports success (no JSON-RPC error), rather than an explicit error indicating the conversion could not be completed. Downstream consumers (wallets, exchanges, explorers) that rely on this RPC for balance/supply display could display incorrect (empty/zero) values as if they were authoritative, without any signal that the value is unreliable — mirroring the "wrong data returned" impact class for a single unprivileged query.

### Likelihood Explanation
Reaching this path requires only a single unprivileged `getTokenAccountBalance` or `getTokenSupply` RPC call against a Token-2022 mint/account configured with an `InterestBearingConfig` or `ScaledUiAmountConfig` extension, whose conversion computation fails and returns `None`. No special privileges, multiple calls, or client-specific conditions are needed to trigger the code path shown above.

### Recommendation
`token_amount_to_ui_amount_v3()` (or its callers in `rpc/src/rpc.rs`) should distinguish between "no `ui_amount_string`" and "conversion failed," and the RPC handlers `get_token_account_balance`/`get_token_supply` should return an explicit `Error` (as they already do for other invalid-parameter cases) instead of silently returning a `UiTokenAmount` with an empty string / `None` when the underlying extension's `amount_to_ui_amount` call fails.

### Proof of Concept
1. Create a mint with the SPL Token-2022 `InterestBearingConfig` (or `ScaledUiAmountConfig`) extension configured such that `amount_to_ui_amount()` returns `None` for the given `unix_timestamp`/rate combination.
2. Call the JSON-RPC method `getTokenSupply` (or `getTokenAccountBalance`) for that mint/account.
3. Observe that `rpc.rs::get_token_supply` / `get_token_account_balance` returns a successful `RpcResponse<UiTokenAmount>` with `ui_amount: null` and `ui_amount_string: ""` rather than a JSON-RPC error, exactly analogous to the referenced finding where an unchecked degenerate return value feeds directly into a caller that trusts it.

pub fn token_amount_to_ui_amount_v3(
    amount: u64,
    additional_data: &SplTokenAdditionalDataV2,
) -> UiTokenAmount {
    let decimals = additional_data.decimals;
    let (ui_amount, ui_amount_string) = if let Some((interest_bearing_config, unix_timestamp)) =
        additional_data.interest_bearing_config
    {
        let ui_amount_string =
            interest_bearing_config.amount_to_ui_amount(amount, decimals, unix_timestamp);
        (
            ui_amount_string
                .as_ref()
                .and_then(|x| f64::from_str(x).ok()),
            ui_amount_string.unwrap_or("".to_string()),
        )
    } else if let Some((scaled_ui_amount_config, unix_timestamp)) =
        additional_data.scaled_ui_amount_config
    {
        let ui_amount_string =
            scaled_ui_amount_config.amount_to_ui_amount(amount, decimals, unix_timestamp);
        (
            ui_amount_string
                .as_ref()
                .and_then(|x| f64::from_str(x).ok()),
            ui_amount_string.unwrap_or("".to_string()),
        )
    } else {
        let ui_amount = 10_usize
            .checked_pow(decimals as u32)
            .map(|dividend| amount as f64 / dividend as f64);
        (ui_amount, real_number_string_trimmed(amount, decimals))
    };

    pub fn get_token_account_balance(
        &self,
        pubkey: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let account = bank.get_account(pubkey).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;

        if !is_known_spl_token_id(account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token account".to_string(),
            ));
        }
        let token_account = StateWithExtensions::<TokenAccount>::unpack(account.data())
            .map_err(|_| Error::invalid_params("Invalid param: not a Token account".to_string()))?;
        let mint = &Pubkey::from_str(&token_account.base.mint.to_string())
            .expect("Token account mint should be convertible to Pubkey");
        let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
        let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
        Ok(new_response(&bank, balance))
    }

    pub fn get_token_supply(
        &self,
        mint: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;
        if !is_known_spl_token_id(mint_account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token mint".to_string(),
            ));
        }
        let mint = StateWithExtensions::<Mint>::unpack(mint_account.data()).map_err(|_| {
            Error::invalid_params("Invalid param: mint could not be unpacked".to_string())
        })?;

        let interest_bearing_config = mint
            .get_extension::<InterestBearingConfig>()
            .map(|x| (*x, bank.clock().unix_timestamp))
            .ok();

        let scaled_ui_amount_config = mint
            .get_extension::<ScaledUiAmountConfig>()
            .map(|x| (*x, bank.clock().unix_timestamp))
            .ok();

        let supply = token_amount_to_ui_amount_v3(
            mint.base.supply,
            &SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            },
        );
        Ok(new_response(&bank, supply))
    }
