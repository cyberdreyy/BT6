## Title
Fee-like value is permanently burned when `createDstEscrow` accepts unvalidated zero fee recipients paired with native-token funding - (File: `contracts/BaseEscrowFactory.sol`, `contracts/EscrowDst.sol`)

### Summary
`BaseEscrowFactory::createDstEscrow` accepts the entire `Immutables` struct — including the ABI-encoded `protocolFeeRecipient` / `integratorFeeRecipient` fields inside `parameters` — directly from the caller with no validation. `EscrowDst::_withdraw` later blindly transfers `protocolFeeAmount`/`integratorFeeAmount` to those recipients via `_uniTransfer` without checking they are non-zero. When the destination token is native ETH (`token == address(0)`), sending value to `address(0)` succeeds silently, so any unprivileged caller of `createDstEscrow` can permanently burn the protocol/integrator fee portion of a swap instead of it reaching its intended recipient — the same root cause as the referenced `GaugeProxy::distributeToken` report (fee transferred to an unchecked/zero recipient is burned).

### Finding Description
`createDstEscrow` takes `dstImmutables` (calldata) as-is and only checks the native amount and the cancellation-time bound before deploying the clone and funding it: [1](#0-0) 

Nothing here validates the contents of `dstImmutables.parameters`, which is decoded later by `ImmutablesLib` as `(protocolFeeAmount, integratorFeeAmount, protocolFeeRecipient, integratorFeeRecipient)`: [2](#0-1) 

When the escrow is later withdrawn, `EscrowDst::_withdraw` transfers the fee amounts directly to whatever recipients were embedded, with no zero-address guard: [3](#0-2) 

The transfer path used, `_uniTransfer`, for the native-token branch performs a raw low-level call that succeeds even when `to == address(0)`: [4](#0-3) 

Unlike the ERC20 branch (where `safeTransfer` to `address(0)` reverts on standard-compliant tokens, e.g. OpenZeppelin's `_transfer` check), the native-ETH branch has no equivalent protection — `to.call{value: amount}("")` to `address(0)` simply succeeds and the ETH is unrecoverably burned.

There is no on-chain cross-check tying the `protocolFeeRecipient`/`integratorFeeRecipient` supplied to `createDstEscrow` back to the values computed on the source chain in `BaseEscrowFactory::_postInteraction` (which are only emitted in `SrcEscrowCreated` for off-chain reference, not enforced): [5](#0-4) 

Any unprivileged taker/resolver calling `createDstEscrow` (a public, permissionless function reachable in the live destination-escrow creation flow) can therefore encode `protocolFeeRecipient = address(0)` and/or `integratorFeeRecipient = address(0)` while the destination token is native ETH. The maker still receives the same net amount (`amount - integratorFeeAmount - protocolFeeAmount`), so the maker/taker swap itself is unaffected, but the fee amount owed to the protocol/integrator is silently and permanently burned upon `withdraw`/`publicWithdraw` instead of collected.

### Impact Explanation
This matches the "High: theft or permanent loss of unclaimed fee-like value" bounty category — the protocol/integrator fee, which is unclaimed value at the time of `createDstEscrow`, is irrecoverably burned rather than paid out, with no way for anyone to reclaim it afterward (the escrow's balance accounting already subtracted the fee amount from the maker's payout, so the ETH truly disappears to `address(0)`).

### Likelihood Explanation
Low-to-medium: it requires the destination token to be native ETH and requires the escrow-creating party (the resolver/taker, an unprivileged and permissionless caller of `createDstEscrow`) to supply zeroed fee-recipient bytes in `parameters`. No signature or permission is required to trigger it, and normal integrations wouldn't naturally hit this unless the recipient fields are mishandled or maliciously set, similar to the low-likelihood/high-impact framing of the original report.

### Recommendation
Add explicit checks in `EscrowDst::_withdraw` (and the symmetric `EscrowSrc` fee-paying path, if present) that revert if `integratorFeeAmount > 0 && integratorFeeRecipient == address(0)` or `protocolFeeAmount > 0 && protocolFeeRecipient == address(0)`, mirroring the recommendation in the referenced report. Additionally, consider validating `dstImmutables.parameters` in `createDstEscrow` (e.g., disallow zero fee recipients when the corresponding fee amount is non-zero) so misconfigured escrows cannot even be deployed.

### Proof of Concept
1. Resolver/taker calls `EscrowFactory.createDstEscrow{value: dstAmount + safetyDeposit}(dstImmutables, srcCancellationTimestamp)` with `dstImmutables.token = address(0)` (native ETH), `dstImmutables.parameters = abi.encode(protocolFeeAmount, integratorFeeAmount, address(0), address(0))`, and `protocolFeeAmount + integratorFeeAmount > 0`.
2. After the withdrawal timelock elapses, taker calls `EscrowDst.withdraw(secret, immutables)`.
3. In `_withdraw`, `_uniTransfer(address(0), address(0), integratorFeeAmount)` and `_uniTransfer(address(0), address(0), protocolFeeAmount)` both succeed silently (native ETH sent to `address(0)`), burning the fee amounts. The maker still receives `amount - integratorFeeAmount - protocolFeeAmount`; the protocol/integrator receive nothing and the burned ETH is unrecoverable.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }

        if (token == address(0)) {
            _ethTransfer(to, amount);
