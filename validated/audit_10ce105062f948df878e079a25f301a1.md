This external DeFi bug is a **state-reset race**: a check-then-act window lets an actor race a privileged-timing state transition to defeat an intended one-time/invariant guard. The closest verified analog in this Chainlink node repository is a genuine **TOCTOU race in the gateway's JWT replay-protection cache**, reachable from unprivileged, internet-facing HTTP trigger requests.

### Title
JWT replay-protection cache has a check-then-act race allowing a single-use JWT to be replayed - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize` is the entry point that authenticates incoming HTTP-trigger requests to the gateway using a signed JWT, and it enforces single-use of each JWT via a `jwtReplayCache` keyed by the token's `jti` claim. The check (`isReplay`) and the commit (`recordUsage`) are two separate, non-atomic critical sections guarded by independent lock acquisitions, so two requests carrying the same JWT that arrive concurrently can both pass the replay check before either records usage, letting an unprivileged client replay a "used once" authenticated request.

### Finding Description
`Authorize` first calls `h.jwtCache.isReplay(claims.ID)` under an `RLock`, and only after further authorization checks succeed does it call `h.jwtCache.recordUsage(claims.ID)` under a `Lock`, in a separate, later critical section: [1](#0-0) 

The `isReplay`/`recordUsage` primitives themselves are correctly locked internally, but the read-check and the write-commit are not combined into one atomic operation (no compare-and-set): [2](#0-1) 

Because a client fully controls when and how many times it submits an HTTP trigger request carrying the same signed JWT, an attacker can send two (or more) copies of the identical authenticated request in parallel. Both goroutines will call `isReplay(claims.ID)` before either has called `recordUsage(claims.ID)`, since the two operations happen in different, unsynchronized critical sections separated by additional authorized-key lookup logic. Both requests will then be treated as valid, single-use authorization is defeated, and `recordUsage` is called twice harmlessly after the fact — the damage (double execution) is already done.

This is called from the internet-facing HTTP trigger path for every incoming workflow-execute request: [3](#0-2) 

### Impact Explanation
The `jti`-based replay cache exists specifically to prevent a captured/observed signed JWT from being reused (e.g., to prevent duplicate/unauthorized re-execution of a workflow trigger, similar in purpose to a nonce). The race allows an external, unprivileged client (or anyone who obtains a copy of a previously-sent authenticated request, e.g., via network observation, retry, or an intermediary) to defeat this single-use guarantee and cause the gateway to authorize and forward duplicate node-side executions for the same request — a concrete request-impersonation/replay bypass of an authentication control on the internet-facing gateway.

### Likelihood Explanation
Exploitation only requires the ability to send the same signed request payload twice within a short window (e.g., via HTTP client concurrency or simple retry-race tooling) — no privileged access, cryptographic break, or timing side channel is required beyond ordinary concurrent request submission. Since `checkRateLimit`/`authorizeRequest` run per-request without any additional synchronization tying the read-check to the write-commit, the race window is bounded only by normal request-processing latency, which is realistically achievable over a network.

### Recommendation
Make the replay check-and-record atomic: combine `isReplay` and `recordUsage` into a single method that acquires the write lock once, checks for existing `jti`, and inserts it in the same critical section (a "check-and-set"), returning whether the insert succeeded, e.g.:
```go
func (cache *jwtReplayCache) checkAndRecord(jti string) bool {
    cache.mu.Lock()
    defer cache.mu.Unlock()
    if _, exists := cache.cache[jti]; exists {
        return false // already used
    }
    cache.cache[jti] = time.Now()
    return true
}
```
and call this single atomic operation immediately upon parsing `claims.ID` in `Authorize`, before performing the remaining authorized-key lookups.

### Proof of Concept
1. Obtain (or replay) a validly signed HTTP-trigger JWT-authenticated request for a registered workflow.
2. Fire two identical copies of the request at the gateway concurrently (e.g., via two goroutines/HTTP clients hitting the same gateway endpoint at the same instant).
3. Both requests reach `WorkflowMetadataHandler.Authorize` and call `h.jwtCache.isReplay(claims.ID)` before either has called `h.jwtCache.recordUsage(claims.ID)`, so both pass the replay check.
4. Both requests proceed through `authorizeRequest`/rate-limit checks and are forwarded to the workflow DON as two independent authorized executions of what was intended to be a single-use signed request.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
