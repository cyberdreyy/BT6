### Title
Multisig Executes Requests Using Stale Confirmations From Removed Members, Bypassing the Confirmation Threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges pending requests that were *filed* by the member being deleted; it does not scrub that member's existing confirmations from other members' pending requests. Because `confirm()` authorizes execution purely by counting the size of the stored confirmation set against `num_confirmations`, a confirmation recorded by a member who has since been removed still counts toward the threshold. This lets a request execute with fewer *live* member approvals than `num_confirmations` requires.

### Finding Description
The multisig invariant is: a request can only execute once `num_confirmations` distinct **current** members have approved it. The contract instead checks `confirmations.len() + 1 >= self.num_confirmations` where `confirmations` is a persisted `HashSet<String>` of member identifiers collected over time [1](#0-0) .

When a member is removed via `DeleteMember`, `delete_member` only removes requests where the request's original signer (`r.member == member`) matches the deleted member, and clears that member's `num_requests_pk` bookkeeping — it never walks other pending requests to strip confirmations previously cast by the now-removed member: [2](#0-1) 

Consequently, if member `D` confirms request `R` (filed by someone else) and is later removed from `members` by a separate `DeleteMember` request, `R`'s confirmation set still contains `D`'s stale approval. Any subsequent `confirm()` calls by the remaining live members only need to add enough confirmations to reach `num_confirmations` in total — including the stale one — so a request that should require `K` live approvals is authorized with only `K-1` live approvals plus one dead one.

The binding that should hold is:
```
confirmations_from_current_members(R) >= num_confirmations
```
but the code actually enforces:
```
confirmations_ever_recorded(R) >= num_confirmations
```
which is not equivalent once membership changes between the time confirmations are cast and the time the threshold is reached.

### Impact Explanation
This falls under the Critical impact category: "a multisig request executed below threshold." A `Transfer`, `AddKey`/`FunctionCall`, or `AddMember` action (e.g., moving NEAR out of the multisig account or installing an attacker-controlled key) can be authorized with fewer live signers than the configured K-of-N policy guarantees, undermining the core security assumption of the multisig and allowing funds to move without the intended level of authorization.

### Likelihood Explanation
This does not require any redeploy, foundation action, or external exploit tooling — it only requires the normal governance sequence that any multisig naturally goes through: a member confirms a pending request, and later that member is removed (a routine key-rotation/membership-change operation supported by the contract itself, `DeleteMember`). No code outside `multisig2/src/lib.rs` needs to be trusted incorrectly; the flaw is intrinsic to `delete_member`'s incomplete cleanup, making it reliably reproducible whenever member turnover occurs while requests are outstanding.

### Recommendation
When deleting a member, iterate all pending requests and remove that member's entry from each request's confirmation set (not just requests they authored), or alternatively validate at `confirm()` time that every identifier in the stored confirmation set still corresponds to a current member (filtering out stale entries) before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. `D` calls `add_request_and_confirm(R)` for a `Transfer` request — `R`'s confirmation set = `{D}`.
3. Members execute a separate, properly-authorized `DeleteMember { member: D }` request (3 confirmations from A/B/C) — `delete_member` removes `D` from `members`, but `R` was not filed by `D`, so its confirmation set is left untouched: `{D}` [3](#0-2) .
4. `A` calls `confirm(R)` → `confirmations.len()==1 (D)+1==2 < 3` → inserted, set becomes `{D, A}`.
5. `B` calls `confirm(R)` → `confirmations.len()==2+1==3 >= 3` → `remove_request` + `execute_request(R)` fires the transfer [4](#0-3) .
6. Result: `R` executed with only 2 live-member confirmations (`A`, `B`) plus one stale confirmation from removed member `D`, violating the configured 3-of-N threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
