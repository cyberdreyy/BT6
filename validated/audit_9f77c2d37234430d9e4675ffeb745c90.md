### Title
`FactoryV1::init_stablecoin`/`init_asset_token` silently skip `DEFAULT_ADMIN_ROLE` grant when `initialAdmin` is `address(0)`, permanently bricking role-gated B‑20 token administration - ([File: crates/common/precompiles/src/b20_factory/logic/v1.rs])

### Summary
The `Voting.sol` report flags that `initialize()` never validates a caller-supplied address, so a zero value silently bricks the contract and forces a redeploy. The Base B‑20 factory precompile has the same bug class: `createB20` accepts an unvalidated `initialAdmin` address from the token creator, and if it is `address(0)` the factory simply skips granting `DEFAULT_ADMIN_ROLE`, leaving the freshly created token with no administrator at all.

### Finding Description
`TokenCreateParams::decode` copies `initialAdmin` straight from caller-supplied ABI parameters into `CommonParams` with no validation: [1](#0-0) 

`FactoryV1::init_stablecoin` (and the analogous `init_asset_token`) then conditionally grants `DefaultAdmin` only `if !common.initial_admin.is_zero()`: [2](#0-1) 

`TokenCreateParams::validate()` / `validate_stablecoin` / `validate_asset` do not check `initial_admin` at all — only `currency` and `decimals` are validated: [3](#0-2) 

Because the role grant is unconditionally skipped rather than rejected, a token created with `initialAdmin = address(0)` deploys successfully with `isB20Initialized == true`, but no account holds `DEFAULT_ADMIN_ROLE`. Since role-admin bootstrap for a B‑20 token only happens in this one factory code path, there is no way to later grant any role (pause, mint-cap changes, seize/freeze policy updates, upgrades) — precisely the "must be reinstalled" failure mode from the original report, except here it's the token contract instance rather than the whole system.

### Impact Explanation
Any token whose creator passes `address(0)` as `initialAdmin` (mistake, bug in an integrating wallet/SDK, or copy-paste from a template) becomes permanently ungovernable: no one can pause it in an emergency, update its supply cap, or manage compliance/seize policies. For a "Stablecoin" or "Asset" variant B‑20 token this is a fund/functionality freezing condition for the entire token deployment (all future holders), not just the creator, since normal ERC‑20 transfer/balance functionality continues but all admin-gated safety and compliance controls are permanently disabled. This matches the report's core concern — an initializer that consumes a zero address with no revert, and the resulting permanent bricking.

### Likelihood Explanation
This is trivially reachable by any unprivileged account: `createB20` is a public precompile dispatch entry point requiring only calldata construction with `initialAdmin = address(0)`, which is one field in an ABI-encoded struct. No governance, special role, or race condition is needed; it happens deterministically for every affected creation call.

### Recommendation
Add an explicit zero-address check for `initialAdmin` in `TokenCreateParams::validate_stablecoin`/`validate_asset` (or in `FactoryV1::create_b20` before dispatching to `init_stablecoin`/`init_asset_token`), reverting with a dedicated error (e.g. `ZeroInitialAdmin`) instead of silently skipping the `grant_role_unchecked` call at [2](#0-1) .

### Proof of Concept
1. Caller (any unprivileged account) calls `createB20` on the B‑20 factory precompile with `variant = STABLECOIN` (or `ASSET`), a fresh `salt`, and ABI-encoded `B20StablecoinCreateParams { version, name, symbol, initialAdmin: address(0), currency }`, and empty `initCalls`.
2. `TokenCreateParams::decode` accepts the zero `initialAdmin` unchanged; `validate()` performs no check on it.
3. `init_stablecoin` initializes token storage successfully, emits `B20Created`, and skips the `grant_role_unchecked(DefaultAdmin, ...)` branch because `common.initial_admin.is_zero()`.
4. `createB20` returns success; `isB20Initialized(token) == true`.
5. Any subsequent call requiring `DEFAULT_ADMIN_ROLE` (pause, `updateSupplyCap`, policy updates, role management) on the new token reverts for every address, including the original creator — the token's administrative surface is permanently unusable.

impl TokenCreateParams {
    /// Decodes ABI-encoded creation parameters for `variant`.
    pub fn decode(variant: B20Variant, params: &Bytes) -> Result<Self> {
        match variant {
            B20Variant::Stablecoin => {
                let p = IB20Factory::B20StablecoinCreateParams::abi_decode_validate(params)
                    .map_err(Self::invalid_params)?;
                Ok(Self::Stablecoin {
                    common: CommonParams { version: p.version, initial_admin: p.initialAdmin },
                    init: B20StablecoinInit {
                        name: p.name,
                        symbol: p.symbol,
                        supply_cap: B20FactoryStorage::DEFAULT_SUPPLY_CAP,
                        currency: p.currency,
                    },
                })
            }
            B20Variant::Asset => {
                let p = IB20Factory::B20AssetCreateParams::abi_decode_validate(params)
                    .map_err(Self::invalid_params)?;
                Ok(Self::Asset {
                    common: CommonParams { version: p.version, initial_admin: p.initialAdmin },
                    init: B20AssetInit {
                        name: p.name,
                        symbol: p.symbol,
                        supply_cap: B20FactoryStorage::DEFAULT_SUPPLY_CAP,
                        multiplier: INITIAL_MULTIPLIER,
                        decimals: p.decimals,
                    },
                })
            }
        }
    }

    /// Validates variant-specific invariants after the shared version check.
    ///
    /// Each arm owns its own rules. Version is checked first by the caller (`check_version`)
    /// so that version errors always take precedence over field-level errors.
    pub fn validate(&self) -> Result<()> {
        match self {
            Self::Stablecoin { init, .. } => Self::validate_stablecoin(init),
            Self::Asset { init, .. } => Self::validate_asset(init),
        }
    }

    /// Validates stablecoin initialization fields.
    pub const fn validate_stablecoin(_init: &B20StablecoinInit) -> Result<()> {
        // Currency validation is delegated to `B20StablecoinStorage::initialize`, which rejects
        // empty values with `MissingRequiredField` and non-A-Z values with `InvalidCurrency`.
        Ok(())
    }

    /// Validates asset-token initialization fields.
    pub fn validate_asset(init: &B20AssetInit) -> Result<()> {
        if init.decimals < B20AssetStorage::MIN_DECIMALS
            || init.decimals > B20AssetStorage::MAX_DECIMALS
        {
            return Err(BasePrecompileError::revert(IB20Factory::InvalidDecimals {
                decimals: init.decimals,
            }));
        }
        Ok(())
    }
