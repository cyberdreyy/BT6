### Title
Integer underflow in `stopEpoch` `AccrueInterest` emission triggers a false borrower default and permanently freezes/socializes all lender funds - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
The U-Boot CVE is an integer underflow during packet-length computation that corrupts downstream processing. The analog here is an unsigned underflow in `_stopEpoch`: the `emit AccrueInterest(_expectedInterest - _totBorrowed, _totalFees)` statement subtracts prefunded external principal from epoch interest inside the `try` block. When `_totBorrowed > _expectedInterest` — the normal state for a prefunded deployment where principal was already pushed to the borrower — the subtraction reverts, is swallowed by the `catch`, and incorrectly invokes `_handleBorrowerDefault`, setting the terminal `defaulted` flag on a solvent pool.

### Finding Description
In `_stopEpoch` (contracts/IdleCDOEpochVariant.sol:330-506):

1. `_totBorrowed = _beforeStopEpoch(_isRequestingAllFunds)` (line 353) returns additional principal "held outside the CDO strategy-token balance". The prefunded variant `IdleCDOEpochVariantPrefunded` overrides this hook to include principal already sent directly to the borrower (queue deposits / `depositDuringEpoch` push underlyings to the borrower without a matching in-contract strategy-token basis).
2. `_expectedInterest` is only increased by `_totBorrowed` in the close-pool branch (`_interest == 1`, lines 367-372). On a normal `stopEpoch`/`stopEpochWithDuration` call, `_expectedInterest` remains just the epoch interest (typically a few percent of principal).
3. At line 495, `emit AccrueInterest(_expectedInterest - _totBorrowed, _totalFees)` underflows whenever outstanding external principal exceeds epoch interest — i.e., on essentially every non-closing stop of a prefunded pool. Example: 1,000,000 USDC principal already sent to borrower, 8,000 USDC epoch interest → `8,000 - 1,000,000` reverts.
4. Because the emit sits inside the `try` scope whose `catch` (line 501) calls `_handleBorrowerDefault(_amountToPullFromBorrower + _pendingWithdraws)`, the underflow is misclassified as a repayment failure: `defaulted = true`, the contract pauses, `allowAAWithdrawRequest`/`allowBBWithdrawRequest` are set to false, and `isEpochRunning` is cleared — even though the borrower repaid in full and `collectWithdrawFunds` already succeeded at line 410.

Broken invariant: solvency/fair accounting — a healthy epoch settlement is converted into a hard default. `defaulted` has no reset path; the only exit is `finalizeDefault`, which applies a recovery haircut (`defaultRecoveryPrice = reserveAmount / totalBasis`) to both active LPs and pending receipts, socializing a fictitious loss onto all lenders.

### Impact Explanation
- All lender principal becomes claimable only through the default-recovery path, at a haircut price determined by whatever reserve `finalizeDefaultRecovery` can assemble — guaranteed loss on fully-backed funds.
- Pending withdraw receipts (`pendingWithdraws`) stop being funded at par and are instead haircut via `_claimDefaultedWithdrawRequest` / `lossRecoveryPriceByEpoch` logic.
- If no recovery source is provided, the default-finalized state permanently freezes user funds (recovery price 0 or recovery never finalized — either way unclaimed funds are locked).
- An unprivileged attacker can amplify or guarantee the condition: a KYC-passing lender using `depositDuringEpoch` (when `isDepositDuringEpochDisabled == false`) calls `mintStrategyTokens` + `_transferUnderlyings(_borrower())` (lines 730-732), pushing additional principal outside the CDO and enlarging `_totBorrowed` far above `_expectedInterest` before the honest manager's stop call.

### Likelihood Explanation
The trigger requires no malicious action: an honest manager calls `stopEpoch(_newApr, 0)` (or `stopEpochWithDuration` with `_interest` 0 or >1) after `epochEndDate`, exactly as designed. On any prefunded deployment where `_beforeStopEpoch` reports borrower-held principal on non-closing stops — which is the hook's documented purpose ("include principal already sent to the borrower") — `_expectedInterest < _totBorrowed` holds in every epoch where interest < principal, i.e., always. Existing guards do not stop it: `_checkNotAllowed` at lines 338-351 checks flags and interest-vs-fees, not the emit arithmetic, and the `try/catch` converts the panic into a state-changing false default rather than a clean revert. Caveat: the exact non-closing return value of `IdleCDOEpochVariantPrefunded._beforeStopEpoch` was not fully verified in this pass; if it returns 0 when `!_isClosing`, the underflow does not fire on normal stops — that specific branch should be confirmed.

### Recommendation
- Compute the emit operand defensively: `emit AccrueInterest(_expectedInterest > _totBorrowed ? _expectedInterest - _totBorrowed : 0, _totalFees)` or move the event emission out of the `try` block.
- More fundamentally, separate "borrower transfer failed" from arithmetic/panic failures: only the `getFundsFromBorrower` external call should be wrapped in `try/catch`; all accounting after it should run outside the catchable scope so an internal revert cannot be reinterpreted as a borrower default.
- Add a regression test stopping an epoch on a prefunded variant with outstanding borrower principal and `_interest = 0`, asserting `defaulted == false`.

### Proof of Concept
Foundry fork sketch (prefunded variant deployment assumed in test harness, as in `test/foundry/IdleCDOEpochVariantPrefunded*.sol` style setups):

```solidity
function testStopEpochUnderflowFalseDefault() external {
    // Setup: prefunded CDO, KYC'd lender, epoch duration 30d, apr 10%
    // 1. Attacker (or any lender) deposits during buffer; prefunded path sends
    //    principal straight to borrower -> _beforeStopEpoch will return it.
    deal(address(underlying), attacker, 1_000_000e6);
    vm.prank(attacker);
    cdoEpoch.depositAA(1_000_000e6);          // funds routed to borrower prefund

    vm.prank(manager);
    cdoEpoch.startEpoch();

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Borrower fully approves + repays interest owed (honest repayment)
    uint256 repay = cdoEpoch.expectedEpochInterest(); // ~8k, << 1_000_000e6 principal
    deal(address(underlying), borrower, repay, true);
    vm.prank(borrower);
    underlying.approve(address(cdoEpoch), repay);

    // Honest manager stop -> emit AccrueInterest(expectedInterest - totBorrowed)
    // underflows (8k - 1_000_000e6) -> catch -> _handleBorrowerDefault
    vm.prank(manager);
    cdoEpoch.stopEpoch(10e18, 0);

    assertTrue(cdoEpoch.defaulted());          // false default despite full repayment
    assertTrue(cdoEpoch.paused());
    assertFalse(cdoEpoch.allowAAWithdrawRequest());

    // Lender funds now only recoverable via finalizeDefault with a haircut,
    // or frozen if never finalized.
}
```

If `IdleCDOEpochVariantPrefunded._beforeStopEpoch` returns 0 on non-closing stops, the same underflow is still reachable whenever `additionalPrincipal > expectedInterest` on any variant overriding the hook; confirm that return path before finalizing the PoC.
