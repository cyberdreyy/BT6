### Title
Shared, unauthenticated-keyed metering cache lets any bundle sender poison another sender's transaction-inclusion decision - (File: `crates/builder/metering/src/ext.rs`)

### Summary
The Base builder exposes `base_setMeteringInformation(tx_hash, meter)` via `MeteringStoreExt`, which writes directly into `MeteringStore`, a single cache shared across **all** transactions the builder processes for resource-unit throttling [1](#0-0) . The cache is keyed only by `TxHash` — a value that is public (visible in the mempool/gossip) and never bound to the caller's identity or to any proof that the caller actually simulated that transaction [2](#0-1) . This is structurally the same bug class as the n8n advisory: a single shared cache, keyed by an attacker-influenceable/guessable key, that is consumed by the execution/inclusion pipeline for *other* users' work.

### Finding Description
`MeteringStore::insert` unconditionally overwrites whatever `MeterBundleResponse` is currently cached for a `tx_hash` with the value supplied over RPC [3](#0-2) . The payload builder later reads this same shared entry via `ResourceMeteringConfig::simulated_sample`/`check_simulated_usage` to decide whether to throttle or permanently reject the transaction identified by that hash [4](#0-3) . Nothing ties the submitted `meter` payload to the actual signer/sender of the transaction being metered — the RPC accepts any `(TxHash, MeterBundleResponse)` pair from any caller who can reach the `base` RPC namespace on the builder (the ingress-rpc `BuilderConnector` is one legitimate caller, but the JSON-RPC method itself carries no authorization or provenance check in `MeteringStoreExt` [5](#0-4) ).

Because any pending transaction's hash is public before it is included in a block, an attacker who observes a victim's pending transaction hash in the mempool can call `base_setMeteringInformation` with a forged `MeterBundleResponse` for that hash. The forged sample is consumed the next time the builder scans the pool: `check_simulated_usage` treats it as the victim's real resource usage and decides whether to admit or exclude the transaction [6](#0-5) . If the forged sample reports usage that exceeds a transaction-scope budget, the decision is `is_permanent() == true`, and the victim's transaction is pushed into `permanently_rejected_txs`, fed into the shared `RejectionCache`, and evicted from the pool entirely — even on a later, unrelated payload job, since the rejection cache is consulted across jobs and blocks [7](#0-6) [8](#0-7) . Conversely, a forged sample reporting artificially low usage lets an attacker's own (or any) transaction bypass real resource-metering throttles.

This mirrors the n8n bug class precisely: a cache shared across unrelated principals' work units, keyed by something derivable/observable rather than principal-bound, where one principal's write silently corrupts another principal's execution outcome.

### Impact Explanation
- **Availability / griefing (permanent freezing of a user's transaction from inclusion):** an attacker can cause an arbitrary victim's pending transaction to be permanently evicted from the mempool and the cross-job rejection cache by forging metering data claiming it exceeds a transaction-scope resource-unit budget, effectively censoring specific senders' transactions from ever being included while metering is enabled.
- **Unauthorized resource-throttle bypass:** conversely, forged low-usage samples let a caller's own transactions dodge real metering budgets, unfairly consuming block resource-unit budget meant to protect the chain/builder from overload.
- This reaches the builder's `execute_best_transactions` path (transaction/block building and resource metering — explicitly in scope), and the outcome (a legitimate transaction is permanently excluded from every future block build, or a resource budget is silently violated) is a concrete, non-DoS-only correctness/censorship impact on a specific unprivileged sender's transaction.

### Likelihood Explanation
Likelihood is Medium: the attack requires reaching the builder's `base_setMeteringInformation` RPC method. In the deployed topology this is meant to be called only by the ingress-rpc `BuilderConnector` component forwarding meterBundle results, but the code shown does not enforce that only the ingress service (or any authenticated/allow-listed caller) can invoke it — `MeteringStoreExtension` registers the method as a normal RPC module with no caller-identity or origin check in `MeteringStoreExt` itself. If the builder's RPC port (or any misconfigured/exposed deployment of it) is reachable by third parties, or if the ingress-rpc trust boundary can be spoofed, any party who can observe a victim's mempool transaction hash (trivial — hashes are public) can exploit this without needing to control any state or execute any code themselves.

### Recommendation
- Bind cached metering entries to the actual simulated transaction rather than trusting an arbitrary caller-supplied `(tx_hash, meter)` pair: verify the metering RPC caller is the trusted ingress/simulation service (mTLS, shared secret, or restrict the RPC to an internal-only listener/IPC), and/or verify `meter.results[].tx_hash == tx_hash` and that the reported gas/opcodes are plausible for the transaction's actual encoded call data before accepting the write.
- Consider namespacing/authenticating `base_setMeteringInformation` separately from public RPC modules, and never exposing it on the same listener as the public `eth_*`/ingress endpoints without additional authorization.
- Add an audit trail correlating accepted metering writes to their originating trusted service instance so a poisoned entry can be attributed and entries from unexpected sources rejected.

### Proof of Concept
Conceptual/reachability PoC (author verification would require live deployment access):
1. Attacker observes victim's pending transaction `tx_v` in the mempool and its `tx_hash = H`.
2. Attacker crafts a `MeterBundleResponse` claiming `tx_gas_used`/opcode usage for `H` that exceeds an enforced transaction-scope resource dimension (e.g., a huge `STATE_NEW_STORAGE_SLOT` count) and calls `base_setMeteringInformation(H, forged_meter)` on the builder's RPC.
3. On the next payload-building pass, `check_simulated_usage(&H, ...)` in `crates/execution/payload/src/config.rs` reads the forged entry, returns a `Throttle` decision with `scope: Transaction`, which `is_permanent()` marks true.
4. The builder pushes `H` into `permanently_rejected_txs`, which is fed into the shared `RejectionCache::mark_rejected`, and the transaction is evicted from the pool — permanently excluded from all future blocks even though the victim's real transaction never actually used those resources. impl MeteringProvider for MeteringStore {
    fn get(&self, tx_hash: &TxHash) -> Option<MeterBundleResponse> {
        if !self.metering_enabled.load(Ordering::Relaxed) {
            return None;
        }

        self.cache.get(tx_hash)
    }

    fn is_enabled(&self) -> bool {
        self.metering_enabled.load(Ordering::Relaxed)
    }

    fn insert(&self, tx_hash: TxHash, metering: MeterBundleResponse) {
        // If the builder needed metering data for this tx but didn't have it,
        // the data arrived late. Record how late and what the values were.
        if let Some(needed_at) = self.needed_at.remove(&tx_hash) {
            let latency_ms = needed_at.elapsed().as_millis() as f64;
            BuilderMetrics::metering_late_arrival_total().increment(1);
            BuilderMetrics::metering_late_arrival_latency_ms().record(latency_ms);
            BuilderMetrics::metering_late_arrival_execution_time_us()
                .record(metering.total_execution_time_us as f64);
            return;
        }

        self.cache.insert(tx_hash, metering);
        BuilderMetrics::metering_store_size().set(self.cache.entry_count() as f64);
    }

    fn mark_included_without_metering(&self, tx_hash: &TxHash) {
        if !self.metering_enabled.load(Ordering::Relaxed) || self.cache.get(tx_hash).is_some() {
            return;
        }

        // Atomically record the first unmetered inclusion. Later flashblock
        // iterations must not overwrite the original timestamp.
        self.needed_at.entry_by_ref(tx_hash).or_insert(Instant::now());
    }

    fn skip(&self, tx_hash: &TxHash) {
        self.needed_at.invalidate(tx_hash);
    }

    fn remove(&self, tx_hashes: &[TxHash]) {
        for hash in tx_hashes {
            self.cache.invalidate(hash);
        }
        BuilderMetrics::metering_store_size().set(self.cache.entry_count() as f64);
    }

    fn clear(&self) {
        self.cache.invalidate_all();
        self.needed_at.invalidate_all();
        BuilderMetrics::metering_store_size().set(0.0);
    }

    fn set_enabled(&self, enabled: bool) {
        self.metering_enabled.store(enabled, Ordering::Relaxed);
    }
}

    /// Looks up the simulated sample for `tx_hash`, if the provider has a matching result.
    pub fn simulated_sample(&self, tx_hash: &TxHash) -> Option<ResourceSample> {
        if !self.is_active() {
            return None;
        }
        MeteringProvider::get(self.provider.as_ref(), tx_hash)
            .and_then(|meter| ResourceSample::from_meter(&meter, tx_hash))
    }

    /// Checks simulated `meterBundle` usage against the schedule.
    ///
    /// Payload builders call this before EVM execution and skip the transaction
    /// when [`ResourceThrottlingDecision::should_exclude`] is true. The returned
    /// sample is passed to [`Self::check_executed_usage`] after execution.
    /// Sequencer transactions use [`Self::unthrottled_usage`] /
    /// [`Self::account_unthrottled`] instead.
    ///
    /// [`ResourceThrottlingDecision::CalculationFailed`] is not recorded here:
    /// the transaction still executes, and [`Self::check_executed_usage`] records
    /// the final outcome, including a later calculation failure.
    /// This method does not add usage to the block totals.
    pub fn check_simulated_usage(
        &self,
        tx_hash: &TxHash,
        cumulative: &[u128],
    ) -> (Option<ResourceSample>, ResourceThrottlingDecision) {
        if !self.is_active() {
            return (None, ResourceThrottlingDecision::Allow(ResourceMeteringUsage::zero(0)));
        }
        let simulated = self.simulated_sample(tx_hash);
        let decision = simulated.as_ref().map_or_else(
            || {
                ResourceThrottlingDecision::Allow(ResourceMeteringUsage::zero(
                    self.schedule.dimensions.len(),
                ))
            },
            |sample| self.schedule.decide_sample(sample, cumulative),
        );
        if decision.should_exclude() {
            self.record_decision(tx_hash, &decision);
        }
        (simulated, decision)
    }

    /// Creates a new [`RejectionCache`] with the given capacity and TTL.

    pub fn is_rejected(&self, hash: &TxHash) -> bool {
        self.contains_key(hash)

        self.0.contains_key(hash)
