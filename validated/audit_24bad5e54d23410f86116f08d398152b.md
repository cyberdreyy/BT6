### Title
Unauthenticated LOOP plugin pprof endpoint exposes plugin process memory dumps - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers `/plugins/:name/debug/pprof/*profile`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/symbol` on the top-level `api` router group without any `auth.Authenticate` middleware, unlike every other sensitive route (`debugRoutes`, `sessionRoutes`, `v2Routes`) which explicitly wrap handlers with `auth.Authenticate(...)`. Any unauthenticated client that can reach the node's HTTP API can call `LoopRegistryServer.pluginPPROFHandler` to pull full pprof heap/goroutine/profile dumps from a registered LOOP plugin process.

### Finding Description
`loopRoutes` is mounted on the `api` group in `NewRouter`: [1](#0-0) 
Compare this to `debugRoutes`, `sessionRoutes`, and the `authv2`/`userOrEI` groups in the same file, all of which wrap their handlers in `auth.Authenticate(...)`: [2](#0-1) [3](#0-2) 

`loopRoutes` itself has no auth wrapper at all: [4](#0-3) 

The `api` group only applies rate limiting and session middleware (which just loads the session cookie store, it doesn't enforce authentication): [5](#0-4) 

`pluginPPROFHandler` looks up the plugin by name in the `plugins.LoopRegistry`, builds a URL to the plugin's internal pprof endpoint, and forwards the request/response directly to the caller with no additional authorization check: [6](#0-5) [7](#0-6) 

Since there is no auth middleware in the call chain and `doRequest` writes the raw plugin response body back with `gc.Data(http.StatusOK, ...)`, any unauthenticated caller who can reach the node's exposed HTTP port can retrieve full heap/goroutine dumps (`?debug=1` or raw pprof binary) from any registered LOOP plugin (e.g., median, mercury, etc.). Heap/goroutine dumps of a running process routinely contain in-memory secrets — including OCR/CSA/EVM private key material, decrypted job configs, and API credentials — held by the plugin process.

### Impact Explanation
This is an authentication-soundness/secret-confinement violation: an unauthenticated network client can extract raw process memory (heap/goroutine profiles) from a chainlink LOOP plugin, which can expose private keys or other sensitive in-memory state. This maps to Chainlink's "key/secret disclosure" bounty impact class, potentially enabling full node/key compromise depending on what's resident in the plugin's memory at capture time.

### Likelihood Explanation
No credentials, roles, or preconditions are required beyond network reachability to the node's HTTP API and at least one LOOP plugin being registered (common for OCR2 median/mercury/functions plugin-based jobs). The request is a single unauthenticated `GET /plugins/<name>/debug/pprof/heap?debug=1`, fully repeatable and trivially scriptable.

### Recommendation
Wrap `loopRoutes` registration with the same authentication middleware used elsewhere (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), and additionally gate it with `auth.RequiresAdminRole` given the sensitivity of pprof/heap data, consistent with how `metricRoutes` is only exposed under `authv2` with admin-gated debug access.

### Proof of Concept
1. Handler-level integration test (in `core/web`):
   - Start a stub HTTP server simulating a LOOP plugin's pprof endpoint (`httptest.NewServer` returning a fixed body for `/debug/pprof/heap`).
   - Register a fake plugin in `plugins.LoopRegistry` with `EnvCfg.PrometheusPort` pointing at the stub server's port, and set `loopHostName` to `127.0.0.1` (or override via `env.LOOPPHostName`).
   - Build the router via `NewRouter` (or directly mount `loopRoutes` on a fresh `gin.Engine`) without any `Authorization`/session cookie set on the test request.
   - Issue `GET /plugins/median/debug/pprof/heap?debug=1` using `httptest.NewRecorder()`.
   - Assert response status is `200 OK` and body equals the stub server's fixed payload, proving the unauthenticated request reached `pluginPPROFHandler` and returned plugin-internal data.
2. Negative control: repeat the same request against `/v2/keys/eth` (an `authv2` route) and confirm it returns `401 Unauthorized` without credentials, demonstrating the asymmetry between properly-authenticated routes and the unauthenticated `loopRoutes`.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
