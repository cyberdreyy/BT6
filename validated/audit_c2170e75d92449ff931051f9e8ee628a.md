### Title
Improper Validation of Signed Timestamp Leads to Staleness-Check Bypass in Gateway Legacy Trigger Handler - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` in the internet-facing Gateway handler accepts a client-supplied `Timestamp` field inside `TriggerRequestPayload`, checks only for the exact value `0`, and then casts the signed timestamp to `uint` to compare it against the current time minus a max-age window. Just like the reported oracle bug (signed price cast to `uint256` without a negative check), a negative `Timestamp` supplied by an unprivileged client underflows when cast to `uint`, producing a very large value that can bypass the intended staleness validation.

### Finding Description
The handler decodes the payload and validates it as follows: [1](#0-0) 

The code checks `payload.Timestamp == 0` to catch missing timestamps, but does not check for negative values. It then computes:
```go
if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
    // stale message
}
```
`uint(payload.Timestamp)` is only meaningful as a defensive cast if `Timestamp` is a signed integer type; the existing `== 0` guard confirms the author anticipated invalid values but only handled the zero case, mirroring exactly the pattern in the external report where a signed price is cast to `uint256` with only a subset of invalid values guarded against. If an unprivileged client (any caller able to reach the Gateway's legacy HTTP trigger endpoint, which routes into `HandleLegacyUserMessage`) submits a payload with a negative `Timestamp` (e.g., `-1`), the cast underflows to a huge `uint` value. Since the left-hand side (`uint(time.Now().Unix()) - MaxAllowedMessageAgeSec`) is a bounded, "normal-sized" unsigned value, the comparison `lhs > huge_rhs` evaluates to `false`, so the "stale message" branch is skipped entirely — the staleness/freshness check is effectively neutralized for any negative timestamp.

This request then proceeds to `common.ValidatedRequestFromMessage` and is forwarded to all DON members via `don.SendToNode`, i.e., the bypass allows an unprivileged caller's malformed/replayable request to pass a validation gate meant to reject stale or manipulated trigger requests before it is broadcast to the node network: [2](#0-1) 

### Impact Explanation
This is analogous to the reported medium-severity issue: an integer sign-handling gap in a validation check that is supposed to gate a downstream operation. Here, the gate is the freshness/staleness check for externally-submitted trigger requests processed by the Gateway (an internet-facing, unprivileged-reachable component). Bypassing it means the intended anti-replay/anti-stale-request protection for `MethodWebAPITrigger` requests can be defeated by any external caller crafting a negative timestamp, undermining a safety control at the message-envelope validation layer of the gateway.

### Likelihood Explanation
The `Timestamp` field originates directly from untrusted, unprivileged, internet-facing client input (`payload` is unmarshaled from `body.Payload` of a message submitted to the Gateway's legacy trigger endpoint), and no authentication or privilege is required to set it to a negative number — only standard JSON encoding of a negative integer. The only barrier is the `== 0` check, which a negative value trivially avoids.

### Recommendation
Add an explicit lower-bound check before or in place of the zero-only check, e.g.:
```go
if payload.Timestamp <= 0 {
    // reject as invalid / stale
}
```
and avoid using an unguarded `uint(...)` cast on the signed `Timestamp` when computing the staleness comparison. Perform the comparison entirely in a signed type (or validate strict positivity first) to prevent underflow-based bypass, matching the recommendation from the referenced report (explicit `<= 0` rejection prior to any unsigned cast).

### Proof of Concept
1. Craft a Gateway legacy JSON-RPC request whose `body.Payload` decodes to `webapicap.TriggerRequestPayload{Timestamp: -1, ...}` with method `web_api_trigger`.
2. Submit it to the Gateway's `ProcessRequest`/`HandleLegacyUserMessage` path as an unauthenticated/unprivileged external client.
3. `payload.Timestamp == 0` is `false` (it's `-1`), so the "missing timestamp" branch is skipped.
4. `uint(payload.Timestamp)` underflows to `18446744073709551615` (on 64-bit `uint`), making `uint(time.Now().Unix()) - MaxAllowedMessageAgeSec > uint(payload.Timestamp)` false regardless of actual elapsed time, so the "stale message" branch is also skipped.
5. The clearly invalid/stale request is forwarded to all DON members via `don.SendToNode`, bypassing the intended freshness validation. [3](#0-2)

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
