### Title
Stale pre-default instant-withdraw receipts bypass the recovery haircut and are paid at par from strategy funds - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`finalizeDefaultRecovery` only includes `instantWithdrawClaimsByEpoch[epochNumber]` (the *current* epoch's instant receipts) in the defaulted claim basis, and `_claimDefaultedInstantWithdrawRequest` only clears the per-epoch entry for `defaultRecoveryEpoch`. An instant-withdraw receipt created in an **earlier** epoch that was never funded (i.e. `collectInstantWithdrawFunds` was never called for it because liquidity was lent out) survives finalization as stale pending state in `instantWithdrawsRequests[user]`. When the attacker later calls `claimInstantWithdrawRequest`, the defaulted-epoch clearing is a no-op for them and the full stale amount is burned and paid at par through `_transferFundedClaim`, which only checks that the default recovery reserve is not touched — not that the claim was ever funded or haircut.

### Finding Description
The analog to the LUKSO `_pendingOwner` bug: per-epoch receipt state is keyed by epoch, but finalization clears only the *default* epoch's entry, leaving earlier-epoch entries active and payable at par.

- `requestInstantWithdraw` records `instantWithdrawsRequestsByEpoch[user][epochNumber]` and adds to `instantWithdrawsRequests[user]` and `pendingInstantWithdraws` (`IdleCreditVault.sol:356-375`).
- `defaultPendingClaimBasis` adds `instantWithdrawClaimsByEpoch[epochNumber]` to the recovery basis only, so older-epoch instant receipts are **excluded** from `totalBasis` and receive no haircut (`IdleCreditVault.sol:644-649`).
- `_defaultPrefundedInstantReserve` computes reserve as `instantBasis(currentEpoch) - pendingInstantWithdraws`; when an old unfunded receipt inflates `pendingInstantWithdraws` above the current-epoch basis, no prefunded reserve is recognized for it (`IdleCreditVault.sol:716-722`).
- In `claimInstantWithdrawRequest`, `_claimDefaultedInstantWithdrawRequest` clears only `instantWithdrawsRequestsByEpoch[user][defaultRecoveryEpoch]`; for an older receipt it returns 0, then the contract burns the full `instantWithdrawsRequests[user]` and pays it at par via `_transferFundedClaim` (`IdleCreditVault.sol:382-392`, `842-856`).

The receipt was never funded by `collectInstantWithdrawFunds`, was never included in the recovery basis, yet is paid 1:1 from underlying held by the strategy (e.g. funds awaiting `sendInterestAndDeposits` or borrower routing), which are only protected by the `balance - reserve >= amount` check.

### Impact Explanation
An unprivileged KYC-passed lender receives their unfunded stale instant receipt at par, while every defaulted-epoch claimant is haircut by `defaultRecoveryPrice`. The payout consumes strategy underlyings that belong to the borrower pool / active accounting, i.e. a direct transfer of value equal to `(1 - defaultRecoveryPrice) * receiptAmount` more than their fair share, and up to the full receipt amount if the claim had zero funded backing. If the strategy balance is insufficient, the same stale entry instead permanently freezes the claim — but when any non-reserve balance exists (partial prefunding of other claims, interest payments sitting in the strategy), the payout succeeds as theft.

### Likelihood Explanation
Requires: (1) the attacker requests an instant withdraw in epoch N that remains unfunded because available liquidity was lent to the borrower (plausible under utilization pressure — instant liquidity is not guaranteed); (2) the borrower defaults in a later epoch before the queue funds the request (honest, unprivileged sequencing only); (3) the strategy holds non-reserve underlying at claim time. All steps use only normal user actions and honest privileged calls; no malicious role is needed.

### Recommendation
In `_claimDefaultedInstantWithdrawRequest`, clear `instantWithdrawsRequestsByEpoch` entries for **all** epochs ≤ `defaultRecoveryEpoch` (or aggregate unfunded instant basis across epochs in `defaultPendingClaimBasis`), so stale pre-default receipts are either haircut like current-epoch ones or included in the funded reserve. At minimum, apply `defaultRecoveryPrice` to any instant receipt whose `pendingInstantWithdraws` contribution was never collected, rather than paying it at par through `_transferFundedClaim`.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "../../contracts/strategies/idle/IdleCreditVault.sol";

contract StaleInstantReceipt_POC is Test {
    IdleCreditVault vault;      // configured strategy
    address cdo;                // IdleCDOEpochVariant instance
    address attacker = address(0xA11CE);

    function setUp() public {
        // fork mainnet; vault/cdo wired via setWhitelistedCDO
        // attacker is KYC-allowed lender holding tranche tokens
    }

    function testStaleInstantReceiptPaidAtPar() public {
        uint256 req = 100e18;

        // --- Epoch N running ---
        // Attacker requests instant withdraw while all liquidity is lent out:
        vm.prank(cdo);
        vault.requestInstantWithdraw(req, attacker);
        // CDO never calls collectInstantWithdrawFunds (no spare liquidity);
        // request stays in pendingInstantWithdraws + instantWithdrawsRequests.

        // --- Epoch N ends, epoch N+1 starts; borrower deploys funds, defaults ---
        // (honest stopEpoch/startEpoch/default sequencing via the CDO)

        // --- Default recovery finalized in epoch M > N ---
        vm.prank(cdo);
        vault.finalizeDefaultRecovery(recovered, recoverySource);
        // instantWithdrawsRequestsByEpoch[attacker][M] == 0 (request was epoch N)
        // => basis excluded the stale receipt; no haircut, no reserve for it.

        // Assume the strategy holds non-reserve underlying (e.g. prefunded
        // amounts for other instant claims or interest not yet forwarded).
        uint256 balBefore = underlying.balanceOf(attacker);

        vm.prank(cdo);
        vault.claimInstantWithdrawRequest(attacker);

        // Stale receipt paid 1:1 at par despite never being funded or haircut
        assertEq(underlying.balanceOf(attacker) - balBefore, req);
        // This exceeds the attacker's fair recovery share of
        // req * defaultRecoveryPrice / 1e18.
    }
}
```
