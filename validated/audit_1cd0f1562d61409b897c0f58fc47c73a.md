### Title
Cache key wildcard characters (`*`, `?`) survive `cachekey.Sanitize` and are inserted verbatim into the IAM session-policy `Resource` ARN, letting a job broaden its own S3 cache credentials beyond the single intended object - ([File: cache/s3v2/s3.go])

### Summary
`cachekey.Sanitize` only handles path separators, `..` traversal, and trailing whitespace; it never rejects or escapes IAM wildcard metacharacters (`*`, `?`). `s3Client.generateSessionPolicy` then interpolates the resulting `objectName` directly into the `Resource` field of an IAM policy via `fmt.Sprintf`, and the code comment's claim that `encoding/json` "escapes" special characters is incorrect for this threat model - JSON escaping only protects JSON *syntax* (quotes, backslashes), it does nothing to neutralize `*`/`?`, which are interpreted by the AWS IAM policy engine as glob wildcards regardless of how the string was serialized.

### Finding Description
- `cachekey.Sanitize` (`cache/cachekey/cachekey.go:27-57`) normalizes separators, resolves `.`/`..` traversal, and trims trailing whitespace, but does not filter or escape `*`/`?`. [1](#0-0) 
- The sanitized cache key becomes part of `objectName`, passed unmodified into `s3Adapter.GetGoCloudURL` → `client.FetchCredentialsForRole(ctx, roleARN, a.config.BucketName, a.objectName, upload, a.timeout)`. [2](#0-1) 
- `FetchCredentialsForRole` calls `c.generateSessionPolicy(bucketName, objectName, upload)`, which builds the `Resource` field with `fmt.Sprintf("arn:%s:s3:::%s/%s", s3Partition, bucketName, objectName)` and only afterwards runs the struct through `json.Marshal`. [3](#0-2) 
- The in-code comment asserts this is safe because "any special characters in objectName ... are escaped at the value position and cannot alter the policy structure" - this is true for JSON syntax but false for IAM policy semantics: `json.Marshal` does not escape `*` or `?`, and AWS IAM's `Resource` matcher treats unescaped `*`/`?` in an ARN as wildcards. [4](#0-3) 
- The resulting `sessionPolicy` string is passed as the `Policy` parameter to `sts.AssumeRole`, which AWS evaluates and intersects with the underlying IAM role's permissions to scope the returned session credentials. [5](#0-4) 
- Those credentials are then cached for up to one hour, keyed by `(roleARN, bucketName, objectName, upload)`, and returned to the job as environment variables for direct S3 access. [6](#0-5) [7](#0-6) 

Consequently, a pipeline author who sets `cache: key: "*"` (or any key ending in `*`/`?`, e.g. `foo*`) obtains an ARN such as `arn:aws:s3:::bucket/runner/<token>/project/<id>/*`, which is a valid IAM wildcard resource matching every object under that prefix - i.e., every cache object belonging to that project (all cache keys, all branches/pipelines), not merely the single object the job is supposed to access. If the underlying IAM role's actual permission boundary is broader than the intended per-object grant (e.g., a shared role scoped at bucket level, common when the assumed role itself already covers the whole bucket and relies on the session policy for narrowing), the wildcard removes that narrowing entirely, since the session policy is what is supposed to restrict the role down to one object.

### Impact Explanation
A job's temporary AWS credentials, which are supposed to be scoped to a single cache object, can be widened by the job itself to cover an entire prefix (up to the whole bucket, depending on how much of the ARN path the wildcard consumes and where operators place the wildcard-bearing key relative to project-scoping segments). This lets a job read or overwrite other cache objects (other cache keys, other pipelines/branches) that it was not supposed to have access to, for up to one hour due to `assumeRoleCredCache`. Whether this crosses project boundaries depends on how much of the ARN path before the cache key is attacker-influenced versus fixed server-side (e.g., a deterministic `runner/<token>/project/<id>/` prefix); regardless, it is a concrete violation of the "job-controlled cache keys must not expand IAM scope" invariant even within a single project's cache namespace.

### Likelihood Explanation
This requires no special privilege beyond authoring a `.gitlab-ci.yml` `cache: key` value (or, if cache keys can be templated from CI/CD variables, an unprivileged variable value) - a completely standard pipeline-author capability. It is deterministic and repeatable: any job with `cache: key: "*"` (or with a trailing `*`/`?`) that uses the S3v2 cache adapter with role-based (STS AssumeRole) credentials will trigger this on every run.

### Recommendation
Reject or escape IAM wildcard metacharacters (`*`, `?`) in `cache/cachekey/cachekey.go`'s `Sanitize`, or defensively escape them in `s3Client.generateSessionPolicy` before building the `Resource` ARN (IAM has no universal escape for `*`/`?` in ARNs, so the correct fix is to reject cache keys containing these characters, similar to how `Sanitize` already rejects/removes other problematic characters). Add a regression test asserting that `Sanitize` and/or `generateSessionPolicy` never produce a `Resource` string containing an unescaped `*` or `?` beyond what was structurally intended (bucket/prefix boundaries controlled by the runner, not the job).

### Proof of Concept
```go
func TestGenerateSessionPolicy_RejectsWildcardCacheKey(t *testing.T) {
    key, err := cachekey.Sanitize("*")
    require.NoError(t, err)
    // BUG: currently returns "*" unchanged.
    require.NotContains(t, key, "*", "sanitized cache key must not contain IAM wildcard characters")

    c := &s3Client{awsConfig: &aws.Config{Region: "us-east-1"}, s3Config: &cacheconfig.CacheS3Config{}}
    policy, err := c.generateSessionPolicy("test-bucket", "runner/token/project/123/"+key, false)
    require.NoError(t, err)

    var doc policyDocument
    require.NoError(t, json.Unmarshal([]byte(policy), &doc))
    resource := doc.Statement[0].Resource
    // Assert the Resource only ever matches the single intended object.
    require.False(t, strings.Contains(resource, "*") || strings.Contains(resource, "?"),
        "session policy Resource must not contain unescaped IAM wildcards: %s", resource)
}
```
Fuzz variant: fuzz `cachekey.Sanitize` inputs and feed the sanitized output into `generateSessionPolicy`, asserting the parsed `Resource` field never contains `*`/`?` outside the exact literal path supplied by the runner-controlled prefix segments.

```go
func Sanitize(cacheKey string) (string, error) {
	if cacheKey == "" {
		return "", nil
	}

	// Decode percent-encoded chars and normalise separators, then
	// resolve traversals against a virtual root so ".." can never
	// escape beyond the root.
	cleaned := path.Clean("/" + normaliser.Replace(cacheKey))

	// Strip the leading "/" we added, split into segments, then walk
	// backwards trimming trailing whitespace from the rightmost
	// segments—dropping any that become empty.
	parts := strings.Split(cleaned[1:], "/")
	n := len(parts)
	for n > 0 {
		parts[n-1] = strings.TrimRightFunc(parts[n-1], unicode.IsSpace)
		if parts[n-1] != "" {
			break
		}
		n--
	}

	key := strings.Join(parts[:n], "/")

	if key == "" {
		return "", fmt.Errorf("cache key %q could not be sanitized", cacheKey)
	}

	return key, nil
}
```

```go
func assumeRoleCacheKey(roleARN, bucketName, objectName string, upload bool) string {
	uploadStr := "0"
	if upload {
		uploadStr = "1"
	}
	return roleARN + "\x00" + bucketName + "\x00" + objectName + "\x00" + uploadStr
}
```

```go
func (c *s3Client) generateSessionPolicy(bucketName, objectName string, upload bool) (string, error) {
	action := "s3:GetObject"
	if upload {
		action = "s3:PutObject"
	}

	// https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html
	s3Partition := "aws"
	// https://docs.aws.amazon.com/govcloud-us/latest/UserGuide/using-govcloud-arns.html
	switch {
	case strings.HasPrefix(c.awsConfig.Region, "us-gov-"):
		s3Partition = "aws-us-gov"
	case strings.HasPrefix(c.awsConfig.Region, "cn-"):
		s3Partition = "aws-cn"
	}

	// Build the policy via encoding/json rather than string formatting so that
	// any special characters in objectName (which originates from the cache
	// key in .gitlab-ci.yml) are escaped at the value position and cannot
	// alter the policy structure.
	doc := policyDocument{
		Version: "2012-10-17",
		Statement: []policyStatement{
			{
				Effect:   "Allow",
				Action:   []string{action},
				Resource: fmt.Sprintf("arn:%s:s3:::%s/%s", s3Partition, bucketName, objectName),
			},
		},
	}

	if c.s3Config.EncryptionType() == cacheconfig.S3EncryptionTypeKms || c.s3Config.EncryptionType() == cacheconfig.S3EncryptionTypeDsseKms {
		// Permissions needed for multipart upload: https://repost.aws/knowledge-center/s3-large-file-encryption-kms-key
		doc.Statement = append(doc.Statement, policyStatement{
			Effect:   "Allow",
			Action:   []string{"kms:Decrypt", "kms:GenerateDataKey"},
			Resource: c.s3Config.ServerSideEncryptionKeyID,
		})
	}

	out, err := json.Marshal(doc)
	if err != nil {
		return "", fmt.Errorf("marshalling session policy: %w", err)
	}
	return string(out), nil
```
