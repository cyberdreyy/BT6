### Title
Zero-supply withdrawals cause `depositReward` to strand accrued rewards - (File: `contracts/StakingRewards.sol`)

### Summary
`StakingRewards.depositReward()` calculates remaining rewards as though distribution continued while `_totalSupply == 0`, omitting rewards accrued during the empty-staking interval from the next reward rate and leaving them stranded in the contract. [1](#0-0) [2](#0-1) 

### Finding Description
`rewardPerToken()` returns `rewardPerTokenStored` without accruing anything while `_totalSupply == 0`, so rewards are not distributed during an empty-supply interval. [1](#0-0) 

An unprivileged staker can withdraw the final staking-token balance, reducing `_totalSupply` to zero. [3](#0-2) 

When the honest `rewardsDistribution` account later calls `depositReward()`, the `updateReward(address(0))` modifier executes first and moves `lastUpdateTime` to the current timestamp. [4](#0-3) [5](#0-4) 

The function then computes `leftover` as `(periodFinish - block.timestamp) * rewardRate`, which only retains future scheduled rewards and incorrectly treats the empty-supply interval since the previous `lastUpdateTime` as already distributed. [6](#0-5) 

The omitted amount is `elapsedWhileEmpty * oldRewardRate`, where `elapsedWhileEmpty` is measured from the last accounting timestamp at which supply became zero to the `depositReward()` timestamp. [2](#0-1) 

For example, with a 7-day 700 USDC reward period, a final withdrawal after 1 day, and a 100 USDC top-up after another 2 days, the contract carries forward only 4 days of old rewards instead of 6 days, omitting approximately 200 USDC from the new distribution. [6](#0-5) 

The same accounting pattern also exists in `DelegateStakingRewardsIDLE.depositReward()`. [7](#0-6) [8](#0-7) 

### Impact Explanation
Rewards allocated for the zero-supply interval remain outside `rewardRate`, so future stakers receive less than the amount still held by the contract. [9](#0-8) 

The stranded amount equals approximately `oldRewardRate * elapsedWhileEmpty`; in the 700 USDC example, approximately 200 USDC is excluded from claimable rewards. [2](#0-1) 

Those rewards remain temporarily frozen in the contract because the accounting no longer schedules them, although the honest owner can rescue the reward-token balance through `recoverERC20()`. [10](#0-9) 

### Likelihood Explanation
Any staking-token holder can create `_totalSupply == 0` by withdrawing the last stake, after which only a routine honest reward top-up before `periodFinish` is required to trigger the accounting error. [11](#0-10) [12](#0-11) 

The contract is designed to be called by the IdleCDO rewards-distribution path, including staking fee tokens for the fee receiver, so this sequence does not require a malicious privileged role. [13](#0-12) [14](#0-13) 

### Recommendation
Before advancing `lastUpdateTime`, preserve the previous accounting timestamp and calculate undistributed rewards from that timestamp when `_totalSupply == 0`. [12](#0-11) [5](#0-4) 

Conceptually, the nonzero-supply path should continue using `periodFinish - block.timestamp`, while the zero-supply path should use `periodFinish - previousLastUpdateTime`; only afterward should `rewardPerTokenStored` and `lastUpdateTime` be updated. [1](#0-0) [5](#0-4) 

Apply the same correction to the duplicated rollover logic in `DelegateStakingRewardsIDLE.depositReward()`. [8](#0-7) 

### Proof of Concept
```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {StakingRewards} from "../contracts/StakingRewards.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract StakingRewardsZeroSupplyPoC is Test {
    uint256 private constant FORK_BLOCK = 19_462_710;

    address private constant TREASURY =
        0xe4E69ef860D3018B61A25134D60678be8628f780;
    address private constant IDLE =
        0x875773784Af8135eA0ef43b5a374AaD105c5D39e;
    address private constant USDC =
        0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    address private constant attacker =
        0x500D082eBb47447489D7dAB8fAcE2Ffcb2D4a2De;
    address private constant victim =
        0xd889Acb680D5eDbFeE593d2b7355a666248bAB9b;

    StakingRewards private stakingRewards;

    function testZeroSupplyTopUpOmitsUndistributedRewards() external {
        vm.createSelectFork("mainnet", FORK_BLOCK);

        stakingRewards = new StakingRewards();
        stakingRewards.initialize(
            TREASURY,
            USDC,
            IDLE,
            address(this),
            true
        );

        vm.startPrank(attacker);
        IERC20Detailed(IDLE).approve(address(stakingRewards), type(uint256).max);
        stakingRewards.stake(100_000e18);
        vm.stopPrank();

        vm.startPrank(TREASURY);
        IERC20Detailed(USDC).approve(address(stakingRewards), type(uint256).max);
        stakingRewards.depositReward(address(0), 700e6);
        vm.stopPrank();

        uint256 firstFinish = stakingRewards.periodFinish();
        uint256 oldRate = stakingRewards.rewardRate();

        // Rewards are distributed normally for one day.
        skip(1 days);

        // The attacker makes totalSupply zero. They have accrued 100 USDC.
        vm.prank(attacker);
        stakingRewards.withdraw(100_000e18);
        uint256 zeroSupplyLastUpdate = stakingRewards.lastUpdateTime();
        assertEq(stakingRewards.totalSupply(), 0);

        // No rewards can be distributed for the next two days.
        skip(2 days);
        uint256 notifyTime = block.timestamp;

        // An honest rewardsDistribution top-up rolls the period over.
        vm.prank(TREASURY);
        stakingRewards.depositReward(address(0), 100e6);

        uint256 actualScheduled = stakingRewards.getRewardForDuration();

        // Correct accounting preserves the six days not distributed since the
        // last timestamp at which stakers existed.
        uint256 correctScheduled =
            100e6 + (firstFinish - zeroSupplyLastUpdate) * oldRate;

        // Actual accounting preserves only the four days after notifyTime.
        uint256 currentScheduledBeforeRounding =
            100e6 + (firstFinish - notifyTime) * oldRate;

        assertApproxEqAbs(
            actualScheduled,
            currentScheduledBeforeRounding,
            1e6
        );
        assertApproxEqAbs(
            correctScheduled - actualScheduled,
            200e6,
            1e6
        );

        // A later staker can only claim the under-scheduled amount.
        vm.startPrank(victim);
        IERC20Detailed(IDLE).approve(address(stakingRewards), type(uint256).max);
        stakingRewards.stake(1e18);
        vm.stopPrank();

        skip(7 days);

        uint256 victimRewards = stakingRewards.earned(victim);
        assertApproxEqAbs(victimRewards, actualScheduled, 1e6);

        vm.prank(victim);
        stakingRewards.getReward();
        vm.prank(attacker);
        stakingRewards.getReward();

        // Approximately 200 USDC remains unscheduled and stranded.
        uint256 stranded = IERC20Detailed(USDC).balanceOf(address(stakingRewards));
        assertGt(stranded, 199e6);

        // It is temporarily frozen from reward distribution, though the owner
        // can rescue the reward token because it differs from stakingToken.
        stakingRewards.recoverERC20(USDC, stranded);
        assertEq(
            IERC20Detailed(USDC).balanceOf(address(stakingRewards)),
            0
        );
    }
}
```
