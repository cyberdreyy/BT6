### Title
Staking while paused inflates `total_staked_balance` beyond `account_locked_balance` - ([File: staking-pool/src/internal.rs])

### Summary
`stake()`, `stake_all()`, and `deposit_and_stake()` call `internal_stake` unconditionally regardless of `self.paused`, incrementing `total_staked_balance` and minting shares. They then call `internal_restake()`, which immediately returns without staking anything on-chain if `self.paused == true`. The result is `total_staked_balance` grows while the actual validator-locked balance (`env::account_locked_balance()`) does not, breaking the accounting invariant.

### Finding Description
The invariant claimed is: `total_staked_balance <= env::account_locked_balance()` whenever the pool is not mid-restake (i.e., outside of the async stake promise window).

Tracing the code:
- `stake(amount)` in [1](#0-0)  calls `internal_ping()`, `internal_stake(amount)`, then `internal_restake()` with no check on `self.paused` anywhere in this path.
- Likewise `stake_all()` [2](#0-1)  and `deposit_and_stake()` [3](#0-2)  have the same structure.
- `internal_stake` unconditionally mutates state: it converts `amount` to `num_shares`, deducts `charge_amount` from `account.unstaked`, and increases `self.total_staked_balance` and `self.total_stake_shares` — with no `paused` guard: [4](#0-3) .
- `internal_restake` is the only place that checks `paused`, and when true it returns immediately without issuing the `Promise::new(...).stake(...)` action that would actually raise `env::account_locked_balance()`: [5](#0-4) .
- The `paused` field's own doc comment states "When paused, the account unstakes everything (stakes 0) and doesn't restake," confirming the intended behavior is that while paused, on-chain staked balance is meant to be 0, yet `total_staked_balance` accounting is not held back: [6](#0-5) .

No existing guard (`assert_owner`, `assert_self`, etc.) blocks this: `stake`, `stake_all`, and `deposit_and_stake` are all open, unprivileged entrypoints with no `assert!(!self.paused, ...)` check. Only the owner-only methods `pause_staking`/`resume_staking` reference `paused` for transition purposes [7](#0-6) ; none of the delegator-facing staking methods check it.

Exploit flow: owner (or anyone observing a paused pool) calls `pause_staking()`. Now any unprivileged account with unstaked balance calls `stake(amount)` (or `deposit_and_stake`). `internal_stake` credits shares and increases `total_staked_balance` by `amount`. `internal_restake` returns early doing nothing on-chain. `env::account_locked_balance()` remains unchanged (or 0), while `total_staked_balance` is now strictly greater than it. This can be repeated by the same or different accounts to grow the divergence arbitrarily (bounded only by each account's unstaked balance).

### Impact Explanation
This does not move funds out of the contract directly, but it causes the contract's internal share-price accounting (`total_staked_balance` / `total_stake_shares`, used by `staked_amount_from_num_shares_rounded_down/up`) to diverge from the real locked balance backing it. Every account's reported `staked_balance` (via `get_account_staked_balance`, used for reward attribution and later unstake/withdraw amount calculations) is computed from this inflated `total_staked_balance`. Later, when `resume_staking` is called and `internal_restake` finally re-stakes, or when `internal_ping` computes `total_reward = total_balance - self.last_total_balance` using `env::account_locked_balance() + env::account_balance()`, the reward/loss accounting can be skewed relative to what was actually earned/locked, misattributing rewards or losses between the owner and delegators. This matches the "accounting value diverges from reality where another party settles on it" High-severity category, since other delegators' pro-rata share of real rewards is diluted or distorted by shares/staked-balance credited without backing.

### Likelihood Explanation
Feasibility is high: the attacker only needs unstaked balance already deposited in the pool (trivial via `deposit()`), and the pool must be paused (an event that legitimately occurs for validator node maintenance, not attacker-controlled but a realistic real-world state). Once paused, any account can call `stake()`/`stake_all()`/`deposit_and_stake()` repeatedly with no special privilege, cost being just gas, and can repeat across multiple calls/accounts to amplify the divergence.

### Recommendation
Add an explicit guard against staking while paused, e.g. in `internal_stake` or in each public entrypoint (`stake`, `stake_all`, `deposit_and_stake`):
```rust
assert!(!self.paused, "Staking is paused");
```
placed before shares are minted and `total_staked_balance` is incremented, so that staking is rejected entirely while the pool is paused, keeping `total_staked_balance` accounting consistent with what `internal_restake` can actually place on-chain.

### Proof of Concept
```rust
#[test]
fn test_stake_while_paused_overstates_total_staked_balance() {
    let mut emulator = Emulator::new(
        owner(),
        "KuTCtARNzxZQ3YvXDeLjx83FDqxv2SdQTSbiq876zR7".to_string(),
        zero_fee(),
    );

    // Owner pauses the pool.
    emulator.update_context(owner(), 0);
    emulator.contract.pause_staking();
    assert!(emulator.contract.is_staking_paused());

    // Attacker deposits unstaked funds.
    let deposit_amount = ntoy(1_000_000);
    emulator.update_context(bob(), deposit_amount);
    emulator.contract.deposit();
    emulator.amount += deposit_amount;

    // Snapshot locked balance before staking while paused.
    let locked_before = emulator.locked_amount; // env::account_locked_balance() equivalent

    // Attacker stakes while paused -- internal_restake() returns early, nothing staked on-chain.
    emulator.update_context(bob(), 0);
    let total_staked_before = emulator.contract.total_staked_balance;
    emulator.contract.stake(deposit_amount.into());

    // No promise executed the actual stake action, so locked balance is unchanged.
    let locked_after = emulator.locked_amount;
    assert_eq!(locked_before, locked_after, "locked balance must not change while paused");

    // But total_staked_balance grew, breaking the invariant total_staked_balance <= account_locked_balance.
    let total_staked_after = emulator.contract.total_staked_balance;
    assert_eq!(total_staked_after, total_staked_before + deposit_amount);
    assert!(
        total_staked_after > locked_after,
        "Invariant violated: total_staked_balance ({}) > account_locked_balance ({})",
        total_staked_after,
        locked_after
    );
}
```
This test pauses via the owner (a precondition, not an attacker action), then has an unprivileged account (`bob`) call `stake()`, and directly asserts the broken invariant `total_staked_balance > account_locked_balance` while paused.

    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;
