### Title
gateway.ProcessRequest forwards attacker-controlled/empty Auth to confidentialrelay handler without cryptographic verification - ([File: core/services/gateway/gateway.go])

### Summary
`gateway.ProcessRequest` decodes the `auth` string into the `jsonrpc2.Request.Auth` field via `jsonrpc2.DecodeRequest` and dispatches straight to `h.HandleJSONRPCUserMessage` without ever cryptographically validating that value against a sender key. The `confidentialrelay` handler's `HandleJSONRPCUserMessage` does not check `req.Auth` at all, so an unauthenticated caller with `auth=""` or `auth="garbage-jwt"` reaches the same fan-out-to-DON-nodes code path with no differentiated rejection tied to identity.

### Finding Description
`gateway.ProcessRequest` [1](#0-0)  decodes the raw request and attaches the raw `auth` string to `jsonRequest.Auth` via `jsonrpc2.DecodeRequest`, with no signature/JWT verification performed in this function. It then resolves a handler and calls `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` [2](#0-1) . The HTTP layer that feeds this simply strips the `Bearer ` prefix from the `Authorization` header and passes it through verbatim as `auth`, with no verification either [3](#0-2) .

The `confidentialrelay` handler's `HandleJSONRPCUserMessage` only validates `req.ID` (non-empty, ≤200 chars) before calling `h.fanOutToNodes` — it never reads or validates `req.Auth`: [4](#0-3) . No `Authorizer`, JWT validator, or allowlist check exists anywhere in `core/services/gateway/handlers/confidentialrelay/handler.go`, unlike the `vault` handler, which explicitly runs requests through `GatewayVaultRequestProcessor.ProcessRequest` → `authorizeAndStamp` → `Authorizer.AuthorizeRequest` (JWT-based or allowlist-based) before dispatch [5](#0-4) [6](#0-5) . The `confidentialrelay` handler has no equivalent step.

This means both an empty `auth=""` and a malformed `auth="garbage-jwt"` produce identical control flow through `gateway.ProcessRequest` → `multiHandler.HandleJSONRPCUserMessage` [7](#0-6)  → `confidentialrelay.handler.HandleJSONRPCUserMessage` → `fanOutToNodes`, with no rejection based on sender identity.

However, the impact of this gap depends on what `fanOutToNodes` sends and what the receiving DON nodes do with it. The forwarded request/params still carry whatever `workflow_id`/`execution_id` and capability-exec fields the caller supplied, and it is the DON member nodes (not the gateway) that ultimately execute and sign responses; the audit scope here is bounded to `ProcessRequest`/the confidentialrelay handler path and does not extend into node-side authorization enforcement, which was not located in the reachable code for this handler.

### Impact Explanation
Because `confidentialrelay`'s `HandleJSONRPCUserMessage` performs no auth/allowlist/JWT check on `req.Auth` (unlike the `vault` handler's `Authorizer` chain), any caller able to reach the gateway's HTTP endpoint can submit `capabilityExec`/`secretsGet` JSON-RPC requests that are fanned out to DON member nodes as if from a legitimate identity, since the gateway layer performs no identity binding at all. This matches a request-impersonation / authorization-bypass class of impact, assuming node-side execution trusts the gateway to have already screened the sender — a gap the audit could not fully confirm since node-side authorization enforcement is outside the reachable `gateway.go`/`confidentialrelay` handler code path examined here.

### Likelihood Explanation
No credential or role is required — any client capable of sending a JSON-RPC POST to the gateway's HTTP endpoint can supply any string (or empty string) as the `Authorization: Bearer` value and reach `fanOutToNodes` identically. The behavior is deterministic and repeatable for any `capabilityExec`/`secretsGet` request routed to the `confidentialrelay` handler.

### Recommendation
Add an explicit auth/authorization step in `confidentialrelay.handler.HandleJSONRPCUserMessage` — analogous to the vault handler's `Authorizer.AuthorizeRequest` / JWT validation chain — before calling `fanOutToNodes`, so that `req.Auth` is cryptographically verified and bound to a specific sender/owner prior to dispatch, and reject requests with missing or invalid auth with a distinct error rather than proceeding identically for both empty and malformed tokens.

### Proof of Concept
Go handler-level test plan (extending `core/services/gateway/handlers/confidentialrelay/handler_test.go`):
1. Build a `handler` via `setupHandler(t, 4)`.
2. Construct two otherwise-identical `jsonrpc.Request[json.RawMessage]{ID: "req-x", Method: MethodCapabilityExec, Params: validCapParamsJSON("wf1")}`, one with `Auth: ""` and one with `Auth: "garbage-jwt"`.
3. Call `h.HandleJSONRPCUserMessage(ctx, req, cb)` for each and assert both return `nil` error and both trigger `don.SendToNode` fan-out calls (mock `DON.On("SendToNode", ...)`), demonstrating no differentiated rejection based on `Auth` content.
4. Additionally assert `h.getActiveRequest(req.ID)` is non-nil for both cases, confirming both requests are queued for DON dispatch identically regardless of auth validity.

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

// ProcessRequest runs validate → authorize → prefix ID → stamp params.
func (p *GatewayVaultRequestProcessor) ProcessRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	publicKey *tdh2easy.PublicKey,
) (*AuthorizedGatewayVaultRequest, error) {
	if p.stripOwnerPrefixForAuth {
		originalRequestID, _ := stripPrefixedVaultRequestID(req.ID)
		req.ID = originalRequestID
	}

	switch req.Method {
	case vaulttypes.MethodSecretsCreate:
		return p.processCreateSecretsRequest(ctx, req, publicKey)
	case vaulttypes.MethodSecretsUpdate:
		return p.processUpdateSecretsRequest(ctx, req, publicKey)
	case vaulttypes.MethodSecretsDelete:
		return p.processDeleteSecretsRequest(ctx, req)
	case vaulttypes.MethodSecretsList:
		return p.processListSecretIdentifiersRequest(ctx, req)
	default:
		return nil, fmt.Errorf("unsupported gateway vault method: %s", req.Method)
	}
}

// AuthorizeRequest verifies JWTBasedAuth state and token claims, and returns a common AuthResult.
func (v *jwtBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	isEnabled, err := v.authEnabledGate.Limit(ctx)
	if err != nil {
		v.lggr.Errorw("failed to resolve JWTBasedAuth gate", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to resolve JWTBasedAuth gate: %w", err)
	}
	if !isEnabled {
		v.lggr.Debugw("JWTBasedAuth rejected request because it is disabled", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("JWTBasedAuth is disabled")
	}

	claims, err := v.validateToken(ctx, req.Auth)
	if err != nil {
		v.lggr.Debugw("JWTBasedAuth token validation failed", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("invalid JWT auth token: %w", err)
	}

	if scopeErr := enforceVaultJWTOAuthScopes(req.Method, claims.OAuthScopes); scopeErr != nil {
		v.lggr.Debugw("JWTBasedAuth OAuth scope rejected request", "method", req.Method, "requestID", req.ID, "orgID", claims.OrgID, "scopes", claims.OAuthScopes, "error", scopeErr)
		return nil, fmt.Errorf("invalid JWT auth token: %w", scopeErr)
	}

	if claims.TenantID == 0 {
		return nil, ErrMissingTenantID
	}
	if claims.TenantID != v.expectedTenantID {
		v.lggr.Debugw("JWT tenant id does not match job spec auth0 tenantID", "method", req.Method, "requestID", req.ID, "orgID", claims.OrgID, "claimsTenantID", claims.TenantID, "expectedTenantID", v.expectedTenantID)
		return nil, fmt.Errorf("%w: jwt tenant id %d expected tenant id %d", ErrJWTTenantIDJobSpecMismatch, claims.TenantID, v.expectedTenantID)
	}

	requestDigest, err := req.Digest()
	if err != nil {
		v.lggr.Debugw("JWTBasedAuth failed to compute request digest", "method", req.Method, "requestID", req.ID, "orgID", claims.OrgID, "workflowOwner", claims.WorkflowOwner, "error", err)
		return nil, fmt.Errorf("failed to compute request digest: %w", err)
	}

	if !strings.EqualFold(requestDigest, claims.RequestDigest) {
		v.lggr.Debugw("JWTBasedAuth request digest mismatch", "method", req.Method, "requestID", req.ID, "orgID", claims.OrgID, "workflowOwner", claims.WorkflowOwner, "computedDigest", requestDigest, "claimedDigest", claims.RequestDigest)
		return nil, fmt.Errorf("request digest mismatch: computed=%s claimed=%s", requestDigest, claims.RequestDigest)
	}

	derivedWorkflowOwner, err := DeriveJWTAuthorizedVaultWorkflowOwner(claims.OrgID, claims.TenantID, claims.WorkflowOwner)
	if err != nil {
		v.lggr.Debugw("JWTBasedAuth failed to derive authorized workflow owner", "method", req.Method, "requestID", req.ID, "orgID", claims.OrgID, "error", err)
		return nil, fmt.Errorf("invalid JWT auth token: %w", err)
	}

	authExpiresAt := claims.ExpiresAt.UTC().Add(jwtValidationLeeway).Unix()
	v.lggr.Debugw("JWTBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "orgID", claims.OrgID, "workflowOwner", derivedWorkflowOwner, "digest", requestDigest, "expiresAt", authExpiresAt)
	return &AuthResult{
		orgID:         claims.OrgID,
		workflowOwner: derivedWorkflowOwner,
		digest:        requestDigest,
		expiresAt:     authExpiresAt,
	}, nil
}
