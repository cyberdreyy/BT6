**Analysis:**

The premise conflates two unrelated things: `has_reconfiguration()` on `StateComputeResult`/`ExecutionOutput` is purely a metadata query (`self.execution_output.next_epoch_state.is_some()`) used by consensus/executor plumbing to know whether an epoch change occurred in a block's output [1](#0-0) . It is not a gate that causes a "retry" or re-execution of the same block/transaction — nothing in `PartialStateComputeResult` [2](#0-1)  or the executor pipeline re-runs Move-level logic like `staking_contract::distribute()` a second time for an already-produced output; the field is checked to route commit/notification behavior, not to duplicate execution.

Even hypothetically, `staking_contract::distribute()` and its internal function `distribute_internal` are idempotent by construction: they withdraw exactly `inactive + pending_inactive` from the stake pool via `stake::withdraw_with_cap`, and if a second call finds nothing left to withdraw, `distribution_amount == 0` and the function short-circuits and returns immediately without touching the distribution pool or paying anyone [3](#0-2) . So a duplicate call to `distribute()` around any boundary cannot pay commission twice — the underlying stake-pool balances are the source of truth and are consumed on first withdrawal.

Additionally, `distribute` is explicitly designed to be callable by anyone without owner/operator privileges ("Allow anyone to distribute already unlocked funds") [4](#0-3) , and this is intentional since it only moves already-unlocked funds to their already-determined recipients (based on `distribution_pool` shares computed via `update_distribution_pool`), so an unprivileged caller triggering `distribute()` cannot redirect or duplicate value regardless of reconfiguration timing.

No concrete unprivileged path was found that causes double commission computation; the claimed `has_reconfiguration()` retry mechanism does not exist in the executor code, and the Move-level accounting is protected against double-payment independently.

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };
