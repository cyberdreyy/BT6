### Title
Multisig request executes with confirmations from removed keys/members below the live-member threshold - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
`confirm()` in both `multisig/src/lib.rs` and `multisig2/src/lib.rs` counts a signer's confirmation into a request's `HashSet<PublicKey>`/`HashSet<String>` without any later invalidation if that signer's key/membership is subsequently removed. The `DeleteKey`/`DeleteMember` cleanup logic only purges requests *originated* by the removed identity (`r.signer_pk == pk` in `multisig/src/lib.rs:198-216`, `r.member == member` in `multisig2/src/lib.rs:361-371`) — it never scans `self.confirmations` for other pending requests that the removed identity had merely confirmed. As a result, a request can reach `num_confirmations` and execute using a mix of live and already-revoked confirmations, breaking the equality "confirmations counted == live members."

### Finding Description
In `multisig/src/lib.rs`, `confirm()` (lines 246-266) inserts `env::signer_account_pk()` into `self.confirmations.get(&request_id)` when the threshold isn't yet met. Separately, `execute_request`'s `DeleteKey` branch (lines 198-216) removes only the requests whose `signer_pk == pk` (i.e., requests the removed key itself created) and clears `num_requests_pk` for that key, but does not touch `self.confirmations` entries belonging to *other* requests where that key had already contributed a confirmation. The equivalent logic exists in `multisig2/src/lib.rs`'s `delete_member` (lines 355-379), which purges only requests where `r.member == member`.

Because NEAR access-key removal (via `promise.delete_key`) revokes the key from actually being able to sign further transactions, an attacker/removed member cannot add *new* confirmations after removal — but any confirmation they added *before* removal on a request that is still pending (i.e., a request created by someone else, not yet executed) remains permanently recorded and still counts toward `num_confirmations`.

### Impact Explanation
This lets a multisig request execute (moving funds, adding/deleting keys, deploying contracts, or calling arbitrary functions via `MultiSigRequestAction::Transfer`/`FunctionCall`/etc.) with fewer *currently live* confirming members than the configured threshold, since a stale confirmation from a member removed after confirming is still tallied. This is a "multisig request executed below threshold" scenario — a Critical-impact class per the rules, since it can move NEAR/wNEAR held by the multisig account without the intended number of live authorizers agreeing.

### Likelihood Explanation
Any legitimate governance flow where a member confirms several pending requests and is later removed (a normal operational event — e.g., rotating out a compromised or departing signer) leaves those stale confirmations live. No special privilege is needed beyond normal multisig operation; the remaining live members simply need to add sufficient additional confirmations to cross `num_confirmations`, unaware that one of the "confirmations" belongs to a member that no longer exists.

### Recommendation
When removing a key/member (`DeleteKey` in `multisig/src/lib.rs`, `DeleteMember`/`delete_member` in `multisig2/src/lib.rs`), iterate over **all** pending requests' `confirmations` sets (not just those originated by the removed identity) and strip the removed key/member's entry from each, re-checking whether removal drops a request below its confirmation count if execution was imminent. Alternatively, validate at `confirm()`/execution time that every public key/member counted in a request's confirmation set is still a current member before allowing the threshold check to pass.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. Member `B` calls `add_request` to create request `R` (e.g., `Transfer` to some receiver).
3. Member `A` calls `confirm(R)` → `confirmations[R] = {A}`.
4. Members `B, C, D` (3 live confirmations) submit and confirm a separate `DeleteMember { member: A }` request, which executes and calls `delete_key`/removes `A` from `self.members`. Because `A`'s only pending self-originated requests are purged (none here, since `R` was created by `B`), `confirmations[R]` still contains `A`.
5. Now only `B` and `C` (2 live members) need to confirm `R`: `B` created it (already implicitly not confirmed unless via `add_request_and_confirm`), so `B` confirms, then `C` confirms → `confirmations[R] = {A, B, C}`, length 3, meeting `num_confirmations = 3` and executing `R`'s `Transfer` — even though `A` is no longer a member and only 2 live members (`B`, `C`) actually authorized it at confirmation time.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);

        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
