### Title
Floor-rounded 70% threshold in `GlobalStateEvaluator::reached_agreement` lets signers capitulate their miner viewpoint below the true supermajority — (File: libsigner/src/v0/signer_state.rs)

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority threshold with **floor** division, while the authoritative on-chain/at-signing threshold, `NakamotoBlockHeader::compute_voting_weight_threshold`, computes the same 70% with **ceiling** division. Whenever `total_weight * 7` is not an exact multiple of 10, the two "70%" thresholds diverge by 1 weight unit, and the signer-side state machine will treat consensus as reached at a weight that the block-signing logic would reject as insufficient.

### Finding Description
`compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs` rounds the 70% threshold **up**: [1](#0-0) 

This ceiling threshold is the one actually enforced for a block's signer signature to be valid (`verify_signer_signatures`) and is mirrored on the signer side wherever real block signatures/pre-commits are tallied, e.g. `store_and_process_block_signature`'s `min_weight` check: [2](#0-1) 

However, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` in `libsigner/src/v0/signer_state.rs` — used purely to decide global *state-machine* agreement (protocol version, burn view, and crucially the agreed **current miner**) — round the same 70% threshold **down** (floor), with no `+1` for a nonzero remainder: [3](#0-2) 

For any `total_weight` where `total_weight * 7 % 10 != 0` (i.e. most real-world weight distributions), the state-machine's "reached agreement" threshold is exactly 1 weight unit lower than the true supermajority that `compute_voting_weight_threshold` and the block-signing path require. This is the same class of bug as the report's `maxAmountsIn` slip: two supposedly-identical quantities (here, "70% of total signer weight") are computed by two different rounding rules, and code that assumes they agree can be fooled by the gap.

The consequence is not merely cosmetic: `reached_agreement` directly gates `determine_global_state`, which supplies the state-machine's view of `current_miner`, and is consumed by `capitulate_miner_view`/`capitulate_viewpoint` to decide whether a signer should switch its local view of the canonical miner: [4](#0-3) 

and by `check_miner_inactivity` to decide whether to time out the current miner in favor of the prior one: [5](#0-4) 

Because `reached_agreement` under-counts the required weight by 1 unit whenever the remainder is nonzero, a signer can capitulate its miner viewpoint (i.e., decide which miner's tenure/blocks it will treat as canonical and be willing to sign) on a vote weight that is below the true 70% supermajority that the rest of the protocol (block signature verification) requires for equivalent consensus. This breaks the intended equality between "the state machine agrees on miner X" and "70% of weighted signers actually agree on miner X."

### Impact Explanation
This falls under the Critical category "a signer signing an invalid, non-canonical, or conflicting block": a signer's decision about which miner/tenure is currently valid — which gates whether it is willing to sign proposals from that miner and whether it treats a competing miner as `InvalidatedBeforeFirstBlock` — is driven by a threshold that is systematically weaker than the actual 70% supermajority used elsewhere in the same codebase for the equivalent decision. A single off-by-one-weight-unit signer capitulating to a not-actually-supermajority-backed miner view can start signing/pre-committing for blocks from a miner the rest of the honest majority has not actually endorsed at the required strength, or prematurely invalidate the legitimate miner, both of which are safety/liveness-relevant deviations from the intended supermajority rule.

### Likelihood Explanation
This requires no attacker action, a majority, or special access — it triggers organically any time the sum of online-signer weights participating in a given `address_updates` round is not an exact multiple of 10 relative to the 7/10 threshold (the overwhelmingly common case for real weight distributions, e.g. any `total_weight` not divisible by 10). It is a deterministic rounding defect reachable purely by ordinary gossip of `StateMachineUpdate` messages among a one-slot signer's peers, exactly the "gossip"-triggerable class allowed by the rules.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` (and `reached_disagreement`, for symmetry) use the same ceiling-rounding convention as `NakamotoBlockHeader::compute_voting_weight_threshold`, e.g.:
```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total = u64::from(self.total_weight);
    let threshold = u64::from(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD);
    let numerator = total.strict_mul(threshold);
    let needed = numerator.div_ceil(10); // ceiling division
    u64::from(vote_weight) >= needed
}
```
Ideally, factor a single shared `compute_voting_weight_threshold`-style helper used by both `stackslib` and `libsigner`/`stacks-signer` so the "70% of weight" quantity can never diverge between the two crates again.

### Proof of Concept
Given `total_weight = 11` (e.g., 11 signers each with weight 1, or any equivalent distribution summing to 11):
- `compute_voting_weight_threshold(11)`: `11*7 = 77`, `77 % 10 = 7 != 0` ⇒ `ceil = 1`; threshold = `77/10 + 1 = 8`. A block/pre-commit needs **8/11** weight to be valid.
- `GlobalStateEvaluator::reached_agreement(vote_weight)` with `total_weight = 11`: `11*7/10 = 7` (integer floor). `reached_agreement` returns `true` once `vote_weight >= 7`.

So with exactly `7` out of `11` weight units agreeing on a given `current_miner`/state view, `determine_global_state`/`capitulate_miner_view` will report "global agreement reached" and a signer may capitulate its miner viewpoint accordingly — one full weight unit short of the `8/11` supermajority that `compute_voting_weight_threshold` (and hence actual block-signature validity) requires for the same 70% guarantee.         let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);

            0

        };

            )
        })
    }
