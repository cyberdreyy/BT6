### Title
Unauthenticated disclosure of LOOP plugin pprof/metrics/discovery endpoints - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the top-level `api` group without wrapping them in `auth.Authenticate`, unlike every other sensitive route in the file. Any unauthenticated client can reach these handlers and obtain plugin process metrics, discovery target lists, and full pprof profiles/goroutine dumps.

### Finding Description
`NewRouter` builds the `api` router group with only rate-limiting and session-store middleware (no authentication requirement), then calls `loopRoutes(app, api)`: [1](#0-0) 

`loopRoutes` registers the LOOP plugin endpoints directly on this unauthenticated `api` group: [2](#0-1) 

Compare this to `debugRoutes`, which wraps its `/debug` group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [3](#0-2) , and to `metricRoutes`, which is only invoked inside the authenticated `authv2` group at the end of `v2Routes` [4](#0-3) . No equivalent authentication wrapper exists for `loopRoutes`.

The handlers themselves perform no authentication/authorization checks — `discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` in `core/web/loop_registry.go` immediately look up the plugin by name and proxy the request to the internal LOOP process, returning the response body directly to the caller: [5](#0-4) [6](#0-5) 

An attacker with no credentials at all can therefore send `GET /discovery`, `GET /plugins/<name>/metrics`, `GET /plugins/<name>/debug/pprof/<profile>` (e.g. `heap`, `goroutine`, `profile`), or `POST /plugins/<name>/debug/pprof/symbol`, and the node will proxy back the plugin's Prometheus metrics or full pprof/goroutine dumps.

### Impact Explanation
This exposes internal LOOP plugin runtime data (Prometheus metrics, heap/goroutine profiles, symbol tables) to any unauthenticated network client that can reach the node's web server port. Such data can reveal internal memory addresses/layout, running goroutine stacks (potentially including sensitive values held in memory), and metric labels/values that describe operational internals of the node's plugin processes — an information-disclosure impact consistent with Chainlink's "sensitive data exposure" bounty class, though it does not directly yield fund movement or job execution.

### Likelihood Explanation
Trivial to exploit: it requires zero credentials — no session cookie, no API key/secret, no external-initiator token — only network reachability to the node's configured web server port and knowledge/enumeration of a valid `:name` plugin identifier (which is itself partially disclosed by the unauthenticated `/discovery` endpoint, since it lists plugin metric paths and names). This is fully repeatable and requires no timing or race conditions.

### Recommendation
Wrap `loopRoutes` registration with the same authentication middleware used elsewhere (e.g. `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), and apply an appropriate minimum role (e.g. admin/run role) via `auth.RequiresAdminRole`/`auth.RequiresRunRole`, consistent with how `metricRoutes` is scoped inside the authenticated `authv2` group.

### Proof of Concept
Go handler-integration test plan:
1. Build a test `chainlink.Application` (or reuse existing router test helpers in `core/web/router_test.go`/`loop_registry_test.go`) with a registered fake LOOP plugin in `app.GetLoopRegistry()`.
2. Call `web.NewRouter(app, nil)` to get the `*gin.Engine`.
3. Using `httptest.NewRecorder()` and `httptest.NewRequest`, issue:
   - `GET /discovery` with no `Cookie` header and no `X-API-KEY`/`X-API-SECRET` headers.
   - `GET /plugins/<registered-name>/metrics` with no auth headers.
   - `GET /plugins/<registered-name>/debug/pprof/goroutine` with no auth headers.
   - `POST /plugins/<registered-name>/debug/pprof/symbol` with no auth headers.
4. Assert each response returns `http.StatusOK` (or plugin-proxy status) with plugin/metrics/pprof body content, instead of `http.StatusUnauthorized`, demonstrating the missing `auth.Authenticate` gate on `loopRoutes`.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
