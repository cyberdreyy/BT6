This is confirmed as a real vulnerability.

### Title
Job-controlled `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` variables can override injected cache credentials due to first-match env lookup in helper process construction - ([File: functions/concrete/run/env/env.go])

### Summary
The runner builds the cache-archiver/cache-extractor helper process's environment by concatenating `os.Environ()`, then `e.Env` (populated from job CI/CD variables), then `e.GitLabEnv`, and finally the cache adapter's injected credentials (`desc.Env`, containing `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` from `s3CredentialsAdapter.GetCredentials`) last. Because Go's environment lookup (`os.Getenv`) returns the *first* matching key in the process's `envp` slice rather than the last, a job-defined `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` variable placed earlier in the slice takes precedence over the operator-injected credential appended at the end, letting an unprivileged job redirect S3 cache traffic to attacker-controlled credentials/endpoints.

### Finding Description
`e.Env` is populated directly from job step variables/`JobVars` in `functions/concrete/run/runner.go` (`stepEnv := builtinCtx.GetEnvs(); for key, value := range jobVars { stepEnv[key] = value.GetStringValue() }`, then `Env: stepEnv`) — this is fully attacker-controlled, since any job can define a CI/CD variable named `AWS_ACCESS_KEY_ID` or `AWS_SECRET_ACCESS_KEY` in `.gitlab-ci.yml`. [1](#0-0) 

When the cache-archiver/cache-extractor helper subprocess is invoked, `functions/concrete/run/env/env.go`'s `Command` builds the environment slice for `exec.Cmd` in this exact order: `os.Environ()`, then all of `e.Env` (job vars), then `e.GitLabEnv`, and only *last* the `env` parameter (the resolved cache credentials passed through `HelperEnvs(desc.Env)`): [2](#0-1) 

The cache credentials themselves originate from `s3CredentialsAdapter.GetCredentials` (static keys) or `s3v2` `GetGoCloudURL`/`FetchCredentialsForRole` (STS-assumed role), and flow into `cacheDownloadDescriptor`/`cacheUploadDescriptor` as `Descriptor.Env`: [3](#0-2) [4](#0-3) 

These are then merged with `desc.Env` and passed to `e.RunnerCommand(ctx, e.HelperEnvs(desc.Env), args...)` in `cache_archive.go`, and similarly in `cache_extract.go` via `envOverlay`: [5](#0-4) [6](#0-5) 

Because Go's runtime environment lookup (`os.Getenv`/`syscall.Getenv` on Unix) scans the process's environ slice and returns the *first* match, not the last, having `AWS_ACCESS_KEY_ID=attacker-key` earlier in the `cmd.Env` slice (from job variables) beats the correctly-injected value appended at the end from `desc.Env`. This is the opposite of the intended "last write wins" semantics that developers commonly assume when concatenating env maps, and there is no filtering/precedence-enforcement logic anywhere in `Command`, `HelperEnvs`, `cacheDownloadDescriptor`, or `cacheUploadDescriptor` to strip or de-duplicate reserved credential keys before invoking the helper. `cache_extract.go`'s inline comment ("Primary wins on key collision ... alt's env only fills keys the primary descriptor didn't set") demonstrates the developers were aware of key-collision ordering semantics for `alt`/`desc` maps but did not consider job-variable collisions with the same keys.

The AWS SDK used by the cache-archiver/cache-extractor helper (through GoCloud's AWS SDK v2 credential resolution or the legacy static-credentials path) reads `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` from the process environment via `os.Getenv`, so whichever value is discovered first in the environ slice is what AWS SDK will actually use to sign/authenticate S3 requests.

### Impact Explanation
An unprivileged pipeline author can define `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` as job/pipeline variables. When the runner archives or extracts the cache via the S3 adapter with static credentials, the helper subprocess's actual outbound S3 request is signed with the attacker's credentials instead of the operator's. This lets the job redirect the cache upload/download to an attacker-controlled S3 account/bucket (data exfiltration of cache contents, or cache poisoning by uploading malicious artifacts under attacker's own bucket that still appear to originate from the runner's cache flow), impacting cross-project cache integrity/confidentiality as scoped.

### Likelihood Explanation
This is trivially reproducible: it only requires the S3 cache adapter to be configured with static `AccessKey`/`SecretKey` (a common configuration, not just IAM-role/STS-based), and a job defining CI/CD variables `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`. No special privileges are needed beyond normal pipeline variable definition rights. It is deterministic given Go's environment-lookup semantics (first-match-wins), so it reproduces on every run once the runner is on the concrete/step-runner execution path (`UseConcrete` feature flag) with S3 static-key caching configured.

### Recommendation
In `functions/concrete/run/env/env.go`'s `Command`, and in `HelperEnvs`, ensure the cache-adapter-injected credentials (`env`/`extra` parameter) cannot be shadowed by job-controlled variables: either de-duplicate the `environ` slice so only the last occurrence of each key is kept (i.e., build a `map[string]string` merge with job vars first and injected credentials last, then serialize to a single `KEY=VALUE` entry per key), or explicitly strip/reject `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` (and other cloud-provider credential variable names used by GCS/Azure adapters) from `e.Env`/job variables before invoking cache-related helper subprocesses.

### Proof of Concept
Go unit test in `functions/concrete/run/env` package:
```go
func TestCommand_JobVarCannotShadowInjectedCacheCredential(t *testing.T) {
    e := &Env{
        Env: map[string]string{
            "AWS_ACCESS_KEY_ID": "attacker-controlled-key", // simulates job variable
        },
        GitLabEnv: map[string]string{},
        WorkingDir: t.TempDir(),
    }
    // "extra" simulates desc.Env from cacheUploadDescriptor/GetCredentials
    extra := map[string]string{"AWS_ACCESS_KEY_ID": "operator-injected-key"}

    // Use a helper script/binary that just prints $AWS_ACCESS_KEY_ID and assert
    // stdout contains "operator-injected-key", not "attacker-controlled-key".
    var stdout bytes.Buffer
    e.Stdout = &stdout
    err := e.Command(context.Background(), "printenv", extra, "AWS_ACCESS_KEY_ID")
    require.NoError(t, err)
    assert.Contains(t, stdout.String(), "operator-injected-key",
        "job-defined AWS_ACCESS_KEY_ID must not shadow the cache adapter's injected credential")
}
```
Expected current (buggy) result: the test fails because `printenv`/the child process (via Go's first-match `os.Getenv` semantics, or `printenv`'s libc `getenv`) resolves to `attacker-controlled-key`, proving the override succeeds against the intended invariant.

func (e *Env) Command(ctx context.Context, name string, env map[string]string, args ...string) error {
	environ := os.Environ()
	for k, v := range e.Env {
		environ = append(environ, k+"="+v)
	}
	for k, v := range e.GitLabEnv {
		environ = append(environ, k+"="+v)
	}
	for k, v := range env {
		environ = append(environ, k+"="+v)
	}

	cmd := gracefulexitcmd.New(ctx, e.GracefulExitDelay, name, args...)
	cmd.Dir = e.WorkingDir
	cmd.Env = environ
	cmd.Stdout = e.Stdout
	cmd.Stderr = e.Stderr

	return normalizeExitError(cmd.Run(), cmd.ProcessState)
}

func (a *s3CredentialsAdapter) GetCredentials() map[string]string {
	credMap := make(map[string]string)

	// For IAM instance profiles, Go Cloud will fetch the credentials with the AWS SDK.
	if a.config.AccessKey == "" || a.config.SecretKey == "" {
		return credMap
	}

	credMap["AWS_ACCESS_KEY_ID"] = a.config.AccessKey
	credMap["AWS_SECRET_ACCESS_KEY"] = a.config.SecretKey

	return credMap
}

func cacheDownloadDescriptor(ctx context.Context, build *Build, sharded bool) func(string) (cacheprovider.Descriptor, error) {
	return func(cacheKey string) (cacheprovider.Descriptor, error) {
		adapter := cache.GetAdapter(build.Runner.Cache, build.GetBuildTimeout(), build.Runner.ShortDescription(), fmt.Sprintf("%d", build.JobInfo.ProjectID), cacheKey, sharded)

		goCloudURL, err := adapter.GetGoCloudURL(ctx, false)
		if goCloudURL.URL != nil {
			return cacheprovider.Descriptor{
				GoCloudURL: true,
				URL:        goCloudURL.URL.String(),
				Env:        goCloudURL.Environment,
			}, err
		}

		url := adapter.GetDownloadURL(ctx)
		if url.URL == nil {
			return cacheprovider.Descriptor{}, nil
		}

		desc := cacheprovider.Descriptor{
			URL:     url.URL.String(),
			Headers: url.Headers,
		}

		if headURL := adapter.GetHeadURL(ctx); headURL.URL != nil {
			desc.HeadURL = headURL.URL.String()
		}

		return desc, nil
	}
}
