### Title
Vault handler request-timeout error path leaks DON node addresses and raw node responses through `gateway.ProcessRequest` - (File: core/services/gateway/handlers/vault/handler.go)

### Summary
When a vault request (including the unauthenticated `MethodPublicKeyGet`) times out before quorum is reached, `removeExpiredRequests` builds an error string that embeds every responding node's address and its full raw JSON-RPC response, and this string is returned to the requesting client verbatim through `gateway.ProcessRequest`. The `errorResponse` helper has no sanitization step for `api.RequestTimeoutError`, so the internal node/DON information is not redacted before being written into the wire response the attacker receives.

### Finding Description
`gateway.ProcessRequest` forwards whatever the handler's callback produces straight to the HTTP client: `response, err := callback.Wait(ctx)` ... `return response.RawResponse, api.ToHttpErrorCode(response.ErrorCode)` [1](#0-0) .

In the vault handler, `removeExpiredRequests` iterates over `activeRequests` that timed out waiting for DON quorum and, for each, concatenates every node address and its raw node response into a single string, then wraps it in an `errors.New(...)` that becomes the response's error message and `data`: [2](#0-1) 

That error is passed to `errorResponse` with `api.RequestTimeoutError`. The `switch errorCode` in `errorResponse` only sanitizes/rewraps specific codes (`NodeReponseEncodingError`, `InvalidParamsError`, `UnsupportedMethodError`, `UserMessageParseError`); `RequestTimeoutError` falls into the no-op branch, so the original, unredacted `err.Error()` (containing node addresses and raw responses) is written directly into the JSON-RPC wire message via `h.codec.EncodeNewErrorResponse(req.ID, ..., err.Error(), data)`: [3](#0-2) 

Critically, `MethodPublicKeyGet` requests bypass all authorization checks (`"Public key requests don't require authorization"`), so any signed request from an arbitrary EOA can enter the `fanOutToVaultNodes` / `activeRequests` lifecycle and hit this timeout path without owning any workflow or holding any privilege: [4](#0-3) 

This response then flows back unmodified through `callback.Wait` into `gateway.ProcessRequest`'s final `return response.RawResponse, ...` with no additional filtering at the gateway layer.

### Impact Explanation
Any signed request that legitimately (or, if an attacker can influence node responsiveness/quorum, deliberately) fails to reach quorum before the configured `requestTimeout` will leak the addresses of all DON member nodes that had responded plus their raw JSON-RPC payloads to the original requester. This discloses DON membership/topology and internal node identifiers to an unprivileged caller, which is reconnaissance data that can be leveraged to target specific nodes (e.g., for rate-limit exhaustion, downstream request forgery, or selecting nodes to attack in order to force further quorum failures/leaks), aligning with an information-disclosure class impact against Chainlink's gateway trust boundary.

### Likelihood Explanation
Reaching the vulnerable path requires only sending a signed `MethodPublicKeyGet` (no authorization needed) or an authorized vault method request and having the DON not reach quorum within `requestTimeout` (default derived from `RequestTimeoutSec`, default 30s) [5](#0-4) . This can occur under normal network conditions (slow/partitioned nodes) without any attacker privilege, and is deterministically reproducible in a unit test by mocking `don.SendToNode` to simulate delayed/partial node responses and letting the cleanup ticker fire.

### Recommendation
In `errorResponse` (core/services/gateway/handlers/vault/handler.go), add `api.RequestTimeoutError` to the sanitized branches: replace the detailed `err` (which contains node addresses/raw responses) with a generic message (e.g., `"request timed out waiting for DON quorum"`), log the detailed `nodeResponsesStr` only via `h.lggr` (not to the user), and drop the `data` payload for this error code so no per-node information reaches the client.

### Proof of Concept
Table-driven test in `core/services/gateway/handlers/vault/handler_test.go`:
1. Construct a `handler` with a mocked `don.SendToNode` that never/slowly responds so the request stays in `activeRequests` past `requestTimeout`.
2. Send a `MethodPublicKeyGet` (unauthorized) request through `HandleJSONRPCUserMessage`, then advance the fake clock past `requestTimeout` and invoke `removeExpiredRequests`.
3. Capture the callback's `UserCallbackPayload.RawResponse`, unmarshal the JSON-RPC error, and assert `Error.Message` and `Error.Data` do NOT contain any node address substring (e.g., `"0x..."` from `donConfig.Members`) nor the string `"---:::"` used to join node responses — asserting the response matches a generic allowlisted message instead of leaking internal node data.

func (h *handler) errorResponse(
	req jsonrpc.Request[json.RawMessage],
	errorCode api.ErrorCode,
	err error,
	data []byte,
) gwhandlers.UserCallbackPayload {
	switch errorCode {
	case api.FatalError:
	case api.NodeReponseEncodingError:
		h.lggr.Errorw(err.Error(), "requestID", req.ID)
		// Intentionally hide the error from the user
		err = errors.New(errorCode.String())
	case api.InvalidParamsError:
		paramsStr := ""
		if req.Params != nil {
			paramsStr = string(*req.Params)
		}
		h.lggr.Errorw("invalid params", "requestID", req.ID, "params", paramsStr)
		err = errors.New("invalid params error: " + err.Error())
	case api.UnsupportedMethodError:
		h.lggr.Errorw("unsupported method", "requestID", req.ID, "method", req.Method, "error", err.Error())
		err = errors.New("unsupported method(" + req.Method + "): " + err.Error())
	case api.UserMessageParseError:
		h.lggr.Errorw("user message parse error", "requestID", req.ID, "error", err.Error())
		err = errors.New("user message parse error: " + err.Error())
	case api.NoError:
	case api.UnsupportedDONIdError:
	case api.ConflictError:
	case api.HandlerError:
	case api.LimitExceededError:
	case api.RequestTimeoutError:
	case api.StaleNodeResponseError:
		// Unused in this handler
	}

	// Strip the owner prefix from the json response ID before sending it back to the user
	// This ensures compliance with JSONRPC 2.0 spec, which requires response id to match request id
	index := strings.Index(req.ID, vaulttypes.RequestIDSeparator)
	if index != -1 {
		req.ID = req.ID[index+2:]
	}

	return gwhandlers.UserCallbackPayload{
		RawResponse: h.codec.EncodeNewErrorResponse(
			req.ID,
			api.ToJSONRPCErrorCode(errorCode),
			err.Error(),
			data,
		),
		ErrorCode: errorCode,
	}
}
