### Title
Unbounded TCP/WebSocket connection acceptance in flashblocks publisher leads to file-handle exhaustion - (File: crates/builder/publish/src/listener.rs)

### Summary
The flashblocks `WebSocketPublisher`'s `Listener::run` accept loop takes every incoming TCP connection unconditionally and spawns a handler task for each, with no limit on concurrent connections (no `max_connections`, no per-IP or global semaphore), unlike every other network-facing server in this repository.

### Finding Description
`WebSocketPublisher::with_capacity` binds a `TcpListener` on the configured flashblocks address and spawns `Listener::new(...).run()` [1](#0-0) . Inside `Listener::run`, the loop does `listener.accept()` and immediately `tokio::spawn`s a task for each accepted socket that performs a WebSocket handshake (bounded by a 10s timeout) and then runs a `BroadcastLoop` for the connection's lifetime [5](#0-4) . There is no cap on the number of sockets that can be simultaneously accepted/held open, no per-IP limiting, and no backpressure applied at accept time — mirroring the root cause described in GHSA-xmw9-q7x9-j5qc, where Blaze accepted connections unconditionally onto a dedicated pool, exhausting OS socket handles before any higher-level limit could apply.

### Impact Explanation
An unauthenticated remote party can open a very large number of TCP connections to the flashblocks WebSocket publisher port and hold them open (completing or stalling within the 10s handshake window and repeating), exhausting the node's file descriptor limit. Once file handles are exhausted, the process can fail to accept further connections, open new files/sockets for its other duties (e.g., serving other RPC/P2P sockets or writing to disk), leading to a node halt or denial of service for the flashblocks pending-state feed and potentially other node subsystems sharing the process-wide FD limit.

### Likelihood Explanation
High likelihood: the flashblocks publisher listens on a plain TCP/WebSocket port with no authentication and no connection accounting, so any anonymous client that can reach the port can trivially open many connections. No privileged access, valid transaction, or protocol knowledge is required — only network reachability to the listener address.

### Recommendation
Add a global (and optionally per-IP) concurrent-connection cap to `Listener` (e.g., an `Arc<Semaphore>` acquired before/at accept time, or a counter checked before completing the WebSocket handshake), rejecting/closing connections beyond the limit, matching the pattern already used in `crates/infra/websocket-proxy/src/rate_limit.rs` and the `max_connections` setting on the jsonrpsee RPC server in `crates/consensus/service/src/actors/rpc/actor.rs`.

### Proof of Concept
A client-side PoC would open connections in a loop to the flashblocks publisher's bound address (`SocketAddr` passed to `WebSocketPublisher::new`/`with_capacity`) without completing/closing the WebSocket handshake promptly, repeating faster than the 10-second handshake timeout evicts stale sockets, until the process's file-descriptor limit is exhausted; verification would require running the publisher binary and observing accept failures or process-wide FD exhaustion, which is not verifiable purely from static code review — this should be confirmed by a Devin session with runtime access if a definitive PoC is required.

            }),

impl RateLimit for InMemoryRateLimit {
    fn try_acquire(self: Arc<Self>, addr: IpAddr) -> Result<Ticket, RateLimitError> {
        let mut inner = self.inner.lock().unwrap_or_else(|e| e.into_inner());

        let permit = Arc::clone(&inner.semaphore).try_acquire_owned().map_err(|_| {
            RateLimitError::Limit {
                reason: "Global limit".to_owned(),
                limit_type: RateLimitType::Global,
            }
        })?;

        let current_count = inner.active_connections.get(&addr).copied().unwrap_or(0);

        if current_count + 1 > self.per_ip_limit {
            debug!(message = "Rate limit exceeded, trying to acquire", client = addr.to_string());
            return Err(RateLimitError::Limit {
                reason: String::from("IP limit exceeded"),
                limit_type: RateLimitType::PerIp,
            });
        }

        let new_count = current_count + 1;

        inner.active_connections.insert(addr, new_count);

        let rate_limiter: Arc<dyn RateLimit> = Arc::clone(&self) as Arc<dyn RateLimit>;
        Ok(Ticket { addr, _permit: permit, rate_limiter })
    }
