## Analysis

Confirmed: `extractZipFile` in `helpers/archives/zip_extract.go` uses `file.Name` (raw zip entry path) with no `filepath.Clean`, no traversal check (`..`), and no containment check against an extraction root. [1](#0-0) 

The only path-related guard in the extraction pipeline is `errorIfGitDirectory`, which only checks whether the first path segment is `.git` — it does nothing to block `../` traversal. [2](#0-1) [3](#0-2) 

Critically, in `ziplegacy.extractor.Extract`, the `dir` field (extraction root passed from `CacheExtractorCommand.Execute` via `archive.NewExtractor(format, f, size, wd)`) is stored on the struct but **never used** — `Extract` calls `archives.ExtractZipArchive(zr)` directly without joining `e.dir` to any entry path. [4](#0-3) 

So extraction happens directly against `file.Name`, interpreted relative to the process's current working directory (the job's working directory, `wd` from `os.Getwd()`), with `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile(file.Name, ...)` allowing arbitrary `../../` segments to escape that directory. [5](#0-4) [6](#0-5) 

## Scoped impact caveat

The scoped impact requires that this traversal let a job overwrite a mounted service-account token or shared volume file to gain elevated identity/permissions — this depends on filesystem/mount topology of the executor (Kubernetes pod mounts, Docker container mounts, etc.), which is not something I can verify from this repo alone. What I can verify from the code is that `extractZipFile`/`ExtractZipArchive` performs no path sanitization and the passed-in extraction root (`dir`/`wd`) is not enforced, so writes go wherever `file.Name` (fully attacker-controlled, since caches/artifacts zips are attacker-supplied) resolves relative to CWD. If the CWD-relative traversal reaches a writable file such as a projected service-account token, that's a real path to identity escalation on Kubernetes executors; but whether such a token file is writable via a normal path-traversal `os.OpenFile` (as opposed to needing root/privileged access to the mount) depends on container/pod security context, not on this code.

### Title
Zip archive extraction path traversal via unsanitized `zip.File.Name` - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` (and its callers `ExtractZipArchive`/`ExtractZipFile`, reached via `ziplegacy.extractor.Extract` for cache/artifact zip restoration) writes archive entries using the raw `file.Name` from the zip, with no `..`-traversal or containment check against the intended extraction directory. The extraction root (`dir`) passed into the legacy zip extractor is not even used, so a malicious cache/artifact zip whose entry names contain `../` segments can create/overwrite files outside the job workspace, anywhere the runner process's CWD-relative resolution permits.

### Finding Description
`CacheExtractorCommand.Execute` obtains the job working directory (`wd`) and passes it into `archive.NewExtractor(format, f, size, wd)`, then calls `extractor.Extract(ctx)`. [5](#0-4) 
For the zip legacy format, `NewExtractor` returns a `ziplegacy.extractor{r, size, dir}`, but `Extract` never uses `e.dir` — it just runs `archives.ExtractZipArchive(zr)` over the raw `zip.Reader`. [7](#0-6) 
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry, only guarding against `.git` as first path component (`errorIfGitDirectory`), not against `..` traversal. [8](#0-7) 
`extractZipFile` does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` then dispatches to `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`, all of which call `os.OpenFile(file.Name, ...)`, `os.Mkdir(file.Name, ...)`, or `os.Symlink(string(data), file.Name)` directly with the unsanitized name. [9](#0-8) 
Because Go's `filepath.Dir`/`os.OpenFile` do not restrict `..` segments, an entry named e.g. `../../../var/run/secrets/kubernetes.io/serviceaccount/token` resolves relative to the process's CWD and can traverse outside the workspace. Cache archives are downloaded/restored from user-configured cache paths and keys and are fully attacker-controlled content (the CI job produces and later restores its own cache/artifacts zip), so an unprivileged pipeline author can craft such a zip.

### Impact Explanation
If the traversal path from the job's CWD reaches a writable target such as a projected/mounted service-account token file, a shared executor volume, or another job's directory, the job can overwrite that file's contents, potentially replacing a service-account token or injecting content into files consumed by other processes with different privilege — an escape from the intended cache/artifact extraction root. The actual reachable targets depend entirely on the executor's filesystem/mount layout (Kubernetes pod volume mounts, Docker bind mounts, shell executor host paths), which this code does not constrain at all.

### Likelihood Explanation
Preconditions are minimal for an unprivileged user: control over `.gitlab-ci.yml` cache/artifacts configuration and the ability to produce a cache archive is standard pipeline-author capability. The archiver side does have git-directory checks but no path-traversal checks either (not reviewed in depth here, but the extractor side clearly lacks them), and the extractor's `dir` parameter is dead code, so there is no containment enforcement whatsoever. This is highly reproducible: any crafted zip with `../` entries will trigger `os.MkdirAll`/`os.OpenFile` outside the intended root when extracted.

### Recommendation
In `extractZipFile` (or centrally in `ExtractZipArchive`), resolve each `file.Name` against the intended extraction root, reject/clean entries whose cleaned path escapes that root (e.g., using `filepath.Clean` plus a check that the resulting absolute path has the root as a prefix, or `filepath.Rel` + reject leading `..`), before calling `os.MkdirAll`/`os.OpenFile`/`os.Symlink`/`os.Mkdir`. Additionally, wire `ziplegacy.extractor.dir` into `ExtractZipArchive` so extraction always happens under the caller-supplied root rather than silently using the process CWD.

### Proof of Concept
Go unit test added to `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpRoot := t.TempDir()
    outsideMarker := filepath.Join(t.TempDir(), "outside", "pwned")

    // Build in-memory zip with a traversal entry name pointing from tmpRoot to outsideMarker.
    rel, _ := filepath.Rel(tmpRoot, outsideMarker) // e.g. "../<tmp2>/outside/pwned"
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, _ := zw.Create(rel)
    _, _ = w.Write([]byte("payload"))
    _ = zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    oldWd, _ := os.Getwd()
    _ = os.Chdir(tmpRoot)
    defer os.Chdir(oldWd)

    err := ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the traversal file was NOT created outside tmpRoot.
    _, statErr := os.Stat(outsideMarker)
    assert.True(t, os.IsNotExist(statErr), "expected no file to be written outside extraction root, but found: %s", outsideMarker)
}
```
Expected current behavior: the assertion fails (file IS created outside `tmpRoot`), demonstrating the traversal bug; after a fix enforcing containment, the assertion passes.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
