### Title
Global (non-namespaced) requestID map in `httpTriggerHandler` allows any authorized workflow user to squat another user's/workflow's requestID and deny their trigger request - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`httpTriggerHandler.callbacks` is keyed purely by the client-supplied `requestID` string, shared across **all** workflows served by a shard endpoint, with no binding to workflow ID, workflow owner, or authorized key. An attacker authorized for their own workflow A can submit a `workflows.execute` request whose `id` is set to a value they predict a victim (workflow B or another user of workflow A) will use next, occupying the slot in `setupCallback` before the victim's genuine request arrives. The victim's legitimate call then fails with `jsonrpc.ErrConflict`, a targeted denial of service on that specific request.

### Finding Description
In `HandleUserTriggerRequest` [1](#0-0) , the pipeline is: parse/validate → `resolveWorkflowID` → `authorizeRequest` (JWT signature verification bound only to the request's own params/ID via `VerifyRequestJWT`, and checked against the authorized-key set of the workflow resolved *from the attacker's own request*) → `checkRateLimit` → `setupCallback(ctx, req.ID, ...)`.

`setupCallback` guards uniqueness solely on the raw `requestID` string in a single map shared across the entire `httpTriggerHandler` instance: [2](#0-1) 

`validateRequestID` only rejects empty IDs or IDs containing `/`; it does not scope or namespace the ID by workflow or owner: [3](#0-2) 

Because the JWT verification in `Authorize` only checks that the signature matches a digest computed from the attacker's *own* self-consistent request (workflowID, params, ID) [4](#0-3) , an attacker who is legitimately authorized for their own workflow A can freely choose any `req.ID` string (including one they predict the victim will use for workflow B, or for a different session of workflow A) and pass authorization cleanly. Their request then reaches `setupCallback` first and claims `h.callbacks[requestID]`. When the victim's genuine request for the same `requestID` arrives afterward, `setupCallback` finds the key already present and returns `jsonrpc.ErrConflict`, causing `HandleUserTriggerRequest` to fail for the victim (confirmed by the existing test `"duplicate JWT token and request ID"` demonstrating the second submission with the same ID cleanly fails) [5](#0-4) .

Regarding the second sub-question (cross-user data confusion via `reqWithAuthorizedKey`): this is not exploitable. The attacker's own request is dispatched under the attacker's own `workflowID`/key via `sendWithRetries`, and the response is routed back only to the attacker's own registered `callback` object in `h.callbacks[requestID]` [6](#0-5) . The victim's request never gets registered (it is rejected at `setupCallback` before any callback/response wiring occurs), so no attacker-controlled data is ever delivered to the victim, and the victim's own request never silently succeeds — the failure is clean and immediate as `ErrConflict`.

### Impact Explanation
This is a targeted, repeatable denial-of-service against a specific request ID/workflow trigger: any authorized workflow owner (a normal capability, not requiring elevated privilege) can prevent another user's or workflow's specific trigger invocation from ever executing by squatting the identifier first, provided the requestID is predictable (e.g., sequential/timestamp-based client SDK defaults, as hypothesized). This does not lead to fund loss, key disclosure, or cross-user data leakage — the failure mode is clean rejection (`ErrConflict`), matching a griefing/availability-impact class rather than a confidentiality or integrity breach.

### Likelihood Explanation
Requires only that the attacker (a) be authorized for at least one workflow (any legitimate workflow client credential suffices — this is a low bar, not admin/operator access), and (b) can predict or observe the victim's next `requestID` value. Predictability depends entirely on the victim's client-side ID generation scheme; if IDs are random/UUIDv4, this is not practically exploitable, but the code provides no server-side protection against it regardless of how IDs are generated. The attack is fully reproducible via a single pre-emptive `HandleUserTriggerRequest` call with a chosen ID.

### Recommendation
Scope the `callbacks` map (and the uniqueness check in `setupCallback`) by a composite key that includes the resolved `workflowID` (and/or authorized key/owner) in addition to the raw `requestID`, e.g. `workflowID + "/" + requestID`, so that requestID collisions can only occur within the same workflow's own request stream, not across unrelated workflows/users. This preserves the intended per-workflow idempotency semantics of `requestID` while eliminating cross-workflow squatting.

### Proof of Concept
Go test plan (extends existing `TestHttpTriggerHandler_HandleUserTriggerRequest` in `http_trigger_handler_test.go`):
1. Register two distinct workflows, `workflowA` (attacker-owned) and `workflowB` (victim-owned), each with their own signing key, via `registerWorkflow`.
2. Attacker: build a `jsonrpc.Request` with `ID = "predictable-id"`, `Workflow.WorkflowID = workflowA`, sign with attacker's key, call `handler.HandleUserTriggerRequest` with a mock `callbackAttacker`; assert `require.NoError(t, err)` and that `handler.callbacks["predictable-id"]` exists.
3. Victim: build a second `jsonrpc.Request` with the same `ID = "predictable-id"`, `Workflow.WorkflowID = workflowB`, signed with the victim's own key, call `handler.HandleUserTriggerRequest` with `callbackVictim`.
4. Assert `require.Error(t, err)` and `require.Contains(t, err.Error(), "in-flight request ID")`.
5. Assert via `callbackVictim.Wait(ctx)` that the user error payload has `ErrorCode == api.FromJSONRPCErrorCode(jsonrpc.ErrConflict)`, confirming clean, non-silent failure (no attacker data returned, no silent success) — demonstrating the DoS but ruling out data-confusion impact.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
