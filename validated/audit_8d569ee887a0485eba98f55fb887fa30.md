### Title
`Readyz` health endpoint discloses per-service internal health details to unauthenticated callers regardless of the `full` query parameter's value - ([File: core/web/health_controller.go])

### Summary
The `/readyz` route is registered without any authentication middleware, and `HealthController.Readyz` gates its detailed-checks branch using `c.GetQuery("full")`, which only checks for the presence of the query key rather than its value. Any unauthenticated request such as `GET /readyz?full=false`, `GET /readyz?full=`, or any other value triggers the same detailed disclosure branch as `full=true`.

### Finding Description
`healthRoutes` registers `r.GET("/readyz", hc.Readyz)` directly on the base `api` group in `NewRouter`, which only carries the global rate limiter and session middleware — no `auth.Authenticate` wrapper is applied, unlike `/debug`, `/sessions` (DELETE), and all `/v2` routes which explicitly wrap handlers with `auth.Authenticate(...)`. [1](#0-0) 

Inside `Readyz`, the detail-gating check is:
```go
if _, ok := c.GetQuery("full"); !ok {
    return
}
```
`gin.Context.GetQuery` returns `ok=true` whenever the key exists in the query string, irrespective of its value (empty string, `"false"`, `"0"`, etc. all count as present). This means the check is not a boolean value check — it is purely a "was the key supplied" check. [2](#0-1) 

As a result, once this key-presence check passes, the handler unconditionally builds and returns the full list of per-check statuses/output (`checker.IsReady()` errors), via `jsonAPIResponse(c, checks, "checks")`, with no distinction based on the actual value of `full`. [3](#0-2) 

This contrasts directly with the `PublicReadyz` handler, whose doc comment explicitly states it "never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints" — confirming this is a recognized risk that was mitigated for the public endpoint but not for `Readyz`. [4](#0-3) 

The existing test suite only asserts status codes for `/readyz` without exercising the `full` parameter or the checks payload, and only tests `full=true` against `/public-readyz` for emptiness — it does not verify that non-"true" values of `full` are rejected on `/readyz`. [5](#0-4) 

### Impact Explanation
An unauthenticated attacker with network access to the node's HTTP API can retrieve the full set of internal health check names, pass/fail status, and error output strings (e.g., DB connectivity issues, RPC/chain client errors, service names) by issuing `GET /readyz?full=<any value>`. This maps to Chainlink's "sensitive information disclosure" bounty class — internal service topology and failure details are exposed pre-authentication, which can aid further targeted attacks (e.g., identifying a failing/misconfigured chain client or DB to target).

### Likelihood Explanation
No preconditions or credentials are required — this is a single unauthenticated GET request to a route with zero auth middleware in front of it. It is trivially and repeatably reproducible against any deployed node exposing the health endpoint publicly.

### Recommendation
Fix the value check to only trigger detailed output on an actual truthy value, e.g. `if v, _ := c.GetQuery("full"); v == "true" { ... }`, and additionally consider requiring authentication (or restricting this route to internal/private networks) for the detailed-check branch, mirroring the `PublicReadyz` design intent.

### Proof of Concept
```go
func TestHealthController_Readyz_FullParamValueAgnostic(t *testing.T) {
    t.Parallel()
    app := cltest.NewApplicationWithKey(t)
    healthChecker := new(mocks.Checker)
    healthChecker.On("Start").Return(nil).Once()
    healthChecker.On("IsReady").Return(false, map[string]error{"chk": errors.New("boom")})
    healthChecker.On("Close").Return(nil).Once()
    app.HealthChecker = healthChecker
    require.NoError(t, app.Start(t.Context()))

    client := app.NewHTTPClient(nil) // unauthenticated client

    for _, v := range []string{"true", "false", "", "0", "anything"} {
        resp, cleanup := client.Get("/readyz?full=" + v)
        t.Cleanup(cleanup)
        body, _ := io.ReadAll(resp.Body)
        assert.Contains(t, string(body), "\"checks\"") // detailed output leaked for every value
    }

    // baseline: omitting the key entirely should return no body
    resp, cleanup := client.Get("/readyz")
    t.Cleanup(cleanup)
    body, _ := io.ReadAll(resp.Body)
    assert.Empty(t, body)
}
```
Expected: all `full=<value>` variants (including `false`) return the identical detailed `checks` JSON array as `full=true`, while omitting `full` returns an empty body — confirming both the value-agnostic bug and the total absence of authentication on this route.

// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}

func TestHealthController_Readyz(t *testing.T) {
	t.Parallel()
	var tt = []struct {
		name   string
		ready  bool
		status int
	}{
		{
			name:   "not ready",
			ready:  false,
			status: http.StatusServiceUnavailable,
		},
		{
			name:   "ready",
			ready:  true,
			status: http.StatusOK,
		},
	}
	for _, tc := range tt {
		t.Run(tc.name, func(t *testing.T) {
			t.Parallel()
			app := cltest.NewApplicationWithKey(t)
			healthChecker := new(mocks.Checker)
			healthChecker.On("Start").Return(nil).Once()
			healthChecker.On("IsReady").Return(tc.ready, nil).Once()
			healthChecker.On("Close").Return(nil).Once()

			app.HealthChecker = healthChecker
			require.NoError(t, app.Start(t.Context()))

			client := app.NewHTTPClient(nil)
			resp, cleanup := client.Get("/readyz")
			t.Cleanup(cleanup)
			assert.Equal(t, tc.status, resp.StatusCode)
		})
	}
}
