## Title
Unvalidated `parameters` field length in `createDstEscrow` permanently breaks `EscrowDst` withdrawal, freezing swap funds until rescue delay - (File: contracts/BaseEscrowFactory.sol)

### Summary
The seed report describes a bug in which an unvalidated, attacker/user-suppliable payload (`multihopCell`) is accepted without a format check, is later parsed by a downstream contract that assumes a fixed layout, and causes a cell-underflow panic that permanently locks the associated funds. The same root cause — accepting an arbitrary-length, unvalidated byte blob at fund-locking time and unconditionally parsing it with fixed offsets during withdrawal — exists in this repository's `createDstEscrow` / `EscrowDst._withdraw` flow via the `Immutables.parameters` field.

### Finding Description
`createDstEscrow` in `BaseEscrowFactory` accepts a caller-supplied `IBaseEscrow.Immutables` struct (`dstImmutables`), including an arbitrary `bytes parameters` field, and deploys+funds an `EscrowDst` clone without validating the byte-length or structure of `parameters`: [1](#0-0) 

The only checks performed are on `msg.value`/token transfer amounts and the timelock ordering — the `parameters` bytes are copied verbatim into the salt/hash used for the CREATE2 deployment and stored in the escrow, with no length or format check: [2](#0-1) 

Later, `EscrowDst._withdraw` — the only normal path to complete the swap — unconditionally parses this field with fixed byte offsets via `integratorFeeAmountCd()` and `protocolFeeAmountCd()`: [3](#0-2) 

Both accessors revert with `IndexOutOfRange` if `parameters.length` is smaller than the expected fixed size (`0x40`/`0x20` bytes respectively): [4](#0-3) 

Because `withdraw`/`publicWithdraw` both route through `_withdraw` and this parsing happens unconditionally (not only when a fee is actually non-zero), any `dstImmutables.parameters` shorter than `0x40` bytes (e.g., empty bytes, as produced by naive/incorrect off-chain tooling) makes it **impossible to ever successfully call `withdraw`** on that specific escrow, since the same immutables (including the malformed `parameters`) must be replayed and matched via `onlyValidImmutables`/`immutables.hash()`: [5](#0-4) 

This exactly mirrors the seed bug: an unvalidated payload accepted at fund-locking time, parsed with fixed offsets downstream, causing an underflow/out-of-range revert that blocks the fund-release path.

The only recovery path is `rescueFunds`, callable solely by `immutables.taker` after `RESCUE_DELAY`, which bypasses the `parameters` parsing entirely: [6](#0-5) 

Since `cancel` also does not touch `parameters` (only `withdraw` does), the destination funds are stuck for the entire private/public withdrawal and private cancellation windows, and only become retrievable — by the taker, not the maker — once `RESCUE_DELAY` elapses. In the interim, the maker's corresponding source-chain funds in `EscrowSrc` also cannot be released via the intended secret-reveal path, because that reveal is meant to occur through the `EscrowDst.withdraw` call, which always reverts.

### Impact Explanation
This fits the bounty's High category: "temporary freezing of funds during the live swap lifecycle." `createDstEscrow` has no access control restricting who can call it or what `parameters` it accepts, so any unprivileged actor (the resolver/taker performing the swap, matching the seed report's "Alice mistakenly builds a malformed cell" scenario) can lock the destination-side funds into a state where the entire intended withdrawal mechanism (`withdraw`/`publicWithdraw`) is permanently non-functional for that escrow instance until `RESCUE_DELAY` passes — and even then, recovery is limited to the `taker`, not the maker who was supposed to receive the destination funds.

### Likelihood Explanation
Likelihood is meaningful because `parameters` is a raw, unstructured `bytes` field that must be constructed correctly off-chain (mirroring the `DstImmutablesComplement.parameters` emitted from the source-chain `SrcEscrowCreated` event) with no on-chain schema enforcement, and any deviation (e.g., a resolver/integration bug, or a shortened/empty payload) is silently accepted by `createDstEscrow` and only surfaces as a revert during the subsequent, time-sensitive withdrawal.

### Recommendation
In `createDstEscrow` (`contracts/BaseEscrowFactory.sol`), validate that `dstImmutables.parameters` either is empty (skip fee logic) or has the exact expected length/format (`0x80` bytes, matching `abi.encode(protocolFeeAmount, integratorFeeAmount, protocolFeeRecipient, integratorFeeRecipient)`) before deploying/funding the escrow, reverting the creation transaction rather than allowing a malformed value to be locked in. Additionally, consider making the `parameters` length check in `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd` tolerant (e.g., treat `parameters.length == 0` as "no fees") for the case where a caller intentionally supplies no fee metadata, so accidental short payloads don't collide with the "no fee" case.

### Proof of Concept
1. A resolver calls `createDstEscrow(dstImmutables, srcCancellationTimestamp)` with `dstImmutables.parameters = ""` (or any bytes shorter than `0x40`), paying the correct `msg.value`/ERC20 amount. The call succeeds: `BaseEscrowFactory.createDstEscrow` (contracts/BaseEscrowFactory.sol:165-185) deploys and funds `EscrowDst` with no check on `parameters`.
2. Once the withdrawal window opens, the resolver calls `withdraw(secret, dstImmutables)` on the deployed `EscrowDst`. `_withdraw` (contracts/EscrowDst.sol:79-96) calls `immutables.integratorFeeAmountCd()`, which reverts with `IndexOutOfRange` (contracts/libraries/ImmutablesLib.sol:89-95) because `parameters.length < 0x40`.
3. Every subsequent call to `withdraw`/`publicWithdraw` with the same `dstImmutables` reverts identically — the funds cannot be released to the maker through the normal path.
4. Only after `RESCUE_DELAY` elapses can `rescueFunds` (contracts/BaseEscrow.sol:71-79) be called, and only by `immutables.taker`, recovering the tokens to the taker instead of completing the swap to the maker.

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    /**
     * @notice Returns the integrator fee amount from the immutables (calldata version).

     * @return ret The integrator fee amount.

    function integratorFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
```

```text
    function hash(IBaseEscrow.Immutables calldata immutables) internal pure returns(bytes32 ret) {
        // Compute the EIP-712 hash for the immutables struct
        bytes calldata parameters = immutables.parameters;
        assembly ("memory-safe") {
            let ptr := mload(0x40)

            // Copy immutables.parameters to memory and compute its hash
            calldatacopy(ptr, parameters.offset, parameters.length)
            let parametersHash := keccak256(ptr, parameters.length)

            // Copy the immutables struct to memory, patch `parameters` and compute its hash
            calldatacopy(ptr, immutables, IMMUTABLES_SIZE)
            mstore(add(ptr, IMMUTABLES_LAST_WORD), parametersHash)
            ret := keccak256(ptr, IMMUTABLES_SIZE)
        }
    }
```

```text
    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
```
