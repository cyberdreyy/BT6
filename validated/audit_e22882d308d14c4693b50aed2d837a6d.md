Confirmed: the `ActivationRegistry` precompile explicitly guards against a zero-address caller matching a zero admin (`authorized_admin` in `crates/common/precompiles/src/activation/storage.rs:224-234` rejects when `caller.is_zero()` even before comparing to `admin`), specifically because deposit transactions on Base can execute with `msg.sender == Address::ZERO` on a misconfigured chain. `PolicyRegistryV1::require_admin` (`crates/common/precompiles/src/policy/logic/v1.rs:80-91`) has no equivalent zero-caller guard — it only checks `packed.admin() != caller`.

### Title
Renounced PolicyRegistry admin can be reclaimed by a zero-address deposit-tx caller - (File: crates/common/precompiles/src/policy/logic/v1.rs)

### Summary
`PolicyRegistryV1::renounce_admin` sets a policy's stored admin to `Address::ZERO` to "permanently relinquish" admin control [1](#0-0) . However, `require_admin`, the gate used by every admin-only operation (`stage_update_admin`, `finalize_update_admin`, `renounce_admin`, and via `update_membership` the `update_allowlist`/`update_blocklist` entry points), only checks `packed.admin() != caller` [2](#0-1) . It never rejects `caller == Address::ZERO`, unlike the sibling `ActivationRegistry` precompile, which explicitly special-cases this in `authorized_admin` because "a zero-address caller must be rejected even when the admin is also configured as `Address::ZERO` ... This prevents deposit transactions with `msg.sender == Address::ZERO` from toggling activation state" [3](#0-2) .

### Finding Description
Once a policy's admin is renounced (set to `Address::ZERO`), `require_admin` compares `packed.admin() == Address::ZERO` against `storage.caller()`. If a transaction ever reaches the `PolicyRegistry` precompile with `msg.sender == Address::ZERO` — the exact scenario the activation-registry code explicitly guards against for deposit transactions on a misconfigured chain — the equality check `packed.admin() != caller` evaluates false, and `require_admin` incorrectly returns success, treating the zero-address caller as the legitimate admin of a policy that was supposed to be permanently un-owned [4](#0-3) . This mirrors the reported bug class: an address(0) is implicitly accepted/treated as a valid privileged identity where the code's own documented invariant ("permanently relinquishes admin") assumes it cannot be.

### Impact Explanation
A "permanently relinquished" policy (admin == zero) is supposed to be frozen forever with no further mutation. If a zero-address caller can pass `require_admin`, it could call `update_allowlist`/`update_blocklist` to add or remove members from that policy, or `stage_update_admin`/`finalize_update_admin` to re-assign the policy to an attacker-controlled address, fully reversing the renouncement. Since policies gate B20 token transfer authorization, this is a concrete unauthorized-operation vector that undermines an intended freeze/immutability guarantee.

### Likelihood Explanation
This is gated behind the precondition established elsewhere in the same codebase (activation registry comment/tests) that deposit transactions can have `msg.sender == Address::ZERO` on a misconfigured chain. The `PolicyRegistry`'s `require_admin` codepath, unlike `ActivationRegistry`'s `authorized_admin`, does not defend against this precondition, so the bug is real given that reachable state, but I could not fully verify within available context whether the deposit-transaction path that produces `msg.sender == Address::ZERO` is reachable in a correctly configured production Base chain versus only a "misconfigured" one as the activation-registry comment states. This uncertainty affects the likelihood.

### Recommendation
Add an explicit zero-caller rejection to `PolicyRegistryV1::require_admin` (and any V2 equivalent) mirroring `ActivationRegistryStorage::authorized_admin`'s pattern: reject when `storage.caller().is_zero()` before comparing to `packed.admin()`, so a renounced (admin == zero) policy can never be re-claimed by a zero-address caller.

### Proof of Concept
1. Create a custom policy with `admin = ADMIN` via `create_policy`.
2. `ADMIN` calls `renounce_admin(policy_id)`, setting the stored admin to `Address::ZERO` [1](#0-0) .
3. A transaction reaches the precompile with `storage.caller() == Address::ZERO` (the same precondition the `ActivationRegistry` code defends against for deposit transactions, per its comment at `crates/common/precompiles/src/activation/storage.rs:694-696`).
4. That zero-address caller invokes `update_allowlist`/`update_blocklist`/`stage_update_admin` on the renounced policy; `require_admin` computes `packed.admin() (== Address::ZERO) != caller (== Address::ZERO)` as `false`, so the call is authorized as admin despite the policy having been renounced.

    /// Validates the policy exists and the caller is its current admin.
    /// Returns `(packed, caller)` on success.
    fn require_admin<S: PolicyAccounting>(
        &self,
        storage: &S,
        policy_id: u64,
    ) -> Result<(PackedPolicy, Address)> {
        let packed = self.require_custom(storage, policy_id)?;
        let caller = storage.caller();
        if packed.admin() != caller {
            return Err(BasePrecompileError::revert(IPolicyRegistry::Unauthorized {}));
        }
        Ok((packed, caller))
    }

    fn renounce_admin(&self, storage: &mut S, policy_id: u64) -> Result<()> {
        let (packed, caller) = self.require_admin(storage, policy_id)?;
        storage.write_policy_word(policy_id, packed.with_admin(Address::ZERO).into_u256())?;
        storage.delete_pending_admin(policy_id)?;
        storage.emit_event(
            IPolicyRegistry::PolicyAdminUpdated {
                policyId: policy_id,
                previousAdmin: caller,
                newAdmin: Address::ZERO,
            }
            .encode_log_data(),
        )?;
        Ok(())
    }

    /// Returns the effective admin if one is configured and the caller address can be authorized.
    pub fn authorized_admin(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        let caller = self.storage.caller();
        if caller.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller }));
