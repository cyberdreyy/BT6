### Title
Unauthenticated Workflow Trigger via Legacy Gateway Handler Bypasses Allowlist/Rate-Limiting - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The legacy web-API-trigger path in the Gateway's capabilities handler forwards any inbound user message to **every** node in the DON without ever checking that the sender is an authorized/allow-listed caller for that DON, and without any rate limiting. This is explicitly marked with a `// TODO: apply allowlist and rate-limiting here` comment left in production code.

### Finding Description
`HandleLegacyUserMessage` in [1](#0-0)  performs the following steps for every inbound trigger request:
1. Decodes the `TriggerRequestPayload` and validates only structural fields (`Timestamp` non-zero, message not stale).
2. Explicitly skips authorization: [2](#0-1) 
3. Validates the method is `web_api_trigger`.
4. Saves a callback keyed only by `msg.Body.MessageId` and fans the request out to **all** DON members: [3](#0-2) 

Unlike the newer v2 HTTP Trigger Handler, which requires JWT-signed requests to be checked against a per-workflow set of `authorizedKeys` before dispatch (`authorizeRequest` → `workflowMetadataHandler.Authorize`) as seen in [4](#0-3)  and [5](#0-4) , the legacy `handler.go` code path has no equivalent ownership/allowlist check. Any caller who can reach this handler's `web_api_trigger` method can cause the DON's capability nodes to receive and process a trigger message, which can initiate workflow execution on the DON — the same class of issue as the Napier bug, where an unprivileged actor can force an action (there: PT/YT issuance against another party's unclaimed yield; here: forwarding/dispatching a trigger to a DON's nodes) that should require authorization/consent from the resource owner (the workflow/DON operator), consuming the DON's resources and bypassing any allowlist/quota gate that the design otherwise relies on.

### Impact Explanation
Bypassing the allowlist for the legacy webAPI trigger path means an unauthorized party can force the gateway to relay arbitrary trigger payloads to all DON member nodes, potentially causing unauthorized workflow executions, consuming node processing capacity DON-wide (no rate limit is applied to inbound legacy triggers as it is applied on the v2 path), and using the callback map (`savedCallbacks`) as an amplification/DoS vector since entries are only bounded by time/size-based pruning (`pruneCallbacks`), not per-sender quotas. This maps to the "allowlist or quota bypass" / "unauthorized job run" category called out as acceptable impact.

### Likelihood Explanation
The check is missing unconditionally (not behind a feature flag), and the code path is reachable through the standard `HandleUserMessage`-style dispatch used by the gateway's message routing (`multihandler.go`/`gateway.go`) for any message using `MethodWebAPITrigger` on this handler. I could not fully trace, within the remaining tool budget, the exact unauthenticated HTTP endpoint wiring that reaches this legacy handler versus the v2 handler in the current gateway configuration, so I cannot confirm whether this legacy path is still exposed by default or has been superseded/disabled in favor of the v2 `httpTriggerHandler`. This is a material open question that should be verified before treating this as exploitable in the current deployment.

### Recommendation
- Implement the allowlist/rate-limiting check called out by the TODO before saving the callback and fanning the message out to DON members, mirroring the v2 `authorizeRequest`/`checkRateLimit` pattern.
- If the legacy handler is deprecated/unused in current gateway configurations, remove it entirely rather than leaving an unauthenticated code path in the codebase.
- Add per-sender/per-DON rate limiting for `HandleLegacyUserMessage` matching `checkRateLimit` in the v2 handler.

### Proof of Concept
Not independently verified end-to-end due to the ask-only/read-only nature of this investigation and the inability to confirm current routing/exposure of the legacy handler; the concrete gap is the absence of the authorization check at [2](#0-1)  combined with the unconditional fan-out at [6](#0-5) , contrasted with the guarded v2 equivalent at [4](#0-3) .

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}

		return err
	}

	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

		return err

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
