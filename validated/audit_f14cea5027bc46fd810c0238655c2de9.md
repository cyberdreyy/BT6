`update_reward_cycle` in `stacks-signer/src/monitoring/mod.rs` is a trivial Prometheus metrics setter — it just sets a gauge value (`CURRENT_REWARD_CYCLE.set(reward_cycle)`) or is a no-op when the `monitoring_prom` feature is disabled. [1](#0-0) [2](#0-1) 

It has no cache, no block-id key, no equivocation record, no BlockResponse aggregation, and no interaction with block validation at all. It is called only from the monitoring server's periodic `update_metrics` polling loop, which fetches `pox_info.reward_cycle_id` directly from the node's own RPC response and forwards it to a metrics gauge — there is no attacker-controlled input path here, no BlockProposal handling, no signer/StackerDB message handling.
