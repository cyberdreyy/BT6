### Title
Timestamp freshness check only rejects stale messages, never future-dated ones, allowing pre-signed messages to be replayed far beyond the intended expiry window - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` validates `payload.Timestamp` with `uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp)`, which only fires when the timestamp is too old. [1](#0-0)  A message with `Timestamp` set arbitrarily far in the future always satisfies `now - maxAge <= timestamp`, so the staleness check never rejects it, and no other check in this legacy code path bounds the timestamp from above or otherwise prevents reuse of the same signed message.

### Finding Description
`HandleLegacyUserMessage` decodes `webapicap.TriggerRequestPayload` from `msg.Body.Payload`, checks that `Timestamp != 0`, then performs the one-sided freshness check. [2](#0-1)  The check compares `now - MaxAllowedMessageAgeSec` against `payload.Timestamp` and rejects only when the message is older than the allowed window; it never checks `payload.Timestamp > now (+ some clock-skew bound)`. Consequently, an attacker who can produce one validly-signed message can set `Timestamp` to, e.g., `now + 10 years`, and that message will pass the freshness gate indefinitely into the future — it can be submitted (or resubmitted) at any later date and will never be rejected as stale.

Beyond the timestamp gate itself, this legacy handler path has no per-message replay/dedup protection: `savedCallbacks[msg.Body.MessageId]` is only used to route the eventual response back to the caller and is unconditionally overwritten on each call, unlike the v2 handlers (`v2/http_trigger_handler.go`, `confidentialrelay/handler.go`, `vault/handler.go`) which explicitly reject duplicate/already-seen request IDs or JWT `jti` values via in-flight tracking or a `RequestReplayGuard`. [3](#0-2)  Since `HandleLegacyUserMessage` provides no such guard, a future-dated pre-signed message can be resubmitted repeatedly and processed each time as long as the (now unbounded) freshness check keeps passing.

### Impact Explanation
This defeats the intended request-expiry/freshness guarantee for capability-triggering messages (`MethodWebAPITrigger`) submitted through the legacy gateway handler. An attacker holding one valid signature can stockpile a pre-signed, far-future-dated `TriggerRequestPayload` and replay it at will, well beyond any operator-intended freshness window, to repeatedly trigger `handleWebAPITriggerMessage`/DON dispatch (`don.SendToNode` fan-out to all DON members). [4](#0-3)  This is a request-binding/freshness bypass enabling unauthorized repeated triggering of capability workflows, matching an "unauthorized job/run trigger" style impact rather than a full authentication bypass, since a legitimately-signed message is still required.

### Likelihood Explanation
Exploitation requires only that the attacker possess any key capable of producing a signature accepted by `common.ValidatedRequestFromMessage`/the DON-side verification for this method — no operator/admin access is needed. Once such a signed message with an inflated future `Timestamp` exists, it can be submitted at any point after signing and is deterministically accepted by this check every time, making the bug easily and repeatably exploitable with a trivial precondition (one valid signature).

### Recommendation
Add an upper-bound (future-skew) check alongside the existing staleness check, e.g.:
```go
now := uint(time.Now().Unix())
if now < uint(payload.Timestamp) - maxClockSkewSec || now - h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
    // reject as stale/invalid timestamp
}
```
Reject any message whose `Timestamp` is more than a small, configurable clock-skew allowance ahead of `time.Now()`. Additionally, consider adding replay protection (e.g., a seen-message-ID/digest cache similar to `RequestReplayGuard` used elsewhere) to this legacy handler so that even a validly-timestamped message cannot be resubmitted multiple times.

### Proof of Concept
Add a table-driven test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `webapicap.TriggerRequestPayload` with `Timestamp = time.Now().Unix() + 10*365*24*3600` (10 years in the future), sign/wrap it into an `api.Message` as done in existing tests for `HandleLegacyUserMessage`.
2. Call `handler.HandleLegacyUserMessage(ctx, msg, callback)` with a `HandlerConfig.MaxAllowedMessageAgeSec` set to a small value (e.g., 120).
3. Assert that the current code does NOT reject it (`don.SendToNode` is called, or the callback does not receive a "stale message" error) — demonstrating the flaw.
4. After applying the fix, assert the handler now sends back `ErrorCode: api.HandlerError` with message "stale message" (or a new "invalid timestamp" error) and does not forward the message to `don.SendToNode`.
5. Optionally add a second subtest resubmitting the same future-dated message twice to show it is processed both times, motivating the replay-guard recommendation.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
