### Title
APR0 withdraw receipt permanently reverts `stopEpoch` after APR is raised, freezing all pool funds - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
Analogous to the tickBin-grief report, an unprivileged lender can plant a piece of state (`apr0TotalPrincipal > 0`) that makes a mandatory state-transition function (`stopEpoch` → `prepareStopEpochWithApr0`) revert unconditionally once the honest manager later sets a non-zero APR. Every subsequent `stopEpoch`/`stopEpochWithDuration` — including the close-pool sentinel path — reverts before any borrower settlement, so the epoch can never close and all TVL plus pending receipts stay locked until a privileged recovery sequence is executed.

### Finding Description
When a user calls `IdleCDOEpochVariant.requestWithdraw` during a buffer period while `unscaledApr == 0`, `IdleCreditVault.requestWithdraw` routes the request into `_requestWithdrawApr0`, which increments the global bucket `apr0TotalPrincipal` and records `apr0Users[_user].principalEpoch = epochNumber` [1](#0-0) [2](#0-1) .

At the end of that same epoch the honest manager calls `stopEpochWithDuration(_newApr, ...)`, which settles the epoch and then stores the new APR via `_setScaledApr` → `setAprsWithBuffer`, making `unscaledApr != 0` [3](#0-2) [4](#0-3) . Critically, the APR0 receipt's `apr0TotalPrincipal` is only cleared inside `prepareStopEpochWithApr0` at the *next* `stopEpoch` (line 540) — it is not cleared by the stop that sets the new APR, and `_settleApr0`/user claims cannot decrement it either [5](#0-4) .

On the next `stopEpoch`, `prepareStopEpochWithApr0` hits:

```solidity
uint256 _principal = apr0TotalPrincipal;
if (_principal == 0) { return ...; }
if (unscaledApr != 0) { revert NotAllowed(); }   // L506-508 — unreached-zero bucket + nonzero APR
``` [6](#0-5) 

This call sits at `IdleCDOEpochVariant._stopEpoch` line 362, *outside* the `try/catch` that handles borrower default, so the revert propagates and the epoch stays `isEpochRunning = true` forever [7](#0-6) . There is no user-side or manager-side parameter combination that avoids the check: `_interest == 1` close-pool, `_interest == 0` expected-interest, and override paths all call `prepareStopEpochWithApr0` unconditionally, and no `stopEpochWithDuration` argument resets `apr0TotalPrincipal` or `unscaledApr`.

### Impact Explanation
Permanent freezing of the entire pool's funds as a pure grief:

- `stopEpoch` can never succeed while `apr0TotalPrincipal != 0 && unscaledApr != 0`, so the epoch remains `isEpochRunning = true` indefinitely. Because `startEpoch` called `_pause()`, deposits and all withdrawal *requests* stay disabled for the duration [8](#0-7) .
- `claimWithdrawRequest` is blocked for every user since `epochNumber <= lastWithdrawRequest[user]` can never advance without a successful `stopEpoch` [9](#0-8) .
- Even the close-pool recall (`stopEpoch(0, 1)`) reverts, so principal cannot be recovered through the intended winding-down path; quantified exposure is the full `getContractValue()` plus `pendingWithdraws`.

Recovery exists only via a privileged sequence outside the normal flow: the manager must call `IdleCreditVault.setAprs(0, 0)` to zero `unscaledApr`, run a `stopEpoch` under APR 0 so `prepareStopEpochWithApr0` finally clears the bucket (line 540), and only then restore the APR — analogous to the original report where an upgrade/manager action was needed to unbrick the pool. This qualifies as temporary freezing of all funds plus theft-equivalent blocking of the APR0 user's matured receipt, not mere gas/DoS noise.

### Likelihood Explanation
Cheap and deterministic for any KYC-passed lender:

1. During any buffer period where `unscaledApr == 0` (a supported operating mode — the APR0 flow and its tests exist precisely for this), deposit 1 wei of underlying via `depositAA`/`depositBB` and call `requestWithdraw(1 wei, tranche)`. This sets `apr0TotalPrincipal = 1` and `principalEpoch = epochNumber` at near-zero cost.
2. Wait for the honest manager's routine `stopEpochWithDuration(newApr, ...)` which sets `unscaledApr != 0`. No attacker influence over privileged calls is needed — the manager raises the APR as part of normal operations.
3. Every subsequent `stopEpoch` reverts with `NotAllowed`.

No existing guard stops it: the `lossRecoveryPrice` guard in `requestWithdraw` is unrelated, `_skimDonatedAssets` doesn't touch the bucket, and the revert occurs before the borrower default `try/catch`, so even default handling cannot trigger.

### Recommendation
Move the `unscaledApr != 0` revert out of the mandatory settlement path, or settle/stale-close the APR0 bucket independently of the current APR. Concretely: in `prepareStopEpochWithApr0`, when `unscaledApr != 0` and `apr0TotalPrincipal != 0`, settle the stranded principal with zero APR0 interest (move it into `pendingWithdraws`/per-user settled principal and clear `apr0TotalPrincipal`) rather than reverting. Alternatively, snapshot the APR that applied at request time (`principalEpoch`) instead of reading the live `unscaledApr`, so a later APR change cannot invalidate an in-flight receipt.

### Proof of Concept
Foundry test extending the existing `IdleCreditVault.t.sol` harness (`test/foundry/IdleCreditVault.t.sol`), which already exposes `_startEpochAndCheckPrices`, `_stopEpochAndCheckPrices`, `_forceLastEpochAprToZero` and a `borrower` funded via `deal` [10](#0-9) :

```solidity
function testApr0BucketGriefsStopEpoch() external {
    uint256 amount = 10_000 * ONE_SCALE;
    uint256 mintedAA = idleCDO.depositAA(amount);

    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // make this an APR0 epoch and place a dust APR0 withdraw request
    _forceLastEpochAprToZero(); // in prod: manager legitimately ran an apr0 epoch
    cdoEpoch.requestWithdraw(1, address(AAtranche)); // attacker: 1 wei
    assertEq(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 1);

    // honest manager runs the next epoch and raises APR as usual
    _startEpochAndCheckPrices(1); // startEpoch uses apr set by prior stop; simulate raise:
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(initialProvidedApr, 0); // unscaledApr != 0

    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, type(uint128).max);

    // every stopEpoch variant reverts forever -> epoch cannot close, funds frozen
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 1); // even close-pool recall is bricked

    assertTrue(cdoEpoch.isEpochRunning());
    assertEq(cdoEpoch.defaulted(), false); // default catch never reached
}
```

Note on uncertainty: I could not re-verify the exact gating in `IdleCDOEpochVariant.requestWithdraw` for whether the attacker request must land in the buffer vs. a running epoch, and `setAprs` manager-only access is inferred from existing tests (`test/foundry/IdleCreditVault.t.sol:3165`, `5981` use `vm.prank(manager)`). The core revert chain — `requestWithdraw` setting `apr0TotalPrincipal` under `unscaledApr == 0`, the unconditional `unscaledApr != 0` revert in `prepareStopEpochWithApr0`, and that call sitting outside the default `try/catch` — is directly confirmed in the code above.

  /// @notice settle APR=0 requests for a user once their epoch is finalized
  /// @param _user address of the user
  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
      _apr0User.principalEpoch = epochNumber;
    }
    _apr0User.principal += _amount;
    // Epoch-level APR0 principal used only to compute stopEpoch APR0 pro-rata interest.
    apr0TotalPrincipal += _amount;
  }
