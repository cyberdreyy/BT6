### Title
Unauthenticated Pipeline Run Resume Endpoint Allows Anyone to Inject Task Results and Force Job Run Completion - (File: core/web/pipeline_runs_controller.go)

### Summary
The `PipelineRunsController.Resume` handler, mounted at `PATCH <application>/jobs/:ID/runs/:runID`, accepts a `pipeline.ResumeRequest` body and calls `prc.App.ResumeJobV2(ctx, taskID, result)` with **no session/API-token/role check performed in the handler itself**. The only reference to authentication in the function is the audit log entry name `audit.UnauthedRunResumed`, which explicitly documents that this action is expected to occur without an authenticated session. [2](#0-1) 

### Finding Description
Compare to `PipelineRunsController.Create`, which explicitly checks `auth.GetAuthenticatedUser(c)` before allowing a run to be triggered via an integer job ID. [3](#0-2)  The `Resume` handler performs no equivalent check — it parses `runID` as a UUID (the pipeline task ID), decodes an arbitrary JSON body into `pipeline.ResumeRequest`, and directly resumes the pipeline run with attacker-supplied `result` data. [4](#0-3) 

This is analogous to the reported bug class: a state-mutating function (`AddProposal()` in the external report) that lacks authorization checks and can be invoked directly by any caller, bypassing the intended control flow (voting/access control in the report; authenticated session or a proper capability check here). In this codebase's design, the "secret" that is supposed to gate resumption is the unguessable `runID` UUID (used as a bridge-adapter callback capability token) rather than a session or API key — meaning if an attacker can discover or guess a valid `runID`, they can directly resume/complete a pipeline run and control the task's result value with no authentication at all.

### Impact Explanation
If a `runID` (UUID) is leaked (e.g., via logs, error messages, third-party bridge adapter logs, or a bridge adapter's outbound request), an unauthenticated third party can call this endpoint to inject an arbitrary result and force completion of that specific job run, potentially manipulating oracle/task output data that downstream consumers of the pipeline run depend on. This mirrors the report's core theme — a lack of authorization enabling arbitrary state mutation that should be gated to a trusted actor (the governance module in the report; the specific bridge adapter callback in this codebase).

### Likelihood Explanation
Exploitation requires knowledge of a specific run's UUID `runID`, which is not enumerable and is intended to act as a bearer-style capability token, so this is by design lower likelihood than the original completely-open `AddProposal()`. However, unlike the reported issue, there is no additional secret or signature validation on the resume payload—possession of the UUID alone is sufficient, so any leak of the ID constitutes a full authentication bypass for that run.

### Recommendation
Verify at the very least that this design is intentional and documented; if so, ensure `runID` values are never logged, exposed in error messages, or otherwise leaked, and consider adding an additional shared-secret/HMAC check on the resume payload beyond the UUID itself so that the endpoint is not solely secured by an opaque identifier. Compare and align this behavior with `PipelineRunsController.Create`'s explicit `auth.GetAuthenticatedUser` check pattern.

### Proof of Concept
1. Obtain (or leak) a valid pending `runID` (UUID) for a pipeline task awaiting external resumption.
2. Send `PATCH /v2/jobs/{ID}/runs/{runID}` with a crafted `pipeline.ResumeRequest` JSON body containing an attacker-chosen result.
3. `Resume` calls `prc.App.ResumeJobV2` directly with no authentication check [5](#0-4) , completing the run with attacker-controlled data.

func (prc *PipelineRunsController) Create(c *gin.Context) {
	ctx := c.Request.Context()

		pipelineRun, err := prc.App.PipelineORM().FindRun(ctx, jobRunID)

	// Webhook runs used external job UUIDs; that job type has been removed.

		return
	}

	_, isUser := auth.GetAuthenticatedUser(c)
	// only users are allowed to run jobs using int IDs - EIs not allowed
	if isUser {

		var jobID int32
		jobID64, err := strconv.ParseInt(idStr, 10, 32)

				return
			}

			return
		}

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
