Confirmed: `KaminoInitObligation` also lacks a group account and pause check, matching the same pattern as `DriftInitUser`. This confirms the gap is a systemic pattern across the "init" instructions for all integrations (Drift, Kamino, and likely Solend/Juplend), not a one-off oversight.

### Title
`drift_init_user` (and analogous Kamino/Solend/Juplend init instructions) lack a protocol-pause check, allowing CPI execution and fund movement during an admin-declared pause - ([File: programs/marginfi/src/instructions/drift/init_user.rs])

### Summary
`DriftInitUser` has no `group` account in its `Accounts` struct and never calls `is_protocol_paused()` or `validate_bank_state`, unlike `DriftDeposit` which enforces `!group.load()?.is_protocol_paused()` [1](#0-0) . As a result, any unprivileged caller (`fee_payer`) can invoke `drift_init_user`, which performs multiple Drift CPIs (`initialize_user_stats`, `initialize_user`, token transfer, `deposit`) even while the group admin has paused the protocol via `panic_state_cache` [2](#0-1) . The same pattern (no `group` account, no pause check) exists in `KaminoInitObligation` [3](#0-2) , indicating a systemic gap in the "init" family of integration instructions.

### Finding Description
`drift_deposit` explicitly gates on the group's pause state both via an Anchor `constraint` on the `group` account and via `validate_bank_state(&bank, InstructionKind::FailsIfPausedOrReduceState)` [4](#0-3) [1](#0-0) . `DriftInitUser`'s `Accounts` struct, by contrast, only validates `bank`, `liquidity_vault`, `mint`, `signer_token_account`, and the Drift PDAs — there is no `group` field at all and `is_protocol_paused()`/`validate_bank_state` is never invoked anywhere in `drift_init_user` [5](#0-4) . Consequently, `fee_payer` (any signer holding at least 10 units of the bank's mint) can call `drift_init_user` and successfully execute `cpi_init_user_stats`, `cpi_init_user`, `cpi_transfer_user_to_liquidity_vault`, and `cpi_drift_deposit` regardless of `MarginfiGroup.is_protocol_paused()` being true [6](#0-5) .

### Impact Explanation
This bypasses the pause invariant for CPI execution into an external, potentially compromised or misbehaving integration (Drift) during exactly the window an admin intended to halt all interaction with that integration. Although the deposited funds originate from the caller's own `signer_token_account`, the instruction still forces irreversible on-chain state changes (creation of the bank's Drift `user`/`user_stats` PDAs and an actual `deposit` CPI moving funds into the bank's `liquidity_vault` and then into Drift) that the admin's pause was meant to prevent — this matters if pause was triggered due to a known issue with the Drift market/integration itself. It also breaks the consistency invariant that "pause must halt every user-facing instruction across Drift/Kamino/Solend/Juplend," which the codebase otherwise enforces uniformly on deposit/withdraw paths.

### Likelihood Explanation
The precondition (group paused, bank's Drift user/user_stats not yet initialized) is a normal operational window — e.g., a bank added to the group but not yet fully set up when a pause is triggered, or an admin pausing after add_pool but before init_user is called. Any account holding the minimum 10 units of the bank mint can trigger this permissionlessly and repeatably (once per bank, since Drift PDAs can only be initialized once).

### Recommendation
Add a `group: AccountLoader<'info, MarginfiGroup>` account to `DriftInitUser` (and the analogous `KaminoInitObligation`/Solend/Juplend init structs) with a `has_one = group` on `bank` and an Anchor constraint `!group.load()?.is_protocol_paused() @ MarginfiError::ProtocolPaused`, matching the pattern already used in `DriftDeposit`.

### Proof of Concept
Integration test plan:
1. Set up a `MarginfiGroup`, admin-pause it via the pause instruction (set `panic_state_cache` paused flag with a future expiry).
2. Add a Drift-tagged bank via `add_pool`/`add_bank` (without yet calling `drift_init_user`).
3. As an unprivileged wallet, fund a `signer_token_account` with ≥10 units of the bank mint.
4. Call `drift_init_user(ctx, 10)` with the group still paused.
5. Assert (current behavior) the instruction succeeds — `integration_acc_2`/`integration_acc_3` PDAs get created and the Drift `deposit` CPI executes — documenting the pause bypass. Once the fix (adding `group` + pause constraint) is applied, assert the transaction fails with `MarginfiError::ProtocolPaused`.

pub fn drift_init_user(ctx: Context<DriftInitUser>, amount: u64) -> MarginfiResult {
    let authority_bump: u8;
    let market_index: u16;
    let pool_id: u8;
    {
        let bank = ctx.accounts.bank.load()?;
        authority_bump = bank.liquidity_vault_authority_bump;

        let integration_acc_1 = ctx.accounts.integration_acc_1.load()?;
        market_index = integration_acc_1.market_index;
        pool_id = integration_acc_1.pool_id;
    }

    // Arbitrarily setting minimum deposit to 10 absolute units to always keep the account alive.
    require_gte!(amount, 10, MarginfiError::DriftUserInitDepositInsufficient);

    ctx.accounts.cpi_init_user_stats(authority_bump)?;

    ctx.accounts.cpi_init_user(authority_bump)?;

    ctx.accounts.cpi_transfer_user_to_liquidity_vault(amount)?;

    if pool_id != 0 {
        ctx.accounts
            .cpi_update_user_pool_id(pool_id, authority_bump)?;
    }

    ctx.accounts
        .cpi_drift_deposit(amount, market_index, authority_bump)?;

    /// Returns true if the protocol is in a paused state and the time has not yet expired, false it
    /// not paused or timer has expired.
    fn is_protocol_paused(&self) -> bool {
        // Note: In rare event clock fails to unwrap, time = 0 always fails the is_expired check.
        let current_timestamp = Clock::get().map(|c| c.unix_timestamp).unwrap_or(0);

        self.panic_state_cache.is_paused_flag()
            && !self.panic_state_cache.is_expired(current_timestamp)
    }
