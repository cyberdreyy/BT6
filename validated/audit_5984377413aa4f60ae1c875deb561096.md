### Title
Unauthenticated ERC4626 spot valuation is trusted for epoch interest and stop-epoch solvency - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` prices epoch PnL and decides whether a stop-epoch shortfall is covered from `vault.convertToAssets(shares)` at the current block, i.e. a spot value controlled by the external ERC4626’s immediate state rather than realized withdrawals. A permissionless user of that vault can move share price/liquidity around `startEpoch`/`stopEpoch`, causing `totalInterestDueNow()` to report phantom interest or causing `onStopEpoch` to misclassify a covered shortfall as uncovered. The broken invariant is fair mint/burn and solvency: IdleCDO consumes an interest value and a coverage decision that are not backed by funds actually pulled from the vault. [1](#0-0) [2](#0-1) 

### Finding Description
The external advisory’s bug class is “trust an integrity-unprotected source for what code/assets you accept.” The closest credit-vault analog is `ProgrammableBorrower` trusting the external ERC4626’s spot conversion as an accounting oracle. `_vaultNetInterest` computes `earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault` against `principalAssets = epochStartVaultAssets + epochDepositedToVault`, so any transient increase in `convertToAssets` becomes `interest`; any transient decrease becomes `loss`. [3](#0-2) 

`totalInterestDueNow()` is the pool-facing value consumed by IdleCDO before the stop flow, and it directly includes that vault-interest leg plus borrower interest and buffer interest. `onStopEpoch` then uses the same spot `_currentVaultAssets()` to decide whether to attempt `vault.withdraw(shortfall)` or to return early and let the later `transferFrom` fail into default handling. No guard bounds `convertToAssets` against realized assets, compares it to a TWAP/reference price, or requires that reported “interest” be withdrawn before it is credited. [4](#0-3) [5](#0-4) [6](#0-5) 

### Impact Explanation
During a running programmable epoch, an attacker who is only a user of the ERC4626 vault can move the vault’s exchange rate/liquidity and corrupt the single value IdleCDO reads at stop. Inflation case: `totalInterestDueNow()` is overstated by the manipulated delta, so the epoch is priced with phantom yield and tranche holders/feeReceiver are credited value not actually recovered from the vault; after the attacker unwinds the price move, the pool has a backing hole approximately equal to the fake delta. Deflation case: `shortfall > _currentVaultAssets()` returns success without attempting withdrawal, so the CDO’s `transferFrom` can fail and be treated as default even though the vault position was economically redeemable once the manipulation is removed. Example: for a 10,000,000 underlying sleeve, a 1% move in `convertToAssets` creates or hides 100,000 of epoch PnL; repeated epochs turn this into a quantifiable transfer to early-exiting tranche holders or an unjustified BB-first default loss. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
The required actor is unprivileged: any address that can use the same ERC4626 vault or move its observed rate can do this, and the code explicitly exposes `vaultInterestAccrued`, `vaultLoss`, `totalInterestDueNow`, and `availableToBorrow` from live `convertToAssets` readings. The honest borrower does not need to cooperate; the manipulation targets the valuation channel, not borrower permissions. Existing guards do not stop it: `setVault` only checks `asset()`, `onStartEpoch` snapshots baselines from the same spot value, `onStopEpoch` accepts `shortfall <= _currentVaultAssets()` as coverability, and default handling still relies on the failed pull path rather than verifying that reported PnL was realized. [9](#0-8) [10](#0-9) [11](#0-10) 

### Recommendation
Do not use spot `convertToAssets` as epoch PnL or stop-epoch coverability. Track the vault sleeve by realized cash flows: assets deposited, assets actually returned by `vault.withdraw`/`redeem`, and borrower interest settled by `settleBorrowerInterest`; make `totalInterestDueNow` a function of realized/verified deltas plus contractual borrower interest, not a live share-price reading. If a valuation is still needed, bound it by `previewRedeem` after an actual withdraw attempt, a manipulation-resistant oracle/TWAP, and hard deviation limits; otherwise revert instead of crediting interest or forcing default. Add stop-time invariant checks that `_amountRequired` is either on hand or proven by assets received from `vault.withdraw(shortfall)`, and treat an ERC4626 withdrawal failure as liquidity failure only after comparing attempted-withdrawal output to the amount credited upstream.

### Proof of Concept
Foundry fork PoC shape against a deployed `ProgrammableBorrower` and its configured permissionless ERC4626:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IERC20Detailed} from "contracts/interfaces/IERC20Detailed.sol";
import {IERC4626} from "contracts/interfaces/IERC4626.sol";
import {ProgrammableBorrower} from "contracts/strategies/idle/ProgrammableBorrower.sol";

contract SpotVaultPricePoC is Test {
    ProgrammableBorrower pb;
    IERC4626 vault;
    IERC20Detailed asset;
    address idleCDO = address(0xCD0);
    address attacker = address(0xA77);

    function test_spotConvertToAssetsMovesEpochInterest() public {
        // Arrange: start an epoch through the only-idleCDO hook.
        vm.prank(idleCDO);
        pb.onStartEpoch(0);

        uint256 shares = vault.balanceOf(address(pb));
        uint256 beforeAssets = vault.convertToAssets(shares);
        uint256 beforeInterest = pb.totalInterestDueNow();

        // Attacker is only a vault user / direct token sender. Move the ERC4626 spot rate
        // by depositing/withdrawing/donating/using liquidity so convertToAssets changes.
        vm.startPrank(attacker);
        asset.approve(address(vault), type(uint256).max);
        uint256 move = beforeAssets / 100; // 1% reported PnL move
        deal(address(asset), attacker, move);
        asset.transfer(address(vault), move); // or transient rate/liquidity move for vaults where this is removable
        vm.stopPrank();

        uint256 afterInterest = pb.totalInterestDueNow();
        assertGt(afterInterest, beforeInterest);

        // IdleCDO consumes afterInterest at stop while PB only attempts to withdraw the required
        // amount; once the attacker unwinds the rate move, the credited delta is not backed.
        vm.prank(idleCDO);
        pb.onStopEpoch(beforeAssets + move, false);
    }
}
```

The essential assertion is that `totalInterestDueNow()` changes solely because `convertToAssets` moved, while `onStopEpoch` bases the withdrawal/default branch on the same manipulated `_currentVaultAssets()` rather than assets actually received. [5](#0-4) [3](#0-2)

  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
