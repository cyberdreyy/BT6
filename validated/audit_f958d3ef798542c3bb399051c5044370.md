### Title
Zip-slip in ExtractZipArchive allows arbitrary Lchown via unsanitized `file.Name` in `processZipUIDGidField` - (File: helpers/archives/zip_extra.go)

### Summary
`ExtractZipArchive` in `helpers/archives/zip_extract.go` never validates or sanitizes `zip.File.Name` before using it in filesystem operations, and this same unsanitized `file.Name` is passed straight into `os.Lchown` by `processZipUIDGidField` in `helpers/archives/zip_extra_unix.go`. An attacker who controls the zip archive later extracted by the runner (e.g. via cache restore) can embed a crafted `ZipUIDGidFieldType` extra field on an entry whose `Name` traverses outside the intended extraction root (`../`, absolute path), causing the runner to change ownership of an arbitrary file on the host/shared filesystem.

### Finding Description
`ExtractZipArchive` iterates `archive.File` twice: first calling `extractZipFile(file)` (which itself has no path containment — it does `os.MkdirAll(filepath.Dir(file.Name), ...)` and writes to `file.Name` verbatim), then calling `processZipExtra(&file.FileHeader)` for each entry. [1](#0-0) 

The only path check present is `errorIfGitDirectory`, which merely rejects paths whose first cleaned path segment is `.git` — it does nothing to prevent `../` traversal or absolute paths. [2](#0-1) 

`processZipExtra` parses the `Extra` field of the zip header and dispatches `ZipUIDGidFieldType` entries to `processZipUIDGidField`, again keying off the raw `file.Name` from the (unsanitized) `zip.FileHeader`. [3](#0-2) 

`processZipUIDGidField` then calls `os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))` directly, with no `filepath.Clean`/containment check against the extraction root. [4](#0-3) 

Go's standard `archive/zip` package does not sanitize `File.Name` for callers — it is the extractor's responsibility, which is missing here entirely. Since the extraction root is never joined against `file.Name` (no `filepath.Join(root, file.Name)` + boundary check pattern anywhere in `zip_extract.go` or `zip_extra.go`), a crafted entry name such as `../../other-project/cache/file` or an absolute path will cause both the file write step and the subsequent `Lchown` to act outside the intended job/cache directory. `zip_legacy_extractor.go`'s `Extract` method takes a `dir` field but never uses it to constrain paths — it just calls `archives.ExtractZipArchive(zr)` with no root confinement. [5](#0-4) 

### Impact Explanation
On a shared runner filesystem (as stipulated in the precondition — shared cache/checkout paths across jobs), an unprivileged pipeline author who controls a cache archive can cause the runner process to call `os.Lchown` on a path outside their own job tree, altering ownership of files belonging to another project's checkout or cache. This is a concrete file-system integrity/isolation violation: ownership corruption of files the attacker does not own, potentially disrupting or corrupting another job's build state.

### Likelihood Explanation
Exploitability requires: (1) the ability to produce or influence the contents of a cache/artifact zip archive that the runner will later extract (achievable by any job that writes to a shared cache key, or by tampering with an artifact before restore in a shared-storage setup), and (2) the runner's extraction happening in a filesystem context shared with other jobs' data (stated precondition). Given those preconditions, the exploit is fully deterministic and repeatable — crafting a matching `ZipUIDGidFieldType` extra field with a traversal `Name` is straightforward with the standard `archive/zip` writer APIs.

### Recommendation
- Sanitize/validate every `zip.File.Name` once, immediately upon iterating `archive.File` in `ExtractZipArchive`, rejecting or clamping entries whose cleaned, joined path escapes the extraction root (reject absolute paths and any `..` component after `filepath.Clean` relative to root).
- Compute a single canonicalized target path per entry (e.g., `target := filepath.Join(root, file.Name); if !strings.HasPrefix(target, root+string(filepath.Separator)) { reject }`) and use that same validated `target` consistently in `extractZipFile`, `lchmod`, and `processZipExtra`/`processZipUIDGidField`, instead of re-deriving `file.Name` in each function.
- Apply the same containment check to `extractZipSymlinkEntry`'s target rewriting and to `zip_legacy_extractor.go`'s `Extract`, which currently ignores its own `dir` field entirely.

### Proof of Concept
Go unit test outline (add to `helpers/archives/zip_extract_test.go`):
1. Build an in-memory zip via `archive/zip.Writer` containing one entry named `../outside/target.txt` with a body, and set `FileHeader.Extra` to a manually constructed `ZipUIDGidFieldType` (`0x7875`) extra field with `Version=1, UIDSize=4, UID=<attacker-chosen>, GIDSize=4, Gid=<attacker-chosen>`.
2. Create a temp directory `root`, `chdir` into a subdirectory `root/job`, and call `archives.ExtractZipArchive` on the reader.
3. Assert that `root/outside/target.txt` was created/chowned (demonstrating escape from `root/job`), i.e. `os.Lstat("../outside/target.txt")` succeeds and its `Sys().(*syscall.Stat_t).Uid/Gid` match the attacker-supplied values — proving `Lchown` acted outside the intended `root/job` tree.
4. Expected (fixed) behavior: `ExtractZipArchive` should return/skip the entry with an error such as "invalid path" and no file should be created or chowned outside `root/job`.

func processZipExtra(file *zip.FileHeader) error {
	if len(file.Extra) == 0 {
		return nil
	}

	r := bytes.NewReader(file.Extra)
	for {
		field, data, err := readZipExtraField(r)
		if err == io.EOF {
			break
		} else if err != nil {
			return err
		}

		switch field.Type {
		case ZipUIDGidFieldType:
			err = processZipUIDGidField(data, file)
		case ZipTimestampFieldType:
			err = processZipTimestampField(data, file)
		}
		if err != nil {
			return err
		}
	}

	return nil
}
```

func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
```
