### Title
Bank closure permanently locks accrued but uncollected protocol/insurance/group fees - ([File: programs/marginfi/src/instructions/marginfi_group/close_bank.rs])

### Summary
The analog to the `Raises.sol` bug (fee amounts owed to the protocol becoming unretrievable because a state-changing instruction doesn't route them into a claimable balance first) exists in marginfi's `lending_pool_close_bank` instruction. It validates that a bank has zero open positions and zero asset/liability shares before permanently destroying the `Bank` account, but it never checks or accrues `collected_group_fees_outstanding`, `collected_insurance_fees_outstanding`, or `collected_program_fees_outstanding`.

### Finding Description
In marginfi, protocol/group/insurance fees accrue into three fields on the `Bank` account (`collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, `collected_program_fees_outstanding`) as a side effect of `accrue_interest`, as documented in `guides/ADMIN/COLLECTING_FEES.md:47-58`. The tokens backing these outstanding fee amounts sit physically in the bank's `liquidity_vault` PDA until someone calls the permissionless `lending_pool_collect_bank_fees` instruction, which moves them out to `insurance_vault`, `fee_vault`, and the global `fee_ata` [1](#0-0) .

`lending_pool_close_bank` only checks `CLOSE_ENABLED_FLAG`, that `lending_position_count`/`borrowing_position_count` are zero, and that `total_asset_shares`/`total_liability_shares` are zero (via `is_zero_with_tolerance`) and `emissions_remaining` is zero — before dropping the bank and letting Anchor's `close = admin` constraint destroy the `Bank` account [2](#0-1) . It never checks that `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, or `collected_program_fees_outstanding` are zero, and it never invokes `accrue_interest`/`lending_pool_collect_bank_fees` to flush them first.

Because all fee-collection and fee-withdrawal instructions (`LendingPoolCollectBankFees`, `LendingPoolWithdrawFees`, `LendingPoolWithdrawFeesPermissionless`) require an `AccountLoader<'info, Bank>` with `has_one = group` constraints derived from the live `Bank` account data [3](#0-2) [4](#0-3) , once the `Bank` account is closed there is no longer any instruction that can reference the (now-destroyed) bank to authorize a transfer out of its `liquidity_vault`. Any token balance in that vault corresponding to unflushed `collected_*_fees_outstanding` amounts is orphaned in a PDA account whose owner-derivation seeds reference a bank key that no account exists for, since the bump/vault addresses are derived from `LIQUIDITY_VAULT_AUTHORITY_SEED` + `bank.key()`, and every consuming instruction requires loading the live `Bank` struct fields (e.g., `bump = bank.load()?.liquidity_vault_authority_bump`).

This mirrors the `Raises.sol` root cause exactly: a state-transition/closing instruction changes the accounting to a terminal state without first moving the already-accrued protocol fee into a recoverable location, permanently stranding funds that the protocol/insurance/group are owed.

### Impact Explanation
This causes a durable, unrecoverable loss of protocol, insurance, and group fee revenue. Every dollar of `collected_insurance_fees_outstanding` that hasn't yet been swept to the `insurance_vault` is capital that should back socialized losses; permanently losing it degrades the insurance fund's ability to cover future bad debt. The `collected_program_fees_outstanding` and `collected_group_fees_outstanding` amounts represent lost protocol/group revenue. While this requires the specific sequence of a bank winding down to zero shares while having non-trivial uncollected fees, and requires the group admin (or whoever holds `CLOSE_ENABLED_FLAG` closing rights) to execute `lending_pool_close_bank`, it does not require any privilege bypass to trigger the loss — it's a missing invariant check, not an authorization flaw, and the loss is financial and permanent (funds sit unreachable in the vault after account closure) rather than merely delayed.

### Likelihood Explanation
Likelihood is moderate: banks are periodically wound down and closed as part of normal lifecycle management (`guides/ADMIN/BANK_STATE.md:140-151` documents "Closure" as a normal step once positions are zero). Interest accrual runs whenever any user interacts with the bank, so any bank with borrow activity accumulates non-zero `collected_*_fees_outstanding` values continuously; the operator only needs to forget (or simply not know they need) to call the permissionless `lending_pool_collect_bank_fees` before closing. Since `lending_pool_collect_bank_fees` is a separate, easily-forgotten step and `close_bank` performs no automatic accrual/collection nor any guard against non-zero outstanding fees, this is a plausible operational-error trigger rather than a purely theoretical one.

### Recommendation
Before closing the bank, either:
1. Add a check in `lending_pool_close_bank` requiring `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, and `collected_program_fees_outstanding` to be zero (with tolerance), forcing the admin to run `lending_pool_collect_bank_fees` (and downstream `LendingPoolWithdrawFees`) first; or
2. Have `lending_pool_close_bank` itself accrue interest and perform the fee-sweeping logic (moving outstanding fees from `liquidity_vault` into `insurance_vault`/`fee_vault`/`fee_ata`) prior to destroying the `Bank` account, so no value is ever silently stranded.

### Proof of Concept
1. Group admin creates and operationalizes a bank; users deposit and borrow, causing `accrue_interest` to run repeatedly and increment `bank.collected_insurance_fees_outstanding`, `bank.collected_group_fees_outstanding`, and `bank.collected_program_fees_outstanding` (see `programs/marginfi/src/state/bank.rs:578-602`).
2. All borrowers repay and all depositors withdraw so `total_asset_shares` and `total_liability_shares` return to zero and `lending_position_count`/`borrowing_position_count` hit zero — but nobody has yet called `lending_pool_collect_bank_fees`, so the `collected_*_fees_outstanding` fields remain non-zero and their backing tokens remain in `liquidity_vault`.
3. Group admin calls `lending_pool_close_bank`. All of `close_bank.rs`'s checks pass (`CLOSE_ENABLED_FLAG` set, zero positions, zero shares, zero emissions) since none of them inspect the fee-outstanding fields; the `Bank` account is closed and its rent returned to the admin.
4. The `liquidity_vault` token account (and any residual token balance corresponding to the outstanding fees) can no longer be accessed by `LendingPoolCollectBankFees` / `LendingPoolWithdrawFees` / `LendingPoolWithdrawFeesPermissionless`, since all of them require loading the now-nonexistent `Bank` account to derive/validate the vault authority PDA and bump — the fee tokens are permanently stranded.

Note: I was not able to run this scenario end-to-end (no execution environment available in this ask-only session), so this is a static-analysis-based determination from `close_bank.rs`, `collect_bank_fees.rs`, and `bank.rs`; I recommend validating the exact PDA/token-account fate (whether the vault SOL/token balance becomes truly unrecoverable versus reclaimable via some other admin path not found in my search) with a live/bankrun test before treating this as fully confirmed.

pub fn lending_pool_close_bank(ctx: Context<LendingPoolCloseBank>) -> MarginfiResult {
    let mut group = ctx.accounts.group.load_mut()?;
    // Note: Groups created prior to 0.1.2 have a non-authoritative count here, so subtraction
    // without saturation could reduce the count below zero.
    group.banks = group.banks.saturating_sub(1);

    let bank = ctx.accounts.bank.load()?;

    // banks created prior to 0.1.4 can never be closed because we cannot guarantee an accurate
    // position count for those banks.
    check!(
        bank.get_flag(CLOSE_ENABLED_FLAG),
        MarginfiError::BankCannotClose,
        "Only banks created in 0.1.4 and later can close"
    );
    check!(
        bank.lending_position_count == 0 && bank.borrowing_position_count == 0,
        MarginfiError::BankCannotClose,
        "Only banks with no open positions can close"
    );
    check!(
        I80F48::from(bank.total_asset_shares).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
            && I80F48::from(bank.total_liability_shares)
                .is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
        MarginfiError::BankCannotClose
    );
    check!(
        I80F48::from(bank.emissions_remaining).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
        MarginfiError::BankCannotClose
    );

    drop(bank);

    // Bank will now be closed by anchor

    Ok(())
}
