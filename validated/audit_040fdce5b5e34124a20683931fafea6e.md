### Title
Absence of Absolute Recency Check in MetaOracle Price Aggregation Allows Stale Prices to Pass Validation - (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

### Summary

The `meta_oracle` module in the Sui oracle framework performs a relative timestamp window check anchored to oracle data timestamps rather than the current blockchain time (`Clock`). If all contributing oracles are stale, the relative check still passes, allowing arbitrarily old prices to be accepted as valid.

### Finding Description

In `add_simple_oracle`, `max_timestamp` is overwritten with each oracle's data timestamp as oracles are added: [1](#0-0) 

After all oracles are added, `max_timestamp` holds the timestamp of the **last oracle added** (not the current wall-clock time, and not even the true maximum across all oracles — it is simply overwritten on each call).

In `combine()`, the staleness filter is: [2](#0-1) 

`min_timestamp = max_timestamp - time_window_ms` is computed entirely from oracle-supplied data. No `Clock` object is ever passed to `combine()` or `median()`. If all oracles stopped updating one hour ago, `max_timestamp` is one hour old, `min_timestamp` is one hour and `time_window_ms` ago, and every oracle's data still passes `data::timestamp(&oracle_data) > min_timestamp` — because they are all within the relative window of each other.

The underlying `get_latest_data` in `simple_oracle` also performs no staleness check: [3](#0-2) 

It returns whatever is stored, regardless of age. The `StoredData` struct does carry a `timestamp` field: [4](#0-3) 

but it is never compared against the current `Clock` time in the aggregation path.

### Impact Explanation

Any on-chain protocol that calls `meta_oracle::median()` or `meta_oracle::add_simple_oracle()` to price assets, compute collateral ratios, or trigger liquidations can be fed prices that are hours or days old. An attacker who observes that oracle operators have stopped updating (e.g., due to downtime) can exploit the divergence between the stale on-chain price and the real market price to:

- Borrow against overvalued collateral using a stale high price.
- Avoid liquidation using a stale favorable price.
- Arbitrage any protocol that settles at the stale price.

This matches the "harmful smart-contract behavior" impact class (High/Medium).

### Likelihood Explanation

Oracle liveness failures are a known operational risk. The `SimpleOracle` is a shared object updated by a permissioned operator address: [5](#0-4) 

If the operator's key is compromised, the operator goes offline, or the off-chain data pipeline fails, updates stop. The on-chain contract has no mechanism to detect this because it never compares stored timestamps against the current `Clock`.

### Recommendation

Pass a `&Clock` reference into `combine()` (and by extension `median()`) and enforce an absolute maximum age:

```move
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, clock: &Clock): (vector<T>, vector<address>) {
    let now_ms = clock::timestamp_ms(clock);
    // ...
    if (data::timestamp(&oracle_data) >= now_ms - meta_oracle.max_age_ms) {
        // accept
    }
}
```

Replace the relative `max_timestamp - time_window_ms` window with an absolute `now - max_age_ms` bound. Add a `max_age_ms` field to `MetaOracle` and abort if fewer than `threshold` fresh readings are available.

### Proof of Concept

1. Deploy the `oracle` package on a local Sui network.
2. Call `simple_oracle::submit_data` to publish a price at time T.
3. Wait longer than `time_window_ms` (e.g., 2 minutes if `time_window_ms = 60000`).
4. Call a downstream contract that invokes `meta_oracle::add_simple_oracle` + `meta_oracle::median`.
5. Observe that `combine()` computes `min_timestamp = T - 60000` and accepts the data at timestamp T, even though the current clock is `T + 120000`. The price is 2 minutes stale but passes validation.
6. Repeat with arbitrarily large staleness — the check never fails as long as all oracles are within `time_window_ms` of each other, regardless of how old they all are relative to the present.

        let min_timestamp = max_timestamp - time_window_ms;
