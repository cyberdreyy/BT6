## Answer

Yes — `staking_contract::distribute(staker, operator)` is genuinely permissionless (no signer check at all) and calling it after `switch_operator`/`switch_operator_with_same_commission` can misattribute a stale operator's pending commission to the new operator through `update_distribution_pool`. [1](#0-0) 

### Title
`distribute()` after `switch_operator` misattributes old operator's pending commission to the new operator - (aptos-move/framework/aptos-framework/sources/staking_contract.move)

### Summary
`switch_operator` calls `distribute_internal` then `request_commission_internal(old_operator, ...)` *before* updating the contract's operator field, which leaves a distribution-pool shareholder entry keyed by `old_operator` holding shares for the just-unlocked (but not yet withdrawable) commission. The contract is then re-keyed under `new_operator` and `stake::set_operator_with_cap` is invoked, but the shareholder address in the `Pool` is never migrated. [2](#0-1) [3](#0-2) 

Any later, unprivileged call to `distribute(staker, new_operator)` runs `update_distribution_pool(distribution_pool, distribution_amount, operator=new_operator, commission_percentage)`, which taxes the value growth of *every* shareholder except `operator` and transfers the "unpaid commission" shares to `operator`. [4](#0-3) 

Because the stale `old_operator` entry is no longer recognized as "the operator" (the check is `shareholder != operator` where `operator == new_operator`), if that entry's underlying pending_inactive stake continues accruing rewards before its lockup fully expires, `update_distribution_pool` treats that growth as taxable reward and skims/transfers shares from `old_operator` to `new_operator`. [5](#0-4) 

### Finding Description
1. `switch_operator` first forces `distribute_internal` (pays out already-inactive funds) and then `request_commission_internal(old_operator, staking_contract)`, which calls `add_distribution(old_operator, staking_contract, old_operator, commission_amount)` — i.e. `distribution_pool.buy_in(old_operator, commission_amount)` — and `stake::unlock_with_cap` for that commission. [6](#0-5) 
2. Immediately after, the contract's operator identity is changed (`stake::set_operator_with_cap(..., new_operator)`, `commission_percentage = new_commission_percentage`) and the `StakingContract` struct (including its `distribution_pool`) is moved to be keyed by `new_operator`. [7](#0-6) 
3. The `Pool`'s shareholder list still contains `old_operator` as a plain address with shares — the pool has no concept of "this shareholder used to be the operator." Nothing distinguishes it from an ordinary staker's pending distribution.
4. The commission just requested for `old_operator` is `pending_inactive`, not yet withdrawable; it keeps earning validator rewards until the stake pool's lockup expires and it moves to `inactive`.
5. Any address can call `distribute(staker, new_operator)` at any point afterward (no role check whatsoever). [8](#0-7) 
6. That call computes `total_potential_withdrawable = inactive + pending_inactive` and invokes `update_distribution_pool(pool, distribution_amount, operator=new_operator, commission_percentage)` before redeeming shares. [9](#0-8) 
7. Inside `update_distribution_pool`, since `old_operator`'s entry is `shareholder != operator` (operator is now `new_operator`), any growth in that entry's value relative to its last-recorded worth is charged `commission_percentage` and the corresponding shares are transferred from `old_operator` to `new_operator`. [10](#0-9) 

The net effect: value that is rightfully `old_operator`'s already-earned, unlock-requested commission is partly redirected to `new_operator` once `distribute()` is triggered by anyone. This breaks the invariant that distribution amounts strictly follow each shareholder's rightful ownership and misattributes commission-eligible inactive/pending-inactive stake to an unintended recipient.

### Impact Explanation
This redirects real economic value (operator commission) from the operator who actually earned it (`old_operator`) to a different operator (`new_operator`) who did not perform the corresponding validation work, purely as a side effect of a state-crystallizing call that any unprivileged account can trigger. It corrupts the accounting invariant that distribution shares track each shareholder's true entitlement across `pending_inactive`/`inactive` stake and commission. The magnitude scales with reward accrual during the lockup window between the operator switch and the eventual `distribute()` call, and with how frequently the affected stake pool has operator switches with nonzero pending commission.

### Likelihood Explanation
- `distribute()` requires no signer authorization at all, so triggering the settlement is trivial for any address.
- The precondition (calling `switch_operator`/`switch_operator_with_same_commission` while there is a nonzero commission amount) is a normal staker action, not a privileged or unusual one — commission accrual is the default state of any staking contract with `commission_percentage > 0`.
- The only additional requirement is that some reward accrual occurs on the `pending_inactive` bucket before the lockup fully expires and `distribute()` is called, which happens naturally given Aptos's epoch-based reward compounding.

### Recommendation
When `switch_operator`/`switch_operator_with_same_commission` moves the `StakingContract` to a new operator key, migrate (rename) the `old_operator`'s shareholder entry to the currently-effective operator identity within `distribution_pool` (e.g. transfer shares from `old_operator` to `new_operator` 1:1, without going through the commission-tax path in `update_distribution_pool`), or explicitly exclude/checkpoint that entry so it isn't further taxed as an ordinary shareholder. Alternatively, force a hard `distribute_internal` flush of the specific commission distribution for `old_operator` (paying it out immediately rather than leaving it as `pending_inactive`) before the operator identity changes.

### Proof of Concept
```
1. Staker creates a staking_contract with operator = OP_A, commission_percentage = 10.
2. Stake pool accrues rewards over several epochs so accumulated_rewards > 0.
3. Staker calls switch_operator_with_same_commission(staker, OP_A, OP_B).
   -> request_commission_internal adds a distribution_pool entry keyed by OP_A
      for the accrued commission_amount (now pending_inactive), then the
      StakingContract's operator becomes OP_B.
4. Let several more epochs pass so the pending_inactive commission bucket
   (still keyed by OP_A) accrues additional rewards, and the lockup expires
   so it becomes inactive.
5. A random, unrelated signer (not staker, OP_A, OP_B, or governance) calls
   staking_contract::distribute(staker, OP_B).
6. Assert (expected, currently violated): OP_A receives exactly the original
   commission_amount plus its own rightful share growth; OP_B receives
   nothing extra beyond its own genuine post-switch commission.
   Actual: update_distribution_pool taxes OP_A's stale entry's growth and
   transfers those shares to OP_B, so OP_B's payout at distribution time
   exceeds its rightful share and OP_A's payout is reduced accordingly.
```

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

    /// Add a new distribution for `recipient` and `amount` to the staking contract's distributions list.
    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
