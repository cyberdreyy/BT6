### Title
Unsanitized alternate cache key allows path traversal in local cache archive/extract path when `FF_HASH_CACHE_KEYS` is enabled - ([File: functions/concrete/run/stages/cache_archive.go])

### Summary
When the `FF_HASH_CACHE_KEYS` feature flag is enabled, `AlternateKey` on both `CacheArchive` and `CacheExtract`'s `CacheSource` is set to the raw, unsanitized human-readable cache key (expanded from CI variables) instead of the sanitized/hashed form. This value flows unsanitized into `cacheArchivePath` (`filepath.Join(e.CacheDir, key, "cache.zip")`), permitting `../` sequences from `cache.key` to escape `CacheDir`.

### Finding Description
`cacheArchivePath` itself performs no path confinement beyond `filepath.Join`/`filepath.Rel`: [1](#0-0) . Path-traversal safety is meant to come from `cachekey.Sanitize`, which clamps `..`/absolute segments to a virtual root before the key is used: [2](#0-1) .

However, `builder.cacheKey` only calls `Sanitize` when `FF_HASH_CACHE_KEYS` is **off**. When the flag is **on**, `humanKey` is left as the raw, `ExpandValue`-expanded `cache.Key` with no traversal sanitation at all: [3](#0-2) .

In `buildCacheArchive`, the primary `Key` field is safe because it's set to `resolvedKey` (a SHA-256 hex hash when the flag is on). But `AlternateKey` is explicitly set to the **unsanitized** `humanKey` when the flag is on:
```go
alternateResolved := humanKey
if !b.isFeatureFlagOn(featureflags.HashCacheKeys) {
    alternateResolved = fmt.Sprintf("%x", sha256.Sum256([]byte(humanKey)))
}
``` [4](#0-3) . The identical pattern also produces `CacheSource.AlternateKey` for cache extraction: [5](#0-4) .

This unsanitized `AlternateKey` is then used directly to build the on-disk archive path via `alternateArchivePath` → `cacheArchivePath(e, s.AlternateKey)`, with no re-validation: [6](#0-5) . It is passed to the helper binary as `--alternate-file` for both archiving and extraction: [7](#0-6)  and via `src.AlternateKey`/`s.archivePath` in `CacheExtract.archivePath` for extraction targets (note: the extract path shown reads `--file archiveFile` from `src.Key`, but `src.AlternateKey` is exposed on `CacheSource` for the same purpose in the helper's alternate-lookup logic) [8](#0-7) .

Since `filepath.Join` (via `filepath.Clean`) resolves `..` normally with no virtual-root clamp (unlike `cachekey.Sanitize`), a `cache.key` value such as `../../other-job-id/session` (expanded via a CI variable) produces an `AlternateKey` string containing literal `../` sequences, and `cacheArchivePath` will resolve a path outside `CacheDir`.

### Impact Explanation
With `FF_HASH_CACHE_KEYS` enabled and a shared `CacheDir` across concurrently scheduled jobs on the same host, an unprivileged pipeline author can set `cache.key` (or a variable it expands from) to contain `../` sequences. The resulting `--alternate-file` path used by the cache-archiver/extractor helper process escapes the job's own `CacheDir/<key>` subtree and can collide with, overwrite, or read files at an attacker-chosen relative location on the host filesystem — including another concurrently running job's cache/session state directory, matching the scoped impact (cross-job file collision affecting another job's on-host process state).

### Likelihood Explanation
Requires: (1) `FF_HASH_CACHE_KEYS` feature flag enabled on the runner, (2) shared `CacheDir` across concurrently scheduled jobs on one host (documented as a supported configuration), and (3) `cache.paths`/`cache.untracked` set so the archive/extract stage actually runs. Given these preconditions, the exploit is fully attacker-controlled via `.gitlab-ci.yml` `cache.key` (or a variable), requires no special privileges, and is deterministic/repeatable — not merely theoretical.

### Recommendation
Route `AlternateKey` through the same traversal-safe handling as the primary key: either always apply `cachekey.Sanitize` (virtual-root clamp) to `humanKey` before using it as `AlternateKey`, or hash it when it isn't already hashed, regardless of `FF_HASH_CACHE_KEYS` state. Additionally, harden `cacheArchivePath` itself to reject/clamp any key containing `..` segments or absolute-path components after `filepath.Join`, so a defect in caller-side sanitation cannot translate into a path-confinement break.

### Proof of Concept
Go unit test (extends `cache_archive_test.go` style):
```go
func TestCacheArchivePath_RejectsTraversal(t *testing.T) {
    e := &env.Env{WorkingDir: "/builds/group/project", CacheDir: "/cache"}
    maliciousKey := "../../other-job-id/session"
    got := cacheArchivePath(e, maliciousKey)
    // Assert resolved absolute path stays under CacheDir.
    abs := filepath.Join(e.CacheDir, maliciousKey, "cache.zip")
    assert.True(t, strings.HasPrefix(filepath.Clean(abs), filepath.Clean(e.CacheDir)+string(filepath.Separator)),
        "cache archive path escaped CacheDir: %s", abs)
}
```
Builder-level PoC (mirrors `TestBuild_CacheArchive`/`TestBuild_FeatureFlags` in `builder_test.go`): construct a job with `cache.key: "../../other-job-id/session"`, enable `featureflags.HashCacheKeys` via `WithFeatureFlagProvider`, call `buildConfig`, and assert `config.CacheArchive[0].AlternateKey` still contains `..` and that `filepath.Join(cacheDir, config.CacheArchive[0].AlternateKey)` resolves outside `cacheDir` — demonstrating the missing sanitation on the hashing-enabled code path.

func Sanitize(cacheKey string) (string, error) {
	if cacheKey == "" {
		return "", nil
	}

	// Decode percent-encoded chars and normalise separators, then
	// resolve traversals against a virtual root so ".." can never
	// escape beyond the root.
	cleaned := path.Clean("/" + normaliser.Replace(cacheKey))

	// Strip the leading "/" we added, split into segments, then walk
	// backwards trimming trailing whitespace from the rightmost
	// segments—dropping any that become empty.
	parts := strings.Split(cleaned[1:], "/")
	n := len(parts)
	for n > 0 {
		parts[n-1] = strings.TrimRightFunc(parts[n-1], unicode.IsSpace)
		if parts[n-1] != "" {
			break
		}
		n--
	}

	key := strings.Join(parts[:n], "/")

	if key == "" {
		return "", fmt.Errorf("cache key %q could not be sanitized", cacheKey)
	}

	return key, nil

func (b *builder) cacheKey(name string) (string, string, []string, error) {
	// Virtual-root prefix prevents a leading / or .. in JobName/Ref from producing an unexpected key,
	// especially under FF_HASH_CACHE_KEYS=on where humanKey is used unsanitized.
	rawKey := path.Join("/", b.meta.JobInfo.Name, b.meta.GitInfo.Ref)[1:]
	if name != "" {
		rawKey = b.variables.ExpandValue(name)
	}

	var warnings []string
	var humanKey string
	if b.isFeatureFlagOn(featureflags.HashCacheKeys) {
		humanKey = rawKey
	} else {
		sanitized, err := cachekey.Sanitize(rawKey)
		switch {
		case err != nil:
			warnings = append(warnings, err.Error())
		case sanitized != rawKey:
			warnings = append(warnings, fmt.Sprintf("cache key %q sanitized to %q", rawKey, sanitized))
		}
		humanKey = sanitized
	}

	if humanKey == "" {
		return "", "", warnings, fmt.Errorf("empty cache key")
	}

	resolvedKey := humanKey
	if b.isFeatureFlagOn(featureflags.HashCacheKeys) {
		resolvedKey = fmt.Sprintf("%x", sha256.Sum256([]byte(humanKey)))
	}

	return humanKey, resolvedKey, warnings, nil
}
