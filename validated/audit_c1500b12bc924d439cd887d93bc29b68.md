### Title
Current tenure's miner can spam non-advancing block proposals to indefinitely suppress the inactivity timeout and block signer fallback - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`SortitionData::check_latest_block_in_tenure` refreshes a tenure's `last_activity_time` whenever the active miner submits a block proposal that does *not* advance the chain (i.e. `chain_length <= info.block.header.chain_length`), as long as the last known block hasn't been globally signed for longer than `reorg_attempts_activity_timeout`. This activity timestamp is exactly what `SortitionState::is_timed_out` uses to decide whether the current miner has gone inactive and should be timed out in favor of falling back to a valid prior miner. A malicious (or simply misbehaving) current-tenure miner can therefore keep re-sending stale/non-advancing block proposals forever, resetting the clock each time, and never actually get timed out — even though it never produces a valid, height-advancing block.

### Finding Description
`check_latest_block_in_tenure` is called by the signer's proposal-validation path (`stacks-signer/src/v0/signer.rs`, via `SortitionData::get_tenure_last_block_info`/`check_latest_block_in_tenure`) for every incoming `BlockProposal` for the active tenure. [1](#0-0) 

When the proposed block's `chain_length` does not exceed the tenure's last known signed block, the code takes the rejection branch but, before returning `Ok(false)`, unconditionally refreshes the tenure's activity timer as long as `info.signed_group` is `None` (i.e. the block is only locally accepted, not yet globally accepted) or within `reorg_attempts_activity_timeout` of the last global signature: [2](#0-1) 

This timestamp is stored per tenure `consensus_hash` via `SignerDb::update_last_activity_time`: [3](#0-2) 

The exact same key (`tenure_id`/`consensus_hash`) is later read by `SortitionState::is_timed_out`, which is the sole gate deciding whether the miner has become inactive: [4](#0-3) 

And `check_miner_inactivity` only proceeds to revert to a prior valid miner when `is_timed_out` returns true: [5](#0-4) 

Because the "activity" bump in `check_latest_block_in_tenure` fires on a proposal that *fails* the height check (i.e. it is not actually progressing the chain), the current miner does not need to ever produce a valid or higher block to be counted as "active." It only needs to keep sending some non-advancing block proposal for its own tenure before `block_proposal_timeout` elapses. This is directly analogous to the reported `LiquidityGauge` bug: the integral (`last_activity_time`/timeout condition) is only updated based on elapsed time since the last update, and an actor who can trigger that update at will (here, the current tenure's miner, a single actor requiring no majority) can keep `dt`/`elapsed` from ever crossing the threshold, permanently suppressing the state transition that should otherwise occur (falling back to a valid miner).

### Impact Explanation
This is a liveness wedge: as long as the malicious/stalled miner keeps re-sending (or slightly perturbing) rejected/non-advancing proposals faster than `block_proposal_timeout`, `is_timed_out` never returns true, so `check_miner_inactivity` never triggers a fallback to the prior valid miner. Since the current miner also cannot produce a canonical advancing block (whether unable or unwilling), the chain stalls in that tenure until a new Bitcoin block/sortition occurs. This matches the "High" impact bucket: a signer state machine wedged such that it never falls back to a valid miner despite the active miner being unproductive, blocking chain progress for an entire tenure.

### Likelihood Explanation
The trigger requires only the party who currently holds the active tenure (a single miner, no majority of signers, no other signer's key) to submit repeated, cheaply-constructed block proposals whose `chain_length` does not exceed the previously known chain length — these do not need to pass full block validation, since the height check short-circuits before deeper validation. Doing this at intervals shorter than `block_proposal_timeout` is well within a normal actor's capability (this is exactly the kind of gossip/proposal traffic a miner is already expected to send), making the likelihood high for a miner willing to grief or one that is buggy and re-broadcasting stale proposals.

### Recommendation
Do not treat a proposal that fails the "block must be higher" check as valid miner activity unless there is corroborating evidence the miner is behaving correctly (e.g., only count it once per reorg attempt, or only within a bounded number/rate of such resets, or require the reorg target to itself be plausible/canonical rather than merely "not yet globally signed"). Consider decoupling "reorg attempt is not penalized" from "reorg attempt resets the inactivity clock," so that repeated non-advancing proposals cannot indefinitely suppress `is_timed_out`. At minimum, bound how much cumulative time a tenure can have its inactivity clock refreshed by non-advancing proposals (a hard ceiling on total suppressed time per tenure), so that a stalled miner is always eventually superseded within `N * block_proposal_timeout`.

### Proof of Concept
1. Signer accepts (locally, not yet globally) a block `B1` from the active tenure's miner (`consensus_hash = CH`); `signed_group` is `None`.
2. Miner (holding tenure `CH`) crafts and sends a new `BlockProposal` for `CH` with `chain_length <= B1.chain_length` (e.g., an older/duplicate/lower block). This fails `check_latest_block_in_tenure`'s height check.
3. Because `info.signed_group.is_none()`, the `is_none_or` guard is satisfied, so `signer_db.update_last_activity_time(&CH, now)` fires — see [2](#0-1) .
4. Repeat step 2 at any interval `< block_proposal_timeout`, indefinitely.
5. `SortitionState::is_timed_out(CH, ...)` at [6](#0-5)  keeps computing `elapsed = now - last_activity` as small, so `elapsed > block_proposal_timeout` is never true.
6. `check_miner_inactivity` in [7](#0-6)  returns early every time (`is_timed_out == false`), so signers never revert to the prior valid miner, and the tenure stalls with no forward chain progress until the next Bitcoin block/sortition.

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
