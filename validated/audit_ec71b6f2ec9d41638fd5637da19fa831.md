### Title
`ExtractZipArchive` second-pass metadata application (`Chtimes`) follows a symlink planted by a later duplicate-named entry, allowing entry-order manipulation to redirect mtime writes off the intended path - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` extracts every entry in a first loop, then in a second loop applies `lchmod` and `processZipExtra` (which can call `os.Chtimes`) using each `zip.File`'s `Name`/`FileHeader`, independent of what is actually on disk at that path by the time the second loop runs. Because zip archives can contain duplicate `Name` values, an attacker can place a regular file entry followed later by a symlink entry with the identical `Name`; after the first loop finishes, that path is a symlink, and the second loop's `processZipTimestampField` call for the earlier (regular-file) entry invokes `os.Chtimes(file.Name, ...)`, which follows the symlink and updates the mtime of whatever the symlink points to.

### Finding Description
`ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`) does:
1. First loop: for every `archive.File`, call `extractZipFile`, which for symlink entries does `os.Remove(file.Name); os.Symlink(data, file.Name)` (`zip_extract.go:22-39`) and for regular files does `os.Remove(file.Name)` then writes a new file (`zip_extract.go:41-59`). Both remove-then-create the same path, so the *last* entry with a given `Name` determines what occupies that path on disk.
2. Second loop: for every `archive.File` again, call `lchmod(file.Name, file.Mode())` and `processZipExtra(&file.FileHeader)`, which dispatches to `processZipTimestampField` (`zip_extra.go:50-68`). That function checks `file.Mode().IsRegular()` — using the *header's* recorded mode, not the current filesystem state — and if true calls `os.Chtimes(file.Name, acTime, modTime)`. `os.Chtimes` follows symlinks.

If the attacker crafts a zip with entry A = regular file at path `P` and a later entry B = symlink at the same path `P` pointing to a location outside the extraction root (e.g. `../../other-project/shared-cache/foo`), then after the first loop, `P` is a symlink to the attacker-chosen target. In the second loop, when the iterator reaches entry A again, `processZipTimestampField` still evaluates `file.Mode().IsRegular()` as true (from A's header) and calls `os.Chtimes(P, ...)`, which follows the symlink and updates the mtime of the external target file — not `P` itself.

Note that `processZipUIDGidField` uses `os.Lchown`, which does *not* follow symlinks, so UID/GID changes are not affected by this issue; the `lchmod` helper on Linux explicitly no-ops for symlink mode bits, so chmod is likewise not exploitable this way. The concrete exploitable primitive is limited to `os.Chtimes` via `processZipTimestampField`.

There is no path-containment check (`filepath.Clean`/`..` rejection) or "no duplicate names" check anywhere in `ExtractZipArchive`, `extractZipFile`, or `processZipExtra`; the only existing guard, `errorIfGitDirectory`, only blocks `.git` paths and does nothing to prevent path traversal or symlink redirection (`path_check_helper.go:13-19`). This confirms existing checks do not stop the described flow.

### Impact Explanation
The exploit path allows an attacker-crafted archive extraction (e.g., artifacts/cache download performed by Runner) to modify the **modification timestamp** of an arbitrary file reachable via a symlink target outside the extraction root, as long as the Runner process has filesystem permission to write to that target and the symlink resolves there. This is a narrow, low-severity "out-of-tree file operation" (mtime corruption only, since chown/chmod are not affected), but it does violate the stated invariant that "file operations must stay within intended build/cache/artifact roots," and could be used to corrupt build caching heuristics or interfere with another project's shared files if such symlink targets are reachable (e.g., same host, shared executor filesystem, no per-job chroot/container isolation).

### Likelihood Explanation
This requires: (1) the attacker fully controls archive contents (true for artifacts/cache created by a pipeline the attacker controls), (2) duplicate `Name` values are accepted by Go's `archive/zip` reader (they are — `zip.Reader` does not deduplicate), (3) the Runner process extracting the archive must have write permission to a path reachable via a symlink escaping the workspace, and this generally requires a shared-filesystem executor context without per-job isolation (e.g., shell executor, or shared volumes) — this is consistent with documented shell-executor trust assumptions but the specific mtime-redirection technique via duplicate zip entries is not a documented/accepted risk, so it is not excluded by the "reject shell-executor trust" rule. The bug is deterministic and easily reproducible with a two-entry zip.

### Recommendation
In `ExtractZipArchive`'s second loop, re-check the actual on-disk file type at `file.Name` (e.g. via `os.Lstat`) before applying `Chtimes`, and skip/warn if the current on-disk entry is a symlink or does not match the type recorded in the header. Alternatively, merge the two loops into a single pass per entry (extract, then immediately apply `lchmod`/`processZipExtra` for that same entry) so metadata application always targets the freshly-extracted object rather than whatever occupies the path after the whole archive is processed. Additionally, reject duplicate `file.Name` entries within a single archive, and use `os.Lchtimes`-equivalent behavior (lstat-based, non-following) where possible instead of `os.Chtimes`.

### Proof of Concept
```go
func TestExtractZipArchive_DuplicateNameSymlinkRedirectsChtimes(t *testing.T) {
    dir := t.TempDir()
    outsideTarget := filepath.Join(t.TempDir(), "outside.txt")
    require.NoError(t, os.WriteFile(outsideTarget, []byte("x"), 0o644))
    origInfo, _ := os.Stat(outsideTarget)
    origMtime := origInfo.ModTime()

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)

    // Entry A: regular file "shared" with timestamp extra field
    fh := &zip.FileHeader{Name: "shared", Method: zip.Store}
    fh.SetModTime(time.Now())
    // ... set Extra with ZipTimestampFieldType for a fixed modTime T
    w, _ := zw.CreateHeader(fh)
    w.Write([]byte("hello"))

    // Entry B: symlink "shared" -> outsideTarget (escapes dir)
    fhSym := &zip.FileHeader{Name: "shared"}
    fhSym.SetMode(os.ModeSymlink | 0o777)
    wSym, _ := zw.CreateHeader(fhSym)
    wSym.Write([]byte(outsideTarget))

    zw.Close()

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    os.Chdir(dir)
    defer os.Chdir(wd)

    err := ExtractZipArchive(r)
    require.NoError(t, err)

    // Assert: "shared" is now a symlink (from entry B)
    fi, _ := os.Lstat("shared")
    require.True(t, fi.Mode()&os.ModeSymlink != 0)

    // Assert: outsideTarget's mtime was changed by entry A's Chtimes call,
    // proving the second-pass metadata application followed the symlink
    // rather than skipping/erroring due to type mismatch.
    newInfo, _ := os.Stat(outsideTarget)
    require.NotEqual(t, origMtime, newInfo.ModTime())
}
```
Expected assertions: `shared` on disk is a symlink pointing outside `dir`, and the mtime of `outsideTarget` (outside the workspace) has been modified as a side effect of extracting entry A's metadata — demonstrating the out-of-tree `Chtimes` operation caused by entry-order/duplicate-name TOCTOU in the two-pass design. func extractZipSymlinkEntry(file *zip.File) (err error) {
```go
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

	}

		return err
	}
	defer func() { _ = out.Close() }()

	return
}
```

```go
func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
```

```go
func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```

```go
func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
}
```
