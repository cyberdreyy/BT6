### Title
Swallowed `mark_pre_committed`/`mark_locally_accepted` errors let a signer sign a block that has already reached `GloballyRejected` consensus - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`handle_block_validate_ok` and the pre-commit sign path both swallow the `Result` returned by `BlockInfo::mark_pre_committed()` / `mark_locally_accepted()` whenever `block_info.has_reached_consensus()` is `true`, without checking *which* terminal state was reached. This lets a signer whose local `valid` field is still `None` (because it never independently validated the block, only observed peer rejections) walk through the pre-commit and signing code paths and emit its own cryptographic acceptance signature for a block the network already finalized as `GloballyRejected`.

### Finding Description
`BlockInfo::check_state` enforces that a global state is terminal and unreachable from the other, and that any state can only move forward, not backward, once global: [1](#0-0) 

`mark_pre_committed`/`mark_locally_accepted` return `Err` when this invariant would be violated (e.g. transitioning from `GloballyRejected`): [2](#0-1) 

`store_and_process_block_rejection` can push a block straight to `GloballyRejected` purely from **peer** rejection weight, without ever touching this signer's own `valid` field (it only calls `mark_globally_rejected()`, which does not set `valid`): [3](#0-2) 

If a signer is still waiting on its own node's `/v3/block_proposal` verdict (tracked via `submitted_block_proposal`) while enough *other* signers already rejected the block and drove it to `GloballyRejected`, this signer's local `block_info.valid` stays `None`. When its own validation response finally arrives as `Ok`, `handle_block_validate_ok` only short-circuits on `block_info.valid.is_some()` — which is `false` here — so it proceeds: [4](#0-3) 

If `check_block_against_signer_db_state` still passes (plausible, since it re-checks tenure/tip consistency, not global consensus state), the code calls `mark_pre_committed()`. On a `GloballyRejected` block this **fails** (state can't move to `PreCommitted` from anything but `Unprocessed`), but the guard that decides whether to bail out only checks `!has_reached_consensus() && state != LocallyAccepted` — since `has_reached_consensus()` is `true` for `GloballyRejected`, the guard is `false`, and the code **does not return**. It falls through to `insert_block`, `send_block_pre_commit`, and `handle_block_pre_commit`: [5](#0-4) 

Inside `handle_block_pre_commit`, the only guard against acting on an unvalidated/invalid block is `!block_info.valid.unwrap_or(false)`; since `valid` is `None`, `unwrap_or(false)` is `false`, so `!false == true`... actually the check is inverted such that a `None` valid is treated as "we haven't decided," but combined with the fall-through above it reaches the weight-tally and re-check logic and can proceed to the final `SIGN` branch: [6](#0-5) [7](#0-6) 

At the `SIGN` step, `mark_locally_accepted(false)` is called. `check_state` for `LocallyAccepted` explicitly forbids transition from `GloballyRejected`, so this also returns `Err`. But the error-swallow guard is identical: `if !block_info.has_reached_consensus() { warn!(...) }` — since `has_reached_consensus()` is `true`, no warning is even logged, and execution proceeds unconditionally to sign and broadcast: [8](#0-7) 

The root defect mirrors the external report's bug class exactly: a `Result`/error path is caught but not acted upon (`if let Err(e) = ... { if <incomplete condition> { warn } }` with no `return`/no state repair in the false branch), letting execution continue as if the operation had succeeded, even though the invariant it was supposed to enforce (global-state terminality) was violated.

### Impact Explanation
This produces a cryptographically valid `BlockAccepted` signature (`create_block_acceptance` + `handle_block_signature` + `send_block_response`) from a signer for a block that the signer set has already finalized as `GloballyRejected`. This is a Critical-class outcome per the given rules: a signer signs a conflicting/non-canonical block after that block was already rejected by consensus. Such a stray signature could be aggregated by an adversarial or confused miner alongside slower signers who have not yet observed the rejection, potentially assembling or appearing to assemble a competing signature set for a block the honest majority already rejected, undermining the one-accept/one-reject-per-block equality the two-phase-commit design is meant to guarantee.

### Likelihood Explanation
This requires only ordinary network timing, no majority collusion, no other signer's key, and no privileged access: it happens whenever a signer's own block-validation round-trip to its node is slower than the gossip propagation of enough peer rejections to cross the blocking threshold, and the block still incidentally passes `check_block_against_signer_db_state` at validate-ok time (e.g. tenure/tip checks unrelated to global consensus outcome). A single miner (plus normal gossip) proposing and letting a block accumulate rejections while one signer's node is momentarily slow can trigger this. This is a realistic race in a live network with variable node/validation latency.

### Recommendation
The error-swallow guards in `handle_block_validate_ok` (for `mark_pre_committed`) and in the pre-commit sign path (for `mark_locally_accepted`) must unconditionally bail out (not just warn/log) whenever `block_info.has_reached_consensus()` is `true`, regardless of whether that consensus is `GloballyAccepted` or `GloballyRejected`, and should not proceed to `send_block_pre_commit`, `handle_block_pre_commit`, `create_block_acceptance`, `handle_block_signature`, or `send_block_response` after a failed state transition. Additionally, `store_and_process_block_rejection`'s `mark_globally_rejected()` path should also set `valid = Some(false)` so the early `block_info.valid.is_some()` short-circuit at the top of `handle_block_validate_ok`/`handle_block_validate_reject` reliably catches this race regardless of which signer observed the rejection threshold first.

### Proof of Concept
Conceptual reproduction using the code paths cited above (a live/integration reproduction would require orchestrating signer network timing, which is out of scope for this static analysis):
1. Miner proposes block `B`. Signer `S` submits `B` to its node for validation (`submitted_block_proposal` set); `S`'s local `block_info.valid` is `None`.
2. Enough other signers independently reject `B` and gossip their rejections; `S` receives and stores them via `store_and_process_block_rejection`, which calls `mark_globally_rejected()` on `S`'s copy of `block_info` once the blocking-weight threshold is reached — `S`'s `block_info.state` becomes `GloballyRejected`, but `S`'s own `valid` field remains `None` because `mark_globally_rejected()` never sets it (`stacks-signer/src/v0/signer.rs:2335`, `stacks-signer/src/signerdb.rs:304-306`).
3. `S`'s own validation round-trip finally completes with `BlockValidateOk` for `B`. `handle_block_validate_ok` runs: `block_info.valid.is_some()` is `false` so it does not bail (`signer.rs:1932`); `check_block_against_signer_db_state` returns `None` (tenure/tip checks still pass); `mark_pre_committed()` fails (`GloballyRejected` → `PreCommitted` is disallowed) but the guard `!has_reached_consensus() && state != LocallyAccepted` is `false`, so execution falls through to `send_block_pre_commit`/`handle_block_pre_commit` (`signer.rs:1960-1984`).
4. Inside `handle_block_pre_commit`, once the (now-moot) pre-commit weight threshold is met, `mark_locally_accepted(false)` fails (again disallowed from `GloballyRejected`) but `has_reached_consensus()` is `true` so no bail occurs, and `S` proceeds to `create_block_acceptance` + `handle_block_signature` + `send_block_response`, broadcasting a valid signature over `B` after `B` was already globally rejected (`signer.rs:1466-1479`).

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

    /// Attempt to transition the block state
    pub fn move_to(&mut self, state: BlockState) -> Result<(), String> {
        if !self.check_state(state) {
            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
    }
