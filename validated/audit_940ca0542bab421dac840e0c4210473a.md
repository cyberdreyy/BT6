### Title
View/Run-role authenticated users can read a bridge's plaintext `OutgoingToken` secret via `GET /v2/bridge_types/:BridgeName` - ([File: core/web/bridge_types_controller.go])

### Summary
`BridgeTypesController.Show` is registered without any role gate, unlike `Create`/`Update`/`Destroy`, and returns the bridge resource via `presenters.NewBridgeResource`, which unconditionally includes the bridge's `OutgoingToken` field. Any authenticated user regardless of role (`view`, `run`, `edit`, `admin`) can retrieve the raw outgoing credential for any bridge.

### Finding Description
The route is registered in `core/web/router.go` as:
```
authv2.GET("/bridge_types/:BridgeName", bt.Show)
```
while the sibling mutating routes are role-gated:
```
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
``` [1](#0-0) 

`Show` only requires the base `authv2` group middleware (session or API token authentication, no role check), then fetches the bridge and serializes it directly:
```go
bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
...
jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
``` [2](#0-1) 

`presenters.NewBridgeResource` copies `b.OutgoingToken` into the response unconditionally, with no role parameter or redaction logic:
```go
func NewBridgeResource(b bridges.BridgeType) *BridgeResource {
	return &BridgeResource{
		...
		OutgoingToken:          b.OutgoingToken,
		...
	}
}
``` [3](#0-2) 

The unit test for this presenter confirms `outgoingToken` is always serialized in full, with no gating by caller role: [4](#0-3) 

The existing RBAC route table also documents (and thus locks in) this behavior — `GET /v2/bridge_types/MOCK` is marked `viewOnlyAllowed: true`: [5](#0-4) 

Because `RequiresEditRole`/`RequiresAdminRole` are never applied to `Show`, and the presenter performs no secret redaction, any authenticated principal — including a `view`-role user or a restricted API token — can fetch `OutgoingToken` for any bridge in the node by simply calling `GET /v2/bridge_types/<name>`.

### Impact Explanation
`OutgoingToken` is the credential the Chainlink node uses to authenticate itself to the external bridge/adapter when making outbound requests. Disclosure of this token to a low-privileged (`view`/`run`) user or restricted API-token holder allows that attacker to impersonate the node when calling the external bridge endpoint directly, or replay/reuse the token against the bridge adapter outside of the node's control. This matches the "key/credential exfiltration" bounty class — theft of a service credential that is scoped to a secret-only, admin/edit-role operation.

### Likelihood Explanation
Trivial and fully repeatable: any valid session/API token of any role (including `view` or `run`) can call `GET /v2/bridge_types/:BridgeName` with no additional preconditions, network access, or privilege escalation required. This is a straightforward single unauthenticated-by-role HTTP GET.

### Recommendation
Wrap `bt.Show` with a role check consistent with the other bridge-mutation endpoints (e.g., `auth.RequiresEditRole` or higher), or have `presenters.NewBridgeResource`/`BridgeTypesController.Show` redact `OutgoingToken` (and any other secret fields) unless the caller's role is at least `edit`/`admin`, similar to how `IncomingToken` is only populated in the `Create` response path.

### Proof of Concept
1. Unit test on `presenters.NewBridgeResource`: construct a `bridges.BridgeType` with a non-empty `OutgoingToken`, call `NewBridgeResource`, and assert that the resulting `BridgeResource.OutgoingToken` is non-empty regardless of any role context — demonstrating no redaction exists (mirrors `core/web/presenters/bridges_test.go` `TestBridgeResource`).
2. Handler/integration test using `web.Router`:
   - Create a bridge with `App.BridgeORM().CreateBridgeType` setting a known `OutgoingToken`.
   - Create an HTTP client authenticated as `sessions.UserRoleView`.
   - Issue `GET /v2/bridge_types/<name>`.
   - Assert `http.StatusOK` (not `Forbidden`/`Unauthorized`) and that the JSON response body's `attributes.outgoingToken` equals the known secret value, proving the secret is exfiltrable by a view-role user.

func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
```

func TestBridgeResource(t *testing.T) {

			"name":"test",

			"useConnectionManager":true,

		}
	}
}
`
