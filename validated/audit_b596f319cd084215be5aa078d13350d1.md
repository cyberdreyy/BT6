### Title
Multisig executes requests below the configured confirmation threshold because `delete_member` does not purge confirmations a removed member gave on requests they didn't create - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm` treats `confirmations.len() + 1 >= num_confirmations` as proof that `num_confirmations` distinct, currently-valid members approved a request [1](#0-0) . That equality only holds if every entry in the `confirmations` set still belongs to a live member. `delete_member` only clears requests/confirmations for requests where the removed member is the original requester (`r.member == member`); it never scans confirmation sets of requests created by other members [2](#0-1) . A confirmation left by a member before they are removed therefore stays counted forever, letting a request execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
The intended custody binding is:
`confirmations.len() at execution time == number of distinct, currently-valid members who approved the request`, and this must be `>= num_confirmations`.

`delete_member` breaks this binding:
```
// delete outstanding requests by public_key
let request_ids: Vec<u32> = self
    .requests
    .iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
``` [3](#0-2) 

This only removes requests *created* by the deleted member. It does not iterate other pending requests to strip the deleted member's entry out of their `confirmations: HashSet<String>`. `assert_valid_request` and `confirm` only validate that the *caller* is a current member [4](#0-3) ; they never re-validate the members recorded in the existing `confirmations` set. So a stale confirmation from an already-removed member is silently counted toward the threshold check:
```
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
}
``` [5](#0-4) 

### Impact Explanation
This is Critical under the stated impact list: "a multisig request executed below threshold." A K-of-N multisig's entire security guarantee is that any state-changing action (transfer, key/contract deployment, membership change) requires K live approvals. With this flaw, an action can execute with as few as `num_confirmations - 1` live-member approvals plus one ghost approval from a member who has since been removed (e.g., because their key was compromised or they left the organization) — precisely the scenario `delete_member` exists to protect against.

### Likelihood Explanation
This requires no attacker privilege beyond the multisig's own normal, expected governance workflow: creating a request, confirming it partially, and later removing a member for routine reasons (rotation, offboarding, compromise) while that member has an outstanding confirmation on some other pending request. No malicious member, foundation, or owner action is required — the bug is triggered by an ordinary, legitimate operational sequence rather than by anyone abusing granted privileges.

### Recommendation
When deleting a member, iterate all pending requests' `confirmations` sets (not just requests the member originated) and remove the deleted member's entry from each, re-checking whether any request should now be considered under-confirmed. Alternatively, validate confirmation-set membership against `self.members` at `confirm()`/execution time before counting toward the threshold.

### Proof of Concept
1. Initialize multisig with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `A` calls `add_request_and_confirm(X)` for a `Transfer` request → `confirmations[X] = {A}`.
3. `B` calls `confirm(X)` → `confirmations[X] = {A, B}` (2/3, request stays pending).
4. Members execute (via normal K-of-3 consensus not involving X) a `DeleteMember{B}` request. `delete_member` only scans for requests where `r.member == B` (i.e., requests B created); request `X` was created by `A`, so its confirmations set `{A, B}` is left untouched. `B` is removed from `self.members`.
5. `C` calls `confirm(X)`. `assert_valid_request` passes because `C` is a live member. `confirmations.len() + 1 = 3 >= num_confirmations(3)` → request `X` executes.
6. Result: request `X` (the `Transfer`) executes on the strength of only two currently-valid members (`A`, `C`) approving, with `B`'s stale, post-removal confirmation counted as the third — the K-of-N threshold guarantee is violated.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
