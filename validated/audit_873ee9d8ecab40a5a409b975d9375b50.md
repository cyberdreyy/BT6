### Title
Vault `AllowListBasedAuth` authenticates by request-content digest, not by sender identity, allowing anyone who reproduces public request bytes to impersonate the workflow owner - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
The Vault gateway's default authorization path (`allowListBasedAuth.AuthorizeRequest`) treats "knowledge of a request whose hash matches an on-chain allowlisted digest" as proof of identity, and grants the caller the associated `workflowOwner`. This digest is not a secret: it is published on-chain by the owner via a public `AllowlistRequest` transaction, and the underlying JSON-RPC request content that hashes to it (method + params, e.g. owner address, namespace, secret key names) is itself unencrypted and often fully public or guessable. There is no signature, token, or `msg.sender`-equivalent binding the actual caller of the gateway to the owner who allowlisted the digest.

### Finding Description
`AuthorizeRequest` computes `req.Digest()` from the plaintext JSON-RPC request and simply checks whether that digest exists in the list returned by `WorkflowRegistrySyncer.GetAllowlistedRequests`, then returns the `Owner` recorded on-chain for that digest as the authenticated identity — with no proof that the caller possesses the owner's key or session: [1](#0-0) 

The digest itself comes from a fully public on-chain transaction (`WorkflowRegistry.AllowlistRequest(requestDigest, expiry)`), readable by anyone via `GetAllowlistedRequests`/`getActiveAllowlistedRequestsReverse`: [2](#0-1) [3](#0-2) 

Critically, for methods like `vault.secrets.list` and `vault.secrets.delete`, the params that produce the digest contain no secret material at all — just the owner's (public) address, namespace, and key strings, as shown in the unit test fixtures: [4](#0-3) 

The higher-level `Authorizer` explicitly falls back to this allowlist path whenever `req.Auth` (the JWT/signature field) is empty — i.e., this is the default/legacy path with zero identity binding: [5](#0-4) 

This is the analog of the reported bug class: authentication is derived from a value ("password") that is fully observable from the blockchain/transaction data (the allowlisted digest) combined with content that is not secret (owner address, namespace, key names), rather than from a cryptographic proof tied to `msg.sender`/the actual requester (as `JWTBasedAuth` correctly does by binding a signed token's `authorization_details.request_digest` claim to a verified identity).

### Impact Explanation
Because the digest is public and the underlying request content is frequently non-secret (owner address + namespace/key strings for list/delete operations), any unprivileged party who can observe or reconstruct the exact request bytes can submit that request to the Vault gateway before the legitimate owner does. The replay guard (`RequestReplayGuard.CheckAndRecord`) makes a matching digest single-use, so this becomes a race: an attacker who wins the race is authorized with the real owner's `workflowOwner` identity, allowing them to delete or list that owner's secrets (via `MethodSecretsDelete`/`MethodSecretsList`), or block the legitimate owner's own subsequent operation (denial of service) since the digest is now consumed. This is unauthorized action performed as another user via a non-cryptographic authentication check reachable by any unprivileged gateway client.

### Likelihood Explanation
Exploitability depends on the attacker being able to reproduce the exact plaintext request. For `vault.secrets.list`/`vault.secrets.delete`, the params (owner address, namespace, key) are not secret and are either publicly known (owner address) or easily guessable/observable (default namespaces, common key names), and the digest itself is unconditionally public via the on-chain allowlist. This makes exploitation plausible primarily against non-create operations and does not require compromising any key material — only reconstructing public/guessable request bytes and winning a timing race against the legitimate submission.

### Recommendation
Bind authorization to a verified request signer rather than to reproducible request content: require every gateway request to carry a signature (as `JWTBasedAuth`/`req.Auth` already supports) verifiable against the claimed owner's key, and deprecate/remove the no-`Auth` allowlist fallback in `authorizer.authorizeRequest`, or at minimum require the allowlist path to additionally verify a signature over the request from the owner's registered key before trusting the digest match.

### Proof of Concept
1. Owner `O` submits `AllowlistRequest(digest, expiry)` on-chain for a `vault.secrets.list` request with `{Namespace: "main", Owner: O}` (per `core/capabilities/vault/allow_list_based_auth_test.go:134-155`). This transaction and its calldata (including `digest`) are public.
2. Attacker `A`, without any key belonging to `O`, reconstructs the identical JSON-RPC request `{method: "vault.secrets.list", params: {Namespace: "main", Owner: O}}` — trivial since `Owner` is `O`'s public address and `Namespace` is a common/default value.
3. `A` computes the same digest via `req.Digest()` and submits the request to the Vault gateway before `O` does.
4. `allowListBasedAuth.AuthorizeRequest` (`core/capabilities/vault/allow_list_based_auth.go:34-76`) matches the digest against the on-chain allowlist entry and returns `AuthResult{workflowOwner: O}` — authorizing `A` as `O` with no proof `A` controls `O`'s key.
5. The replay guard then marks that digest consumed, so `O`'s legitimate request is subsequently rejected as "already used," while `A` has performed the list/delete operation as `O`.

```go
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
```

```go
// GetAllowlistedRequests uses contract reader to query the contract for all allowlisted requests
func (w *workflowRegistry) getAllowlistedRequests(ctx context.Context, contractReader types.ContractReader) ([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, *big.Int, *types.Head, error) {
	if contractReader == nil {
		return nil, nil, nil, errors.New("cannot fetch allow listed requests: nil contract reader")
	}
	contractBinding := types.BoundContract{
		Address: w.workflowRegistryAddress,
		Name:    WorkflowRegistryContractName,
	}

	// Read current total allowlisted requests
	var headAtLastRead *types.Head
	var totalAllowlistedRequestsResult *big.Int
	readIdentifier := contractBinding.ReadIdentifier(TotalAllowlistedRequestsMethodName)
	headAtLastRead, err := contractReader.GetLatestValueWithHeadData(
		ctx, readIdentifier, primitives.Unconfirmed, nil, &totalAllowlistedRequestsResult,
	)
	if err != nil {
		return []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}, w.lastSeenAllowlistedRequestsCount, &types.Head{Height: "0"}, errors.New("failed to get latest value with head data. error: " + err.Error())
	}
```

```go
func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
```
