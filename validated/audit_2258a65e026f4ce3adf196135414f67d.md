### Title
Vault DKG result export gated with edit-role instead of admin-role, allowing non-admin disclosure of DKG result package - ([File: core/web/router.go])

### Summary
`POST /v2/vault/dkg_results/export` is wrapped with `auth.RequiresEditRole` instead of `auth.RequiresAdminRole`, unlike every other key/secret-export route in the same file (`csa`, `eth`/`evm`, `ocr`, `ocr2`, `p2p`, `solana`, `cosmos`, `starknet`, `aptos`, `stellar`, `tron`, `sui`, `ton`, `vrf`), all of which require `RequiresAdminRole`. `VaultController.ExportDKGResult` returns the raw hex-encoded DKG result package (`v.ReportWithResultPackage`) plus its SHA256, i.e., secret DKG material, to any caller who only holds edit role.

### Finding Description
`v2Routes` registers the vault routes as: [1](#0-0) 
Compare against the pattern used for every other `*.Export` handler in the same function, e.g. CSA, ETH/EVM, OCR, OCR2, P2P, and the generic multi-chain key loop, all gated with `auth.RequiresAdminRole`: [2](#0-1) [3](#0-2) [4](#0-3) 

`VaultController.ExportDKGResult` reads the stored DKG result package for a given `instanceId` from `vault.NewVaultORM` and returns the raw hex-encoded secret material and its hash directly in the JSON API response, with no additional authorization check beyond the route-level role gate: [5](#0-4) 

Because the route only requires `auth.RequiresEditRole`, any authenticated user/token holding edit role (a lower privilege than admin) can call this endpoint and retrieve the DKG result package for any known `instanceId`, even though the handler and route are explicitly documented/named as exposing "vault/DKG material" — content that is architecturally treated as admin-only everywhere else key-export functionality exists in this router.

### Impact Explanation
This is a role/authorization inconsistency leading to disclosure of sensitive DKG secret/result material to a principal with lesser privilege (edit role) than the admin role required for functionally equivalent export operations elsewhere in the codebase (`ekc.Export`, `ocrkc.Export`, `ocr2kc.Export`, `p2pkc.Export`, `csakc.Export`, and the generic multi-chain keys export loop). This corresponds to Chainlink's "unauthorized disclosure of sensitive key/secret material via role bypass" impact class — an edit-role user can obtain DKG result packages that the system's own design intends to restrict to admins.

### Likelihood Explanation
Exploitation only requires a valid edit-role session/token (already a granted, non-admin credential) and knowledge/enumeration of a valid `instanceId` for a DKG result stored in the vault ORM. There is no rate limiting or extra secret-specific gate beyond the role check, so exploitation is a single authenticated POST request and is fully repeatable.

### Recommendation
Change the route registration in `v2Routes` to require `auth.RequiresAdminRole` for `POST /v2/vault/dkg_results/export` (and evaluate whether `verify` should also require admin, since it discloses a SHA of secret material tied to a public key, though verify does not return raw material). At minimum, align `ExportDKGResult` with the `RequiresAdminRole` pattern used consistently by every other `*.Export` handler in `core/web/router.go`.

### Proof of Concept
Go handler-level integration test plan:
1. Set up the router via `NewRouter` (or a minimal test router mirroring `v2Routes`) with a mocked `chainlink.Application` whose `GetKeyStore()`/`GetDB()` return a vault ORM containing a seeded DKG result package for a known `instanceId`.
2. Create two authenticated test clients: one with `admin` role, one with `edit` role (via `auth.Authenticate`/session/token fixtures used elsewhere in `core/web/*_test.go`, e.g. `vault_controller_test.go`).
3. Send `POST /v2/vault/dkg_results/export` with `{"instanceId": "<seeded-id>"}` as the edit-role client.
   - Expected (current buggy behavior): `200 OK` with `exportDKGResult` JSON body containing hex-encoded `ReportWithResultPackage` and its SHA256 — i.e., secret disclosure succeeds.
4. As a comparison, send `POST /v2/keys/eth/export/:address` (or `/v2/keys/ocr/export/:ID`) as the same edit-role client.
   - Expected: `403 Forbidden` due to `auth.RequiresAdminRole`.
5. Assert the inconsistency: `vault/dkg_results/export` returns 200 for edit role while equivalent key-export routes return 403 for the same edit-role credential, confirming the authorization bypass.
6. After applying the fix (`auth.RequiresAdminRole` on the vault export route), re-run the edit-role request and assert it now returns `403 Forbidden`, matching the other export endpoints.

// ExportDKGResult returns the DKGResult corresponding to the given instance ID
// "POST <application>/vault/dkg_results/export"
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
