### Title
Cross-user response hijacking via `MessageId` collision in `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Finding Description
`HandleLegacyUserMessage` stores each user's response callback keyed solely by the attacker-controlled `msg.Body.MessageId`, with no check for an existing entry before overwriting: `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` [1](#0-0) . `MessageId` is fully client-supplied and only constrained by length/format in `Message.Validate()` — it is never derived from or bound to the sender's identity/signature in a way that prevents collisions across different users, and `Sign`/`ExtractSigner` only recover the signer's address separately from `Body.Sender`, without any per-sender namespacing of `MessageId` [2](#0-1) . When a node eventually responds, `handleWebAPITriggerMessage` looks up and deletes the callback solely by `msg.Body.MessageId` and forwards the DON's response payload to whatever callback is currently stored under that key [3](#0-2) . If an attacker sends a second `web_api_trigger` request reusing a victim's in-flight `MessageId` before the DON responds, the attacker's callback silently replaces the victim's callback in the map. When the DON's response for that `MessageId` arrives, it is delivered to the attacker's callback instead of the victim's, and the victim's original request is dropped (never receives a response). No allowlist/rate-limit/uniqueness check currently exists at this point (`TODO: apply allowlist and rate-limiting here` at line 384 confirms the gap) [4](#0-3) .

### Impact Explanation
Cross-user response hijacking: an attacker with only the ability to send a single signed gateway request can capture another user's `web_api_trigger` response payload (workflow trigger execution result), and cause the victim's legitimate request to silently fail. This matches the "cross-user response confusion" / unauthorized disclosure of another user's data impact class referenced in the audit scope.

### Likelihood Explanation
The only precondition is knowledge of a victim's in-flight `MessageId` and timing the malicious request to land between the victim's send and the DON's response. `MessageId` is attacker-supplied and not validated for uniqueness, so any attacker able to submit one signed JSON-RPC message to the gateway (the minimal capability level — any external caller with a valid ECDSA key, not requiring elevated roles) can attempt this collision. Exploitability depends on the attacker being able to predict or observe a victim's `MessageId` (e.g., low-entropy or client-reused IDs, or IDs learned via logs/telemetry/side channels), which affects real-world likelihood but the code path itself provides zero protection once that ID is known — it is fully deterministic and repeatable.

### Recommendation
Do not allow a new `HandleLegacyUserMessage` call to silently overwrite an existing `savedCallbacks` entry. At minimum, check `found` before inserting and reject/error on collision, and/or scope the map key to `(Sender, MessageId)` instead of `MessageId` alone so that only the original sender's messages can ever collide with themselves. Also validate `MethodWebAPITrigger` responses from the DON against the original request's sender before dispatching to the saved callback.

### Proof of Concept
Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build handler via existing `setupHandler(t)` helper.
2. Craft `victimMsg := triggerRequest(t, victimKey, ...)` and `attackerMsg := triggerRequest(t, attackerKey, ...)` but manually force `attackerMsg.Body.MessageId = victimMsg.Body.MessageId` (re-sign after mutating so signature stays valid).
3. Call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCb)`, then immediately `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCb)`.
4. Assert `handler.savedCallbacks[MessageId].Callback == attackerCb` (victim's callback silently replaced).
5. Simulate DON response: `resp, _ := hc.ValidatedResponseFromMessage(victimMsg)` then `handler.HandleNodeMessage(ctx, resp, nodes[0].Address)`.
6. Assert `attackerCb.Wait(ctx)` returns the victim's response payload, and `victimCb.Wait(ctx)` times out/never resolves — proving cross-user response hijacking and demonstrating the isolation invariant is broken.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
