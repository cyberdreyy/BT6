### Title
Edit-role users can export another user's DKG secret material via `POST /v2/vault/dkg_results/export` - ([File: core/web/vault_controller.go])

### Summary
`VaultController.ExportDKGResult` returns the raw DKG `ReportWithResultPackage` (secret share material) for any `instanceId` supplied in the request body, with no ownership/ACL check binding the instance to the caller. The route is gated only by `auth.RequiresEditRole`, which permits any non-view/non-run user, rather than `auth.RequiresAdminRole` or any per-instance authorization.

### Finding Description
`ExportDKGResult` decodes the request body for `InstanceID`, looks it up directly via `vault.NewVaultORM(vc.App.GetDB()).ReadResultPackage(ctx, InstanceID)`, and if found, hex-encodes and returns `v.ReportWithResultPackage` (the DKG result/secret share package) plus its SHA256 digest in the JSON response: [1](#0-0) 

There is no check anywhere in this handler that the authenticated caller (obtained via `auth.RequiresEditRole` middleware) is the owner of, or otherwise authorized for, the specified `instanceId`/job/subscription. The ORM's `ReadResultPackage` performs a straight `SELECT ... FROM dkg_results WHERE instance_id = $1` with no user/job scoping column at all: [2](#0-1) 

The `RequiresEditRole` middleware only rejects `UserRoleView` and `UserRoleRun`; any user with `edit` (or `admin`) role passes, whereas `RequiresAdminRole` is the only middleware in the codebase that restricts to true admin privilege: [3](#0-2) 

Because `instanceId` values are not secret (they can be enumerated/guessed/observed via job configuration, logs, or the companion `verify` endpoint) and the export endpoint performs no ownership binding, any edit-role-authenticated caller can supply another party's `instanceId` and receive the full DKG result package — key/share material — in the response.

### Impact Explanation
This is a secret/key-material disclosure vulnerability: an edit-role credential (a role that in Chainlink's model is meant for managing jobs/bridges, not for extracting cryptographic secret shares) can retrieve another user's/job's DKG result package, including the raw report and result package bytes that back the vault's threshold-key material. This maps to the "vault/DKG secret exfiltration" impact class — key custody material leaving the node to an under-privileged caller, which could aid reconstruction of DKG secrets/shares depending on the sensitivity of `ReportWithResultPackage`.

### Likelihood Explanation
Preconditions are minimal: any valid edit-role API token or session (a common day-to-day node-operator credential level, not admin) plus a candidate `instanceId`. There is no per-request ownership check, so exploitation is a single POST with a guessed/known/leaked instance ID — fully repeatable and requires no race conditions or timing.

### Recommendation
- Change the route registration for `/v2/vault/dkg_results/export` to require `auth.RequiresAdminRole` (or introduce an explicit vault-export permission), matching the sensitivity of exported key material.
- Additionally/alternatively, add an authorization check inside `ExportDKGResult` (and `ReadResultPackage`) that binds the `instanceId` to a job/subscription owned by or accessible to the authenticated user, returning 403/404 without leaking secret payload when the caller is not authorized.

### Proof of Concept
Go handler-level integration test plan (in `core/web/vault_controller_test.go` style):
1. Seed two users: `userA` (edit role) and `userB` (edit role), and insert a `dkg_results` row for an instance created in the context of `userB`'s job/subscription (or simply any known `instance_id`).
2. Authenticate as `userA` with a valid edit-role API token/session.
3. Send `POST /v2/vault/dkg_results/export` with body `{"instanceId": "<userB's instance id>"}`.
4. Assert current behavior: HTTP 200 with `exportDKGResult` JSON payload containing hex-encoded `ReportWithResultPackage` and SHA — i.e., secret material returned to `userA`, who has no relationship to that instance.
5. Expected secure behavior (post-fix): HTTP 403/404 with no `hexPackage`/secret content in the response body, and route wrapped with `auth.RequiresAdminRole` or an ownership check rejecting cross-user access.

```go
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
```

```go
func (o *orm) ReadResultPackage(ctx context.Context, iid dkgocrtypes.InstanceID) (*dkgocrtypes.ResultPackageDatabaseValue, error) {
	var configDigest []byte
	var seqNr uint64
	var reportWithResultPackage []byte
	var signatures pq.ByteaArray
	var signerOracleIDs []byte

	query := `SELECT config_digest, seq_nr, report_with_result_package, signatures, signer_oracle_ids FROM dkg_results WHERE instance_id = $1;`
	row := o.ds.QueryRowxContext(ctx, query, iid)
	err := row.Scan(&configDigest, &seqNr, &reportWithResultPackage, &signatures, &signerOracleIDs)
	if errors.Is(err, sql.ErrNoRows) {
		return nil, nil
	}
	if err != nil {
		return nil, errors.Wrap(err, "failed to read dkg result")
	}
```

```go
// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
```
