### Title
Unauthenticated disclosure of internal service names and health error details via GET /readyz?full=true - ([File: core/web/health_controller.go])

### Summary
The `healthRoutes` registration in `core/web/router.go` wires `/readyz` to `HealthController.Readyz` on the base `api` router group with no `auth.Authenticate` wrapper, unlike `/debug`, `/v2` admin routes, etc. Any unauthenticated network client can call `GET /readyz?full=true` and receive a JSON array of every internal health-check name (e.g. `Mercury.WSRPCPool`, `CRE.DispatcherWrapper`) plus raw error strings for failing components, while the newer `PublicReadyz` handler was explicitly written to redact this same information.

### Finding Description
`healthRoutes` in [1](#0-0)  registers `r.GET("/readyz", hc.Readyz)` directly on the router group `r` (built from `api := engine.Group(...)` at [2](#0-1) ) with no authentication middleware, in contrast to `debugRoutes` which wraps `/debug` in `auth.Authenticate(...)` at [3](#0-2)  and `v2Routes` which requires session/token/admin/edit/run roles for all sensitive endpoints.

`HealthController.Readyz` at [4](#0-3)  checks `hc.App.GetHealthChecker().IsReady()`, and if the `full` query parameter is present at all (`c.GetQuery("full")`), it iterates the full map of health-check errors, builds a `presenters.Check` per check (containing `Name` — the fully qualified internal component identifier — and `Output` — the raw `err.Error()` string) and returns it via `jsonAPIResponse`. There is no session, token, or role check anywhere in this path.

This is directly contrasted by `PublicReadyz` at [5](#0-4) , whose doc comment states it is "intended for public load balancer health checks" and "never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints." The existence of this redacted sibling endpoint demonstrates that the maintainers recognize `/readyz`'s detailed output as sensitive, yet `/readyz` itself remains reachable, unauthenticated, on the same router as `/public-readyz`.

### Impact Explanation
An unauthenticated attacker who can reach the node's web server can enumerate the full internal architecture: capability/service module names (`Mercury.WSRPCPool`, `CRE.DispatcherWrapper`, etc.), and free-form error text from those subsystems (which can include connection details, chain IDs, plugin state, or other internals depending on the component's `HealthReport` implementation). This is an information-disclosure finding — it aids reconnaissance for further attacks (fingerprinting enabled products/relayers, plugin versions, failure conditions) but does not by itself grant fund movement, key disclosure, or authentication bypass. It maps to a low/informational "sensitive information disclosure" bounty class rather than a critical/high finding.

### Likelihood Explanation
No preconditions are required beyond network reachability to the node's HTTP API port — no credentials, tokens, or session. The request is a single unauthenticated `GET /readyz?full=true`, fully repeatable and requires no timing or race conditions.

### Recommendation
Require authentication (or restrict to loopback/internal network only) on the detailed `/readyz?full=true` path, or make `Readyz` redact check names/outputs by default the same way `PublicReadyz` does, only allowing full detail behind `auth.Authenticate`. Alternatively, document and enforce that `/readyz` must never be exposed on the public-facing listener and only `/public-readyz` should be exposed externally, ideally enforced by placing `/readyz` behind the authenticated route group.

### Proof of Concept
Add/extend a Go handler-level test in `core/web/health_controller_test.go`:
1. Instantiate `HealthController` with a mock `chainlink.Application` whose `GetHealthChecker()` returns a checker with at least one failing check (e.g. name `"Mercury.WSRPCPool"`, error `"connection refused"`).
2. Build a `gin.Context` for `GET /readyz?full=true` with **no** `auth.Authenticate` middleware or session/token set (simulating an anonymous request), directly invoking `hc.Readyz(c)` as the router does not require any auth for this route.
3. Assert the response body is `200`/`503` with a JSON `checks` array containing the check's `Name` (`"Mercury.WSRPCPool"`) and `Output` (`"connection refused"`) fields — matching existing `TestHealthController_Readyz` expectations.
4. Separately assert (via inspection of `router.go`'s `healthRoutes` function or an integration test hitting the real `NewRouter` output) that `/readyz` has no `auth.Authenticate` middleware in its middleware chain, while `/debug` and `/v2` routes do, confirming the route is unauthenticated by design/registration.

```go
// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
```

```go
func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}
```
