## Title
`bitcoin_block_arrival` leaves the local state machine permanently `Uninitialized` on any downstream error, wedging the signer - (File: `stacks-signer/src/v0/signer_state.rs`)

### Summary
`bitcoin_block_arrival` explicitly sets `self` to `Self::Uninitialized` via `std::mem::replace` before recomputing the state machine, with a comment claiming this is deliberate ("so that if this function errors, self is left as uninitialized") [1](#0-0) . Every subsequent fallible call uses `?` and, unlike the RIPEMD160 case where a stale pointer caused a crash on dictionary finalize, here the "resource" (the prior, valid `SignerStateMachine`) is discarded up front and never restored on the error path, so an error converts a transient failure into a permanent wedge.

### Finding Description
At the top of `bitcoin_block_arrival`, `prior_state` is taken via `mem::replace(self, Self::Uninitialized)`, and `prior_state_machine` is derived from it [2](#0-1) . Immediately after, the function calls `client.get_peer_info()?` [3](#0-2) , and later `client.get_current_and_last_sortition()?`, `cur_sortition.is_tenure_valid(...)?`, `last_sortition.is_tenure_valid(...)?`, and `Self::make_miner_state(...)?` — all before the single terminal assignment `*self = Self::Initialized(SignerStateMachine { ... })` at the very end of the function [4](#0-3) .

Because `self` was already forced to `Uninitialized` before any of these fallible calls, any `?`-propagated error (e.g., a transient RPC failure to `get_peer_info` or `get_current_and_last_sortition`, which are ordinary node/network calls, not majority-controlled) causes an early return **without restoring `self`**. The comment in the code frames this as intentional, but intentional or not, it converts every transient RPC hiccup on a burn-block arrival into a signer that is stuck in `LocalStateMachine::Uninitialized` until the next `NewBurnBlock` event happens to succeed end-to-end.

This differs from the correctly-guarded sibling function just above it (`stacks_block_arrival`), which performs the same `mem::replace` pattern but restores `*self = LocalStateMachine::Initialized(prior_state_machine)` on every one of its early-return branches before returning `Ok(())` [5](#0-4) . `bitcoin_block_arrival` has no equivalent restoration for its `?`-based error paths.

The impact chain is direct: `process_event` calls `handle_pending_update`/`bitcoin_block_arrival` on essentially every event-loop pass when a burn block arrival needs settling [6](#0-5) . While `Uninitialized`, the signer cannot produce a `StateMachineUpdate`, cannot validate/pre-commit/sign new block proposals against a miner view, and other signers observing this signer's state will see it stalled — a liveness/equivocation-guard degradation for that signer, potentially delaying the whole 70%-signature threshold if enough signers hit the same transient RPC error around the same burn block.

### Impact Explanation
This matches the "High" liveness class: a signer wedged such that it stops participating in signing valid blocks until an unrelated future event (`NewBurnBlock`) happens to complete without any RPC error. It is a single-signer, no-majority-required trigger (any StacksClient RPC failure — timeout, connection reset, node restart, or a fault-injection channel already present in this codebase for tests) suffices; no adversarial signer or majority collusion is needed.

### Likelihood Explanation
`get_peer_info` and `get_current_and_last_sortition` are ordinary node RPC calls made on every settled burn-block arrival; RPC/timeout errors against the local stacks-node are a realistic occurrence (network hiccups, node restarts, node under load during a reorg — precisely when this code path is exercised most). Given the explicit "left as uninitialized" comment, this looks like a deliberate but likely mistaken design choice (or an incomplete refactor relative to `stacks_block_arrival`'s pattern), making it plausible in production rather than purely theoretical.

### Recommendation
On every `?`-propagated error path inside `bitcoin_block_arrival` (or via a wrapping helper), restore `*self` to `LocalStateMachine::Initialized(prior_state_machine)` (or the original `prior_state` if `prior_state_machine` cannot be reliably reconstituted) before returning the error, mirroring the pattern already used in `stacks_block_arrival`. Alternatively, only commit `mem::replace(self, Self::Uninitialized)` after all fallible operations have succeeded, keeping `self` untouched until the final assignment.

### Proof of Concept
Not independently exploitable from outside the signer (it requires an internal RPC failure), so no external PoC was constructed; the wedge is demonstrated purely by code inspection:
1. Signer event loop reaches a burn-block arrival needing settlement and calls `bitcoin_block_arrival`.
2. `mem::replace(self, Self::Uninitialized)` executes, discarding the current valid state.
3. `client.get_peer_info()?` (or a later `?` call) returns `Err` due to a transient RPC/node error.
4. Function returns `Err` immediately; `self` remains `LocalStateMachine::Uninitialized`.
5. All subsequent calls to `process_event`/`try_into_update_message_with_version` on this signer fail to produce a valid state machine update until a future `bitcoin_block_arrival` call succeeds end-to-end, wedging the signer's participation for that interval.
