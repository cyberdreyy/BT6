### Title
Bridge Show endpoint discloses OutgoingToken to any authenticated role - ([File: core/web/router.go])

### Summary
The route `GET /v2/bridge_types/:BridgeName` is registered in `v2Routes` without any `auth.RequiresEditRole`/`auth.RequiresRunRole` wrapper, only requiring generic authentication (session or API token). `BridgeTypesController.Show` returns `presenters.NewBridgeResource(bt)` which unconditionally includes the `OutgoingToken` field, allowing any authenticated user regardless of role (including view-only) to retrieve the bridge's outgoing credential.

### Finding Description
In `core/web/router.go`, the bridge routes are: [1](#0-0) 
`POST`, `PATCH`, and `DELETE` on `/bridge_types` are wrapped with `auth.RequiresEditRole`, but `GET /bridge_types/:BridgeName` (`bt.Show`) is bound directly with no role check, only participating in the outer `authv2` group's generic `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)` middleware, which accepts any valid session/token irrespective of role.

`BridgeTypesController.Show` fetches the bridge and serializes it via `presenters.NewBridgeResource`: [2](#0-1) 

The presenter unconditionally copies `OutgoingToken` into the JSON response without any role-based redaction: [3](#0-2) 

`OutgoingToken` is the credential used by the node to authenticate itself to the external bridge adapter (analogous to `IncomingToken`, which is deliberately only returned on `Create`). No role gate or field redaction exists on the `Show` path, so any authenticated principal — even one holding only the view role — can call `GET /v2/bridge_types/MOCK` and receive the `outgoingToken` value in the response body.

### Impact Explanation
Exposure of `OutgoingToken` lets a low-privileged (view-role) authenticated user impersonate the Chainlink node when calling the external bridge/adapter, since that token is the secret the node presents to the adapter. This matches the Chainlink bounty "sensitive information disclosure / credential exposure enabling impersonation" impact class — it is a real authorization-exactness violation (view-role principal obtaining a credential intended to be confined to edit/admin-level operators).

### Likelihood Explanation
Any authenticated session or API token — no elevated role required — can immediately exploit this via a single GET request with a valid bridge name. This is trivially and repeatably reachable; the only precondition is possessing any valid login/token, which is explicitly in-scope for this audit (view/run-role users, restricted API tokens).

### Recommendation
Add a role check (e.g., `auth.RequiresEditRole`) to `GET /v2/bridge_types/:BridgeName` in `core/web/router.go`, consistent with the other mutating bridge routes, or redact `OutgoingToken` from the `BridgeResource` returned by `Show`/`Index` for users below edit/admin role. Also audit `GET /bridge_types` (`bt.Index`, line 269) which has the same unguarded exposure through `presenters.NewBridgeResource`.

### Proof of Concept
Go handler-level test plan (extending `core/web/bridge_types_controller_test.go`):
1. Create a bridge with a known `OutgoingToken` via an admin/edit session (`POST /v2/bridge_types`).
2. Create a second session/API token with role `view` (or `run`) only, using `cltest` helpers for view-role users (as used elsewhere in `router_test.go`/`auth_test.go`).
3. As the view-role session, perform `GET /v2/bridge_types/<name>`.
4. Assert response status is `200 OK` (not `401/403`), and assert the JSON body's `attributes.outgoingToken` equals the bridge's actual outgoing token (proving disclosure), demonstrating the missing role gate compared to `POST/PATCH/DELETE /bridge_types` which correctly return `403` for the same view-role session.

```go
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
```
