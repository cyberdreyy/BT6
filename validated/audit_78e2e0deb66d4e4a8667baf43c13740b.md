### Title
Malicious sortition winner can indefinitely refresh tenure "last activity" via stale block proposals, wedging signers so they never fall back to the prior miner - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`stacks-signer` gates fallback-to-prior-miner (the mechanism that lets signers abandon an unresponsive current-tenure miner and resume signing under the previous miner) on a per-tenure `last_activity_time` timestamp. That timestamp is refreshed not only by valid, height-advancing block proposals but also by stale/conflicting proposals that fail the height check. A single-slot miner who has won the sortition can therefore never actually produce a signable block, yet keep resending old/conflicting proposals to reset its own inactivity clock forever, preventing every signer from ever timing it out — a liveness wedge analogous to the `avgStart` reset in the `StakedExa` report, where a cheap, low-value action from one actor resets a timer another party relies on, permanently stalling their expected progress.

### Finding Description
`SortitionData::check_latest_block_in_tenure` (called from `check_block_against_signer_db_state`/`check_proposal`, see `stacks-signer/src/chainstate/mod.rs:383-479`) evaluates an incoming block proposal against the signer's local view of the tenure's last signed/pre-committed block. When the proposal does **not** advance the chain length past what is already known (i.e., it is stale or conflicting), the code still treats it as valid miner activity and calls: [1](#0-0) 

and again for the pre-commit-only case: [2](#0-1) 

Both branches call `signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())`, which unconditionally overwrites the tenure's activity timestamp: [3](#0-2) 

This timestamp is the sole liveness signal consumed by both chainstate versions' `is_timed_out` checks, which gate `check_miner_inactivity`'s decision to fall back to the prior tenure: [4](#0-3) [5](#0-4) 

The equality/wedge broken here is the same class as the `avgStart` bug: a lightweight, attacker-controlled event (here, rebroadcasting the same or a non-advancing block proposal — no valid block production, no signature threshold, no majority of signers required) resets a shared timer that other parties (the whole signer set) rely on to detect true inactivity. As long as the current sortition winner (a single actor controlling one slot) keeps sending such proposals faster than `block_proposal_timeout`/`reorg_attempts_activity_timeout`, `elapsed > timeout` in `is_timed_out` never becomes true for *any* signer independently evaluating its own local `signerdb`, so `check_miner_inactivity` (see `docs/signer-flows.md:450-533`) never triggers `make_miner_state(prior sortition)`.

### Impact Explanation
This is a High-severity liveness wedge under the given impact categories ("a signer wedged into never signing valid blocks"): the malicious miner does not need to ever produce a valid, height-advancing block. By continuously replaying/gossiping non-advancing or conflicting proposals, it keeps every signer's local activity clock fresh, blocking the entire signer set from reverting to the previous, honest miner. The tenure stalls until an external event (a new bitcoin block / new sortition) breaks the loop, at attacker cost of merely broadcasting cheap StackerDB messages — no stake majority, no valid block, no signature aggregation needed.

### Likelihood Explanation
Likelihood is high for any miner that wins a single sortition slot (a routine, permissionless occurrence) and chooses to grief instead of mine. The check that credits inactivity-suppressing "activity" runs unconditionally on every incoming proposal that fails the height check, with no independent rate limit tied to actual chain progress, and the guard windows (`reorg_attempts_activity_timeout`, freshness of `approved_time`/`signed_group`) are attacker-observable and can be timed to keep re-triggering the "still counts as activity" branches indefinitely.

### Recommendation
Do not treat proposals that fail to advance the tenure's chain length (or that merely conflict with an existing signed/pre-committed block) as unconditional evidence of miner activity for the purpose of resetting `last_activity_time`. At minimum:
- Rate-limit how often a single non-advancing proposal can refresh `last_activity_time` for a given tenure (e.g., only the first stale proposal after a real activity gap counts).
- Consider requiring a stricter signal (e.g., a proposal that at least matches the previously seen stale proposal's hash should not re-arm the timer; only genuinely new/distinct stale proposals within the reorg window should count, and only up to the `reorg_attempts_activity_timeout` bound total, not indefinitely per fresh call).
- Decouple `is_timed_out`'s liveness clock from data the current miner directly controls; anchor it more strongly to burn-block-derived time where the miner cannot manufacture "activity" cheaply.

### Proof of Concept
Conceptual reproduction using existing test scaffolding (`stacks-signer/src/chainstate/tests/v1.rs`/`v2.rs`, which already exercise `SortitionState::is_timed_out` and `SignerDb::update_last_activity_time`):
1. Set up a `SignerDb` and a `SortitionData`/tenure as in `check_sortition_timeout` (`stacks-signer/src/chainstate/tests/v1.rs:641-721`).
2. Insert an initial signed/pre-committed block at chain_length N for the tenure.
3. Repeatedly submit `BlockProposal`s with `chain_length <= N` (or duplicates of the same pre-committed block) through `check_latest_block_in_tenure`, spaced at intervals shorter than `block_proposal_timeout`.
4. Observe `signer_db.get_last_activity_time(consensus_hash)` advancing on every call (per `update_last_activity_time`, `stacks-signer/src/signerdb.rs:2248-2257`), and `SortitionState::is_timed_out` (`stacks-signer/src/chainstate/v1.rs:55-94`) never returning `true` despite no new valid block ever being produced — demonstrating the tenure never times out and the fallback to the prior miner is permanently suppressed.

Note: I was not able to fully trace the exact rate at which `stacks-node`/gossip permits repeated identical `BlockProposal` StackerDB writes to reach `check_latest_block_in_tenure` in production (i.e., whether some outer dedup exists before this check runs); a full confirmation of exploitability at network scale would require a Devin session with the running signer/test harness to reproduce end-to-end.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

impl SortitionState {
    /// Check if the sortition identified by the ConsensusHash is timed out based on
    /// the blocks within the signer db and the block proposal timeout
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        signer_db: &SignerDb,
        eval: &GlobalStateEvaluator,
        local_address: &StacksAddress,
        timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = signer_db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) =
            signer_db.get_burn_block_received_time_from_signers(eval, sortition, local_address)?
        else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = signer_db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };
        if elapsed > timeout {
            info!("Sortition has timed out";
                "sorition" => %sortition,
                "timeout" => %timeout.as_secs(),
                "elapsed" => %elapsed.as_secs()
            )
        }
        Ok(elapsed > timeout)
    }
