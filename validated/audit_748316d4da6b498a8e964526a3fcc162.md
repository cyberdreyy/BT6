### Title
APR truncation before multiplication can zero out borrower interest - ([File: contracts/strategies/idle/ProgrammableBorrower.sol])

### Summary
`ProgrammableBorrower._calcInterest` divides `borrowerApr` by `100` before multiplying it by principal and elapsed time. Because `borrowerApr` is a `1e18`-scaled percentage, any configured APR below `1e18`—that is, below 1% APR—truncates to zero. The borrower therefore accrues no contractual interest even though the configured rate is nonzero.

### Finding Description
In `ProgrammableBorrower.sol:561-563`, interest is calculated as:

```solidity
return principal * (borrowerApr / 100) * elapsed / (YEAR * ONE_TRANCHE_TOKEN);
```

The intended value is:

```solidity
principal * borrowerApr / 100 * elapsed / (YEAR * ONE_TRANCHE_TOKEN)
```

Since Solidity integer division truncates, `borrowerApr / 100` is `0` for every `borrowerApr < 1e18`. For example, an APR of `0.5e18` represents 0.5%, but `0.5e18 / 100 == 0`.

The same ordering is present in `IdleCDOEpochVariant._calcInterestWithApr`:

```solidity
return _amount * (_apr / 100) * epochDuration / (365 days * ONE_TRANCHE_TOKEN);
```

For a sub-1% configured strategy APR, this similarly computes zero expected epoch interest.

### Impact Explanation
A credit facility can legitimately use an APR below 1%; the APR cap only bounds the value at `20e18` and does not impose a minimum. In that configuration, borrower debt and epoch interest are calculated as zero rather than the contractual sub-1% rate.

For a programmable borrower with a 0.5% APR and a 100 million token principal outstanding for 365 days, expected interest is approximately 500,000 tokens, but the implementation records zero. This permanently under-credits the pool and its tranche holders unless a privileged operator manually overrides the stop-epoch interest.

### Likelihood Explanation
The bug requires a nonzero APR below `1e18`. This is within the supported configuration range and does not require malicious privileged behavior. A lender cannot trigger it independently, but once such a facility is configured, the incorrect result is deterministic and affects all accrued borrower interest while the sub-1% rate remains active.

### Recommendation
Perform division only after all multiplications:

```solidity
// contracts/strategies/idle/ProgrammableBorrower.sol
return principal * borrowerApr * elapsed / (100 * YEAR * ONE_TRANCHE_TOKEN);
```

```solidity
// contracts/IdleCDOEpochVariant.sol
return _amount * _apr * epochDuration / (100 * 365 days * ONE_TRANCHE_TOKEN);
```

Add tests for fractional percentage APRs such as `0.5e18`, `0.99e18`, and `1.01e18`.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract AprTruncationHarness is ProgrammableBorrower {
    function setAprAndPrincipal(uint256 apr, uint256 principal) external {
        borrowerApr = apr;
        borrowerPrincipal = principal;
        lastBorrowerAccrual = block.timestamp;
    }

    function calculateInterest(uint256 principal, uint256 elapsed)
        external
        view
        returns (uint256)
    {
        return _calcInterest(principal, elapsed);
    }
}

contract AprTruncationTest is Test {
    AprTruncationHarness internal borrower;

    function setUp() public {
        borrower = new AprTruncationHarness();
    }

    function testSubOnePercentAprTruncatesToZero() public {
        uint256 principal = 100_000_000e18;
        uint256 apr = 0.5e18; // 0.5% APR
        uint256 elapsed = 365 days;

        uint256 actual = borrower.calculateInterest(principal, elapsed);

        // Expected with multiply-before-divide:
        // principal * apr / 100 = 500_000e18 for one year.
        uint256 expected = 500_000e18;

        assertEq(actual, 0);
        assertEq(expected, 500_000e18);
        assertLt(actual, expected);
    }
}
```
