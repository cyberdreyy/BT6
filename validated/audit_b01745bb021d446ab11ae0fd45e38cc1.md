### Title
Zip extraction allows path traversal ("zip slip") enabling arbitrary `Chtimes`/`Mkdir`/`Chown` outside job root - (File: helpers/archives/zip_extract.go, helpers/archives/zip_extra.go)

### Summary
`ExtractZipArchive` (helpers/archives/zip_extract.go) uses each `zip.File.Name` verbatim for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile`, `os.Symlink`, `lchmod`, and later `processZipExtra` → `processZipTimestampField` calls `os.Chtimes(file.Name, ...)` on the same unsanitized name. The only path validation performed, `errorIfGitDirectory` in path_check_helper.go, checks solely for a leading `.git` path segment and never rejects `..` traversal segments, so a crafted archive entry name such as `../../other-project/cache/foo` can cause file writes, directory creation, chmod/chown, and mtime/atime changes outside the intended extraction root.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` and for each entry:
1. Calls `errorIfGitDirectory(file.Name)` — this only guards against `.git` as the first path segment [1](#0-0) , it performs no `..`/absolute-path containment check.
2. Calls `extractZipFile(file)`, which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` before dispatching to `extractZipDirectoryEntry`/`extractZipSymlinkEntry`/`extractZipFileEntry`, all of which use `file.Name` directly with `os.Mkdir`, `os.Symlink`, or `os.OpenFile` [2](#0-1) .
3. In a second loop, calls `lchmod(file.Name, file.Mode())` and `processZipExtra(&file.FileHeader)` [3](#0-2) .
4. `processZipExtra` dispatches timestamp extra fields to `processZipTimestampField(data, file)`, which — provided `file.Mode().IsDir()` or `IsRegular()` is true (both attacker-controlled via the entry's mode bits in the zip header) and the timestamp flag bit is set — calls `os.Chtimes(file.Name, acTime, modTime)` directly on the untrusted name [4](#0-3) .

Since `file.Name` and `file.Mode()` both originate from the attacker-supplied `zip.FileHeader` (job-controlled cache/artifact archive contents), and no code path canonicalizes the resolved path against the extraction root or rejects `..` segments, a malicious archive entry named e.g. `../../../home/gitlab-runner/other-project/artifacts/report.xml` will have its parent directories created via `MkdirAll`, its content written/overwritten by `extractZipFileEntry`, and afterward have its `Chtimes` mtime/atime rewritten by `processZipTimestampField` — all outside the job's own extraction directory. This is the classic "zip slip" pattern; the runner's only existing defense is `.git`-directory suppression, which does not cover directory traversal at all.

### Impact Explanation
An attacker who controls the contents of a cache or artifact zip archive consumed by a runner job can, upon extraction, write/overwrite files and mutate file timestamps/permissions/ownership (`Chtimes`, `lchmod`, and `Lchown` from `processZipUIDGidField`) at arbitrary filesystem paths reachable by the runner process, including another project's cache/artifact files or other host paths sharing the extraction filesystem (e.g. shared cache directories, `/home/gitlab-runner/*` on shell executors, or shared volumes in non-isolated executors). This matches the scoped impact: unauthorized file metadata modification/access outside the job root, potentially corrupting or disturbing another project's cache/artifact files sharing the host.

### Likelihood Explanation
The bug is reachable purely through job-controlled input: any job that uses `cache`/`artifacts` and can influence the zip file contents extracted by the runner (e.g., via a custom-built cache/artifact archive, or a compromised/malicious cache poisoning another job on a shared runner) can supply crafted `..`-containing entry names. No special privileges beyond being a normal pipeline author are required. The precondition that the extraction root is not chrooted/jailed is realistic for shell executors and any executor sharing a filesystem/cache volume across jobs, which is a common, non-exotic configuration for self-hosted or shared runners (this is a general Runner code-path bug, not merely a documented risky admin choice like shell-executor host trust — the traversal is exploitable regardless of executor type as long as extraction shares a filesystem with other jobs' data).

### Recommendation
In `extractZipFile` and in `processZipExtra`/`processZipTimestampField`/`processZipUIDGidField`, canonicalize and validate `file.Name` against the extraction root before any filesystem operation: reject entries whose cleaned, absolute resolved path (`filepath.Join(root, file.Name)`) is not lexically within `root` (using something equivalent to the common "zip slip" guard — reject `filepath.IsAbs(file.Name)` and reject paths where `filepath.Rel(root, resolved)` starts with `..`). Extend `path_check_helper.go`'s validation beyond the `.git`-only check to include this containment check, and apply it uniformly to all operations (`Mkdir`, `MkdirAll`, `OpenFile`, `Symlink`, `Chtimes`, `Lchown`, `lchmod`) in `helpers/archives/zip_extract.go` and `helpers/archives/zip_extra.go`.

### Proof of Concept
Go fuzz/unit test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    root := t.TempDir()
    outsideTarget := filepath.Join(filepath.Dir(root), "outside_marker.txt")
    _ = os.WriteFile(outsideTarget, []byte("original"), 0o644)

    // Build a zip with an entry name containing "../" that resolves outside root
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    fw, _ := zw.CreateHeader(&zip.FileHeader{
        Name:   "../outside_marker.txt",
        Method: zip.Deflate,
    })
    fw.Write([]byte("attacker-controlled content"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    prevDir, _ := os.Getwd()
    os.Chdir(root)
    defer os.Chdir(prevDir)

    err := ExtractZipArchive(zr)
    assert.NoError(t, err)

    // Assertion: content outside root must remain unchanged
    content, _ := os.ReadFile(outsideTarget)
    assert.Equal(t, "original", string(content), "zip slip: file outside extraction root was overwritten")
}
```
Expected (current, vulnerable) result: the assertion fails because `outside_marker.txt` is overwritten with attacker content, proving the traversal write; a similar test using a timestamp extra field (`ZipTimestampFieldType`) on an entry named `../outside_marker.txt` can assert that `os.Stat(outsideTarget).ModTime()` is unexpectedly changed to the attacker-supplied value, proving the `Chtimes` escape via `processZipTimestampField`.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}
