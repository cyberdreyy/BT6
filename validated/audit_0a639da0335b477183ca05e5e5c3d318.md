## Analog Found: Operator‑fee double counting from an unreconciled "gross gas" vs. "net (refund‑adjusted) gas" split

### Title
Operator-fee vault over-crediting / unbacked ETH mint from inconsistent gas-used accounting between `reward_beneficiary` and `operator_fee_refund` - (File: `crates/common/evm/src/handler.rs`, `crates/common/evm/src/l1block.rs`)

### Summary
The Puffer report's root cause is a single value (`lidoLockedETH` / `getPendingLidoETHAmount()`) being credited/debited at two different points in time under an implicit assumption that "amount requested" and "amount later reconciled" are the same, when in fact they can diverge (a LIDO slashing event). The Base analog is the OP-stack Isthmus **operator fee** settlement path in the revm-based transaction handler: the amount credited to `OPERATOR_FEE_VAULT` at `reward_beneficiary` and the amount refunded back to the caller at `reimburse_caller` are each computed from what should be *the same* "gas actually billed" quantity, but they are derived from two different gas figures — one that includes the EIP-3529 gas refund and one that does not.

### Finding Description
For a standard (non-deposit, non-EIP-8130) transaction post-Isthmus, the caller is charged the *worst-case* operator fee up front, priced on `tx.gas_limit()`, inside `chain.tx_cost_with_tx()` / `L1BlockInfo::tx_cost()`: [1](#0-0) 

At the end of execution the fee is settled in two separate handler hooks:

1. `reward_beneficiary` credits `Predeploys::OPERATOR_FEE_VAULT` using `frame_result.gas().used()`: [2](#0-1) 

2. `reimburse_caller` separately computes an "additional refund" to hand back to the caller, via `operator_fee_refund`, which is defined as the difference between the fee at `gas.limit()` and the fee at the *EIP-3529-refund-adjusted* gas amount `gas.limit() - (gas.remaining() + gas.refunded())`: [3](#0-2) [4](#0-3) 

The bug-class match to the Puffer report: `operator_fee_refund`'s "gas used" figure subtracts the SSTORE/SELFDESTRUCT refund (`gas.refunded()`), i.e. it is the *net billed gas*, while `reward_beneficiary`'s `frame_result.gas().used()` is the standard revm `Gas::used()` accessor, which reports gross execution gas (`limit - remaining`) **without** subtracting the refund. These two call sites implicitly assume "gas used for vault crediting" and "gas used for refund reconciliation" are the same quantity — exactly the same class of assumption break as Puffer's "requested == received" LIDO withdrawal amount. When a transaction earns a non-zero capped EIP-3529 refund (e.g., clearing storage slots or self-destructing a contract), `gross_used > net_used`, so:

- Vault credit = `operator_fee_charge(gross_used)`
- Caller refund = `operator_fee_charge(gas_limit) − operator_fee_charge(net_used)`
- Total paid out = `operator_fee_charge(gas_limit) + [operator_fee_charge(gross_used) − operator_fee_charge(net_used)]`

Since the caller was only charged `operator_fee_charge(gas_limit)` up front, and `operator_fee_charge(·)` is monotone increasing in gas (`gas*scalar/1e6 + constant`, or `gas*scalar*100` post-Jovian), the bracketed term is strictly positive whenever a gas refund is earned — meaning more ETH is distributed (vault + caller) than was ever debited from the caller. This is corroborated by the newer `evm2` engine, which avoids the discrepancy entirely by settling gas first and then computing both the vault credit and refund from **one single, already-refund-adjusted** `gas_used` value: [5](#0-4) 

The presence of a "single source of truth" pattern in `evm2` but a two-different-gas-figures pattern in the legacy `evm` handler is the same structural smell as the Puffer report: one code path tracks a value assuming symmetry between two points in time/computation, and the other reconciles it inconsistently.

### Impact Explanation
If confirmed, this results in ETH being minted out of thin air on every Isthmus/Jovian-era transaction that earns a net positive EIP-3529 gas refund (a common, attacker-triggerable condition — e.g., clearing previously-set storage slots). This directly maps to the required "unbacked supply" / "protocol insolvency" impact class: the operator-fee vault (and/or the caller) receives more ETH than the chain ever collected, silently inflating total L2 ETH supply relative to what was deposited/collected, which over time breaks the 1:1 ETH backing invariant the OP-stack fee-routing model depends on.

### Likelihood Explanation
Reachable by any unprivileged transaction sender: simply submit an ordinary EIP-1559/legacy transaction on Isthmus+ that triggers an SSTORE clear (or SELFDESTRUCT) refund. No special permissions, precompile access, or L1 event is required — this is a pure execution-layer transaction crafted to hit the affected code path, making the likelihood high once/if the divergent gas figures are confirmed to actually diverge (this hinges on the exact semantics of revm's `Gas::used()`, which I could not directly inspect in this session — see caveat below).

### Recommendation
Reconcile the operator-fee vault credit and the caller refund calculation in `crates/common/evm/src/handler.rs` / `crates/common/evm/src/l1block.rs` to use the exact same refund-adjusted "billed gas" value on both sides — mirroring the single-`gas_used` pattern already used by `crates/common/evm2/src/handler.rs`'s `settle_transaction`. Add a differential/parity test (like `standard_fee_parity.rs`) specifically exercising a transaction that earns a non-zero EIP-3529 refund and assert conservation: `debit_from_caller == credit_to_vault + credit_to_beneficiary + credit_to_L1_vault + refund_to_caller` exactly, with no residual mint/burn.

### Proof of Concept
Conceptual (mirroring the Puffer report's PoC limitation): construct an Isthmus/Jovian transaction whose `calls`/execution clears a previously non-zero storage slot to earn an EIP-3529 refund; compare `frame_result.gas().used()` (gross) against `gas.limit() - (gas.remaining() + gas.refunded())` (net) as used respectively by `reward_beneficiary` and `operator_fee_refund`; assert that `operator_fee_charge(gross) > operator_fee_charge(net)`, then sum all post-transaction balance deltas (caller, coinbase, `L1_FEE_VAULT`, `BASE_FEE_VAULT`, `OPERATOR_FEE_VAULT`) against the caller's pre-transaction upfront debit to show the total exceeds it by exactly `operator_fee_charge(gross) - operator_fee_charge(net)`.

**Caveat / unverified assumption:** I was not able to directly inspect the definition of `Gas::used()` (the revm `Gas` struct) within this session due to the tool-call budget being exhausted; the analysis assumes the standard revm convention that `Gas::used() == limit - remaining` (gross, pre-EIP-3529-refund), which is what makes this discrepancy real rather than cosmetic. If `Gas::used()` in this codebase is defined to already subtract the refund, then `reward_beneficiary` and `operator_fee_refund` would already agree and this finding would not hold. I recommend a Devin session with full repository access confirm the exact semantics of `Gas::used()` (and `Gas::refunded()`/`Gas::remaining()`) before treating this as a confirmed vulnerability rather than a strong candidate.

    /// Calculate the operator fee for executing this transaction.
    ///
    /// Introduced in isthmus. Prior to isthmus, the operator fee is always zero.
    pub fn operator_fee_refund(&self, gas: &Gas, spec_id: BaseSpecId) -> U256 {
        if !spec_id.is_enabled_in(BaseUpgrade::Isthmus) {
            return U256::ZERO;
        }

        let operator_cost_gas_limit =
            self.operator_fee_charge_inner(U256::from(gas.limit()), spec_id);
        let operator_cost_gas_used = self.operator_fee_charge_inner(
            U256::from(gas.limit() - (gas.remaining() + gas.refunded() as u64)),
            spec_id,
        );

        operator_cost_gas_limit.saturating_sub(operator_cost_gas_used)
    }

    fn settle_transaction(
        host: &mut Evm<'_, BaseEvmTypes>,
        envelope: &BaseTxEnvelope,
        gas: GasSettlement<BaseEvmTypes>,
    ) -> HandlerResult<TxResult<BaseEvmTypes>> {
        let caller = gas.caller;
        let basefee = host.block_env().basefee;
        let l1_fee = host.ext().l1_fee;
        // The operator fee charged upfront (on the gas limit), stashed in before_execution.
        let operator_fee_charged = host.ext().operator_fee;

        // Default settlement refunds the caller's unused gas and pays the coinbase the priority
        // fee. The base fee is credited to its vault below (the OP-stack does not burn it).
        let mut result = default_settle_gas(host, gas)?;
        let gas_used = result.tx_gas_used();

        // Refund the operator fee down from the amount charged (on the gas limit) to the gas
        // actually used; the net is credited to the operator-fee vault below.
        let operator_fee_used = Self::operator_fee(host, envelope, gas_used);
        let operator_fee_refund = operator_fee_charged.saturating_sub(operator_fee_used);
        Self::credit(host, caller, operator_fee_refund)?;

        // Distribute the collected OP-stack fees to their vaults.
        Self::credit(host, Predeploys::L1_FEE_VAULT, l1_fee)?;
        Self::credit(
            host,
            Predeploys::BASE_FEE_VAULT,
            basefee.saturating_mul(U256::from(gas_used)),
        )?;
        Self::credit(host, Predeploys::OPERATOR_FEE_VAULT, operator_fee_used)?;

        result.ext.l1_fee = l1_fee;
        Ok(result)
    }
