### Title
No path-traversal check for legacy zip extraction — MkdirAll and file writes both escape the job root regardless of entry type - ([File: helpers/archives/zip_extract.go])

### Summary
The specific claim that `extractZipFile`'s `MkdirAll(filepath.Dir(file.Name), 0o777)` call at line 63 creates directories outside the job root *only* for irregular-mode entries (FIFO/socket/device) before the type switch is technically true but understates the actual issue: `filepath.Dir(file.Name)` is never validated for `..` traversal for **any** entry type, so the same `MkdirAll` call also runs — and succeeds outside the root — for regular files, directories, and symlinks, which are then also written outside the root via `os.Mkdir`/`os.OpenFile`/`os.Symlink` at `file.Name`. There is no sandboxing/chroot check anywhere in this file, unlike the `tarzstd` extractor (`commands/helpers/archive/tarzstd/tarzstd_extractor.go`), which explicitly validates that the resolved absolute path stays under `e.dir` before calling `MkdirAll`.

### Finding Description
`extractZipFile` [1](#0-0)  unconditionally calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` before ever checking `file.Mode()`. `file.Name` comes directly from the zip's central directory (fully attacker-controlled if the attacker supplies or influences a zip archive processed here), and it is never canonicalized or checked for `..` segments or absolute paths anywhere in `ExtractZipArchive`/`extractZipFile`. The only existing validation, `errorIfGitDirectory` [2](#0-1) , only detects a `.git` prefix and is unrelated to path traversal.

Compare this to the sibling `tarzstd` extractor, which resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path that doesn't have `e.dir` as a prefix **before** calling `MkdirAll` [3](#0-2) . The zip extractor in `helpers/archives/zip_extract.go` has no equivalent check at all — this is a pre-existing, structural gap in the legacy zip path (used by `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go` [4](#0-3) ), not a bug specific to the irregular-mode branch.

So while the question's premise (MkdirAll fires before the mode-based skip) is correct, the "irregular mode" framing is a red herring: the same unguarded `MkdirAll` — followed by an actual file/dir/symlink write via `extractZipDirectoryEntry`/`extractZipSymlinkEntry`/`extractZipFileEntry` — occurs for ordinary regular-file and directory entries too. That means the true impact is not limited to "directory creation as a precursor," but full arbitrary file/symlink write outside the job root for any zip processed through this legacy path, since there's no boundary check for any entry type, not just irregular ones.

### Impact Explanation
If an attacker can get a maliciously crafted zip archive processed by `ExtractZipFile`/`ExtractZipArchive` (e.g., via the `ziplegacy` fallback extractor used for cache/artifact extraction), entries with `Name` values like `../../../../tmp/evil/x` cause directory creation and file/symlink writes outside the intended extraction root. This is a genuine path-traversal / zip-slip class issue affecting all entry types, not merely a "directory creation precursor" limited to irregular-mode entries.

### Likelihood Explanation
Feasibility depends on whether an attacker-controlled zip actually reaches this legacy code path in a real runner deployment. `ExtractZipArchive`/`ExtractZipFile` are exercised directly in `helpers/archives/zip_extract_test.go`, and the `ziplegacy` extractor is registered as an `archive.Extractor` implementation alongside `fastzip`/`tarzstd`. I was not able to fully confirm from the indexed code within the tool-call budget under what runtime conditions (`fastzip` failure fallback, specific archiver flag, etc.) the `ziplegacy` path is selected instead of `fastzip` (which likely has its own protections), nor whether caches/artifacts zips are attacker-forgeable end-to-end in the deployed pipeline flow (e.g., whether GitLab validates/re-derives artifact archives, or whether only Runner-created artifacts ever reach this decoder). This should be verified with a Devin session that traces `archive.Extractor` selection logic in `commands/helpers/archiver.go` / `commands/helpers/cache_extractor.go` / `commands/helpers/artifacts_uploader*.go` to establish the exact reachable trigger conditions.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `extractZipFile` (or to `ExtractZipArchive`) before calling `MkdirAll`/writing any entry: resolve `filepath.Abs(filepath.Join(destRoot, file.Name))`, verify the result has `destRoot` as a strict path prefix, and reject/skip the entry (with a warning, consistent with the existing `pathErrorTracker` pattern) if it does not — for every entry type, not just irregular-mode ones.

```go
// helpers/archives/zip_extract_test.go
func TestExtractZipFilePathTraversal(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        f, err := os.Create(fileName)
        require.NoError(t, err)
        zw := zip.NewWriter(f)
        w, err := zw.Create("../../evil/traversal.txt")
        require.NoError(t, err)
        _, _ = io.WriteString(w, "pwned")
        require.NoError(t, zw.Close())
        require.NoError(t, f.Close())

        cwd, _ := os.Getwd()
        err = ExtractZipFile(fileName)
        require.NoError(t, err)

        // Assert no file/dir was created outside cwd
        _, statErr := os.Stat(filepath.Join(filepath.Dir(filepath.Dir(cwd)), "evil"))
        assert.True(t, os.IsNotExist(statErr), "traversal entry escaped the extraction root")
    })
}
```
Expected (current buggy) result: the assertion fails because `../../evil/` is created outside `cwd`. After adding a root-containment check analogous to `tarzstd_extractor.go`, the test should pass.

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
