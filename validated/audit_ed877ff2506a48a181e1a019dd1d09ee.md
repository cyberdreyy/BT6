### Title
Buffer-period deposit frontruns `stopEpoch` interest realization and steals a share of epoch yield - ([File: contracts/IdleCDOEpochVariant.sol](contracts/IdleCDOEpochVariant.sol))

### Summary
In `isInterestMinted` mode the epoch's interest is credited to the CDO only when the manager calls `stopEpoch` (`mintStrategyTokens` mints the accrued interest into the vault, raising `getContractValue` and therefore `priceAA`/`priceBB` in a single transaction). During the buffer window between epochs, `depositAA`/`depositBB` remain open to any KYC'd wallet and mint tranche tokens at the *pre-interest* `priceAA`/`priceBB`. An attacker who watches the mempool (or simply times `epochEndDate`) can deposit in the same block immediately before `stopEpoch`, then request and claim a withdrawal after the interest is realized, capturing a pro-rata slice of yield that accrued entirely to pre-existing depositors. This is the credit-vault analog of frontrunning/backrunning an oracle price update: the "price" here is the tranche NAV price, and `stopEpoch` is the predictable price update.

### Finding Description
- `IdleCDOCreditVault.getContractValue` counts `_contractTokenBalance(strategyToken)` [1](#0-0) . In `isInterestMinted` mode no strategy tokens exist for the pending interest until `stopEpoch` mints them (verified by `testStopEpochMinting...`: `strategyToken.balanceOf(cdoEpoch)` increases by exactly `expectedEpochInterest` at `stopEpoch`, `IdleCreditVault.t.sol:2582`).
- `IdleCDOEpochVariant._deposit` (lines 644-650) only requires `whenNotPaused` and `isWalletAllowed`, skims donated `token`, then calls `IdleCDOCreditVault._deposit` which runs `_updateAccounting()` and mints via `_mintSharesAtCurrPrice` at `priceAA`/`priceBB` [2](#0-1) . `_updateAccounting` can only distribute gains already visible in `getContractValue`, so a buffer deposit is priced strictly before the epoch interest.
- `depositDuringEpoch` is explicitly gated (`isDepositDuringEpochDisabled`, `!isEpochRunning`, `block.timestamp >= epochEndDate`) precisely to avoid mispriced mid-epoch entry [3](#0-2) , but the ordinary `_deposit` path in the buffer has no equivalent protection: it silently mints at a stale price even though `expectedEpochInterest`/`totalInterestDueNow` is already deterministic and publicly computable (`IdleCreditVaultImpliedPrice._accruedGain` exposes exactly this accrued-but-unrealized gain [4](#0-3) ).
- Sequence (buffer phase, minted-interest mode): attacker calls `depositAA(D)` → minted `D / priceAA_pre` shares → manager's `stopEpoch` mints `I` strategy tokens → `priceAA` jumps → attacker `requestWithdraw`/`claimWithdrawRequest` redeems at the higher price. Profit ≈ `D/(NAV+D) * I`, paid by diluting existing AA holders. The symmetric direction (request withdrawal before a loss-crystallizing `stopEpoch`, re-deposit after) applies when the epoch ends at a loss.
- Existing guards do not stop it: `_skimDonatedAssets` only forwards raw `token` donations, `_updateAccounting` cannot price not-yet-minted interest, and `skipDefaultCheck`/default reverts are irrelevant on the gain path.

### Impact Explanation
Direct theft of unclaimed yield: the attacker extracts a fraction `D/(NAV+D)` of the epoch's realized interest `I` without bearing any epoch duration risk. With flash-loaned `D`, the fraction approaches the whole `I` (bounded only by `_guarded` deposit limits and KYC). Existing tranche holders' payout per share is permanently reduced.

### Likelihood Explanation
`stopEpoch` is a public, scheduled manager call (anyone can compute `epochEndDate` and the pending interest via `totalInterestDueNow`/`impliedVirtualPrice`), so the price jump is fully predictable — the same precondition as the oracle-frontrun bug class. The only requirements are a KYC-passing wallet and deposit capacity under `_guarded` limits. Profit per epoch is bounded by the epoch interest times the attacker's share of post-deposit TVL, so it is repeatable every epoch.

### Recommendation
Mint tranche tokens during buffer deposits at the *implied* price that already accounts for pending epoch interest (e.g., price shares using `getContractValue() + expectedEpochInterest - pendingWithdrawFees`, as `IdleCreditVaultImpliedPrice` already computes), or realize accrued interest inside `_updateAccounting` before minting rather than only at `stopEpoch`. Alternatively, disallow new deposits once `block.timestamp >= epochEndDate` until `stopEpoch` has executed and the new epoch has started.

### Proof of Concept
Foundry fork PoC outline (mirroring `test/foundry/IdleCreditVault.t.sol` setup):

```solidity
// setup: depositAA(10_000e6) as honest user, setIsInterestMinted(true), startEpoch
// warp to buffer: vm.warp(cdoEpoch.epochEndDate() + 1)

uint256 pricePre = cdoEpoch.virtualPrice(address(aaTranche));
uint256 expectedInterest = cdoEpoch.expectedEpochInterest(); // == lastEpochInterest to be minted

// Attacker (KYC'd, e.g. setKeyringParams bypassed in test) deposits in buffer,
// same tx ordering just before manager.stopEpoch
deal(USDC, attacker, attackDeposit);
vm.startPrank(attacker);
underlying.approve(address(cdoEpoch), attackDeposit);
idleCDO.depositAA(attackDeposit);
vm.stopPrank();

uint256 attackerShares = aaTranche.balanceOf(attacker);

// Manager honestly stops the epoch -> mints interest -> price jumps
vm.prank(manager);
cdoEpoch.stopEpoch(apr, 0);

uint256 pricePost = cdoEpoch.virtualPrice(address(aaTranche));
assertGt(pricePost, pricePre);

// Attacker requests + claims withdrawal, redeeming shares at pricePost
vm.prank(attacker);
cdoEpoch.requestWithdraw(attackerShares, address(aaTranche));
// ... claimWithdrawRequest per epoch flow ...

uint256 attackerValue = attackerShares * pricePost / 1e18;
assertGt(attackerValue, attackDeposit); // risk-free profit from epoch interest
// attackerValue - attackDeposit ≈ attackDeposit/(NAV+attackDeposit) * expectedInterest
```

Uncertainty: the exact claim path (`claimWithdrawRequest` vs `claimInstantWithdrawRequest`) and whether `allowAAWithdrawRequest` stays enabled through the stop/claim transition were not fully verified in this pass; if the withdrawal window closes, the same dilution is still capturable by simply holding the shares into the next epoch and withdrawing then. The core mispricing — buffer deposits minting at a price that excludes deterministic, publicly known pending interest in `isInterestMinted` mode — is confirmed by `getContractValue` counting only minted `strategyToken`s and the test showing `strategyToken` balance increasing by `expectedEpochInterest` exactly at `stopEpoch`.

```text
  function _accruedGain(IdleCDOEpochVariant cdo) private view returns (uint256 accruedGain) {
    uint256 duration = cdo.epochDuration();
    uint256 endDate = cdo.epochEndDate();
    uint256 startDate = endDate > duration ? endDate - duration : 0;
    if (duration == 0 || block.timestamp <= startDate) return 0;

    uint256 elapsed = block.timestamp >= endDate ? duration : block.timestamp - startDate;
    bool isProgrammable = cdo.isProgrammableBorrower();
    uint256 expectedInterest = isProgrammable ? _programmableBorrowerInterest(cdo) : cdo.expectedEpochInterest();
    uint256 pendingFees = cdo.pendingWithdrawFees();
    if (elapsed == 0 || expectedInterest <= pendingFees) return 0;

    accruedGain = expectedInterest - pendingFees;
    if (!isProgrammable) accruedGain = accruedGain * elapsed / duration;
    uint256 mgmtFee = cdo.managementFee();
    if (mgmtFee != 0) {
      // Match stop accounting: management fees reduce gains before performance fees.
      // strategyTokenBalance - unclaimedFees is the equivalent of _managedContractValue() in IdleCDOEpochVariant.sol
      uint256 strategyTokenBalance = IERC20Detailed(cdo.strategyToken()).balanceOf(address(cdo));
      uint256 fees = cdo.unclaimedFees();
      uint256 feeBase = strategyTokenBalance > fees ? strategyTokenBalance - fees : 0;
      uint256 accruedManagementFee = feeBase *
        mgmtFee *
        (block.timestamp - cdo.latestHarvestBlock()) /
        (FULL_ALLOC * 365 days);
      if (accruedManagementFee >= accruedGain) return 0;
      accruedGain -= accruedManagementFee;
    }
    accruedGain -= accruedGain * cdo.fee() / FULL_ALLOC;
  }
```
