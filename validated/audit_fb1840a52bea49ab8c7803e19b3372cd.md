### Title
Withdraw fees can be fully avoided by splitting withdraw requests so the per-request fee truncates to zero - (File: contracts/IdleCDOCreditVault.sol / contracts/strategies/idle/IdleCreditVault.sol)

### Summary
The vault charges a performance fee on withdraw interest computed as `interest * fee / FULL_ALLOC` (with `FULL_ALLOC = 100_000`), accumulated into `pendingWithdrawFees` each time a lender calls `requestWithdraw`. Because the fee is computed per request and Solidity division truncates, any single request whose accrued interest is below `FULL_ALLOC / fee` wei produces a fee of exactly zero. A tranche-token holder can split one large withdrawal into many small `requestWithdraw` calls and pay no performance fee at all, while still claiming full principal plus interest.

### Finding Description
All fee math in the credit vault stack uses floor division against `FULL_ALLOC`:

- Performance fee on gains: `unclaimedFees += (nav - _lastNAV) * fee / FULL_ALLOC` [1](#0-0) 
- Performance fee on withdraw interest (same model, per request): `_apr0Fee = _apr0InterestGross * _cdo.fee() / FULL_ALLOC` [2](#0-1) 
- Management fee: `_nav * managementFee * _duration / 3153600000000` [3](#0-2) 

`IdleCreditVault.requestWithdraw` is permissionless-gated only by `_onlyIdleCDO`, takes an arbitrary `_amount`/`_principal` per call, and records the receipt per epoch (`withdrawsRequestsByEpoch[_user][currentEpoch] += _amount`) [4](#0-3) . Nothing enforces a minimum request size or aggregates a user's requests before computing the fee, so with a configured `fee` of e.g. 10% (`fee = 10_000`), every chunk whose withdraw interest is `< 10` wei contributes `pendingWithdrawFees += 0`. A single lump withdrawal of the same total would accrue a large enough interest base to produce a nonzero fee.

The same truncation-free-splitting weakness exists in `_updateAccounting`'s gain fee and `_accrueManagementFee` [5](#0-4) : each `latestHarvestBlock` checkpoint truncates the accrued fee remainder, so forcing frequent checkpoints (any lender's deposit/withdraw triggers one) permanently discards fractional fees that would otherwise compound into a claimable `unclaimedFees` amount.

Note: the codebase already shows awareness that a truncated ratio can be harmful — `collectWithdrawFunds` explicitly reverts when `lossRecoveryPrice` rounds to zero [6](#0-5)  — but no equivalent guard exists on the fee path.

### Impact Explanation
The protocol (feeReceiver/owner via `_transferFeeUnderlyings` [7](#0-6) ) loses the entire performance fee on withdraw interest for any user who splits requests finely enough. Loss magnitude per withdrawal is `totalInterest * fee / FULL_ALLOC` — bounded by the fee rate but unbounded in aggregate across users and epochs. This is a direct, quantifiable loss of protocol revenue, not a rounding dust issue: the attacker chooses chunk size to drive the fee to exactly zero rather than merely losing a sub-wei remainder.

### Likelihood Explanation
Requires only a KYC-passed tranche holder (unprivileged) and works in any epoch phase where `requestWithdraw` is enabled (buffer/running, fixed-APR or APR0 mode — the APR0 path uses the same `* fee / FULL_ALLOC` formula). The economic constraint mirrors the external report: each request is a separate transaction, so profitability depends on gas costs versus the avoided fee. For high-value low-decimal underlyings or large positions, the avoided fee (`interest * 10%`) easily exceeds the per-call gas cost. No privileged cooperation is needed; owner/manager calls are only sequenced around (epoch start/stop proceed normally).

### Recommendation
Round the withdraw/management fee up (`(x * fee + FULL_ALLOC - 1) / FULL_ALLOC`) or enforce a minimum fee / minimum withdraw-request size so no nonzero interest escapes the fee. Alternatively, accumulate each user's request interest in a per-epoch bucket and compute the fee once at `stopEpoch`/claim time over the aggregate, matching how `apr0RateByEpoch` already aggregates per-epoch interest before settling [8](#0-7) .

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDOCreditVault} from "../contracts/IdleCDOCreditVault.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract FeeRoundingSplitTest is Test {
    IdleCDOCreditVault cdo;      // deployed per repo deploy scripts / factory
    IdleCreditVault strategy;
    IERC20Detailed underlying;   // e.g. mainnet USDC fork
    address lender = address(0xBEEF);
    uint256 constant FULL_ALLOC = 100_000;

    function test_splitWithdrawAvoidsFee() public {
        // Setup (fork mainnet, KYC-approve lender via KeyringIdleWhitelist,
        // owner sets fee = 10_000 (10%), managementFee > 0, epoch started).
        uint256 depositAmt = 1_000_000e6;
        deal(address(underlying), lender, depositAmt);
        vm.startPrank(lender);
        underlying.approve(address(cdo), depositAmt);
        cdo.depositAA(depositAmt);           // mint AA tranche tokens

        // Warp into the epoch so withdraw interest accrues.
        vm.warp(block.timestamp + 7 days);

        uint256 trancheBal = IERC20Detailed(address(cdo.AATranche())).balanceOf(lender);

        // Choose chunk size so per-request interest < FULL_ALLOC / fee wei
        // (e.g. interest per chunk <= 9 wei when fee = 10_000).
        uint256 chunks = 1_000;
        uint256 chunk = trancheBal / chunks;

        uint256 feesBefore = cdo.pendingWithdrawFees();
        for (uint256 i; i < chunks; ++i) {
            cdo.requestWithdraw(chunk, 0 /* isInstant flag per repo API */);
        }
        uint256 feesAfter = cdo.pendingWithdrawFees();

        // Baseline: same total requested in one call yields fee > 0.
        // On a fresh clone of the state, requestWithdraw(trancheBal) once:
        //   singleFee > 0
        assertEq(feesAfter - feesBefore, 0);        // split path: zero fee
        // assertGt(singleFee, 0);                  // lump path: nonzero fee

        // After stopEpoch + borrower funding, claim pays principal+interest at par.
        // stopEpoch(); borrower funds pendingWithdraws; collectWithdrawFunds(...)
        uint256 balBefore = underlying.balanceOf(lender);
        cdo.claimWithdrawRequest();                // via IdleCreditVault.claimWithdrawRequest
        assertGt(underlying.balanceOf(lender) - balBefore, 0);
        vm.stopPrank();
    }
}
```

Caveat: the exact per-request fee expression lives in `IdleCDOEpochVariant`'s withdraw-interest path (`_calcInterest`/`pendingWithdrawFees` accumulation), which I could not fully read within available iterations; the PoC assumes the standard implementation of `requestWithdraw(amount, instant)` on that variant.   function requestWithdraw(uint256 _amount, address _user, uint256 _principal) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    if (_amount == 0) return;
    if (defaultRecoveryFinalized) {
      // user should first claim old already-funded withdraw requests before requesting new ones after default
      if (_hasWithdrawRequest(_user) || instantWithdrawsRequests[_user] != 0 || postDefaultRequests[_user] != 0) {
        revert NotAllowed();
      }
      // Preserve request/claim UX after default without increasing borrower-facing pendingWithdraws.
      // The CDO passes an already-haircut amount because finalization lowered virtualPrice first.
      _burn(msg.sender, _amount);
      _mint(_user, _amount);
      postDefaultRequests[_user] = _amount;
      return;
    }
    bool isClosed = IIdleCDOEpochVariant(idleCDO).epochEndDate() == 0;
    uint256 currentEpoch = epochNumber;
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (
      lossRecoveryPrice != 0 &&
      (withdrawsRequestsByEpoch[_user][lossEpoch] != 0 ||
      (apr0Users[_user].principal != 0 && apr0Users[_user].principalEpoch == lossEpoch))
    ) {
      // A loss-adjusted receipt must be claimed before opening a later request, otherwise
      // `lastWithdrawRequest` would stop pointing to the epoch that stores its haircut.
      revert NotAllowed();
    }
    // burn strategy tokens from cdo (we don't burn future interest here, only the principal)
    _burn(msg.sender, _principal);
    // mint equal amount of strategy tokens to the user as receipt (interest included), useful in case of default
    _mint(_user, _amount);
    // A successfully closed pool already recalled all funds and has no later stopEpoch.
    if (!isClosed) {
      // Global amount that stopEpoch must source from borrower/strategy for all pending receipts.
      pendingWithdraws += _amount;
    }
    // save the epoch of the last withdraw request (buffer + epochDuration is 1 epoch)
    lastWithdrawRequest[_user] = currentEpoch;
    // APR=0 requests keep separate accounting and settle interest at stopEpoch.
    // `_amount` here is the post-management-fee principal bucket for that flow.
    if (unscaledApr == 0 && !isClosed) {
      _requestWithdrawApr0(_amount, _user);
    } else {
      // increase the withdraw requests for the user
      // we record both per-user (old, kept for compatibility) and per-epoch so
      // on finalization we can distinguish "default-epoch pending receipts"
      // from old funded receipts.
      withdrawsRequests[_user] += _amount;
      withdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    }
