### Title
Unconditional `os.MkdirAll` in `extractZipFile` pre-stages attacker-chosen directories even for entry types the switch statement explicitly ignores - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipFile` always calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` before checking the entry's type, so a zip entry with `os.ModeNamedPipe`/`os.ModeSocket`/`os.ModeDevice` and a path-traversal `Name` (e.g. `../outside/dir/x`) will still cause the parent directory chain to be created on disk, even though the subsequent `switch` branch logs a warning and explicitly declines to materialize the entry. No path validation exists anywhere in the extraction path to prevent this.

### Finding Description
In `extractZipFile`: [1](#0-0) 

`os.MkdirAll(filepath.Dir(file.Name), 0o777)` runs unconditionally at the top of the function, before the `switch file.Mode() & os.ModeType` dispatch. For `os.ModeNamedPipe, os.ModeSocket, os.ModeDevice` the switch branch only logs a warning (`"File ignored"`) and performs no file materialization — but the directory creation side effect from the `MkdirAll` call above has already occurred regardless.

The only path check performed anywhere in the extraction flow is `errorIfGitDirectory`, which merely rejects `.git`-prefixed paths: [2](#0-1) 
There is no `filepath.Clean`/`filepath.IsLocal`/prefix-containment check anywhere in `helpers/archives/zip_extract.go` or `ExtractZipArchive`: [3](#0-2) 

So a crafted zip entry `Name = "../outside/dir/x"` with mode `os.ModeNamedPipe` will cause `filepath.Dir(file.Name)` (`"../outside/dir"`) to be created via `MkdirAll` with `0o777` permissions before the switch statement discards the entry. This confirms the exact reachable path and call sequence claimed.

### Impact Explanation
This directory pre-staging by itself only creates empty directories outside the intended extraction root; it does not write file content. However, it is important to note that regular file entries (`extractZipFileEntry`) and symlink entries (`extractZipSymlinkEntry`) in this same code already have no path-containment checks at all — `os.Remove`/`os.OpenFile`/`os.Symlink` are called directly on `file.Name` without any `filepath.Clean` or root-boundary validation. So the broader path-traversal write capability already exists independent of the pipe/socket/device branch; the pipe-entry directory pre-staging is a real but narrow contributing primitive within an already-traversal-vulnerable extractor.

### Likelihood Explanation
Trivial to trigger: an attacker who controls artifact/cache zip contents (e.g. a job that produces a cache or artifact archive consumed by another job/runner operation) can include a pipe-mode entry with a `../`-prefixed name. No special privileges are required beyond the ability to supply archive content that gets extracted by the runner.

### Recommendation
Sanitize/validate `file.Name` (and any path derived from it) against the extraction root before performing any filesystem operation, including the `MkdirAll` call — e.g. use `filepath.Clean`, reject absolute paths and paths escaping the destination root (`filepath.IsLocal` or manual `strings.HasPrefix` containment check after `filepath.Join`+`Clean`), and apply this check once per entry before dispatching into `extractZipFile`, rather than only checking for `.git` paths. Additionally, move the `MkdirAll` call to happen only for entry types that will actually be materialized, or perform the path-safety check prior to the `MkdirAll`.

### Proof of Concept
```go
func TestExtractZipFile_IgnoredEntryDoesNotCreateDirs(t *testing.T) {
    dir := t.TempDir()
    // simulate extraction root
    extractRoot := filepath.Join(dir, "workdir")
    require.NoError(t, os.MkdirAll(extractRoot, 0o755))

    // build an in-memory zip with a single ModeNamedPipe entry
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    hdr := &zip.FileHeader{Name: "../outside/dir/x"}
    hdr.SetMode(os.ModeNamedPipe)
    _, err := zw.CreateHeader(hdr)
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    wd, _ := os.Getwd()
    _ = os.Chdir(extractRoot)
    defer os.Chdir(wd)

    err = ExtractZipArchive(&zr.Reader)
    require.NoError(t, err)

    _, statErr := os.Stat(filepath.Join(extractRoot, "..", "outside", "dir"))
    assert.True(t, os.IsNotExist(statErr), "directory should NOT be created for an ignored entry type")
}
```
Expected: without a fix, `statErr` will be `nil` (directory exists) because `MkdirAll` ran before the switch discarded the pipe entry, failing the assertion — proving the bug. After adding a path-containment check prior to `MkdirAll`, the directory should not exist and the test passes.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}

	}
