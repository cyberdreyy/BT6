### Title
Signer bypasses its own-tenure equivocation guard and signs a conflicting block when the node's tenure-tip RPC is unreachable - (File: stacks-signer/src/v0/signer.rs)

### Summary
This is the analog of the C4 finding: a call whose target cannot be reached is treated as if it returned success instead of being treated as "unknown/unsafe," which lets the caller proceed past a safety check it should have failed. In `Signer::handle_block_pre_commit`, the own-tenure duplicate-signature guard queries the node for the tenure's canonical tip via `get_tenure_tip`; if that RPC call errors (node unreachable, timeout, etc.), the code does not refuse to sign — it logs a warning and falls through to the signature path anyway.

### Finding Description
When the pre-commit weight threshold is reached for a block, `handle_block_pre_commit` re-checks whether the proposal conflicts with anything this signer has already signed in the *same tenure* (a guard the docs call the "own-tenure conflict guard," since the earlier `check_block_against_signer_db_state` only checks parent-tenure or same-tenure tips depending on block type and does not cover this specific carve-out): [1](#0-0) 

```rust
if conflicts.iter().any(|conflict| {
    conflict.consensus_hash == block_info.block.header.consensus_hash
        && !self.reorg_permit_stands(stacks_client, conflict)
}) {
    match stacks_client.get_tenure_tip(&block_info.block.header.consensus_hash) {
        Ok(tip) => {
            let tip_height = tip.anchored_header.height();
            if tip_height >= block_info.block.header.chain_length {
                warn!(...); // refuse to sign
                return;
            }
        }
        Err(e) => {
            warn!(
                "{self}: Failed to fetch the canonical tip of the proposed block's tenure: {e:?}. Treating the tenure as unconfirmed.";
                ...
            );
            // falls through -- no `return` here
        }
    }
}
```

Every other conflict-resolution helper in the same file (`conflict_still_blocks`, `reorg_permit_stands`) explicitly treats node errors as "leave the conflict in place" / "conflict keeps blocking," precisely because the code's own design rationale states: "Whenever the node cannot be asked, the conflict keeps blocking: that only delays the replacement until the signature goes stale, whereas wrongly signing cannot be taken back." [2](#0-1) [3](#0-2) 

This one branch is the exception: an `Err` from `get_tenure_tip` is treated as "unconfirmed" and the function proceeds toward `SIGN`, exactly like a low-level call that returns `success = true` when the target address does not exist — an inability to verify state is silently converted into "the check passed." [4](#0-3) 

The project's own documentation confirms this asymmetric behavior is intentional but flags it as the one place where "unreachable" maps to "sign" instead of "hold": [5](#0-4) 

### Impact Explanation
If a signer has already signed (or observed a group signature/acceptance for) a block in a given tenure, and a *different, conflicting* block proposal for the same tenure crosses the 70% pre-commit threshold while that signer's connection to its own stacks-node happens to fail on the `get_tenure_tip` call, the signer will sign the conflicting block instead of refusing. This directly breaks the one-per-height / non-conflicting invariant this guard exists to enforce — the exact "own-tenure conflict guard" the code comments describe as covering the case that `check_block_against_signer_db_state`'s duplicate-block check (which only runs once, at proposal time) can no longer catch. A signer producing a second, conflicting signature for the same tenure is a critical equivocation: it directly contributes bearer-instrument weight toward two competing blocks at the same height, undermining the safety guarantee that motivates every other conflict check in this file to fail closed rather than open.

### Likelihood Explanation
This requires only: (1) an attacker/miner to produce two conflicting proposals in the same tenure that both individually gather pre-commit weight from different signer subsets (already an anticipated adversarial scenario the guard is built for), and (2) a transient RPC failure between one signer and its own stacks-node at the specific moment its pre-commit threshold check runs for the second, conflicting proposal. No majority of signers, no other signer's key, and no StackerDB/auth-token access is needed — only ordinary node flakiness (restart, brief unavailability, timeout) coinciding with the threshold-crossing event, which is a plausible, attacker-influenceable timing window (an attacker can delay/pace a competing proposal's pre-commits to land during a target signer's connectivity blip).

### Recommendation
Make the error branch of the `get_tenure_tip` call in this same-tenure guard consistent with every other conflict check in the file: on `Err`, refuse to sign for now (return early) rather than falling through to `SIGN`, mirroring the "leave the conflict in place" policy used in `conflict_still_blocks` and `reorg_permit_stands`.

### Proof of Concept
1. Two conflicting block proposals `A` and `B` are produced for the same tenure at the same height (or `B` at height ≥ signer's already-signed block).
2. Signer `S` signs `A` first (recorded via `mark_locally_accepted`/`signed_self`).
3. `B` later gathers enough pre-commit weight from other signers to cross the 70% threshold and reaches `S`'s `handle_block_pre_commit` for `B`.
4. `get_signed_conflicts` returns `A` as a same-tenure conflict; `reorg_permit_stands` returns `false` (no sanctioned reorg), so the code enters the `get_tenure_tip` check block at [6](#0-5) .
5. If `S`'s call to its stacks-node's `get_tenure_tip` errors (network blip, node restart, RPC timeout), the `Err` arm logs "Treating the tenure as unconfirmed" and does not `return`.
6. Execution falls through the surrounding conflict checks and proceeds to `SIGN`, producing `S`'s signature over `B` — a second, conflicting signature from `S` in the same tenure, which is the equivocation this guard is documented to prevent.
