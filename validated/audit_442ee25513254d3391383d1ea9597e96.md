### Title
SSH executor cancellation only kills the SSH session, not the remote process group, allowing detached child processes to survive job cancellation and Cleanup() - (File: helpers/ssh/ssh_command.go)

### Summary
`Client.Run` in `helpers/ssh/ssh_command.go` handles job cancellation (`ctx.Done()`) by sending `ssh.SIGKILL` to the SSH session and closing it, then `executor.Cleanup()` in `executors/ssh/ssh.go` merely closes the underlying SSH TCP connection via `Client.Cleanup()`. Neither path kills the remote process group spawned by the job's shell script, so a script that detaches a child (`setsid ... & disown`) continues running on the shared SSH host indefinitely.

### Finding Description
`executor.Run` (executors/ssh/ssh.go:55-73) forwards the build script as `Command.Stdin` to `s.sshCommand.Run(cmd.Context, ...)`. In `Client.Run` (helpers/ssh/ssh_command.go:141-178), the remote command is executed via `session.Start(cmd.Command)`, and cancellation is handled by:
```go
case <-ctx.Done():
    _ = session.Signal(ssh.SIGKILL)
    _ = session.Close()
    return <-waitCh
```
`session.Signal` per the SSH protocol only sends a signal request tied to the specific channel/session (and many `sshd` implementations don't even honor arbitrary signal requests for exec channels), and `session.Close()` closes the SSH channel — it does not send SIGKILL/SIGTERM to a process group on the remote host. An unprivileged pipeline author fully controls `cmd.Script` (`s.BuildShell.CmdLine` + `cmd.Stdin`), so they can trivially spawn a detached process that is reparented and immune to channel closure, e.g. `setsid nohup sleep infinity </dev/null &>/dev/null & disown; exit 0`. Because the child is session-leader-detached (`setsid`) with redirected file descriptors and no PTY, closing the SSH channel or killing the login shell does not deliver any signal to it — it simply becomes an orphan reparented to init on the SSH host, unaffected by `session.Close()`.

`executor.Cleanup` (executors/ssh/ssh.go:75-78) and `Client.Cleanup` (helpers/ssh/ssh_command.go:180-184) only call `s.client.Close()`, closing the whole SSH connection — again, this affects the transport, not remote OS processes. There is no remote process-group tracking (e.g., recording a PGID and running `kill -- -PGID`), no wrapping of the script in a subshell whose PID is captured for later cleanup, and no `sshd`-level session-scoped cgroup that would reclaim resources on session end. This matches a real gap: the invariant "job resources must be reclaimed on cancellation" is violated for the SSH executor.

### Impact Explanation
Because SSH executors are configured as shared runners (`SharedBuildsDir: true` in `executors/ssh/ssh.go:86`) targeting the same remote host across builds, any pipeline author with access to a runner using this executor can leave arbitrary long-lived processes on the shared SSH host. These orphaned processes persist across job cancellation, `Cleanup()`, and even subsequent unrelated jobs/projects assigned to that runner, consuming CPU, memory, open file descriptors, or network ports on the shared host — a multi-tenant resource-exhaustion / persistence issue reachable from an ordinary `.gitlab-ci.yml` script, not requiring any privileged configuration.

### Likelihood Explanation
Highly feasible and fully reachable by an unprivileged job author: no special runner config beyond "SSH executor is configured" is needed, and the exploit is a single shell line in the job script. It is deterministic and repeatable — every job run using the same host will reproduce the orphaned-process persistence, since neither the cancellation path nor `Cleanup()` performs remote process-group cleanup.

### Recommendation
Track the remote job's process group (e.g., wrap the executed command as `exec setsid sh -c '...'` and capture its PID, or query `pgrep -P`/use a marker file) and, on `ctx.Done()` in `Client.Run` and/or in `executor.Cleanup`, issue a remote kill against the full process group/session (e.g., `ssh` a follow-up command such as `kill -KILL -- -<pgid>` or use `pkill -g <pgid>`) rather than relying solely on `session.Signal` + `session.Close`. Alternatively, run each job inside a cgroup/systemd-scope on the remote host that is torn down deterministically on session end, ensuring resources are reclaimed regardless of process detachment tricks used in the job script.

### Proof of Concept
Integration test using the existing `helpers/ssh/stub_ssh_server.go`/`stub_ssh_server_unix.go` test scaffolding:
1. Start a real/stub `sshd` (or the repo's stub SSH server) that actually forks the requested exec command as a real OS process.
2. Build a `ssh.Client`, `Connect()`, then call `Run(ctx, Command{Command: shell, Stdin: "setsid nohup sh -c 'echo $$ > /tmp/pid; sleep 300' </dev/null &>/dev/null & disown; exit 0"})`.
3. Cancel `ctx` shortly after `Run` returns (or wrap in a context with short deadline) and confirm `Run` returns via the `ctx.Done()` branch.
4. Call `Client.Cleanup()` / `executor.Cleanup()`.
5. Open a second, independent SSH connection to the same host and assert that the PID recorded in `/tmp/pid` is still present in `/proc/<pid>` (or `kill -0 <pid>` succeeds), proving the process survived cancellation and cleanup.
6. Assert failure of the invariant: expected behavior is PID not found (process reaped); actual behavior is PID still alive. [1](#0-0) [2](#0-1)

func (s *Client) Run(ctx context.Context, cmd Command) error {
	if s.client == nil {
		return errors.New("not connected")
	}

	session, err := s.client.NewSession()
	if err != nil {
		return err
	}
	defer func() { _ = session.Close() }()

	session.Stdin = strings.NewReader(cmd.Stdin)
	session.Stdout = cmd.Stdout
	session.Stderr = cmd.Stderr
	err = session.Start(cmd.Command)
	if err != nil {
		return err
	}

	waitCh := make(chan error)
	go func() {
		err := session.Wait()
		if _, ok := err.(*ssh.ExitError); ok {
			err = &ExitError{Inner: err}
		}
		waitCh <- err
	}()

	select {
	case <-ctx.Done():
		_ = session.Signal(ssh.SIGKILL)
		_ = session.Close()
		return <-waitCh

	case err := <-waitCh:
		return err
	}
}

func (s *Client) Cleanup() {
	if s.client != nil {
		_ = s.client.Close()
	}
}
