### Title
secp256k1 signature malleability enables authorization/nonce replay for programs using secp256k1 signature verification - (File: precompiles/src/secp256k1.rs, programs/sbf/rust/secp256k1_recover/src/lib.rs)

### Summary
The `secp256k1_program` precompile verification routine [4](#0-3)  and the `secp256k1_recover` syscall used by on-chain programs both accept ECDSA signatures without enforcing canonical (low-S) form. For any valid `(r, s, v)` signature over a message, the value `(r, -s mod n, v^1)` is also a distinct-but-valid signature recovering the identical public key/eth address. This is exactly the ECDSA malleability class described in the external report (SWC-117): "every signature can be used twice" when a consumer tracks "used" signatures by their exact byte value rather than a canonical nonce/identifier.

### Finding Description
`agave_precompiles::secp256k1::verify` parses the signature with `libsecp256k1::Signature::parse_standard_slice` and recovers the signer address via `libsecp256k1::recover`, with no check that `s` is in the lower half of the curve order [5](#0-4) . The repository's own `test_malleability` unit test demonstrates that both the original signature and the S-negated variant (with flipped recovery id) pass verification for the same message and eth address in a single instruction [2](#0-1) .

Likewise, the `secp256k1_recover` syscall (exposed to on-chain BPF programs via `solana_secp256k1_recover::secp256k1_recover`) is documented in-repo as accepting malleable signatures, and the malleable variant recovers to the same public key [3](#0-2) .

By contrast, the `secp256r1_program` precompile explicitly rejects non-canonical (high-S) signatures by comparing `s` against `SECP256R1_HALF_ORDER` [6](#0-5) , confirming that canonicalization is a known, applied mitigation elsewhere in the same codebase but is absent for secp256k1.

This is the direct analog of the reported certificate-controller bug: any on-chain program (e.g., token bridges, meta-transaction relayers, "gasless" transfer/permit programs, or oracle/attestation consumers) that uses the secp256k1 precompile or `secp256k1_recover` to authenticate an off-chain-signed message, and that prevents replay by storing/checking the *raw signature bytes* as a "used" marker (rather than a message hash, nonce, or the recovered address plus a separate nonce), can be trivially bypassed. An unprivileged transaction sender who observes any previously-used valid secp256k1 signature can derive the malleable counterpart signature (flip `s` and `v`) without any private key knowledge, producing a new, distinct, but equally-valid signature blob that authenticates the identical message/address. If this second signature is submitted in a new transaction, the consuming program's replay-guard sees an "unused" signature and processes the authorized action again.

### Impact Explanation
Depending on how a program built on top of this precompile enforces replay protection, this can enable: replay of a signed authorization to execute a privileged action a second time (e.g. a bridge withdrawal, permit-based token transfer, or claim), leading to unsigned/duplicate fund movement or double execution of an operation intended to be single-use. This falls under the accepted "replay or free execution" impact category, since it is fundamentally the same signature-malleability replay bypass identified in the original report, just applied to Solana's secp256k1 precompile/syscall rather than a Solidity certificate controller.

### Likelihood Explanation
Exploitation requires no privileged access — any transaction sender can construct the malleable signature from a publicly observable, previously-submitted valid signature (S-negation is a pure arithmetic operation on public data) and submit it in an ordinary transaction. The precompile itself has no built-in defense (unlike `secp256r1`), so the vulnerability's actual triggerability depends entirely on whether a downstream program naively uses raw signature bytes as its replay-protection key — a documented, common anti-pattern (this is precisely the pattern the original SWC-117 report targeted).

### Recommendation
Enforce canonical low-S signatures in the `secp256k1` precompile's `verify` function (as already done in `secp256r1::verify`), rejecting any signature whose `s` value is greater than `n/2`. Additionally/alternatively, document and encourage that any program consuming secp256k1/`secp256k1_recover` output for replay protection track a canonical nonce or a hash of the semantic message rather than the raw signature bytes.

### Proof of Concept
The existing repository test `test_malleability` in `precompiles/src/secp256k1.rs` is itself the PoC: it signs a message once, derives the S-negated/flipped-recovery-id counterpart signature purely from public signature data (`alt_signature.s = -alt_signature.s`), and shows both pass `verify()` successfully for the same eth address and message [7](#0-6) . An attacker would replicate this off-chain: observe any secp256k1-signed instruction data on-chain, compute the alternate `(s, v)` pair, and resubmit it as a new instruction against a downstream program that keys its replay-protection off the raw signature bytes.

pub fn verify(
    data: &[u8],
    instruction_datas: &[&[u8]],
    _feature_set: &FeatureSet,
) -> Result<(), PrecompileError> {
    if data.is_empty() {
        return Err(PrecompileError::InvalidInstructionDataSize);
    }
    let count = data[0] as usize;
    if count == 0 && data.len() > 1 {
        // count is zero but the instruction data indicates that is probably not
        // correct, fail the instruction to catch probable invalid secp256k1
        // instruction construction.
        return Err(PrecompileError::InvalidInstructionDataSize);
    }
    let expected_data_size = count
        .saturating_mul(SIGNATURE_OFFSETS_SERIALIZED_SIZE)
        .saturating_add(1);
    if data.len() < expected_data_size {
        return Err(PrecompileError::InvalidInstructionDataSize);
    }
    for i in 0..count {
        let start = i
            .saturating_mul(SIGNATURE_OFFSETS_SERIALIZED_SIZE)
            .saturating_add(1);
        let end = start.saturating_add(SIGNATURE_OFFSETS_SERIALIZED_SIZE);

        let offsets: SecpSignatureOffsets = bincode::deserialize(&data[start..end])
            .map_err(|_| PrecompileError::InvalidSignature)?;

        // Parse out signature
        let signature_index = offsets.signature_instruction_index as usize;
        if signature_index >= instruction_datas.len() {
            return Err(PrecompileError::InvalidInstructionDataSize);
        }
        let signature_instruction = instruction_datas[signature_index];
        let sig_start = offsets.signature_offset as usize;
        let sig_end = sig_start.saturating_add(SIGNATURE_SERIALIZED_SIZE);
        if sig_end >= signature_instruction.len() {
            return Err(PrecompileError::InvalidSignature);
        }

        let signature = libsecp256k1::Signature::parse_standard_slice(
            &signature_instruction[sig_start..sig_end],
        )
        .map_err(|_| PrecompileError::InvalidSignature)?;

        let recovery_id = libsecp256k1::RecoveryId::parse(signature_instruction[sig_end])
            .map_err(|_| PrecompileError::InvalidRecoveryId)?;

        // Parse out pubkey
        let eth_address_slice = get_data_slice(
            instruction_datas,
            offsets.eth_address_instruction_index,
            offsets.eth_address_offset,
            HASHED_PUBKEY_SERIALIZED_SIZE,
        )?;

        // Parse out message
        let message_slice = get_data_slice(
            instruction_datas,
            offsets.message_instruction_index,
            offsets.message_data_offset,
            offsets.message_data_size as usize,
        )?;

        let message_hash: [u8; 32] = solana_keccak_hasher::hash(message_slice).to_bytes();
        let pubkey = libsecp256k1::recover(
            &libsecp256k1::Message::parse_slice(&message_hash).unwrap(),
            &signature,
            &recovery_id,
        )
        .map_err(|_| PrecompileError::InvalidSignature)?;
        let eth_address = eth_address_from_pubkey(&pubkey.serialize()[1..].try_into().unwrap());

        if eth_address_slice != eth_address {
            return Err(PrecompileError::InvalidSignature);
        }
    }
    Ok(())
}
