### Title
Gateway Legacy Web-API-Trigger Handler Broadcasts Unauthorized/Unrate-Limited Requests to All DON Nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`handler.HandleLegacyUserMessage` in the gateway's legacy web-api-capabilities handler forwards any unprivileged, externally-submitted trigger message to every member of a DON without performing sender allowlisting or rate limiting at the gateway level, despite an explicit `// TODO: apply allowlist and rate-limiting here` marker in the code. This mirrors the `BasePool.swap()` vs `BasePoolV2.swap()` pattern from the external report: an older/legacy code path is missing a validation check that the newer, parallel implementation (`httpTriggerHandler` in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`) explicitly performs before dispatching to nodes.

### Finding Description
The gateway exposes a JSON-RPC/legacy HTTP endpoint (`gateway.ProcessRequest` in `core/services/gateway/gateway.go`) that, for legacy-format requests bearing a `DonId`, dispatches to `h.HandleLegacyUserMessage`: [1](#0-0) 

Inside `HandleLegacyUserMessage`, the only checks performed are: JSON payload decoding, a non-zero timestamp check, and a staleness check. Immediately after that, the code explicitly notes the missing allowlist step and then, other than checking that the method name equals `MethodWebAPITrigger`, broadcasts the request to **every** DON member: [2](#0-1) 

Compare this to the newer v2 pipeline `httpTriggerHandler.HandleUserTriggerRequest`, which validates the request, resolves the workflow, **authorizes the request** (`authorizeRequest` → JWT signature + authorized-key check via `workflowMetadataHandler.Authorize`), and **enforces per-workflow rate limiting** (`checkRateLimit`) before ever contacting a node: [3](#0-2) [4](#0-3) 

The legacy handler has no analogous `authorizeRequest`/`checkRateLimit` step — the gateway-level allowlist/rate-limit gate was never implemented for the legacy path, as the TODO comment confirms. The only downstream check is the node-side `allowedSenders`/`rateLimiter.Allow` check in `triggerConnectorHandler.processTrigger` (`core/capabilities/webapi/trigger/trigger.go` lines 79-149), which happens only *after* the message has already been sent to every DON member.

### Impact Explanation
Any unauthenticated, unprivileged HTTP client that can reach the gateway's public endpoint can submit a well-formed legacy `web_api_trigger` message (with a valid signature satisfying `Message.Validate()`, which only validates format/length, not authorization) and force the gateway to fan that message out to **all nodes in the target DON**, with no gateway-side allowlist or rate limit. This:
- Bypasses the allowlist/quota gate that the sibling v2 implementation enforces before touching nodes, allowing quota/DoS amplification: a single unprivileged request is multiplied across every DON member's ingress path.
- Increases resource consumption and attack surface on every node in the DON for arbitrary "webAPITrigger" traffic, since the *only* mitigating layer (per-workflow `allowedSenders`) executes at the node, not the gateway, and is unbounded per unauthorized submitter until it reaches that point.
- Undermines the gateway's intended role as a filtering/authorization boundary in front of the DON, which is precisely the concern the `onlyRouter`-style modifier addresses in the referenced report (a caller bypassing the router's validation layer).

This does not grant fund movement or secret disclosure directly, but it is a concrete allowlist/quota bypass at the gateway layer reachable by any unprivileged client, consistent with the "internet-facing gateway (message envelopes, allowlist/subscriptions, handlers, caches)" scope.

### Likelihood Explanation
High reachability: the legacy code path is live (used whenever `msg.Body.DonId != ""`, per `gateway.ProcessRequest`), requires no special privileges, and the only barrier is passing `Message.Validate()` (format/signature-length checks) — not an authorization check. The gap is explicitly self-documented via the TODO comment, confirming it is a known, unaddressed omission rather than a speculative concern.

### Recommendation
Implement the missing gateway-level allowlist and rate-limiting check in `HandleLegacyUserMessage` before broadcasting to DON members, mirroring the `authorizeRequest`/`checkRateLimit` gating already present in `httpTriggerHandler.HandleUserTriggerRequest`. At minimum, verify the message sender against a configured/registered allowlist and apply a rate limiter keyed by sender prior to the `don.SendToNode` fan-out loop, rather than relying solely on the node-side `triggerConnectorHandler.processTrigger` check.

### Proof of Concept
1. Craft a legacy-format JSON-RPC request with a valid `DonId`, `Method: "web_api_trigger"`, and a syntactically valid signature/payload satisfying `api.Message.Validate()` (see `core/services/gateway/api/message.go` lines 54-88).
2. POST it to the gateway's public HTTP endpoint, which routes to `gateway.ProcessRequest` → `h.HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go` lines 341-420).
3. Observe that the message is broadcast via `don.SendToNode` to every member in `h.donConfig.Members` (line 417-419) without any gateway-side allowlist or rate-limit check, unlike the equivalent v2 flow's `authorizeRequest`/`checkRateLimit` gating (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go` lines 99-106, 361-396).
4. Repeat rapidly from an unprivileged client to demonstrate unmitigated fan-out amplification to all DON nodes for a request with no gateway-side authorization.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
