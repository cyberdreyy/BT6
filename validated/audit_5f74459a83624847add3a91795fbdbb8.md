### Title
Confirmations by removed multisig members remain counted toward execution threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges requests and confirmations that were *originated* by the member being removed. It never scans other pending requests to strip confirmations previously cast by that member as a *confirmer*. As a result, a stale confirmation from an account/key that has since been removed from `members` still counts toward `num_confirmations` when a later, still-current member calls `confirm`, allowing a `Transfer`/`FunctionCall`/`DeployContract` request to execute with fewer genuinely live signers than the configured threshold.

### Finding Description
`confirm` computes quorum purely from the size of the `confirmations: HashSet<String>` recorded for a `request_id`: [1](#0-0) 

`delete_member` enforces that enough members remain (`self.members.len() - 1 >= self.num_confirmations`) and removes outstanding *requests whose originating member* (`r.member == member`) is the one being deleted, along with those requests' confirmation sets. It does **not** touch confirmation sets on other requests where the removed member had already called `confirm` as one of several confirmers: [2](#0-1) 

`assert_valid_request` (invoked from `confirm`) only checks that the *current caller* is a live member and that the request/confirmation maps exist - it never re-validates that previously stored confirmation strings in the set still correspond to live members: [3](#0-2) 

Consequently the binding "confirmations counted == confirmations from currently-live members" is broken: `confirmations.len() >= num_confirmations` can be satisfied by a mix of live and no-longer-member confirmers.

### Impact Explanation
This is a High/Critical-class issue: it lets a multisig request (e.g. `Transfer`, `FunctionCall`, `DeployContract`, or even another `AddMember`/`DeleteMember`) execute below the number of confirmations from currently authorized signers - i.e., "a multisig request executed below threshold." If a key/account is removed from the multisig (e.g., because it was compromised or an employee left), any confirmation it cast earlier on a still-pending, different request remains valid credit toward quorum. Combined with one or two additional live confirmations, funds held by the multisig account can be moved (`Transfer`) by fewer live/trusted parties than `num_confirmations` requires.

### Likelihood Explanation
Requires: (1) a pending request that a subsequently-removed member had already confirmed, and (2) enough remaining live members to add the missing confirmation(s). This is a normal, expected sequence for any multisig that rotates membership while requests are outstanding (e.g., removing a departing/compromised signer) - no attacker-controlled deployment or foundation privilege is required beyond ordinary multisig operation, and the flaw is deterministic, not probabilistic.

### Recommendation
When a member is deleted, iterate all pending requests and strip that member's entry from every `confirmations` set (not just requests it originated), or alternatively validate at `confirm`/execution time that every string in the stored confirmation set still corresponds to a member in `self.members`, discarding stale entries before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize multisig with 4 members `A, B, C, D` and `num_confirmations = 3`.
2. `A` calls `add_request` creating request `R` (`Transfer` to some account).
3. `B` calls `confirm(R)` → confirmations = `{B}`.
4. `C` calls `confirm(R)` → confirmations = `{B, C}` (one short of quorum 3).
5. Separately, members `A, C, D` (3 confirmations, satisfying quorum on a different request) execute `DeleteMember { member: B }` via `add_request_and_confirm`/`confirm`. `delete_member` removes `B` from `self.members` and removes only requests where `r.member == B` (none, since `R` was created by `A`); `R`'s confirmation set `{B, C}` is untouched.
6. `D` (still live) calls `confirm(R)`. `confirmations.len() + 1 == 3 == num_confirmations`, so `execute_request` runs the `Transfer`, even though `B` is no longer a member - the request executed with only 2 truly live confirmations (`C`, `D`) instead of the required 3.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
