### Title
Zip extraction creates world-writable directories at unvalidated, traversal-controlled paths - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` using the raw `file.Name` from the zip entry, with no check that the resolved path stays within an intended extraction root. Because `file.Name` is fully attacker-controlled zip archive metadata and is never joined against or validated against a destination root, a crafted entry name containing `../` sequences will create intermediate directories with `0o777` permissions anywhere the runner process has filesystem access, including paths outside the intended cache/artifact directory.

### Finding Description
The extraction call chain `ExtractZipFile` → `ExtractZipArchive` → `extractZipFile` → `os.MkdirAll(filepath.Dir(file.Name), 0o777)` operates directly on `file.Name` as read from the zip's central directory, with no `filepath.Clean`/root-join/prefix-check performed anywhere in the path. [1](#0-0) 
The only pre-extraction validation present is `errorIfGitDirectory`, which only rejects `.git`-prefixed paths and does nothing to prevent `../` traversal or absolute paths. [2](#0-1) 
The subsequent file write in `extractZipFileEntry` also uses the same unvalidated `file.Name` with `os.OpenFile`, confirming there is no path confinement anywhere in the extraction path. [3](#0-2) 
Because Go's `zip.Reader.File[].Name` is attacker-supplied when the archive itself is attacker-supplied (e.g., an artifact/cache zip a job produces or a job-controlled cache restore path), a name like `../../../shared-cache/other-project/x` will cause `filepath.Dir` to resolve to a path outside the intended extraction directory, and `MkdirAll` will create it (and any missing intermediate directories) with mode `0o777`.

### Impact Explanation
On systems with a shared, host-level cache/artifact directory structure across projects/jobs, a job that controls the contents of a zip being extracted (its own cache or artifact archive) can cause intermediate directories to be created outside its own confined extraction root, with world-writable permissions. This creates directories other unrelated jobs/projects sharing the host could subsequently write into (dependency confusion/poisoning), since the directories are `0o777` rather than restricted to the runner/user umask.

### Likelihood Explanation
The precondition (shared host cache/artifact directory layout across projects, typical of shell/docker executors with host-mounted cache paths) is common in real runner deployments. The exploit path requires no privilege beyond controlling the contents of a job's own cache/artifact zip, which any unprivileged pipeline author can do (e.g., via a `cache: paths` or custom artifact zip crafted with a manipulated entry name, or a crafted `.zip` used as a cache archive). No existing check in the code (only the `.git`-directory guard) stops a `../`-prefixed entry name.

### Recommendation
Before any `MkdirAll`/`OpenFile`/`Symlink` call in `extractZipFile`, resolve `file.Name` against the known extraction root using `filepath.Clean(filepath.Join(root, file.Name))` and verify the resulting path has `root` as a prefix (with a trailing separator check to avoid partial-prefix bypass), rejecting the entry otherwise. Additionally, avoid `0o777` as a fixed directory mode; derive intermediate directory permissions from a safe default (e.g., `0o755`) rather than a permissive constant, independent of the path-validation fix.

### Proof of Concept
```go
func TestExtractZipFile_PathTraversal_MkdirAllEscapesRoot(t *testing.T) {
    root := t.TempDir()
    // simulate change into the intended extraction root, as real callers do
    require.NoError(t, os.Chdir(root))

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, err := zw.Create("../../../shared-cache/other-project/x")
    require.NoError(t, err)
    _, _ = w.Write([]byte("poisoned"))
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert: the created directory must remain inside root
    escaped := filepath.Join(filepath.Dir(root), "..", "..", "shared-cache", "other-project")
    _, statErr := os.Stat(escaped)
    assert.True(t, os.IsNotExist(statErr), "directory should not have been created outside root")

    // If it were created, also assert it is not world-writable
    if statErr == nil {
        info, _ := os.Stat(escaped)
        assert.NotEqual(t, os.FileMode(0o777), info.Mode().Perm()&0o777)
    }
}
```
Expected current behavior (bug present): the directory `shared-cache/other-project` is created outside `root` with mode `0o777`, and the assertions fail, proving the traversal + permissive-mode issue.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
