### Title
Signer-side supermajority checks (`reached_agreement`/`reached_disagreement`) use floor-rounding while the canonical block-signature threshold uses ceil-rounding, causing signers to act on a weight bar lower than the true 70% supermajority - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` / `reached_disagreement`, which gate the signer's internal "global state" consensus (active miner, burn view, protocol version, tx-replay-set, and miner-capitulation logic), compute the 70%/30% weight bars with **floor** integer division. The canonical, node-enforced signature threshold `NakamotoBlockHeader::compute_voting_weight_threshold`, used both by `stackslib` block validation and by the signer's own `store_and_process_block_signature`/`handle_block_pre_commit`/`handle_block_rejection` paths, computes the same 70% bar with **ceiling** rounding. For any `total_weight` where `total_weight * 7` is not a multiple of 10, the two thresholds differ by exactly 1, so a vote tally can satisfy the signer's internal "global agreement" while falling short of the threshold the chain would require to actually accept a block signed on that basis.

### Finding Description
Two independent computations of the same 70%-supermajority constant diverge by construction:

- `libsigner/src/v0/signer_state.rs` (floor): [1](#0-0) 

- `stackslib/src/chainstate/nakamoto/mod.rs` (ceil, used to validate actual block signatures): [2](#0-1) 

The regression tests explicitly lock in the floor semantics of `reached_agreement`/`reached_disagreement` as ">=70% floor" and ">30% strict" without reconciling them to the chain's ceil-based `compute_voting_weight_threshold`: [3](#0-2) 

`reached_agreement`/`reached_disagreement` are the sole gate for several consensus-relevant signer decisions, notably `capitulate_miner_view`, which decides whether a signer should switch its local "current miner" state machine to a different miner based on gossip from other signers: [4](#0-3) 

as well as `determine_global_state`, `determine_global_burn_view`, and `determine_latest_supported_signer_protocol_version`: [5](#0-4) 

Because these code paths use the *floor* value of `total_weight*7/10` (and the *floor* of `total_weight*3/10` for the blocking-minority check), there exist `total_weight` values (any not evenly divisible such that `total_weight*7 % 10 != 0`) for which a vote weight sitting exactly on the floor bar is treated by the signer as having reached global "agreement"/"disagreement", while that same weight would be judged insufficient by `NakamotoBlockHeader::compute_voting_weight_threshold`, which is what actually gates whether the node will accept the resulting Nakamoto block's aggregated signer signatures (`verify_signer_signatures`): [6](#0-5) 

This is the same class of bug as the referenced report: two components of the same protocol independently re-derive "70% of total" using different rounding conventions, and the weaker one is used to drive a state transition (there: minting math; here: signer state-machine agreement) while the stronger one is the actual enforcement rule (there: token transfer amounts; here: block-signature acceptance).

### Impact Explanation
Since `capitulate_miner_view` (and the other `determine_*` helpers) use the weaker (floor) bar, a signer can conclude "the network has reached global agreement" on a new active miner, burn view, or protocol version with strictly less supporting weight than the 70% ceil-based supermajority the protocol elsewhere requires for a block's signer signatures to be accepted. This can cause signers to diverge in which `SignerStateMachine`/miner they consider canonical near threshold boundaries (a `total_weight`/vote-weight pair sitting in the 1-part gap between floor and ceil), i.e., different honest signers act on inconsistent "stale/threshold" views of the reward set consensus. That matches the High-impact class: "a signer ... acting on a stale reward set/threshold." In the worst case this manifests as a liveness wedge - signers split between two miner views because the internal agreement bar was crossed for a subset of signers but the corresponding block-signature threshold (`compute_voting_weight_threshold`) required by the node is never actually reachable for the "agreed" miner, stalling block production/acceptance.

### Likelihood Explanation
No majority/attacker control is required: this is a deterministic off-by-one that appears whenever `total_weight * 7` is not a multiple of 10, which is the common case for realistic signer weight distributions (only weight totals that are multiples of 10, or that happen to divide evenly, avoid the gap). It is triggered purely by honest signer gossip converging near the boundary, exactly the "high probability of occurring" scenario flagged as high severity in the analogous report.

### Recommendation
Route `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` through the same `NakamotoBlockHeader::compute_voting_weight_threshold` (ceil-based) computation used for actual block-signature acceptance, rather than an independently re-derived floor-based formula, so all components agree on a single, consistently-rounded supermajority/blocking-minority definition.

### Proof of Concept
1. Let `total_weight = 11` (achievable with normal weight distributions).
2. `NakamotoBlockHeader::compute_voting_weight_threshold(11)` computes `ceil(11*7/10) = ceil(7.7) = 8` - i.e., the chain requires **8** units of weight to accept aggregated block signatures.
3. `GlobalStateEvaluator::reached_agreement(7)` computes `7 >= floor(11*7/10) = floor(7.7) = 7` → `true` - the signer's internal logic considers **7** units of weight sufficient for "global agreement."
4. If exactly 7/11 weight of signers gossip a new `current_miner` view via `StateMachineUpdate`, any signer's `capitulate_miner_view` call (`stacks-signer/src/v0/signer_state.rs:981-1115`) will treat this as reaching agreement (via `reached_agreement`) and switch its local miner state, even though the same weight tally would be one unit short of the `compute_voting_weight_threshold` bar the chain enforces for that miner's block signatures to actually be accepted - producing signer-side state divergence unsupported by the protocol's real supermajority rule.

    /// Check if the supplied vote weight crosses the global agreement threshold.

    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

#[test]
/// Locks the joint behavior of `reached_agreement` and `reached_disagreement`
/// at a single `total_weight`:
///   - agreement: `>=` 70% (inclusive)
///   - disagreement: `>` 30% (strict)
///   - three regions: [0, 30%] neither, (30%, 70%) disagreement only,
///     [70%, total] both
///
/// Walking 0, 30%, 30%+1, 70%-1, 70% catches a flipped inequality on either
/// side and any drift between the two threshold constants. Also pins the
/// "agreement implies disagreement" relation, which holds as long as the
/// agreement threshold sits above the disagreement one.
fn thresholds_partition_weight_space() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // 0%: neither.
    assert!(!evaluator.reached_agreement(0));
    assert!(!evaluator.reached_disagreement(0));

    // Exactly 30%: strict `>`, so not yet disagreement.
    assert!(!evaluator.reached_agreement(300_000_000));
    assert!(!evaluator.reached_disagreement(300_000_000));

    // One unit past 30%: gap region, disagreement only.
    assert!(!evaluator.reached_agreement(300_000_001));
    assert!(evaluator.reached_disagreement(300_000_001));

    // One unit below 70%: still in the gap.
    assert!(!evaluator.reached_agreement(699_999_999));
    assert!(evaluator.reached_disagreement(699_999_999));

    // Exactly 70%: agreement (`>=`), and disagreement still holds since 70% > 30%.
    assert!(evaluator.reached_agreement(700_000_000));
    assert!(evaluator.reached_disagreement(700_000_000));
}
