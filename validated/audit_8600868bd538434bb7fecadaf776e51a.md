### Title
`Readyz` returns full per-check readiness details unauthenticated via `?full` param, negating the security purpose of `PublicReadyz` - ([File: core/web/health_controller.go])

### Summary
`healthRoutes` registers both `/readyz` and `/public-readyz` in the same unauthenticated `api` router group with no distinguishing auth/middleware, so both are equally reachable by any unauthenticated caller. `PublicReadyz` is documented and coded to always return only a bare status code, but `Readyz` returns detailed per-check name/status/error output when the caller supplies `?full`, so the "public vs internal" distinction claimed in the code comment does not actually exist at the application layer.

### Finding Description
`healthRoutes` wires both readiness endpoints to the same unauthenticated `api` gin group with no additional auth middleware: [1](#0-0)  and this group itself only has rate limiting and session middleware, no `auth.Authenticate`: [2](#0-1) .

`PublicReadyz` is explicitly documented as "a minimal readiness endpoint intended for public load balancer health checks" that "never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints," and its implementation only ever writes a status code: [3](#0-2) .

`Readyz`, however, checks for a `full` query parameter and, if present, serializes the full per-check name/status/error output (`presenters.Check{JAID, Name, Status, Output}`) into the JSON response body: [4](#0-3) .

Because there is no auth or network-boundary enforcement distinguishing the two routes at the application/router level, any unauthenticated caller that can reach `/readyz` can obtain the same detailed internal check information (service names, pass/fail status, and raw error text) that `PublicReadyz`'s design explicitly tries to prevent from being exposed on a publicly reachable endpoint.

The existing test suite confirms this: `TestHealthController_PublicReadyz` asserts the body is always empty even with `?full=true`, while `TestHealthController_Readyz` only checks the status code and does not assert against detail leakage on `/readyz?full=true`: [5](#0-4) .

### Impact Explanation
An unauthenticated caller reaching the node's HTTP interface can call `GET /readyz?full=true` and receive internal service/check names and raw error messages (e.g., from chain client, head tracker, tx manager, etc. health checks) that the `PublicReadyz` design intentionally withholds. This is an information-disclosure issue: it can reveal internal service topology, dependency names, and error text (potentially including internal endpoint details or configuration hints) to any unauthenticated network client, undermining the intended public/internal separation. It does not by itself grant authentication bypass, key disclosure, or fund movement, so its severity is limited to internal state/information disclosure.

### Likelihood Explanation
No preconditions or credentials are required — the endpoint is unauthenticated by design, and any client that can reach the node's web server (the same interface that serves the GraphQL API, sessions, etc.) can issue `GET /readyz?full=true`. This is fully repeatable and deterministic; whether it constitutes an exploitable issue in a given deployment depends on whether `/readyz` is reachable from outside the intended internal network — the application code itself makes no such distinction, so it cannot be relied upon as a boundary.

### Recommendation
Enforce the intended distinction at the application layer instead of relying purely on deployment/network topology: either (a) make `Readyz` ignore the `full` parameter entirely (matching `PublicReadyz`) and move the detailed check output behind an authenticated/internal-only route, or (b) require the same "no per-check details" behavior for `Readyz` unless the request is authenticated, and only allow `?full` on a route gated by `auth.Authenticate`.

### Proof of Concept
Go handler-level test plan (extending `core/web/health_controller_test.go`):
1. Start an app with a mocked `healthChecker` returning `IsReady() -> (false, map[string]error{"CheckA": errors.New("internal detail")})`.
2. `GET /public-readyz?full=true` unauthenticated — assert response body is empty (already covered by `TestHealthController_PublicReadyz`).
3. `GET /readyz?full=true` unauthenticated — assert response body is **not** empty and contains `"CheckA"` and `"internal detail"` in the JSON payload.
4. Assert this succeeds without any `Authorization`/session cookie, demonstrating that the same unauthenticated caller gets strictly more information from `/readyz` than from `/public-readyz`, contradicting the code's stated security intent for `PublicReadyz`.

	}

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func TestHealthController_Readyz(t *testing.T) {
	t.Parallel()
	var tt = []struct {

func TestHealthController_PublicReadyz(t *testing.T) {
	t.Parallel()
	var tt = []struct {
		name   string
		ready  bool
		status int
	}{
		{
			name:   "not ready",
			ready:  false,
			status: http.StatusServiceUnavailable,
		},
		{
			name:   "ready",
			ready:  true,
			status: http.StatusOK,
		},
	}
	for _, tc := range tt {
		t.Run(tc.name, func(t *testing.T) {
			t.Parallel()
			app := cltest.NewApplicationWithKey(t)
			healthChecker := new(mocks.Checker)
			healthChecker.On("Start").Return(nil).Once()
			healthChecker.On("IsReady").Return(tc.ready, nil)
			healthChecker.On("Close").Return(nil).Once()

			app.HealthChecker = healthChecker
			require.NoError(t, app.Start(t.Context()))

			client := app.NewHTTPClient(nil)

			// Base path returns status only, no body.
			resp, cleanup := client.Get("/public-readyz")
			t.Cleanup(cleanup)
			assert.Equal(t, tc.status, resp.StatusCode)
			body, err := io.ReadAll(resp.Body)
			require.NoError(t, err)
			assert.Empty(t, body)

			// ?full=true must NOT expose per-check details on this endpoint.
			respFull, cleanupFull := client.Get("/public-readyz?full=true")
			t.Cleanup(cleanupFull)
			assert.Equal(t, tc.status, respFull.StatusCode)
			bodyFull, err := io.ReadAll(respFull.Body)
			require.NoError(t, err)
			assert.Empty(t, bodyFull)
		})
	}
}
