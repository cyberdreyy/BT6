### Title
CORS wildcard-origin bypass via missing dot-boundary check in gateway HTTP server allowed-origin suffix match - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's user-facing HTTP server (`core/services/gateway/network/httpserver.go`) validates `Origin` headers against a configured allowlist that supports wildcard entries like `*.example.com`. The wildcard match strips the `*.` prefix and then performs a raw `strings.HasSuffix` comparison against the request's `Origin` host, without checking that the matched suffix is preceded by a domain-label boundary (a `.`). This is the same root-cause bug class as CVE-2022-27779 (curl trailing-dot TLD cookie bypass): improper/incomplete domain boundary validation that allows an untrusted host to be misclassified as belonging to a trusted domain.

### Finding Description
`isAllowedOrigin` in [1](#0-0)  parses both the incoming `Origin` header and each configured `CORSAllowedOrigins` entry into scheme/host/port via `splitURL`. For wildcard entries it does:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [2](#0-1) 

Because `HasSuffix` performs a raw string tail comparison, any origin host ending with the literal characters of `allowedHost` is accepted — even if it is not actually a subdomain. For an operator-configured `CORSAllowedOrigins = ["https://*.ethereum.org"]`, the reduced `allowedHost` is `ethereum.org`. An attacker-registered domain such as `evilethereum.org` or `notethereum.org` also satisfies `HasSuffix(originHost, "ethereum.org")`, since there is no requirement that the character immediately preceding the suffix match be a `.`. This directly parallels the curl CVE's flaw where a trailing dot broke a naive TLD suffix check — here a missing/omitted dot boundary breaks the subdomain suffix check.

This function gates `handleRequest`, the entry point for the gateway's internet-facing user server (`UserServerConfig`) that processes JSON-RPC requests forwarded to DON nodes: [3](#0-2) . On a successful `isAllowedOrigin` match, the server reflects the attacker's `Origin` value into `Access-Control-Allow-Origin` together with `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers`, and the gateway integration config shows `CORSEnabled = true` with `CORSAllowedOrigins` wildcard patterns being a supported, documented configuration shape [4](#0-3) .

### Impact Explanation
If a node operator configures a wildcard allowed origin (e.g., `*.ethereum.org` or `*.mycompany.com`), any attacker who registers a domain with that string as a literal suffix (no dot boundary), such as `evilethereum.org`, can serve a malicious web page at that origin. A browser visiting that page can then make credentialed cross-origin requests to the gateway's user-facing JSON-RPC endpoint, with the gateway reflecting `Access-Control-Allow-Origin: https://evilethereum.org`. This is a genuine CORS-allowlist bypass reachable by an unprivileged, arbitrary external actor — not a peer/node-operator-only issue — since the user server is explicitly the internet-facing endpoint intended for third-party dApp frontends (e.g., Remix) to submit requests, as reflected in the test fixtures using `https://remix.ethereum.org`.

### Likelihood Explanation
Exploitability depends entirely on operator configuration using a wildcard `CORSAllowedOrigins` entry (not the default, but a documented/supported pattern per the test suite `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`). Given wildcard configuration is a first-class, tested feature intended precisely to allow subdomains, and domain registration for a suffix-colliding name is trivial and cheap for an attacker, likelihood is moderate whenever wildcard CORS entries are used.

### Recommendation
Change the wildcard suffix check to require a dot boundary (or exact match) immediately preceding the suffix, e.g.:
```go
if strings.HasSuffix(originHost, "."+allowedHost) || originHost == allowedHost {
    return true
}
```
Additionally consider validating that `allowedHost` is not empty after stripping `*.`, and add regression tests asserting that `evilethereum.org` / `notethereum.org` are rejected against an `*.ethereum.org` allowlist entry.

### Proof of Concept
1. Configure the gateway user server: `CORSEnabled = true`, `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. From a malicious page hosted at `https://evilethereum.org`, send a `fetch` request to the gateway's `/user` JSON-RPC path with `Origin: https://evilethereum.org`.
3. Observe the gateway's `handleRequest` calls `isAllowedOrigin("https://evilethereum.org")` [5](#0-4) , which returns `true` because `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true`, and the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, permitting the untrusted origin's credentialed cross-origin requests.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {

		if s.isAllowedOrigin(origin) {

			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
