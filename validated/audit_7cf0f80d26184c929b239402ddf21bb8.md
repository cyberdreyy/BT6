### Title
Gateway `HandleLegacyUserMessage` Broadcasts Unfiltered, Unauthenticated User Requests to Every DON Node - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The internet-facing Gateway forwards every syntactically-valid, freshly-signed `web_api_trigger` message from an anonymous internet client to **all** members of the target DON, without ever applying an allowlist check, despite the code explicitly documenting that this check is required.

### Finding Description
`gateway.ProcessRequest` decodes an incoming HTTP request and, for legacy (DON-scoped) requests, only validates the message via `msg.Validate()` [1](#0-0) , then dispatches it to the handler's `HandleLegacyUserMessage`. `Message.Validate()` performs field-length checks and cryptographic signature extraction (`ExtractSigner`), but the "sender" it derives is simply whatever address corresponds to the (attacker-controlled, freely generatable) key used to sign the message — there is no comparison against any known/allowed sender set [2](#0-1) .

In `handler.HandleLegacyUserMessage`, after decoding the payload and checking only that the payload has a non-zero timestamp and is not stale, the code contains an explicit unresolved gap:
```go
// TODO: apply allowlist and rate-limiting here
if msg.Body.Method != MethodWebAPITrigger {
    ...
}
```
No allowlist or per-sender rate limiting is applied before the message is broadcast to `h.donConfig.Members` via `don.SendToNode` for every node in the target DON [3](#0-2) . This is precisely the "does not filter input before trusting/propagating it" bug class: the Gateway is the outlier-filtering boundary here (analogous to the PriceOracle not filtering malformed feed data before use), and the developers' own TODO acknowledges the missing control.

The only remaining check is at each individual node's `webapiTrigger` capability, which does enforce `allowedSenders`/`allowedTopics`/per-sender rate limiting before actually firing a workflow trigger [4](#0-3) . So a full workflow-execution bypass is prevented at the node layer, but the Gateway itself performs zero filtering of anonymous input before fanning it out DON-wide.

### Impact Explanation
Any unauthenticated internet client can generate an arbitrary ECDSA keypair, sign a well-formed message, and get the Gateway to unconditionally broadcast it to every node in a DON. Because there is no allowlist or rate limiting at the Gateway ingress (only downstream, per-workflow, at each node), this allows unprivileged actors to force resource consumption (signature/JSON decode, connection I/O, `SendToNode` calls) across an entire DON's node set with a single HTTP request repeated at will, and to probe/enumerate registered `allowedTopics`/response behavior via the `"no Matching Workflow Topics"` vs. rate-limit vs. unauthorized-sender error paths. This is a DoS/resource-amplification and minor information-disclosure exposure directly reachable from the internet-facing gateway.

### Likelihood Explanation
High: the endpoint is explicitly internet-facing (Gateway HTTP), requires no credentials besides a self-generated signing key, and the missing control is called out by name in a `TODO` comment in the shipped code, confirming the gap is real and not mitigated elsewhere in this code path.

### Recommendation
Implement the allowlist/rate-limiting check referenced by the TODO in `HandleLegacyUserMessage` before saving the callback and broadcasting to DON members — reject unknown/non-allowlisted senders and apply a per-sender rate limit at the Gateway ingress, not only inside the node-side `webapiTrigger` capability.

### Proof of Concept
1. Generate an arbitrary ECDSA keypair (no registration or credentials needed).
2. Craft a legacy `Message` with `Body.Method = "web_api_trigger"`, a valid `DonId`, and a `TriggerRequestPayload` containing a fresh `Timestamp` and arbitrary `Topics`.
3. Sign it with the generated key via `Message.Sign` semantics and POST it to the Gateway's HTTP endpoint.
4. `gateway.ProcessRequest` → `msg.Validate()` succeeds (only checks signature validity/format, not sender identity) [2](#0-1) .
5. `HandleLegacyUserMessage` passes the timestamp/method checks and, with no allowlist enforced, calls `don.SendToNode` for every member of `h.donConfig.Members` [5](#0-4) , repeatable at will by the same anonymous caller.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
