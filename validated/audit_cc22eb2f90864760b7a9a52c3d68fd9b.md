### Title
Missing allowlist/rate-limiting enforcement in the internet-facing gateway's legacy WebAPI trigger handler - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The `Rewards.sol` report describes a bug class where safety checks (`whenNotPaused`) reference a control mechanism (`pause()`/`unpause()`) that was never actually implemented, leaving the contract permanently unable to enforce the intended restriction. The analogous pattern exists in the Chainlink gateway's `capabilities` handler: `HandleLegacyUserMessage` contains an explicit `// TODO: apply allowlist and rate-limiting here` comment at the exact point where an authorization/allowlist check is expected, but no such check is ever implemented or invoked before the request is forwarded to every DON member.

### Finding Description
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` is the entry point for legacy (`DonId`-addressed) user requests arriving at the internet-facing gateway HTTP server, reached via `gateway.ProcessRequest` in `core/services/gateway/gateway.go`. [1](#0-0) 

The handler performs only payload decoding, timestamp/staleness checks, and a method-name check, then immediately dispatches the message to every DON member via `don.SendToNode`: [2](#0-1) 

The comment on line 384, `// TODO: apply allowlist and rate-limiting here`, is placed directly before the method check and request dispatch, indicating the developers intended to gate this path with an allowlist and rate limiter — analogous to `whenNotPaused` markers that assume an enforcement mechanism exists — but the mechanism was never wired in. [3](#0-2) 

By contrast, the sibling `vault` gateway handler in the same package family does implement a full authorization chain (`Authorizer`, `AllowListBasedAuth`, `JWTBasedAuth`, `GatewayVaultRequestProcessor`) before processing any request: [4](#0-3) [5](#0-4) 

This confirms that allowlist/authorization gating is the established security pattern for gateway-exposed handlers in this codebase, and its absence in the capabilities `handler.go` legacy path is a gap rather than a by-design omission. The only protection applied to node-originated messages in this file is `nodeRateLimiter.Allow(nodeAddr)` inside `handleWebAPIOutgoingMessage`, which limits *node*-to-gateway traffic, not *user*-to-gateway traffic; the user-facing `HandleLegacyUserMessage` path has no equivalent check. [6](#0-5) 

### Impact Explanation
Because no allowlist or rate limit is enforced on the legacy WebAPI trigger path, any unprivileged client that can reach the gateway HTTP endpoint and craft a validly-signed, non-stale message can trigger `web_api_trigger` requests broadcast to every member of a DON, unthrottled by user identity. This defeats the intended per-user/per-caller access restriction and quota controls that the codebase pattern (as demonstrated by the vault handler) treats as mandatory for gateway-exposed capability requests, enabling unauthorized job/workflow trigger fan-out and potential resource-exhaustion of DON members from an unprivileged actor.

### Likelihood Explanation
The vulnerable code path (`HandleLegacyUserMessage`) is reachable directly from the gateway's public `ProcessRequest` entry point for any legacy request that supplies a `DonId`, requiring only a well-formed request and valid message signature (handled generically by `common.ValidatedRequestFromMessage`), not an allowlisted identity. Since the TODO is unconditional and no feature flag guards it, every deployment of this handler is affected, making likelihood high for any environment exposing this legacy message path.

### Recommendation
Implement the allowlist and rate-limiting check referenced by the TODO comment in `HandleLegacyUserMessage`, mirroring the pattern used by the `vault` gateway handler (`Authorizer`/`AllowListBasedAuth` plus a per-request validator) before the method dispatch and `don.SendToNode` broadcast at lines 384–420 of `core/services/gateway/handlers/capabilities/handler.go`. At minimum, verify the requester identity against a configured allowlist and apply a per-caller rate limiter symmetric to the existing `nodeRateLimiter` before forwarding requests to DON members.

### Proof of Concept
Not independently verified against a running gateway instance; the analysis is based on static code review. A concrete PoC would require: (1) standing up a gateway configured with the `capabilities` handler, (2) crafting a legacy `web_api_trigger` request with a valid signature and non-stale timestamp from an account not present in any expected allowlist, and (3) confirming via logs/metrics that the request is broadcast to all `donConfig.Members` without any authorization or throttling rejection — which the code at lines 384–420 shows is structurally possible since no such check exists in the call path.

// NewGatewayHandler creates a Vault gateway connector handler with internal auth wiring.
// Pass a non-nil authorizer only in tests or other cases that need to override the default
// allowlist/JWT authorization chain.
func NewGatewayHandler(
	secretsService vaulttypes.SecretsService,
	connector gatewayConnector,
	workflowRegistrySyncer workflowsyncerv2.WorkflowRegistrySyncer,
	lggr logger.Logger,
	limitsFactory limits.Factory,
	authorizer Authorizer,
	auth0 *Auth0Config,
) (*GatewayHandler, error) {
	var jwtAuthService services.Service
	var jwtBasedAuth Authorizer
	if auth0 != nil {
		var err error
		jwtAuthService, err = NewJWTBasedAuth(JWTBasedAuthConfig{
			IssuerURL: auth0.IssuerURL,
			Audience:  auth0.Audience,
			TenantID:  auth0.TenantID,
		}, limitsFactory, lggr)
		if err != nil {
			return nil, fmt.Errorf("failed to create JWTBasedAuth: %w", err)
		}
		jwtBasedAuth = jwtAuthService.(Authorizer)
	}

	if authorizer == nil {
		allowListBasedAuth := NewAllowListBasedAuth(lggr, workflowRegistrySyncer)
		authorizer = NewAuthorizer(allowListBasedAuth, jwtBasedAuth, lggr)
	}

	requestValidator, err := NewRequestValidatorFromLimitsFactory(limitsFactory)
	if err != nil {
		return nil, fmt.Errorf("failed to create request validator: %w", err)
	}

	metrics, err := newMetrics()
	if err != nil {
		return nil, fmt.Errorf("failed to create metrics: %w", err)
	}

	requestProcessor, err := NewGatewayVaultRequestProcessor(requestValidator, authorizer, true, lggr)
	if err != nil {
		return nil, fmt.Errorf("failed to create gateway vault request processor: %w", err)
	}
