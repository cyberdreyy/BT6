Based on the code reviewed, `helpers/archives/zip_extract.go` performs no path sanitization when extracting zip entries.

### Title
Zip extraction lacks Zip Slip / absolute-path / symlink-target validation - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipFileEntry`, `extractZipSymlinkEntry`, `extractZipDirectoryEntry`) use `file.Name` directly as a filesystem path with no check for absolute paths, `..` traversal, or symlink targets pointing outside the extraction root. The only path-related check present (`errorIfGitDirectory`) only rejects `.git` directory entries and has nothing to do with path confinement.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and for each entry calls `extractZipFile(file)`, which does: [1](#0-0) 

- `os.MkdirAll(filepath.Dir(file.Name), 0o777)` — creates arbitrary parent directories using the raw, attacker-controlled `file.Name`, with no `filepath.Clean`, no rejection of `filepath.IsAbs(file.Name)`, and no check that the resolved path stays under a target root.
- For symlink entries (`os.ModeSymlink`), `extractZipSymlinkEntry` reads the link target directly from the archive's file content and calls `os.Symlink(string(data), file.Name)` with zero validation of the target: [2](#0-1) 
- For regular files, `extractZipFileEntry` writes content to `file.Name` (again unsanitized) via `os.OpenFile`: [3](#0-2) 

The only pre-existing safeguard, `errorIfGitDirectory`/`isPathAGitDirectory`, only detects `.git`-prefixed paths and does nothing for `../` sequences or absolute paths: [4](#0-3) 
`pathErrorTracker.actionable` only deduplicates warning logs — it does not stop extraction or validate paths, and critically `ExtractZipArchive` **always returns `nil`** regardless of any errors encountered (only warnings are logged), so nothing halts a malicious extraction: [5](#0-4) 

Go's `archive/zip` package (unlike `zip.Reader.Open`, which does sanitize) does not sanitize `File.Name` when accessed via `archive.File` — entries like `../../etc/cron.d/x` or an absolute path `/etc/cron.d/x` are passed through verbatim. There is no code anywhere in this file, `path_check_helper.go`, or `path_error_tracker.go` that calls `filepath.Clean`, rejects `filepath.IsAbs`, verifies the resolved path is a descendant of the extraction root (e.g. via `filepath.Rel` + prefix check), or restricts symlink targets. Existing unit tests (`zip_extract_test.go`) only cover a well-formed archive, `.git` warning behavior, and symlink mode preservation — none test hostile paths.

Attacker (an unprivileged pipeline author) fully controls `file.Name` and symlink target content when producing an artifact/cache zip that is later downloaded via `network/requester.go` (`network.requester.Do`) by `CacheExtractorCommand`/`ArtifactsDownloaderCommand` and extracted with `ExtractZipFile` → `ExtractZipArchive`.

### Impact Explanation
If runner extraction occurs with sufficient filesystem privileges relative to the target path (e.g., extraction into a directory the runner process can write outside of, or a build path under attacker influence combined with `../` traversal), a malicious zip can write or overwrite files outside the intended build/cache root, or plant a symlink that redirects subsequent writes elsewhere — matching the scoped impact of host file write/overwrite outside the build root.

### Likelihood Explanation
Fully feasible and repeatable: a normal GitLab user/pipeline author can produce and upload an artifact/cache archive as part of a normal job (`artifacts:` or `cache:` config), and the runner will download and extract it with `ArtifactsDownloaderCommand`/`CacheExtractorCommand` with no additional privilege required. Nothing in `ExtractZipArchive` blocks such entries, and the function unconditionally returns `nil`, meaning failures (or, on some OSes, successful malicious writes) are silently logged as warnings at most.

### Recommendation
In `extractZipFile` (and before iterating in `ExtractZipArchive`), validate each `file.Name`:
- Reject entries with `filepath.IsAbs(file.Name)`.
- Clean the path and verify, via `filepath.Rel(root, filepath.Join(root, file.Name))`, that it does not start with `..` or equal `..`.
- For symlink entries, validate that the resolved target (relative to the entry's directory) also stays within the extraction root; reject absolute symlink targets and targets that escape the root.
- Propagate these path-validation errors as hard failures (not just warnings) from `ExtractZipArchive`, rather than always returning `nil`.

func TestExtractZipArchiveRejectsPathTraversal(t *testing.T) {
    buf := new(bytes.Buffer)
    w := zip.NewWriter(buf)
    f, _ := w.Create("../evil.txt")
    _, _ = f.Write([]byte("pwned"))
    require.NoError(t, w.Close())

    r, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    tmpDir := t.TempDir()
    wd, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(wd)

    err = ExtractZipArchive(r)
    // Expect an error (or at minimum that the file was NOT written outside tmpDir)
    _, statErr := os.Stat(filepath.Join(tmpDir, "..", "evil.txt"))
    assert.True(t, os.IsNotExist(statErr), "traversal file should not exist outside root")
}

func TestExtractZipArchiveRejectsSymlinkEscape(t *testing.T) {
    buf := new(bytes.Buffer)
    w := zip.NewWriter(buf)
    hdr := &zip.FileHeader{Name: "link"}
    hdr.SetMode(os.ModeSymlink | 0o777)
    fw, _ := w.CreateHeader(hdr)
    _, _ = fw.Write([]byte("/etc/cron.d/x"))
    require.NoError(t, w.Close())

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    tmpDir := t.TempDir()
    wd, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(wd)

    err := ExtractZipArchive(r)
    target, _ := os.Readlink(filepath.Join(tmpDir, "link"))
    assert.NotEqual(t, "/etc/cron.d/x", target, "symlink should not point outside root")
}

	return

	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
