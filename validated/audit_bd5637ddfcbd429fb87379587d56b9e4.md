### Title
`Message.Validate()` binds signature to sender but never verifies the signer is authorized for the attacker-chosen `DonId`, enabling cross-DON message routing - ([File: core/services/gateway/api/message.go])

### Summary
`Message.Validate()` in `core/services/gateway/api/message.go` only checks field lengths/format and recovers the signer address into `m.Body.Sender`; it never checks that the recovered signer is a member of, or otherwise authorized to address, the DON identified by `m.Body.DonId`. `gateway.ProcessRequest` in `core/services/gateway/gateway.go` then uses the attacker-supplied `msg.Body.DonId` verbatim as `handlerKey` to select `g.handlers[handlerKey]`, so any holder of a valid ECDSA key can address any registered legacy DON handler simply by putting that DON's ID in the message body.

### Finding Description
`Validate()` performs the following checks and nothing more relevant to authorization: [1](#0-0) 
It never cross-references `m.Body.DonId` against a set of DONs the recovered `signerBytes` is registered to. The signature only proves "some private key produced this signature over this exact payload (including DonId)" — it does not prove the signer has any relationship to that DonId.

In `gateway.ProcessRequest`, for legacy requests the DON ID drives handler selection directly: [2](#0-1) 
There is no subsequent check tying `msg.Body.Sender` (the recovered signer) to the selected `handlerKey`/DON before the message is dispatched to the handler via `HandleLegacyUserMessage`.

Downstream, at least two legacy handlers forward the message to DON nodes without validating the sender against any DON-specific allowlist. The capabilities/web-api-trigger handler explicitly defers this: [3](#0-2) 
and forwards to all of that DON's node members regardless of who signed the request: [4](#0-3) 
This gap is acknowledged directly in the handler's own test suite: [5](#0-4) 
The `dummyHandler` exhibits the same pattern — it signs/validates the message and immediately fans it out to `d.donConfig.Members` with no sender check: [6](#0-5) 

Net effect: an attacker holding any valid ECDSA key (not necessarily registered anywhere) can craft a `Message` with `DonId` set to any DON that has a registered legacy handler, sign it, and have the gateway route it straight to that DON's handler/node set. `Validate()` succeeds because it only checks format, not sender-to-DON binding.

### Impact Explanation
This allows cross-DON impersonation / unauthorized capability-execution routing: a request destined for one DON's web-api-trigger (or other legacy) handler can be issued by any signer, not just parties actually authorized to trigger that DON's workflows. Depending on what the target handler does with the forwarded payload (e.g., trigger workflow execution on nodes), this can result in unauthorized job/workflow triggering on a DON the attacker was never subscribed to — matching the "unauthorized job run" bounty impact class.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only *any* ECDSA keypair capable of signing (`MessageSignatureLen`-compatible signature) — no subscription or prior registration with the target DON is required, since `Validate()`/`ExtractSigner()` accept any valid signature and there is no membership check performed before/after routing. This is trivially reproducible via `gateway.ProcessRequest` with a hand-crafted signed `Message`.

### Recommendation
Add an authorization step (either inside `Message.Validate()` given an injected DON-membership lookup, or immediately after routing in `gateway.ProcessRequest`/each `HandleLegacyUserMessage` implementation) that verifies `msg.Body.Sender` is a member of/authorized for `msg.Body.DonId` before dispatching to the handler. This should apply uniformly across all legacy handlers (`capabilities`, `dummy`, etc.), not be left as a per-handler TODO.

### Proof of Concept
Go handler-level integration test:
1. Configure a gateway with two legacy handlers for `"don-A"` and `"don-B"`, each with distinct, disjoint node member lists.
2. Generate an ECDSA key `attackerKey` that is not present in either DON's `Members` list (or is only in don-A's member/allowlist conceptually, since none currently exists).
3. Build a `Message` with `Body.DonId = "don-B"`, sign it with `attackerKey` via `msg.Sign(attackerKey)`.
4. Call `gw.ProcessRequest(ctx, encodedMsg, "")`.
5. Assert: currently the handler for `don-B` receives and forwards the request (`HandleLegacyUserMessage` invoked, `don.SendToNode` called for don-B's members) — proving the DonId was accepted purely as a routing key with no sender-authorization check.
6. Expected secure behavior: the call should be rejected (e.g., `api.UnsupportedDONIdError`-style rejection or new `SenderNotAuthorizedError`) because `attackerKey`'s address is not authorized for `don-B`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageId] = &savedCallback{msg.Body.MessageId, callback}
	don := d.don
	d.mu.Unlock()
	params, err := json.Marshal(msg)
	if err != nil {
		return err
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
