### Title
GET /v2/external_initiators (Index/Show) discloses OutgoingToken outbound callback credential to any authenticated API token holder - ([File: core/web/presenters/external_initiators.go])

### Summary
`presenters.ExternalInitiatorResource`, used by `ExternalInitiatorsController.Index` for `GET /v2/external_initiators`, serializes the `OutgoingToken` field from `bridges.ExternalInitiator` directly into the JSON response. This token is a secret generated in `bridges.NewExternalInitiator` (core/bridges/external_initiator.go:54) and is meant only to authenticate the node's outbound callback requests to the external initiator's URL, yet it is returned in plaintext to any caller who can hit the listing endpoint.

### Finding Description
`bridges.ExternalInitiator` stores two secrets meant strictly for outbound use: `OutgoingSecret` and `OutgoingToken` (core/bridges/external_initiator.go:29-30), generated once at creation time in `NewExternalInitiator` (core/bridges/external_initiator.go:54-55). These are the credentials the node itself presents when calling back into the external initiator's HTTP endpoint (`X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret`-style outbound auth), not credentials meant to be handed to node API clients.

`ExternalInitiatorsController.Index` (core/web/external_initiators_controller.go:50-59) fetches all `ExternalInitiator` rows and converts each with `presenters.NewExternalInitiatorResource(initiator)`. That presenter (core/web/presenters/external_initiators.go:57-77) explicitly copies `ei.OutgoingToken` into the `ExternalInitiatorResource.OutgoingToken` JSON field (`json:"outgoingToken"`), which is then returned as part of the paginated JSON:API response body from `GET /v2/external_initiators`.

This is not merely theoretical — the repo's own test `TestExternalInitiatorsController_Index` (core/web/external_initiators_controller_test.go:104-126) explicitly asserts `externalInitiators[0].OutgoingToken` equals the stored `OutgoingToken`, confirming the field is intentionally serialized and returned by the live handler.

Note: `OutgoingSecret` itself is NOT present in `ExternalInitiatorResource` (only `AccessKey` and `OutgoingToken` are exposed, not `OutgoingSecret` or `HashedSecret`/`Salt`), so the full outbound credential pair is not entirely disclosed — but the `OutgoingToken` half is.

### Impact Explanation
Any client capable of authenticating to the node's HTTP API (this endpoint is behind the standard node session/API-token auth in `core/web/router.go`, not gated by an elevated "admin-only" role beyond normal authenticated access) can retrieve the `OutgoingToken` for every configured external initiator via `GET /v2/external_initiators`. Since this token is used by the node to authenticate itself to the external initiator's own webhook receiver, an attacker who also controls or intercepts traffic to that external URL (or who is the operator of that external initiator service) gains the ability to verify/replay a forged callback as if it came from the legitimate node, i.e., partial credential disclosure that undermines the "secrets never leave" trust boundary for EI outbound authentication. This matches the "sensitive credential disclosure" bounty class, though impact is bounded because `OutgoingSecret` is not exposed, limiting full impersonation capability depending on how the specific EI validates the pair.

### Likelihood Explanation
Low barrier: any credential holder with normal (non-admin-restricted) access to the node's HTTP API — a valid session cookie or API token — can call `GET /v2/external_initiators` with no special role checks beyond standard authentication, and receive `OutgoingToken` for all initiators in the response body. This is deterministic and repeatable, not dependent on timing or race conditions.

### Recommendation
Redact `OutgoingToken` (and ensure `OutgoingSecret`/`HashedSecret`/`Salt` remain excluded) from `presenters.ExternalInitiatorResource` used by `Index`/Show responses; outbound credentials should only ever be returned once, at creation time, via `presenters.ExternalInitiatorAuthentication` in the `Create` response (core/web/external_initiators_controller.go:98), consistent with how `HashedSecret`/`Salt`/`AccessKey`'s secret counterpart are already withheld from the listing resource.

### Proof of Concept
Go handler-level test plan (extending `TestExternalInitiatorsController_Index` in core/web/external_initiators_controller_test.go):
1. Insert an `ExternalInitiator` via `cltest.MustInsertExternalInitiatorWithOpts` with a known `OutgoingToken` value (as already done for `eiFoo`).
2. As an authenticated (non-admin-required) API client, call `GET /v2/external_initiators`.
3. Parse the JSON:API response into `[]presenters.ExternalInitiatorResource`.
4. Assert `externalInitiators[i].OutgoingToken` is empty/absent — this assertion currently FAILS against the existing code (the existing test at line 109/126 proves the opposite: the field is populated), demonstrating the disclosure.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
