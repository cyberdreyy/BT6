### Title
Multisig request execution counts confirmations from revoked/deleted keys, allowing a request to execute below the live-member threshold - (File: `multisig/src/lib.rs`)

### Summary
`MultiSigContract::confirm` decides whether to execute a pending request purely by comparing the size of the stored `confirmations` set against `num_confirmations` [1](#0-0) . When a key is revoked via the `DeleteKey` action, the contract only purges requests that were *originated* by that key; it never scans `self.confirmations` to strip confirmations the revoked key previously cast on *other, still-pending* requests [2](#0-1) . A stale confirmation from a key that is no longer part of the multisig therefore keeps counting toward the threshold, letting a request execute with fewer live, currently-authorized approvals than `num_confirmations` requires.

### Finding Description
The contract's custody guarantee is: a request executes only once at least `num_confirmations` *currently valid* keys have approved it. The state tracked to enforce this is the `confirmations: UnorderedMap<RequestId, HashSet<PublicKey>>` map [3](#0-2) , compared against `num_confirmations` in `confirm`:
```
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
}
``` [4](#0-3) 

The only place confirmations are ever cleaned up in response to key revocation is inside the `DeleteKey` action handler, and it is scoped exclusively to requests whose `signer_pk` (the request's *originator*) equals the deleted key:
```
let request_ids: Vec<u32> = self.requests.iter()
    .filter(|(_k, r)| r.signer_pk == pk)
    .map(|(k, _r)| k)
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
self.num_requests_pk.remove(&pk);
``` [5](#0-4) 

This filter only matches the *request's creator* key, not every key that appears inside every request's `HashSet<PublicKey>` of confirmations. So if key `B` confirmed a request `R` created by key `A`, and `B` is later revoked (e.g., because it was compromised, an employee left, or the multisig owners rotate keys), `R`'s confirmation set still contains `B`'s stale approval. `R` can later execute with only `num_confirmations - 1` approvals from currently-live keys, because `B`'s dead vote still counts.

### Impact Explanation
This breaks the "confirmations counted versus live members" custody binding explicitly relevant to multisig contracts: the equality `len(confirmations recorded) == len(confirmations from currently-authorized signers)` no longer holds after any `DeleteKey` action. Since this contract typically custodies NEAR/wNEAR and gates `Transfer`, `DeployContract`, `AddKey`/`DeleteKey`, and `FunctionCall` actions purely on this counter, a request can be executed (funds transferred, keys added, contracts redeployed) while genuinely having fewer live confirmations than the configured threshold — i.e., "a multisig request executed below threshold," which is explicitly listed as a Critical-severity impact.

### Likelihood Explanation
No attacker code execution or malicious deployment is needed — this is a pure logic defect triggered by the contract's own normal, documented workflow (revoking a signing key via `DeleteKey`, which is a standard multisig maintenance operation e.g. after key rotation or suspected compromise). Any multisig instance that ever revokes a key while other pending requests carry that key's confirmation is affected; no redeploy, foundation intervention, or out-of-scope party is required to trigger the divergence.

### Recommendation
When executing `DeleteKey`, iterate over *all* entries in `self.confirmations` (not only requests whose `signer_pk` matches) and remove the deleted public key from every confirmation set, re-checking whether now-unconfirmed requests must be considered under-confirmed again. Alternatively, at `confirm`-time, validate that every public key present in a request's confirmation set is still a currently active access key for the contract before counting it toward `num_confirmations`.

### Proof of Concept
1. Initialize multisig with `num_confirmations = 3` and access keys `A`, `B`, `C`, `D`.
2. Key `A` calls `add_request` to create request `R` (e.g., `Transfer` of funds to an attacker-controlled/colluding account).
3. Key `B` calls `confirm(R)` → `confirmations[R] = {B}` (1/3).
4. Multisig owners submit and confirm a separate `DeleteKey { public_key: B }` request (e.g., because `B` is suspected compromised) — this executes via `execute_request`, which only removes requests where `signer_pk == B` (none here, since `B` didn't originate `R`); `confirmations[R]` still contains `B`.
5. Keys `C` and `D` call `confirm(R)`, bringing `confirmations[R].len() == 2` plus the caller for a resulting evaluated count `3 >= 3`, but only `A` (originator, uncounted), `C`, and `D` are actually still-live confirmers alongside the stale `B` — `R` executes with a stale, revoked key's approval substituting for a genuine third live confirmation.     fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
