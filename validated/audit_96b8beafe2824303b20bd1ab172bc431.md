### Title
`/debug/vars` exposes Go runtime expvar data to any authenticated user regardless of role (missing role check) - ([File: core/web/router.go])

### Summary
The `debugRoutes` function registers `GET /debug/vars` behind only `auth.AuthenticateBySession`, with no `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrapper, unlike virtually every other sensitive endpoint in `v2Routes`. Any authenticated user, including one with the lowest privilege `view` role, can therefore fetch process-level expvar data (memstats, cmdline, and any custom-published internal counters).

### Finding Description
`debugRoutes` in [1](#0-0)  mounts the `/debug` group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` and directly attaches `expvar.Handler()` to `/vars` with no additional role-checking middleware. Comparing this to the rest of the router, sensitive endpoints are consistently wrapped with `auth.RequiresRunRole`, `auth.RequiresEditRole`, or `auth.RequiresAdminRole` (e.g. [2](#0-1) , [3](#0-2) ). `AuthenticateBySession` in [4](#0-3)  only verifies that the session cookie maps to a valid user row and sets that user in context — it performs no role comparison. The role-check functions (`RequiresRunRole`, `RequiresEditRole`, `RequiresAdminRole`) are separate, opt-in wrappers defined in [5](#0-4) , and `debugRoutes` never applies any of them. Consequently, a user provisioned with only the `view` role (the lowest privilege tier) can successfully authenticate via session and hit `GET /debug/vars`, receiving the full expvar JSON payload (Go runtime `memstats`, `cmdline`, and any other variables published via `expvar.Publish` elsewhere in the process).

### Impact Explanation
This is an authorization-exactness / least-privilege violation: a view-only user obtains process-level internals (command-line arguments, memory statistics, and potentially other custom-published internal counters/paths) that are not intended to be visible to that role. While expvar data by itself is not typically credential material, it can leak internal implementation details, resource usage patterns, and process arguments that aid further reconnaissance/targeting of the node — this falls under "information disclosure via role/authorization bypass," a real bypass of the app's own least-privilege scheme (view role should not reach any endpoint requiring higher-than-view intent, as it does for other operationally-similar debug endpoints).

### Likelihood Explanation
Highly likely and trivially reproducible: the only precondition is possessing any valid session, including a `view`-role user, which is the lowest privilege level provisionable by an admin. No special conditions, timing, or race are required — a single unauthenticated-to-view login followed by one GET request suffices, and the behavior is deterministic/repeatable every time.

### Recommendation
Wrap the `/debug/vars` route with at least `auth.RequiresRunRole` (matching the treatment of other debug/internal endpoints such as those in `metricRoutes`, which are mounted under `authv2` with per-route role wrappers), e.g.:
```go
func debugRoutes(app chainlink.Application, r *gin.RouterGroup) {
	group := r.Group("/debug", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	group.GET("/vars", auth.RequiresRunRole(func(c *gin.Context) { expvar.Handler().ServeHTTP(c.Writer, c.Request) }))
}
```

### Proof of Concept
Go handler-level integration test plan:
1. Build a test app/router via `NewRouter` with a mocked `AuthenticationProvider`/session store, seeding a user with `clsessions.UserRoleView`.
2. Perform `POST /sessions` (or directly inject a session cookie via the test's cookie store) to authenticate as the view-role user.
3. Issue `GET /debug/vars` with that session cookie using `httptest.NewRecorder()`/`httptest.NewRequest()`.
4. Assert `recorder.Code == http.StatusOK` and that the response body is valid JSON containing expvar keys (e.g. `"cmdline"`, `"memstats"`).
5. Contrast with a control test hitting a `RequiresRunRole`-protected route (e.g. `/v2/replay_from_block/:number`) with the same view-role session and assert `401 Unauthorized`, demonstrating the inconsistency — `/debug/vars` succeeds where equivalent-sensitivity endpoints fail.

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
