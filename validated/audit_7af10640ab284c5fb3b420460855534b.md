### Title
Instant-withdrawal path in `requestWithdraw` skips management and performance fees entirely - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
Analogous to the Size `compensate` bug where the fragmentation fee is charged only when `exiterCreditRemaining > 0`, `IdleCDOEpochVariant.requestWithdraw` charges the upfront management fee and performance fee (`_totalWithdrawFees`) only on the *normal* queued-withdrawal branch. When the same call routes through the instant-withdrawal branch (triggered when the honest manager lowers the vault APR by more than `instantWithdrawAprDelta`), the function returns early and the user's receipt is minted for the full gross principal: no management fee is deducted and `pendingWithdrawFees` is not incremented, even though the receipt leaves live NAV and waits to be funded exactly like a normal receipt.

### Finding Description
In `requestWithdraw` (contracts/IdleCDOEpochVariant.sol:739-791), `_underlyings` is computed as the gross principal. If `_isInstantWithdrawEnabled()` and `lastEpochApr > currentApr + instantWithdrawAprDelta`, the code calls `creditVault.requestInstantWithdraw(_underlyings, msg.sender)` and `_withdrawOps`, then returns — never executing lines 772-778:

```solidity
uint256 principal = _underlyings;
(uint256 interest, int256 diff) = _calcInterestWithdrawRequest(_underlyings, _tranche);
uint256 totalFees = _totalWithdrawFees(principal, interest);
_underlyings = principal + interest - totalFees;
pendingWithdrawFees += totalFees;
```

`_totalWithdrawFees` computes `_calculateManagementFee(_principal, _withdrawRequestManagementFeeDuration())` plus the net performance fee on interest. The code comment at lines 786-787 states the management fee is charged upfront "for the time it waits outside live NAV: remaining buffer plus the next epoch." An instant-withdraw receipt also leaves live NAV at request time and can only be paid when the strategy is funded via `collectInstantWithdrawFunds` (contracts/strategies/idle/IdleCreditVault.sol:398-403), i.e., it waits outside live NAV for the same kind of period. Yet `IdleCreditVault.requestInstantWithdraw` (lines 356-375) mints the receipt token 1:1 for the full `_underlyings` and records the full amount in `instantWithdrawsRequests`/`pendingInstantWithdraws`, so the user later claims the entire gross amount via `claimInstantWithdrawRequest` (lines 380-393) with zero fee.

The conditional structure mirrors the external bug exactly: the fee exists behind a conditional branch, and one legitimate user-reachable path produces a split/exit whose fee term is never evaluated.

### Impact Explanation
Every instant withdrawal routed through this branch avoids the full upfront management fee on principal (`principal * managementFee * _withdrawRequestManagementFeeDuration() / (365 days * FULL_ALLOC)`) and any performance fee that would have been charged on projected interest. The loss accrues to `feeReceiver`/owner as permanently uncollected protocol revenue — there is no later accounting hook that recovers it, because `pendingWithdrawFees` is never increased and the receipt is minted at gross. For a vault with e.g. a 1% management fee and a ~35-day buffer+epoch duration, each instant exit of size `P` avoids roughly `P * 0.01 * 35/365` in fees, and repeated exits scale linearly.

### Likelihood Explanation
The path is reachable by any KYC-passed tranche holder whenever the honest manager lowers the vault APR by more than `instantWithdrawAprDelta` — a documented, non-privileged-adversary trigger (`_isInstantWithdrawEnabled`, `unscaledApr` comparison at lines 761-763). APR reductions are a normal operational event (rate renegotiation, de-risking), so the condition is met in realistic operation, not only in adversarial setups. Every user who happens to exit during such a window pays no fee, while users exiting in normal windows pay the full fee — an inconsistent fee regime rather than a designed waiver (no comment or documentation states instant withdrawals are fee-free; the fee justification comment applies equally to them). Caveat: if instant receipts are intended to be funded faster than normal receipts, a reduced fee could be argued, but the code charges *zero*, which is not defensible under the stated rationale for the upfront fee.

### Recommendation
Apply `_totalWithdrawFees` (or at least `_calculateManagementFee` over the same duration) to the instant-withdrawal branch before minting the receipt:

```diff
if (_isInstantWithdrawEnabled()) {
    uint256 currentApr = creditVault.unscaledApr();
    if (lastEpochApr > (currentApr + instantWithdrawAprDelta)) {
+       uint256 totalFees = _calculateManagementFee(_underlyings, _withdrawRequestManagementFeeDuration());
+       _underlyings -= totalFees;
+       pendingWithdrawFees += totalFees;
        creditVault.requestInstantWithdraw(_underlyings, msg.sender);
        _withdrawOps(_amount, _underlyings, _tranche);
        return _underlyings;
    }
}
```

The exact fee duration for instant receipts should be reviewed (e.g., remaining buffer only vs. buffer + epoch), but the fee should not be unconditionally skipped.

### Proof of Concept
Foundry test (extends the harness in test/foundry/IdleCreditVault.t.sol):

```solidity
function testInstantWithdrawSkipsManagementFee() external {
    uint256 amount = 10_000 * ONE_SCALE;
    uint256 mgmtFeeRate = 1_000; // 1%

    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    _setManagementFee(mgmtFeeRate);

    uint256 trancheAmount = idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);

    _startEpochAndCheckPrices(0);

    // Honest manager lowers APR by more than instantWithdrawAprDelta
    uint256 lowApr = cdoEpoch.lastEpochApr() - cdoEpoch.instantWithdrawAprDelta() - 1;
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(lowApr, lowApr);

    uint256 principal = trancheAmount * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;
    uint256 expectedMgmtFee = _calcManagementFee(principal, mgmtFeeRate, _withdrawRequestManagementFeeDuration());

    uint256 requested = cdoEpoch.requestWithdraw(trancheAmount, address(AAtranche));

    // BUG: receipt is minted for gross principal; no fee is charged or booked
    assertEq(requested, principal, "instant path returned gross principal");
    assertEq(cdoEpoch.pendingWithdrawFees(), 0, "no management fee booked");
    assertEq(
        IdleCreditVault(address(strategy)).instantWithdrawsRequests(address(this)),
        principal,
        "receipt claimable at gross, expected principal - fee"
    );
    // expected behavior would be: requested == principal - expectedMgmtFee
}
```

Note: precise helper names (`_setManagementFee`, `_withdrawRequestManagementFeeDuration`) follow the existing test file; the PoC asserts the fee-skip by comparing `pendingWithdrawFees` and the minted receipt against the fee a normal `requestWithdraw` of the same size would charge (as in `testRequestWithdrawChargesManagementFeeUpfront`, test/foundry/IdleCreditVault.t.sol:1255-1290).
