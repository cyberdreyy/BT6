### Title
Vault DKG result export endpoint allows edit-role users to exfiltrate raw DKG secret share material that all other key-export endpoints restrict to admin role - (File: core/web/router.go, core/web/vault_controller.go)

### Summary
The route `/v2/vault/dkg_results/export` is guarded by `auth.RequiresEditRole` instead of `auth.RequiresAdminRole`, unlike every other `/keys/*/export` endpoint (ETH, EVM, OCR, OCR2, P2P, VRF, CSA, and the generic per-chain keys loop) which all require `RequiresAdminRole`. The handler `VaultController.ExportDKGResult` reads the raw `ReportWithResultPackage` bytes from the vault ORM and returns them hex-encoded, unredacted, via `presenters.NewExportDKGResultResource`.

### Finding Description
`v2Routes` registers the vault export route as `authv2.POST("/vault/dkg_results/export", auth.RequiresEditRole(vault.ExportDKGResult))`, whereas the equivalent key-export routes for every other key type use `auth.RequiresAdminRole`. `VaultController.ExportDKGResult` (`core/web/vault_controller.go`) takes only an `instanceId` in the POST body, looks up the DKG result package via `vault.NewVaultORM(vc.App.GetDB()).ReadResultPackage`, hex-encodes the raw `v.ReportWithResultPackage` bytes, and returns them unredacted through `presenters.NewExportDKGResultResource(hexPackage, shaStr)`, which places the full hex string directly in the `hexDKGResultPackage` JSON field with no masking. Because the route only requires `RequiresEditRole`, any authenticated user provisioned with the lower "edit" role (e.g., a UI operator who should only manage jobs/bridges/external initiators, not export cryptographic key material) can call this endpoint and receive the raw DKG secret-share package — material that is functionally analogous to the private key exports gated behind `RequiresAdminRole` for ETH/EVM/OCR/OCR2/P2P/VRF/CSA keys. No additional confirmation, MFA, or admin-role check gates this specific action, so the edit-role session alone is sufficient.

### Impact Explanation
An edit-role account (a lesser privilege tier than admin, per Chainlink's own role hierarchy view/edit/run/admin) can retrieve raw DKG secret share bytes intended to require admin-only key-export privilege. This is a scoped authorization-tier inconsistency that enables key/secret material disclosure to a less-trusted principal, matching Chainlink's "key or secret disclosure" bounty impact class, though at a lower severity than full node compromise since it requires a valid edit-role credential (not zero-privilege) and depends on a DKG result package existing for the given `instanceId`.

### Likelihood Explanation
Requires only a valid edit-role session (not admin) — a materially lower bar than the admin credential required for every other key export. The request is a single authenticated `POST /v2/vault/dkg_results/export` with a known/guessable/enumerable `instanceId`, fully repeatable, and needs no race condition or timing dependency.

### Recommendation
Change the route registration in `core/web/router.go` from `auth.RequiresEditRole(vault.ExportDKGResult)` to `auth.RequiresAdminRole(vault.ExportDKGResult)` to match the authorization tier used by `ekc.Export`, `vrfkc.Export`, `ocrkc.Export`, and all other key-export controllers.

### Proof of Concept
Go handler-level integration test plan:
1. In a test analogous to `TestVaultController_ExportDKGResult` (`core/web/vault_controller_test.go`), set up an authenticated client using an **edit-role** session/token (not admin) instead of the default admin client used in `setupVaultControllerTests`.
2. Write a DKG result package via `orm.WriteResultPackage` as in the existing test.
3. POST `/v2/vault/dkg_results/export` with `{"instanceId": "test-instance-id"}` using the edit-role client.
4. Assert the response is `http.StatusOK` and contains the non-empty `hexDKGResultPackage` field (proving successful exfiltration by an edit-role account).
5. As a comparative table test, iterate over `routesRolesMap`-style pairs of `/keys/eth/export/:address`, `/keys/vrf/export/:keyID`, `/keys/ocr/export/:ID` (expect `RequiresAdminRole` → edit-role client gets `403`) versus `/vault/dkg_results/export` (currently `RequiresEditRole` → edit-role client gets `200`), asserting the discrepancy, and asserting parity (`403` for edit-role) after the fix is applied.
