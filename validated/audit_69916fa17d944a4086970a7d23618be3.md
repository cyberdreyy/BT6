### Title
Dust APR0 withdraw request permanently reverts `stopEpoch` after any APR increase - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
The external report (libde265 segfault via crafted input) maps to a crafted-input crash analog: a cheap, unprivileged transaction that poisons epoch state so the epoch-end settlement path reverts unconditionally. In `IdleCreditVault`, any user can open a 1-wei APR=0 withdraw receipt; once `apr0TotalPrincipal != 0`, `prepareStopEpochWithApr0` reverts with `NotAllowed` whenever `unscaledApr != 0`, so `stopEpoch`/`stopEpochWithDuration` cannot execute while APR is positive.

### Finding Description
`requestWithdraw` routes APR=0 requests into `_requestWithdrawApr0`, which increments `apr0TotalPrincipal` by the user's net receipt amount with no minimum [1](#0-0) . The only gate is `unscaledApr == 0 && !isClosed` at request time [2](#0-1) .

At epoch end the CDO calls `prepareStopEpochWithApr0`, which hard-reverts if the APR0 bucket is non-empty while `unscaledApr != 0` [3](#0-2) . `apr0TotalPrincipal` is only reset inside that same function (line 540) or via the default-claim path `_clearWithdrawClaimForEpoch(_isClearingApr0=true)` [4](#0-3) . Neither is reachable while stopEpoch reverts and no default is being finalized — the bucket is stuck.

Attack sequence (running epoch, APR=0 configuration):
1. Manager legitimately sets `unscaledApr = 0` (existing APR0 mode, exercised by tests like `testApr0WithdrawGetsInterestAtStopEpoch`).
2. Attacker (KYC'd lender) deposits a dust amount and calls `requestWithdraw` → `apr0TotalPrincipal = dust`.
3. Manager later sets a positive `unscaledApr` (normal operation; honest role, we only sequence around it).
4. `stopEpoch` reverts at line 507 every time while APR > 0.

The receipt itself cannot be claimed to clear the bucket because claims require `epochNumber > lastWithdrawRequest` [5](#0-4) , and `epochNumber` only advances via a successful stopEpoch.

### Impact Explanation
Temporary freezing of all vault funds: deposits, pending withdraw receipts, and borrower repayments cannot settle while the manager wants a positive APR. The freeze is only resolvable by the manager setting APR back to 0 — which itself imposes a 0-yield epoch on all LPs — or by default finalization. Cost to the attacker is dust plus gas. If the APR0 revert is intentional, it converts a routine APR raise into a vault-wide settlement outage triggerable by anyone.

### Likelihood Explanation
Requires the vault to pass through an `unscaledApr == 0` window (used for pool-close / APR0 modes in this codebase) and then raise APR, which is a plausible operational transition rather than an exotic state. Attacker is an ordinary KYC'd tranche holder. One caveat I could not fully verify within the iteration limit: the exact call site in `IdleCDOEpochVariant.stopEpoch` that invokes `prepareStopEpochWithApr0` and whether its revert propagates uncaught — the `_onlyIdleCDO` external interface strongly implies a direct call, but this should be confirmed in the PoC.

### Recommendation
Do not revert on `unscaledApr != 0` in `prepareStopEpochWithApr0`. Instead, when APR is positive, settle the outstanding APR0 bucket at zero rate (or migrate it into the normal `withdrawsRequestsByEpoch` bucket) and set `apr0TotalPrincipal = 0`, so a stale dust bucket cannot wedge epoch settlement. Alternatively, enforce a minimum APR0 request amount and/or clear a user's open APR0 principal when APR changes via `setAprs`.

### Proof of Concept
```solidity
// Foundry fork test sketch (test/foundry/IdleCreditVault.t.sol harness)
function testDustApr0RequestBlocksStopEpochAfterAprRaise() external {
    IdleCreditVault vault = IdleCreditVault(address(strategy));

    // 1. Pool in APR0 mode (honest manager action)
    vm.prank(manager);
    vault.setAprs(0, 0);

    // 2. Attacker (KYC'd user) deposits dust and requests withdraw at APR=0
    address attacker = makeAddr('attacker');
    _depositWithUser(attacker, 1, true); // 1 wei underlying
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(0, address(AAtranche));
    assertGt(vault.apr0TotalPrincipal(), 0);

    // 3. Honest manager raises APR before epoch end
    vm.prank(manager);
    vault.setAprs(initialProvidedApr, 0);

    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());

    // 4. stopEpoch reverts: NotAllowed from prepareStopEpochWithApr0
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(initialProvidedApr, 0);

    // Attacker cannot self-clear: claim reverts (epoch never advanced)
    vm.prank(attacker);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.claimWithdrawRequest();
}
```
