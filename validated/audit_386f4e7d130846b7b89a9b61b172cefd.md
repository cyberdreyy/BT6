### Title
Any staking-contract shareholder can permanently block staker/operator payouts by disabling direct coin transfers - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::distribute_internal` pays out **every** pending shareholder (the staker and the operator/beneficiary) in a single atomic Move transaction via `aptos_account::deposit_coins`. `deposit_coins` aborts if the recipient is not yet registered for `AptosCoin` and has opted out of unsolicited transfers with `aptos_account::set_allow_direct_coin_transfers(false)`. Because Move transactions are all-or-nothing, one shareholder disabling direct transfers blocks the payout to **all** other shareholders sharing the same `StakingContract`, mirroring the external report's root cause (an unconditional native-asset push that can be made to revert, freezing funds for every other party in the same batch) — except here it hits Aptos stake/commission withdrawal rights instead of `AVAX`.

### Finding Description
`distribute_internal` (aptos-move/framework/aptos-framework/sources/staking_contract.move) withdraws all withdrawable stake pool balance and then loops over every shareholder recorded in `staking_contract.distribution_pool`, redeeming their shares and depositing coins to them: [1](#0-0) 

Both the staker (principal/rewards, added via `unlock_stake`/`unlock_rewards`) and the operator or its beneficiary (commission, added via `request_commission_internal`) are shareholders of the same `distribution_pool` for a given `(staker, operator)` pair: [2](#0-1) 

The payout uses `aptos_account::deposit_coins`, which asserts `can_receive_direct_coin_transfers(to)` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has not registered for the coin type and has explicitly opted out via `set_allow_direct_coin_transfers`: [3](#0-2) [4](#0-3) 

Because `distribute_internal`'s `while` loop must successfully deposit to *every* shareholder before the function returns, and a Move abort reverts the entire transaction (the `redeem_shares` calls on the in-memory pool are never committed), any single shareholder who is unregistered for `AptosCoin` and has called `set_allow_direct_coin_transfers(account, false)` will cause `distribute()` to abort for the whole `StakingContract`, no matter who calls it (the function is explicitly open to "anyone"): [5](#0-4) 

This is functionally identical to the external report's issue: a native-asset push to a party that can be made to fail traps funds for everyone bundled into the same transfer batch. Here the "batch" is the shared distribution pool between an unprivileged staker and their operator/beneficiary.

### Impact Explanation
An operator (or its beneficiary) can grief a staker by disabling direct coin transfers on their own account before any commission is unlocked. Once the staker calls `unlock_stake`/`unlock_rewards` (which force `distribute_internal` first) or `distribute()` is called by anyone, the transaction will always revert as long as the operator's account remains unregistered/opted-out — permanently blocking the staker's own principal and reward withdrawal from that stake pool, and vice versa (a staker can grief an operator's commission payout the same way). This is a "permanent lock or non-recoverable loss of claim rights in stake/commission/beneficiary flows" and a "withdrawal of stake... not owned by the attacker" denial, satisfying the required impact criteria, and it requires no privileged role — only calling the fully public `aptos_account::set_allow_direct_coin_transfers` on one's own account.

### Likelihood Explanation
Likelihood is High: `set_allow_direct_coin_transfers` is a normal, permissionless, user-facing entry function; any operator, beneficiary, or staker can invoke it on their own account at any time, and `distribute()`/`unlock_stake()`/`unlock_rewards()`/`request_commission()` are all normal unprivileged user flows that trigger `distribute_internal`. The only precondition is that the griefing account is not yet registered for `AptosCoin` (true for freshly created accounts that have never held/received APT directly), which is a common real-world state for delegate/beneficiary accounts set up specifically to receive future payouts.

### Recommendation
Do not let a single failing recipient revert distribution to all other shareholders. Options:
- Isolate each recipient's payout in a way that failures don't roll back other recipients' redemptions (e.g., track/skip failed deposits and let the shareholder later "claim" instead of push-only), or
- Use a `coin::deposit`-only path that unconditionally registers the recipient (bypassing `can_receive_direct_coin_transfers`) for staking-contract-controlled distributions, since these are pre-agreed contractual entitlements, not unsolicited transfers, or
- Catch failures per-recipient (not possible with current Move abort semantics without restructuring), or move to a pull-based claim model per shareholder so one uncooperative party cannot block another's withdrawal.

### Proof of Concept
1. Staker creates a staking contract with an operator via `staking_contract::create_staking_contract`, staking `X` APT with `Y`% commission.
2. Operator calls `aptos_account::set_allow_direct_coin_transfers(operator_signer, false)` on a fresh operator/beneficiary account that has never registered/received `AptosCoin` directly (or sets a beneficiary account in the same state via `set_beneficiary_for_operator`).
3. Stake pool accrues rewards; operator lockup expires.
4. Staker calls `staking_contract::unlock_stake` (or anyone calls `distribute`), which internally calls `distribute_internal`. When the loop reaches the operator/beneficiary recipient, `aptos_account::deposit_coins` asserts `can_receive_direct_coin_transfers` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. The entire transaction reverts — the staker's own unlocked principal/rewards are not paid out either, and this repeats for every future `distribute()`/`unlock_stake`/`unlock_rewards`/`request_commission` call as long as the operator keeps direct transfers disabled, permanently locking the staker's claim on their own stake.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
