### Title
Unbounded recursive RLP decoding of `TrieNode` in the fault-proof MPT allows an attacker-controlled preimage to stack-overflow and abort the fault-proof program - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode::decode` in `crates/proof/mpt/src/node.rs:567-604` is a recursive-descent RLP decoder for Merkle Patricia Trie nodes with no recursion-depth bound. For `Extension` nodes it recurses via `Self::decode(buf)` inside `try_decode_leaf_or_extension_payload` [1](#0-0) , and for `Branch` nodes it recurses via `Vec::<Self>::decode(buf)` [2](#0-1) . Neither path tracks or limits nesting depth, mirroring the exact bug class in the reported advisory (unauthenticated recursive-descent parser with no depth bound leading to `std::process::abort()` on stack overflow).

### Finding Description
The fault-proof program resolves account/storage trie nodes by fetching preimages keyed by hash and decoding them with `TrieNode::decode`. This happens both during direct preimage decode (`OracleL1ChainProvider::trie_node_by_hash`, `crates/proof/proof/src/l1/chain_provider.rs:125-142`) [3](#0-2)  and while walking/opening the trie via `TrieNode::unblind`/`TrieNode::open`, which repeatedly calls `fetcher.trie_node_by_hash` and then recurses into child nodes [4](#0-3) .

Two independent recursion vectors exist:
1. **Single-node "extension chain" attack**: an attacker can construct one long chain of nested `Extension` RLP nodes (`Self::decode` calling itself directly for each extension level) inside a single preimage blob, causing `TrieNode::decode` to recurse to a depth bounded only by the encoded byte length of the attacker-controlled preimage — no `MAX_TRIE_DEPTH`-style guard exists anywhere in `crates/proof/mpt/src/node.rs`.
2. **Cross-preimage chained unblinding**: even bounding a single preimage's nesting, `TrieNode::open`/`unblind` recursively fetches and decodes each subsequent blinded child from a *new* preimage supplied by the (attacker-influenced, in the fault-proof program's untrusted-until-verified) preimage oracle, so a sufficiently long malicious proof chain can still recurse arbitrarily deep across calls.

This is architecturally identical to the reported `scim_proto` bug: a recursive-descent decoder invoked on attacker-supplied bytes before any semantic/authorization check, with no depth ceiling, in a process that `abort()`s the whole program on stack overflow rather than returning a `Result` error.

Unlike the observability-events, txpool-validity, and CBOR-attestation parsers in this codebase — which all explicitly enforce depth/count bounds (`MAX_DATA_VALIDATION_DEPTH` in `crates/common/observability-events/src/event.rs:412`, `DEFAULT_MAX_VALIDITY_PREDICATES` bound in `crates/execution/txpool/src/validity.rs:510-550`, `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs:13,96-100`) — the MPT `TrieNode` decoder in `crates/proof/mpt` has no equivalent guard.

### Impact Explanation
The fault-proof program is the component that computes the provable output root used to resolve dispute games. If a party (a dispute-game participant, or anyone able to influence the preimages served to/consumed by the fault-proof program, e.g. via a malicious/oversized account or storage proof node) can cause `TrieNode::decode` to recurse past the guard page, Rust's runtime calls `std::process::abort()`, killing the fault-proof program process (host or on-chain zkVM/OP-style fault-proof execution). This is a node-halt / "wrong or missing provable output root" class impact: the program cannot produce a result, breaking dispute resolution for the affected claim and potentially forcing default judgments or requiring off-chain intervention — a concrete availability failure of the fault-proof pipeline that the rules classify as valid (fault-proof program and MPT scope).

### Likelihood Explanation
Reachability requires that the fault-proof program is made to open/decode a maliciously deep MPT proof chain during dispute resolution. Given that MPT proof structures (account/storage tries) are fundamentally attacker-influenceable inputs during fault-proof verification (the prover/challenger supplies or induces the trie path being proven), and that the RLP `Header`/list-length checks impose only per-node structural validity (not depth), building a proof chain of a few thousand nested `Extension` nodes (analogous to the ~2,000–3,000 nesting levels shown in the original advisory's PoC) is a bounded, inexpensive construction. However, exploitability specifics (e.g., whether preimages are additionally size/authenticity-checked by the preimage oracle before reaching `TrieNode::decode`, and the exact stack size configured for the process running the fault-proof program) were not verified in this pass and would need confirmation in a live/host environment.

### Recommendation
Add an explicit depth counter threaded through `TrieNode::decode`, `try_decode_leaf_or_extension_payload`, `TrieNode::open`, and `TrieNode::unblind`, rejecting decode/traversal once a fixed maximum (e.g., matching Ethereum's practical max trie depth, ~64) is exceeded, analogous to the `MAX_CBOR_NESTING_DEPTH` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`. Return a `TrieNodeError` variant instead of allowing unbounded native recursion.

### Proof of Concept
Construct an RLP preimage encoding a chain of nested 2-item `Extension` list nodes (`rlp([encoded_path, rlp([encoded_path, rlp([...])])])`) several thousand levels deep, each individually valid per `try_decode_leaf_or_extension_payload`'s structural checks, and feed it as the root/child preimage supplied to `TrieNode::decode` (e.g., via `OracleL1ChainProvider::trie_node_by_hash` or `TrieNode::open`/`unblind` during a proof walk). This drives `Self::decode` to re-enter itself once per extension level with no depth check, exhausting the worker stack and triggering `fatal runtime error: stack overflow, aborting`, exactly as demonstrated against the SCIM PEG parser in the original advisory. Confirming an end-to-end PoC through the full fault-proof preimage-oracle pipeline was not performed in this review and is recommended before treating this as fully verified.

    /// Unblinds the [`TrieNode`] if it is a [`TrieNode::Blinded`] node.
    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.
                *self = Self::Empty;
            } else {
                *self = fetcher
                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }

    /// Walks down the trie to a leaf value with the given key, if it exists. Preimages for blinded
    /// nodes along the path are fetched using the `fetcher` function, and persisted in the inner
    /// [`TrieNode`] elements.
    ///
    /// ## Takes
    /// - `self` - The root trie node
    /// - `path` - The nibbles representation of the path to the leaf node
    /// - `fetcher` - The preimage fetcher for intermediate blinded nodes
    ///
    /// ## Returns
    /// - `Err(_)` - Could not retrieve the node with the given key from the trie.
    /// - `Ok(None)` - The node with the given key does not exist in the trie.
    /// - `Ok(Some(_))` - The value of the node
    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }
