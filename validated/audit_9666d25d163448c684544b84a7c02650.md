### Title
Multisig confirmations from removed members are not purged, allowing requests to execute with confirmations below the effective live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm()` in `multisig2/src/lib.rs` tallies confirmations stored in `self.confirmations` without re-validating that every previously recorded confirmer is still a current member of the multisig. `delete_member()` only purges pending requests that were *created* by the removed member, but leaves that member's confirmations on *other* members' pending requests intact. This lets a request execute using a stale confirmation from an account that is no longer a member, effectively lowering the number of live, currently-authorized approvers below `num_confirmations`.

### Finding Description
`confirm()` computes the currently-calling member with `current_member()`, which does re-check live membership for the *new* confirmation being added: [1](#0-0) 

However, when tallying whether the threshold has been met, it only counts set membership of the `confirmations` `HashSet<String>` — it never re-validates that the *previously stored* entries in that set still correspond to current members: [2](#0-1) 

`delete_member()` is the only place that prunes confirmations, and it does so only for requests whose `request.member` (the original creator) equals the member being deleted — it does not scan or clean the `confirmations` sets of requests created by *other* members that the removed member had already confirmed: [3](#0-2) 

This is the direct analog of the ZetaChain bug: a "vote"/confirmation is counted as valid at execution time even though the underlying signer's active status (multisig membership) changed after the confirmation was recorded and was never re-checked.

### Impact Explanation
This breaks the K-of-N custody guarantee that the multisig's threshold (`num_confirmations`) is meant to enforce: a `Transfer`, `FunctionCall`, `AddKey`, or other privileged `MultiSigRequestAction` can execute having been approved by fewer than `num_confirmations` *currently live* members, because one or more of the counted confirmations belongs to an account that has since been removed via `DeleteMember`. This is a Critical-impact issue per the given rubric ("a multisig request executed below threshold"), since it can allow unauthorized transfer of NEAR or execution of privileged actions (e.g., adding a full-access key) without the intended quorum of active members.

### Likelihood Explanation
The scenario requires only ordinary use of the multisig's documented flow (no owner/foundation/victim-key compromise, no redeploy): a member confirms a pending request created by someone else, that confirming member is later removed via a normal `DeleteMember` request (e.g., because they went rogue, lost a key, or the group rotates membership), and then the remaining members simply continue confirming the original request. Since nothing re-validates old confirmations, the stale confirmation silently still counts. This is a realistic and easily-triggered ordering of otherwise-legitimate operations.

### Recommendation
When tallying confirmations in `confirm()` (and/or whenever `delete_member`/membership changes occur), filter/require that every entry in the `confirmations` set for a request still satisfies `self.members.contains(...)` before counting it toward `num_confirmations`. Alternatively, on `DeleteMember`, iterate over **all** pending requests (not just ones created by that member) and remove the deleted member's entry from each request's `confirmations` set.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. Member `B` calls `add_request` (creates request `R`, a `Transfer`), then `confirm(R)` → `confirmations = {B}` (via `add_request_and_confirm`).
3. Member `A` calls `confirm(R)` → `confirmations = {A, B}` (2 of 3 needed).
4. Separately, members submit and confirm a `DeleteMember { member: A }` request (3 confirmations from B, C, D) which executes and removes `A` from `self.members` — per `delete_member()`, this only purges requests created by `A`; request `R` (created by `B`) is untouched, so its `confirmations` set still contains `A`.
5. Member `C` calls `confirm(R)`. `confirmations.len() + 1 == 3 >= num_confirmations(3)` → `R` executes, even though only `B` and `C` are actually current, live members who approved it — `A`'s stale confirmation was counted despite `A` no longer being a member. [2](#0-1) [3](#0-2)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Returns current member: either predecessor as account or if it's the same as current account - signer.
    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
