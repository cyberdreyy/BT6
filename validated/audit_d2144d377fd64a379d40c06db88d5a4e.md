### Title
Global signer-state agreement threshold uses floor rounding while the canonical block-approval threshold uses ceiling rounding, letting the state machine "agree" on a global view below the true supermajority bar - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement`/`reached_disagreement` in `libsigner/src/v0/signer_state.rs` computes the approval threshold with a plain floor division (`total_weight * THRESHOLD / 10`), while the canonical, consensus-enforced threshold `NakamotoBlockHeader::compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs` computes the same 70%-style threshold with an explicit ceiling adjustment. This is the same class of defect as the reported `_getTokenPrices` bug: a value that is supposed to represent "the same quantity, scaled/rounded consistently across two code paths" is instead computed with two different rounding rules, so the two paths disagree on what counts as "enough."

### Finding Description
`reached_agreement`: [1](#0-0) 

computes `vote_weight >= total_weight * THRESHOLD / 10` (integer floor division, no ceiling).

The canonical threshold used to actually gate block approval on-chain and in the signer's own signature/pre-commit counting is: [2](#0-1) 

which explicitly adds a `ceil` term so that `threshold = ceil(total_weight * THRESHOLD / 10)`.

Whenever `total_weight * THRESHOLD` is not an exact multiple of 10 (i.e., whenever the reward-set weight total is not divisible by 10 for a 70%-style threshold), these two formulas diverge by exactly one weight unit: `compute_voting_weight_threshold` requires one more unit of weight than `reached_agreement` does. For example, with `total_weight = 15` and `THRESHOLD = 7`: `15*7/10 = 10.5` → `compute_voting_weight_threshold` returns `11` (ceiling), but `reached_agreement` returns `true` once vote weight reaches `10` (floor).

`reached_agreement` is the sole gate used throughout `GlobalStateEvaluator::determine_global_state`, `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `find_majority_prefix_replay_set`: [3](#0-2) 

This global state (burn view, current miner, protocol version, tx replay set) is exactly what feeds `GlobalStateView::check_proposal`, used by `check_block_against_global_state` in the v0 signer to decide whether a proposed block is acceptable: [4](#0-3) 

Meanwhile, the actual weight thresholds that gate pre-commits and signature broadcast in the same signer both correctly call the ceiling-based `compute_voting_weight_threshold`: [5](#0-4) [6](#0-5) 

So there are two different thresholds for what should be the identical 70%-style supermajority concept: one (block-signing/pre-commit weight, and the node's on-chain `verify_signer_signatures` check) rounds up; the other (global-state agreement used to decide the current miner/burn view/replay set that gates whether a proposal is even considered valid) rounds down. This is precisely analogous to the report's core defect: a quantity that must be scaled/rounded consistently across two enforcement points is instead computed inconsistently, breaking the intended equality between "the weight the state machine considers agreed" and "the weight actually required for the canonical decision."

### Impact Explanation
This is a "stale/incorrect threshold" class defect (High, per the specified impact categories: "a signer... acting on a stale reward set/threshold"). Because `determine_global_state` can flip to "agreement reached" one weight-unit earlier than the real supermajority bar, a signer can:
- Treat a `current_miner`/burn-block view as globally agreed and use it to validate/accept a block proposal via `check_block_against_global_state`, even though the true 70%-and-round-up bar (the one enforced identically for pre-commits, signatures, and on-chain `verify_signer_signatures`) has not been met.
- Similarly under- or over-shoot agreement on `tx_replay_set` and `active_signer_protocol_version`, since both paths reuse `reached_agreement`.

This does not directly forge a signature, but it desynchronizes the signer's gating decision (which blocks/miners/replay-sets are considered "canonical" enough to evaluate) from the value that is actually consensus-critical elsewhere in the same codebase, which is the "equality break" pattern the prompt calls out for aggregated-weight vs verified-accept mismatches.

### Likelihood Explanation
The divergence is deterministic and occurs whenever `total_weight * THRESHOLD` is not an exact multiple of 10 - a very common condition for real reward-set weight totals (only totals that are multiples of 10 avoid the gap, given the 70/10 constant). No majority collusion is required: the discrepancy is a one-weight-unit gap inherent to the two formulas, triggered by ordinary signer state-machine update gossip reaching exactly the floor value. This makes it a low-effort, high-likelihood arithmetic inconsistency rather than a contrived attack.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` (and `reached_disagreement`) use the same ceiling-rounding formula as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by having one call the other (or sharing a single threshold-computation helper) so the "70%-style supermajority" concept cannot diverge between the global-state-machine agreement path and the canonical block-approval/pre-commit/signature path.

### Proof of Concept
1. Construct a reward set/signer set whose `total_weight` is not a multiple of 10, e.g. `total_weight = 15`, `THRESHOLD = 7` (70%).
2. `compute_voting_weight_threshold(15)` → `ceil(15*7/10) = ceil(10.5) = 11` (the value required to actually sign/broadcast a block or pass `verify_signer_signatures`).
3. `GlobalStateEvaluator::reached_agreement(10)` with `total_weight = 15` → `10 >= 15*7/10 (=10, floor)` → `true`.
4. With only `10` units of weight (one unit short of the canonical `11` needed), `determine_global_state` (via `libsigner/src/v0/signer_state.rs:129`, `libsigner/src/v0/signer_state.rs:138`, `libsigner/src/v0/signer_state.rs:74`, `libsigner/src/v0/signer_state.rs:94`) will settle on a "globally agreed" burn view / current miner / protocol version / replay set, and `check_block_against_global_state` in `stacks-signer/src/v0/signer.rs:944` will use that state to accept/reject proposals - despite the same weight of `10` being insufficient under the canonical `compute_voting_weight_threshold` used for actual signature/pre-commit thresholds and on-chain verification.

    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Will return a BlockRejection if the block is invalid, none otherwise.

    fn check_block_against_global_state(
        &mut self,
        stacks_client: &StacksClient,
        block: &NakamotoBlock,
    ) -> Option<BlockRejection> {
        let signer_signature_hash = block.header.signer_signature_hash();
        let block_id = block.block_id();
        let Some(global_state) = self.global_state_evaluator.determine_global_state() else {
            warn!(
                "{self}: Cannot validate block, no global signer state";
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_id,
                "local_signer_state" => ?self.local_state_machine
            );
            return Some(self.create_block_rejection(RejectReason::NoSignerConsensus, block));
        };

        let global_state_view = GlobalStateView {
            signer_state: global_state,
            config: self.proposal_config.clone(),
        };

        info!(
            "{self}: Evaluating proposal against global state";
            "signer_state" => ?global_state_view.signer_state,
            "signer_signature_hash" => %signer_signature_hash,
            "block_id" => %block_id,
            "local_signer_state" => ?self.local_state_machine,
        );

        // Check if proposal can be rejected now if not valid against the global state
        match global_state_view.check_proposal(stacks_client, &mut self.signer_db, block) {
            // Error validating block

                );

            Err(reject_code) => {

                    "block_id" => %block_id,
                    "reject_reason" => %reject_code,
                    "reject_code" => ?reject_code,

                Some(self.create_block_rejection(reject_code, block))
            }
            // Block proposal passed check, still don't know if valid
            Ok(_) => None,
