## Analog Found: Closing a balance permanently destroys unclaimed emissions

### Title
Closing a lending account balance discards `emissions_outstanding` without settling or blocking it - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
`BankAccountWrapper::close_balance` deactivates a `Balance` via `balance.close()`, which resets the struct to `Balance::empty_deactivated()`. This wipes `emissions_outstanding` — the field that tracks a user's accrued-but-unclaimed reward tokens — without first requiring that value to be claimed or zero. Although the codebase defines a dedicated error variant `MarginfiError::CannotCloseOutstandingEmissions` (`"Cannot close balance because of outstanding emissions"`) specifically for this scenario, it is never referenced by any instruction handler, meaning the intended safeguard was never wired up.

### Finding Description
`Balance` stores `emissions_outstanding: WrappedI80F48` — unclaimed emissions rewards for a position — alongside `asset_shares`/`liability_shares` [1](#0-0) .

`close_balance` in `BankAccountWrapper` only validates that `current_liability_amount` and `current_asset_amount` are zero before calling `balance.close()`: [2](#0-1) 

`Balance::close()` unconditionally overwrites the whole struct with `Self::empty_deactivated()`, which zeroes every field, including `emissions_outstanding`: [3](#0-2) 

The instruction entrypoint `lending_account_close_balance` accrues bank interest and updates the bank cache, but never touches or settles the balance's `emissions_outstanding` before invoking `bank_account.close_balance`: [4](#0-3) 

Critically, `MarginfiError` already defines the exact guard this flow is missing — `CannotCloseOutstandingEmissions` ("Cannot close balance because of outstanding emissions") — but a repo-wide search shows this variant is declared in `errors.rs` and never used anywhere else in the codebase [5](#0-4) . This confirms the safeguard was intended but never implemented — the same root-cause pattern as the UsualSP report: state that represents a reward/allocation balance is reset to zero without first settling or blocking on it.

### Impact Explanation
Any user (or account authority) who calls `lending_account_close_balance` on a position that still carries positive `emissions_outstanding` (accrued but not yet claimed/airdropped) permanently loses that reward value — it's zeroed on-chain with no path to recovery, and no error is raised despite an error type existing precisely for this case. This is a direct, durable financial loss to the user, matching the "reduced/lost reward accumulation" impact class from the source report.

### Likelihood Explanation
The precondition is simply that a user has non-zero `emissions_outstanding` at the moment they fully withdraw/repay a position and then call `close_balance` — a completely permissionless, unprivileged, normal-user action that requires no special setup, race condition, or admin cooperation. Any bank with an active or historically active emissions campaign is exposed whenever depositors churn positions, which is an ordinary usage pattern.

### Recommendation
In `BankAccountWrapper::close_balance` (or in the `lending_account_close_balance` instruction), settle/claim `emissions_outstanding` before calling `balance.close()`, or explicitly `check!` that `emissions_outstanding` is zero using the existing `MarginfiError::CannotCloseOutstandingEmissions`, forcing a claim first.

### Proof of Concept
Not executed (no test harness run); based on static code review: an emissions-enabled bank position accrues `emissions_outstanding` over time, the user fully withdraws (asset/liability shares → 0) leaving unclaimed `emissions_outstanding` untouched, then calls `lending_account_close_balance`; `close_balance` passes both `IllegalBalanceState` checks (zero assets/liabilities) and proceeds to `balance.close()`, silently zeroing the previously nonzero `emissions_outstanding` with no error and no settlement path.

    pub fn close_balance(&mut self, in_receivership: bool) -> MarginfiResult<()> {
        let balance = &mut self.balance;
        let bank = &mut self.bank;

        let current_liability_amount =
            bank.get_liability_amount(balance.liability_shares.into())?;
        let current_asset_amount = bank.get_asset_amount(balance.asset_shares.into())?;

        check!(
            current_liability_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing debt"
        );

        check!(
            current_asset_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing assets"
        );

        let asset_shares: I80F48 = balance.asset_shares.into();
        let liability_shares: I80F48 = balance.liability_shares.into();

        let had_liabs = liability_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
