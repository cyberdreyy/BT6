### Title
Stale confirmations from a deleted multisig member remain counted toward the approval threshold, allowing a request to execute with fewer live confirmers than `num_confirmations` - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member` only purges outstanding **requests originated by** the removed member; it never scans the `confirmations` map to strip that member's confirmation from *other* pending requests they had already confirmed. Because `confirm()` counts entries in that stale `HashSet<String>` without checking membership, a confirmation from an account that is no longer a member still counts toward reaching `num_confirmations`, letting a request execute with fewer live, authorized confirmers than the configured threshold requires.

### Finding Description
Confirmations are tracked in `confirmations: LookupMap<RequestId, HashSet<String>>` [1](#0-0) , and `confirm()` decides whether to execute purely by comparing the size of that set (plus the current caller) to `self.num_confirmations`, with no re-validation that every entry in the set is still a current member: [2](#0-1) 

`delete_member` is the only place membership removal is handled, and it cleans confirmations only for requests where the removed member was the **original requester** (`r.member == member`): [3](#0-2) 

It never iterates other requests' `confirmations` sets to drop the deleted member's string entry from requests they merely *confirmed* (but did not create). Consequently, a confirmation cast by a member who is later removed keeps "voting weight" in the threshold count for any request that member confirmed before being deleted.

The binding that should hold is:
`confirmations.len()` for a request == number of *live* members who confirmed it.

After a `DeleteMember` execution this equality breaks for any request the removed member had confirmed but not created — the stale confirmation is still counted, but the confirming account no longer belongs to `self.members`.

### Impact Explanation
This lets a request execute (including `Transfer`, `AddKey` giving a full access key, `FunctionCall`, or another `DeleteMember`/`AddMember`) with strictly fewer live, authorized confirmations than `num_confirmations` mandates — i.e., a multisig request executed below threshold. This is a Critical-class impact per the funds/authorization criteria: the K-of-N guarantee the contract is built to provide is silently violated, letting a coalition smaller than K move funds or add access keys.

### Likelihood Explanation
This is reachable through entirely normal, unprivileged multisig usage: any member can confirm any pending request, and `DeleteMember` is a standard, documented multisig action (no foundation, owner, or external actor needed — just the multisig's own K-of-N approval flow, which is the mechanism being attacked). The only requirement is timing/ordering of confirm vs. delete-member actions, which members fully control, making this practically triggerable, not merely theoretical.

### Recommendation
When executing `DeleteMember`, iterate all pending requests' `confirmations` sets and remove the deleted member's string entry (not just requests they authored). Alternatively, have `confirm()` recompute the *effective* confirmation count by filtering the stored set against `self.members` before comparing to `num_confirmations`, so removed members can never contribute to reaching the threshold.

### Proof of Concept
1. Initialize `MultiSigContract::new` with 4 members `A, B, C, D` and `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R1` (e.g. `Transfer`). `D` calls `confirm(R1)` — `confirmations[R1] = {D}` (1 of 3, not yet executed).
3. `A, B, C` create and confirm a `DeleteMember { member: D }` request (reaching the real threshold of 3) — `execute_request` runs `delete_member(promise, D)` at `multisig2/src/lib.rs:356-379`. Since `D` did not *originate* `R1`, `R1`'s entry in `confirmations` is untouched; `confirmations[R1]` remains `{D}`, even though `D` is now removed from `self.members`.
4. `A` calls `confirm(R1)`: `confirmations.len() == 1` (`{D}`) `+ 1 == 2 < 3` → not executed yet, `confirmations[R1]` becomes `{D, A}`.
5. `B` calls `confirm(R1)`: `confirmations.len() == 2` (`{D, A}`) `+ 1 == 3 >= num_confirmations` → `execute_request` runs `R1`'s `Transfer`.

`R1` executed with only two live members (`A`, `B`) actually authorizing it, plus one stale confirmation from removed member `D` — one fewer live confirmer than the configured 3-of-4 threshold requires.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
