This confirms the finding. The Vault resolver has a `classifyError` function that inspects HTTP status codes and maps 4xx client errors to `secrets.NewResolvingConfigurationError` (no retry) and 5xx to `secrets.NewResolvingExternalDependencyError`, as seen in `helpers/secrets/resolvers/vault/resolver.go` lines 83-104. ### Title
GCP Secret Manager resolver never classifies errors, causing job-controlled permanent failures to be retried as RunnerSystemFailure - (File: helpers/secrets/resolvers/gcp_secret_manager/resolver.go)

### Summary
The GCP Secret Manager resolver's `Resolve()` method returns raw, unclassified errors from `service.Client.GetSecret` (from `getToken`/`access`), unlike the Vault resolver which classifies HTTP status codes into `secrets.ResolvingConfigurationError`/`ResolvingExternalDependencyError`. As a result, `wrapSecretResolvingError` in `common/build.go` always falls back to `RunnerSystemFailure` for GCP errors, and `attemptResolveSecrets`'s `retry.NewNoValue` loop retries `SecretsRetrievalAttempts` (up to 10, clamped in `validateAttemptSettings`, `common/build_settings.go` lines 134-153) times against the real GCP backend using the runner's WIF credentials, even for permanently failing, job-controlled inputs like a malformed `secret.Name`.

### Finding Description
The call chain is: `Build.resolveSecrets` (`common/build.go:1696`) → `attemptResolveSecrets` (line 1742) → `retry.NewNoValue(...).Run()` → `executeResolveSecretsStage` (line 1757) → `resolver.Resolve(b.Secrets)` → `defaultSecretsResolver.handleSecret` (`common/secrets.go:116-135`) → GCP `resolver.Resolve()` (`helpers/secrets/resolvers/gcp_secret_manager/resolver.go:40-46`) → `client.GetSecret` (`helpers/gcp_secret_manager/service/gcp_secret_manager.go:38-61`).

A job can set `GCPSecretManagerSecret.Name`/`Version` to a value that Secret Manager's `AccessSecretVersion` API rejects with a 4xx client error (e.g., malformed resource name → 400 `INVALID_ARGUMENT`). This error surfaces from `access()` (line 97-108) as a plain gRPC/API error, gets wrapped by `fmt.Errorf("failed to get secret: %w", err)` in `GetSecret` (line 49), and then by `fmt.Errorf("resolving secrets: %w", err)` in `executeResolveSecretsStage` (`common/build.go:1775`). None of these wrap types satisfy `errors.As` checks for `*secrets.ResolvingConfigurationError` or `*secrets.ResolvingExternalDependencyError` in `wrapSecretResolvingError` (`common/build.go:1719-1736`), so the error is classified as `RunnerSystemFailure` and — critically — is retried by `attemptResolveSecrets`'s retry loop rather than failing fast.

This differs from the Vault resolver's `classifyError` (`helpers/secrets/resolvers/vault/resolver.go:83-104`), which explicitly maps 400/401/403/404 to `ResolvingConfigurationError` (implying no-retry-as-transient semantics) and 5xx to `ResolvingExternalDependencyError`. The GCP resolver has no analogous classification step, so it is asymmetrically unprotected.

### Impact Explanation
Each job-controlled malformed/invalid secret request causes up to `SecretsRetrievalAttempts` (clamped 1-10, default determined by `SECRETS_RETRIEVAL_ATTEMPTS` variable, `common/build_settings.go:134-153`) real network round-trips against Google's STS token-exchange and Secret Manager `AccessSecretVersion` endpoints, using the runner's actual Workload Identity Federation credentials. This amplifies request volume sent to GCP backends under job control, though the classification itself does not leak any secret and does not escape the job or runner sandbox — the impact is limited to unnecessary retries and increased backend load per job.

### Likelihood Explanation
Trivially reachable and fully repeatable: any job author who can request a `gcp_secret_manager` secret can set an invalid `Name` (e.g. containing disallowed characters, or a nonexistent secret ID formatted to trigger `INVALID_ARGUMENT`) with no other privileges. No timing race or special environment is needed; the retry amplification triggers on every such job run given `SecretsRetrievalAttempts > 1`.

### Recommendation
Add a `classifyError` (or equivalent) step to the GCP resolver in `helpers/secrets/resolvers/gcp_secret_manager/resolver.go`, mirroring the Vault resolver's pattern: inspect the underlying gRPC/API status code (e.g. via `status.FromError` for `codes.InvalidArgument`, `codes.PermissionDenied`, `codes.NotFound`, `codes.Unauthenticated`) and wrap with `secrets.NewResolvingConfigurationError`; map `codes.Unavailable`/`Internal`/5xx to `secrets.NewResolvingExternalDependencyError`. This ensures `wrapSecretResolvingError` correctly classifies the failure and the retry loop in `attemptResolveSecrets` does not retry configuration errors.

func classifyError(err error) error {
	if err == nil {
		return nil
	}

	var apiErr apiStatusCoder
	if !errors.As(err, &apiErr) {
		return err
	}

	switch code := apiErr.StatusCode(); {
	case code == http.StatusBadRequest,
		code == http.StatusUnauthorized,
		code == http.StatusForbidden,
		code == http.StatusNotFound:
		return secrets.NewResolvingConfigurationError(err)
	case code >= 500:
		return secrets.NewResolvingExternalDependencyError(err)
	default:
		return err
	}
}

func (b *Build) validateAttemptSettings() []error {
	var errs []error

	clamp := func(variable *int, varName string) {
		const minAttempts, maxAttempts = 1, 10
		val := max(minAttempts, min(maxAttempts, *variable))
		if val != *variable {
			*variable = val
			errs = append(errs, fmt.Errorf("%s: number of attempts out of the range [%d, %d], clamping to: %d", varName, minAttempts, maxAttempts, *variable))
		}
	}

	clamp(&b.buildSettings.ExecutorJobSectionAttempts, "EXECUTOR_JOB_SECTION_ATTEMPTS")
	clamp(&b.buildSettings.GetSourcesAttempts, "GET_SOURCES_ATTEMPTS")
	clamp(&b.buildSettings.ArtifactDownloadAttempts, "ARTIFACT_DOWNLOAD_ATTEMPTS")
	clamp(&b.buildSettings.RestoreCacheAttempts, "RESTORE_CACHE_ATTEMPTS")
	clamp(&b.buildSettings.SecretsRetrievalAttempts, "SECRETS_RETRIEVAL_ATTEMPTS")

	return errs
}
