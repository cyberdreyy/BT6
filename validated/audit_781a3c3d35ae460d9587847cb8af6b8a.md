### Title
Post-default withdraw receipts drain the shared recovery reserve at par, freezing defaulted-epoch claims - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
Like the OpenJPEG `pi.c` OOB read, where an index walks outside the data it was meant to reference, `IdleCreditVault` lets post-`finalizeDefaultRecovery` withdraw requests index a payout pool (the isolated `defaultRecoveryReserve`) that was sized only for pre-default claimants. `requestWithdraw` mints a 1:1 receipt for `postDefaultRequests` and `_claimPostDefaultWithdrawRequest` pays it at par via `_transferDefaultRecovery`, even though these claims were never part of `totalBasis` used to compute `defaultRecoveryPrice`. The reserve is therefore overspent, and legitimately haircutted default-epoch receipts underflow `defaultRecoveryReserve` and can never claim.

### Finding Description
`finalizeDefaultRecovery` computes `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis`, where `totalBasis = activeBasis + defaultPendingClaimBasis()`. `defaultPendingClaimBasis` only counts `pendingWithdraws` plus current-epoch instant claims — i.e., only claims that existed at default time.

After finalization, `requestWithdraw` takes a dedicated branch:

- `contracts/strategies/idle/IdleCreditVault.sol` lines 247–257: when `defaultRecoveryFinalized`, it burns CDO strategy tokens, mints a full `_amount` receipt to the user and stores `postDefaultRequests[_user] = _amount`.
- `_claimPostDefaultWithdrawRequest` (lines 760–767) pays `amount` 1:1 through `_transferDefaultRecovery`.
- `_transferDefaultRecovery` (lines 912–917) does `defaultRecoveryReserve -= _amount` and transfers underlying.

The reserve equals `recovered + prefunded + old reserve` — exactly enough for `totalBasis * recoveryPrice`. Every post-default claim consumes reserve that was priced for someone else. When `recoveryPrice < RECOVERY_FULL` (the normal haircut case), a new entrant can buy tranche tokens at the post-default depressed `tranchePrice`/`virtualPrice`, call `requestWithdraw` with an amount whose haircut was already applied via `virtualPrice`, then `claimWithdrawRequest` and withdraw at 1:1 from the recovery reserve. Each such claim shrinks `defaultRecoveryReserve`; once it drops below an honest claimant's payout, `defaultRecoveryReserve -= _amount` underflows and reverts, permanently freezing the remaining defaulted-epoch receipts (`withdrawsRequestsByEpoch`, APR0 buckets, and defaulted instant receipts via `_claimDefaultedInstantWithdrawRequest`).

The reserve-isolation guard `_transferFundedClaim` (lines 897–907) only protects the reserve from *funded* claims; nothing caps post-default claims against `defaultRecoveryReserve`, and `requestWithdraw` post-default performs no solvency check that `defaultRecoveryReserve` covers the new receipt.

### Impact Explanation
An unprivileged tranche-token holder (anyone who buys tranche tokens after finalization, or an existing holder who waited) converts a haircut-priced position into a par payout from the recovery reserve. Direct theft of other claimants' recovery up to the full reserve, plus permanent freezing of all unpaid defaulted/post-default claims once the reserve is exhausted — both accepted impact classes. Loss is bounded only by `defaultRecoveryReserve`; with a 50% recovery price, roughly half the reserve can be siphoned before honest claims start reverting.

### Likelihood Explanation
Requires only: a default occurred, `finalizeDefaultRecovery` ran with `recoveryPrice < 1e18`, and the attacker holds/acquires tranche tokens (they trade freely at the depressed post-default price; `requestWithdraw` post-default only requires the user have no outstanding requests). No privileged cooperation needed — the attacker's `requestWithdraw`/`claimWithdrawRequest` calls are unprivileged entrypoints on `IdleCDOEpochVariant` (lines 967–971 delegate to the vault), and honest `finalizeDefaultRecovery`/`restoreOperations` sequencing is normal protocol operation. The only uncertainty is whether `IdleCDOEpochVariant.requestWithdraw` applies an additional `defaulted()` gate before reaching the strategy; the existence of the dedicated `defaultRecoveryFinalized` branch in `requestWithdraw` indicates the post-default path is intended to be reachable.

### Recommendation
Either pay post-default claims at `defaultRecoveryPrice` (so every claim consumes `claimBasis * price` of reserve, matching how the reserve was sized), or escrow a separate, separately-funded bucket for post-default requests so they never touch `defaultRecoveryReserve`. Alternatively revert `requestWithdraw` once `defaultRecoveryFinalized` and route exits through `DefaultDistributor.claim`/tranche redemption at the recovery price.

function testPostDefaultClaimDrainsRecoveryReserve() external {
    // Setup: victim deposits AA, epoch runs, borrower defaults.
    _depositWithUser(victim, 10000 * ONE_SCALE, true);
    _startEpochAndCheckPrices(0);
    // borrower fails to repay -> default
    vm.prank(manager);
    cdoEpoch.stopEpoch(initialProvidedApr, 0); // triggers default path

    // Finalize recovery at 50%: recovered = basis / 2
    // ...finalizeDefaultRecovery(_recoveredAmount, recoverySource)...

    // Victim's pending/defaulted receipt is priced at 0.5.
    // Attacker buys tranche tokens at post-default virtualPrice (~0.5 of par).
    uint256 cheapTranches = dealTranchesTo(attacker); // costs ~half of face

    // Attacker opens a post-default request: minted 1:1 receipt at face value.
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(cheapTranches, address(AAtranche));

    uint256 reservePre = strategy.defaultRecoveryReserve();
    vm.prank(attacker);
    cdoEpoch.claimWithdrawRequest(); // _claimPostDefaultWithdrawRequest pays 1:1

    // Attacker received full face value from the reserve.
    assertGt(underlying.balanceOf(attacker), costOf(cheapTranches));

    // Victim's haircutted claim now reverts on `defaultRecoveryReserve -= amount`
    // once attacker claims push the reserve below the victim payout.
    vm.prank(victim);
    vm.expectRevert();
    cdoEpoch.claimWithdrawRequest();
}
