### Title
MetaOracle::combine() Staleness Window Is Relative to Oracle Data, Not Current Clock — Stale Prices Pass Unchecked - (File: crates/sui-oracle/move/oracle/sources/meta_oracle.move)

### Summary
`MetaOracle::combine()` computes its freshness window as `max_timestamp - time_window_ms`, where `max_timestamp` is the timestamp of the last `SimpleOracle` added. It never compares against the current on-chain clock. If all oracle operators stop submitting data, every stored reading still passes the staleness filter because the filter is anchored to the data itself, not to wall-clock time. Any protocol that calls `MetaOracle::median()` will silently receive arbitrarily old prices.

### Finding Description

`MetaOracle` is the production oracle aggregation primitive in `crates/sui-oracle/move/oracle/sources/meta_oracle.move`. Its public API is:

1. `new()` — creates a `MetaOracle` with a caller-supplied `time_window_ms`.
2. `add_simple_oracle()` — reads the latest stored value from a `SimpleOracle` and records its timestamp as `max_timestamp`.
3. `median()` → `combine()` — filters readings and returns the median.

`max_timestamp` is set in `add_simple_oracle()`:

```move
// meta_oracle.move lines 38-44
public fun add_simple_oracle<T: copy + drop + store>(meta_oracle: &mut MetaOracle<T>, oracle: &SimpleOracle) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));  // ← last-added wins
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
```

Two compounding defects:

1. **No clock parameter.** `combine()` never receives a `Clock` object. There is no call to `clock::timestamp_ms()` anywhere in the staleness path.
2. **Self-referential window.** `min_timestamp = max_timestamp - time_window_ms`. If every oracle last updated at epoch `T_old` (hours or days ago), then `min_timestamp = T_old - window`. Every reading with timestamp near `T_old` satisfies `timestamp > T_old - window` and is accepted as fresh.

The correct invariant is `data::timestamp > clock::timestamp_ms(clock) - time_window_ms`.

`SimpleOracle::get_latest_data()` returns whatever was last written by `submit_data()`, with no freshness gate of its own:

```move
// simple_oracle.move lines 51-58
public fun get_latest_data<T: store + copy>(oracle: &SimpleOracle, ticker: String): Option<Data<T>> {
    if (!df::exists_(&oracle.id, ticker)) { return option::none() };
    let data: &StoredData<T> = df::borrow(&oracle.id, ticker);
    let StoredData { value, sequence_number, timestamp, identifier } = *data;
    option::some(data::new(value, ticker, sequence_number, timestamp, oracle.address, identifier))
}
```

### Impact Explanation

Any Move package that calls `MetaOracle::median()` to price assets, compute collateral ratios, or trigger liquidations will receive prices that may be hours or days old without any on-chain error or abort. The `threshold` check (`assert!(vector::length(&values) >= threshold)`) only verifies that enough oracles responded at some point in the past; it does not verify that any response is recent relative to the current block time. Downstream protocols that rely on this primitive for financial decisions (e.g., margin, lending, settlement) are exposed to the same class of harm described in the external report: stale prices enabling incorrect liquidations or preventing correct ones.

### Likelihood Explanation

Oracle operators can go offline due to infrastructure failure, key rotation, or deliberate shutdown. Sui's `Clock` object advances with every checkpoint; if oracle operators stop calling `submit_data`, the gap between `clock::timestamp_ms()` and the stored `timestamp` grows unboundedly while `combine()` remains unaware. Any ordinary user can call `add_simple_oracle` + `median` in a PTB at any time, receiving the stale result.

### Recommendation

Pass a `&Clock` into `combine()` and `median()`, and anchor the window to the current time:

```move
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, clock: &Clock): (vector<T>, vector<address>) {
    let now = clock::timestamp_ms(clock);
    let min_timestamp = now - meta_oracle.time_window_ms;
    ...
    if (data::timestamp(&oracle_data) > min_timestamp) { ... }
```

Remove the `max_timestamp` field from `MetaOracle` entirely, as it serves no correct purpose once the clock is used.

### Proof of Concept

1. Oracle operator calls `submit_data` at time `T = 1_000_000 ms`, storing price `P_old`.
2. Operator goes offline. No further `submit_data` calls are made.
3. At time `T_now = 4_600_000 ms` (one hour later), a user constructs a PTB:
   - `meta_oracle::new(threshold=1, time_window_ms=60_000, ticker="SUIUSD")` → `MetaOracle { max_timestamp: 0, time_window_ms: 60_000 }`
   - `meta_oracle::add_simple_oracle(&mut meta, &oracle)` → reads stored data with `timestamp = 1_000_000`; sets `max_timestamp = 1_000_000`.
   - `meta_oracle::median(meta)` → `combine()` computes `min_timestamp = 1_000_000 - 60_000 = 940_000`. The stored reading has `timestamp = 1_000_000 > 940_000` → **passes**. Returns `P_old`.
4. The user receives a price that is 3,600 seconds stale with no abort, no error, and no indication of staleness. [1](#0-0) [2](#0-1) [3](#0-2)
