## Title
Unredacted sequencer transport errors leak sequencer endpoint credentials to any anonymous `eth_sendRawTransaction` caller - (File: `crates/execution/rpc/src/error.rs`)

### Summary
The `SequencerClientError → ErrorObject` conversion used by `eth_sendRawTransaction` forwards the raw `Display` string of any non-`ErrorResp` alloy `RpcError<TransportErrorKind>` (e.g. connection/TLS/DNS failures) straight back to the RPC caller, without the credential redaction that this same codebase applies everywhere else an operator RPC/sequencer URL can appear in an error.

### Finding Description
When an anonymous client calls `eth_sendRawTransaction`, the transaction is forwarded to the sequencer via `SequencerClient::forward_raw_transaction` → `SequencerClient::request`, both of which just log and propagate the underlying transport error: [1](#0-0) 

That error becomes a `BaseEthApiError::Sequencer(SequencerClientError)`, and the RPC layer converts it into the JSON-RPC error object returned to the caller: [2](#0-1) 

For the `RpcError::ErrorResp` variant the code/message/data come from the sequencer's own structured JSON-RPC error (safe). For every *other* variant of `RpcError<TransportErrorKind>` — connection refused, DNS failure, TLS error, timeout, etc. — the fallback arm calls `err.to_string()` directly and puts it into the returned `ErrorObject` message: [3](#0-2) 

Alloy's `TransportErrorKind`/reqwest transport errors commonly embed the full request URL in their `Display` output (e.g. `"error sending request for url (https://user:password@l1.example/v3/api-key?token=secret)"`), which the same codebase explicitly documents and tests as a credential-leak vector in `TxManagerError`'s classifier: [4](#0-3) [5](#0-4) 

and in the batch RPC client used for load tests: [6](#0-5) 

Both of those call sites explicitly strip/replace the transport error text before it can reach any output. `SequencerClient` supports arbitrary custom headers and any HTTP(S)/WS(S) endpoint string operators configure (`SequencerClient::new_with_headers`), which is the same class of “operator endpoint commonly embeds API key/userinfo” URL that basectl, prover-service, and tx-manager all treat as sensitive and redact: [7](#0-6) 

The `BaseEthApiError::Sequencer` conversion is the one path in this family that was missed — it passes the raw transport-error string, potentially containing the sequencer's basic-auth userinfo or an embedded API key, directly into the JSON-RPC response body served to the original, unauthenticated `eth_sendRawTransaction` caller.

### Impact Explanation
Any anonymous transaction sender who calls `eth_sendRawTransaction` on a Base node during a sequencer connectivity failure (misconfiguration, credential rotation window, network blip, TLS issue, etc.) receives the operator's sequencer RPC URL — including any embedded username/password or API key — directly in the JSON-RPC error response. This is a credential-disclosure vulnerability (CWE-532 analog, but worse than a log-only leak since it is returned straight to an untrusted, unauthenticated third party over the public RPC surface) that could let an attacker who observes the error message access or abuse the operator's sequencer endpoint.

### Likelihood Explanation
Triggering this requires only sending any raw transaction to a public `eth_sendRawTransaction` endpoint while the configured sequencer endpoint is unreachable or the connection otherwise fails at the transport layer — a condition attackers can also help induce (e.g., by flooding forwarding paths) and one that can occur during normal operational events (credential rotation, network partition, TLS cert renewal) without any privileged access.

### Recommendation
Sanitize the non-`ErrorResp` arm of `From<SequencerClientError> for ErrorObject` the same way `TxManagerError`/`RpcErrorClassifier` and the load-tests batch client already do: replace `err.to_string()` with a fixed, credential-free message (e.g. `"sequencer transport request failed"`) instead of embedding the raw transport error text, and add regression tests mirroring `tx-manager`'s `classify_replaces_transport_error_messages` to assert the sequencer endpoint's userinfo/API key never appears in the RPC response.

### Proof of Concept
1. Configure a Base node's sequencer endpoint with embedded credentials, e.g. `--rollup.sequencer-http https://user:secretApiKey@sequencer.internal:8545`.
2. Make the sequencer endpoint unreachable (firewall block, DNS failure, or TLS misconfiguration) so the HTTP transport fails before an `ErrorResp` is produced.
3. As any anonymous client, call `eth_sendRawTransaction` with any validly-formed transaction.
4. Observe the JSON-RPC error response: it contains the `Display` output of the underlying `RpcError<TransportErrorKind>`, which includes the full request URL `https://user:secretApiKey@sequencer.internal:8545`, disclosing the sequencer credentials to the caller — see the unredacted fallback at `crates/execution/rpc/src/error.rs:140-145`.

    /// Creates a new [`SequencerClient`] for the given URL.

    /// If the URL is a websocket endpoint we connect a websocket instance.
    pub async fn new(sequencer_endpoint: impl Into<String>) -> Result<Self, Error> {

    /// Creates a new `SequencerClient` for the given URL with the given headers
    ///
    /// This expects headers in the form: `header=value`
    pub async fn new_with_headers(
        sequencer_endpoint: impl Into<String>,
        headers: Vec<String>,
    ) -> Result<Self, Error> {
        let sequencer_endpoint = sequencer_endpoint.into();
        let endpoint = BuiltInConnectionString::from_str(&sequencer_endpoint)?;
        if let BuiltInConnectionString::Http(url) = endpoint {
            let mut builder = alloy_reqwest::Client::builder()
                // we force use tls to prevent native issues
                .use_rustls_tls();

            if !headers.is_empty() {
                let mut header_map = alloy_reqwest::header::HeaderMap::new();
                for header in headers {
                    if let Some((key, value)) = header.split_once('=') {
                        header_map.insert(
                            key.trim()
                                .parse::<alloy_reqwest::header::HeaderName>()
                                .map_err(|err| Error::InvalidHeader(err.to_string()))?,
                            value
                                .trim()
                                .parse::<alloy_reqwest::header::HeaderValue>()
                                .map_err(|err| Error::InvalidHeader(err.to_string()))?,
                        );
                    }
                }
                builder = builder.default_headers(header_map);
            }

            let client = builder.build()?;
            Self::with_http_client(url, client)
        } else {
            let client = ClientBuilder::default().connect_with(endpoint).await?;
            let inner = SequencerClientInner::new(sequencer_endpoint, client);
            Ok(Self { inner: Arc::new(inner) })
        }
    }

                    );

        let start = Instant::now();
        let rlp_hex = hex::encode_prefixed(tx);
        let tx_hash =

                warn!(

                    %err,
                    "Failed to forward transaction to sequencer",
                );
            })?;
        SequencerMetrics::record_forward_latency(start.elapsed());
        Ok(tx_hash)

/// Error type when interacting with the Sequencer
#[derive(Debug, thiserror::Error)]
pub enum SequencerClientError {
    /// Wrapper around an [`RpcError<TransportErrorKind>`].
    #[error(transparent)]
    HttpError(#[from] RpcError<TransportErrorKind>),
}

impl From<SequencerClientError> for jsonrpsee_types::error::ErrorObject<'static> {
    fn from(err: SequencerClientError) -> Self {
        match err {
            SequencerClientError::HttpError(RpcError::ErrorResp(ErrorPayload {
                code,
                message,
                data,
            })) => jsonrpsee_types::error::ErrorObject::owned(code as i32, message, data),
            err => jsonrpsee_types::error::ErrorObject::owned(
                INTERNAL_ERROR_CODE,
                err.to_string(),
                None::<String>,
            ),
        }
    }
}
