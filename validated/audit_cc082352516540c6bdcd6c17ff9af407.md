### Title
Inconsistent supermajority threshold rounding between `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` allows a sub-threshold coalition to force global-state consensus — ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` and `reached_disagreement`, which gate the signer's belief about the canonical active miner, burn view, supported protocol version, and tx-replay set, compute the 70%/30% supermajority threshold using plain floor integer division. The canonical block-approval threshold used everywhere else in the codebase (`NakamotoBlockHeader::compute_voting_weight_threshold`, used by `verify_signer_signatures`, `store_and_process_block_signature`, `handle_block_pre_commit`, and rejection counting in `stacks-signer/src/v0/signer.rs`) explicitly rounds the same 70%/30% split *up* (ceiling). For any `total_weight` not a multiple of 10, these two "70% supermajority" definitions diverge by exactly 1 weight unit, so a coalition holding the floor amount (strictly less than the true supermajority) can satisfy `reached_agreement` while failing the canonical block-approval threshold.

### Finding Description
`compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs` computes the block-approval threshold with an explicit ceiling adjustment: [1](#0-0) 

This is the threshold enforced when a signature set is checked for block approval (`verify_signer_signatures`) and when the signer decides it has enough weight to broadcast a signed block or mark rejection/pre-commit consensus in `stacks-signer/src/v0/signer.rs`: [2](#0-1) [3](#0-2) 

By contrast, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement`, which are used to derive the signer's global view of the active protocol version, current miner, burn view, and replay set, use plain floor division with no ceiling adjustment: [4](#0-3) 

These two functions are meant to encode the same conceptual "70% approve / 30% block" supermajority (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD == 7`), but they diverge whenever `total_weight * 7` is not a multiple of 10. For example, with `total_weight = 11`: `compute_voting_weight_threshold` returns `8` (`11*7=77`, `77/10=7` with remainder ⇒ ceil to `8`), while `reached_agreement` treats `7` (`77/10=7`, floored) as sufficient — a full unit of weight lower, i.e. a coalition holding only 63.6% is treated as having reached the "70%" agreement, versus the canonical 72.7% actually required for block approval elsewhere.

This inconsistency is exercised through `GlobalStateEvaluator::determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state`, all of which call `reached_agreement` directly: [5](#0-4) [6](#0-5) 

These global-state determinations feed safety-relevant decisions in the signer's block-processing state machine, e.g. gating whether the miner-invalidation/reorg-guard logic applies at all: [7](#0-6) 

### Impact Explanation
A minority weight coalition equal to the floor value (but below the canonical ceiling threshold) can force the signer set to "agree" on a protocol version, burn view, current-miner, or tx-replay-set state that has not actually reached the true Nakamoto supermajority used for block approval. Because this global-state consensus gates protocol-version-dependent behavior (e.g. whether the legacy reorg/invalid-miner guard is applied) and the signer's belief about the canonical current miner, this discrepancy can steer signer behavior — including whether a signer treats a given miner/tenure as canonical and consequently which blocks it is willing to sign — using a weight bar that is measurably lower than what block-signature verification (`verify_signer_signatures`) actually requires. This creates a wedge between the signer's local "global state" belief and the canonical approval threshold, which is the class of bug this scan targets (equality/threshold divergence causing incorrect signer decisions).

### Likelihood Explanation
Triggering the divergence requires no majority and no protocol violation — it only requires normal gossip of `StateMachineUpdate` messages from signers holding a combined weight equal to the floor-rounded threshold for a `total_weight` that is not a clean multiple of 10 (the common case in real reward sets, since signer weights are apportioned by stacked amount and rarely sum to an exact multiple of 10). Any one/few colluding or even honestly-diverging signers whose combined weight lands in the 1-unit gap between floor and ceiling thresholds will trigger this divergence during normal operation.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the same ceiling-rounding formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, call `compute_voting_weight_threshold` directly) so that "70% supermajority" is defined identically across all consensus-relevant threshold checks in the signer and chainstate.

### Proof of Concept
For `total_weight = 11`:
- `NakamotoBlockHeader::compute_voting_weight_threshold(11)` = `ceil(11*7/10)` = `8`.
- `GlobalStateEvaluator::reached_agreement(7)` with `total_weight = 11` returns `true` because `7 >= 11*7/10 = 7` (integer floor), even though `7 < 8`, the canonical block-approval threshold.
This is directly verifiable against the existing test assertions for both formulas: [8](#0-7) [9](#0-8) 
No test in the repository asserts equivalence between `compute_voting_weight_threshold` and `reached_agreement` for the same `total_weight`, confirming the two are unaligned formulas for the same nominal supermajority.

        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);

            0

            1

                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Determine what the global burn view is if there is one
    pub fn determine_global_burn_view(&self) -> Option<(&ConsensusHash, u64)> {
        let mut burn_blocks = HashMap::new();

        }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)

        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

#[test]
/// Locks the joint behavior of `reached_agreement` and `reached_disagreement`
/// at a single `total_weight`:
///   - agreement: `>=` 70% (inclusive)
///   - disagreement: `>` 30% (strict)
///   - three regions: [0, 30%] neither, (30%, 70%) disagreement only,
///     [70%, total] both
///
/// Walking 0, 30%, 30%+1, 70%-1, 70% catches a flipped inequality on either
/// side and any drift between the two threshold constants. Also pins the
/// "agreement implies disagreement" relation, which holds as long as the
/// agreement threshold sits above the disagreement one.
fn thresholds_partition_weight_space() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // 0%: neither.
    assert!(!evaluator.reached_agreement(0));
    assert!(!evaluator.reached_disagreement(0));

    // Exactly 30%: strict `>`, so not yet disagreement.
    assert!(!evaluator.reached_agreement(300_000_000));
    assert!(!evaluator.reached_disagreement(300_000_000));

    // One unit past 30%: gap region, disagreement only.
    assert!(!evaluator.reached_agreement(300_000_001));
    assert!(evaluator.reached_disagreement(300_000_001));

    // One unit below 70%: still in the gap.
    assert!(!evaluator.reached_agreement(699_999_999));
    assert!(evaluator.reached_disagreement(699_999_999));

    // Exactly 70%: agreement (`>=`), and disagreement still holds since 70% > 30%.
    assert!(evaluator.reached_agreement(700_000_000));
    assert!(evaluator.reached_disagreement(700_000_000));
}
