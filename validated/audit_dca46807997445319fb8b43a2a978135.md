## Title
Malformed `parameters` in `createDstEscrow` bricks both `withdraw` and `publicWithdraw`, permanently freezing maker funds until taker-only cancel/rescue - (File: `contracts/BaseEscrowFactory.sol`, `contracts/EscrowDst.sol`, `contracts/libraries/ImmutablesLib.sol`)

### Summary
`createDstEscrow` accepts an arbitrary `dstImmutables.parameters` blob from the caller (the destination-escrow creator/taker) without any length or fee-consistency validation, then funds the escrow with the full `amount` and safety deposit regardless of that content. [2](#0-1)  Both `EscrowDst.withdraw` and `EscrowDst.publicWithdraw` funnel into the shared `_withdraw` function, which unconditionally decodes `integratorFeeAmountCd()` / `protocolFeeAmountCd()` from `immutables.parameters`. [3](#0-2)  `ImmutablesLib.protocolFeeAmountCd`/`integratorFeeAmountCd` revert with `IndexOutOfRange()` whenever `parameters.length` is shorter than `0x20`/`0x40` bytes. [4](#0-3)  Since `parameters` is baked into the immutables hash used both as the CREATE2 salt and as the per-call validation hash, no other value can ever be substituted at withdrawal time. [5](#0-4) 

### Finding Description
`createDstEscrow` is a permissionless entrypoint — any address can call it with self-chosen `dstImmutables`, funding the escrow with their own dst tokens and safety deposit. [2](#0-1)  Nothing in this function validates `parameters.length` or that decoded fee amounts are sane relative to `amount`. An attacker acting as the destination-escrow creator can set `parameters` to a 1-byte (or empty) blob. The escrow deploys and gets funded normally (the `safeTransferFrom`/`msg.value` checks don't touch `parameters`). Once timelocks progress to `DstPublicWithdrawal`, any access-token holder who knows the secret calls `publicWithdraw`, but `_withdraw` reverts at `immutables.integratorFeeAmountCd()`/`protocolFeeAmountCd()` because `parameters.length < 0x20`. [6](#0-5)  The identical revert occurs for the private `withdraw()` path since both share `_withdraw`. Because `withdraw`/`publicWithdraw` are the only functions that pay out to the maker, and both are permanently bricked by the fixed, hash-committed `parameters`, the maker can never receive the destination funds through the normal happy path — including via the public-withdrawal safety valve that is specifically designed to protect the maker against an uncooperative/malicious taker.

### Impact Explanation
The only remaining exits are `cancel()` and `rescueFunds()`, both gated by `onlyCaller(immutables.taker.get())` — i.e., only the same party that created the malformed escrow. [7](#0-6) [1](#0-0)  This removes the intended trust-minimization guarantee that any access-token holder can complete a valid withdrawal on the maker's behalf once the secret is known, turning what should be a self-service payout into a scenario fully controlled by the potentially malicious taker. This matches "Temporary freezing of funds" during the live swap lifecycle, since the maker's payout is completely blocked until the taker chooses to cancel (returning tokens to themselves, not the maker) or waits out `RESCUE_DELAY` to self-rescue.

### Likelihood Explanation
High. `createDstEscrow` has no whitelist/authorization gate visible in scoped code, and constructing a 1-byte `parameters` field requires no special privileges — only the ability to call `createDstEscrow` with a crafted `Immutables` struct and fund it, which is the normal, expected action of any resolver/taker.

### Recommendation
Validate `dstImmutables.parameters` length (and ideally the sanity of decoded fee amounts vs. `amount`) inside `createDstEscrow` before deployment/funding, or make fee decoding tolerant of short/empty `parameters` (treating missing fee fields as zero) so that `withdraw`/`publicWithdraw` cannot be permanently bricked by caller-supplied metadata.

### Proof of Concept
1. Attacker (as taker) builds `dstImmutables` with a valid `hashlock`/`maker`/`token`/`amount`, but sets `parameters = hex"00"` (1 byte).
2. Attacker calls `createDstEscrow{value: safetyDeposit}(dstImmutables, srcCancellationTimestamp)`, which deploys and fully funds `EscrowDst` (tokens transferred via `safeTransferFrom`). [2](#0-1) 
3. Warp past `DstWithdrawal` — attacker (taker) simply never calls `withdraw`.
4. Warp past `DstPublicWithdrawal`; any access-token holder calls `publicWithdraw(secret, immutables)`. This reverts with `ImmutablesLib.IndexOutOfRange()` from `protocolFeeAmountCd`, because `parameters.length (1) < 0x20`. [8](#0-7) 
5. The maker's payout is stuck; only the attacker/taker can later call `cancel()` (reclaiming the deposited dst tokens for themselves) or `rescueFunds()` after `RESCUE_DELAY`.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    function hash(IBaseEscrow.Immutables calldata immutables) internal pure returns(bytes32 ret) {
        // Compute the EIP-712 hash for the immutables struct
        bytes calldata parameters = immutables.parameters;
        assembly ("memory-safe") {
            let ptr := mload(0x40)

            // Copy immutables.parameters to memory and compute its hash
            calldatacopy(ptr, parameters.offset, parameters.length)
            let parametersHash := keccak256(ptr, parameters.length)

            // Copy the immutables struct to memory, patch `parameters` and compute its hash
            calldatacopy(ptr, immutables, IMMUTABLES_SIZE)
            mstore(add(ptr, IMMUTABLES_LAST_WORD), parametersHash)
            ret := keccak256(ptr, IMMUTABLES_SIZE)
        }
    }
