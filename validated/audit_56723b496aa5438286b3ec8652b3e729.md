### Title
Unprivileged caller can inject a zero-price `Listing` dynamic field via `uid_mut()` and drain kiosk items for free — (`crates/sui-framework/packages/sui-framework/sources/kiosk/kiosk.move`)

### Summary
When a `Kiosk` has `allow_extensions=true`, `uid_mut()` returns `&mut UID` to **any** caller with no ownership check. Because `Listing` is a public struct and `purchase()` blindly trusts the `Listing` dynamic field as the sale price, an attacker can inject `Listing { id: <item_id>, is_exclusive: false }` with `price=0` and call `purchase()` with a zero-value coin to extract any placed-but-not-yet-listed item for free.

### Finding Description

`uid_mut()` guards access only on the `allow_extensions` boolean flag:

```move
public fun uid_mut(self: &mut Kiosk): &mut UID {
    assert!(self.allow_extensions, EUidAccessNotAllowed);
    &mut self.id
}
```

No `KioskOwnerCap` is required. Once the owner enables `allow_extensions` (intending to allow extension metadata), every address on-chain can call `uid_mut()` and obtain `&mut UID` — the same UID that backs all kiosk-internal dynamic fields including `Listing`, `Item`, and `Lock`.

`Listing` is a fully public struct:

```move
public struct Listing has copy, drop, store { id: ID, is_exclusive: bool }
```

Any module can construct it. An attacker can therefore call:

```move
df::add(kiosk.uid_mut(), Listing { id: victim_item_id, is_exclusive: false }, 0u64);
```

`purchase()` then removes that DF, reads `price = 0`, asserts `0 == payment.value()` (passes with a zero coin), decrements `item_count`, removes the item from `dof`, deposits 0 into `profits`, and returns:

```move
(inner, transfer_policy::new_request(id, 0, object::id(self)))
```

The attacker receives the item and a `TransferRequest` with `paid=0`.

### Impact Explanation

- **Direct fund theft**: the kiosk owner receives 0 SUI instead of the intended sale price for any placed item.
- **State corruption**: `kiosk.profits` is not credited; `TransferRequest.paid=0` causes royalty rules that inspect `paid` to compute zero royalties, undermining creator revenue enforcement.
- Meets the Critical gate: *"direct fund theft or state corruption from unauthorized object … transfer … that breaks object ownership … or execution authority guarantees."*

### Likelihood Explanation

Requires `allow_extensions=true`. This is deprecated but still functional and settable by any kiosk owner. Owners enabling it for legitimate extension use (e.g., attaching metadata) do not expect it to expose item-theft. The attack is permissionless once the flag is set — no leaked keys, no validator collusion, no governance.

### Recommendation

1. **Immediate**: Add an owner check to `uid_mut()`:
   ```move
   public fun uid_mut(self: &mut Kiosk, cap: &KioskOwnerCap): &mut UID {
       assert!(self.has_access(cap), ENotOwner);
       &mut self.id
   }
   ```
   This is a breaking change but the function is already deprecated.
2. **Alternatively**: Remove `uid_mut()` entirely (it is already marked deprecated in favour of `uid_mut_as_owner` and the `kiosk_extension` API).
3. **Defense-in-depth**: In `purchase()`, verify the `Listing` DF was written through the authorised `list()` path (e.g., by storing a separate owner-signed nonce or by restricting DF writes to `(package)` visibility).

/// Called in a PTB after the victim kiosk has allow_extensions=true

public fun steal<T: key + store>(
    kiosk: &mut Kiosk,
    item_id: ID,
    policy: &TransferPolicy<T>,
    ctx: &mut TxContext,

    let zero_coin = coin::zero<SUI>(ctx);
    let (item, request) = kiosk.purchase<T>(item_id, zero_coin);

    // 4. Confirm against a permissive policy (or any policy with no paid-amount rule)
    sui::transfer_policy::confirm_request(policy, request);

}
