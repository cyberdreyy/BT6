### Title
Bridge `outgoingToken` secret is returned unredacted to any authenticated caller via `BridgeTypesController.Show`/`Index`/`Update`/`Destroy` - ([File: core/web/presenters/bridges.go])

### Finding Description
`bridges.BridgeType` stores the incoming credential only as a salted hash (`IncomingTokenHash`/`Salt`), but stores `OutgoingToken` in plaintext, exactly as generated in `NewBridgeType`: [1](#0-0) . `presenters.NewBridgeResource` maps this plaintext value directly into the `outgoingToken` JSON field with no `omitempty`/redaction, unlike `IncomingToken` which is commented as "only provided when creating a Bridge": [2](#0-1) .

`BridgeTypesController.Show` fetches the persisted `bridges.BridgeType` (which includes the plaintext `OutgoingToken`) via `FindBridge` and passes it straight into `NewBridgeResource` for the JSON API response: [3](#0-2) . The same happens in `Index`, `Update`, and `Destroy`: [4](#0-3) [5](#0-4) [6](#0-5) .

Because `OutgoingToken` is not hashed at rest and is echoed on every read/mutation of the bridge (not only at creation, unlike `IncomingToken`), any caller authorized to hit these bridge routes receives the live plaintext outgoing credential in the response body. I was not able to confirm from the code read so far the exact minimum role gate configured in `core/web/router.go` for the bridge type routes (the grep matched but content wasn't inspected before the tool budget ran out), so I cannot conclusively confirm that a "view"-role (as opposed to "admin"/"edit") session can reach `Show`. This is a material gap in verification for the specific "any authenticated caller regardless of role" claim.

### Impact Explanation
If a caller with only read/view privileges (or any role permitted to call bridge GET endpoints) can reach `Show`/`Index`, they obtain the node's outgoing bridge authentication secret, which the node uses to authenticate itself to the external adapter. This secret could be replayed by the attacker to impersonate the node's outbound calls to the external adapter, or used for further reconnaissance/lateral movement against the adapter infrastructure — a credential-disclosure impact class.

### Likelihood Explanation
Preconditions: attacker must hold any authenticated session/API token capable of calling `GET /v2/bridge_types/:BridgeName` (or the index/update/destroy routes) and a bridge type must already exist. The disclosure is deterministic and repeatable (every call returns the current plaintext `outgoingToken`), not one-time like `IncomingToken`. The unresolved variable is the exact minimum role required by the router for this route, which determines whether this reaches down to a low-privileged "view" role as the question assumes, or is restricted to higher-privileged roles already trusted with bridge management.

### Recommendation
Do not persist or return `OutgoingToken` in plaintext through the presenter for read paths; only return it (like `IncomingToken`) at bridge-creation time, and store/return a redacted or hashed representation thereafter. Add `omitempty`/masking to `BridgeResource.OutgoingToken` in `core/web/presenters/bridges.go` and strip it from `NewBridgeResource` for `Show`, `Index`, `Update`, and `Destroy` responses.

### Proof of Concept
1. Go handler-integration test using the existing web test harness (see `core/web/bridge_types_controller_test.go` patterns):
   - Create a bridge via `POST /v2/bridge_types` as an admin/authenticated user; capture the returned `outgoingToken`.
   - Using a session/API token restricted to the lowest permitted role able to call bridge routes (confirm exact role from `core/web/router.go`), call `GET /v2/bridge_types/:BridgeName`.
   - JSON-unmarshal the response into `presenters.BridgeResource` and assert `resource.OutgoingToken != ""` and equals the value captured at creation, proving the secret is disclosed on every subsequent read regardless of the caller's role tier.
   - Repeat for `Index`, `Update`, `Destroy` responses to show the leak is not confined to Create.

// Update can change the restricted attributes for a bridge
func (btc *BridgeTypesController) Update(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")
	btr := &bridges.BridgeTypeRequest{}

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := c.ShouldBindJSON(btr); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if err := ValidateBridgeType(btr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := orm.UpdateBridgeType(ctx, &bt, btr); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	btc.App.GetAuditLogger().Audit(audit.BridgeUpdated, map[string]any{
		"bridgeName":                   bt.Name,
		"bridgeConfirmations":          bt.Confirmations,
		"bridgeMinimumContractPayment": bt.MinimumContractPayment,
		"bridgeURL":                    bt.URL,
	})

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// Destroy removes a specific Bridge.
func (btc *BridgeTypesController) Destroy(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error searching for bridge: %w", err))
		return
	}
	jobsUsingBridge, err := btc.App.JobORM().FindJobIDsWithBridge(ctx, name)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error searching for associated v2 jobs: %w", err))
		return
	}
	if len(jobsUsingBridge) > 0 {
		jsonAPIError(c, http.StatusConflict, fmt.Errorf("can't remove the bridge because jobs %v are associated with it", jobsUsingBridge))
		return
	}
	if err = orm.DeleteBridgeType(ctx, &bt); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("failed to delete bridge: %w", err))
		return
	}

	btc.App.GetAuditLogger().Audit(audit.BridgeDeleted, map[string]any{"name": name})

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
