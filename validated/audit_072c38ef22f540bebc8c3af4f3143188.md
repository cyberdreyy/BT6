### Title
Unauthenticated LOOP plugin metrics/pprof/discovery endpoints exposed on `/plugins/:name/*` - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the base `api` group, which only has rate-limiting and session middleware applied — no `auth.Authenticate` wrapper is used, unlike every other sensitive route in the file. This lets a fully unauthenticated attacker reach `LoopRegistryServer.pluginPPROFHandler` and pull a pprof/profile dump proxied from a registered LOOP plugin process.

### Finding Description
`NewRouter` builds the base group `api` with only `rateLimiter(...)` and `sessions.Sessions(...)` middleware [1](#0-0) , then calls `loopRoutes(app, api)` which registers the plugin routes with no additional auth middleware at all: [2](#0-1) . Contrast this with `debugRoutes` (wraps `/debug/vars` in `auth.Authenticate(...)`) at [3](#0-2) , and with the core node's own `/debug/pprof/*` endpoints registered via `metricRoutes(authv2)` which is only reachable inside the `authv2` group requiring `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)` [4](#0-3) [5](#0-4) .

`pluginPPROFHandler` looks up the plugin by name and, if found, proxies the request to `http://{loopHostName}:{PrometheusPort}/debug/pprof/{profile}` with no credential check of its own: [6](#0-5) . An attacker sending `GET /plugins/{name}/debug/pprof/heap` with zero auth headers reaches this handler and receives whatever the backing LOOP plugin process returns.

However, this endpoint forwards to the **LOOP plugin subprocess's** own pprof/metrics port (`p.EnvCfg.PrometheusPort` on `loopHostName`, normally `localhost`) — it is not proxying the main `chainlink` node process's `/debug/pprof`. The node's own memory (containing private keys, session tokens, etc.) is served by `net/http/pprof` handlers wired in `metricRoutes`, which are gated by `auth.Authenticate` inside the authenticated `authv2` group, as shown above. So the un-authenticated route does not directly dump the core node process's heap/goroutines/private-key material; it discloses profiling data (goroutine stacks, memory allocation info, potentially plugin-internal state) of the separate LOOP plugin process. Still, this is an authentication gap: any unauthenticated caller can discover registered plugin names (via `/discovery`) and pull that plugin's runtime profile, and depending on the plugin (e.g., a signing/median LOOP plugin), goroutine/heap dumps could still reveal sensitive in-memory state specific to that plugin (e.g., report data, RPC endpoints, internal config) without any credential. This is a genuine authentication-soundness bug: a debug surface reachable without any of `auth.Authenticate`'s token/session/EI checks, in direct contrast to the analogous `/v2/.../debug/pprof` routes that require authentication.

### Impact Explanation
This does not directly expose the chainlink node process's own private keys or user session tokens in memory (that surface is authenticated). It does expose an unauthenticated debug/profiling surface for LOOP plugin subprocesses (heap, goroutine, cmdline, symbol, profile), enabling information disclosure of plugin internal state and aiding further reconnaissance/attack planning against the node without any credentials. This corresponds to a limited "information disclosure via missing authentication on a debug endpoint" impact class — lower severity than direct core-process key/session leakage, but still a real authentication-soundness gap since it deviates from the codebase's own established pattern of gating all debug/pprof surfaces behind `auth.Authenticate`.

### Likelihood Explanation
No preconditions or credentials are required — any network client that can reach the node's HTTP listener can call these routes; only rate limiting applies (`rl.AuthenticatedPeriod/Authenticated`, not tied to auth). The attacker only needs to know or discover a plugin name, which itself is discoverable unauthenticated via `GET /discovery` [7](#0-6) . This makes the request trivially repeatable and fully unauthenticated.

### Recommendation
Wrap `loopRoutes` registrations in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` (and an appropriate role check, e.g. `auth.RequiresAdminRole` or `RequiresViewRole`) consistent with `debugRoutes` and `metricRoutes`, so `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` all require valid session/API-token credentials before being served.

### Proof of Concept
1. Build a Go handler-level test using `NewRouter` with a minimal `chainlink.Application` mock providing a `GetLoopRegistry()` populated with one test plugin (via `plugins.NewTestLoopRegistry`).
2. Issue `httptest.NewRequest("GET", "/plugins/testplugin/debug/pprof/heap", nil)` with no `Authorization` header and no session cookie, through `router.ServeHTTP`.
3. Assert the response status is not `401`/`403` and that `pluginPPROFHandler` is invoked (e.g., by stubbing the backing plugin HTTP server to return a marker body and asserting it's echoed back), demonstrating the route is reachable without any of `auth.Authenticate`'s checks.
4. Compare against a control request to `/v2/debug/pprof/heap` (in `authv2`) with no auth headers and assert it correctly returns `401 Unauthorized`, highlighting the inconsistency.

func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
