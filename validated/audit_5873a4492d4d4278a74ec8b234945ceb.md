### Title
Stale-conflict fast path bypasses the node-truth `conflict_still_blocks` check, letting a signer sign a genuinely live conflicting block - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
The external report's root issue is a **static parameter that cannot adapt to real conditions**, breaking a safety invariant that depends on that parameter tracking reality. The `stableswap` amplifier is fixed at pool creation and can't respond to changing market conditions, letting an attacker exploit the mismatch between the frozen parameter and the true state of the world. The direct analog in this repo is `tenure_last_block_proposal_timeout` (`freshness_cutoff`): a fixed wall-clock window used as a *proxy* for "is this signed conflicting block still alive in the chain?", when the repo already has a deterministic, node-derived answer to that exact question (`conflict_still_blocks`) that gets skipped entirely once the timer expires.

### Finding Description
Before a signer puts its signature on a block that crossed the pre-commit threshold, it must check that no fresh, still-live conflicting signature exists at the same or higher height, in any tenure: [1](#0-0) 

The `find()` predicate only calls the deterministic, node-derived `conflict_still_blocks` (which asks the node whether the conflicting tenure's sortition is still canonical and whether the chain still reaches the conflicting block) **if** `conflict.last_endorsed > freshness_cutoff` is true. `freshness_cutoff` is `get_epoch_time_secs() - tenure_last_block_proposal_timeout` — a purely local, static-duration heuristic (default 30s): [2](#0-1) [3](#0-2) 

Once `conflict.last_endorsed <= freshness_cutoff`, the conflict is treated as stale and dropped from consideration **without ever consulting the node**. But `conflict_still_blocks` is the only mechanism in the codebase that can *prove* a conflicting signature is dead (via sortition-canonicity and tenure-tip lookups): [4](#0-3) 

`get_signed_conflicts` explicitly documents that a signature is a "bearer instrument" that stays dangerous until proven dead, and that even global rejection does not clear it — only staleness or node-derived death do: [5](#0-4) 

The bug is that "staleness" (a local, fixed-duration heuristic like the frozen amplifier) is allowed to stand in for "node-derived death" and short-circuits the actual proof. `tenure_last_block_proposal_timeout` cannot adapt to real network/propagation conditions — exactly the "static parameter, dynamic reality" mismatch in the referenced report.

### Impact Explanation
If a signer's own earlier signature over block A (height H, tenure T1) is older than `tenure_last_block_proposal_timeout` (default 30s) but block A is, per the node, still fully canonical and reachable (i.e. `conflict_still_blocks` would return `true`), the signer will nonetheless sign a competing block B at height H in tenure T2 without ever asking the node. Because each signer independently computes `freshness_cutoff` from its own local clock and its own `last_endorsed` timestamp, different signers cross this threshold at different times under normal propagation delay/jitter or a miner-induced stall (holding block A just under 70% weight while gossip is slow). This creates a window where overlapping-but-different signer subsets can accumulate threshold weight on A and B respectively — i.e., a rejection/staleness timer, not chain truth, decides whether a signer may double-sign at a height. This is exactly the class the prompt calls out as Critical: "a signer signing an invalid, non-canonical, or conflicting block."

### Likelihood Explanation
No majority of colluding signers is required — a single miner (plus ordinary gossip delay, or a deliberately slow/partitioned relay of pre-commits/signatures) can hold block A just below the global-acceptance threshold for slightly longer than `tenure_last_block_proposal_timeout`, then propose a conflicting block B in a new tenure. Every signer's freshness clock runs independently off wall time, so the "safe" 30s default is a fixed guess, not a proof, and is reachable purely through timing/network conditions any single proposer can influence.

### Recommendation
Do not let the local `freshness_cutoff` heuristic bypass `conflict_still_blocks`. At minimum, when a conflict is "stale" per the local timer, still require an authoritative node check before allowing the new signature (i.e., always require `conflict_still_blocks`/`reorg_permit_stands` semantics, using the timer only to decide whether the round-trip is worth attempting, not to skip verifying liveness). Alternatively, replace the fixed timeout with a value negotiated/observed dynamically (e.g., derived from actual global-acceptance/rejection observation rather than a static duration), analogous to Curve's `ramp_A`-style adjustable parameter instead of a frozen constant.

### Proof of Concept
1. Miner proposes block A at height H in tenure T1; enough signers pre-commit and this signer signs A (`signed_self = t0`), but global acceptance stalls (e.g., gossip delay, some signers slow/offline) so A never reaches 70% weight.
2. Miner (or a Bitcoin reorg) starts tenure T2 and proposes block B at height H.
3. At `t0 + tenure_last_block_proposal_timeout + ε`, this signer re-evaluates the pre-commit threshold for B. `get_signed_conflicts` returns A as a conflict, but `conflict.last_endorsed (t0) <= freshness_cutoff`, so the `find()` predicate in `stacks-signer/src/v0/signer.rs:1403-1411` short-circuits to `false` without calling `conflict_still_blocks` — even though block A is still fully canonical on the node (i.e., `conflict_still_blocks` would have returned `true` had it been checked).
4. The signer signs B. Other signers, whose own `last_endorsed`/local clocks lag or lead slightly, may still complete A's signature set later (their own freshness windows haven't lapsed, or they never signed A but do so afterward believing it is still the tip), producing two independently-completable, conflicting signed blocks at height H.

    fn conflict_still_blocks(
        &self,
        stacks_client: &StacksClient,
        conflict: &SignedConflictInfo,
        proposed_height: u64,
    ) -> bool {
        if let Ok(burn_block) = self
            .signer_db
            .get_burn_block_by_ch(&conflict.consensus_hash)
        {
            match stacks_client.get_sortition_by_burn_hash(&burn_block.block_hash) {
                Ok(_) => {
                    // The tenure's sortition is still canonical: the conflict is live at the
                    // burn chain level, so fall through to the block-level questions.
                }
                Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => {
                    // A 404 only proves the sortition was orphaned if the node's burnchain
                    // view actually covers the burn block's height: a node still catching up
                    // 404s canonical burn blocks it hasn't processed yet (and the
                    // endpoint also 404s on internal data misses). Only trust it once the
                    // node's burnchain tip is at or past the stored burn block.
                    match stacks_client.get_peer_info() {
                        Ok(peer_info) if peer_info.burn_block_height >= burn_block.block_height => {
                            info!("{self}: A conflicting block's tenure was orphaned by a burnchain fork. The conflict no longer blocks.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                                "conflicting_block_height" => conflict.stacks_height,
                                "burn_block_hash" => %burn_block.block_hash,
                            );
                            return false;
                        }
                        Ok(peer_info) => {
                            info!("{self}: The node does not know a conflicting block's burn block, but its burnchain tip has not reached that height, so this does not prove the tenure was orphaned. Leaving the conflict in place.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                                "burn_block_hash" => %burn_block.block_hash,
                                "burn_block_height" => burn_block.block_height,
                                "node_burn_block_height" => peer_info.burn_block_height,
                            );
                            return true;
                        }
                        Err(e) => {
                            warn!("{self}: Failed to fetch the node's burnchain tip while checking a conflicting block's tenure: {e:?}. Leaving the conflict in place.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                            );
                            return true;
                        }
                    }
                }
                Err(e) => {
                    warn!("{self}: Failed to check whether a conflicting block's tenure is still canonical: {e:?}. Leaving the conflict in place.";
                        "conflicting_consensus_hash" => %conflict.consensus_hash,
                    );
                    return true;
                }
            }
        }
        let node_reaches_conflict = match stacks_client.get_tenure_tip(&conflict.consensus_hash) {
            Ok(tip) => tip.anchored_header.height() >= conflict.stacks_height,
            // A 404 is an answer, not a failure: the node has no blocks in that tenure at all.
            Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => false,
            Err(e) => {
                warn!("{self}: Failed to fetch the canonical tip of a conflicting block's tenure: {e:?}. Leaving the conflict in place.";
                    "conflicting_consensus_hash" => %conflict.consensus_hash,
                    "conflicting_block_height" => conflict.stacks_height,
                );
                return true;
            }
        };
        node_reaches_conflict
            || (!conflict.globally_accepted && conflict.stacks_height <= proposed_height)
    }
