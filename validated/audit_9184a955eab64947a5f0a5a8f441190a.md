## #ValidAnalog found

### Title
Unvalidated `new_authority` in account migration allows funds to be permanently frozen - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
The `transfer_to_new_account` (and `transfer_to_new_account_pda`) instructions let a `MarginfiAccount` authority migrate their account's lending positions to a brand-new account under a `new_authority` of their choosing. The `new_authority` field is declared as a completely unchecked account with no validation that it is a non-default, controllable public key, mirroring the reported `_updateFeeWallet` bug class where an address field is accepted without any sanity check.

### Finding Description
`TransferToNewAccount` and `TransferToNewAccountPda` accept `new_authority` as an `UncheckedAccount`, explicitly documented as unchecked: [1](#0-0) 

`transfer_to_new_account` then uses this raw key to initialize the new account's authority, and disables/zeroes the old account, moving the lending balances to the new account: [2](#0-1) 

No check anywhere in `transfer_to_new_account` (or the analogous `transfer_to_new_account_pda`) rejects `new_authority == Pubkey::default()` or any other address that no keypair can sign for. The only checks performed are on the *old* account (frozen state, flashloan/receivership/order-execution flags, `migrated_to == default`) and on the global fee wallet used for the migration fee — none constrain `new_authority` itself: [3](#0-2) 

The off-chain `p0-cli` tooling does add a client-side guard (`if new_authority == Pubkey::default() { bail!(...) }`), but this is purely an optional convenience check in one client and provides no on-chain protection: [4](#0-3) 

Any other client, SDK, or direct RPC call can invoke `transfer_to_new_account`/`transfer_to_new_account_pda` with `new_authority` set to `Pubkey::default()` (or any other un-ownable/incorrect key) and the on-chain program will accept it unconditionally, because there is no on-chain enforcement.

### Impact Explanation
`initialize_migrated_account` copies the old account's `lending_account` (all deposit/borrow balances) into the newly created account, and `finalize_migrated_old_account` disables the old account and zeroes its `lending_account`, permanently moving control of the funds to the new account: [5](#0-4) 

If `new_authority` is set to the zero address (or otherwise unresolvable/unsignable key), the new account becomes permanently uncontrollable — no signature can ever satisfy `authority` checks for future instructions — while the old account is disabled and its balances are already zeroed. All deposited/borrowed positions held by that account become durably frozen and irretrievable, exactly the "funds become irretrievable" impact described in the original report about an unvalidated `feeWallet`. This is an unprivileged, user-facing action (any account authority can trigger it on their own account) with a genuine financial/durable-freeze consequence, not merely a theoretical or admin-only issue.

### Likelihood Explanation
This can be triggered by any account authority calling a permissionless, unprivileged instruction (`transfer_to_new_account` / `transfer_to_new_account_pda`) — no admin or special role is required. It could occur due to a client bug, a malicious front-end, or a user error, since only the optional CLI in this repo performs the sanity check and no on-chain constraint exists. Given that this instruction is part of the standard account-migration flow (also exposed to PDA-based accounts), the likelihood of a bad `new_authority` being submitted (accidentally or via a compromised/careless integrator) is realistic.

### Recommendation
Add on-chain validation in `transfer_to_new_account` and `transfer_to_new_account_pda` to reject `new_authority == Pubkey::default()` (and any other easily identifiable invalid values, e.g. the program ID or the old account's own key/authority) before finalizing the migration, mirroring the recommendation from the original `feeWallet` finding. Consider requiring `new_authority` to be provided as a signer, or at minimum requiring an explicit non-default check with a clear error such as `MarginfiError::InvalidAuthority` prior to zeroing/disabling the old account.

### Proof of Concept
1. Create a `MarginfiAccount` and deposit funds so it has non-zero `lending_account` balances.
2. Call `transfer_to_new_account` (or `transfer_to_new_account_pda`) directly via RPC/SDK (bypassing `p0-cli`'s client-side check), supplying:
   - `old_marginfi_account` = the funded account
   - `new_authority` = `Pubkey::default()` (all-zero key)
   - valid `global_fee_wallet` matching `group.fee_state_cache.global_fee_wallet`
3. Observe the transaction succeeds: `initialize_migrated_account` copies the lending balances into the new account with `authority = Pubkey::default()`, and `finalize_migrated_old_account` sets `ACCOUNT_DISABLED` on the old account and zeroes its `lending_account`.
4. Attempt to interact with the new account (deposit, withdraw, borrow, etc.) with any keypair — every such instruction requires `authority` to sign, which is impossible for the zero address, permanently locking the migrated funds.

fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}

pub fn transfer_to_new_account(ctx: Context<TransferToNewAccount>) -> MarginfiResult {
    // Validate the global fee wallet and claim a nominal fee
    let group = ctx.accounts.group.load()?;
    check_eq!(
        ctx.accounts.global_fee_wallet.key(),
        group.fee_state_cache.global_fee_wallet,
        MarginfiError::InvalidFeeAta
    );
    anchor_lang::system_program::transfer(ctx.accounts.transfer_fee(), ACCOUNT_TRANSFER_FEE)?;

    let mut old_account = ctx.accounts.old_marginfi_account.load_mut()?;

    check!(
        !old_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_RECEIVERSHIP),
        MarginfiError::ForbiddenIx
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION),
        MarginfiError::ForbiddenIx
    );

    check!(
        old_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before transfer"
    );

    // Prevent multiple migrations from the same account
    check_eq!(
        old_account.migrated_to,
        Pubkey::default(),
        MarginfiError::AccountAlreadyMigrated
    );

    let mut new_account = ctx.accounts.new_marginfi_account.load_init()?;
    let current_timestamp = Clock::get()?.unix_timestamp as u64;
    initialize_migrated_account(
        &mut new_account,
        &old_account,
        ctx.accounts.new_authority.key(),
        current_timestamp,
        ctx.accounts.old_marginfi_account.key(),
    );

#[derive(Accounts)]
pub struct TransferToNewAccount<'info> {
    #[account(
        constraint = (
            !group.load()?.is_protocol_paused()
        ) @ MarginfiError::ProtocolPaused
    )]
    pub group: AccountLoader<'info, MarginfiGroup>,

    #[account(
        mut,
        has_one = group @ MarginfiError::InvalidGroup,
        constraint = {
            let a = old_marginfi_account.load()?;
            account_not_frozen_for_authority(&a, authority.key())
        } @ MarginfiError::AccountFrozen,
        constraint = {
            let a = old_marginfi_account.load()?;
            let g = group.load()?;
            is_signer_authorized(&a, g.admin, authority.key(), false, false)
        } @ MarginfiError::Unauthorized
    )]
    pub old_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    #[account(
        init,
        payer = fee_payer,
        space = 8 + std::mem::size_of::<MarginfiAccount>()
    )]
    pub new_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    pub authority: Signer<'info>,

    #[account(mut)]
    pub fee_payer: Signer<'info>,

    /// CHECK: WARN: New authority is completely unchecked

    /// CHECK: Validated against group fee state cache
    #[account(mut)]
    pub global_fee_wallet: UncheckedAccount<'info>,

}
