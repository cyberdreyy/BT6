### Title
Unauthenticated request forwarding to DON nodes via `confidentialrelay` handler's `HandleJSONRPCUserMessage` - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
The non-legacy JSON-RPC routing path in `gateway.ProcessRequest` dispatches requests by service name to `g.serviceToMultiHandler` without calling `msg.Validate()` or any signature check, unlike the legacy path which does [1](#0-0) . While the vault handler independently enforces authorization via `h.requestProcessor.ProcessRequest` before doing privileged work [2](#0-1) , the `confidentialrelay` handler's `HandleJSONRPCUserMessage` performs no equivalent authentication/authorization check and immediately fans the raw request out to all DON member nodes.

### Finding Description
`gateway.ProcessRequest` treats any request with `msg == nil || msg.Body.DonId == ""` as a "non-legacy" request and routes purely by `jsonRequest.ServiceName()` into `g.serviceToMultiHandler[serviceName]`, calling `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` directly — no `msg.Validate()`, no signature verification is performed on this path [3](#0-2) . Multi-handler dispatch further routes purely by JSON-RPC `Method` string with no auth involved [4](#0-3) .

For `confidentialrelay.handler.HandleJSONRPCUserMessage` (methods `MethodSecretsGet`, `MethodCapabilityExec`), the only checks performed are on `req.ID` (non-empty, ≤200 chars); it then creates an `activeRequest` and calls `h.fanOutToNodes`, which sends `&ar.req` directly to every DON member node via `h.don.SendToNode` [5](#0-4) [6](#0-5) . There is no call to any authorizer, no signature verification, and no ownership/identity check anywhere in this handler — contrasting directly with the vault handler's `requestProcessor.ProcessRequest` gate [7](#0-6) .

An unauthenticated attacker can submit a JSON-RPC request with `ServiceName` matching the confidentialrelay service (no `DonId`, no `Auth`/signature fields), causing the gateway to route it straight into this handler and forward it to every node in the target DON, unauthenticated. Whether this is fully exploitable depends on what downstream enclave/DON-side verification exists (the code comments state "the enclave verifies signatures and reaches quorum" for *responses*, but the *request itself*, including e.g. `MethodSecretsGet` parameters like requested secret identifiers/owner, reaches the DON with no gateway-side identity binding) [8](#0-7) .

### Impact Explanation
If the DON-side/enclave logic that ultimately processes `MethodSecretsGet`/`MethodCapabilityExec` relies on the gateway to have authenticated/attributed the caller (as the vault handler does via `AuthorizedOwner()`), an attacker could request another user's confidential secrets or trigger capability execution under an impersonated identity, since no owner/authorization claim is verified before the request reaches the DON. This matches the "unauthorized job run" / "request impersonation" / "secret disclosure" bounty classes — but the ultimate severity depends on unverifiable DON/enclave-side enforcement not visible in this codebase, which is a genuine open question.

### Likelihood Explanation
Precondition is minimal: any unauthenticated network caller able to reach the gateway's user HTTP port and knowing (or guessing) the confidentialrelay `ServiceName`/method names can trigger this path with zero credentials — no signature, no `DonId`, no `Auth` token required, as confirmed by the identical routing test pattern used for the `vault`/`workflows` services in `gateway_test.go` (`newJSONRpcRequest` with no auth) [9](#0-8) . It is fully repeatable and requires no special network position.

### Recommendation
Add an explicit authentication/authorization step in `confidentialrelay.handler.HandleJSONRPCUserMessage` before `fanOutToNodes` is called — mirroring the vault handler's `requestProcessor.ProcessRequest`/`AuthorizedOwner()` pattern — so the gateway attributes and validates ownership/authorization of `MethodSecretsGet`/`MethodCapabilityExec` requests instead of relying on unverified downstream enforcement. Alternatively/additionally, enforce a signature or auth-field check at the `gateway.ProcessRequest` non-legacy path itself for all service-routed requests, rather than leaving it entirely to individual handlers.

### Proof of Concept
Go handler-level integration test plan:
1. Instantiate a `confidentialrelay.handler` with a mocked `handlers.DON` (`mocks.NewDON`) and DON config with N members, as done in `handler_test.go`.
2. Build a `jsonrpc.Request[json.RawMessage]` for `MethodSecretsGet` with no `Auth` field set and arbitrary `Params` (e.g., another user's secret owner/id).
3. Call `h.HandleJSONRPCUserMessage(ctx, req, callback)` directly (simulating what `gateway.ProcessRequest` does for the non-legacy path with no `DonId`/signature).
4. Assert `don.SendToNode` was called for every DON member (via `don.On("SendToNode", ...)` mock) — proving the request was forwarded with no authorization check having occurred, unlike the equivalent vault test (`TestVaultHandler_HandleJSONRPCUserMessage`) where an `Authorizer`/`requestProcessor` mock is asserted to have been invoked before forwarding.
5. Add a companion assertion enumerating `g.serviceToMultiHandler`-registered handlers (`vault`, `workflows`, `confidentialrelay`) and confirming each has an invoked authorizer mock on `HandleJSONRPCUserMessage` with no `Auth`; expect the `confidentialrelay` case to fail this assertion, demonstrating the gap.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}

	if !vaulttypes.IsGatewaySecretsMethod(req.Method) {
		return h.sendImmediateUserResponse(ctx, req, callback, api.UnsupportedMethodError, errors.New("this method is unsupported: "+req.Method))
	}

	_, cachedPublicKey := h.getCachedPublicKey()
	authorized, err := h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)
	if err != nil {
		if vaultcap.IsInvalidVaultParamsError(err) {
			return h.sendImmediateUserResponse(ctx, req, callback, api.InvalidParamsError, err)
		}
		h.lggr.Errorw("request not authorized", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "error", err)
		return errors.New("request not authorized: " + err.Error())
	}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
