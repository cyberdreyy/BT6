### Title
Missing replay protection and future-timestamp bypass of staleness check allows indefinite re-dispatch of a signed gateway message - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` only rejects messages that are *too old*; it never rejects messages with a future `payload.Timestamp`, and it does not track previously-processed `MessageId`s for this handler. Combined, this allows the exact same signed message (or a signed message with a manipulated future timestamp) to be forwarded to every DON member repeatedly.

### Finding Description
The staleness check is:
```go
if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
    // reject as stale
}
``` [1](#0-0) 

This condition only fires when `payload.Timestamp` is smaller than `now - MaxAllowedMessageAgeSec`, i.e. it only bounds messages from below (rejects old messages). There is no corresponding upper-bound check ensuring `payload.Timestamp <= now` (or `<= now + small skew`). If an attacker sets `payload.Timestamp` far in the future, `uint(payload.Timestamp)` is large and the inequality is never true, so the message is never treated as stale, regardless of `MaxAllowedMessageAgeSec`.

Separately, after passing the staleness check, the handler does:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()

for _, member := range h.donConfig.Members {
    err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
}
``` [2](#0-1) 

This unconditionally overwrites any prior entry for `msg.Body.MessageId` and dispatches to all DON members again — there is no per-`MessageId` "already processed" guard in this handler, unlike other gateway handlers in the same codebase (e.g. the JWT replay cache in `WorkflowMetadataHandler.Authorize` [3](#0-2) , the `RequestReplayGuard` used in the Vault handler [4](#0-3) , and the `activeRequests` duplicate-ID guard in the confidential relay handler [5](#0-4) ). None of that dedup logic exists on this legacy web-API-trigger path.

Because the signature covers `msg.Body` (which includes `Payload`, hence `Timestamp`), a valid signature the attacker already produced over a given `Timestamp` remains valid forever for replay of that exact byte-identical message — there is no requirement that the gateway have never seen this `MessageId`/signature/timestamp combination before.

### Impact Explanation
An unprivileged client who has produced one validly-signed `web_api_trigger` message can resend that identical message to the gateway indefinitely (or with a manipulated future timestamp to permanently bypass the age check). Each resend causes `HandleLegacyUserMessage` to dispatch the request to every DON node again via `don.SendToNode`, causing repeated unauthorized/duplicate triggering of DON node processing on behalf of that message, consuming DON/node compute resources without new authorization. This matches the "unauthorized job run / resource exhaustion via request replay" impact class — it is a duplicate-dispatch/DoS-adjacent issue rather than credential leakage or fund movement, since the message is the attacker's own signed message (no cross-user impersonation is demonstrated here).

### Likelihood Explanation
Preconditions are minimal: an attacker only needs a single previously valid signed message and network access to the gateway's message endpoint — no elevated privileges, admin access, or additional signing capability is required. The bug is trivially and repeatably exploitable by simply re-submitting the same JSON payload/signature multiple times, or by crafting one message with `Timestamp` set arbitrarily far in the future before ever submitting it.

### Recommendation
1. Add an upper bound to the staleness check to reject messages timestamped too far in the future:
   ```go
   now := uint(time.Now().Unix())
   if now - h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) || uint(payload.Timestamp) > now + allowedClockSkewSec {
       // reject
   }
   ```
   Also guard against unsigned underflow by using signed `int64` arithmetic instead of `uint` subtraction.
2. Add per-`MessageId` (or per-signature-digest) replay tracking with TTL, similar to the `RequestReplayGuard` used by the Vault handler or the `jwtReplayCache` used by `WorkflowMetadataHandler`, and reject `HandleLegacyUserMessage` calls with a `MessageId` already seen within the allowed time window instead of silently overwriting `savedCallbacks`.

### Proof of Concept
Go unit test plan in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a valid `api.Message` with `webapicap.TriggerRequestPayload{Timestamp: uint32(time.Now().Add(48*time.Hour).Unix())}`, sign it, and call `HandleLegacyUserMessage` twice with two different `handlers.Callback` mocks.
2. Assert: (a) both calls return `nil` error (no "stale message" rejection despite the far-future timestamp), and (b) `don.SendToNode` mock records dispatch to all DON members on *both* calls (`Times(2*len(members))`), demonstrating duplicate dispatch of the same signed message.
3. A second table case: submit the same message (unmodified `Timestamp` within the valid window) twice in a row and assert `don.SendToNode` is invoked twice for the same `MessageId`/payload, confirming absence of replay/dedup protection.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

	}

}
