### Title
Malicious current-tenure miner can indefinitely refresh `last_activity_time` via repeated conflicting proposals, wedging the inactivity-fallback and stalling the chain for a full burn interval - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`check_latest_block_in_tenure` counts *any* rejected, non-advancing block proposal (a "reorg attempt" or a duplicate at the same height) as valid miner activity by unconditionally calling `signer_db.update_last_activity_time`, with no check for whether this specific conflict, block hash, or time window has already been counted. Because a single slot-winning miner can cheaply mint an unlimited number of distinct proposals (e.g. by varying the timestamp field), it can call this activity-refresh path as many times as it wants, indefinitely resetting the clock that `check_miner_inactivity`/`SortitionState::is_timed_out` uses to decide whether to give up on the current miner and fall back to a valid prior tenure. This mirrors the `Voter@poke` bug class: a state-mutating function reachable without any "have I already counted this" guard, callable repeatedly to accrue/extend a benefit (here, "still active") indefinitely.

### Finding Description
`check_latest_block_in_tenure` in [1](#0-0)  implements the following logic: when a new block proposal does not advance past the tenure's last signed (or pre-committed) block, and the conflicting block's endorsement is still "fresh" (within `reorg_attempts_activity_timeout`), the code calls:

```rust
signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
``` [2](#0-1) 

This call is unconditional on every evaluation — there is no de-duplication by block hash, no cap on how many times it may fire within a window, and no requirement that the proposal be a *new* or otherwise meaningfully different attempt. The same helper is documented to run at three distinct pipeline stages for a given block — proposal arrival, validate-ok, and pre-commit/signing — and is explicitly noted as "a pre-commit never vetoes anything, it only counts as miner activity" [3](#0-2) .

`update_last_activity_time` is a plain upsert with no history or counter, just a timestamp overwrite: [4](#0-3) 

The consumer of this timestamp, `SortitionState::is_timed_out`, only gives up on the current miner once `elapsed > block_proposal_timeout` since the last recorded activity, and explicitly skips the check entirely once a block has been signed in the tenure: [5](#0-4) 

`check_miner_inactivity` uses this to decide whether to fall back to a prior valid tenure when the current miner appears to have stalled: [6](#0-5) 

A miner that has won the current slot but never intends to (or cannot) produce a block that reaches the pre-commit/signature threshold can instead keep submitting distinct, cheaply-crafted proposals that conflict with its own already-accepted or pre-committed block at the same height (e.g., only the `timestamp` field differs, producing a fresh `signer_signature_hash` each time). Each such proposal is evaluated fresh by `should_reevaluate_block` (a genuinely new block is never short-circuited) [7](#0-6) , runs through `check_latest_block_in_tenure`, fails the height check, and — as long as the previously pre-committed/locally-accepted block's timestamp is still within `reorg_attempts_activity_timeout` — refreshes `last_activity_time` for that same tenure. By repeating this before each window expires, the miner can extend "I am still active" indefinitely, exactly analogous to `Voter@poke` never checking whether the token already voted this cycle before accruing more Flux.

### Impact Explanation
While a signed block in the tenure already exists, `is_timed_out` short-circuits to `false` regardless, so the refresh trick's only bite is in the window before any block has reached the group signature threshold. During that window, this lets a single slot-winning miner unilaterally suppress the signer set's inactivity fallback and hold the tenure hostage without ever producing a globally-accepted block — no majority of signers, other signers' keys, or auth tokens are required, only ordinary block-proposal gossip from the current miner. This is a liveness wedge under the ruleset's High-impact bucket ("a signer wedged into never signing valid blocks... acting on a stale... threshold"): signers can be kept perpetually deferring to a miner that will never actually deliver a block, rather than falling back to a legitimate prior tenure. The wedge is naturally bounded by the next Bitcoin sortition (a new tenure begins regardless), which caps the blast radius to roughly one burn interval rather than being truly unbounded like the original Flux report — this materially limits severity compared to the reported analog.

### Likelihood Explanation
The prerequisites are attacker-cheap: only the current tenure's mining key and the ability to produce syntactically valid, distinctly-hashed block proposals (trivial — vary the timestamp) at the same or lower height as an already-evaluated one. No cryptographic breaks, no signer collusion, and no privileged access are needed. The main constraint is the `reorg_attempts_activity_timeout` window, which the miner must beat with each successive proposal — well within reach of automated proposal generation.

### Recommendation
Cap or rate-limit how much a single tenure's `last_activity_time` can be extended by non-advancing/conflicting proposals within a rolling window (e.g., track the number of distinct reorg-attempt refreshes per tenure, or require the conflicting endorsement's own freshness to strictly decrease rather than being re-derived from a resettable "now"). Alternatively, only count a conflicting proposal as activity the first time a given consensus_hash/height pair is seen, rather than on every fresh proposal hash.

### Proof of Concept
1. Miner M wins the sortition for tenure T and proposes block A at height N; signer pre-commits (or locally accepts) A, setting `approved_time`/`signed_self` at time t0.
2. Before `reorg_attempts_activity_timeout` elapses, M submits block B (same tenure T, height N, different `timestamp` field ⇒ new `signer_signature_hash`). `should_reevaluate_block` treats it as unseen and re-runs `check_proposal` → `check_latest_block_in_tenure`, which finds B does not exceed A's height, and since A's endorsement is still fresh, calls `update_last_activity_time(T, now)`.
3. Repeat step 2 with blocks C, D, E, ... each time before the timeout window from the previous refresh expires.
4. `SortitionState::is_timed_out(T, ...)` never observes `elapsed > block_proposal_timeout`, so `check_miner_inactivity` never falls back to the prior tenure, even though M has never produced a block that reached the group signature threshold in T.

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

        // A block we have only pre-committed to must NOT veto this proposal, but, similar to above
        // this should still count as activity for the miner.
        let last_accepted_block = signer_db
            .get_last_accepted_block(tenure_id)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;
        if let Some(info) = last_accepted_block {
            let is_fresh_pre_commit = info.state == BlockState::PreCommitted
                && info.approved_time.is_some_and(|approved_time| {
                    approved_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
                        > get_epoch_time_secs()
                });
            if is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length {
                info!(
                    "Miner's block proposal conflicts with a block we have only pre-committed to. Counting it as miner activity, but not rejecting the proposal.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "pre_committed_signer_signature_hash" => %info.block.header.signer_signature_hash(),
                    "pre_committed_chain_length" => info.block.header.chain_length,
                );
                if let Err(e) = signer_db
                    .update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
                {
                    warn!("Failed to update last activity time: {e}");
                }
            }

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
