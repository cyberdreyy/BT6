## Finding

### Title
Unbounded recursion in MPT traversal causes fault-proof program hang/stack-overflow on attacker-crafted L1 preimages - (File: `crates/proof/mpt/src/list_walker.rs`, `crates/proof/mpt/src/node.rs`)

### Summary
The CVE-2017-14333 bug class is "attacker-controlled chained/linked data field (`vn_next`) drives an unbounded loop with no sanity bound, causing a hang/DoS." The Base fault-proof program's MPT walker has the analogous defect: `TrieNode::unblind`/`open`/`insert` (`crates/proof/mpt/src/node.rs`) and `OrderedListWalker::fetch_leaves` (`crates/proof/mpt/src/list_walker.rs`) recursively follow `TrieNode::Blinded { commitment }` hash pointers by fetching preimages from the `TrieProvider`/preimage oracle, with no recursion-depth bound anywhere in the crate.

### Finding Description
In the fault-proof/derivation pipeline, L1 receipts and transactions are derived from an MPT root by walking the trie via `OrderedListWalker::hydrate` → `fetch_leaves`, which recurses into `TrieNode::Blinded` children by calling `Self::get_trie_node` (which calls `fetcher.trie_node_by_hash`) and then recursing again: [1](#0-0) 

Likewise `TrieNode::open`, `TrieNode::insert`, and `TrieNode::unblind` all recurse into child/blinded nodes without any depth counter or limit: [2](#0-1) 

The preimages consumed here are supplied by the untrusted `PreimageOracleClient` in the fault-proof/dispute-game context (`crates/proof/proof/src/l1/chain_provider.rs`, used to derive L1 deposit transactions and system-config updates from attacker-controlled L1 receipt data during derivation): [3](#0-2) 

The oracle is the honest/dishonest-challenger-fed preimage server for a dispute game; a dispute-game participant controls what preimages are served for a given hash and can therefore construct (or claim to serve) a chain of `Extension`/`Branch` nodes nested arbitrarily deep, each node's child being another valid, hash-addressed blob. There is no `MAX_DEPTH`-style guard in this crate (confirmed absent via search), unlike other parsers in the codebase such as the CBOR/COSE parser which explicitly enforces `MAX_CBOR_NESTING_DEPTH`: [4](#0-3) 

Each recursive call in `open`/`insert`/`unblind`/`fetch_leaves` consumes stack space and issues a synchronous/async round trip to the preimage oracle per level; an arbitrarily deep chain therefore drives either unbounded stack growth (native stack overflow, aborting the process) or an effectively unbounded, time-consuming traversal loop — directly analogous to the readelf `vn_next` hang: an attacker-influenced "next" chain with no depth/sanity check drives the victim program into a hang or crash.

### Impact Explanation
This code runs inside the fault-proof program that computes the L2 output root used to resolve dispute games. A crafted preimage chain that causes the program to hang or stack-overflow means the fault-proof program can never produce (or times out before producing) the correct output root for the disputed claim, i.e. a node halt / inability to serve a provable output root for that dispute game path. This satisfies the "wrong provable output root" / "node halt" impact bar required by the validation rules.

### Likelihood Explanation
Reachable directly by a dispute-game participant who controls what preimages get served in response to hints during the derivation phase (deriving deposit transactions/system-config from L1 receipts via `OrderedListWalker`). No special privileges beyond normal participation in the dispute-game / preimage-serving protocol are required, and the vulnerable code path (deriving deposits/receipts from an L1 receipts MPT root) is exercised on every epoch transition during derivation, making the attack surface routinely reachable.

### Recommendation
Add an explicit recursion/traversal depth limit (mirroring the `MAX_CBOR_NESTING_DEPTH` pattern already used elsewhere in the codebase) to `TrieNode::open`, `TrieNode::insert`, `TrieNode::unblind`, and `OrderedListWalker::fetch_leaves`, returning a structured error once a maximum depth (e.g., bounded by the maximum possible nibble-path length, which is intrinsically bounded for a real MPT) is exceeded, so a pathological/attacker-supplied preimage chain cannot drive unbounded recursion.

### Proof of Concept
1. In the dispute game, when the fault-proof program requests a preimage for a receipts/transactions MPT root hash via the `PreimageOracleClient`, serve a `TrieNode::Extension` node whose child is another `Blinded` commitment.
2. Repeat this recursively for the requested child hash, N times, each being a syntactically valid two-item RLP list decodable by `TrieNode::decode` (`crates/proof/mpt/src/node.rs:567-604`).
3. When `OrderedListWalker::hydrate`/`fetch_leaves` (or `TrieNode::open`/`unblind`) walks this chain, each level triggers another recursive call and another oracle round-trip with no depth check, consuming stack frames unboundedly until the process stack-overflows or the walk becomes practically non-terminating within the proof program's time budget.

    /// Unblinds the [`TrieNode`] if it is a [`TrieNode::Blinded`] node.
    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.
                *self = Self::Empty;
            } else {
                *self = fetcher
                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }

    /// Walks down the trie to a leaf value with the given key, if it exists. Preimages for blinded
    /// nodes along the path are fetched using the `fetcher` function, and persisted in the inner
    /// [`TrieNode`] elements.
    ///
    /// ## Takes
    /// - `self` - The root trie node
    /// - `path` - The nibbles representation of the path to the leaf node
    /// - `fetcher` - The preimage fetcher for intermediate blinded nodes
    ///
    /// ## Returns
    /// - `Err(_)` - Could not retrieve the node with the given key from the trie.
    /// - `Ok(None)` - The node with the given key does not exist in the trie.
    /// - `Ok(Some(_))` - The value of the node
    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }
