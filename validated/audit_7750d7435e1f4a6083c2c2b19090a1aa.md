## Analysis: Recursive Function Bug Class Analog Found

The CVE-2019-9543 bug class — **unbounded recursive decoding of untrusted structured data causing stack-exhaustion DoS** — maps to the recursive `TrieNode` implementation in the Base fault-proof MPT crate, which decodes attacker-suppliable preimage data with no depth bound, directly analogous to `JBIG2Stream::readGenericBitmap()`'s unguarded recursion on crafted bitstream data.

### Title
Unbounded recursive `TrieNode` decode/traversal enables stack-overflow DoS of the fault-proof program via crafted dispute-game preimages - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode`'s `Decodable::decode`, `open`, `insert`, `unblind`, and `collapse_if_possible` are all self-recursive with no maximum-depth guard. These functions are the core trie-walking primitives used by the fault-proof program (`base-proof-mpt`, consumed by `base-proof` and `base-proof-client`) to resolve L1/L2 state during dispute-game execution. A dispute-game participant supplying preimage data through the preimage oracle can craft deeply nested RLP-encoded trie nodes that satisfy the oracle's only integrity check (`keccak256(value) == key`) while causing unbounded native-stack recursion when decoded/traversed, crashing the fault-proof program (Cannon/zkVM/TEE) before it can compute or validate an output root.

### Finding Description
`TrieNode::decode` recurses into itself for `Extension` nodes and into `Vec::<Self>::decode` for `Branch` nodes, with no recursion-depth tracking: [1](#0-0) 

The leaf/extension payload helper likewise recurses unconditionally: [2](#0-1) 

Runtime traversal functions `open`, `insert`, and `unblind` mirror this pattern, recursing through `Extension`/`Blinded` nodes indefinitely: [3](#0-2) [4](#0-3) 

Per Ethereum's RLP node-embedding rule (implemented here in `encode`/`payload_length`/`blinded_length`), any child node encoding to fewer than 32 bytes is embedded **inline** in its parent's RLP rather than referenced by a separate hash: [5](#0-4) 

This means recursion depth for a single `TrieNode::decode` call is bounded only by how much nesting fits in **one** preimage blob — not by the real Ethereum trie's fixed 64-nibble key length. The preimage oracle used by both L1 and L2 chain providers verifies only the hash of the blob, not its internal structure/depth: [6](#0-5) [7](#0-6) 

and the general preimage-acceptance check across the proof stack only validates `keccak256(value) == key` (or SHA-256 for blobs), with no structural/depth constraint: [8](#0-7) [9](#0-8) 

This is the fault-proof program's only supported target, per the README describing the recursive, in-memory MPT design intentionally used to support the `base-proof-executor` stateless execution path: [10](#0-9) 

The same crate's `OrderedListWalker`, used to derive attacker-influenced L1 lists (transactions/receipts) during derivation, is built atop the same recursive `TrieNode::open`/`decode` machinery: [11](#0-10) 

### Impact Explanation
A crash of the fault-proof program mid-execution during a dispute game prevents the program from computing/validating an output root for the claimed L2 block, per the epilogue's compare-and-halt logic: [12](#0-11) 

Because a segfault/stack overflow does not return a controlled error the caller can catch, it manifests as an unrecoverable process abort rather than the intended `InvalidClaim` error path, denying the honest party the ability to resolve the dispute-game move that depends on this trie traversal — a node-halt condition on a security-critical path (fault-proof resolution), matching the accepted "node halt" / "wrong provable output root" impact classes.

### Likelihood Explanation
The attacker role of "dispute-game participant" supplying preimage data is explicitly within the analog's threat model. Constructing a valid deeply-nested RLP blob whose keccak256 matches a required key is computationally trivial (the attacker picks the plaintext bytes themselves and computes the hash — no preimage search needed), so likelihood of triggering deep native recursion in `TrieNode::decode`/`open`/`insert`/`unblind` is high **once an injection point exists** where the fault-proof program is made to decode attacker-chosen bytes as a `TrieNode` rather than the cryptographically-committed real state content. The main open question — and the reason this should be treated as Medium rather than definitively High/Critical without further verification — is precisely bounding which preimage requests in the pipeline accept attacker-chosen bytes versus bytes cryptographically tied to a committed root/L1 block that the attacker cannot forge (state trie roots and storage keys are keccak256-derived and depth-bounded to 64 nibbles, limiting attacker control over shape for legitimate state paths).

### Recommendation
Add an explicit recursion-depth (or iterative-with-explicit-stack) bound to `TrieNode::decode`, `try_decode_leaf_or_extension_payload`, `open`, `insert`, `unblind`, and `collapse_if_possible` in `crates/proof/mpt/src/node.rs`, rejecting any structure exceeding the maximum theoretically valid Ethereum MPT depth (64 nibbles plus a small embedding-nesting allowance), and reject/error rather than recurse further when the bound is exceeded.

### Proof of Concept
1. Construct a chain of `TrieNode::Extension` values where each child is RLP-encoded to under 32 bytes (so it is embedded inline per `blinded_length`/`payload_length`, rather than referenced by hash), nested to a depth of tens of thousands of levels within a single preimage blob.
2. Compute `keccak256` of the resulting blob and submit it as the preimage for a key the fault-proof program will request during trie traversal (e.g., in the dispute-game's preimage-oracle submission flow).
3. When `OracleL1ChainProvider::trie_node_by_hash` / `OracleL2ChainProvider::trie_node_by_hash` calls `TrieNode::decode` on the blob, the recursive descent into `try_decode_leaf_or_extension_payload → Self::decode` exhausts the native stack, crashing the fault-proof program before it can validate the claimed output root.

    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })

                        .map_err(|_| alloy_rlp::Error::UnexpectedList)

    /// Verify that a preimage's content matches its key for hash-based key types.
    ///
    /// For [`PreimageKeyType::Keccak256`] keys the keccak256 digest of `value`
    /// must produce a key equal to `key`. For [`PreimageKeyType::Sha256`] keys
    /// the SHA-256 digest is checked instead. Local and `GlobalGeneric` keys are
    /// context-dependent and cannot be verified by hash, so they are accepted
    /// without validation.
    ///
    /// Blob and Precompile keys use composite hashing schemes that cannot be
    /// validated with the value alone, so they are also accepted as-is.
    fn check_preimage(key: &PreimageKey, value: &[u8]) -> crate::Result<()> {
        let expected_hash: Option<[u8; 32]> = match key.key_type() {
            PreimageKeyType::Keccak256 => Some(keccak256(value).0),
            PreimageKeyType::Sha256 => Some(sha2::Sha256::digest(value).into()),
            // Blob keys are `keccak256(commitment ++ z)` and precompile keys are
            // `keccak256(address ++ input)` — neither can be re-derived from the
            // stored value alone, so we skip verifying them here and instead verify them
            // during derivation.
            PreimageKeyType::Local
            | PreimageKeyType::GlobalGeneric
            | PreimageKeyType::Blob
            | PreimageKeyType::Precompile => None,
        };

        if let Some(hash) = expected_hash
            && key != &PreimageKey::new(hash, key.key_type())
        {
            return Err(NitroError::InvalidPreimage(*key));
        }
        Ok(())
    }

# `base-proof-mpt`

A recursive, in-memory implementation of Ethereum's hexary Merkle Patricia Trie (MPT).

## Overview

Implements Ethereum's Merkle Patricia Trie with support for retrieval, insertion, deletion, and
root computation via RLP-encoded trie node encoding. Starting from a trie root hash, `TrieNode`
lazily fetches and caches node preimages via `TrieProvider`, enabling stateless block execution
without storing the full state. Designed as the trie backend for [`base-proof-executor`](../executor).
