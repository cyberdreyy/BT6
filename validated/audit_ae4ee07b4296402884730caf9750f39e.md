### Title
Unauthenticated 401 response leaks raw backend/database error text via `AuthenticateExternalInitiator` → `jsonAPIError` - ([File: core/web/auth/auth.go])

### Summary
When `FindExternalInitiator` returns any error other than `sql.ErrNoRows` (e.g. a DB connection timeout, driver error, or query failure), `AuthenticateExternalInitiator` wraps it with `errors.Wrap(err, "finding external initiator")` and returns it as the middleware error. `Authenticate` then passes this wrapped error straight to `jsonAPIError`, which serializes `err.Error()` (including the original, unsanitized DB/driver error text) into the JSON body returned with HTTP 401 to the unauthenticated caller.

### Finding Description
The external-initiator auth path is: [1](#0-0) 

Any non-`sql.ErrNoRows` error from `FindExternalInitiator` is wrapped with a static prefix but otherwise preserved and returned unmodified up through `Authenticate`: [2](#0-1) 

`jsonAPIError` (duplicated in `core/web/auth/helpers.go` and `core/web/helpers.go`) has no special handling for generic errors — unless the error is a `*models.JSONAPIErrors`, it falls through to `c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))`, directly embedding `err.Error()` (i.e., the wrapped DB/driver error string) into the HTTP response body: [3](#0-2) 

An unauthenticated caller can trigger this by sending any request to an external-initiator-protected endpoint with `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers set to any value. As long as the lookup in `FindExternalInitiator` fails with something other than "row not found" (e.g., a transient DB timeout, connection pool exhaustion, or a query-level error), the raw driver/DB error text (which can include SQL fragments, driver identifiers such as `pq:`/`lib/pq`, or connection-level detail) is placed in the JSON error body sent back to the caller — no privileged access, session, or valid credential is required to reach this code path, since it executes during authentication itself, before any authorization check.

### Impact Explanation
This is an information-disclosure issue: an unauthenticated caller can, under DB-level failure conditions, receive backend implementation details (driver name, potentially partial query/schema fragments) in an HTTP 401 response. This matches Chainlink's "informational disclosure of non-sensitive backend implementation details" class — it does not by itself grant authentication bypass, key/secret disclosure, or fund movement, but it does leak internal error/schema information to an unauthenticated party, which is explicitly the condition the question asks about.

### Likelihood Explanation
Reachable by any unauthenticated network client with zero credentials — only requires hitting an endpoint that uses `AuthenticateExternalInitiator` middleware while the DB layer is in a degraded/erroring state (e.g., connection timeout, transient outage, or pool exhaustion). It is not exploitable at will under normal healthy-DB conditions (the common failure returns `sql.ErrNoRows`, which is already sanitized to `auth.ErrorAuthFailed`), so likelihood depends on transient DB failures or an attacker-induced DB slowdown, making it a real but conditionally-triggered disclosure.

### Recommendation
In `AuthenticateExternalInitiator`, do not propagate the wrapped underlying error to the HTTP layer. Log the detailed error server-side (e.g., via `logger`) and return a generic `auth.ErrorAuthFailed` (or a new sanitized sentinel error) to the caller for any `FindExternalInitiator` failure, mirroring the pattern already used for `sql.ErrNoRows`. More broadly, `jsonAPIError` should not serialize arbitrary `err.Error()` for internal errors reachable pre-authentication; only sanitized/typed errors should be exposed.

### Proof of Concept
Go handler-level integration test:
1. Implement a fake `Authenticator` whose `FindExternalInitiator` returns a non-`sql.ErrNoRows` error, e.g. `errors.New("pq: connection timeout to db-host:5432")`.
2. Wrap a test route with `auth.Authenticate(fakeAuthr, auth.AuthenticateExternalInitiator)`.
3. Send an HTTP request with `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers set to any value, no session/API token.
4. Assert response status is 401.
5. Assert response JSON body's `errors[].detail` field does NOT contain substrings from the raw injected error (e.g., `"pq:"`, `"connection timeout"`, `"db-host"`), and instead is a generic message.
6. Currently the test would fail because the body contains `"finding external initiator: pq: connection timeout to db-host:5432"`, proving the leak.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
