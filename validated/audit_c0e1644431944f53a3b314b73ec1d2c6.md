### Title
Mid-epoch depositors can dilute surprise `stopEpoch` yield - (File: `contracts/IdleCDOEpochVariant.sol`)

### Summary
`depositDuringEpoch` prices new tranche tokens using only `expectedEpochInterest`, while an honest manager can later settle a larger realized amount through the `_interest` override in `stopEpoch`. A KYC-passing attacker can deposit immediately before `epochEndDate`, receive shares priced without the unexpected profit, and then request withdrawal after `stopEpoch` distributes that profit across all tranche supply. [1](#0-0) [2](#0-1) 

### Finding Description
`depositDuringEpoch` is permitted while an epoch is running, before `epochEndDate`, when the feature is enabled, AYS is disabled, and the vault is not in programmable-borrower mode. [3](#0-2) 

The mint calculation protects existing holders only against the currently stored `expectedEpochInterest`: it computes existing holders’ expected final NAV, adds the depositor’s prorated interest, and mints shares from that estimate. [1](#0-0) 

`stopEpoch` accepts an explicit `_interest` value greater than `expectedEpochInterest`; the only constraints are that it covers pending withdrawal fees and that `_newApr == 0`. [4](#0-3) 

After pulling the realized interest, `stopEpoch` calls `_updateAccounting`, which distributes the entire NAV increase across the then-current tranche supply, including shares minted shortly before the epoch ended. [5](#0-4) [6](#0-5) 

A concrete sequence is:

1. The pool has 1,000 units in AA and 100 units of expected epoch interest.
2. One second before `epochEndDate`, the attacker deposits 1,000 units through `depositDuringEpoch`; the mint price is based on an expected final NAV of approximately 1,100 plus only the attacker’s one-second entitlement.
3. The attacker receives approximately 909.09 AA tranche tokens.
4. After `epochEndDate`, the manager calls `stopEpoch(0, 200)`, settling 100 units of additional realized yield.
5. `_updateAccounting` raises NAV to approximately 2,200 across approximately 1,909.09 shares.
6. The attacker’s shares are now worth approximately 1,045.45 units, capturing about 45.45 units of the 100-unit surprise yield despite supplying capital for only one second.
7. Once `stopEpoch` unpauses the vault and reopens withdrawal requests, the attacker calls `requestWithdraw` and fixes that inflated value into a withdrawal receipt. [7](#0-6) [8](#0-7) 

This breaks fair mint/burn accounting: the late depositor receives part of a gain that was economically attributable to capital supplied before the deposit.

### Impact Explanation
Existing tranche holders lose the fraction of unexpected realized yield captured by the late entrant. In the example above, approximately 45.45% of the 100-unit surprise yield is diverted to the attacker, subject to rounding and configured fees; larger attacker deposits increase the extracted share. [9](#0-8) 

The loss is direct NAV dilution rather than a temporary valuation issue because `stopEpoch` crystallizes the interest into tranche prices and `requestWithdraw` converts the inflated shares into a fixed strategy-token receipt. [10](#0-9) [11](#0-10) 

### Likelihood Explanation
The attack requires a supported non-programmable deployment with `isDepositDuringEpochDisabled == false`, `isAYSActive == false`, an initialized target tranche, and a KYC-allowed attacker. Programmable-borrower vaults reject this path, but the same restrictions explicitly identify the affected mode. [3](#0-2) 

The attacker must enter before `epochEndDate`, while the honest manager’s higher-than-expected settlement occurs after it. This is feasible whenever operational practice can settle realized borrower payments above `expectedEpochInterest`; the attacker does not need to control the manager or borrower and can size the deposit according to the anticipated override. [12](#0-11) 

### Recommendation
Prevent `depositDuringEpoch` during a cutoff window before `epochEndDate`, or defer such deposits for post-stop settlement at a price that excludes incremental realized interest above the deposit-time expectation. If deferral is used, mint shares from `(deposit amount + contractual prorated interest)` while reserving any `_interest - expectedEpochInterest` surplus for tranche holders whose capital was already recorded before the late deposit. [13](#0-12) [14](#0-13)

function testAudit_MidEpochDepositCapturesUnexpectedStopInterest() external {
    // Zero-fee, one-year, no-buffer configuration with 10% APR.
    vm.startPrank(manager);
    cdoEpoch.setEpochParams(365 days, 0);
    IdleCreditVault(address(strategy)).setAprs(10e18, 10e18);
    vm.stopPrank();

    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, 0);

    uint256 initialDeposit = 1_000 * ONE_SCALE;
    uint256 attackerDeposit = 1_000 * ONE_SCALE;
    uint256 surpriseInterest = 100 * ONE_SCALE;

    // Existing LP supplies 1,000; expected contractual interest is 100.
    idleCDO.depositAA(initialDeposit);

    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);

    _startEpochAndCheckPrices(0);

    vm.prank(owner);
    cdoEpoch.setIsDepositDuringEpochDisabled(false);

    // Attacker enters one second before the end. The mint is priced only against
    // expectedEpochInterest, not the later stopEpoch override.
    vm.warp(cdoEpoch.epochEndDate() - 1);

    address attacker = makeAddr("lateDepositor");
    deal(defaultUnderlying, attacker, attackerDeposit);

    vm.startPrank(attacker);
    IERC20Detailed(defaultUnderlying).approve(address(cdoEpoch), attackerDeposit);
    uint256 attackerShares = cdoEpoch.depositDuringEpoch(
        attackerDeposit,
        address(AAtranche)
    );
    vm.stopPrank();

    uint256 settledInterest =
        cdoEpoch.expectedEpochInterest() + surpriseInterest;

    // Honest borrower funds and approves the higher realized interest.
    deal(defaultUnderlying, borrower, settledInterest);
    vm.prank(borrower);
    IERC20Detailed(defaultUnderlying).approve(
        address(cdoEpoch),
        settledInterest
    );

    // The manager settles the realized 200-ish interest with a zero next APR.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, settledInterest);

    // Roughly: shares = 909.09e18 and final NAV/share = 2200 / 1909.09.
    uint256 attackerValue =
        attackerShares * cdoEpoch.virtualPrice(address(AAtranche)) /
        ONE_TRANCHE_TOKEN;

    // The attacker supplied 1,000 for one second but captures about 45.45 of
    // the 100-unit surprise yield.
    assertGt(attackerValue, attackerDeposit + 40 * ONE_SCALE);

    // Convert the diluted NAV into a fixed withdrawal receipt.
    vm.prank(attacker);
    uint256 receipt = cdoEpoch.requestWithdraw(
        attackerShares,
        address(AAtranche)
    );

    assertApproxEqAbs(receipt, attackerValue, 2);
    assertGt(receipt, attackerDeposit + 40 * ONE_SCALE);
}
