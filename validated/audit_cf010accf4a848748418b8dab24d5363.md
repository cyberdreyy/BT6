### Title
Stale cached role in `ldap_user_api_tokens` allows demoted admin/edit user to retain elevated API access until next LDAP sync - ([File: core/sessions/ldapauth/ldap.go])

### Summary
`ldapAuthenticator.FindUserByAPIToken` (core/sessions/ldapauth/ldap.go:205-236) returns the `user_role` cached in the `ldap_user_api_tokens` table at token-creation time, validating only the token's time-based expiry (`created_at + UserAPITokenDuration()`), not current LDAP group membership. Role downgrades are only propagated by `LDAPServerStateSyncer.Work()` (core/sessions/ldapauth/sync.go:93-284), which runs on a periodic timer/startup, not synchronously on each API-token-authenticated request, creating a window where a demoted user's token still authorizes admin/edit actions.

### Finding Description
When a user authenticates via `X-API-KEY`/`X-API-SECRET`, `AuthenticateByToken` (core/web/auth/auth.go:78-112) calls `authr.FindUserByAPIToken(ctx, token.AccessKey)` and trusts the returned `sessions.User.Role` directly, setting it into the gin context via `c.Set(SessionUserKey, &user)`. Downstream role guards `RequiresEditRole`/`RequiresAdminRole` (core/web/auth/auth.go:219-254) only check this `user.Role` value — they perform no independent upstream verification. `FindUserByAPIToken` itself only runs `SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1` [1](#0-0)  and returns the stored `user_role` verbatim if not expired [2](#0-1) . The only mechanism that updates `ldap_user_api_tokens.user_role` to reflect a role downgrade is `LDAPServerStateSyncer.Work()`'s `UPDATE ldap_user_api_tokens SET user_role = CASE ...` statement [3](#0-2) , gated by `UpstreamSyncInterval`/`UpstreamSyncRateLimit` timers [4](#0-3) , not invoked per API-token request. This contradicts the package's own doc comment claiming sync "happens for every auth endpoint hit" [5](#0-4)  — for API-token auth this is not actually true, since `AuthenticateByToken` never calls `Work()`.

### Impact Explanation
An admin/edit-role user whose LDAP group membership is revoked can continue to invoke privileged routes (e.g., admin-role-gated `PATCH /v2/config`, or edit-role job/bridge mutation endpoints) using their previously issued API token until the background `Work()` sync runs and updates or purges the token row. This matches the "authorization bypass / role escalation retained after privilege revocation" bounty class — a demoted user retains admin control over the node via a still-cached elevated role.

### Likelihood Explanation
Requires only a previously issued, unexpired LDAP-backed API token for a user who was admin/edit at token creation time via `CreateAndSetAuthToken`/`SetAuthToken` (core/sessions/ldapauth/ldap.go:532-592). No additional credentials, no operator/host access needed — the attacker simply keeps using an already-held token after being removed from the LDAP admin/edit group. The exposure window is bounded by `UpstreamSyncInterval` (operator-configured), which can be arbitrarily long, and is fully deterministic/repeatable.

### Recommendation
Either (a) have `AuthenticateByToken`/`FindUserByAPIToken` trigger or check against a freshly-synced state before granting elevated role, (b) reduce/bound `UpstreamSyncInterval` and additionally re-verify role against upstream LDAP (or at least trigger `Work()`) synchronously for privileged (edit/admin) role checks, or (c) have `RequiresEditRole`/`RequiresAdminRole` perform a lightweight freshness check (e.g., compare token's last-synced timestamp against a max staleness bound) before authorizing.

### Proof of Concept

func (l *LDAPServerStateSyncer) Work(ctx context.Context) {
	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}
