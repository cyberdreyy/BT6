### Title
Unbounded `replay_transactions` in a gossiped `StateMachineUpdate` causes O(n²) computation in `find_majority_prefix_replay_set`, threatening a liveness wedge - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::determine_global_state` is invoked by every signer on essentially every block-proposal evaluation path that uses global state (`check_block_against_global_state` in `stacks-signer/src/v0/signer.rs`). When no exact agreement exists on the transaction replay set, it falls back to `find_majority_prefix_replay_set`, which repeatedly scans the entire `tx_replay_sets` map while truncating a candidate prefix one element at a time until majority support is found [1](#0-0) . The size and content of the `replay_transactions` vector inside a `StateMachineUpdate` is controlled entirely by the broadcasting signer, with no bound enforced before `insert_update` accepts it and folds it into every other signer's global-state computation [2](#0-1)  and [3](#0-2) .

### Finding Description
This is analogous to the `lestrrat-go/jwx` issue: an attacker-controlled parameter (there, `p2c`; here, the length/content of `replay_transactions`) drives an algorithm whose cost scales with that attacker-chosen value, with no upper bound enforced at the point of acceptance.

`find_majority_prefix_replay_set` does the following on every call where no exact-agreement replay set exists:
1. Sorts all distinct replay sets seen across signers.
2. Computes `starts_with` over the full candidate prefix against every entry in `tx_replay_sets` — an O(m·k) operation, where `m` is the number of distinct replay sets observed and `k` is the candidate prefix length.
3. Then iteratively pops one transaction at a time off the candidate prefix and **re-scans all entries again** for each of the (up to) `k` truncation steps [4](#0-3) .

This gives roughly O(m·k²) comparisons, where each comparison is a `StacksTransaction` equality check (potentially expensive itself for large transactions, since `Vec<StacksTransaction>::starts_with` performs deep `PartialEq` on each element). One misbehaving signer, using nothing but their own signing key, can broadcast a `StateMachineUpdate` with a very large `replay_transactions` vector via StackerDB gossip. Every other signer's `insert_update` accepts it unconditionally (it only checks that the address is a known signer, not the payload size) [2](#0-1) , and this record persists in `address_updates` and is re-processed on every subsequent `determine_global_state` call — i.e., on every incoming block proposal evaluated via `check_block_against_global_state` [5](#0-4) .

### Impact Explanation
If the per-call cost of `find_majority_prefix_replay_set` becomes large enough, a signer's single-threaded event loop can be monopolized on the CPU-bound recomputation triggered by every incoming block proposal or gossip update, delaying `handle_block_proposal` → `submit_block_for_validation` → pre-commit → signature flow. Because the signer network operates on tight timing (block_proposal_max_age_secs, pre-commit thresholds, miner timeouts), a sustained CPU stall risks the signer missing timing windows and never delivering its signature in time for legitimate blocks — matching the "High: signer wedged into never signing valid blocks" impact category. It does not itself allow a signer to sign an invalid block or fake a threshold; it is a resource-exhaustion/liveness risk analogous to the JWE report's CWE-400 classification.

### Likelihood Explanation
Triggering the expensive path only requires one non-cooperating signer sending a crafted `StateMachineUpdate` over the existing gossip channel with their own valid signing key — no majority collusion, no other signer's key, and no auth token are required, satisfying the in-scope "one-slot miner (plus gossip)" threat model. However, this is fundamentally a payload-size/computational-cost issue rather than a pure protocol-logic equality break, and I was not able to fully confirm (within the available index) whether `StateMachineUpdateContent`/`StateMachineUpdateMessage` deserialization in `libsigner/src/v0/messages.rs` already enforces a hard cap on `replay_transactions` length or overall message size before `insert_update` is reached — the file exists and defines these types, but I could not read its bounds-checking logic directly in this session. If such a bound already exists (e.g., a small max transaction count per state machine update, consistent with the "failsafe" auto-clear behavior noted in the changelog), the practical severity is much lower and may not constitute a meaningful DoS at all.

### Recommendation
- Enforce an explicit maximum length (and per-transaction size ceiling) on `replay_transactions` at message deserialization/`insert_update` time, rejecting or truncating oversized payloads before they enter `address_updates`.
- Cache/short-circuit `find_majority_prefix_replay_set` results per `(burn_block, address_updates snapshot)` so it is not recomputed from scratch on every block-proposal evaluation when inputs haven't changed.
- Consider bounding the truncation loop's worst-case work (e.g., cap `k` independent of attacker input, or compare by transaction id/hash rather than full transaction equality) to keep the routine's cost sub-quadratic regardless of adversarial input.

### Proof of Concept
Conceptual (cannot be fully validated without confirming message-size bounds in `libsigner/src/v0/messages.rs`):
1. Malicious signer `S` (a normal reward-cycle participant, using only their own key) constructs a `StateMachineUpdateMessage` with `StateMachineUpdateContent::V1.replay_transactions` populated with a very large number of distinct, well-formed `StacksTransaction`s that share no common prefix with what other signers are proposing.
2. `S` broadcasts this update over StackerDB as part of normal gossip.
3. Every other signer's `GlobalStateEvaluator::insert_update` accepts it (only known-address check) [2](#0-1) .
4. On the next block proposal, each signer calls `check_block_against_global_state` → `determine_global_state` → `find_majority_prefix_replay_set`, which must scan and repeatedly truncate/re-scan the oversized replay set [3](#0-2) , [1](#0-0) , consuming disproportionate CPU relative to the small gossip payload cost paid by the attacker, potentially delaying that signer's participation in the current block round.

                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };

            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

    /// Find the longest common prefix of replay sets that has majority support.
    /// This implements the longest common prefix (LCP) strategy where if one signer's replay set
    /// is [A,B,C] and another is [A,B], we should use [A,B] as the replay set.
    /// Order matters for transaction replay - [A,B] and [B,A] have no common prefix.
    fn find_majority_prefix_replay_set(
        &self,
        tx_replay_sets: &HashMap<ReplayTransactionSet, u32>,
    ) -> Option<ReplayTransactionSet> {
        if tx_replay_sets.is_empty() {
            return None;
        }

        // First, try to find an exact match that reaches agreement
        for (replay_set, weight) in tx_replay_sets {
            if self.reached_agreement(*weight) {
                return Some(replay_set.clone());
            }
        }

        // No exact agreement found, find longest common prefix with majority support

        // Sort replay sets by weight (descending), then deterministically by length and content
        let mut sorted_sets: Vec<_> = tx_replay_sets.iter().collect();
        sorted_sets.sort_by(|(set_a, weight_a), (set_b, weight_b)| {
            // Primary: weight descending
            let weight_cmp = weight_b.cmp(weight_a);
            if weight_cmp != Ordering::Equal {
                return weight_cmp;
            }
            // Secondary: length descending (longer sequences first)
            let len_cmp = set_b.0.len().cmp(&set_a.0.len());
            if len_cmp != Ordering::Equal {
                return len_cmp;
            }
            // Tertiary: compare transaction IDs for determinism
            for (lhs, rhs) in set_a.0.iter().zip(&set_b.0) {
                let ord = lhs.txid().cmp(&rhs.txid());
                if ord != Ordering::Equal {
                    return ord;
                }
            }
            Ordering::Equal
        });

        // Start with the most supported replay set as initial candidate
        if let Some((initial_set, _)) = sorted_sets.first() {
            let mut candidate_prefix = initial_set.0.clone();
            let mut total_supporting_weight = 0u32;

            // Find all sets that support the current candidate prefix
            for (replay_set, weight) in tx_replay_sets {
                if replay_set.0.starts_with(&candidate_prefix) {
                    total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                }
            }

            // If the initial candidate already has majority support, return it
            if self.reached_agreement(total_supporting_weight) {
                return Some(ReplayTransactionSet::new(candidate_prefix));
            }

            // Otherwise, iteratively truncate the prefix until we find majority support
            while !candidate_prefix.is_empty() {
                // Remove the last transaction from the prefix
                candidate_prefix.pop();

                // Recalculate supporting weight for the shorter prefix
                total_supporting_weight = 0u32;
                for (replay_set, weight) in tx_replay_sets {
                    if replay_set.0.starts_with(&candidate_prefix) {
                        total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                    }
                }

                // If this prefix has majority support, return it
                if self.reached_agreement(total_supporting_weight) {
                    return Some(ReplayTransactionSet::new(candidate_prefix));
                }
            }
        }

        // If no common prefix with majority support is found, return None
        None
    }

    /// Check if block should be rejected based on global signer state
    /// Will return a BlockRejection if the block is invalid, none otherwise.
    /// This is the Post-global signer state activation path
    fn check_block_against_global_state(
        &mut self,
        stacks_client: &StacksClient,
        block: &NakamotoBlock,
    ) -> Option<BlockRejection> {
        let signer_signature_hash = block.header.signer_signature_hash();
        let block_id = block.block_id();
        let Some(global_state) = self.global_state_evaluator.determine_global_state() else {
            warn!(
                "{self}: Cannot validate block, no global signer state";
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_id,
                "local_signer_state" => ?self.local_state_machine
            );
            return Some(self.create_block_rejection(RejectReason::NoSignerConsensus, block));
        };

        let global_state_view = GlobalStateView {
            signer_state: global_state,
            config: self.proposal_config.clone(),
        };

        info!(
            "{self}: Evaluating proposal against global state";
            "signer_state" => ?global_state_view.signer_state,
            "signer_signature_hash" => %signer_signature_hash,
            "block_id" => %block_id,
            "local_signer_state" => ?self.local_state_machine,
        );

        // Check if proposal can be rejected now if not valid against the global state
        match global_state_view.check_proposal(stacks_client, &mut self.signer_db, block) {
            // Error validating block
            Err(RejectReason::ConnectivityIssues(e)) => {
                warn!(
                    "{self}: Error checking block proposal: {e}";
                    "signer_signature_hash" => %signer_signature_hash,
                    "block_id" => %block_id,
                );
                Some(self.create_block_rejection(RejectReason::ConnectivityIssues(e), block))
            }
            // Block proposal is bad
            Err(reject_code) => {
                warn!(
                    "{self}: Block proposal invalid";
                    "signer_signature_hash" => %signer_signature_hash,
                    "block_id" => %block_id,
                    "reject_reason" => %reject_code,
                    "reject_code" => ?reject_code,
                );
                Some(self.create_block_rejection(reject_code, block))
            }
            // Block proposal passed check, still don't know if valid
            Ok(_) => None,
        }
