### Title
Staker can indefinitely block operator commission withdrawal via unbounded lockup extension - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::reset_lockup` lets the *staker* alone call `stake::increase_lockup_with_cap` to push the underlying stake pool's `locked_until_secs` further into the future, with no upper bound and no operator consent. This is the exact analog of the `DaosLive.extendTime()` bug: a single privileged-but-unprivileged-relative-to-the-victim party (the staker, who is not the harmed operator) can repeatedly renew a lockup right before it would expire, permanently denying a different, uninvolved party (the operator) access to funds it is already entitled to (its already-requested commission sitting in `pending_inactive`).

### Finding Description
`staking_contract::reset_lockup` is callable only by the staker: [1](#0-0) 

It forwards to `stake::increase_lockup_with_cap`, which enforces only that the new lock time strictly exceeds the old one — there is no cap on how many times or how far this can be pushed: [2](#0-1) 

Meanwhile, the operator's commission flow works as follows: `request_commission`/`request_commission_internal` moves the operator's earned commission from `active` to `pending_inactive` via `stake::unlock_with_cap`, but this amount only becomes actually withdrawable once the pool's lockup naturally expires (converted from `pending_inactive` to `inactive` at epoch boundary): [3](#0-2) 

Because the staker holds sole authority over `reset_lockup`, and this call is independent of and can be issued after the operator's commission has already been unlocked into `pending_inactive`, a malicious or grieving staker can call `reset_lockup` once per lockup cycle (each time strictly before the current `locked_until_secs` is reached) to keep resetting `locked_until_secs` forward forever. This mirrors the report's `extendTime()` pattern exactly: `old_locked_until_secs < new_locked_until_secs` is the only guard, just as `DaosLive` only checked `_endTime < block.timestamp`.

### Impact Explanation
This traps the operator's already-earned and already-unlocked commission (`pending_inactive`) indefinitely, since it can never convert to `inactive`/withdrawable coin as long as the staker keeps renewing the lockup. This falls squarely under the required impact category "Operator commission ... payout ... corruption that credits the wrong account or traps value" and "Permanent lock or non-recoverable loss of claim rights in stake ... commission ... flows." The staker does not need any elevated/governance role beyond the ordinary staker role it already legitimately holds over its *own* stake pool — the victim (operator) holds none of the roles being abused, satisfying the "wrong-role control ... without already holding that role" pivot from the operator's perspective (its commission claim is effectively nullified by another party's unilateral action).

### Likelihood Explanation
The `reset_lockup` entry function is completely permissionless for any staker who created a `staking_contract` (a normal, common, non-privileged, mainnet-reachable flow — not governance, not admin-only). No collusion, special timing precision, or race condition beyond "call once per lockup cycle" is required, making this trivially and repeatedly executable by any staker who wants to grief an operator (e.g., after a dispute over commission percentage or after firing an operator).

### Recommendation
Add a cap on lockup extension analogous to fixing the `DaosLive` bug: require operator consent (or a governance/admin override) before allowing further lockup extension once the operator has outstanding unlocked commission awaiting withdrawal, or bound the total time a staker may extend `locked_until_secs` past the point where operator commission was requested. Alternatively, decouple operator commission withdrawal from the staker-controlled pool lockup entirely so it cannot be re-locked once already unlocked.

### Proof of Concept
1. Staker creates a `staking_contract` with operator O and commission_percentage > 0 via `staking_contract::create_staking_contract`.
2. Stake pool earns rewards; operator or staker calls `request_commission`, which unlocks O's commission into `pending_inactive` via `request_commission_internal` (`staking_contract.move:637-674`).
3. Before the pool's `locked_until_secs` is reached, staker calls `staking_contract::reset_lockup(staker, operator)` (`staking_contract.move:552-562`), which calls `stake::increase_lockup_with_cap` (`stake.move:1042-1061`), pushing `locked_until_secs` forward by another full `recurring_lockup_duration_secs`.
4. Repeat step 3 every cycle, indefinitely, before each expiry.
5. O's `pending_inactive` commission never converts to `inactive`, and `withdraw`/`distribute_internal` never has anything withdrawable for O — the commission is permanently trapped as long as staker keeps calling `reset_lockup`.

Note: I was unable to locate/verify the exact `distribute_internal`/`withdraw_commission` function bodies in this pass (grep for those exact names returned no match within the tool budget available), so the final conversion-to-withdrawal step is inferred from the documented `pending_inactive`→`inactive` lockup-expiry mechanism in `stake.move` rather than directly re-confirmed line-by-line in `staking_contract.move`. I recommend verifying `distribute_internal` and the operator's withdrawal entrypoint directly in the repo to confirm there is no independent bypass (e.g., an operator-only emergency withdrawal) before treating this as fully conclusive.

    /// Convenient function to allow the staker to reset their stake pool's lockup period to start now.
    public entry fun reset_lockup(staker: &signer, operator: address) acquires Store {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);
        let pool_address = staking_contract.pool_address;
        stake::increase_lockup_with_cap(&staking_contract.owner_cap);

        emit(ResetLockup { operator, pool_address });
    }

    /// Unlock commission amount from the stake pool. Operator needs to wait for the amount to become withdrawable
    /// at the end of the stake pool's lockup period before they can actually can withdraw_commission.
    ///
    /// Only staker, operator or beneficiary can call this.
    public entry fun request_commission(
        account: &signer, staker: address, operator: address
    ) acquires Store, BeneficiaryForOperator {
        let account_addr = signer::address_of(account);
        assert!(
            account_addr == staker
                || account_addr == operator
                || account_addr == beneficiary_for_operator(operator),
            error::unauthenticated(ENOT_STAKER_OR_OPERATOR_OR_BENEFICIARY)
        );
        assert_staking_contract_exists(staker, operator);

        let store = borrow_global_mut<Store>(staker);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);
        // Short-circuit if zero commission.
        if (staking_contract.commission_percentage == 0) { return };

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker,
            operator,
            staking_contract,
        );

        request_commission_internal(
            operator,
            staking_contract,
        );
    }

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    public fun increase_lockup_with_cap(owner_cap: &OwnerCapability) acquires StakePool {
        let pool_address = owner_cap.pool_address;
        assert_stake_pool_exists(pool_address);
        let config = staking_config::get();

        let stake_pool = borrow_global_mut<StakePool>(pool_address);
        let old_locked_until_secs = stake_pool.locked_until_secs;
        let new_locked_until_secs =
            timestamp::now_seconds()
                + staking_config::get_recurring_lockup_duration(&config);
        assert!(
            old_locked_until_secs < new_locked_until_secs,
            error::invalid_argument(EINVALID_LOCKUP)
        );
        stake_pool.locked_until_secs = new_locked_until_secs;

        event::emit(
            IncreaseLockup { pool_address, old_locked_until_secs, new_locked_until_secs }
        );
    }
