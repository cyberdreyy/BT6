### Title
Unauthenticated access to internal LOOP plugin Prometheus metrics via GET /plugins/:name/metrics - ([File: core/web/loop_registry.go])

### Summary
The `/plugins/:name/metrics` route registered by `loopRoutes` proxies to a LOOP plugin's internal Prometheus endpoint and is mounted on the main API group without any authentication middleware, unlike other debug endpoints such as `/debug/vars`. This allows any unauthenticated network client to retrieve internal plugin metrics data.

### Finding Description
`loopRoutes` is invoked directly on the `api` group in `NewRouter` with no auth wrapper: `debugRoutes(app, api); healthRoutes(app, api); sessionRoutes(app, api); v2Routes(app, api); loopRoutes(app, api)` [1](#0-0) . Inside `loopRoutes`, the metrics, discovery, and pprof endpoints are registered as plain `r.GET`/`r.POST` calls with no auth middleware applied: [2](#0-1) .

This is in stark contrast to `debugRoutes`, which explicitly wraps its group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` before exposing `/debug/vars` [3](#0-2) .

`pluginMetricHandler` looks up the plugin by the `:name` path param, builds an internal URL `http://%s:%d/metrics` using `l.loopHostName` and the plugin's registered `PrometheusPort`, fetches it, and writes the raw response body back to the caller with `StatusOK` — with no session/token/role check anywhere in the handler: [4](#0-3) . The sibling pprof proxy handlers (`pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) have the identical problem, forwarding to the plugin's `/debug/pprof/*` endpoints without auth [5](#0-4) .

The discovery endpoint itself also leaks target hostnames/ports and plugin names to any unauthenticated caller, further aiding reconnaissance for this issue [6](#0-5) .

No auth middleware, session check, or role check intercepts this request path; the existing unit tests for `LoopRegistryServer` only cover marshal/write error paths and do not exercise the router or auth gate [7](#0-6) .

### Impact Explanation
An unauthenticated attacker who can reach the node's HTTP API can retrieve internal Prometheus metrics for any registered LOOP plugin (and, via the sibling handlers, pprof profiling/heap/goroutine dumps and symbol data). This is an information-disclosure vulnerability: internal operational metrics, timing data, counts of requests/errors, and potentially plugin-specific labels/internal identifiers are exposed to any anonymous network client. Depending on plugin instrumentation, this could reveal information useful for further reconnaissance or fingerprinting of the node's internal architecture, chain/OCR job activity patterns, and version/config info — matching a "sensitive data exposure via authentication bypass on an internal debug/admin endpoint" bounty class. It does not directly enable fund movement, but it removes the intended "internal-only" trust boundary between node and plugin metrics/pprof and hands it to any network-reachable client.

### Likelihood Explanation
Fully unauthenticated and trivially reachable: the route is registered on the main API router group with zero auth middleware, so any client capable of sending an HTTP GET to the node's web server port can exploit it once a plugin name is known (which can itself be discovered via the equally unauthenticated `/discovery` endpoint). No credentials, session cookie, or API token are required. This is repeatable and deterministic.

### Recommendation
Wrap `loopRoutes` (and its sibling `metricRoutes`) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or an appropriate admin-role-gated) middleware used for `debugRoutes`, or move these endpoints to a separate internal-only listener/port that is not exposed on the public API surface. At minimum, require session/token auth plus `auth.RequiresAdminRole` for `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*`, and `/discovery`.

### Proof of Concept
Go handler-level integration test plan:
1. Build a test `chainlink.Application` (or reuse existing test app helpers) with a `plugins.LoopRegistry` that has one plugin registered via `NewTestLoopRegistry`/`Register`, with `EnvCfg.PrometheusPort` pointed at a `httptest.NewServer` that serves a known Prometheus metric line, e.g. `test_plugin_metric_total 42`.
2. Call `web.NewRouter(app, nil)` to build the real gin engine (as production code does), then wrap it with `httptest.NewServer(router)`.
3. Issue `http.Get(server.URL + "/plugins/<registered-name>/metrics")` **without** setting any `Cookie` or `Authorization`/API-token header.
4. Assert `resp.StatusCode == http.StatusOK` and that the response body contains `test_plugin_metric_total`.
5. As a control, issue the same unauthenticated request to `/debug/vars` and assert it is rejected (e.g., redirected/401/403), demonstrating the inconsistency between `debugRoutes` (protected) and `loopRoutes` (unprotected).

func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
