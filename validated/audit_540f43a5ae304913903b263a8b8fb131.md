### Title
Client-controlled `requestID` is used as a global, unpartitioned map key for HTTP trigger callbacks, allowing an unprivileged client to block or hijack another workflow's in-flight request - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
The `httpTriggerHandler` uses the caller-supplied JSON-RPC `req.ID` as the sole key into a single, gateway-wide `callbacks` map shared across all workflows and workflow owners. There is no per-owner/per-workflow namespacing of this key, unlike the analogous report where a coarse, attacker-influenceable/predictable value (`block.number`) was used as a uniqueness key (nonce) for concurrent orders, causing legitimate operations to collide and get rejected, and allowing an attacker to pre-empt the slot to block others.

### Finding Description
`HandleUserTriggerRequest` validates the request ID only for non-emptiness and absence of `/` [1](#0-0) , then calls `setupCallback`, which stores the callback keyed purely by `requestID` in the handler-wide map `h.callbacks map[string]savedCallback`, with no owner/workflow component in the key: [2](#0-1) . If any other in-flight request (from any workflow, any owner) already holds that same `requestID`, the new request is rejected with a conflict error before it is dispatched to nodes: [3](#0-2) .

Because `req.ID` is entirely client-controlled and the map is global (not partitioned by `workflowOwner`/`workflowID`), an unprivileged attacker who submits HTTP trigger requests with a chosen or guessed `requestID` can pre-empt that ID slot before a legitimate caller uses it — analogous to the reported bug where `block.number` (a coarse, non-unique-per-actor value) was used as a permit2 nonce, letting one party's use of the value block another's concurrent, unrelated operation. Node responses are also routed back purely by `resp.ID` via `HandleNodeTriggerResponse` (`saved, exists := h.callbacks[resp.ID]`) [4](#0-3) , so an ID collision could route/deliver a response for one workflow into the callback of a different, unrelated request if IDs collide in time.

### Impact Explanation
This is a request-availability/integrity issue reachable directly by an unprivileged client: normal, legitimate HTTP trigger executions for one workflow owner can be denied service ("requestID has already been used") by another unrelated party's concurrent request using the same ID, and in the worst case a response could be delivered to the wrong caller's aggregator if collisions coincide with node responses. This mirrors the "Medium" impact/"High" likelihood characterization in the source report: no fund loss, but a concrete denial of legitimate operation and potential cross-request confusion caused entirely by an under-scoped uniqueness key.

### Likelihood Explanation
Likelihood is high for the DoS variant because `requestID` is fully attacker-supplied and only lightly validated (non-empty, no `/`); an attacker with any gateway access can flood the endpoint with many requestIDs (including predictable/sequential ones a legitimate client might use, e.g., UUIDs generated with weak randomness, or brute-forced short IDs) to occupy slots ahead of legitimate users. The cross-user response-confusion variant requires the response window (`h.callbacks` lifetime, bounded by `requestTimeout`) to overlap for two distinct requests sharing an ID, which is plausible in a busy gateway.

### Recommendation
Scope the `callbacks` map key by both `workflowOwner`/`workflowID` and `requestID` (e.g., a composite key struct as already done elsewhere in the codebase, such as `globalId{sender, id}` in `core/services/gateway/handlers/common/requestcache.go`) so that request IDs are only required to be unique per caller/workflow rather than globally across the entire gateway.

### Proof of Concept
1. Attacker sends `workflows.execute` HTTP trigger request A with `id = "X"` for workflow W1 (owned by attacker) — this reserves `h.callbacks["X"]` immediately.
2. Before A's request completes/times out, a legitimate user sends `workflows.execute` for workflow W2 with the same `id = "X"` (e.g., a client that constructs deterministic or short request IDs).
3. `setupCallback` sees `h.callbacks["X"]` already exists and returns `jsonrpc.ErrConflict`, denying the legitimate user's request even though it targets a completely different, unrelated workflow: [3](#0-2) .

```go
func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}
```

```go
func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// Build one response aggregator per shard the workflow is assigned to.
	assigned := h.workflowMetadataHandler.WorkflowShards(workflowID)
	if len(assigned) == 0 {
		// this shouldn't happen because we checked it in authorizeRequest()
		h.handleUserError(ctx, requestID, jsonrpc.ErrInternal, fmt.Sprintf("Workflow %s is not assigned to any DONs", workflowID), callback)
		return nil, errors.New("workflow is not assigned to any shards")
	}

	aggregators := make(map[string]*aggregation.IdenticalNodeResponseAggregator, len(assigned))
	for _, shard := range assigned {
		// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
		threshold := (len(shard.members)+shard.f)/2 + 1
		agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
		if err != nil {
			return nil, errors.New("failed to create response aggregator: " + err.Error())
		}
		aggregators[shard.donID] = agg
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:            callback,
		requestStartTime:    requestStartTime,
		createdAt:           time.Now(),
		responseAggregators: aggregators,
		doneCh:              doneCh,
	}
	return doneCh, nil
```

```go
func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
```
