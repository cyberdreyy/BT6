### Title
Zip cache extractor lacks path/symlink traversal checks, allowing archive entries to write files outside the job's build directory - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` (and its helpers `extractZipFile`, `extractZipSymlinkEntry`, `extractZipDirectoryEntry`) create directories, files, and symlinks using the raw `file.Name`/`file.Linkname` (symlink target data) from the zip archive, with no `filepath.Clean`/`HasPrefix`/chroot-style validation, unlike the tar+zstd extractor (`commands/helpers/archive/tarzstd/tarzstd_extractor.go:58-64`) which explicitly checks `strings.HasPrefix(path, e.dir+separator)`. A job that controls the pushed cache archive content can supply a `.zip` cache with `../`-prefixed entry names or a symlink entry pointing outside the extraction root, allowing writes outside the intended cache directory when the archive is later extracted.

### Finding Description
`extractZipFile` (`helpers/archives/zip_extract.go:61-83`) does `os.MkdirAll(filepath.Dir(file.Name), ...)` and then, depending on entry type, calls `os.Mkdir(file.Name, ...)`, `os.OpenFile(file.Name, ...)`, or `os.Symlink(string(data), file.Name)` directly on the attacker-controlled `file.Name` string from the zip header [1](#0-0) . There is no normalization/containment check against an extraction root anywhere in this file — the only path validation present is `errorIfGitDirectory`, which merely warns about `.git` paths and does nothing to prevent traversal [2](#0-1) . Contrast this with the tar+zstd extractor, which computes `path := filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path failing `strings.HasPrefix(path, e.dir+separator)` [3](#0-2) .

However, tracing the actual invocation path shows the zip legacy extractor's `Extract` method receives a `dir` field (the intended extraction root, passed from `cache_extractor.go`'s `os.Getwd()`) but never uses it at all — it just calls `archives.ExtractZipArchive(zr)` with no relation to `e.dir` [4](#0-3) . Extraction therefore always occurs relative to the process's actual current working directory, which `CacheExtractorCommand.Execute` sets via `wd, err := os.Getwd()` (i.e., whatever directory the cache-extractor sub-process/helper binary was launched in — the job's build/cache directory) before invoking the extractor [5](#0-4) .

Exploit flow: an attacker-controlled job creates and pushes a cache using the `cache-archiver` (invoked from `functions/concrete/run/stages/cache_archive.go`), but critically the archiver only zips files that already exist under the job's own working tree — so injecting traversal entries via the legitimate cache-archiver path is constrained by what files exist locally at archive time. The more direct exploitation is that GitLab cache keys/paths are attacker-controlled (job author picks the `key:` and can reference arbitrary sibling cache slots), and if two jobs share the same runner host/`CacheDir` (e.g., self-hosted shared runners with the shell or non-isolated executors, or a job with a crafted cache archive uploaded to shared cache storage under a guessed/predictable key), a subsequent `cache-extractor` invocation of a poisoned zip will run `os.Mkdir`/`os.OpenFile`/`os.Symlink` on `../../victim/payload`-style names or on a symlink whose target is `/` or another absolute path, writing/overwriting files outside the current `wd`.

### Impact Explanation
If reached, this allows a cache archive to place or overwrite files outside the intended extraction directory (e.g., another job's workspace, or arbitrary paths writable by the runner process' user) purely by controlling zip entry names/symlink targets — a classic Zip Slip. This violates the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
The `dir` parameter is present in the extractor struct precisely to serve as a containment boundary (as done correctly for tar+zstd), but it's unused for zip, so this is a genuine code-level defect. **Uncertain/unverified**: I could not confirm within this session whether (a) the standard `cache-archiver` path itself permits crafting archive entries with `../` names or symlink entries pointing outside the workspace (this would require inspecting `commands/helpers/cache_archiver.go`/`archives/zip_create.go`, which weren't fully reviewed here), and (b) whether cross-job impact is actually reachable given how `CacheDir`/`BuildDir` isolation and `wd` are set per job in the runner's process/executor model (e.g., custom/shell executors share a host filesystem across jobs, but each job typically gets a distinct `CacheDir`/`BuildDir` subpath, and the extractor's `wd` would be that job's own directory, not another job's — meaning traversal `../` entries would need to escape the job's own directory tree to actually reach another job's files, which is plausible but not proven with a concrete PoC in this session). The vulnerability (missing check) is real and reachable via any actor able to supply a raw zip byte stream to `cache-extractor`/`ExtractZipArchive` (this also includes cross-project cache sharing if cache buckets/keys are shared or guessable), but the "which victim workspace" scoped impact needs runtime verification of directory isolation to fully confirm severity.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to the zip extraction path: resolve each `file.Name` against `filepath.Abs(filepath.Join(dir, file.Name))`, reject entries where the resolved path is not equal to or does not have `dir+separator` as prefix, and apply the same check to symlink targets (`extractZipSymlinkEntry`) before calling `os.Symlink`. Additionally, wire the previously-unused `dir` field in `ziplegacy/zip_legacy_extractor.go` through to `ExtractZipArchive` (changing its signature to accept the extraction root) instead of relying implicitly on `os.Getwd()`.

### Proof of Concept
```go
// helpers/archives/zip_extract_traversal_test.go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    dir := t.TempDir()
    extractDir := filepath.Join(dir, "extract")
    require.NoError(t, os.MkdirAll(extractDir, 0777))
    victim := filepath.Join(dir, "victim")
    require.NoError(t, os.MkdirAll(victim, 0777))

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    w, _ := zw.Create("../victim/payload.txt")
    _, _ = w.Write([]byte("pwned"))
    // symlink entry pointing outside
    hdr := &zip.FileHeader{Name: "evil-link", Method: zip.Store}
    hdr.SetMode(os.ModeSymlink | 0777)
    sw, _ := zw.CreateHeader(hdr)
    _, _ = sw.Write([]byte("/"))
    require.NoError(t, zw.Close())

    require.NoError(t, os.Chdir(extractDir))
    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the traversal entry landed OUTSIDE extractDir (proves the bug)
    _, statErr := os.Stat(filepath.Join(dir, "victim", "payload.txt"))
    assert.NoError(t, statErr, "file escaped extraction directory - Zip Slip confirmed")

    // Assert symlink points outside extractDir
    target, _ := os.Readlink(filepath.Join(extractDir, "evil-link"))
    assert.Equal(t, "/", target)
}
```
Expected result on the current code: both assertions pass, confirming files/symlinks escape the intended extraction root. After applying the recommended `HasPrefix`-style containment check (mirroring `tarzstd_extractor.go`), `ExtractZipArchive` should instead return an error and the file should never be created outside `extractDir`.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func (c *CacheExtractorCommand) Execute(cliContext *cli.Context) {
	log.SetRunnerFormatter()

	c.normalizeExtractorArgs()
	if err := validateCacheTransferTuning(c.TransferBufferSize, c.ChunkSize, c.Concurrency); err != nil {
		logrus.Fatalln(err)
	}

	wd, err := os.Getwd()
	if err != nil {

	if c.File == "" {
		warningln("Missing cache file")
	}

		if err != nil {

		}

		warningln("Cache file does not exist")
	}

		logrus.Fatalln(err)

		logrus.Fatalln(err)
