### Title
Revoked/rotated workflow signer keys remain valid in the HTTP-Trigger gateway due to stale first-shard-wins caching of `authorizedKeys` and delayed observation reaping - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The `WorkflowMetadataHandler` in the Chainlink Gateway's HTTP Trigger handler authorizes inbound, unprivileged HTTP-trigger requests by checking a signer's public key against a cached `authorizedKeys` map that is rebuilt periodically from per-shard aggregated node observations. Similar to the Visor `approveTransferERC721()` bug where a granted approval is never actually cleared/revoked and continues to authorize a transfer after the owner intends to revoke it, this cache can continue to authorize a previously valid (now-rotated/removed) signer key because (1) the merge logic in `syncMetadata` is "first-shard-wins" rather than latest-wins, and (2) stale observations for the old key set are only purged after a configurable `cleanupInterval`, not immediately upon key rotation.

### Finding Description
`WorkflowMetadataHandler.Authorize` grants access to any signer whose ECDSA public key is present in `h.authorizedKeys[workflowID]`: [1](#0-0) 

That map is entirely rebuilt on every call to `syncMetadata`, by iterating `h.shards` and, for each shard, taking that shard's `WorkflowMetadataAggregator.Aggregate()` result: [2](#0-1) 

Crucially, when two shards report metadata for the *same* `workflowID` and the same `workflowReference` (owner/name/tag — which does **not** change when a signer key is rotated or revoked), the code only appends the shard to `workflowShards` and explicitly skips re-assigning `authorizedKeys` for that workflow ID:
```
if existingRef, idExists := workflowIDToRef[workflowID]; idExists {
    if existingRef == workflowRef {
        workflowShards[workflowID] = append(workflowShards[workflowID], shard)
    } else { ... }
    continue
}
``` [3](#0-2) 

This means whichever shard's data is processed *first* in the `for _, shard := range h.shards` loop "wins" for the entire authorization set of that workflow, regardless of which observation is more recent (there is no comparison against `sequence`/recency across shards, only within a single shard's `Aggregate()` sort).

Compounding this, revoked/removed keys are not immediately purged. A workflow's authorization digest (which includes the `AuthorizedKeys` set) is only dropped from an aggregator once none of the DON's nodes have re-reported it for `cleanupInterval`: [4](#0-3) 
and new observations are only added, never explicitly invalidated when a workflow owner updates the on-chain authorized-key list — the old digest simply ages out passively: [5](#0-4) 

As in the reported Visor bug, there is no explicit "revoke" code path invoked at rotation time — authorization removal depends entirely on time-based reaping and, in the multi-shard case, is not even guaranteed to converge, since a lagging or slow-to-update shard can keep re-supplying the old, revoked key set indefinitely and will always be preferred if it happens to be processed first in `h.shards`.

### Impact Explanation
An unprivileged actor holding a previously authorized (now compromised, rotated, or explicitly removed) signer private key can continue to submit valid JWT-signed HTTP Trigger requests (`vaulttypes`/`gateway_common.MethodWorkflowExecute`) that pass `Authorize()` and get relayed to the workflow DON, because the gateway's cached `authorizedKeys` set for that workflow ID was never actually overwritten with the updated (revoked) key list. This is a request-impersonation / authorization-bypass condition: a party whose access should have been revoked can keep triggering workflow executions belonging to another owner.

### Likelihood Explanation
This requires (a) an attacker/compromised party who once held a legitimately authorized signer key for a specific workflow, and (b) either a `cleanupInterval` window before reaping takes effect, or a persistently lagging shard that keeps re-reporting the stale metadata ahead of the updated shard in `h.shards` iteration order. The first condition (bounded window) is likely to always occur to some degree; the second (indefinite persistence) is dependent on DON node lag/ordering and is less certain to occur, but the code contains no explicit guard against it (no recency/sequence comparison across shards, no proactive revocation call at key-rotation time).

### Recommendation
- When merging results across shards in `syncMetadata`, prefer the observation with the highest `sequence` number (most-recently observed) rather than "first shard in `h.shards` wins," so a workflow owner's most recent authorized-key update always takes precedence over stale data from any shard.
- Do not passively rely on `cleanupInterval` aging to invalidate authorization; instead, when a `WorkflowMetadata` push/pull response reports a *new* digest for an already-known `workflowReference`, immediately evict any other digest observations tied to that same reference so an old key set cannot continue to satisfy quorum.
- Consider adding a monotonically increasing version/nonce to `WorkflowMetadata` (sourced from on-chain workflow registry state) and only accept observations with a version >= the currently cached version, explicitly rejecting/clearing stale ones.

### Proof of Concept
Conceptual PoC (analogous to the two Visor PoCs):
1. Workflow owner registers workflow `W` with `AuthorizedKeys = [Eve]`. All shards observe and reach quorum; `authorizedKeys["W"] = {Eve}`.
2. Owner detects Eve's key is compromised and rotates the on-chain authorized keys to `[Alice]`. Nodes in shard A push/pull the updated metadata quickly and reach quorum with the new digest; nodes in shard B are slow (network partition, restart, or simply behind in polling) and continue reporting the old digest containing Eve until their next successful pull, which can be up to `MetadataPullRequestTimeoutMs`/`CleanUpPeriodMs` later.
3. `syncMetadata` iterates `h.shards`; if shard B (still holding Eve) is processed before shard A in this cycle (e.g., due to slice ordering or timing of the two aggregators reaching threshold on different ticks), `authorizedKeys["W"]` is set to `{Eve}` and shard A's update is discarded for that cycle (Case 1 short-circuits without overwriting).
4. Eve signs an HTTP Trigger JWT for workflow `W`; `WorkflowMetadataHandler.Authorize` succeeds because `{Eve}` is still present in `h.authorizedKeys["W"]`, and the request is dispatched to the DON — despite the owner's explicit revocation.

This could not be fully validated by execution (no test harness access in this read-only analysis), but the code paths cited above show no mechanism that guarantees prompt, deterministic replacement of a revoked key across all shards, which is the same root cause pattern as the referenced report: an authorization grant that is never explicitly and reliably cleared.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (h *WorkflowMetadataHandler) syncMetadata(ctx context.Context) {
	authorizedKeys := make(map[string]map[gateway.AuthorizedKey]struct{})
	workflowRefToID := make(map[workflowReference]string)
	workflowIDToRef := make(map[string]workflowReference)
	workflowShards := make(map[string][]*shardEndpoint)

	for _, shard := range h.shards {
		agg := h.aggs[shard.donID]
		metadata := agg.Aggregate()
		for _, data := range metadata {
			workflowID := data.WorkflowSelector.WorkflowID
			workflowRef := workflowReference{
				workflowOwner: data.WorkflowSelector.WorkflowOwner,
				workflowName:  data.WorkflowSelector.WorkflowName,
				workflowTag:   data.WorkflowSelector.WorkflowTag,
			}

			// Case 1: this workflow ID was already registered. If the reference
			// matches, this is the same workflow reported by another shard —
			// append the shard to its fan-out list. If the reference differs,
			// it's a conflicting observation; drop it.
			if existingRef, idExists := workflowIDToRef[workflowID]; idExists {
				if existingRef == workflowRef {
					workflowShards[workflowID] = append(workflowShards[workflowID], shard)
				} else {
					h.lggr.Debugw("Duplicate workflow ID with conflicting reference, dropping",
						"workflowID", workflowID, "existingRef", existingRef, "conflictingRef", workflowRef)
				}
				continue
			}

			// Case 2: this workflow reference was already registered under a
			// different workflow ID. First-wins by reference; drop the duplicate.
			if _, refExists := workflowRefToID[workflowRef]; refExists {
				h.lggr.Debugw("Duplicate workflow reference found, dropping",
					"workflowRef", workflowRef, "workflowID", workflowID)
				continue
			}

			// Case 3: new workflow ID and reference — register it.
			workflowIDToRef[workflowID] = workflowRef
			workflowRefToID[workflowRef] = workflowID
			authorizedKeys[workflowID] = make(map[gateway.AuthorizedKey]struct{})
			for _, key := range data.AuthorizedKeys {
				authorizedKeys[workflowID][key] = struct{}{}
			}
			workflowShards[workflowID] = append(workflowShards[workflowID], shard)
		}
	}

func (agg *WorkflowMetadataAggregator) reapObservations(ctx context.Context) {
	agg.mu.Lock()
	defer agg.mu.Unlock()
	now := time.Now()
	var expiredCount int
	for node, digestObservedAt := range agg.observedAt {
		for digest, observedAt := range digestObservedAt {
			if now.Sub(observedAt) > agg.cleanupInterval {
				delete(agg.observedAt[node], digest)
				if len(agg.observedAt[node]) == 0 {
					delete(agg.observedAt, node)
				}
				_, ok := agg.observations[digest]
				if !ok {
					agg.lggr.Warnw("Observation digest not found in observations", "digest", digest, "node", node)
					continue
				}
				agg.observations[digest].nodes.Remove(node)
				if len(agg.observations[digest].nodes) == 0 {
					delete(agg.observations, digest)
				}
				expiredCount++
			}
		}
	}
	if expiredCount > 0 {
		agg.metrics.IncrementMetadataObservationsCleanUpCount(ctx, int64(expiredCount), agg.lggr)
		agg.lggr.Debugw("Removed expired callbacks", "count", expiredCount)
	}
	agg.metrics.RecordMetadataObservationsCount(ctx, int64(len(agg.observations)), agg.lggr)

// Collect adds an observation from a workflow node to the aggregator.
func (agg *WorkflowMetadataAggregator) Collect(obs *gateway_common.WorkflowMetadata, nodeAddress string) error {
	if obs.WorkflowSelector.WorkflowID == "" || obs.WorkflowSelector.WorkflowName == "" ||
		obs.WorkflowSelector.WorkflowOwner == "" || obs.WorkflowSelector.WorkflowTag == "" {
		return errors.New("observation is missing required fields")
	}
	if nodeAddress == "" {
		return errors.New("node address cannot be empty")
	}
	agg.mu.Lock()
	defer agg.mu.Unlock()
	digest, err := obs.Digest()
	if err != nil {
		return err
	}
	_, ok := agg.observedAt[nodeAddress]
	if !ok {
		agg.observedAt[nodeAddress] = make(map[string]time.Time)
	}
	agg.observedAt[nodeAddress][digest] = time.Now()

	_, ok = agg.observations[digest]
	if !ok {
		agg.sequenceCounter++
		agg.observations[digest] = &NodeObservations{
			observation: obs,
			nodes:       make(StringSet),
			sequence:    agg.sequenceCounter,
		}
	}
	agg.observations[digest].nodes.Add(nodeAddress)
	return nil
}
