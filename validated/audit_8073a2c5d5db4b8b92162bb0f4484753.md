Based on my investigation of `handle_block_signature` → `store_and_process_block_signature` in `stacks-signer/src/v0/signer.rs`, I found a plausible analog to the RUSTSEC memory-exhaustion pattern (a check that isn't re-run/isn't performed immediately before an action, so the "safe" condition is assumed rather than verified), applied to the signature-aggregation path rather than one-per-height enforcement.

### Title
Signer aggregates and broadcasts a block it never itself validated or explicitly rejected as invalid - (File: stacks-signer/src/v0/signer.rs)

### Summary
`store_and_process_block_signature`, reached from `handle_block_signature` whenever a peer's `BlockAccepted` message is received, tallies signature weight and, once the 70% threshold is crossed, calls `mark_locally_accepted` and `broadcast_signed_block` to push the block to the node [1](#0-0) . Unlike the pre-commit-to-signature path (`handle_block_pre_commit`), which re-runs `check_block_against_signer_db_state` and the `get_signed_conflicts`/`conflict_still_blocks`/`reorg_permit_stands` chain immediately before signing [2](#0-1) , `store_and_process_block_signature` never checks `block_info.valid` before broadcasting.

### Finding Description
`store_and_process_block_signature` only guards on `block_info.signed_group.is_some()` before tallying peer acceptance signatures and, once weight crosses `min_weight`, immediately calls `mark_locally_accepted(true)` and `broadcast_signed_block` [3](#0-2) . There is no check anywhere in this function of `block_info.valid` (whether this signer's own node validated the block) nor a re-run of `check_block_against_signer_db_state` / conflict checks that the parallel pre-commit→signature path performs at lines 1345-1421 immediately before signing. By contrast, the documented design intent (`docs/signer-flows.md`) explicitly states the chainstate re-check must happen "immediately" before a signature leaves the box because "time passes, the burn chain can fork, and another block may win the same slot" [4](#0-3) . This mirrors the RUSTSEC-2020-0019 bug class precisely: a termination/safety check (`wants_read`/`process_new_packets`) that is supposed to run immediately after a triggering event is instead deferred or skipped, letting stale state substitute for a live check.

Concretely, `handle_block_signature` is reachable purely from gossip (`BlockAccepted` messages relayed over StackerDB) and requires no local validation state: `block_lookup_by_reward_cycle` only requires that `handle_block_proposal` created a `BlockInfo` row for the hash (which happens for any not-known-invalid proposal, valid or not, per line 1716-1719 comment "Do not store KNOWN invalid blocks... We only store blocks that are valid or unknown" [5](#0-4) ). If this signer's own node validation is still pending (`block_info.valid == None`) when 70% of peer signatures arrive via gossip, `store_and_process_block_signature` will still mark it locally accepted and broadcast it — with no requirement that this signer's own validation agrees.

### Impact Explanation
This does not, by itself, let a miner alone forge signer signatures — a genuine 70% signature weight still requires real signer keys. However, it does break the "signed vs validated" equality that the rest of the codebase enforces everywhere else (proposal check, pre-commit re-check): the recheck that stops a stale/now-invalid decision from being acted upon is present on the pre-commit→sign path but absent on the gossip-driven signature-aggregation path. Combined with the freshness/conflict windows this repo explicitly designs around (Bitcoin reorgs, tenure supersession, `reorg_permit_stands`), a signer could broadcast a block as globally-approvable based purely on peer gossip while its own local chainstate view — which the rest of the codebase treats as authoritative for conflict/liveness decisions — has since diverged, without ever independently confirming that divergence via `check_block_against_signer_db_state`.

### Likelihood Explanation
Reachable purely via ordinary gossip (`BlockResponse::Accepted` messages), no majority of malicious signers or extra key material is required beyond what already exists in a functioning signer set reaching honest 70% agreement; the missing check is an asymmetry versus the parallel, better-guarded pre-commit path, which suggests it is a gap rather than an intentional design choice.

### Recommendation
Add the same re-check performed in `handle_block_pre_commit` (`check_block_against_signer_db_state`, freshness/conflict checks via `get_signed_conflicts`/`conflict_still_blocks`/`reorg_permit_stands`) into `store_and_process_block_signature` immediately before `mark_locally_accepted`/`broadcast_signed_block`, so that reaching the acceptance threshold via peer gossip cannot short-circuit this signer's own live chainstate verification.

### Proof of Concept
I was unable to construct or run an executable PoC within this ask-only session (no filesystem/test-execution access). The above is based on static code-path analysis of `stacks-signer/src/v0/signer.rs`; a concrete PoC would require instrumenting a `SignerTest` (as used in `stacks-node/src/tests/signer/v0/mod.rs`) to delay this signer's own `/v3/block_proposal` validation response while injecting 70%-weight peer `BlockAccepted` gossip for the same block, then observing whether `broadcast_signed_block` fires before this signer's own `block_info.valid` is set — this remains **unverified** and should be confirmed by a background agent with test-execution access before treating it as confirmed rather than a plausible structural gap.

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }

## 5. Pre-commit threshold → signature

The only place the signer produces a block signature by counting votes.
Pre-commits from peers (and our own) accumulate; at ≥70% weight the signer
decides whether to follow through. Between validation and threshold, we may have
signed a _different_ block at the same height, possibly in another tenure, so
the world must be re-checked before the signature leaves the box.
