### Title
Floor-division rounding in `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` understates the 70%/30% supermajority threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The report's bug class is a division-vs-multiplication/rounding-direction error that silently relaxes a required threshold ("under-collects" relative to the true requirement). The same rounding-direction defect exists in `GlobalStateEvaluator::reached_agreement` and `reached_disagreement`, which compute the 70%/30% signer-weight supermajority thresholds used by the local signer state machine. Unlike the canonical, on-chain threshold calculation `NakamotoBlockHeader::compute_voting_weight_threshold`, which explicitly rounds *up* (ceiling) to guarantee at least 70% weight, the signer-side agreement check truncates (floors), so a sub-70% weight coalition can be treated as having "reached agreement."

### Finding Description
`NakamotoBlockHeader::compute_voting_weight_threshold` (the canonical/on-chain threshold used to verify block signatures) is defined with explicit ceiling rounding: [1](#0-0) 

By contrast, `GlobalStateEvaluator::reached_agreement` and `reached_disagreement`, used by every signer to decide whether the *global* view (burn block, current miner, protocol version, tx replay set) has reached consensus, compute the threshold with plain integer division and no ceiling correction: [2](#0-1) 

Because `total_weight * 7` is not always a multiple of 10, `(total_weight * 7) / 10` truncates down. E.g. with `total_weight = 11`, the true 70% requirement is `7.7`, meaning at least `8` weight units are needed to reach ≥70%; the floor computation instead accepts `vote_weight = 7` (only ~63.6% of weight) as having "reached agreement." The analogous flaw exists in `reached_disagreement` for the 30% blocking-minority side (it should round the complement up as well, but instead floors, understating the blocking-minority requirement rather than over-stating it, which is a separate but symmetrical rounding inconsistency).

This threshold feeds directly into the local state-machine determination functions:
- `determine_latest_supported_signer_protocol_version` (protocol-version agreement)
- `determine_global_burn_view` (which burn view is treated as globally agreed)
- `determine_global_state` (which `current_miner` and `tx_replay_set` are treated as globally agreed) [3](#0-2) 

These are the same GlobalStateEvaluator determinations documented as governing "current miner" acceptance and burn-view-driven behavior in the signer's decision flow, per `stacks-signer/src/v0/signer.rs` and `stacks-signer/src/signerdb.rs` consumers of `reached_agreement` (e.g. `get_burn_block_received_time_from_signers`): [4](#0-3) 

The existing regression test in the repo only guards against a u32 overflow wrap, not the rounding-direction correctness, and explicitly hard-codes the boundary check at the exact `total_weight * 7 % 10 == 0` case, missing the non-multiple-of-10 case where the flaw is observable: [5](#0-4) 

### Impact Explanation
This lets the local signer state machine conclude "global agreement reached" on a burn view, protocol version, current-miner, or transaction-replay set using less than the true, intended 70% supermajority weight whenever `total_weight * 7` is not an exact multiple of 10 (the common case for most realistic signer-weight distributions). Since `determine_global_state`'s `current_miner` and `determine_global_burn_view` outputs steer which miner/tenure the signer treats as canonical and which burn view it uses for freshness/staleness checks throughout `stacks-signer/src/v0/signer.rs`'s decision flow, a signer can act on a threshold that is not actually backed by a genuine supermajority. This matches the "High: a signer... acting on a stale reward set/threshold" impact class: the signer's notion of global consensus is built on a systematically weaker-than-advertised threshold, diverging from the strict-ceiling threshold enforced on-chain for block-signature verification (`compute_voting_weight_threshold`), creating an equality break between the signer's internal state-machine "agreement" and the node's canonical supermajority definition.

### Likelihood Explanation
No majority collusion or malicious signer key is required — this is a deterministic arithmetic property of the formula that triggers whenever `total_weight * 7 mod 10 != 0`, which is the overwhelmingly common case for arbitrary signer-weight totals (only weights that are exact multiples of 10 avoid it entirely for the 70% case). Any set of honestly-behaving signers whose combined weight falls in the gap between the floored and true ceiling threshold will trigger a divergence from the intended supermajority requirement on every relevant `reached_agreement` call (protocol version, burn view, current miner, tx replay set, and `get_burn_block_received_time_from_signers`).

### Recommendation
Change `reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use the same ceiling-rounding approach as `NakamotoBlockHeader::compute_voting_weight_threshold` (round up when computing the required weight for agreement, and round down/complement correctly for the blocking-minority side), so the signer-side notion of "reached agreement" is never weaker than the canonical on-chain supermajority definition:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total_weight = u64::from(self.total_weight);
    let threshold = total_weight.strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD);
    let required = threshold.div_ceil(10); // round up
    u64::from(vote_weight) >= required
}
```

### Proof of Concept
1. Construct a `GlobalStateEvaluator` with `total_weight = 11` (e.g., 11 signers of weight 1 each, or any distribution summing to 11).
2. True 70% requirement: `11 * 0.7 = 7.7`, i.e., ≥8 weight units are needed for a genuine ≥70% supermajority.
3. Call `evaluator.reached_agreement(7)`:
   - Current code: `(11 * 7) / 10 = 77 / 10 = 7` (floor) → `7 >= 7` → `true` (incorrectly reports agreement reached).
   - Correct code (ceiling): `div_ceil(77, 10) = 8` → `7 >= 8` → `false` (correctly rejects).
4. This means a coalition holding only 7/11 (~63.6%) of the weight is treated by `determine_global_state`/`determine_global_burn_view`/`determine_latest_supported_signer_protocol_version` as having reached the 70% global-agreement threshold, one weight unit short of the true requirement — the direct analog of the reported "under-collection" from floor-vs-ceiling rounding.

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };

                .entry(update.local_supported_signer_protocol_version)

        protocol_versions.sort_by_key(|(version, _)| *version);

            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

                burn_block_height,

                tx_replay_set: ReplayTransactionSet::none(),

            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }

        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {

            self.find_majority_prefix_replay_set(&tx_replay_sets)

/// Regression: u32 multiplication in `reached_agreement` wrapped silently in
/// release builds for `total_weight > u32::MAX / 7 ≈ 613_566_756`. With
/// `total_weight = 1_000_000_000` the buggy expression `total_weight * 7 / 10`
/// wrapped to ~270_503_270, allowing roughly 27% of total weight to satisfy
/// the 70% supermajority check. The fix widens to u64 first.
fn reached_agreement_no_u32_overflow() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // Pre-fix wrap landed at 270_503_270; assert that vote_weight at the wrapped
    // value is correctly rejected — i.e., 27% does not satisfy 70%.
    assert!(
        !evaluator.reached_agreement(270_503_270),
        "27% of total_weight must not satisfy the 70% threshold"
    );
    // Boundary: exactly 70% must pass.
    assert!(
        evaluator.reached_agreement(700_000_000),
        "70% of total_weight must satisfy the 70% threshold"
    );
    // Just below 70% must fail.
    assert!(
        !evaluator.reached_agreement(699_999_999),
        "below 70% must not satisfy the threshold"
    );
}
