## Analysis

The report describes CWE-613 (Insufficient Session Expiration): a credential/session token that should time out but can be resurrected and reused after its intended lifetime. In this repo, the closest analog is the EIP-8205 withdrawal-credentials **preregistration** mechanism, which binds a validator pubkey to withdrawal credentials for a bounded window (`PREREGISTRATION_EXPIRY_SLOTS`) to protect depositors against front-running.

### Title
Preregistration bindings can be resurrected indefinitely because the signed authorization has no expiry/nonce, defeating `PREREGISTRATION_EXPIRY_SLOTS` and letting a stale withdrawal-credentials binding block/redirect a depositor's later deposit — (File: `specs/_features/eip8205/beacon-chain.md`)

### Summary
The `PreregistrationRequest` signature only commits to `pubkey` and `withdrawal_credentials` — never to a slot, nonce, or expiry — and is verified with a fork-agnostic, replay-tolerant domain "so a preregistration signed once remains valid across fork boundaries, like a deposit signature" [1](#0-0) [2](#0-1) . Only the *stored record's* `expiry_slot`, computed at insertion time, limits how long a binding is enforced [3](#0-2) [4](#0-3) . Because the underlying message never expires, anyone who observed a historical `PreregistrationRequest` (public execution-layer/mempool/on-chain data) can resubmit the exact same bytes at any later time, as long as no *currently active* binding for that pubkey exists, and the chain will happily re-admit it and mint a brand-new `expiry_slot` [5](#0-4) .

### Finding Description
`process_preregistration_request` admits a request whenever there is no *active* binding for the pubkey, the pubkey isn't already a validator, it isn't in `pending_deposits`, and capacity allows it — and the signature check (`is_valid_preregistration_signature`) never checks freshness because the signed payload has no time/nonce component [6](#0-5) [7](#0-6) .

Concrete scenario:
1. Staking pool preregisters pubkey `P` with withdrawal credentials `W_old` (signed request `R_old`). It is stored with `expiry_slot = s0 + PREREGISTRATION_EXPIRY_SLOTS`.
2. Time passes, `R_old`'s binding naturally lapses (`is_active_preregistration` returns `False` once `parent_slot >= expiry_slot`) because the pool switched providers; nothing has re-preregistered yet, and the physically-expired record may still sit in `validator_preregistrations` awaiting the next epoch sweep [8](#0-7) .
3. Before the pool submits a new preregistration for `W_new` (or a real deposit), any observer (unprivileged, no coalition needed) simply rebroadcasts the *same* historical `R_old` bytes. Since there is currently no active binding, `process_preregistration_request` re-accepts `R_old` verbatim and stores a fresh `StoredPreregistration(pubkey=P, withdrawal_credentials=W_old, expiry_slot=current_slot + PREREGISTRATION_EXPIRY_SLOTS)` [9](#0-8) .
4. The pool's legitimate deposit request for `W_new` now hits `process_deposit_request`, sees an *active* preregistration bound to `W_old`, finds `deposit_request.withdrawal_credentials != preregistration.withdrawal_credentials`, and silently discards the deposit request [10](#0-9) .
5. The attacker can repeat step 3 indefinitely (every time the binding lapses) using the same never-expiring signature, perpetually re-arming protection pinned to the stale `W_old` credentials and causing the depositor's real, correctly-credentialed deposits to be discarded — with the EL-side ETH transfer already consumed and never credited to any validator.

This breaks the "Gwei created/destroyed/paid to non-owner" equality: legitimate deposit value is discarded/stuck because a third party, without current authorization from the depositor, unilaterally re-instates an authorization window the depositor had let lapse, using nothing but publicly-replayable historical data.

### Impact Explanation
An unprivileged actor who merely observed prior on-chain/mempool data can perpetually re-arm an intentionally-time-limited authorization (`PREREGISTRATION_EXPIRY_SLOTS`) that was designed to expire, and use it to force discard of a depositor's legitimately-signed deposit whose withdrawal credentials no longer match. Because the deposit contract's ETH has already moved on the execution side, the discarded deposit request corresponds to real Gwei that never gets credited to any validator — matching the "Gwei destroyed" Critical criterion. No coalition, malicious client, or majority stake is required.

### Likelihood Explanation
All request data (`pubkey`, `withdrawal_credentials`, `signature`) needed to replay `R_old` is public once included in an execution payload. The only precondition is a window where no active binding currently exists for that pubkey (e.g., between the natural expiry of an old binding and submission of a new one/deposit), which routinely occurs in the "switch providers" workflow the feature explicitly targets. No special access or timing precision beyond normal transaction inclusion is required.

### Recommendation
Bind the signed payload to a validity window or nonce, e.g., include an `expiry_slot`/`valid_after` or a monotonically increasing sequence number inside `ValidatorPreregistration` itself (covered by the signature), and reject `PreregistrationRequest`s whose embedded expiry is in the past or whose nonce has already been consumed for that pubkey — rather than relying solely on state-tracked `expiry_slot`, which only limits enforcement of a *stored* record, not the reusability of the underlying signature.

### Proof of Concept
1. Pool signs `ValidatorPreregistration(pubkey=P, withdrawal_credentials=W_old)` → `R_old`; include in a block; binding stored with `expiry_slot = s0+N`.
2. Advance slots past `s0+N` (binding no longer active per `is_active_preregistration`) without any new preregistration for `P`.
3. Attacker resubmits `R_old` unchanged in a later block's `PreregistrationRequests`; `process_preregistration_request` re-admits it (no active binding, no validator yet, not pending, under capacity, signature still verifies) and stores a new record with a fresh `expiry_slot`.
4. Pool's real deposit for `P` with `withdrawal_credentials=W_new` arrives; `process_deposit_request` sees active `preregistration.withdrawal_credentials == W_old != W_new` and discards it, per [10](#0-9) .

def is_valid_preregistration_signature(state: BeaconState, request: PreregistrationRequest) -> bool:
    preregistration = ValidatorPreregistration(
        pubkey=request.pubkey,
        withdrawal_credentials=request.withdrawal_credentials,
    )
    domain = compute_domain(
        DOMAIN_PREREGISTRATION,
        genesis_validators_root=state.genesis_validators_root,
    )
    signing_root = compute_signing_root(preregistration, domain)
    return bls.Verify(request.pubkey, signing_root, request.signature)

#### New `is_active_preregistration`

*Note*: Activity is evaluated against the slot of the outstanding parent
payload, whose execution requests are the ones being applied during block
processing. Once stored, a binding therefore remains active for subsequently
processed payloads whose slots are below its stored `expiry_slot`, regardless of
when the expired record is physically swept.

```python
def is_active_preregistration(state: BeaconState, preregistration: StoredPreregistration) -> bool:
    parent_slot = state.latest_execution_payload_bid.slot
    return parent_slot < preregistration.expiry_slot
```

#### New `process_preregistration_expiry`

*Note*: The sweep is garbage collection only: bindings are enforced through
`is_active_preregistration`, so its timing has no effect on whether a binding is
enforced or a request is admitted, and expiry is independent of finality. An
expired record may therefore remain physically stored until the next sweep.
Reusing the same predicate, which is keyed to the outstanding parent bid,
guarantees that a record is never removed while a payload it still covers
remains outstanding.

```python
def process_preregistration_expiry(state: BeaconState) -> None:
    state.validator_preregistrations = ValidatorPreregistrations(
        data=[
            preregistration
            for preregistration in state.validator_preregistrations
            if is_active_preregistration(state, preregistration)
        ]
    )
```

##### New `process_preregistration_request`

```python
def process_preregistration_request(state: BeaconState, request: PreregistrationRequest) -> None:
    pubkey = request.pubkey

    # An active binding for this pubkey makes the new request a no-op,
    # whether the duplicate is exact or conflicting
    if get_active_preregistration(state, pubkey) is not None:
        return

    # A pubkey with an existing validator cannot be preregistered
    if pubkey in [validator.pubkey for validator in state.validators]:
        return

    # A pubkey with a valid pending deposit cannot be preregistered
    if is_pending_validator(state.pending_deposits, pubkey):
        return

    # The capacity check counts only active records, so the timing of the
    # garbage-collection sweep does not affect admission. It applies to
    # appends and to replacements alike, since both create an active binding
    active_preregistrations = [
        preregistration
        for preregistration in state.validator_preregistrations
        if is_active_preregistration(state, preregistration)
    ]
    if len(active_preregistrations) >= PREREGISTRATIONS_LIMIT:
        return

    if not is_valid_preregistration_signature(state, request):
        return

    preregistration = StoredPreregistration(
        pubkey=pubkey,
        withdrawal_credentials=request.withdrawal_credentials,
        expiry_slot=state.slot + PREREGISTRATION_EXPIRY_SLOTS,
    )
    index = get_stored_preregistration_index(state, pubkey)
    if index is not None:
        # Replace the expired record in place
        state.validator_preregistrations[index] = preregistration
    else:
        state.validator_preregistrations.append(preregistration)
```

def process_deposit_request(state: BeaconState, deposit_request: DepositRequest) -> None:
    # [New in EIP8205]
    preregistration = get_active_preregistration(state, deposit_request.pubkey)
    if preregistration is not None:
        if deposit_request.withdrawal_credentials != preregistration.withdrawal_credentials:
            return

        if not is_valid_deposit_signature(
            deposit_request.pubkey,
            deposit_request.withdrawal_credentials,
            deposit_request.amount,
            deposit_request.signature,
        ):
