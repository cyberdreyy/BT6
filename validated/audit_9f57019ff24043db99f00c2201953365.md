## Title
Job can forge step-status JSON marker via `echo`/`printf`, causing `entrypointLogForwarder` to mis-pause/mis-resume trace forwarding - (File: `executors/kubernetes/container_entrypoint_forwarder.go`)

## Summary
The marker that `entrypointLogForwarder.commandStatus` parses out of container logs is just a timestamp-prefixed, unauthenticated JSON blob (`{"command_exit_code": N, "script": "path"}`) produced by a shell trap generated in `shells/abstract.go`/`shells/bash.go`/`trap_command_exit_status.go`. There is no nonce, HMAC, or any secret tying the marker to the runner; a job with shell access can `printf` a byte-identical line and get it accepted by `StageCommandStatus.TryUnmarshal`.

## Finding Description
`entrypointLogForwarder.commandStatus` (`executors/kubernetes/container_entrypoint_forwarder.go:91-113`) validates only that the line begins with a value parseable by `time.Parse(containerLoggerTimeStampFormat, ts)` followed by a space, then hands the remainder to `shells.StageCommandStatus.TryUnmarshal`, which is a plain `encoding/json.Unmarshal` into `{command_exit_code, script}` (`shells/trap_command_exit_status.go:26-61`). Neither field is derived from any secret, sequence number, or HMAC — it's fully predictable static JSON, as also demonstrated by the fallback marker format `fallbackExitStatusMarkerFmt` used in `executors/kubernetes/kubernetes.go` and the trap literal duplicated in `kubernetes_test.go` (`jsonTerminationTrap`), which is exactly:
```
{"command_exit_code": $exit_code, "script": "$0"}
```
Since the job's own script runs inside the same container whose combined stdout/stderr stream is what `entrypointLogForwarder.Write` consumes (line-buffered on `\n`), a job step can emit a line with a timestamp prefix in `containerLoggerTimeStampFormat` followed by `{"command_exit_code": N, "script": "..."}` via `echo`/`printf`/`date`, and `commandStatus` will accept it as genuine, flipping `lf.paused` accordingly (`writeLine`, lines 22-30).

Effects of a forged marker:
- If `command_exit_code` is present (`IsExited()==true`) → `lf.paused = false`, resuming forwarding of subsequent job output into the trace even if the runner had previously paused it (e.g. during a helper/predefined phase) — trace content bleed between phases.
- If `command_exit_code` is absent but `script` names a valid stage (`BuildStage() != ""`) → `lf.paused = true`, silently suppressing forwarding of the job's own subsequent stdout/stderr from the trace (the line itself is also dropped, since `ok==true` short-circuits the write at line 32).

This is a legitimate parsing/authentication gap: the marker channel has no authentication, and the only gate is timestamp-format + JSON-shape, both fully attacker-reproducible from inside the job's own script.

## Impact Explanation
Within scope: a job can forge/suppress the exit-status marker to make `entrypointLogForwarder` pause trace forwarding (hiding subsequent output of its own step from the trace) or prematurely resume forwarding (causing helper-container/other-phase output framing confusion in the visible trace). This is trace tampering as scoped — the job can control what appears/disappears in its own step's log stream by exploiting the marker channel. It does not, based on the code seen, let a job forge *another job's* results, escape its container, or affect the runner's real pass/fail decision — `checkScriptExecution`/step exit-code determination is driven by the actual process exit status observed by the executor's attach/exec plumbing, not solely by this log-derived marker for pass/fail (though I could not fully trace `kubernetes.go`'s consumption of `cmdStatus`/`BuildStage()` before the tool budget ran out, so I cannot conclusively state whether step-skip/exit-code forgery beyond trace-pause/resume is also reachable — that requires reviewing the remaining 10 references in `kubernetes.go` that I was unable to inspect in this session).

## Likelihood Explanation
Fully feasible and repeatable: any job with shell access in the build/helper container (the default, unprivileged case) can construct the marker with only `date`/`printf`, no special permissions needed. The `containerLoggerTimeStampFormat` (`2006-01-02T15:04:05.999999999Z`) is derivable via `date -u +%Y-%m-%dT%H:%M:%S.%NZ` or similar, and the JSON body has no randomness.

## Recommendation
Bind the marker to a per-invocation unpredictable value (e.g., a random nonce generated by the runner and injected as an environment variable not exposed to user commands, or wrap the marker in an HMAC keyed with a runner-only secret) and require `commandStatus`/`TryUnmarshal` to verify that token before treating the line as authoritative, rejecting any line without a valid signature.

## Proof of Concept
Unit test extending `container_entrypoint_forwarder_test.go`-style tests:
1. Construct a fake `Sink`.
2. Feed `lf.Write` a line: `"<validTimestamp> " + fmt.Sprintf(`{"command_exit_code": 0, "script": "%s"}`, "/some/legit/stage/path") + "\n"` — a string an attacker could produce purely with `date`+`printf` from inside the job container.
3. Assert `lf.paused` toggles exactly as it would for a genuine trap-emitted marker, and that the forged line itself is swallowed (not written to Sink), proving the job controlled trace visibility of its own subsequent output.
4. Assert no distinguishing feature (nonce/HMAC) exists that a legitimate marker would have but the forged one lacks — i.e., diff the exact accepted format in `stageCommandExitStatusImpl`/`TryUnmarshal` against what a POSIX shell one-liner can produce. // commandStatus inspects the current data if it's a [shells.StageCommandStatus]
// This is done, so we understand if the logs coming in are part of a step_command or "something else".
func (lf *entrypointLogForwarder) commandStatus(p []byte) (shells.StageCommandStatus, bool) {
	cmdStatus := shells.StageCommandStatus{}

	// check if the first part resembles a timestamp
	if len(p) < len(containerLoggerTimeStampFormat) ||
		p[len(containerLoggerTimeStampFormat)] != ' ' {
		return cmdStatus, false
	}

	line := string(p)
	ts := line[:len(containerLoggerTimeStampFormat)]
	_, err := time.Parse(containerLoggerTimeStampFormat, ts)

	if err != nil {
		return cmdStatus, false
	}

	// the actual log line starts after the timestamp + a space
	line = line[len(containerLoggerTimeStampFormat)+1:]

	ok := cmdStatus.TryUnmarshal(line)
	return cmdStatus, ok
}

package shells

import (
	"encoding/json"
	"fmt"
	"strings"

	"gitlab.com/gitlab-org/gitlab-runner/common"
)

// stageCommandExitStatusImpl is a private struct used to unmarshall the log line read.
// All of its fields are optional, so it can check to make sure against the required and optional ones.
// The fields are then applied to StageCommandStatus which is the exposed, ready-to-use struct.
type stageCommandExitStatusImpl struct {
	// CommandExitCode is the exit code of the last command.
	CommandExitCode *int `json:"command_exit_code"`
	// Script is the script which was executed as an entrypoint for the current execution step.
	// The scripts are currently named after the stage they are executed in.
	// This property is **NOT REQUIRED** and may be nil in some cases.
	// For example, when an error is reported by the log processor itself and not the script it was monitoring.
	Script *string `json:"script"`
}

// tryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It's safe to use the struct only if this method returns no error.
func (cmd *stageCommandExitStatusImpl) tryUnmarshal(line string) error {
	return json.Unmarshal([]byte(line), cmd)
}

func (cmd stageCommandExitStatusImpl) isEmpty() bool {
	return cmd.CommandExitCode == nil && cmd.Script == nil
}

func (cmd stageCommandExitStatusImpl) applyTo(to *StageCommandStatus) {
	to.CommandExitCode = cmd.CommandExitCode
	to.Script = cmd.Script
}

type StageCommandStatus struct {
	CommandExitCode *int
	Script          *string
}

// TryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It wil return true only if the unmarshalled struct has all of its required fields be non-nil.
// It's safe to use the struct only if this method returns true.
func (c *StageCommandStatus) TryUnmarshal(line string) bool {
	var status stageCommandExitStatusImpl
	err := status.tryUnmarshal(line)
	if err != nil {
		return false
	}

	if status.isEmpty() {
		return false
	}

	status.applyTo(c)

	return true
}
