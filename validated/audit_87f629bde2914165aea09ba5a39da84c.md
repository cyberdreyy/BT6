### Title
Rounding-direction mismatch between the signer's `GlobalStateEvaluator::reached_agreement` and the consensus-critical `NakamotoBlockHeader::compute_voting_weight_threshold` allows sub-70% weight to be treated as supermajority agreement - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The signer-side `GlobalStateEvaluator::reached_agreement` (and its complement `reached_disagreement`) computes the 70% supermajority threshold with a floor (truncating) division, while the canonical, consensus-critical threshold used to actually validate a Nakamoto block's signer signatures, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly rounds the threshold *up* (ceiling). This is the exact "wrong rounding direction" bug class from the external report: a quantity that must be conservative (the threshold a vote must clear) is rounded the wrong way, letting fewer votes than the true supermajority satisfy the check.

### Finding Description
`NakamotoBlockHeader::compute_voting_weight_threshold` intentionally rounds up so that a block can never be accepted with less than the true 70% of weight: [1](#0-0) 

This threshold is exactly what `verify_signer_signatures` (chain-level block validation) enforces: [2](#0-1) 

However, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement`, which the signer software uses to decide when the *signer set* has reached agreement on global state (active protocol version, global burn view, current-miner state machine, and the transaction replay set), use plain floor division instead of the ceiling used by the canonical threshold function: [3](#0-2) 

These two functions implement the *same* nominal "70% supermajority" concept but round in opposite directions. For any `total_weight` that is not an exact multiple of 10, `floor(total_weight * 7 / 10) < ceil(total_weight * 7 / 10)`, so there exists an integer vote weight (namely `floor(total_weight*7/10)`) that:
- **is accepted** by `GlobalStateEvaluator::reached_agreement` as "supermajority agreement," but
- **is rejected** by `compute_voting_weight_threshold`/`verify_signer_signatures` as insufficient to satisfy the actual consensus rule.

`reached_agreement` is used to determine consensus-relevant local decisions such as the current-miner state machine, the burn view, and the transaction replay set that this signer will act on: [4](#0-3) 

This means a coalition of signers (via ordinary gossip of `StateMachineUpdate` messages over StackerDB, no majority key or special access required beyond normal participation) whose combined weight sits between the floor-rounded and ceiling-rounded thresholds can make an honest signer's `GlobalStateEvaluator` conclude "global agreement" has been reached on a miner/tenure/replay-set view that does **not** actually have the 70% supermajority support the protocol requires elsewhere (e.g., for block signing itself). This can steer the signer's own state machine (and hence its future signing/rejection decisions) onto a view that is inconsistent with what the canonical, ceiling-based threshold would recognize as legitimate - breaking the intended equality between "signer-computed agreement" and "protocol-enforced supermajority."

### Impact Explanation
This breaks the invariant that the local signer's notion of "the signer network agrees" is at least as strict as the protocol's actual 70%-weight requirement. A signer can be led to adopt (and act on) a `current_miner`/burn-view/tx-replay-set state that only ~(true_threshold - 1 weight unit) of the network actually supports, i.e., strictly less than the real supermajority. Downstream, this state feeds into miner-following and replay-set decisions in the v0 signer (`determine_global_state`), which can cause a signer to sign for a miner/tenure or apply a transaction-replay policy that a true supermajority never agreed to - i.e., contributing to a signer acting on/signing a non-canonical view. This matches the "signer wedged/acting on a stale or unverified aggregated state" and "signing based on a miscounted (rounded) aggregate" impact classes.

### Likelihood Explanation
No majority of signers and no special access is needed - only that `total_weight` (sum of registered signer weights for the reward cycle) not be an exact multiple of 10, which is the common case, and that the weight distribution allow a coalition to land exactly on the floor-rounded value. Given typical signer weight distributions (weight units derived from stacked amounts), this gap is frequently just 1 weight unit, so it can be triggered by ordinary variance in participation/timing of `StateMachineUpdate` gossip rather than a crafted attack, making it plausible in normal operation, not merely theoretical.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` round in the same (conservative/ceiling) direction as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by sharing the same helper, so "agreement" as computed by the signer state machine can never be satisfied by less than the true supermajority weight that the chain itself requires: [5](#0-4) [1](#0-0) 

### Proof of Concept
1. Let `total_weight = 11` (e.g., 11 signer weight units in the reward set - a realistic small reward set).
2. Canonical threshold: `compute_voting_weight_threshold(11)` = `ceil(11*7/10)` = `ceil(7.7)` = `8`. This is the number of weight units the chain requires before a block signature set (or, by the same math, any true "70% supermajority") is valid.
3. Signer-side check: `GlobalStateEvaluator::reached_agreement(7)` evaluates `7 >= (11 * 7) / 10` = `7 >= 77/10` = `7 >= 7` (integer floor) → `true`.
4. Therefore 7 out of 11 weight units (63.6%, strictly below the true 70% supermajority the protocol requires) is enough for a signer's `GlobalStateEvaluator` to declare `determine_global_state`/`determine_global_burn_view`/`determine_latest_supported_signer_protocol_version` "agreed," while the same weight would be rejected as insufficient by `verify_signer_signatures`/`compute_voting_weight_threshold` for an actual block. This demonstrates the rounding-direction inconsistency and its concrete effect on the signer's global-state determination.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
