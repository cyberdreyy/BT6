### Title
Stale Oracle Price Returned Without Absolute Freshness Check — (`File: crates/sui-oracle/move/oracle/sources/simple_oracle.move`, `meta_oracle.move`)

---

### Summary

The Sui oracle framework's `get_latest_data` function in `simple_oracle.move` returns stored price data with no check that the stored timestamp is recent relative to the current block time. The `MetaOracle` aggregator in `meta_oracle.move` performs only a relative inter-oracle consistency window (`max_timestamp - time_window_ms`) but never compares any timestamp against the on-chain `Clock`. If oracle operators stop submitting updates, arbitrarily old prices are silently returned to every consumer.

---

### Finding Description

`get_latest_data` is the framework's primary read path. It takes no `Clock` argument and performs no freshness assertion: [1](#0-0) 

It simply reads whatever `StoredData` is stored in the dynamic field and wraps it in `Option<Data<T>>`. The `timestamp` field inside `StoredData` is set at submission time: [2](#0-1) 

but is never validated on the read path.

The `MetaOracle` aggregator does apply a window filter in `combine`: [3](#0-2) 

However, `min_timestamp = max_timestamp - time_window_ms` is a **relative** bound anchored to the most-recently-added oracle's own timestamp — not to the current block time. `max_timestamp` is set by `add_simple_oracle` by unconditionally overwriting with each successive oracle's timestamp: [4](#0-3) 

Neither `combine` nor `median` accepts a `Clock` object: [5](#0-4) 

Consequently, if all N oracle operators stop submitting data simultaneously, `max_timestamp` is anchored to the last stale submission, the relative window passes all N stale feeds, the `threshold` assertion at line 66 is satisfied, and `median` returns a price that may be hours or days old — with no error or warning.

The reference consumer `simple_fx` demonstrates the end-to-end path: it calls `get_latest_data` and immediately uses the returned value to compute a token amount, with no timestamp inspection: [6](#0-5) 

---

### Impact Explanation

Any on-chain application that calls `get_latest_data` or `MetaOracle::median` and acts on the returned price (exchange, lending, liquidation) will operate on stale data when oracle operators are offline or censored. This enables:

- Buying assets at outdated low prices (fund theft from the protocol).
- Avoiding liquidation because the stale price does not reflect a real-world drop.
- Triggering incorrect liquidations if the stale price is artificially high.

This matches the **harmful smart-contract behavior** class (High/Medium impact).

---

### Likelihood Explanation

Oracle liveness depends entirely on off-chain operators. Any network disruption, operator key compromise, or deliberate griefing causes the on-chain data to go stale. Because the framework provides no on-chain staleness gate, every consumer silently inherits the risk. The trigger is public (any caller of `get_latest_data`) and requires no special privilege.

---

### Recommendation

1. Add a `clock: &Clock` parameter to `get_latest_data` and assert that `clock::timestamp_ms(clock) - stored_timestamp <= max_staleness_ms` before returning data.
2. Add the same `Clock` parameter to `MetaOracle::combine` / `median` and replace the relative `max_timestamp - time_window_ms` window with an absolute `clock::timestamp_ms(clock) - time_window_ms` lower bound.
3. Expose a `max_staleness_ms` field in `SimpleOracle` so deployers can configure the acceptable freshness window per feed.

---

### Proof of Concept

1. Deploy the `oracle` package and create a `SimpleOracle`.
2. Call `submit_data` once to store a price at block time T.
3. Wait (or advance the simulated clock) so that the current block time is T + Δ where Δ >> any reasonable freshness window.
4. Call `get_latest_data` — it returns the price with timestamp T and no error.
5. Call `simple_fx` with the stale oracle — it mints `MockUSD` at the T-era exchange rate, not the current rate.
6. For `MetaOracle`: repeat with three stale oracles; `trusted_fx` passes the threshold check and returns the stale median price because `max_timestamp` is anchored to the stale data, not to `clock::timestamp_ms`. [1](#0-0) [3](#0-2)

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
