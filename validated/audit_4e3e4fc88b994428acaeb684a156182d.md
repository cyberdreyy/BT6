### Title
Unbounded per-caller fan-out via `MethodPublicKeyGet` cache-miss path bypasses authorization and lacks rate limiting - ([File: core/services/gateway/handlers/vault/handler.go])

### Finding Description
`HandleJSONRPCUserMessage` explicitly special-cases `vaulttypes.MethodPublicKeyGet` to skip `requestProcessor.ProcessRequest` entirely, relying on an in-memory cache to avoid repeated node fan-out: [1](#0-0) 

When `h.getCachedPublicKey()` returns `nil` (cache miss), the code path calls `h.newActiveRequest(req, callback)` followed by `h.handlePublicKeyGet(ctx, ar)` with **no authorization check and no per-caller/global rate limiting** on this branch: [2](#0-1) 

`newActiveRequest` only rejects a request if the exact same `req.ID` is already in-flight; it does not throttle by sender identity, IP, or any quota. Since the caller fully controls `req.ID` (only constrained to be non-empty and ≤200 chars), an attacker can trivially generate a fresh unique ID per request to bypass the "ID already exists" de-duplication.

`handlePublicKeyGet` re-checks the cache and, on a miss, calls `fanOutToVaultNodes`, which forwards the request to every DON member node: [3](#0-2) 

The only rate limiter present in this handler (`h.nodeRateLimiter`) throttles *inbound node responses* in `HandleNodeMessage`, not outbound *user-triggered* fan-out requests: [4](#0-3) 

By contrast, the sibling HTTP-trigger gateway handler explicitly enforces a `userRateLimiter.AllowErr` gate before doing any node fan-out for user-submitted requests: [5](#0-4) 

No equivalent gate exists for the vault handler's `MethodPublicKeyGet` cache-miss path. The code comment ("we cache this value quite aggressively so don't need to worry about DoS") documents the design assumption but provides no backstop for the window where the cache is empty — at node startup, after a cache-clearing event, or whenever quorum on the public key response cannot be reached (e.g., node outage/partition causing `errInsufficientResponsesForQuorum`/`errQuorumUnobtainable` indefinitely). During that window, every distinct-ID request from an unauthenticated, unprivileged caller results in one full DON-wide fan-out (`SendToNode` to every DON member).

### Impact Explanation
This is a resource-exhaustion / availability issue: an unprivileged, unauthenticated caller of the gateway JSON-RPC endpoint can force unlimited DON-wide message fan-out by repeatedly sending `MethodPublicKeyGet` requests with fresh IDs while the cache is unset, without ever needing to pass `GatewayVaultRequestProcessor.ProcessRequest`'s authorization. This consumes node/DON compute and network bandwidth shared with legitimate paying subscribers of the same DON, matching a Denial-of-Service impact class (degraded/DoS'd node availability affecting other tenants) rather than a direct fund-loss or key-disclosure bug.

### Likelihood Explanation
Preconditions: the cache must be empty (guaranteed at every gateway/handler startup before the first successful quorum-backed public key fetch, and potentially indefinitely if quorum can't be reached due to node issues). No credentials, authentication, or special role are required — this is the literal unauthenticated, "no authorization required" code path by design. The attack is trivially repeatable: generate a UUID for `req.ID` and re-send. This makes the likelihood of the DoS window being hit non-trivial, though the *duration* of exposure (bound to the empty-cache window) somewhat limits real-world severity compared to a permanent bypass.

### Recommendation
Add a per-sender (and global) rate limiter — similar to the `userRateLimiter` pattern used in `httpTriggerHandler.checkRateLimit` — gating the `MethodPublicKeyGet` cache-miss branch of `HandleJSONRPCUserMessage` before `newActiveRequest`/`fanOutToVaultNodes` are invoked, so unauthenticated cache-miss requests cannot cause unbounded DON fan-out regardless of caller identity.

### Proof of Concept
Go handler-level test plan (extending `handler_test.go` conventions using `setupHandler`):
1. Construct a `handler` via `setupHandler(t)` with `don.On("SendToNode", ...)` mocked to count invocations.
2. Force `h.cachedPublicKeyGetResponse`/`h.cachedPublicKeyObject` to remain `nil` (do not call `cacheVaultPublicKeyForTest`).
3. In a loop of N (e.g., 1000) iterations, call `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request[json.RawMessage]{ID: uuid.New().String(), Method: vaulttypes.MethodPublicKeyGet}, callback)` with a fresh callback each time.
4. Assert `don.AssertNumberOfCalls(t, "SendToNode", N*len(donConfig.Members))` — i.e., fan-out scales linearly and unboundedly with attacker-controlled request volume, with no rejections due to rate limiting.
5. Add an expected-fix assertion: after introducing a per-sender rate limiter, the same loop should show `SendToNode` call count capped at the configured burst/RPS regardless of N, with excess requests returning a rate-limit error via `callback.Wait`.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
