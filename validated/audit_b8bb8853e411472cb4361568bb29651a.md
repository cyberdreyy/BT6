### Title
Unauthenticated disclosure of LOOP plugin registry, metrics, and pprof profiles via `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*` - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the shared `api` router group with no authentication middleware attached, unlike other sensitive routes such as `/debug/vars` and `/sessions` (DELETE) which are explicitly wrapped with `auth.Authenticate`. Any unauthenticated client that can reach the node's HTTP port can enumerate registered LOOP plugins, pull their Prometheus metrics, and pull pprof profiles/heap dumps proxied from the plugin's internal process.

### Finding Description
In `core/web/router.go`, `NewRouter` builds an `api` group with only rate limiting and cookie-session middleware attached, then calls route-registration helpers: [1](#0-0) 
Compare `debugRoutes`, which wraps `/debug/vars` in `auth.Authenticate(...)`: [2](#0-1) 
and `sessionRoutes`, which wraps the session-destroy route in the same authenticator: [3](#0-2) 
against `loopRoutes`, which registers all four LOOP endpoints directly on the unauthenticated `api` group with no `auth.Authenticate` wrapper at all: [4](#0-3) 

The handlers themselves perform no credential check. `discoveryHandler` returns the full list of registered plugins with their metrics paths as JSON: [5](#0-4) 
`pluginMetricHandler` proxies to the plugin's internal `/metrics` endpoint and returns the body verbatim: [6](#0-5) 
`pluginPPROFHandler` proxies to the plugin's internal `/debug/pprof/<profile>` endpoint (including `heap`, `profile`, `goroutine`, etc., driven by attacker-supplied `gc.Param("profile")` and query parameters) and returns the raw response: [7](#0-6) 
The existing integration test even demonstrates the reachable path through `app.NewHTTPClient(nil)` — i.e., a plain unauthenticated HTTP client — hitting `/discovery` and `/plugins/<name>/metrics` and getting `200 OK` with data: [8](#0-7) 
No session-role wrapper, GraphQL-style auth, or any check on `gc.Request` occurs before these handlers execute, so any request reaching the node's HTTP listener — with zero cookie, API key, or token — is served.

### Impact Explanation
An unauthenticated attacker with network access to the node's HTTP port gets:
- Full enumeration of running LOOP plugins and their names via `/discovery`.
- Plugin Prometheus metrics via `/plugins/:name/metrics`, which can leak internal operational/state data.
- Full pprof profiles/heap dumps via `/plugins/:name/debug/pprof/*profile`, which can leak in-memory secrets, keys, or other sensitive runtime data captured in a heap/goroutine dump.

This matches Chainlink's bounty "information disclosure" class — sensitive internal operational data exposed without authentication.

### Likelihood Explanation
Preconditions are zero credentials: only network reachability to the node's configured HTTP port (`WebServer.HTTPPort`, default 6688) is needed. This requires no valid session, no API token, and no role. Feasibility is high and fully repeatable via a single `curl` or Go `net/http` GET request; the existing test suite already demonstrates a plain HTTP client reaching these routes successfully. The primary limiting factor is deployment-level network exposure of the node's API port, but the code itself provides no authentication layer as a defense-in-depth measure, unlike comparable routes (`/debug/vars`, session destroy) in the same router.

### Recommendation
Wrap the `loopRoutes` group in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or a dedicated internal/metrics-only auth mechanism, e.g. a bearer-token check similar to `prometheusHandler`'s token gate used for `/metrics`) before exposing `/discovery`, `/plugins/:name/metrics`, and the pprof endpoints, consistent with how `/debug/vars` and other sensitive routes are protected.

### Proof of Concept
Go handler-level integration test plan:
1. Build a test `chainlink.Application` with `NewLoopRegistryServer` wired in (reuse fixtures from `loop_registry_test.go`), and register a mock LOOP plugin via `app.GetLoopRegistry().Register(...)`.
2. Construct `router, _ := web.NewRouter(app, nil)` and wrap with `httptest.NewServer(router)`.
3. Using a raw `http.Client{}` (no cookie jar, no `Authorization` header set), issue:
   - `GET /discovery` — assert `200 OK` and that the response body JSON-unmarshals into `[]*targetgroup.Group` containing the registered plugin's metrics path label.
   - `GET /plugins/<name>/metrics` — assert `200 OK` and body contains plugin-exposed metric text.
   - `GET /plugins/<name>/debug/pprof/heap` — assert `200 OK` and a non-empty pprof-format body.
4. Assert none of the requests were redirected to a login page or returned `401`/`403`, confirming the absence of authentication enforcement.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
