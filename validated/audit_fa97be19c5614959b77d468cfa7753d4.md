### Title
Zip/cache/artifact extraction via `ziplegacy`/`archives.ExtractZipArchive` lacks path-traversal containment enforced by `tarzstd` - ([File: helpers/archives/zip_extract.go])

### Summary
`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`'s `extractor.Extract` delegates directly to `archives.ExtractZipArchive`, which writes each zip entry to `file.Name` with no check that the resolved path stays inside the extraction root. Since `openArchive` (used by both `CacheExtractorCommand.Execute` and `ArtifactsDownloaderCommand.Execute`) defaults to `archive.Zip` format unless the file's magic bytes match zstd/gzip, an attacker who controls the raw bytes of a cache or artifact zip file can guarantee the vulnerable `ziplegacy` path is used and traverse outside the intended working directory.

### Finding Description
The call chain is: `CacheExtractorCommand.Execute` / `ArtifactsDownloaderCommand.Execute` → `openArchive(c.File)` (`commands/helpers/artifacts_downloader.go:148-173`, mirrored in `cache_extractor.go:646`) → `archive.NewExtractor(format, f, size, wd)` → for `archive.Zip`, `ziplegacy.NewExtractor` → `extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32`) → `archives.ExtractZipArchive(zr)` (`helpers/archives/zip_extract.go:85-110`) → `extractZipFile(file)` → `extractZipFileEntry`/`extractZipSymlinkEntry`/`extractZipDirectoryEntry`, all of which call `os.OpenFile(file.Name, ...)`, `os.Symlink(data, file.Name)`, or `os.Mkdir(file.Name, ...)` directly using the attacker-supplied `zip.File.Name` with **no path validation** (no `filepath.Abs`, no `filepath.Rel`, no prefix/containment check). The only check present, `errorIfGitDirectory` (`helpers/archives/path_check_helper.go:21-31`), only rejects `.git` as the first path segment and does nothing to stop `../../etc/cron.d/x`-style traversal or symlink-based traversal.

Format selection in `openArchive` is driven purely by the first 4 bytes of the file: it defaults to `archive.Zip` unless the magic matches zstd (`archive.TarZstd`) or gzip (`archive.Gzip`, which has no registered extractor). An unprivileged pipeline author fully controls the bytes of an uploaded artifact or cache archive (`artifacts:paths`, `cache:paths` output, or a custom zip crafted and uploaded as a "cache"/"artifact"), so they can trivially produce a valid zip file (not matching the zstd magic) containing a malicious entry name like `../../../../home/gitlab-runner/.ssh/authorized_keys` or a directory-escaping symlink. When that cache/artifact is later restored (same job re-run, later stage, or a subsequent pipeline reusing the cache key on a shared runner), `openArchive` selects `archive.Zip`, `ziplegacy.NewExtractor` is used, and `ExtractZipArchive` writes the file wherever the entry name points, unconstrained by `wd`.

This differs materially from `tarzstd.extractor.Extract` (`commands/helpers/archive/tarzstd/tarzstd_extractor.go:57-64`), which explicitly resolves `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it unless `strings.HasPrefix(path, e.dir+string(filepath.Separator))`. The `fastzip` extractor (`commands/helpers/archive/fastzip/zip_fastzip_extractor.go`) delegates to the upstream `github.com/saracen/fastzip` library, which does perform path containment. Only `ziplegacy` is missing the check, and it is the *default* extractor for the `archive.Zip` format used whenever the uploaded archive isn't recognized as zstd/gzip — meaning the weaker path is reachable by default, not merely as a corner case.

### Impact Explanation
An unprivileged job can cause the runner host (or shared-runner worker filesystem, for executors that extract on the host such as shell/custom executors, or within the job container in the case of docker-based extraction helpers) to write attacker-controlled file contents to an arbitrary path outside the artifact/cache extraction root, limited only by the OS file permissions of the runner process. This can lead to overwriting files inside the build directory tree's parent, other jobs' workspaces sharing the same runner data root, or other files reachable by the runner user, depending on executor and directory layout — a classic "Zip Slip" file write primitive.

### Likelihood Explanation
High feasibility and full repeatability: the attacker is an ordinary pipeline author who only needs to (1) craft a zip archive with a `..`-traversal or symlink entry, (2) upload it as a `cache` or `artifacts` archive from a job (or otherwise get such bytes accepted where `CacheExtractorCommand`/`ArtifactsDownloaderCommand` will process them), and (3) trigger extraction (cache restore on a later job, or artifact download). No admin action or configuration flag change is required; the vulnerable code path (`archive.Zip` → `ziplegacy`) is the default when the uploaded bytes don't carry zstd/gzip magic bytes.

### Recommendation
Add the same containment check used in `tarzstd` (resolve `filepath.Abs`/`filepath.Join(dir, file.Name)` and verify `strings.HasPrefix(path, dir+string(filepath.Separator))` or `path == dir`) inside `archives.ExtractZipArchive`/`extractZipFile` (or thread the target `dir` through `ziplegacy.extractor.Extract` and validate before calling `extractZipFile`), and reject/skip entries with symlink targets that escape the target directory as well. Ensure all `archive.Extractor` implementations (`fastzip`, `tarzstd`, `ziplegacy`) share one common path-validation helper so the invariant "extraction stays within the root" is enforced uniformly regardless of which format is auto-selected by `openArchive`.

func openArchive(filename string) (*os.File, int64, archive.Format, error) {
	format := archive.Zip

	f, err := os.Open(filename)
	if err != nil {
		return nil, 0, format, err
	}

	var magic [4]byte
	_, _ = f.Read(magic[:])
	_, _ = f.Seek(0, io.SeekStart)
	switch {
	case bytes.HasPrefix(magic[:], zstMagic):
		format = archive.TarZstd
	case bytes.HasPrefix(magic[:], gzipMagic):
		format = archive.Gzip
	}

	fi, err := f.Stat()
	if err != nil {
		f.Close()
		return nil, 0, format, err
	}

	return f, fi.Size(), format, nil
}
