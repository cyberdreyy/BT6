### Title
Stale or carried-over Chainlink price used to compute junior-to-senior loss transfer at epoch stop - (File: contracts/strategies/usual/IdleUsualStrategy.sol)

### Summary
`IdleUsualStrategy.getChainlinkPrice()` validates the Chainlink USD0++ feed only with a 24h `updatedAt` freshness check. It does not verify that `answeredInRound >= roundId` (i.e., that the answer is not carried over from a previous round) and does not check `answer > 0`. The price is consumed in `IdleCDOUsualVariant.stopEpoch()` to size the NAV transfer from the junior (BB) tranche to the senior (AA) tranche so each senior token redeems at $1 parity. A stale-but-fresh-looking or invalid answer therefore corrupts the loss waterfall: juniors can be drained far beyond the real USD0++ discount (or seniors under-compensated), and a non-positive answer reverts `stopEpoch` and freezes all withdrawals permanently.

### Finding Description
`getChainlinkPrice` discards `roundId` and `answeredInRound`: [1](#0-0) 

The only guard is `updatedAt > block.timestamp - 24 hours`. Per Chainlink semantics, a round's `updatedAt` can be recent while the returned `answer` was carried over from an earlier round (when `answeredInRound < roundId`), so this check is insufficient — exactly the bug class in the reference report.

The corrupted price feeds directly into the loss waterfall in `stopEpoch`: [2](#0-1) 

`targetAATVL = lastNAVAA * oneToken / _oraclePrice` is hyperbolic in the price: the lower the reported price, the more junior NAV is credited to seniors via `lastNAVAA` inflation, and `_updateAccounting()` then socializes the "loss" onto BB holders through `_virtualPriceAux` (loss branch, lines 152–167).

There are two failure modes:
1. **Stale/incorrect low price** (`0 < answer < real price`, carried over from a pre-depeg round or a round with `answeredInRound < roundId`): `targetAATVL` is oversized, `lastNAVAA` is inflated, junior NAV is cut to compensate. If `newJuniorTVL <= 0` the BB tranche price is even set to 0 (line 164). Juniors redeem at a destroyed `virtualPrice`; seniors withdraw more than fair value → direct misallocation of pool funds.
2. **`answer <= 0`**: `uint256(answer)` reverts on negative values and `oneToken / 0` reverts on zero, so `stopEpoch` permanently reverts → `isEpochRunning` stays true, `allowAAWithdraw`/`allowBBWithdraw` stay false, and all user funds are frozen (deposits were already paused for the whole epoch).

Neither `getFloorPrice` (only applied in `setOraclePrice`, and the oracle price is passed through it but a 0/stale value below floor is clamped only for `oraclePrice` storage — note `stopEpoch` uses the raw `_oraclePrice` for `targetAATVL`, not the floored value) nor any other guard prevents this.

### Impact Explanation
Direct, quantifiable misallocation between tranches: with `lastNAVAA = N` and a reported price `p < real price r`, juniors lose `N * (1/p - 1/r)` USD0++ to seniors, up to the entire junior TVL (BB price → 0). If the feed ever returns a non-positive or carried-over zero answer, `stopEpoch` cannot execute and all deposited USD0++ is permanently frozen since withdrawals were disabled at `startEpoch`.

### Likelihood Explanation
Medium-low likelihood, high impact. Triggering requires the Chainlink feed to return carried-over/stale data or a ≤0 print at the single moment `stopEpoch` is called — not attacker-controllable, but the vault is disposable and runs exactly one ~6-month epoch, so there is only one settlement event and no retry/fallback path. The floor-price clamp exists in `setOraclePrice` but is bypassed for the `targetAATVL` computation, which uses the raw `_oraclePrice`.

### Recommendation
In `getChainlinkPrice` (contracts/strategies/usual/IdleUsualStrategy.sol:164-172) validate the full round tuple and answer sign:

```solidity
(uint80 roundId, int256 answer,, uint256 updatedAt, uint80 answeredInRound) =
    IOracle(USD0ppOracle).latestRoundData();
require(answer > 0, "Invalid price");
require(updatedAt > block.timestamp - 24 hours, "Stale price");
require(answeredInRound >= roundId, "Stale round");
```

Additionally, in `stopEpoch` use the floor-clamped value (the result of `setOraclePrice`/`oraclePrice`) rather than the raw `_oraclePrice` when computing `targetAATVL`, so the protocol's own depeg floor actually bounds the junior→senior transfer.

### Proof of Concept
Foundry fork test (mainnet, fork block after USD0++ oracle deployment). Mock the oracle to simulate a carried-over round:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDOUsualVariant} from "../contracts/IdleCDOUsualVariant.sol";
import {IdleUsualStrategy} from "../contracts/strategies/usual/IdleUsualStrategy.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract StaleOraclePoC is Test {
    IdleCDOUsualVariant cdo;
    IdleUsualStrategy strategy;

    address constant USD0ppOracle = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;
    address constant USD0pp = 0x35D8949372D46B7a3D5A56006AE77B215fc69bC0;

    function setUp() public {
        vm.createSelectFork("mainnet");
        // deploy cdo (IdleCDOUsualVariant) + strategy via factory/harness,
        // deposit USD0++ into AA and BB tranches as two test users,
        // owner calls cdo.startEpoch(180 days);
    }

    function testStaleCarriedOverPrice() public {
        vm.warp(cdo.epochEndDate() + 1);

        // Simulate a round whose answer is carried over (stale, e.g. deep-depeg print 0.50
        // while the real current market price recovered to 0.99) but updatedAt is fresh.
        uint80 fakeRound = 100;
        int256 staleAnswer = 0.5e8;           // stale carried-over value
        vm.mockCall(
            USD0ppOracle,
            abi.encodeWithSignature("latestRoundData()"),
            abi.encode(fakeRound, staleAnswer, block.timestamp, block.timestamp, fakeRound - 5)
            // answeredInRound < roundId => carried over; current code accepts it
        );

        vm.prank(cdo.owner());
        cdo.stopEpoch();

        // targetAATVL = lastNAVAA * 1e18 / 0.5e18 => doubles senior NAV,
        // wiping out junior TVL via _updateAccounting.
        uint256 bbPrice = cdo.virtualPrice(cdo.BBTranche());
        assertLt(bbPrice, 1e18); // juniors take catastrophic loss from a stale print
    }

    function testZeroAnswerFreezesEpoch() public {
        vm.warp(cdo.epochEndDate() + 1);
        vm.mockCall(
            USD0ppOracle,
            abi.encodeWithSignature("latestRoundData()"),
            abi.encode(uint80(1), int256(0), block.timestamp, block.timestamp, uint80(1))
        );
        vm.prank(cdo.owner());
        vm.expectRevert(); // division by zero at targetAATVL
        cdo.stopEpoch();
        // allowAAWithdraw/allowBBWithdraw remain false => user funds frozen
    }
}
```

Key observation for the PoC: since `stopEpoch` is owner-called and uses the feed value in the same transaction, the test demonstrates that a stale carried-over answer with a fresh `updatedAt` (or a 0/negative answer) is accepted/reverts, translating oracle staleness directly into tranche NAV misallocation or permanent fund freeze.
