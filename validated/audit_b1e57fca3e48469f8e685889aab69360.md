### Title
Division-before-multiplication in `jovian_da_footprint` truncates DA-footprint gas metering - ([File: crates/common/l1-fees/src/params.rs])

### Summary
`L1FeeParams::jovian_da_footprint` computes the FastLZ-estimated compressed size, divides it by `1_000_000` **before** multiplying by the DA-footprint gas scalar, discarding the sub-`1e6` remainder prior to scaling — the same division-before-multiplication ordering flagged in the external Ajna `_roundToScale` report.

### Finding Description
`tx_estimated_size_fjord` returns the FastLZ-estimated transaction size pre-scaled by `1e6` (fixed-point). `jovian_da_footprint` is documented as intending `estimatedSize * scalar / 1e6`, but the implementation instead divides first and multiplies second: [1](#0-0) 

Compare this to the correct multiply-then-divide ordering used consistently elsewhere in the very same file for `data_gas`, `calculate_tx_l1_cost_bedrock`, `calculate_tx_l1_cost_ecotone`, and `calculate_tx_l1_cost_fjord`, all of which perform `saturating_mul(...)` before `wrapping_div(...)`: [2](#0-1) [3](#0-2) 

`jovian_da_footprint` is the lone outlier that divides by `1_000_000` **first**, then multiplies by `scalar`, truncating up to `999_999` units of the fixed-point size before scaling — this loses precision proportional to the scalar value on essentially every transaction (any `tx_estimated_size_fjord(input)` not an exact multiple of `1e6`).

### Impact Explanation
This function feeds the Jovian DA-footprint gas value used for block-level DA/gas accounting (`da_footprint_gas_scalar`), consumed in `crates/common/evm/src/executor/block_executor.rs` and `crates/execution/flashblocks/src/state_builder.rs`. Per the analog rules, any effect confined purely to block-building resource/gas metering (no state corruption, no fund theft, no unbacked mint, no consensus-critical mismatch) falls under the "resource-only" analog category, which is explicitly excluded from valid findings. I was not able to fully trace, within the remaining budget, whether the truncated DA-footprint value also feeds into any consensus-critical derivation output (e.g., a value hashed into the block header, receipts, or used in fault-proof state-transition verification) as opposed to being purely a local resource-accounting/block-building input. That distinction is required to determine whether this rises above a resource-only rounding issue.

### Likelihood Explanation
Triggered on every Jovian-era transaction once `da_footprint_gas_scalar` is configured (100% of transactions after the Jovian upgrade activates with a scalar set), since `tx_estimated_size_fjord` almost never returns an exact multiple of `1_000_000`.

### Recommendation
Reorder to multiply before dividing, matching the sibling functions in the same file: `U256::from(tx_estimated_size_fjord(input)).saturating_mul(scalar).wrapping_div(U256::from(1_000_000u64))`.

### Proof of Concept
Given `tx_estimated_size_fjord(input) = 100_500_000` (fixed-point, i.e. 100.5 compressed bytes) and `scalar = 7`:
- Current (divide-then-multiply): `100_500_000 / 1_000_000 = 100` (the `.5` truncated) `* 7 = 700`.
- Correct (multiply-then-divide): `100_500_000 * 7 = 703_500_000`, `/ 1_000_000 = 703`.

The current code under-reports the DA footprint by `3` gas units per transaction in this example, with the error scaling proportionally to `scalar` for every transaction whose FastLZ size estimate is not an exact multiple of `1e6`.

**Caveat:** Because this affects only the Jovian DA-footprint gas metering path (a resource/gas-accounting computation rather than a fund-custody, consensus state-root, or output-root computation as far as I could confirm), I am not fully confident this clears the "no resource-only" exclusion bar in the validation rules. If a Devin session can confirm `jovian_da_footprint`'s output is folded into a consensus-critical value (e.g., block header field, receipt field consumed by the fault-proof program, or gas charged/refunded from user balances) rather than purely a builder-side block-size/gas-limit check, this would elevate to a valid Medium/High finding under the given rules.

    /// Calculates the L1 calldata gas for posting `input`, per the schedule at `upgrade`.
    ///
    /// Post-Fjord uses the FastLZ-estimated compressed size; earlier forks count
    /// EIP-2028 calldata tokens, with pre-Regolith adding 68 signature bytes.
    pub fn data_gas(input: &[u8], upgrade: BaseUpgrade) -> U256 {
        if Self::is_enabled(upgrade, BaseUpgrade::Fjord) {
            let estimated_size = U256::from(tx_estimated_size_fjord(input));
            return estimated_size
                .saturating_mul(U256::from(NON_ZERO_BYTE_COST))
                .wrapping_div(U256::from(1_000_000u64));
        }

        let mut tokens = input.iter().fold(0u64, |acc, &byte| {
            acc + if byte == 0 { 1 } else { NON_ZERO_BYTE_MULTIPLIER_ISTANBUL }
        });
        if !Self::is_enabled(upgrade, BaseUpgrade::Regolith) {
            tokens += PRE_REGOLITH_SIGNATURE_BYTES * NON_ZERO_BYTE_MULTIPLIER_ISTANBUL;
        }
        U256::from(tokens.saturating_mul(STANDARD_TOKEN_COST))
    }

    /// Calculates the Jovian DA-footprint gas for posting the enveloped transaction bytes `input`.
    ///
    /// The footprint is the FastLZ-estimated compressed size (scaled by `1e6`, as
    /// [`tx_estimated_size_fjord`] returns) divided back down by `1e6` and multiplied by the
    /// DA-footprint gas scalar. Returns zero when no scalar is set (pre-Jovian or unconfigured).
    /// Mirrors the reference `jovian_da_footprint_estimation`.
    pub fn jovian_da_footprint(&self, input: &[u8]) -> u64 {
        let Some(scalar) = self.da_footprint_gas_scalar else {
            return 0;
        };
        U256::from(tx_estimated_size_fjord(input))
            .wrapping_div(U256::from(1_000_000u64))
            .saturating_mul(scalar)
            .saturating_to::<u64>()
    }

    /// Pre-Ecotone (Bedrock) L1 cost. Deposit and empty transactions are fee-exempt.
    pub fn calculate_tx_l1_cost_bedrock(&self, input: &[u8], upgrade: BaseUpgrade) -> U256 {
        if Self::is_fee_exempt(input) {
            return U256::ZERO;
        }
        Self::data_gas(input, upgrade)
            .saturating_add(self.l1_fee_overhead.unwrap_or_default())
            .saturating_mul(self.l1_base_fee)
            .saturating_mul(self.l1_base_fee_scalar)
            .wrapping_div(U256::from(1_000_000u64))
    }

    /// Post-Ecotone L1 cost:
    /// `calldataGas * (l1BaseFee*16*l1BaseFeeScalar + l1BlobBaseFee*l1BlobBaseFeeScalar) / 16e6`.
    pub fn calculate_tx_l1_cost_ecotone(&self, input: &[u8], upgrade: BaseUpgrade) -> U256 {
        if Self::is_fee_exempt(input) {
            return U256::ZERO;
        }
        // The very first Ecotone block (unless activated at genesis) still prices
        // using the Bedrock function, detected via unset Ecotone scalars.
        if self.empty_ecotone_scalars {
            return self.calculate_tx_l1_cost_bedrock(input, upgrade);
        }
        let rollup_data_gas_cost = Self::data_gas(input, upgrade);
        self.calculate_l1_fee_scaled_ecotone()
            .saturating_mul(rollup_data_gas_cost)
            .wrapping_div(U256::from(1_000_000u64 * NON_ZERO_BYTE_COST))
    }

    /// Post-Fjord L1 cost:
    /// `estimatedSize * (baseFeeScalar*l1BaseFee*16 + blobFeeScalar*l1BlobBaseFee) / 1e12`.
    pub fn calculate_tx_l1_cost_fjord(&self, input: &[u8]) -> U256 {
        if Self::is_fee_exempt(input) {
            return U256::ZERO;
        }
        let l1_fee_scaled = self.calculate_l1_fee_scaled_ecotone();
        if l1_fee_scaled.is_zero() {
            return U256::ZERO;
        }
        U256::from(tx_estimated_size_fjord(input))
            .saturating_mul(l1_fee_scaled)
            .wrapping_div(U256::from(1_000_000_000_000u64))
    }
