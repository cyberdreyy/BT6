### Title
`getTokenAccountBalance` computes UI amount using decimals from an unverified "mint" account whose ownership is never checked - ([File: rpc/src/rpc.rs] / [File: rpc/src/parsed_token_accounts.rs])

### Summary
The RPC handler for `getTokenAccountBalance` trusts the `mint` field embedded in an untrusted token account's raw data and fetches "mint" metadata (decimals, interest-bearing/scaled-UI config) from whatever account sits at that address — without ever confirming that account is actually owned by a legitimate SPL Token/Token-2022 program. This mirrors the reported class of bug: consuming data from an address without validating it is the expected kind of "contract" (here, a program-owned mint account) before trusting its content.

### Finding Description
`get_token_account_balance` in [1](#0-0)  validates that the *token account* itself is owned by a known SPL token program:

```rust
if !is_known_spl_token_id(account.owner()) {
    return Err(Error::invalid_params("Invalid param: not a Token account".to_string()));
}
let token_account = StateWithExtensions::<TokenAccount>::unpack(account.data())...;
let mint = &Pubkey::from_str(&token_account.base.mint.to_string())...;
let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
```

However, the `mint` pubkey used afterward comes directly from the token account's own data (`token_account.base.mint`), a field that is entirely attacker-controlled — anyone can create a genuine SPL token account (owned by the real token program, so it passes the check above) whose `mint` field points to an arbitrary pubkey.

That pubkey is then resolved via `get_mint_owner_and_additional_data`, defined in [2](#0-1) :

```rust
pub(crate) fn get_mint_owner_and_additional_data(bank: &Bank, mint: &Pubkey) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        ...
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(...)?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}
```

`get_additional_mint_data` (same file, lines 110-130) merely calls `StateWithExtensions::<Mint>::unpack(data)` — a pure byte-layout parse that succeeds for *any* account whose data happens to match the `Mint` struct layout, regardless of which program owns it. Critically, back in `get_token_account_balance`, the returned owner is discarded (`let (_, data) = ...`) and `is_known_spl_token_id` is **never** applied to it — unlike the sibling function `get_token_largest_accounts`, which does perform this check on the value returned from the same helper ( [3](#0-2) ).

As a result, an attacker can:
1. Deploy/own a program that owns an account containing 82+ bytes crafted to successfully decode as a `Mint` (arbitrary `decimals`, bogus `interest_bearing_config`/`scaled_ui_amount_config` extension state if desired).
2. Create a legitimate SPL token account (owned by the real token program) whose `mint` field points at that fake "mint" account.
3. Call `getTokenAccountBalance` on that token account.

The RPC node will then use the attacker-chosen `decimals` (and any interest-bearing/scaled-UI config) to compute `ui_amount`/`ui_amount_string`, without ever verifying the "mint" is a legitimate mint. This is directly analogous to the reported issue of trusting a low-level interaction with an address without confirming it is the expected contract/program.

### Impact Explanation
Any unprivileged caller of the public `getTokenAccountBalance` JSON-RPC method can obtain silently misreported balance data (wrong decimals, wrong scaling) for accounts they control, with a single low-rate call and no elevated privileges — falling under "decoder panic and misreporting" / "wrong ... account data returned" from a query.

### Likelihood Explanation
Likelihood is high for a self-serve display attack (crafting a program-owned pseudo-mint account is easy and requires only ordinary transaction privileges, no validator/operator role), though the blast radius is limited to whichever caller queries this specific attacker-crafted account (it does not corrupt consensus-critical state).

### Recommendation
In `get_token_account_balance` (and anywhere else `get_mint_owner_and_additional_data`'s returned owner is discarded), validate that the returned mint-account owner satisfies `is_known_spl_token_id` before using its decimals/extension data, mirroring the check already performed in `get_token_supply` and `get_token_largest_accounts`.

### Proof of Concept
1. Deploy a small on-chain program that owns an account and writes 82+ bytes into it matching the `spl_token::state::Mint` packed layout, with `decimals` set to an arbitrary attacker-chosen value (e.g. 0 instead of the real 9) and `is_initialized = true`.
2. Create a genuine SPL Token account (owned by `spl_token::id()`), initializing its `mint` field to the pubkey of the fake account from step 1, with some `amount`.
3. Call `getTokenAccountBalance` with the pubkey of the token account from step 2.
4. Observe that `ui_amount`/`ui_amount_string`/`decimals` in the response are computed using the attacker-controlled fake mint's `decimals`/extension config, not from a validated SPL mint account — confirming the account-owner check is bypassed, matching the pattern in [4](#0-3) .

    pub fn get_token_account_balance(
        &self,
        pubkey: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let account = bank.get_account(pubkey).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;

        if !is_known_spl_token_id(account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token account".to_string(),
            ));

        let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
        Ok(new_response(&bank, balance))
    }

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}
