### Title
Inconsistent rounding between `GlobalStateEvaluator::reached_agreement` (floor) and `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling) causes the signer's global-state consensus to be reached below the true 70% supermajority - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The signer's `GlobalStateEvaluator` decides whether a global state-machine value (protocol version, burn view, active miner/tenure, tx replay set) has reached "agreement" using a **floor** division of the 70% supermajority threshold, while the canonical on-chain/consensus threshold used everywhere else for block approval and pre-commit/rejection tallying (`NakamotoBlockHeader::compute_voting_weight_threshold`) uses a **ceiling** division of the same threshold. This is the same bug class as the reported VotingEscrow issue: the same conceptual quantity ("has X% of weight been reached") is computed with two different rounding rules in two different code paths, breaking the intended equality between "aggregated weight" and "verified/consensus-required weight."

### Finding Description
`libsigner/src/v0/signer_state.rs`:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
``` [1](#0-0) 

This performs integer floor division: `threshold = floor(total_weight * 7 / 10)`, and agreement is `vote_weight >= threshold`.

Compare this to the canonical block-approval threshold used by the chain and by the signer's own pre-commit/rejection tallying logic:

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
``` [2](#0-1) 

This is a strict **ceiling**: `threshold = ceil(total_weight * 7 / 10)`.

Whenever `total_weight * 7` is not a multiple of 10 (i.e. whenever `total_weight` is not a multiple of 10), `floor(0.7*total_weight) < ceil(0.7*total_weight)` by exactly 1. For example, with `total_weight = 11`: `compute_voting_weight_threshold` requires `8`, but `reached_agreement(7)` returns `true`. This is used throughout `GlobalStateEvaluator` (`determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, `determine_global_state`, `find_majority_prefix_replay_set`), all called from the signer's global-state code paths: [3](#0-2) [4](#0-3) 

The `GlobalStateEvaluator`'s `determine_global_state` output feeds directly into `GlobalStateView`, which is used to accept/reject block proposals via `check_proposal`, matching the miner/tenure the signer will sign against: [5](#0-4) 

Meanwhile, the actual chain-consensus block-signature threshold (`verify_signer_signatures`) and the signer's own pre-commit threshold (`handle_block_pre_commit`) and rejection threshold (`store_and_process_block_rejection`) all use the ceiling-rounded `compute_voting_weight_threshold`: [6](#0-5) [7](#0-6) 

So the two "70% supermajority reached" checks used across the codebase disagree by up to 1 unit of weight whenever `total_weight` is not divisible by 10 — the state-machine agreement path (floor) is strictly *weaker* than the block-approval path (ceiling).

### Impact Explanation
`reached_agreement` under-counts the true supermajority requirement by up to 1 weight unit whenever `total_weight % 10 != 0`. Because `determine_global_state()` output becomes the signer's authoritative view of the current miner/tenure (`GlobalStateView::check_proposal`, `SortitionState::is_timed_out`/`check_miner_inactivity` in `stacks-signer/src/v0/signer_state.rs`), a set of signers whose combined weight equals `floor(0.7*total_weight)` — which is below the actual `ceil(0.7*total_weight)` supermajority the network requires for block approval — will cause every signer's `GlobalStateEvaluator` to converge on a "globally agreed" miner/tenure/burn-view/protocol-version state that was never actually approved by a true 70% supermajority. Signers then evaluate and sign block proposals against this under-approved consensus view. This is a High-impact class per the rules: the signer's threshold/aggregated-weight equality diverges from the verified-accepts equality used for actual block approval, i.e. a signer can act on (and sign against) a state that a genuine supermajority never approved.

This does not require a majority of signers to be malicious — it is a deterministic arithmetic discrepancy that manifests for any `total_weight` not a multiple of 10 (the common case, since signer weight is derived from stacked amounts and is essentially never round to exactly a multiple of 10). No attacker collusion, key compromise, or majority control is needed; it is inherent in the weight distribution crossing this off-by-one boundary.

### Likelihood Explanation
High. `total_weight` being a multiple of 10 is a coincidence, not something enforced by the protocol; in practice almost every reward cycle's `total_weight` will not be exactly divisible by 10, so this rounding mismatch is present in essentially every reward cycle. The bug is triggered passively, simply by normal signer gossip (`StateMachineUpdate` messages over StackerDB) reaching the floor-rounded boundary weight — no special crafted proposal is needed, only ordinary operation with a weight distribution landing on the off-by-one boundary.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` consistent with `NakamotoBlockHeader::compute_voting_weight_threshold` by using the same ceiling-rounding rule for the 70% supermajority (and the corresponding floor rule for the complementary 30% blocking minority), e.g.:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total = u64::from(self.total_weight);
    let num = total.strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD);
    let threshold = num.div_ceil(10); // ceiling, matching compute_voting_weight_threshold
    u64::from(vote_weight) >= threshold
}
```

Ideally, factor out a single shared threshold-computation function used by both `stackslib`'s `compute_voting_weight_threshold` and `libsigner`'s `GlobalStateEvaluator`, so that any future changes to the supermajority constant or rounding rule cannot diverge again.

### Proof of Concept
1. Configure (or naturally have) a reward cycle where the sum of signer weights `total_weight = 11` (e.g., signers with weights `[4,4,3]` summing to 11 — any non-multiple-of-10 total works).
2. `NakamotoBlockHeader::compute_voting_weight_threshold(11)` returns `8` (the real, consensus-required 70% supermajority), confirmed by the existing regression test `test_compute_voting_weight_threshold` pattern (e.g. `compute_voting_weight_threshold(511) == 358`, a ceiling result) at [8](#0-7) .
3. Build a `GlobalStateEvaluator` with `total_weight = 11` and have a subset of signers whose weight sums to `7` (e.g. `[4,3]`) send identical `StateMachineUpdate`s (identical `MinerState`, `burn_block`, `active_signer_protocol_version`).
4. Call `evaluator.reached_agreement(7)` — it returns `true` (since `floor(11*7/10) = 7`), and `determine_global_state()` returns this `SignerStateMachine` as the agreed global state, even though only `7/11 ≈ 63.6%` of weight supports it, below the `8/11 ≈ 72.7%` the chain would actually require to approve a block signed under this same threshold constant.
5. Every honest signer that receives these same 7 units of weighted updates converges on this state via `GlobalStateView::check_proposal`, and will validate/sign block proposals against a miner/tenure view that was never actually approved by the true on-chain 70% threshold — demonstrating the aggregated-weight/verified-accepts inconsistency.

        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view

        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
