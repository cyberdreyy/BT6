## Title
Unbounded recursion in MPT trie-node decoding and traversal enables stack-overflow DoS of the fault-proof program via a crafted preimage - (File: `crates/proof/mpt/src/node.rs`, `crates/proof/mpt/src/list_walker.rs`)

### Summary
`TrieNode::decode` and `OrderedListWalker::fetch_leaves` in `base-proof-mpt` recursively descend into nested trie-node structures with no depth limit. Both are reachable from the fault-proof program (`OracleL1ChainProvider` and `OracleL2ChainProvider`) when deriving the L1/L2 transactions and receipts lists during dispute-game trace execution, using preimage data an adversarial party ultimately controls. A crafted preimage containing deeply nested inline (non-hash-blinded) branch/extension nodes can drive unbounded native-stack recursion and crash the executing process, exactly analogous to CVE-2016-9439's infinite-recursion DoS in a recursive-descent parser.

### Finding Description
`TrieNode::decode` (`crates/proof/mpt/src/node.rs:567-604`) parses RLP list headers and, for a 17-element list, calls `Vec::<Self>::decode(buf)`, which itself recursively invokes `TrieNode::decode` for every child element: [1](#0-0) 

Per the standard Ethereum MPT node encoding, a branch/extension child needs to be hash-blinded only if its own RLP encoding exceeds 32 bytes; smaller children may be embedded inline directly in the parent's RLP payload. That means a single preimage blob can encode an arbitrarily deep chain of inline `Branch`/`Extension` nodes (each just a few bytes), all decoded in one recursive call chain, with no depth check anywhere in the decoder.

`OrderedListWalker::fetch_leaves` (`crates/proof/mpt/src/list_walker.rs:86-129`) then walks the resulting in-memory tree with the same unbounded recursion pattern, recursing once per `Branch` child and once per `Extension`: [2](#0-1) 

This code path is reached by the fault-proof program itself. `OracleL1ChainProvider::receipts_by_hash` and `block_info_and_transactions_by_hash` (`crates/proof/proof/src/l1/chain_provider.rs:68-122`) call `OrderedListWalker::try_new_hydrated` against `header.receipts_root` / `header.transactions_root`, using `TrieNode::decode` on preimages fetched from the oracle: [3](#0-2) 

The equivalent L2 path exists in `OracleL2ChainProvider::block_by_number` (`crates/proof/proof/src/l2/chain_provider.rs:115-152`), also via `OrderedListWalker` and the same `TrieNode::decode`: [4](#0-3) 

The oracle only guarantees that a fetched preimage hashes to the requested key; it does not constrain the internal shape/nesting of that preimage's RLP content. A dispute-game participant supplying preimages (or an L1 block producer/batcher crafting the underlying transactions/receipts data that the program later re-derives) can therefore construct a single node preimage containing thousands of nested inline branch/extension nodes, which is a valid RLP blob but forces thousands of recursive stack frames in both `TrieNode::decode` and `fetch_leaves` when the fault-proof program processes it.

### Impact Explanation
The fault-proof program is the component that computes/validates the L2 output root claimed in a dispute game. If a crafted preimage causes it to blow its native call stack, the executing process crashes instead of producing a claim, which:
- Prevents an honest defender/challenger from completing execution of the fault-proof program for that dispute, effectively halting resolution of the game.
- Can be used to force computation of an incorrect/incomplete result if the crash is not uniformly deterministic across implementations (violating the fault-proof requirement of consistent, well-defined execution).

This satisfies the "node halt" / "wrong provable output root" impact classes for Medium severity.

### Likelihood Explanation
Exploitation requires only the ability to supply/derive L1 or L2 block data (transactions/receipts) whose corresponding trie preimages the fault-proof program will later fetch and decode — reachable by any party who can get such data included in the chain history the program traverses (e.g., a malicious L1 block or a party controlling preimages fed into the oracle for a dispute). No special privileges beyond normal transaction/block inclusion are needed, and the RLP encoding trick (deeply nested small inline nodes) requires no cryptographic break, only encoding effort.

### Recommendation
Add an explicit recursion/depth bound to both `TrieNode::decode` (`crates/proof/mpt/src/node.rs`) and `OrderedListWalker::fetch_leaves` (`crates/proof/mpt/src/list_walker.rs`), rejecting nodes/traversals beyond the maximum theoretically valid MPT depth (bounded by key length, e.g. 64 nibbles for 32-byte keys), or convert the traversal to an explicit iterative work-stack rather than native recursion to avoid stack-based DoS regardless of nesting depth.

### Proof of Concept
1. Construct an RLP blob representing a `TrieNode::Branch` (17-element list) whose first slot is itself an inline (non-blinded, <32-byte) `TrieNode::Extension`/`TrieNode::Branch`, and repeat this nesting thousands of times within a single buffer (each level adds only a few bytes, so a compact blob can encode very deep nesting).
2. Store this blob as a preimage under its own `keccak256` hash so it passes the oracle's preimage-integrity check.
3. Reference this hash as (or reachable from) a block's `transactions_root`/`receipts_root` that `OracleL1ChainProvider`/`OracleL2ChainProvider` will fetch during fault-proof program execution.
4. When `OrderedListWalker::try_new_hydrated` → `fetch_leaves` and the underlying `TrieNode::decode` process this preimage, the recursive calls grow the native stack proportionally to the nesting depth, crashing the process with a stack overflow before it can produce a valid claim.

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
