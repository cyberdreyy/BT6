### Title
Unrestricted `receive()` in `BaseVault` allows anyone to send ETH into the vault with no shares/units minted and no automatic refund - ([File: v3/src/core/BaseVault.sol])

### Summary
`BaseVault` (inherited by `MultiDepositorVault` / `SingleDepositorVault` via `FeeVault`) declares `receive() external payable { }` with no sender restriction, unlike `AeraVaultV2`, whose `receive()` explicitly reverts unless `msg.sender == wrappedNativeToken`. A user who sends ETH directly to a v3 vault address (instead of depositing through `ProvisionerV2.deposit`/`mint`, which only accept ERC20 `token` parameters) gets no vault units minted and has no self-service way to reclaim the ETH.

### Finding Description
`BaseVault.receive()` at [1](#0-0)  accepts ETH unconditionally from any caller. This mirrors the exact root cause in the external report: an always-open `receive()` that silently swallows ETH without triggering any minting logic. `ProvisionerV2.deposit`/`mint`, the only user-facing entry points that mint vault units, take an `IERC20 token` argument and route funds through `_syncDeposit`/`_tokensToUnitsFloorIfActive` [2](#0-1)  - there is no payable/ETH-accepting path in `ProvisionerV2` that would credit units for value sent as native ETH. Contrast this with `AeraVaultV2.receive()`, which is deliberately guarded: it reverts unless the caller is the wrapped native token contract itself, so an ordinary user's direct ETH transfer to a v2 vault reverts and their ETH is never captured [3](#0-2) . The v3 `BaseVault.receive()` has no such guard.

The only recovery path is `Sweepable.sweep(address(0), amount)`, which is `requiresAuth`-gated and sends the native token to `msg.sender` (the authorized sweeper/owner), not automatically back to the original depositor [4](#0-3) . This differs from the pure loss in the UXDController report only in that a privileged party could manually intervene, but the ordinary user has no way to reclaim funds themselves and no units/shares are minted to them, which is the exact broken invariant asserted in the analog report.

### Impact Explanation
An ordinary user who mistakenly sends ETH directly to a v3 `MultiDepositorVault`/`SingleDepositorVault` address loses that ETH from their own perspective: no vault units are minted, and they cannot withdraw or reclaim it themselves. The ETH becomes trapped in the vault, recoverable only at the discretion of an authorized role via `sweep`, which is not automatic and not guaranteed to return funds to the original sender. This constitutes a freezing/loss-of-user-funds scenario comparable in kind to the original UXDController finding.

### Likelihood Explanation
No privileged role or third party action is required — the flaw is triggered purely by an ordinary user directly sending ETH to the vault address (e.g., via wallet UI misconfiguration, copy-paste error, or misunderstanding that native ETH is accepted as a deposit asset). This requires zero preconditions beyond the vault being deployed and having a positive ETH balance capability, which it inherently does since `receive()` is unguarded.

### Recommendation
Restrict `BaseVault.receive()` similarly to `AeraVaultV2.receive()` — only accept ETH from the wrapped native token contract (or from within `_executeSubmit` operations that legitimately unwrap WETH), and `revert` for any other caller. Alternatively, document prominently that direct ETH transfers are unsupported and will require manual intervention via `sweep`, and/or emit an event so off-chain monitoring can detect and return misdirected funds.

### Proof of Concept
1. Deploy a `MultiDepositorVault` (or `SingleDepositorVault`) via the v3 factory with any valid `BaseVaultParameters`.
2. From an unrelated EOA (`alice`), call `alice.call{value: 1 ether}("")` against the vault address.
3. Assert the call succeeds (`receive()` has no guard, so it does not revert).
4. Assert `alice`'s vault-unit balance (`ERC20(vault).balanceOf(alice)`) is unchanged (`0` before and after).
5. Assert `address(vault).balance` increased by `1 ether`, confirming the ETH is now held by the vault with no unit minted to `alice` and no automatic mechanism for `alice` to retrieve it — matching the exact PoC pattern from the analog report but on `BaseVault.receive()` [1](#0-0) .

    /// @inheritdoc ISweepable
    function sweep(address token, uint256 amount) external requiresAuth {
        if (token == address(0)) {
            // Interactions: send the native token to the owner
            (bool success,) = msg.sender.call{ value: amount }("");
            // Requirements: check that the execution was successful
            require(success, Aera__FailedToSendNativeToken());
        } else {
            // Interactions: transfer the token to the owner
            IERC20(token).safeTransfer(msg.sender, amount);
        }

        // Log the sweep event
        emit Sweep(token, amount);
    }
