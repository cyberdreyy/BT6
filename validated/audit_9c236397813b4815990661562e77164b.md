### Title
GET /v2/bridge_types/:BridgeName exposes bridge OutgoingToken to any authenticated (view-role) user - ([File: core/web/router.go])

### Summary
The route `GET /v2/bridge_types/:BridgeName` is registered without any role check (only session/token authentication), while sibling mutating routes (`PATCH`, `DELETE`, `POST`) correctly require `auth.RequiresEditRole`. `BridgeTypesController.Show` returns a `presenters.BridgeResource` whose `OutgoingToken` field is serialized unconditionally, so any authenticated view-role user can retrieve the bridge's outgoing token.

### Finding Description
In `v2Routes`, the bridge_types routes are defined as: [1](#0-0) 
Note that `GET /bridge_types/:BridgeName` (`bt.Show`) has no `auth.RequiresEditRole`/`RequiresAdminRole` wrapper, unlike `POST`, `PATCH`, and `DELETE` on the same resource. It only inherits the outer `authv2` group's generic authentication middleware (`AuthenticateByToken`/`AuthenticateBySession`), which accepts any valid session regardless of role, including a view-role user.

`BridgeTypesController.Show` fetches the bridge and serializes it via `presenters.NewBridgeResource`: [2](#0-1) 

`BridgeResource` includes `OutgoingToken` with no `omitempty`/redaction, populated directly from the stored plaintext bridge secret: [3](#0-2) 

`BridgeType.OutgoingToken` is stored and used as plaintext (unlike `IncomingTokenHash`, which is hashed), confirmed at bridge creation: [4](#0-3) 

Because `Show` has no role gate, a low-privileged view-role user authenticated via a valid session/API token can call `GET /v2/bridge_types/:BridgeName` and receive the bridge's `outgoingToken` in the JSON response, which is meant to be a secret used by the node to authenticate outbound bridge webhook callbacks.

### Impact Explanation
This is a credential/secret disclosure to a low-privileged (view-role) authenticated user: exposure of `OutgoingToken`, which the external bridge adapter uses to authenticate callback requests. Impact class: node key/secret disclosure — a view-role user could impersonate the node's outbound bridge callback authentication, potentially forging job-run completion callbacks to bridges that trust the outgoing token, or leaking the value to a further attacker.

### Likelihood Explanation
Minimal precondition: attacker only needs a valid but low-privileged (view) session or API token — no edit/admin role, no operator/host access. The request is a single unauthenticated-role-check `GET` and is fully repeatable for every bridge configured on the node, with no rate limiting beyond the generic authenticated rate limiter.

### Recommendation
Wrap `GET /v2/bridge_types/:BridgeName` with `auth.RequiresEditRole` (or at minimum ensure `BridgeResource`/`Show` omits `OutgoingToken` for non-edit roles), consistent with the other mutating bridge routes, and consider omitting `OutgoingToken` from `Show`/`Index` responses entirely (analogous to how `IncomingToken` is only returned on `Create`).

### Proof of Concept
Go handler-level integration test plan:
1. Use `cltest.NewApplication(t)` and create a bridge via `app.BridgeORM().CreateBridgeType` with a known `OutgoingToken`.
2. Create an HTTP client scoped to a view-role user session/token (e.g., via `app.NewHTTPClient(&cltest.UserView)` or equivalent helper used in `bridge_types_controller_test.go`).
3. Call `client.Get("/v2/bridge_types/" + bt.Name.String())`.
4. Assert `resp.StatusCode == http.StatusOK` (proving the view-role user is not blocked).
5. Parse the JSON-API response into `presenters.BridgeResource` and assert `resource.OutgoingToken == bt.OutgoingToken`, demonstrating the secret token is returned to a view-role user — expected behavior should instead be a `403 Forbidden` or a redacted token field.

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
