### Title
View-role users can retrieve raw signed transaction hex for all node keys/chains via unrestricted `/v2/transactions` and `/v2/tx_attempts` routes - ([File: core/web/router.go])

### Summary
The `authv2.GET("/transactions", ...)`, `/transactions/:TxHash`, `/transactions/evm`, `/transactions/evm/:TxHash`, `/tx_attempts`, and `/tx_attempts/evm` routes are registered without any `auth.RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrapper, unlike nearly every other sensitive route in `v2Routes`. Since Chainlink has no per-user tx ownership scoping, any authenticated `UserRoleView` session or API token can call `TransactionsController.Index`/`Show` or `TxAttemptsController.Index` and receive `presenters.EthTxResource`, which embeds `Hex` (JSON field `rawHex`) populated directly from `txa.SignedRawTx` — the complete raw signed Ethereum transaction across all keys/chains on the node.

### Finding Description
In `core/web/router.go`, the transaction routes are mounted under `authv2` (session/token authenticated) but with no role-elevation middleware:
```go
tas := TxAttemptsController{app}
authv2.GET("/tx_attempts", paginatedRequest(tas.Index))
authv2.GET("/tx_attempts/evm", paginatedRequest(tas.Index))

txs := TransactionsController{app}
authv2.GET("/transactions/evm", paginatedRequest(txs.Index))
authv2.GET("/transactions/evm/:TxHash", txs.Show)
authv2.GET("/transactions", paginatedRequest(txs.Index))
authv2.GET("/transactions/:TxHash", txs.Show)
```
Compare this to nearby routes for external initiators, bridges, transfers, and replay operations, all of which are wrapped in `auth.RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole`. `TransactionsController.Index`/`Show` (`core/web/evm_transactions_controller.go`) and `TxAttemptsController.Index` (`core/web/evm_tx_attempts_controller.go`) call `tc.App.TxmStorageService()` unconditionally across the whole node's tx store (no chain/key/user filter), and build responses with `presenters.NewEthTxResourceFromAttempt`. That presenter sets `r.Hex = hexutil.Encode(txa.SignedRawTx)`, exposing the full raw signed transaction bytes (`rawHex` JSON field) alongside gas price, nonce, sender/recipient, and chain ID for every transaction ever sent by any of the node's keys. Because `auth.RequiresRunRole` only blocks `UserRoleView`, and these routes apply no role check at all, a plain `UserRoleView` session/token is sufficient to reach them.

### Impact Explanation
This maps to a credential/secret exposure impact: raw signed transactions can be rebroadcast (replay) if not yet mined, or reveal exact historical calldata/nonce/fee patterns that lower-privileged operators should not see. This corresponds to Chainlink's "unauthorized information disclosure to a low-privileged role" class rather than direct fund loss, but is a genuine authorization-boundary bug since it breaks the intended privilege separation between `view`, `run`, `edit`, and `admin` roles.

### Likelihood Explanation
Trivial and fully reproducible: any node operator who provisions a `UserRoleView` account (a common practice for read-only dashboards/monitoring) or issues a view-scoped API token can call `GET /v2/transactions` or `GET /v2/tx_attempts` with no additional privilege, and the JSON response for every entry includes `rawHex`. No timing race, no misconfiguration required beyond the existence of a view-role credential, which is an intended, supported role in the system.

### Recommendation
Wrap these routes with at least `auth.RequiresEditRole` (or a dedicated role) consistent with other sensitive endpoints, and/or strip `Hex`/`SignedRawTx` from the presenter output returned to non-privileged callers (e.g., only include `rawHex` for `edit`/`admin` roles, or remove it from the JSON API resource entirely since `Hash`/`State`/`GasPrice`/`Nonce` are sufficient for monitoring use cases).

### Proof of Concept
Go handler-level integration test plan (extending `core/web/evm_transactions_controller_test.go`):
1. Start `cltest.NewApplicationWithKey(t)`, insert a confirmed tx with a legacy attempt via `txmgrtest.MustInsertConfirmedEthTxWithLegacyAttempt`.
2. Create an HTTP client authenticated as a `UserRoleView` user/token (see existing helpers in `core/internal/cltest` for role-scoped sessions, similar to tests in `core/web/auth/auth_test.go`).
3. `GET /v2/transactions` and `GET /v2/tx_attempts` with that view-role client; assert `http.StatusOK` (demonstrating no role check blocks it, unlike e.g. `POST /v2/replay_from_block/:number` which returns 401 for view role).
4. Parse the response into `[]presenters.EthTxResource` and assert `txs[0].Hex` equals `hexutil.Encode(attempt.SignedRawTx)`, proving the raw signed tx bytes are disclosed to a view-role caller.
5. As the fix validation, add an assertion that view-role responses either 401/403 or omit the `rawHex` field.
