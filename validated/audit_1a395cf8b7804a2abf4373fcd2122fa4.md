### Title
Pre-authorization workflow-existence oracle in `resolveWorkflowID` allows enumeration of private workflow owner/name/tag combinations - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`HandleUserTriggerRequest` calls `resolveWorkflowID` (which internally calls `WorkflowMetadataHandler.GetWorkflowID`) before calling `authorizeRequest`. The two failure paths return distinguishable error messages ("Workflow not found..." vs "Auth failure: ..."), letting an unauthenticated caller determine whether a guessed `(workflowOwner, workflowName, workflowTag)` triple corresponds to a real, registered workflow without ever presenting a valid signature.

### Finding Description
In `HandleUserTriggerRequest` [1](#0-0) , `resolveWorkflowID` is invoked before `authorizeRequest`. `resolveWorkflowID` normalizes `workflowOwner` (public on-chain address) and hashes `workflowName`, then calls `WorkflowMetadataHandler.GetWorkflowID(workflowOwner, workflowName, workflowTag)` [2](#0-1) , which does a pure in-memory map lookup with no ownership/authorization check [3](#0-2) .

If the lookup fails, the handler returns "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'" [4](#0-3) . If the lookup succeeds, execution proceeds to `authorizeRequest`, which calls `WorkflowMetadataHandler.Authorize` and, on any failure (invalid/missing JWT, unregistered signer, replay), returns a distinctly worded "Auth failure: ..." error [5](#0-4) .

Because no signature or credential is required to reach `resolveWorkflowID`, and the two failure branches produce different, client-visible messages, an unauthenticated attacker who knows (or guesses) a `workflowOwner` address and workflow name string can distinguish "this owner has no workflow with this name/tag" from "this owner has a workflow with this name/tag but I'm not authorized to trigger it." This turns workflow existence into a pre-authentication oracle, violating the stated invariant that workflow metadata/existence should not leak to unauthorized parties.

### Impact Explanation
This is an information-disclosure issue: it lets an attacker confirm the existence, naming convention, and tag/version scheme of another user's private workflow without any valid credentials, which can be used to build a target list for further attacks (e.g., signer/key guessing, social engineering, or timing further probes against a specific victim's active workflow). It does not by itself allow execution, fund movement, or secret disclosure, so it falls into a low/informational information-disclosure impact class rather than a critical privilege-escalation one.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs network access to the gateway's user-facing HTTP trigger endpoint and a guessed `workflowOwner` (public, on-chain) and `workflowName`/`workflowTag` string — no valid JWT or authorized key is required to reach the differentiating branch. The probe is fully repeatable and automatable (simple POST loop comparing response text), so likelihood is high once an attacker has a plausible name/tag candidate to test, though the practical value is bounded by how easily workflow names/tags can be guessed.

### Recommendation
Return an identical, generic error (same code and message, e.g. "Workflow not found or not authorized") for both the "workflow reference not found" and "authorization failed" branches in `HandleUserTriggerRequest`, so that resolution failures and authorization failures are indistinguishable to the caller. Alternatively, require JWT/signature verification (structural validity) before performing the workflow reference lookup, and only reveal generic errors thereafter.

### Proof of Concept
Handler-level integration test in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler_test.go`:
1. Register a workflow in the test `WorkflowMetadataHandler` via `syncMetadata`/`workflowRefToID` with owner `A`, name `"secret-workflow"`, tag `"v1"`, and an authorized key belonging to user `A`.
2. Case 1 (nonexistent): send `workflows.execute` request with `workflowOwner=A`, `workflowName="does-not-exist"`, `workflowTag="v1"`, no/garbage `Auth`. Assert response contains "Workflow not found...".
3. Case 2 (exists, unauthorized): send `workflows.execute` request with `workflowOwner=A`, `workflowName="secret-workflow"`, `workflowTag="v1"`, garbage/invalid `Auth` (or a JWT signed by an unrelated key). Assert response contains "Auth failure: ...".
4. Assert the two response bodies/messages differ, proving an attacker can distinguish existence of the workflow reference without valid credentials — demonstrating the pre-authorization oracle.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *WorkflowMetadataHandler) GetWorkflowID(workflowOwner, workflowName, workflowTag string) (string, bool) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	workflowRef := workflowReference{
		workflowOwner: workflowOwner,
		workflowName:  workflowName,
		workflowTag:   workflowTag,
	}
	workflowID, exists := h.workflowRefToID[workflowRef]
	if !exists {
		return "", false
	}
	return workflowID, true
}
