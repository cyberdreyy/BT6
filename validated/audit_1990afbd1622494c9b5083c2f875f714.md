### Title
Unauthenticated access to LOOP plugin pprof debug endpoints (`GET /plugins/:name/debug/pprof/*profile`, `POST /plugins/:name/debug/pprof/symbol`) - ([File: core/web/router.go])

### Summary
`loopRoutes()` registers the LOOP plugin discovery, metrics, and pprof debug endpoints directly on the unauthenticated `api` router group, unlike the node's own `/v2/debug/pprof` endpoints which are nested inside the `authv2` group requiring session/token authentication. This allows any unauthenticated client to pull pprof profiles (heap, goroutine, cmdline, symbol resolution, etc.) from any registered LOOP plugin process.

### Finding Description
In `core/web/router.go`, `NewRouter` creates the `api` group with only rate-limiting and session-store middleware (no authentication): [1](#0-0) 

`loopRoutes(app, api)` is called directly on this unauthenticated `api` group and registers: [2](#0-1) 

Contrast this with the node's own pprof handler, `metricRoutes`, which is deliberately placed inside the authenticated `authv2` sub-group (created with `auth.Authenticate(...)`): [3](#0-2) [4](#0-3) 

and `debugRoutes` similarly wraps its group with `auth.Authenticate`: [5](#0-4) 

The pprof forwarding handlers themselves perform no authentication or authorization check — they only look up the plugin by name and proxy the request to the plugin's internal pprof port: [6](#0-5) [7](#0-6) 

Since `loopRoutes` is invoked outside any `auth.Authenticate(...)` wrapper, and the handlers have no independent auth check, any unauthenticated HTTP client that can reach the node's API port can call `GET /plugins/:name/debug/pprof/<profile>` or `POST /plugins/:name/debug/pprof/symbol` and receive full pprof output (heap dumps, goroutine stacks, cmdline, symbol tables) from the named LOOP plugin process.

### Impact Explanation
Successful exploitation leaks LOOP plugin process memory/heap/goroutine dumps to an unauthenticated attacker. Heap and goroutine profiles can contain sensitive in-memory data such as key material, request payloads, or internal state, and `cmdline`/`symbol` outputs disclose binary paths and internal function/symbol layout useful for further attacks. This falls under credential/secret disclosure and information-disclosure impact classes for a Chainlink node.

### Likelihood Explanation
No credentials are required — the attacker only needs network access to the node's exposed web/API port and a valid plugin name (discoverable via the also-unauthenticated `GET /discovery` and `GET /plugins/:name/metrics` endpoints registered in the same `loopRoutes` block). This is trivially and repeatably exploitable with a single HTTP request.

### Recommendation
Wrap the routes registered in `loopRoutes` with the same authentication middleware used elsewhere (e.g., register them on an `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`-protected sub-group, and require admin role for pprof/symbol endpoints, mirroring `metricRoutes`'s placement inside `authv2`).

### Proof of Concept
Go handler-level integration test plan:
1. Build the router via `NewRouter(app, nil)` with a test `chainlink.Application` that has at least one plugin registered in the `LoopRegistry` (or a fake `RegisteredLoop` pointing to a local `httptest.Server` serving `net/http/pprof` handlers on a fixed port).
2. Issue `httptest.NewRequest("GET", "/plugins/<pluginName>/debug/pprof/heap", nil)` through the router `ServeHTTP` with no `Authorization` header, no session cookie.
3. Assert the response status is `200 OK` (not `401`/`403`) and the body contains valid pprof profile bytes/headers (e.g., `Content-Type: application/octet-stream` or pprof magic bytes).
4. Repeat with `POST /plugins/<pluginName>/debug/pprof/symbol` with no auth, asserting a non-401/403 response reaching the plugin's pprof symbol handler.
5. As a control, compare against `GET /v2/debug/pprof/heap` (the node's own pprof, nested in `authv2`) with no auth and assert it correctly returns `401 Unauthorized`, demonstrating the inconsistency.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
