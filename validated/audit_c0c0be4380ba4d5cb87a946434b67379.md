### Title
Integer-truncation in the staked-stream load EMA lets a controlled QUIC stream rate permanently suppress `staked_throttling_enabled`, disabling per-stake ingest fairness - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::update_ema`/`ema_function` in `streamer/src/nonblocking/stream_throttle.rs` compute a fixed-point exponential moving average of QUIC stream load using integer division by `STREAM_LOAD_EMA_MULTIPLIER = 1024`. Because the per-interval load contribution is scaled by a small integer smoothing factor before dividing by 1024, an aggregate load that stays under a computable per-interval threshold causes the EMA update to always truncate to zero, exactly like the `rewardsPerToken_.accumulated` staying at zero in the referenced report while `lastUpdated`/state continues to advance.

### Finding Description
`ema_function` implements:
```
updated_ema = (recent_load * multiplied_smoothing_factor
               + current_ema * (MULTIPLIER - multiplied_smoothing_factor)) / MULTIPLIER
``` [1](#0-0) 

with `multiplied_smoothing_factor = 2 * 1024 / (STREAM_LOAD_EMA_INTERVAL_COUNT + 1) = 2048 / 41 = 49` (integer division), and `STREAM_LOAD_EMA_INTERVAL_COUNT = 40` [2](#0-1) .

`update_ema` is invoked from `update_ema_if_needed`, which is called on every `increment_load` (i.e., on every accepted stream from a staked QUIC connection) once at least `STREAM_LOAD_EMA_INTERVAL_MS` (5ms) has elapsed since the last update [3](#0-2) . `load_in_recent_interval` is a single shared atomic counter across *all* staked connections that is swapped to zero on each update [4](#0-3) .

When `current_ema` is 0 and `recent_load` (i.e., the sum of streams opened by all staked peers in that 5ms window) is `R`:
```
updated_ema = (R * 49) / 1024
```
This truncates to `0` for any `R <= 20` (since `20*49 = 980 < 1024`, but `21*49 = 1029 >= 1024`). As long as aggregate staked-stream throughput stays at or below ~20 streams per 5ms window (~4,000 streams/sec across the whole node), `current_load_ema` never leaves `0`, no matter how long this is sustained. Because `staked_throttling_enabled` is only flipped to `true` once `updated_load_ema >= staked_throttling_on_load_threshold` (a positive threshold) [5](#0-4) , the throttling flag can be kept permanently `false` by pacing stream opens to remain at/under this rounding threshold in every 5ms window, indefinitely, even while continuously consuming ingest capacity.

This is the same bug class as the report: the "accumulator" (`current_load_ema`) never increments because of integer truncation on a small numerator/large denominator ratio, while the "clock"/state (`last_update`, `load_in_recent_interval` resets) keeps advancing every interval — an ordinary, unprivileged staked client can trivially pace its own QUIC stream requests (or, since the counter is shared, coordinate with other staked connections) to stay under the per-interval threshold.

### Impact Explanation
`staked_throttling_enabled` gates `available_load_capacity_in_throttling_duration`, which is what caps how many streams a staked peer may open relative to its stake share versus the unstaked pool [6](#0-5) . If the EMA is kept pinned at 0 by pacing, the throttling branch is never taken and staked peers instead always get `max_staked_load_in_throttling_window` (the full pool) rather than a stake-proportional share. A staked attacker (or a small coalition) can therefore consume a disproportionate/unfair amount of the TPU/QUIC ingest capacity relative to other staked validators without ever triggering the fairness mechanism meant to protect against exactly this kind of ingest monopolization — this is an ingest-starvation condition against the QUIC-based TPU intake path.

### Likelihood Explanation
The trigger is entirely client-controlled: any staked QUIC client can pace the rate at which it opens new streams. No special privileges, leaked keys, or node-level access are needed — only ordinary QUIC connections from a staked identity. The precise threshold (~20 increments per 5ms shared across all staked connections) is derivable from public constants in the code, making the attack straightforward to calibrate.

### Recommendation
- Avoid integer truncation to zero in `ema_function`, e.g. round to nearest instead of floor, or track load using higher-precision fixed point that doesn't collapse small-but-sustained loads to zero.
- Alternatively, accumulate a running/leaky sum rather than resetting `load_in_recent_interval` to zero every interval, so sustained sub-threshold load still contributes over time.
- Add a floor mechanism so that a nonzero `recent_load` sustained across many intervals cannot be treated identically to true zero load.

### Proof of Concept
1. As a staked QUIC client, open new streams at a controlled cadence such that no more than 20 streams (in aggregate across all currently-active staked connections observed by the node) are counted within any 5ms window (`STREAM_LOAD_EMA_INTERVAL_MS`).
2. Each time `update_ema_if_needed` fires (via `increment_load`), `ema_function(0, R)` with `R <= 20` computes `(R*49)/1024 = 0`, so `current_load_ema` remains `0` [7](#0-6) .
3. Since `current_load_ema` never reaches `staked_throttling_on_load_threshold`, `staked_throttling_enabled` stays `false` forever [5](#0-4) .
4. `available_load_capacity_in_throttling_duration` then always returns the full `max_staked_load_in_throttling_window` instead of a stake-weighted share [8](#0-7) , letting the attacker sustain this level of throughput indefinitely (which, summed across the many 100ms throttling windows over time, is a large volume of ingest) without the fairness mechanism ever engaging — mirroring how the reported contract's rewards accumulator stayed at zero while `lastUpdated` kept advancing.

    fn ema_function(current_ema: u128, recent_load: u128) -> u128 {
        // Using the EMA multiplier helps in avoiding the floating point math during EMA related calculations
        const STREAM_LOAD_EMA_MULTIPLIER: u128 = 1024;
        let multiplied_smoothing_factor: u128 =
            2 * STREAM_LOAD_EMA_MULTIPLIER / (u128::from(STREAM_LOAD_EMA_INTERVAL_COUNT) + 1);

        // The formula is
        //    updated_ema = recent_load * smoothing_factor + current_ema * (1 - smoothing_factor)
        // To avoid floating point math, we are using STREAM_LOAD_EMA_MULTIPLIER
        //    updated_ema = (recent_load * multiplied_smoothing_factor
        //                   + current_ema * (multiplier - multiplied_smoothing_factor)) / multiplier
        (recent_load * multiplied_smoothing_factor
            + current_ema * (STREAM_LOAD_EMA_MULTIPLIER - multiplied_smoothing_factor))
            / STREAM_LOAD_EMA_MULTIPLIER
    }

    fn update_ema(&self, time_since_last_update_ms: u128) {
        // if time_since_last_update_ms > STREAM_LOAD_EMA_INTERVAL_MS, there might be intervals where ema was not updated.
        // count how many updates (1 + missed intervals) are needed.
        let num_extra_updates =
            time_since_last_update_ms.saturating_sub(1) / u128::from(STREAM_LOAD_EMA_INTERVAL_MS);

        let load_in_recent_interval =
            u128::from(self.load_in_recent_interval.swap(0, Ordering::Relaxed));

        let mut updated_load_ema = Self::ema_function(
            u128::from(self.current_load_ema.load(Ordering::Relaxed)),
            load_in_recent_interval,
        );

        for _ in 0..num_extra_updates {
            updated_load_ema = Self::ema_function(updated_load_ema, 0);
            if updated_load_ema == 0 {
                break;
            }
        }

    pub(crate) fn update_ema_if_needed(&self) {
        const EMA_DURATION: Duration = Duration::from_millis(STREAM_LOAD_EMA_INTERVAL_MS);
        // Read lock enables multiple connection handlers to run in parallel if interval is not expired
        if Instant::now().duration_since(*self.last_update.read().unwrap()) >= EMA_DURATION {
            let mut last_update_w = self.last_update.write().unwrap();
            // Recheck as some other thread might have updated the ema since this thread tried to acquire the write lock.
            let since_last_update = Instant::now().duration_since(*last_update_w);
            if since_last_update >= EMA_DURATION {
                *last_update_w = Instant::now();
                self.update_ema(since_last_update.as_millis());
            }
        }
    }

    pub(crate) fn increment_load(&self, peer_type: ConnectionPeerType) {
        if peer_type.is_staked() {
            self.load_in_recent_interval.fetch_add(1, Ordering::Relaxed);
        }
        self.update_ema_if_needed();
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
