### Title
`buildArtifactMetadata` discloses masked/protected variable names in SLSA provenance metadata - ([File: functions/concrete/builder/builder.go])

### Summary
`buildArtifactMetadata` unconditionally appends every job variable's `Key` from `b.meta.Variables` into `meta.Parameters`, with no filtering for masked or protected status. This metadata is embedded into the artifact's SLSA provenance JSON when `RUNNER_GENERATE_ARTIFACTS_METADATA` is enabled, meaning the names of secret CI/CD variables become visible in artifact metadata to anyone who can download the artifact.

### Finding Description
In `buildArtifactMetadata` [1](#0-0) , the code iterates `b.meta.Variables` (of type `spec.Job.Variables`) and appends every `v.Key` to `meta.Parameters` without checking whether that variable is masked or protected. This `ArtifactMetadata` struct is attached to the upload when `shouldGenerateArtifactMetadata` returns true [2](#0-1) , gated only by the `RUNNER_GENERATE_ARTIFACTS_METADATA` feature toggle and zip-format requirement [3](#0-2) . There is no filtering logic in this path comparable to what exists elsewhere for masking values in logs/traces — the check here operates only on `v.Key` (the variable **name**), not the value, so the value itself is never disclosed, but the existence and exact name of a variable configured with a secret name (e.g., `AWS_SECRET_ACCESS_KEY`, `DEPLOY_TOKEN_STAGING`) is embedded in the artifact metadata regardless of its `Masked`/`Protected` flags.

I was unable to fully verify within the available index whether `spec.Variable` even carries `Masked`/`Protected` fields that this function should be checking against — `common/spec/spec.go` and `common/spec/variables.go` do reference `Masked`/`Protected` concepts, but I could not retrieve their exact field definitions in this session to confirm the struct shape or whether GitLab's job spec already strips masked variables from `Job.Variables` before reaching the runner (in which case this would be a non-issue, since the runner never even sees masked variable keys). Similarly, I could not confirm from this codebase whether `CI_RUNNER_ID` in `b.variables` is a value fixed by the runner/server or one an unprivileged job author could override via a custom-defined CI/CD variable of the same name — this depends on precedence rules in `variables.Provider`, which I was not able to inspect fully before running out of iterations.

### Impact Explanation
If `spec.Job.Variables` sent to the runner does include masked/protected variable definitions (with only their values redacted upstream, not the keys removed), then the variable **names** leak into the artifact's provenance metadata, which is more widely accessible than build logs (any user who can download artifacts, potentially across relaxed artifact visibility settings) — enabling attackers to enumerate secret variable names for targeted guessing/social engineering across projects. This is a real but narrow information-disclosure concern (names only, not values) and is scoped correctly.

### Likelihood Explanation
Preconditions: `RUNNER_GENERATE_ARTIFACTS_METADATA=true`, artifact format `zip`, and the job has masked/protected variables whose keys are present in `b.meta.Variables` as received by the runner. This is fully within reach of a pipeline author who controls their own project's CI/CD variables and pipeline configuration.

### Recommendation
Filter `b.meta.Variables` in `buildArtifactMetadata` to exclude entries flagged `Masked` or `Protected` before appending `v.Key` to `meta.Parameters`, matching the intended invariant that protected variable presence should not be disclosed to unintended consumers.

### Proof of Concept
```go
func TestBuildArtifactMetadata_ExcludesMaskedProtectedVariableNames(t *testing.T) {
    job := spec.Job{
        Variables: spec.JobVariables{
            {Key: "NORMAL_VAR", Value: "x"},
            {Key: "SECRET_TOKEN", Value: "y", Masked: true},
            {Key: "PROTECTED_VAR", Value: "z", Protected: true},
        },
        Artifacts: []spec.Artifact{{Format: spec.ArtifactFormatZip, Paths: []string{"out"}}},
    }
    vars := fakeVariablesProviderWith("RUNNER_GENERATE_ARTIFACTS_METADATA", "true")

    b := builder{meta: job, variables: vars}
    meta := b.buildArtifactMetadata()

    assert.NotContains(t, meta.Parameters, "SECRET_TOKEN")
    assert.NotContains(t, meta.Parameters, "PROTECTED_VAR")
    assert.Contains(t, meta.Parameters, "NORMAL_VAR")
}
```
