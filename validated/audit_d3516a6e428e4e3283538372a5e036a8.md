### Title
Confidential-relay `activeRequests` map keyed only by `req.ID` allows a stale straggler node response for a completed request to be merged into a different requester's later request that reuses the same ID - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`newActiveRequest` and `HandleNodeMessage` correlate node responses to callers purely by the string `req.ID` [1](#0-0) , with no per-registration nonce, generation counter, or sender/owner binding. Because a request is removed from `h.activeRequests` as soon as quorum/early-need is reached (potentially before every DON node has answered) [2](#0-1) , a straggling node response for the just-completed request can still arrive afterward and, if a second caller has already re-registered the identical ID, will be silently folded into that unrelated request's bundle.

### Finding Description
`HandleJSONRPCUserMessage` accepts a caller-supplied `req.ID` with only a non-empty/length check, no uniqueness-to-caller or session binding [3](#0-2) . `newActiveRequest` rejects the ID only if it is *currently* present in `h.activeRequests`; once the map entry has been deleted the same ID is free to be reused by any other caller [4](#0-3) .

`sendResponseAndClearRequest` marks a request completed and deletes it from `h.activeRequests` as soon as an early-quorum bundle is ready (`earlyNeed = 2F+1`), which can happen while up to `F` nodes have not yet answered [5](#0-4) [2](#0-1) . If, after that deletion, a straggling node's response for the same original `req.ID` arrives, `HandleNodeMessage` looks it up purely via `h.getActiveRequest(resp.ID)` [6](#0-5) . If a *different* request with the same ID has meanwhile been registered by another caller, the map lookup returns that new `activeRequest`, and the stale response is accepted via `addResponseForNode` and merged by `bundler.Bundle()` into the new caller's bundle [7](#0-6) . The resulting bundle (including the stray node's payload originating from the earlier, unrelated request/params) is then delivered to the second caller's own callback via `forwardBundle`/`sendResponseAndClearRequest` [8](#0-7) . Nothing in this path validates that a node's response actually corresponds to the specific request object/params for which it was solicited — only the ID string is checked.

### Impact Explanation
This is a cross-user response-confusion primitive: a node's answer intended for one requester's `MethodSecretsGet`/`MethodCapabilityExec` call can be delivered to a different, unrelated requester merely because they reused the same JSON-RPC `id`. This maps to Chainlink's "cross-user secrets/response confusion" bounty class — an attacker who can trigger receipt of another party's relay bundle content gains unauthorized access to data that should be isolated to the original requester's session.

### Likelihood Explanation
Exploitation requires the attacker to (a) know or predict a victim's `req.ID` value (feasible if IDs are not cryptographically random, e.g., sequential/deterministic IDs from a workflow/SDK), and (b) win a narrow timing race: register the same ID after the victim's request is deleted from `activeRequests` but before the last straggling node response (bounded by `nodeSendTimeout`/`requestTimeout`, up to several seconds) arrives. No elevated privileges are needed beyond being able to submit `HandleJSONRPCUserMessage` requests, but the race window is narrow and the ID must genuinely collide, making this a low-but-nonzero likelihood, timing-dependent issue rather than a trivially repeatable one.

### Recommendation
Bind each `activeRequest` to a unique internal generation token (not just the caller-supplied `req.ID`) and validate that on response receipt — e.g., store a monotonically increasing correlation key or object pointer identity check alongside `req.ID` in a lookup table keyed by `(nodeAddr-independent) internal ID`, and reject/drop node responses whose internal generation does not match the currently active registration for that ID. Alternatively, tag outgoing node requests with a gateway-generated nonce embedded in the JSON-RPC ID (or params) so stale responses can never match a subsequently-registered request.

### Proof of Concept
Go table/integration test in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Configure a small DON (e.g., F=1, 3 nodes) with a mocked `bundler` and `don.SendToNode`.
2. Submit request A with ID `"X"`; simulate 2 of 3 nodes responding immediately so `forwardBundleOrTerminateIfReady` reaches `earlyNeed` and calls `sendResponseAndClearRequest`, deleting `"X"` from `h.activeRequests`.
3. Immediately submit request B (different method/params, different callback) with the same ID `"X"` via `HandleJSONRPCUserMessage`; assert `newActiveRequest` succeeds (no "ID already exists" error) because the old entry was deleted.
4. Deliver the 3rd (straggling) node's response for the original request A (`resp.ID == "X"`) via `HandleNodeMessage`.
5. Assert that this stale response is added to request B's `activeRequest.responses` (via a spy on `addResponseForNode`) and that `bundler.Bundle` for B is invoked with the contaminated response set — demonstrating that `getActiveRequest("X")` incorrectly matched a response for the original request to the newly-registered, unrelated request.

	if err != nil {
		return err
	}

}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) getActiveRequest(requestID string) *activeRequest {
	h.mu.RLock()
	defer h.mu.RUnlock()
	return h.activeRequests[requestID]
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

// forwardBundle sends a previously-built bundle to the enclave. The gateway makes
// no trust decision; the enclave verifies signatures and reaches quorum.
func (h *handler) forwardBundle(ctx context.Context, l logger.Logger, ar *activeRequest, summary *BundleSummary) error {
	nodes := len(h.donConfig.Members)
	rawResponse, err := jsonrpc.EncodeResponse(summary.Response())
	if err != nil {
		l.Errorw("failed to encode response", "error", err)
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.NodeReponseEncodingError, err))
	}
	l.Infow("forwarding relay response bundle to enclave",
		"signedResponses", summary.Signed(),
		"earlyNeed", 2*h.donConfig.F+1,
		"collected", summary.Total(),
		"nodes", nodes,
		"remaining", nodes-summary.Total(),
		"errorResponses", summary.Error(),
		"undecodableResponses", summary.Undecodable(),
		"nodeErrors", summary.NodeErrorsFormatted(),
	)
	return h.sendResponseAndClearRequest(ctx, ar, gwhandlers.UserCallbackPayload{
		RawResponse: rawResponse,
		ErrorCode:   api.NoError,
	})
}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
