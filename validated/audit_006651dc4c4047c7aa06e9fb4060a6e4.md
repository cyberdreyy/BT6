### Title
GET /v2/external_initiators (Index) has no role-based authorization, exposing all external initiators' AccessKey/OutgoingToken to any authenticated user - ([File: core/web/router.go], [File: core/web/external_initiators_controller.go])

### Summary
The `/v2/external_initiators` routes registered in `v2Routes` correctly wrap `POST` and `DELETE` with `auth.RequiresEditRole`, but the `GET` (Index) route is registered with only the base `authv2` authentication group and no role check at all. This means any authenticated user, including a `UserRoleView` session/token holder, can list every external initiator record and its `AccessKey`/`OutgoingToken`.

### Finding Description
In `core/web/router.go`:
```go
eia := ExternalInitiatorsController{app}
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))
authv2.DELETE("/external_initiators/:Name", auth.RequiresEditRole(eia.Destroy))
``` [1](#0-0) 

`authv2` only requires successful authentication via token or session (`auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), with no minimum role enforced. `eia.Index` performs no additional role gating itself before querying and returning all external initiators: [2](#0-1) 

The JSON-API resource returned by `Index`, `ExternalInitiatorResource`, includes `AccessKey` and `OutgoingToken` for every initiator in the system (not scoped to the requesting user), unlike `Create`'s one-time response which additionally includes `Secret`/`OutgoingSecret`: [3](#0-2) 

The existing test `TestExternalInitiatorsController_Index` confirms an authenticated client (which in this test setup uses an admin-equivalent session, but the route itself imposes no role restriction) can retrieve `AccessKey` and `OutgoingToken` for initiators it did not create: [4](#0-3) 

Note: the specific premise in the question about a "duplicate EI management route missing RequiresEditRole" allowing `Create` to be reached via an unauthenticated/ping-adjacent group is not supported by the code — there is only one registration each for `POST`/`DELETE /v2/external_initiators`, both correctly wrapped in `auth.RequiresEditRole`, and `ExternalInitiatorsEnabled()` is checked inside `Create` itself as a feature flag, not a security boundary that can be bypassed via routing. The genuinely exploitable issue is the missing role check on the `Index` (`GET`) route.

### Impact Explanation
A low-privilege authenticated user (view-role session or API token) can enumerate `AccessKey` and `OutgoingToken` values for every external initiator configured on the node, not just their own. `AccessKey`/incoming secret pairs authenticate inbound webhook requests to the node's external-initiator endpoints, and `OutgoingToken` is used by the node to authenticate itself back to the initiator service. Disclosure of `AccessKey`/`OutgoingToken` to an unintended, lower-privileged user constitutes cross-user credential/information disclosure and could facilitate impersonation of external-initiator traffic, matching a credential-exposure / authorization-bypass bounty class. Note the incoming `Secret` and `OutgoingSecret` values themselves are not included in the `Index` response (only in the one-time `Create` response), so the impact is limited to `AccessKey`/`OutgoingToken` disclosure, not full secret disclosure.

### Likelihood Explanation
Minimal precondition: any valid authenticated session or API token, including the lowest `UserRoleView` role. No special timing or race condition is required — a single `GET /v2/external_initiators` call is sufficient and fully repeatable.

### Recommendation
Wrap the `Index` route with an explicit role check consistent with `Create`/`Destroy` (e.g., `auth.RequiresEditRole` or, if broader visibility is intentional, at minimum `auth.RequiresViewRole` combined with per-user/organization scoping), or scope the returned initiators/redact `AccessKey`/`OutgoingToken` fields for lower-privileged roles in `NewExternalInitiatorResource`.

### Proof of Concept
Go handler-level integration test (extends existing `external_initiators_controller_test.go` patterns):
1. Start app with `ExternalInitiatorsEnabled = true`.
2. Create a user/session with `sessions.UserRoleView` (see helpers used elsewhere, e.g. `cltest.NewApplicationWithConfig` + `client.LoggedInWithRole` or equivalent view-role HTTP client helper used across other role tests in `core/web/*_controller_test.go`).
3. Insert an external initiator via `bridges.NewORM(db).CreateExternalInitiator` (simulating another admin/edit user's initiator) with known `AccessKey`/`OutgoingToken`.
4. As the view-role client, call `GET /v2/external_initiators`.
5. Assert `http.StatusOK` (not 401/403), and assert the response body's `ExternalInitiatorResource[].AccessKey` and `.OutgoingToken` match the values inserted, proving a view-role user retrieved another user's initiator credentials.
6. As a control, call `POST /v2/external_initiators` with the same view-role client and assert `http.StatusUnauthorized`, confirming `Create` is correctly gated (falsifying the duplicate-route-bypass hypothesis while confirming the `Index` gap).

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
