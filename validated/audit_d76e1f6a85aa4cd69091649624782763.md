### Title
An APR0 withdraw request permanently bricks `stopEpoch` if APR is reconfigured, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.prepareStopEpochWithApr0` reverts whenever `apr0TotalPrincipal != 0` while `unscaledApr != 0`. `apr0TotalPrincipal` is only ever zeroed inside that same function (after the revert check) or via the default-claim cleanup path. A lender who opens an APR0 withdraw request while APR is 0 can therefore permanently revert every subsequent `stopEpoch`/`stopEpochWithDuration` call once the vault's APR is set to a non-zero value — a routine manager action — before that request's epoch is stopped. Since the revert happens before `getFundsFromBorrower` and `_handleBorrowerDefault`, no epoch can close and no default path can be entered. Analogous to the libde265 crash: a crafted input (a tiny APR0 receipt) poisons a global state bucket so the core processing function can never complete again.

### Finding Description
In `requestWithdraw`, when `unscaledApr == 0`, the request principal is added to the APR0 bucket via `_requestWithdrawApr0`, which increases `apr0TotalPrincipal` and stores `apr0Users[_user].principalEpoch = epochNumber` (`IdleCreditVault.sol:285-286`, `567-577`).

At epoch end, `IdleCDOEpochVariant.stopEpoch` calls `_strategy.prepareStopEpochWithApr0(_interest)` early, before any borrower pull or default handling (`IdleCDOEpochVariant.sol:362`). Inside:

- `if (unscaledApr != 0) revert NotAllowed();` — `IdleCreditVault.sol:506-508`
- `apr0TotalPrincipal = 0` only executes at `IdleCreditVault.sol:540`, after the revert and only when reached.

`unscaledApr` is set by `setAprsWithBuffer`/`setAprs` (callable by the CDO or the honest manager, `IdleCreditVault.sol:217-235`). Nothing prevents the manager from setting a non-zero APR while an APR0 request is still open — the revert is the only enforcement, and it enforces it by bricking the vault. There is no function that lets a user or manager remove `apr0TotalPrincipal` after the APR changes:

- `_settleApr0` only moves per-user `principal` to `settledPrincipal`; it does not touch `apr0TotalPrincipal` (`545-565`).
- `_claimFundedWithdrawRequest`/`claimInstantWithdrawRequest` never decrement `apr0TotalPrincipal` (only the default-path `_clearWithdrawClaimForEpoch` with `_isClearingApr0=true` does, `827`).
- `epochNumber` only increments in `deposit()` during `stopEpoch` (`607-614`), which is unreachable while `prepareStopEpochWithApr0` reverts, so the APR0 request can never settle either.
- `stopEpoch` calls `prepareStopEpochWithApr0` before the `try getFundsFromBorrower`/`catch → _handleBorrowerDefault` block, so the default/finalizeDefault cleanup path cannot be entered to clear the bucket.

Broken invariant: liveness/solvency of the epoch state machine — a user-controlled receipt makes the only function that recycles borrowed principal permanently uncallable.

### Impact Explanation
Permanent freezing of the entire pool. All borrowed principal and accrued interest remain with the borrower, `epochEndDate` passes but `stopEpoch` always reverts, `epochNumber` never advances, no withdraw request (normal, APR0, or instant beyond prefunded cash) can ever be claimed, and `finalizeDefault` is unreachable because `defaulted` can never be set. Quantified loss: 100% of TVL lent for the running epoch plus all future epochs' queued funds are frozen indefinitely; an attacker's cost is a dust-sized APR0 withdraw request (KYC'd lender only).

### Likelihood Explanation
Requires a specific but plausible ordering: the vault runs an APR0 epoch (an explicitly supported mode, `_requestWithdrawApr0` and `apr0RateByEpoch` exist for it), any single KYC'd lender requests a withdraw during the buffer period, and the manager later sets a non-zero APR via `setAprsWithBuffer`/`setApr` before that epoch's `stopEpoch` — a supported, honest action ("only CDO and manager can set the APR", `IdleCreditVault.sol:223`). No guard warns the manager that open APR0 principal exists (`apr0TotalPrincipal` is not checked in `setApr`), so this is one routine configuration call away from an irreversible brick. The attacker only needs a minimal request, making the attack near-free.

### Recommendation
Do not gate `stopEpoch` on a stale `unscaledApr` value. Either snapshot the APR at request time (per `principalEpoch`) and settle the open bucket using that snapshot, or treat a non-zero current APR as settling the APR0 bucket with zero accrued rate instead of reverting. Additionally, reject APR changes in `setApr`/`setAprsWithBuffer` while `apr0TotalPrincipal != 0`, and/or provide a manager function to force-close the APR0 bucket so the state machine always has a recovery path.

### Proof of Concept
Foundry fork outline (mirroring `test/foundry/IdleCreditVault.t.sol` helpers):

```solidity
function testApr0RequestBricksStopEpochAfterAprChange() external {
    // Pool running in APR0 mode: unscaledApr == 0
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    // Victim deposits, epoch starts, epoch ends, buffer opens
    idleCDO.depositAA(10_000 * ONE_SCALE);
    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);            // settles cleanly, APR0 bucket empty

    // Buffer period: attacker (KYC'd lender) deposits dust and requests APR0 withdraw
    address attacker = makeAddr("attacker");
    _depositWithUser(attacker, 10 * ONE_SCALE);
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(IERC20(AAtranche).balanceOf(attacker), address(AAtranche));
    assertGt(strategy.apr0TotalPrincipal(), 0);

    // Epoch starts with the APR0 request pending
    vm.prank(manager);
    cdoEpoch.startEpoch();

    // Honest manager reconfigures APR to non-zero mid-epoch (supported action)
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(initialProvidedApr, initialProvidedApr);

    // Warp past epoch end and fund borrower — every stopEpoch permanently reverts
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 0);

    // No default path: prepareStopEpochWithApr0 reverts before _handleBorrowerDefault.
    // epochNumber can never advance; all borrower-held principal is frozen forever.
}
```
