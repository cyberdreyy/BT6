### Title
Malicious sortition winner can indefinitely suppress the miner-inactivity timeout by resending non-advancing block proposals - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`SortitionData::check_latest_block_in_tenure` treats *any* proposal that fails to confirm the tenure's latest **locally-accepted-but-not-yet-globally-accepted** block as "miner activity" and unconditionally bumps `last_activity_time`, with no cap on how many times or how quickly it may be replayed. Since `SortitionState::is_timed_out`/`check_miner_inactivity` compute miner inactivity purely from this same `last_activity_time`, a single malicious sortition winner can rebroadcast a stale/conflicting (non-advancing) block proposal forever and prevent the signer network from ever timing the tenure out and falling back to the prior, valid miner. This is the exact analog of the OpenBazaar `lastModified` reset bug: instead of "add tiny funds to reset the escrow timer," here the attacker "resend a non-advancing block proposal to reset the inactivity timer."

### Finding Description
`check_latest_block_in_tenure` [1](#0-0)  checks whether an incoming proposal's `chain_length` exceeds the tenure's last **signed** block. If not, it is rejected (`Ok(false)`), but before returning it still calls `signer_db.update_last_activity_time(...)` when:

```
info.signed_group.is_none_or(|signed_time| {
    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
})
``` [2](#0-1) 

`Option::is_none_or` returns `true` unconditionally when `signed_group` is `None`. `signed_group` is only populated once a block reaches **global** acceptance; a block that is merely **locally accepted** (signed by this signer, crossed 70% signature weight, but not yet confirmed by the node/`NewBlock` event) has `signed_group == None`. In that case the `reorg_attempts_activity_timeout` bound never applies at all — every single conflicting/non-advancing proposal the miner resends bumps `last_activity_time`, with no limit on frequency or count.

The same pre-commit branch has an identical unconditional bump for pre-committed (unsigned) blocks [3](#0-2) .

This timer is the sole input to the inactivity check that lets the signer network abandon an unresponsive/misbehaving miner:

```
let last_activity = db.get_last_activity_time(sortition)?...unwrap_or(received_time);
...
Ok(elapsed > block_proposal_timeout)
``` [4](#0-3) 

which feeds `check_proposal` (v1) [5](#0-4)  and `check_miner_inactivity` (v0 global state machine) [6](#0-5) , which is the *only* mechanism by which the signer set falls back to a prior valid miner when the current sortition winner goes bad:
```
if !is_timed_out { return Ok(()); }
// the tenure timed out, try to see if we can use the prior tenure instead
``` [7](#0-6) 

`check_latest_block_in_tenure` is invoked directly from proposal handling in `check_block_against_signer_db_state` [8](#0-7) , so the attacker only needs to be the current sortition winner sending ordinary `BlockProposal` gossip — no majority of signers, no other signer's key, and no node/StackerDB bug is required, satisfying the "one-slot miner (plus gossip)" constraint.

### Impact Explanation
This is a liveness wedge: the current tenure/miner can never be marked inactive and the signer set can never fall back to the prior (valid) miner, because the malicious miner keeps "touching" `last_activity_time` via non-advancing proposals — precisely the "buyer perpetually resets `lastModified`" pattern from the report, but applied to the signer's inactivity/tenure-timeout state machine instead of an escrow timeout. While the current miner is withheld from ever timing out, the signer network is stuck waiting on a miner that will never legitimately advance the chain, matching the report's "funds/participation effectively locked until the malicious party stops." This corresponds to the allowed High-impact class: "a signer wedged into never signing valid blocks" (here: never being permitted to switch to a miner who can actually produce valid, advancing blocks).

### Likelihood Explanation
Trivial to trigger: the attacker only needs to win a single sortition (the "one-slot miner" role explicitly permitted by scope) and repeatedly gossip the same or slightly modified non-advancing `BlockProposal` (e.g., re-proposing an already-locally-accepted-but-not-yet-globally-accepted block, or a lower-chain_length block) faster than `block_proposal_timeout`. No majority collusion, no auth token, and no other signer's key are needed — the unconditional `is_none_or(None) == true` branch guarantees the reset every time as long as the block hasn't reached the `signed_group` (global-acceptance) milestone, which the attacker fully controls by simply not letting/needing the block confirm.

### Recommendation
Bound the "locally-accepted-only" activity-reset branch the same way the globally-accepted branch is bounded, or track and cap the number/frequency of activity bumps per tenure (mirroring the report's own suggested fix of "limit the number of times... modified"). Concretely: replace `is_none_or(...)` with a scheme that still enforces `reorg_attempts_activity_timeout` (or an equivalent bound measured from first-seen-conflict) even when `signed_group` is `None`, e.g. by tracking the *first* time this particular conflict was observed for the tenure and only refreshing activity within a bounded window from that first observation, rather than indefinitely on every resend.

### Proof of Concept
1. Malicious node wins a sortition and becomes the current tenure's miner.
2. It proposes block `B1`; enough signers locally accept it (`signed_self`/local-70% signature weight reached) but the miner withholds it from the node so it never reaches `signed_group`/global acceptance (`BlockState::GloballyAccepted` never set) — entirely under the miner's control (e.g., never submit/push `B1`, or delay/censor it at the network layer).
3. Miner keeps sending a new proposal `B1'` at chain_length ≤ `B1`'s chain_length (e.g., resending `B1` itself, or a competing block at the same/lower height), roughly every few seconds, well under `block_proposal_timeout`.
4. Each such proposal hits `check_latest_block_in_tenure`, fails the "does not confirm as many blocks" branch, but because `info.signed_group.is_none()` the `is_none_or` guard is unconditionally true, so `signer_db.update_last_activity_time(...)` fires every time [9](#0-8) .
5. `SortitionState::is_timed_out` therefore never observes `elapsed > block_proposal_timeout` [10](#0-9) , so `check_miner_inactivity` never falls back to the prior miner [11](#0-10) , and the tenure is wedged indefinitely as long as the attacker keeps repeating step 3.

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    pub fn check_miner_inactivity(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<(), SignerChainstateError> {
        let Self::Initialized(ref mut state_machine) = self else {
            // no inactivity if the state machine isn't initialized
            return Ok(());
        };

        let MinerState::ActiveMiner { ref tenure_id, .. } = state_machine.current_miner else {
            // no inactivity if there's no active miner
            return Ok(());
        };

        let version = SortitionStateVersion::from_protocol_version(
            state_machine.active_signer_protocol_version,
        );
        let is_timed_out = SortitionState::is_timed_out(
            &version,
            tenure_id,
            db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )?;

        if !is_timed_out {
            return Ok(());
        }

        // the tenure timed out, try to see if we can use the prior tenure instead
        let CurrentAndLastSortition { last_sortition, .. } =
            client.get_current_and_last_sortition()?;
        let Some(last_sortition) = last_sortition
            .and_then(|val| SortitionData::try_from(val).ok())
            .map(|data| SortitionState::new(version, data))
        else {
            warn!("Signer State: Current miner timed out due to inactivity, but could not find a valid prior miner. Allowing current miner to continue");
            return Ok(());
        };
