### Title
Multisig request confirmations and state are consumed before promise execution succeeds, allowing threshold-approved requests to be discarded on failure without retry - (multisig/src/lib.rs, multisig2/src/lib.rs)

### Summary
In both `multisig/src/lib.rs` and `multisig2/src/lib.rs`, `confirm()` calls `remove_request()` — which deletes the request, its confirmations, and decrements the signer's `num_requests_pk` — and then unconditionally fires the corresponding actions via `execute_request()`, before the resulting `Promise` resolves. Neither contract registers a callback to inspect `PromiseResult` and react to failure/bounce of the scheduled cross-contract actions.

### Finding Description
`confirm()` in `multisig/src/lib.rs` (and identically in `multisig2/src/lib.rs`) checks whether the number of confirmations has reached `num_confirmations`, and if so, immediately calls `self.remove_request(request_id)` followed by `self.execute_request(request)`: [1](#0-0) 

`remove_request` deletes the confirmations map entry and the request entry, and decrements `num_requests_pk` for the original signer — this is the state that models "K signatures obtained, action authorized": [2](#0-1) 

`execute_request` builds a `Promise` chain (`Transfer`, `AddKey`, `DeleteKey`, `FunctionCall`, `DeployContract`, etc.) and returns it, with no `.then(ext_self::...)` callback attached: [3](#0-2) 

The README documents an intended state machine where "each step of execution... puts a callback... when callback executes, it checks if promise executed successfully: if no — stops executing the request and return failure": [4](#0-3) 

However, no such callback exists anywhere in the contract — the only matches for `callback`/`PromiseResult` in the whole repo are in the README files themselves, not in `multisig/src/lib.rs` or `multisig2/src/lib.rs`. The equality that should hold is: `request marked executed/consumed` ⇔ `underlying receiver-side action actually succeeded`. Instead the contract sets this state (deletes the request/confirmations) at proposal time, before the promise's outcome is known, exactly as in the external report's `try_execute` / `executed?` pattern for the TON order contract. If the scheduled promise (e.g., `AddKey`/`DeleteKey`/`FunctionCall`/`DeployContract`/`Transfer` to a receiver that rejects it, or an access-key operation that fails due to a stale/duplicate key) fails on the receiving side, the NEAR runtime will refund any attached balance back to the multisig automatically, but the request's authorization record is already gone — signers who reached threshold cannot resubmit the same `request_id` and must start the K-of-N confirmation process over from scratch, as the code comment itself acknowledges: [5](#0-4) 

The same pattern is present in `multisig2`: [6](#0-5) 

### Impact Explanation
This does not directly move funds below threshold (NEAR's `Transfer` promise itself either succeeds atomically or is refunded, unlike TON's bounce-carries-balance mechanic), but it breaks the confirmations-counted-versus-outcome-delivered binding: the multisig's authorization ledger (`requests`/`confirmations`) is irreversibly cleared as soon as threshold is met, regardless of whether the receiver-side effect (key rotation, function call, contract deployment) actually took hold. For actions like `AddKey`/`DeleteKey`/`AddMember`/`DeleteMember` that mutate access control, a failed promise (e.g., duplicate key already exists) leaves the multisig's on-chain access state diverged from what the signers believe was authorized, with no automatic retry and no record of the failed authorization for auditing.

### Likelihood Explanation
Any legitimate K-of-N confirmation flow that races with an external state change on the receiver (key already added/removed, function call precondition changed, insufficient balance for a bundled action) will trigger this without any privileged access — likelihood matches the original report's characterization (Medium): it requires a normal, permitted set of signer confirmations plus an ordinary receiver-side failure condition, not an attacker forging signatures.

### Recommendation
Attach a `.then()` callback (private, `#[private]`) to the `Promise` returned by `execute_request` that inspects `env::promise_result(0)`, and only treat the request as finalized/consumed on success; on failure, either restore the request/confirmations for retry or emit an explicit "request failed" record instead of silently discarding the K-of-N authorization. This matches the behavior the README already documents but that is missing from the implementation.

### Proof of Concept
1. Multisig configured with `num_confirmations = 2`, members A, B, C.
2. Signers propose and confirm a request with action `AddKey { public_key: P }` targeting the multisig's own account, reaching 2 confirmations.
3. `confirm()` removes the request/confirmations (`remove_request`) and calls `execute_request`, which issues `promise.add_access_key(P, ...)`.
4. If key `P` was already added by an out-of-band transaction (or any other reason `add_access_key` fails on execution), the promise action fails; NEAR does not roll back the `remove_request` state change since it already committed in the same receipt before the async promise result is known.
5. `get_request(request_id)` now panics ("No such request") and `list_request_ids()` no longer contains it — signers must recreate and re-confirm the entire request from zero despite having already met the threshold, with no visibility that the prior authorization was silently dropped.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    // removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .expect("Failed to remove existing element");
        // decrement num_requests for original request signer
        let original_signer_pk = request_with_signer.signer_pk;
        let mut num_requests = self.num_requests_pk.get(&original_signer_pk).unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_signer_pk, &num_requests);
        // return request
        request_with_signer.request
    }
