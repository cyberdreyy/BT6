### Title
Unprivileged caller can register `Currency<T>` and obtain `TreasuryCap<T>` for any foreign `key`-typed coin, enabling unauthorized minting — (`crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

### Summary

`coin_registry::new_currency` is a `public fun` with only a `T: key` ability constraint. It contains no check that the transaction sender or calling module is the publisher of the package that defines `T`. Any address can call it with a type defined in a third-party package, receive a fully functional `TreasuryCap<T>`, and mint unlimited `Coin<T>`.

### Finding Description

`new_currency` is declared:

```move
public fun new_currency<T: /* internal */ key>(
    registry: &mut CoinRegistry,
    ...
): (CurrencyInitializer<T>, TreasuryCap<T>)
```

The `/* internal */` token is a block comment — the Move compiler treats it as whitespace. The effective constraint is `T: key`. The function body performs two checks:

```move
assert!(!registry.exists<T>(), ECurrencyAlreadyExists);
assert!(is_ascii_printable!(&symbol), EInvalidSymbol);
```

Neither check verifies that the caller is the module/package that defines `T`. The function then calls `coin::new_treasury_cap<T>(ctx)`, which is `public(package)` and accessible from `coin_registry` (same `sui` package). That function calls `balance::create_supply_internal<T>()`, producing a `Supply<T> { value: 0 }` — structurally and functionally identical to the supply created by the OTW-gated `balance::create_supply`. The resulting `TreasuryCap<T>` is a fully operational minting capability. [6](#0-5) 

### Impact Explanation

An attacker who calls `new_currency<VictimPackage::VictimCoin>` (where `VictimCoin has key`) receives:

- A `TreasuryCap<VictimCoin>` with which they can call `coin::mint` to produce unlimited `Coin<VictimCoin>`.
- A `CurrencyInitializer<VictimCoin>` hot-potato that, once finalized, registers a `Currency<VictimCoin>` in the shared `CoinRegistry` with attacker-controlled metadata.
- After `finalize`, a `MetadataCap<VictimCoin>` granting control over the coin's name, symbol, description, and icon.

The legitimate package owner is permanently locked out of registering their own coin (`ECurrencyAlreadyExists` will fire on any subsequent attempt). If the coin type was previously issued via the legacy `coin::create_currency` OTW path, a second independent `Supply<VictimCoin>` tracker now exists, breaking the supply invariant and enabling unbounded inflation.

This satisfies the Critical gate: **unauthorized object creation** (`TreasuryCap<T>` for a foreign type) and **state corruption** (CoinRegistry poisoned, supply invariant broken).

### Likelihood Explanation

The attack requires only a single PTB. No special privileges, no leaked keys, no malicious validators. The attacker needs only to know a coin type with `key` ability that has not yet been registered in the `CoinRegistry`. Given that the registry is new and legacy coins migrate lazily, a large surface of unregistered `key`-typed coin structs exists on mainnet.

### Recommendation

Add a publisher/module-origin check before issuing the `TreasuryCap`. The standard pattern in Sui is to require either:

1. A one-time witness `T: drop` (as `new_currency_with_otw` already does), which proves the caller is the module initializer of the package defining `T`; or
2. A `Publisher` object for the package that defines `T`, verified via `sui::package::from_package<T>(&publisher)`.

Option 2 allows post-`init` registration while still enforcing ownership:

```move
public fun new_currency<T: key>(
    publisher: &Publisher,
    registry: &mut CoinRegistry,
    ...
): (CurrencyInitializer<T>, TreasuryCap<T>) {
    assert!(publisher.from_package<T>(), ENotPackagePublisher);
    ...
}
```

The `registry.exists<T>()` guard is the only race condition: if the victim registers first, the attack is blocked for that type. For any unregistered `key`-typed coin, the attack succeeds unconditionally.
