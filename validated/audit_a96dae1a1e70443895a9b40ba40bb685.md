### Title
Griefing lock of vesting distributions via unregistered/opted-out beneficiary blocking `distribute()` for all shareholders - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute()` [1](#0-0)  loops over every shareholder of a vesting contract and calls `aptos_account::deposit_coins()` for each one in a single atomic transaction, without checking beforehand whether each recipient can actually accept the transfer. `deposit_coins` aborts if the recipient has disabled direct coin transfers and isn't already registered for the coin type [2](#0-1) . Because a single failing recipient reverts the whole transaction, one shareholder or beneficiary can permanently block distribution of vested funds for every other shareholder in the same vesting contract — analogous to the Good Entry bug where an unchecked low-level `call` return value let one uncooperative recipient permanently lock funds belonging to others in a shared pool.

### Finding Description
`distribute()` is a permissionless `public entry fun` [3](#0-2) . It withdraws all currently claimable stake from the underlying `staking_contract` into a single `Coin<AptosCoin>` and then iterates `shareholders` computing each one's share and calling:
```
aptos_account::deposit_coins(recipient_address, share_of_coins);
``` [4](#0-3) 

`deposit_coins` will `abort` with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the target address is not yet registered for `AptosCoin` and has disabled `allow_arbitrary_coin_transfers` (default is enabled, but any account can call `set_allow_direct_coin_transfers(false)` on `aptos_account`) [2](#0-1) . Since Move transactions are atomic, an abort at any point in the shareholder loop unwinds the *entire* `distribute()` call — including the withdrawal that already happened.

Only the *beneficiary* address set via `set_beneficiary` is checked for APT registration at set-time (`assert_account_is_registered_for_apt`) [5](#0-4) . The `shareholder` addresses themselves (added at `create_vesting_contract` time via `buy_ins`) are never checked, and even a beneficiary that was registered at set-time can later disable direct transfers (`allow_arbitrary_coin_transfers = false`), which is a per-account toggle independent of registration status, causing subsequent `distribute()` calls to abort.

Critically, `terminate_vesting_contract()` also calls `distribute()` unconditionally as its first step [6](#0-5) , meaning even the admin cannot terminate the vesting contract (to eventually recover funds via `admin_withdraw`) while any shareholder is in this blocked state. `vest()`/`vest_many()` are unaffected (they only call `unlock_stake`, not `distribute`), but `distribute`, `distribute_many`, and `terminate_vesting_contract` are all blocked.

### Impact Explanation
Any single shareholder (or their configured beneficiary) in a multi-shareholder vesting contract can unilaterally and permanently prevent all other shareholders from claiming their vested/unlocked APT, and can prevent the admin from terminating the contract to recover funds. This is a share-accounting/claim-right corruption that traps value belonging to accounts other than the attacker — matching the "Permanent lock or non-recoverable loss of claim rights in ... vesting flows" impact category. The attacker needs no privileged role; they only need to be (or convince the admin to add them as) one of the shareholders, then call `aptos_account::set_allow_direct_coin_transfers(false)` on their own account before it is ever registered for `AptosCoin`.

### Likelihood Explanation
Likelihood is meaningful but conditional: it requires the attacker to be a shareholder of a shared vesting contract with other legitimate shareholders (a common setup for team/investor vesting pools with multiple recipients), and for that address to never have been registered for `AptosCoin` while direct transfers are disabled. This is an easy, cheap, unprivileged action requiring a single call to `set_allow_direct_coin_transfers`. Because `distribute()` and `distribute_many()` are also open to permissionless invocation, once the state is set, every future call will predictably abort, making the DoS persistent and reproducible.

### Recommendation
- In `distribute()`, do not let a single recipient's failed deposit abort the entire batch: wrap each `aptos_account::deposit_coins` in per-recipient fallback logic (e.g., attempt registration/deposit and, if not possible, route that shareholder's share to a claimable/pending balance they can withdraw later, rather than including it in the same atomic all-or-nothing loop).
- Alternatively, require/verify at `create_vesting_contract` and `set_beneficiary` time that every shareholder/beneficiary address is registered for `AptosCoin` and re-validate (or forbid disabling transfers for) accounts already used as vesting recipients.
- Decouple `terminate_vesting_contract`'s admin recovery path from a full successful `distribute()` so a blocked shareholder cannot also block contract termination and admin fund recovery.

### Proof of Concept
1. Admin creates a vesting contract with two shareholders, A and B, via `create_vesting_contract` [7](#0-6) .
2. Shareholder A's account has never registered for `AptosCoin` (new account) and A calls `aptos_account::set_allow_direct_coin_transfers(false)` (function referenced in `aptos_account.move`).
3. Time passes, `vest()` unlocks stake for both A and B, and stake becomes withdrawable.
4. Anyone calls `distribute(contract_address)`. `withdraw_stake` succeeds and pulls the whole withdrawable amount into `coins` [8](#0-7) ; the loop reaches shareholder A and `aptos_account::deposit_coins(A, share_of_coins)` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` [9](#0-8) .
5. The entire transaction reverts; B (and every future call to `distribute`/`distribute_many`/`terminate_vesting_contract`) can never receive their share as long as A keeps this configuration, since the loop iterates `shareholders` unconditionally each time.

Note: I was not able to execute this in a live Move test environment (no test/terminal tool access in this mode); the trace above is derived directly from the cited source of `vesting.move` and `aptos_account.move`. A Devin session with repo/test execution access would be needed to run a Move unit test confirming the abort and the resulting DoS empirically.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
