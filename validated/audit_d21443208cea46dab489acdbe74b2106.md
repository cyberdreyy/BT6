### Title
Stale Confirmations From Deleted Members Allow Multisig Requests to Execute Below the Confirmation Threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only purges confirmation records for requests that the removed member *authored*, but not confirmation records for requests the removed member merely *confirmed*. Because `confirm()` counts every entry in the `confirmations` set — including confirmations left behind by members who have since been deleted — a request can reach `num_confirmations` and execute even though the number of currently-live members who actually confirmed it is smaller than the configured threshold.

### Finding Description
`confirm()` decides whether to execute a request purely by counting stored confirmation strings against `self.num_confirmations`: [1](#0-0) 

The confirmation store (`confirmations: LookupMap<RequestId, HashSet<String>>`) is keyed by `RequestId` and is populated with `member.to_string()` values as members call `confirm`. It is never re-validated against the current `members` set at read time.

When a member is deleted, `delete_member` cleans up only the requests where `r.member == member` (i.e., requests *authored* by the removed member); it does not scan or clean the `confirmations` sets of *other* pending requests that the removed member had already confirmed: [2](#0-1) 

The custody binding that should hold is: `confirmations counted == confirmations from currently live members`. This binding is broken — a stale confirmation from a removed member remains counted forever, inflating the confirmation count for any request that member confirmed before being removed.

### Impact Explanation
This matches the "Critical" impact class of "a multisig request executed below threshold." An attacker (or any member acting maliciously before being removed) can get a transfer/withdrawal/AddKey/DeployContract request into a state where it needs only `num_confirmations - 1` (or fewer) *live* signatures to execute, because a stale confirmation from an already-removed member still counts toward the threshold. This weakens the K-of-N guarantee the contract is supposed to enforce, potentially enabling unauthorized fund transfers or key/contract changes with fewer genuinely authorized approvals than intended.

### Likelihood Explanation
No special privilege is required beyond being (at some point) a legitimate multisig member — which is the normal operating assumption for any member of a K-of-N scheme. The sequence (create request, confirm, get removed via `DeleteMember`, other members finish confirming) is a natural sequence of legitimate multisig operations; no attacker needs elevated access beyond acting as any one member at any point before their own removal.

### Recommendation
When a member is deleted, iterate over all pending requests' `confirmations` sets and remove the deleted member's confirmation entry (not just the requests they authored). Alternatively, validate at `confirm()`-time (and before deciding to execute) that all recorded confirmations still correspond to current `members`, discarding stale ones before comparing the count against `num_confirmations`.

### Proof of Concept
1. Initialize with members `[A, B, C, D]`, `num_confirmations = 3`.
2. `B` calls `add_request(transfer_request)` → request `R` created, empty confirmations.
3. `A` calls `confirm(R)` → `confirmations[R] = {A}` (1 < 3, not executed).
4. Separately, members submit and confirm a `DeleteMember { member: A }` request (using 3 other confirmations); `delete_member` removes `A` from `members`, and only cleans up requests where `r.member == A` — `R` (authored by `B`) is untouched, so `confirmations[R]` still contains stale `A`.
5. `C` calls `confirm(R)` → `confirmations[R] = {A, C}` (2 < 3).
6. `D` calls `confirm(R)`: at check time `confirmations.len() == 2` (`A, C`), `+1 == 3 >= num_confirmations(3)` → request executes.
7. Result: `R` (e.g., a `Transfer`) executed with confirmations from only 2 live members (`C`, `D`) plus one stale, no-longer-valid confirmation from removed member `A` — below the intended 3-of-N threshold. [1](#0-0) [2](#0-1)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
