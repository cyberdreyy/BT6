### Title
Front-runnable deterministic lockup address lets an attacker squat any future owner's lockup with attacker-chosen parameters - (File: lockup-factory/src/lib.rs)

### Summary
`LockupFactory::create` derives the lockup contract's `AccountId` purely as `sha256(owner_account_id)[..20].<factory>`, with no dependency on the caller, a nonce, or the caller's chosen arguments. Any unprivileged account can precompute this address off-chain for a known future grant recipient and call `create()` first, permanently deploying a lockup at that address with attacker-chosen `lockup_duration`, `vesting_schedule`, and `staking_pool_whitelist_account_id`, blocking the legitimate employer/foundation from ever deploying the intended lockup at that address.

### Finding Description
Binding claimed: `deployed_lockup_args(owner_account_id) == intended_creator_args(owner_account_id)`, i.e. the parameters live at `sha256(owner_account_id)[..20].<factory>` should be exactly those chosen by the rightful funder (the employer/foundation), since that address is meant to represent "the lockup for `owner_account_id`."

The address computation has no dependency on `predecessor_account_id` or any nonce: [1](#0-0) 

`create()` is `#[payable]` and callable by anyone who attaches `MIN_ATTACHED_BALANCE`; it builds `LockupArgs` entirely from caller-supplied parameters (`lockup_duration`, `vesting_schedule`, `release_duration`, `whitelist_account_id`) and only sets `foundation_account_id` conditionally on `vesting_schedule.is_some()`: [2](#0-1) 

Exploit flow:
1. Attacker computes `hex::encode(sha256("victim.near")[..20]) + "." + factory_account_id` off-chain — identical to what the factory computes.
2. Attacker calls `create(owner_account_id="victim.near", lockup_duration=<attacker-chosen, e.g. 0>, vesting_schedule=None, ...)` attaching `MIN_ATTACHED_BALANCE`, before the victim's employer ever calls `create()` for that owner. `Promise::new(lockup_account_id).create_account().deploy_contract(...).transfer(...).function_call("new", ...)` succeeds since the account does not yet exist.
3. When the employer/foundation later calls `create(owner_account_id="victim.near", lockup_duration=<intended>, vesting_schedule=<intended>, ...)`, the same deterministic address resolves to an account that already exists. The `create_account` action fails (`AccountAlreadyExistsError`), the whole batched promise fails, and `on_lockup_create`'s `is_promise_success()` check is `false`, so the employer's deposit is refunded and no new deployment occurs: [3](#0-2) 
4. The lockup contract permanently remains initialized with the attacker's chosen `lockup_duration`/`vesting_schedule`/`staking_pool_whitelist_account_id` — parameters the rightful creator (foundation/employer) never chose, and there is no re-init or update path in the lockup contract to change these after `new()`.

No guard (`assert_owner`, `assert_called_by_foundation`, nonce, or caller-derived salt) ties the address or the deployed args to the caller's identity, so the binding "deployed args == legitimate creator's intended args" is broken by design.

### Impact Explanation
This matches the explicitly Critical category "a lockup deployed with parameters its rightful creator never chose." The attacker can pre-emptively squat the address for any known future employee/investor account name, permanently determining that owner's lockup terms (e.g., `lockup_duration=0`, no vesting) before the real foundation/employer transaction lands. Every subsequent legitimate `create()` call for that owner fails and is refunded rather than lost, but the intended lockup (with the foundation's real vesting schedule) can never be deployed at that address — this is systemic and repeatable across every future owner account name, contract-wide.

### Likelihood Explanation
Low cost, fully permissionless: the attacker only needs `MIN_ATTACHED_BALANCE` (3.5 NEAR) and knowledge of the future owner's account name (e.g., a soon-to-be-created employee/investor NEAR account, which is often predictable or publicly known ahead of grant issuance). No special privileges, keys, or races beyond simple transaction ordering are required, and the attack is repeatable for any number of target owner names.

### Recommendation
Bind the derived lockup address (or an additional check within `create`/lockup `new`) to the funding party's identity or an authorization mechanism — e.g., require `predecessor_account_id == foundation_account_id` (or a signed/whitelisted request) before allowing `create()` to deploy a lockup for a given `owner_account_id`, or incorporate a value only the rightful funder can supply (e.g., a foundation-issued one-time token) into the derivation/validation so an unprivileged account cannot pre-emptively claim another owner's address.

### Proof of Concept
```rust
// lockup-factory/src/tests (illustrative, using existing test_utils helpers)
#[test]
fn test_attacker_frontruns_owner_lockup_address() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    // Off-chain precomputation of the deterministic address for the victim owner.
    let victim_owner = account_tokens_owner(); // e.g. "tokenowner.testnet"
    let predicted_address = lockup_account(); // sha256(victim_owner)[..20] + factory

    // Attacker calls create() first, choosing lockup_duration = 0 and no vesting.
    context.predecessor_account_id = "attacker.testnet".to_string();
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(victim_owner.clone(), 0u64.into(), None, None, None, None);

    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    contract.on_lockup_create(predicted_address.clone(), ntoy(30).into(), "attacker.testnet".to_string());

    // Legitimate employer later calls create() for the same owner with real terms;
    // create_account fails because predicted_address already exists -> promise fails.
    context.predecessor_account_id = "employer.near".to_string();
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(victim_owner, 63036000000000000u64.into(), Some(/* real vesting */ vesting_schedule_or_hash), None, None, None);

    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Failed);
    let created = contract.on_lockup_create(predicted_address, ntoy(30).into(), "employer.near".to_string());

    // Assert binding is broken: employer's create failed/refunded, attacker's args (lockup_duration=0, no vesting) are what remains live.
    assert_eq!(created, false);
}
```
This demonstrates that `deployed_lockup_args(victim_owner)` equals the attacker's chosen args, not the employer's intended args, confirming the broken binding.

    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
