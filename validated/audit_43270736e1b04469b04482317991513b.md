### Title
`extractZipFileEntry` performs no path validation, allowing zip-slip path traversal via crafted archive entry names - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFileEntry` (and its siblings `extractZipDirectoryEntry`/`extractZipSymlinkEntry`) write to `file.Name` taken directly from the zip's `FileHeader` with no canonicalization, no `..`/absolute-path rejection, and no root-containment check. Because there is no validation step at all, the "separator normalization bypass" premise doesn't apply literally, but the underlying invariant — that extraction must stay within the intended root — is violated outright by any attacker-controlled entry name (with `../`, `..\`, or an absolute path).

### Finding Description
`ExtractZipFile`/`ExtractZipArchive` (helpers/archives/zip_extract.go:85-120) iterate `archive.File` and, for each entry, call `extractZipFile`, which does: [1](#0-0) 
This calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to `extractZipFileEntry`, `extractZipDirectoryEntry`, or `extractZipSymlinkEntry`, all of which use `file.Name` verbatim as the destination path for `os.OpenFile`, `os.Mkdir`, or `os.Symlink`: [2](#0-1) 

The only check performed before extraction is `errorIfGitDirectory`, which only detects a leading `.git` path segment and is unrelated to traversal: [3](#0-2) [4](#0-3) 

There is no call to `filepath.Clean`, no rejection of `filepath.IsAbs(file.Name)`, no check that the resolved path stays under a working-directory root (unlike `helpers.IsImmediateChild` or the Windows `Contains` helper elsewhere in the codebase, which are not used here): [5](#0-4) [6](#0-5) 

Go's `archive/zip` package does not sanitize the `File.Name` field for direct field access (that protection only applies when using the `fs.FS`/`Reader.Open` interface, which this code does not use) — `file.Name` can legitimately be `../../etc/passwd`, `..\..\..\Windows\System32\...` on Windows, or an absolute path, and it is passed straight through to filesystem calls. The existing unit tests (`zip_extract_test.go`) only cover normal file extraction, `.git` warning, and symlink mode — there is no test asserting traversal protection, confirming no such protection is implemented or tested.

Since there is no validation of any kind (not just a normalization mismatch between validate/write steps), a mixed-separator or platform-specific path form always resolves exactly where `os.OpenFile`/`os.Mkdir`/`os.Symlink` interpret it — i.e., there is no divergent "validation path" to bypass, because none exists.

### Impact Explanation
A GitLab job author who controls a cache or artifact archive consumed by the Runner (e.g., a cache restored on a later job, or an artifact produced by an upstream job and downloaded by a downstream job/pipeline) can craft a ZIP with entries named e.g. `../../../../home/gitlab-runner/.ssh/authorized_keys` or an absolute path, causing the Runner process to write or overwrite files outside the job's build/cache directory on the host or container running the executor. This can lead to arbitrary file write within the Runner's filesystem permissions, potentially achieving persistence or privilege escalation on shared runners (shell executor) or breaking out of the intended cache/artifact directory in other executors that share a filesystem mount.

### Likelihood Explanation
No privileged access is required — any pipeline author who can produce a job artifact/cache (their own job) can construct the malicious zip content consumed later by Runner's extraction code path (`ExtractZipFile`/`ExtractZipArchive`). The bug is deterministic and 100% reproducible: any entry name containing `..` segments or an absolute path is honored without modification.

### Recommendation
Before extracting each entry, canonicalize `file.Name` (convert to OS separators, `filepath.Clean`), reject absolute paths, and verify the resulting path is contained within the target extraction root using a path-containment check like `helpers.IsImmediateChild`-style logic (rooted comparison via `filepath.Rel` and rejecting results starting with `..` or being non-relative), applying it in `extractZipFile`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry` before any `os.MkdirAll`, `os.OpenFile`, `os.Mkdir`, or `os.Symlink` call. Also validate symlink targets to prevent writing symlinks that point outside the root.

### Proof of Concept
```go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    dir := t.TempDir()
    outsideMarker := filepath.Join(t.TempDir(), "pwned.txt")

    tempFile, _ := os.CreateTemp("", "archive")
    defer os.Remove(tempFile.Name())
    archive := zip.NewWriter(tempFile)

    // relative segments escaping the root
    relPath, _ := filepath.Rel(dir, outsideMarker)
    w, _ := archive.Create(relPath) // e.g. "../../tmp/xxx/pwned.txt"
    io.WriteString(w, "pwned")
    archive.Close()
    tempFile.Close()

    wd, _ := os.Getwd()
    os.Chdir(dir)
    defer os.Chdir(wd)

    err := ExtractZipFile(tempFile.Name())
    require.NoError(t, err)

    // Assert: file must NOT exist outside dir
    _, statErr := os.Stat(outsideMarker)
    assert.True(t, os.IsNotExist(statErr), "extraction must not escape target root")
}
```
Expected current behavior: the assertion fails — `pwned.txt` is created outside `dir`, proving the traversal. A fixed implementation should reject or clamp the entry and keep the assertion passing.

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}

// IsImmediateChild checks if child is an immediate subdirectory of parent.
// Both paths are cleaned and converted to absolute paths before comparison.
// If it is not able to determine the relative path between parent and child, returns false.
func IsImmediateChild(parent, child string) bool {
	rel, err := filepath.Rel(filepath.Clean(parent), filepath.Clean(child))
	return err == nil && rel != "." && !strings.HasPrefix(rel, "..") && !strings.Contains(rel, string(filepath.Separator))
}

func (p *windowsPath) Contains(basePath, targetPath string) bool {
