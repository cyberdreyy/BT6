### Title
Removed multisig member's stale confirmation still counts toward execution threshold - ([File: multisig2/src/lib.rs])

### Summary
`DeleteMember` in the `multisig2` contract only purges requests that the removed member *authored*, but never scans other pending requests' confirmation sets for entries left behind by that member as a *confirmer*. Because `confirm()` only checks the raw size of the confirmations `HashSet` against `num_confirmations`, a request can later execute counting a confirmation from an account/key that is no longer a multisig member, letting the request run below the actual number of live authorizing signers.

### Finding Description
`confirm()` determines whether to execute a request purely by counting the size of the stored confirmation set: `confirmations.len() as u32 + 1 >= self.num_confirmations` [1](#0-0) . Nothing re-validates, at confirm-time or at member-removal time, that every entry already present in `confirmations` still corresponds to a current member of `self.members`.

`delete_member()` cleans up state for the removed member, but its cleanup of `requests`/`confirmations` is scoped only to requests where `r.member == member`, i.e. requests the removed member originally *authored* — not requests they had merely *confirmed*: [2](#0-1) 

If member `D` confirms an unrelated pending request `R` (adding `D`'s serialized identity string to `R`'s confirmation set), and is subsequently removed from the multisig via a legitimate `DeleteMember{D}` execution, `R`'s confirmation set still contains `D`'s string. `delete_member` never iterates `self.confirmations` to strip `D` out of `R`. Later, when a live member confirms `R`, the stale entry from `D` is counted alongside the live confirmer(s), and the request executes once the *counted* size reaches `num_confirmations` — even though fewer than `num_confirmations` currently-live members ever approved it.

This breaks the intended custody binding: "confirmations counted" (the size of the stored `HashSet<String>`) must equal "confirmations from live members" (accounts/keys presently in `self.members`). The bug class mirrors the SP1 advisory's root cause: trusting a previously-recorded value (an index/flag/confirmation) without re-validating it against the authoritative current state (verifying-key chip names / `is_complete` constraints / member set) before it is consumed to authorize an action.

### Impact Explanation
`execute_request` can perform `Transfer`, `AddKey`/`AddFullAccessKey`, `DeployContract`, `AddMember`, or arbitrary `FunctionCall` on the multisig's own account once the (partially stale) threshold is reached [3](#0-2) . Since NEAR/wNEAR transfers and account-controlling actions are gated purely by this confirmation count, a request can be pushed through execution with fewer genuinely live/authorized signers than the configured `num_confirmations` threshold — i.e., a multisig request executed below its true threshold, moving funds or granting access keys without the intended level of authorization. This matches the "Critical" impact class explicitly listed in scope (a multisig request executed below threshold).

### Likelihood Explanation
The attack requires no privileged position beyond being (or having been) an ordinary multisig member/key holder at some point, plus the removal of that member happening through the contract's normal `DeleteMember` flow (which itself requires the confirmation threshold, but is a routine operation — e.g. rotating keys, offboarding a member, or a member removing their own compromised/lost key). Any member can leave a "landmine" confirmation on a pending request before being removed, or the timing can occur incidentally (member confirms request R, then later gets removed for unrelated reasons) without any special coordination or attacker-controlled deployment. The `add_key_delete_key_storage_cleared` test in the same file demonstrates that the developers were aware requests needed to be pruned on member deletion, but only handled the "authored by removed member" case, not the "confirmed by removed member" case [4](#0-3) .

### Recommendation
When executing `DeleteMember`, iterate all entries of `self.confirmations` (not just `self.requests` filtered by `r.member == member`) and remove the deleted member's identity string from every confirmation set. Alternatively (and more robustly), change `confirm()` to recompute the live confirmation count by filtering the stored confirmation set against `self.members.contains(...)` before comparing against `num_confirmations`, so that stale entries from removed members never count toward the threshold regardless of cleanup completeness.

### Proof of Concept
1. Initialize `MultiSigContract::new([A, B, C, D], 3)` (`num_confirmations = 3`).
2. `A` (or any member) calls `add_request` to create request `R` = `Transfer{amount}` to some receiver.
3. `D` calls `confirm(R)` → `confirmations(R) = {D}` (1/3, no execution) — see `confirm` logic [5](#0-4) .
4. Separately, members `A, B, C` create and confirm a `DeleteMember{D}` request (3/3), which executes `delete_member(promise, D)`. This only removes requests authored by `D`; `R` (authored by `A`, merely confirmed by `D`) is untouched, and `confirmations(R)` still contains `D`'s string — see `delete_member` [2](#0-1) . `D` is now removed from `self.members`.
5. `A` calls `confirm(R)`. `confirmations(R).len() == 1` (the stale `D` entry) `+ 1 == 2`... to actually hit `>= 3`, one more live member's confirmation is needed — e.g. `B` also confirms: `confirmations(R) = {D, A}`, then `B` confirms → count becomes `2 + 1 = 3 >= 3`, and `execute_request` fires the `Transfer`.
6. Result: the transfer executed with confirmations from only `A` and `B` (2 live members) plus a stale entry from `D`, who was no longer a member of the multisig at execution time — one fewer live confirmer than the configured `num_confirmations = 3` threshold.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(

                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),

                    }
                }

                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name,
                    args.into(),
                    deposit.into(),
                    Gas::from(gas.0),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
