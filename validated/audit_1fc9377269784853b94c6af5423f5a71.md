### Title
Zip extraction performs `os.Lchown`/`lchmod` (and file writes) on unsanitized `file.Name`, enabling path traversal to overwrite ownership/permissions outside the extraction root - ([File: helpers/archives/zip_extract.go], [File: helpers/archives/zip_extra_unix.go], [File: helpers/archives/os_unix.go])

### Summary
`ExtractZipArchive` never validates or cleans `zip.File.Name` against directory traversal (`../`) or absolute paths before using it in `os.Mkdir`, `os.OpenFile`, `os.Symlink`, `lchmod`, and `processZipUIDGidField`'s `os.Lchown`. The only existing guard, `errorIfGitDirectory`, only blocks paths whose first cleaned component is `.git` and does nothing to stop traversal outside the extraction root.

### Finding Description
`ExtractZipArchive` iterates `archive.File` twice: first calling `extractZipFile(file)` [1](#0-0) , which uses `file.Name` directly to `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.Mkdir`, `os.OpenFile`, or `os.Symlink` with zero sanitization [2](#0-1) . The second loop then calls `lchmod(file.Name, file.Mode())` and `processZipExtra(&file.FileHeader)` on that same unsanitized `file.Name` [3](#0-2) . `processZipExtra` dispatches to `processZipUIDGidField`, which parses attacker-supplied `ZipUIDGidField` extra-field bytes (UID/GID chosen freely by whoever crafts the archive) and calls `os.Lchown(file.Name, uid, gid)` directly on that path [4](#0-3) . `lchmod` similarly calls `unix.Fchmodat` on the raw `file.Name` with `AT_SYMLINK_NOFOLLOW` [5](#0-4) .

The only path check present anywhere in this package, `errorIfGitDirectory`/`isPathAGitDirectory`, only rejects paths whose first `filepath.Clean` component equals `.git`; it does not reject `../`-prefixed names, absolute paths, or symlink-based traversal (e.g., first entry is a symlink `foo -> /etc`, second entry named `foo/passwd`) [6](#0-5) . There is no `filepath.Rel`/prefix check anywhere in `helpers/archives` confirming extracted paths stay under the extraction root — confirmed by the absence of any such check in the whole `helpers/archives` package.

Exploit flow: an unprivileged job supplies or generates a zip archive (e.g., as a cache or artifact, or via `ziplegacy` extractor used by `commands/helpers` [7](#0-6) ) whose entries include a `Name` like `../../some/outside/path` (or a symlink-traversal chain) plus a `ZipUIDGidField` extra field. First pass writes/creates the file/symlink at that outside path (subject to normal filesystem permission on the runner process); second pass calls `lchmod` and `os.Lchown` on the same resolved outside path, changing its mode bits and (if the runner process has `CAP_CHOWN`/root, common for many CI executor setups) its owning UID/GID.

### Impact Explanation
An unprivileged job can, at minimum, overwrite/chmod files outside its intended extraction root (its own workspace) that its process has write access to — a classic "zip slip" write-anywhere-writable primitive, worsened here because the second loop unconditionally re-chmods and (if privileged) re-chowns that external path using attacker-controlled mode/UID/GID values. If the runner's build/helper process ever runs with elevated privileges (root or `CAP_CHOWN`) — which is common in some executor configurations for artifact/cache extraction — this becomes ownership-and-permission tampering of files outside the job's own workspace (e.g., another project's cache directory or a shared helper binary path if reachable/writable), which can seed a privilege-escalation chain when a later, more-privileged process reads/executes that file.

### Likelihood Explanation
Feasible and repeatable: crafting a zip with a traversal `Name` and a `ZipUIDGidField` extra record is trivial with any zip-writing library and doesn't require any special access beyond controlling the archive contents (job-supplied artifact/cache zip, or content downloaded during the job that gets extracted by `ExtractZipArchive`/`ziplegacy.extractor`). The only gating factor for the `Lchown` half is whether the runner's extraction process has permission to chown to arbitrary UIDs (root/`CAP_CHOWN`); the file-write and `lchmod` halves work regardless of privilege level, as long as the target path is writable by the job's own user, which is enough to demonstrate the missing-sanitization bug even without full ownership escalation.

### Recommendation
Before performing any filesystem operation with `file.Name` (`Mkdir`, `MkdirAll`, `OpenFile`, `Symlink`, `lchmod`, `Lchown`), resolve the target against a fixed extraction root and reject/skip entries where the cleaned, joined path escapes that root (standard zip-slip mitigation: `filepath.Join(root, file.Name)` then verify `filepath.Rel(root, joined)` doesn't start with `..` or isn't absolute). Apply this check once per entry before either extraction loop, and make `lchmod`/`os.Lchown` operate only on paths that passed the check.

### Proof of Concept
Go unit test added to `helpers/archives/zip_extract_test.go`:
1. Build an in-memory zip with:
   - Entry `Name: "../outside/pwn"`, regular file content, plus a `ZipUIDGidField` extra field (Type `0x7875`) encoding an arbitrary UID/GID (e.g., 1000).
2. Set up a temp extraction directory, `chdir` into it, and call `ExtractZipArchive` on the crafted `*zip.Reader`.
3. Assert that no file was created at `<tempdir>/../outside/pwn` (i.e., outside the extraction root), and that `os.Lstat` on that resolved path either fails (`os.IsNotExist`) or, if the platform test double-tracks syscalls, assert `os.Lchown`/`lchmod` were never invoked for paths whose `filepath.Rel(root, path)` starts with `..`.
4. Expected (current, failing) result: the file is created at the traversal path outside `tempdir`, and `lchmod`/`os.Lchown` execute against it — demonstrating the missing containment check.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```

```go
func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
}
```

```go
func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
```
