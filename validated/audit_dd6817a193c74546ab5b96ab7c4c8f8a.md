### Title
Stale write-off requests never expire and remain fillable by anyone at outdated prices - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary
`createWriteOffRequest` is gated to a running epoch, but `fullfillWriteOffRequest` has no expiry and no epoch-state check at all. A request priced against the tranche value at creation time remains executable by any wallet indefinitely. As epochs accrue interest and the tranche appreciates (or after a default/recovery repricing), a stale request becomes a free option that any fulfiller can exercise against the lender, extracting the difference between the stale ask and the current tranche value. This is the exact analog of "pending change never expires and can be executed by anyone": the request is a pending, user-priced swap that can be executed in any later state.

### Finding Description
- `createWriteOffRequest` requires `isEpochRunning()` and locks `tranches` + a fixed `underlyings` ask in `userRequests[msg.sender]` [1](#0-0) .
- `fullfillWriteOffRequest(_user, _tranches, _underlyings)` is callable "by any wallet" with no epoch gating, no deadline, and no repricing — it only checks `_underlyings >= currentRequest.underlyings` [2](#0-1) .
- There is no `createdAt`/expiry field in `WriteOffRequest` [3](#0-2) .

Attack trace:
1. During a running epoch, lender creates a request: escrows `T` tranche tokens, asks `U` underlyings, pricing near current NAV.
2. One or more epochs complete. `stopEpoch` credits interest, so `virtualPrice`/`tranchePrice` rises; the escrowed `T` tranches are now worth `T * price_N+k > U`.
3. An unprivileged attacker EOA calls `fullfillWriteOffRequest(lender, T, U)`, pays the stale `U`, receives the appreciated tranches, then redeems them through the normal `claimWithdrawRequest`/epoch-withdraw flow (or holds them for a default-recovery claim if the pool defaults), pocketing the accrued yield that economically belonged to the lender.
4. If the lender notices and calls `deleteWriteOffRequest`, the attacker front-runs the cancel and fills in the same block — the fill path has no defense.

The broken invariant is fair value transfer / time-bounded consent: the lender consented to `U` underlyings *at creation-time pricing*, not in perpetuity. Existing guards do not stop this: `nonReentrant` is irrelevant, the `WrongRequest` check only enforces the stale terms, and `deleteWriteOffRequest` cannot win against an atomic fill.

### Impact Explanation
Direct theft of accrued yield from the lender. Loss is quantified as `T * (price_at_fill − price_at_create)` — the interest accrued on the escrowed tranches while the request sat unfilled. For requests left across many epochs (the exact "forgotten pending change" scenario of the source report), the spread grows with cumulative epoch interest; after a `stopEpochWithDuration(_lossAmount)` or default repricing the asymmetry can be even larger. A secondary consequence: `pendingUnderlyings` remains permanently inflated by dead requests, distorting any off-chain fulfilment accounting.

### Likelihood Explanation
Medium. It requires a lender to leave a request open across epoch boundaries (plausible — there is no incentive or mechanism forcing cancellation, and requests are explicitly designed to wait for a borrower/fulfiller) and tranche appreciation, which happens every epoch by design. The attacker needs no privilege: any EOA can call `fullfillWriteOffRequest`.

### Recommendation
Add an expiry to `WriteOffRequest` (e.g., `createdAt` / `deadline` or the epoch number at creation) and revert in `fullfillWriteOffRequest` once expired or once the epoch has rolled over (`block.timestamp > deadline`, or `IdleCreditVault(strategy).epochNumber() != requestEpoch`), letting `deleteWriteOffRequest` reclaim stale escrows. Optionally also gate fulfillment to `isEpochRunning()` to match creation semantics.

### Proof of Concept
Foundry fork PoC outline (extend `test/foundry/IdleCreditVault.t.sol` harness):

```solidity
// setup: lender deposits AA, epoch running
vm.prank(manager);
cdoEpoch.startEpoch();

uint256 tranches = aaTranche.balanceOf(lender);
uint256 ask = tranches * cdoEpoch.virtualPrice(address(aaTranche)) / 1e18;

// lender prices request at current NAV
vm.prank(lender);
aaTranche.approve(address(escrow), tranches);
vm.prank(lender);
escrow.createWriteOffRequest(tranches, ask);

// epochs pass; stopEpoch credits interest -> tranche appreciates
for (uint i; i < 3; i++) {
    deal(underlying, borrower, _expectedFundsEndEpoch());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(apr, 0);
    vm.prank(manager);
    cdoEpoch.startEpoch();
}

// attacker fills the stale, still-open request at the old price
uint256 attackerBalPre = aaTranche.balanceOf(attacker);
deal(underlying, attacker, ask);
vm.prank(attacker);
IERC20(underlying).approve(address(escrow), ask);
vm.prank(attacker);
escrow.fullfillWriteOffRequest(lender, tranches, ask); // succeeds despite N epochs passing

uint256 currentValue = tranches * cdoEpoch.virtualPrice(address(aaTranche)) / 1e18;
assertGt(currentValue, ask); // attacker stole currentValue - ask of accrued yield
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }
```

```text
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }
```
