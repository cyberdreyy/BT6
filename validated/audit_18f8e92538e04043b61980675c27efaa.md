## Finding

### Title
Unregistered shareholder can permanently freeze `distribute()`/`distribute_internal()` for all other shareholders in `vesting::distribute` and `staking_contract::distribute_internal` - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`, `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`vesting::distribute` and `staking_contract::distribute_internal` iterate over *all* shareholders of a shared pool and push coins to each recipient via `aptos_account::deposit_coins` inside the same atomic transaction. If any single recipient is not yet registered for `AptosCoin` and has disabled direct coin transfers (`aptos_account::set_allow_direct_coin_transfers(false)`), `deposit_coins` aborts. Because the abort happens mid-loop, the *entire* distribution transaction reverts, permanently blocking distribution to every other, unrelated shareholder — this is the exact "blacklisted-recipient blocks the shared-refund path" pattern from the external report, just implemented with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` instead of an ERC-20 blacklist revert.

### Finding Description
`vesting::distribute` withdraws all distributable stake once, then loops over `grant_pool.shareholders()` and calls `aptos_account::deposit_coins(recipient_address, share_of_coins)` for each one: [1](#0-0) 

`staking_contract::distribute_internal` does the analogous thing over the `distribution_pool` shareholders (staker + operator/beneficiary), calling `aptos_account::deposit_coins(recipient, ...)` for each redeemed share inside a `while` loop: [2](#0-1) 

`aptos_account::deposit_coins` will only auto-register the recipient and proceed if the recipient allows direct transfers; otherwise it aborts: [3](#0-2) 

Any account holder can disable direct transfers for themselves at any time, without needing any special privilege and without ever holding or registering `AptosCoin` (e.g. via a sponsored/fee-payer transaction that doesn't require the signer to own gas): [4](#0-3) 

Neither `vesting::create_vesting_contract`/`vesting::distribute` nor `staking_contract`'s distribution path validates ahead of time that every shareholder in the shared pool is (and will remain) registered/willing to accept direct coin transfers before the funds are pulled out of the stake pool and the shared distribution loop begins. `assert_account_is_registered_for_apt` exists in the codebase but is not applied per-shareholder in this loop before iterating — it is only used for the `withdrawal_address` in unrelated call sites.

### Impact Explanation
Once `distribute()` (vesting) or `distribute()`/`distribute_internal()` (staking_contract) begins iterating shareholders and hits one that cannot accept the deposit, the Move VM aborts the whole transaction, rolling back the stake withdrawal too. As long as that address still owns nonzero shares in the shared `grant_pool`/`distribution_pool`, every future call to `distribute()`/`distribute_many()`/`request_commission`-triggered `distribute_internal` (which force-distributes any already-inactive stake before proceeding) will hit the same abort and fail identically. This permanently strands:
- All other shareholders' vested/reward APT in `vesting::distribute`.
- The staker's principal withdrawal and the operator's/beneficiary's commission in `staking_contract`, since `unlock_stake` and `request_commission` both call `distribute_internal` first.

This is a permanent, non-recoverable loss of claim rights for uninvolved parties sharing the same vesting contract or staking contract — matching the "Permanent lock or non-recoverable loss of claim rights in stake, delegation, commission, beneficiary, or vesting flows" impact category.

### Likelihood Explanation
Likelihood is credible but not trivial:
- The griefing party must already be a shareholder of the vesting contract or be the staker/operator/beneficiary of the staking contract (this membership is set by the vesting/staking admin, not attacker-controlled at will).
- The griefing party must not yet be registered for `AptosCoin` at the time of griefing and must call `set_allow_direct_coin_transfers(false)` — achievable via a sponsored/fee-payer transaction without ever holding APT, so no capital is required.
- Once triggered, the DoS is durable and low-cost to maintain (the attacker only needs to keep direct transfers disabled and stay unregistered).

This is realistically triggerable on mainnet for any freshly-added vesting shareholder or a staking-contract staker/beneficiary who has not yet interacted with `AptosCoin`.

### Recommendation
- Before pulling funds out of the stake pool and starting the distribution loop, validate that every shareholder (or at least skip/queue individually) can currently receive `AptosCoin`, and do not let one recipient's failure abort the whole batch.
- Prefer a per-recipient try/catch-like pattern (not natively available in Move) or restructure to write successfully-distributed amounts durably (e.g., in `pool_u64` shares) as soon as each individual deposit succeeds, and skip (not abort) recipients that currently cannot accept direct transfers, leaving their share balance intact for later withdrawal by them.
- Alternatively, require/lock a recipient's `AptosCoin` registration and direct-transfer opt-in state at admission time and disallow the shareholder from disabling it while unpaid distributions are outstanding.

### Proof of Concept
1. Admin creates a vesting contract with shareholders `[S1, S2]` via `create_vesting_contract`, `S2` being a freshly generated address that has never interacted with `AptosCoin`. [5](#0-4) 
2. `S2`, using a sponsored/fee-payer transaction (no APT needed), calls `aptos_account::set_allow_direct_coin_transfers(S2_signer, false)`. [6](#0-5) 
3. Time passes; rewards/vested tokens accumulate and become withdrawable from the stake pool.
4. Anyone calls `vesting::distribute(contract_address)`. The function withdraws the funds, then iterates shareholders; when it reaches `S2` it calls `aptos_account::deposit_coins(S2, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` because `S2` is unregistered and has opted out. [7](#0-6) 
5. The transaction reverts entirely; `S1`'s rewards are never distributed, and every subsequent call to `distribute`/`distribute_many` fails the same way as long as `S2` retains nonzero shares — permanently locking `S1`'s funds in the vesting contract's stake pool.

The same sequence applies to `staking_contract::distribute`/`unlock_stake`/`request_commission` via `distribute_internal`, where a griefing staker or beneficiary blocks payout of both the staker's principal and the operator's commission. [8](#0-7)

    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

    /// Allow anyone to distribute already unlocked funds. This does not affect reward compounding and therefore does
    /// not need to be restricted to just the staker or operator.
    public entry fun distribute(
        staker: address, operator: address
    ) acquires Store, BeneficiaryForOperator {
        assert_staking_contract_exists(staker, operator);
        let store = borrow_global_mut<Store>(staker);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);
        distribute_internal(
            staker,
            operator,
            staking_contract,
        );
    }

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
    /// receive.
    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
    }
