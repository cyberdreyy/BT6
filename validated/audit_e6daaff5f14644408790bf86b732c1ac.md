### Title
Symlink-as-directory-component write outside job root during zip extraction - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and later `os.OpenFile`/`os.Remove` on `file.Name` without checking whether any path component is a symlink created earlier in the same archive by `extractZipSymlinkEntry`. Because Go's `os.MkdirAll`/`os.OpenFile` follow symlinks when resolving intermediate path components, an attacker-crafted archive containing a symlink entry followed by a file entry that uses the symlink name as a path prefix (e.g. `link` -> `/tmp/foo`, then `link/evil`) can cause writes to land at the resolved symlink target instead of inside the extraction root.

### Finding Description
`extractZipSymlinkEntry` (helpers/archives/zip_extract.go:22-39) creates a symlink with `os.Symlink(string(data), file.Name)`, where `data` is fully attacker-controlled (it's just the entry's file content) and `file.Name` is also attacker-controlled. There is no validation that the symlink target stays inside the extraction directory, and no validation of `file.Name` itself (no zip-slip check for `..` or absolute names either, though that is a related but separate issue).

`extractZipFile` (helpers/archives/zip_extract.go:61-83) is invoked per-entry in `archive.File` order (attacker controls ordering since it's their zip file). For a later entry named e.g. `link/evil`:
- `filepath.Dir("link/evil")` = `"link"`.
- `os.MkdirAll("link", 0o777)` — if `link` is a symlink to an existing directory, `MkdirAll` calls `os.Stat` on the path (which follows the symlink), finds it "already a directory", and returns `nil` without error, `does not error out`.
- `extractZipFileEntry` then runs `os.Remove("link/evil")` and `os.OpenFile("link/evil", O_WRONLY|O_CREATE|O_TRUNC, ...)`. Both of these resolve the `link` component by following the symlink, so the actual write lands at `<symlink-target>/evil`, not under the intended job/cache/artifact extraction root.

Existing checks in this file are limited to `errorIfGitDirectory` (helpers/archives/path_check_helper.go:21-31), which only blocks `.git`-prefixed paths, and `pathErrorTracker`, which only deduplicates repeated warning logs — neither validates symlink targets or blocks path traversal through symlinks. There is no code anywhere in `ExtractZipArchive` that lstat's intermediate directory components to confirm they are real directories created during this extraction (as opposed to symlinks resolving elsewhere).

Note: the simpler "same name reused" variant described in the prompt (`link` symlink followed by a regular file entry also named `link`) is not exploitable, because `os.Remove(file.Name)` in `extractZipFileEntry`/`extractZipSymlinkEntry` removes the symlink itself rather than following it, and the subsequent `OpenFile`/`Symlink` recreates `link` as a plain new object at that path. The actual reachable exploit path is the "symlink used as a directory prefix for a *different* file name" variant (`link/evil`), which does bypass containment as described above.

### Impact Explanation
An attacker who controls a cache or artifact zip archive (job author supplying `cache`/`artifacts` paths, or a cache poisoning scenario against a shared runner) can, via `ExtractZipArchive`, cause subsequent file-entry writes to be redirected to any directory the job's OS user can write to and that the job process can reference by symlink (e.g. other paths under the runner's builds directory on a shared shell/docker executor host, other job workspaces if paths are reused, or arbitrary writable locations reachable by the executing user). This is a file-write-outside-extraction-root primitive, matching the "File operations must stay within intended build/cache/artifact roots" invariant. Actual reach beyond the job's own writable filesystem area depends on OS permissions of the process running the extraction, and on shared/host-level path reuse (shell executor), which limits blast radius on properly isolated executors (Docker/Kubernetes) but is real on shell executors or in cache-poisoning scenarios where an artifact/cache tarball is later re-extracted with elevated context.

### Likelihood Explanation
Fully feasible and repeatable: the attacker only needs to control the contents of a cache or artifact zip that will later be extracted by `ExtractZipArchive`/`ExtractZipFile` (both cache and artifact restoration paths use this code, per `cache/cache.go` and `commands/helpers/cache_extractor_test.go` referencing zip extraction). No special runner privileges are needed; it requires crafting a zip with a symlink entry and a following regular-file entry whose name has the symlink name as a directory-path prefix — trivially constructible with Go's `archive/zip` package or any zip tool that permits symlink entries (Unix external file attributes with `S_IFLNK`).

### Recommendation
In `extractZipFile`, before calling `os.MkdirAll(filepath.Dir(file.Name), ...)` and before opening/removing `file.Name`, walk each path component with `os.Lstat` (not `Stat`) and reject/skip the entry if any component that should be a plain directory is actually a symlink (or does not resolve to something created within the current extraction root). Alternatively, resolve `filepath.EvalSymlinks` on the parent directory and verify the resolved path is still within the extraction root (`strings.HasPrefix` after `filepath.Clean`, with a trailing separator to avoid prefix-substring bypass), rejecting extraction otherwise. Additionally, validate `extractZipSymlinkEntry`'s target path (`string(data)`) against the same containment check, rejecting symlinks whose target escapes the extraction root, and add zip-slip validation of `file.Name` itself (reject absolute paths or paths containing `..` that escape the root) since that is currently unchecked as well.

### Proof of Concept
Go unit test to add to `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipFileSymlinkDirTraversal(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        outsideDir := t.TempDir() // simulates a writable path outside extraction root

        f, err := os.Create(fileName)
        require.NoError(t, err)

        archive := zip.NewWriter(f)
        // symlink entry "link" -> outsideDir
        hdr := &zip.FileHeader{Name: "link"}
        hdr.SetMode(os.ModeSymlink | 0o777)
        w, err := archive.CreateHeader(hdr)
        require.NoError(t, err)
        _, err = w.Write([]byte(outsideDir))
        require.NoError(t, err)

        // regular file entry "link/evil" using the symlink as a directory prefix
        w2, err := archive.Create("link/evil")
        require.NoError(t, err)
        _, err = w2.Write([]byte("pwned"))
        require.NoError(t, err)

        require.NoError(t, archive.Close())
        require.NoError(t, f.Close())

        err = ExtractZipFile(fileName)
        require.NoError(t, err)

        // Assert: content must NOT have been written outside the extraction root
        _, statErr := os.Stat(filepath.Join(outsideDir, "evil"))
        assert.True(t, os.IsNotExist(statErr),
            "expected extraction to be contained; found file written via symlink outside root")
    })
}
```

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
