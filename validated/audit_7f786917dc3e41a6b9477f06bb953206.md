### Title
Attacker-controlled `parameters` length in `createDstEscrow` bricks both private and public destination withdrawal — (File: `contracts/EscrowDst.sol`, `contracts/libraries/ImmutablesLib.sol`)

### Summary
`createDstEscrow` accepts arbitrary `Immutables.parameters` bytes from any unprivileged caller with no length/shape validation. `EscrowDst._withdraw`, used by both `withdraw` and `publicWithdraw`, unconditionally calls `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd`, which revert `IndexOutOfRange()` if `parameters.length < 0x40`/`0x20`. A `parameters` blob shorter than 64 bytes makes every withdrawal call revert — permanently, for both the private taker path and the public access-token-holder path — regardless of a valid secret.

### Finding Description
`createDstEscrow` is a permissionless entrypoint; the caller fully controls the `Immutables` struct including `parameters`, and only checks the funding amount and cancellation-timestamp ordering — never the encoding/length of `parameters`. The immutables (including the malformed `parameters`) are hashed into the CREATE2 salt and later re-checked only for equality (`onlyValidImmutables`), not well-formedness. Both `withdraw` (private, `onlyCaller(taker)`) and `publicWithdraw` (public, `onlyAccessTokenHolder`) call the shared `_withdraw`, which reads `integratorFeeAmountCd()` first. If `parameters.length < 64`, this reverts unconditionally, before any fee/amount logic executes and irrespective of secret correctness or timelock stage. The public-withdrawal safety valve — intended to let any access-token holder finalize the swap if the taker is unresponsive — therefore cannot rescue the escrow. The only remaining exit is `cancel()`, callable only by `taker`, after `DstCancellation`, which returns the deposited amount to `taker`, not `maker`.

### Impact Explanation
This breaks the intended invariant that a funded destination escrow with a known secret can always be settled via at least the public-withdrawal fallback. In the normal cross-chain-swap flow, a malicious taker who already extracted the maker's source-chain funds (using the same secret) can deploy the destination escrow with a sub-64-byte `parameters` field, guaranteeing the maker never receives the corresponding destination payout via `withdraw`/`publicWithdraw`, and later reclaim the destination-side deposit for themselves via `cancel()` once the cancellation window opens. This matches "temporary freezing of funds during the live swap lifecycle" (High) at minimum, and can escalate to a maker fund-loss scenario when chained with the source-chain withdrawal by the same malicious taker.

### Likelihood Explanation
High. `createDstEscrow` requires no privilege beyond funding the escrow (which the taker/resolver normally does anyway), and crafting a 31-byte `parameters` value is trivial. No existing check in `createDstEscrow`, `_withdraw`, or `ImmutablesLib` prevents this.

### Recommendation
Validate `dstImmutables.parameters` length/shape inside `createDstEscrow` (e.g., require it be exactly `0` or exactly the expected fixed size for the four fee fields, `0x80` bytes), rejecting any other length before deployment. Alternatively, make `ImmutablesLib`'s fee getters return `0`/safe defaults for short-but-otherwise-benign lengths, and require full-size (`0x80`) parameters for anything that encodes fee data, so a malformed blob cannot silently gate the withdrawal path.

### Proof of Concept
1. Attacker calls `createDstEscrow` with a legitimate `hashlock`, `maker`, `amount`, `safetyDeposit`, valid `timelocks`, but sets `parameters = <31 arbitrary bytes>`, funding the escrow with `msg.value`/ERC20 as required. [1](#0-0) 
2. Once `DstWithdrawal` stage begins, taker calls `withdraw(secret, immutables)`; `_withdraw` calls `integratorFeeAmountCd()`, which checks `parameters.length < 0x40` (31 < 64) and reverts `IndexOutOfRange()`. [8](#0-7) 
3. Warp to `DstPublicWithdrawal`; any access-token holder calls `publicWithdraw(secret, immutables)` — same `_withdraw` path, same revert. [6](#0-5) 
4. Only `cancel()` after `DstCancellation`, callable solely by `taker`, unlocks the funds — refunding `taker`, never `maker`. [7](#0-6)

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }

        }
