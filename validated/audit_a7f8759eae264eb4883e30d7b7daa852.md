### Title
Unauthenticated arbitrary state write via `replace()` in state-manipulation contract - (File: state-manipulation/src/lib.rs)

### Summary
The `replace()` entrypoint in the state-manipulation utility contract decodes a caller-supplied JSON payload and writes every `(key, value)` pair directly into contract storage via raw `storage_write` syscalls, with no check on `predecessor_account_id`, ownership, or any other authorization gate. Any account can call this method on any account where this contract is (still) deployed and overwrite arbitrary storage keys, including `STATE`, letting them fabricate the persisted contract struct (e.g. `owner_account_id` of a lockup/staking/multisig contract) to redirect custody of the account's NEAR on the next call.

### Finding Description
The broken binding: `storage state at key K == value only the entitled party (self/owner) requested`. In practice: `env::predecessor_account_id() == <required privileged caller>` should be checked before any `storage_write`, but it never is.

Code path: `replace()` reads raw input via `input()`, deserializes it into `entries: Vec<(&str, &str)>`, and for each pair calls `storage_write(&base64::decode(key)?, &base64::decode(value)?)` with no caller check whatsoever: [1](#0-0) 

`storage_write` itself is a thin unsafe wrapper around `near_sys::storage_write` with no assertion logic: [2](#0-1) 

There is no `assert_self()`, `assert_owner`, `predecessor_account_id` comparison, or any access-control primitive anywhere in the file — the entire 195-line source contains no such guard.

Exploit flow, given the stated precondition (the contract is deployed on the target account, as acknowledged by the README describing it as a maintenance/migration tool intentionally left on "intermediate accounts"): an attacker (any unprivileged account) sends a transaction calling `replace` on the victim account with `{"entries":[["<base64 STATE>", "<base64 bytes of a forged LockupContract/StakingContract/MultiSigContract struct with attacker-controlled owner_account_id>"]]}`. Since no check exists on who the caller is, the write succeeds and the victim account's `STATE` is overwritten with attacker-chosen bytes.

### Impact Explanation
Once `STATE` is overwritten with a forged struct (e.g., setting `owner_account_id` to the attacker), any subsequent call into the "real" contract logic (once/if the real contract code is present or redeployed on top, or as combined with other state fields) will treat the attacker as the legitimate owner, enabling withdrawal or transfer of the account's NEAR balance. This matches the Critical category: "NEAR or wNEAR moved out of a pool, lockup, multisig ... by a party not entitled to it" / "an account ... deployed with parameters its rightful creator never chose." The blast radius is scoped strictly to accounts that still have this state-manipulation contract deployed and reachable; it is repeatable against every such account.

### Likelihood Explanation
The only precondition is that the state-manipulation contract remains deployed and callable on a target account holding NEAR — which the question itself notes is a real intermediate/maintenance state that can persist. Given that precondition, exploitation cost is a single transaction with a crafted JSON payload and standard gas; no special privilege, key, or foundation role is required, and it is trivially repeatable across any account in this state.

### Recommendation
Add an explicit authorization check at the top of `replace()` (and `clean()`) comparing `env::predecessor_account_id()` against `env::current_account_id()` (self-call only) or against a hardcoded/owner account, rejecting the call otherwise. Alternatively, ensure this contract is never left deployed on any account holding user funds beyond the atomic migration transaction (deploy, call, redeploy-real-contract in one batched transaction), removing the window during which it's externally callable.

async fn unauthorized_replace_overwrites_state() -> anyhow::Result<()> {

    // Attacker crafts forged STATE bytes naming themselves as owner

    let entries = vec![(base64::encode("STATE"), base64::encode(&forged_state_bytes))];

    // Call replace() from the attacker's account, NOT the contract owner
    attacker
        .call(&worker, contract.id(), "replace")
        .args_json(&serde_json::json!({ "entries": entries }))?
        .max_gas()

    assert_eq!(state_items.get(&b"STATE".to_vec()).unwrap(), &forged_state_bytes);
    // Binding broken: value written == attacker's arbitrary choice,
    // while it should equal only a value predecessor_account_id was authorized to set.
    Ok(())

#[cfg(feature = "replace")]
#[no_mangle]
pub fn replace() {
    #[derive(serde::Deserialize)]
    struct ReplaceInput<'a> {
        #[serde(borrow)]
        entries: Vec<(&'a str, &'a str)>,
    }

    let input = input().unwrap();
    let args: ReplaceInput = serde_json::from_slice(&input).unwrap();
    for (key, value) in args.entries {
        storage_write(
            &base64::decode(key).unwrap(),
            &base64::decode(value).unwrap(),
        );
    }
}
