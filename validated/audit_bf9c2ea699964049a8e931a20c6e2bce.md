## Title
Legacy (v1) signer chainstate skips the tenure-duplicate check for locally-accepted-but-not-globally-accepted blocks, letting a single miner get a signer to sign a conflicting tenure-start block - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
`SortitionsView::validate_tenure_change_payload` in the legacy (v1) signer chainstate path guards against a duplicate tenure-start proposal by calling `SignerDb::get_last_globally_accepted_block`, whereas the newer v2 path (`stacks-signer/src/chainstate/v2.rs`) performs the equivalent check with `SignerDb::get_last_signed_block`, which also covers locally-accepted (signed-but-not-yet-globally-accepted) blocks. The v2 change is an explicit, tested regression fix; v1 was never given the same fix and is still live for signers running the pre-global-state protocol version.

### Finding Description
`check_block_against_state` dispatches to either the global-state path or the legacy local-state path depending on the negotiated protocol version: [1](#0-0) 

The legacy path uses `SortitionsView::check_proposal` (v1), which for a tenure-change block calls `validate_tenure_change_payload`: [2](#0-1) 

The duplicate check there queries only `get_last_globally_accepted_block`: [3](#0-2) 

In contrast, the v2 equivalent explicitly switched to `get_last_signed_block`, which additionally covers `LocallyAccepted` blocks: [4](#0-3) [5](#0-4) 

That the v2 fix was a deliberate correction of exactly this gap is confirmed by the regression test comment: "previously, the check used `get_last_globally_accepted_block`, which would miss blocks in `LocallyAccepted` or `PreCommitted` state and incorrectly allow a duplicate tenure change": [6](#0-5) 

The docs for this exact anchor also call out the divergence between v1 and v2 as intentional/known: "`DuplicateBlockFound` ... v2 counts locally or globally accepted blocks (`get_last_signed_block`); v1 counts only globally accepted ones (`get_last_globally_accepted_block`)": [7](#0-6) 

**Why this breaks the safety equality.** A block reaches `LocallyAccepted` the moment a signer's own weighted acceptances (pre-commits/signatures) cross the 70% *local* threshold, well before it is pushed to the stacks-node and becomes globally accepted: [8](#0-7) 

Because a locally-accepted-but-not-yet-globally-accepted block has never been pushed to the node (`broadcast_signed_block` only fires once `signed_group` is set), the stacks-node's own duplicate/parent checks in `postblock_proposal.rs` (`check_block_has_valid_parent`, `check_block_builds_on_highest_block_in_tenure`) cannot see it either — they only see blocks already committed to the node's chainstate: [9](#0-8) 

So, for any *individual* signer that is running the v1/legacy protocol version and that itself never signed the first tenure-start block for a tenure (e.g., it was slow, offline, or the miner deliberately routed the two competing tenure-start proposals to disjoint subsets of signers via gossip), **both** of the layered defenses fail simultaneously for that signer:
- Node-side: doesn't know about the not-yet-globally-accepted first block, so it can't reject the second block as building on a stale/duplicated tenure.
- Signer-side (v1) proposal check: `get_last_globally_accepted_block` returns `None` (the first block is still merely `LocallyAccepted`), so `DuplicateBlockFound` never fires.

The last remaining backstop is the pre-commit/signing-time "own-tenure conflict guard" in `handle_block_pre_commit`, which relies on `get_signed_conflicts` — but that query only inspects *this signer's own* `signed_self`/`signed_group` state for the tenure's consensus hash: [10](#0-9) [11](#0-10) 

If this particular signer never voted on/signed the first block, it has no row satisfying `signed_self IS NOT NULL OR signed_group IS NOT NULL` for that tenure, so this guard also cannot see the conflict. The signer therefore proceeds through validation, pre-commit, and signing for the second (duplicate/conflicting) tenure-start block despite an equivalent, already-signed sibling for the same tenure existing among other signers — exactly the "two blocks at the same height are siblings" scenario the framework is designed to prevent, as stated by the doc: "signing both would be the double-sign this guard exists for."

This is a direct analog of the Decidim advisory's pattern: a check that is correctly enforced in one code path (the templates permission enforcement Decidim added/fixed) is missing in an adjacent, still-reachable code path (the pre-2023 controllers) — here, the fixed v2 check vs. the unfixed v1 check on the identical `SortitionsView`-style entry point, `check_proposal`.

### Impact Explanation
This lets a single miner (with control over gossip/message delivery order, no majority of signers or private keys required) induce individual v1-protocol signers to place a valid signature over a **conflicting tenure-start block** for a tenure that another signer subset has already locally accepted. This matches the specified Critical impact category: "a signer signing an invalid, non-canonical, or conflicting block." It undermines the one-per-tenure equivocation guarantee the whole pre-commit/conflict-tracking design (sections 5 and 7 of the docs) exists to enforce, and can seed a chain split / signature-set fragmentation across the mixed v1/v2 signer fleet.

### Likelihood Explanation
Requires only a malicious/adversarial miner plus normal gossip-timing control — no signer collusion, no private key compromise, and no majority of signers. It is exploitable specifically against signers still negotiated onto the legacy (v1) protocol version (`determine_active_signer_protocol_version` / `uses_global_state()`), which remains supported code, per `check_block_against_state`'s branch on `state_version.uses_global_state()`. The precondition (some signers locally-accept the first tenure-start block while others have not yet seen/signed it) is a realistic race during ordinary network propagation, not a contrived edge case.

### Recommendation
Change `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload` to use `SignerDb::get_last_signed_block` (matching the v2 fix) instead of `get_last_globally_accepted_block`, so that a `LocallyAccepted` block in the tenure also triggers `RejectReason::DuplicateBlockFound` for v1-protocol signers. Add a v1-equivalent regression test mirroring `check_tenure_change_rejects_when_locally_accepted_block_exists` in `stacks-signer/src/chainstate/tests/v2.rs`.

### Proof of Concept
1. A malicious miner submits tenure-start block `B1` (with a `TenureChange`+`Coinbase`) for tenure `T` and gossips it to signer subset `S1` only.
2. `S1` validates and signs `B1`; assume `S1`'s combined weight reaches the 70% *local* threshold for `S1`'s own view, moving `B1` to `LocallyAccepted` per `store_and_process_block_signature` (`stacks-signer/src/v0/signer.rs:2503-2537`), but the block is not yet pushed to the node (no `broadcast_signed_block` because `signed_group` is not yet observed network-wide), so no node in the network has `B1` in its chainstate.
3. The same miner crafts a second, different tenure-start block `B2` for the *same tenure* `T` (same `consensus_hash`, differing transactions/parent choice) and gossips it only to signer subset `S2`, which is disjoint (or largely disjoint) from `S1` and running the legacy (v1) protocol version.
4. For a signer in `S2` that never received/signed `B1`: node-side validation of `B2` succeeds (the node has no record of `B1`); `SortitionsView::check_proposal` → `validate_tenure_change_payload` (v1) calls `get_last_globally_accepted_block(T)`, which returns `None` (since `B1` is only `LocallyAccepted`, not globally accepted anywhere) — no `DuplicateBlockFound`.
5. `B2` proceeds through node validation and pre-commit. At `handle_block_pre_commit`'s own-tenure conflict guard, `get_signed_conflicts` finds no row for tenure `T` in this signer's own `signerdb` (it never signed `B1`), so the guard does not block signing.
6. The `S2` signer signs `B2`, producing a valid signature over a block that conflicts with `B1`, which other signers have already signed for the same tenure — an equivocation the design otherwise prevents.

    fn validate_tenure_change_payload(
        &self,
        proposed_by: &ProposedBy,
        tenure_change: &TenureChangePayload,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
    ) -> Result<(), RejectReason> {
        // Check that the tenure change's prev_tenure matches the sortition's known parent tenure.
        // This catches block commits with bad parent_block_ptr (e.g., vtxindex=0 exploit).
        let parent_tenure_id = &proposed_by.state().data.parent_tenure_id;
        if &tenure_change.prev_tenure_consensus_hash != parent_tenure_id {
            warn!(
                "Block commit parent tenure mismatch: the block commit's parent_block_ptr does not correspond to the actual parent tenure";
                "committed_parent_tenure" => %parent_tenure_id,
                "actual_parent_tenure" => %tenure_change.prev_tenure_consensus_hash,
                "consensus_hash" => %block.header.consensus_hash,
                "signer_signature_hash" => %block.header.signer_signature_hash(),
            );
            return Err(RejectReason::InvalidParentBlock);
        }

        // Ensure that the tenure change block confirms the expected parent block
        let confirms_expected_parent = SortitionData::check_tenure_change_confirms_parent(
            tenure_change,
            block,
            signer_db,
            client,
            self.config.tenure_last_block_proposal_timeout,
            self.config.reorg_attempts_activity_timeout,
        )
        .map_err(SignerChainstateError::from)?;
        if !confirms_expected_parent {
            return Err(RejectReason::InvalidParentBlock);
        }
        // now, we have to check if the parent tenure was a valid choice.
        let is_valid_parent_tenure = proposed_by.state().data.check_parent_tenure_choice(
            signer_db,
            client,
            &self.config.first_proposal_burn_block_timing,

        if !is_valid_parent_tenure {
            return Err(RejectReason::ReorgNotAllowed);
        }
        let last_in_current_tenure = signer_db
            .get_last_globally_accepted_block(&block.header.consensus_hash)
            .map_err(|e| {
                SignerChainstateError::from(ClientError::InvalidResponse(e.to_string()))
            })?;
        if let Some(last_in_current_tenure) = last_in_current_tenure {
            warn!(
                "Miner block proposal contains a tenure change, but we've already signed a block in this tenure. Considering proposal invalid.";
                "proposed_block_consensus_hash" => %block.header.consensus_hash,
                "proposed_block_signer_signature_hash" => %block.header.signer_signature_hash(),
                "last_in_tenure_signer_signature_hash" => %last_in_current_tenure.block.header.signer_signature_hash(),
            );
            return Err(RejectReason::DuplicateBlockFound);
        }
        Ok(())
    }

    /// Return the last signed block in a tenure (identified by its consensus hash).
    /// A block is considered signed if it is locally or globally accepted. Blocks that
    /// have only been pre-committed are excluded, because a pre-commit does not put a
    /// signature over the block and may be safely superseded by a competing proposal.
    ///
    /// This answers "what is the tenure's signed tip?", a different question from
    /// [`SignerDb::has_signed_block_in_tenure`]'s "does a signature bind us to this tenure?",
    /// which is why the predicates deliberately differ on rejected blocks (see there).
    pub fn get_last_signed_block(
        &self,
        tenure: &ConsensusHash,
    ) -> Result<Option<BlockInfo>, DBError> {
        let query = "SELECT block_info FROM blocks WHERE consensus_hash = ?1 AND state IN (?2, ?3) ORDER BY stacks_height DESC LIMIT 1";
        let args = params![
            tenure,
            &BlockState::GloballyAccepted.to_string(),
            &BlockState::LocallyAccepted.to_string(),
        ];
        let result: Option<String> = query_row(&self.db, query, args)?;

        try_deserialize(result)
    }

        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,

        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,

        ];

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}

                &block.header.parent_block_id,

                reason: "No parent block".into(),

                chainstate,
                sortdb,
                &parent_header.consensus_hash,
                &block.header.parent_block_id,
            )?;
