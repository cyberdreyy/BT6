### Title
Unbounded `OperatorFee` (and other) SystemConfig updates allow the L1 SystemConfig owner to impose unlimited operator fees on every L2 transaction with no sanity bound - ([File: crates/common/genesis/src/updates/operator_fee.rs])

### Summary
The Kairos report flags admin setters (`setMinOfferCost`, `setAuctionDuration`, etc.) that accept arbitrary values with no upper/lower bound, letting a trusted-but-fallible admin impose economically damaging parameters on users. The same design gap exists in Base's `SystemConfig` update pipeline: `OperatorFeeUpdate`, `GasConfigUpdate`, `GasLimitUpdate`, and `MinBaseFeeUpdate` decode raw `ConfigUpdate` log data from the L1 `SystemConfig` contract and apply it to the L2 chain's economic parameters with only ABI-shape validation - no range/sanity checks on the actual values.

### Finding Description
`OperatorFeeUpdate::apply` unconditionally sets `config.operator_fee_scalar` (a `u32`, i.e. up to ~4.29e9) and `config.operator_fee_constant` (a `u64`) straight from decoded log bytes with no bound checking: [1](#0-0) 

These values flow directly into per-transaction fee computation with no cap: [2](#0-1) 

Since `product.saturating_add(operator_fee_constant)` is only saturated against `U256::MAX`, an extreme `operator_fee_scalar`/`operator_fee_constant` value (e.g. the owner's operator-fee-vault key is compromised, or the operator/owner multisig mis-configures the value, mirroring the "admin mixed up tokens" scenario in the report) causes every non-deposit L2 transaction to be charged a massive operator fee, deducted from the sender's balance: [3](#0-2) [4](#0-3) 

The same unbounded-setter pattern recurs for `GasConfigUpdate` (`overhead`/`scalar`, full `U256` range, no cap) and `GasLimitUpdate` (`gas_limit` up to `u64::MAX`, or `0`), both applied without any sanity check: [5](#0-4) [6](#0-5) 

The decode/validate layer (`SystemConfigLog`/`UpdateDataValidator`) only checks ABI pointer/length shape, not the semantic value: [7](#0-6) 

Unlike the Kairos precompile logic where `setAuctionPriceFactor` has a documented minimum, none of these `SystemConfig` update appliers enforce any minimum/maximum on the values they persist into the derived chain state.

### Impact Explanation
An operator fee scalar/constant set far outside a sane range (whether via an admin mistake or a compromised L1 `SystemConfig` owner key) is applied automatically by every node during derivation and charged against every user transaction's balance with no per-block or protocol-level cap - a direct and unavoidable loss of funds for users who cannot avoid it once the update lands on L1, exactly matching the "loss of funds via unbounded admin parameter" bug class from the report. A `gas_limit` of `0` (or a similarly degenerate `GasConfig`/`MinBaseFee` value) can also stall block building/derivation, a node-halt-class impact.

### Likelihood Explanation
Requires the entity controlling the L1 `SystemConfig` contract (protocol admin/owner) to emit a bad `ConfigUpdate` log, either through operator error or key compromise - the same "trusted admin, no limits" precondition the Sherlock report is built on. Given there is no value-range validation anywhere in the derivation pipeline, any such log is applied without any secondary guard.

### Recommendation
Add explicit sanity bounds when decoding/applying `OperatorFeeUpdate`, `GasConfigUpdate`, `GasLimitUpdate`, and `MinBaseFeeUpdate` (and reject/ignore updates outside those bounds, similar to how `GasConfigUpdate::try_from` already rejects invalid Ecotone scalars), so a single L1 `SystemConfig` update cannot impose unbounded per-transaction fees or degenerate gas limits on the L2 chain.

### Proof of Concept
1. L1 `SystemConfig` owner (or a compromised key) emits a `ConfigUpdate(OperatorFee)` log with `operator_fee_scalar = u32::MAX` and `operator_fee_constant = u64::MAX`, as encoded by `OperatorFeeUpdate::try_from` (see test harness helper `enqueue_operator_fee_update` in `actions/harness/src/l1/miner.rs:376-400`).
2. The derivation pipeline decodes and applies this via `SystemConfig::process_config_update_log` → `OperatorFeeUpdate::apply` with no bound check [1](#0-0) .
3. Every subsequent non-deposit transaction is charged `operator_fee_charge_inner`, which saturates to an enormous value and is deducted from the sender's balance via `ensure_can_pay_fees`/fee-charging logic [2](#0-1) , effectively locking users out of the chain or draining their funds with no way to opt out.

```rust
    /// Calculates the operator fee for a given `gas` amount.
    ///
    /// Missing scalars fall back to zero to match the execution path during the
    /// txpool bootstrap window before the first L1 attributes deposit.
    pub fn operator_fee_charge_inner(&self, gas: U256, upgrade: BaseUpgrade) -> U256 {
        let operator_fee_scalar = self.operator_fee_scalar.unwrap_or_default();
        let operator_fee_constant = self.operator_fee_constant.unwrap_or_default();

        let product = if Self::is_enabled(upgrade, BaseUpgrade::Jovian) {
            gas.saturating_mul(operator_fee_scalar)
                .saturating_mul(U256::from(OPERATOR_FEE_JOVIAN_MULTIPLIER))
        } else {
            gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
        };
        product.saturating_add(operator_fee_constant)
    }
```

```rust
    /// Introduced in isthmus. Prior to isthmus, the operator fee is always zero.
```

```rust
    /// Returns the Isthmus operator fee for `envelope` over `gas`. Zero for deposits and before
    /// Isthmus.
    ///
    /// The operator fee is an Isthmus feature; `L1FeeParams::operator_fee_charge` computes it
    /// unconditionally, so the Isthmus gate is applied here (matching the reference, which gates
    /// in its `reward_beneficiary`). The Base upgrade ladder is discriminant-ordered.
    fn operator_fee(host: &mut Evm<'_, BaseEvmTypes>, envelope: &BaseTxEnvelope, gas: u64) -> U256 {
        let Some(enveloped) = envelope.enveloped() else {
            return U256::ZERO;
        };
        let upgrade = host.config_spec_id().upgrade();
        if (upgrade as u8) < (BaseUpgrade::Isthmus as u8) {
            return U256::ZERO;
        }
        host.block_env().ext.operator_fee_charge(enveloped, U256::from(gas), upgrade)
    }
```
