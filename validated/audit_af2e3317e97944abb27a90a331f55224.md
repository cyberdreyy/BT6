### Title
Unsanitized symlink target in zip extraction permits creation of symlinks pointing outside the job workspace - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` creates a filesystem symlink using the raw, attacker-controlled zip entry content as the link target with no validation that the target is relative and confined to the extraction directory. Any job that controls a zip file processed by `ExtractZipArchive` (e.g., cache/artifact download/extraction) can embed a symlink entry whose target is an absolute host path or a `../`-traversal path, and the resulting dangling symlink is left on disk for later job steps or Runner-side tooling to read/write through.

### Finding Description
`extractZipFile` dispatches based on `file.Mode() & os.ModeType`; for `os.ModeSymlink` it calls `extractZipSymlinkEntry` [1](#0-0) . That function reads the entry's file content as the symlink target string and calls `os.Symlink(string(data), file.Name)` with zero validation of the target value [2](#0-1) . The only sanitation performed anywhere in `ExtractZipArchive` is `errorIfGitDirectory`, which only rejects `.git`-prefixed entry *names*, not symlink *targets* [3](#0-2) . There is no `filepath.Clean`/containment check, no rejection of absolute paths, and no rejection of `..` segments in the link target anywhere in `helpers/archives/zip_extract.go`. The existing test suite (`zip_extract_test.go`) only covers `.git` warnings and mode preservation for symlinks — there is no test that exercises a malicious symlink target [4](#0-3) .

Because `os.Symlink` merely records the target string without dereferencing it, `os.Symlink("/etc/passwd", "link")` or `os.Symlink("../../secret", "link")` both succeed unconditionally; the created symlink is a dangling/absolute reference on disk. `ExtractZipArchive` is the function used by cache-extractor/artifacts-downloader code paths to unpack an archive that is at least partly derived from the job's own working tree (cache/artifacts), and an unprivileged job author fully controls the contents of the cache/artifact zip they cause the Runner to produce or a colluding/second job to substitute.

### Impact Explanation
By itself, creating a dangling symlink does not read or write host files — it only plants a symlink whose target resolves outside the intended workspace. The scoped impact requires a **subsequent** operation that follows the link (e.g., a later build step, `cp`/`tar`/editor within the job, or Runner helper code that opens `file.Name` for read/write assuming it stays inside the workspace). If any later Runner-controlled file operation in the job (not covered in this specific function) opens/writes through such a symlink without `O_NOFOLLOW`/lstat checks, it could read/overwrite files outside the job's cache/build directory. Within the strict scope of this question — the extraction function itself — the concrete, provable impact is: an attacker-controlled zip can make `ExtractZipArchive` place a symlink at an attacker-chosen path (subject to zip-slip on the *name* too, since `file.Name` is also unsanitized) pointing at an arbitrary absolute path or parent-traversal path, without any error, warning, or rejection.

### Likelihood Explanation
Feasible and fully attacker-controlled: any pipeline author can construct a custom zip file (e.g. crafted as a cache or artifact) containing a `zip.FileHeader` with `Mode()&os.ModeType == os.ModeSymlink` and file content `"/etc/passwd"` or `"../../outside"`. The archive is then extracted via `ExtractZipFile`/`ExtractZipArchive` whenever the Runner restores that cache/artifact (`cache-extractor`, `artifacts-downloader` commands wrap this via `commands/helpers`). No credentials or special privileges are needed beyond normal job authorship; this is deterministic and repeatable on every extraction of the crafted archive.

### Recommendation
In `extractZipSymlinkEntry`, validate the symlink target before calling `os.Symlink`: reject absolute paths (`filepath.IsAbs`), and reject any target whose cleaned, joined path (`filepath.Join(filepath.Dir(file.Name), target)`) escapes the extraction root (i.e., `filepath.Rel` result starts with `..` or is `..`). Apply the same containment check to `file.Name` itself in `extractZipFile`/`ExtractZipArchive` to prevent zip-slip on the entry path, mirroring protections that should also exist in the tar extractor.

### Proof of Concept
```go
// helpers/archives/zip_extract_test.go
func TestExtractZipFileMaliciousSymlinkTarget(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        f, err := os.Create(fileName)
        require.NoError(t, err)
        defer f.Close()

        archive := zip.NewWriter(f)
        hdr := &zip.FileHeader{Name: "evil_link"}
        hdr.SetMode(os.ModeSymlink | 0o777)
        w, err := archive.CreateHeader(hdr)
        require.NoError(t, err)
        _, err = w.Write([]byte("/etc/passwd")) // or "../../secret"
        require.NoError(t, err)
        require.NoError(t, archive.Close())
        f.Close()

        err = ExtractZipFile(fileName)
        require.NoError(t, err) // currently succeeds - should error or sanitize

        target, err := os.Readlink("evil_link")
        require.NoError(t, err)
        // Expected (post-fix) assertion: target must not be absolute or escape cwd
        assert.False(t, filepath.IsAbs(target), "symlink target must not be an absolute host path")
    })
}
```
Running this against current `extractZipSymlinkEntry` shows the symlink is created pointing at `/etc/passwd` with no error, confirming the missing validation.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
