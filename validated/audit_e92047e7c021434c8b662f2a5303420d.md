### Title
Blacklisted lender cannot claim matured withdrawals because claim functions hard-code payout to `msg.sender` - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`IdleCDOEpochVariant.claimWithdrawRequest()` and `claimInstantWithdrawRequest()` take no `recipient` parameter and always settle to `msg.sender` [1](#0-0) . The vault then burns the caller's receipt tokens and `safeTransfer`s the underlying to that same address [2](#0-1) . If the underlying token (e.g. USDC/USDT) adds the user to its blocklist after the request was made, every claim attempt reverts inside the token transfer and the user's matured, already-funded withdrawal is permanently frozen.

### Finding Description
The withdraw flow mints a strategy-token receipt to the user in `requestWithdraw`, keyed to `withdrawsRequests[_user]` / `lastWithdrawRequest[_user]` [3](#0-2) . When the epoch ends and `collectWithdrawFunds` pulls funded underlyings into the vault, the only exit is `claimWithdrawRequest(address _user)`, which is `_onlyIdleCDO`-gated and receives `_user` exclusively as `msg.sender` from the CDO [4](#0-3) . `_claimFundedWithdrawRequest` burns the receipt and calls `_transferFundedClaim(_user, amount)`, paying the same blocked address [5](#0-4) . Because the accounting is bound to the blocked address, the user cannot even hand the claim to a clean wallet — a different caller has no `withdrawsRequests` entry to claim.

### Impact Explanation
A KYC-passing lender who gets blocklisted by the underlying token after depositing loses access to their full matured claim: the tokens remain in `IdleCreditVault` while every `claimWithdrawRequest` reverts. This is permanent freezing of user funds equal to the entire claim amount (`normalAmount + apr0Principal + apr0Interest`). The same applies to instant withdrawals via `claimInstantWithdrawRequest` [6](#0-5) .

### Likelihood Explanation
Requires an external dependency (USDC/USDV-style blocklisting), which lowers likelihood, but the protocol is built for exactly this class of compliance-gated underlying tokens — it already integrates `isWalletAllowed`/Keyring KYC [7](#0-6) , showing counterparty compliance risk is a recognized surface. No guard (`_checkAllowed`, skim, default reverts) intercepts the claim path, so a blocklist event deterministically freezes the funds.

### Recommendation
Add a `recipient` parameter to `claimWithdrawRequest`/`claimInstantWithdrawRequest` on `IdleCDOEpochVariant`, forward it to `IdleCreditVault` so the receipt is still burned from `msg.sender` but `underlyingToken.safeTransfer` pays the chosen recipient. (Note: `IdleCDOEpochQueue.claimWithdrawRequest`/`claimDepositRequest` have the same shape but are out of scope [8](#0-7) .)

### Proof of Concept
Foundry fork sketch (underlying = USDC, fork mainnet, use `aa`/vault deploy fixtures from `test/foundry/IdleCreditVault.t.sol`):

```solidity
// user deposits AA, starts/stops epoch 0 normally

_startEpochAndCheckPrices(0);

// USDC admin blocklists user between request and claim

// claim now always reverts inside safeTransfer; funds stay in the vault
vm.prank(user);
vm.expectRevert();
cdoEpoch.claimWithdrawRequest();
// no alternative path: a clean helper has no withdrawsRequests entry
vm.prank(helper);
vm.expectRevert();
cdoEpoch.claimWithdrawRequest();
assertGt(strategyToken.balanceOf(address(vault)), 0); // funds permanently frozen
```

```text
  function claimWithdrawRequest(address _user) external returns (uint256 amount) {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized) {
      // Post-default requests are already priced after the haircut and backed by the reserve,
      // so they must not fall through to the defaulted-epoch receipt logic.
      amount = _claimPostDefaultWithdrawRequest(_user);
      if (amount != 0) return amount;
      // Only receipts created in the defaulted epoch are haircutted here; old fulfilled
      // receipts are handled below at par if they were already funded before default.
      amount = _claimDefaultedWithdrawRequest(_user);
    }
    amount += _claimLossAdjustedWithdrawRequest(_user);
    return amount + _claimFundedWithdrawRequest(_user);
  }

  /// @notice Claim a funded non-default withdraw request at par.
  /// @param _user address of the user
  /// @return amount amount claimed
  function _claimFundedWithdrawRequest(address _user) internal returns (uint256 amount) {
    // User should wait at least an epoch before claiming the withdraw. Once the epoch is over user can withdraw 
    // at any time even if a new epoch started. 
    // So if epochNumber is the same as the last withdraw request then we revert. Epoch number is increased at stopEpoch
    // NOTE: If a user does not claim a withdraw request and instead requests another withdraw, he will have to wait
    // for another epoch to claim both requests.
    // NOTE 2: if borrower defaults, old withdraw requests can still be claimed
    if (IIdleCDOEpochVariant(idleCDO).epochEndDate() != 0 && (epochNumber <= lastWithdrawRequest[_user])) {
      revert NotAllowed();
    }
    // settle APR=0 requests once the related epoch has ended
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    // Claim includes:
    // - settled APR0 principal from finalized epochs
    // - still-open APR0 principal: if pool-close mode was used (_interest == 1), IdleCDO sets
    //   epochEndDate = 0 and claims can be immediate, while _settleApr0 can still skip settlement
    //   for the current request epoch (reqEpoch >= epochNumber).
    // - settled APR0 interest
    uint256 normalAmount = withdrawsRequests[_user];
    uint256 apr0PrincipalAmount = _apr0User.settledPrincipal + _apr0User.principal;
    uint256 apr0InterestAmount = _apr0User.settledInterest;
    amount = normalAmount + apr0PrincipalAmount + apr0InterestAmount;
    // burn strategy tokens 1:1 with the principal only (normal amount already includes interest)
    _burn(_user, normalAmount + apr0PrincipalAmount);
    withdrawsRequests[_user] = 0;
    lastWithdrawRequest[_user] = 0;
    if (apr0PrincipalAmount != 0 || apr0InterestAmount != 0) {
      delete apr0Users[_user];
    }
    _transferFundedClaim(_user, amount);
```

```text
  function claimWithdrawRequest(uint256 _epoch) external {
    // check if withdraw requests were processed and claimed for the epoch
    uint256 _withdrawPrice = epochWithdrawPrice[_epoch];
    _checkNotAllowed(
      (_withdrawPrice == 0 && !isEpochWithdrawZero[_epoch]) ||
      epochPendingClaims[_epoch] != 0
    );
    // amount is in tranche tokens
    uint256 amount = userWithdrawalsEpochs[msg.sender][_epoch];
    if (amount == 0) {
      return;
    }
    // reset user withdraw request counter for the epoch
    userWithdrawalsEpochs[msg.sender][_epoch] = 0;
    // transfer underlyings to user based on the withdraw price of that epoch
    if (_withdrawPrice != 0) {
      IERC20Detailed(underlying).safeTransfer(msg.sender, amount * _withdrawPrice / ONE_TRANCHE);
    }
  }
```
