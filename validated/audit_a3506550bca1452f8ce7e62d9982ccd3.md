### Title
Interactive terminal exec session bypasses trace-based variable masking, leaking protected/masked CI/CD variables - (File: executors/docker/terminal.go)

### Summary
`terminalConn.Start` in `executors/docker/terminal.go` creates a Docker exec session directly attached to the container's TTY and proxies raw bytes with `terminal.ProxyStream(w, r, dockerTTY, proxy)`, an external `gitlab-terminal` package call that has no knowledge of the Runner's masking logic. The masking implementation (`common/buildlogger` and `common/buildlogger/internal/masker`) only wraps the trace/log writer used for job script stdout/stderr, and is never attached to this raw exec/TTY path, so any masked or protected variable echoed inside the interactive terminal is delivered to the browser client unmasked.

### Finding Description
Masking in this Runner is implemented as a `Writer` wrapper: `buildlogger.New` builds a `Logger` whose `maskPhrases`/`maskTokenPrefixes` are applied via `masker.New(w, phrases)` [1](#0-0)  and the actual phrase-scrubbing writer chain lives in `common/buildlogger/internal/masker/masker.go` [2](#0-1) . This mechanism is exercised only for the job's script execution trace, as shown by the masking test harness that runs a build and inspects the trace buffer for `[MASKED]` substitutions [3](#0-2) .

The interactive terminal path is structurally separate. `commandExecutor.TerminalConnect` builds a `terminalConn` that only carries a `*buildlogger.Logger` for error/debug logging, not as an output writer [4](#0-3) . `terminalConn.Start` issues `ContainerExecCreate`/`ContainerExecAttach` against the running build container to get a raw TTY connection (`dockerTTY`), then hands `w` (the HTTP/WebSocket response), `r`, `dockerTTY`, and a `terminal.NewStreamProxy` stopper directly to `terminal.ProxyStream(w, r, dockerTTY, proxy)` from the external `gitlab-terminal` package [5](#0-4) . That call is a pure bidirectional byte-stream proxy between the container's TTY and the WebSocket client; nothing in this call chain constructs or applies a `masker.Masker`, references `maskPhrases`, or otherwise filters bytes. `ProxyTerminal`/`terminal.ProxyStream` in `session/terminal/terminal.go` similarly only manage timeout/disconnect/stop channel plumbing around `proxyFunc`, with no data inspection [6](#0-5) .

Since protected/masked CI/CD variables are exported as real environment variables inside the build container (so job scripts can use them), any user who can reach the interactive terminal endpoint for that job can run `echo $CI_JOB_TOKEN` or `echo $SOME_MASKED_VAR` and receive the value verbatim over the terminal WebSocket, with no masking check performed anywhere on this path.

### Impact Explanation
An attacker who can trigger a pipeline and open its interactive web terminal (a capability exposed by GitLab CI when `session_server`/interactive terminal is enabled for a runner) can print any masked or protected variable available in the container's environment — including values the pipeline author is not otherwise permitted to view in plaintext (e.g., protected-branch-only variables, deployment tokens, `CI_JOB_TOKEN`) — and read it directly from the terminal output. This is a concrete confidentiality bypass of the masking invariant via a channel distinct from, and not covered by, trace-based masking.

### Likelihood Explanation
Preconditions are modest: the runner must have the interactive web terminal/session server enabled (a supported, documented Runner feature, not an unusual admin misconfiguration), and the attacker needs the ability to open a terminal session on a job that has the target masked/protected variable in its environment. Given those, the exploit is trivial and 100% reproducible: run the pipeline, open the terminal, type `echo $VAR`, and read the plaintext response — no timing, race conditions, or scanning required.

### Recommendation
Wrap the terminal's output stream with the same masking writer chain used for build traces before it reaches `terminal.ProxyStream`. Concretely, wire `t.logger`'s configured mask phrases (or a shared masker component fed by the same `common.Build` variable list) into a filtering `io.Writer` placed between `dockerTTY`'s output and the WebSocket `ResponseWriter`, so `ProxyStream` writes go through masking before leaving the Runner. Because interactive terminals are stateful, byte-oriented streams (not line trace records), the masker must be applied at the byte-stream layer (similar to `masker.New`), tolerating masked phrases split across TTY reads.

### Proof of Concept
Integration test plan (extending the existing `docker` terminal test suite alongside `common/buildtest/masking.go` patterns):
1. Configure a build with a masked variable, e.g. `spec.Variable{Key: "MASKED_KEY", Value: "MASKED_VALUE", Masked: true}`, using the docker executor.
2. Start the build so the container is running, then call `commandExecutor.TerminalConnect()` to obtain a `terminalConn`, and invoke `Start` against a test `httptest.ResponseRecorder`/WebSocket harness.
3. Send `echo $MASKED_KEY\n` as terminal stdin.
4. Capture the raw bytes written back through `w` (the `ResponseWriter`/WebSocket) and assert:
   - `assert.NotContains(t, string(termOutput), "MASKED_VALUE")` (currently fails, proving the leak), and
   - `assert.Contains(t, string(termOutput), "[MASKED]")` (currently fails, proving no masking is applied).
5. Compare against `RunBuildWithMasking`'s trace-based assertions in `common/buildtest/masking.go` to demonstrate the discrepancy between the two output channels for the same variable.

func New(log Trace, entry *logrus.Entry, opts Options) Logger {
	l := Logger{mu: new(sync.Mutex)}

	l.maskPhrases = internal.Unique(opts.MaskPhrases)
	l.maskTokenPrefixes = internal.Unique(
		append(opts.MaskTokenPrefixes, tokensanitizer.DefaultTokenPrefixes(opts.MaskAllDefaultTokens)...),
	)
	l.timestamping = opts.Timestamping

	if log != nil {
		l.base = internal.NewNopCloser(log)
		l.w = l.wrap(l.base, StreamExecutorLevel, Stdout)
	}

	l.Tee = internal.NewTee(l.SendRawLog, entry, log != nil && log.IsStdout())
	if opts.TeeOnly {
		l.Tee = l.Tee.WithoutLog()
	}

	return l
}

// New returns a new Masker.
func New(w io.WriteCloser, phrases [][]byte) *Masker {
	m := &Masker{}
	m.next = w

	// Create a masker for each unique phrase
	for i := 0; i < len(phrases); i++ {
		m.next = &masker{next: m.next, phrase: phrases[i]}
	}

	return m
}

func (m *Masker) Write(p []byte) (n int, err error) {
	return m.next.Write(p)
}

// Close flushes any remaining data and closes the underlying writer.
func (m *Masker) Close() error {
	return m.next.Close()
}

func (t terminalConn) Start(w http.ResponseWriter, r *http.Request, timeoutCh, disconnectCh chan error) {
	execConfig := client.ExecCreateOptions{
		TTY:          true,
		AttachStdin:  true,
		AttachStderr: true,
		AttachStdout: true,
		Cmd:          t.shell,
	}

	exec, err := t.client.ContainerExecCreate(t.ctx, t.containerID, execConfig)
	if err != nil {
		t.logger.Errorln("Failed to create exec container for terminal:", err)
		http.Error(w, "failed to create exec for build container", http.StatusInternalServerError)
		return
	}

	execStartCfg := client.ExecAttachOptions{TTY: true}

	resp, err := t.client.ContainerExecAttach(t.ctx, exec.ID, execStartCfg)
	if err != nil {
		t.logger.Errorln("Failed to exec attach to container for terminal:", err)
		http.Error(w, "failed to attach tty to build container", http.StatusInternalServerError)
		return
	}

	dockerTTY := newDockerTTY(&resp)
	proxy := terminal.NewStreamProxy(1) // one stopper: terminal exit handler

	// wait for container to exit
	go func() {
		t.logger.Debugln("Waiting for the terminal container:", t.containerID)
		err := t.executor.waiter.Wait(t.ctx, t.containerID)
		t.logger.Debugln("The terminal container:", t.containerID, "finished with:", err)

		stopCh := proxy.GetStopCh()
		if err != nil {
			stopCh <- fmt.Errorf("build container exited with %w", err)
		} else {
			stopCh <- errors.New("build container exited")
		}
	}()

	terminalsession.ProxyTerminal(
		timeoutCh,
		disconnectCh,
		proxy.StopCh,
		func() {
			terminal.ProxyStream(w, r, dockerTTY, proxy)
		},
	)
}

func ProxyTerminal(timeoutCh, disconnectCh, proxyStopCh chan error, proxyFunc func()) {
	disconnected := make(chan bool, 1)
	// terminal exit handler
	go func() {
		// wait for either session timeout or disconnection from the client
		select {
		case err := <-timeoutCh:
			proxyStopCh <- err
		case <-disconnected:
			// forward the disconnection event if there is any waiting receiver
			nonBlockingSend(
				disconnectCh,
				errors.New("finished proxying (client disconnected?)"),
			)
		}
	}()

	proxyFunc()
	disconnected <- true
}
