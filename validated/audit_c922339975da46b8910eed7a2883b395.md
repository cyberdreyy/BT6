### Title
View-role authenticated user can dump full process heap (including decrypted private key material) via unauthenticated pprof endpoints - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` registers the entire `net/http/pprof` handler set (`/v2/debug/pprof/*`) under the `authv2` route group, which only requires successful authentication (`AuthenticateByToken`/`AuthenticateBySession`) with no `RequiresEditRole`/`RequiresAdminRole`/`RequiresRunRole` wrapper, unlike every other sensitive endpoint in that group. A user with the lowest privilege role (`view`) can therefore call `GET /v2/debug/pprof/heap` and receive a raw heap dump.

### Finding Description
In `v2Routes` [1](#0-0) , the `authv2` group is wrapped only with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, which succeeds for any valid session/API token regardless of role. Every sensitive route within this group (keys, jobs, users, transfers, etc.) is explicitly wrapped with `auth.RequiresEditRole`/`auth.RequiresAdminRole`/`auth.RequiresRunRole` on top of the group-level authentication, e.g. `authv2.GET("/keys/eth", ekc.Index)` (unwrapped index, but export/import/delete are wrapped) and `authv2.POST("/vault/dkg_results/verify", auth.RequiresEditRole(...))` [2](#0-1) . However, `metricRoutes(authv2)` is called at the end of the group with no such role wrapper [3](#0-2) , and the function itself registers all pprof handlers unconditionally: `pprofGroup.GET("/heap", ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP))` [4](#0-3) .

The role hierarchy in `core/web/auth/auth.go` defines `RequiresRunRole` (blocks `view`), `RequiresEditRole` (blocks `view`/`run`), and `RequiresAdminRole` (requires exactly `admin`) [5](#0-4) . Since `metricRoutes` uses none of these, any authenticated user — including one whose role is `clsessions.UserRoleView` — passes the group-level `Authenticate` check and reaches the raw `pprof.Handler("heap")`, which serializes the full Go heap profile, potentially including plaintext/decrypted key material or other in-memory secrets handled by the keystore and other services during the process's lifetime.

### Impact Explanation
This matches the Chainlink bounty "sensitive data exposure via broken access control" class: a low-privilege (`view`) credential holder — who should only have read-only access to already-redacted, presenter-filtered API responses — can extract raw process memory. Heap/profile dumps from a long-running node process are a well-known vector for leaking secrets that pass through memory (e.g., decrypted private keys, session tokens, DB credentials) even though presenter/redaction layers scrub structured API responses elsewhere in the codebase (e.g., ETH/OCR/CSA key export endpoints are `RequiresAdminRole`-gated specifically to prevent this class of exposure). This is a confinement failure: a `view` role should never be equivalent to `admin` for this kind of introspection endpoint.

### Likelihood Explanation
Minimal precondition: any valid `view`-role session cookie or API token (the lowest privilege tier issuable via `POST /v2/users`/session login) is sufficient — the same credential used for legitimate read-only dashboards. The request is a single unauthenticated-role `GET /v2/debug/pprof/heap` (or `/goroutine`, `/allocs`, `/profile`, `/trace`, etc., which are equally unguarded), fully reproducible and repeatable with no side effects or rate limiting beyond the standard authenticated rate limiter.

### Recommendation
Wrap `metricRoutes` registration with `auth.RequiresAdminRole` (consistent with other introspective/administrative endpoints like key export/import and log-level patch), e.g. change `metricRoutes(authv2)` to register each route as `authv2.GET("/debug/pprof/heap", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP)))`, or wrap the whole `pprofGroup` with a role-check middleware before registering handlers.

### Proof of Concept
Handler-level integration test plan (Go, using `httptest` + the existing router test harness, e.g. `core/web/router_test.go`/`core/web/presenters` test setup pattern):
1. Set up a test app via existing helpers (`cltest.NewApplication`/`setupWebAuthenticationTest` style used elsewhere in `core/web`), create three users: `admin`, `edit`, and `view` role, obtaining valid session cookies or API tokens for each via `sessions.Sessions`/API token creation flow.
2. For each user, issue `GET /v2/debug/pprof/heap` with the router built by `NewRouter`.
3. Assert:
   - `admin` and `edit`/`run` users currently receive `200 OK` with `Content-Type: application/octet-stream` pprof profile bytes (demonstrating the vulnerable behavior extends beyond intended admin-only scope too, though the core assertion is on `view`).
   - `view`-role user currently also receives `200 OK` with non-empty pprof body — this is the failing assertion proving the vulnerability (expected/fixed behavior: `403 Forbidden` with no profile bytes, matching `auth.RequiresAdminRole`'s `jsonAPIError(c, http.StatusForbidden, ...)` behavior seen in `core/web/auth/auth.go` lines 238-254).
4. Repeat for `/v2/debug/pprof/goroutine`, `/allocs`, `/profile`, `/trace`, `/cmdline` to confirm the whole `pprofGroup` is unguarded.
5. After applying the recommended fix (wrapping with `auth.RequiresAdminRole`), re-run the test suite and assert `view`/`edit` users now receive `403 Forbidden`, and only `admin` receives `200 OK`.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
