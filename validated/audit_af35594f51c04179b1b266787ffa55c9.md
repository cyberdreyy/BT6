## Finding: Stale confirmations from removed multisig members are still counted toward the approval threshold

The reported WalletConnect bug is a race between an approval/authorization state and a peer's up-to-date view of that state. The reachable analog here is in `multisig2/src/lib.rs`: a member's `confirm()` vote on a request is never invalidated when that member is later removed from the multisig, so a request can execute with fewer *live* approvals than `num_confirmations` requires.

### Root cause

`confirm()` counts votes from a per-request `HashSet<String>` of member identities without ever re-validating that those identities are still current members: [1](#0-0) 

`DeleteMember` (invoked from `execute_request`) only purges requests that were *originated* by the removed member — it does not scan other pending requests' confirmation sets for votes cast by that member: [2](#0-1) 

So if member `A` confirms a request `R` that was created by a different member `B`, and `A` is subsequently removed via a separate, unrelated `DeleteMember` request, `R`'s confirmation set still contains `A`'s stale vote. `A`'s vote continues to count toward `self.num_confirmations` in a future `confirm()` call: [3](#0-2) 

### Binding broken

The multisig is supposed to guarantee: `confirmations recorded on a request == confirmations from members currently in self.members`. Once a member is deleted, that equality breaks for any request the deleted member confirmed but did not originate — the stale vote silently persists and is treated as valid. This directly matches the allowed custody-binding class "confirmations counted versus live members."

### Impact

`Critical` — a request (transfer of funds, `AddKey`, `AddMember`, `DeployContract`, `SetNumConfirmations`, etc.) can be executed with fewer than `num_confirmations` *live* member approvals, i.e. "a multisig request executed below threshold." An attacker who controls or colludes with a member that is about to be removed can pre-confirm arbitrary pending/future requests; after removal, the remaining live members only need to supply `num_confirmations - 1` (or fewer, if multiple such stale votes exist) approvals to execute, silently lowering the effective threshold below what the multisig's owners intended.

### Likelihood

Requires a member to already be a legitimate signer at some point and later be removed (a normal, expected multisig operation — e.g. offboarding a compromised or departing signer). No privileged, foundation, or victim-key access is needed beyond normal multisig member churn plus an unconfirmed request left pending across that churn.

### Proof of Concept

1. Initialize `MultiSigContract::new([A, B, C, D], 3)` (4 members, 3-of-4 threshold).
2. `B` calls `add_request(transfer_to_attacker)` → `request_id = R` (`R.member == B`).
3. `A` calls `confirm(R)` → `confirmations[R] = {A}` (len 1, `1+1 < 3`, stored).
4. Separately, members confirm and execute a `DeleteMember { member: A }` request (a normal action, e.g. `A` is being offboarded). This calls `delete_member`, which only removes requests where `r.member == A` — `R` was created by `B`, so it is untouched and `confirmations[R]` still equals `{A}`.
5. `B` calls `confirm(R)` → `confirmations[R] = {A, B}` (len 2, `2+1 < 3`, stored).
6. `C` calls `confirm(R)` → `len(confirmations)+1 == 3 >= num_confirmations` → `execute_request` runs the transfer.

Result: the transfer executed with real approvals only from `B` and `C` (2 live members), while the multisig was configured to require 3-of-4 — `A`'s stale, post-removal vote made up the difference. See `confirm` at [4](#0-3)  and `delete_member` at [2](#0-1) .

### Recommendation

When executing `DeleteMember`, iterate all pending requests' `confirmations` sets (not just requests originated by the removed member) and strip the removed member's identity from each; recompute whether any request should revert to "unconfirmed" state. Alternatively, have `confirm()` filter the stored confirmation set against `self.members` before comparing its length to `num_confirmations`, so removed members' votes never count.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
