Based on the codebase, this bug class **is reachable** in the B20 token precompiles' role-management functions (`grantRole`/`revokeRole`/`renounceRole`), unlike the activation registry's `setAdmin`, which explicitly guards against a zero-address admin.

### Title
Token admin can grant `DEFAULT_ADMIN_ROLE` to the zero address and then renounce their own role, permanently bricking role administration - (File: `crates/common/precompiles/src/b20_asset/logic/v2.rs`, `crates/common/precompiles/src/b20_stablecoin/logic/v2.rs`)

### Summary
The B20 asset/stablecoin precompile role-mutation functions (`grant_role`, `grant_role_unchecked`, `revoke_role`, `renounce_role`) never validate that `account` is non-zero when granting or holding `DefaultAdmin` (equivalent to `ADMIN_ROLE`). By contrast, the activation registry's `set_admin` explicitly rejects `Address::ZERO` via `IActivationRegistry::ZeroAdminAddress`, showing the codebase is aware of this hazard elsewhere but did not apply the same guard to B20 role management.

### Finding Description
`grant_role_unchecked` sets the role bit for whatever `account` is passed and bumps `role_member_count` for `DefaultAdmin` without checking `account != Address::ZERO`: [1](#0-0) 

The only protection against losing all admins is the "last admin" check in `revoke_role`/`renounce_role`, which compares `role_member_count(role) == U256::ONE`: [2](#0-1) 

If the real admin calls `grantRole(DEFAULT_ADMIN_ROLE, address(0))`, `role_member_count` becomes `2`, defeating the last-admin check. The admin can then `renounceRole`/`revokeRole` their own `DefaultAdmin` role, since the count is no longer `1`. The only remaining `DefaultAdmin` holder is `address(0)`, which can never submit a transaction, permanently freezing all admin-gated operations (role grants/revokes, `setRoleAdmin`, pausing, policy updates) on that token.

For comparison, the activation registry treats this exact scenario as a first-class vulnerability and reverts with `ZeroAdminAddress`: [3](#0-2) 

The dispatch path confirms `grantRole`/`revokeRole`/`renounceRole` are directly reachable by any caller holding the `DefaultAdmin` role (an ordinary signed transaction sender), through the standard precompile call path: [4](#0-3) 

The `NonZeroAddress` wrapper exists in the codebase precisely for guarding transfer/mint parties, but is not applied to role-account parameters: [5](#0-4) 

### Impact Explanation
Once `DefaultAdmin` is left solely on `address(0)`, no account can ever grant roles, revoke roles, change `setRoleAdmin` mappings, pause the token, or update policies for that B20 token again. This is a permanent, irreversible loss of administrative control over the token contract (comparable to freezing token governance functionality), reachable purely from a single admin-signed transaction sequence — no external attacker needed, but it is an unrecoverable self-inflicted bricking that the protocol should prevent, matching the medium-severity class in the reported analog.

### Likelihood Explanation
Likelihood is low-to-medium since it requires the admin to intentionally or mistakenly grant `DefaultAdmin` to the zero address before renouncing/revoking their own role — but nothing in the code prevents it, and the pattern (grant to zero, then revoke last "real" holder) is a plausible operational mistake, especially given no client-side validation is enforced at the precompile layer.

### Recommendation
Add an explicit zero-address check in `grant_role`/`grant_role_unchecked` (and ideally `revoke_role`) mirroring the `ZeroAdminAddress` guard already used in `ActivationRegistryStorage::set_admin`:
```rust
if account.is_zero() {
    return Err(BasePrecompileError::revert(IB20::ZeroAdminAddress {})); // or a new IB20 error variant
}
```
Apply this at minimum whenever `role == B20TokenRole::DefaultAdmin.id()`, closing the gap that lets the "last admin" count-based check be circumvented.

### Proof of Concept
1. Admin `A` holds `DefaultAdmin` on a `B20Asset`/`B20Stablecoin` token (`role_member_count == 1`).
2. `A` calls `grantRole(DEFAULT_ADMIN_ROLE, address(0))` → succeeds via `grant_role_unchecked`, `role_member_count` becomes `2`.
3. `A` calls `renounceRole(DEFAULT_ADMIN_ROLE, A)` (or `revokeRole` as another admin) → the "last admin" check (`role_member_count == U256::ONE`) does not trigger because count is `2`, so the call succeeds.
4. Now the only holder of `DefaultAdmin` is `address(0)`. No further `grantRole`, `revokeRole`, `setRoleAdmin`, `pause`, or `updatePolicy` calls requiring `DefaultAdmin` privilege can ever succeed for this token.

    fn grant_role_unchecked(
        &self,
        token: &mut B20AssetToken<S, A>,
        role: B256,
        account: Address,
        sender: Address,
    ) -> Result<()> {
        if token.accounting().has_role(role, account)? {
            return Ok(());
        }
        token.accounting_mut().set_role(role, account, true)?;
        if role == B20TokenRole::DefaultAdmin.id() {
            let current = token.accounting().role_member_count(role)?;
            let next =
                current.checked_add(U256::ONE).ok_or_else(BasePrecompileError::under_overflow)?;
            token.accounting_mut().set_role_member_count(role, next)?;
        }
        token
            .accounting_mut()
            .emit_event(IB20::RoleGranted { role, account, sender }.encode_log_data())
    }

//! Non-zero address wrapper for B-20 transfer parties.

use alloy_primitives::Address;

/// Error returned when constructing a [`NonZeroAddress`] from [`Address::ZERO`].
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct ZeroAddressError;

/// An [`Address`] proven not to be the zero address.
///
/// Construction fails with [`ZeroAddressError`] for the zero address. Callers map that into the
/// appropriate typed revert (`InvalidReceiver`, `InvalidSender`, …). The private field preserves
/// the invariant: there is no public way to wrap [`Address::ZERO`].
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct NonZeroAddress(Address);

impl NonZeroAddress {
    /// Returns a non-zero address, or [`ZeroAddressError`] if `address` is zero.
    pub fn new(address: Address) -> Result<Self, ZeroAddressError> {
        if address == Address::ZERO { Err(ZeroAddressError) } else { Ok(Self(address)) }
    }

    /// Returns the wrapped address.
    pub const fn get(self) -> Address {
        self.0
    }
}
