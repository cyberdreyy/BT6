### Title
Unauthenticated/global request-ID collision in confidential relay gateway handler allows targeted denial-of-service against a specific requester - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`(*handler).HandleJSONRPCUserMessage` in the confidential relay gateway handler only validates that `req.ID` is non-empty and ≤200 characters before inserting it as the sole key into the shared `h.activeRequests` map. Unlike the sibling `vault` handler, this handler never binds the request ID to the caller's authorized identity (no owner prefix, no per-caller namespace), so any unprivileged caller who can reach this handler can submit a request with an ID that collides with another subscriber's in-flight or about-to-be-submitted request, causing the victim's legitimate call to fail with "request ID already exists."

### Finding Description
`HandleJSONRPCUserMessage` performs only these checks before calling `newActiveRequest`: [1](#0-0) 

`newActiveRequest` keys the global `h.activeRequests` map directly by the attacker-supplied `req.ID`, with no ownership binding: [2](#0-1) 

Compare this to `vault/handler.go`, where `HandleJSONRPCUserMessage` runs the request through `h.requestProcessor.ProcessRequest`, which authorizes the caller and rewrites `req.ID` to `authorizedOwner + separator + originalID` *before* `newActiveRequest` is invoked: [3](#0-2) [4](#0-3) 

That owner-prefixing in the vault handler means a colliding raw ID from a different owner produces a different final map key, preventing cross-owner collisions for the `Create/Update/Delete/List` methods. The confidential relay handler has no equivalent step: it never authorizes the caller or namespaces the ID by owner, so the 200-character length check is effectively the *only* gate before the ID occupies a slot in the shared map. Any two callers who happen to pick (or guess) the same `req.ID` — including a predictable scheme derived from `method/workflowID/uuid`-like conventions used elsewhere in the gateway — collide, and whichever request arrives second is rejected with `"request ID already exists: " + req.ID"`, denying that specific request to its rightful sender.

### Impact Explanation
This is a targeted denial-of-service against a specific subscriber's confidential-relay request/response flow: an attacker who can send any gateway JSON-RPC message can pre-empt a known or predictable request ID belonging to another user/workflow, causing legitimate secrets-get or capability-exec relay requests to fail outright. It does not expose secrets or bypass authorization for reading data (the request never actually leaks the victim's response payload to the attacker), but it maps to the "Denial of Service" bounty class — selective disruption of another user's request rather than availability across all users.

### Likelihood Explanation
Exploitability requires only the ability to send a JSON-RPC user message to this handler (no privileged role, no DON/operator access) and knowledge or reasonable prediction of the target's `req.ID`. Since IDs elsewhere in the gateway follow predictable, non-secret conventions incorporating public data like method name and workflow ID, guessing a colliding ID is plausible for a determined but unprivileged attacker. The race only needs the attacker's request to be submitted before the victim's for the victim's later attempt to fail; if the attacker's request is a valid syntactic relay request it will simply proceed and consume the slot, and it can be retried repeatedly at low cost.

### Recommendation
Bind `activeRequests` keys to the authenticated caller's identity, not just the raw client-supplied ID — e.g., derive/require a namespaced key such as `callerIdentity + separator + req.ID` (mirroring the `authorizedOwner` prefixing pattern already used in `core/capabilities/vault/gateway_vault_request_processor.go`) before calling `newActiveRequest` in `core/services/gateway/handlers/confidentialrelay/handler.go`. Alternatively, authenticate/authorize the request and validate that the caller is entitled to the `workflow_id`/subject referenced by the ID before allowing it to occupy a slot in the shared map.

### Proof of Concept
Go test plan (mirrors the existing `TestConfidentialRelayHandler_DuplicateRequestID` at `core/services/gateway/handlers/confidentialrelay/handler_test.go:767-785`, but demonstrating cross-caller pre-emption):
1. Set up the handler via `setupHandler(t, 4)` as in the existing test.
2. Construct `victimID := "MethodCapabilityExec/wf-123/expected-uuid"` following the predictable `<method>/<workflowID>/<uuid>` convention.
3. Simulate the attacker calling `h.HandleJSONRPCUserMessage` first with `req.ID = victimID`, an attacker-controlled `cb1`, and arbitrary/garbage params for a workflow the attacker does not own; assert `err == nil` (request accepted, no ownership check performed).
4. Simulate the legitimate victim calling `h.HandleJSONRPCUserMessage` with the same `req.ID = victimID` and a legitimate `cb2` payload; assert `err != nil` and `strings.Contains(err.Error(), "request ID already exists")`.
5. Assert `h.getActiveRequest(victimID)` still refers to the attacker's `activeRequest` (`req` fields matching the attacker's submitted params), proving the victim's real request was displaced/denied rather than processed.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
