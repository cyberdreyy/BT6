### Title
`URLSanitizer.Write` loses the accumulated key match at exactly the maximum-token-length boundary, letting a split `x-amz-security-token=`/`private_token=`-style secret leak unmasked - ([File: common/buildlogger/internal/urlsanitizer/urlsanitizer.go])

### Summary
`URLSanitizer` persists partial key-match state (`s.match`) across `Write()` calls to support streamed/chunked output, but the capacity-reset guard at the top of the loop (`if len(s.match) == cap(s.match) { s.match = s.match[:0] }`) fires unconditionally as soon as a *new* `Write()` call begins, even when the previously accumulated `s.match` is a complete, valid key match that simply hasn't yet seen its terminating `=`. Because `cap(s.match)` is sized to exactly `len(longest token)+1`, the longest key, `x-amz-security-token` (21 chars + 1 leading `?`/`&` = 22 = cap), triggers this reset precisely when a chunk boundary falls right after the full key name and before the `=`. The buffered key is silently discarded, so the following `=<value>` is written straight through unmasked.

### Finding Description
In `Write()` (`common/buildlogger/internal/urlsanitizer/urlsanitizer.go:53-152`), when a delimiter (`=`, `?`, `&`) is not found within the current chunk, the code falls into the char-by-char accumulation path (lines 104-112) and keeps appending bytes to `s.match` until the outer loop condition `n < len(p)` fails, i.e. until the chunk ends. This lets `s.match` grow to exactly `cap(s.match)` (22 bytes for `?x-amz-security-token`) without ever passing through the cap-check line 82-84 in the *same* call, because that check only runs at the top of the loop, and the loop exits via the outer `for n < len(p)` condition, not via that check.

On the *next* `Write()` call, execution re-enters the loop with `s.masking == false` and `len(s.match) == cap(s.match) == 22`. The very first thing the loop body does (line 82-84) is:
```go
if len(s.match) == cap(s.match) {
    s.match = s.match[:0]
}
```
This wipes the fully-formed key match (`"?x-amz-security-token"`) before the code has any chance to see the following `=` and consult `tokenParamKeys`. With `s.match` now empty, processing falls into the "fast path" (line 88-97) which just searches for the next `?`/`&`; since the remaining chunk starts with `=<secret>...` and contains none, `off == -1` and the whole remainder (the real token value) is written verbatim to the underlying writer at the end of `Write()` (line 147-149), completely bypassing masking.

This only affects the longest configured key, `x-amz-security-token`, because `cap(s.match)` is derived as `max(len(token))+1` over `tokenParamKeys` (`New()`, lines 41-50), and only that key's full length plus its leading punctuation byte equals `cap` exactly. Shorter keys such as `private_token` (14 with leading char) never hit this exact-cap collision at the char-by-char accumulation boundary, so the report's mention of `private_token` is only partially applicable — the concrete, provable case is `x-amz-security-token`.

No other safeguard exists: `masking` is `false` throughout this path (the sanitizer hasn't yet recognized a sensitive key), so the `s.masking` short-circuit at the top of `Write()` never engages, and there's no other check protecting `s.match` from being cleared between calls.

### Impact Explanation
Any job/trace stream that is processed through `urlsanitizer.New(w)` (wired into every executor/work/service stream via `Logger.wrap` in `common/buildlogger/build_logger.go:213-224`) can have a real `x-amz-security-token` value (e.g. an AWS STS temporary token embedded in a presigned cache/artifact URL that Runner or job tooling prints/echoes) appear unmasked in the CI job trace if the underlying `Write()` calls happen to split at the exact byte offset right after the key name and before `=`. This directly violates the core invariant that "Secrets, tokens, and masked values must not leak across jobs, projects, logs, traces, caches, artifacts, or sessions," exposing a temporary AWS credential in plaintext in job output.

### Likelihood Explanation
The vulnerability is deterministic given the right chunk boundary — no randomness or race is needed to trigger the logic error itself, only a chunk split at a byte offset that is fully within the attacker's/job's influence when a job or Runner-internal writer emits an `x-amz-security-token=...` string in multiple pieces. Because the buildlogger's `Stream()` writers receive job stdout/stderr in OS-pipe-sized reads and are also fed by higher-level wrapping (`internal.NewSync`, `timestamper`, `tokensanitizer`) that can itself re-chunk data, a sufficiently long line (e.g. one containing a presigned URL) crossing an internal buffer/read boundary at the vulnerable offset is plausible in real job output, especially for long values like presigned S3 URLs that a job might `cat`/`echo` in pieces (e.g. via `printf` calls or partial `curl -v` output flushed incrementally). This is reproducible reliably in a unit test by feeding the exact split.

### Recommendation
Do not reset `s.match` based purely on reaching `cap`; only discard a partial match when it is confirmed to be non-matching (e.g. after failing the `tokenParamKeys` lookup or after seeing a param-terminating delimiter without `=`). Alternatively, check for a complete match against `tokenParamKeys` (prefix-matching against the known key set) incrementally as bytes are appended, or increase/adjust the invariant so the cap-based reset can never coincide with the exact length of a real key, and add a regression test that specifically feeds `"...?x-amz-security-token"` and `"=<secret>..."` in two separate `Write()` calls (and generally at every possible split offset) to assert the token never appears unmasked in the output.

### Proof of Concept
```go
func TestURLSanitizer_SplitAtExactCapBoundary(t *testing.T) {
    secret := "AQoDYXdzEPT//////////wEXAMPLEtc=="
    full := []byte("https://s3.amazonaws.com/bucket/key?x-amz-security-token=" + secret + "&x-amz-signature=abc")

    for splitAt := 1; splitAt < len(full); splitAt++ {
        buf := new(bytes.Buffer)
        s := urlsanitizer.New(internal.NewNopCloser(buf))

        _, err := s.Write(full[:splitAt])
        require.NoError(t, err)
        _, err = s.Write(full[splitAt:])
        require.NoError(t, err)
        require.NoError(t, s.Close())

        require.NotContains(t, buf.String(), secret,
            "secret leaked unmasked when split at offset %d: %q", splitAt, buf.String())
    }
}
```

func (s *URLSanitizer) Write(p []byte) (n int, err error) {
	var last int

	for n < len(p) {
		// if we're in masking mode, we throw away all bytes until we find
		// the end of the parameter we're masking.
		if s.masking {
			off := bytes.IndexFunc(p[n:], isParamEnd)
			if off == -1 {
				// no end found, so skip these bytes
				n += len(p[n:])
				last = n
				break
			} else {
				// end found, so skip the bytes up until the match and write
				// [MASKED] in their place.
				n += off
				last += off
				s.masking = false

				_, err = s.w.Write(mask)
				if err != nil {
					return n, err
				}
			}
		}

		// if our match is at capacity (maximum token size), reset it and
		// continue looking for the next token.
		if len(s.match) == cap(s.match) {
			s.match = s.match[:0]
		}

		// fast path: if we're not matching any parameters, skip towards ? or &
		// if none found, we can bail early
		if len(s.match) == 0 {
			off := bytes.IndexAny(p[n:], "?&")
			if off == -1 {
				n += len(p[n:])
				break
			} else {
				s.match = append(s.match, p[n+off])
				n += off + 1
			}
		}

		// all of p consumed, so break
		if n >= len(p) {
			break
		}

		// find any of key name
		off := bytes.IndexAny(p[n:], "=?&")

		// if not found, continue adding to key match
		if off == -1 {
			s.match = append(s.match, p[n])
			n++
			continue
		}

		// bail early if the key contains another param separator
		if p[n+off] == '?' || p[n+off] == '&' {
			s.match = s.match[:0]
			n += off
			continue
		}

		// bail early if key would exceed our known key sizes
		if off+len(s.match) > cap(s.match) {
			s.match = s.match[:0]
			n++
			continue
		}

		key := append(s.match, p[n:n+off]...) //nolint:gocritic
		n += off + 1

		// check if the key is one supported, and if so, write data until this
		// point and move to masking mode
		if _, ok := tokenParamKeys[strings.ToLower(string(key[1:]))]; ok {
			_, err = s.w.Write(p[last:n])
			if err != nil {
				return n, err
			}

			last = n
			s.masking = true
		}

		// reset match
		s.match = s.match[:0]
	}

	if len(p[last:n]) > 0 {
		_, err = s.w.Write(p[last:n])
	}

	return n, err
}

func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {
		w = timestamper.New(w, timestamper.StreamType(streamType), uint8(streamID), true)
	}

	w = tokensanitizer.New(w, l.maskTokenPrefixes)
	w = urlsanitizer.New(w)
	w = masker.New(w, l.maskPhrases)
	w = internal.NewSync(w)

	return w
