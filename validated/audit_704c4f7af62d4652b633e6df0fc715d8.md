### Title
Unauthenticated `/v2/resume/:runID` endpoint allows any external party to permanently finalize (and thereby DOS) a pending async bridge task before the legitimate external adapter response arrives - (File: core/web/pipeline_runs_controller.go)

### Summary
Chainlink's async bridge task pipeline exposes a resume callback (`PATCH /v2/resume/:runID`) that an external adapter calls back to when it eventually finishes computing a value. The endpoint accepts an unauthenticated request identified only by a task UUID, and unconditionally applies attacker-controlled `value`/`error` to finalize the corresponding pending pipeline task. This is directly analogous to the reported Sense `redeem` bug: an unprivileged party supplies data that is trusted to represent the outcome of an external, asynchronous process, and once consumed, the pipeline's suspended state is irreversibly finalized/mutated — meaning the actual, correct response (when it later arrives) is silently dropped because the run is no longer `running`/`suspended`.

### Finding Description
The `PipelineRunsController.Resume` handler parses only a `runID` path parameter (actually a task UUID) and a JSON body, with no caller authentication: [1](#0-0) 

It calls `App.ResumeJobV2`, which forwards directly to the pipeline `Runner.ResumeRun`: [2](#0-1) 

`ResumeRun` immediately writes the supplied value/error into the task run and, if the run was suspended, restarts it: [3](#0-2) 

The underlying `UpdateTaskRunResult` finalizes the task row and flips the run state from `suspended` back to `running` inside a `FOR UPDATE`-guarded query that only matches runs still in `running`/`suspended` state: [4](#0-3) 

The task's `BridgeTask` embeds this exact resume URL, containing only the predictable path `/v2/resume/<task-uuid>`, into the outbound request sent to the external adapter so that the adapter can call back once its async work completes: [5](#0-4) 

Because the callback route requires no secret/token to correlate the resuming request with the specific external adapter that was contacted (the task UUID in the URL path is the only "credential"), and the audit log for this action is explicitly named `UnauthedRunResumed`: [6](#0-5) 

any external party who can reach the node's webserver and predict/observe/leak a pending task UUID can submit a bogus resume payload. Once processed, the underlying SQL update (`WHERE pipeline_runs.state in ('running', 'suspended')`) means the task is finalized and the run either completes with attacker-controlled data or restarts — either way, the *real* external adapter's subsequent legitimate callback to the same `/v2/resume/<uuid>` URL will no longer find a matching pending run and its true result is lost. This mirrors the Sense `redeem` bug class: a user-supplied value silently consumes/finalizes an asynchronous external process's state variable, permanently discarding the genuine result with no recovery path.

### Impact Explanation
- An unprivileged/unauthenticated network client that can reach the node's web server (which per the codebase is explicitly the "internet-facing" listener class covered by this analysis) can prematurely finalize any in-flight async bridge task it can enumerate/observe, poisoning job run outputs with attacker-chosen values or errors.
- This directly causes cross-user/cross-run response confusion (attacker output overwrites the legitimate external adapter's output) and a denial-of-service against the real external adapter response, since the pending state is destroyed once consumed and cannot be resumed twice.
- For jobs that feed on-chain reports (e.g., Flux Monitor/EA-backed jobs using async bridges), this could inject falsified data into a job run or silently drop the correct value, undermining the integrity of oracle results — a "request impersonation" of the external adapter's role.

### Likelihood Explanation
- Likelihood depends on the attacker being able to guess or obtain the task UUID. UUIDs are not inherently secret and are transmitted to the external adapter over plain request bodies (potentially over the network, through logs, or intermediary proxies), so leakage or interception is plausible, especially in less-trusted async EA deployments.
- The route requires no authentication token whatsoever (unlike `/v2/external_initiators` runs, which at least required access-key/secret headers), so once a valid UUID is known, exploitation is trivial (a single unauthenticated PATCH request).

### Recommendation
- Require the resume callback to present a per-task secret/token (not just the predictable task UUID) that only the node and the specific external adapter it dispatched the request to would know, and validate it before applying `ResumeRun`.
- Alternatively, bind the resume URL to a one-time, cryptographically random token stored alongside the task and invalidate it after first use, rejecting the request if replayed or if it doesn't match.
- Rate-limit and audit resume attempts, and consider requiring the resume payload to be signed or delivered over an authenticated channel.

### Proof of Concept
1. Configure a job with an async bridge task; the pipeline sends the external adapter a request containing `responseURL = https://node/v2/resume/<taskUUID>`, as seen in `finalizeAndMarshalBridgeRequestData` [5](#0-4) .
2. An attacker who learns or intercepts `<taskUUID>` (e.g., via network observation, logs, or a compromised intermediary) sends `PATCH /v2/resume/<taskUUID>` with an arbitrary JSON body before the genuine external adapter responds.
3. `PipelineRunsController.Resume` accepts the request without authentication and calls `ResumeJobV2` → `ResumeRun` → `UpdateTaskRunResult`, finalizing the task with the attacker's value and restarting/completing the run [3](#0-2) [4](#0-3) .
4. When the legitimate external adapter later calls back to the same `/v2/resume/<taskUUID>` URL with the correct result, the `UpdateTaskRunResult` query no longer matches (the run is no longer `running`/`suspended`), so the real result is silently discarded — the pipeline output has already been poisoned/finalized by the attacker.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

		Value: value,
		Error: err,
	})

		return fmt.Errorf("failed to update task run result: %w", err)

			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
