### Title
Malicious vesting shareholder can permanently brick `distribute()`/`terminate_vesting_contract()`, locking all other shareholders' vested stake and rewards - ([File: aptos-move/framework/aptos-framework/sources/vesting.move])

### Summary
The external report's root cause is a permissionless, unrecoverable revert inside a loop that every repayment/emergency path depends on (`ownerOf()` reverting for a burned NFT). The Aptos analog exists in `vesting::distribute()`: it iterates every shareholder of a vesting contract and unconditionally calls `aptos_account::deposit_coins` for each one in the same atomic loop. Any single shareholder can make their own `deposit_coins` call permanently revert by opting out of direct coin transfers while remaining unregistered for `AptosCoin`. Since `distribute()` is not fault-tolerant (no skip/try-catch per recipient), this locks the entire withdrawable balance for **all** shareholders sharing the vesting contract, and it also blocks `terminate_vesting_contract()` and, transitively, `admin_withdraw()`.

### Finding Description
`distribute()` withdraws all currently-withdrawable stake from the underlying stake pool and then pays every shareholder (or their beneficiary) their proportional share in a single loop: [1](#0-0) 

Each iteration calls `aptos_account::deposit_coins(recipient_address, share_of_coins)`. That function only succeeds unconditionally if the recipient is already registered for `AptosCoin`. If not registered, it requires `can_receive_direct_coin_transfers(to)` to be true, otherwise it aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`: [2](#0-1) 

`allow_arbitrary_coin_transfers` (direct-transfer opt-in) defaults to true but any account holder can flip it to `false` themselves via `set_allow_direct_coin_transfers`, which requires only their own signer: [3](#0-2) 

A shareholder in a vesting contract (or an admin-controlled `beneficiary` address that the shareholder does not fully control, but which is derived from a signer any malicious party can control before being set as beneficiary) can therefore:
1. Never call `coin::register<AptosCoin>()`.
2. Call `set_allow_direct_coin_transfers(&signer, false)`.

Since `distribute()` is permissionless (any caller, callable by anyone including `distribute_many`), any subsequent call by anyone will reach that shareholder's turn in the loop and revert the entire transaction — including the already-executed `withdraw_stake` inside the same call, which is rolled back. This makes `distribute()` permanently and unconditionally revert for that vesting contract.

This directly bricks:
- `terminate_vesting_contract()`, which calls `distribute()` first before flipping state to `VESTING_POOL_TERMINATED`: [4](#0-3) 
- `admin_withdraw()`, which is gated on the contract already being in `VESTING_POOL_TERMINATED` state — a state that can never be reached once `terminate_vesting_contract` is permanently blocked: [5](#0-4) 

The same failure-loop pattern (iterate all shareholders/operator in a shared distribution and deposit synchronously without failure isolation) also exists in `staking_contract::distribute_internal`, affecting staker/operator commission payouts: [6](#0-5) 

### Impact Explanation
Any single shareholder of a shared vesting contract can, using only an unprivileged signer action on their own account, cause `distribute()` to permanently revert. Because `distribute()` first withdraws all pending inactive/rewards stake from the underlying stake pool and only then pays out shares, and because the failing deposit is inside the same atomic transaction, this traps *all other, innocent shareholders'* already-vested and reward stake with no way to ever collect it — `distribute`, `terminate_vesting_contract`, and `admin_withdraw` are all permanently blocked for that vesting contract. This is a permanent, non-recoverable loss of claim rights in a vesting flow affecting parties who did not opt into the malicious behavior, matching the required "Permanent lock or non-recoverable loss of claim rights ... in vesting flows" impact.

### Likelihood Explanation
Likelihood is high: the only precondition is that the attacker is a legitimate shareholder (or has been assigned as a beneficiary) in a multi-shareholder vesting contract, and the only action required is calling the standard, unprivileged, publicly documented `aptos_account::set_allow_direct_coin_transfers(account, false)` entry function on their own account while never registering for `AptosCoin`. No race condition, no special timing, and no elevated privileges are needed.

### Recommendation
`distribute()` (and `staking_contract::distribute_internal`) should not let one recipient's failed deposit revert payouts to all other recipients. Wrap each per-shareholder deposit in a way that isolates failures (e.g., use `coin::deposit` with a pre-check via `coin::is_account_registered` and `can_receive_direct_coin_transfers`, and if a recipient cannot receive funds, hold their share in an internal claimable balance/escrow instead of aborting the whole distribution), so that a malicious or misconfigured recipient cannot block distribution for others.

### Proof of Concept
1. Admin creates a vesting contract with shareholders A (honest) and B (malicious), using `create_vesting_contract`.
2. B never calls `coin::register<AptosCoin>()` for their own account.
3. B calls `aptos_account::set_allow_direct_coin_transfers(&B_signer, false)`.
4. Time passes; vesting/rewards accrue and become withdrawable.
5. Anyone calls `vesting::distribute(contract_address)` (or `vest`, which internally calls flows leading to `distribute`, or `terminate_vesting_contract`).
6. The loop in `distribute()` reaches B's `aptos_account::deposit_coins` call, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` because B is unregistered and opted out.
7. The entire transaction reverts, including the `withdraw_stake` from the underlying stake pool that happened earlier in the same call.
8. Every future call to `distribute`, `terminate_vesting_contract`, and (transitively) `admin_withdraw` reverts the same way — shareholder A's vested stake and rewards, and any subsequent funds, are permanently locked, with no admin recovery path since `terminate_vesting_contract` itself calls `distribute()` first.

        assert_active_vesting_contract(contract_address);

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
