### Title
Unredacted internal handler error messages returned verbatim to unauthenticated gateway callers via `newError` - ([File: core/services/gateway/gateway.go])

### Summary
`newError` places the raw `err.Error()` string returned by any gateway handler directly into the JSON-RPC `WireError.Message` field, which is sent back over HTTP to the requesting client without any redaction. Since `HandleJSONRPCUserMessage`/`HandleLegacyUserMessage` errors from all handlers (vault, capabilities, confidentialrelay, dummy) flow through this single formatting function, any handler that wraps a backend/internal error into its returned `error` (e.g. the vault handler's authorization failure) will have that internal text delivered to an unauthenticated caller.

### Finding Description
In `core/services/gateway/gateway.go`, `processRequest` calls `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` and on error immediately does: [1](#0-0) 
which returns `newError(jsonRequest.ID, api.HandlerError, err.Error())` — embedding the handler's raw error text into the wire response with no sanitization: [2](#0-1) 

For the vault handler, an unauthenticated request that fails authorization triggers: [3](#0-2) 
`err` here originates from `GatewayVaultRequestProcessor.authorizeAndStamp`, which itself wraps the underlying `Authorizer.AuthorizeRequest` failure with `fmt.Errorf("request not authorized: %w", err)`: [4](#0-3) 
This double-wrapped error (containing whatever detail the underlying `Authorizer` implementation put into its error, e.g. digest/signature/owner-mismatch diagnostics) is returned as the `error` from `HandleJSONRPCUserMessage`, propagates to `gateway.go:275`, and is placed verbatim into the JSON-RPC response `Message` field returned to the caller's HTTP connection. No authentication is required to reach this path — an unauthenticated/unauthorized caller triggering `MethodSecretsCreate/Update/Delete/List` with a bad or missing signature is precisely the attacker who receives this detailed message.

There is no presenter/redaction layer between the handler error and the wire response; `newError` is a pure pass-through formatter.

### Impact Explanation
This is an information-disclosure issue: internal implementation detail from the authorization/validation backend (error text that may include identifiers, validation internals, or diagnostic context not intended for external consumption) is surfaced to any unprivileged, potentially unauthenticated, gateway caller. This matches Chainlink's "Sensitive Information Disclosure" bounty class rather than fund loss or privilege escalation — it does not itself grant unauthorized actions, but it can aid further attacks (e.g., probing authorization logic, learning about internal owner/id formats) via verbose error oracle behavior.

### Likelihood Explanation
Trivially reachable and repeatable: any caller of the gateway's public JSON-RPC endpoint can send a `vault` method request (e.g. `secrets_create`) with an invalid/missing `Auth` field to force `AuthorizeRequest` to fail, and receive the detailed error text back in the HTTP response. No credentials or prior authorization are required to hit this specific code path, since the failure occurs at authorization time itself. The same generic pass-through pattern applies to any other handler that returns a wrapped internal error.

### Recommendation
Sanitize/generalize handler-returned errors before placing them into the wire response `Message` field in `newError` (or at the call sites in `gateway.go`). Return a generic message such as "request not authorized" or "internal handler error" to the caller, and log the full `err` (with detail) server-side only. Ensure handler implementations (e.g., vault's `authorizeAndStamp`) do not propagate raw internal authorizer error strings up through user-facing error paths — wrap them in a caller-safe sentinel error type before returning from `HandleJSONRPCUserMessage`.

```go
func newError(id string, errCode api.ErrorCode, errMsg string) ([]byte, int) {
	response := jsonrpc2.Response[json.RawMessage]{
		Version: jsonrpc2.JsonRpcVersion,
		ID:      id,
		Error: &jsonrpc2.WireError{
			Code:    api.ToJSONRPCErrorCode(errCode),
			Message: errMsg,
			Data:    nil,
		},
	}
```
