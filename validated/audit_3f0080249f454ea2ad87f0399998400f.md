This mirrors the report's core issue — an unprivileged actor being able to mutate another party's pending state (here, a paused pipeline run) via a public endpoint, with the only "authentication" being knowledge of a value (UUID) rather than an ownership/ACL check.### Title
Unauthenticated `/v2/resume/:runID` endpoint allows request forgery to inject a finalized result into another job's pending pipeline run - (File: `core/web/pipeline_runs_controller.go`)

### Summary
`PATCH /v2/resume/:runID` is mounted in the unauthenticated route group and completes/overwrites a suspended pipeline task purely by supplying its `taskID` UUID in the URL, with zero ownership or capability check tying the caller to that job/run.

### Finding Description
The route is registered outside any auth middleware: [1](#0-0) 

The `Resume` handler parses `runID` (actually a `pipeline_task_runs.id` UUID) from the URL, decodes an arbitrary JSON body into a `ResumeRequest`, converts it to a `Result`, and immediately calls `ResumeJobV2`/`ResumeRun` — with no check that the caller is the external adapter that originated this specific async task, nor any user/job-ownership validation: [2](#0-1) 

Under the hood, `UpdateTaskRunResult` looks up the pending run purely by `taskID` and unconditionally writes the attacker-supplied `Result` into `pipeline_task_runs`, then flips the run from `suspended` back to `running`, which triggers the scheduler to resume with the forged value baked in: [3](#0-2) [4](#0-3) 

This is structurally the same class of bug as the report: a piece of per-entity state that gates future computation (there: `mapMemberSynth_lastTime` gating reward accrual; here: the pending task's `Result`/finished status gating pipeline continuation) can be mutated by an unprivileged, unauthenticated third party who only needs to guess/obtain the identifying value (there: member address is public; here: the `taskID` UUID). Whoever can call the resume URL "wins" and permanently determines the outcome of another party's job run — a legitimate async external adapter racing an attacker's forged resume is subject to a TOCTOU race with no idempotency/ownership guard, and if the attacker's request lands first, the legitimate adapter's later completion is silently ignored (task is no longer pending) or, in bidding scenarios, corrupts the on-chain-bound result the job produces.

### Impact Explanation
An attacker who obtains or brute-forces a pending task's UUID (e.g., via response/URL leakage, logs, or a race with a slow external adapter) can:
- Force any node's paused webhook/async bridge task to resolve with attacker-chosen data, corrupting the job's on-chain submission or downstream computation.
- Grief legitimate external adapters permanently: since `UpdateTaskRunResult` only matches on `state in ('running','suspended')`, once the attacker's forged completion lands, the task is no longer pending and the genuine adapter's real callback is discarded, denying the job the correct answer, indefinitely as long as the attacker keeps winning the race, mirroring the "member never earns any reward" griefing pattern in the report.
- No confidentiality bypass is required — this is a pure integrity/availability issue on job-run outcomes.

### Likelihood Explanation
The endpoint is intentionally exposed without authentication (by design, to let external HTTP adapters call back), which the code comments confirm is a known trust boundary ("locking the current run... prevents races with /v2/resume"), but that locking only guards against internal races, not against unauthenticated forged requests carrying a valid-looking UUID. Task UUIDs are not treated as high-entropy secrets in the codebase's threat model documentation; they are effectively bearer tokens for the resume action, so exposure (e.g., via network logs, HTTP referrer, load balancer/gateway logs, or misconfigured `BridgeResponseURL`) is plausible for anyone incentivized to target a specific node's job outcomes.

### Recommendation
- Require a per-run/per-task secret (e.g., a signed/HMAC-derived token, separate from the raw `taskID`) that only the initiating bridge/external adapter and node share, similar to how External Initiator access is verified via a hashed secret in `bridges.AuthenticateExternalInitiator`.
- Alternatively, bind the resume token to the specific bridge configured on the task at creation time and verify request provenance (e.g., shared bearer header) before calling `ResumeJobV2`.
- Make `UpdateTaskRunResult` idempotent/first-writer-wins with an explicit "already resolved" rejection rather than silently overwriting, and audit-log rejected duplicate/forged resume attempts distinctly from successful ones (currently `audit.UnauthedRunResumed` logs all attempts identically).

### Proof of Concept
1. Create a webhook/async bridge job whose task pauses awaiting an external adapter callback (`Async = "true"` in `task.bridge.go`), producing a `taskID` UUID embedded in the `responseURL` sent to the external adapter.
2. Before the legitimate external adapter responds, an attacker who has obtained/guessed that UUID sends:
   `PATCH /v2/resume/<taskID>` with body `{"data": <attacker-controlled value>}` — no auth headers required, per `v2Routes`'s unauthenticated group registration.
3. `PipelineRunsController.Resume` decodes the body and calls `App.ResumeJobV2(ctx, taskID, result)` unconditionally.
4. `orm.UpdateTaskRunResult` finds the run in `running`/`suspended` state by `taskID` alone, writes the attacker's `Result`, and flips the run back to `running`; the scheduler resumes the pipeline with the forged value.
5. When the real external adapter later posts its genuine result to the same URL, `UpdateTaskRunResult`'s `WHERE ... pipeline_runs.state in ('running','suspended')` filter no longer matches (state has moved on), so its update is a no-op — the legitimate response is lost and the pipeline result is permanently the attacker's forged value.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
