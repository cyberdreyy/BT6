## Title
Signer's v1 tenure-change duplicate check uses `get_last_globally_accepted_block`, missing `LocallyAccepted`/`PreCommitted` state, allowing a signer to sign a conflicting second tenure-start block - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
`SortitionsView::validate_tenure_change_payload` (v1 chainstate path, used when the active signer protocol version does not use global state) checks for an existing block in the current tenure via `signer_db.get_last_globally_accepted_block(...)` before allowing a new tenure-change proposal through. This mirrors the Compound-style bug class in the reference report: a downstream equality/membership check silently omits a state that should be included, so it wrongly succeeds ("no conflict found") even though a conflicting local commitment already exists.

### Finding Description
In `stacks-signer/src/chainstate/v1.rs`, `validate_tenure_change_payload` (around lines 461-519) queries: [1](#0-0) 

using `get_last_globally_accepted_block`, which only matches `BlockState::GloballyAccepted` rows. It does not see a block the signer already `LocallyAccepted` or `PreCommitted` in the same tenure.

By contrast, the v2 chainstate path's equivalent function was fixed to use `get_last_signed_block`, which matches both `GloballyAccepted` and `LocallyAccepted` states: [2](#0-1) [3](#0-2) 

A regression test explicitly documents this exact fix on the v2 side and states the old (globally-accepted-only) behavior "would miss blocks in `LocallyAccepted` or `PreCommitted` state and incorrectly allow a duplicate tenure change": [4](#0-3) 

This same defect remains present, unfixed, in the v1 path's `validate_tenure_change_payload`, which is dispatched whenever the signer evaluates a proposal against local (non-global) state: [5](#0-4) 

The proposal-time `DuplicateBlockFound` check is documented as a one-shot gate that "never runs again": [6](#0-5) 

The backstop for this gap is the pre-commit-time `get_signed_conflicts` check, but that function only returns rows where `signed_self IS NOT NULL OR signed_group IS NOT NULL` - i.e., it also excludes `LocallyAccepted`-but-not-yet-`signed_self`... actually a `LocallyAccepted` block does set `signed_self`, so `get_signed_conflicts` *would* catch a `LocallyAccepted` sibling at pre-commit time via the "own tenure" branch: [7](#0-6) 

However, the *first* gate — the proposal-arrival `check_proposal` call — has no such coverage in v1 for a merely `LocallyAccepted` (signed by this signer, but not yet at global threshold) block in the same tenure: it will not be rejected as `DuplicateBlockFound` at arrival, so it is submitted to the node for validation and progresses toward pre-commit, in violation of the intended one-tenure-start-block-per-tenure invariant the check exists to enforce. Whether the pre-commit-stage `get_signed_conflicts` backstop always intervenes in every timing window (e.g. before the node itself has processed/rejected a genuinely conflicting tenure-start block) could not be fully traced in the remaining time; the two proposal-time functions (v1 vs v2) are demonstrably inconsistent, and the v2 code and its dedicated regression test both explicitly document that the v1-style check is broken.

### Impact Explanation
This breaks the "approved-parent vs canonical" / one-per-tenure equality invariant that `validate_tenure_change_payload`'s `DuplicateBlockFound` check exists to enforce: a signer running the v1 (local/non-global-state) protocol path can be induced by a miner to validate and pre-commit to (and, if the pre-commit-stage backstop does not universally cover every window, potentially sign) a second, conflicting tenure-start block for a tenure in which it already locally accepted a different tenure-start block. That is a Critical-class outcome per the rules (a signer signing a conflicting block) if the pre-commit backstop does not close every window, or at minimum a correctness/consistency defect that lets an already-superseded proposal pass a check whose entire purpose is to prevent it from doing so.

### Likelihood Explanation
Reachable by a single miner (one-slot) with no need for a signer majority: the miner simply needs to (re)propose a second tenure-start block for the same tenure after a signer has locally (but not yet globally) accepted an earlier one. The v1 path is live whenever `determine_active_signer_protocol_version()` resolves to a version that does not use global state, per `check_block_against_state`'s dispatch.

### Recommendation
Change `stacks-signer/src/chainstate/v1.rs`'s `validate_tenure_change_payload` to use `signer_db.get_last_signed_block(...)` (matching both `GloballyAccepted` and `LocallyAccepted`) instead of `get_last_globally_accepted_block`, bringing it in line with the already-fixed v2 implementation, and add a v1-side regression test mirroring `check_tenure_change_rejects_when_locally_accepted_block_exists` in `stacks-signer/src/chainstate/tests/v2.rs`.

### Proof of Concept
1. Configure a signer to run the v1 (non-global-state) protocol path.
2. Miner proposes tenure-start block A for tenure T; signer validates and `mark_locally_accepted`s it (state `LocallyAccepted`, not yet `GloballyAccepted`).
3. Miner proposes a second, conflicting tenure-start block B for the same tenure T.
4. In `SortitionsView::check_proposal` → `validate_tenure_change_payload`, `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)` returns `None` (block A is only `LocallyAccepted`), so the `DuplicateBlockFound` rejection is skipped and block B is submitted for validation instead of being rejected at proposal time — unlike the v2 path, which would catch this via `get_last_signed_block` (see the passing v2 regression test `check_tenure_change_rejects_when_locally_accepted_block_exists`, which fails against the old globally-accepted-only logic).

    pub fn get_signed_conflicts(
        &self,
        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,
    ) -> Result<Vec<SignedConflictInfo>, DBError> {
        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,
                MAX(COALESCE(b.signed_self, 0), COALESCE(b.signed_group, 0)) AS last_endorsed,
                st.superseded_by_consensus_hash, st.superseded_by_burn_block_hash
            FROM blocks b
            LEFT JOIN superseded_tenures st ON st.consensus_hash = b.consensus_hash
            WHERE (b.signed_self IS NOT NULL OR b.signed_group IS NOT NULL)
                AND b.stacks_height >= ?1
                AND b.signer_signature_hash != ?2
            ORDER BY b.stacks_height DESC";
        let args = params![
            u64_to_sql(height)?,
            excluded_signer_signature_hash.to_string(),
        ];
        query_rows(&self.db, query, args)
