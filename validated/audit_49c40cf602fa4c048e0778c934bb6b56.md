### Title
Client-Controlled MessageId Collision in Gateway Legacy Handler Causes Cross-User Response Hijacking - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The Gateway's legacy WebAPI trigger handler stores each in-flight user request's callback in a shared map keyed solely by the client-supplied `MessageId` (the JSON-RPC request `id`), with no check for an existing in-flight entry with the same key. An unprivileged external client submitting a request to the internet-facing gateway with the same `MessageId` as another concurrent request silently overwrites the earlier caller's callback entry, causing the DON's eventual response to be delivered to the wrong requester — a direct analog of the reported CDP-manager bug class where an unprivileged actor manipulates shared ordered/keyed state to corrupt another party's in-flight record.

### Finding Description
`gateway.ProcessRequest` decodes the incoming JSON-RPC request and, for legacy (DON-routed) requests, calls the target handler's `HandleLegacyUserMessage`, passing along the client-controlled JSON-RPC `id` as `msg.Body.MessageId`: [1](#0-0) 

In `core/services/gateway/handlers/capabilities/handler.go`, `HandleLegacyUserMessage` stores the caller's `callback` in `h.savedCallbacks` keyed only by `msg.Body.MessageId`, with **no existence check**: [2](#0-1) 

Because `MessageId` originates directly from the request's JSON-RPC `id` field (client-supplied), any unprivileged client can choose an arbitrary ID. If two different requests (e.g., a victim's and an attacker's) arrive with the same `MessageId` while the first is still in flight, the map entry is unconditionally overwritten:
```go
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
```
When a DON node later responds with that `MessageId`, `handleWebAPITriggerMessage` looks up and deletes whichever callback is currently stored and delivers the response to it — the second registrant, not necessarily the original requester: [3](#0-2) 

The only sender validation performed on the inbound node response is that `msg.Body.Sender == nodeAddr` (i.e., that the DON node is who it claims to be), not that the response correlates to the request's actual originating HTTP caller: [4](#0-3) 

This is notably inconsistent with the newer v2 HTTP trigger handler, which explicitly detects and rejects a duplicate/in-flight `requestID` before registering a callback: [5](#0-4) 

The legacy handler and the also-affected `dummyHandler` (`core/services/gateway/handlers/handler.dummy.go`) lack this guard entirely: [6](#0-5) 

### Impact Explanation
An unprivileged client interacting with the internet-facing gateway can, by choosing a `MessageId`/JSON-RPC `id` that collides with another in-flight request, hijack another user's response (receiving data intended for someone else) or silently cause the victim's request to hang until timeout. This is a cross-user response confusion issue, matching the accepted impact category in the Validate criteria. It does not require any privilege beyond normal API access to the gateway's user-facing endpoint, and requires no cooperation from the victim beyond concurrent, overlapping requests (which is realistic for any commonly-guessable or default ID such as `"1"`, timestamps, or sequential counters commonly used by clients).

### Likelihood Explanation
Exploitation requires the attacker to predict or race a `MessageId` value used by another concurrent legitimate request. Since IDs are entirely client-chosen with no server-side uniqueness enforcement, a malicious client can simply flood the gateway with requests for a range of common/likely ID values to increase the chance of collision with another user's concurrent request, or target scripted/automated clients known to reuse fixed or low-entropy IDs. This is a purely network-reachable, unprivileged-client attack with no need for insider or peer access.

### Recommendation
In `core/services/gateway/handlers/capabilities/handler.go` (`HandleLegacyUserMessage`) and `core/services/gateway/handlers/handler.dummy.go`, check for an existing entry in `savedCallbacks` for the given `MessageId` before inserting, and reject (or otherwise safely refuse) the second request with a conflict error — mirroring the guard already present in `httpTriggerHandler.setupCallback`. Additionally, consider deriving/validating message correlation using an internal or per-connection identifier that cannot be controlled/colluded by unrelated clients, rather than trusting the raw client-supplied ID alone.

### Proof of Concept
1. Client A sends a legacy request to the gateway with `id = "X"`; `HandleLegacyUserMessage` stores A's callback under `savedCallbacks["X"]` and dispatches to DON nodes.
2. Before the DON responds to A's request, Client B sends another legacy request also with `id = "X"`. `HandleLegacyUserMessage` overwrites `savedCallbacks["X"]` with B's callback (no uniqueness check, as shown at [7](#0-6) ).
3. When a DON node responds with `MessageId = "X"` (intended for A's request), `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds B's callback, deletes the entry, and delivers A's response data to B ( [8](#0-7) ).
4. Client A's original HTTP request instead blocks until `gw.ProcessRequest`'s context times out, returning a generic timeout/handler error ( [9](#0-8) ), while Client B has received a response that was not addressed to it.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageId] = &savedCallback{msg.Body.MessageId, callback}
	don := d.don
	d.mu.Unlock()
	params, err := json.Marshal(msg)
	if err != nil {
		return err
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
