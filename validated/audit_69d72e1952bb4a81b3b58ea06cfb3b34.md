### Title
Incomplete credential redaction blacklist causes token/secret/key fields to be logged in plaintext on request logging path shared with `jsonAPIError` error responses - ([File: core/web/router.go])

### Finding Description
Every request to `/v2` and `/query` routes passes through `loggerFunc`, which is installed as global middleware in `NewRouter` before route dispatch [1](#0-0) . This middleware captures the full request body and query values and logs them at Debug level after the handler completes, regardless of whether the handler succeeded or returned an error via `jsonAPIError` [2](#0-1) . `jsonAPIError` itself in `core/web/auth/helpers.go` does not log the request; it only appends the error to `c.Error()` for the gin context and writes the JSON error response [3](#0-2) , but the surrounding `loggerFunc` in `router.go` logs the raw request body/query for the very same request, sanitized only via `readSanitizedJSON`/`redact`, which rely on an `isBlacklisted` field-name check.

The blacklist only covers password-related field names: [4](#0-3) 

It contains `password`, `newpassword`, `oldpassword`, `current_password`, `new_account_password`, and a `strings.Contains(lk, "password")` fallback. It does **not** contain any entry for `token`, `secret`, or `key`/`keyexport`-style field names [5](#0-4) . Any JSON body field submitted by a client under names like `token`, `secret`, `incomingToken`, `outgoingToken`, `incomingSecret`, or export-bundle passwords not matching the `password` substring will be logged verbatim in the Debug-level request log, including on error paths that ultimately return through `jsonAPIError`.

### Impact Explanation
Because the sanitization blacklist is field-name-based and incomplete, credential-bearing request fields other than password variants (e.g., external-initiator tokens/secrets, or any other secret/token-named field accepted by a `/v2` handler) are written to the node's log output in cleartext whenever a request reaches the logging middleware and terminates in an error (or success) response. This matches the "server credential/key theft" impact class if an attacker with any lower-privileged log-reading access (e.g., via a separate lower-severity log-exposure bug) can read node logs, since sensitive values submitted by any user (including admins performing key/EI operations) would be recoverable from logs rather than properly redacted.

### Likelihood Explanation
Exploitation requires: (1) an attacker or victim submitting a request containing a `token`/`secret`-named field to any `/v2` route wrapped by `loggerFunc` (this applies broadly since the middleware is global), and (2) the attacker separately obtaining read access to the node's log stream (assumed to be a lower-severity issue per the audit's precondition). The redaction gap itself is deterministic and trivially reproducible for any field name not equal to or containing "password". This is a configuration/completeness gap in the blacklist rather than a bypassable check — it will reliably fail to redact any qualifying field.

### Recommendation
Expand `blacklist` (and/or the `isBlacklisted` substring check) in `core/web/router.go` to also match `token`, `secret`, `key`, `privatekey`, `mnemonic`, `seed`, and similar credential-related substrings, or convert to an allow-list model for logged fields instead of a deny-list, especially for endpoints handling key export/import and external-initiator token/secret creation.

### Proof of Concept
Table-driven Go test targeting `isBlacklisted`/`readSanitizedJSON` in `core/web/router.go`:
```go
func TestIsBlacklisted_CredentialFieldCoverage(t *testing.T) {
    cases := []string{
        "password", "newPassword", // should be true (already covered)
        "token", "secret", "incomingToken", "outgoingToken",
        "privateKey", "keyExportPassword", "mnemonic", "seed",
    }
    for _, k := range cases {
        assert.True(t, isBlacklisted(k), "field %q should be redacted but isn't", k)
    }
}
```
Expected: fails for `token`, `secret`, `incomingToken`, `outgoingToken`, `privateKey`, `keyExportPassword`, `mnemonic`, `seed`, demonstrating the incomplete redaction. A handler-level integration test can additionally POST a JSON body containing `{"token":"supersecret"}` to a `/v2` route that returns an error via `jsonAPIError`, capture logger output, and assert `"supersecret"` does not appear in plaintext — it currently will.

```go
// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
```
