### Title
Multisig requests execute with confirmations from removed members - `delete_member` never purges stale confirmation entries on requests it did not author - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only deletes requests whose `member` field (the original *creator*) equals the member being removed; it never scans the `confirmations` map to strip that member's confirmation string from requests *authored by someone else*. Because `confirm()` blindly trusts `confirmations.len()`, a stale confirmation cast by a member who has since been deleted (or deleted and re-added) still counts toward `num_confirmations`, letting a request execute with fewer live, currently-authorized confirmations than required.

### Finding Description
The binding that must hold is: `confirmations.get(request_id).len()` (the value used in `confirm()` to gate execution) `== |{m ∈ self.members : m confirmed request_id while being a member}|`. This is violated.

- `add_request` stores the creating member in `MultiSigRequestWithSigner.member` [1](#0-0) .
- `confirm` inserts `member.to_string()` into the request's `confirmations: HashSet<String>` and later checks purely `confirmations.len() as u32 + 1 >= self.num_confirmations` to decide whether to execute [2](#0-1) .
- `delete_member` removes only the requests whose `r.member == member` (i.e., requests *created* by the removed member) along with their confirmation sets; it never touches confirmation sets of requests created by other members even if the removed member had previously cast a confirmation on them [3](#0-2) .

Exploit flow (members = `[attacker(AccessKey{pk}), B, C]`, `num_confirmations=2`):
1. B creates request `R` (`r.member == B`).
2. Attacker calls `confirm(R)`: `confirmations.len()==0`, `0+1<2`, so it just inserts `attacker.to_string()` into `R`'s confirmation set and returns without executing [4](#0-3) .
3. B and C submit/confirm a `DeleteMember{member: AccessKey{pk}}` self-request, which executes and calls `delete_member`. Since `R.member == B`, `R` is not in the filtered `request_ids`, so `R`'s confirmation set — still containing the attacker's stale string — is left completely intact [5](#0-4) .
4. Optionally, B and C re-add the attacker via `AddMember{member: AccessKey{pk}}`, restoring the exact same `MultisigMember` (same public key ⇒ identical `to_string()` representation) with a freshly-attached access key, but `add_member` never touches the `confirmations` map either [6](#0-5) . (Re-adding is not even required for the exploit to succeed — the stale confirmation counts even permanently after deletion.)
5. C now calls `confirm(R)`. `confirmations.get(R)` still returns `{attacker_string}`, so `len()+1 == 2 >= num_confirmations`, and `execute_request` fires the underlying `Promise` (e.g., `Transfer`, `AddKey`, `FunctionCall`) [7](#0-6) .

No existing guard prevents this: `assert_valid_request` only checks that the caller is a current member and that the request/confirmation entries exist, not that every entry inside the confirmation `HashSet` still corresponds to a live member [8](#0-7) .

### Impact Explanation
An attacker (or any member who is later removed, deliberately or otherwise) leaves a "ghost" confirmation on any pending request authored by someone else. That ghost confirmation is honored forever, letting the remaining member(s) execute the request — including `Transfer`, `AddKey`, `DeployContract`, or `FunctionCall` actions — while only one truly live confirmation was actually cast, one below the configured `num_confirmations`. This directly matches the Critical category: "a multisig request executed below `num_confirmations` live members," and can result in NEAR leaving the multisig account, a full-access key being added, or a malicious contract deployment, all authorized by fewer live signers than the multisig's own policy requires. This is repeatable for every pending request that a soon-to-be-removed member confirmed but did not author, across any multisig instance deployed from this contract.

### Likelihood Explanation
Preconditions are trivial and require no special privilege beyond being one of the ordinary multisig members participating in normal governance: a member confirms a request they didn't create, and that member is later removed (a routine operation, e.g. key rotation). No attacker-specific unprivileged capability is needed beyond acting as a legitimate multisig member during normal churn — meaning any operational membership change (rotating a compromised or departing member) silently leaves behind exploitable stale confirmations. This makes the bug highly likely to be triggered even without adversarial intent, and trivially repeatable for every request confirmed-but-not-executed prior to a membership change.

### Recommendation
When a member is deleted, iterate over **all** entries in `confirmations` (not just requests authored by that member) and remove the deleted member's `to_string()` entry from every confirmation `HashSet`. Alternatively, validate at `confirm()`/execution time that every string in the confirmation set still corresponds to a member currently present in `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
```rust
// multisig2/src/lib.rs test module
#[test]
fn test_stale_confirmation_survives_delete_member() {
    // members: alice (Account), bob (Account), attacker (AccessKey TEST_KEY)
    // num_confirmations = 2
    testing_env!(context_with_account(alice(), 1_000));
    let mut c = MultiSigContract::new(members_for_test(), 2); // [alice, bob, attacker]

    // 1. bob creates request R (Transfer)
    testing_env!(context_with_account(bob(), 1_000));
    let request = MultiSigRequest {
        receiver_id: alice(),
        actions: vec![MultiSigRequestAction::Transfer { amount: 1_000.into() }],
    };
    let request_id = c.add_request(request.clone());

    // 2. attacker confirms R (not enough to execute, len 0+1 < 2)
    testing_env!(context_with_key(attacker_pk(), 1_000));
    c.confirm(request_id);
    assert_eq!(c.confirmations.get(&request_id).unwrap().len(), 1);

    // 3. alice+bob remove attacker via DeleteMember self-request (2 confirmations)
    testing_env!(context_with_account(alice(), 1_000));
    let del_req = MultiSigRequest {
        receiver_id: alice(), // current_account_id
        actions: vec![MultiSigRequestAction::DeleteMember {
            member: MultisigMember::AccessKey { public_key: attacker_pk() },
        }],
    };
    let del_id = c.add_request(del_req);
    c.confirm(del_id); // alice confirms, 1 < 2
    testing_env!(context_with_account(bob(), 1_000));
    c.confirm(del_id); // bob confirms -> executes DeleteMember

    // ASSERT: R's confirmation set still holds the (now removed) attacker entry
    assert_eq!(c.confirmations.get(&request_id).unwrap().len(), 1);
    assert!(!c.members.contains(&MultisigMember::AccessKey { public_key: attacker_pk() }));

    // 4. bob alone confirms R -> stale attacker confirmation + bob = 2 >= num_confirmations
    testing_env!(context_with_account(bob(), 1_000));
    let result = c.confirm(request_id);
    // BINDING VIOLATION: request executed (removed from `requests`) with only
    // ONE live confirming member (bob), while num_confirmations == 2.
    assert_eq!(c.requests.len(), 0);
}
```
This test demonstrates that `R` executes via `execute_request` (Promise fired) after only one live member (`bob`) freshly confirmed, with the second "confirmation" coming from `attacker`, who was already deleted from `self.members` — violating `confirmations.len() == live confirming members` and satisfying the Critical impact bar.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(","),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name,
                    args.into(),
                    deposit.into(),
                    Gas::from(gas.0),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
