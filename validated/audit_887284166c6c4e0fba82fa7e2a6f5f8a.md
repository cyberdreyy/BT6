### Title
Cache alternate-key archive path bypasses traversal sanitization when `FF_HASH_CACHE_KEYS` is enabled - (File: `functions/concrete/run/stages/cache_archive.go`)

### Summary
`cacheArchivePath` in `functions/concrete/run/stages/cache_archive.go` builds the on-disk cache archive path with a bare `filepath.Join(e.CacheDir, key, "cache.zip")` and performs no traversal or absolute-path validation of `key`, relying entirely on the caller to have already sanitized the key. The primary cache key (`CacheArchive.Key` / `CacheSource.Key`) is always either passed through `cachekey.Sanitize` (path-traversal safe) or SHA-256 hashed before reaching this function, but the *alternate* key (`CacheArchive.AlternateKey` / `CacheSource.AlternateDescriptor` companion `AlternateKey`) is derived from the raw, unsanitized human-readable key when `FF_HASH_CACHE_KEYS` is enabled.

### Finding Description
`cacheArchivePath` is: [1](#0-0) 

It has no defense of its own — it trusts that `key` cannot contain `..` segments or be absolute. Confinement is only achieved because upstream callers sanitize the key before constructing `CacheArchive`/`CacheSource`. That upstream logic lives in the analogous (and explicitly "mirrored", per the doc comment on `CacheExtract.archivePath`) `newCacheConfig` function in `shells/abstract.go`: [2](#0-1) 

The key defect: when `featureflags.HashCacheKeys` is **on**, the `sanitizer` is replaced with a no-op that returns the raw, job-supplied key unchanged (`func(s string) (string, error) { return s, nil }`), while `hasher` becomes SHA-256. `humanKey` therefore keeps any `../` sequences the job supplied via `cache:key` (expanded from CI variables via `build.GetAllVariables().ExpandValue(userKey)`), and only the *primary* `hashedKey` is hex-hashed and thus safe: [3](#0-2) 

However, `alternateKey := cacheAlternateKey(humanKey, hashEnabled)` returns `humanKey` itself (unsanitized, unhashed) when hashing is enabled, and this unsanitized key is fed straight into the same unguarded `path.Join(build.CacheDir, key, "cache.zip")` construction used for `AlternateArchiveFile`: [4](#0-3) 

The equivalent path in the new stages architecture is `CacheArchive.alternateArchivePath` / `CacheExtract`'s alternate handling, which calls the very same unguarded `cacheArchivePath(e, s.AlternateKey)`: [5](#0-4) 

Because `filepath.Join` on an absolute `CacheDir` collapses excess `..` at the filesystem root rather than erroring, a sufficiently long `../../../...` prefix in the job's `cache:key` cancels out `CacheDir`'s own depth and lands the resulting `--alternate-file` argument outside `CacheDir` (e.g. `CacheDir=/cache` + key `../../etc/cron.d/x` → `/etc/cron.d/x/cache.zip`), which is then passed to `cache-archiver --alternate-file` / used by `cache-extractor` for the alternate URL, per `functions/concrete/run/stages/cache_archive.go:53-55` and `functions/concrete/run/stages/cache_extract.go:102-112`.

An absolute-path key (e.g. `/etc/passwd`) does **not** escape via `filepath.Join`, since `Join` treats non-first arguments as ordinary path components (unlike a raw `path.Join` "reset to root" semantic) — so that specific sub-case in the question is not exploitable. The real escape vector is `../`-style relative traversal combined with the alternate-key sanitizer bypass.

### Impact Explanation
When `FF_HASH_CACHE_KEYS` is enabled, a job can set `cache:key` to a value containing `../` segments and cause the runner to write the created cache archive (`cache-archiver --alternate-file`) to, or fetch a "cache" from (`cache-extractor --alternate-url` local staging), a path outside the intended `CacheDir`. This can lead to cross-job/cross-project cache-directory poisoning or writing files to unintended locations on the host/container filesystem that backs the cache volume, violating the "file operations must stay within intended cache root" invariant.

### Likelihood Explanation
Precondition: `FF_HASH_CACHE_KEYS` must be enabled. GitLab Runner feature flags of this `FF_*` form are commonly settable per-job via the `variables:` section of `.gitlab-ci.yml`, which is fully attacker/job-controlled and requires no runner-admin action. Given that, the only remaining requirement is supplying a `cache:key` with enough leading `../` components to cancel `CacheDir`'s path depth — fully job-controlled and repeatable. The primary (hashed) key path is not affected, limiting the practical blast radius to the alternate-key fallback mechanism, but that mechanism is exercised on every cache archive/extract operation whenever hashing is enabled (used to interoperate with the "other" naming scheme).

### Recommendation
Apply `cachekey.Sanitize` (or an equivalent traversal-safe normalization) to the human-readable key unconditionally, before it is used to compute `alternateKey`, regardless of `FF_HASH_CACHE_KEYS` state. Additionally, harden `cacheArchivePath` itself (defense-in-depth) to reject or clean keys that resolve outside `filepath.Clean(e.CacheDir)` after joining, rather than relying solely on caller-side sanitization.

### Proof of Concept
Go unit test targeting `cacheArchivePath` directly:
```go
func TestCacheArchivePath_Confinement(t *testing.T) {
    e := &env.Env{WorkingDir: "/builds/g/p", CacheDir: "/cache"}
    for _, key := range []string{"../../etc/cron.d/x", "../../../../etc/passwd"} {
        got := cacheArchivePath(e, key)
        abs := filepath.Join(e.WorkingDir, got) // resolve the returned relative path
        assert.Truef(t, strings.HasPrefix(filepath.Clean(abs), filepath.Clean(e.CacheDir)+string(filepath.Separator)),
            "archive path %q escaped CacheDir %q", abs, e.CacheDir)
    }
}
```
This test currently fails for `../../etc/cron.d/x`-style keys because `cacheArchivePath` performs no confinement check. A companion test on `shells/abstract.go`'s `newCacheConfig` with `featureflags.HashCacheKeys: true` and `userKey: "../../etc/cron.d/x"` should assert that `AlternateArchiveFile` remains lexically under `CacheDir`; it currently does not.

func newCacheConfig(build *common.Build, userKey string, keyChecks ...func(string) bool) (*cacheConfig, string, error) {
	if build.CacheDir == "" {
		return nil, "", fmt.Errorf("unset cache directory")
	}

	rawKey := path.Join("/", build.JobInfo.Name, build.GitInfo.Ref)[1:]
	if userKey != "" {
		rawKey = build.GetAllVariables().ExpandValue(userKey)
	}

	hasher := func(s string) string { return s }
	sanitizer := cachekey.Sanitize
	// if hash key support is enabled, we don't need to sanitize keys anymore
	if build.IsFeatureFlagOn(featureflags.HashCacheKeys) {
		hasher = func(s string) string { return fmt.Sprintf("%x", sha256.Sum256([]byte(s))) }
		sanitizer = func(s string) (string, error) { return s, nil }
	}

	var warning string
	humanKey, err := sanitizer(rawKey)
	switch {
	case err != nil:
		warning = err.Error()
	case humanKey != rawKey:
		warning = fmt.Sprintf("cache key %q sanitized to %q", rawKey, humanKey)
	}

	for _, check := range keyChecks {
		if !check(humanKey) {
			// if a key check does not succeed, we drop out immediately
			return nil, warning, nil
		}
	}

	if humanKey == "" {
		return nil, warning, fmt.Errorf("empty cache key")
	}

	hashedKey := hasher(humanKey)
