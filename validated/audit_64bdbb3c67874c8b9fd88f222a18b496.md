### Title
Unsanitized `file.Name` allows zip-slip path traversal in `os.Lchown`/`os.Chtimes` calls during zip extraction, amplified across many crafted entries - ([File: helpers/archives/zip_extra.go])

### Summary
The `processZipExtra` for-loop itself terminates correctly and safely (it is bounded by the length of `file.Extra`, consumed byte-by-byte until `io.EOF`), so the "infinite loop / non-termination" premise in the question is false. However, the underlying primitive it exercises — `os.Lchown(file.Name, ...)` and `os.Chtimes(file.Name, ...)` in `helpers/archives/zip_extra.go` and `helpers/archives/zip_extra_unix.go` — operates on the raw, attacker-controlled `zip.FileHeader.Name` with no path-traversal sanitization anywhere in the extraction pipeline, so a crafted archive can direct ownership/timestamp changes to paths outside the intended extraction root, and this is repeated once per malicious entry.

### Finding Description
`ExtractZipArchive` in `helpers/archives/zip_extract.go` (lines 85-110) iterates `archive.File` twice: once to write file contents via `extractZipFile`, and once to apply mode/ownership/timestamp metadata via `lchmod` and `processZipExtra`. The only path check performed anywhere in this pipeline is `errorIfGitDirectory` (`helpers/archives/path_check_helper.go` lines 13-31), which only detects a leading `.git` path segment — it does not clean or reject `..` segments, absolute paths, or symlink-based escapes.

`processZipExtra` (`helpers/archives/zip_extra.go` lines 96-122) walks `file.Extra` and, for each `ZipUIDGidFieldType`/`ZipTimestampFieldType` record found, calls `processZipUIDGidField`/`processZipTimestampField`, which in turn call: [1](#0-0) [2](#0-1) 

Both pass `file.Name` straight from the zip header, unresolved and unvalidated, to `os.Lchown`/`os.Chtimes`. Since a zip entry `Name` is fully attacker-controlled (e.g. `../../shared-cache/foo`, or a name that resolves to a path already present via a symlink planted by an earlier "file" entry in the same archive), the effective filesystem target can be outside the intended extraction directory.

The loop over `archive.File` in `ExtractZipArchive` (lines 98-107) means this call happens once per entry, so an archive with N crafted entries produces N `Lchown`/`Chtimes` calls against N attacker-chosen paths (via traversal or shared symlink targets) — this is "amplification by entry count," not by the inner `processZipExtra` loop, which only processes one file's own `Extra` bytes and always terminates.

### Impact Explanation
An attacker who controls the contents of a cache or artifact zip (any CI job author) can cause the Runner, on extraction, to invoke `os.Lchown`/`os.Chtimes` against files outside the extraction root — e.g. shared bind-mounted cache volumes, or (via symlink-then-metadata ordering) files elsewhere on the host filesystem reachable from the extraction working directory. This violates the invariant that "file operations must stay within intended build/cache/artifact roots" and can corrupt ownership/timestamps of files shared across jobs/projects on a shared runner host, without requiring any privileged executor misconfiguration.

### Likelihood Explanation
Feasible and repeatable: creating a zip with crafted `Name` fields and `0x7875`/`0x5455` extra fields requires no special privilege — any job that produces or consumes a cache/artifact archive extracted by `ExtractZipArchive`/`ExtractZipFile` can trigger it. The only precondition is a shared/writable extraction context (e.g., cache volume shared across jobs on the same host/executor), which is a normal GitLab Runner deployment pattern, not an admin misconfiguration being restated.

### Recommendation
Before any extraction or metadata operation (`extractZipFile`, `processZipUIDGidField`, `processZipTimestampField`, `lchmod`), resolve and validate `file.Name` against the extraction root: reject entries whose cleaned path escapes the root (`..` traversal), reject absolute paths, and ensure symlink targets created earlier in the same archive can't be used to redirect subsequent same-named operations outside the root. This should live in a shared path-validation helper invoked from `ExtractZipArchive` for every entry, not just the `.git` check.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversalOwnershipChange(t *testing.T) {
    tmp := t.TempDir()
    outsideTarget := filepath.Join(tmp, "..", "victim-outside-root")
    os.WriteFile(outsideTarget, []byte("preexisting"), 0o644)

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    hdr := &zip.FileHeader{Name: "../victim-outside-root"}
    hdr.SetMode(0o644)
    // craft ZipUIDGidFieldType extra with attacker-chosen uid/gid
    var extra bytes.Buffer
    binary.Write(&extra, binary.LittleEndian, ZipExtraField{Type: ZipUIDGidFieldType, Size: 10})
    binary.Write(&extra, binary.LittleEndian, ZipUIDGidField{1, 4, 1337, 4, 1337})
    hdr.Extra = extra.Bytes()
    w, _ := zw.CreateHeader(hdr)
    w.Write([]byte("data"))
    zw.Close()

    prevWD, _ := os.Getwd()
    os.Chdir(tmp)
    defer os.Chdir(prevWD)

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := ExtractZipArchive(r)
    require.NoError(t, err)

    // Assert ownership attempt was made against the outside-root path
    fi, _ := os.Lstat(outsideTarget)
    stat := fi.Sys().(*syscall.Stat_t)
    require.EqualValues(t, 1337, stat.Uid, "ownership of file outside extraction root was modified")
}
```
Expected assertion: the file outside the intended extraction directory (`victim-outside-root`) has its UID changed to the attacker-specified value `1337`, proving the missing path-containment check, independent of the (correctly terminating) `processZipExtra` loop.

```go
func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
```

```go
func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```
