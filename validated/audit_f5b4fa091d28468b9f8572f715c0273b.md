## Analysis

The CVE-2017-12141 bug class is a heap-based buffer overflow reached while parsing attacker-crafted, structurally-nested binary data (`TNEFFillMapi` in `ytnef.c`), causing memory-safety corruption and a crash/DoS. The closest reachable analog in `ThankGod76/base--024` is an **unbounded-recursion memory-safety issue in the Merkle-Patricia-Trie (MPT) node decoder** used by the fault-proof program, which is fed by attacker/challenger-supplied preimages during dispute-game execution.

### Root cause

`TrieNode::decode` in `crates/proof/mpt/src/node.rs` recursively decodes RLP-encoded trie nodes: an `Extension` node's child pointer is decoded by directly recursing into `Self::decode(buf)` [1](#0-0) , and children shorter than 32 bytes RLP-encoded length are **embedded inline rather than blinded/hashed** (`node.length() >= B256::ZERO.len()` gates blinding) [2](#0-1) . This means a single self-contained buffer can encode an arbitrarily deep chain of nested `Extension` nodes (each only a few bytes of overhead) that is fully parsed via unbounded, non-tail recursion in `Decodable for TrieNode::decode` and `try_decode_leaf_or_extension_payload` with no depth limit or iterative fallback anywhere in the decode path [3](#0-2) .

This decoder is invoked directly on bytes retrieved from the untrusted preimage oracle in the fault-proof program (`OracleL1ChainProvider::trie_node_by_hash`) without any nesting-depth validation before/after `TrieNode::decode` [4](#0-3) , and similarly in the executor's disk-backed trie provider [5](#0-4) .

### Impact

Because a challenger/dispute-game participant supplies preimages that only need to match a claimed hash (the content itself is otherwise attacker-controlled), a maliciously crafted preimage with thousands of nested inline `Extension` levels can drive the recursive decoder to exhaust the call stack, crashing the fault-proof program mid-execution. This is a "node halt" / incorrect dispute resolution class impact — the fault-proof program can no longer produce a provable output for that step, which can stall or invalidate a dispute game.

### Caveat

I did not find an explicit recursion-depth guard anywhere in `crates/proof/mpt`, but I could not fully verify from the index whether some upstream limit (e.g., overall trie depth bound enforced elsewhere in the derivation/dispute pipeline, or a preimage-size cap in the oracle/host) mitigates this before the recursion is reached. Given index size limits, some call-site or host-side size-limiting logic may exist outside what I could inspect — a full Devin session with complete repo access would be needed to confirm whether any such external bound exists before treating this as conclusively exploitable.

### Title
Unbounded recursive TrieNode decoding allows stack-exhaustion crash of the fault-proof program via crafted dispute-game preimages - (`crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` recursively parses nested `Extension`/`Branch` nodes without any depth limit, and nodes under 32 bytes are embedded inline rather than hash-blinded, allowing a single crafted preimage buffer to encode deep recursive nesting.

### Finding Description
`Decodable for TrieNode::decode` dispatches `Extension` payload parsing to `try_decode_leaf_or_extension_payload`, which recurses into `Self::decode(buf)` for the child node [6](#0-5) . Since short children are stored inline (not blinded) per the encoding logic [2](#0-1) , an attacker can build one preimage blob containing thousands of nested extension levels, each adding a stack frame during decode, with no maximum-depth check enforced in `node.rs` or its callers.

### Impact Explanation
This is reachable from the fault-proof program's trie-node provider, which decodes oracle-supplied preimages directly (`OracleL1ChainProvider::trie_node_by_hash`) [7](#0-6) . A dispute-game participant who controls what preimage is served for a claimed hash can trigger stack exhaustion, crashing/halting the fault-proof program and preventing it from producing a correct provable output root for that execution step.

### Likelihood Explanation
Constructing a deeply nested but hash-valid preimage is straightforward (attacker computes their own keccak256 hash over the crafted bytes), and no code path bounds recursion depth before or during `TrieNode::decode`.

### Recommendation
Add an explicit maximum recursion/nesting depth check in `TrieNode::decode` (and the `Extension`/`Branch` list decode paths) or rewrite the decoder to use an explicit iterative work-stack instead of native call recursion, rejecting nodes that exceed the practical trie depth (e.g., 64–128 levels for a 32-byte-keyed MPT).

### Proof of Concept
Construct an RLP buffer consisting of thousands of consecutive 2-element extension-node lists (`[encoded_path, child]`), where each `child` is itself a nested extension-node list under the 32-byte inline threshold, terminated by a short leaf node. Feed this buffer as the trie-node preimage returned for the hash requested by `OracleL1ChainProvider::trie_node_by_hash`/`TrieNodeProvider::trie_node_by_hash`; decoding it drives `TrieNode::decode` into recursion depth proportional to nesting count, exhausting the stack.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
