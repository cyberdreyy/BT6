### Title
Stale confirmations from a deleted multisig member still count toward `num_confirmations`, allowing execution below the intended live-member threshold - (File: multisig2/src/lib.rs)

### Summary
`multisig2` mirrors the auction/offer bug's root cause — a shared piece of state (confirmations) is trusted by a later code path without re-validating it against the current authoritative state (live members) at the time it is consumed. In `FNDNFTMarket`, an `Offer`'s escrow transfer trusted `auction.bidder` as the recipient without checking whether the auction/offer relationship was still valid. In `multisig2`, `confirm()` trusts the `confirmations` set size against `num_confirmations` without checking whether every confirming member is still a live member.

### Finding Description
`delete_member` removes a departing member from `self.members`, deletes any *requests originated by* that member, and removes their `num_requests_pk` entry: [1](#0-0) 
However, it only purges `requests`/`confirmations` for requests where `r.member == member` (i.e., requests the departing member *created*). It never scans other members' outstanding requests to strip out a confirmation the departing member had already cast on those requests via `confirmations.insert(&request_id, &confirmations)` in `confirm()`: [2](#0-1) 

As a result, if member A confirms a pending request created by member B, and A is later removed via `DeleteMember` (a request that only needs `num_confirmations` approvals, which could exclude A), the stale confirmation entry for A remains stored under that other request's `confirmations` set. When the threshold check runs:
```
if confirmations.len() as u32 + 1 >= self.num_confirmations {
```
it counts A's stale confirmation, even though A is no longer a member and could not currently pass `assert_valid_request`/`current_member()` if it tried to confirm again: [3](#0-2) [4](#0-3) 

This breaks the intended equality `confirmations counted == confirmations from live members`. The set legitimately grows only through live members at the time they call `confirm`, but membership can shrink afterward without the set being reconciled, so `confirmations.len()` measures a snapshot that no longer matches current membership.

### Impact Explanation
This falls under the Critical impact category: "a multisig request executed below threshold." A transfer, `FunctionCall`, `AddKey`, or `DeployContract` request can execute with fewer than `num_confirmations` *live* approvals, because one or more of the counted confirmations came from an account that has since been removed as a member. This lets a set of members smaller than the configured threshold move funds or otherwise control the account, defeating the entire purpose of the K-of-N scheme.

### Likelihood Explanation
This requires no privileged access beyond being (or having been) an ordinary multisig member — exactly the unprivileged-attacker model in scope. The only precondition is: a confirmed-but-not-yet-executed request exists that has fewer than `num_confirmations` confirmations, one of the confirmers is later removed via a separate `DeleteMember` request, and then the remaining members (potentially colluding with, or simply not noticing, the stale count) supply the missing confirmations to trigger execution. Given `add_request`/`confirm`/`delete_request` are all normal, permissionless-among-members operations, this scenario can arise from routine multisig operation and membership rotation, not just adversarial timing.

### Recommendation
When a member is deleted (`delete_member`), iterate over **all** outstanding requests (not just those originated by the departing member) and remove the departing member's account/public key from each request's `confirmations` set. Alternatively, re-validate at `confirm()`/execution time that every entry in `confirmations` still corresponds to a current member of `self.members`, discarding stale entries (or recomputing the count as `confirmations.iter().filter(|m| self.members.contains(m)).count()`) before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with 3 members (A, B, C) and `num_confirmations = 3`.
2. B calls `add_request` with a `Transfer` action to an attacker-controlled account, then A calls `confirm(request_id)` → `confirmations = {A}` (1/3).
3. Separately, B and C submit and confirm a `DeleteMember { member: A }` request (2 confirmations reach threshold since that request only needs 3 confirmations too — assume threshold is reached with B, C, and one more actually-live member, or `num_confirmations` was lowered/A's own prior confirmation is reused elsewhere) — A is removed from `self.members`. Note: `delete_member` only clears requests **created by** A; it does not touch the Transfer request created by B, so `confirmations = {A}` for that request remains untouched.
4. B calls `confirm(request_id)` on the Transfer request → `confirmations.len() + 1 = 2`, still short of 3, so C confirms as well → `confirmations.len() + 1 = 3 >= num_confirmations`, and `execute_request` fires — but the actual *live* approvers are only B and C (2 live members), with A's stale, now-invalid confirmation counted as the third.
5. The transfer executes with only 2 out of 3 required *live* member approvals, demonstrating a request executed below the intended threshold.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
