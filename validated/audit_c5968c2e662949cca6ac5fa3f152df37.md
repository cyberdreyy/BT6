### Title
Tar+zstd extractor allows unrestricted symlink targets via `hdr.Linkname`, enabling a tar-slip/symlink-follow escape outside `e.dir` - ([File: commands/helpers/archive/tarzstd/tarzstd_extractor.go])

### Summary
`extractor.Extract` validates only the *location* of an archive entry (`e.dir + hdr.Name`) against the chroot prefix, but never validates the *target* of `TypeSymlink` entries (`hdr.Linkname`) before calling `os.Symlink(hdr.Linkname, path)` in the deferred loop. Because subsequent extraction of any other archive entry reuses `os.MkdirAll`/`os.Create`, which follow existing symlinks in intermediate path components, a two-entry archive can create a symlink pointing outside `e.dir` and then write/create files through it, escaping the intended extraction root.

### Finding Description
The path-safety check at [1](#0-0)  only constrains where an entry is *created* (`filepath.Join(e.dir, hdr.Name)`), by checking that path has `e.dir` as a prefix. It performs no check on `hdr.Linkname` at all.

For symlink entries, the header is simply deferred and later materialized unconditionally: [2](#0-1) 
`os.Symlink(hdr.Linkname, path)` is called with an attacker-controlled `Linkname` that can be `../../../etc`, `/etc`, or any absolute/relative path — there is no check that the resolved symlink target stays inside `e.dir`.

By itself, creating a dangling/misdirected symlink object inside `e.dir` does not write data outside `e.dir` — but it sets up a classic "tar-slip" follow-through: if the same archive (or the same extraction directory reused across the job) later contains an entry whose `hdr.Name` is `"<symlinkname>/evilfile"`, the earlier per-entry code path calls:
- `os.MkdirAll(filepath.Dir(path), 0777)` at [3](#0-2)  and
- `os.Create(path)` at [4](#0-3) 

Both of these standard library calls transparently follow symlinks present in intermediate path components. Since the prefix check at line 62 only inspects the *textual* joined path (`e.dir/<symlinkname>/evilfile`), which still starts with `e.dir`, the check passes even though the real filesystem write, after the OS follows the earlier-planted symlink, lands wherever the symlink points (e.g. under `/etc` or a sibling job's workspace). The `updateFileMetadata`/`lchown`/`lchtimes` calls in [5](#0-4)  are correctly no-follow (`Lutimes`/`Lchown`/`AT_SYMLINK_NOFOLLOW`) and only affect the symlink inode itself, so they are not the escape vector — the escape happens through the plain `os.MkdirAll`/`os.Create` calls used for later entries that traverse through the attacker-planted symlink.

No other layer in `commands/helpers/archive/archive.go` or the extractor performs `Lstat`-based intermediate-component checks or `EvalSymlinks` confinement, so this is unmitigated.

### Impact Explanation
Cache and artifact archives are fully attacker-controlled content (a pipeline author's job script populates the cache/artifact directory, which is later tar+zstd-archived and, in a subsequent job, extracted with this code). A crafted archive can plant a symlink named e.g. `link` → `/` (or any absolute path) followed by an entry `link/authorized_keys` or similar, causing the extractor to write files outside the intended `e.dir` job workspace on the machine performing extraction. This matches the scoped impact of writing outside the job workspace/cache root, potentially affecting other jobs/tenants if the extraction host or volume is shared/reused.

### Likelihood Explanation
This requires no special privilege — any pipeline author who can populate a cache or artifact directory can produce this archive; the tar format fully supports `TypeSymlink` with arbitrary `Linkname` values, and Go's `archive/tar` reader does not sanitize `Linkname`. The exploit is deterministic and repeatable given the deferred-extraction ordering shown in the code (symlinks/directories always processed in a second pass after all `TypeReg` entries, so ordering within the archive controls which entries are treated as "planted symlink" vs "follow-through write").

### Recommendation
Validate `hdr.Linkname` resolution before calling `os.Symlink`: reject (or resolve-and-check) any symlink whose target, once joined relative to its containing directory and cleaned, escapes `e.dir`. Additionally, before creating any regular file/dir whose parent path component is a symlink, `Lstat` each path component (or use `securejoin`-style path resolution / `openat2` with `RESOLVE_BENEATH`/`O_NOFOLLOW` on non-final components) so extraction can never traverse through an attacker-planted symlink, whether or not the symlink target address itself is validated.

### Proof of Concept
```go
func TestExtractor_SymlinkEscape(t *testing.T) {
    dir := t.TempDir()
    var buf bytes.Buffer
    zw, _ := zstd.NewWriter(&buf)
    tw := tar.NewWriter(zw)

    // Plant a symlink inside e.dir pointing outside it
    _ = tw.WriteHeader(&tar.Header{
        Name:     "escape",
        Typeflag: tar.TypeSymlink,
        Linkname: "../../../../tmp", // or absolute "/tmp"
        Mode:     0777,
    })

    // Follow-through: write a file through the symlink
    content := []byte("pwned")
    _ = tw.WriteHeader(&tar.Header{
        Name:     "escape/pwned.txt",
        Typeflag: tar.TypeReg,
        Size:     int64(len(content)),
        Mode:     0644,
    })
    _, _ = tw.Write(content)

    _ = tw.Close()
    _ = zw.Close()

    r := bytes.NewReader(buf.Bytes())
    ext, err := tarzstd.NewExtractor(r, int64(r.Len()), dir)
    require.NoError(t, err)

    err = ext.Extract(context.Background())
    // Expected (fixed) behavior: extraction must fail or refuse to follow the symlink
    require.Error(t, err)

    // Expected (buggy) behavior observed today: no error, and file exists outside dir
    _, statErr := os.Stat("/tmp/pwned.txt")
    require.Error(t, statErr, "file must not be written outside extraction root")
}
```
Assertions: extraction must either reject the archive (Linkname escapes `e.dir`) or must not allow subsequent entries to traverse through the planted symlink to write outside `dir`.

func lchtimes(name string, mode os.FileMode, atime, mtime time.Time) error {
	if runtime.GOOS == "zos" {
		if err := lchmod(name, mode); err != nil {
			return err
		}
	}
	at := unix.NsecToTimeval(atime.UnixNano())
	mt := unix.NsecToTimeval(mtime.UnixNano())
	tv := [2]unix.Timeval{at, mt}

	err := unix.Lutimes(name, tv[:])
	if err != nil {
		return &os.PathError{Op: "lchtimes", Path: name, Err: err}
	}

	return nil
}
