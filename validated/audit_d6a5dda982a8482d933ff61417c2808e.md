### Title
Zero-elasticity `BaseFeeParams` from decoded block-header extra data can reach `calc_next_block_base_fee`, causing an integer-division-by-zero panic - ([File: crates/proof/executor/src/util.rs])

### Summary
`decode_holocene_eip_1559_params_block_header` and `decode_jovian_eip_1559_params_block_header` in `crates/proof/executor/src/util.rs` only guard against a zero *denominator*, but never validate that the decoded *elasticity multiplier* is non-zero. The resulting `BaseFeeParams { elasticity_multiplier, max_change_denominator }` is passed into `alloy_eips::calc_next_block_base_fee` (via `StatelessL2Builder::next_block_base_fee` / `prepare_block_env` in `crates/proof/executor/src/builder/env.rs`), which computes `gas_target = gas_limit / elasticity_multiplier`. An `elasticity_multiplier` of `0` causes an integer division-by-zero panic in Rust, aborting execution — directly analogous to the ImageMagick `sRGBTransformImage()` division-by-zero (CVE-2021-20311), which is also a divide-by-zero triggered by attacker-supplied input reaching an unchecked arithmetic operation.

### Finding Description
`HoloceneExtraData::decode` / `JovianExtraData::decode` (in `crates/common/consensus/src/extra/holocene.rs` and the Jovian analog) simply split the header's `extra_data` bytes into two raw `u32` values — `elasticity` and `denominator` — with no semantic validation of either value: [1](#0-0) 

`decode_holocene_eip_1559_params_block_header` and `decode_jovian_eip_1559_params_block_header` in the proof executor consume these decoded values and only check `denominator == 0`: [2](#0-1) 

There is no corresponding check for `elasticity == 0`. Compare this to the equivalent logic in `crates/execution/chainspec/src/basefee.rs`, `base_fee_params_from_extra_data`, which explicitly rejects the case where exactly one of `elasticity`/`denominator` is zero: [3](#0-2) 

The proof-executor path does not reuse this stricter validation. The resulting `BaseFeeParams` (with `elasticity_multiplier` potentially `0`) flows from `StatelessL2Builder::active_base_fee_params` into `prepare_block_env` → `next_block_base_fee` → `alloy_eips::calc_next_block_base_fee`: [4](#0-3) [5](#0-4) 

`calc_next_block_base_fee` (from `alloy_eips`, external to this repo) computes the EIP-1559 gas target as `parent_gas_limit / base_fee_params.elasticity_multiplier`. When `elasticity_multiplier == 0`, this is an integer division by zero, which panics in Rust (`attempt to divide by zero`), aborting the process.

The extra data being decoded here is the parent L2 block header's `extraData` field, which for the fault-proof / stateless L2 execution path is derived from L1 batch/deposit data during block derivation — data that is not independently re-validated for a non-zero elasticity multiplier before reaching this arithmetic.

### Impact Explanation
A crafted header with a non-zero denominator but zero elasticity multiplier reaches an unguarded division, causing an immediate panic. In the fault-proof program / stateless L2 builder context, this halts proof generation (denial of service for the dispute-game/fault-proof pipeline that depends on this executor), matching the "node halt" / "wrong provable output root" (via aborted execution rather than a wrong root) impact category permitted by the scan rules. This is a High-severity availability issue, directly analogous to the referenced CVE's division-by-zero DoS.

### Likelihood Explanation
The only requirement is a Holocene/Jovian-encoded `extra_data` header field with a non-zero denominator and a zero elasticity multiplier — a 9- or 17-byte value fully attacker/derivation-controlled. No privileged role is required to construct such a header value that flows through block derivation; the check that exists (`denominator == 0`) demonstrates the developers were aware of the division-by-zero risk but did not fully close it for the elasticity term.

### Recommendation
Add symmetric validation in `decode_holocene_eip_1559_params_block_header` and `decode_jovian_eip_1559_params_block_header` (mirroring `base_fee_params_from_extra_data` in `crates/execution/chainspec/src/basefee.rs`): reject the case where `elasticity == 0` while `denominator != 0` (and vice versa), returning `Eip1559ValidationError`/`EIP1559ParamError::InvalidParams` instead of allowing `elasticity_multiplier = 0` to reach `calc_next_block_base_fee`.

### Proof of Concept
1. Construct a Holocene-encoded header `extra_data`: `[0x00 (version), denominator=0x00000001 (nonzero), elasticity=0x00000000]` (9 bytes total).
2. Feed this header as the `parent_header` into `StatelessL2Builder::active_base_fee_params` with Holocene active and Jovian inactive.
3. `decode_holocene_eip_1559_params_block_header` returns `Ok(BaseFeeParams { elasticity_multiplier: 0, max_change_denominator: 1 })` because only `denominator == 0` is checked.
4. This `BaseFeeParams` is passed to `next_block_base_fee` → `calc_next_block_base_fee(gas_used, parent.gas_limit(), ..., params)`, which internally computes `parent.gas_limit() / params.elasticity_multiplier` → divide-by-zero panic, aborting the executor process.

    /// Returns (`elasticity`, `denominator`).
    pub fn decode_params(eip_1559_params: B64) -> (u32, u32) {

        let elasticity: [u8; 4] = eip_1559_params.0[4..8].try_into().expect("sufficient length");
        (u32::from_be_bytes(elasticity), u32::from_be_bytes(denominator))

pub(crate) fn decode_holocene_eip_1559_params_block_header(
    header: &Header,
) -> ExecutorResult<BaseFeeParams> {
    let (elasticity, denominator) = HoloceneExtraData::decode(header.extra_data())?;

    // Check for potential division by zero.
    // In the block header, the denominator is always non-zero.
    // <https://github.com/ethereum-optimism/specs/blob/main/specs/protocol/holocene/exec-engine.md#eip-1559-parameters-in-block-header>
    if denominator == 0 {
        return Err(ExecutorError::InvalidExtraData(Eip1559ValidationError::ZeroDenominator));
    }

    Ok(BaseFeeParams {
        elasticity_multiplier: elasticity.into(),
        max_change_denominator: denominator.into(),
    })
}

pub(crate) fn decode_jovian_eip_1559_params_block_header(
    header: &Header,
) -> ExecutorResult<(BaseFeeParams, u64)> {
    let (elasticity, denominator, min_base_fee) = JovianExtraData::decode(header.extra_data())?;

    // Check for potential division by zero.
    // In the block header, the denominator is always non-zero.
    // <https://github.com/ethereum-optimism/specs/blob/main/specs/protocol/holocene/exec-engine.md#eip-1559-parameters-in-block-header>
    if denominator == 0 {
        return Err(ExecutorError::InvalidExtraData(Eip1559ValidationError::ZeroDenominator));
    }

    Ok((
        BaseFeeParams {
            elasticity_multiplier: elasticity.into(),
            max_change_denominator: denominator.into(),
        },
        min_base_fee,
    ))
}

fn base_fee_params_from_extra_data(
    chain_spec: impl EthChainSpec,
    timestamp: u64,
    elasticity: u32,
    denominator: u32,
) -> Result<BaseFeeParams, EIP1559ParamError> {
    if elasticity == 0 && denominator == 0 {
        Ok(chain_spec.base_fee_params_at_timestamp(timestamp))
    } else if elasticity == 0 || denominator == 0 {
        Err(EIP1559ParamError::InvalidParams)
    } else {
        Ok(BaseFeeParams::new(denominator as u128, elasticity as u128))
    }
}

    fn next_block_base_fee(
        &self,
        params: BaseFeeParams,
        parent: &Header,
        min_base_fee: u64,
    ) -> Option<u64> {
        if !self.config.is_jovian_active(parent.timestamp()) {
            return parent.next_block_base_fee(params);
        }

        // Starting from Jovian, we use the maximum of the gas used and the blob gas used to
        // calculate the next base fee.
        let gas_used = if parent.blob_gas_used().unwrap_or_default() > parent.gas_used() {
            parent.blob_gas_used().unwrap_or_default()
        } else {
            parent.gas_used()
        };

        let mut next_block_base_fee = calc_next_block_base_fee(
            gas_used,
            parent.gas_limit(),
            parent.base_fee_per_gas().unwrap_or_default(),
            params,
        );

        // If the next block base fee is less than the min base fee, set it to the min base fee.
        // # Note
        // Before Jovian activation, the min-base-fee is 0 so this is a no-op.
        if next_block_base_fee < min_base_fee {
            next_block_base_fee = min_base_fee;
        }

        Some(next_block_base_fee)
    }

    /// Returns the active base fee parameters for the parent header.
    /// Returns the min-base-fee as the second element of the tuple.
    ///
    /// ## Note
    /// Before Jovian activation, the min-base-fee is 0.
    pub(crate) fn active_base_fee_params(
        config: &RollupConfig,
        parent_header: &Header,
        payload_timestamp: u64,
    ) -> ExecutorResult<(BaseFeeParams, u64)> {
        match config {
            // After Holocene activation, the base fee parameters are stored in the
            // `extraData` field of the parent header. If Holocene wasn't active in the
            // parent block, the default base fee parameters are used.
            _ if config.is_jovian_active(parent_header.timestamp) => {
                decode_jovian_eip_1559_params_block_header(parent_header)
            }
            _ if config.is_holocene_active(parent_header.timestamp) => {
                decode_holocene_eip_1559_params_block_header(parent_header)
                    .map(|base_fee_params| (base_fee_params, 0))
            }
            // If the next payload attribute timestamp is past canyon activation,
            // use the canyon base fee params from the rollup config.
            _ if config.is_canyon_active(payload_timestamp) => {
                // If the payload attribute timestamp is past canyon activation,
                // use the canyon base fee params from the rollup config.
                Ok((config.chain_op_config.post_canyon_params(), 0))
            }
            _ => {
                // If the next payload attribute timestamp is prior to canyon activation,
                // use the default base fee params from the rollup config.
                Ok((config.chain_op_config.pre_canyon_params(), 0))
            }
        }
    }
