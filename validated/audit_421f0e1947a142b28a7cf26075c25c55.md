### Title
Missing negative/zero check on Chainlink USD0++ answer lets a malfunctioning feed skip the junior→senior depeg compensation - (File: contracts/strategies/usual/IdleUsualStrategy.sol)

### Summary
`IdleUsualStrategy.getChainlinkPrice()` casts the Chainlink `int256 answer` directly to `uint256` without validating `answer > 0`. A negative answer is reinterpreted as an astronomically large price (~2.56e77 for `-1`), so `IdleCDOUsualVariant.stopEpoch()` treats USD0++ as trading above $1 and returns early, skipping the entire loss-socialization mechanism that tops up senior tranche holders to $1 parity.

### Finding Description
The Usual variant vault is a depeg-protection product: at `stopEpoch`, if the oracle price of USD0++ is below `oneToken` ($1), the CDO increases `lastNAVAA` to `lastNAVAA * oneToken / _oraclePrice` and calls `_updateAccounting()`, which books the difference as a loss absorbed 100% by the junior (BB) tranche, compensating seniors [1](#0-0) .

The price comes from `getChainlinkPrice()`, which only checks staleness (`updatedAt > block.timestamp - 24 hours`) and then does `return uint256(answer) * 1e10` with no `answer > 0` check [2](#0-1) . Chainlink's `latestRoundData` returns `int256` precisely because negative answers are representable. When `answer < 0`, the `int256`→`uint256` cast reinterprets the two's-complement bit pattern (e.g., `-1` → `2^256 - 1`), yielding a scaled "price" of ~2.56e77. The `if (_oraclePrice >= oneToken) return;` branch in `stopEpoch` then skips the compensation entirely [3](#0-2) , and `setOraclePrice` stores this garbage value since it trivially exceeds the floor price [4](#0-3) . The same unchecked value is stored in `oraclePrice` at `initialize` and `priceAtStartEpoch` at `startEpoch` [5](#0-4) [6](#0-5) .

Notably, this vault has no other safeguard: `_checkDefault` is a no-op and `maxDecreaseDefault` is `FULL_ALLOC`, so nothing else catches a bad price [7](#0-6) .

### Impact Explanation
If the feed returns a negative or zero answer at `stopEpoch` (a malfunctioning/misconfigured feed — the exact scenario this oracle exists to price), the junior→senior payout is skipped. If the real USD0++ price is below $1 at that moment, senior tranche holders permanently lose `(1 - realPrice) * lastNAVAA` worth of compensation they were owed, while junior holders (an attacker can simply be a BB tranche-token holder who waits for the feed anomaly) keep funds that should have been transferred. A `0` answer additionally causes a division-by-zero revert in `targetAATVL = lastNAVAA * oneToken / _oraclePrice`, DoS-ing `stopEpoch` and freezing all redemptions since `allowAAWithdraw`/`allowBBWithdraw` are only set inside that function — though the stale check and the negative-cast path are the more likely manifestation. Broken invariant: loss waterfall (juniors absorb depeg loss first).

### Likelihood Explanation
Low-to-moderate: it requires the USD0++ Chainlink feed to emit a negative answer during a narrow `stopEpoch` window (or `initialize`/`startEpoch`). Chainlink feeds can carry negative answers for non-crypto assets, and the feed here is updated infrequently (50 bps deviation threshold), so a stale-but-fresh-enough bad round can persist. The attacker only needs to hold BB tranche tokens — an allowed unprivileged role — and does not need to perform any action; the loss accrues automatically when the owner calls `stopEpoch` while the feed is bad. Severity consistent with the Medium-rated source finding.

### Recommendation
Add a sanity bound in `getChainlinkPrice()`:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
require(answer > 0, "Invalid price");
return uint256(answer) * 1e10;
```

Optionally also cap the upper bound (`answer <= someMaxPrice`) to reject absurd values, and use `latestRoundData`'s `answeredInRound >= roundId` completeness check.

### Proof of Concept
Foundry fork-style PoC outline (place in `test/foundry/`):

```solidity
function testNegativeOracleSkipsLoss() public {
    // setup: CDO deployed, users deposited 100e18 USD0++ into AA and BB, epoch started & ended
    // mock the USD0++ feed to return a negative answer
    vm.mockCall(
        0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB, // USD0ppOracle
        abi.encodeWithSelector(IOracle.latestRoundData.selector),
        abi.encode(uint80(1), int256(-1), block.timestamp, block.timestamp, uint80(1))
    );
    vm.warp(epochEndDate + 1);
    cdo.stopEpoch(); // does NOT revert
    // _oraclePrice = uint256(-1)*1e10 >= 1e18 -> early return
    assertEq(cdo.lastNAVAA(), navAABefore);        // seniors never topped up to $1 parity
    // BB holder redeems full NAV; AA holder redeemable only at real (depegged) value
}
```

For the `answer == 0` variant, mock `int256(0)` and assert `cdo.stopEpoch()` reverts with a division-by-zero panic, leaving withdrawals permanently gated.
