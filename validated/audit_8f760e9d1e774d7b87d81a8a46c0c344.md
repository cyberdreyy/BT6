## Finding

### Title
Stale-conflict window in `handle_block_pre_commit` lets a signer sign a block that conflicts with an already-signed/globally-accepted block in a *different* tenure at the same height - ([File: stacks-signer/src/v0/signer.rs])

### Summary
The pre-commit-to-signature guard in `Signer::handle_block_pre_commit` treats a previously-signed conflicting block as "stale" purely based on a wall-clock timeout (`tenure_last_block_proposal_timeout`, default 30s), and for cross-tenure conflicts it performs **no node re-verification at all** once that timeout elapses — unlike the same-tenure case, which re-queries the node's tenure tip before allowing a replacement.

### Finding Description
`handle_block_pre_commit` looks up every block ever signed at or above the candidate's height across all tenures via `get_signed_conflicts` [1](#0-0) , then only blocks the new signature if a conflict is "fresh":

```
conflict.last_endorsed > freshness_cutoff
    && !self.reorg_permit_stands(...)
    && self.conflict_still_blocks(...)
``` [2](#0-1) 

`freshness_cutoff` is simply `now - tenure_last_block_proposal_timeout` [3](#0-2) , and `conflict_still_blocks` (the only place that asks the node whether the conflicting block is actually dead) is **only invoked for conflicts that already pass the freshness test** — stale conflicts never reach it, per the code's own comment: "stale conflicts cost no round-trips" [4](#0-3) .

For conflicts that are stale, the code falls back to a second, narrower check that only re-verifies the tenure that the **new** block itself belongs to:

```
if conflicts.iter().any(|conflict| {
    conflict.consensus_hash == block_info.block.header.consensus_hash
        && !self.reorg_permit_stands(stacks_client, conflict)
}) {
    match stacks_client.get_tenure_tip(&block_info.block.header.consensus_hash) { ... }
}
``` [5](#0-4) 

This only re-checks conflicts whose `consensus_hash` equals the *new* block's own tenure. A stale conflict recorded against a **third, unrelated tenure** (e.g. an already globally-accepted block A from tenure T1) is neither re-verified by `conflict_still_blocks` (skipped because stale) nor caught by this own-tenure branch (its `consensus_hash` differs), so the loop falls through to:

```
if !conflicts.is_empty() {
    info!("... none of those conflicts still blocks it. Signing the replacement.");
}
... 
self.handle_block_signature(...)  // signs and broadcasts
``` [6](#0-5) 

The design's own documentation acknowledges the earlier `check_block_against_signer_db_state` chainstate re-check (which this fallback relies on) only inspects **one** tenure — a tenure-change block's parent, or the block's own tenure — and explicitly states "a signed sibling at the same height in a third tenure is invisible to it" [7](#0-6) . The stale-conflict fallback assumes that blind spot is covered elsewhere, but it is not: a third-tenure conflict that has gone stale purely by clock is neither asked about (`conflict_still_blocks`) nor checked by the earlier chainstate re-check.

### Impact Explanation
This lets a signer place a second, valid signature on a block B in tenure T2 that conflicts (same height) with a block A in tenure T1 that this same signer already signed and which may still be globally accepted/canonical — purely because `tenure_last_block_proposal_timeout` (30s by default) elapsed since A's signature, with zero verification that A is actually dead. If enough signers independently hit this same staleness window (which is a simple, deterministic wall-clock condition any miner can wait out), a majority-weight signature set can accumulate over a conflicting/non-canonical block, i.e. a signer signing a conflicting block — the Critical impact category defined in scope.

### Likelihood Explanation
The trigger requires no majority of signers, no key compromise, and no auth token: a single miner that wins two competing tenures at the same height (or re-proposes an old, unconfirmed tenure) needs only to delay ~30+ seconds (the default `tenure_last_block_proposal_timeout`) between the first block's signature and presenting the conflicting proposal in the second tenure to individual signers. This is well within a lone miner's control of message/proposal timing, and the guard is a purely local, per-signer wall-clock computation with no majority collusion needed to trip it.

### Recommendation
For stale conflicts whose `consensus_hash` differs from both the new block's own tenure and (for tenure-change blocks) its parent tenure, still invoke `conflict_still_blocks` (or an equivalent node-derived liveness check) before allowing the signature, rather than relying solely on the elapsed-time heuristic and the narrower own-tenure re-check. Alternatively, widen `get_signed_conflicts`'s freshness-independent fallback check to cover every conflicting tenure, not just the tenure of the currently-evaluated block.

### Proof of Concept
1. Miner wins tenure T1, proposes tenure-start block A at height H; signer set (including victim signer S) signs A; A becomes globally accepted.
2. Miner (or another with a winning sortition) starts tenure T2 whose tenure-change/parent selection passes the single-tenure `check_block_against_signer_db_state` check (e.g., a different parent lineage not covered by that single-tenure check), and proposes block B also at height H.
3. Signer S validates and pre-commits B while A's `last_endorsed` timestamp is still fresh — B stays `PreCommitted`, blocked by the fresh-conflict guard at [8](#0-7) .
4. Miner waits > `tenure_last_block_proposal_timeout` (default 30s) and re-proposes/re-triggers pre-commit re-evaluation for B (`should_reevaluate_block` re-runs `handle_block_pre_commit` for `PreCommitted` blocks, see [9](#0-8) ).
5. Now `conflict.last_endorsed <= freshness_cutoff` for A, so A is skipped by the fresh-conflict loop; A's `consensus_hash` (T1) ≠ B's `consensus_hash` (T2), so it's also skipped by the own-tenure re-check at [5](#0-4) ; `conflicts.is_empty()` is false but the code logs "Signing the replacement" and signs B [6](#0-5) .
6. Signer S has now produced valid signatures over two conflicting blocks (A and B) at height H in different tenures, without ever confirming A was actually orphaned.
