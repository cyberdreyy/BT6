### Title
A dust APR=0 withdraw request permanently bricks `stopEpoch` once APR is raised, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.requestWithdraw` records any withdraw made while `unscaledApr == 0` into the global `apr0TotalPrincipal` bucket with no minimum amount. `prepareStopEpochWithApr0` then hard-reverts with `NotAllowed()` if `apr0TotalPrincipal != 0 && unscaledApr != 0`, and it reverts *before* clearing the bucket. A KYC-passing lender can therefore plant a dust-sized APR0 receipt; the next time the honest manager sets a non-zero APR, every subsequent `stopEpoch` reverts, so no epoch can close and no withdraw receipt can mature — trapping all lender principal in the vault.

### Finding Description
In `IdleCDOEpochVariant.requestWithdraw`, when the pool APR is 0 the call routes into `IdleCreditVault.requestWithdraw`, which calls `_requestWithdrawApr0` and unconditionally adds the (fee-netted) amount to `apr0TotalPrincipal` — there is no dust threshold [1](#0-0) , [2](#0-1) .

At epoch end, `stopEpoch` calls `prepareStopEpochWithApr0`, which reverts if `apr0TotalPrincipal != 0` while `unscaledApr != 0`, and the revert happens *before* `apr0TotalPrincipal = 0` at the end of the function, so the bucket is never cleared [3](#0-2) .

The only other code paths that reduce `apr0TotalPrincipal` are `_clearWithdrawClaimForEpoch` (only reachable via default-recovery finalization) and `_settleApr0`, which requires `epochNumber` to advance — i.e. it requires a successful `stopEpoch` [4](#0-3) , [5](#0-4) . The protocol's own test confirms the revert: `testApr0InvariantRevertsIfAprChangesAfterApr0Request` [6](#0-5) .

Because `epochEndDate != 0` and `epochNumber <= lastWithdrawRequest[_user]`, claimers cannot take the funded path either; the stuck APR0 requester's receipt can never settle while `stopEpoch` reverts [7](#0-6) .

Attack sequence (buffer phase, APR0 mode):
1. Pool runs an epoch with `unscaledApr == 0` (already supported mode; `setAprs(0,0)` is a legitimate manager action).
2. Attacker (whitelisted lender) deposits a minimal amount and calls `requestWithdraw(1 wei tranche, AATranche)` → `apr0TotalPrincipal` becomes nonzero.
3. Manager later sets a positive APR via `setAprs` (an honest, routine action — APRs change between epochs).
4. Every `stopEpoch` now reverts in `prepareStopEpochWithApr0`. Epoch can never close; borrower funds can never be recalled; all withdraw claims revert; the vault is frozen for all users.
5. The only recovery paths are the manager setting APR back to 0 forever (protocol can never earn/quote positive APR again — effectively permanent economic freeze) or forcing a borrower default / emergency shutdown, both of which socialize losses or require privileged intervention the attacker can wait out.

### Impact Explanation
Permanent freezing of all user funds (or permanent loss of the protocol's ability to run a positive-APR epoch) for the cost of a dust deposit plus gas. The attacker pays ~1 wei of underlying; the vault's entire TVL is bricked. This maps the CVE's "crafted input crashes the program" class onto the vault: an unprivileged, arbitrarily small user input poisons global epoch state so the state machine halts — with direct fund impact (frozen TVL), satisfying the acceptance bar rather than being a gas-only DoS.

### Likelihood Explanation
High triggerability: it only needs one epoch where `unscaledApr == 0` (a supported configuration exercised extensively in tests) and a whitelisted wallet, which any approved lender possesses. The detonating action (manager raising APR) is the normal course of business, not attacker-controlled privilege. No existing guard stops it: `_skimDonatedAssets`, `isWalletAllowed`, epoch gating, and the loss-recovery checks all pass; the revert is reached through honest privileged calls only.

### Recommendation
Decouple the APR0 lifecycle from the *current* APR: record the APR at request time per epoch bucket and let `prepareStopEpochWithApr0` settle outstanding APR0 principal at whatever interest the epoch realized (or at zero) instead of reverting. Alternatives: sweep the dust — enforce a minimum APR0 request size; or let `prepareStopEpochWithApr0` roll `apr0TotalPrincipal` forward (settle at 0 rate and clear the bucket) when `unscaledApr != 0` rather than reverting, since the receipt basis is already fixed in `pendingWithdraws`.

// Foundry fork test, contracts deployed per test/foundry/IdleCreditVault.t.sol harness
function testDustApr0RequestBricksStopEpoch() external {
    // config: APR currently 0 (legit manager action)
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);                    // honest TVL exists
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, 0, _expectedFundsEndEpoch());

    // Attacker: whitelisted lender, dust deposit + dust withdraw request
    address attacker = makeAddr('attacker');
    deal(defaultUnderlying, attacker, 1e6);
    _depositWithUser(attacker, 1e6, true);        // KYC'd lender
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(1, address(AAtranche)); // 1 wei tranche -> apr0TotalPrincipal = dust
    assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

    _startEpochAndCheckPrices(1);

    // Honest manager raises APR for the next epoch (routine business action)
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(1e18, 1e18);

    // Every stopEpoch now reverts -> epoch can never close -> TVL frozen
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 0);

    // Retry with funded borrower / override interest still reverts identically
    deal(defaultUnderlying, borrower, 1e24);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 1000 * ONE_SCALE);

    // Attacker cannot clear it either: claim requires epochNumber to advance
    vm.prank(attacker);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.claimWithdrawRequest();
}

        if (_apr0InterestGross != 0) {

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
