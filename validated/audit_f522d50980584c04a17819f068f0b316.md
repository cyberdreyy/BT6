### Title
Winning miner defeats `block_proposal_timeout` inactivity check by refreshing `last_activity_time` with cheap, guaranteed-to-be-rejected re-proposals - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
The signer's miner-inactivity detector (`SortitionState::is_timed_out`) measures elapsed time since a per-tenure `last_activity_time` in SignerDB, which is refreshed automatically whenever the current sortition's miner sends *any* stale/duplicate block proposal — no signature, no node validation, and no real chain progress required. A malicious or stalled winning miner can therefore broadcast cheap re-proposals at will to keep resetting this clock, exactly like the ECG `distribute(1)` wei-call analog prolonging a distribution window, permanently suppressing the `block_proposal_timeout` fallback that is supposed to let signers revert to the previous, legitimate miner.

### Finding Description
`check_latest_block_in_tenure` [1](#0-0)  is the routine that both `confirms_latest_block_in_same_tenure` and `check_tenure_change_confirms_parent` delegate to on every incoming block proposal [2](#0-1) . When the proposed block's `chain_length` is not higher than the tenure's already-known signed tip, the proposal is rejected as "does not confirm as many blocks as we expect" — but before returning `Ok(false)`, it unconditionally calls `signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())` as long as the existing tip's `signed_group` timestamp is still within `reorg_attempts_activity_timeout` [3](#0-2) . A second branch does the same for conflicts against a merely pre-committed (unsigned) block [4](#0-3) .

This activity timestamp is exactly what gates the inactivity timeout: `SortitionState::is_timed_out` falls back to `last_activity_time` (or burn-block-receipt time if none is set) and only reports timeout once `elapsed > block_proposal_timeout` [5](#0-4) . `check_proposal` uses this exact check to decide whether to flip the current sortition's miner to `InvalidatedBeforeFirstBlock`, which is the gate that lets the *previous* miner's tenure-extend be accepted [6](#0-5) ; the v0 signer-state path calls the analogous check before ever considering reverting to the prior miner's tenure [7](#0-6) .

The proposal that refreshes this timer costs the miner essentially nothing: it is evaluated purely against local `SignerDB` state (no node round-trip, no fee, no need to ever win validation) — the same category of "few wei" cheap-call griefing the external report describes for `distribute(1)`. The miner simply needs to keep re-sending an already-superseded/duplicate proposal (or any proposal at or below the known tip height) at intervals shorter than `block_proposal_timeout`.

### Impact Explanation
This is a liveness wedge matching the High-severity bar: a stalled or malicious current-tenure miner (a one-slot miner) can indefinitely defeat the `block_proposal_timeout`/`InvalidatedBeforeFirstBlock` mechanism that exists specifically to let signers fall back to the previous miner. Since `docs/signing.md` and the sample config document that `block_proposal_timeout_ms` is "one of two gates that must be satisfied before the signer will accept a tenure extend from the PREVIOUS miner" [8](#0-7) , defeating it means the honest previous miner can never be allowed to extend, and the network is stuck waiting on a miner who is not actually producing valid chain progress. This is the direct analog of "prolonging the time for rewards to get distributed" — here it prolongs (indefinitely, while the attacker keeps sending trivial proposals) the window during which no productive tenure can proceed.

### Likelihood Explanation
Likelihood is straightforwardly high once a malicious/no-longer-productive miner controls the current sortition slot: producing a stale/duplicate block proposal requires only a valid miner signature over the block header (which the winning miner already controls) and does not need to pass node-side validation or reach consensus. It can be repeated on a timer well under `block_proposal_timeout` (default 120s) at negligible cost, mirroring the "call `distribute(1)` once a day" griefing pattern from the external report but here refreshing a security-relevant liveness timer rather than a reward schedule.

### Recommendation
Do not treat every stale/duplicate/conflicting proposal as "miner activity" for the purposes of resetting `last_activity_time`. At minimum, only count it as activity the first time it is seen per tenure/height (or rate-limit/dedupe by signature hash), and separately require some proof of forward progress (e.g., a strictly higher chain length than any previously-seen proposal from this miner) before refreshing the timer. This mirrors the ECG mitigation of adding a minimum threshold/anti-griefing check before allowing an operation to reset a time-based interpolation window.

### Proof of Concept
1. Miner M wins the current sortition and produces one valid block that reaches `GloballyAccepted`/`LocallyAccepted` state, establishing a signed tenure tip at height H.
2. M then repeatedly re-broadcasts (or slightly mutates and re-signs) a block proposal at height ≤ H for the same tenure, once every `reorg_attempts_activity_timeout` window, without ever producing a new higher block.
3. Each proposal hits `check_latest_block_in_tenure`'s early branch (`block.header.chain_length <= info.block.header.chain_length`) and calls `update_last_activity_time`, resetting the clock used by `SortitionState::is_timed_out` / `check_miner_inactivity` [9](#0-8) [10](#0-9) .
4. As long as M keeps this cadence tighter than `block_proposal_timeout`, `elapsed > block_proposal_timeout` never becomes true, so `check_proposal`/`check_miner_inactivity` never flips M's status to `InvalidatedBeforeFirstBlock`, and the previous miner's tenure-extend gate never opens — indefinitely stalling productive tenure progress despite M producing no further valid blocks.

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    pub fn check_miner_inactivity(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<(), SignerChainstateError> {
        let Self::Initialized(ref mut state_machine) = self else {
            // no inactivity if the state machine isn't initialized
            return Ok(());
        };

        let MinerState::ActiveMiner { ref tenure_id, .. } = state_machine.current_miner else {
            // no inactivity if there's no active miner
            return Ok(());
        };

        let version = SortitionStateVersion::from_protocol_version(
            state_machine.active_signer_protocol_version,
        );
        let is_timed_out = SortitionState::is_timed_out(
            &version,
            tenure_id,
            db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )?;

        if !is_timed_out {
            return Ok(());
        }

        // the tenure timed out, try to see if we can use the prior tenure instead
        let CurrentAndLastSortition { last_sortition, .. } =
            client.get_current_and_last_sortition()?;
        let Some(last_sortition) = last_sortition
            .and_then(|val| SortitionData::try_from(val).ok())
            .map(|data| SortitionState::new(version, data))
        else {
            warn!("Signer State: Current miner timed out due to inactivity, but could not find a valid prior miner. Allowing current miner to continue");
            return Ok(());
        };

        let sortition_data = last_sortition.data();
        // If we already reverted to the last sortition miner, don't time it out as it means we have already timed out the current sorititon miner
        // as there is no other miner available.
        if &sortition_data.consensus_hash == tenure_id {
            warn!("Signer State: Last sortition miner has timed out, but no prior valid miner. Allowing last sortition miner to continue");
