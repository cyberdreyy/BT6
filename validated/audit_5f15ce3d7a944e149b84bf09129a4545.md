### Title
Unauthenticated `/health` and `/readyz` endpoints leak internal component/service identifiers beyond intended minimal-disclosure design - ([File: core/web/router.go], [File: core/web/health_controller.go])

### Summary
`HealthController.Health` and `HealthController.Readyz` return per-check names (e.g. chain/relayer/service identifiers) and, on failure, error output text to any caller, while `HealthController.PublicReadyz` was explicitly written as a "minimal" endpoint that "never returns per-check details ... to avoid leaking internal service state on publicly reachable endpoints." [1](#0-0)  If `/health` and `/readyz` are reachable on the unauthenticated `api` route group (as stated in the question) rather than gated the same way `PublicReadyz` is intended to be, an unauthenticated client can enumerate internal component names and status/error strings that the code's own documentation says should not be exposed on public endpoints.

### Finding Description
`HealthController.Health` builds a list of `presenters.Check{JAID, Name, Status, Output}` from `checker.IsHealthy()` and serializes it as JSON/HTML/plaintext with no redaction of check names, which correspond to internal component identifiers (e.g. per-chain/per-relayer health-checkable services registered with the health checker). [2](#0-1)  `HealthController.Readyz` behaves similarly when called with `?full`, additionally exposing `Output` (raw error text) for failing checks. [3](#0-2)  By contrast, `PublicReadyz` is explicitly documented as the safe-for-public variant, returning only an HTTP status code and nothing else. [1](#0-0)  The doc comment on `PublicReadyz` itself states the design intent that non-minimal health data should not be exposed on publicly reachable endpoints, implying `Health`/`Readyz` were expected to require authentication or restricted access. If these routes are registered on the router group without the authentication middleware wrapper (as asserted by the question against `core/web/router.go`), that intent is violated and any unauthenticated caller can retrieve the full component/check list and error output.

### Impact Explanation
This maps to an information-disclosure / minimum-disclosure violation: an unauthenticated attacker can enumerate internal service and chain/relayer identifiers and, when a component is unhealthy, potentially see error text that may reference internal endpoints or configuration hints. This is topology/internal-service enumeration rather than secret-key or credential leakage, so it does not by itself grant privilege escalation, fund movement, or authentication bypass — it is a reconnaissance-class disclosure that aids further attacks (e.g., targeting supported chains/relayers).

### Likelihood Explanation
Precondition is none beyond network reachability of the node's API port; the request is a plain unauthenticated `GET /health` (or `GET /readyz?full`). This is trivially repeatable and requires no credentials, consistent with the described attacker model (unauthenticated client).

### Recommendation
Gate `/health` and full `/readyz` behind the same authentication/session middleware used for other operator-only diagnostic routes, or reduce their unauthenticated payload to match `PublicReadyz` (status-only), exposing full per-check detail only to authenticated/administrative callers.

### Proof of Concept
1. Unit/handler test: register routes as done in `core/web/router.go`, issue `httptest` `GET /health` without any `Authorization`/cookie, assert HTTP response body contains `presenters.Check` entries with non-empty `Name` fields corresponding to internal components.
2. Repeat with `GET /public-readyz` and assert the response body is empty and only a status code is set (per `PublicReadyz` implementation).
3. Diff the two payload sizes/fields to confirm `/health` discloses structured internal identifiers while `/public-readyz` discloses nothing beyond up/down.
4. Assert failure: if router.go wraps `/health` in the authenticated middleware, the first request should return `401`, invalidating the finding — this must be checked against the actual `core/web/router.go` route registration to confirm placement.

Note: I was unable to fully verify the exact route-group registration lines (with/without auth middleware) for `/health` and `/readyz` in `core/web/router.go` due to tool limitations in this session; the finding is based on the explicit documented design intent in `health_controller.go` and the question's stated premise. Confirming the exact middleware wrapping in `core/web/router.go` is required to fully validate this before treating it as conclusively proven.

	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEHTML, gin.MIMEPlain) {
	case gin.MIMEJSON:
		break // default

	case gin.MIMEHTML:
		if err := newCheckTree(checks).WriteHTMLTo(c.Writer); err != nil {
			hc.App.GetLogger().Errorw("Failed to write HTML health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return

	case gin.MIMEPlain:
		if err := writeTextTo(c.Writer, checks); err != nil {
			hc.App.GetLogger().Errorw("Failed to write plaintext health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return
	}

	slices.SortFunc(checks, presenters.CmpCheckName)
	jsonAPIResponseWithStatus(c, checks, "checks", status)
}
