### Title
Missing sender authorization check in `HandleLegacyUserMessage` allows any valid-signature sender to broadcast requests to all DON members - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` validates message structure, decoding, timestamp freshness, and method name, but never checks whether `msg.Body.Sender` (the ECDSA-recovered address) is an authorized subscriber of `h.donConfig` before broadcasting the request via `don.SendToNode` to every DON member. Any attacker who generates a fresh keypair, signs a well-formed `MethodWebAPITrigger` message via `api.Message.Sign`, and POSTs it to the gateway can have their arbitrary trigger payload relayed to all DON nodes.

### Finding Description
The request flow is: `gateway.ProcessRequest` (core/services/gateway/gateway.go:218) decodes the JSON-RPC request, calls `msg.Validate()` (line 253) which only checks structural validity and recovers the signer via `ExtractSigner`/`crypto.SigToPub` (core/services/gateway/api/message.go:54-88, 124-134) — it does not check the signer against any allowlist, it merely confirms the signature is well-formed and sets `msg.Body.Sender` to whatever address the recovered public key maps to. The gateway then looks up the handler by `msg.Body.DonId` and calls `h.HandleLegacyUserMessage(ctx, msg, callback)` (gateway.go:269).

Inside `HandleLegacyUserMessage` (core/services/gateway/handlers/capabilities/handler.go:341-421), the checks performed are: payload unmarshal success, `payload.Timestamp != 0`, message staleness against `MaxAllowedMessageAgeSec`, and `msg.Body.Method == MethodWebAPITrigger`. Immediately preceding the method check is an explicit unaddressed `// TODO: apply allowlist and rate-limiting here` comment (line 384). No code path in the function reads `msg.Body.Sender` or cross-references it against `h.donConfig` members, subscribers, or any allowlist structure. The function then unconditionally loops `for _, member := range h.donConfig.Members` and calls `don.SendToNode(ctx, member.Address, req)` for every DON member (lines 417-419), relaying the attacker-controlled, arbitrary-signer request to the entire DON.

This is corroborated by the handler's own test suite, which contains a matching acknowledgment: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` (core/services/gateway/handlers/capabilities/handler_test.go:365), and by `TestHandlerReceiveHTTPMessageFromClient` (handler_test.go:236-260) which demonstrates a signed message from `nodes[0].PrivateKey` — not an actual "subscriber" identity check — succeeding and broadcasting via `don.SendToNode` with no allowlist gate.

### Impact Explanation
This matches an "unauthorized capability execution" / allowlist-bypass class of impact: any unauthenticated party can force every node in a DON to process an arbitrary `web_api_trigger` payload attributed to an attacker-chosen key, consuming DON compute, triggering downstream external HTTP calls (via `handleWebAPIOutgoingMessage`/`sendHTTPMessageToClient`), and potentially exhausting per-DON or per-node capacity/allowlist quotas intended to restrict trigger submission to legitimate subscribers.

### Likelihood Explanation
Preconditions are minimal: only network access to the gateway's HTTP endpoint and the ability to generate an ECDSA keypair (`crypto.GenerateKey`) to sign a structurally valid `api.Message` via `msg.Sign`. No relationship to the DON, no existing subscription, and no credentials are required. The attack is fully repeatable and scriptable.

### Recommendation
Before the `for _, member := range h.donConfig.Members` broadcast loop, add an authorization check that verifies `msg.Body.Sender` against an allowlist of authorized subscribers/senders for the target DON/job (as the TODO comment indicates was intended), rejecting or rate-limiting unauthorized senders with an appropriate `api.ErrorCode` response instead of unconditionally relaying to `don.SendToNode`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
