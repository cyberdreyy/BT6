### Title
Unbounded recursion in `TrieNode::decode` allows stack-overflow denial of service when opening L1/L2 trie preimages - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode::decode` (the RLP decoder for Merkle-Patricia Trie nodes used throughout the fault-proof program) recurses into itself with no depth limit when decoding `Extension`/`Branch` node payloads. This mirrors the CVE-2016-6513 bug class: a dissector/decoder that recurses on nested untrusted input without bounding recursion depth, causing a crash (stack overflow) rather than a graceful parse error.

### Finding Description
`TrieNode::decode` in `crates/proof/mpt/src/node.rs` peeks at the RLP header and, for list items matching `LEAF_OR_EXTENSION_LIST_LENGTH`, calls `try_decode_leaf_or_extension_payload`, which for extension nodes recursively invokes `Self::decode(buf)` again [1](#0-0) . For branch nodes it decodes a `Vec::<Self>::decode(buf)`, which similarly recurses into `Self::decode` for each of up to 16 children [2](#0-1) . There is no `depth` parameter or maximum-nesting check anywhere in this decode path, unlike the CBOR parser elsewhere in the codebase that explicitly enforces `MAX_CBOR_NESTING_DEPTH` [3](#0-2) .

This decoder is reached from the fault-proof program's L1 chain provider: `OracleL1ChainProvider::trie_node_by_hash` fetches a preimage from the (attacker-influenceable) preimage oracle and immediately calls `TrieNode::decode` on the raw bytes [4](#0-3) . Crucially, the decode happens *before* any keccak256 hash-consistency check against the requested key is performed in this function — the returned `TrieNode` is trusted at decode time, and only the RLP structure (not a length/depth invariant) drives the recursion. The same pattern recurs in `OrderedListWalker::fetch_leaves`, which walks `Branch`/`Extension` nodes recursively while pulling in blinded child preimages via `Self::get_trie_node`/`fetcher.trie_node_by_hash` with no depth bound of its own [5](#0-4) , and it is invoked for L1 receipts/transactions tries during derivation [6](#0-5) .

Because the preimage oracle in a dispute game is populated by the (possibly malicious) party providing preimages during the interactive/offline fault-proof execution, a party can supply a chain of deeply nested, syntactically-valid RLP "extension" or "branch" nodes (or a long chain of blinded-node preimages each resolving to another nested node) that decodes recursively far beyond any real Ethereum trie depth (which is naturally capped near 64 levels by fixed-length keys, but nothing in `TrieNode::decode` itself enforces that cap on raw bytes).

### Impact Explanation
An attacker-crafted (or malicious dispute-game participant-supplied) sequence of preimages can drive `TrieNode::decode`/`fetch_leaves`/`open` into deep, unbounded recursion, exhausting the call stack and crashing the fault-proof program process. In the context of a dispute game this can prevent honest execution of the trace to completion or cause the fault-proof VM/host process executing this crate to halt/panic — a denial-of-service against a trust-critical path (deriving receipts, transactions, account/storage state used to compute the provable output root). This matches the "node halt" / "wrong provable output root" category, since a crash during proof execution can prevent production of a correct output root or halt the program handling the dispute step.

### Likelihood Explanation
Reaching this code requires supplying oracle preimages during fault-proof execution (a dispute-game participant/host-controlled path) or L1 header/receipts/transactions data during derivation. It is not reachable from a simple `eth_*` RPC call by an anonymous client, but it is reachable by a dispute-game participant supplying preimages/hints, which is within the listed reachable-actor scope ("dispute-game participant"). The RLP structural check (`rlp_list_element_length`, list-length matching) does not perform any bound on nesting depth, so constructing the malicious payload is straightforward with a normal RLP encoder — no cryptographic break is required to build the nesting chain itself, though supplying it via `trie_node_by_hash` still requires it to be accepted as *a* preimage entry in the oracle for some hash the fetcher requests (an adversarial actor with control over preimage submission during the fault-proof program's execution can do this).

### Recommendation
Add an explicit depth counter/limit to `TrieNode::decode` (and to `TrieNode::open`, `TrieNode::insert`, `TrieNode::delete`, and `OrderedListWalker::fetch_leaves`), mirroring the `MAX_CBOR_NESTING_DEPTH` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`, and reject RLP-encoded trie data whose real (or apparent) MPT nesting exceeds the maximum theoretical depth for 32-byte hashed keys (well under 100). Alternatively/additionally, convert the recursive decode into an iterative/stack-based traversal so recursion depth is not proportional to attacker-controlled input structure.

### Proof of Concept
Conceptually: construct RLP bytes representing an `Extension` node whose "key" preimage points (via `Self::decode(buf)` recursion) to another `Extension` node, repeated N times (e.g., N = 100,000), each valid 2-element RLP list satisfying `LEAF_OR_EXTENSION_LIST_LENGTH`. Feed this as the preimage returned for a queried hash in `OracleL1ChainProvider::trie_node_by_hash` (or as a `Branch` fan-out chain for `OrderedListWalker::fetch_leaves`). Calling `TrieNode::decode(&mut bytes.as_ref())` on this buffer recurses N times with no bound, causing a stack overflow and process crash — analogous to the WBXML dissector's unbounded recursion in CVE-2016-6513.

    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }
