The `nodes.GET("", ...)`, `nodes.GET("/:network", ...)`, and `chains.GET("/:network/:ID/nodes", ...)` routes are registered without any role wrapper [1](#0-0) , so a `view`-role user (or any authenticated user with `UserRoleView`) can call them, since `RequiresEditRole`/`RequiresAdminRole` are the only gates that reject `UserRoleView` and neither is applied here [2](#0-1) .

`NodesController.Index` returns `presenters.NodeResource`, whose `Config` field is the raw TOML config string for the node, unredacted [3](#0-2) . For EVM (and other chain) nodes, this TOML directly embeds `WSURL`/`HTTPURL` (e.g. `wss://.../ws`, `https://...`) as shown in the node config marshalling and test fixtures [4](#0-3) [5](#0-4) . If an operator configures RPC URLs with embedded basic-auth credentials or API keys in the userinfo/query string (a supported and common RPC provider pattern), those secrets would be included verbatim in this `Config` string and returned to any authenticated view-role user via `GET /v2/nodes`, `GET /v2/nodes/:network`, or `GET /v2/chains/:network/:ID/nodes`.

However, I could not verify from the indexed code whether URL credentials are ever actually embedded in `HTTPURL`/`WSURL` in this codebase versus supplied out-of-band (e.g., via headers), nor whether there's a redaction step elsewhere (e.g., in `config.MustParseURL` or TOML marshalling) that strips userinfo before storing `Config`. The `NewNodeResource`/`NodeStatus.Config` pipeline shows no redaction logic in the reachable code I found.

### Title
View-role users can retrieve unredacted node RPC config (including any embedded credentials) via GET /v2/nodes - ([File: core/web/router.go])

### Summary
The `nodes` route group and the nested `chains/:network/:ID/nodes` route are registered under `authv2` without `auth.RequiresEditRole` or `auth.RequiresAdminRole`, so any authenticated user — including `UserRoleView` — can call `NodesController.Index` and receive the full raw TOML `Config` for every configured node, including its `HTTPURL`/`WSURL`.

### Finding Description
`v2Routes` mounts `nodes := authv2.Group("nodes")` and registers `nodes.GET("", paginatedRequest(nodesController.Index))`, `nodes.GET("/:network", ...)`, and `chains.GET("/:network/:ID/nodes", ...)` with no role wrapper [1](#0-0) . Compare this to sibling routes in the same file that explicitly gate mutating/sensitive operations with `auth.RequiresEditRole`/`auth.RequiresAdminRole` (e.g. VRF key export/import, forwarders track/delete) [6](#0-5) . `RequiresEditRole` is the only middleware that rejects `UserRoleView`; without it, `authv2`'s base `auth.Authenticate` middleware admits any valid session regardless of role [7](#0-6) . `NodesController.Index` builds `presenters.NodeResource` per node, copying `node.Config` (raw TOML) unmodified into the JSON response [8](#0-7) [9](#0-8) . This TOML config includes `WSURL`/`HTTPURL` fields verbatim [5](#0-4) .

### Impact Explanation
If any node's RPC URL embeds authentication material (basic-auth userinfo, API keys in path/query — a common pattern for hosted RPC providers), that secret is disclosed to any `view`-role user, breaking the "secrets never leave" boundary between admin-configured infrastructure secrets and lower-privilege users. This matches the credential/secret-disclosure impact class.

### Likelihood Explanation
Requires only a valid `view`-role session or view-scoped API token — the lowest privilege level in the system — and a single unauthenticated-parameter GET request. Highly repeatable and requires no special conditions beyond the operator having configured an RPC URL containing credentials, which is plausible but not guaranteed by the codebase alone (I could not confirm the operator config always/never embeds secrets in URLs).

### Recommendation
Wrap the `nodes.GET` and `chains.../:ID/nodes` routes with `auth.RequiresEditRole` (or a stricter role) as done for other sensitive config-exposing routes, or have `presenters.NewNodeResource`/`NodeStatus.Config` redact userinfo/credentials from URLs before serialization regardless of role.

### Proof of Concept
Go handler-integration test plan:
1. Set up a `TestApplication` with an EVM node configured with `HTTPURL = "https://user:secret@rpc.example.com"`.
2. Create a session/API token with `UserRoleView`.
3. Call `GET /v2/nodes` (and `/v2/chains/:network/:ID/nodes`) using that view-role credential.
4. Assert HTTP 200 (not 401/403) is returned — confirming no role gate exists.
5. Assert the response body's `data[].attributes.config` contains the substring `user:secret@rpc.example.com`, demonstrating the raw credential-bearing URL leaks to a view-role caller.
6. Contrast with an edit-role-gated route (e.g. `POST /v2/keys/vrf`) to show the asymmetry in role enforcement within the same router file.

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}

func (n *nodesController[R]) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")
	network := c.Param("network")

	var nodes []types.NodeStatus
	var count int
	var err error

	relayers := n.relayers
	if network != "" {
		relayers = relayers.List(chainlink.FilterRelayersByType(network))
	}

	ctx := c.Request.Context()
	if id == "" {
		// fetch all nodes
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size)
	} else {
		// fetch nodes for chain ID
		// backward compatibility
		var rid types.RelayID
		err = rid.UnmarshalString(id)
		if err != nil {
			rid.ChainID = id
			rid.Network = network
		}
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size, rid)
	}

	resources := make([]R, 0, len(nodes))
	for _, node := range nodes {
		res := n.newResource(node)
		resources = append(resources, res)
	}

	paginatedResponse(c, "node", size, page, resources, count, err)
