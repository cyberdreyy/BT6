### Title
No-Clock Staleness Guard in `get_latest_data` Allows Arbitrarily Old Price Data to Be Used — (`File: crates/sui-oracle/move/oracle/sources/simple_oracle.move`, `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

The Sui oracle framework's `get_latest_data` function in `simple_oracle.move` returns stored price data with no validation of the data's age against the current on-chain clock. The `meta_oracle.combine` function applies only a *relative* inter-oracle staleness window — not an absolute wall-clock check — meaning that if all oracle operators stop submitting updates simultaneously, arbitrarily old prices pass through as "trusted" data. Any protocol that consumes this framework without adding its own staleness guard will silently act on stale prices.

---

### Finding Description

**`simple_oracle::get_latest_data` — no clock parameter, no age check**

`get_latest_data` is a public function that any on-chain caller can invoke. It reads the stored `StoredData<T>` entry and returns it unconditionally:

```move
public fun get_latest_data<T: store + copy>(oracle: &SimpleOracle, ticker: String): Option<Data<T>> {
    if (!df::exists_(&oracle.id, ticker)) {
        return option::none()
    };
    let data: &StoredData<T> = df::borrow(&oracle.id, ticker);
    let StoredData { value, sequence_number, timestamp, identifier } = *data;
    option::some(data::new(value, ticker, sequence_number, timestamp, oracle.address, identifier))
}
``` [1](#0-0) 

The function signature does not accept a `&Clock` argument. The `timestamp` field stored inside `StoredData` is recorded at submission time via `clock::timestamp_ms(clock)`: [2](#0-1) 

but is never compared against the current time when the data is *read*. There is no maximum-age assertion, no abort, and no `Option::none` return for stale entries.

**`meta_oracle::combine` — relative window, not absolute wall-clock check**

`MetaOracle` is the "trusted" aggregation layer. Its `combine` function filters out oracle readings that fall outside a `time_window_ms` window:

```move
let min_timestamp = max_timestamp - time_window_ms;
...
if (data::timestamp(&oracle_data) > min_timestamp) {
    vector::push_back(&mut values, *data::value(&oracle_data));
``` [3](#0-2) 

`max_timestamp` is set to the timestamp of the **last oracle added**, not to the current clock time:

```move
public fun add_simple_oracle<T: copy + drop + store>(meta_oracle: &mut MetaOracle<T>, oracle: &SimpleOracle) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
``` [4](#0-3) 

If all oracle operators stop submitting updates at the same time, every stored timestamp is equally old. `max_timestamp` equals the most-recently-added oracle's stale timestamp, `min_timestamp = max_timestamp - time_window_ms`, and all readings still satisfy `timestamp > min_timestamp` as long as they were submitted within `time_window_ms` of each other — even if that window ended hours or days ago. The `MetaOracle` never compares any timestamp to `sui::clock::Clock`.

---

### Impact Explanation

Any protocol that calls `get_latest_data` or uses `MetaOracle::median` to price assets, compute exchange rates, or trigger liquidations will silently consume arbitrarily old prices. This constitutes **harmful smart-contract behavior**: financial state transitions (minting, swapping, liquidating) execute against prices that no longer reflect market reality, enabling loss of funds for users of those protocols. The `simple_oracle` framework is a production shared-object package in the Sui monorepo, not a test artifact.

---

### Likelihood Explanation

Oracle operators are off-chain processes. Any network disruption, operator failure, or deliberate halt causes the on-chain `StoredData` to age without any on-chain mechanism to detect or reject it. A single ordinary SUI holder can call `get_latest_data` or any protocol function that internally calls it at any time, with no special privilege required.

---

### Recommendation

1. **Add a `Clock` parameter to `get_latest_data`** and assert that `clock::timestamp_ms(clock) - timestamp <= MAX_STALENESS_MS` before returning data; return `option::none()` or abort if the data is too old.

2. **In `meta_oracle::combine`, compare `max_timestamp` against `clock::timestamp_ms(clock)`** (requiring `Clock` to be threaded through `add_simple_oracle` and `median`) so that the absolute age of the freshest oracle reading is bounded, not just the relative spread between oracles.

3. **Expose a `get_latest_data_with_staleness_check`** variant that takes `&Clock` and a caller-supplied `max_age_ms`, making the safe path the default API.

---

### Proof of Concept

1. Oracle operator submits a price for `SUIUSD` at time `T` via `submit_data`. The stored `timestamp` is `T`.
2. Operator goes offline. No further `submit_data` calls are made.
3. At time `T + 3600_000` (one hour later), an attacker calls a protocol that internally calls `simple_oracle::get_latest_data` for `SUIUSD`.
4. `get_latest_data` returns the entry with `timestamp = T` — no check is performed.
5. The protocol computes `amount = mist_amount * stale_price_value` and mints/transfers assets at the hour-old price.
6. The attacker profits from the price discrepancy between the stale on-chain price and the real market price.

The same attack applies to `MetaOracle`: if all three oracles in `trusted_fx` stopped updating simultaneously, `combine` passes all three stale readings (they are within `time_window_ms` of each other), `median` returns the stale median, and the protocol acts on it. [5](#0-4) [1](#0-0) [6](#0-5)
