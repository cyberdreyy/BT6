### Title
`check_parent_tenure_choice` conflates "we never pre-committed" with "poorly-timed block", letting a miner front-run a permitted reorg of an already-canonical tenure - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`SortitionData::check_parent_tenure_choice` decides whether a miner is allowed to reorg a prior tenure. For a reorged tenure that produced a block, it only permits the reorg if that block's local record shows it was "poorly timed" (produced very close to the next sortition). When the local record has no `approved_time`, the code assumes "we did not sign over the reorged tenure's first block, considering it as a late-arriving proposal" and hard-codes `proposal_to_sortition = 0`, which always passes the "poorly timed" test and permits the reorg — regardless of how long the tenure's block actually existed and how canonical/established it was.

### Finding Description
The vulnerable logic: [1](#0-0) 

```rust

    let proposal_to_sortition = if let Some(approved_at) = local_block_info.approved_time {
        sortition_state_received_time.saturating_sub(approved_at)
    } else {
        info!("We did not sign over the reorged tenure's first block, considering it as a late-arriving proposal");
        0
    };
    if Duration::from_secs(proposal_to_sortition) < *first_proposal_burn_block_timing {
        ... superseded_tenures.push(tenure); continue;
    }
    ...
```

`approved_time` is only ever stamped by `mark_pre_committed`/`mark_locally_accepted`, never by `mark_globally_accepted`: [2](#0-1) 

A signer that never personally pre-committed to a tenure's first block before the network already reached the 70% threshold and pushed the block will have a `BlockInfo` whose `approved_time` is `None` even though `signed_group`/state is `GloballyAccepted`. This happens through the ordinary `SignerEvent::NewBlock` path, which jumps a still-`Unprocessed` block straight to `GloballyAccepted` without ever calling `mark_pre_committed`/`mark_locally_accepted`: [3](#0-2) 

`get_first_approved_block_in_tenure` still returns this record (its query matches on `signed_group IS NOT NULL`), so `check_parent_tenure_choice` retrieves a real, globally-accepted, canonical block for the reorged tenure but with `approved_time == None`, and — instead of treating this as "we have local knowledge but no timing data" — it collapses to `proposal_to_sortition = 0`, which is always `< first_proposal_burn_block_timing` (default 60s). The tenure is then unconditionally superseded and the reorg permitted: [4](#0-3) 

This is the same bug class as the Knox report: a code path treats an "empty"/default value (`approved_time == None`) as evidence of a specific favorable state (block arrived too late to matter), when in fact that default can be produced by an entirely different, common, and miner-influenceable timing race — a signer whose own validation/pre-commit lagged behind the rest of the signer set reaching threshold.

### Impact Explanation
The guard exists specifically to stop a new miner from orphaning an established tenure that "had enough time" to be seen by the network. Because this equality is broken (validation-lag vs genuinely-late-arriving-proposal), a signer can be led to treat a well-established, long-canonical tenure as fair game for a reorg. `check_parent_tenure_choice`'s result feeds directly into `validate_tenure_change_payload`, whose only alternative is `RejectReason::ReorgNotAllowed`: [5](#0-4) 

A `true` result here lets the signer sign a tenure-change block that discards a previously-canonical, globally-accepted tenure it should have refused — a signer signing a non-canonical/conflicting block, which is the Critical impact class in scope.

### Likelihood Explanation
No majority of signers or key compromise is required. The precondition (a signer's own `approved_time` unset while the block reached `GloballyAccepted` via the `NewBlock`/network-threshold path rather than via its own pre-commit) is a normal occurrence for any signer whose local `/v3/block_proposal` validation round-trip is slower than the rest of the signer set reaching the 70% pre-commit/signature threshold — i.e., ordinary node load, network jitter, or a one-slot miner intentionally delaying delivery of the proposal to specific signers relative to others while ensuring the rest of the set signs quickly. A miner who then wins the very next sortition and proposes a tenure-change block reorging that tenure can trigger this evaluation on any signer sitting in that state.

### Recommendation
Do not default `proposal_to_sortition` to `0` when `approved_time` is `None`. Distinguish "we have no local record of this tenure's block at all" (already handled safely by the `None` branch a few lines above, which rejects the reorg) from "we have a record, but never independently pre-committed/timed it because it was already globally accepted by others." In the latter case, fall back to a timestamp actually correlated with when the block became canonical (e.g. `signed_group`, or the burn-block-receive time recorded for the tenure) rather than assuming worst-case-favorable timing of `0`.

### Proof of Concept
1. Miner A produces tenure T's first (and only) block `B`. Signer `S` receives the `BlockProposal` for `B` and stores it as `Unprocessed`, but the node's `/v3/block_proposal` validation response for `S` is slow.
2. Before `S`'s own validation/pre-commit completes, the rest of the signer set reaches the 70% signature threshold and the block is pushed to the node.
3. `S` receives `SignerEvent::NewBlock` for `B`; per `stacks-signer/src/v0/signer.rs:706-727`, `S` looks up the still-`Unprocessed` `BlockInfo`, calls `mark_globally_accepted()`, and stores it. `approved_time` remains `None`; `signed_group` is set.
4. Time passes; tenure T is long-established and canonical (many blocks/confirmations later on the burnchain, well past `first_proposal_burn_block_timing`).
5. Miner A (or an ally) wins a later sortition without building on T's tip and proposes a tenure-change block reorging T.
6. `S` evaluates `check_parent_tenure_choice`: `get_first_approved_block_in_tenure` returns `B`'s record; `local_block_info.approved_time` is `None`, so `proposal_to_sortition` is forced to `0`, which is `< first_proposal_burn_block_timing`. `S` marks T as superseded and permits the reorg, contrary to the intended rule that only genuinely poorly-timed tenures may be reorged.

    /// Mark this block as valid, record the approved time timestamp if not already set and attempt to mark it as pre-committed.
    pub fn mark_pre_committed(&mut self) -> Result<(), String> {
        self.valid = Some(true);
        self.approved_time.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::PreCommitted)
    }

    /// Mark this block as valid and the appropriate timestamps if they aren't already set, and attempt to mark it as locally accepted.
    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Mark this block's signed group time if not already set and attempt to mark it as globally accepted.
    pub fn mark_globally_accepted(&mut self) -> Result<(), String> {
        self.signed_group.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::GloballyAccepted)
    }
