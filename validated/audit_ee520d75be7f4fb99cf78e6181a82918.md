### Title
`IdleUsualStrategy.getChainlinkPrice` does not verify the Chainlink answer is inside the aggregator min/max bounds, so a circuit-breaker-clamped USD0++ price corrupts the senior/junior loss waterfall in `IdleCDOUsualVariant.stopEpoch` - ([contracts/strategies/usual/IdleUsualStrategy.sol:164](contracts/strategies/usual/IdleUsualStrategy.sol))

### Summary
`getChainlinkPrice` reads `latestRoundData` from the USD0++/USD Chainlink feed and only validates staleness (`updatedAt > block.timestamp - 24 hours`). It never checks whether `answer` equals the aggregator's circuit-breaker bounds (`minAnswer`/`maxAnswer`). When an asset crashes below `minAnswer` (LUNA-style) or spikes above `maxAnswer`, Chainlink keeps returning the clamped bound rather than the true market price. That bound is then consumed verbatim by `IdleCDOUsualVariant.stopEpoch` to compute how much junior TVL must be transferred to seniors to restore $1 parity, breaking the loss-socialization invariant.

### Finding Description
- `contracts/strategies/usual/IdleUsualStrategy.sol:164-172`: `getChainlinkPrice` returns `uint256(answer) * 1e10` with a stale check only; no `answer < maxAnswer` / `answer > minAnswer` validation, no `answer > 0` check either.
- `contracts/IdleCDOUsualVariant.sol:77`: `stopEpoch` fetches `_oraclePrice = _strategy.getChainlinkPrice()` and calls `setOraclePrice`.
- `IdleUsualStrategy.setOraclePrice` (lines 155-161) clamps to `IUSD0pp(USD0pp).getFloorPrice()` — this floor protects only against a price lower than Usual's own redemption floor; it does not detect a feed that is pinned at `minAnswer` *above* the true market price.
- `stopEpoch` then computes `targetAATVL = lastNAVAA * oneToken / _oraclePrice` (line 93) and bumps `lastNAVAA` so that the subsequent `_updateAccounting` registers a loss absorbed entirely by juniors via `_virtualPriceAux` (lines 152-168).

Attack path (unprivileged junior holder):
1. During the running epoch, attacker holds BB (junior) tranche tokens acquired via normal KYC'd `depositBB`.
2. USD0++ suffers a crash below the Chainlink feed's `minAnswer` (e.g., true price $0.50, feed clamped at `minAnswer = $0.90`). The aggregator keeps answering within the 24h heartbeat, so the staleness check passes.
3. Owner calls `stopEpoch()` (honest privileged action — attacker only sequences around it). `_oraclePrice` = $0.90 instead of $0.50. `targetAATVL = lastNAVAA / 0.9` understates the real shortfall (`lastNAVAA / 0.5` required for true parity).
4. `_updateAccounting` books too small a junior loss; seniors are left below $1 parity. The attacker calls `withdrawBB` (allowed since `allowBBWithdraw = true`) and redeems junior tranche tokens at a virtual price inflated by the escaped loss.

Symmetric upper-bound case: if USD0++ spikes above `maxAnswer`, the feed reports a price lower than reality; if `maxAnswer < 1`, juniors over-transfer to seniors, letting a senior-tranche attacker redeem more than fair parity value.

### Impact Explanation
Direct mispricing of the loss waterfall: juniors permanently escape a portion of the USD0++ depeg compensation owed to seniors (or vice versa in the max-bound case). Senior holders suffer an unrecoverable shortfall proportional to `lastNAVAA * (1/clampedPrice - 1/truePrice)` — e.g., with 10M USD0++ senior NAV, a true price of $0.50 vs a clamped $0.90 means ~8.9M USD0++ of missing junior coverage, diluting senior redemption value well below $1. This is a permanent loss of funds for the disadvantaged tranche class, not a DoS.

### Likelihood Explanation
- Requires an extreme USD0++ move beyond the feed's circuit-breaker band — a tail event, but precisely the event this vault was built to protect against (depeg protection for seniors). The vault's whole purpose is to make seniors whole on depeg; the missing bound check fails exactly when it matters most.
- The attacker needs only be a junior/senior tranche holder redeeming after `stopEpoch`; no privileged action. `stopEpoch` and `setOraclePrice` are owner/idleCDO gated, so the attacker cannot trigger it, but simply holding tranche tokens through an honest `stopEpoch` suffices.
- Partial mitigation: `setOraclePrice` floors at `USD0pp.getFloorPrice()` and `stopEpoch` early-returns when `_oraclePrice >= oneToken`, so the max-bound overpay only triggers if `maxAnswer < 1e8` on the feed. The min-bound (crash) case is the realistic one and is unmitigated.

### Recommendation
In `getChainlinkPrice`, also fetch `roundId`/`answeredInRound` and validate the answer against the feed bounds, e.g.:

```solidity
(uint80 roundId, int256 answer, , uint256 updatedAt, uint80 answeredInRound) =
    IOracle(USD0ppOracle).latestRoundData();
require(answer > 0 && answeredInRound >= roundId, "Invalid round");
require(updatedAt > block.timestamp - 24 hours, "Stale price");
require(answer > MIN_ANSWER && answer < MAX_ANSWER, "Price out of bounds");
```

Alternatively store the feed's `minAnswer`/`maxAnswer` at deployment (via the aggregator's `minAnswer`/`maxAnswer` view functions where exposed) and revert so `stopEpoch` cannot proceed on a clamped price, forcing manual resolution instead of silently mispricing the waterfall.

### Proof of Concept
Foundry fork test (mainnet, since `USD0ppOracle` is a hardcoded mainnet address):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;
import "forge-test/IdleCDOUsualVariantBase.sol"; // reuse existing fork fixture

contract MinMaxAnswerPoC is IdleCDOUsualVariantBaseTest {
    // Mock aggregator that mimics the circuit breaker: clamps answer to minAnswer
    function testClampedOracleUnderpaysSeniors() external {
        // 1. Lenders deposit: AA (senior) 1000 usd0++, BB (junior) 1000 usd0++
        _depositAA(1000e18); _depositBB(1000e18);
        vm.prank(owner); idleCDO.startEpoch(180 days);
        vm.warp(block.timestamp + 180 days + 1);

        // 2. True USD0++ price crashes to $0.50, but the feed clamps at minAnswer $0.90.
        //    Replace USD0ppOracle bytecode with a mock returning answer = 0.9e8, fresh updatedAt.
        MockClampedFeed mock = new MockClampedFeed(0.9e8);
        vm.etch(USD0pp_ORACLE, address(mock).code);

        // 3. Owner stops epoch — getChainlinkPrice returns 0.9e18, no bounds check reverts
        vm.prank(owner); idleCDO.stopEpoch();

        // 4. Senior virtual price should be ~1e18 * 1/0.5 = 2e18-equivalent coverage,
        //    but only 1/0.9 is applied -> senior price < parity.
        uint256 aaPrice = idleCDO.virtualPrice(AA);
        assertLt(aaPrice, ONE_TRANCHE_TOKEN); // senior left below $1 parity
        // Junior attacker withdraws at inflated price: _withdrawBB succeeds,
        // junior NAV retained = crash loss that should have been socialized away.
    }
}

contract MockClampedFeed {
    int256 ans;
    constructor(int256 a) { ans = a; }
    function latestRoundData() external view returns (uint80, int256, uint256, uint256, uint80) {
        return (1, ans, block.timestamp, block.timestamp, 1); // fresh, passes stale check
    }
}
```

The PoC demonstrates that with the real feed clamped at `minAnswer`, `stopEpoch` completes successfully and produces a senior `virtualPrice` strictly below the parity the vault promises, while juniors retain redeemable value that should have covered the senior shortfall.
