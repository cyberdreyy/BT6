### Title
Stale cached role allows continued elevated access after LDAP role downgrade until periodic sync completes - (File: core/sessions/ldapauth/ldap.go)

### Summary
Similar to the `updateBondCurve` bug class — where a state-changing update (curve change) doesn't force synchronous recomputation of a dependent value (depositable amount), leaving stale/inconsistent state that can be exploited — the Chainlink node's LDAP authentication provider caches a user's `user_role` in the `ldap_sessions` and `ldap_user_api_tokens` tables at login/token-creation time, and every subsequent authenticated request trusts that cached role directly rather than revalidating it against the authoritative upstream LDAP group membership. Reconciliation only happens asynchronously via a background timer (`LDAPServerStateSyncer.Work`), so a user whose privileges were just downgraded upstream keeps acting with the old, higher-privileged role for up to a full sync interval.

### Finding Description
`AuthorizedUserWithSession` reads the cached `user_role` column straight out of `ldap_sessions` and returns it without any live LDAP lookup: [1](#0-0) 

Likewise, `FindUserByAPIToken` reads the cached `user_role` from `ldap_user_api_tokens` and returns it directly: [2](#0-1) 

The package doc comment claims role changes "propagate through ... This sync happens for every auth endpoint hit, and via the defined sync interval," but the actual per-request auth paths above never invoke any upstream revalidation — they only query local Postgres tables: [3](#0-2) 

The only mechanism that reconciles local cached roles with the authoritative upstream LDAP group state is the background `LDAPServerStateSyncer.Work` function, which runs on a configurable timer (`UpstreamSyncInterval`) or once at startup — not per request: [4](#0-3) 

That function performs a bulk `UPDATE ldap_sessions SET user_role = CASE ...` / `UPDATE ldap_user_api_tokens SET user_role = CASE ...` to bring cached roles in line with the freshly queried upstream group membership: [5](#0-4) 

This is structurally the same defect class as the reported `updateBondCurve` issue: an authorization-relevant state change (role/group membership change upstream) is not forced to propagate synchronously to the derived, consumed value (the cached role used for authorization decisions on every request). The system instead relies on an out-of-band periodic reconciliation, creating a window of inconsistent state that a demoted/lower-privileged actor can exploit simply by continuing to use their already-issued session cookie or API token.

### Impact Explanation
An operator who is demoted from `Admin`/`Edit` to a lower role (e.g., `Read`/`Run`) in the upstream LDAP directory — because they are no longer trusted with elevated privileges — continues to be authenticated and authorized as their old, higher role for every request handled by `AuthenticateBySession`/`AuthenticateByToken` until the next scheduled `UpstreamSyncInterval` tick fires: [6](#0-5) [7](#0-6) 

Depending on operator configuration, `UpstreamSyncInterval` can be set arbitrarily long, meaning the demoted (now supposed to be unprivileged for the removed capability) user retains admin-level control of the node's jobs, keys, and configuration mutation endpoints for an extended period — a concrete role/privilege-bypass.

### Likelihood Explanation
This requires only a normal, expected operational action (an administrator demoting a user's LDAP group membership) combined with the demoted user simply continuing to use their already-established session cookie or API token — no attacker sophistication or race condition timing is needed. Any LDAP-backed Chainlink node deployment with a non-trivial `UpstreamSyncInterval` is affected on every role downgrade.

### Recommendation
Perform a live (or short-TTL-cached, e.g., cached only for a few seconds) revalidation of the user's upstream role on every `AuthorizedUserWithSession` / `FindUserByAPIToken` call rather than trusting the value most recently written to `ldap_sessions`/`ldap_user_api_tokens`, or at minimum immediately invalidate/downgrade a session's cached role the moment an admin-triggered role change is detected, rather than deferring it to the next timer-driven `Work()` sync. This mirrors the "2-step update" recommendation in the analog report: ensure the derived/cached authorization value can never be read in a state inconsistent with the authoritative source.

### Proof of Concept
1. Configure the node with LDAP auth and `UpstreamSyncInterval` set to a non-trivial duration (e.g., 30 minutes).
2. User `alice@example.com` is a member of the LDAP Admin group; she logs in via `CreateSession`, which calls `FindUser` and stores `role=Admin` in `ldap_sessions`: [8](#0-7) 
3. An administrator removes `alice` from the Admin group upstream in LDAP (demoting her to Read-only).
4. Before the next `LDAPServerStateSyncer.Work()` tick runs, `alice` continues to send authenticated requests using her existing session cookie.
5. `AuthenticateBySession` → `AuthorizedUserWithSession` reads the still-cached `user_role = Admin` row from `ldap_sessions` and authorizes her as Admin, allowing her to perform admin-only actions (e.g., job/key management) despite no longer being an authorized Admin upstream, until the sync interval elapses and the role UPDATE in `sync.go` finally executes.

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

func (l *ldapAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (sessions.User, error) {
	if len(sessionID) == 0 {
		return sessions.User{}, errors.New("session ID cannot be empty")
	}
	// Query the ldap_sessions table for given session ID, user role and email are cached so
	// no further upstream LDAP query is performed
	var foundSession struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	if err := l.ds.GetContext(ctx, &foundSession,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_sessions WHERE id = $1",
		sessionID, l.config.SessionTimeout().Duration(),
	); err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	if !foundSession.Valid {
		// Sessions expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE id = $1", sessionID); execErr != nil {
			l.lggr.Errorf("error purging stale ldap session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	return sessions.User{
		Email: foundSession.UserEmail,
		Role:  foundSession.UserRole,
	}, nil
}

func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}

	// Bind was successful meaning user and credentials are present in LDAP directory
	// Reuse FindUser functionality to fetch user roles used to create ldap_session entry
	// with cached user email and role
	foundUser, err := l.FindUser(ctx, escapedEmail)
	if err != nil {
		l.lggr.Infof("Successful user login, but error querying for user groups: user: %s, error %v", escapedEmail, err)
		returnErr = errors.New("log in successful, but no assigned groups to assume role")
	}

	isLocalUser := false
	if returnErr != nil {
		// Unable to log in against LDAP server, attempt fallback local auth with credentials, case of local CLI Admin account
		// Successful local user sessions can not be managed by the upstream server and have expiration handled by the reaper sync module
		foundUser, returnErr = l.localLoginFallback(ctx, sr)
		isLocalUser = true
	}

	// If err is still populated, return
	if returnErr != nil {
		return "", returnErr
	}

	l.lggr.Infof("Successful LDAP login request for user %s - %s", sr.Email, foundUser.Role)

	// Save session, user, and role to database. Given a session ID for future queries, the LDAP server will not be queried
	// Sessions are set to expire after the duration + creation date elapsed, and are synced on an interval against the upstream
	// LDAP server
	session := sessions.NewSession()
	_, err = l.ds.ExecContext(
		ctx,
		"INSERT INTO ldap_sessions (id, user_email, user_role, localauth_user, created_at) VALUES ($1, $2, $3, $4, now())",
		session.ID,
		strings.ToLower(sr.Email),
		foundUser.Role,
		isLocalUser,
	)
	if err != nil {
		l.lggr.Errorf("unable to create new session in ldap_sessions table %v", err)
		return "", fmt.Errorf("error creating local LDAP session: %w", err)
	}

	l.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": sr.Email})

	return session.ID, nil
}

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}
