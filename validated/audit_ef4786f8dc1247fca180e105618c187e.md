### Title
Delayed `stopEpoch` lets borrower interest accrue past `epochEndDate`, minting unbacked yield to tranche holders - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
In programmable-borrower mode, epoch interest is not a fixed amount computed for `epochDuration`; it is priced at `block.timestamp` when `stopEpoch` is invoked via `ProgrammableBorrower.totalInterestDueNow()` → `borrowerInterestAccruedNow()` → `_pendingBorrowerInterest`. Because nothing caps the accrual at `epochEndDate`, a delayed `stopEpoch` (the honest-owner/manager analogue of Perennial's delayed `sync`) accrues `borrowerApr` over `stopTime - epochStart` rather than over `epochDuration`, over-emitting interest to tranche holders exactly like `_unsettled` over-emitting rewards past `versionComplete`.

### Finding Description
`stopEpoch` only requires `block.timestamp >= epochEndDate`; there is no upper bound on when it may be called (`IdleCDOEpochVariant.sol:338-351`). The expected interest is resolved through the programmable hook, which snapshots `totalInterestDueNow()`:

```solidity
// ProgrammableBorrower.sol:330-334
function totalInterestDueNow() external view returns (uint256) {
  (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
  uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
  return totalGain > loss ? totalGain - loss : 0;
}
```

`borrowerInterestAccruedNow` (ProgrammableBorrower.sol:310-312) adds `_pendingBorrowerInterest`, which prorates `borrowerApr` over raw elapsed seconds:

```solidity
// ProgrammableBorrower.sol:554-558
function _pendingBorrowerInterest(uint256 principal, uint256 last) internal view returns (uint256) {
  if (principal == 0 || last == 0 || borrowerApr == 0) return 0;
  uint256 elapsed = block.timestamp - last;
  return elapsed == 0 ? 0 : _calcInterest(principal, elapsed);
}
```

`lastBorrowerAccrual` is seeded at epoch start, so elapsed can far exceed `epochDuration`. Contrast with the fixed-APR path, where `expectedEpochInterest` is locked at `startEpoch` via `_calcInterest(getContractValue())` scaled to `epochDuration` (IdleCDOEpochVariant.sol:260-262) and is immune to stop-time drift.

In minted-interest mode (`isInterestMinted`), this over-accrued amount is minted into tranche prices: `_amountToPullFromBorrower = 0` and `settleBorrowerInterest` books the full accrued value as `borrowerInterestDebt` (IdleCDOEpochVariant.sol:374-380, 413-415). Tranche holders can then claim withdraw at the inflated `virtualPrice` while the backing is only the borrower's vault sleeve + future debt repayment. If accrued interest exceeds what the borrower can cover, the pool tips into the `_handleBorrowerDefault` path and the loss is socialized.

### Impact Explanation
Every second `stopEpoch` is delayed mints `principal * borrowerApr / YEAR` of extra interest to AA/BB holders that was not earned within the intended epoch and may not be backed by ERC4626 vault yield. Withdrawers who claim first capture the inflated price; late claimants and remaining LPs absorb the shortfall if the borrower-side debt becomes unrecoverable, producing insolvency or forced default — the same "over-emission paid by the last ones out" dynamic as the Perennial report.

### Likelihood Explanation
The trigger is a delayed honest-manager `stopEpoch` call (keeper downtime, congestion, operational delay), matching the report's threat model; no malicious privileged action is needed. An unprivileged attacker profits simply by holding tranches and claiming at the drifted price once `stopEpoch` lands. Impact grows linearly with delay, bounded only by when the honest manager eventually stops the epoch.

### Recommendation
Cap the programmable accrual window at the scheduled epoch end: clamp `elapsed` to `min(block.timestamp, epochStart + epochDuration) - lastBorrowerAccrual` inside `_pendingBorrowerInterest`/`_accrueBorrowerInterest` (store `epochEndDate` in `startEpochAccounting`), or pass `epochEndDate` to `onStopEpoch` and accrue only up to it. This mirrors the report's recommendation of pro-rata capping at the program end.

### Proof of Concept

```solidity
function testDelayedStopOverAccrues() external {
  uint256 amount = 10_000 * oneScale;
  vm.prank(owner); cdoEpoch.setIsInterestMinted(true);
  idleCDO.depositAA(amount);
  _startEpochAndCheckPrices(0);

  // Scheduled end passes; manager calls stopEpoch much later
  vm.warp(cdoEpoch.epochEndDate() + 30 days);

  uint256 due = programmableBorrower.totalInterestDueNow();
  uint256 cappedExpected = /* apr * epochDuration */;
  assertGt(due, cappedExpected); // 30 extra days of minted interest

  vm.prank(manager); cdoEpoch.stopEpoch(0, 0);
  // Tranche price reflects drifted interest; borrowerInterestDebt includes it
}
```
