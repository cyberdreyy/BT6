### Title
Unprivileged Type-Swap via `remove_value_for_upgrade` + `upgrade` Enables Direct Fund Theft and Permanent State Corruption — (`crates/sui-framework/packages/sui-framework/sources/versioned.move`)

---

### Summary

`versioned.move` exposes two `public` functions — `remove_value_for_upgrade` and `upgrade` — with no caller-identity or type-consistency enforcement. Any PTB sender who can pass a shared `Versioned` object as a mutable input can extract the inner value (e.g., `Coin<SUI>`), transfer it to themselves, and then satisfy the hot-potato `VersionChangeCap` by calling `upgrade` with a completely different type (e.g., `u64`). The result is direct fund theft and permanent type corruption of the shared object.

---

### Finding Description

`VersionChangeCap` is a hot-potato struct (no abilities) that is returned by `remove_value_for_upgrade` and must be consumed by `upgrade` in the same transaction:

```move
public struct VersionChangeCap {
    versioned_id: ID,
    old_version: u64,
}
``` [1](#0-0) 

The cap records only `versioned_id` and `old_version`. It records **no type information** about what was removed.

`upgrade` validates only two invariants:

```move
assert!(versioned_id == object::id(self), EInvalidUpgrade);
assert!(old_version < new_version, EInvalidUpgrade);
``` [2](#0-1) 

There is no check that the `T` in `upgrade<T>` matches the `T` used in `remove_value_for_upgrade<T>`. Both functions are `public` with no access-control guard: [3](#0-2) [4](#0-3) 

---

### Impact Explanation

**Direct fund theft + permanent state corruption (Critical).**

Attack steps in a single PTB from an unprivileged sender:

1. Pass the shared `Versioned` object (wrapping `Coin<SUI>` at version V) as a mutable input.
2. Call `versioned::remove_value_for_upgrade<Coin<SUI>>(versioned)` → receives `(coin: Coin<SUI>, cap: VersionChangeCap)`.
3. Call `transfer::public_transfer(coin, attacker_address)` → coin is stolen. (`Coin<SUI>` has `key + store`, so `public_transfer` is valid.)
4. Call `versioned::upgrade<u64>(versioned, V+1, 0u64, cap)` → hot potato consumed; a `u64` is now stored at version V+1.

After the transaction:
- The attacker holds the `Coin<SUI>`.
- The `Versioned` object's dynamic field at version V+1 contains a `u64`.
- Any subsequent `load_value<Coin<SUI>>` aborts with `EFieldTypeMismatch` — the coin is permanently inaccessible to the legitimate owner through this object.

---

### Likelihood Explanation

**High.** The entry path is a standard PTB with a shared-object mutable input — no special permissions, no leaked keys, no malicious validators required. Any `Versioned` shared object wrapping a coin or other valuable asset is immediately exploitable by any on-chain sender. The `Versioned` module is a Sui-framework utility actively used by protocols to manage upgradeable shared state.

---

### Recommendation

1. **Record the removed type tag in `VersionChangeCap`** and assert it matches in `upgrade`, or make `upgrade` generic-free and enforce the same type at the Move level.
2. **Add an access-control field** (e.g., an `ID` of an owner/admin capability) to `VersionChangeCap` and verify it in `upgrade`, so only the authorized caller who initiated `remove_value_for_upgrade` can complete the upgrade.
3. Alternatively, **restrict `remove_value_for_upgrade` and `upgrade` to `public(package)`** so only the defining module (or modules in the same package) can call them, forcing all callers to go through their own access-controlled wrappers.

---

### Proof of Concept

```move
// Attacker's PTB (pseudocode):
// 1. versioned: &mut Versioned  (shared object wrapping Coin<SUI> at version 1)
let (coin, cap) = versioned::remove_value_for_upgrade<Coin<SUI>>(&mut versioned);
// coin is now Coin<SUI> belonging to the legitimate owner

transfer::public_transfer(coin, @attacker);
// coin stolen

versioned::upgrade<u64>(&mut versioned, 2, 0u64, cap);
// hot potato consumed; Versioned now holds u64 at version 2

// After tx: load_value<Coin<SUI>>(&versioned) aborts with EFieldTypeMismatch
```

The `VersionChangeCap` hot-potato pattern was intended to guarantee a value is always returned, but it provides no guarantee that the **same type** or an **authorized caller** returns it.

public fun upgrade<T: store>(
    self: &mut Versioned,
    new_version: u64,
    new_value: T,
    cap: VersionChangeCap,
) {
    let VersionChangeCap { versioned_id, old_version } = cap;
    assert!(versioned_id == object::id(self), EInvalidUpgrade);
    assert!(old_version < new_version, EInvalidUpgrade);
    dynamic_field::add(&mut self.id, new_version, new_value);
    self.version = new_version;
}
