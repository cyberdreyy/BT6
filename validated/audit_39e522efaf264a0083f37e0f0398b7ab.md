### Title
Username Enumeration via Distinguishable Login Error Messages - ([File: core/sessions/localauth/orm.go], [File: core/web/auth/helpers.go])

### Finding Description
`SessionsController.Create` (`core/web/sessions_controller.go`) calls `sc.App.AuthenticationProvider().CreateSession(ctx, sr)` and, on any error, forwards the raw `err` unmodified to `jsonAPIError(c, http.StatusUnauthorized, err)`. [1](#0-0) 

`jsonAPIError` serializes that error verbatim into the JSON response body via `models.NewJSONAPIErrorsWith(err.Error())` unless it's already a `*models.JSONAPIErrors`. [2](#0-1) 

The underlying `orm.CreateSession` (`core/sessions/localauth/orm.go`) produces different, distinguishable error strings depending on *why* authentication failed:
- Non-existent email: `o.FindUser(ctx, sr.Email)` fails with the raw driver error (e.g., `sql: no rows in result set`) and that error is returned unwrapped: `if err != nil { return "", err }`. [3](#0-2) 
- Existing email, wrong password: `pkgerrors.New("Invalid password")`. [4](#0-3) 
- Case-mismatch email compare failure (rare/theoretical): `pkgerrors.New("Invalid email")`. [5](#0-4) 

These three code paths yield textually distinct error strings that flow unmodified into the HTTP 401 response body. An unauthenticated attacker probing `POST /sessions` can therefore distinguish "no such user" (raw SQL driver error text) from "user exists but wrong password" (`"Invalid password"`), enabling account/email enumeration. This is a genuine information-leak/credential-oracle bug distinct from timing side channels (the code already defends against a *timing* oracle via `constantTimeEmailCompare`, but does nothing to normalize the textual error).

### Impact Explanation
This maps to Chainlink's "information disclosure" bounty class — specifically, unauthenticated enumeration of valid node-operator/API-user email addresses. While it does not by itself grant authentication bypass or fund movement, it materially assists a credential-stuffing/brute-force attacker by letting them first enumerate valid accounts and then focus password guessing only on confirmed-valid emails, and it may also leak raw database driver text (e.g., column/table hints from SQL errors) to unauthenticated clients.

### Likelihood Explanation
Fully unauthenticated, single HTTP request required (`POST /sessions`), trivially repeatable and automatable — no rate limiting or additional preconditions are evident in this handler path. This is a realistic and cheap reconnaissance step against any exposed Operator UI/API login endpoint.

### Recommendation
Normalize all authentication-failure paths in `orm.CreateSession` to return one generic sentinel error (e.g., `sessions.ErrInvalidCredentials` or similar) regardless of whether the email was not found, the password was wrong, or the email case-mismatch check failed, and have `SessionsController.Create` map any `CreateSession` error to a fixed generic 401 message (e.g., `"invalid credentials"`) rather than passing `err.Error()` through `jsonAPIError`. Ensure DB/driver errors are never serialized directly to unauthenticated clients.

### Proof of Concept
Go handler-level test plan (extending `TestSessionsController_Create` in `core/web/sessions_controller_test.go`):
1. Create one user via `app.AuthenticationProvider().CreateUser`.
2. Issue `POST /sessions` with `{"email":"nonexistent@test.net","password":"whatever"}` and capture the full response body.
3. Issue `POST /sessions` with `{"email":"<existing-user-email>","password":"wrongpassword"}` and capture the full response body.
4. Assert both return `401`.
5. Assert `resp1.Body != resp2.Body` today (proving the vulnerability exists) — e.g., body 1 contains SQL driver text like `sql: no rows in result set` while body 2 contains `Invalid password`.
6. After the fix, assert both bodies are byte-for-byte identical, containing only a generic message such as `"invalid credentials"`.

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
