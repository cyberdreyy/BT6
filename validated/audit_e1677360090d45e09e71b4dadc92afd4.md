### Title
Unbounded recursive RLP decoding of `TrieNode` allows stack-overflow DoS of the fault-proof program via a single crafted trie-node preimage - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` (the RLP `Decodable` implementation for `base-proof-mpt`'s `TrieNode`) recurses into itself with no depth bound whenever it decodes `Extension` or `Branch` nodes whose children are RLP-embedded (i.e. shorter than 32 bytes) rather than hash-blinded. Because RLP allows arbitrarily many small nested lists to be packed into a single byte string, a single attacker-supplied "trie node" preimage can encode thousands of nested `Extension`/`Branch` layers, driving unbounded native-stack recursion on decode. This mirrors the GPAC `dmx_saf` bug class cited in CVE-2025-70305: a recursive box/structure parser with no nesting-depth guard, triggerable by a single crafted input, causing a stack-overflow DoS.

### Finding Description
`TrieNode::decode` dispatches by RLP list length: [1](#0-0) 

For `BRANCH_LIST_LENGTH` it calls `Vec::<Self>::decode(buf)`, which in turn calls `TrieNode::decode` once per branch slot, and for `LEAF_OR_EXTENSION_LIST_LENGTH` it calls `try_decode_leaf_or_extension_payload`, which for extension nodes recurses via `Self::decode(buf)`: [2](#0-1) 

Per the Ethereum trie encoding rule implemented here, a child node is only replaced by its 32-byte keccak commitment (`Blinded`) when its RLP-encoded length is `>= 32` bytes; otherwise it is embedded inline: [3](#0-2) 

This means an attacker who controls the bytes returned for a single preimage-oracle fetch can construct one small (well under any reasonable size limit) but deeply/recursively nested RLP blob — e.g. a chain of single-child branch/extension nodes each with near-zero payload — that decodes through thousands of nested `Self::decode` calls in one `TrieNode::decode` invocation. There is no depth counter or recursion limit anywhere in `node.rs` or its `util::rlp_list_element_length` helper (unlike the CBOR parser in `crates/proof/tee/registrar/src/cbor.rs`, which explicitly enforces `MAX_CBOR_NESTING_DEPTH`).

This decoder is invoked directly on untrusted preimage-oracle data in the fault-proof program's chain providers, with no depth or size validation prior to decode: [4](#0-3) [5](#0-4) 

Both `OracleL1ChainProvider::trie_node_by_hash` and `OracleL2ChainProvider::trie_node_by_hash` are core to the fault-proof program's state/derivation path (`crates/proof/executor`, `crates/proof/mpt`), reached whenever the program walks the account/storage trie or a receipts/transactions trie during dispute-game execution.

### Impact Explanation
In a permissionless fault dispute game, the preimage oracle response for a hash is supplied by/derived from data the program treats as untrusted until keccak-verified — the verification only checks the outer hash equals `keccak256(bytes)`, not the internal structure. An attacker who can influence what bytes are served for a given trie-node hash lookup (e.g. as an adversarial op-program/host implementation, or via crafted L1/L2 state made reachable through a malicious but hash-consistent preimage) can trigger uncontrolled native-stack recursion during `TrieNode::decode`, crashing the fault-proof program process with a stack overflow. This is a Denial-of-Service against the program responsible for producing the provable output root: an aborted/crashed program cannot produce a correct output root, which can translate into an inability to correctly resolve a dispute-game claim (wrong/missing provable output).

### Likelihood Explanation
Reaching this code path requires only a single trie-node preimage fetch during normal derivation/execution inside the fault-proof program — every account/storage lookup and list-walk (`OrderedListWalker`) goes through `trie_node_by_hash` → `TrieNode::decode`. Constructing a small RLP blob with thousands of nested single-element branch/extension nodes is straightforward and requires no cryptographic effort beyond matching the keccak256 preimage-key check.

### Recommendation
Add an explicit recursion-depth (or equivalently, node-count) limit to `TrieNode::decode` / `try_decode_leaf_or_extension_payload`, mirroring the `MAX_CBOR_NESTING_DEPTH` guard already used in `crates/proof/tee/registrar/src/cbor.rs`, and return a decode error once the limit is exceeded rather than recursing unboundedly. Since a valid Ethereum trie's maximum depth is bounded by nibble length (64), a conservative limit (e.g. 64–128) fully covers legitimate use.

### Proof of Concept
Conceptually: build a byte string encoding `N` nested `Extension` nodes, each with the shortest possible 1-nibble path and a payload smaller than 32 bytes, terminating in an `Empty`/`Leaf` node, similar in structure to the existing round-trip test: [6](#0-5) 
Feed the fully-encoded blob as the "preimage" returned by a mocked `TrieProvider`/oracle for a given hash (satisfying the keccak check), and call `TrieNode::decode` on it (or `trie_node_by_hash`, as in `OracleL1ChainProvider`/`OracleL2ChainProvider`). With a sufficiently large `N` (a few thousand nested extension levels fits well under typical preimage size limits), the recursive `Self::decode` calls exhaust the native stack and crash the process, analogous to the recursive `dmx_saf` overflow in GPAC triggered by a crafted `.saf` file.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
