### Title
Unbounded trust in attacker-malleable ERC4626 share balance inflates `totalInterestDueNow`, forcing overcharge or default of the honest borrower - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
Analogous to the Syncope report — where an attacker-supplied definition is executed verbatim into a trusted settlement path — `IdleCDOEpochVariant` treats the programmable borrower's self-reported interest number as ground truth for `stopEpoch`. That number is derived from `vault.balanceOf(this) → convertToAssets`, a value any EOA can inflate by transferring vault shares (or donating underlying, for balance-based vaults) directly to the `ProgrammableBorrower` contract. The unsanctioned "input" is executed into settlement: IdleCDO pulls the inflated `_expectedInterest` in cash from the honest borrower, or triggers `_handleBorrowerDefault` if the borrower cannot cover it.

### Finding Description
`_resolveStopEpochInterest` returns `IProgrammableBorrower(_borrower()).totalInterestDueNow()` verbatim in programmable mode (contracts/IdleCDOEpochVariant.sol:1001-1008), with only the `>1` sentinel check — no cap against `_calcInterestWithApr(getContractValue(), maxApr)` except in the minted-interest branch (line 379).

`totalInterestDueNow()` (ProgrammableBorrower.sol:330-334) = borrower interest + bufferInterest + positive vault PnL − vault loss, where vault PnL comes from `_vaultNetInterest()` → `_currentVaultAssets()` = `vault.convertToAssets(vault.balanceOf(address(this)))` (lines 337-349, 546-549). The share balance is permissionlessly increasable: vault shares are a freely transferable ERC20, so any EOA can `vault.deposit()` and `transfer` the shares to the `ProgrammableBorrower`. The contract has no mechanism to distinguish earned yield from pushed-in shares — no skim, no snapshot of expected NAV, no sanity bound in non-minted mode.

Attack trace (epoch running, non-minted mode, programmable borrower):
1. Attacker deposits `D` underlying into the ERC4626 vault and transfers the minted shares to `ProgrammableBorrower`.
2. Owner/manager calls `stopEpoch(0, 0)`. `_resolveStopEpochInterest` returns `realInterest + D`.
3. `getFundsFromBorrower` pulls `D` extra cash from the honest borrower's wallet via its standing `transferFrom` approval (line 408). The borrower is charged for funds it never owed.
4. If the borrower's balance/allowance can't cover `D`, the pull reverts and `_handleBorrowerDefault(_amountToPullFromBorrower + _pendingWithdraws)` fires, socializing a fabricated "default" onto BB-first LPs and routing the facility into the default/claims path.

The same primitive works in the minted branch up to the `maxApr` cap, minting fee/strategy-token value against pushed shares.

### Impact Explanation
Direct theft: the borrower is force-charged an arbitrary, attacker-set amount `D` that lands in the pool (it is real cash pulled, not just accounting). Insolvency/forced default: when `D` exceeds the borrower's liquid balance, an honest, fully solvent facility is defaulted, burning BB tranche holders first and freezing pending withdraw claims into the defaulted-epoch claims flow. Magnitude is bounded only by the attacker's spend (cost = `D`), but the harm falls on third parties (borrower, then LPs via loss waterfall) — i.e., the attacker converts `D` of their own funds into ≥`D` of damage to protocol participants with no privileged role required.

### Likelihood Explanation
Requires only a running programmable-borrower epoch in non-minted (cash-pull) mode — the default configuration. The attacker needs no role: vault shares are permissionlessly transferable, and no guard rejects unexpected share inbound. `epochStartVaultAssets`/baselines only snapshot at epoch boundaries, so intra-epoch pushes land entirely in `netDelta`. The `maxApr` guard exists only under `isInterestMinted`, leaving the standard path unbounded. Triggering is timing-sensitive to the honest `stopEpoch` call, but the donated position persists until the next stop, so the attacker can front-run any observed stop transaction.

### Recommendation
Bound the pool-facing interest in `IdleCDOEpochVariant.stopEpoch` for all modes, not just minted: `require(_resolvedInterest <= _calcInterestWithApr(getContractValue(), maxApr) + pendingWithdrawFees)`. Alternatively, make `ProgrammableBorrower` track principal-baseline shares (`shares` minted by its own `deposit` calls, e.g. store `vaultSharesOwed` updated only in `_depositToVault`/`withdraw`) and compute `_currentVaultAssets` from the minimum of actual vs. tracked shares, or skim `convertToAssets(unexpectedShares)` to feeReceiver before settlement. Either way, unsolicited share inflows must not enter the settlement price.

### Proof of Concept

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
// Reuse test/foundry/ProgrammableBorrowerCreditVault.t.sol harness:
// idleCDO (IdleCDOEpochVariant), programmableBorrower, morphoVault/ERC4626 `vault`,
// USDC underlying, revolvingBorrower with standing approve to programmableBorrower.

contract DonatedShareInflationPoC is Test /* inherits the fixture */ {
    function testDonatedSharesForceOverchargeOrDefault() external {
        uint256 deposit = 10_000 * oneScale;
        vm.prank(owner);
        cdoEpoch.setIsInterestMinted(false);          // cash-pull mode (default)
        idleCDO.depositAA(deposit);
        _startEpochAndCheckPrices(0);                 // epoch running; funds parked in vault

        // Honest borrower draws nothing; contractual interest ~ 0.
        uint256 baselineInterest = programmableBorrower.totalInterestDueNow();

        // Attacker (any EOA): buy vault shares and push them onto ProgrammableBorrower.
        address attacker = makeAddr("attacker");
        uint256 donation = 5_000 * oneScale;          // D
        deal(USDC, attacker, donation);
        vm.startPrank(attacker);
        IERC20(USDC).approve(address(vault), donation);
        uint256 shares = vault.deposit(donation, attacker);
        IERC20(address(vault)).transfer(address(programmableBorrower), shares);
        vm.stopPrank();

        uint256 inflated = programmableBorrower.totalInterestDueNow();
        assertApproxEqAbs(inflated, baselineInterest + donation, 3);

        // Warp past epochEndDate, drain instant pendings per harness, then:
        // Case A: borrower wallet has >= D liquid -> vm.prank(owner) cdoEpoch.stopEpoch(0,0)
        //   pulls `inflated` cash; assert USDC.balanceOf(borrower) decreased by ~donation
        //   beyond contractual interest owed (i.e., stolen).
        // Case B: borrower balance < D -> same call hits getFundsFromBorrower revert ->
        //   _handleBorrowerDefault; assert defaultedEpoch == true and BB price absorbed
        //   the fabricated loss.
    }
}
```
Run on a mainnet/test fork reusing the existing `ProgrammableBorrowerCreditVault.t.sol` setup (real `vault`, `idleCDO`, `revolvingBorrower`). No Foundry cheat on accounting is needed — the inflation vector is a plain ERC20 share transfer.
