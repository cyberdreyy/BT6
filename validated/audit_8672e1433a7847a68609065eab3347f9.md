### Title
Unbounded Stale Data Accepted by `MetaOracle` Due to Relative-Only Timestamp Freshness Check — (`File: crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

`meta_oracle::combine` validates oracle data freshness using only a relative comparison between oracle timestamps (`max_timestamp - time_window_ms`), with no reference to the current on-chain clock. Additionally, `add_simple_oracle` does not track the true maximum timestamp — it unconditionally overwrites `max_timestamp` with each successive oracle's timestamp. Together, these two flaws allow arbitrarily old price data to pass the freshness gate whenever all contributing oracles have stopped updating, which is the exact "both oracles broken/untrusted → stale last-good-price returned" root cause from the external report, transposed into the Sui oracle framework.

---

### Finding Description

**Bug 1 — `add_simple_oracle` does not track the maximum timestamp** [1](#0-0) 

`max_timestamp` is unconditionally overwritten with each oracle's timestamp. If three oracles are added with timestamps `[T_old, T_mid, T_new]` in any order, `max_timestamp` ends up as the *last-added* oracle's timestamp, not the largest. Adding them in decreasing order (`T_new`, `T_mid`, `T_old`) leaves `max_timestamp = T_old`, the minimum, making `min_timestamp` even lower and widening the acceptance window further.

**Bug 2 — `combine` performs a relative-only freshness check with no `Clock` reference** [2](#0-1) 

`min_timestamp = max_timestamp - time_window_ms` is derived entirely from oracle-stored timestamps. Neither `combine` nor its only caller `median` accepts a `sui::clock::Clock` parameter: [3](#0-2) 

Contrast this with `simple_oracle::submit_data`, which correctly uses `clock::timestamp_ms(clock)` to record the wall-clock time of submission: [4](#0-3) 

Because `combine` never compares against the current time, if every oracle operator stops submitting updates (network outage, key compromise, coordinated downtime), all stored data — regardless of how old — passes the check `data::timestamp(&oracle_data) > min_timestamp`, since `min_timestamp` is anchored to the stale data itself.

---

### Impact Explanation

Any on-chain protocol that calls `meta_oracle::median` to obtain a trusted price (as demonstrated in the reference test module) will silently receive an arbitrarily stale price when all oracle operators are offline: [5](#0-4) 

The `assert!(vector::length(&values) >= threshold, ...)` guard only checks that enough oracles responded — it does not check that any of them are fresh. A DeFi protocol using this module for collateral valuation, liquidation triggers, or swap pricing would operate on a price that may be hours, days, or weeks old, enabling incorrect liquidations, under-collateralized borrows, or arbitrage extraction against the stale price. This matches the "harmful smart-contract behavior" impact class (High/Medium) in the allowed-impact gate.

---

### Likelihood Explanation

The trigger requires no privileged access. Any ordinary caller can invoke `meta_oracle::median` on a `MetaOracle` object whose contributing `SimpleOracle` objects have not been updated. Oracle liveness depends entirely on off-chain operators; a network partition, key rotation failure, or coordinated outage of all oracle operators is a realistic scenario. The bug is latent in every deployment of this module and activates automatically once oracle updates cease.

---

### Recommendation

1. **Pass `&Clock` to `combine` and `median`** and assert `data::timestamp(&oracle_data) + max_age_ms > clock::timestamp_ms(clock)` for each accepted data point, where `max_age_ms` is a configurable staleness bound.

2. **Fix `add_simple_oracle` to track the true maximum**: replace the unconditional assignment with a conditional update:
   ```move
   let ts = data::timestamp(option::borrow(&oracle_data));
   if (ts > meta_oracle.max_timestamp) {
       meta_oracle.max_timestamp = ts;
   };
   ```
   Even after this fix, the absolute clock check (point 1) is still required.

3. **Abort rather than silently succeed** when fewer than `threshold` fresh data points exist, which the current code already does via `assert!` — but the assert is only reached after the stale data has already been accepted.

---

### Proof of Concept

```move
// Setup: three SimpleOracle objects last updated at epoch T_stale (e.g., 7 days ago).
// No oracle operator has submitted new data since then.
// Current clock time: T_now = T_stale + 7_days_in_ms.

let mut meta = meta_oracle::new<u64>(
    3,           // threshold: need 3 oracles
    60_000,      // time_window_ms: 60 seconds
    string::utf8(b"SUIUSD")
);

// All three oracles have timestamp T_stale.
meta_oracle::add_simple_oracle(&mut meta, oracle1); // max_timestamp = T_stale
meta_oracle::add_simple_oracle(&mut meta, oracle2); // max_timestamp = T_stale (overwritten)
meta_oracle::add_simple_oracle(&mut meta, oracle3); // max_timestamp = T_stale (overwritten)

// combine() computes: min_timestamp = T_stale - 60_000
// Each oracle's timestamp T_stale > T_stale - 60_000  → all three pass.
// assert!(3 >= 3) passes.
// median() returns the 7-day-old price with no error.
let trusted = meta_oracle::median(meta);
// trusted.value is the price from 7 days ago — accepted as "trusted".
```

The call succeeds and returns stale data. No `Clock` is consulted at any point in `combine` or `median`, so the current wall-clock time `T_now` is never compared against `T_stale`.

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
