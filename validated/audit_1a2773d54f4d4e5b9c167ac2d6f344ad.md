## Title
Unregistered shareholder disabling direct-coin-transfers can permanently brick `vesting::distribute`/`terminate_vesting_contract` payouts for all co-shareholders - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute` iterates over every shareholder in the grant pool and calls `aptos_account::deposit_coins` for each one in a single atomic transaction, with no per-shareholder error isolation. [1](#0-0) 
`deposit_coins` only checks `can_receive_direct_coin_transfers` when the recipient does not yet have a registered `CoinStore` for the coin type; that check aborts the whole transaction if the flag is disabled. [2](#0-1) 
Because `create_vesting_contract` never requires shareholders (only the `withdrawal_address`) to be pre-registered for APT, a shareholder can remain unregistered and, without needing any privileged role, call `aptos_account::set_allow_direct_coin_transfers(false)` on their own account to make every future `distribute()` call abort inside the shareholder loop. [3](#0-2) 

### Finding Description
1. `create_vesting_contract` only asserts that `withdrawal_address` is registered for APT via `assert_account_is_registered_for_apt`; shareholders are added to `grant_pool` via `pool_u64::buy_in` with no such requirement. [4](#0-3) 
2. A shareholder whose account exists but has never called `coin::register<AptosCoin>` can call the unprivileged, permissionless entry function `aptos_account::set_allow_direct_coin_transfers(false)`, creating/updating their own `DirectTransferConfig` to disallow arbitrary coin transfers.
3. When `vest()`/lockup expiry make funds withdrawable, `distribute()` withdraws all coins and loops `shareholders.for_each_ref` calling `aptos_account::deposit_coins(recipient_address, share_of_coins)` for each shareholder (or its beneficiary, if set). [5](#0-4) 
4. Inside `deposit_coins`, since the target account already `exists_at` (so `create_account` is skipped) but is *not* registered for the coin, the function checks `can_receive_direct_coin_transfers` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the flag was disabled. [6](#0-5) 
5. Because Move transactions are atomic, this single failing deposit aborts the entire `distribute()` call, and since `terminate_vesting_contract` calls `distribute()` internally before unlocking remaining stake, that entry point is blocked too. [7](#0-6) 

This matches the proof idea exactly: with two shareholders in one vesting contract, one of them (unregistered, `allow_arbitrary_coin_transfers=false`) blocks `distribute()` for both, since the loop has no isolation and no skip-on-failure logic.

### Impact Explanation
This breaks the "Unlock, reactivate, withdraw... paths must not redirect value or strand it permanently" invariant: an unprivileged, uninvolved co-shareholder's stake and reward balance becomes unrecoverable through `distribute()`/`terminate_vesting_contract()` as long as the griefing shareholder's `DirectTransferConfig` remains disabled and their `CoinStore` remains unregistered. Value is not stolen but is strandable for the entire pool.

There is a partial admin mitigation: the vesting admin (or a `beneficiary_resetter` role holder) can call `set_beneficiary` to redirect the griefing shareholder's payout to a different address they control, which would let `deposit_coins` succeed (a beneficiary address chosen by the admin could be pre-registered for APT). This requires proactive privileged intervention and is not automatic — until it happens, every co-shareholder's vested/reward funds are frozen.

### Likelihood Explanation
Trivial and fully unprivileged: the attacker only needs to (a) be listed as a shareholder in the vesting contract (which the vesting admin controls at creation time, so this could also be a malicious/compromised shareholder added innocuously) and (b) never register a `CoinStore` for AptosCoin, then call `set_allow_direct_coin_transfers(false)` — a standard entry function anyone can call on their own account. No governance, operator, or admin role is needed to trigger the DoS.

### Recommendation
- In `vesting::distribute`, wrap each per-shareholder deposit so that a failure for one shareholder does not abort the whole distribution (e.g., use `coin::deposit`/direct `CoinStore` writes guarded by pre-registration checks, or catch/skip failures and retain undistributed coins for later retry to just that shareholder).
- Alternatively, require shareholders (like `withdrawal_address`) to be registered for APT (or have direct transfers enabled) at `create_vesting_contract` time, and/or re-validate this invariant before allowing an already-created shareholder to disable direct transfers while unclaimed vesting shares exist.
- Consider having `deposit_coins` used by `vesting::distribute` bypass the opt-out check entirely (similar to how genesis/system flows handle registration), since this is a pre-agreed vesting payout rather than an arbitrary/unsolicited transfer.

### Proof of Concept
1. Admin creates a vesting contract with two shareholders, `shareholder_1` and `shareholder_2`, via `create_vesting_contract` (or `setup_vesting_contract`) with non-zero buy-ins for each; neither shareholder is required to have a `CoinStore` for APT registered. [8](#0-7) 
2. `shareholder_1` never calls `coin::register<AptosCoin>` and calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own account (a standard, unprivileged transaction).
3. Validator joins the pool, stake earns rewards; call `vest(contract_address)` and `stake::fast_forward_to_unlock(stake_pool_address)` (mirroring `test_end_to_end`'s flow). [9](#0-8) 
4. Call `distribute(contract_address)`. The loop reaches `shareholder_1` and calls `aptos_account::deposit_coins(shareholder_1_address, share_of_coins)`, which hits the `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` abort since `shareholder_1`'s `CoinStore` isn't registered and their `DirectTransferConfig.allow_arbitrary_coin_transfers == false`. [10](#0-9) 
5. The entire `distribute()` transaction aborts, so `shareholder_2`'s vested/reward funds also remain undistributed and stuck in the stake pool; `terminate_vesting_contract` also fails since it calls `distribute` first.

Note: I could not fully verify the exact bytecode/text of `set_allow_direct_coin_transfers`/`can_receive_direct_coin_transfers` function bodies in this indexed snapshot (lines beyond 150 in `aptos_account.move` were not available in the index), but their behavior is corroborated by the module's spec file describing the same abort condition and by the `deposit_coins` logic shown above. [11](#0-10)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
