### Title
Cross-Module Publisher Bypass in `claim` Allows Co-Publisher to Steal `DisplayCap<T>` — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

### Summary

`display_registry::claim` accepts any `LegacyDisplay<T>` by value without verifying that it was created by the publisher of the module that defines `T`. Because `display::new<T>` only enforces a **package-level** check (`from_package<T>()`), any co-publisher in the same package can fabricate a `LegacyDisplay<M2::Foo>` using M1's `Publisher` and then call `claim` to permanently seize `DisplayCap<M2::Foo>` before the legitimate owner does.

### Finding Description

**Step 1 — Legacy display creation uses only a package-level check.**

`display::new<T>` calls `is_authorized<T>(pub)`: [1](#0-0) 

which delegates to: [2](#0-1) 

`from_package<T>()` only compares the package address of `T` against `self.package`. It does **not** check the module name. So M1's `Publisher` (with `package = <addr>`) passes `from_package<M2::Foo>()` as long as M2 lives in the same package.

**Step 2 — `claim` performs no publisher or provenance check.** [3](#0-2) 

The only guard is `display.cap_id.is_none()`. There is no assertion that the `LegacyDisplay<T>` was produced by the publisher of the module that defines `T`. Any `LegacyDisplay<T>` object — regardless of which co-publisher created it — is accepted.

**Step 3 — `system_migration` creates `Display<T>` with `cap_id = none()`.** [4](#0-3) 

This is the exact precondition the attacker needs: a shared `Display<M2::Foo>` with an unclaimed cap slot.

**Step 4 — `claim_with_publisher` (the safe path) also only checks `from_package`.** [5](#0-4) 

So even the publisher-gated path does not enforce module-level ownership.

### Impact Explanation

Once the attacker calls `claim`, `display.cap_id` is permanently filled with the attacker's cap ID. The legitimate owner of M2::Foo can never call `claim` or `claim_with_publisher` again (both abort on `ECapAlreadyClaimed`). The attacker holds the sole `DisplayCap<M2::Foo>` and can call `set`, `unset`, and `clear` to inject arbitrary display metadata (image URLs, names, descriptions) for M2::Foo objects across all wallets and explorers that consume the V2 display registry. This is permanent, irreversible state corruption of the display object.

### Likelihood Explanation

The attack is executable in a single transaction by anyone who:
1. Published (or received via transfer) a `Publisher` for any module in the same package as the target type, and
2. Acts before the legitimate owner claims their cap.

`Publisher` has `key, store` and is freely transferable, so the attacker need not be the original package deployer.

### Recommendation

Replace the package-level `from_package` check in `display::is_authorized` (and in `claim_with_publisher`) with a module-level check using `from_module<T>()`: [6](#0-5) 

Alternatively, add a `publisher: &Publisher` parameter to `claim` and assert `publisher.from_module<T>()` before accepting the legacy object.

### Proof of Concept

```
1. Publish package P containing:
   - module m1 { struct M1OTW has drop {}; fun init(otw: M1OTW, ctx) { package::claim_and_keep(otw, ctx) } }
   - module m2 { struct Foo has key { id: UID } }

2. Attacker holds Publisher for m1 (package = addr(P)).

3. System migration runs: Display<m2::Foo> { cap_id: none() } is shared.

4. Attacker calls:
     let legacy = display::new<m2::Foo>(&m1_publisher, ctx);
     // passes: from_package<m2::Foo>() == true (same package addr)

5. Attacker calls:
     let cap = display_registry::claim(&mut display_m2_foo, legacy, ctx);
     // passes: cap_id.is_none() == true, no further check

6. Attacker now holds DisplayCap<m2::Foo>.
   display_m2_foo.cap_id == some(cap.id).
   Legitimate m2 owner can never claim; ECapAlreadyClaimed on every attempt.
```
