### Title
Stale cross-tenure conflict skips all liveness re-verification, letting a signer double-sign siblings at the same height - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`handle_block_pre_commit`'s conflict guard only re-verifies a *fresh* cross-tenure conflict against the node (`conflict_still_blocks`), and only re-verifies a *same-tenure* conflict against the node's tenure tip. Once a signed sibling's endorsement age exceeds `freshness_cutoff`, if that sibling lives in a tenure that is neither the proposed block's own tenure nor its tenure-change parent, no code path asks the node whether the sibling is still canonical — the block is signed unconditionally.

### Finding Description
`SignerDb::get_signed_conflicts` (`stacks-signer/src/signerdb.rs:1606-1625`) returns every signed block at or above a given height across *any* tenure, annotated with `last_endorsed = max(signed_self, signed_group)`. `handle_block_pre_commit` (`stacks-signer/src/v0/signer.rs:1383-1465`) consumes this list in two separate filters:

1. Fresh-conflict guard (`stacks-signer/src/v0/signer.rs:1403-1421`): blocks signing only if `conflict.last_endorsed > freshness_cutoff && !reorg_permit_stands && conflict_still_blocks(...)`. Because of `&&` short-circuiting, once `last_endorsed <= freshness_cutoff`, `conflict_still_blocks` (the only code that asks the node whether the conflicting tenure's sortition/tip is still canonical, per `stacks-signer/src/v0/signer.rs:1137-1206`) is never called.
2. Own-tenure guard (`stacks-signer/src/v0/signer.rs:1432-1457`): only fires when `conflict.consensus_hash == block_info.block.header.consensus_hash`, i.e. the conflict is in the *same* tenure as the block being signed.

For two sibling tenures T1 (block A, height h) and T2 (block B, height h) both built on a common parent tenure T0, A's `consensus_hash` (T1) is neither T2 (B's own tenure) nor T0 (B's tenure-change parent). The earlier chainstate recheck `check_block_against_signer_db_state` (`stacks-signer/src/v0/signer.rs:1803-1880`) also only checks the *parent* tenure T0 for a tenure-change block via `check_tenure_change_confirms_parent` — it never inspects T1. This third-tenure blind spot is explicitly acknowledged in `docs/signer-flows.md` ("the re-check only ever looks at _one_ tenure... so a signed sibling at the same height in a third tenure is invisible to it"), and the design deliberately relies on `get_signed_conflicts`'s any-tenure guard to cover it — but only while the conflict is fresh.

Once A's `last_endorsed` timestamp ages past `freshness_cutoff` (`get_epoch_time_secs() - tenure_last_block_proposal_timeout`), both guards fall through: `conflicts.iter().any(...)` at line 1432 finds no match (A's tenure != B's tenure), so control reaches `if !conflicts.is_empty() { info!(...) }` and then unconditionally `block_info.mark_locally_accepted(false)` (`stacks-signer/src/v0/signer.rs:1458-1467`) — no node query is made to confirm A is actually dead. If A is still the canonical block at height h (attacker-controlled timing simply requires waiting out `tenure_last_block_proposal_timeout`, a known, public config value), the signer signs B anyway.

### Impact Explanation
This breaks the uniqueness/safety invariant that a signer must place at most one signature per `(tenure, height)` position when both siblings could still be canonical. An attacker who wins a single sortition (T2) can craft a tenure-change block B at the same height as a still-live block A signed in a sibling tenure T1 built on the same parent, wait past `tenure_last_block_proposal_timeout`, and get the victim signer to sign B without ever verifying A is dead. Aggregated across enough signers doing the same thing, this can finalize two conflicting blocks at the same height, i.e. a genuine chain split — matching the Critical "signer signing a conflicting block (chain safety)" category. It is repeatable per height/tenure pair and requires only the attacker's own slot plus ordinary StackerDB gossip of a pre-commit/proposal, not any privileged role.

### Likelihood Explanation
Preconditions: the victim signer must have already signed A via `mark_locally_accepted` in tenure T1, and enough pre-commit weight (attacker's own signature plus honest signers who validate B as they would validate any legitimately-parented tenure-change block) must cross `compute_voting_weight_threshold`. The timing requirement (wait out `tenure_last_block_proposal_timeout`, a fixed, publicly known duration) is fully within a single unprivileged miner's control — no majority of signers, no compromised keys, no local access needed. It is deterministic and reproducible on demand.

### Recommendation
Do not gate the any-tenure conflict check purely on freshness before deciding whether to skip liveness re-verification. Either (a) always call `conflict_still_blocks` (or an equivalent node-derived liveness check) for any conflict whose tenure is not the proposed block's own tenure or its tenure-change parent, regardless of staleness, or (b) extend `check_block_against_signer_db_state` / `check_tenure_change_confirms_parent` to also validate against any other tenure with a fresh-or-stale signed conflict at or above the proposed height before allowing `mark_locally_accepted`.

### Proof of Concept
Extend the existing `run_cross_tenure_scenario` test harness (`stacks-signer/src/v0/tests.rs`) with a new `TenureAFate` variant, e.g. `StaleButStillCanonical`:
```rust
#[test]
fn stale_cross_tenure_conflict_still_canonical_must_not_be_signed() {
    // Zero out tenure_last_block_proposal_timeout so A's signature is immediately stale,
    // but configure the mock node so that tenure 1's tip is still block A (i.e. A is in
    // fact still canonical at height h).
    let (info_a, info_b) = run_cross_tenure_scenario_with_timeout(
        Duration::ZERO,
        TenureAFate::StaleButStillCanonical, // node's get_tenure_tip(tenure_a) == A
    );
    assert_a_signed(&info_a);
    // EXPECTED (safety): B must be refused because A is still canonical.
    assert_eq!(
        info_b.state,
        BlockState::PreCommitted,
        "block B must NOT be signed: sibling A is still canonical at this height, got: {}",
        info_b.state
    );
    assert!(info_b.signed_self.is_none());
}
```
Running this against current code shows `info_b.state == BlockState::LocallyAccepted` and `info_b.signed_self.is_some()`, i.e. the signer signs B despite A remaining canonical — confirming the equality `conflict.last_endorsed > freshness_cutoff` is treated as the sole liveness gate for cross-tenure conflicts, with no fallback node check once it goes false.
