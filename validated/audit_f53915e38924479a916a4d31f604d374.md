### Title
Zip archive extraction lacks path-traversal (Zip Slip) protection allowing writes outside the job workspace - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile`, `extractZipFileEntry`, `extractZipDirectoryEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` use `file.Name` from the ZIP archive directly with `os.MkdirAll`, `os.OpenFile`, `os.Mkdir`, and `os.Symlink` without validating that the resolved path stays within the extraction root. The only path check present, `errorIfGitDirectory`, only rejects `.git` paths, not `../` traversal segments.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry [1](#0-0) . `extractZipFile` does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`, all of which use `file.Name` verbatim as the destination path passed to `os.OpenFile`, `os.Mkdir`, or `os.Symlink` [2](#0-1) . There is no `filepath.Clean`, no check that the final path is rooted under the current working directory, and no rejection of `..` segments anywhere in this file. The only sanitization applied is `errorIfGitDirectory`, which only blocks paths whose first component is `.git` [3](#0-2) [4](#0-3) . This function is reachable from `ExtractZipFile` (used by CLI helpers) and from the legacy zip extractor `ziplegacy.extractor.Extract`, which is invoked by artifact/cache download commands (`commands/helpers/artifacts_downloader.go`, `commands/helpers/cache_extractor.go`) that operate on job-controlled artifact/cache archive content [5](#0-4) .

An attacker who controls the contents of a ZIP artifact or cache (e.g., a job that generates its own `artifacts:paths` output and later a different/attacker-controlled job or step downloads/extracts it, or a job that supplies a crafted `.zip` for `artifacts-downloader`) can name a `zip.File` entry `../../../../home/gitlab-runner/.bashrc` (or any absolute-like relative traversal). `filepath.Dir` on that name still yields a `../../../home/gitlab-runner` path, which `os.MkdirAll` will happily create outside the working directory, and the subsequent `os.OpenFile`/`os.Symlink` write will land there.

Whether this is truly exploitable to escalate beyond "the job's own filesystem access" depends on execution context: for the `shell` executor this writes into arbitrary paths reachable by the OS user running the job (already a documented shell-executor trust boundary), while for containerized executors (docker/kubernetes) the write is confined to the container filesystem the job process already controls, so no privilege escalation across job/project boundaries. The functions have no built-in root confinement, so the invariant "file operations must stay within intended build/cache/artifact roots" is violated at the code level, but the audit rules explicitly instruct rejecting "shell executor trust on a shared host" as a documented insecure admin choice, and for other executors the attacker already has equivalent write access within their own job's sandbox — extracting a traversal ZIP does not grant access to another job, project, or executor sandbox escape beyond what the job already has.

### Impact Explanation
Within a single job's own execution context (its own container or its own shell-executor user), an attacker-controlled zip can write files to arbitrary paths reachable by that job's process, e.g., overwriting files elsewhere in the job's own filesystem tree outside the intended artifact/cache directory. This does not, by itself, grant access to another job's workspace, another project, or escape the executor's sandbox on containerized executors, because the writable filesystem is already the same one the job process can access directly (e.g., via a normal script). On shell executors sharing a host, this could write to the runner user's home directory (e.g. `.bashrc`) affecting subsequent jobs on that same shared runner — but that scenario matches the excluded case of "shell executor trust on a shared host" per the audit rules.

### Likelihood Explanation
Trivial to construct: any pipeline author can create a job that produces or downloads a crafted ZIP (as an artifact or cache) with a traversal-containing entry name, since `zip.Writer.Create` does not itself prevent arbitrary names. Reaching `ExtractZipArchive` only requires that the artifact/cache be later extracted by the runner-provided helper (`artifacts-downloader`, `cache-extractor`), which happens automatically for any job that declares `artifacts:paths`/`cache` and a dependent job/stage that consumes it.

### Recommendation
In `extractZipFile`/`extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`, resolve `file.Name` against the extraction root with `filepath.Clean`/`filepath.Join`, then verify (e.g., via `filepath.Rel` or a prefix check after `filepath.EvalSymlinks`) that the resulting path does not escape the intended root before performing any `MkdirAll`/`OpenFile`/`Mkdir`/`Symlink` operation; reject or skip entries that fail this check, consistent with how the existing `errorIfGitDirectory` mechanism is already wired into `ExtractZipArchive`'s per-file error path.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    origWD, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(origWD)

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    f, err := zw.Create("../evil.txt")
    require.NoError(t, err)
    _, err = f.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = ExtractZipArchive(zr)
    require.NoError(t, err)

    escaped := filepath.Join(tmpDir, "..", "evil.txt")
    _, statErr := os.Stat(escaped)
    assert.NoError(t, statErr, "file was written outside extraction root")
    _ = os.Remove(escaped)
}
```
Expected (current) behavior: `evil.txt` is created one directory above `tmpDir`, demonstrating the missing path-confinement check. A fix should make this test fail to create the file outside `tmpDir` (or return an actionable error instead).

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
