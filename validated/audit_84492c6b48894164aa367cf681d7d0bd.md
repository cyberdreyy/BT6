### Title
Stale node responses for a cleaned-up requestID can be delivered to an unrelated workflow's caller when the requestID is reused - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`HandleNodeTriggerResponse` looks up the callback purely by the client-chosen string `resp.ID` in the global `h.callbacks` map, with no generation/epoch binding to the specific registration that dispatched the outbound request. Because `cleanupCallback` only closes `doneCh` (which merely stops future retries, not in-flight `SendToNode` calls) and deletes the map entry, a late response for a just-completed request can be matched against a brand-new `savedCallback` that reused the same `requestID` for a different workflow, delivering the wrong workflow's node-response payload to the wrong caller.

### Finding Description
`setupCallback` stores callbacks keyed only by `requestID` in `h.callbacks` [1](#0-0) , and once the entry is removed via `delete(h.callbacks, requestID)` in `cleanupCallback` [2](#0-1) , the same `requestID` string is immediately available for reuse by a completely unrelated subsequent `HandleUserTriggerRequest` call (e.g., a different workflow), which will pass the `found` check in `setupCallback` and register a fresh `savedCallback` under that identical key.

`sendWithRetries`/`sendToShard` fan a request out across all shards a workflow is assigned to in parallel goroutines, and only the *retry loop* is gated by `doneCh`; an already-dispatched `shard.connMgr.SendToNode` call for a slower shard has no cancellation tied to `doneCh` (its context is derived from the overall `MaxTriggerRequestDurationMs` timeout, not from cleanup) [3](#0-2) . So after one shard wins quorum and `cleanupCallback` fires, other shards' node responses for the *same* original request can still arrive over the network afterward.

When they do, `HandleNodeTriggerResponse` looks up `h.callbacks[resp.ID]` and only additionally validates that the responding node's shard `donID` is present in `saved.responseAggregators` [4](#0-3) . It never verifies that the response actually belongs to the same workflow/registration instance that originally requested it — there is no per-registration nonce, workflowID check, or epoch counter. If the reused `requestID`'s new registration (workflowB) happens to be assigned to the same shard `donID` as the old one (workflowA), the late, genuine, identical-content node responses from workflowA's slow shard (which were all mutually identical by design of `IdenticalNodeResponseAggregator`) get fed into workflowB's fresh aggregator via `agg.CollectAndAggregate` [5](#0-4) . If enough of them arrive before/along workflowB's own quorum forms (or the shard's `threshold` is met by them alone, e.g., small single-node shards), `saved.SendResponse` is invoked with workflowA's payload but delivered to workflowB's registered `Callback` [6](#0-5) .

### Impact Explanation
This is a cross-workflow response confusion: workflowB's caller can receive workflowA's actual node execution result payload instead of (or mixed with/blocking) their own. This corresponds to the "attacker-controlled/unrelated data returned to another user" bounty class — a caller receives another workflow's trigger response data due to lack of per-registration isolation beyond the raw string ID.

### Likelihood Explanation
The precondition is a requestID collision between two sequential registrations (the reused ID must belong to the same shard-assignment set), plus a timing race where a slower shard's in-flight response for the old registration arrives after cleanup but reaches the new registration's aggregator threshold. Because `requestID` is entirely client-chosen and there is no per-caller/per-owner namespacing enforced beyond an in-flight uniqueness check, an attacker who can predict or intentionally reuse IDs (their own sequential/low-entropy scheme, or exploiting the lack of namespacing between distinct authorized workflows) can increase the likelihood, especially for small shard configurations where `threshold` is low. It requires precise timing and shared shard assignment, making it a real but non-trivial-to-hit race rather than a trivially repeatable attack in all deployments.

### Recommendation
Bind responses to a specific registration instance rather than the raw client-chosen `requestID` alone: generate an internal unique registration token/epoch (e.g., `requestID` + monotonically-increasing counter or UUID) used as the map key and echoed in the outbound node request so `HandleNodeTriggerResponse` can verify the response corresponds to the currently-registered instance before aggregating; alternatively, retain a short-lived tombstone for cleaned-up `requestID`s and reject/log any node response addressed to a tombstoned ID whose registration instance doesn't match.

### Proof of Concept
Go unit test plan in `http_trigger_handler_test.go`:
1. Set up a handler with two shards sharing a common shard/donID, threshold=1 for simplicity.
2. Register request1 (requestID="X", workflowA) via `setupCallback`, obtain its `savedCallback.responseAggregators`.
3. Manually invoke `cleanupCallback("X")` to simulate quorum being reached by another shard (do not actually feed the shared shard's aggregator).
4. Register request2 (requestID="X", workflowB) via `setupCallback` (asserts it succeeds since the old entry was deleted).
5. Call `handler.HandleNodeTriggerResponse(ctx, resp, nodeAddrBelongingToSharedShard)` using a response payload representative of workflowA's execution result.
6. Assert via the callback captured for workflowB (`callback2.Wait`) whether it receives workflowA's payload — expected secure behavior: the response should be rejected (error returned, no delivery) because it doesn't belong to workflowB's registration; current behavior: `callback2` receives workflowA's raw response, demonstrating the isolation violation.

func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}

func (h *httpTriggerHandler) sendToShard(ctx context.Context, shard *shardEndpoint, legacyExecutionID, executionIDWithTriggerIndex string, req *jsonrpc.Request[json.RawMessage], doneCh <-chan struct{}) error {
	nodeTimeout := time.Duration(h.config.NodeSendTimeoutMs) * time.Millisecond

	successfulNodes := make(map[string]bool)
	b := backoff.Backoff{
		Min:    time.Duration(h.config.RetryConfig.InitialIntervalMs) * time.Millisecond,
		Max:    time.Duration(h.config.RetryConfig.MaxIntervalTimeMs) * time.Millisecond,
		Factor: h.config.RetryConfig.Multiplier,
		Jitter: true,
	}

	for {
		var pending []string
		for _, member := range shard.members {
			if !successfulNodes[member.Address] {
				pending = append(pending, member.Address)
			}
		}

		// Buffered so every goroutine can send its result and exit without waiting on a reader.
		results := make(chan nodeSendResult, len(pending))
		var wg sync.WaitGroup
		for _, nodeAddress := range pending {
			wg.Add(1)
			go func(nodeAddress string) {
				defer wg.Done()

				nodeCtx, nodeCancel := context.WithTimeout(ctx, nodeTimeout)
				defer nodeCancel()

				h.metrics.IncrementTriggerCapabilityRequestCount(ctx, nodeAddress, gateway_common.MethodWorkflowExecute, h.lggr)
				sendStart := time.Now()
				err := shard.connMgr.SendToNode(nodeCtx, nodeAddress, req)
				h.metrics.RecordGatewayToNodeLatency(ctx, time.Since(sendStart).Milliseconds(), nodeAddress, gateway_common.MethodWorkflowExecute, h.lggr)
				if err != nil {
					h.metrics.IncrementTriggerCapabilityRequestFailures(ctx, nodeAddress, gateway_common.MethodWorkflowExecute, h.lggr)
				}
				results <- nodeSendResult{nodeAddress: nodeAddress, err: err}
			}(nodeAddress)
		}
		wg.Wait()
		close(results)

		// Only this goroutine reads from results, so successfulNodes and combinedErr need no locking.
		var combinedErr error
		for res := range results {
			if res.err != nil {
				combinedErr = errors.Join(combinedErr, fmt.Errorf("node %s: %w", res.nodeAddress, res.err))
				h.lggr.Debugw("Failed to send trigger request to node, will retry",
					"node", res.nodeAddress,
					"shard", shard.donID,
					"legacyExecutionID", legacyExecutionID,
					"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
					"error", res.err)
			} else {
				successfulNodes[res.nodeAddress] = true
			}
		}

		if len(successfulNodes) == len(shard.members) {
			h.lggr.Infow("Successfully sent trigger request to all nodes in shard",
				"shard", shard.donID,
				"legacyExecutionID", legacyExecutionID,
				"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
				"nodeCount", len(shard.members))
			return nil
		}

		// Not all nodes succeeded, wait and retry
		h.lggr.Debugw("Retrying failed nodes for trigger request",
			"shard", shard.donID,
			"legacyExecutionID", legacyExecutionID,
			"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
			"failedCount", len(shard.members)-len(successfulNodes),
			"errors", combinedErr)

		select {
		case <-doneCh:
			h.lggr.Infow("Callback already responded to, stopping retries",
				"shard", shard.donID,
				"legacyExecutionID", legacyExecutionID,
				"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
				"requestID", req.ID,
				"successNodes", len(successfulNodes),
				"totalNodes", len(shard.members))
			return nil
		case <-time.After(b.Duration()):
			continue
		case <-ctx.Done():
			return fmt.Errorf("shard %s: request retry time exceeded, some nodes may not have received the request: legacyExecutionID=%s, executionIDWithTriggerIndex=%s, successNodes=%d, totalNodes=%d",
				shard.donID, legacyExecutionID, executionIDWithTriggerIndex, len(successfulNodes), len(shard.members))
		}
	}

func (agg *IdenticalNodeResponseAggregator) CollectAndAggregate(
	resp *jsonrpc.Response[json.RawMessage],
	nodeAddress string) (*jsonrpc.Response[json.RawMessage], error) {
	if resp == nil {
		return nil, errors.New("response cannot be nil")
	}
	if nodeAddress == "" {
		return nil, errors.New("node address cannot be empty")
	}

	key, err := resp.Digest()
	if err != nil {
		return nil, fmt.Errorf("error generating digest for response: %w", err)
	}

	// Check if the node already submitted a different response
	if oldKey, exists := agg.nodeToResponse[nodeAddress]; exists && oldKey != key {
		if nodes, ok := agg.responses[oldKey]; ok {
			nodes.Remove(nodeAddress)
			// Clean up empty response groups
			if len(nodes) == 0 {
				delete(agg.responses, oldKey)
			}
		}
	}

	if _, ok := agg.responses[key]; !ok {
		agg.responses[key] = make(StringSet)
	}
	agg.responses[key].Add(nodeAddress)
	agg.nodeToResponse[nodeAddress] = key

	if len(agg.responses[key]) >= agg.threshold {
		return resp, nil
	}

	return nil, nil
