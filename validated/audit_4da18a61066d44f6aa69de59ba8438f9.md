### Title
Stale-price check in `getChainlinkPrice` reverts at heartbeat boundary, blocking `stopEpoch`/`startEpoch` and freezing withdrawals - ([File: contracts/strategies/usual/IdleUsualStrategy.sol])

### Summary
`IdleUsualStrategy.getChainlinkPrice()` enforces a strict `updatedAt > block.timestamp - 24 hours` staleness check against the USD0++ Chainlink feed, which itself has a 24-hour heartbeat. When the feed's `updatedAt` is exactly 24h old (or if Chainlink delays an update past the heartbeat), the call reverts. Both `startEpoch` and `stopEpoch` in `IdleCDOUsualVariant` call `getChainlinkPrice()`, so epoch transitions — and therefore withdrawals, which remain disabled until `stopEpoch` flips `allowAAWithdraw`/`allowBBWithdraw` — are temporarily bricked for as long as the price is stale.

### Finding Description
In `contracts/strategies/usual/IdleUsualStrategy.sol` lines 163-172:

```solidity
function getChainlinkPrice() public view returns (uint256) {
    // Oracle it is not updated frequently but only if there is a deviation of 50 bips from
    // the last reported value.There is also a 24 hours hearbeat. So we check that the last round
    // is not older than 24 hours
    (,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
    require(updatedAt > block.timestamp - 24 hours, "Stale price");
    return uint256(answer) * 1e10;
}
```

The staleness window is equal to (not greater than) the feed's heartbeat, and the comparison is strict `>`. At the exact moment a new round is due, `block.timestamp - updatedAt == 24 hours` and the check fails. Any keeper/Chainlink delay pushes the revert window arbitrarily long.

This function is invoked by `IdleCDOUsualVariant.startEpoch` (line 63) and, critically, by `stopEpoch` (line 77). `stopEpoch` is the only path that re-enables withdrawals (`allowAAWithdraw = true`, `allowBBWithdraw = true`, lines 80-83) and settles the senior tranche at par via `lastNAVAA` adjustment. There is no fallback: if the oracle is stale, `stopEpoch` reverts entirely, so once `epochEndDate` passes, lenders cannot withdraw even though the epoch has notionally ended — a temporary freeze of all tranche holders' funds lasting until the feed updates.

### Impact Explanation
Users' funds are frozen for the duration of oracle staleness beyond the epoch end. During the freeze, if USD0++ trades below $1 off-oracle, senior tranche holders cannot exit at the par-protected price the epoch design intends, and junior holders cannot exit at all. This mirrors the external report's class (staleness window vs. heartbeat mismatch causing reverts in user-facing flows) but on idle-tranches' own surface the impact lands on the epoch state machine rather than a single order — freezing the entire pool's withdrawals.

### Likelihood Explanation
Medium. The revert is guaranteed to occur in a window each heartbeat cycle: for any block where `block.timestamp - updatedAt >= 24 hours` — i.e., exactly when a round is due or delayed — both epoch functions revert. Whether it bites depends on whether `stopEpoch`/`startEpoch` is called inside that window. Since only the owner can call them and epochs are long, probability of hitting a stale window is low per epoch, but Chainlink heartbeat delays do occur. No attacker action is required; an unprivileged lender is only a victim here, which fits the "temporary freezing" acceptance criterion but reduces exploitability.

### Recommendation
Use a staleness tolerance strictly greater than the heartbeat, e.g. `require(updatedAt > block.timestamp - 26 hours)` or `25 hours`, and/or use `>=` consistently with a padded window. Alternatively, in `stopEpoch`, fall back to `IUSD0pp(USD0pp).getFloorPrice()` (already consulted in `setOraclePrice`, line 159) when the Chainlink round is stale, since the contract already treats the floor as a safe lower bound.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDOUsualVariant} from "../contracts/IdleCDOUsualVariant.sol";
import {IdleUsualStrategy} from "../contracts/strategies/usual/IdleUsualStrategy.sol";

contract StaleOracleStopEpoch is Test {
    // Fork mainnet at a block where USD0ppOracle.updatedAt is >= 24h old,
    // or mock the oracle to return updatedAt == block.timestamp - 24 hours.

    function testStopEpochRevertsOnStalePrice() public {
        IdleCDOUsualVariant cdo = IdleCDOUsualVariant(<CDO_ADDRESS>);
        IdleUsualStrategy strat = IdleUsualStrategy(cdo.strategy());
        address owner = cdo.owner();

        // 1. owner starts an epoch (succeeds while price is fresh)
        vm.prank(owner);
        cdo.startEpoch(7 days);

        // 2. warp past epochEndDate AND into a stale-oracle window:
        //    vm.mockCall on USD0ppOracle latestRoundData to return
        //    updatedAt = block.timestamp - 24 hours (boundary, strict > fails)
        vm.warp(block.timestamp + 7 days);
        vm.mockCall(
            strat.USD0ppOracle(),
            abi.encodeWithSelector(bytes4(keccak256("latestRoundData()"))),
            abi.encode(uint80(1), int256(1e8), block.timestamp, block.timestamp - 24 hours, uint80(1))
        );

        // 3. stopEpoch reverts: withdrawals stay disabled, funds frozen
        vm.prank(owner);
        vm.expectRevert("Stale price");
        cdo.stopEpoch();

        assertFalse(cdo.allowAAWithdraw());
        assertFalse(cdo.allowBBWithdraw());
    }
}
