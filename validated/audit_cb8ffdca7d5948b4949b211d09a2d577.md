### Title
Stale confirmations from removed multisig members count toward the approval threshold, allowing execution below required signatures - ([File: multisig2/src/lib.rs])

### Summary
`multisig2::MultiSigContract::confirm` counts entries in the `confirmations` set for a request and executes it once the count reaches `num_confirmations`, but it never re-validates that each confirming identity is still a current member at execution time. `delete_member` only purges requests *created by* the removed member; it does not scrub that member's confirmations from other still-pending requests they had merely co-signed. This is the same class of bug as the reported `store::validateIterator` issue: a completion/threshold check (`foundKeys`/`confirmations.len()`) is trusted without verifying it still matches the current authoritative set (`expectedKeys`/live `members`).

### Finding Description
`delete_member` removes the departing member from `self.members` and deletes only requests where `r.member == member` (i.e., requests they authored), clearing confirmations for those: [1](#0-0) 

It does not scan `self.confirmations` for entries where the removed member appears as a *confirmer* of someone else's still-open request. `confirm()` then blindly trusts the stored `confirmations` set size against the live `num_confirmations` threshold: [2](#0-1) 

`assert_valid_request` only checks that the caller is currently a member and that the request/confirmations records exist — it does not re-validate that previously recorded confirmers in the set are still members: [3](#0-2) 

The same pattern (confirmations not scrubbed for keys that merely confirmed, only for keys that authored) exists in the older `multisig` contract via `DeleteKey`: [4](#0-3) 

### Impact Explanation
This breaks the custody binding that a request is only executed once the number of *live, authorized* confirmations reaches `num_confirmations`. An attacker (or colluding remaining members) can get a stale confirmation counted from a member who has since been removed, causing a transfer, key-addition, or other privileged multisig action to execute with fewer than the configured threshold of currently valid signers. Per the stated impact criteria, "a multisig request executed below threshold" is Critical.

### Likelihood Explanation
Requires only ordinary multisig operations that any member can trigger (confirm a pending request, then vote to remove a different member via a separate self-request, then confirm again) — no owner/foundation privilege, redeploy, or external compromise is needed. The only constraint is timing: the confirming request must remain open (not deleted/executed) while the membership change happens, which is a normal and likely operational sequence (e.g. rotating a compromised or departing signer while other requests are in flight).

### Recommendation
When counting confirmations in `confirm()`, filter the stored `confirmations` set to only those entries still present in `self.members` before comparing against `num_confirmations` (mirroring the audit's remediation: "ensure the set of tracked/expected identities equals the set actually validated"). Additionally, `delete_member`/`DeleteKey` should scrub the removed identity from confirmation sets of *all* pending requests, not only ones they authored.

### Proof of Concept
1. Deploy `multisig2` with members `[A, B, C]`, `num_confirmations = 2`.
2. `A` calls `add_request` for a `Transfer` action (request R1, not yet confirmed).
3. `B` calls `confirm(R1)` → `confirmations = {B}`, count = 1, below threshold (2), request stays open.
4. Separately, members create and confirm a self-request `DeleteMember { member: B }` with 2 confirmations (e.g. `A` and `C`), executing `delete_member(B)`. This removes `B` from `self.members` and deletes only requests authored by `B` — R1 (authored by `A`) is untouched, and `confirmations[R1]` still contains `B`.
5. `C` calls `confirm(R1)`. `confirmations.len() + 1 = 2 >= num_confirmations (2)` → the transfer executes, even though only one currently-live member (`C`) actually approved it against the required 2-of-3 threshold.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************

            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);

    fn assert_valid_request(&mut self, request_id: RequestId) {
        // request must come from key added to contract account
        assert(
            self.current_member().is_some(),
            "Caller (predecessor or signer) is not a member of this multisig",
        );
        // request must exist
        assert(
            self.requests.get(&request_id).is_some(),
            "No such request: either wrong number or already confirmed",
        );
        // request must have
        assert(
            self.confirmations.get(&request_id).is_some(),
            "Internal error: confirmations mismatch requests",
        );
    }
