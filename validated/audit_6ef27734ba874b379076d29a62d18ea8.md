### Title
Signer's `capitulate_miner_view` adopts a minority (>30%) miner state as canonical instead of requiring the documented 70% agreement threshold - (File: `stacks-signer/src/v0/signer_state.rs`)

### Summary
`LocalStateMachine::capitulate_miner_view` is supposed to only switch a signer's local view of "who the current miner is / what tenure to build on" once a 70%-weight supermajority of signers report the same `StateMachineUpdateMinerState`. However, when the local signer's own `signerdb` already has *any* globally-accepted block recorded for the candidate tenure (`nmb_blocks > 0`), the code silently downgrades the required bar from `reached_agreement` (≥70%) to `reached_disagreement` (>30%, the "blocking minority" threshold), letting a colluding minority force a state-machine switch it should not be able to force alone.

### Finding Description
`capitulate_miner_view` tallies weighted votes for each distinct `StateMachineUpdateMinerState::ActiveMiner{..}` reported by peers via `StateMachineUpdate` messages: [1](#0-0) 

```
let entry = miners.entry(miner_state).or_insert(0);
*entry += weight;
if !eval.reached_disagreement(*entry) {
    // We don't even see a blocking minority threshold. Ignore.
    continue;
}

let nmb_blocks = signerdb
    .get_globally_accepted_block_count_in_tenure(tenure_id)
    .unwrap_or(0);
if nmb_blocks == 0 && !eval.reached_agreement(*entry) {
    continue;
}
```

`reached_agreement` requires ≥70% of total signer weight; `reached_disagreement` requires only >30% (the amount needed to *block* a 70% quorum, not to *form* one): [2](#0-1) 

The `if nmb_blocks == 0 && !eval.reached_agreement(*entry) { continue; }` guard means: as soon as `nmb_blocks > 0` (the local signerdb already holds ≥1 `GloballyAccepted` block for that `tenure_id`, from `get_globally_accepted_block_count_in_tenure`), the 70% requirement is skipped entirely and the code proceeds to evaluate/adopt that `miner_state` candidate with only >30% support: [3](#0-2) 

Crucially, `miner_state` is the *entire* struct — `current_miner_pkh`, `tenure_id`, `parent_tenure_id`, `parent_tenure_last_block`, `parent_tenure_last_block_height` — used as the HashMap key: [4](#0-3) 

`nmb_blocks > 0` only proves that *some* block in that tenure previously reached a legitimate 70% signature threshold; it says nothing about whether the *specific* `parent_tenure_last_block`/`parent_tenure_last_block_height`/`current_miner_pkh` tuple currently being voted on by the 30%-minority is correct. A colluding minority (>30% weight, well under a majority) reporting a divergent view of that same, already-partially-accepted tenure (e.g., a stale or forked `parent_tenure_last_block`) is enough to make the local signer accept and adopt that view as its new `current_miner`, once it also passes the `local_parent_tenure_last_block_height < *parent_tenure_last_block_height` and burn-block matching checks further down: [5](#0-4) 

This directly weakens the invariant the code's own documentation states is consensus-critical: [6](#0-5) 

> "The whole miner state, including `parent_tenure_last_block`, is the equality key for global agreement, so what this flow computes is consensus-visible."

The bug class mirrors the V3Oracle finding: a value gate (`reached_agreement`, the "validated" 70% price/oracle check) is bypassed based on an unrelated, spot/local, attacker-influenceable condition (`nmb_blocks`, computed purely from the signer's own local DB state for a possibly-unrelated block in the same tenure) — exactly like using the manipulable spot-derived `amount0`/`amount1` while only validating price bounds.

### Impact Explanation
Once the local signer capitulates to a minority-supported `current_miner`/`parent_tenure_last_block`, all downstream logic keyed on that state machine value is affected — most importantly, the block-proposal and pre-commit evaluation paths (`check_latest_block_in_tenure`, `check_parent_tenure_choice`, `has_signed_block_in_tenure`) which rely on the signer's belief about the canonical tenure and parent tip. This can:
- Wedge the signer into evaluating proposals against a **non-canonical, minority-endorsed parent tenure view**, causing it to reject legitimate proposals built on the actual (majority) tip, or to treat a minority-favored tenure/proposal as canonical.
- Break the state-machine's designed safety property that global agreement (`StateMachineUpdate` equality) requires 70% weight, allowing <70% (just >30%) of signers to steer an individual signer's canonical view — a liveness wedge on that signer, and a step toward signing off a wrong/conflicting tenure view if further checks (e.g., node RPC responses under Bitcoin fork conditions) are also favorable to the attacker.

This falls in the "wedge the state machine" / "acting on a stale reward set or view" category defined as in-scope High-impact behavior.

### Likelihood Explanation
Requires only >30% signer weight (a "blocking minority", not a majority) plus a tenure that already has at least one legitimately globally-accepted block (a routine, not rare, condition — most active tenures reach this quickly). No majority, no other signer's key, and no StackerDB/transport exploitation is needed — only crafting/broadcasting `StateMachineUpdate` messages with a divergent `parent_tenure_last_block`/`parent_tenure_last_block_height` for an already-active tenure, which is exactly the kind of one-slot/gossip-reachable analog in scope.

### Recommendation
Do not let the presence of *any* globally-accepted block in a tenure (`nmb_blocks > 0`) substitute for the 70% agreement threshold when adopting a *different* miner-state view (especially a different `parent_tenure_last_block`). Either:
- Always require `reached_agreement` (≥70%) before capitulating `current_miner`, or
- If a lower bar is intentional for progressing an already-agreed tenure, restrict the relaxation to fields that cannot diverge (e.g., only allow capitulating on `parent_tenure_last_block_height` increasing monotonically and matching signerdb/node-verified data), never on an unverified peer-reported struct value gated by an unrelated local count.

### Proof of Concept
1. Tenure `T` produces one block `B0` that legitimately reaches 70% signatures and is marked `GloballyAccepted` in every signer's `signerdb` (`get_globally_accepted_block_count_in_tenure(T) == 1` for all).
2. A colluding minority controlling slightly more than 30% of signer weight broadcasts `StateMachineUpdate` messages claiming an `ActiveMiner` state for tenure `T` with a different (e.g., stale or forked) `parent_tenure_last_block`/`parent_tenure_last_block_height` than the honest majority's view.
3. On a victim (honest, non-colluding) signer, `capitulate_miner_view` iterates the tallied `miner_state` votes: the minority's `entry` weight exceeds 30% → `reached_disagreement` passes → because `nmb_blocks == 1 > 0` for `T`, the `reached_agreement` (70%) check at [7](#0-6)  is skipped entirely.
4. If the height/burn-block checks (lines 1056-1090) also pass for the minority's reported view, `capitulate_miner_view` returns that miner state, and `capitulate_viewpoint` installs it as the signer's new `current_miner`, even though it never reached the documented 70% global-agreement threshold.

**Uncertainty:** I could not fully trace every downstream consumer of `current_miner`/`parent_tenure_last_block` (e.g., exact behavior of `check_parent_tenure_choice` when fed this manipulated view) within the available index; a full exploit chain to an actual signature-on-invalid-block would require confirming those interactions, which may need deeper reading of `stacks-signer/src/chainstate/mod.rs` and `v1.rs`/`v2.rs` beyond what the index surfaced.

```rust
    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
```

```rust
    /// Return the count of globally accepted blocks in a tenure (identified by its consensus hash)
    pub fn get_globally_accepted_block_count_in_tenure(
        &self,
        tenure: &ConsensusHash,
    ) -> Result<u64, DBError> {
        let query = "SELECT COALESCE((MAX(stacks_height) - MIN(stacks_height) + 1), 0) AS block_count FROM blocks WHERE consensus_hash = ?1 AND state = ?2";
        let args = params![tenure, &BlockState::GloballyAccepted.to_string()];
        let block_count_opt: Option<u64> = query_row(&self.db, query, args)?;
        match block_count_opt {
            Some(block_count) => Ok(block_count),
            None => Ok(0),
        }
    }
```
