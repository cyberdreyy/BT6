### Title
`withdraw_rewards` silently caps staker SUI rewards when `rewards_pool` is insufficient, causing permanent fund loss — (`File: crates/sui-framework/packages/sui-system/sources/staking_pool.move`)

### Summary

In `sui_system::staking_pool`, the private `withdraw_rewards` function silently caps the reward payout to `pool.rewards_pool.value()` when the pool's actual reward balance is less than the exchange-rate-calculated entitlement. The staker receives fewer SUI than they earned, and the shortfall is permanently lost. This is the direct Sui analog of the Sherlock `pullReward` silent-failure bug: instead of reverting so the caller can handle the error, the function swallows the deficit and returns a smaller-than-owed `Balance<SUI>`.

### Finding Description

`withdraw_rewards` computes the staker's reward entitlement from the historical exchange rate, then silently clamps it:

```move
// This may happen when we are withdrawing everything from the pool and
// the rewards pool balance may be less than reward_withdraw_amount.
// TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
pool.rewards_pool.split(reward_withdraw_amount)
``` [1](#0-0) 

Two pieces of evidence confirm this is an unresolved defect, not an intentional design:

1. The error constant `EInsufficientRewardsPoolBalance` (value `4`) is declared but **never used anywhere in the module** — it was clearly intended to guard this exact path. [2](#0-1) 

2. The `TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN` comment shows the developers have observed the condition in production but have not diagnosed or fixed it. [3](#0-2) 

The caller `request_withdraw_stake` joins the (potentially short) reward balance onto the principal and returns it to the staker without any check that the reward amount matched the entitlement:

```move
let rewards_withdraw = pool.withdraw_rewards(
    principal_withdraw_amount,
    pool_token_withdraw_amount,
    ctx.epoch(),
);
// ...
principal_withdraw.join(rewards_withdraw);
principal_withdraw
``` [4](#0-3) 

This is exposed to any ordinary SUI holder through the public entry point `sui_system::request_withdraw_stake`:

```move
public entry fun request_withdraw_stake(
    wrapper: &mut SuiSystemState,
    staked_sui: StakedSui,
    ctx: &mut TxContext,
) {
    let withdrawn_stake = wrapper.request_withdraw_stake_non_entry(staked_sui, ctx);
    transfer::public_transfer(withdrawn_stake.into_coin(ctx), ctx.sender());
}
``` [5](#0-4) 

### Impact Explanation

When `pool.rewards_pool.value() < reward_withdraw_amount`, the staker receives `principal + actual_pool_balance` instead of `principal + exchange_rate_entitlement`. The difference — which can be many SUI, not just 1 MIST — is permanently destroyed: it is neither returned to the staker nor credited elsewhere. The `UnstakingRequestEvent` emitted by `validator::request_withdraw_stake` records the wrong (reduced) `reward_amount`, so there is no on-chain signal that the staker was shortchanged. [6](#0-5) 

This matches the **High/Medium** impact class: harmful smart-contract behavior causing permanent, irreversible fund loss for ordinary stakers.

### Likelihood Explanation

The condition is reachable through two independent paths, both confirmed by existing test code:

**Path 1 — Pool-token underflow.** When `pool.pool_token_balance < pool.pending_pool_token_withdraw`, `process_pending_stake_withdraw` sets `pool_token_balance = 0`. The next epoch's exchange rate is then computed against a deflated token supply, making the per-token SUI value appear higher than the actual `rewards_pool` can support. The existing test explicitly asserts this state:

```move
// insufficient pool token balance
assert!(pool.pool_token_balance() < pool.pending_pool_token_withdraw_amount());
``` [7](#0-6) 

**Path 2 — Accumulated `mul_div!` rounding.** `get_sui_amount` uses integer truncation (`(a as u128 * b as u128 / c as u128) as u64`). Over many epochs and many stakers, the sum of per-staker entitlements computed from the stored exchange rate can exceed the actual `rewards_pool` balance by more than 1 MIST. [8](#0-7) 

### Recommendation

**Short term:** Replace the silent `.min()` clamp with an assertion using the already-defined error code:

```move
assert!(pool.rewards_pool.value() >= reward_withdraw_amount, EInsufficientRewardsPoolBalance);
pool.rewards_pool.split(reward_withdraw_amount)
```

**Long term:** Audit and fix the root cause of the `rewards_pool` shortfall. The `TODO` comment has been present without resolution; the pool-token underflow path in `process_pending_stake_withdraw` and the accumulated rounding in `mul_div!` should both be investigated and corrected so that `rewards_pool.value()` always equals or exceeds the sum of all staker entitlements at epoch boundaries.

### Proof of Concept

1. Alice stakes 100 SUI at epoch 0 (exchange rate 1:1, receives 100 pool tokens).
2. Rewards accumulate over several epochs; the pool-token underflow scenario occurs (as demonstrated in `rewards_distribution_tests.move` lines 961–1019): `pool_token_balance` drops below `pending_pool_token_withdraw`, causing the epoch-6 exchange rate to be recorded as `155 SUI : 86.67 pool tokens` (≈ 1.788 SUI per token).
3. Alice calls `sui_system::request_withdraw_stake`. `withdraw_rewards` computes her entitlement as `100 × 155 / 86.67 ≈ 178.8 SUI` in rewards, but `pool.rewards_pool.value()` is only `55 SUI`.
4. The `.min()` silently caps her reward to `55 SUI`. She receives `100 + 55 = 155 SUI` instead of `100 + 78.8 = 178.8 SUI`.
5. The `~23.8 SUI` shortfall is permanently lost — no revert, no event, no recourse. [9](#0-8) [10](#0-9)

fun withdraw_rewards(
    pool: &mut StakingPool,
    principal_withdraw_amount: u64,
    pool_token_withdraw_amount: u64,
    epoch: u64,
): Balance<SUI> {
    let exchange_rate = pool.pool_token_exchange_rate_at_epoch(epoch);
    let total_sui_withdraw_amount = exchange_rate.get_sui_amount(pool_token_withdraw_amount);
    let mut reward_withdraw_amount = if (total_sui_withdraw_amount >= principal_withdraw_amount) {
        total_sui_withdraw_amount - principal_withdraw_amount
    } else 0;

    reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
    pool.rewards_pool.split(reward_withdraw_amount)
}

```text
fun get_sui_amount(exchange_rate: &PoolTokenExchangeRate, token_amount: u64): u64 {
    // When either amount is 0, that means we have no stakes with this pool.
    // The other amount might be non-zero when there's dust left in the pool.
    if (exchange_rate.sui_amount == 0 || exchange_rate.pool_token_amount == 0) {
        return token_amount
    };

    mul_div!(exchange_rate.sui_amount, token_amount, exchange_rate.pool_token_amount)
}
