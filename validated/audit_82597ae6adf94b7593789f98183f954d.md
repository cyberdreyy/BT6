### Title
Signature scope excludes `response_data` in `BlockAccepted`/`BlockRejection`, letting a one-slot relayer forge tenure-extend timestamps and reject metadata under another signer's signature - (File: `libsigner/src/v0/messages.rs`)

### Summary
`BlockAccepted` and `BlockRejection` carry a `response_data: BlockResponseData` field (`tenure_extend_timestamp`, `tenure_extend_read_count_timestamp`, `reject_reason`, `failed_txid`) that is included in the wire message but never covered by the cryptographic signature. Any StackerDB participant who observes a genuine, publicly-broadcast `BlockAccepted`/`BlockRejection` can copy its `signature`/`signer_signature_hash`, swap in arbitrary `response_data`, and rebroadcast it. Every receiver — node (`stackerdb_listener.rs`) and other signers (`signer.rs`) — will recover the *original* signer's public key and accept the forged fields as if that signer had approved them.

### Finding Description
`BlockAccepted::new`/`create_block_acceptance` sign only the raw block sighash: [1](#0-0) 
and verification on both the node side and the signer side recovers the public key from that same raw sighash, ignoring `metadata`/`response_data` entirely: [2](#0-1) [3](#0-2) 

`BlockRejection`'s domain-separated `hash()` used for both `sign()` and `verify()`/`recover_public_key()` covers only `signer_signature_hash` (plus `chain_id` via the domain tuple) — not `reason`, `reason_code`, or `response_data`: [4](#0-3) 

The struct definitions confirm `response_data`/`metadata` are separate, signature-uncovered fields: [5](#0-4) 

Consequently, a party who merely observes StackerDB traffic (which is public — every signer and node reads every signer's chunks) can take Signer X's real signature over block B and re-emit a message with the same `signer_signature_hash`/`signature` but a different `response_data.tenure_extend_timestamp`, `tenure_extend_read_count_timestamp`, `reject_reason`, or `failed_txid`. Because verification only checks the signature against the raw sighash (accept) or the hash-of-`signer_signature_hash`+`chain_id` (reject), the forged fields pass as authentic and are attributed to Signer X.

On the node side, these forged timestamps are folded directly into weighted-threshold state that gates mining decisions: [6](#0-5) [7](#0-6) 
and are consumed by the miner to decide whether to extend the tenure: [8](#0-7) [9](#0-8) 

For rejections, the forged `failed_txid`/`reason_code` feeds the per-transaction "problematic weight" tally used to decide whether a tx should be excluded network-wide: [10](#0-9) 

This breaks the equality "signed vs validated": the receivers treat `response_data` as if it were verified content of Signer X's signature, when in fact it is attacker-controlled and covered by nothing.

### Impact Explanation
An attacker with only a single StackerDB write slot (and the ability to observe public gossip — no majority, no victim key, no auth token) can:
- Forge Signer X's `tenure_extend_timestamp`/`tenure_extend_read_count_timestamp` to `0` or `u64::MAX` while keeping X's genuine weight counted toward the 70% threshold, either forcing a premature tenure/read-count extension or permanently blocking one (`find_weighted_timestamp_by_threshold`), which is a **liveness wedge**: the miner's tenure-extend decision is driven by data the signer set never actually approved.
- Forge Signer X's `reject_reason`/`failed_txid` on a rejection to blame an unrelated transaction as "problematic," fraudulently accruing X's weight toward marking that tx excludable, mis-tallying the weighted signer response.

This matches the "liveness wedge" / "aggregated-weight vs verified-accepts" class in scope: the accumulated weight used for a consensus-adjacent decision no longer reflects what was actually signed by the claimed signer.

### Likelihood Explanation
High feasibility: StackerDB chunks are broadcast publicly to all signers and the node listener; no special access beyond a normal signer/miner-observer role and one's own StackerDB write slot is required. The only work needed is capturing one legitimate signed message per target signer/block and re-encoding it with a different `response_data`. No cryptographic break is required — this is a message-format flaw (incomplete signing scope), not a signature forgery.

### Recommendation
Include `response_data` (and `metadata` where it carries security-relevant data) inside the signed hash for both `BlockAccepted` and `BlockRejection` (e.g., extend `BlockRejection::hash()`'s structured-data payload to include the serialized `response_data`, and change `create_block_acceptance`/`handle_block_signature` to sign/verify over `signer_signature_hash || response_data` rather than the bare sighash). Reject messages during deserialization/verification if the recomputed hash (over the full authenticated payload) does not match.

### Proof of Concept
1. Passively observe StackerDB traffic for a genuine `BlockAccepted` from Signer X over block B: `{signer_signature_hash: H, signature: S, metadata: M, response_data: {tenure_extend_timestamp: T, ...}}`. `S` is valid because `S = sign_X(H.bits())` per `create_block_acceptance`.
2. Craft a new message reusing `H` and `S` verbatim, but replace `response_data.tenure_extend_timestamp` with `0` (or `u64::MAX`) and `metadata.server_version` arbitrarily.
3. Broadcast this crafted message on the attacker's own StackerDB slot (any signer, or a low-weight signer's slot) as if relaying/re-signing on behalf of X — the message itself carries `S` unmodified.
4. Node's `stackerdb_listener.rs` recovers `signer_pubkey` from `S` over `H.bits()` — this succeeds and matches X's registered key (verification code at lines 411-426 checks only `S` against `H`, never touching `response_data`), so `update_idle_timestamp(signer_pubkey_X, 0, weight_X)` is called with the forged timestamp attributed to X's real weight.
5. `SignerCoordinator::get_tenure_extend_timestamp`/`get_read_count_extend_timestamp` (`find_weighted_timestamp_by_threshold`) now compute the 70%-threshold timestamp using this forged value, corrupting the miner's `should_full_tenure_extend`/`should_read_count_extend` decision.

Note: I could not fully trace whether the node deduplicates messages per signer per block in a way that would allow a *second*, forged message for the same `(signer, block)` pair to actually overwrite an already-recorded genuine one before/after the real message arrives (i.e., exact race/ordering semantics of `update_idle_timestamp`/`gathered_signatures` map keyed by `slot_id` for repeated sends) — this would need to be confirmed with test execution to establish whether the forged message must arrive first, last, or can simply co-exist and be picked up by `find_weighted_timestamp_by_threshold`'s per-signer overwrite semantics (`signer_idle_timestamps` keyed by signer, so a later message from the same signer replaces the earlier value, which supports the forgery landing regardless of arrival order, but this determinism was not runtime-verified here).

pub struct BlockAccepted {
    /// The signer signature hash of the block that was accepted
    pub signer_signature_hash: Sha512Trunc256Sum,
    /// The signer's signature across the acceptance
    pub signature: MessageSignature,
    /// Signer message metadata
    pub metadata: SignerMessageMetadata,
    /// Extra versioned block response data
    pub response_data: BlockResponseData,
}

impl StacksMessageCodec for BlockAccepted {
    fn consensus_serialize<W: Write>(&self, fd: &mut W) -> Result<(), CodecError> {
        write_next(fd, &self.signer_signature_hash)?;
        write_next(fd, &self.signature)?;
        write_next(fd, &self.metadata)?;
        write_next(fd, &self.response_data)?;
        Ok(())
    }

    fn consensus_deserialize<R: Read>(fd: &mut R) -> Result<Self, CodecError> {
        let signer_signature_hash = read_next::<Sha512Trunc256Sum, _>(fd)?;
        let signature = read_next::<MessageSignature, _>(fd)?;
        let metadata = read_next::<SignerMessageMetadata, _>(fd)?;
        let response_data = read_next::<BlockResponseData, _>(fd)?;
        Ok(Self {
            signer_signature_hash,
            signature,
            metadata,
            response_data,
        })
    }
}

    /// The signature hash for the block rejection
    pub fn hash(&self) -> Sha256Sum {
        let domain_tuple = make_structured_data_domain("block-rejection", "1.0.0", self.chain_id);
        let data = Value::buff_from(self.signer_signature_hash.as_bytes().into()).unwrap();
        structured_data_message_hash(data, domain_tuple)
    }

    /// Sign the block rejection and set the internal signature field
    fn sign(&mut self, private_key: &StacksPrivateKey) -> Result<(), String> {
        let signature_hash = self.hash();
        self.signature = private_key.sign(signature_hash.as_bytes())?;
        Ok(())
    }

    /// Verify the rejection's signature against the provided signer public key
    pub fn verify(&self, public_key: &StacksPublicKey) -> Result<bool, String> {
        if self.signature == MessageSignature::empty() {
            return Ok(false);
        }
        let signature_hash = self.hash();
        public_key
            .verify(&signature_hash.0, &self.signature)
            .map_err(|e| e.to_string())
    }

    /// Recover the public key from the rejection signature
    pub fn recover_public_key(&self) -> Result<StacksPublicKey, &'static str> {
        if self.signature == MessageSignature::empty() {
            return Err("No signature to recover public key from");
        }
        let signature_hash = self.hash();
        StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            signature_hash.as_bytes(),
            &self.signature,
        )
    }
}

    fn should_full_tenure_extend(
        &self,
        coordinator: &mut SignerCoordinator,
    ) -> Result<bool, NakamotoNodeError> {
        if self.last_block_mined.is_none() {
            // if we haven't mined blocks yet, no tenure extends needed
            return Ok(false);
        }
        let is_replay = self.config.miner.replay_transactions
            && coordinator
                .get_signer_global_state()
                .map(|state| state.tx_replay_set.is_some())
                .unwrap_or(false);
        if is_replay {
            // we're in replay, we should always TenureExtend
            info!("Tenure extend: In replay, always extending tenure");
            return Ok(true);
        }

        // Do not extend if we have spent a threshold amount of the
        // budget, since it is not necessary.
        let usage = self
            .tenure_budget
            .proportion_largest_dimension(&self.tenure_cost);
        if usage < self.config.miner.tenure_extend_cost_threshold {
            return Ok(false);
        }

        let tenure_extend_timestamp = coordinator.get_tenure_extend_timestamp();
        if get_epoch_time_secs() <= tenure_extend_timestamp
            && self.tenure_change_time.elapsed() <= self.config.miner.tenure_timeout
        {
            return Ok(false);
        }

        info!("Miner: Time-based tenure extend";
              "current_timestamp" => get_epoch_time_secs(),
              "tenure_extend_timestamp" => tenure_extend_timestamp,
              "tenure_change_time_elapsed" => self.tenure_change_time.elapsed().as_secs(),
              "tenure_timeout_secs" => self.config.miner.tenure_timeout.as_secs(),
        );
        Ok(true)
    }
