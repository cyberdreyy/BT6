### Title

Tranche collateral oracle excludes accrued epoch interest, enabling premature liquidation - (contracts/strategies/morpho/TranchesChainlinkOracle.sol)

### Summary

`TranchesChainlinkOracle.latestRoundData()` reports `cdo.virtualPrice(collateralToken)` directly. During a running credit-vault epoch, `virtualPrice` only reflects the last accounting checkpoint; accrued epoch yield is tracked separately by `expectedEpochInterest` and is not reflected in the oracle price until `stopEpoch()` updates accounting. A tranche-backed Morpho borrower can therefore be liquidated while the tranche’s implied economic value is still sufficient to keep the position above LLTV.

### Finding Description

The Morpho tranche adapter returns the stored CDO virtual price:

```solidity
return (0, int256(cdo.virtualPrice(collateralToken)), 0, 0, 0);
``` [1](#0-0) 

`virtualPrice()` derives its value from `getContractValue()` and the last saved tranche NAVs. [2](#0-1)  During a running epoch, the CDO’s strategy-token NAV does not continuously include fixed-APR yield. `startEpoch()` instead stores projected yield in `expectedEpochInterest`. [3](#0-2)  That projected value is applied to NAV only through the privileged `stopEpoch()` flow. [4](#0-3) 

The repository already defines the economically appropriate live valuation in `IdleCreditVaultImpliedPrice.impliedVirtualPrice()`. It starts from `virtualPrice` and adds elapsed epoch interest, adjusted by the AA/BB split and fees. [5](#0-4)  For non-programmable borrowers, it accrues `expectedEpochInterest - pendingWithdrawFees` linearly over `epochDuration`; for programmable borrowers, it reads `totalInterestDueNow()` without prorating it again. [6](#0-5) 

Thus, while an epoch is running, the oracle reports principal at the previous checkpoint while the helper recognizes accrued, net-of-fee yield. The deployment script explicitly creates Morpho markets using this adapter as the tranche collateral oracle and configures a 98% LLTV. [7](#0-6) 

### Impact Explanation

An unprivileged Morpho liquidator can liquidate a tranche-collateralized borrower before the borrower is economically undercollateralized. With a 98% LLTV, an accrued tranche gain greater than approximately `collateralValue / 49` can be sufficient to make the position healthy under the implied price while the stale oracle still reports it below the liquidation threshold.

The borrower loses tranche collateral through liquidation even though the corresponding epoch yield would have preserved the required collateral value. Loss is bounded by the seized collateral plus the liquidation incentive; at a 98% LLTV, the maximum immediate loss can include roughly 2% of collateral value plus the Morpho liquidation incentive and rounding.

### Likelihood Explanation

The discrepancy exists for the full duration of every running epoch and grows linearly with accrued interest in fixed-APR mode. It does not require malicious privileged behavior, oracle manipulation, token donation, or borrower default. Any third-party liquidator can call Morpho `liquidate()` once the stale oracle price places the position below LLTV.

At the configured 98% LLTV, positions are intentionally close to the threshold, so even modest epoch interest can create the discrepancy. The same issue can affect programmable-borrower deployments because the helper treats `totalInterestDueNow()` as already accrued to the current timestamp.

### Recommendation

Use `IdleCreditVaultImpliedPrice.impliedVirtualPrice(collateralToken)` as the collateral price reported by `TranchesChainlinkOracle`, or implement equivalent valuation logic directly in the oracle.

The oracle should:

- return `virtualPrice` when no epoch is running or the CDO is defaulted;
- accrue `expectedEpochInterest - pendingWithdrawFees` over `epochDuration` for fixed-APR pools;
- use `IProgrammableBorrower.totalInterestDueNow()` for programmable-borrower pools;
- subtract accrued management and performance fees consistently with `IdleCreditVaultImpliedPrice`;
- apply the current AA/BB gain split before returning the selected tranche’s implied NAV per share.

A fork test should assert that the oracle equals `impliedVirtualPrice()` throughout the epoch, not merely after `stopEpoch()`.

### Proof of Concept

A Foundry fork PoC can reproduce the pricing mismatch with this sequence:

```solidity
// Setup:
// 1. Deploy or fork an IdleCreditVault CDO, AA tranche, TranchesChainlinkOracle,
//    and a Morpho market whose collateralToken is AAtranche and LLTV is 98%.
// 2. lender deposits AA tranches.
// 3. victim supplies `C` AA tranches as collateral.
// 4. victim borrows approximately 98% of oracle-reported collateral value.
// 5. manager starts an epoch with positive fixed APR.

vm.warp(epochStart + epochDuration / 2);

uint256 oraclePrice = trancheOracle.latestRoundData().answer;
uint256 impliedPrice = impliedPriceHelper.impliedVirtualPrice(AA_TRANCHE);

assertLt(oraclePrice, impliedPrice);

uint256 oracleCollateralValue = C * oraclePrice / 1e18;
uint256 impliedCollateralValue = C * impliedPrice / 1e18;

// Morpho sees the position as liquidatable:
assertLt(oracleCollateralValue, debt / marketParams.lltv * 1e18);

// The economically accrued position remains above the threshold:
assertGt(impliedCollateralValue, debt / marketParams.lltv * 1e18);

address liquidator = makeAddr("liquidator");
vm.prank(liquidator);
morpho.liquidate(
    marketParams,
    victim,
    seizedAssets,
    0,
    ""
);

// The victim loses collateral even though impliedPrice includes accrued epoch yield
// and would have prevented liquidation.
assertGt(seizedAssets, 0);
```

  function _accruedGain(IdleCDOEpochVariant cdo) private view returns (uint256 accruedGain) {
    uint256 duration = cdo.epochDuration();
    uint256 endDate = cdo.epochEndDate();
    uint256 startDate = endDate > duration ? endDate - duration : 0;
    if (duration == 0 || block.timestamp <= startDate) return 0;

    uint256 elapsed = block.timestamp >= endDate ? duration : block.timestamp - startDate;
    bool isProgrammable = cdo.isProgrammableBorrower();
    uint256 expectedInterest = isProgrammable ? _programmableBorrowerInterest(cdo) : cdo.expectedEpochInterest();
    uint256 pendingFees = cdo.pendingWithdrawFees();
    if (elapsed == 0 || expectedInterest <= pendingFees) return 0;

    accruedGain = expectedInterest - pendingFees;
    if (!isProgrammable) accruedGain = accruedGain * elapsed / duration;
    uint256 mgmtFee = cdo.managementFee();
    if (mgmtFee != 0) {
      // Match stop accounting: management fees reduce gains before performance fees.
      // strategyTokenBalance - unclaimedFees is the equivalent of _managedContractValue() in IdleCDOEpochVariant.sol
      uint256 strategyTokenBalance = IERC20Detailed(cdo.strategyToken()).balanceOf(address(cdo));
      uint256 fees = cdo.unclaimedFees();
      uint256 feeBase = strategyTokenBalance > fees ? strategyTokenBalance - fees : 0;
      uint256 accruedManagementFee = feeBase *
        mgmtFee *
        (block.timestamp - cdo.latestHarvestBlock()) /
        (FULL_ALLOC * 365 days);
      if (accruedManagementFee >= accruedGain) return 0;
      accruedGain -= accruedManagementFee;
    }
    accruedGain -= accruedGain * cdo.fee() / FULL_ALLOC;
  }

  /// @notice Current net epoch interest due from a programmable borrower.
  /// @dev The borrower returns interest accrued to now, so callers must not prorate it again.
  function _programmableBorrowerInterest(IdleCDOEpochVariant cdo) private view returns (uint256) {
    address borrower = IdleCreditVault(cdo.strategy()).borrower();
    return IProgrammableBorrower(borrower).totalInterestDueNow();
  }
