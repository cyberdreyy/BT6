### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm()` decides whether a request has reached quorum purely by counting entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set for that request, comparing `confirmations.len() + 1 >= self.num_confirmations`. When a member is removed via `DeleteMember`, `delete_member()` only purges requests *created by* that member; it never scans other active requests' confirmation sets to strip out confirmations the removed member had already cast. This is the same class of bug as the reported `CToken` issue: a security-critical check (`transferAllowed()` / here, quorum-reached check) is evaluated against stale state instead of the state that should exist after a state-changing precondition (`accrueInterest()` / here, membership removal) has been applied.

### Finding Description
`confirm()` in `multisig2/src/lib.rs` computes quorum solely from the raw count of strings in the per-request `HashSet`: [1](#0-0) 

`delete_member()` removes the departing member from `self.members`, but only cleans up requests where `r.member == member` (i.e. requests the removed member *created*), removing those requests' confirmations wholesale. It never iterates `self.confirmations` to remove the removed member's entry from confirmation sets on *other* still-active requests that the member had previously confirmed: [2](#0-1) 

`remove_request()` (used on `delete_request` and successful `confirm`) also has no notion of purging a specific member's stale confirmations from unrelated requests: [3](#0-2) 

Binding that should hold: `confirmations_counted(request) == confirmations_from_current_members(request)`. After a `DeleteMember` execution, this equality breaks for any pending request that the removed member had confirmed before removal — the stale confirmation persists in the `HashSet` and continues to count toward `num_confirmations`.

### Impact Explanation
This falls under the explicitly listed Critical impact "a multisig request executed below threshold." A request (e.g. `Transfer`, `AddKey`, `FunctionCall`) can be executed with fewer *live* member confirmations than `num_confirmations` requires, because one of the counted confirmations belongs to a member who has since been removed. This can allow funds to be transferred, full-access keys added, or arbitrary function calls executed by the multisig account with an effectively lower real threshold than configured — directly undermining the multisig's security guarantee.

### Likelihood Explanation
No special privilege beyond normal multisig operation is required to trigger this: it happens whenever (a) a member confirms a request without it reaching quorum, and (b) that member is later removed via a normal `DeleteMember` request (e.g., because their key was rotated/compromised or they left the organization) while the earlier request they confirmed is still pending. This is a plausible, even expected, operational sequence for any long-lived multisig with rotating membership and is not gated by any documented initialization assumption.

### Recommendation
When executing `DeleteMember`, iterate over all entries in `self.confirmations` and remove the deleted member's identity string from every confirmation set, not just from requests the member created. Alternatively, when computing quorum in `confirm()`, filter `confirmations` against `self.members` (counting only confirmations from accounts/keys currently present in `members`) before comparing against `num_confirmations`.

### Proof of Concept
1. Multisig has 4 members `A, B, C, D` with `num_confirmations = 3`.
2. `A` creates request `R1` (e.g. `Transfer`). `D` calls `confirm(R1)` → `confirmations(R1) = {D}` (1 < 3, not yet executed): [4](#0-3) 
3. Separately, a `DeleteMember { member: D }` request reaches quorum via `A, B, C` and executes. `delete_member` removes `D` from `self.members`, but `R1` was created by `A`, not `D`, so `R1`'s confirmations (`{D}`) are left untouched: [5](#0-4) 
4. Now `members = {A, B, C}`, live threshold intent is 3-of-3. `A` calls `confirm(R1)` → `confirmations(R1) = {D, A}`, count check `1+1=2 < 3`, not executed yet.
5. `B` calls `confirm(R1)` → check `confirmations.len()+1 = 2+1 = 3 >= 3` → quorum reached, `R1` executes via `execute_request`: [6](#0-5) 
6. `R1` (e.g. a `Transfer`) executes with only 2 genuinely live-member confirmations (`A`, `B`) plus one stale confirmation from the removed member `D`, one short of the intended 3-live-member threshold.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
