### Title
pprof debug routes mounted with authentication-only (no role check), exposing cmdline/heap/goroutine dumps to any low-privilege API-key holder - (File: core/web/router.go)

### Summary
The `metricRoutes` function registers Go's `net/http/pprof` handlers (`/debug/pprof/{cmdline,heap,goroutine,profile,trace,...}`) directly under the `authv2` route group in `v2Routes`, which only requires passing `auth.Authenticate` (session or API token) with no `RequiresEditRole`/`RequiresAdminRole`/`RequiresRunRole` wrapper. Any credential holder able to authenticate at all — including the lowest-privilege `view` role via `X-API-KEY`/`X-API-SECRET` — can dump the node's full memory heap, goroutine stacks, and process command line.

### Finding Description
In `core/web/router.go`, `v2Routes` builds `authv2` as: [1](#0-0) 
this group only enforces `auth.Authenticate` (token or session), which in turn (in `core/web/auth/auth.go`) only validates the credential and sets the authenticated user in context — it performs no role comparison at all: [2](#0-1) [3](#0-2) 

Role enforcement is only added when individual routes are explicitly wrapped with `auth.RequiresEditRole`, `auth.RequiresAdminRole`, or `auth.RequiresRunRole` (defined at lines 200-255 of `auth.go`). Every sensitive route in `v2Routes` (key export/import/delete, user management, etc.) is wrapped this way — except the debug/pprof routes, which are mounted unwrapped: [4](#0-3) 

`metricRoutes` registers the raw stdlib pprof handlers with no role gate whatsoever: [5](#0-4) 

Since `authv2` itself carries no role requirement, and `metricRoutes(authv2)` adds none either, any principal that can successfully authenticate at all — a `view`-role user or a restricted `X-API-KEY`/`X-API-SECRET` pair (see `AuthenticateByToken`, lines 78-112) — can reach `GET /v2/debug/pprof/cmdline`, `/heap`, `/goroutine`, `/profile`, `/trace`, `/allocs`, `/block`, `/mutex`, `/threadcreate`. `pprof.Cmdline` returns the full process command line (which can include secrets passed via flags), and `heap`/`goroutine`/`profile`/`trace` dumps can leak private keys, passwords, or other secrets currently resident in node memory (e.g., decrypted keystore material, session tokens, DB connection strings held in memory).

This contrasts with `debugRoutes`, which only exposes `expvar` and is deliberately kept minimal: [6](#0-5) 
but the far more sensitive pprof surface bypasses that isolation and is exposed on the fully authenticated (but not role-gated) `authv2` group.

### Impact Explanation
This matches the "Critical - server credential/key theft" bounty class: a low-privilege API credential (or `view`-role session) is sufficient to retrieve heap/goroutine memory dumps and process command-line arguments from a running node, which can contain decrypted private keys, node secrets, or key-export passwords held transiently in memory or passed as command-line flags. No operator/admin/host access is required.

### Likelihood Explanation
Any user who can obtain the lowest role (`view`) session or a restricted API access-key/secret pair — which chainlink nodes routinely issue for automation/monitoring purposes — can immediately and repeatably hit these endpoints with no additional escalation. The attack is a single unauthenticated-role HTTP GET once basic credentials are held, fully reproducible, and requires no timing or race conditions.

### Recommendation
Wrap all handlers registered by `metricRoutes` (and any future debug endpoints mounted on `authv2`) with `auth.RequiresAdminRole`, matching the sensitivity of key-export/import/delete routes. Alternatively, move pprof handlers into a separate route group requiring the admin role explicitly, and audit `debugRoutes`/`metricRoutes` call sites to ensure no debug/profiling handler is reachable via a group whose only gate is `auth.Authenticate`.

### Proof of Concept
Go handler-level integration test plan (using existing router test harness, e.g. `core/web/router_test.go` conventions):
1. Set up a test app and router via `web.NewRouter`, create a user with `sessions.UserRoleView` and/or an API token (`X-API-KEY`/`X-API-SECRET`) with the lowest role.
2. Issue `GET /v2/debug/pprof/cmdline` and `GET /v2/debug/pprof/heap` with the view-role session cookie / API token headers set, no elevated role.
3. Assert response status is `200 OK` (not `401`/`403`), and that response body contains process command-line/heap data — proving the endpoint is reachable without any `RequiresXRole` check.
4. As a control, issue the same requests with an anonymous/no-credential client and confirm `auth.Authenticate` correctly returns `401` (proving only the authentication check, not authorization/role check, is applied) — highlighting that once *any* valid low-privilege credential exists, the endpoint is fully exposed.
5. Compare against `/v2/keys/eth/export/:address` (which requires `auth.RequiresAdminRole`) with the same view-role credential and confirm it correctly returns `403 Forbidden`, demonstrating the inconsistency in role enforcement between key-export routes and debug/pprof routes.

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}
