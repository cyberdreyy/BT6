### Title
Symlink target escapes workspace root in raw artifact archiver, allowing exfiltration of files outside build directory - ([File: commands/helpers/archive/raw/raw_archiver.go])

### Summary
`fileArchiver.findRelativePathInProject` and `fileArchiver.process` only perform lexical validation (via `filepath.Abs`/`filepath.Rel`) on the *path itself*, never resolving symlinks, so a symlink located inside the job workspace that points outside of it will pass validation and be added to `c.files`. `archiver.Archive` in `raw_archiver.go` then calls `os.Open(pathname)` (line 41), which follows symlinks transparently, streaming the symlink target's contents — potentially files outside the intended workspace root — to the artifact upload pipe.

### Finding Description
The relevant validation chain is:
- `fileArchiver.processPath` → `findRelativePathInProject` (commands/helpers/file_archiver.go:191-222): computes `abs := filepath.Abs(base)` and `rel := filepath.Rel(c.wd, abs)`, then rejects only if the resulting *string* starts with `".."`. This is a purely syntactic/lexical check of the given path string — it never calls `filepath.EvalSymlinks` or otherwise dereferences symlinks to verify the final resolved target is inside `c.wd`.
- `doublestar.FilepathGlob(rel, doublestar.WithNoFollow())` (file_archiver.go:160) avoids following symlinks only during glob expansion of intermediate path segments, not for the leaf match itself.
- `filepath.Walk` (file_archiver.go:169) does not follow symlinks for directory recursion, but a symlink *file* itself is visited as a leaf entry.
- `fileArchiver.process` (file_archiver.go:65-101) re-applies the same lexical `Abs`/`Rel` check on the walked path and, if it passes, calls `c.add(relative)`.
- `fileArchiver.add` (file_archiver.go:127-138) uses `os.Lstat` (not following the symlink) merely to confirm existence and to store `FileInfo`, but this does not stop the symlink from being included in `c.files`.
- Finally, `archiver.Archive` (raw/raw_archiver.go:35-49) calls `os.Open(pathname)` for the single raw file. `os.Open` follows symlinks by default (no `O_NOFOLLOW`), so if `pathname` is a symlink whose target lies outside the workspace, the runner opens and streams that external file's bytes via `io.Copy(a.w, f)`.

Because `--artifact-format=raw` restricts the archive to exactly one file (`ErrTooManyRawFiles` check, raw_archiver.go:36-38), an attacker only needs to control a single `fileArchiver.Paths` entry that resolves (lexically) to a symlink inside the workspace. Nothing in the enumeration or archiving path resolves or rejects symlinks whose targets are outside `c.wd`.

Attacker-controlled inputs: `.gitlab-ci.yml` `artifacts:paths` (mapped to `fileArchiver.Paths`) and `artifacts:format: raw` (mapped to `Format`), plus arbitrary shell commands in the `script:` section to create the symlink (`ln -s /path/to/target ./leak`) before the artifacts stage runs. Both are fully within an unprivileged pipeline author's control.

Existing checks reviewed and found insufficient:
- The `..`-prefix check in `findRelativePathInProject`/`process` only validates the *literal path string* supplied, not the resolved file the OS will actually open — a classic symlink-based path-validation bypass (TOCTOU/symlink race not even required, this is a direct data flow).
- `doublestar.WithNoFollow()` and `os.Lstat` in `add()` correctly identify that the entry is a symlink, but that information is discarded; no code path rejects symlink entries or resolves/validates their targets before reading.
- No `filepath.EvalSymlinks` call exists anywhere in `file_archiver.go` or `raw_archiver.go`.

### Impact Explanation
If the sensitive target (e.g., a mounted `CI_JOB_TOKEN` file, a leftover secret file from a previous job sharing the same executor/host path, or a registry/cache credential file readable by the job's OS user) exists at a path readable by the job process, this bug lets an unprivileged pipeline author exfiltrate its exact contents through the normal `artifacts:paths` + `artifacts:format: raw` mechanism, with the bytes appearing in the uploaded artifact retrievable from the GitLab UI/API. This is a concrete host-file-read-outside-workspace primitive, matching the scoped impact (cross-project/cross-job secret exfiltration via raw artifact upload), contingent on the executor/host actually leaving such a file accessible to the job's OS user (e.g., shell executor on a shared host, or any executor where the job process has read access to a path outside the checked-out project directory).

### Likelihood Explanation
Preconditions: the job's OS user must have read permission on the target file, and the target must be reachable via a filesystem path from the job process (true for shell/host-based executors, and for any executor configuration where the workspace is not the only readable location for the job's user). Given those preconditions, the exploit is fully attacker-controlled and deterministic — no race condition, no timing dependency, no privilege needed beyond authoring a pipeline. It is 100% repeatable in that configuration.

### Recommendation
In `fileArchiver.process`/`findRelativePathInProject` (and/or in the raw archiver just before opening), resolve the fully dereferenced path with `filepath.EvalSymlinks` and re-run the "inside `c.wd`" containment check against the resolved path, rejecting any entry whose resolved target escapes the workspace root. Alternatively, explicitly reject symlink entries (`info.Mode()&os.ModeSymlink != 0`) unless their `EvalSymlinks` result stays within `c.wd`, and have `raw_archiver.Archive` open files with symlink-safe semantics (e.g., verify `os.Lstat` is not a symlink, or verify `filepath.EvalSymlinks(pathname)` is still prefixed by the workspace root before calling `os.Open`).

### Proof of Concept
```go
func TestRawArchiver_SymlinkEscapesWorkspace(t *testing.T) {
    workspace := t.TempDir()
    outside := t.TempDir()

    secretPath := filepath.Join(outside, "secret.txt")
    require.NoError(t, os.WriteFile(secretPath, []byte("SUPER-SECRET-TOKEN"), 0600))

    linkPath := filepath.Join(workspace, "leak")
    require.NoError(t, os.Symlink(secretPath, linkPath))

    // Simulate fileArchiver enumeration with cwd = workspace, Paths = ["leak"]
    prevWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(workspace))
    defer os.Chdir(prevWd)

    fa := &fileArchiver{Paths: []string{"leak"}}
    require.NoError(t, fa.enumerate())

    // Assert the symlink passed validation and is in the file set
    require.Contains(t, fa.files, "leak")

    // Now feed into raw archiver, as artifacts_uploader.createBodyProvider does
    var buf bytes.Buffer
    a, err := raw.NewArchiver(&buf, workspace, archive.CompressionLevelDefault)
    require.NoError(t, err)

    err = a.Archive(context.Background(), fa.files)
    require.NoError(t, err)

    // BUG: bytes streamed are the outside secret file's contents,
    // not rejected as "outside build directory"
    assert.Equal(t, "SUPER-SECRET-TOKEN", buf.String())
}
```
Expected (post-fix) assertion: `Archive` should return an error (or `enumerate`/`process` should have excluded `leak`) rather than successfully streaming the external file's contents.
