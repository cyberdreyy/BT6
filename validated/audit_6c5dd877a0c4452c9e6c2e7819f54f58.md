### Title
Multisig `confirm()` counts stale confirmations from removed members, allowing request execution below the live-member threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` in `multisig2/src/lib.rs:294-315` decides whether a request is ready to execute purely by counting entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set for that request, comparing `confirmations.len() + 1 >= self.num_confirmations`. `delete_member` (`multisig2/src/lib.rs:355-379`) only purges requests that were *originated* by the removed member (`r.member == member`); it never scans other pending requests to strip confirmations that the removed member previously cast. As a result, a confirmation cast by an account that is later removed from `members` keeps counting toward the threshold on any request it confirmed before being removed, letting a request execute with fewer *currently live* confirming members than `num_confirmations` requires.

### Finding Description
The relevant binding that should hold is: `confirmations counted == confirmations from members who are current members at execution time`. The code breaks this equality.

- `add_request`/`confirm` store confirmations keyed only by a serialized `MultisigMember` string in a plain `HashSet<String>` per request (`multisig2/src/lib.rs:128, 195-197, 300-314`).
- `confirm()` (`multisig2/src/lib.rs:294-315`) never re-validates that everyone already present in `confirmations` for that `request_id` is still in `self.members` — it just checks set cardinality:
```
multisig2/src/lib.rs:299-314
let mut confirmations = self.confirmations.get(&request_id).unwrap();
...
if confirmations.len() as u32 + 1 >= self.num_confirmations {
    let request = self.remove_request(request_id);
    self.execute_request(request)
} else {
    confirmations.insert(member.to_string());
    ...
}
```
- `delete_member()` (`multisig2/src/lib.rs:355-379`) removes the member from `self.members` and cleans up *only* the requests whose originating `member` field equals the deleted member. It does not iterate `self.confirmations` for other still-open requests to drop stale entries belonging to that member:
```
multisig2/src/lib.rs:361-374
let request_ids: Vec<u32> = self.requests.iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
self.num_requests_pk.remove(&member.to_string());
self.members.remove(&member);
```

So once a member confirms a request they didn't create, and is later removed via a separate `DeleteMember` action, their old confirmation silently remains attached to that pending request and still counts toward `num_confirmations` on the next `confirm()` call, even though `members.len()` may now equal (or barely exceed) `num_confirmations` with that member excluded.

### Impact Explanation
This crosses the threshold-authorization boundary explicitly called out as Critical: "a multisig request executed below threshold." An arbitrary-value `Transfer`, `FunctionCall`, `AddKey`/`DeployContract` request can be pushed to execution with confirmations from fewer *live* members than `num_confirmations` mandates, because one or more of the counted confirmations belongs to an account that is no longer a member. This directly undermines the K-of-N security guarantee the contract is meant to provide and can enable unauthorized fund transfers or privilege changes out of the multisig-controlled account.

### Likelihood Explanation
Reaching this requires only ordinary multisig operations available to any current member (no foundation/owner/redeploy needed):
1. A pending request exists that is confirmed by member B (who did not create it).
2. Member B is later removed via a normal (legitimate) `DeleteMember` request.
3. Another member confirms the still-pending request, and the stale confirmation from B is counted, crossing the threshold with one fewer live confirming member than intended.

This is a natural sequence of legitimate multisig lifecycle operations (create request → partial confirm → membership change → further confirm), not a contrived or purely theoretical path, so likelihood is credible for any deployment where membership changes over the life of outstanding requests.

### Recommendation
When removing a member in `delete_member`, iterate over **all** pending requests' `confirmations` sets (not just requests they originated) and remove the departing member's entry from each. Alternatively, have `confirm()` re-validate, at confirmation time, that every account/key present in the stored confirmation set is still a current member (filtering out stale ones) before comparing against `num_confirmations`, so removed members' prior approvals can never count toward execution.

### Proof of Concept
Given `members = [A, B, C, D]`, `num_confirmations = 3`:
1. `A.add_request(X)` — request `X` created, 0 confirmations.
2. `B.confirm(X)` — `confirmations(X) = {B}` (1 < 3, not executed).
3. `A, C, D` jointly pass a separate `DeleteMember{B}` request (3/4 live confirmations, legitimate) → `members = [A, C, D]`, `confirmations(X)` for request `X` is untouched and still contains `B`.
4. `C.confirm(X)` — code computes `confirmations.len() (=1, containing stale "B") + 1 >= 3` → `2 >= 3` is false... 

Note: with these exact numbers a third confirmer is still needed, but the arithmetic still undercounts *live* approvers: after step 4, `confirmations(X) = {B, C}`, count = 2, one more confirmation (e.g. from `D`) reaches `3 >= 3` and executes `X` — yet the *live* signers who ever approved `X` are only `C` and `D` (2 live members), because `B`'s approval is stale. The request executes believing 3 members approved it while only 2 current members actually did, violating the K-of-N guarantee. This is directly reproducible by exercising `add_request`, `confirm`, and `delete_member` in the sequence above against `multisig2/src/lib.rs`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
