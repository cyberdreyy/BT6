### Title
Masked variable value split across stdout/stderr bypasses masking - ([File: executors/instance/instance.go])

### Summary
The instance executor's `Run` function creates two entirely independent writer chains (with independent masker state) for stdout and stderr. Because the masking logic only tracks partial-phrase matches within a single stream's writer instance, a job that writes part of a masked secret to stdout and the remainder to stderr will have neither fragment recognized as the full secret, so it is never replaced with `[MASKED]` in the job trace.

### Finding Description
`executor.Run` in `executors/instance/instance.go` (lines 82-94) obtains `stdout` and `stderr` writers via two separate calls to `e.BuildLogger.Stream(buildlogger.StreamWorkLevel, buildlogger.Stdout)` and `...Stderr`. `Logger.Stream` (common/buildlogger/build_logger.go:90-99) calls `l.wrap` independently for each, and `wrap` (lines 213-224) constructs a brand-new `masker.New(w, l.maskPhrases)` chain per call. The `masker` type (common/buildlogger/internal/masker/masker.go) tracks a `matching` counter per phrase per masker instance — state that exists only within one chain instance and is never shared or synchronized across the stdout and stderr chains. A pipeline author who controls job script content (a normal, unprivileged capability) can print, e.g., the first half of a masked variable's value to stdout and the second half to stderr (via shell redirection like `printf %s "${SECRET:0:5}"; printf %s "${SECRET:5:}" >&2`). Neither the stdout masker instance nor the stderr masker instance ever observes the complete phrase in sequence, so the match state in each resets/completes without a full match, and the raw plaintext fragments are written to the job trace unmasked. Because both stdout and stderr are eventually merged into the same trace log (both ultimately write into `e.base`/the job's trace), fragments of the secret end up as unmasked plaintext, defeating the masking feature's intended guarantee that masked CI/CD variable values never appear in the trace.

### Impact Explanation
Masked CI/CD variables (tokens, credentials) intentionally hidden from the job log can be leaked in cleartext (in fragments, but full-value if split just right, or trivially reconstructable) to anyone who can view the job trace/log — this includes other maintainers/viewers of the pipeline output. This directly violates the runner's core invariant that "masked values must not leak ... in logs."

### Likelihood Explanation
Fully attacker-controlled and trivially reproducible: any pipeline author who defines a masked variable and writes a `.gitlab-ci.yml` job script can split writes across file descriptors 1 and 2 using ordinary shell syntax. No special runner configuration, executor privilege, or admin cooperation is required — this is a design gap in per-stream masker state, not a misconfiguration.

### Recommendation
Share masking state across stdout and stderr for a given job/stream rather than instantiating independent masker chains per call to `Stream()`. For example, construct one shared `masker.New` chain (and token/URL sanitizer chains) per build/job and have both the stdout and stderr `io.WriteCloser` write through the same underlying masker state (with a mutex to serialize partial-match tracking across the two concurrent streams), so that a phrase split across the two streams is still detected sequentially, or alternatively track cross-stream partial matches explicitly.

### Proof of Concept
Go unit test in `common/buildlogger`:
```go
func TestMaskingBypassAcrossStdoutStderr(t *testing.T) {
    jt := newFakeJobTrace()
    l := New(jt, nil, Options{MaskPhrases: []string{"supersecret"}})

    stdout := l.Stream(StreamWorkLevel, Stdout)
    stderr := l.Stream(StreamWorkLevel, Stderr)

    _, _ = stdout.Write([]byte("super"))
    _, _ = stderr.Write([]byte("secret"))
    require.NoError(t, stdout.Close())
    require.NoError(t, stderr.Close())

    output := jt.Read()
    assert.NotContains(t, output, "supersecret") // should not leak in combination
    assert.NotContains(t, output, "super")        // ideally partial fragment also masked/held
}
```
Expected today: the test fails because `output` contains the literal fragments `super` and `secret` unmasked (since each masker chain independently completes/aborts its own partial match), demonstrating the bypass. A PoC pipeline job would define a masked variable `SECRET_TOKEN` and run `printf '%s' "${SECRET_TOKEN:0:4}"; printf '%s' "${SECRET_TOKEN:4}" 1>&2`, then inspect the job trace for the plaintext value.

```go
func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {
```

```go
// New returns a new Masker.
func New(w io.WriteCloser, phrases [][]byte) *Masker {
	m := &Masker{}
	m.next = w

	// Create a masker for each unique phrase
	for i := 0; i < len(phrases); i++ {
		m.next = &masker{next: m.next, phrase: phrases[i]}
	}

	return m
}

func (m *Masker) Write(p []byte) (n int, err error) {
	return m.next.Write(p)
}

// Close flushes any remaining data and closes the underlying writer.
func (m *Masker) Close() error {
	return m.next.Close()
}

type masker struct {
	phrase   []byte
	matching int
	next     io.WriteCloser
}
```
