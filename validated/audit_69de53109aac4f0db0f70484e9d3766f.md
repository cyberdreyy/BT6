### Title
Cross-request response confusion via requestID reuse after cleanupCallback - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`h.callbacks` is a single global map keyed only by the user-supplied `requestID` string, with no generation/incarnation token distinguishing one registration from a later one that reuses the same ID. Once `cleanupCallback` deletes an entry (either on quorum success in `HandleNodeTriggerResponse` or via `reapExpiredCallbacks`), a new `workflows.execute` request can immediately re-register under the same `requestID` for a completely different workflow, and any subsequent late/duplicate DON response for the *original* request gets routed into the *new* registration's aggregator and delivered via `SendResponse` to the new caller.

### Finding Description
`setupCallback` only guards against **concurrent** reuse of an in-flight ID: `if _, found := h.callbacks[requestID]; found { ... }` [1](#0-0) . It performs no check that the ID hasn't been *recently freed*, and once freed, a fresh entry with brand-new `responseAggregators` is inserted at the same map key [2](#0-1) .

`HandleNodeTriggerResponse` looks up `h.callbacks[resp.ID]` purely by the string ID, with no verification that the response actually originates from the workflow/execution associated with the *current* registration under that ID [3](#0-2) . The only binding check is that the responding node's shard has an aggregator entry (`saved.responseAggregators[shard.donID]`), which merely confirms the node's shard is assigned to *whatever* workflow is currently registered — it does not confirm the response belongs to that workflow's execution.

`validateRequestID` only forbids requestIDs containing `/`; any other string, including one an attacker has learned is currently, or was recently, in flight for another workflow, is accepted [4](#0-3) .

`cleanupCallback` deletes the map entry the instant quorum is reached for the original request (from inside `HandleNodeTriggerResponse`, still holding `callbacksMu`) [5](#0-4) [6](#0-5) . Because a DON typically has more members than the aggregation threshold `(N+F)/2+1` computed in `setupCallback` [7](#0-6) , it is expected/normal (not an attack on the DON) for slower honest nodes to still be in flight with correct-but-late responses for the original request after quorum and cleanup have already happened.

`IdenticalNodeResponseAggregator.CollectAndAggregate` groups purely by response digest and node address, with no knowledge of which "generation"/registration it belongs to [8](#0-7) . If enough of these late/duplicate responses for the old request arrive after an attacker has re-registered the same `requestID` for a new (different) workflow, they will silently accumulate in the *new* aggregator instance and, once the new aggregator's threshold is met by stale nodes' matching late responses, `SendResponse` will deliver the *old* workflow's output to the attacker's newly-registered callback.

The attack does not require a malicious DON, malicious node, or OCR compromise: the only "malicious" actor is the unprivileged attacker who (a) knows or guesses a `requestID` string currently or about-to-become inactive (no format constraint beyond "no `/`"), and (b) races to immediately re-register that same ID for their own/new workflow before the last few slow honest node responses for the original request land.

### Impact Explanation
This is a cross-user/cross-workflow response confusion: output belonging to one execution (which may include another user's private/derived workflow result data) can be delivered into a different, attacker-controlled callback/execution context, matching Chainlink's "unauthorized action on another user's job" / "cross-user data disclosure" bounty impact class. Because the JSON-RPC response envelope's `ID` is the only association mechanism and it is entirely attacker-supplied, the security invariant "each node response is uniquely bound to its originating request/workflow" does not hold across ID lifecycles.

### Likelihood Explanation
Exploitability depends on:
1. The attacker being able to learn/guess an in-flight or about-to-be-cleaned-up `requestID` belonging to another caller (requestIDs are not scoped per-caller/session in the map, so any string collision qualifies), and
2. Enough of the original request's slower-but-honest DON member responses still being unsent/in-flight at the moment cleanup happens and the attacker's new registration lands, and reaching the new aggregator's threshold before the new legitimate request's real nodes respond.

Condition (2) is a normal, expected race in any deployment where DON quorum thresholds are less than full membership (which the code explicitly designs for, via `(N+F)/2+1`), so it is realistically achievable, especially against slower/larger shards or under network jitter — no privileged access or DON compromise is required, only precise timing and knowledge/guessing of the target `requestID`.

### Recommendation
Bind each registration to an internally-generated, unguessable execution/generation token (not just the caller-supplied `requestID`) and validate that late `HandleNodeTriggerResponse` calls match that token before aggregating/delivering. Alternatively, never reuse a `requestID` map slot for a fixed cooldown window after `cleanupCallback`/`reapExpiredCallbacks`, and reject `setupCallback` calls for IDs seen recently, or embed and check the `workflowID`/execution ID inside the aggregated response digest so a match against a wrong registration is impossible.

### Proof of Concept
Go handler-level integration test in `http_trigger_handler_test.go`:
1. Register callback A for `requestID="X"`, `workflowID=WA`, obtain its `responseAggregators` shard set.
2. Call `HandleNodeTriggerResponse` with enough distinct node responses (matching digest) to reach quorum for WA's shard, confirm `SendResponse` fires for callback A and `cleanupCallback("X")` removes the entry (`h.callbacks["X"]` absent).
3. Immediately call `setupCallback`/`HandleUserTriggerRequest` to register callback B for the same `requestID="X"` but a different `workflowID=WB` (assigned to an overlapping shard/node set), asserting it succeeds (no "already used" error).
4. Simulate a late/duplicate node response for the original request A (same `resp.ID="X"`, from nodes belonging to the overlapping shard, with content/digest matching the *original* workflow A's aggregated output) via `HandleNodeTriggerResponse`, repeated until reaching B's aggregator threshold.
5. Assert that callback B's `SendResponse` mock receives the payload — demonstrating that workflow A's response content is delivered to workflow B's registration, proving cross-request response confusion. Expected (buggy) result: B's callback receives A's payload; a fixed implementation would instead reject/discard the stale response or fail to associate it with B.

```go
func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}
```

```go
func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
```

```go
// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}
```

```go
func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
```

```go
func (agg *IdenticalNodeResponseAggregator) CollectAndAggregate(
	resp *jsonrpc.Response[json.RawMessage],
	nodeAddress string) (*jsonrpc.Response[json.RawMessage], error) {
	if resp == nil {
		return nil, errors.New("response cannot be nil")
	}
	if nodeAddress == "" {
		return nil, errors.New("node address cannot be empty")
	}

	key, err := resp.Digest()
	if err != nil {
		return nil, fmt.Errorf("error generating digest for response: %w", err)
	}

	// Check if the node already submitted a different response
	if oldKey, exists := agg.nodeToResponse[nodeAddress]; exists && oldKey != key {
		if nodes, ok := agg.responses[oldKey]; ok {
			nodes.Remove(nodeAddress)
			// Clean up empty response groups
			if len(nodes) == 0 {
				delete(agg.responses, oldKey)
			}
		}
	}

	if _, ok := agg.responses[key]; !ok {
		agg.responses[key] = make(StringSet)
	}
	agg.responses[key].Add(nodeAddress)
	agg.nodeToResponse[nodeAddress] = key

	if len(agg.responses[key]) >= agg.threshold {
		return resp, nil
	}

	return nil, nil
}
```
