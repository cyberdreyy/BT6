### Title
Unprotected pre-initialization window in `StakingRewards` lets anyone register a fake stake and later drain real staked tranche tokens and all reward yield - ([File: contracts/StakingRewards.sol](contracts/StakingRewards.sol))

### Summary
`StakingRewards` follows the same pattern as the RocketStorage bug: the contract is deployed "empty" and only becomes usable after a separate `initialize` transaction. Before `initialize` runs, `stakingToken` and `rewardsToken` are `address(0)`, and `stake()` performs no validation on that state. Because `SafeERC20` accepts calls to `address(0)` (empty returndata is treated as success), anyone can call `stake(amount)` during the deployment window and get an arbitrarily large internal `_balances`/`_totalSupply` entry without transferring a single token. Once the owner initializes the contract and the IdleCDO begins staking tranche tokens (via `stakeFor`) and distributing rewards (via `depositReward`), the attacker can `withdraw` their phantom stake — receiving real tranche tokens deposited by legitimate stakers — and `getReward`/`exit` to capture essentially 100% of all distributed rewards.

### Finding Description
- `initialize` only guards on `require(address(stakingToken) == address(0), 'Initialized')` (`StakingRewards.sol:40`). Staking does not modify `stakingToken`, so a pre-init `stake` does not block initialization.
- `stake` → `_stake` credits `_balances[_user] += amount` and `_totalSupply += amount` and then executes `stakingToken.safeTransferFrom(_payer, address(this), amount)` (`StakingRewards.sol:89-98`). When `stakingToken == address(0)`, the low-level call succeeds with empty returndata, which OpenZeppelin's `SafeERC20` treats as a successful transfer. No tokens move, but the balance is recorded.
- After initialization, `withdraw` sends real tokens pro-rata to the fake balance (`StakingRewards.sol:100-106`), and `getReward` pays out `rewardsToken` according to `earned()`, which is proportional to `_balances / _totalSupply` (`StakingRewards.sol:66-75`, `108-115`). A sufficiently large phantom balance dilutes legitimate stakers to ~0 reward.
- The window is real: deployment and `initialize` are separate transactions (the contract uses a plain `initialize` function, not a proxy with atomic init data, e.g. deployed via `forge-scripts`/deployment tasks). An attacker can front-run or simply act any time between deployment and initialization.

### Impact Explanation
Direct theft. The attacker withdraws real tranche tokens (the `stakingToken`) that the IdleCDO stakes on behalf of `feeReceiver` for fee distribution, and captures effectively all `rewardsToken` distributed via `depositReward` for as long as their dominant balance persists. Loss equals the entire staked tranche-token balance (up to the phantom amount) plus all emitted rewards — unbounded by construction since `amount` is attacker-chosen.

### Likelihood Explanation
Requires only monitoring the mempool/deployment for a `StakingRewards` deployment whose `initialize` hasn't run yet, plus one `stake` transaction. No privileged role needed; attacker is an arbitrary EOA. Likelihood is bounded by whether new `StakingRewards` instances are still being deployed for IdleCDO fee staking, but the vulnerable window exists on every such deployment where init is a separate transaction.

### Recommendation
- Prevent any state-changing interaction before initialization: add an `isInitialized` flag (set in `initialize`) and require it in `stake`, `stakeFor`, `withdraw`, and `getReward` — analogous to RocketPool's `contract.storage.initialised` guard.
- Alternatively deploy via an upgradeable proxy with atomic `initialize` calldata, or set `stakingToken` in the constructor.
- As defense-in-depth, revert in `_stake`/`_stake` when `address(stakingToken) == address(0)`.

### Proof of Concept
Foundry (mainnet fork or local) sketch:

```solidity
function testPreInitStakeStealsFunds() public {
    // 1. Deployer deploys StakingRewards (initialize NOT yet called)
    StakingRewards sr = new StakingRewards();

    // 2. Attacker front-runs initialize with a phantom stake
    address attacker = makeAddr("attacker");
    vm.prank(attacker);
    sr.stake(type(uint128).max); // stakingToken == address(0): transfer is a no-op success

    // 3. Owner initializes (still succeeds: stakingToken was untouched)
    sr.initialize(rewardsDistribution, address(rewardToken), address(trancheToken), owner, true);

    // 4. IdleCDO stakes real tranche tokens for feeReceiver and deposits rewards
    trancheToken.mint(rewardsDistribution, 1_000e18);
    vm.startPrank(rewardsDistribution);
    trancheToken.approve(address(sr), type(uint256).max);
    sr.stakeFor(feeReceiver, 1_000e18);
    rewardToken.mint(rewardsDistribution, 100e18);
    rewardToken.approve(address(sr), 100e18);
    sr.depositReward(address(0), 100e18);
    vm.stopPrank();

    // 5. Attacker drains real tranche tokens + ~all rewards
    vm.warp(block.timestamp + 1 days);
    vm.startPrank(attacker);
    sr.withdraw(1_000e18); // pulls real tranche tokens sent by rewardsDistribution
    sr.getReward();        // captures ~100% of rewardToken
    vm.stopPrank();

    assertEq(trancheToken.balanceOf(attacker), 1_000e18);
    assertApproxEqAbs(rewardToken.balanceOf(attacker), 100e18, 1);
}
```
