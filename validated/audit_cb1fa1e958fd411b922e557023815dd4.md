## Title
Unregistered/opted-out recipient permanently blocks `distribute()` for all shareholders of a `staking_contract` distribution pool - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

## Summary
`staking_contract::distribute_internal` withdraws all currently unlocked/inactive stake for a `StakingContract` in one shot and then loops over every shareholder of the contract's `distribution_pool`, paying each one via `aptos_account::deposit_coins`. If any single shareholder in that pool (staker, current operator/beneficiary, or a stale prior operator that still holds a residual distribution share from an earlier `switch_operator`) has not registered a `CoinStore<AptosCoin>` and has opted out of unsolicited coin transfers, the deposit call aborts. Because the payout to all shareholders happens inside one atomic `while` loop, that single abort reverts the whole transaction, so **no** shareholder — including parties who did nothing wrong — can ever get their already-unlocked stake or commission paid out via `distribute()` until the “poisoning” account fixes its own configuration. This mirrors the reported OFT bug class: one recipient's state (there: blacklist; here: direct-transfer opt-out / missing CoinStore) blocks a shared settlement operation instead of being isolated or redirected.

## Finding Description
`distribute()` is explicitly permissionless (“Allow anyone to distribute already unlocked funds”) and calls `distribute_internal`: [1](#0-0) 

`distribute_internal` withdraws the full unlocked balance in one `coin::withdraw`-style call and then iterates every shareholder in `distribution_pool`, extracting a slice of the withdrawn `Coin<AptosCoin>` for each and calling `aptos_account::deposit_coins`: [2](#0-1) 

`aptos_account::deposit_coins` will abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` for any recipient that exists, has not registered a `CoinStore<AptosCoin>`, and has disabled `allow_arbitrary_coin_transfers` via `DirectTransferConfig`: [3](#0-2) [4](#0-3) 

The distribution pool can hold shares for more than just the current operator and staker: `add_distribution` is used for the current operator's commission and, on `switch_operator`, the previous operator's pending commission remains in the same `distribution_pool` until claimed: [5](#0-4) 

Because `distribute_internal`'s `while` loop pays out every shareholder in a single atomic transaction (lines 889-900 above), any one of these accounts — including a former operator who no longer has any role or privilege over the contract — can make itself unreachable via `aptos_account::set_allow_direct_coin_transfers(false)` before ever registering an `AptosCoin` `CoinStore`. As soon as that stale/unprivileged account has any pending distribution share left in the pool, every future `distribute()` call for that `staker`/`operator` pair aborts, so the current operator's already-unlocked commission and the staker's already-unlocked principal are blocked from ever settling.

## Impact Explanation
This traps otherwise fully-unlocked, already-inactive stake and commission that legitimately belongs to the staker and the current (unrelated, honest) operator, with no way to force payment through `distribute()` — a non-recoverable stranding of claim rights caused entirely by an unprivileged third party's own account configuration, matching the "operator commission... payout... corruption that... traps value" and "permanent lock or non-recoverable loss of claim rights" impact categories.

## Likelihood Explanation
Any account can call `aptos_account::set_allow_direct_coin_transfers(false)` on itself and simply never call `coin::register<AptosCoin>`; this requires no special privilege and is a normal, permissionless user action. A residual distribution share for a stale operator is a normal byproduct of `switch_operator`, so the precondition (an unprivileged, uninvolved account holding a nonzero share in the pool) is straightforward to engineer or occurs incidentally.

## Recommendation
In `distribute_internal`, isolate per-recipient failures instead of letting a single failing deposit abort the whole loop — e.g., wrap each `aptos_account::deposit_coins` call so that on failure the funds are escrowed/redirected (similar to the `StakedUSDeOFTAdapter` remediation of crediting the contract owner instead of reverting), or require/verify that each shareholder already has a registered `CoinStore` before allowing its share to be added to `distribution_pool`, so failures affect only that shareholder's payout rather than the entire batch.

## Proof of Concept
1. Staker creates a `staking_contract` with `operator1`; `operator1` accrues commission and it becomes unlocked/inactive in `distribution_pool`.
2. Staker calls `switch_operator` to `operator2` — `operator1`'s pending commission distribution share remains in the same `distribution_pool` per lines 781-805 above.
3. `operator1` (no longer privileged over the contract in any way) calls `aptos_account::set_allow_direct_coin_transfers(false)` and never registers a `CoinStore<AptosCoin>`.
4. Anyone calls `staking_contract::distribute(staker, operator2)`. `distribute_internal`'s loop reaches `operator1`'s share and calls `aptos_account::deposit_coins(operator1_addr, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. The whole transaction reverts — `operator2`'s already-unlocked commission and the staker's already-unlocked principal remain undistributed indefinitely, with no `distribute()` call able to succeed until `operator1` (who has no further relationship with the contract) changes its own settings.

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
