### Title
Multisig signer with `Pubkey::default()` value is silently dropped from parsed `signers` list, causing `signers.len() != num_valid_signers` - ([File: account-decoder/src/parse_token.rs])

### Summary
`parse_token_v3` decodes a 355-byte SPL-Token `Multisig` account and filters the fixed 11-slot `signers` array to build the JSON `signers` list, using presence of `Pubkey::default()` as the sole signal that a slot is "unused padding." Because the SPL Token program's `InitializeMultisig` instruction accepts any account pubkeys as authorized signers (no signing requirement, no validation that the pubkey isn't all-zero), an attacker can legitimately create a multisig whose first `n` signer slots include the all-zero pubkey (which happens to coincide with the System Program ID), causing that entry to be indistinguishably dropped from the reported list.

### Finding Description
In `parse_token_v3`, the Multisig branch decodes signers as: [1](#0-0) 

The `filter_map` drops any entry equal to `Pubkey::default()` without regard for whether it lies within the first `multisig.n` "valid" slots or the trailing padding slots beyond `n` (the `Multisig` struct is always a fixed `[Pubkey; 11]` array where unused tail slots are zero-filled). The code assumes `Pubkey::default()` can only appear in unused padding, but the on-chain SPL Token program does not enforce that a real signer's pubkey be non-default — `InitializeMultisig` simply copies the pubkeys of whatever accounts are passed in as `signer_pubkeys`, with no restriction against passing the account whose key equals `Pubkey::default()` (the System Program ID, `11111111111111111111111111111111`, is numerically all-zero and thus equal to `Pubkey::default()`). An attacker can therefore initialize a multisig with `n = 3` where one of the three intended signer slots holds the System Program's pubkey. When `getAccountInfo` with `jsonParsed` encoding decodes this account, `num_valid_signers` (`multisig.n`) still reports 3, but `signers` will only contain 2 entries, with no field indicating a slot was suppressed.

### Impact Explanation
This is a decoder/RPC misreporting issue affecting `PARSE_FIDELITY`: integrators reconciling multisig authority membership via `getAccountInfo`/`jsonParsed` will see an incomplete/undercounted `signers` array relative to `num_valid_signers`, silently hiding a legitimate authorized signer (in this case, the System Program) from the reported set. It does not crash the validator or corrupt consensus state; scoped impact is limited to misreported account data returned by a single RPC query, matching the "decoder panic and misreporting" acceptance criterion.

### Likelihood Explanation
Fully attacker-reachable with no privileged access: any account owner can call SPL Token's `InitializeMultisig` and choose to include the System Program account (or any other account whose derived pubkey collides with `Pubkey::default()`, though System Program is the only practical/realistic candidate) as one of the `m`-of-`n` signers. A single `getAccountInfo` call with `jsonParsed` encoding triggers the flawed decoding path. This is deterministic and 100% repeatable.

### Recommendation
Only filter by array index (index `>= multisig.n`) rather than by pubkey value equality, e.g., take `multisig.signers.iter().take(multisig.n as usize)` instead of `filter_map` on `Pubkey::default()`, so genuine signers whose pubkey happens to be `Pubkey::default()` are preserved and the reported list length always matches `num_valid_signers`.

### Proof of Concept
```rust
#[test]
fn test_parse_multisig_default_pubkey_signer_dropped() {
    let signer1 = Pubkey::new_from_array([1; 32]);
    let signer2 = Pubkey::default(); // e.g. System Program ID, legitimately included as a signer
    let signer3 = Pubkey::new_from_array([3; 32]);
    let mut multisig_data = vec![0; Multisig::get_packed_len()];
    let mut signers = [Pubkey::default(); 11];
    signers[0] = signer1;
    signers[1] = signer2;
    signers[2] = signer3;
    let mut multisig = Multisig::unpack_unchecked(&multisig_data).unwrap();
    multisig.m = 2;
    multisig.n = 3; // 3 valid signers, one of which is Pubkey::default()
    multisig.is_initialized = true;
    multisig.signers = signers;
    Multisig::pack(multisig, &mut multisig_data).unwrap();

    if let TokenAccountType::Multisig(ui_multisig) = parse_token_v3(&multisig_data, None).unwrap() {
        assert_eq!(ui_multisig.num_valid_signers, 3);
        // Fidelity loss: only 2 signers reported instead of 3
        assert_eq!(ui_multisig.signers.len(), ui_multisig.num_valid_signers as usize); // FAILS: len is 2, not 3
    } else {
        panic!("expected Multisig variant");
    }
}
```
Expected: the assertion `signers.len() == num_valid_signers` fails, demonstrating that a legitimate signer entry equal to `Pubkey::default()` is silently and indistinguishably dropped from the parsed output.
