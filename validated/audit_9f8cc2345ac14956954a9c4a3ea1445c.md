### Title
Divide-before-multiply truncation in `L1FeeParams::jovian_da_footprint` underprices the Jovian DA-footprint fee - (File: `crates/common/l1-fees/src/params.rs`)

### Summary
`L1FeeParams::jovian_da_footprint` performs integer division before multiplication, truncating the scaled FastLZ size before it is multiplied by the DA-footprint gas scalar. This is the exact divide-before-multiply pattern described in the external report for `Rewarder._calibrateReward()`, and it exists in the transaction-fee/resource-pricing path that every user transaction goes through post-Jovian.

### Finding Description
`tx_estimated_size_fjord` returns the FastLZ-estimated compressed size pre-scaled by `1e6` [1](#0-0) . To recover the correct footprint, the value must be divided by `1e6` only after being multiplied by the scalar to preserve fractional precision; instead `jovian_da_footprint` divides first and multiplies second: [2](#0-1) 

```rust
pub fn jovian_da_footprint(&self, input: &[u8]) -> u64 {
    let Some(scalar) = self.da_footprint_gas_scalar else {
        return 0;
    };
    U256::from(tx_estimated_size_fjord(input))
        .wrapping_div(U256::from(1_000_000u64))   // divide first — truncates
        .saturating_mul(scalar)                    // multiply second — loses fractional part
        .saturating_to::<u64>()
}
```

Compare this with the sibling `calculate_tx_l1_cost_ecotone`/`calculate_tx_l1_cost_fjord`/`calculate_tx_l1_cost_bedrock` functions in the same file, which correctly multiply first and divide last: [3](#0-2) . `jovian_da_footprint` is the outlier that divides before multiplying, truncating up to `(1_000_000 - 1)/1_000_000` of a unit of estimated size before the scalar is applied — for any `scalar > 1` this systematically undercounts the footprint versus the mathematically equivalent `(estimated_size * scalar) / 1_000_000`, since integer division discards the same remainder regardless of scale but the discarded fraction is amplified when multiplying by `scalar` afterward instead of before.

`jovian_da_footprint` feeds directly into the DA-footprint gas figure used by the block executor and EVM2 executor (`crates/common/evm/src/executor/block_executor.rs`, `crates/common/evm2/src/executor.rs`) and by the flashblocks state builder (`crates/execution/flashblocks/src/state_builder.rs`), which is the resource/fee accounting for every ordinary user transaction once the Jovian upgrade is active.

### Impact Explanation
Because every transaction's estimated size is truncated to the nearest whole 1,000,000-unit before being scaled, the computed DA-footprint gas is silently lower than the mathematically correct value for any input whose estimated size is not an exact multiple of `1e6`. This is a fee-accounting/resource-metering computation that determines how much DA capacity/gas each transaction is charged, so precision loss here directly means transactions are systematically undercharged relative to the intended schedule.

### Likelihood Explanation
This code path executes unconditionally for every transaction post-Jovian whenever `da_footprint_gas_scalar` is configured — it requires no attacker action beyond sending an ordinary transaction, so the erroneous calculation triggers on essentially 100% of relevant transactions.

### Recommendation
Restructure the expression to multiply before dividing, matching the pattern used by the other cost functions in this file:
```rust
U256::from(tx_estimated_size_fjord(input))
    .saturating_mul(scalar)
    .wrapping_div(U256::from(1_000_000u64))
    .saturating_to::<u64>()
```

### Proof of Concept
Given `tx_estimated_size_fjord(input) = 1_999_999` (i.e., `1e6 + 999_999`, not an exact multiple of `1e6`) and `scalar = 3`:
- Current (buggy) order: `1_999_999 / 1_000_000 = 1` → `1 * 3 = 3`.
- Correct order: `1_999_999 * 3 = 5_999_997` → `5_999_997 / 1_000_000 = 5`.

The buggy path returns `3` instead of the correct `5`, understating the DA-footprint gas by ~40% for this input — confirming the truncation described in the analog report occurs identically here at `crates/common/l1-fees/src/params.rs:94-97`. [4](#0-3)

/// Calculate the estimated compressed transaction size in bytes, scaled by 1e6.
/// This value is computed based on the following formula:
/// max(minTransactionSize, intercept + fastlzCoef*fastlzSize)
pub fn tx_estimated_size_fjord(input: &[u8]) -> u64 {
    let fastlz_size = flz_compress_len(input) as u64;

    fastlz_size
        .saturating_mul(L1_COST_FASTLZ_COEF)
        .saturating_sub(L1_COST_INTERCEPT)
        .max(MIN_TX_SIZE_SCALED)
}
