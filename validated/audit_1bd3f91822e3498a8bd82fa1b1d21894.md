### Title
v1 signer's `validate_tenure_change_payload` uses `get_last_globally_accepted_block` instead of `get_last_signed_block`, letting a v1-protocol signer sign a duplicate tenure-start block that a v2 signer would reject — ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
`stacks-signer/src/chainstate/v1.rs`'s `validate_tenure_change_payload` still guards against a duplicate tenure-start block in the *own* tenure using `signer_db.get_last_globally_accepted_block(...)` [1](#0-0) , while the v2 implementation of the identical check was fixed to use `signer_db.get_last_signed_block(...)`, which also covers `LocallyAccepted` blocks [2](#0-1) . The project's own regression test and changelog entry document this exact class of bug as fixed for v2 ("ensure there are no locally accepted blocks in the tenure, not just globally accepted blocks") [3](#0-2) [4](#0-3) , but v1.rs was left with the older, narrower predicate.

### Finding Description
`check_proposal`'s tenure-change path calls `validate_tenure_change_payload` exactly once, at proposal arrival, and this is documented as the only place the `DuplicateBlockFound` protection for a second tenure-start block in the same tenure is enforced — it is never re-run at validate-ok or at signing time [5](#0-4) .

In v1, the guard queries only globally-accepted blocks:
```
let last_in_current_tenure = signer_db
    .get_last_globally_accepted_block(&block.header.consensus_hash)?;
if let Some(last_in_current_tenure) = last_in_current_tenure {
    return Err(RejectReason::DuplicateBlockFound);
}
``` [1](#0-0) 

A block that this signer has itself signed but that has not yet reached the 70% global-acceptance threshold is `LocallyAccepted`, not `GloballyAccepted` — `mark_locally_accepted` only promotes to `GloballyAccepted` via a separate call once the group threshold or node confirmation is observed [6](#0-5) . Because `get_last_globally_accepted_block` cannot see this state, `validate_tenure_change_payload` in v1 will not reject a second, competing tenure-start proposal for the same tenure that arrives while the first block is only `LocallyAccepted`.

By contrast v2 explicitly widened this to `get_last_signed_block`, precisely to close this gap, as its own doc comment states: "Only blocks we have signed (locally or globally accepted) count here" [7](#0-6) , and the corresponding regression test enshrines this as the correct behavior [8](#0-7) . v1.rs was never updated to match.

I attempted to determine whether the later, shared pre-commit-time re-check (`get_signed_conflicts` in `stacks-signer/src/v0/signer.rs`, section 5 of the flow docs) would still catch this at signature time regardless of the v1 proposal-time gap. I could not fully verify within the tool budget whether `check_block_against_signer_db_state` invokes `validate_tenure_change_payload` again at pre-commit/validate-ok time, or only the tip-confirmation check (`check_latest_block_in_tenure`) — the docs state the `DuplicateBlockFound` check specifically "never runs again" after proposal time and that the pre-commit-stage `get_signed_conflicts`-based "own-tenure conflict guard" is what is relied on to cover this gap generically. If that shared guard is fully effective for v1 as well, the practical exploitability of this specific v1/v2 divergence would be limited to causing the proposal to be pre-committed by mistake rather than actually signed — still a real deviation from intended behavior (the v1 signer will pre-commit to and echo willingness for a genuinely duplicate tenure-start block that v2 signers correctly reject outright), but not necessarily a final invalid signature. This residual uncertainty should be resolved by a Devin session with the ability to trace `check_block_against_signer_db_state`'s exact call graph and confirm whether it re-invokes the tenure-change duplicate check.

### Impact Explanation
If the shared section-5 guard does not fully cover this gap for v1 (e.g., due to timing/tenure-specific edge cases such as identical proposal/pre-commit interleavings, or protocol-version-specific state machines where `is_valid_signer`/threshold computation differs), a v1-protocol signer could pre-commit and potentially sign a second tenure-start block for a tenure where it has already locally accepted (signed) a different block — a conflicting/duplicate-block signature, which is the "Critical" impact category (a signer signing a conflicting block). Even in the more conservative case where the pre-commit-stage conflict guard blocks the final signature, this is still a live divergence between v1 and v2 correctness that increases attack surface for miner-driven double-proposal races on any network segment still running v1-protocol signers.

### Likelihood Explanation
This is reachable by a single miner (one gossip actor) alone: the miner needs only to propose two tenure-start blocks for the same tenure in quick succession, timed so the first reaches `LocallyAccepted` on some signer before the second's proposal-time check runs on that signer. No majority of signers or any additional signer key material is required to trigger the v1 check's blind spot; whether it is fully neutralized downstream depends on code paths not fully traced here.

### Recommendation
Change `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload` to use `signer_db.get_last_signed_block(&block.header.consensus_hash)` instead of `get_last_globally_accepted_block`, mirroring the v2 fix, so that a `LocallyAccepted` (signed but not yet globally accepted) block in the same tenure also triggers `RejectReason::DuplicateBlockFound` at proposal time for v1-protocol signers. Add a v1-specific regression test analogous to `check_tenure_change_rejects_when_locally_accepted_block_exists` in `stacks-signer/src/chainstate/tests/v2.rs` to lock in the fix and prevent future divergence between the two chainstate implementations.

### Proof of Concept
1. Boot a network segment where the active signer protocol version resolves to `SortitionStateVersion::V1` (pre `GLOBAL_SIGNER_STATE_ACTIVATION_VERSION`) [9](#0-8) .
2. As the tenure's miner, propose tenure-start block A; have it locally accepted (signed) by a target signer without yet reaching the network-wide 70% weight (e.g., by controlling/delaying delivery to other signers).
3. Immediately propose a second, conflicting tenure-start block B for the same tenure (same `consensus_hash`) to the target signer.
4. On the target v1 signer, `check_proposal` → `validate_tenure_change_payload` calls `get_last_globally_accepted_block`, which returns `None` because A is only `LocallyAccepted`, so B is not rejected with `DuplicateBlockFound` [1](#0-0) , unlike the equivalent v2 test `check_tenure_change_rejects_when_locally_accepted_block_exists`, which asserts this exact scenario must be rejected [8](#0-7) .
5. Observe whether B proceeds to node validation and pre-commit; confirming whether the section-5 `get_signed_conflicts` guard subsequently blocks the actual signature requires further tracing of `check_block_against_signer_db_state`'s call graph, which a Devin session with full repository/build access can verify by instrumenting or unit-testing the v1 code path directly.

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}

or at signing:

- `validate_tenure_change_payload` rejects with `DuplicateBlockFound` when we

guard to cover the same ground.

    /// Mark this block as valid and the appropriate timestamps if they aren't already set, and attempt to mark it as locally accepted.
    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Mark this block's signed group time if not already set and attempt to mark it as globally accepted.
    pub fn mark_globally_accepted(&mut self) -> Result<(), String> {
        self.signed_group.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::GloballyAccepted)
    }
