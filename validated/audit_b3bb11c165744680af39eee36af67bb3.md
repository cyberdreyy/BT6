### Title
Multisig executes requests below the effective confirmation threshold because confirmations from removed members are only purged for requests *they* created, not for requests they *confirmed* — (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
Both `multisig/src/lib.rs` and `multisig2/src/lib.rs` implement a K-of-N confirmation scheme where a request executes once `confirmations.len() + 1 >= num_confirmations`. When a member/key is removed via a `DeleteKey`/`DeleteMember` action, the contract only deletes pending *requests that member itself originally added*, and clears confirmations for *those* requests. It does not scan and strip that member's public key/account out of the confirmation sets of *other* still-pending requests that the removed member had previously confirmed. As a result, a stale confirmation from a no-longer-valid member continues to count toward `num_confirmations`, allowing a request to execute with fewer live/current members' approval than the configured threshold.

### Finding Description
`confirm()` counts confirmations purely by set membership and size, without re-validating that every entry in the confirmation set still corresponds to a current signer/member: [1](#0-0) 

The key-removal path (`MultiSigRequestAction::DeleteKey`) only cleans up requests whose `signer_pk` (the request's *creator*) equals the removed key, and removes that key's `num_requests_pk` counter — it never inspects other requests' `confirmations` sets for the removed key: [2](#0-1) 

The same pattern exists in `multisig2`'s `delete_member`, which only purges requests originally created by the removed member and their confirmations, leaving the removed member's confirmation entries intact on any *other* pending request they had already confirmed: [3](#0-2) 

`confirm()` in `multisig2` has the identical counting logic: [4](#0-3) 

**Binding that should hold:** `confirmations recorded for request R` should equal `confirmations from members who are still live members of the multisig at the moment R executes`. Because stale confirmations are never invalidated when a member is removed, this equality is broken: `count(confirmations(R)) >= num_confirmations` can be true while `count(confirmations(R) ∩ live_members) < num_confirmations`.

### Impact Explanation
This directly matches the Critical impact category "a multisig request executed below threshold." Concretely:
1. A K-of-N multisig has members {A, B, C, D}, `num_confirmations = 3`.
2. Member A creates request R (e.g., `Transfer` of funds) via `add_request`.
3. Member B confirms R (`confirm`) — 1 confirmation recorded, not yet enough.
4. The multisig (via a separate, properly-threshold-confirmed `DeleteKey`/`DeleteMember` request) removes B as a member — legitimate operational churn (e.g., offboarding), not an attack in itself.
5. R's confirmation set still contains B's stale public key/entry, since only requests *created by* B were purged, not R (which was created by A).
6. Members C and D now confirm R. `confirmations.len() + 1 >= 3` becomes true using A(creator)+B(stale)+C, or B(stale)+C+D — i.e., the request executes having received real approval from at most 2 still-live members instead of the required 3.

Funds can move (`Transfer`, `FunctionCall`, `AddKey`/`AddMember`, `DeployContract`) with authorization from fewer currently-authorized parties than the multisig's security model guarantees, undermining the entire threshold-custody assumption — a direct authorisation-boundary violation with potential NEAR loss.

### Likelihood Explanation
This requires no external attacker or malicious deployment: it is triggered by completely ordinary multisig lifecycle operations — creating a request, partially confirming it, and later rotating/removing a member before the request is fully confirmed or resolved (a common real-world sequence, e.g. an employee leaving, a compromised key being rotated out, or key management hygiene). No privileged bypass, no reentrancy trick, and no malicious counterparty are needed; it is a latent state-consistency bug reachable through normal usage of the in-scope `multisig`/`multisig2` contracts.

### Recommendation
When executing `DeleteKey` (`multisig/src/lib.rs`) or `DeleteMember` (`multisig2/src/lib.rs`), iterate over **all** pending requests (not just those created by the removed key/member) and remove the removed identity from each request's confirmation set, decrementing/adjusting as needed. Alternatively, validate at `confirm()`/execution time that every entry in the confirmation set still corresponds to a currently valid member/key before counting it toward `num_confirmations`, rejecting or lazily pruning stale entries.

### Proof of Concept
1. Deploy `multisig` (or `multisig2`) with `num_confirmations = 3` and members/keys A, B, C, D.
2. As A: `add_request(request)` targeting a `Transfer` action → `request_id`.
3. As B: `confirm(request_id)` → confirmations = {B}, request stays pending (1 < 3).
4. As A, C, D (threshold reached on a separate request): submit and confirm a `DeleteKey { public_key: B }` request → executed, B's access key removed from the account and from `num_requests_pk`, but `confirmations` map for the original `request_id` is untouched (only requests where `signer_pk == B` are purged — see `multisig/src/lib.rs` lines 198–216, which filters on `r.signer_pk == pk`, not on `confirmations` membership).
5. As C: `confirm(request_id)` → confirmations = {B, C}, len 2, `+1 >= 3` not yet true.
6. As D: `confirm(request_id)` → confirmations = {B, C, D}, `len() as u32 + 1 >= 3` is true → `execute_request` runs the `Transfer`, even though B is no longer a member and only A (creator) + C + D ever validly authorized it while B's stale entry padded the count. [5](#0-4) [2](#0-1)

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })

            // remove confirmations for this request

            self.requests.remove(&request_id);

        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
