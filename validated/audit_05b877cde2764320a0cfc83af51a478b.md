Based on the code, the guard is correct and complete — there is no bypass.

**Analysis:**

`NonDelegateAction`'s custom `BorshDeserialize::deserialize_reader` reads the discriminant byte first and rejects it if it matches either entry in `DELEGATE_VARIANT_NUMBERS = [ACTION_DELEGATE_NUMBER, ACTION_DELEGATE_V2_NUMBER]` (i.e., `8` for `Action::Delegate` and `14` for `Action::DelegateV2`), for *every* position in a `Vec<NonDelegateAction>`, since Vec deserialization deserializes each element independently through this same override. [1](#0-0) 

This means it is structurally impossible to construct a `DelegateAction.actions: Vec<NonDelegateAction>` or `DelegateActionV2.actions: Vec<NonDelegateAction>` containing an inner `Delegate` or `DelegateV2` variant — the borsh deserializer errors out with `ErrorKind::InvalidInput` before such a value can ever exist in memory. [2](#0-1) 

Consequently, `Action::post_quantum_signatures_required`'s recursive branches for `Action::Delegate` and `Action::DelegateV2` call `.get_actions()` (which converts each `NonDelegateAction` back into a plain `Action` via the private `From` impl that just unwraps the inner value) and then `.any(Action::post_quantum_signatures_required)` over that list. [3](#0-2) [4](#0-3) 

Since every element of that list is guaranteed (by the deserialization guard above) to never be a `Delegate`/`DelegateV2` action, the recursive call can never actually recurse into another delegate layer — it only ever evaluates the non-recursive arms (`Stake`, `AddKey`, `DeleteKey`, `TransferToGasKey`, `WithdrawFromGasKey`, or the no-key-material arms). The recursion is therefore vacuously safe: it exists for defense-in-depth / exhaustiveness but the delegate-nesting guard makes the recursive case unreachable in practice, and there is no gap through which a nested delegate carrying unchecked post-quantum key material could escape classification.

This is directly validated by the repo's own tests: `test_delegate_variant_encodings_match` and `test_delegate_action_deserialization` explicitly assert that borsh-serialized bytes with discriminant `8` or `14` are rejected by `NonDelegateAction::try_from_slice` with `ErrorKind::InvalidInput`, for both `Delegate` and `DelegateV2`. [5](#0-4) [6](#0-5)
