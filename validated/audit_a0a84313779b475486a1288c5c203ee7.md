### Title
Incorrect `max_timestamp` Tracking in `MetaOracle::add_simple_oracle` Allows Stale Oracle Data to Bypass the Time-Window Staleness Filter — (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

`MetaOracle::add_simple_oracle` unconditionally overwrites `max_timestamp` with each successive oracle's timestamp instead of tracking the running maximum. Because `combine()` anchors its staleness cutoff to `max_timestamp - time_window_ms`, any caller who adds a `SimpleOracle` whose last-submitted data is old as the final oracle in the sequence causes the cutoff to be anchored to a stale reference point. All oracle readings — including arbitrarily old ones — then satisfy the filter, and the `median()` function returns a price derived from stale data with no error or revert.

---

### Finding Description

`add_simple_oracle` in `meta_oracle.move` is:

```move
public fun add_simple_oracle<T: copy + drop + store>(
    meta_oracle: &mut MetaOracle<T>,
    oracle: &SimpleOracle
) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
``` [1](#0-0) 

The field is named `max_timestamp` and is initialised to `0`:

```move
max_timestamp: 0,
``` [2](#0-1) 

But the assignment `meta_oracle.max_timestamp = data::timestamp(...)` is a plain overwrite, not a `max()` comparison. After N oracles are added, `max_timestamp` holds the timestamp of the **last** oracle added, not the largest timestamp seen.

`combine()` then computes the staleness cutoff as:

```move
let min_timestamp = max_timestamp - time_window_ms;
``` [3](#0-2) 

If the last oracle added carries an old timestamp `T_old`, then `min_timestamp = T_old - time_window_ms`, which is a very old cutoff. Every oracle reading whose stored timestamp exceeds that old cutoff passes the filter — including readings that are far outside the intended freshness window.

`get_latest_data` in `simple_oracle.move` returns whatever is stored with no staleness check of its own:

```move
public fun get_latest_data<T: store + copy>(oracle: &SimpleOracle, ticker: String): Option<Data<T>> {
    if (!df::exists_(&oracle.id, ticker)) {
        return option::none()
    };
    let data: &StoredData<T> = df::borrow(&oracle.id, ticker);
    let StoredData { value, sequence_number, timestamp, identifier } = *data;
    option::some(data::new(value, ticker, sequence_number, timestamp, oracle.address, identifier))
}
``` [4](#0-3) 

The `MetaOracle` is the only layer that is supposed to enforce freshness, but its filter is broken.

---

### Impact Explanation

Any on-chain contract that calls `meta_oracle::median()` to obtain a trusted price can receive a median computed from arbitrarily stale readings. Because `MetaOracle` is a stack value constructed inside a PTB, the caller controls the order in which `add_simple_oracle` is called. A caller who places a `SimpleOracle` with an old last-update timestamp last in the sequence silently shifts the staleness window backward, causing the `median()` call to succeed and return a stale price instead of aborting. Financial logic downstream (swaps, collateral valuations, liquidation thresholds) would then operate on incorrect prices — the Sui analog of the Chainlink `latestAnswer` returning 0 silently.

---

### Likelihood Explanation

`SimpleOracle` objects are permissionlessly created by anyone via `create()`:

```move
public entry fun create(name: String, url: String, description: String, ctx: &mut TxContext) {
    let oracle = SimpleOracle { id: object::new(ctx), address: tx_context::sender(ctx), ... };
    transfer::share_object(oracle)
}
``` [5](#0-4) 

An attacker can create a `SimpleOracle`, submit data once to record a timestamp, wait until that timestamp is stale, then pass that oracle as the last argument to `add_simple_oracle` in any PTB that constructs a `MetaOracle`. No privileged access is required.

---

### Recommendation

Replace the plain assignment in `add_simple_oracle` with a maximum comparison:

```move
if (option::is_some(&oracle_data)) {
    let ts = data::timestamp(option::borrow(&oracle_data));
    if (ts > meta_oracle.max_timestamp) {
        meta_oracle.max_timestamp = ts;
    };
};
```

Additionally, `combine()` should validate that `max_timestamp` itself is recent (e.g., compare against `Clock`) before computing `min_timestamp`, mirroring the `latestRoundData` + staleness-check pattern recommended in the original Chainlink finding.

---

### Proof of Concept

1. Attacker calls `simple_oracle::create()` → gets `stale_oracle` (shared object).
2. Attacker calls `simple_oracle::submit_data(stale_oracle, clock, "SUIUSD", old_value, ...)` at time `T_old`.
3. Time passes; `T_old` is now older than `time_window_ms`.
4. Attacker constructs a PTB:
   - `meta_oracle::new(threshold=3, time_window_ms=60_000, "SUIUSD")` → `mo`
   - `meta_oracle::add_simple_oracle(&mut mo, fresh_oracle_1)` → `max_timestamp = T_fresh1`
   - `meta_oracle::add_simple_oracle(&mut mo, fresh_oracle_2)` → `max_timestamp = T_fresh2`
   - `meta_oracle::add_simple_oracle(&mut mo, stale_oracle)` → `max_timestamp = T_old` ← **overwritten**
5. `meta_oracle::median(mo)` computes `min_timestamp = T_old - 60_000`, a very old cutoff.
6. All three oracles' readings satisfy `timestamp > min_timestamp`; the median succeeds and returns a price that includes the stale value from `stale_oracle`.
7. Any downstream financial function consuming this `TrustedData` operates on a corrupted price. [1](#0-0) [3](#0-2) [4](#0-3)

        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);

                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };

        (values, oracles)
