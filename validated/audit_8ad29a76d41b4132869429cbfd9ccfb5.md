### Title
`LlamaPayRouterOracle` prices Chainlink-fed LlamaPay stream tokens without checking `updatedAt` staleness - ([File: v2/periphery/AbstractAssetOracle.sol])

### Summary
`AbstractAssetOracle._getPrice()` (used by `LlamaPayRouterOracle` at `v2/periphery/LlamaPayRouterOracle.sol` `_llamaPayBalance`) calls `IAeraV2Oracle(priceFeed).latestRoundData()` on a real Chainlink `AggregatorV2V3Interface` feed and validates only `price <= 0`, discarding `updatedAt`. This is the exact pattern from the report (Chainlink `latestRoundData()` consumed without a staleness/heartbeat check), and it exists side-by-side with the codebase's own fix for the same problem in `AeraVaultAssetRegistry._checkOraclePrice()`, which does enforce `updatedAt + asset.heartbeat + 1 hours < block.timestamp`. [1](#0-0) [2](#0-1) 

### Finding Description
`LlamaPayRouterOracle` is registered in `AeraVaultAssetRegistry` and implements `IAeraV2Oracle.latestRoundData()`, whose `answer` is derived from `_getValue()` → `_llamaPayBalance()` → `_getPrice(priceFeed)` for each configured LlamaPay stream token. [3](#0-2) 
`_llamaPayBalance` fetches the LlamaPay balance and multiplies it by the price returned from `_getPrice(priceFeed)`: [4](#0-3) 
`_getPrice` calls the real Chainlink-style price feed and only checks `price <= 0`, never checking `updatedAt`: [1](#0-0) 
`LlamaPayRouterOracle` declares its price feeds as `AggregatorV2V3Interface` immutables (`_priceFeed0.._priceFeed9`), i.e. genuine external Chainlink aggregators, not internal Aera oracles. [5](#0-4) [6](#0-5) 
This value flows into `AeraVaultAssetRegistry.spotPrices()`, which is the vault's NAV/unit-price source used for deposit/withdraw/fee accounting elsewhere in the vault: [7](#0-6) 
This exactly matches the reported root cause: consuming Chainlink `latestRoundData()` without validating `updatedAt` against a tolerance, allowing stale prices to be used silently. Notably, the same codebase already remediated this exact defect for regular ERC20 assets in `_checkOraclePrice` (heartbeat-based staleness check), but the equivalent guard was never applied to the `LlamaPayRouterOracle`/`AbstractAssetOracle` code path.

### Impact Explanation
If a Chainlink feed used by `LlamaPayRouterOracle` becomes stale (feed halt, deviation-threshold gridlock, L2 sequencer downtime, etc.), `_getPrice()` keeps returning the last reported price indefinitely instead of reverting. Because this valuation feeds directly into `AeraVaultAssetRegistry.spotPrices()`, which determines the vault's unit NAV, an incorrect/stale price for the LlamaPay-managed asset can misprice vault shares. Users depositing or redeeming while the true asset price has diverged from the stale price can mint/redeem at an incorrect NAV, extracting value from (or diluting) other depositors — a live theft-of-user-funds scenario matching Sherlock/Immunefi Medium-severity impact for stale oracle price consumption.

### Likelihood Explanation
Requires: (1) a vault configured with `LlamaPayRouterOracle` and at least one non-zero `priceFeed` slot pointing at a real Chainlink aggregator, and (2) that Chainlink feed going stale (a documented, non-hypothetical Chainlink failure mode, and exactly the precondition accepted in the original Sherlock report). No privileged action or role collusion is needed — the mispricing propagates automatically into any ordinary user's deposit/redeem transaction via the standard vault flow once the feed is stale. Likelihood is bounded by whether `LlamaPayRouterOracle` is actually deployed/enabled for a live vault; this could not be independently confirmed against on-chain deployment records given index/tool limits.

### Recommendation
Add the same staleness check used in `AeraVaultAssetRegistry._checkOraclePrice` to `AbstractAssetOracle._getPrice`: read `updatedAt` from `latestRoundData()`, plumb a per-feed heartbeat/tolerance parameter into `LlamaPayRouterOracle`'s constructor/storage, and revert (e.g. `AeraPeriphery__StalePrice`) if `block.timestamp - updatedAt` exceeds that tolerance, mirroring the existing pattern:
```solidity
(, int256 answer,, uint256 updatedAt,) = IAeraV2Oracle(priceFeed).latestRoundData();
if (answer <= 0) revert AeraPeriphery__InvalidPrice(priceFeed, answer);
if (heartbeat > 0 && updatedAt + heartbeat + 1 hours < block.timestamp) {
    revert AeraPeriphery__StalePrice(priceFeed, updatedAt);
}
```

### Proof of Concept
1. Fork mainnet at a block where a LlamaPay-managed token's Chainlink feed is still "fresh" per its heartbeat.
2. Deploy `LlamaPayRouterOracle` with `_priceFeed0` set to that real Chainlink aggregator and `_llamaPay0` set to a live LlamaPay contract with a non-zero balance for the router; register the oracle in `AeraVaultAssetRegistry` per its `AssetInformation` (as the `oracle` for the corresponding asset).
3. Warp `block.timestamp` forward past the feed's heartbeat (e.g. mock/pause the feed, or forward far beyond its typical update cadence) without updating the feed's round data, simulating staleness.
4. Call `AeraVaultAssetRegistry.spotPrices()` (or directly `LlamaPayRouterOracle.latestRoundData()`); assert it does NOT revert and still returns the stale price, in contrast to calling `_checkOraclePrice` on a normal ERC20 asset with the same stale-feed configuration, which reverts with `Aera__OraclePriceIsTooOld`.
5. Show that a `deposit`/`withdraw` executed against the vault at this stale NAV yields a demonstrably incorrect share/asset exchange relative to the true (fresh) price, quantifying value extracted by/lost to the depositor.

    /// @notice Ensure oracle returns valid value and it's up to date.
    /// @param asset Asset details to check.
    /// @return price Valid oracle price.
    function _checkOraclePrice(AssetInformation memory asset)
        internal
        view
        returns (uint256 price)
    {
        (, int256 answer,, uint256 updatedAt,) = asset.oracle.latestRoundData();

        // Check price staleness
        if (answer <= 0) {
            revert Aera__OraclePriceIsInvalid(asset, answer);
        }
        if (
            asset.heartbeat > 0
                && updatedAt + asset.heartbeat + 1 hours < block.timestamp
        ) {
            revert Aera__OraclePriceIsTooOld(asset, updatedAt);
        }

        price = uint256(answer);
    }

    /// @notice Get the LlamaPay balance in numerator terms scaled to 18 decimals.
    function _llamaPayBalance(
        ILlamaPay llamaPay,
        address priceFeed,
        uint256 rescaleFactor,
        uint256 invertedPriceNumerator
    ) internal view returns (uint256) {
        // Get the balance of this contract from LlamaPay contract.
        // Note: balance is always 20 decimals.
        uint256 balance = llamaPay.balances(address(this));
        // If the balance is zero, return zero.
        if (balance == 0) return 0;
        // If the price feed is absent, return balance downscaled to 18 decimals.
        if (priceFeed == address(0)) {
            return balance / _LLAMAPAY_DOWNSCALE_FACTOR;
        }

        uint256 price = _getPrice(priceFeed);
        // Invert the price if necessary.
        if (invertedPriceNumerator > 0) {
            price = invertedPriceNumerator / price;
        }

        // Multiply balance by the price and rescale to 18 decimals.
        return _mulDiv(balance, price, rescaleFactor);
    }
