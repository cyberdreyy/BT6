## Analysis

Tracing the "duplicate/mismatched context parameter" bug class from the Solidity report onto Aptos stake-lockup code, the closest analog lives in `aptos_framework::staking_contract`'s operator-switch and commission-distribution flow.

### Title
Stale commission shares bypass `beneficiary_for_operator` redirect after `switch_operator` — ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`distribute_internal()` redirects a payout to an operator's beneficiary only when the shareholder recorded in the `distribution_pool` equals the `operator` address passed into the function call. [1](#0-0) 
`switch_operator()` records pending commission shares under the **old** operator's address (via `request_commission_internal`), then re-keys the whole `StakingContract` (including its `distribution_pool`) under the **new** operator address in the `Store.staking_contracts` map. [2](#0-1) 
Any subsequent `distribute()` call is made with the **new** operator address as the `operator` parameter, so the equality check `recipient == operator` in `distribute_internal` never matches the old operator's pending share. [3](#0-2) 

### Finding Description
`request_commission_internal` books commission for `old_operator` into `distribution_pool` via `add_distribution(operator, staking_contract, operator, commission_amount)`, where `operator == old_operator`, so the shareholder key stored is `old_operator`. [4](#0-3) 

`switch_operator()` then unlocks this commission (still `pending_inactive`, not yet withdrawable) and re-inserts the entire `StakingContract` struct — including the `distribution_pool` containing the `old_operator` share — under the new key `new_operator`: [5](#0-4) 

Once the stake pool's lockup expires, whoever calls `distribute(staker, new_operator)` invokes `distribute_internal(staker, new_operator, staking_contract)`. Inside, `operator == new_operator`, but the pending share's `recipient == old_operator`. The check `if (recipient == operator)` therefore fails, so the beneficiary substitution `recipient = beneficiary_for_operator(operator)` is skipped, and the funds are paid directly to the raw `old_operator` account instead of the beneficiary address `old_operator` had configured via `set_beneficiary_for_operator`. [6](#0-5) 

This mirrors the audited bug's root cause: a single identifier/parameter (`operator`) is reused across two different contexts (the identity that *earned* the share vs. the identity currently keying the map) that can diverge, silently breaking an intended routing invariant.

### Impact Explanation
This breaks the "beneficiary payout ... must not credit the wrong account" invariant. An operator who configures a beneficiary (e.g., a cold-storage or multisig address) for security/compliance reasons loses that protection for any commission accrued but not yet distributed at the moment the staker calls `switch_operator`. The funds are not stolen by a third party, but they are unconditionally routed to the operator's on-chain EOA/resource address instead of the address the operator explicitly designated to receive payouts — a wrong-account credit in the operator commission/beneficiary flow.

### Likelihood Explanation
This requires no special privilege beyond the staker's normal `switch_operator` call (a legitimate, frequently-documented staking-contract operation) combined with the old operator having previously called `set_beneficiary_for_operator` and having any unwithdrawn/unlocked commission pending at switch time — a very plausible sequence (commission requests followed by an operator change before the lockup fully clears is a normal operational pattern, not an edge case requiring privileged setup).

### Recommendation
`distribute_internal` should resolve the beneficiary based on the recorded shareholder address itself (`beneficiary_for_operator(recipient)` whenever `recipient` is a known/former operator of this pool), rather than comparing against the single `operator` parameter tied to the current map key. Alternatively, `switch_operator` should force a full `distribute_internal` for `old_operator` (not just `distribute_internal` before requesting the final commission) so no shares tagged with `old_operator` persist past the operator switch.

### Proof of Concept
1. Staker creates a staking contract with `operator1`; `operator1` calls `set_beneficiary_for_operator(beneficiary1)`. [6](#0-5) 
2. Stake pool earns rewards; staker calls `switch_operator(staker, operator1, operator2, new_commission)`. Inside, `request_commission_internal` books commission as a share for `operator1` in `distribution_pool`, then `stake::unlock_with_cap` puts it in `pending_inactive` (not yet withdrawable), and the contract is re-keyed to `operator2`. [7](#0-6) 
3. After the lockup period elapses, anyone calls `distribute(staker, operator2)`. `distribute_internal` iterates shareholders, finds `recipient == operator1 != operator2`, skips beneficiary substitution, and pays the commission directly to `operator1`'s address instead of `beneficiary1`. [8](#0-7) 

The existing test suite only exercises the case where `distribute()` is fully drained for `operator1` *before* `switch_operator` runs, which never reaches this branch and thus never exercises the divergence. [9](#0-8)

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Allows staker to switch operator without going through the lenghthy process to unstake.
    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
