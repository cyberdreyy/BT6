### Title
External ERC4626 vault `convertToAssets` is trusted as epoch yield, letting an unprivileged vault user inject phantom interest into tranche prices via a share-price donation - (File: `contracts/strategies/idle/ProgrammableBorrower.sol`)

### Summary
The Dosage bug class is "a value taken verbatim from an untrusted external response (`Content-Type`) is used to construct a security-critical output (the file path), escaping the intended boundary." The analog in idle-tranches is `ProgrammableBorrower._vaultNetInterest()`: it derives the epoch's vault PnL entirely from the external vault's self-reported `convertToAssets(shares)` price (`_currentVaultAssets()`), which an unprivileged user of that ERC4626 vault can manipulate by directly transferring underlying into the vault. For programmable-borrower deployments `isInterestMinted` is forced to `true`, so the fabricated delta is minted as real tranche yield at `stopEpoch`.

### Finding Description
- `ProgrammableBorrower._currentVaultAssets()` prices the entire vault position with `vault.convertToAssets(vault.balanceOf(address(this)))` (`ProgrammableBorrower.sol:546-549`). This is the "response-derived extension" of the analog: raw metadata returned by an external, attacker-influenced system, consumed without a sanity bound.
- `_vaultNetInterest()` (`ProgrammableBorrower.sol:337-347`) computes `netDelta = bufferedVaultDelta + earnedAssets - principalAssets`. Any increase in the vault's exchange rate after `onStartEpoch` snapshots `epochStartVaultAssets` (line 219) is reported as interest in `totalInterestDueNow()` (lines 330-334).
- `IdleCDOEpochVariant` reads `totalInterestDueNow()` at `stopEpoch` as the single pool-facing yield figure and, because `setIsInterestMinted(false)` reverts for programmable borrowers (`IdleCDOEpochVariant.sol:166-170`), mints strategy tokens against that reported interest — backing nothing real beyond the donation itself.
- Attack path (running epoch, minted-interest/programmable mode):
  1. Attacker is an ordinary user of the same external ERC4626 vault (explicitly in the allowed attacker set) and also a KYC-passed tranche holder.
  2. During the epoch, attacker directly transfers `X` underlying to the vault (not via `deposit`), raising `convertToAssets` for the ProgrammableBorrower's shares by `~X * PB_shares / totalShares`.
  3. Manager calls `stopEpoch`; `totalInterestDueNow()` includes the phantom delta, and the CDO mints interest as strategy tokens, raising both tranche prices / `getContractValue`.
  4. Attacker requests and claims withdrawal at the inflated tranche price, paid from real pool assets (borrower principal and other LPs' funds).
- Guards do not stop this: `_skimDonatedAssets()` only removes raw underlying sitting on the CDO, not price inflation inside the external vault; there is no cap, rate check, or two-source validation on `convertToAssets` anywhere in the accounting path; `onDefault`'s comment even notes `convertToAssets` is an externally controlled valuation.

### Impact Explanation
Direct theft / insolvency. Phantom vault yield is crystallized into tranche prices. Tranche holders exiting after the inflated `stopEpoch` redeem against assets the pool does not actually own beyond the donated amount; the last withdrawers absorb the shortfall (BB-first, then AA). Attacker profit = attacker tranche share × phantom interest − unrecoverable portion of the donation. If the ProgrammableBorrower dominates the vault's share supply and the attacker holds a large tranche position, the extracted inflated redemption can exceed the donation cost; otherwise the attack still manufactures an unbacked NAV and a loss borne by other LPs. The broken invariant is fair mint/burn plus donation isolation.

### Likelihood Explanation
Requires a programmable-borrower deployment whose ERC4626 sleeve vault accepts permissionless shareholding and has `convertToAssets` manipulable by direct asset transfers (true for standard ERC4626 vaults without virtual-share/donation hardening). Needs the attacker to be a tranche holder (KYC) or to induce exits, and a donation sized against the pool NAV. Conditions are realistic but configuration-dependent; severity is medium-high rather than certain-high.

### Recommendation
Bound the externally sourced price instead of trusting `convertToAssets` verbatim:
- Track vault cost-basis in shares/assets deposited (`epochDepositedToVault` already exists) and cap reported `interest` at a configured maximum (e.g., `maxVaultApr`-derived bound) per epoch.
- Alternatively value the position via a manipulation-resistant preview (`previewRedeem` with min-out checks at withdrawal time) or only realize vault PnL from actually withdrawn assets (`epochWithdrawnFromVault`), not mark-to-market of `convertToAssets`.

### Proof of Concept
Foundry fork PoC outline:
1. Deploy/fork `IdleCDOEpochVariant` + `IdleCreditVault` + `ProgrammableBorrower` wired to a standard ERC4626 vault (e.g., an OpenZeppelin ERC4626 mock or a real forked vault) holding `underlying` (USDC).
2. `depositAA` from KYC'd attacker (via `KeyringIdleWhitelist`/mock whitelist), owner sets `isProgrammableBorrower = true`, `startEpoch` → PB deposits idle funds into vault; `epochStartVaultAssets` snapshotted.
3. Attacker `underlying.transfer(vault, DONATION)` directly to the vault contract, inflating `convertToAssets`.
4. Warp past `epochEndDate`; manager calls `stopEpoch` → `totalInterestDueNow()` ≈ DONATION × PB share fraction is minted as interest; tranche `virtualPrice` rises.
5. Attacker `requestWithdraw` + `claimWithdrawRequest`; assert `underlying.balanceOf(attacker) - deposit > DONATION_cost` (profit when attacker tranche share is high) or assert `getContractValue > realBacking` insolvency gap and a second LP's claim reverting for insufficient funds.
