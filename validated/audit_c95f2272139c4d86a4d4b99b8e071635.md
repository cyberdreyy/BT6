### Title
`lastWithdrawRequest` overwritten by a later request lets a loss-adjusted receipt be re-claimed at par - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
Like the binder UAF — where `t->to_proc` is cleared under one path and the freed/stale object is then dereferenced under another — `IdleCreditVault` keeps only a single "latest request epoch" pointer (`lastWithdrawRequest[_user]`). A loss-adjusted receipt's epoch reference is silently overwritten when the user files a second `requestWithdraw`, so the haircut path can never trigger and the still-recorded receipt is later paid at par through the funded-claim path.

### Finding Description
`requestWithdraw` records each request per epoch (`withdrawsRequestsByEpoch[_user][currentEpoch]`) and aggregates it into `withdrawsRequests[_user]`, but stores only the newest epoch in `lastWithdrawRequest[_user]` (line 282, 292–293). When a `stopEpochWithDuration` realizes a loss, `collectWithdrawFunds` is called with `_amount < pendingBasis`, stores `lossRecoveryPriceByEpoch[epochNumber]`, and zeroes `pendingWithdraws` (lines 414–421) — i.e., the borrower only funds `pendingToFund`, the haircut amount is never sent (see `previewLossAdjustedWithdrawFunds`, lines 457–459).

The only path that applies that haircut is `_claimLossAdjustedWithdrawRequest`, which resolves the loss epoch exclusively through `lossEpoch = lastWithdrawRequest[_user]` and `lossRecoveryPriceByEpoch[lossEpoch]` (lines 789–794). If the user requests a second withdrawal in a later epoch, `lastWithdrawRequest` is overwritten, `lossRecoveryPriceByEpoch[newEpoch] == 0`, and the function returns 0 — the epoch-N haircut is unreachable. Execution then falls into `_claimFundedWithdrawRequest`, which pays `normalAmount = withdrawsRequests[_user]` — the full aggregate including the haircutted epoch-N receipt — at par (lines 338–349). The epoch gate `epochNumber <= lastWithdrawRequest[_user]` (line 326) passes once epoch N+1 ends, and nothing in `_claimFundedWithdrawRequest` re-checks `lossRecoveryPriceByEpoch` for the older epochs contained in the aggregate.

### Impact Explanation
The user is paid `withdrawsRequests[_user]` at par, but the reserve only received `pendingToFund = claimBasis_N * lossRecoveryPrice` for the epoch-N portion. The difference `claimBasis_N * (1 - lossRecoveryPrice)` is paid out of funded reserves belonging to other withdraw receipts (or, by extension, strategy-held underlying), breaking the one-receipt-one-payout and loss-waterfall invariants: the loss that `stopEpochWithDuration` assigned to pending receipts is socialized back onto funded claimants / the pool. The theft is bounded by the recorded loss share and is fully reproducible.

### Likelihood Explanation
All steps use unprivileged user calls plus normal owner/manager/borrower sequencing (a loss-adjusted `stopEpochWithDuration`, epoch restarts, ordinary `requestWithdraw`/`claimWithdrawRequest`). The code explicitly permits stacking requests across epochs without claiming (comment at lines 323–324), so the pointer-overwrite precondition requires nothing exotic. The only requirement is a partial-loss epoch, which is a designed flow (`stopEpochWithDuration(_lossAmount)`).

### Recommendation
Do not key the loss-adjusted claim off a single mutable `lastWithdrawRequest` pointer. Either iterate the user's per-epoch receipts (`withdrawsRequestsByEpoch`) and apply `lossRecoveryPriceByEpoch` per epoch inside `_claimFundedWithdrawRequest`, or disallow a new `requestWithdraw` while `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]] != 0` and the receipt is unclaimed. Analogously to the kernel fix, the epoch reference must be consumed under the same "lock" (same claim path) that pays it out.

// test/foundry/IdleCreditVault.t.sol context (reuse existing helpers:
// _depositWithUser, _startEpochAndCheckPrices, _stopEpochAndCheckPrices)
function testLossAdjustedReceiptEscapesHaircutViaSecondRequest() external {
    address user = makeAddr("user");
    _depositWithUser(user, 100_000 * ONE_SCALE, true);
    uint256 trancheBal = IERC20(AAtranche).balanceOf(user);

    // Epoch N: request withdraw of half.
    vm.prank(user);
    cdoEpoch.requestWithdraw(trancheBal / 2, address(AAtranche));
    uint256 lossEpoch = IdleCreditVault(address(strategy)).lastWithdrawRequest(user);

    // Loss-adjusted stop: borrower funds only pendingToFund; haircut stored at lossRecoveryPriceByEpoch[lossEpoch].
    // (mirror the stopEpochWithDuration(...) sequence used in IdleCDOEpochQueue.t.sol:817-830)
    _stopEpochWithLoss(/* partial loss, e.g. 50% */);

    // Epoch N+1: pool continues (stopEpochWithDuration set a new duration), user requests again.
    // This overwrites lastWithdrawRequest[user] -> N+1.
    vm.prank(user);
    cdoEpoch.requestWithdraw(trancheBal / 4, address(AAtranche));

    // Run and stop epoch N+1 normally (fully funded).
    _stopCurrentEpochWithApr(initialProvidedApr);

    // Claim: _claimLossAdjustedWithdrawRequest reads lastWithdrawRequest == N+1,
    // lossRecoveryPriceByEpoch[N+1] == 0 -> skipped. _claimFundedWithdrawRequest pays
    // withdrawsRequests[user] (epoch-N + epoch-N+1 receipts) at par.
    uint256 balPre = underlying.balanceOf(user);
    vm.prank(user);
    cdoEpoch.claimWithdrawRequest();
    uint256 paid = underlying.balanceOf(user) - balPre;

    // Expected: epoch-N portion should be paid at lossRecoveryPriceByEpoch[lossEpoch] < RECOVERY_FULL.
    // Actual: full par. Assert the overpayment equals claimBasis_N * (1 - lossRecoveryPrice).
    uint256 haircutLoss = /* epoch-N claimBasis */ (trancheBal / 2 /* + interest */)
        * (RECOVERY_FULL - strategy.lossRecoveryPriceByEpoch(lossEpoch)) / RECOVERY_FULL;
    assertGt(paid, /* par funding received by strategy */, "claim exceeded funded reserve");
    // The excess equals haircutLoss stolen from other funded receipts / strategy holdings.
}
