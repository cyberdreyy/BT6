### Title
Activation Registry `setAdmin` Performs Single-Step Admin Transfer With No Acceptance Step, Risking Permanent Loss of Admin Control - (File: crates/common/precompiles/src/activation/storage.rs)

### Summary
The Base-native `ActivationRegistry` precompile's `set_admin` function immediately overwrites the stored admin address with an attacker/caller-supplied `new_admin` in a single transaction, with no staging or acceptance step by the new admin. This is the same bug class flagged in the referenced Sherlock report against NounsBuilder's `Auction.unpause`: an ownership/admin transfer that completes unilaterally without the new party confirming receipt, creating risk that control is transferred to an unintended or unreachable address with no recovery path.

### Finding Description
`ActivationRegistryStorage::set_admin` validates the call (non-static, state-backed admin enabled, `new_admin` non-zero, caller authorized as current admin) and then writes the new admin directly to storage in the same call: [1](#0-0) 

This is a one-step transfer: as soon as the transaction lands, the previous admin's authority is gone and all subsequent authorization checks (`require_admin_caller`) resolve against `new_admin`, whether or not that address is capable of ever sending a transaction as itself (e.g., a contract without matching call logic, a precompile address, or a simple typo). There is no `pendingAdmin`/`finalizeUpdateAdmin` style two-step handshake for this admin role.

Notably, the same codebase already implements the correct two-step pattern elsewhere for an analogous "policy admin" role — `stage_update_admin` / `finalize_update_admin`, where the new admin must actively call `finalize_update_admin` to accept the transfer before it takes effect: [2](#0-1) [3](#0-2) 

This shows the design intentionally mitigates the exact bug class described in the report (unverified ownership/admin transfer) for the policy registry admin, but the activation registry's `set_admin` was not brought in line with that safer pattern.

### Impact Explanation
The `ActivationRegistry` admin is the sole authority gating activation/deactivation of core Base-native precompile features — `PolicyRegistry`, `B20Stablecoin`, and `B20Asset` — via `activate`/`deactivate`, both of which are gated by the same `require_admin_caller(admin_config)`: [4](#0-3) 

If `setAdmin` is executed with a `new_admin` value that cannot subsequently send a valid authenticated call (e.g., a contract address with no compatible logic, a multisig/precompile address that can never originate the required caller context, or simply the wrong EOA), admin authority over feature activation is permanently and irrecoverably lost — there is no fallback or recovery mechanism once `admin_config.state_enabled` is true and the stored admin is non-zero, since the zero-fallback path only applies when the stored value is exactly zero: [5](#0-4) 

This constitutes a permanent freezing of the ability to activate/deactivate protocol features (e.g., freezing the B20 stablecoin/asset or policy registry rollout state), matching the "permanent freezing of funds/functionality" impact bar for a High-severity finding.

### Likelihood Explanation
Likelihood requires the current admin to submit a `setAdminCall` with an incorrect or non-functional `new_admin` value. This can happen through operational error (typo, wrong checksum, wrong network's address reused) or through compromise of the admin key being used to intentionally set an unreachable address. Given the admin role is expected to rotate over time (the golden/system tests specifically exercise `setAdmin` rotation flows), the operation is a normal, reachable part of the precompile's lifecycle rather than a rare edge case: [6](#0-5) [7](#0-6) 

### Recommendation
Adopt the same two-step admin transfer pattern already implemented for the policy registry admin role. Add a `pending_admin` storage slot and split `set_admin` into `stage_update_admin` (current admin nominates `new_admin`) and `finalize_update_admin` (only callable by the pending admin, which finalizes the rotation), mirroring: [8](#0-7) 

### Proof of Concept
1. Chain is running with Cobalt active and `ActivationAdminConfig::state_backed(Some(admin))`.
2. Current admin calls `IActivationRegistry::setAdminCall { newAdmin: X }` where `X` is a contract address that has no function selector matching the calls used by `require_admin_caller`'s caller check (or simply an address whose private key is lost/unreachable), exactly as exercised by the existing test harness for legitimate rotation: [9](#0-8) 
3. `set_admin` executes in a single step — no acceptance from `X` is required — and `self.admin.write(new_admin)` commits immediately.
4. All subsequent `activate`/`deactivate`/`setAdmin` calls now check `require_admin_caller` against `X`, which can never satisfy it, permanently freezing feature-activation control for `PolicyRegistry`, `B20Stablecoin`, and `B20Asset`.

    /// Returns the effective activation admin address.
    ///
    /// When state-backed admin storage is disabled, this always returns the static fallback. When
    /// state-backed admin storage is enabled, a non-zero storage value wins; a zero storage value
    /// falls back to the static chain-config admin so Cobalt can replay historical Beryl activation
    /// transactions before the first admin rotation.
    ///
    /// [`Address::ZERO`] here means "no admin is set": it is not a valid admin address.
    /// Configuration-time validation rejects `Some(Address::ZERO)`, so in a correctly
    /// constructed chain spec the zero return always means `activation_admin_address` was
    /// `None`. Callers must not treat the zero return as a meaningful admin address.
    pub fn admin(&self, admin_config: ActivationAdminConfig) -> Result<Address> {
        if admin_config.state_enabled {
            let stored_admin = self.stored_admin()?;
            if !stored_admin.is_zero() {
                return Ok(stored_admin);
            }
        }
        Ok(admin_config.fallback.unwrap_or(Address::ZERO))
    }

    /// Sets the activation registry admin address.
    pub fn set_admin(
        &mut self,
        new_admin: Address,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }
        if !admin_config.state_enabled {
            return Err(BasePrecompileError::revert(
                IActivationRegistry::AdminStorageNotEnabled {},
            ));
        }
        if new_admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::ZeroAdminAddress {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        self.__initialize()?;
        self.admin.write(new_admin)?;
        self.emit_event(IActivationRegistry::AdminChanged {
            previousAdmin: caller,
            newAdmin: new_admin,
            caller,
        })?;

        Ok(())
    }

fn golden_stage_and_finalize_update_admin() {
    let mut s = fresh();
    let id = create(&mut s, ADMIN, ADMIN, PolicyType::ALLOWLIST);

    let (rev, _) = call_policy(
        &mut s,
        ADMIN,
        IPolicyRegistry::stageUpdateAdminCall { policyId: id, newAdmin: ADMIN2 }.abi_encode(),
    );
    assert!(!rev);
    let (_, pending) = call_policy(
        &mut s,
        OUTSIDER,
        IPolicyRegistry::pendingPolicyAdminCall { policyId: id }.abi_encode(),
    );
    assert_eq!(
        pending,
        Bytes::from(IPolicyRegistry::pendingPolicyAdminCall::abi_encode_returns(&ADMIN2))
    );
    assert_eq!(
        s.get_events(registry()).last().unwrap().topics()[0],
        IPolicyRegistry::PolicyAdminStaged::SIGNATURE_HASH
    );

    let (rev, _) = call_policy(
        &mut s,
        ADMIN2,
        IPolicyRegistry::finalizeUpdateAdminCall { policyId: id }.abi_encode(),

    let (_, admin) = call_policy(
        &mut s,
        OUTSIDER,
