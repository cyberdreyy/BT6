### Title
Gateway `Message.Validate()` binds no DON/subscriber authorization to `DonId`/`Sender`, enabling cross-DON request routing with only self-signed data - (File: `core/services/gateway/api/message.go`)

### Summary
`(m *Message) Validate()` only checks field lengths/format and that the signature is internally self-consistent (i.e., that `Body.Sender` can be recovered from the signature over the attacker-chosen `DonId`/`Receiver`/payload) — it never checks that the recovered signer is actually a permitted party for that `DonId`. The gateway then routes purely by `msg.Body.DonId` to the corresponding `Handler`, and the legacy web-API handler forwards the request to every member of that DON without any allowlist/subscriber check, as its own code comment admits.

### Finding Description
`Message.Validate()` in `core/services/gateway/api/message.go` performs only structural checks and signature recovery: [1](#0-0) 

Because `DonId` is one of the fields included in `GetRawMessageBody` that gets signed, an attacker can always produce a "valid" signature over any `DonId`/`Receiver` they choose — they just sign with their own key. Validation only proves the message is self-consistent (signature matches sender for the exact bytes submitted, including the attacker-chosen `DonId`), not that the resulting `Body.Sender` is authorized to interact with that `DonId`: [2](#0-1) 

The gateway then routes the request purely by looking up the `DonId` string in its handler map, with no cross-check against the sender's actual DON membership/subscription: [3](#0-2) 

The resolved `Handler.HandleLegacyUserMessage` for that DON (e.g. the web-API capabilities handler) then forwards the message to **all members of the target DON** without checking the sender against any allowlist or subscription list — the code contains an explicit TODO acknowledging this gap: [4](#0-3) 

The corresponding test file also documents this as a known, unresolved gap ("pending question... where senders and rate limits are validated"): [5](#0-4) 

Exploit flow: an attacker holding a valid signing key registered only with DON-B constructs `Message{Body: {DonId: "DON-A", Receiver: <DON-A address>, ...}}`, signs it with their own key (which is legitimate — `Sign`/`SignKS` sign whatever `DonId` is set in the struct), and POSTs it to the gateway. `Validate()` succeeds because the signature matches the signer over the submitted bytes. `gateway.ProcessRequest` looks up `g.handlers["DON-A"]` and invokes `HandleLegacyUserMessage`, which broadcasts the (untrusted) message to every DON-A node member — with only a `TODO: apply allowlist and rate-limiting here` comment marking the missing check.

### Impact Explanation
This is a request-impersonation / allowlist-bypass class finding: a legitimate subscriber of DON-B can inject signed messages that are dispatched to DON-A's node members and processed as if from an authorized party, since neither `Validate()` nor the legacy handler enforce that the extracted `Sender` is a registered/authorized participant for the target `DonId`. This can lead to unauthorized triggering of workflow/webhook processing on DON-A nodes by a party that was never subscribed there.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only a valid ECDSA signing key that is legitimately registered on any DON (DON-B), no special role or admin access. The attack is deterministic and repeatable — sign any message with `DonId` set to the target DON and POST to the gateway ingress endpoint. It is fully client-side reachable and requires no host/operator access.

### Recommendation
After `Validate()` succeeds and the handler for `Body.DonId` is resolved, add an explicit authorization step (in `gateway.ProcessRequest` or in `Handler.HandleLegacyUserMessage`) that checks the recovered `Body.Sender` against a per-DON allowlist/subscriber registry before dispatching to DON members, resolving the outstanding `TODO: apply allowlist and rate-limiting here` in `core/services/gateway/handlers/capabilities/handler.go`.

### Proof of Concept
Go handler-level integration test plan:
1. Configure two `handler` instances (DON-A, DON-B) as in `handler_test.go`'s `setupHandler`, each with distinct `donConfig.Members`.
2. Generate a signing key `attackerKey` that is only ever registered/expected as a member/subscriber of DON-B (not DON-A).
3. Build `msg := api.Message{Body: {DonId: "DON-A", Method: MethodWebAPITrigger, Receiver: <donA addr>, Payload: validTriggerPayload}}`; call `msg.Sign(attackerKey)`.
4. Assert `msg.Validate()` returns `nil` (proving Validate accepts cross-DON forged messages).
5. Call `gateway.ProcessRequest` (or directly `donAHandler.HandleLegacyUserMessage`) with `msg` and a mock `DON` for DON-A; assert `don.SendToNode` is invoked for DON-A's members (expected: should be rejected/blocked because `attackerKey` is not an authorized sender for DON-A, but the current code forwards it).
6. Add a mocked/subscriber-tracking allowlist to show no rejection occurs — confirming the routing/authorization gap.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func GetRawMessageBody(msgBody *MessageBody) [][]byte {
	alignedMessageId := make([]byte, MessageIdMaxLen)
	copy(alignedMessageId, msgBody.MessageId)
	alignedMethod := make([]byte, MessageMethodMaxLen)
	copy(alignedMethod, msgBody.Method)
	alignedDonId := make([]byte, MessageDonIdMaxLen)
	copy(alignedDonId, msgBody.DonId)
	alignedReceiver := make([]byte, MessageReceiverLen)
	copy(alignedReceiver, msgBody.Receiver)
	return [][]byte{alignedMessageId, alignedMethod, alignedDonId, alignedReceiver, msgBody.Payload}
}
