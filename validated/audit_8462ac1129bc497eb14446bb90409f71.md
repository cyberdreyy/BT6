### Title
Missing per-instance authorization check in `VaultController.ExportDKGResult` allows any authenticated caller to harvest DKG result packages by guessing `instanceId` - (File: core/web/vault_controller.go)

### Finding Description
`VaultController.ExportDKGResult` at `core/web/vault_controller.go` decodes the request body into `ExportDKGResultRequest{InstanceID string}`, validates only that `InstanceID` is non-empty, and then directly queries the store with the attacker-supplied value: [1](#0-0) 

There is no check anywhere in the function that ties the requesting session/API token/role to the specific `InstanceID` being requested — the lookup via `vault.NewVaultORM(vc.App.GetDB()).ReadResultPackage(...)` is performed unconditionally for any `InstanceID` the caller supplies, and on success the raw `ReportWithResultPackage` bytes (hex-encoded) are returned to the caller: [2](#0-1) 

This is identical in structure to `VerifyDKGResult`, which similarly performs no ownership/authorization check on `InstanceID` before reading and processing the stored package: [3](#0-2) 

Since `InstanceID` values are plain strings supplied by the DKG/vault plugin (and stored keyed by that string in the `dkg_results` table per `core/store/migrate/migrations/0278_create_dkg_results_table.sql` and `core/services/ocr2/plugins/vault/orm.go`), any caller who can reach this route and who can guess or enumerate an `InstanceID` (e.g., sequential, deterministic, or otherwise predictable IDs derived from job/DON identifiers) can retrieve DKG result packages belonging to other jobs/instances that they have no legitimate relationship to.

### Impact Explanation
A successful export discloses `ReportWithResultPackage`, the serialized DKG result/report used by the vault capability. Because the endpoint returns this to any caller supplying a valid instance ID with no ownership check, this is a cross-tenant/cross-job data disclosure vulnerability — matching the "isolation across jobs/instances" invariant explicitly called out in the question, and Chainlink's bounty class of unauthorized disclosure of sensitive node/job data.

### Likelihood Explanation
The precondition is that the caller can reach the route at all (i.e., is an authenticated web-API caller) and can determine or guess a valid `InstanceID` string. The function itself performs no authorization scoping by design, so exploitation is fully repeatable and requires no elevated privilege beyond whatever base authentication the route mandates — there is no additional instance-level ACL. I was not able to fully confirm from available context whether the route registration in `core/web/router.go` restricts this endpoint to an admin-only role or merely requires any authenticated session; that detail affects exact severity but does not change the fact that the handler itself has no per-instance authorization logic.

### Recommendation
Add an authorization layer to `ExportDKGResult` (and `VerifyDKGResult`) that verifies the requesting principal is entitled to the specific `InstanceID` (e.g., by associating instances with the job/DON that owns them and checking the caller's role/ownership against that mapping) before calling `ReadResultPackage`. Additionally consider restricting this route to an admin-only role given the sensitivity of DKG result packages, and avoid using unauthenticated/predictable instance identifiers as the sole access key.

### Proof of Concept
1. Seed two DKG result packages for `InstanceID` "A" and "B" via `vault.NewVaultORM(db).WriteResultPackage(...)`, representing two different jobs/tenants.
2. Using a single low-privileged HTTP session/token, `POST /v2/vault/dkg_results/export` with `{"instanceId":"A"}`, then again with `{"instanceId":"B"}`.
3. Assert that both requests succeed and return the respective `ReportWithResultPackage` hex payloads to the same caller, with no authorization error, demonstrating that the caller can harvest any instance's DKG result by iterating `InstanceID` values.
4. Compare against expected behavior: only requests for instances owned by/associated with the caller's job or credential should succeed; others should return 403/404 for authorization reasons (not merely "not found" for non-existent IDs).

func (vc *VaultController) VerifyDKGResult(c *gin.Context) {
	var req VerifyDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" || req.MasterPublicKey == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId and masterPublicKey are required"))
		return
	}

	keys, err := vc.App.GetKeyStore().DKGRecipient().GetAll()
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}
	if len(keys) == 0 {
		jsonAPIError(c, http.StatusBadRequest, errors.New("no DKG recipient key found"))
		return
	}
	if len(keys) > 1 {
		jsonAPIError(c, http.StatusBadRequest, errors.New("multiple DKG recipient keys found"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	err = vaultcap.VerifyDKGResult(v.ReportWithResultPackage, req.MasterPublicKey, keys[0])
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("DKG result verification failed: %w", err))
		return
	}

	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewVerifyDKGResultResource(shaStr), "verifyDKGResult")
}

	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
