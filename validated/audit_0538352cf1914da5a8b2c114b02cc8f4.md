### Title
`isPathAGitDirectory` fails to detect `.git` paths reached via `..` traversal, and `ExtractZipArchive` performs no path-confinement (Zip Slip) letting archive entries write outside the extraction root - ([File: helpers/archives/path_check_helper.go], [File: helpers/archives/zip_extract.go])

### Summary
`isPathAGitDirectory` only checks whether `filepath.Clean(path)`'s first path segment equals `.git`, but `filepath.Clean` does not collapse a leading `..` segment on a relative path, so an entry like `../.git/hooks/pre-commit` is never flagged as a git path. Independently, and more importantly, `ExtractZipArchive`/`extractZipFile` in `zip_extract.go` never validates or confines `file.Name` before calling `os.Mkdir`, `os.MkdirAll(filepath.Dir(file.Name))`, `os.OpenFile`, or `os.Symlink`, so any zip entry with `../` segments is extracted at whatever path it resolves to, which is a classic Zip Slip path-traversal bug.

### Finding Description
`isPathAGitDirectory` (`helpers/archives/path_check_helper.go:13-19`) does:
```go
parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
if len(parts) > 0 && parts[0] == ".git" { return true }
```
For an entry name `../.git/hooks/pre-commit`, `filepath.Clean` cannot remove the leading `..` (there is no preceding real segment to cancel it against), so the cleaned result is `../.git/hooks/pre-commit`, and `parts[0]` is `..`, not `.git`. This means `errorIfGitDirectory` returns `nil` and `printGitArchiveWarning` never fires for such an entry — the git-warning check is bypassable by prefixing any `.git`-based traversal name with `..`.

However, this warning is only a `logrus.Warn` diagnostic in `ExtractZipArchive` (`helpers/archives/zip_extract.go:89-91`) — it does not block extraction or otherwise change program state (`tracker.actionable(err)` only controls whether the message prints, not whether `extractZipFile` runs). So bypassing this check has no operational impact by itself.

The real issue is that `extractZipFile` (`helpers/archives/zip_extract.go:41-83`) and its helpers (`extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`) use `file.Name` verbatim in `os.Mkdir`, `os.MkdirAll(filepath.Dir(file.Name), 0o777)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(string(data), file.Name)` with no check that the resolved path stays within the intended extraction directory (no `filepath.Rel`/prefix check against a base directory, no rejection of `..` segments). This is the well-known "Zip Slip" vulnerability: any zip archive entry such as `../../etc/cron.d/evil` or `../../../home/gitlab-runner/.ssh/authorized_keys` will be written outside the extraction root when the archive is extracted, entirely independent of whether the entry name also matches `.git`.

### Impact Explanation
An attacker who controls a cache or artifact zip archive consumed by the runner (job cache push/pull, artifact download) can craft entry names with `../` segments to write or overwrite arbitrary files reachable by the runner process's filesystem permissions, outside the job's build/cache directory. This violates the "File operations must stay within intended build/cache/artifact roots" invariant. Depending on runner user/permissions and executor type, this could allow overwriting files on the host/build machine (e.g., shell executor) reachable by the runner's OS user, which is a genuine confinement-boundary violation, not merely a documented admin trust choice, because the attacker is only a job author supplying archive content, not an admin.

### Likelihood Explanation
Fully attacker-controlled: a job author controls the contents and file names inside artifacts/cache they push, and the runner will later extract that archive (e.g., on cache restore for another job run, or via `ExtractZipFile`/`ExtractZipArchive`). No special privileges are needed beyond authoring a pipeline. This is directly reachable and repeatable — no additional preconditions such as admin misconfiguration are required. The `.git`-detection bypass itself is a real but low-impact logic gap (cosmetic warning suppression); the substantial, concretely exploitable issue is the total absence of path confinement in `zip_extract.go`.

### Recommendation
1. In `extractZipFile`/`ExtractZipArchive`, resolve `file.Name` against the destination root with `filepath.Join(destRoot, file.Name)`, then verify via `filepath.Rel` (or an equivalent prefix check after `filepath.Clean`) that the resulting path is still inside `destRoot`; reject/skip entries that escape.
2. Reject entries whose cleaned path starts with `..` or is absolute, before any file-system operation (`Mkdir`, `MkdirAll`, `OpenFile`, `Symlink`).
3. Fix `isPathAGitDirectory` to also treat any cleaned path containing a `.git` component anywhere (not just as `parts[0]`) as a git path, and to explicitly flag paths that resolve outside the archive root (leading `..`) as suspicious, in addition to the extraction-root confinement fix above (this check alone doesn't stop extraction, so the confinement fix is required regardless).

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    zipPath := filepath.Join(tmpDir, "evil.zip")

    // build a zip with an entry "../../evil.txt" (relative to intended extraction dir)
    f, _ := os.Create(zipPath)
    zw := zip.NewWriter(f)
    w, _ := zw.Create("../../evil.txt")
    _, _ = w.Write([]byte("pwned"))
    _ = zw.Close()
    _ = f.Close()

    extractDir := filepath.Join(tmpDir, "job", "extract")
    _ = os.MkdirAll(extractDir, 0o777)
    origWD, _ := os.Getwd()
    _ = os.Chdir(extractDir)
    defer os.Chdir(origWD)

    err := archives.ExtractZipFile(zipPath)
    require.NoError(t, err)

    // Assert the file escaped extractDir, landing two levels up
    escapedPath := filepath.Join(tmpDir, "job", "evil.txt") // actually lands outside "extract"
    _, statErr := os.Stat(filepath.Join(tmpDir, "evil.txt"))
    require.NoError(t, statErr, "file should not have escaped extraction root, but it did")
}
```

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
