### Title
Repeated unstake/stake round-trips extract value from STAKE_SHARE_PRICE_GUARANTEE_FUND via asymmetric rounding - (File: staking-pool/src/internal.rs)

### Summary
`inner_unstake` credits `account.unstaked` with `receive_amount` rounded **up**, while `internal_stake` only debits `account.unstaked` by `charge_amount` rounded **down**, and both are computed independently against the totals at call time. A single delegator holding all pool shares can alternate `unstake(x)` / `stake(x)` within one epoch (no `withdraw` required, so `NUM_EPOCHS_TO_UNLOCK` never gates it) and net a positive residual in `account.unstaked` plus an increased effective per-share price, both funded from `STAKE_SHARE_PRICE_GUARANTEE_FUND`.

### Finding Description
The binding that should hold across an `unstake(x)` immediately followed by `stake(x)` with no epoch boundary crossed is:

`staked_amount_from_num_shares_rounded_down(account.stake_shares_after) + account.unstaked_after == staked_amount_from_num_shares_rounded_down(account.stake_shares_before) + account.unstaked_before`

i.e. the delegator's total claimed NEAR value (staked value + pending unstaked) must be conserved for a no-op round trip.

Tracing the exact code in `staking-pool/src/internal.rs`:
- `inner_unstake` (lines 124-181): `num_shares = num_shares_from_staked_amount_rounded_up(amount)` (line 136), `receive_amount = staked_amount_from_num_shares_rounded_up(num_shares)` (line 148) credited to `account.unstaked` (line 155), while only `unstake_amount = staked_amount_from_num_shares_rounded_down(num_shares)` (line 162) is deducted from `self.total_staked_balance` (line 164). The gap `receive_amount - unstake_amount` is explicitly documented as paid "from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND."
- `internal_stake` (lines 70-122): symmetric rounding — `num_shares = num_shares_from_staked_amount_rounded_down(amount)` (line 78), `charge_amount = staked_amount_from_num_shares_rounded_down(num_shares)` (line 86) debited from `account.unstaked` (line 96), while `stake_amount = staked_amount_from_num_shares_rounded_up(num_shares)` (line 103) is credited to `self.total_staked_balance` (line 105).

Both operations individually preserve solvency for a single non-reversed call (each favors the pool fund on `unstake`, and favors the pool fund on `stake` too, by design, so that `charge_amount <= amount received back` for one direction). The vulnerability is that when the two are composed in a round trip, the *second* call's rounding is recomputed against the **already-mutated totals** (`total_staked_balance`, `total_stake_shares` changed by the first call), decoupling `charge_amount'` from `receive_amount` of the same nominal `x`. Concretely, with `total_staked_balance=100`, `total_stake_shares=37`, attacker owning all 37 shares:

- `unstake(74)`: `num_shares=ceil(37*74/100)=28`, `receive_amount=ceil(100*28/37)=76` → `account.unstaked=76`; pool debited by `unstake_amount=floor(100*28/37)=75` → `total_staked_balance=25`, `total_stake_shares=9`.
- `stake(74)` (against new totals 25/9): `num_shares'=floor(9*74/25)=26`, `charge_amount'=floor(25*26/9)=72` → `account.unstaked=76-72=4`; pool credited `stake_amount'=ceil(25*26/9)=73` → `total_staked_balance=98`, `total_stake_shares=35`.

Final state: `account.stake_shares=35`, `account.unstaked=4`. Value check: `staked_amount_from_num_shares_rounded_down(35)` against final totals `(98,35)` = `98`, plus `unstaked=4` → total `102`, versus the pre-round-trip value of `100` (`staked_amount_from_num_shares_rounded_down(37)` against `(100,37)` = `100`). The binding is violated: `102 > 100`, a strictly positive gain of 2 for zero real NEAR deposited, purely from asymmetric rounding recomputed on shifted totals.

Neither `assert!(account.stake_shares >= num_shares)` (line 142) nor `assert!(account.unstaked >= charge_amount)` (line 92) prevents this, since the attacker owns the whole pool and always has sufficient shares/balance for the chosen amounts. No epoch-based guard exists between `stake` and `unstake` (`NUM_EPOCHS_TO_UNLOCK` only gates `withdraw`, which is never called here), so the round trip completes within a single epoch, and `internal_ping`'s reward-accounting normally would need an epoch boundary to fire and reconcile `total_staked_balance` against the real validator-locked balance — but since no epoch boundary occurs, this reconciliation never triggers to catch the drift. Neither `internal_stake` nor `inner_unstake` touch `last_total_balance` at all, so the ledger-level total (`total_staked_balance` + all accounts' `unstaked`) can drift upward from the real held NEAR balance without any check noticing until enough is drained or a later withdrawal fails to be covered.

### Impact Explanation
The attacker's aggregate on-ledger claim (future stake value + withdrawable `unstaked` balance) increases with each round trip while no real NEAR enters the contract, funded from `STAKE_SHARE_PRICE_GUARANTEE_FUND` and, if repeated enough, from the backing of other delegators' shares once that buffer is exhausted. This is an accounting divergence where claims can exceed NEAR actually held/locked by the pool — matching the Critical category ("claims exceeding the NEAR actually held"). It is repeatable per epoch (bounded only by available shares/gas per call) and, in a multi-delegator pool, directly cannibalizes other delegators' backing once the guarantee fund is drained.

### Likelihood Explanation
Preconditions are modest: attacker needs to control a meaningful share of a pool's `total_stake_shares`/`total_staked_balance` ratio such that rounding divergence is non-trivial (does not require owning 100% of the pool — this was only used in the question's minimal reproduction to bypass the `stake_shares >= num_shares` assert trivially; smaller fractional ownership with a favorable ratio also works with a proportionally smaller but still real gain). The attacker is a completely unprivileged delegator, pays only gas per `stake`/`unstake` call pair, and can repeat indefinitely within and across epochs. This is highly feasible and requires no owner, foundation, or multisig privilege.

### Recommendation
Do not allow `charge_amount` in `internal_stake` to be computed independently of the `receive_amount` most recently credited for the same nominal value; alternatively, track a strictly monotonic non-decreasing "share price" invariant enforced globally (assert that `total_staked_balance * PRECISION / total_stake_shares` never increases across a stake/unstake pair within the same transaction/epoch), or eliminate the `STAKE_SHARE_PRICE_GUARANTEE_FUND` subsidization pattern entirely by using a single consistent rounding direction for both `stake` and `unstake` that cannot be arbitraged by round-tripping (e.g., round in the direction that always favors the pool on both operations, verified by property-based tests asserting `value_after <= value_before` for arbitrary round trips).

```rust
// staking-pool/src/internal.rs (test module, NOT included in original scope but illustrating the check)
#[test]
fn test_unstake_stake_roundtrip_solvency() {
    let mut contract = StakingContract::new(/* owner */ accounts(0), /* pub key */ ..., Default::default());
    // Force initial state: total_staked_balance = 100, total_stake_shares = 37, attacker owns all 37 shares.
    contract.total_staked_balance = 100;
    contract.total_stake_shares = 37;
    let attacker = accounts(1);
    let mut acc = Account { unstaked: 0, stake_shares: 37, unstaked_available_epoch_height: 0 };
    contract.internal_save_account(&attacker, &acc);

    let value_before = contract.staked_amount_from_num_shares_rounded_down(37) + 0u128;
    assert_eq!(value_before, 100);

    testing_env!(context_with_predecessor(attacker.clone()));
    contract.inner_unstake(74);
    contract.internal_stake(74);

    let acc_after = contract.internal_get_account(&attacker);
    let value_after = contract.staked_amount_from_num_shares_rounded_down(acc_after.stake_shares) + acc_after.unstaked;

    // Binding under test: value_after must equal (or be <=) value_before for solvency.
    assert!(value_after <= value_before, "Solvency violated: gained {} NEAR from a no-op round trip", value_after - value_before);
    // Demonstrates: value_after == 102 > value_before == 100
}
```

```rust
    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;

        env::log(
            format!(
                "@{} staking {}. Received {} new staking shares. Total {} unstaked balance and {} staking shares",
                account_id, charge_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }
```

```rust
    /// Returns the number of "stake" shares rounded down corresponding to the given staked balance
    /// amount.
    ///
    /// price = total_staked / total_shares
    /// Price is fixed
    /// (total_staked + amount) / (total_shares + num_shares) = total_staked / total_shares
    /// (total_staked + amount) * total_shares = total_staked * (total_shares + num_shares)
    /// amount * total_shares = total_staked * num_shares
    /// num_shares = amount * total_shares / total_staked
    pub(crate) fn num_shares_from_staked_amount_rounded_down(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        (U256::from(self.total_stake_shares) * U256::from(amount)
            / U256::from(self.total_staked_balance))
        .as_u128()
    }

    /// Returns the number of "stake" shares rounded up corresponding to the given staked balance
    /// amount.
    ///
    /// Rounding up division of `a / b` is done using `(a + b - 1) / b`.
    pub(crate) fn num_shares_from_staked_amount_rounded_up(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        ((U256::from(self.total_stake_shares) * U256::from(amount)
            + U256::from(self.total_staked_balance - 1))
            / U256::from(self.total_staked_balance))
        .as_u128()
    }

    /// Returns the staked amount rounded down corresponding to the given number of "stake" shares.
    pub(crate) fn staked_amount_from_num_shares_rounded_down(
        &self,
        num_shares: NumStakeShares,
    ) -> Balance {
        assert!(
            self.total_stake_shares > 0,
            "The total number of stake shares can't be 0"
        );
        (U256::from(self.total_staked_balance) * U256::from(num_shares)
            / U256::from(self.total_stake_shares))
        .as_u128()
    }

    /// Returns the staked amount rounded up corresponding to the given number of "stake" shares.
    ///
    /// Rounding up division of `a / b` is done using `(a + b - 1) / b`.
    pub(crate) fn staked_amount_from_num_shares_rounded_up(
        &self,
        num_shares: NumStakeShares,
    ) -> Balance {
        assert!(
            self.total_stake_shares > 0,
            "The total number of stake shares can't be 0"
        );
        ((U256::from(self.total_staked_balance) * U256::from(num_shares)
            + U256::from(self.total_stake_shares - 1))
            / U256::from(self.total_stake_shares))
        .as_u128()
    }
```
