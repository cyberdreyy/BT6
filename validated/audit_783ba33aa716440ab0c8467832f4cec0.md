## Title
Stale confirmations from removed members allow execution below `num_confirmations` live members - (`multisig2/src/lib.rs`)

### Summary
`delete_member` only purges pending requests and confirmations that were *originated* by the removed member; it never scans other still-pending requests to strip confirmation entries the removed member already cast as a *confirmer*. Because `confirm` decides execution purely from `confirmations.len()`, a request can later execute with fewer live-member confirmations than `num_confirmations`, allowing an unprivileged combination of member actions (or a member colluding with timing) to move funds out of the multisig with an under-threshold quorum.

### Finding Description
The invariant that should hold is:
`num_confirmations(request) == |{ c in confirmations[request_id] : c is a current member at execution time }|`

but the contract only enforces `confirmations.len() + 1 >= num_confirmations` in `confirm`: [1](#0-0) 

`delete_member` removes only requests whose *original signer* (`r.member`) equals the removed member, clearing confirmations for *those* requests, but it does not touch `confirmations` entries the removed member added while confirming requests originated by someone else: [2](#0-1) 

Exploit flow with members `{A, B, C, D}` and `num_confirmations = 3`:
1. Member `B` opens request `R` (e.g. `Transfer` to an arbitrary `receiver_id`, or any self-request action needing `assert_self_request` with `receiver_id = env::current_account_id()`).
2. Member `C` calls `confirm(R)` — `confirmations[R] = {C}` (1/3, not yet executed).
3. Separately, a `DeleteMember { member: C }` self-request is created and confirmed by 3 members (`A`, `B`, `D`), and executes via `execute_request` → `delete_member`, removing `C` from `self.members`. This loop only deletes requests where `r.member == C` (requests *created* by C); `R` was created by `B`, so it and its confirmation set (still containing `C`) survive untouched.
4. `B` then calls `confirm(R)` → `confirmations[R] = {C, B}`.
5. `A` calls `confirm(R)` → `confirmations.len() (2) + 1 >= num_confirmations (3)` is true, so `remove_request` + `execute_request` fire, even though the only currently-live confirmers are `A` and `B` — two members, not three.

`assert_valid_request` and `current_member()` only check that the *caller* of the current `confirm` call is a member; they never re-validate the accounts/keys already recorded inside the `confirmations` set. `assert_self_request` is irrelevant to this defect — it only gates whether specific action types are allowed to target `env::current_account_id()`, and is satisfied trivially by the attacker choosing `receiver_id = env::current_account_id()` for actions that require it (or is simply not called for plain `Transfer` actions).

### Impact Explanation
An attacker (or a set of colluding members, one of which is subsequently removed) can get a `Transfer`, `AddKey`, `FunctionCall`, or other fund/permission-moving request executed with only `num_confirmations - 1` (or fewer) live members' approval. This directly breaks the core multisig security guarantee and can move NEAR out of the multisig account to a party never entitled to it — Critical severity per the stated impact categories ("a multisig request executed below `num_confirmations` live members").

### Likelihood Explanation
Requires only that the multisig has more than `num_confirmations` members (so a member can be removed while confirmations remain below `num_confirmations`), and that at least one member is later removed while a foreign-originated request holds their confirmation — an ordinary operational sequence (member rotation/offboarding), not an exotic attack. No special privilege is needed beyond normal member behavior in `confirm`/`add_request`; the race window is simply "confirm before removal, keep confirming after removal." It is fully repeatable per removal event and per pending request.

### Recommendation
On `delete_member`, iterate over all `self.requests` entries and remove the deleted member's identifier from every request's confirmation `HashSet`, not just requests it authored. Alternatively, at execution time in `confirm`, filter `confirmations` to only those entries whose corresponding `MultisigMember` is currently `self.members.contains(...)` before comparing the count to `num_confirmations`.

    // 2. key1 (an AccessKey member) confirms R -> confirmations[R] = {key1}

    // 4. bob confirms R -> confirmations[R] = {key1, bob}

    //    yet c.requests no longer contains R (it executed) — invariant violated.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
