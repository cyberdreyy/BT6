### Title
`accountSubscribe` fails to notify account closure when account was last modified at slot 0 - ([File: rpc/src/rpc_subscriptions.rs])

### Summary
`filter_account_result` in `rpc/src/rpc_subscriptions.rs` uses `Slot` value `0` both as the sentinel for "account does not exist" and as a legitimate slot number (the genesis/first slot). When an account's real last-modified slot is `0` and the account is later closed, the resulting "not found" default (`0`) collides with the previous notified slot (`0`), so the equality check that gates notification incorrectly treats the closure as "no change" and suppresses the notification, exactly mirroring the reported bug class of treating a coincidental zero as "no change occurred."

### Finding Description
`filter_account_result` decides whether to notify a subscriber by comparing the account's current modified slot against the slot it was last notified for: [1](#0-0) 

```rust
fn filter_account_result(
    result: Option<(AccountSharedData, Slot)>,
    params: &AccountSubscriptionParams,
    last_notified_slot: Slot,
    bank: Arc<Bank>,
) -> (Option<UiAccount>, Slot) {
    // If the account is not found, `last_modified_slot` will default to zero and
    // we will notify clients that the account no longer exists if we haven't already
    let (account, last_modified_slot) = result.unwrap_or_default();

    // If last_modified_slot < last_notified_slot this means that we last notified for a fork
    // and should notify that the account state has been reverted.
    let account = (last_modified_slot != last_notified_slot).then(|| { ... });
    (account, last_modified_slot)
}
```

The comment itself acknowledges the design intent: "not found" is represented by defaulting `last_modified_slot` to `0` (`Slot::default()`), and the client is supposed to be notified "if we haven't already" — i.e., whenever `last_modified_slot != last_notified_slot`.

The bug: `last_notified_slot` for a subscription is seeded from `initial_last_notified_slot`, which calls `bank.get_account_modified_slot(&params.pubkey)`: [2](#0-1) 

If the account genuinely exists and was last modified at slot `0` (e.g. it was created/funded in the genesis block, which is a normal, common occurrence for well-known accounts, sysvars, or accounts funded in genesis config), then `last_notified_slot` for that subscription starts at the real value `0` — not as a "no value" sentinel, but as an actual, legitimate slot number.

Later, if that account is closed (e.g., all lamports drained so it's removed from the accounts index), `bank.get_account_modified_slot` returns `None`, and `result.unwrap_or_default()` in `filter_account_result` produces `last_modified_slot == 0` as well, this time as a "not found" sentinel rather than a real slot.

Since `last_modified_slot (0) == last_notified_slot (0)`, the `(last_modified_slot != last_notified_slot).then(...)` check evaluates false, so `account` becomes `None` — the notification carries no update. Nothing is sent to the client; `check_commitment_and_notify` treats this as "not notified" and does not update `last_notified_slot`: [3](#0-2) 

The subscriber is silently left believing the account still exists in its last-known state, and every subsequent poll will keep computing the same colliding `0 == 0` comparison (since `last_notified_slot` never advances away from `0` for this subscription), so the closure is never reported at any future point either.

### Impact Explanation
This is a query/subscription (`accountSubscribe` via the JSON-RPC pubsub, an unprivileged, remotely reachable API) returning stale/incorrect account state to a client. A client relying on `accountSubscribe` notifications (e.g., wallets, exchanges, bots tracking balance/closure of an account created at genesis or any account whose most recent write happens to land at slot 0) will never learn that the account was closed. This matches the allowed "wrong-slot/fork/account data returned" impact category — the validator process itself is not corrupted, but the RPC subscription protocol silently drops a state transition it is contractually supposed to report, producing an incorrect view of on-chain state for any unprivileged client. It is a genuine logic defect analogous to the reported "zero treated as no-change" class, reachable purely through normal client usage of a public RPC subscription, no privileged/validator role required.

### Likelihood Explanation
Likelihood depends on an account whose true last-modified slot is exactly `0` (genesis) later being closed while a live `accountSubscribe` websocket subscription is open for it, and the same collision recurring on every subsequent check since `last_notified_slot` is never advanced. Genesis-created/funded accounts (e.g., pre-funded test/faucet accounts, well-known program-owned accounts initialized in `genesis_config`) are a normal, reproducible pattern, especially on devnets/testnets and local validators, making this readily triggerable without any special access.

### Recommendation
Do not overload `Slot` `0` as a sentinel for "account not found." Change `result.unwrap_or_default()`'s tuple type to explicitly track existence (e.g., `Option<Slot>` for `last_modified_slot`, or an explicit `existed: bool` flag) so that "the account transitioned to non-existent" is always distinguishable from "the account was last modified at slot 0," and gate notification on that explicit existence-change signal rather than a raw equality comparison of `Slot` values that can coincidentally be zero on both sides.

### Proof of Concept
1. Start a local validator whose genesis config funds/creates an account `A` (so `bank.get_account_modified_slot(&A)` returns `Some((account, 0))` — a legitimately zero last-modified slot).
2. Open a JSON-RPC pubsub `accountSubscribe` for `A`. In `NotificationEntry::Subscribed` processing, `initial_last_notified_slot` seeds `last_notified_slot = 0` for this subscription (per `rpc_subscriptions.rs:454-478`).
3. Drain all lamports out of `A` in a later slot so it is removed from the accounts index (`bank.get_account_modified_slot(&A)` now returns `None`).
4. On the next `notify_watchers` pass for this subscription, `filter_account_result` computes `result.unwrap_or_default()` → `last_modified_slot = 0`; since `last_notified_slot` is also `0`, `(0 != 0)` is `false`, so no `UiAccount` update is produced and the closure notification is never sent.
5. The subscriber never receives an `accountNotification` reflecting the account's closure, for the life of the subscription — confirmable by comparing `getAccountInfo` (which correctly returns `null`) against the missing pubsub notification.

fn check_commitment_and_notify<P, S, B, F, X, I>(
    params: &P,
    subscription: &SubscriptionInfo,
    bank_forks: &RwLock<BankForks>,
    slot: Slot,
    bank_method: B,

    notifier: &RpcNotifier,
    is_final: bool,

where
    S: Clone + Serialize,
    B: Fn(&Bank, &P) -> X,
    F: Fn(X, &P, Slot, Arc<Bank>) -> (I, Slot),
    X: Clone + Default,
    I: IntoIterator<Item = S>,
{
    let mut notified = false;
    let bank = bank_forks.read().unwrap().get(slot);
    if let Some(bank) = bank {
        let results = bank_method(&bank, params);
        let mut w_last_notified_slot = subscription.last_notified_slot.write().unwrap();
        let (filter_results, result_slot) =
            filter_results(results, params, *w_last_notified_slot, bank);
        for result in filter_results {
            notifier.notify(
                RpcResponse::from(RpcNotificationResponse {
                    context: RpcNotificationContext { slot },
                    value: result,
                }),
                subscription,
                is_final,
            );
            *w_last_notified_slot = result_slot;
            notified = true;
        }
    }

    notified
}

fn initial_last_notified_slot(
    params: &SubscriptionParams,
    bank_forks: &RwLock<BankForks>,
    block_commitment_cache: &RwLock<BlockCommitmentCache>,
    optimistically_confirmed_bank: &RwLock<OptimisticallyConfirmedBank>,
) -> Option<Slot> {
    match params {
        SubscriptionParams::Account(params) => {
            let slot = if params.commitment.is_finalized() {
                block_commitment_cache
                    .read()
                    .unwrap()
                    .highest_super_majority_root()
            } else if params.commitment.is_confirmed() {
                optimistically_confirmed_bank.read().unwrap().bank.slot()
            } else {
                block_commitment_cache.read().unwrap().slot()
            };

            let bank = bank_forks.read().unwrap().get(slot)?;
            Some(bank.get_account_modified_slot(&params.pubkey)?.1)
        }
        _ => None,
    }
}
