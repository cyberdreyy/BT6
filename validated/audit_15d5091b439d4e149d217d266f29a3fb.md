### Title
Transient `getFundsFromBorrower` failure inside `stopEpoch`'s try/catch permanently defaults a solvent pool with no replay path - (File: `contracts/IdleCDOEpochVariant.sol`)

### Summary
`IdleCDOEpochVariant._stopEpoch` wraps the borrower pull in `try this.getFundsFromBorrower(...) { ... } catch { _handleBorrowerDefault(...) }`. The catch treats any failure of the inner `transferFrom` — including gas exhaustion inside the forwarded 63/64 sub-call — as a real borrower default and sets `defaulted = true`. That flag is terminal: `restoreOperations()` reverts when `defaulted` is set, `startEpoch` reverts, and all lender funds can only exit through the loss-haircut `finalizeDefault` recovery path. This mirrors bug M-1: the outer transaction finalizes state (permanent default) even though the inner call failed transiently and there is no mechanism to replay it.

### Finding Description
In `contracts/IdleCDOEpochVariant.sol` at the end of `_stopEpoch` (lines ~408-505), the success/failure of the epoch hinges on one external self-call:

```solidity
try this.getFundsFromBorrower(_amountToPullFromBorrower + _pendingWithdraws) {
    // ... full success path
} catch {
    _handleBorrowerDefault(_amountToPullFromBorrower + _pendingWithdraws);
}
```

`getFundsFromBorrower` (lines 550-553) is a thin wrapper around `_transferUnderlyingsFrom(_borrower(), address(this), _amount)`. Because it is invoked as an external call it receives at most 63/64 of the gas remaining at that point — after `prepareStopEpochWithApr0`, `_accrueManagementFee`, `previewLossAdjustedWithdrawFunds`, and the programmable-borrower `onStopEpoch` hook have already consumed gas. If the remaining gas is enough to enter the try and run `_handleBorrowerDefault`, but not enough for the `transferFrom` (or the transfer transiently fails for any other reason, e.g. a paused-token or allowance hiccup), execution lands in `catch`.

`_handleBorrowerDefault` (lines 577-599) then:
- sets `defaulted = true`,
- pauses the contract,
- clears `isEpochRunning`,
- disables both withdraw-request flags.

`restoreOperations` (line 622) reverts on `defaulted`, and nothing else clears the flag. The borrower — who was fully funded and approved — is now locked out of the normal repay/close path, and lenders' only exit is `finalizeDefault`, which applies a recovery haircut to both active tranches and pending withdraw receipts (`_claimDefaultedWithdrawRequest` in `IdleCreditVault.sol` lines 772-784, paying `claimBasis * defaultRecoveryPrice / RECOVERY_FULL`). The same pattern exists in `getInstantWithdrawFunds` (lines 566-573) and `startEpoch`'s `sendFundsToBorrower` try/catch (lines 295-303), which can also finalize `defaulted` on a transient transfer failure.

The broken invariant is the M-1 invariant: an outer call records an irreversible outcome for a sub-call failure that should have been retryable. There is no `retryGetFunds` / repay-then-resume path; one atomic transaction decides "pull failed ⇒ permanent default."

### Impact Explanation
If the catch branch executes while the borrower is solvent, every lender's funds are frozen in the defaulted pool. Recovery requires `finalizeDefault`, which distributes only the recovered amount pro rata via `defaultRecoveryPrice` — any gap between the borrower's true obligation and the recovered escrow is a permanent loss, and even with full recovery lenders suffer a forced freeze and lose all subsequent yield (`_setScaledApr(0)`, `epochDuration = 0`). Loss magnitude: up to the full pool NAV (all AA + BB principal plus accrued interest) that must now flow through the recovery-haircut path.

### Likelihood Explanation
Low-to-medium. The direct trigger (narrow gas window where the sub-call OOGs but the catch completes) is the same "user/keeper supplied too little gas" scenario that M-1 established as realistic — gas estimation can be skewed by `prepareStopEpochWithApr0` settling APR0 buckets, management-fee accrual, and the programmable-borrower `onStopEpoch` ERC4626 withdraw, all of which make the pre-call gas consumption variable and hard to predict. Additionally, in programmable mode an unprivileged user of the borrower's ERC4626 vault can transiently drain vault liquidity; while `onStopEpoch` correctly bubbles that revert for retry, any residual failure surfacing inside `getFundsFromBorrower` itself (e.g. a token-side transfer revert) is converted into the permanent default rather than a retryable revert. The asymmetry — retryable failure vs. irreversible `defaulted` — is what makes this a defect rather than an operational inconvenience.

### Recommendation
Separate "definitely insolvent" from "transfer didn't succeed" so a transient pull failure is replayable:
- In the catch branch, do not call `_handleBorrowerDefault` unconditionally. Either let the revert bubble (remove the try/catch) and add an explicit, separately callable `handleBorrowerDefault()`/`markDefault()` function, or
- Keep the catch but record a `pendingDefault` state that must be confirmed by a second transaction verifying the borrower still lacks balance/allowance, giving operators a chance to retry the pull first, or
- Forward a fixed gas stipend sized to a plain ERC20 `transferFrom` (e.g. `this.getFundsFromBorrower{gas: G}(...)`) and verify post-catch that the failure was not OOG before defaulting.

Apply the same treatment to `getInstantWithdrawFunds` and the `sendFundsToBorrower` catch in `startEpoch`.

### Proof of Concept
Foundry fork test sketch (reuses the harness in `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testStopEpochTransientPullFailurePermanentlyDefaults() external {
    // standard setup: deposit AA/BB, honest borrower approved for the full pull
    uint256 amount = 10000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);
    _startEpochAndCheckPrices(0);

    uint256 expectedInterest = cdoEpoch.expectedEpochInterest();
    uint256 pending = IdleCreditVault(address(strategy)).pendingWithdraws();
    uint256 owed = expectedInterest + pending;
    // honest borrower: fully funded and approved
    deal(defaultUnderlying, borrower, owed);
    vm.prank(borrower);
    IERC20Detailed(defaultUnderlying).approve(address(cdoEpoch), owed);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // call stopEpoch with a gas limit sized so that the forwarded
    // 63/64 sub-call OOGs but the catch + _handleBorrowerDefault completes.
    // (binary-search GAS between a successful run and a top-level OOG)
    (bool ok, ) = address(cdoEpoch).call{gas: GAS}(
        abi.encodeCall(IdleCDOEpochVariant.stopEpoch, (0, 0))
    );
    assertTrue(ok, "outer tx succeeded");

    // outer tx finalized: borrower permanently defaulted despite being solvent
    assertTrue(cdoEpoch.defaulted(), "transient failure recorded as default");
    assertFalse(cdoEpoch.isEpochRunning(), "epoch killed");

    // no replay path exists:
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.restoreOperations();
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.startEpoch();

    // borrower can no longer repay through the normal stopEpoch flow;
    // lenders are forced into the haircut recovery path
    uint256 bal = IERC20Detailed(defaultUnderlying).balanceOf(borrower);
    assertEq(bal, owed, "borrower still holds the money the pool could not pull");
}
```

The PoC demonstrates the M-1 shape exactly: outer call completes and records final state; inner call fails on insufficient forwarded gas; the failed action is not replayable because `defaulted` is terminal.

Note on certainty: the variable-gas pre-call work (`prepareStopEpochWithApr0`, fee accrual, `onStopEpoch`) makes the OOG window plausible, but whether a practically reachable gas window exists depends on measured gas costs of each branch; the structural defect (any transient `transferFrom` failure ⇒ irreversible default with no retry) holds regardless of which specific failure mode is used to trigger the catch.
