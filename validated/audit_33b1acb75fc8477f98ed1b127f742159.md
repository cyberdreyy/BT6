### Title
Multisig requests can execute below the required confirmation threshold because confirmations from deleted members are never purged - ([File: multisig2/src/lib.rs])

### Summary
`HatsSignerGate`'s `maxSigners` bug class (a counter that is supposed to track a "current, live" set diverges from the set actually recorded) has a direct analog in both `multisig/src/lib.rs` and `multisig2/src/lib.rs`. The contracts track `num_confirmations` (the K in K-of-N) against the *size* of a `confirmations: HashSet<...>` for each pending request, but when a member/key is removed from the multisig, only the requests **created** by that member are purged - any confirmation that member already cast on a request created by someone else is left untouched in the `confirmations` map. `confirm()` never re-validates that every entry in the stored confirmation set still corresponds to a live member, so a stale confirmation from a since-removed member can be counted toward reaching the threshold.

### Finding Description
The confirmation-counting invariant that must hold is:

`live confirmations for request R == recorded confirmations for request R`

i.e. every account/key string stored in `self.confirmations[R]` must currently be a member of `self.members` (multisig2) or hold an active key (multisig).

In `multisig2/src/lib.rs`, `confirm()` simply compares the size of the stored `HashSet<String>` to `self.num_confirmations`, with no re-check of live membership: [1](#0-0) 

When a member is removed via `DeleteMember`/`delete_member`, the code only removes **requests that member created** (`r.member == member`) and clears their `num_requests_pk` entry and their own access key. It never scans `self.confirmations` for other requests where that member's identifier was recorded as a confirmer: [2](#0-1) 

The same gap exists in the original `multisig/src/lib.rs` contract: `DeleteKey` filters only requests whose *creator* (`signer_pk`) matches the deleted key, leaving confirmations that key cast on other requests intact: [3](#0-2) 
and `confirm()` there likewise just counts set size against `num_confirmations`: [4](#0-3) 

`remove_request()` only clears confirmations when a request is fully removed (executed or deleted), not when a member is deleted while other pending requests still hold their stale confirmation: [5](#0-4) 

Exactly like the `HatsSignerGate.signerCount` case, the "recorded count" (`confirmations.len()`) is not kept in sync with the true "live" set (`self.members`), so `num_confirmations` can be satisfied with fewer than K currently-authorized approvals.

### Impact Explanation
This breaks the multisig's core authorization guarantee: a `Transfer`, `AddKey`/`AddMember`, `FunctionCall`, `DeployContract`, or any other privileged action can be executed with fewer live confirmations than the configured `num_confirmations` threshold. That is a direct instance of the listed Critical impact - "a multisig request executed below threshold" - since an action (e.g. moving funds out of the multisig account) is authorized by a set of confirmations that no longer reflects who is actually entitled to approve it.

### Likelihood Explanation
The only precondition is normal contract usage: a member creates or confirms a request, and later a member-removal (`DeleteMember`/`DeleteKey`) request is executed while the first request is still pending (which is expected/likely in any long-lived multisig, since `REQUEST_COOLDOWN` and typical governance changes take time). No special privilege beyond being one of the existing multisig members is required, and member turnover (removing a departing or compromised signer) is a normal, encouraged operation - making the stale-confirmation state easy to reach.

### Recommendation
When deleting a member/key, iterate over **all** pending requests' confirmation sets (not just those the member created) and strip that member's identifier from each. Alternatively, when counting confirmations in `confirm()`, filter the stored set to only identifiers that are still present in `self.members` (or have a currently valid key) before comparing against `num_confirmations`, so stale confirmations can never contribute to reaching the threshold.

### Proof of Concept
1. Initialize `multisig2` with members `{A, B, C}` and `num_confirmations = 2`.
2. `A` calls `add_request(R)` for a `Transfer` to an attacker-controlled address (`add_request` at `multisig2/src/lib.rs:170`).
3. `B` calls `confirm(R)` - since `confirmations.len()+1 (1) < 2`, `B`'s identifier is stored: `confirmations[R] = {B}` (`multisig2/src/lib.rs:294-315`).
4. Separately, the multisig executes a `DeleteMember { member: B }` request (properly confirmed by 2 members, e.g. `A` and `C`) to remove `B` (`multisig2/src/lib.rs:239-242`, `delete_member` at `355-379`). `B` is removed from `self.members`, but `confirmations[R]` still contains `B`.
5. `A` calls `confirm(R)`. `current_member()` returns `A` (still a live member). `confirmations[R]` is `{B}`, doesn't contain `A`, so `confirmations.len()+1 == 2 >= num_confirmations(2)` → the request executes (`multisig2/src/lib.rs:304-309`).
6. Result: `R` (the `Transfer`) executes with only **one** currently-live confirming member (`A`); `B`'s confirmation, from a member removed from the multisig, was counted toward the 2-of-3 threshold - a multisig request executed below the intended live-signer threshold.

        self.assert_valid_request(request_id);

            .unwrap_or_else(|| env::panic_str("Must be validated above"));

        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);

            ********************************/

        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);

        }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
