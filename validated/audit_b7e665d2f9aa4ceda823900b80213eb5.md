## Title
Panic (Denial-of-Service) in `TrieNode::open` when Extension node `prefix` is longer than remaining `path` in the fault-proof MPT implementation - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::open` in `crates/proof/mpt/src/node.rs` performs an unchecked `path.slice(..prefix.len())` when traversing an `Extension` node, without first verifying that `path.len() >= prefix.len()`. If a decoded/fetched `Extension` node's `prefix` is longer than the remaining `path` nibbles, the `Nibbles::slice` call panics on an out-of-range index, crashing the fault-proof program. This is the same bug class fixed upstream in kona/optimism commit [40d8cf2](https://github.com/ethereum-optimism/optimism/commit/40d8cf29c2c27c25bbd7e86e91cc40e7412a9310) (#19728), which added a length guard before slicing in `TrieNode::open`.

### Finding Description
The vulnerable code: [1](#0-0) 

```rust
Self::Extension { prefix, node } => {
    if path.slice(..prefix.len()) == *prefix {
        // Follow extension branch
        node.unblind(fetcher)?;
        node.open(&path.slice(prefix.len()..), fetcher)
    } else {
        Ok(None)
    }
}
```

Unlike the `Branch` arm just above it, which safely uses `path.get(0).ok_or(TrieNodeError::PathTooShort)?` to guard against short paths, the `Extension` arm does not check `prefix.len() <= path.len()` before calling `path.slice(..prefix.len())`. `Nibbles::slice` (from `alloy_trie`) panics when given an out-of-bounds range, exactly like the `TrieNode::open` panic described in the referenced kona/optimism fix.

`TrieNode::open` is the core trie-traversal primitive used throughout the fault-proof executor to resolve account and storage state during dispute-game state transition verification: [2](#0-1) [3](#0-2) 

Both `get_trie_account` (account lookups) and `storage` (storage slot lookups) call `TrieNode::open`/`root_node.open` on nodes populated by unblinding preimages fetched from the (host-provided) `TrieProvider`/`TrieHinter`. An `Extension` node whose `prefix` nibble-length exceeds the remaining path length would trigger the panic during this traversal, halting execution of the fault-proof program mid-dispute-game verification.

### Impact Explanation
A panic inside the fault-proof program (used to compute/verify the dispute-game output root) constitutes a node/program halt that prevents production of a valid provable output for that step, which can stall or invalidate dispute-game resolution — one of the explicitly accepted impact categories (node halt / wrong provable output root).

### Likelihood Explanation
The trie traversal path is reached on every account and storage access performed by the stateless executor while replaying a block inside the fault-proof program, using preimages resolved through the host/hinter interface. Any node preimage (however it is introduced into the traversal — decoded from RLP or provider-supplied) whose `Extension.prefix` is longer than the remaining path nibbles reaches this exact unguarded slice, mirroring precisely the condition fixed upstream in kona.

### Recommendation
Add a length check before slicing in the `Extension` arm of `TrieNode::open`, mirroring the guard already used in the `Branch` arm, e.g.:
```rust
Self::Extension { prefix, node } => {
    if prefix.len() > path.len() {
        return Ok(None);
    }
    if path.slice(..prefix.len()) == *prefix {
        ...
    }
}
```
Add a regression test asserting `TrieNode::open` returns `Ok(None)` (not a panic) when `prefix.len() > path.len()`.
