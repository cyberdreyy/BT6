## Title
`permit()` on the B20 token precompiles can be front-run to DOS the composite permit+transfer flow - (File: `crates/common/precompiles/src/common/ops/permit.rs`, `crates/common/precompiles/src/b20_stablecoin/logic/v1.rs`, `crates/common/precompiles/src/b20_asset/logic/v1.rs`, and their V2 counterparts)

### Summary
Base's enshrined B20 token precompiles (`b20_stablecoin` and `b20_asset`) implement an EIP-2612-style `permit()` that anyone can submit on behalf of `owner`, since only the ECDSA signature is checked and the caller identity is never validated against `owner`. Because a valid, unconsumed `(v, r, s)` signature is fully reusable by any address until its nonce is consumed, an attacker who observes a pending `permit()` call (or a composite call that begins with `permit()`) in the mempool can copy the signature and submit it first, advancing `owner`'s nonce. This causes the victim's own subsequent `permit()` sub-call to revert, exactly mirroring the "repay can be DOSed" bug class: a public, state-dependent operation guarded by a value (here, a signature-bound nonce, there, a debt amount) that an unprivileged third party can mutate ahead of the victim's transaction to force a revert.

### Finding Description
`permit()` recovers the signer from `args` and the token's **current** nonce for `owner`, then unconditionally increments that nonce and applies the approval: [1](#0-0) 

The dispatcher routes `permit` calls without any caller/role check — unlike nearly every other mutating entry point in the same `dispatch.rs`, which passes `caller`/`privileged` through to a guard: [2](#0-1) 

The nonce-binding logic itself lives in the shared `PermitArgs` helper, which hashes `(owner, spender, value, nonce, deadline)` and recovers the signer purely from the signature — it never checks `msg.sender`: [3](#0-2) 

Once a signature for a given `nonce` is consumed by *any* sender, a second submission of the identical `(v, r, s)` for that owner fails signer recovery against the now-advanced nonce, exactly as the codebase's own replay test documents: [4](#0-3) 

This is the same bug class as the referenced `repay()` DOS: a publicly-callable state transition (`debts[user] -= amount` there; `nonce[owner]++` here) is gated by a check (`debt >= amount` there; `recovered == owner` at `nonce` there) that an unprivileged third party can invalidate by observing the pending transaction and submitting a state-mutating call first, causing the victim's transaction to revert.

### Impact Explanation
Any protocol or wallet flow on Base that composes `permit()` with a following action in the same transaction (e.g., "permit then transferFrom", a common gasless-approval UX pattern) can have its `permit()` leg griefed: an attacker monitoring the mempool copies the visible `(owner, spender, value, deadline, v, r, s)` and submits a standalone `permit()` call with higher priority fee. The victim's composite transaction then reverts when its own `permit()` sub-call recovers against the already-advanced nonce, wasting the victim's gas and denying the intended action for that block/attempt. This can be repeated to persistently deny the victim's permit-dependent flow, matching the DOS classification and severity level (Medium) of the original finding.

### Likelihood Explanation
The attack requires only observing a public transaction in the mempool and submitting an unprivileged call with the same calldata (or extracted signature fields) at higher priority — no special role, precompile privilege, or capital is needed. `permit()` is reachable identically from both the B20 stablecoin and B20 asset precompiles (V1 and V2), all of which perform recovery/nonce advancement with no `msg.sender` gate.

### Recommendation
Mitigate by making the composite consumer resilient to a possibly-already-executed permit: wrap the `permit()` sub-call so a revert is tolerated when the resulting allowance is already sufficient (the common "try/catch permit, then check allowance" pattern), or bind the permit's replay space to something the front-runner cannot pre-empt (e.g., accept only via configuration change type flows already scope-gated in this codebase, or require the same-transaction caller to equal `owner`/`spender` where the design allows it).

### Proof of Concept
1. Alice signs a valid `permit(owner=Alice, spender=Bob, value=100, nonce=0, deadline=…)` and submits a transaction that calls `permit()` followed by `transferFrom` in the same call (mirroring the "permit + action" UX pattern this precompile is designed to support).
2. Mallory observes Alice's pending transaction in the mempool and extracts `(v, r, s)`.
3. Mallory submits a standalone `permit()` call with Alice's exact signature and a higher priority fee; it lands first, and `token.accounting_mut().increment_nonce(args.owner)` advances Alice's nonce to `1`, per [5](#0-4) .
4. Alice's original transaction executes next; its `permit()` sub-call recomputes the signing hash using nonce `1`, `recover_signer` yields a different address than `owner`, and `validate_recovered_address` reverts with `InvalidSigner`, per [6](#0-5) , causing Alice's whole composite call to revert and denying her intended transfer.

    fn permit(
        &self,
        token: &mut B20StablecoinToken<S, A>,
        chain_id: u64,
        now: U256,
        args: PermitArgs,
    ) -> Result<()> {
        if now > args.deadline {
            return Err(BasePrecompileError::revert(IB20::ExpiredSignature {
                deadline: args.deadline,
            }));
        }
        let domain_sep = self.domain_separator(token, chain_id)?;
        let nonce = token.accounting().nonce(args.owner)?;
        let signing_hash = args.signing_hash(domain_sep, nonce);
        let recovered = args.recover_signer(signing_hash)?;
        PermitArgs::validate_recovered_address(recovered, args.owner)?;
        token.accounting_mut().increment_nonce(args.owner)?;
        self.approve(token, args.owner, args.spender, args.value)
    }

    /// Hashes the EIP-2612 `Permit` struct for `nonce`.
    pub fn struct_hash(&self, nonce: U256) -> B256 {
        keccak256(
            (Self::TYPEHASH, self.owner, self.spender, self.value, nonce, self.deadline)
                .abi_encode(),
        )
    }

    /// Builds the EIP-712 signing digest: `keccak256("\x19\x01" ‖ domainSeparator ‖ structHash)`.
    pub fn signing_hash(&self, domain_separator: B256, nonce: U256) -> B256 {
        let struct_hash = self.struct_hash(nonce);
        let mut buf = [0u8; 66];
        buf[..2].copy_from_slice(&Self::EIP712_SIGNING_PREFIX);
        buf[2..34].copy_from_slice(domain_separator.as_slice());
        buf[34..66].copy_from_slice(struct_hash.as_slice());
        keccak256(buf)
    }

    /// Validates a recovered ECDSA address against the declared `owner`.
    ///
    /// Returns `Err(InvalidSigner)` when `recovered` is `Address::ZERO` (matching Solidity's
    /// explicit zero-address guard) or when `recovered != owner`.
    pub fn validate_recovered_address(recovered: Address, owner: Address) -> Result<()> {
        if recovered.is_zero() || recovered != owner {
            return Err(BasePrecompileError::revert(IB20::InvalidSigner {
                signer: recovered,
                owner,
            }));
        }
        Ok(())
    }
