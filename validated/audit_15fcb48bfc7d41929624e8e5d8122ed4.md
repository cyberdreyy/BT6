### Title
`GlobalStateEvaluator::reached_agreement`/`reached_disagreement` compute the 70% supermajority threshold by floor division, allowing global consensus (current miner, burn view, tx-replay set, protocol version) to be adopted with less than the intended 70% weight — ([File: libsigner/src/v0/signer_state.rs])

### Summary
The rounding-down bug class from the report (dividing total voting power and truncating, so less than the full/intended amount is required/allocated) has a direct analog in `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs`. Unlike the block-signature approval threshold in `stackslib/src/chainstate/nakamoto/mod.rs::compute_voting_weight_threshold`, which correctly rounds the 70% threshold **up** (ceiling), the global-state agreement threshold used for signer-set consensus on the active miner, burn view, tx-replay set, and protocol version rounds the threshold **down** (floor), which can let sub-70% weight be treated as having reached the supermajority.

### Finding Description
`reached_agreement` computes:
```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
``` [1](#0-0) 

This is `vote_weight >= floor(total_weight * 7 / 10)`. Because the division truncates, the computed threshold can be strictly less than the true 70% cutoff whenever `total_weight * 7` is not a multiple of 10. For example, with `total_weight = 13`: true 70% is `9.1`, so the minimum integer weight that actually represents ≥70% is `10`. But `floor(13*7/10) = 9`, so `reached_agreement(9)` returns `true` even though `9/13 ≈ 69.2% < 70%`.

By contrast, the block header signature-verification threshold used for actual block approval, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly computes a ceiling:
```rust
let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
u32::try_from((total_weight * threshold) / 10 + ceil)...
``` [2](#0-1) 
which is verified correct by `test_compute_voting_weight_threshold`'s "Round-up check" (`511 -> 358`, i.e. `ceil(511*0.7)=358`, not `floor=357`). [3](#0-2) 

So the two consensus-relevant thresholds in the same codebase are inconsistent: the signature-counting threshold is correct (ceiling), but the signer-set global-state agreement threshold (`GlobalStateEvaluator::reached_agreement`) is off-by-rounding (floor), analogous to the reported Solidity bug where floor division under-allocates/under-requires the intended total.

`GlobalStateEvaluator::determine_global_state` (and `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, `find_majority_prefix_replay_set`) all rely on `reached_agreement` to decide the *active miner*, *burn view*, *tx replay set*, and *protocol version* that the signer will use to validate/sign proposals. [4](#0-3)  This global state is then consumed directly by `GlobalStateView::check_proposal` to decide whether a block proposal matches the "current miner"/tenure and should be accepted, i.e., it gates whether a signer signs a block: [5](#0-4) , and by `check_block_against_global_state` in the v0 signer event loop. [6](#0-5) 

`reached_disagreement` has the analogous floor-rounding issue on the 30% blocking-minority side:
```rust
pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
``` [7](#0-6) 

### Impact Explanation
This breaks the intended "aggregated-weight vs verified-accepts" equality for the global signer-set state machine: the code is supposed to require a genuine ≥70% supermajority weight before signers converge on a `current_miner`/burn view/tx-replay-set, but due to floor-division rounding, a set of signer updates with strictly less than 70% of total weight (e.g., ~69.2% at `total_weight=13`) can satisfy `reached_agreement`. Any client (a subset of signers, potentially orchestrated via gossip by a miner-influenced set of colluding or duplicated-weight signers, or simply an unlucky weight distribution) whose combined weight lands in the rounding gap can cause other signers to adopt a "global state" (including which miner/tenure is considered active) that does not actually have true supermajority backing. Since `check_proposal`/`check_block_against_global_state` gate block acceptance/signing on this global state, this can cause a signer to treat a proposal as valid (matching `current_miner`) under a consensus view that was reached with less than the intended weight — fitting the "High: a signer ... acting on a stale reward set/threshold" category, since the *threshold itself* is miscalculated for the live signer-set weight.

### Likelihood Explanation
The rounding gap is a purely deterministic function of `total_weight` (any value where `total_weight * 7` isn't a multiple of 10 — the overwhelming majority of possible weight sums), so it will trigger under completely ordinary signer-set weight distributions, not just crafted ones. No majority of signers, no other signer's key, and no privileged access are required — it's a latent arithmetic flaw reachable whenever enough weight (which can be just under the "true" 70%, itself well under a majority-plus for most weight distributions) accumulates in `address_updates` for a given candidate value (miner state/burn view/protocol version/replay set) via ordinary state-machine-update gossip.

### Recommendation
Change `reached_agreement`'s threshold computation to match `compute_voting_weight_threshold`'s ceiling logic (i.e., `vote_weight >= ceil(total_weight * THRESHOLD / 10)`), and correspondingly review `reached_disagreement` for the same floor/ceiling boundary issue, so the two consensus threshold computations in the codebase are consistent and both actually enforce ≥70%/>30% rather than an under-counted approximation.

### Proof of Concept
Using `evaluator_with_total_weight(13)` (`GlobalStateEvaluator { total_weight: 13, .. }`), calling `reached_agreement(9)`:
- Computed threshold: `floor(13 * 7 / 10) = floor(9.1) = 9`
- Check: `9 >= 9` → `true`
- Actual weight fraction: `9 / 13 ≈ 69.23%`, which is **below** the intended 70% supermajority.

This demonstrates that `reached_agreement` accepts a vote weight below the true 70% threshold, mirroring the reported Solidity rounding-down bug where the proportional/threshold computation loses precision due to integer division truncation rather than rounding up to preserve the guaranteed minimum.

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    fn check_block_against_global_state(
        &mut self,
        stacks_client: &StacksClient,
        block: &NakamotoBlock,
    ) -> Option<BlockRejection> {
        let signer_signature_hash = block.header.signer_signature_hash();
        let block_id = block.block_id();
        let Some(global_state) = self.global_state_evaluator.determine_global_state() else {
            warn!(
                "{self}: Cannot validate block, no global signer state";
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_id,
                "local_signer_state" => ?self.local_state_machine
            );
            return Some(self.create_block_rejection(RejectReason::NoSignerConsensus, block));
        };

        let global_state_view = GlobalStateView {
            signer_state: global_state,
            config: self.proposal_config.clone(),
        };

        info!(
            "{self}: Evaluating proposal against global state";
            "signer_state" => ?global_state_view.signer_state,
            "signer_signature_hash" => %signer_signature_hash,
            "block_id" => %block_id,
            "local_signer_state" => ?self.local_state_machine,
        );

        // Check if proposal can be rejected now if not valid against the global state
        match global_state_view.check_proposal(stacks_client, &mut self.signer_db, block) {
            // Error validating block
            Err(RejectReason::ConnectivityIssues(e)) => {
                warn!(
                    "{self}: Error checking block proposal: {e}";
                    "signer_signature_hash" => %signer_signature_hash,
                    "block_id" => %block_id,
                );
                Some(self.create_block_rejection(RejectReason::ConnectivityIssues(e), block))
            }
            // Block proposal is bad
            Err(reject_code) => {
                warn!(
                    "{self}: Block proposal invalid";
                    "signer_signature_hash" => %signer_signature_hash,
                    "block_id" => %block_id,
                    "reject_reason" => %reject_code,
                    "reject_code" => ?reject_code,
                );
                Some(self.create_block_rejection(reject_code, block))
            }
            // Block proposal passed check, still don't know if valid
            Ok(_) => None,
        }
    }
