### Title
First depositor can inflate tranche share price via raw underlying donation and steal subsequent deposits - ([File: contracts/IdleCDOCreditVault.sol])

### Summary
`IdleCDOCreditVault._deposit` mints tranche tokens at a price derived from `getContractValue()`, which includes raw underlying sitting in the contract (`_contractTokenBalance(token)`). Unlike `IdleCDOEpochVariant` — which calls `_skimDonatedAssets()` before accounting in `_deposit`, `requestWithdraw`, `depositDuringEpoch`, `startEpoch`, `stopEpoch` and `updateAccounting` — the base credit-vault deposit/withdraw path has no donation skim. A first depositor can therefore donate underlyings, crystallize the donation as tranche gain, and execute the classic first-depositor share-inflation attack.

### Finding Description
1. Attacker calls `depositAA(1)` when AA supply is 0. `_tranchePrice` returns `oneToken` for an empty tranche (`IdleCDOCreditVault.sol:422-427`), so the attacker is minted ~1 wei of tranche tokens and `lastNAVAA = 1`.
2. Attacker transfers `D` underlyings directly to the CDO. `getContractValue()` (`IdleCDOCreditVault.sol:125-128`) counts `strategyToken + raw token - unclaimedFees`, so `nav` becomes `1 + D`.
3. Victim calls `depositAA(V)` with `V < D`. `_updateAccounting()` (`IdleCDOCreditVault.sol:222-236`) computes `totalGain = nav - lastNAV = D`, skims the performance fee into `unclaimedFees`, and — since AA is the only holder — assigns the rest of the gain to `lastNAVAA`, setting `priceAA ≈ D` underlying per 1 wei of shares.
4. `_mintSharesAtCurrPrice` (`IdleCDOCreditVault.sol:344-348`) computes `minted = V * ONE_TRANCHE_TOKEN / priceAA`, which rounds to 0. The victim's `V` lands in the contract with no shares minted, but `lastNAVAA += V`.
5. Attacker calls `withdrawAA(1)` (via `_withdrawOps`, `IdleCDOCreditVault.sol:369-382`) and receives essentially the entire NAV `1 + D + V`, stealing `V`.

Note the inconsistency proving this is unintended: the view path `virtualPrice()` uses `_managedContractValue()` (`IdleCDOCreditVault.sol:172-180`), which explicitly excludes raw underlyings under the assumption "unsolicited transfers are skimmed on interactions" — but the state-changing `_updateAccounting` uses `getContractValue()` which includes them, and `IdleCDOCreditVault._deposit` never skims.

Guards that do not stop it: `depositDuringEpoch`'s `_trancheTotSupply == 0` check (`IdleCDOEpochVariant.sol:677`) is epoch-variant only; KYC (`isWalletAllowed`) does not apply to `IdleCDOCreditVault._deposit` and a whitelisted lender is an allowed attacker anyway; `_guarded`/`limit` only bounds TVL.

### Impact Explanation
Direct theft of user deposits. Any victim depositing less than the donation amount mints 0 shares and forfeits the full deposit to the attacker. Attacker profit ≈ victim deposit `V`, for donation cost `D ≥ V` (bounded by the victim's deposit size; profitable whenever `V` exceeds the gas/fees on `D`).

### Likelihood Explanation
Requires being the first depositor of a tranche on a freshly deployed non-epoch credit vault (or a tranche class whose supply was fully exited). Attack cost is the donation, which is recovered along with the stolen amount on withdrawal. The attacker only profits if a subsequent deposit occurs before withdrawal, which is the standard precondition for all first-depositor/inflation bugs.

### Recommendation
- Call `_skimDonatedAssets()` at the top of `IdleCDOCreditVault._deposit` and the withdraw path, or make `_updateAccounting` use `_managedContractValue()` so raw donations are never crystallized as tranche gains.
- Alternatively, mint a minimum number of dead shares on the first deposit (or require a minimum initial deposit) so the price cannot be arbitrarily inflated per wei of share.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

// Foundry test against a deployed IdleCDOCreditVault (non-epoch variant)
function testFirstDepositorInflation() public {
    uint256 donation = 1_000 * ONE_SCALE;
    uint256 victimDeposit = 500 * ONE_SCALE;

    // 1. attacker is first AA depositor with 1 wei
    deal(underlying, attacker, 1 + donation);
    vm.startPrank(attacker);
    IERC20(underlying).approve(address(cdo), 1);
    cdo.depositAA(1);
    // 2. donation inflates NAV
    IERC20(underlying).transfer(address(cdo), donation);
    vm.stopPrank();

    // 3. victim deposit mints 0 shares
    deal(underlying, victim, victimDeposit);
    vm.startPrank(victim);
    IERC20(underlying).approve(address(cdo), victimDeposit);
    uint256 minted = cdo.depositAA(victimDeposit);
    vm.stopPrank();
    assertEq(minted, 0, "victim minted 0 shares");

    // 4. attacker withdraws everything
    vm.prank(attacker);
    cdo.withdrawAA(1);
    assertGe(IERC20(underlying).balanceOf(attacker), donation + victimDeposit, "attacker stole deposit");
}
```
