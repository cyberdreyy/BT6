### Title
CORS wildcard suffix check allows origin spoofing without subdomain boundary ("evil"+allowedHost bypass) - ([File: core/services/gateway/network/httpserver.go])

### Summary
`httpServer.isAllowedOrigin` implements wildcard host matching (`*.allowed.com`) using a plain `strings.HasSuffix(originHost, allowedHost)` check without verifying a `.` boundary precedes the match. This lets an attacker who controls a domain like `evilallowed.com` (or `xnotallowed.com`) satisfy the suffix check for a configured wildcard `*.allowed.com`, causing the gateway to reflect that attacker Origin in `Access-Control-Allow-Origin`.

### Finding Description
In `core/services/gateway/network/httpserver.go`, `isAllowedOrigin` (lines 142-178) parses both the incoming `Origin` header and each configured allowed origin via `splitURL`, which lowercases the raw URL before calling `url.Parse` [1](#0-0) .

After matching scheme and port, the wildcard branch strips the `*.` prefix from the configured allowed host and then does:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [2](#0-1) 

This is a pure string-suffix comparison with no requirement that the character immediately preceding the matched suffix in `originHost` be a `.`. Consequently, for a configured wildcard entry such as `*.notallowed.com` (allowedHost becomes `notallowed.com`), an attacker-registered domain `evilnotallowed.com` also satisfies `strings.HasSuffix("evilnotallowed.com", "notallowed.com")`, even though it is not a subdomain of `notallowed.com`.

This is reached directly from `handleRequest`: when `CORSEnabled` is true, the raw `Origin` header value is passed unmodified to `isAllowedOrigin`, and if it returns true the same raw (attacker-supplied) origin string is reflected verbatim into `Access-Control-Allow-Origin` [3](#0-2) . No additional allowlist enforcement or origin canonicalization happens afterward, so the flawed suffix check is the sole gate.

Regarding the specific percent-encoding/unicode-casing angle raised in the question: `strings.ToLower` operates on ASCII/Unicode case folding of the whole raw string before `url.Parse`, and the code uses `parsedURL.Host` (not IDN-normalized `Hostname()` punycode conversion). While Unicode case-folding edge cases (e.g., Turkish dotless-I) are theoretically dependent on Go's `ToLower` behavior, browsers only ever send real, resolvable ASCII/punycode hostnames as `Origin`, so no percent-encoding/homograph path was found that bypasses matching independent of the suffix-boundary defect. The concretely exploitable and reachable flaw is the missing dot-boundary in the wildcard suffix check.

### Impact Explanation
An attacker who registers a domain sharing a suffix with a configured wildcard allowed origin (e.g., `evilnotallowed.com` vs. configured `*.notallowed.com`) can have their page's cross-origin `fetch`/`XHR` requests to the gateway HTTP endpoint reflected with `Access-Control-Allow-Origin: <attacker origin>`. If the browser is willing to expose the response (i.e., credentials/cookies are attached, or the response otherwise contains sensitive per-caller data), the attacker page can read cross-origin gateway responses intended only for domains actually beneath `notallowed.com`. This falls under cross-origin response/credential confusion — an allowlist-bypass class issue. Note: the code does not appear to set `Access-Control-Allow-Credentials`, and the gateway relies on a bearer JWT/Authorization header rather than cookies for the `ProcessRequest` handler, which reduces (but does not eliminate, depending on deployment/session model) the practical severity versus a cookie-based auth CORS bypass.

### Likelihood Explanation
Preconditions: `CORSEnabled=true` and at least one wildcard entry (`*.something.com`) configured in `CORSAllowedOrigins`. No credentials or privileged access are needed — any unauthenticated attacker who can register/control a domain that happens to end with the same suffix (without a dot boundary) can trigger the bypass, and get a victim browser to visit their page and issue cross-origin requests. This is fully attacker-controlled and repeatable; it requires only domain registration, not any node/operator compromise.

### Recommendation
Fix the wildcard suffix check to require a `.` boundary (or compare against a properly-prefixed suffix), e.g.:
```go
if strings.HasPrefix(allowed, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
Additionally, consider parsing/normalizing hosts via `net/url`'s IDNA-aware `Hostname()`/`net.ParseIP`/punycode handling rather than raw `strings.ToLower` on the entire URL string, to avoid any future Unicode-casing edge cases in host comparison.

### Proof of Concept
Add a table-driven Go test for `isAllowedOrigin` in `core/services/gateway/network/httpserver_test.go`:
```go
func TestIsAllowedOrigin_WildcardBoundary(t *testing.T) {
    s := &httpServer{
        config: &HTTPServerConfig{CORSAllowedOrigins: []string{"https://*.notallowed.com"}},
        lggr:   logger.Test(t),
    }
    cases := []struct {
        origin string
        want   bool
    }{
        {"https://sub.notallowed.com", true},   // legit subdomain
        {"https://notallowed.com", false},      // bare domain not covered by wildcard's intended scope (or true if base should match, per policy)
        {"https://evilnotallowed.com", false},  // attacker domain sharing suffix - MUST be rejected
        {"https://xnotallowed.com", false},     // attacker domain sharing suffix - MUST be rejected
    }
    for _, c := range cases {
        got := s.isAllowedOrigin(c.origin)
        assert.Equal(t, c.want, got, "origin=%s", c.origin)
    }
}
```
Currently `evilnotallowed.com` and `xnotallowed.com` incorrectly return `true`, demonstrating the bypass; after applying the dot-boundary fix they return `false`.

func (s *httpServer) splitURL(rawURL string) (string, string, string, error) {
	// lowercase the URL to avoid case sensitivity issues
	parsedURL, err := url.Parse(strings.ToLower((rawURL)))
	if err != nil {
		return "", "", "", fmt.Errorf("error parsing URL: %w", err)
	}

	host, port, err := net.SplitHostPort(parsedURL.Host)
	if err != nil {
		// if there's no port, the host itself is returned
		if parsedURL.Host != "" {
			return parsedURL.Scheme, parsedURL.Host, "", nil
		}
		return "", "", "", fmt.Errorf("error splitting host and port: %w", err)
	}

	return parsedURL.Scheme, host, port, nil
}
