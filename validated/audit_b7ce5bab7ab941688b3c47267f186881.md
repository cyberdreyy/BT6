### Title
Multisig Executes Requests Using Stale Confirmations From Removed Members, Bypassing the Live-Confirmation Threshold - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
The multisig contracts count confirmations by raw `HashSet` size without validating that each recorded confirmer is still a current member. When a member/key is removed via `DeleteKey` (`multisig`) or `DeleteMember` (`multisig2`), the cleanup logic only purges confirmations for requests *originated* by the removed member, not confirmations that member *cast on requests originated by someone else*. Those stale confirmations remain counted toward `num_confirmations`, so a request can execute with fewer live, currently-authorized confirmers than the configured threshold — a multisig request executed below threshold.

### Finding Description
`confirm()` in both contracts checks `confirmations.len() as u32 + 1 >= self.num_confirmations` and executes the request once that count is reached, with no re-validation that the previously stored confirmers are still members: [1](#0-0) 

The only cleanup of stale confirmations happens in the `DeleteKey` action, and it filters `self.requests` by `r.signer_pk == pk` — i.e., requests *added* by the removed key — not requests the removed key merely *confirmed*: [2](#0-1) 

The same limited-scope cleanup exists in `multisig2`'s `delete_member`, which filters `self.requests` by `r.member == member` (originator) only: [3](#0-2) 

The invariant the contract is supposed to maintain is: `confirmations.len() >= num_confirmations` implies at least `num_confirmations` *currently valid* members approved the request. Because a removed member's confirmation on a request they didn't originate is never purged, this invariant breaks: `confirmations.len()` can reach `num_confirmations` while the number of live members who approved is `num_confirmations - 1` (or fewer, if multiple such stale confirmations exist).

### Impact Explanation
This allows a multisig request (fund transfer, key/member add, function call, contract upgrade, etc.) to execute with fewer than the configured `num_confirmations` live approvals, directly undermining the K-of-N security guarantee the contract is designed to provide. This matches the Critical impact category "a multisig request executed below threshold" — funds or privileged actions can be authorized by less than the intended quorum of currently trusted keys/accounts.

### Likelihood Explanation
This requires no external attacker privilege beyond ordinary multisig lifecycle events that are expected to happen regularly: a member confirms a pending request they didn't create, and later that member (or their key) is legitimately removed (offboarding, key rotation, compromise response) while the request they confirmed is still outstanding. Given `REQUEST_COOLDOWN` (15 min) and the `active_requests_limit` (default 12) allowing many concurrent pending requests, it is plausible for a request to remain unconfirmed/pending for extended periods while member turnover occurs, especially in longer-lived multisig deployments (e.g., DAO treasuries).

### Recommendation
When removing a member/key (`DeleteKey` / `DeleteMember`), iterate over *all* pending requests' confirmation sets (not just requests originated by the removed member) and strip the removed member's identifier from each. Alternatively, validate membership of every entry in the confirmations set at `confirm()`-time before counting toward the threshold, discarding/ignoring confirmations from accounts/keys no longer present in the members set.

### Proof of Concept
1. Initialize `multisig2` with 4 members `A, B, C, D` and `num_confirmations = 3`.
2. `A` calls `add_request` to create `R1` (e.g., `Transfer` of funds) — `R1.member = A`, `confirmations[R1] = {}`.
3. `D` calls `confirm(R1)` → `confirmations[R1] = {D}` (size 1, below threshold).
4. `A`, `B`, `C` (3 of the 4 live members, satisfying threshold) submit and confirm request `R2 = DeleteMember { member: D }`. This executes `delete_member`, which removes `D` from `self.members`, deletes `D`'s access key, and only purges requests where `r.member == D` — `R1` is untouched because it was originated by `A`. `confirmations[R1]` still contains `D`.
5. `B` calls `confirm(R1)` → `confirmations[R1] = {D, B}` (size 2, below threshold).
6. `C` calls `confirm(R1)` → `confirmations[R1] = {D, B, C}` (size 3) → `3 >= num_confirmations (3)` → `execute_request(R1)` runs the `Transfer`.
7. Result: `R1` executed with only `B` and `C` as currently live, authorized confirmers (2 of 4 remaining members), plus a stale confirmation from `D`, who was removed from the multisig before the request executed — the request ran below the intended live-member threshold. [4](#0-3) [3](#0-2)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
