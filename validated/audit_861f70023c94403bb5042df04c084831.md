### Title
Unauthenticated `/health` and `/readyz?full` endpoints leak internal service names and error details - ([File: core/web/router.go], [File: core/web/health_controller.go])

### Finding Description
`healthRoutes(app, api)` is registered directly on the top-level `api` gin group in `NewRouter` [1](#0-0) , and that group's middleware stack only applies rate limiting and cookie sessions [2](#0-1) , with no `auth.Authenticate` wrapper applied before `healthRoutes` (auth is applied per-endpoint later, e.g. for `/query` and via `ExtendRouter`) [3](#0-2) . This means any handlers registered inside `healthRoutes` are reachable by an unauthenticated caller.

`HealthController.Health` and `HealthController.Readyz` (with `?full`) iterate over `checker.IsHealthy()` / `checker.IsReady()` results and emit, per check, the full internal check `Name` (which encodes hierarchical service/component identifiers such as relayer/chain sub-service names) and `Output` set to `err.Error()` — the raw underlying error string from the failing internal component [4](#0-3) [5](#0-4) . This is returned as JSON/HTML/plaintext to the caller with no redaction beyond the `HealthStatusPassing`/`HealthStatusFailing` boolean-style status.

Notably, the code already acknowledges the risk: `PublicReadyz` was added explicitly to be a minimal boolean-only endpoint "to avoid leaking internal service state on publicly reachable endpoints," implying `/health` and `/readyz?full=1` do leak per-check names and error text and are intentionally more verbose [6](#0-5) . Unlike `PublicReadyz`, neither `Health` nor `Readyz` restricts detail disclosure based on caller identity, and neither route is behind `auth.Authenticate`.

### Impact Explanation
An unauthenticated attacker (no credentials, no role) can enumerate internal component/service names (which can reveal relayer/chain identifiers and internal architecture topology) and error strings from failing dependencies (which can include connection details, RPC endpoint errors, or other internal state) by simply issuing `GET /health` or `GET /readyz?full=1`. This is an unauthenticated internal topology/service-health disclosure — it does not directly yield secrets/keys or fund movement, but it aids reconnaissance for further attacks and violates the stated minimal-disclosure invariant that the authors themselves encoded via `PublicReadyz`'s doc comment.

### Likelihood Explanation
Trivial and fully repeatable: no preconditions, no credentials, a single unauthenticated HTTP GET request against a node's default web server exposes the information whenever any health check is in a failing state (or always, for check names, when the `full` query param is passed to `/readyz`).

### Recommendation
Apply the same "boolean-only for unauthenticated" policy used in `PublicReadyz` to `/health` and `/readyz` by default: gate emission of per-check `Name`/`Output` fields behind `auth.Authenticate` (or a similarly authenticated variant), keeping only a public boolean/status-code endpoint unauthenticated. Alternatively, require an internal-only network binding or auth token for the verbose variants and keep `/public-readyz`-style boolean checks as the only unauthenticated route.

### Proof of Concept
Go handler-level integration test using `httptest`:
1. Build a `chainlink.Application` mock/stub whose `GetHealthChecker()` returns a checker with at least one failing service check named e.g. `"EVM.42161.HeadTracker"` and an error like `errors.New("dial tcp 10.0.0.5:8545: connect: connection refused")`.
2. Construct the router via `NewRouter(app, nil)`.
3. Issue `httptest.NewRequest("GET", "/health", nil)` with no `Authorization`/session cookie set, serve it through the router, and assert `resp.StatusCode` is not `401/403`.
4. Parse the JSON body and assert it contains the check `Name` (`"EVM.42161.HeadTracker"`) and `Output` (the raw error text) — demonstrating internal topology/error disclosure to an unauthenticated caller, contrary to the "minimal disclosure" invariant.
5. Repeat for `GET /readyz?full=1` to show the same detail leak on that route.
6. Contrast with `GET /public-readyz`, which should only return a bare 200/503 status with no body, confirming that endpoint alone satisfies the intended invariant.

```go
// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
```

```go
func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}
```
