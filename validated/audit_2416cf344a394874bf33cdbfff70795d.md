### Title
Unbounded per-request memory/serialization cost in `getSupply` via attacker-created stake accounts - ([File: runtime/src/non_circulating_supply.rs])

### Summary
`calculate_non_circulating_supply` scans all stake-program accounts and inserts every `Initialized`/`Stake` account whose lockup is in force or whose `authorized.withdrawer` matches a hardcoded list into an unbounded `HashSet<Pubkey>`, with no cap on set size. This set is converted directly into `RpcSupply.non_circulating_accounts` and returned in a single `getSupply` response, so an attacker who cheaply creates many such stake accounts on-chain can make the size and cost of a single RPC response scale with attacker-controlled on-chain data volume.

### Finding Description
The call chain is `rpc_accounts_scan::AccountsScan::get_supply` → `JsonRpcRequestProcessor::get_supply` (`rpc/src/rpc.rs:1121-1153`) → `JsonRpcRequestProcessor::calculate_non_circulating_supply` (`rpc/src/rpc.rs:298-307`) → `solana_runtime::non_circulating_supply::calculate_non_circulating_supply` (`runtime/src/non_circulating_supply.rs:19-79`).

In `calculate_non_circulating_supply`, all stake-program accounts are fetched (`bank.get_filtered_indexed_accounts` or `bank.get_program_accounts`) and iterated: any `StakeStateV2::Initialized(meta)` or `StakeStateV2::Stake(meta, ..)` whose `meta.lockup.is_in_force(&clock, None)` is true, or whose `meta.authorized.withdrawer` is in the hardcoded `withdraw_authority()` list, is inserted into `non_circulating_accounts_set: HashSet<Pubkey>` [1](#0-0) . There is no cap (e.g., no `MAX_NON_CIRCULATING_ACCOUNTS`) on the number of entries added to this set, and the final `NonCirculatingSupply.accounts` is simply `non_circulating_accounts_set.into_iter().collect()` [2](#0-1) .

Back in `get_supply`, unless `exclude_non_circulating_accounts_list` is set, every pubkey in `non_circulating_supply.accounts` is converted to a `String` and placed into `RpcSupply.non_circulating_accounts: Vec<String>` [3](#0-2) , which is serialized and returned in one JSON-RPC response, defined at `rpc-client-types/src/response.rs:478-485` [4](#0-3) .

Creating a qualifying `StakeStateV2::Initialized` account only requires funding a stake account and either setting a lockup or setting `authorized.withdrawer` to one of the hardcoded pubkeys in `withdraw_authority()` — no privileged role, staking activity, or leader/validator control is needed; this is a plain, permissionless on-chain write via the stake program. The test `test_calculate_non_circulating_supply` confirms that account count and iteration scale linearly with the number of qualifying stake accounts [5](#0-4) , and there is no length/byte cap comparable to `MAX_GET_PROGRAM_ACCOUNT_FILTERS` or `scan_results_limit_bytes` applied to the resulting `non_circulating_accounts` list itself — the `scan_results_limit_bytes` guard on `get_filtered_indexed_accounts` bounds the accounts scanned from storage, not the size of the resulting pubkey list serialized back to the client [6](#0-5) . `exclude_non_circulating_accounts_list` is opt-in by the caller and not a server-enforced limit [7](#0-6) .

### Impact Explanation
A single `getSupply` call causes the validator to allocate a `HashSet<Pubkey>`, a `Vec<Pubkey>`, and a `Vec<String>` (via `pubkey.to_string()`) all proportional to N attacker-created stake accounts, plus O(N) JSON serialization cost for the response. This falls under "unbounded per-request memory allocation and serialization cost proportional to attacker-controlled on-chain data," since the cost of one low-rate RPC call is bound by attacker-authored account volume rather than an explicit protocol-level cap.

### Likelihood Explanation
Feasible and fully repeatable: the attacker needs only enough lamports to create N `StakeStateV2::Initialized` accounts (rent-exempt minimum per account) with a lockup or a withdrawer matching `withdraw_authority()`, then issue one `getSupply` call. No special permissions, validator control, or high request rate are required, satisfying the "one client, one low-rate call" threat model.

### Recommendation
Introduce an explicit upper bound (e.g., `MAX_NON_CIRCULATING_ACCOUNTS`) on the number of pubkeys collected in `non_circulating_accounts_set` in `runtime/src/non_circulating_supply.rs`, and/or cap and clearly document the size of `RpcSupply.non_circulating_accounts` returned by `get_supply` in `rpc/src/rpc.rs`, independent of on-chain stake-account volume (e.g., truncate the list and always compute `lamports` over the full set while capping only the returned `accounts` vector, or require `exclude_non_circulating_accounts_list` above a configurable account-count threshold).

### Proof of Concept
Integration test plan (extending the pattern in `runtime/src/non_circulating_supply.rs:450-546`):
1. In a `#[test]` similar to `test_calculate_non_circulating_supply`, parametrize `num_stake_accounts` over {10, 1_000, 10_000, 100_000}, each created as `StakeStateV2::Initialized(meta)` with `meta.lockup.epoch = 1` (lockup in force) and inserted into the bank's genesis accounts.
2. For each N, call `calculate_non_circulating_supply(&bank)` and record wall-clock time and the size (`non_circulating_supply.accounts.len()` and estimated serialized byte size via `serde_json::to_vec`).
3. Assert `non_circulating_supply.accounts.len() == N` for all tested N (no cap observed), and that response construction time/memory grows roughly linearly (or worse due to `HashSet` overhead and `to_string()` allocations) with N, with no assertion failure triggered by any built-in limit — demonstrating the absence of a `MAX_NON_CIRCULATING_ACCOUNTS`-style cap.
4. Optionally exercise the full path via `rpc::rpc_accounts_scan::AccountsScanImpl::get_supply` in the `RpcHandler::start()` test harness (as in `test_get_supply`, `rpc/src/rpc.rs:5371-5396`) with N stake accounts pre-populated, asserting `result.value.non_circulating_accounts.len() == N`.

    fn test_calculate_non_circulating_supply() {
        let mut accounts: BTreeMap<Pubkey, Account> = BTreeMap::new();
        let balance = 10;
        let num_genesis_accounts = 10;
        for _ in 0..num_genesis_accounts {
            accounts.insert(
                solana_pubkey::new_rand(),
                Account::new(balance, 0, &Pubkey::default()),
            );
        }
        let non_circulating_accounts = non_circulating_accounts();
        let num_non_circulating_accounts = non_circulating_accounts.len() as u64;
        for key in non_circulating_accounts.clone() {
            accounts.insert(key, Account::new(balance, 0, &Pubkey::default()));
        }

        let num_stake_accounts = 3;
        for _ in 0..num_stake_accounts {
            let pubkey = solana_pubkey::new_rand();
            let meta = Meta {
                authorized: Authorized::auto(&pubkey),
                lockup: Lockup {
                    epoch: 1,
                    ..Lockup::default()
                },
                ..Meta::default()
            };
            let stake_account = Account::new_data_with_space(
                balance,
                &StakeStateV2::Initialized(meta),
                StakeStateV2::size_of(),
                &stake::program::id(),
            )
            .unwrap();
            accounts.insert(pubkey, stake_account);
        }

        let slots_per_epoch = 32;
        let genesis_config = GenesisConfig {
            accounts,
            epoch_schedule: EpochSchedule::new(slots_per_epoch),
            cluster_type: ClusterType::MainnetBeta,
            ..GenesisConfig::default()
        };
        let (bank0, bank_forks) =
            Bank::new_for_tests(&genesis_config).wrap_with_bank_forks_for_tests();
        let mut bank = bank0;
        assert_eq!(
            bank.capitalization(),
            (num_genesis_accounts + num_non_circulating_accounts + num_stake_accounts) * balance
                + genesis_sysvar_and_builtin_program_lamports(),
        );

        let non_circulating_supply = calculate_non_circulating_supply(&bank).unwrap();
        assert_eq!(
            non_circulating_supply.lamports,
            (num_non_circulating_accounts + num_stake_accounts) * balance
        );
        assert_eq!(
            non_circulating_supply.accounts.len(),
            num_non_circulating_accounts as usize + num_stake_accounts as usize
        );

        &self,
        bank: &Arc<Bank>,
        index_key: &IndexKey,
        program_id: &Pubkey,
        filters: Vec<RpcFilterType>,
        sort_results: bool,
    ) -> ScanResult<Vec<KeyedAccountSharedData>> {
        let bank = Arc::clone(bank);
        let index_key = index_key.to_owned();
        let program_id = program_id.to_owned();
        let byte_limit_for_scans = self.config.scan_results_limit_bytes;
        let mut accounts = self
            .runtime
            .spawn_blocking(move || {
                bank.get_filtered_indexed_accounts(
                    &index_key,
                    |account| {
                        // The program-id account index checks for Account owner on inclusion.
                        // However, due to the current AccountsDb implementation, an account may
                        // remain in storage as a zero-lamport AccountSharedData::Default() after
                        // being wiped and reinitialized in later updates. We include the redundant
                        // filters here to avoid returning these accounts.
                        account.owner().eq(&program_id)
                            && filters
                                .iter()
                                .all(|filter_type| filter_allows(filter_type, account))
                    },
                    byte_limit_for_scans,
                )
            })
            .await
            .expect("Failed to spawn blocking task")?;
