### Title
Signature-tally path (`store_and_process_block_signature`) broadcasts a group-signed block without re-running the chainstate/conflict checks that the pre-commit signing path performs — ([File: stacks-signer/src/v0/signer.rs])

### Summary
`handle_block_pre_commit` — the only path where this signer places its *own* signature — re-validates the block against `check_block_against_signer_db_state` and the sibling/conflict-freshness rules immediately before signing [1](#0-0) . But `store_and_process_block_signature`, the function that tallies *other* signers' `BlockAccepted` messages, decides the group-acceptance threshold has been reached, promotes the block via `mark_locally_accepted(true)`, and broadcasts the fully-signed block to the node, performs no such re-check [2](#0-1) . Because `BlockInfo::check_state` explicitly allows the transition `LocallyRejected -> LocallyAccepted` ("re-evaluated") [3](#0-2) , this signer can end up locally-accepting and rebroadcasting a block it had itself already rejected or refused to sign as conflicting/non-canonical, purely because it received enough gossiped signatures from other signers.

### Finding Description
Two entry points converge on "does this signer sign/promote this exact block":

1. **Own signing path** — `handle_block_validate_ok` → `handle_block_pre_commit`. Before this signer ever calls `mark_locally_accepted(false)` and creates its own signature, it explicitly re-runs `check_block_against_signer_db_state` (rejects if the chainstate view has changed) [1](#0-0) , and then checks for fresh, still-live sibling conflicts via `get_signed_conflicts`/`reorg_permit_stands`/`conflict_still_blocks`, refusing to sign if a conflict still blocks [4](#0-3) .

2. **Signature-tally path** — `handle_block_response(Accepted)` → `handle_block_signature` → `store_and_process_block_signature`. This is invoked for every `BlockAccepted` gossiped by other signers. Once weight crosses `compute_voting_weight_threshold`, it directly calls `block_info.mark_locally_accepted(true)` and then `self.broadcast_signed_block(...)`, sending the aggregated signature bundle to the node [5](#0-4) . It contains **no call** to `check_block_against_signer_db_state`, `get_signed_conflicts`, or any freshness/canonical check — the only guards present are "signature already exists" and `signed_group.is_some()` [6](#0-5) .

`BlockInfo::check_state` permits `LocallyRejected -> LocallyAccepted` as a valid "re-evaluated" transition [7](#0-6) , and `mark_locally_accepted` performs no independent validity check of its own beyond the state-machine move [8](#0-7) .

Concretely: a signer S locally rejects block B (e.g. via `handle_block_validate_ok`'s `check_block_against_signer_db_state` branch, or via `handle_block_pre_commit`'s conflict-refusal branch that simply returns without ever changing state to `LocallyRejected` — but in the validate-ok case it explicitly calls `mark_locally_rejected()` [9](#0-8) ). If enough *other* signers still accept and sign B — because their own view of the chain differs, or the conflict became stale from their vantage point, or they signed before the fork that invalidated it from S's perspective — their gossiped `BlockAccepted` messages arrive at S and are tallied in `store_and_process_block_signature` with no re-check against S's own current (rejecting) chainstate view. Once weight crosses threshold, S calls `mark_locally_accepted(true)` (state machine permits `LocallyRejected -> LocallyAccepted`) and immediately calls `broadcast_signed_block`, pushing the block S itself deemed invalid/conflicting to the stacks-node.

This is the structural analog of the reported bug class: `matchOrder` (the "produce our own signature" path) carries the full guard (`payable`/re-validation), while `batchMatchOrders` (the "aggregate and forward" path that should behave identically) is missing it.

### Impact Explanation
This breaks the "approved-parent vs canonical" / "aggregated-weight vs verified-accepts" equality: the signer's aggregate-broadcast decision is not gated by the same chainstate/conflict verification its own signing decision is gated by. A signer can be made to hand a fully-signed, group-accepted block bundle to its own node for a block that it had independently determined to be invalid or conflicting from its local chainstate view — i.e., the signer participates in broadcasting/pushing a block it itself flagged as non-canonical/conflicting, which is exactly the Critical-tier impact category ("a signer signing an invalid, non-canonical, or conflicting block").

### Likelihood Explanation
Reaching this requires no more than the normal gossip flow already used by the protocol (other signers' legitimately-signed `BlockAccepted` messages arriving after this signer has locally rejected the same block due to a since-changed chainstate view, e.g. a burn fork or a sibling/conflict resolution race — the exact race conditions the `run_sibling_scenario` test suite in `stacks-signer/src/v0/tests.rs` is built to exercise). No majority-signer collusion, key compromise, or auth bypass is needed; only a race between this signer's own re-evaluation and its receipt of other signers' pre-existing valid signatures over StackerDB.

### Recommendation
Before `store_and_process_block_signature` calls `mark_locally_accepted(true)` and `broadcast_signed_block`, re-run the same `check_block_against_signer_db_state` (and, ideally, the conflict/freshness checks) that `handle_block_pre_commit` runs immediately prior to signing. If the block no longer passes those checks, treat crossing the acceptance threshold as a broadcast-worthy but non-actionable event for this signer (or re-derive rejection) rather than unconditionally promoting and forwarding the block.

### Proof of Concept
1. Signer S validates block B via `handle_block_validate_ok`; `check_block_against_signer_db_state` detects a conflict and S calls `mark_locally_rejected()` + broadcasts a rejection [9](#0-8) .
2. Meanwhile, ≥ threshold-weight of other signers had already (validly, from their own point-in-time view) produced `BlockAccepted` signatures for B and gossiped them over StackerDB.
3. S receives these `BlockAccepted` messages via `handle_block_response` → `handle_block_signature` → `store_and_process_block_signature` [10](#0-9) .
4. `store_and_process_block_signature` stores each signature, and once `total_signature_weight >= min_weight`, calls `block_info.mark_locally_accepted(true)` — a transition `check_state` allows from `LocallyRejected` [7](#0-6)  — then calls `self.broadcast_signed_block(...)` [11](#0-10) , with no re-invocation of `check_block_against_signer_db_state` anywhere in this call path.
5. S's node receives and stores/broadcasts a block that S's own most recent chainstate check had deemed invalid/conflicting.

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }

    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }
