### Title
Unbounded API-key brute forcing on the flashblocks WebSocket proxy - (File: crates/infra/websocket-proxy/src/server.rs)

### Summary
The `base-websocket-proxy` (the public WebSocket entry point that fans out flashblocks pending-state broadcasts and other subscription data to downstream clients) checks the caller-supplied `api_key` path segment *before* any per-IP or global rate limiting is applied. An attacker can therefore send unlimited authentication attempts against `/ws/{api_key}` with no throttling, mirroring the CVE-2018-16703 pattern of "insufficient server-side access control and login attempt limit enforcement" that enables user/credential enumeration and brute-force attacks.

### Finding Description
`authenticated_websocket_handler` and `authenticated_filter_websocket_handler` look up the supplied key via `state.auth.get_application_for_key(&api_key)` and only call into `websocket_handler` (which is the function that actually invokes `state.rate_limiter.try_acquire(client_addr)`) when the key is valid. [1](#0-0) [2](#0-1) 

When the key is invalid, the handler simply increments an `unauthorized_requests` metric and returns `401 Unauthorized` — it never touches the `InMemoryRateLimit` (global semaphore + per-IP connection limiter) defined in `crates/infra/websocket-proxy/src/rate_limit.rs`, and there is no separate IP-based request-rate middleware wrapping these routes in `Server::listen` (unlike the unrelated telemetry crate's `IpRateLimiter`/`PerIpRateLimit`, which is not used here). [3](#0-2) 

API keys are simple operator-supplied `app:key` strings parsed by `Authentication::try_from`, with no built-in entropy requirement, lockout counter, or backoff on repeated failures. [4](#0-3) 

Because the connection-limiting `try_acquire` call is only reached after a *successful* auth lookup, invalid-key attempts are effectively free for the attacker: they don't consume tickets, don't get throttled by the per-IP/global limiter, and (absent any external WAF) can be retried at whatever rate the attacker's network allows. This directly matches the reported bug class: authorization checks that can be probed at unlimited rate because the rate/attempt-limiting control sits downstream of, rather than in front of, the credential check.

### Impact Explanation
The WebSocket proxy gates access to flashblocks pending-block broadcasts and filtered event streams (a WebSocket query path explicitly in scope). A successful key guess grants an attacker unauthorized, free access to another paying application's private, low-latency pending-state feed, which is exactly the kind of information that provides MEV/front-running advantage on unconfirmed transactions before they land on-chain. This is an unauthorized-access/data-exfiltration primitive with concrete financial upside for the attacker at the expense of legitimate subscribers, reachable by any anonymous WebSocket client with no privileges.

### Likelihood Explanation
Exploitability depends on the entropy/length of operator-chosen API keys (set via the `--api-keys` CLI flag as arbitrary strings), which is outside this code's control. However, the code path itself imposes no cost, delay, or lockout on failed attempts, so any weak, short, or reused key in production is trivially brute-forceable from a single unauthenticated client over the public listener, with the server offering no telemetry-driven blocking beyond a simple failure counter.

### Recommendation
Apply IP-based rate limiting (or a dedicated failed-auth counter with exponential backoff/lockout) to the `/ws/{api_key}` and `/ws/{api_key}/filter` routes *before* the authentication check, not only after a key is validated — reuse the existing `IpRateLimiter`/`PerIpRateLimit` middleware pattern already implemented in the telemetry crate, or extend `InMemoryRateLimit` to gate unauthenticated/failed lookups as well. Additionally, use constant-time comparison for key lookup and consider requiring high-entropy, operator-issued keys with periodic rotation.

### Proof of Concept
1. Deploy `base-websocket-proxy` with `--api-keys app1:secretkey`.
2. From an unauthenticated client, repeatedly connect to `ws://<host>:8545/ws/<guess>` with different `<guess>` values in a tight loop.
3. Observe that requests are answered immediately with `401 Unauthorized` at the client's maximum request rate — no `429 Too Many Requests` is ever returned and no delay is imposed, because `state.rate_limiter.try_acquire` in `websocket_handler` (`crates/infra/websocket-proxy/src/server.rs:233`) is never reached for invalid keys, confirming attempts are unmetered and unlimited.             info!("Public endpoint is enabled");
            router = router.route("/ws", any(unauthenticated_websocket_handler));

            registry: self.registry.clone(),

async fn authenticated_websocket_handler(
    State(state): State<ServerState>,
    ws: WebSocketUpgrade,
    ConnectInfo(addr): ConnectInfo<SocketAddr>,
    headers: HeaderMap,
    Path(api_key): Path<String>,
) -> impl IntoResponse {
    let application = state.auth.get_application_for_key(&api_key).cloned();

    application.map_or_else(
        || {
            Metrics::unauthorized_requests().increment(1);

            Response::builder()
                .status(StatusCode::UNAUTHORIZED)
                .body(Body::from(json!({"message": "Invalid API key"}).to_string()))
                .unwrap()
        },
        |app| {
            Metrics::connections_by_app(app).increment(1);
            websocket_handler(state, ws, addr, headers, FilterType::None)
        },
    )
}

fn websocket_handler(
    state: ServerState,
    ws: WebSocketUpgrade,
    addr: SocketAddr,
    headers: HeaderMap,
    filter: FilterType,
) -> Response {
    let connect_addr = addr.ip();
    let client_addr = state.trusted_proxy_config.client_ip(connect_addr, &headers);

    let ticket = match state.rate_limiter.try_acquire(client_addr) {
        Ok(ticket) => ticket,
        Err(RateLimitError::Limit { reason, limit_type }) => {
            match limit_type {
                RateLimitType::PerIp => {
                    info!(
                        message = "per-IP rate limit exceeded",
                        client_ip = client_addr.to_string(),
                        reason = reason
                    );
                    Metrics::per_ip_rate_limited_requests().increment(1);
                }
                RateLimitType::Global => {
                    Metrics::global_rate_limited_requests().increment(1);
                }
            }

            return Response::builder()
                .status(StatusCode::TOO_MANY_REQUESTS)
                .body(Body::from(json!({"message": reason}).to_string()))
                .unwrap();
        }
    };

impl TryFrom<Vec<String>> for Authentication {
    type Error = AuthenticationParseError;

    fn try_from(args: Vec<String>) -> Result<Self, Self::Error> {
        let mut applications = HashSet::new();
        let mut key_to_application: HashMap<String, String> = HashMap::new();

        if args.is_empty() {
            return Err(NoData());
        }

        for arg in args {
            let mut parts = arg.split(':');
            let app = parts.next().ok_or_else(|| MissingApplicationArgument(arg.clone()))?;
            if app.is_empty() {
                return Err(MissingApplicationArgument(arg.clone()));
            }

            let key = parts.next().ok_or_else(|| MissingAPIKeyArgument(app.to_string()))?;
            if key.is_empty() {
                return Err(MissingAPIKeyArgument(app.to_string()));
            }

            if parts.count() > 0 {
                return Err(TooManyComponents(app.to_string()));
            }

            if applications.contains(app) {
                return Err(DuplicateApplicationArgument(app.to_string()));
            }

            if key_to_application.contains_key(key) {
                return Err(DuplicateAPIKeyArgument(app.to_string()));
            }

            applications.insert(app.to_string());
            key_to_application.insert(key.to_string(), app.to_string());
        }

        Ok(Self { key_to_application })
    }
}

impl Authentication {
    /// Create an authentication instance with no registered keys.
    pub fn none() -> Self {
        Self { key_to_application: HashMap::new() }
    }

    /// Create a new authentication instance from a map of API keys to application names.
    pub const fn new(api_keys: HashMap<String, String>) -> Self {
        Self { key_to_application: api_keys }
    }

    /// Look up the application name associated with the given API key.
    pub fn get_application_for_key(&self, api_key: &str) -> Option<&String> {
        self.key_to_application.get(api_key)
    }
}
