### Title
Stale confirmations from removed multisig members remain counted toward the approval threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` tallies confirmations solely from the `confirmations: LookupMap<RequestId, HashSet<String>>` set recorded for a request. `delete_member` (invoked via the self-authorized `DeleteMember` action) removes the departing member from `self.members` and cleans up *requests the member itself created*, but it never scans the `confirmations` map to strip that member's serialized identity from confirmation sets of *other* pending requests they had already confirmed. This is the same class of bug as the `vcon`/`CoreRef` desync in the reference report: one place (`self.members`, the live source of truth for authorization) is updated, while another place that consumes a cached/recorded copy of that authorization (`self.confirmations`) is never refreshed, so the two diverge.

### Finding Description
`confirm()` decides whether to execute a request purely by counting entries already stored in `self.confirmations.get(&request_id)`: [1](#0-0) 

Membership authorization for *initiating* a confirmation is (correctly) re-checked live at call time via `current_member()`, which consults `self.members`: [2](#0-1) 

However, `delete_member` — the function that actually removes a member from `self.members` — only purges requests that the removed member *created* (matched by `r.member == member`); it does not touch `self.confirmations`, so any confirmation the removed member previously cast on requests created by *other* members remains in the `HashSet<String>` for that request: [3](#0-2) 

Because `confirm()` never re-validates that every string already present in `confirmations` still corresponds to a current member of `self.members`, a confirmation cast by an account that is later removed from the multisig still counts toward `num_confirmations` when a subsequent, still-current member confirms the same request.

### Impact Explanation
This breaks the multisig's core custody binding: `num_confirmations` live members === threshold required to move funds or execute privileged actions. With this bug, `confirmations_actually_from_current_members + 1 < num_confirmations` can still trigger `execute_request` (including `Transfer`, `FunctionCall`, `AddKey`, `DeployContract`), because a stale confirmation from an already-removed member is counted as if it were live. This matches the explicitly listed Critical impact: "a multisig request executed below threshold."

### Likelihood Explanation
No privileged actor or redeploy is required — any sequence of ordinary multisig operations (a member confirms a pending request, then that same member is later removed via a separate, properly-confirmed `DeleteMember` request) triggers the desync. Membership changes over the lifetime of a multisig account (turnover of employees/keyholders) are an expected, routine operation, and outstanding requests routinely persist across such changes since deletion of a request requires its own action.

### Recommendation
When executing `DeleteMember`, iterate over all requests in `self.requests` (not just ones the removed member created) and remove the removed member's key from each request's `confirmations` `HashSet`, decrementing effective progress accordingly. Alternatively, when tallying confirmations in `confirm()`, filter `confirmations` against `self.members` at count time (`confirmations.iter().filter(|m| self.members.contains(m)).count()`), so removed members' past confirmations can no longer count toward the live threshold.

### Proof of Concept
1. Multisig initialized with 4 members `{A, B, C, D}` and `num_confirmations = 3`.
2. `B` calls `add_request` creating `R1 = Transfer{amount, receiver_id: attacker}` (0 confirmations).
3. `C` calls `confirm(R1)` → `confirmations[R1] = {C}` (1 of 3).
4. Separately, `D` proposes and the members properly confirm (3-of-4, none of whom is `C`) a `DeleteMember{member: C}` request; it executes via `delete_member`, removing `C` from `self.members`. Per [4](#0-3)  this only purges requests *created by* `C`; `R1` (created by `B`) and its `confirmations[R1] = {C}` entry are untouched.
5. `A` calls `confirm(R1)` → `confirmations[R1] = {C, A}`, size 2.
6. `B` calls `confirm(R1)` → `2 + 1 >= 3` is true, so `execute_request` runs the `Transfer`, even though only `A` and `B` — two currently-live members — actually confirmed; `C`'s stale, now-unauthorized confirmation was decisive in reaching the threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {

                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }

            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)

            None
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
