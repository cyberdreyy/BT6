### Title
A single dust deposit in the prefunded AA epoch queue permanently bricks `stopEpochWithDuration`, freezing all vault funds - (File: contracts/IdleCDOEpochQueue.sol)

### Summary
The prefunded epoch variant routes epoch settlement through `_afterStopEpochWithDuration`, which calls `IdleCDOEpochQueue.prefundedDepositsToProcess()`. That view reverts whenever `epochPendingDeposits[epochToSettle] != 0`. A KYC-passed lender can deposit 1 wei of underlying into the AA queue for the next epoch and simply never cancel it, causing every subsequent `stopEpochWithDuration` call to revert — permanently freezing all user principal and yield in the vault. This is the direct analog of the EVerest report: a cheap, unprivileged-triggerable abort (assert/revert) in a critical path halts the entire module and, transitively, everyone else's funds.

### Finding Description
In `IdleCDOEpochVariantPrefunded`, once `epochQueue` is configured:

1. The direct `stopEpoch` selector is blocked by `_beforeStopEpoch` (`_checkNotAllowed(msg.sig == this.stopEpoch.selector)`), so the manager must use `stopEpochWithDuration`.
2. `stopEpochWithDuration` ends in `_afterStopEpochWithDuration`, which unconditionally calls `queue.prefundedDepositsToProcess()`: [1](#0-0) 
3. `prefundedDepositsToProcess` reverts if raw pending deposits for the epoch being settled remain in the queue: [2](#0-1) 
4. Any wallet passing `_checkAllowed` (epoch running + Keyring KYC) can create such a pending deposit via `requestDeposit`, which only requires the AA prefunded-cutoff conditions — conditions that are trivially satisfied before prefunding occurs, and entirely absent when `prefundedDepositWindow == 0`: [3](#0-2) 
5. Pending deposits can only be removed by `deleteRequest`, callable solely by the depositor themselves. The honest manager/owner has no path to force-clear an attacker's queue deposit: [4](#0-3) 

The manager's only alternatives don't help: `processDepositsToBorrower` would send the attacker's dust (along with all queued funds) to the borrower — but it can only be called while the epoch is running and before the prefund cutoff, and calling it converts the deposit to `epochPrefundedDeposits`, which the attacker still indirectly controls the timing of; more importantly, in the common configuration where the manager does not prefund (or `prefundedDepositWindow == 0` disables the cutoff), a fresh dust deposit can be placed at any time, including the same block, to keep `epochPendingDeposits` non-zero.

The broken invariant: epoch settlement must not depend on the goodwill of a single unprivileged depositor. One stuck dust deposit → `prefundedDepositsToProcess` reverts → `_afterStopEpochWithDuration` reverts → whole `stopEpochWithDuration` reverts → `isEpochRunning` stays true forever → `_beforeUnpause` blocks unpause, `requestWithdraw` claims never fund, deposits stay paused. No existing guard (skim, `_checkAllowed`, `checkPrefunding`, `only-CDO`) prevents a KYC'd attacker from leaving a pending deposit.

### Impact Explanation
Permanent freezing of all funds in the credit vault: borrower principal, all AA/BB tranche positions, queued withdrawal requests, and unclaimed yield are locked because the epoch can never be stopped. Cost to the attacker: 1 wei of underlying plus gas. All other users' funds (potentially the entire pool TVL) are frozen indefinitely.

### Likelihood Explanation
Requires only a KYC-passing wallet (an authorized lender class explicitly in scope) and a dust `requestDeposit`. No privileged role, no timing race beyond depositing before settlement, and it works repeatedly — each new epoch can be griefed the same way. The only prerequisite is the prefunded variant with a configured `epochQueue`, which is exactly the deployment this code path exists for.

### Recommendation
Make stop-time settlement robust to stray pending deposits:
- Either auto-sweep `epochPendingDeposits` into the prefunded amount inside `processPrefundedDeposits`/`_afterStopEpochWithDuration` (fund them from the queue balance), or
- Allow the manager to force-refund pending deposits at stop (a `deleteRequestFor` path during settlement), or
- Hard-close `requestDeposit` once `epochPrefundedDeposits[nextEpoch] != 0` is already enforced — extend this by also blocking new deposits once the epoch has entered its final settlement window regardless of `prefundedDepositWindow`, and make `prefundedDepositsToProcess` return 0 (refunding pending deposits in place) rather than reverting.

```solidity
// test/foundry/QueueGriefStopEpoch.t.sol
function testDustDepositBricksStopEpoch() external {
    // prefunded variant, epochQueue set, epoch running
    address attacker = makeAddr("kyc-attacker"); // passes Keyring whitelist
    deal(defaultUnderlying, attacker, 1);
    _whitelistUser(attacker);

    // honest users already deposited; epoch is running
    _startEpochAndCheckPrices(0);

    // attacker leaves 1 wei pending deposit for nextEpoch and never cancels
    vm.startPrank(attacker);
    IERC20Detailed(defaultUnderlying).approve(address(queue), 1);
    queue.requestDeposit(1);
    vm.stopPrank();

    // manager tries to settle the epoch — permanently reverts
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpochWithDuration(0, initialProvidedApr, cdoEpoch.epochDuration(), 0);

    // direct stopEpoch is also blocked
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, initialProvidedApr);

    // all vault funds remain frozen: isEpochRunning still true, claims never fund
    assertTrue(cdoEpoch.isEpochRunning());
}
```

```text
  function _afterStopEpochWithDuration() internal override {
    address _queue = epochQueue;
    if (_queue == address(0)) return;

    IIdleCDOEpochQueuePrefunded _epochQueue = IIdleCDOEpochQueuePrefunded(_queue);
    uint256 _prefunded = _epochQueue.prefundedDepositsToProcess();
    if (_prefunded == 0) return;
    // A zero post-loss AA price cannot safely mint new shares into the same tranche token.
    _checkNotAllowed(priceAA == 0);

    // Prefunded deposits already reached the borrower, so they must join AA even if stop defaulted.
    // Mint tranche shares at the post-stop price and mirror the same amount in strategy tokens,
    // so the queue can later distribute shares to users at the epoch price.
    uint256 _prefundedMinted = _mintSharesAtCurrPrice(_prefunded, _queue, AATranche);
    IdleCreditVault(strategy).mintStrategyTokens(_prefunded);
    // Finalize the prefunded epoch in the queue by storing the epoch price and clearing state.
    _epochQueue.processPrefundedDeposits(_prefundedMinted);
```

```text
    _checkAllowed(msg.sender);

    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    uint256 nextEpoch = IdleCreditVault(strategy).epochNumber() + 1;
    uint256 _prefundedWindow = prefundedDepositWindow;
    // Only the AA prefunded queue enforces a deposit cutoff for the next epoch.
    if (tranche == _cdo.AATranche() && _isPrefundedQueueEnabled()) {
      IdleCDOEpochVariantPrefunded(idleCDOEpoch).checkPrefunding(epochPendingDeposits[nextEpoch] + amount);
      // Once funds are prefunded, or once the subscription window is reached, the next epoch is closed.
      _checkNotAllowed(
        epochPrefundedDeposits[nextEpoch] != 0 || (
        _prefundedWindow != 0 && block.timestamp + _prefundedWindow >= _cdo.epochEndDate()
      ));

    // get underlying tokens from user
    IERC20Detailed(underlying).safeTransferFrom(msg.sender, address(this), amount);
    // deposit will be made in the next buffer period (ie next epoch)
    // updated user queued amount for the next epoch
    userDepositsEpochs[msg.sender][nextEpoch] += amount;
    // update pending deposits
    epochPendingDeposits[nextEpoch] += amount;
```

```text
  function deleteRequest(uint256 _requestEpoch) external {
    // if the epoch price is already set, deposits were already processed so
    // the deposit request can't be deleted.
    _checkNotAllowed(epochPrice[_requestEpoch] != 0 || epochPrefundedDeposits[_requestEpoch] != 0);

    uint256 amount = userDepositsEpochs[msg.sender][_requestEpoch];
    if (amount == 0) {
      return;
    }
    // reset user deposit for the epoch
    userDepositsEpochs[msg.sender][_requestEpoch] = 0;
    // update pending deposits
    epochPendingDeposits[_requestEpoch] -= amount;
    // transfer underlyings back to the user
    IERC20Detailed(underlying).safeTransfer(msg.sender, amount);
  }
```
