### Title
Global-state supermajority check `reached_agreement` uses floored (not ceiling) division, letting a sub-70% weight coalition force "global consensus" on miner/protocol/replay-set state - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority threshold as a plain floor division (`total_weight * 7 / 10`), while every other consumer of the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant (`NakamotoBlockHeader::compute_voting_weight_threshold`, used by consensus verification and by `stacks-signer`'s own pre-commit/signature-acceptance and node-side coordinator logic) computes the threshold with an explicit ceiling adjustment. For any `total_weight` that is not a multiple of 10 (the overwhelmingly common case), the floor threshold is one weight-unit lower than the "real" 70% threshold used for block signing/approval, so a coalition holding just under 70% (but ≥ the floored value) can force `determine_global_state`/`determine_latest_supported_signer_protocol_version`/`determine_global_burn_view`/`find_majority_prefix_replay_set` to declare consensus.

### Finding Description
The 70% supermajority constant is defined once, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD: u64 = 7` [1](#0-0) , and used to gate block signing/consensus in `NakamotoBlockHeader::compute_voting_weight_threshold`, which explicitly rounds the threshold **up** (ceiling) whenever the multiplication is not evenly divisible by 10: [2](#0-1) 

This ceiling-rounded threshold is what actually gates block acceptance everywhere else in the signing pipeline: consensus verification of a block's signatures (`verify_signer_signatures`) [3](#0-2) , the signer's own pre-commit tally [4](#0-3) , the signer's block-acceptance tally [5](#0-4) , and the node-side mining coordinator's threshold [6](#0-5) .

By contrast, `GlobalStateEvaluator::reached_agreement`, which is meant to represent the exact same "70% supermajority" concept for the *global state machine* (protocol version, current miner, burn-block view, and tx-replay-set agreement), uses a plain truncating (floor) division with no ceiling adjustment: [7](#0-6) 

Because `gcd(7,10)=1`, `total_weight*7 mod 10 == 0` only when `total_weight mod 10 == 0`. For any other `total_weight` (e.g. 11, 13, 17, 100 signers each weight 1 sums differently, any realistic non-multiple-of-10 weight distribution), `floor(total_weight*7/10)` is exactly 1 less than `ceil(total_weight*7/10)`. Example: `total_weight = 11` → `compute_voting_weight_threshold` returns 8 (72.7%), but `reached_agreement` accepts `vote_weight = 7` (63.6%) as "agreement".

`reached_agreement` (and the parallel `reached_disagreement`, which has the analogous floor issue for the 30% blocking-minority check) is the sole gate used by:
- `determine_latest_supported_signer_protocol_version` [8](#0-7) 
- `determine_global_burn_view` [9](#0-8) 
- `determine_global_state` (agrees on `current_miner`/`MinerState` and tx replay set) [10](#0-9) 
- `find_majority_prefix_replay_set` [11](#0-10) 

`determine_global_state`'s output feeds directly into block-proposal validation: `check_block_against_global_state` calls `determine_global_state()` and, if it succeeds, builds a `GlobalStateView` whose `signer_state.current_miner` is used by `GlobalStateView::check_proposal` to accept or reject a block based on whether its miner pubkey hash / tenure / consensus hash match the "agreed" `ActiveMiner` [12](#0-11)  and [13](#0-12) . If `determine_global_state()` returns `None`, the block is unconditionally rejected as `NoSignerConsensus`; if it wrongly returns `Some` under a sub-70% coalition, the block is instead validated against that (improperly-quorate) miner view.

The regression tests in this file demonstrate awareness of overflow bugs in this exact arithmetic (guarding against `u32` wraparound) but do not address the floor-vs-ceiling discrepancy itself; the existing tests only check exact 70%/30% boundaries with `total_weight` values chosen to be evenly divisible by 10 [14](#0-13) , so the off-by-one at non-multiple-of-10 weights is not covered.

### Impact Explanation
This breaks the intended equality that "global signer consensus" (protocol version, current-miner/tenure view, burn-block view, tx-replay-set) requires the same ≥70%-weight supermajority as block signing itself. A coalition of signers holding strictly less than the true 70% weight threshold (but ≥ the floored value — always exactly 1 weight unit less, for any non-multiple-of-10 total weight) can force the rest of the honest signer set to adopt:
- a different `current_miner`/tenure view than the properly-quorate one, which is then used to accept or reject block proposals via `GlobalStateView::check_proposal`,
- a stale/incorrect `tx_replay_set`,
- a different `active_signer_protocol_version`.

This falls under the "High" impact category explicitly listed in scope: a signer "acting on a stale reward set/threshold" — here the effective consensus threshold used for the global state machine is silently weaker than the block-signing threshold it is supposed to mirror, so signers can be steered into a global-state view that does not actually have majority (70%) backing, potentially causing them to reject valid blocks from the properly-supported miner, or accept a global view backed only by a large minority. Because this weakened threshold does not itself require a majority of the signer set (it can be satisfied by a coalition just below 70%, which is well under 50%+1 of an honest majority working correctly is not required to trigger it — the deviation itself is exactly one weight-unit, reachable by any coalition size that would already be near the true threshold), it is a low-cost/free rounding defect, not something needing collusion of a majority to exploit; it only requires enough of the signer set's weight to sit exactly on the floor-vs-ceiling boundary, which is common in real-world signer weight distributions.

### Likelihood Explanation
The discrepancy triggers deterministically whenever `total_weight` (the sum of active signer weights for the reward cycle) is not an exact multiple of 10 — which is true for almost any real-world signer set (weights are derived from PoX stacking amounts and reward-slot allocation, not designed to sum to multiples of 10). No malicious action beyond normal message broadcasting (`StateMachineUpdate` messages that any single signer or small group of signers already sends as part of normal operation) is needed to reach the boundary; the bug is a systemic off-by-one in the threshold formula itself, not a crafted attack input, so it fires on virtually every reward cycle boundary case.

### Recommendation
Make `reached_agreement` and `reached_disagreement` use the same rounding convention as `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling division), or better, have both call into a single shared threshold-computation helper so the "70%"/"30%" semantics can never diverge between the global state machine and block-signing/approval logic.

### Proof of Concept
Conceptual (arithmetic) demonstration using the existing helper `evaluator_with_total_weight` from `libsigner/src/tests/signer_state.rs`:

```rust

// compute_voting_weight_threshold(11) == ceil(11*7/10) == 8  (72.7%)
// reached_agreement uses floor(11*7/10) == 7  (63.6%)
assert!(evaluator.reached_agreement(7)); // wrongly reports "consensus reached"
// yet NakamotoBlockHeader::compute_voting_weight_threshold(11) requires 8,
// which is what block-signature verification, pre-commit tally, and the
```

With only 7/11 signers' weight backing a `StateMachineUpdate`, `determine_global_state` (and thus `current_miner`/tx-replay-set agreement) is treated as settled even though the block-signing threshold used everywhere else in the same reward cycle would require 8/11. This is unconfirmed against a live end-to-end signer run (the analysis is based on static code inspection of the threshold formulas and their call sites); a background agent with test-execution access should add a unit test analogous to `reached_agreement_no_u32_overflow` at a non-multiple-of-10 `total_weight` to confirm the discrepancy against `NakamotoBlockHeader::compute_voting_weight_threshold`.

```rust
    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
```

```rust
    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }
```

```rust
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }
```

```rust
    /// Find the longest common prefix of replay sets that has majority support.
    /// This implements the longest common prefix (LCP) strategy where if one signer's replay set
    /// is [A,B,C] and another is [A,B], we should use [A,B] as the replay set.
    /// Order matters for transaction replay - [A,B] and [B,A] have no common prefix.
    fn find_majority_prefix_replay_set(
        &self,
        tx_replay_sets: &HashMap<ReplayTransactionSet, u32>,
    ) -> Option<ReplayTransactionSet> {
        if tx_replay_sets.is_empty() {
            return None;
        }

        // First, try to find an exact match that reaches agreement
        for (replay_set, weight) in tx_replay_sets {
            if self.reached_agreement(*weight) {
                return Some(replay_set.clone());
            }
        }

        // No exact agreement found, find longest common prefix with majority support

        // Sort replay sets by weight (descending), then deterministically by length and content
        let mut sorted_sets: Vec<_> = tx_replay_sets.iter().collect();
        sorted_sets.sort_by(|(set_a, weight_a), (set_b, weight_b)| {
            // Primary: weight descending
            let weight_cmp = weight_b.cmp(weight_a);
            if weight_cmp != Ordering::Equal {
                return weight_cmp;
            }
            // Secondary: length descending (longer sequences first)
            let len_cmp = set_b.0.len().cmp(&set_a.0.len());
            if len_cmp != Ordering::Equal {
                return len_cmp;
            }
            // Tertiary: compare transaction IDs for determinism
            for (lhs, rhs) in set_a.0.iter().zip(&set_b.0) {
                let ord = lhs.txid().cmp(&rhs.txid());
                if ord != Ordering::Equal {
                    return ord;
                }
            }
            Ordering::Equal
        });

        // Start with the most supported replay set as initial candidate
        if let Some((initial_set, _)) = sorted_sets.first() {
            let mut candidate_prefix = initial_set.0.clone();
            let mut total_supporting_weight = 0u32;

            // Find all sets that support the current candidate prefix
            for (replay_set, weight) in tx_replay_sets {
                if replay_set.0.starts_with(&candidate_prefix) {
                    total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                }
            }

            // If the initial candidate already has majority support, return it
            if self.reached_agreement(total_supporting_weight) {
                return Some(ReplayTransactionSet::new(candidate_prefix));
            }

            // Otherwise, iteratively truncate the prefix until we find majority support
            while !candidate_prefix.is_empty() {
                // Remove the last transaction from the prefix
                candidate_prefix.pop();

                // Recalculate supporting weight for the shorter prefix
                total_supporting_weight = 0u32;
                for (replay_set, weight) in tx_replay_sets {
                    if replay_set.0.starts_with(&candidate_prefix) {
                        total_supporting_weight = total_supporting_weight.saturating_add(*weight);
                    }
                }

                // If this prefix has majority support, return it
                if self.reached_agreement(total_supporting_weight) {
                    return Some(ReplayTransactionSet::new(candidate_prefix));
                }
            }
        }

        // If no common prefix with majority support is found, return None
        None
    }
```
