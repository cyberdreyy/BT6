### Title
Legacy MessageId Collision Causes Cross-User Callback Overwrite in dummyHandler - ([File: core/services/gateway/handlers/handler.dummy.go])

### Finding Description
`dummyHandler.HandleLegacyUserMessage` stores the caller's `Callback` in a shared map keyed only by the attacker-supplied `msg.Body.MessageId`, with an unconditional map write and no existence check: [1](#0-0) 

`MessageId` is fully attacker-controlled and is not cryptographically bound to the sender's identity or to uniqueness across users. `Message.Validate()`/`Message.Sign()` only prove that the signer authored a message with that specific `MessageId`; they do not prevent two different signers from independently choosing the same `MessageId`: [2](#0-1) [3](#0-2) 

The reachable path is unauthenticated: `gateway.ProcessRequest` decodes the raw HTTP body, validates the message (signature format/length + business rules), and dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` for any legacy DON-targeted request — there is no per-user auth gate or MessageId-uniqueness check in this path: [4](#0-3) 

When two requests (victim, then attacker) use the same `MessageId` for the same DON/handler, the second `HandleLegacyUserMessage` call silently overwrites `d.savedCallbacks[msg.Body.MessageId]`, discarding the victim's callback reference. When the node eventually responds, `HandleNodeMessage` looks up the callback solely by `MessageId` and delivers the response to whichever callback is currently stored — the attacker's: [5](#0-4) 

This handler is registered as a selectable DON handler type via `handler_factory.go` (referenced by `NewDummyHandler`), so it is reachable in a running gateway configuration, not just in tests.

### Impact Explanation
This is a cross-user response confusion vulnerability: an unauthenticated attacker who predicts or brute-forces a victim's `MessageId` (which, per `Message.Validate`, can be any non-empty string up to 128 bytes with no randomness/uniqueness requirement enforced) can overwrite the victim's callback entry, causing either (a) the victim's node response to be delivered to the attacker instead (response/data leakage to an unauthorized party), or (b) the victim to never receive a response (silent DoS on their request). This matches the "cross-user response confusion" bounty impact class.

### Likelihood Explanation
Exploitation requires only the ability to send a legacy gateway message with a matching `DonId`/`Method` and an identical `MessageId` string, no authentication or role beyond generic gateway API access, and a signing key (attacker's own, cheaply generated) since the signature only needs to be valid for the attacker's own message body, not tied to MessageId ownership. It is fully repeatable and requires only that the attacker guess/predict the victim's MessageId (e.g., if MessageIds are sequential, timestamp-based, or otherwise low-entropy) and win a race before the node responds to the victim's original request.

### Recommendation
Reject `HandleLegacyUserMessage` calls whose `MessageId` already exists in `savedCallbacks` (return an error such as "duplicate message ID") instead of silently overwriting, mirroring the requirement of a 1:1 mapping between MessageId and caller. Consider additionally scoping the map key by sender address (e.g., `sender+messageId`) so that MessageId collisions across different senders cannot occur at all, and/or generating server-side MessageIds instead of trusting client-supplied ones for callback correlation.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/handler.dummy_test.go`:
1. Construct two signed `api.Message`s from two different private keys ("victim" and "attacker"), both with `Body.MessageId = "M"`, same `Method`/`DonId`.
2. Call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCb)`.
3. Before any node response, call `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCb)`.
4. Call `handler.HandleNodeMessage(ctx, resp, nodeAddr)` once with `resp.ID == "M"`.
5. Assert: only `attackerCb.Wait()` returns a value while `victimCb.Wait()` times out/blocks (or vice versa) — demonstrating the callback map only retains one entry per `MessageId` regardless of sender, and the response is misdelivered.
6. Expected fix behavior: `HandleLegacyUserMessage` for the attacker's duplicate `MessageId` should return an error and not overwrite `victimCb`, so `victimCb.Wait()` succeeds and the attacker's call is rejected.

func (d *dummyHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return err
	}
	msg.Body.MessageId = resp.ID
	err = msg.Validate()
	if err != nil {
		return err
	}
	if nodeAddr != msg.Body.Sender {
		return fmt.Errorf("node address %s does not match message sender %s", nodeAddr, msg.Body.Sender)
	}
	d.mu.Lock()
	savedCb, found := d.savedCallbacks[msg.Body.MessageId]
	delete(d.savedCallbacks, msg.Body.MessageId)
	d.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(&msg), ErrorCode: api.NoError})
	}
	return nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

// Message signatures are over the following data:
//  1. MessageId aligned to 128 bytes
//  2. Method aligned to 64 bytes
//  3. DonId aligned to 64 bytes

//  5. Payload (raw bytes before parsing)
func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
