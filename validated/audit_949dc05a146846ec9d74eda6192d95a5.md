### Title
Calculated stake rewards are permanently burned instead of paid when a stake account is closed between epoch-reward calculation and distribution - (File: runtime/src/bank/partitioned_epoch_rewards/distribution.rs)

### Summary
`distribute_partitioned_epoch_rewards` calculates all stake rewards for an epoch in a single "calculation" block, then pays them out over several subsequent "distribution" blocks, one partition per block [1](#0-0) . When a partition is processed, `store_stake_accounts_in_partition` looks up each targeted stake account in the current `StakesCache` and calls `build_updated_stake_reward` to apply the reward [2](#0-1) . If the stake account can no longer be found (`DistributionError::AccountNotFound`) or fails to be updated, the code does not retry, re-credit, or preserve the reward — it simply adds the reward amount to `stake_reward_lamports_burned` and moves on, exactly mirroring the reported bug class ("on failure, skip it and process the next one, funds permanently lost").

### Finding Description
Rewards for an epoch are computed once, at the epoch-boundary "calculation" block, from a snapshot of the `StakesCache` [3](#0-2) . The actual crediting of stake accounts, however, happens later, spread across `partition_indices.len()` subsequent blocks [4](#0-3) . There is no mechanism in the codebase (confirmed via `RewardInterval`, which is only used internally for reward bookkeeping, not to block stake-program instructions) that prevents a stakeholder from submitting ordinary stake instructions (e.g. deactivate + withdraw, fully closing the account) during this multi-block distribution window.

If a delegator's stake account is closed (or its state otherwise becomes inconsistent with the calculation-time snapshot) before its partition is processed, `build_updated_stake_reward` returns `DistributionError::AccountNotFound` because the account is no longer present in `stakes_cache_accounts` [5](#0-4) . In `store_stake_accounts_in_partition`, this error path does not credit anyone; it silently accumulates the amount into `stake_reward_lamports_burned` and `block_reward_lamports_burned` and continues to the next reward in the partition [6](#0-5) . The comment directly above the function acknowledges this is considered an anomaly ("there should never be rewards burned") [7](#0-6) , yet the code path exists and has no recovery, refund, or re-mint mechanism — the reward capital is permanently destroyed rather than delivered to the delegator or returned to the calculation pool.

This is structurally the same bug class as the referenced Hubble `processWithdrawals` issue: a queued, pre-computed payout is processed in a loop; when an individual payout step fails, the loop just skips it and continues, and the amount is lost forever with no path to re-execute or reclaim it.

### Impact Explanation
This is reward/stake accounting corruption: a delegator who is otherwise entitled to their calculated staking reward for the epoch can have that reward permanently burned merely by exercising an ordinary, unprivileged action (withdrawing/closing their stake account) during the normal, multi-block reward-distribution window that follows every epoch boundary. Because the reward capital is subtracted from `capitalization` and not credited to any account, this is a real loss of validator/delegator funds and a divergence between the amount SIMD-0116 rewards accounting promised the network (`total_rewards`/`distributed_rewards` sysvar bookkeeping still accounts for it as "distributed" even though it was burned) and what any account actually received.

### Likelihood Explanation
The precondition — a stake account being closed or otherwise no longer resolvable in `StakesCache` between the reward calculation block and its assigned distribution block — is trivially reachable by an unprivileged user with withdraw authority over their own stake account. The distribution window spans multiple blocks (`get_reward_distribution_num_blocks`), giving a comfortably wide timing window for any stake owner to race their own withdrawal against their own reward payout [8](#0-7) . No special privileges, leader control, or malicious peer behavior is required.

### Recommendation
When `build_updated_stake_reward` fails because the target stake account cannot be found or updated, do not burn the reward. Instead, either credit the lamports to a durable location (e.g., a system-owned account tied to the pubkey, if one still exists) or ensure such failures cannot occur by making the calculation-to-distribution window commit-consistent — for example, by preventing full closure of a stake account with an outstanding, calculated-but-undistributed reward (analogous to how `pending_delegator_rewards` blocks vote-account withdrawal until owed rewards are paid, see `programs/vote/src/vote_state/mod.rs` `withdraw` and `programs/vote/src/vote_state/handler.rs` `add_pending_delegator_rewards`) [9](#0-8) [10](#0-9) .

### Proof of Concept
1. Near an epoch boundary, have a delegator's stake account be included in the epoch-reward calculation snapshot (`build_partitioned_stake_rewards`/`store_stake_accounts_in_partition` compute a nonzero `PartitionedStakeReward` for the account) [11](#0-10) .
2. During the reward-distribution window (any of the blocks between the calculation block and the block matching this stake's partition index), submit an ordinary `Deactivate`+`Withdraw` (or already-deactivated `Withdraw`) transaction from the stake account's withdraw authority that fully withdraws and closes the account.
3. When the bank reaches the block corresponding to this stake's partition index, `distribute_epoch_rewards_in_partition` -> `store_stake_accounts_in_partition` looks the pubkey up in `stakes_cache_accounts` and fails to find it, hitting `DistributionError::AccountNotFound` [5](#0-4) .
4. The reward amount is added to `stake_reward_lamports_burned`/`block_reward_lamports_burned` rather than paid to the delegator — the test `test_invalid_inflation_rewards_collector_burns_sysvar_rewards` demonstrates the analogous "burn on failed credit" bookkeeping already exercised in the test suite for a different failure mode (invalid commission collector), confirming the burn path is live code [12](#0-11) .

    pub(in crate::bank) fn distribute_partitioned_epoch_rewards(&mut self) {
        let EpochRewardStatus::Active(status) = &self.epoch_reward_status else {
            return;
        };

        let distribution_starting_block_height = match &status {
            EpochRewardPhase::Calculation(status) => status.distribution_starting_block_height,
            EpochRewardPhase::Distribution(status) => status.distribution_starting_block_height,
        };

        let height = self.block_height();
        if height < distribution_starting_block_height {
            return;
        }

        if let EpochRewardPhase::Calculation(status) = &status {
            // epoch rewards have not been partitioned yet, so partition them now
            // This should happen only once immediately on the first rewards distribution block, after reward calculation block.
            let epoch_rewards_sysvar = self.get_epoch_rewards_sysvar();
            let (partition_indices, partition_us) = measure_us!({
                epoch_rewards_hasher::hash_rewards_into_partitions(
                    &status.all_stake_rewards,
                    &epoch_rewards_sysvar.parent_blockhash,
                    epoch_rewards_sysvar.num_partitions as usize,
                )
            });

            // update epoch reward status to distribution phase
            self.set_epoch_reward_status_distribution(
                distribution_starting_block_height,
                Arc::clone(&status.all_stake_rewards),
                partition_indices,
            );

            datapoint_info!(
                "epoch-rewards-status-update",
                ("slot", self.slot(), i64),
                ("block_height", height, i64),
                ("partition_us", partition_us, i64),
                (
                    "distribution_starting_block_height",
                    distribution_starting_block_height,
                    i64
                ),
            );
        }

        let EpochRewardStatus::Active(EpochRewardPhase::Distribution(partition_rewards)) =
            &self.epoch_reward_status
        else {
            // We should never get here.
            unreachable!(
                "epoch rewards status is not in distribution phase, but we are trying to \
                 distribute rewards"
            );
        };

        let distribution_end_exclusive =
            distribution_starting_block_height + partition_rewards.partition_indices.len() as u64;

            self.epoch_schedule.get_slots_in_epoch(self.epoch)
                > partition_rewards.partition_indices.len() as u64
        );

        if height >= distribution_starting_block_height && height < distribution_end_exclusive {
            let partition_index = height - distribution_starting_block_height;

            self.distribute_epoch_rewards_in_partition(partition_rewards, partition_index);
        }

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

        // SIMD-0123: vote account cannot be closed if
        // pending_delegator_rewards > 0.

        let reject_active_vote_account_close = vote_state

            .last()

                // if current_epoch - last_epoch_with_credits < 2 then the validator has received credits
                // either in the current epoch or the previous epoch. If it's >= 2 then it has been at least
                // one full epoch since the validator has received credits.
                current_epoch.saturating_sub(*last_epoch_with_credits) < 2
            })
            .unwrap_or(false);

        if reject_active_vote_account_close {
            return Err(VoteError::ActiveVoteAccountClose.into());
        } else {
            // Deinitialize upon zero-balance
            VoteStateHandler::deinitialize_vote_account_state(&mut vote_account, target_version)?;
        }
    } else {
        // SIMD-0123: withdrawable balance when pending_delegator_rewards > 0
        // is lamports - pending_delegator_rewards - rent_exempt_minimum.
        let min_rent_exempt_balance = rent_sysvar.minimum_balance(vote_account.get_data().len());

            .checked_add(pending_delegator_rewards)
            .ok_or(InstructionError::ArithmeticOverflow)?;
        if remaining_balance < min_balance {
            return Err(InstructionError::InsufficientFunds);
        }
