### Title
`HandleLegacyUserMessage` forwards unauthenticated web API trigger requests to the entire DON without any allowlist or rate-limit check - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The `capabilities` gateway `handler.HandleLegacyUserMessage` function, which processes messages arriving from the internet-facing Gateway on behalf of external/unprivileged callers, contains an explicit `// TODO: apply allowlist and rate-limiting here` comment immediately before it accepts and forwards a `MethodWebAPITrigger` message to every member of the DON. Unlike the JSON-RPC path (`HandleJSONRPCUserMessage`) and other handlers in the codebase that gate access with `nodeRateLimiter`/allowlists, this legacy path performs no sender authorization or throttling before broadcasting the request to all DON nodes.

### Finding Description
This is the same bug class as the 0x-order `_validateOrder` finding: a code path that is *supposed* to restrict who may invoke a privileged action (submitting a trigger through the internet-facing Gateway) omits the restriction check, so any caller — not just the intended, allowlisted set of senders — can exercise it.

`handler.HandleLegacyUserMessage` decodes the payload, validates timestamp freshness, and checks the method name is `MethodWebAPITrigger`, but the access-control gate is missing: [1](#0-0) 

The comment at line 384, `// TODO: apply allowlist and rate-limiting here`, is placed directly before the method-name check and directly after all other validation, confirming that no allowlist or rate limiting is applied on this path before the request is dispatched to every DON member via `don.SendToNode`: [2](#0-1) 

By contrast, the `handler` struct is provisioned with a `nodeRateLimiter` (used only for node→gateway traffic in other methods), and other request-handling paths in the same package/repo (e.g. `OutgoingConnectorHandler.HandleGatewayMessage`, vault/confidentialrelay handlers) explicitly apply per-sender/global rate limits before processing: [3](#0-2) 

This shows the intended design pattern (apply allowlist/rate-limit before forwarding a request) exists elsewhere in the codebase but is missing specifically in the legacy trigger-message ingestion path, mirroring the missing `takerAddress`/`senderAddress` checks in the original 0x finding: a caller-restriction control that should exist to keep the action permissioned is absent, letting unprivileged/unrestricted parties reach a sensitive forwarding action.

### Impact Explanation
Because no allowlist check gates this method, any unauthenticated internet client that can reach the Gateway's legacy endpoint can submit `MethodWebAPITrigger` messages that get relayed to every node in the target DON (`for _, member := range h.donConfig.Members { ... don.SendToNode(...) }`). This allows:
- Triggering workflow executions on behalf of arbitrary/unauthorized senders (workflow-trigger spoofing / unauthorized job run), since the trigger payload's sender is not verified against an allowlist at this layer.
- A vector for flooding/DoS against the entire DON membership, since there is no rate limiting on this ingestion path before fan-out to nodes (the existing `nodeRateLimiter` is not applied here).

The test suite even documents the gap explicitly: `handler_test.go` has an outstanding TODO stating "Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated" — confirming this is a known, currently-unresolved omission rather than a defense-in-depth redundancy elsewhere: [4](#0-3) 

### Likelihood Explanation
High. The affected function is reachable directly by any external client sending a legacy-format message to the internet-facing gateway (no privileged credentials required), and the missing check is an unconditional code-path gap (not dependent on timing or race conditions). The presence of the literal `TODO` comment confirms the maintainers are aware the control is not yet implemented.

### Recommendation
Add sender authorization (allowlist against the DON's configured/authorized workflow owners or senders) and apply `h.nodeRateLimiter` (or an equivalent per-sender/global rate limiter) inside `HandleLegacyUserMessage` before the method-name check and before requests are forwarded to DON members, consistent with how `OutgoingConnectorHandler.HandleGatewayMessage` and other handlers already gate incoming traffic.

### Proof of Concept
Not independently executable from static analysis alone; the code path itself is the proof:
1. An external, unauthenticated client sends a legacy `api.Message` with `Body.Method == MethodWebAPITrigger` and a valid-looking `TriggerRequestPayload` (fresh `Timestamp`) to the Gateway.
2. `handler.HandleLegacyUserMessage` reaches line 384's method check with no prior allowlist/rate-limit gate, then calls `common.ValidatedRequestFromMessage` and forwards to all DON members: [5](#0-4) 
3. Every DON node processes the forwarded trigger request as if it came from an authorized sender.

**Uncertainty note:** I could not fully confirm whether allowlist/rate-limit enforcement might exist at an outer layer (e.g., in `gateway.go`'s `ProcessRequest` or in DON-side `HandleNodeMessage`) before `HandleLegacyUserMessage` is invoked for the legacy message path, since I did not find such a check in the files I was able to inspect within the available search budget, and the explicit TODO comments (both in the handler and its test file) strongly suggest no such check exists yet. A Devin session with full repository access should verify the call path from the HTTP entrypoint (`gateway.go`) into `HandleLegacyUserMessage` to rule out an enforcement point I may have missed.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
