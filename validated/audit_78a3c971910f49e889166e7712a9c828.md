## Title
Stale confirmations from removed multisig members are never purged, allowing a request to execute below the configured live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only clears the `confirmations` map for requests that were *created* by the removed member (`r.member == member`). It never scans the `confirmations` sets of *other* pending requests that the removed member may have already confirmed. Since `confirm()` only compares `confirmations.len()` against `num_confirmations` with no check that every entry in the set still belongs to a current member, a request can be executed using a "confirmation" from an account/key that is no longer part of the multisig, effectively executing below the real live-member threshold.

### Finding Description
`confirm()` counts raw set size against the threshold: [1](#0-0) 

`delete_member()` cleans up requests *created* by the removed member, but not confirmations the removed member left on *other* requests: [2](#0-1) 

The confirmation storage is a plain `HashSet<String>` keyed only by the member's stringified identity, with no reference back to the live `members` set at execution time: [3](#0-2) 

The intended invariant is: a request executes only when it has `num_confirmations` approvals **from members who are still part of the multisig at execution time**. The actual code enforces only: the *cardinality* of the historical confirmations set (regardless of whether those confirmers are still members) reaches `num_confirmations`. Deleting a member removes them from `self.members` and cleans up requests *they created*, but any confirmation they previously cast on someone else's pending request is left untouched in `self.confirmations`, permanently inflating that request's approval count with a "ghost" vote.

### Impact Explanation
This breaks the authorization boundary the multisig is designed to enforce ("a multisig request executed below threshold" — Critical per the impact list). A request can be pushed over `num_confirmations` using a confirmation from an account that has since been removed (e.g., for misbehavior, key rotation, or compromise), so the request executes with strictly fewer *live* approvals than the configured threshold. Since executable actions include `Transfer`, `AddKey`/`AddMember`, and `FunctionCall`, this can lead to unauthorized transfer of NEAR or granting of access/membership that the current member set never actually approved at the required threshold.

### Likelihood Explanation
This requires no attacker code, no owner privilege abuse, and no redeploy — only the normal, documented multisig flow: (1) a member confirms a pending request, (2) that member is later removed via the standard `DeleteMember` action, (3) a subsequent, otherwise-insufficient confirmation from a still-live member pushes the stale total over threshold. This is a straightforward sequencing of ordinary operations any member set will eventually perform (member rotation is an expected lifecycle event), making it readily reachable in practice.

### Recommendation
When executing `delete_member`, iterate `self.confirmations` (or maintain a reverse index of confirmer → request IDs) and remove the deleted member's entry from every request's confirmation set, not just requests they created. Alternatively, at `confirm()` time, filter/count only confirmations whose member entries are still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
Members = {A, B, C, D}, `num_confirmations = 3`.
1. `A.add_request_and_confirm(RequestX)` → `confirmations[RequestX] = {A}` (len 1).
2. `B.confirm(RequestX)` → `confirmations[RequestX] = {A, B}` (len 2, `< 3`, stays pending) — see `confirm()` at [4](#0-3) .
3. Members legitimately fully-confirm and execute a separate `DeleteMember { member: B }` request. `delete_member` runs: it filters `self.requests` for entries whose *creator* (`r.member`) is `B` — `RequestX` was created by `A`, so it is **not** touched; only `self.members` loses `B` — see [5](#0-4) . `confirmations[RequestX]` still equals `{A, B}`.
4. Live members are now {A, C, D}, threshold still 3.
5. `C.confirm(RequestX)` → `confirmations.len() + 1 == 3 >= num_confirmations(3)` → `RequestX` executes, using `B`'s stale, no-longer-valid confirmation alongside only two genuinely live approvals (`A`, `C`).

`RequestX` (which could be a `Transfer`, `AddKey`, or `AddMember` action) executes with only 2 real current-member approvals against a configured 3-of-N threshold — an authorization-threshold bypass.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
