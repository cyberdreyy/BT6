### Title
Missing duplicate/in-flight check on `MessageId` in `HandleLegacyUserMessage` allows cross-request response injection via key reuse - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handleWebAPITriggerMessage` correctly deletes the `savedCallback` entry under the lock before invoking `SendResponse` outside the lock, which prevents a double-fire on the *same* callback object (also independently guarded by `Callback.SendResponse`'s `sent` `atomic.Bool`). However, `HandleLegacyUserMessage` stores a new callback under `msg.Body.MessageId` with no check for an existing/in-flight entry, so if that exact `MessageId` is reused for a second request immediately after the first one's callback is deleted, a later duplicate/delayed node response for the *original* request will be delivered to the *new* request's callback instead. [1](#0-0) [2](#0-1) 

### Finding Description
`handleWebAPITriggerMessage` looks up and deletes the saved callback for `msg.Body.MessageId` while holding `h.mu`, then calls `SendResponse` outside the lock: [1](#0-0) 

`HandleLegacyUserMessage` (invoked once per incoming user request from `gateway.ProcessRequest`) unconditionally writes `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}`, with no check that the key is not already populated by another in-flight request: [2](#0-1) 

`MessageId` is fully attacker/client-controlled — it comes straight from the JSON-RPC request `ID` field (or the legacy `Message.Body.MessageId`), only bounded by a length check, with no uniqueness enforcement by the gateway: [3](#0-2) [4](#0-3) [5](#0-4) 

Exploit sequence for the same DON/handler instance:
1. Request A is submitted with `MessageId = "X"` via `HandleLegacyUserMessage`, storing callback A under key `"X"` and broadcasting to all DON members. [6](#0-5) 
2. Node1's response for A arrives; `handleWebAPITriggerMessage` deletes key `"X"` and calls `SendResponse` on callback A. [1](#0-0) 
3. Immediately after, a second, unrelated request B reuses `MessageId = "X"` via `HandleLegacyUserMessage`. Since there is no "already in use" check, `h.savedCallbacks["X"]` is overwritten with callback B. [2](#0-1) 
4. Node2's delayed/duplicate response for the *original* request A arrives with `MessageId = "X"`. `handleWebAPITriggerMessage` finds `h.savedCallbacks["X"]` — which is now callback B — deletes it and delivers A's stale response data to B's caller. [1](#0-0) 
5. When request B's own legitimate node responses later arrive, the map entry has already been deleted/reassigned, so those responses are silently dropped (`found == false`), and B's caller has already received the wrong response for A.

Because `Callback.SendResponse` uses `sent.CompareAndSwap` and a buffered channel, this does not crash or double-fire on the same object, but the underlying design has no protection against key-collision/reuse across sequential requests. This is corroborated by the newer v2 implementation which explicitly guards against this exact scenario by rejecting reused/duplicate in-flight request IDs: [7](#0-6)  — a check absent from the legacy `HandleLegacyUserMessage` path.

### Impact Explanation
An unauthenticated/unprivileged caller of the gateway's legacy webAPI-trigger endpoint can cause a completely unrelated, subsequent request that happens to reuse the same `MessageId` to receive a stale/foreign response payload instead of its own, and have its own legitimate response silently dropped. This is a cross-request response confusion bug: data belonging to request A is delivered to the party who issued request B. If an attacker can predict, brute-force, or otherwise cause collision with a victim's `MessageId` (there is no per-caller namespace or ownership binding on `MessageId`), this becomes a mechanism to intercept another party's trigger response or to disrupt a victim's request/response flow (denial of the victim's expected response).

### Likelihood Explanation
Exploitability against the *same* attacker's own two sequential requests (self-collision) is trivial and fully attacker-controlled — no special privilege, credentials, or precise timing beyond issuing two requests with the same chosen ID and waiting for the natural duplicate/delayed node responses that occur in any multi-member DON. Exploitability against a genuinely unrelated victim additionally requires either knowledge of the victim's exact concurrent `MessageId` or a low-entropy/predictable ID scheme used by legitimate clients, which reduces but does not eliminate real-world feasibility; the timing window is bounded by natural DON-response latency (which can be hundreds of milliseconds to seconds), not nanosecond-precision races.

### Recommendation
In `HandleLegacyUserMessage`, before inserting into `h.savedCallbacks`, check whether an entry already exists for `msg.Body.MessageId` and reject the request (mirroring the `setupCallback` conflict check already implemented in `v2/http_trigger_handler.go`) rather than silently overwriting it. Additionally, consider binding saved callbacks to a combination of `MessageId` and a gateway-generated nonce/requester identity so that colliding client-chosen IDs cannot be substituted for one another across independent request lifecycles.

### Proof of Concept
Go test plan (`core/services/gateway/handlers/capabilities/handler_test.go`):
1. Call `handler.HandleLegacyUserMessage(ctx, msgA, cbA)` with `MessageId = "X"`, mocking `don.SendToNode` to succeed for both DON members.
2. Call `handler.HandleNodeMessage(ctx, respFromNode1ForA, nodes[0].Address)` — assert `cbA.Wait` returns A's correctly encoded response, and assert `handler.savedCallbacks["X"]` is empty afterward.
3. Immediately call `handler.HandleLegacyUserMessage(ctx, msgB, cbB)` also with `MessageId = "X"` — assert (current buggy behavior) that `handler.savedCallbacks["X"]` now holds `cbB`.
4. Call `handler.HandleNodeMessage(ctx, respFromNode2ForA, nodes[1].Address)` (a duplicate/delayed response still bearing `MessageId = "X"` and payload for request A).
5. Assert `cbB.Wait` returns A's stale response payload (`codec.EncodeLegacyResponse(msgA)`), not an error and not B's expected payload — demonstrating the cross-request response injection. Also assert that B's real node responses (if delivered afterward) are dropped because `handler.savedCallbacks["X"]` no longer exists.
6. After applying the recommended fix (reject duplicate `MessageId`), re-run the test and assert step 3 instead returns an error/conflict response to `cbB` and `handler.savedCallbacks["X"]` remains unaffected/untouched by B until A's lifecycle fully completes.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

// ValidatedMessageFromReq validated and extracts a legacy Gateway Message
// from params field of JSON-RPC request
func ValidatedMessageFromReq(req *jsonrpc.Request[json.RawMessage]) (*api.Message, error) {
	if req.Version != "2.0" {
		return nil, errors.New("incorrect jsonrpc version")
	}
	if req.Method == "" {
		return nil, errors.New("empty method field")
	}
	if req.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var m api.Message
	err := json.Unmarshal(*req.Params, &m)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal request params: %w", err)
	}
	m.Body.Method = req.Method
	m.Body.MessageId = req.ID
	err = m.Validate()
	if err != nil {
		return nil, err
	}
	return &m, nil
}

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	var isLegacyRequest = false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonId == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonId
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
