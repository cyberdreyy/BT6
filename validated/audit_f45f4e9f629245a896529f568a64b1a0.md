### Title
Stale confirmations from removed multisig members still count toward execution threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm()` executes a request once `confirmations.len() + 1 >= num_confirmations`, but the confirmations set is never pruned when a confirming member is later removed from the multisig via a `DeleteMember` request. This allows a request to be executed with fewer live-member confirmations than `num_confirmations` actually requires.

### Finding Description
`confirm()` counts entries in `self.confirmations.get(&request_id)` without checking that each entry still corresponds to a current member of `self.members`: [1](#0-0) 

`delete_member()` only removes *requests originated by* the member being deleted, and purges confirmations for *those* requests. It does not scan other pending requests to strip the removed member's confirmation entries: [2](#0-1) 

`assert_valid_request()`, called from both `confirm()` and `delete_request()`, only checks that the *caller* is currently a member — it performs no validation of the historical confirmers stored in the set: [3](#0-2) 

This breaks the intended equality: `confirmations.len() == number of live members who confirmed`. Instead, `confirmations.len() >= number of live members who confirmed` can hold, since departed members' confirmations remain baked into the set.

### Impact Explanation
Sequence:
1. Multisig has members `{A, B, C, D}` with `num_confirmations = 3`.
2. Member `B` (soon to be removed) confirms a pending `Transfer` request `R` created by `A`. Confirmations for `R` = `{A, B}`.
3. Separately, a `DeleteMember{B}` request is created and executed (requires 3 confirmations from other members) — `B` is removed from `self.members`. `R`'s confirmation set is untouched (it's not "owned" by `B`).
4. Now only `C` needs to confirm `R` to reach `confirmations.len() + 1 == 3 >= num_confirmations`, even though `B` is no longer a member. The request executes (e.g. a `Transfer`) with only 2 genuinely live-member confirmations (`A`'s implicit add + `C`), not 3.

This is a multisig request executed below the intended threshold, matching the "Critical" impact bucket ("a multisig request executed below threshold"). Funds can be moved, keys added, or contract code deployed with fewer than `num_confirmations` current authorized approvals — a direct authorization-boundary violation, not merely a griefing/DoS issue.

### Likelihood Explanation
No privileged access is required beyond being (at some point) a legitimate multisig member who confirms a request before later being removed (a routine operational event — key rotation, member offboarding, compromised-key remediation). Because removal and confirmation ordering is entirely legitimate and expected to happen in normal multisig lifecycle, the likelihood of this state arising is high, and it requires no attacker to do anything abnormal — only for a normal `DeleteMember` action to occur after a confirmation was already cast on an unrelated pending request.

### Recommendation
When executing `DeleteMember`, iterate over all pending requests' confirmation sets and remove the deleted member's entry (mirroring the pruning that is already done for requests the member originated). Alternatively, `confirm()` should recompute confirmations by filtering the stored set through `self.members.contains(...)` before comparing against `num_confirmations`, ensuring the equality "counted confirmations == confirmations from currently live members" always holds.

### Proof of Concept
Not independently executable here (no test harness run), but the state transition is directly derivable from the code paths cited above:
1. `add_request` (by A) → `confirm` (by B) → confirmations = `{A, B}` (2 confirmations, `num_confirmations=3`, not yet executed).
2. A separate request `DeleteMember{B}` reaches 3 confirmations and executes, calling `delete_member(promise, B)` at [4](#0-3)  — this only touches requests where `r.member == B` (i.e., requests B *created*), not the request from step 1 where B only confirmed.
3. `confirm` is called by `C` on the original request: `assert_valid_request` passes (C is a live member), `confirmations.len() (2) + 1 >= num_confirmations (3)` → request executes via `execute_request`, even though B (one of the counted confirmers) is no longer a member. [5](#0-4)

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
