### Title
Zip extraction path traversal (zip-slip) bypasses the advisory `.git` check and writes outside the working directory - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` writes every zip entry using the raw, attacker-controlled `file.Name` via `os.MkdirAll`/`os.OpenFile` in `extractZipFile` without any path sanitization or root confinement. The only path-related gate, `errorIfGitDirectory`, is both non-blocking (its error is only used to control log-warning deduplication via `tracker.actionable`) and trivially bypassed by combining a `.git` prefix with `../` traversal segments, since `isPathAGitDirectory` calls `filepath.Clean` before checking the first path segment.

### Finding Description
`isPathAGitDirectory` in `helpers/archives/path_check_helper.go` (lines 13-19) does:
```go
parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
if len(parts) > 0 && parts[0] == ".git" { return true }
```
`filepath.Clean` normalizes `.git/../../outside/payload` to `../outside/payload`, whose first segment is `..`, not `.git` — so the git-directory heuristic never fires for this crafted name, evading detection entirely.

Separately, even when `errorIfGitDirectory` *does* return a `*os.PathError` (in `ExtractZipArchive`, `helpers/archives/zip_extract.go` lines 89-91), the result is only fed into `tracker.actionable(err)`, which exists purely to suppress repetitive log lines (`helpers/archives/path_error_tracker.go`). It never short-circuits the loop or skips extraction — `extractZipFile(file)` on line 93 is called unconditionally regardless of the git-check outcome.

`extractZipFile` (lines 61-83) and its helpers `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry` all operate directly on `file.Name` with no `filepath.Clean`, no `..` rejection, and no confinement/join against a safe base directory:
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
```
Since `zip.File.Name` originates from the archive's central directory headers and is attacker-controlled (an unprivileged pipeline author can supply an artifact/cache zip with arbitrary names, e.g. via `artifacts:` upload/download or custom cache archives fed back through `ExtractZipFile`/`ExtractZipArchive`), a name like `.git/../../../../tmp/evil` or simply `../../outside/payload` writes outside the intended extraction root. No other sanitization exists anywhere in `helpers/archives/` — confirmed by searching the package for `filepath.Clean`, `filepath.Rel`, or any zip-slip guard; the only hit is the ineffective one in `path_check_helper.go`.

### Impact Explanation
An attacker-controlled zip archive (cache or artifact) extracted by the Runner can write/overwrite files outside the designated build/cache directory on the executor host or container filesystem, matching the "File operations must stay within intended build/cache/artifact roots" invariant. This can lead to cache/artifact poisoning across job re-use, and on shared/persistent executors (shell, or hosts with persistent volumes), potential cross-job/cross-tenant file corruption or overwrite, since the "detect and warn" path never becomes "detect and block."

### Likelihood Explanation
Fully feasible for a normal, unprivileged pipeline author: zip headers permit arbitrary `Name` strings including `../` sequences, and no code path validates or rejects them before extraction. The heuristic that might catch a naive `.git/../` attempt is bypassed by `filepath.Clean` reordering, so the "defense" adds a false sense of security while providing zero enforcement. Repeatable on every extraction of a crafted archive.

### Recommendation
- Make `errorIfGitDirectory` (or a renamed enforcement function) fail-closed: if it returns a non-nil error, `ExtractZipArchive` should skip that file and/or abort extraction, not just gate log output.
- Independently, add a dedicated zip-slip guard in `extractZipFile` (and the directory/symlink/file entry helpers): compute the intended output path via `filepath.Join(destRoot, file.Name)`, `filepath.Clean` it, and verify (e.g. via `filepath.Rel` or a prefix check with `filepath.Separator`) that it stays within `destRoot` before calling `os.MkdirAll`/`os.OpenFile`/`os.Symlink`; reject entries that escape.
- Reject symlink targets that point outside the extraction root as well.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversalEscapesWorkdir(t *testing.T) {
    tmpDir := t.TempDir()
    outsideMarker := filepath.Join(tmpDir, "..", "zipslip_poc_marker")
    defer os.Remove(outsideMarker)

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    // crafted name: bypasses isPathAGitDirectory (Clean -> "../zipslip_poc_marker")
    // and escapes tmpDir via extractZipFile's unsanitized os.OpenFile
    w, _ := zw.Create(".git/../../zipslip_poc_marker")
    _, _ = w.Write([]byte("payload"))
    _ = zw.Close()

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    wd, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(wd)

    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err) // ExtractZipArchive always returns nil

    // Assert file was written OUTSIDE tmpDir despite the .git-looking name
    _, statErr := os.Stat(outsideMarker)
    assert.NoError(t, statErr, "expected zip-slip: file written outside extraction root")
}
```
Expected result today: the test passes, proving the marker file is created outside `tmpDir` and `ExtractZipArchive` returns `nil`, confirming the check is advisory-only and non-enforcing.
