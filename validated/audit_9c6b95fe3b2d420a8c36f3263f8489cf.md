### Title
Attacker-controlled `MessageId` collision in `savedCallbacks` map allows cross-user trigger response delivery - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` stores the caller's response callback in `h.savedCallbacks` keyed solely by the client-supplied `msg.Body.MessageId`, with no uniqueness check, sender binding, or allowlist enforcement. Because `MessageId` is fully attacker-chosen (only constrained to be non-empty, ≤128 bytes, and not end in a null byte), an unprivileged signer can submit a `web_api_trigger` request whose `MessageId` collides with a concurrently in-flight victim request, silently overwriting the victim's saved callback and causing the eventual DON response to be delivered to the wrong caller.

When a DON node later responds, `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks[msg.Body.MessageId]` purely by that string key and forwards the response to whatever callback currently occupies that slot — it does not verify that the response corresponds to the same sender/request that originally created the entry: [4](#0-3) 

Exploit flow: victim B sends a `web_api_trigger` request with `MessageId = X`, which is saved into `savedCallbacks["X"]` and forwarded to DON nodes. Before the DON responds, attacker A sends their own `web_api_trigger` request using the same `MessageId = "X"` (a value they chose, predicted, or observed), which is accepted (signature/format-valid) and overwrites `savedCallbacks["X"]` with A's callback. When a DON node responds with `MessageId = X` (nodes echo back the ID from whichever request they process, and the JSON-RPC `ID`/`MessageId` correlation in `common.ValidatedMessageFromResp`/`ValidatedMessageFromReq` is likewise just the raw ID field), `handleWebAPITriggerMessage` finds A's callback in the map and delivers the response there instead of to B — leaking B's trigger response to A and leaving B's request to time out.

### Impact Explanation
This breaks the isolation invariant of `savedCallbacks`: a response intended for one user's HTTP-triggered capability request can be redirected to another user's session. This is a cross-user response confusion issue — arbitrary-response disclosure / request-hijacking impact class, since the trigger response payload (which can contain data derived from the workflow/capability execution) is attacker-obtainable by simply guessing/colliding a `MessageId`.

### Likelihood Explanation
No authentication/allowlist gate exists before the callback is stored (confirmed by the `TODO` at line 384); any party capable of producing a validly formatted, ECDSA-signed gateway message can reach `HandleLegacyUserMessage`. `MessageId` collision requires only sending a request with a matching ID during the victim's request window — feasible if IDs are predictable/short-lived or observable (e.g., via shared client libraries, timestamps, or brute-forcing a modest ID space), and is fully repeatable since there's no per-ID rate limiting or ownership check.

### Recommendation
Bind each `savedCallbacks` entry to the sender identity in addition to `MessageId` (e.g., key by `(sender, MessageId)` or a gateway-generated unpredictable internal correlation ID), reject/log attempts to reuse an in-flight `MessageId`, and validate on response delivery that the responding DON message matches the original sender/session context before invoking the saved callback.

### Proof of Concept
1. In `handler_test.go`, construct two `api.Message` requests with identical `MessageId` ("collide-id") signed by two different `nodes[i].PrivateKey`/test keys, one representing victim, one attacker.
2. Call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCb)` — assert `h.savedCallbacks["collide-id"]` is set to victim's callback.
3. Call `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCb)` before any node response — assert `h.savedCallbacks["collide-id"]` now equals attacker's callback (overwrite).
4. Simulate DON response via `handler.HandleNodeMessage`/`handleWebAPITriggerMessage` for `MessageId="collide-id"`.
5. Assert `attackerCb.Wait(ctx)` receives the response while `victimCb.Wait(ctx)` times out — demonstrating cross-user delivery/loss.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
