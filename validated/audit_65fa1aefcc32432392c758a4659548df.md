### Title
Signer's v1 (local-state) tenure-duplicate check misses locally-accepted/pre-committed sibling blocks, letting a miner get a conflicting tenure-start block signed - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
`SortitionsView::validate_tenure_change_payload` in the v1 (local signer-state) chainstate path detects a duplicate tenure-start block by calling `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)` [1](#0-0) . This only sees blocks that have already reached `GloballyAccepted` state. It misses a sibling block in the same tenure that a signer has already validated and locally accepted (or pre-committed) but which has not yet crossed the 70% global-acceptance threshold. The equivalent v2 (global-state) check was already fixed to close this exact gap by querying `get_last_signed_block` (which includes `LocallyAccepted`) instead [2](#0-1) , and there is a regression test documenting the fix and the failure mode it addresses [3](#0-2) . The v1 path was left unpatched, so the same bug class (an access/duplicate check that fails to enumerate all states that should count) still exists there.

### Finding Description
`check_proposal` in v1 dispatches tenure-start blocks into `validate_tenure_change_payload`, which is the *only* place the "already have a block in this tenure" rule is enforced — it "never runs again" at validate-ok or at signing time, as the project's own flow documentation states [4](#0-3) .

The v1 implementation of that rule is:

```rust
let last_in_current_tenure = signer_db
    .get_last_globally_accepted_block(&block.header.consensus_hash)
    ...
if let Some(last_in_current_tenure) = last_in_current_tenure {
    ...
    return Err(RejectReason::DuplicateBlockFound);
}
``` [1](#0-0) 

`get_last_globally_accepted_block` only queries rows in state `GloballyAccepted` [5](#0-4) . A block that a signer has validated and moved to `LocallyAccepted` — i.e. it has already produced a signature over it via `mark_locally_accepted` — is invisible to this query until 70% of signer weight has also signed it and it is promoted to `GloballyAccepted`.

This is precisely the bug the v2 path fixed, and the fix's own regression test explains the failure mode directly: "previously, the check used `get_last_globally_accepted_block`, which would miss blocks in `LocallyAccepted` or `PreCommitted` state and incorrectly allow a duplicate tenure change" [6](#0-5) . The v2 fix replaced the query with `get_last_signed_block`, which returns rows in `GloballyAccepted` OR `LocallyAccepted` [7](#0-6)  and was applied in `chainstate/v2.rs` [8](#0-7) . `v1.rs` was never updated to match.

The v1 code path is not dead: `SortitionStateVersion::from_protocol_version` routes any negotiated active signer protocol version below `GLOBAL_SIGNER_STATE_ACTIVATION_VERSION` (currently `2`) to `V1` [9](#0-8) , and `SUPPORTED_SIGNER_PROTOCOL_VERSION`/`GLOBAL_SIGNER_STATE_ACTIVATION_VERSION` are both `2` today [10](#0-9) , meaning any signer fleet running an older/blocking-minority-downgraded protocol version (a state explicitly exercised by `downgrade_signer_protocol_version`) is on this vulnerable code [11](#0-10) .

### Impact Explanation
A single miner, without needing any other signer's key or a majority of signers, can present two competing tenure-start blocks (A and B) for the same tenure to the signer set:
- Before A reaches the 70% signature threshold (still `LocallyAccepted`, not yet `GloballyAccepted`) on some signers,
- the miner sends a second, different tenure-start block B for the same tenure to other signers who have not yet locally accepted A.
- Those signers' `check_proposal` → `validate_tenure_change_payload` call `get_last_globally_accepted_block`, which returns `None` because A is not yet globally accepted, so `DuplicateBlockFound` is never raised and B is allowed to proceed through node validation and pre-commit/signing.

This breaks the one-signed-block-per-tenure invariant: it is possible for a signer to sign block B while other signers have already signed/are signing sibling block A in the same tenure — a signer signing a conflicting block, which is the Critical-impact class defined for this codebase.

### Likelihood Explanation
The trigger requires only normal proposal timing (the race window between the first tenure-start block being validated/locally-accepted by some signers and its promotion to global acceptance) plus a miner (or gossip delay) presenting a second tenure-start block to signers who haven't seen/accepted the first yet. No majority of signers, no stolen keys, and no auth_token access is required — only that the network hasn't (or hasn't yet) negotiated up to the v2/global-state protocol version, which is a state the project's own tests show is reachable (protocol downgrade, mixed-version fleets).

### Recommendation
Update `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload` to use `signer_db.get_last_signed_block(&block.header.consensus_hash)` instead of `get_last_globally_accepted_block`, mirroring the fix already applied in `chainstate/v2.rs`, so any `LocallyAccepted` (or otherwise signed) sibling block in the tenure is correctly treated as a duplicate and rejected.

### Proof of Concept
1. Boot a signer set running protocol version < `GLOBAL_SIGNER_STATE_ACTIVATION_VERSION` (v1/local-state path), e.g. via a blocking-minority downgrade as in `downgrade_signer_protocol_version`.
2. Miner proposes tenure-start block A for tenure T; wait until at least one signer S1 has validated and locally-accepted A (`BlockState::LocallyAccepted`) but before 70% weight is reached (A stays out of `GloballyAccepted`).
3. Miner proposes a second, distinct tenure-start block B for the same tenure T (different tx set/pubkey_hash) to a signer S2 that has not yet processed A.
4. Observe that S2's `validate_tenure_change_payload` call to `get_last_globally_accepted_block` returns `None` (A isn't globally accepted yet), so no `DuplicateBlockFound` rejection is produced, and S2 proceeds to validate and potentially sign B — producing two signed, conflicting tenure-start blocks (A, B) for tenure T across the signer set.

/// The version of the sortition state
#[derive(Debug, Clone)]
pub enum SortitionStateVersion {
    /// Version 1: Local Signer State evaluation only
    V1,
    /// Version 2: Global Signer State evaluation
    V2,
}

impl SortitionStateVersion {
    /// Convert the protocol version to a sortition state version
    pub fn from_protocol_version(version: u64) -> Self {
        if version < GLOBAL_SIGNER_STATE_ACTIVATION_VERSION {
            Self::V1
        } else {
            Self::V2
        }
    }
    /// Uses global state version
    pub fn uses_global_state(&self) -> bool {
        match self {
            Self::V1 => false,
            Self::V2 => true,
        }
    }
}

/// **majority of locally supported** signer protocol versions.
///
/// Scenario (10 signers):
/// 1) Baseline: all signers start on `SUPPORTED_SIGNER_PROTOCOL_VERSION` and can sign blocks.
/// 2) Downgrade 30%: non-blocking minority downgraded. Stays at `SUPPORTED_SIGNER_PROTOCOL_VERSION`.
/// 3) Downgrade 40%: blocking minority downgraded. Downgrades to `SUPPORTED_SIGNER_PROTOCOL_VERSION - 1`.
/// 4) Upgrade 70%: majority upgraded. Upgrades back to `SUPPORTED_SIGNER_PROTOCOL_VERSION`.
#[test]
#[ignore]
fn downgrade_signer_protocol_version() {
    if env::var("BITCOIND_TEST") != Ok("1".into()) {
        return;
    }
    // To make the math easier, use 10 signers
    let num_signers: usize = 10;

    // Integer percent helper (e.g. 30 => 3 when num_signers=10)
    fn pct(num_signers: usize, percent: usize) -> usize {
        (num_signers * percent) / 100
    }

    // Boot with the most recent supported version
    let mut signer_test: SignerTest<SpawnedSigner> = SignerTest::new(num_signers, vec![]);
    signer_test.boot_to_epoch_3();

    info!(
        "------------------------- Confirm miner tenure continues and all signers use protocol {SUPPORTED_SIGNER_PROTOCOL_VERSION} -------------------------"
    );
    let versions = signer_test.signer_addresses_versions();
    mine_burn_block_and_confirm_signer_rollover(&mut signer_test, &versions);

    let downgraded_version = SUPPORTED_SIGNER_PROTOCOL_VERSION.saturating_sub(1);
    let downgraded_versions = signer_test
        .signer_addresses_versions()
        .into_iter()
        .map(|(addr, _)| (addr, downgraded_version))
        .collect::<Vec<_>>();
    info!("------------------------- Downgrading Signer Versions to {downgraded_version} for 30 Percent of Signers -------------------------");
    // Since only 30 percent downgraded. Active protocol version should stay the same
    signer_test
        .restart_first_n_signers_with_supported_version(pct(num_signers, 30), downgraded_version);
    let versions = signer_test.signer_addresses_versions();
    mine_burn_block_and_confirm_signer_rollover(&mut signer_test, &versions);
    info!("------------------------- Downgrading Signer Versions to {downgraded_version} for 40 Percent of Signers -------------------------");
    // A blocking minority has downgraded, so expect everyone to negotiate to downgraded_version.
    signer_test

    mine_burn_block_and_confirm_signer_rollover(&mut signer_test, &downgraded_versions);

    // A majority of signers have upgraded, expect everyone to negotiate back to the supported version.
