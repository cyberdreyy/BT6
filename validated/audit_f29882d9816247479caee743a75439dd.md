### Title
Unauthenticated exposure of LOOP plugin pprof/metrics endpoints allows internal service reconnaissance, path-traversal request forwarding, and profiling-based DoS - ([File: core/web/router.go])

### Summary
`loopRoutes` is mounted directly on the top-level `api` group with no `auth.Authenticate*` middleware, unlike every other sensitive route group (`debugRoutes`, `authv2`). This leaves `LoopRegistryServer.pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`, `pluginMetricHandler`, and `discoveryHandler` reachable by any unauthenticated client of the node's HTTP API.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the `api` group with only rate-limiting and session middleware attached, and then calls `loopRoutes(app, api)` without any authentication wrapper: [1](#0-0) 

Compare this to `debugRoutes`, which explicitly requires `auth.Authenticate(...)` before exposing `/debug/vars`, and `authv2`/`metricRoutes`, which require token/session auth before exposing the node's own `/debug/pprof/*` endpoints: [2](#0-1) [3](#0-2) 

`loopRoutes` registers `GET /plugins/:name/debug/pprof/*profile`, `POST /plugins/:name/debug/pprof/symbol`, `GET /plugins/:name/metrics`, and `GET /discovery` with no auth middleware at all. `pluginPPROFHandler` takes the attacker-controlled `:name` and wildcard `:profile` route params and builds an outbound request URL by direct string concatenation: [4](#0-3) 

The `:profile` wildcard is inserted into the URL unsanitized (`"http://%s:%d/debug/pprof/"+gc.Param("profile")`), so an attacker can supply path-traversal sequences (e.g. `../foo`) to redirect the forwarded request to arbitrary paths on the internal LOOP plugin's HTTP listener, not just its pprof endpoints. The `seconds` query parameter is also attacker controlled and directly extends the request timeout (`PPROFOverheadSeconds` + attacker value), letting an unauthenticated caller keep server-side goroutines and outbound connections open for extended, attacker-chosen durations: [5](#0-4) 

Because there is no authentication middleware on this route group, none of the node's existing auth/role checks (`auth.Authenticate`, `auth.RequiresRunRole`, etc.) are invoked before these handlers execute, so an unauthenticated attacker of the node's public API port can reach them directly.

### Impact Explanation
An unauthenticated attacker can: (1) enumerate registered LOOP plugins and their internal metrics topology via `/discovery` and `/plugins/:name/metrics`; (2) pull CPU/heap/goroutine pprof dumps from internal plugin processes, which can leak sensitive runtime data (memory contents, internal addresses, stack traces) without any credential; (3) abuse the unsanitized wildcard `:profile` parameter to redirect the node's outbound proxy request to other paths on the internal plugin listener (limited SSRF/path traversal within the loop-host network); and (4) trigger resource exhaustion / denial of service by repeatedly issuing long-`seconds` profile requests that tie up server-side goroutines and connections. This falls under Chainlink's "unauthorized information disclosure" and "denial of service" bounty impact classes, since it requires no privilege and directly bypasses the node's authentication layer for an entire route family.

### Likelihood Explanation
No credentials, roles, or special preconditions are required — only network reachability to the node's standard HTTP API port, which is the same port used for all other authenticated v2 routes. The routes are unconditionally registered in `NewRouter` for every node running LOOP plugins, making this fully repeatable and trivially automatable (a simple `curl` to `/plugins/<name>/debug/pprof/heap` or `/discovery`).

### Recommendation
Wrap `loopRoutes` (or at minimum the `pprof`/`metrics` sub-routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used elsewhere, and apply an admin/run-role requirement (`auth.RequiresAdminRole` or similar) given the sensitivity of pprof data. Additionally, validate/allowlist the `:profile` wildcard against the known pprof sub-paths (`profile`, `heap`, `goroutine`, `allocs`, `block`, `mutex`, `threadcreate`, `trace`, `cmdline`) instead of concatenating it unsanitized into the outbound URL, and cap the `seconds` parameter server-side.

### Proof of Concept
Go handler-integration test plan (using `httptest` + the router built by `NewRouter`):
1. Construct a test `chainlink.Application` with a `LoopRegistry` containing one registered plugin (e.g. name `"median"`, with a stub HTTP server on `EnvCfg.PrometheusPort` serving `/debug/pprof/heap`).
2. Build the router via `web.NewRouter(app, nil)` without setting any `Authorization`/session cookie on the test request.
3. Issue `GET /plugins/median/debug/pprof/heap` with no auth headers; assert the response status is `200 OK` and contains the stub pprof payload — proving the endpoint is reachable without authentication (compare against `GET /debug/vars` or `GET /v2/jobs`, which should return `401`).
4. Issue `GET /plugins/median/debug/pprof/../secret` (URL-encoded traversal) against the stub server and assert the forwarded request path on the stub server matches the traversed path, proving unsanitized path forwarding.
5. Issue `GET /plugins/median/debug/pprof/profile?seconds=60` and assert the outbound request context timeout is `60+30=90s` (via a mock `http.Client`/`RoundTripper` capturing the deadline), demonstrating attacker control over hold-open duration.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
