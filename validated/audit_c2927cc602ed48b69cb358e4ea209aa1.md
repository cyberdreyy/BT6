### Title
Unregistered signer's `web_api_trigger` legacy Message bypasses gateway-side authorization and is broadcast to all DON nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`api.Message.Validate()` only checks structural well-formedness and that the signature recovers to *some* ECDSA address; it never checks DON membership. `gateway.ProcessRequest` calls only `msg.Validate()` before dispatching to the DON's handler. The WebAPI capabilities handler (`handler.HandleLegacyUserMessage`, used for `MethodWebAPITrigger`) has an explicit unimplemented `// TODO: apply allowlist and rate-limiting here` and forwards the message to **all** configured DON members without checking `msg.Body.Sender` against any allowlist.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go:250-262`) treats any request carrying a `DonId` as legacy, calls `msg.Validate()` [1](#0-0) , and — as long as the signature is well-formed and recoverable and the DON ID is configured — dispatches straight to `h.HandleLegacyUserMessage(ctx, msg, callback)` with no further sender check [2](#0-1) .

`Message.Validate()` (`core/services/gateway/api/message.go:54-88`) only validates field lengths/null-byte suffixes and calls `ExtractSigner()` to populate `m.Body.Sender`; it never checks that the recovered address belongs to any registered/allowlisted entity [3](#0-2) .

In `core/services/gateway/handlers/capabilities/handler.go`, `HandleLegacyUserMessage` (used for `MethodWebAPITrigger`) contains the comment `// TODO: apply allowlist and rate-limiting here` immediately before the method-name check, and then unconditionally forwards the request to every DON member via `don.SendToNode` — `msg.Body.Sender` is never checked against any list at the gateway layer [4](#0-3) . This confirms the attacker's premise: any unregistered keypair can produce a well-formed, validly-signed `Message` targeting a real `DonId`, pass `Validate()`, and reach `HandleLegacyUserMessage`, which broadcasts the attacker's arbitrary trigger payload to all DON nodes.

The actual last line of defense is on the DON-node side in `core/capabilities/webapi/trigger/trigger.go`, where `processTrigger` checks `trigger.allowedSenders[sender.String()]` per matched topic before dispatching a `TriggerResponse` to the registered workflow [5](#0-4) . Since every configured trigger maintains its own `allowedSenders` map, an unregistered sender's trigger event is rejected there ("unauthorized Sender") and no workflow is actually triggered — so the workflow-triggering invariant is preserved at the node, not at the gateway.

### Impact Explanation
This is not full unauthorized-job-triggering (blocked by node-side `allowedSenders`), but it is a real defense-in-depth gap: the gateway forwards attacker-controlled `web_api_trigger` payloads to **every node of a real DON** without any gateway-level authorization, rate limiting, or membership check, despite an explicit TODO acknowledging this is missing. This allows an unauthenticated attacker to: (1) consume node/gateway processing and network resources across the whole DON for any real `DonId` (amplification/DoS vector — one gateway request fans out to N nodes), and (2) probe/enumerate DON membership behavior and rate limits, since messages reach `processTrigger` on every node before being rejected. It does not itself qualify as job-run compromise or fund movement given the node-side allowlist, so the practical bounty class is closer to "gateway-side authorization gap / resource-amplification" rather than "unauthorized job run."

### Likelihood Explanation
Fully feasible for an unauthenticated attacker: generate any ECDSA keypair, sign a `Message` with `Method: web_api_trigger`, a real/known `DonId`, and any payload with a `Timestamp` within `MaxAllowedMessageAgeSec`, and POST it to the gateway user port. No credentials, DON membership, or prior state are required, and the request is fully repeatable since `Validate()`/`ProcessRequest` place no membership gate in the path.

### Recommendation
Implement the missing allowlist/rate-limit check at the gateway layer in `handler.HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go`) before forwarding to `don.SendToNode`, matching the intent of the existing TODO — e.g., reject requests whose `msg.Body.Sender` is not present in any registered trigger's `allowedSenders` set (or a DON-level allowlist) and apply the `nodeRateLimiter`/a sender-based rate limiter prior to fan-out, rather than relying solely on the node-side check in `processTrigger`.

### Proof of Concept
1. Unit test in `core/services/gateway/handlers/capabilities` (or a handler-integration test mirroring `gateway_test.go`'s `newGatewayWithMockHandler`):
   - Construct a `config.DONConfig` with N node members.
   - Craft an `api.Message` with `Method: MethodWebAPITrigger`, a valid `DonId`, `Payload` containing `webapicap.TriggerRequestPayload{Timestamp: now}`, signed with a freshly generated, unregistered `ecdsa.PrivateKey` (`crypto.GenerateKey()`), via `msg.Sign(privateKey)`.
   - Call `msg.Validate()` and assert it returns `nil` (confirming signature-format-only validation passes).
   - Call `handler.HandleLegacyUserMessage(ctx, msg, callback)` with a mocked `handlers.DON`, and assert `don.SendToNode` is invoked for **every** configured member address (demonstrating the gateway fans out without a sender check).
2. Companion node-side test using `triggerConnectorHandler.processTrigger` (`core/capabilities/webapi/trigger/trigger.go`) with a registered workflow whose `allowedSenders` does NOT include the attacker's address; assert `processTrigger` returns the `"unauthorized Sender"` error and no `TriggerResponse` is emitted on `trigger.ch`, confirming the node — not the gateway — is the only enforcement point today.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
