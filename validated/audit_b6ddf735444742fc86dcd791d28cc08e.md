### Title
Unscoped `savedCallbacks` map keyed only by attacker-controlled `MessageId` allows response hijacking / clobbering across senders - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` stores each pending user callback in `h.savedCallbacks` keyed solely by `msg.Body.MessageId`, a value fully controlled by the requesting client via the JSON-RPC `id` field, without checking whether an entry already exists or binding the entry to the request's authenticated sender. A second, concurrent `HandleLegacyUserMessage` call using the same `MessageId` (chosen by any client) silently overwrites the first entry, so the eventual `handleWebAPITriggerMessage` node response is delivered to the second caller's `Callback` instead of the first requester's.

### Finding Description
`MessageId` originates entirely from client input: in `JsonRPCCodec.DecodeJSONRequest` (`core/services/gateway/api/jsonrpccodec.go:24-33`) it is copied directly from the JSON-RPC request `ID` (`msg.Body.MessageId = request.ID`), and `Message.Validate()` (`core/services/gateway/api/message.go:54-88`) only checks length/format constraints — it never ties `MessageId` uniqueness to the sender that `ExtractSigner()` derives from the signature.

In `HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go:411-414`):
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
```
this write is unconditional — there is no `if _, exists := h.savedCallbacks[...]; exists` guard, and no check that a pre-existing entry belongs to the same `msg.Body.Sender`. Any two independently and validly signed requests (different senders, both pass `Validate()`/signature checks) that happen to carry the same `MessageId` will collide in this single, DON-scoped map.

Later, `handleWebAPITriggerMessage` (`handler.go:148-162`) looks up and deletes by `MessageId` only and delivers the response to whichever `Callback` is currently stored — the most recent writer wins:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
return savedCb.SendResponse(...)
```
No authentication/authorization check re-validates that the response's destination `Callback` corresponds to the sender who originally triggered the DON request. The signature verification performed at ingress (`Message.Validate`) only proves who sent *that particular message*, not that its `MessageId` is unique/unclaimed.

### Impact Explanation
If a second sender submits a `web_api_trigger` (or is racing a legitimate one) with a colliding `MessageId`, the original requester's callback is orphaned (their gateway HTTP call will hang until the `callback.Wait` timeout and eventually receive `RequestTimeoutError`), and the DON's response — which may echo the original request's payload/trigger metadata — is instead delivered to the second sender's HTTP response. This is a cross-user response confusion: request/response attribution is no longer guaranteed to be to a single authenticated sender, and it also provides a trivial DoS primitive against a targeted sender's request if the `MessageId` (or its likely value, e.g., a small/sequential counter) can be predicted or brute-forced.

### Likelihood Explanation
No special privilege is required — any unauthenticated (but signature-capable) client of the gateway user-facing HTTP API can submit a `web_api_trigger` request with an arbitrary `message_id` (`api.MessageIdMaxLen` allows short strings and the JSON-RPC `id` cap is 200 chars). The main precondition is that the attacker's chosen `MessageId` collides with a value used by a concurrently pending legitimate request; this becomes practical if IDs are short/sequential/predictable, or via brute force / birthday-style collision attempts against high-traffic DONs, since the map is shared across all users of a given DON handler. No signature bypass is needed — the attacker only sends their own validly signed message with a colliding ID.

### Recommendation
Scope pending-callback keys by both `MessageId` and `Sender` (e.g., `sender+":"+messageId`), or reject/queue the new request with an error when an unexpired entry for the same `MessageId` already exists instead of silently overwriting it. Additionally, when delivering a response in `handleWebAPITriggerMessage`, verify that the response's `Sender`/node context matches the originally recorded sender before invoking the stored callback.

### Proof of Concept
Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build two distinct signed `api.Message` values for `MethodWebAPITrigger` with different private keys (different senders) but identical `Body.MessageId` (e.g., `"dup-id"`), each with valid payload/timestamp.
2. Call `handler.HandleLegacyUserMessage(ctx, msgA, cbA)` then `handler.HandleLegacyUserMessage(ctx, msgB, cbB)` (simulating a race/collision), each with a distinct `hc.NewCallback()`.
3. Simulate a node response for the DON tied to `msgA`'s `MessageId` via `handler.HandleNodeMessage(ctx, resp, nodeAddr)`.
4. Assert that `cbA.Wait(ctx)` times out/never resolves (original requester's callback dropped) while `cbB.Wait(ctx)` receives the response intended for `msgA` — proving cross-sender response delivery and demonstrating the missing existence/sender check at `handler.go:411-414`. func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (*JsonRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	if err != nil {
		return nil, err
	}
	msg.Body.MessageId = request.ID
	msg.Body.Method = request.Method
	return &msg, nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
