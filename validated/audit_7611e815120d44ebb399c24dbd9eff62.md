### Title
`updateMultiplier`/`updateUIMultiplier` on B20 Asset tokens mutate economic value with no `ensure_not_paused` guard - (File: `crates/common/precompiles/src/b20_asset/logic/v1.rs`, `crates/common/precompiles/src/b20_asset/logic/v2.rs`)

### Summary
The B20 Asset precompile logic implements a `Pausable`-style feature-bit system covering `TRANSFER`, `MINT`, `BURN`, and (in V2) `SEIZE`. Every one of these state-changing entry points calls `B20Guards::ensure_not_paused` before mutating balances. However, `update_multiplier` (V1/V2) and `update_ui_multiplier` (V2) — the functions that rescale every holder's effective/UI balance and `totalSupplyUI()` — perform only a role check (`ensure_operator_role`) and never check any pause bit, because no `MULTIPLIER` variant even exists in `PausableFeature`.

### Finding Description
`AssetV1::update_multiplier` and `AssetV2::update_multiplier`/`update_ui_multiplier` only guard on the `OPERATOR_ROLE`, with no pause check at all: [1](#0-0) [2](#0-1) [3](#0-2) 

By contrast, every balance-affecting operation in the same modules explicitly checks the corresponding pause bit first: [4](#0-3) [5](#0-4) 

This is structural, not an oversight limited to one code path: the `PausableFeature` enum itself has no `MULTIPLIER` member — it is fixed at `TRANSFER`/`MINT`/`BURN` (V1) or `TRANSFER`/`MINT`/`BURN`/`SEIZE` (V2), so there is no bit an operator could even choose to pause this surface with: [6](#0-5) [7](#0-6) 

`total_supply_ui`/`balance_of_ui` derive directly from this multiplier, so changing it instantly rescales the UI-visible value of every account's holdings without moving a single raw token: [8](#0-7) 

### Impact Explanation
This mirrors the referenced GoGoPool finding class exactly: an economically significant, value-inflating/deflating operation ("inflate the token value") is not covered by the pause mechanism that protects all its sibling operations. When a token is paused (e.g. `TRANSFER`+`MINT`+`BURN`+`SEIZE` all halted in response to an incident, exploit investigation, or compromised key), an operator can still instantly rescale the effective value of every holder's balance via `updateMultiplier`/`updateUIMultiplier`, while ordinary holders are frozen out of `transfer`/`burn` and cannot react (exit, hedge, or arbitrage). Concretely: if the `OPERATOR_ROLE` key is compromised at the same time governance pauses the token to contain damage, the attacker can still rebase the multiplier upward for accounts they control (crediting themselves UI value not backed by any minted raw supply) and simply wait for unpause to redeem/transfer it out — an unauthorized value-creation ("unbacked supply") path that the pause was specifically supposed to prevent.

### Likelihood Explanation
Requires `OPERATOR_ROLE`, so it is not exploitable by a fully anonymous caller, but it is directly reachable by any account already holding that role (the same class of actor GoGoPool judges accepted as the trust boundary being violated), via a single precompile call (`updateMultiplier`/`updateUIMultiplier`), with no additional preconditions beyond the role and multiplier-bounds checks already in the code.

### Recommendation
Add a dedicated `MULTIPLIER` (or reuse an existing) `PausableFeature` bit and gate `update_multiplier` and `update_ui_multiplier` (and `cancel_ui_multiplier_update`) behind `B20Guards::ensure_not_paused`, consistent with `transfer`/`mint`/`burn`/`seize`, so that pausing a token also halts the exchange-rate/rebase surface.

### Proof of Concept
1. Deploy a `B20Asset` (V2) token; grant `OPERATOR_ROLE` to address `OP`.
2. Guardian/admin calls `pause([TRANSFER, MINT, BURN, SEIZE])` — confirmed to block all balance-moving operations (see `golden_transfer_reverts_when_paused`, `golden_batch_mint_reverts_when_paused`, `golden_seize_reverts_when_paused`).
3. While still paused, `OP` calls `updateMultiplier(newMultiplier)` (or schedules `updateUIMultiplier`) — this succeeds because `update_multiplier`/`update_ui_multiplier` never call `ensure_not_paused`: [2](#0-1) 
4. `totalSupplyUI()`/`balanceOfUI(account)` immediately reflect the new multiplier for every holder, even though holders cannot `transfer`/`burn` to react, while unpausing later lets the rescaled value be freely moved.
