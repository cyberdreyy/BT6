### Title
Paused ERC4626 vault permanently freezes programmable-borrower epochs and withdrawals - (File: `contracts/strategies/idle/ProgrammableBorrower.sol`)

### Summary
`ProgrammableBorrower.onStopEpoch` makes `IdleCDOEpochVariant.stopEpoch` depend on a successful ERC4626 `vault.withdraw` whenever the borrower does not already hold enough underlying. If the configured external vault pauses withdrawals, the stop transaction reverts with `StopEpochVaultLiquidityUnavailable`, leaving `isEpochRunning` active and all withdrawal requests unclaimable. [1](#0-0) [2](#0-1) 

### Finding Description
At epoch start, the programmable borrower deposits all idle underlying into the configured ERC4626 vault. [3](#0-2)  At epoch end, `stopEpoch` calls `onStopEpoch`; if the cash shortfall is economically covered by vault shares, a failed `vault.withdraw` is rethrown as `StopEpochVaultLiquidityUnavailable` instead of returning `false` and entering the default path. [4](#0-3) 

This behavior is intentionally used for transient liquidity failures, but there is no fallback that skips the unavailable vault or marks the sleeve unavailable. [5](#0-4)  `emergencyExitVault` uses the same external vault position through `vault.redeem`, so it cannot bypass a vault whose withdrawal and redemption functions are paused. [6](#0-5)  `setVault` also refuses migration while either epoch accounting is active or the old vault share balance is nonzero. [7](#0-6) 

### Impact Explanation
A permanently paused or permanently reverting ERC4626 withdrawal path permanently prevents `stopEpoch` from completing. The epoch remains running, `restoreOperations` returns without unpausing while `isEpochRunning` is true, normal withdrawal requests remain pending, and the underlying represented by the vault shares remains inaccessible. [8](#0-7) [9](#0-8) 

For the existing test configuration, a `10,000 USDC` AA deposit with a `5,000 USDC` pending withdrawal causes the stop path to require a vault recall; if that recall permanently reverts, all vault-sleeve principal and the pending receipt remain frozen indefinitely. [5](#0-4) 

### Likelihood Explanation
The issue requires an external ERC4626 vault used by a programmable borrower to become paused or permanently unable to process redemptions. That condition is outside the lender’s control and does not require a malicious privileged role. The code explicitly anticipates temporary vault liquidity failure, but only supports retrying the same withdrawal path and provides no exclusion, forced default, or migration route while shares remain. [10](#0-9) [11](#0-10) 

### Recommendation
Add an owner/manager-controlled failed-vault path that can disable the current vault without requiring a successful redemption. For example:

- allow `setVault` during an emergency after marking the old position as impaired and tracking its claim basis separately;
- add an `onStopEpoch` failure mode that lets `IdleCDOEpochVariant` enter default or loss accounting instead of reverting forever;
- support a permissioned claim/recovery mechanism for any future redemption from the disabled vault;
- preserve the current retryable `StopEpochVaultLiquidityUnavailable` behavior only until the operator explicitly marks the vault as failed.

The mitigation should distinguish temporary illiquidity from permanent integration failure so an ordinary failed withdrawal does not prematurely socialize losses. [12](#0-11)

// test/foundry/ProgrammableBorrowerCreditVault.t.sol
function testPausedProgrammableVaultPermanentlyBlocksStopEpoch() external {
    uint256 amount = 10_000 * oneScale;
    uint256 requestedShares = aaTranche.balanceOf(address(this)) / 2;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    idleCDO.depositAA(amount);
    cdoEpoch.requestWithdraw(requestedShares, address(aaTranche));
    _startEpochAndCheckPrices(0);

    assertGt(
        morphoVault.balanceOf(address(programmableBorrower)),
        0,
        "idle assets should be inside external vault"
    );

    // Simulate a permanently paused external ERC4626 on the mainnet fork.
    vm.mockCallRevert(
        STEAKHOUSE_USDC,
        abi.encodeWithSelector(IERC4626.withdraw.selector),
        "vault withdrawals paused"
    );
    vm.mockCallRevert(
        STEAKHOUSE_USDC,
        abi.encodeWithSelector(IERC4626.redeem.selector),
        "vault redemptions paused"
    );

    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(StopEpochVaultLiquidityUnavailable.selector));
    cdoEpoch.stopEpoch(0, 0);

    assertTrue(cdoEpoch.isEpochRunning(), "epoch remains stuck");
    assertFalse(cdoEpoch.defaulted(), "default handling is unreachable");
    assertGt(strategy.pendingWithdraws(), 0, "receipt remains unfunded");

    // The emergency exit uses redeem() on the same paused vault and cannot unwind it.
    vm.prank(manager);
    vm.expectRevert("vault redemptions paused");
    programmableBorrower.emergencyExitVault(0);

    // Vault replacement is also blocked while the paused position remains.
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    programmableBorrower.setVault(GAUNTLET_USDC_PRIME);

    // Retrying after an arbitrary delay reaches the same permanent revert.
    vm.warp(block.timestamp + 365 days);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(StopEpochVaultLiquidityUnavailable.selector));
    cdoEpoch.stopEpoch(0, 0);
}

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;
    epochAccountingActive = true;

  function onStopEpoch(uint256 _amountRequired, bool _isRequestingAllFunds) external nonReentrant returns (bool success) {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // if we want to close the pool and the borrower still owes any amount, consider it a failure and let IdleCDO handle it as a default instead of a close. 
    if (_isRequestingAllFunds && (borrowerPrincipal != 0 || borrowerInterestDebt != 0 || borrowerInterestAccrued != 0)) {
      return false;
    }

    uint256 onHand = underlyingToken.balanceOf(address(this));
    if (_amountRequired > onHand) {
      uint256 shortfall = _amountRequired - onHand;
      // If the vault shares do not economically cover the shortfall, let IdleCDO's later
      // transferFrom fail and use the existing default path. Only an otherwise-covered ERC4626
      // withdrawal failure should make stopEpoch retryable.
      if (shortfall > _currentVaultAssets()) return true;
      try vault.withdraw(shortfall, address(this), address(this)) returns (uint256 shares) {
        if (epochAccountingActive) {
          epochWithdrawnFromVault += shortfall;
        }
        emit WithdrawnFromVault(shortfall, shares, address(this));
      } catch {
        revert StopEpochVaultLiquidityUnavailable();
      }
    }

    // `totalInterestDueNow()` was already read by IdleCDO before calling this hook, so once the
    // stop flow begins we can clear the previous carry and snapshot the remaining vault sleeve
    // as the baseline for measuring buffer-period vault PnL before the next epoch starts.
    bufferedVaultDelta = 0;
    bufferInterest = 0;
    bufferStartVaultAssets = _currentVaultAssets();

    // Stop reserving epoch-end withdraw liquidity once IdleCDO has started the stop flow.
    epochPendingWithdraws = 0;
    epochAccountingActive = false;
    emit EpochAccountingStopped();
    success = true;
  }

  /// @notice Request a withdraw from the vault
  /// @param _amount Amount of tranche tokens 
  /// @param _tranche Tranche to withdraw from
  /// @return _underlyings Amount of underlyings requested
  function requestWithdraw(uint256 _amount, address _tranche) external returns (uint256 _underlyings) {
    _checkTranche(_tranche);
    _checkNotAllowed(
      (_tranche == AATranche ? !allowAAWithdrawRequest : !allowBBWithdrawRequest) ||
      !isWalletAllowed(msg.sender)
    );
  
    // we check if there are donated assets to the pool and transfer them to the feeReceiver if any
    _skimDonatedAssets();

    // we trigger an update accounting to check for eventual losses
    _updateAccounting();

    IdleCreditVault creditVault = IdleCreditVault(strategy);
    if (_amount == 0) {
      _amount = _userTrancheBal(msg.sender, _tranche);
    }
    _underlyings = _trancheToUnderlyings(_amount, _tranche);

    // Programmable borrower deployments do not support instant withdrawals.
    // If apr decresed wrt last epoch, request instant withdraw and burn tranche tokens directly
    // we compare unscaled aprs
    if (_isInstantWithdrawEnabled()) {
      uint256 currentApr = creditVault.unscaledApr();
      if (lastEpochApr > (currentApr + instantWithdrawAprDelta)) {
        // burn strategy tokens from cdo and mint an equal amount to msg.sender as receipt
        creditVault.requestInstantWithdraw(_underlyings, msg.sender);
        // burn tranche tokens and decrease NAV
        _withdrawOps(_amount, _underlyings, _tranche);
        return _underlyings;
      }
    }

    uint256 principal = _underlyings;
    (uint256 interest, int256 diff) = _calcInterestWithdrawRequest(_underlyings, _tranche);
    uint256 totalFees = _totalWithdrawFees(principal, interest);
    // user is requesting principal + interest minus upfront management fee and net performance fee
    _underlyings = principal + interest - totalFees;
    // add expected fees to pending withdraw fees counter
    pendingWithdrawFees += totalFees;

    /// if there is an AA withdrawal the overperformance that the amount withdrawed would have generated for BB tranches
    /// is saved in interestForOverUnderPerformance. This is used to calculate the interest that should be added to the
    /// expectedEpochInterest at the startEpoch.
    /// If there is a BB withdrawal this amount is subtracted from the expectedEpochInterest
    interestForOverUnderPerformance += diff;

    // The receipt is fixed now and leaves live NAV. Charge management fees upfront
    // for the time it waits outside live NAV: remaining buffer plus the next epoch.
    creditVault.requestWithdraw(_underlyings, msg.sender, principal);
    // burn tranche tokens and decrease NAV without interest for the next epoch as it was not yet counted in NAV
    _withdrawOps(_amount, principal, _tranche);
