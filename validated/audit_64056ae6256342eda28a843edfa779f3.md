### Title
Single-step activation registry admin rotation can permanently lock out feature activation control - (File: `crates/common/precompiles/src/activation/storage.rs`)

### Summary
`ActivationRegistryStorage::set_admin` rotates the privileged admin address that gates `activate`/`deactivate` for critical Base-native precompile features (`PolicyRegistry`, `B20Stablecoin`, `B20Asset`) in a single transaction, with no staging/confirmation step. This mirrors the reported DAO-address bug class: a privileged address change that should be two-step (offer/accept) is implemented as one atomic write, so a copy-paste or typo error in the `newAdmin` argument transfers control to an unintended (but non-zero) address with no recovery path.

### Finding Description
`set_admin` only guards against the zero address and requires the current admin as caller; it writes `new_admin` directly to storage in one call: [1](#0-0) 

Contrast this with the `PolicyRegistry` precompile, which the codebase itself implements with a proper two-step admin transfer (`stageUpdateAdmin` followed by `finalizeUpdateAdmin` from the pending admin), as validated by its own tests: [2](#0-1) 

The activation registry's admin controls activation/deactivation of feature flags gating other precompiles (e.g. `B20Stablecoin`, `B20Asset`, `PolicyRegistry`) via `require_admin_caller` inside `set_activated`: [3](#0-2) 

Because `set_admin` accepts any non-zero address in a single call, a misclick or wrong-address paste by the legitimate admin (e.g. an EOA or multisig operator) immediately and irreversibly hands admin authority to an address that may not be under anyone's control, with the previous admin instantly losing all rights (enforced/tested at `crates/common/precompiles/src/activation/storage.rs:478-485`, `old_admin_err`).

### Impact Explanation
Loss of the activation admin key permanently freezes the ability to activate or deactivate Base-native precompile features (`B20Stablecoin`, `B20Asset`, `PolicyRegistry`). If a feature is later required to be deactivated (e.g. to respond to a discovered vulnerability) or a new feature needs activation, there is no way to recover admin control once it is set to an unreachable address, since `set_admin` again requires the (now unreachable) admin to authorize any further rotation. This is a protocol-level permanent loss of control over precompile feature governance, distinct from a mere key-management inconvenience because there is no on-chain recovery mechanism.

### Likelihood Explanation
The change requires only a single mistaken/malicious transaction from the current legitimate admin (analogous to the reported DAO-change scenario), so likelihood is tied entirely to operational error during key rotation — no attacker action is needed, but the resulting freeze is permanent and effectively equivalent to a self-inflicted node/feature-control halt.

### Recommendation
Adopt the same two-step pattern already used by `PolicyRegistry` (`stageUpdateAdmin`/`finalizeUpdateAdmin`) for `ActivationRegistryStorage::set_admin`: stage the new admin, and require the pending admin to call a `finalize` function to accept the role, ensuring the address is reachable/controlled before revoking the previous admin's authority.

### Proof of Concept
1. Current activation admin `A` calls `IActivationRegistry.setAdmin(newAdmin)` intending to rotate to a new multisig, but mistypes/pastes the wrong non-zero address `X` (an address nobody controls).
2. `set_admin` succeeds because `X` is non-zero: [4](#0-3)  — `admin` storage is updated to `X` and `A`'s calls to `activate`/`deactivate` now revert (`require_admin_caller` rejects `A`), as confirmed by the existing unit test `set_admin_updates_storage_and_authorization`: [5](#0-4) .
3. Since `X` cannot originate transactions, no address can ever again call `set_admin`, `activate`, or `deactivate` on the registry — feature activation state (and control over enabling/disabling `B20Stablecoin`/`B20Asset`/`PolicyRegistry`) is permanently frozen.

    /// Sets the activation registry admin address.
    pub fn set_admin(
        &mut self,
        new_admin: Address,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }
        if !admin_config.state_enabled {
            return Err(BasePrecompileError::revert(
                IActivationRegistry::AdminStorageNotEnabled {},
            ));
        }
        if new_admin.is_zero() {
            return Err(BasePrecompileError::revert(IActivationRegistry::ZeroAdminAddress {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        self.__initialize()?;
        self.admin.write(new_admin)?;
        self.emit_event(IActivationRegistry::AdminChanged {
            previousAdmin: caller,
            newAdmin: new_admin,
            caller,
        })?;

        Ok(())
    }

    /// Sets the feature activation state.
    pub fn set_activated(
        &mut self,
        feature: B256,
        to_activated_state: bool,
        admin_config: ActivationAdminConfig,
    ) -> Result<()> {
        // Keep this guard at the shared mutation boundary so `activate`, `deactivate`, and direct
        // `set_activated` callers all get the same static-call behavior after calldata validation.
        if self.storage.is_static() {
            return Err(BasePrecompileError::revert(IActivationRegistry::StaticCallNotAllowed {}));
        }

        let caller = self.require_admin_caller(admin_config)?;

        let current_activated_state = self.features.at(&feature).read()?;

        let is_activating_and_already_activated = to_activated_state && current_activated_state;
        let is_deactivating_and_already_deactivated =
            !to_activated_state && !current_activated_state;

        if is_activating_and_already_activated {
            return Err(BasePrecompileError::revert(IActivationRegistry::AlreadyActivated {
                feature,
            }));
        }
        if is_deactivating_and_already_deactivated {
            return Err(BasePrecompileError::revert(IActivationRegistry::FeatureNotActivated {
                feature,
            }));
        }

        if to_activated_state {
            self.__initialize()?;
            self.features.at_mut(&feature).write(true)?;
            self.emit_event(IActivationRegistry::FeatureActivated { feature, caller })?;
        } else {
            self.features.at_mut(&feature).delete()?;
            self.emit_event(IActivationRegistry::FeatureDeactivated { feature, caller })?;
        }

        Ok(())
    }

    #[test]
    fn set_admin_updates_storage_and_authorization() {
        let mut storage = HashMapStorageProvider::new(1);
        storage.set_caller(ADMIN);

        StorageCtx::enter(&mut storage, |ctx| {
            ActivationRegistryStorage::new(ctx).set_admin(NEW_ADMIN, STATE_ADMIN_CONFIG).unwrap()
        });

        StorageCtx::enter(&mut storage, |ctx| {
            let registry = ActivationRegistryStorage::new(ctx);
            assert_eq!(registry.stored_admin().unwrap(), NEW_ADMIN);
            assert_eq!(registry.admin(STATE_ADMIN_CONFIG).unwrap(), NEW_ADMIN);
            assert_eq!(registry.admin(STATIC_ADMIN_CONFIG).unwrap(), ADMIN);
        });

        let events = storage.get_events(ActivationRegistryStorage::ADDRESS);
        let event = IActivationRegistry::AdminChanged::decode_log_data(events.last().unwrap())
            .expect("admin change event decodes");
        assert_eq!(event.previousAdmin, ADMIN);
        assert_eq!(event.newAdmin, NEW_ADMIN);
        assert_eq!(event.caller, ADMIN);

        let old_admin_err = StorageCtx::enter(&mut storage, |ctx| {
            ActivationRegistryStorage::new(ctx).activate(FEATURE, STATE_ADMIN_CONFIG)
        })
        .unwrap_err();
        assert_eq!(
            old_admin_err,
            BasePrecompileError::revert(IActivationRegistry::Unauthorized { caller: ADMIN })
        );

        storage.set_caller(NEW_ADMIN);
        StorageCtx::enter(&mut storage, |ctx| {
            ActivationRegistryStorage::new(ctx).activate(FEATURE, STATE_ADMIN_CONFIG)
        })
        .unwrap();
        assert_activated(&mut storage, true);
    }
