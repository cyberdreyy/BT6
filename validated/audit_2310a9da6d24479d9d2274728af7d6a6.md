### Title
Global contract identity for `GlobalContractDeployMode::AccountId` survives `DeleteAccount` and can be silently hijacked by re-registering the freed account name - ([File: runtime/runtime/src/global_contracts.rs], [File: core/store/src/utils/mod.rs])

### Summary
When a contract is deployed with `GlobalContractDeployMode::AccountId`, the code is stored under `TrieKey::GlobalContractCode{ identifier: AccountId(name) }`, a state entry that is explicitly *not* part of the account's own state and is therefore never touched by `remove_account`/`action_delete_account`. Because "ownership" of this mutable slot is defined purely by whoever currently controls the account name (not by any persisted key/identity check), deleting the owner account and having an unrelated party register the same name (permissionless for top-level names `>= min_allowed_top_level_account_length`) lets that new party redeploy code under the identical `GlobalContractIdentifier::AccountId(name)`, silently taking over the code executed for every pre-existing account that had opted in via `UseGlobalContract`/`AccountContract::GlobalByAccount(name)`.

### Finding Description
`GlobalContractDeployMode::AccountId` stores contract code keyed only by the account-id string, via `initiate_distribution`/`apply_distribution_current_shard` writing to `TrieKey::GlobalContractCode { identifier: GlobalContractCodeIdentifier::AccountId(account_id) }` [1](#0-0) , and applied at `apply_distribution_current_shard` with `state_update.set(trie_key, ...)` [2](#0-1) .

This trie key is explicitly documented as *not* belonging to the account: `TrieKey::get_account_id` returns `None` for `GlobalContractCode` with the comment "Even though global contract code might be deployed under account id, it doesn't correspond to the data stored for that account id" [3](#0-2) , and it is likewise excluded from account-scoped state-change handling [4](#0-3) .

`action_delete_account` calls `remove_account`, which removes `Account`, `ContractCode`, access keys, gas keys, and contract data for the account — but never removes `TrieKey::GlobalContractCode` or `TrieKey::GlobalContractNonce` [5](#0-4) [6](#0-5) . So after `owner.near`-style account deletes itself, `GlobalContractCode{AccountId(owner)}` and its nonce remain in state indefinitely, while `Account{owner}` no longer exists.

Any account with `account_id.len() >= min_allowed_top_level_account_length` can be created by an arbitrary predecessor with no registrar involvement, per `action_create_account`'s top-level branch (`predecessor_id != registrar_account_id` is only rejected when the name is *shorter* than the threshold) [7](#0-6) . Thus an unprivileged attacker can recreate the exact deleted name.

Once the attacker controls a fresh account with that name, they can submit `Action::DeployGlobalContract(DeployGlobalContractAction { code, deploy_mode: GlobalContractDeployMode::AccountId })`. `action_deploy_global_contract`/`initiate_distribution` derive the identifier purely from the *current* `account_id` of the deploying account — there is no check that this is the "same" logical owner as before, nor any binding to a specific public key or account creation epoch [8](#0-7) . The nonce mechanism (`increment_nonce`/`check_and_update_nonce`) exists only to prevent stale/duplicate distribution receipts for idempotency, not to gate authorization by identity [9](#0-8) .

Victim accounts that previously ran `UseGlobalContract(AccountId(owner))` have `AccountContract::GlobalByAccount(owner)` stored on their own `Account`, and code/hash lookups always resolve dynamically by name against the current trie value, never pinned to a hash or an owner-identity snapshot at opt-in time [10](#0-9) [11](#0-10) . Consequently, after the takeover, every such victim account will execute the new registrant's code the next time it is invoked, with zero additional signature or consent from the victim.

### Impact Explanation
This is an authorization-escalation-across-accounts bug: control over arbitrary victims' effective contract code is transferred to an unrelated, unprivileged third party without any signature from the victims. Because the global contract mechanism is explicitly designed to let code perform privileged logic on behalf of every opted-in account (e.g. wallet-style contracts, DeFi logic), an attacker who hijacks the identifier can deploy malicious code (e.g. redirecting funds, changing access-control logic) that is transparently executed against every account still bound via `GlobalByAccount(owner)`. This falls under "Stealing or loss of funds" and "authorization escalation across accounts" categories.

### Likelihood Explanation
Preconditions: (1) the original owner account for the `AccountId` identifier must later be deletable (own `DeleteAccount` action, or become deletable via `MAX_ACCOUNT_DELETION_STORAGE_USAGE`/`GasKeyBalanceTooHigh` limits — deletable by design for regular accounts); and (2) the account name must become creatable again by the attacker, which is guaranteed to be permissionless if `len(account_id) >= min_allowed_top_level_account_length` (a real, commonly-used class of top-level accounts on NEAR). Both preconditions require no validator/node privilege — an ordinary funded account can perform `CreateAccount`, `DeployGlobalContract`, and `DeleteAccount` entirely through public RPC. The attack is deterministic and fully repeatable once the name is free; the attacker only needs to win the race to (re)create the account name before anyone else and before old victims re-verify their binding.

### Recommendation
Bind the `GlobalContractDeployMode::AccountId` identifier's authorization to something that cannot be recycled by unrelated third parties, e.g.:
- Remove (or version-tag/invalidate) `TrieKey::GlobalContractCode`/`GlobalContractNonce` for `AccountId`-mode contracts as part of `remove_account`/`action_delete_account` when the account being deleted is itself the identifier owner, so a freshly created account with the same name starts from a clean slate; and/or
- Track an explicit "epoch"/creation-nonce of the owning account alongside the global contract entry, and have `UseGlobalContract`-derived `AccountContract::GlobalByAccount` bindings pin to that epoch, invalidating (or requiring re-opt-in for) the binding if the underlying account identity changes.

### Proof of Concept
Test-loop integration test:
1. Create `owner` (name length `>= min_allowed_top_level_account_length`, e.g. 40 chars) and `victim` accounts.
2. `owner` submits `DeployGlobalContract{ code: codeA, deploy_mode: AccountId }`; wait for distribution to complete.
3. `victim` submits `UseGlobalContract{ contract_identifier: AccountId(owner) }`; call a method on `victim` and assert it executes `codeA`'s behavior.
4. `owner` submits `DeleteAccount{ beneficiary_id: someone }`; assert `owner` no longer exists via `view_account`.
5. Assert directly (via low-level trie/state query, e.g. `ViewGlobalContractCodeByAccountId`) that `GlobalContractCode{AccountId(owner)}` is still present/queryable even though `owner`'s account is gone.
6. A different signer (`attacker`, unrelated to `owner`) submits `CreateAccount` for the exact name `owner` (permissible since length `>= min_allowed_top_level_account_length`).
7. `attacker` (now controlling account named `owner`) submits `DeployGlobalContract{ code: codeB, deploy_mode: AccountId }`.
8. Without `victim` signing anything new, call the same method on `victim` again and assert it now executes `codeB`'s behavior (e.g. via a distinguishable return value/log), proving the pre-existing `GlobalByAccount(owner)` binding silently now runs attacker-controlled code.

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())

/// Increments the nonce for the given global contract identifier and writes
/// it to state immediately.
fn increment_nonce(
    state_update: &mut TrieUpdate,
    id: &GlobalContractIdentifier,
) -> Result<u64, RuntimeError> {
    let identifier: GlobalContractCodeIdentifier = id.clone().into();

    let nonce_key = TrieKey::GlobalContractNonce { identifier };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;

    let new_nonce = stored_nonce.checked_add(1).ok_or_else(|| {
        RuntimeError::UnexpectedIntegerOverflow("increment_global_contract_nonce".into())
    })?;
    set_nonce(state_update, nonce_key, new_nonce);
    Ok(new_nonce)
}

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)
}

// Checks if the incoming nonce is fresh and updates the stored nonce. Returns
// true if the nonce is fresh, false if it's stale. The nonce is set
// immediately and the freshness check allows the same nonce (>=).
fn check_and_update_nonce(
    global_contract_data: &GlobalContractDistributionReceipt,
    identifier: &GlobalContractCodeIdentifier,
    state_update: &mut TrieUpdate,
) -> Result<bool, RuntimeError> {
    let nonce_key = TrieKey::GlobalContractNonce { identifier: identifier.clone() };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;
    let incoming_nonce = global_contract_data.nonce();

    // Allow the same nonce since the nonce is updated immediately when
    // initiating distribution to prevent multiple distributions with the same
    // nonce from being initiated.
    if incoming_nonce < stored_nonce {
        return Ok(false);
    }

    set_nonce(state_update, nonce_key, incoming_nonce);
    Ok(true)
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }

    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError> {
        let key = TrieKey::GlobalContractCode { identifier: self.clone().into() };
        let code_hash = match self {
            GlobalContractIdentifier::AccountId(_) => None,
            GlobalContractIdentifier::CodeHash(hash) => Some(hash),
        };
        let code = store.get(&key, AccessOptions::DEFAULT)?;
        Ok(code.map(|code| ContractCode::new(code, code_hash)))
    }
}
