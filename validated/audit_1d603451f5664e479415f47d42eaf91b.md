### Title
Peer block-acceptance signatures are tallied and broadcast without checking this signer's own validity/state - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`handle_block_signature` authenticates an incoming `BlockAccepted` signature (recovers the pubkey, confirms it belongs to a registered signer) and then unconditionally forwards it to `store_and_process_block_signature`, which tallies signing weight and, once ≥70% weight is reached, calls `mark_locally_accepted(true)` and `broadcast_signed_block` — pushing the block to this signer's own node. [1](#0-0)  Unlike the sibling pre-commit path, this code path never checks `block_info.valid` (whether *this* signer has itself validated, or even rejected, the block) before counting a peer's signature toward the group threshold and pushing the block.

### Finding Description
Two structurally parallel code paths exist for counting weight toward the 70% signing threshold:

1. `handle_block_pre_commit` — before tallying pre-commit weight or acting on it, explicitly gates on this signer's own validation state:
```rust
if !block_info.valid.unwrap_or(false) {
    // We received a pre-commit for a block that we have not validated or we have already marked this block as invalid.
    debug!(...);
    return;
}
``` [2](#0-1) 

2. `handle_block_signature` / `store_and_process_block_signature` — the analogous path for full acceptance signatures — performs signer-address authentication only (pubkey recovery + `is_valid_signer`) and then calls `store_and_process_block_signature`, which tallies `total_signature_weight` and, once the threshold is met, calls `block_info.mark_locally_accepted(true)` and `self.broadcast_signed_block(...)` with **no check of `block_info.valid`** anywhere in this path. [3](#0-2) 

This is the same bug class as the FraxPoolV3 `amoMinterBorrow` report: a privileged action (here, counting a peer signature toward the group threshold and pushing the resulting block to the node) is reachable through a code path that omits a guard ("valid") that a parallel, more carefully-guarded path ("pre-commit") enforces. The only guard in `store_and_process_block_signature` before counting a peer's signature and forwarding it is `signed_group.is_some()` (already-decided short-circuit) and a redirect-to-pre-commit for signers whose pre-commit hasn't been seen yet — the signer's own `valid` flag for the block is never consulted.

Practically, this means a signer that has never validated a block (e.g. `block_info.valid.is_none()` because its own node validation is still pending, or it timed out) — or one that has actively marked the block as `LocallyRejected` (`block_info.valid == Some(false)`) — can still have its local `BlockInfo` promoted to `GloballyAccepted`-adjacent (`mark_locally_accepted(true)`) and have `broadcast_signed_block` push that block to its own node purely because enough *other* signers' signatures arrived over StackerDB.

### Impact Explanation
This breaks the "aggregated-weight vs verified-accepts" equality: the signer's local acceptance tally can reach threshold and trigger a broadcast without the local signer itself having verified block validity, which is the whole purpose of `valid`/`check_block_against_signer_db_state` checks elsewhere in the codebase. If reachable with `block_info.valid` unset or `Some(false)`, this is a Critical-class issue (a signer effectively acting on/propagating a block it never confirmed valid, undermining the "signer signing an invalid/non-canonical block" guarantee that every other threshold-crossing path (`handle_block_pre_commit`) is careful to enforce).

### Likelihood Explanation
Reachable purely by gossip: any registered signer (or a set of signers, once ≥70% signing weight of *authentic* signatures is gathered) broadcasting `BlockResponse::Accepted` messages over StackerDB triggers `handle_block_signature` → `store_and_process_block_signature` on every other signer, including ones that have not yet validated or have rejected the block. No majority compromise, no key theft, and no local access is required — only that authentic accept messages from other signers (who did validate, per protocol) circulate before or independent of this signer's own validation completing. This matches the "gossip-triggerable" and "rejection/validity vs aggregated-weight mismatch" analog classes called out as in-scope.

### Recommendation
- Short term: In `store_and_process_block_signature` (or earlier in `handle_block_signature`), require `block_info.valid == Some(true)` before counting the incoming signature toward `total_signature_weight`/triggering `mark_locally_accepted`/`broadcast_signed_block`, mirroring the guard already present in `handle_block_pre_commit`. If `valid` is `None` or `Some(false)`, park the signature (as is already done for unknown blocks via `add_pending_block_signature_response`) rather than acting on it immediately.
- Long term: Audit all threshold-crossing entry points (`handle_block_pre_commit`, `handle_block_signature`/`store_and_process_block_signature`, and any future paths) for consistent enforcement of the `valid` gate and the `check_block_against_signer_db_state` re-check, since these are exactly the kind of "similar function, different guard" duplication that produces this class of bug.

### Proof of Concept
Not independently reproduced against a running network; based on static code review of `stacks-signer/src/v0/signer.rs`. The critical evidence is the asymmetry between `handle_block_pre_commit`'s explicit `if !block_info.valid.unwrap_or(false) { return; }` guard [2](#0-1)  and the complete absence of any equivalent check in `handle_block_signature`/`store_and_process_block_signature` [4](#0-3) . I was unable to fully trace whether some other caller-side gate (upstream of `handle_block_signature`, e.g. in `handle_event_match`) filters on `valid` before dispatch, since the index did not surface such a check; a Devin session with full source access should confirm no such gate exists elsewhere before treating this as conclusively exploitable.

    /// Handle an observed signature from another signer
    fn handle_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        accepted: &BlockAccepted,
    ) {
        let BlockAccepted {
            signer_signature_hash: block_hash,
            signature,
            metadata,
            ..
        } = accepted;
        debug!(
            "{self}: Received a block-accept signature: ({block_hash}, {signature}, {})",
            metadata.server_version
        );

        // recover public key
        let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
            block_hash.bits(),
            signature,
        ) else {
            debug!("{self}: Received unrecovarable signature. Will not store.";
                   "signature" => %signature,
                   "signer_signature_hash" => %block_hash);

            return;
        };

        // authenticate the signature -- it must be signed by one of the stacking set
        let signer_address = StacksAddress::p2pkh(self.mainnet, &public_key);
        if !self.is_valid_signer(&signer_address) {
            debug!("{self}: Received block acceptance with an invalid signature. Will not store.";
                "signer_public_key" => ?public_key,
                "signer_address" => %signer_address,
                "signer_signature_hash" => %block_hash,
                "signature" => %signature
            );
            return;
        }
        let Some(mut block_info) = self.block_lookup_by_reward_cycle(block_hash) else {
            if let Err(e) = self.signer_db.add_pending_block_signature_response(
                block_hash,
                &signer_address,
                signature,
            ) {
                warn!("{self}: Failed to add pending block signature response: {e:?}");
            }
            return;
        };

        info!("{self}: Received block acceptance";
            "signer_pubkey" => public_key.to_hex(),
            "signer_address" => %signer_address,
            "signer_signature_hash" => %block_hash,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "signer_weight" => self.signer_weights.get(&signer_address).copied().unwrap_or(0),
            "tenure_extend_timestamp" => accepted.response_data.tenure_extend_timestamp,
            "tenure_extend_read_count_timestamp" => accepted.response_data.tenure_extend_read_count_timestamp
        );
        self.store_and_process_block_signature(
            stacks_client,
            sortition_state,
            &mut block_info,
            &signer_address,
            signature,
        );
    }

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }
