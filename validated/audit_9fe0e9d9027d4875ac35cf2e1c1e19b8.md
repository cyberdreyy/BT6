### Title
Zip archive extraction (`ExtractZipArchive`) never sanitizes `file.Name`, allowing Zip-Slip path traversal for both file writes and `os.Chtimes` via `processZipTimestampField` - (File: helpers/archives/zip_extract.go, helpers/archives/zip_extra.go)

### Summary
`ExtractZipArchive` in `helpers/archives/zip_extract.go` passes the raw, attacker-controlled `zip.File.Name` straight into `os.MkdirAll`, file creation, symlink creation, `lchmod`, and — critically for this question — `processZipExtra` → `processZipTimestampField` → `os.Chtimes(file.Name, ...)`. The only path check performed anywhere in this package is `errorIfGitDirectory`, which only detects a leading `.git` path component; there is no `..`-traversal or absolute-path validation anywhere in the extraction pipeline.

### Finding Description
The call chain is exactly as described:
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) loops `archive.File`, calling `extractZipFile(file)` (line 61-83), which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then creates/writes/symlinks at `file.Name` with no cleaning or containment check [1](#0-0) . A second loop then calls `lchmod(file.Name, ...)` and `processZipExtra(&file.FileHeader)` [2](#0-1) . Inside `processZipExtra`, for a `ZipTimestampFieldType` extra record, `processZipTimestampField` is invoked and calls `os.Chtimes(file.Name, acTime, modTime)` directly on the unsanitized name [3](#0-2) .

The only sanity check performed on `file.Name` in the whole package is `errorIfGitDirectory`, which strips/splits the cleaned path and only rejects paths whose first component is `.git` [4](#0-3) ; it does nothing to reject `../` segments or absolute paths. No other function in `zip_extract.go`, `zip_extra.go`, or `path_check_helper.go` calls `filepath.Rel`, checks for `..`, or validates that the resolved path stays under an extraction root. A crafted `zip.File` with `Name = "../../other-project/build/target"` and a `ZipTimestampFieldType` Extra field with the "mod time present" flag set will therefore result in `os.Chtimes` being called on that traversal path, and (via `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`) the same traversal also allows outright file content/symlink writes outside the extraction root — the Chtimes call is simply riding on a pre-existing Zip-Slip vulnerability in the whole extractor.

### Impact Explanation
Within the stated scope (timestamp mutation only), an attacker who controls the contents of their own job's cache/artifact zip can forge mtimes on arbitrary paths reachable from the process's file permissions — including another project's cached build artifacts if the runner's build/cache directory layout is shared or predictable (e.g., shell executor with a shared builds root, or predictable `CI_PROJECT_DIR`/cache-key derived paths). This can corrupt or bypass mtime-based cache invalidation logic for other projects' pipelines, causing stale or incorrect artifacts to be reused. Note that the same unsanitized `file.Name` is used for actual file/directory/symlink creation earlier in `ExtractZipArchive`, so the real-world severity extends beyond timestamps to full Zip-Slip file write/symlink creation, though that broader impact is outside this question's explicit scope.

### Likelihood Explanation
Feasibility is high and does not require any privileged or admin action: any pipeline author can produce an artifact/cache zip with attacker-controlled entry names and Extra fields (the `archive/zip` format allows arbitrary `Name` strings and arbitrary `Extra` byte payloads not validated by Go's `zip` package on read). The exploit is 100% reproducible whenever a Runner extracts a job-supplied zip via `ExtractZipFile`/`ExtractZipArchive`. The only variable is the "impact scope" precondition — whether the runner's execution environment shares a predictable/overlapping directory tree across different projects' jobs (true for some shell-executor configurations with non-isolated build dirs, or intentionally-colliding cache keys within a project/group). Within a single project/pipeline (which always shares a build root across jobs), the traversal-to-Chtimes primitive is unconditionally reachable.

### Recommendation
Sanitize/validate `file.Name` once per entry before any filesystem operation in `ExtractZipArchive`: reject or clean entries whose cleaned path is absolute or, after `filepath.Join(destRoot, file.Name)`, does not have `destRoot` as a prefix (canonical Zip-Slip defense). Apply this check before `extractZipFile`, `lchmod`, and `processZipExtra` so that no code path (write, chmod, or chtimes) ever operates on a path outside the intended extraction directory. Track the destination root explicitly since `ExtractZipArchive` currently has no notion of an extraction root at all — it operates on `file.Name` as if it is always intended to be relative to the current working directory, without enforcing it.

### Proof of Concept
Go test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversalTimestamp(t *testing.T) {
    tmpRoot := t.TempDir()
    outsideDir := t.TempDir()          // simulates another project's build dir
    outsideFile := filepath.Join(outsideDir, "victim.txt")
    require.NoError(t, os.WriteFile(outsideFile, []byte("data"), 0o644))
    before, _ := os.Stat(outsideFile)

    // Build a zip whose entry name traverses out of tmpRoot into outsideDir
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    relTraversal, _ := filepath.Rel(tmpRoot, outsideFile) // e.g. ../../xxx/victim.txt
    fh := &zip.FileHeader{Name: relTraversal}
    fh.SetMode(0o644)
    var extra bytes.Buffer
    field := ZipExtraField{Type: ZipTimestampFieldType, Size: uint16(binary.Size(&ZipTimestampField{}))}
    ts := ZipTimestampField{Flags: 1, ModTime: uint32(time.Date(1999,1,1,0,0,0,0,time.UTC).Unix())}
    binary.Write(&extra, binary.LittleEndian, &field)
    binary.Write(&extra, binary.LittleEndian, &ts)
    fh.Extra = extra.Bytes()
    w, _ := zw.CreateHeader(fh)
    w.Write([]byte("payload"))
    zw.Close()

    require.NoError(t, os.Chdir(tmpRoot))
    r, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    _ = ExtractZipArchive(r)

    after, _ := os.Stat(outsideFile)
    assert.NotEqual(t, before.ModTime(), after.ModTime(), "mtime of file outside extraction root was mutated via Zip-Slip + Chtimes")
}
```
Expected assertion: `after.ModTime()` equals the forged `1999-01-01` timestamp rather than `before.ModTime()`, proving `os.Chtimes` reached a path outside `tmpRoot`.

```go
func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```
