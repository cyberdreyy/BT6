### Title
Unbounded `operator_fee_scalar`/`operator_fee_constant` from L1 `SystemConfig` allows fee-vault theft of L2 sender/payer ETH beyond what any signed transaction agreed to - (File: `crates/common/genesis/src/updates/operator_fee.rs`)

### Summary
`OperatorFeeUpdate::try_from` decodes `operator_fee_scalar` (`u32`) and `operator_fee_constant` (`u64`) straight from an L1 `SystemConfig` `ConfigUpdate` log with no sanity bound, and `SystemConfig::update_with_receipts`/`process_config_update_log` apply it unconditionally. These values are then used post-Isthmus to compute the "operator fee" charged to every L2 transaction's gas payer, deducted from their account balance during execution — a charge that is not part of what the transaction signer capped or agreed to when signing `max_fee_per_gas`.

### Finding Description
`OperatorFeeUpdate` parses the packed scalar/constant fields with zero range checking: [1](#0-0) 

and is applied directly to the chain's `SystemConfig`: [2](#0-1) 

This flows unconditionally through the derivation pipeline into every L1 info deposit (`L1BlockInfoTx::try_new`) and the `SystemConfig` used by attribute building: [3](#0-2) 

At execution time, `operator_fee_charge_inner` computes the fee as `gas * operator_fee_scalar [* Jovian multiplier] + operator_fee_constant`, entirely determined by these unbounded values: [4](#0-3) 

The fee is charged upfront from the caller/payer's balance in the transaction handler, based purely on `gas_limit` and the currently active (attacker-controllable) scalar/constant — not on anything the transaction signer capped: [5](#0-4) [6](#0-5) 

The only pre-charge guard, `ensure_can_pay_fees`, merely verifies the caller can *afford* the currently configured operator fee — it does not bound the fee itself: [7](#0-6) 

The same unbounded value is echoed in the EIP-8130 path's `prepay`/`settle_fees`, which pre-charges and settles `operator_cost` computed from the same `operator_fee_charge`: [8](#0-7) [9](#0-8) 

Unlike `max_fee_per_gas`/`max_priority_fee_per_gas`, which are fields the sender explicitly signs and caps, the operator fee scalar/constant are chain-level parameters sourced from L1 `SystemConfig` data and are not bounded by, or reflected in, anything the transaction signer commits to. A `SystemConfig`-controlled (or otherwise attacker-written) `ConfigUpdate(OperatorFee)` log setting `operator_fee_scalar` near `u32::MAX` and/or `operator_fee_constant` near `u64::MAX` causes every subsequently-processed L2 transaction to have an enormous, unbounded ETH amount debited from its payer and routed to `Predeploys::OPERATOR_FEE_VAULT`, exactly mirroring the referenced `WETH_TRANSFER_GAS_UNITS` pattern: an ungoverned multiplier applied against user funds without the user's consent captured in their signature.

### Impact Explanation
Every account transacting on the L2 pays gas fees computed from `gas_limit * operator_fee_scalar [+ operator_fee_constant]`, uncapped by anything in the signed transaction. Once such a `ConfigUpdate` is derived and becomes canonical, it can drain a large fraction of any sender/payer's ETH balance on their very next (already-pending, already-signed) transaction — this is a direct unauthorized transfer of user funds into the operator fee vault, satisfying the "theft of funds" impact bar.

### Likelihood Explanation
This requires an L1 `SystemConfig` update log to be posted (the mechanism by which operator fee parameters are legitimately updated) with a malicious scalar/constant. There is no bounds check anywhere in the decode/apply/consume pipeline (`OperatorFeeUpdate::try_from`, `SystemConfig::apply`, `operator_fee_charge_inner`) to reject or clamp an extreme value, so if the update is emitted (whether by a compromised or careless system-config owner, or a bug elsewhere permitting an unauthorized emission), it propagates deterministically and is applied without any override or circuit breaker.

### Recommendation
Add sanity bounds when decoding/applying `OperatorFeeUpdate` (and analogous `SystemConfig` numeric fields) — e.g., cap `operator_fee_scalar`/`operator_fee_constant` to a reasonable maximum in `OperatorFeeUpdate::try_from` or in `operator_fee_charge_inner`, and/or require the operator fee to be included in (and capped by) something the transaction signer explicitly agrees to, so an extreme system-config update cannot unilaterally over-charge previously-signed transactions.

### Proof of Concept
1. Emit an L1 `ConfigUpdate(OperatorFee)` log (type 5) via the `SystemConfig` contract with `operator_fee_scalar = 0xFFFFFFFF` and `operator_fee_constant = u64::MAX`, as encoded by `enqueue_operator_fee_update` in the test harness: [10](#0-9) 
2. The derivation pipeline applies it via `SystemConfig::update_with_receipts` → `OperatorFeeUpdate::apply`, with no bound check: [11](#0-10) 
3. Alice has a pending signed EIP-1559 transaction with `gas_limit = 30_000_000` and sufficient ETH balance to cover her signed `max_fee_per_gas * gas_limit`.
4. Once the malicious config is active, `operator_fee_charge_inner(gas_limit, upgrade)` computes an operator fee on the order of `30_000_000 * 0xFFFFFFFF` (or with the Jovian multiplier, ×100 more), vastly exceeding anything Alice signed for.
5. `before_execution`/`prepay` debits this amount from Alice's balance (`Self::ensure_can_pay_fees` only checks she has enough to cover it, not that it's bounded), and it is credited to `Predeploys::OPERATOR_FEE_VAULT`: [12](#0-11) 
6. Alice's transaction executes as she requested, but she is charged an operator fee she never agreed to and could not have anticipated from her signed transaction fields.

    /// Calculates the operator fee for a given `gas` amount.
    ///
    /// Missing scalars fall back to zero to match the execution path during the
    /// txpool bootstrap window before the first L1 attributes deposit.
    pub fn operator_fee_charge_inner(&self, gas: U256, upgrade: BaseUpgrade) -> U256 {
        let operator_fee_scalar = self.operator_fee_scalar.unwrap_or_default();
        let operator_fee_constant = self.operator_fee_constant.unwrap_or_default();

        let product = if Self::is_enabled(upgrade, BaseUpgrade::Jovian) {
            gas.saturating_mul(operator_fee_scalar)
                .saturating_mul(U256::from(OPERATOR_FEE_JOVIAN_MULTIPLIER))
        } else {
            gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
        };
        product.saturating_add(operator_fee_constant)
    }

    /// Returns the Isthmus operator fee for `envelope` over `gas`. Zero for deposits and before
    /// Isthmus.
    ///
    /// The operator fee is an Isthmus feature; `L1FeeParams::operator_fee_charge` computes it
    /// unconditionally, so the Isthmus gate is applied here (matching the reference, which gates
    /// in its `reward_beneficiary`). The Base upgrade ladder is discriminant-ordered.
    fn operator_fee(host: &mut Evm<'_, BaseEvmTypes>, envelope: &BaseTxEnvelope, gas: u64) -> U256 {
        let Some(enveloped) = envelope.enveloped() else {
            return U256::ZERO;
        };
        let upgrade = host.config_spec_id().upgrade();
        if (upgrade as u8) < (BaseUpgrade::Isthmus as u8) {
            return U256::ZERO;
        }
        host.block_env().ext.operator_fee_charge(enveloped, U256::from(gas), upgrade)
    }

    /// Rejects the transaction when `caller` cannot cover the full upfront charge — the maximum
    /// gas cost, the transferred value, and the OP-stack L1 data and operator fees.
    ///
    /// The framework's `validate_sender` already rejects a caller that cannot cover the gas cost
    /// and value, but it is unaware of the L1 and operator fees charged here, and
    /// [`charge_upfront`] deducts with wrapping arithmetic. Without this guard an underfunded
    /// caller would silently wrap to a spurious balance instead of the transaction failing; this
    /// mirrors the revm reference, which rejects such a caller with `LackOfFundForMaxFee`.
    ///
    /// A no-op for deposits (funded on L1 and exempt) and when fee charging or balance checks are
    /// disabled (e.g. `eth_call` simulation), matching the conditions under which `validate_sender`
    /// and `charge_upfront` themselves enforce balances.
    fn ensure_can_pay_fees(
        host: &mut Evm<'_, BaseEvmTypes>,
        envelope: &BaseTxEnvelope,
        caller: Address,
        l1_fee: U256,
        operator_fee: U256,
    ) -> HandlerResult<()> {
        let Some(tx) = envelope.as_standard() else {
            return Ok(());
        };
        if !host.feature(EvmFeatures::FEE_CHARGE) || !host.feature(EvmFeatures::BALANCE_CHECK) {
            return Ok(());
        }
        let required = U256::from(tx.gas_limit())
            .saturating_mul(U256::from(tx.max_fee_per_gas()))
            .saturating_add(tx.value())
            .saturating_add(l1_fee)
            .saturating_add(operator_fee);
        let balance =
            host.state_mut().account(&caller, false).map_err(HandlerError::Fatal)?.balance();
        if balance < required {
            return Err(HandlerError::InsufficientFunds);
        }
        Ok(())
    }

impl TxHandlerHooks<BaseEvmTypes> for BaseTxHandlerHooks {
    fn before_execution(
        host: &mut Evm<'_, BaseEvmTypes>,
        envelope: &BaseTxEnvelope,
        caller: Address,
        upfront_fee: U256,
    ) -> HandlerResult<()> {
        // Charge the upfront gas cost, the L1 data fee, and the operator fee (on the gas limit)
        // from the caller. Both fees are stashed for settlement so it charges/refunds against the
        // exact amounts collected here, without recomputing them.
        let l1_fee = Self::l1_fee(host, envelope);
        let operator_fee = Self::operator_fee(host, envelope, envelope.gas_limit());
        let ext = host.ext_mut();
        ext.l1_fee = l1_fee;
        ext.operator_fee = operator_fee;
        // `validate_sender` only checks the gas cost and value; the L1 and operator fees are
        // charged on top here via `charge_upfront`'s wrapping subtraction, so reject an
        // underfunded caller up front rather than let its balance wrap to a spurious value.
        Self::ensure_can_pay_fees(host, envelope, caller, l1_fee, operator_fee)?;
        charge_upfront(
            host,
            caller,
            upfront_fee.saturating_add(l1_fee).saturating_add(operator_fee),
        )
    }

    pub fn update_with_receipts(
        &mut self,
        receipts: &[Receipt],
        l1_system_config_address: Address,
        ecotone_active: bool,
    ) -> (Vec<SystemConfigUpdateKind>, Vec<SystemConfigUpdateError>) {
        receipts
            .iter()
            .filter(|r| r.status != Eip658Value::Eip658(false))
            .flat_map(|r| &r.logs)
            .filter(|log| {
                let topics = log.topics();
                log.address == l1_system_config_address
                    && !topics.is_empty()
                    && topics[0] == SystemConfigUpdate::TOPIC

            .map(|log| self.process_config_update_log(log, ecotone_active))
            .fold((Vec::new(), Vec::new()), |(mut updates, mut errors), result| {
                match result {
                    Ok(kind) => updates.push(kind),
                    Err(e) => errors.push(e),
                }
                (updates, errors)
            })
    }
