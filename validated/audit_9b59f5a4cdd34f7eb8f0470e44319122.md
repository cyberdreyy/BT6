### Title
Unauthenticated flood of `web_api_trigger` messages triggers global (non-isolated) eviction of other users' pending `savedCallbacks` in `pruneCallbacks` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`h.savedCallbacks` is a single global map shared by all callers of `HandleLegacyUserMessage`, with no per-sender quota or allowlist enforcement before an entry is stored. `pruneCallbacks` evicts purely by global count against `MaxSavedCallbacks`, sorted by `createdAt` (oldest first), so any signer who can produce enough valid `MethodWebAPITrigger` messages can force eviction of another user's earlier, still-pending callback before the real DON node response arrives.

### Finding Description
`HandleLegacyUserMessage` stores every accepted request keyed only by `msg.Body.MessageId` in the shared `h.savedCallbacks` map without any per-sender bound or allowlist check: [1](#0-0) 

The comment `// TODO: apply allowlist and rate-limiting here` confirms no sender identity/authorization check gates entry into this map; only signature-structure validation (`common.ValidatedRequestFromMessage`) and message freshness (`payload.Timestamp`) are enforced. This is corroborated by the handler test suite's own TODO: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated`. [2](#0-1) 

`pruneCallbacks` (invoked periodically by a background goroutine, and reachable at any time relative to a victim's outstanding request) removes expired entries, then — if the *global* count still exceeds `MaxSavedCallbacks` — sorts **all** remaining entries by `createdAt` across all senders and deletes the oldest half, with no per-sender partitioning: [3](#0-2) 

Because eviction accounting is global rather than per-sender, an attacker who is merely "any signer" (there is no allowlist gate before `savedCallbacks[msg.Body.MessageId]` is populated) can submit a burst of `MaxSavedCallbacks + N` distinct signed `web_api_trigger` messages. Once the global map exceeds `MaxSavedCallbacks`, the next prune cycle evicts the oldest half by `createdAt` — which can include a legitimate victim's earlier-created, still-unanswered `savedCallback`. When the victim's real node response later arrives, `handleWebAPITriggerMessage` looks up the (now-deleted) entry, finds nothing, and silently drops the response: [4](#0-3) 

The victim's `callback.Wait(ctx)` in the gateway's request path then times out with no way to distinguish "flood-evicted" from "node never responded": [5](#0-4) 

### Impact Explanation
This is a cross-user availability/isolation issue: an unprivileged signer (no allowlist enforced at this layer) can extinguish another legitimate user's pending gateway request by exhausting the shared `MaxSavedCallbacks` bound, causing the victim to receive a timeout instead of the genuine DON response. This matches a Denial-of-Service / cross-user isolation-violation impact class rather than authentication bypass or fund loss — one tenant's flood traffic can silently discard another tenant's in-flight capability response.

### Likelihood Explanation
The only precondition is possession of any valid ECDSA key that can produce a correctly-signed `api.Message` for `MethodWebAPITrigger` with a fresh `Timestamp` — no allowlist membership is checked before the callback is cached (`// TODO: apply allowlist and rate-limiting here`). The default `MaxSavedCallbacks` is 20,000 and prune runs every `CallbackPruneIntervalSec` (default 30s), so the attacker must sustain a burst large enough to push the global map over the threshold within a victim's outstanding window — feasible for an attacker with modest throughput (this is also gated only by the per-sender node rate limiter downstream, not by user-message ingestion). The attack is repeatable at will.

### Recommendation
Partition `savedCallbacks` accounting and eviction per sender/signer (e.g., a bounded per-sender quota plus fair global eviction, or reject new entries once a sender's own quota is exceeded rather than evicting other senders' oldest entries), and enforce the still-pending allowlist/rate-limiting TODO before admitting a message into `savedCallbacks` at all.

### Proof of Concept
1. In `handler_test.go`, extend `TestPruneCallbacks` (or add a new test) to seed `h.savedCallbacks` with one "victim" entry created at `now - 1s` via a call path equivalent to `HandleLegacyUserMessage`.
2. Loop calling `HandleLegacyUserMessage` (or directly populate `savedCallbacks`) with `MaxSavedCallbacks` distinct signed messages from *different* attacker private keys (using `gwcommon.NewTestNodes`/`triggerRequest` helpers), all created after the victim's entry.
3. Call `handler.pruneCallbacks()`.
4. Assert: `handler.savedCallbacks["victim-id"]` no longer exists (evicted), demonstrating that the victim's real subsequent node response via `HandleNodeMessage`/`handleWebAPITriggerMessage` would find `found == false` and silently drop, while attacker-created entries dominate the surviving set — confirming global (non-isolated) eviction.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}
