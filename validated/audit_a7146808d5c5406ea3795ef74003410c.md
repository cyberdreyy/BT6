### Title
Stale `FeeStateCache.global_fee_wallet` in `MarginfiGroup` allows fee/rent redirection to a revoked wallet via permissionless instructions - (File: `programs/marginfi/src/instructions/marginfi_account/admin_close.rs`, `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`)

### Summary
`MarginfiGroup` stores a cached copy of the program-wide `FeeState.global_fee_wallet` in `fee_state_cache.global_fee_wallet` [1](#0-0) . This cache is only written at group creation and whenever the permissionless `propagate_fee_state` instruction is explicitly called [2](#0-1) , but several permissionless/value-moving instructions validate the destination wallet against this cached copy rather than the live `FeeState` account. If the global fee admin rotates `global_fee_wallet` via `edit_global_fee_state`, every `MarginfiGroup` that has not yet re-run `propagate_fee_state` continues to route funds to the old wallet, mirroring the Quest/QuestFactory stale-address pattern in the source report.

### Finding Description
The canonical source of truth for the protocol fee wallet is `FeeState.global_fee_wallet`, updatable by the `global_fee_admin` via `edit_fee_state`/`edit_global_fee_state` [3](#0-2) . Each `MarginfiGroup` keeps its own `fee_state_cache.global_fee_wallet` copy, set at group init [4](#0-3)  and only refreshed by the permissionless `propagate_fee_state`/`PropagateFee` instruction [2](#0-1) .

Two permissionless, value-moving instructions validate against this stale per-group cache instead of the live `FeeState`:
- `admin_close_account` closes an inactive, empty `MarginfiAccount` and sends its rent lamports to `global_fee_wallet`, which is constrained to equal `group.fee_state_cache.global_fee_wallet` [5](#0-4) .
- `transfer_to_new_account_pda` charges a flat `ACCOUNT_TRANSFER_FEE` and transfers it to `global_fee_wallet`, again checked against `group.fee_state_cache.global_fee_wallet` [6](#0-5) .

Both instructions are explicitly documented as permissionless in `PERMISSIONS_AND_ROLES.md` [7](#0-6) . Because there is no forced/atomic propagation when `FeeState.global_fee_wallet` changes, every already-created `MarginfiGroup` retains the old wallet address in its cache indefinitely, until someone happens to call `propagate_fee_state` for that specific group. Any signer can still trigger `admin_close_account` or account transfers naming the old wallet as `global_fee_wallet`, and the runtime constraint will accept it because it matches the (stale) cache — exactly the "QuestFactory changed, Quest still holds old address" pattern from the source report, except here the mismatch is between the group's cached copy and the live `FeeState`.

### Impact Explanation
If `global_fee_wallet` is rotated (e.g., because the old wallet's keys were compromised or the operator wants to migrate custody), funds continue flowing to the old wallet from every group that hasn't been re-propagated:
- Rent from `admin_close_account` on any stale/inactive account across all un-propagated groups.
- The flat `ACCOUNT_TRANSFER_FEE` on every `transfer_to_new_account_pda` call across all un-propagated groups.

Given there can be many `MarginfiGroup`s (one per integrator/vault) and propagation must be manually triggered per-group, this creates a durable window — potentially indefinite for inactive/abandoned groups — during which value is misdirected to an address the protocol no longer considers authoritative. This is a direct analog of the reported class: state that should track a single source of truth becomes durably inconsistent, and unprivileged/permissionless callers cause value to move to a stale destination.

### Likelihood Explanation
Wallet rotation is a normal admin operation (e.g., incident response, key rotation, migrating custody), and `propagate_fee_state` is a manual, per-group opt-in step, not a bundled/atomic part of `edit_global_fee_state`. Any signer can trivially invoke `admin_close_account` or `transfer_to_new_account_pda` on any group at any time — no special privileges required — so exploitation of the staleness window requires no more than knowing the old wallet address and having eligible accounts to close/transfer, both of which are permissionless preconditions.

### Recommendation
Do not rely on a per-group cached copy for fee-wallet validation in security-sensitive/value-transfer paths. Either:
- Have `admin_close_account` and `transfer_to_new_account_pda` read `global_fee_wallet` directly from the live `FeeState` account (passed in as a required, seed-derived account) instead of `group.fee_state_cache.global_fee_wallet`, or
- Make `edit_global_fee_state` require/force propagation to all groups atomically (impractical on-chain), or at minimum emit a strong operational warning and provide tooling/automation (already partially present via `p0-cli/src/processor/fee.rs::propagate_fee`) to propagate to all groups immediately after any `fee_wallet` change, and consider rejecting fee/rent transfers if `fee_state_cache.last_update` is older than an acceptable staleness bound.

### Proof of Concept
1. Global fee admin calls `edit_global_fee_state` with a new `fee_wallet`, rotating away from `OLD_WALLET` [3](#0-2) .
2. `propagate_fee_state` is not called for `GroupX` (there is no requirement or automatic trigger to do so) [8](#0-7) ; `GroupX.fee_state_cache.global_fee_wallet` still equals `OLD_WALLET`.
3. Any signer submits `admin_close_account` for an eligible empty/inactive account in `GroupX`, passing `OLD_WALLET` as `global_fee_wallet`; the constraint `global_fee_wallet.key() == group.load()?.fee_state_cache.global_fee_wallet` passes and rent is sent to `OLD_WALLET` [9](#0-8) .
4. Similarly, any account-transfer via `transfer_to_new_account_pda` in `GroupX` pays `ACCOUNT_TRANSFER_FEE` to `OLD_WALLET` [10](#0-9) .
5. This repeats for every group that has not independently called `propagate_fee_state`, redirecting fee/rent value away from the protocol's current, authoritative wallet.

```rust
pub fn propagate_fee(ctx: Context<PropagateFee>) -> Result<()> {
    let mut group = ctx.accounts.marginfi_group.load_mut()?;
    let fee_state = ctx.accounts.fee_state.load()?;

    group.fee_state_cache.global_fee_wallet = fee_state.global_fee_wallet;
    group.fee_state_cache.program_fee_fixed = fee_state.program_fee_fixed;
    group.fee_state_cache.program_fee_rate = fee_state.program_fee_rate;

    let clock = Clock::get()?;
    group.fee_state_cache.last_update = clock.unix_timestamp;

    group
        .panic_state_cache
        .update_from_panic_state(&fee_state.panic_state, clock.unix_timestamp);
```

```markdown
### Permissionless Operations

Some instructions can be called by anyone:

- **`LendingPoolCollectBankFees`** - Moves accrued fees from the liquidity vault to the appropriate
  fee vaults. Anyone can call this.
- **`LendingPoolWithdrawFeesPermissionless`** - Sends fees to the admin's pre-configured
  destination account, if one has been set.
- **`LendingAccountLiquidate`** (classic liquidation) - Any signer can liquidate an unhealthy
  account.
- **`StartLiquidation`** (receivership liquidation) - Any signer can initiate receivership
  liquidation of an unhealthy account.
- **`HandleBankruptcy`** - Only permissionless if the bank has the
  `PERMISSIONLESS_BAD_DEBT_SETTLEMENT` flag set.
- **Interest accrual** - Happens automatically when any user interacts with a bank.
```
