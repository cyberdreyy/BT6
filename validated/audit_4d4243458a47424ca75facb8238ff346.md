### Title
Stale Confirmations From Removed Multisig Members Are Still Counted Toward the Approval Threshold - (File: `multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
When a multisig member is removed via `DeleteMember` (in `multisig2`) or `DeleteKey` (in `multisig`), the contract only purges pending requests that the removed member *originated*. It does not scan the `confirmations` set of *other* pending requests for entries belonging to the removed member. As a result, a confirmation cast by a member before their removal remains counted toward `num_confirmations` even after that member is no longer part of the multisig, allowing a request to execute with fewer live-member confirmations than the configured threshold.

### Finding Description
`confirm()` decides whether to execute a request purely by comparing the size of the `confirmations` `HashSet` to `self.num_confirmations`: [1](#0-0) 

`delete_member()` (executed as a `MultiSigRequestAction::DeleteMember` action) removes the member from `self.members` and deletes any *requests originated by that member*, but it filters solely on `r.member == member` — i.e., the requester field of `MultiSigRequestWithSigner` — never inspecting the `confirmations` map for requests that the removed member merely *confirmed* (but did not create): [2](#0-1) 

The equality that should hold is: `confirmations.len()` for a request == number of currently-live members who confirmed it. After `delete_member`, this equality is broken — a stale confirmation from a now-removed member is still present in the `HashSet<String>` and continues to count.

The legacy `multisig/src/lib.rs` contract has the identical flaw in its `DeleteKey` action handler, which filters removed requests by `r.signer_pk == pk` (the original requester) and never cleans confirmations on other pending requests: [3](#0-2) 

### Impact Explanation
This breaks the threshold-authorization binding explicitly called out in scope: "confirmations counted versus live members." A multisig request can be executed with fewer *currently authorized* signers than `num_confirmations` requires, because a removed (e.g., compromised, terminated, or malicious) member's earlier confirmation is silently honored post-removal. This is a Critical-impact scenario ("a multisig request executed below threshold"), since it can let a transfer, key addition/removal, or function call proceed on the authority of members who no longer hold that authority at execution time.

### Likelihood Explanation
The scenario requires no attacker privilege escalation beyond normal multisig usage: any member who confirms a pending request and is later removed (a routine operational event, e.g. after key compromise or personnel change) leaves behind a stale confirmation. The remaining members, unaware that one of the counted confirmations belongs to a no-longer-trusted party, can unknowingly execute (or a colluding subset of members can knowingly exploit) the request below the intended live threshold.

### Recommendation
When removing a member (`delete_member` / `DeleteKey`), iterate over all pending requests' `confirmations` sets and strip any entry matching the removed member's identity string/public key, not just requests they originated. Alternatively, revalidate `confirm()`'s stored confirmation set against current `self.members` membership at execution time before comparing to `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R` (e.g., a `Transfer`).
3. `A` calls `confirm(R)` → 1 confirmation. `B` calls `confirm(R)` → 2 confirmations (`{A, B}`), still below threshold.
4. Members submit and confirm a separate request `DeleteMember{ member: A }` (e.g., because `A`'s key was compromised) — this executes and removes `A` from `self.members`, but `R`'s confirmations set still contains `A`.
5. `C` calls `confirm(R)` → `confirmations.len()` becomes 3, meeting `num_confirmations`, and `execute_request(R)` fires — even though only `B` and `C` are currently live, trusted members; `A`'s stale confirmation supplied the third vote after being revoked.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
