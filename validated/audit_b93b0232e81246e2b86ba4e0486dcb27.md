### Title
Floor-rounded 70% supermajority threshold in `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` diverges from the canonical ceiling-rounded block-approval threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The on-chain, authoritative supermajority threshold for Nakamoto signer weight (`NakamotoBlockHeader::compute_voting_weight_threshold`) is explicitly computed with a ceiling (round-up), as documented in its own comment ("Round-up check") and tests [1](#0-0) . In contrast, `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` — which drive the signer's internal state-machine consensus (burn view, active-miner state, protocol version, tx replay set) — compute the same 70%/30% thresholds with plain integer division, which floors (rounds down) rather than rounding up [2](#0-1) .

### Finding Description
`compute_voting_weight_threshold` explicitly adds a ceiling adjustment so that, e.g., for `total_weight = 3`, the required weight is `ceil(3*7/10) = 3` (all three units) [3](#0-2) .

`GlobalStateEvaluator::reached_agreement`, however, computes:
```
vote_weight >= total_weight * 7 / 10   (integer division, floors)
```
For `total_weight = 3`, this evaluates `3*7/10 = 21/10 = 2` (floor), so `reached_agreement(2)` returns `true` even though the canonical formula requires all 3 units (`ceil(21/10) = 3`). The same divergence exists in `reached_disagreement`, which uses `10 - threshold` as the multiplier [4](#0-3) . This is exactly analogous to the reported bug pattern: `amountUsdX18.div(price)` (floor) vs the recommended `divUp` — a boolean/threshold gate that is supposed to require a true supermajority instead silently accepts a smaller fraction whenever `total_weight * 7` is not an exact multiple of 10 (i.e., whenever `total_weight % 10 != 0`), which is the common case for any real reward-set weight distribution.

This threshold function is used pervasively to decide the signer's local consensus state: determining the global burn view [5](#0-4) , the overall agreed `SignerStateMachine` (current miner, tx-replay set, protocol version) [6](#0-5) , the majority-supported protocol version [7](#0-6) , and — critically — the "active miner"/blocking-minority evaluation in `stacks-signer/src/v0/signer_state.rs` that decides whether a signer should treat another tenure's block count/miner view as authoritative based on `reached_disagreement`/`reached_agreement` on `entry` weight [8](#0-7) , and to timestamp when the burn view "achieved" global agreement in `signerdb.rs` [9](#0-8) .

### Impact Explanation
Because the floor-rounded threshold requires strictly less weight than the true 70% ceiling threshold, the signer's local state machine can conclude "global agreement" on a burn view, active miner, or tx replay set with a vote weight that would *not* satisfy the canonical 70% supermajority used elsewhere in the protocol (`compute_voting_weight_threshold`/`verify_signer_signatures`). Since `determine_global_state`'s output (particularly `current_miner`/tenure view and `tx_replay_set`) feeds signer decision-making about which miner/tenure is active and which transactions should be excluded from replay, a systematically under-strict threshold weakens the guarantee that these safety-relevant internal decisions require an actual supermajority, nudging the signer set toward premature/incorrect consensus (a weakening of the safety margin rather than a hard majority requirement bypass). This falls under the "aggregated-weight vs verified-accepts" equality class the task calls out, since the aggregated vote weight used inside the signer's own consensus evaluator no longer matches the verified/ceiling-based accept threshold used by the rest of the codebase.

### Likelihood Explanation
The divergence is deterministic and not dependent on attacker-controlled input: it triggers whenever `total_weight % 10 != 0` for the relevant weight sum, which is the common case for real PoX-derived signer weights (only exact multiples of 10 avoid it). No majority compromise or key theft is needed to trigger the divergence itself — it is a latent formula bug present for all signers running this code, since they all use the same (buggy) floor-based comparator consistently. However, I could not fully verify within the available iterations whether this internal-consensus weakening is reachable to produce a concrete, provable safety break (e.g., a signer being pushed to sign an actually-invalid/non-canonical block) as opposed to only weakening an internal bookkeeping threshold that is not itself gating block signature validity (which uses the correct ceiling-based `compute_voting_weight_threshold` directly, per `store_and_process_block_signature` in `stacks-signer/src/v0/signer.rs`). This uncertainty is noted rather than resolved due to running out of investigation iterations before tracing every downstream consumer of `determine_global_state`/`current_miner` in `stacks-signer/src/v0/signer.rs`.

### Recommendation
Align `reached_agreement` and `reached_disagreement` with the same ceiling-rounding convention already used by `NakamotoBlockHeader::compute_voting_weight_threshold`, e.g.:
```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total = u64::from(self.total_weight);
    let threshold = (total.strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)).div_ceil(10);
    u64::from(vote_weight) >= threshold
}
```
and correspondingly for `reached_disagreement`, so that the signer's internal consensus threshold never requires strictly less weight than the canonical on-chain 70% supermajority.

### Proof of Concept
For `total_weight = 3`, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`:
- Canonical threshold (`compute_voting_weight_threshold(3)`): `ceil(3*7/10) = ceil(2.1) = 3`.
- `GlobalStateEvaluator::reached_agreement(2)` with `total_weight = 3`: `2 >= 3*7/10 = 21/10 = 2` (integer floor) → `true`.

This shows a vote weight of `2` (66.7% of `3`) is treated by `reached_agreement` as reaching the "70% supermajority," while the canonical formula used elsewhere in the codebase for the same nominal threshold requires the full weight of `3` (100%). [10](#0-9) [3](#0-2)

    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

                continue;

            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);

                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {

            self.find_majority_prefix_replay_set(&tx_replay_sets)
