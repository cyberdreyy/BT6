### Title
APR0 withdrawal request can veto a mid-lifecycle APR transition and force a zero-APR epoch - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary

An unprivileged, KYC-approved tranche holder can create an APR0 withdrawal request immediately before an honest manager changes the vault APR. The manager’s APR update succeeds because `setAprs` does not check the outstanding APR0 principal bucket, but `stopEpoch` later always reverts while `apr0TotalPrincipal != 0` and `unscaledApr != 0`. The manager must restore APR to zero before the epoch can be stopped, allowing the attacker to veto the intended APR transition for that epoch.

### Finding Description

`IdleCreditVault.requestWithdraw` routes a request into `apr0Users` and adds its principal to `apr0TotalPrincipal` whenever `unscaledApr == 0`. [1](#0-0) [2](#0-1) 

The manager-facing `setAprs` updates `unscaledApr` without rejecting a transition away from zero while that bucket remains open. [3](#0-2) 

At epoch finalization, `prepareStopEpochWithApr0` explicitly treats nonzero `unscaledApr` with an outstanding APR0 bucket as invalid and reverts. [4](#0-3) 

This check executes before the epoch can complete, collect borrower funds, update accounting, or open the next buffer period. [5](#0-4) 

### Impact Explanation

For an APR0 vault with NAV `V`, an attacker holding tranche tokens can front-run a routine manager APR update with a withdrawal request. Once the manager’s transaction changes `unscaledApr` to a nonzero value, `stopEpoch` and `stopEpochWithDuration` become unusable until the manager restores APR to zero and stops the epoch under the old accounting mode.

The direct fund impact is the yield that was supposed to accrue during that epoch. For NAV `V`, intended unscaled APR `r`, and epoch-plus-buffer duration `T`, the denied borrower interest is approximately:

```text
forgoneInterest = V * r * T / 365 days
```

For example, forcing a `10,000,000` underlying-token vault that should have earned 10% APR through a 30-day epoch denies approximately `82,191` underlying tokens of interest. The funds are temporarily frozen rather than stolen: restoring `unscaledApr` to zero allows `prepareStopEpochWithApr0` to pass and normal epoch settlement to continue.

### Likelihood Explanation

The issue requires an APR0 credit vault, a KYC-approved tranche holder or queue user able to submit a withdrawal request, and an honest APR change while that request remains unsettled. Those conditions are mode-specific, so the issue is conditional rather than universally reachable. No privileged-key compromise, oracle manipulation, default, or external protocol failure is required.

### Recommendation

Prevent the inconsistent state from being created. In `IdleCreditVault.setAprs` and `setAprsWithBuffer`, reject a transition from `unscaledApr == 0` to a nonzero APR while `apr0TotalPrincipal != 0`. Alternatively, explicitly settle or cancel all outstanding APR0 requests before permitting the mode transition. Add a regression test showing that an APR update cannot strand an open APR0 bucket in `stopEpoch`.

### Proof of Concept

The following Foundry sequence assumes the existing `IdleCreditVault.t.sol` fixture and helpers. It demonstrates that a user request under APR0 causes the manager’s subsequent nonzero APR configuration to wedge `stopEpoch` until APR is restored to zero.

```solidity
// test/foundry/IdleCreditVault.t.sol
function testApr0RequestBlocksAprTransitionAtStopEpoch() external {
    address attacker = makeAddr('apr0-transition-attacker');
    uint256 amount = 10_000 * ONE_SCALE;

    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);

    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    _depositWithUser(attacker, amount, true);

    // The attacker requests withdrawal while the request lifecycle is APR0.
    vm.prank(attacker);
    uint256 requestBasis = cdoEpoch.requestWithdraw(0, address(AAtranche));
    assertGt(requestBasis, 0, 'APR0 request was not created');
    assertEq(
        IdleCreditVault(address(strategy)).apr0TotalPrincipal(),
        requestBasis,
        'APR0 bucket was not opened'
    );

    _startEpochAndCheckPrices(0);

    // An honest manager attempts a routine APR change during the open lifecycle.
    // The call succeeds because setAprs does not check apr0TotalPrincipal.
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(10e18, 10e18);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Epoch settlement is blocked while nonzero APR coexists with APR0 principal.
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, 0, epochDuration, 0);

    assertTrue(cdoEpoch.isEpochRunning(), 'epoch unexpectedly stopped');
    assertEq(
        IdleCreditVault(address(strategy)).apr0TotalPrincipal(),
        requestBasis,
        'APR0 bucket was not preserved'
    );

    // Recovery requires undoing the APR transition and settling one epoch at APR0.
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, 0, epochDuration, 0);

    assertFalse(cdoEpoch.isEpochRunning(), 'APR0 stop did not recover');
    assertEq(
        IdleCreditVault(address(strategy)).apr0TotalPrincipal(),
        0,
        'APR0 bucket was not closed'
    );
}
```
