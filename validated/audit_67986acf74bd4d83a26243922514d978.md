### Title
Reward tokens not listed in `convexRewards` are never swapped or forwarded and remain permanently stuck in the strategy - (File: contracts/strategies/convex/ConvexBaseStrategy.sol)

### Summary
`ConvexBaseStrategy.redeemRewards()` calls `IBaseRewardPool(rewardPool).getReward()`, which transfers **all** accrued reward tokens for the Convex position (CRV, CVX, plus any "extra rewards" such as LDO on the ETH-stETH pool) to the strategy contract. The subsequent swap loop iterates only over the `convexRewards` array. Any reward token actually paid out by `getReward()` but absent from `convexRewards` is left sitting on the strategy contract. The contract is designed to "not have any funds at the end of each tx" and exposes no general `sweep`/`rescueToken`/`transferToken` method, so these rewards are permanently frozen instead of being converted to LP tokens and credited to tranche holders.

### Finding Description
In `redeemRewards` (`ConvexBaseStrategy.sol:288`):

```solidity
IBaseRewardPool(rewardPool).getReward();
```

claims every reward token the Convex `BaseRewardPool` distributes, including tokens attached via Convex's `extraRewards` mechanism. Then (`ConvexBaseStrategy.sol:295-325`):

```solidity
for (uint256 i = 0; i < _convexRewards.length; i++) {
    if (_skipSell[i]) continue;
    _reward = _convexRewards[i];
    _rewardBalance = _rewardToken.balanceOf(address(this));
    if (_rewardBalance == 0) continue;
    ...
    _router.swapExactTokensForTokens(...);
}
```

only tokens enumerated in `convexRewards` are swapped to WETH and further into the Curve LP token. The reward list is set at initialize time via `addReward` (`ConvexBaseStrategy.sol:185-187`) and is a static configuration. If the underlying Convex pool emits a reward token that was not registered (e.g., LDO for the steth pool, or a token added by Convex to `extraRewards` after deployment), each `harvest()` still pulls those tokens into the strategy but never touches them again. Unlike the analogous `IdleTruefiStrategy`, which has an owner `transferToken` escape hatch (`IdleTruefiStrategy.sol:249-255`), `ConvexBaseStrategy` has no generic token-recovery function, so the balance cannot be recovered even by governance without a contract upgrade.

### Impact Explanation
Direct loss of yield for all AA/BB tranche holders of the affected IdleCDO: reward tokens that should be sold and reinvested (raising `price()` / tranche NAV) instead accumulate idle in the strategy contract. For pools paying third-party incentives this can be a material fraction of the strategy APR. The loss compounds every harvest and the tokens are unrecoverable without upgrading the strategy implementation.

### Likelihood Explanation
Requires no attacker action beyond normal operation: any pool whose Convex reward set is a superset of `convexRewards` (misconfiguration at deployment, or a new extra-reward token added by the pool later) triggers it automatically on every `harvest()`. The unprivileged attacker angle is minimal — the loss is passive — matching the external report's bug class exactly.

### Recommendation
- Add an owner-only `sweep(address token)`/`transferToken` method to `ConvexBaseStrategy` for tokens not otherwise accounted for, or
- Ensure `addReward`/registration covers every token returned by the reward pool's `extraRewardsLength()`/`extraRewards(i)` at deployment and whenever Convex changes the reward set.

### Proof of Concept
Foundry fork test (mainnet, e.g. Convex pool 25 steth where `getReward()` pays CRV, CVX, LDO):

```solidity
// deploy ConvexBaseStrategy initialized with convexRewards = [CRV, CVX] only (no LDO)
// deposit LP via whitelisted CDO, warp forward so rewards accrue
uint256 ldoBefore = IERC20(LDO).balanceOf(address(strategy));
cdo.harvest(skipFlags, skipReward, minAmounts, sellAmounts, extraData);
uint256 ldoAfter = IERC20(LDO).balanceOf(address(strategy));
assertGt(ldoAfter, ldoBefore); // LDO claimed but never swapped/forwarded
// subsequent harvests keep increasing the stuck balance; no function exists to move it
```

Caveat: I was unable to confirm within the available iterations whether a later version of this file adds a recovery method; the finding assumes the shown `ConvexBaseStrategy` is the in-scope implementation.
