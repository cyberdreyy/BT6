### Title
`debug/vars` endpoint discloses expvar internals to any authenticated session regardless of role - ([File: core/web/router.go])

### Summary
`debugRoutes` in `core/web/router.go` wraps `/debug/vars` only with `auth.Authenticate(..., auth.AuthenticateBySession)`, which merely validates that a session cookie corresponds to a valid, non-expired user session. It does not apply any of the `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrappers found in `core/web/auth/auth.go`, so any authenticated user, including a `UserRoleView` account, can retrieve the full expvar payload (goroutine counts, memstats, custom exported vars).

### Finding Description
`debugRoutes` builds the `/debug` group with a single middleware, `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, then registers `group.GET("/vars", expvar.Handler())` [1](#0-0) . `auth.Authenticate` only iterates through the given `authMethod`s (here just `AuthenticateBySession`) and aborts with 401 if none succeed; it performs no role check [2](#0-1) . `AuthenticateBySession` looks up the session cookie, resolves it to a user via `AuthorizedUserWithSession`, and sets the user in the gin context, again without evaluating `user.Role` [3](#0-2) . Compare this to other protected routes, such as `sessionRoutes`'s `DELETE /sessions`, which likewise uses only `AuthenticateBySession` (session-only actions are expected to be role-agnostic), but privileged config/job endpoints elsewhere in the router are wrapped with `RequiresEditRole`/`RequiresAdminRole` (defined at lines 202-255 of `auth.go`) to enforce a minimum role. `debugRoutes` has no equivalent wrapper, so a `UserRoleView` session (the lowest privilege role, checked explicitly in `RequiresRunRole` at line 210 of `auth.go`) passes straight through to `expvar.Handler()` and receives the full JSON dump of registered expvars.

### Impact Explanation
This is an authorization-exactness gap: internal runtime state (goroutine counts, GC/memstats, and any custom `expvar.Publish`-registered variables, which in Chainlink can include internal counters/metrics) is disclosed to the lowest-privileged authenticated principal instead of being restricted to run/edit/admin roles. This maps to an "information disclosure via authorization bypass" class issue — a view-only user gains visibility into information intended for operators, which could aid further attacks (e.g., reconnaissance of internal state, resource exhaustion vectors) but does not by itself allow fund movement or credential/key exposure.

### Likelihood Explanation
The only precondition is a valid, low-privilege (`UserRoleView`) session cookie, which is the minimum access a node operator would grant to an external/read-only user. Once such a session exists, the exploit is a single unauthenticated-by-role `GET /debug/vars` request; it is trivially repeatable and requires no additional exploitation techniques.

### Recommendation
Wrap the `/debug/vars` route with a role-check middleware, e.g. `auth.RequiresEditRole` or at minimum `auth.RequiresRunRole`, consistent with other operator-only diagnostic routes:
```go
func debugRoutes(app chainlink.Application, r *gin.RouterGroup) {
	group := r.Group("/debug", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	group.GET("/vars", auth.RequiresEditRole(expvar.Handler()))
}
```
(adjusting for the `func(*gin.Context)` signature expected by `RequiresEditRole`).

### Proof of Concept
1. Handler-level integration test (in `core/web/router_test.go` style):
   - Set up a test app with a `UserRoleView` user and obtain a valid session cookie via `POST /sessions`.
   - Issue `GET /debug/vars` with that session cookie.
   - Assert the response status is `200` and body contains valid expvar JSON (e.g., `cmdline`, `memstats` keys), demonstrating the missing role check.
2. Negative control: repeat with `RequiresEditRole`/`RequiresRunRole` applied (post-fix) and assert `401`/`403` for the view-role session while an `edit`/`run`/`admin` session still returns `200`.

```go
func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}
```

```go
// Authenticate is middleware which authenticates the request by attempting to
// authenticate using all the provided methods.
func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}
```
