### Title
Unvalidated `req.Method` in `handler.HandleJSONRPCUserMessage` broadcasts arbitrary-method JSON-RPC to entire DON before allowlist enforcement - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` never checks `req.Method` against `h.Methods()` (`MethodSecretsGet`/`MethodCapabilityExec`) before creating an `activeRequest` and calling `fanOutToNodes`, which broadcasts the raw, attacker-controlled `req` (including `Method`) to every DON member via `h.don.SendToNode`. The only method validation that exists (`bundler.Bundle`'s `errUnknownMethod` in `bundler.go`) runs later, on the first node response or on request expiry — well after the fan-out side effect has already occurred.

### Finding Description
`handler.HandleJSONRPCUserMessage` (`core/services/gateway/handlers/confidentialrelay/handler.go:349-366`) only validates `req.ID` (non-empty, ≤200 chars), then calls `h.newActiveRequest` and unconditionally `h.fanOutToNodes(ctx, l, ar)`. `fanOutToNodes` (`handler.go:618-652`) iterates `h.donConfig.Members` and calls `h.don.SendToNode(sendCtx, node.Address, &ar.req)` for every member, forwarding `req.Method` verbatim with no allowlist check against `h.Methods()` (`handler.go:341-343`, returning only `MethodSecretsGet`/`MethodCapabilityExec`). The only place `req.Method` is validated against known values is `bundler.Bundle`'s `switch req.Method` in `bundler.go:118-163`, which returns `errUnknownMethod` in its `default` branch — but `Bundle` is invoked only from `HandleNodeMessage` (on first node response), `removeExpiredRequests` (on request timeout), or `forwardAfterGrace`, i.e., strictly after `fanOutToNodes` has already sent the request to the DON.

However, whether this handler-level gap is externally reachable depends on the routing layer above it, `multiHandler` in `core/services/gateway/multihandler.go`. `multiHandler.HandleJSONRPCUserMessage` (lines 62-69) calls `m.getHandler(jsonRequest.Method)`, which normally enforces the allowlist via `methodToHandler` (populated per-method from each handler's `Methods()` in `NewMultiHandler`, lines 22-47). Crucially, `getHandler` (lines 80-96) contains a special case: **if `len(m.typeToHandler) == 1`, it returns that single handler directly regardless of the requested method**, bypassing the `methodToHandler` map/allowlist entirely, explicitly for "backwards compatibility." Per `core/services/gateway/handler_factory.go`, each DON/service can be configured with a single handler type (e.g., only `ConfidentialRelayHandlerType`); in that configuration, `typeToHandler` has exactly one entry, and the method-allowlist bypass applies, letting an arbitrary `req.Method` string reach `handler.HandleJSONRPCUserMessage` unchecked.

### Impact Explanation
When reachable (single-handler-per-DON config, which is a normal, supported deployment shape per `handler_factory.go`), an unprivileged gateway client can submit any `Method` string and force `fanOutToNodes` to broadcast attacker-controlled JSON-RPC traffic (arbitrary method name, arbitrary `Params` as `json.RawMessage`) to every node in the DON before any allowlist check occurs. This is an authorization-enforced-only-at-a-later-layer bypass: the intended access control (`Methods()`/allowlist) is violated at the point of external effect (network send to all DON nodes), even though the request is later rejected once a node responds or the request expires. This does not directly leak secrets or bypass vault/key-material access controls (the enclave/relay-node side still processes/validates whatever it receives), but it is a concrete allowlist-bypass and DON-wide traffic-amplification/DoS vector: an unauthenticated-cost-free request can generate `N` (DON size) outbound sends per request with attacker-chosen method/payload content, independent of whether the method is ever legitimate.

### Likelihood Explanation
Feasibility depends entirely on deployment topology: the bypass requires the confidential-relay (or any) handler to be the sole handler type registered for a given service/DON in `multiHandler.typeToHandler`. This is a valid, supported single-handler configuration per `handler_factory.go` (`ConfidentialRelayHandlerType` alone), not a misconfiguration. Given that, the precondition is only "reach `HandleJSONRPCUserMessage` as an unauthenticated/low-privileged gateway user," which is the gateway's normal entry point (`gateway.ProcessRequest` in `gateway.go:218-292`), requiring no special credentials. It is fully repeatable per request ID.

### Recommendation
Add an explicit method allowlist check at the top of `handler.HandleJSONRPCUserMessage` (before `newActiveRequest`/`fanOutToNodes`), rejecting any `req.Method` not in `h.Methods()` with `api.UnsupportedMethodError`, mirroring the pattern already used in the vault handler (`vault/handler.go:431-433`, `IsGatewaySecretsMethod` check before any node interaction). Additionally, remove or gate the single-handler bypass in `multiHandler.getHandler` (`multihandler.go:80-88`) so it does not skip the `methodToHandler` lookup, or ensure it still returns errors for genuinely unknown methods.

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}

func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))

			}

func (m *multiHandler) HandleJSONRPCUserMessage(ctx context.Context, jsonRequest jsonrpc.Request[json.RawMessage], callback handlers.Callback) error {
	h, err := m.getHandler(jsonRequest.Method)
	if err != nil {
		return fmt.Errorf("failed to get handler for method %s: %w", jsonRequest.Method, err)
	}

	return h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
}

func (m *multiHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h, err := m.getHandler(resp.Method)
	if err != nil {
		return fmt.Errorf("failed to get handler for method %s: %w", resp.Method, err)
	}

	return h.HandleNodeMessage(ctx, resp, nodeAddr)
}

func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	// If there's only one handler, return it directly.
	// This preserves backwards compatibility for cases where the method
	// isn't specified on responses (and for cases where only one handler is registered more generally).
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}

	handler, ok := m.methodToHandler[method]
	if !ok {
		return nil, errors.New("no handler found for method " + method)
	}

	return handler, nil
}
