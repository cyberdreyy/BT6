Analysis: The liquidation-fee bug in the Sentiment report stems from a lending protocol taking a fee from the liquidator's entire seized collateral rather than from their profit margin, making liquidations economically unviable. This repository's fee model is structurally different — it is a cross-chain atomic-swap escrow system where `protocolFeeAmount`/`integratorFeeAmount` are pre-computed off-chain via `FeeCalcLib.getFeeAmounts` [1](#0-0)  and baked into the immutable escrow parameters before the resolver/taker ever commits funds. There is no "liquidator profit" analog to protect: the taker (resolver) voluntarily fills the order and deploys the destination escrow knowing the exact fee amounts in advance, and `_postInteraction` explicitly guards against the fee exceeding the taking amount via `if (integratorFeeAmount + protocolFeeAmount >= takingAmount) revert InvalidFeeAmounts();` [2](#0-1) . Fees are simply deducted at withdrawal time and routed to `integratorFeeRecipientCd()`/`protocolFeeRecipientCd()` [3](#0-2) , with no dynamic "cost vs. reward" incentive calculation analogous to a liquidation discount that could be miscalculated. There is no reachable root cause in this codebase matching the reported bug class under the unprivileged-user model and required bounty scope.

    function getFeeAmounts(
        uint256 amount,
        uint256 protocolFee,
        uint256 integratorFee,
        uint256 integratorShare
    ) internal pure returns (uint256 integratorFeeAmount, uint256 protocolFeeAmount) {
        uint256 denominator = _BASE_1E5 + integratorFee + protocolFee;
        uint256 integratorFeeTotal = amount.mulDiv(integratorFee, denominator);
        integratorFeeAmount = integratorFeeTotal.mulDiv(integratorShare, _BASE_1E2);
        protocolFeeAmount = amount.mulDiv(protocolFee, denominator) + integratorFeeTotal - integratorFeeAmount;
    }
