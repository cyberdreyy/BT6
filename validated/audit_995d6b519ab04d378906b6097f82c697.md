### Title
Confirmations from deleted multisig members remain counted toward `num_confirmations` threshold, allowing requests to execute below the intended threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` removes a departing member's own outstanding *requests* and their confirmation records, but it never scans and purges that member's confirmations that were cast on requests *created by other members*. `confirm` then counts all entries in `self.confirmations` toward `self.num_confirmations` without checking that every counted confirmation still belongs to a current member. A request can therefore be executed by counting "phantom" confirmations from accounts/keys that have since been removed from the multisig, executing a transfer, key addition, or function call with fewer live-member approvals than the configured threshold requires.

### Finding Description
`confirm` computes the confirmation count purely from the stored set and compares it to `num_confirmations`, without re-validating membership of every prior confirmer: [1](#0-0) 

`delete_member` only cleans up requests that were *created* by the removed member (`r.member == member`), and only removes confirmations tied to those specific requests. It does not search `self.confirmations` for entries where the removed member had confirmed someone else's still-pending request: [2](#0-1) 

`assert_valid_request` (called from `confirm`) only checks that the *caller* is currently a member; it does not re-verify the membership of confirmers already recorded in `self.confirmations`: [3](#0-2) 

The binding that should hold is: `confirmations.len() counted in confirm == number of confirmations from accounts that are members at time of confirm`. Because stale confirmations from removed members are never purged from pending requests created by *other* members, this equality is broken — the count can include confirmers who are no longer part of `self.members`, letting a request reach the threshold with fewer currently-authorized approvals than `num_confirmations` mandates.

### Impact Explanation
This is a threshold-bypass on a multisig wallet: a request (e.g. `Transfer`, `AddKey`, `FunctionCall`) can be executed with confirmations from accounts that have since been removed as members, meaning the number of *live* members who actually approved is strictly less than `num_confirmations`. This matches the "Critical — a multisig request executed below threshold" impact category, since NEAR held by the multisig account (or actions on its access keys) can move despite not receiving the required number of current approvals.

### Likelihood Explanation
Any current member (an unprivileged party in the sense that they only hold the access typical members already have, not the removed member) can exploit this deterministically: create/confirm requests before a co-member is removed, wait for that removal (a routine multisig operation, e.g. offboarding a compromised or departing signer), then finish confirming with the remaining live members. No special timing or race condition is required — it is a straightforward two-step sequence available to ordinary members.

### Recommendation
When deleting a member in `delete_member`, iterate over `self.requests`/`self.confirmations` for *all* pending requests (not just ones the removed member authored) and strip the removed member's entry from each confirmation set. Alternatively, when counting confirmations in `confirm`, filter `confirmations` to only those entries whose corresponding member is still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with 3 members `A, B, C` and `num_confirmations = 3`.
2. `A` calls `add_request_and_confirm(request)` — confirmations = `{A}`.
3. `B` calls `confirm(request_id)` — confirmations = `{A, B}` (2 < 3, not yet executed).
4. Members vote to remove `B` via a separate `DeleteMember { member: B }` request (this only deletes requests `B` created, not `B`'s confirmation left on step 3's request, per [4](#0-3) ). `B`'s stale confirmation on the pending transfer request remains in `self.confirmations`.
5. `C` calls `confirm(request_id)` — confirmations = `{A, B, C}`, `len()+1 >= 3` is already satisfied by the stale set (`len()==2` plus C makes 3), so [5](#0-4)  executes the request.
6. The transfer/action executes having been approved by only 2 members that are still part of the multisig (`A`, `C`) plus one removed member (`B`), even though `num_confirmations = 3` was meant to require 3 *current* members' approval.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
