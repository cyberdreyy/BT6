## Analog Vulnerability Found

### Title
CORS wildcard-origin allowlist bypass via missing subdomain-boundary check (domain confusion) - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's internet-facing HTTP server implements its own CORS origin allowlist logic in `isAllowedOrigin`. When an operator configures a wildcard entry such as `*.remix.com` in `CORSAllowedOrigins`, the check strips the `*.` prefix and then only performs a raw `strings.HasSuffix` match against the origin host, without requiring a literal `.` boundary before the suffix. [1](#0-0)  This is the same bug class as CVE-2022-30115: a "missing required step" in hostname validation — curl compared hostnames without normalizing a trailing dot, letting an attacker-controlled variant slip past an equality check; here, the gateway compares hostnames without enforcing a subdomain-separator dot, letting an attacker-registered domain slip past a suffix check.

### Finding Description
`isAllowedOrigin` parses both the incoming `Origin` header and each configured allowed origin via `splitURL`, which only lowercases the URL and splits scheme/host/port — it performs no other normalization. [2](#0-1) 

For wildcard entries, the matching logic is:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [3](#0-2) 

Given an operator configuration of `CORSAllowedOrigins = ["https://*.remix.com"]` (intended to allow only true subdomains of `remix.com`), an attacker who registers `evilremix.com` can send a request with `Origin: https://evilremix.com`. Since `"evilremix.com"` ends with the substring `"remix.com"`, `strings.HasSuffix` returns `true` and the request is treated as coming from an allowed origin — even though `evilremix.com` is not a subdomain of `remix.com` at all. The handler then reflects the attacker's origin back in `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, and `Access-Control-Allow-Headers`. [4](#0-3) 

This mirrors the CVE-2022-30115 root cause exactly: a string-comparison-based trust boundary (HSTS host match / CORS host match) that omits the mandatory separator/anchor check needed to prevent a crafted-but-distinct hostname from satisfying the match.

### Impact Explanation
This is a concrete allowlist bypass on the Gateway's internet-facing HTTP entrypoint (`handleRequest`), which forwards `ProcessRequest` to gateway handlers using any bearer JWT supplied in the `Authorization` header. [5](#0-4)  An attacker who controls a domain that merely ends with the configured suffix (no dot boundary required) can have their origin treated as trusted for CORS purposes, undermining the operator's intent when configuring wildcard allowlists (e.g. `*.mycompany.com` also matching `evilmycompany.com`, `notmycompany.com`, etc.). Any browser-based client of the Gateway that relies on this wildcard allowlist for CSRF/CORS protection is exposed to cross-origin request/response confusion from an unrelated, attacker-registered domain.

### Likelihood Explanation
Exploitation only requires: (1) an operator using a wildcard CORS entry (a documented/supported feature, exercised in tests such as `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`) [6](#0-5) , and (2) registration of an inexpensive domain name that shares the suffix string. No privileged access or special network position is needed — this is exploitable by any unprivileged web attacker who can lure a victim browser to their page.

### Recommendation
Fix the wildcard match to require a proper subdomain boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".remix.com"
    if originHost == suffix[1:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
i.e., match against `.remix.com` (including the leading dot) rather than `remix.com`, so `evilremix.com` no longer satisfies `HasSuffix`. Add regression tests for adjacent/prefix-confusable domains (e.g. `evilremix.com`, `notremix.com`) similar to the existing wildcard CORS tests.

### Proof of Concept
1. Configure the Gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.remix.com"]`.
2. From a browser page hosted at `https://evilremix.com`, send a `fetch` request to the Gateway's HTTP endpoint with `Origin: https://evilremix.com`.
3. Observe that `isAllowedOrigin` returns `true` (since `"evilremix.com"` has suffix `"remix.com"`), and the response includes `Access-Control-Allow-Origin: https://evilremix.com`, allowing the attacker page's JavaScript to read the response — despite `evilremix.com` never being an authorized subdomain.

func (s *httpServer) splitURL(rawURL string) (string, string, string, error) {
	// lowercase the URL to avoid case sensitivity issues

		}
		return "", "", "", fmt.Errorf("error splitting host and port: %w", err)
	}

	return parsedURL.Scheme, host, port, nil
}

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
