### Title
Stale/decommissioned Chainlink USD0++ oracle permanently bricks `stopEpoch` and locks all tranche funds — (`File: contracts/IdleCDOUsualVariant.sol`)

### Summary
`IdleCDOUsualVariant` is a single-epoch vault: once `startEpoch` is called, deposits and withdrawals are disabled until the owner calls `stopEpoch`. `stopEpoch` unconditionally calls `IdleUsualStrategy.getChainlinkPrice()`, which reverts with `"Stale price"` if the Chainlink USD0++ feed's `updatedAt` is older than 24 hours. If the Chainlink feed stops being updated (deprecation, decommissioning, or a missed heartbeat — the same class of risk as deprecated Balancer oracles in the reference report), `stopEpoch` can never be executed, withdrawals can never be re-enabled, and all deposited USD0++ is locked forever. There is no fallback path: `stopEpoch` hard-reverts before any state changes, and `setOraclePrice` cannot be used to bypass it.

### Finding Description
The reference bug concerns settlement reverting because an external price source (Balancer's deprecated oracle) deviates or becomes unreliable. The analog here is identical in structure: `stopEpoch()` at `contracts/IdleCDOUsualVariant.sol:70-100` performs a mandatory external oracle read:

```solidity
uint256 _oraclePrice = _strategy.getChainlinkPrice();
_strategy.setOraclePrice(_oraclePrice);
```

`getChainlinkPrice` in `contracts/strategies/usual/IdleUsualStrategy.sol:164-172` enforces:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
return uint256(answer) * 1e10;
```

Three revert conditions exist, none guarded or recoverable:

1. `updatedAt <= block.timestamp - 24 hours` → `"Stale price"` revert. The code comment acknowledges the feed only updates on a 50 bps deviation or 24h heartbeat, so even normal operation is a race against the heartbeat boundary; a delayed keepers update permanently DoSes `stopEpoch` until the next update — and if the feed is decommissioned (Chainlink routinely deprecates feeds), it reverts forever.
2. `answer <= 0` → `uint256(answer)` casting revert (`SafeCast` panic). No `answer > 0` check exists.
3. The oracle contract itself reverting (e.g., `latestRoundData` removed or access restricted on an aggregator migration) propagates the revert.

Because `epochEndDate` can never be reset (`startEpoch` reverts with `"9"` once `epochEndDate != 0`), and withdrawals (`allowAAWithdraw`/`allowBBWithdraw`) are only re-enabled inside `stopEpoch`, a permanent revert means permanent lock. `isEpochRunning` stays true, `paused()` stays true, and both `withdrawAA`/`withdrawBB` (gated by `allowAAWithdraw`/`allowBBWithdraw` in `IdleCDO`) remain blocked.

The owner cannot mitigate on-chain: `setOraclePrice` (IdleUsualStrategy.sol:155) only writes the cached `oraclePrice`, but `stopEpoch` ignores the cached value and always calls `getChainlinkPrice()` first. There is no owner override to force-stop the epoch or re-enable withdrawals without the oracle read succeeding.

### Impact Explanation
Permanent freezing of 100% of vault TVL. All senior (AA) and junior (BB) tranche holders' USD0++ deposits, plus accrued USUAL harvest yield sitting in the strategy, are locked with no recovery path other than a contract upgrade (and `stopEpoch`/`withdraw` logic lives in the CDO whose storage depends on this call path). Broken invariant: liveness of the epoch state machine — funds must always be exitable after epoch end, but the design couples withdrawal enablement to a single hard-reverting external oracle read.

### Likelihood Explanation
The trigger is not attacker-dependent (same as the reference report, where the trigger is oracle deprecation by the vendor). Chainlink decommissions feeds on a schedule; a feed that only updates on 50bps deviation can also lapse the 24h heartbeat during low-volatility periods, causing temporary — and potentially indefinite — DoS windows. Note this requires the epoch to actually reach `epochEndDate` (~6 months of locked deposits), which is precisely when feed deprecation risk is highest. Severity is high (permanent lock), likelihood moderate (depends on feed longevity), consistent with a Medium finding like the source report.

### Recommendation
- Do not revert inside `stopEpoch` on a stale/dead oracle. Wrap `getChainlinkPrice` in a try/catch; on failure, fall back to a governance-set price via the existing `setOraclePrice` path (e.g., make `stopEpoch` accept a manual `_price` parameter usable only when the oracle read fails).
- Alternatively, split withdrawal re-enablement from the price read: unpause withdrawals with a separately callable function so users can exit even if the oracle is dead.
- Add `require(answer > 0)` before casting and check `answeredInRound >= roundId` for completeness.

### Proof of Concept
Foundry fork test (mainnet), in the style of `test/foundry/IdleUsualStrategy.t.sol`:

```solidity
function testStopEpochStaleOracleLocksFunds() external {
    uint256 amount = 10000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _transferBurnedTrancheTokens(address(this), false);

    IdleCDOUsualVariant _cdo = IdleCDOUsualVariant(address(idleCDO));
    IdleUsualStrategy _strategy = IdleUsualStrategy(_cdo.strategy());

    vm.prank(owner);
    _cdo.startEpoch(0); // deposits + withdraws now disabled

    // Simulate feed deprecation: oracle stops updating
    vm.mockCall(
        _strategy.USD0ppOracle(),
        abi.encodeWithSelector(IOracle.latestRoundData.selector),
        abi.encode(uint80(1), int256(1e8), uint256(0), block.timestamp - 25 hours, uint80(1))
    );

    vm.warp(block.timestamp + 1); // epochEndDate reached

    // Owner cannot stop the epoch -> withdraws can never be re-enabled
    vm.prank(owner);
    vm.expectRevert(bytes("Stale price"));
    _cdo.stopEpoch();

    // Confirmed locked: withdrawals still disabled
    assertFalse(_cdo.allowAAWithdraw());
    assertFalse(_cdo.allowBBWithdraw());
    vm.expectRevert(); // withdrawAA reverts
    _cdo.withdrawAA(0);
}
```

The same permanent-freeze outcome results from `vm.warp`ing past `updatedAt + 24 hours` on a fork where the live feed is already near its heartbeat, or from `answer <= 0` triggering the `uint256(int)` cast panic — in all cases `stopEpoch` reverts forever and tranche holders' funds are locked.
