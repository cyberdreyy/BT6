### Title
Unprivileged ERC4626 vault depositor injects phantom yield into epoch interest accounting, causing unbacked strategy-token mints and pool insolvency - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
In programmable-borrower mode, `IdleCDOEpochVariant` prices each epoch from a single `totalInterestDueNow()` expression evaluated on the `ProgrammableBorrower`. That expression trusts `_currentVaultAssets()` (the ERC4626 `convertToAssets` of the borrower's vault position) minus a baseline tracked only via `epochStartVaultAssets`, `epochDepositedToVault`, `epochWithdrawnFromVault` and `bufferedVaultDelta`. Any third party who deposits into the same ERC4626 vault inflates `convertToAssets` exactly like a sandboxed "expression" reading attacker-controlled input: the deposit is counted as epoch profit because the accounting cannot distinguish external deposits from real vault yield. In minted-interest mode this phantom profit is then minted as unbacked strategy tokens to tranche holders and fee receivers; the attacker immediately withdraws the deposit, converting the fabricated profit into a real vault loss that is socialized onto lenders BB-first.

### Finding Description
- `ProgrammableBorrower._vaultNetInterest()` computes `netDelta = bufferedVaultDelta + (currentVaultAssets + epochWithdrawnFromVault) - (epochStartVaultAssets + epochDepositedToVault)` [1](#0-0) . `epochDepositedToVault` is only incremented by the contract's own `_depositToVault` calls [2](#0-1)  — deposits made by any other ERC4626 vault user raise `convertToAssets` but never raise `principalAssets`, so they read as pure "interest".
- `totalInterestDueNow()` returns that fabricated interest to `IdleCDOEpochVariant.stopEpoch` [3](#0-2) .
- In minted-interest mode, `stopEpoch` calls `_strategy.mintStrategyTokens(_grossInterest)` and `_updateAccounting()`, distributing the phantom interest into tranche prices and minting fee shares to `feeReceiver`/`owner` — all backed by assets the borrower never paid [4](#0-3) .
- After `stopEpoch`, the attacker withdraws their deposit from the ERC4626 vault. `_currentVaultAssets` drops; the next epoch's `netDelta` becomes negative and is reported as `vaultLoss`, reducing `totalInterestDueNow` and socializing the hole onto BB tranche holders [5](#0-4) .
- The only guard is the `maxApr` cap check, which merely bounds `D` to roughly `maxApr`-scaled interest on `getContractValue()` and exists only in minted mode [6](#0-5) . As long as phantom "yield" stays under the cap — still up to `maxApr × NAV` per epoch — it is minted in full. In non-minted mode the same inflation makes `getFundsFromBorrower` pull cash the borrower never owed, forcing a spurious `_handleBorrowerDefault` (default path on an honest borrower — permanent freezing of the epoch flow) [7](#0-6) .

### Impact Explanation
An attacker (any ERC4626 vault depositor — no pool role needed) can (a) in minted mode: mint up to `maxApr`-bounded unbacked strategy tokens distributed to tranche holders/fee receivers, then remove the backing, leaving the pool insolvent by `D` and the loss socialized BB-first on the next epoch — quantified loss up to `maxApr × getContractValue() × duration/YEAR` per epoch, repeatable; (b) in non-minted mode: force `transferFrom` failure and `_handleBorrowerDefault` on a solvent borrower, freezing the facility. The fair-mint/burn and solvency invariants are broken: shares are minted against yield that exists only inside an external share price the attacker controls.

### Likelihood Explanation
Requires only that the configured ERC4626 vault accepts third-party deposits/withdrawals (true for Morpho-style vaults used in tests like `ProgrammableBorrowerCreditVault.t.sol` [8](#0-7) ). The attacker's capital cost is temporary — the deposit is withdrawn after `stopEpoch` — and the transaction can be timed via public mempool observation of `stopEpoch` calls each epoch, or front-run. No privileged role, oracle, or borrower cooperation is needed.

### Recommendation
Make the epoch-interest expression immune to external vault-share-price manipulation: track vault *shares* held plus a per-share baseline instead of `convertToAssets` deltas (e.g., snapshot `balanceOf` shares and `convertToAssets(1 share)` at `onStartEpoch`, and compute interest only from share-price drift net of external inflow), or exclude net third-party flows by measuring interest as `currentShares × startPrice − principal`. Alternatively, accrue vault yield via a time-weighted/share-price checkpoint taken at epoch boundaries that external single-block deposits cannot move, and validate `totalInterestDueNow` against borrower-contractual interest only.

### Proof of Concept
Foundry fork PoC (modeled on `test/foundry/ProgrammableBorrowerCreditVault.t.sol`):

```solidity
// Setup: real Morpho ERC4626 vault, programmable borrower, isInterestMinted = true
// Attacker = EOA holding underlying, no roles.

// 1. Epoch runs; lender deposited 10_000e6 via depositAA, epoch started.
uint256 depositAA = 10_000 * oneScale;
idleCDO.depositAA(depositAA);
cdoEpoch.startEpoch(); // via manager
// ProgrammableBorrower parked funds in vault; epochStartVaultAssets = 10_000e6.

// 2. Warp to epoch end; attacker deposits D into the ERC4626 vault.
uint256 D = 400 * oneScale; // below maxApr-scaled cap so _checkNotAllowed passes
underlying.approve(address(vault), D);
uint256 attackerShares = vault.deposit(D, attacker);   // inflates convertToAssets

// Phantom profit: totalInterestDueNow now includes ~D as "vault interest"
assertGt(programmableBorrower.totalInterestDueNow(), realYieldOnly + D - 1);

// 3. Honest manager calls stopEpoch — D is minted as unbacked strategy tokens.
vm.prank(manager);
cdoEpoch.stopEpoch(0, 0);
// _strategy.mintStrategyTokens(_grossInterest) minted ~D of unbacked tokens;
// AA/BB virtual prices and feeReceiver minted shares reflect D of fake yield.

// 4. Attacker withdraws deposit from vault.
vault.redeem(attackerShares, attacker, attacker);
// _currentVaultAssets drops by ~D; next epoch reports vaultLoss ≈ D,
// reducing totalInterestDueNow and socializing the hole onto BB holders.

// 5. Assert insolvency: minted interest tokens have no cash backing;
//    sum(tranche NAV) > totalUnderlying held by borrower + vault.
uint256 poolNAV = cdoEpoch.getContractValue();
uint256 backing = programmableBorrower.totalUnderlying();
assertGt(poolNAV, backing); // gap ≈ D, borne by BB-first loss waterfall
```

Variant (non-minted mode): step 2 identical; `stopEpoch` then attempts `getFundsFromBorrower(expectedInterest + pendingWithdraws)` where expected interest includes `D` cash the borrower doesn't hold → `transferFrom` fails → `_handleBorrowerDefault` triggers a false default and freezes the honest facility.

```text
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
```
