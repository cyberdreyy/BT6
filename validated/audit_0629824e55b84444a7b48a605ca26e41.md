## Analysis

Yes — this is a real accounting flaw in `staking_contract.move`, though the mechanism is subtly different from a literal "in-flight/pending call" race (Move transactions execute atomically; there is no re-entrancy). The actual bug is that `switch_operator` does not exempt the **old operator's already-settled, unpaid commission balance** from the pool's ongoing "commission-on-growth" mechanism once a new operator takes over.

### How the mis-attribution happens

`switch_operator` first pays out anything already inactive, then settles the old operator's outstanding commission into the `distribution_pool` as a normal share balance, and only then swaps the operator: [1](#0-0) 

The settlement itself is correct — `request_commission_internal` calls `add_distribution(old_operator, staking_contract, old_operator, commission_amount)`, crediting shares to `old_operator` specifically: [2](#0-1) 

The problem is that if the commission wasn't yet withdrawable (stake pool lockup not expired), `old_operator`'s shares **remain in the same shared `distribution_pool` object**, which is now stored under the `new_operator` key: [3](#0-2) 

Every subsequent call to `add_distribution` or `distribute_internal` (triggered by `request_commission`, `unlock_stake`, or `distribute`, callable by the new operator or even the staker) runs `update_distribution_pool`, which taxes the **growth** of every shareholder except the caller's `operator` parameter — which by now is `new_operator`: [4](#0-3) 

Since `old_operator` is still a live shareholder in the pool (their commission is pending_inactive and still earning stake rewards until lockup end), this loop treats `old_operator`'s own already-earned, unpaid commission balance exactly like ordinary staker principal, and siphons `new_commission_percentage` worth of its reward growth to `new_operator` — an operator that had no role while that balance was accruing. This repeats on every subsequent commission request/distribution call until `old_operator` finally withdraws, continuously bleeding value from the old operator to whoever currently holds the operator role.

This is distinct from the `delegation_pool.move` model, whose `synchronize_delegation_pool` fully settles commission into fresh shares state before `set_operator` runs, and which has an existing regression test (`test_change_operator`) proving clean separation of pre/post-switch commission — that protection does not exist for `staking_contract.move`'s shares-based `distribution_pool`. [5](#0-4) 

## Title
Unclaimed old-operator commission is taxed away to the new operator after `switch_operator` — ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::switch_operator` settles the departing operator's unpaid commission into the shared `distribution_pool` as an ordinary shareholder entry, then hands the same pool over to the incoming operator. If that settled commission has not yet become withdrawable (stake pool lockup still active), every later `request_commission`/`unlock_stake`/`distribute` call attributed to the new operator runs `update_distribution_pool`, which charges the new operator's commission rate on the growth of *all* other shareholders' balances — including the old operator's own already-earned, unwithdrawn commission. The old operator's entitlement is thus repeatedly taxed away to the new operator for as long as it remains unwithdrawn.

### Finding Description
`switch_operator` calls `distribute_internal` (pays out only what's currently inactive) and `request_commission_internal` (settles the old operator's still-active-stake-based commission as shares in `distribution_pool`) before reassigning the operator role via `stake::set_operator_with_cap` and moving the `StakingContract` (including its `distribution_pool`) under the `new_operator` key: [6](#0-5) 

If the old operator's settled commission is still `pending_inactive` (lockup not yet expired), it remains a live shareholder balance in `distribution_pool`, still accruing stake-pool rewards. `update_distribution_pool`'s commission mechanism is generic — it taxes "any stakeholder except the current `operator` argument" on relative growth, with no notion that a shareholder might be a *former operator's own unclaimed commission* rather than staker capital: [7](#0-6) 

Because the `operator` argument passed into this function after the switch is always `new_operator` (from `add_distribution`/`distribute_internal` calls keyed by the new map entry), the old operator's residual balance gets classified as "someone else's stake" and taxed at the new operator's commission rate — money the new operator did nothing to earn.

### Impact Explanation
This directly violates the "commission across the switch boundary" and "reward-synchronization accounting" invariants: an unprivileged staker action (`switch_operator`, callable by the contract-owning staker at will, requires no operator/governance privilege) can cause continuing, compounding value transfer from the old operator's already-vested commission to the new operator, for as long as the old operator delays withdrawal. This is a real economic/value-integrity bug, not merely a cosmetic one — the old operator (or their beneficiary) ends up receiving strictly less than their exact pre-switch-accrued commission.

### Likelihood Explanation
Likelihood is high for any staker who switches operators without first waiting for a full lockup cycle to elapse and calling `distribute` to flush existing commission — a routine operational pattern (e.g., mid-lockup-cycle operator changes for performance/SLA reasons). No special preconditions or privileged access are needed; only ordinary `request_commission`/`switch_operator`/`request_commission` sequencing across epochs.

### Recommendation
Before removing `old_operator` from the map / handing the `distribution_pool` to `new_operator`, either (a) force full settlement/withdrawal of the old operator's commission share regardless of lockup status (e.g., snapshot and pay via a side channel once unlocked, tracked independently of the shared pool), or (b) exempt pre-switch shareholder balances belonging to former operators from `update_distribution_pool`'s commission-on-growth logic — e.g. by tagging shares with the commission rate/operator epoch under which they were earned, so future commission calculations only apply to genuinely new growth attributable to the current operator's management.

### Proof of Concept
Sketch (following existing test patterns in `staking_contract.move`, e.g. `test_operator_can_set_beneficiary_for_operator`):
1. `setup_staking_contract(aptos_framework, staker, operator1, INITIAL_BALANCE, 10)`; join validator set; `stake::end_epoch()` to accrue rewards.
2. `request_commission(operator1, staker_address, operator1_address)` — settles operator1's commission into `distribution_pool` as pending_inactive (lockup NOT yet expired, so it stays a live shareholder, unlike the existing tests which call `stake::fast_forward_to_unlock` + `distribute` first to flush it).
3. `switch_operator(staker, operator1_address, operator2_address, new_commission_pct)`.
4. `stake::end_epoch()` one or more times so the still-locked pending_inactive amount (containing operator1's unpaid commission) earns additional rewards.
5. `request_commission(operator2, staker_address, operator2_address)` — this invokes `update_distribution_pool` with `operator = operator2_address`, taxing operator1's residual balance growth and transferring shares to operator2.
6. `stake::fast_forward_to_unlock(pool_address)`; `distribute(staker_address, operator2_address)`.
7. Assert: `coin::balance<AptosCoin>(operator1_address)` (or its beneficiary) is **less than** `expected_commission_1` grown purely by stake-pool rewards (i.e., less than `with_rewards(expected_commission_1)`), while `operator2_address` receives the difference — demonstrating the old operator's exact pre-switch commission share was not preserved.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Allows staker to switch operator without going through the lenghthy process to unstake.
    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
