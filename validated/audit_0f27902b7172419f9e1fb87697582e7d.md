### Title
Stale confirmations from removed members allow FunctionCall/Transfer actions to execute below the live `num_confirmations` threshold - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges pending requests that were *authored* by the removed member; it never scans other requests' `confirmations` sets to strip the removed member's identity string from votes it cast on requests it did not author. Because `confirm()` counts raw entries in the `HashSet<String>` rather than intersecting them with the current `self.members` set, a request can reach `num_confirmations` and execute (including a `FunctionCall` with an attached deposit) with fewer *live* member approvals than the threshold requires.

### Finding Description
The binding that should hold is:
`confirmations.get(&request_id).len() == |{ m ∈ confirmations.get(&request_id) : m ∈ self.members }|`
i.e. every string recorded in a request's confirmation set must correspond to a currently-active member. This binding is violated after a `DeleteMember` action executes.

`confirm()` blindly trusts the raw confirmation count: [1](#0-0) 

`delete_member` removes the deleted member from `self.members`, and cleans up only requests where `r.member == member` (i.e., requests the removed member originally *added*), but does nothing to any other request's `confirmations` set that may still contain that member's identity string from a prior `confirm()` call: [2](#0-1) 

`current_member()` and `assert_valid_request()` only validate the *caller* of the current transaction against `self.members`; they never re-validate the *stored* confirmation strings belonging to other, already-departed members: [3](#0-2) 

Exploit flow:
1. Members `A, B, C, D` exist, `num_confirmations = 3`.
2. `B` calls `add_request` with `R1 = FunctionCall { deposit: X, receiver: attacker_contract, ... }` (or `Transfer`). `A` and `B` each call `confirm(R1)` → `confirmations(R1) = {A, B}` (2 of 3, not yet executable).
3. Independently, members push through `R2 = DeleteMember { member: A }` with 3 confirmations from `B, C, D`; it executes and removes `A` from `self.members`. `delete_member` only cleans requests authored by `A`; `R1` was authored by `B`, so `confirmations(R1)` still contains the string for `A`.
4. `C` calls `confirm(R1)`. `confirmations(R1).len() + 1 == 3 >= num_confirmations`, so `execute_request(R1)` fires — the `FunctionCall` deposit is sent to the attacker's contract even though only `B` and `C` are actually live members who approved it; `A`'s stale vote fills the gap left by a member the multisig itself removed.

Existing guards (`assert_valid_request`, `current_member`, `assert_self_request`, `assert_one_action_only`) all check the *caller*, never the *stored confirmer set*, so none of them catch this divergence.

### Impact Explanation
NEAR (the attached `deposit`) leaves the multisig account and reaches a receiver/method chosen by the request, having been approved by fewer live members than `num_confirmations` mandates. This matches the explicitly Critical category "a multisig request executed below `num_confirmations` live members" — the multisig's core security guarantee (k-of-n live approval before funds move) is broken. The bug is repeatable for every pending request that received a confirmation from a member later removed by `DeleteMember`, and applies to any action type executed via `execute_request` (Transfer, FunctionCall with deposit, AddKey, etc.), not just FunctionCall.

### Likelihood Explanation
Exploitation requires only ordinary, expected multisig operation: a pending request partially confirmed, followed by any subsequent `DeleteMember` execution (a routine key-rotation/offboarding action), followed by one more `confirm()` call from a still-active member. No special privileges beyond normal member status are needed to trigger the stale-count effect, and no code path currently invalidates or re-checks old confirmations against the current member set. This is a systemic design gap, not a rare edge case—any multisig that removes a member while other requests are mid-confirmation is exposed.

### Recommendation
When executing a `DeleteMember` action, iterate all pending requests' `confirmations` sets and strip the removed member's identity string (`member.to_string()`), not just requests they authored. Alternatively, change `confirm()`/`execute_request()` to compute the confirmation count as the intersection of stored confirmations with `self.members` at execution time, ensuring only live members' approvals count toward `num_confirmations`.

            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }

    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    /// Add member to the list. Adds access key if member is key based.
    fn add_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        self.members.insert(&member.clone().into());
        match member {
            MultisigMember::AccessKey { public_key } => promise.add_access_key(
                public_key.into(),
                DEFAULT_ALLOWANCE,
                env::current_account_id(),
                MULTISIG_METHOD_NAMES.to_string(),
            ),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }

    /// Prevents access to calling requests and make sure request_id is valid - used in delete and confirm
    fn assert_valid_request(&mut self, request_id: RequestId) {
        // request must come from key added to contract account
        assert(
            self.current_member().is_some(),
            "Caller (predecessor or signer) is not a member of this multisig",
        );
        // request must exist
        assert(
            self.requests.get(&request_id).is_some(),
            "No such request: either wrong number or already confirmed",
        );
        // request must have
        assert(
            self.confirmations.get(&request_id).is_some(),
            "Internal error: confirmations mismatch requests",
        );
    }
