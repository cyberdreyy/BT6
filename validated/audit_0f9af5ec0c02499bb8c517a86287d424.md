### Title
Zip artifact extraction allows path traversal (Zip Slip) - ([File: helpers/archives/zip_extract.go])

### Summary
Artifacts downloaded between jobs (triggered from `shells/abstract.go: downloadArtifacts` via the `gitlab-runner-helper artifacts-downloader` subcommand) are extracted using `archive.NewExtractor`, which for the `zip` format resolves to `ziplegacy.extractor.Extract` and ultimately `archives.ExtractZipArchive`. This function writes files using the raw `zip.File.Name` value with no path sanitization or containment check against the extraction root, unlike the `tarzstd` extractor which validates entries stay inside the target directory. An attacker controlling artifact content in an earlier job can therefore embed `../` traversal segments in zip entry names and, when a downstream job downloads that artifact, write/overwrite files outside the downstream job's root.

### Finding Description
`ArtifactsDownloaderCommand.Execute` (invoked as a result of `downloadArtifacts` shell-generated commands in `shells/abstract.go`) downloads the artifacts archive and calls: [1](#0-0) 

For the `zip` format, `archive.NewExtractor` dispatches to the registered extractor function, which for zip resolves to `ziplegacy.NewExtractor`: [2](#0-1) 

That extractor delegates directly to `archives.ExtractZipArchive`, which iterates zip entries and calls `extractZipFile(file)` using `file.Name` verbatim — it is never joined with, or validated against, the extraction root directory: [3](#0-2) 

`extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry` all use `file.Name` as an absolute/relative filesystem path with no `filepath.Abs`/prefix check: [4](#0-3) 

Contrast this with the `tarzstd` extractor, which does compute `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any resulting path that escapes `e.dir`: [5](#0-4) 

The only extra check applied to zip entries is `errorIfGitDirectory`, which only guards against `.git` as the first path segment and is not a path-containment check: [6](#0-5) 

Because zip entry names are fully attacker-controlled artifact metadata (an earlier, unprivileged pipeline job can produce/upload an artifact zip with crafted entry names such as `../../outside/file` or absolute paths, or symlink entries pointing outside the root via `extractZipSymlinkEntry`), a downstream job that downloads and extracts this artifact will write those files relative to its current working directory without containment, allowing escape from the intended job root.

### Impact Explanation
An attacker who controls an earlier job's artifact contents (a normal pipeline author) can produce a malicious zip artifact that, when extracted by a later job (`downloadArtifacts`/dependencies), writes or overwrites files outside the downstream job's assigned root — e.g., overwriting git config, build scripts, cached state, or other files elsewhere in the build directory tree on the runner host/container. This can lead to code execution in a later — potentially protected-ref — job, or tampering with cross-job state on shared executors (shell executor, or docker/kubernetes executors that share a builds volume), matching the "protected-ref escalation or cross-job state tampering via path-root escape" impact.

### Likelihood Explanation
This is directly reachable by any unprivileged user who can define a job that produces an artifact (`artifacts:paths`) and control its contents (trivial: create a zip with crafted entry names via any archiving tool or by uploading a raw zip through the artifacts API) and have another job (in the same or a dependent pipeline) download it via `dependencies`/`needs`. No special privilege beyond normal pipeline authorship is required, and the missing check is a straightforward code path with no other mitigating validation in `ExtractZipArchive`. This is a classic and previously well-known "Zip Slip" class bug, elevating likelihood/feasibility.

### Recommendation
Apply the same containment check used in `tarzstd_extractor.go` to all zip extraction paths: resolve each entry's target path with `filepath.Join(dir, cleanedName)`, take `filepath.Abs`, and verify it has `dir` as a strict prefix (or is `dir` itself) before creating directories/files/symlinks; reject and abort on violation. Also validate/reject symlink targets (`extractZipSymlinkEntry`) that resolve outside the target directory, and reject absolute paths in `file.Name`.

### Proof of Concept
Go unit test targeting `helpers/archives/zip_extract.go`:
1. Create an `archive/zip.Writer` in memory with an entry named `../../pwned.txt` (and one with `../../evil_symlink` pointing outside as `os.ModeSymlink`).
2. `chdir` into a temp directory representing the "downstream job root" (e.g., `t.TempDir()/root`), and call `archives.ExtractZipArchive(zipReader)`.
3. Assert that `../../pwned.txt` (relative to `root`, i.e., outside of it) was NOT created, and that all files extracted are contained within `root`.
4. Expected current (buggy) behavior: `pwned.txt` and/or the symlink are created outside `root`, proving the escape. After the fix, `ExtractZipArchive` should return an error and no file should exist outside `root`.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
