### Title
Withdraw-disable flags from `emergencyShutdown`/`_handleBorrowerDefault` are not enforced in `IdleCDOEthenaVariant._withdraw` - (File: contracts/IdleCDOEthenaVariant.sol)

### Summary
The base `IdleCDO` uses the `allowAAWithdraw` / `allowBBWithdraw` flags as the withdrawal kill-switch: `_emergencyShutdown` sets `allowBBWithdraw = false` (and optionally AA) to freeze redemptions while losses are crystallized [1](#0-0) . `IdleCDOEthenaVariant` fully overrides `_withdraw` to implement the sUSDe cooldown flow and never consults `allowAAWithdraw`/`allowBBWithdraw` or the paused flag — it only checks `cooldownDuration() != 0`, the same-block guard, and `_checkDefault()` [2](#0-1) . This mirrors the reported bug class: an admin-set redemption pause is trivially circumvented because one redeem path does not enforce it.

### Finding Description
In `IdleCDO`, `emergencyShutdown()` and the epoch-variant `_emergencyShutdown`/`_handleBorrowerDefault` freeze withdrawals by clearing `allowBBWithdraw`/`allowAAWithdraw` (and pausing) [1](#0-0) [3](#0-2) . The Ethena variant's `_withdraw` override replaces the base implementation wholesale — it computes `toRedeem` from the current tranche price, burns the caller's tranche tokens, updates `lastNAVAA`/`lastNAVBB`, and ships sUSDe into a fresh `EthenaCooldownRequest` clone — without any `allowAAWithdraw`/`allowBBWithdraw`/`WithdrawNotAllowed` check [4](#0-3) . Any unprivileged AA or BB tranche holder can therefore call `withdrawAA`/`withdrawBB` after the guardian has emergency-shut the pool down, exactly the "pause not enforced in an alternate redeem path" pattern of the Illuminate finding.

### Impact Explanation
The emergency shutdown exists so that withdrawals stop while a loss/default is being handled (so remaining LPs share losses pro-rata under the BB-first waterfall). A holder who front-runs via this path exits at the pre-crystallization `virtualPrice`, draining sUSDe/underlying ahead of other claimants; their avoided loss is socialized onto the remaining AA/BB holders who can no longer exit, and `lastNAV` bookkeeping is decremented mid-shutdown, corrupting the subsequent forced accounting. Loss equals the withdrawn NAV that should have been frozen and haircut.

### Likelihood Explanation
Requires only that the vault is in (or enters) `emergencyShutdown`/default state while `cooldownDuration() != 0` on sUSDe — an ordinary operating state for this variant. Any tranche holder (unprivileged) can trigger it with a single `withdrawBB`/`withdrawAA` call; no privileged collusion is needed.

### Recommendation
Add the `allowAAWithdraw`/`allowBBWithdraw` checks (and/or `whenNotPaused` semantics consistent with the base class) at the top of `IdleCDOEthenaVariant._withdraw`, mirroring the guards in `IdleCDO._withdraw`, so emergency and default shutdowns actually freeze redemptions.

### Proof of Concept
Foundry fork sketch: deploy/attach the Ethena-variant CDO with sUSDe cooldowns enabled; deposit AA and BB; owner calls `emergencyShutdown()` (sets `allowBBWithdraw = false`, pauses); a BB holder calls `withdrawBB(0)` — expected: revert `WithdrawNotAllowed`, actual: succeeds, tranche tokens burned and sUSDe streamed into the user's `EthenaCooldownRequest` clone [5](#0-4) .

Caveat: I could not re-verify in this pass whether the flag checks in `IdleCDO` live inside `withdrawAA`/`withdrawBB` wrappers (which would still block this path) rather than inside `_withdraw`. The `IdleCDOBestYieldVariant` comment — "this flag doesn't work when not paused… not necessary because `_withdrawAA()` is disabled" [6](#0-5)  — suggests the checks are part of the internal withdraw flow the Ethena override replaces, supporting the finding; a definitive check of `IdleCDO.sol`'s `withdrawAA`/`_withdraw` bodies is needed to confirm no wrapper-level guard exists.

```text
  function _withdraw(uint256 _amount, address _tranche) override internal nonReentrant returns (uint256 toRedeem) {
    // if no cooldown is set we can use the normal path
    // if (IStakedUSDeV2(strategyToken).cooldownDuration() == 0) {
    //   return super._withdraw(_amount, _tranche);
    // }
    require(IStakedUSDeV2(strategyToken).cooldownDuration() != 0, '9');
    // we send susde to a contract, one for each cooldown request,
    // created on the fly for the user as multiple cooldowns cannot be managed 
    // by the same contract

    // check if a deposit is made in the same block from the same user
    _checkSameBlock();
    // check if _strategyPrice decreased
    _checkDefault();
    // accrue interest to tranches and updates tranche prices
    _updateAccounting();
    // redeem all user balance if 0 is passed as _amount
    if (_amount == 0) {
      _amount = IERC20Detailed(_tranche).balanceOf(msg.sender);
    }
    require(_amount != 0, '0');
    // Calculate the amount of USDe that the user can redeem
    toRedeem = _amount * _tranchePrice(_tranche) / ONE_TRANCHE_TOKEN;
    // Get amount of SUSDe
    uint256 SUSDeRedeemed = toRedeem * ONE_TRANCHE_TOKEN / _strategyPrice();

    // burn tranche token
    IdleCDOTranche(_tranche).burn(msg.sender, _amount);

    // update NAV with the _amount of underlyings removed
    if (_tranche == AATranche) {
      lastNAVAA -= toRedeem;
    } else {
      lastNAVBB -= toRedeem;
    }

    // update trancheAPRSplitRatio
    _updateSplitRatio(_getAARatio(true));

    // Create a contract for this cooldown request, passing address(this) and msg.sender as args
    EthenaCooldownRequest clone = EthenaCooldownRequest(cooldownImpl.clone(
      abi.encodePacked(address(this), msg.sender), 
      msg.value
    ));
    // Send requested SUSDe to the new contract
    IERC20Detailed(strategyToken).safeTransfer(address(clone), SUSDeRedeemed);
    // Start the cooldown
    clone.startCooldown();
```

```text
  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
  }
```
