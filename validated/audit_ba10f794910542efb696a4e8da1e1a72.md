## Title
Confirmations from removed multisig members remain counted toward the execution threshold, allowing requests to execute below the live-member quorum - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` decides whether to execute a pending request purely by comparing the *size* of the stored `confirmations` set against `num_confirmations`. `delete_member` only purges confirmations/requests that the removed member themselves *created* — it never scrubs confirmations that removed member cast on requests created by other members. A confirmation recorded by a member who is later removed therefore keeps counting toward the threshold forever, letting a request execute with fewer live, currently-authorized confirmers than `num_confirmations` actually requires.

### Finding Description
The binding the contract is supposed to maintain is:

```
confirmations counted for request R == confirmations from accounts that are CURRENTLY members
```

`confirm()` only checks the raw set size: [1](#0-0) 

`delete_member()` removes stale requests/confirmations *only* for the request(s) originated by the removed member: [2](#0-1) 

Nothing else purges a departing member's confirmation entries from other members' pending requests, and `confirm()`/`remove_request()` never re-validate that every string in the `confirmations: HashSet<String>` still corresponds to a live `MultisigMember`: [3](#0-2) 

Consequence: a confirmation cast by a member before their removal is never invalidated when the member is later removed via a separate `DeleteMember` request (itself an authorized multisig action). The stale confirmation permanently inflates the count for any request that member touched before being removed.

### Impact Explanation
This breaks the equality that the multisig is meant to enforce: `confirmations counted == confirmations from live members`. Concretely:
- Members `A, B, C, D`, `num_confirmations = 3`.
- `A` creates request `R` (e.g. `Transfer`). `D` confirms it (1/3).
- The group separately removes `D` (e.g. because the key was compromised or the employee departed) via a `DeleteMember` request that reaches 3 confirmations from `A, B, C`. `delete_member` only cleans up requests *created by* `D`, so `R`'s confirmation set still contains `D`.
- Now only `A, B, C` are members, but `R` still shows `D`'s stale confirmation.
- `A` and `B` confirm `R`. `confirmations.len() + 1 = 3 >= num_confirmations (3)` → `R` executes, even though `C` (the third live member) never approved it.

This is a request executed below the intended live threshold — funds move (or keys/members are changed) with fewer authorized live approvals than `num_confirmations` mandates, matching the Critical impact category "a multisig request executed below threshold."

### Likelihood Explanation
No special privilege beyond being (or having been) an ordinary multisig member is required, and member turnover (revoking a compromised/departing signer's access) is a normal, expected multisig operation. Any time a member is removed after having confirmed but not triggered execution of an outstanding request, that stale confirmation persists indefinitely and can later combine with fewer live confirmations to reach the threshold.

### Recommendation
When executing `confirm()` (and in `remove_request`), only count confirmations whose entry still corresponds to a current member of `self.members`. Additionally, `delete_member` should scrub the removed member's entry from every request's confirmation set (not only requests they created), e.g. by iterating `self.confirmations` and removing the member's key wherever present.

### Proof of Concept
1. Deploy `MultiSigContract::new([A, B, C, D], 3)`.
2. `A` calls `add_request(Transfer{...})` → `request_id = R`.
3. `D` calls `confirm(R)` → confirmations = `{D}` (1/3).
4. Members submit and confirm a `DeleteMember{member: D}` request with `A, B, C` (3/3) → `D` removed; members are now `{A, B, C}`.
5. `A` calls `confirm(R)` → confirmations = `{D, A}` (2/3).
6. `B` calls `confirm(R)` → `confirmations.len() + 1 == 3 >= num_confirmations (3)` → `execute_request(R)` fires the `Transfer`, even though `C` never confirmed and `D` is no longer a member. [1](#0-0) [2](#0-1)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
