### Title
Zip Slip in `ziplegacy` cache/artifact extractor allows writing files outside the job working directory - ([File: helpers/archives/zip_extract.go])

### Summary
`ziplegacy.extractor.Extract` discards the `dir` argument it receives from `archive.NewExtractor` and instead calls `archives.ExtractZipArchive`, which extracts every `zip.File.Name` using `os.MkdirAll`/`os.OpenFile` directly on the raw, attacker-controlled name with no path containment check. Unlike `tarzstd`, which validates each resolved path against `e.dir+string(filepath.Separator)`, the zip path has no such guard, so a cache archive with `../` or absolute paths in entry names writes outside the job root.

### Finding Description
`CacheExtractorCommand.Execute` computes the job working directory (`wd`) and passes it into `archive.NewExtractor(format, f, size, wd)` [1](#0-0) . For the zip format this resolves to `ziplegacy.NewExtractor`, which stores `dir` on the `extractor` struct but the `Extract` method never uses `e.dir` — it just builds a `zip.Reader` and calls `archives.ExtractZipArchive(zr)` [2](#0-1) .

`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry, only checking `errorIfGitDirectory(file.Name)` (which merely blocks a leading `.git` path segment) [3](#0-2) [4](#0-3) . `extractZipFile` then does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and, via `extractZipFileEntry`, `os.OpenFile(file.Name, ...)` using the raw entry name as-is, relative to the process's current working directory [5](#0-4) .

Contrast this with `tarzstd_extractor.go`, which resolves each entry with `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path that doesn't have `e.dir` as prefix [6](#0-5) . No equivalent join/containment check exists anywhere in the zip legacy extraction path. Because the cache zip file is downloaded from a URL under job/pipeline control (`CacheExtractorCommand.download`) and then opened with `archive.NewExtractor(archive.Zip, ...)` before calling `.Extract()`, an attacker who controls the cache blob content (e.g., poisoning cache upload from their own pipeline, or via a MITM'd/misconfigured cache store reachable by the pipeline) can embed entries such as `../../poison` to write files outside the job's working directory.

### Impact Explanation
A crafted cache (or artifact, since the same `ziplegacy`/`archives.ExtractZipArchive` path is used for artifact extraction via `archive.NewExtractor`) zip can overwrite or create arbitrary files reachable by relative-path traversal from the runner's current working directory at extraction time, up to the permissions of the job process. On shared runner hosts this enables cross-job or cross-project file poisoning (e.g., overwriting files in sibling build directories, or planting files that a later job/step trusts), matching the scoped impact of unauthorized file write/overwrite outside job root.

### Likelihood Explanation
The path is reachable through the normal cache-extraction flow (`gitlab-runner cache-extractor`) used automatically by every job with `cache:` configured, and no special permissions are needed beyond controlling the cache content (uploaded by an earlier job in the same pipeline/project, or from a shared/misconfigured cache backend). The bug is deterministic: the `dir` parameter is provably unused in `ziplegacy.extractor.Extract`, and there is no other containment check in `ExtractZipArchive`/`extractZipFile`, so any zip with `../` entries reliably escapes.

### Recommendation
Thread `dir` through `ziplegacy.extractor.Extract` into `archives.ExtractZipArchive`/`extractZipFile`, resolving each entry as `filepath.Abs(filepath.Join(dir, file.Name))` and rejecting any resolved path that is not prefixed by `dir+string(filepath.Separator)` (mirroring the check already implemented in `commands/helpers/archive/tarzstd/tarzstd_extractor.go`). Apply the same fix consistently to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, and `extractZipFileEntry` so symlink targets/directories are equally confined.

### Proof of Concept
Go unit test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpDir := t.TempDir()
    outsideMarker := filepath.Join(filepath.Dir(tmpDir), "poison")
    defer os.Remove(outsideMarker)

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    f, _ := zw.Create("../poison")
    _, _ = f.Write([]byte("pwned"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    _ = os.Chdir(tmpDir)
    defer os.Chdir(wd)

    err := ExtractZipArchive(zr)
    assert.Error(t, err, "extraction should be confined and reject '../' entries")
    _, statErr := os.Stat(outsideMarker)
    assert.True(t, os.IsNotExist(statErr), "file must not be written outside extraction root")
}
```
Expected current behavior: the test fails (no error returned, `poison` file created outside `tmpDir`), demonstrating the missing containment check compared to `tarzstd`'s equivalent test coverage.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

func ExtractZipArchive(archive *zip.Reader) error {
