### Title
Staking while paused inflates `total_staked_balance` without any on-chain stake action - (File: `staking-pool/src/internal.rs`)

### Summary
`internal_stake` unconditionally increments `self.total_staked_balance` and mints stake shares for the caller regardless of the `paused` flag. `internal_restake`, the only function gated on `paused`, simply returns early when `paused == true`, so the `Promise::new(...).stake(...)` action that would actually lock NEAR on the validator account is never issued. This lets any unprivileged account call `stake`/`stake_all`/`deposit_and_stake` while the pool is paused and grow `total_staked_balance` without a corresponding increase in `env::account_locked_balance()`.

### Finding Description
The invariant being tested is:
`total_staked_balance == env::account_locked_balance()` (whenever the contract is not mid-restake).

Tracing the call path for `stake(amount)` (and `deposit_and_stake`/`stake_all`):
1. `internal_ping` runs first, distributing rewards based on `account_locked_balance() + account_balance() - attached_deposit()` vs `last_total_balance` [1](#0-0) . This is orthogonal to the pause bug and does not check `paused`.
2. `internal_stake(amount)` is called. It computes `num_shares`, `charge_amount`, deducts `account.unstaked`, and then unconditionally does:
```
self.total_staked_balance += stake_amount;
self.total_stake_shares += num_shares;
``` [2](#0-1) 
There is no check of `self.paused` anywhere inside `internal_stake`.
3. Only afterward does the entrypoint call `internal_restake()`, which is the sole gate on `paused`:
```
pub(crate) fn internal_restake(&mut self) {
    if self.paused {
        return;
    }
    Promise::new(env::current_account_id())
        .stake(self.total_staked_balance, self.stake_public_key.clone())
        ...
}
``` [3](#0-2) 
When `paused == true`, this function returns immediately — no `Promise::stake` action is scheduled, so `env::account_locked_balance()` never changes.

Root cause: the accounting mutation (`total_staked_balance += stake_amount`) in `internal_stake` and the actual on-chain staking action in `internal_restake` are decoupled, and only the latter checks `paused`. None of the standard guards (`assert_owner`, `is_promise_success`, `assert_one_yocto`, etc.) apply to `stake`/`deposit_and_stake`, which are explicitly open to any account. The attacker's exact call: as any account with an `unstaked` balance (or via `deposit_and_stake` with an attached deposit) on a pool where the owner has set `paused = true` (a legitimate, ownerless-triggerable pool state that can persist across many blocks — e.g. during key rotation or maintenance), call `stake(amount)` repeatedly. Each call increases `total_staked_balance` and mints the caller `stake_shares` while `account_locked_balance()` remains unchanged, since `internal_restake` no-ops.

With `reward_fee_fraction` at zero, `internal_ping`'s subsequent reward distribution logic (owner fee splitting) does not mask or self-correct the divergence — the extra "phantom" staked balance is attributed entirely to the depositor's shares at a share price computed against an inflated `total_staked_balance` that no longer reflects real locked NEAR, so the share price itself becomes wrong for every future staker/unstaker in the pool.

### Impact Explanation
Every unprivileged account can call `stake` while the pool is paused to mint shares that are backed by nothing beyond their own already-attached/deposited-but-unstaked NEAR being reclassified from `account.unstaked` into `account.stake_shares`/`total_staked_balance`, while `total_staked_balance` no longer matches `env::account_locked_balance()`. This breaks the core pool invariant relied upon by `num_shares_from_staked_amount_rounded_down`/`staked_amount_from_num_shares_rounded_down` (share price = `total_staked_balance / total_stake_shares`), corrupting the share price for all subsequent stakers and unstakers in the pool — an accounting divergence that other delegators/the owner will settle on when computing rewards, unstaking, or withdrawing. This matches the "High" impact category: accounting value diverges from reality and another party settles on it. It is repeatable indefinitely across accounts and epochs as long as `paused` remains true.

### Likelihood Explanation
Preconditions: the pool must be `paused` (owner-set state, but attacker does not need to be the owner — they just need the pool to be in this state, which can happen during routine maintenance/key rotation) and the attacker needs any nonzero `unstaked` balance or an attached deposit via `deposit_and_stake`. There is no role requirement on `stake`/`stake_all`/`deposit_and_stake`. Cost is trivial (one transaction, minimal deposit), and the exploit is fully repeatable by any number of accounts for as long as the pool stays paused.

### Recommendation
Add an explicit `assert!(!self.paused, "Staking is paused")` (or equivalent) at the top of `internal_stake` (and symmetrically consider `inner_unstake`) so that share/balance accounting cannot be mutated while the contract is not actually staking on-chain, keeping `total_staked_balance` and `env::account_locked_balance()` in lockstep whenever the pool is paused.

### Proof of Concept
Using `near-sdk-sim`/`testing_env!`:
1. Deploy staking pool contract, set `reward_fee_fraction` numerator = 0.
2. As owner, call `pause()` (or set `self.paused = true` via the exposed owner method) so `paused == true`.
3. As an attacker account, call `deposit_and_stake()` with attached deposit `X` (or `deposit()` then `stake(X)`).
4. Assert: `contract.total_staked_balance` increased by `X` (minus rounding), while `env::account_locked_balance()` (mocked/tracked in the sim context) remains unchanged (0 or its prior value).
5. Explicit binding check: before the call, `total_staked_balance_before == account_locked_balance_before`; after the call, `total_staked_balance_after = total_staked_balance_before + X > account_locked_balance_after == account_locked_balance_before`, proving the invariant `total_staked_balance <= account_locked_balance` is violated outside of any mid-restake promise.
6. Confirm `internal_restake` was never invoked with an actual `Promise::stake` action by checking no logs/receipts for `stake` action were generated (since `paused` short-circuits it) — `internal_restake`'s early return at [4](#0-3)  confirms this at the code level.

        if self.last_epoch_height == epoch_height {
            return false;
        }

        // New total amount (both locked and unlocked balances).

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
