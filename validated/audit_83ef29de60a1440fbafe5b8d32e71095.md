Confirmed: `rescueFunds` is gated by `onlyCaller(immutables.taker.get())` [1](#0-0) , meaning only the original resolver/taker can ever reclaim funds, even after `RESCUE_DELAY`. There is no permissionless rescue path.

### Title
Dust safety deposits let an unprivileged maker create escrows nobody is economically incentivized to publicly withdraw/cancel, causing temporary freezing of swap funds - (File: contracts/BaseEscrowFactory.sol, contracts/BaseEscrow.sol)

### Summary
The `safetyDeposit` value that funds the public-withdraw/public-cancel incentive for `EscrowSrc`/`EscrowDst` is taken verbatim from `extraDataArgs.deposits`, packed into the signed order extension, with no protocol-enforced minimum [2](#0-1) . This is the same root cause as the Perpetual `LibLiquidation.getPenalty()` bug: an economic incentive fee is proportional to a value fully controllable by an unprivileged party, with no floor, so it can be driven low enough that it no longer covers the gas cost of the third-party action it's meant to incentivize.

### Finding Description
A maker constructs and signs a Fusion order together with its extension (which must hash-match the order salt per Limit Order Protocol rules), embedding `extraDataArgs.deposits` — the packed src/dst safety deposits [2](#0-1) . Nothing in `_postInteraction` or `createDstEscrow` enforces a minimum safety deposit relative to `makingAmount`/`amount` or to realistic L2 gas costs [3](#0-2) .

`publicWithdraw`/`publicCancel` are only callable by any access-token holder, whose sole compensation is `immutables.safetyDeposit` sent via `_ethTransfer(msg.sender, immutables.safetyDeposit)` [4](#0-3) [5](#0-4) . If that deposit is set to zero or dust, no rational third party will call these functions once the originally-assigned taker becomes unresponsive (crashes, goes offline, or simply refuses after private-period expiry).

Crucially, once the private window and public window both fail to produce a caller, the only remaining exit is `rescueFunds`, but it is restricted to `onlyCaller(immutables.taker.get())` [6](#0-5)  — there is no permissionless rescue path even after `RESCUE_DELAY`. This is stricter than the Perpetual analog (where liquidation could still eventually happen, just unprofitably); here the funds can become durably stuck if the specific taker never returns.

### Impact Explanation
This matches the "temporary freezing of funds during the live swap lifecycle" High-impact category: the maker's tokens in `EscrowSrc` and the resolver's tokens in `EscrowDst` remain locked past all timelock windows because no unprivileged actor has sufficient economic incentive to trigger `publicWithdraw`/`publicCancel`, and the permissioned `rescueFunds` cannot help if the taker is gone.

### Likelihood Explanation
Low-to-medium. Triggering it requires: (1) a maker who signs an order with a dust `safetyDeposit` in the extension (technically feasible for anyone constructing their own order/extension since only the extension hash needs to match the order salt), and (2) the originally-filling taker becoming unresponsive during the private window. Absent a resolver failure, escrows are always resolved by the private-window taker economically, so this only manifests as an edge case — similar to how the Perpetual report's sponsor/judges treated it as Medium rather than High/Critical, citing feasibility concerns balanced against the fact that it can also occur organically (e.g., a resolver crashing on a low-value order) rather than only via deliberate attack.

### Recommendation
- Enforce a protocol-level minimum `safetyDeposit` (absolute or proportional to `makingAmount`/`amount`) in `_postInteraction` and `createDstEscrow`, reverting if it falls below a floor calibrated to expected L2 gas costs.
- Consider making `rescueFunds` callable by any access-token holder (not only the original `taker`) after `RESCUE_DELAY`, so dust-safety-deposit escrows are not permanently dependent on a single potentially-unresponsive address.

### Proof of Concept
1. Maker signs a Fusion order + extension where `extraDataArgs.deposits` packs `srcSafetyDeposit = 1 wei` and `dstSafetyDeposit = 1 wei`.
2. Resolver A fills the order; `EscrowSrc`/`EscrowDst` are deployed with `safetyDeposit = 1` each [7](#0-6) .
3. Resolver A does not call `withdraw` in the private window (e.g., process crash).
4. Public window opens; any access-token holder could call `EscrowDst.publicWithdraw` / `EscrowSrc.publicWithdraw` / `publicCancel`, but the 1-wei `_ethTransfer(msg.sender, immutables.safetyDeposit)` payout [5](#0-4)  is far below gas cost, so nobody calls it.
5. `rescueFunds` remains restricted to Resolver A (`onlyCaller(immutables.taker.get())`) [1](#0-0) , who is unresponsive — funds stay locked indefinitely.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
