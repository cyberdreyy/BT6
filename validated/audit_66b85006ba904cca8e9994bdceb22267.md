This resolves the question definitively. The `Destroy` route is protected: `sessionRoutes` registers `auth.DELETE("/sessions", sc.Destroy)` on a group wrapped with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [1](#0-0) . The session cookie itself is stored via `cookie.NewStore(secret)`, a cryptographically signed/encrypted gorilla-sessions cookie store keyed by a server-side secret from `app.SecretGenerator().Generate(config.RootDir())` [2](#0-1) . This means an attacker cannot simply write an arbitrary `sessionID` string into their own cookie value — the cookie store encodes/signs the entire session payload, so tampering with it (e.g., substituting another user's `sessionID`) invalidates the cookie signature and gin-contrib/sessions will fail to decode it, causing `session.Get(auth.SessionIDKey)` to return nothing.
