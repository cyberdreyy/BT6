## Analysis

The reported bug class — a value recorded/snapshotted at one point in the protocol state, then used later as if it were still valid without re-validating it against the current state — has a direct analog in `multisig2/src/lib.rs`: **stale confirmations from removed members are never purged and continue to count toward the K-of-N execution threshold.**

### Finding Description

`confirm()` counts confirmations purely by set size, without checking that each entry in the set is still a current member: [1](#0-0) 

`assert_valid_request()` only validates that the *caller* confirming right now is a live member; it never re-validates the *existing* entries already stored in `self.confirmations`: [2](#0-1) 

When a member is removed via `DeleteMember`, `delete_member()` only deletes requests that member *created* (`r.member == member`). It never scans `self.confirmations` to strip that member's stale confirmations from requests created by *other* members: [3](#0-2) 

Because `self.confirmations` is a `LookupMap<RequestId, HashSet<String>>` keyed by member string, and is never pruned on member removal (except for the removed member's own authored requests), a confirmation cast by a member who is later removed remains permanently counted for any pending request authored by someone else.

### Impact Explanation

This breaks the core custody binding of the multisig: **"confirmations counted" should equal "confirmations from currently live members,"** i.e. `len(live confirmers) >= num_confirmations`. With this bug, `len(live confirmers) + len(stale confirmers) >= num_confirmations` is what's actually enforced. A request (e.g. `Transfer`) can therefore execute with fewer live-member confirmations than the configured threshold — a multisig request executed below threshold, which the scope rules explicitly classify as Critical impact (funds moved by a party — or fewer parties — not entitled to authorize it).

### Likelihood Explanation

This requires no privileged foundation/owner action beyond normal multisig member operations (creating requests, confirming, and removing a member) — all of which are standard, expected multisig member actions. Any sequence where a member confirms a request that is not later cleaned up before that member is removed reproduces the bug.

### Proof of Concept

Members = {A, B, C}, `num_confirmations = 2`.

1. B calls `add_request(R)` where `R = Transfer { amount, receiver_id: attacker }` (B does **not** confirm, so `confirmations[R] = {}`).
2. A calls `confirm(R)` → `confirmations[R] = {A}` (1 < 2, not executed). [4](#0-3) 
3. B and C jointly pass a self-request `DeleteMember { member: A }` (2 confirmations, meets threshold `3-1=2 >= num_confirmations=2`), executing `delete_member(A)`. This removes A from `self.members` and deletes only requests *created* by A — `R` (created by B) is untouched, and `confirmations[R] = {A}` remains in storage. [3](#0-2) 
4. Members are now {B, C}. C calls `confirm(R)`. `assert_valid_request` passes (C is a live member). `confirmations[R].len() (=1, stale A) + 1 (C) = 2 >= num_confirmations (2)` → **`R` executes**, transferring funds to `attacker`. [5](#0-4) 

Only **one live member (C)** actually authorized the transfer at execution time (B merely created it without confirming) — the K=2 threshold was satisfied only because a removed member's stale confirmation was still counted.

### Recommendation

When a member is removed (`delete_member`), iterate all requests' confirmation sets and remove entries matching the deleted member's identity string, or alternatively, at `confirm()` time re-validate every entry in `confirmations` against `self.members` before comparing the count to `num_confirmations`, discarding stale entries.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
