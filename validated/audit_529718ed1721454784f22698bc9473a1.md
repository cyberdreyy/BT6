### Title
Missing Absolute Staleness Check in `MetaOracle.combine()` Allows Arbitrarily Old Prices to Pass Time-Window Filter — (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

The `MetaOracle` module in the Sui oracle framework filters aggregated oracle data using a relative time window (`max_timestamp - time_window_ms`) but never validates data freshness against the current block time. If all contributing `SimpleOracle` instances stop updating, `MetaOracle.median()` will silently return prices from arbitrarily far in the past. A compounding bug in `add_simple_oracle()` overwrites `max_timestamp` with each oracle's timestamp instead of tracking the true maximum, making the time-window filter order-dependent and further weakening the staleness guard.

---

### Finding Description

**Root cause 1 — No absolute staleness check (direct M-13 analog)**

`MetaOracle` is constructed without a `Clock` reference and neither `add_simple_oracle()` nor `combine()` / `median()` ever receives one. [1](#0-0) 

`combine()` computes:
```move
let min_timestamp = max_timestamp - time_window_ms;
```
and accepts any oracle reading whose `timestamp > min_timestamp`. Because `max_timestamp` is derived entirely from the oracle data itself — not from `clock::timestamp_ms()` — the filter is purely relative. If every contributing oracle last updated two years ago but within `time_window_ms` of each other, all readings pass and `median()` returns a two-year-old price with no error.

This is the exact analog of the M-13 `if(timeStamp == 0)` check: the guard only tests internal consistency of the oracle data, not freshness relative to the current moment.

**Root cause 2 — `max_timestamp` overwrite instead of max-tracking** [2](#0-1) 

`add_simple_oracle()` unconditionally overwrites `max_timestamp` with the timestamp of the oracle just added (if it has data). It does not compare against the existing value. Consequently:

- If oracle A (ts = 1 000 000) is added first, then oracle B (ts = 500 000), `max_timestamp` becomes 500 000.
- `min_timestamp = 500 000 − time_window_ms`, which is lower than intended.
- Oracle A's reading (ts = 1 000 000) passes the filter even though it is outside the intended window relative to oracle B.

The result is that the effective time window is order-dependent and can be silently widened by the insertion order of oracles.

**Root cause 3 — `max_timestamp` initialised to 0** [3](#0-2) 

If every oracle returns `None` (no data for the ticker), `max_timestamp` stays 0. `combine()` then evaluates `0 − time_window_ms`, which underflows a `u64` and aborts the transaction — a secondary denial-of-service path reachable by any caller who invokes `median()` on a freshly created `MetaOracle` before any oracle has submitted data.

---

### Impact Explanation

Any on-chain protocol that imports `MetaOracle` and calls `median()` to obtain a trusted price — for collateral valuation, liquidation thresholds, settlement, or swap pricing — will silently consume stale prices whenever oracle operators stop updating. Because the framework module exposes no staleness guarantee, downstream protocols have no on-chain signal that the returned `TrustedData` is outdated. This matches the "harmful smart-contract behavior" impact class (High/Medium). [4](#0-3) 

---

### Likelihood Explanation

Oracle liveness failures are realistic: network partitions, operator key rotation, off-chain service outages, or deliberate griefing can all cause `SimpleOracle` objects to stop receiving `submit_data` calls. Any ordinary user (unprivileged caller) can then invoke `median()` on the stale `MetaOracle` and receive an outdated price that the framework presents as trusted. No privileged role is required to trigger the condition. [5](#0-4) 

---

### Recommendation

1. **Add an absolute staleness check.** Pass a `Clock` reference to `median()` (or `combine()`) and assert that `max_timestamp >= clock::timestamp_ms(clock) - max_staleness_ms` before returning data.

2. **Fix `max_timestamp` tracking.** Replace the unconditional overwrite in `add_simple_oracle()` with a conditional max:
   ```move
   let ts = data::timestamp(option::borrow(&oracle_data));
   if (ts > meta_oracle.max_timestamp) {
       meta_oracle.max_timestamp = ts;
   };
   ```

3. **Guard against underflow.** In `combine()`, check `max_timestamp >= time_window_ms` before computing `min_timestamp`, or use saturating subtraction.

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
