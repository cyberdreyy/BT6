### Title
Unprivileged ERC4626 vault user can inflate `totalInterestDueNow()` and get unbacked interest minted into tranche NAV - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
In programmable-borrower mode, `IdleCDOEpochVariant._stopEpoch` trusts `IProgrammableBorrower.totalInterestDueNow()` as the realized epoch interest. That value is computed in `ProgrammableBorrower._vaultNetInterest()` directly from `vault.convertToAssets(shares)` — a spot ERC4626 price that any unprivileged vault depositor can manipulate by donating underlying to the vault. In minted-interest mode (`isInterestMinted`), `_stopEpoch` pulls no cash for interest (`_amountToPullFromBorrower = 0`) and instead calls `IdleCreditVault.mintStrategyTokens(_grossInterest)`, creating unbacked pool NAV out of the phantom "interest". This is the direct analog of CVE-2024-45034: an unprivileged party (a DAG author / a vault user) injects content into a shared resource that a privileged executor (the scheduler / `stopEpoch`) then executes/trusts. The accounting executed by the manager-triggered epoch settlement is attacker-controlled.

### Finding Description
- `ProgrammableBorrower._vaultNetInterest()` (contracts/strategies/idle/ProgrammableBorrower.sol:337-347) computes epoch interest as `bufferedVaultDelta + (convertToAssets(shares) + epochWithdrawnFromVault) - (epochStartVaultAssets + epochDepositedToVault)`. The live `convertToAssets` term is fully attacker-malleable: any ERC4626 vault user can donate underlying directly to the vault (or use inflation-style share-price manipulation) between `epochStartVaultAssets` snapshot and the manager's `stopEpoch` call.
- `totalInterestDueNow()` (lines 330-334) returns that inflated delta plus borrower interest. `IdleCDOEpochVariant._resolveStopEpochInterest` (contracts/IdleCDOEpochVariant.sol:1001-1005) adopts it verbatim in programmable mode.
- In minted-interest mode `_stopEpoch` (contracts/IdleCDOEpochVariant.sol:373-433) sets `_amountToPullFromBorrower = 0`, so the phantom interest is never verified against real cash; it calls `_strategy.mintStrategyTokens(_grossInterest)` and mints fee shares via `_mintSharesAtCurrPrice`, inflating AA/BB tranche prices and `unclaimedFees` with value that does not exist.
- The only cap is `_checkNotAllowed(_maxApr != 0 && _grossInterest > _calcInterestWithApr(getContractValue(), _maxApr) + _pendingWithdrawFees)` (lines 377-380): it is a no-op when `maxApr == 0`, so a donation of size D mints ~D of unbacked interest.
- The donation cannot be recovered by the attacker only if the vault never returns it — but the attacker can also hold vault shares before donating, recapturing most of D at redemption while the inflated epoch accounting persists. Meanwhile the attacker, as a tranche-token holder, requests withdrawal at the inflated NAV and is paid from real principal pulled from the borrower at subsequent epochs (`_strategy.collectWithdrawFunds` at line 410 funds pending withdraws with real cash), draining other LPs. Alternatively, even without a vault position, a holder of a dominant tranche share profits because `mintStrategyTokens` raises `virtualPrice` for all holders while backing stays flat → pool insolvency.

### Impact Explanation
Direct theft / insolvency: phantom interest minted as strategy tokens permanently overstates `getContractValue()`, so early claimers (including the attacker's `requestWithdraw`/`claimWithdrawRequest` and instant-withdraw claims) redeem tranche tokens against real underlying that belongs to remaining LPs. Loss is quantifiable as approximately the donation size D net of the portion the attacker recaptures via vault shares and the fee split — profitable whenever the attacker's claim on the inflated NAV exceeds D. With `maxApr == 0`, D is uncapped.

### Likelihood Explanation
Requires programmable-borrower mode with `isInterestMinted == true` (the configuration exercised throughout `test/foundry/ProgrammableBorrowerCreditVault.t.sol`) and either `IdleCreditVault.maxApr == 0` or a donation below the APR cap — the cap also covers legitimate borrower interest, so it is weak even when set. The attacker needs no privileged role: donating underlying to a Morpho-style ERC4626 vault and holding tranche tokens are both permitted attacker actions. The only sequencing requirement is acting before the honest manager's scheduled `stopEpoch` — trivially satisfiable since `stopEpoch` requires `block.timestamp >= epochEndDate`, a publicly known window.

### Recommendation
Do not price epoch interest off a manipulable spot `convertToAssets`. Options: (a) enforce a nonzero `maxApr` cap unconditionally (remove the `maxApr != 0` escape so `_grossInterest` is always bounded by `_calcInterestWithApr(getContractValue(), _maxApr) + _pendingWithdrawFees`); (b) account vault PnL on shares redeemed, not on live valuation — e.g., compute interest from `epochWithdrawnFromVault` proceeds versus shares burned, or use a TWAP/locked price; (c) in minted mode, verify interest by pulling cash (or escrowing the delta) rather than minting unbacked strategy tokens.

### Proof of Concept
Reproducible in Foundry against the existing `ProgrammableBorrowerCreditVault.t.sol` harness (uses a mock/mintable ERC4626):

```solidity
// Setup: owner sets isInterestMinted=true; pool deposits, epoch starts.
// ProgrammableBorrower deposits all idle funds into `vault`.
idleCDO.depositAA(1_000_000e6);
cdoEpoch.startEpoch(); // manager; onStartEpoch deposits to vault

// Attacker (unprivileged): deposit a small vault position, then donate D
// directly to the vault to inflate convertToAssets during the running epoch.
uint256 D = 500_000e6;
vault.deposit(1e6, attacker);
usdc.transfer(address(vault), D);            // donation inflates share price

// Honest manager stops the epoch after epochEndDate.
vm.warp(cdoEpoch.epochEndDate() + 1);
vm.prank(manager);
cdoEpoch.stopEpoch(0, 0);                    // minted mode: no cash pulled for interest

// ~D of unbacked strategy tokens were minted; AA price inflated with zero backing.
assertGt(strategy.balanceOf(strategyAddr), realAssets); // minted > cash
assertGt(cdoEpoch.virtualPrice(address(aaTranche)), priceBefore);
// Attacker requests withdraw at inflated NAV; subsequent epochs fund it from
// real borrower principal -> remaining LPs' claims become undercollateralized.
```

Caveat: I confirmed `maxApr` exists in `contracts/strategies/idle/IdleCreditVault.sol` but could not verify its configured default in this iteration; the exploit is unconditional when `maxApr == 0` and bounded by the APR cap otherwise — both cases are covered by the recommendation.
