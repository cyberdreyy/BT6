### Title
Zip extractor performs no path-traversal (zip-slip) validation and its shared per-`Op` error deduplication can additionally suppress the only diagnostic signal for a malicious entry - (`helpers/archives/zip_extract.go`)

### Summary
`ExtractZipArchive` writes every zip entry's `file.Name` directly to the filesystem via `os.MkdirAll`, `os.OpenFile`, and `os.Symlink` with no check that the resolved path stays inside the extraction root, unlike the tar/zstd extractor which explicitly validates with `filepath.Abs`/`strings.HasPrefix` [1](#0-0) . Because there is no path check, a `../`-crafted entry in an attacker-supplied cache/artifact zip is written to an arbitrary path with no error at all, so `pathErrorTracker` never even sees it — the dedup mechanism is not the primary hiding mechanism, the missing validation is. In the rarer case a traversal attempt does raise an `os.PathError` (e.g. permission denied), `pathErrorTracker.actionable` can additionally suppress that log line if a benign entry earlier in the archive raised a `PathError` with the same `Op` string.

### Finding Description
`extractZipFile`/`extractZipFileEntry`/`extractZipSymlinkEntry`/`extractZipDirectoryEntry` use `file.Name` verbatim for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(data, file.Name)` [2](#0-1) . There is no `filepath.Clean`/`filepath.Abs`/prefix check anywhere in this file to ensure the resulting path stays under the extraction directory, in contrast to `commands/helpers/archive/tarzstd/tarzstd_extractor.go` which explicitly rejects entries that escape `e.dir` [1](#0-0) . This zip path is reached via `ziplegacy.NewExtractor(...).Extract()` → `archives.ExtractZipArchive` [3](#0-2) , which is the code that extracts attacker-controlled cache/artifact zip archives during job execution.

Because a `../../foo` entry succeeds (assuming filesystem permissions allow the write, which they typically do for paths under the job's working tree or sibling project directories on shared runners/executors), `extractZipFileEntry` returns `nil` error — `pathErrorTracker.actionable(nil)` returns `false` at the top of `actionable` [4](#0-3)  — so no warning is ever emitted for the malicious entry, independent of any dedup logic. The `actionable` dedup by `pathErr.Op` [5](#0-4)  only matters for the narrower case where the traversal attempt itself errors (e.g. permission denied) with the same `Op` (e.g. `"open"`) as an earlier benign conflicting entry — in that case the first `"open"` error marks `seenOps["open"]=true` and the traversal entry's later `"open"` PathError is swallowed, so `logrus.Warningf` at `helpers/archives/zip_extract.go:94` never fires for it.

### Impact Explanation
Two related but distinct issues combine: (1) a genuine zip-slip write primitive with zero path containment, letting an unprivileged pipeline author's crafted cache/artifact archive write files to paths outside the intended extraction root without any error or log at all; (2) for the subset of traversal attempts that do fail with an OS error, the per-`Op` deduplication in `pathErrorTracker` can additionally erase the one diagnostic line that would have flagged the attempt, if a same-`Op` benign error occurred first in the same archive. This satisfies the "file write within intended roots" invariant violation and the "undetected in logs used for incident response" concern for the subset of cases that do error.

### Likelihood Explanation
Feasible and repeatable: an unprivileged user controls the contents of cache/artifact archives uploaded/downloaded as part of their own job, and `ExtractZipArchive` is invoked on that archive with no traversal guard. Whether the traversal write succeeds silently (most likely, given no error path at all) or produces a `PathError` that then may or may not be deduped depends on filesystem permissions and ordering of entries in the archive, but the underlying missing-validation bug is deterministic and always reachable through `ziplegacy.NewExtractor`.

### Recommendation
Add path-containment validation identical in spirit to `tarzstd_extractor.go`'s check to `extractZipFile` (or a wrapper in `ExtractZipArchive`): resolve `filepath.Join(destDir, file.Name)` to an absolute path and reject/skip entries whose resolved path is not prefixed by `destDir`, returning a distinct sentinel error type. Additionally, change `pathErrorTracker` (or the call sites) to key deduplication on `(Op, category)` where "category" distinguishes security-relevant errors (e.g. traversal-rejection errors) from generic filesystem errors, or simply never suppress traversal-rejection errors regardless of `Op`.

### Proof of Concept
Go unit test in `helpers/archives`:
1. Build an in-memory `zip.Writer` with N benign entries whose extraction will each raise the same `os.PathError.Op` (e.g. N entries named to conflict with an existing read-only directory, causing repeated `"open"` errors), plus one malicious entry named `../../evil.txt`.
2. Call `archives.ExtractZipArchive` against a `zip.Reader` built from that buffer, inside a temp extraction dir.
3. Assert (a) that `../../evil.txt` was actually created outside the temp extraction dir (proving no path containment — the primary bug), and (b) capture `logrus` output and assert whether any log line mentioning `evil.txt` or a traversal-specific message appears; expect it does not appear because either no error occurred (case a) or, if forced to error via permissions, it is deduped by `pathErrorTracker.actionable` due to a matching `Op` from the benign entries processed earlier in `archive.File` order.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
