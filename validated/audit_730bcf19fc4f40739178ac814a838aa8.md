Confirmed vulnerability chain found: `os.Rename(c.AlternateFile, c.File)` in `tryRenameAlternateFile()` directly renames a job-controlled path.

### Title
Unsanitized cache key used to build `--alternate-file` path when `FF_HASH_CACHE_KEYS` is enabled, allowing cross-project cache-file rename/overwrite via path traversal - (File: functions/concrete/builder/builder.go, commands/helpers/cache_archiver.go)

### Summary
When the `FF_HASH_CACHE_KEYS` feature flag is enabled, `builder.cacheKey()` skips `cachekey.Sanitize` and uses the raw, attacker-controlled cache key directly as `humanKey`. This raw key becomes `CacheArchive.AlternateKey`/`CacheSource.AlternateKey`, which is joined unsanitized into a filesystem path (`cacheArchivePath`) and passed to `cache-archiver --alternate-file`, where `tryRenameAlternateFile()` calls `os.Rename(c.AlternateFile, c.File)` on it without any traversal check.

### Finding Description
`b.cacheKey()` at [1](#0-0)  only calls `cachekey.Sanitize` when `FF_HASH_CACHE_KEYS` is **off**; when the flag is on, `humanKey = rawKey` unmodified — the job's expanded `cache.Key` string, which may contain `../` sequences, is used as-is.

In `buildCacheArchive()`, `alternateResolved := humanKey` is used directly (not sha256-hashed) whenever `HashCacheKeys` is on: [2](#0-1) . This raw traversal-laden string is stored as `CacheArchive.AlternateKey`.

`CacheArchive.alternateArchivePath()` then builds the local file path with no sanitization at all: [3](#0-2)  — it simply does `filepath.Join(e.CacheDir, key, "cache.zip")` then `filepath.Rel(e.WorkingDir, absPath)`, with no check that the result stays under `CacheDir`. Both `filepath.Join` and `filepath.Rel` happily resolve `..` segments, so a key like `../../other-project-cachedir/somekey` collapses into a path pointing outside `CacheDir/ProjectUniqueDir()`.

This path is then passed as `--alternate-file <path>` to the `cache-archiver` helper subcommand (`RunnerCommand`), consumed in `commands/helpers/cache_archiver.go`. `tryRenameAlternateFile()` performs `os.Rename(c.AlternateFile, c.File)` on it directly: [4](#0-3) , with no path-containment validation before the rename.

Unlike the primary key path (which is `sha256(humanKey)` — a hex hash, inherently safe as a path component) and unlike the `cache.cache.go` `GetAdapter` remote-object-path logic (which explicitly validates `strings.HasPrefix(fullPath, basePath+"/")` — see [5](#0-4) ), the local alternate-file path has **no equivalent containment check**. `cachekey.Sanitize` (which resolves `..` against a virtual root and would prevent escape, see [6](#0-5) ) is bypassed entirely in this code path because `FF_HASH_CACHE_KEYS` disables the sanitizer.

Exploit flow: attacker sets `.gitlab-ci.yml` `cache.key: "../../../<victim-project-cache-dir>/somekey"` on a runner with `FF_HASH_CACHE_KEYS=true`. Job builds cache with `AlternateKey` = raw key. `cache-archiver` is invoked with `--file <hashed-safe-path> --alternate-file <path traversal target>`. If the target path (`c.AlternateFile`) exists (e.g., another project's `cache.zip`), and the primary hashed file doesn't yet exist locally, `os.Rename` moves/overwrites the victim's cache file to the attacker's location — destructively removing the other project's cache archive and replacing the attacker's local cache file with its contents.

### Impact Explanation
On a shared runner host with a shared cache directory, an unprivileged pipeline author can cause the runner helper to rename another project's `cache.zip` out of its own directory (data-loss / poisoning) and pull its contents into their own project's cache archive (read of foreign cache contents, potentially containing sensitive build artifacts or credentials cached by another project). This is a concrete cross-project cache confidentiality/integrity violation, matching the scoped impact.

### Likelihood Explanation
Requires the `FF_HASH_CACHE_KEYS` feature flag enabled and a shared local cache directory across projects (default for shared runners using local/host cache). The attacker only needs to control `.gitlab-ci.yml`/CI variables for `cache.key` — no elevated privileges. The traversal depth needed depends on the concrete `CacheDir` layout (`CacheDir/AlternateKey/cache.zip`), which is knowable/guessable since cache dir naming conventions are documented. Fully reproducible with a unit test.

### Recommendation
Apply the same sanitization/containment check to the alternate-key path as done for `GetAdapter`'s object path: run `cachekey.Sanitize` (or an equivalent `path.Clean`+prefix-check against `CacheDir`) on the alternate key even when `FF_HASH_CACHE_KEYS` is enabled, or validate in `cacheArchivePath`/`tryRenameAlternateFile` that the resolved absolute path is contained within `e.CacheDir` before joining/renaming. Reject and log a warning (skip the alternate-file feature) if containment fails, mirroring the existing `GetAdapter` validation pattern.

func (b *builder) cacheKey(name string) (string, string, []string, error) {
	// Virtual-root prefix prevents a leading / or .. in JobName/Ref from producing an unexpected key,
	// especially under FF_HASH_CACHE_KEYS=on where humanKey is used unsanitized.
	rawKey := path.Join("/", b.meta.JobInfo.Name, b.meta.GitInfo.Ref)[1:]
	if name != "" {
		rawKey = b.variables.ExpandValue(name)
	}

	var warnings []string
	var humanKey string
	if b.isFeatureFlagOn(featureflags.HashCacheKeys) {
		humanKey = rawKey
	} else {
		sanitized, err := cachekey.Sanitize(rawKey)
		switch {
		case err != nil:
			warnings = append(warnings, err.Error())
		case sanitized != rawKey:
			warnings = append(warnings, fmt.Sprintf("cache key %q sanitized to %q", rawKey, sanitized))
		}
		humanKey = sanitized
	}

func (c *CacheArchiverCommand) tryRenameAlternateFile() {
	if c.AlternateFile == "" || c.AlternateFile == c.File {
		return
	}

	_, err := os.Stat(c.File)
	if err == nil {
		logrus.Debugln("Primary cache file already exists locally, skipping rename from alternate")
		return
	}
	if !errors.Is(err, fs.ErrNotExist) {
		logrus.WithError(err).Warningln("Failed to stat primary cache file")
		return
	}

	if _, err := os.Stat(c.AlternateFile); err != nil {
		logrus.Debugln("Alternate cache file not found locally, nothing to rename")
		return
	}

	if err := os.MkdirAll(filepath.Dir(c.File), 0o700); err != nil {
		logrus.WithError(err).Warningln("Failed to create directory for cache file rename")
		return
	}

	if err := os.Rename(c.AlternateFile, c.File); err != nil {
		logrus.WithError(err).Warningln("Failed to rename alternate cache file to primary")
		return
	}

	logrus.Infoln("Renamed alternate cache file to primary")
}

// Sanitize validates and normalises a cache key.
// Cache keys may contain path separators. The function:
//   - decodes URL-encoded '/' (%2f) and '.' (%2e) characters
//   - replaces all '\' with '/'
//   - resolves path traversals (., ..) within a virtual root
//   - strips trailing whitespace from the rightmost path segments,
//     removing any that become empty after trimming
func Sanitize(cacheKey string) (string, error) {
	if cacheKey == "" {
		return "", nil
	}

	// Decode percent-encoded chars and normalise separators, then
	// resolve traversals against a virtual root so ".." can never
	// escape beyond the root.
	cleaned := path.Clean("/" + normaliser.Replace(cacheKey))

	// Strip the leading "/" we added, split into segments, then walk
	// backwards trimming trailing whitespace from the rightmost
	// segments—dropping any that become empty.
	parts := strings.Split(cleaned[1:], "/")
	n := len(parts)
	for n > 0 {
		parts[n-1] = strings.TrimRightFunc(parts[n-1], unicode.IsSpace)
		if parts[n-1] != "" {
			break
		}
		n--
	}

	key := strings.Join(parts[:n], "/")

	if key == "" {
		return "", fmt.Errorf("cache key %q could not be sanitized", cacheKey)
	}

	return key, nil
}
