The critical vulnerability lies in `shells/bash.go`, function `BashWriter.DotEnvVariables` [1](#0-0)  combined with `helpers.DotEnvEscape` [2](#0-1) .

### Title
Unquoted heredoc delimiter in DotEnvVariables allows shell metacharacter/EOF-collision injection from propagated dotenv variables - (File: shells/bash.go)

### Summary
`BashWriter.DotEnvVariables` builds a `cat << EOF > file ... EOF` heredoc using an unquoted delimiter (`<< EOF`, not `<< 'EOF'`), and the values it writes come only from `helpers.DotEnvEscape`, which escapes characters for *dotenv-file* parsing (backslash, double-quote, `\n`, `\r`) but does not neutralize shell metacharacters (`$`, `` ` ``) or a bare `EOF` line. Because the whole generated script (including this heredoc block) is later re-interpreted by `eval` in `BashWriter.Finish`, a dotenv value containing `$(...)`, backticks, or a line equal to `EOF` is executed as shell code or terminates the heredoc early when the script runs.

### Finding Description
`DotEnvVariables` constructs:
```
cat << EOF > <file>
KEY="value"
EOF
```
using `helpers.DotEnvEscape(variables)` for the body [1](#0-0) . `DotEnvEscape` only escapes `\`, `"`, `\n`, `\r` — characters needed so `godotenv` (the reader on the other end) parses the value back correctly — but does nothing about `$`, backticks, or a value/line matching the heredoc terminator `EOF` [2](#0-1) .

The heredoc delimiter is unquoted (`<< EOF`), which per POSIX/bash semantics means the heredoc body undergoes parameter expansion (`$VAR`), command substitution (`` `cmd` `` / `$(cmd)`), and backslash processing before being written to the file — this is standard heredoc behavior, distinct from the intention of writing literal file content.

This entire buffer (`b.String()`, which is the whole generated stage script including this heredoc) is subsequently wrapped by `b.escape(...)` (ANSI-C `$'...'` quoting) and handed to `eval` inside a subshell in `Finish` [3](#0-2) . `eval` re-parses the string as shell source, so heredoc processing (including `$()`, backticks, and terminator matching) happens exactly as if the heredoc had been typed directly into a shell — the ANSI-C outer quoting only protects the string from the *outer* shell's parsing, not from `eval`'s inner interpretation.

Consequently, if a variable value contains `$(id)`, `` `id` ``, or a literal line `EOF`, the resulting script will either execute the embedded command substitution while building the dotenv file, or will terminate the heredoc prematurely so that the remainder of the attacker-supplied value is parsed as normal shell commands (classic heredoc-terminator injection).

### Impact Explanation
If reachable with attacker-controlled dotenv values, this allows arbitrary shell command execution in the context of the job/stage script that writes the dotenv file — a cross-job (or intra-job) runner-side code execution primitive, matching the requested scoped impact.

Based purely on the escaping/heredoc logic itself (independent of caller), the unquoted-heredoc + insufficient escaping issue is real and reproducible: any caller passing untrusted string values through `DotEnvVariables`/`DotEnvEscape` is exposed to this injection, since neither function neutralizes `$`, backticks, or an embedded `EOF` line.

### Recommendation
- Quote the heredoc delimiter: use `cat << 'EOF' > file` instead of `cat << EOF > file` so the body is treated as a literal, non-expanding here-document.
- Additionally/alternatively, have `DotEnvEscape` reject or escape values that would collide with the heredoc terminator, or switch to a non-heredoc write mechanism (e.g., `printf '%s'` per line with `ShellEscape`/`PosixShellEscape`) that goes through the existing metacharacter-safe escaping already used elsewhere in `bash.go` (e.g. `Variable`, `ExportRaw`).

```go
func TestDotEnvVariablesHeredocInjection(t *testing.T) {

        "FOO": "bar\nEOF\ntouch /tmp/pwned\ncat << EOF",
        "BAZ": "$(touch /tmp/pwned2)",
    })
    script := w.Finish(false)

    // Run script under bash and assert:
    // 1. /tmp/pwned and /tmp/pwned2 do NOT exist (command substitution/EOF break-out must not execute)
    // 2. dotEnvFile content for FOO/BAZ matches the literal input strings exactly
}
```
Expected (buggy) result: `/tmp/pwned*` files get created, proving command execution occurred during heredoc processing — confirming the vulnerability. Expected (fixed) result after quoting the heredoc delimiter: no execution occurs and the file contains the literal, unexpanded values.

```go
func DotEnvEscape(variables map[string]string) string {
	var sb strings.Builder

	// Sort variables to get deterministic output
	keys := make([]string, 0, len(variables))
	for key := range variables {
		keys = append(keys, key)
	}
	sort.Strings(keys)

	for _, key := range keys {
		if !isValidDotEnvKey(key) {
			// Skip invalid keys
			continue
		}

		value := variables[key]
		fmt.Fprintf(&sb, "%s=\"%s\"\n", key, escapeDotEnvValue(value))
	}

	return sb.String()
}
```
