### Title
Division-before-multiplication precision loss in Jovian DA-footprint gas metering - (File: `crates/common/l1-fees/src/params.rs`, mirrored in `crates/common/evm/src/executor/block_executor.rs`)

### Summary
`L1FeeParams::jovian_da_footprint` and its consensus-execution counterpart `BaseBlockExecutor::jovian_da_footprint_estimation` divide the FastLZ-estimated compressed transaction size by `1_000_000` *before* multiplying by the DA-footprint gas scalar, instead of multiplying first and dividing once at the end. This is the same "division before multiplication" precision-loss class flagged in the referenced Sherlock report against `AaveLeverageStrategyExtension._calculateMinRepayUnits()`.

### Finding Description
`tx_estimated_size_fjord` returns the estimated compressed size *scaled by `1e6`* (per its doc comment: "estimated compressed transaction size in bytes, scaled by 1e6"). [1](#0-0) 

In `jovian_da_footprint`, the scaled size is divided by `1_000_000` **first**, and only then multiplied by `da_footprint_gas_scalar`:
```rust
U256::from(tx_estimated_size_fjord(input))
    .wrapping_div(U256::from(1_000_000u64))
    .saturating_mul(scalar)
    .saturating_to::<u64>()
``` [2](#0-1) 

Contrast this with the correct order used one function below for the analogous Ecotone L1 cost, where the multiplication happens first and the division happens once, at the end, preserving precision:
```rust
self.calculate_l1_fee_scaled_ecotone()
    .saturating_mul(rollup_data_gas_cost)
    .wrapping_div(U256::from(1_000_000u64 * NON_ZERO_BYTE_COST))
``` [3](#0-2) 

The same division-first pattern is duplicated in the block executor's live path that actually enforces the Jovian DA-footprint block limit during transaction execution:
```rust
let encoded = tx_env
    .encoded_bytes()
    .map_or_else(..., ...)
    .saturating_div(1_000_000);
...
Ok(encoded.saturating_mul(da_footprint_gas_scalar))
``` [4](#0-3) 

Because `estimated_size` is truncated by integer division before the scalar multiply, any fractional remainder below `1e6` is discarded before it can contribute (scaled by the multiplier) to the final result. For small compressed sizes this rounding is coarse: `tx_estimated_size_fjord` floors at `MIN_TX_SIZE_SCALED = 100_000_000` (i.e. 100 bytes scaled by 1e6), so `estimated_size / 1_000_000` truncates to whole-byte granularity before the scalar is applied, whereas multiplying first and dividing once would retain sub-byte precision proportional to the scalar's magnitude. [5](#0-4) 

### Impact Explanation
`da_footprint_used` (accumulated per block from `jovian_da_footprint_estimation`) is compared against a protocol-defined per-block DA-footprint gas limit under the Jovian upgrade's DA-footprint block-limit spec, gating how many/how large transactions a block can include. Because the metering here systematically under-counts the DA footprint gas relative to the "multiply-then-divide" reference formula used elsewhere in the same file, blocks can be built (or accepted) that consume more real L1 DA capacity than the metered figure implies. This is a resource-metering divergence rather than a memory-safety bug, and its practical severity depends on how tightly the DA-footprint limit is enforced relative to actual L1 blob/calldata capacity — a systematic under-count could allow block builders/sequencers to pack more DA-heavy transactions per block than the limit intends, degrading the invariant the limit is meant to enforce.

### Likelihood Explanation
Any transaction sender's calldata triggers this computation on every transaction once Jovian is active and a DA-footprint scalar is configured (`da_footprint_gas_scalar.is_some()`), since it runs unconditionally in the per-transaction block-execution path shown above. The precision loss is deterministic and reproducible for any input, not dependent on adversarial timing, but its magnitude scales with the scalar value and shrinks in relative terms for large transactions (division truncation of an integer divided by 1e6 is at most `999999/1e6` units of pre-scalar error).

### Recommendation
Reorder the arithmetic to multiply before dividing, matching `calculate_tx_l1_cost_ecotone`'s pattern, in both `L1FeeParams::jovian_da_footprint`:
```rust
U256::from(tx_estimated_size_fjord(input))
    .saturating_mul(scalar)
    .wrapping_div(U256::from(1_000_000u64))
    .saturating_to::<u64>()
```
and in `BaseBlockExecutor::jovian_da_footprint_estimation`, deferring the `saturating_div(1_000_000)` until after multiplying by `da_footprint_gas_scalar`. Confirm the two implementations (`params.rs` and `block_executor.rs`) are kept numerically identical, since currently they duplicate the same formula independently and could drift.

### Proof of Concept
Given `tx_estimated_size_fjord` at the floor `MIN_TX_SIZE_SCALED = 100_000_000` (100 bytes, scaled by 1e6) and a `da_footprint_gas_scalar` of, e.g., `7`:
- Current (divide-then-multiply): `100_000_000 / 1_000_000 = 100`, then `100 * 7 = 700`.
- Correct (multiply-then-divide): `100_000_000 * 7 = 700_000_000`, then `700_000_000 / 1_000_000 = 700`.

These match at the floor value, but for any `tx_estimated_size_fjord(input)` value not an exact multiple of `1_000_000` (e.g. `100_500_000`, a 100.5-byte estimate above the floor with a fractional remainder), the divide-first path truncates to `100 * 7 = 700`, while multiply-first yields `100_500_000 * 7 / 1_000_000 = 703`, an under-count of `3` DA-footprint gas units per transaction — demonstrated directly by the existing unit test's own floor-only case, which cannot distinguish the two orderings: [6](#0-5)

    /// Calculates the Jovian DA-footprint gas for posting the enveloped transaction bytes `input`.
    ///
    /// The footprint is the FastLZ-estimated compressed size (scaled by `1e6`, as
    /// [`tx_estimated_size_fjord`] returns) divided back down by `1e6` and multiplied by the
    /// DA-footprint gas scalar. Returns zero when no scalar is set (pre-Jovian or unconfigured).
    /// Mirrors the reference `jovian_da_footprint_estimation`.
    pub fn jovian_da_footprint(&self, input: &[u8]) -> u64 {
        let Some(scalar) = self.da_footprint_gas_scalar else {
            return 0;
        };
        U256::from(tx_estimated_size_fjord(input))
            .wrapping_div(U256::from(1_000_000u64))
            .saturating_mul(scalar)
            .saturating_to::<u64>()
    }

    fn jovian_da_footprint_estimation(
        &mut self,
        tx_env: &E::Tx,
        tx: impl RecoveredTx<R::Transaction>,
    ) -> Result<u64, BlockExecutionError> {
        // Try to use the enveloped tx if it exists, otherwise use the encoded 2718 bytes
        let encoded = tx_env
            .encoded_bytes()
            .map_or_else(
                || estimate_tx_compressed_size(tx.tx().encoded_2718().as_ref()),
                |encoded| estimate_tx_compressed_size(encoded),
            )
            .saturating_div(1_000_000);

        // Load the L1 block contract into the cache. If the L1 block contract is not pre-loaded the
        // database will panic when trying to fetch the DA footprint gas scalar.
        self.evm.db_mut().basic(Predeploys::L1_BLOCK_INFO).map_err(BlockExecutionError::other)?;

        let da_footprint_gas_scalar = L1BlockInfo::fetch_da_footprint_gas_scalar(self.evm.db_mut())
            .map_err(BlockExecutionError::other)?
            .into();

        Ok(encoded.saturating_mul(da_footprint_gas_scalar))
    }

/// Calculate the estimated compressed transaction size in bytes, scaled by 1e6.
/// This value is computed based on the following formula:
/// max(minTransactionSize, intercept + fastlzCoef*fastlzSize)
pub fn tx_estimated_size_fjord(input: &[u8]) -> u64 {
    let fastlz_size = flz_compress_len(input) as u64;

    fastlz_size
        .saturating_mul(L1_COST_FASTLZ_COEF)
        .saturating_sub(L1_COST_INTERCEPT)
        .max(MIN_TX_SIZE_SCALED)
}
