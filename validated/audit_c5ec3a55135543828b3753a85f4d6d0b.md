### Title
Unsafe pointer cast between `alloy_eips::eip4844::Blob` and `c_kzg::Blob` assumes cross-crate memory layout compatibility without any static guarantee - ([File: crates/consensus/providers/src/blobs.rs])

### Summary
`OnlineBlobProvider::blobs_with_proofs` in `crates/consensus/providers/src/blobs.rs` reinterprets a boxed `alloy_eips::eip4844::Blob` as a `c_kzg::Blob` (and back) via raw pointer casts, justified only by a code comment ("all types have the same size and alignment") rather than any compiler-enforced guarantee. This is the same bug class as GHSA-rm4w-6696-r77p (`nb-connect`): casting between two independently-maintained types across a crate boundary while assuming a memory layout that neither crate's public API promises.

### Finding Description
`blobs_with_proofs` performs:
```rust
// SAFETY: all types have the same size and alignment
let kzg_blob = unsafe { Box::from_raw(Box::<Blob>::into_raw(blob.blob) as *mut c_kzg::Blob) };
...
// SAFETY: all types have the same size and alignment
let alloy_blob = unsafe { Box::from_raw(Box::<c_kzg::Blob>::into_raw(kzg_blob) as *mut Blob) };
``` [1](#0-0) 

Neither `alloy_eips::eip4844::Blob` nor `c_kzg::Blob` is defined in this repository — both are external, independently versioned crates. Rust's standard/ecosystem convention does not guarantee that two structurally-similar newtypes defined in different crates share identical size, alignment, or field layout unless explicitly documented and pinned (e.g., with `#[repr(C)]`/`#[repr(transparent)]` plus a compile-time `size_of`/`align_of` assertion). No such static assertion exists anywhere in this codebase for these two types — a search for `assert_eq_size!`, `size_of::<Blob>()`, or similar layout-compatibility checks near this code found none. The safety comment is an unverified assumption, exactly the pattern the `nb-connect` advisory describes: casting `SocketAddrV4`/`SocketAddrV6` to the OS `sockaddr` layout without any layout guarantee from the standard library, which "will cause invalid memory access if the standard library changes the implementation... no warnings or errors will be emitted once the change happens."

This function is reached from `fetch_blobs_with_proofs`, which is called on the L1 blob-derivation path (`OnlineBlobProvider`), fetching and recomputing KZG commitments/proofs for blobs referenced during L1 batch derivation. [2](#0-1) 

### Impact Explanation
If either the `alloy_eips` or `c-kzg` dependency changes its internal `Blob` representation (e.g., adds a length prefix, changes to a different-sized array, adds padding, or changes alignment) in a way that still compiles against the same public size constant, this unchecked pointer reinterpretation becomes silent undefined behavior: out-of-bounds heap reads/writes, corrupted KZG commitment/proof computation, or a crash (node halt) during L1 derivation — with no compiler error or runtime warning, mirroring the exact failure mode called out in the `nb-connect` advisory. Because this runs inside every base node's block-derivation pipeline, a layout drift introduced by a routine dependency bump could cause a fleet-wide node halt or corrupted derived state without any attacker action required, and no test in the crate would catch it since Rust makes no cross-crate layout promises.

### Likelihood Explanation
This is not currently a memory-safety bug for the pinned dependency versions (both types are presently simple fixed-size byte-array wrappers of the same size), but it is a fragile invariant that is invisible to the type system and undocumented in either crate. Any change to `c-kzg` or `alloy_eips` internals (which are not under this repository's control) silently reintroduces undefined behavior, exactly analogous to the referenced advisory that this comment-only safety justification is standing in for a real invariant guarantee.

### Recommendation
Replace the raw pointer reinterpretation with either:
- A compile-time layout assertion (`static_assertions::assert_eq_size!` / `assert_eq_align!`) placed directly next to the unsafe cast so any layout drift fails the build, or
- A safe conversion that copies bytes through the public API (`Blob::as_ref()` / `Blob::from(bytes)` or equivalent constructors) instead of transmuting pointers, accepting the (likely negligible) copy cost, or
- Pin `c-kzg`'s `Blob` layout explicitly (if it exposes a documented `#[repr(C)]`/fixed-size guarantee) and add a regression test that fails to compile if the assumption is violated.

### Proof of Concept
Not applicable as a live exploit against current pinned versions — the finding is a code-pattern analog of GHSA-rm4w-6696-r77p: the unsafe cast in `blobs_with_proofs` (`crates/consensus/providers/src/blobs.rs:130-145`) relies solely on an unverified comment ("all types have the same size and alignment") for a cross-crate pointer reinterpretation, with no `static_assertions`/`size_of` check anywhere in the crate to catch a future layout mismatch introduced by an `alloy_eips` or `c-kzg` version bump.

    /// Converts a vector of boxed blobs to a vector of blobs with their KZG commitments and proofs.
    ///
    /// Note: for performance reasons, we need to transmute the blobs to the `c_kzg::Blob` type to
    /// avoid the overhead of moving the blobs around or reallocating the memory.
    fn blobs_with_proofs(
        blobs: Vec<BoxedBlob>,
    ) -> Result<Vec<BlobWithCommitmentAndProof>, c_kzg::Error> {
        blobs
            .into_iter()
            .map(|blob| {
                let kzg_settings = EnvKzgSettings::Default;

                // SAFETY: all types have the same size and alignment
                let kzg_blob =
                    unsafe { Box::from_raw(Box::<Blob>::into_raw(blob.blob) as *mut c_kzg::Blob) };

                let commitment = kzg_settings
                    .get()
                    .blob_to_kzg_commitment(&kzg_blob)
                    .map(|blob| blob.to_bytes())?;
                let proof = kzg_settings
                    .get()
                    .compute_blob_kzg_proof(&kzg_blob, &commitment)
                    .map(|proof| proof.to_bytes())?;

                // SAFETY: all types have the same size and alignment
                let alloy_blob =
                    unsafe { Box::from_raw(Box::<c_kzg::Blob>::into_raw(kzg_blob) as *mut Blob) };

                Ok(BlobWithCommitmentAndProof {
                    blob: alloy_blob,
                    kzg_commitment: FixedBytes::from(*commitment),
                    kzg_proof: FixedBytes::from(*proof),
                })
            })
            .collect()
    }

    pub async fn fetch_blobs_with_proofs(

    }
