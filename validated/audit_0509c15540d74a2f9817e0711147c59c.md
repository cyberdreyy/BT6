### Title
Missing role gate on debug/pprof endpoints allows any authenticated user (including lowest "view" role) to access internal profiling data - ([File: core/web/router.go])

### Summary
`v2Routes` mounts `metricRoutes(authv2)` inside the `authv2` group, which only requires `auth.AuthenticateByToken` or `auth.AuthenticateBySession` to succeed — with no minimum role requirement. Unlike every other sensitive endpoint in that block (wrapped in `auth.RequiresRunRole`, `auth.RequiresEditRole`, or `auth.RequiresAdminRole`), the pprof routes registered by `metricRoutes` have no per-route role wrapper at all, so any successfully authenticated user regardless of role can hit them.

### Finding Description
In `core/web/router.go`, `authv2` is created via:
```go
authv2 := r.Group("/v2", auth.Authenticate(app.AuthenticationProvider(),
    auth.AuthenticateByToken,
    auth.AuthenticateBySession,
))
``` [1](#0-0) 

This only validates that the caller has *any* valid session or API token — it does not check the user's role (`view`, `run`, `edit`, `admin`). Every sensitive route inside this block is individually wrapped with a role-check function (e.g. `auth.RequiresAdminRole(ekc.Delete)`, `auth.RequiresEditRole(bt.Create)`), which is defined in `core/web/auth/auth.go`:
- `RequiresRunRole` rejects only `UserRoleView`.
- `RequiresEditRole` rejects `UserRoleView` and `UserRoleRun`.
- `RequiresAdminRole` requires exactly `UserRoleAdmin`. [2](#0-1) 

However, `metricRoutes` is called directly on `authv2` with no such wrapper:
```go
// Debug routes accessible via authentication
metricRoutes(authv2)
``` [3](#0-2) 

And `metricRoutes` itself registers pprof handlers with plain `GET`/`POST`, no role check:
```go
func metricRoutes(r *gin.RouterGroup) {
	pprofGroup := r.Group("/debug/pprof")
	pprofGroup.GET("/", ginHandlerFromHTTP(pprof.Index))
	...
	pprofGroup.GET("/heap", ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP))
	pprofGroup.GET("/goroutine", ginHandlerFromHTTP(pprof.Handler("goroutine").ServeHTTP))
	...
}
``` [4](#0-3) 

As a result, any user who possesses valid session cookie or a valid API token/secret pair — even one assigned the lowest `UserRoleView` role — passes `auth.Authenticate` and can then reach `GET /v2/debug/pprof/heap`, `/goroutine`, `/allocs`, `/profile`, `/trace`, `/mutex`, `/block`, `/threadcreate`, and `POST /v2/debug/pprof/symbol`. These endpoints expose full process memory heap dumps, goroutine stack traces (including function arguments/local state), CPU/execution traces, and symbol resolution — all of which can reveal internal state, memory layout, and potentially secrets or key material transiently held in process memory, none of which is redacted like the JSON API responses are (compare to `redact`/`isBlacklisted` used for password fields elsewhere in this same file). [5](#0-4) 

### Impact Explanation
This falls under "unauthorized information disclosure of internal node state" — a low-privilege (`view`-role) credential holder can extract heap/goroutine/profile data that may contain fragments of secrets, private key material, or internal addresses useful for further exploitation (e.g. crafting subsequent attacks or bypassing ASLR-dependent mitigations). This is a real confinement violation: debug/profiling surfaces intended to be operator/admin-only are reachable by any authenticated principal, contrary to the comment "Debug routes accessible via authentication" which implies broader-than-intended access.

### Likelihood Explanation
Minimal precondition: possession of any valid, even lowest-privileged, user credential (session cookie or API token/secret pair with `UserRoleView`). No special network position, no admin/operator access needed. Fully repeatable via simple authenticated HTTP GET requests; every other similarly sensitive route in the same function requires at least `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole`, confirming this is an inconsistency/omission rather than an intentional broad-access design.

### Recommendation
Wrap the pprof routes registered by `metricRoutes` with `auth.RequiresAdminRole` (consistent with how `debugRoutes`'s `/debug/vars` is also gated only by authentication but arguably should also be tightened, and consistent with the sensitivity level of every other admin-tier route in `v2Routes`). E.g.:
```go
func metricRoutes(r *gin.RouterGroup) {
	pprofGroup := r.Group("/debug/pprof")
	pprofGroup.GET("/", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Index)))
	...
}
```
Ensure all handlers in this group require `UserRoleAdmin`.

### Proof of Concept
Go handler-integration test plan (using the existing test harness pattern in `core/web/router_test.go`/`core/web/auth`):
1. Create a test app and node router via `NewRouter`.
2. Create a user with `clsessions.UserRoleView` and obtain a valid API token via `NewAPIToken`, or authenticate via session.
3. Issue `GET /v2/debug/pprof/heap` (and `/goroutine`, `/allocs`, `/profile`, `/trace`, `/mutex`, `/block`, `/threadcreate`, `POST /v2/debug/pprof/symbol`) with the `X-API-KEY`/`X-API-SECRET` headers (or session cookie) for the view-role user.
4. Assert current behavior returns `200 OK` with pprof binary/profile payload (demonstrating the bug), and expected/fixed behavior should return `401`/`403` per `RequiresAdminRole`.
5. Repeat with `UserRoleRun` and `UserRoleEdit` credentials to confirm none are rejected, only `UserRoleAdmin` should pass after the fix.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
