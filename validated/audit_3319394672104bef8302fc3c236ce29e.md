### Title
Missing role-based authorization on `DeleteCSAKey` mutation allows view-role users to delete CSA keys - ([File: core/web/resolver/mutation.go])

### Finding Description
The GraphQL mutation endpoint at `POST /query` is wired in `core/web/router.go` with only `auth.AuthenticateGQL(...)` as middleware, which authenticates a session but does not perform any role check before dispatching to resolvers. [1](#0-0) 

`DeleteCSAKey` in `core/web/resolver/mutation.go` and its supporting types in `core/web/resolver/csa_keys.go` contain no role/permission checks of their own — they call directly into the keystore to delete the key and return a `DeleteCSAKeyPayloadResolver`. [2](#0-1) 

Because authorization is enforced only at the HTTP-authentication layer (session validity) and not at the per-mutation/role layer for the `/query` GraphQL surface, any authenticated session — including one whose associated user role is "view" — that can reach `POST /query` can invoke `DeleteCSAKey` and any other destructive mutation (bridges, keys, feeds managers, jobs, chains) exposed by the schema, since there is no wrapper analogous to a `RequiresAdmin`/`RequiresEditRole` guard applied per resolver.

### Impact Explanation
A "view" role user can delete a node's CSA key via `DeleteCSAKey`, which is used for the node's connection to the Feeds Manager / relay authentication. Removing this key can disconnect the node from job/config distribution channels or otherwise disrupt job management, degrading oracle reporting reliability — matching the "misreporting of prices and/or data" bounty impact class for a low-privileged user gaining destructive capability reserved for admins.

### Likelihood Explanation
The only precondition is possessing any authenticated session on the node's GraphQL API (`POST /query`), regardless of assigned role ("view"/"run"). No operator, admin, host, or DB access is required, and the mutation is a standard part of the public GraphQL schema (`core/web/schema/type/csa_keys.graphql`), making this trivially repeatable by sending a single mutation request.

### Recommendation
Add explicit role-based authorization checks to all destructive/mutating GraphQL resolvers (e.g. `DeleteCSAKey`, and other delete/disable mutations for bridges, keys, feeds managers, jobs, chains), requiring the session's role to be Admin/Edit before allowing execution — either via a resolver-level guard or a schema-directive/middleware enforced centrally for the `/query` mutation type, similar to REST route-level `requiresAdmin` checks.

### Proof of Concept
1. Create a test node session with role `View` (`sessions.UserRoleView` or equivalent) using existing test helpers in `core/web/resolver/csa_keys_test.go`.
2. Construct a GraphQL mutation request: `mutation { deleteCSAKey(id: "<existing_csa_key_id>") { ... on DeleteCSAKeySuccess { csaKey { id } } } }`.
3. Send it through the resolver test harness (as used in `csa_keys_test.go`) using the view-role session context.
4. Assert that the mutation succeeds (key deleted) despite the view role — expected/fixed behavior should instead return an authorization error (e.g. HTTP 403 / GraphQL error) and leave the key intact.
5. Repeat for other destructive mutations (`DeleteBridge`, `DeleteJob`, `DeleteFeedsManagerChainConfig`, etc.) in `mutation.go` to confirm the same missing role-check pattern.

	key csakey.KeyV2

func NewDeleteCSAKeySuccess(key csakey.KeyV2) *DeleteCSAKeySuccessResolver {
	return &DeleteCSAKeySuccessResolver{key: key}
}

func (r *DeleteCSAKeySuccessResolver) CSAKey() *CSAKeyResolver {
	return NewCSAKey(r.key)
}

type DeleteCSAKeyPayloadResolver struct {
	key csakey.KeyV2
	NotFoundErrorUnionType
}

func NewDeleteCSAKeyPayload(key csakey.KeyV2, err error) *DeleteCSAKeyPayloadResolver {
	var e NotFoundErrorUnionType

	if err != nil {
		e = NotFoundErrorUnionType{err: err, message: err.Error(), isExpectedErrorFn: func(err error) bool {
			return errors.As(err, &keystore.KeyNotFoundError{})
		}}
	}

	return &DeleteCSAKeyPayloadResolver{key: key, NotFoundErrorUnionType: e}
}

func (r *DeleteCSAKeyPayloadResolver) ToDeleteCSAKeySuccess() (*DeleteCSAKeySuccessResolver, bool) {
	if r.err == nil {
		return NewDeleteCSAKeySuccess(r.key), true
	}
	return nil, false
}
