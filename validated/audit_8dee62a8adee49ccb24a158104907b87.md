## Impact Assessment

A `todo!()` panic in Rust terminates the executing thread or async task. Depending on whether the RPC server uses `catch_unwind` or `panic = "abort"`, this either crashes the entire fullnode process or kills the request handler. Either way, a single public transaction permanently places an object in a state that crashes any fullnode that tries to serve it via the live RPC/gRPC API.

This matches the bounty scope's **Low** impact class: *"public-input fullnode crash … on unmodified software."*

### Title
`todo!()` panic in `From<Owner>` RPC conversion crashes fullnode when querying a `Owner::Party` object — (`crates/sui-types/src/rpc_proto_conversions.rs`)

### Summary
Any public caller can transfer an object using `sui::transfer::public_party_transfer` with a `single_owner` party, storing it on-chain as `Owner::Party`. Any subsequent RPC/gRPC query for that object's ownership hits the unimplemented `todo!("Party WIP")` arm in the `From<Owner>` proto conversion, panicking the server.

### Finding Description
`public_party_transfer` is a public Move function gated only by `is_single_owner`, which is trivially satisfied by calling `sui::party::single_owner(addr)`. After execution, the object is stored with `Owner::Party`. The gRPC/REST state-service endpoints that return object metadata call the `From<Owner>` impl in `rpc_proto_conversions.rs`. The `O::Party { .. }` arm at line 2222 is `todo!()` — a hard panic with no fallback or error return.

### Impact Explanation
A single transaction by any ordinary SUI holder permanently places an object in a state that panics any fullnode RPC handler that reads it. This is a public-input fullnode crash, in scope at **Low** severity.

### Likelihood Explanation
Trivially reproducible: create any `key + store` object, call `public_party_transfer` with `single_owner`, then query the object ID via any RPC endpoint. No special privileges, no malicious validators.

### Recommendation
Replace `todo!("Party WIP")` with a proper proto encoding for the `Party` owner variant, or return a structured error instead of panicking. Until the Party feature is fully implemented, the RPC layer must handle this variant gracefully (e.g., return `UNIMPLEMENTED` or a dedicated proto field).
