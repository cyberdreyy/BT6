### Title
Unbounded recursive TrieNode decode/traversal in the fault-proof MPT allows attacker-controlled preimages to stack-overflow the fault-proof program - (File: crates/proof/mpt/src/node.rs)

### Summary
The CVE-2016-1522 bug class is "recursive load calls that do not consider a size/depth check, causing a stack/heap overflow from adversarial nested input." `base-proof-mpt`'s `TrieNode` is described as "a recursive, in-memory implementation" of the hexary MPT [1](#0-0) , and its `Decodable` impl, `open`, `insert`, `delete`, and `collapse_if_possible` methods all recurse into child nodes with no depth or node-count bound, unlike the CBOR/EIP-8130/observability-events code paths elsewhere in the repo that explicitly cap recursion depth (`MAX_CBOR_NESTING_DEPTH`, `MAX_DATA_VALIDATION_DEPTH`, single-level delegate-authenticator checks).

### Finding Description
`TrieNode::decode` recursively calls `Vec::<Self>::decode` for branch nodes and `Self::decode` for extension-node children with no depth counter passed through: [2](#0-1)  The extension/leaf payload decoder also recurses via `Self::decode(buf)` for the extension child [3](#0-2) . Live-trie walking methods (`open`, `insert`, `delete`, `collapse_if_possible`, `unblind`) similarly recurse per path nibble/blinded-node with no depth limit, each unblind step reaching out to `TrieProvider::trie_node_by_hash` to fetch attacker/L1-derived preimages and continuing recursion: [4](#0-3) [5](#0-4) 

This mirrors Graphite2's `Code.cpp` defect: `load()` calls recursed into nested references without an aggregate size/depth check, letting attacker data blow past the intended bound. Here, an extension-node chain (`rlp([path, child])`) can be nested arbitrarily deep because each `TrieNode::decode` call only checks the immediate RLP header/list-length, not cumulative nesting depth, and the trie is populated from preimages resolved through `TrieProvider` implementations that pull data from an oracle/kv-store fed by potentially adversarial L1/dispute-game inputs, e.g. `OracleL1ChainProvider::trie_node_by_hash` [6](#0-5) . This is precisely the "derivation of attacker-written L1 deposit and system-config data" and "the fault-proof program and MPT" surface called out as in-scope in the rules.

By contrast, every other recursive parser in this codebase enforces an explicit depth cap: the Nitro CBOR walker rejects depth over 64 [7](#0-6) , and the observability-events data validator rejects nesting past 16 [8](#0-7) . `TrieNode`'s recursive decode/traversal has no analogous guard.

### Impact Explanation
In the fault-proof program, a dispute-game participant/challenger supplies preimages that back the state/account/storage tries used to compute the derived output root. If an attacker can construct (or cause the honest client to fetch) a pathologically deep extension-node chain as a "trie node" preimage — each layer only 32 bytes (a blinded child hash) or small enough to stay unblinded, nested to thousands of levels — repeated `unblind`+`open`/`decode` recursion can exhaust the native stack of the fault-proof program (a bare-metal/zkVM or Cannon-style execution environment with a small, fixed stack), crashing or hanging the program before it can produce a claim. This can manifest as: the fault-proof program failing to compute the correct/any provable output root (denial of service on the dispute path), or an unrecoverable crash that halts the challenger/defender's local proof computation — both explicitly listed acceptable impacts ("wrong provable output root", "node halt").

### Likelihood Explanation
Reachability requires only that an adversary control (or influence) preimage bytes resolved via `TrieProvider::trie_node_by_hash` during fault-proof execution — this is exactly the trust model of the fault-proof program, which must safely process untrusted L1/L2 state data supplied through the preimage oracle during a dispute. No privileged access is needed: constructing a deeply nested RLP extension-node chain is straightforward and cheap (each level adds tens of bytes), and the recursive call chain (`decode`→`decode`, or `open`→`unblind`→`open`) has no early-exit depth check anywhere in `crates/proof/mpt/src/node.rs`.

### Recommendation
Add an explicit nesting-depth counter (threaded through `decode`, `open`, `insert`, `delete`, `unblind`, and `collapse_if_possible`) analogous to `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`, and reject/short-circuit once a sane maximum (e.g., matching the maximum possible MPT depth of 64 nibbles for account/storage tries) is exceeded. Alternatively, convert the traversal to an explicit iterative loop with a bounded stack.

### Proof of Concept
Not independently verified against a running fault-proof program (index-only review); conceptually: craft an RLP byte string of chained extension nodes `rlp([encoded_path, rlp([encoded_path, rlp([...])])])` (or blinded-hash extension nodes that each resolve via `TrieProvider` to another extension node) nested to a depth sufficient to exceed the fault-proof program's stack (thousands of levels, each only tens of bytes), then feed the corresponding preimages through `OracleL1ChainProvider`/`DiskTrieNodeProvider`. Calling `TrieNode::decode` (or `open`) on the root should recurse without bound and crash/stack-overflow the process. This requires running the actual fault-proof binary to confirm the crash, which was not available in this read-only review — flagged as unverified.

# `base-proof-mpt`

A recursive, in-memory implementation of Ethereum's hexary Merkle Patricia Trie (MPT).

## Overview

Implements Ethereum's Merkle Patricia Trie with support for retrieval, insertion, deletion, and
root computation via RLP-encoded trie node encoding. Starting from a trie root hash, `TrieNode`
lazily fetches and caches node preimages via `TrieProvider`, enabling stateless block execution
without storing the full state. Designed as the trie backend for [`base-proof-executor`](../executor).

    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }

fn find_forbidden_data_key(data: &Map<String, Value>, depth: usize) -> Option<ForbiddenDataReason> {
    if depth > MAX_DATA_VALIDATION_DEPTH {
        return Some(ForbiddenDataReason::TooDeep);
    }
    for (key, value) in data {
        if is_forbidden_data_key(key) {
            return Some(ForbiddenDataReason::Key(key.clone()));
        }
        if let Some(reason) = find_forbidden_data_value(value, depth + 1) {
            return Some(reason);
        }
    }
    None
}
