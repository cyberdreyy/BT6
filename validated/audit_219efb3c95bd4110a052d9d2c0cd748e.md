The `LendingPoolConfigureBankInterestOnly` account struct enforces `has_one = delegate_curve_admin @ MarginfiError::Unauthorized` on the `group` account and requires `delegate_curve_admin` to be a `Signer`, both checked by Anchor's account-validation layer *before* the instruction handler body executes. [1](#0-0) 

This means an attacker without the actual `delegate_curve_admin` keypair cannot even reach the handler's mutation logic (`bank.config.interest_rate_config.update(...)`) — the `has_one` constraint and `Signer` check fail first, causing the entire transaction to abort with `Unauthorized` before any bank state is touched. There is no "late binding" here: the authorization check is an Anchor account-validation constraint evaluated prior to instruction execution, not a check performed midway through the handler after some mutation. [2](#0-1) 

This is confirmed by the existing test `configure_bank_interest_only_not_admin`, which changes the group's `delegate_curve_admin` to a random pubkey, then calls the instruction with a signer that no longer matches, and asserts the transaction fails with `MarginfiError::Unauthorized` — proving no state mutation occurs for unauthorized callers. [3](#0-2) 

The `bank` account is additionally bound to the correct `group` via `has_one = group @ MarginfiError::InvalidGroup`, preventing cross-group/bank substitution attacks. Since Anchor validates all account constraints (`has_one`, `Signer`) atomically before invoking the handler, and any failure aborts the entire transaction with no partial state changes persisted, there is no reachable path for an unprivileged caller to mutate `interest_rate_config` or bypass the `delegate_curve_admin`/`admin` role requirement.

pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

    Ok(())
}
