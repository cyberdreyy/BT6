### Title
Vote Program `authorize` Sets Authorized Voter/Withdrawer to Unvalidated (Zero) Pubkey - (File: programs/vote/src/vote_state/mod.rs)

### Summary
The `authorize` function in the vote program sets `authorized_withdrawer` and the authorized voter to any pubkey supplied in the `Authorize`/`AuthorizeChecked` instruction, with no check that the new authority is a legitimate, retrievable address (e.g., not `Pubkey::default()`). This mirrors the reported `_updateFeeWallet` bug class: an address that controls fund movement is written to state without sanity validation.

### Finding Description
`authorize()` handles `VoteAuthorize::Withdrawer` by requiring only that the *current* authorized withdrawer sign, then unconditionally overwrites the withdrawer with the caller-supplied `authorized` pubkey: [1](#0-0) 

Likewise, the voter-authorization branch sets the new authorized voter without validating the target address itself: [2](#0-1) 

There is no check anywhere in this path rejecting `Pubkey::default()` (the all-zero address) or any other address that cannot subsequently produce a valid signature, unlike the SIMD-0232 commission-collector path which explicitly validates system ownership, rent-exemption, and reserved-key status before accepting a new address: [3](#0-2) 

The analogous `initialize_nonce_account` system instruction has the same gap — it stores the caller-supplied `nonce_authority` pubkey verbatim with no validation that it is non-default or otherwise usable: [4](#0-3) 

### Impact Explanation
If the current authorized withdrawer mistakenly (or via a buggy/compromised CLI/wallet integration) sets the new authorized withdrawer to `Pubkey::default()` or another address without a corresponding keypair, the vote account's withdraw authority becomes permanently unusable — funds in the vote account (and the ability to reassign authorities) become irretrievable, exactly as described in the original report ("An incorrect fee wallet address, like the zero address, could cause funds to become irretrievable"). This is a state/fund-lock issue, not a privilege-escalation or consensus issue.

### Likelihood Explanation
Low. This can only occur if the legitimate authorized withdrawer signs a transaction setting the new authority to an invalid address — it is a self-inflicted misconfiguration path (comparable to the original report's own "Low" severity rating), not an attacker-controlled unauthorized mutation. No external validation exists to catch this class of mistake, whereas the parallel commission-collector code path in the same file already implements such checks.

### Recommendation
Add a validation step in `authorize()` (and in `initialize_nonce_account`) rejecting `Pubkey::default()` (and optionally other known-unusable/reserved addresses) as a new authorized voter/withdrawer/nonce authority, returning `InstructionError::InvalidArgument` in that case, consistent with the validation already applied to the vote commission collector via `NewCommissionCollector::validate_and_resolve_key`.

### Proof of Concept
1. Vote account `V` has `authorized_withdrawer = W`.
2. `W` signs a `VoteInstruction::Authorize(Pubkey::default(), VoteAuthorize::Withdrawer)` (or `AuthorizeChecked` variant) transaction.
3. `authorize()` at [1](#0-0)  accepts it unconditionally, setting `authorized_withdrawer = Pubkey::default()`.
4. No keypair exists for `Pubkey::default()`, so no future `Withdraw` instruction can ever be signed by the new "authority" — the vote account's lamports beyond rent-exempt minimum become permanently locked.

impl NewCommissionCollector<'_, '_> {
    /// Validates the collector per SIMD-0232 and returns its pubkey.
    ///
    /// The designated commission collector must either be equal to the vote
    /// account's address OR satisfy ALL of the following constraints:
    ///
    /// 1. Must be a system program owned account.
    /// 2. Must be rent-exempt.
    /// 3. Must not be a reserved account (checked via writable flag).
    pub fn validate_and_resolve_key(
        &self,
        vote_account: &BorrowedInstructionAccount,
        rent: &Rent,
    ) -> Result<Pubkey, InstructionError> {
        match self {
            NewCommissionCollector::VoteAccount => Ok(*vote_account.get_key()),
            NewCommissionCollector::NewAccount(collector_account) => {
                // 1. Must be a system program owned account.
                if collector_account.get_owner() != &system_program::id() {
                    return Err(InstructionError::InvalidAccountOwner);
                }

                // 2. Must be rent-exempt.
                if !rent.is_exempt(
                    collector_account.get_lamports(),
                    collector_account.get_data().len(),
                ) {
                    return Err(InstructionError::InsufficientFunds);
                }

                // 3. Must not be a reserved account (checked via writable flag).
                if !collector_account.is_writable() {
                    return Err(InstructionError::InvalidArgument);
                }

                Ok(*collector_account.get_key())
            }
        }
    }
}

pub(crate) fn initialize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    rent: &Rent,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Initialize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    match account.get_state::<Versions>()?.state() {
        State::Uninitialized => {
            let min_balance = rent.minimum_balance(account.get_data().len());
            if account.get_lamports() < min_balance {
                ic_msg!(
                    invoke_context,
                    "Initialize nonce account: insufficient lamports {}, need {}",
                    account.get_lamports(),
                    min_balance
                );
                return Err(InstructionError::InsufficientFunds);
            }
            let durable_nonce =
                DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
            let data = nonce::state::Data::new(
                *nonce_authority,
                durable_nonce,
                invoke_context
                    .environment_config
                    .blockhash_lamports_per_signature,
            );
            let state = State::Initialized(data);
            account.set_state(&Versions::new(state))
        }
