### Title
Zip extraction accepts absolute paths, `../` traversal, and unrestricted symlink targets, allowing arbitrary file write outside the extraction root - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive`/`extractZipFile` in `helpers/archives/zip_extract.go` writes each `zip.File.Name` directly to disk via `os.MkdirAll`, `os.OpenFile`, and `os.Symlink` without validating that the resolved path stays within the extraction root. The only existing check, `errorIfGitDirectory`, only blocks `.git` paths and does not stop absolute paths, `../` traversal, or symlinks pointing outside the root.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry: [1](#0-0) 

`extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches based on `file.Mode()`:
- For directories: `os.Mkdir(file.Name, ...)` [2](#0-1) 
- For symlinks: reads the link target from the entry's data and calls `os.Symlink(string(data), file.Name)` with no validation of either the link path or link target [3](#0-2) 
- For regular files: `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` [4](#0-3) 

None of these functions call `filepath.Clean`, check for `filepath.IsAbs`, reject `..` path segments, or verify that a resolved symlink target remains within the extraction directory. The only path check performed anywhere in the extraction pipeline is `errorIfGitDirectory`, which strictly checks whether the first path component (after `filepath.Clean`) is `.git` — it does nothing for absolute paths or traversal sequences: [5](#0-4) 

Go's `archive/zip` package (unlike the writer, which sanitizes names) does not sanitize `File.Name` on read — an attacker who builds a raw zip (bypassing `archive/zip.Writer`, e.g., writing the local file header/central directory manually) can set `Name` to `/etc/cron.d/x` or `../../evil`. This is confirmed by the existing test suite, which only exercises benign entries (`temporary_file.txt`, `.git/test_file`) and never a traversal or absolute path case — there is no test asserting rejection of such entries: [6](#0-5) 

Both cache download (`cache_extractor.go`) and artifact download (`artifacts_downloader.go`) invoke this same zip extraction path after a `network.requester.Do` (or similar) download of attacker-controllable archive content (cache key/artifact contents are fully attacker-controlled in a pipeline the attacker runs), so the archive bytes reaching `ExtractZipArchive` are untrusted, attacker-crafted content.

### Impact Explanation
An attacker who controls the contents of an uploaded cache or artifact archive (any pipeline author) can craft a zip whose entries use absolute paths or `../` sequences, or use a symlink entry pointing outside the extraction root, causing the Runner process to write/overwrite arbitrary files on the host filesystem (or inside the executor's filesystem) outside the intended build/cache root when that archive is later restored via `gitlab-runner cache-extractor` / `artifacts-downloader`. Depending on which user/permissions the Runner process runs as, this can lead to file overwrite, and in privileged/shell-executor contexts, code execution or persistence (e.g., cron files, SSH authorized_keys, shell profile files).

### Likelihood Explanation
Feasibility is high: no privileged access is required — a standard GitLab user who can run a pipeline and control an artifact/cache archive can trigger this. Crafting a raw zip with an arbitrary `File.Name` (absolute or containing `..`) is straightforward using a low-level zip writer or hand-crafted headers, since Go's `archive/zip` reader does not reject such names. The vulnerability is fully reproducible and deterministic — every extraction of a matching malicious archive triggers the write.

### Recommendation
In `extractZipFile` (and equivalently for symlink targets), before performing any filesystem operation:
1. Reject/skip entries with `filepath.IsAbs(file.Name)` true.
2. `filepath.Clean` the name and verify (e.g., via `filepath.Rel` against the extraction root, or ensuring the cleaned path does not start with `..` / is not equal to `..`) that the resulting path is confined to the target directory.
3. For symlink entries, additionally validate that the joined `(root, file.Name)` and the resolved target (`filepath.Join(filepath.Dir(target path), data)`) both stay within the root; reject symlinks with absolute targets or targets that escape the root after resolution.
4. Apply the same checks in `ExtractZipArchive` before calling `extractZipFile`, so unsafe entries are skipped/reported rather than silently written.

### Proof of Concept
```go
func TestExtractZipArchiveRejectsPathTraversal(t *testing.T) {
    tempFile, err := os.CreateTemp("", "archive")
    require.NoError(t, err)
    defer os.Remove(tempFile.Name())

    zw := zip.NewWriter(tempFile)
    // Manually craft a raw header with a traversal name, bypassing zip.Writer.Create's
    // own name sanitization by using CreateHeader with a raw Name field.
    fh := &zip.FileHeader{Name: "../evil.txt", Method: zip.Deflate}
    w, err := zw.CreateHeader(fh)
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())
    tempFile.Close()

    workDir := t.TempDir()
    extractDir := filepath.Join(workDir, "extract")
    require.NoError(t, os.Mkdir(extractDir, 0o755))

    // simulate extraction rooted at extractDir
    os.Chdir(extractDir)
    err = ExtractZipFile(tempFile.Name())

    // Expected (after fix): error or entry skipped, and file must NOT exist
    // outside extractDir.
    _, statErr := os.Stat(filepath.Join(workDir, "evil.txt"))
    assert.True(t, os.IsNotExist(statErr), "traversal entry must not be written outside extraction root")
}
```
Currently this test would fail (the file is written to `workDir/evil.txt`), demonstrating the escape; after applying the recommended path-confinement checks, the assertion should pass. A similar test with a symlink entry (`Mode: os.ModeSymlink`, data `"/root/.ssh/authorized_keys"`) should assert that no symlink is created pointing outside the root, or that extraction errors out for that entry.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
