### Title
ETH Transfer Griefing Causes Permanent Fund Lock in Bridge Vault - (File: bridge/evm/contracts/SuiBridge.sol)

### Summary
`SuiBridge._transferTokensFromVault` pushes ETH directly to the recipient address via `vault.transferETH(payable(recipientAddress), amount)`. Because `isTransferProcessed[message.nonce]` is only set **after** the transfer succeeds, a recipient contract that reverts on ETH receipt permanently prevents the bridge message from ever being marked processed, locking the ETH in the vault with no recovery path.

### Finding Description
In `SuiBridge.sol`, `_transferTokensFromVault` performs a direct ETH push for ETH-type bridge transfers:

```solidity
if (tokenID == BridgeUtils.ETH) {
    vault.transferETH(payable(recipientAddress), amount);
} else {
    vault.transferERC20(tokenAddress, recipientAddress, amount);
}
```

The caller, `transferBridgedTokensWithSignatures`, only marks the nonce consumed **after** the internal call returns:

```solidity
_transferTokensFromVault(
    message.chainID,
    tokenTransferPayload.tokenID,
    tokenTransferPayload.recipientAddress,
    erc20AdjustedAmount
);
// mark message as processed
isTransferProcessed[message.nonce] = true;
```

If `vault.transferETH` reverts — because the `recipientAddress` is a smart contract without a `receive()` or `fallback()` function — the entire transaction reverts. `isTransferProcessed[message.nonce]` is never written. Every subsequent retry of the same signed message will also revert. The ETH remains in the vault indefinitely with no on-chain mechanism to redirect it or let the user claim it via an alternative address. [1](#0-0) [2](#0-1) 

The same code path exists in `SuiBridgeV2._transferTokensFromVault`: [3](#0-2) 

### Impact Explanation
**Permanent fund lock (High/Medium).** Any ETH bridged from Sui to an Ethereum recipient address that is a smart contract without ETH-receive logic is irrecoverably locked in `BridgeVault`. There is no admin escape hatch, no alternative-address claim function, and no way to re-route the signed bridge message to a different recipient. The nonce is never consumed, so the message slot is also permanently wasted.

### Likelihood Explanation
**Low.** The scenario requires the recipient to be a contract that rejects raw ETH — a multisig, DAO treasury, or any contract deployed without a `receive()` function. This can occur accidentally (user copies a contract address instead of an EOA) or intentionally. The bridge UI cannot prevent it because the recipient address is embedded in the signed message before any EVM-side validation.

### Recommendation
Replace the push-payment model for ETH with a pull-payment (claim) pattern inside `BridgeVault`:

1. Instead of calling `payable(recipient).call{value: amount}("")` (or equivalent) immediately, store `pendingWithdrawals[recipient] += amount`.
2. Expose a public `claimETH()` function that lets the recipient withdraw at will.
3. Apply the same pattern to `SuiBridgeV2` and any future bridge versions.

This mirrors the standard OpenZeppelin `PullPayment` pattern and eliminates the griefing surface entirely.

### Proof of Concept
1. User calls `send_token` (Move side) specifying an Ethereum recipient that is a Gnosis Safe or any contract without `receive()`.
2. Bridge authorities co-sign the `TOKEN_TRANSFER` message.
3. Any caller invokes `transferBridgedTokensWithSignatures(signatures, message)`.
4. Execution reaches `vault.transferETH(payable(recipientAddress), amount)`.
5. The vault's raw-ETH send reverts because the recipient contract has no payable fallback.
6. The whole transaction reverts; `isTransferProcessed[nonce]` stays `false`.
7. Steps 3–6 repeat forever — every retry reverts.
8. The ETH is permanently locked in `BridgeVault`; the user has no recourse.

    function transferBridgedTokensWithSignatures(
        bytes[] memory signatures,
        BridgeUtils.Message memory message
    )
        external
        nonReentrant
        verifyMessageAndSignatures(message, signatures, BridgeUtils.TOKEN_TRANSFER)
        onlySupportedChain(message.chainID)
    {
        // verify that message has not been processed
        require(!isTransferProcessed[message.nonce], "SuiBridge: Message already processed");

        IBridgeConfig config = committee.config();

        BridgeUtils.TokenTransferPayload memory tokenTransferPayload =
            BridgeUtils.decodeTokenTransferPayload(message.payload);

        // verify target chain ID is this chain ID
        require(
            tokenTransferPayload.targetChain == config.chainID(), "SuiBridge: Invalid target chain"
        );

        // convert amount to ERC20 token decimals
        uint256 erc20AdjustedAmount = BridgeUtils.convertSuiToERC20Decimal(
            IERC20Metadata(config.tokenAddressOf(tokenTransferPayload.tokenID)).decimals(),
            config.tokenSuiDecimalOf(tokenTransferPayload.tokenID),
            tokenTransferPayload.amount
        );

        _transferTokensFromVault(
            message.chainID,
            tokenTransferPayload.tokenID,
            tokenTransferPayload.recipientAddress,
            erc20AdjustedAmount
        );

        // mark message as processed
        isTransferProcessed[message.nonce] = true;

        emit TokensClaimed(
            message.chainID,
            message.nonce,
            config.chainID(),
            tokenTransferPayload.tokenID,
            erc20AdjustedAmount,
            tokenTransferPayload.senderAddress,
            tokenTransferPayload.recipientAddress
        );
    }
```

    function _transferTokensFromVault(
        uint8 sendingChainID,
        uint8 tokenID,
        address recipientAddress,
        uint256 amount
    ) private whenNotPaused limitNotExceeded(sendingChainID, tokenID, amount) {
        address tokenAddress = committee.config().tokenAddressOf(tokenID);

        // Check that the token address is supported
        require(tokenAddress != address(0), "SuiBridge: Unsupported token");

        // transfer eth if token type is eth
        if (tokenID == BridgeUtils.ETH) {
            vault.transferETH(payable(recipientAddress), amount);
        } else {
            // transfer tokens from vault to target address
            vault.transferERC20(tokenAddress, recipientAddress, amount);
        }

        // update amount bridged
        limiter.recordBridgeTransfers(sendingChainID, tokenID, amount);
    }
```
