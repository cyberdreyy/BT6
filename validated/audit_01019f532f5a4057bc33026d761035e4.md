### Title
Non-atomic composition of bank / optimistically-confirmed-bank / block-commitment-cache reads causes misreported transaction confirmation status - (File: `rpc/src/rpc.rs`)

### Summary
The RToken bug arises because a user's redeem transaction is evaluated against basket/collateral state that changes ("basket refresh") between the time the transaction is submitted and the time it actually executes, so the redemption is settled against a mix of pre- and post-transition state, producing a wrong (and exploitable) result. The closest reachable, unprivileged analog in `agave` is in the JSON-RPC transaction-status path, where `JsonRpcRequestProcessor::get_transaction_status` composes a single `TransactionStatus` response from three independently-read, unsynchronized snapshots of validator state (`bank`, `optimistically_confirmed_bank`, `block_commitment_cache`). Because these reads are not taken atomically, a caller of `getSignatureStatuses`/`getSignatureStatus` can receive a `TransactionStatus` that mixes state from different points in time, misreporting the actual confirmation state of a transaction.

### Finding Description
`get_transaction_status` first obtains the signature's `(slot, status)` from a `bank` reference that was captured earlier by the caller (`get_signature_statuses` calls `self.bank(Some(CommitmentConfig::processed()))` once at [1](#0-0) ). It then independently re-fetches a *fresh* `optimistically_confirmed_bank` via `self.bank(Some(CommitmentConfig::confirmed()))` and separately locks `self.block_commitment_cache` to compute `confirmations` and `is_finalized`: [2](#0-1) 

Each of `bank`, `optimistically_confirmed_bank`, and `r_block_commitment_cache` is refreshed from live, concurrently-mutated validator state (`self.bank_forks`, `self.optimistically_confirmed_bank`, `self.block_commitment_cache`) via `JsonRpcRequestProcessor::bank` [3](#0-2) , which is continuously updated out-of-band by `AggregateCommitmentService::run` as votes/roots arrive [4](#0-3) . Because the three reads inside `get_transaction_status` happen at different instants relative to that background update stream, and because `get_signature_statuses` performs this composition once per signature in a loop over up to `MAX_GET_SIGNATURE_STATUSES_QUERY_ITEMS` signatures [5](#0-4) , root/commitment progression can happen between the `bank` status lookup and the later `block_commitment_cache`/`optimistically_confirmed_bank` lookups for the same or different signatures in the same call. This is structurally the same "check happens against state A, decision is finalized against state B" pattern that lets the RToken redemption use stale collateral data: here it lets a single RPC call assemble a `TransactionStatus` from a stale `bank`-derived slot paired with a newer `block_commitment_cache`/`optimistically_confirmed_bank` snapshot (or vice versa), producing an internally inconsistent report of `confirmations`/`confirmation_status` for the queried transaction.

### Impact Explanation
This is reachable by any unprivileged RPC client calling `getSignatureStatuses` — no special role is required. The impact is a wrong/misleading `TransactionStatus` returned to the caller (misreporting), which can cause client software (wallets, exchanges, `confirm_transaction_with_spinner`-style logic in `rpc-client/src/nonblocking/rpc_client.rs`) to treat a transaction as more or less finalized than it actually is, exactly analogous to how the reserve protocol lets a caller act on stale/inconsistent state.

### Likelihood Explanation
The three independent locks/state reads (`bank`, `optimistically_confirmed_bank`, `block_commitment_cache`) are taken back-to-back with no shared snapshot or version check, and commitment-cache updates happen continuously from `AggregateCommitmentService` in a separate thread, so the window for observing inconsistent combinations is present on every call, though the actual size of any observable discrepancy is normally small (bounded by how far commitment can advance during the handling of one RPC request).

### Recommendation
Capture a single, consistent snapshot of the relevant commitment state (root, highest_super_majority_root, optimistically-confirmed slot) once at the start of `get_transaction_status`/`get_signature_statuses`, and derive `bank`, `optimistically_confirmed_bank` lookups, and `is_finalized` checks from that single snapshot instead of independently re-reading `self.bank(...)` and `self.block_commitment_cache` at different points during the computation.

### Proof of Concept
1. Submit a transaction and call `getSignatureStatuses` for its signature just as the transaction's slot is crossing the `highest_super_majority_root` boundary (i.e., becoming finalized) and as `optimistically_confirmed_bank` is being updated concurrently by `OptimisticallyConfirmedBankTracker`/`AggregateCommitmentService`.
2. Because `get_transaction_status` reads `bank` (captured earlier), `optimistically_confirmed_bank` (read fresh), and `block_commitment_cache` (read fresh) at different instants, the returned `TransactionStatus.confirmation_status`/`confirmations` can reflect a mix of pre- and post-root-advance state rather than a single consistent point in time, matching the general TOCTOU pattern described in the referenced report where a user's action is settled against a blend of two different chain states.

    fn bank(&self, commitment: Option<CommitmentConfig>) -> Arc<Bank> {
        debug!("RPC commitment_config: {commitment:?}");

        let commitment = commitment.unwrap_or_default();
        if commitment.is_confirmed() {
            let bank = self
                .optimistically_confirmed_bank
                .read()
                .unwrap()
                .bank
                .clone();
            debug!("RPC using optimistically confirmed slot: {:?}", bank.slot());
            return bank;
        }

        let slot = self
            .block_commitment_cache
            .read()
            .unwrap()
            .slot_with_commitment(commitment.commitment);

        match commitment.commitment {
            CommitmentLevel::Processed => {
                debug!("RPC using the heaviest slot: {slot:?}");
            }
            CommitmentLevel::Finalized => {
                debug!("RPC using block: {slot:?}");
            }
            CommitmentLevel::Confirmed => unreachable!(), // SingleGossip variant is deprecated
        };

        let r_bank_forks = self.bank_forks.read().unwrap();
        r_bank_forks.get(slot).unwrap_or_else(|| {
            // We log a warning instead of returning an error, because all known error cases
            // are due to known bugs that should be fixed instead.
            //
            // The slot may not be found as a result of a known bug in snapshot creation, where
            // the bank at the given slot was not included in the snapshot.
            // Also, it may occur after an old bank has been purged from BankForks and a new
            // BlockCommitmentCache has not yet arrived. To make this case impossible,
            // BlockCommitmentCache should hold an `Arc<Bank>` everywhere it currently holds
            // a slot.
            //
            // For more information, see https://github.com/solana-labs/solana/issues/11078
            warn!(
                "Bank with {:?} not found at slot: {:?}",
                commitment.commitment, slot
            );
            r_bank_forks.root_bank()
        })

    pub async fn get_signature_statuses(
        &self,
        signatures: Vec<Signature>,
        config: Option<RpcSignatureStatusConfig>,
    ) -> Result<RpcResponse<Vec<Option<TransactionStatus>>>> {
        let search_transaction_history = config
            .map(|x| x.search_transaction_history)
            .unwrap_or(false);
        if search_transaction_history {
            self.check_if_transaction_history_enabled()?;
        }

        let bank = self.bank(Some(CommitmentConfig::processed()));
        let mut statuses: Vec<Option<TransactionStatus>> = vec![];

        for signature in signatures {
            let status = if let Some(status) = self.get_transaction_status(signature, &bank) {
                Some(status)
            } else if search_transaction_history {
                if let Some(status) = self
                    .blockstore
                    .get_rooted_transaction_status(signature)
                    .map_err(|_| Error::internal_error())?
                    .filter(|(slot, _status_meta)| {
                        slot <= &self
                            .block_commitment_cache
                            .read()
                            .unwrap()
                            .highest_super_majority_root()
                    })
                    .map(|(slot, status_meta)| {
                        let err = status_meta.status.clone().err();
                        TransactionStatus {
                            slot,
                            status: status_meta.status,
                            confirmations: None,
                            err,
                            confirmation_status: Some(TransactionConfirmationStatus::Finalized),
                        }
                    })
                {
                    Some(status)
                } else if let Some(bigtable_ledger_storage) = &self.bigtable_ledger_storage {
                    bigtable_ledger_storage
                        .get_signature_status(&signature)
                        .await
                        .map(Some)
                        .unwrap_or(None)
                } else {
                    None
                }
            } else {
                None
            };
            statuses.push(status);
        }
        Ok(new_response(&bank, statuses))
    }

    fn get_transaction_status(
        &self,
        signature: Signature,
        bank: &Bank,
    ) -> Option<TransactionStatus> {
        let (slot, status) = bank.get_signature_status_slot(&signature)?;

        let optimistically_confirmed_bank = self.bank(Some(CommitmentConfig::confirmed()));
        let optimistically_confirmed =
            optimistically_confirmed_bank.get_signature_status_slot(&signature);

        let r_block_commitment_cache = self.block_commitment_cache.read().unwrap();
        let confirmations = if r_block_commitment_cache.root() >= slot
            && is_finalized(&r_block_commitment_cache, bank, &self.blockstore, slot)
        {
            None
        } else {
            r_block_commitment_cache
                .get_confirmation_count(slot)
                .or(Some(0))
        };
        let err = status.clone().err();
        Some(TransactionStatus {
            slot,
            status,
            confirmations,
            err,
            confirmation_status: if confirmations.is_none() {
                Some(TransactionConfirmationStatus::Finalized)
            } else if optimistically_confirmed.is_some() {
                Some(TransactionConfirmationStatus::Confirmed)
            } else {
                Some(TransactionConfirmationStatus::Processed)
            },
        })
    }
