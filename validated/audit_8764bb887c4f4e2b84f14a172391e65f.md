### Title
JWT replay-cache check-then-act race in `Authorize` allows single-use JWT to authenticate two concurrent requests - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` enforces "one JWT = one request" by calling `jwtCache.isReplay(jti)` before verifying the signer and only calling `jwtCache.recordUsage(jti)` after all other checks succeed. Because `isReplay` and `recordUsage` acquire the cache's `sync.RWMutex` separately rather than atomically, two concurrent `Authorize` calls with the same JWT can both pass the replay check before either records usage, letting an attacker who intercepts/replays a valid JWT execute the same trigger request twice.

### Finding Description
`Authorize` is the JWT-based auth entrypoint for the gateway's HTTP-trigger workflow metadata path, reachable per-request whenever a workflow trigger request carrying a signed JWT arrives at the gateway handler: [1](#0-0) 

The replay-protection primitive is: [2](#0-1) 

`isReplay` takes an `RLock`, checks map membership, and releases the lock; `recordUsage` is called later, after the authorized-key lookup, under a separate `Lock`/`Unlock`. There is no single critical section covering "check-and-mark" — this is a classic TOCTOU (check-then-act) race. If two goroutines invoke `Authorize` with the same `token`/`jti` concurrently:
1. Goroutine A calls `isReplay(jti)` → `false` (not yet recorded).
2. Goroutine B calls `isReplay(jti)` → `false` (A hasn't called `recordUsage` yet).
3. Both A and B pass the signer/authorized-key checks (same signature, same workflow) and both call `recordUsage(jti)`.
4. Both `Authorize` calls return a valid `*gateway.AuthorizedKey`, meaning the single JWT authenticated two separate requests.

This breaks the invariant documented in the comment ("manages used JWT IDs to prevent replay attacks") and lets an attacker who has captured/replayed a legitimate JWT (e.g., from a public/observed request) fire two (or more, bounded by scheduling) concurrent copies of that request to the gateway, each treated as independently authorized.

### Impact Explanation
This allows JWT replay to duplicate another user's authenticated trigger request — an attacker in possession of a single valid, still-fresh JWT can cause it to authorize more than one workflow-trigger invocation instead of exactly one, which corresponds to a request-impersonation / authentication-bypass class impact (duplicate execution of an action gated by "one JWT, one use").

### Likelihood Explanation
Preconditions: the attacker must possess/observe a full, validly-signed JWT (not just the `jti`, since `utils.VerifyRequestJWT` verifies signature against the body) directed at a workflow they can already reach, and be able to send it twice concurrently to the gateway. No operator/admin access is required — any external party capable of sending two simultaneous gateway requests with the same captured token can trigger the race. The race window is real but requires precise timing (both `isReplay` calls must land before either `recordUsage`); it is feasible but not deterministic on every attempt, making it a moderate-likelihood, network-timing-dependent race rather than a trivially deterministic bypass.

### Recommendation
Make check-and-record atomic: add a single method like `checkAndMarkUsed(jti string) bool` that holds the write lock for the entire "check membership, then insert" sequence, and use it as an early gate in `Authorize` before performing signer/authorized-key validation. Return "replay detected" if the entry already existed.

### Proof of Concept
Go unit test in `workflow_metadata_handler_test.go`:
1. Construct a `WorkflowMetadataHandler` with a valid workflow ID registered with a signer's `AuthorizedKey`.
2. Generate one valid JWT token (fixed `jti`) signed by that authorized key for a given request.
3. Launch two goroutines that both call `h.Authorize(workflowID, token, req)` concurrently, synchronized via a barrier (e.g., a channel/`sync.WaitGroup` released simultaneously) to maximize race probability; run with `-race` and repeat in a loop (e.g., 1000 iterations) to reveal the race.
4. Assert that across repeated runs, exactly one of the two `Authorize` calls returns `nil, err` ("JWT token has already been used...") — flag failure (both succeeding) as reproducing the vulnerability.
5. Additionally add a direct unit test on `jwtReplayCache` calling `isReplay`/`recordUsage` from two goroutines with the same `jti` to demonstrate both can observe `isReplay() == false` before either calls `recordUsage`.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
