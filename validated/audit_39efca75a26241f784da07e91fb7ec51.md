### Title
Instant-withdrawal path in `requestWithdraw` skips management and performance fees, letting lenders exit fee-free when APR drops - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
The Footium bug class is an *inconsistent fee regime across two economically equivalent exit paths*: player sales carry EIP-2981 royalties while club sales (a bundled exit) carry none, so users route value through the fee-free path. In IdleCreditVault deployments the same asymmetry exists inside `IdleCDOEpochVariant.requestWithdraw`: the normal withdrawal-request path charges an upfront management fee plus net performance fee via `_totalWithdrawFees`, while the instant-withdrawal branch (taken whenever `unscaledApr` dropped by more than `instantWithdrawAprDelta` relative to `lastEpochApr`) escapes all fees entirely and receives a receipt for the full principal.

### Finding Description
In `IdleCDOEpochVariant.requestWithdraw` (`contracts/IdleCDOEpochVariant.sol:739-791`) there are two mutually exclusive branches:

- **Normal path** (lines 772-790): computes `(interest, diff) = _calcInterestWithdrawRequest(...)`, then `totalFees = _totalWithdrawFees(principal, interest)` and `pendingWithdrawFees += totalFees`. Per `_totalWithdrawFees`/`_calculateManagementFee` (lines ~901-905), the fee is `max(mgmtFee, interest - netGainAfterFees)` — i.e., the management fee on principal is charged **even when interest is zero**, covering the remaining buffer plus the next epoch (`_withdrawRequestManagementFeeDuration`, lines 925-931).
- **Instant path** (lines 761-769): when `_isInstantWithdrawEnabled()` and `lastEpochApr > creditVault.unscaledApr() + instantWithdrawAprDelta`, the CDO calls `creditVault.requestInstantWithdraw(_underlyings, msg.sender)` where `_underlyings` is the full principal from `_trancheToUnderlyings`. No interest is calculated, no `_totalWithdrawFees` is invoked, and `pendingWithdrawFees` is not incremented.

`IdleCreditVault.requestInstantWithdraw` (`contracts/strategies/idle/IdleCreditVault.sol:356-375`) then mints the user a 1:1 receipt for the gross `_amount`, and `claimInstantWithdrawRequest` (lines 380-393) pays it out at par via `_transferFundedClaim`. At no point is the management fee — which the normal path charges upfront on principal for epoch + remaining-buffer duration — applied to the instant path.

So two lenders requesting a withdrawal in the same block get different treatment solely based on whether the APR happened to drop: one pays `principal * managementFee * (epochDuration + remainingBuffer) / YEAR` upfront, the other pays nothing.

### Impact Explanation
Loss of protocol yield: the `feeReceiver` permanently loses the upfront management fee on every instant withdrawal. The loss is quantified as `principal * managementFeeRate * _withdrawRequestManagementFeeDuration() / YEAR` per request — the same amount explicitly collected as `pendingWithdrawFees` on the normal path and forwarded to `feeReceiver` at `stopEpoch` (per tests `testRequestWithdrawChargesManagementFeeUpfront`, `testRequestWithdrawDuringBufferChargesRemainingBufferManagementFee` in `test/foundry/IdleCreditVault.t.sol`). Like the accepted Footium medium, the harm is protocol revenue bypassed through a parallel exit path, not insolvency. This maps to "theft of unclaimed yield" for `feeReceiver`, scaled by TVL that exits instantly after each APR cut.

### Likelihood Explanation
The trigger is an APR decrease exceeding `instantWithdrawAprDelta`, set by the honest manager/borrower at `startEpoch`/rate renegotiation — an unprivileged lender cannot force it, but can sequence around it: the moment `unscaledApr` drops, any KYC-passed tranche holder (`allowAAWithdrawRequest`/`allowBBWithdrawRequest` and `isWalletAllowed` are still required) can call `requestWithdraw` and exit fee-free. In fixed-rate credit vaults APR reductions are a normal operational event (renegotiated terms), so the window recurs. No existing guard compensates: `_skimDonatedAssets` and `_updateAccounting` run identically, and `pendingInstantWithdraws`/`instantWithdrawsRequestsByEpoch` track only the funded basis, never fees.

### Recommendation
Apply `_totalWithdrawFees(principal, 0)` (or at minimum `_calculateManagementFee(principal, _withdrawRequestManagementFeeDuration())`) to `_underlyings` before calling `requestInstantWithdraw`, credit the result to `pendingWithdrawFees`, and pass the net amount as the receipt — mirroring the normal branch. If instant exit is intended to be fee-free because no waiting-epoch yield accrues, the management-fee duration for normal requests should be re-derived so both paths are consistent; otherwise document the asymmetry explicitly.

### Proof of Concept
Foundry fork PoC sketch (against `test/foundry/IdleCreditVault.t.sol` harness):

```solidity
function testInstantWithdrawSkipsFees() external {
    uint256 amount = 100_000 * ONE_SCALE;
    _setFeeParams(TL_MULTISIG, 10_000, FULL_ALLOC, cdoEpoch.managementFee()); // 10% perf fee
    _setManagementFee(1_000); // 1% mgmt fee

    uint256 trancheAmount = idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _startEpochAndCheckPrices(0);

    // manager lowers APR below lastEpochApr - instantWithdrawAprDelta
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(newUnscaledApr, newScaledApr);

    uint256 principal = trancheAmount * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;
    uint256 expectedMgmtFee = _calcManagementFee(principal, 1_000, epochDuration + remainingBuffer);

    uint256 feesBefore = cdoEpoch.pendingWithdrawFees();
    uint256 requested = cdoEpoch.requestWithdraw(trancheAmount, address(AAtranche));

    // instant path: full principal receipt, zero fees accrued
    assertEq(requested, principal);
    assertEq(cdoEpoch.pendingWithdrawFees(), feesBefore); // expectedMgmtFee never charged
}
```

Uncertainty I could not fully resolve in this pass: whether `instantWithdrawAprDelta` gating is documented as intentionally fee-free (a design-choice defense, mirroring the first Footium escalation) and whether the prefunded variant overrides this branch. The inconsistency itself is directly visible in the code: `_totalWithdrawFees` is only reachable on the non-instant branch.
