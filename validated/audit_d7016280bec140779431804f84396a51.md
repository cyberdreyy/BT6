### Title
v1 signer's `DuplicateBlockFound` guard checks only *globally*-accepted blocks, letting a signer sign a second competing tenure-start block in the same tenure - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
The v1 signer's tenure-change duplicate-block check queries `get_last_globally_accepted_block`, while the equivalent v2 check was hardened (per an explicit regression test) to use `get_last_signed_block`, which also covers `LocallyAccepted`/`PreCommitted` states. This is the same "incomplete denylist" bug class as the external report: a safety check enumerates only a subset of the states/paths that must be blocked (global acceptance) instead of the full set that actually represents "we have already committed to a first block in this tenure" (local + pre-committed + global), leaving a gap a miner can exploit.

### Finding Description
In `stacks-signer/src/chainstate/v1.rs`, `validate_tenure_change_payload` guards against a miner replaying/forking the tenure-start block by checking: [1](#0-0) 
This uses `get_last_globally_accepted_block(&block.header.consensus_hash)` — i.e., it only detects a duplicate if a *prior* tenure-start block already reached full (globally-accepted) consensus.

The v2 equivalent, `validate_tenure_change_payload` in `chainstate/v2.rs`, was fixed to use `get_last_signed_block` instead: [2](#0-1) 
and there is an explicit regression test proving the old (global-only) behavior was a bug: [3](#0-2) 
The test's own comment states plainly: *"previously, the check used `get_last_globally_accepted_block`, which would miss blocks in `LocallyAccepted` or `PreCommitted` state and incorrectly allow a duplicate tenure change."*

This means: for a fleet of signers still running the v1 protocol path (`state_version.uses_global_state()` false — see `check_block_against_state` dispatch), the exact same flaw the v2 test fixes is still present in v1's code path, since v1.rs was not updated to match. [4](#0-3) 

### Impact Explanation
Each signer independently decides whether to sign a tenure-start (`TenureChange`+`Coinbase`) block. The `DuplicateBlockFound` check exists precisely to enforce the invariant "we do not sign two different first-blocks for the same tenure." Under the v1 path, a signer that has already `LocallyAccepted` or `PreCommitted` to tenure-start block A (but that block has not yet crossed the 70% signature threshold to become globally accepted) will **not** detect a second, different tenure-start block B for the same tenure as a duplicate, because the check only looks for globally-accepted blocks. The signer can then proceed to validate and potentially sign block B as well.

If different subsets of v1 signers end up pre-committed/locally-accepted to A and signed to B (or vice versa), this breaks the "one approved/signed block per tenure per signer" equality and can contribute to two conflicting blocks each accumulating partial signature weight in the same tenure — a signer signing a conflicting block, which is explicitly in the Critical impact bucket for this scan.

### Likelihood Explanation
This is reachable by a single miner (one slot) simply proposing two different tenure-start blocks for the same tenure — no majority or additional signer key is needed. It requires only that some v1-protocol signers have locally-accepted/pre-committed the first proposal without yet reaching global acceptance, which is an ordinary window in the protocol's threshold-based signing flow (`check_block_against_state` → `check_block_against_local_state` for v1). Since v1 remains a supported/active code path for signers who haven't or can't move to global-state consensus, this is a real, not purely theoretical, path.

### Recommendation
Update `validate_tenure_change_payload` in `stacks-signer/src/chainstate/v1.rs` to use `get_last_signed_block` (or equivalently check `LocallyAccepted`/`PreCommitted`/`GloballyAccepted` states) instead of `get_last_globally_accepted_block`, mirroring the fix already applied to the v2 path, so that the duplicate-tenure-start-block guard is consistent and complete across both protocol versions.

### Proof of Concept
1. A miner proposes tenure-start block A for tenure T. A quorum of v1 signers begins locally accepting/pre-committing to A but weight has not yet reached the 70% threshold for global acceptance.
2. The same miner (or a colluding relay) proposes a second, different tenure-start block B for the same tenure T (different chosen transactions/timestamp), before A reaches global acceptance.
3. A v1 signer that has locally accepted/pre-committed A receives proposal B. `check_block_against_local_state` → `validate_tenure_change_payload` calls `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)`, which returns `None` because A is only `LocallyAccepted`/`PreCommitted`, not globally accepted.
4. No `DuplicateBlockFound` rejection is returned; the signer proceeds to consider B for validation/signing, in contradiction with its own already-committed view of A for the same tenure — exactly the scenario the v2 regression test (`check_tenure_change_rejects_when_locally_accepted_block_exists`) was added to prevent, but which remains unfixed in the v1 path.

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}
