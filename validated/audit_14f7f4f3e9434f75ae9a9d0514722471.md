### Title
Zip slip / path traversal and unrestricted symlink target write in zip extraction - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipFile`, `extractZipDirectoryEntry`, `extractZipFileEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` use `file.Name` (and, for symlinks, attacker-supplied link-target `data`) directly with `os.MkdirAll`, `os.OpenFile`, and `os.Symlink`, with no `..`/absolute-path validation and no chroot/prefix check. This is unlike the tar+zstd extractor, which explicitly resolves paths against `e.dir` and rejects anything outside it.

### Finding Description
`ExtractZipArchive` iterates `archive.File` entries and calls `extractZipFile(file)` for each [1](#0-0) . `extractZipFile` does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches by mode to create directories, symlinks, or regular files, all using `file.Name` unmodified [2](#0-1) . `extractZipFileEntry` removes any existing file at `file.Name` and opens/writes it with `O_CREATE|O_TRUNC` [3](#0-2) . `extractZipSymlinkEntry` reads the symlink target from the archived file content (`data`) and calls `os.Remove(file.Name)` followed by `os.Symlink(string(data), file.Name)` — both the link path and the link target are fully attacker-controlled, with no validation that `data` stays within any root [4](#0-3) .

The only pre-extraction check is `errorIfGitDirectory`, which only rejects `.git`-prefixed paths and is not a general traversal guard [5](#0-4) [6](#0-5) . There is no `filepath.Abs`/`strings.HasPrefix(path, dir+sep)` check comparable to the tar+zstd extractor's chroot enforcement [7](#0-6) .

This code path is reachable via the `ziplegacy` extractor, whose `Extract` method simply builds a `zip.Reader` from attacker-supplied bytes and calls `archives.ExtractZipArchive(zr)` — notably, the `dir` field passed into `NewExtractor` is stored but never used or enforced [8](#0-7) . `ziplegacy` is registered as the default Zip/ZipZstd extractor and is used for cache/artifact download/extraction unless `FF_USE_FASTZIP` is enabled (which swaps in `fastzip`) [9](#0-8) . Cache archives and artifact zips are content an unprivileged pipeline author fully controls (they can craft a custom cache/artifact upload with malicious entries), so `file.Name` and symlink target `data` are attacker inputs reaching this unguarded extraction path.

### Impact Explanation
A crafted zip cache/artifact with an entry `Name` containing `../../` sequences (or an absolute path) allows writing/overwriting arbitrary files relative to the process's current working directory, outside the intended cache/build directory. Similarly, a zip symlink entry can point anywhere on the filesystem the runner process can write, and subsequent writes through that symlink (in the same or a later extraction/build step) can overwrite files outside the job root. This can lead to overwriting files later executed by the runner or job (e.g. build scripts), a path to code execution, and violates the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Feasible and reproducible by any pipeline author: caches and artifacts are ordinary zip files whose entries are fully attacker-controlled; no special privileges beyond running a normal CI job are required. The only limiting factor is the effective permissions of the runner process's OS user and the CWD at the time of extraction, but the code itself contains no path/target validation, so exploitation is bounded only by OS-level write permissions of the runner user, not by any Runner-side control.

### Recommendation
Validate `file.Name` and resolve it against the intended extraction root (as the tar+zstd extractor does) before any `Mkdir`/`OpenFile`/`Symlink` call: compute `filepath.Abs(filepath.Join(dir, file.Name))` and reject if the result doesn't have `dir` as prefix. For symlink entries, also validate/reject targets that resolve outside the extraction root (or reject absolute symlink targets and `..`-escaping relative targets). Ensure the `dir` parameter passed to `ziplegacy.NewExtractor` is actually threaded through to `ExtractZipArchive`/`extractZipFile` and enforced.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Build an in-memory `zip.Writer` with an entry named `../../evil.txt` containing arbitrary bytes, and another symlink-mode entry named `link` whose content (target) is `/etc/passwd` (or an absolute path outside a temp test root).
2. Change CWD (or extraction root) to a fresh temp subdirectory `root/`.
3. Call `archives.ExtractZipArchive(zipReader)`.
4. Assert: `evil.txt` is created outside `root/` (e.g. at `root/../evil.txt`), proving traversal; and assert that `root/link` is a symlink pointing to `/etc/passwd` (an absolute out-of-root path), proving the symlink target is unrestricted.
Both assertions succeeding demonstrates the missing path/target validation compared to `tarzstd`'s chroot check.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
