### Title
Unsanitized `requestedURI` passed to `rest.Request.Suffix()` enables proxy-path traversal beyond the job's own service/namespace scope - ([File: executors/kubernetes/service_proxy.go])

### Summary
`serviceEndpointRequest` builds a Kubernetes API `services/proxy` sub-resource request by concatenating a fixed namespace/service/port with a completely attacker-supplied `requestedURI` via `.Suffix(requestedURI)` [1](#0-0) . No validation, cleaning, or traversal-rejection is applied to `requestedURI` before it is handed to `rest.Request`, whose `Suffix()` implementation joins the string via `path.Join` semantics, so `../../` sequences can walk the constructed URL path back out of the `namespaces/<ns>/services/<scheme>:<name>:<port>/proxy` prefix and re-target a different resource path on the same API server.

### Finding Description
`requestedURI` is attacker-controlled: it is the trailing path segment of a request to the job's session server proxy endpoint, parsed verbatim by `parseProxyParams` from `r.URL.Path` with only a non-empty check on service/port, and no cleaning of the URI segment [2](#0-1) . It is passed unchanged through `proxyHandler` → `Requester.ProxyRequest` → `executor.ProxyRequest` → `proxyHTTPRequest`/`proxyWSRequest` → `serviceEndpointRequest` [3](#0-2) [4](#0-3) [5](#0-4) .

The only checks performed before the request is issued are: (1) that `port` matches one of the job's own registered `proxy.Port` entries via `PortByNameOrNumber` [6](#0-5) , and (2) that the job's own pod is `Running`/ready [7](#0-6) . Neither check inspects `requestedURI` for `..`, absolute-path markers, or other traversal content. This is in contrast to other user-controlled path-like values in this codebase (e.g. cache keys), which are explicitly sanitized against traversal with `cachekey.Sanitize` before use [8](#0-7) . No equivalent sanitization exists for `requestedURI` in `service_proxy.go`.

The existing test suite only exercises benign suffixes (e.g. `"foobar"`) and confirms the resulting URL is `.../services/<scheme>:<name>:<port>/proxy/foobar` [9](#0-8) ; there is no test asserting that the resulting request URL stays confined to `s.pod.Namespace`/the selected service when `requestedURI` contains traversal sequences, so this class of input is unguarded and untested.

Because `rest.Request.Suffix()` in client-go joins the suffix onto the already-built path prefix using `path.Clean`/`path.Join` semantics (standard client-go behavior), a sufficient number of `../` segments in `requestedURI` collapses preceding path components — including the `namespaces/<ns>` and `services/<scheme>:<name>:<port>/proxy` segments that are supposed to hard-scope the request to the job's own namespace and declared service. An attacker who legitimately owns a running job (and therefore has access to that job's session token/port-forwarding UI, which is exactly the feature this code implements) can supply a crafted `requestedURI` to redirect the underlying Kubernetes REST call to a different `services/<name>:<port>/proxy` target, and — if the runner's own Kubernetes service account has RBAC broader than the single job namespace — to a different namespace.

### Impact Explanation
Within the runner's own operating namespace, this allows a job author to reach the `services/proxy` sub-resource of *any* Service object in that namespace via the runner's Kubernetes credentials, not just the service(s)/alias(es) they declared for their own job — violating the invariant that the session-scoped proxy only reaches the caller's own pod/service. If the runner's service account RBAC is broader than namespace-scoped (cluster role or multi-namespace bindings), the same flaw extends the reach to other namespaces' services, an SSRF-style pivot inside the cluster using the runner's own credentials. The severity of the cross-namespace portion is gated by the RBAC granted to the runner's service account, which is an operator choice; the same-namespace traversal (reaching non-declared services within the job's own namespace) is unconditional and does not depend on any extra admin misconfiguration.

### Likelihood Explanation
Preconditions are met by any normal, unprivileged pipeline author: they need only a running job on the Kubernetes executor with the session server enabled (used for the standard "Web Terminal"/port-forwarding feature), and knowledge of their own job's session token, which GitLab legitimately provides to job owners for this exact proxy feature. Crafting a `requestedURI` containing `../` segments is trivial and fully attacker-controlled from the HTTP path. The bug is deterministically reproducible since there is no code path that rejects or cleans traversal sequences.

### Recommendation
Sanitize `requestedURI` in `serviceEndpointRequest` (or earlier, in `session.parseProxyParams`/`ProxyRequest`) before passing it to `Suffix()`: reject or strip `.`/`..` path segments and leading `/` using `path.Clean` plus an explicit rejection of any `..` segment (mirroring the approach already used in `cache/cachekey.Sanitize`), and add a unit test asserting that `serviceEndpointRequest`'s resulting `rest.Request.URL()` always retains the exact `namespaces/<s.pod.Namespace>/services/<scheme>:<serviceName>:<port>/proxy` prefix regardless of `requestedURI` content.

### Proof of Concept

```go
func TestServiceEndpointRequest_PathTraversalIsRejected(t *testing.T) {
    ex := newExecutor()
    ex.pod = &api.Pod{ObjectMeta: metav1.ObjectMeta{Name: "job-pod", Namespace: "job-ns"}}
    ex.kubeClient = testKubernetesClient(...)

    port := proxy.Port{Number: 80, Protocol: "http"}
    req, err := ex.serviceEndpointRequest(http.MethodGet, "my-service",
        "../../../../namespaces/other-ns/services/http:other-svc:80/proxy/secret", port)
    require.NoError(t, err)

    u := req.URL().Path
    // Expected (fixed) behavior: traversal must not escape the job's own namespace/service.
    assert.Contains(t, u, "/namespaces/job-ns/services/http:my-service:80/proxy")
    assert.NotContains(t, u, "other-ns")
    assert.NotContains(t, u, "other-svc")
}
```
Running this against the current implementation is expected to fail the `assert.Contains(t, u, "/namespaces/job-ns/...")`/`NotContains` assertions, demonstrating that the constructed URL path escapes the intended namespace/service scope.

```go
func (s *executor) ProxyRequest(
	w http.ResponseWriter,
	r *http.Request,
	requestedURI string,
	port string,
	settings *proxy.Settings,
) {
	logger := logrus.WithFields(logrus.Fields{
		"uri":      r.RequestURI,
		"method":   r.Method,
		"port":     port,
		"settings": settings,
	})

	portSettings, err := settings.PortByNameOrNumber(port)
	if err != nil {
		logger.WithError(err).Errorf("port proxy %q not found", port)
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	if !s.servicesRunning(s.Context) {
		logger.Errorf("services are not ready yet")
		http.Error(w, http.StatusText(http.StatusServiceUnavailable), http.StatusServiceUnavailable)
		return
	}

	if websocket.IsWebSocketUpgrade(r) {
		proxyWSRequest(s, w, r, requestedURI, portSettings, settings, logger)
		return
	}

	proxyHTTPRequest(s, w, r, requestedURI, portSettings, settings, logger)
}
```

```go
func (s *Session) proxyHandler(w http.ResponseWriter, r *http.Request) {
	serviceName, port, requestedURI, ok := parseProxyParams(strings.TrimPrefix(r.URL.Path, s.Endpoint+"/proxy/"))
	if !ok {
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	logger := s.log.WithField("uri", r.RequestURI)
	logger.Debug("Proxy session request")

	serviceProxy := s.proxyPool[serviceName]
	if serviceProxy == nil {
		logger.Warn("Proxy not found")
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	if serviceProxy.ConnectionHandler == nil {
		logger.Warn("Proxy connection handler is not defined")
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	serviceProxy.ConnectionHandler.ProxyRequest(w, r, requestedURI, port, serviceProxy.Settings)
}
```

```go
// parseProxyParams returns the service, port and requestedURI
// from a proxy path. Service and port are not optional.
func parseProxyParams(path string) (service string, port string, uri string, ok bool) {
	p := strings.SplitN(path, "/", 3)
	switch len(p) {
	case 2:
		return p[0], p[1], "", p[0] != "" && p[1] != ""
	case 3:
		return p[0], p[1], p[2], p[0] != "" && p[1] != ""
	}
	return "", "", "", false
}
```

```go
// Sanitize validates and normalises a cache key.
// Cache keys may contain path separators. The function:
//   - decodes URL-encoded '/' (%2f) and '.' (%2e) characters
//   - replaces all '\' with '/'
//   - resolves path traversals (., ..) within a virtual root
//   - strips trailing whitespace from the rightmost path segments,
//     removing any that become empty after trimming
func Sanitize(cacheKey string) (string, error) {
	if cacheKey == "" {
		return "", nil
	}

	// Decode percent-encoded chars and normalise separators, then
	// resolve traversals against a virtual root so ".." can never
	// escape beyond the root.
	cleaned := path.Clean("/" + normaliser.Replace(cacheKey))

	// Strip the leading "/" we added, split into segments, then walk
	// backwards trimming trailing whitespace from the rightmost
	// segments—dropping any that become empty.
	parts := strings.Split(cleaned[1:], "/")
	n := len(parts)
	for n > 0 {
		parts[n-1] = strings.TrimRightFunc(parts[n-1], unicode.IsSpace)
		if parts[n-1] != "" {
			break
		}
		n--
	}

	key := strings.Join(parts[:n], "/")

	if key == "" {
		return "", fmt.Errorf("cache key %q could not be sanitized", cacheKey)
	}

	return key, nil
```
