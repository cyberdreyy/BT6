### Title
Gateway routes legacy JSON-RPC requests to any DON's handler based solely on attacker-supplied `DonId`, with no verification that the message sender is a member of that DON - ([File: core/services/gateway/gateway.go])

### Summary
`gateway.ProcessRequest` selects the target handler purely by looking up `msg.Body.DonId` in the `g.handlers` map after validating only the message's self-consistency (`msg.Validate()`, which just checks field lengths/format and extracts the signer address) — it never checks whether the extracted signer is a member of, or otherwise authorized for, the DON identified by `DonId`. Any holder of an ECDSA key can therefore get their request routed into `h.HandleLegacyUserMessage` for an arbitrary DON they were never provisioned into.

### Finding Description
In `gateway.ProcessRequest`, for legacy requests (`msg.Body.DonId != ""`):
```go
isLegacyRequest = true
if err = msg.Validate(); err != nil { ... }
handlerKey = msg.Body.DonId
h, ok = g.handlers[handlerKey]
if !ok { return newError(..., "Unsupported DON ID: "+handlerKey) }
...
err = h.HandleLegacyUserMessage(ctx, msg, callback)
``` [1](#0-0) 

`msg.Validate()` (`core/services/gateway/api/message.go`) only checks field lengths/null-byte suffixes and calls `ExtractSigner()` to populate `msg.Body.Sender` from the signature — it does not check DON membership at all: [2](#0-1) 

The lookup `g.handlers[handlerKey]` is a static map from configured DON IDs to their handlers, built at gateway startup — reaching a DON's handler requires only knowing/guessing its `DonId` string, which is not a secret (DON IDs are typically documented/public identifiers).

Once inside the capabilities handler, `HandleLegacyUserMessage` explicitly defers any allowlist enforcement:
```go
// TODO: apply allowlist and rate-limiting here
if msg.Body.Method != MethodWebAPITrigger { ... }
...
for _, member := range h.donConfig.Members {
    err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
}
``` [3](#0-2) 

This confirms the exploit path end-to-end: an attacker generates any ECDSA keypair, signs a well-formed legacy `Message` with `Body.DonId` set to a target DON they have no relationship to, sends it to the gateway HTTP endpoint, and the gateway forwards it straight to that DON's handler, which then broadcasts the (unauthenticated-as-far-as-DON-membership) trigger payload to every node of that DON. This is directly demonstrated by the existing test `TestGateway_LegacyRequest_HandlerResponse`, which signs with a freshly generated `crypto.GenerateKey()` key (never provisioned anywhere) and DonId `"testDON"`, and the mock handler for `testDON` is invoked and returns a normal success response: [4](#0-3) 

### Impact Explanation
This allows request impersonation / unauthorized triggering of a DON's workflow pipeline: an attacker with no DON membership can inject `web_api_trigger` messages that get forwarded to all nodes of a target DON, bypassing any expectation that only registered/authorized senders can reach a DON's message-handling logic. The explicit `// TODO: apply allowlist and rate-limiting here` comment confirms the sender-level authorization gate that should stop this is not implemented, so the only remaining defense is whatever validation nodes perform downstream (outside this repo/handler), meaning gateway-side defense-in-depth for DON-scoped access is absent.

### Likelihood Explanation
Highly feasible and repeatable: the attacker needs only an ECDSA keypair (self-generated, free) and knowledge of the target `DonId` string, which is not treated as a secret in the codebase (DON IDs appear in configuration and are meant to be referenced by legitimate external senders too). No credentials, node access, or prior provisioning are required — this is directly reproducible via the existing test harness pattern in `gateway_test.go`.

### Recommendation
Enforce authorization at (or before) the routing step in `gateway.ProcessRequest`, or at minimum in each handler's `HandleLegacyUserMessage`/`HandleJSONRPCUserMessage`: verify that `msg.Body.Sender` (the recovered signer) is present in that specific DON's configured allowlist (e.g., `donConfig.Members`, or a separate authorized-senders/workflow-owner allowlist) before dispatching the message to node(s). Implement the currently deferred `// TODO: apply allowlist and rate-limiting here` check in `core/services/gateway/handlers/capabilities/handler.go` so requests from senders not authorized for that DON/method are rejected with an authorization error instead of being forwarded.

### Proof of Concept
Go integration test plan (extends existing `gateway_test.go` patterns):
1. Configure a gateway with two DONs, `donA` and `donB`, each with distinct mock handlers and distinct member allowlists (e.g., `donB.Members` containing only pre-provisioned keys).
2. Generate a fresh, never-provisioned ECDSA key `attackerKey` (not present in `donB`'s config/members).
3. Build and sign a legacy `api.Message` with `Body.DonId = "donB"` using `attackerKey` via `msg.Sign(attackerKey)`, encode via `api.JsonRPCCodec{}.EncodeLegacyRequest`.
4. Call `gw.ProcessRequest(ctx, rawRequest, "")`.
5. Assert that `donB`'s mock handler's `HandleLegacyUserMessage` was invoked (via `mock.AssertCalled`) despite `attackerKey`'s address never appearing in `donB`'s member/allowlist configuration, and that the response status is 200 (success), demonstrating the DON-scoped authorization bypass.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func TestGateway_LegacyRequest_HandlerResponse(t *testing.T) {
	t.Parallel()

	gw, handler := newGatewayWithMockHandler(t)
	handler.On("HandleLegacyUserMessage", mock.Anything, mock.Anything, mock.Anything, mock.Anything).Return(nil).Run(func(args mock.Arguments) {
		msg := args.Get(1).(*api.Message)
		callback := args.Get(2).(handlers.Callback)
		// echo back to sender with attached payload
		msg.Body.Payload = []byte(`{"result":"OK"}`)
		msg.Signature = ""
		codec := api.JsonRPCCodec{}
		err := callback.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
		require.NoError(t, err)
	})

	method := "request"
	req := newSignedLegacyRequest(t, "abcd", method, "testDON", []byte{})
	response, statusCode := gw.ProcessRequest(t.Context(), req, "")
	requireJSONRPCResult(t, method, response, "abcd",
		`{"signature":"","body":{"message_id":"abcd","method":"request","don_id":"testDON","receiver":"","payload":{"result":"OK"}}}`)
	require.Equal(t, 200, statusCode)
}
