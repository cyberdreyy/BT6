### Title
Missing edit/admin-role authorization on `DELETE /v2/bridge_types/:BridgeName` allows run-role session to delete unassociated bridges - ([File: core/web/bridge_types_controller.go])

### Finding Description
`BridgeTypesController.Destroy` performs the bridge lookup, checks `FindJobIDsWithBridge` for v2 pipeline associations, and if none are found calls `orm.DeleteBridgeType` directly — with no role check anywhere inside the handler itself. [1](#0-0) 

Compare this to the GraphQL mutation resolver for the same operation, `Resolver.DeleteBridge`, which explicitly calls `authenticateUserCanEdit(ctx)` before doing anything else — enforcing that only Edit/Admin role sessions can delete a bridge. [2](#0-1) 

The REST `v2` API session middleware (`sessions.Sessions` + `auth.AuthenticateGQL`/session cookie auth wired in `NewRouter`) only validates that a request carries a valid authenticated session — it does not gate on the user's `Role` (Admin/Edit/Run/View) the way the GraphQL layer's `authenticateUserCanEdit` helper does. [3](#0-2) 

Because `Destroy` never checks the caller's role, and the router only requires a valid authenticated session to reach the handler, a user whose session has the "Run" role (which per the intended multi-user RBAC model should be limited to job execution, not destructive mutation of bridges) can successfully issue `DELETE /v2/bridge_types/:BridgeName` and delete any bridge not referenced by a v2 job — the `jobsUsingBridge` guard only protects bridges still wired into v2 pipeline specs, not bridges referenced by legacy/v1 job specs or other out-of-band consumers.

### Impact Explanation
A Run-role principal can destructively mutate node configuration state (deleting a bridge and its `IncomingToken`) that they should not be authorized to modify under the node's RBAC model. This causes denial-of-service for any external integration or legacy job relying on that bridge indirectly (since `FindJobIDsWithBridge` only scans v2 pipeline task specs), and represents an authorization-exactness violation: a lower-privileged role performing an Edit/Admin-tier destructive action.

### Likelihood Explanation
Precondition is simply possessing valid Run-role session credentials — no admin/host access needed. The request is a single unauthenticated-role-check REST call (`DELETE /v2/bridge_types/{name}`), fully reproducible and repeatable against any bridge name not currently wired into a v2 job.

### Recommendation
Add an explicit role check (equivalent to GraphQL's `authenticateUserCanEdit`) inside `BridgeTypesController.Destroy` (and ideally `Create`/`Update`) or wrap the `/v2/bridge_types` DELETE/POST/PATCH routes in `core/web/router.go` with a `RequiresEditRole`/`RequiresAdminRole` middleware, consistent with the protection already present on the GraphQL `DeleteBridge` mutation.

### Proof of Concept
1. In `core/web/bridge_types_controller_test.go`, create a session with `sessions.UserRoleRun`.
2. Create a bridge via an Admin session (or fixture) that is not referenced by any v2 job.
3. Using the Run-role session's authenticated client, call `client.Delete("/v2/bridge_types/" + bridgeName)`.
4. Assert the response is `401`/`403` (expected if fixed) rather than `200`.
5. Assert `BridgeORM.DeleteBridgeType` was not invoked (mock/spy or verify bridge still exists via `FindBridge` after the call) — currently this assertion fails, confirming the bridge is deleted despite the Run-role session.

func (btc *BridgeTypesController) Destroy(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error searching for bridge: %w", err))
		return
	}
	jobsUsingBridge, err := btc.App.JobORM().FindJobIDsWithBridge(ctx, name)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error searching for associated v2 jobs: %w", err))
		return
	}
	if len(jobsUsingBridge) > 0 {
		jsonAPIError(c, http.StatusConflict, fmt.Errorf("can't remove the bridge because jobs %v are associated with it", jobsUsingBridge))
		return
	}
	if err = orm.DeleteBridgeType(ctx, &bt); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("failed to delete bridge: %w", err))
		return
	}
