### Title
Unrestricted `init_global_fee_state`/`initialize_fee_state` allows front-running to hijack the global fee admin and fee wallet - ([File: programs/marginfi/src/instructions/marginfi_group/init_global_fee_state.rs])

### Summary
`initialize_fee_state` (instruction `init_global_fee_state`) initializes the program-wide singleton `FeeState` PDA and sets `global_fee_admin`, `global_fee_wallet`, and all protocol fee parameters directly from caller-supplied arguments, with no check that the caller is a legitimate/privileged deployer. [1](#0-0)  The account struct only requires an arbitrary `Signer` as `payer`, with no owner/admin gating on who may call the instruction. [2](#0-1) 

### Finding Description
This mirrors the tSQD `registerTokenOnL2` bug class: a "runs once per program" configuration-setting instruction (comment explicitly states "Runs once per program to init the global fee state") is left unrestricted, and once the `FeeState` PDA is initialized (`init` at a fixed seed `FEE_STATE_SEED`), it can never be re-initialized, permanently locking in whatever values were passed. [3](#0-2) 

Just as the tSQD bug allowed an attacker to front-run and permanently set an incorrect L2 token address, here an attacker can front-run the legitimate deployer's `init_global_fee_state` transaction (which is publicly visible in the mempool before confirmation) and call it themselves with `admin_key` and `fee_wallet` set to attacker-controlled addresses. [4](#0-3) 

The resulting `global_fee_admin` is subsequently the sole authority permitted to update fee parameters (via `has_one = global_fee_admin` checks in `edit_global_fee`), meaning once hijacked, the legitimate protocol admin can never regain control except through a program upgrade. [5](#0-4) 

### Impact Explanation
Impact is high: the attacker becomes the permanent `global_fee_admin` for the entire program (all groups/banks reference this singleton `FeeState`), and `global_fee_wallet` is the destination for protocol-wide fee flows (e.g., referenced by fee harvesting logic such as `programs/marginfi/src/instructions/kamino/harvest_reward.rs`). This is a durable, unrecoverable takeover of a protocol-wide privileged role and fee-redirection primitive with financial effect, analogous to the "bridge token broken and unable to be changed" outcome in the original report. [6](#0-5) 

### Likelihood Explanation
Likelihood is medium: the instruction only needs to be called once, at (or shortly after) deployment, and any signer can call it since there is no access control—an attacker monitoring the mempool/deployment sequence can front-run the legitimate initialization transaction the same way described in the original report for `registerTokenOnL2`.

### Recommendation
Restrict `init_global_fee_state` (and the analogous `init_global_fee_state_v2`) so it can only be called by a known/trusted authority—e.g., require the signer to match a hardcoded program upgrade authority or a value baked into the program at build time, or gate the instruction behind a one-time setup performed atomically during deployment (same transaction as program deployment) rather than as a separately callable instruction.

### Proof of Concept
1. Deployer deploys the marginfi program and prepares to call `init_global_fee_state` with the legitimate `admin_key`/`fee_wallet`.
2. Attacker observes the pending transaction (or simply races to call it first, since no gating exists) and submits their own `init_global_fee_state(attacker_admin, attacker_fee_wallet, ...)` transaction with higher priority fee.
3. Because `fee_state` is `init` at a fixed PDA (`FEE_STATE_SEED`), the attacker's transaction succeeds first; the legitimate deployer's subsequent call fails ("account already in use"). [7](#0-6) 
4. The attacker is now `global_fee_admin` and can call `edit_global_fee` to set any fee parameters, and `global_fee_wallet` redirects protocol fees to the attacker, permanently.

#[allow(unused_variables)]
pub fn initialize_fee_state(
    ctx: Context<InitFeeState>,
    admin_key: Pubkey,
    fee_wallet: Pubkey,
    bank_init_flat_sol_fee: u32,
    liquidation_flat_sol_fee: u32,
    order_init_flat_sol_fee: u32,
    program_fee_fixed: WrappedI80F48,
    program_fee_rate: WrappedI80F48,
    liquidation_max_fee: WrappedI80F48,
    order_execution_max_fee: WrappedI80F48,
) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_init()?;
    fee_state.global_fee_admin = admin_key;
    fee_state.global_fee_wallet = fee_wallet;
    fee_state.key = ctx.accounts.fee_state.key();
    fee_state.bank_init_flat_sol_fee = bank_init_flat_sol_fee;
    fee_state.bump_seed = ctx.bumps.fee_state;
    fee_state.program_fee_fixed = program_fee_fixed;
    fee_state.program_fee_rate = program_fee_rate;
    fee_state.liquidation_max_fee = liquidation_max_fee;
    fee_state.liquidation_flat_sol_fee = liquidation_flat_sol_fee;
    fee_state.order_execution_max_fee = order_execution_max_fee;
    fee_state.order_init_flat_sol_fee = order_init_flat_sol_fee;

    Ok(())
}
