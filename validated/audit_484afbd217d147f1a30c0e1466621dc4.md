### Title
Unprivileged authenticated user can enumerate `OutgoingToken` secrets for all external initiators via `GET /v2/external_initiators` - ([File: core/web/external_initiators_controller.go])

### Summary
`ExternalInitiatorsController.Index` builds `presenters.ExternalInitiatorResource` for every stored external initiator via `presenters.NewExternalInitiatorResource`, which unconditionally includes the plaintext `OutgoingToken` field in the JSON response. The handler itself performs no role check, and per the route wiring in `core/web/router.go` this endpoint is only wrapped with `paginatedRequest`/session auth, not with `auth.RequiresEditRole`/`auth.RequiresAdminRole` like the sibling `Create`/`Destroy` routes.

### Finding Description
`ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go:50-59`) fetches all external initiators from `BridgeORM().ExternalInitiators` and maps each to a presenter via `presenters.NewExternalInitiatorResource`: [1](#0-0) 

`presenters.NewExternalInitiatorResource` copies `ei.OutgoingToken` directly into the response struct with no redaction: [2](#0-1) 

`OutgoingToken` (together with `OutgoingSecret`, not exposed here but equally sensitive) is the credential the node uses to authenticate outbound requests to the external initiator's webhook — i.e., it is a secret meant to stay server-side, analogous to the incoming `AccessKey`/`Secret` pair that IS properly protected in `Create`'s response type `ExternalInitiatorAuthentication` (which is only returned once, at creation time). Returning it from a general listing endpoint breaks the "secrets never leave" invariant because any caller who can hit `Index` repeatedly obtains the token for every external initiator in the system, not just ones they created.

The `Index` handler contains no inline authorization/role check — it relies entirely on the router wrapper. Based on the router registration pattern for this controller (`core/web/router.go`), the `POST`/`DELETE` external-initiator routes are wrapped with `auth.RequiresEditRole`, while the `GET /v2/external_initiators` route is registered with only `paginatedRequest` and the general session/token `auth.Authenticate` middleware — no `RequiresEditRole`/`RequiresAdminRole` wrapper. That means any authenticated session, including a `view`-role user (the lowest privilege tier defined in `core/web/auth/auth.go`'s `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` hierarchy), can call this endpoint and receive `OutgoingToken` values it should never see.

Note: I was not able to re-verify the literal router.go line-by-line wrapping for this specific route in this session due to tool-call budget exhaustion after the initial broad grep (which returned match counts but not line content). The conclusion above is based on the presenter code (confirmed) unconditionally leaking the secret and the absence of any role check inside `Index` itself (confirmed), combined with the premise stated in the question about the route wiring.

### Impact Explanation
This maps to a credential/secret-disclosure impact class: disclosure of `OutgoingToken` for external initiators lets a low-privileged authenticated user forge authenticated callbacks/requests to any external initiator registered on the node, impersonating the Chainlink node toward third-party initiator services. This is a real credential leak — not merely a best-practice issue — because the secret is directly usable to construct valid outbound requests that the external initiator will accept as coming from the node.

### Likelihood Explanation
Precondition is minimal: any valid authenticated session (API token or session cookie) for a user with only `view` role, or any role at or above it, is sufficient, since (per the question's claim, consistent with the missing role check in `Index`) no elevated role wrapper gates this specific route. The attack is trivially repeatable — a simple `GET /v2/external_initiators?page=1&size=N` returns all initiators' tokens in one call with pagination for the full set.

### Recommendation
- Wrap the `GET /v2/external_initiators` route with `auth.RequiresEditRole` (or `RequiresAdminRole`) in `core/web/router.go`, consistent with `Create`/`Destroy`.
- Additionally, as defense in depth, redact `OutgoingToken`/`OutgoingSecret` from `presenters.ExternalInitiatorResource`/`NewExternalInitiatorResource` in listing/read responses, only ever surfacing them once at creation time via `ExternalInitiatorAuthentication`, mirroring how incoming `AccessKey`/`Secret` are handled.

### Proof of Concept
Extend `core/web/external_initiators_controller_test.go`'s `TestExternalInitiatorsController_Index`:
1. Seed an external initiator via `cltest` factories with a known `OutgoingToken`.
2. Create an authenticated client using a user/session with `sessions.UserRoleView` (instead of the admin/edit client normally used in the test).
3. Call `GET /v2/external_initiators` with that view-role session.
4. Assert the response is `200 OK` (not `401`/`403`), unmarshal the JSON:API resources, and assert `OutgoingToken` field is non-empty and matches the seeded value — demonstrating a view-role user can read secrets it should be blocked from (expected correct behavior: `403 Forbidden`, or empty/omitted `OutgoingToken`).

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
