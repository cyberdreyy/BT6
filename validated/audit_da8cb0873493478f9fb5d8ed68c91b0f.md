### Title
Unauthenticated pipeline-run `Resume` endpoint accepts attacker-controlled task results, bypassing the "off-chain work performed" invariant - ([File: core/web/pipeline_runs_controller.go])

### Summary
`PipelineRunsController.Resume` in `core/web/pipeline_runs_controller.go` is a state-mutating handler that finalizes a pending pipeline task and resumes the run, and it is explicitly labeled in the audit log as `audit.UnauthedRunResumed`, indicating the route is reachable without session/API-key authentication. This mirrors the vader `Pools.sync()` bug class: a function meant to be invoked only as a trusted callback after real off-chain work has been verified/performed is instead externally reachable, letting an unprivileged caller directly supply the "result" that the pipeline pipeline treats as authoritative.

### Finding Description
`Resume` takes a `runID` (task UUID) from the URL and an arbitrary JSON body decoded into `pipeline.ResumeRequest`, converts it into a `pipeline.Result`, and calls `prc.App.ResumeJobV2(ctx, taskID, result)` directly: [1](#0-0) 

This endpoint exists so that asynchronous bridge adapters can call back into the node once they've completed off-chain computation for a bridge task (see the async bridge test hitting `http://localhost:6688/v2/resume/`) [2](#0-1) . The pipeline runner's `ResumeRun` is wired directly into the transaction manager's resume callback and pipeline ORM without any secondary authorization step verifying the caller is the legitimate bridge/adapter that owns that specific pending task: [3](#0-2) 

The only "access control" is the audit log call after the fact:
```go
prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
``` [4](#0-3) 

The naming `UnauthedRunResumed` is itself an admission that this write path bypasses the node's normal authentication methods (`AuthenticateBySession`, `AuthenticateByToken`, `AuthenticateExternalInitiator`) applied elsewhere in the web layer [5](#0-4) . Unlike the vader case where `sync()` had no modifier at all, here the "unprivileged caller" is deliberately allowed to call the endpoint, but the only thing gating a legitimate resume from a malicious one is knowledge of the `runID` UUID — there is no proof that the caller actually performed (or is authorized to report) the off-chain work for that specific task, analogous to `sync()` updating pool balances without the Router having verified/enforced an actual token transfer.

### Impact Explanation
If a `runID` (task UUID) is disclosed or guessable/leaked through some other channel (e.g., logs, error messages, timing, or a compromised bridge response URL), an unprivileged network client can inject an arbitrary `pipeline.Result` to complete that pending task with attacker-chosen data. Because pipeline results (e.g., price data for a Flux Monitor/OCR job) can directly drive on-chain transactions submitted by the node, this can manipulate job outputs and downstream fund-moving transactions — the same class of impact as the vader finding (accounting/state corrupted without the expected real-world precondition being satisfied).

### Likelihood Explanation
Exploitation requires knowledge of a specific pending task's UUID, which is normally only known to the legitimate bridge adapter the node called out to. This reduces likelihood versus a fully open function, but the endpoint itself enforces zero authentication or ownership check, so any leak of the run/task ID (logs, error responses, network observation of the bridge callback URL, a compromised or malicious "bridge" adapter) is sufficient for a full state-mutation bypass, matching the "unprivileged actor" and "unauthorized job run" criteria in scope.

### Recommendation
Add an authentication/authorization mechanism to `PipelineRunsController.Resume` beyond mere possession of the task UUID — e.g., require a per-task shared secret/HMAC bound to the originating bridge task (verified before decoding/applying the result), or restrict the endpoint to be callable only by the specific bridge configured for that task, similar to how `AuthenticateExternalInitiator` binds a request to a specific registered initiator. At minimum, treat the `runID` as a capability token, generate it with sufficient entropy, and ensure it is never leaked in logs/errors, while adding explicit validation that the resumed task belongs to the expected bridge task type before accepting the result.

### Proof of Concept
1. Trigger (or observe) a job containing an async bridge task; the node calls out to the bridge with a `ResponseURL` of the form `http://<node>:6688/v2/resume/<taskID>` [6](#0-5) .
2. An attacker who obtains or guesses `<taskID>` sends: `PATCH /v2/jobs/:ID/runs/<taskID>` with a crafted JSON body (`pipeline.ResumeRequest`) containing attacker-chosen `data`/`error` fields, without any session cookie or API key.
3. `PipelineRunsController.Resume` decodes the body and calls `prc.App.ResumeJobV2(ctx, taskID, result)` directly, with no check verifying the caller is the legitimate bridge server for that task [7](#0-6) .
4. The pipeline run is completed using the attacker-supplied result, potentially propagating to downstream on-chain transactions.

Note: due to index size limits, I could not locate the route-registration file that mounts `/v2/jobs/:ID/runs/:runID` (routes.go was not found in the indexed content), so I could not directly confirm at the router level whether this path is fully excluded from all authentication middleware or only from some. The `audit.UnauthedRunResumed` naming and the absence of any authentication check inside the `Resume` handler itself are the basis for this finding; a Devin session with full repository access would be needed to confirm the exact route-mounting configuration.

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionExternalInitiatorKey, ei)

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}
