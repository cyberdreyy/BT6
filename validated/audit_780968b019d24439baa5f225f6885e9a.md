### Title
Unsynchronized map access in `WorkflowMetadataHandler.Authorize` causes concurrent map read/write panic, crashing the gateway on ordinary HTTP trigger requests - (File: `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go`)

### Summary
`WorkflowMetadataHandler.Authorize` is called for every incoming HTTP trigger request from an external, unprivileged client and reads the shared `h.authorizedKeys` map without acquiring `h.mu`. Meanwhile, the handler's own periodic background job `syncMetadata` overwrites `h.authorizedKeys`, `h.workflowRefToID`, `h.workflowIDToRef`, and `h.workflowShards` under `h.mu.Lock()`. Because one code path is protected and the other isn't, a concurrent read (`Authorize`) racing with a write (`syncMetadata`) can trigger Go's fatal, unrecoverable "concurrent map read and write" error, crashing the entire gateway process.

### Finding Description
`Authorize` is defined at: [1](#0-0) 

Note it takes no `h.mu.RLock()`/`RUnlock()` before accessing `h.authorizedKeys[workflowID]` at line 92, unlike every other accessor in the same struct (`GetWorkflowID`, `GetWorkflowReference`, `WorkflowShards`), which correctly take `h.mu.RLock()`: [2](#0-1) 

The writer path, `syncMetadata`, runs on a periodic ticker (`MetadataAggregationIntervalMs`) and replaces the maps wholesale under the mutex: [3](#0-2) 

`Authorize` is reached directly from an unprivileged, internet-facing entrypoint: any external client's HTTP trigger request flows through `httpTriggerHandler.HandleUserTriggerRequest` → `authorizeRequest` → `workflowMetadataHandler.Authorize`: [4](#0-3) [5](#0-4) 

This mirrors the reported bug class exactly: a resource/state transition (map replacement in `setMarket`-equivalent `syncMetadata`) is properly guarded in one place but the corresponding consumer path (`deposit`-equivalent `Authorize`) omits the required step (acquiring the lock), leading to a crash under otherwise normal, unprivileged usage rather than a graceful error.

### Impact Explanation
Go's runtime detects concurrent unsynchronized map read/write and calls `fatal("concurrent map read and write")`, which cannot be recovered by `defer/recover` — it immediately terminates the process. Since `syncMetadata` runs periodically for the lifetime of the gateway and `Authorize` is invoked on every single external HTTP trigger request, any sustained request traffic has a nonzero probability of colliding with a metadata sync cycle, crashing the gateway node and denying service to all workflows relying on it — a full availability failure of the internet-facing gateway, triggerable by any unprivileged client simply by sending normal traffic at volume.

### Likelihood Explanation
No special access, authentication bypass, or malicious payload is required — an unprivileged client only needs to send a moderate rate of legitimate/otherwise-valid HTTP trigger requests (which get routed to `Authorize`) while the handler's periodic `syncMetadata` ticker fires (`MetadataAggregationIntervalMs`, likely on the order of seconds). Under any non-trivial request volume this race window will eventually be hit, making the crash probable in production, not merely theoretical.

### Recommendation
Acquire `h.mu.RLock()`/`RUnlock()` around the reads of `h.authorizedKeys` in `Authorize` (mirroring the pattern already used by `GetWorkflowID`, `GetWorkflowReference`, and `WorkflowShards`), consistent with how `syncMetadata` guards its writes with `h.mu.Lock()`.

### Proof of Concept
Run two goroutines concurrently against a `WorkflowMetadataHandler` instance with `go test -race`:
1. Goroutine A repeatedly calls `handler.Authorize(workflowID, token, req)` (simulating incoming HTTP trigger requests).
2. Goroutine B repeatedly calls `handler.syncMetadata(ctx)` (simulating the periodic aggregation ticker), after seeding the aggregator via `agg.Collect(...)` so the map is actually reassigned each cycle.

Under `-race`, this immediately reports a data race on `h.authorizedKeys`; without `-race`, sufficiently concurrent execution reliably produces `fatal error: concurrent map read and write`, terminating the test process — demonstrating the same crash would occur in the running gateway.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (h *WorkflowMetadataHandler) GetWorkflowID(workflowOwner, workflowName, workflowTag string) (string, bool) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	workflowRef := workflowReference{
		workflowOwner: workflowOwner,
		workflowName:  workflowName,
		workflowTag:   workflowTag,
	}
	workflowID, exists := h.workflowRefToID[workflowRef]
	if !exists {
		return "", false
	}
	return workflowID, true
}

	defer h.mu.RUnlock()

	return workflowRef, exists

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
