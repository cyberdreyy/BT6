### Title
Workflow owner/name/tag enumeration oracle via distinguishable error messages in `resolveWorkflowID` vs `authorizeRequest` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateWorkflowFields` only checks the *syntax* of `WorkflowOwner`/`WorkflowName`/`WorkflowTag` (hex format, length, non-empty) and never binds these fields to the JWT signer before workflow resolution. Because `resolveWorkflowID` and `authorizeRequest` return distinct, differently-worded errors, a caller holding any valid run-role JWT (even for an unrelated workflow) can distinguish "no such workflow" from "workflow exists but I'm not authorized," enabling owner/name/tag enumeration.

### Finding Description
`validateWorkflowFields` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:214-258`) validates presence and hex/length format of `WorkflowOwner`, `WorkflowName`, and `WorkflowTag` only — it performs no comparison against the JWT signer's address: [1](#0-0) 

The caller flow in `HandleUserTriggerRequest` is: `validatedTriggerRequest` (which calls `validateWorkflowFields`) → `resolveWorkflowID` → `authorizeRequest`: [2](#0-1) 

`resolveWorkflowID`, when `WorkflowID` is empty, looks up `workflowOwner`/`workflowName`/`workflowTag` via `GetWorkflowID` and, on failure, emits: `"Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'"` with JSON-RPC code `ErrInvalidRequest`: [3](#0-2) 

If the lookup succeeds (i.e., the owner/name/tag combination corresponds to a real registered workflow), execution proceeds to `authorizeRequest`, which calls `h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)` and, on failure (e.g., JWT signer not in the workflow's authorized-key set), emits a **different** message: `"Auth failure: " + err.Error()`: [4](#0-3) 

Both errors use the same JSON-RPC error code (`jsonrpc.ErrInvalidRequest`), but the message text differs ("Workflow not found..." vs "Auth failure: ..."). Since `GetWorkflowID` is a plain map lookup keyed by the exact `(owner, name, tag)` tuple, and `validateWorkflowFields` never checks that the JWT signer matches the claimed `WorkflowOwner` before this lookup, any holder of a valid run-role JWT (even for a completely unrelated workflow) can pass `validatedTriggerRequest` and then submit requests enumerating candidate `WorkflowOwner` values (with a fixed guessed `WorkflowName`/`WorkflowTag`) and observe which owner addresses produce "Auth failure" (workflow exists) versus "Workflow not found" (does not exist).

### Impact Explanation
This is an information-disclosure/reconnaissance issue: an attacker can determine which owner/name/tag combinations correspond to real, registered workflows without needing to hold an authorized key for them. This does not by itself grant unauthorized triggering (that still requires passing `Authorize` in `authorizeRequest`), but it provides an oracle that helps an attacker fingerprint victims' deployed workflows and target further attacks (e.g., focused key-compromise attempts, social engineering, or exploiting rate-limit/DoS surfaces per victim workflow) — this maps to Chainlink's "information disclosure enabling further attack" class rather than a direct fund-loss/auth-bypass class, since actual triggering still requires passing `Authorize`.

### Likelihood Explanation
Feasibility is high: the only precondition is possession of any valid run-role JWT (even for a workflow unrelated to the target), which is sufficient to pass `validatedTriggerRequest`'s syntactic checks. Enumeration is fully automatable and repeatable — an attacker can script a loop over guessed `WorkflowOwner` addresses with a fixed `WorkflowName`/`WorkflowTag` and inspect the returned error text/code to build an owner enumeration oracle.

### Recommendation
Return a single, opaque error message/code for both "workflow not found" and "auth failure" paths when resolving via owner/name/tag (and ideally also for the direct-`WorkflowID` path), so that the two failure conditions are indistinguishable to the caller. Alternatively, defer detailed reason codes to internal logging only, and standardize the user-facing error to something generic like "workflow not found or not authorized" for both `resolveWorkflowID` and `authorizeRequest` failures reached via the owner/name/tag path.

### Proof of Concept
Add a table-driven test in `http_trigger_handler_test.go`:
1. Register one workflow (`workflowOwnerA`, `name`, `tag`) with an authorized key for `signerA`.
2. Craft a JWT signed by an unrelated key `signerB` (not authorized for any workflow, or authorized only for a different workflow).
3. Send trigger request A: `WorkflowOwner = workflowOwnerA` (existing), `WorkflowName = name`, `WorkflowTag = tag`, signed by `signerB` → expect result reaches `authorizeRequest` and returns `"Auth failure: ..."`.
4. Send trigger request B: `WorkflowOwner = <random nonexistent address>`, same `name`/`tag`, signed by `signerB` → expect `resolveWorkflowID` returns `"Workflow not found..."`.
5. Assert that the two returned error strings/messages differ, confirming the oracle exists (test should fail once fixed, when messages are unified into an identical opaque error for both cases).

	}

		return err

func (h *httpTriggerHandler) validateWorkflowFields(ctx context.Context, workflow gateway_common.WorkflowSelector, requestID string, callback handlers.Callback) error {
	hasWorkflowID := workflow.WorkflowID != ""
	hasWorkflowName := workflow.WorkflowName != ""
	hasWorkflowOwner := workflow.WorkflowOwner != ""
	hasWorkflowTag := workflow.WorkflowTag != ""

	if !hasWorkflowID {
		if !hasWorkflowName {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflowName is required when workflowID is not provided", callback)
			return errors.New("workflowName is required when workflowID is not provided")
		}
		if !hasWorkflowOwner {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflowOwner is required when workflowID is not provided", callback)
			return errors.New("workflowOwner is required when workflowID is not provided")
		}
		if !hasWorkflowTag {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflowTag is required when workflowID is not provided", callback)
			return errors.New("workflowTag is required when workflowID is not provided")
		}
	}

	if hasWorkflowID {
		if err := h.validateWorkflowID(ctx, workflow.WorkflowID, requestID, callback); err != nil {
			return err
		}
	}
	if hasWorkflowOwner {
		if err := h.validateWorkflowOwner(ctx, workflow.WorkflowOwner, requestID, callback); err != nil {
			return err
		}
	}
	if hasWorkflowName {
		if err := h.validateWorkflowName(ctx, workflow.WorkflowName, requestID, callback); err != nil {
			return err
		}
	}

	if workflow.WorkflowTag != "" {
		if err := h.validateWorkflowTag(ctx, workflow.WorkflowTag, requestID, callback); err != nil {
			return err
		}
	}

	return nil
}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
