### Title
Stale confirmations from deleted members count toward the confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
In `MultiSigContract`, when a member is removed via `DeleteMember`, `delete_member()` only clears requests *authored* by that member; it never scans other pending requests to strip that member's confirmation from their `confirmations: LookupMap<RequestId, HashSet<String>>` entries. `confirm()` (multisig2/src/lib.rs:294-315) simply compares `confirmations.len()` to `self.num_confirmations`, without checking that every entry in the confirmations set still corresponds to a live member. This breaks the binding "confirmations counted == live members who confirmed."

### Finding Description
`delete_member` (multisig2/src/lib.rs:356-379) iterates `self.requests` and removes only requests where `r.member == member` (requests the departing member created), then removes `member` from `self.members`: [3](#0-2) 

It never touches `self.confirmations` entries for requests created by *other* members that the departing member had already confirmed. Those stale confirmation strings remain in the `HashSet<String>` for those requests.

`confirm()` then computes eligibility purely from the size of that set: [4](#0-3) 

So if member `M1` confirms request `R` (created by `M2`), and is later removed via a legitimate `DeleteMember` action, `R`'s confirmation set still contains `M1`. A subsequent confirmation from a still-current member makes `confirmations.len()+1 >= num_confirmations` true and executes `R`, even though only `num_confirmations - 1` *currently live* members actually confirmed it. The K-of-N threshold binding (`live confirmations == num_confirmations`) is violated by a stale/ghost confirmation.

### Impact Explanation
This lets a request execute (transfer, `AddKey`, `FunctionCall`, etc.) with fewer than `num_confirmations` *live* signers, i.e., a multisig request executed below the actual threshold of current members — this matches the Critical impact category "a multisig request executed below threshold."

### Likelihood Explanation
Requires no attacker privilege beyond normal multisig usage: any member confirms a pending request, that member is later removed (a routine `DeleteMember` operation performed through the normal K-of-N flow, not an attacker action against invariants), and the stale confirmation silently persists on any request that member confirmed but that had not yet reached threshold and is still within the request lifetime/cooldown window. This is a natural sequence of legitimate multisig operations, not a contrived edge case, making it readily reachable.

### Recommendation
When a member is deleted, iterate all pending requests (or maintain a reverse index from member → confirmed request IDs) and remove the departing member's entry from every `confirmations` set, not just the requests they authored. Alternatively, validate at `confirm()` time that every account/key in the confirmations set for a request is still a current member before counting it toward `num_confirmations`.

### Proof of Concept
1. Initialize multisig with members `{A, B, C}`, `num_confirmations = 2`.
2. `B` calls `add_request` creating request `R` (e.g., a `Transfer`).
3. `A` calls `confirm(R)` → confirmations = `{A}`, `1 < 2`, so `R` stays pending.
4. Members vote (via the normal multisig flow) to `DeleteMember { member: A }`; `delete_member` removes `A` from `self.members` and only removes requests authored by `A` — `R` (authored by `B`) and its confirmation set `{A}` are untouched.
5. `C` calls `confirm(R)` → confirmations set becomes checked as `{A}.len() + 1 = 2 >= num_confirmations (2)` → `R` executes, even though `A` is no longer a member and only one *current* member (`C`) plus one departed member's stale vote authorized it.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
