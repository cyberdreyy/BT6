### Title
Gateway `HandleLegacyUserMessage` forwards unprivileged client `web_api_trigger` requests to every capability DON node without enforcing the per-workflow sender/topic allowlist - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The `sellOption()` bug allowed an attacker-controlled parameter (`optionInstrumentAddress`) to be used for all authorization/value checks while the actually-authorized, signed field (`order.optionMarketAddress`) was silently ignored, letting the caller bypass the intended validation entirely. The same class of bug — "the code that is supposed to authorize a request skips the check and forwards the request anyway" — is present in the Chainlink Gateway's legacy Web API trigger path: `HandleLegacyUserMessage` explicitly forwards a client-supplied request to **all** DON nodes without applying the `allowedSenders`/`allowedTopics` authorization that the workflow's registered trigger config defines, per its own `// TODO: apply allowlist and rate-limiting here` comment.

### Finding Description
The Chainlink Gateway's `web_api_trigger` capability is designed so that only senders present in a workflow's `AllowedSenders` list (validated in `processTrigger`) can trigger the workflow: [1](#0-0) . This check exists in the newer `HandleGatewayMessage` node-facing path [2](#0-1) .

However, the Gateway's own `HandleLegacyUserMessage`, which is the entry point for unprivileged external HTTP clients hitting the Gateway directly, does not perform any equivalent allowlist or sender validation before broadcasting the request to every member of the DON: [3](#0-2) 

The comment at line 384, `// TODO: apply allowlist and rate-limiting here`, and the accompanying test comment `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` [4](#0-3)  confirm that this authorization step is acknowledged as missing rather than intentionally deferred to another verified layer. The handler only validates message structure, decoding, and staleness [5](#0-4)  before signing off and fanning the request out to every DON member: [6](#0-5) .

This mirrors the reported bug class: a parameter/identity that is supposed to gate authorization (`AllowedSenders`/`AllowedTopics`, analogous to `order.optionMarketAddress`) exists in the system, but the actual enforcement path used for the (external, unprivileged) client-originated request does not perform the comparison — it is only performed downstream in a different code path (`processTrigger`, only reached via `HandleGatewayMessage`, the node-facing message flow), similar to how the exploit report showed a signed/authorized value being ignored in favor of an unchecked value supplied by the caller.

### Impact Explanation
If `HandleLegacyUserMessage` is a live code path reachable by external clients (its purpose per the file's own comments and tests is to receive user-originated trigger messages), any unauthenticated/unprivileged actor able to reach the Gateway's public endpoint could submit a `web_api_trigger` message and have it broadcast to every node in the DON, regardless of whether their sender address is in any workflow's `AllowedSenders` list. This is a request-impersonation / allowlist-bypass class of vulnerability: attackers could trigger workflow executions they are not authorized to trigger, and depending on downstream node-side handling, cause unwanted or unauthorized workflow runs, resource exhaustion (fan-out to every node with no rate limiting keyed on sender), or interference with per-sender rate-limiting protections designed into `triggerConnectorHandler`.

### Likelihood Explanation
This depends on whether `HandleLegacyUserMessage` is still wired to a live, internet-facing route or is dead/legacy code retained for backward compatibility (its name and code both explicitly say "Legacy"). I could not conclusively determine, using the indexed code, whether this method is currently invoked from an active HTTP/websocket route registration in this repo snapshot — that requires tracing the `handlers.Handler` interface's caller graph and route wiring, which was not fully visible in the retrieved context. Given the explicit unresolved TODO and lack of any allowlist enforcement in the function itself, if this path is still reachable, the likelihood of exploitation is high since no authentication/authorization step blocks it.

### Recommendation
Enforce the same sender/topic allowlist validation used in `processTrigger` (`trigger.allowedSenders`, `trigger.allowedTopics`) inside `HandleLegacyUserMessage` before broadcasting to DON members, or reject/deprecate the legacy path entirely if it is superseded by `HandleGatewayMessage`. At minimum, resolve the outstanding TODO and remove the "send to all nodes unconditionally" fallback in the legacy handler.

### Proof of Concept
Not independently reproducible from the indexed code alone since I could not confirm the live HTTP route wiring for `HandleLegacyUserMessage` in this repo snapshot; a Devin session with full repository/build access would be needed to trace whether this handler is still registered on a reachable Gateway endpoint and to construct an end-to-end PoC request.

func (h *triggerConnectorHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) error {
	msg, err := hc.ValidatedMessageFromReq(req)
	if err != nil {
		h.lggr.Errorw("error validating message from request", "err", err, "request", req)
		return nil
	}
	body := &msg.Body
	sender := ethCommon.HexToAddress(body.Sender)
	var payload webapicap.TriggerRequestPayload
	err = json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw("error decoding payload", "err", err)
		err = h.sendResponse(ctx, gatewayID, body, ghcapabilities.TriggerResponsePayload{Status: "ERROR", ErrorMessage: fmt.Errorf("error %s decoding payload", err.Error()).Error()})
		if err != nil {
			h.lggr.Errorw("error sending response", "err", err)
		}
		return nil
	}

	switch body.Method {
	case ghcapabilities.MethodWebAPITrigger:
		resp := h.processTrigger(ctx, gatewayID, body, sender, payload)
		var response ghcapabilities.TriggerResponsePayload
		if resp == nil {
			response = ghcapabilities.TriggerResponsePayload{Status: "ACCEPTED"}
		} else {
			response = ghcapabilities.TriggerResponsePayload{Status: "ERROR", ErrorMessage: resp.Error()}
			h.lggr.Errorw("Error processing trigger", "gatewayID", gatewayID, "body", body, "response", resp)
		}
		err = h.sendResponse(ctx, gatewayID, body, response)
		if err != nil {
			h.lggr.Errorw("Error sending response", "body", body, "response", response, "err", err)
		}
		return nil

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
