### Title
Attacker-controlled `GitCloneFlags` `--template` override on native clone path leads to malicious `post-checkout` hook execution - ([File: functions/concrete/run/stages/get_sources.go])

### Summary
`GetSources.gitClone` builds the clone argument list with the runner-generated `--template templateDir` first and then unconditionally appends `s.GitCloneFlags` with no filtering, so a repeated `--template=<attacker dir>` in `GitCloneFlags` wins (git honors the last `--template` flag) and lets an attacker substitute their own template directory. If that directory contains an executable `hooks/post-checkout`, git copies it into `.git/hooks` during clone, and the subsequent `gitCheckout` call executes it. `gitInit`, by contrast, does not append any user-supplied flags after its own `--template templateDir`, so the `gitInit`/fetch path is not affected.

### Finding Description
In `gitClone` [1](#0-0) , `cloneArgs` is assembled as:
```
cloneArgs := s.configArgs()
cloneArgs = append(cloneArgs, "clone", "--no-checkout", remoteURL, ".", "--template", templateDir)
...
cloneArgs = append(cloneArgs, s.GitCloneFlags...)
```
`templateDir` here is the runner-owned directory created in `setupTemplateDir` [2](#0-1) , which only ever contains a `config` file (no hooks) and is meant to be authoritative for safety-relevant git behavior (default branch, credential/interactive settings, and the include of the per-job external git config). Because `s.GitCloneFlags` is appended **after** the runner's `--template templateDir`, and because git's argument parser takes the last occurrence of a repeated flag, any `--template=/path` value present in `GitCloneFlags` silently overrides the runner's template directory — there is no denylist or validation of `GitCloneFlags` contents anywhere in this file.

This path is only reachable when `s.GitStrategy == gitStrategyClone && s.UseNativeClone && gitVersionAtLeast(...)` [3](#0-2) . If an attacker can get an arbitrary/writable directory referenced via `GitCloneFlags` (e.g. a path inside the job's cache/fixture area that the job itself populated earlier in the pipeline, or via `pre_clone_step`), they can place `hooks/post-checkout` (executable) in that directory. `git clone --template=<attacker dir>` copies the template's `hooks/` contents into `.git/hooks`. Cloning itself uses `--no-checkout` so the hook does not fire immediately, but `s.Checkout` subsequently calls `gitCheckout`, which runs `git ... checkout -f -q <SHA>` [4](#0-3) . A `post-checkout` hook present in `.git/hooks` fires on this checkout, executing attacker-controlled code in the job's git-command execution context (helper/host, depending on executor).

Note: the question also asks about `gitInit`. That function is not vulnerable to this specific override — its args list is fixed (`"init", ".", "--template", templateDir`, optionally `--object-format`) and no user-supplied flags (`GitCloneFlags`/`GitFetchFlags`) are appended to it [5](#0-4) . The real exposure is isolated to `gitClone`'s native-clone path.

Existing protections do not stop this: there is no allow/deny list applied to `GitCloneFlags` before use, and `cleanupGitState` only removes a stale `post-checkout` hook from `.git/hooks` at the *start* of the stage (before this job's clone runs) [6](#0-5) , which does not protect against a hook installed during the current clone via an overridden template.

### Impact Explanation
An attacker who can influence `GitCloneFlags` (and provide/write a malicious template directory reachable during the job) can get git to install and later execute an arbitrary `post-checkout` hook, resulting in command execution outside the job's declared `script` steps, in the git-command execution context (helper/host per executor). This matches the scoped impact: arbitrary command execution triggered by git hooks outside the job's declared script, gated behind the runner-authoritative-template invariant being violated.

### Likelihood Explanation
Exploitability is conditioned on:
1. `GitStrategy=clone`, `UseNativeClone=true`, and a bundled git version ≥ 2.49 (feature-gated path).
2. The attacker being able to inject a `--template=<path>` entry into `GitCloneFlags` and having write/execute access to that path before the clone runs (e.g., via a prior stage/cache/fixture writable location in the same job).
This is a narrower path than a generic "any job variable" attack, since `GitCloneFlags` population source (CI-variable vs. runner-config-only) was not fully confirmed in this pass, but the ordering flaw in the code itself (no filtering of `--template` in `GitCloneFlags`) is a concrete, real logic bug independent of that.

### Recommendation
- Filter/deny any `--template`, `--separate-git-dir`, `--upload-pack`, or similarly safety-relevant flag out of `GitCloneFlags`/`GitFetchFlags`/`GitCleanFlags` before use, or apply them via a mechanism that cannot be overridden by later flags (e.g., pass `--template` last, or use `git -c init.templateDir=<dir>` combined with rejecting `--template` occurrences in user-supplied flags).
- Alternatively, place the runner-controlled `--template templateDir` after `s.GitCloneFlags` in the argument list so any user-supplied `--template` is superseded, and additionally validate that no user flag can set `init.templateDir` via `-c`.

### Proof of Concept
Go unit test in `functions/concrete/run/stages/get_sources_test.go`:
```go
func TestGitCloneFlags_CannotOverrideTemplateDir(t *testing.T) {
    s := GetSources{
        GitStrategy:    gitStrategyClone,
        UseNativeClone: true,
        GitCloneFlags:  []string{"--template=/tmp/attacker-template"},
    }
    // capture args passed to git() via a stub/mocked e.Command
    gotArgs := captureGitArgs(t, func(ctx context.Context, e *env.Env) error {
        return s.gitClone(ctx, e, "/runner/safe/template", "https://example.com/repo.git", nil)
    })

    // assert the LAST --template occurrence in gotArgs is still the
    // runner-provided templateDir, not the attacker-supplied one.
    idx := lastIndexOf(gotArgs, "--template")
    require.NotEqual(t, -1, idx)
    require.Equal(t, "/runner/safe/template", gotArgs[idx+1],
        "attacker-controlled GitCloneFlags overrode runner template dir")
}
```
Expected current (buggy) result: assertion fails because `gotArgs[idx+1] == "/tmp/attacker-template"`, proving the override. Integration PoC: set up a job with `GIT_STRATEGY=clone`, `UseNativeClone=true`, and a `GitCloneFlags` entry `--template=<writable dir containing hooks/post-checkout>`; observe the hook executes after checkout.

func (s GetSources) setupTemplateDir(e *env.Env, extConfigFile string) (string, func(), error) {
	templateDir := filepath.Join(e.WorkingDir+".tmp", templateDirName)
	_ = os.RemoveAll(templateDir)

	if err := os.MkdirAll(templateDir, 0o755); err != nil {
		return "", func() {}, fmt.Errorf("creating template dir: %w", err)
	}

	cleanup := func() { _ = os.RemoveAll(templateDir) }

	absExtConfig, err := filepath.Abs(extConfigFile)
	if err != nil {
		cleanup()
		return "", func() {}, fmt.Errorf("resolving ext config path: %w", err)
	}

	content := strings.Join([]string{
		"[init]", "\tdefaultBranch = none",
		"[fetch]", "\trecurseSubmodules = false",
		"[credential]", "\tinteractive = never",
		"[gc]", "\tautoDetach = false",
		"[include]", fmt.Sprintf("\tpath = %s", filepath.ToSlash(absExtConfig)),
	}, "\n") + "\n"

	if err := os.WriteFile(filepath.Join(templateDir, "config"), []byte(content), 0o644); err != nil {
		cleanup()
		return "", func() {}, fmt.Errorf("writing template config: %w", err)
	}

	return templateDir, cleanup, nil
}

func (s GetSources) gitInit(ctx context.Context, e *env.Env, templateDir, remoteURL, extConfigFile string, extraEnv map[string]string) error {
	args := []string{"init", ".", "--template", templateDir}
	if s.ObjectFormat != "" && s.ObjectFormat != "sha1" {
		args = append(args, "--object-format", s.ObjectFormat)
	}

	if err := git(ctx, e, extraEnv, args...); err != nil {
		return fmt.Errorf("git init: %w", err)
	}

	if err := git(ctx, e, extraEnv, "remote", "add", "origin", remoteURL); err != nil {
		if err := git(ctx, e, extraEnv, "remote", "set-url", "origin", remoteURL); err != nil {
			return fmt.Errorf("setting remote URL: %w", err)
		}
		// For existing repos the template isn't reapplied — explicitly include
		// the external config.
		absExtConfig, _ := filepath.Abs(extConfigFile)
		pattern := regexp.QuoteMeta(filepath.Base(extConfigFile)) + "$"
		if err := git(ctx, e, extraEnv,
			"config", "--file", filepath.Join(e.WorkingDir, ".git", "config"),
			"--replace-all", "include.path", absExtConfig, pattern,
		); err != nil {
			e.Warningf("Failed to configure include.path for existing repo: %v", err)
		}
	} else {
		e.Noticef("Created fresh repository.")
	}

	return nil
}

func (s GetSources) gitCheckout(ctx context.Context, e *env.Env, extraEnv map[string]string) error {

		short = short[:8]
	}
