## Analog Found: Griefing / permanent stake-fund lock via `deposit_coins` revert in `staking_contract::distribute_internal`

### Title
Malicious operator/staker can permanently block `distribute`, `unlock_stake`, `request_commission`, and `switch_operator` by opting out of direct coin transfers, trapping counterparty stake indefinitely - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
The Solidity report's core invariant break is: a single uncooperative counterparty can force a value-transfer step to fail, and because that failing transfer is embedded in a larger settlement flow, the failure blocks (or misdirects) funds belonging to *other, cooperative* parties. The Aptos analog is in `staking_contract::distribute_internal`, which iterates over every shareholder of the shared `distribution_pool` and unconditionally calls `aptos_account::deposit_coins` for each one [1](#0-0) . `deposit_coins` aborts if the recipient is unregistered for `AptosCoin` and has opted out of direct coin transfers [2](#0-1) . Since Move transactions are atomic, that single abort reverts the *entire* call — including withdrawal of funds legitimately owed to the other shareholder(s) in the same pool.

### Finding Description
`staking_contract`'s distribution pool is shared between the staker and the operator (or the operator's beneficiary) [3](#0-2) . `distribute_internal`:
1. Withdraws all currently inactive/pending_inactive stake from the stake pool via `stake::withdraw_with_cap` (funds now exist only as an in-memory `Coin<AptosCoin>` for this transaction) [4](#0-3) .
2. Loops over *all* shareholders of `distribution_pool` and calls `aptos_account::deposit_coins(recipient, ...)` for each [1](#0-0) .

`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the target account is not registered for `AptosCoin` and has disabled direct transfers via `DirectTransferConfig` — a self-service, unprivileged opt-out documented as "enabled by default; users can opt-out at any time" [5](#0-4) [2](#0-1) .

Critically, `distribute_internal` is not only reachable via the public `distribute()` entry function (callable by anyone, analogous to `settleAuction()`) [6](#0-5) , but is also force-invoked as a mandatory first step inside `unlock_stake`, `request_commission`, `switch_operator`, and `update_commision` [7](#0-6) [8](#0-7) [9](#0-8) . So if either the staker or the operator/beneficiary has an outstanding pending distribution and opts out of direct transfers (without registering `CoinStore<AptosCoin>`), the entire shared distribution pool becomes unpayable — because the loop cannot skip a bad recipient, it aborts the whole transaction (equivalent to the report's "NFT transfer fails, whole settlement blocked" scenario).

### Impact Explanation
This breaks the required invariant that "unlock, reactivate, withdraw ... paths must not redirect value or strand it permanently" for stake/staking_contract flows. Concretely:
- An operator (unprivileged relative to the staker's own stake) can grief the staker: after accruing a pending commission distribution, the operator calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own account (or the beneficiary's) and never registers `CoinStore<AptosCoin>`. From then on, `unlock_stake`, `switch_operator`, and `update_commision` — all of which the staker needs to exit or renegotiate the relationship — unconditionally abort at `distribute_internal`, because the operator's pending commission share can't be paid.
- Since `owner_cap` for the underlying stake pool is held exclusively inside the `staking_contract` resource account, there is no alternate path for the staker to withdraw stake that bypasses `distribute_internal`. The staker's already-unlocked/inactive stake is permanently stuck in the shared distribution pool until the operator voluntarily re-enables transfers — a direct analog to the seller being unable to cancel/settle the auction once the malicious bidder starts griefing.
- This is a genuine "permanent lock / non-recoverable loss of claim rights" scenario as defined in the required impact list, without requiring the attacker to hold any privileged role — an operator is not privileged over the staker's principal, yet can hold it hostage.

### Likelihood Explanation
High feasibility, low cost: the "attack" only requires the operator/beneficiary calling a standard, unprivileged public function (`aptos_account::set_allow_direct_coin_transfers(false)`) on their own account, with no special timing or race condition. It naturally arises anytime there is a fee/commission dispute between a staker and operator, giving the operator a credible extortion lever ("re-enable coin transfers if you keep me as operator" or "pay off-chain").

### Recommendation
`distribute_internal` should not let one recipient's inability to receive funds block payouts to the rest of the pool. Options:
- Wrap each `aptos_account::deposit_coins` call so a failure escrows that specific recipient's share (e.g., in a per-recipient claimable resource) instead of reverting the whole distribution, then let that party call a separate `claim` function later once registered/opted-in.
- Alternatively, use `coin::deposit` semantics that don't depend on the optional `DirectTransferConfig` opt-out for module-internal (non-arbitrary) transfers that are the direct result of the recipient's own prior staking actions, since these are not "unsolicited" transfers.

### Proof of Concept
1. Staker creates a staking contract with Operator O, commission 10% (`create_staking_contract`).
2. Time passes; rewards accrue. Operator calls `request_commission`, which internally calls `distribute_internal` then adds Operator's commission share to `distribution_pool` [10](#0-9) .
3. Before the commission becomes withdrawable (i.e., while it is still `pending_inactive`), Operator calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own address and never registers `CoinStore<AptosCoin>` for it (or does so for their beneficiary address set via `set_beneficiary_for_operator`).
4. Once lockup expires and the commission becomes withdrawable, Staker calls `unlock_stake` to withdraw part of their own stake. `unlock_stake` first calls `distribute_internal`, which now must pay out Operator's pending commission share as part of the same loop [11](#0-10) . The `aptos_account::deposit_coins` call to Operator aborts.
5. The entire `unlock_stake` transaction reverts. Staker's stake remains locked in the shared pool. Every subsequent call to `unlock_stake`, `switch_operator`, `update_commision`, or public `distribute` by anyone will likewise abort, until Operator voluntarily re-enables direct transfers.

Note: I was not able to fully re-verify the exact default boolean value returned by `can_receive_direct_coin_transfers` for freshly created accounts within the remaining tool budget, though the module's own doc comment states direct transfers are "enabled by default" and can be disabled at any time by the account owner [12](#0-11) , which is sufficient to establish the unprivileged opt-out path used in this PoC.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Allow anyone to distribute already unlocked funds. This does not affect reward compounding and therefore does
    /// not need to be restricted to just the staker or operator.
    public entry fun distribute(
        staker: address, operator: address
    ) acquires Store, BeneficiaryForOperator {
        assert_staking_contract_exists(staker, operator);
        let store = borrow_global_mut<Store>(staker);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);
        distribute_internal(
            staker,
            operator,
            staking_contract,
        );
    }

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
