### Title
Missing role check on `GET /v2/external_initiators` exposes `OutgoingToken` to view-role users - ([File: core/web/router.go], [File: core/web/external_initiators_controller.go])

### Summary
`GET /v2/external_initiators` is registered without any `RequiresEditRole`/`RequiresRunRole` wrapper, unlike `POST`/`DELETE` on the same resource, so any authenticated user regardless of role — including the lowest-privilege `view` role — can list all `ExternalInitiator` records and read every initiator's `OutgoingToken`. `OutgoingSecret` itself is correctly never serialized (the `ExternalInitiatorResource` presenter struct omits that field entirely), so the second half of the question is not exploitable, but the first half (unauthorized token disclosure to a lower-privilege caller) is.

### Finding Description
In `core/web/router.go`, the `/v2/external_initiators` routes are set up as: [1](#0-0) 

`Create` and `Destroy` are wrapped in `auth.RequiresEditRole`, but `Index` (`GET /v2/external_initiators`) is bound directly with only `paginatedRequest(eia.Index)` — no role check at all, meaning it only requires the base `authv2` authentication (session/token, any role: view, run, edit, admin).

`ExternalInitiatorsController.Index` builds `presenters.ExternalInitiatorResource` for every record and returns it in a JSON:API paginated response: [2](#0-1) 

The resource struct includes `OutgoingToken` in cleartext: [3](#0-2) 

Note that `OutgoingSecret` is not a field on `ExternalInitiatorResource` at all — only `ExternalInitiatorAuthentication` (returned solely from the edit-role-gated `Create` response) carries both `OutgoingToken` and `OutgoingSecret`: [4](#0-3) 

So the presenter redaction for `OutgoingSecret` is correctly enforced on `Index`. The exploitable gap is that a `view`-role user — the least-privileged authenticated role, accepted as an "unprivileged" attacker per the audit rules — can call `GET /v2/external_initiators` and obtain `OutgoingToken` and `AccessKey` for every external initiator configured on the node, not just their own. `RequiresRunRole`/`RequiresEditRole` middleware (`core/web/auth/auth.go`, lines 202–236) is simply never applied to this route, so there is no authorization check stopping this.

### Impact Explanation
`OutgoingToken` (paired with `OutgoingSecret`, generated together via `utils.NewSecret` in `NewExternalInitiator`, `core/bridges/external_initiator.go:38-57`) is the credential the node uses to authenticate itself when it calls back into the external initiator's own service. Disclosure of `OutgoingToken` to a view-role user is a genuine credential-exposure issue (matches the "sensitive credential disclosure to unauthorized role" bounty impact class): a view-role account (e.g., a read-only dashboard/monitoring integration) can enumerate all initiators' outgoing tokens node-wide, beyond what its role is meant to allow. It does not itself yield full authentication to the EI (since `OutgoingSecret` is still redacted from this response), but partial credential exposure combined with any weaker verification on the EI side, or reuse/logging of that token, extends the blast radius beyond the intended role boundary.

### Likelihood Explanation
Trivial and repeatable: any account provisioned with `view` role (the minimum authenticated role) can call `GET /v2/external_initiators` with a valid session or API token and receive `OutgoingToken` values for all initiators in a single unauthenticated-role-check request. No edit/run privilege, no additional exploitation steps, and no timing/race conditions are required.

### Recommendation
Gate `GET /v2/external_initiators` with at least `auth.RequiresRunRole` (or `RequiresEditRole`, consistent with `Create`/`Destroy`) in `core/web/router.go`, matching the sensitivity of the data returned. Alternatively, if `Index` must remain accessible to `view` role for other reasons, strip `OutgoingToken` from `ExternalInitiatorResource` for callers below `edit` role, or omit it entirely from the list endpoint and only surface it once at creation time (as is already done for `OutgoingSecret`).

### Proof of Concept
Go handler-level integration test:
1. Start app with an `ExternalInitiatorsController` wired to a real router (as in `TestExternalInitiatorsController_Index`, `core/web/external_initiators_controller_test.go:63-127`).
2. Create a session/API token for a user with `clsessions.UserRoleView`.
3. Insert an `ExternalInitiator` via `cltest.MustInsertExternalInitiatorWithOpts` with a known `OutgoingToken`.
4. Using the view-role client, call `GET /v2/external_initiators`.
5. Assert response is `200 OK` (not `401`/`403`) and that `externalInitiators[i].OutgoingToken` equals the known outgoing token — demonstrating a view-role account can read outgoing credentials for initiators it does not own.
6. As a control, assert the JSON payload never contains an `outgoingSecret` key (confirming `OutgoingSecret` redaction still holds).

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// ExternalInitiatorAuthentication includes initiator and authentication details.
type ExternalInitiatorAuthentication struct {
	Name           string        `json:"name,omitempty"`
	URL            models.WebURL `json:"url"`
	AccessKey      string        `json:"incomingAccessKey,omitempty"`
	Secret         string        `json:"incomingSecret,omitempty"`
	OutgoingToken  string        `json:"outgoingToken,omitempty"`
	OutgoingSecret string        `json:"outgoingSecret,omitempty"`
}

// NewExternalInitiatorAuthentication creates an instance of ExternalInitiatorAuthentication.
func NewExternalInitiatorAuthentication(
	ei bridges.ExternalInitiator,
	eia auth.Token,
) *ExternalInitiatorAuthentication {
	var result = &ExternalInitiatorAuthentication{
		Name:           ei.Name,
		AccessKey:      ei.AccessKey,
		Secret:         eia.Secret,
		OutgoingToken:  ei.OutgoingToken,
		OutgoingSecret: ei.OutgoingSecret,
	}
	if ei.URL != nil {
		result.URL = *ei.URL
	}
	return result
}
