### Title
Stale Oracle Data Accepted Without Current-Time Validation in `get_latest_data` and `MetaOracle.combine` — (`crates/sui-oracle/move/oracle/sources/simple_oracle.move`, `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

The Sui oracle Move package exposes two public functions — `simple_oracle::get_latest_data` and `meta_oracle::median` (via `combine`) — that return price data without comparing the stored timestamp against the current block time (`Clock`). The `MetaOracle` staleness filter uses `max_timestamp` (the timestamp of the most recently added oracle feed) as its reference point instead of the current block time, so if all oracle providers stop updating, arbitrarily old data passes the freshness window and is returned as trusted. Any on-chain protocol that calls these functions for financial calculations will silently consume stale prices.

---

### Finding Description

**Root cause 1 — `get_latest_data` has no staleness check at all.**

`submit_data` correctly records `clock::timestamp_ms(clock)` when writing data: [1](#0-0) 

But `get_latest_data` accepts no `Clock` argument and performs no age comparison before returning the stored value: [2](#0-1) 

The returned `Data<T>` carries a `timestamp` field, but the caller receives no signal that the data is stale; it is indistinguishable from fresh data.

**Root cause 2 — `MetaOracle.combine` anchors its freshness window to `max_timestamp`, not to the current block time.**

`add_simple_oracle` sets `max_timestamp` to the timestamp of the last oracle added (not the true maximum, and not the current time): [3](#0-2) 

`combine` then computes `min_timestamp = max_timestamp - time_window_ms` and accepts any oracle whose timestamp exceeds that floor: [4](#0-3) 

Neither `combine` nor `median` accepts a `Clock` argument: [5](#0-4) 

**Concrete staleness scenario.** Suppose three oracle providers last updated at time T (e.g., 08:00 UTC) and `time_window_ms = 60_000` (60 s). At 10:00 UTC (T + 7 200 000 ms), a user calls a protocol that builds a `MetaOracle`, calls `add_simple_oracle` three times, then calls `median`. `max_timestamp` = T; `min_timestamp` = T − 60 s. All three feeds have timestamps > T − 60 s, so all three pass. `median` returns a price that is two hours old with no error or warning.

The off-chain Rust uploader does have a `staleness_tolerance` guard: [6](#0-5) 

But this guard is entirely off-chain. It only prevents the oracle node from submitting a data point that was stale before it was uploaded. It does not prevent on-chain consumers from reading data that became stale after it was uploaded (e.g., because the oracle node went offline). The on-chain Move code has no equivalent protection.

---

### Impact Explanation

Any Move protocol that calls `get_latest_data` or `MetaOracle.median` for price-sensitive logic (collateral valuation, liquidation thresholds, swap rates, etc.) will silently use arbitrarily old prices whenever the oracle node is delayed or offline. This constitutes harmful smart-contract behavior: financial state transitions (mints, burns, liquidations, swaps) execute at incorrect prices, causing direct fund loss for users of those protocols. The `get_latest_data` function is public and callable by any package publisher or ordinary user constructing a PTB.

---

### Likelihood Explanation

Oracle node outages are a known operational risk (network partition, upstream data provider failure, software bug). The off-chain staleness guard only protects against the node submitting old data; it does not protect against the node going silent. Because the on-chain check is absent, any period of oracle silence — however brief — leaves stale data silently consumable for an unbounded duration. The `MetaOracle` `time_window_ms` parameter provides a false sense of security because it is anchored to the stale data itself rather than to the current block time.

---

### Recommendation

1. **Add a `Clock` parameter and a `max_age_ms` parameter to `get_latest_data`** and abort (or return `option::none`) when `clock::timestamp_ms(clock) - timestamp > max_age_ms`:

```move
public fun get_latest_data<T: store + copy>(
    oracle: &SimpleOracle,
    ticker: String,
    clock: &Clock,
    max_age_ms: u64,
): Option<Data<T>> {
    if (!df::exists_(&oracle.id, ticker)) { return option::none() };
    let data: &StoredData<T> = df::borrow(&oracle.id, ticker);
    let StoredData { value, sequence_number, timestamp, identifier } = *data;
    if (clock::timestamp_ms(clock) - timestamp > max_age_ms) {
        return option::none()
    };
    option::some(data::new(value, ticker, sequence_number, timestamp, oracle.address, identifier))
}
```

2. **Pass `Clock` through `add_simple_oracle`, `combine`, and `median`** and replace `max_timestamp` with `clock::timestamp_ms(clock)` as the freshness anchor:

```move
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, clock: &Clock): (vector<T>, vector<address>) {
    let MetaOracle { mut oracle_data, threshold, time_window_ms, .. } = meta_oracle;
    let now = clock::timestamp_ms(clock);
    let min_timestamp = now - time_window_ms;
    // ... rest unchanged
}
```

3. **Fix the `max_timestamp` accumulation bug** in `add_simple_oracle`: use `max(max_timestamp, data::timestamp(...))` rather than unconditional assignment, so insertion order does not affect the result.

### Proof of Concept

```
T = 08:00:00 UTC  — oracle providers last submit data via submit_data (timestamp stored = T)
T + 2h            — oracle node goes offline; no new submit_data calls
T + 2h + 1s       — attacker/user calls a protocol that does:
                      let mut meta = meta_oracle::new(2, 60_000, b"SUIUSD");
                      meta_oracle::add_simple_oracle(&mut meta, &oracle_a);  // ts = T
                      meta_oracle::add_simple_oracle(&mut meta, &oracle_b);  // ts = T
                      meta_oracle::add_simple_oracle(&mut meta, &oracle_c);  // ts = T
                      // max_timestamp = T; min_timestamp = T - 60_000 ms
                      // all three feeds: timestamp T > T - 60_000 → accepted
                      let price = meta_oracle::median(meta);
                      // price is 2-hour-old data, returned as TrustedData with no error
```

The protocol proceeds to execute financial logic (e.g., a liquidation or a swap) at the stale price. No on-chain assertion fires.

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
