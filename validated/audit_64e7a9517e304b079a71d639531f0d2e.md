### Title
`switch_operator` leaves stale commission shares in the shared `distribution_pool`, letting the new operator siphon the old operator's locked commission growth - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::switch_operator` reuses the same `StakingContract.distribution_pool` when moving a staking contract from `old_operator` to `new_operator`, without purging or ring-fencing the commission shares that were just bought-in for `old_operator`. Every later call that grows the pool's `total_coins` (any `distribute`, `request_commission`, `unlock_stake`, or `add_stake`, all permissionless) runs `update_distribution_pool`, which excludes only the *current* operator address from commission-charging. Since `old_operator != new_operator` after the switch, the old operator's already-earned, locked (pending_inactive) commission balance is now treated as an ordinary "staker-like" shareholder and is repeatedly taxed at `new_commission_percentage`, with the taxed shares transferred straight into `new_operator`'s balance in the same pool.

### Finding Description
When a staker calls `switch_operator`, the code does: [1](#0-0) 

`request_commission_internal` is invoked for `old_operator` before the switch, which calls `add_distribution(operator=old_operator, ..., recipient=old_operator, commission_amount)` and buys `old_operator` shares into `staking_contract.distribution_pool`: [2](#0-1) [3](#0-2) 

The exact same `staking_contract` object (including its `distribution_pool`, now holding `old_operator`'s unpaid commission shares) is then re-inserted into the map under the `new_operator` key: [4](#0-3) 

Any subsequent permissionless call that changes the pool's stake amount (`distribute`, `request_commission`, `unlock_stake`, `add_stake`) triggers `update_distribution_pool` with `operator = new_operator`: [5](#0-4) 

This function charges commission on the *growth* of every shareholder's balance whose address differs from the passed-in `operator`, transferring the taxed shares to that `operator`. Before the switch, `old_operator`'s own commission shares were excluded from taxation because `shareholder == operator`. After the switch, `old_operator != new_operator`, so `old_operator`'s locked commission balance (which keeps growing while sitting in `pending_inactive`, since Aptos rewards accrue on locked/pending_inactive stake too) is now wrongly treated as taxable "staker" balance, and each growth increment is skimmed at `new_commission_percentage` and credited to `new_operator`'s shares in the same pool via `pool_u64::transfer_shares`.

This is reachable with no special privilege: `distribute` is a public entry function callable by anyone, and normal staker actions (`add_stake`, `unlock_stake`, `request_commission`) also invoke the same pool-update path, so simply letting time (epochs) pass and calling any of these functions repeatedly drains value from `old_operator`'s already-earned/locked commission into `new_operator`'s balance.

### Impact Explanation
This corrupts commission accounting and credits the wrong account: value that unambiguously belongs to `old_operator` (already-requested, locked commission awaiting the stake pool's lockup expiry) is progressively transferred to `new_operator`, who has no claim to work done for the prior lockup cycle. This falls squarely under the required impact "Operator commission ... share-accounting corruption that credits the wrong account or traps value," and is triggerable by any unprivileged caller (the staker performing a normal `switch_operator`, or any third party calling permissionless `distribute`/`request_commission` afterward) without the attacker needing to already hold the old operator's role. The magnitude scales with the reward rate and time between the switch and `old_operator`'s eventual withdrawal.

### Likelihood Explanation
High. `switch_operator` is a normal, permissionless staker operation with no cooldown preventing subsequent stake activity, and the poisoning path (`update_distribution_pool`) is triggered by ordinary, frequent operations (`distribute`, `unlock_stake`, `add_stake`, `request_commission`), all of which are public entry functions. No special conditions are required beyond an operator switch happening while the old operator has unpaid, locked commission in `distribution_pool` (a very common state, since commission is typically requested before/at the switch).

### Recommendation
Do not reuse the same `distribution_pool` across an operator switch while it still holds unresolved shares for the old operator. Options:
- Force a full `distribute_internal` and zero-out check before allowing `switch_operator` to leave residual shares, or
- Track commission ownership per-epoch/operator explicitly (e.g., snapshot and pay out old operator's shares fully before reassigning the pool to `new_operator`), or
- In `update_distribution_pool`, exclude the recorded original recipient of each share bucket from taxation rather than comparing against the *current* operator address, so historically-earned commission for a former operator can never be re-taxed on behalf of a new operator.

### Proof of Concept
1. Staker creates a staking contract with `operator_A`, commission `10%`. Validator joins active set and accrues rewards.
2. `operator_A` (or staker) calls `request_commission` (or it happens implicitly inside `switch_operator`), locking, say, `1000 APT` of commission for `operator_A` as pending_inactive shares in `distribution_pool`.
3. Staker calls `switch_operator(old_operator=operator_A, new_operator=operator_B, new_commission_percentage=10)`. The `distribution_pool` — still containing `operator_A`'s 1000 APT worth of shares — is now stored under `operator_B`'s key.
4. Epochs pass; the locked pending_inactive stake (including `operator_A`'s 1000 APT) earns further rewards.
5. Anyone calls `distribute(staker, operator_B)` (permissionless). `distribute_internal` -> `update_distribution_pool(pool, new_total, operator=operator_B, 10%)` runs: since `operator_A != operator_B`, `operator_A`'s balance growth is taxed 10% and those shares are transferred to `operator_B`.
6. Repeat step 4–5 across multiple epochs before `operator_A` calls `distribute` to claim their commission: each cycle skims part of `operator_A`'s locked balance into `operator_B`, who withdraws it as if it were their own commission.

Note: I was unable to run the Move test suite in this environment to empirically confirm the numeric skim on a live VM; the trace above is based on direct code reading of `switch_operator`, `request_commission_internal`, `add_distribution`, and `update_distribution_pool` in `staking_contract.move`. A background Devin session with test execution capability could add a Move unit test (mirroring existing tests like `test_update_commission`) to concretely demonstrate the balance shift from `operator_A` to `operator_B`.

```text
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );
```

```text
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }
```

```text
    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
```
