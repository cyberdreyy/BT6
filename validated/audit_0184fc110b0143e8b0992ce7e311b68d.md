### Title
Stale confirmations from removed members are not purged from other pending requests, allowing a request to execute with fewer live-member confirmations than `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member()` only removes confirmations for requests that were *created* by the removed member. It does not scrub that member's confirmation entries on other members' pending requests. Because `confirm()` only compares the *size* of the stored confirmation `HashSet` against `num_confirmations` (never re-validating that each entry still belongs to a current member), a confirmation cast by a member who is later removed keeps counting toward the threshold. This lets a request execute with fewer genuinely-live confirmations than the configured threshold, breaking the invariant `confirmations counted == live members who approved`.

### Finding Description
Confirmations are stored per request as a `HashSet<String>` in `self.confirmations` [1](#0-0) .

`confirm()` executes the request purely based on the cardinality of this set versus `num_confirmations`: [2](#0-1) 

`delete_member()` removes a departing member from `self.members` and deletes only the requests that member *itself* created — it does not touch `self.confirmations` entries the member left on *other* members' requests: [3](#0-2) 

Sequence:
1. Multisig has members `{A, B, C, D}`, `num_confirmations = 3`.
2. `D` creates request `R` (e.g., a `Transfer`). `A` confirms `R` → `confirmations(R) = {A}`.
3. Separately, members vote to remove `A` (an `DeleteMember{A}` request reaches threshold and executes). `delete_member` only clears requests created by `A`; `R`'s confirmation set still contains `A`, because `R` was created by `D`, not `A`. Live members are now `{B, C, D}`.
4. `B` confirms `R` → `confirmations(R) = {A, B}`, size 2. `confirm()` checks `2 + 1 >= 3` → true, and executes `R`.

`R` executes with only two genuinely live approvals (`B` and `D`, the creator/implicit confirmer via `add_request_and_confirm` semantics, or just `B` if added via `add_request`), even though the contract enforces `num_confirmations = 3`. The stale entry from the removed member `A` was silently counted as if it were a live approval.

### Impact Explanation
This breaks the binding "confirmations counted == live members who approved," letting a `MultiSigRequest` (including `Transfer`, `FunctionCall`, `AddKey`, etc.) execute below the actual threshold of currently-authorized signers. Per the scope's impact classes this is Critical: "a multisig request executed below threshold," and it can directly enable unauthorized movement of NEAR held by the multisig account.

### Likelihood Explanation
No attacker-controlled deployment, foundation action, or key compromise is required — only ordinary multisig member turnover (a routine `DeleteMember` action) combined with a confirmation made before removal. Any multisig contract that ever rotates/removes a member while requests are pending is exposed. This is a straightforward, always-reachable code path in normal operation.

### Recommendation
When executing `DeleteMember`, iterate over **all** pending requests (not just those created by the removed member) and remove the departing member's entry from each request's confirmation `HashSet`; alternatively, validate at `confirm()`-time (before comparing set size to `num_confirmations`) that every stored confirmer in the set is still present in `self.members`, discarding stale ones or recomputing the live count before the threshold check.

### Proof of Concept
```rust
// members: A, B, C, D ; num_confirmations = 3
let mut c = MultiSigContract::new(vec![A, B, C, D], 3);

// D creates request R
let r = c.add_request(transfer_request); // as D
// A confirms R
c.confirm(r); // as A -> confirmations(r) = {A}

// Separately: members reach threshold to remove A via DeleteMember action
// (delete_member only purges requests created by A, not r)

// Now live members = {B, C, D}
// B confirms R
c.confirm(r); // as B -> confirmations(r).len() == 2; 2+1 >= 3 -> executes
// R executes even though only 1-2 live members ever approved it,

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
