### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing requests to execute below `K` live confirmations - (`File: multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only purges requests and confirmation sets for requests that the removed member *originally created* (`r.member == member`). It never scans other outstanding requests to remove confirmation entries the removed member may have already cast on *other* members' requests. Since `confirm()` counts confirmations purely by `HashSet` length, a stale confirmation from a now-removed member is still counted as a valid vote, letting a request execute with fewer live-member confirmations than `num_confirmations` requires.

### Finding Description
`confirm()` decides whether to execute a request purely based on the size of the stored `confirmations` set for that `request_id`: [1](#0-0) 

Nothing in this path re-validates that every account/key present in `confirmations` is still a current member of `self.members` at execution time — it only checks that the *current caller* is a member via `assert_valid_request`/`current_member()`. [2](#0-1) 

When a member is removed, `delete_member` cleans up only requests that member itself created, and the confirmation set attached to those requests: [3](#0-2) 

It does **not** iterate `self.confirmations` to strip the removed member's entries from other members' pending requests. Consequently, if member `B` confirmed a pending request `X` created by member `A`, and `B` is later removed from the multisig (a normal, unprivileged multisig operation), `B`'s confirmation on `X` remains in storage and continues to count toward the `num_confirmations` threshold for `X`.

This breaks the intended equality: `confirmations counted for a request == confirmations from members who are live at execution time`. Instead, `confirmations counted ⊇ {stale entries from removed members} ∪ {live confirmations}`.

### Impact Explanation
This directly matches the Critical impact category "a multisig request executed below threshold": an attacker who is a live member (or colludes with fewer live members than `num_confirmations`) can get a malicious request (e.g. `Transfer`, `AddKey` with full access permission, `FunctionCall`) executed by relying on stale confirmations left behind by members that have since been removed via `DeleteMember`. This effectively lowers the real number of *live* signatures required, undermining the entire K-of-N security guarantee of the multisig, and can result in NEAR (or access to the account) being moved/granted by fewer authorized parties than configured.

### Likelihood Explanation
Member turnover (removing a compromised or departing member/key) is a normal operational event for any long-lived multisig, and the contract does not require confirmations to be re-validated or purged on such removal. Any request left pending across a `DeleteMember` execution is exposed; no special privileges beyond being a current or former legitimate member are needed to benefit from the stale-vote count, only ordinary usage plus timing.

### Recommendation
When removing a member in `delete_member`, iterate all entries in `self.confirmations` (not just requests created by that member) and remove the removed member's identity from every confirmation set, re-checking whether any request now falls below the required threshold. Alternatively, at `confirm()`/execution time, filter the stored confirmation set down to only entries whose owner is still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request` with a malicious `Transfer`/`AddKey` request `X` targeting the multisig account itself.
3. `B` calls `confirm(X)` → `confirmations = {B}` (1 < 3, not yet executed).
4. `C` calls `confirm(X)` → `confirmations = {B, C}` (2 < 3, not yet executed).
5. Separately, via a normal, properly-confirmed `DeleteMember { member: B }` request, `B` is removed from the multisig. `delete_member` only cleans up requests *created* by `B`; request `X` (created by `A`) and its confirmation set `{B, C}` are left untouched.
6. `D` calls `confirm(X)` → `confirmations.len() (2) + 1 == 3 >= num_confirmations (3)` → request `X` executes, even though only `C` and `D` are still live members who actually confirmed — one fewer live confirmation than the configured threshold. [1](#0-0) [3](#0-2)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

        );
    }
