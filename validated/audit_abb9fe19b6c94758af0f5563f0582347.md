This confirms the vulnerability. The `wd` passed to `archive.NewExtractor` is only used by the tar/tarzstd/zip-legacy extractors as `e.dir` for path validation, but for `zip` format the `ziplegacy.extractor.Extract` never uses `e.dir` at all — it calls `archives.ExtractZipArchive(zr)` directly without any chroot/prefix check. Combined with `extractZipFile`/`extractZipFileEntry` in `helpers/archives/zip_extract.go` using `file.Name` verbatim for `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile(file.Name, ...)`, a malicious zip entry name containing `../` traversal writes outside the intended working directory.

### Title
Zip archive extraction path traversal allows writing files outside job workspace - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` and `extractZipFileEntry` in `helpers/archives/zip_extract.go` use the raw `zip.File.Name` from the archive to build filesystem paths (`os.MkdirAll(filepath.Dir(file.Name), 0o777)`, `os.OpenFile(file.Name, ...)`) without any validation that the resolved path stays within the extraction directory. `ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) receives a `dir` field but never uses it to constrain extraction, unlike `tarzstd.extractor.Extract` which resolves `filepath.Join(e.dir, hdr.Name)` and rejects paths that escape via `strings.HasPrefix(path, e.dir+separator)`.

### Finding Description
The reachable call path is `CacheExtractorCommand.Execute` (`commands/helpers/cache_extractor.go:655-660`) → `archive.NewExtractor(format, f, size, wd)` → for zip format, `ziplegacy.NewExtractor` → `extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32`) → `archives.ExtractZipArchive(zr)` (`helpers/archives/zip_extract.go:85-110`) → `extractZipFile` → `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`.

At no point is `file.Name` checked against the working directory. `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` directly on the raw name [1](#0-0) , and `extractZipFileEntry` opens/writes to `file.Name` directly [2](#0-1) . Since extraction happens from the process's current working directory (`wd` obtained via `os.Getwd()` in `cache_extractor.go`, then `os.chdir`-relative paths are used implicitly through relative `file.Name`), a zip entry named e.g. `../../../../home/gitlab-runner/.ssh/authorized_keys` resolves relative to CWD and escapes the intended cache directory.

By contrast, `tarzstd.extractor.Extract` explicitly guards against this: it computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it if `!strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir` [3](#0-2) . The zip path has no equivalent check — `ziplegacy.extractor.Extract` stores `dir` in its struct but never references it in `Extract` [4](#0-3) .

`ExtractZipArchive` also performs a `errorIfGitDirectory` check and git-archive warning, but this is unrelated to path traversal and does not prevent it [5](#0-4) . No `filepath.Clean`, `filepath.Abs`, or prefix check exists anywhere in the zip extraction path.

Both cache restore (`CACHE_COMPRESSION_FORMAT=zip`, default) and artifact download flows that use `archive.NewExtractor` with the zip format are affected, since both route through the same `ExtractZipArchive` function with attacker-controlled archive bytes (an unprivileged pipeline author fully controls the cache/artifact content it uploads in a prior job, which is later restored/extracted in another job run — potentially on the same host/runner for shell/docker executors sharing paths).

### Impact Explanation
A crafted zip with entries such as `../../../../etc/passwd`-style names (or paths escaping the intended cache/artifact directory) causes the runner process to `MkdirAll` and write/overwrite files at attacker-chosen paths outside the job's working directory, using the permissions of the `gitlab-runner` process. This can corrupt files, plant files that get picked up by a later job on the same host (e.g. shared cache directories, shell executor home directory), or overwrite files another job/pipeline relies on — a file write primitive outside the job workspace, matching the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Fully reachable by an unprivileged pipeline author: they only need to control the content of a cache archive (trivial — caches are written by job scripts and read back via `cache:` config) or an artifact zip, then have it restored/extracted by a later job (own job or a shared-runner scenario where cache/artifact paths overlap, e.g. shared runner host paths, distributed cache directories, or repeated pipeline runs on the same executor). Constructing a zip with a `..`-traversal entry name is trivial (Go's `archive/zip` writer, or manually crafted zip, does not validate names). No authentication or privilege escalation is required beyond normal CI job execution rights.

### Recommendation
In `helpers/archives/zip_extract.go`, before acting on `file.Name` in `extractZipFile` (and its sub-functions), resolve the target path against the intended root directory and reject entries that escape it — mirroring `tarzstd_extractor.go`'s approach: compute `filepath.Join(rootDir, file.Name)`, take `filepath.Abs`, and verify it has `rootDir` as a prefix (or use `filepath.Rel` and check for `..`/absolute results) before calling `MkdirAll`/`OpenFile`/`Mkdir`/`Symlink`. Since `ExtractZipArchive` currently has no directory context, thread the extraction root down from `ziplegacy.extractor.Extract` (which already has `e.dir` but discards it) through `ExtractZipArchive`/`extractZipFile`/`extractZipFileEntry`, and add the same "cannot be extracted outside of chroot" validation used by tarzstd.

func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    origWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(origWd)

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    w, err := zw.CreateHeader(&zip.FileHeader{Name: "../escape.txt"})
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the file was NOT created outside tmpDir's parent
    escapedPath := filepath.Join(filepath.Dir(tmpDir), "escape.txt")
    _, statErr := os.Stat(escapedPath)
    require.True(t, os.IsNotExist(statErr), "path traversal succeeded: file created at %s", escapedPath)
}
