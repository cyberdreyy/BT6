Found a concrete TOCTOU (check-then-act) race in the JWT replay cache used to authorize unprivileged HTTP-trigger requests. This is analogous in bug-class to Orion's reentrancy: a check against a stateful cache happens, but the state update (marking the token "used") happens in a separate, non-atomic step later, leaving a window where the same credential can be reused concurrently.

### Title
JWT replay-cache check-then-record race allows single-use HTTP trigger token to authorize concurrent duplicate requests - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The `WorkflowMetadataHandler.Authorize` function checks whether a JWT `jti` has already been used via `jwtCache.isReplay(claims.ID)`, and only later calls `jwtCache.recordUsage(claims.ID)` after verifying the signer is an authorized key. These two operations are not atomic with respect to each other, creating a check-then-act race window analogous to the reentrancy pattern in the Orion exploit (where a balance/state check preceded a state update, letting a re-entrant call observe stale state).

### Finding Description
`Authorize` at [1](#0-0)  performs:
1. `h.jwtCache.isReplay(claims.ID)` — an `RLock`-protected read-only check [2](#0-1) 
2. Authorized-key lookup
3. `h.jwtCache.recordUsage(claims.ID)` — a separate `Lock`-protected write [3](#0-2) 

Because the check (`isReplay`) and the record (`recordUsage`) happen under two independent, non-overlapping locks (not one atomic "check-and-record" critical section), two goroutines handling concurrent HTTP trigger requests bearing the identical single-use JWT can both pass `isReplay` as `false` before either calls `recordUsage`. Both then proceed to be treated as authorized and dispatched to the DON via `HandleUserTriggerRequest`/`authorizeRequest` at [4](#0-3) .

This is architecturally the same class of bug as the Orion exploit: a state check ("has this been used/spent yet?") is performed, an external/asynchronous operation proceeds, and only afterward is the state persisted — allowing the same credential to be "spent" more than once by racing requests before the record catches up. Note that request-ID-based in-flight deduplication (`in-flight request` checks in `http_trigger_handler.go`) is a separate mechanism keyed on `req.ID`, not on the JWT's `jti`; an attacker can send the same valid JWT with two different `req.ID`/JSON-RPC IDs (since `req.ID` is client-supplied per test evidence at [5](#0-4) , which shows the JTI check is what stops replay when IDs differ, but only when timing is sequential, not concurrent).

### Impact Explanation
A single-use, short-lived JWT intended to authorize exactly one workflow-trigger request could be replayed concurrently to trigger the same workflow execution twice (or more) against the DON, bypassing the intended single-use / anti-replay guarantee for an unprivileged, internet-facing HTTP trigger endpoint. Depending on the workflow's side effects (e.g., triggering fund-moving or state-changing on-chain actions), this could cause duplicate unauthorized job/workflow executions.

### Likelihood Explanation
Exploitation requires firing two (or more) requests bearing the same JWT at effectively the same time, which is straightforward for a remote unprivileged client to script (no special access or timing precision beyond a race is required, similar to classic TOCTOU races). The race window includes JWT signature verification, the authorized-key map lookup, and lock acquisition/release overhead, giving a real but narrow window per request pair.

### Recommendation
Merge the replay check and the record into a single atomic critical section (analogous to `RequestReplayGuard.CheckAndRecord` already used elsewhere in the codebase at [6](#0-5) , which correctly performs "check-if-seen" and "record" under one lock). Replace `isReplay` + later `recordUsage` calls in `Authorize` with a single `CheckAndRecordJTI(claims.ID)`-style method that holds the write lock for the entire check-and-set operation, returning an error immediately if the `jti` was already present, and only inserting it if it was not.

### Proof of Concept
Not independently reproduced with a running node; this is inferred directly from the source. Conceptually:
1. Client obtains a valid single-use JWT for `MethodWorkflowExecute` with `jti = X`.
2. Client sends two concurrent HTTP trigger requests with distinct `req.ID`s (`A` and `B`) but the same JWT (`jti = X`).
3. Both goroutines call `Authorize`, both execute `h.jwtCache.isReplay(X)` before either calls `h.jwtCache.recordUsage(X)`.
4. Both pass authorization and are forwarded to `HandleUserTriggerRequest`, resulting in two accepted/dispatched executions from one single-use token — confirmed conceptually against the check/record split at [7](#0-6) , contrasted with the correctly atomic pattern in [6](#0-5) .

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
