### Title
Zip-slip path traversal / arbitrary symlink write in legacy zip extractor bypasses artifact confinement - ([File: helpers/archives/zip_extract.go])

### Summary
The legacy zip extraction path (`ziplegacy` package, used by `archive.NewExtractor` for the `Zip`/`ZipZstd` formats whenever `FF_USE_FASTZIP` is not overriding the registration) writes files using the raw, attacker-controlled `zip.File.Name` field with no path-confinement check at all. This is inconsistent with the `tarzstd` extractor, which explicitly validates that resolved paths stay under the extraction directory, and allows a crafted artifact zip to write files/symlinks outside the intended build directory when `ArtifactsDownloaderCommand.Execute` (or `CacheExtractorCommand.Execute`) extracts it.

### Finding Description
`ArtifactsDownloaderCommand.Execute` computes `wd, _ := os.Getwd()` and calls `archive.NewExtractor(format, f, size, wd)` [1](#0-0) . For the `Zip`/`ZipZstd` formats, unless `FF_USE_FASTZIP` is enabled to override the registration, the extractor used is `ziplegacy.extractor` [2](#0-1) .

`ziplegacy.extractor.Extract` discards the `dir` field entirely and simply calls `archives.ExtractZipArchive(zr)` with no directory argument at all: [3](#0-2) 

`ExtractZipArchive` iterates zip entries and calls `extractZipFile(file)` for each, which uses `file.Name` (the raw, attacker-supplied path from the zip central directory) directly, with only a `.git`-directory check — no path-traversal or absolute-path validation: [4](#0-3) [5](#0-4) 

`extractZipFileEntry`/`extractZipSymlinkEntry` then perform `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(string(data), file.Name)` using this unsanitized name/content: [6](#0-5) 

Compare this to the `tarzstd` extractor, which explicitly resolves the absolute path and rejects anything escaping `e.dir`: [7](#0-6) 

No equivalent check exists anywhere in the `ziplegacy`/`helpers/archives` code path. A zip entry named e.g. `../../../../some/other/path` (or an absolute-like traversal chain) is honored verbatim, relative to whatever the process's current working directory happens to be (which is the downstream job's build directory when invoked from `ArtifactsDownloaderCommand.Execute`). Symlink entries are equally unchecked, and both the symlink location and its target content are attacker-controlled.

### Impact Explanation
When the ziplegacy extractor is in use, a malicious dependency-job author can craft an artifacts archive whose entries traverse out of the downstream job's build directory, writing arbitrary files (or dangling symlinks with attacker-chosen targets) to any path reachable and writable by the runner helper process's OS user — outside the artifact/build root that cross-job artifact transfer is supposed to be confined to. On shared runners where multiple jobs/projects execute under the same OS user, this permits one job's artifacts to write into another job's directory or elsewhere on the runner filesystem, violating the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Reachable whenever the `ziplegacy` extractor handles `Zip`/`ZipZstd` extraction — which happens by default for `Zip` unless the operator has enabled `FF_USE_FASTZIP` (an opt-in flag gating the `archive.Register(archive.Zip, fastzip.NewArchiver, fastzip.NewExtractor)` call), and always for `ZipZstd` decompression unless that flag additionally overrides it (per explicit comment in the registration code) [8](#0-7) . Any unprivileged CI user who can author a job whose artifacts are consumed downstream via `dependencies:`/`needs:` can supply the malicious archive; no special runner privileges are required, and the flow is deterministically repeatable.

### Recommendation
Add the same confinement check used in `tarzstd_extractor.go` to the zip-legacy extraction path: resolve each `zip.File.Name` to an absolute path against the target extraction directory and reject the entry if it does not remain a descendant of that directory (also reject/limit symlink targets similarly). Thread the actual `dir` parameter through `ziplegacy.extractor.Extract` into `archives.ExtractZipArchive`/`extractZipFile` instead of relying implicitly on the process's current working directory.

### Proof of Concept
Differential Go test exercising `archive.NewExtractor` for `zip` (ziplegacy), `tarzstd`, and `fastzip` with an identical malicious payload:
```go
func TestExtractorPathTraversalConsistency(t *testing.T) {
    payloadName := "../../evil.txt" // or a symlink entry pointing outside dir
    for _, format := range []archive.Format{archive.Zip, archive.TarZstd} {
        t.Run(string(format), func(t *testing.T) {
            dir := t.TempDir()
            subdir := filepath.Join(dir, "sub")
            require.NoError(t, os.MkdirAll(subdir, 0777))

            archiveBytes := buildArchiveWithTraversalEntry(t, format, payloadName, "pwned")

            extractor, err := archive.NewExtractor(format, bytes.NewReader(archiveBytes), int64(len(archiveBytes)), subdir)
            require.NoError(t, err)

            err = extractor.Extract(context.Background())
            // Expect rejection for all formats:
            assert.Error(t, err, "extractor must reject path traversal entries")
            assert.NoFileExists(t, filepath.Join(dir, "evil.txt"))
        })
    }
}
```
Expected/actual: `tarzstd` rejects with `"cannot be extracted outside of chroot"`; `ziplegacy` currently extracts successfully and creates `dir/../evil.txt` (i.e., `dir_parent/evil.txt`), demonstrating the inconsistency and the traversal bug. This can be escalated to an integration-level PoC by driving it through `ArtifactsDownloaderCommand.Execute` with a fake `network.Network` returning the crafted zip, asserting a file appears outside `wd`.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
