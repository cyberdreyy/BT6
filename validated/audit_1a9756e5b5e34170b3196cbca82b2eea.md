### Title
GET /v2/chains/:network/:ID and GET /v2/nodes/:network expose raw node/chain TOML config (including RPC URLs) to any authenticated view-role user — ([File: core/web/router.go])

### Summary
The chains and nodes routes are registered under the `authv2` group, which only requires the generic `auth.Authenticate` middleware (token or session), with no `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper like most other sensitive routes in the same file. The handlers return `presenters.ChainResource`/`presenters.NodeResource`, which embed the raw `Config` TOML string of the node/chain without any redaction.

### Finding Description
In `core/web/router.go`, the routes are registered as: [1](#0-0) 
No `auth.RequiresEditRole` or `auth.RequiresAdminRole` wrapper is applied, unlike comparable mutating/sensitive routes elsewhere in the same function (e.g. `keys/*`, `jobs`, `bridge_types`). This means any principal that merely passes the base `auth.Authenticate` check (session or API token holder with the lowest "view" role) can reach `chainsController.Show`/`Index` and `nodesController.Index`.

`chainsController.Show` (`core/web/chains_controller.go:69-78`) and `nodesController.Index` (`core/web/nodes_controller.go:44-79`) call into `presenters.NewChainResource`/`presenters.NewNodeResource`: [2](#0-1) 
Both presenters copy the `Config` field (a TOML-serialized string of the chain/node configuration) verbatim into the JSON:API response, with no field-level redaction logic in the web layer. Chain/node TOML configs for EVM (and other chains) commonly contain `WSURL`/`HTTPURL` node connection strings, which frequently embed provider API keys or auth tokens directly in the URL path or query string (e.g., Alchemy/Infura-style endpoints). Because the route only requires baseline authentication and not `RequiresEditRole`, a low-privileged view-role session or API token can retrieve this data via a simple GET.

### Impact Explanation
This matches the Chainlink bounty impact class of "sensitive credential/secret disclosure" — a view-role user (or restricted API token holder) can read RPC endpoint URLs that may contain embedded API keys/auth material for chains configured on the node, which are otherwise intended to be admin/edit-role-only configuration data.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs a valid authenticated session or API token with the lowest ("view") role — no edit/admin privilege is required, since no `RequiresEditRole`/`RequiresAdminRole` wrapper guards these routes. The request is a single unauthenticated-role-elevation-free GET call, fully repeatable, and requires no timing or race conditions.

### Recommendation
Wrap the chain/node read routes with a role check appropriate to the sensitivity of the data (at minimum confirm this is intentional design consistent with other "Index" routes like `/keys/eth` which are also view-accessible), and/or redact `Config` fields containing embedded credentials (URL userinfo, API keys in query/path segments) in `presenters.NewChainResource`/`presenters.NewNodeResource` before serialization, similar to existing config-secret masking patterns used elsewhere (e.g., `ConfigController`/`SecretsForLogging`-style masking).

### Proof of Concept
1. In `core/web/chains_controller_test.go`/`nodes_controller_test.go` (or a new handler-level integration test), create a test app session authenticated with `sessions.ViewRole` only (no edit/admin role) using the existing `cltest.CreateUserWithRole`/`cltest.NewIntegrationTestConfig` helpers used elsewhere in the package.
2. Configure a chain/node with an `HTTPURL`/`WSURL` containing embedded credentials (e.g., `https://user:secret@rpc.example.com` or `https://rpc.example.com/v2/APIKEY`).
3. Perform `GET /v2/chains/evm/1` and `GET /v2/nodes/evm` with the view-role session cookie/token.
4. Assert the handler returns HTTP 200 (not 401/403), and that the JSON:API `attributes.config` field in the response body contains the raw URL string with the embedded credential/API key — confirming disclosure to a view-role principal without any edit-role check being enforced.

type ChainResource struct {
	JAID
	Network string `json:"network"`
	Enabled bool   `json:"enabled"`
	Config  string `json:"config"` // TOML
}

// GetName implements the api2go EntityNamer interface
func (r ChainResource) GetName() string {
	return "chain"
}

// NewChainResource returns a new ChainResource for chain.
func NewChainResource(chain chainlink.NetworkChainStatus) ChainResource {
	return ChainResource{
		JAID:    NewJAID(chain.ID),
		Network: chain.Network,
		Config:  chain.Config,
		Enabled: chain.Enabled,
	}
}

type NodeResource struct {
	JAID
	ChainID string `json:"chainID"`
	Name    string `json:"name"`
	Config  string `json:"config"` // TOML
	State   string `json:"state"`
}

// NewNodeResource returns a new NodeResource for node.
func NewNodeResource(node types.NodeStatus) NodeResource {
	return NodeResource{
		JAID:    NewPrefixedJAID(node.Name, node.ChainID),
		ChainID: node.ChainID,
		Name:    node.Name,
		State:   node.State,
		Config:  node.Config,
	}
}
