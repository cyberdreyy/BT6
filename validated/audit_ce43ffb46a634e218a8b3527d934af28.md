### Title
`getChainlinkPrice` hardcodes an 8-decimal feed assumption and returns a 28-decimal price when the feed answers with 18 decimals — ([File: contracts/strategies/usual/IdleUsualStrategy.sol](contracts/strategies/usual/IdleUsualStrategy.sol))

### Summary
`IdleUsualStrategy.getChainlinkPrice()` multiplies the Chainlink `answer` by a hardcoded `1e10`, assuming the feed has 8 decimals. If the `USD0ppOracle` feed (`0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB`) returns an 18-decimal answer — as is the case for many Chainlink feeds — the returned "oracle price" is ~1e28 instead of ~1e18. Since `oraclePrice` is compared against `oneToken` (`1e18`) in `IdleCDOUsualVariant.stopEpoch()`, the senior-protection loss waterfall is permanently skipped. [1](#0-0) 

### Finding Description
In `IdleUsualStrategy.sol:164-172`:

```solidity
function getChainlinkPrice() public view returns (uint256) {
    (,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
    require(updatedAt > block.timestamp - 24 hours, "Stale price");
    // scale the answer to 18 decimals
    return uint256(answer) * 1e10;
}
```

The function never queries `IOracle.decimals()`. It blindly scales by `1e10`, which is only correct for an 8-decimal feed. The `IOracle` interface declared at the top of the file doesn't even expose `decimals()`.

This price feeds three critical paths:
1. `initialize()` sets `oraclePrice = getChainlinkPrice()` (line 71).
2. `IdleCDOUsualVariant.startEpoch()` stores `priceAtStartEpoch = getChainlinkPrice()` (IdleCDOUsualVariant.sol:63).
3. `IdleCDOUsualVariant.stopEpoch()` uses it to decide whether juniors owe seniors a top-up (IdleCDOUsualVariant.sol:77-99):

```solidity
uint256 _oraclePrice = _strategy.getChainlinkPrice();
_strategy.setOraclePrice(_oraclePrice);
...
if (_oraclePrice >= oneToken) {
  return;  // <-- junior coverage skipped
}
uint256 targetAATVL = lastNAVAA * oneToken / _oraclePrice;
lastNAVAA += targetAATVL - lastNAVAA;
_updateAccounting();
```

With an 18-decimal feed, a real price of e.g. $0.90 produces `answer = 0.9e18` → `getChainlinkPrice() = 0.9e28`, which is always `>= oneToken`. `stopEpoch` therefore always takes the early-return branch: `targetAATVL` is never computed, `lastNAVAA` is never raised to par, and `_updateAccounting()` is never called to socialize the loss into the junior tranche. [2](#0-1) 

### Impact Explanation
Broken invariant: **loss waterfall / senior-at-par guarantee**. The Usual-variant CDO promises that when USD0++ trades below $1, the junior (BB) tranche absorbs the depeg so `lastNAVAA` is restated at `1 / oraclePrice`, keeping seniors whole at $1 par. With an 18-decimal feed:

- A $0.90 real price is read as ~$9e9 (0.9e28 vs `oneToken` = 1e18).
- `stopEpoch` early-returns; no loss is pushed to the BB tranche.
- After the epoch, both AA and BB holders redeem against the unadjusted NAV. AA holders withdraw at a NAV priced on USD0++ tokens actually worth $0.90 — a ~10% (or worse, unbounded as price falls) shortfall that was supposed to be borne entirely by juniors. Juniors escape their obligation; senior losses equal `lastNAVAA * (1 - realPrice)`.

Additionally `setOraclePrice`'s floor check (`price >= floorPrice ? price : floorPrice`) is bypassed in effect: the inflated scaled value always exceeds the floor, so even a catastrophic depeg is masked.

The scenario is realistic: Chainlink USD feeds on several networks (and custom feeds like the Usual USD0++ oracle, which is not a standard 8-decimal aggregator) use 18 decimals, and nothing in the code pins the feed's decimals at deployment.

### Likelihood Explanation
Likelihood is driven by configuration, not attacker action — matching the source report's class. The bug triggers if `USD0ppOracle.decimals() != 8`. No privileged misbehavior is required: the honest owner calls `startEpoch`/`stopEpoch` in the ordinary flow, and the mis-scaled price is committed via `setOraclePrice` (which only checks the lower bound `floorPrice`, not an upper bound). The severity of mispricing is worst-case: 10^10 inflation means *any* real price, including near zero, reads as ≥ $1, so the junior-coverage mechanism is dead code under a mismatched feed.

### Recommendation
Query the feed's decimals and normalize dynamically instead of hardcoding `1e10`:

```solidity
uint8 feedDecimals = IAggregatorV3(USD0ppOracle).decimals();
return uint256(answer) * 10**(18 - feedDecimals);
```

Extend the `IOracle` interface with `decimals()`, and consider a sanity bound in `setOraclePrice`/`stopEpoch` (e.g., revert if the scaled price exceeds a max such as 2e18 for a ~$1 stable asset).

### Proof of Concept
Foundry fork test (place in `test/foundry/`), demonstrating that an 18-decimal answer produces a 1e28-scale price and skips the junior-coverage branch:

```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "./TestIdleCDOLossMgmt.sol";
import {IdleUsualStrategy} from "../../contracts/strategies/usual/IdleUsualStrategy.sol";
import {IdleCDOUsualVariant} from "../../contracts/IdleCDOUsualVariant.sol";

contract OracleDecimalsPoC is TestIdleCDOLossMgmt {
    address constant USD0pp = 0x35D8949372D46B7a3D5A56006AE77B215fc69bC0;
    address constant USD0ppOracle = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;

    function _selectFork() public override { vm.createSelectFork("mainnet", 21767467); }
    function _deployCDO() internal override returns (IdleCDO _cdo) { _cdo = new IdleCDOUsualVariant(); }
    function _deployStrategy(address _owner) internal override returns (address, address) {
        strategy = new IdleUsualStrategy();
        strategyToken = IERC20Detailed(address(strategy));
        stdstore.target(address(strategy)).sig(strategy.token.selector).checked_write(address(0));
        IdleUsualStrategy(address(strategy)).initialize(USD0pp, _owner);
        return (address(strategy), USD0pp);
    }
    function _postDeploy(address _cdo, address _owner) internal override {
        vm.prank(_owner);
        IdleUsualStrategy(address(strategy)).setWhitelistedCDO(_cdo);
    }
    function _createLoss(uint256) internal override {}

    function test_eighteenDecimalFeedSkipsJuniorCoverage() public {
        // Simulate the feed answering with 18 decimals (real price $0.90)
        vm.mockCall(
            USD0ppOracle,
            abi.encodeWithSelector(bytes4(0xfeaf968c)), // latestRoundData()
            abi.encode(uint80(1), int256(0.9e18), uint256(0), block.timestamp, uint80(1))
        );

        // Bug: returned as 0.9e28 instead of 0.9e18
        uint256 scaled = IdleUsualStrategy(address(strategy)).getChainlinkPrice();
        assertEq(scaled, 0.9e28);

        // Setup: seniors deposit during buffer phase
        uint256 amount = 100_000 * 1e18;
        deal(USD0pp, address(this), amount);
        IERC20Detailed(USD0pp).approve(address(idleCDO), amount);
        idleCDO.depositAA(amount);

        vm.prank(owner);
        IdleCDOUsualVariant(address(idleCDO)).startEpoch(7 days);
        vm.warp(block.timestamp + 7 days);

        uint256 navAABefore = idleCDO.lastNAVAA();

        vm.prank(owner);
        IdleCDOUsualVariant(address(idleCDO)).stopEpoch();

        // With correct scaling, lastNAVAA should be raised to navAABefore * 1e18/0.9e18
        // Bug: early return leaves it unchanged -> seniors eat the depeg, juniors escape
        assertEq(idleCDO.lastNAVAA(), navAABefore);
        assertEq(IdleUsualStrategy(address(strategy)).oraclePrice(), 0.9e28);
    }
}
```
