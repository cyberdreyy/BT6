### Title
`GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use floor division instead of the node's ceiling-rounded threshold, causing signer global-state consensus to diverge from the on-chain block-approval threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` and `reached_disagreement` compute the 70%/30% weight thresholds with plain integer floor division, while the canonical on-chain threshold computation `NakamotoBlockHeader::compute_voting_weight_threshold` explicitly rounds *up* (ceil) for the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant. This mirrors the M-3 report's root cause exactly: a percentage/threshold computed via floor division silently accepts a smaller quorum than intended.

### Finding Description
The node-side/consensus-critical threshold used to verify or accumulate block-signature weight always rounds up: [1](#0-0) 

This ceil semantics is deliberately tested and relied upon by the signer when tallying block acceptance/rejection weight (`store_and_process_block_signature`, `handle_block_pre_commit`, rejection tally), all of which call `compute_voting_weight_threshold`: [2](#0-1) [3](#0-2) 

However, `GlobalStateEvaluator` — used by every signer to decide the agreed-upon global state (active miner, burn view, active signer-protocol version, and tx-replay set) — computes the same 70%/30% thresholds with plain floor division instead of the ceil logic used elsewhere: [4](#0-3) 

`determine_global_state`, `determine_latest_supported_signer_protocol_version`, and `determine_global_burn_view` all gate their decisions on `reached_agreement`: [5](#0-4) [6](#0-5) 

Concrete example of the divergence: with `total_weight = 13`, `compute_voting_weight_threshold` returns `10` (`13*7=91`, `91%10 != 0` → ceil adds 1, `91/10 + 1 = 10`), confirmed by the repo's own round-up regression test: [7](#0-6) 

but `reached_agreement(9)` for the same `total_weight = 13` returns `true`, since `13*7/10 = 9` (floor) and `9 >= 9`. This 1-weight-unit gap means the signer set's `GlobalStateEvaluator` will declare "global agreement" on a `current_miner`/burn view/replay set/protocol version at a weight that is strictly below the actual supermajority threshold the chain (and the signer's own block-signature tally logic) enforces.

### Impact Explanation
This breaks the "aggregated-weight vs verified-accepts" equality: the signer's internal notion of reaching consensus on the active miner/global state can be satisfied by less weight than the canonical, ceil-based 70% threshold used for block approval elsewhere in the same codebase. A signer could thus commit to treating a particular miner/burn view/tx-replay-set as the agreed global state without a genuine supermajority behind it, diverging from what the rest of the network (and the node-side `verify_signer_signatures`/`compute_voting_weight_threshold`) would consider sufficient. Because this affects which miner/state a signer treats as authoritative for signing decisions, it can push a signer toward signing/acting on a state that a true supermajority did not actually approve.

### Likelihood Explanation
The gap is deterministic and requires no coordination or majority collusion — it triggers whenever `total_weight * 7` is not evenly divisible by 10 (the common case for most reward-set sizes), which is a normal, naturally occurring configuration rather than an adversarial setup. It is reachable purely through the state each signer already collects from ordinary StackerDB gossip.

### Recommendation
Change `reached_agreement`/`reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use the same ceiling-rounded formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (or call that function directly) so that "global state agreement" thresholds are always at least as strict as the on-chain block-approval threshold.

### Proof of Concept
1. Construct a `GlobalStateEvaluator` with `total_weight = 13` (e.g., 13 signers of weight 1 each). [8](#0-7) 
2. Call `evaluator.reached_agreement(9)` → returns `true` (`13*7/10 = 9`).
3. Compare against `NakamotoBlockHeader::compute_voting_weight_threshold(13)` → returns `10` (ceil of `9.1`).
4. The signer's global-state machine considers "agreement reached" for a candidate current_miner/burn view/protocol version at weight 9, one full unit below the 10-weight supermajority the chain itself requires for block approval — demonstrating the precision-loss divergence.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
