I've confirmed the vulnerability in `multisig2/src/lib.rs`. The `delete_member` function at lines 356-379 only removes confirmations for requests that were *added* by the deleted member (via the `filter_map` on line 365 matching `r.member == member`), but it never scrubs that member's confirmation entries from the `confirmations` sets of *other* requests they may have previously confirmed. The `confirm` function at lines 292-315 then blindly trusts `confirmations.len()` without verifying that each entry still belongs to a current member, so a stale confirmation from a removed member can count toward the threshold.

### Title
Stale confirmations from removed multisig members are still counted toward the approval threshold - (File: multisig2/src/lib.rs)

### Summary
`confirm()` counts `confirmations.len()` against `num_confirmations` without validating that every counted confirmation belongs to a currently active member. `delete_member()` only purges confirmation sets for requests that the removed member themselves *added* (`self.requests.iter().filter_map(|(k, r)| if r.member == member ...)`, `multisig2/src/lib.rs:362-371`); it never scans the `confirmations` map to strip that member's entry from requests added by *other* members that this member had confirmed. This breaks the equality that should hold: `confirmations recorded for a request == confirmations from members who are still active`.

### Finding Description
`add_request` stores a request keyed by nonce and initializes an empty `confirmations: HashSet<String>` [1](#0-0) . Any current member can call `confirm`, which inserts `member.to_string()` into that set if the threshold isn't yet reached [2](#0-1) .

When a member is removed via `DeleteMember`, `delete_member` deletes outstanding requests *added by* that member and clears their confirmation sets, and removes the member from `self.members` and `num_requests_pk` [3](#0-2) . It does not iterate the `confirmations` map to remove the departing member's string entry from confirmation sets belonging to requests added by *other* members. Since `confirm` only checks set length (`confirmations.len() as u32 + 1 >= self.num_confirmations`), a confirmation cast by a now-removed member is still counted as valid weight toward the threshold.

### Impact Explanation
This crosses the "confirmations counted versus live members" authorization boundary and can result in "a multisig request executed below threshold" — an explicitly Critical impact for this contract class. Concretely: with `num_confirmations = 2` and members `{A, B, C}`, if a pending request added by `C` already has a confirmation from `A`, and `A` is subsequently removed from the multisig via a legitimate `DeleteMember` action, the request's confirmation set still contains `A`. When `B` (a single genuinely current member) confirms, the code sees `len()+1 = 2 >= 2` and executes the request — even though only one currently-authorized member (`B`) ever approved it under the current membership. The multisig's core custody guarantee (`k` live signers must approve before funds move or membership/config changes) is violated.

### Likelihood Explanation
No privileged access is required beyond being (or having been) a normal multisig member — a role any of the account's key holders already have. The only precondition is that a member removal happens after some confirmations have already accumulated on other pending requests, which is a routine operational sequence (member rotation, key revocation) rather than a contrived edge case. No redeploy, foundation intervention, or malicious validator is needed.

### Recommendation
When executing `DeleteMember`, iterate all entries in `self.confirmations` (not just those for requests added by the removed member) and remove the departing member's string key from every confirmation set. Alternatively, have `confirm` re-validate, at count time, that every string in the stored confirmation set still corresponds to `self.members.contains(...)`, discarding stale entries before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new(members = [A, B, C], num_confirmations = 2)`.
2. `C` calls `add_request(transfer_request)` → `request_id = 0`, `confirmations[0] = {}`.
3. `A` calls `confirm(0)` → `0 + 1 = 1 < 2`, so `confirmations[0] = {A}` (not yet executed).
4. Members submit and confirm a separate `DeleteMember { member: A }` request that reaches threshold with `B` and `C` (legitimate, using still-current members) → `delete_member` runs: it only scans requests added by `A` (none here belong to `A`), so `confirmations[0]` is untouched and still contains `A`; `A` is removed from `self.members`.
5. `B` (now one of only two remaining members) calls `confirm(0)` → `confirmations[0].len() (=1, containing stale A) + 1 = 2 >= 2` → `execute_request` runs the transfer, even though only `B`, a single live member, ever approved it under current membership. [3](#0-2) [2](#0-1)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************

            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
