### Title
RPC `jsonParsed` token-account encoding trusts an unverified `mint` account, causing misreported token balances/decimals - (File: `rpc/src/parsed_token_accounts.rs`)

### Summary
The bug class in the report is: a user-supplied/attacker-controlled address is used to drive downstream logic without verifying it is the entity it is claimed to be (a whitelisted `marketHelper`). The Agave analog is in the RPC layer's `jsonParsed` token-account encoding path: the "mint" address is read directly out of attacker-controlled SPL token account data, and the account found at that address is trusted to be a real mint — without ever checking that its owner is actually an SPL Token/Token-2022 program — before its `decimals`/extension config are used to compute the reported `uiAmount`.

### Finding Description
`get_parsed_token_account` and `get_parsed_token_accounts` extract the mint pubkey directly from the raw bytes of a token account via `get_token_account_mint`, then fetch whatever account currently lives at that pubkey and, if it happens to unpack as a `Mint`, use its `decimals`/extension fields to build `SplTokenAdditionalDataV2` for UI encoding: [1](#0-0) 

The single-account helper `get_parsed_token_account` never validates the owner of the resolved "mint" account: it goes straight from `get_token_account_mint` → `account_resolver::get_account_from_overwrites_or_bank` → `get_additional_mint_data`, which itself only calls `StateWithExtensions::<Mint>::unpack(data)` and does not check `mint_account.owner()` at all: [2](#0-1) 

The batch helper `get_parsed_token_accounts` does call `get_mint_owner_and_additional_data`, which returns the owner alongside the parsed data, but the returned owner is never compared against the token account's actual owning program before the decimals are used: [3](#0-2) [4](#0-3) 

Because SPL Token/Token-2022's `InitializeAccount`/`InitializeAccount2/3` instructions do not require the "mint" argument to actually be owned by a token program at initialization time (the runtime/token program stores whatever pubkey is supplied as `mint` in the token account's data), any unprivileged user can create a token account whose `mint` field points to an arbitrary account — including a system-owned or otherwise attacker-controlled account whose 82-byte (or extension-formatted) contents happen to unpack successfully as a legacy `Mint` (which has no program-id/discriminator binding of its own; only the SPL-Token program is expected to enforce that relationship at the instruction level, not at data-parsing time).

This is directly analogous to the reported issue: the code assumes a referenced address (`marketHelper` / here, "mint") was produced/validated by the trusted, whitelisted program, but never re-verifies that assumption before using the pointed-to data to drive further logic (building the market `execute()` call / here, computing `uiAmount`).

By contrast, the SVM's own token-balance computation explicitly performs this owner check before trusting mint data, showing the codebase is aware this validation is required: [5](#0-4) 

### Impact Explanation
An unprivileged user can construct a token account with a "mint" field pointing at an account they fully control the contents of, causing the RPC's `jsonParsed` account encoding (used by `getAccountInfo`, `getProgramAccounts`, `getTokenAccountsByOwner`, etc. through `get_parsed_token_account`/`get_parsed_token_accounts`) to report an attacker-chosen `decimals` value, and consequently an incorrect `uiAmount`/`uiAmountString` for that token account, to any RPC client. This is "wrong ... account data returned" from a read-only JSON-RPC query — it does not require any special privilege and does not touch consensus state, but it directly misleads any client, wallet, or exchange that relies on the RPC-computed decimal-adjusted balance for that account, which can lead to erroneous accounting/display of balances.

### Likelihood Explanation
High likelihood of triggering: creating an SPL token account with an arbitrary "mint" pubkey requires no special permission — it is a standard, permissionless `InitializeAccount`-family instruction available to any transaction sender. Crafting an account whose data unpacks as a legacy `Mint` struct is straightforward since `Mint::unpack` has no owner/program binding.

### Recommendation
In `get_parsed_token_account` (and defensively re-verify in `get_parsed_token_accounts`), after resolving the "mint" account, check that its owner equals the token account's own owner (the SPL Token/Token-2022 program id) before using its data to build `AccountAdditionalDataV3`/`SplTokenAdditionalDataV2`, mirroring the check already performed in `svm/src/transaction_balances.rs`'s `unpack_token_account`. If the owner does not match, the additional data should be treated as absent (falling back to raw/no-decimals display) rather than trusting the parsed decimals.

### Proof of Concept
1. Send a transaction that creates account `A` (e.g., owned by the System Program) whose 82-byte data is hand-crafted to unpack as a legacy SPL `Mint` with `is_initialized = true` and `decimals = 250` (or any attacker-chosen value), with no real relationship to any token program.
2. Send a transaction creating SPL Token account `B` via `InitializeAccount`, passing `A`'s pubkey as the `mint` argument (allowed since the token program does not require `mint` to be a genuine, correctly-owned mint account at this stage) and depositing some `amount` of "tokens" into `B` (e.g., via `MintTo` is not even necessary — raw `amount` bytes in `B`'s data can be set arbitrarily as long as `B` is a valid-length token account, since the account is fully attacker-controlled prior to being reported).
3. Query `getAccountInfo(B, {encoding: "jsonParsed"})` or `getTokenAccountsByOwner(...)` against the RPC node. The RPC will call `get_token_account_mint(B.data())` → resolve account `A` → `get_additional_mint_data` unpacks `A` as a `Mint` with `decimals = 250` → the returned `uiTokenAmount.uiAmount`/`decimals` fields reflect the attacker's fabricated decimals rather than any real token metadata, without the RPC ever checking that `A` is owned by a Token/Token-2022 program.

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })

impl SvmTokenInfo {
    fn unpack_token_account<CB: TransactionProcessingCallback>(
        account_loader: &mut AccountLoader<CB>,
        account: &AccountSharedData,
        index: usize,
    ) -> Option<Self> {
        let program_id = *account.owner();
        let generic_token::Account {
            mint,
            owner,
            amount,
        } = generic_token::Account::unpack(account.data(), &program_id)?;

        let mint_account = account_loader.load_account(&mint)?;
        if *mint_account.owner() != program_id {
            return None;
        }

        let generic_token::Mint { decimals, .. } =
            generic_token::Mint::unpack(mint_account.data(), &program_id)?;

        Some(Self {
            account_index: index.try_into().ok()?,
            mint,
            amount,
            owner,
            program_id,
            decimals,
        })
    }
