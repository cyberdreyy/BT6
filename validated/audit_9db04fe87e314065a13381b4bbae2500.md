### Title
Missing allowlist/rate-limit at gateway-handler layer allows unbounded flooding of DON nodes via `HandleLegacyUserMessage` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` performs stale-message and payload-format checks but explicitly skips sender allowlisting and rate-limiting (marked by the `// TODO: apply allowlist and rate-limiting here` comment) before broadcasting the request to every DON member and recording an entry in `h.savedCallbacks`. An attacker who can reach the legacy gateway endpoint with a validly-signed `MethodWebAPITrigger` message can flood `don.SendToNode` calls and grow `h.savedCallbacks` without any throttling at this layer.

### Finding Description
The request path is: `gateway.ProcessRequest` (`core/services/gateway/gateway.go:267-269`) decodes and validates the JSON-RPC envelope/signature, then routes legacy requests straight into `h.HandleLegacyUserMessage(ctx, msg, callback)` with no per-sender rate limiting applied at the gateway layer itself. Inside `HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go:341-421`), the checks performed are: payload JSON decode success, non-zero timestamp, and message-age staleness (`handler.go:359-383`). Immediately after these checks and directly preceding the `MethodWebAPITrigger` dispatch, there is the comment `// TODO: apply allowlist and rate-limiting here` (`handler.go:384`), and no allowlist or rate-limit check is actually invoked before the message proceeds to `common.ValidatedRequestFromMessage`, gets stored into `h.savedCallbacks` (`handler.go:411-414`), and is broadcast to every DON member via `don.SendToNode` in a loop over `h.donConfig.Members` (`handler.go:416-419`).

This is corroborated by the handler's own test suite, which contains an explicit outstanding TODO: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` (`core/services/gateway/handlers/capabilities/handler_test.go:365`), confirming this is a known, unresolved gap rather than an intentional design decision backed by an equivalent control elsewhere in this call path.

`nodeRateLimiter` on the `handler` struct (`handler.go:57`, `handler.go:166-168`) only throttles outbound messages *from nodes* (`handleWebAPIOutgoingMessage`), not inbound user-submitted trigger messages — it is not consulted in `HandleLegacyUserMessage` at all.

The downstream `allowedSenders` control in `core/capabilities/webapi/trigger/trigger.go` is a workflow/capability-level authorization enforced on the DON node side (once a node receives the forwarded trigger), not something intercepting the message before it fans out from the Gateway to `donConfig.Members`. This means every DON node in the config already receives and processes the signed request (incurring signature verification cost and network I/O), and `h.savedCallbacks` already grows, before any node-side allowlist decision is made. A signature check alone does not constitute rate limiting or an allowlist, since an attacker can generate unlimited fresh ECDSA keys, each producing a validly-signed but from-an-unrecognized-sender message.

### Impact Explanation
This maps to a Denial-of-Service impact against DON nodes and the Gateway process: an attacker can force the Gateway to call `don.SendToNode` against every configured DON member for an unbounded number of freshly-keyed, distinctly-`MessageId`'d requests, consuming DON node processing/signature-verification resources and network bandwidth. It also grows `h.savedCallbacks`, though this map has a size-based (`MaxSavedCallbacks`, default 20000, `handler.go:44,89-91`) and age-based (`CallbackMaxAgeSec`) pruning mechanism run periodically (`pruneCallbacks`, `handler.go:299-339`), which bounds unbounded memory growth from that particular map but does not prevent the fan-out flood to DON nodes itself.

### Likelihood Explanation
Preconditions are minimal: an unauthenticated attacker able to reach the gateway's legacy HTTP/JSON-RPC endpoint and capable of generating ECDSA keys (trivial, no cost). Chainlink's own signature-validation on the message (`msg.Validate()` in `gateway.go:253` and `common.ValidatedRequestFromMessage` in `handler.go:397`) only verifies that the message is internally self-consistent and signed by *some* key — it does not require the key to be pre-registered or rate-limited, so the check does not stop this flood. This is fully repeatable and requires no privileged access, matching the "unauthenticated attacker" threat model in scope.

### Recommendation
Implement the allowlist and rate-limiting check explicitly called out by the TODO in `HandleLegacyUserMessage`, before the `don.SendToNode` fan-out loop:
- Reject/limit requests from senders not present in a configured Gateway-level allowlist (or, at minimum, apply a per-sender rate limiter similar to `h.nodeRateLimiter` but keyed on the message sender/public key extracted during signature validation) prior to storing into `h.savedCallbacks` and prior to iterating `h.donConfig.Members`.
- Ensure the limiter state is bounded (e.g., LRU or TTL-evicted per-sender buckets) to avoid the rate limiter itself becoming a memory-exhaustion vector.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
