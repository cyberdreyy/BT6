## Finding

### Title
Malicious vesting shareholder can permanently DoS `vesting::distribute` (and `terminate_vesting_contract`) for all co-shareholders by opting out of direct coin transfers - (File: aptos-move/framework/aptos-framework/sources/vesting.move)

### Summary
`vesting::distribute` iterates over **every** shareholder of a `VestingContract` in a single transaction and pushes coins to each one via `aptos_account::deposit_coins`. That function unconditionally aborts if the recipient has no registered `CoinStore<AptosCoin>` **and** has opted out of direct coin transfers via `aptos_account::set_allow_direct_coin_transfers(false)` — a fully permissionless, self-service call. Because the loop is atomic and unguarded, any single shareholder (or their designated beneficiary) can permanently block distribution of vested tokens and rewards to **all other shareholders** sharing the same vesting contract, mirroring the external report's pattern where a single actor's revert on a shared payout path locks funds for everyone else.

This pushes coins to **every** shareholder unconditionally, in one atomic transaction, with no per-shareholder failure isolation.

`aptos_account::deposit_coins` will abort if the target account has not registered a `CoinStore<CoinType>` and has explicitly disabled direct transfers: [2](#0-1) 

```
public fun deposit_coins<CoinType>(to: address, coins: Coin<CoinType>) acquires DirectTransferConfig {
    if (!account::exists_at(to)) { create_account(to); };
    if (!coin::is_account_registered<CoinType>(to)) {
        assert!(can_receive_direct_coin_transfers(to), error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS));
        coin::register<CoinType>(&create_signer(to));
    };
    coin::deposit<CoinType>(to, coins)
}
```

`set_allow_direct_coin_transfers` is a fully permissionless, self-controlled entry function — no privilege beyond controlling one's own account is required: [3](#0-2) 

Any shareholder of a vesting contract can, at any point after being added as a shareholder, call `set_allow_direct_coin_transfers(signer, false)` on their own account (and simply never register a `CoinStore<AptosCoin>`). From that point forward, **every** call to `vesting::distribute(contract_address)` will abort as soon as the loop reaches that shareholder, because the abort propagates and reverts the whole transaction (Move transactions are atomic). Since `distribute` is also invoked internally by `vest`, `unlock_rewards`'s downstream flows, and — critically — by `terminate_vesting_contract`: [4](#0-3) 

```
public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
    assert_active_vesting_contract(contract_address);
    distribute(contract_address);   // <-- also blocked
    ...
}
```

the griefing shareholder blocks not only the `distribute` path used to pay out rewards/vested tokens to co-shareholders, but also the contract termination/admin recovery path, since `terminate_vesting_contract` calls `distribute` unconditionally before proceeding.

### Impact Explanation
A single unprivileged shareholder can permanently freeze payout of vested tokens and staking rewards for **all** shareholders of the same `VestingContract`, and also block the admin's ability to terminate the vesting contract and recover the underlying stake pool funds. Since the underlying stake stays locked/inactive inside the `stake` pool and can never be pulled out through `distribute`/`admin_withdraw` (the latter also requires prior termination), this constitutes a non-recoverable, permanent lock of legitimate claim rights belonging to third parties who did not participate in the griefing — squarely matching the required impact "Permanent lock or non-recoverable loss of claim rights in ... vesting flows," analogous to the external report's block-stuffing/revert-hook pattern where a single party's revert locks value for all co-participants.

### Likelihood Explanation
High. The attack requires only:
1. Being (or becoming, if shareholders can be added post-creation) a shareholder of a vesting contract holding at least one other shareholder.
2. A single permissionless self-call to `set_allow_direct_coin_transfers(false)`.
3. Not registering `CoinStore<AptosCoin>` (default state for accounts that only interact via other means, or an account can simply avoid ever registering).

No special role, timing race, or capital investment is required, unlike the original report's block-stuffing cost model — making this strictly easier to execute than the seed bug.

### Recommendation
- In `vesting::distribute` (and any similar push-based multi-recipient payout loop, e.g. `staking_contract::distribute_internal`), isolate per-recipient failures so that one recipient's inability to receive funds does not revert payouts to all other shareholders — e.g., wrap the deposit in a way that failed deposits are instead escrowed/held in a per-shareholder claimable balance instead of an unconditional push, or skip failing recipients and let them claim manually later.
- Alternatively, decouple `terminate_vesting_contract` from a mandatory successful `distribute` call so contract termination cannot be indefinitely blocked by a single participant.

### Proof of Concept
1. Admin creates a vesting contract with shareholders `[A (attacker), B (victim)]` via `create_vesting_contract`.
2. `A` calls `aptos_account::set_allow_direct_coin_transfers(signer_A, false)` and never registers `CoinStore<AptosCoin>` (e.g., a fresh account that has not previously received APT via `CoinStore`).
3. Time passes; vesting/rewards accrue and become withdrawable stake in the pool (`unlock_rewards`/`vest`, then lockup expiry).
4. Anyone calls `vesting::distribute(contract_address)`.
5. The `for_each_ref` loop reaches shareholder `A`; `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, reverting the entire transaction — `B` receives nothing.
6. Every subsequent call to `distribute` (and `terminate_vesting_contract`, which calls `distribute` first) aborts identically, permanently freezing `B`'s (and any other shareholder's) vested tokens and rewards, as well as blocking admin termination/recovery of the vesting contract's stake.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
