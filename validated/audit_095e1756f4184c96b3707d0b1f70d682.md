### Title
Unauthenticated gateway request-ID collision allows griefing of another user's confidential-relay request - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

### Summary
`ConfidentialRelayHandler.HandleJSONRPCUserMessage()` accepts a caller-supplied JSON-RPC `req.ID` from any client reaching the internet-facing gateway and uses that raw, attacker-controlled string as the sole key of a single shared `activeRequests` map across *all* users of the DON/gateway instance, with no per-owner or per-session namespacing.

### Finding Description
`HandleJSONRPCUserMessage` only checks that `req.ID` is non-empty and ≤200 characters, then calls `newActiveRequest`, which rejects the request outright if that exact ID string is already present in the map: [1](#0-0) [2](#0-1) 

The map key is the raw `req.ID` with no per-user/owner scoping. This is unlike the sibling `vault` gateway handler, which deliberately namespaces node-response tracking by `owner + RequestIDSeparator + requestID` to prevent exactly this kind of cross-user collision, as seen in its test expectations: [3](#0-2) 

Because the confidential-relay handler has no such per-owner namespace and no authentication/binding of `req.ID` ownership prior to insertion into the shared map, any unprivileged, unauthenticated client that can reach the gateway's JSON-RPC endpoint can:
1. Observe or predict a legitimate user's chosen `req.ID` (e.g., a workflow execution ID, a sequential counter, or any ID pattern that leaks through logs, telemetry, or client-side determinism), or simply race to submit first with a colliding ID.
2. Submit a request with that same `req.ID` first.
3. Cause the legitimate user's subsequent request with the same ID to be rejected with `"request ID already exists: <id>"`, denying that specific request/user service without ever having valid authorization for the underlying capability.

This directly parallels the `CSModule.compensateELRewardsStealingPenalty()` griefing pattern in the external report: a permissionless / unauthenticated entry point mutates process-wide shared state keyed by a value the victim also controls, and doing so first causes the victim's legitimate, otherwise-valid call to fail — a pure griefing/DoS vector requiring no special privilege from the attacker.

### Impact Explanation
An attacker with no credentials, no allowlist entry, and no capability configuration can deny service to a specific, targeted confidential-relay request merely by guessing or observing its `req.ID` and submitting a colliding request first. This can be used to selectively block particular users' or workflows' confidential-relay/secrets-get and capability-exec calls at the gateway layer, causing failed or delayed execution for the victim, which is an availability impact on an internet-facing entry point that other parts of the codebase (vault handler) treat as a security-relevant concern worth explicit mitigation (owner-namespacing).

### Likelihood Explanation
Likelihood is moderate: the attacker needs a way to learn or guess an in-flight `req.ID` before the corresponding legitimate request arrives at this specific gateway node instance. If `req.ID`s are predictable (sequential, derivable from workflow/execution IDs, or observable via any side channel such as node logs, other public interfaces, or timing), exploitation is straightforward and repeatable, since the `HandleJSONRPCUserMessage` entry point performs no authentication of the ID's ownership before consuming the shared keyspace.

### Recommendation
Namespace `activeRequests` (and any other request-ID-keyed shared state within `confidentialrelay/handler.go`) by an authenticated caller/owner identity in addition to the raw request ID, mirroring the `owner + RequestIDSeparator + requestID` pattern already used in `core/services/gateway/handlers/vault/handler.go`, so that a request ID collision can only occur within a single authenticated owner's own request stream rather than across all unauthenticated gateway clients.

### Proof of Concept
1. Attacker (no credentials required) sends a JSON-RPC request to the confidential-relay gateway endpoint with `Method: MethodSecretsGet` (or `MethodCapabilityExec`) and `ID` equal to a value the attacker expects a target victim to use next (e.g., a predictable/observed execution or request ID).
2. `HandleJSONRPCUserMessage` accepts it (only length/emptiness checked) and inserts it into `h.activeRequests[req.ID]` via `newActiveRequest`.
3. Before the attacker's bogus request is cleaned up (bounded by `RequestTimeoutSec`, default 30s per `defaultRequestTimeoutSec`), the legitimate victim submits their real request with the same `req.ID`.
4. `newActiveRequest` returns `"request ID already exists: <id>"` and the victim's legitimate request is rejected, denying them service for that request cycle — analogous to the CSModule griefer front-running the legitimate `compensateELRewardsStealingPenalty()` call with a smaller compensation to force the real call to revert.

```go
func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
```

```go
func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
```
