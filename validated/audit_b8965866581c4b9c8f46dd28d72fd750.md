### Title
Job-controlled stdout lines matching the JSON exit-status schema are unmarshalled and logged verbatim, allowing log injection into the runner's debug log - ([File: shells/trap_command_exit_status.go])

### Summary
`StageCommandStatus.String()` interpolates `*c.Script` (and `*c.CommandExitCode`) directly into a `fmt.Sprintf` string with no sanitization, and this string is passed straight to `logrus`'s `Debugln` in the Kubernetes executor's `forwardLogLine`. Because `forwardLogLine` runs `TryUnmarshal` on *every* line coming from the build container's combined stdout/stderr log file, a job's own script — not just the runner-generated exit-status trap — can emit a line that satisfies the JSON schema and inject attacker-chosen bytes (including newlines/ANSI escapes) into the runner's operator-facing debug log.

### Finding Description
The Kubernetes executor pipes the build container's stdout/stderr into a log file (`s.buildRedirectionCmd`), which the log processor streams line by line [1](#0-0) . Every line is fed to `forwardLogLine`, which unconditionally tries to unmarshal it as a `StageCommandStatus` regardless of whether it originated from the runner's own trap or from user job output: [2](#0-1) 

`TryUnmarshal`/`tryUnmarshal` only require valid JSON with at least one of `command_exit_code` or `script` non-nil — there is no origin check, no allowlist of expected script paths, and no schema restriction beyond basic JSON shape: [3](#0-2) 

On a successful match, the whole struct (via `Stringer`) is embedded directly into a debug-level log call: [4](#0-3) 

`String()` performs raw `fmt.Sprintf("%v", *c.Script)` interpolation with no escaping of control characters, newlines, or ANSI sequences: [5](#0-4) 

That formatted string reaches `logrus` via `Tee.Debugln`, which forwards `args` straight to `entry.Debugln(args...)` — again with no sanitization: [6](#0-5) 

Any job step in the Kubernetes executor can trivially cause its own script to print a line like `{"script":"X\nlevel=error msg=\"fake incident\""}` to stdout. Since that stdout is captured into the same log file the log processor scans (`tee -a logFile` / `Out-File`), the injected line is indistinguishable from the runner-generated exit marker and will be unmarshalled successfully (`Script` alone is sufficient to pass `isEmpty()`), then logged verbatim with the embedded newline breaking the single-log-line invariant.

### Impact Explanation
An unprivileged pipeline author can inject fabricated, multi-line, or ANSI/control-sequence-laden content into the GitLab Runner process's own debug log (`--debug` / debug log level), which is consumed by runner operators/administrators for troubleshooting and, in some deployments, by log-parsing/SIEM tooling. This can be used to spoof fake log lines (e.g., impersonating error/warning entries) or corrupt line-oriented log parsers, misleading incident response. It does not, by itself, escape the job sandbox, leak secrets, or affect other jobs/projects — impact is confined to log integrity/spoofing on the runner host as scoped by the question.

### Likelihood Explanation
Preconditions: Kubernetes executor in use, and runner debug-level logging enabled (`--debug` or `log_level: debug`) — a common operator configuration during troubleshooting. Given that, any pipeline author can reliably trigger the injection deterministically by simply `echo`-ing a matching JSON line in their `script:`; no race condition, timing, or privilege escalation is required, so it is fully repeatable.

### Recommendation
- Sanitize/escape `*c.Script` (and any other user-influenced fields) before interpolating into `String()` — e.g., strip or escape control characters (`\n`, `\r`, ESC) and cap length.
- In `forwardLogLine`, do not treat arbitrary matching JSON from the container's general stdout stream as trusted exit-status data; instead use a unique, hard-to-forge marker (e.g., a per-invocation nonce/prefix) written only by the runner-generated trap script, and require an exact-prefix match before attempting `TryUnmarshal`.
- Ensure `logrus` output uses a formatter/encoder that quotes or escapes newlines/control bytes in message fields (or explicitly `strconv.Quote` the interpolated value in `String()`), so a single log entry cannot be split into multiple.

### Proof of Concept
Go unit test in `shells/trap_command_exit_status_test.go` style:
```go
func TestStageCommandStatus_StringInjection(t *testing.T) {
    payload := "evil\nlevel=error msg=\"fake incident, escaped detection\""
    script := payload
    status := StageCommandStatus{Script: &script}

    out := status.String()

    // Assert the log line does not introduce embedded newlines / multiple lines,
    // i.e. the invariant "one call = one log record" holds.
    assert.NotContains(t, out, "\n", "String() must not allow a single field to fabricate multiple log lines")
}
```
Integration-level PoC: run a Kubernetes-executor job with `--debug` and a job step `script: ["echo '{\"script\":\"pwn\\nlevel=error msg=\\\"fake\\\"'\"]}"`, then inspect the runner process debug log and assert it contains an injected `level=error msg="fake"` line that did not originate from the runner itself, confirming `forwardLogLine`/`String()` accepted and logged attacker-controlled content verbatim.

func (s *executor) forwardLogLine(w io.Writer, line string) {
	var status shells.StageCommandStatus
	if !status.TryUnmarshal(line) {
		if _, err := w.Write([]byte(line)); err != nil {
			s.BuildLogger.Warningln(fmt.Sprintf("Error writing log line to trace: %v", err))
		}

		return
	}

	s.BuildLogger.Debugln(fmt.Sprintf("Setting remote stage status: %s", status))
	s.remoteStageStatusMutex.Lock()
	s.remoteStageStatus = status
	s.remoteStageStatusMutex.Unlock()

	if status.IsExited() {
		s.remoteProcessTerminated <- status
	}
}

// tryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It's safe to use the struct only if this method returns no error.
func (cmd *stageCommandExitStatusImpl) tryUnmarshal(line string) error {
	return json.Unmarshal([]byte(line), cmd)
}

func (cmd stageCommandExitStatusImpl) isEmpty() bool {
	return cmd.CommandExitCode == nil && cmd.Script == nil
}

func (cmd stageCommandExitStatusImpl) applyTo(to *StageCommandStatus) {
	to.CommandExitCode = cmd.CommandExitCode
	to.Script = cmd.Script
}

type StageCommandStatus struct {
	CommandExitCode *int
	Script          *string
}

// TryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It wil return true only if the unmarshalled struct has all of its required fields be non-nil.
// It's safe to use the struct only if this method returns true.
func (c *StageCommandStatus) TryUnmarshal(line string) bool {
	var status stageCommandExitStatusImpl
	err := status.tryUnmarshal(line)
	if err != nil {
		return false
	}

	if status.isEmpty() {
		return false
	}

	status.applyTo(c)

	return true
}

func (c StageCommandStatus) String() string {

	}
