### Title
No rate limiting applies before JWT authorization in HTTP trigger flow, allowing unlimited unauthenticated probing/DoS - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`HandleUserTriggerRequest` calls `authorizeRequest` (JWT verification) before `checkRateLimit`, and no rate limiter exists earlier in the call chain (gateway `ProcessRequest` → `HandleJSONRPCUserMessage` → `HandleUserTriggerRequest`) that throttles requests by sender/IP prior to authentication. An attacker can therefore send unlimited requests with invalid or unauthorized JWTs against a target `workflowID` without ever being throttled, enabling workflow-existence/authorized-signer probing and CPU-cost DoS via repeated JWT signature verification.

### Finding Description
`HandleUserTriggerRequest` runs steps in this order: `validatedTriggerRequest` → `resolveWorkflowID` → `authorizeRequest` → `checkRateLimit` [1](#0-0) . `authorizeRequest` calls `h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)`, which performs full ECDSA JWT signature verification (`utils.VerifyRequestJWT`) and authorized-key lookup before any rate limit is checked [2](#0-1) [3](#0-2) .

`checkRateLimit` only fires *after* successful authorization, and it is scoped to `ScopeWorkflow` using the workflow's own owner-derived CRE context, i.e., it throttles legitimate/authorized senders per workflow, not per attacker/sender for failed-auth attempts [4](#0-3) .

Tracing the entry point: the gateway's `ProcessRequest` dispatches directly to `h.HandleJSONRPCUserMessage`, which calls `triggerHandler.HandleUserTriggerRequest` with no rate limiting or per-sender throttling applied beforehand [5](#0-4) [6](#0-5) . The only earlier gate is `MaxRequestBytesLimiter` in `httpserver.go`, which bounds payload size, not request rate [7](#0-6) . Unlike the Vault JWT auth path, which explicitly supports a `WithJWTBasedAuthGateLimiter` to bound JWT-verification cost before doing expensive crypto work, the HTTP trigger `Authorize` path has no equivalent gate.

As a result: (1) `resolveWorkflowID`/`authorizeRequest` error messages ("workflow reference not found" / "Auth failure: ...") let an attacker distinguish nonexistent workflows from existing ones and probe whether a given signer key is authorized, all before rate limiting engages; (2) full JWT ECDSA verification work is performed for every attacker-supplied token with no cap, since the workflow-scoped rate limiter never runs for failed-auth requests.

### Impact Explanation
This is a scoped availability/information-disclosure issue: unauthenticated attackers get unlimited free probing capacity to enumerate workflow existence and test authorized signer keys for a targeted subscriber's workflow, and can impose unbounded CPU cost on the gateway via repeated JWT verification — a quota/rate-limit bypass rather than a full authentication bypass or fund-movement bug.

### Likelihood Explanation
Fully unauthenticated and trivially repeatable: any client can POST to the gateway's user-facing HTTP endpoint with an arbitrary/invalid `Auth` JWT and a target `workflowID`, with no credentials or preconditions required, and the request volume is bounded only by payload-size limits, not by rate limiting, since `checkRateLimit` runs strictly after `authorizeRequest` succeeds.

### Recommendation
Add a per-sender/global rate limiter (or a JWT-verification gate limiter, similar to `WithJWTBasedAuthGateLimiter` used in the Vault auth path) in front of `validatedTriggerRequest`/`authorizeRequest` in `HandleUserTriggerRequest`, so that unauthenticated/failed-auth attempts are throttled independent of workflow lookup success, and make error responses for "workflow not found" and "auth failure" indistinguishable where feasible to reduce enumeration surface.

### Proof of Concept
Go test plan in `http_trigger_handler_test.go`:
1. Construct a `httpTriggerHandler` with a restrictive `userRateLimiter` (e.g., `limits.WorkflowRateLimiter(1, 0)`), matching the existing `TestHttpTriggerHandler_HandleUserTriggerRequest_RateLimiting` setup.
2. Register a workflow to obtain a valid `workflowID` and authorized key.
3. In a loop (e.g., 1000 iterations), call `handler.HandleUserTriggerRequest` with an invalid/expired JWT (`req.Auth = "invalid.jwt.token"`) targeting the registered `workflowID`.
4. Assert every call returns the "auth failure" error (per existing `TestHttpTriggerHandler_HandleUserTriggerRequest_JWTAuthorization` "invalid JWT token" case) and that none are ever rejected with `jsonrpc.ErrLimitExceeded`, proving `userRateLimiter.AllowErr` is never invoked for failed-auth attempts.
5. Instrument/mock `userRateLimiter.AllowErr` (or assert on a counter) to confirm it was called zero times across all 1000 failed-auth attempts, demonstrating no rate limit accrues for unauthenticated probing.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
