### Title
Missing min-answer check on Chainlink USD0++ feed causes wrong loss socialization at epoch end - (File: contracts/strategies/usual/IdleUsualStrategy.sol)

### Summary
`IdleUsualStrategy.getChainlinkPrice()` reads the Chainlink USD0++/USD feed and only validates freshness (`updatedAt > block.timestamp - 24 hours`), with no check that the reported `answer` is not the feed's pre-set `minAnswer`. `IdleCDOUsualVariant.stopEpoch()` consumes this price to compute `targetAATVL`, i.e. how much the junior (BB) tranche must transfer to the senior (AA) tranche to restore $1 parity. If USD0++ crashes below the feed's `minAnswer` (the LUNA scenario), Chainlink keeps reporting `minAnswer`, which is higher than the real market price. The junior tranche then compensates seniors far less than required, and seniors permanently redeem USD0++ worth less than $1.

### Finding Description
In `IdleUsualStrategy.getChainlinkPrice()` (contracts/strategies/usual/IdleUsualStrategy.sol, lines 164-172) the price is fetched with only a staleness check:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
return uint256(answer) * 1e10;
```

There is no verification that `answer` is above the aggregator's `minAnswer`. Chainlink feeds clamp prices at configured bounds; during a collapse the feed returns `minAnswer` while the market price is much lower.

`IdleCDOUsualVariant.stopEpoch()` (contracts/IdleCDOUsualVariant.sol, lines 70-100) uses this price directly:

```solidity
uint256 _oraclePrice = _strategy.getChainlinkPrice();
_strategy.setOraclePrice(_oraclePrice);
...
uint256 targetAATVL = lastNAVAA * oneToken / _oraclePrice;
lastNAVAA += targetAATVL - lastNAVAA;
_updateAccounting();
```

`_updateAccounting()` then routes the implied "loss" to juniors via `_virtualPriceAux`, and `setOraclePrice()` only floors the price at `IUSD0pp(USD0pp).getFloorPrice()` — it never caps or sanity-checks an inflated value, so an inflated `minAnswer` passes through unmodified. After `stopEpoch`, `allowAAWithdraw`/`allowBBWithdraw` are re-enabled and seniors redeem at the inflated-price-based virtual price.

### Impact Explanation
Broken invariant: loss waterfall / fair burn. If real USD0++ price is e.g. $0.02 but the feed's `minAnswer` is $0.50, `stopEpoch` computes `targetAATVL = lastNAVAA / 0.50` — only ~4% of the USD0++ tokens actually needed to reach $1 parity. The excess remains credited to the junior tranche. Any unprivileged senior tranche holder calling `withdrawAA` permanently receives far fewer tokens than the designed $1 guarantee; juniors withdraw tokens that should have been socialized to seniors. If `minAnswer >= $1` (feed configured at parity floor), `stopEpoch` returns early at line 87-89 and juniors pay *nothing* despite a real depeg — the entire depeg-protection mechanism silently fails. The loss is permanent and quantified by `(targetAATVL_true - targetAATVL_reported)` per senior token.

### Likelihood Explanation
The condition requires USD0++ to crash below the Chainlink feed's `minAnswer` during the single 6-month epoch. This is precisely the scenario the vault exists to protect against (the contract is explicitly a "usd0++ depeg protection" product, lines 8-16 of `IdleCDOUsualVariant.sol`), so the vulnerable path is the primary payoff path. No attacker privilege is needed — the honest owner calls `stopEpoch`, and any senior holder realizes the loss by redeeming. Existing guards do not help: `setOraclePrice` only enforces a lower bound (`floorPrice`), the staleness check still passes because Chainlink keeps heartbeating the clamped value, and `maxDecreaseDefault` is set to `FULL_ALLOC` so no default path triggers.

### Recommendation
- In `getChainlinkPrice()`, read `minAnswer`/`maxAnswer` from the feed's aggregator (via `AggregatorV2V3Interface` or the proxy's `aggregator()` → `minAnswer()`/`maxAnswer()`) and revert or flag when `answer == minAnswer`, so `stopEpoch` cannot silently use a clamped price.
- Alternatively/additionally, cross-check the Chainlink answer against a second source (e.g. USD0pp `getFloorPrice()`, a DEX TWAP) inside `stopEpoch` before computing `targetAATVL`, and revert if deviation exceeds a threshold so juniors correctly socialize the full loss.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDOUsualVariant} from "../contracts/IdleCDOUsualVariant.sol";
import {IdleUsualStrategy} from "../contracts/strategies/usual/IdleUsualStrategy.sol";

interface IChainlinkMinMax {
    function latestRoundData() external view returns (uint80, int256, uint256, uint256, uint80);
    function aggregator() external view returns (address);
}
interface IAccessControlledOffchainAggregator {
    function minAnswer() external view returns (int192);
    function maxAnswer() external view returns (int192);
}

contract MinAnswerPoC is Test {
    // USD0++ / USD chainlink feed hardcoded in IdleUsualStrategy
    address constant USD0ppOracle = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;

    IdleCDOUsualVariant cdo;   // deployed via repo deploy helpers
    IdleUsualStrategy strat;

    function setUp() public {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));
        // deploy IdleCDOUsualVariant + IdleUsualStrategy, deposit senior/junior, owner calls startEpoch(180 days)
    }

    function test_minAnswerUndercompensatesSeniors() public {
        // --- precondition: feed reports minAnswer while market crashed ---
        (, int256 answer,,,) = IChainlinkMinMax(USD0ppOracle).latestRoundData();
        address agg = IChainlinkMinMax(USD0ppOracle).aggregator();
        int192 minAns = IAccessControlledOffchainAggregator(agg).minAnswer();
        // In the crash scenario: answer == minAnswer >> real market price

        // warp to epoch end; honest owner stops epoch
        vm.warp(cdo.epochEndDate());
        uint256 navAABefore = cdo.lastNAVAA();
        vm.prank(cdo.owner());
        cdo.stopEpoch();   // uses inflated `answer` -> understated targetAATVL

        // senior holder redeems
        uint256 aaBal = cdo.AATrancheToken().balanceOf(address(this));
        uint256 before_ = usd0pp.balanceOf(address(this));
        cdo.withdrawAA(aaBal);
        uint256 received = usd0pp.balanceOf(address(this)) - before_;

        // With true market price p_true < minAnswer, fair payout would be
        // aaBal * 1/p_true usd0++; assert we received ~ aaBal * 1/minAnswer instead
        assertLt(received, navAABefore * 1e18 / uint256(int256(minAns)) * 1e10 + 1);
        // => seniors are permanently underpaid; residual stays credited to juniors
    }
}
```
The PoC relies on a mainnet fork where the feed's `answer` has hit `minAnswer` (or a mock aggregator wired identically) to demonstrate that `stopEpoch` under-socializes the loss to the junior tranche and senior withdrawals are permanently reduced.
