### Title
`redeem_fungible_staked_sui` lacks rewards-pool balance cap, causing permanent fund lock for inactive pools — (File: crates/sui-framework/packages/sui-system/sources/staking_pool.move)

---

### Summary

`redeem_fungible_staked_sui` pre-calculates `rewards_amount` from the exchange rate and then calls `pool.rewards_pool.split(rewards_amount)` with no guard against the pool having less than that amount. The sibling function `withdraw_rewards` (used by `request_withdraw_stake`) carries an explicit defensive cap for exactly this scenario, but `redeem_fungible_staked_sui` does not. For a deactivated (inactive) pool whose `rewards_pool` has been drained by prior `request_withdraw_stake` calls, every subsequent `redeem_fungible_staked_sui` call aborts, and because there is no alternative redemption path, the caller's `FungibleStakedSui` tokens are permanently locked.

---

### Finding Description

**The guarded path — `withdraw_rewards`:**

`withdraw_rewards`, called by `request_withdraw_stake`, explicitly caps the reward amount at the actual pool balance before splitting:

```move
// This may happen when we are withdrawing everything from the pool and
// the rewards pool balance may be less than reward_withdraw_amount.
// TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
pool.rewards_pool.split(reward_withdraw_amount)
``` [1](#0-0) 

The `TODO` comment confirms the developers know the rewards pool can fall below the calculated amount, and the `.min()` cap is the mitigation.

**The unguarded path — `redeem_fungible_staked_sui`:**

`redeem_fungible_staked_sui` calculates `rewards_amount` from the same exchange-rate formula, then calls `split` with no cap:

```move
let mut sui_out = fungible_staked_sui_data.principal.split(principal_amount);
sui_out.join(pool.rewards_pool.split(rewards_amount));   // no .min() guard
``` [2](#0-1) 

If `rewards_amount > pool.rewards_pool.value()`, `balance::split` aborts the entire transaction. The `FungibleStakedSui` object is rolled back (not consumed), but for an inactive pool the rewards pool is never replenished, so every future attempt also aborts.
