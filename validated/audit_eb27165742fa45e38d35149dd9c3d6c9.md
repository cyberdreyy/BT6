### Title
Unbounded recursion in `TrieNode::decode`/`try_decode_leaf_or_extension_payload` allows stack-overflow DoS of the fault-proof program - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode::decode` in `crates/proof/mpt/src/node.rs` recursively decodes each nested `Extension` node by calling `Self::decode(buf)` directly on the same buffer, with no depth counter or recursion limit, analogous to the go-ipld-prime DAG-CBOR/DAG-JSON decoders described in GHSA-w239-58x2-q8p5 that recursed once per nested collection with no `MaxDepth`.

### Finding Description
`TrieNode::decode` [1](#0-0)  peeks the RLP header, and for a two-item list whose length matches `LEAF_OR_EXTENSION_LIST_LENGTH`, calls `Self::try_decode_leaf_or_extension_payload(buf)` [2](#0-1) . Inside that function, when the node is classified as an `Extension`, the value is decoded by directly calling `Self::decode(buf)` again on the *same* underlying buffer [3](#0-2) , with no depth counter passed or checked anywhere in this call chain.

Unlike the CBOR parser used elsewhere in this repo for TEE attestation (`crates/proof/tee/registrar/src/cbor.rs`), which explicitly tracks a `depth` parameter and enforces `MAX_CBOR_NESTING_DEPTH = 64` [4](#0-3) [5](#0-4) , `TrieNode::decode` has no analogous guard. Each extension level only costs a small number of RLP bytes (an RLP list header + a 1-byte path + another nested list header), so a single crafted blob of length N can encode roughly N/3 nested `Extension` levels, all resolved in one call without ever invoking the `TrieProvider` fetcher (unblinding only happens for `Blinded` 32-byte-string nodes, not for inline unblinded extensions within the same buffer).

This routine is the core RLP decoder for Merkle-Patricia-Trie nodes used throughout the fault-proof program's trie utilities (`crates/proof/mpt`), which is explicitly reachable by data derived from L1 (deposit/system-config proofs) and preimage-oracle-fed data in the fault-proof/attacker-influenced execution path called out in scope.

### Impact Explanation
A crafted trie-node preimage/blob with deep, non-blinded extension nesting can drive `TrieNode::decode` into unbounded recursion, exhausting the call stack and crashing the process with a fatal (non-recoverable) stack overflow — analogous to the "distinct from a recoverable panic" failure mode in the referenced advisory. In the fault-proof program context this halts proof generation/verification for that input, which can prevent the node from producing/verifying a correct output root (node halt / inability to serve a dispute-game step), matching the "node halt" / "wrong provable output root" impact classes.

### Likelihood Explanation
Likelihood depends on whether callers of `TrieNode::decode` bound the size or nesting of attacker-supplied trie-node bytes before invoking decode, and whether preimage-oracle responses in the fault-proof program are capped at sizes small enough to make deep nesting impractical. I was not able to fully verify, within the available index, the exact preimage size caps enforced by `crates/proof/preimage` or `crates/proof/proof/src/caching_oracle.rs`, nor every call site that feeds untrusted bytes into `TrieNode::decode` (e.g. via `crates/proof/proof/src/l1/chain_provider.rs`, `l2/chain_provider.rs`). This is a real analog to the report's bug class (recursion depth unbounded in a decoder consuming untrusted, attacker-shaped nested data), but confirming full exploitability requires checking those size limits, which the current index could not fully resolve.

### Recommendation
Add an explicit depth parameter/counter to `TrieNode::decode` / `try_decode_leaf_or_extension_payload` (mirroring the `depth` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`), and return a decode error once nesting exceeds a bounded constant (e.g. 64–1024 levels, consistent with realistic Ethereum trie depths).

### Proof of Concept
Construct a single RLP buffer consisting of repeated two-item lists of the form `[encoded_path_bytes, <nested list>]`, each classified by `rlp_list_element_length` as `LEAF_OR_EXTENSION_LIST_LENGTH` and by the path's first nibble as an `Extension` prefix, nesting thousands of levels deep (all inline, non-blinded, so no hash lookup breaks the chain) before terminating in an `Empty`/`Blinded` leaf. Passing this buffer to `TrieNode::decode` recurses once per nested level with no depth check, consuming stack proportional to nesting depth until the process aborts with a stack overflow.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}
