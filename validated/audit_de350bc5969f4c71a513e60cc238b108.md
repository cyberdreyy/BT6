### Title
Missing sender allowlist enforcement in `handler.HandleLegacyUserMessage` allows any signed key to invoke DON web API triggers - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` validates message structure, payload shape, and timestamp freshness, but never checks whether `msg.Body.Sender` is a member of any allowlist/subscription list for the DON/workflow being targeted before forwarding the request to every DON node and registering a callback in `h.savedCallbacks`. Any holder of an arbitrary ECDSA keypair can sign a `MethodWebAPITrigger` message and have it broadcast to the entire DON.

### Finding Description
The gateway's `ProcessRequest` in `core/services/gateway/gateway.go` decodes the incoming JSON-RPC request, calls `msg.Validate()` (which only checks field lengths and recovers the signer via `ExtractSigner`, populating `msg.Body.Sender`), looks up the handler by `DonId`, and calls `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `msg.Validate()` only proves a valid ECDSA signature exists over the message body — it does not check the signer against any allowlist [2](#0-1) .

Inside `HandleLegacyUserMessage`, the checks performed are: payload JSON decoding, `Timestamp != 0`, message staleness, and `Method == MethodWebAPITrigger`. Immediately after these, there is an explicit `// TODO: apply allowlist and rate-limiting here` comment followed directly by the method check — no sender/topic authorization logic exists between message validation and the request being registered/forwarded [3](#0-2) . The handler then unconditionally stores the callback under `h.savedCallbacks[msg.Body.MessageId]` and forwards the request to every member of the DON via `don.SendToNode` [4](#0-3) .

There is no `Allowlist` field or check anywhere in `core/services/gateway` (confirmed via search), and the handler's own test suite documents this gap with the comment `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` at the end of `TestHandlerReceiveHTTPMessageFromClient` [5](#0-4) . This confirms the missing check is a known, unresolved gap rather than being handled elsewhere in the pipeline.

### Impact Explanation
Any external party who can generate an ECDSA keypair (trivial, no privilege needed) can craft and sign a `web_api_trigger` message and submit it to the gateway HTTP endpoint. The gateway will forward this request to all DON member nodes and allocate a `savedCallback` entry, consuming DON compute/relay resources and node bandwidth that should be reserved for allowlisted/subscribed workflow owners. This matches an "unauthorized DON capability invocation / resource consumption via impersonation" impact — a denial-of-service / resource-abuse vector against the DON compute budget and gateway callback map (bounded by `defaultMaxSavedCallbacks`, but still attacker-fillable).

### Likelihood Explanation
Preconditions are minimal: the attacker needs only a self-generated private key (no allowlist membership, no prior relationship to the DON) and network access to the gateway's HTTP endpoint. The message just needs to pass `Validate()` (valid signature, non-empty ID/method/DonId, correct lengths) and have `Method == MethodWebAPITrigger` with a well-formed `webapicap.TriggerRequestPayload` and fresh timestamp — all attacker-controlled and easily satisfied. This is fully repeatable and requires no race conditions or special timing.

### Recommendation
Implement the allowlist check called out by the TODO before forwarding/storing the callback: verify `msg.Body.Sender` against the DON/workflow-specific allowlist (e.g., subscribed owner addresses for the target `capability`/workflow ID in the payload) and reject unauthorized senders with `api.UnauthorizedError` (or similar) prior to the `don.SendToNode` loop and before inserting into `h.savedCallbacks`. Add per-sender rate limiting alongside the existing `nodeRateLimiter` (which only limits per-node outgoing messages, not per-user incoming triggers).

### Proof of Concept
Extend `TestHandlerReceiveHTTPMessageFromClient` in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Set up `handler` via `setupHandler(t)` as usual, where `nodes` (from `gwcommon.NewTestNodes`) represent the only legitimately known/allowlisted DON members' keys used elsewhere in the suite for other purposes; generate a fresh, unrelated keypair `atk, _ := crypto.GenerateKey()` that has never been registered/allowlisted anywhere.
2. Build a valid `TriggerRequestPayload` (fresh timestamp, valid `params`), sign the resulting `api.Message` with `atk` instead of any known node key, mirroring `triggerRequest(t, ...)` helper but substituting the attacker key.
3. Call `handler.HandleLegacyUserMessage(ctx, attackerMsg, cb)`.
4. Assert `err == nil`, that `don.SendToNode` (mock `handlermocks.DON`) was invoked once per DON member (`len(donConfig.Members)` times) with this message, and that `handler.savedCallbacks[attackerMsg.Body.MessageId]` is populated — demonstrating the request was fully processed and forwarded despite the signer not being part of any allowlist, proving the missing enforcement.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
