### Title
One-block reward capture via shares held only across an epoch boundary - (File: `staking-pool/src/internal.rs`)

### Summary
The pooled-staking accounting in `StakingContract::internal_ping` (`staking-pool/src/internal.rs:194-250`) attributes a realized epoch reward to whatever `stake_shares` exist in the pool at the moment `internal_ping` runs, not to the shares that were actually staked while the reward was being earned on-chain. Because `internal_stake` (`staking-pool/src/internal.rs:70-122`) lets anyone mint shares at the current price with no minimum holding period, an attacker can mint shares immediately before the reward is realized and redeem them immediately after, capturing a pro-rata slice of a reward their capital never helped earn.

### Finding Description
The binding this contract is supposed to preserve is:
`account.stake_shares_held_during_reward_epoch / total_stake_shares_during_reward_epoch == account.reward_share_of(total_reward)`

i.e., the fraction of `total_reward` credited to an account in `internal_ping` should reflect the shares that account held for the epoch that generated the reward.

What `internal_ping` actually does: [1](#0-0) 
computes `total_reward` as the delta between the contract's current NEAR balance and `last_total_balance`, and immediately distributes `remaining_reward` by inflating `total_staked_balance` — which increases the value of every outstanding "stake" share at that instant, using whatever `total_stake_shares` happens to be *right now*. There is no record of how long each share existed relative to the epoch that produced the reward.

`internal_stake` (`staking-pool/src/internal.rs:70-122`) lets any unprivileged account convert `unstaked` balance into shares at the *current* share price with no cooldown: [2](#0-1) 

Exploit flow:
1. Late in epoch `E` (before the validator reward for `E` is realized as an on-chain balance bump), the attacker calls `deposit_and_stake()` / `stake()`, minting shares at the pre-reward price.
2. NEAR protocol credits the validator's locked balance with epoch `E`'s reward; this shows up as `env::account_locked_balance() + env::account_balance()` growing, but the attacker's newly minted stake did not actually contribute to that reward (stake changes only take effect for seat/weight purposes with a multi-epoch delay under NEAR's protocol).
3. On the first transaction of epoch `E+1` (any call — the attacker's own `unstake()` works), `internal_ping` fires, sees `total_reward > 0`, and — because `reward_fee_fraction` numerator is 0, so `owners_fee == 0` and all of `total_reward` flows to `remaining_reward` — inflates `total_staked_balance` for **all** currently outstanding shares, including the ones the attacker minted moments earlier.
4. The attacker immediately calls `unstake()`/`inner_unstake` (`staking-pool/src/internal.rs:124-181`), converting the now-inflated shares back to `unstaked` balance at the new (higher) price, permanently locking in a reward slice proportional to shares held for roughly one block, identical in ratio to a delegator who held those shares for the entire epoch.

None of the existing guards stop this: `internal_ping`'s only assertion is `total_balance >= self.last_total_balance` (ensuring rewards aren't negative, not that they're fairly distributed by duration) (`staking-pool/src/internal.rs:208-211`); there is no `assert_owner`, cooldown, or minimum-epochs-held check on `internal_stake` or `inner_unstake`.

Caveat: I was not able to fully re-confirm, within the tool budget available, the exact statement order of `internal_ping()` relative to `internal_stake`/`inner_unstake` inside the public `stake`/`unstake`/`deposit_and_stake` entrypoints in `staking-pool/src/lib.rs` (I could not load that file before running out of iterations). Based on the standard NEAR core-contracts staking-pool design (ping called once per action, before the balance-mutating step), the sequencing above holds, but this should be verified directly against `staking-pool/src/lib.rs` in the target repository before filing.

### Impact Explanation
Every genuine long-term delegator's shares are diluted: the fixed reward pie for epoch `E` is now divided among more shares than actually earned it, so continuous stakers receive less reward per share than the invariant promises, while the attacker walks away with a slice of yield for one block of capital exposure. This is repeatable every epoch, against any pool with `reward_fee_fraction` numerator 0 (or even nonzero — the owner's slice is unaffected, but delegators are still diluted), and scales with the amount the attacker is willing to stake right before the reward realizes. This matches the "High — rewards … attributed to the wrong party" impact category: no NEAR leaves the contract improperly, but the internal accounting value (share price / reward attribution) diverges from the true entitlement, and other delegators settle for less based on that divergence.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's control: any account can `deposit_and_stake()` with no minimum, and can `unstake()`/`withdraw()` (subject to the normal `NUM_EPOCHS_TO_UNLOCK` delay for cash-out, but the accounting gain is locked in immediately at `inner_unstake` time). The only skill required is timing the stake call near an epoch boundary, which is observable via `env::epoch_height()` and public RPC. Cost is just the staked principal and gas; it is repeatable indefinitely across epochs and across any staking-pool instance deployed from this codebase.

### Recommendation
Introduce time-weighting or a minimum holding period before newly minted shares participate in reward distribution — e.g., snapshot `total_stake_shares` at the start of the epoch being rewarded (before any `internal_stake` calls in the new epoch) and only apply `internal_ping`'s reward inflation to shares that existed at that snapshot, or require a minimum number of full epochs held before a share is eligible for a given epoch's reward split.

### Proof of Concept
Using `near-sdk-sim` (or `near-workspaces`) with two simulated delegators against a staking pool with `reward_fee_fraction = {numerator: 0, denominator: 100}`:
1. Delegator A calls `deposit_and_stake(X)` at epoch `E-1` and holds through epoch `E`.
2. Delegator B calls `deposit_and_stake(X)` at the last block of epoch `E` (same principal `X` as A), immediately before the epoch flips.
3. Advance to epoch `E+1`; trigger `internal_ping` (e.g., by having B call `unstake(1)` or any pool method).
4. Assert: `B.stake_shares * share_price_after - X` (B's unrealized gain) is proportionally equal to `A.stake_shares * share_price_after - X` (A's gain for the same principal), even though A held shares for the full epoch and B held them for one block — violating the claimed invariant that reward is proportional to shares held *across the rewarded epoch*.
5. Assert the sum of both gains exceeds what should have been distributable had only A's principal been eligible for epoch `E`'s reward, demonstrating dilution/misattribution. [3](#0-2) [4](#0-3) [5](#0-4)

    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;

        env::log(
            format!(
                "@{} staking {}. Received {} new staking shares. Total {} unstaked balance and {} staking shares",
                account_id, charge_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }

    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

            env::log(
                format!(
                    "Epoch {}: Contract received total rewards of {} tokens. New total staked balance is {}. Total number of shares {}",
                    epoch_height, total_reward, self.total_staked_balance, self.total_stake_shares,
                )
                    .as_bytes(),
            );
            if num_shares > 0 {
                env::log(format!("Total rewards fee is {} stake shares.", num_shares).as_bytes());
            }
        }

        self.last_total_balance = total_balance;
        true
    }
