### Title
Stale per-epoch instant-withdraw accounting inflates default recovery price and drains `defaultRecoveryReserve` - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`claimInstantWithdrawRequest` pays out an instant receipt and clears only the aggregate `instantWithdrawsRequests[_user]`, but never clears the per-epoch bookkeeping entries `instantWithdrawsRequestsByEpoch[_user][epoch]` and `instantWithdrawClaimsByEpoch[epoch]` [1](#0-0) . These "freed" (already-paid) claims are still referenced later by the default-finalization path, exactly like the ksmbd UAF where a freed transport was still dereferenced by an async notification. `defaultPendingClaimBasis` and `_defaultPrefundedInstantReserve` read `instantWithdrawClaimsByEpoch[epochNumber]`, so phantom already-claimed basis is counted both as defaulted claim basis and as "already-held" reserve [2](#0-1) [3](#0-2) . The result is an inflated `defaultRecoveryPrice` backed by tokens that were already paid out, overpaying earlier claimers and leaving later claimers unpayable [4](#0-3) .

### Finding Description
Within a single `epochNumber` a user can:

1. Request an instant withdraw; the CDO funds it via `getInstantWithdrawFunds`/`collectInstantWithdrawFunds`, so `pendingInstantWithdraws` returns to 0 while `instantWithdrawClaimsByEpoch[epoch]` and `instantWithdrawsRequestsByEpoch[user][epoch]` stay set.
2. Call `claimInstantWithdrawRequest` — `instantWithdrawsRequests[_user]` is zeroed but the per-epoch entries remain (stale/UAF reference).
3. Later in the same epoch, anyone (including the attacker via a second account) creates a *new* unfunded instant request, making `pendingInstantWithdraws != 0`.
4. Borrower defaults; `finalizeDefaultRecovery` computes `pendingBasis` including the full stale `instantWithdrawClaimsByEpoch` and adds `instantBasis - pendingInstant` (which includes the stale claim) as `prefundedReserve` — tokens that are no longer in the contract.

Recovery price is computed as `reserveAmount * 1e18 / totalBasis` where `reserveAmount` contains phantom underlying [5](#0-4) . Claims via `_claimDefaultedWithdrawRequest`/`_claimDefaultedInstantWithdrawRequest` pay `claimBasis * defaultRecoveryPrice / 1e18` from the real reserve [6](#0-5) , so each phantom unit overpays real claimers; when the reserve is exhausted, later legitimate claimers' `_transferDefaultRecovery` reverts — permanent freezing/theft of unclaimed recovery.

Additionally, if a user has only a stale per-epoch instant entry, calling `claimInstantWithdrawRequest` after default finalization hits `_claimDefaultedInstantWithdrawRequest`, which executes `instantWithdrawsRequests[_user] -= claimBasis` on a zero aggregate and reverts on underflow [7](#0-6) .

### Impact Explanation
An unprivileged tranche-token holder inflates `defaultRecoveryPrice` by the amount of their already-claimed instant withdrawals. Every defaulted-epoch receipt (normal and instant) is then paid at a price backed by non-existent tokens. If the attacker holds any defaulted receipt, they extract up to the phantom amount of extra underlying; the deficit materializes as unpayable claims for other users (direct theft + permanent freezing of unclaimed recovery, quantified as the stale claimed amount).

### Likelihood Explanation
Requires only: an instant-withdraw-enabled vault, one funded-and-claimed instant withdrawal, and a second unfunded instant request plus a borrower default in the same `epochNumber`. All attacker steps are unprivileged user actions; the default itself is triggered by honest manager calls around an under-funded borrower. No privileged misbehavior is needed.

### Recommendation
Mirror the kernel fix (tie the free to the object lifetime): when a funded instant claim is paid in `claimInstantWithdrawRequest`, also decrement `instantWithdrawsRequestsByEpoch[_user][epochNumber]` and `instantWithdrawClaimsByEpoch[epochNumber]` (tracking the request epoch per user if an instant request can span epochs). Ensure `defaultPendingClaimBasis`/`_defaultPrefundedInstantReserve` only count live, unfunded instant basis.

### Proof of Concept
```solidity
// Foundry fork PoC sketch (test/foundry/IdleCreditVault.t.sol harness)
// Pre: epoch E running, instant withdraws enabled (setInstantWithdrawParams), honest manager/borrower.

// 1) Attacker requests instant withdraw of 100e6 and it gets funded + claimed.
cdoEpoch.requestInstantWithdraw(100e6, address(AAtranche)); // as attacker
// manager calls getInstantWithdrawFunds -> collectInstantWithdrawFunds
vm.prank(attacker); cdoEpoch.claimInstantWithdrawRequest(); // paid 100e6
// STALE: instantWithdrawsRequestsByEpoch[attacker][E] == 100e6
//        instantWithdrawClaimsByEpoch[E]          == 100e6  (never cleared)

// 2) Victim opens a normal withdraw request (basis 1000e6) and an unfunded
//    instant request of 50e6 in the same epoch E.
//    pendingWithdraws = 1000e6; pendingInstantWithdraws = 50e6;
//    instantWithdrawClaimsByEpoch[E] = 150e6 (100 stale + 50 live)

// 3) Borrower repays insufficiently -> manager stopEpoch path defaults;
//    finalizeDefaultRecovery(recovered, source):
//      pendingBasis    = 1000e6 + 150e6 = 1150e6
//      prefundedReserve= 150e6 - 50e6   = 100e6  <-- phantom (already paid out)
//      defaultRecoveryPrice inflated by 100e6 of non-existent tokens.

// 4) Attacker's defaulted normal receipt claims at inflated price ->
//    overpayment up to ~100e6; subsequent legitimate claims revert on
//    safeTransfer when the real reserve is exhausted.
assertGt(vault.defaultRecoveryPrice(), fairPrice); // fair = realReserve*1e18/trueBasis
```

Without the bug, `instantWithdrawClaimsByEpoch[E]` would be 50e6 and `prefundedReserve` would be 0; the 100e6 phantom inflation and the resulting insolvency disappear.

  function _defaultPrefundedInstantReserve() internal view returns (uint256 prefundedReserve) {
    uint256 pendingInstant = pendingInstantWithdraws;
    if (pendingInstant == 0) return prefundedReserve;
    uint256 instantBasis = instantWithdrawClaimsByEpoch[epochNumber];
    if (instantBasis > pendingInstant) {

  function _claimDefaultedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, defaultEpoch, true);
    if (claimBasis == 0) return amount;

    // pendingWithdraws stores the claim basis owed by the borrower, including APR0 interest.
    pendingWithdraws -= claimBasis;
    // Only receipt principal exists as strategy tokens. APR0 interest is included in claimBasis
    // but was never minted as a user strategy-token receipt.
    _burn(_user, burnAmount);
    amount = (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL;
    _transferDefaultRecovery(_user, amount);
  }
