### Title
Front-runnable on-chain allowlist digest allows unprivileged attacker to grief legitimate Vault requests via replay-guard denial-of-service - ([File: core/capabilities/vault/authorizer.go])

### Summary
The Vault gateway's `AllowListBasedAuth` authorization path treats a purely content-derived request digest as the sole bearer credential for authorizing a Vault operation. Because the digest that grants authorization is published on-chain (via the WorkflowRegistry allowlist transaction) before the legitimate workflow owner submits the matching JSON-RPC request to the gateway, any unprivileged party who observes the on-chain allowlist entry can extract the digest, reconstruct the exact request parameters, and submit it to the gateway first. The gateway's `RequestReplayGuard` then marks that digest as "already seen," causing the legitimate owner's subsequent identical request to be rejected with `ErrRequestAlreadySeen`. This mirrors the ERC‑2612 permit front-running griefing pattern: a publicly observable, deterministic authorization artifact can be front-run and "used up" by an attacker to deny service to the legitimate holder, even though no secrets are stolen.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` computes `req.Digest()` from the request body and checks it against `workflowRegistrySyncer.GetAllowlistedRequests(ctx)` — entries that were placed on-chain by the workflow owner's `WorkflowRegistryOwnerAllowlistedRequest` transaction. [1](#0-0) 

Once any request whose digest matches an allowlisted entry is authorized, `authorizer.AuthorizeRequest` records that digest in a `RequestReplayGuard` keyed purely on the digest value, independent of which caller submitted it: [2](#0-1) 

The replay guard is a simple map of digest → expiry with no binding to session, IP, or requester identity: [3](#0-2) 

Because the allowlisting transaction (and its `RequestDigest`) is public on-chain data, and because the digest is fully deterministic from the request's method/params/owner (the same data the legitimate owner will submit), an attacker who observes the on-chain allowlist entry can reconstruct the identical JSON-RPC request body and race it to the gateway ahead of the legitimate owner. The retry loop in `findAllowlistedItemWithRetry` even waits up to ~30 seconds (10 retries × 3s) for the allowlist entry to propagate, widening the window in which an attacker's copy can land first: [4](#0-3) 

Whichever request reaches the gateway first "consumes" the digest via the replay guard; the legitimate owner's own subsequent submission of the same content is then rejected with `ErrRequestAlreadySeen`, exactly analogous to how a front-run permit invalidates the legitimate caller's subsequent transaction.

### Impact Explanation
Impact is Low/Medium and availability-only: no secrets are disclosed and no funds move, but a legitimate workflow owner's authorized Vault operation (secret create/update/delete/list) can be denied by a third party who has no privileged access, simply by observing public on-chain allowlist data and racing a duplicate request to the gateway. This can disrupt time-sensitive secret provisioning/rotation workflows and force the owner to re-mint a new on-chain allowlist entry (with new digest/expiry), similar to the described permit-griefing pattern's "impact: no funds lost, but service denied."

### Likelihood Explanation
Likelihood is high for any actor who monitors the WorkflowRegistry contract's allowlist transactions and can send HTTP/gateway JSON-RPC requests: the request digest and its parameters (owner, method, request_id, secret IDs — not plaintext secret values) are fully derivable from public on-chain data, and the retry window built into `allowListBasedAuthRetryCount`/`allowListBasedAuthRetryInterval` (up to ~30s) gives attackers ample time to submit a copy to the gateway. No authentication beyond producing the matching JSON body is required for this codepath (`req.Auth == ""`), which is explicitly the backward-compatible, unauthenticated allowlist-based path. [5](#0-4) 

### Recommendation
Bind the replay-guard consumption / allowlist authorization to something the attacker cannot forge or front-run purely from public on-chain data — e.g., require the gateway request to be additionally signed by the workflow owner's key (as already done in the JWT-based auth path) rather than relying solely on parameter-derived digest matching for the legacy `req.Auth == ""` path. Alternatively, bind the allowlisted digest to the specific submitting session/connection or require a fresh, owner-signed nonce per gateway submission so a duplicate content match from an unauthenticated third party cannot consume the on-chain-authorized digest before the legitimate owner's request arrives.

### Proof of Concept
1. Workflow owner submits an on-chain transaction to `WorkflowRegistry` allowlisting a Vault request with digest `D` (public, visible in mempool/on-chain events) for method `vault.secrets.create` with specific `owner`/`namespace`/`secret id` parameters.
2. Attacker observes the on-chain event/transaction, reconstructs the exact JSON-RPC request body (method, params, request_id) that hashes to `D` — this is fully public data, not the encrypted secret payload itself.
3. Attacker submits this reconstructed request to the gateway before the legitimate owner's own client does.
4. `allowListBasedAuth.AuthorizeRequest` matches digest `D` against the allowlist and authorizes it; `authorizer.AuthorizeRequest` records `D` in `RequestReplayGuard`. [6](#0-5) 
5. When the legitimate owner's client subsequently submits the identical request (same digest `D`), `RequestReplayGuard.CheckAndRecord` returns `ErrRequestAlreadySeen`, and the legitimate request is rejected — denial of service on the owner's authorized operation, even though the attacker gains no secret content. [7](#0-6)

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)

	}

	return authResult, nil

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {

	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.

	}
	return a.authorizeJWTBasedAuth(ctx, req)

type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
