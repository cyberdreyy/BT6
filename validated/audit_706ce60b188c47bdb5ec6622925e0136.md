### Title
Unauthenticated forwarding of arbitrary POST body to internal LOOP pprof symbol endpoint via `pluginPPROFPOSTSymbolHandler` - (File: core/web/loop_registry.go)

### Summary
The route `POST /plugins/:name/debug/pprof/symbol` is registered on the top-level unauthenticated `api` group in `loopRoutes` (`core/web/router.go`), with no `auth.Authenticate` middleware applied, unlike the sibling `debugRoutes` and `metricRoutes` which explicitly require session/token authentication for debug-level capabilities. Any unauthenticated caller can hit `LoopRegistryServer.pluginPPROFPOSTSymbolHandler`, which reads the raw request body and forwards it via `doRequest` as a POST to the internal LOOP's `/debug/pprof/symbol` endpoint, returning the raw response body to the caller.

### Finding Description
`loopRoutes` is invoked with the plain `api` group (no auth middleware) in `NewRouter`: [1](#0-0)  and registers the POST symbol route unauthenticated: [2](#0-1) .

By contrast, `debugRoutes` wraps `/debug/vars` in `auth.Authenticate(..., auth.AuthenticateBySession)` [5](#0-4) , and the full pprof handler set exposed via `metricRoutes` is only reachable from within the authenticated `authv2` group requiring session/token auth plus `RequiresAdminRole`-adjacent constraints on other endpoints [6](#0-5) . There is no equivalent gate on `loopRoutes`.

`pluginPPROFPOSTSymbolHandler` reads `gc.Param("name")`, looks up the plugin in the registry, builds the internal LOOP URL, reads the entire unauthenticated request body via `io.ReadAll(gc.Request.Body)`, and forwards it as a POST to `http://<loopHostName>:<port>/debug/pprof/symbol`, then returns the raw response body directly to the caller via `gc.Data(http.StatusOK, ...)`: [4](#0-3)  and [7](#0-6) . No authentication, role check, or origin validation occurs anywhere on this code path — an attacker only needs network access to the node's HTTP API and a valid registered plugin name (obtainable from the also-unauthenticated `/discovery` endpoint at line 232).

### Impact Explanation
This grants an unauthenticated network attacker a debug-capability oracle into an internal LOOP process's pprof `/debug/pprof/symbol` endpoint, which resolves addresses to symbol names — leaking internal binary/memory layout information (function addresses/symbols) that assists further attacks (e.g., crafting exploits against the LOOP plugin process) and constitutes an information-disclosure/authorization-exactness violation for a capability the codebase itself treats as requiring authentication elsewhere (`debugRoutes`, `metricRoutes`). It matches an information-disclosure / broken-access-control bounty class rather than direct fund loss.

### Likelihood Explanation
Trivial and fully repeatable: no credentials, tokens, or roles are required — only knowledge of a registered plugin name (which can itself be harvested unauthenticated from `GET /discovery`), and a single HTTP POST request. This is a persistent bug in the route table, not a transient misconfiguration.

### Recommendation
Wrap `loopRoutes` (or at minimum the `debug/pprof` sub-routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `authv2`/`debugRoutes`, and consider adding a role check (e.g., `auth.RequiresAdminRole`) consistent with the sensitivity of exposing internal pprof endpoints.

### Proof of Concept
1. In `core/web/router_test.go` (or a new test file), build the router via `NewRouter` with a test `chainlink.Application` that registers a fake plugin in the `LoopRegistry` and stub `loopHostName`/`PrometheusPort` pointing to an `httptest.NewServer` that responds 200 with a known body to `POST /debug/pprof/symbol`.
2. Issue `httptest.NewRequest("POST", "/plugins/<name>/debug/pprof/symbol", body)` with no `Authorization` header/session cookie through the router's `ServeHTTP`.
3. Assert the response status is `200` and the response body exactly matches the mock internal server's body, proving unauthenticated pass-through.
4. Additionally assert that hitting `POST /v2/keys/...` (an authv2 route) without credentials returns `401`, to contrast that the symbol route uniquely lacks the auth gate.

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
