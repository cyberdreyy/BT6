### Title
Zip Slip: `ExtractZipArchive` performs no path-confinement check, unlike `tarzstd` extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`archives.ExtractZipArchive` writes every zip entry using the raw `file.Name` field with no join against, or containment check relative to, the extraction directory, whereas `tarzstd`'s extractor explicitly resolves each entry to an absolute path and rejects any path that doesn't stay under the target directory. A crafted cache/artifact zip with `..`-segments or an absolute path in an entry name can therefore write/create files and directories outside the intended extraction root when restored via `CacheExtractorCommand`/`ArtifactsDownloaderCommand`.

### Finding Description
The call chain is `ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32`) → `archives.ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`). Note that the `extractor` struct stores a `dir` field (the target root passed in via `NewExtractor`) but `Extract` never references it: [1](#0-0) 

Inside `ExtractZipArchive`, each `file.Name` is used verbatim to build parent directories and the target file path (`os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Mkdir(file.Name, ...)`, `os.Symlink(...)`), with the only pre-check being `errorIfGitDirectory`, which only rejects paths starting with `.git`: [2](#0-1) [3](#0-2) [4](#0-3) 

There is no `filepath.Clean`, no `filepath.Join` against a root, no `filepath.Abs` resolution, and no `strings.HasPrefix` containment check anywhere in this path. Compare this to `tarzstd`'s extractor, which computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and then enforces `strings.HasPrefix(path, e.dir+string(filepath.Separator))`, rejecting anything that would escape: [5](#0-4) 

In practice, the legacy zip extractor's safety depends entirely on the process's current working directory being the extraction root (there is even a test comment: `// hack: legacy archiver require being in the correct working dir`). But a zip entry name of `../../etc/cron.d/x` or, on Windows, an absolute path such as `C:\Windows\System32\...`, or on Unix `/etc/cron.d/x`, bypasses that convention entirely because Go's `os.OpenFile`/`os.MkdirAll` will honor absolute paths and `..` traversal without any rejection. `CacheExtractorCommand.Execute` builds the extractor with `wd` (the process working directory) as `dir`, but since `ziplegacy`'s `Extract` never consults `dir`, this offers no real confinement: [6](#0-5) 

### Impact Explanation
An attacker who controls the contents of a cache/artifact zip (e.g., produced in one job/stage and consumed in another job on the same shared runner host, or via `.zip`-encoded cache uploaded by the attacker's own pipeline and later restored) can write arbitrary files at attacker-chosen absolute or relative-traversal paths on the host running the extraction step, when the runner selects the legacy zip extractor (`ziplegacy`, the default decompressor for zstd zip and the default when fastzip is not enabled per `commands/helpers/archiver.go` `init()`). This matches the scoped impact: host file write outside the workspace, persisting beyond job lifetime/cancellation, on shell or other executors where the runner process has meaningful filesystem write permissions.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs control over an uploaded cache/artifact's zip content (a standard capability for any pipeline author using `cache:`/`artifacts:` keys) and needs the runner to use the legacy zip extractor path (default unless `FF_USE_FASTZIP` is enabled, in which case `fastzip.NewExtractor` is used instead and may have its own protections — not covered by this scope). No special privileges beyond normal pipeline authorship are required, and the flaw is deterministic (no race or timing dependency).

### Recommendation
Add the same containment check used by `tarzstd_extractor.go` to `archives.ExtractZipArchive` (or to `ziplegacy.extractor.Extract` before delegating): resolve each `file.Name` against the actual extraction root via `filepath.Join(dir, file.Name)` + `filepath.Abs`, reject entries whose resolved path does not have `dir+string(filepath.Separator)` as a prefix (and isn't equal to `dir`), and reject/normalize absolute paths and `..` segments prior to any `os.Mkdir`/`os.OpenFile`/`os.Symlink` call. This requires threading `e.dir` (currently unused) through into `ExtractZipArchive`.

### Proof of Concept
Go unit test (added alongside `helpers/archives/zip_extract_test.go` or `commands/helpers/archive/ziplegacy`):
1. Build an in-memory zip via `archive/zip` containing one entry named `../outside/pwned.txt` (and a second variant using an absolute path like `/tmp/pwned_abs.txt` on Unix).
2. Create two temp dirs: `root` (intended extraction target) and set CWD to `root`.
3. Call `ziplegacy.NewExtractor(reader, size, root)` then `extractor.Extract(ctx)`.
4. Assert: `os.Stat(filepath.Join(filepath.Dir(root), "outside", "pwned.txt"))` returns `nil` error today (proving escape), while the expected/fixed behavior should return an error from `Extract` and no file created outside `root`.
5. Differential assertion: run the identical traversal payload (adapted to tar format) through `tarzstd.NewExtractor` and confirm it returns `fmt.Errorf("... cannot be extracted outside of chroot ...")`, demonstrating the parity gap between the two extractors for identical attacker input.

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
