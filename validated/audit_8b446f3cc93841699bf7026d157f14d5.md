### Title
Cross-user response hijacking via attacker-chosen `MessageId` collision in gateway `savedCallbacks` map - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The gateway's legacy capabilities handler indexes pending user requests in a shared `map[string]*savedCallback` keyed solely by the client-supplied `MessageId`/JSON-RPC request `ID`, with no per-user namespacing and no collision check on insert. Any unprivileged client can choose or predict this ID, allowing it to overwrite another in-flight legitimate request's callback entry and receive that other user's DON response instead of an error — a direct HTTP-gateway analog of the reported bug class: a shared, low-cost, attacker-controllable piece of state that is written unconditionally and later consumed to make decisions/deliver value to whichever party currently "owns" it.

### Finding Description
`HandleLegacyUserMessage` stores the caller's callback keyed by `msg.Body.MessageId`, which originates 1:1 from the untrusted request ID supplied over the wire: [2](#0-1) 

This map assignment does not check whether an entry for that ID already exists — it unconditionally overwrites (`h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}`). When a DON node later replies, `handleWebAPITriggerMessage` looks the ID up, deletes it, and delivers the *first* response received to whoever is currently registered under that key: [3](#0-2) 

`gw.ProcessRequest` only limits ID length to 200 characters; it performs no uniqueness/ownership validation before dispatching to the handler: [4](#0-3) 

Because `MessageId` is fully attacker-chosen and globally shared across all users of a DON's handler instance (the map has no per-caller/per-session partition, unlike the v2 HTTP trigger handler which derives internal IDs via `EncodeExecutionID`/`GenerateExecutionIDWithTriggerIndex`), a malicious client can:
1. Predict or brute-force a `MessageId` that a legitimate victim is likely to use (e.g., sequential/low-entropy IDs, or IDs disclosed via logs/telemetry), or race to submit a request with the exact same ID as an observed in-flight victim request.
2. Submit its own `HandleLegacyUserMessage` request using that same `MessageId` before the victim's DON response arrives, overwriting `h.savedCallbacks[id]` with the attacker's own callback.
3. When the DON node responds to the *victim's* original message (which still carries the same MessageId on the wire), `handleWebAPITriggerMessage` matches it against the *attacker's* callback entry and delivers the victim's response content to the attacker.
4. The legitimate victim's callback reference is lost/orphaned and will simply time out, receiving no response (denial of service), while the attacker receives data intended for another party's workflow execution (cross-user response confusion / potential information disclosure of workflow/trigger data).

This mirrors the report's root bug class: a piece of shared, cheaply-manipulable state (there, `totalBorrowAssets`/`totalSupplyAssets` ratio; here, the `savedCallbacks` map keyed by attacker-controlled ID) is updated without validating that the actor updating it is entitled to, letting an unprivileged party corrupt state that other honest participants depend on, causing loss (of funds there; of response confidentiality/availability here) for the honest party.

### Impact Explanation
An unprivileged, unauthenticated-beyond-standard-node-API client interacting with the gateway's legacy WebAPI trigger endpoint can cause:
- **Cross-user response confusion**: a victim's DON-returned data is redirected to the attacker's HTTP connection.
- **Denial of service** for the victim, whose original request silently times out.
This is a genuine violation of request/response isolation between mutually untrusted gateway clients and does not require any privileged role, network position, or malicious node — only sending an HTTP JSON-RPC request with an ID equal to another concurrently in-flight request's ID.

### Likelihood Explanation
Exploitability depends on the attacker being able to guess or observe a victim's in-flight `MessageId` and win a race before the corresponding DON response arrives. If client applications generate high-entropy random IDs and never reuse/leak them, the practical likelihood is reduced to scenarios where IDs are predictable (sequential counters, timestamps, or externally observable via shared logs/dashboards) or where the attacker is the same infrastructure tenant issuing many requests to increase collision odds. The complete absence of a collision guard in code, however, means the protection currently rests entirely on client-side ID entropy/discipline rather than on the gateway itself — the standard indicator of a real, exploitable design gap rather than a purely theoretical one.

### Recommendation
In `HandleLegacyUserMessage` (and the equivalent `dummyHandler.HandleLegacyUserMessage`), reject or namespace requests instead of blindly overwriting: check `if _, exists := h.savedCallbacks[msg.Body.MessageId]; exists { return error }` before insertion, and/or key the map by a server-generated, unguessable composite of `(caller identity or connection, MessageId)` rather than the raw client-supplied ID alone. This is consistent with how the newer v2 HTTP trigger handler already derives internal execution/request identifiers rather than trusting the raw external ID directly.

### Proof of Concept
1. Victim sends a legitimate legacy `web_api_trigger`-flow HTTP JSON-RPC request to the gateway with request ID `X` and awaits response (`handler.HandleLegacyUserMessage` stores `savedCallbacks[X] = victimCallback`).
2. Before the DON responds, attacker sends its own request to the same gateway/handler using the same ID `X` (`handler.HandleLegacyUserMessage` overwrites `savedCallbacks[X] = attackerCallback`), as permitted because `ProcessRequest`/`ValidatedMessageFromReq` performs no per-caller uniqueness check on the ID [5](#0-4) .
3. The DON node responds to the *victim's* original message with the same `MessageId` `X`.
4. `HandleNodeMessage`/`handleWebAPITriggerMessage` looks up `savedCallbacks[X]`, finds the attacker's callback, deletes the entry, and calls `savedCb.SendResponse(...)`, delivering the victim's data to the attacker's HTTP connection [3](#0-2) .
5. The victim's original callback is never invoked and eventually times out at the gateway's `callback.Wait(ctx)` layer [6](#0-5) .

func ValidatedMessageFromReq(req *jsonrpc.Request[json.RawMessage]) (*api.Message, error) {
	if req.Version != "2.0" {
		return nil, errors.New("incorrect jsonrpc version")
	}
	if req.Method == "" {
		return nil, errors.New("empty method field")
	}
	if req.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var m api.Message
	err := json.Unmarshal(*req.Params, &m)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal request params: %w", err)
	}
	m.Body.Method = req.Method
	m.Body.MessageId = req.ID
	err = m.Validate()
	if err != nil {
		return nil, err
	}
	return &m, nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.

		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
