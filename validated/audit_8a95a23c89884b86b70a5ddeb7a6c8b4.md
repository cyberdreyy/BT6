### Title
Missing Authentication on `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol` Enables Unauthenticated pprof Access to Plugin Processes - ([File: core/web/router.go], [File: core/web/loop_registry.go])

### Summary
The `loopRoutes` function registers `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the `api` router group without any `auth.Authenticate` wrapper, unlike every other sensitive route group (`v2Routes`, `debugRoutes`, `sessionRoutes`). This allows a fully unauthenticated client to trigger pprof profiling (including CPU profiles with attacker-controlled duration) and POST arbitrary bodies to the plugin's internal `/debug/pprof/symbol` endpoint via `pluginPPROFPOSTSymbolHandler`.

### Finding Description
`NewRouter` mounts `api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))` and then calls `loopRoutes(app, api)` [1](#0-0) . Inside `loopRoutes`, the plugin pprof/metrics endpoints are registered with no `auth.Authenticate` middleware at all, unlike `authv2` routes in `v2Routes` or `debugRoutes`'s `/debug` group which explicitly wrap handlers with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [2](#0-1) , [3](#0-2) .

Notably, the `metricRoutes` function — which defines the auth-adjacent `/debug/pprof` group referenced in the question — is defined but is **never called** in `NewRouter` (only `debugRoutes`, `healthRoutes`, `sessionRoutes`, `v2Routes`, and `loopRoutes` are invoked) [4](#0-3) , [5](#0-4) . So the standard core-node `/debug/pprof/symbol` path is not actually reachable in this build at all — it is dead code — but the plugin-scoped equivalent `/plugins/:name/debug/pprof/symbol` **is** reachable and unauthenticated.

`pluginPPROFPOSTSymbolHandler` reads the raw request body and forwards it verbatim via `doRequest` (a plain `http.DefaultClient.Do`) to `http://{loopHostName}:{PrometheusPort}/debug/pprof/symbol` for the named plugin [6](#0-5) . Because this route sits only behind the generic `api` group (rate limiter + session middleware, no auth check), any unauthenticated client can invoke it as long as they know or guess a registered plugin name (obtainable unauthenticated via `/discovery`, also mounted without auth in the same `loopRoutes` block).

### Impact Explanation
An unauthenticated attacker can:
- Trigger CPU/heap/goroutine/block/mutex profiling of a plugin process via `pluginPPROFHandler`, with attacker-controlled `seconds` query param controlling profiling duration — enabling a resource-exhaustion / DoS vector against the plugin.
- POST arbitrary symbol-lookup payloads to the plugin's internal `/debug/pprof/symbol` and receive symbol/function-name resolution data back, which can leak internal binary layout information (function names, addresses) useful for further attacks.
- Retrieve plugin Prometheus metrics via `/plugins/:name/metrics` without authentication.

This matches the "unauthorized action / information disclosure" bounty class — an unauthenticated actor obtaining internal diagnostic data and being able to trigger resource-intensive operations on a service that should require an authenticated session, contrary to the authentication pattern applied everywhere else in the router.

### Likelihood Explanation
Highly likely and trivially exploitable: no credentials are required, the plugin name can be enumerated via the equally-unauthenticated `/discovery` endpoint, and the routes are always mounted whenever any LOOP plugin is registered. No special network position, admin access, or misconfiguration is needed beyond default node deployment.

### Recommendation
Wrap `loopRoutes`'s pprof/metrics endpoints (and `/discovery`, `/plugins/:name/metrics`) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or token-based) middleware applied elsewhere in the router, consistent with `debugRoutes` and `v2Routes`. If external scraping (Prometheus) genuinely requires unauthenticated `/discovery` and `/metrics`, isolate those specific read-only metrics endpoints from the pprof/symbol forwarding endpoints, and require authentication for all `/debug/pprof/*` and `/debug/pprof/symbol` plugin routes.

### Proof of Concept
Go handler-integration test plan (using `cltest.NewApplicationWithConfigAndKey` similar to `loop_registry_test.go`):
1. Start app and register a mock LOOP plugin (as in `TestLoopRegistry`) [7](#0-6) .
2. Create an **unauthenticated** `http.Client` (do not call `app.NewHTTPClient` with session cookie, or explicitly strip auth headers/cookies).
3. Assert `POST /plugins/mockLoopImpl/debug/pprof/symbol` with a crafted body (e.g. `b=0x1234`) returns `200 OK` with resolved symbol data, proving no authentication is enforced.
4. Assert `GET /plugins/mockLoopImpl/debug/pprof/profile?seconds=30` similarly succeeds unauthenticated.
5. Compare against `POST /v2/...` authenticated-only routes (e.g. `/v2/users`) using the same unauthenticated client and assert `401 Unauthorized`, demonstrating the inconsistency between `loopRoutes` and other route groups.
6. Additionally assert that `metricRoutes` is unreachable at all in the running router (e.g., request `GET /debug/pprof/` returns `404`), confirming the referenced "authenticated pprof group" in `router.go` is dead code and the only reachable pprof surface is the unauthenticated plugin-scoped one.

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
