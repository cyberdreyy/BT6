### Title
Instant-withdrawal requests bypass the upfront management/performance fee haircut, letting a lender exit without paying fees charged to queued withdrawers - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`requestWithdraw` has two paths. The normal path computes `totalFees = _totalWithdrawFees(principal, interest)` (management fee for remaining buffer + next epoch, plus performance fee on projected interest), subtracts it from the user's receipt, and adds it to `pendingWithdrawFees` so `stopEpoch` pulls that fee amount from the borrower and forwards it to the `feeReceiver`. The instant-withdrawal path (triggered when `lastEpochApr > currentApr + instantWithdrawAprDelta`) skips this entirely: the user gets a receipt for the full `_underlyings` with no fee deducted and nothing added to `pendingWithdrawFees`.

### Finding Description
In `contracts/IdleCDOEpochVariant.sol` `requestWithdraw` (~lines 761-790):

```solidity
if (_isInstantWithdrawEnabled()) {
  uint256 currentApr = creditVault.unscaledApr();
  if (lastEpochApr > (currentApr + instantWithdrawAprDelta)) {
    creditVault.requestInstantWithdraw(_underlyings, msg.sender);
    _withdrawOps(_amount, _underlyings, _tranche);   // no fee deducted
    return _underlyings;
  }
}
uint256 principal = _underlyings;
(uint256 interest, int256 diff) = _calcInterestWithdrawRequest(_underlyings, _tranche);
uint256 totalFees = _totalWithdrawFees(principal, interest);
_underlyings = principal + interest - totalFees;   // normal path pays fees
pendingWithdrawFees += totalFees;
```

The fee the normal path charges exists because the requested principal stays deployed with the borrower for the remainder of the buffer/epoch before the claim is funded — the management fee compensates for that time. An instant-withdraw receipt is in the same situation: the underlying remains with the borrower until `startEpoch`/`collectInstantWithdrawFunds` sources liquidity (`IdleCreditVault.requestInstantWithdraw` just burns CDO strategy tokens and mints the receipt at lines 356-375; funds arrive later via `collectInstantWithdrawFunds`). Yet no fee is booked: `pendingWithdrawFees` is not increased, so `stopEpoch` (`_transferFeeUnderlyings(_pendingWithdrawFees)`, line 419) never pulls that amount from the borrower. The fee owed on that principal is simply never collected.

This mirrors the external bug: a position can exit while fees that should be attributed to it are never debited. Here the deficit is not socialized onto other lenders' NAV directly (the receipt is principal-only), but the protocol/`feeReceiver` permanently loses the management fee on instantly-exited principal, and that shortfall is effectively absorbed by the vault's fee revenue funded from epoch interest that remaining LPs' capital generates.

### Impact Explanation
- Every lender exiting via the instant path pays zero management fee on principal that remains borrower-deployed for the rest of the epoch, while a queued withdrawer pays `_totalWithdrawFees` upfront. Loss = `managementFee * principal * (remainingBuffer + epochDuration) / YEAR` per exiting request; with e.g. a 1% management fee and full-epoch duration this is ~1% of the exited principal per epoch, repeatable every epoch where the APR-drop condition holds.
- Fee revenue is part of `expectedEpochInterest`/NAV accounting; uncollected `pendingWithdrawFees` mean the borrower is asked for less at `stopEpoch`, so the shortfall lands on the protocol fee share that otherwise reduces what is split to tranches.

### Likelihood Explanation
Requires `disableInstantWithdraw == false`, `allowInstantWithdraw` conditions, and a post-stop APR lower than `lastEpochApr - instantWithdrawAprDelta`. The APR is set by the honest manager at `stopEpoch`, so the attacker cannot force the trigger; they can only opportunistically exit in the buffer window after a genuine APR reduction (a routine event when borrower rates reprice). Any KYC-passed tranche holder can do this permissionlessly each time it occurs. Conditional but realistic; impact per occurrence is bounded by the management fee rate.

### Recommendation
Apply the same upfront fee model to instant requests: before calling `creditVault.requestInstantWithdraw`, compute `totalFees = _totalWithdrawFees(principal, 0)` (management fee only, since instant withdrawers forgo epoch interest), reduce `_underlyings` by it, and add it to `pendingWithdrawFees` so `stopEpoch` collects it from the borrower.

```solidity
if (lastEpochApr > (currentApr + instantWithdrawAprDelta)) {
  uint256 fees = _totalWithdrawFees(_underlyings, 0);
  _underlyings -= fees;
  pendingWithdrawFees += fees;
  creditVault.requestInstantWithdraw(_underlyings, msg.sender);
  _withdrawOps(_amount, _underlyings, _tranche);
  return _underlyings;
}
```

### Proof of Concept
Foundry fork test (extend `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testInstantWithdrawSkipsManagementFee() external {
    uint256 amount = 10_000 * ONE_SCALE;
    uint256 mgmtFeeRate = 1_000; // 1%
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    _setManagementFee(mgmtFeeRate);

    uint256 trancheAmount = idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);

    // epoch 0 at initialProvidedApr
    _startEpochAndCheckPrices(0);
    // stop with unscaled apr dropped by more than instantWithdrawAprDelta
    _stopEpochAndCheckPrices(0, initialProvidedApr - cdoEpoch.instantWithdrawAprDelta() - 1, _expectedFundsEndEpoch());

    // buffer period: request full instant withdraw
    uint256 requested = cdoEpoch.requestWithdraw(0, address(AAtranche));
    uint256 principal = trancheAmount * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;

    // BUG: full principal receipt, zero fees booked
    assertEq(requested, principal, "instant withdraw paid no fee haircut");
    assertEq(cdoEpoch.pendingWithdrawFees(), 0, "no fee booked for borrower pull");

    // A queued request on identical principal would have paid:
    //   _calcManagementFee(principal, mgmtFeeRate, buffer + epochDuration)
    uint256 skippedFee = _calcManagementFee(principal, mgmtFeeRate, _withdrawRequestManagementFeeDuration());
    assertGt(skippedFee, 0, "fee permanently lost");
}
```

Expected: `requested == principal` and `pendingWithdrawFees == 0`, while the equivalent normal request would haircut the receipt by `skippedFee` and enqueue it for collection at the next `stopEpoch`.

Caveat: I was unable to fully read `IdleCDOEpochVariant._isInstantWithdrawEnabled`/`getInstantWithdrawFunds` internals and `_totalWithdrawFees` body (file access truncated), so whether the instant path's fee exemption is a deliberate design trade-off (withdrawer forgoes interest, and principal's fee is deemed covered differently) should be confirmed against the full source. If intentional, the finding reduces to a design inconsistency rather than an exploitable hole.
