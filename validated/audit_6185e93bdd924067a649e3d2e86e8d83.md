### Title
Canonical workflowID computed for gateway-side authorization is not reused in the request forwarded to DON nodes - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Finding Description
`HandleUserTriggerRequest` first validates the raw, attacker-supplied `workflow.workflowID` with `validateWorkflowID`/`validateHexInput`, which only enforces lowercase hex and a maximum length (≤66 chars for a 32-byte ID) — it does **not** require the value to be full-length/zero-padded [1](#0-0) .

`resolveWorkflowID` then computes a canonical, zero-padded form via `normalizeHex(workflowID, workflowIDLength)` and uses **only this canonical value** for everything downstream in the gateway: the `GetWorkflowReference` existence check, `authorizeRequest` (JWT signer authorization against `h.authorizedKeys[workflowID]`), `checkRateLimit`, `setupCallback`, and `WorkflowShards` (which DON shard receives the message) [2](#0-1) .

However, the JSON‑RPC request that is actually forwarded to the DON nodes for execution is built from `triggerReq` — the **pre-normalization, attacker-supplied** request object — not from a request carrying the canonical workflowID:
```go
reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
...
return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
``` [3](#0-2) 

`reqWithAuthorizedKey` only overwrites the `Key` field and re-marshals `triggerReq.Params` (which still has the original, unnormalized `Workflow.WorkflowID`) — the canonical `workflowID` produced by `resolveWorkflowID` is never substituted back into the outgoing message body [4](#0-3) . The canonical ID is used only for logging/observability (`legacyExecutionID`, `executionIDWithTriggerIndex`) [5](#0-4) , and for shard selection via `WorkflowShards(workflowID)` — but the shard/DON that ultimately receives and interprets the workflow selector field still sees the attacker's original, possibly un-padded value.

This is exactly the pattern flagged in the audit question: the canonical/normalized form is computed once (in `resolveWorkflowID`) and reused for the *authorization* and *rate-limiting* decision, but the *execution* payload sent onward to the DON nodes carries a different (non-canonical) representation of the same logical field.

### Impact Explanation
I could not fully verify the node-side (DON capability) parsing logic for the `workflows.execute` `Workflow` selector field, since the `HTTPTriggerRequest`/`WorkflowSelector` type and its consumer live in the external `chainlink-common` module and DON-node capability code, which is outside this repo's indexed content. Based solely on what is verifiable in this repository, the concrete, demonstrable issue is: the gateway's authorization, rate-limiting and shard-routing decisions are keyed off a canonicalized workflow identifier, while the actual message delivered to nodes retains the attacker-controlled, non-canonical identifier string. This is a structural robustness/integrity defect (representation confusion between the value that is checked and the value that is acted upon), but I cannot confirm from the code available here that a DON node would resolve the non-canonical ID to a *different, actually-registered* workflow belonging to another owner (which would be required for the "theft of protocol revenue" impact described in the question). Absent that confirmed node-side behavior, I can validate the mismatch itself but not the full cross-owner billing-confusion exploit chain end-to-end.

### Likelihood Explanation
Any unauthenticated internet client can send a signed gateway HTTP-trigger request with an arbitrary, sub-length hex `workflowID` (e.g. `0xabc` instead of the full 66-character canonical form) that still passes `validateHexInput`. The gateway resolves and authorizes against the padded canonical ID, while forwarding the un-padded value to nodes. Reproducing the mismatch (the padded vs. unpadded identifier discrepancy) is trivially repeatable; whether it can be escalated to actual cross-owner execution depends on node-side behavior not present in this repo's index.

### Recommendation
In `HandleUserTriggerRequest`, replace `triggerReq.Params.Workflow.WorkflowID` with the canonical `workflowID` returned by `resolveWorkflowID` before calling `reqWithAuthorizedKey`, so the exact same normalized identifier used for authorization, rate limiting, and shard routing is the one delivered to DON nodes for execution. Compute the canonical form once and thread it through every subsequent step instead of re-using the original `triggerReq`.

### Proof of Concept
Go handler-level test plan (`http_trigger_handler_test.go`):
1. Register a workflow with canonical ID `0x00000000000000000000000000000000000000000000000000000000000abc` (arbitrary padded 32-byte ID) and an authorized key, via the metadata handler test helpers already present in the test file.
2. Send `HandleUserTriggerRequest` with `workflow.workflowID = "0xabc"` (valid lowercase hex, under max length) signed by the authorized key.
3. Assert `authorizeRequest`/`checkRateLimit`/`WorkflowShards` are invoked with (or succeed against) the padded canonical ID `0x0000...0abc`.
4. Capture the JSON‑RPC request actually handed to `shard.connMgr.SendToNode` (mock `connMgr`) and assert its `Workflow.WorkflowID` field equals the same canonical padded ID rather than the raw `"0xabc"`.
5. Expected (failing) result with current code: the outgoing node request contains `"0xabc"`, not the canonical padded form — demonstrating the two representations diverge between the authorization/rate-limit path and the execution path.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

func (h *httpTriggerHandler) validateWorkflowID(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	if err := validateHexInput(workflowID, workflowIDLength); err != nil {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflowID "+err.Error(), callback)
		return errors.New("workflowID " + err.Error())
	}

	return nil
}

// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}

func reqWithAuthorizedKey(req *jsonrpc.Request[gateway_common.HTTPTriggerRequest], key gateway_common.AuthorizedKey) (*jsonrpc.Request[json.RawMessage], error) {
	params := *req.Params
	params.Key = key
	msg, err := json.Marshal(params)
	if err != nil {
		return nil, errors.New("error marshaling trigger request")
	}
	rawMsg := json.RawMessage(msg)
	r := &jsonrpc.Request[json.RawMessage]{
		Version: req.Version,
		ID:      req.ID,
		Method:  gateway_common.MethodWorkflowExecute,
		Params:  &rawMsg,
	}
	return r, err
}
