## Analysis

The reported bug class is: an internet-facing message handler processes untrusted messages/packets without verifying sender/channel authenticity before executing privileged actions — evidenced by a left-over `// TODO: authenticate the message with channel-id` in the reference code.

The Chainlink gateway has a directly analogous unpatched TODO comment guarding the same kind of missing check, in the **legacy WebAPI capabilities handler**, which is reachable from any unauthenticated HTTP client hitting the gateway's public `/` endpoint.

### Title
Legacy WebAPI Gateway Handler Fans Out Unauthenticated User Messages to All DON Nodes Without Allowlist Check - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`handler.HandleLegacyUserMessage` in the gateway's legacy WebAPI capabilities handler forwards any well-formed, self-signed `web_api_trigger` message to every member of the DON, without checking that the sender is an authorized/allowlisted workflow owner. The code explicitly contains a `// TODO: apply allowlist and rate-limiting here` comment marking the missing check [1](#0-0) , mirroring the same class of bug as the referenced report's uncommented-out `// TODO: authenticate the message with channel-id`.

### Finding Description
Any external, unauthenticated client can `POST` a JSON-RPC request to the gateway's public endpoint. `gateway.ProcessRequest` decodes the request and, for messages carrying a `DonId`, treats it as a "legacy request," calling `msg.Validate()` and then dispatching to the handler's `HandleLegacyUserMessage` [2](#0-1) .

`Message.Validate()` only checks field lengths/formats and recovers the sender address from the ECDSA signature via `ExtractSigner()` — it does not check that the recovered signer is a member of any allowlist; an attacker can generate an arbitrary keypair, self-sign the message, and pass validation trivially [3](#0-2) .

Once validated, `HandleLegacyUserMessage` performs only payload-decoding and staleness checks, then hits the acknowledged-but-unimplemented authorization gap:
```go
// TODO: apply allowlist and rate-limiting here
if msg.Body.Method != MethodWebAPITrigger {
```
and unconditionally fans the request out to **every** DON member node:
```go
for _, member := range h.donConfig.Members {
    err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
}
``` [4](#0-3) 

This is in stark contrast to the JSON-RPC (non-legacy) WebAPI trigger path in `triggerConnectorHandler`, which correctly enforces a per-workflow `allowedSenders` allowlist before dispatching any trigger event to a workflow (`processTrigger` rejects senders not in `allowedSenders`) [5](#0-4) . The legacy handler has no equivalent check at all — it is the "commented-out/never-implemented authentication" analog described in the report.

### Impact Explanation
Because the legacy handler accepts a message from any self-signed key and forwards it to every node in the DON, an unprivileged, unauthenticated external actor can:
- Force every node in the DON to process and act on a fabricated `web_api_trigger` message intended to originate from a legitimate registered workflow/EA, since the underlying node-side capability may not re-validate sender authorization for legacy-routed messages the way `RegisterTrigger`'s `allowedSenders` map does for the JSON-RPC path.
- Trigger uncontrolled fan-out amplification (single external request → N node deliveries), consuming DON compute/network resources — a resource-exhaustion/DoS vector against the whole DON from a single unauthenticated HTTP request.
- Potentially cause unauthorized job/workflow execution paths downstream if node-side capability trust the gateway-forwarded sender field without further checks, matching the "unauthorized job run" risk class from the rules.

### Likelihood Explanation
The gateway HTTP endpoint is explicitly internet-facing and designed to accept external client requests; no authentication/authorization is required to reach `ProcessRequest` and hit the legacy branch — only a syntactically valid, self-signed message is required. This makes the path trivially and remotely reachable by any unprivileged actor, with the missing check acknowledged in-code via the TODO comment.

### Recommendation
Implement the sender/workflow allowlist and rate-limiting check in `HandleLegacyUserMessage` before forwarding to `don.SendToNode`, equivalent to (or reusing) the `allowedSenders` enforcement already present in the JSON-RPC `triggerConnectorHandler.processTrigger` path [5](#0-4) . At minimum, verify `msg.Body.Sender` against a configured allowlist/DON-side registry before dispatching to any node, and apply per-sender rate limiting to prevent fan-out amplification abuse.

### Proof of Concept
1. Generate an arbitrary ECDSA keypair (no registration needed).
2. Construct an `api.Message` with `Body.Method = "web_api_trigger"`, a valid `DonId` for a target DON, and a `TriggerRequestPayload` with a non-zero `Timestamp`.
3. Sign the message with the arbitrary key via `Message.Sign` — this passes `Validate()` since `ExtractSigner` merely recovers whatever key signed it.
4. Wrap in a JSON-RPC request and `POST` it to the gateway's public endpoint (`gw.ProcessRequest`).
5. Observe that `HandleLegacyUserMessage` skips the allowlist step (it is a no-op TODO) and calls `don.SendToNode` for every member in `h.donConfig.Members`, delivering the attacker-crafted trigger to the entire DON without any sender authorization check.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
