### Title
Session/API-token validity is recomputed using the live config duration rather than a fixed expiry, letting stale credentials become valid again after a config change - (File: core/sessions/localauth/orm.go, core/sessions/ldapauth/ldap.go, core/sessions/oidcauth/oidc.go)

### Summary
Chainlink Node's authentication providers (local, LDAP, and OIDC) never persist a session/API-token expiration timestamp. Instead, every authorization check re-derives validity by adding the *currently configured* `SessionTimeout` / `UserAPITokenDuration` to the record's stored `created_at`/`last_used` timestamp and comparing to `now()`. This is structurally identical to the BendDAO auction bug, where `auctionEndTimestamp` was computed on-the-fly from `bidStartTimestamp + (current) auctionDuration` instead of being fixed at creation time.

### Finding Description
- Local auth: `findValidSession` checks `last_used + $2 >= now()` where `$2` is `o.sessionDuration`, itself derived from the live `WebServer.SessionTimeout` config value. [1](#0-0) 
- LDAP auth: session validity is `created_at + $2 >= now()` with `$2 = l.config.SessionTimeout().Duration()`, and API token validity is `created_at + $2 >= now()` with `$2 = l.config.UserAPITokenDuration().Duration()`. [2](#0-1) [3](#0-2) 
- OIDC auth: identical pattern for both sessions and API tokens. [4](#0-3) [5](#0-4) 

In none of these paths is an absolute expiry timestamp stored at session/token creation. Expiry is entirely a function of the *current* config value at lookup time. If an operator increases `SessionTimeout` or `UserAPITokenDuration` (e.g., to accommodate a legitimate operational need), every previously issued session/token record still present in the `sessions`, `ldap_sessions`, `oidc_sessions`, `ldap_user_api_tokens`, or `oidc_user_api_tokens` tables is retroactively re-validated against the new, longer duration. Expired records are only purged lazily — on the next lookup attempt when `Valid` is false — so any not-yet-purged, previously-expired credential becomes usable again the moment the duration is increased.

### Impact Explanation
An unprivileged actor who has obtained a stale session ID or API token that should already be expired (leaked via logs, browser history, shared/former-employee machine, `X-Chainlink-Session` cookie theft, etc.) is currently blocked because `AuthorizedUserWithSession`/`FindUserByAPIToken` compute the record as invalid and purge it. However, this protection is entirely dependent on the *current* configured duration. Any operator adjustment that lengthens `SessionTimeout` or `UserAPITokenDuration` — for entirely unrelated, legitimate reasons — retroactively re-validates all not-yet-purged stale credentials still in the table, silently reviving unauthorized access for anyone holding one of them. Conversely, shortening the duration invalidates currently active, legitimately logged-in operators mid-session, an availability/timing issue mirroring the "auction shortened, catching participants off guard" scenario from the source report.

### Likelihood Explanation
Session/API-token duration is an ordinary, user-facing TOML config value (`WebServer.SessionTimeout`, `UserAPITokenDuration`) that operators are expected to tune. The purge-on-access design means stale rows can persist indefinitely if never queried again before the duration is widened, so the window in which a stale credential could be revived is directly tied to normal, expected operational config changes rather than exotic conditions.

### Recommendation
Store an absolute `expires_at` (or a fixed `created_at`/`last_used` snapshot value at time of validity check) rather than deriving validity from `created_at/last_used + <live config duration>`. Alternatively, run the reaper (`core/sessions/localauth/reaper.go`) synchronously/eagerly whenever the configured duration is reduced or increased, and/or persist the duration that was in effect at creation time so historical validity windows are not silently altered by later config changes.

### Proof of Concept
1. Attacker obtains an old, already-expired session ID or API token belonging to a legitimate user (e.g., from logs, a shared terminal, or a former employee's browser).
2. Operator increases `WebServer.SessionTimeout` (or the equivalent `UserAPITokenDuration`) in the node's TOML config for an unrelated operational reason and restarts/reloads the node.
3. The stale session row (`sessions`/`ldap_sessions`/`oidc_sessions`) or token row is still present because it was never accessed again (and thus never purged).
4. Attacker replays the stale session ID/API token. `AuthorizedUserWithSession`/`FindUserByAPIToken` recompute validity using the new, larger duration against the old `created_at`/`last_used` value, and the check now returns `Valid = true`, granting the attacker authenticated access under the original user's role.

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired
func (oi *oidcAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (clsessions.User, error) {
	if len(sessionID) == 0 {
		return clsessions.User{}, errors.New("session ID cannot be empty")
	}
	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc_sessions table for given session ID, user role and email are saved after the id claims is provided and validated
		var foundSession struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundSession,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_sessions WHERE id = $1",
			sessionID, oi.config.SessionTimeout().Duration(),
		); err != nil {
			if errors.Is(err, sql.ErrNoRows) {
				return clsessions.ErrUserSessionExpired
			}
			return err
		}
		if !foundSession.Valid {
			// Sessions expired, purge
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundSession.UserEmail,
			Role:  foundSession.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE id = $1", sessionID); execErr != nil {
				oi.lggr.Errorf("error purging stale OIDC session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}
