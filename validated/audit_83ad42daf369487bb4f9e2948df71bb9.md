### Title
Removed multisig member's stale confirmation on an unauthored request is counted toward `num_confirmations`, allowing execution below the live-member threshold - (File: multisig2/src/lib.rs)

### Summary
`delete_member` only purges requests *authored* by the member being removed (`r.member == member`) and that member's `num_requests_pk` entry, but never scans `self.confirmations` for other requests the removed member had already confirmed. Because `confirm` counts `self.confirmations.get(&request_id)` by raw `HashSet<String>` size regardless of current membership, a stale confirmation string from a removed member still counts toward `num_confirmations`, letting one remaining live member push execution over the threshold.

### Finding Description
The binding that must hold for every executed request is: `count of distinct members currently in self.members that confirmed R == self.num_confirmations`. `confirm` at [1](#0-0)  checks `confirmations.len() as u32 + 1 >= self.num_confirmations` where `confirmations` is the raw `HashSet<String>` stored per request, with membership never re-validated at execution time.

`delete_member` at [2](#0-1)  only removes requests where `r.member == member` (i.e. requests *authored* by the removed member) and clears that member's `num_requests_pk` entry, but it does not iterate `self.confirmations` to strip the removed member's `to_string()` entry from other requests they had merely confirmed but did not author.

Exploit flow with 3 members (A, B, C), `num_confirmations = 2`:
1. B (or C) creates request R via `add_request` — confirmations set starts empty (`multisig2/src/lib.rs:194-197`).
2. A calls `confirm(R)`: `confirmations.len()==0`, `0+1 >= 2` is false, so A's member string is inserted into `confirmations`, size becomes 1 (`multisig2/src/lib.rs:304-314`).
3. B and C submit and confirm a `DeleteMember { member: A }` self-request, which executes `delete_member(promise, A)`. Since A did not author R, R's entry in `self.requests` isn't touched, and crucially `self.confirmations` for R is never scanned — A's stale confirmation string remains inside R's `HashSet<String>`.
4. C calls `confirm(R)`. `assert_valid_request` and `current_member()` succeed for C (still a live member). `confirmations.len()` is still 1 (A's stale entry), so `1 + 1 >= 2` is true, and `execute_request(R)` fires immediately — with only C being a genuinely live confirming member.

The binding is broken: distinct live members that confirmed R is 1 (only C; A is no longer in `self.members`), but `num_confirmations` is 2. `assert_valid_request` (`multisig2/src/lib.rs:407-423`) only checks the *caller* is currently a member — it does not re-validate the *existing* confirmations in the set against current membership, so the stale entry survives undetected.

### Impact Explanation
This lets a `Transfer`, `AddKey { permission: None }`, `FunctionCall`, or `DeployContract` action be executed against the multisig's held NEAR with effectively fewer live confirmers than `num_confirmations`, moving funds out of the multisig account to a receiver not properly authorized by the required threshold of current members. This is Critical: NEAR leaves a multisig account without the entitled quorum. It is repeatable any time a member is removed while holding an outstanding confirmation on a request they did not author themselves.

### Likelihood Explanation
Preconditions are ordinary multisig operation, not attacker-controlled account balances: any member being confirmed on a request and later removed (a normal, foreseeable operational sequence, e.g. rotating out a compromised or departing signer) leaves this residue automatically — no special attacker action or cost is required beyond the remaining members transacting normally. The remaining live member(s) need only call `confirm` on the stale request to trigger under-threshold execution.

### Recommendation
In `delete_member`, before/while removing the member, also scan `self.confirmations` for all requests containing `member.to_string()` and remove that entry (decrementing effective count), or alternatively re-validate the confirmations set against `self.members` inside `confirm`/`execute_request` before comparing against `num_confirmations`, filtering out any confirmer strings no longer present in `self.members`.

### Proof of Concept
```rust
#[test]
fn test_stale_confirmation_after_delete_member_executes_below_threshold() {
    // members: A (access key), B (access key), C (access key); num_confirmations = 2
    testing_env!(context_with_key(pk_a(), amount));
    let mut c = MultiSigContract::new(vec![member_a(), member_b(), member_c()], 2);

    // B creates request R to transfer funds to attacker-controlled receiver
    testing_env!(context_with_key(pk_b(), amount));
    let request_id = c.add_request(MultiSigRequest {
        receiver_id: attacker(),
        actions: vec![MultiSigRequestAction::Transfer { amount: amount.into() }],
    });

    // A confirms R -> confirmations = {A}, size 1 (not executed, 1 < 2)
    testing_env!(context_with_key(pk_a(), amount));
    c.confirm(request_id);
    assert_eq!(c.confirmations.get(&request_id).unwrap().len(), 1);

    // B and C submit+confirm DeleteMember{A} as a self-request (2-of-3 satisfied by B, C)
    testing_env!(context_with_key(pk_b(), amount));
    let del_id = c.add_request_and_confirm(MultiSigRequest {
        receiver_id: alice(), // current_account_id
        actions: vec![MultiSigRequestAction::DeleteMember { member: member_a() }],
    });
    testing_env!(context_with_key(pk_c(), amount));
    c.confirm(del_id); // executes DeleteMember{A}; A removed from self.members

    // Assert: confirmations on R still contain A's stale entry (not purged)
    assert_eq!(c.confirmations.get(&request_id).unwrap().len(), 1);
    assert!(!c.members.contains(&member_a()));

    // C confirms R -> 1 (stale A) + 1 (C) >= 2 -> executes with only 1 live confirmer
    testing_env!(context_with_key(pk_c(), amount));
    c.confirm(request_id);

    // Binding check: live confirmers of R == 1 (C only), but num_confirmations == 2
    assert_eq!(c.requests.get(&request_id), None); // request executed/removed
    // In an integration (near-workspaces) test, additionally assert receiver's
    // balance increased by `amount`, proving the Transfer fired with only 1 live confirmer.
}
```

```rust
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
```

```rust
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
```
