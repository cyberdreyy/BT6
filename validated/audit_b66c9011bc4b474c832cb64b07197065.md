The vulnerability is real: `confirmations` are stored as a bare `HashSet<String>` per request, and the threshold check in `confirm` at multisig2/src/lib.rs:304 (`confirmations.len() as u32 + 1 >= self.num_confirmations`) only counts entries in that set — it never re-validates that each confirming string still corresponds to a live entry in `self.members`. `delete_member` at multisig2/src/lib.rs:356-379 only purges `requests`/`confirmations` for requests whose `r.member == member` (i.e., requests *authored* by the removed member), never scanning other requests' confirmation sets for stale entries left behind by that member.

### Title
Stale confirmations from removed members count toward `num_confirmations` threshold in `confirm` - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm` counts entries in a request's `confirmations: HashSet<String>` to decide whether `num_confirmations` has been reached, but `delete_member` never removes a departed member's confirmation from requests it did not author. A member can confirm a `Transfer` request, be removed via `DeleteMember`, and still have their confirmation counted toward execution, letting the request execute with fewer live confirming members than `num_confirmations`.

### Finding Description
The broken binding: `count of distinct members currently in self.members that confirmed request_id` should equal `num_confirmations` before execution, but the code instead checks `confirmations.len() as u32 + 1 >= self.num_confirmations` at [1](#0-0) , which is a raw cardinality of a `HashSet<String>` with no cross-check against `self.members`.

Root cause: `delete_member` filters and purges only requests authored by the removed member (`r.member == member`) at [2](#0-1) . It does not iterate `self.confirmations` for other requests to strip out the departing member's `to_string()` entry. `current_member()` at [3](#0-2)  is only invoked at confirm-time to identify the *caller*, not to re-validate previously stored confirmations.

Exploit flow with 4 members, `num_confirmations=3`:
1. Member A calls `add_request` for a `Transfer` (confirmations = {}).
2. Mallory (`MultisigMember::Account { account_id: mallory }`, a legitimate member at this point) calls `confirm(request_id)` → `confirmations.len()+1 = 1 < 3`, so her string is inserted: confirmations = {mallory}.
3. Any member submits and confirms a separate `DeleteMember { member: mallory }` request, executing `delete_member`, which removes mallory from `self.members` and her access key/entry, but leaves `confirmations = {mallory}` on the original transfer request untouched.
4. Member B calls `confirm(request_id)` → `confirmations.len()+1 = 2 < 3` still, needs one more.
5. Member C calls `confirm(request_id)` → `confirmations.len()+1 = 3 >= 3` → executes `Transfer`, even though only B and C (2 live members) plus a phantom mallory entry authorized it.

None of the existing guards catch this: `assert_valid_request` only checks that the *caller* is currently a member [4](#0-3) ; it never revalidates the *stored* confirmation strings. `assert_self_request` and `assert_one_action_only` are unrelated to this path.

### Impact Explanation
NEAR is transferred out of the multisig account via `Transfer` authorized by fewer live members than `num_confirmations` requires — matching the Critical category "a multisig request executed below `num_confirmations` live members." The remaining legitimate members' funds move to `receiver_id` without the intended quorum, and this is repeatable for any request type (`Transfer`, `FunctionCall`, `AddKey`, etc.) as long as a member confirms before being removed and confirmations aren't otherwise purged.

### Likelihood Explanation
Preconditions are ordinary multisig operation: any member who later gets removed (e.g. for being compromised, resigning, or malicious) but had already confirmed a pending request will leave that stale confirmation counted forever. No special attacker cost beyond normal membership churn — this can happen even accidentally during routine member rotation, and an actively malicious removed-member scenario (confirm right before being kicked) is trivially reproducible.

### Recommendation
When removing a member in `delete_member`, iterate all outstanding `confirmations` entries (not just requests authored by that member) and remove the member's `to_string()` key from each `HashSet<String>`. Alternatively, in `confirm`/execution, recompute the count by intersecting stored confirmation strings with current `self.members` before comparing against `num_confirmations`.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);

            .unwrap_or_else(|| env::panic_str("Must be validated above"));

            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );

            let request = self.remove_request(request_id);

            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
