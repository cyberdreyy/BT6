## Analysis Result

### Title
Stale confirmations from removed multisig members still count toward `num_confirmations`, allowing a request to execute below the live-member threshold - (File: `multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
`MultiSigContract::confirm` authorizes and executes a pending `MultiSigRequest` purely by counting entries in the `confirmations` set for that request against `self.num_confirmations`. `delete_member` (v2) / the `DeleteKey` action (v1) only purge confirmations for requests *proposed* by the removed member, not confirmations that member cast on *other* still-pending requests. A member removed from the multisig therefore leaves a "ghost" approval behind on any request they previously confirmed but did not propose, letting that request execute with fewer genuinely current, live-member approvals than the configured k-of-n threshold requires.

### Finding Description
In `multisig2/src/lib.rs`, `confirm()` decides execution solely from the size of the stored confirmation set: [1](#0-0) 

Membership removal is handled by `delete_member`, which only cleans up requests the removed member *proposed* (`r.member == member`), and removes their `num_requests_pk` bookkeeping — it never scans `self.confirmations` for entries belonging to the removed member on requests proposed by *other* members: [2](#0-1) 

Concretely:
1. Members `A, B, C, D` exist, `num_confirmations = 3`.
2. `A` proposes request `R` (e.g. `Transfer`). `B` confirms (`confirmations = {B}`), `C` confirms (`confirmations = {B, C}`). `R` is one confirmation short of executing.
3. A separate, legitimately-approved request removes `C` from the multisig (`DeleteMember { member: C }`), executed with 3 *different* live confirmations (e.g. `A, B, D`). `delete_member` only inspects requests where `r.member == C` (i.e. requests C itself proposed) — `R` was proposed by `A`, so `C`'s stale confirmation entry inside `R`'s `confirmations` set is never removed.
4. `C` is now fully removed from `self.members` and has no access key/authority.
5. `D` confirms `R`. `confirm()` computes `confirmations.len() as u32 + 1 = 3 >= num_confirmations (3)` and executes `R`.

`R` executes as if 3 members approved it, but only `B` and `D` are actual current members at execution time — `C`'s ghost confirmation, cast before removal, silently fills the third slot. The same pattern exists in the legacy `multisig/src/lib.rs`, where `DeleteKey` only removes requests whose `signer_pk` (the proposer) equals the deleted key, leaving that key's confirmations on other pending requests uncleaned: [3](#0-2) [4](#0-3) 

The binding broken: **confirmations recorded (`confirmations.len()`) must equal live-member approvals**, but the contract lets a stale, post-removal confirmation persist and be counted as a current approval.

### Impact Explanation
This directly matches the Critical impact class "a multisig request executed below threshold." Any high-value action gated by the multisig — `Transfer`, `FunctionCall`, `AddKey`, `DeployContract`, or even `AddMember`/`SetNumConfirmations` — can be pushed through with fewer genuinely live approvals than the configured k-of-n policy, undermining the entire security assumption of the contract (that k *current* signers must agree). Funds can move, or governance-critical parameters can change, with an authorization count that no longer reflects reality.

### Likelihood Explanation
This requires no attacker-controlled deployment or foundation privilege — it is reachable purely through the intended, documented multisig workflow (propose → partially confirm → remove a member for unrelated reasons, e.g. key rotation/offboarding → complete confirmation). Any multisig that rotates members (a routine, expected operation per the contract's own `AddMember`/`DeleteMember` design) while it has outstanding partially-confirmed requests is exposed. No special crafting beyond normal usage timing is needed.

### Recommendation
When removing a member (`delete_member` in v2, `DeleteKey` handling in v1), iterate over **all** pending requests' `confirmations` sets (not just requests proposed by that member) and remove any confirmation entry belonging to the removed member/key. Alternatively, re-validate at `confirm()`/execution time that every entry in the stored `confirmations` set still corresponds to a current member of `self.members` before comparing the count against `num_confirmations`.

### Proof of Concept
```rust
// multisig2/src/lib.rs - illustrative extension of existing test module
#[test]
fn test_stale_confirmation_survives_member_removal() {
    // members: A, B, C, D ; num_confirmations = 3
    let mut c = MultiSigContract::new(members_abcd(), 3);

    // A proposes R (e.g. large Transfer), B and C confirm it -> 2/3, not yet executable.
    testing_env!(context_with_account_key(a_account(), a_key(), 0));
    let r_id = c.add_request(transfer_request(bob(), 1_000_000));

    testing_env!(context_with_account_key(b_account(), b_key(), 0));
    c.confirm(r_id); // confirmations = {B}

    testing_env!(context_with_account_key(c_account(), c_key(), 0));
    c.confirm(r_id); // confirmations = {B, C}
    assert_eq!(c.get_confirmations(r_id).len(), 2);

    // Separately, A/B/D remove member C via a fully, legitimately confirmed DeleteMember request.
    testing_env!(context_with_account_key(a_account(), a_key(), 0));
    let del_id = c.add_request(delete_member_request(c_member()));
    c.confirm(del_id);
    testing_env!(context_with_account_key(b_account(), b_key(), 0));
    c.confirm(del_id);
    testing_env!(context_with_account_key(d_account(), d_key(), 0));
    c.confirm(del_id); // executes DeleteMember{C}; C removed from self.members

    // C's stale confirmation on R was never purged (delete_member only checks requests C *proposed*).
    assert_eq!(c.get_confirmations(r_id).len(), 2); // still contains stale C entry

    // D confirms R: count = {B, C(stale), D} = 3 >= num_confirmations(3) -> executes,
    // even though C is no longer a member; only B and D are truly live approvers.
    testing_env!(context_with_account_key(d_account(), d_key(), 0));
    c.confirm(r_id); // Transfer executes with only 2 live-member approvals, not 3.
}
```

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************

            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
