### Title
APR0 interest remainder stranded forever in the credit vault after `stopEpoch` truncation — (`contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
The external report's bug class is *value destroyed by down-rounding to a representable unit*. The same class exists in `IdleCreditVault`'s APR=0 withdrawal bucket: `prepareStopEpochWithApr0` books `_apr0NetInterest` into `pendingWithdraws` (so the borrower funds it in full at `collectWithdrawFunds`), but converts it to a per-epoch rate `apr0RateByEpoch[epochNumber] = (_apr0NetInterest * 1e18) / _principal` that truncates, and each user later materializes interest as `principal * rate / 1e18` which truncates a second time. The sum of all claimable interest is strictly less than `_apr0NetInterest`, so a remainder of underlying is pulled from the borrower into the strategy that no receipt can ever claim. There is no sweep that can repay it to lenders without breaking receipt accounting — it sits unbacked in the strategy contract.

### Finding Description
- In `prepareStopEpochWithApr0`, when APR0 receipts exist and the manager stops the epoch with an override interest above `pendingWithdrawFees`, the strategy adds the full `_apr0NetInterest` to `pendingWithdraws` but stores only the floored rate `(_apr0NetInterest * 1e18) / apr0TotalPrincipal`. (`contracts/strategies/idle/IdleCreditVault.sol:521-537`) [1](#0-0) 
- The borrower then funds `pendingWithdraws` at par through `getFundsFromBorrower` → `collectWithdrawFunds` in `IdleCDOEpochVariant._stopEpoch`, transferring the full `_apr0NetInterest` in underlying to the strategy. (`contracts/IdleCDOEpochVariant.sol:408-410`) [2](#0-1) 
- Each user settles via `_settleApr0`, which credits `(_principal * _rate) / 1e18` — both the stored rate and this multiplication round down. For `N` users the total paid is `≤ _apr0NetInterest`, and strictly less whenever `(_apr0NetInterest * 1e18) % _principal != 0` or per-user truncation dust accumulates. (`contracts/strategies/idle/IdleCreditVault.sol:556-564`) [3](#0-2) 
- The unpaid residue is neither tracked in `pendingWithdraws` (the claim decrements only `claimBasis`, i.e., the floored amounts) nor in `defaultRecoveryReserve`, so `_transferFundedClaim`'s reserve guard doesn't protect it and no function routes it back to lenders. (`contracts/strategies/idle/IdleCreditVault.sol:772-783,897-907`) [4](#0-3) 

An unprivileged KYC'd lender triggers this simply by calling `IdleCDOEpochVariant.requestWithdraw` while `unscaledApr == 0`, choosing a principal that makes `_apr0NetInterest * 1e18` non-divisible by `apr0TotalPrincipal` (almost always true), then the honest manager runs `stopEpoch(0, interest)` and the residue is stranded the moment the user claims. Multiple requesters amplify the loss by up to ~1 wei each plus the rate-truncation share. This mirrors the report: non-round values silently burn/lock tokens because the code never reconciles the funded amount with the representable claim amount.

### Impact Explanation
Permanent (or at best owner-rescuable via the generic `transferToken` escape hatch, which is not part of receipt accounting) freezing of borrower-funded yield. Per epoch the stranded amount is bounded by roughly `apr0TotalPrincipal / 1e18 + n_users` wei, i.e., dust-scale for a 6-decimal pool token but nonzero and irrecoverable through the claim path. Impact is bounded but the invariant break — borrower pays interest that no one can ever receive — is deterministic.

### Likelihood Explanation
Triggering requires only the APR=0 mode (used for lender-requested exits when the pool APR is zeroed), a positive realized epoch interest override, and any principal/rate combination that isn't perfectly divisible — the overwhelmingly common case. No privileged misbehavior is needed; the honest manager's `stopEpoch` crystallizes the loss.

### Recommendation
Either carry the truncation remainder into the next claimable bucket, or compute claims without a stored rate: keep `_apr0NetInterest` per epoch (`apr0NetInterestByEpoch`) and pay `userPrincipal * apr0NetInterest / epochPrincipal` so the last claimant can receive the exact remainder, or track `settledInterest` cumulatively and pay `expectedTotal - alreadySettled` to the final settler. Alternatively, add the undistributed dust to `defaultRecoveryReserve`-style accounting or refund it to the borrower rather than letting it sit unbacked in the strategy.

### Proof of Concept
Foundry fork-style test (same harness as `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testApr0StrandedInterest() public {
    IdleCreditVault strat = IdleCreditVault(address(strategy));
    uint256 amount = 10_000 * ONE_SCALE;

    // deposits, then manager zeroes the APR (normal flow for lender exits)
    idleCDO.depositAA(amount);
    vm.prank(manager);
    strat.setAprs(0, 0);           // unscaledApr = 0 -> APR0 bucket
    uint256 tranche = IERC20(address(AAtranche)).balanceOf(address(this));
    cdoEpoch.requestWithdraw(tranche, address(AAtranche));
    assertGt(strat.apr0TotalPrincipal(), 0);

    _startEpochAndCheckPrices(0);

    // honest borrower repays principal + odd interest chosen so
    // _apr0NetInterest * 1e18 % apr0TotalPrincipal != 0
    uint256 interest = strat.pendingWithdraws() / 3 + 7;
    uint256 principal = strat.apr0TotalPrincipal();
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, amount + interest);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, interest);

    uint256 balBefore = underlying.balanceOf(address(this));
    cdoEpoch.claimWithdrawRequest();
    uint256 paid = underlying.balanceOf(address(this)) - balBefore;

    // the strategy holds borrower-funded interest no receipt can claim
    uint256 stranded = underlying.balanceOf(address(strat));
    assertGt(stranded, 0, "apr0 truncation dust stranded");
    // paid < principal + full pro-rata net interest; stranded > 0 forever
    assertLt(paid, principal + interest * 9 / 10);
}
```

Confidence caveat: I verified the accounting path statically (`prepareStopEpochWithApr0` → `collectWithdrawFunds` → `_settleApr0`/`_claimFundedWithdrawRequest`); I did not execute the PoC. If maintainers consider owner-rescuable dust out of scope, the strict analog may be judged informational rather than medium.
