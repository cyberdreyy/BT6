### Title
IDOR in `VaultController.ExportDKGResult` allows any authenticated API user to fetch another workflow's DKG result package by guessing/enumerating `instanceId` - ([File: core/web/vault_controller.go])

### Summary
`VaultController.ExportDKGResult` accepts an arbitrary `instanceId` from the request body and passes it directly to `vault.NewVaultORM(vc.App.GetDB()).ReadResultPackage` with no check that the calling session/API token is bound to or authorized for that specific DKG instance. Any authenticated node API client (including view/run-role users) can therefore retrieve the `ReportWithResultPackage` (and downstream `MasterPublicKey`-derived) material for any instance ID, not only the ones associated with their own requests.

### Finding Description
The handler `func (vc *VaultController) ExportDKGResult(c *gin.Context)` [1](#0-0)  decodes `ExportDKGResultRequest{InstanceID string}` from the POST body, validates only that the string is non-empty, and then calls:

```go
orm := vault.NewVaultORM(vc.App.GetDB())
v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
``` [2](#0-1) 

There is no step in this function (or in the sibling `VerifyDKGResult` handler, which has the identical pattern) that verifies the requesting session/API token "owns" or is otherwise entitled to the specific `instanceId` being requested. The result is serialized and returned directly to the caller:

```go
hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
...
jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
``` [3](#0-2) 

The gate for this endpoint is only the standard Chainlink node HTTP auth middleware (valid session cookie or API token), which authenticates *who* the caller is but does not authorize *which* `instanceId` they may access — that binding simply does not exist anywhere in this code path.

### Impact Explanation
This matches the "unauthorized disclosure of another user's/job's secret material" bounty class: an authenticated but low-privileged caller (view or run-role user, or any holder of a valid API token) can exfiltrate the `ReportWithResultPackage` bytes for any DKG instance ID on the node, including ones they have no legitimate relationship to, by supplying the ID directly. Because this data feeds into DKG/vault master-key verification and reconstruction flows, disclosure is a confidentiality violation of the DKG result and downstream vault key material.

### Likelihood Explanation
The precondition is only a valid session/API token — no special role or elevated permission is required based on the code reviewed since the handler performs no per-instance ownership check at all. The main constraint on exploitability is knowledge/guessability of a target `instanceId`; if instance IDs are non-secret, sequential, or otherwise obtainable (e.g., from other node API responses, logs, or job specs the user could observe), this is trivially and repeatably exploitable with a single POST request.

### Recommendation
Bind each stored DKG result row to the requesting principal/workflow at creation time (e.g., an owner/job/workflow reference column), and in `ExportDKGResult`/`VerifyDKGResult` verify that the authenticated caller's session/token is authorized for the specific `instanceId` before calling `ReadResultPackage`, returning 403/404 otherwise.

### Proof of Concept
1. Seed two DKG result rows in the `dkg_results` table (via `vault.NewVaultORM(...).SaveResultPackage` or direct SQL) with distinct `instanceId` values ("instanceA", "instanceB") and distinct `ReportWithResultPackage` byte payloads simulating two different tenants/workflows.
2. Using a test HTTP client authenticated as a low-privileged (view-role) session/API token, POST to `/vault/dkg_results/export` with `{"instanceId": "instanceB"}`.
3. Assert the response's `hexPackage` equals `hex.EncodeToString` of tenant B's stored `ReportWithResultPackage`, proving cross-tenant disclosure with no ownership check enforced.
4. Repeat for `/vault/dkg_results/verify` to show the same missing-binding issue in `VerifyDKGResult`.

```go
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
```
