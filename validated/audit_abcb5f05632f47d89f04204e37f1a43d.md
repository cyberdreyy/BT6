## Finding

### Title
Miner can indefinitely suppress tenure-inactivity timeout by spamming stale block proposals - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`SortitionData::check_latest_block_in_tenure` refreshes a tenure's `last_activity_time` every time it sees *any* block proposal that fails to exceed the tenure's known chain length, as long as that failure falls inside the `reorg_attempts_activity_timeout`/`tenure_last_block_proposal_timeout` freshness window. This "activity" timestamp is exactly the clock that `SortitionState::is_timed_out` (v1 and v2) uses to decide whether the current miner has gone inactive and should be replaced. A single miner — the sole slot-holder for its own tenure — can keep submitting cheap, provably-rejected, stale/duplicate proposals for its own tenure faster than `block_proposal_timeout`, perpetually resetting `last_activity_time` to "now" and preventing `is_timed_out` from ever firing, even though the miner is not actually extending the chain. This is directly analogous to the Union Finance bug where `vouch.lastUpdated` is refreshed on any repetitive borrow (not just genuine repayment/new debt), letting the frozen-coin-age/overdue mechanism be trivially reset by cheap repeated actions from a single party.

### Finding Description
`check_latest_block_in_tenure` is called for the block's *own* tenure via `confirms_latest_block_in_same_tenure` (and for the parent tenure via `check_tenure_change_confirms_parent`) from `check_block_against_signer_db_state`, at proposal arrival, at validate-ok, and again at the pre-commit-threshold recheck: [1](#0-0) 

Whenever the newly proposed block does not exceed the height of the tenure's already-known block, and the prior block's `signed_group` timestamp (or lack thereof) is still within `reorg_attempts_activity_timeout`, the code unconditionally calls `signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())` before rejecting the proposal: [2](#0-1) 

There is no novelty check: it doesn't matter whether this is the first reorg/stale-proposal attempt or the hundredth from the same miner in the same tenure — every occurrence stamps `last_activity_time` to the current time. The same unconditional refresh also happens for stale proposals that only conflict with a fresh pre-commit: [3](#0-2) 

This timestamp is the sole basis (besides burn-block receive time as a fallback) for deciding tenure inactivity in both protocol versions: [4](#0-3) [5](#0-4) 

`is_timed_out` feeds two consensus-relevant decisions:
- `check_miner_inactivity`, which decides whether to fail over to the prior tenure's miner: [6](#0-5) 
- v1's `SortitionsView::check_proposal`, which marks the current miner's status `InvalidatedBeforeFirstBlock` once timed out: [7](#0-6) 

Because each distinct (differently-signed/-timestamped) low/duplicate proposal is treated as a fresh evaluation rather than a known block replay (`should_reevaluate_block` only short-circuits identical block hashes), the current miner can trivially manufacture an unbounded stream of cheap, always-rejected proposals for its own tenure — no majority, no other signer's key, no elevated access required — each one legitimately reaching `check_latest_block_in_tenure` and refreshing `last_activity_time`.

### Impact Explanation
This breaks the liveness guarantee the inactivity timeout exists to provide: signers should fall back to a prior valid miner once the current one stops making real progress within `block_proposal_timeout`. A miner that has effectively stalled (e.g., cannot or will not produce a taller valid block, perhaps because it lost its private mempool/state or is intentionally withholding) can nonetheless keep resetting its own activity clock indefinitely by re-broadcasting trivially-varied stale proposals faster than the timeout. Signers will never conclude the miner is inactive, `check_miner_inactivity` never reverts to the prior tenure, and the chain stalls under a tenure that produces no forward progress — a signer "wedged into never signing valid blocks" from the legitimate backup miner, matching the High-severity liveness-wedge criterion.

### Likelihood Explanation
Trivially reachable by the single miner that already controls proposal broadcasting for its own tenure — no cooperation from other signers or the majority is needed, and the cost is just repeatedly signing/broadcasting cheap invalid block headers (e.g., varying the timestamp field) that get rejected but still count as "activity."

### Recommendation
Do not refresh `last_activity_time` on every repetitive/duplicate stale proposal. Either:
- Only refresh activity on a genuinely novel signal (e.g., first occurrence of a stale/reorg proposal in the freshness window, similar to how frozen coin age should be based on `lastRepay`/first occurrence rather than every repetitive borrow), or
- Rate-limit/cap how often a single miner's proposals can extend `last_activity_time` within one `block_proposal_timeout` window, so a drip of cheap rejected proposals cannot indefinitely suppress the inactivity fallback.

### Proof of Concept
1. Miner M wins a tenure and proposes/gets a block signed at height H.
2. M then repeatedly crafts new proposals at height ≤ H (varying header fields such as `timestamp` so each has a distinct `signer_signature_hash`) and broadcasts them at intervals shorter than `block_proposal_timeout`.
3. Each proposal is evaluated fresh (distinct hash), reaches `confirms_latest_block_in_same_tenure` → `check_latest_block_in_tenure`, fails the `chain_length` check, and — because it is within `reorg_attempts_activity_timeout` of the last signed block — calls `update_last_activity_time` for M's own tenure: [2](#0-1) 
4. `is_timed_out` computes `elapsed = now - last_activity_time`, which never exceeds `block_proposal_timeout` because of step 3's continual refresh: [8](#0-7) 
5. `check_miner_inactivity`/`check_proposal` never treat M as timed out, so signers never fail over to the prior miner even though M produces no further valid chain progress.

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    /// the blocks within the signer db and the block proposal timeout
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        signer_db: &SignerDb,
        eval: &GlobalStateEvaluator,
        local_address: &StacksAddress,
        timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall

        if has_block {
            return Ok(false);
        }
        let Some(received_ts) =
            signer_db.get_burn_block_received_time_from_signers(eval, sortition, local_address)?
        else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);

            return Ok(false);
        };
        if elapsed > timeout {
            info!("Sortition has timed out";
                "sorition" => %sortition,
                "timeout" => %timeout.as_secs(),
                "elapsed" => %elapsed.as_secs()
            )
        }
        Ok(elapsed > timeout)
    }
