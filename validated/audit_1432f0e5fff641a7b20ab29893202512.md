### Title
Unprivileged strategy-token donation inflates `pendingWithdraws`, forcing a borrower default and diluting recovery payouts - (File: `contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
`IdleCDOEpochVariant.requestWithdraw` mints withdraw-receipt strategy tokens (`IdleCreditVault` ERC20) directly to the caller. These tokens are freely transferable. An attacker can donate them to the CDO contract, where `_skimDonatedAssets` only sweeps `token` (underlying) and ignores the strategy-token balance. The donation inflates `getContractValue`/`_managedContractValue`, which inflates the interest credited to subsequent withdraw requests via `_calcInterestWithdrawRequest`, inflating `pendingWithdraws` beyond the borrower's actual debt. The next `stopEpoch` then fails in `getFundsFromBorrower` and triggers `_handleBorrowerDefault`, pausing the pool and haircutting every honest claim in `finalizeDefaultRecovery`.

### Finding Description
In `IdleCreditVault.requestWithdraw` the CDO burns `_principal` strategy tokens but mints `_amount` (principal + projected interest) to the user as a transferable ERC20 receipt [1](#0-0) . `IdleCDOEpochVariant._skimDonatedAssets` only transfers `token` (underlying) to `feeReceiver`; donated strategy tokens are never isolated [2](#0-1) .

`_calcInterestWithdrawRequest` computes total epoch interest from `_managedContractValue()`, which counts the CDO's full strategy-token balance including the donation [3](#0-2) . The receipt amount `_underlyings = principal + interest - totalFees` is then pushed into `pendingWithdraws` [4](#0-3) .

At `stopEpoch`, `getFundsFromBorrower(_amountToPullFromBorrower + _pendingWithdraws)` pulls the inflated aggregate; when it exceeds the borrower's real obligation/allowance the transfer reverts and the catch block calls `_handleBorrowerDefault` [5](#0-4) . `defaulted` is set, the pool is paused, and withdraw requests are disabled [6](#0-5) . In `finalizeDefaultRecovery`, `defaultPendingClaimBasis` includes the inflated `pendingWithdraws`, so the attacker's bogus claim basis shares the real recovery pro rata and depresses `defaultRecoveryPrice` for everyone [7](#0-6) .

### Impact Explanation
- Forced borrower default with no borrower misbehavior: all deposits paused and all withdraw requests frozen until `finalizeDefault` — temporary freezing of all user funds.
- Recovery dilution: the attacker's inflated claim basis is paid from the same `defaultRecoveryReserve`, so honest active LPs and receipt holders receive a permanently lower `defaultRecoveryPrice` — direct partial theft of LP funds and unclaimed yield.
- Quantification sketch: donating `D` strategy tokens raises `_managedContractValue` by `D`, inflating a full-tranche withdraw receipt's interest term by roughly `D * apr * epochDuration / 365d / lastNAV` per unit, plus any price-side gain captured via remaining tranche holdings. The `pendingWithdraws` overshoot needed to default the pool equals the borrower's real repayment shortfall, bounded and achievable with a moderate deposit.

### Likelihood Explanation
Requires only a KYC-passing tranche holder (explicitly an allowed attacker class), an ERC20 `transfer` of receipt tokens to the CDO, and one `requestWithdraw`. No privileged role needed; the honest manager's routine `stopEpoch` triggers the default. Guards do not stop it: `_skimDonatedAssets` misses strategy tokens, `_updateAccounting` happily books the donation as gain, and the `try/catch` in `stopEpoch` converts the shortfall into a default rather than reverting.

### Recommendation
- Include the strategy-token balance in donation isolation: track CDO strategy-token backing separately from `balanceOf(idleCDO)`, or subtract unsolicited strategy-token inflows in `getContractValue`/`_managedContractValue`/`_lossActiveBasis`.
- Alternatively make withdraw receipts non-transferable (soulbound to `_user`) in `IdleCreditVault`, or restrict `_transfer` so receipt tokens cannot be sent to `idleCDO`.
- Sanity-check `pendingWithdraws` in `stopEpoch` against a cap derived from last saved NAV + `expectedEpochInterest` before pulling funds.

### Proof of Concept
A Foundry fork PoC would: (1) deposit AA (and BB) as attacker + honest user; (2) attacker calls `requestWithdraw` and `transfer`s the minted strategy-token receipt to `address(cdoEpoch)`; (3) attacker calls `requestWithdraw(0, AATranche)` on the remainder — receipt now priced against inflated `_managedContractValue`, so `pendingWithdraws` exceeds borrower's funded amount; (4) warp past `epochEndDate`, `manager.stopEpoch(0,0)` — `getFundsFromBorrower` reverts → `_handleBorrowerDefault`, `defaulted == true`, `paused == true`; (5) `owner.finalizeDefault(recovered, source)` shows honest user's claim pays less than pro-rata fair share while attacker claims on the inflated basis.

Caveat I could not fully verify within tool-call limits: the exact body of `getContractValue`/`_managedContractValue` in `IdleCDOCreditVault.sol` (whether unsolicited strategy tokens at `price() == 1` are counted — the `price()` of `IdleCreditVault` is fixed at `oneToken`, strongly suggesting yes) [8](#0-7) .

  /// @dev Called by the CDO. `_recoverySource` must approve this strategy for `_recoveredAmount`.
  /// `_recoveredAmount` is the exact external recovery to pull; already-held strategy funds
  /// are added separately because they should not be pulled from `_recoverySource` again.
  /// A zero or subprecision aggregate recovery finalizes at price zero. Active tranche prices are
  /// then zero and pending receipts can be cleared without a payout; any positive reserve too small
  /// to represent at `RECOVERY_FULL` precision remains isolated as recovery dust.
  /// @param _recoveredAmount exact amount of recovered underlying supplied by `_recoverySource`
  /// @param _recoverySource address that supplies recovered underlying
  /// @return defaultBBNav BB's final recovered active NAV
  function finalizeDefaultRecovery(uint256 _recoveredAmount, address _recoverySource) external returns (uint256 defaultBBNav) {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();

    IIdleCDOEpochVariant cdo = IIdleCDOEpochVariant(idleCDO);
    if (defaultRecoveryFinalized || !cdo.defaulted()) revert NotAllowed();
    if (_recoveredAmount != 0 && _recoverySource == address(0)) revert NotAllowed();

    // Active holders are still represented by strategy tokens owned by the CDO. Add the
    // default-epoch net interest so they use the same claim basis as pending redeemers.
    // Split gross backing by saved NAV and default interest by the configured APR split.
    // The CDO strategy-token balance is its gross active value before `unclaimedFees`.
    // Using it directly restores those waived unpaid fees to active recovery basis.
    uint256 activeBalance = balanceOf(idleCDO);
    uint256 activeInterest = _defaultActiveInterestBasis(cdo);
    uint256 activeBasis = activeBalance + activeInterest;
    defaultBBNav = _defaultBBBasis(cdo, activeBalance, activeInterest);
    // Pending receipts have already left active CDO NAV, so they are added as a separate basis.
    uint256 pendingBasis = defaultPendingClaimBasis();
    uint256 totalBasis = activeBasis + pendingBasis;
    if (totalBasis == 0) revert NotAllowed();

    // Some recovery funds may already be in this strategy: partially prefunded instant requests
    // and borrower-send funds that failed at epoch start. Count both without pulling them again.
    uint256 prefundedReserve = _defaultPrefundedInstantReserve();
    uint256 reserveAmount = _recoveredAmount + prefundedReserve + defaultRecoveryReserve;
    // Recovery can be above par if the recovered funds exceed the computed basis.
    uint256 recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis;

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
