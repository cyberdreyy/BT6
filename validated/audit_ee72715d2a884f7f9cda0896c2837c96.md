### Title
Operator-fee refund computed by subtracting two independently floored fee amounts instead of flooring the gas-difference once — (`File: crates/common/evm/src/l1block.rs`)

### Summary
`L1BlockInfo::operator_fee_refund` derives the caller's post-execution refund by independently computing `operator_fee_charge_inner(gas_limit)` and `operator_fee_charge_inner(gas_used)` and subtracting the two results, rather than computing the fee on `gas_limit - gas_used` directly. This is the same rounding-order defect as the Panoptic finding: `floor(A) - floor(B)` is not equal to `floor(A - B)` and can exceed it by up to 1 unit, so the refund paid back to the caller can be larger than the fee actually attributable to the unused gas, silently under-crediting the operator-fee vault. [1](#0-0) 

### Finding Description
The Isthmus operator fee is charged up front against `gas_limit` in `operator_fee_charge`/`operator_fee_charge_inner`, which computes `gas * operator_fee_scalar / OPERATOR_FEE_SCALAR_DECIMAL + operator_fee_constant` (with a different multiplier path for Jovian): [2](#0-1) [3](#0-2) 

After execution, `operator_fee_refund` is supposed to return to the caller the portion of that up-front charge that corresponds to unused gas:

```rust
let operator_cost_gas_limit = self.operator_fee_charge_inner(U256::from(gas.limit()), spec_id);
let operator_cost_gas_used = self.operator_fee_charge_inner(
    U256::from(gas.limit() - (gas.remaining() + gas.refunded() as u64)),
    spec_id,
);
operator_cost_gas_limit.saturating_sub(operator_cost_gas_used)
```

Because `operator_fee_charge_inner` performs an integer division (`gas * scalar / decimal`), each side is independently floored before subtraction. For non-integer quotients, `floor(A) - floor(B)` can be `floor(A-B) + 1` — exactly the arithmetic identity the Panoptic report exploited (`(currFeeGrowth*liq/Q128) - (prevFeeGrowth*liq/Q128)` vs `(currFeeGrowth-prevFeeGrowth)*liq/Q128`). Here, `A = gas_limit`, `B = gas_used`, and the "correct" refund for the *actual* unused gas is `floor((gas_limit - gas_used) * scalar / decimal)`; the code instead computes `floor(A*s/d) - floor(B*s/d)`, which can be up to 1 wei larger than the correct value.

The additive `operator_fee_constant` term cancels exactly on subtraction (no rounding contribution there), so the entire discrepancy is attributable to this division-order mismatch on the `scalar`-weighted term.

### Impact Explanation
Every post-Isthmus transaction that leaves unused gas (i.e., almost every transaction, since `gas_used < gas_limit` unless the tx consumes exactly its limit) is a candidate for this off-by-one refund. Because the refund is computed and applied deterministically inside block execution (`validate_against_state_and_deduct_caller` deducts the up-front charge, and the refund path returns balance to the caller after execution), each transaction can silently overpay the caller by up to 1 wei of ETH relative to what it should have kept in the operator-fee vault (`OperatorFeeVault` predeploy). This is a systemic, protocol-level fee-accounting bug rather than an attacker-triggered exploit, and any single occurrence is bounded to 1 wei per transaction — there is no compounding multi-user amplification analogous to the Panoptic multi-holder scenario, since the deduction/refund pair is per-transaction and self-contained.

Given the per-transaction bound of 1 wei and lack of any user-controlled amplification vector, this does not rise to a "concrete unauthorized operation, theft, or freezing of funds" at the scale required — it is systemic dust-level fee leakage from the protocol's own revenue collection, not an economically exploitable vulnerability an attacker can direct or scale.

### Likelihood Explanation
The condition (`gas.limit() != gas.remaining() + gas.refunded()`, i.e., any gas actually consumed) is met on essentially every transaction, so the code path executes constantly. However, the resulting discrepancy is bounded to at most 1 wei per transaction and is not attacker-controllable in direction or magnitude beyond that bound — it is a systemic protocol rounding leak, not an exploitable griefing/theft vector reachable by a single crafted transaction to extract meaningful value.

### Recommendation
Compute the refund directly from the actual unused-gas amount rather than subtracting two independently-floored fee evaluations, i.e.:
```rust
let unused_gas = U256::from(gas.remaining() + gas.refunded() as u64);
let refund = self.operator_fee_charge_inner_no_constant(unused_gas, spec_id);
```
where the scalar-only (no-constant) helper mirrors the Uniswap-V3-style "compute delta first, then divide once" pattern, eliminating the double-flooring gap. Add a regression test asserting `operator_fee_refund(...) <= floor((gas_limit - gas_used) * scalar / decimal)` (or equality) across scalar/gas value fuzzing.

### Proof of Concept
Given `operator_fee_scalar = s`, `decimal = d = OPERATOR_FEE_SCALAR_DECIMAL`, choose `gas_limit = A`, `gas_used = B` such that `A*s mod d` and `B*s mod d` straddle a boundary so that `floor(A*s/d) - floor(B*s/d) = floor((A-B)*s/d) + 1`. Concretely (analogous to the Panoptic PoC's Q128 example): with `d = 1_000_000` (per `OPERATOR_FEE_SCALAR_DECIMAL`), pick `s` and `A, B` such that `A*s = k*d + 999_999` and `B*s = j*d + 1` for integers `k, j` with `A*s - B*s` a multiple of `d` minus a small remainder — this reproduces `floor(A*s/d) - floor(B*s/d) = (A*s - B*s)/d + 1` while the true delta-based computation yields exactly `(A*s - B*s)/d`. Instantiating `operator_fee_charge_inner` with these two `gas` values via the existing test harness in `crates/common/evm/src/l1block.rs` (see `test_operator_fee_refund`/`test_operator_fee_charge_formulas`) and comparing against `(A - B) * s / d` demonstrates the 1-unit excess refund.     pub fn operator_fee_refund(&self, gas: &Gas, spec_id: BaseSpecId) -> U256 {
```rust
        if !spec_id.is_enabled_in(BaseUpgrade::Isthmus) {
            return U256::ZERO;
        }

        let operator_cost_gas_limit =
            self.operator_fee_charge_inner(U256::from(gas.limit()), spec_id);
        let operator_cost_gas_used = self.operator_fee_charge_inner(
            U256::from(gas.limit() - (gas.remaining() + gas.refunded() as u64)),
            spec_id,
        );

        operator_cost_gas_limit.saturating_sub(operator_cost_gas_used)
    }
```

```rust
    /// Calculates the operator fee for a given `gas` amount.
    ///
    /// Missing scalars fall back to zero to match the execution path during the
    /// txpool bootstrap window before the first L1 attributes deposit.
    pub fn operator_fee_charge_inner(&self, gas: U256, upgrade: BaseUpgrade) -> U256 {
        let operator_fee_scalar = self.operator_fee_scalar.unwrap_or_default();
        let operator_fee_constant = self.operator_fee_constant.unwrap_or_default();

        let product = if Self::is_enabled(upgrade, BaseUpgrade::Jovian) {
            gas.saturating_mul(operator_fee_scalar)
                .saturating_mul(U256::from(OPERATOR_FEE_JOVIAN_MULTIPLIER))
        } else {
            gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
        };
        product.saturating_add(operator_fee_constant)
    }
```
