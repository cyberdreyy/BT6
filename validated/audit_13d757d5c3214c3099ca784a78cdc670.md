### Title
CreateAccount bypasses deterministic-account protection, permanently blocking legitimate DeterministicStateInit deploys - ([File: runtime/runtime/src/actions.rs])

### Finding Description
`check_account_existence`'s `Action::CreateAccount` branch only rejects the action when `account_is_implicit(account_id, config.wasm_config.eth_implicit_accounts)` returns `true`. [1](#0-0)  `account_is_implicit` is a narrowly-scoped predicate historically built to guard only the two "implicit" account kinds (`NearImplicitAccount`, 64-hex, and `EthImplicitAccount`, `0x…`) so that a `CreateAccount` action cannot hijack an account whose public key/address the attacker doesn't control. `NearDeterministicAccount` (`0s…`-prefixed) ids are a separate `AccountType` variant used by `Action::DeterministicStateInit`, whose existence check deliberately allows both existing and non-existing accounts through, relying on `deploy_deterministic_account`-style logic to skip installation once `account.is_some()` — i.e. it treats a pre-existing account record as "already initialized, do nothing." [2](#0-1) 

Because `account_is_implicit` does not treat `NearDeterministicAccount` ids as implicit, a plain `Action::CreateAccount` targeting a syntactically valid `0s…` account id is not rejected by this predicate. If that id also satisfies the ordinary account-creation rules in `action_create_account` (either it is a sub-account of the sender, or — since deterministic ids are long, like implicit ids — it is a long enough top-level name to bypass the registrar-only restriction), the action succeeds: `actor_id` is set to the attacker and a bare `Account` with `AccountContract::None` is created at that id. [3](#0-2) 

Once that bare account record exists, a later, legitimate `DeterministicStateInitAction` at the same id passes `check_account_existence` (which explicitly allows both existing and non-existing accounts for this action) but the deploy step observes `account.is_some()` and treats the account as already initialized, silently skipping the real code/data installation the rightful deriver intended.

### Impact Explanation
An attacker can pre-empt any `0s…` deterministic account id before its rightful deriver submits the real `DeterministicStateInit` action, permanently occupying the address with an empty, contract-less account under the attacker's `actor_id`. Funds or calls later routed to that deterministic address (which callers/relayers assume will host specific deployed code) are stranded against a bare account that will never run the intended contract logic, matching the "permanent freezing of user funds" bounty category, and denying the legitimate deployer any recourse since the account already exists.

### Likelihood Explanation
Exploitation only requires an ordinary funded account submitting an unprivileged transaction with a single `CreateAccount` action targeting a known/predictable `0s…` id — no special permissions, validator access, or leaked keys are needed. Deterministic account ids are derivable by anyone who knows the derivation inputs (e.g., factory contract + salt), so front-running the legitimate deployer is feasible and repeatable for any target id before its real initializer transaction lands.

### Recommendation
Extend `account_is_implicit` (or add an explicit check in `check_account_existence`'s `Action::CreateAccount` branch) to also reject `AccountType::NearDeterministicAccount` ids, mirroring the protection already given to `NearImplicitAccount` and `EthImplicitAccount`, so only `Action::DeterministicStateInit` can ever populate a `0s…` account.

### Proof of Concept
1. Unit test `action_create_account` with an `account_id` constructed to have `AccountType::NearDeterministicAccount` (a `0s…`-prefixed, correctly-formatted id) as predecessor's sub-account or as a sufficiently long top-level id; call `check_account_existence(&Action::CreateAccount(...), &None, &account_id, &config, false)` and assert it returns `Ok(())` (not rejected), then call `action_create_account` and assert `account` becomes `Some(Account { contract: AccountContract::None, .. })` with `actor_id == attacker`.
2. Follow up with a `DeterministicStateInitAction` targeting the same `account_id` with the real state_init/code payload; call `check_account_existence` for `Action::DeterministicStateInit` (expect `Ok(())` since it allows existing accounts) then invoke the deploy path and assert that the deploy is skipped/no-op because `account.is_some()`, leaving `AccountContract::None` instead of the intended deployed contract — demonstrating the legitimate deployer's install is permanently blocked.

pub(crate) fn action_create_account(
    fee_config: &RuntimeFeesConfig,
    account_creation_config: &AccountCreationConfig,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    account_id: &AccountId,
    predecessor_id: &AccountId,
    result: &mut ActionResult,
) {
    if account_id.is_top_level() {
        if account_id.len() < account_creation_config.min_allowed_top_level_account_length as usize
            && predecessor_id != &account_creation_config.registrar_account_id
        {
            // A short top-level account ID can only be created registrar account.
            result.result = Err(ActionErrorKind::CreateAccountOnlyByRegistrar {
                account_id: account_id.clone(),
                registrar_account_id: account_creation_config.registrar_account_id.clone(),
                predecessor_id: predecessor_id.clone(),
            }
            .into());
            return;
        } else {
            // OK: Valid top-level Account ID
        }
    } else if !account_id.is_sub_account_of(predecessor_id) {
        // The sub-account can only be created by its root account. E.g. `alice.near` only by `near`
        result.result = Err(ActionErrorKind::CreateAccountNotAllowed {
            account_id: account_id.clone(),
            predecessor_id: predecessor_id.clone(),
        }
        .into());
        return;
    } else {
        // OK: Valid sub-account ID by proper predecessor.
    }

    *actor_id = account_id.clone();
    *account = Some(Account::new(
        Balance::ZERO,
        Balance::ZERO,
        AccountContract::None,
        fee_config.storage_usage_config.num_bytes_account,
    ));
