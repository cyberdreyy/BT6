### Title
`GlobalStateEvaluator::reached_agreement` uses floor division instead of ceiling, letting the signer set treat a sub-70%-weight view as global consensus - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority threshold with a plain integer division (`floor`), while the actual block-signing threshold used everywhere else in the codebase (`NakamotoBlockHeader::compute_voting_weight_threshold`, used in `verify_signer_signatures` at the node, and by the signer's own pre-commit/signature-tally logic) computes the threshold with an explicit `ceil`. Whenever `total_weight * 7` is not a multiple of 10, these two thresholds differ by exactly one unit of weight, so the global state-machine agreement check can fire with strictly less than the true 70% weight required to actually sign/approve a block.

### Finding Description
Compare the two threshold computations:

`stackslib/src/chainstate/nakamoto/mod.rs`: [1](#0-0) 
```
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```
This is `ceil(0.7 * total_weight)` and is the threshold used to verify block signatures at the node (`verify_signer_signatures`) and by the v0 signer's own signature/pre-commit tallying (`handle_block_pre_commit`, `store_and_process_block_signature`, `store_and_process_block_rejection` in `stacks-signer/src/v0/signer.rs`).

`libsigner/src/v0/signer_state.rs`: [2](#0-1) 
```
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}

pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```
`reached_agreement` computes `floor(0.7 * total_weight)` and only requires `vote_weight >= floor(...)`. Whenever `0.7 * total_weight` is not an integer, `floor(0.7*W) = ceil(0.7*W) - 1`, i.e. `reached_agreement` requires exactly one unit of weight less than the real supermajority threshold `compute_voting_weight_threshold` demands. (`reached_disagreement` is not affected the same way: `W - ceil(0.7W) == floor(0.3W)`, which matches the "blocking minority" computation used elsewhere, e.g. `self.total_weight.saturating_sub(self.weight_threshold)` in `stacks-node/src/nakamoto_node/signer_coordinator.rs:522` — only `reached_agreement` diverges.)

`GlobalStateEvaluator` (via `reached_agreement`) is what decides, from gossiped `StateMachineUpdate`s, whether the signer set has reached global agreement on the active signer protocol version (`determine_latest_supported_signer_protocol_version`), the global burn view (`determine_global_burn_view`), and — critically — the global `SignerStateMachine`, including which miner/tenure is the current canonical one (`determine_global_state`, used to build `MinerState::ActiveMiner`). Per `docs/signer-flows.md`, this global state feeds directly into a signer's local state-machine updates and capitulation logic, which in turn determine which miner/tenure a signer is willing to build off of and sign.

### Impact Explanation
Because `reached_agreement` requires one unit of weight less than the genuine 70% supermajority (`compute_voting_weight_threshold`), a coalition holding strictly less than the true 70% threshold weight (but exactly `floor(0.7*W)`) can be treated by `GlobalStateEvaluator::determine_global_state` as having reached "global consensus" on a `current_miner`/burn view. A signer capitulating to this falsely-"agreed" global state (see `capitulate_viewpoint` / `handle_pending_update` in `signer_state.rs`) can end up building its local view of the canonical miner/tenure on a basis that never actually cleared the real 70% weight bar that block-signature verification enforces. This is the "acting on a threshold weaker than the one the chain actually enforces" pattern from the analog report: the intended safety margin is silently narrowed by an off-by-one rounding error, moving the signer's judgment of "is this canonical" out of sync with the invariant the network actually requires (High: acting on a miscalculated/looser threshold that misaligns local judgment with actual consensus requirements).

### Likelihood Explanation
This does not require a majority of signers or any privileged access — it triggers deterministically any time `total_weight * 7 mod 10 != 0` (the common case for typical signer-weight totals) and the gossiped `StateMachineUpdate`s for competing views split such that one view's weight lands exactly at `floor(0.7*W)`. No malicious behavior beyond normal signer/miner gossip is needed to hit the discrepancy; it is a latent correctness bug in every reward cycle whose total weight isn't a multiple that makes `0.7*W` exact.

### Recommendation
Change `GlobalStateEvaluator::reached_agreement` to use the same ceiling-based computation as `NakamotoBlockHeader::compute_voting_weight_threshold` (i.e., `vote_weight >= ceil(total_weight * NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD / 10)`), ideally by calling `compute_voting_weight_threshold` directly instead of re-implementing the arithmetic, so the two thresholds can never drift apart again.

### Proof of Concept
Take `total_weight = 11`, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`:
- Real signing threshold: `compute_voting_weight_threshold(11) = ceil(11*7/10) = ceil(7.7) = 8` (i.e. 8/11 ≈ 72.7% weight actually required to sign/approve a block, matching the unit test at `stackslib/src/chainstate/nakamoto/tests/mod.rs:4118-4122`, which pins the round-up behavior).
- `GlobalStateEvaluator::reached_agreement(7)`: `floor(11*7/10) = floor(7.7) = 7`; `7 >= 7` → `true`.

So a set of signers whose gossiped `StateMachineUpdate`s agree on a given `current_miner`/burn view with only weight `7` out of `11` (63.6%) will have that view reported as "globally agreed" by `determine_global_state`/`determine_global_burn_view`, even though the same weight (`7`) would be rejected as insufficient by `compute_voting_weight_threshold` (which needs `8`) everywhere block signatures are actually tallied and verified.
