### Title
BridgeTypesController.Show leaks the bridge's plaintext OutgoingToken secret to any authenticated user regardless of role - (File: core/web/bridge_types_controller.go)

### Summary
`GET /v2/bridge_types/:BridgeName` is registered without any role wrapper (`authv2.GET("/bridge_types/:BridgeName", bt.Show)`), unlike `Create`/`Update`/`Destroy` which require `auth.RequiresEditRole`. `Show` returns `presenters.NewBridgeResource(bt)`, whose JSON always includes the cleartext `OutgoingToken` field (not `omitempty`), so a view-role authenticated user can read another admin-created bridge's `OutgoingToken` secret.

### Finding Description
The route is defined at [1](#0-0) , where `bt.Show` is bound directly under `authv2` (session/token authentication only) with no `auth.RequiresEditRole`/`RequiresViewRole` wrapper, while `Create`, `Update`, and `Destroy` are all wrapped with `auth.RequiresEditRole`. This is confirmed by the route RBAC test table entry `{"GET", "/v2/bridge_types/MOCK", true, true, true}`, meaning view role is explicitly allowed on this route [2](#0-1) .

`Show` fetches the persisted `bridges.BridgeType` by name and serializes it via `presenters.NewBridgeResource`: [3](#0-2) .

`NewBridgeResource` unconditionally copies `b.OutgoingToken` into the JSON `outgoingToken` field, which has no `omitempty` tag, unlike `IncomingToken` which does: [4](#0-3) .

The `BridgeType` model persists `OutgoingToken` in cleartext (only `IncomingTokenHash`/`Salt` are hashed) as generated in `NewBridgeType`: [5](#0-4) . `IncomingToken` itself is not stored on `BridgeType` at all (only its salted hash is persisted, confirmed via `AuthenticateBridgeType`), so it cannot leak through `Show`; but `OutgoingToken` is stored verbatim and is exposed on every `Show`/`Index` call.

### Impact Explanation
`OutgoingToken` is the bridge's shared secret used to authenticate the node's outbound requests to the external adapter (sent as a bearer/authorization value on outgoing pipeline HTTP calls to the bridge URL). Any authenticated user with only view role — who is not supposed to manage bridges or external initiators — can call `GET /v2/bridge_types/:BridgeName` and obtain this cleartext secret for any bridge on the node, enabling them to impersonate the node when talking to (or spoof responses sent as) the external adapter that trusts this token. This is a secret-disclosure / role-authorization-bypass finding matching the "sensitive credential/secret disclosure to unauthorized user" bounty class. Note: `IncomingToken` (the token an external initiator would present to the bridge's webhook resume endpoint) is not persisted in cleartext and is not exposed here, so the "impersonate the external initiator to forge signed webhook requests" part of the question as literally stated is not substantiated — only `OutgoingToken` leaks.

### Likelihood Explanation
Trivial and fully repeatable: requires only a valid view-role session/API token (the lowest privilege authenticated role in the system) and knowledge/guessing of a bridge name (bridge names are also enumerable via the unrestricted `GET /v2/bridge_types` index route, which is likewise not role-gated). No admin credentials, host access, or social engineering needed.

### Recommendation
Wrap `bt.Show` (and `bt.Index`) with an appropriate role check consistent with the sensitivity of `OutgoingToken` (e.g., `auth.RequiresEditRole` or `auth.RequiresAdminRole`), or strip `OutgoingToken` (and any other secret) from `presenters.BridgeResource` for view-role callers / general `Show` responses, exposing it only to edit/admin roles or only at creation time as is already done for `IncomingToken`.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/bridge_types_controller_test.go` patterns):
1. Start app with `cltest.NewApplication`, create an admin HTTP client and a view-role client (`cltest.User{Role: sessions.UserRoleView}`).
2. As admin, `POST /v2/bridge_types` with a valid `BridgeTypeRequest`; capture the response and separately query the DB/ORM for the persisted `BridgeType.OutgoingToken` value.
3. As the view-role client, call `GET /v2/bridge_types/:BridgeName` for the created bridge.
4. Assert response status is 200 (not 401/403) — proving the route is not role-restricted.
5. Parse the JSON body and assert `data.attributes.outgoingToken` equals the known persisted `OutgoingToken` value — proving disclosure.
6. Assert `incomingToken`/`salt` fields are absent (to scope the finding precisely to `OutgoingToken`).

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
