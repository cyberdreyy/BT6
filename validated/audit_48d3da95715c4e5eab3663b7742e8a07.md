### Title
Token-account JSON-parsed decimals/uiAmount can be forged via unvalidated mint-ownership lookup - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`get_parsed_token_account`/`get_parsed_token_accounts` and `get_token_account_balance` derive the decimals used to compute `UiTokenAmount` by reading the 32-byte "mint" field embedded in a token account's raw data and fetching whatever account currently lives at that pubkey, without ever checking that the fetched mint account is owned by a recognized SPL Token program. An attacker who controls the on-chain data of both a token account and an arbitrary "mint-shaped" account can make the RPC layer report decimals/uiAmount computed from unrelated, attacker-chosen data.

### Finding Description
`get_token_account_mint` only extracts bytes `[0..32]` from `account.data()` after verifying overall length via `Account::valid_account_data`; it returns the embedded pubkey with no relationship check to the account's owner program: [1](#0-0) .

`get_parsed_token_account` then resolves that pubkey directly against the bank and feeds its raw `data()` into `get_additional_mint_data`, which only calls `StateWithExtensions::<Mint>::unpack(data)` — it never checks `mint_account.owner()` against `spl_token_interface::id()` or `spl_token_2022_interface::id()`: [2](#0-1) [3](#0-2) .

The batch path `get_parsed_token_accounts` and `get_mint_owner_and_additional_data` have the same gap — the only owner check performed is the native-mint special case; for any other pubkey the mint account's owner is fetched but never validated as a token program before its `decimals` field is trusted: [4](#0-3) .

`get_token_account_balance` in `rpc/src/rpc.rs` checks `is_known_spl_token_id(account.owner())` for the **token account** being queried, but calls `get_mint_owner_and_additional_data(&bank, mint)` using the mint pubkey taken from `token_account.base.mint` with no equivalent ownership check on the resolved mint account: [5](#0-4) .

Because Solana's SPL Token/Token-2022 `Mint` layout (82-byte base struct: `mint_authority: COption<Pubkey>`, `supply: u64`, `decimals: u8`, `is_initialized: bool`, `freeze_authority: COption<Pubkey>`) is public and trivially satisfiable, an attacker can write any account (owned by any program, including `system_program` via a data-bearing PDA created by their own program, or simply another self-owned token account/mint under the same token program) whose bytes unpack successfully as a `Mint`, and point an SPL token account's `mint` field at it. The RPC layer will then compute `tokenAmount.decimals`/`uiAmount` from that unrelated data instead of the account's real, ownership-consistent mint.

### Impact Explanation
This falls under the "decoder panic and misreporting" category explicitly listed as in-scope: `getAccountInfo` (encoding=`jsonParsed`) and `getTokenAccountBalance`/`getTokenAccountsByOwner`/`getTokenAccountsByDelegate`/`getProgramAccounts` (jsonParsed) can return a `tokenAmount.decimals`/`uiAmount` that is disconnected from the actual mint that governs the token account, misleading any client (wallets, explorers, other on-chain-data consumers relying on RPC) that trusts the parsed/derived fields rather than re-deriving decimals themselves. It does not corrupt raw account bytes, consensus state, or cause a crash — the effect is confined to the convenience JSON-parsed/derived fields.

### Likelihood Explanation
Fully attacker-controlled and requires no privileges beyond depositing arbitrary account data on-chain (a normal, unprivileged operation) followed by a single `getAccountInfo`/`getTokenAccountBalance` RPC call. No parameter-limit, commitment, or length-check guard in the current code addresses this — the only existing check (`is_known_spl_token_id`) validates the *queried* account's owner, not the *resolved mint's* owner, leaving the gap open and easily reproducible.

### Recommendation
In `get_additional_mint_data`/`get_mint_owner_and_additional_data` (rpc/src/parsed_token_accounts.rs) and in `get_token_account_balance` (rpc/src/rpc.rs), verify `mint_account.owner()` is `spl_token_interface::id()` or `spl_token_2022_interface::id()` (or matches the token account's own owner program) before unpacking it as a `Mint` and using its `decimals`/extension data; return an error (or fall back to raw/binary encoding) if the ownership check fails.

### Proof of Concept
```rust
// rpc/src/parsed_token_accounts.rs (test module) or rpc/src/rpc.rs test module
#[test]
fn test_mint_owner_not_validated() {
    let rpc = RpcHandler::start();
    let bank = rpc.working_bank();

    // "Mint" placeholder owned by an unrelated/non-token program, decimals = 0
    let fake_mint_pubkey = Pubkey::new_unique();
    let mut mint_data = vec![0; Mint::get_packed_len()];
    let mint = Mint { decimals: 0, is_initialized: true, ..Mint::default() };
    Mint::pack(mint, &mut mint_data).unwrap();
    let fake_mint_account = AccountSharedData::from(Account {
        lamports: 1,
        data: mint_data,
        owner: system_program::id(), // NOT a token program
        ..Account::default()
    });
    bank.store_account(&fake_mint_pubkey, &fake_mint_account);

    // Real token account, mint field points at fake_mint_pubkey, real decimals elsewhere = 9
    let token_account_pubkey = Pubkey::new_unique();
    let mut account_data = vec![0; TokenAccount::get_packed_len()];
    let token_account = TokenAccount {
        mint: fake_mint_pubkey,
        owner: Pubkey::new_unique(),
        amount: 1_000_000_000,
        state: TokenAccountState::Initialized,
        ..TokenAccount::default()
    };
    TokenAccount::pack(token_account, &mut account_data).unwrap();
    let token_account_shared = AccountSharedData::from(Account {
        lamports: 1,
        data: account_data,
        owner: spl_token_interface::id(),
        ..Account::default()
    });
    bank.store_account(&token_account_pubkey, &token_account_shared);

    // Expect: either an error/rejection, or decimals tied to a validated mint.
    let result = get_mint_owner_and_additional_data(&bank, &fake_mint_pubkey);
    assert!(result.is_err(), "mint account owned by non-token program must be rejected");
}
```
Expected (current buggy) behavior: the call succeeds and returns `decimals: 0` derived from the unrelated, non-token-owned account, which then propagates into `getTokenAccountBalance`/`getAccountInfo(jsonParsed)` responses. After the fix, this must return an error instead of silently trusting the unrelated mint data.

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}

    pub fn get_token_account_balance(
        &self,
        pubkey: &Pubkey,
        commitment: Option<CommitmentConfig>,
    ) -> Result<RpcResponse<UiTokenAmount>> {
        let bank = self.bank(commitment);
        let account = bank.get_account(pubkey).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find account".to_string())
        })?;

        if !is_known_spl_token_id(account.owner()) {
            return Err(Error::invalid_params(
                "Invalid param: not a Token account".to_string(),
            ));
        }
        let token_account = StateWithExtensions::<TokenAccount>::unpack(account.data())
            .map_err(|_| Error::invalid_params("Invalid param: not a Token account".to_string()))?;
        let mint = &Pubkey::from_str(&token_account.base.mint.to_string())
            .expect("Token account mint should be convertible to Pubkey");
        let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
        let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
        Ok(new_response(&bank, balance))
    }
