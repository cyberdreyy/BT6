### Title
GET /v2/external_initiators leaks `OutgoingToken`, letting any authenticated node user impersonate the node to the external initiator's webhook - ([File: core/web/presenters/external_initiators.go])

### Summary
`NewExternalInitiatorResource` unconditionally copies `ei.OutgoingToken` into the `ExternalInitiatorResource.OutgoingToken` field with no redaction, and `ExternalInitiatorsController.Index` returns this resource for every external initiator on `GET /v2/external_initiators`. `OutgoingToken` is the credential the node uses to authenticate itself when calling out to the external initiator's own callback/webhook URL, so any authenticated caller who can reach this list endpoint can read it and replay it against the EI's endpoint, impersonating the node.

### Finding Description
`ExternalInitiatorResource` in `core/web/presenters/external_initiators.go` declares `OutgoingToken string \`json:"outgoingToken"\`` without `omitempty` or masking, and `NewExternalInitiatorResource` sets it directly from the stored `bridges.ExternalInitiator.OutgoingToken`: [1](#0-0) 

`ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go`) fetches all external initiators from `BridgeORM().ExternalInitiators` and wraps every record with `presenters.NewExternalInitiatorResource`, then returns them via `paginatedResponse`: [2](#0-1) 

By contrast, the `Create` handler correctly returns a one-time `ExternalInitiatorAuthentication` payload containing secrets (`AccessKey`, `Secret`, `OutgoingToken`, `OutgoingSecret`) that is meant to be shown only once at creation time. The `Index`/list path should never re-expose the same outbound secret material, but it does — `OutgoingToken` sits alongside non-sensitive fields (`Name`, `URL`, `AccessKey`, `CreatedAt`, `UpdatedAt`) in the same struct with no gating.

I was unable to fully confirm within the indexed portion of `core/web/router.go` the exact role/permission level enforced on the `GET /v2/external_initiators` route (the file only partially matched in the index), so the precise minimum role required to reach `Index` could not be independently verified from the available context.

### Impact Explanation
Any caller able to invoke `GET /v2/external_initiators` obtains the `OutgoingToken` for every registered external initiator. Since `OutgoingToken` authenticates the Chainlink node's outbound calls to the EI's own URL, possession of it lets an attacker forge requests that appear to originate from the node, i.e., request/credential impersonation against a third-party callback endpoint — this matches the "credential/secret disclosure enabling impersonation" bounty impact class.

### Likelihood Explanation
Exploitation requires only a valid, non-privileged session capable of hitting the list endpoint (no special admin action, no race condition, no additional bypass). Because the presenter always serializes the field for every returned record and `Index` performs no filtering or redaction, the exposure is deterministic and repeatable on every call to the endpoint.

### Recommendation
Remove `OutgoingToken` (and any other outbound-auth secret) from `ExternalInitiatorResource`/`NewExternalInitiatorResource`, or mask it (e.g., return only a redacted placeholder) for list/show operations. Return the plaintext `OutgoingToken` only once, at creation time, via `ExternalInitiatorAuthentication`, consistent with how `AccessKey`'s companion `Secret` is already handled.

### Proof of Concept
1. Create an external initiator via `POST /v2/external_initiators`, capturing the returned `outgoingToken` from the `ExternalInitiatorAuthentication` response.
2. As the same (or another authenticated, lower-privileged) session, call `GET /v2/external_initiators`.
3. Assert in a Go handler-level test (extending `core/web/external_initiators_controller_test.go`) that the JSON response for `Index` contains a non-empty `outgoingToken` field matching the value from step 1 — proving persistent disclosure.
4. Expected fix assertion: after remediation, `outgoingToken` should be absent or a fixed redacted placeholder in the `Index` response while remaining correctly returned once at `Create`.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
