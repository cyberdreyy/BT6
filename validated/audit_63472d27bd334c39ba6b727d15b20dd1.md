## Title
Deleting a multisig member does not purge their stale confirmations on other pending requests, allowing a request to execute below the live-member threshold - ([File: multisig2/src/lib.rs])

## Summary
`delete_member()` in `multisig2/src/lib.rs` only clears confirmations for requests that the deleted member *originally submitted* (`r.member == member`). It does not scan `self.confirmations` to strip that member's signature from *other* pending requests they merely confirmed but did not create. Because `confirm()` counts entries in the per-request `confirmations: LookupMap<RequestId, HashSet<String>>` set toward `num_confirmations` without checking whether each entry still corresponds to a current member of `self.members`, a stale confirmation from a removed member is still counted as valid, letting a request execute with fewer than `num_confirmations` *live* signatures.

## Finding Description
`confirm()` [1](#0-0)  increments/checks the confirmation count purely from the stored `HashSet<String>` for the `request_id`, comparing `confirmations.len() as u32 + 1 >= self.num_confirmations` and then executing the request. It never re-validates that the accounts/keys already present in that set are still in `self.members`.

`delete_member()` [2](#0-1)  removes the member from `self.members` and deletes the access key, and it purges only requests where `r.member == member` (i.e., requests **added** by that member):
```
let request_ids: Vec<u32> = self
    .requests
    .iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
```
It does not iterate `self.confirmations` to remove the deleted member's string key from *other* requests' confirmation sets where that member had only added a confirmation (not authored the request).

Concrete break of the "confirmations counted vs. live members" binding:
1. Multisig has members A, B, C, D with `num_confirmations = 3`.
2. B creates request R (added by B, one implicit signer via `add_request_and_confirm`... or separately confirmed by A too), so `confirmations[R] = {A}` (1 of 3).
3. Members vote to delete A via a separate `DeleteMember{A}` request (which is unrelated to R, so R's confirmation set is left untouched — `delete_member` only purges requests *authored* by A, not R which was authored by B).
4. A is now removed from `self.members`; the multisig legitimately has 3 live members left (B, C, D) and still needs 3 (all of them) for `num_confirmations = 3`.
5. B and C confirm R: `confirmations[R]` becomes `{A, B, C}` → `len() == 2`, so `2 + 1 >= 3` → request executes with only 2 currently-live confirmers (B, C) plus a stale confirmation from A who is no longer a member.

This means the equality the contract is supposed to guarantee — `count(confirmations for R) == count(live members who confirmed R)` — is broken: `confirmations.len()` can exceed the number of live signers once any confirmer is later deleted, allowing threshold to be satisfied by fewer real approvers than `num_confirmations` requires.

## Impact Explanation
This is Critical impact per the custody-binding rules: "a multisig request executed below threshold." An attacker who is one of the remaining members (or colludes with a removed member's prior confirmation) can get transfers, `DeployContract`, `AddKey`, `AddMember`/`DeleteMember`, or `FunctionCall` actions executed with fewer live approvals than `num_confirmations` mandates, effectively lowering the multisig's security threshold without any explicit `SetNumConfirmations` action. This directly threatens custody of NEAR held by the multisig account (arbitrary transfers, adding attacker-controlled keys/members) with less than the configured quorum of genuinely current signers.

## Likelihood Explanation
Requires an unprivileged-to-the-binding but plausible sequence: multiple pending requests coexist (allowed, `active_requests_limit` defaults to 12), one member confirms a request they didn't author, and separately that member is deleted (a routine multisig operation, e.g., key rotation or offboarding a signer) before the first request is fully confirmed. No attacker privilege beyond being an existing member (or exploiting normal member turnover) is needed; this is a realistic operational sequence rather than a contrived edge case, since request cooldown/active-request windows make concurrent open requests common.

## Recommendation
When deleting a member, also purge that member's identifier from every request's confirmation set (not only requests they authored), e.g.:
```rust
let member_key = member.to_string();
for (request_id, mut confirmations) in self.confirmations.iter() {
    if confirmations.remove(&member_key) {
        self.confirmations.insert(&request_id, &confirmations);
    }
}
```
Alternatively/additionally, in `confirm()`, filter `confirmations` to only count entries where `self.members.contains(...)` before comparing against `num_confirmations`, so stale entries never contribute to reaching the threshold.

## Proof of Concept
Conceptual reproduction (matches the multisig2 unit-test harness style already in the file):
1. `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. As B: `add_request_and_confirm(request_R)` → `confirmations[R] = {B}`.
3. As A: `confirm(request_R)` → `confirmations[R] = {A, B}` (len 2).
4. As a quorum of members, execute `DeleteMember{member: A}` via its own request/confirm flow → `self.members = {B, C, D}`, but `confirmations[R]` is untouched (still `{A, B}`) because `delete_member` only purges requests where `r.member == A`, and R was authored by B.
5. As C: `confirm(request_R)` → `confirmations[R].len() == 2` before insert, `2 + 1 >= 3` → request R executes, even though only B and C are live members who actually confirmed (2 of 3 required, with A's stale confirmation counted as the third).

This demonstrates a request executing below the intended live-member confirmation threshold.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
