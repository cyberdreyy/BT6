### Title
`GlobalStateEvaluator::reached_agreement()` uses floor rounding instead of ceiling, letting a single non-majority signer force false "global agreement" on burn view / tx-replay-set / miner state - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement()` computes the 70% threshold with plain integer floor division, while the analogous and consensus-critical `NakamotoBlockHeader::compute_voting_weight_threshold()` in `stackslib/src/chainstate/nakamoto/mod.rs` explicitly rounds up (ceiling) for the same 70% ratio. This mirrors the reported `Pool._amountToBin()` bug class: two code paths that are supposed to compute the identical "70% of total" gate diverge by a rounding unit, so a value that should be *below* threshold is treated as *reaching* it.

### Finding Description
`reached_agreement` is defined as: [1](#0-0) 

```
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```

This performs `(total_weight * 7) / 10` with truncating integer division — i.e. it floors the required weight.

Compare with the block-signature threshold used elsewhere in the same protocol, `NakamotoBlockHeader::compute_voting_weight_threshold`: [2](#0-1) 

which explicitly adds a `ceil` term so that any remainder rounds *up*, guaranteeing at least 70% (not "at least 70%, floor-rounded").

For any `total_weight` where `total_weight * 7` is not evenly divisible by 10 (e.g. `total_weight = 11` → floor threshold = 7, ceiling threshold = 8), `reached_agreement` will report agreement one weight-unit *before* the true 70% threshold is met. Since a signer's own weight can be exactly this 1-unit gap (a normal, non-majority signer weight, not requiring an attacker to control a majority), a single signer's vote can tip `reached_agreement` into returning `true` when the actual supporting weight is strictly less than 70%.

This function backs three separate consensus decisions inside `GlobalStateEvaluator`:
- `determine_latest_supported_signer_protocol_version` (protocol-version agreement), [3](#0-2) 
- `determine_global_burn_view` (agreed current burn view), [4](#0-3) 
- `determine_global_state` (agreed current miner + tx-replay set), [5](#0-4) 

all of which gate what a signer treats as the network's canonical view of the current miner, burn view, and — critically — the **tx replay set**, which directly influences whether a signer will accept/sign a block as canonical versus reject it as conflicting.

### Impact Explanation
Because `determine_global_state` feeds `found_state_view`/`final_replay_set` used to decide the signer's accepted `current_miner` and `tx_replay_set` (see lines 129-156), an attacker-controlled or merely mis-weighted minority of gossip updates could cause a signer to declare "global agreement" on a burn view, miner, or replay set with weight that is actually below the intended 70% supermajority. This can steer the signer's state machine (and hence its willingness to sign blocks) based on a state that does not have true supermajority backing — a violation of the "aggregated-weight vs. verified accepts" equality the task explicitly calls out. Depending on downstream consumption (e.g. deciding tx-replay bounds that affect whether a signer signs a block containing replayed/conflicting transactions), this can manifest as a signer signing under an incorrect global-state assumption. This does not require a majority of signers — only a normal single signer weight aligned with the specific rounding gap.

### Likelihood Explanation
Any `total_weight` value (sum of all registered signer weights for a reward cycle) where `total_weight * 7 % 10 != 0` produces this gap; that is the large majority of practical reward-set weight sums, so the divergence is easily reachable during ordinary reward-cycle configurations, not a contrived edge case. The gap is only 1 unit of weight, so it can be exactly the weight of one small/medium signer submitting a normal StackerDB `StateMachineUpdate` message — well within a single miner/gossip actor's capability and matching the "plus gossip" trigger allowed by scope.

### Recommendation
Make `reached_agreement` use the same ceiling rounding as `compute_voting_weight_threshold`, e.g.:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total_weight = u64::from(self.total_weight);
    let threshold = u64::from(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD);
    let raw = total_weight * threshold;
    let ceil = if raw % 10 == 0 { 0 } else { 1 };
    u64::from(vote_weight) >= raw / 10 + ceil
}
```
and audit `reached_disagreement` for the analogous strict inequality/rounding consistency.

### Proof of Concept
1. Configure a reward set with signer weights summing to `total_weight = 11` (e.g. weights `[4, 4, 3]`).
2. `compute_voting_weight_threshold(11)` (the canonical block-approval threshold) returns `8` (ceil(7.7) = 8), per `stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`.
3. `GlobalStateEvaluator::reached_agreement(7)` returns `true` because `11*7/10 = 7` (floor), per `libsigner/src/v0/signer_state.rs:171-175` — even though `7/11 ≈ 63.6% < 70%`.
4. Two signers with combined weight 7 (e.g. `4 + 3`) submitting matching `StateMachineUpdate`s for a burn view / tx-replay-set / miner is enough to make `determine_global_state`/`determine_global_burn_view` declare "global agreement" reached, despite lacking the true 70% supermajority that the block-signature path enforces elsewhere in the same codebase.     pub fn determine_global_state(&self) -> Option<SignerStateMachine> {

            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set

            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
