Mapping the report's bug class ("a validity check accepts stale/out-of-context authorization data that should have been invalidated") onto the in-scope NEAR contracts, the closest analog is in `multisig2`, where confirmations recorded by a member are never revoked when that member is later removed from the multisig.

### Title
Stale confirmations from removed multisig members remain counted toward the approval threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges requests that the removed member *created*; it does not scrub that member's confirmations from other still-open requests. `confirm()` tallies confirmations purely by set size against `num_confirmations` without re-checking that every recorded confirmer is still in `self.members`, so a former member's stale signature can still count toward executing a request after that member has been removed.

### Finding Description
`confirm()` accepts a confirmation, then checks the total count against the threshold: [1](#0-0) 

Membership removal is handled in `delete_member`, which removes requests keyed by the member being deleted, but filters strictly by `r.member == member` (i.e. only requests the departing member originally *authored*): [2](#0-1) 

Any request that a *different* member authored, but that the soon-to-be-removed member had already confirmed (added their identity string into `self.confirmations.get(&request_id)`), is left untouched. The confirmations `HashSet<String>` for that request keeps the stale entry indefinitely, since nothing else in the contract re-validates confirmer identities against the current `self.members` set (`assert_valid_request` only checks that the *caller* is currently a member, not that *previously stored* confirmations still belong to current members): [3](#0-2) 

This breaks the equality the k-of-n scheme is supposed to guarantee: `confirmations counted == confirmations from live members`. After a removal, that equality becomes `confirmations counted > confirmations from live members`, meaning fewer *actually authorized* signers are needed to push a request past `num_confirmations`.

### Impact Explanation
This falls under the Critical category — "a multisig request executed below threshold." Once a member's stale confirmation persists on an open request, the number of currently-valid members required to reach `num_confirmations` on that request is reduced by one for every stale confirmation retained. In smaller multisigs (e.g., an intended 3-of-4), this can allow execution of arbitrary `MultiSigRequestAction`s — including `Transfer`, `FunctionCall`, `AddKey`, or `DeployContract` — with fewer live authorized approvals than the configured threshold, effectively moving funds or granting privileges without the intended level of authorization.

### Likelihood Explanation
Exploitation requires: (1) a member confirms a request but does not immediately push it to execution (i.e., it stays below threshold), (2) that member is later removed via `DeleteMember`, and (3) the remaining live members confirm the request believing/expecting the threshold reflects live signers. This is a plausible operational sequence for any multisig that rotates membership while requests are pending — no attacker-controlled deployment or foundation cooperation is needed beyond ordinary multisig usage; a member (even one about to be removed, e.g., an outgoing employee or compromised key holder) simply needs to confirm a request before departure.

### Recommendation
In `delete_member`, iterate over all open requests and remove the departing member's entry from every `confirmations` set (not just requests they authored), decrementing effective progress toward threshold. Alternatively, in `confirm()`/`assert_valid_request`, filter `confirmations` to only entries whose identity is currently present in `self.members` before comparing against `num_confirmations`, so stale confirmations from removed members never count.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `B` calls `add_request` for a `Transfer` action (request `X`), not self-confirmed yet, or confirmed by `B` only.
3. `A` calls `confirm(X)` — confirmations for `X` now `{B, A}` (size 2, below threshold 3).
4. Separately, a `DeleteMember { member: A }` request is created and approved by threshold, executing `delete_member` for `A`. Since request `X` was authored by `B` (not `A`), it is not touched; `X`'s confirmations remain `{B, A}` even though `A` is no longer in `self.members`.
5. `C` calls `confirm(X)` — confirmations size becomes 3 (`{B, A, C}`), meeting `num_confirmations = 3`, and `execute_request` runs the `Transfer`.
6. Result: the transfer executed with only two currently-live members (`B`, `C`) genuinely approving, one fewer than the configured 3-of-4 threshold, because `A`'s stale confirmation was still counted after removal. [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
