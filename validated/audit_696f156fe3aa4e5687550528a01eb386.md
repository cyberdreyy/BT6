### Title
Cross-epoch instant-withdraw receipts escape the default haircut and are paid at par from the recovery reserve — ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
Analogous to per-request cookies leaking across a redirect boundary, instant-withdraw receipts are scoped per request-epoch (`instantWithdrawsRequestsByEpoch[user][epoch]`), but the default-finalization basis and the claim path treat the *aggregate* `instantWithdrawsRequests[user]` inconsistently. `defaultPendingClaimBasis()` only includes `instantWithdrawClaimsByEpoch[epochNumber]` — the epoch in which default finalization runs — while the claim path only haircuts receipts tagged to `defaultRecoveryEpoch`. An instant receipt created in an earlier epoch that stayed unfunded (`pendingInstantWithdraws` carries over epoch boundaries since `collectInstantWithdrawFunds` is the only decreaser) is therefore excluded from the haircut basis yet still paid at par via `_transferFundedClaim`, consuming recovery-denominated liquidity.

### Finding Description
- `requestInstantWithdraw` records receipts under `instantWithdrawsRequestsByEpoch[user][currentEpoch]` and bumps the aggregate `instantWithdrawsRequests[user]` and `pendingInstantWithdraws` (`IdleCreditVault.sol:367-374`).
- `defaultPendingClaimBasis()` adds instant receipts to the default haircut basis only for `instantWithdrawClaimsByEpoch[epochNumber]` at finalization time (`IdleCreditVault.sol:644-648`). Receipts recorded under earlier epochs are omitted from the basis, so no recovery was reserved for them at the haircut price.
- `claimInstantWithdrawRequest` first clears only `instantWithdrawsRequestsByEpoch[user][defaultRecoveryEpoch]` at `defaultRecoveryPrice` (`IdleCreditVault.sol:842-855`), then pays the *entire remaining* aggregate `instantWithdrawsRequests[user]` — which includes pre-default-epoch receipts — at par through `_transferFundedClaim` (`IdleCreditVault.sol:387-392`), which draws on `defaultRecoveryReserve` when nonzero (`IdleCreditVault.sol:897-900`).
- Result: a receipt minted in epoch N, carried unfunded across the epoch boundary, is honored in the defaulted epoch N+k context at 100% while same-context receipts are haircut to `defaultRecoveryPrice`. The par payout consumes the same underlying pool/reserve that backs the haircutted claims, diluting every defaulted-epoch claimant below the intended recovery price — the exact "credential scoped to one context replayed in another" shape of the aiohttp bug.

### Impact Explanation
Direct theft/dilution of recovery funds. Each unit of stale-epoch instant receipt pays out at par instead of `defaultRecoveryPrice/RECOVERY_FULL`, so other claimants and active tranche holders recover strictly less than the finalized recovery price guarantees. With `RECOVERY_FULL`-precision accounting this is a quantifiable shortfall equal to `staleBasis * (1 - defaultRecoveryPrice/RECOVERY_FULL)`.

### Likelihood Explanation
Requires an instant-withdraw request that remains unfunded across at least one `stopEpoch` boundary followed by a borrower default and `finalizeDefaultRecovery`. Unfunded instant receipts persist (`pendingInstantWithdraws` only decreases via `collectInstantWithdrawFunds`), so sequencing around honest manager/borrower calls suffices; an unprivileged lender just needs to hold a stale instant receipt. Caveat: I could not fully verify within the available context whether `IdleCDOEpochVariant` forces instant-queue funding at every stopEpoch — if the CDO always drains `pendingInstantWithdraws` before epoch rollover, the precondition collapses. Confirm with a PoC before reporting.

### Recommendation
Include all unfunded instant receipts in the default haircut basis (e.g., track a global `pendingInstantWithdraws`-denominated basis rather than `instantWithdrawClaimsByEpoch[epochNumber]`), or clear/haircut `instantWithdrawsRequestsByEpoch` entries for every epoch ≤ `defaultRecoveryEpoch` inside `_claimDefaultedInstantWithdrawRequest` instead of letting stale receipts fall through to the par claim path.

### Proof of Concept
Foundry fork sketch (pattern after `test/foundry/IdleCreditVault.t.sol` APR0/default tests):
1. Deposit AA, start epoch 0, `requestInstantWithdraw` for user U; leave it unfunded across `stopEpoch` (borrower does not return instant liquidity).
2. Run epoch 1; borrower defaults → `finalizeDefaultRecovery` with `defaultRecoveryPrice < RECOVERY_FULL`. `defaultPendingClaimBasis` excludes U's epoch-0 receipt.
3. Second instant request in epoch 1 (default epoch) by user V, also unfunded.
4. `claimInstantWithdrawRequest(U)`: V's epoch-1 receipt is haircut; U's epoch-0 receipt pays 1:1 from `defaultRecoveryReserve`/strategy balance.
5. Assert U received `amount` while V received `amount * defaultRecoveryPrice / RECOVERY_FULL`, and assert total paid > reserved recovery → insolvency/dilution.
