### Title
Unbounded `savedCallbacks` map growth via unauthenticated `HandleLegacyUserMessage` flooding causes oldest-first eviction of legitimate cross-user callbacks - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` inserts an entry into `h.savedCallbacks` keyed by attacker-controlled `MessageId` with no allowlist or rate limiting (the code explicitly has a `// TODO: apply allowlist and rate-limiting here` marker), and `pruneCallbacks` only trims the map to `MaxSavedCallbacks/2` periodically (default every 30s), deleting the **oldest** entries first. An unauthenticated attacker who can reach the gateway's user HTTP endpoint can flood it with many uniquely-`MessageId`d, self-signed legacy requests faster than the prune interval, pushing the map past `MaxSavedCallbacks` (default 20000) and causing legitimate, earlier-registered victim callbacks to be silently deleted before the DON responds.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) routes any legacy request (identified by a non-empty `DonId`) through `msg.Validate()` and then calls `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `msg.Validate()` only performs structural/signature-format validation of the message the caller itself crafted and signed — it does not check the sender against any per-DON allowlist, so any external client capable of generating a keypair can produce valid, distinct messages.

Inside `HandleLegacyUserMessage`, after minimal payload checks, the handler unconditionally stores the callback:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
```
with no rate-limiting or allowlist check, as the code itself acknowledges with `// TODO: apply allowlist and rate-limiting here` [2](#0-1) .

`pruneCallbacks` runs on a timer (`CallbackPruneIntervalSec`, default 30s) and, if the map exceeds `MaxSavedCallbacks` (default 20000), sorts all entries by `createdAt` ascending and deletes everything except the newest `maxSize/2`:
```go
sort.Slice(entries, func(i, j int) bool {
    return entries[i].createdAt.Before(entries[j].createdAt)
})
for _, e := range entries[:len(entries)-maxSize/2] {
    delete(h.savedCallbacks, e.id)
    evicted++
}
``` [3](#0-2) 

Because eviction is strictly oldest-first, a victim's legitimately earlier-registered callback is deleted before newer attacker-injected ones, regardless of whose request it is. When the DON later responds to the victim's `MessageId`, `handleWebAPITriggerMessage` does a lookup that will fail (`found=false`), and the response is silently dropped — the callback's `SendResponse` is never invoked:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
if found {
    return savedCb.SendResponse(...)
}
return nil
``` [4](#0-3) 

The victim's HTTP request will hang until its own request context deadline expires (returned as `RequestTimeoutError` by `gateway.ProcessRequest`) instead of receiving the correct answer — a cross-user denial-of-service caused entirely by an unrelated, unprivileged attacker.

### Impact Explanation
This is a Denial of Service against unrelated legitimate users: an unprivileged party can cause other users' in-flight, already-accepted DON requests to be silently discarded, forcing them into timeout instead of a valid response, without needing any credential, allowlist membership, or prior relationship to the victim's DON/workflow. This matches the "isolation violation / cross-user denial-of-service" bounty class (unauthorized effect on another user's request/response due to missing quota/allowlist enforcement).

### Likelihood Explanation
Feasibility is high: the attacker only needs the ability to send valid legacy-format JSON-RPC gateway messages with unique `MessageId`s and a self-generated signature good enough to pass `msg.Validate()`'s structural checks — no DON-side authorization is required at this stage (that TODO is explicitly unimplemented). The only per-request constraint is `len(jsonRequest.ID) <= 200`, which does not meaningfully throttle volume. The attack is bounded only by the 30-second default prune interval and 20000-callback threshold, both attainable by a moderate-volume scripted flood against the gateway's user-facing HTTP port, and is fully repeatable.

### Recommendation
- Implement the pending "apply allowlist and rate-limiting" TODO at `HandleLegacyUserMessage`, applying a per-sender rate limiter before inserting into `savedCallbacks`.
- Change eviction policy to be sender-aware/fair (e.g., cap callbacks per sender, or use a per-user rate limiter/quota) rather than a single global age-sorted trim that penalizes early, legitimate requests during a flood.
- Consider rejecting/backpressuring new `HandleLegacyUserMessage` inserts once the map is already at `MaxSavedCallbacks` rather than silently evicting existing entries.

### Proof of Concept
Go unit test plan in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with `MaxSavedCallbacks` set to a small test value (e.g., 10) and `CallbackPruneIntervalSec` disabled (call `pruneCallbacks()` directly instead of waiting on the ticker).
2. Register one "victim" callback via `HandleLegacyUserMessage` with a distinct `MessageId` and a callback whose `SendResponse` is tracked (e.g., using a channel or mock recording invocation).
3. In a loop, call `HandleLegacyUserMessage` (or directly populate `h.savedCallbacks`) with attacker-generated messages bearing unique `MessageId`s until `len(h.savedCallbacks) > MaxSavedCallbacks`.
4. Invoke `h.pruneCallbacks()`.
5. Assert the victim's `MessageId` is no longer present in `h.savedCallbacks` (`_, found := h.savedCallbacks[victimID]; assert.False(t, found)`).
6. Simulate the DON responding to the victim's original message via `handleWebAPITriggerMessage` and assert `SendResponse` was never called for the victim — demonstrating the dropped response / cross-user DoS.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
