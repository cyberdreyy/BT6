### Title
In-memory replay guard resets on Vault node/process restart, permitting replay of previously-authorized allowlist requests within their expiry window - ([File: core/capabilities/vault/request_replay_guard.go])

### Summary
The Vault capability's `authorizer` deduplicates authorized JSON-RPC requests using an in-memory `RequestReplayGuard` keyed by request digest with an expiry timestamp taken from the allowlist entry (`ExpiryTimestamp`). This guard is purely in-process state, analogous to the SKALE `MessageProxy` counters that reset to zero when a connected chain is removed/reconnected, permitting replayed messages to pass signature checks again.

### Finding Description
`NewAuthorizer` constructs a fresh `RequestReplayGuard` with an empty `seen` map every time an `authorizer` is created: [1](#0-0) 

`AuthorizeRequest` performs `AuthorizeRequest` -> `CheckAndRecord(digest, expiresAt)` and only rejects a request if the digest is present in the guard's in-memory `seen` map and unexpired: [2](#0-1) 

The guard's state lives only in a Go map (`seen map[string]int64`) with no persistence: [3](#0-2) 

The allowlist-based authorization path (`allowListBasedAuth.AuthorizeRequest`) validates a request purely by checking that its digest is currently present in the on-chain `getActiveAllowlistedRequestsReverse` allowlist and that `ExpiryTimestamp` has not passed — it does not itself enforce single-use semantics; that responsibility is delegated entirely to the in-memory `RequestReplayGuard`: [4](#0-3) 

Because the allowlist entry (owner + digest + expiry) remains valid on-chain until its `ExpiryTimestamp` (which can be up to 48 hours in the future, as seen in deployment tooling that sets `ExpiryTimestamp: time.Now().Add(48 * time.Hour)`), any event that clears the in-process `seen` map — a node/process restart of the component holding the `authorizer` (e.g., gateway node handler restart, deploy, crash-and-recover, or DON node re-launch) — causes the guard to "forget" that a given allowlisted request digest was already consumed. A previously captured/observed request (which is not secret — it is validated purely by digest match against a public, on-chain allowlist and does not require possession of any private key) can then be resubmitted and will pass authorization a second time, exactly mirroring the SKALE bug class: state that is supposed to prevent replay resets on a lifecycle event, while the underlying authorization material (equivalent to "old signatures") remains valid.

### Impact Explanation
An unprivileged client that observes/intercepts (or otherwise learns) a previously-authorized allowlisted Vault request (e.g., `SecretsCreate`/`SecretsUpdate`/`SecretsDelete`) can replay it after any restart of the Vault DON node process that resets the replay guard, as long as the on-chain allowlist entry has not yet expired (which may be hours). This can result in unauthorized re-execution of vault operations (secret create/update/delete) bound to the still-valid allowlist entry, since the on-chain allowlist by itself is the only "signature" check and the in-memory guard was the sole barrier to replay.

### Likelihood Explanation
Likelihood is moderate: it requires (1) a restart of the node/process holding the `authorizer` (a routine and expected operational event — deploys, crashes, scaling events, upgrades), and (2) the attacker having previously observed or captured a valid allowlisted request before its expiry. Since allowlist expiry windows are on the order of hours to days, and node restarts happen fairly often in production node fleets, the exposure window is non-trivial but is bounded by the request needing to have been authorized once already and by knowledge of that specific request payload/digest.

### Recommendation
Persist replay-guard state (e.g., in the node's database) instead of relying solely on an in-memory map, so that consumed digests survive process restarts, or bind single-use enforcement to the on-chain workflow registry itself (e.g., have the contract or syncer mark/consume allowlist entries once used, mirroring "once used, always used" semantics) rather than to ephemeral node memory.

### Proof of Concept
1. A workflow owner allowlists a Vault request digest `D` with `ExpiryTimestamp` set far in the future (see `UserAllowlistRequestInput.ExpiryTimestamp`, e.g. `time.Now().Add(48*time.Hour)`).
2. A legitimate client submits the corresponding request; `allowListBasedAuth.AuthorizeRequest` succeeds and `replayGuard.CheckAndRecord(D, expiresAt)` records `D` as seen (`core/capabilities/vault/authorizer.go:109`).
3. An unprivileged observer captures this exact request payload (transport-level observation is out of scope here, but the value of the check is that the request contains no secret binding it to a single use beyond `D`'s presence in `seen`).
4. The Vault DON node process is restarted (deploy/crash/redeploy) — `NewAuthorizer` is invoked again, creating a brand-new, empty `RequestReplayGuard` (`core/capabilities/vault/authorizer.go:90-97`).
5. The observer resubmits the identical request. `allowListBasedAuth.AuthorizeRequest` again finds `D` still present and unexpired in the on-chain allowlist (`core/capabilities/vault/allow_list_based_auth.go:34-77`), and `replayGuard.CheckAndRecord` succeeds because `D` is absent from the freshly-initialized `seen` map — the request is authorized a second time.

**Uncertainty:** I could not fully confirm from the indexed code how frequently/under what exact operational conditions the `authorizer` (and therefore the `RequestReplayGuard`) is re-instantiated in a running Vault DON deployment, nor whether some higher-level component persists/restores replay state across restarts elsewhere in the codebase that wasn't surfaced by search. Additionally, this class of "state resets on restart" issue is much closer to a robustness/replay-window gap than to a directly attacker-triggerable unprivileged bypass without a preceding restart event, so its real-world exploitability depends on operational restart cadence, which I cannot verify from static code alone.

	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")

		return nil, err
	}

type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}
