### Title
Local block-acceptance broadcast is not gated on the local state-machine transition, letting a signer rebroadcast signatures for a block it has already recorded as `GloballyRejected` - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`store_and_process_block_signature` decides to broadcast a block purely from the tallied acceptance signature weight, then attempts `block_info.mark_locally_accepted(true)`. If that transition is rejected by `BlockInfo::check_state` (because the block was already finalized as `GloballyRejected`), the error is swallowed — and in the exact case where the block has already reached consensus, even the warning is suppressed — while the function still unconditionally calls `broadcast_signed_block` with the collected signatures. This mirrors the Union Finance M-13 pattern: a "public"/outer decision path (accept-weight tally) delegates a state mutation to a stricter, terminal-state-aware function (`mark_locally_accepted` via `check_state`/`move_to`), that function correctly refuses because the underlying invariant (`GloballyRejected` is terminal against `GloballyAccepted`/`LocallyAccepted`) forbids it, but the caller ignores the failure and performs the side effect anyway.

### Finding Description
`BlockInfo::check_state` explicitly encodes that once a block state is `GloballyRejected`, it can never move to `LocallyAccepted`/`GloballyAccepted`: [1](#0-0) 
and `move_to` returns `Err` rather than mutating state when `check_state` fails: [2](#0-1) 

`store_and_process_block_signature` decides whether to broadcast solely from the running acceptance-signature weight tally (`total_signature_weight >= min_weight`), independent of the block's current terminal state: [3](#0-2) 

It then calls `mark_locally_accepted(true)`, but any `Err` (the only way this can fail is the terminal-state guard above) is only logged — and is entirely swallowed with no warning at all when `has_reached_consensus()` is already true — after which `insert_block` and `broadcast_signed_block` both execute unconditionally: [4](#0-3) 

The prior "reject threshold reached" path independently marks a block `GloballyRejected` once ≥30% weight rejects it, using this signer's own locally recorded rejection weight: [5](#0-4) 

Because rejection and acceptance weight are each tallied from independently-arriving `BlockResponse` messages (accept and reject are stored in separate tables and evaluated on receipt of each new message, not atomically against each other), it is possible for this signer's local view to first cross the 30%+ rejection threshold (finalizing the block as `GloballyRejected` in its own `signerdb`), and only afterward receive/re-process enough acceptance signatures — arriving late, replayed, or produced by signers who re-evaluate a prior rejection into an acceptance, a transition the documented state diagram explicitly allows (`LocallyRejected → LocallyAccepted : re-evaluated`) — to also cross the acceptance threshold. In that ordering, `store_and_process_block_signature`'s decision to broadcast fires even though this signer's own database has already recorded the block as terminally rejected, exactly the asymmetric-caller-vs-callee-checks bug class in M-13: the outer function ("debtWriteOff"/acceptance-tally path) proceeds based on its own looser precondition while the inner function ("cancelVouch"/`mark_locally_accepted`) enforces the real invariant and fails — but the failure is discarded instead of aborting the outer action.

### Impact Explanation
This breaks the "rejection vs acceptance" equality the design is built to guarantee (per `docs/signer-flows.md`: "Global states are terminal against each other" and "Adoption is the ground truth"). A signer's `broadcast_signed_block` call feeds the miner/node coordinator (`signer_coordinator.rs`/`stackerdb_listener.rs`) which treats crossing `weight_threshold` as sufficient to accept the block — i.e., a block outcome that this signer's own bookkeeping has finalized as rejected still gets relayed as if accepted, which is squarely the Critical category "a rejection recounted as an accept."

### Likelihood Explanation
No majority-of-signers compromise, private key, or `auth_token` is required — an attacker only needs to influence the *timing/order* in which legitimate `BlockResponse` (accept/reject) gossip messages reach a given signer, e.g. by delaying delivery of some acceptance messages until after the local rejection tally crosses 30%, or by exploiting the explicitly-allowed reject→accept re-evaluation path. This is exactly the kind of "one-slot miner plus gossip"-triggerable race the scope calls out.

### Recommendation
Gate the broadcast on the transition actually succeeding: if `mark_locally_accepted` returns `Err`, abort the broadcast (do not call `insert_block`/`broadcast_signed_block`) whenever the failure is due to the block already being globally finalized in the opposite direction, mirroring the M-13 fix of making the inner state-check authoritative rather than best-effort. Concretely, check `block_info.has_reached_consensus()` (or match on the specific state) *before* deciding to broadcast, and return early without broadcasting if the block is already `GloballyRejected`.

### Proof of Concept
1. Signer S receives enough `BlockRejection` responses for a proposal to cross the 30%+ blocking-minority threshold; `handle_block_rejection`-path code marks the block `GloballyRejected` in S's `signerdb` (lines 2313-2341).
2. Due to network delay/reordering (or a subsequent re-evaluation flip by some signers from reject to accept), S later receives/processes `BlockAcceptance` messages that cross the 70% weight threshold in `store_and_process_block_signature` (lines 2494-2523).
3. `mark_locally_accepted(true)` is called; `check_state` correctly returns `false` (state is `GloballyRejected`), so `move_to` returns `Err`, and because `has_reached_consensus()` is already `true`, even the warning is suppressed (lines 2525-2532).
4. Execution falls through to `insert_block` and unconditionally to `broadcast_signed_block`, relaying the accepted-signature set for a block S's own database has recorded as globally rejected (lines 2533-2538).

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
