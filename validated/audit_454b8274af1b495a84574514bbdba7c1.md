### Title
Pprof debug routes reachable by any authenticated view/run-role user without admin role check - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` registers `/v2/debug/pprof/*` handlers inside the `authv2` group, which only requires `auth.Authenticate` (valid session or API token), with no `auth.RequiresAdminRole` (or any role) wrapper on the individual pprof routes, unlike nearly every other sensitive endpoint in the same group. This allows any authenticated user — including one with only `UserRoleView` or `UserRoleRun` — to hit `/v2/debug/pprof/heap`, `/goroutine`, `/trace`, `/profile`, etc. and dump process memory/goroutine state.

### Finding Description
In `core/web/router.go`, the `authv2` group is created with only base authentication: [1](#0-0) 
Nearly every sensitive route registered inside this group is explicitly wrapped with a role-check middleware, e.g. `auth.RequiresAdminRole`, `auth.RequiresEditRole`, or `auth.RequiresRunRole` (see the `/users`, `/keys/*`, `/transfers/*` routes at lines 251-383). However, the debug/pprof routes are registered via: [2](#0-1) 
which calls: [3](#0-2) 
None of the `pprofGroup.GET/POST` calls in `metricRoutes` wrap the handler with `auth.RequiresAdminRole` or any other role-checking middleware — they inherit only the `authv2` group's base `auth.Authenticate` middleware. This is a genuine inconsistency: the surrounding code pattern in the same function demonstrates that route authors are expected to add per-route role gates for sensitive functionality, and pprof endpoints (which expose full heap dumps, goroutine stacks with potential in-memory secrets/key material, CPU/execution traces, and enable `debug/pprof/cmdline`) are strictly more sensitive than many of the routes that *are* gated (e.g., `/keys/vrf` DELETE requires admin, but full heap dump requires nothing beyond authentication).

An attacker who obtains any valid session cookie or API token for a `UserRoleView`-only user (the lowest privilege role, intended only for read-only dashboard access) can issue `GET /v2/debug/pprof/heap` and receive a full heap dump, or `GET /v2/debug/pprof/goroutine?debug=2` to get full goroutine stack traces — potentially exposing sensitive data held in memory (private keys, session tokens, decrypted secrets) that a view-only user should never be able to access.

### Impact Explanation
This maps to Chainlink's "information disclosure via authorization bypass" impact class: a low-privilege authenticated user gains unauthorized access to sensitive operational data (heap/goroutine dumps) that could contain key material or other secrets resident in memory, and also gains a DoS lever via `/debug/pprof/profile` (CPU profiling blocks briefly) or `/debug/pprof/trace`. It does not grant direct fund movement, but it is a role/authorization-boundary violation exposing internal node runtime state to unprivileged users.

### Likelihood Explanation
Preconditions are minimal: only a valid low-privilege (`view` or `run` role) session or API token is required, no admin credentials or elevated access needed. Since this is a role-check omission (structural, in the route table itself) rather than a runtime condition, it is deterministic and repeatable on every request.

### Recommendation
Wrap the pprof routes registered by `metricRoutes` with `auth.RequiresAdminRole` (consistent with other sensitive debug/administrative endpoints), e.g.:
```go
pprofGroup.GET("/heap", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP)))
```
applied to all handlers in `metricRoutes`.

### Proof of Concept
Handler-level integration test plan (Go, using `httptest` + `gin`):
1. Build the router via `web.NewRouter` (or a minimal harness that calls `v2Routes`) with a mock `AuthenticationProvider`/session store.
2. Create a session for a user with `sessions.UserRoleView` (or `UserRoleRun`).
3. Issue `GET /v2/debug/pprof/heap` with that session's auth cookie.
4. Assert expected behavior: `403 Forbidden` (consistent with other admin-gated routes like `DELETE /v2/keys/eth/:keyID`).
5. Observe actual behavior: `200 OK` with a valid pprof heap dump body, confirming the missing role check.
6. Repeat for `/v2/debug/pprof/goroutine`, `/v2/debug/pprof/trace`, `/v2/debug/pprof/profile` to show the whole `metricRoutes` set is affected.
