Confirmed: there is no path-traversal (zip-slip) protection anywhere in `helpers/archives/zip_extract.go`. The only content check is `errorIfGitDirectory`/`isPathAGitDirectory`, which merely blocks `.git`-prefixed paths and does not restrict `..` traversal or absolute paths. This is in clear contrast to `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, which explicitly resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects paths escaping the extraction root with `strings.HasPrefix(path, e.dir+string(filepath.Separator))`. The legacy zip path (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go` → `archives.ExtractZipArchive`) has no equivalent check, and is wired into both `commands/helpers/cache_extractor.go` and `commands/helpers/artifacts_downloader.go`, both of which extract into the job's working directory (`wd`) obtained from `os.Getwd()`.

### Title
Zip Slip / path traversal in legacy zip extractor allows writing outside the extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` and its helpers (`extractZipFileEntry`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`) use `zip.File.Name` verbatim in `os.MkdirAll(filepath.Dir(file.Name), 0o777)`, `os.Mkdir`, `os.OpenFile`, and `os.Symlink` calls, with zero validation that the resulting path stays inside the extraction root. The only sanitization performed (`errorIfGitDirectory`) targets `.git` paths, not `..` traversal or absolute paths, so a crafted cache/artifact zip entry can create directories and files anywhere the runner process has permission to write.

### Finding Description
`ExtractZipFile` → `ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry [1](#0-0) . `extractZipFile` runs `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to per-type handlers, all operating directly on `file.Name` with no `filepath.Clean`/root-confinement check [2](#0-1) . `extractZipFileEntry` and `extractZipSymlinkEntry` likewise write to `file.Name` unchecked [3](#0-2) . The only content filter, `errorIfGitDirectory`/`isPathAGitDirectory`, only rejects entries whose first path segment (after `filepath.Clean`) is `.git`; it does not detect or block `..` segments or absolute paths [4](#0-3) .

This legacy zip extractor is reachable from `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`, which simply calls `archives.ExtractZipArchive(zr)` with no extraction-root argument or containment check [5](#0-4) . This extractor is selected by `commands/helpers/cache_extractor.go`'s `Execute` (used for `gitlab-runner cache-extractor`, restoring job caches into `wd = os.Getwd()`) and by `commands/helpers/artifacts_downloader.go`'s `Execute` (restoring job artifacts) [6](#0-5) [7](#0-6) . Both extract into the current job working directory with no absolute/`..`-path check on individual zip entries.

By contrast, the sibling tar+zstd extractor for the same class of operation explicitly guards against this: it computes `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any resulting path that isn't prefixed by `e.dir` [8](#0-7) . The zip path has no analogous check, confirming this is a missing check rather than an intentional design decision.

Since a job/pipeline author fully controls the contents of files placed in `cache:paths`/`artifacts:paths` before they're archived, and since archive creation for zip in this codebase (`zip_create.go`) does not appear to canonicalize entry names either, a malicious pipeline (or a compromised dependency introduced into the build) can inject a crafted entry name such as `../../tmp/attacker_dir/payload` or an absolute path into the zip that a later job (same or shared runner/cache) will download and extract, causing `os.MkdirAll` to create a `0o777` directory tree outside the intended extraction root before the payload file itself is written by `extractZipFileEntry`.

### Impact Explanation
On a shared runner/host where the extraction root (job working directory or shared cache directory) is common across jobs/projects, this allows an unprivileged pipeline author to: (1) create world-writable (`0o777`, subject to umask) directory trees outside the job's sandbox, and (2) write/overwrite arbitrary files reachable by the runner process's file permissions, including files in other jobs' or projects' working directories if a shared cache path is used. This is a "file operations must stay within intended build/cache/artifact roots" invariant violation, matching the scoped impact of unauthorized file/directory creation outside job root and potential cross-job disruption.

### Likelihood Explanation
Feasibility is high and fully within an unprivileged pipeline author's control: producing a zip with an attacker-chosen `FileHeader.Name` is trivial with the standard `archive/zip` package, and the vulnerable code path is exercised on every cache restore (`cache_extractor.go`) and artifact download (`artifacts_downloader.go`) that hits the legacy zip extractor. No authentication bypass or extra privilege is required — only the ability to get a crafted zip processed by `ExtractZipFile`/`ExtractZipArchive` (e.g., via a cache archive uploaded by an earlier pipeline stage/job that a subsequent job then restores).

### Recommendation
Add root-confinement validation in `helpers/archives/zip_extract.go`, mirroring `commands/helpers/archive/tarzstd/tarzstd_extractor.go`: resolve each `file.Name` against the intended extraction root with `filepath.Abs(filepath.Join(root, file.Name))`, reject entries whose absolute path does not have the root as a prefix (or use `filepath.Rel` and reject results starting with `..`), and reject absolute/`..`-containing entry names before calling `os.MkdirAll`, `os.Mkdir`, `os.OpenFile`, or `os.Symlink`. Also thread an explicit extraction-root parameter through `ExtractZipFile`/`ExtractZipArchive`/`extractZipFile` instead of relying implicitly on the process's current working directory.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}

	_ = os.Remove(file.Name)

	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
