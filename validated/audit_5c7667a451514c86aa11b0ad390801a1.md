### Title
View-role users can register new WebAuthn/MFA credentials via unrestricted `GET /v2/enroll_webauthn` and `POST /v2/enroll_webauthn` - ([File: core/web/router.go])

### Summary
The `/v2/enroll_webauthn` routes are registered under `authv2` (which only requires a valid authenticated session/token) but are not wrapped with `auth.RequiresEditRole` or `auth.RequiresAdminRole`, unlike nearly every other account/config-modifying route in the same route group. This lets any authenticated user, including one with `UserRoleView`, call `WebAuthnController.BeginRegistration` and `FinishRegistration` to add a new MFA credential to their own account.

### Finding Description
`v2Routes` wires the WebAuthn enrollment endpoints with no role gate: [1](#0-0) 

Compare this to every other mutating endpoint in the same block, which is explicitly wrapped with `auth.RequiresEditRole` or `auth.RequiresAdminRole` (e.g. `POST /users`, `POST /external_initiators`, `POST /bridge_types`): [2](#0-1) 

`WebAuthnController.BeginRegistration` only checks that a user is authenticated (`auth.GetAuthenticatedUser`), it never inspects `user.Role`: [3](#0-2) 

`FinishRegistration` behaves the same way and, upon success, actually persists the new credential to the user's account via `sessions.AddCredentialToUser`: [4](#0-3) 

The role-check helpers `RequiresEditRole` / `RequiresAdminRole` exist and explicitly reject `UserRoleView` (and `UserRoleRun` for edit) with 401/403, but they are simply never applied to these two routes: [5](#0-4) 

Because `Authenticate` (session or token) is the only middleware applied to `authv2`, a session belonging to a `UserRoleView` user passes `auth.GetAuthenticatedUser` successfully and reaches the handler body unimpeded: [6](#0-5) 

### Impact Explanation
This falls under unauthorized account modification / role separation bypass — a view-only user is normally restricted from performing account-mutating actions, yet can enroll a new WebAuthn/MFA authenticator for their own account. While this doesn't compromise other users' data, it violates the intended exact role boundary the codebase otherwise strictly enforces (every comparable mutating endpoint is wrapped with `RequiresEditRole`/`RequiresAdminRole`), and could be leveraged to entrench persistent MFA-based access on a supposedly read-only account, or as a building block if role assignment/token issuance is later mismanaged.

### Likelihood Explanation
Trivial and fully reproducible: any user with a valid session or API token and `UserRoleView` can immediately call `GET /v2/enroll_webauthn` then `POST /v2/enroll_webauthn` with a valid WebAuthn attestation to add a credential — no additional privilege, secret, or race condition needed.

### Recommendation
Wrap both routes with the appropriate role gate, e.g.:
```go
authv2.GET("/enroll_webauthn", auth.RequiresEditRole(wa.BeginRegistration))
authv2.POST("/enroll_webauthn", auth.RequiresEditRole(wa.FinishRegistration))
```
matching the pattern used for `/user/password` and other self-service account-modification endpoints, per whatever the intended role policy is (at minimum exclude `UserRoleView`).

### Proof of Concept
Go handler-level test (in `core/web` test package, similar to existing `webauthn_controller_test.go` if present, or `TestAuth_RequiresEditRole` pattern in `auth_test.go`):
1. Set up a gin router with `authv2.GET("/enroll_webauthn", wa.BeginRegistration)` exactly as in `router.go`.
2. Create a test user with `sessions.UserRoleView` and log in / obtain a valid session cookie via the existing `SessionsController.Create` flow (or directly set `SessionUserKey` in context to a `UserRoleView` user, as done in `auth_test.go` for other role tests).
3. Issue `GET /v2/enroll_webauthn` with the view-role session.
4. Assert response status is `200 OK` and the body contains valid `PublicKeyCredentialCreationOptions` (i.e. successfully begins registration) rather than `401 Unauthorized`/`403 Forbidden`.
5. As a control, repeat the same request against a route wrapped with `auth.RequiresEditRole` (e.g. `/v2/bridge_types` POST) with the same view-role session and assert it returns `401 Unauthorized`, demonstrating the inconsistency.

func (w *WebAuthnController) BeginRegistration(c *gin.Context) {
	ctx := c.Request.Context()
	user, ok := auth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}

	orm := w.App.AuthenticationProvider()
	uwas, err := orm.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %+v", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	options, err := w.inProgressRegistrationsStore.BeginWebAuthnRegistration(*user, uwas, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in BeginWebAuthnRegistration: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	optionsp := presenters.NewRegistrationSettings(*options)

	jsonAPIResponse(c, optionsp, "settings")

func (w *WebAuthnController) FinishRegistration(c *gin.Context) {
	ctx := c.Request.Context()
	user, ok := auth.GetAuthenticatedUser(c)
	if !ok {
		logger.Sugared(w.App.GetLogger()).AssumptionViolationf("failed to obtain current user from context")
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	orm := w.App.AuthenticationProvider()
	uwas, err := orm.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	credential, err := w.inProgressRegistrationsStore.FinishWebAuthnRegistration(*user, uwas, c.Request, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in FinishWebAuthnRegistration: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}

	if sessions.AddCredentialToUser(ctx, w.App.AuthenticationProvider(), user.Email, credential) != nil {
		w.App.GetLogger().Errorf("Could not save WebAuthn credential to DB for user: %s", user.Email)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// Forward registered credentials for audit logs
	credj, err := json.Marshal(credential)
	if err != nil {
		w.App.GetLogger().Errorf("error in Marshal credentials: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}
	w.App.GetAuditLogger().Audit(audit.Auth2FAEnrolled, map[string]any{"email": user.Email, "credential": string(credj)})

// Authenticate is middleware which authenticates the request by attempting to
// authenticate using all the provided methods.
func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// GetAuthenticatedUser extracts the authentication user from the context.
func GetAuthenticatedUser(c *gin.Context) (*clsessions.User, bool) {
	obj, ok := c.Get(SessionUserKey)
	if !ok {
		return nil, false
	}

	user, ok := obj.(*clsessions.User)

	return user, ok
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
