### Title
B20 tokens can be created with `initialAdmin = address(0)`, permanently freezing all future role administration - (File: `crates/common/precompiles/src/b20_factory/logic/v1.rs`)

### Summary
`B20FactoryV1::init_stablecoin` and `init_asset_token` only grant the `DefaultAdmin` role to `common.initial_admin` when that address is non-zero, with no validation that a caller-supplied `initialAdmin` is actually set. A `createB20` transaction can pass `initialAdmin = Address::ZERO`, producing a live token with zero `DEFAULT_ADMIN_ROLE` holders.

### Finding Description
In `FactoryV1::init_stablecoin` and `FactoryV1::init_asset_token`, the admin role grant is conditional and unchecked: [1](#0-0) [2](#0-1) 

`TokenCreateParams::validate()` and `Self::check_version` are the only validations run before dispatching to these functions in `Factory::create_b20`, and neither rejects a zero `initial_admin`: [3](#0-2) 

This behavior is explicitly exercised (and treated as expected) by the existing test `test_create_asset_token_grants_default_admin_role`, whose second half creates a token with `initialAdmin: Address::ZERO` and asserts no `DefaultAdmin` role is ever granted: [4](#0-3) 

Once a token exists with no `DEFAULT_ADMIN_ROLE` holder, every subsequent non-privileged `grantRole`/`revokeRole` call is gated by `ensure_role_admin_mutations_available` plus a `role_admin` lookup requiring the caller to already hold the role's admin role: [5](#0-4) [6](#0-5) 

Because no account holds `DEFAULT_ADMIN_ROLE`, no caller can ever pass this check for that token again. `grant_role_unchecked` (the only privileged bypass) is reachable solely from the factory during the one-shot `initCalls` array executed inside `create_b20` itself: [7](#0-6) 
After the creating transaction completes, there is no remaining code path that can grant any role — `Mint`, `Pause`, `Metadata`, `PolicyAdmin`, or `DefaultAdmin` itself — on that token ever again.

### Impact Explanation
A token deployed via `createB20` with `initialAdmin = address(0)` and no `initCalls` granting roles becomes permanently un-administrable: no account can ever call `grantRole`, `revokeRole`, update metadata/URI, change policy, mint, or pause it going forward, since every privileged mutation path requires either an existing `DEFAULT_ADMIN_ROLE` holder or the one-time factory bootstrap that has already passed. This permanently freezes the token's governance/administrative capabilities (and any capability gated behind a role, e.g. minting or pausing) with no recovery path, matching a permanent freezing-of-functionality impact analogous to the original Gitcoin "program created without admin" issue.

### Likelihood Explanation
Reachable by any unprivileged caller of the public `createB20` precompile entry point (mirrors the original report's "any transaction sender") by simply passing `initialAdmin = address(0)` — no special privileges are required, and nothing in `TokenCreateParams::validate` or `check_version` rejects it. This can happen accidentally (a caller not filling in the field) or be used deliberately to grief/deploy an unusable, but address-reserved, token.

### Recommendation
Reject `initialAdmin == Address::ZERO` in `TokenCreateParams::validate()` (or in `init_stablecoin`/`init_asset_token`) unless `initCalls` is proven to grant `DEFAULT_ADMIN_ROLE` to some other non-zero account, so every created token is guaranteed to have at least one administrator capable of future role management.

### Proof of Concept
1. Call the B20 factory precompile's `createB20` with `variant = ASSET` (or `STABLECOIN`), any valid `name`/`symbol`/`decimals`, `initialAdmin = Address::ZERO`, and `initCalls = []`.
2. `Factory::create_b20` → `init_asset_token` runs; since `common.initial_admin.is_zero()` is true, the `grant_role_unchecked(DefaultAdmin, ...)` branch is skipped entirely (`crates/common/precompiles/src/b20_factory/logic/v1.rs:135-142`).
3. The token is deployed and emits `B20Created`, but `has_role(DefaultAdmin.id(), any_address)` is false for every address, as confirmed by the existing test at `crates/common/precompiles/src/b20_factory/logic/v1.rs:724-761`.
4. Any subsequent call to `grantRole`/`revokeRole` on this token from any address fails `ensure_role_admin_mutations_available`/`role_admin` checks (`crates/common/precompiles/src/b20_asset/logic/v1.rs:461-476`), permanently locking the token's role administration.
