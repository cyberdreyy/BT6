### Title
Floor-rounded 70%/30% thresholds in `GlobalStateEvaluator` diverge from the ceiling-rounded consensus threshold used for block signing, causing signers to capitulate to a miner without a true supermajority - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` and `reached_disagreement` compute the 70%/30% signer-weight thresholds using floor integer division, while the consensus-critical threshold used to actually authorize a block signature, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly rounds *up* (ceiling). These two "70% of weight" computations are supposed to represent the same supermajority concept but round in opposite directions, exactly analogous to the reported Balancer bug where `addLiquidity` rounds up and `removeLiquidity` rounds down for what should be the same price.

### Finding Description
The chain-level/consensus threshold is computed with an explicit ceiling: [1](#0-0) 

This ceiling function is used both by the node (`verify_signer_signatures`) and by the signer itself when deciding it has gathered enough signatures to broadcast a block: [2](#0-1) 

In contrast, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` — used to determine the *signer-local perceived global state* (current miner, burn view, protocol version, tx replay set) — use plain floor division with no ceiling adjustment: [3](#0-2) 

For any `total_weight` not evenly divisible by 10, `floor(total_weight*7/10)` is strictly less than the ceiling value returned by `compute_voting_weight_threshold(total_weight)`. This is the identical class of asymmetric rounding as the Balancer report: two computations meant to express the same "70% supermajority" invariant diverge by up to one weight unit, and this gap is reachable by a byzantine set holding less than a true 70% (ceiling) supermajority.

`reached_agreement` feeds `determine_global_state`, `determine_global_burn_view`, and `determine_latest_supported_signer_protocol_version`: [4](#0-3) [5](#0-4) 

These, in turn, drive `LocalStateMachine::capitulate_miner_view` in `stacks-signer`, which changes a signer's *current_miner* viewpoint (and can mark a sortition's current miner as `InvalidatedBeforeFirstBlock`) whenever `eval.determine_global_burn_view()`/`determine_global_state()` claims agreement has been reached: [6](#0-5) [7](#0-6) [8](#0-7) 

Because `capitulate_miner_view` relies on the floor-rounded `reached_agreement`/`reached_disagreement`, a coalition holding just under the true 70% ceiling threshold (but at or above the floor threshold) can flip a signer's local `current_miner`/burn-view state even though that same weight would not be sufficient to actually get a block *signed and broadcast* under `compute_voting_weight_threshold`/`verify_signer_signatures`. This creates an equality break between "the weight that convinces a signer's state machine a new miner/view is canonical" and "the weight that is actually required to authorize a block for that view" — the two quantities that should be identical (both represent "70% supermajority of the same signer set") but round in opposite directions.

### Impact Explanation
This does not directly forge a signature nor accept an invalid block by itself, but it can wedge/destabilize the signer's local state machine or push it into a state inconsistent with the real consensus threshold: a minority coalition just below the real 70% ceiling can force honest signers to capitulate their local miner/burn view (and even mark the previously-valid miner's sortition as invalidated) prematurely, while the real block-signing threshold has not been met. Depending on timing this can cause signers to stall (waiting on a miner view that never reaches the real threshold to be signed) — a liveness wedge — or to oscillate their local view as different coalitions straddle the floor/ceiling gap on different rounds, since the floor value only differs by at most 1 weight unit from the ceiling and does not require a majority of the full signer set, only of the coalition size relative to `total_weight`. This matches the "signer wedged" / liveness-consequence class called for in the rules, though it stops short of causing an actual invalid/non-canonical block signature, since the terminal signing gate (`store_and_process_block_signature`) still correctly uses the ceiling `compute_voting_weight_threshold`.

### Likelihood Explanation
The divergence is deterministic whenever `total_weight * 7` is not a multiple of 10 — which is the common case for real-world reward sets (arbitrary signer counts/weights), not a contrived edge case. No majority is required, only a coalition whose weight lands in the 1-unit gap between the floor and ceiling thresholds (e.g., `total_weight = 13` → floor threshold 9, ceiling threshold 10). This is a narrower window than a full protocol break, but it is reachable by ordinary reward-set weight distributions without any privileged access.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same ceiling-based rounding as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, call that function directly) so that "70% agreement" as perceived by a signer's local state machine is never satisfied by less weight than would actually be required to sign/broadcast a block for that same view. Likewise align the `30%` blocking-minority computation with `total_weight - compute_voting_weight_threshold(total_weight)` rather than an independent floor division, to avoid a second point of drift.

### Proof of Concept
With `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD == 7` and `total_weight = 13`:
- `compute_voting_weight_threshold(13)`: `13*7=91`, `91 % 10 = 1 ≠ 0` → `ceil=1` → `91/10 + 1 = 10`. Real signing requires weight ≥ 10 (76.9%).
- `reached_agreement` in `libsigner/src/v0/signer_state.rs`: `13*7/10 = 9` (floor, no ceiling) → agreement is claimed at weight ≥ 9 (69.2%).

A coalition controlling weight = 9 (which is *not* enough to ever get a block signed per `compute_voting_weight_threshold`/`verify_signer_signatures`) is sufficient to make `GlobalStateEvaluator::determine_global_burn_view`/`determine_global_state` report agreement, causing `LocalStateMachine::capitulate_miner_view` to switch honest signers' `current_miner` and burn-view state — and potentially mark the prior sortition's miner as `InvalidatedBeforeFirstBlock` — based on a supermajority that is one weight unit short of what the chain-level threshold actually demands.     pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

        let mut burn_blocks = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();

                .or_insert_with(|| 0);

                return Some((burn_block, burn_block_height));

    pub fn capitulate_miner_view(
        &mut self,
        stacks_client: &StacksClient,
        eval: &mut GlobalStateEvaluator,
        signerdb: &mut SignerDb,
        local_update: &StateMachineUpdateMessage,
        tenure_last_block_proposal_timeout: Duration,
    ) -> Option<StateMachineUpdateMinerState> {
        // First always make sure we consider our own viewpoint
        eval.insert_update(
            stacks_client.get_signer_address().clone(),
            local_update.clone(),
        );

        // Determine the current burn block from the local update
        let (current_burn_block, current_burn_block_height) =
            local_update.content.burn_block_view();

        // Determine the global burn view
        let (global_burn_block, global_burn_block_height) = eval.determine_global_burn_view()?;
        if current_burn_block != global_burn_block {
            debug!(
                "Signer State: Burn block mismatch. Cannot capitulate.";
                "current_burn_block" => %current_burn_block,
                "current_burn_block_height" => current_burn_block_height,
                "global_burn_block" => %current_burn_block,
                "global_burn_block_height" => global_burn_block_height,
            );
            // We don't have the majority's burn block yet...will have to wait
            crate::monitoring::actions::increment_signer_agreement_state_conflict(
                crate::monitoring::SignerAgreementStateConflict::BurnBlockDelay,
            );
            return None;
        }
