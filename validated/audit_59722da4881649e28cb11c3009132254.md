### Title
Unbounded recursion via zero-length RLP extension nodes in `TrieNode` causes stack overflow in the fault-proof program - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::open`, `insert`, `delete`, and `unblind` in `crates/proof/mpt/src/node.rs` recursively descend attacker-influenced Merkle Patricia Trie (MPT) node data fetched via a `TrieProvider`/preimage oracle. The RLP decoder for `TrieNode::Extension` accepts a **zero-length prefix**, which is never validated as invalid. Because each `Self::Extension` recursion step in `open`/`insert`/`delete` only advances the target `path` by `prefix.len()` nibbles, a chain of zero-length-prefix `Extension`/`Blinded` nodes lets an attacker force arbitrarily deep, unbounded recursion with no consumption of the traversal path — directly analogous to the CVE-2021-30471 class of bug (uncontrolled recursive call leading to stack overflow from untrusted nested input).

### Finding Description
`TrieNode::decode` (`crates/proof/mpt/src/node.rs:567-604`) dispatches to `try_decode_leaf_or_extension_payload` (lines 439-469) whenever it sees a 2-element RLP list. That function decodes the packed path bytes and only requires `path.first()` to exist — i.e., the RLP-encoded path byte string must be at least 1 byte: [1](#0-0) 

For an "extension-even" prefix byte (`0x00`), `unpack_path_to_nibbles(None, path[1..])` is called with an empty `path[1..]` slice, producing an `Extension { prefix: <0 nibbles>, node }`. Nothing in the decoder rejects a zero-length extension prefix, even though canonical Ethereum MPT encoding never produces one (extensions always compress ≥1 shared nibble).

This zero-length prefix is fatal to the recursive traversal routines, because they only make forward progress by slicing off `prefix.len()` nibbles of the search path: [2](#0-1) 

When `prefix` has length 0, `path.slice(..0) == prefix` is trivially true and `node.open(&path.slice(0..), fetcher)` recurses with the *exact same* remaining path. The only per-call growth is the recursion stack depth (and one `unblind` preimage fetch). The same pattern (`node.insert`, `node.delete`, and the mutually recursive `unblind`→`open`/`insert`/`delete` calls for `Blinded` nodes) exists at: [3](#0-2) [4](#0-3) 

Because each `Blinded` node is only unblinded by fetching its keccak256 preimage from an untrusted `TrieProvider` (the fault-proof preimage oracle), an attacker who can choose the byte content behind arbitrary self-consistent `keccak256` commitments (which they always can, since they pick the plaintext and its hash is whatever it hashes to) can construct an arbitrarily long chain: `Extension(prefix=∅) -> Blinded(h1) -> Extension(prefix=∅) -> Blinded(h2) -> ...`, each `hN` resolving via the preimage oracle to the next zero-length extension. This is functionally identical to `OrderedListWalker::fetch_leaves` in `crates/proof/mpt/src/list_walker.rs:87-129`, which recurses through `Branch`/`Extension`/`Blinded` variants with no depth cap at all.

This code path is exercised by `TrieDB::get_trie_account` in the stateless proof executor, which calls `self.root_node.open(...)` against oracle-fed trie data during fault-proof execution: [5](#0-4) 

Notably, an equivalent depth-limiting protection already exists elsewhere in the codebase for exactly this bug class — `crates/proof/tee/registrar/src/cbor.rs` enforces `MAX_CBOR_NESTING_DEPTH` on its recursive CBOR parser — but no analogous bound exists for `TrieNode` traversal/decoding.

### Impact Explanation
The MPT crate backs the Base fault-proof program's stateless block executor (`base-proof-executor`/`base-proof-mpt`), which is run by dispute-game participants (challengers/defenders) to compute L2 output roots from L1-derived data and preimage-oracle-served trie witnesses (see `crates/proof/client`, `crates/proof/host`). A dispute-game participant who controls or influences the witness/preimage set backing a claimed state root can craft a degenerate trie with a long chain of zero-length-prefix extension/blinded nodes. When an honest party's fault-proof program (either the native Rust prover, the Cannon/MIPS FPVM, or the SP1 zk range/succinct program) attempts to `open`/`insert`/`delete` an account or storage slot along that path, it recurses without bound and crashes with a stack overflow, aborting proof execution. This can prevent the honest party from computing/submitting a valid output root within the dispute window, i.e., a node/proof-program halt during the fault dispute game — potentially enabling an invalid output root to go unchallenged or a valid challenge to fail to complete.

### Likelihood Explanation
Reachability requires the ability to shape the trie witness data (preimages) consumed by the fault-proof program for a specific claimed state, which a dispute-game participant naturally controls when constructing the proof/witness for their side of a dispute. The decoder does not reject the malformed zero-length extension prefix, and no recursion-depth guard exists anywhere in the `open`/`insert`/`delete`/`unblind`/`fetch_leaves` call chains, so exploitation only requires constructing self-consistent keccak256 preimages, which is always possible by choosing content freely.

### Recommendation
- Reject RLP-decoded `Extension` nodes with a zero-length `prefix` in `try_decode_leaf_or_extension_payload` (`crates/proof/mpt/src/node.rs`), matching canonical Ethereum MPT invariants.
- Add an explicit recursion/iteration depth bound (e.g., bounded by the maximum nibble path length, ~64, plus a small safety margin) to `TrieNode::open`, `insert`, `delete`, `collapse_if_possible`, `unblind`, and `OrderedListWalker::fetch_leaves`, returning an error instead of recursing indefinitely, mirroring the `MAX_CBOR_NESTING_DEPTH` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`.
- Consider converting these traversal routines to iterative (loop-based) implementations to remove reliance on the call stack entirely for depth safety in the `no_std` fault-proof program environment.

### Proof of Concept
1. Craft a leaf/blinded node `V` and compute `h0 = keccak256(rlp(V))`.
2. Craft `E0 = Extension{prefix: [] (encoded as path byte 0x00), node: Blinded(h0)}`, compute `h1 = keccak256(rlp(E0))`.
3. Repeat: `E_{i} = Extension{prefix: [] (0x00), node: Blinded(h_{i-1})}`, `h_i = keccak256(rlp(E_i))`, for N iterations large enough to exceed the runtime stack (e.g., tens of thousands for a typical few-MB stack, given each frame's `open`/`unblind` local variables).
4. Populate a preimage store / `TrieProvider` mock so `trie_node_by_hash(h_i)` returns `E_i` for each `i`, with `E_N` as the trie root.
5. Call `TrieNode::new_blinded(h_N).open(&any_path, &fetcher)` (as `TrieDB::get_trie_account` does): each call unblinds, sees an `Extension` with empty prefix, and recurses with the identical `path`, consuming one stack frame per link without terminating until the process stack overflows.     pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

    fn try_decode_leaf_or_extension_payload(buf: &mut &[u8]) -> TrieNodeResult<Self> {
        // Decode the path and value of the leaf or extension node.
        let path = Bytes::decode(buf).map_err(TrieNodeError::RLPError)?;
        let Some(first_byte) = path.first() else {
            return Err(TrieNodeError::InvalidNodeType);
        };
        let first_nibble = first_byte >> NIBBLE_WIDTH;
        let first = match first_nibble {
            PREFIX_EXTENSION_ODD | PREFIX_LEAF_ODD => Some(first_byte & 0x0F),
            PREFIX_EXTENSION_EVEN | PREFIX_LEAF_EVEN => None,
            _ => return Err(TrieNodeError::InvalidNodeType),
        };

        // Check the high-order nibble of the path to determine the type of node.
        match first_nibble {
            PREFIX_EXTENSION_EVEN | PREFIX_EXTENSION_ODD => {
                // Extension node
                let extension_node_value = Self::decode(buf).map_err(TrieNodeError::RLPError)?;
                Ok(Self::Extension {
                    prefix: unpack_path_to_nibbles(first, path[1..].as_ref()),
                    node: Box::new(extension_node_value),
                })
            }
            PREFIX_LEAF_EVEN | PREFIX_LEAF_ODD => {
                // Leaf node
                let value = Bytes::decode(buf).map_err(TrieNodeError::RLPError)?;
                Ok(Self::Leaf { prefix: unpack_path_to_nibbles(first, path[1..].as_ref()), value })
            }
            _ => Err(TrieNodeError::InvalidNodeType),
        }
    }
