### Title
Inconsistent supermajority rounding between `GlobalStateEvaluator` agreement/disagreement checks and the canonical `compute_voting_weight_threshold` used for block approval — ([File: libsigner/src/v0/signer_state.rs])

### Summary
The dust-truncation bug class describes two parallel accounting paths that are supposed to compute the same quantity but apply inconsistent rounding, causing one path to under/over-count relative to the other. The same class of defect exists in this codebase: the canonical supermajority threshold used to approve/verify Nakamoto blocks is computed with **ceiling** division, while the signer-side `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` helpers — which drive the local signer state machine's view of the canonical miner, burn view, and protocol version — use plain **floor** division. These two definitions of "70% supermajority" diverge whenever `total_weight * 7` is not exactly divisible by 10, which is the common case.

### Finding Description
The chain-canonical threshold used both by `NakamotoBlockHeader::verify_signer_signatures` and the `.signers-voting` Clarity contract is computed with an explicit ceiling: [1](#0-0) 

and, consistently, the on-chain aggregate-key voting contract also rounds up: [2](#0-1) 

However, the signer-side `GlobalStateEvaluator` helper functions that decide whether the *signer set* (not the block signatures) has reached agreement/disagreement about global state (current miner, burn view, protocol version, tx-replay set) use a **floor** division with no ceiling adjustment: [3](#0-2) 

For `total_weight = 11`, the canonical (ceiling) threshold is `ceil(11*7/10) = 8`, but `reached_agreement` returns `true` as soon as `vote_weight >= 7` (`floor(11*7/10) = 7`). This is exactly analogous to `_updateTotalSecondaryDebt` failing to apply the same dust-truncation rule that `updateAccountDebt` applies — one code path enforces the "round up to preserve the true 70% supermajority" invariant, the sibling path does not, silently weakening the threshold by up to one unit of weight.

This weaker threshold is used pervasively to determine the local signer's view of global state:
- `determine_latest_supported_signer_protocol_version` (protocol version agreement)
- `determine_global_burn_view` (burn view agreement)
- `determine_global_state` (state-machine/tx-replay-set agreement) [4](#0-3) 

and it also gates `capitulate_miner_view`/`update_protocol_version` in the higher-level `LocalStateMachine`, which is invoked via `eval.reached_disagreement`/`eval.reached_agreement` in `stacks-signer/src/v0/signer_state.rs`.

### Impact Explanation
This falls under the High-impact category "acting on a stale reward set/threshold." Because `reached_agreement` accepts a strictly weaker weight than the canonical ceiling-based threshold used for actual block approval (`compute_voting_weight_threshold`) and for the aggregate-key voting contract, a set of signers whose combined weight satisfies the *weaker* floor threshold but not the *canonical* ceiling threshold will have their `GlobalStateEvaluator` conclude that "global agreement" on a miner/burn-view/protocol-version has been reached, even though that same weight would be insufficient to actually approve a block on-chain. This can cause a signer to capitulate its local miner viewpoint (and thus its willingness to sign/reject proposals from a given miner) based on a quorum that is one unit of weight below what the protocol actually requires, producing a genuine equality break between "the state the signer believes is globally agreed" and "the state that would actually be validated/approved by the chain-level 70% supermajority."

### Likelihood Explanation
This triggers automatically any time `total_weight * 7` is not a multiple of 10 (the overwhelmingly common case for realistic signer-weight distributions), with no majority collusion, malicious signer, or special network condition required — it is a deterministic arithmetic discrepancy baked into the code, triggered by ordinary weight distributions during a single reward cycle.

### Recommendation
Change `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use the same ceiling-division formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (and the `.signers-voting` Clarity contract), so that all three definitions of the 70%/30% supermajority thresholds are numerically identical for the same `total_weight`.

### Proof of Concept
1. Construct a `GlobalStateEvaluator` with `total_weight = 11` (e.g. 11 signers each with weight 1, or any weight distribution summing to 11).
2. Call `evaluator.reached_agreement(7)` — returns `true` (7/11 ≈ 63.6%).
3. Compare against `NakamotoBlockHeader::compute_voting_weight_threshold(11)`, which returns `8` — i.e., the canonical block-approval logic requires 8/11 (≈72.7%) weight to be considered a valid supermajority.
4. Thus a set of signers holding only 7/11 weight is treated by the local `GlobalStateEvaluator` (used for `determine_global_state`, `determine_global_burn_view`, `determine_latest_supported_signer_protocol_version`, and `capitulate_miner_view`) as having reached global agreement, while the same weight would be rejected as insufficient by `verify_signer_signatures`/`compute_voting_weight_threshold` for actual block approval — demonstrating the threshold-equality break.         let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {

        };

            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Determine what the global burn view is if there is one
    pub fn determine_global_burn_view(&self) -> Option<(&ConsensusHash, u64)> {
        let mut burn_blocks = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();

            let entry = burn_blocks
                .entry((burn_block, burn_block_height))
                .or_insert_with(|| 0);
            *entry += weight;
            if self.reached_agreement(*entry) {
                return Some((burn_block, burn_block_height));
            }
        }
        None
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

/// Regression: u32 multiplication in `reached_agreement` wrapped silently in
/// release builds for `total_weight > u32::MAX / 7 ≈ 613_566_756`. With
/// `total_weight = 1_000_000_000` the buggy expression `total_weight * 7 / 10`
/// wrapped to ~270_503_270, allowing roughly 27% of total weight to satisfy
/// the 70% supermajority check. The fix widens to u64 first.
fn reached_agreement_no_u32_overflow() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // Pre-fix wrap landed at 270_503_270; assert that vote_weight at the wrapped
    // value is correctly rejected — i.e., 27% does not satisfy 70%.
    assert!(
        !evaluator.reached_agreement(270_503_270),
        "27% of total_weight must not satisfy the 70% threshold"
    );
    // Boundary: exactly 70% must pass.
    assert!(
        evaluator.reached_agreement(700_000_000),
        "70% of total_weight must satisfy the 70% threshold"
    );
    // Just below 70% must fail.
    assert!(
        !evaluator.reached_agreement(699_999_999),
        "below 70% must not satisfy the threshold"
    );
}
