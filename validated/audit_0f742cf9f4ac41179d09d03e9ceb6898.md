### Title
Coins sent directly to a `staking_contract`/`vesting` resource-account address are permanently unrecoverable — no rescue path exists - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move], [File: aptos-move/framework/aptos-framework/sources/vesting.move])

### Summary
`staking_contract::create_staking_contract` and `vesting::create_vesting_contract` each create a resource account (a normal Aptos account with its own `CoinStore<AptosCoin>`) to host a `StakePool`. The `SignerCapability` for that resource account is stored privately inside the `StakingContract`/`VestingContract` resource and is only ever used internally to call `stake::*_with_cap` functions on the `StakePool`'s own `active`/`inactive`/`pending_active`/`pending_inactive` `Coin<AptosCoin>` fields. Neither `staking_contract.move` nor `vesting.move` exposes any function analogous to the `rescueERC20` in the referenced report to sweep the resource account's plain `CoinStore` balance. Since `aptos_account::transfer`/`deposit_coins` allow *any* unprivileged account to permissionlessly deposit `AptosCoin` into any existing account (including these resource accounts), any coins accidentally (or intentionally) sent directly to a stake-pool resource-account address end up sitting in that account's `CoinStore`, completely outside of the `StakePool`'s internal accounting, and there is no code path — not even a destructive one like "cancel the stream" in the referenced Sherlock finding — that can ever move them out.

### Finding Description
- `create_stake_pool` in `staking_contract.move` creates a resource account and stores its `SignerCapability` inside `StakingContract`; the corresponding `owner_cap: OwnerCapability` is used exclusively to call `stake::add_stake_with_cap`, `stake::unlock_with_cap`, `stake::withdraw_with_cap`, etc. [1](#0-0) 
- All accounting in `staking_contract.move` (`distribute_internal`, `request_commission_internal`, `add_stake`) operates purely on `stake::get_stake`/`stake::withdraw_with_cap`, i.e., the `Coin<AptosCoin>` fields inside the `StakePool` resource, never on the resource account's generic `CoinStore<AptosCoin>` balance. [2](#0-1) 
- `vesting.move` follows the identical pattern: `signer_cap` for the vesting resource account is stored in `VestingContract` and only used to drive `stake`/`staking_contract` operations (`unlock_stake`, `withdraw_stake`, `distribute`, `admin_withdraw`). There is no function that inspects or moves the resource account's own coin balance outside of the stake-pool accounting. [3](#0-2) [4](#0-3) 
- Meanwhile, `aptos_account::deposit_coins`/`transfer` let *anyone* permissionlessly deposit `AptosCoin` into an existing account by auto-registering a `CoinStore` if needed (subject only to the recipient's own opt-out flag, which a resource account never sets). [5](#0-4) 
- Grep across `staking_contract.move` and `vesting.move` confirms there is no `rescue`/`sweep`/`recover` function of any kind in either module — the analog to the Nouns `rescueERC20` function simply does not exist for the streaming/staking token (`AptosCoin`) or any other token accidentally deposited to these resource accounts.

Because the `SignerCapability`/`OwnerCapability` for these pool addresses is never exposed to any external caller (not even the staker/admin), and no framework function reads or transfers the resource account's raw `CoinStore` balance, any `AptosCoin` transferred directly to a `staking_contract` or `vesting` pool address (e.g. via `aptos_account::transfer(sender, pool_address, amount)`) is stranded permanently — it is not reflected in `principal`, `remaining_grant`, `distribution_pool`, or `grant_pool` accounting, and no combination of `unlock_stake`, `distribute`, `terminate_vesting_contract`, or `admin_withdraw` can ever access it, since those functions only operate on amounts inside the `StakePool`'s internal fields, not the account's `CoinStore`.

### Impact Explanation
This causes a **permanent, non-recoverable loss of funds** for any unprivileged party (attacker or accident) that sends `AptosCoin` directly to a `staking_contract`/`vesting` pool resource-account address. Unlike the referenced NounsDAO issue — where the payer at least had an escape hatch via canceling the stream — Aptos's `staking_contract`/`vesting` modules provide *no* escape hatch whatsoever: the funds are permanently locked in the resource account's `CoinStore` with no path to retrieve them, matching the "Permanent lock or non-recoverable loss of claim rights" impact category.

### Likelihood Explanation
The path is trivially reachable by any unprivileged account: knowledge of a public `pool_address` (queryable via `stake_pool_address`/`vesting.move` view functions) plus a single `aptos_account::transfer` call is sufficient. No special privileges, timing, or governance action is required. The likelihood of accidental triggering (e.g., a user mistakenly sending stake top-ups directly instead of via `staking_contract::add_stake`) is realistic given that these resource accounts are ordinary, publicly-visible addresses.

### Recommendation
Add an explicit rescue/sweep entry function to `staking_contract.move` and `vesting.move`, gated to the staker/admin, that uses the internally-held `SignerCapability` to withdraw any `Coin<AptosCoin>` (or other `CoinType`) balance sitting in the resource account's `CoinStore` that is *not* already accounted for by the `StakePool`'s tracked balances (mirroring the corrected `rescueERC20` pattern: only allow withdrawal of the surplus beyond what's already tracked in `principal`/`remaining_grant`/`distribution_pool`/`grant_pool`).

### Proof of Concept
1. Staker creates a staking contract: `staking_contract::create_staking_contract(staker, operator, voter, 100_APT, 10, seed)`, yielding pool address `P` (a resource account with `CoinStore<AptosCoin>` already registered). [1](#0-0) 
2. Anyone (attacker or the staker by mistake) calls `aptos_account::transfer(sender, P, 1000)`, which succeeds because `P` exists and accepts direct transfers. [6](#0-5) 
3. The 1000 octas now sit in `P`'s `CoinStore<AptosCoin>`, invisible to `staking_contract_amounts`, `distribute`, `unlock_stake`, `request_commission`, etc., all of which only read `stake::get_stake(P)` (the `StakePool`'s internal fields). [7](#0-6) 
4. No caller — staker, operator, beneficiary, or admin — can ever retrieve these 1000 octas: there is no function in `staking_contract.move`/`vesting.move` that exposes the resource account's `SignerCapability` to move its raw `CoinStore` balance, and grepping confirms no `rescue`/`sweep`/`recover` function exists in either module.

Note: I was not able to fully trace `stake::initialize_stake_owner` to confirm at which exact point `CoinStore<AptosCoin>` for the resource account gets registered (index truncated before I could view it), but this does not affect the core finding: `aptos_account::deposit_coins` will auto-register the `CoinStore` on first deposit regardless, so the transfer will succeed even if not pre-registered.

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }

    /// Calculate accumulated rewards and commissions since last update.
    fun get_staking_contract_amounts_internal(
        staking_contract: &StakingContract
    ): (u64, u64, u64) {
        // Pending_inactive is not included in the calculation because pending_inactive can only come from:
        // 1. Outgoing commissions. This means commission has already been extracted.
        // 2. Stake withdrawals from stakers. This also means commission has already been extracted as
        // request_commission_internal is called in unlock_stake
        let (active, _, pending_active, _) =
            stake::get_stake(staking_contract.pool_address);
        let total_active_stake = active + pending_active;
        let accumulated_rewards = total_active_stake - staking_contract.principal;
        let commission_amount =
            accumulated_rewards * staking_contract.commission_percentage / 100;

        (total_active_stake, accumulated_rewards, commission_amount)
    }

    fun create_stake_pool(
        staker: &signer,
        operator: address,
        voter: address,
        contract_creation_seed: vector<u8>
    ): (signer, SignerCapability, OwnerCapability) {
        // Generate a seed that will be used to create the resource account that hosts the staking contract.
        let seed =
            create_resource_account_seed(
                signer::address_of(staker), operator, contract_creation_seed
            );

        let (stake_pool_signer, stake_pool_signer_cap) =
            account::create_resource_account(staker, seed);
        stake::initialize_stake_owner(&stake_pool_signer, 0, operator, voter);

        let owner_cap = stake::extract_owner_cap(&stake_pool_signer);

        (stake_pool_signer, stake_pool_signer_cap, owner_cap)

    /// Withdraw all funds to the preset vesting contract's withdrawal address. This can only be called if the contract
    /// has already been terminated.
    public entry fun admin_withdraw(admin: &signer, contract_address: address) acquires VestingContract {
        let vesting_contract = borrow_global<VestingContract>(contract_address);
        assert!(
            vesting_contract.state == VESTING_POOL_TERMINATED,
            error::invalid_state(EVESTING_CONTRACT_STILL_ACTIVE)
        );

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let amount = coin::value(&coins);
        if (amount == 0) {
            coin::destroy_zero(coins);
            return
        };
        aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);

        emit(
            AdminWithdraw {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount,
            },
        );
    }
