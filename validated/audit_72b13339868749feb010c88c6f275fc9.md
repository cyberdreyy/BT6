### Title
Multisig executes requests below live-member threshold due to stale confirmations from deleted members - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member()` only purges confirmations for requests that were *authored* by the removed member. It never scans other members' pending requests to strip out confirmations that the removed member had already cast. Because `confirm()` decides execution purely from the size of the stored confirmation set, a stale confirmation from an already-deleted member is still counted toward `num_confirmations`, letting a request execute with fewer live, currently-authorized members than the configured threshold.

### Finding Description
`confirm()` checks only the cardinality of the `confirmations` set against `num_confirmations`, with no validation that every entry in that set still corresponds to a current member: [1](#0-0) 

`delete_member()` removes the member from `self.members` and cleans up `num_requests_pk`, but the only confirmation cleanup it performs is for requests where `r.member == member` (i.e., requests the deleted member *authored*), not requests they merely *confirmed*: [2](#0-1) 

The invariant the contract is supposed to maintain is:
```
confirmations_counted(request) == number of *current* members who confirmed
```
After a `DeleteMember` action executes, this equality is broken for any other pending request that the removed member had confirmed: the stored `confirmations` set still contains that member's entry, so `confirmations_counted(request) > number of current members who confirmed`.

### Impact Explanation
This lets a `MultiSigRequest` (e.g. a `Transfer` of NEAR out of the multisig account, or a `FunctionCall`) execute with strictly fewer live/authorized confirmations than `num_confirmations` requires. This is a direct violation of the K-of-N threshold guarantee the contract exists to provide — funds can move (or arbitrary actions such as `AddKey`/`FunctionCall` can execute) without the intended number of currently-trusted parties approving. This matches the "Critical" impact class: a multisig request executed below threshold.

### Likelihood Explanation
The sequence requires: (1) a member confirms request X but does not push it over threshold, (2) a separate `DeleteMember` request removing that same member is confirmed and executed, (3) another still-current member confirms X, which now counts the stale confirmation plus the new one to reach threshold. This can arise naturally in normal operational churn (e.g., a compromised or departing member's key is revoked while some of their previously-cast confirmations are still pending elsewhere) — no special privilege beyond being a normal multisig member is needed to trigger the final `confirm()` call that pushes the stale-count request over the threshold. The bug is purely an accounting oversight in `delete_member`, independent of documented initialization or configuration, and reachable through the contract's normal public API (`add_request`, `confirm`, `DeleteMember`).

### Recommendation
When removing a member in `delete_member`, iterate over **all** pending requests' confirmation sets (not just those authored by the removed member) and remove the member's entry from each. Alternatively, re-validate on every `confirm()` call that all entries in the stored `confirmations` set are still contained in `self.members`, discarding stale entries before comparing the count to `num_confirmations`.

### Proof of Concept
1. Initialize multisig with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request(X)` (a `Transfer` request), does not confirm.
3. `B` calls `confirm(X)` → `confirmations(X) = {B}` (size 1, below threshold).
4. `C` calls `confirm(X)` → `confirmations(X) = {B, C}` (size 2, below threshold — one more confirmation needed).
5. Separately, members `A`, `C`, `D` create and fully confirm a `DeleteMember { member: B }` request; it executes, removing `B` from `self.members` and its access key, but `confirmations(X)` still contains `B`'s entry (untouched, since `X` was authored by `A`, not `B`).
6. `D` calls `confirm(X)`: `confirmations(X).len() + 1 == 3 >= num_confirmations`, so `X` executes — even though only `C` and `D` are actually current, live approvers (2 of 4 remaining members), not the required 3. [3](#0-2) [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
