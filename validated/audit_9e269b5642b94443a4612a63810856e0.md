### Title
Unbounded growth of `GitLabClient.clients` cache keyed by per-job token, causing persistent memory/FD leak - ([File: network/gitlab.go])

### Summary
`GitLabClient.getClient` (network/gitlab.go) caches an `*client` (with its own `http.Client`/`http.Transport`) in the `n.clients` map keyed by a string built from `credentials.GetURL()`, `credentials.GetToken()`, `credentials.GetTLSCAFile()`, and `credentials.GetTLSCertFile()`. Since job-scoped requests (`UpdateJob`/`PatchTrace`/artifact and cache calls) use `JobCredentials`, whose `Token` field is the ephemeral, per-job job token issued by GitLab, every processed job produces a distinct cache key. No code path removes entries from `n.clients` after the job finishes, is canceled, or times out.

### Finding Description
`getClient` builds the cache key and inserts a new `*client` on every miss: [1](#0-0) 

The key explicitly includes `credentials.GetToken()`: [2](#0-1) 

`newClient` (network/client.go) allocates a fresh `http.Client`/transport-holding `*client` struct for each cache miss: [3](#0-2) 

`requestCredentials` is the generic interface satisfied by both `RunnerCredentials` (stable, used for `RequestJob`) and `JobCredentials` (per-job, used for `UpdateJob`/`PatchTrace`/artifact/cache network calls): [4](#0-3) 

I searched the entire repository for any eviction/expiry/cleanup logic touching `n.clients` (`evict`, `expire`, `cleanup`, `len(n.clients)`, etc.) and found none in `network/gitlab.go` or `network/client.go`. The only "aging" mechanism present, `withMaxAge`/`ensureTransportMaxAge`, only closes *idle connections* inside an existing `*client`'s transport every `connectionMaxAge` — it does not remove the `*client` entry from the map: [5](#0-4) 

Because GitLab issues a fresh job token per job, and this token is part of the cache key, each job processed by a shared runner leaves a permanent, unreclaimed entry in `n.clients`, regardless of whether the job succeeds, fails, or is canceled.

### Impact Explanation
Over the runner's lifetime, `GitLabClient.clients` grows by one entry per job ever processed by that GitLabClient instance (one per configured runner). Each entry holds an `http.Client`/`http.Transport` (potentially with open idle connections, TLS session state, etc.). This is unbounded memory and file-descriptor growth in the single, shared runner process — a resource-exhaustion condition that persists across and beyond individual job lifetimes, and that can eventually affect the reliability of the runner for all other projects that share it, without requiring any admin misconfiguration.

### Likelihood Explanation
This is fully attacker-reachable by an ordinary CI pipeline author: no special privilege is needed beyond the ability to trigger jobs (a standard capability for any project using a shared runner). The condition is deterministic and repeatable — every additional job token guarantees at least one additional map entry, with no cap, no LRU, no TTL-based removal observed anywhere in `network/gitlab.go` or `network/client.go`.

### Recommendation
Do not use the raw per-job token as (part of) the long-lived cache key, or add bounded lifecycle management to `n.clients`:
- Evict/close the `*client` entry once the job it belongs to completes (hook into job completion in the caller that owns `JobCredentials`), or
- Replace the unbounded `map[string]*client` with a size/time-bounded cache (e.g., LRU with TTL) that closes idle connections and deletes evicted entries, or
- Key the cache on stable per-runner/per-URL/per-TLS-config identity only, and pass the per-job token through the request rather than baking it into the cache key.

### Proof of Concept
Go unit test sketch (extends existing `network/client_test.go` / `network/gitlab_test.go` patterns):
```go
func TestGetClientCacheGrowsUnbounded(t *testing.T) {
    n := &GitLabClient{}
    const jobs = 10000
    for i := 0; i < jobs; i++ {
        creds := common.JobCredentials{
            URL:   "https://gitlab.example.com",
            Token: fmt.Sprintf("job-token-%d", i), // unique ephemeral token per job
        }
        _, err := n.getClient(&creds)
        require.NoError(t, err)
    }
    n.lock.Lock()
    defer n.lock.Unlock()
    // No eviction exists: map size equals number of jobs ever processed.
    assert.Equal(t, jobs, len(n.clients))
}
```
Expected assertion: `len(n.clients) == jobs` after processing `jobs` synthetic job credentials, demonstrating the cache never shrinks regardless of job completion, proving unbounded accumulation.

func (n *GitLabClient) getClient(credentials requestCredentials) (*client, error) {
	n.lock.Lock()
	defer n.lock.Unlock()

	if n.clients == nil {
		n.clients = make(map[string]*client)
	}
	key := fmt.Sprintf(
		"%s_%s_%s_%s",
		credentials.GetURL(),
		credentials.GetToken(),
		credentials.GetTLSCAFile(),
		credentials.GetTLSCertFile(),
	)
	c, ok := n.clients[key]
	if ok {
		return c, nil
	}

	c, err := newClient(
		credentials,
		n.apiRequestsCollector,
		withMaxAge(n.connectionMaxAge),
		withHttpClientOptions(n.httpClientOptions),
		withCertificateDirectory(n.certDirectory),
	)
	if err != nil {
		return nil, fmt.Errorf("new client: %w", err)
	}

	n.clients[key] = c

	return c, nil
}

func (n *client) ensureTransportMaxAge() {
	if n.connectionMaxAge == 0 {
		return
	}

	if n.Transport == nil {
		return
	}

	elapsed := time.Since(n.lastIdleRefresh)
	if elapsed <= n.connectionMaxAge {
		return
	}

	logrus.WithFields(logrus.Fields{
		"elapsed_s": elapsed.Seconds(),
		"max_age_s": n.connectionMaxAge.Seconds(),
	}).Debug("Closing idle connections")
	n.CloseIdleConnections()
	n.lastIdleRefresh = time.Now()
}

func newClient(requestCredentials requestCredentials, collector *APIRequestsCollector, options ...option) (*client, error) {
	url, err := url.Parse(fixCIURL(requestCredentials.GetURL()) + "/api/v4/")
	if err != nil {
		return nil, fmt.Errorf("parse URL: %w", err)
	}

	if url.Scheme != "http" && url.Scheme != "https" {
		return nil, errors.New("only http or https scheme supported")
	}

	c := &client{
		url:      url,
		caFile:   requestCredentials.GetTLSCAFile(),
		certFile: requestCredentials.GetTLSCertFile(),
		keyFile:  requestCredentials.GetTLSKeyFile(),
	}
	c.requester = newRetryRequester(&c.Client, collector)

	for _, o := range options {
		o(c)
	}

	if c.certDirectory != "" {
		host := strings.Split(url.Host, ":")[0]
		c.findCertificate(&c.caFile, host+".crt")
		c.findCertificate(&c.certFile, host+".auth.crt")
		c.findCertificate(&c.keyFile, host+".auth.key")
	}

	return c, nil
}
