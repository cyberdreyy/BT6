### Title
Prefunded AA shares minted at stale pre-default `priceAA` after a defaulted `stopEpoch` — rollback asymmetry between failed stop and post-stop hook - (File: contracts/IdleCDOEpochVariantPrefunded.sol)

### Summary
The kernel bug is an init/destroy asymmetry: `clsact_destroy()` tested whether `{ingress,egress}_entry` were non-NULL, but on a mid-init rollback those pointers still held valid values from the previous instance, so cleanup freed resources belonging to stale state. The credit-vault analog is the pair `_stopEpoch` / `_afterStopEpochWithDuration` in `IdleCDOEpochVariantPrefunded`: `_afterStopEpochWithDuration` mints prefunded AA shares using `priceAA`, which is only refreshed by `_updateAccounting()` inside the success branch of the `try this.getFundsFromBorrower(...)` block. When the borrower pull fails and `_handleBorrowerDefault` runs (the "destroy" path), `priceAA` remains at the pre-stop, pre-loss value — exactly the "valid entry from the previous instance" condition — yet `_afterStopEpochWithDuration` still runs unconditionally from `stopEpochWithDuration` (`contracts/IdleCDOEpochVariant.sol:520-530`).

### Finding Description
In `_stopEpoch` the success path calls `_updateAccounting()` which updates `priceAA`/`priceBB` to reflect the epoch's accrued interest (`contracts/IdleCDOEpochVariant.sol:436`). The catch path calls `_handleBorrowerDefault` and returns with prices untouched (`contracts/IdleCDOEpochVariant.sol:501-505`). `stopEpochWithDuration` then always invokes `_afterStopEpochWithDuration` (`contracts/IdleCDOEpochVariant.sol:529`), which in the prefunded variant does:

- `_mintSharesAtCurrPrice(_prefunded, _queue, AATranche)` — mints `prefunded / priceAA` shares at the stale pre-default price (`IdleCDOEpochVariantPrefunded.sol:85`),
- `mintStrategyTokens(_prefunded)` — creates `_prefunded` strategy-token backing inside NAV (`:86`),
- `processPrefundedDeposits(_prefundedMinted)` — clears the queue's prefunded accounting (`:88`).

The only guard is `_checkNotAllowed(priceAA == 0)` (`:80`), which does not detect a stale but non-zero price — the same class of "tests the wrong predicate" failure as the clsact fix (the correct check is whether *this* stop instance actually refreshed prices, i.e., `!defaulted`, or using a loss-adjusted price).

### Impact Explanation
Two invariant violations follow:

1. **Fair mint/burn / solvency mismatch.** Shares are minted at a NAV-per-share that never priced the default loss, while the strategy tokens minted for them are counted at face value in `getContractValue`. After `finalizeDefault`/recovery pricing, the mismatch between the stale-price share count and the face-value backing is socialized across all AA holders — prefunded claimants either over-dilute the default-recovery claim basis of existing LPs or strand the excess minted NAV, depending on the sign of the pre/post-default price delta. Either way, one side's recovery is reduced by roughly `prefunded × |1 − recoveryMultiplier|`.
2. **One receipt, one payout.** `epochPrefundedDeposits` is cleared in the queue while the shares were priced against the wrong epoch state, so the queue's per-user `epochPrice` distribution no longer reconciles with the minted tranche tokens — a permanent loss or freeze for prefunded depositors' unclaimed recovery.

A KYC-passing lender whose queued deposit was prefunded (a permitted attacker class) is directly affected/affects others; no privileged misbehavior is required — a genuine borrower repayment failure at `epochEndDate` suffices, which is the routine default scenario the code itself anticipates.

### Likelihood Explanation
Requires only (a) prefunded variant with `epochQueue` set, (b) pending `prefundedDepositsToProcess() > 0`, and (c) a borrower `transferFrom` failure during `stopEpochWithDuration` — a normal default, not an exotic sequence. The code comment (`:82`, "`...even if stop defaulted`") confirms the path is exercised; the stale-price use is the defect.

### Recommendation
In `_afterStopEpochWithDuration`, branch on the outcome of the stop: when `defaulted` is true, mint shares at the post-default/recovery price (e.g., defer minting until `finalizeDefaultRecovery` sets the recovery multiplier, or price with `previewLossAdjustedWithdrawFunds`-consistent NAV) rather than the stale `priceAA`; equivalently, make `_mintSharesAtCurrPrice` take an explicit "prices refreshed this call" flag set only on the non-defaulted path — mirroring the kernel's `mini_qdisc_pair_inited` per-instance initialization check.

### Proof of Concept
```solidity
// Foundry fork-style PoC (anvil fork of the prefunded deployment)
// Setup: prefunded variant, epochQueue configured, AA tranche only.

function testPrefundedMintedAtStalePriceOnDefault() external {
    uint256 amount = 3e6;
    address user = makeAddr("prefunded-user");

    vm.prank(manager);
    cdoEpoch.setEpochQueue(address(queue));
    vm.prank(manager);
    queue.setPrefundedDepositWindow(PREFUNDED_DEPOSIT_WINDOW);

    _requestDepositWithUser(user, amount);          // KYC'd lender queues deposit
    uint256 requestEpoch = strategy.epochNumber() + 1;
    _enterPrefundedWindow(PREFUNDED_DEPOSIT_WINDOW);
    vm.prank(manager);
    queue.processDepositsToBorrower();              // prefund reaches borrower

    uint256 stalePriceAA = cdoEpoch.priceAA();      // pre-loss price snapshot

    // Borrower repays less than owed -> getFundsFromBorrower reverts -> default path.
    address borrower = strategy.borrower();
    deal(address(underlying), borrower, 1);         // insufficient repayment
    vm.prank(borrower);
    underlying.approve(address(cdoEpoch), type(uint256).max);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, 0, cdoEpoch.epochDuration(), 0);

    assertTrue(cdoEpoch.defaulted(), "expected default");
    // BUG: hook still ran and minted AA shares to the queue at the stale price.
    assertEq(cdoEpoch.priceAA(), stalePriceAA, "priceAA never refreshed on default path");
    assertEq(queue.epochPrefundedDeposits(requestEpoch), 0, "queue state cleared anyway");
    // Shares minted at stalePriceAA vs strategy tokens minted at face value:
    // recovery is later distributed per-claim-basis, so existing AA holders' recovery
    // is diluted (or prefunded claimants permanently underpaid) by ~amount * (1 - recovery).
}
```
