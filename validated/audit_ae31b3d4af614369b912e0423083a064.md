## Title
Time-based staleness bypasses liveness verification, allowing a signer to sign two conflicting blocks at the same height across tenures - ([File: stacks-signer/src/v0/signer.rs])

## Summary
`Signer::handle_block_pre_commit` guards against double-signing by checking every previously-signed block that conflicts in height (`get_signed_conflicts`), but it only calls the node-verified liveness check (`conflict_still_blocks`) on conflicts that are still "fresh" by a purely local wall-clock heuristic. Once a conflict is older than `tenure_last_block_proposal_timeout`, it is dropped from consideration for cross-tenure conflicts entirely — no query is ever made to confirm the earlier tenure is actually dead/orphaned. This mirrors the external report's flaw: substituting a theoretical/assumed proxy (MCR ratio / elapsed time) for the real, verifiable quantity (available collateral / actual chain liveness), producing a decision that is wrong exactly when the assumption fails.

## Finding Description
In `Signer::handle_block_pre_commit`, after the pre-commit threshold is reached, the signer queries all previously signed blocks at the same or higher height across every tenure: [1](#0-0) 

The only branch that performs a real, node-verified liveness check (`conflict_still_blocks`, which calls `get_sortition_by_burn_hash` / `get_tenure_tip`) is gated by `conflict.last_endorsed > freshness_cutoff`: [2](#0-1) 

`freshness_cutoff` is a pure wall-clock computation (`get_epoch_time_secs() - tenure_last_block_proposal_timeout`), and `last_endorsed` is simply `MAX(signed_self, signed_group)` recorded when the earlier block was signed: [3](#0-2) 

Once a conflict falls outside this local time window, it is excluded from the `conflict_still_blocks` check entirely. The only remaining guard applies solely to conflicts in the **same tenure** as the new proposal: [4](#0-3) 

A conflict recorded in a **different** tenure that has simply aged past the timeout — while its tenure is still fully canonical and its block still reachable on the node's chain — is never re-verified via `conflict_still_blocks`. The signer proceeds straight to `SIGN`. `conflict_still_blocks` itself documents that its purpose is precisely to distinguish "actually dead" from "merely stale": [5](#0-4) 

but the caller only invokes it while the conflict is still fresh, defeating that purpose for the cross-tenure case. The design comment even concedes the assumption is that once stale, "whether this block may replace what another tenure built is settled by the chainstate checks above" — but the earlier chainstate re-check (`check_block_against_signer_db_state`) is documented elsewhere as checking only **one** tenure (parent tenure for tenure-change blocks, own tenure otherwise), so a genuinely live sibling in a third tenure is invisible to both guards once the time window elapses.

## Impact Explanation
This breaks the "no double-signing at the same height" equivocation guard the whole pre-commit/conflict mechanism exists to enforce. If a signer's earlier signature over block A (tenure X, height h) ages past `tenure_last_block_proposal_timeout` while tenure X is still canonical and unresolved (e.g. a stalled/slow miner, network delay, or gossip lag — conditions a single miner can help engineer by delaying block production or tenure-extension), and a different miner subsequently gets a conflicting block B (tenure Y, height h) through the normal pre-commit flow, the signer will sign B without ever asking the node whether A is dead. That produces two independently, validly signed blocks at the same height in different tenures from the same signer — an equivocation/conflicting-signature event, which is explicitly called out as Critical impact ("a signer signing an invalid, non-canonical, or conflicting block").

## Likelihood Explanation
Likelihood is Low-to-Medium: it requires only ordinary network/timing conditions (or a stalling miner) to exceed `tenure_last_block_proposal_timeout` between two tenures competing for the same height, plus another honest majority of signers pre-committing to the second block through the normal path (this is the expected steady-state behavior for a legitimately competing tenure, not an insider requirement). No majority-signer collusion or key compromise is needed — a single miner delaying/timing tenure switches is sufficient to create the stale window this code path relies on.

## Recommendation
Do not use wall-clock freshness alone as a proxy for "conflict is dead" for cross-tenure conflicts. Either always run `conflict_still_blocks` (node-verified) regardless of staleness before signing a cross-tenure conflicting block, or explicitly require a node-confirmed orphaning/liveness answer (not merely elapsed time) before excluding a cross-tenure conflict from the guard, mirroring how `reorg_permit_stands` and `conflict_still_blocks` derive liveness from the node rather than from a timestamp.

## Proof of Concept
1. Signer S validates and signs block A at height h in tenure X (`signed_self`/`signed_group` timestamp recorded as `last_endorsed`).
2. Tenure X stalls (e.g. miner delay, network partition) for longer than `tenure_last_block_proposal_timeout` without the chain advancing past A.
3. `freshness_cutoff` passes `last_endorsed` for A's conflict record: `conflicts.iter().find(...)` at `stacks-signer/src/v0/signer.rs:1403-1411` now evaluates `conflict.last_endorsed > freshness_cutoff` as `false`, so `conflict_still_blocks` is never called for A.
4. A new tenure Y proposes block B at the same height h; enough signers pre-commit (per normal operation, not requiring a compromised majority) and S reaches the pre-commit threshold for B.
5. The same-tenure-only check at `stacks-signer/src/v0/signer.rs:1432-1457` does not match (A is in tenure X, B is in tenure Y), so nothing blocks signing.
6. S signs B at `SIGN` — despite A's tenure X still being canonical and unresolved — producing two valid signer signatures at height h across different tenures from the same signer.

    pub fn get_signed_conflicts(
        &self,
        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,
    ) -> Result<Vec<SignedConflictInfo>, DBError> {
        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,
                MAX(COALESCE(b.signed_self, 0), COALESCE(b.signed_group, 0)) AS last_endorsed,
                st.superseded_by_consensus_hash, st.superseded_by_burn_block_hash
            FROM blocks b
            LEFT JOIN superseded_tenures st ON st.consensus_hash = b.consensus_hash
            WHERE (b.signed_self IS NOT NULL OR b.signed_group IS NOT NULL)
                AND b.stacks_height >= ?1
                AND b.signer_signature_hash != ?2
            ORDER BY b.stacks_height DESC";
        let args = params![
            u64_to_sql(height)?,
            excluded_signer_signature_hash.to_string(),
        ];
        query_rows(&self.db, query, args)
    }
