### Title
`FungibleStakedSui` Redemption Permanently Blocked by Shared `rewards_pool` Drain in Inactive Staking Pools — (`crates/sui-framework/packages/sui-system/sources/staking_pool.move`)

---

### Summary

`redeem_fungible_staked_sui` unconditionally calls `pool.rewards_pool.split(rewards_amount)` with no defensive cap, while the sibling path `withdraw_rewards` (used by regular `StakedSui` holders) explicitly caps the draw with `.min(pool.rewards_pool.value())`. In an inactive staking pool, regular `StakedSui` holders can drain the shared `rewards_pool` to zero while always succeeding (thanks to the cap). Any subsequent `FungibleStakedSui` redemption that computes a non-zero `rewards_amount` from the still-positive exchange rate will then abort, permanently locking the FSS holder's principal inside `fungible_staked_sui_data.principal` with no emergency-exit path.

---

### Finding Description

**Two withdrawal paths share one `rewards_pool` but apply different guards.**

`withdraw_rewards` (called by `request_withdraw_stake` for regular `StakedSui`):

```move
// staking_pool.move:439
reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
pool.rewards_pool.split(reward_withdraw_amount)
```

`redeem_fungible_staked_sui` (the only exit for `FungibleStakedSui` holders):

```move
// staking_pool.move:220-221
let mut sui_out = fungible_staked_sui_data.principal.split(principal_amount);
sui_out.join(pool.rewards_pool.split(rewards_amount));   // NO .min() guard
``` [1](#0-0) [2](#0-1) 

**Why the pool can be drained.** For inactive pools, `request_withdraw_stake` immediately calls `process_pending_stake_withdraw()`, so every regular-staker withdrawal settles in the same transaction. The `.min()` guard lets each such call succeed even when the pool is nearly empty, collectively draining `rewards_pool` to zero. [3](#0-2) 

**Why the exchange rate still shows rewards after the drain.** For inactive pools, `pool_token_exchange_rate_at_epoch` clamps to the deactivation epoch's rate, which was recorded when rewards were still present. No new `deposit_rewards` calls occur after deactivation. So `calculate_fungible_staked_sui_withdraw_amount` computes a positive `rewards_amount` from the stale-but-fixed rate, then `pool.rewards_pool.split(rewards_amount)` aborts because the actual balance is 0. [4](#0-3) [5](#0-4) 

**No emergency exit exists for `FungibleStakedSui`.** Unlike `StakedSui`, which carries its principal as a self-custodied `Balance<SUI>` inside the object, `FungibleStakedSui` holds only a pool-token count (`value: u64`). The principal SUI is pooled inside `fungible_staked_sui_data.principal`. The sole on-chain redemption path is `redeem_fungible_staked_sui`; there is no emergency-unstake equivalent. [6](#0-5) 

The `ValidatorSet` explicitly routes FSS redemptions to inactive pools, confirming this is a supported and expected code path: [7](#0-6) 

The developers are already aware that `rewards_pool` can fall short of the computed amount (the `TODO` comment in `withdraw_rewards`), but the fix was only applied to the `StakedSui` path, not to the `FungibleStakedSui` path. [8](#0-7) 

---

### Impact Explanation

FSS holders in a deactivated staking pool can have their entire staked principal permanently locked inside `fungible_staked_sui_data.principal`. The SUI is not destroyed, but it is inaccessible: the only redemption function aborts, and there is no alternative withdrawal path. This constitutes a **permanent fund lock** matching the HackenProof High/Medium impact class.

---

### Likelihood Explanation

The scenario requires:
1. A validator that was once active and has earned rewards (common).
2. Some stakers converted `StakedSui` → `FungibleStakedSui` before deactivation (the FSS feature is actively promoted).
3. The validator is later removed/deactivated (happens when validators leave the set).
4. Regular `StakedSui` holders withdraw before FSS holders redeem (natural race; regular holders are incentivized to withdraw quickly).

All four conditions are realistic and can occur without any privileged actor. Any ordinary SUI holder who holds a regular `StakedSui` in the same pool can trigger the lock simply by withdrawing their own stake first.

---

### Recommendation

Apply the same defensive cap inside `redeem_fungible_staked_sui` that already exists in `withdraw_rewards`:

```move
// staking_pool.move ~line 221
let rewards_amount = rewards_amount.min(pool.rewards_pool.value());
sui_out.join(pool.rewards_pool.split(rewards_amount));
```

Alternatively, track FSS-attributable rewards separately (analogous to the M-5 fix of separating payout-token accounting from staked-token accounting) so that regular `StakedSui` withdrawals cannot consume rewards that belong to FSS holders.

---

### Proof of Concept

```
Epoch D  : Pool active. sui_balance = 200 SUI, rewards_pool = 50 SUI.
           Exchange rate stored at epoch D: 250 SUI / 200 pool-tokens = 1.25.
           User A holds StakedSui (100 SUI principal, 100 pool-tokens).
           User B holds FungibleStakedSui (value = 100 pool-tokens,
             fungible_staked_sui_data.principal = 100 SUI).

Epoch D+1: Validator deactivated. No further deposit_rewards calls.
           Exchange rate clamped to epoch D value (1.25) forever.

Epoch D+2: User A calls request_withdraw_stake.
             withdraw_rewards computes reward = 25 SUI.
             .min(50) → takes 25 SUI from rewards_pool.
             rewards_pool now = 25 SUI.
           User A calls request_withdraw_stake again (or a second StakedSui holder does).
             withdraw_rewards computes reward = 25 SUI.
             .min(25) → takes 25 SUI from rewards_pool.
             rewards_pool now = 0 SUI.

Epoch D+3: User B calls redeem_fungible_staked_sui.
             calculate_fungible_staked_sui_withdraw_amount:
               total_sui_amount = 1.25 * 100 = 125 SUI
               total_rewards    = 125 - 100  =  25 SUI
               rewards_amount   = 25 SUI
             pool.rewards_pool.split(25)  ← ABORTS (balance = 0)
           User B's 100 SUI principal is permanently locked in
           fungible_staked_sui_data.principal with no exit path.
``` [9](#0-8) [10](#0-9)

public(package) fun redeem_fungible_staked_sui(
    pool: &mut StakingPool,
    fungible_staked_sui: FungibleStakedSui,
    ctx: &TxContext,
): Balance<SUI> {
    let FungibleStakedSui { id, pool_id, value } = fungible_staked_sui;
    assert!(pool_id == object::id(pool), EWrongPool);

    id.delete();

    let latest_exchange_rate = pool.pool_token_exchange_rate_at_epoch(ctx.epoch());
    let fungible_staked_sui_data: &mut FungibleStakedSuiData =
        &mut pool.extra_fields[FungibleStakedSuiDataKey {}];

    let (
        principal_amount,
        rewards_amount,
    ) = latest_exchange_rate.calculate_fungible_staked_sui_withdraw_amount(
        value,
        fungible_staked_sui_data.principal.value(),
        fungible_staked_sui_data.total_supply,
    );

    fungible_staked_sui_data.total_supply = fungible_staked_sui_data.total_supply - value;

    let mut sui_out = fungible_staked_sui_data.principal.split(principal_amount);
    sui_out.join(pool.rewards_pool.split(rewards_amount));

    pool.pending_total_sui_withdraw = pool.pending_total_sui_withdraw + sui_out.value();
    pool.pending_pool_token_withdraw = pool.pending_pool_token_withdraw + value;

    sui_out
}

fun calculate_fungible_staked_sui_withdraw_amount(
    latest_exchange_rate: PoolTokenExchangeRate,
    fungible_staked_sui_value: u64,
    fungible_staked_sui_data_principal_amount: u64, // fungible_staked_sui_data.principal.value()
    fungible_staked_sui_data_total_supply: u64, // fungible_staked_sui_data.total_supply
): (u64, u64) {
    // 1. if the entire FungibleStakedSuiData supply is redeemed, how much sui should we receive?
    let total_sui_amount = latest_exchange_rate.get_sui_amount(
        fungible_staked_sui_data_total_supply,
    );

    // min with total_sui_amount to prevent underflow
    let fungible_staked_sui_data_principal_amount = fungible_staked_sui_data_principal_amount.min(
        total_sui_amount,
    );

    // 2. how much do we need to withdraw from the rewards pool?
    let total_rewards = total_sui_amount - fungible_staked_sui_data_principal_amount;

    // 3. proportionally withdraw from both wrt the fungible_staked_sui_value.
    let principal_withdraw_amount = mul_div!(
        fungible_staked_sui_value,
        fungible_staked_sui_data_principal_amount,
        fungible_staked_sui_data_total_supply,
    );

    let rewards_withdraw_amount = mul_div!(
        fungible_staked_sui_value,
        total_rewards,
        fungible_staked_sui_data_total_supply,
    );

fun withdraw_rewards(
    pool: &mut StakingPool,
    principal_withdraw_amount: u64,
    pool_token_withdraw_amount: u64,
    epoch: u64,
): Balance<SUI> {
    let exchange_rate = pool.pool_token_exchange_rate_at_epoch(epoch);
    let total_sui_withdraw_amount = exchange_rate.get_sui_amount(pool_token_withdraw_amount);
    let mut reward_withdraw_amount = if (total_sui_withdraw_amount >= principal_withdraw_amount) {
        total_sui_withdraw_amount - principal_withdraw_amount
    } else 0;

    // This may happen when we are withdrawing everything from the pool and
    // the rewards pool balance may be less than reward_withdraw_amount.
    // TODO: FIGURE OUT EXACTLY WHY THIS CAN HAPPEN.
    reward_withdraw_amount = reward_withdraw_amount.min(pool.rewards_pool.value());
    pool.rewards_pool.split(reward_withdraw_amount)
}

```text
public(package) fun redeem_fungible_staked_sui(
    self: &mut ValidatorSet,
    fungible_staked_sui: FungibleStakedSui,
    ctx: &TxContext,
): Balance<SUI> {
    let staking_pool_id = fungible_staked_sui.pool_id();

    let validator = if (self.staking_pool_mappings.contains(staking_pool_id)) {
        // This is an active validator.
        let validator_address = self.staking_pool_mappings[staking_pool_id];
        self.get_candidate_or_active_validator_mut(validator_address)
    } else {
        // This is an inactive pool.
        assert!(self.inactive_validators.contains(staking_pool_id), ENoPoolFound);
        self.inactive_validators[staking_pool_id].load_validator_maybe_upgrade()
    };

    validator.redeem_fungible_staked_sui(fungible_staked_sui, ctx)
}
