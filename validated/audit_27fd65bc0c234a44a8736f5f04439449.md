### Title
Any staking-contract recipient can permanently block operator commission and staker stake distribution via unregistered/blocked `CoinStore` - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::distribute_internal` pays out *all* pending recipients (the operator/beneficiary and the staker) from a single shared `distribution_pool` in one all-or-nothing loop, using `aptos_account::deposit_coins` for every recipient. Because Move has no try/catch, if a single deposit aborts, the entire transaction (and thus the whole distribution) reverts — for every recipient, not just the one that failed. This is the exact bug pattern described in the external report: an unprivileged party can make itself un-payable and thereby hold *other parties'* already-earned, already-unlocked funds hostage indefinitely.

### Finding Description
`distribute_internal` withdraws the pool's total withdrawable stake and buys every recipient (staker + operator, or operator's beneficiary) into a single shares distribution, then loops over all shareholders in that pool, calling `aptos_account::deposit_coins` for each: [1](#0-0) 

`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the target account is not registered for the coin and has explicitly disabled direct coin transfers via `set_allow_direct_coin_transfers(account, false)`: [2](#0-1) 

That configuration flag is fully controlled by the account owner themselves: [3](#0-2) 

Because `distribute_internal` is invoked from `distribute`, `request_commission`, `unlock_stake`, and `switch_operator` (i.e. essentially every user-facing entrypoint of the contract), and it always tries to pay out *both* the staker's queued stake withdrawal *and* the operator's commission in the same shares pool/loop: [4](#0-3) [5](#0-4) 

...a staker who deliberately (or an already-set) disables direct-transfer acceptance on their own account permanently blocks `distribute_internal` from completing. Unlike the operator side, which has a `BeneficiaryForOperator` override that can redirect commission payouts to a different address: [6](#0-5) 

there is **no equivalent beneficiary/redirect mechanism for the staker address**. Once the staker is un-payable, the operator has no way to reroute or force payment of their own already-earned, already-unlocked commission — it is stuck in the shared `distribution_pool` forever, exactly mirroring the LAO bug: a party who cannot (or chooses not to) receive funds prevents completely unrelated parties from getting funds that rightfully belong to them, and there is no pull-based fallback to let the unaffected party claim their share independently.

### Impact Explanation
This breaks the "Operator commission ... payout ... corruption that credits the wrong account or traps value" and "Unlock, reactivate, withdraw ... paths must not redirect value or strand it permanently" invariants explicitly called out in the required impact list. The operator's commission (their share of validator rewards) becomes permanently non-withdrawable as soon as the staker's coin store becomes non-receiving, with no recovery path in the current code (no per-recipient pull withdrawal, no beneficiary override for staker). This is a real fund-trapping bug reachable entirely by unprivileged accounts (a staker configuring their own `DirectTransferConfig`), not requiring any admin/governance action or leaked keys.

### Likelihood Explanation
Likelihood is moderate-to-high: any staker can trivially call `aptos_account::set_allow_direct_coin_transfers(false)` on their own account (a normal, unprivileged, publicly available entry function) and simply never register/opt back in, either maliciously to grief the operator, or accidentally (e.g., a smart-contract/resource account staker that never registers for `AptosCoin` and can't call `register` back). The condition is trivial to trigger and persists until the staker re-enables transfers or registers the coin store — something they may refuse to do specifically to hold the operator's commission hostage.

### Recommendation
Adopt a pull pattern for `distribute_internal`, consistent with the resolution the external report ultimately mandated: instead of pushing coins to every shareholder in a single atomic loop, either (1) skip/quarantine a recipient whose deposit fails and continue distributing to the rest (would require restructuring since Move aborts propagate), or (2) credit each shareholder's payable amount into a per-recipient pending-withdrawal record and let each recipient pull their own funds via a separate `withdraw_distribution(recipient)` entry function. This ensures one un-payable recipient cannot block distributions owed to any other party (operator vs. staker) sharing the same `StakingContract`.

### Proof of Concept
1. Staker `S` creates a staking contract with operator `O` and 10% commission via `create_staking_contract`.
2. `S` calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own signer, and never calls `coin::register<AptosCoin>` — perfectly legal, unprivileged self-configuration. [3](#0-2) 
3. Time passes; the stake pool accrues rewards, so operator `O` is entitled to commission.
4. `O` calls `request_commission(operator, staker, operator)`. This first calls `distribute_internal`, which withdraws any already-inactive stake and calls `update_distribution_pool`/loops over shareholders, then tries `aptos_account::deposit_coins(S, ...)` for staker `S`'s queued distribution (if any exists) — or, once `S` calls `unlock_stake` even once to queue any withdrawal, every subsequent `distribute`/`request_commission`/`unlock_stake`/`switch_operator` call will loop through `S` in the same `distribution_pool` and abort. [7](#0-6) 
5. The transaction aborts every time, so `O`'s already-unlocked commission coins remain trapped in the shared `distribution_pool`/stake pool indefinitely, with no beneficiary-redirect mechanism available for the staker side to work around it.

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
