## Analysis [1](#0-0) 

`createDstEscrow` is a fully unprivileged, publicly callable entrypoint. Any taker/resolver can pass an arbitrary `IBaseEscrow.Immutables` struct, including an arbitrary `parameters` blob, and the factory performs **no validation** on its length or contents — it only checks that `msg.value`/token transfer match `immutables.amount`/`safetyDeposit`: [1](#0-0) 

The deployed `EscrowDst` clone stores the immutables hash (including the `parameters` hash) via `ImmutablesLib.hashMem`, so any later call must reuse those exact `parameters`. Both `withdraw` and `publicWithdraw` funnel into the same internal `_withdraw`, which unconditionally decodes fee data from `immutables.parameters` before paying out the maker: [2](#0-1) 

The decoding is done via `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd`, which `revert IndexOutOfRange()` whenever `parameters.length` is smaller than `0x40`/`0x20` bytes respectively: [3](#0-2) 

Since `_withdraw` is shared by `withdraw` (private) and `publicWithdraw` (public, access-token-gated) — see: [4](#0-3) 

a 1-byte `parameters` blob makes **every** withdrawal call revert with `IndexOutOfRange`, regardless of caller or secret validity, for the entire withdrawal/public-withdrawal window. The only surviving path is `cancel()`, which after the `DstCancellation` timelock refunds the deposited token **and safety deposit back to the taker**, not the maker: [5](#0-4) 

So a fully funded destination escrow (correct `amount`, correct token balance) can be rendered permanently un-claimable by the maker purely because of a malformed `parameters` length chosen by the escrow's own creator at `createDstEscrow` time — confirming the question's claim that neither the private nor the public withdrawal path can finalize, and the funds only return via cancellation to the taker who deployed it, not to the maker who was supposed to receive them.

### Title
Unvalidated `parameters` length in `createDstEscrow` permanently bricks both `withdraw` and `publicWithdraw` on `EscrowDst` - (File: `contracts/EscrowDst.sol`, `contracts/libraries/ImmutablesLib.sol`, `contracts/BaseEscrowFactory.sol`)

### Summary
`createDstEscrow` never validates the length/encoding of the attacker-supplied `immutables.parameters` field before funding and deploying an `EscrowDst` clone. `EscrowDst._withdraw`, shared by both `withdraw` and `publicWithdraw`, unconditionally calls `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd` on that field, which revert with `IndexOutOfRange` for any `parameters` shorter than 64/32 bytes. A 1-byte `parameters` blob therefore makes every withdrawal call — private or public — permanently revert for the life of the withdrawal windows.

### Impact Explanation
The maker's intended dst payout becomes permanently unobtainable through either withdrawal path; the only recovery path is `cancel()`, which sends the escrowed token amount and safety deposit back to the **taker**, not the maker. This results in the maker never receiving their destination-side funds while the escrow's original funds are recoverable only by the party that created the malformed escrow — a fund-freeze/misdirection that fits the "permanent freezing of funds" / fund-loss category for the maker's expected settlement.

### Likelihood Explanation
The entrypoint (`createDstEscrow`) is fully permissionless and requires no special privilege — any actor funding a destination escrow can pass a short `parameters` value while otherwise fully complying with the safety-deposit/amount checks, making this trivially reproducible.

### Recommendation
Validate `dstImmutables.parameters.length` (e.g., require it to be exactly `0x80` bytes, matching the four ABI-encoded fee fields) inside `createDstEscrow` before deploying/funding the clone, so malformed metadata is rejected at creation time rather than bricking withdrawal later.

### Proof of Concept
1. Call `createDstEscrow` with a valid `amount`/`safetyDeposit` and correct token funding, but set `immutables.parameters` to a single arbitrary byte (e.g., `hex"00"`).
2. Warp past `DstWithdrawal` and call `EscrowDst.withdraw(secret, immutables)` with the correct secret from the taker — it reverts with `IndexOutOfRange` (parameters.length `1 < 0x40`).
3. Warp past `DstPublicWithdrawal`, mint/hold the access token, and call `publicWithdraw(secret, immutables)` — it also reverts with `IndexOutOfRange`, confirming both private and public paths are bricked.
4. Only after `DstCancellation`, `cancel(immutables)` succeeds, returning `immutables.amount` and the safety deposit to `immutables.taker` — never to the maker. [2](#0-1) [6](#0-5)

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
```
