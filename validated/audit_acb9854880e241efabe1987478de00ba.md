The reported issue is specific to Primitive's AMM fee-growth accumulator pattern, where `feeAmount` (WAD-denominated) is divided by `liquidity` to produce a per-liquidity-unit fee growth value stored in `feeGrowthGlobalAsset`, and later re-multiplied by a WAD liquidity value in `syncPositionFees` to compute `tokensOwedAsset` — a `mulWadDown`/`divWadDown` unit mismatch that never gets rescaled back to token decimals before crediting withdrawable balances.

marginfi-v2 does not use this fee-growth-accumulator-per-unit-of-liquidity architecture at all. Fees here are accrued directly as token-amount-denominated `I80F48` values via `calc_interest_payment_for_period`, which multiplies a dimensionless APR rate by `total_liabilities_amount` — itself derived from `get_liability_amount`, already expressed in the bank's native token-decimal amount space [1](#0-0) . These amounts are stored directly into `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, and `collected_program_fees_outstanding` on the `Bank`, and later withdrawn as-is via `bank.withdraw_spl_transfer` in `lending_pool_collect_bank_fees`, with no intermediate WAD-per-liquidity growth tracker or subsequent liquidity re-multiplication step [2](#0-1) .

Because there is no `feeGrowthGlobal`/`syncPositionFees`-style two-step "divide by liquidity, then re-multiply by liquidity" computation anywhere in the fee-accrual or fee-collection paths, the specific root cause of the Primitive bug (a WAD value being credited and then withdrawn as if it were already in token-decimal units) has no structural analog in this codebase's interest/fee accounting or in the LP share-based deposit/withdraw accounting [3](#0-2) .

/// Calculates the interest payment for a given period `time_delta` in a principal value `value` for interest rate (in APR) `arp`.
/// Result is the interest payment.
fn calc_interest_payment_for_period(apr: I80F48, time_delta: u64, value: I80F48) -> Option<I80F48> {
    if apr.is_zero() {
        return Some(I80F48::ZERO);
    }

    let interest_payment: I80F48 = value
        .checked_mul(apr)?
        .checked_mul(time_delta.into())?
        .checked_div(SECONDS_PER_YEAR)?;

    Some(interest_payment)
}
