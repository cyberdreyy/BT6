### Title
Permissionless front-run of Kamino Farms `harvest_reward` can permanently strand reward tokens in the bank's obligation reward ATA - (File: `programs/marginfi/src/instructions/kamino/harvest_reward.rs`)

### Summary
`kamino_harvest_reward` computes the amount of reward tokens "earned" as a balance delta (`post_transfer_balance - pre_transfer_balance`) taken immediately before and after the CPI to Kamino Farms' `harvest_reward`, and only sweeps that delta to the global fee wallet. If a third party calls Kamino Farms' `harvest_reward` for the same `user_state`/reward mint outside of this narrow window (which the underlying Farms program explicitly allows via its `is_harvesting_permissionless` configuration, evidenced by the `HarvestingNotPermissionlessPayerMismatch` error code), the deposited rewards land in the vault-owned `user_reward_ata` but are never captured by a subsequent legitimate `kamino_harvest_reward` call, because they are already present in `pre_transfer_balance`. Since `user_reward_ata` is a PDA-owned account with no generic sweep path, those tokens become permanently stuck.

### Finding Description
`kamino_harvest_reward` in `programs/marginfi/src/instructions/kamino/harvest_reward.rs` is: [1](#0-0) 

The critical lines are the balance-delta computation: [2](#0-1) 

`user_reward_ata` is an ATA owned by the bank's `liquidity_vault_authority` PDA, not by marginfi's program authority in a way that restricts external interaction with the underlying Kamino Farms `harvest_reward` instruction: [3](#0-2) 

Kamino Farms exposes a farm config flag `updateIsHarvestingPermissionless`, and a distinct error `harvestingNotPermissionlessPayerMismatch` ("Harvesting is not permissionless, payer does not match user state owner"), confirming that when a farm is configured for permissionless harvesting, *any* payer can trigger `harvest_reward` for a given `user_state` (i.e., for the bank's obligation), sending reward tokens straight into `user_reward_ata`: [4](#0-3) 

If such an external, permissionless `harvest_reward` call executes in a prior transaction (a benign "crank" or a deliberate front-run), the reward tokens sit in `user_reward_ata` before marginfi's own `kamino_harvest_reward` executes. On the subsequent marginfi call, `pre_transfer_balance` already includes those funds, so `received = post_transfer_balance - pre_transfer_balance` only reflects the incremental reward accrued during marginfi's own CPI call. The pre-existing balance is never transferred by `cpi_transfer_obligation_owner_to_destination(received)`, which only moves the computed `received` amount: [5](#0-4) 

Because `user_reward_ata` is a PDA-controlled account tied to a specific reward mint that isn't part of marginfi's tracked bank vaults, there is no generic sweep/rescue instruction that can recover these stranded tokens; they must be reflected as a delta at exactly the right time to ever leave the account. This is the same root cause as the referenced report: computing earned rewards as a delta around a permissionless external claim call, instead of sweeping the full balance present after the claim.

### Impact Explanation
Reward tokens intended for distribution to the global fee wallet (and ultimately mrgn users of the bank, per the Kamino integration's reward-distribution plan) can be permanently and durably frozen in `user_reward_ata`. This is a durable freeze/loss-of-value bug: value that should be recoverable by the protocol becomes inaccessible, with no admin or permissionless recovery path shown in the instruction. The financial effect scales with the size and frequency of Kamino farm rewards on wrapped Kamino banks: [6](#0-5) 

### Likelihood Explanation
Likelihood depends on whether the specific Kamino Farms reward configuration in use has `is_harvesting_permissionless` enabled for the relevant `farm_state`. When enabled, triggering the underlying `harvest_reward` CPI target directly (bypassing marginfi's wrapper) requires no special privilege — any payer can call it for the obligation's `user_state`, per the Farms IDL's own permissionless-harvest support and associated error code. This makes the front-run/interleaving trivially reachable whenever that config flag is set, without needing to be a validator, peer, or privileged admin.

### Recommendation
Replace the pre/post balance delta with the full post-claim balance of `user_reward_ata` when computing the amount to sweep in `kamino_harvest_reward`, i.e., after `cpi_harvest_rewards`, read `accessor::amount(&ctx.accounts.user_reward_ata...)` directly (rather than subtracting a stale `pre_transfer_balance`) and pass that entire balance to `cpi_transfer_obligation_owner_to_destination`. This mirrors the confirmed mitigation from the referenced report ("refactoring from a delta of balance to absolute balances") and ensures any reward tokens deposited by third-party permissionless harvest calls are still swept out on the next invocation.

### Proof of Concept
1. Configure (or identify) a Kamino Farms `farm_state` tied to a marginfi Kamino-wrapped bank's obligation with `is_harvesting_permissionless = true`.
2. An attacker/observer directly invokes Kamino Farms' `harvest_reward` (bypassing marginfi) using `user_state` = the bank's obligation user state and `user_reward_token_account` = the bank's `liquidity_vault_authority`-owned `user_reward_ata`. This deposits reward tokens into `user_reward_ata`.
3. Later, marginfi's `kamino_harvest_reward` is called (permissionlessly, by anyone, as intended): `pre_transfer_balance` now already reflects the step-2 deposit at [7](#0-6) .
4. After the internal CPI harvest (`cpi_harvest_rewards`), only newly-accrued rewards since step 3 are counted as `received` at [8](#0-7) , and only that smaller amount is transferred to `destination_token_account` at [9](#0-8) .
5. The tokens deposited in step 2 remain permanently in `user_reward_ata`, uncounted and unsweepable in any subsequent call, since each future call will again only compute the incremental delta from that point forward.

```rust
pub fn kamino_harvest_reward(
    ctx: Context<KaminoHarvestReward>,
    reward_index: u64,
) -> MarginfiResult {
    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())
}
```

```rust
    pub fn cpi_transfer_obligation_owner_to_destination(&self, amount: u64) -> MarginfiResult {
        let program = self.token_program.to_account_info();
        let accounts = TransferChecked {
            from: self.user_reward_ata.to_account_info(),
            to: self.destination_token_account.to_account_info(),
            authority: self.liquidity_vault_authority.to_account_info(),
            mint: self.reward_mint.to_account_info(),
        };
        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);
        let cpi_ctx = CpiContext::new_with_signer(program.key(), accounts, signer_seeds);
        let decimals = self.reward_mint.decimals;
        transfer_checked(cpi_ctx, amount, decimals)?;
        Ok(())
    }
```
