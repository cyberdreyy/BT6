## Title
Interest continues to accrue on a bank while it is Paused, blocking user repayment - (File: `programs/marginfi/src/instructions/marginfi_group/accrue_bank_interest.rs`)

### Summary
Marginfi lets a group admin set an individual bank to the `Paused` operational state, which blocks `LendingAccountRepay`, `LendingAccountWithdraw`, `LendingAccountBorrow`, and deposits on that bank via `validate_bank_state`. However, the permissionless `lending_pool_accrue_bank_interest` instruction only checks the group's *global* pause flag (`is_protocol_paused`), not the individual bank's `operational_state`. This means anyone can keep accruing interest against a bank that is Paused at the bank level, while borrowers on that specific bank are simultaneously blocked from repaying — mirroring exactly the reported "interest accrual while VaultController paused" bug class.

### Finding Description
The `LendingAccountRepay` accounts validation calls `validate_bank_state(&bank, InstructionKind::FailsInPausedState)` before `bank.accrue_interest(...)` runs, so a user cannot repay against a Paused bank: [1](#0-0) 

Meanwhile, `LendingPoolAccrueBankInterest`'s account constraints only gate on the group-level pause (`!group.load()?.is_protocol_paused()`) — there is no check of `bank.config.operational_state` at all: [2](#0-1) 

`validate_bank_state` is the only gate that enforces bank-level pause semantics (`InstructionKind::FailsInPausedState`, `FailsInReduceState`, `FailsIfPausedOrReduceState`), and it is never invoked from the accrue-interest instruction path: [3](#0-2) 

Per the project's own documentation, a bank in the Paused state is supposed to halt *all* operations, including repay and liquidate: [4](#0-3) 

Since `accrue_interest` itself performs no bank-state check and just computes elapsed-time-based interest against `total_liability_shares`, calling the permissionless `lending_pool_accrue_bank_interest` instruction on a Paused bank still increases `liability_share_value` (and outstanding fees), even though the affected borrowers cannot call `LendingAccountRepay` to pay it down: [5](#0-4) 

### Impact Explanation
Borrowers on a bank an admin has set to `Paused` (e.g. during an incident investigation) are locked out of `repayUSDi`-equivalent functionality (`LendingAccountRepay`), yet liability continues to compound because any third party can permissionlessly call `lending_pool_accrue_bank_interest` on that same bank. This can push borrower positions toward or past insolvency purely due to interest accrued during a window when they had no means to defend their position, and — matching the original report's exact scenario — since liquidation is also blocked in the Paused state, the position becomes immediately liquidatable the moment the bank is unpaused, causing unwarranted collateral loss.

### Likelihood Explanation
`lending_pool_accrue_bank_interest` is explicitly permissionless (documented as such in `lib.rs`), requires no special authority, and only needs the target bank/group pubkeys — trivial to call on any Paused bank with active liabilities and assets. Any bank admin action that pauses a single bank (a documented, ordinary admin operation, not an edge case) is sufficient to create the window; no attacker collusion or unusual state is required.

### Recommendation
Add a bank-state check to `LendingPoolAccrueBankInterest`'s account validation (or inside `accrue_interest`) that fails when `bank.config.operational_state == BankOperationalState::Paused`, consistent with how `validate_bank_state(..., InstructionKind::FailsInPausedState)` is applied to repay/withdraw/liquidate paths. As the original report recommends, this check should not be a precursor that could itself lock the admin out of un-pausing — keep pause/unpause admin instructions independent of this validation.

### Proof of Concept
1. Admin sets Bank X to `Paused` via `lending_pool_configure_bank` (group-level global pause is NOT engaged).
2. A borrower with an outstanding liability on Bank X calls `LendingAccountRepay` — fails with `BankPaused` because `validate_bank_state` rejects `FailsInPausedState`.
3. Any permissionless caller submits `lending_pool_accrue_bank_interest` for Bank X — this succeeds because its only constraint is `!group.load()?.is_protocol_paused()`, which is `false`/passes since only the bank (not the group) is paused.
4. `bank.accrue_interest` executes normally, increasing `liability_share_value` for all borrowers on Bank X, including the one blocked from repaying in step 2.
5. Repeat step 3 over time; when admin unpauses Bank X, the borrower's position may already be underwater and immediately liquidatable, despite having been unable to repay during the pause window.

    let mut bank = ctx.accounts.bank.load_mut()?;

#[derive(Debug, Clone, Copy)]
pub enum InstructionKind {
    /// Only fails if the bank is in `BankKilledByBankruptcy`, technically doesn't exist (yet)
    Unrestricted,
    /// E.g. withdraw, repay
    FailsInReduceState,
    /// E.g. liquidation
    FailsInPausedState,
    /// E.g. borrow, deposit
    FailsIfPausedOrReduceState,
}

// TODO remove redundant checks for these elsewhere in the program (they are nested many laters deep
// in various value delta functions)
/// Validate the bank's state does not forbid the execution of an instruction
pub fn validate_bank_state(bank: &Bank, kind: InstructionKind) -> MarginfiResult {
    if bank.config.operational_state == BankOperationalState::KilledByBankruptcy {
        return err!(MarginfiError::BankKilledByBankruptcy);
    }
    // Bank exists but has not completed one-time setup (e.g. JupLend seed deposit). Block every
    // operation until init runs.
    if bank.config.operational_state == BankOperationalState::Uninitialized {
        return err!(MarginfiError::BankUninitialized);
    }

    match kind {
        InstructionKind::FailsInReduceState if bank.config.operational_state.is_reduce_only() => {
            return err!(MarginfiError::BankReduceOnly);
        }

        InstructionKind::FailsInPausedState
            if bank.config.operational_state == BankOperationalState::Paused =>
        {
            return err!(MarginfiError::BankPaused);
        }

        InstructionKind::FailsIfPausedOrReduceState
            if matches!(
                bank.config.operational_state,
                BankOperationalState::Paused
                    | BankOperationalState::ReduceOnly
                    | BankOperationalState::ReduceOnlyWithBorrowingPower
            ) =>
        {
            return match bank.config.operational_state {
                BankOperationalState::Paused => {
                    err!(MarginfiError::BankPaused)
                }
                state if state.is_reduce_only() => {
                    err!(MarginfiError::BankReduceOnly)
                }
                _ => unreachable!(),
            };
        }
        _ => {}
    }

    Ok(())
}

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
