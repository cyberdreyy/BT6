### Title
Unauthenticated pipeline-run resume endpoint allows anyone to inject task results and force-resume suspended jobs - (File: core/web/pipeline_runs_controller.go)

### Summary
This is the same bug class as the Sherlock finding: a privileged, state-changing operation (`Pool.transferLPs` completing an approved-but-discretionary transfer) is reachable by *any* caller instead of only the party that is supposed to control its timing/content. In chainlink's node API, `PipelineRunsController.Resume` performs the analogous "complete a pending, sensitive operation" role for async/bridge pipeline tasks, but it is mounted on the unauthenticated route group, so no session, API token, or external-initiator credential is required to invoke it.

### Finding Description
The `/v2/resume/:runID` route is registered in the `unauthedv2` group, bypassing all authentication middleware (`auth.Authenticate`) applied to the rest of the `/v2` API: [1](#0-0) 

`PipelineRunsController.Resume` accepts a `runID` (parsed as a `uuid.UUID` "taskID") and an arbitrary JSON body decoded into `pipeline.ResumeRequest`, then calls `App.ResumeJobV2`, which flows into `pipeline.Runner.ResumeRun` → `orm.UpdateTaskRunResult`, directly writing attacker-supplied `Value`/`Error` into the suspended pipeline task and, if the task was the last pending one, restarting execution of the entire pipeline run: [3](#0-2) [4](#0-3) [5](#0-4) 

The only "access control" is possession of the `taskID` UUID — there is no verification that the caller is the bridge/adapter that the async task was actually waiting on, nor any session/API-key/EI credential check, unlike every other privileged mutation in the API (which sits behind `auth.Authenticate(...)`, `auth.RequiresRunRole`, etc., as seen in the surrounding `v2Routes` function).

### Impact Explanation
Because this endpoint is completely unauthenticated and only gated by a UUID that may leak (e.g., via logs, bridge callback URLs, external adapter responses, or brute-force since it's just a UUID guess surface shared with many other systems), an unprivileged network client can:
- Inject falsified task output/error into a suspended pipeline run tied to a job (e.g., poisoning oracle observation data before an OCR/Flux Monitor/VRF job pipeline continues), analogous to controlling the timing/outcome of the LP transfer at an "inappropriate time."
- Force-resume/restart pipeline execution at an attacker-chosen moment, disrupting or manipulating job execution flow that legitimate node operators/bridges expect to control exclusively.

This directly matches the accepted impact classes: unauthorized job run/state manipulation via request impersonation, absent any authentication check that should restrict the caller to the specific bridge/adapter completing that async task.

### Likelihood Explanation
The route is unconditionally unauthenticated by design (`unauthedv2` group), so exploitation only requires network reachability to the node's API and knowledge/guessing of a `runID`/task UUID — no credentials needed. Since async bridge adapters are external HTTP endpoints, task UUIDs are plausibly exposed to third parties (or logged) as part of normal async bridge workflows, making this more than a purely theoretical brute-force scenario.

### Recommendation
Require the caller to be the specific external adapter/bridge that the pipeline is awaiting (e.g., by requiring a per-task secret token embedded in the callback URL, or moving this endpoint under bridge/API-token authentication similar to `AuthenticateExternalInitiator`), rather than accepting any unauthenticated caller who supplies a valid `runID`.

### Proof of Concept
1. Identify or guess a suspended pipeline run's `taskID` (UUID) for an async/bridge task awaiting resumption.
2. Send `PATCH /v2/resume/<taskID>` with an arbitrary JSON body (e.g., `{"data":"attacker-controlled-value"}`) — no `Content-Type`/session/API key needed since the route is in `unauthedv2`.
3. `PipelineRunsController.Resume` parses the body via `pipeline.ResumeRequest.ToResult()` and calls `App.ResumeJobV2`, which writes the attacker's value into `pipeline_task_runs` and resumes/restarts the job pipeline if it was the last pending task — all without any authentication check tying the caller to the expected adapter.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
