### Title
Post-default withdraw requests pay 1:1 from `defaultRecoveryReserve` without verifying the reserve was funded — drains recovery owed to defaulted-epoch claimants - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
Analogous to an XML signature-wrapping attack — where the verifier authenticates one element but acts on a different, unsigned element — `IdleCreditVault.requestWithdraw` mints a post-default receipt into `postDefaultRequests` whose backing is never verified, and `_claimPostDefaultWithdrawRequest` then honors that receipt at par by consuming `defaultRecoveryReserve`, the isolated fund priced for defaulted-epoch claimants.

### Finding Description
After `defaultRecoveryFinalized` is set in `finalizeDefaultRecovery`, `defaultRecoveryReserve` holds exactly `recoveredAmount + prefundedInstant + priorReserve`, sized so that `claimBasis * defaultRecoveryPrice` covers all defaulted-epoch receipts and active NAV (`contracts/strategies/idle/IdleCreditVault.sol:686-693`).

The post-default branch of `requestWithdraw` (`:247-257`) burns CDO strategy tokens, mints `_amount` receipt tokens to the user, and stores `postDefaultRequests[_user] = _amount`. The comment says the CDO passes an already-haircut amount, but no underlying ever enters the strategy and no reserve top-up is required at request time.

`_claimPostDefaultWithdrawRequest` (`:760-767`) then does `defaultRecoveryReserve -= amount` via `_transferDefaultRecovery` (`:912-917`) with no check that a matching `reserveDefaultRecovery`/borrower funding occurred. The only reserve-safety guard, `_transferFundedClaim`'s `balance - reserve < amount` check (`:899-905`), protects the funded-claim path, not the reserve-spending path.

The access control is `_onlyIdleCDO`, but the receipt is address-bound to `_user`, so any unprivileged lender who deposits/requests after finalization can claim.

### Impact Explanation
Each unit of an unfunded post-default request steals one unit of `defaultRecoveryReserve` at par, while defaulted-epoch claimants are only owed `defaultRecoveryPrice` per unit. An attacker requesting a post-default withdraw and claiming before the borrower/top-up funds arrive consumes reserve belonging to defaulted receipt holders and active-LP recovery, leaving later claims to underflow/revert — direct theft of unclaimed recovery, up to the attacker's deposit size per request (repeatable across epochs/requests since the guard only checks `postDefaultRequests[_user] != 0` per request).

### Likelihood Explanation
Requires only: pool defaulted and `finalizeDefaultRecovery` executed (honest manager flow), and the CDO permitting post-default `requestWithdraw`/`claimWithdrawRequest` calls — the code path exists specifically to "preserve request/claim UX after default." The attacker is an ordinary KYC'd lender; no privileged role needed. The theft materializes whenever a claim lands before matching reserve funding, which the strategy does not enforce as an ordering or accounting invariant.

### Recommendation
Track funded post-default backing separately (e.g., `postDefaultFunded`) and only permit `_claimPostDefaultWithdrawRequest` payouts up to that funded amount, crediting it in `reserveDefaultRecovery`/`collectWithdrawFunds`; alternatively escrow post-default receipts outside `defaultRecoveryReserve` so unfunded requests cannot consume defaulted-epoch recovery.

### Proof of Concept
Foundry fork sketch:

```solidity
// Pool defaulted; manager calls finalizeDefaultRecovery -> defaultRecoveryReserve = R,
// defaultRecoveryPrice = p < 1e18, defaulted claimants owed R in aggregate.
uint256 reserve0 = strategy.defaultRecoveryReserve();

// Attacker (unprivileged lender post-default):
vm.prank(attacker);
cdoEpoch.requestWithdraw(x, address(AAtranche)); // mints postDefaultRequests[attacker] = x
// No underlying entered the strategy; reserve is still R.

vm.prank(attacker);
cdoEpoch.claimWithdrawRequest(); // _claimPostDefaultWithdrawRequest pays x 1:1 from R

assertEq(strategy.defaultRecoveryReserve(), reserve0 - x);
assertEq(underlying.balanceOf(attacker) - balPre, x);
// Defaulted-epoch claimant's share x * p / 1e18 is now underfunded; their claim reverts
// on reserve underflow or is permanently short by x.
```
