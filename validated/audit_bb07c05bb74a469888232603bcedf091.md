### Title
Unpriced programmable-borrower vault gains let buffer deposits dilute LPs - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`ProgrammableBorrower` records ERC4626 gains earned during the buffer in `bufferedVaultDelta`, but those gains are not represented in the CDO’s tranche price until the following `stopEpoch`. An unprivileged lender can observe the gain, deposit during the reopened buffer window at the old price, and receive a pro-rata share of yield earned before their deposit.

### Finding Description
After a successful programmable-borrower epoch stop, `ProgrammableBorrower.onStopEpoch` stores the current ERC4626 position value as `bufferStartVaultAssets`, while `IdleCDOEpochVariant` unpauses deposits and withdrawal requests for the buffer period. [1](#0-0) [2](#0-1) 

If the external ERC4626 share price increases during that buffer, an attacker can call `depositAA` or `depositBB`. `_deposit` calls `_updateAccounting`, but the vault NAV is based only on `strategyToken` and raw underlying balances; the programmable borrower’s ERC4626 gain is not part of `getContractValue` and does not update tranche prices. [3](#0-2) [4](#0-3) 

When the next epoch starts, `onStartEpoch` computes `bufferedVaultDelta = currentVaultAssets - bufferStartVaultAssets` and carries it into the active epoch. [5](#0-4)  At the following stop, `totalInterestDueNow` includes that delta and the CDO mints strategy tokens for the realized gain before updating tranche prices. [6](#0-5) [7](#0-6) 

The fair-mint invariant is therefore broken: shares minted during the buffer are priced using a NAV that excludes already-earned external-vault PnL, but those shares participate in that PnL when it is crystallized.

### Impact Explanation
An attacker with sufficient temporary capital can capture a pro-rata fraction of pre-existing vault appreciation.

Example:

- CDO principal: `1,000,000 USDC`
- External vault gain during the buffer: `100,000 USDC`
- Attacker deposits: `9,000,000 USDC`
- Ignoring fees and subsequent yield, the attacker owns approximately 90% of the tranche and captures approximately `90,000 USDC` of yield that accrued before their deposit.

This is direct dilution and theft of yield from existing tranche holders. The attacker can request withdrawal after the gain is crystallized and claim through the normal epoch withdrawal process.

### Likelihood Explanation
Likelihood is moderate:

- It requires a deployment using `isProgrammableBorrower`.
- The attacker must satisfy `isWalletAllowed` if Keyring is configured, but any KYC-passing lender qualifies under the threat model.
- No privileged action is required; the attacker only needs to deposit during the normal buffer window after observing external-vault appreciation.
- Deposits intentionally remain available after `stopEpoch`, and programmable borrowers deliberately defer vault PnL to the next `stopEpoch`, creating the stale-price window.
- Capital must remain committed through the next epoch rather than being atomically flash-loan repayable, but the profit scales with the deposit amount and does not require control of the borrower, manager, guardian, or oracle.

### Recommendation
Account for programmable-borrower buffer gains before allowing buffer-period deposits or requests.

Possible approaches:

- Include a reliable, manipulation-resistant estimate of `bufferedVaultDelta`/vault PnL in CDO accounting before minting tranche shares.
- Alternatively, realize or checkpoint programmable-borrower vault PnL into strategy tokens at `onStopEpoch`, before deposits reopen.
- If external-vault valuation cannot safely be included in NAV, pause ordinary deposits while programmable-borrower buffer PnL remains uncrystallized.
- Add regression tests where the ERC4626 price changes between `stopEpoch` and `startEpoch`, followed by a large lender deposit.

### Proof of Concept
A Foundry test can reproduce the dilution by driving the production programmable-borrower flow:

```solidity
function testBufferVaultGainDilutedByLateDeposit() external {
    // Existing LP owns the pool before the first epoch.
    uint256 lpDeposit = 1_000_000e6;
    idleCDO.depositAA(lpDeposit);

    // Honest manager runs epoch 0 to completion.
    startEpoch();
    vm.warp(idleCDO.epochEndDate() + 1);
    stopEpoch();

    // Deposits are now reopened for the buffer.
    assertFalse(idleCDO.paused());

    // External ERC4626 NAV rises while the pool is in the buffer.
    // This is an external market gain, not a deposit into the CDO.
    uint256 vaultGain = 100_000e6;
    increaseErc4626AssetPerShare(vaultGain);

    // The attacker buys shares before the buffer gain is carried into
    // ProgrammableBorrower.bufferedVaultDelta by startEpoch.
    address attacker = makeAddr("attacker");
    uint256 attackerDeposit = 9_000_000e6;
    deal(asset, attacker, attackerDeposit);

    vm.startPrank(attacker);
    IERC20(asset).approve(address(idleCDO), attackerDeposit);
    uint256 attackerShares = idleCDO.depositAA(attackerDeposit);
    vm.stopPrank();

    // Honest manager starts the next epoch. onStartEpoch snapshots the
    // already-existing vault gain into bufferedVaultDelta.
    vm.prank(manager);
    idleCDO.startEpoch();

    vm.warp(idleCDO.epochEndDate() + 1);

    // totalInterestDueNow includes the pre-deposit buffer gain, and the CDO
    // mints strategy tokens before repricing tranche shares.
    vm.prank(manager);
    idleCDO.stopEpoch(0, 0);

    // The attacker's shares now claim approximately 90% of the 100k gain.
    uint256 attackerValue =
        attackerShares * idleCDO.virtualPrice(address(AAtranche)) / 1e18;

    assertApproxEqRel(
        attackerValue,
        attackerDeposit + 90_000e6,
        0.01e18
    );
}
```

The core assertion is that `depositAA` mints shares before `onStartEpoch` converts the already-realized ERC4626 buffer gain into pool yield, so the new shares participate in yield they did not fund.

  function _managedContractValue() internal virtual view returns (uint256) {
    uint256 strategyTokenBalance = _contractTokenBalance(strategyToken);
    uint256 fees = unclaimedFees;
