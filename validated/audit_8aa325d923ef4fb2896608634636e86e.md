### Title
Equivocation via `validate_tenure_change_payload` (v1) duplicate-block check using globally-accepted-only lookup — ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
`SortitionsView::validate_tenure_change_payload` in `chainstate/v1.rs` guards against re-signing a duplicate tenure-change block by querying `signer_db.get_last_globally_accepted_block`, which only returns a block once it reached network-wide 70% acceptance [1](#0-0) . The v2 equivalent explicitly replaced this with `get_last_signed_block`, which also matches blocks the signer only locally accepted, with an inline comment stating the rationale for counting "blocks we have signed (locally or globally accepted)" [2](#0-1) . This asymmetry means a v1 signer can be induced to sign a second, conflicting tenure-change block for a tenure it already locally signed but that never reached global acceptance.

### Finding Description
The equality that should hold: for any given signer, at most one signed (locally or globally accepted) tenure-start block should exist per tenure. `validate_tenure_change_payload` (v1) is the exact chokepoint that is supposed to enforce this before a second tenure-change block from the same miner slot is admitted for validation/signing [3](#0-2) .

Root cause: the v1 duplicate check calls `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)`, which only returns blocks that reached the network-wide 70% global-acceptance threshold — not blocks this signer itself already signed and marked `LocallyAccepted` [1](#0-0) . If the signer's own earlier tenure-change block for the same `consensus_hash` stalled below the global threshold (e.g., the miner deliberately split the vote or withheld broad gossip), `get_last_globally_accepted_block` returns `None`, and `DuplicateBlockFound` is never raised.

The v2 implementation of the identical check was changed to `get_last_signed_block`, explicitly documented as intentionally including locally-accepted blocks "a block we have merely pre-committed to carries no signature from us, so it is safe to accept a competing tenure-start block in its place if it failed to reach consensus" — implying the opposite (signed-but-not-globally-accepted) blocks must NOT be treated as safe to override [4](#0-3) . This comment/behavior change is direct evidence that the v1 check's scope (`GloballyAccepted` only) is insufficient and was corrected in v2.

Attacker's exact flow, with only one miner slot and StackerDB gossip:
1. Win a sortition slot for tenure T; propose tenure-change block B1 (consensus_hash = T).
2. Cause the network vote for B1 to stall below the 70% global-acceptance threshold while still delivering it to the target v1 signer, who validates and signs it (`mark_locally_accepted`, i.e., `signed_self` recorded, per the state model referenced in `docs/signer-flows.md`) [5](#0-4) .
3. Because B1 never reaches `GloballyAccepted`, `get_last_globally_accepted_block(T)` still returns `None` for that signer.
4. Attacker crafts and gossips a second tenure-change block B2, also consensus_hash = T (same tenure), through a normal `BlockProposal`.
5. `validate_tenure_change_payload` (v1) runs the same checks; the duplicate-block guard (line 505-518) passes because it never sees B1 (only locally accepted).
6. If the other structural checks (`prev_tenure_consensus_hash` match, `check_tenure_change_confirms_parent`, `check_parent_tenure_choice`) pass — trivially true since B2 targets the exact same parent/tenure as B1 — the v1 signer proceeds to validate and eventually sign B2 too.
7. The single v1 signer has now produced signatures over two distinct, conflicting blocks for the same tenure (equivocation).

Why existing guards don't catch this: the check is purely a chainstate-level duplicate lookup keyed on `get_last_globally_accepted_block`; there is no separate uniqueness gate elsewhere in the v1 path that also considers `LocallyAccepted` blocks for this exact per-tenure tenure-change duplicate check (unlike v2, which explicitly does this). The node-side validation call, reward set/threshold, and BlockResponse aggregation are orthogonal — they don't prevent a signer from producing a second valid signature once the chainstate layer fails to flag the duplicate.

### Impact Explanation
This breaks the "uniqueness/no-equivocation" safety property for signer signatures: a single v1 signer's signature can be attached to two different, conflicting tenure-start blocks for the same tenure. If enough other signers (v1 or otherwise) are independently tricked similarly, or if this signature is combined with signatures from signers who signed the competing chain, it can produce two block-response aggregates that both look locally valid to different observers, creating a fork/equivocation at the chain-safety level. This matches the Critical category: "a signer signing an invalid, non-canonical, or conflicting block (chain safety)." It is repeatable per-tenure and per-v1-signer, since nothing resets or corrects the check once it fails to find B1.

### Likelihood Explanation
Preconditions: at least one signer negotiates to protocol version 1 (`SortitionStateVersion::V1`, active when negotiated version < `GLOBAL_SIGNER_STATE_ACTIVATION_VERSION` = 2) [6](#0-5) . This is not purely test-only: the codebase's own test (`downgrade_signer_protocol_version`) demonstrates that a real 40%+ blocking minority of signers running an older supported version forces the whole cluster to negotiate down to v1 [7](#0-6) , a realistic situation during a rolling software upgrade. The attacker only needs: (1) one miner slot to propose two conflicting tenure-change blocks for the same tenure, and (2) the ability to prevent B1 from reaching the 70% global-acceptance threshold while it still reaches the targeted v1 signer — both achievable purely through gossip/proposal timing without needing majority signer control, node access, or any key material. It is repeatable for every tenure where a v1 signer is targeted during the rollout window.

### Recommendation
In `chainstate/v1.rs`'s `validate_tenure_change_payload`, replace the duplicate-block lookup `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)` with the same signed-block union used in v2 (`get_last_signed_block`, i.e., locally OR globally accepted), so that a v1 signer's own signature commitment is honored regardless of whether the block later reached global consensus. This aligns v1's equivocation guard with the fix already implemented in v2.

// stacks-signer/src/chainstate/tests/v1.rs (new test)
#[test]
fn v1_duplicate_check_misses_locally_accepted_block() {
    // Setup: a SignerDb with a BlockInfo B1 for tenure T stored with
    // state = BlockState::LocallyAccepted (signed_self stamped, never GloballyAccepted).
    let mut signer_db = SignerDb::new(...);
    let block1 = make_tenure_change_block(consensus_hash_t, height, ...);
    let mut block_info1 = BlockInfo::from(block1.clone());
    block_info1.mark_locally_accepted(false).unwrap(); // signer signed locally, no global consensus
    signer_db.insert_block(&block_info1).unwrap();

    // Sanity: last globally accepted returns None (root cause).
    assert!(signer_db
        .get_last_globally_accepted_block(&consensus_hash_t)
        .unwrap()
        .is_none());
    // But last signed block does see it.
    assert!(signer_db
        .get_last_signed_block(&consensus_hash_t)
        .unwrap()
        .is_some());

    // Craft a second, conflicting tenure-change block B2 for the same tenure T.
    let block2 = make_tenure_change_block(consensus_hash_t, height, /* different content */ ...);

    let sortitions_view = build_sortitions_view_for_tenure(consensus_hash_t, ...);
    let result = sortitions_view.validate_tenure_change_payload(
        &proposed_by,
        block2.get_tenure_change_tx_payload().unwrap(),
        &block2,
        &mut signer_db,
        &client,
    );

    // EXPECTED (fixed): Err(RejectReason::DuplicateBlockFound)
    // ACTUAL (bug): Ok(()) -- v1 admits the conflicting block because it only
    // checked get_last_globally_accepted_block, proving the equivocation gap.
    assert_eq!(result, Err(RejectReason::DuplicateBlockFound));
}

    /// in tenure changes, we need to check:
    /// (1) if the tenure change confirms the expected parent block (i.e.,
    /// the last globally accepted block in the parent tenure)
    /// (2) if the parent tenure was a valid choice
    fn validate_tenure_change_payload(
        &self,
        proposed_by: &ProposedBy,
        tenure_change: &TenureChangePayload,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
    ) -> Result<(), RejectReason> {
        // Check that the tenure change's prev_tenure matches the sortition's known parent tenure.
        // This catches block commits with bad parent_block_ptr (e.g., vtxindex=0 exploit).
        let parent_tenure_id = &proposed_by.state().data.parent_tenure_id;
        if &tenure_change.prev_tenure_consensus_hash != parent_tenure_id {
            warn!(
                "Block commit parent tenure mismatch: the block commit's parent_block_ptr does not correspond to the actual parent tenure";
                "committed_parent_tenure" => %parent_tenure_id,
                "actual_parent_tenure" => %tenure_change.prev_tenure_consensus_hash,
                "consensus_hash" => %block.header.consensus_hash,
                "signer_signature_hash" => %block.header.signer_signature_hash(),
            );
            return Err(RejectReason::InvalidParentBlock);
        }

        // Ensure that the tenure change block confirms the expected parent block
        let confirms_expected_parent = SortitionData::check_tenure_change_confirms_parent(
            tenure_change,
            block,
            signer_db,
            client,
            self.config.tenure_last_block_proposal_timeout,
            self.config.reorg_attempts_activity_timeout,
        )
        .map_err(SignerChainstateError::from)?;
        if !confirms_expected_parent {
            return Err(RejectReason::InvalidParentBlock);
        }
        // now, we have to check if the parent tenure was a valid choice.
        let is_valid_parent_tenure = proposed_by.state().data.check_parent_tenure_choice(
            signer_db,
            client,
            &self.config.first_proposal_burn_block_timing,
        )?;
        if !is_valid_parent_tenure {
            return Err(RejectReason::ReorgNotAllowed);
        }
        let last_in_current_tenure = signer_db
            .get_last_globally_accepted_block(&block.header.consensus_hash)
            .map_err(|e| {
                SignerChainstateError::from(ClientError::InvalidResponse(e.to_string()))
            })?;
        if let Some(last_in_current_tenure) = last_in_current_tenure {
            warn!(
                "Miner block proposal contains a tenure change, but we've already signed a block in this tenure. Considering proposal invalid.";
                "proposed_block_consensus_hash" => %block.header.consensus_hash,
                "proposed_block_signer_signature_hash" => %block.header.signer_signature_hash(),
                "last_in_tenure_signer_signature_hash" => %last_in_current_tenure.block.header.signer_signature_hash(),
            );
            return Err(RejectReason::DuplicateBlockFound);
        }
        Ok(())
    }

/// The version of the sortition state
#[derive(Debug, Clone)]
pub enum SortitionStateVersion {
    /// Version 1: Local Signer State evaluation only
    V1,
    /// Version 2: Global Signer State evaluation
    V2,
}

impl SortitionStateVersion {
    /// Convert the protocol version to a sortition state version
    pub fn from_protocol_version(version: u64) -> Self {
        if version < GLOBAL_SIGNER_STATE_ACTIVATION_VERSION {
            Self::V1
        } else {
            Self::V2
        }
    }
    /// Uses global state version
    pub fn uses_global_state(&self) -> bool {
        match self {
            Self::V1 => false,
            Self::V2 => true,
        }
    }
}

/// Scenario (10 signers):
/// 1) Baseline: all signers start on `SUPPORTED_SIGNER_PROTOCOL_VERSION` and can sign blocks.

/// 3) Downgrade 40%: blocking minority downgraded. Downgrades to `SUPPORTED_SIGNER_PROTOCOL_VERSION - 1`.

#[test]
#[ignore]

    if env::var("BITCOIND_TEST") != Ok("1".into()) {
        return;
    }
    // To make the math easier, use 10 signers
    let num_signers: usize = 10;

    // Integer percent helper (e.g. 30 => 3 when num_signers=10)
    fn pct(num_signers: usize, percent: usize) -> usize {
        (num_signers * percent) / 100
    }

    // Boot with the most recent supported version
    let mut signer_test: SignerTest<SpawnedSigner> = SignerTest::new(num_signers, vec![]);
    signer_test.boot_to_epoch_3();

    info!(
        "------------------------- Confirm miner tenure continues and all signers use protocol {SUPPORTED_SIGNER_PROTOCOL_VERSION} -------------------------"
    );
    let versions = signer_test.signer_addresses_versions();
    mine_burn_block_and_confirm_signer_rollover(&mut signer_test, &versions);

    let downgraded_version = SUPPORTED_SIGNER_PROTOCOL_VERSION.saturating_sub(1);
    let downgraded_versions = signer_test
        .signer_addresses_versions()
        .into_iter()
        .map(|(addr, _)| (addr, downgraded_version))
        .collect::<Vec<_>>();
    info!("------------------------- Downgrading Signer Versions to {downgraded_version} for 30 Percent of Signers -------------------------");
    // Since only 30 percent downgraded. Active protocol version should stay the same
    signer_test
        .restart_first_n_signers_with_supported_version(pct(num_signers, 30), downgraded_version);
    let versions = signer_test.signer_addresses_versions();
    mine_burn_block_and_confirm_signer_rollover(&mut signer_test, &versions);
    info!("------------------------- Downgrading Signer Versions to {downgraded_version} for 40 Percent of Signers -------------------------");
    // A blocking minority has downgraded, so expect everyone to negotiate to downgraded_version.
    signer_test
        .restart_first_n_signers_with_supported_version(pct(num_signers, 40), downgraded_version);
    mine_burn_block_and_confirm_signer_rollover(&mut signer_test, &downgraded_versions);
