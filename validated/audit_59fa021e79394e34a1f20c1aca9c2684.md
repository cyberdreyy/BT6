Confirmed: `assert_valid_request` (multisig2/src/lib.rs:407-423) only checks that the *caller* is currently a member; it never revalidates the *existing* entries inside a request's `confirmations` set against the current member list. Combined with `delete_member` (lines 355-379) only purging requests *originated* by the removed member — not scrubbing that member's votes cast on other members' requests — a former member's stale vote survives and is counted by `confirm()`'s threshold check (`confirmations.len() as u32 + 1 >= self.num_confirmations`, line 304). This breaks the invariant `confirmations counted == live members who approved`, allowing a request to execute below the real live-member threshold. The identical pattern exists in the older `multisig` contract via `DeleteKey` (multisig/src/lib.rs:198-216), which filters only `r.signer_pk == pk` for requests originated by that key, leaving that key's confirmations on other requests untouched.

### Title
Multisig executes requests using stale confirmations from removed members, bypassing the confirmation threshold - (File: `multisig2/src/lib.rs`, also `multisig/src/lib.rs`)

### Summary
`delete_member` (and the legacy `DeleteKey` action in `multisig`) only deletes requests *created* by the removed member/key, but does not remove that member's confirmation entries from other pending requests they had previously confirmed. `confirm()` later counts these stale confirmations toward `num_confirmations`, so a request can execute with fewer *live* member approvals than the configured threshold requires.

### Finding Description
The equality that should hold is: `count(confirmations recorded for request R) == count(current members who approved R)`. In practice, `delete_member` breaks this by only scrubbing requests where `r.member == member` [1](#0-0) , leaving the removed member's vote inside the `confirmations: LookupMap<RequestId, HashSet<String>>` of any other request they confirmed but did not create. `confirm()` then executes the request purely based on the size of this stale set: `if confirmations.len() as u32 + 1 >= self.num_confirmations` [2](#0-1) , without re-validating that every recorded confirmer is still a current member. `assert_valid_request` only checks that the *caller* is a current member, not the historical confirmers [3](#0-2) . The same gap exists in the legacy `multisig` contract's `DeleteKey` handling, which filters requests by `r.signer_pk == pk` (the originating key) only [4](#0-3) .

### Impact Explanation
This is Critical: a multisig request (e.g. a `Transfer` moving NEAR out of the account, or a `DeployContract`/`AddKey` action) can be executed with confirmations from fewer *currently authorized* members than `num_confirmations` requires, because one of the counted votes belongs to a member who has since been removed. This directly breaks the K-of-N custody guarantee the contract is supposed to enforce.

### Likelihood Explanation
Member turnover (removing a departing member, a compromised key, or a misbehaving co-signer) is an expected, documented multisig operation (`DeleteMember`/`DeleteKey`). Any pending request that a to-be-removed member had confirmed, but did not originate, will retain that stale vote indefinitely (there is no expiry independent of `REQUEST_COOLDOWN`/deletion), so the bug is trivially triggered by routine membership changes rather than requiring an unusual sequence.

### Recommendation
When removing a member/key, iterate over all `confirmations` entries (not just requests originated by that member) and remove the member's/key's entry from every confirmation `HashSet`. Alternatively, revalidate at `confirm()`/`execute_request()` time that every account/key present in the stored confirmations set is still a current member before counting it toward `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `B` calls `add_request_and_confirm(R)` where `R` is a `Transfer` request — confirmations for `R` = `{B}` (1/3).
3. `A` calls `confirm(R)` — confirmations for `R` = `{A, B}` (2/3), request not yet executed.
4. Through a separate, properly-confirmed request, the multisig executes `DeleteMember { member: A }`. Per `delete_member`, only requests where `r.member == A` (i.e., requests *created* by `A`) are purged; since `R` was created by `B`, `R`'s confirmation set `{A, B}` is untouched, and `A` is now removed from `self.members`.
5. `C` (a genuinely current, third member) calls `confirm(R)`. `confirmations.len() + 1 == 3 >= num_confirmations(3)`, so `R` executes — even though only `B` and `C` are current members who actually approved it; the required third approval came from `A`, who is no longer part of the multisig.     /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
