### Title
Gas underpayment in `promise_yield_resume` when reading `payload` from a register with an attacker-declared `payload_len` smaller than the register's actual content - (File: runtime/near-vm-runner/src/logic/logic.rs)

### Finding Description
In `promise_yield_resume`, the byte fee for the payload is computed and charged with `self.result_state.gas_counter.pay_per(yield_resume_byte, payload_len)` at logic.rs:3856, using the caller-supplied `payload_len` argument. Only afterwards is the payload actually resolved via `get_memory_or_register!(self, payload_ptr, payload_len)` at logic.rs:3858, which — when `payload_ptr` addresses a register (register mode) — ignores the declared `payload_len` and returns the register's real stored byte length. The code then reassigns `let payload_len = payload.len() as u64;` at logic.rs:3859, but this reassigned value is used only for the `max_yield_payload_size` bound check at logic.rs:3860-3866, not to correct the fee already charged at line 3856. [1](#0-0) 

An attacker-controlled contract can: (1) write a large payload (up to `max_yield_payload_size`) into a register via a prior host call, then (2) call `promise_yield_resume` passing that register as `payload_ptr` while declaring a small `payload_len` in the call arguments. Because the fee is computed from the declared argument before the register content is resolved, the attacker pays `yield_resume_byte` fees only for the small declared length while the runtime actually reads, allocates (`payload.into_owned()`), and forwards the full large register payload to `submit_promise_resume_data` at logic.rs:3872, which stores it and later delivers it in the yield-resume callback receipt. [2](#0-1) 

No other check re-validates or re-charges based on the resolved length; the `max_yield_payload_size` check only bounds the size, it does not adjust gas already burnt. The identical pattern also exists in `promise_yield_resume_with_yield_id`. [3](#0-2) 

### Impact Explanation
This breaks the metering totality invariant: the byte-fee charged does not equal the actual bytes processed/stored/forwarded. An attacker can submit large yield-resume payloads (up to the configured `max_yield_payload_size`) while paying gas fees for an arbitrarily small declared length (including near-zero), resulting in systematic gas underpayment for storage and cross-receipt data-forwarding work performed by the runtime. This falls into the "Fee payment bypass" category — the attacker extracts state storage/compute work from validators at below-cost gas price, which is a resource-metering/DoS-adjacent economic bug rather than direct fund theft.

### Likelihood Explanation
The precondition is straightforward and fully within an unprivileged attacker's control: deploy a contract, populate a register with a large payload via any register-writing host call, and invoke `promise_yield_resume` with a mismatched, smaller `payload_len` while pointing `payload_ptr` at that register. This requires no special permissions, validator access, or race conditions, and is fully repeatable per transaction, so the likelihood of exploitation is high once corroborated by a register-mode read (subject to confirming the exact register-mode sentinel/behavior of `get_memory_or_register!`, which could not be fully inspected within tool constraints).

### Recommendation
Move the `pay_per(yield_resume_byte, ...)` charge to occur after `payload` is resolved via `get_memory_or_register!`, using the actual resolved `payload.len()` rather than the caller-declared `payload_len`. Apply the same fix to `promise_yield_resume_with_yield_id`.

### Proof of Concept
Add a unit test in `runtime/near-vm-runner/src/logic/tests/yield_resume.rs`:
1. Populate a register (e.g., register id `0`) with a payload of size `N` bytes (close to `max_yield_payload_size`).
2. Call `promise_yield_resume` with `payload_ptr` set to the register sentinel and `payload_len` declared as a small value (e.g., `1`), and record gas burnt.
3. Repeat with a separate call where `payload_len` is declared as `N` (matching actual register size) and compare gas burnt.
4. Assert that gas burnt differs between the two calls despite both submitting an `N`-byte payload to `submit_promise_resume_data`, proving the fee tracks the declared length rather than the resolved length — confirming the metering totality violation.
