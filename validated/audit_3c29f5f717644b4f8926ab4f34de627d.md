## Title
Unbounded recursive MPT `TrieNode::decode` allows stack-overflow DoS of the fault-proof program via attacker-crafted trie preimages - (File: `crates/proof/mpt/src/node.rs`)

### Summary
CVE-2016-4008 is a Libtasn1 infinite/deep recursion during non-strict DER decoding, triggered by a crafted certificate with attacker-controlled nesting. Base's `base-proof-mpt` crate implements Ethereum's Merkle Patricia Trie decoding the same way GnuTLS/Libtasn1 decoded ASN.1: `Decodable for TrieNode::decode` recurses into child items purely based on the RLP structure it is handed, with **no depth limit** on nested `Branch`/`Extension` nodes.

### Finding Description
`TrieNode::decode` in [1](#0-0)  dispatches on the RLP header: for a 17-element list it decodes a `Vec::<Self>::decode(buf)` (a `Branch`), and for a 2-element list it calls `try_decode_leaf_or_extension_payload`, which itself calls `Self::decode(buf)` again for an `Extension` node's child [2](#0-1) . Each of these recursive calls has no depth counter or recursion-depth ceiling, unlike the CBOR parser elsewhere in the same proof stack, which explicitly enforces `MAX_CBOR_NESTING_DEPTH` and rejects deep nesting [3](#0-2) .

Crucially, the real Ethereum MPT invariant — that only sub-nodes whose RLP encoding is ≤32 bytes may be embedded (unblinded) directly, while anything larger must be referenced by a keccak hash (`Blinded`) — is enforced only on the *encode* path (`blinded_length`/`payload_length`), not on `decode`. `TrieNode::decode` will happily decode an arbitrarily large, arbitrarily deep chain of embedded `Branch`/`Extension` nodes as long as the wrapping RLP is well formed. The same unbounded-recursion pattern repeats in traversal helpers such as `OrderedListWalker::fetch_leaves`, which recurses into `Branch`/`Extension` children without any depth check [4](#0-3) .

This is reachable from attacker-controlled data because trie node preimages are fetched by hash from the untrusted preimage oracle inside the fault-proof program, e.g. `OracleL1ChainProvider::trie_node_by_hash` [5](#0-4)  and the analogous L2 chain provider. The oracle only guarantees the returned bytes hash to the requested key — it does not constrain their internal structure. An attacker who controls the account/storage trie contents that end up referenced during L1 derivation or L2 state proofs (e.g., via a contract they deploy, or L1 data they post) can craft a single large preimage blob whose RLP encodes thousands of nested embedded branch/extension frames.

### Impact Explanation
Decoding such a crafted preimage inside the fault-proof program (used to resolve dispute games) causes deep native recursion in `TrieNode::decode`/`fetch_leaves`, exhausting the call stack and aborting the process. A stack overflow during dispute-game execution means the honest party cannot compute/prove the correct output root within the challenge window, which can let a malicious claim go unchallenged or force a node halt of the proof program — directly matching the allowed "wrong provable output root" / "node halt" impact classes for the fault-proof program and MPT.

### Likelihood Explanation
Any party can create L1/L2 data (a contract, storage layout, or transaction) that produces a state/storage trie whose node preimages are large, deeply self-nested RLP lists satisfying the requested hash — no privileged access is required, only crafted account/contract state that the fault-proof program will later need to walk during normal dispute verification of a block touching that state.

### Recommendation
Add an explicit recursion/depth bound to `TrieNode::decode` (and to `OrderedListWalker::fetch_leaves`) analogous to the `MAX_CBOR_NESTING_DEPTH` guard already used in `crates/proof/tee/registrar/src/cbor.rs`, and/or enforce the embed-vs-blind invariant (reject non-blinded child items whose encoded length exceeds 32 bytes) during decode, not just encode.

### Proof of Concept
1. Construct an RLP blob `B0` that decodes as a `Branch` (`BRANCH_LIST_LENGTH` = 17 elements), where element `i` is itself a fully embedded (non-blinded) `Branch`/`Extension` node `B1`, which itself embeds `B2`, and so on for N (tens of thousands) levels — each level individually valid RLP, never exceeding the oracle's max preimage size in total.
2. Arrange for this structure to be the actual preimage of a state/storage/account trie node hash that the fault-proof program will request while executing/verifying a block that touches attacker-controlled state (e.g., a contract account or storage slot the attacker created).
3. When the fault-proof program calls `trie_node_by_hash` → `TrieNode::decode` on this preimage [6](#0-5) , the recursive `Vec::<Self>::decode`/`Self::decode` calls recurse N times with no bound, exhausting the stack and aborting the process before the dispute game step can complete.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
