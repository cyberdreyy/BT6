## Finding: Integration deposit paths (Drift / Juplend / Kamino / Solend) don't account for Token-2022 transfer fees, breaking the pre-fee/post-fee amount reconciliation that the core deposit path enforces

### Title
Token-2022 transfer-fee mints break amount accounting in Drift/Juplend/Kamino/Solend integration deposits - (File: `programs/marginfi/src/instructions/drift/deposit.rs`, and analogous `juplend/deposit.rs`, `kamino/deposit.rs`, `solend/deposit.rs`)

### Summary
The external report (M01) describes the risk of fee-on-transfer / non-reverting ERC20 tokens breaking accounting when a contract assumes it receives the full amount it requested to be transferred. marginfi's core `lending_account_deposit` path correctly handles this class of bug for Token-2022 `TransferFeeConfig` mints by pre-computing a `pre_fee` amount so the vault actually receives exactly the credited amount: [1](#0-0) 

However, the integration deposit instructions for Drift, Juplend, Kamino, and Solend banks omit this adjustment entirely. They transfer the user-supplied `amount` directly via `transfer_checked` into an intermediary `liquidity_vault`, then immediately pass that same raw `amount` into the downstream protocol's deposit CPI: [2](#0-1) [3](#0-2) [4](#0-3) 

The same pattern (raw `amount` transferred and reused for the downstream CPI, with no `calculate_pre_fee_spl_deposit_amount` call) appears in the Juplend, Kamino, and Solend deposit flows: [5](#0-4) [6](#0-5) [7](#0-6) 

### Finding Description
`calculate_pre_fee_spl_deposit_amount` and `nonzero_fee` exist specifically to detect Token-2022 mints carrying an active `TransferFeeConfig` extension and adjust transfer amounts accordingly: [8](#0-7) 

These helpers are used by the core `lending_account_deposit`/`lending_account_withdraw` paths, but none of the integration (`drift`, `juplend`, `kamino`, `solend`) deposit account structs or handler functions call them. The Drift bank creation path (`lending_pool_add_bank_drift`) only checks decimal limits and oracle setup, and merely records `IS_T22` in `bank.flags`—it performs no check against `TransferFeeConfig` (or any fee-bearing extension) being present on the mint: [9](#0-8) 

Consequently, if an admin ever creates a Drift/Juplend/Kamino/Solend bank backed by a Token-2022 mint with a nonzero `TransferFeeConfig`, `drift_deposit`'s `cpi_transfer_user_to_liquidity_vault(amount)` moves `amount` tokens out of the user, but the `liquidity_vault` receives only `amount - fee`. The very next call, `cpi_drift_deposit(market_index, amount, authority_bump)`, still instructs Drift to move the full, un-adjusted `amount` out of that same underfunded vault. This diverges from the pattern the M01 report warns about (assuming the destination always receives exactly what was requested) and is exactly the class of bug the core deposit path was hardened against but the integration paths were not.

### Impact Explanation
For any Drift/Juplend/Kamino/Solend bank whose underlying mint is Token-2022 with an active transfer fee, deposits become internally inconsistent: the intermediary vault holds less than the amount the marginfi program instructs the downstream lending/perp protocol to move on-chain. In the best case, this reverts on-chain because the vault has insufficient balance (a livelock/DoS on that bank), but the deeper problem is architectural: the integration deposit flows have no mechanism to detect or defensively compute the true amount received into the intermediary vault before invoking the downstream deposit CPI with a different, unverified value, unlike `lending_account_deposit`, which explicitly reconciles pre-fee/post-fee amounts before crediting bank shares. Any residual balance already sitting in the intermediary vault (e.g., dust from prior operations, or fees from other users' partial transfers) could let a deposit CPI succeed despite an underfunded transfer, silently drawing on other users' or the bank's own funds and corrupting the 1:1 relationship between user-supplied tokens and downstream protocol credit.

### Likelihood Explanation
This requires the marginfi group admin to add a Drift/Juplend/Kamino/Solend bank on a Token-2022 mint that has (or later gains, since `TransferFeeConfig` authority can be mutable) a nonzero transfer fee — an admin action, but nothing in the on-chain program prevents it, unlike the explicit `InvalidTransfer` guard enforced elsewhere for emissions deposits on fee/hook mints: [10](#0-9) 
No equivalent guard exists for the integration bank paths, so the vulnerable configuration is directly reachable by an unprivileged depositor once such a bank exists.

### Recommendation
Apply the same fee-aware amount reconciliation used in `lending_account_deposit`/`lending_account_withdraw` (via `calculate_pre_fee_spl_deposit_amount`/`calculate_post_fee_spl_deposit_amount`) to all integration deposit/withdraw flows (Drift, Juplend, Kamino, Solend): measure the intermediary vault's balance delta after the initial `transfer_checked` and use that actual received amount (not the raw instruction `amount`) for the downstream protocol CPI and for bank share accounting. Additionally, either reject Token-2022 mints with an active `TransferFeeConfig`/`TransferHook` at `lending_pool_add_bank_*` time for these integrations (mirroring the `InvalidTransfer` check already used for emissions deposits), or fully thread the fee-adjusted amount through every integration deposit/withdraw code path.

### Proof of Concept
1. Admin creates a Drift-integrated bank (`lending_pool_add_bank_drift`) using a Token-2022 mint that has an active `TransferFeeConfig` (e.g., 1% fee) — no on-chain check blocks this.
2. A user calls `drift_deposit(amount)` with `signer_token_account` holding sufficient balance.
3. `cpi_transfer_user_to_liquidity_vault(amount)` executes `transfer_checked(amount)`; due to the transfer fee, `liquidity_vault` receives only `amount * 0.99`.
4. `cpi_drift_deposit(market_index, amount, authority_bump)` is invoked with the original, un-adjusted `amount`, instructing Drift to move `amount` tokens from `liquidity_vault` — which only holds `amount * 0.99` — into `drift_spot_market_vault`.
5. Depending on prior vault balance, this either reverts (bricking deposits on that bank) or succeeds while drawing on token balance the current depositor did not actually contribute, breaking the intended 1:1 backing between user deposits and Drift-side credited scaled balance.

        let program = self.drift_program.to_account_info();
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), authority_bump);
        let mut cpi_ctx = CpiContext::new_with_signer(program.key(), accounts, signer_seeds);

        // Construct remaining accounts in the required order for Drift:
        // 1. Oracle accounts (if provided)
        // 2. Spot market account (always required)
        // 3. Token mint (required for Token-2022, harmless to include for regular mints)
        let mut remaining_accounts = Vec::new();

        // Add oracle if provided (not needed if using oracle type QuoteAsset)
        if let Some(oracle) = &self.drift_oracle {
            remaining_accounts.push(oracle.to_account_info());
        }

        // Always add spot market account
        remaining_accounts.push(self.integration_acc_1.to_account_info());

        // Always add token mint (needed for Token-2022 support)
        remaining_accounts.push(self.mint.to_account_info());

        cpi_ctx = cpi_ctx.with_remaining_accounts(remaining_accounts);

        // Call drift deposit with reduce_only = false
        deposit(cpi_ctx, market_index, amount, false)?;
        Ok(())
    }

pub fn calculate_pre_fee_spl_deposit_amount(
    mint_ai: AccountInfo,
    post_fee_amount: u64,
    epoch: u64,
) -> MarginfiResult<u64> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(post_fee_amount);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    match mint.get_extension::<TransferFeeConfig>() {
        Ok(transfer_fee_config) => {
            let epoch_fee = transfer_fee_config.get_epoch_fee(epoch);
            let pre_fee_amount = calculate_pre_fee_amount(epoch_fee, post_fee_amount).unwrap();
            Ok(pre_fee_amount)
        }
        Err(_) => Ok(post_fee_amount),
    }
}

pub fn calculate_post_fee_spl_deposit_amount(
    mint_ai: AccountInfo,
    input_amount: u64,
    epoch: u64,
) -> MarginfiResult<u64> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(input_amount);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    let fee = if let Ok(transfer_fee_config) = mint.get_extension::<TransferFeeConfig>() {
        transfer_fee_config
            .calculate_epoch_fee(epoch, input_amount)
            .unwrap()
    } else {
        0
    };

    let output_amount = input_amount
        .checked_sub(fee)
        .ok_or(MarginfiError::MathError)?;

    Ok(output_amount)
}

pub fn nonzero_fee(mint_ai: AccountInfo, epoch: u64) -> MarginfiResult<bool> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(false);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    if let Ok(transfer_fee_config) = mint.get_extension::<TransferFeeConfig>() {
        return Ok(u16::from(
            transfer_fee_config
                .get_epoch_fee(epoch)
                .transfer_fee_basis_points,
        ) != 0);
    }

    Ok(false)
}

pub fn lending_pool_add_bank_drift(
    ctx: Context<LendingPoolAddBankDrift>,
    bank_config: DriftConfigCompact,
    bank_seed: u64,
) -> MarginfiResult {
    // Note: Drift banks don't need to debit the flat SOL fee because these will always be
    // first-party pools owned by mrgn and never permissionless pools
    let LendingPoolAddBankDrift {
        bank_mint,
        bank: bank_loader,
        integration_acc_1: spot_market_loader,
        integration_acc_2: obligation_loader,
        integration_acc_3: user_stats_loader,
        ..
    } = ctx.accounts;

    let mut bank = bank_loader.load_init()?;
    let mut group = ctx.accounts.group.load_mut()?;
    let spot_market_key = spot_market_loader.key();

    // Validate that we're using a supported Drift oracle setup type
    require!(
        matches!(
            bank_config.oracle_setup,
            OracleSetup::DriftPythPull | OracleSetup::DriftSwitchboardPull
        ),
        MarginfiError::DriftInvalidOracleSetup
    );

    require!(
        (bank_mint.decimals as u32) <= DRIFT_PRECISION_EXP,
        MarginfiError::DriftUnsupportedTokenDecimals
    );

    let liquidity_vault_authority_bump = ctx.bumps.liquidity_vault_authority;
    let insurance_vault_bump = ctx.bumps.insurance_vault;
    let insurance_vault_authority_bump = ctx.bumps.insurance_vault_authority;
    let fee_vault_bump = ctx.bumps.fee_vault;
    let fee_vault_authority_bump = ctx.bumps.fee_vault_authority;

    let config = bank_config.to_bank_config(spot_market_key);

    *bank = Bank::new(
        ctx.accounts.group.key(),
        config, // Use the modified BankConfig directly instead of converting from BankConfigCompact
        bank_mint.key(),
        bank_mint.decimals,
        ctx.accounts.liquidity_vault.key(),
        ctx.accounts.insurance_vault.key(),
        ctx.accounts.fee_vault.key(),
        Clock::get().unwrap().unix_timestamp,
        liquidity_vault_bump,
        liquidity_vault_authority_bump,
        insurance_vault_bump,
        insurance_vault_authority_bump,
        fee_vault_bump,
        fee_vault_authority_bump,
        bank_seed,
    );
    bank.flags |= BANK_SEED_KNOWN;
    if bank_mint.to_account_info().owner == &anchor_spl::token_2022::ID {
        bank.flags |= IS_T22;
    }

    // Set Drift-specific fields
    bank.integration_acc_1 = spot_market_key;
    bank.integration_acc_2 = obligation_loader.key();
    bank.integration_acc_3 = user_stats_loader.key();

    log_pool_info(&bank);

    group.add_bank()?;

    bank.config.validate()?;
    bank.config
        .validate_oracle_setup(ctx.remaining_accounts, None, None, None)?;
