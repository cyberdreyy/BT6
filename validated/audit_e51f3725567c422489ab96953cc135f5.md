### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing request execution below the true live-member threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` in `multisig2/src/lib.rs` decides whether to execute a pending request purely by comparing `confirmations.len()` (a `HashSet<String>` of member identifiers who previously called `confirm`) against `self.num_confirmations`. When a member is removed via `DeleteMember`, `delete_member` only purges confirmations for requests that member *originally created* (`r.member == member`), not confirmations that member cast on *other* still-pending requests. As a result, a removed member's stale confirmation continues to count toward the threshold of any request they confirmed but did not create, letting that request execute with fewer live, currently-authorized confirmers than `num_confirmations` requires.

### Finding Description
The contract state binding that must hold is:
`confirmations_recorded_for_request(R) ⊆ current_members` at the moment `confirm` decides to execute `R`.

`confirm()` only checks set membership/size, never re-validating that every account/key in the stored confirmation set is still a `self.members` entry: [1](#0-0) 

`delete_member()` removes stale requests and confirmations only for requests where the removed member is the **original submitter** (`r.member == member`), never scanning other requests' confirmation sets for entries belonging to the removed member: [2](#0-1) 

`remove_request`/`assert_valid_request` similarly never re-check confirmation validity against the live `members` set: [3](#0-2) 

So a confirmation, once recorded in `self.confirmations`, is permanent unless the confirming member happens to also be the *creator* of that specific request. This is the exact "confirmations counted versus live members" binding the scope calls out — the contract even encodes an explicit invariant in `new()`/`delete_member()` that `members.len() >= num_confirmations` must hold, but that invariant is meaningless if stale confirmations from non-members still count toward execution.

The identical pattern exists in the older `multisig/src/lib.rs`, where `DeleteKey` only clears confirmations of requests originally signed by the deleted key (`r.signer_pk == pk`), not confirmations that key cast on other pending requests: [4](#0-3) [5](#0-4) 

### Impact Explanation
This matches the "Critical" impact category: a multisig request executed below threshold. An attacker (or a member acting maliciously right before being removed, or simply a coincidental sequence of legitimate operations) can cause a `Transfer`, `FunctionCall`, `AddKey`, `DeployContract`, etc. request to execute with fewer genuinely authorized confirmers than `num_confirmations` mandates, because a removed member's earlier confirmation is silently retained and counted. This effectively lowers the security threshold of the multisig without any of the remaining members' knowledge or consent, and can be used to move funds or execute privileged actions with an insufficient quorum of live signers.

### Likelihood Explanation
This requires only ordinary, unprivileged multisig usage patterns already supported by the contract: a member confirms a request they did not create, and then that member is later removed via a normal `DeleteMember` execution (which any k-of-n quorum can trigger without any special knowledge of this bug). No special permissions beyond being an existing multisig member are needed, and the sequence (confirm on one request as a non-creator, then get removed, then have another member cast the last confirmation) is a very ordinary sequence of multisig operations, especially in a scenario where a departing member's access is revoked while requests are still outstanding.

### Recommendation
When removing a member (`delete_member` / `DeleteKey`), iterate over **all** requests' confirmation sets (not just those the member created) and strip that member's identifier from each. Alternatively, when computing `confirmations.len()` in `confirm()`, filter the confirmation set to only those entries that are still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. Member `A` calls `add_request(R)` (e.g. a `Transfer`), which is *not* auto-confirmed (or confirmed by `A` alone) — `R.member == A`, `confirmations(R) = {}` or `{A}`.
3. Member `B` calls `confirm(R)` → `confirmations(R) = {A, B}` (or `{B}` if A didn't confirm) — 2 confirmations, below threshold.
4. Member `D` calls `confirm(R)` → `confirmations(R) = {A, B, D}` — still below threshold (3 < 3 is false only once it reaches 3; assume this step brings it to exactly 2, e.g. `{B, D}` if A never confirmed).
5. Separately, members `A`, `B`, `C` submit and confirm a `DeleteMember { member: D }` request `R2` (3-of-4 threshold met with live members), which executes `delete_member(D)`. Since `R2.member` (the request creator) is not `D`, and `R`'s `member` field is `A` (not `D`), `delete_member` does **not** touch `R`'s confirmation set — `D`'s stale confirmation in `confirmations(R) = {B, D}` remains.
6. Members are now `{A, B, C}`; `D` is removed, but `confirmations(R)` still contains `D`.
7. Member `C` calls `confirm(R)`: `confirmations.len() + 1 = 3 >= num_confirmations (3)` → `R` executes, even though only `B` and `C` are live members who actually confirmed (2 live confirmations), one short of the required 3-of-4 (now effectively 3-of-3) threshold.

This demonstrates `R` executing with a stale, no-longer-authorized confirmation counted toward the threshold — a multisig request executed below the true live-member threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }

    /// Prevents access to calling requests and make sure request_id is valid - used in delete and confirm
    fn assert_valid_request(&mut self, request_id: RequestId) {
        // request must come from key added to contract account
        assert(
            self.current_member().is_some(),
            "Caller (predecessor or signer) is not a member of this multisig",
        );
        // request must exist
        assert(
            self.requests.get(&request_id).is_some(),
            "No such request: either wrong number or already confirmed",
        );
        // request must have
        assert(
            self.confirmations.get(&request_id).is_some(),
            "Internal error: confirmations mismatch requests",
        );
    }
