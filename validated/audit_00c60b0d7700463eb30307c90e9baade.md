### Title
Stale confirmations from removed multisig members are counted toward the confirmation threshold - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` removes a member from `self.members` and deletes only the requests that member itself originated, but never purges that member's confirmation entries from the `confirmations` map for other pending requests that member had already confirmed. `confirm()` counts confirmations purely by `HashSet` length without checking that each confirming identity is still in `self.members`. As a result, a request can be executed with fewer than `num_confirmations` *live* members having actually approved it, because a departed member's stale confirmation is still counted.

### Finding Description
The confirmation-count invariant the contract is supposed to enforce is:
`live_member_confirmations(request) >= num_confirmations`

In practice the contract only enforces:
`confirmations.get(request_id).len() >= num_confirmations`

These are equal only while every entry in the confirmation `HashSet` corresponds to a member still present in `self.members`. `delete_member` breaks this equality: when member `M` is removed via a `DeleteMember` request, the cleanup code at `multisig2/src/lib.rs:361-373` iterates `self.requests` and removes/clears confirmations *only* for requests where `r.member == member` (i.e., requests `M` itself created). Any other outstanding request `R` (created by a different member) that `M` had previously confirmed via `confirm()` keeps `M`'s identity string inside `self.confirmations[R]`. `self.members.remove(&member)` removes `M` from the live member set, but the stale entry in `confirmations[R]` is never touched.

Later, when `confirm()` is called by other members on `R`, the threshold check at `multisig2/src/lib.rs:304` (`confirmations.len() as u32 + 1 >= self.num_confirmations`) counts `M`'s stale confirmation as if `M` were still a live, entitled confirmer, even though `M` has been deleted (and, if `M` was an `AccessKey` member, its access key has been revoked on-chain via `promise.delete_key`).

This is the direct multisig analog of the reported Zebra bug: `pop_root`/`remove_request` on the "confirmed and executed" path correctly cleans up confirmation data, but the alternate removal path (`delete_member`, analogous to `pop_tip`) leaves associated per-request state (confirmations) behind, and that stale state is retained in the persisted contract state and later relied upon by `confirm()`'s threshold check.

### Impact Explanation
This breaks the authorization/threshold binding the multisig is meant to guarantee: "a multisig request executed below threshold" of *currently authorized* signers. An attacker scenario: request `R` (e.g., a `Transfer` or `AddKey` action) is created and confirmed by member `M`. `M` is subsequently removed as a member (e.g., due to key rotation/compromise response). The remaining members only need to supply `num_confirmations - 1` fresh confirmations to push `R` over the threshold, since `M`'s stale confirmation is still silently counted — effectively allowing a request to execute with one fewer live signer than `num_confirmations` requires. This directly matches the in-scope Critical impact category: "a multisig request executed below threshold."

### Likelihood Explanation
No privileged action beyond the normal multisig workflow is required — this can be triggered by any sequence of ordinary member operations (a member confirms a pending request, a `DeleteMember` request later executes for that same member, remaining confirmers subsequently confirm). No malicious insider or foundation cooperation, redeploy, or external actor is needed; it is a straightforward incomplete-cleanup path reachable through documented contract methods (`confirm`, `execute_request` → `delete_member`).

### Recommendation
When executing `DeleteMember`, iterate all outstanding requests' confirmation sets (not just requests originated by the removed member) and strip the removed member's identity string from each. Alternatively, have `confirm()` re-validate, at threshold-check time, that every stored confirming identity is still present in `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R` (e.g., a `Transfer`).
3. `B` calls `confirm(R)` → `confirmations[R] = {B}` (len 1, below threshold).
4. Members execute a separate, already-approved `DeleteMember { member: B }` request; `delete_member` runs at `multisig2/src/lib.rs:356-379`, removing `B` from `self.members` but leaving `confirmations[R] = {B}` untouched because `R` was not created by `B`.
5. `C` calls `confirm(R)` → `confirmations[R] = {B, C}`, len 2.
6. `D` calls `confirm(R)` → check at `multisig2/src/lib.rs:304`: `2 + 1 >= 3` → true → `R` executes.
7. `R` executed with confirmations from only `C` and `D` — two *live* members — despite `num_confirmations = 3`, because `B`'s stale, post-removal confirmation was counted.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Removes request, removes confirmations and reduces num_requests_pk - used in delete, delete_key, and confirm
    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
