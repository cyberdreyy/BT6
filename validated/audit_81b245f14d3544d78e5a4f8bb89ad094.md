### Title
Zip archive extraction performs no path-traversal validation on `zip.File.Name`, allowing writes outside the job/cache root - (helpers/archives/zip_extract.go)

### Summary
`extractZipFile`/`extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` use `file.Name` directly (via `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Mkdir`, `os.Symlink`) with no cleaning, no root/prefix check, and no rejection of absolute paths or `..` segments. This is called by `ExtractZipArchive` / `ExtractZipFile`, which is what `ziplegacy.extractor.Extract` invokes for cache/artifact zip extraction — notably, that extractor even accepts a `dir` parameter but never uses it, so extraction paths are resolved purely against `file.Name` and the process CWD. [1](#0-0) [2](#0-1) 

### Finding Description
`extractZipFile` builds the destination purely from the archive entry name with no containment check:
```
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
``` [1](#0-0) 

Compare this to the tar/zstd extractor in the same codebase, which explicitly resolves the absolute path and rejects anything that escapes the chroot dir:
```
path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))
if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
    return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir)
}
``` [3](#0-2) 

The zip path has no equivalent guard. `ExtractZipArchive` only checks for `.git` directory entries (a data-integrity warning, not a security boundary) before calling `extractZipFile` for every entry: [4](#0-3) . `ziplegacy.extractor` (used for cache-extractor zip archives) receives a `dir` argument from the caller but discards it entirely, calling `archives.ExtractZipArchive(zr)` with no join/validation against that directory: [5](#0-4) . So extraction destination is resolved relative to the process's current working directory only, via bare relative/absolute `file.Name` values, with no sanitization for `../` or drive-letter absolute paths on Windows.

Attacker-controlled input: a job author fully controls the contents of `cache:paths` (compressed into a cache zip) or artifact contents. GitLab Runner itself creates the archive from job-controlled paths (`cache-archiver`), but the cache/artifact zip could also be a maliciously crafted or corrupted archive obtained from a compromised/attacker-controlled cache blob storage location, or, more directly, a job could stage a cache path whose contents include a specially named file (zip entries are derived from local filesystem paths during archiving, but the zip format itself allows arbitrary raw entry names if the archive is manipulated between creation and extraction, e.g. via a shared/writable cache blob store, GoCloud bucket, or man-in-the-middle on the presigned URL response before extraction). Because `helpers/archives/zip_extract.go` performs no server-side validation of `file.Name` at extract time, any `.zip` reaching `CacheExtractorCommand`/`ExtractZipFile`/`ExtractZipArchive` with crafted entry names like `..\..\..\Users\...\somefile` (Windows) or `../../foo` will be written outside the intended extraction root.

However, I could not confirm a concrete path from this bug to overwriting `CACHE_METADATA` / the `--env-file` specifically. `writeCacheMetadataFile` is invoked directly by `CacheExtractorCommand.download*` after downloading the raw cache archive bytes (not through `ExtractZipArchive`), and `loadEnvFile`/`--env-file` reads a file whose path (`c.EnvFile`) is a runner-supplied CLI argument, not derived from zip contents. So while the underlying path-traversal-during-extraction bug is real, the specific claimed impact (poisoning the `CACHE_METADATA`/env-file consumed by `CacheArchiverCommand`) is not substantiated by the code paths found; the actual concrete impact is that extracted file/directory/symlink entries can land anywhere the runner process can write, relative to CWD, which on a shared runner host (or shared build directory across projects, e.g. concurrency reuse of a builds dir) could overwrite files belonging to other jobs/projects.

### Impact Explanation
A crafted zip archive extracted via `ExtractZipArchive` (used by `ExtractZipFile`/`ziplegacy` extractor for cache/artifact restore) can write, overwrite, or symlink files outside the intended cache/build directory, up to whatever the runner process user can access on the host filesystem — this includes files belonging to concurrently or previously-run jobs/projects sharing the same runner host (e.g., other projects' checked-out source, cached credentials files, or scripts later executed by another job), which is a cross-project integrity/confidentiality violation on shared/non-isolated executors (shell executor, or Windows service-based runners without per-job filesystem isolation). [6](#0-5) 

### Likelihood Explanation
Exploitability requires the attacker to control or corrupt the zip archive bytes that reach `ExtractZipArchive`/`ExtractZipFile` (e.g., via cache poisoning, a compromised/misconfigured shared cache bucket, or a crafted artifact that gets processed by helper zip-extraction code paths) and requires the runner to be one without strong per-job filesystem isolation (shell/Windows executor sharing a builds root among jobs) — Docker/Kubernetes executors with per-job container filesystems substantially reduce the blast radius. The zip-format entry names are not sanitized anywhere in the extraction path, so if such an archive is reachable, the traversal is 100% reproducible and requires no race or timing. [7](#0-6) 

### Recommendation
Add the same containment check used in the tar/zstd extractor to the zip code path: resolve `filepath.Join(rootDir, file.Name)` to an absolute path and reject any entry (file, directory, or symlink target) whose resolved path does not have `rootDir` as a prefix, before calling `os.MkdirAll`/`os.OpenFile`/`os.Mkdir`/`os.Symlink`. Also make `ziplegacy.extractor.Extract` actually pass and use its `dir` field (currently ignored) so extraction is always rooted at the intended directory rather than the ambient process CWD.

### Proof of Concept
```go
// helpers/archives/zip_extract_traversal_test.go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    zipPath := filepath.Join(tmpDir, "evil.zip")

    f, _ := os.Create(zipPath)
    zw := zip.NewWriter(f)
    w, _ := zw.Create("../outside.txt") // or "..\\outside.txt" on Windows
    w.Write([]byte("pwned"))
    zw.Close()
    f.Close()

    outsideMarker := filepath.Join(filepath.Dir(tmpDir), "outside.txt")
    _ = os.Remove(outsideMarker)

    err := ExtractZipFile(zipPath)
    require.NoError(t, err)

    _, statErr := os.Stat(outsideMarker)
    // Expected (secure) behavior: file should NOT exist outside tmpDir.
    assert.True(t, os.IsNotExist(statErr), "zip traversal wrote file outside extraction root: %s", outsideMarker)
}
```
Expected result on the current code: the assertion fails — `outside.txt` is created one directory above the intended location, proving the missing containment check.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
