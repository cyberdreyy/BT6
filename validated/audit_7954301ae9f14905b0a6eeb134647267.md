### Title
Flashblocks pending-state builder omits the `BaseTime` predeploy install/link transition, diverging from canonical block execution - (File: `crates/execution/flashblocks/src/state_builder.rs`)

### Summary
`BaseBlockExecutor::apply_pre_execution_changes` runs three irregular-state transitions before executing any transaction in a real block: `canyon::ensure_create2_deployer`, `BaseTime::ensure_predeploy`, and `zenith::ensure_eip8130_system_accounts`. [3](#0-2)  The flashblocks `PendingStateBuilder::apply_pre_execution_changes`, which is explicitly documented as mirroring that behavior "to ensure that the cached execution results match what the validator computes," [4](#0-3)  only calls `ensure_create2_deployer` and `ensure_eip8130_system_accounts` — it never calls `BaseTime::ensure_predeploy`. [5](#0-4) 

### Finding Description
`BaseTime::ensure_predeploy` is the transition that, at the Denim activation block, installs the `BaseTime` implementation bytecode at its code-namespace address and links the EIP-1967 implementation slot of the pre-existing `BaseTime` proxy (`Predeploys::BASE_TIME`) to it. [6](#0-5)  Until this transition runs, the `BaseTime` proxy's EIP-1967 implementation slot is zero, so any call through the proxy (e.g. `timestampMs()`, `timestampMillisPart()`) fails to delegate to real logic.

This is structurally the same bug class as the "Blast configured in the implementation contract constructor, not the proxy" report: a piece of state that only takes effect when written to the *specific execution context serving the request* is applied on one code path (canonical block execution) but skipped on another path that independently builds/serves state (flashblocks pending state). Flashblocks' `PendingStateBuilder` maintains its own EVM/DB and independently re-derives pending block state for RPC serving (`eth_call`, `eth_getBalance`, pending block queries) ahead of/instead of the canonical block executor's committed state. Because `ensure_predeploy` is skipped there, the pending-state EVM database never gets the implementation linked, even though the canonical executor's database (used to build the final, canonical block) does.

### Impact Explanation
On the Denim activation timestamp (and for every subsequent pending block built purely from `PendingStateBuilder` state without inheriting the canonical DB's already-applied transition), the flashblocks/pending code path will serve stale or broken results for any interaction that reads or calls through the `BaseTime` proxy: the EIP-1967 implementation slot remains `0`, so `eth_call`/pending-state reads against `Predeploys::BASE_TIME` resolve to an empty/void implementation instead of the real `timestampMs`/`timestampMillisPart` logic. Any downstream consumer or contract relying on `BaseTime`'s pending-state view (used e.g. for L2 sub-second timestamp precision) gets wrong data from the RPC-facing pending state, while the canonical chain state is correct — a state/query divergence between what full nodes commit and what flashblocks pending state reports. This falls under "flashblocks pending state" derivation errors and can serve wrong `eth_call`/pending query results to RPC clients.

### Likelihood Explanation
This triggers deterministically and automatically at the Denim upgrade activation timestamp for any node running the flashblocks pending-state path — no attacker action is required; it is a straightforward code-path omission comparable to forgetting to configure Blast on the proxy. It is a Medium-severity correctness bug (public `eth_*`/pending-state divergence) rather than a fund-loss issue, since `BaseTime` is a read-oriented metadata predeploy, but it is a concrete, reachable defect in the flashblocks pending-state derivation path explicitly named as in-scope.

### Recommendation
Add the missing `BaseTime::ensure_predeploy(spec, self.pending_block.timestamp, self.evm.db_mut())` call to `PendingStateBuilder::apply_pre_execution_changes` in `crates/execution/flashblocks/src/state_builder.rs`, mirroring the exact sequence used in `BaseBlockExecutor::apply_pre_execution_changes` (create2 deployer → `BaseTime::ensure_predeploy` → EIP-8130 system-account stub), so pending/flashblocks state and canonical block state cannot diverge on this transition.

### Proof of Concept
1. Configure a chain with the Denim upgrade activation timestamp `T`.
2. Run a node with the flashblocks pending-state builder enabled and produce a pending block for timestamp `T` via `PendingStateBuilder` before the canonical block executor commits block `T`.
3. Call `timestampMs()`/`timestampMillisPart()` (or any function) on the `BaseTime` proxy address (`Predeploys::BASE_TIME`) using an `eth_call` against the pending block.
4. Observe: the call reverts or returns empty/incorrect data because the EIP-1967 implementation slot at `Predeploys::BASE_TIME` is still zero in the pending-state DB, whereas the same call against the canonical, fully-executed block (which does invoke `BaseTime::ensure_predeploy` via `BaseBlockExecutor`) succeeds and returns correct data — demonstrating the divergence caused by the missing call in `crates/execution/flashblocks/src/state_builder.rs`.

        self.system_caller.apply_blockhashes_contract_call(self.ctx.parent_hash, &mut self.evm)?;

    /// Applies EIP-4788, EIP-2935, and Canyon create2 deployer pre-execution changes to the EVM.
    ///
    /// Must be called once per block, before executing any transactions. This mirrors the
    /// `apply_pre_execution_changes` behavior of [`base_common_evm::BaseBlockExecutor`] to ensure
    /// that the cached execution results match what the validator computes.
    pub fn apply_pre_execution_changes(
        &mut self,
        parent_hash: B256,
        parent_beacon_block_root: Option<B256>,
    ) -> Result<(), StateProcessorError>
    where
        DB: AlloyDatabase + StateDB,
        ChainSpec: Clone,
    {
        let spec = self.receipt_builder.chain_spec();
        let mut system_caller = SystemCaller::new(spec.clone());
        system_caller
            .apply_blockhashes_contract_call(parent_hash, &mut self.evm)
            .map_err(|e| ExecutionError::EvmEnv(e.to_string()))?;
        system_caller
            .apply_beacon_root_contract_call(parent_beacon_block_root, &mut self.evm)
            .map_err(|e| ExecutionError::EvmEnv(e.to_string()))?;

        ensure_create2_deployer(spec, self.pending_block.timestamp, self.evm.db_mut())
            .map_err(|e| ExecutionError::EvmEnv(e.to_string()))?;

        // At the Zenith (EIP-8130) transition, plant a code stub on the code-less
        // enshrined system accounts (the 2D nonce manager) so the persistent state
        // the enshrined path writes to them is not reaped by EIP-161 end-of-block
        // state clearing.
        ensure_eip8130_system_accounts(spec, self.pending_block.timestamp, self.evm.db_mut())
            .map_err(|e| ExecutionError::EvmEnv(e.to_string()))?;

        Ok(())
    }

    /// Installs the `BaseTime` implementation and links its existing proxy before transactions.
    ///
    /// Existing chains must already contain the reserved proxy runtime with
    /// [`Predeploys::PROXY_ADMIN`] in its EIP-1967 admin slot. This transition validates that
    /// historical invariant; it does not install or repair proxy state.
    ///
    /// The transition is staged behind the `Denim` activation condition. The implementation slot
    /// is the durable migration marker: any existing linkage is preserved so later execution cannot
    /// rewrite the initial deployment or undo a governance upgrade.
    pub fn ensure_predeploy<DB>(
        chain_spec: impl Upgrades,
        timestamp: u64,
        db: &mut DB,
    ) -> Result<(), BaseTimeTransitionError<DB::Error>>
    where
        DB: Database + DatabaseCommit,
    {
        if !chain_spec.is_denim_active_at_timestamp(timestamp) {
            return Ok(());
        }

        let expected_implementation = U256::from_be_slice(Self::IMPLEMENTATION_ADDRESS.as_slice());
        let current_implementation =
            db.storage(Predeploys::BASE_TIME, Self::IMPLEMENTATION_SLOT)?;
        if current_implementation != U256::ZERO {
            return Ok(());
        }

        let proxy_info =
            db.basic(Predeploys::BASE_TIME)?.ok_or(BaseTimeTransitionError::MissingProxy)?;
        if proxy_info.is_empty_code_hash() {
            return Err(BaseTimeTransitionError::CodelessProxy);
        }

        let current_admin = db.storage(Predeploys::BASE_TIME, Self::ADMIN_SLOT)?;
        if current_admin != U256::from_be_slice(Predeploys::PROXY_ADMIN.as_slice()) {
            return Err(BaseTimeTransitionError::UnexpectedProxyAdmin { actual: current_admin });
        }
