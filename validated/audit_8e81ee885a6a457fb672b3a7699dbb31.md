## Title
`InitializeNonceAccount` lacks a signer check on the nonce account, enabling front-run takeover of durable-nonce authority - (File: `programs/system/src/system_instruction.rs`)

### Summary
The system program's `InitializeNonceAccount` handler sets the durable-nonce authority for an account without ever verifying that the account (or its owner) actually signed the transaction. Any account sitting in `Uninitialized` nonce state with a rent-exempt balance can be "claimed" by an attacker who submits an `InitializeNonceAccount` instruction naming themselves as authority, exactly analogous to the zAuction `init()` front-running bug in the source report.

### Finding Description
`initialize_nonce_account` only checks that the target account is writable and in `State::Uninitialized`, and that it has sufficient lamports for rent-exemption — it never checks a signers set: [1](#0-0) 

This is in stark contrast to the sibling functions in the same file/module, which do enforce signer checks before mutating account state, e.g. `allocate`/`assign` require `address.is_signer(signers)`: [2](#0-1) 

and `withdraw_nonce_account`/`advance_nonce_account` require the current `data.authority` to be a signer before mutating state: [3](#0-2) 

The dispatcher in `system_processor.rs` confirms no signer set is threaded into the initialize path — it just fetches the account, checks the `RecentBlockhashes` and `Rent` sysvars, and calls `initialize_nonce_account`, taking the `authorized` pubkey directly from unauthenticated instruction data: [4](#0-3) 

Because the target nonce account itself is not required to sign, whoever's `InitializeNonceAccount` instruction lands *first* against a given uninitialized, rent-exempt, correctly-sized account wins control of that account's `authority` field — regardless of who created or funded it. This mirrors the reported zAuction pattern: an unprotected initializer that "can be called by anyone," is racy/front-runnable, and only reveals the compromise when the legitimate initializer's later call fails.

A durable-nonce account is commonly created via `CreateAccountWithSeed` (deterministic address derived from a public base key + seed) so its address can be computed off-chain by an observer before the initialize instruction lands, or simply observed via any two-step (non-atomic) create+initialize submission flow. Once an attacker's `InitializeNonceAccount(attacker_pubkey)` instruction confirms first, the attacker becomes `data.authority` and can subsequently call `WithdrawNonceAccount` and pass the authority signer check, then drain the account's lamports to a destination of their choice: [5](#0-4) 

### Impact Explanation
An attacker who wins the initialization race gains full nonce authority over lamports that were funded by another party, and can subsequently withdraw those lamports via `WithdrawNonceAccount` to an address of their choosing — this is a concrete unsigned/unauthorized fund movement, reachable from a single unprivileged transaction with no special leader or validator conditions.

### Likelihood Explanation
Exploitation requires (1) a target account that is system-owned, correctly sized for nonce state, rent-exempt-funded, and still `Uninitialized`, and (2) the attacker's `InitializeNonceAccount` instruction landing before the legitimate owner's. This is most practical when create-and-initialize are submitted as separate transactions, or when the nonce address is derivable in advance (e.g. `CreateAccountWithSeed`) and observable before confirmation — a realistic but not universal usage pattern, since the common `system_instruction::create_nonce_account` helper bundles create+initialize atomically in one transaction, which is not racy. Likelihood is therefore moderate: it depends on client/tooling behavior rather than being universally exploitable against all nonce account creations.

### Recommendation
Require the nonce account itself (or a designated creator/funder) to be a transaction signer inside `initialize_nonce_account`, consistent with the signer checks already present in `allocate`, `assign`, `advance_nonce_account`, and `withdraw_nonce_account`. This closes the front-running window regardless of whether create and initialize are submitted atomically.

### Proof of Concept
1. Victim funds and allocates a system-owned account `N` sized for nonce state (e.g. via `CreateAccountWithSeed`, address deterministically derivable from a known base key/seed), intending to send a subsequent `InitializeNonceAccount(victim_authority)` transaction for `N`.
2. Attacker observes/derives `N`'s address before the victim's initialize transaction confirms and submits their own transaction containing `SystemInstruction::InitializeNonceAccount(attacker_authority)` targeting `N`; this succeeds because `initialize_nonce_account` never checks that `N` or the victim signed — only writability, state, and rent are checked (`programs/system/src/system_instruction.rs:163-201`).
3. The victim's subsequent initialize transaction now fails since `N`'s state is `Initialized` (`programs/system/src/system_instruction.rs:202-209`), and the attacker calls `WithdrawNonceAccount` signed with `attacker_authority`, passing the `check_signer(&data.authority)` check (`programs/system/src/system_instruction.rs:99-150`), draining `N`'s lamports to an attacker-controlled account.

pub(crate) fn withdraw_nonce_account(
    from_account_index: IndexOfAccount,
    lamports: u64,
    to_account_index: IndexOfAccount,
    rent: &Rent,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
    instruction_context: &InstructionContext,
) -> Result<(), InstructionError> {
    let mut from = instruction_context.try_borrow_instruction_account(from_account_index)?;
    if !from.is_writable() {
        ic_msg!(
            invoke_context,
            "Withdraw nonce account: Account {} must be writeable",
            from.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let check_signer = |signer: &Pubkey| {
        if !signers.contains(signer) {
            ic_msg!(
                invoke_context,
                "Withdraw nonce account: Account {} must sign",
                signer
            );
            return Err(InstructionError::MissingRequiredSignature);
        }
        Ok(())
    };

    let state: Versions = from.get_state()?;
    match state.state() {
        State::Uninitialized => {
            if lamports > from.get_lamports() {
                ic_msg!(
                    invoke_context,
                    "Withdraw nonce account: insufficient lamports {}, need {}",
                    from.get_lamports(),
                    lamports,
                );
                return Err(InstructionError::InsufficientFunds);
            }
            check_signer(from.get_key())?;
        }
        State::Initialized(data) => {
            if lamports == from.get_lamports() {
                let durable_nonce =
                    DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
                if data.durable_nonce == durable_nonce {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: nonce can only advance once per slot"
                    );
                    return Err(SystemError::NonceBlockhashNotExpired.into());
                }
                check_signer(&data.authority)?;
                from.set_state(&Versions::new(State::Uninitialized))?;
            } else {
                let min_balance = rent.minimum_balance(from.get_data().len());
                let amount = checked_add(lamports, min_balance)?;
                if amount > from.get_lamports() {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: insufficient lamports {}, need {}",
                        from.get_lamports(),
                        amount,
                    );
                    return Err(InstructionError::InsufficientFunds);
                }
                check_signer(&data.authority)?;
            }
        }
    };

    from.checked_sub_lamports(lamports)?;
    drop(from);
    let mut to = instruction_context.try_borrow_instruction_account(to_account_index)?;
    to.checked_add_lamports(lamports)?;

    Ok(())
