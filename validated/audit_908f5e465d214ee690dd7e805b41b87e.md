## Title
Confirmations from removed multisig members remain counted toward the confirmation threshold, allowing a request to execute below the configured `K`-of-`N` quorum - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only purges requests that were *created* by the removed member; it does not scrub that member's *confirmations* on requests created by other members. Because `confirm()` counts entries in the stored confirmation `HashSet<String>` without verifying that each entry is still a live member, a stale confirmation from a deleted member is counted as if it were a valid, current signature, letting a request execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
The binding that must hold is:
`live_member_confirmations(request) >= num_confirmations` before `execute_request` runs.

In `confirm()`, the threshold check only compares the *size* of the stored confirmation set against `num_confirmations`, with no re-validation that every string in that set still corresponds to a current member: [1](#0-0) 

`delete_member` removes requests keyed by `r.member == member` (i.e., requests *originated* by the removed member) and clears `num_requests_pk` for that member, but never inspects or cleans the `confirmations` map for requests created by *other* members that the removed member had already confirmed: [2](#0-1) 

Consequently, a request created by member `A` and confirmed by member `B` retains `B`'s entry in its `confirmations` set even after `B` is later removed via a separate `DeleteMember` action. When two more *live* members confirm afterward, `confirm()` sees `len() + 1 >= num_confirmations` and executes the request, even though only two currently-live members actually approved it.

### Impact Explanation
This breaks the core multisig guarantee "K of N *current* members must approve before any action executes." It directly matches the "a multisig request executed below threshold" Critical impact category: transfers, `FunctionCall`s, key additions, or further membership changes can be pushed through with fewer live approvals than configured, undermining the security assumption that funds/authority controlled by the multisig require `K` genuine, current signers.

### Likelihood Explanation
Membership changes (removing a departing employee, rotating a compromised key, revoking a partner) are a normal, expected multisig operation, and it is entirely plausible for a member to have an unconfirmed vote pending on some request at the time they are removed. No malicious member action is required — an ordinary churn event (add request → partial confirm → unrelated member removal → remaining confirmations) is enough to leave a "ghost" confirmation counted toward quorum.

### Recommendation
When executing `DeleteMember`, iterate all active requests' confirmation sets and remove any entry matching the deleted member's `to_string()` representation (not just requests the member originated). Alternatively, validate at `confirm()` time that every entry in the confirmation set still corresponds to a current member of `self.members`, discarding stale entries (or recomputing the live count) before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new([A, B, C, D], 3)`.
2. `A` calls `add_request` with a `Transfer` action → `request_id = R1`, confirmations = `{}`.
3. `B` calls `confirm(R1)` → `confirmations(R1) = {B}` (1 < 3, not executed).
4. Separately, `A`, `C`, `D` fully confirm a `DeleteMember { member: B }` request → `B` is removed from `self.members`; since `B` did not create `R1`, `delete_member`'s cleanup (`r.member == member`, matching `A`) never touches `R1` or its confirmation set, so `confirmations(R1)` still equals `{B}`. [3](#0-2) 
5. `C` calls `confirm(R1)` → `len()+1 = 2 < 3` → `confirmations(R1) = {B, C}`.
6. `D` calls `confirm(R1)` → `len()+1 = 3 >= 3` → `execute_request` runs the `Transfer`. [4](#0-3) 
7. Result: `R1` executed with only `C` and `D` as live confirming members plus a stale confirmation from removed member `B` — 2 live confirmations satisfied a nominal `3`-confirmation threshold, violating the multisig's quorum guarantee.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
