### Title
StepRunnerStream passthrough mode bypasses phrase/URL/token masking for pre-stamped step-runner output - ([File: common/buildlogger/build_logger.go])

### Summary
The question's specific claim that `Build.executeStepStage` and the `steps.JobInfo{...}` literal live in `common/build_step_dispatch.go` does not match the code: that file only contains `stepDispatch` and `stagesToConcreteStep`, neither of which builds `steps.JobInfo{ID: ..., ProjectDir: ..., Variables: b.GetAllVariables()}` [1](#0-0) [2](#0-1) . However, investigating the real sink named in the question — `StepRunnerStream` — reveals a genuine masking bypass: when step-runner output is detected as "pre-stamped" and `Timestamping` is enabled, the writer chooses a raw `passthrough` path that skips the masker, URL sanitizer, and token sanitizer entirely [3](#0-2) [4](#0-3) .

### Finding Description
`StepRunnerStream` builds a `stepRunnerStream` with three candidate writers: `passthrough` (`internal.NewSync(l.base)` — no filters at all), `buildStripped` (demuxes inner stream and routes through the normal `wrap` chain, which includes masker/urlsanitizer/tokensanitizer), and `buildWrapped` (the normal `wrap` chain) [5](#0-4) . `pickMode` selects `passthrough` whenever the first written chunk satisfies `isPreStamped` (matches an RFC3339-like timestamp header shape) **and** `l.timestamping` is true [4](#0-3) . In the `passthrough` branch, bytes go straight to `l.base` — bypassing `masker.New`, `urlsanitizer.New`, and `tokensanitizer.New` that are otherwise always applied in `wrap` [6](#0-5) .

Step-runner steps such as `builtin://script_legacy` execute attacker-supplied script content built from job-defined `script` inputs and `build.GetAllVariables()`-derived environment [7](#0-6) . If a job script simply echoes a masked/secret variable (e.g. `echo $SOME_SECRET`) and step-runner emits its own timestamp-stamped line for that stdout (which it does whenever line-level stamping is active), the resulting line satisfies `isPreStamped`. If the Runner's own `Timestamping` option is also enabled, `pickMode` picks `passthrough`, and the entire line — secret value included — is written to the trace without ever going through the masker/token sanitizer. This is a concrete violation of the invariant "secrets/masked values must not leak ... through traces."

### Impact Explanation
An unprivileged pipeline author who can supply a script step (or any builtin step whose `Inputs` cause it to echo a variable) can get a masked CI/CD variable, `CI_JOB_TOKEN`-derived, or other secret written verbatim to the visible job trace, when the runner has `Timestamping` enabled and the step-runner backend emits pre-stamped stdout for that line. This is trace-level secret disclosure within the attacker's own job/project — it does not by itself grant cross-project access, but it defeats the masking invariant that Runner otherwise guarantees for every other output path.

### Likelihood Explanation
Preconditions: (1) Runner configured/feature-flagged with `Timestamping` on for the build logger, (2) the executed step is a step-runner-backed stage (e.g. `stepRunBuildStage`/`script_legacy`) whose stdout line happens to match the 28-byte pre-stamp header shape produced by step-runner itself. Both conditions are plausible in normal shell/step usage and are not attacker-exotic; the attacker only needs to control what a step echoes (trivial via `script:` in `.gitlab-ci.yml` using a masked variable). No existing check re-applies masking on the passthrough path, so once the mode is selected there is no mitigation.

### Recommendation
Never fully bypass masking/token/URL sanitization for step-runner output, even in the "pre-stamped" passthrough case. At minimum, run the masker/tokensanitizer/urlsanitizer chain over the payload portion of pre-stamped lines before forwarding them to `l.base`, rather than routing raw bytes directly through `internal.NewSync(l.base)`.

### Proof of Concept
Go unit test in `common/buildlogger`:
1. Construct a `Logger` via `New(...)` with `Options{Timestamping: true, MaskPhrases: []string{"SECRET_VALUE"}}`.
2. Call `Stream := logger.StepRunnerStream(0, Stdout)`.
3. Write a byte slice that satisfies `isPreStamped` (a valid RFC3339Z header followed by a space) and includes `"SECRET_VALUE"` in the remainder of the line.
4. Assert that the underlying trace/base writer output still contains the literal `"SECRET_VALUE"` unmasked (proving bypass), whereas writing the same payload through `logger.Stream(0, Stdout)` (the normal wrap chain) masks it as `[MASKED]` or similar.
5. Expected assertion failure demonstrates that `StepRunnerStream`'s passthrough path does not apply the same masking guarantees as the standard trace path.

Note: I was unable to confirm within the available index the exact contents of `common/build.go`'s `executeStepStage` (the grep pattern errored and I could not re-run it before the tool budget ended), so I cannot confirm the precise `steps.JobInfo{...}` literal or line numbers cited in the question, nor whether `GetAllVariables()` is filtered before being handed to the step-runner backend. The masking-bypass mechanism confirmed above is independent of that and stands on its own in `common/buildlogger/build_logger.go`.

func (l *Logger) StepRunnerStream(streamID int, streamType StreamType) io.WriteCloser {
	if l.base == nil {
		return internal.NewNopCloser(io.Discard)
	}

	return &stepRunnerStream{
		timestamping: l.timestamping,
		passthrough:  internal.NewSync(l.base),
		buildStripped: func() io.WriteCloser {
			return newInnerStreamStripper(
				l.wrap(l.base, streamID, Stdout),
				l.wrap(l.base, streamID, Stderr),
			)
		},
		buildWrapped: func() io.WriteCloser {
			return l.wrap(l.base, streamID, streamType)
		},
	}
}

func (s *stepRunnerStream) pickMode(p []byte) func() {
	return func() {
		switch {
		case isPreStamped(p) && s.timestamping:
			s.chosen = s.passthrough
		case isPreStamped(p):
			s.chosen = s.buildStripped()
		default:
			s.chosen = s.buildWrapped()
		}
	}
}

func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {
		w = timestamper.New(w, timestamper.StreamType(streamType), uint8(streamID), true)
	}

	w = tokensanitizer.New(w, l.maskTokenPrefixes)
	w = urlsanitizer.New(w)
	w = masker.New(w, l.maskPhrases)
	w = internal.NewSync(w)

	return w
}
