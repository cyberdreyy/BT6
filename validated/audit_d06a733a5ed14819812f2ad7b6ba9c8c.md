### Title
Unbounded, unabortable materialization of secondary-index pubkeys in `AccountsDb::index_scan_accounts` allows attacker-authored account count to drive CPU/memory cost of a single `getProgramAccounts`/`getTokenAccountsByOwner`/`getTokenAccountsByMint` call - ([File: accounts-db/src/accounts_db.rs])

### Summary
`AccountsDb::index_scan_accounts` calls `self.accounts_index.get_index_key_pubkeys(&index_key)` to obtain the full set of pubkeys mapped to a secondary index key (ProgramId/SplTokenMint/SplTokenOwner) *before* entering the loop that checks `config.is_aborted()`. Because `get_index_key_pubkeys` -> `SecondaryIndex::get` -> `RwLockSecondaryIndexEntry::keys()` eagerly clones every inner pubkey into a `Vec<Pubkey>` under a `RwLock` read guard, an attacker who registers many small on-chain accounts sharing one owner/mint/program key can force a single low-rate RPC call to allocate and iterate an arbitrarily large `Vec<Pubkey>` and hold the corresponding lock, with no size limit applied at this stage — `ScanConfig::abort()` cannot interrupt this step at all, and even once the per-pubkey loop starts, the `byte_limit_for_scan` abort only fires after the accumulated *account data* size passes a threshold, not based on the number of accounts scanned.

### Finding Description
The RPC methods `getProgramAccounts` (with `AccountIndex::ProgramId`), `getTokenAccountsByOwner` (`AccountIndex::SplTokenOwner`), and `getTokenAccountsByMint` (`AccountIndex::SplTokenMint`) route through `JsonRpcRequestProcessor::get_filtered_indexed_accounts` [1](#0-0) , which calls `Bank::get_filtered_indexed_accounts` [2](#0-1) , which calls `Accounts::load_by_index_key_with_filter` [3](#0-2) , which calls `AccountsDb::index_scan_accounts` [4](#0-3) .

`ScanConfig::abort()`/`is_aborted()` [9](#0-8)  is only consulted inside the `for` loop and inside `Accounts::accumulate_and_check_scan_result_size`, which itself is only invoked (and only sets the abort flag) once `byte_limit_for_scan` accumulated *account payload bytes* exceed the configured `scan_results_limit_bytes` [10](#0-9) [11](#0-10) . If `scan_results_limit_bytes` is unset (`None`), `accumulate_and_check_scan_result_size` unconditionally returns `false` and the scan is never aborted at all [12](#0-11) .

Attacker inputs: the attacker (unprivileged client) simply submits normal transactions to create many small accounts (e.g., zero/low-lamport, minimal-data SPL token accounts or arbitrary program-owned accounts) all sharing the same mint, owner, or program-id pubkey. This is on-chain data the attacker fully controls and requires no privileged access. They then send a single `getTokenAccountsByOwner`/`getTokenAccountsByMint`/`getProgramAccounts` (with `account_indexes` enabled by the operator) RPC call at any rate ≤ one call per `CLUSTER_SLOT_TIME_TARGET / 2`.

Why existing checks fail:
- The `byte_limit_for_scan`/`scan_results_limit_bytes` guard bounds only the sum of returned account *data*, and is checked lazily per matched account inside `scan_func`; it never bounds (a) the initial `Vec<Pubkey>` materialization cost, which is proportional to the total number of accounts ever indexed under that key, or (b) the number of `do_load` calls issued for accounts that are filtered out by `filter(account)` (which happens before `accumulate_and_check_scan_result_size` runs, since `load_while_filtering` only accumulates size for accounts that pass the filter).
- `RwLockSecondaryIndexEntry::keys()` has no cap and is not interruptible, so its cost is strictly determined by attacker-authored account count, not by any validator-side limit.

### Impact Explanation
This falls under "unbounded CPU/memory hold... during a single low-rate call," matching Agave's RPC DoS bounty category for a single client issuing at most one call per `CLUSTER_SLOT_TIME_TARGET / 2`. A single call can force the JSON-RPC blocking thread to allocate a `Vec<Pubkey>` sized to the number of attacker-created accounts (32 bytes/pubkey plus allocator overhead) and to then issue one `do_load` (storage lookup) per pubkey for however many entries pass the filter before the byte-limit abort (if configured at all) trips — with the initial enumeration cost entirely unbounded regardless of that config. This can degrade RPC responsiveness and consume validator memory disproportionate to any explicit request-side limit.

### Likelihood Explanation
Preconditions: the validator operator must have enabled the relevant secondary account index (`--account-index program-id` / `spl-token-owner` / `spl-token-mint`), which is a supported, non-default but commonly-used configuration for RPC nodes serving `getProgramAccounts`/`getTokenAccountsBy*`. Given that, the attack is fully reproducible by any unprivileged client: create N small accounts sharing an index key (cheap, since minimum-rent accounts are inexpensive), then issue one `getProgramAccounts`/`getTokenAccountsByOwner`/`getTokenAccountsByMint` call. No operator misconfiguration beyond "index enabled" is required, and the effect scales linearly (or worse, given lock contention) with attacker-controlled N. Note: if `scan_results_limit_bytes` is unset (RPC default `JsonRpcConfig::scan_results_limit_bytes: None`), there is no server-side scan abort at all for this path.

### Recommendation
- Bound the size of `get_index_key_pubkeys` results before materializing them into a `Vec` — e.g., stream/iterate the underlying `DashMap`/`HashSet` entries directly with an early-exit closure rather than collecting all keys up front, so `config.is_aborted()` (or a new pubkey-count limit) can interrupt enumeration itself.
- Introduce an explicit, always-enforced cap (independent of `scan_results_limit_bytes`) on the number of pubkeys/`do_load` calls processed per `index_scan_accounts` invocation, checked incrementally, not only on accumulated byte size of matched results.
- Ensure the byte/count limit is enforced even when accounts are filtered out by `filter()`, since currently only accounts that pass the filter increment `sum`.

        account_indexes: spl_token_mint_index_enabled(),
        ..AccountsDb::new_for_tests_with_config(Vec::new(), DEFAULT_ACCOUNTS_DB_CONFIG)

    account_data[SPL_TOKEN_INITIALIZED_OFFSET] = 1;

    // Attacker creates a large number (N) of minimal accounts under one mint key.
    const N: usize = 2_000_000; // attacker-controlled, unbounded by any RPC parameter
    for _ in 0..N {
        let pubkey = Pubkey::new_unique();
        let mut acct = AccountSharedData::new(1, account_data.len(), &spl_generic_token::token::id());
        acct.set_data(account_data.clone());
        db.store_for_tests((1, &[(&pubkey, &acct)][..]));
    }
    db.add_root_and_flush_write_cache(1);

    // No byte_limit_for_scan configured -> ScanConfig never aborts.
    let config = ScanConfig::default().recreate_with_abort();
    let start = Instant::now();
    let mut count = 0usize;
    db.index_scan_accounts(
        &Ancestors::default(),
        0,
        IndexKey::SplTokenMint(mint_key),
        |maybe_account| {
            if maybe_account.is_some() {
                count += 1;
            }
        },
        &config,
    )
    .unwrap();
    let elapsed = start.elapsed();

    // EXPECTED (bug): elapsed time and memory grow linearly with N, unbounded by
    // any request parameter — this assertion currently fails to hold to a fixed
    // bound as N grows, demonstrating cost is dictated by attacker-authored state.
    assert_eq!(count, N);
    assert!(
        elapsed.as_secs() < 1,
        "index_scan_accounts took {elapsed:?} for N={N} accounts; cost is unbounded by request params"
    );
}

    pub(crate) fn index_scan_accounts<F>(
        &self,
        ancestors: &Ancestors,
        bank_id: BankId,
        index_key: IndexKey,
        mut scan_func: F,
        config: &ScanConfig,
    ) -> ScanResult<bool>
    where
        F: FnMut(Option<(&Pubkey, AccountSharedData, Slot)>),
    {
        let key = match &index_key {
            IndexKey::ProgramId(key) => key,
            IndexKey::SplTokenMint(key) => key,
            IndexKey::SplTokenOwner(key) => key,
        };
        if !self.account_indexes.include_key(key) {
            // the requested key was not indexed in the secondary index, so do a normal scan
            let used_index = false;
            self.scan_accounts(ancestors, bank_id, scan_func, config)?;
            return Ok(used_index);
        }

        // Register this scan so that slots needed by the scan are not cleaned out from under us.
        let scan_guard = ScanGuard::try_new(&self.scan_tracker, bank_id, || self.max_root())
            .ok_or(ScanError::SlotRemoved {
                slot: ancestors.max_slot(),
                bank_id,
            })?;

        // If the scan's ancestors are all rooted, drop them and scan roots only
        // Scan Guard max root must be used as the scan guard guarantees that
        // the account state as of max root is persisted in the database
        let max_root_ancestors = Ancestors::from(vec![scan_guard.max_root()]);
        let ancestors = if scan_guard.should_use_ancestors(ancestors) {
            ancestors
        } else {
            &max_root_ancestors
        };

        for pubkey in self.accounts_index.get_index_key_pubkeys(&index_key) {
            if config.is_aborted() {
                break;
            }
            if let Some((account, slot)) = self.do_load(
                ancestors,
                &pubkey,
                LoadHint::Unspecified,
                PopulateReadCache::False,
            ) {
                scan_func(Some((&pubkey, account, slot)));
            }
        }

        // Check whether the bank was removed while the scan was in progress.
        if scan_guard.was_scan_corrupted() {
            return Err(ScanError::SlotRemoved {
                slot: ancestors.max_slot(),
                bank_id,
            });
        }
        let used_index = true;
        Ok(used_index)
    }

#[derive(Debug, Default)]
pub(crate) struct ScanConfig {
    /// checked by the scan. When true, abort scan.
    pub(crate) abort: Option<Arc<AtomicBool>>,
}

impl ScanConfig {
    /// mark the scan as aborted
    pub(crate) fn abort(&self) {
        if let Some(abort) = self.abort.as_ref() {
            abort.store(true, Ordering::Relaxed)
        }
    }

    /// use existing 'abort' if available, otherwise allocate one
    pub(crate) fn recreate_with_abort(&self) -> Self {
        ScanConfig {
            abort: Some(self.abort.clone().unwrap_or_default()),
        }
    }

    /// true if scan should abort
    pub(crate) fn is_aborted(&self) -> bool {
        if let Some(abort) = self.abort.as_ref() {
            abort.load(Ordering::Relaxed)
        } else {
            false
        }
    }
