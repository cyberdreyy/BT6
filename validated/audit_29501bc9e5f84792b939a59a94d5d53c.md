### Title
Zip extraction in `ExtractZipArchive` performs no path-containment validation, allowing absolute/traversal `zip.File.Name` entries to reach `os.MkdirAll`, file writes, and `processZipUIDGidField`'s `os.Lchown` outside the extraction root - (File: `helpers/archives/zip_extract.go`, `helpers/archives/zip_extra_unix.go`)

### Summary
`ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`, `lchmod`, `processZipUIDGidField`) use `file.Name` from the zip archive verbatim, with no `filepath.Clean`/prefix check against an extraction root anywhere in the chain. The only path-related check, `errorIfGitDirectory` / `isPathAGitDirectory` in `helpers/archives/path_check_helper.go`, only rejects names whose first cleaned path segment is `.git` and performs no traversal or absolute-path validation.

### Finding Description
`ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`) iterates `archive.File` and only calls `errorIfGitDirectory(file.Name)` before extraction; that function (`helpers/archives/path_check_helper.go:13-19`) only checks `parts[0] == ".git"` after `filepath.Clean`, so any other absolute path (e.g. `/tmp/x`) or relative path with `../` segments passes untouched. `extractZipFile` (`helpers/archives/zip_extract.go:61-83`) then does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and, depending on file type, `os.OpenFile(file.Name, ...)` (`extractZipFileEntry`) or `os.Symlink(...)` (`extractZipSymlinkEntry`) directly on `file.Name` — never joined with, or checked against, any extraction root/working directory. In the second loop, `lchmod(file.Name, ...)` and `processZipExtra` → `processZipUIDGidField(data, file)` (`helpers/archives/zip_extra_unix.go:37-48`) call `os.Lchown(file.Name, uid, gid)` on that same unchecked path.

Critically, unlike the sibling `tarzstd` extractor (`commands/helpers/archive/tarzstd/tarzstd_extractor.go:57-64`), which explicitly computes `path = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it if it escapes `e.dir`, `ExtractZipArchive` never receives or uses an extraction-root parameter at all — the `dir` field on `ziplegacy.extractor` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:12-32`) is stored but never passed into `archives.ExtractZipArchive`. Extraction is entirely dependent on the process's current working directory for relative names, and completely unconstrained for absolute names. This is corroborated by the test comment "hack: legacy archiver require being in the correct working dir" in `commands/helpers/archiver_test.go:68`.

An attacker (pipeline author) controls artifact/cache zip contents, so a crafted `zip.File{Name: "/etc/passwd"}` or `Name: "../../../../etc/passwd"` reaches `os.MkdirAll`, file write/symlink creation, `lchmod`, and `os.Lchown` with no containment check anywhere in this call chain.

### Impact Explanation
Any job producing an artifact/cache zip that is later restored via the legacy zip extractor can write files, create symlinks, or change ownership/mode at an attacker-chosen absolute or traversal-resolved host path (e.g. a shared file used by other jobs/runner processes), scoped as file/ownership corruption on the runner host reachable purely through job-controlled archive content.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs to control the artifact/cache zip's raw entries (achievable by hand-crafting a zip, since `archive/zip`'s `Writer` does not itself prevent arbitrary `Name` values, or via any tool that writes a zip without extractor-side validation) and have that zip processed by the ziplegacy extraction path (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go` → `archives.ExtractZipArchive`) used by `commands/helpers/artifacts_downloader.go` / `commands/helpers/cache_extractor.go`. No authentication or privilege escalation is required beyond normal job/artifact submission.

### Recommendation
Add a real containment check in the zip extraction path: pass the intended extraction root into `ExtractZipArchive`/`extractZipFile`, compute `filepath.Join(root, file.Name)`, and reject (or clamp) any resulting path that is not a descendant of `root` (mirroring the check already present in `tarzstd_extractor.go`) before any `MkdirAll`, file write, symlink creation, `lchmod`, or `os.Lchown` call. This should be independent of / in addition to the unrelated `.git`-specific check in `errorIfGitDirectory`.

### Proof of Concept
```go
func TestExtractZipArchive_RejectsAbsoluteAndTraversalPaths(t *testing.T) {
    tmp := t.TempDir()
    target := filepath.Join(t.TempDir(), "victim") // simulate a host path outside extraction root

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    // Absolute path escape
    w, _ := zw.Create(target)
    w.Write([]byte("pwned"))
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    origWD, _ := os.Getwd()
    _ = os.Chdir(tmp)
    defer os.Chdir(origWD)

    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err) // currently succeeds silently - demonstrates the bug

    // Expected (post-fix) assertion: file must NOT be written outside tmp
    _, statErr := os.Stat(target)
    require.True(t, os.IsNotExist(statErr), "extraction escaped the intended root: %s was created", target)
}
```
Run against current code: the file is written to `target` (outside `tmp`) and no error is returned, confirming the missing containment check. A fix should make `os.Stat(target)` return `IsNotExist` (or `ExtractZipArchive` should return an error for the escaping entry).
