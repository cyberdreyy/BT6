### Title
Malformed/out-of-project `exclude` pattern silently disables all *subsequent* exclude checks for a file, causing intended-exclusions to leak into the persisted artifact - (`File: commands/helpers/file_archiver.go`)

### Summary
`fileArchiver.isExcluded` iterates over `c.Exclude` patterns and calls `findRelativePathInProject` on each pattern. If any single pattern fails to resolve relative to the working directory (e.g. it is malformed, absolute, or escapes the project root with `..`), the function immediately `return false, ""` from inside the loop instead of continuing to check the remaining patterns. This means one "bad" exclude entry silently short-circuits and effectively disables all other exclude rules for that file, so files that should have been excluded (e.g. `.git/config`, `.env`, credentials) get archived and uploaded as a persistent job artifact.

### Finding Description
In `commands/helpers/file_archiver.go`: [1](#0-0)

```go
func (c *fileArchiver) isExcluded(path string) (bool, string) {

		if err != nil {
			logrus.Warningf("isExcluded: %v", err.Error())

		...
	}

```

`c.Exclude` is directly attacker-controlled: it comes from the `artifacts.exclude` field in `.gitlab-ci.yml`, is expanded via `spec.ArtifactExclude` and passed through `functions/concrete/run/stages/artifact_upload.go`'s `archiverArgs()` as repeated `--exclude` flags to `gitlab-runner-helper artifacts-uploader`, which populates `fileArchiver.Exclude` in `commands/helpers/artifacts_uploader.go`. [2](#0-1) 

The per-pattern `findRelativePathInProject` call returns an error whenever a pattern is absolute or resolves outside the working directory (`rel == ".."` or begins with `"../"`), as demonstrated by the existing tests `no match - pattern not in project` and `no match - absolute pattern not in project`. [3](#0-2) [4](#0-3) 

Because `isExcluded` is called per candidate file inside `process()`, and the loop `return`s on the *first* pattern that errors rather than `continue`-ing, the order of patterns in `Exclude` matters: if a job author (or malicious/careless CI config, e.g. via a templated/`include:`-supplied fragment, or attacker-influenced `inputs`/variables used to build the exclude list) places any single malformed/out-of-root pattern before a legitimate exclude pattern such as `**/.git/config` or `**/*.env`, the legitimate pattern is never evaluated for that file and the file is not excluded — it proceeds to `c.add(relative)` and is archived. Existing tests only cover a single-pattern list per case, so this multi-pattern ordering defect is untested and unnoticed. [5](#0-4) 

### Impact Explanation
Any file matched by legitimate `exclude` patterns (e.g. `.git/config` containing embedded remote credentials, `.env` secrets, `id_rsa`, etc.) can end up bundled into the uploaded artifact archive whenever the `exclude` list also contains — anywhere before the intended pattern — one entry that is absolute, uses `..`, or otherwise fails `findRelativePathInProject`. Artifacts persist beyond job completion and remain downloadable by any project member with artifact-download permission, so this is a persistence/exposure surface distinct from a one-job DoS, matching the scoped impact in the question.

### Likelihood Explanation
Trigger requires only a `.gitlab-ci.yml`/CI config with an `artifacts.exclude` list containing more than one pattern, where a pattern earlier in the list is malformed or points outside the project directory (easy to happen accidentally with a mistyped absolute path, an `inputs`-expanded value that resolves to `../something`, or deliberately, by a pipeline author or a compromised included template). This is fully reachable by any project member able to edit or influence CI config — no elevated Runner privileges are needed — and is 100% repeatable given a fixed exclude-pattern order.

### Recommendation
Change the early `return false, ""` on a per-pattern resolution error into a `continue` to the next pattern, and only warn per bad pattern instead of aborting evaluation of the remaining exclude list:
```go
for _, pattern := range c.Exclude {
    relPattern, err := c.findRelativePathInProject(pattern)
    if err != nil {
        logrus.Warningf("isExcluded: %v", err.Error())
        continue
    }
    ...
}
return false, ""
```

```go
func (c *fileArchiver) isExcluded(path string) (bool, string) {
	// Both path and pattern need to be normalized with filepath.ToSlash().
	// Matching will fail with Windows machines using "\\" path separators and patterns with "/" path separators
	path = filepath.ToSlash(path)
	for _, pattern := range c.Exclude {
		relPattern, err := c.findRelativePathInProject(pattern)
		if err != nil {
			logrus.Warningf("isExcluded: %v", err.Error())
			return false, ""
		}
		relPattern = filepath.ToSlash(relPattern)
		excluded, err := doublestar.Match(relPattern, path)
		if err == nil && excluded {
			return true, pattern
		}
	}

	return false, ""
}
```

```go
func (c *fileArchiver) findRelativePathInProject(path string) (string, error) {
	slashPath := filepath.ToSlash(path)
	if filepath.Clean(slashPath) == filepath.Clean(c.wd) {
		return ".", nil
	}

	base, patt := slashPath, ""
	// check if path contains a glob pattern
	if strings.ContainsAny(slashPath, "*?[{") {
		base, patt = doublestar.SplitPattern(slashPath)
	}

	abs, err := filepath.Abs(base)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact absolute path %s: %w", path, err)
	}

	rel, err := filepath.Rel(c.wd, abs)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact relative path %s: %w", path, err)
	}

	// If fully resolved relative path begins with ".." it is not a subpath of our working directory
	if strings.HasPrefix(rel, ".."+string(filepath.Separator)) || rel == ".." {
		return "", fmt.Errorf("artifact path is not a subpath of project directory: %s", path)
	}

	// Relative path is needed now that our fsys "root" is at the working directory
	rel = filepath.Join(rel, patt)
	rel = filepath.FromSlash(rel)
	return rel, nil
```
