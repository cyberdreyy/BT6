### Title
Unprivileged Former Package Owner Can Seize `DisplayCap<T>` on System-Migrated `Display<T>` via Missing Publisher Check in `claim` — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

---

### Summary

`claim` accepts any `LegacyDisplay<T>` as proof of ownership without verifying the caller is the *current* package owner. Because `LegacyDisplay<T>` (`sui::display::Display<T>`) carries `has key, store`, it is a freely transferable Sui object. A former package owner who retained (or received) a `LegacyDisplay<T>` before transferring the `Publisher` can call `claim` on a system-migrated `Display<T>` (where `cap_id` is `None`) and permanently seize the `DisplayCap<T>`, locking the legitimate current owner out forever.

---

### Finding Description

`system_migration` creates a `Display<T>` with `cap_id: option::none()`: [1](#0-0) 

The `claim` function's only guard is that `cap_id` is not yet set: [2](#0-1) 

By contrast, `claim_with_publisher` additionally asserts `publisher.from_package<T>()`: [3](#0-2) 

`LegacyDisplay<T>` is declared with `has key, store`: [4](#0-3) 

Because it has `store`, it is freely transferable via `transfer::public_transfer`. `claim` never checks whether the `LegacyDisplay<T>` being consumed corresponds to the *current* package owner — it only checks that one exists for type `T`.

**Attack path:**

1. Alice publishes a package defining type `T`, receives `Publisher`.
2. Alice calls `display::new<T>(&publisher, ctx)` to mint a `LegacyDisplay<T>` and retains it (or transfers it to any accomplice).
3. Alice transfers `Publisher` to Bob (legitimate new owner).
4. System migration runs `system_migration<T>`, creating `Display<T>` with `cap_id: None`.
5. Alice calls `claim(&mut Display<T>, legacy_display, ctx)` — no publisher check fires.
6. `display.cap_id` is filled with Alice's new `DisplayCap<T>` ID.
7. Bob calls `claim_with_publisher` → aborts with `ECapAlreadyClaimed`. Bob is permanently locked out. [5](#0-4) 

---

### Impact Explanation

- **Unauthorized `DisplayCap<T>` seizure**: Alice obtains the capability that authorizes `set`, `unset`, and `clear` on the shared `Display<T>` object for Bob's type. She can overwrite display fields (name, image URL, description) for every object of type `T` across the entire ecosystem.
- **Permanent lock**: Once `cap_id` is filled, `ECapAlreadyClaimed` prevents Bob from ever claiming via either `claim` or `claim_with_publisher`. The legitimate owner has no recovery path.
- **Transferable attack surface**: Because `LegacyDisplay<T>` has `store`, Alice can sell or transfer the "claim ticket" to a third party, making this a tradeable exploit primitive.

This constitutes **harmful smart-contract behavior** (unauthorized capability seizure + permanent management lock for the legitimate owner) and **state corruption** (`cap_id` of the shared `Display<T>` is set to an unauthorized object ID).

---

### Likelihood Explanation

Any package that changed ownership after V1 display objects were created is vulnerable during the window between system migration and the new owner claiming the cap. The attacker only needs to have held the `Publisher` at any prior point (to mint a `LegacyDisplay<T>`) and act before the new owner claims. This is a race condition with a clear, low-cost exploit transaction.

---

### Recommendation

Add a `Publisher` check to `claim`, mirroring `claim_with_publisher`:

```move
public fun claim<T: key>(
    display: &mut Display<T>,
    publisher: &Publisher,       // add publisher as additional proof
    legacy: LegacyDisplay<T>,
    ctx: &mut TxContext,
): DisplayCap<T> {
    assert!(display.cap_id.is_none(), ECapAlreadyClaimed);
    assert!(publisher.from_package<T>(), ENotValidPublisher); // add this
    let cap = DisplayCap<T> { id: object::new(ctx) };
    display.cap_id.fill(cap.id.to_inner());
    legacy.destroy();
    cap
}
```

This ensures that only the *current* package owner (who holds the `Publisher`) can claim the cap, even if they also happen to hold a `LegacyDisplay<T>`.

#[test]
fun exploit_former_owner_seizes_cap() {
    test_tx!(|registry, scenario| {
        // Step 1: Alice (original publisher) mints a LegacyDisplay<T> and retains it
        let alice_publisher = new_publisher(scenario);
        let alice_legacy = display::new<MyKeyOnlyType>(&alice_publisher, scenario.ctx());

        // Step 2: Alice transfers Publisher to Bob (package ownership transfer)
        // (alice_publisher transferred to @bob)
        alice_publisher.burn(); // simplified: in reality transferred to Bob

        // Step 3: System migration creates Display<T> with cap_id: None
        let migration_cap = take_migration_cap(scenario);
        registry.system_migration<MyKeyOnlyType>(&migration_cap, vector[], vector[], scenario.ctx());
        scenario.next_tx(@alice);

        // Step 4: Alice calls claim() with her retained LegacyDisplay — no publisher check!
        let mut display = scenario.take_shared<Display<MyKeyOnlyType>>();
        assert!(display.cap_id().is_none()); // cap unclaimed
        let stolen_cap = display.claim(alice_legacy, scenario.ctx());

        // Step 5: cap_id is now set to Alice's cap — Bob is permanently locked out
        assert!(display.cap_id().is_some());
        // Bob calling claim_with_publisher would now abort with ECapAlreadyClaimed

        // Alice can now manipulate Bob's display fields
        display.set(&stolen_cap, b"image_url".to_string(), b"https://attacker.com/evil.png".to_string());

        test_scenario::return_shared(display);
        transfer::public_transfer(stolen_cap, @alice);
        migration_cap.destroy_system_migration_cap();
    });
}
