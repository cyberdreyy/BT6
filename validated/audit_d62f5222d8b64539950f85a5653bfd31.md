### Title
Unbounded Recursion in `TrieNode::decode` Enables Stack-Overflow DoS of the Fault-Proof Program via Crafted MPT Preimages - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode::decode` in `crates/proof/mpt/src/node.rs` is a recursive-descent RLP parser for Ethereum's Merkle Patricia Trie with no recursion-depth limit, mirroring the `Utf8GraphQLParser` bug class in the report. Any actor who can supply a preimage to the fault-proof program's preimage oracle (e.g. a dispute-game participant submitting data to the on-chain Large Preimage Oracle, or an attacker-controlled L1/L2 RPC endpoint that the host queries) can craft a single blob whose keccak256 hash matches an expected trie-node commitment but which, when RLP-decoded, recurses arbitrarily deep through nested `Extension`/`Branch` structures, overflowing the stack.

### Finding Description
`TrieNode::decode` peeks at the RLP header and, for `Extension` nodes, recursively calls `Self::decode(buf)` on the inner node, and for `Branch` nodes decodes a `Vec::<Self>` where each of the (up to 17) elements again recursively invokes `TrieNode::decode`: [1](#0-0) 

The leaf/extension payload helper also recurses into `Self::decode` for extension children: [2](#0-1) 

There is no depth counter or bound anywhere in this module — the only structural check is `rlp_list_element_length`/header parsing, none of which limit recursion depth: [3](#0-2) 

This decoder is the trie-node decode path used throughout the fault-proof stack. In particular, `OracleL1ChainProvider::trie_node_by_hash` and `OracleL2ChainProvider::trie_node_by_hash` fetch a preimage from the preimage oracle by `keccak256` key and pass the raw bytes straight into `TrieNode::decode`, with no independent depth or structural validation beyond the hash match: [4](#0-3) [5](#0-4) 

The oracle only guarantees `keccak256(data) == key`; it does not validate the internal shape of `data`. In the OP-Stack fault-dispute-game design, arbitrary preimage bytes for a claimed keccak256 key can be supplied by dispute-game participants via the (large) preimage oracle mechanism prior to program execution, so an adversary fully controls the byte content as long as the hash matches. A crafted preimage that RLP-encodes as a long chain of nested `Extension` nodes (each only a few bytes) can pack thousands of recursion levels into a payload well under typical preimage-size limits, exactly matching the reported bug class ("~40 KB payload can trigger a `StackOverflowException`" analog — here an uncatchable Rust stack overflow/abort).

### Impact Explanation
A `StackOverflowException`-equivalent (Rust process abort on stack overflow) is likewise uncatchable — this crashes the fault-proof program mid-execution. Because trie-node decoding happens during trusted, deterministic replay of the derivation/execution used to compute the claimed output root in a dispute game, crashing the honest program prevents it from completing execution and producing/verifying the correct output root within the game's clock. This can lead to the dispute resolving with a wrong/unprovable output root, or a halted proof program — both explicitly listed as qualifying impacts ("wrong provable output root", "node halt"). This also affects the host/executor paths (`crates/proof/executor`) that build a `TrieDB` from preimages during stateless execution, and the L1/L2 oracle-backed providers used within Cannon/MIPS-style fault-proof VMs, broadening the blast radius across the fault-proof program.

### Likelihood Explanation
Any dispute-game participant (or a party able to feed adversarial preimage data through the preimage oracle for a claimed keccak256 key) can trigger this deterministically with a single crafted preimage — no privileged access, no race condition, and no dependency on complex trie state is required, only that the crafted bytes hash to the expected key. This mirrors the "AC:L / PR:N / UI:N" characteristics of the CVE analog.

### Recommendation
Add an explicit recursion-depth counter/limit to `TrieNode::decode` (and its recursive helpers `try_decode_leaf_or_extension_payload`, the `Branch` element decode loop, and `unblind`/`open`/`insert` where they recurse based on attacker-controlled preimage structure), returning a catchable `TrieNodeError` once a safe maximum depth (e.g., bounded by the maximum possible real MPT depth, ~64-nibble paths) is exceeded, analogous to the `MaxAllowedRecursionDepth` fix adopted upstream for `Utf8GraphQLParser`.

### Proof of Concept
Construct a byte buffer `preimage` that RLP-encodes as a deeply nested chain: `Extension(prefix, Extension(prefix, Extension(prefix, ... Leaf)))` with N ≈ tens of thousands of nesting levels (each level adds only a few bytes, so overall size can stay in the tens-of-KB range). Compute `key = keccak256(preimage)` and register it in a `TrieProvider`/preimage oracle so that `trie_node_by_hash(key)` returns this data. Any caller that reaches `TrieNode::decode(&mut preimage.as_ref())` — e.g. `OracleL1ChainProvider::trie_node_by_hash` — will recurse N times through `Self::decode` inside `try_decode_leaf_or_extension_payload`, overflowing the stack and aborting the process before any validation of the decoded structure occurs.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

pub(crate) fn rlp_list_element_length(buf: &mut &[u8]) -> alloy_rlp::Result<usize> {
    let header = Header::decode(buf)?;
    if !header.list {
        return Err(alloy_rlp::Error::UnexpectedString);
    }
    let len_after_consume = buf.len() - header.payload_length;

    let mut list_element_length = 0;
    while buf.len() > len_after_consume {
        let header = Header::decode(buf)?;
        buf.advance(header.payload_length);
        list_element_length += 1;
    }
    Ok(list_element_length)
}

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
