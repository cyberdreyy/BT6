### Title
Cross-job pipeline run disclosure via unscoped runID lookup in PipelineRunsController.Show - ([File: core/web/pipeline_runs_controller.go])

### Summary
`PipelineRunsController.Show` handles `GET /v2/jobs/:ID/runs/:runID` but never validates that the fetched run actually belongs to the job identified by `:ID`. It parses only `runID`, calls `FindRun` directly, and returns the result, so any authenticated caller can enumerate `runID` values to read pipeline run data belonging to a different job.

### Finding Description
In `Show`, the handler reads `c.Param("runID")`, sets it on a `pipeline.Run{}`, and immediately calls `prc.App.PipelineORM().FindRun(ctx, pipelineRun.ID)` without ever reading or using `c.Param("ID")` to check that the run's `PipelineSpecID`/job binding matches the job in the URL path: [1](#0-0) 

Compare this with `Index`, which does scope the query by job ID when `:ID` is present: [2](#0-1) 

Because `Show` performs a global lookup keyed only by run ID, and Chainlink's HTTP router applies authentication/role middleware at the route level (not per-resource ownership checks), any authenticated user who can reach `GET /v2/jobs/:ID/runs/:runID` for a job they own can substitute an arbitrary `:runID` belonging to a run of a different job and receive that run's full presenter output (inputs, outputs, task run results, which may embed bridge responses or other sensitive values) via `presenters.NewPipelineRunResource`.

### Impact Explanation
This is cross-user/cross-job disclosure of pipeline run inputs/outputs, which can include bridge/adapter responses, external initiator payloads, and other data not intended to be visible outside the owning job scope — matching Chainlink's "unauthorized disclosure of sensitive information" bounty impact class.

### Likelihood Explanation
Preconditions are low: any authenticated user with view-level role access to the jobs/runs endpoints can trigger this by simply changing the `:runID` path segment; run IDs are sequential integers and easily enumerable, making the attack fully repeatable without special privileges.

### Recommendation
In `Show`, after calling `FindRun`, verify that the returned run's associated job/pipeline-spec ID matches the job ID from `c.Param("ID")` (mirroring the scoping logic already used in `Index`), and return 404/403 on mismatch. Alternatively, change `PipelineORM` to expose a `FindRun(ctx, jobID, runID)` variant that scopes the query at the database level.

### Proof of Concept
Go handler-level integration test:
1. Create two jobs, Job A and Job B, each with a completed pipeline run (RunA, RunB) containing distinguishable sensitive output data.
2. As an authenticated view-role user with access to Job A, send `GET /v2/jobs/{JobA.ID}/runs/{RunB.ID}`.
3. Assert the response is `200 OK` and contains RunB's data (owned by Job B), proving the job-scoping in the URL is not enforced.
4. Assert (as expected fix) that after adding job-ownership validation, the same request instead returns `404`/`403`.

func (prc *PipelineRunsController) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")

	// Temporary: if no size is passed in, use a large page size. Remove once frontend can handle pagination
	if c.Query("size") == "" {
		size = 1000
	}

	var pipelineRuns []pipeline.Run
	var count int
	var err error

	ctx := c.Request.Context()
	if id == "" {
		pipelineRuns, count, err = prc.App.JobORM().PipelineRuns(ctx, nil, offset, size)
	} else {
		jobSpec := job.Job{}
		err = jobSpec.SetID(c.Param("ID"))
		if err != nil {
			jsonAPIError(c, http.StatusUnprocessableEntity, err)
			return
		}

		pipelineRuns, count, err = prc.App.JobORM().PipelineRuns(ctx, &jobSpec.ID, offset, size)
	}

	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	res := presenters.NewPipelineRunResources(pipelineRuns, prc.App.GetLogger())
	paginatedResponse(c, "pipelineRun", size, page, res, count, err)
}

func (prc *PipelineRunsController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	pipelineRun := pipeline.Run{}
	err := pipelineRun.SetID(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	pipelineRun, err = prc.App.PipelineORM().FindRun(ctx, pipelineRun.ID)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	res := presenters.NewPipelineRunResource(pipelineRun, prc.App.GetLogger())
	jsonAPIResponse(c, res, "pipelineRun")
}
