### Title
Gateway legacy `Message`/`MessageId` replay causes duplicate re-execution of user capability requests - ([File: core/services/gateway/api/message.go])

### Summary
`Message.Sign`/`Message.SignKS` bind a signature to `MessageId`, `Method`, `DonId`, `Receiver`, and `Payload` [1](#0-0) , but nothing in the gateway enforces that a given signed `(Signature, MessageId)` pair can only ever be processed once. The only "duplicate" checks (`RequestCache.NewRequest` and `handler.savedCallbacks`) are transient, in-memory maps keyed by `MessageId`/`(sender, MessageId)` that are deleted once the original request completes or times out, after which an attacker who has a copy of the original signed raw bytes can resubmit them and have the gateway accept and re-dispatch them as a brand-new request to the DON.

### Finding Description
`gateway.ProcessRequest` decodes the raw HTTP body into an `api.Message`, calls `msg.Validate()` (which only checks field lengths/nulls and recovers the signer via `ExtractSigner`), and then dispatches to the handler's `HandleLegacyUserMessage` [2](#0-1) . There is no check anywhere in this path that the `(Sender, MessageId)` pair has not been seen before in a persistent sense.

For the web-API capabilities handler, `HandleLegacyUserMessage` stores the callback in `h.savedCallbacks[msg.Body.MessageId]` and forwards the message to all DON nodes [3](#0-2) . When the DON responds, `handleWebAPITriggerMessage` looks up and **deletes** the entry from `savedCallbacks`, then sends the response to the caller [4](#0-3) . Once deleted, nothing prevents the exact same signed message from being resubmitted: it will pass `Validate()` again, be treated as a brand new request, get a fresh `savedCallbacks` entry, and be re-broadcast to every DON node — causing the capability payload to be executed a second time.

The generic `common.RequestCache` used by other legacy handlers has the same limitation: `NewRequest` only rejects a message while its `globalId{sender, id}` entry is still present in the cache; the entry is removed by `deleteAndSendOnce` as soon as the aggregated response is sent or on timeout [5](#0-4) . So replay-rejection is only effective for the duration the request is "in flight," not for the life of the `MessageId`.

The only anti-staleness control in this path is an application-level payload timestamp check in the web-API trigger handler (`payload.Timestamp` vs `MaxAllowedMessageAgeSec`) [6](#0-5) , which bounds the replay window (default ~120s) but does not prevent replay within that window.

By contrast, the Vault gateway path explicitly recognizes and closes this exact gap with a persistent `RequestReplayGuard` that tracks digests with an expiry and rejects duplicates via `ErrRequestAlreadySeen` [7](#0-6) , confirming that the legacy `api.Message` path (used by the capabilities/web-API handler) lacks equivalent protection.

### Impact Explanation
An attacker who obtains a copy of a previously-sent, validly-signed gateway `Message` (e.g., via logs, a proxy, or any other network vantage point granted by the "network access to the gateway" precondition) can resubmit the identical bytes and have the gateway/DON process it as a new, distinct request within the staleness window. This causes unauthorized re-execution of the user's capability call (e.g., a `web_api_trigger`/webapi target/compute action being invoked twice), which can produce duplicate side effects (double HTTP calls, duplicate workflow runs) attributed to the original legitimate sender. This maps to a "unauthorized job run" / duplicated-action impact class rather than fund theft or key disclosure, since no cross-user redirection or credential exposure occurs — the response still routes back to whichever party currently possesses the signed bytes.

### Likelihood Explanation
Exploitation requires only network-level possession of one legitimate, previously-observed signed raw request body (no private key or additional secret is required) and the ability to send an HTTP request to the gateway's user endpoint — both are within the stated attacker capability ("only network access to the gateway"). The replay must occur before the request's original processing lifecycle is completed... actually replay must occur after original completes but within `MaxAllowedMessageAgeSec` (default 120s) to pass the staleness check, making the window narrow but real and repeatable for any captured message within that time.

### Recommendation
Add a persistent, expiry-based replay guard for the generic `api.Message`/legacy gateway path, analogous to `vault.RequestReplayGuard`: track `(Sender, MessageId)` digests with an expiry derived from `MaxAllowedMessageAgeSec` and reject requests whose digest was already recorded, rather than relying solely on the transient `savedCallbacks`/`RequestCache` maps that are cleared once the original round-trip completes.

### Proof of Concept
1. In `core/services/gateway/handlers/capabilities/handler_test.go` (or a new integration test alongside `gateway_integration_test.go`), construct a signed `api.Message` with `Method = MethodWebAPITrigger` and a valid `payload.Timestamp` within `MaxAllowedMessageAgeSec`.
2. Call `handler.HandleLegacyUserMessage` (or `gateway.ProcessRequest`) once, simulate the DON node response via `HandleNodeMessage`, and assert the callback receives a successful response and `savedCallbacks` no longer contains the `MessageId`.
3. Immediately resubmit the exact same raw signed bytes via `HandleLegacyUserMessage`/`gateway.ProcessRequest` again.
4. Assert that the second call is **not** rejected as a duplicate (no "already processed"/replay error is returned) and that a new `savedCallbacks` entry is created and the message is sent to DON nodes again — demonstrating the message is treated as a distinct, newly authorized request rather than being deduplicated.

func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}

func (m *Message) SignKS(ctx context.Context, ks keys.MessageSigner, signer common.Address) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := ks.SignMessage(ctx, signer, gw_common.Flatten(rawData...))
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(signer.Hex())
	return nil
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
	codec := api.JsonRPCCodec{}
	timer := time.AfterFunc(c.timeout, func() {
		err := c.deleteAndSendOnce(key, handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(request), ErrorCode: api.RequestTimeoutError})
		if err != nil {
			lggr.Errorw("failed to send timeout response", "error", err)
		}
	})
	c.cache[key] = &pendingRequest[T]{Callback: callback, responseData: responseData, timeoutTimer: timer}
	return nil
}

// Call ResponseProcessor on the response.
// There are two possible outcomes:
//
//	(a) remove request from cache and send aggregated response to the user
//	(b) update request's responseData and keep it in cache, awaiting more responses from nodes
func (c *requestCache[T]) ProcessResponse(response *api.Message, process ResponseProcessor[T]) error {
	if response == nil {
		return errors.New("response is nil")
	}
	key := globalId{response.Body.Receiver, response.Body.MessageId}
	// retrieve entry
	c.mu.Lock()
	entry, ok := c.cache[key]
	c.mu.Unlock()
	if !ok {
		return errors.New("request not found")
	}
	// process under per-entry lock
	entry.mu.Lock()
	aggregated, newResponseData, err := process(response, entry.responseData)
	if newResponseData != nil {
		entry.responseData = newResponseData
	}
	entry.mu.Unlock()
	if err != nil {
		return err
	}
	if aggregated != nil {
		return c.deleteAndSendOnce(key, *aggregated)
	}
	return nil
}

func (c *requestCache[T]) deleteAndSendOnce(key globalId, callbackResponse handlers.UserCallbackPayload) error {
	c.mu.Lock()
	entry, deleted := c.cache[key]
	delete(c.cache, key)
	c.mu.Unlock()
	if deleted {
		entry.timeoutTimer.Stop()
		return entry.SendResponse(callbackResponse)
	}

	return nil

var ErrRequestAlreadySeen = errors.New("request was already authorized previously")

// RequestReplayGuard prevents replay of already-processed requests by tracking
// request digests with expiry timestamps. It is safe for concurrent use.
//
// Used by both the AllowListBasedAuth flow and the JWTBasedAuth flow to ensure
// that a given request digest is only accepted once.
type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
