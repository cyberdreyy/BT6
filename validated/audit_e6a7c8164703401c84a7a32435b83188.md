### Title
Failed `stopEpoch` leaks unfunded APR0 interest into `pendingWithdraws` and defaulted-epoch claim basis, diluting default recovery - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
Like the kernel fix where a BPF trampoline image is allocated and then orphaned when `fentry` attach fails, `IdleCDOEpochVariant._stopEpoch` commits APR0 settlement state (`pendingWithdraws`, `apr0RateByEpoch`, `apr0TotalPrincipal`) *before* the fallible borrower pull inside the `try`/`catch`. When the pull fails and `_handleBorrowerDefault` runs, that accrued-but-never-funded interest remains booked as a pending-withdraw liability — an orphaned allocation. An unprivileged APR0 withdraw requester can trigger this to inflate their defaulted-epoch claim basis and steal a disproportionate share of the fixed recovery pool.

### Finding Description
In `IdleCDOEpochVariant._stopEpoch` (contracts/IdleCDOEpochVariant.sol:330-505), the sequence is:

1. `_strategy.prepareStopEpochWithApr0(_interest)` is called at line 362 — **outside** the `try` block.
2. Inside `prepareStopEpochWithApr0` (IdleCreditVault.sol:490-541), when APR0 principal exists and the epoch interest is overridden, the strategy irreversibly executes:
   - `pendingWithdraws += _apr0NetInterest` (line 535) — booked as a liability owed to receipt holders.
   - `apr0RateByEpoch[epochNumber] = _apr0NetInterest * 1e18 / _principal` (line 537) — each APR0 requester's claimable settled interest is derivable and accrued via `_settleApr0` (IdleCreditVault.sol:561).
   - `apr0TotalPrincipal = 0` (line 540) — the bucket is closed so this can never be rolled back or re-accrued.
3. Only afterwards does the `try this.getFundsFromBorrower(...)` (line 408) run. If the borrower underpays or the transfer reverts, the `catch` at line 501 calls `_handleBorrowerDefault` and **returns**, leaving all the mutations from step 2 in place.

The result mirrors the leaked `bpf_trampoline_*` image: resources (claim basis and `pendingWithdraws`) are allocated for an operation that failed and are never released. `_accrueManagementFee` at line 384 similarly mutates `unclaimedFees` before the fallible pull.

The attacker is an ordinary KYC-passing lender who calls `requestWithdraw` while `unscaledApr == 0` (APR0 bucket). The default itself is caused by the honest borrower simply not repaying — no privileged misbehavior required; the manager invokes `stopEpoch` with an override interest and the pull fails, or for a programmable borrower `onStopEpoch` returns false (line 398-403, same leak).

### Impact Explanation
`pendingWithdraws` and the stored `apr0RateByEpoch` record interest that the borrower never paid. On `finalizeDefault`, the defaulted-epoch pending claim basis (`defaultPendingClaimBasis`/`_claimDefaultedWithdrawRequest` path) includes this phantom interest. Because recovery is distributed pro rata out of a fixed `_recoveredAmount`, the attacker's APR0 receipt claims a basis of principal + unfunded interest, extracting real recovered underlying that should have gone to other pending receipt holders and active LPs. This is direct theft by dilution; the loss equals the phantom `_apr0NetInterest` share of the recovery, quantified by `apr0RateByEpoch[defaultedEpoch] * attackerPrincipal / 1e18` relative to total claim basis. Additionally, `instantWithdrawClaimsByEpoch`/normal receipt claims are permanently devalued, and `pendingWithdraws` stays elevated so `previewLossAdjustedWithdrawFunds`/default accounting is permanently skewed.

### Likelihood Explanation
Requires: (a) a vault running with `unscaledApr == 0` during the request epoch so APR0 accounting is active; (b) an attacker with a nonzero APR0 withdraw request; (c) a `stopEpoch` where `expectedEpochInterest` resolves > `pendingWithdrawFees` (any positive-interest stop) followed by a failed borrower pull — i.e., an ordinary borrower default, the exact scenario this code path is designed for. No privileged collusion needed; borrower default is a normal, anticipated failure mode, analogous to `fentry` failing on `trap_init`.

### Recommendation
Make APR0 settlement atomic with successful funding, mirroring the kernel fix (free the trampoline when attach fails). Either:
- Move `prepareStopEpochWithApr0` and `_accrueManagementFee` inside the `try` so a failed pull atomically reverts them, or
- Snapshot `pendingWithdraws`, `apr0RateByEpoch[epochNumber]`, and `apr0TotalPrincipal` before the pull and restore them in the `catch`/`onStopEpoch == false` branch before `_handleBorrowerDefault`, so orphaned claim basis is never persisted.

Also apply the same rollback to `expectedEpochInterest`/`pendingWithdrawFees`/`unclaimedFees` writes that currently survive a defaulted stop.

### Proof of Concept
Foundry fork PoC (solidity, run against a mainnet fork with USDC and the deployed `IdleCDOEpochVariant`/`IdleCreditVault`):

```solidity
// test/foundry/PoCApr0LeakOnDefault.t.sol
function testApr0InterestLeaksOnFailedStop() public {
    // 1. Configure pool with unscaledApr == 0 (APR0 mode).
    // 2. attacker (KYC'd) deposits AA during buffer, requests withdraw -> apr0Users[attacker].principal = P.
    cdoEpoch.requestWithdraw(attackerTrancheBal, address(AAtranche));
    assertEq(creditVault.apr0TotalPrincipal(), P);

    // 3. startEpoch, then stopEpoch with override interest > pendingWithdrawFees.
    vm.prank(manager); cdoEpoch.startEpoch();
    vm.warp(cdoEpoch.epochEndDate() + 1);
    // Borrower has zero balance/allowance -> getFundsFromBorrower reverts -> catch -> default.
    deal(USDC, borrower, 0);
    vm.prank(manager); cdoEpoch.stopEpoch(0, overrideInterest);
    assertTrue(cdoEpoch.defaulted());

    // 4. LEAK: unfunded interest still booked.
    assertGt(creditVault.apr0RateByEpoch(epoch), 0);            // orphaned rate
    assertGt(creditVault.pendingWithdraws(), P);                // P + phantom interest

    // 5. finalizeDefault with fixed recovery R: attacker's claim basis includes
    //    phantom interest -> attacker recovers > principal * R / trueBasis,
    //    stealing from other receipt holders. Assert dilution:
    //    attacker claim > P * R / (truePendingBasis + activeBasis).
}
```
