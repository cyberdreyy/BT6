### Title
Zero-price write-off requests let anyone seize escrowed tranche tokens for free - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` never validates `underlyingsRequested`, so a lender can create (or extend) a request asking for `0` underlyings. `fullfillWriteOffRequest` then only requires `_underlyings >= currentRequest.underlyings`, which a zero ask satisfies with `_underlyings == 0`. Any unprivileged wallet can therefore fulfil the request, pay nothing, and receive the full `tranches` balance escrowed by the lender.

### Finding Description
- `createWriteOffRequest(amount, underlyingsRequested)` checks only `isEpochRunning()` and `amount != 0`; `underlyingsRequested` is stored unvalidated (lines 86-102).
- `fullfillWriteOffRequest(_user, _tranches, _underlyings)` reverts only if `currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings` (line 129). With `underlyings == 0`, passing `_underlyings = 0` and `_tranches = currentRequest.tranches` succeeds.
- The fulfiller then receives the lender's tranche tokens via `IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches)` (line 151) while transferring `0` underlying (the fee math on line 144 yields `_totFee = 0`, and `safeTransfer(_user, 0)` is a no-op for standard ERC20s).
- A user can also silently zero out an existing priced request's marginal ask: repeated calls accumulate `tranches` and `underlyings` independently, and one call with `underlyingsRequested = 0` deposits additional tranches at zero marginal price. More critically, the escrow permits a request that is economically nonsensical (giving away debt receipts for nothing) with no guard.
- Missing-validation analog: like the Expat bug (missing contextual validity checks on input), the contract fails to validate a semantically invalid parameter at entry, and downstream logic treats it as legitimate.

### Impact Explanation
Direct theft of escrowed tranche tokens: any EOA/contract can call `fullfillWriteOffRequest` and drain a zero-priced request's entire tranche balance for `0` underlying. Tranche tokens represent claim on vault NAV (or can be written off by the borrower), so the loss equals the full virtual-price value of the escrowed tranches. No privileged role is involved — the fulfiller is unprivileged, owner/borrower are honest and need take no action.

### Likelihood Explanation
Requires a lender to create (or top up) a request with `underlyingsRequested == 0`. This can happen via a UI/integrator bug, a mistakenly omitted parameter, or a second `createWriteOffRequest` call intended only to add tranches (the function signature forces the caller to also supply an `underlyingsRequested` value, making `0` the natural "no change" input — which silently dilutes the aggregate ask rather than leaving it unchanged). Once such a request exists, theft is permissionless and atomic. Likelihood is moderate; impact per occurrence is the full escrowed amount.

### Recommendation
In `createWriteOffRequest`, revert when `underlyingsRequested == 0` (a write-off request asking for nothing is never legitimate). Optionally also require `currentRequest.tranches == 0` for top-ups, or provide a separate function to add tranches while preserving the existing ask, so callers cannot accidentally reset the marginal price to zero.

### Proof of Concept
```solidity
// Foundry fork test — assume vault `cdoEpoch`, `AAtranche`, escrow deployed and epoch running
function testZeroPriceWriteOffTheft() external {
    address lender = makeAddr("lender");
    address attacker = makeAddr("attacker");
    uint256 trancheAmt = 10_000 * 1e18;

    // lender holds AA tranches and creates a request with a zero ask
    deal(address(AAtranche), lender, trancheAmt);
    vm.startPrank(lender);
    AAtranche.approve(address(escrow), trancheAmt);
    escrow.createWriteOffRequest(trancheAmt, 0); // missing validation
    vm.stopPrank();

    // any wallet fulfils with 0 underlyings and takes all tranche tokens
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(lender, trancheAmt, 0);

    assertEq(AAtranche.balanceOf(attacker), trancheAmt, "attacker seized escrowed tranches for free");
    assertEq(underlying.balanceOf(lender), 0, "lender received nothing");
}
```
