### Title
Unauthenticated GraphQL Introspection and Alias/Field-Duplication Amplification on `/query` due to missing introspection disablement and per-field-only auth checks - (File: core/web/router.go)

### Summary
The Chainlink node's GraphQL endpoint `POST /query` only limits query *depth* (`graphql.MaxDepth(10)`) and does not disable introspection or bound query *width* (aliases / duplicate fields). Combined with an authentication middleware that never aborts unauthenticated requests, an unauthenticated client can run full introspection queries and width-based amplification queries against the node's public GraphQL surface.

### Finding Description
The GraphQL handler is wired up in `graphqlHandler`, which only conditionally applies `graphql.MaxDepth(10)` based on `Insecure.InfiniteDepthQueries`, with no `DisableIntrospection`, alias limit, or field-duplication guard anywhere in the codebase: [1](#0-0) 

The route itself is guarded by `auth.AuthenticateGQL`, but that middleware is designed to be non-blocking — it silently `return`s (without aborting) when no session cookie/sessionID is present or when the session lookup fails, letting the request continue to the GraphQL handler unauthenticated: [2](#0-1) [3](#0-2) 

Per-field authorization is enforced only inside individual resolver functions (`authenticateUser`, `authenticateUserCanRun`, etc.), which check `auth.GetGQLAuthenticatedSession` from the request context: [4](#0-3) 

Introspection queries (`__schema`, `__type`) are resolved directly by the `graph-gophers/graphql-go` engine itself, not by `resolver.Resolver` methods, so they never pass through the above per-field auth checks. Since introspection is never disabled via a `graphql.SchemaOpt` (no `DisableIntrospection` option is used anywhere in the codebase), an unauthenticated request to `/query` can retrieve the full schema. Likewise, `MaxDepth(10)` bounds nesting depth but does not bound the number of aliases or duplicate fields at a given depth, so a single introspection or shallow query can still be crafted with hundreds of aliases/duplicated fields to multiply server-side work and response size — exactly the "Alias Overloading" / "Field Duplication" / "Introspection-based Circular Query" classes from the report, reachable pre-authentication.

### Impact Explanation
An unauthenticated actor reaching the node's web/API surface can: (1) enumerate the complete internal GraphQL schema (types, mutations such as `createJob`, `deleteAPIToken`, key-management mutations, etc.) via introspection, aiding further attacks; and (2) submit alias-heavy or duplicate-field-heavy introspection/queries to consume CPU/memory and degrade node responsiveness (DoS), all without providing a valid session cookie.

### Likelihood Explanation
Likelihood is moderate: it requires network access to the node's GraphQL endpoint (typically exposed to the operator UI/API network, sometimes reachable more broadly depending on deployment), but no credentials, tokens, or prior access are needed — a single crafted HTTP POST suffices.

### Recommendation
- Explicitly disable introspection in production via a `graphql.SchemaOpt` (e.g., a custom validation pass or the graph-gophers `DisableIntrospection`-equivalent) unless `Insecure.InfiniteDepthQueries`/dev mode is set, mirroring the existing `MaxDepth` gating in `graphqlHandler` (core/web/router.go).
- Add width-based validation (max aliases, max duplicate fields per query) alongside `MaxDepth`, e.g. via `github.com/ivandotv/graphql-no-alias`-style directive validation or a custom query cost/complexity analyzer.
- Ensure `auth.AuthenticateGQL` fully aborts (401) requests lacking a valid session before they reach `graphqlHandler`, rather than passing them through silently, so that only per-field checks decide authorization *of authenticated* users, not whether any request reaches the engine at all.

### Proof of Concept
1. Without any session cookie, send:
```
POST /query HTTP/1.1
Content-Type: application/json

{"query": "query { __schema { types { name fields { name } } } } "}
```
This is processed by `graphqlHandler` (core/web/router.go:110-134) without hitting any `authenticateUser*` check, returning the full schema.
2. Send a wide, shallow aliased introspection or public query, e.g. 500 aliases of `__typename` or a type lookup, to observe amplified response time/size — `MaxDepth(10)` (core/web/router.go:116-120) does not reject it since nesting depth stays low.

```go
func graphqlHandler(app chainlink.Application) gin.HandlerFunc {
	rootSchema := schema.MustGetRootSchema()

	// Disable introspection and set a max query depth in production.
	var schemaOpts []graphql.SchemaOpt

	if !app.GetConfig().Insecure().InfiniteDepthQueries() {
		schemaOpts = append(schemaOpts,
			graphql.MaxDepth(10),
		)
	}

	schema := graphql.MustParseSchema(rootSchema,
		&resolver.Resolver{
			App: app,
		},
		schemaOpts...,
	)
```

```go
func AuthenticateGQL(authenticator Authenticator, lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		ctx := c.Request.Context()
		session := sessions.Default(c)
		sessionID, ok := session.Get(SessionIDKey).(string)
		if !ok {
			return
		}

		user, err := authenticator.AuthorizedUserWithSession(ctx, sessionID)
		if err != nil {
			if errors.Is(err, clsessions.ErrUserSessionExpired) {
				lggr.Warnw("Failed to authenticate session", "err", err)
			} else {
				lggr.Errorw("Failed call to AuthorizedUserWithSession, unable to get user", "err", err)
			}
			return
		}

		ctx = WithGQLAuthenticatedSession(c.Request.Context(), user, sessionID)

		c.Request = c.Request.WithContext(ctx)
	}
}
```

```go
// Authenticates the user from the session cookie, presence of user inherently provides 'view' access.
func authenticateUser(ctx context.Context) error {
	if _, ok := auth.GetGQLAuthenticatedSession(ctx); !ok {
		return unauthorizedError{}
	}
	return nil
}

// Authenticates the user from the session cookie and asserts at least 'run' role.
func authenticateUserCanRun(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role == sessions.UserRoleView {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}

// Authenticates the user from the session cookie and asserts at least 'edit' role.
func authenticateUserCanEdit(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	switch session.User.Role {
	case sessions.UserRoleView, sessions.UserRoleRun:
		return RoleNotPermittedError{session.User.Role}
	default:
	}
	return nil
}

// Authenticates the user from the session cookie and asserts has 'admin' role
func authenticateUserIsAdmin(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role != sessions.UserRoleAdmin {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}
```
