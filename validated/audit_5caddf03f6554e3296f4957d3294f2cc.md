### Title
Unauthenticated-role GET /v2/nodes and /v2/chains/:network/:ID/nodes routes lack any role check, exposing raw NodeStatus.Config (including RPC URLs) to view-role users - ([File: core/web/router.go])

### Summary
Unlike nearly every other mutating/administrative route in `v2Routes`, the `chains`/`nodes` GET routes are registered directly on the `authv2` group without any `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, so any authenticated session — including the lowest-privileged `view` role — can call them. `NodesController.Index` returns `presenters.NodeResource` built directly from `types.NodeStatus`, which carries the node's raw config (including RPC endpoint URLs), so any view-role user can retrieve chain node connection details.

### Finding Description
`v2Routes` builds `authv2 := r.Group("/v2", auth.Authenticate(...))`, which only checks that a *valid session or API token exists* — it performs no role check at all [1](#0-0) . Every other sensitive/administrative resource on this group is explicitly hardened with a role wrapper, e.g. `auth.RequiresAdminRole(uc.Index)` for `/users`, `auth.RequiresEditRole(jc.Create)` for job creation, `auth.RequiresEditRole(vrfkc.Create)` for VRF keys [2](#0-1) [3](#0-2) .

In contrast, the chains/nodes routes are registered with no such wrapper: [4](#0-3) 

`auth.RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` in `core/web/auth/auth.go` are the only mechanisms in this codebase that reject `UserRoleView` sessions [5](#0-4) ; since chains/nodes routes never call any of these, a `view`-role authenticated user (or a restricted API token with view role) passes `Authenticate` and reaches `nodesController.Index` unimpeded.

`nodesController[R].Index` calls `relayers.NodeStatuses(...)` and wraps each result with `n.newResource(node)` = `presenters.NewNodeResource`, returning the resource list via `paginatedResponse` with no redaction step in the controller itself [6](#0-5) . `types.NodeStatus` (from `chainlink-common/pkg/types`) carries the node's raw TOML `Config` field, which in EVM/Cosmos/Solana relayer configs typically embeds the node's `HTTPURL`/`WSURL` — and for many hosted RPC providers (Alchemy, Infura, QuickNode, etc.) these URLs embed the API key as a path/query component. If `presenters.NewNodeResource` passes this `Config` value through unredacted, the raw URL (and any embedded key) is returned in the JSON response to any authenticated caller regardless of role.

### Impact Explanation
This corresponds to a credential/secret disclosure impact: an unprivileged, view-role-only session can enumerate all configured chains and nodes and obtain internal/authenticated RPC endpoint URLs, potentially including embedded API keys for third-party RPC providers. This could allow the attacker to consume the operator's paid RPC quota, pivot to querying the operator's private RPC infrastructure, or use the leaked credentials against the provider's account.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs any valid authenticated session/API token with the lowest privilege level (`view`), which is explicitly designed to be a restricted, read-mostly role. No admin/operator access, no host access, and no misconfiguration is required — this is a routing/authorization gap present in default route wiring. The endpoint is a simple `GET` with no special headers, fully repeatable, and trivially scriptable (`curl -H "X-API-KEY..." -H "X-API-SECRET..." /v2/nodes`).

### Recommendation
Wrap the chains/nodes GET routes with an explicit minimum-role check (at minimum `auth.RequiresViewRole`/`RequiresEditRole` depending on desired sensitivity, consistent with other routes), and — more importantly — ensure `presenters.NewNodeResource` redacts or strips credential-bearing fields (URLs with embedded userinfo/API keys) from `types.NodeStatus.Config` before serialization, independent of role, since RPC secrets should never be serialized to any client.

### Proof of Concept
1. In a `core/web` handler-integration test (using the existing `setupNodesControllerTests`/`setupChainsControllerTests` helpers as seen in `core/web/chains_controller_integration_test.go`), configure a relayer with an EVM node whose `HTTPURL`/`WSURL` embeds a fake API key, e.g. `https://eth-mainnet.example.com/v2/SECRET_API_KEY`.
2. Create a test user/session with `sessions.UserRoleView`.
3. Issue `client.Get("/v2/nodes")` and `client.Get("/v2/chains/EVM/1/nodes")` using that view-role session.
4. Assert HTTP 200 is returned (proving no role check blocks the view user) and parse the JSON body's `attributes.config` (or equivalent) field.
5. Assert the returned config/URL fields do **not** contain the literal substring `SECRET_API_KEY` or any userinfo-embedded credential — this assertion currently fails, demonstrating the leak.
6. As a regression fix validation, add a test case in `core/web/presenters/node_test.go` asserting `NewNodeResource` redacts URL query/userinfo components from `Config` for all roles.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (n *nodesController[R]) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")
	network := c.Param("network")

	var nodes []types.NodeStatus
	var count int
	var err error

	relayers := n.relayers
	if network != "" {
		relayers = relayers.List(chainlink.FilterRelayersByType(network))
	}

	ctx := c.Request.Context()
	if id == "" {
		// fetch all nodes
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size)
	} else {
		// fetch nodes for chain ID
		// backward compatibility
		var rid types.RelayID
		err = rid.UnmarshalString(id)
		if err != nil {
			rid.ChainID = id
			rid.Network = network
		}
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size, rid)
	}

	resources := make([]R, 0, len(nodes))
	for _, node := range nodes {
		res := n.newResource(node)
		resources = append(resources, res)
	}

	paginatedResponse(c, "node", size, page, resources, count, err)
