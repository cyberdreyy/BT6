### Title
Presigned cache URL signature leaks into job trace via unmasked `*url.Error` on chunked range-fetch failure - ([File: commands/helpers/cache_extractor.go])

### Summary
`presignedRangeFetchChunk` builds the range-GET request from the raw, unsanitized presigned URL and returns any `c.getClient().Do(req)` error verbatim. Because Go's `http.Client.Do` wraps transport failures in a `*url.Error` that embeds the full request URL (including the query-string signature), that raw URL propagates unmodified through `transfer.ParallelRangeDownload` → `downloadParallel` (wrapped as `retryableErr`) → `doRetry` → `warningln`/`logrus.Warningln`, printing the signed URL to the job trace without ever passing through `url_helpers.CleanURL`.

### Finding Description
`tryPresignedParallelDownload` calls `c.presignedRangeFetchChunk(selectedURL)` with the *raw* `selectedURL` (the presigned URL, signature included) at `commands/helpers/cache_extractor.go:304`, and the closure at `commands/helpers/cache_extractor.go:337-354` issues `http.NewRequest`/`c.getClient().Do(req)` directly against that raw URL on every chunk fetch: [1](#0-0) 

If the backend misbehaves mid-download (connection reset/closed on a later range request, DNS hiccup, TLS failure, etc.), `Do` returns a `*url.Error{Op, URL, Err}` whose `Error()` method formats as `"<op> \"<URL>\": <err>"` — and `URL` here is the exact string passed to `http.NewRequest`, i.e. the full presigned URL with its query-string signature (e.g. AWS `X-Amz-Signature`). That error is returned as-is from the closure, bubbles through `transfer.ParallelRangeDownload`, and is wrapped without modification at `downloadParallel`: [2](#0-1) 

`doRetry` (in `retry_helper.go`) unwraps/relogs this via `logrus.WithError(err).Warningln("Retrying...")` on each retry, and on final exhaustion `Execute` calls `warningln(err)` at `commands/helpers/cache_extractor.go:638`, which calls `logrus.Warningln(args)` — i.e. `err.Error()` — printing straight to the job trace: [3](#0-2) 

Notably, the code elsewhere is clearly aware of this risk and deliberately scrubs URLs before logging success paths — e.g. `cleanedURL := url_helpers.CleanURL(selectedURL)` is computed and used for the "Downloading … from" info log at `commands/helpers/cache_extractor.go:303,526`, and `selectPresignedURL` scrubs URLs for its `logrus.WithFields` call at `commands/helpers/cache_extractor.go:140-141`. But no equivalent scrubbing exists on the *error* path for either the parallel/chunked fetch (`presignedRangeFetchChunk`) or the pre-existing sequential path (`getCache`, `commands/helpers/cache_extractor.go:192-204`), both of which pass the raw signed URL to `http.Client.Get/Do` and propagate any resulting `*url.Error` unsanitized.

This confirms the tested invariant is **violated in the same way on both paths** — the chunked/parallel path does not mask URLs any worse than sequential, but neither path masks them at all on transport-error branches, despite the codebase's established pattern (`url_helpers.CleanURL`) for doing so on the success/logging branches.

### Impact Explanation
A presigned cache URL is a bearer credential: whoever holds it can GET (and, depending on signature scope, potentially PUT) the cache object until the signature expires. If this error string reaches a job trace/log viewable by anyone other than the strictly-intended job owner during the signature's validity window (e.g., public pipelines, project members with read-only job-log access, or trace exposure through log forwarding/artifacts), that viewer gains the ability to read or tamper with that job's cache object by replaying the leaked signed URL — matching the "signature leak enabling cache read/tamper by another party viewing the trace" impact. The impact is bounded to whatever the specific presigned URL authorizes and its remaining TTL.

### Likelihood Explanation
Reaching this code path requires: `FF_USE_PARALLEL_CACHE_TRANSFER=true`, `Concurrency>1`, a cache object large enough to exceed `effectiveParallelChunkSize()` so parallel chunking is used, and a transient/backend failure on one of the range-GET requests after the initial probe succeeds (e.g., connection drop, timeout, DNS failure) — none of which require special privilege beyond configuring cache/CI settings and having a cache backend that can be made to fail mid-transfer (e.g. a proxy the job's cache config points at, or exploiting network flakiness). This is readily reproducible in a unit test by pointing the extractor at an `httptest.Server` that serves the first probe request normally and then hijacks/closes the connection on a subsequent range request.

### Recommendation
Sanitize errors returned from `presignedRangeFetchChunk` (and from the sequential `getCache`/`fetchPresignedTimestamp` paths) before they can reach any `Warningln`/`logrus` call: wrap `*url.Error` (or any error whose message may embed the request URL) by replacing its `URL` field with `url_helpers.CleanURL(rawURL)` prior to returning, e.g. build a sanitizing wrapper in `presignedRangeFetchChunk` and `getCache` that checks `errors.As(err, &urlErr)` and rewrites `urlErr.URL` to the cleaned value before propagating it up through `retryableErr`.

### Proof of Concept
Go unit test in `commands/helpers/cache_extractor_test.go`:
1. Start an `httptest.Server` handler that: on the first request (single-byte range probe) responds `206 Partial Content` with `Content-Range`/`Content-Length` indicating a size larger than `ChunkSize`; on the second request (an actual chunk GET), hijack the connection (`w.(http.Hijacker).Hijack()`) and close it immediately without writing a response, forcing `http.Client.Do` to return a `*url.Error` wrapping a connection-reset/EOF error.
2. Append a query string to the server URL simulating a signature, e.g. `?X-Amz-Signature=SECRETVALUE`.
3. Configure `CacheExtractorCommand{URL: serverURL, Concurrency: 4, ChunkSize: smallValue}`, set `FF_USE_PARALLEL_CACHE_TRANSFER=true`, and call `c.download(0)` (or `c.handlePresignedURL()`).
4. Capture the returned error's `.Error()` string (or hook `logrus` output) and assert it does **not** contain `"X-Amz-Signature"` or `"SECRETVALUE"` — the test should currently **fail**, demonstrating the leak, until the recommended sanitization is applied.

```go
func (c *CacheExtractorCommand) presignedRangeFetchChunk(rawURL string) func(offset, length int64) (io.ReadCloser, error) {
	return func(offset, length int64) (io.ReadCloser, error) {
		req, err := http.NewRequest(http.MethodGet, rawURL, nil)
		if err != nil {
			return nil, err
		}
		req.Header.Set("Range", fmt.Sprintf("bytes=%d-%d", offset, offset+length-1))
		resp, err := c.getClient().Do(req)
		if err != nil {
			return nil, err
		}
```
