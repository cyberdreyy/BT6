## Analog Found

### Title
Signer local state machine left permanently `Uninitialized` when a miner mines an empty tenure, wedging block-proposal evaluation until the next burn block ([File: stacks-signer/src/v0/signer_state.rs])

### Summary
`LocalStateMachine::bitcoin_block_arrival` optimistically resets the signer's local state machine to `Uninitialized` before recomputing it, expecting the recomputation to always succeed. A single miner can force the recomputation to fail by simply producing a tenure with zero signed blocks, causing the fallible lookup `get_parent_tenure_last_block` to return `Err`. Because the reset already happened, the signer is left with `Self::Uninitialized` until it fortuitously succeeds on a subsequent, unrelated burn block — mirroring the `_exitSafe` pattern in the Palmera report, where a single self-inflicted state change (`disableModule`) makes a required lookup (`getPreviewModule`) return the "missing" sentinel and the enclosing function hard-fails, leaving the caller's flow broken.

### Finding Description
`bitcoin_block_arrival` begins by taking the local state and swapping it out with `Self::Uninitialized`, with the comment explicitly stating the reset is meant to make failure-mode handling "safe": [1](#0-0) 

It only restores `self = Self::Initialized(...)` at the very end of the function, on the success path: [2](#0-1) 

In between, it computes the new miner view via `make_miner_state`, using `?` to propagate any error and leave `self` as `Uninitialized`: [3](#0-2) 

`make_miner_state` itself is fallible only because of `get_parent_tenure_last_block`: [4](#0-3) 

`get_parent_tenure_last_block` combines the stacks-node's view (`client.get_tenure_tip`) and the local signerdb's view (`SortitionData::get_tenure_last_block_info`, which only counts *signed* blocks). If **both** are empty — i.e., the parent tenure produced no block the node can report and no block was ever signed for it — the function hard-errors with `NoParentTenureInfo` instead of falling back to any default: [5](#0-4) 

A single miner fully controls whether their own tenure ever produces a signed block: if they win a sortition and simply never propose (or never get a block signed) during that tenure, then when the *next* sortition's burn-block arrival is processed, `parent_tenure_id` points at that empty tenure, and both lookups legitimately return nothing — triggering `NoParentTenureInfo` and leaving `self` as `Uninitialized`.

The caller in `signer.rs` only logs a warning and does not retry or repair the state: [6](#0-5) 

While `Uninitialized`, the signer cannot serialize a `StateMachineUpdate` (used to build proposal-evaluation views and to broadcast agreement state) — `update_parent_tenure_last_block` and the equivalent broadcast path silently no-op when `try_into_update_message_with_version` fails: [7](#0-6) 

and the inactivity-repair housekeeping explicitly skips any state machine that is not `Initialized`, so nothing proactively heals it: [8](#0-7) 

### Impact Explanation
This is the same bug class as the Palmera report: a lookup (`getPreviewModule` / `get_parent_tenure_last_block`) that a single actor can force into the "not found" branch by manipulating state they solely control (`disableModule` / mining an empty tenure), and the caller has already committed to a state transition (disabling further exits / wiping `self` to `Uninitialized`) before discovering the lookup will fail. The signer is wedged out of evaluating and signing any block proposals — matching the defined High-severity outcome "a signer wedged into never signing valid blocks" — until a subsequent, unrelated burn-block arrival happens to recompute successfully (i.e., the *next* parent tenure it needs to look up is non-empty). During that window the signer contributes no valid signature weight, which is a liveness degradation reachable by any single miner without cooperation from other signers or a majority.

### Likelihood Explanation
Triggerable unilaterally by any miner who wins a sortition slot and withholds block production for that tenure (or otherwise fails to get any block signed before the next sortition) — no majority of signers, no other signer's key, and no StackerDB/transport manipulation is required. The condition (`stacks_node_last_block == None && signerdb_last_block == None`) is a legitimate, reachable state, not a contrived edge case, since empty tenures are a normal occurrence (e.g., a miner tenure that times out or is orphaned before any block is produced).

### Recommendation
Do not treat `NoParentTenureInfo` as fatal in `bitcoin_block_arrival`/`make_miner_state`. Either (a) fall back to a well-defined default (e.g., reuse the last known-good `parent_tenure_last_block` from the prior initialized state, or treat the tenure as contributing no new tip rather than aborting), or (b) restructure `bitcoin_block_arrival` so the `Uninitialized` reset is not committed until the replacement state is fully computed, so a transient lookup failure leaves the *previous* valid state intact instead of wiping it.

### Proof of Concept
1. Miner A wins a sortition for tenure `T` and deliberately proposes zero blocks (or its only proposal never gets signed by any signer) before the next sortition occurs.
2. A subsequent sortition occurs (tenure `T+1`, `parent_tenure_id = T`), producing a `NewBurnBlock`/`SignerEvent::NewBurnBlock` event.
3. The signer runs `bitcoin_block_arrival` (`stacks-signer/src/v0/signer_state.rs:563-733`), which resets `self` to `Uninitialized` (line 575) and then calls `make_miner_state(T, ...)` → `get_parent_tenure_last_block(T)` (lines 682-688, 426-451, 379-423).
4. Because tenure `T` has no node-visible tip and no signed block in `signerdb`, both branches at lines 415-421 are `None`, returning `Err(SignerChainstateError::NoParentTenureInfo(T))`.
5. The `?` at line 688 propagates the error out of `bitcoin_block_arrival`; `signer.rs` logs a warning (lines 671-672) and does nothing further.
6. `self.local_state_machine` remains `LocalStateMachine::Uninitialized` until the next burn-block arrival succeeds, during which the signer cannot build a `StateMachineUpdate` (line 744-749) or correctly evaluate/sign block proposals.
