### Title
Signer broadcasts a fresh block-acceptance signature even when the state-machine mark that should authorize it fails, letting a locally GloballyRejected block be signed and re-accepted - (File: stacks-signer/src/v0/signer.rs)

### Summary
`BlockInfo::mark_pre_committed` and `BlockInfo::mark_locally_accepted` mutate `valid`/timestamp fields as unconditional side effects *before* attempting the actual state transition via `move_to`, and return an `Err` only if `move_to` fails [1](#0-0) . Their callers in `stacks-signer/src/v0/signer.rs` treat that `Err` as advisory rather than blocking: when `has_reached_consensus()` is true they suppress the warning and fall through to broadcast a pre-commit or a full signature regardless of whether the mark actually succeeded [2](#0-1) [3](#0-2) . This mirrors the reported bug class exactly: an operation's "not successful" result is ignored, and the event (here, a signature broadcast) is emitted anyway.

### Finding Description
`mark_pre_committed()`:
```rust
pub fn mark_pre_committed(&mut self) -> Result<(), String> {
    self.valid = Some(true);
    self.approved_time.get_or_insert(get_epoch_time_secs());
    self.move_to(BlockState::PreCommitted)
}
``` [4](#0-3) 

sets `valid = Some(true)` unconditionally, then attempts `move_to`, which can fail (e.g. `PreCommitted` is only reachable from `Unprocessed`) [5](#0-4) . The same pattern exists in `mark_locally_accepted` [6](#0-5) .

A `BlockInfo` can legitimately reach `GloballyRejected` from `LocallyAccepted` (a group-signed acceptance that never set `valid`, because `mark_locally_accepted(true)` only sets `signed_group`, not `valid`) followed by `mark_globally_rejected()`, which does not touch `valid` either [7](#0-6) . In this state, `valid == None` and `state == GloballyRejected`.

If a delayed `BlockValidateOk` for this same block later arrives, `handle_block_validate_ok` only short-circuits when `block_info.valid.is_some()` [8](#0-7)  — which is false here — so it proceeds. If `check_block_against_signer_db_state` finds no conflict, the `else` branch calls `mark_pre_committed()`:
```rust
if let Err(e) = block_info.mark_pre_committed() {
    // The block may have reached enough signatures before we validated the block ...
    if !block_info.has_reached_consensus()
        && block_info.state != BlockState::LocallyAccepted
    { warn!(...); return; }
}
self.signer_db.insert_block(&block_info)...;
self.send_block_pre_commit(signer_signature_hash.clone());
self.handle_block_pre_commit(stacks_client, sortition_state, &address, signer_signature_hash);
``` [9](#0-8) 

`mark_pre_committed()` fails (state stays `GloballyRejected`), but `has_reached_consensus()` is true, so the guard is bypassed and execution continues with `valid` now forced to `true` — a value that was never validated, and directly contradicts the terminal `GloballyRejected` state this signer itself recorded. The block is persisted with `valid=true`/`state=GloballyRejected`, a pre-commit is broadcast for it, and `handle_block_pre_commit` is invoked with our own address.

Inside `handle_block_pre_commit`, the guard `if !block_info.valid.unwrap_or(false) { return; }` [10](#0-9)  is now bypassed because `valid` is `true`. If the pre-commit weight threshold and the chainstate re-check both pass, execution reaches the sign branch:
```rust
if let Err(e) = block_info.mark_locally_accepted(false) {
    if !block_info.has_reached_consensus() {
        warn!("{self}: Failed to mark block as locally accepted: {e:?}",);
    }
}
self.signer_db.insert_block(&block_info)...;
let accepted = self.create_block_acceptance(&block_info.block);
self.handle_block_signature(stacks_client, sortition_state, &accepted);
self.send_block_response(&block_info.block, accepted.into());
``` [3](#0-2) 

`mark_locally_accepted(false)` fails because `move_to` forbids `LocallyAccepted` from `GloballyRejected` [11](#0-10) , but since `has_reached_consensus()` is true the warning is suppressed and, unconditionally, `create_block_acceptance` produces a real signature over the block and it is broadcast via `send_block_response`. The signer's own recorded rejection (a >30%-weight blocking outcome) is thereby converted into a broadcast acceptance signature — exactly analogous to the report's "emits events even when not success" pattern, except here the "event" is a cryptographic block-acceptance signature.

### Impact Explanation
This breaks the "rejection recounted as an accept" invariant explicitly called out as Critical impact: a signer that already locally concluded a block is `GloballyRejected` (dead) ends up broadcasting a valid signature accepting it anyway, contributing weight toward the 70% signing threshold for a block the signer itself determined should not be signed. Because the terminal `GloballyRejected`/`GloballyAccepted` states are meant to be mutually exclusive and final [5](#0-4) , this signature undermines the sticky-rejection guarantee the codebase's own design notes describe (docs/signer-flows.md, section on the block lifecycle) and can help revive a block the signer set already rejected.

### Likelihood Explanation
This requires: (1) the block to reach `LocallyAccepted` via group-signed peer signatures before this signer's own node validation completes (a normal, common race under the documented "asynchronous validation" design — see the `signers_wait_for_validation.rs` test acknowledging this exact race) [12](#0-11) ; (2) a blocking minority (>30% weight) of rejections to subsequently push the same block to `GloballyRejected`; and (3) the signer's own delayed `BlockValidateOk`/pre-commit replay to arrive afterward and pass `check_block_against_signer_db_state`. All three conditions are reachable by a single miner crafting a re-proposal/timing sequence plus ordinary gossip replay (pending pre-commit/signature tables already exist specifically to replay "early" messages), without requiring a majority of signers' keys or any auth-token access.

### Recommendation
In `stacks-signer/src/signerdb.rs`, make `mark_pre_committed` and `mark_locally_accepted` only mutate `valid`/timestamps *after* `move_to` succeeds (or roll back the mutation on `Err`). In `stacks-signer/src/v0/signer.rs`, change the callers so that when the mark fails, the code never proceeds to `create_block_acceptance` / `send_block_pre_commit` / `send_block_response` unless the state is confirmed to be `GloballyAccepted` specifically — not merely `has_reached_consensus()` (which also matches `GloballyRejected`). A rejected block must never fall through to a broadcast signature.

### Proof of Concept
1. Signer S receives enough peer `BlockPreCommit`/`BlockResponse::Accepted` messages for block B to cross the pre-commit/signing weight threshold before S's own `submit_block_for_validation` response returns; `store_and_process_block_signature`/`handle_block_pre_commit` calls `mark_locally_accepted(true)`, moving B to `LocallyAccepted` with `valid` left `None` [6](#0-5) .
2. A blocking minority of other signers (>30% weight) then reject B for reasons unrelated to S's chainstate view; `store_and_process_block_rejection`/`handle_block_rejection` drives B to `GloballyRejected` via `mark_globally_rejected()`, which also never touches `valid` [13](#0-12) .
3. S's stacks-node finally returns the (delayed) `BlockValidateOk` for B. `handle_block_validate_ok` passes the `valid.is_some()` guard (still `None`) [8](#0-7) , `check_block_against_signer_db_state` returns `None`, and `mark_pre_committed()` is called: `valid` is forced to `true`, `move_to` fails, but because `has_reached_consensus()` is true the code proceeds to `send_block_pre_commit` and self-triggers `handle_block_pre_commit` [9](#0-8) .
4. Inside `handle_block_pre_commit`, the `valid` guard now passes (`true`), the pre-commit/chainstate checks pass, and `mark_locally_accepted(false)` is invoked; it fails the `move_to` (disallowed from `GloballyRejected`) but the code unconditionally calls `create_block_acceptance`, `handle_block_signature`, and `send_block_response`, broadcasting a genuine signature for B [3](#0-2) .

Result: S's own rejected-block verdict is silently overwritten and a real acceptance signature for a `GloballyRejected` block is broadcast to the network.

    /// Mark this block as valid and the appropriate timestamps if they aren't already set, and attempt to mark it as locally accepted.
    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Mark this block's signed group time if not already set and attempt to mark it as globally accepted.
    pub fn mark_globally_accepted(&mut self) -> Result<(), String> {
        self.signed_group.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::GloballyAccepted)
    }

    /// Mark this block as invalid and attempt to mark it as locally rejected
    pub fn mark_locally_rejected(&mut self) -> Result<(), String> {
        self.valid = Some(false);
        self.move_to(BlockState::LocallyRejected)
    }

    pub fn mark_globally_rejected(&mut self) -> Result<(), String> {
        self.move_to(BlockState::GloballyRejected)

    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(

            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
