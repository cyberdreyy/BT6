### Title
Unauthenticated attacker can flood `savedCallbacks` to trigger premature eviction of a victim's pending trigger request, causing silent starvation of their response - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` accepts any message with a syntactically valid ECDSA signature (any keypair, no allowlist check) and unconditionally stores a `savedCallback` keyed by attacker-controlled `MessageId`. `pruneCallbacks` runs every `CallbackPruneIntervalSec` and, when `len(savedCallbacks) > MaxSavedCallbacks`, deletes the oldest half by `createdAt` without ever calling `SendResponse` on the evicted callbacks, silently orphaning any legitimate still-pending request that happens to be older.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go:267-269`) routes any legacy-style signed message straight to `h.HandleLegacyUserMessage(ctx, msg, callback)` after only `msg.Validate()`, which just checks field lengths and that the signature is well-formed/recoverable — it does not check DON membership, an allowlist, or per-sender quota [1](#0-0) [2](#0-1) . The `HandleLegacyUserMessage` function itself contains an explicit TODO acknowledging the missing allowlist/rate-limit: `// TODO: apply allowlist and rate-limiting here` [3](#0-2) . Any caller who can produce a fresh keypair, sign a well-formed trigger payload, and choose a unique `MessageId` gets an entry inserted into the shared map: [4](#0-3) .

`pruneCallbacks` runs on a fixed timer (`CallbackPruneIntervalSec`, default 30s) and, once the map exceeds `MaxSavedCallbacks` (default 20000), sorts all entries by `createdAt` and deletes the oldest half via plain `delete()` — it never invokes the evicted callback's `SendResponse`: [5](#0-4) . Because eviction is by absolute age across the whole shared map (not per-sender), an attacker who registers a burst of >`MaxSavedCallbacks`/2 new callbacks in a single prune interval will cause the *oldest* entries — which may include a legitimate victim's still-outstanding request awaiting a DON node's response — to be silently dropped from the map. When the DON node eventually replies via `handleWebAPITriggerMessage`, the lookup `h.savedCallbacks[msg.Body.MessageId]` returns `found == false` and the response is simply discarded [6](#0-5) . The victim's blocked `callback.Wait(ctx)` in `gateway.ProcessRequest` then only unblocks via its own context timeout, returning a generic `handler timeout` / `RequestTimeoutError` rather than the actual (already computed) response [7](#0-6) .

No existing check stops this: `msg.Validate()` only validates signature well-formedness, not sender authorization; `nodeRateLimiter` in this handler only throttles *outgoing* messages keyed by `nodeAddr` in `handleWebAPIOutgoingMessage`, not inbound user message ingestion into `savedCallbacks`; there is no per-sender cap on `savedCallbacks` entries.

### Impact Explanation
This is a shared-resource denial-of-isolation / DoS between unprivileged callers of the same DON handler instance: one attacker (needing only the ability to generate ECDSA keypairs and sign messages — no credentials, no allowlist membership) can cause another legitimate user's trigger request to time out and appear to fail, even though the underlying DON node did respond correctly. This does not lead to fund loss, key disclosure, or privilege escalation, but is a legitimate availability/DoS impact under Chainlink's bounty impact classes for gateway service disruption affecting other tenants.

### Likelihood Explanation
Feasible and repeatable with modest effort: an attacker only needs to generate many keypairs (or reuse one, incrementing `MessageId`), sign `web_api_trigger` payloads with a valid current timestamp, and send >`MaxSavedCallbacks`/2 (default 10,000) requests within one `CallbackPruneIntervalSec` window (default 30s) to guarantee eviction of older entries. No authentication, allowlisting, or elevated role is required; the code path is unauthenticated except for signature well-formedness, which the attacker fully controls with a self-generated key.

### Recommendation
- Enforce a per-sender allowlist and/or per-sender quota for `savedCallbacks` insertion in `HandleLegacyUserMessage` (the code already has a TODO for this).
- On eviction in `pruneCallbacks`, invoke `SendResponse` with an explicit timeout/overloaded error instead of silently deleting, so callers fail fast with an accurate error rather than hanging until their own context timeout.
- Consider bounding `savedCallbacks` growth proactively (reject new inserts once at capacity, returning a "server overloaded" error) rather than only pruning periodically after the fact.

### Proof of Concept
Go handler-level integration test plan (`core/services/gateway/handlers/capabilities/handler_test.go`):
1. Configure handler with a small `MaxSavedCallbacks` (e.g., 10) and short `CallbackPruneIntervalSec`.
2. Register a "victim" callback via `handler.HandleLegacyUserMessage` with a unique, early `MessageId`; do not deliver a node response yet.
3. In a loop, call `handler.HandleLegacyUserMessage` with freshly generated signing keys and unique `MessageId`s to exceed `MaxSavedCallbacks` (e.g., insert 20 more entries), advancing/mocking time so the victim's `createdAt` is the oldest.
4. Manually invoke `handler.pruneCallbacks()` (or wait for the ticker).
5. Assert `handler.savedCallbacks` no longer contains the victim's `MessageId`.
6. Deliver the legitimate node response for the victim's `MessageId` via `handler.HandleNodeMessage`, and assert that `victimCallback.Wait(ctx)` times out / never receives the expected `UserCallbackPayload`, proving the response was silently dropped instead of delivered or erroring immediately.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
