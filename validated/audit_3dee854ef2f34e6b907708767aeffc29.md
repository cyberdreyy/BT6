## Title
Signer fails open and double-signs a sibling block in the same tenure when the node's tenure-tip lookup errors or 404s - ([File: stacks-signer/src/v0/signer.rs])

### Summary
When the pre-commit threshold is reached for a block whose only surviving conflict is a *stale* self-conflict in its *own* tenure, the signer asks the node for that tenure's canonical tip via `get_tenure_tip` to decide whether the earlier signed sibling is already confirmed on-chain. If that RPC call returns any error — including a plain `404 Not Found` meaning "the node has no blocks in this tenure at all" — the signer logs a warning and falls through to sign the new block anyway, rather than refusing. This is the same fail-open pattern as the Traefik advisory: a security-relevant lookup fails or cannot be resolved, the failure is only logged, and the caller proceeds as if the check had passed.

### Finding Description
The relevant logic lives in `Signer::handle_block_pre_commit`'s stale-conflict handling in [1](#0-0) :

```rust
if conflicts.iter().any(|conflict| {
    conflict.consensus_hash == block_info.block.header.consensus_hash
        && !self.reorg_permit_stands(stacks_client, conflict)
}) {
    match stacks_client.get_tenure_tip(&block_info.block.header.consensus_hash) {
        Ok(tip) => {
            let tip_height = tip.anchored_header.height();
            if tip_height >= block_info.block.header.chain_length {
                warn!(... "Refusing to sign.");
                return;
            }
        }
        Err(e) => {
            warn!(
                "{self}: Failed to fetch the canonical tip of the proposed block's tenure: {e:?}. Treating the tenure as unconfirmed.";
                ...
            );
        }
    }
}
```

Unlike the analogous fresh-conflict check in `conflict_still_blocks`, which explicitly distinguishes a `NOT_FOUND` response from other errors and treats an unreachable node as "conflict keeps blocking" (fail closed) — see [2](#0-1)  — this stale-conflict branch collapses both a transient RPC failure *and* a legitimate 404 (meaning the node simply has never received any block for that tenure yet) into a single `Err(e)` arm that only logs and does not `return`. Execution falls through to the signing path at the end of the function, so `mark_locally_accepted` / `handle_block_signature` proceed exactly as if the lookup had confirmed the tenure was unconfirmed on-chain.

The docs for this exact branch acknowledge the asymmetry explicitly: "For the own-tenure question below, an unreachable node is instead treated as unconfirmed and the signature goes out" [3](#0-2) , and the corresponding flowchart shows `TIP -- "node unreachable" --> SIGN` right next to `TIP -- "no — never confirmed" --> SIGN` [4](#0-3) .

The equality this breaks is the "one signature per height per tenure" guard the whole pre-commit conflict machinery exists to enforce (see the guard's own stated purpose: "The guard exists to stop us endorsing two blocks that could both end up in the chain" [5](#0-4) ). A `404`/error response to `get_tenure_tip` is not proof the earlier sibling was never confirmed — it can equally mean the earlier signed block simply has not yet been handed to *this* node (blocks are only pushed to the node once the *entire* signer set has signed, per the code comment at `check_latest_block_in_tenure` and `get_signed_conflicts`, e.g. [6](#0-5) ). Treating that ambiguity as "safe to sign" reintroduces exactly the double-sign the whole pre-commit re-check was built to prevent.

### Impact Explanation
If this signer ends up signing two different blocks (A and B) at the same height within the same tenure, that is a critical equivocation: a single signer contributing conflicting signatures toward two blocks that could both end up canonical satisfies the "a signer signing an invalid, non-canonical, or conflicting block" criterion. It does not require compromising any other signer's key, a majority of signers, or any privileged access — only a single miner (one slot) crafting two sibling proposals in the same tenure spaced far enough apart that the first signature becomes stale, combined with the completely ordinary condition that the first block was never (yet) handed off to this signer's node (which happens naturally, since node hand-off requires the *whole* signer set, not just this one signer, to have signed).

### Likelihood Explanation
The precondition — the earlier sibling never having reached the node — is a *normal* operating condition, not an exotic fault: it is guaranteed to be true for any block this signer accepted before the entire signer set reached consensus and pushed it to the node. A single miner only needs to: (1) get one block A signed/locally-accepted by this signer in tenure T at height H, (2) wait past `tenure_last_block_proposal_timeout` so A's endorsement is "stale," and (3) propose a sibling block B in the same tenure T at the same height H. No RPC failure or network fault is even required to trigger this path — a genuine, un-pushed block naturally 404s at `get_tenure_tip`.

### Recommendation
Mirror the fail-closed handling already used in `conflict_still_blocks` and `reorg_permit_stands`: on any `Err` from `get_tenure_tip` in the own-tenure stale-conflict branch — including `NOT_FOUND` — refuse to sign (`return`) rather than falling through, or at minimum require a second, independent confirmation (e.g., checking `signed_group`/global acceptance state locally) before treating "tenure not found on this node" as proof the earlier sibling is unconfirmed.

### Proof of Concept
1. Miner proposes block A (tenure T, height H). Enough of the signer set (or just this signer, if only local accept is needed to set `signed_self`) causes this signer to sign/locally-accept A: `signed_self` is set ( [7](#0-6) ).
2. A is not yet pushed to the node (normal: hand-off requires full signer-set signatures), so `get_tenure_tip(T)` on this signer's node would 404.
3. Wait until `A.signed_self` age exceeds `tenure_last_block_proposal_timeout` (freshness cutoff), so the fresh-conflict path in `handle_block_pre_commit` ( [8](#0-7) ) no longer blocks.
4. Miner proposes sibling block B (same tenure T, same height H). It passes validation and reaches the pre-commit threshold. `get_signed_conflicts` returns A as a same-tenure conflict ( [9](#0-8) ).
5. `handle_block_pre_commit` reaches the own-tenure stale-conflict block, calls `get_tenure_tip(T)`, which returns `Err(NOT_FOUND)` since A was never pushed. The code logs "Treating the tenure as unconfirmed" and falls through, signing B ( [10](#0-9) ).
6. This signer now holds valid signatures over both A and B at the same height in tenure T — an equivocation.

    /// Return every signed block at or above the given Stacks height, in ANY tenure, excluding
    /// the block with the given signer signature hash, ordered by height (highest first). A
    /// block is considered signed if a signature was ever put over it, ours (`signed_self`)
    /// or the observed group's (`signed_group`). Blocks that were only pre-committed carry no
    /// signature and are never returned. Each row carries the most recent endorsement time
    /// (`signed_self`/`signed_group`, whichever is later) so the caller can judge freshness per
    /// conflict.
    ///
    /// The search deliberately spans all tenures: two blocks at the same height are siblings
    /// no matter which tenure they belong to (e.g. a tenure-start block conflicts with the
    /// previous tenure's block at the same height), so a signature over either may conflict
    /// with a fresh signature over the other.
    ///
    /// Blocks in tenures whose reorg we sanctioned under the reorg-timing rules (see
    /// [`SignerDb::mark_tenure_superseded`]) are still returned, but annotated with the
    /// permitting tenure's sortition (`superseded_by_*`): the permit only holds while that
    /// sortition is canonical, which the caller derives from the node per evaluation (see
    /// `Signer::reorg_permit_stands`) -- like every other question about whether a conflict is
    /// still *live* (`Signer::conflict_still_blocks`), it is not recorded.

    pub fn get_signed_conflicts(
        &self,
        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,
    ) -> Result<Vec<SignedConflictInfo>, DBError> {
        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,
                MAX(COALESCE(b.signed_self, 0), COALESCE(b.signed_group, 0)) AS last_endorsed,
                st.superseded_by_consensus_hash, st.superseded_by_burn_block_hash
            FROM blocks b
            LEFT JOIN superseded_tenures st ON st.consensus_hash = b.consensus_hash
            WHERE (b.signed_self IS NOT NULL OR b.signed_group IS NOT NULL)
                AND b.stacks_height >= ?1
                AND b.signer_signature_hash != ?2
            ORDER BY b.stacks_height DESC";
        let args = params![
            u64_to_sql(height)?,
            excluded_signer_signature_hash.to_string(),
        ];
        query_rows(&self.db, query, args)
    }
