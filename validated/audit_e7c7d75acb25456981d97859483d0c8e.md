## Analysis

The bug-class in the Argo advisory — a network listener that trusts unauthenticated remote input and executes privileged actions on it — has a direct analog in the stacks-signer's own inbound HTTP listener.

The `SignerEventReceiver`'s HTTP server accepts POST requests on `/proposal_response`, `/new_block`, `/new_burn_block`, and `/stackerdb_chunks` with **no authentication check on the request itself** — only method/URL routing is checked before the body is deserialized and forwarded into the runloop [1](#0-0) . `process_event` reads the body and deserializes it directly into a typed event with no signature, token, or source-IP verification [2](#0-1) . The `auth_token`/`auth_password` setting only protects the **node's** RPC (`/v3/block_proposal`) — it plays no role in authenticating the **signer's** own inbound listener [3](#0-2) . Shipped reference configs even bind this listener to `0.0.0.0` [4](#0-3) .

On the consumption side, `handle_block_validate_ok` unconditionally trusts a `BlockValidateOk` keyed only by `signer_signature_hash`: it clears the pending submission, records validation time, and — if `block_info.valid` is still `None` — proceeds straight to `mark_pre_committed`/signing after only a narrow consistency re-check (`check_block_against_signer_db_state`, which covers tenure/parent bookkeeping, not transaction execution) [5](#0-4) . If `block_info.valid` is already set (a decision was made), any later response — including the real node's — is discarded [6](#0-5) .

### Title
Unauthenticated signer event listener lets a single miner forge a `BlockValidateOk`, causing the signer to sign a block that was never validated by its node — ([File: libsigner/src/events.rs])

### Summary
The signer's own HTTP event listener (bound by shipped configs to `0.0.0.0`) performs no authentication of inbound POSTs before dispatching them as `BlockValidateResponse` events into the signer runloop. A miner who legitimately proposes a block over StackerDB can, in parallel, forge a fake "validated OK" response to this listener for that block's known `signer_signature_hash`, causing the signer to treat an un-validated (possibly invalid) block as validated and sign it — breaking the "signed vs validated" invariant.

### Finding Description
`SignerEventReceiver::next_event` routes any POST to `/proposal_response` straight into `process_event::<T, BlockValidateResponse>` without checking any credential, token, or peer identity [7](#0-6) . The resulting `SignerEvent` is forwarded to the runloop and dispatched to `handle_block_validate_ok`, which is keyed purely on `signer_signature_hash` — a value that is publicly broadcast by the miner over StackerDB as soon as the block proposal is announced [8](#0-7) . Because there is only one authentication mechanism in the system (`auth_token`/`auth_password`, which secures the **node's** RPC surface, not the **signer's** own listening port) [9](#0-8) , any network peer that can reach the signer's `endpoint` (default sample binds to `0.0.0.0:30000`) can inject a forged "OK" verdict for a block hash it did not compute or validate.

`handle_block_validate_ok` then performs only the narrow `check_block_against_signer_db_state` re-check (tenure/parent/consensus-hash bookkeeping) before marking the block pre-committed and moving it toward a signature [10](#0-9) ; it does not independently re-run the node's execution/validation pipeline. Once `block_info.valid` is set this way, the genuine, later-arriving rejection from the real node is discarded because of the "already processed" guard [6](#0-5) .

### Impact Explanation
This breaks the "signed vs validated" equality called out in scope: the signer's cryptographic signature is meant to attest that the paired stacks-node executed and accepted the block, but here the "validated" state is established purely from an unauthenticated network message, decoupled from any real execution by the node. A single miner (already able to broadcast one syntactically-plausible-but-semantically-invalid proposal, which is a permitted action) combined with network reach to the signer's listener can cause that signer to sign an invalid/non-canonical block — the Critical impact tier defined for this scan.

### Likelihood Explanation
Exploitation requires only: (1) the attacker's ordinary ability to broadcast a block proposal as a miner, and (2) network reachability to the signer's own event-receiver port. No majority of signers, no other signer's private key, and no knowledge of `auth_token` is required, since that token does not gate this endpoint at all. The reference/sample configurations bind this listener to `0.0.0.0`, and the operator warning in the codebase only cautions about exposing the *node* to external signers, not about exposing the *signer's* own listener [11](#0-10) .

### Recommendation
Authenticate inbound requests to the signer's event-receiver HTTP endpoint (e.g., require and check the same `auth_token`/shared secret used between node and signer on every request, not just at the transport layer), and/or bind the listener to loopback/a private interface by default. Additionally, `handle_block_validate_ok` should not treat a `BlockValidateOk` as authoritative proof of validation unless it can be tied to the specific submission made to the node (e.g., via a per-submission nonce/token correlated with `submit_block_for_validation`), rather than solely trusting the correlating hash value that is public knowledge.

### Proof of Concept
1. Configure a signer per the shipped sample (`endpoint = "0.0.0.0:30000"`) [4](#0-3) .
2. As a miner, broadcast a block proposal over StackerDB that is syntactically valid but would fail real chainstate execution (e.g., contains a transaction that violates a cost limit or double-spends) — the signer stores it `Unprocessed` and submits it to its node for validation [12](#0-11) .
3. Immediately POST a forged `BlockValidateResponse::Ok` JSON body (containing the same `signer_signature_hash`) to `http://<signer-endpoint>/proposal_response` — no credentials are required [13](#0-12) .
4. The signer processes the forged event via `handle_block_validate_ok`, marks the block pre-committed, and proceeds toward signing it — even though the real node either has not yet responded or would reject it [10](#0-9) ; the eventual genuine rejection from the node is dropped by the "already processed" guard [6](#0-5) .

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
