### Title
Symlink traversal bypasses build-directory confinement check in `fileArchiver.process` - (File: commands/helpers/file_archiver.go)

### Summary
`fileArchiver.process` validates that a candidate path stays inside `c.wd` using purely lexical operations (`filepath.Abs` + `filepath.Rel` + a `".."+Separator` prefix check), never resolving symlinks. A directory symlink placed inside the working directory that points outside it (e.g. to `/etc` or a sibling directory) produces a path string that lexically resolves under `c.wd`, passes the confinement check, and is then `os.Lstat`'d and archived even though the OS transparently follows the symlink component when opening/stating the file, so the real file lives outside `c.wd`.

### Finding Description
`process()` only manipulates the path string: [1](#0-0) 
`filepath.Abs`/`filepath.Rel` are purely lexical (`path/filepath` docs: they do not touch the filesystem or resolve symlinks). If the working directory contains a symlinked directory (`c.wd/evil -> /etc`), a match such as `c.wd/evil/passwd` yields `relative = "evil/passwd"`, which does **not** start with `"..`+Separator`, so the check at line 77 passes. `c.add()` then calls `os.Lstat(path)` on that relative path, and since only the final path component is `Lstat`'d (not resolved), the OS still walks through the `evil` symlink to reach the real, out-of-tree file: [2](#0-1) 
The `doublestar.WithNoFollow()` option used in `processPath` only guards against symlink cycles/expansion during `**` glob wildcard traversal: [3](#0-2) 
It does not stop a literal, non-wildcard path segment (or `filepath.Walk`, which itself also does not follow symlinks for *sub*-entries but does not re-validate the *root* `match` value's realpath against `c.wd` either) from being emitted as a match whose real location is outside `c.wd`. Nothing in `process`, `add`, or the callers (`processPath`, `processUntracked`) calls `filepath.EvalSymlinks` (or equivalent) to compare the *real* path against `c.wd` before accepting the file into `c.files`. The existing integration test fixtures (`setupEnvironment` in `commands/helpers/file_archiver_integration_test.go`) only exercise symlinks that stay *inside* the same project root, so the case of a symlink escaping `c.wd` entirely is untested. [4](#0-3) 

### Impact Explanation
This is a violation of the documented invariant that "file operations must stay within intended build/cache/artifact roots." Concretely, an attacker-controlled pipeline that can create a symlink inside the working directory (e.g., via a checked-in repo symlink, a build step, or `GIT_STRATEGY`/cache reuse leaving a stale symlink) and reference it through `artifacts:paths`/`cache:paths` can cause the runner to package files reachable through that symlink into the job's artifact or cache archive — files that are lexically "outside build directory" by the code's own intended rule but slip past the check. This converts local filesystem read access the job process already has into a persistently stored, downloadable CI artifact, which is a meaningful exfiltration/persistence primitive distinct from merely `cat`-ing the file into job logs (which are size-limited/maskable), especially on runners without egress but with artifact upload enabled.

### Likelihood Explanation
Preconditions are simple and fully attacker-controlled: an unprivileged pipeline author only needs to create a symlink inside the checkout (a symlink can be committed to a git repo, or created by a build step) pointing to a path outside `c.wd` that the runner process can read, and declare an `artifacts:paths`/`cache:paths` entry that traverses that symlink. The behavior is deterministic and 100% reproducible — no race condition or timing dependency.

### Recommendation
In `fileArchiver.process` (and consistently in `findRelativePathInProject`), resolve the real path with `filepath.EvalSymlinks` (or manually resolve and validate each path component) before or in addition to the lexical `filepath.Rel` check, and reject any match whose resolved real path is not itself a descendant of `filepath.EvalSymlinks(c.wd)`. Apply the same real-path validation to `c.add`/`os.Lstat` so a path that lexically looks like `evil/passwd` but resolves outside `c.wd` is rejected before being added to `c.files`.

### Proof of Concept
```go
func TestFileArchiverRejectsSymlinkEscapingWorkingDirectory(t *testing.T) {
    wd := t.TempDir()
    outside := t.TempDir()
    secret := filepath.Join(outside, "secret.txt")
    require.NoError(t, os.WriteFile(secret, []byte("top-secret"), 0644))

    // symlinked directory inside wd pointing outside wd
    linkDir := filepath.Join(wd, "evil")
    require.NoError(t, os.Symlink(outside, linkDir))

    oldWd, _ := os.Getwd()
    defer os.Chdir(oldWd)
    require.NoError(t, os.Chdir(wd))

    f := fileArchiver{Paths: []string{"evil/secret.txt"}}
    err := f.enumerate()
    require.NoError(t, err)

    // Expect: file must NOT be archived because its real path
    // (outside/secret.txt) escapes c.wd, even though the lexical
    // relative path "evil/secret.txt" does not start with "..".
    assert.Empty(t, f.sortedFiles(),
        "archiver must not include files reached via a symlink escaping the working directory")
}
```
Running this test against the current implementation is expected to **fail** (the file is included), demonstrating the bypass; after adding real-path validation with `filepath.EvalSymlinks`, the test should pass.

```go
func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

	if err == nil {
		// Process path only if it lives in our build directory
		if !strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			excluded, rule := c.isExcluded(relative)
			if excluded {
				c.exclude(rule)
				return false
			}

			err = c.add(relative)
		} else {
			err = errors.New("not supported: outside build directory")
		}
	}
```

```go
func (c *fileArchiver) add(path string) error {
	// Always use slashes
	path = filepath.ToSlash(path)

	// Check if file exist
	info, err := os.Lstat(path)
	if err == nil {
		c.files[path] = info
	}

	return err
}
```
