### Title
Stale confirmations from removed multisig members count toward execution threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` tallies a request's approval count purely from the `confirmations: LookupMap<RequestId, HashSet<String>>` set without checking whether each entry still belongs to a current member. `delete_member` only purges confirmations for requests that the *removed member itself created* (`r.member == member`), not confirmations that removed member cast on other members' outstanding requests. A member can therefore be evicted from the multisig while their prior confirmation on someone else's still-pending request keeps counting toward `num_confirmations`, letting that request execute with fewer than `num_confirmations` live approvers.

### Finding Description
The binding that must hold is: `confirmations recorded on a request == confirmations from currently-live members`. The confirm-threshold check breaks this equality: [1](#0-0) 

`confirm` reads `self.confirmations.get(&request_id)` and compares `confirmations.len() as u32 + 1 >= self.num_confirmations` with no filtering against `self.members`.

`delete_member` cleans up only requests that the *departing* member originated: [2](#0-1) 

The filter is `r.member == member` (the request's creator/signer), i.e. it removes requests that member itself added and their associated confirmation sets. It never scans other requests' `confirmations` HashSets to strip entries where the *confirmer* (not the creator) equals the removed member. Those stale entries physically remain in the `confirmations` LookupMap for requests created by other, still-live members.

Concrete path:
1. Members `{A, B, C, D}`, `num_confirmations = 3`.
2. `A` calls `add_request` creating request `R` (e.g. `Transfer`). `B` and `C` call `confirm(R)`; `confirmations[R] = {B, C}` (2 < 3, not yet executed).
3. A separate `DeleteMember{member: B}` request is created and confirmed by 3 live members (`A, C, D`), executing `delete_member`. Per the code above, this only clears requests *created by* `B`; `R` was created by `A`, so `confirmations[R]` still contains `B` even though `B` is no longer in `self.members`.
4. `D` now calls `confirm(R)`. `confirmations.len()` (`{B, C}`) `+ 1 = 3 >= num_confirmations (3)`, so `R` executes — even though the only genuinely live confirmers are `C` and `D` (2 of 4 current members), one short of the configured 3-of-n threshold.

### Impact Explanation
This lets a `MultiSigRequest` (including `Transfer`, `FunctionCall`, `AddKey`, further `AddMember`/`DeleteMember`, etc.) execute with fewer live confirmations than `num_confirmations` mandates, i.e. a multisig request executed below threshold. This is a Critical-severity break of the multisig's core custody guarantee — funds or privileged actions can be authorized by a coalition smaller than the configured k-of-n security threshold, up to and including moving NEAR out of the account.

### Likelihood Explanation
This requires no special privilege beyond being (at some point) a legitimate member who confirms a pending request and is later removed via the normal `DeleteMember` governance flow — a routine operational event (e.g., rotating out an employee or compromised key). No attacker key, redeploy, or infrastructure control is needed; it's a deterministic consequence of `delete_member`'s incomplete cleanup combined with `confirm`'s unfiltered count.

### Recommendation
When removing a member in `delete_member`, iterate over all entries in `self.confirmations` (not just requests the member created) and remove the departing member's identity string from every confirmation `HashSet`. Alternatively, change `confirm`'s threshold check to only count confirmation entries whose signer is currently present in `self.members`, e.g. by filtering `confirmations.iter().filter(|m| self.members.contains(m)).count()` before comparing against `num_confirmations`.

### Proof of Concept
```rust
// members = {A, B, C, D}, num_confirmations = 3
let r = add_request(...);          // created by A
confirm(r);                        // as B -> confirmations[r] = {B}
confirm(r);                        // as C -> confirmations[r] = {B, C}  (2 < 3)

// Separately remove B via a fully-confirmed DeleteMember request
add_request_and_confirm(DeleteMember{ member: B });
// -> delete_member only clears requests where r.member == B; confirmations[r] untouched

confirm(r);                        // as D -> confirmations.len() (2) + 1 = 3 >= 3 -> EXECUTES
// Only C and D are live confirmers (2 of 4 members), below the configured 3-of-n threshold.
```

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
