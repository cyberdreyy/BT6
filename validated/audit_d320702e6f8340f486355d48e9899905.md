### Title
Unauthenticated disclosure of LOOP plugin registry via `/discovery` and `/plugins/:name/metrics` endpoints - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` mounts `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the base `api` router group with no `auth.Authenticate` wrapper, unlike every other route group (`debugRoutes`, `sessionRoutes`'s authenticated group, `authv2`). This lets a fully unauthenticated network client enumerate the node's registered LOOP plugin names, their Prometheus metrics paths, and pull live metrics/pprof profiling data from those plugins.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the base group `api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))` (no auth middleware) and then calls `loopRoutes(app, api)` directly on that unauthenticated group: [1](#0-0) . Compare this to `debugRoutes`, which wraps its group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [2](#0-1) , and to `v2Routes`'s `authv2` group which requires token/session auth for almost all endpoints [3](#0-2) .

`loopRoutes` itself registers the handlers with no auth middleware at all: [4](#0-3) .

`discoveryHandler` in `core/web/loop_registry.go` iterates `l.registry.List()` and returns a JSON array of Prometheus service-discovery target groups, one per registered LOOP plugin, each labeled with `LabelMetaPluginName` (the plugin's name) and its metrics scrape path `/plugins/<name>/metrics`: [5](#0-4) . `pluginMetricHandler` then proxies to the internal plugin's `/metrics` endpoint using only the `:name` path param with no auth check: [6](#0-5) . The pprof handlers (`pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) similarly proxy debug/pprof requests to the internal LOOP plugin process without any authentication: [7](#0-6) .

No auth middleware, session check, or token check exists anywhere on the request path from `GET /discovery` (or `GET /plugins/:name/metrics`, or the pprof endpoints) to these handlers.

### Impact Explanation
This falls under Chainlink's "informational disclosure" / "sensitive data exposure" bounty class rather than key/fund compromise: an unauthenticated attacker on the network can enumerate the exact set of LOOP plugins running on a node (revealing internal architecture/topology), scrape their Prometheus metrics (which may include operationally sensitive counters/gauges depending on plugin implementation), and reach `/debug/pprof/*` and `/debug/pprof/symbol` proxied through the plugin metrics port, enabling runtime profiling/introspection of the plugin process without credentials. This is a real, exploitable authentication gap on a production HTTP route, not merely a misconfiguration, since the code explicitly mounts it on the unauthenticated `api` group.

### Likelihood Explanation
No preconditions beyond network reachability to the node's web server port. Any unauthenticated HTTP client can send `GET /discovery` and receive `200 OK` with the full plugin list; this is 100% repeatable and requires no credentials, tokens, or session cookies.

### Recommendation
Wrap `loopRoutes` registrations with the same authentication middleware used for other internal/debug endpoints, e.g. mount them via a group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` (and consider requiring admin role, similar to `auth.RequiresAdminRole`), or restrict `/discovery` and `/plugins/*` to a separate internal-only listener/network segment intended only for the Prometheus scraper rather than the public API port.

### Proof of Concept
Existing test `TestLoopRegistry` in `core/web/loop_registry_test.go` already demonstrates this: it creates `client := app.NewHTTPClient(nil)` (no auth credentials) [8](#0-7) , then issues `client.Get("/discovery")` and asserts `http.StatusOK` with the full plugin/label list decoded successfully [9](#0-8) , and separately `client.Get(expectedLooppEndPoint)` (`/plugins/mockLoopImpl/metrics`) also returns `200 OK` with plugin metric contents [10](#0-9) . A minimal handler-level PoC: build the router via `web.NewRouter(app, nil)`, issue `httptest.NewRecorder()` + `http.NewRequest("GET", "/discovery", nil)` with no `Authorization` header or session cookie, call `router.ServeHTTP(rec, req)`, and assert `rec.Code == http.StatusOK` and the response body contains the registered plugin name(s) — confirming unauthenticated disclosure.

```go
// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
