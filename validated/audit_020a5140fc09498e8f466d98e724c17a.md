### Title
Path traversal in artifact metadata generation via unsanitized `artifacts:name` - (File: commands/helpers/artifact_metadata.go)

### Summary
`ArtifactsUploaderCommand.Execute` passes the job-controlled `c.Name` (set from the `artifacts:name` CI/CD field) directly as `artifactName` into `generateStatementToFile`, bypassing the `filepath.Base()` sanitization that is applied to the same value when computing the actual archive filename via `artifactFilename()`. The unsanitized value is used in `filepath.Join(opts.artifactsWd, fmt.Sprintf(artifactsStatementFormat, opts.artifactName))`, allowing a `../` sequence to make the resulting metadata file path escape `opts.artifactsWd`.

### Finding Description
In `commands/helpers/artifacts_uploader.go`, `Execute` calls: [1](#0-0) 

Note that `c.Name` is passed as `artifactName` unmodified. Compare this with `createBodyProvider`, which computes the actual upload filename through `artifactFilename`, applying `filepath.Base(name)` sanitation before use: [2](#0-1) [3](#0-2) 

`generateStatementToFile` then builds the destination path with no sanitation at all: [4](#0-3) 

`fmt.Sprintf(artifactsStatementFormat, opts.artifactName)` produces `"<artifactName>-metadata.json"`. If `artifactName` contains `../` sequences (e.g. `../../other-namespace/other-project`), `filepath.Join` cleans the resulting path such that it resolves outside `opts.artifactsWd` (which is `c.wd`, the job's build/working directory). `os.WriteFile` then writes the JSON metadata file to that escaped path, overwriting or creating files outside the build root.

`c.Name` originates from the `artifacts:name` field in `.gitlab-ci.yml`, only passed through `shell.Expand` for shell-variable expansion (not path sanitization) in `normalizeArgs`: [5](#0-4) 

This confirms there is no path-traversal check between the CI-controlled name and the file write in `generateStatementToFile`. The only sanitation that exists (`filepath.Base` in `artifactFilename`) is not applied on this code path.

### Impact Explanation
On a shared runner host (e.g., shell/host executors, or any executor where the build root is a real filesystem path reachable outside the sandbox), an unprivileged pipeline author who sets `artifacts:name: '../../other-namespace/other-project/pwned'` combined with `RUNNER_GENERATE_ARTIFACTS_METADATA=true` can cause the runner helper to write a `pwned-metadata.json` file outside the job's own build directory, into another project's or shared area's path — a cross-project file write/overwrite that persists after the job completes. This matches the "medium persistent multi-tenant disruption" scope: it is a build-root escape via a job-controlled field, not depending on any executor sandbox escape itself (only on the file write path validation).

### Likelihood Explanation
- Requires `RUNNER_GENERATE_ARTIFACTS_METADATA=true` to be enabled for the runner/job (a runner-level feature flag, not attacker controlled, but plausible in provenance/SLSA-enabled setups).
- Requires zip (or other supported) artifact format — default.
- Requires a shared builds root accessible across projects (host/shell executor with predictable/shared build paths, or any executor configuration where multiple projects' build dirs are siblings under a common root).
- The attacker only needs the ability to set `artifacts:name` in `.gitlab-ci.yml`, which any pipeline author can do — no elevated privilege required.
- Given these preconditions, the exploit is deterministic and repeatable every job run.

### Recommendation
Sanitize `artifactName` before use in `generateStatementToFile`, e.g., apply `filepath.Base()` (as already done in `artifactFilename`) or explicitly validate that the resolved path stays within `opts.artifactsWd` (reject `..` segments / verify `filepath.Rel`/prefix containment) before calling `os.WriteFile`. Ideally, reuse the same sanitized name used for the archive (`artifactFilename` output) as the base for the metadata filename instead of the raw `c.Name`.

### Proof of Concept
```go
func TestGenerateStatementToFile_PathTraversal(t *testing.T) {
    tmpWd := t.TempDir()
    g := &artifactStatementGenerator{
        StartedAtRFC3339: time.Now().Format(time.RFC3339),
        EndedAtRFC3339:   time.Now().Format(time.RFC3339),
    }

    opts := generateStatementOptions{
        artifactName: "../../victim/pwn",
        files:        map[string]os.FileInfo{},
        artifactsWd:  tmpWd,
        jobID:        1,
    }

    file, err := g.generateStatementToFile(opts)
    require.NoError(t, err)

    // Assert the resolved path stays within artifactsWd (this assertion currently FAILS,
    // proving the traversal escapes the intended directory).
    rel, err := filepath.Rel(tmpWd, file)
    require.NoError(t, err)
    require.False(t, strings.HasPrefix(rel, ".."), "metadata file escaped artifactsWd: %s", file)
}
```
Expected today: the test fails because `file` resolves to a path like `<parent-of-tmpWd>/../victim/pwn-metadata.json`, confirming the escape. After applying `filepath.Base()` sanitation (or containment validation) on `artifactName`, the test should pass.

func (c *ArtifactsUploaderCommand) artifactFilename(name string, format spec.ArtifactFormat) string {
	name = filepath.Base(name)
	if name == "" || name == "." {
		name = DefaultUploadName
	}

	switch format {
	case spec.ArtifactFormatZip, spec.ArtifactFormatZipZstd:
		return name + ".zip"

	case spec.ArtifactFormatGzip:
		return name + ".gz"

	case spec.ArtifactFormatTarZstd:
		return name + ".tar.zst"
	}
	return name
}
