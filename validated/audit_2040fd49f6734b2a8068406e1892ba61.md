### Title
Replay-guard digest is consumed before owner/authorization validation, allowing a griefing DoS analogous to nonce-burn-with-revert - (File: core/capabilities/vault/authorizer.go)

### Summary
The Vault gateway request-authorization pipeline records a request's replay-guard digest as "used" (`RequestReplayGuard.CheckAndRecord`) **before** it validates that the payload inside the request actually matches the authorized workflow owner. If validation subsequently fails, the whole request is rejected, but the digest has already been permanently marked as seen — a one-time-use resource (the "nonce" equivalent) that is now unusable by the legitimate caller. This mirrors the reported Inverter-Network issue where an EIP-2771 forwarder's nonce is consumed even when the underlying call reverts.

### Finding Description
`authorizer.AuthorizeRequest` performs the following steps in order:
1. Resolve the `AuthResult` (owner, digest, expiry) via the allowlist or JWT auth path.
2. Call `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` — this **permanently marks the digest as seen** for its expiry window.
3. Only afterward does it call `validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner())`, which checks that the secret owners embedded in the request params match the authorized workflow owner. [1](#0-0) 

The replay guard itself is a simple "seen"-map keyed by digest with no distinction between a digest that was fully processed successfully and one that failed downstream: [2](#0-1) 

Because `CheckAndRecord` runs before `validateSecretOwnersMatchAuthorized`, any request whose digest matches an on-chain allowlisted entry (`allowListBasedAuth.AuthorizeRequest` looks up the digest against `WorkflowRegistry` allowlisted requests) will consume that digest even if the accompanying params fail owner-binding validation and the request is ultimately rejected: [3](#0-2) 

This is the direct analog of the Inverter forwarder bug: the nonce/digest (a single-use authorization token) is spent regardless of whether the operation it authorizes actually succeeds, and the pipeline provides no way to "return" or invalidate the wasted consumption.

### Impact Explanation
Since `AuthResult.Digest()`/expiry is tied to an on-chain allowlisted request (published via `WorkflowRegistry`), and the replay guard is a shared, gateway-wide in-memory map, a party that can submit a JSON-RPC message to the gateway with the same digest but with params engineered to fail `validateSecretOwnersMatchAuthorized` (e.g. mismatched owner field(s), or exploiting whatever fields are/aren't covered by the request digest) can burn a legitimate, on-chain-approved one-time authorization before the genuine caller's real request is ever delivered. Since the guard entry persists until `expiresAtUnix`, this results in denial-of-service against the legitimate owner's create/update/delete/list secrets operation for the lifetime of that allowlisted digest — a permanent, un-retriable failure of an operation the owner explicitly authorized on-chain.

### Likelihood Explanation
Exploitability depends on exactly which fields are hashed by `jsonrpc.Request.Digest()` (not available in the indexed codebase) — if the digest is computed over the full raw params bytes, an attacker cannot forge a different-owner-but-same-digest request and this order-of-operations bug is unreachable in practice. If the digest only covers a subset of fields (e.g., method + id, or excludes fields validated later such as embedded owner metadata within nested structures), the attack becomes directly reachable by an unprivileged gateway client. This uncertainty should be resolved by inspecting `chainlink-common/pkg/jsonrpc2` `Request.Digest()`, which is outside this repo's indexed contents.

### Recommendation
Reorder the pipeline so that all payload/owner validation (`validateSecretOwnersMatchAuthorized`) happens strictly before `replayGuard.CheckAndRecord` is invoked, or make replay-guard recording transactional/rollback-able on downstream validation failure so a digest is only "spent" once the full request has been confirmed authorized and dispatched.

### Proof of Concept
1. Owner publishes an allowlisted request (digest `D`, owner `O`, expiry `T`) on-chain via `WorkflowRegistry`.
2. Attacker crafts a JSON-RPC request to the gateway whose `Digest()` still resolves to `D` (dependent on which fields are hashed) but whose params contain a secret `Owner` field different from `O`.
3. `allowListBasedAuth.AuthorizeRequest` finds the allowlisted entry for `D` and returns a valid `AuthResult`. [4](#0-3) 
4. `authorizer.AuthorizeRequest` calls `replayGuard.CheckAndRecord(D, T)`, which succeeds and marks `D` as seen.
5. `validateSecretOwnersMatchAuthorized` then fails because the params' owner does not match `O`, and the whole request returns an error to the caller. [5](#0-4) 
6. The legitimate owner `O` later submits the correctly-formed request using digest `D`; it is rejected with `ErrRequestAlreadySeen` because the guard already recorded `D`, permanently denying the operation until expiry `T`.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}
