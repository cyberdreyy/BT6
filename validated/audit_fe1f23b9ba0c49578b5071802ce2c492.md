### Title
Non-Creator Can Claim `DisplayCap<T>` via `claim()` Without Publisher Verification — (File: `crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

---

### Summary

`display_registry::claim()` issues a `DisplayCap<T>` — the sole authority to modify the global display metadata for every object of type `T` — to whoever presents any `LegacyDisplay<T>` object, without verifying that the caller is the original package publisher. Because the legacy `sui::display::Display<T>` struct carries `key, store` abilities and is therefore freely transferable, any address that acquires a legacy display object (by purchase, gift, or any other means) can permanently seize creator-level control over the display metadata for an entire NFT collection.

---

### Finding Description

**Root cause — wrong authorization token accepted as creator proof**

The V2 migration path provides two ways to claim a `DisplayCap<T>`:

```move
// display_registry.move line 99-109
public fun claim<T: key>(
    display: &mut Display<T>,
    legacy: LegacyDisplay<T>,   // ← any holder of this object qualifies
    ctx: &mut TxContext,
): DisplayCap<T> {
    assert!(display.cap_id.is_none(), ECapAlreadyClaimed);
    let cap = DisplayCap<T> { id: object::new(ctx) };
    display.cap_id.fill(cap.id.to_inner());
    legacy.destroy();
    cap
}
``` [1](#0-0) 

The sibling function `claim_with_publisher` correctly enforces creator identity:

```move
// display_registry.move line 112-122
public fun claim_with_publisher<T: key>(
    display: &mut Display<T>,
    publisher: &mut Publisher,
    ctx: &mut TxContext,
): DisplayCap<T> {
    assert!(display.cap_id.is_none(), ECapAlreadyClaimed);
    assert!(publisher.from_package<T>(), ENotValidPublisher); // ← publisher check
    ...
}
``` [2](#0-1) 

`claim()` performs no equivalent check. It treats possession of a `LegacyDisplay<T>` as sufficient proof of creator authority.

**Why possession of `LegacyDisplay<T>` is not creator proof**

The legacy `sui::display::Display<T>` struct is declared with `key, store`:

```move
// display.move line 48
public struct Display<phantom T: key> has key, store {
``` [3](#0-2) 

The `store` ability means the object can be transferred to any address via `transfer::public_transfer`. The original creator may have sold, gifted, or accidentally sent their `Display<T>` to another address. Any subsequent holder can then call `claim()`.

**The same flaw exists in `migrate_v1_to_v2`**

```move
// display_registry.move line 149-159
public fun migrate_v1_to_v2<T: key>(
    registry: &mut DisplayRegistry,
    legacy: LegacyDisplay<T>,   // ← no publisher check
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    let (mut display, cap) = new_display<T>(registry, ctx);
    display.fields = *legacy.fields();
    legacy.destroy();
    (display, cap)
}
``` [4](#0-3) 

This path is exploitable for any type whose V2 `Display<T>` has not yet been created in the registry (i.e., types not covered by the system snapshot migration).

---

### Impact Explanation

`DisplayCap<T>` is the sole key that authorises `set`, `unset`, and `clear` on the shared `Display<T>` object:

```move
public fun set<T>(display: &mut Display<T>, _: &DisplayCap<T>, name: String, value: String)
public fun unset<T>(display: &mut Display<T>, _: &DisplayCap<T>, name: String)
public fun clear<T>(display: &mut Display<T>, _: &DisplayCap<T>)
``` [5](#0-4) 

Because there is exactly one `Display<T>` per type (derived deterministically from the global registry), a successful `claim()` by a non-creator gives that attacker permanent, exclusive control over the display metadata — `name`, `description`, `image_url`, `link`, `creator`, etc. — for every object of type `T` across the entire network. The attacker can:

- Replace image URLs with malicious or misleading content for all holders of type-T NFTs.
- Erase or falsify creator attribution, corrupting provenance records.
- Permanently lock out the legitimate creator, since `cap_id` is filled once and the `ECapAlreadyClaimed` guard prevents any future claim.

This constitutes **harmful smart-contract behavior** (state corruption of the global display registry) reachable from a public transaction by an ordinary SUI holder.

---

### Likelihood Explanation

The attack window is open for every type whose V2 `Display<T>` was created by the system snapshot migration with `cap_id: none` and has not yet been claimed by the legitimate creator. The attacker only needs to:

1. Acquire any legacy `Display<T>` for the target type — possible because `Display<T>` has `store` and can be bought, received as a gift, or obtained from a creator who transferred it carelessly.
2. Call `display_registry::claim(display_v2, legacy_display, ctx)` in a single PTB before the legitimate creator does.

No special privilege, validator access, or governance quorum is required. The `DisplayRegistry` is a shared object accessible to any transaction.

---

### Recommendation

Add a `Publisher` verification to `claim()`, mirroring `claim_with_publisher`:

```move
public fun claim<T: key>(
    display: &mut Display<T>,
    legacy: LegacyDisplay<T>,
    publisher: &Publisher,       // ← add publisher parameter
    ctx: &mut TxContext,
): DisplayCap<T> {
    assert!(display.cap_id.is_none(), ECapAlreadyClaimed);
    assert!(publisher.from_package<T>(), ENotValidPublisher); // ← add check
    let cap = DisplayCap<T> { id: object::new(ctx) };
    display.cap_id.fill(cap.id.to_inner());
    legacy.destroy();
    cap
}
```

Apply the same fix to `migrate_v1_to_v2`. Alternatively, consider removing the `store` ability from the legacy `Display<T>` struct so it cannot be transferred away from the original creator, though this is a breaking change to the V1 API.

### Proof of Concept

```move
// Attacker acquires a legacy Display<VictimNFT> by any means (purchase, gift, etc.)
// The V2 Display<VictimNFT> exists in the registry with cap_id = none (post-migration)

// Step 1: Attacker calls claim() — no publisher required
let stolen_cap = display_registry::claim<VictimNFT>(
    &mut display_v2,       // shared Display<VictimNFT> with cap_id = none
    legacy_display,        // attacker-held LegacyDisplay<VictimNFT>
    ctx,
);

// Step 2: Attacker corrupts display metadata for ALL VictimNFT holders
display_registry::set<VictimNFT>(
    &mut display_v2,
    &stolen_cap,
    b"image_url".to_string(),
    b"https://attacker.example/phishing.png".to_string(),
);

// Step 3: Legitimate creator can never reclaim — ECapAlreadyClaimed fires forever
```

The `claim` function at line 99 of `display_registry.move` accepts the legacy display object without any publisher check, issues the cap, and fills `cap_id` permanently. [6](#0-5)
