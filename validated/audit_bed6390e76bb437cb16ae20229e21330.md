No vulnerability found for this question.

`NakamotoBlockHeader::signer_signature_hash_inner` hashes all consensus-critical fields — `version`, `chain_length`, `burn_spent`, `consensus_hash`, `parent_block_id`, `tx_merkle_root`, `state_index_root`, `timestamp`, `miner_signature`, `pox_treatment`, and (version-gated) `problematic_txs` — through SHA-512/256 [1](#0-0) . Since `tx_merkle_root` is itself hashed into the digest, two headers with different `tx_merkle_root` values producing the same `signer_signature_hash()` would require an actual SHA-512/256 collision, not a "construction bug" in the hashing code. The premise of the question — that an attacker can "engineer" two distinct valid header bodies to collide under the real hash function — is a request to break a cryptographic primitive's collision resistance, which is explicitly out of scope ("theoretical findings", cryptographic-primitive defects with no path through the signer's own logic).

`StackerDBListenerComms::insert_block` does key its status map only by `Sha512Trunc256Sum` (the `signer_signature_hash`) [2](#0-1) , and `BlockAccepted`/`BlockResponse::Rejected` messages are also matched against `blocks` by that same hash alone [3](#0-2) . This confirms the keying-by-hash-only design the question describes, but the attack requires finding a genuine hash collision to exploit it — no code defect makes two distinct headers actually produce equal `signer_signature_hash()` values, and there's an existing regression test (`signer_signature_hash_includes_problematic_txs`, `problematic_txs_serialization_is_version_gated`) confirming the hash is sensitive to all consensus-relevant fields [4](#0-3) .

    fn signer_signature_hash_inner(&self) -> Result<Sha512Trunc256Sum, CodecError> {
        let mut hasher = Sha512_256::new();
        let fd = &mut hasher;
        write_next(fd, &self.version)?;
        write_next(fd, &self.chain_length)?;

        write_next(fd, &self.consensus_hash)?;

        write_next(fd, &self.tx_merkle_root)?;
        write_next(fd, &self.state_index_root)?;
        write_next(fd, &self.timestamp)?;
        write_next(fd, &self.miner_signature)?;
        write_next(fd, &self.pox_treatment)?;
        if Self::version_includes_problematic_txs(self.version) {
            write_next(fd, &self.problematic_txs)?;
        }
        Ok(Sha512Trunc256Sum::from_hasher(hasher))
