### Title
Operator fee truncates to zero for small `gas * operator_fee_scalar` products, allowing systematic fee-skirting on Isthmus (pre-Jovian) - (File: `crates/common/l1-fees/src/params.rs`)

### Summary
The Isthmus operator fee is computed by `L1FeeParams::operator_fee_charge_inner`, which (pre-Jovian) performs `gas.saturating_mul(operator_fee_scalar) / OPERATOR_FEE_SCALAR_DECIMAL` before adding the constant term [1](#0-0) . This mirrors the Allo `_fundPool` bug class: a percentage-style fee computed via integer division that truncates to zero whenever the numerator is smaller than the divisor (`1_000_000`), letting the fee be skirted instead of merely reduced.

### Finding Description
`operator_fee_charge_inner` computes, for the pre-Jovian path:

```rust
gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
``` [1](#0-0) 

`OPERATOR_FEE_SCALAR_DECIMAL` is a fixed `1_000_000` divisor [2](#0-1) . Whenever `gas * operator_fee_scalar < 1_000_000`, Rust integer division floors the scaled component to `0`, and the only fee actually charged is `operator_fee_constant`. If the system operator's configured `operator_fee_constant` is `0` for a period (a valid configuration state, confirmed by the test asserting both fields are legitimately `0` before Isthmus activation and configured independently thereafter [3](#0-2) ), the entire operator fee for that transaction becomes `0`, exactly the "fee rounds to zero for small values" pattern flagged in the Allo report.

This computed value is not merely informational — it is charged upfront from the caller and credited to the `OPERATOR_FEE_VAULT` in the EVM2 handler's `before_execution`/`settle_transaction` hooks [4](#0-3) , so a zero-valued fee is a real, not cosmetic, loss of protocol revenue on every affected transaction. Because `gas` here is the transaction's `gas_limit` (attacker-controlled, subject only to intrinsic-gas minimums) [5](#0-4) , any signed transaction sender can choose a `gas_limit`/interact with a chain configuration whose `operator_fee_scalar` is small enough that `gas_limit * operator_fee_scalar < 1_000_000`, and thereby have the scalar-based portion of the operator fee floored to zero — bypassing the fee mechanism that is supposed to apply to every non-deposit transaction, analogous to Allo's `_amount * percentFee / 1e18` truncation letting a "small deposit" dodge the intended fee.

Notably, the Jovian upgrade path multiplies instead of dividing (`gas.saturating_mul(operator_fee_scalar).saturating_mul(OPERATOR_FEE_JOVIAN_MULTIPLIER)`) [6](#0-5) , which structurally eliminates this truncation-to-zero class going forward — but the vulnerable division-based formula remains live for any chain/period where Isthmus is active and Jovian is not yet activated.

### Impact Explanation
Systematic zero-fee execution reduces the protocol's operator-fee revenue collection to nothing for a subset of transactions, exactly mirroring the accepted Sherlock Medium-severity classification of the Allo issue ("protocol doesn't collect fees ... this is only acceptable for a privileged role, not for any sender"). Any unprivileged transaction sender — not a privileged pool-manager-equivalent role — can reach and exploit this, satisfying the "reachable from a single signed transaction" bar.

### Likelihood Explanation
Likelihood is contingent on chain configuration: the truncation only manifests when `operator_fee_scalar` is small relative to `gas_limit` and `operator_fee_constant` is zero or small. This is a legitimate, reachable configuration state during the Isthmus-active/pre-Jovian window (explicitly tested as a valid state in the harness), and gas_limit is entirely attacker-chosen within intrinsic-gas bounds, so any attacker aware of the active `operator_fee_scalar`/`operator_fee_constant` values can trivially select a `gas_limit` that zeroes the scalar term.

### Recommendation
Round the scalar-based term up rather than down (ceiling division), or enforce a minimum non-zero operator fee floor when `operator_fee_scalar` and/or `operator_fee_constant` are configured to prevent full truncation, consistent with how the Jovian multiplier-based formula avoids the issue structurally.

### Proof of Concept
1. Chain is on Isthmus (not yet Jovian) with `operator_fee_scalar` set such that, for a typical `gas_limit` (e.g., `21_000`), `gas_limit * operator_fee_scalar < 1_000_000` (e.g., `operator_fee_scalar <= 47`), and `operator_fee_constant == 0`.
2. Any unprivileged sender submits a normal (non-deposit) transaction with that `gas_limit`.
3. `operator_fee_charge_inner` computes `21_000 * scalar / 1_000_000 == 0`, plus `operator_fee_constant == 0`, yielding total operator fee `0` [1](#0-0) .
4. `before_execution`/`settle_transaction` charge and credit this `0` operator fee to `OPERATOR_FEE_VAULT` [4](#0-3) , so the protocol collects nothing from this transaction despite Isthmus's operator fee being active — repeatable by any sender for every transaction meeting the threshold.

    pub fn operator_fee_charge_inner(&self, gas: U256, upgrade: BaseUpgrade) -> U256 {
        let operator_fee_scalar = self.operator_fee_scalar.unwrap_or_default();
        let operator_fee_constant = self.operator_fee_constant.unwrap_or_default();

        let product = if Self::is_enabled(upgrade, BaseUpgrade::Jovian) {
            gas.saturating_mul(operator_fee_scalar)
                .saturating_mul(U256::from(OPERATOR_FEE_JOVIAN_MULTIPLIER))
        } else {
            gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
        };
        product.saturating_add(operator_fee_constant)
    }

impl TxHandlerHooks<BaseEvmTypes> for BaseTxHandlerHooks {
    fn before_execution(
        host: &mut Evm<'_, BaseEvmTypes>,
        envelope: &BaseTxEnvelope,
        caller: Address,
        upfront_fee: U256,
    ) -> HandlerResult<()> {
        // Charge the upfront gas cost, the L1 data fee, and the operator fee (on the gas limit)
        // from the caller. Both fees are stashed for settlement so it charges/refunds against the
        // exact amounts collected here, without recomputing them.
        let l1_fee = Self::l1_fee(host, envelope);
        let operator_fee = Self::operator_fee(host, envelope, envelope.gas_limit());
        let ext = host.ext_mut();
        ext.l1_fee = l1_fee;
        ext.operator_fee = operator_fee;
        // `validate_sender` only checks the gas cost and value; the L1 and operator fees are
        // charged on top here via `charge_upfront`'s wrapping subtraction, so reject an
        // underfunded caller up front rather than let its balance wrap to a spurious value.
        Self::ensure_can_pay_fees(host, envelope, caller, l1_fee, operator_fee)?;
        charge_upfront(
            host,
            caller,
            upfront_fee.saturating_add(l1_fee).saturating_add(operator_fee),
        )
    }

    fn settle_transaction(
        host: &mut Evm<'_, BaseEvmTypes>,
        envelope: &BaseTxEnvelope,
        gas: GasSettlement<BaseEvmTypes>,
    ) -> HandlerResult<TxResult<BaseEvmTypes>> {
        let caller = gas.caller;
        let basefee = host.block_env().basefee;
        let l1_fee = host.ext().l1_fee;
        // The operator fee charged upfront (on the gas limit), stashed in before_execution.
        let operator_fee_charged = host.ext().operator_fee;

        // Default settlement refunds the caller's unused gas and pays the coinbase the priority
        // fee. The base fee is credited to its vault below (the OP-stack does not burn it).
        let mut result = default_settle_gas(host, gas)?;
        let gas_used = result.tx_gas_used();

        // Refund the operator fee down from the amount charged (on the gas limit) to the gas
        // actually used; the net is credited to the operator-fee vault below.
        let operator_fee_used = Self::operator_fee(host, envelope, gas_used);
        let operator_fee_refund = operator_fee_charged.saturating_sub(operator_fee_used);
        Self::credit(host, caller, operator_fee_refund)?;

        // Distribute the collected OP-stack fees to their vaults.
        Self::credit(host, Predeploys::L1_FEE_VAULT, l1_fee)?;
        Self::credit(
            host,
            Predeploys::BASE_FEE_VAULT,
            basefee.saturating_mul(U256::from(gas_used)),
        )?;
        Self::credit(host, Predeploys::OPERATOR_FEE_VAULT, operator_fee_used)?;
```
