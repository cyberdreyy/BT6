### Title
Name squatting a planned multisig id lets an attacker permanently seize `<name>.<factory>` with self-chosen members - ([File: multisig-factory/src/lib.rs])

### Summary
`MultisigFactory::create` is a fully public, unrestricted method that derives the deployed contract's account id purely from the caller-supplied `name` (`format!("{}.{}", name, env::current_account_id())`), with no reservation, ownership check, or minimum-deposit enforcement. Whoever calls `create(name, members, num_confirmations)` first for a given `name` permanently owns that sub-account with the members and confirmation threshold they chose, since `create_account()` fails for any subsequent caller once the name exists.

### Finding Description
The binding an observer/relying party assumes is: `deployed_members(<name>.<factory>) == intended_owner_chosen_members(name)`. Nothing in the contract enforces this. `create` at `multisig-factory/src/lib.rs:29-49` takes `name`, `members`, and `num_confirmations` directly from the (unprivileged) predecessor and issues: [1](#0-0) 

There is no `assert_owner`, no allow-list, no minimum-deposit assertion (unlike `lockup-factory`, which enforces `MIN_ATTACHED_BALANCE` at `lockup-factory/src/lib.rs:117`), and no per-name reservation mechanism. Because NEAR account creation is first-come-first-served, an attacker can watch for (or predict) a `name` that an organization plans to use, call `create` first with attacker-controlled `members`/`num_confirmations`, and attach just enough NEAR to cover contract-code storage staking (the minimum the promise chain requires to succeed, with no floor enforced by the contract itself). The intended owner's later `create` call for the same `name` will fail outright (`create_account` on an existing account id fails), permanently ceding the trusted-looking address `<name>.<factory>` to the attacker's multisig, with attacker-chosen signers and threshold.

None of the existing guards apply here: there is no `assert_self()`/promise-result check gating this initial call (the function is a plain public entrypoint, not a callback), no `is_promise_success()` gate before something sensitive happens, and no owner/foundation check anywhere in `MultisigFactory`. This differs from `lockup-factory`, which at least uses a deterministic name derived from the beneficiary account id's hash plus a minimum deposit, and includes `on_lockup_create` rollback logic; `multisig-factory` has none of these mitigations.

### Impact Explanation
Any party (a DAO, protocol, or team) that intends to later deploy a multisig at a predictable `<name>.<factory>` id and directs users/counterparties to trust or send funds to that address before actually deploying it is exposed: an attacker who deploys first controls all signer keys/accounts and the confirmation threshold. Any NEAR subsequently sent to that address, or any authority ceded to "the multisig at that name" by third parties, is fully controlled by the attacker — this matches "an account whitelisted or a lockup deployed with parameters its rightful creator never chose" / a trusted contract instantiated with attacker-chosen parameters. It is repeatable across every unclaimed `name` value at this factory and costs the attacker only the storage-staking deposit for one WASM deployment per squatted name.

### Likelihood Explanation
The precondition is simply that the attacker learns or guesses a `name` string before the legitimate party submits its own `create` transaction — feasible via public announcements, documentation, front-end code, or brute-forcing common/expected names, and it requires no special privileges, only the ability to send an ordinary NEAR transaction with a modest deposit. The cost is bounded by the storage cost of deploying `multisig2.wasm` under the chosen sub-account name. This is directly demonstrable in a unit test/`near-workspaces` simulation: call `create` from an attacker account with attacker-chosen `members`/`num_confirmations`, then attempt the intended owner's `create` call for the same `name` and observe it fail, while the deployed multisig's `members`/`num_confirmations` equal the attacker's values, not the intended owner's.

### Recommendation
Require some form of pre-registration/reservation or authorization for `name` before allowing `create` to succeed for it (e.g., a foundation/owner-gated allow-list similar to `lockup-factory`'s `foundation_account_id`, or deriving the sub-account id deterministically from an identity the true owner controls, such as a signature or a full-access key challenge), and/or enforce a documented minimum deposit and require the caller to prove control over the intended name/identity before deployment.

use near_sdk::borsh::{self, BorshDeserialize, BorshSerialize};
use near_sdk::json_types::Base58PublicKey;
use near_sdk::serde::{Deserialize, Serialize};
use near_sdk::serde_json::json;
use near_sdk::{env, near_bindgen, AccountId, Promise};

#[global_allocator]
static ALLOC: near_sdk::wee_alloc::WeeAlloc<'_> = near_sdk::wee_alloc::WeeAlloc::INIT;

const CODE: &[u8] = include_bytes!("../../multisig2/res/multisig2.wasm");

/// This gas spent on the call & account creation, the rest goes to the `new` call.
const CREATE_CALL_GAS: u64 = 50_000_000_000_000;

#[derive(Serialize, Deserialize)]
#[serde(crate = "near_sdk::serde", untagged)]
pub enum MultisigMember {
    AccessKey { public_key: Base58PublicKey },
    Account { account_id: AccountId },
}

#[near_bindgen]
#[derive(BorshSerialize, BorshDeserialize, Default)]
pub struct MultisigFactory {}

#[near_bindgen]
impl MultisigFactory {
    #[payable]
    pub fn create(
        &mut self,
        name: AccountId,
        members: Vec<MultisigMember>,
        num_confirmations: u64,
    ) -> Promise {
        let account_id = format!("{}.{}", name, env::current_account_id());
        Promise::new(account_id)
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                json!({ "members": members, "num_confirmations": num_confirmations })
                    .to_string()
                    .as_bytes()
                    .to_vec(),
                0,
                env::prepaid_gas() - CREATE_CALL_GAS,
            )
    }
