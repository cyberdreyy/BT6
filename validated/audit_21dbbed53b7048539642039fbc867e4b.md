### Title
Time-of-check/time-of-use race in request ID reuse allows a stale node response to be attributed to an unrelated, newly created `activeRequest` - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`h.activeRequests` is keyed purely by the attacker/client-supplied JSON-RPC `req.ID`, and there is a real (if narrow) window between a completed request's entry being deleted and a reused ID's new entry being inserted versus a still-in-flight node response for the old request arriving. If a late node response for a just-completed request lands after the same ID has been reused for a brand-new, logically unrelated request, `getActiveRequest` will return the new `activeRequest`, and the stale response gets silently merged into it via `addResponseForNode`.

### Finding Description
`h.activeRequests` is a single global map keyed only by `req.ID` [1](#0-0) , with no per-caller/session namespacing. `req.ID` originates from the client-controlled JSON-RPC request decoded in `gateway.ProcessRequest` and passed straight through `HandleJSONRPCUserMessage` [2](#0-1) [3](#0-2) .

Lifecycle:
- `newActiveRequest` takes `h.mu.Lock()`, checks the map for `req.ID`, and only inserts if absent [4](#0-3) .
- Completion happens in `sendResponseAndClearRequest`, which CAS-claims the request, sends the response, then separately (under a second `h.mu.Lock()`) deletes the map entry [5](#0-4) .
- `HandleNodeMessage` looks up the active request purely by `resp.ID` via `getActiveRequest`, which takes only `h.mu.RLock()` [6](#0-5) , and on a hit calls `ar.addResponseForNode(nodeAddr, resp)` with no verification that the response actually corresponds to the request currently stored under that ID (no correlation beyond the map key) [7](#0-6) .

Because deletion of the old entry and insertion of the new entry are each individually protected by `h.mu` but are two separate lock acquisitions with no atomic "delete-then-block-reinsert" barrier, the following interleaving is possible:
1. Request A (ID `X`) completes: `sendResponseAndClearRequest` CASes `completed=true`, sends the response, and deletes `activeRequests["X"]`.
2. A slow/late node response for A (sent before quorum/expiry, but delivered afterward — the code explicitly anticipates such late arrivals, since `HandleNodeMessage` already defends against `ar == nil`) is still in flight.
3. A brand-new, logically unrelated `HandleJSONRPCUserMessage` call reuses ID `X` (e.g., another concurrent caller using a predictable/sequential ID scheme, or the same caller retrying quickly) and successfully inserts a new `activeRequest` B into `activeRequests["X"]` because the map slot is now empty.
4. The late node response for A now arrives at `HandleNodeMessage`, `getActiveRequest("X")` returns B instead of nil, and `addResponseForNode` attaches A's stale node response into B's `responses` map, which is later bundled and forwarded via `h.bundler.Bundle(ar.req, copiedResponses, l)` using B's own `req` but a mix of B's and A's node responses.

This mixes response data across two logically distinct requests under the same reused ID, silently, with only the downstream enclave's signature/quorum verification (not verified in this file) as a potential backstop.

### Impact Explanation
This is a cross-user/cross-request response confusion bug in the gateway-to-DON relay path: a late node response meant for one now-completed relay request can be blended into the bundle of a different, currently active request that happens to reuse the same JSON-RPC ID. Depending on what the enclave actually verifies on the receiving end (out of scope for this file), this could pollute quorum accounting for an unrelated request or, at minimum, cause a legitimate active request's bundle to contain a foreign, stale signed response, violating the intended per-request isolation the map is meant to enforce.

### Likelihood Explanation
The window requires: (1) a node response delayed enough to arrive after its own request has completed and been deleted, which is a normal and anticipated occurrence in this code (the nil-check in `HandleNodeMessage` exists specifically for this case), and (2) the same `req.ID` being reused by a different logical request within that narrow window. Since `req.ID` is entirely attacker/client-supplied with no per-caller namespacing, and many JSON-RPC clients use predictable/incrementing IDs, ID collisions across independent unauthenticated callers hitting the same DON/service are plausible, especially under load or via deliberate ID reuse by an attacker probing this behavior. This makes the race feasible and repeatable, though it does depend on network/timing conditions to actually land the stale response inside the reinsertion window.

### Recommendation
Do not rely on `req.ID` reuse safety being implicit; make request identity unique for the lifetime concerns involved:
- Generate an internal unique correlation token (e.g., UUID) per `activeRequest` at creation time, independent of the client-supplied `req.ID`, and key `h.activeRequests` by that internal token; forward the internal token to nodes instead of (or in addition to) the raw client ID so `HandleNodeMessage` correlates responses against the exact request instance, not merely a potentially-reused string key.
- Alternatively, retain a short "tombstone" for recently completed IDs (bounded by `nodeSendTimeout`/`requestTimeout`) that rejects immediate reuse and causes late responses matching a tombstoned ID to be dropped rather than risk correlating to a wrong request.

### Proof of Concept
Go handler-level integration test plan:
1. Configure a `handler` with a controllable `clockwork.FakeClock`, a small `donConfig` (e.g., F=1, 3 members), and a mock `don.SendToNode`.
2. Call `HandleJSONRPCUserMessage` for request A with `ID="dup-id"`; obtain the created `activeRequest` A via `h.getActiveRequest("dup-id")`.
3. Drive A to completion (e.g., call `HandleNodeMessage` enough times to reach quorum, or directly invoke `h.sendResponseAndClearRequest` on A) and assert `h.getActiveRequest("dup-id")` becomes `nil`.
4. Immediately call `HandleJSONRPCUserMessage` for a new, unrelated request B reusing `ID="dup-id"` with different params/callback, and confirm `h.getActiveRequest("dup-id")` now returns B.
5. Concurrently (or immediately after step 4, before B completes), call `HandleNodeMessage` with a `resp.ID="dup-id"` from a node address that never sent a response to B, simulating a stale response originally destined for A.
6. Assert that this stale response is present in B's `copiedResponses()`/final bundled response — demonstrating that A's data was merged into B's request. Assert violation: the test should show at least one entry in B's `responses` map whose value/content matches the response fabricated for "A", not anything derived from B's actual fan-out to nodes.
7. Repeat with tighter timing (goroutines + explicit synchronization channels/`sync.WaitGroup`) to interleave deletion (step 3), reinsertion (step 4), and the stale `HandleNodeMessage` call (step 5) to make the race deterministic in the test via injected hooks/synchronization rather than relying on real timing.

func (ar *activeRequest) addResponseForNode(nodeAddr string, resp *jsonrpc.Response[json.RawMessage]) bool {
	ar.mu.Lock()
	defer ar.mu.Unlock()
	_, exists := ar.responses[nodeAddr]
	if exists {
		return false
	}

	ar.responses[nodeAddr] = resp
	return true
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) getActiveRequest(requestID string) *activeRequest {
	h.mu.RLock()
	defer h.mu.RUnlock()
	return h.activeRequests[requestID]
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
