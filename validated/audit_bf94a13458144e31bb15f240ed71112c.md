### Title
Session authorization uses non-constant-time token comparison enabling timing side-channel - ([File: session/session.go])

### Summary
`Session.withAuthorization` compares the session token using Go's built-in `!=` string comparison instead of a constant-time comparison, which short-circuits on the first mismatched byte. Because the session HTTP/WebSocket endpoint (`/session/<uuid>/proxy/` and `/session/<uuid>/exec`) is reachable by any client holding the session URL, a byte-by-byte timing side-channel could in principle be used to help brute-force the `s.Token` value.

### Finding Description
`withAuthorization` performs the check `if s.Token != r.Header.Get("Authorization")` before dispatching to `proxyHandler` or `execHandler`. [1](#0-0) 

The `Token` is generated once via `generateToken()` (32-byte random UUID) alongside the session `Endpoint`, and both are surfaced to GitLab (via `common.SessionInfo`/`RequestJob` response) so that GitLab's web terminal/proxy features can reach the runner's session server. [2](#0-1) 

Go's native `!=` on strings compares byte-by-byte and returns as soon as a mismatch is found, meaning the time taken by the comparison correlates weakly with the number of leading bytes that match. An attacker who can reach the session endpoint (e.g., another party who intercepts/guesses the session URL, or in multi-tenant setups where the session port is exposed) could attempt to statistically infer the token by measuring response latency across many requests per byte, rather than relying purely on the token's full 32-byte entropy in one guess.

### Impact Explanation
If successful, this side-channel would let an unprivileged attacker who already has network access to the session endpoint reduce the effective entropy of the session token, eventually forging a valid `Authorization` header and hijacking another job's interactive terminal or service proxy session — a cross-session impersonation matching the "auth state must not let one job impersonate another" invariant.

### Likelihood Explanation
This is a low-likelihood/high-difficulty vector: the token is a 32-byte random UUID, session lifetime is bounded to a single job's runtime (`execHandler` and the session server exist only while the job/terminal session is active), and real-world network jitter typically dwarfs the microsecond-level timing signal from a short-circuited string comparison, especially over TLS/WebSocket connections. No concrete PoC in this environment demonstrates a statistically reliable extraction within the token's practical lifetime, so this remains a theoretically valid but practically very hard to exploit weakness rather than a confirmed, readily reproducible bug.

### Recommendation
Replace the direct string comparison with a constant-time comparison, e.g. `subtle.ConstantTimeCompare([]byte(s.Token), []byte(r.Header.Get("Authorization"))) == 1`, to eliminate the timing side-channel regardless of practical exploitability.

### Proof of Concept
Not able to produce a reliable, reproducible PoC given the token's entropy and session lifetime constraints; this would require a statistical timing-attack harness sending many requests per byte position against a live session endpoint within the job's execution window, which is not practically demonstrable as a deterministic unit test. A defensive unit test can only assert that the comparison function is constant-time (e.g., using `crypto/subtle`), not that the current implementation is exploitable in practice.

func NewSession(logger *logrus.Entry) (*Session, error) {
	endpoint, token, err := generateEndpoint()
	if err != nil {
		return nil, err
	}

	if logger == nil {
		logger = logrus.NewEntry(logrus.StandardLogger())
	}

	logger = logger.WithField("uri", endpoint)

	sess := &Session{
		Endpoint:      endpoint,
		Token:         token,
		DisconnectCh:  make(chan error),
		TimeoutCh:     make(chan error),
		terminalSetCh: make(chan struct{}),

		log: logger,
	}

	sess.setMux()

	return sess, nil
}

func generateEndpoint() (string, string, error) {
	sessionUUID, err := helpers.GenerateRandomUUID(32)
	if err != nil {
		return "", "", err
	}

	token, err := generateToken()
	if err != nil {
		return "", "", err
	}

	return "/session/" + sessionUUID, token, nil
}

func generateToken() (string, error) {
	token, err := helpers.GenerateRandomUUID(32)
	if err != nil {
		return "", err
	}

	return token, nil
}

func (s *Session) withAuthorization(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		logger := s.log.WithField("uri", r.RequestURI)
		logger.Debug("Endpoint session request")

		if s.Token != r.Header.Get("Authorization") {
			logger.Error("Authorization header is not valid")
			http.Error(w, http.StatusText(http.StatusUnauthorized), http.StatusUnauthorized)
			return
		}

		next.ServeHTTP(w, r)
	})
}
