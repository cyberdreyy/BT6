### Title
`IdleCreditVault.initialize` skips the `maxApr` bound enforced by `setApr`, letting a misconfigured APR inflate epoch interest beyond what the borrower repays - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`IdleCreditVault.initialize` sets `maxApr = DEFAULT_MAX_APR` (20e18 scaled) and then directly assigns `lastApr = _apr` without validating `_apr <= maxApr`. Every subsequent APR update goes through `setApr`/`setAprs`/`setAprsWithBuffer`, which enforce `if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed()` — but the initializer bypasses that guard entirely. This mirrors the external bug class: the "happy path" setters carry an invariant (`_initialMortgageRate < _liquidationMortgageRate`, here `_apr <= maxApr`) that the one-time initialization path fails to enforce.

### Finding Description
In `contracts/strategies/idle/IdleCreditVault.sol`:

```solidity
maxApr = DEFAULT_MAX_APR;          // L143
// on the first setup we set the lastApr equal to the unscaledApr
lastApr = _apr;                    // L145 — no _apr <= maxApr check
unscaledApr = _apr;
```

while the guarded path is:

```solidity
uint256 _maxApr = maxApr;
if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();  // L232-233
lastApr = _apr;
```

`lastApr` (exposed via `getApr()`) drives `expectedEpochInterest`/`_calcInterest` in the CDO (`IdleCDOEpochVariant`/`IdleCDOEpochVariantPrefunded`), which determines how much interest the borrower must fund at `stopEpoch`/`stopEpochWithDuration`. An initializer APR of, say, 100e18 (or a value where `apr * (duration+buffer)/duration` would overflow a reasonable bound) causes the CDO to book interest far above anything the borrower will repay. At `stopEpoch`, the borrower either cannot transfer the inflated `expectedEpochInterest + pendingWithdraws` amount — forcing `stopEpochWithDuration(_lossAmount)` accounting that socializes the shortfall — or the epoch simply cannot close and funds are frozen until a loss is declared. In a default, the loss hits BB tranche holders first, exactly the "users absorb the admin's misconfiguration" impact of the original report.

### Impact Explanation
An erroneously high initial APR inflates the interest liability booked against the pool. When the borrower repays only the real (lower) negotiated interest, the CDO records a loss: pending withdraw receipts get haircut via `lossRecoveryPriceByEpoch`, and the residual `activeLoss` is absorbed BB-first by tranche holders through `_updateAccounting`. Unprivileged lenders lose a quantifiable fraction of principal (the spread between booked and funded interest) purely due to a missing `require` in the initializer — the same severity and mechanism class as the JUSD finding.

### Likelihood Explanation
Requires an owner/manager misconfiguration at deployment (the APR is supplied via `CreditVaultParams.apr` through `IdleCreditVaultFactory`), matching the original report's admin-mistake precondition. No unprivileged attacker action is needed to trigger it; any lender depositing before `stopEpoch` is exposed. The invariant already exists in code (`setApr` enforces it), which both proves the check was intended and confirms the initializer is a genuine gap rather than a design choice.

### Recommendation
Enforce the cap in the initializer by routing through the existing check:

```solidity
// in IdleCreditVault.initialize, replace direct assignment with:
maxApr = DEFAULT_MAX_APR;
require(_apr <= maxApr, "APR_TOO_HIGH"); // or call setApr(_apr)
lastApr = _apr;
unscaledApr = _apr;
```

Additionally validate `unscaledApr` consistently, since `setAprs`/`setAprsWithBuffer` only cap the scaled value while `unscaledApr == 0` gates the APR0 accounting path.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../contracts/strategies/idle/IdleCreditVault.sol";

contract InitAprBypassTest is Test {
    IdleCreditVault vault;
    MockERC20 underlying;

    function setUp() public {
        underlying = new MockERC20("USDC", "USDC", 6);
        vault = new IdleCreditVault();
    }

    function testInitializeAcceptsAprAboveMax() public {
        uint256 badApr = 100e18; // 5x DEFAULT_MAX_APR (20e18)

        // Direct setter enforces the cap
        vault.initialize(address(underlying), address(this), address(0x1), address(0x2), "B", 1e18);
        vm.expectRevert(IdleCreditVault.NotAllowed.selector);
        vault.setApr(badApr);

        // But a fresh vault accepts the same APR at init with no revert
        IdleCreditVault vault2 = new IdleCreditVault();
        vault2.initialize(address(underlying), address(this), address(0x1), address(0x2), "B", badApr);
        assertEq(vault2.getApr(), badApr); // lastApr > maxApr: invariant violated
    }
}
```

Demonstrates that `setApr(badApr)` reverts while `initialize(..., badApr)` succeeds, leaving the vault booking epoch interest at an uncapped rate that the borrower's repayment at `stopEpoch` cannot cover, producing a realized loss socialized across BB tranche holders and pending withdraw receipts.
