### Title
Zip legacy `Extract` has no per-path collision/traversal guard at all, so case-fold or platform-alias name collisions are unenforceable - ([File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go])

### Summary
`ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33`) discards the extraction root (`e.dir`) entirely and delegates directly to `archives.ExtractZipArchive` [1](#0-0) , which writes every `zip.File.Name` verbatim to the process's current working directory with no path canonicalization, no `..`/absolute-path rejection, and no case-fold/alias-collision detection [2](#0-1) . Because there is no name-canonicalization or collision check at all, there is nothing case-fold aliasing could "bypass" — the more fundamental issue is that any two paths (whether case-variant or otherwise) can independently target the same or a different filesystem entry with zero validation, and paths can even escape the intended directory outright.

### Finding Description
`extractor.Extract` in `zip_legacy_extractor.go` only builds a `zip.Reader` and calls `archives.ExtractZipArchive(zr)`; the `dir` field captured in `NewExtractor` is never passed to or used by `ExtractZipArchive` [3](#0-2) . `ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)`, which uses `file.Name` directly as a filesystem path (via `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Mkdir(file.Name, ...)`, `os.Symlink(...)`) [4](#0-3) . The only check performed is `errorIfGitDirectory`, which rejects paths whose first component is literally `.git` — a purely string-based, case-sensitive, non-canonicalizing check [5](#0-4) . There is no chroot/prefix validation like the one present in the tar/zstd extractor (`strings.HasPrefix(path, e.dir+...)`) [6](#0-5) , and no deduplication or canonical-name map that a case-fold/alias attack would need to defeat.

Consequently the "case-fold or alias collision" scenario posed by the question does not apply as a distinct bug here: there is no validation step whose result could be spoofed by a case-variant or platform-alias name, because validation is absent for both the safe and unsafe representations. Two zip entries differing only by case (e.g. `Config` and `config`) are simply processed sequentially by `extractZipFile`, each one removing (`os.Remove`) and recreating the target on disk — on case-insensitive filesystems (Windows, default macOS) they resolve to one path and the second entry silently overwrites/replaces the first; on case-sensitive filesystems (Linux) they are simply two independent files. This is a consequence of the total absence of the chroot/traversal guard, not of a case-fold-specific logic flaw.

### Impact Explanation
Since `dir` is unused, on any platform a crafted archive entry containing `../` segments or an absolute path can write outside the intended extraction directory — this is the actual concrete, reachable issue (classic zip-slip), broader than the case-fold scenario asked about. On case-insensitive filesystems, case-variant names in the archive collide and let a later entry silently overwrite an earlier extracted file within the same extraction, but this does not by itself defeat a "validation vs write" split because no such split/validation exists for the legacy zip extractor.

### Likelihood Explanation
`ziplegacy.NewExtractor`/`Extract` is reachable from `commands/helpers/artifacts_downloader.go:131-140` and `commands/helpers/cache_extractor.go:655-663`, both of which are invoked by the `artifacts-downloader`/`cache-extractor` internal Runner commands run per job on artifact/cache download and extraction, driven by attacker-controlled archive bytes (job artifacts/cache content) [7](#0-6) [8](#0-7) . However, whether the `ziplegacy` extractor (vs. the `fastzip` extractor, which is the primary implementation for `archive.Zip`) is actually the code path exercised for real artifact/cache downloads was not fully confirmed within the available index — `archive.Register` calls for `archive.Zip`/`archive.ZipZstd` in `zip_legacy_archiver.go` register `ziplegacy.NewExtractor` [9](#0-8) , but I could not verify in this session whether a later registration (e.g., from the `fastzip` package) overrides it for the default zip format at runtime.

### Recommendation
Add the same chroot/prefix validation used in `tarzstd_extractor.go` to `ExtractZipArchive`/`extractZipFile`: join `file.Name` against the extraction root, `filepath.Clean`/`filepath.Abs` the result, and reject any path that does not stay within the root (covering `..`, absolute paths, and symlink targets). Additionally, canonicalize/normalize names (e.g., via `filepath.ToSlash` and a case-insensitive dedup map when extracting on case-insensitive filesystems) and reject archives containing colliding names before any file is written, rather than allowing sequential overwrite.

### Proof of Concept
Go test plan (`commands/helpers/archive/ziplegacy/zip_legacy_extractor_test.go`):
1. Build an in-memory zip with two entries `"Secret.txt"` (benign content) and `"secret.txt"` (attacker content), plus a third entry `"../outside.txt"`.
2. Call `NewExtractor(zip.Zip, reader, size, tmpDir)` then `Extract(ctx)`.
3. Assert: (a) `outside.txt` must NOT be written outside `tmpDir` — currently it is written outside, since `dir` is unused; (b) after extraction, exactly one deterministic winner file exists on case-insensitive filesystems, and the loser entry is rejected/reported rather than silently overwritten.
Both assertions currently fail against the existing implementation, confirming the missing validation.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
