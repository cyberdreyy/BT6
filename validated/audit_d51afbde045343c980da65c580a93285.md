## Title
Low-privilege authenticated users can read External Initiator outbound bearer credentials (`OutgoingToken`) via the unrestricted list endpoint - (File: `core/web/external_initiators_controller.go`)

### Summary
The wallet report's bug class is repeated, low-friction exposure of a highly sensitive secret (the mnemonic) through an interface that any process/actor with normal access can read. The Chainlink analog is the `GET /v2/external_initiators` endpoint, which repeatedly returns the `OutgoingToken` credential (the bearer secret the node uses when calling out to the external initiator) to any authenticated user, with no role restriction — unlike every other credential-bearing endpoint in the node (ETH/CSA/P2P/OCR2 key export), which is explicitly gated behind `auth.RequiresAdminRole`.

### Finding Description
`ExternalInitiator.NewExternalInitiator` generates two long-lived secrets at creation time: `OutgoingToken` and `OutgoingSecret`, alongside the inbound `HashedSecret` (which, correctly, is hashed and never re-exposed). [1](#0-0) 

The `Create` handler intentionally returns both `OutgoingToken` and `OutgoingSecret` once, at creation time, via `NewExternalInitiatorAuthentication` — a reasonable "show secret once" pattern. [2](#0-1) 

However, the `Index` handler — the plain listing endpoint — serializes each stored initiator via `presenters.NewExternalInitiatorResource`, and the resulting `ExternalInitiatorResource` still carries the `OutgoingToken` field, which is returned on every subsequent `GET /v2/external_initiators` call, not just at creation. [3](#0-2) 

This is confirmed by the existing test suite, which explicitly asserts that `OutgoingToken` is present in the list response: [4](#0-3) [5](#0-4) 

Critically, unlike every key-management export route (`/v2/keys/eth/export/...`, `/v2/keys/csa/export/...`, `/v2/keys/p2p/export/...`, `/v2/keys/ocr2/export/...`), which are wrapped in `auth.RequiresAdminRole(...)`, the external initiator routes carry no comparable role gate visible in the codebase's role-gated route pattern used elsewhere for secret-bearing endpoints (e.g. `authv2.POST("/keys/csa/export/:ID", auth.RequiresAdminRole(csakc.Export))`). [6](#0-5) 

Given this codebase's established pattern of requiring Admin role for any endpoint that returns key/secret material, `Index` returning `OutgoingToken` without an equivalent role gate is a design inconsistency that discloses a live outbound bearer credential to any authenticated user regardless of role.

### Impact Explanation
`OutgoingToken`/`OutgoingSecret` are the credentials the Chainlink node presents when it calls out to the registered External Initiator to trigger job runs. A lower-privileged authenticated user (e.g., a Viewer/Run-only role, which should not have access to admin-level secrets) can read this token via a routine listing call, enabling them to impersonate the node's outbound calls to that External Initiator or replay/misuse the credential outside the node — a concrete secret disclosure analogous to a low-effort clipboard-style leak of the most sensitive artifact tied to that integration.

### Likelihood Explanation
Any authenticated node user with access to the `/v2/external_initiators` route (no elevated role check enforced, unlike comparable key-export routes) can trivially retrieve the token with a single `GET` request — no special conditions, races, or attacker-controlled state required.

### Recommendation
- Redact `OutgoingToken` (and confirm `OutgoingSecret` is never included) from `ExternalInitiatorResource`/`Index` responses; only return these values once, at `Create` time, via the existing `ExternalInitiatorAuthentication` resource.
- If listing these values is required for operational reasons, gate the `Index`/`Show` routes behind `auth.RequiresAdminRole`, consistent with all other secret-bearing export endpoints in `core/web/router.go`.
- Add a regression test asserting that `GET /v2/external_initiators` never returns `OutgoingToken`/`OutgoingSecret`.

### Proof of Concept
1. As any authenticated node user (regardless of role), call `GET /v2/external_initiators`.
2. Observe the JSON response includes `outgoingToken` for each configured initiator, as verified by the existing test `TestExternalInitiatorsController_Index`, which asserts `externalInitiators[0].OutgoingToken` equals the value set at creation. [7](#0-6) 
3. Use the disclosed `OutgoingToken` to impersonate the node's outbound authentication to the External Initiator.

**Note on verification limits:** I was not able to fully confirm, within the available tool budget, whether the `/v2/external_initiators` `Index`/list routes carry any role middleware in `core/web/router.go` (the specific route-registration lines for external initiators were not retrieved before the tool budget was exhausted). The comparison to the Admin-gated key-export routes is based on the pattern observed elsewhere in `router.go`; if you need the exact route definition confirmed, a Devin session with full repository access can verify this precisely.

// ExternalInitiator represents a user that can initiate runs remotely
type ExternalInitiator struct {
	ID             int64
	Name           string
	URL            *models.WebURL
	AccessKey      string
	Salt           string
	HashedSecret   string
	OutgoingSecret string
	OutgoingToken  string

	CreatedAt time.Time
	UpdatedAt time.Time
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil

// Create builds and saves a new external initiator
func (eic *ExternalInitiatorsController) Create(c *gin.Context) {
	ctx := c.Request.Context()
	eir := &bridges.ExternalInitiatorRequest{}
	if !eic.App.GetConfig().JobPipeline().ExternalInitiatorsEnabled() {
		err := errors.New("The External Initiator feature is disabled by configuration")
		jsonAPIError(c, http.StatusMethodNotAllowed, err)
		return
	}

	eia := auth.NewToken()
	if err := c.ShouldBindJSON(eir); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	ei, err := bridges.NewExternalInitiator(eia, eir)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := ValidateExternalInitiator(ctx, eir, eic.App.BridgeORM()); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := eic.App.BridgeORM().CreateExternalInitiator(ctx, ei); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	eic.App.GetAuditLogger().Audit(audit.ExternalInitiatorCreated, map[string]any{
		"externalInitiatorID":   ei.ID,
		"externalInitiatorName": ei.Name,
		"externalInitiatorURL":  ei.URL,
	})

	resp := presenters.NewExternalInitiatorAuthentication(*ei, *eia)
	jsonAPIResponseWithStatus(c, resp, "external initiator authentication", http.StatusCreated)
}
