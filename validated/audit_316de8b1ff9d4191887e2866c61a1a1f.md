## Finding: Missing beneficiary-registration check in `staking_contract::set_beneficiary_for_operator` permanently blocks staker's stake distribution and operator switching

### Title
Operator-controlled beneficiary can permanently DoS staker fund distribution and operator switch - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract.move`'s `distribute_internal` pays out commission and staker funds to multiple recipients in a single loop via `aptos_account::deposit_coins`, which aborts if the recipient cannot receive direct coin transfers. `vesting.move` explicitly guards against this by requiring `assert_account_is_registered_for_apt(new_beneficiary)` before setting a beneficiary [1](#0-0) , with an explicit comment stating this exists so `distribute()` "wouldn't fail and block all other accounts from receiving APT if one beneficiary is not registered." The analogous `staking_contract::set_beneficiary_for_operator` has no such check [2](#0-1) , allowing an operator to set a beneficiary that cannot accept direct transfers, which then reverts every future distribution to that staking contract — blocking the staker's own inactive-stake withdrawal.

### Finding Description
`distribute_internal` withdraws all inactive/pending_inactive coins from the stake pool and iterates over every shareholder in the `distribution_pool` (staker and operator/beneficiary) in one loop, calling `aptos_account::deposit_coins` for each recipient [3](#0-2) . `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the target account is not registered for the coin and has disabled direct coin transfers [4](#0-3) .

`set_beneficiary_for_operator` lets the operator (an unprivileged party relative to the staker's funds) freely set any address as their commission beneficiary with no registration/receivability check [5](#0-4) . If that beneficiary address cannot accept direct transfers (e.g. an account/object that called `coin::register`-avoidant patterns or explicitly disabled direct transfers), then any call into `distribute_internal` — which resolves the operator's payout recipient via `beneficiary_for_operator(operator)` [6](#0-5)  — aborts for the *entire* transaction, not just the operator's portion.

Because `distribute_internal` is invoked as the first step inside `unlock_stake` [7](#0-6)  and inside `switch_operator*` functions before the operator can be changed [8](#0-7) , a poisoned beneficiary blocks:
- the staker from withdrawing any of their already-unlocked (inactive) stake via `distribute`/`unlock_stake`,
- the staker from switching away from the malicious operator via `switch_operator`/`switch_operator_with_same_commission`.

Since `set_beneficiary_for_operator` is only gated by a feature flag (`operator_beneficiary_change_enabled`) and requires no staker consent [9](#0-8) , the operator — a party who does not own the staker's principal — can unilaterally trap the staker's funds and prevent the staker from firing them.

### Impact Explanation
This is a stake-lockup analog to the Malt whitelisted-recipient revert bug: an unprivileged, non-owning actor (operator) sets a hostile recipient address that causes the shared payout path to revert, freezing legitimate owners' (staker's) withdrawal and exit rights. Because both `unlock_stake`/`distribute` and `switch_operator` depend on `distribute_internal` succeeding first, the staker has no recovery path within `staking_contract.move` itself once the operator sets an unreachable beneficiary — their inactive stake becomes permanently non-withdrawable and they cannot fire the operator. This satisfies the "permanent lock or non-recoverable loss of claim rights" and "wrong-role control...without already holding that role" impact categories.

### Likelihood Explanation
High likelihood: `set_beneficiary_for_operator` is a normal, unprivileged, operator-callable entry function requiring no special setup [10](#0-9) . Any operator (malicious, compromised, or simply misconfiguring) can trigger this by setting a beneficiary address that never registers for `AptosCoin` and disables direct transfers, which requires no coordination with the staker.

### Recommendation
Add the same guard used in `vesting::set_beneficiary` to `staking_contract::set_beneficiary_for_operator`: require `aptos_account::assert_account_is_registered_for_apt(new_beneficiary)` (or equivalent `can_receive_direct_coin_transfers` check) before accepting the new beneficiary. Additionally, consider making `distribute_internal` resilient to a single failing recipient (e.g., skip/queue a failed payout instead of aborting the whole distribution) so a single bad beneficiary cannot block distribution to the staker.

### Proof of Concept
1. Staker creates a staking contract with operator O via `staking_contract::create_staking_contract`, stakes funds, O joins the validator set, rewards accrue.
2. O calls `set_beneficiary_for_operator(O, B)` where B is an address that has never registered for `AptosCoin` and has called `set_allow_direct_coin_transfers(false)` (or is an object/resource account with no coin store and rejects direct deposits).
3. Stake pool accrues inactive/pending_inactive funds (via normal unlock cycle).
4. Staker calls `staking_contract::distribute(staker, O)` (or `unlock_stake`), which internally calls `distribute_internal` → `beneficiary_for_operator(O)` resolves to B → `aptos_account::deposit_coins(B, ...)` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. The entire transaction reverts — the staker cannot withdraw their own already-unlocked stake.
6. Staker attempts `switch_operator(staker, O, new_operator, commission)` to fire O; this also calls `distribute_internal` first and reverts for the same reason, so the staker is stuck with operator O and cannot access unlocked funds. [11](#0-10) [12](#0-11)

    ) acquires Store, BeneficiaryForOperator {
        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.

        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

            staking_contract,
            staker_address,
            amount,
        );

        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            UnlockStake { pool_address, operator, amount, commission_paid }
        );
    }

    /// beneficiary. To ensures payment to the current beneficiary, one should first call `distribute` before switching
    /// the beneficiary. An operator can set one beneficiary for staking contract pools, not a separate one for each pool.
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
