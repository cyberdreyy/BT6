Based on the codebase evidence, there is a concrete analog matching this bug class in marginfi's emissions accounting.

### Title
Closing a lending account balance permanently destroys unclaimed `emissions_outstanding` without paying or validating it - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
The M-33 bug class is: a state-resetting operation (restaking) wipes out an accounting field (`tokenIdRewards`) that tracks a user's pending, unclaimed reward, causing that reward to be permanently lost because the reset happens before/without settling it. The same pattern exists in marginfi's `close_balance` flow: it resets the entire `Balance` struct (including `emissions_outstanding`) via `Balance::close()`/`empty_deactivated()`, with no check or payout of any accrued-but-unclaimed emissions.

### Finding Description
Each `Balance` tracks `emissions_outstanding`, the unclaimed emissions reward accrued for that specific position: [1](#0-0) 

`lending_account_close_balance` loads the balance, accrues bank interest, and calls `bank_account.close_balance(in_receivership)`: [2](#0-1) 

The `close_balance` implementation only validates that `current_liability_amount` and `current_asset_amount` are zero (with tolerance for dust), and routes any leftover asset dust to `collected_insurance_fees_outstanding`. It never inspects or settles `emissions_outstanding` before calling `balance.close()`: [3](#0-2) 

`balance.close()` fully resets the struct via `Self::empty_deactivated()`, which sets `emissions_outstanding` back to `I80F48::ZERO`: [4](#0-3) [5](#0-4) 

Notably, the error enum already contains a dedicated variant apparently meant to guard against exactly this scenario — `CannotCloseOutstandingEmissions` ("Cannot close balance because of outstanding emissions"), but it is not referenced anywhere in the `close_balance` instruction or the `BankAccountWrapper::close_balance` function shown: [6](#0-5) 

This mirrors the `BoostAggregator` bug precisely: a legitimate, permissionless-to-the-user maintenance/lifecycle action (`unstakeAndWithdraw` restaking / here, `lending_account_close_balance`) resets an accounting slot that stores a pending, user-owned reward balance, without first settling or transferring that value out, causing silent, irreversible loss.

I was not able to fully inspect `programs/marginfi/src/instructions/marginfi_account/emissions.rs` (the claim instruction) in this session due to a tool error, so I cannot confirm with certainty whether some other code path enforces `CannotCloseOutstandingEmissions` before this instruction is reachable, or whether `emissions_outstanding` is normally settled to zero by a prior deposit/withdraw call before a balance can be closed. This is a gap that should be verified directly in the repository before treating this as fully confirmed — specifically checking whether `close_balance`'s preconditions (typically requiring `current_asset_amount`/`current_liability_amount` at zero) can ever be reached while `emissions_outstanding` is still nonzero in practice.

### Impact Explanation
If reachable with nonzero `emissions_outstanding`, this causes a direct, silent loss of user-owned reward tokens with no recovery path — the value simply vanishes from on-chain state when the balance struct is reset, analogous to the confirmed Maia finding.

### Likelihood Explanation
Emissions accrue as a side effect of interest updates on any active balance in a bank running an emissions campaign; users close balances routinely once their asset/liability is fully withdrawn/repaid. Whether the check is actually missing (not just present elsewhere) is the open question above — likelihood is contingent on that gap being real rather than enforced by another guard I could not verify in this session.

### Recommendation
Before calling `balance.close()` in `close_balance`, explicitly check that `emissions_outstanding` is zero (returning `MarginfiError::CannotCloseOutstandingEmissions` if not), or automatically flush/transfer the outstanding emissions to the user (or an emissions-destination account) as part of the close instruction, mirroring the C4 mitigation of always settling pending value before resetting accounting state.

### Proof of Concept
1. A bank has an active emissions campaign (`emissions_rate` set) as described in `guides/USER/EMISSIONS.md`.
2. A user deposits into that bank; interest/emissions accrual updates the user's `Balance.emissions_outstanding` to a nonzero value.
3. The user fully withdraws/repays the position so `current_asset_amount` and `current_liability_amount` are within `ZERO_AMOUNT_THRESHOLD`, satisfying `close_balance`'s preconditions, while `emissions_outstanding` remains nonzero.
4. The user (or anyone authorized) calls `lending_account_close_balance`.
5. `BankAccountWrapper::close_balance` calls `balance.close()`, which resets `emissions_outstanding` to zero without any transfer/claim, permanently destroying the user's unclaimed emissions.

```rust
pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
```

```rust
    /// When `in_receivership` is true, clears the bank's liquidation price cache lock
    /// so that banks whose balances are closed mid-liquidation don't stay permanently locked.
    pub fn close_balance(&mut self, in_receivership: bool) -> MarginfiResult<()> {
        let balance = &mut self.balance;
        let bank = &mut self.bank;

        let current_liability_amount =
            bank.get_liability_amount(balance.liability_shares.into())?;
        let current_asset_amount = bank.get_asset_amount(balance.asset_shares.into())?;

        check!(
            current_liability_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing debt"
        );

        check!(
            current_asset_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing assets"
        );

        let asset_shares: I80F48 = balance.asset_shares.into();
        let liability_shares: I80F48 = balance.liability_shares.into();
        // Counters are incremented in `*_balance_internal` when shares cross
        // `ZERO_AMOUNT_THRESHOLD` upward; match that condition so we don't
        // double-decrement positions that already crossed downward earlier.
        let had_assets = asset_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);
        let had_liabs = liability_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);

        balance.close()?;

        if in_receivership {
            bank.cache.clear_liquidation_price_cache_locked();
        }

        // Asset-side dust = real tokens still in the liquidity vault that the
        // user never withdrew. Route to `collected_insurance_fees_outstanding`
        // so vault content stays fully accounted for, mirroring the fractional-
        // remainder handling in `withdraw_all`.
        if current_asset_amount > I80F48::ZERO {
            bank.collected_insurance_fees_outstanding =
                I80F48::from(bank.collected_insurance_fees_outstanding)
                    .checked_add(current_asset_amount)
                    .ok_or_else(math_error!())?
                    .into();
        }

        bank.change_asset_shares(-asset_shares, false)?;
        // Liability-side dust = bad debt the borrower never repaid. Decrementing
        // here makes the loss explicit instead of leaving phantom shares in
        // `total_liability_shares` that would compound interest indefinitely.
        bank.change_liability_shares(-liability_shares, true)?;

        if had_assets {
            bank.decrement_lending_position_count();
        }
        if had_liabs {
            bank.decrement_borrowing_position_count();
        }

        Ok(())
    }
```
