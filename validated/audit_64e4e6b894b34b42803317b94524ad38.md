### Title
Path traversal / zip-slip in legacy zip extraction (`helpers/archives`) allows writes outside build/cache root - (File: `helpers/archives/path_check_helper.go`, `helpers/archives/zip_extract.go`)

### Summary
`extractZipFile`/`extractZipFileEntry`/`extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` write files using `zip.File.Name` verbatim, and the only pre-extraction validation, `errorIfGitDirectory` in `helpers/archives/path_check_helper.go`, only rejects names whose first path segment is `.git`. There is no rejection of `../` traversal segments or absolute paths, so a crafted zip entry name can cause writes outside the intended extraction directory.

### Finding Description
`errorIfGitDirectory` -> `isPathAGitDirectory` only checks `filepath.Clean(path)`'s first path segment for `".git"`: [1](#0-0) 
It performs no check for a leading `..`, an absolute path, or embedded `../` segments after cleaning (e.g. `foo/../../bar` cleans to `../bar`, whose first segment is `..`, not `.git`, and is therefore never flagged).

`ExtractZipArchive` calls `errorIfGitDirectory` purely for the warning log, but treats any other error path as non-fatal (`tracker.actionable`), and unconditionally proceeds to `extractZipFile(file)`: [2](#0-1) 

`extractZipFile` does `os.MkdirAll(filepath.Dir(file.Name), ...)` and then dispatches to `extractZipFileEntry` (regular files, `os.OpenFile(file.Name, ...)`) or `extractZipSymlinkEntry` (`os.Symlink(target, file.Name)`), all using the raw, attacker-controlled `file.Name`: [3](#0-2) 

This code is consumed by the "legacy" zip extractor, `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`, whose `Extract()` calls `archives.ExtractZipArchive(zr)` directly and **never uses the `dir` field that was passed to `NewExtractor`**: [4](#0-3) 
The test suite explicitly documents that this extractor only works correctly because the caller has `chdir`'d into the target directory first ("hack: legacy archiver require being in the correct working dir"): [5](#0-4) 

However, the real callers — `ArtifactsDownloaderCommand.Execute` and `CacheExtractorCommand.Execute` — do **not** `chdir`; they just capture `wd := os.Getwd()` and pass it as the `dir` argument to `archive.NewExtractor(format, f, size, wd)`, relying on the extractor implementation to honor it: [6](#0-5) [7](#0-6) 
Because the ziplegacy `Extract()` silently ignores `dir`, extraction happens relative to the process's actual current working directory using the raw `file.Name` from the archive, with zero sanitization of `..`/absolute paths. Any zip entry named e.g. `../../../../home/gitlab-runner/.gitlab-runner/config.toml` or an absolute path will be written outside the job workspace that `wd` was intended to confine extraction to.

### Impact Explanation
An attacker who controls the content of a cache/artifact zip (uploaded from their own job) can, when this artifact/cache is later downloaded and extracted by the runner (in the same or another job/project reusing that cache key), overwrite arbitrary files reachable from the runner process's cwd via `..` traversal, or write to an absolute path if the runner process has permissions to do so (e.g. runner config, other checked-out repos, or another job's workspace on a shared host runner). This is a classic zip-slip vulnerability, scoped exactly to cross-project cache/artifact poisoning as described in the question.

### Likelihood Explanation
The vulnerable code path (`helpers/archives` package, no `..`/absolute-path guard) is unconditionally reachable whenever the "ziplegacy" extractor is selected for zip extraction — this package/extractor exists specifically as an alternate/legacy implementation, and GitLab Runner is known to allow selecting archiver/extractor implementations via feature-flag CI/CD variables (e.g. `FF_USE_FASTZIP`), which a pipeline author can set in their own `.gitlab-ci.yml`. I could not fully verify within this session the exact registration/selection condition that routes to `ziplegacy` vs. `fastzip` in this specific snapshot of the repo (this would require confirming `Register(...)` call sites and any feature-flag gating, which I did not get to inspect), so this is a documented gap rather than a fully traced end-to-end confirmation. If `ziplegacy` is reachable via any user-settable configuration, the exploit is trivially repeatable: any pipeline author can craft a cache/artifact zip with malicious entry names and have it processed by `cache-extractor`/`artifacts-downloader`.

### Recommendation
Add strict path validation in `helpers/archives/zip_extract.go` (or centrally in `path_check_helper.go`) before any filesystem operation: for each `file.Name`, reject or clamp entries where `filepath.IsAbs(name)` is true, or where `filepath.Clean(filepath.Join(dir, name))` does not have `dir` as a prefix (the standard zip-slip check). Apply this to `extractZipFile`, `extractZipFileEntry`, `extractZipDirectoryEntry`, and `extractZipSymlinkEntry` (also validate symlink targets, not just the entry name). Additionally, fix `ziplegacy.extractor.Extract` to actually use `e.dir` (e.g. by resolving all entries relative to `e.dir` explicitly, not relying on process cwd).

### Proof of Concept
```go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    testOnArchive(t, func(t *testing.T, archive *zip.Writer) {
        f, err := archive.Create("../../evil.txt")
        require.NoError(t, err)
        _, err = io.WriteString(f, "pwned")
        require.NoError(t, err)
    }, func(t *testing.T, fileName string) {
        wd, _ := os.Getwd()
        outsidePath := filepath.Join(filepath.Dir(filepath.Dir(wd)), "evil.txt")
        defer os.Remove(outsidePath)

        err := ExtractZipFile(fileName)
        require.NoError(t, err)

        // BUG: file was written outside the intended extraction root
        _, statErr := os.Stat(outsidePath)
        assert.NoError(t, statErr, "expected traversal write outside extraction root")
    })
}
```
Expected (buggy) result: the file lands at `outsidePath`, two directories above the extraction root, proving the traversal. A fixed version should instead return an error and never create `outsidePath`.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
