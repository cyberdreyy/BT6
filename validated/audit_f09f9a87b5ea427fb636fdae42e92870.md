### Title
Request-ID reuse after `sendResponseAndClearRequest` allows stale straggler node responses to be routed into a new caller's `activeRequest` - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`newActiveRequest` only rejects a `req.ID` while it is still present in `h.activeRequests`; once a request is cleared by `sendResponseAndClearRequest`, the same ID can be reused immediately by any caller. Because `HandleNodeMessage` looks up the target purely by `resp.ID` via `h.getActiveRequest`, a straggler response addressed to the just-cleared (victim) request can be delivered into a brand-new `activeRequest` created by a different, unrelated caller who reused the same ID.

### Finding Description
`req.ID` is entirely client-supplied: it comes straight from the JSON-RPC payload decoded in `gateway.ProcessRequest` (`jsonRequest.ID`), with only a length check, and is passed unchanged into `HandleJSONRPCUserMessage` [1](#0-0)  and then into `h.newActiveRequest` [2](#0-1) .

`newActiveRequest` only guards against a *currently live* duplicate ID: [3](#0-2)  There is no per-ID cooldown, sequence/generation number, or binding of `req.ID` to the caller/connection that created it.

`sendResponseAndClearRequest` deletes the ID from `h.activeRequests` as soon as any completion path (node quorum, grace window, or expiry) fires [4](#0-3) , which can happen well before every DON member's response has arrived (e.g. as soon as quorum/grace elapses, or on expiry after `requestTimeout`).

`HandleNodeMessage` resolves the target purely by ID with no generation check: [5](#0-4)  If a straggling node response for the original (now-cleared) request arrives after a second caller has registered a new `activeRequest` under the identical ID, `getActiveRequest(resp.ID)` returns the new caller's `activeRequest`, and `addResponseForNode` merges the stale response directly into the new request's `responses` map, later feeding it into that caller's `bundler.Bundle` output and potentially into the response sent back to the new (attacker) caller via `forwardBundle`/`sendResponseAndClearRequest`.

Nothing in this file cryptographically or structurally binds a node response to the specific request generation (no nonce/epoch embedded in the ID space, no rejection of responses whose method/params fingerprint doesn't match the currently-registered request). The only correlation key is the bare string ID, which is attacker-controlled and freely reusable the instant the prior holder's request completes.

### Impact Explanation
This is a cross-user response confusion bug: an attacker who predicts/reuses a request ID immediately after it is cleared can have late DON responses meant for a different (victim) session merged into the attacker's own confidential-relay aggregation, and — depending on bundler/quorum behavior — forwarded back to the attacker as part of their bundle. In the `confidentialrelay` handler this method space includes `MethodSecretsGet` and `MethodCapabilityExec` [6](#0-5) , so a contaminated bundle could mix node-signed response fragments belonging to another user's secrets/capability-exec request into the attacker's own delivered response. This matches the "cross-user response confusion" bounty impact class described in the task rubric.

### Likelihood Explanation
Exploitability requires: (1) an unprivileged, unauthenticated ability to choose an arbitrary `req.ID` string (confirmed — the ID is caller-supplied with only a length cap), and (2) winning a race between a victim's request clearing (`sendResponseAndClearRequest`) and a late DON response for the same original ID still arriving. Since `defaultCleanUpPeriod` is 1 second and quorum/grace completion can fire well before all `donConfig.Members` have replied, and node sends can be delayed up to `nodeSendTimeout`/network latency, a straggler response landing after clear-but-before-attacker-reuse is a realistic timing window, not a purely theoretical one. No credentials beyond ordinary gateway API access are required, and the attack is repeatable.

### Recommendation
Bind `req.ID` to a per-registration generation/nonce that is not attacker-predictable-reusable, e.g., internally key `activeRequests` by a tuple of `(req.ID, monotonic generation counter)` or embed a server-minted UUID alongside the client ID, and have `HandleNodeMessage` verify that a stale/generation-mismatched response is dropped rather than merged. Alternatively, once an ID is cleared, quarantine it for at least `requestTimeout` before allowing reuse, and have `HandleNodeMessage` explicitly check that the `activeRequest` it retrieves was created after the response's originating request was sent (e.g., compare `createdAt` against a response-carried timestamp/session token).

### Proof of Concept
Go unit test plan in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` with a fake `clock` and mock `bundler`/`don`.
2. Call `HandleJSONRPCUserMessage` for "victim" request with `ID = "shared-id"`, then directly force completion via `h.sendResponseAndClearRequest` (or drive quorum so it clears), simulating the victim's request finishing and being deleted from `h.activeRequests`.
3. Immediately call `HandleJSONRPCUserMessage` for "attacker" request reusing `ID = "shared-id"`, capturing the new `activeRequest` pointer returned via `h.getActiveRequest("shared-id")`.
4. Invoke `h.HandleNodeMessage` with a `jsonrpc.Response` whose `ID = "shared-id"` from a DON member, representing the victim's straggler response.
5. Assert that this stale response is present in the attacker's `activeRequest.responses` map (`ar.copiedResponses()`), demonstrating it was NOT dropped and instead merged into the wrong (attacker) generation — proving the invariant "no ID reuse cross-talk" is violated. A fixed implementation should assert the straggler response is discarded (e.g., by generation mismatch) and never appears in the attacker's bundle.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
