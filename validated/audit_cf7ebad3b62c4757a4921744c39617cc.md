### Title
Request ID reuse after `sendResponseAndClearRequest` allows a straggling node response for a deleted request to attach to a new, unrelated `activeRequest` - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`newActiveRequest` only rejects a `req.ID` while it is *currently* present in `h.activeRequests`; once `sendResponseAndClearRequest` deletes the entry, the exact same ID can be reused by any caller. Because `HandleNodeMessage` looks up the `activeRequest` purely by the string ID with no generation/nonce binding to the specific fan-out call that produced it, a late (straggling) node reply tied to the just-completed request can be routed into a brand-new `activeRequest` created by a different caller who reused the freed ID.

### Finding Description
`HandleJSONRPCUserMessage` performs only length/emptiness checks on the attacker-supplied `req.ID` and then calls `newActiveRequest`: [1](#0-0) 

`newActiveRequest` guards only against *concurrent* collisions - it checks `h.activeRequests[req.ID] != nil`, which is `nil` again the instant the previous request completes: [2](#0-1) 

Completion always goes through `sendResponseAndClearRequest`, which sends the response and then deletes the map entry under lock, freeing the ID for reuse with no cooldown, tombstone, or generation counter: [3](#0-2) 

`HandleNodeMessage` resolves the target `activeRequest` solely by `resp.ID` via `getActiveRequest`, with no check that the responding node's message actually belongs to the fan-out that created the *current* holder of that ID: [4](#0-3) 

The bundler is explicitly documented as a "dumb fan-in" that forwards every collected per-node response without verifying signatures, signer membership, or deciding quorum itself - it defers all trust decisions to the downstream enclave: [5](#0-4) 

Given this, the described sequence is reachable purely through the gateway API: (1) victim's request with ID `X` completes and is deleted from `activeRequests`; (2) attacker immediately calls `HandleJSONRPCUserMessage` with `req.ID = X` and their own params, succeeding because the map entry no longer exists; (3) a slow node from the victim's original fan-out for `X` finally replies; `HandleNodeMessage` finds the attacker's freshly created `activeRequest` under key `X` and calls `ar.addResponseForNode`, splicing the victim-context response into the attacker's response set, which is then bundled with `ar.req` (the attacker's own request) and forwarded toward the attacker's callback once quorum-readiness heuristics are satisfied. The same pattern exists in the vault handler, which uses an identical `newActiveRequest`/`sendResponse`+`delete` pattern. [6](#0-5) [7](#0-6) 

No component in the gateway itself verifies that a node's response is tied to the exact request instance (e.g., via a per-fan-out nonce, generation counter, or binding the response to the specific `req.Params`/context that was sent) rather than just the reusable string ID.

### Impact Explanation
This breaks the stated isolation invariant ("one user's callback cannot be answered with another's data") at the gateway layer: a straggling, cryptographically-valid node response destined for one caller's original request can be merged into a different caller's active request purely by ID collision, and forwarded downstream in that caller's bundle. Whether this ultimately yields secret/result disclosure to the attacker depends on validation performed by the downstream enclave (not present in this repository), which the gateway explicitly does not perform itself. At minimum this is a cross-user response-object confusion bug at the handler level that violates request isolation and could corrupt quorum bundle contents; combined with enclave-side handling, it maps to the "cross-user response leakage (secrets/capability result)" bounty impact class described in the question.

### Likelihood Explanation
Exploitability requires only a run-role/authenticated gateway client credential (no operator/admin access), and the ability to observe or predict when a target's request completes (e.g., via response timing) and to choose the same ID for a follow-up request. Request IDs are fully attacker-chosen (only length/non-empty checks apply), and the race window is bounded only by how late a straggling node reply can arrive relative to `sendResponseAndClearRequest`. This is feasible but requires timing precision and a genuinely slow/lagging node in the DON, making it a real but non-trivial race condition rather than a guaranteed-reliable exploit.

### Recommendation
Bind each `activeRequest` to a unique internal generation/nonce independent of the attacker-supplied `req.ID` (e.g., include a monotonically increasing counter or random session token in the outbound request to nodes, and require `HandleNodeMessage` to match that token rather than the bare user-supplied ID before attaching a response). Alternatively, retain a short-lived tombstone for recently completed IDs so `newActiveRequest` rejects immediate reuse, and have `HandleNodeMessage` discard responses whose fan-out context does not match the currently active request.

### Proof of Concept
Go handler-level integration test plan (confidentialrelay package):
1. Configure a DON with `setupHandler(t, N)`.
2. Call `h.HandleJSONRPCUserMessage` for "victim" with `req.ID = "shared-id"` and params `P1`; supply enough signed `HandleNodeMessage` calls from all-but-one node to reach `forwardBundleOrTerminateIfReady`'s completion path, causing `sendResponseAndClearRequest` to fire and delete `activeRequests["shared-id"]`. Assert `h.getActiveRequest("shared-id")` is `nil`.
3. Immediately call `h.HandleJSONRPCUserMessage` for "attacker" reusing `req.ID = "shared-id"` with different params `P2`; assert it succeeds (no "request ID already exists" error).
4. Deliver the still-pending straggling node response (signed for `P1`/victim context) via `h.HandleNodeMessage(ctx, victimStragglerResp, nodeAddr)`.
5. Assert that this response is recorded against the attacker's `activeRequest` (e.g., inspect via `ar.copiedResponses()` or observe it appearing in the bundle delivered to the attacker's callback), demonstrating that data from the victim's original relay flow was merged into the attacker's request/callback rather than being dropped as stale.

```go
func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
```

```go
func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
```

```go
func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

	copiedResponses := ar.copiedResponses()
	// Bundle readiness counts decodable signed responses, while the enclave remains
	// responsible for signature and quorum verification. A collected response cannot
	// be replaced by a later response from the same node.
	summary, err := h.bundler.Bundle(ar.req, copiedResponses, l)
	if err != nil {
		l.Errorw("failed to build relay response bundle", "error", err)
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, err))
	}
	return h.forwardBundleOrTerminateIfReady(ctx, l, ar, summary, len(h.donConfig.Members)-summary.Total(), false)
```

```go
func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
```

```go
// bundler assembles the gateway's response to the enclave. The gateway is a dumb
// fan-in: it forwards every per-node signed response it collected, in one bundle,
// without verifying signatures, checking signer membership, or deciding quorum.
//
// The enclave is the sole trust anchor. It groups the bundle by response hash,
// verifies each signature against the relay-DON signer set, and accepts the result
// backed by F+1 valid distinct signers. Because responses are keyed upstream by the
// gateway-authenticated node address (one response per node), a single compromised
// relay node can contribute at most its own one response to the bundle. It cannot
// manufacture quorum by fabricating signer identities; the worst it can do is add
// noise the enclave discards. This is what closes the prior liveness gap, where the
// gateway counted unverified, attacker-controlled signer identities toward quorum
// and could commit to a forged response, starving the enclave of the real one.
```

```go
func (h *handler) sendResponse(ctx context.Context, userRequest *activeRequest, resp gwhandlers.UserCallbackPayload) error {
	switch resp.ErrorCode {
	case api.StaleNodeResponseError:
	case api.FatalError:
	case api.NodeReponseEncodingError:
	case api.RequestTimeoutError:
	case api.HandlerError:
	case api.ConflictError:
	case api.LimitExceededError:
		h.metrics.requestInternalError.Add(ctx, 1, metric.WithAttributes(
			attribute.String("don_id", h.donConfig.DonId),
			attribute.String("error", resp.ErrorCode.String()),
		))
	case api.InvalidParamsError:
	case api.UnsupportedMethodError:
	case api.UserMessageParseError:
	case api.UnsupportedDONIdError:
		h.metrics.requestUserError.Add(ctx, 1, metric.WithAttributes(
			attribute.String("don_id", h.donConfig.DonId),
		))
	case api.NoError:
		h.metrics.requestSuccess.Add(ctx, 1, metric.WithAttributes(
			attribute.String("don_id", h.donConfig.DonId),
		))
	}

	err := userRequest.SendResponse(resp)
	if err != nil {
		h.lggr.Errorw("error sending response to user", "requestID", userRequest.req.ID, "error", err)
		return err
	}

	h.mu.Lock()
	defer h.mu.Unlock()
	delete(h.activeRequests, userRequest.req.ID)
	h.lggr.Debugw("response sent to user", "requestID", userRequest.req.ID, "errorCode", resp.ErrorCode)
	return nil
}
```
