### Title
Peer-signature tally path (`store_and_process_block_signature`) skips the chainstate/conflict re-check that the sibling pre-commit path enforces, letting a signer broadcast a block it has refused to sign - ([File: stacks-signer/src/v0/signer.rs])

### Summary
The v0 signer has two independent code paths that can push a signer's local state to "enough signatures, broadcast the block": (1) `handle_block_pre_commit`, reached from `BlockPreCommit` messages and from `handle_block_validate_ok`'s own pre-commit, and (2) `store_and_process_block_signature`, reached from peer `BlockResponse::Accepted` messages via `handle_block_signature`. Only path (1) re-runs `check_block_against_signer_db_state` (the "RECHECK" gate) and the conflict/`reorg_permit_stands` guard immediately before counting weight toward the threshold [1](#0-0) . Path (2) never calls this check: it stores the signature via `add_block_signature`, tallies `total_signature_weight`, and on reaching threshold directly calls `block_info.mark_locally_accepted(true)` and `broadcast_signed_block` [2](#0-1) .

### Finding Description
`handle_block_pre_commit` treats a validated-but-not-yet-fresh conflict (a block this signer already signed at the same or higher height, in any tenure) as a reason to stay silent rather than sign — a "hold" state (`HOLD1`/`HOLD2` in `docs/signer-flows.md` section 5) [3](#0-2) . That guard, plus the sticky `check_block_against_signer_db_state` rejection right before it, only exists on the pre-commit→signature path.

`store_and_process_block_signature` is the *other* place a signer's local view is mutated to "locally accepted" and broadcast to the node [4](#0-3) . Once a peer signer's `has_committed` flag is already true for a given block hash — which is set by any earlier call to `add_block_pre_commit`, including the "outdated peer" fallback used the very first time an out-of-order acceptance arrives — every subsequent `BlockAccepted` signature from that peer skips the fallback branch entirely (`OLD -- no --> GRP` in the flow doc) and goes straight into weight tallying [5](#0-4) . Nowhere in that tally path is `check_block_against_signer_db_state`, `get_signed_conflicts`, or `conflict_still_blocks` invoked. `mark_locally_accepted(true)` is a legal state transition even from `LocallyRejected`/`Unprocessed` per `BlockInfo::check_state` [6](#0-5) , so this signer's local state flips to accepted, and `broadcast_signed_block` assembles the aggregate signature set straight from whatever is stored in the DB and unconditionally calls `handle_post_block` to push the block to this signer's own node [7](#0-6) .

This is the same root-cause shape as the reported bug class: two independent code paths implement "am I allowed to act on this block," and only one was updated/maintained to include the guard (role check ↔ chainstate/conflict re-check); the other silently omits it.

### Impact Explanation
A signer can end up assembling and pushing to its own node a block that it had explicit, local, signed-conflict evidence to refuse — i.e., contributing its network bandwidth/API surface to adopt a conflicting/stale block its own conflict guard was designed to block, without ever re-verifying that the conflict is still stale or that the chainstate checks still pass. This maps to "a rejection/hold recounted as an acceptance-and-broadcast" — the local safety guard against signing/propagating a conflicting block is bypassed on the signature-tally path even though it is enforced on the pre-commit-tally path for the identical threshold decision.

### Likelihood Explanation
Reachable purely via gossiped StackerDB messages from other signers (`BlockPreCommit` once, then `BlockResponse::Accepted`), requiring no majority-key compromise, auth token, or local node access — only ≥70% weight of *other* signers actually issuing real acceptances for a block this signer's conflict guard would otherwise hold on. This can occur naturally in a benign fork/reorg race (the scenario the guard exists for) since the guard is timing- and view-dependent per signer.

### Recommendation
Have `store_and_process_block_signature` invoke the same `check_block_against_signer_db_state` re-check (and conflict/`reorg_permit_stands` evaluation) before calling `mark_locally_accepted` and `broadcast_signed_block`, mirroring what `handle_block_pre_commit` does immediately before signing, so both paths that can trigger a broadcast share one authoritative gate.

### Proof of Concept
1. Signer S has already signed block A at height h (tenure T1); `signed_self` set, conflict recorded.
2. A competing block B is proposed at height h in tenure T2 (or a re-proposed tenure-start block). S validates B (`valid=true`), pre-commits; the pre-commit round for B reaches 70% weight including S and peers P1..Pn (so S has stored `add_block_pre_commit` for each Pi — `has_committed(B, Pi)=true`).
3. S's own `handle_block_pre_commit` RECHECK/conflict guard determines A is still fresh/live and refuses to sign B (`HOLD1`), so S never sets `signed_self` for B.
4. P1..Pn, on their own view, do sign B and each broadcast a real `BlockResponse::Accepted(B)` over StackerDB.
5. On S, `handle_block_signature`→`store_and_process_block_signature` processes each: `has_committed(B, Pi)` is already true, so the "outdated peer" fallback is skipped; the signature is stored and tallied with no re-check of `block_info.valid` or conflict state.
6. Once accumulated weight ≥70%, S calls `mark_locally_accepted(true)` and `broadcast_signed_block`, which posts B (with the aggregated signature set) to S's own node via `handle_post_block` — despite S itself having refused to add its own signature moments earlier for exactly this conflict.

    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
