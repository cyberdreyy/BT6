This confirms it: `limitwriter` is used elsewhere (trace buffer, docker helpers) but is not applied anywhere in the archive extraction path — none of the extractors (`tarzstd`, `ziplegacy`, `fastzip`) enforce a decompressed-size limit on `io.Copy`.

### Title
Unbounded decompression in tar+zstd extractor allows disk-exhaustion (zstd bomb) via cache/artifact extraction - ([File: commands/helpers/archive/tarzstd/tarzstd_extractor.go])

### Summary
`extractor.Extract` decompresses a zstd stream and writes each tar entry to disk with `io.Copy(f, tr)` with no cumulative or per-file byte cap, so a small, highly-compressible cache/artifact archive can expand to an arbitrarily large amount of data and fill the shared runner host's disk.

### Finding Description
In `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, `Extract` builds a `zstd.NewReader` over the input and wraps it in a `tar.NewReader`, then for each regular file entry calls `os.Create(path)` followed by `io.Copy(f, tr)` (lines 87-99) with no limit on bytes written, no check against `hdr.Size`, and no aggregate quota across all entries in the archive. The only checks performed are path-traversal protection (`filepath.Abs`/`strings.HasPrefix` at lines 57-64) and irregular-file-mode skipping (line 53) — neither limits decompressed volume. This extractor is invoked from both `CacheExtractorCommand.Execute` (`commands/helpers/cache_extractor.go`, calling `archive.NewExtractor(...).Extract(ctx)`) and `ArtifactsDownloaderCommand.Execute` (`commands/helpers/artifacts_downloader.go`), both of which are executed inside a job's build context on the runner host. An attacker who controls job cache/artifact content (any pipeline author) can push a cache using `CACHE_COMPRESSION_FORMAT: tarzstd`, containing one or more tar entries whose content is highly compressible (e.g., all-zero data), achieving compression ratios in the thousands-to-one range typical of zstd. Although `CacheArchiverCommand.MaxUploadedArchiveSize` (`commands/helpers/cache_archiver.go` lines 445-457) can cap the *compressed* archive size on upload, this only bounds what is stored/uploaded — it does not constrain the decompressed output size during extraction, and is optional/unset by default. There is no equivalent guard, and no per-file `hdr.Size` cross-check, in the extraction path, nor is `limitwriter.New` (which exists in the codebase and is used elsewhere, e.g. `helpers/trace/buffer.go`) applied here.

### Impact Explanation
On shared executors (e.g., `shell` executor with multiple concurrent jobs, or hosts running multiple job build directories), a single job's cache or artifact extraction can consume all available disk space on the host filesystem shared by other concurrently-running jobs/tenants, causing their cache/artifact extraction, build directory writes, or Docker layer operations to fail with "no space left on device," a persistent multi-tenant denial of service until the disk is cleaned up.

### Likelihood Explanation
Feasible and repeatable: an attacker only needs to be an authorized pipeline author who can set `CACHE_COMPRESSION_FORMAT: tarzstd` and push a cache containing a small, highly-compressible payload (e.g., a sparse/zero-filled file); zstd trivially compresses such data by orders of magnitude. No admin privileges, no exploitation of leaked credentials, and no cluster compromise are required — this is a standard cache-push job followed by any job (including a subsequent job by the same or other project sharing the host) triggering extraction.

### Recommendation
Enforce a decompressed-size limit during extraction in `tarzstd_extractor.go` (and other extractors lacking one): wrap the per-file writer with `helpers/limitwriter.New(f, maxSize)` (already available in the codebase) and/or maintain a running total of bytes written across all entries in the archive, aborting extraction with an error once a configurable maximum (e.g., a `CACHE_MAX_EXTRACTED_SIZE`/`ARTIFACTS_MAX_EXTRACTED_SIZE` setting) is exceeded. Additionally, cross-check `io.Copy` byte counts against `hdr.Size` from the tar header to detect truncation/mismatch attacks.

func TestExtract_ZstdBombExpandsUnbounded(t *testing.T) {
    // Build a tar containing one file with a huge declared size but tiny
    // actual highly-compressible zero content, compressed with zstd.
    var tarBuf bytes.Buffer
    tw := tar.NewWriter(&tarBuf)
    const bombSize = 5 << 30 // 5GB of zeros
    hdr := &tar.Header{Name: "bomb.bin", Mode: 0600, Size: bombSize}
    require.NoError(t, tw.WriteHeader(hdr))
    zeroBuf := make([]byte, 1<<20)
    var written int64
    for written < bombSize {
        n, err := tw.Write(zeroBuf)
        require.NoError(t, err)
        written += int64(n)
    }
    require.NoError(t, tw.Close())

    var zstdBuf bytes.Buffer
    zw, err := zstd.NewWriter(&zstdBuf)
    require.NoError(t, err)
    _, err = zw.Write(tarBuf.Bytes())
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    // zstdBuf.Len() should be tiny (KBs) vs 5GB decompressed.
    require.Less(t, zstdBuf.Len(), 1<<20, "compressed archive should be small")

    dir := t.TempDir()
    ext, err := NewExtractor(bytes.NewReader(zstdBuf.Bytes()), int64(zstdBuf.Len()), dir)
    require.NoError(t, err)

    err = ext.Extract(context.Background())
    // EXPECTED (fixed behavior): extraction should fail once a size cap is
    // exceeded, e.g. errors.Is(err, limitwriter.ErrWriteLimitExceeded).
    require.Error(t, err, "extraction of an oversized decompressed payload must be rejected before writing all bytes to disk")

    fi, statErr := os.Stat(dir + "/bomb.bin")
    require.NoError(t, statErr)
    require.Less(t, fi.Size(), int64(bombSize), "extractor must not be allowed to write the full multi-GB payload to disk")
}

package limitwriter

import (
	"errors"
	"io"
)

var ErrWriteLimitExceeded = errors.New("write limit exceeded")

type limitWriter struct {
	w       io.Writer
	limit   int64
	written int64
}

func New(w io.Writer, n int64) io.Writer {
	return &limitWriter{w: w, limit: n}
}

func (w *limitWriter) Write(p []byte) (n int, err error) {
	capacity := w.limit - w.written
	if capacity <= 0 {
		return 0, io.ErrShortWrite
	}

	if int64(len(p)) > capacity {
		n, err = w.w.Write(p[:capacity])
		if err == nil {
			err = ErrWriteLimitExceeded
		}
	} else {
		n, err = w.w.Write(p)
	}

	if n < 0 {
		n = 0
	}
	w.written += int64(n)

	return n, err
}
