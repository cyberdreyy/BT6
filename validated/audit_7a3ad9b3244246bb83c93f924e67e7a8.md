### Title
`updateFileMetadata` re-resolves by path after file creation, allowing symlink-swap TOCTOU to redirect `chmod` (and best-effort `chown`) onto another file - ([File: commands/helpers/archive/tarzstd/tarzstd_extractor.go])

### Summary
`Extract` validates the destination `path` once (lexical containment check), creates the file via `os.Create`, closes the `*os.File`, and then calls `e.updateFileMetadata(path, hdr)`, which re-resolves the *same path string* through separate `lchtimes`/`lchmod`/`lchown` syscalls instead of operating on the already-open file descriptor. On Linux, `lchmod` intentionally omits `AT_SYMLINK_NOFOLLOW` for non-symlink entries (it's unsupported for `fchmodat` on Linux), so if the on-disk object at `path` is swapped for a symlink between `f.Close()` and the `Fchmodat` call, `chmod` follows the symlink and mutates the *target's* permission bits instead of the extracted file's.

### Finding Description
The relevant sequence is: [1](#0-0) 

`path` is validated once via a lexical prefix check against `e.dir`: [2](#0-1) 

then the file is created and written, closed, and `updateFileMetadata` is invoked by path string: [3](#0-2) 

`lchmod` on Linux does not set `AT_SYMLINK_NOFOLLOW` for non-symlink modes (because Linux `fchmodat` has no `AT_SYMLINK_NOFOLLOW` support), so it *follows* a symlink placed at `path`: [4](#0-3) 

If a concurrent process with write access to the same directory (e.g., a background process left running by a previous job sharing the same cache/build directory, or a colluding concurrent job on a shared executor host with a predictable/shared restore path) unlinks the just-created regular file and replaces it with a symlink pointing at an arbitrary file outside `e.dir` in the window between `f.Close()` (line 97-99) and the `lchmod` call inside `updateFileMetadata` (line 130-136), the subsequent `Fchmodat(AT_FDCWD, path, mode, 0)` call follows the symlink and applies `hdr.FileInfo().Mode()` (attacker-controlled via the tar header) to the symlink's target instead of the intended extracted file. `os.Lchown` and `unix.Lutimes` (used for ownership/time) are symlink-safe (`AT_SYMLINK_NOFOLLOW` semantics baked into the syscalls), so only the `chmod` step is affected, but that is sufficient to alter permission bits (e.g., add world-writable or setuid bits) on a file the attacker does not otherwise control, entirely outside the intended `e.dir` root — violating the stated invariant that validation and final write must be bound to the same real path.

Existing checks are insufficient because the containment check at lines 62-64 is purely lexical (string-prefix check on the computed `path`), performed once before creation, and never re-verified against the real filesystem object right before the metadata syscalls run. There is no `fchmod`-on-fd usage (which would have been immune to the swap since it targets the already-open descriptor) — the code reopens by path name instead.

### Impact Explanation
An attacker who can win the narrow race window can force the runner process to `chmod` an arbitrary file outside the extraction root to an attacker-chosen mode taken from the tar header (e.g., world-writable, setuid/setgid bits, or removal of read/execute permissions on a critical file), causing a permission-bit trusted-file overwrite. This does not allow full content overwrite (content writes are done via `io.Copy` inside `os.Create`'s fd before the race window opens), and it does not affect `chown`/`chtimes` since those syscalls are symlink-safe.

### Likelihood Explanation
The race window is very small (between `f.Close()` and the `lchmod` syscall for the same tar entry) and requires an attacker-controlled concurrent process with write access to the exact same target path at the exact right moment — this generally requires a shared, predictable extraction directory across job executions (e.g., project-scoped cache directories reused between pipeline runs) plus a tight retry loop to win the race reliably. It is not exploitable purely via crafted archive contents in a single sequential extraction pass, since nothing else executes on that path between creation and metadata update within the same process. Feasibility is real but low, and repeatable only with looped racing attempts and a favorably shared/predictable path.

### Recommendation
Perform metadata operations using the already-open file descriptor (`f`) returned by `os.Create` (e.g., `f.Chmod(mode)`, `f.Chown(uid, gid)`, and an fd-based time-setting syscall) before closing it, rather than reopening by path string in `updateFileMetadata`. If a path-based fallback is required (e.g., for symlinks/dirs in the deferred pass), verify the target inode/device identity (e.g., via `os.Lstat` immediately before and comparing device/inode, or opening with `O_NOFOLLOW`) right before the metadata syscalls to detect a swap and abort.

### Proof of Concept
Go integration test plan:
1. Extract a crafted tar+zstd archive containing one regular file entry `foo` with a distinctive mode (e.g., `0644`).
2. Instrument/hook (or use a `time.Sleep` injected via a test build tag, or run the real code under `strace`/ptrace-free harness) to, immediately after `f.Close()` but before `updateFileMetadata` runs, have a separate goroutine/process: `os.Remove(dir+"/foo")` then `os.Symlink("/tmp/victim", dir+"/foo")`.
3. Create `/tmp/victim` beforehand with mode `0600`.
4. After extraction completes, assert `os.Lstat(dir+"/foo")` returns a symlink (proving the swap succeeded) and assert `os.Stat("/tmp/victim").Mode()` now equals the attacker-controlled mode from the tar header (e.g., `0644` or `04755`) instead of its original `0600`, proving the chmod followed the symlink onto the victim file outside the intended extraction root.

```go
func (e *extractor) updateFileMetadata(path string, hdr *tar.Header) error {
	fi := hdr.FileInfo()

	if err := lchtimes(path, fi.Mode(), time.Now(), fi.ModTime()); err != nil {
		return err
	}

	if err := lchmod(path, fi.Mode()); err != nil {
		return err
	}

	_ = lchown(path, hdr.Uid, hdr.Gid)
	return nil
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int
	if runtime.GOOS == "linux" {
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}

	return nil
}
```
