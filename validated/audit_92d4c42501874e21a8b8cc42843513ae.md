### Title
Missing protocol-pause check on `lending_account_close_balance` allows state mutation during emergency pause - (File: `programs/marginfi/src/instructions/marginfi_account/close_balance.rs`)

### Summary
Every user-facing `MarginfiAccount` instruction gates on the global emergency pause via a `constraint = (!group.load()?.is_protocol_paused()) @ MarginfiError::ProtocolPaused` on the `group` account in its `Accounts` struct — confirmed present in `LendingAccountDeposit`/`LendingAccountBorrow`/`LendingAccountWithdraw`/`LendingAccountRepay`/`LendingAccountLiquidate` (`grep` matches in each file) and explicitly visible in `PlaceOrder`, `StartExecuteOrder`, and `EndExecuteOrder` in `programs/marginfi/src/instructions/marginfi_account/order.rs:515,662,728`. `LendingAccountCloseBalance`, defined in `programs/marginfi/src/instructions/marginfi_account/close_balance.rs:59-87`, has no such constraint on its `group: AccountLoader<'info, MarginfiGroup>` field, and `grep` for `ProtocolPaused`/`is_protocol_paused` in that file returns zero matches.

### Finding Description
`lending_account_close_balance` (`close_balance.rs:19-57`) closes out a zero/dust balance on a user's lending account via `bank_account.close_balance(in_receivership)` and updates `bank.update_bank_cache(group)`. This mutates on-chain accounting state (`BankAccountWrapper::close_balance`, `LendingAccount::sort_balances`, `MarginfiAccount::sync_indexer_flags`) exactly like deposit/withdraw/borrow/repay do, yet its `Accounts` struct (`close_balance.rs:59-87`) omits the `is_protocol_paused()` guard that all analogous instructions apply. This is directly analogous to the reported bug class: two sibling entry points (`bridgeMessage`/`bridgeMessageWETH`) omitted a modifier (`ifNotEmergencyState`) that the primary sibling (`bridgeAsset`) enforced, so the emergency pause did not uniformly halt state-changing operations. Here, `lending_account_close_balance` is the outlier missing the pause gate that `deposit`/`withdraw`/`borrow`/`repay`/`liquidate`/`order` all enforce.

### Impact Explanation
When `global_fee_admin`/`pause_delegate_admin` invokes `panic_pause` in response to a discovered soundness bug or ongoing exploit (per `guides/ADMIN/PERMISSIONS_AND_ROLES.md:147-159`, which explicitly states deposit/borrow/withdraw/repay and liquidation are "blocked while paused"), `lending_account_close_balance` remains callable. This lets any account holder continue to close out balances (mutate `lending_account.balances`, invoke `bank_account.close_balance`, and refresh `bank.update_bank_cache`) during the pause window meant to freeze the protocol while an incident is investigated — undermining the safety guarantee the pause is designed to provide, and potentially interacting with account state in ways the incident responders assumed were frozen (e.g., clearing balances an admin is relying on being intact for forced deleverage/bankruptcy resolution).

### Likelihood Explanation
High reachability: `lending_account_close_balance` is a standard permissionless instruction reachable by any account authority with a signer, requiring only an existing `MarginfiAccount` and `Bank`; no special privilege is needed, and it is trivially triggerable during any active pause simply by calling it normally.

### Recommendation
Add the same constraint used elsewhere to `LendingAccountCloseBalance`'s `group` account in `close_balance.rs`:
```rust
#[account(
    constraint = (!group.load()?.is_protocol_paused()) @ MarginfiError::ProtocolPaused
)]
pub group: AccountLoader<'info, MarginfiGroup>,
```
matching the pattern in `order.rs:515`, and in `deposit.rs`/`withdraw.rs`/`borrow.rs`/`repay.rs`/`liquidate.rs`.

1. Admin calls `panic_pause` (`programs/marginfi/src/instructions/marginfi_group/panic_pause.rs:7`), then `try_propagate_fee_state` so `MarginfiGroup.panic_state_cache.is_paused_flag()` is true (test pattern shown in `programs/marginfi/tests/admin_actions/actions_during_pause.rs:142-150` for withdraw).

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
