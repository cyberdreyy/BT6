**Analysis:** `distribute` is intentionally permissionless — the doc comment states "Allow anyone to distribute already unlocked funds. This does not affect reward compounding and therefore does not need to be restricted to just the staker or operator." [1](#0-0) 

The claimed exploit requires the caller to redirect funds to themselves or corrupt the recipient set, but `distribute_internal`'s loop pays out based on the `distribution_pool`'s recorded shareholders and shares, and looks up `beneficiary_for_operator(operator)` fresh at payout time only when the shareholder being redeemed is `operator` itself: [2](#0-1) 

This means:
- The set of shareholders and their share amounts come entirely from prior `add_distribution`/`update_distribution_pool` calls tied to real staker/operator actions (unlock, commission requests), not from the caller of `distribute`.
- Coins for the operator's commission share are always sent to whatever `beneficiary_for_operator(operator)` currently resolves to — i.e., the correctly registered beneficiary — never to the unrelated caller who invoked `distribute`. [3](#0-2) 
- The unrelated third party calling `distribute` gains no funds: `aptos_account::deposit_coins` sends to `recipient`, which is derived from the pool's own shareholder records, not the transaction sender.

The documentation for `set_beneficiary_for_operator` explicitly acknowledges this permissionless-distribute semantics and advises calling `distribute` *before* switching the beneficiary if you want the old beneficiary paid — this is documented, intended behavior, not an exploitable ordering bug: [4](#0-3) 

The proof-of-concept idea itself ("assert coins land only at the currently registered beneficiary and never at the caller") describes exactly the code's correct, intended behavior rather than a violation of it. No unprivileged caller can redirect value to themselves or to any address other than the legitimate, currently-registered beneficiary or the pool's own recorded shareholders.

    /// Allow anyone to distribute already unlocked funds. This does not affect reward compounding and therefore does
    /// not need to be restricted to just the staker or operator.
    public entry fun distribute(
        staker: address, operator: address
    ) acquires Store, BeneficiaryForOperator {
        assert_staking_contract_exists(staker, operator);
        let store = borrow_global_mut<Store>(staker);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);
        distribute_internal(
            staker,
            operator,
            staking_contract,
        );
    }
