### Title
Mint decimals/authority misreported for token accounts whose mint is not owned by a real token program - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`get_additional_mint_data` unconditionally attempts to unpack any account's raw bytes as an `spl_token_2022_interface::state::Mint` via `StateWithExtensions::<Mint>::unpack`, without ever checking that the account is owned by `spl_token_interface::id()` or `spl_token_2022_interface::id()` [1](#0-0) . `get_mint_owner_and_additional_data` fetches whatever account exists at the `mint` pubkey and passes its data straight into this function before returning success, again with no owner gating [2](#0-1) .

### Finding Description
`get_parsed_token_account` and `get_parsed_token_accounts` derive the mint pubkey from the token account's raw data via `get_token_account_mint`, fetch that mint account from the bank/overwrites, and feed its bytes into `get_additional_mint_data`/`get_mint_owner_and_additional_data` with no check that the mint account's `owner()` is a real SPL token program before trusting the unpacked `decimals`, `mint_authority`-derived extension config, etc. [3](#0-2) [4](#0-3) .

SPL Token's on-chain `InitializeAccount`/`InitializeAccount2/3` historically does not enforce that the referenced mint account is owned by the token program at instruction time (this is the well-known "fake-mint" pattern already exploited against wallets/exchanges in the wild). An attacker can therefore, as an unprivileged client:
1. Write/deploy an account (e.g. under `bpf_loader_upgradeable` or any other non-token owner) whose byte layout happens to unpack successfully as a `Mint` struct (trivial: a `Mint` is a small fixed packed layout, so any account with a controlled data buffer of the right size/values will unpack).
2. Create a genuine SPL Token token account (real owner = `spl_token::id()`) whose `mint` field points at that fake-mint account.
3. Query it via `getTokenAccountBalance` / `getTokenAccountsByOwner` (jsonParsed) / other paths that route through `get_parsed_token_account(s)`.

Because `get_additional_mint_data` only calls `StateWithExtensions::<Mint>::unpack(data)` and never checks `mint_account.owner()` against `is_known_spl_token_id`, the RPC will happily report `decimals` (and any extension-derived UI scaling such as `InterestBearingConfig`/`ScaledUiAmountConfig`) sourced from an account that is not actually controlled by any token program. This violates the stated invariant that "parsed output belongs to the requested key/program."

### Impact Explanation
This causes `getTokenAccountBalance`/parsed-account RPC responses to report attacker-controlled `decimals` and mint-authority-adjacent extension data for a mint that isn't a real token-program account, which downstream integrators (wallets, exchanges, explorers) rely on to compute UI balances. Corresponds to the "wrong account data returned" bounty category — data integrity/misreporting, not a crash or consensus issue.

### Likelihood Explanation
Fully attacker-controlled and requires only ordinary account creation transactions plus a single read-only RPC call, matching the unprivileged single-client threat model; no special validator access or elevated privileges are needed and the exploit is deterministically reproducible.

### Recommendation
In `get_mint_owner_and_additional_data`/`get_additional_mint_data`, verify the mint account's owner against `spl_generic_token::is_known_spl_token_id` (or explicitly `spl_token_interface::id()` / `spl_token_2022_interface::id()`) before unpacking and trusting its bytes as a `Mint`, and propagate/enforce this check consistently in all callers (`get_parsed_token_account`, `get_parsed_token_accounts`, and any RPC handler using these helpers), not only at the top-level token-account-owner check.

### Proof of Concept
Integration test in `rpc/src/parsed_token_accounts.rs`:
```rust
#[test]
fn test_fake_mint_owner_not_validated() {
    // Build a Mint-shaped byte buffer with decimals = 9, mint_authority = attacker pubkey.
    let mut mint_data = vec![0; Mint::get_packed_len()];
    let mint = Mint { decimals: 9, is_initialized: true, ..Default::default() };
    Mint::pack(mint, &mut mint_data).unwrap();

    // Store this account under bpf_loader_upgradeable::id() (NOT a token program) in the bank.
    let bank = create_test_bank();
    let fake_mint_pubkey = Pubkey::new_unique();
    let mut account = AccountSharedData::new(1, mint_data.len(), &bpf_loader_upgradeable::id());
    account.set_data(mint_data);
    bank.store_account(&fake_mint_pubkey, &account);

    // Call get_mint_owner_and_additional_data directly.
    let result = get_mint_owner_and_additional_data(&bank, &fake_mint_pubkey);

    // Expected (fixed) behavior: Err, since owner is not a known SPL token id.
    // Actual (buggy) behavior: Ok((bpf_loader_upgradeable::id(), data_with_decimals_9)).
    assert!(result.is_err(), "mint owned by non-token program must not be trusted");
}
```
Additional end-to-end test: create a genuine `spl_token::id()`-owned token account whose `mint` field is `fake_mint_pubkey`, call `get_parsed_token_account`, and assert the returned `UiAccount` JSON does not surface decimals sourced from `fake_mint_pubkey` unless its owner is verified as a real token program.

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
