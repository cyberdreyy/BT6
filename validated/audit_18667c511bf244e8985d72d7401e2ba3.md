### Title
`MetaOracle` staleness check never validates against current clock time — (`File: crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

### Summary

The Sui oracle framework (`crates/sui-oracle`) contains two compounding staleness-check failures in `meta_oracle.move`. The `combine` function computes its freshness window relative to the last-added oracle's own timestamp rather than the current on-chain clock, so if every oracle feed is simultaneously stale the check passes unconditionally. Additionally, `add_simple_oracle` overwrites `max_timestamp` with each successive oracle's timestamp instead of tracking the true maximum, making the window anchor even less reliable.

### Finding Description

**`simple_oracle::get_latest_data`** (the primitive read path) returns whatever `StoredData` is on-chain with no age check at all:

```move
// simple_oracle.move L51-58
public fun get_latest_data<T: store + copy>(oracle: &SimpleOracle, ticker: String): Option<Data<T>> {
    if (!df::exists_(&oracle.id, ticker)) { return option::none() };
    let data: &StoredData<T> = df::borrow(&oracle.id, ticker);
    let StoredData { value, sequence_number, timestamp, identifier } = *data;
    option::some(data::new(value, ticker, sequence_number, timestamp, oracle.address, identifier))
}
``` [1](#0-0) 

No `Clock` is passed; no age comparison is performed.

**`meta_oracle::add_simple_oracle`** is supposed to track the freshest timestamp seen, but it unconditionally overwrites `max_timestamp` with each oracle's value instead of taking the maximum:

```move
// meta_oracle.move L38-44
public fun add_simple_oracle<T: copy + drop + store>(meta_oracle: &mut MetaOracle<T>, oracle: &SimpleOracle) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));  // overwrites, not max()
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
``` [2](#0-1) 

**`meta_oracle::combine`** then derives its freshness floor from that corrupted `max_timestamp` — never from `sui::clock::Clock`:

```move
// meta_oracle.move L51-68
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>): (vector<T>, vector<address>) {
    let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
    let min_timestamp = max_timestamp - time_window_ms;   // ← no Clock, no current time
    ...
    if (data::timestamp(&oracle_data) > min_timestamp) { ... }
``` [3](#0-2) 

The `MetaOracle` struct carries `time_window_ms` and `max_timestamp` but has no `Clock` field and no `Clock` parameter anywhere in its public API (`new`, `add_simple_oracle`, `median`): [4](#0-3) 

### Impact Explanation

Any on-chain contract that calls `meta_oracle::median` (or `simple_oracle::get_latest_data` directly) to price assets, compute collateral ratios, or settle positions will silently consume arbitrarily old prices. If oracle operators stop submitting updates — due to network congestion, downtime, or deliberate griefing — the framework returns the last stored value with no revert, no error, and no indication of staleness. A user can exploit the gap between the stale on-chain price and the true market price to extract value (e.g., borrow against over-valued collateral, liquidate under-valued positions). This matches the "harmful smart-contract behavior" class in the High/Medium impact tier.

### Likelihood Explanation

The `simple_oracle::submit_data` entry point is restricted to the oracle's registered address, so an attacker cannot inject a fake price. However, the attacker does not need to. They only need to wait for a period of natural oracle inactivity (network congestion, operator downtime) and then interact with any protocol that consumes the oracle. The `MetaOracle` API is fully public and callable by any ordinary SUI holder in a PTB. [5](#0-4) 

### Recommendation

1. Pass `&Clock` into `add_simple_oracle` (or `median`) and compare each oracle's timestamp against `clock::timestamp_ms(clock)` rather than against `max_timestamp`.
2. Fix `add_simple_oracle` to track the true maximum: `meta_oracle.max_timestamp = max(meta_oracle.max_timestamp, data::timestamp(...))`.
3. Abort in `combine` if `max_timestamp` itself is older than `time_window_ms` relative to the current clock.

### Proof of Concept

```move
// Attacker PTB (pseudocode)
// 1. Oracle operator goes offline; SimpleOracle still holds a price from T-2h.
// 2. Attacker constructs a MetaOracle with time_window_ms = 3_600_000 (1 h).
let mut meta = meta_oracle::new<DecimalValue>(1, 3_600_000, utf8(b"SUIUSD"));
// 3. add_simple_oracle reads the 2-hour-old price; max_timestamp = T-2h.
meta_oracle::add_simple_oracle(&mut meta, stale_oracle);
// 4. combine: min_timestamp = (T-2h) - 1h = T-3h.
//    The 2-hour-old data satisfies timestamp > T-3h → passes.
// 5. median() returns the stale price with no error.
let trusted = meta_oracle::median(meta);
// 6. Downstream protocol uses trusted price to mint/borrow/liquidate.
```

The `combine` check `data::timestamp(&oracle_data) > min_timestamp` passes because `min_timestamp` is anchored to the stale oracle's own timestamp, not to the present moment. No privileged access is required; any caller can trigger this in a single PTB. [6](#0-5)

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
