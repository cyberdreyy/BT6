### Title
`get_additional_mint_data` accepts Mint-shaped data from any account regardless of owning program - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`get_additional_mint_data` and `get_mint_owner_and_additional_data` in `rpc/src/parsed_token_accounts.rs` unpack a referenced mint account's raw bytes with `StateWithExtensions::<Mint>::unpack` and derive `decimals`, `interest_bearing_config`, and `scaled_ui_amount_config` from it without ever verifying that the account is owned by `spl_token_interface::id()` or `spl_token_2022_interface::id()`. Any account whose bytes happen to unpack as a valid `Mint` layout is trusted, even if its actual on-chain owner is an unrelated program such as `system_program`.

### Finding Description
`get_parsed_token_account` resolves the mint pubkey purely from the token account's raw `mint` field via `get_token_account_mint(account.data())`, then fetches that pubkey's account with `account_resolver::get_account_from_overwrites_or_bank` [1](#0-0)  and immediately passes its `data()` to `get_additional_mint_data`, without inspecting `mint_account.owner()`.

`get_additional_mint_data` itself performs no owner check at all — it only calls `StateWithExtensions::<Mint>::unpack(data)` and, on success, extracts `decimals`, `InterestBearingConfig`, and `ScaledUiAmountConfig` directly into `SplTokenAdditionalDataV2`: [2](#0-1) 

`get_mint_owner_and_additional_data`, used by `get_parsed_token_accounts` for batch `jsonParsed` decoding, has the same gap: it fetches `bank.get_account(mint)` and calls `get_additional_mint_data(bank, mint_account.data())`, returning `*mint_account.owner()` alongside the trusted decimal/extension data without validating that owner is a genuine token program id first: [3](#0-2) 

Because `get_parsed_token_account` (used on the `simulateTransaction` overwrite path via `overwrite_accounts`) derives the "mint" pubkey entirely from attacker-controlled token-account bytes, an attacker in a single `simulateTransaction` call with account overrides can point the `mint` field at an arbitrary address holding a `Mint::pack()`-shaped buffer whose real owner is not a token program (e.g. `system_program::id()`). The unpack succeeds because `StateWithExtensions::<Mint>::unpack` only checks byte layout, not the account owner, so `get_additional_mint_data` returns attacker-chosen `decimals`/extension configs as if legitimate.

### Impact Explanation
This directly causes misreported `UiTokenAmount.decimals`/`ui_amount` (and mint authority/extension) fields in `jsonParsed` RPC responses for `getAccountInfo`, `getTokenAccountBalance`, and `getTokenSupply`-style flows, sourced from an account that was never validated as a real SPL token/Token-2022 mint. This matches the scoped impact: "An unprivileged attacker can decode instruction or token data into an incorrect but plausible parsed result, misreporting program, authority, amount, decimals, or token owner to downstream integrators."

### Likelihood Explanation
The precondition only requires one `simulateTransaction` call with account overwrites (a normal, unprivileged RPC feature) supplying a `Mint::pack()`-shaped buffer at an address not owned by a token program, then a `getAccountInfo(jsonParsed)` on the associated token account. No elevated privileges, validator control, or multiple calls are needed, making this readily reproducible.

### Recommendation
In `get_additional_mint_data` (or its callers `get_parsed_token_account` / `get_mint_owner_and_additional_data`), validate that the mint account's owner equals `spl_token_interface::id()` or `spl_token_2022_interface::id()` (e.g., via `spl_generic_token::is_known_spl_token_id`) before unpacking and trusting its `Mint` extension data; return an error otherwise.

```rust
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}
```

```rust
fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
```
