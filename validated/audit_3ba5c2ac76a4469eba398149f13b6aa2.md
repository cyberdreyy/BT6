### Title
`store_and_process_block_signature` tallies peer signatures toward the group-signing threshold without checking `block_info.valid` - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` (reached via `handle_block_signature`, which handles a `BlockAccepted` gossip message from another signer) stores an incoming peer signature and, once the accumulated weight crosses the 70% threshold, calls `mark_locally_accepted` and broadcasts the block to the node. Unlike every other path that leads to a signature/acceptance decision, it never checks `block_info.valid` (or re-runs `check_block_against_signer_db_state`) before doing so.

### Finding Description
Two sibling code paths exist for counting toward the 70%-weight signature threshold:

- `handle_block_pre_commit` explicitly gates on validity before it will let a pre-commit progress toward a signature: [1](#0-0) 
It also re-runs `check_block_against_signer_db_state` right before actually signing.

- `handle_block_validate_ok`/pre-commit and re-proposal logic (`determine_response`, `should_reevaluate_block`) all gate their responses on `block_info.valid` being `Some(true)`: [2](#0-1) 

By contrast, `handle_block_signature` only checks that the recovered public key belongs to a legitimate signer (`is_valid_signer`) — it never inspects `block_info.valid`: [3](#0-2) 

It then unconditionally calls `store_and_process_block_signature`, which stores the signature, tallies `total_signature_weight` from all stored signatures, and — once `total_signature_weight >= min_weight` — calls `block_info.mark_locally_accepted(true)` and `broadcast_signed_block`, all without ever consulting `block_info.valid` or re-running `check_block_against_signer_db_state`: [4](#0-3) 

This is the same bug class as the report: a "read/aggregation" path (`getRewardsAmount` counting all epochs without excluding claimed ones) diverges from the "write" path (`claimRewards` which does check). Here, the signature-tallying/broadcast path diverges from the sibling pre-commit/validation paths that do gate on validity, meaning a locally-unvalidated or locally-rejected block's signature count can still be advanced and even pushed toward acceptance purely from peer gossip.

### Impact Explanation
If this signer's own validation of the block is still pending (`block_info.valid == None`, e.g. `Unprocessed`/before `check_submitted_block_proposal` resolves) or the block was already locally rejected (`block_info.valid == Some(false)`), peer `BlockAccepted` gossip messages are still accepted, stored, and tallied toward the 70% threshold. If enough peer signatures (potentially from a byzantine/faulty minority combined with normal gossip replay) arrive before or despite this signer's own negative verdict, `mark_locally_accepted` fires and `broadcast_signed_block` is invoked, pushing a block this signer never validated as canonical/valid to the node. This is a potential root-cause for a rejection-vs-acceptance mismatch or a signer helping push an invalid/non-canonical block, matching the "Critical" impact bucket (signature/acceptance divorced from this signer's own validity determination).

### Likelihood Explanation
Reachable purely via normal StackerDB gossip replay of `BlockResponse::Accepted` messages from other signers (a single miner-controlled tenure with normal signer participation can produce this timing window, e.g. between proposal arrival and validation-response processing, or after this signer locally rejects but peers still gossip their acceptances). No majority compromise or key access is required — only the ordering/timing of message delivery, which the report explicitly allows as an "analog miner + gossip" trigger.

### Recommendation
Add the same guard used in `handle_block_pre_commit` to `store_and_process_block_signature`/`handle_block_signature`: bail out (or defer) unless `block_info.valid == Some(true)`, and re-run `check_block_against_signer_db_state` before calling `mark_locally_accepted`/`broadcast_signed_block`, mirroring the recheck performed in the pre-commit and validate-ok paths.

### Proof of Concept
1. A block proposal `B` is stored (`Unprocessed`) but this signer's own validation has not yet returned (`block_info.valid == None`), or the validation has returned `Reject` (`block_info.valid == Some(false)`).
2. Other signers broadcast `BlockResponse::Accepted` for `B` (either honestly racing, or replayed/gossiped).
3. `handle_block_signature` → `store_and_process_block_signature` accepts each of these, since it only checks `is_valid_signer` on the sender, never `block_info.valid`.
4. Once accumulated weight from these stored signatures reaches the ≥70% threshold, `mark_locally_accepted(true)` is called and `broadcast_signed_block` pushes the block to the node — even though this signer itself never determined the block valid.

Note: I was not able to fully verify, within the available tool budget, whether `BlockInfo::check_state`/`move_to` (in `stacks-signer/src/signerdb.rs`) would reject the `Unprocessed → LocallyAccepted` transition at the state-machine level (which could turn `mark_locally_accepted` into a no-op/error in the `Unprocessed` case) — I could not retrieve that function's body before running out of search iterations. The `Some(false)` (locally-rejected) case, however, is confirmed reachable per the state diagram (`LocallyRejected → LocallyAccepted` is an explicitly allowed "re-evaluated" transition), so the missing-validity-check path is real regardless of the `Unprocessed` sub-case. A Devin session with full file access should confirm `check_state`'s exact transition table to pin down both sub-cases precisely.

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }
