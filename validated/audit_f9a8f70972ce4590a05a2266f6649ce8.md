### Title
`max_timestamp` Overwritten Instead of Accumulated in `add_simple_oracle` — (`crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

In `meta_oracle.move`, the `add_simple_oracle` function unconditionally overwrites `max_timestamp` with each oracle's timestamp instead of accumulating the running maximum. The downstream `combine` function anchors the freshness time-window to this corrupted value, so when oracles are added in non-monotonically-increasing timestamp order the window is shifted: stale data passes the filter, or valid data is excluded and the threshold assertion aborts.

---

### Finding Description

`MetaOracle` tracks a `max_timestamp` field that is supposed to represent the highest timestamp seen across all added oracles. `combine` uses it to compute the lower bound of the freshness window:

```
min_timestamp = max_timestamp - time_window_ms
```

Only oracle readings with `timestamp > min_timestamp` are included in the median.

The bug is in `add_simple_oracle` (lines 38–44):

```move
public fun add_simple_oracle<T: copy + drop + store>(
    meta_oracle: &mut MetaOracle<T>,
    oracle: &SimpleOracle
) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        // BUG: unconditional assignment — overwrites instead of max()
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
```

After all oracles are added, `max_timestamp` holds only the **last** oracle's timestamp, not the true maximum. This is structurally identical to the `PolicyLib.sol` bug in the external report, where `vd = ValidationData.wrap(validationDataFromPolicy)` overwrites the accumulated result instead of intersecting it.

The `combine` function then uses the corrupted value:

```move
fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>): (vector<T>, vector<address>) {
    let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
    let min_timestamp = max_timestamp - time_window_ms;   // anchored to wrong point in time
    ...
    if (data::timestamp(&oracle_data) > min_timestamp) {  // filter uses wrong bound
        vector::push_back(&mut values, *data::value(&oracle_data));
    };
    assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
}

### Impact Explanation

Two concrete failure modes arise from public input:

**1. Stale-data inclusion (price manipulation)**
Add oracles in decreasing timestamp order so the last oracle has the oldest timestamp. `max_timestamp` is set to the minimum, making `min_timestamp` very low. All oracle readings—including those far outside the intended freshness window—pass the filter. The median is computed over stale data, producing a price that diverges from the true market price. Any DeFi protocol consuming this oracle can be exploited via the manipulated price.

**2. Valid-data exclusion / functional DoS**
Add oracles in increasing timestamp order so the last oracle has the newest timestamp. `max_timestamp` is set to that newest value. `min_timestamp` is then anchored so high that readings from earlier oracles—which are within the intended window relative to the true maximum—are excluded. If enough valid readings are dropped, `vector::length(&values) < threshold` and the `assert!` aborts the transaction, DoS-ing any protocol that depends on the oracle call completing.

Both modes are reachable because `add_simple_oracle` is `public` and the caller controls the order of invocations. [3](#0-2) [4](#0-3) 

---

### Likelihood Explanation

`add_simple_oracle` is a `public` function; any Move caller can invoke it in any order. The `MetaOracle` struct has no `key` or `store` abilities, so it is a hot-potato consumed within a single transaction—the caller fully controls the sequence of oracle additions. No privileged role is required. Even without adversarial intent, the bug fires whenever a protocol adds oracles in non-monotonically-increasing timestamp order, which is a normal operational scenario (e.g., iterating over a `VecMap` whose insertion order differs from timestamp order). ### Recommendation

Replace the unconditional assignment with a conditional maximum:

```move
public fun add_simple_oracle<T: copy + drop + store>(
    meta_oracle: &mut MetaOracle<T>,
    oracle: &SimpleOracle
) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        let ts = data::timestamp(option::borrow(&oracle_data));
        if (ts > meta_oracle.max_timestamp) {
            meta_oracle.max_timestamp = ts;
        };
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
```

This mirrors the correct fix for the `PolicyLib.sol` bug: accumulate across the loop rather than overwrite.

### Proof of Concept

Setup: `MetaOracle<u64>` with `threshold = 2`, `time_window_ms = 500`.

| Step | Action | `max_timestamp` after |
|------|--------|-----------------------|
| 1 | `add_simple_oracle(oracle_A)` — oracle A has timestamp **2000** | 2000 |
| 2 | `add_simple_oracle(oracle_B)` — oracle B has timestamp **300** | **300** ← overwritten |

After step 2, `max_timestamp = 300` (wrong; should be 2000).

`combine` computes `min_timestamp = 300 - 500`. Since `300 < 500` this is a **u64 underflow**, which aborts the transaction in Move — a functional DoS triggered by any caller who adds a newer oracle before an older one.

Alternatively, with `time_window_ms = 100`:
- `min_timestamp = 300 - 100 = 200`
- Oracle A (timestamp 2000): `2000 > 200` → **passes** (should be excluded; it is 1700 ms newer than the anchor, but the window `[200, 300]` is wrong)
- Oracle B (timestamp 300): `300 > 200` → **passes**
- Median is computed over both, but the intended window `[1500, 2000]` (anchored to oracle A) would have excluded oracle B's stale reading

Result: stale oracle B data is included in the median, producing an incorrect aggregated price. [1](#0-0) [2](#0-1)

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
