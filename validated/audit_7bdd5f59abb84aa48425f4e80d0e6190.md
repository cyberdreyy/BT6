### Title
Cold/uncached vault master public key causes owner-label validation bypass on `CreateSecrets`/`UpdateSecrets` requests - (File: core/capabilities/vault/gateway_vault_request_processor.go)

### Summary
The Nibiru report's root cause is a shared, lazily-populated pointer (`StateDB`) whose mere presence/absence (`nil` check) silently changes security-relevant program flow for a request that never explicitly set it. The Chainlink Vault gateway handler has the same structural pattern: a shared, asynchronously-populated `*tdh2easy.PublicKey` cache on the handler is used to decide, via a `nil` check, whether to run strict owner-label validation on secrets a client submits, or to skip it.

### Finding Description
`handler.getCachedPublicKey()` reads a cache (`cachedPublicKeyGetResponse` / `cachedPublicKeyObject`) that is populated asynchronously — either by a background 1-minute ticker (`fetchVaultPublicKey`) or opportunistically when any node's `MethodPublicKeyGet` response arrives (`tryCachePublicKeyResponse`): [1](#0-0) [2](#0-1) [3](#0-2) 

When an unprivileged client submits `secrets_create`/`secrets_update`, the handler fetches the (possibly still-`nil`) cached key and passes it straight into the shared request processor: [4](#0-3) [5](#0-4) 

Inside `GatewayVaultRequestProcessor.processCreateSecretsRequest`/`processUpdateSecretsRequest`, the presence or absence of that pointer directly toggles which validation routine executes: [6](#0-5) [7](#0-6) 

And in `RequestValidator.validateWriteRequest`, `skipLabelValidation` selects between two materially different checks: `verifyEncryptedSecret(publicKey, req.EncryptedValue)` (structural/decryptability only) versus `EnsureRightLabelOnSecret(publicKey, req.EncryptedValue, req.Id.Owner)` (verifies the ciphertext's embedded label actually matches the claimed `Owner`): [8](#0-7) 

This is functionally identical to the Nibiru bug class: a background/async-populated shared pointer's `nil`-ness (not the actual request content) determines whether an important security check (owner-label binding) runs at all, and that pointer's state depends on unrelated prior traffic/timing (gateway restart, key rotation, or a race before the first successful `fetchVaultPublicKey`/node response), not on anything the requesting client controls or can be held accountable for.

### Impact Explanation
While the cache is cold (gateway just started, restarted, or the periodic 1-minute refresh/first node response hasn't landed yet), any unprivileged client's `secrets_create`/`secrets_update` request is validated with `skipLabelValidation=true`, meaning `EnsureRightLabelOnSecret` — the check that ties the ciphertext's cryptographic label to the declared `Id.Owner` — is skipped entirely in favor of a weaker structural check. This can allow a client to submit an `EncryptedSecret` whose ciphertext label does not correspond to the `Owner` it declares, i.e., an owner/label-binding bypass at the gateway layer, which is precisely the kind of "cross-user response/data confusion" and "quota/authorization bypass" class called out as in-scope. This is a real code-path divergence, not a purely theoretical race — it is deterministic on cache state, and cache state is not caller-controlled and can be forced cold by any deployment event (redeploy, key rotation, gateway crash-restart) or exploited during the startup window.

### Likelihood Explanation
Requires the request to arrive while `cachedPublicKeyObject` is `nil`, i.e., before the first successful `fetchVaultPublicKey` tick or `MethodPublicKeyGet` node response is cached. This is most likely: (a) immediately after gateway process start/restart, (b) if the vault-node cluster is transiently unreachable so `fetchVaultPublicKey` keeps failing (`h.lggr.Errorw("fetchVaultPublicKey: failed to fetch...")` path), extending the cold-cache window indefinitely. An attacker able to observe or predict a gateway restart (deploys are often externally observable via latency/availability signals) or racing at startup could target this window with `secrets_create`/`secrets_update` requests. I was not able to fully inspect the bodies of `EnsureRightLabelOnSecret` and `verifyEncryptedSecret` (their exact validation semantics are only partially visible from my searches — signature difference is clear, but the precise downstream consequence of skipping label validation, e.g., whether node-side re-validation independently blocks the bypass, could not be confirmed with the available index).

### Recommendation
- Do not silently downgrade security validation based on cache availability. If the master public key is unavailable, fail closed (reject `secrets_create`/`secrets_update` with a retryable error) rather than calling `validateWriteRequest` with `skipLabelValidation=true`.
- Alternatively, block/queue write requests until the public key is confirmed available (bounded wait with timeout), rather than passing a `nil` sentinel that changes which validator runs.
- Verify that node-side processing independently and unconditionally re-enforces owner-label binding (`EnsureRightLabelOnSecret`) regardless of what the gateway did, so the gateway is defense-in-depth only, not the sole enforcement point.
- Add metrics/alerts specifically for `skipLabelValidation=true` occurrences on write paths so any relaxed-validation window is observable in production.

### Proof of Concept
1. Restart (or newly start) a Vault gateway handler; `cachedPublicKeyObject` is `nil` and `fetchVaultPublicKey` has not yet completed its first successful tick (`core/services/gateway/handlers/vault/handler.go:279-308`).
2. As soon as the gateway is reachable, send a `secrets_create` JSON-RPC request whose `EncryptedSecrets[i].Id.Owner` does not match the actual label embedded in `EncryptedValue`.
3. `HandleJSONRPCUserMessage` → `getCachedPublicKey()` returns `(nil, nil)` (`handler.go:435`), so `ProcessRequest` is called with `publicKey=nil` (`handler.go:436`).
4. `processCreateSecretsRequest` computes `skipLabelValidation := publicKey == nil // true` (`gateway_vault_request_processor.go:110`), and `validateWriteRequest` runs `verifyEncryptedSecret` instead of `EnsureRightLabelOnSecret` (`validator.go:75-84`), skipping the owner/label binding check.
5. The malformed request is authorized/forwarded to Vault nodes rather than being rejected at the gateway for label mismatch — a window that would not exist if the cache were already warm. [9](#0-8)

func (h *handler) tryCachePublicKeyResponse(resp *jsonrpc.Response[json.RawMessage], l logger.Logger) {
	if resp.Result == nil {
		l.Debugw("no result in public key response, not caching")
		return
	}

	r := &vaultcommon.GetPublicKeyResponse{}
	err := h.unmarshal(bytes.NewReader(*resp.Result), r)
	if err != nil {
		l.Debugw("failed to unmarshal public key response, not caching", "error", err)
		return
	}

	if r.PublicKey == "" {
		l.Debugw("no public key in unmarshaled response, not caching", "response", resp, "result", r)
		return
	}
	masterPublicKey := tdh2easy.PublicKey{}
	masterPublicKeyBytes, err := hex.DecodeString(r.PublicKey)
	if err != nil {
		l.Debugw("failed to decode master public key string", "error", err)
		return
	}
	err = masterPublicKey.Unmarshal(masterPublicKeyBytes)
	if err != nil {
		l.Debugw("failed to unmarshal master public key", "error", err)
		return
	}

	h.mu.Lock()
	h.cachedPublicKeyGetResponse = *resp.Result
	h.cachedPublicKeyObject = &masterPublicKey
	h.mu.Unlock()
	l.Debugw("successfully cached public key response")
}

func (h *handler) getCachedPublicKey() ([]byte, *tdh2easy.PublicKey) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	if h.cachedPublicKeyGetResponse == nil {
		return nil, nil
	}
	copied := make([]byte, len(h.cachedPublicKeyGetResponse))
	copy(copied, h.cachedPublicKeyGetResponse)
	cachedPublicKeyCopy := *h.cachedPublicKeyObject
	return copied, &cachedPublicKeyCopy
}

func (p *GatewayVaultRequestProcessor) processCreateSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	publicKey *tdh2easy.PublicKey,
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var createReq vaultcommon.CreateSecretsRequest
	if err := json.Unmarshal(*req.Params, &createReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		createReq.RequestId = req.ID
		if err := marshalVaultParams(req, &createReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		createReq.RequestId = coalesceRequestID(createReq.RequestId, req.ID)
	}

	skipLabelValidation := publicKey == nil
	if err := p.validator.ValidateCreateSecretsRequest(ctx, publicKey, &createReq, skipLabelValidation); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		createReq.RequestId = prefixedRequestID
		vaultutils.ApplyEncryptedSecretNamespaceDefaults(createReq.EncryptedSecrets)
		return marshalVaultParams(req, &createReq)
	})
}

// validateWriteRequest performs common validation for CreateSecrets and UpdateSecrets requests.
// It treats publicKey as optional, since it can be nil if the gateway nodes don't have the public key cached yet.
func (r *RequestValidator) validateWriteRequest(ctx context.Context, publicKey *tdh2easy.PublicKey, id string, encryptedSecrets []*vaultcommon.EncryptedSecret, skipLabelValidation bool) error {
	if id == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(encryptedSecrets)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(encryptedSecrets) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, req := range encryptedSecrets {
		if req == nil {
			return errors.New("encrypted secret must not be nil at index " + strconv.Itoa(idx))
		}
		if req.Id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}

		if req.EncryptedValue == "" {
			return errors.New("secret must have encrypted value set at index " + strconv.Itoa(idx) + ":" + req.Id.String())
		}

		if err := r.ValidateSecretIdentifier(ctx, req.Id.Key, req.Id.Owner, req.Id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}
		if err := r.ValidateCiphertextSize(ctx, req.Id.Owner, req.EncryptedValue); err != nil {
			return fmt.Errorf("secret encrypted value at index %d is invalid: %w", idx, err)
		}
		if skipLabelValidation {
			if _, err := verifyEncryptedSecret(publicKey, req.EncryptedValue); err != nil {
				return errors.New("Encrypted Secret at index [" + strconv.Itoa(idx) + "] is invalid. Error: " + err.Error())
			}
		} else {
			err := EnsureRightLabelOnSecret(publicKey, req.EncryptedValue, req.Id.Owner)
			if err != nil {
				return errors.New("Encrypted Secret at index [" + strconv.Itoa(idx) + "] doesn't have owner as the label. Error: " + err.Error())
			}
