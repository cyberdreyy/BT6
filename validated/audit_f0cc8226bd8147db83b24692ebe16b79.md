### Title
Unhandled `strings.Repeat` negative-count panic in `normalizeHex` via oversized workflowOwner input - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateHexInput` allows a 42-character all-hex-digit `workflowOwner` string without a literal `"0x"` prefix to pass validation, but `normalizeHex` then computes a negative repeat count and panics in `strings.Repeat`, crashing the request-handling goroutine for all gateway users.

### Finding Description
`validateHexInput(input, expectedLength)` at [1](#0-0)  only checks `len(input) <= expectedLength` (42 for `workflowOwner`), that the string is lowercase, and that `hex.DecodeString` succeeds after trimming an optional `"0x"` prefix via `strings.TrimPrefix`. Because `TrimPrefix` is a no-op unless the string literally starts with the two characters `"0x"`, an attacker can submit a 42-character string composed entirely of valid lowercase hex digits (`0-9a-f`) with no `0x` prefix. Such a string:
- passes the length check (`len == 42`, not `> 42`)
- passes the lowercase check
- has `hex.DecodeString` succeed on the full 42-character string (even length, valid hex chars)

This request flows through `validateWorkflowOwner` at [2](#0-1)  into `resolveWorkflowID`, which calls `normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)` at [3](#0-2) . Inside `normalizeHex` at [4](#0-3) :
```go
hexStr := strings.TrimPrefix(input, "0x")   // no-op, hexStr len = 42
expectedHexLength := length - 2             // 42 - 2 = 40
paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr  // Repeat("0", 40-42) = Repeat("0", -2)
```
`strings.Repeat` with a negative count panics (`"strings: negative Repeat count"`), which is unrecovered anywhere in the call chain — no `recover()` was found in the `core/services/gateway/handlers` package guarding this code path. This is reached from `HandleUserTriggerRequest` at [5](#0-4) , which is invoked before `authorizeRequest` — i.e., prior to any authentication/authorization check, making it reachable by any unauthenticated caller submitting a well-formed JSON-RPC trigger request.

### Impact Explanation
A panic in a goroutine without a `recover()` terminates the entire Go process, crashing the gateway and taking down `http_trigger_handler` (and the whole gateway process) for all users — a Denial of Service matching Chainlink's "Denial of Service" bounty impact class for public-facing gateway infrastructure.

### Likelihood Explanation
No special privileges are required: any client capable of sending a gateway JSON-RPC trigger request (`workflows.execute` method) with a crafted `workflowOwner` field can trigger this. It is deterministic and repeatable — the exact same 42-character all-hex-digit input reliably reproduces the panic.

### Recommendation
In `normalizeHex`, clamp/validate that `len(hexStr) <= expectedHexLength` before computing the repeat count (return an error or truncate/reject oversized input), and fix `validateHexInput` to also reject inputs whose hex-digit length (after optional `0x` trim) exceeds the digit length implied by `expectedLength`, regardless of whether the `0x` prefix is present.

### Proof of Concept
Go unit test in `http_trigger_handler_test.go`:
```go
func TestNormalizeHex_NoPanicOnBoundaryInput(t *testing.T) {
    input := strings.Repeat("a", workflowOwnerLength) // 42 hex chars, no "0x" prefix
    err := validateHexInput(input, workflowOwnerLength)
    require.NoError(t, err) // demonstrates it passes validation

    require.NotPanics(t, func() {
        _ = normalizeHex(input, workflowOwnerLength)
    })
}
```
Expected current behavior: `validateHexInput` returns nil (no error) and `normalizeHex` panics with `strings: negative Repeat count`, confirming the vulnerability. After the fix, either `validateHexInput` should reject this input, or `normalizeHex` should handle it without panicking.

```go
func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}
```
