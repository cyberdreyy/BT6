### Title
Claimed instant-withdraw receipts stay counted in `instantWithdrawClaimsByEpoch`, inflating default-recovery basis and reserve - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
The CVE-2021-47082 analog is a resource that is freed (paid out) but still referenced by later cleanup accounting — a "use-after-free" of a claim basis. `claimInstantWithdrawRequest` pays a funded instant receipt and clears `instantWithdrawsRequests[_user]`, but never clears `instantWithdrawsRequestsByEpoch[_user][epoch]` or `instantWithdrawClaimsByEpoch[epoch]`. If the borrower later defaults in the same `epochNumber`, `defaultPendingClaimBasis`/`_defaultPrefundedInstantReserve` count already-paid claims as both outstanding basis and held reserve, inflating `defaultRecoveryPrice` in `finalizeDefaultRecovery`.

### Finding Description
In `claimInstantWithdrawRequest` (`IdleCreditVault.sol:380-393`), a funded instant claim burns the user's receipt tokens, zeroes `instantWithdrawsRequests[_user]`, and transfers underlying. Neither `instantWithdrawsRequestsByEpoch[_user][epochNumber]` nor the epoch aggregate `instantWithdrawClaimsByEpoch[epochNumber]` is decremented — those are only touched in `_claimDefaultedInstantWithdrawRequest` (`:842-856`).

`collectInstantWithdrawFunds` (`:398-403`) only reduces `pendingInstantWithdraws`; the per-epoch claim aggregates persist after payment.

At default finalization:
- `defaultPendingClaimBasis` (`:644-649`) adds the full `instantWithdrawClaimsByEpoch[epochNumber]` to basis whenever `pendingInstantWithdraws != 0`, including already-paid claims.
- `_defaultPrefundedInstantReserve` (`:716-723`) computes `instantBasis - pendingInstant`, counting already-transferred funds as if they were still reserve held by the strategy.
- `finalizeDefaultRecovery` (`:661-710`) then sets `defaultRecoveryReserve = _recoveredAmount + prefundedReserve + defaultRecoveryReserve` and `recoveryPrice = reserveAmount / totalBasis` — both numerator and denominator are inflated by the ghost amount X.

When R < B (a loss scenario), `(R + X)/(B + X)` pushes `defaultRecoveryPrice` toward par. The strategy is credited with reserve that physically left the contract, so post-default claims via `_claimDefaultedInstantWithdrawRequest`/`_transferDefaultRecovery` and the active-side NAV mint (`:699-705`) are priced against non-existent backing.

### Impact Explanation
Broken invariant: one receipt, one payout — the same instant-withdraw basis is paid at par through `claimInstantWithdrawRequest` and then paid again into recovery pricing. Users who hold defaulted-epoch receipts (normal withdraws, unfunded instant claims) or post-default tranche positions claim against a `defaultRecoveryReserve` that includes phantom funds. Early claimants overdraw; the last claimants' `_transferDefaultRecovery` underflows the real balance and their yield is permanently unclaimable (or the reserve is silently drained by the overpriced active-side mint). Quantification: for paid-amount X, defaulted-epoch instant basis B, and unfunded remainder P = `pendingInstantWithdraws`, `recoveryPrice` is inflated from `reserve/(A + B)` to `(reserve + X)/(A + B + X)`, where X can equal the entire prefunded instant queue (arbitrary size, set by any KYC'd attacker request).

### Likelihood Explanation
All steps use unprivileged actions: an attacker (any KYC-passing lender) requests an instant withdraw during a running epoch, the honest CDO funds it via `collectInstantWithdrawFunds`, the attacker claims (receipt basis stays in `instantWithdrawClaimsByEpoch`), and a subsequent borrower default in the same `epochNumber` with `pendingInstantWithdraws != 0` triggers the inflation when the honest CDO calls `finalizeDefaultRecovery`. No privileged misbehavior is required; the honest borrower/manager calls simply sequence around the attacker's request and claim.

### Recommendation
In `claimInstantWithdrawRequest`, also clear per-epoch accounting for the claim epoch(s): decrement `instantWithdrawsRequestsByEpoch[_user][epoch]` and `instantWithdrawClaimsByEpoch[epoch]` for the epochs backing `instantWithdrawsRequests[_user]` (or track the funded-claim epoch analogously to `withdrawsRequestsByEpoch`). Alternatively, make `_defaultPrefundedInstantReserve` derive the prefunded part only from still-unclaimed per-epoch receipts, and ensure `defaultPendingClaimBasis` cannot include basis whose funds were already transferred out.

### Proof of Concept
Foundry fork test (scaffold in `test/foundry/`, modeled on `testClaimInstantWithdrawRequest` in `test/foundry/IdleCDOEpochQueue.t.sol:1258`):

```solidity
function testClaimedInstantReceiptInflatesRecovery() external {
    _useStandardEpochVariant();
    _stopCurrentEpochWithApr(10e18);            // epoch #1 buffer

    vm.prank(manager);
    cdoEpoch.setInstantWithdrawParams(100, 1e18, false); // instant withdraws enabled

    address attacker = makeAddr('attacker');
    uint256 tranches = _depositWithUser(attacker, 50e6);
    _depositWithUser(makeAddr('lp'), 50e6);

    vm.prank(manager);
    cdoEpoch.startEpoch();

    // Attacker requests instant withdraw and it gets funded via collectInstantWithdrawFunds
    _requestInstantWithdrawWithUser(attacker, tranches);   // wraps cdoEpoch.requestInstantWithdraw
    // CDO collects funded amount (honest manager/borrower flow)
    // ... drive instant funding as in existing tests ...

    // Attacker claims at par; instantWithdrawsRequests[attacker] == 0 but
    // instantWithdrawClaimsByEpoch[epochNumber] still includes `tranches`
    vm.prank(attacker);
    cdoEpoch.claimInstantWithdrawRequest();
    assertEq(strategy.instantWithdrawsRequests(attacker), 0);
    assertGt(strategy.instantWithdrawsRequestsByEpoch(attacker, strategy.epochNumber()), 0); // stale basis

    // Leave some other instant receipt unfunded so pendingInstantWithdraws != 0,
    // then borrower defaults and CDO finalizes recovery.
    // ... trigger _handleBorrowerDefault / finalizeDefaultRecovery ...

    // Assertion: recovery price is inflated toward 1e18 relative to true reserve/basis,
    // and the last defaulted-epoch claim reverts/drains less than defaultRecoveryPrice promises.
    uint256 price = strategy.defaultRecoveryPrice();
    uint256 trueReserve = underlying.balanceOf(address(strategy));
    assertGt(price * strategy.defaultPendingClaimBasis() / 1e18, trueReserve); // claims exceed real backing
}
```

Key checks to encode: after the funded claim, `instantWithdrawClaimsByEpoch[epochNumber]` is unchanged; after `finalizeDefaultRecovery`, `defaultRecoveryReserve` exceeds the strategy's actual `underlyingToken.balanceOf` attributable to recovery, and a second defaulted-epoch claimant receives less than `claimBasis * defaultRecoveryPrice / 1e18` (or reverts).
