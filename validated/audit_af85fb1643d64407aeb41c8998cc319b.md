### Title
v1 chainstate's tenure-duplicate check ignores locally-accepted (only-self-signed) blocks, letting a signer sign two conflicting tenure-start blocks in the same tenure - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
`stacks-signer/src/chainstate/v1.rs`'s `validate_tenure_change_payload` rejects a tenure-start proposal with `DuplicateBlockFound` only when it finds a **globally** accepted block already in that tenure, via `signer_db.get_last_globally_accepted_block(...)` [1](#0-0) . It does not consider blocks the signer has only **locally** accepted (i.e., already signed with `signed_self`, but not yet observed as group-signed). The v2 chainstate path fixed exactly this gap by switching to `get_last_signed_block`, which returns `GloballyAccepted` or `LocallyAccepted` blocks [2](#0-1) , with a regression test explicitly documenting that the old (globally-accepted-only) check "would have incorrectly passed" a duplicate tenure-start proposal [3](#0-2) . The v1 file in this checkout was never updated to match, so the same class of bug that v2 fixed still exists in the v1 code path.

### Finding Description
The signer's proposal-time defense against a miner re-proposing a competing tenure-start block for a tenure the signer has already put a signature over is `validate_tenure_change_payload`'s `DuplicateBlockFound` check. `docs/signer-flows.md` explicitly documents this asymmetry between the two chainstate versions:

> `validate_tenure_change_payload` rejects with `DuplicateBlockFound` when we have already accepted a block in the tenure a tenure-change block is starting. v2 counts locally or globally accepted blocks (`get_last_signed_block`); v1 counts only globally accepted ones (`get_last_globally_accepted_block`). [4](#0-3) 

The doc also states this duplicate check "never runs again" after proposal arrival — it is not repeated at validate-ok time or at signing time [5](#0-4) . `CHANGELOG.md` records the same defect being fixed: "When checking tenure change blocks, ensure there are no locally accepted blocks in the tenure, not just globally accepted blocks" [6](#0-5) , and the corresponding test only landed in `chainstate/tests/v2.rs` [7](#0-6) . The v1 code in this checkout still contains the pre-fix logic:

```
let last_in_current_tenure = signer_db
    .get_last_globally_accepted_block(&block.header.consensus_hash)
``` [8](#0-7) 

This is structurally the same bug class as the XWiki advisory: a required-checks analysis (here, the signer's "have I already committed to a block in this tenure?" check) that is not exhaustive over all the states/kinds that should count (here, `LocallyAccepted` is silently excluded, just as `TextArea` properties were silently excluded from XWiki's required-rights property-type enumeration), letting content through that a complete check would have blocked.

Because a signer under protocol v1 that has already signed (locally accepted, `signed_self` set) a first tenure-start block A for tenure T will not reject a second, different tenure-start proposal B for the same tenure T at proposal time (the v1 `DuplicateBlockFound` gate misses A), and because this check "never runs again," B proceeds to node validation and the pre-commit round. Whether B ultimately gets signed then hinges entirely on the separate own-tenure conflict guard evaluated at the pre-commit threshold (`get_signed_conflicts` + `conflict_still_blocks`/`get_tenure_tip`) [9](#0-8) , whose own documented fallback is to **sign anyway** when the node cannot yet confirm a tip for that tenure ("no — never confirmed --> SIGN", "node unreachable --> SIGN") [10](#0-9) . That fallback exists specifically to avoid stalls when the node hasn't caught up, which is a normal condition early in a tenure — precisely when a signer would have only *locally* (not yet globally) accepted its first tenure-start block. In that window, the v1 gap in the proposal-time check is not compensated by the pre-commit-time guard, and the signer can end up putting a second, conflicting signature over a second tenure-start block B at the same height/tenure as one it already signed (A).

### Impact Explanation
This breaks the "one signed tenure-start block per tenure" equality that the duplicate check exists to enforce, and can produce a signer signature over a conflicting/non-canonical block for a tenure it already endorsed — the Critical-tier impact defined by the rules ("a signer signing an invalid, non-canonical, or conflicting block"). If enough signers hit the same race (all running v1 chainstate, with their nodes not yet caught up on this tenure's tip), the network could accumulate valid signature weight behind two different tenure-start blocks for the same tenure, splitting the group and undermining the single-canonical-block guarantee the pre-commit/threshold protocol is built to provide.

### Likelihood Explanation
This requires only the actions of the single block-producing miner (proposing block A, then quickly re-proposing a different block B for the same tenure) plus normal gossip/latency — no signer collusion, no majority of signers, and no possession of any signer's key. It is gated on: (1) the signer being on the v1 chainstate path (pre-global-signer-state activation, per `check_block_against_local_state`'s doc comment [11](#0-10) ), and (2) the timing window where the signer has locally accepted A but the node has not yet reported a tenure tip for T. Both conditions are plausible in early-tenure/high-latency scenarios but I could not fully confirm from the index whether the v1 path is still reachable/active in current mainnet configurations versus fully superseded by v2 — this affects whether the bug is live or dormant/legacy code, and I was unable to verify it further given tool limits.

### Recommendation
Update `validate_tenure_change_payload` in `stacks-signer/src/chainstate/v1.rs` to use `signer_db.get_last_signed_block` (matching v2's fix) instead of `get_last_globally_accepted_block`, so `DuplicateBlockFound` also fires when the signer has only locally accepted a competing tenure-start block. Additionally, consider re-running (or replacing with a same-tenure variant of) the duplicate check at the pre-commit/signing stage rather than relying solely on the cross-tenure `get_signed_conflicts` guard, since that guard's "unreachable/never confirmed → SIGN" fallback does not protect against this specific same-tenure duplicate scenario.

### Proof of Concept
1. Configure a signer running the v1 chainstate path (pre-global-signer-state activation).
2. Miner proposes tenure-start block A for tenure T; the signer validates it and locally accepts it (`mark_locally_accepted`, `signed_self` set), before it is observed as globally accepted.
3. Before the signer's node reports a tenure tip for T (e.g., due to node lag), the same or a colluding miner proposes a different tenure-start block B for the same tenure T (different transactions/timestamp).
4. At proposal time, `validate_tenure_change_payload` calls `get_last_globally_accepted_block(T)` [8](#0-7) , which returns `None` (A is only locally accepted), so B is **not** rejected with `DuplicateBlockFound`.
5. B proceeds through validation and pre-commit; at the pre-commit threshold, the own-tenure conflict guard's `get_tenure_tip` lookup for T returns "never confirmed" or is unreachable, so per the documented flow the signer signs B [9](#0-8) .
6. The signer has now signed two different blocks (A and B) for the same tenure/height, a conflict the duplicate check exists to prevent — reproducible directly against `stacks-signer/src/chainstate/tests/v1.rs`'s test harness by adapting `check_tenure_change_rejects_when_locally_accepted_block_exists` (already present for v2 [12](#0-11) ) against the v1 `SortitionsView::check_proposal`, which is expected to fail (return `Ok(())` instead of `Err(RejectReason::DuplicateBlockFound)`).

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),

        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}
