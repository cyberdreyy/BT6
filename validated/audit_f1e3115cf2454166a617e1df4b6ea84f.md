### Title
Stale confirmations from deleted members are never purged, letting requests execute below `num_confirmations` live members - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges requests that were *created* by the deleted member (`r.member == member`); it never scans the `confirmations` map to strip that member's prior confirmation entries from requests created by other members. `confirm` then blindly counts every string in the stored `HashSet<String>` toward `num_confirmations`, so a confirmation cast by an account that is no longer (or, per the question, was temporarily not) a member still counts as a valid vote, allowing execution with fewer than `num_confirmations` genuinely current members having approved.

### Finding Description
The binding that must hold is:

`confirmations.get(request_id).len() == |{ m ∈ self.members : m confirmed request_id while being a current member at counting time }|`

but the actual code only maintains:

`confirmations.get(request_id).len() == |raw strings ever inserted and not yet purged|`

Trace:
- `confirm` (`multisig2/src/lib.rs:294-315`) counts `confirmations.len() as u32 + 1 >= self.num_confirmations` purely from the stored `HashSet<String>`, with no check that each stored entry still corresponds to a current member of `self.members`.
- `delete_member` (`multisig2/src/lib.rs:356-379`) removes stored requests/confirmations only for requests the deleted member itself *created*: [1](#0-0) 
It does not iterate `self.confirmations` to strip the deleted member's vote from requests created by *other* members.
- `current_member` (`multisig2/src/lib.rs:322-339`) and `MultisigMember::to_string` (`multisig2/src/lib.rs:102-106`) are only used to identify the *caller* at call time; they play no role in revalidating pre-existing entries inside a request's confirmations set.

Exploit flow (any remaining member as attacker, no privileged position needed beyond being a live member which is a precondition of the scenario, matching the question's "attacker = any remaining member"):
1. Member A creates request R1 targeting some receiver X (not A, not D).
2. Member D confirms R1 → `confirmations[R1] = {D}` (below threshold, request stays pending).
3. The multisig (via normal `DeleteMember` self-requests reaching `num_confirmations`) deletes D. `delete_member` only removes requests where `r.member == D`; since R1.member == A, R1 and its confirmations set (still containing D) survive untouched.
4. D is optionally re-added as `MultisigMember::Account { account_id }` with the same `account_id` (or D simply stays deleted — the bug fires either way since nothing ever re-validates old entries).
5. Two other members confirm R1. The stale `D` entry is counted alongside them, so `confirmations.len() + 1 >= num_confirmations` is satisfied with only 2 contemporaneous confirmations plus 1 stale one, and `execute_request` runs.

Existing guards do not prevent this: `assert_valid_request` (`multisig2/src/lib.rs:407-423`) only checks that the *calling* account is a current member and that the request/confirmations exist — it never re-validates the *stored* confirmer set against current membership.

### Impact Explanation
A multisig request (including `Transfer`, `AddKey`, `FunctionCall`, `DeployContract`, etc.) can be executed with fewer than `num_confirmations` distinct currently-authorized members having actually approved it in the current membership epoch. This is exactly the Critical category "a multisig request executed below `num_confirmations` live members," and can move NEAR/tokens or grant access keys without the required live quorum. This is repeatable for any request that receives a confirmation from a member later removed (whether or not they are re-added), across any multisig deployment using this contract.

### Likelihood Explanation
Preconditions are ordinary multisig operations: a pending request created by one member, a confirmation from a second member who is later removed via a normal `DeleteMember` action (which itself only requires reaching quorum, not attacker privilege), and continued confirmations by remaining members. No special balances or account setup beyond being one of the multisig's own members is needed, and the flow requires no signature forgery — it purely exploits missing state cleanup. It is deterministic and fully reproducible in a unit test.

### Recommendation
When deleting a member in `delete_member`, iterate all entries in `self.confirmations` (not just requests authored by that member) and remove the deleted member's string from every confirmations set; alternatively, revalidate the stored confirmer set against `self.members` at counting time in `confirm` before checking the threshold.

### Proof of Concept
`cargo test` in `multisig2` (unit test with `testing_env!`, extending the existing test module):
1. Build `MultiSigContract::new` with 4 members: `Account{bob}` (A), `Account{carol}` (D), `AccessKey{key1}` (B), `AccessKey{key2}` (C), `num_confirmations = 3`.
2. As `bob` (A): `add_request` R1 with `receiver_id = "dave"`, action `Transfer`. Assert `confirmations.get(R1).len() == 0`.
3. As `carol` (D): `confirm(R1)`. Assert `confirmations.get(R1) == {"D-string"}`, `requests.len() == 1` (not executed, below threshold).
4. Create and drive to execution a `DeleteMember{member: Account{carol}}` self-request (3 confirmations from bob/key1/key2). Assert `members` no longer contains `carol`, but assert `confirmations.get(R1)` still contains D's string (proving no purge occurred).
5. (Optional, matching the question) Re-add `carol` via `AddMember` self-request driven to execution the same way. Assert `members` again contains `carol`.
6. As `key1` (B) then `key2` (C): call `confirm(R1)` twice. Assert on the second call that `requests.len() == 0` (R1 executed) even though only B and C are the confirmations cast after step 4/5 — D's stale entry from step 3 was the third vote, i.e. execution happened with only 2 confirmations genuinely valid under current membership plus 1 stale one, violating `confirmations distinct current == num_confirmations`.     pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
