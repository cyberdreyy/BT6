## Analog Found: Unbounded Recursive `TrieNode` RLP Decoding Enables Stack-Overflow DoS of the Fault-Proof Program

### Title
Unbounded recursion in `TrieNode::decode` allows an attacker-supplied trie preimage to crash the fault-proof program via stack exhaustion - (File: `crates/proof/mpt/src/node.rs`)

### Summary
The GraphQL Java CVE-2023-28867 stems from recursive parsing of an attacker-controlled query with no depth limit, causing stack exhaustion (`CWE-770`). The Base fault-proof/MPT code has the same bug-class: `TrieNode::decode` in [1](#0-0)  recursively decodes RLP-encoded trie nodes (`Extension`/`Branch`) with no recursion-depth or nesting bound, and this decoder is invoked directly on preimage-oracle-supplied bytes inside the fault-proof program.

### Finding Description
`TrieNode::decode` dispatches on RLP list length: a `BRANCH_LIST_LENGTH` (17-element) node decodes a `Vec<Self>` (which itself recurses into `Self::decode` for every child), and a 2-element list is passed to `try_decode_leaf_or_extension_payload`, which for an `Extension` node calls `Self::decode(buf)` again on the nested pointer: [2](#0-1) 

There is no `depth` parameter, no `MAX_*_DEPTH` constant, and no check against total recursion count anywhere in this crate (unlike the CBOR parser elsewhere in the repo, which does track `depth` and enforces `MAX_CBOR_NESTING_DEPTH`, see [3](#0-2) ). Nodes only get "blinded" (replaced by a 32-byte hash reference) when their RLP encoding is ≥32 bytes when *encoding* legitimate tries [4](#0-3) , but the *decoder* places no such constraint on untrusted input — a crafted byte string can encode an arbitrarily long chain of small, inline (non-blinded) `Extension` nodes, each one containing another `Extension` node, forcing one `Self::decode` stack frame per level with no limit.

This decoder is reachable directly from attacker-influenced preimage data in the fault-proof/verification path. The `OracleL2ChainProvider` (used by the client-side FPVM/ZK proof program) implements `TrieProvider::trie_node_by_hash` by fetching a preimage from the oracle and calling `TrieNode::decode` on it unconditionally: [5](#0-4) 

The preimage oracle read path itself places no bound on preimage length before handing the buffer to the decoder — it merely reads a length-prefixed buffer over the channel [6](#0-5) . Because a dispute-game participant (challenger/proposer) supplies the L1/L2 data and preimages that back the fault-proof program's trie walks, a malicious participant can supply a preimage blob crafted as a deeply nested chain of small `Extension` nodes for a hash that is otherwise unverifiable until decode is attempted, driving `TrieNode::decode` into unbounded recursion.

Other trie-walk entry points compound the exposure with their own unbounded recursion: `TrieNode::open` [7](#0-6)  and the leaf-fetching walker [8](#0-7)  both recurse once per trie level with no depth ceiling, each additionally invoking `unblind`, which itself calls back into `fetcher.trie_node_by_hash` → `TrieNode::decode`.

### Impact Explanation
A stack-overflow crash of the fault-proof program is a process abort (SIGSEGV on native targets, or an FPVM trap on zkVM/MIPS targets) rather than a graceful error. Since the fault-proof program is the component that computes and validates the L2 output root for dispute resolution, an attacker who can force it to crash on a legitimate or maliciously-crafted claim can prevent proof generation/verification for that claim, undermining the correctness/availability of the dispute-game output-root check (`node halt` / inability to produce a correct provable output). This satisfies the High-severity "unauthorized operation ... node halt ... wrong provable output root" bar from the validation rubric.

### Likelihood Explanation
The vulnerable code path (`TrieNode::decode`) is exercised on every state/storage/receipt/transaction trie lookup performed by the fault-proof program, and preimages are supplied through an oracle that is populated from potentially attacker-influenced L1/L2 data during a dispute game. Crafting a deeply nested but individually-small `Extension` chain that decodes without hitting the "blind >32 bytes" limit requires only knowledge of the RLP wire format documented in this very file — no cryptographic break is needed, only a preimage whose keccak256 hash matches (which is required for any preimage anyway, but the *structure* inside that preimage is otherwise unconstrained by depth).

### Recommendation
Add an explicit recursion-depth parameter/limit to `TrieNode::decode`, `TrieNode::open`, `TrieNode::insert`, `TrieNode::unblind`, and `OrderedListWalker::fetch_leaves`, mirroring the `depth`/`MAX_CBOR_NESTING_DEPTH` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`, and reject nodes that exceed the maximum possible MPT depth (bounded by key length in nibbles, e.g. 64 for 32-byte keys plus a small safety margin) with a decode error instead of recursing further.

### Proof of Concept
Conceptually: encode a chain of RLP 2-element lists `rlp([encoded_path_nibble, node])` where each `node` is itself another `Extension`-shaped 2-element list (staying below the "blind" threshold at each level so no hash boundary caps the nesting), nested to a depth of tens of thousands of levels within a single preimage blob. Supplying this blob for a `Keccak256` preimage key (with a matching hash, computed by hashing the fully-constructed nested buffer) and feeding it through `OracleL2ChainProvider::trie_node_by_hash` will call `TrieNode::decode` recursively until the fault-proof program's stack is exhausted and the process aborts.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
