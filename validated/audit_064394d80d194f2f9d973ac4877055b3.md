### Title
Zip Slip / path traversal in legacy zip extractor bypasses the `dir` confinement invariant - ([File: helpers/archives/zip_extract.go])

### Summary
The default (non-fastzip) zip/zipzstd extraction path used by `commands/helpers/cache_extractor.go`'s `Execute()` ultimately calls `archives.ExtractZipArchive` in `helpers/archives/zip_extract.go`, which writes files using the raw, attacker-controlled `zip.File.Name` with no `..`/absolute-path sanitization and without ever using the `dir` argument passed to `archive.NewExtractor`. A pipeline author who controls the cache/artifact zip content can supply entry names like `../../etc/cron.d/x` or similar relative traversal sequences and write files outside the intended job workspace.

### Finding Description
`commands/helpers/cache_extractor.go`'s `Execute()` computes `wd, _ := os.Getwd()` and calls `archive.NewExtractor(format, f, size, wd)` [1](#0-0) , then invokes `extractor.Extract(ctx)`. For `Zip`/`ZipZstd` formats registered by the legacy implementation (used whenever the `FF_USE_FASTZIP` feature flag is off, which is the reachable default unless explicitly enabled), the concrete extractor is `ziplegacy.extractor` [2](#0-1) .

Its `Extract` method stores `dir` in the struct but never uses it: it simply opens a `zip.Reader` and calls `archives.ExtractZipArchive(zr)` [3](#0-2) .

`ExtractZipArchive` iterates zip entries and calls `extractZipFile(file)` for each, using `file.Name` directly as a filesystem path with `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Mkdir(file.Name, ...)`, and `os.Symlink(string(data), file.Name)` for symlink entries [4](#0-3) . There is **no** `filepath.Clean`, no `..`-rejection, no absolute-path rejection, and no prefix check against any confinement directory anywhere in this file — the `dir` parameter that `archive.NewExtractor` accepted is completely discarded by this code path.

This contrasts with the `tarzstd` extractor, which correctly builds `path = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path that doesn't have `e.dir` as prefix [5](#0-4) . The legacy zip extractor has no equivalent check, so the invariant "extraction is confined to `dir`" is violated for the default zip/zipzstd path.

An attacker who controls a cache or artifact zip (e.g., produced by a job that crafts a raw zip payload, or one that manipulates `cache:paths`/artifact upload content directly) can insert an entry named e.g. `../../outside-file` or `../../../home/user/.bashrc`. During `cache_extractor.go`'s `Execute()` (invoked by `gitlab-runner cache-extractor` internal command run inside the job's execution context), this entry gets written relative to the process's current working directory rather than being confined to `wd`/the job workspace, because `dir` is never consulted.

### Impact Explanation
On executors where the runner helper process's working directory can be escaped (shell executor, or any executor where the helper binary runs with filesystem access broader than the job directory, e.g., a shared build directory tree), a crafted cache/artifact zip lets a pipeline author write or overwrite arbitrary files outside the job workspace at extraction time, using the permissions of the process running `cache-extractor`. This can corrupt sibling job directories, other cached data, or files elsewhere on the filesystem reachable by relative traversal, directly breaching the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Preconditions: `FF_USE_FASTZIP` must be off (documented current default behavior for many installations) so the `ziplegacy` extractor/registrations are active for `Zip`/`ZipZstd` format instead of `fastzip`. The attacker only needs the ability to produce/control the content of a project's cache or artifact zip (trivial for any pipeline author defining cache/artifact steps and writing a custom zip). No special privileges beyond a normal CI pipeline are required, and the bug is deterministically reproducible since there's no randomness or timing dependency.

### Recommendation
In `helpers/archives/zip_extract.go`, sanitize every `zip.File.Name` before use: reject absolute paths and any name whose `filepath.Clean(name)` does not stay within the destination root (mirror the `tarzstd` check using `filepath.Join(dir, name)` + prefix validation against `filepath.Clean(dir)`), and actually thread the `dir` parameter from `ziplegacy.extractor` through to `ExtractZipArchive`/`extractZipFile` instead of discarding it.

### Proof of Concept
```go
func TestZipLegacyExtractPathTraversal(t *testing.T) {
    outDir := t.TempDir()
    victimDir := t.TempDir() // simulate sibling directory outside outDir

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    // Escape outDir and land in victimDir via relative traversal
    escapePath := filepath.Join("..", filepath.Base(victimDir), "pwned")
    w, err := zw.Create(escapePath)
    require.NoError(t, err)
    _, err = w.Write([]byte("attacker-controlled"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    // Run as the process cwd == outDir, mimicking cache_extractor.go's wd
    origWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(outDir))
    defer os.Chdir(origWd)

    extractor, err := ziplegacy.NewExtractor(bytes.NewReader(buf.Bytes()), int64(buf.Len()), outDir)
    require.NoError(t, err)
    require.NoError(t, extractor.Extract(context.Background()))

    // Assert: file must NOT exist outside outDir
    _, statErr := os.Stat(filepath.Join(victimDir, "pwned"))
    assert.Error(t, statErr, "expected extraction to be confined to outDir, but escaped into victimDir")
}
```
Expected (buggy) result: the file is written into `victimDir/pwned`, proving the extraction escaped the intended `dir`. After the fix (adding path confinement in `zip_extract.go`), `Extract` should return an error and the file should not exist outside `outDir`.
