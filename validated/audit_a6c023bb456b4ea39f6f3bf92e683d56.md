### Title
Insufficient rate limiting on unauthenticated pipeline run resume endpoint enables brute-force/flood abuse - ([File: core/web/router.go])

### Summary
The Chainlink node web server implements a two-tier rate limiter (`Authenticated`: 1000 req/min, `Unauthenticated`: 5 req/20s) and applies the strict `Unauthenticated` tier only to `/sessions` [1](#0-0) . However, the `PATCH /v2/resume/:runID` route, which requires **no authentication at all**, is registered directly on the `unauthedv2` group, which is a child of the `api` group carrying the much looser `Authenticated` rate-limit tier (1000 requests/min) rather than the `Unauthenticated` tier [2](#0-1) [3](#0-2) .

### Finding Description
`NewRouter` builds an `api` group with the `Authenticated` rate limiter and session middleware applied at the top level: [3](#0-2) 

`v2Routes` is called with this `api` group, and inside it creates `unauthedv2 := r.Group("/v2")` (no additional auth middleware), which inherits the parent's `Authenticated` rate-limit middleware since gin `Group()` copies the parent's handler chain. The vulnerable route is: [2](#0-1) 

`prc.Resume` accepts an unauthenticated `PATCH` with a run task UUID and a JSON body, and forwards it directly to `ResumeJobV2`, which resumes/completes a pipeline task with the caller-supplied value/error, with no authentication check whatsoever: [4](#0-3) [5](#0-4) 

The audit event name itself, `UnauthedRunResumed`, confirms the endpoint is intentionally unauthenticated (used by external task callbacks) [6](#0-5) .

By contrast, the node's designers explicitly recognized that unauthenticated, credential-guessing-prone endpoints need the strict `Unauthenticated` tier — this pattern was applied to `/sessions` specifically to stop brute-force login attempts (validated by `TestSessions_RateLimited`, which asserts a 429 after only 5 failed attempts within `UnauthenticatedPeriod`) [7](#0-6) . The `/v2/resume/:runID` endpoint receives no such protection, despite being just as unauthenticated and taking a guessable/enumerable identifier (`runID`, a UUID) plus an attacker-controlled JSON payload that is fed straight into the pipeline task resolution logic.

### Impact Explanation
An unauthenticated remote attacker can send up to 1000 requests per minute (16+ req/s) against `/v2/resume/:runID` — 200x the throttle applied to the analogous `/sessions` unauthenticated endpoint — to enumerate/guess valid pending task run IDs and inject arbitrary `result`/`error` values into in-flight pipeline task runs via `ResumeJobV2` → `pipelineRunner.ResumeRun`. This is a resource-exhaustion and functional-abuse vector matching the HAL-04 report class (lack of rate limiting enabling resource overload and unthrottled abuse), but here it is compounded by the fact that the endpoint under-protected is one that directly mutates job/pipeline execution state without any authentication, rather than a purely read-only endpoint. This can lead to unauthorized manipulation of job run completions (an "unauthorized job run" outcome per the validation criteria).

### Likelihood Explanation
Likelihood is moderate: exploitation requires knowledge or brute-forcing of a valid, still-pending `runID` (UUID v4), which is not trivial to guess blindly, but the endpoint provides no rate-limit deterrent proportional to that risk (it uses the generous "authenticated" quota instead of the "unauthenticated" quota), and is reachable by any anonymous network client that can hit the node's HTTP port.

### Recommendation
- Move `/v2/resume/:runID` into a route group that applies the strict `Unauthenticated` rate-limit tier (same as `/sessions`), or apply a dedicated, low-throughput limiter to this specific route.
- Reconsider whether this endpoint can be authenticated (e.g., via a per-run bridge/callback token) rather than left fully open, consistent with least-privilege design.
- Ensure `ResumeJobV2`/`ResumeRun` validate that the task is actually awaiting external resumption before accepting attacker-supplied results, to reduce the blast radius of any successful guess.

### Proof of Concept
1. Identify a Chainlink node's `/v2/resume/:runID` endpoint is reachable without any `Authorization`/session cookie (confirmed via `unauthedv2` group registration with no `auth.Authenticate` middleware in `core/web/router.go:243`).
2. Because this route sits under the `api` group's `Authenticated` rate limiter (1000 req/min) rather than the `Unauthenticated` tier (5 req/20s) used for `/sessions`, send high-volume `PATCH` requests with different UUIDs to `/v2/resume/:runID` at up to ~16 req/s indefinitely without triggering the stricter throttling that protects other unauthenticated attack surfaces.
3. For any UUID that corresponds to a live pending task run, the attacker-supplied JSON body (`{"error": "...", "value": "..."}`) is passed unauthenticated into `ResumeJobV2`, resuming/mutating that pipeline run. [2](#0-1)

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
```

```go
func TestSessions_RateLimited(t *testing.T) {
	t.Parallel()

	ctx := t.Context()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(ctx))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	client := clhttptest.NewTestLocalOnlyHTTPClient()
	input := `{"email":"brute@force.com", "password": "wrongpassword"}`

	for range 5 {
		request, err := http.NewRequestWithContext(ctx, http.MethodPost, ts.URL+"/sessions", bytes.NewBufferString(input))
		require.NoError(t, err)

		resp, err := client.Do(request)
		require.NoError(t, err)
		assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
	}

	request, err := http.NewRequestWithContext(ctx, http.MethodPost, ts.URL+"/sessions", bytes.NewBufferString(input))
	require.NoError(t, err)

	resp, err := client.Do(request)
	require.NoError(t, err)
	assert.Equal(t, 429, resp.StatusCode)
}
```
