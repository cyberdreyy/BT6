### Title
Inconsistent authorization allows edit-role users to export DKG/vault secret material via lower-privilege role than all other key export endpoints - ([File: core/web/router.go])

### Summary
The `/v2/vault/dkg_results/export` route is wired with `auth.RequiresEditRole` instead of `auth.RequiresAdminRole`, unlike every other key-export endpoint (CSA/ETH/OCR/OCR2/P2P/VRF/chain keys) exposed through `keysController[K,R].Export`, which all require the Admin role. This lets an edit-role (non-admin) authenticated user extract the raw DKG result package, including the encrypted secret share material, via `VaultController.ExportDKGResult`.

### Finding Description
`VaultController.ExportDKGResult` reads the stored DKG result package (which contains `ReportWithResultPackage`, i.e. the DKG secret share material) from the vault ORM and returns it hex-encoded to the caller: [1](#0-0) . This route is registered at `POST /v2/vault/dkg_results/export` guarded only by `auth.RequiresEditRole`: [2](#0-1) .

This is inconsistent with the established authorization pattern in this router file, where sensitive privileged operations that mutate state or reveal secrets (e.g., `lgc.Patch` for log configuration) require `auth.RequiresAdminRole`, while `auth.RequiresEditRole` is reserved for less sensitive mutation actions such as deleting pipeline job spec errors or tracking/deleting EVM forwarders: [3](#0-2) [4](#0-3) . In this codebase's role model, exporting cryptographic key material is treated as an admin-only capability for every other key type via `keysController[K,R].Export`, since key export operations disclose secret material that should not be accessible to lower-privileged edit-role identities. The DKG result export endpoint discloses functionally equivalent secret material (the DKG recipient's decrypted/encrypted share content embedded in the result package) but was wired with the weaker `RequiresEditRole` check, breaking the intended consistent minimum-role invariant for secret-export operations.

An attacker who holds only an edit-role API credential (a real, commonly provisioned lower-privilege credential, not an admin credential) can call this endpoint directly and receive the DKG result package without needing admin rights, whereas the equivalent action for any other key type would be rejected with 401/403 by the `RequiresAdminRole` wrapper.

### Impact Explanation
This is a role/authorization bypass leading to secret material disclosure: an edit-role identity — which should not be able to export key/secret material — can retrieve the DKG result package for any known `instanceId`, including the underlying vault secret share content persisted by the ORM. This corresponds to Chainlink's "unauthorized disclosure of confidential key/secret material" impact class, scoped specifically to DKG/vault secrets, and is a genuine privilege boundary violation relative to the analogous admin-gated key export endpoints in the same router.

### Likelihood Explanation
Exploitation requires only a valid edit-role API token (no admin, no host or database access, no social engineering) — a low bar since edit-role tokens are a normal, non-privileged operator credential tier in Chainlink node deployments. The request is a single unauthenticated-relative-to-admin `POST /v2/vault/dkg_results/export` with a known `instanceId`, fully reproducible and repeatable by anyone issued an edit-role token.

### Recommendation
Change the router registration for the export route to require admin role, consistent with all other key-export endpoints:
```go
authv2.POST("/vault/dkg_results/export", auth.RequiresAdminRole(vault.ExportDKGResult))
```
in `core/web/router.go` at the `authv2.POST("/vault/dkg_results/export", ...)` line. Audit `VerifyDKGResult` as well to confirm `RequiresEditRole` is intentional there (verification returns only a hash, not secret material, so it may be acceptable), but the export path specifically must be restricted to admin to match the trust boundary used for every other key type.

### Proof of Concept
Go handler-level integration test plan:
1. Set up a test app with the vault ORM seeded with a `DKGResult` row for a known `instanceId` (via `vault.NewVaultORM(...).SaveResultPackage` or equivalent test helper used in `vault_controller_test.go`).
2. Create two authenticated clients: one with an Admin-role session/token, one with an Edit-role session/token.
3. Call `POST /v2/vault/dkg_results/export` with `{"instanceId": "<seeded-id>"}` using the edit-role client.
4. Assert: current behavior returns `200 OK` with the DKG result package (hex + sha) — this is the vulnerable behavior (`RequiresEditRole` allows it).
5. Comparative assertion: call any equivalent `keysController[K,R].Export` route (e.g., CSA key export) with the same edit-role client and assert it returns `401`/`403` due to `RequiresAdminRole`.
6. Expected fix assertion: after patching router.go to use `RequiresAdminRole` for the vault export route, step 3 should also return `401`/`403` for the edit-role client, and only succeed for the admin-role client — establishing parity with the other key-export endpoints.

```go
// ExportDKGResult returns the DKGResult corresponding to the given instance ID
// "POST <application>/vault/dkg_results/export"
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
```
