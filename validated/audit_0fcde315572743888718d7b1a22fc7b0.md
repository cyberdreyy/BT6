### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing requests to execute with fewer live-member confirmations than `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm()` in `multisig2/src/lib.rs` decides whether a request has reached quorum purely by counting entries in the `confirmations` set for that request, without verifying that every account/key in that set is still a current member. `delete_member()` only purges requests that were *originated* by the removed member; it does not scrub the removed member's confirmations from other members' pending requests. This lets a request execute once the *stored count* reaches `num_confirmations`, even though one or more of the "confirming" identities counted are no longer members of the multisig.

### Finding Description
`confirm()` performs the threshold check as: [1](#0-0) 

```rust
pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
    self.assert_valid_request(request_id);
    let member = self.current_member().unwrap_or_else(...);
    let mut confirmations = self.confirmations.get(&request_id).unwrap();
    assert(!confirmations.contains(&member.to_string()), "Already confirmed this request with this key");
    if confirmations.len() as u32 + 1 >= self.num_confirmations {
        let request = self.remove_request(request_id);
        self.execute_request(request)
    } else {
        confirmations.insert(member.to_string());
        ...
    }
}
```

`assert_valid_request` only checks that the **caller** is currently a member; it never re-checks the identities already present in the stored `confirmations` set.

`delete_member()` is the only place confirmations/requests are cleaned up when a member is removed: [2](#0-1) 

```rust
fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
    ...
    let request_ids: Vec<u32> = self
        .requests
        .iter()
        .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
        .collect();
    for request_id in request_ids {
        self.confirmations.remove(&request_id);
        self.requests.remove(&request_id);
    }
    self.num_requests_pk.remove(&member.to_string());
    self.members.remove(&member);
    ...
}
```

This filter matches only requests where `r.member == member`, i.e. where the removed member was the **original requester** (`MultiSigRequestWithSigner.member`, set in `add_request` at [3](#0-2) ). It does not iterate `self.confirmations` for *other* requests where the removed member had previously called `confirm()` as a co-signer. Those stale entries (member's `to_string()` representation) remain permanently inside the `HashSet<String>` for that request.

**Binding broken:** `confirmations.len() == number of live members who confirmed`. After a member is removed, this equality becomes `confirmations.len() >= number of live members who confirmed` (it can contain ghosts), while `confirm()` still treats `confirmations.len() + 1 >= num_confirmations` as proof of K-of-N live approval.

### Impact Explanation
This is a Critical issue per the custody/authorization rules: "a multisig request executed below threshold." A `Transfer`, `FunctionCall`, `DeployContract`, `AddKey` (full access key), or any other privileged multisig action can be executed with fewer genuinely live confirming members than the configured `num_confirmations`, undermining the K-of-N security guarantee the contract is supposed to provide. This directly breaks the "confirmations counted versus live members" equality called out as an in-scope custody binding.

### Likelihood Explanation
No special privilege is required beyond being (or having been) a legitimate multisig member — the exact scenario is a normal part of multisig lifecycle management (member rotation/offboarding), which is expected to happen routinely in production. Any request that collects partial confirmations before a confirming member is later removed will retain that member's stale confirmation indefinitely, since nothing ever re-validates or purges it. The bug is triggered by ordinary operational flow, not by an attacker needing to bypass any additional control — it is a latent correctness bug in `delete_member`/`confirm`.

### Recommendation
When removing a member, iterate over *all* pending requests' confirmation sets (not just requests originated by that member) and remove the member's identity string from each. Alternatively, on `confirm()`, filter the stored confirmations set to only identities still present in `self.members` before comparing its length against `num_confirmations` (i.e., compute `confirmations.iter().filter(|c| self.members contains c).count()`), and persist the pruned set back.

### Proof of Concept
1. Initialize `MultiSigContract` with 4 members `A, B, C, D` and `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R1` (e.g., a `Transfer`).
3. `A` and `B` call `confirm(R1)` → `confirmations[R1] = {A, B}` (2 of 3, not yet executed).
4. Separately, members create and confirm a `DeleteMember { member: B }` request with 3 confirmations (`A`, `C`, `D`), which executes and removes `B` from `self.members`. Note `delete_member` only scrubs requests where `r.member == B` (i.e., requests `B` originated) — `R1` was originated by `A`, so it is untouched; `confirmations[R1]` still contains `B`.
5. `C` calls `confirm(R1)`. Inside `confirm()`: `confirmations.len() (=2, containing stale B) + 1 >= num_confirmations (3)` → true. `R1` executes via `execute_request`, even though only `A` and `C` are live members who actually approved it (2 live confirmations, below the K=3 threshold).

This confirms the request executes below the intended live-member confirmation threshold, directly matching the disclosed bug class of "recorded/counted claims not reflecting the actual current backing set" applied to the multisig's confirmation-vs-membership binding.     fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
