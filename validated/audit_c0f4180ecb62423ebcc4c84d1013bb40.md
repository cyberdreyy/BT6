### Title
Epoch cannot be stopped when the external ERC4626 vault valuation reverts, freezing all lender withdrawals even when funds are fully on-hand - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
In programmable-borrower mode, `IdleCDOEpochVariant._stopEpoch` unconditionally prices the ProgrammableBorrower's vault sleeve via `totalInterestDueNow()` → `_vaultNetInterest()` → `_currentVaultAssets()` (`vault.convertToAssets`). If the external vault's share valuation reverts (e.g., its own upstream oracle/valuation path is broken), `stopEpoch` reverts *before* any default handling, so the epoch can never close and all pending/future withdraw requests are trapped — even when the borrower contract holds enough on-hand underlying to cover every obligation (the analog of "no outstanding debt").

### Finding Description
`_stopEpoch` in `IdleCDOEpochVariant.sol` resolves the epoch interest through the programmable borrower:

- `IdleCDOEpochVariant.sol:357` calls `_resolveStopEpochInterest(_interest)`
- `IdleCDOEpochVariant.sol:1004` executes `IProgrammableBorrower(_borrower()).totalInterestDueNow()`
- `ProgrammableBorrower.sol:330-334` `totalInterestDueNow` calls `_vaultNetInterest()`
- `ProgrammableBorrower.sol:339` `_vaultNetInterest` calls `_currentVaultAssets()` (a `vault.convertToAssets` wrapper) whenever `epochAccountingActive` is true — there is no early-return for a fully on-hand position.

If `convertToAssets` reverts, the whole `stopEpoch` transaction reverts at line 357, *before* the `isProgrammableBorrower` branch at line 395-404 that routes failures into `_handleBorrowerDefault`. The default machinery is therefore unreachable: the pool cannot default, cannot stop, and `epochEndDate` passing changes nothing.

The same unguarded valuation exists inside `ProgrammableBorrower.onStopEpoch` itself:

- `ProgrammableBorrower.sol:245` `shortfall > _currentVaultAssets()` — only reached when there is a shortfall, fine.
- `ProgrammableBorrower.sol:261` `bufferStartVaultAssets = _currentVaultAssets()` — **unconditional**. Even when `_amountRequired <= onHand` (all liquidity already held as cash, zero vault withdrawal needed), the hook still prices the vault and would revert.

This mirrors the BlueBerry bug exactly: the code insists on valuing a position (the vault sleeve) even in scenarios where the valuation is not needed for solvency — e.g., borrower has repaid everything, all funds sit as idle underlying on the ProgrammableBorrower, pending withdraws fully covered by on-hand cash. The system still reverts because it cannot skip `convertToAssets` in `totalInterestDueNow`/`onStopEpoch`.

Note `onDefault` (lines 289-301) was deliberately written to *avoid* `convertToAssets` ("must still be able to shut down borrowing" when "the external vault's valuation view is unavailable during stress"), confirming the authors recognized the hazard — but the normal `stopEpoch` path remains entirely dependent on live vault valuation, and `onDefault` is only reachable *through* a successful borrower-default flow that `stopEpoch` never reaches when the view reverts.

### Impact Explanation
All lender funds are frozen for as long as the external vault's `convertToAssets` is unavailable — potentially indefinitely. Withdraw-request claims (`claimWithdrawRequest`) require `stopEpoch` to move funds into `IdleCreditVault` via `collectWithdrawFunds`; instant withdraws require `startEpoch`/`getInstantWithdrawFunds`, also blocked because the epoch state machine is stuck in "running". There is no unprivileged or privileged recovery path inside the epoch flow: the only mitigations are `emergencyExitVault` (redeems shares but does not fix `convertToAssets` reverting, and does not move the epoch forward) or contract upgrades. Loss severity scales with full pool TVL; funds remain recoverable only if/when the external vault's valuation recovers.

### Likelihood Explanation
External ERC4626 vaults (e.g., Morpho/Gauntlet vaults) can have `convertToAssets` that reverts when their underlying market/oracle state is stressed, or `maxWithdraw`/conversion paths can revert during liquidity crises — precisely the conditions under which LPs most want to exit. The trigger requires no attacker action; an unprivileged party cannot cause it directly, but any LP is the victim. Likelihood is moderate (depends on third-party vault behavior), impact is high (indefinite freeze of all epoch funds), consistent with Medium severity. Note: this depends on third-party oracle/valuation failure which is a listed rejection category edge — however the flaw here is the *missing short-circuit* in idle-tranches' own code (no "zero debt / fully on-hand" bypass and no `try` around the valuation), not the external data itself, matching the BlueBerry finding's accepted rationale.

### Recommendation
Short-circuit vault valuation when it is not needed:

1. In `ProgrammableBorrower.onStopEpoch`, skip `bufferStartVaultAssets = _currentVaultAssets()` (line 261) when `vault.balanceOf(address(this)) == 0`, and wrap it in a `try` that falls back to 0 — accounting can be safely re-baselined since a stopped epoch clears `epochPendingWithdraws` anyway.
2. In `totalInterestDueNow`/`_vaultNetInterest`, return early when the contract holds zero vault shares, or let `IdleCDOEpochVariant._resolveStopEpochInterest` wrap the call in `try`/`catch` and, on failure, route to `_handleBorrowerDefault` (the existing default path) rather than propagating the revert — an unpriceable sleeve should degrade to default accounting, not brick the state machine.
3. Alternatively, add a `closePool`/`stopEpoch` escape that requests all funds based on on-hand cash plus a `vault.redeem(all shares)` call (share-denominated, no `convertToAssets` needed).

### Proof of Concept
```solidity
// Foundry fork test — programmable borrower mode, epoch running
function testStopEpochFrozenWhenVaultValuationReverts() external {
    uint256 amount = 10_000 * oneScale;
    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);
    idleCDO.depositAA(amount);                       // funds parked into ERC4626 vault
    cdoEpoch.requestWithdraw(aaTranche.balanceOf(address(this)) / 2, address(aaTranche));
    _startEpochAndCheckPrices(0);

    // Borrower repays everything: all facility funds are now on-hand cash,
    // zero outstanding borrower draw — "no debt" analog.
    vm.prank(borrower);
    programmableBorrower.repay(0);

    // External vault's valuation path breaks (e.g., its oracle freezes)
    vault.setRevertConvertToAssets(true);            // as in MockEpochInvariantVault

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert();                               // revert inside convertToAssets
    cdoEpoch.stopEpoch(0, 0);                        // reverts at _resolveStopEpochInterest

    // Retry is hopeless; default path is never reached.
    assertFalse(cdoEpoch.defaulted());
    assertTrue(cdoEpoch.isEpochRunning());

    // Withdraw request can never be claimed while valuation is broken.
    vm.expectRevert();
    cdoEpoch.claimWithdrawRequest();
}
```

Key assertion: even after the borrower fully repays (all underlying held directly by `ProgrammableBorrower`, nothing needing vault pricing for solvency), `stopEpoch` still reverts because `_vaultNetInterest` and `onStopEpoch` unconditionally call `_currentVaultAssets()`.
