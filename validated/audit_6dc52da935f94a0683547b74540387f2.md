No vulnerability found for this question.

**Rationale:**

1. **Operator role required upfront.** `rotate_consensus_key` in `stake.move` asserts the caller is already `stake_pool.operator_address` for the specific `pool_address` before it will emit a `RotateConsensusKeyEvent` [1](#0-0) . An unprivileged attacker without the operator capability for that pool cannot invoke this path at all, which the review's decision standard explicitly excludes ("Reject anything that assumes the attacker already owns the pool, operator role...").

2. **On-chain commission accounting does not key off pubkey equality.** `staking_contract.move`'s commission logic (`get_staking_contract_amounts_internal`, `request_commission_internal`) computes commission purely from on-chain stake amounts (`active + pending_active` vs. recorded `principal`), never from consensus-key bytes or `RotateConsensusKeyEvent` fields [2](#0-1) [3](#0-2) . There is no on-chain mechanism that "keys off event pubkey equality" for commission distribution; the premise describes a hypothetical off-chain indexer behavior, not an Aptos production stake/delegation code path, which is out of the review's scope.

3. **PoP verification already enforces subgroup validity for the key used on-chain.** `rotate_consensus_key` requires `bls12381::public_key_from_bytes_with_pop` to succeed, and the native `verify_proof_of_possession_internal` / `bls12381_pk_subgroub_check` path rejects invalid/non-subgroup points before the key is accepted [4](#0-3) [5](#0-4) . The `subgroup_check` gap noted in `crates/aptos-crypto/src/bls12381/bls12381_keys.rs` is a Rust-crate-level API caveat (it warns callers to use `Validatable<PublicKey>` rather than relying on bare `try_from`) [6](#0-5) [7](#0-6) ; it does not create two distinct byte-vectors that decode to the *same* effective public key on the Move-level path used for staking, since compressed-point deserialization used by `blst::min_pk::PublicKey` does not admit multiple valid encodings of one curve point in this flow.

4. No unprivileged input changes ownership, commission entitlement, or accounting state in `staking_contract.move`; the described double-crediting mechanism does not exist in the reviewed on-chain code.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Calculate accumulated rewards and commissions since last update.
    fun get_staking_contract_amounts_internal(
        staking_contract: &StakingContract
    ): (u64, u64, u64) {
        // Pending_inactive is not included in the calculation because pending_inactive can only come from:
        // 1. Outgoing commissions. This means commission has already been extracted.
        // 2. Stake withdrawals from stakers. This also means commission has already been extracted as
        // request_commission_internal is called in unlock_stake
        let (active, _, pending_active, _) =
            stake::get_stake(staking_contract.pool_address);
        let total_active_stake = active + pending_active;
        let accumulated_rewards = total_active_stake - staking_contract.principal;
        let commission_amount =
            accumulated_rewards * staking_contract.commission_percentage / 100;

        (total_active_stake, accumulated_rewards, commission_amount)
    }

/***************************************************************************************************
 * native fun bls12381_validate_pubkey
 *
 *   gas cost: base_cost + per_pubkey_deserialize_cost +? per_pubkey_subgroup_check_cost
 *
 * where +? indicates that the expression stops evaluating there if the previous gas-charging step
 * failed
 **************************************************************************************************/
fn native_bls12381_validate_pubkey(
    context: &mut SafeNativeContext,
    ty_args: &[Type],
    mut arguments: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(ty_args.is_empty());
    debug_assert!(arguments.len() == 1);

    context.charge(BLS12381_BASE)?;

    let pk_bytes = safely_pop_arg!(arguments, Vec<u8>);

    let pk = match bls12381_deserialize_pk(pk_bytes, context)? {
        Some(key) => key,
        None => return Ok(smallvec![Value::bool(false)]),
    };

    let valid = bls12381_pk_subgroub_check(&pk, context)?;

    Ok(smallvec![Value::bool(valid)])
}
