**Rationale:** The reported pattern (missing Chainlink L2 sequencer-uptime check) does not exist as an unmitigated issue in this codebase. In `v2/AeraVaultAssetRegistry.sol`, the `spotPrices()` function explicitly checks the sequencer's `latestRoundData()`, reverting with `Aera__SequencerIsDown` if `answer != 0` and enforcing a `GRACE_PERIOD_TIME` (3600s) via `Aera__GracePeriodNotOver` before trusting oracle data [1](#0-0) . Oracle price staleness is also independently enforced per-asset via `_checkOraclePrice`, which reverts on invalid/negative answers and on prices older than the configured heartbeat [2](#0-1) .

For v3, pricing does not go through a raw Chainlink `AggregatorV3Interface` with an unchecked sequencer status at all — it goes through the generic ERC-7726 `IOracle`/`OracleRegistry` abstraction and `PriceAndFeeCalculatorV2`'s own anchor/drift staleness logic (`Aera__StalePrice`, `maxPriceAge` checks), which is independent of any specific Chainlink sequencer feed and is not in scope for this exact bug pattern [3](#0-2) [4](#0-3) .

No live, in-scope contract in this repo mirrors the ChainlinkWrapper's unchecked-sequencer flaw — the closest analog (`AeraVaultAssetRegistry`) already implements the exact recommended mitigation.

    /// @param asset Asset details to check.
    /// @return price Valid oracle price.
    function _checkOraclePrice(AssetInformation memory asset)
        internal
        view
        returns (uint256 price)
    {
        (, int256 answer,, uint256 updatedAt,) = asset.oracle.latestRoundData();

        // Check price staleness
        if (answer <= 0) {
            revert Aera__OraclePriceIsInvalid(asset, answer);
        }
        if (
            asset.heartbeat > 0
                && updatedAt + asset.heartbeat + 1 hours < block.timestamp
        ) {
            revert Aera__OraclePriceIsTooOld(asset, updatedAt);
        }

        price = uint256(answer);
    }
