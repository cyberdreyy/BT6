### Title
Integer-division threshold truncation in gateway HTTP trigger quorum weakens Byzantine fault tolerance guarantee - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
The gateway's HTTP trigger response aggregation threshold is computed as `(len(shard.members)+shard.f)/2 + 1` using Go integer division, which truncates non-integer results exactly like the reported Solidity bug where `optionParams.amount/2` truncation silently weakened a security-critical calculation (`settlementFee`).

### Finding Description
`setupCallback` builds one `IdenticalNodeResponseAggregator` per shard the workflow is assigned to, using a quorum threshold intended to tolerate `F` faulty/non-responding nodes among `N = len(shard.members)`: [1](#0-0) 

The comment states the formula is `(N+F)//2 + 1`, and the code performs `(len(shard.members)+shard.f)/2 + 1` using Go's truncating integer division. When `N + F` is odd, the division truncates the fractional `.5` downward instead of rounding up, silently lowering the required number of matching node responses by exactly the same class of defect as the reported truncation bug (`option.premium` truncation from `amount/2`). The aggregator then releases the response to the end user once `threshold` identical node responses are collected: [2](#0-1) 

Because `F` and shard membership come from the DON/shard configuration (attacker does not directly control it), the severity is lower than a directly attacker-controlled truncation, but it is a genuine off-by-one weakening of the Byzantine quorum bound: with `N + F` odd, the code accepts one fewer matching response than the intended `(N+F)/2 + 1` (mathematically rounded) threshold would require, reducing the number of colluding/faulty nodes needed to force acceptance of a fabricated node response as the canonical answer delivered to an unprivileged client.

### Impact Explanation
This is reachable from any unprivileged workflow trigger request via `HandleUserTriggerRequest` → `setupCallback`, and the resulting threshold directly gates when a node-supplied response is forwarded to the requesting user as the canonical result via `HandleNodeTriggerResponse`. A truncated (too-low) threshold reduces the number of matching malicious/faulty nodes required to get a fabricated response accepted and returned to the user, which is a cross-user/response-integrity concern for the gateway's quorum-based trust model.

### Likelihood Explanation
Likelihood is moderate to low: it requires `len(shard.members) + shard.f` to be odd for a given shard configuration (deployment-dependent, not attacker-controlled at request time), and it also requires an attacker/faulty set of nodes up to `F` to already be compromised or colluding — the difference is only whether the quorum needed is off by one from the intended rounded value. It does not by itself allow an unprivileged client to bypass the mechanism without colluding nodes.

### Recommendation
Compute the threshold with explicit rounding semantics instead of relying on integer truncation, e.g. `threshold := (len(shard.members)+shard.f+1)/2 + 1` (or use ceiling division `(N+F+1)/2` per the intended formula) and add a unit test asserting the threshold for both even and odd `N+F` matches the mathematically rounded value, not the truncated one.

### Proof of Concept
Given a shard with `N = len(shard.members) = 4` and `F = shard.f = 1` (a plausible real config), `N + F = 5` (odd). The intended `(N+F)/2 + 1` rounded up is `3`, but Go's truncating division yields `threshold = 5/2 + 1 = 2 + 1 = 3` — in this particular case it matches; however for `N = 3, F = 0` (`N+F=3`, odd), truncation gives `3/2+1 = 1+1 = 2`, while the mathematically-intended ceiling-rounded value for a BFT quorum requiring tolerance of `F=0` faults among 3 nodes could plausibly need `2` as well, so the concrete numeric divergence depends on the exact intended formula semantics, which are not verified elsewhere in the codebase (no test asserts rounding direction for odd `N+F`) — this should be confirmed/tested by the responsible engineer against the exact BFT quorum formula intended by the `// (N+F)//2 + 1 threshold` comment.
