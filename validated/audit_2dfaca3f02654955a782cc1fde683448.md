### Title
Unstaked balance withdrawal from staking pool debits accounting before confirming NEAR transfer succeeded - permanent loss of withdrawable balance on transfer failure - (File: staking-pool/src/internal.rs)

### Summary
`internal_withdraw` in the staking pool contract decrements the delegator's `unstaked` balance and the pool's `last_total_balance` optimistically, in the same call that fires the outbound `Promise::new(account_id).transfer(amount)`, with no `.then()` callback to verify the transfer actually succeeded [1](#0-0) . This mirrors the H-4 bug class: state that records an entitlement (recorded claim) is mutated without verifying that the corresponding value transfer to the counterparty actually landed, so the ledger can diverge from what the delegator actually received.

### Finding Description
`internal_withdraw` performs the accounting mutation and the transfer in this order:
```
account.unstaked -= amount;
self.internal_save_account(&account_id, &account);
...
Promise::new(account_id).transfer(amount);
self.last_total_balance -= amount;
``` [2](#0-1) 

Unlike every other outbound-transfer flow in this same codebase family, this call has no success/failure callback. Compare to the lockup contract's analogous flows, which all consistently chain a callback that inspects `is_promise_success()` and reverts state if the transfer failed, e.g. `termination_withdraw` → `on_withdraw_unvested_amount` [3](#0-2) [4](#0-3) , and `withdraw_from_staking_pool` → `on_staking_pool_withdraw` [5](#0-4) [6](#0-5) , which explicitly restores the deposit amount if `is_promise_success()` is false.

The staking pool's own README documents the guarantee: "If a user deposited X, the user should be able to withdraw at least X" and "the contract can't lose or lock tokens of users" [7](#0-6) . `internal_withdraw` breaks this because it treats the `Promise::new(...).transfer(amount)` call as fire-and-forget: `account.unstaked` and `last_total_balance` are already decremented before the runtime confirms delivery. NEAR `Promise::new(...).transfer` can fail for several unprivileged-attacker-independent and attacker-triggerable reasons documented elsewhere in this same repo family — e.g., the target account being deleted mid-flight, which the staking-pool README itself calls out as a real scenario that results in the transfer being returned to the pool ("in a rare scenario, where the owner withdraws tokens and while the call is being processed deletes their account, the withdraw transfer will fail and the tokens will be returned to the staking pool") [8](#0-7) . When that happens, the transferred NEAR is returned to the pool balance and redistributed as reward to other delegators in the next `ping`, but the withdrawing account's `unstaked` balance and `last_total_balance` were already decremented and never restored — the delegator's claim vanishes while the funds stay in the contract and get distributed to others.

### Impact Explanation
This breaks the equality `unstaked_balance_recorded == NEAR actually delivered to the delegator`. Before the call: `account.unstaked = U`. After a failed transfer: `account.unstaked = U - amount`, but the delegator received `0` of `amount` — the funds are retained by the pool and folded into `last_total_balance`/reward distribution to other participants. This is an accounting value diverging from reality with another party (other delegators receiving inflated rewards) settling on it, and funds are effectively frozen/lost for the affected delegator — matching the High/Critical impact categories (funds frozen, or claims not matching assets, or rewards mis-attributed to other parties from the failed withdrawer's balance).

### Likelihood Explanation
The trigger doesn't require a privileged role or blacklist analog (there's no NEAR-native blacklist), but the pool's own documentation identifies at least one concrete unprivileged trigger: deleting the withdrawing account while the withdrawal's transfer receipt is in flight [8](#0-7) . Any account holder can delete their own account at will (a `near delete` action mentioned elsewhere in this same repo, e.g. the lockup README's account deletion flow) [9](#0-8) , immediately after submitting `withdraw`, causing the transfer receipt to bounce back to the pool while the ledger already shows the balance debited. This is a self-inflicted loss path for that account, but more importantly it demonstrates that the transfer is not guaranteed to succeed and the contract has zero recovery/callback mechanism, unlike every sibling contract in this repo.

### Recommendation
Chain a `.then()` callback (as done in `lockup/src/owner_callbacks.rs::on_staking_pool_withdraw` and `lockup/src/foundation_callbacks.rs::on_withdraw_unvested_amount`) after `Promise::new(account_id).transfer(amount)`, and only finalize the debit of `account.unstaked` / `last_total_balance` (or restore them) based on `is_promise_success()` in that callback, matching the pattern already used consistently elsewhere in this codebase.

### Proof of Concept
1. Delegator `bob` deposits and unstakes `amount`, waits the required epochs so `unstaked_available_epoch_height` has passed.
2. `bob` calls `withdraw(amount)` → `internal_withdraw` immediately sets `account.unstaked -= amount`, saves the account, decrements `last_total_balance`, and fires `Promise::new(bob).transfer(amount)` with no callback [2](#0-1) .
3. In the same transaction batch, `bob` (or an unrelated concurrent action) deletes the `bob` account before the transfer receipt executes.
4. The transfer receipt fails/returns to the pool (as described in the pool's own README) [8](#0-7) ; the pool's balance keeps the NEAR, which is later redistributed as reward via `internal_ping` to other delegators.
5. `bob`'s `unstaked` balance is permanently reduced by `amount` with no corresponding NEAR ever delivered to `bob`, and no callback exists to detect or reverse this — the claim-vs-asset equality is broken.

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }

    pub fn on_withdraw_unvested_amount(
        &mut self,
        amount: WrappedBalance,
        receiver_id: AccountId,
    ) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        if withdraw_succeeded {
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} succeeded.",
                    amount.0, receiver_id
                )
                    .as_bytes(),
            );
            // Decreasing lockup amount after withdrawal.
            self.lockup_information.termination_withdrawn_tokens += amount.0;
            let unvested_amount = self.get_terminated_unvested_balance().0;
            if unvested_amount > amount.0 {
                // There is still unvested balance remaining.
                let remaining_balance = unvested_amount - amount.0;
                self.vesting_information =
                    VestingInformation::Terminating(TerminationInformation {
                        unvested_amount: remaining_balance.into(),
                        status: TerminationStatus::ReadyToWithdraw,
                    });
                env::log(
                    format!(
                        "Termination Step: There is still terminated unvested balance of {} remaining to be withdrawn",
                        remaining_balance
                    )
                        .as_bytes(),
                );
                if self.get_account_balance().0 == 0 {
                    env::log(b"The withdrawal is completed: no more balance can be withdrawn in a future call");
                }
            } else {
                self.foundation_account_id = None;
                self.vesting_information = VestingInformation::None;
                env::log(b"Vesting schedule termination and withdrawal are completed");
            }
        } else {
            self.set_termination_status(TerminationStatus::ReadyToWithdraw);
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} failed",
                    amount.0, receiver_id,
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded

    pub fn on_staking_pool_withdraw(&mut self, amount: WrappedBalance) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        self.set_staking_pool_status(TransactionStatus::Idle);

        if withdraw_succeeded {
            {
                let staking_information = self.staking_information.as_mut().unwrap();
                // Due to staking rewards the deposit amount can become negative.
                staking_information.deposit_amount.0 = staking_information
                    .deposit_amount
                    .0
                    .saturating_sub(amount.0);
            }
            env::log(
                format!(
                    "The withdrawal of {} from @{} succeeded",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );

            env::log(
                format!(
                    "The withdrawal of {} from @{} failed",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
