### Title
Missing host-boundary in `sshInsteadOfs`/`GetInsteadOfs` rewrite keys lets a crafted submodule `ssh://` URL exfiltrate the CI job token to an attacker-controlled host via git's raw prefix-matching `insteadOf` - (File: `helpers/url/gitauth.go`)

### Summary
`GitAuthHelper.sshInsteadOfs` (and the base HTTPS entry in `GetInsteadOfs`/`repoBaseInsteadOf`) writes `insteadOf` rewrite keys such as `ssh://git@<host>` and `https://<host>` with **no trailing delimiter**. Git's `insteadOf` mechanism does a raw string-prefix match, not a host-boundary-aware match, so any submodule URL whose host merely *starts with* the runner's configured host string (e.g. `gitlab.example.com.attacker.com`) will also match and get rewritten to the token-bearing base URL, causing the job token to be sent to the attacker's host.

### Finding Description
`GitAuthHelper.sshInsteadOfs` builds insteadOf entries keyed by `h.config.Server.EffectiveSSHHost()`: [1](#0-0) 

The scp-style entry (`git@<host>:`) is safe because the trailing colon is a hard boundary. The `ssh://git@<host>` entry, however, has no trailing character, so it is a bare prefix. Similarly, the primary authenticated HTTPS rewrite key built in `GetInsteadOfs` and `repoBaseInsteadOf` uses `trimmed(baseURL)` with no trailing slash: [2](#0-1) [3](#0-2) 

These entries are turned into real `git config` `url.<x>.insteadOf` stanzas by `setupExternalGitConfig`: [4](#0-3) 
The `regexp.QuoteMeta`/anchored pattern here is only used by the `git config --replace-all` CLI to decide which existing multi-valued entry to overwrite — it has no effect on git's own runtime URL-rewrite matching, which is a plain string-prefix comparison per git's documented `insteadOf` semantics.

Attack flow: the job author sets `GIT_SUBMODULE_FORCE_HTTPS=true` (or the runner's global config does), enabling `sshInsteadOfs`. A submodule (which can be an entirely separate, attacker-controlled project referenced via `.gitmodules`) declares its URL as `ssh://git@<runner-ssh-host><attacker-suffix>/repo.git`, e.g. `ssh://git@gitlab.example.com.attacker.com/x.git`, where `gitlab.example.com` is the runner's `CI_SERVER_SHELL_SSH_HOST`/`CI_SERVER_HOST` (a publicly known value visible to any project on the instance). When `git submodule update --init` resolves that URL, git matches the `ssh://git@gitlab.example.com` insteadOf prefix and rewrites the URL to `authedBase + suffix`, i.e. `https://gitlab-ci-token:<TOKEN>@gitlab.example.com.attacker.com/x.git` — the job token is now embedded in a URL whose actual DNS host is `gitlab.example.com.attacker.com`, fully controlled by the attacker, and git performs the HTTP(S) request (leaking the token) to that host.

No existing check stops this: there is no host/DNS validation of `.gitmodules` submodule URLs before configuring insteadOf, and the anchoring in `setupExternalGitConfig`'s `--replace-all` pattern only governs config-file bookkeeping, not the runtime match.

### Impact Explanation
The CI job token (`gitlab-ci-token:<CI_JOB_TOKEN>`) is sent over the network to an attacker-controlled DNS host chosen by whoever controls the submodule's `.gitmodules` entry. The job token typically has read/write API access scoped to the pipeline's project (and possibly others via CI/CD job token access rules), so this is a genuine cross-boundary credential exfiltration to an unintended host, matching the scoped impact described.

### Likelihood Explanation
Preconditions are trivial and fully attacker-controlled: (1) `GIT_SUBMODULE_FORCE_HTTPS` enabled (job-settable, or org default), (2) attacker controls a submodule's `.gitmodules` URL (a normal capability for any project owner/maintainer of a dependency repo referenced as a submodule), (3) knowledge of the runner's configured SSH/host string, which is exposed as `CI_SERVER_HOST`/`CI_SERVER_SHELL_SSH_HOST` predefined variables and is visible to any pipeline running on the same GitLab instance. No coincidental "lexical collision" is required — the attacker deliberately appends a suffix to the known host string. This is fully repeatable and deterministic.

### Recommendation
Add explicit host-boundary delimiters to every `insteadOf` key generated in `helpers/url/gitauth.go`:
- For `ssh://git@<host>` entries in `sshInsteadOfs`, either append a trailing `/` (and adjust the rewritten suffix accordingly) or otherwise ensure git matches on the full authority, not a bare prefix.
- For the primary HTTPS insteadOf key in `GetInsteadOfs` and `repoBaseInsteadOf`, use `baseURL` with a trailing `/` instead of `trimmed(baseURL)`, consistent with how the scp-style `git@<host>:` entry already protects itself with a trailing colon.
- Add a regression test asserting that a URL like `ssh://git@<host>.attacker.com/x` is **not** rewritten by the generated insteadOf entries.

### Proof of Concept
Go unit test in `helpers/url/gitauth_test.go` (style matching existing `TestGetInsteadOfs`):
```go
func TestSSHInsteadOfs_NoHostBoundaryLeak(t *testing.T) {
    c := defaultConfig()
    c.GitSubmoduleForceHTTPS = true
    h := NewGitAuthHelper(c, true)
    insteadOfs, err := h.GetInsteadOfs()
    require.NoError(t, err)

    attackerURL := "ssh://git@" + c.Server.Host + ".attacker.com/x.git"
    for _, io := range insteadOfs {
        // io[1] is the insteadOf "old" key; assert attackerURL does not
        // start with it unless followed by a host-boundary character.
        if strings.HasPrefix(attackerURL, io[1]) {
            boundary := attackerURL[len(io[1])]
            assert.True(t, boundary == '/' || boundary == ':',
                "insteadOf key %q unsafely matches attacker host in %q", io[1], attackerURL)
        }
    }
}
```
This test currently fails for the `ssh://git@gitlab.example.com` entry, proving the prefix collision. A full integration-level PoC extends `TestCredSetup`/submodule tests (`executors/shell/shell_integration_test.go`) with a crafted `.gitmodules` submodule URL of `ssh://git@gitlab.com.attacker.example/x.git` (matching the test's `CI_SERVER_HOST: "gitlab.com"`), and asserts that the token never appears in a request destined for `attacker.example`.

func (h *GitAuthHelper) repoBaseInsteadOf() (*[2]string, error) {
	repoURL, err := url.Parse(h.config.RepoURL)
	if err != nil || !isHTTP(repoURL) {
		return nil, err
	}

	base := *repoURL
	base.Path = ""

	authed, err := h.applyAuth(&base)
	if err != nil {
		return nil, err
	}

	base.User = nil

	return &[2]string{trimmed(authed), trimmed(&base)}, nil
}

func (h *GitAuthHelper) sshInsteadOfs(baseURL string) [][2]string {
	if !h.config.GitSubmoduleForceHTTPS {
		return nil
	}

	host := h.config.Server.EffectiveSSHHost()
	port := h.config.Server.SSHPort

	if port == "" || port == "22" {
		return [][2]string{
			{baseURL + "/", fmt.Sprintf("git@%s:", host)},
			{baseURL, fmt.Sprintf("ssh://git@%s", host)},
		}
	}

	return [][2]string{
		{baseURL, fmt.Sprintf("ssh://git@%s:%s", host, port)},
	}
}
