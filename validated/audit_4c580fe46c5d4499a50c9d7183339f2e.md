### No vulnerability found for this question.

**Analysis:** In `w-near/src/w_near.rs::near_deposit`, the order of operations is: (1) assert `amount > 0`, (2) if unregistered, assert `amount >= storage_balance_bounds().min.0` **before** any state mutation, (3) only then call `internal_register_account` and subtract `min` from `amount`, (4) finally `internal_deposit` the remainder [1](#0-0) .

Because the `assert!(amount >= min)` check happens strictly before `internal_register_account`/`internal_deposit`, an attacker attaching less than `min` causes a panic with zero prior state writes — no partial accounting occurs. On NEAR, a panicking receipt causes the entire attached deposit to be automatically refunded by the protocol runtime, so no NEAR is retained by the contract and no wNEAR is minted, preserving the "rejected deposit ⇒ no state change, no retained NEAR" invariant.

For the "exactly `min`" case, the check passes (`amount >= min` is true), the account is registered, `amount` is reduced by exactly `min`, leaving `0` to be deposited via `internal_deposit`. The attacker's minimum-amount contribution is fully and correctly consumed as storage payment for registration; zero wNEAR is minted for it, so `ft.total_supply` and the NEAR balance remain in lockstep — no unbacked wNEAR is created.

There is no code path here where partial accounting runs and then a later assertion aborts, since the size check strictly precedes any mutation. This does not match the claimed exploit.

    pub fn near_deposit(&mut self) {
        let mut amount = env::attached_deposit();
        assert!(amount > 0, "Requires positive attached deposit");
        let account_id = env::predecessor_account_id();
        if !self.ft.accounts.contains_key(&account_id) {
            // Not registered, register if enough $NEAR has been attached.
            // Subtract registration amount from the account balance.
            assert!(
                amount >= self.ft.storage_balance_bounds().min.0,
                "ERR_DEPOSIT_TOO_SMALL"
            );
            self.ft.internal_register_account(&account_id);
            amount -= self.ft.storage_balance_bounds().min.0;
        }
        self.ft.internal_deposit(&account_id, amount);
        log!("Deposit {} NEAR to {}", amount, account_id);
    }
