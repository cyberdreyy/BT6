### Title
Legacy zip extractor performs no path-traversal validation on zip entry names, allowing archive extraction outside the job workspace - (File: helpers/archives/zip_extract.go, helpers/archives/path_check_helper.go)

### Summary
`isPathAGitDirectory`/`errorIfGitDirectory` in `helpers/archives/path_check_helper.go` only checks whether an extracted entry's first path component is `.git`; it performs no check against `..` traversal or absolute paths. `extractZipFile` in `helpers/archives/zip_extract.go` then calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and `os.OpenFile(file.Name, ...)` directly with the attacker-controlled `file.Name` from the zip entry, with no confinement to an extraction root.

### Finding Description
The call chain `ExtractZipFile -> ExtractZipArchive -> errorIfGitDirectory(file.Name) -> extractZipFile -> os.MkdirAll/os.OpenFile(file.Name)` is confirmed in `helpers/archives/zip_extract.go` (lines 61-96) and `helpers/archives/path_check_helper.go` (lines 13-19). `isPathAGitDirectory` only inspects `parts[0]` after splitting on the OS separator, so it cannot and does not stop `../` sequences or absolute paths — its sole purpose is warning about accidental `.git` overwrite, not path-traversal defense.

Crucially, this legacy zip codepath (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`, wired via `NewExtractor`/`archivers`/`extractors` maps in `commands/helpers/archive/archive.go`) is a registered `Extractor` for the `zip` `Format`, used by both `CacheExtractorCommand.Execute` and `ArtifactsDownloaderCommand.Execute` (`commands/helpers/cache_extractor.go` line 655, `commands/helpers/artifacts_downloader.go` line 131) — i.e., real cache/artifact extraction paths reachable by any pipeline author who controls what gets uploaded as an artifact or cache. Unlike the sibling extractors in this codebase — `tarzstd` (`commands/helpers/archive/tarzstd/tarzstd_extractor.go` lines 58-64, which computes `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects paths not prefixed by `e.dir`) and `fastzip` (which delegates to the `saracen/fastzip` library, known to perform path-confinement internally) — the `ziplegacy`/`archives.ExtractZipArchive` code path **never joins entry names to the extraction directory (`e.dir`) at all**. It operates purely on `file.Name` relative to the process's current working directory, confirmed by the test comment in `commands/helpers/archiver_test.go` line 68: `// hack: legacy archiver require being in the correct working dir`.

This means a crafted zip entry named `../../victim-project/cache/poison` (or an absolute path) will cause `os.MkdirAll` to create directories, and `os.OpenFile` to write a file, outside of the extraction directory the caller intended — landing wherever the relative traversal resolves from the runner process's current directory, which for job/cache extraction is the job's build directory tree. Since GitLab Runner reuses a shared builds/cache root across jobs on the same runner (non-Docker executors, or Docker executors sharing a cache volume), a `../` sequence can reach sibling project directories under that shared root.

### Impact Explanation
On runner configurations where shell/custom/SSH executors (or Docker executors with `--docker-privileged`/shared cache volumes) reuse a common builds/cache directory across concurrent or sequential jobs, a pipeline author who controls a job's cache or artifact archive can plant files or overwrite files (e.g., hook scripts, source files) in another project's cache/build directory that persists after the malicious job finishes or is cancelled — cross-project cache poisoning as scoped. This can lead to code execution in a victim project's subsequent job if the planted file is later sourced/executed (e.g., a build script, `.bashrc`, or a file consumed by the victim's build steps).

### Likelihood Explanation
Feasible and repeatable by any authenticated pipeline author: they only need to control the contents of an artifact/cache zip that the runner will extract (trivial — `artifacts:paths` and `cache:paths` are fully user controlled, and the zip format is a standard structure any user-supplied build step could construct with a raw `zip` invocation before upload isn't even required — the CI job needs only to place a file with a `../`-containing name into the workspace before the runner's own archiver zips it, or an attacker with API-level artifact upload access could upload a hand-crafted zip directly). The extraction happens on every job when cache/artifacts are restored, so the attack surface is exercised routinely. It requires: (1) the runner selects the legacy zip extractor path (default `zip` format, or when `fastzip`/`FF_USE_FASTZIP` isn't in effect), and (2) a shared builds/cache root across jobs (common on shell/ssh/custom executors, and configurable on Docker executors), matching the described "multi-tenant" precondition.

### Recommendation
In `helpers/archives/zip_extract.go`, before calling `extractZipFile`, resolve and validate each entry against an explicit extraction root: compute `target := filepath.Join(root, file.Name)`, reject if `!strings.HasPrefix(filepath.Clean(target)+string(filepath.Separator), filepath.Clean(root)+string(filepath.Separator))` (mirroring the confinement check already present in `tarzstd_extractor.go`), and reject/skip entries with absolute paths or resolving outside `root`. `ExtractZipArchive`/`ExtractZipFile` should accept an explicit `dir` parameter rather than relying on the process's current working directory, aligning the legacy zip extractor's behavior with `fastzip` and `tarzstd`. `isPathAGitDirectory` should remain a separate, additional check — it is not a substitute for path-confinement.

### Proof of Concept
```go
func TestExtractZipArchivePathTraversal(t *testing.T) {
    tempFile, err := os.CreateTemp("", "archive")
    require.NoError(t, err)
    defer os.Remove(tempFile.Name())

    zw := zip.NewWriter(tempFile)
    f, err := zw.Create("../victim-project/cache/poison")
    require.NoError(t, err)
    _, err = f.Write([]byte("malicious"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())
    tempFile.Close()

    workDir := t.TempDir()
    require.NoError(t, os.Chdir(workDir))

    err = ExtractZipFile(tempFile.Name())
    require.NoError(t, err) // current code returns no error, silently escaping

    // Assert the file did NOT land outside workDir
    escaped := filepath.Join(filepath.Dir(workDir), "victim-project/cache/poison")
    _, statErr := os.Stat(escaped)
    assert.True(t, os.IsNotExist(statErr), "zip entry escaped extraction root: %s", escaped)
}
```
Expected (post-fix) behavior: `ExtractZipArchive`/`ExtractZipFile` should either return an error for the traversal entry or confine it under the intended root, and the assertion that no file exists at the escaped path should pass; currently, the file is created outside the root, proving the bug. func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {

		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
