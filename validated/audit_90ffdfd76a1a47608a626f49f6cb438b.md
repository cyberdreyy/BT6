### Title
ziplegacy extractor extracts zip entries relative to CWD without any path-traversal/chroot check, ignoring the `dir` argument entirely - (File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go)

### Summary
`ziplegacy.extractor.Extract` calls `archives.ExtractZipArchive(zr)` and never uses `e.dir` at all, and the downstream `extractZipFile`/`extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry` helpers in `helpers/archives/zip_extract.go` create files using `file.Name` verbatim (relative to the process's current working directory), with no `filepath.Abs`/`strings.HasPrefix` containment check like `tarzstd.extractor.Extract` performs. This is a genuine, code-confirmed asymmetry between the two extractors.

### Finding Description
- `commands/helpers/artifacts_downloader.go` downloads a job's own artifact, detects the format via `openArchive` (zip is the default/fallback format), and calls `archive.NewExtractor(format, f, size, wd)` then `extractor.Extract(ctx)`. [1](#0-0) 
- For the zip format, `ziplegacy.NewExtractor` stores `dir` in the `extractor` struct but `Extract` never references `e.dir`; it only builds a `zip.Reader` and calls `archives.ExtractZipArchive(zr)`. [2](#0-1) 
- `ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)`, which uses `file.Name` directly for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.Mkdir(file.Name, ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(data, file.Name)` — all relative to the process's current directory, with **no** `filepath.Abs`/`filepath.Join(dir, ...)`/`strings.HasPrefix` containment check anywhere in this path. [3](#0-2) 
- The only guard present is `errorIfGitDirectory`, which merely warns/logs if an entry's first path component is `.git`; it does not block `..` traversal or absolute paths. [4](#0-3) 
- By contrast, `tarzstd.extractor.Extract` computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it unless `strings.HasPrefix(path, e.dir+string(filepath.Separator))` or `path == e.dir`. [5](#0-4) 
- Attacker-controlled input: a job author fully controls the content of the artifact zip it uploads to GitLab (via `artifacts:` config), so it can craft zip entries with names like `../../etc/cron.d/x` or absolute paths. When the runner (or a different, later job/pipeline on the same host, e.g. via `dependencies:`/artifact download in another job) downloads and extracts that artifact through `artifacts-downloader`, the zip path is used verbatim, allowing files to be written outside the intended extraction directory (`wd`), i.e., a "zip slip" vulnerability.
- Existing tests only assert benign extraction (`temporary_file.txt`) and the `.git` warning path — there is no test covering `../` traversal for zip extraction, confirming the gap is untested/unguarded. [6](#0-5) 

### Impact Explanation
An unprivileged pipeline author can craft a job artifact (zip) containing entries with `../` (or absolute) paths. When that artifact is later extracted by the Runner's `artifacts-downloader` helper (e.g., when a dependent job in the same pipeline/host downloads it, or in shell/host-based executors where the extraction directory is a real path on the host filesystem), the extractor will write files outside the intended build directory (`wd`), anywhere the runner process has filesystem permissions to write. This is a classic zip-slip / path-traversal write, which can overwrite arbitrary files reachable by the runner process (e.g., other jobs' workspace files, shared cache directories, or — depending on executor/host permissions — files outside the job's sandbox), violating the invariant that "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
This is fully reachable with attacker-controlled data alone: any GitLab user who can define a `.gitlab-ci.yml` job with an `artifacts:` block controls the bytes of the resulting zip archive (via job script output) and hence can inject crafted file names before GitLab Runner uploads/downloads/extracts it. No admin privileges, leaked keys, or malicious peers are required — a normal pipeline author is sufficient. The bug is deterministic and repeatable: the same crafted archive will always bypass containment because there is no check at all in this code path (whereas the parallel tar/zstd path has one), which strongly indicates a real logic gap rather than a false positive.

### Recommendation
Add the same containment check used in `tarzstd.extractor.Extract` to the zip extraction path: resolve each entry's target path with `filepath.Abs(filepath.Join(e.dir, file.Name))` and reject the entry (or the whole extraction) if the resolved path does not have `e.dir+string(filepath.Separator)` as a prefix (or equal `e.dir`). Concretely:
- Thread `e.dir` through `ziplegacy.extractor.Extract` into `archives.ExtractZipArchive`/`extractZipFile` (e.g., add a `dir` parameter and join/validate each `file.Name` against it), instead of ignoring the passed `dir`.
- Apply the same validation to symlink targets (`extractZipSymlinkEntry`) to prevent symlink-based escapes as well.
- Add a regression test (as in `tarzstd_extractor_test.go`, if present) that crafts a zip with a `../` entry and asserts extraction is rejected or contained, mirroring the tar+zstd behavior.

### Proof of Concept
```go
// helpers/archives/zip_extract_traversal_test.go
package archives

import (
	"archive/zip"
	"io"
	"os"
	"path/filepath"
	"testing"

	"github.com/stretchr/testify/require"
)

func TestExtractZipFile_PathTraversal(t *testing.T) {
	dir := t.TempDir()
	outsideDir := t.TempDir() // simulate directory outside the intended extraction root

	zipPath := filepath.Join(dir, "evil.zip")
	f, err := os.Create(zipPath)
	require.NoError(t, err)

	zw := zip.NewWriter(f)
	// Craft a traversal entry that should land in outsideDir/pwned.txt
	rel, err := filepath.Rel(dir, filepath.Join(outsideDir, "pwned.txt"))
	require.NoError(t, err)
	w, err := zw.Create(rel) // e.g. "../<outsideDirName>/pwned.txt"
	require.NoError(t, err)
	_, err = io.WriteString(w, "pwned")
	require.NoError(t, err)
	require.NoError(t, zw.Close())
	require.NoError(t, f.Close())

	// Change CWD to `dir` to simulate artifacts-downloader running with wd == dir
	oldWd, _ := os.Getwd()
	defer os.Chdir(oldWd)
	require.NoError(t, os.Chdir(dir))

	err = ExtractZipFile(zipPath)
	require.NoError(t, err) // currently succeeds with no traversal check

	// BUG: file ends up outside `dir`
	_, statErr := os.Stat(filepath.Join(outsideDir, "pwned.txt"))
	require.NoError(t, statErr, "expected file to escape extraction dir, demonstrating zip-slip")
}
```
Expected result today: the test passes, proving `pwned.txt` is written into `outsideDir` despite extraction being "intended" for `dir` — confirming no containment check exists in the zip legacy path, unlike `tarzstd_extractor.go`'s `filepath.Abs`/`strings.HasPrefix` guard. A differential test can additionally craft the identical `../` entry as a tar+zstd archive and show `tarzstd.extractor.Extract` returns the `"cannot be extracted outside of chroot"` error while `ziplegacy.extractor.Extract` (via `ExtractZipArchive`) succeeds and writes outside `dir`.

type extractor struct {
	r    io.ReaderAt
	size int64
	dir  string
}

// NewExtractor returns a new Zip Extractor.
func NewExtractor(r io.ReaderAt, size int64, dir string) (archive.Extractor, error) {
	return &extractor{r: r, size: size, dir: dir}, nil
}

// Extract extracts files from the reader to the directory passed to
// NewZipExtractor.
func (e *extractor) Extract(ctx context.Context) error {
	zr, err := zip.NewReader(e.r, e.size)
	if err != nil {
		return err
	}

	return archives.ExtractZipArchive(zr)
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
