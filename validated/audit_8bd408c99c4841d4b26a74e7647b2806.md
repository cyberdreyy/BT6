### Title
Missing validation of `requestedURI` in `Session.proxyHandler` allows escaping the intended Kubernetes service-proxy scope - (File: session/session.go)

### Summary
`Session.proxyHandler` extracts `serviceName`, `port`, and `requestedURI` from the raw client-supplied path via `parseProxyParams` and forwards `requestedURI` unmodified to `ConnectionHandler.ProxyRequest` [1](#0-0) . Neither `parseProxyParams` nor the Kubernetes executor's proxy path performs any sanitization of `requestedURI` for traversal sequences before it is appended to a Kubernetes API "services/.../proxy" request path.

### Finding Description
`parseProxyParams` only validates that `service` and `port` are non-empty; the remainder of the path (`requestedURI`) is passed through verbatim, including any `/`, `..`, or encoded traversal segments [2](#0-1) . `proxyHandler` then hands this untouched string straight to `serviceProxy.ConnectionHandler.ProxyRequest(w, r, requestedURI, port, serviceProxy.Settings)` [3](#0-2) .

In the Kubernetes executor implementation, `requestedURI` is appended via `.Suffix(requestedURI)` to a `rest.Request` that is otherwise scoped to `namespaces/{ns}/services/{scheme}:{svc}:{port}/proxy` [4](#0-3) , and the resulting request is executed with the Runner's own Kubernetes client/service-account credentials, not the job's own credentials [5](#0-4) . No `path.Clean`, traversal rejection, or allow-listing of characters is applied to `requestedURI` anywhere in this repository's code before it is concatenated into the outbound Kubernetes API request path.

Because the runner's own Kubernetes client-go REST client is used to make this call, and that client typically carries broader RBAC permissions than the job pod's own service account, a `requestedURI` value crafted with traversal sequences (e.g. `../../secrets`, `../../../pods/other-pod/log`) that survives whatever normalization client-go's `Suffix`/path-joining performs could redirect the outbound request to a different API sub-resource than the intended service's `/proxy` endpoint. I was unable to inspect the vendored `client-go` `rest.Request.Suffix`/URL-building implementation from this index to confirm exactly how (or whether) it normalizes `..` segments before constructing the final request URL, so the degree to which this specific dependency neutralizes traversal could not be fully verified from the code available here. What is verifiable in-repo is that Runner performs **no defense-in-depth validation whatsoever** on `requestedURI` before using it to build a privileged, cross-boundary API request.

### Impact Explanation
If the downstream traversal is not fully neutralized by the vendored HTTP client, an attacker who legitimately holds a valid session token (e.g., a project member using GitLab's port-forwarding/service-proxy or terminal features for their own job) could use a crafted `requestedURI` to make the Runner's privileged Kubernetes client issue requests against other API resources in the job's namespace (secrets, other pods, other services) rather than being confined to the specific service's proxy port that GitLab granted access to. This would violate the invariant that a job proxy session must stay scoped to its own service/port and not access other workloads' resources using Runner's own elevated credentials.

### Likelihood Explanation
Preconditions: attacker must already hold a valid session `Token` for a running job that uses the Kubernetes executor with service proxying enabled (multi-container services with ports, e.g., via GitLab's "Web terminal"/port-forwarding features) — this is a normal, unprivileged capability for pipeline authors on projects where these features are enabled. The attacker fully controls the HTTP path sent to the session's `/proxy/` endpoint, so triggering the code path requires no special access beyond a legitimate session, and it is fully repeatable/scriptable. The extent of exploitability, however, hinges on unverified vendored `client-go` path-joining behavior, so this should be validated end-to-end.

### Recommendation
Sanitize `requestedURI` before use: apply `path.Clean` on the incoming URI and reject the request (404/400) if the cleaned result differs from the original in an unsafe way, starts with `..`, or is an absolute path, i.e., ensure the resolved suffix cannot escape the `namespaces/{ns}/services/{name}/proxy` prefix. This check should be added both in `parseProxyParams`/`proxyHandler` (`session/session.go`) as a general defense and again in `executors/kubernetes/service_proxy.go`'s `serviceEndpointRequest`, immediately before calling `.Suffix(requestedURI)`, so the protection does not depend solely on assumptions about the vendored `client-go` library's internal path handling.

func (s *Session) proxyHandler(w http.ResponseWriter, r *http.Request) {
	serviceName, port, requestedURI, ok := parseProxyParams(strings.TrimPrefix(r.URL.Path, s.Endpoint+"/proxy/"))
	if !ok {
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	logger := s.log.WithField("uri", r.RequestURI)
	logger.Debug("Proxy session request")

	serviceProxy := s.proxyPool[serviceName]
	if serviceProxy == nil {
		logger.Warn("Proxy not found")
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	if serviceProxy.ConnectionHandler == nil {
		logger.Warn("Proxy connection handler is not defined")
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	serviceProxy.ConnectionHandler.ProxyRequest(w, r, requestedURI, port, serviceProxy.Settings)

// parseProxyParams returns the service, port and requestedURI
// from a proxy path. Service and port are not optional.
func parseProxyParams(path string) (service string, port string, uri string, ok bool) {
	p := strings.SplitN(path, "/", 3)
	switch len(p) {
	case 2:
		return p[0], p[1], "", p[0] != "" && p[1] != ""
	case 3:
		return p[0], p[1], p[2], p[0] != "" && p[1] != ""
	}
	return "", "", "", false
}

func (s *executor) serviceEndpointRequest(
	verb, serviceName, requestedURI string,
	port proxy.Port,
) (*rest.Request, error) {
	scheme, err := port.Scheme()
	if err != nil {
		return nil, err
	}

	// kubeAPI: ignore
	result := s.kubeClient.CoreV1().RESTClient().Verb(verb).
		Namespace(s.pod.Namespace).
		Resource("services").
		SubResource("proxy").
		Name(k8net.JoinSchemeNamePort(scheme, serviceName, strconv.Itoa(port.Number))).
		Suffix(requestedURI)

	return result, nil
}

	}

	body, err := req.Stream(s.Context)
	if err != nil {
		message, code := handleProxyHTTPErr(err, logger)
		w.WriteHeader(code)

		if message != "" {
			_, _ = io.WriteString(w, message)
		}
		return
	}

	w.WriteHeader(http.StatusOK)

}
