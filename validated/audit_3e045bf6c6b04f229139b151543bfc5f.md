### Title
Unsanitized `requestedURI` passed into `rest.Request.Suffix()` allows path traversal out of the `services/.../proxy` subresource - ([File: executors/kubernetes/service_proxy.go])

### Summary
`executor.serviceEndpointRequest` builds a Kubernetes REST request scoped to `services/<name>/proxy` in `s.pod.Namespace`, then appends the attacker-influenced `requestedURI` verbatim via `.Suffix(requestedURI)` with no validation, normalization, or rejection of `..`/encoded traversal sequences. [1](#0-0)  The `requestedURI` originates from `session.parseProxyParams`, which simply splits `r.URL.Path` on `/` and returns everything after `service/port/` unmodified (including embedded `/`, `..`, etc.) as the URI. [2](#0-1) 

### Finding Description
The call chain is: `Session.proxyHandler` → `parseProxyParams(strings.TrimPrefix(r.URL.Path, ...))` → `serviceProxy.ConnectionHandler.ProxyRequest(w, r, requestedURI, port, ...)` → `executor.ProxyRequest` → `proxyHTTPRequest`/`proxyWSRequest` → `s.serviceEndpointRequest(...)` → `req.Stream(s.Context)`. [3](#0-2) [4](#0-3) 

`parseProxyParams` only validates that `service` and `port` are non-empty; the URI remainder (`p[2]`) is passed through unchanged, including any `../`, `%2e%2e`, or extra path segments the job author encodes into the proxied request path. [5](#0-4)  `serviceEndpointRequest` performs zero sanitization before calling `Suffix(requestedURI)` on a request that already has `Namespace(s.pod.Namespace).Resource("services").SubResource("proxy").Name(...)` set. [6](#0-5)  I found no `path.Clean`, `filepath.Clean`, or other sanitization applied to `requestedURI` anywhere in `executors/kubernetes` before this call.

The `serviceName` lookup does provide one layer of scoping: `s.proxyPool[serviceName]` must match a service the job itself declared, and the `Namespace` is hardcoded to `s.pod.Namespace` (the job's own namespace) rather than being attacker-supplied. [7](#0-6)  This means an attacker cannot directly choose an arbitrary namespace or a completely unrelated service name — but it does not stop `requestedURI` itself from containing traversal sequences that, once resolved by `k8s.io/client-go`'s internal path-joining logic in `Suffix()`/`URL()`, can rewrite the trailing portion of the request path (e.g., turning `.../services/http:svc:80/proxy/<uri>` into `.../pods/<other-pod>/log` within the same namespace), redirecting the call away from the intended `services/.../proxy` subresource toward a different REST resource/subresource that the request was never meant to target.

**Verification caveat**: The exact traversal-collapsing behavior depends on the vendored `k8s.io/client-go` `rest.Request.Suffix`/`URL()` implementation, which is not present in this repo's index (no vendor directory, dependency pulled via Go modules), so I could not directly confirm from repository contents whether/how many path segments can be popped across the `Namespace`/`Resource`/`SubResource`/`Name` boundary versus the `Suffix` boundary. What I *can* confirm concretely from this repository is that GitLab Runner's own code performs **no validation whatsoever** on `requestedURI` before it is handed to the Kubernetes client — that root-cause gap is real and unambiguous.

### Impact Explanation
If client-go's internal path joining collapses `..` sequences across the pre-built resource path (a well-documented behavior of `path.Join`/`path.Clean` used in `rest.Request`), a job could redirect its own "service proxy" session traffic to other subresources of pods it already has access to within its own namespace (e.g., `pods/<name>/log`, `exec`, `portforward`) that were never intended to be reachable via this path, and potentially — depending on how many segments can be traversed and namespace RBAC scoping of the Runner's service account — resources in namespaces beyond the job's own. This would violate the invariant that "a normal job must not escape its executor sandbox or access another project's workload."

### Likelihood Explanation
Preconditions are low-bar: the attacker only needs to be an ordinary GitLab user able to trigger a CI job with a `services:` definition and control the request path sent to the runner's session/proxy endpoint (which GitLab's Web IDE / port-forwarding feature constructs from job-controlled service/port data). No admin or cluster-compromise is required. The missing-validation root cause is unconditionally reachable on every proxied HTTP/WebSocket request through this code path.

### Recommendation
Validate and normalize `requestedURI` in `session.parseProxyParams` or at the start of `executor.serviceEndpointRequest`: reject any URI containing `..` path segments (after `path.Clean` and URL-decoding), reject absolute paths, and explicitly assert that the cleaned suffix does not begin with `../` relative to the intended `services/<name>/proxy` prefix before calling `.Suffix()`. Add a unit test asserting the final `rest.Request.URL().Path` always begins with `/api/v1/namespaces/<pod.Namespace>/services/` for any crafted `requestedURI` input.

### Proof of Concept
```go
func TestServiceEndpointRequest_RejectsPathTraversal(t *testing.T) {
    fakeClient := fake.NewSimpleClientset()
    ex := &executor{
        kubeClient: fakeClient,
        pod:        &api.Pod{ObjectMeta: metav1.ObjectMeta{Namespace: "job-ns", Name: "job-pod"}},
    }

    maliciousURIs := []string{
        "../../pods/other-pod/log",
        "..%2f..%2fpods/other-pod/exec",
        "../../../namespaces/other-ns/pods/secret-pod/log",
    }

    for _, uri := range maliciousURIs {
        req, err := ex.serviceEndpointRequest(http.MethodGet, "svc", uri, proxy.Port{Number: 80, Protocol: "http"})
        require.NoError(t, err)
        u := req.URL()
        assert.True(t, strings.HasPrefix(u.Path, "/api/v1/namespaces/job-ns/services/"),
            "requestedURI %q escaped intended services/proxy subresource path, got %q", uri, u.Path)
    }
}
```
Expected (pre-fix) result: for traversal payloads with enough `../` segments, the assertion fails because `u.Path` resolves to `/api/v1/namespaces/job-ns/pods/other-pod/log` (or further, `/api/v1/namespaces/other-ns/...`), demonstrating the request was redirected away from the `services/.../proxy` subresource.

func (s *executor) serviceEndpointRequest(
	verb, serviceName, requestedURI string,
	port proxy.Port,
) (*rest.Request, error) {
	scheme, err := port.Scheme()
	if err != nil {
		return nil, err
	}

	// kubeAPI: ignore
	result := s.kubeClient.CoreV1().RESTClient().Verb(verb).
		Namespace(s.pod.Namespace).
		Resource("services").
		SubResource("proxy").
		Name(k8net.JoinSchemeNamePort(scheme, serviceName, strconv.Itoa(port.Number))).
		Suffix(requestedURI)

	return result, nil

func (s *Session) proxyHandler(w http.ResponseWriter, r *http.Request) {
	serviceName, port, requestedURI, ok := parseProxyParams(strings.TrimPrefix(r.URL.Path, s.Endpoint+"/proxy/"))
	if !ok {
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	logger := s.log.WithField("uri", r.RequestURI)
	logger.Debug("Proxy session request")

	serviceProxy := s.proxyPool[serviceName]
	if serviceProxy == nil {
		logger.Warn("Proxy not found")
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	if serviceProxy.ConnectionHandler == nil {
		logger.Warn("Proxy connection handler is not defined")
		http.Error(w, http.StatusText(http.StatusNotFound), http.StatusNotFound)
		return
	}

	serviceProxy.ConnectionHandler.ProxyRequest(w, r, requestedURI, port, serviceProxy.Settings)
}

// parseProxyParams returns the service, port and requestedURI
// from a proxy path. Service and port are not optional.
func parseProxyParams(path string) (service string, port string, uri string, ok bool) {
	p := strings.SplitN(path, "/", 3)
	switch len(p) {
	case 2:
		return p[0], p[1], "", p[0] != "" && p[1] != ""
	case 3:
		return p[0], p[1], p[2], p[0] != "" && p[1] != ""
	}
	return "", "", "", false
}
