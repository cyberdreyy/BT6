### Title
Zip path traversal in `extractZipFileEntry`/`extractZipFile` allows writes outside extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` and `extractZipFileEntry` use `zip.File.Name` verbatim (only creating parent directories with `os.MkdirAll(filepath.Dir(file.Name), ...)` and writing via `os.OpenFile(file.Name, ...)`) without validating that the resolved path stays inside the intended extraction root. Neither `ExtractZipArchive` nor the `ziplegacy.extractor.Extract()` wrapper (which receives a `dir` parameter but never uses it) enforces any containment, so a malicious cache/artifact zip with an entry name such as `../../other-project/.env` will be written relative to the process's current working directory, escaping the job's build root.

### Finding Description
The extraction call chain is: `CacheExtractorCommand.Execute` (commands/helpers/cache_extractor.go:655-663) calls `archive.NewExtractor(format, f, size, wd)` → `ziplegacy.NewExtractor` (commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:20-22) stores `dir` in the `extractor` struct but `Extract()` (lines 26-32) never references `e.dir`; it only calls `archives.ExtractZipArchive(zr)`.

`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `zip.File` entries and only checks `errorIfGitDirectory` (helpers/archives/path_check_helper.go:13-31), which merely rejects paths starting with `.git` — it does not detect or reject `..` traversal segments or absolute paths.

`extractZipFile` (zip_extract.go:61-83) does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and dispatches to `extractZipFileEntry` (lines 41-59), which does `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` at line 51 using the raw, attacker-controlled `file.Name` with no `filepath.Clean`, no join-and-verify against a base directory, and no rejection of `..` components or absolute paths. The `dir` value that was supposed to scope extraction (`wd`, the job's working directory) is silently discarded by the ziplegacy extractor, so paths are resolved solely relative to the current process working directory using whatever string is embedded in the zip's central directory.

An unprivileged pipeline author fully controls the contents of caches (via `cache:` config with attacker-controlled `paths:`) and can hand-craft a raw zip file (bypassing the runner's own archiver, since the download+extract path only requires a valid zip stream, not one produced by the runner's own archiver) containing an entry named e.g. `../../other-project-dir/.env` or `../../../home/gitlab-runner/.ssh/authorized_keys`. When another job on the same shared-filesystem runner (e.g. shell executor, or any executor where the builds directory sits on host-writable storage) downloads/extracts that cache, the write escapes the intended build root.

### Impact Explanation
On a runner where multiple jobs/projects share the same filesystem root (this is the documented trust model for the shell executor, and also occurs for concurrently/sequentially scheduled jobs sharing a builds directory), a crafted cache/artifact zip can write files outside the job's build directory — e.g., overwriting or planting files in a sibling project's workspace, potentially exfiltrating secrets placed there by another job's `.env`/config files, or corrupting arbitrary files reachable by the runner process user. This matches the scoped impact of cross-project file read/write via path traversal.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs the ability to run an ordinary job with `cache:` (or artifact) configuration and control over the archive's contents (a hand-built zip via a `before_script` step, or simply supplying pre-built zip bytes as the cache payload). No admin privileges, no third-party compromise, and no reliance on the shell executor being explicitly told to trust a shared host beyond its already-documented shared-filesystem model — this is a straight file write path bug, not merely a restatement of "shell executor trusts other jobs." Every zip cache/artifact extraction on shell/docker(bind-mount)/any shared-storage-based runner takes this exact code path.

### Recommendation
In `extractZipFile`/`extractZipFileEntry` (helpers/archives/zip_extract.go), and in `ziplegacy.extractor.Extract()`, resolve each `zip.File.Name` against the actual extraction root (the `dir` value already passed to `NewExtractor` but currently unused), e.g. `target := filepath.Join(root, filepath.Clean("/"+file.Name))` or use `filepath.Rel`/`strings.HasPrefix` after `filepath.Clean` to reject any entry whose cleaned path is not `root` or a descendant of `root` (also reject absolute paths and paths starting with `..`). This mirrors the well-known "zip slip" mitigation. `ExtractZipArchive` should be changed to accept and enforce this root, and `errorIfGitDirectory`-style checks should be supplemented with a generic path-containment check applied to every entry before `os.MkdirAll`/`os.OpenFile`/`os.Symlink` calls.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    root := t.TempDir()
    outsideMarker := filepath.Join(filepath.Dir(root), "escaped.txt")
    defer os.Remove(outsideMarker)

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../escaped.txt")
    _, _ = w.Write([]byte("pwned"))
    _ = zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    _ = os.Chdir(root)
    defer os.Chdir(wd)

    err := archives.ExtractZipArchive(zr)
    assert.NoError(t, err) // current code returns no fatal error

    _, statErr := os.Stat(outsideMarker)
    assert.False(t, os.IsNotExist(statErr), "file must not be written outside the extraction root")
}
```
Expected (current, vulnerable) result: `escaped.txt` is created one directory above `root`, proving traversal. func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
