### Title
View-role users can enumerate `/v2/chains/*/nodes` and `/v2/nodes` and obtain raw RPC node configuration (including embedded URL credentials) with no role check - ([File: core/web/router.go])

### Summary
`chains.GET` and `nodes.GET` routes are registered under the `authv2` group, which only requires authentication (`auth.Authenticate`) and does not wrap the handlers with `auth.RequiresEditRole` or `auth.RequiresAdminRole` like nearly every other sensitive route in the same file. As a result, any authenticated user regardless of role, including the lowest `view` role, can call these endpoints and retrieve the full node configuration returned by `presenters.NewNodeResource`, which is built directly from `types.NodeStatus` without redacting the raw config string.

### Finding Description
In `core/web/router.go`, the chain/node routes are defined as: [1](#0-0) 

Unlike sibling routes in the same `authv2` block, e.g. `authv2.POST("/keys/vrf", auth.RequiresEditRole(...))`, `authv2.PATCH("/log", auth.RequiresAdminRole(...))`, or `authv2.DELETE("/nodes/evm/forwarders/:fwdID", auth.RequiresEditRole(...))`, the `chains.GET(...)` and `nodes.GET(...)` calls are registered with no `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper at all: [2](#0-1) 

The `authv2` group itself only enforces that *some* authenticated user (session or API token) is present - it does not check role: [3](#0-2) 

So a user with `UserRoleView` (the lowest privilege tier, meant to be read-only/non-sensitive) satisfies `auth.Authenticate` and reaches `nodesController.Index`: [4](#0-3) 

The handler builds `presenters.NodeResource` directly from `types.NodeStatus` via `presenters.NewNodeResource` with no field-level redaction logic in `nodes_controller.go`. `types.NodeStatus` (in `chainlink-common`) carries the node's raw config (typically the full TOML block a node operator configures per RPC node, including `WSURL`/`HTTPURL` fields). Many operators embed provider API keys or basic-auth credentials directly in these URLs (e.g., `https://mainnet.infura.io/v3/<API_KEY>` or `https://user:pass@host`). Because this endpoint requires no role check and the presenter performs no redaction, a `view`-role user (or any authenticated low-privilege API token holder) can read this data.

Compare this to `RequiresEditRole`, which explicitly exists to gate exactly this class of endpoint from `view`/`run` roles: [5](#0-4) 

### Impact Explanation
This is a role/authorization-bypass leading to secret/credential disclosure: an attacker who only holds `view`-role credentials (the most restricted authenticated tier) can pull RPC endpoint URLs for every configured chain/node, potentially harvesting embedded API keys or basic-auth credentials for third-party RPC providers (Infura/Alchemy/etc.) configured by the node operator. This maps to the Chainlink bounty "unauthorized disclosure of sensitive configuration/credentials via authorization bypass" impact class - it does not directly move funds or forge signatures, but it discloses secrets that could be used to abuse the operator's RPC provider quota/billing or pivot to further reconnaissance.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs a valid `view`-role user session or API token, the lowest privilege class in the CLI/UI (`clsessions.UserRoleView`), which is routinely handed out to auditors/read-only integrations. No admin, edit, or run privilege is required, and the request is a single unauthenticated-role-wise GET to `/v2/chains/evm/:network/:ID/nodes` or `/v2/nodes`. This is trivially repeatable and requires no race condition or timing dependency.

### Recommendation
Wrap the chain/node listing and show routes with `auth.RequiresEditRole` (or an appropriate minimum role) as done for other administrative/configuration endpoints:
```go
chains.GET("", auth.RequiresEditRole(paginatedRequest(chainController.Index)))
chains.GET("/:network", auth.RequiresEditRole(paginatedRequest(chainController.Index)))
chains.GET("/:network/:ID", auth.RequiresEditRole(chainController.Show))
nodes.GET("", auth.RequiresEditRole(paginatedRequest(nodesController.Index)))
nodes.GET("/:network", auth.RequiresEditRole(paginatedRequest(nodesController.Index)))
chains.GET("/:network/:ID/nodes", auth.RequiresEditRole(paginatedRequest(nodesController.Index)))
```
Additionally, add redaction of credentials embedded in `WSURL`/`HTTPURL`/config fields inside `presenters.NewNodeResource` so that even edit/admin-level responses do not leak raw secrets, and so that lower roles (if ever granted access) see a redacted representation instead of the raw connection string.

### Proof of Concept
Handler-level integration test plan (Go, using the existing `cltest`/`web` test harness pattern used elsewhere in `core/web/*_test.go`):
1. Set up a test app (`cltest.NewApplicationWithConfig`/`web.Router`) with one EVM chain/node configured with `HTTPURL` set to `https://user:supersecret@rpc.example.com/v3/APIKEYVALUE`.
2. Create three users with roles `admin`, `edit`, and `view` respectively via `clsessions`.
3. Authenticate as the `view`-role user (session cookie or API token via `X-API-KEY`/`X-API-SECRET`).
4. Issue `GET /v2/chains/evm/:network/:ID/nodes` (and `GET /v2/nodes`) with the `view` user's credentials.
5. Assert the response is `200 OK` (not `401`/`403`), proving the missing role wrapper, and that the JSON body's node `attributes` contain the literal `HTTPURL` string including `supersecret`/`APIKEYVALUE` in plaintext, proving the lack of redaction in `presenters.NewNodeResource`.
6. As a negative control, repeat the same request against `/v2/nodes/evm/forwarders` (which is `auth.RequiresEditRole`-protected) with the `view` user and assert it correctly returns `401 Unauthorized`, demonstrating the inconsistency.

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (n *nodesController[R]) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")
	network := c.Param("network")

	var nodes []types.NodeStatus
	var count int
	var err error

	relayers := n.relayers
	if network != "" {
		relayers = relayers.List(chainlink.FilterRelayersByType(network))
	}

	ctx := c.Request.Context()
	if id == "" {
		// fetch all nodes
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size)
	} else {
		// fetch nodes for chain ID
		// backward compatibility
		var rid types.RelayID
		err = rid.UnmarshalString(id)
		if err != nil {
			rid.ChainID = id
			rid.Network = network
		}
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size, rid)
	}

	resources := make([]R, 0, len(nodes))
	for _, node := range nodes {
		res := n.newResource(node)
		resources = append(resources, res)
	}

	paginatedResponse(c, "node", size, page, resources, count, err)
