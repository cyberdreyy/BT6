### Title
Floor-rounded 70% supermajority in `GlobalStateEvaluator::reached_agreement` lets signer global-state consensus (current miner / burn view) be adopted with less than the true 70% weight - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement`, which decides when a signer's peer-gossiped `StateMachineUpdate`s constitute an agreed-upon global state (current miner, burn view, protocol version, tx-replay set), computes the 70% quorum using integer floor division. The canonical 70% supermajority used for actual block-signature validation, `NakamotoBlockHeader::compute_voting_weight_threshold`, instead rounds the same fraction **up** (ceiling). These are two different implementations of what is supposed to be the same "70% of total signer weight" invariant, and they diverge whenever `total_weight * 7` is not a multiple of 10 — exactly the class of bug described in the report (a supermajority/invariant check computed with a simplified/inconsistent formula that silently permits a below-threshold state to be accepted as canonical).

### Finding Description
`NakamotoBlockHeader::compute_voting_weight_threshold` (the network's normative 70% threshold used both to build blocks and to verify them in `verify_signer_signatures`) rounds up: [1](#0-0) 

`GlobalStateEvaluator::reached_agreement`, used by `stacks-signer` to decide the global signer-state consensus (which miner is active, which burn view is canonical, which protocol version and tx-replay set are agreed), instead performs a plain floor division of the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`/10 fraction: [2](#0-1) 

`reached_agreement` is the sole gate for `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which fixes `current_miner`/`MinerState` and the transaction-replay set that the local signer treats as ground truth): [3](#0-2) [4](#0-3) 

Because the division truncates instead of rounding up, whenever `total_weight * 7` is not exactly divisible by 10, the number of votes required to "reach agreement" is one unit lower than the true ceiling-based 70% used everywhere else in the protocol (block signature verification, pre-commit threshold, acceptance threshold in `stacks-signer/src/v0/signer.rs`). For example, with `total_weight = 13`: `13*7/10 = 9` (floor) is accepted by `reached_agreement`, but `9/13 ≈ 69.2%`, strictly less than the intended 70% supermajority that `compute_voting_weight_threshold(13)` would compute (`ceil(9.1) = 10`, i.e. `10/13 ≈ 76.9%` required). The existing regression tests for `reached_agreement`/`reached_disagreement` in `libsigner/src/tests/signer_state.rs` only exercise `total_weight = 1_000_000_000`, which is exactly divisible by 10 in the relevant fraction, so the rounding discrepancy is untested and unnoticed: [5](#0-4) [6](#0-5) 

This breaks the intended equality "aggregated-weight vs verified-accepts": the aggregated weight test used to decide the signer's *global state* (which the local signer's own decisions about signing/rejecting build on, e.g. via `check_block_against_signer_db_state` and the sortition/miner view) is computed to a different, weaker standard than the weight test used to *verify* an actual quorum decision (block signatures, pre-commits). A coalition holding just under the true 70% (but at/above the floor-rounded value) can force honest signers to converge on a `current_miner`/`burn_block` view, or a `tx_replay_set`, that has not actually cleared the 70% supermajority the protocol intends, degrading the safety margin the supermajority is meant to guarantee.

### Impact Explanation
This falls under "a signer acting on a stale/incorrectly-thresholded reward set" - the global state machine (`determine_global_state`) that governs which miner a signer will treat as legitimate, and which burn view/tx-replay set it will honor, can lock in with less weight than the protocol's genuine 70% supermajority whenever `total_weight` doesn't divide evenly by 10 for the 7/10 fraction. Since signer weight totals are derived from arbitrary stacked amounts (not designed to be multiples of 10), this condition is common, not an edge case. It weakens (rather than outright breaks with a single attacker) the safety margin around signer consensus on the active miner/tenure state that other logic (e.g. reorg permitting, `check_block_against_signer_db_state`) depends on being backed by a genuine supermajority.

### Likelihood Explanation
Medium. It requires an adversarial or just-uncoordinated set of signers whose combined weight sits in the narrow gap between the floor and ceiling thresholds (at most one weight unit) — a normal, frequently-occurring situation given real-world weight distributions, not one requiring a majority of signers to be malicious to trigger the discrepancy. However, exploiting it into a concretely damaging outcome still requires an attacker (or unlucky honest weight distribution) to land exactly in that boundary region and requires the sub-70% actual value to reach the floor-rounded target while remaining under the 70% total the rest of the protocol enforces.

### Recommendation
Make `reached_agreement` (and `reached_disagreement`) use the same rounding convention as `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling division), so that "reaching global agreement" always requires at least the true 70% (respectively strictly more than 30% for disagreement) of `total_weight`, consistent with the block-signature threshold. Add regression tests with `total_weight` values not evenly divisible by 10 for the 7/10 fraction (e.g. `total_weight = 13`) mirroring the existing `test_compute_voting_weight_threshold` rounding tests.

### Proof of Concept
1. Configure a signer set whose weights sum to `total_weight = 13` (e.g., weights 5, 5, 3 across three signers).
2. Have signers controlling weight 9 broadcast a `StateMachineUpdate` agreeing on a particular `current_miner`/burn view; the remaining weight-4 signer disagrees or is silent.
3. `GlobalStateEvaluator::reached_agreement(9)` returns `true` because `13 * 7 / 10 = 9` (floor), even though `9/13 ≈ 69.2% < 70%`.
4. Compare against `NakamotoBlockHeader::compute_voting_weight_threshold(13)`, which returns `10` (ceiling) — the value actually required to reach 70% for block-signature verification.
5. Honest signers therefore treat the `current_miner`/global state as settled with only 69.2% actual weight support, one unit short of the genuine 70% supermajority enforced for block signatures elsewhere in the same codebase.

        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Determine what the global burn view is if there is one

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

/// Regression: u32 multiplication in `reached_agreement` wrapped silently in
/// release builds for `total_weight > u32::MAX / 7 ≈ 613_566_756`. With
/// `total_weight = 1_000_000_000` the buggy expression `total_weight * 7 / 10`
/// wrapped to ~270_503_270, allowing roughly 27% of total weight to satisfy
/// the 70% supermajority check. The fix widens to u64 first.
fn reached_agreement_no_u32_overflow() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // Pre-fix wrap landed at 270_503_270; assert that vote_weight at the wrapped
    // value is correctly rejected — i.e., 27% does not satisfy 70%.
    assert!(
        !evaluator.reached_agreement(270_503_270),
        "27% of total_weight must not satisfy the 70% threshold"
    );
    // Boundary: exactly 70% must pass.
    assert!(
        evaluator.reached_agreement(700_000_000),
        "70% of total_weight must satisfy the 70% threshold"
    );
    // Just below 70% must fail.
    assert!(
        !evaluator.reached_agreement(699_999_999),
        "below 70% must not satisfy the threshold"
    );
}

#[test]
/// Locks the joint behavior of `reached_agreement` and `reached_disagreement`
/// at a single `total_weight`:
///   - agreement: `>=` 70% (inclusive)
///   - disagreement: `>` 30% (strict)
///   - three regions: [0, 30%] neither, (30%, 70%) disagreement only,
///     [70%, total] both
///
/// Walking 0, 30%, 30%+1, 70%-1, 70% catches a flipped inequality on either
/// side and any drift between the two threshold constants. Also pins the
/// "agreement implies disagreement" relation, which holds as long as the
/// agreement threshold sits above the disagreement one.
fn thresholds_partition_weight_space() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // 0%: neither.
    assert!(!evaluator.reached_agreement(0));
    assert!(!evaluator.reached_disagreement(0));

    // Exactly 30%: strict `>`, so not yet disagreement.
    assert!(!evaluator.reached_agreement(300_000_000));
    assert!(!evaluator.reached_disagreement(300_000_000));

    // One unit past 30%: gap region, disagreement only.
    assert!(!evaluator.reached_agreement(300_000_001));
    assert!(evaluator.reached_disagreement(300_000_001));

    // One unit below 70%: still in the gap.
    assert!(!evaluator.reached_agreement(699_999_999));
    assert!(evaluator.reached_disagreement(699_999_999));

    // Exactly 70%: agreement (`>=`), and disagreement still holds since 70% > 30%.
    assert!(evaluator.reached_agreement(700_000_000));
    assert!(evaluator.reached_disagreement(700_000_000));
}
