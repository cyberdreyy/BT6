### Title
Unchecked `new_authority` in `transfer_to_new_account` / `transfer_to_new_account_pda` allows permanent loss of account access - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
`transfer_to_new_account` and `transfer_to_new_account_pda` accept a `new_authority` account that is explicitly documented as `/// CHECK: WARN: New authority is completely unchecked` and typed as `UncheckedAccount`. No on-chain constraint prevents `new_authority` from being `Pubkey::default()` or any other value the caller does not actually control. Once the instruction executes, the old account is irreversibly disabled and its entire lending position (all balances/shares) is moved into the new account, which is now controlled solely by whatever key was supplied as `new_authority`.

### Finding Description
The bug-class from the report is: a length/format check passes validation but the value is not the intended target, and by the time the destination is proven invalid, the source-side funds have already been irreversibly debited with no recovery path.

`transfer_to_new_account`/`transfer_to_new_account_pda` exhibit the same root-cause pattern on Solana: [1](#0-0) 

The old account's checks (`ACCOUNT_IN_FLASHLOAN`, `ACCOUNT_IN_RECEIVERSHIP`, `ACCOUNT_IN_ORDER_EXECUTION`, `active_orders == 0`, `migrated_to == Pubkey::default()`) validate only the *source* account's state — never the destination authority. The new account is initialized with `ctx.accounts.new_authority.key()` as its authority: [2](#0-1) 

and the old account is then permanently disabled and its `lending_account` zeroed out (i.e., its balances/shares are logically moved to the new account, which now records them): [3](#0-2) 

Critically, `new_authority` is accepted with zero validation on-chain: [4](#0-3) [5](#0-4) 

There is no `require!(new_authority.key() != Pubkey::default())`, and no check that `new_authority` is a signer or otherwise able to later demonstrate control. Only the off-chain CLI helper defensively rejects the zero-key client-side — this is not an on-chain invariant and does not protect a user who constructs the instruction directly, via a UI bug, or via a typo'd/incorrect pubkey copy-paste: [6](#0-5) 

Since `authority.key() == new_authority.key()` is never enforced, and `new_authority` need not be a `Signer`, an unprivileged account authority (the only signer required per the `Accounts` struct — `is_signer_authorized(&a, g.admin, authority.key(), false, false)`) can trigger a state change that moves all funds to an address nobody can sign for.

### Impact Explanation
If a user (or any client/integration bug) supplies an incorrect, mistyped, or zero `new_authority`:
- The old account is immediately and irreversibly disabled (`ACCOUNT_DISABLED`) with `lending_account` zeroed.
- All lending positions (deposits/collateral) are recorded under the new account, which is now solely controlled by the unreachable/incorrect `new_authority`.
- There is no revert path: no equivalent of `retryOnReceive` exists — funds are durably locked/lost exactly like the "silent burn" described in the source report, because the value-holding state transition (`finalize_migrated_old_account`) happens unconditionally after `new_authority` is accepted, with no later step verifying it is a controllable key.

This matches the "durable freeze/inconsistency with financial effect" acceptance criteria: an unprivileged, single-signature, permissionless-for-the-account-owner action results in permanent inaccessibility of the account's assets.

### Likelihood Explanation
Likelihood is moderate: this requires either (a) a bug/typo in a wallet or integrator building the instruction manually (bypassing the CLI's client-side guard), or (b) a malicious relayer/UI substituting a wrong `new_authority` for a user who is otherwise trusting the transaction. Because `transfer_to_new_account`/`transfer_to_new_account_pda` are ordinary, unprivileged, user-facing instructions (only requiring the existing account authority's signature), and the destination is a raw `UncheckedAccount` with no sanity check, the attack/mistake surface is realistic, mirroring the "user mistake escalates to permanent loss" scenario in the source finding.

### Recommendation
Add an on-chain guard rejecting `new_authority == Pubkey::default()` in both `transfer_to_new_account` and `transfer_to_new_account_pda`, matching (and enforcing, not just suggesting) the check already present in the off-chain CLI. Additionally consider requiring `new_authority` to be a `Signer` (or otherwise cryptographically prove control, e.g., via a co-signed acknowledgment) before finalizing the migration, so that accidental/malicious transfers to unreachable keys cannot silently strand user funds.

### Proof of Concept
1. Attacker/buggy client crafts a `transfer_to_new_account_pda` instruction where `old_marginfi_account` belongs to a real user with a funded position and `new_authority = Pubkey::default()` (or any pubkey the user does not control).
2. The instruction only requires `authority` (the current, legitimate account owner) to sign — see the `Accounts` struct requiring `is_signer_authorized(...)` for `authority` only, with `new_authority` as an unchecked, non-signing account: [7](#0-6) 
3. The transaction succeeds: `old_account` is disabled and zeroed, `new_account` is initialized with `authority = Pubkey::default()` and holds all the migrated balances.
4. No key exists that can sign for `Pubkey::default()`, so the new account (and thus the user's entire lending position) becomes permanently inaccessible with no retry/recovery instruction available.

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}

pub fn transfer_to_new_account(ctx: Context<TransferToNewAccount>) -> MarginfiResult {
    // Validate the global fee wallet and claim a nominal fee
    let group = ctx.accounts.group.load()?;
    check_eq!(
        ctx.accounts.global_fee_wallet.key(),
        group.fee_state_cache.global_fee_wallet,
        MarginfiError::InvalidFeeAta
    );
    anchor_lang::system_program::transfer(ctx.accounts.transfer_fee(), ACCOUNT_TRANSFER_FEE)?;

    let mut old_account = ctx.accounts.old_marginfi_account.load_mut()?;

    check!(
        !old_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_RECEIVERSHIP),
        MarginfiError::ForbiddenIx
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION),
        MarginfiError::ForbiddenIx
    );

    check!(
        old_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before transfer"
    );

    // Prevent multiple migrations from the same account
    check_eq!(
        old_account.migrated_to,
        Pubkey::default(),
        MarginfiError::AccountAlreadyMigrated
    );

    let mut new_account = ctx.accounts.new_marginfi_account.load_init()?;
    let current_timestamp = Clock::get()?.unix_timestamp as u64;
    initialize_migrated_account(
        &mut new_account,
        &old_account,
        ctx.accounts.new_authority.key(),
        current_timestamp,
        ctx.accounts.old_marginfi_account.key(),
    );

    finalize_migrated_old_account(
        &mut old_account,
        ctx.accounts.new_marginfi_account.key(),
        current_timestamp,
    );

#[derive(Accounts)]
#[instruction(account_index: u16, third_party_id: Option<u16>)]
pub struct TransferToNewAccountPda<'info> {
    #[account(
        constraint = (
            !group.load()?.is_protocol_paused()
        ) @ MarginfiError::ProtocolPaused
    )]
    pub group: AccountLoader<'info, MarginfiGroup>,

    #[account(
        mut,
        has_one = group @ MarginfiError::InvalidGroup,
        constraint = {
            let a = old_marginfi_account.load()?;
            account_not_frozen_for_authority(&a, authority.key())
        } @ MarginfiError::AccountFrozen,
        constraint = {
            let a = old_marginfi_account.load()?;
            let g = group.load()?;
            is_signer_authorized(&a, g.admin, authority.key(), false, false)
        } @ MarginfiError::Unauthorized
    )]
    pub old_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    #[account(
        init,
        payer = fee_payer,
        space = 8 + std::mem::size_of::<MarginfiAccount>(),
        seeds = [
            MARGINFI_ACCOUNT_SEED.as_bytes(),
            group.key().as_ref(),
            new_authority.key().as_ref(),
            &account_index.to_le_bytes(),
            &third_party_id.unwrap_or(0).to_le_bytes(),
        ],
        bump
    )]
    pub new_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    pub authority: Signer<'info>,

    #[account(mut)]
    pub fee_payer: Signer<'info>,

    /// CHECK: WARN: New authority is completely unchecked
    pub new_authority: UncheckedAccount<'info>,

    /// CHECK: Validated against group fee state cache
    #[account(mut)]
    pub global_fee_wallet: UncheckedAccount<'info>,

    /// Instructions sysvar for CPI validation
    /// CHECK: Standard sysvar account
    #[account(address = solana_instructions_sysvar::id())]
    pub instructions_sysvar: UncheckedAccount<'info>,

    pub system_program: Program<'info, System>,
}
