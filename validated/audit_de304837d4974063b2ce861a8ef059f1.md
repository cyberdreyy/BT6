### Title
Unprivileged front-running of `setAprs()` with a dust APR0 withdraw request blocks APR transitions and freezes epoch settlement - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary

`setAprs()` / `setAprsWithBuffer()` / `setApr()` update `unscaledApr` and `lastApr` without checking whether any APR0 withdraw receipts are outstanding. Meanwhile `requestWithdraw()` automatically routes every request into the APR0 bucket whenever `unscaledApr == 0`, and `prepareStopEpochWithApr0()` hard-reverts `NotAllowed` if `unscaledApr != 0` while `apr0TotalPrincipal != 0`. This mirrors the external bug: a state transition that is safe when no "staked" entries exist becomes invalidating once a user inserts an entry between the privileged call's broadcast and the next settlement — except here the missing guard converts into a revert at `stopEpoch`, so an unprivileged lender can permanently veto any APR change away from 0 and repeatedly freeze epoch settlement.

### Finding Description

Three pieces compose the bug:

1. `requestWithdraw()` unconditionally enters the APR0 path when `unscaledApr == 0`, incrementing `apr0TotalPrincipal` via `_requestWithdrawApr0(_amount, _user)` — any KYC-passed lender with a dust tranche position can create this state. [1](#0-0) 

2. `setAprs()` and `setApr()` only check `msg.sender` (CDO or manager) and `maxApr`; there is no check on `apr0TotalPrincipal`. `setAprsWithBuffer` and `stopEpochWithDuration`'s internal APR update funnel into the same unguarded `setApr`. [2](#0-1) 

3. `prepareStopEpochWithApr0()` enforces the lifecycle invariant at settlement time, not at configuration time: it reverts `NotAllowed` whenever `unscaledApr != 0 && apr0TotalPrincipal != 0`. [3](#0-2) 

Because `stopEpoch` (via `prepareStopEpochWithApr0`) is called inside the CDO's epoch-settlement transaction, the revert bricks `stopEpoch` / `stopEpochWithDuration` entirely — not just the APR0 accounting. The existing test `testApr0InvariantRevertsIfAprChangesAfterApr0Request` confirms this revert is reachable but treats it only as an invariant check after the fact. [4](#0-3) 

Attack sequence (buffer phase, fixed-APR mode):

1. Vault runs at `unscaledApr == 0`. Manager/owner broadcasts a legitimate `setAprs(newApr, scaledApr)` (or `stopEpochWithDuration` carrying a nonzero `newApr`) to restore yield.
2. Attacker (any KYC-passing lender) front-runs — or simply transacts in the same buffer window — with `cdoEpoch.requestWithdraw(dustAmount, tranche)`, which hits `unscaledApr == 0` and populates `apr0Users`/`apr0TotalPrincipal`.
3. The APR change lands. At the next `stopEpoch`, `prepareStopEpochWithApr0` reverts `NotAllowed`. The epoch cannot settle.
4. The only recovery is setting the APR back to 0 and settling — but the attacker can re-insert a dust APR0 request in the next buffer, repeating indefinitely. Cost to the attacker is a dust principal locked as a withdraw receipt.

### Impact Explanation

Temporary freezing of all vault funds plus denial of yield: `stopEpoch` cannot execute while the invariant is violated, so every pending withdraw request, all tranche holders' liquidity, and the next `startEpoch` are blocked until APR is reverted to 0. While blocked, the borrower borrows the entire TVL at 0% APR — a quantifiable loss equal to `TVL * intendedApr * duration` per blocked epoch, repeatable every buffer cycle for a near-zero attacker cost (dust principal). The broken invariant is fair settlement: one dust receipt vetoes the honest manager's configuration for all users.

### Likelihood Explanation

Low-to-medium. It requires the vault to be in an APR0 configuration and an honest manager/owner to attempt an APR increase — a routine operation. No privileged maliciousness is needed; any lender who prefers 0-cost denial (e.g., a competing party or a borrower-aligned wallet that benefits from free credit) can execute it with a dust request during any buffer window.

### Recommendation

Mirror the external fix — enforce the invariant at the setter, not at settlement. In `setApr()` (or `setAprs`/`setAprsWithBuffer`), revert if `apr0TotalPrincipal != 0` and the new `unscaledApr` is nonzero, i.e. refuse the APR transition while APR0 receipts are open rather than letting `stopEpoch` brick later. Alternatively, allow the transition but force-settle outstanding APR0 receipts at their request-epoch rate inside the setter, so `stopEpoch` can never be held hostage.

### Proof of Concept

Foundry fork test, modeled on `testApr0InvariantRevertsIfAprChangesAfterApr0Request` in `test/foundry/IdleCreditVault.t.sol`:

```solidity
function testApr0FrontRunBlocksAprTransition() external {
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);

    uint256 amount = 10000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _startEpochAndCheckPrices(0);

    vm.warp(cdoEpoch.epochEndDate() + 1);
    uint256 expectedInterest = cdoEpoch.expectedEpochInterest();
    deal(defaultUnderlying, borrower, expectedInterest);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    _forceLastEpochAprToZero(); // vault now in APR0 mode

    // Attacker: dust APR0 withdraw request (front-run of manager's APR update)
    address attacker = makeAddr("attacker");
    _depositWithUser(attacker, 1e6, true); // dust position
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(1e6, address(AAtranche));

    _startEpochAndCheckPrices(1);

    // Honest manager restores APR
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(1e18, 1e18);

    // Settlement is bricked: stopEpoch reverts while APR0 principal exists
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(0, 0);
    // Repeating: attacker re-requests each buffer => indefinite freeze at APR0.
}
```

Key assertion: `stopEpoch` reverts even though every privileged actor behaved correctly — the missing guard is in `setApr`/`setAprs`, not in the settlement path.

  /// @dev only CDO and manager can set the APR through `setApr`.
  /// @param _unscaledApr unscaled APR
  /// @param _duration epoch duration
  /// @param _buffer buffer duration
  function setAprsWithBuffer(uint256 _unscaledApr, uint256 _duration, uint256 _buffer) external {
    unscaledApr = _unscaledApr;
    setApr(_duration == 0 ? _unscaledApr : _unscaledApr * (_duration + _buffer) / _duration);
  }

  /// @notice set the fixed apr
  /// @dev only cdo and manager can set the apr. If manager manually set apr from 
  /// here it will not be scaled to include the buffer period
  function setApr(uint256 _apr) public {
    address _cdo = idleCDO;

    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
  }
