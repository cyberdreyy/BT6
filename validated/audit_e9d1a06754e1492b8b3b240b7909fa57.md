### Title
Attacker-inflated ERC4626 share price is credited as epoch interest during `stopEpoch`, minting unbacked strategy tokens in programmable/minted-interest mode - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
The pretalx XSS is a stored-injection bug: an unprivileged user plants attacker-controlled data into a field that is later consumed, unsanitized, in a privileged context (the organiser's browser). The direct analog here is `ProgrammableBorrower`'s ERC4626 sleeve: any user of the external vault can inject value into the valuation field (`convertToAssets`) via a donation, and that injected value is later consumed verbatim by the privileged `stopEpoch` flow as real pool interest. In minted-interest mode the phantom interest is crystallized into tranche prices without any cash ever being pulled, creating unbacked NAV the attacker can exit against.

### Finding Description
`stopEpoch` in `IdleCDOEpochVariant` resolves epoch interest through `_resolveStopEpochInterest`, which for a programmable borrower reads `ProgrammableBorrower.totalInterestDueNow()` [1](#0-0) . That value includes `_vaultNetInterest()`, computed as `bufferedVaultDelta + currentVaultAssets + epochWithdrawnFromVault - epochStartVaultAssets - epochDepositedToVault`, where `currentVaultAssets = vault.convertToAssets(vault.balanceOf(this))` [2](#0-1) [3](#0-2) .

`convertToAssets` of any standard ERC4626 is `shares * totalAssets / totalSupply`, so a direct `underlying.transfer(vault, D)` by any EOA inflates the ProgrammableBorrower's reported vault position by its pro-rata share of `D`. Nothing sanitizes this: there is no internal balance bookkeeping, no deviation check against a cost-basis, and the `maxApr` sanity cap on minted interest only applies when `stopEpoch` is called with an explicit override `_interest > 1` [4](#0-3) . With the normal `stopEpoch(0, _newApr)` call the inflated `totalInterestDueNow()` becomes `expectedEpochInterest` unconditionally.

Because programmable deployments require `isInterestMinted` (it cannot be unset while the facility is live) [5](#0-4) , `_amountToPullFromBorrower = 0` and the phantom gain is minted as strategy tokens / tranche price appreciation with zero cash backing [6](#0-5) .

Critically, the donation is recoverable. The attacker first buys a large fraction of the external vault's shares (they are explicitly in scope as "a user of the programmable borrower's ERC4626 vault"), donates `D`, lets the honest manager run `stopEpoch`, then redeems their vault shares to reclaim ~`(attackerVaultShares/totalShares) * D`. The pool's tranche prices, however, now reflect the full inflated `vaultInterestAccrued` portion of `D` attributable to the ProgrammableBorrower's shares — value that was never funded by the borrower.

### Impact Explanation
Insolvency and direct theft. The CDO crystallizes phantom epoch interest into `priceAA`/`priceBB`. Any tranche holder (including the attacker, who can be a KYC-passed lender and/or hold a large tranche position) can then request a withdrawal and be paid from real pool cash at the inflated price, while the vault position does not actually contain the credited interest. The last withdrawers absorb the shortfall. The unbacked amount equals roughly `D * pbShares / vaultTotalShares` (the ProgrammableBorrower's share of the donation), and the attacker's net cost is only the slice of `D` attributable to other vault shareholders plus fees.

### Likelihood Explanation
- Attacker requirements are minimal: any EOA can donate underlying to the ERC4626 vault, and holding vault shares / tranche tokens is within the unprivileged threat model.
- The trigger is an honest manager calling `stopEpoch`, a routine privileged action — exactly the "payload executes in the privileged context" shape of the XSS.
- No existing guard stops it: `_skimDonatedAssets` only skims raw underlying sitting on the CDO, not assets donated to the external vault [7](#0-6) ; the `maxApr` bound is skipped on the normal `_interest == 0` path; `onStopEpoch` does not re-validate the interest figure it was read before the hook ran [8](#0-7) .
- Profitability requires the attacker to hold a meaningful fraction of the external vault's shares (to recover the donation) and/or of the tranches (to monetize the inflation), both plausible for a permissionless ERC4626.

### Recommendation
Track the vault sleeve's principal in shares/assets terms rather than trusting `convertToAssets` deltas: e.g., record `epochStartShares` and value the position at min of `convertToAssets` and a cost-basis bound, or value vault PnL only on actual `deposit`/`withdraw` flows (`epochDepositedToVault`/`epochWithdrawnFromVault`) and treat unsolicited share-price appreciation above a capped rate as a donation excluded from `totalInterestDueNow`. Alternatively, apply the existing `maxApr` ceiling to `totalInterestDueNow()` on the `_interest == 0` path as well, capping creditable epoch interest at `maxApr * epochDuration`.

### Proof of Concept
Foundry fork sketch against `test/foundry/ProgrammableBorrowerCreditVault.t.sol` setup:

```solidity
function testPocVaultDonationInflatesMintedInterest() external {
    // --- setup: programmable borrower mode, isInterestMinted = true ---
    address attacker = makeAddr("attacker");
    uint256 lpDeposit = 100_000 * ONE_SCALE;
    uint256 donation  = 10_000 * ONE_SCALE;

    // honest LP deposits into AA tranche; manager starts epoch
    idleCDO.depositAA(lpDeposit);
    vm.prank(manager);
    cdoEpoch.startEpoch(); // onStartEpoch snapshots epochStartVaultAssets

    // --- attacker buys most of the external ERC4626 vault's shares ---
    deal(defaultUnderlying, attacker, 1_000_000 * ONE_SCALE);
    vm.startPrank(attacker);
    underlying.approve(address(externalVault), type(uint256).max);
    externalVault.deposit(500_000 * ONE_SCALE, attacker); // attacker >> PB share fraction
    vm.stopPrank();

    // --- the payload: raw donation inflates convertToAssets ---
    vm.prank(attacker);
    underlying.transfer(address(externalVault), donation);

    uint256 dueNow = pbBorrower.totalInterestDueNow();
    // PB's share of the donation is now reported as vault interest
    uint256 pbShare = externalVault.balanceOf(address(pbBorrower));
    uint256 phantom = donation * pbShare / externalVault.totalSupply();
    assertApproxEqAbs(dueNow, phantom, 2);

    // --- honest manager triggers the stored payload ---
    deal(defaultUnderlying, borrower, 0); // minted mode pulls nothing
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0); // _interest == 0 -> no maxApr cap applied

    // tranche price crystallized phantom interest
    assertGt(cdoEpoch.virtualPrice(address(AAtranche)), ONE_TRANCHE_TOKEN);

    // --- attacker recovers the donation from the vault ---
    vm.prank(attacker);
    externalVault.redeem(externalVault.balanceOf(attacker), attacker, attacker);
    // attacker reclaimed ~donation * (1 - pbShare/totalShares) plus their principal;
    // the pool NAV is now overstated by ~phantom with no borrower obligation.

    // --- LP exits at inflated price; last withdrawer is short ---
    idleCDO.requestWithdraw(0, address(AAtranche));
    // subsequent claim/withdraw flow pays phantom-value receipts from real cash,
    // leaving residual tranche holders undercollateralized by ~phantom.
}
```

The broken invariant is fair mint/burn and solvency: `expectedEpochInterest` minted interest must correspond to borrower-owed or realized yield, but here it reflects an arbitrary unprivileged donation into the external vault's `totalAssets`, consumed unsanitized by the privileged `stopEpoch` path — the on-chain analog of an attacker field being `innerHTML`-ed into the organiser's session.

  function onStopEpoch(uint256 _amountRequired, bool _isRequestingAllFunds) external nonReentrant returns (bool success) {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // if we want to close the pool and the borrower still owes any amount, consider it a failure and let IdleCDO handle it as a default instead of a close. 
    if (_isRequestingAllFunds && (borrowerPrincipal != 0 || borrowerInterestDebt != 0 || borrowerInterestAccrued != 0)) {
      return false;
    }

    uint256 onHand = underlyingToken.balanceOf(address(this));
    if (_amountRequired > onHand) {
      uint256 shortfall = _amountRequired - onHand;
      // If the vault shares do not economically cover the shortfall, let IdleCDO's later
      // transferFrom fail and use the existing default path. Only an otherwise-covered ERC4626
      // withdrawal failure should make stopEpoch retryable.
      if (shortfall > _currentVaultAssets()) return true;
      try vault.withdraw(shortfall, address(this), address(this)) returns (uint256 shares) {
        if (epochAccountingActive) {
          epochWithdrawnFromVault += shortfall;
        }
        emit WithdrawnFromVault(shortfall, shares, address(this));
      } catch {
        revert StopEpochVaultLiquidityUnavailable();
      }
    }

    // `totalInterestDueNow()` was already read by IdleCDO before calling this hook, so once the
    // stop flow begins we can clear the previous carry and snapshot the remaining vault sleeve
    // as the baseline for measuring buffer-period vault PnL before the next epoch starts.
    bufferedVaultDelta = 0;
    bufferInterest = 0;
    bufferStartVaultAssets = _currentVaultAssets();

    // Stop reserving epoch-end withdraw liquidity once IdleCDO has started the stop flow.
    epochPendingWithdraws = 0;
    epochAccountingActive = false;
    emit EpochAccountingStopped();
    success = true;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
