### Title
Global, unauthenticated request-ID namespace in confidential relay gateway handler allows ID-squatting denial of service - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`h.newActiveRequest` keys `activeRequests` solely by the caller-supplied `req.ID`, with no per-caller/owner namespacing. Any unauthenticated caller who can predict or observe another user's `req.ID` can pre-register that exact ID first, causing the victim's genuine request with the same ID to be rejected via the "already exists" path, which is a targeted denial of a specific victim request.

### Finding Description
`HandleJSONRPCUserMessage` validates only that `req.ID` is non-empty and ≤200 chars, then calls `h.newActiveRequest(req, callback)`: [1](#0-0) 

`newActiveRequest` performs a global existence check keyed purely on the raw, attacker-controlled `req.ID` and rejects with `"request ID already exists"` if any in-flight request already holds that key: [2](#0-1) 

Unlike the sibling vault gateway handler, which derives the authorized owner from `AuthorizeRequest` and rewrites the request ID to `authorizedOwner + RequestIDSeparator + originalRequestID` before using it as a lookup key (`prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID`), the confidential relay handler applies no such per-caller namespace — the top-level `gateway.ProcessRequest` routes non-legacy JSON-RPC requests straight to `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` without binding `req.ID` to an authenticated identity for this handler: [3](#0-2) 

Because the `activeRequests` map is a single global namespace shared by every unauthenticated caller, an attacker who knows or predicts a victim's about-to-be-used `req.ID` can submit their own request with that same ID first. The victim's subsequent legitimate request for that same ID hits the `h.activeRequests[req.ID] != nil` branch and is rejected outright, before ever registering or fanning out to DON nodes.

### Impact Explanation
This is a scoped denial of service: an attacker can block exactly one victim-chosen request ID from ever being processed by the gateway, without needing any credentials, node compromise, or data leakage. It matches Chainlink's "Denial of Service" bounty class at a targeted/limited severity (single request blocked, not gateway-wide outage), since the attacker must guess/know the exact ID string and the effect is confined to that one ID rather than persistent service degradation.

### Likelihood Explanation
Feasibility depends entirely on precondition of ID predictability, as stated in the question. If client libraries generate `req.ID` from high-entropy random values (e.g., UUIDv4), guessing is infeasible and this is not exploitable in practice. If IDs are sequential, derived from user-visible identifiers, or otherwise low-entropy/predictable, the race is trivially reproducible: the attacker only needs to submit a request with the guessed ID slightly before the victim's real request arrives. No authentication is required to reach `HandleJSONRPCUserMessage` for this handler at the gateway layer shown above, so the attacker precondition ("unauthenticated ability to submit relay requests") is met by the existing code path.

### Recommendation
Namespace `activeRequests` by an authenticated caller identity rather than the raw client-supplied `req.ID`, mirroring the vault handler's `authorizedOwner + RequestIDSeparator + originalRequestID` scheme, so that one caller cannot squat another caller's ID slot. If the confidential relay method genuinely has no per-request authentication, consider deriving the dedup key from `(authenticated sender, method, req.ID)` or from a gateway-issued opaque request ID rather than trusting the client-supplied string directly.

### Proof of Concept
Go handler-level test plan in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` via the existing test helper used in that file.
2. Call `h.newActiveRequest(jsonrpc.Request[json.RawMessage]{ID: "T", Method: MethodSecretsGet}, attackerCallback)` and assert it succeeds (simulating attacker pre-registration).
3. Call `h.newActiveRequest(jsonrpc.Request[json.RawMessage]{ID: "T", Method: MethodSecretsGet}, victimCallback)` and assert it returns the `"request ID already exists: T"` error, demonstrating the victim's legitimate request is rejected.
4. Assert `h.activeRequests["T"]` still references the attacker's `activeRequest` (via `Callback` identity or a marker field), confirming the victim's slot was never registered — i.e., cross-caller ID squatting succeeds because no ownership/auth binding exists on the map key.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}

		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
