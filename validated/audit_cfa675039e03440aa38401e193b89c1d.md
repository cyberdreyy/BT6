### Title
Unauthenticated `/health` and `/health.txt` endpoints leak internal service names and error details - ([File: core/web/health_controller.go])

### Summary
The `Health` handler (registered publicly via `healthRoutes`) returns a full JSON/HTML/text breakdown of every internal health check, including the check `Name` and the raw `err.Error()` output for any failing service, to any anonymous caller. This is a plaintext data exposure vulnerability distinct from the already-mitigated `PublicReadyz` endpoint, which was explicitly designed to avoid this exact leak.

### Finding Description
`healthRoutes` registers `/health`, `/health.txt`, and `/readyz` on the `api` router group with no authentication middleware, unlike `debugRoutes` which wraps `/debug/vars` in `auth.Authenticate(...)`: [2](#0-1) 

`HealthController.Health` iterates `checker.IsHealthy()` results and, for each failing internal service, includes the check `Name` and the underlying Go error text verbatim in the response body: [3](#0-2) 

This same detail leak also applies to `Readyz` when the `?full` query parameter is supplied: [4](#0-3) 

Notably, the codebase already contains a purpose-built mitigation for this exact class of issue: `PublicReadyz`, whose doc comment states it "never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints": [5](#0-4) 

The existing test suite confirms the leak is intentional/by-design behavior of `Health` (not a bug in test infra) — `/health` and `/health.txt` return per-check `Name`/`Output` fields for JSON, HTML, and text formats: [6](#0-5) 

An unauthenticated attacker can simply `GET /health` (or `/health.txt`, or `/readyz?full=1`) and receive a list of internal component/service names (e.g., specific chain IDs, relayers, subsystems) along with the exact Go error string produced when that component is unhealthy (e.g., DB connection errors, RPC endpoint failures, config issues) — none of which is redacted or generalized to a boolean.

### Impact Explanation
This falls under Chainlink's "informational disclosure" / low-severity impact class: internal service topology (component names) and internal error strings (which can reveal RPC URLs, DB connectivity issues, chain configuration, or version/library-specific error messages) are exposed to any network-reachable unauthenticated client. This aids reconnaissance for further attacks (e.g., targeting a specific failing subsystem) but does not by itself grant credential/key access, authentication bypass, or fund movement.

### Likelihood Explanation
Trivially reachable and repeatable: zero credentials required, single unauthenticated `GET /health` request from any network location that can reach the node's API port. The only precondition is that at least one internal health check is failing (a naturally occurring node state, e.g., transient RPC/DB issues) or the operator has exposed the health endpoint publicly (a common practice for LB health checks, which is exactly the scenario `PublicReadyz` was built to safely support).

### Recommendation
Restrict `/health`, `/health.txt`, and `/readyz?full` to require authentication (mirroring `debugRoutes`'s use of `auth.Authenticate`), or strip per-check `Name`/`Output` detail from these routes entirely and direct users wanting public health checks to `/public-readyz`. At minimum, redact `err.Error()` text before returning it in `Health`/`Readyz`, since raw internal error strings are the highest-value leak.

### Proof of Concept
1. In `core/web/health_controller_test.go`, add a test using `mocks.Checker` where `IsHealthy()` returns `(false, map[string]error{"internal-relayer-evm-1399100": errors.New("dial tcp 10.0.0.5:8545: connect: connection refused")})`.
2. Start the app with an anonymous `client := app.NewHTTPClient(nil)` (no auth token/session).
3. `resp, _ := client.Get("/health")`.
4. Assert `resp.StatusCode == http.StatusMultiStatus`.
5. Read body and assert it contains the literal service name `internal-relayer-evm-1399100` and the literal error substring `connection refused` — demonstrating that an unauthenticated caller receives specific internal service identifiers and raw error text rather than a generic up/down boolean.
6. Repeat for `/health.txt` and `/readyz?full=1` to confirm the same leak across all three unauthenticated routes.

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}
