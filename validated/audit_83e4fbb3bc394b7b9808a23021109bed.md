### Title
Zip extraction allows symlinked-directory entries to redirect subsequent file writes outside the extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` iterates `archive.File` entries and calls `extractZipFile` for each one without validating that a file's target path stays within the destination directory or without detecting when an intermediate path component is a symlink. An attacker who controls the archive contents (cache/artifact zip) can create a symlink entry pointing outside the extraction root, followed by a file entry whose `Name` is nested under that symlink, causing the later entry to be written through the symlink to an attacker-chosen location.

### Finding Description
`extractZipFile` (helpers/archives/zip_extract.go:61-83) does:
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
```
followed by a switch on `file.Mode()&os.ModeType` that calls `extractZipSymlinkEntry` for `os.ModeSymlink` entries (which does `os.Symlink(string(data), file.Name)` at line 37, with `data` being fully attacker-controlled file content — i.e., the symlink target is arbitrary and unchecked) or `extractZipFileEntry` for regular files (which does `os.OpenFile(file.Name, ...)` at line 51).

There is no logic anywhere in this file, `path_check_helper.go`, or `path_error_tracker.go` that:
- Resolves `file.Name` and verifies it stays under the extraction root (no zip-slip `..` check),
- Rejects a symlink target that points outside the extraction directory,
- Detects that a later entry's parent path was previously created as a symlink (rather than a real directory) and refuses to traverse it.

The only existing guard, `errorIfGitDirectory` (helpers/archives/path_check_helper.go:21-31), only blocks `.git` paths — it does not address path traversal or symlink redirection at all.

Exploit flow:
1. Entry 1: `Name = "link"`, `Mode = os.ModeSymlink`, content = absolute path to a directory outside the extraction root (e.g., another tenant's cache directory reachable on the shared filesystem).
2. `extractZipFile` processes it via `extractZipSymlinkEntry`, creating `link -> /outside/path` in the extraction root.
3. Entry 2: `Name = "link/evil"`, a regular file with attacker content.
4. `extractZipFile` calls `os.MkdirAll(filepath.Dir("link/evil"), 0o777)` → `os.MkdirAll("link", ...)`. Since `link` already exists (as a symlink), `MkdirAll` treats it as satisfying the directory requirement (Go's `MkdirAll` `Stat`s the path and, if it exists and is a directory *or a symlink to a directory*, does not error) and does not recreate it.
5. `extractZipFileEntry` then opens `"link/evil"` for writing; the OS resolves `link` as a symlink and writes `evil` inside the external target directory.

The extraction root confinement invariant is violated because no code checks that `filepath.Dir(file.Name)` (or any of its parents) is a symlink before allowing further writes underneath it, and no destination-root containment check is performed on `file.Name` at all.

### Impact Explanation
On a Runner/executor setup where the extraction root (build directory, cache directory, or artifact download path) resides on a filesystem shared across multiple jobs/tenants (a documented and common cache-mount topology, e.g., shared NFS/host-path caches across concurrent jobs on the same shell/docker executor host), an unprivileged pipeline author can craft a cache or artifact zip that, upon extraction by `ExtractZipArchive`, writes attacker-controlled file content into another job's or project's directory reachable through the symlink target. This breaks the "file operations must stay within intended build/cache/artifact roots" invariant and can lead to cross-project file planting (e.g., overwriting build scripts, cache poisoning) in other jobs sharing that filesystem.

### Likelihood Explanation
Feasible and fully attacker-controlled: cache/artifact archives are supplied by job definitions and are under full control of the pipeline author (`cache:paths`, `artifacts:paths`, or a maliciously crafted `.zip` fed to `gitlab-runner artifacts-downloader`/`cache-extractor`). No special privileges are needed beyond the ability to define a `.gitlab-ci.yml` job or otherwise get a runner to extract an attacker-supplied zip. The only precondition is that the extraction root sits on storage shared with other tenants' paths (common in shared-cache runner fleets), which is a realistic and frequently used Runner deployment pattern, not a purely theoretical one.

### Recommendation
In `extractZipFile`/`ExtractZipArchive`:
- Before extracting each entry, resolve `filepath.Join(destRoot, file.Name)` with `filepath.Clean` and verify the resulting path has `destRoot` as a prefix (reject `..` traversal), matching standard zip-slip mitigations.
- Before calling `os.MkdirAll(filepath.Dir(file.Name), ...)`, `lstat` each path component (or track directories created as symlinks during this extraction pass) and refuse to descend into/create files under a path where any component is a symlink.
- For symlink entries (`extractZipSymlinkEntry`), validate that the symlink target (after resolving relative to the entry's directory) stays within the extraction root, rejecting absolute paths or `..`-escaping targets.

### Proof of Concept
Go test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchiveSymlinkEscape(t *testing.T) {
    extractDir := t.TempDir()
    outsideDir := t.TempDir()

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)

    // Entry 1: symlink "link" -> outsideDir (absolute path)
    linkHdr := &zip.FileHeader{Name: "link"}
    linkHdr.SetMode(os.ModeSymlink | 0o777)
    w, _ := zw.CreateHeader(linkHdr)
    w.Write([]byte(outsideDir))

    // Entry 2: file "link/evil" with attacker content
    fileHdr := &zip.FileHeader{Name: "link/evil"}
    fileHdr.SetMode(0o644)
    w2, _ := zw.CreateHeader(fileHdr)
    w2.Write([]byte("attacker-content"))

    zw.Close()

    origWD, _ := os.Getwd()
    os.Chdir(extractDir)
    defer os.Chdir(origWD)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the file was NOT written into outsideDir
    _, statErr := os.Stat(filepath.Join(outsideDir, "evil"))
    require.True(t, os.IsNotExist(statErr), "attacker content escaped extraction root via symlink")
}
```
Expected current (vulnerable) behavior: `outsideDir/evil` exists with content `"attacker-content"`, proving the escape. After applying the recommended path/symlink validation, the test should pass with the file rejected or confined inside `extractDir`.
