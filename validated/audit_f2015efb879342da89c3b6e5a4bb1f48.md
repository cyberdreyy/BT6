### Title
Cross-request response confusion via request ID reuse in confidential relay handler - (`core/services/gateway/handlers/confidentialrelay/handler.go`, `bundler.go`)

### Summary
The confidential relay handler correlates node responses to in-flight user requests solely by the attacker-controlled `req.ID` string, with no per-instance generation token. Because `sendResponseAndClearRequest` deletes the `activeRequests[req.ID]` map entry as soon as the current holder's bundle is forwarded—while slower DON nodes' responses for that same request ID can still be arriving—a new caller who immediately reuses that same ID can have the stale, late-arriving node response for the *previous* holder's request folded into their own bundle and returned to them.

### Finding Description
`req.ID` is taken verbatim from the untrusted incoming JSON-RPC request in `gateway.ProcessRequest` (`core/services/gateway/gateway.go:220-230`) with no server-assigned uniqueness, no binding to caller identity/connection, and is passed straight into `handler.HandleJSONRPCUserMessage` [1](#0-0) .

`newActiveRequest` only rejects an ID that is *currently* in the `activeRequests` map [2](#0-1) . Once a request completes—via early quorum (`forwardBundleOrTerminateIfReady`), quorum grace, or expiry—`sendResponseAndClearRequest` immediately deletes the map entry, before all DON nodes are guaranteed to have replied (fan-out only needs `F+1`/`2F+1` signed responses, not all nodes, and `nodeSendTimeout`/`requestTimeout` allow late stragglers) [3](#0-2) .

`HandleNodeMessage` resolves an incoming node response purely by `resp.ID` via `getActiveRequest` [4](#0-3) . If a new caller has already re-registered an `activeRequest` under the same ID string before the previous holder's slow node response arrives, `getActiveRequest` returns the *new* caller's `activeRequest` instance instead of `nil`, and `addResponseForNode` merges the stale, unrelated response into the new caller's `responses` map with no check that it actually belongs to the new request instance.

`bundler.Bundle` then decodes every entry in that merged map according to the new caller's `req.Method` and passes the accumulated `out` slice to `wrapBundle`, which stamps the *new* caller's `req.Method`/`req.ID`/`req.Version` onto the resulting envelope [5](#0-4) . The bundler is explicitly documented as a "dumb fan-in" that does not verify which request a signed node response actually corresponds to, relying entirely on ID-based correlation for that [6](#0-5) . The resulting bundle—now potentially containing a signed relay response segment computed for the prior request/holder—is delivered straight back to the new caller's HTTP response via `sendResponseAndClearRequest` → `callback.Wait` in `gateway.ProcessRequest` [7](#0-6) .

No existing check (auth, signature, or per-instance fencing) prevents this: `newActiveRequest`'s existence check only guards against concurrent collisions, not collisions with a just-cleared, still-resolving request under the same ID.

### Impact Explanation
This is a cross-user response confusion / data leak path: a stale signed node response intended for one caller's `MethodSecretsGet`/`MethodCapabilityExec` request can be merged into another caller's newly issued request under a reused ID and returned to that second caller in the gateway's HTTP response. Depending on what the stray signed relay response contains (secrets material or capability execution result signed by DON nodes for the original caller), this constitutes unauthorized cross-user data exposure and request/response impersonation between unrelated gateway clients, matching Chainlink's "request impersonation / cross-user response confusion" bounty class.

### Likelihood Explanation
No special privilege is needed—any connected gateway client fully controls `req.ID` for their own JSON-RPC requests. Exploitation requires only: (1) a small race window where the previous holder of an ID is cleared from `activeRequests` while at least one DON node's response for that same ID is still in flight (routinely possible since quorum can complete before all nodes answer, and node sends are only bounded by `nodeSendTimeoutSec`/`requestTimeoutSec`), and (2) submitting a new request with the identical ID string immediately afterward. Collisions are also plausible unintentionally, since many JSON-RPC clients default to simple/incrementing IDs (e.g. `"1"`), making accidental or deliberately guessed collisions realistic without needing to break any cryptographic control. The race is repeatable and does not require insider access.

### Recommendation
Bind each `activeRequest` to a unique, server-generated instance token (e.g., a monotonically increasing epoch/nonce per ID, or a per-connection/session-scoped composite key) rather than the raw client-supplied `req.ID` alone. `HandleNodeMessage` should validate that an incoming node response's correlating token matches the specific `activeRequest` instance it was fanned out under (e.g., embed the token in the outbound `SendToNode` request and require it echoed back, or key `activeRequests` by `(connection/session, req.ID, instanceEpoch)` and reject/­drop responses whose epoch doesn't match), so that stale responses for a cleared/replaced request are always discarded rather than silently merged into a new caller's bundle.

### Proof of Concept
Handler-level Go test in `core/services/gateway/handlers/confidentialrelay`:
1. Configure a DON with `F=1` (3 members) and a fake `don.SendToNode`/clock so fan-out and timing are controllable.
2. Caller A calls `HandleJSONRPCUserMessage` with `req.ID = "collide"`, method `MethodSecretsGet`.
3. Simulate 2 of 3 nodes responding immediately (reaching `earlyNeed`), causing `forwardBundleOrTerminateIfReady` → `forwardBundle` → `sendResponseAndClearRequest`, which clears `activeRequests["collide"]` and delivers A's callback.
4. Immediately call `HandleJSONRPCUserMessage` again with `req.ID = "collide"` as Caller B (different method/params), asserting `newActiveRequest` succeeds (no "ID already exists" error).
5. Deliver the 3rd node's late `HandleNodeMessage` response for `resp.ID = "collide"` (the one meant for Caller A's request) after step 4.
6. Assert that this stale response is merged into Caller B's `activeRequest.responses` (inspect via `getActiveRequest("collide").copiedResponses()`), and that when Caller B's bundle is later forwarded, `wrapBundle`'s output—delivered to Caller B's callback—contains data derived from Caller A's node response, violating ISOLATION (Caller B should only ever see responses fanned out for Caller B's own request).

		return err
	}

}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}

// bundler assembles the gateway's response to the enclave. The gateway is a dumb
// fan-in: it forwards every per-node signed response it collected, in one bundle,
// without verifying signatures, checking signer membership, or deciding quorum.
//
// The enclave is the sole trust anchor. It groups the bundle by response hash,
// verifies each signature against the relay-DON signer set, and accepts the result
// backed by F+1 valid distinct signers. Because responses are keyed upstream by the
// gateway-authenticated node address (one response per node), a single compromised
// relay node can contribute at most its own one response to the bundle. It cannot
// manufacture quorum by fabricating signer identities; the worst it can do is add
// noise the enclave discards. This is what closes the prior liveness gap, where the
// gateway counted unverified, attacker-controlled signer identities toward quorum
// and could commit to a forged response, starving the enclave of the real one.

func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedCapabilityResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable capability response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedCapabilityResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode capability response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	default:
		return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)
	}
}

func wrapBundle(req jsonrpc.Request[json.RawMessage], encoded json.RawMessage) *jsonrpc.Response[json.RawMessage] {
	return &jsonrpc.Response[json.RawMessage]{
		Version: req.Version,
		ID:      req.ID,
		Method:  req.Method,
		Result:  &encoded,
	}
}
