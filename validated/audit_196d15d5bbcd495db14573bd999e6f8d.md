The question conflates unrelated code: it cites `types/src/epoch_change.rs` / `EpochChangeProof::verify` (consensus epoch-change proof verification) as the file/symbol, but the actual described mechanism concerns `delegation_pool::assert_and_update_proposal_used_voting_power` in the Move framework [1](#0-0) . These are unrelated subsystems (consensus type-level epoch proof verification vs. the Move-based delegation pool voting logic), and there is no code path connecting `EpochChangeProof::verify` to delegation-pool voting-power accounting.

Examining the actual delegation_pool logic: `assert_and_update_proposal_used_voting_power` only compares the stake pool's already-used voting power against `votes_per_proposal` to detect the case where the underlying stake pool voted *before* partial governance voting was enabled [2](#0-1) . If they don't match, the transaction aborts with `EALREADY_VOTED_BEFORE_ENABLE_PARTIAL_VOTING`, which blocks voting entirely rather than corrupting or misrouting voting power to a different account.

Voting power for a delegator is always computed from that delegator's own `vote_delegation` and `active_shares` balance via `calculate_and_update_voter_total_voting_power` / `update_and_borrow_mut_delegated_votes`, keyed on the delegator's or voter's own address [3](#0-2) . `beneficiary_for_operator` is used only for redirecting operator commission share purchases and stake reporting, not for voting-power computation [4](#0-3) . There is no code path by which a delegator's shares (from `add_stake`/`unlock`) get attributed to the beneficiary's voter identity — voting-power accounting and beneficiary/commission accounting are separate, non-overlapping structures (`GovernanceRecords.delegated_votes` vs `BeneficiaryForOperator`).

Since the premise misattributes the vulnerable file/symbol and the actual delegation_pool code enforces (via an abort, not silent corruption) the edge case it describes, with no share-to-voter misattribution path found, this does not meet the bar for a valid finding.

    inline fun assert_and_update_proposal_used_voting_power(
        governance_records: &mut GovernanceRecords, pool_address: address, proposal_id: u64, voting_power: u64
    ) {
        let stake_pool_remaining_voting_power = aptos_governance::get_remaining_voting_power(pool_address, proposal_id);
        let stake_pool_used_voting_power = aptos_governance::get_voting_power(
            pool_address
        ) - stake_pool_remaining_voting_power;
        let proposal_used_voting_power = governance_records.votes_per_proposal.borrow_mut_with_default(proposal_id, 0);
        // A edge case: Before enabling partial governance voting on a delegation pool, the delegation pool has
        // a voter which can vote with all voting power of this delegation pool. If the voter votes on a proposal after
        // partial governance voting flag is enabled, the delegation pool doesn't have enough voting power on this
        // proposal for all the delegators. To be fair, no one can vote on this proposal through this delegation pool.
        // To detect this case, check if the stake pool had used voting power not through delegation_pool module.
        assert!(
            stake_pool_used_voting_power == *proposal_used_voting_power,
            error::invalid_argument(EALREADY_VOTED_BEFORE_ENABLE_PARTIAL_VOTING)
        );
        *proposal_used_voting_power += voting_power;
    }
