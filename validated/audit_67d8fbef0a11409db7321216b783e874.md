### Title
Unauthenticated Vault request-digest replay guard allows front-running DoS of legitimate allowlisted requests - (File: `core/capabilities/vault/request_replay_guard.go`)

### Summary
The Vault gateway's `AllowListBasedAuth` path authorizes any inbound JSON-RPC request whose `req.Digest()` matches a digest previously allowlisted on-chain — it performs **no verification of the request's sender/origin**. Once authorized, the digest is marked "seen" for the lifetime of the on-chain expiry via a single, global `RequestReplayGuard`. Any unprivileged client able to reproduce the exact same request bytes (and therefore the same digest) as a legitimate, already-allowlisted request can submit it to the gateway first, consuming the one-time replay slot and causing every subsequent (legitimate) submission of that exact request to be rejected with `ErrRequestAlreadySeen` until the on-chain expiry timestamp elapses.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` in [1](#0-0)  authorizes purely by matching the incoming request's digest (`req.Digest()`) against entries returned by `GetAllowlistedRequests` — an on-chain, publicly readable allowlist populated by `WorkflowRegistry.AllowlistRequest(requestDigest, expiryTimestamp)`. There is no signature check, no sender/session binding, and `req.Auth == ""` is explicitly the trigger for using this unauthenticated path, as shown in `authorizer.authorizeRequest`: [2](#0-1) .

After a digest is matched, `authorizer.AuthorizeRequest` records it in a shared `RequestReplayGuard` keyed only by the digest string, with an expiry equal to the on-chain `ExpiryTimestamp` (which can be minutes to hours in the future, set by the workflow owner independent of when the real request is actually sent): [3](#0-2) .

The guard itself is a simple "first writer wins" map with no notion of caller identity: [4](#0-3) 

This mirrors the reported bug class precisely: a state-changing/enabling check (`lastBurnTimestamp == block.timestamp` in the Party contract) can be triggered by *any* actor performing an action that is indistinguishable from — and cheaper/faster than — the legitimate actor's action, permanently consuming a resource (a voting-power snapshot slot / here, a single-use digest slot) needed by the legitimate party. Here, the "action" is simply re-sending the exact same JSON-RPC bytes that hash to an already-allowlisted digest; because `AllowListBasedAuth` requires no proof of identity, any observer of the plaintext request (or anyone able to reconstruct it from publicly known fields, e.g. `owner` + `namespace` for `vault.secrets.list`) can front-run the legitimate workflow node's submission through the gateway's public/unauthenticated inbound path.

### Impact Explanation
Once an attacker's copy of the request is processed first:
- The legitimate workflow node's identical request is permanently rejected with `ErrRequestAlreadySeen` until the on-chain `ExpiryTimestamp` passes — denial of service against a specific Vault operation (secrets list/create/update/delete or public-key fetch) for the full allowlisted validity window.
- Because authorization succeeds without verifying who sent the request, if the attacker can reconstruct the exact request content (not merely observe it), they also obtain the actual response (e.g., secret identifiers list) themselves — a request-impersonation/cross-user response confusion in addition to the DoS.

This directly satisfies the "Accept only" criteria: unauthorized job/action execution (processing a Vault action on behalf of a party who never actually authenticated) and allowlist/quota bypass (the single-use slot is consumed by an unauthenticated party).

### Likelihood Explanation
Exploitability depends on the attacker's ability to reproduce the exact request bytes producing the same digest. For read-style requests where the payload is derived from public information (e.g. `vault.secrets.list` — owner address and namespace, both discoverable/predictable) this is straightforward once the digest has been allowlisted on-chain (which is itself a public transaction, `AllowlistRequest`, visible before the real gateway call is ever sent). This gives an attacker a reliable time window to front-run through the same public gateway ingress used by legitimate nodes. Reproducing digests for write requests containing freshly-encrypted secret payloads is harder, so likelihood is highest for list/read operations and lower (but not necessarily impossible, depending on how deterministic/predictable the encrypted payload construction is) for mutating operations.

### Recommendation
- Bind the replay-guard entry (and/or the on-chain allowlist match) to caller/session identity, not solely to the request digest, so an unauthenticated third party cannot consume another party's allowlisted slot.
- Alternatively/additionally, require the `AllowListBasedAuth` path to be accompanied by a lightweight proof of possession (e.g., a signature over the digest by the workflow owner's key, or restricting replay-guard consumption to the connection/session that first established the WebSocket handshake for that DON member) rather than treating "any bytes producing this digest" as authorization.
- Consider scoping the replay guard per authenticated owner rather than globally, and/or shortening effective consumption windows independent of the (owner-controlled, potentially long) on-chain `ExpiryTimestamp`.

### Proof of Concept
Conceptual PoC (mirrors the structure of `TestAllowListBasedAuth_RetriesUntilRequestIsAllowlisted` [5](#0-4)  and `TestAuthorizer_RejectsJWTReplayDuringValidationLeewayWindow` [6](#0-5) ):

1. Workflow owner `O` submits `WorkflowRegistry.AllowlistRequest(digest_D, expiry_T)` on-chain for a `vault.secrets.list` request with public params `{owner: O, namespace: "main"}`. This transaction and digest are publicly visible.
2. Attacker `A` (unprivileged, connected to the same gateway) reconstructs the identical JSON-RPC request (`method=vault.secrets.list`, `params={owner:O, namespace:"main"}`, same request `ID` scheme) so that `req.Digest()` equals `digest_D`, and submits it to the gateway with `req.Auth == ""` before `O`'s actual workflow node does.
3. `allowListBasedAuth.AuthorizeRequest` finds `digest_D` in `GetAllowlistedRequests` and returns an `AuthResult` with `expiresAt = T`; `authorizer.AuthorizeRequest` calls `a.replayGuard.CheckAndRecord(digest_D, T)`, which succeeds and marks `digest_D` as seen until `T`.
4. When `O`'s legitimate workflow node subsequently sends the same request, `CheckAndRecord` finds `digest_D` already present and returns `ErrRequestAlreadySeen`, causing `authorizer.AuthorizeRequest` to reject the legitimate request — reproducing the front-run/DoS pattern described in the external report, until timestamp `T` elapses.

Note: I could not locate the gateway-facing `HandleGatewayMessage`/inbound entrypoint for the Vault handler under `core/services/gateway/handlers/vault/` within the indexed context (only its test file `handler_test.go` was found), so the exact wiring from public gateway ingress to `Authorizer.AuthorizeRequest` for this handler could not be fully traced in this session; the `core/capabilities/vault/gw_handler.go` node-side handler and its request processor were confirmed to route through this `Authorizer`. A full trace of the gateway-side dispatch would benefit from a Devin session with complete repository access.

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func TestAllowListBasedAuth_RetriesUntilRequestIsAllowlisted(t *testing.T) {
	lggr := logger.TestLogger(t)
	owner := common.Address{1, 2, 3}
	req := makeListSecretsRequest(t, "123", "b")

	digest, err := req.Digest()
	require.NoError(t, err)
	digestBytes, err := hex.DecodeString(digest)
	require.NoError(t, err)
	expiry := time.Now().UTC().Unix() + 100
	allowlisted := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{
		{
			RequestDigest:   [32]byte(digestBytes),
			Owner:           owner,
			ExpiryTimestamp: uint32(expiry), //nolint:gosec // it is a safe conversion
		},
	}

	mockSyncer := syncerv2mocks.NewWorkflowRegistrySyncer(t)
	auth := NewAllowListBasedAuth(lggr, mockSyncer)
	auth.retryCount = 2
	auth.retryInterval = time.Millisecond

	mockSyncer.On("GetAllowlistedRequests", mock.Anything).Return([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}).Once()
	mockSyncer.On("GetAllowlistedRequests", mock.Anything).Return([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}).Once()
	mockSyncer.On("GetAllowlistedRequests", mock.Anything).Return(allowlisted).Once()

	authResult, err := auth.AuthorizeRequest(t.Context(), req)
	require.NoError(t, err)
	require.Equal(t, owner.Hex(), authResult.AuthorizedOwner())
	require.Equal(t, expiry, authResult.ExpiresAt())
}

func TestAuthorizer_RejectsJWTReplayDuringValidationLeewayWindow(t *testing.T) {
	rsaKey := generateTestRSAKey(t, "key-1")
	jwksServer := newTestJWKSServer(t, rsaKey)

	issuer := jwksServer.URL() + "/"
	audience := "https://vault.test.chain.link"
	v := newTestValidator(t, issuer, audience)

	derivedOrg123Owner := testJWTExpectedWorkflowOwner(t, 1, "org-123")
	rawRequest := fmt.Appendf(nil, `{"jsonrpc":"2.0","id":"req-1","method":"vault.secrets.list","params":{"request_id":"req-1","owner":"%s","namespace":"main"}}`, derivedOrg123Owner)
	req, err := jsonrpc.DecodeRequest[json.RawMessage](rawRequest, "")
	require.NoError(t, err)

	digest, err := req.Digest()
	require.NoError(t, err)

	// Raw exp is in the past but still within the JWT validation leeway window.
	tokenExp := time.Now().Add(-30 * time.Second)
	token := createTestJWT(t, rsaKey, jwt.MapClaims{
		"iss":                             issuer,
		"aud":                             audience,
		"exp":                             jwt.NewNumericDate(tokenExp),
		"iat":                             jwt.NewNumericDate(time.Now().Add(-2 * time.Minute)),
		"org_id":                          "org-123",
		ClaimVaultSecretManagementEnabled: "true",
		ClaimChainlinkTenantID:            "1",
		"scope":                           OAuthScopeVaultSecretsList,
		"authorization_details": []any{
			map[string]any{
				"type":  "request_digest",
				"value": digest,
			},
		},
	})

	req, err = jsonrpc.DecodeRequest[json.RawMessage](rawRequest, token)
	require.NoError(t, err)

	a := NewAuthorizer(nil, v, logger.TestLogger(t))

	authResult, err := a.AuthorizeRequest(t.Context(), req)
	require.NoError(t, err)
	require.Equal(t, digest, authResult.Digest())
	require.Equal(t, tokenExp.UTC().Add(time.Minute).Unix(), authResult.ExpiresAt())

	authResult, err = a.AuthorizeRequest(t.Context(), req)
	require.Nil(t, authResult)
	require.ErrorIs(t, err, ErrRequestAlreadySeen)
}
