### Title
Unauthenticated symbol-table disclosure via `/plugins/:name/debug/pprof/symbol` proxy - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers plugin pprof endpoints, including the POST symbol-resolution endpoint, on the `api` router group without any `auth.Authenticate` middleware, unlike every other debug/admin route (`debugRoutes`, `authv2`, `metricRoutes`). This lets any unauthenticated network client resolve plugin binary symbol addresses by proxying through the node.

### Finding Description
In `core/web/router.go`, `NewRouter` mounts `loopRoutes(app, api)` directly on the `api` group, which is only wrapped with rate limiting and session-store attachment (`sessions.Sessions`), neither of which enforces authentication: [1](#0-0) 

`loopRoutes` itself applies no `auth.Authenticate` wrapper at all, in contrast to `debugRoutes` (line 181) which explicitly wraps its group with `auth.Authenticate(..., auth.AuthenticateBySession)`, and `metricRoutes` which is only invoked inside the authenticated `authv2` block (line 446): [2](#0-1) 

The handler `pluginPPROFPOSTSymbolHandler` in `core/web/loop_registry.go` looks up the named plugin in the registry, reads the raw request body (attacker-controlled address list), and proxies it as a POST to the plugin's internal `/debug/pprof/symbol` endpoint, then returns the response body verbatim to the caller: [3](#0-2) 

Because there is no authentication check anywhere on this path, `sessions.Sessions` merely attaches a cookie session store (it does not require a valid session), and `rateLimiter` only throttles request rate — it does not verify identity. Any network caller who can reach the node's web port can hit this route without credentials.

### Impact Explanation
An unauthenticated attacker can resolve program-counter addresses to function/symbol names for any registered LOOP plugin binary (e.g., EVM/Solana relayer plugins, median/mercury plugins), which discloses internal binary layout/symbol information. This is reconnaissance-class information disclosure that can materially aid further exploitation (e.g., crafting targeted memory-corruption or logic-abuse exploits against the plugin), matching a "sensitive information disclosure" bounty class rather than direct fund loss.

### Likelihood Explanation
No preconditions are required: no credentials, API token, or session cookie. The attacker only needs network reachability to the node's HTTP port and a running/registered LOOP plugin (`:name` matching an entry in `plugins.LoopRegistry`). This is trivially repeatable via a single unauthenticated HTTP POST.

### Recommendation
Wrap `loopRoutes` (or at minimum the pprof-related routes: `/plugins/:name/debug/pprof/*profile` and `/plugins/:name/debug/pprof/symbol`) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or token-based) middleware used by `debugRoutes`/`authv2`, so pprof/symbol endpoints require an authenticated admin/edit-role session, consistent with `metricRoutes` being gated behind `authv2`.

### Proof of Concept
Go handler-level integration test plan:
1. Build a `gin.Engine` via `NewRouter` (or directly register `loopRoutes` on a test router) with a `chainlink.Application` mock whose `GetLoopRegistry()` returns a registry containing a fake plugin `"testplugin"` pointing at a local `httptest.Server` that implements `/debug/pprof/symbol` (echoing resolved symbol names).
2. Using `httptest.NewRecorder()`/`net/http/httptest`, issue `POST /plugins/testplugin/debug/pprof/symbol` with body `0x<addr>` and **no** `Authorization` header, `Cookie`, or session.
3. Assert response status is `200 OK` (not `401 Unauthorized`) and the response body contains the resolved symbol data from the backing pprof server, proving the request reached `pluginPPROFPOSTSymbolHandler` without authentication.
4. Contrast with a request to an authenticated route (e.g., `/v2/keys/csa`) without credentials, asserting `401`, to demonstrate the discrepancy in auth enforcement between `loopRoutes` and `authv2`.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
