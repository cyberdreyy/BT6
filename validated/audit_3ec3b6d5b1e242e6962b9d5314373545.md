### Title
Unbounded per-account JsonParsed re-encoding/mint-lookup in `get_parsed_token_accounts` allows attacker-driven notifier-thread CPU amplification for `programSubscribe` - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`get_parsed_token_accounts` in `rpc/src/parsed_token_accounts.rs` performs a synchronous, per-account `encode_ui_account(..., UiAccountEncoding::JsonParsed, ...)` call plus, for each account whose mint is not already in a call-local cache, a `bank.get_account()` lookup and `StateWithExtensions::<Mint>::unpack()` decode. This function is invoked from the `programSubscribe` notification path in `rpc_subscriptions.rs` (via `filter_program_results`) whenever accounts owned by the subscribed program change in a slot, with no cap on the number of accounts processed per notification tick. The cost is bounded only by the number of distinct token accounts/mints an attacker chooses to mutate in a slot, not by any fixed limit.

### Finding Description
`get_parsed_token_accounts` [1](#0-0)  iterates the keyed accounts passed to it, and for each one:
1. Extracts the token account's mint via `get_token_account_mint`.
2. Looks up cached mint additional-data in a `HashMap` local to that single call; on a cache miss it calls `get_mint_owner_and_additional_data`, which does `bank.get_account(mint)` followed by `StateWithExtensions::<Mint>::unpack` and extension parsing [2](#0-1) .
3. Calls `encode_ui_account(..., UiAccountEncoding::JsonParsed, ...)`, which performs full JSON-parsed decoding of the token account layout.

This function is imported and used by `rpc_subscriptions.rs`'s program-notification path [3](#0-2) , which is triggered synchronously by slot/account-change notifications delivered to the pubsub notifier. Because the mint cache is scoped to a single call (i.e., a single notification tick) rather than persisted across ticks, and because there is no limit on the number of distinct accounts/mints processed in one call, an attacker who submits enough transactions in a slot to mutate a large number of distinct spl-token accounts (especially accounts under many distinct mints, defeating the intra-call cache) forces the notifier thread to perform O(N) mint lookups and O(N) JsonParsed decodes on every notification tick, for every subscriber.

### Impact Explanation
This maps to an RPC pubsub notifier-thread CPU exhaustion / starvation issue: work done per notification scales linearly (or worse, with repeated `bank.get_account` + `Mint::unpack` for distinct mints) with attacker-controlled account fan-out rather than being bounded by a fixed constant, which can delay or stall notification delivery for all `programSubscribe` clients on that RPC node while the accounts/mints are being processed. This falls under "non-RPC remote resource exhaustion" / RPC crash-adjacent categories, scoped to the RPC pubsub subsystem only.

### Likelihood Explanation
An unprivileged attacker only needs to: (a) open a `programSubscribe` subscription with `jsonParsed` encoding to the spl-token program (or use their own subscription, or rely on any node's existing subscribers), and (b) submit ordinary funded transactions in a slot that create/mutate many distinct token accounts across many distinct mints. Both actions require no special privileges — only transaction fees/rent for the accounts created, which is a cost the attacker bears but that scales sub-linearly relative to the RPC-side quadratic-ish parsing/lookup cost imposed on every connected subscriber node. This is repeatable every slot as long as the attacker keeps submitting transactions, and does not require repeated RPC calls, multiple colluding clients, or `getProgramAccounts`-style scanning — it is driven purely by normal transaction submission plus the existence of the pubsub notification path itself, which is on by default for any RPC node offering `programSubscribe`.

### Recommendation
Bound per-notification work in `get_parsed_token_accounts`/`filter_program_results`: cap the number of accounts processed per notification tick, defer/batch excess accounts to subsequent ticks, and/or persist the mint-additional-data cache across ticks (keyed by slot or with bounded TTL) so repeated mint lookups are not repeated in every notification cycle. Additionally, consider moving encode work off the critical notifier thread (e.g., into a bounded worker pool) so a burst of large N cannot block delivery to unrelated subscribers.

pub fn get_parsed_token_accounts<I>(
    bank: Arc<Bank>,
    keyed_accounts: I,
) -> impl Iterator<Item = RpcKeyedAccount>
where
    I: Iterator<Item = (Pubkey, AccountSharedData)>,
{
    let mut mint_data: HashMap<Pubkey, AccountAdditionalDataV3> = HashMap::new();
    keyed_accounts.filter_map(move |(pubkey, account)| {
        let additional_data = get_token_account_mint(account.data()).and_then(|mint_pubkey| {
            mint_data.get(&mint_pubkey).cloned().or_else(|| {
                let (_, data) = get_mint_owner_and_additional_data(&bank, &mint_pubkey).ok()?;
                let data = AccountAdditionalDataV3 {
                    spl_token_additional_data: Some(data),
                };
                mint_data.insert(mint_pubkey, data);
                Some(data)
            })
        });

        let maybe_encoded_account = encode_ui_account(
            &pubkey,
            &account,
            UiAccountEncoding::JsonParsed,
            additional_data,
            None,
        );
        if let UiAccountData::Json(_) = &maybe_encoded_account.data {
            Some(RpcKeyedAccount {
                pubkey: pubkey.to_string(),
                account: maybe_encoded_account,
            })
        } else {
            None
        }
    })
}

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
