### Title
Unbounded recursive descent in the fault-proof program's MPT walker allows a dispute-game participant to crash proof execution via preimage-oracle-supplied trie data - (File: crates/proof/mpt/src/list_walker.rs, crates/proof/mpt/src/node.rs)

### Summary
The Base fault-proof program uses `base-proof-mpt`, "a recursive, in-memory implementation of Ethereum's hexary Merkle Patricia Trie" [1](#0-0) , to walk trie structures whose node preimages are supplied on demand by an untrusted `TrieProvider`/preimage oracle during fault-proof execution [2](#0-1) . Both `TrieNode::open`/`insert`/`delete`/`unblind` and `OrderedListWalker::fetch_leaves` recurse into child/blinded nodes with no depth bound, analogous to the missing recursion-depth guard that caused CVE-2025-71161's dm-verity DoS.

### Finding Description
`TrieNode::open`, `insert`, `delete`, and `unblind` in `crates/proof/mpt/src/node.rs` are mutually and self-recursive: `Blinded` nodes are unblinded by fetching a preimage from the caller-supplied `fetcher: F: TrieProvider` and then immediately recursing back into `open`/`delete` on the freshly-fetched node [3](#0-2) [4](#0-3) . `OrderedListWalker::fetch_leaves` in `crates/proof/mpt/src/list_walker.rs` similarly recurses over every `Branch`/`Extension` child, unblinding and recursing again for each `Blinded` child, with no depth or node-count limit [5](#0-4) .

Nodes are validated only by keccak256 pre-image matching, not by structural sanity, so any actor who controls what preimages the oracle/host returns for the block's trie roots (transactions, receipts, withdrawals, or account/storage state visited by `get_trie_account`, which itself triggers this same recursive `open` walk [6](#0-5) ) can shape an arbitrarily deep chain of `Extension`/`Blinded` nodes. Because the fault-proof program runs inside a constrained fault-proof VM / zkVM execution environment (limited native stack, as also evidenced by this repo's own stack-overflow-detection tooling in `crates/utilities/cli/tests/sigsegv_test.rs` [7](#0-6) ), unbounded recursive descent risks exhausting the call stack and aborting the fault-proof program before it can compute an output root — the same root-cause class as CVE-2025-71161: recursion depth that is not bounded, driven entirely by attacker-supplied/attacker-shaped input data.

### Impact Explanation
If a dispute-game participant can cause the offchain fault-proof program (or the onchain interactive fraud-proof MIPS/RISC-V execution that mirrors it) to crash mid-execution by supplying a deeply-nested trie structure through the preimage oracle, the node can no longer compute or verify the claimed output root for that dispute — a denial of service against proof generation/verification that can stall the dispute-game resolution or force an incorrect/absent output root (wrong provable output root), which is one of the explicitly in-scope high-impact outcomes.

### Likelihood Explanation
Likelihood is moderate rather than certain: for the account/storage state trie, path length is bounded by the fixed 256-bit keccak key (~64 nibbles), which caps `open`'s recursion depth naturally. However, `OrderedListWalker` (used for the ordered lists — transactions, receipts, withdrawals — reconstructed during derivation/execution inside the fault-proof program) has no such fixed-length key constraint, and its recursion depth is bounded only by how the preimage oracle chooses to shape the trie for the requested root, which is attacker-influenceable in an adversarial dispute-game scenario. I was not able to fully verify from the indexed code how tightly the surrounding fault-proof/executor code caps the number of preimage hints or total trie nodes fetched per root, which affects how deep an adversarial chain of `Extension`/`Blinded` nodes could actually be driven in practice.

### Recommendation
Convert the recursive `open`/`insert`/`delete`/`unblind` and `fetch_leaves` traversals in `crates/proof/mpt/src/node.rs` and `crates/proof/mpt/src/list_walker.rs` to iterative (loop-based) traversals, or add an explicit maximum-depth counter that returns a `TrieNodeError`/`OrderedListWalkerError` once exceeded, mirroring the dm-verity fix of eliminating unbounded recursive correction rather than merely capping recursion count.

### Proof of Concept
Not independently reproducible from the indexed context alone: a full PoC would require constructing a chain of RLP-encoded `Extension`/`Blinded` `TrieNode`s whose keccak256 hashes are supplied via a custom `TrieProvider`/preimage oracle implementation for a given ordered-list root, then invoking `OrderedListWalker::hydrate` (or `TrieNode::open` for an account path) with a recursion depth sufficient to overflow the fault-proof VM's stack — this requires running the actual fault-proof host/client binaries, which is beyond what could be confirmed via static code search alone.

# `base-proof-mpt`

A recursive, in-memory implementation of Ethereum's hexary Merkle Patricia Trie (MPT).

## Overview

Implements Ethereum's Merkle Patricia Trie with support for retrieval, insertion, deletion, and
root computation via RLP-encoded trie node encoding. Starting from a trie root hash, `TrieNode`
lazily fetches and caches node preimages via `TrieProvider`, enabling stateless block execution
without storing the full state. Designed as the trie backend for [`base-proof-executor`](../executor).

    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.
                *self = Self::Empty;
            } else {
                *self = fetcher
                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }

    pub fn delete<F: TrieProvider>(&mut self, path: &Nibbles, fetcher: &F) -> TrieNodeResult<()> {
        match self {
            Self::Empty => Err(TrieNodeError::KeyNotFound),
            Self::Leaf { prefix, .. } => {
                if path == prefix {
                    *self = Self::Empty;
                    Ok(())
                } else {
                    Err(TrieNodeError::KeyNotFound)
                }
            }
            Self::Extension { prefix, node } => {
                let shared_nibbles = path.common_prefix_length(prefix);
                if shared_nibbles < prefix.len() {
                    return Err(TrieNodeError::KeyNotFound);
                } else if shared_nibbles == path.len() {
                    *self = Self::Empty;
                    return Ok(());
                }

                node.delete(&path.slice(prefix.len()..), fetcher)?;

                // Simplify extension if possible after the deletion
                self.collapse_if_possible(fetcher)
            }
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack[branch_nibble].delete(&path.slice(BRANCH_NODE_NIBBLES..), fetcher)?;

                // Simplify the branch if possible after the deletion
                self.collapse_if_possible(fetcher)
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.delete(path, fetcher)
            }
        }

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }

    pub fn get_trie_account(
        &mut self,
        address: &Address,
        block_number: u64,
    ) -> TrieDBResult<Option<TrieAccount>> {
        // Send a hint to the host to fetch the account proof.
        self.hinter
            .hint_account_proof(*address, block_number)
            .map_err(|e| TrieDBError::Provider(e.to_string()))?;

        // Fetch the account from the trie.
        let hashed_address_nibbles = Nibbles::unpack(keccak256(address.as_slice()));
