### Title
Unauthenticated exposure of LOOP plugin discovery, metrics proxy, and pprof/debug endpoints - ([File: core/web/router.go])

### Summary
`loopRoutes` is registered directly on the base `api` router group in `NewRouter` without any `auth.Authenticate` wrapper, unlike every other sensitive route group (`debugRoutes`, `sessionRoutes`, `v2Routes`). This allows any unauthenticated client to enumerate LOOP plugin names via `/discovery` and then pull full pprof profiling/heap data and Prometheus metrics for any registered plugin.

### Finding Description
In `core/web/router.go`, the route registration sequence is: [1](#0-0) 
`debugRoutes` wraps its group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` before exposing `/debug/vars`: [2](#0-1) 
But `loopRoutes` registers directly on `r` (the raw `api` group) with no authentication middleware at all: [3](#0-2) 

This means `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` are reachable by any client that can reach the node's HTTP port, with no session cookie or bearer token required. The handlers in `core/web/loop_registry.go` back this up:
- `discoveryHandler` enumerates all registered LOOP plugins and their metrics paths (`l.registry.List()`), returning plugin names in the JSON service-discovery response. [4](#0-3) 
- `pluginPPROFHandler` proxies arbitrary pprof profile paths (heap, goroutine, profile, trace, etc.) straight through to the internal plugin process based on attacker-supplied `:name` and `*profile` parameters, with no role check performed anywhere in the call chain. [5](#0-4) 

Compare this to the equivalent node-level pprof routes in `metricRoutes`, which are only mounted inside the authenticated `authv2` group (`RequiresAdminRole`-adjacent context) via `metricRoutes(authv2)`: [6](#0-5) 
The LOOP-plugin equivalent bypasses this pattern entirely.

### Impact Explanation
An unauthenticated attacker who can reach the node's web server can discover the names of all installed LOOP plugins and pull heap/goroutine/CPU profiling dumps and Prometheus metrics for each plugin process. Heap and goroutine dumps can leak in-memory secrets, configuration values, or other sensitive state from the plugin process, and repeated `/debug/pprof/profile?seconds=N` requests can be used to consume CPU/goroutine resources on the internal plugin, creating an information-disclosure and resource-exhaustion vector without any credentials. This corresponds to the "sensitive data exposure / unauthorized internal information disclosure" bounty class.

### Likelihood Explanation
No preconditions or credentials are required beyond network reachability to the node's HTTP listener — the same listener that serves the operator UI and API. Any LOOP-plugin-enabled node (i.e., any node configured to run Chainlink LOOPPs) is affected, and the endpoints are simple GET/POST requests, making this trivially repeatable.

### Recommendation
Wrap `loopRoutes` with the same authentication middleware used elsewhere (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), and consider gating pprof/debug access behind `auth.RequiresAdminRole` similar to other admin-only debug/key-management endpoints, mirroring how `debugRoutes` and `metricRoutes` (inside `authv2`) are protected.

### Proof of Concept
Add a handler-level integration test in `core/web/router_test.go` (or a new test file) that:
1. Builds a `chainlink.Application` mock/test app with `GetLoopRegistry()` returning a registry containing at least one registered plugin (name `"test-plugin"`, some `PrometheusPort`).
2. Calls `web.NewRouter(app, nil)` to get the `*gin.Engine`, wraps it in `httptest.NewServer`.
3. Issues `http.Get(srv.URL + "/discovery")` with no cookies/headers and asserts the response is `401`/`403` (currently returns `200` with a JSON body listing `"test-plugin"`).
4. Issues `http.Get(srv.URL + "/plugins/test-plugin/metrics")` with no auth and asserts `401`/`403` (currently proxies to the plugin and returns `200`).
5. Issues `http.Get(srv.URL + "/plugins/test-plugin/debug/pprof/heap")` with no auth and asserts `401`/`403` (currently proxies pprof heap dump and returns `200`).
6. Repeats each request with a valid session cookie only after the fix, expecting `200`, to confirm the fix does not break legitimate authenticated access.

```go
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
