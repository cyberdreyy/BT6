### Title
Unauthenticated pprof profile disclosure for LOOP plugin processes via `/plugins/:name/debug/pprof/*` - ([File: core/web/router.go], [File: core/web/loop_registry.go])

### Summary
The `loopRoutes` function registers `GET /plugins/:name/debug/pprof/*profile` and `POST /plugins/:name/debug/pprof/symbol` directly on the base router group without any `auth.Authenticate` middleware, unlike other sensitive routes (e.g. `/debug/vars`, `/v2/*`) which are wrapped in authenticated route groups. This lets any unauthenticated network client pull full pprof profiles (heap, goroutine, cpu profile, trace, allocs, etc.) from a running LOOP plugin process.

### Finding Description
In `core/web/router.go`, `loopRoutes` is registered on the plain `api` group with no auth wrapper: [1](#0-0) 

Contrast this with `debugRoutes`, which explicitly requires session authentication before exposing `/debug/vars`: [2](#0-1) 

and with `v2Routes`, whose sensitive endpoints are placed under `authv2 := r.Group("/v2", auth.Authenticate(...))`: [3](#0-2) 

The `pluginPPROFHandler` implementation in `core/web/loop_registry.go` takes the `:name` and `*profile` path parameters directly from the unauthenticated request, looks up the plugin's internal Prometheus port in the registry, and proxies the request to the plugin's `/debug/pprof/<profile>` endpoint, returning the raw response body to the caller: [4](#0-3) [5](#0-4) 

Since `api` (the parent gin group passed into `loopRoutes`) only applies rate limiting and session store initialization — not authentication — any client that can reach the node's HTTP API can call this route with zero credentials. The `pluginPPROFPOSTSymbolHandler` (symbol resolution) is similarly unauthenticated. This allows unauthenticated retrieval of heap dumps, goroutine stack traces, CPU/execution traces, and other pprof profiles that can expose in-memory data (e.g., decrypted key material, secrets held in variables, internal addresses/URLs, config values) and aid further exploitation via stack trace/code disclosure.

### Impact Explanation
This is an authorization/authentication bypass exposing sensitive runtime memory diagnostics without any credential, matching Chainlink bounty impact classes around "sensitive data disclosure" / "unauthorized access to node internals." Depending on what secrets happen to be resident in the plugin process memory (e.g., decrypted private keys, mercury/telemetry auth tokens, DB URLs held in `loop.EnvConfig` per `plugins/loop_registry.go`), heap/goroutine dumps could leak them.

### Likelihood Explanation
No preconditions or credentials are required — the attacker only needs network access to the node's HTTP API endpoint and knowledge (or brute-force enumeration) of a registered plugin name. The route is trivially reachable and repeatable (`GET /plugins/<name>/debug/pprof/heap`), making this highly likely to be exploitable wherever the node HTTP interface is reachable by untrusted clients.

### Recommendation
Wrap `loopRoutes` (or at minimum the `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol` routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (and/or admin-role requirement, mirroring `debugRoutes`) that protects `/debug/vars`, so pprof data can only be retrieved by authenticated, sufficiently privileged users.

### Proof of Concept
Add a handler-level integration test in `core/web` similar to `TestLoopRegistry` in `core/web/loop_registry_test.go`:
1. Start the app/router as in `TestLoopRegistry`, register a mock LOOP plugin via `app.GetLoopRegistry().Register("mockLoopImpl")`.
2. Using an **unauthenticated** `http.Client` (not `app.NewHTTPClient` with session cookies, or a raw client without the auth cookie/token), issue `GET /plugins/mockLoopImpl/debug/pprof/heap`.
3. Assert the response status is `200 OK` (not `401`/`403`) and that the body is a valid pprof binary profile (e.g., starts with the pprof gzip magic bytes, or can be parsed via `github.com/google/pprof/profile`).
4. Repeat for `/plugins/mockLoopImpl/debug/pprof/goroutine?debug=1` and confirm goroutine stack traces are returned in plaintext.
5. As a negative control, confirm `GET /debug/vars` returns `401` for the same unauthenticated client, demonstrating the inconsistency between `debugRoutes` and `loopRoutes`.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
