# Missing beneficiary registration check in `staking_contract::set_beneficiary_for_operator` allows an operator to permanently block distribution of unlocked stake and commission - (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

## Summary
`staking_contract::set_beneficiary_for_operator` lets an operator redirect commission to an arbitrary `new_beneficiary` address without verifying that the address can actually receive `AptosCoin`. This is the exact same class of bug as the C4 report: a downstream call (`aptos_account::deposit_coins` acting like the missing `approve`) is guaranteed to fail for a legitimate, foreseeable configuration, and the failure aborts the *entire* atomic operation rather than just the affected leg — reverting `distribute()` for every other stakeholder sharing the same `distribution_pool`.

## Finding Description
`staking_contract::set_beneficiary_for_operator` stores `new_beneficiary` with no validation: [1](#0-0) 

Compare this with `vesting::set_beneficiary`, which explicitly guards against this exact failure mode with a comment describing the risk: [2](#0-1) 

`distribute_internal` iterates over *all* shareholders of the shared `distribution_pool` in a single atomic loop, and when the current shareholder is the operator, redirects the payout to `beneficiary_for_operator(operator)`: [3](#0-2) 

The payout uses `aptos_account::deposit_coins`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has opted out of unregistered direct coin transfers (`DirectTransferConfig.allow_arbitrary_coin_transfers == false`) and has not registered a `CoinStore<AptosCoin>`: [4](#0-3) 

Because `distribute()` is a `while` loop over `distribution_pool.shareholders()` that pays out one recipient at a time within a single transaction, a single unpayable recipient (the operator's misconfigured beneficiary) causes the whole call to abort, so **no shareholder in that loop — including the staker — can receive their already-unlocked/inactive stake** via that `distribute()` invocation: [5](#0-4) 

`distribute()` is explicitly permissionless ("Allow anyone to distribute already unlocked funds"), so any caller who tries to trigger the payout will keep hitting the same abort: [6](#0-5) 

## Impact Explanation
This matches the "Permanent lock or non-recoverable loss of claim rights in stake ... commission, beneficiary" impact category. Once triggered:
- The staker's already-unlocked/inactive stake in that `StakingContract` cannot be withdrawn through `distribute()` (it will always abort at the broken beneficiary recipient).
- The operator's own commission is also stuck, since it's part of the same atomic loop.
- The only fix is for the operator (the party who caused the block, and who might do so maliciously to grief the staker or extort concessions) to call `set_beneficiary_for_operator` again with a valid, receivable address — the staker itself has no ability to unblock the pool, since `set_beneficiary_for_operator` is restricted to the operator's own signer.

This is a real griefing/DoS vector on withdrawal rights that a normal (non-privileged) operator role can trigger against the staker without needing any elevated privileges.

## Likelihood Explanation
Likelihood is moderate: it requires the operator to either accidentally or intentionally set a beneficiary address that has called `aptos_account::set_allow_direct_coin_transfers(false)` and never registered a `CoinStore<AptosCoin>` (e.g., a resource account, a freshly generated address never used to hold APT, or any account that has explicitly opted out of unsolicited transfers). This is plausible operational error, and trivially reproducible/weaponizable by a malicious operator since `set_beneficiary_for_operator` has no validation at all, unlike the analogous `vesting::set_beneficiary` function which the codebase authors clearly recognized needed this exact protection.

## Recommendation
Add the same safeguard used in `vesting::set_beneficiary` to `staking_contract::set_beneficiary_for_operator`: require the new beneficiary to be already registered to receive `AptosCoin` (or otherwise guaranteed to accept the deposit) before allowing the update, e.g. call `aptos_account::assert_account_is_registered_for_apt(new_beneficiary)` (or equivalent) prior to persisting `new_beneficiary`. Additionally, consider hardening `distribute_internal` so that a single unpayable recipient does not block payouts to all other shareholders (e.g., skip/queue the failing recipient instead of aborting the whole loop).

## Proof of Concept
1. Staker creates a `staking_contract` with `operator` via `staking_contract::create_staking_contract`.
2. A throwaway account `B` calls `aptos_account::set_allow_direct_coin_transfers(&B_signer, false)` and never registers a `CoinStore<AptosCoin>`.
3. `operator` calls `staking_contract::set_beneficiary_for_operator(&operator_signer, B)` — succeeds with no validation (line 810-829).
4. Stake pool earns rewards; staker calls `unlock_stake`/waits for lockup to expire so some stake becomes `inactive`.
5. Anyone calls `staking_contract::distribute(staker, operator)`.
6. `distribute_internal` reaches the shareholder `operator`, remaps `recipient` to `B` (line 896-898), and calls `aptos_account::deposit_coins(B, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` because `B` is not registered and has opted out (aptos_account.move line 123-127).
7. The entire `distribute()` transaction reverts — the staker's unlocked/inactive APT (and operator's own commission) remains stuck in the stake pool, and every future call to `distribute()` will revert the same way until `operator` fixes the beneficiary.

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
