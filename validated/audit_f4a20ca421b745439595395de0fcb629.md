### Title
Response cross-delivery due to MessageId-only keyed `savedCallbacks` map with no sender binding - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The gateway's `capabilities.handler` stores pending user callbacks in `savedCallbacks` keyed solely by `msg.Body.MessageId`, with no binding to the original requester's `Sender`. Since `ValidatedRequestFromMessage`/`ValidatedResponseFromMessage` only check that `MessageId` is non-empty (no uniqueness/nonce enforcement), an attacker who submits a request with the same `MessageId` as a victim's concurrently in-flight request can overwrite the victim's saved callback entry, causing a node response for one request to be delivered to the other requester.

### Finding Description
`ValidatedResponseFromMessage` and `ValidatedRequestFromMessage` in `core/services/gateway/handlers/common/message_util.go` only validate that `msg.Body.MessageId` (and `Method` for requests) is non-empty: [1](#0-0) 

Neither function, nor the `api.Message.Validate()` used earlier in `gateway.go` `ProcessRequest`, enforces uniqueness of `MessageId` across concurrent requests. `MessageId` is attacker-controlled: it comes from `jsonRequest.ID`, only bounded to 200 characters: [2](#0-1) 

When a legacy request reaches the capabilities handler, `HandleLegacyUserMessage` stores the callback keyed purely by `MessageId`: [3](#0-2) 

If a second request (from a different `Sender`) arrives concurrently using the same `MessageId`, it silently overwrites the first requester's entry in `h.savedCallbacks`, because the map key does not include `Sender`. When a node response subsequently arrives, `HandleNodeMessage` only validates that the responding node address matches `msg.Body.Sender` of the *node* (i.e. that the DON node signed it), but never validates that the response correlates back to the specific originating end-user request/session: [4](#0-3) 

The lookup/delivery logic in `handleWebAPITriggerMessage`/`handleWebAPIOutgoingMessage` retrieves and deletes whatever entry currently sits at `savedCallbacks[msg.Body.MessageId]` and delivers the response to it, with no check that it belongs to the same user who initiated that particular payload: [5](#0-4) 

The same pattern (MessageId-only keyed map, no Sender check on delivery) exists in the simpler `dummyHandler`: [6](#0-5) 

Exploit flow: attacker submits `HandleLegacyUserMessage` request A with `MessageId="X"`. Victim's client (independently, at the same time) submits request B with `MessageId="X"`. Whichever call runs second under `h.mu.Lock()` overwrites `savedCallbacks["X"]`, orphaning the other request's callback. When the DON responds to either A or B (both requests are forwarded to nodes with `ID: "X"`, so nodes/gateway cannot otherwise distinguish them), `HandleNodeMessage` delivers whatever response arrives first to the *currently stored* callback — which may belong to the other party. This breaks request/response correlation isolation, resulting in cross-delivery of one user's response to another user.

### Impact Explanation
This is a "cross-user response confusion" bug: a low-privileged, unauthenticated gateway client can, by choosing a colliding `MessageId`, cause a legitimate victim's response payload (e.g., HTTP-target/action responses, trigger event payloads carrying data derived from a workflow's request) to be delivered to the attacker's callback instead of the victim's, and vice versa cause the victim to receive a stale/attacker's response. Depending on the capability (`web_api_target`, `compute_action`, `workflow_syncer`, `web_api_trigger`), the delivered data could include response bodies or execution results not intended for the receiving party, and orphaned legitimate requests will simply time out (denial of that specific request).

### Likelihood Explanation
Preconditions are minimal: no privileged role is required — any unauthenticated/low-privileged client able to send legacy gateway requests can choose an arbitrary `MessageId` string (bounded to 200 chars) and race it against a known or guessable victim `MessageId`. The main constraint is timing (the two requests must be concurrently in-flight in the same DON handler instance) and knowledge of the victim's exact `MessageId`, which the question's threat model already grants as a precondition. The bug is deterministic given map-key collision and requires no cryptographic break.

### Recommendation
Bind saved callbacks and response delivery to the full request identity, not just `MessageId`. Options: (1) key `savedCallbacks` by a composite of `Sender + MessageId` (or `Sender + DonId + MessageId`), and reject/queue rather than overwrite existing entries for a duplicate key; (2) when storing the callback, also record the expected `Sender`, and in `HandleNodeMessage`/`handleWebAPITriggerMessage`/`handleWebAPIOutgoingMessage`, verify the response's target correlates to that original sender before delivering; (3) enforce `MessageId` uniqueness per requester within the callback's TTL window and return an explicit error to duplicate submitters instead of silently overwriting.

### Proof of Concept
Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build two signed `api.Message` legacy requests A (Sender = key1) and B (Sender = key2), both with identical `MessageId = "dup-id"`, both `Method = MethodWebAPITrigger`, valid non-stale payloads.
2. Call `handler.HandleLegacyUserMessage(ctx, msgA, cbA)` then immediately `handler.HandleLegacyUserMessage(ctx, msgB, cbB)` (or run concurrently via goroutines with a `sync.WaitGroup`) — assert only one entry with key `"dup-id"` exists in `handler.savedCallbacks` after both calls (proving overwrite).
3. Construct a node response message with `MessageId = "dup-id"`, signed by a node in `donConfig.Members`, with a payload uniquely identifiable as "response-for-A" (or "for-B"). Call `handler.HandleNodeMessage(ctx, resp, nodeAddr)` once.
4. Assert that `cbA.Wait(ctx)` and `cbB.Wait(ctx)` — exactly one of them receives the node response (whichever's callback survived the overwrite), and assert that the surviving callback is not deterministically guaranteed to be the one whose payload matches its own request, i.e., demonstrate that `cbB` (Sender=key2, "victim") can receive a response intended to correlate with `msgA`'s request when B's call executes second and overwrites A's entry — proving isolation is violated. The other callback (`cbA`) should time out / never receive a response, demonstrating the orphaned-request denial effect.

// ValidatedResponseFromMessage converts a legacy Gateway Message to a JSON-RPC response
func ValidatedResponseFromMessage(msg *api.Message) (*jsonrpc.Response[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	res, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawResult := json.RawMessage(res)
	resp := &jsonrpc.Response[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Result:  &rawResult,
		Method:  msg.Body.Method,
	}
	return resp, nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {

	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.

	return nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageId] = &savedCallback{msg.Body.MessageId, callback}
	don := d.don
	d.mu.Unlock()
	params, err := json.Marshal(msg)
	if err != nil {
		return err
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}

func (d *dummyHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return err
	}
	msg.Body.MessageId = resp.ID
	err = msg.Validate()
	if err != nil {
		return err
	}
	if nodeAddr != msg.Body.Sender {
		return fmt.Errorf("node address %s does not match message sender %s", nodeAddr, msg.Body.Sender)
	}
	d.mu.Lock()
	savedCb, found := d.savedCallbacks[msg.Body.MessageId]
	delete(d.savedCallbacks, msg.Body.MessageId)
	d.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(&msg), ErrorCode: api.NoError})
	}
	return nil
}
