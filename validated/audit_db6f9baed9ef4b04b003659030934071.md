Based on my investigation, I found a genuine analog of the reported bug class (using two supply-like values that are computed at different points/consistency levels and then combined arithmetically) in the `getSupply` JSON-RPC handler.

### Title
Non-atomic combination of capitalization and non-circulating-supply scan in `getSupply` can return a wrapped/incorrect circulating supply - (File: `rpc/src/rpc.rs`)

### Summary
`get_supply` computes `non_circulating_supply` from a slow account scan first, then reads `bank.capitalization()` afterward, then subtracts the two without any bounds check. Because the two values are not sourced from the same instant (the bank can still be advancing between the scan and the capitalization read), and the subtraction is unchecked, an inconsistency between the two values can produce an incorrect (wrapped) `circulating` field returned to any unprivileged RPC caller.

### Finding Description
In `JsonRpcRequestProcessor::get_supply`, the handler first performs an expensive scan over all stake-program accounts via `calculate_non_circulating_supply`, which snapshots non-circulating lamports at whatever point-in-time the scan happens to observe account balances, and only afterward reads `bank.capitalization()`: [1](#0-0) 

The `calculate_non_circulating_supply` function itself walks stake accounts (potentially via `get_filtered_indexed_accounts` or `get_program_accounts`) and sums balances with `bank.get_balance(pubkey)`, all read independently of the later `bank.capitalization()` load: [2](#0-1) 

This exactly mirrors the reported bug class: two values that are supposed to represent consistent state of the same underlying pool/ledger (`supply` vs `totalSupply` in the report; here, the sum of non-circulating account balances vs. the bank's global `capitalization` atomic) are read via separate mechanisms at separate times and then combined as if they were synchronized:
```
circulating: total_supply - non_circulating_supply.lamports,
```
This subtraction is a plain unchecked `u64` subtraction. The workspace does not set `overflow-checks = true` for `[profile.release]`: [3](#0-2) 
so in a standard release-built validator this subtraction will silently wrap on underflow rather than panic, producing a bogus near-`u64::MAX` circulating supply value instead of crashing.

The `bank` used here is selected via `self.bank(config.commitment)`, which for `processed`/`confirmed` commitment can be a bank that is still actively being mutated by concurrent transaction processing while the RPC scan is running in a separate `spawn_blocking` task, meaning the values are not guaranteed to reflect the same underlying state.

### Impact Explanation
This is reachable by any unprivileged client via a single call to the public `getSupply` JSON-RPC method (`rpc/src/rpc.rs`'s `rpc_accounts_scan::AccountsScan::get_supply`), which is a standard, commonly-used endpoint. A wrong `circulating`/`total` supply figure returned by a validator's RPC endpoint is "wrong data returned to a query" — misleading downstream consumers (explorers, exchanges, wallets) that rely on `getSupply` for economic calculations, without requiring any validator/operator-role access.

### Likelihood Explanation
The scan performed by `calculate_non_circulating_supply` iterates the entire stake-program account set and is comparatively slow, widening the window during which the bank being queried can continue processing transactions before `bank.capitalization()` is finally read. Triggering an underflow deterministically requires a specific sequence of state changes to non-circulating accounts and capitalization within that window, so likelihood of hitting the exact underflow condition is not guaranteed on every call, but the structural flaw (unsynchronized reads combined via unchecked subtraction) is present on every invocation of `getSupply` and is exacerbated on busy clusters with large stake-account sets and high transaction throughput.

### Recommendation
Ensure `total_supply` and `non_circulating_supply` are captured from the same, consistent point of bank state before performing the scan (e.g., capture `total_supply = bank.capitalization()` prior to the scan, or, better, capture both under a scan that guarantees a consistent snapshot), and replace the raw subtraction with `total_supply.saturating_sub(non_circulating_supply.lamports)` to prevent any wraparound in case the two figures are still found to be inconsistent.

### Proof of Concept
Not independently reproducible as a guaranteed deterministic PoC without live-cluster timing control; the root-cause code path is directly shown above (`rpc/src/rpc.rs:1121-1153` and `runtime/src/non_circulating_supply.rs:19-79`) and the absence of `overflow-checks` in the release profile (`Cargo.toml:606-608`) is confirmed via repository configuration, which together establish that (a) the two quantities are read non-atomically and (b) their unchecked subtraction can silently wrap instead of panicking in production release builds.

    async fn get_supply(
        &self,
        config: Option<RpcSupplyConfig>,
    ) -> RpcCustomResult<RpcResponse<RpcSupply>> {
        let config = config.unwrap_or_default();
        let bank = self.bank(config.commitment);
        let non_circulating_supply =
            self.calculate_non_circulating_supply(&bank)
                .await
                .map_err(|e| RpcCustomError::ScanError {
                    message: e.to_string(),
                })?;
        let total_supply = bank.capitalization();
        let non_circulating_accounts = if config.exclude_non_circulating_accounts_list {
            vec![]
        } else {
            non_circulating_supply
                .accounts
                .iter()
                .map(|pubkey| pubkey.to_string())
                .collect()
        };

        Ok(new_response(
            &bank,
            RpcSupply {
                total: total_supply,
                circulating: total_supply - non_circulating_supply.lamports,
                non_circulating: non_circulating_supply.lamports,
                non_circulating_accounts,
            },
        ))
    }

pub fn calculate_non_circulating_supply(bank: &Bank) -> ScanResult<NonCirculatingSupply> {
    debug!("Updating Bank supply, epoch: {}", bank.epoch());
    let mut non_circulating_accounts_set: HashSet<Pubkey> = HashSet::new();

    for key in non_circulating_accounts() {
        non_circulating_accounts_set.insert(key);
    }
    let withdraw_authority_list = withdraw_authority();

    let clock = bank.clock();
    let stake_accounts = if bank
        .rc
        .accounts
        .accounts_db
        .account_indexes
        .contains(&AccountIndex::ProgramId)
    {
        bank.get_filtered_indexed_accounts(
            &IndexKey::ProgramId(stake::program::id()),
            // The program-id account index checks for Account owner on inclusion. However, due to
            // the current AccountsDb implementation, an account may remain in storage as a
            // zero-lamport Account::Default() after being wiped and reinitialized in later
            // updates. We include the redundant filter here to avoid returning these accounts.
            |account| account.owner() == &stake::program::id(),
            None,
        )?
    } else {
        bank.get_program_accounts(&stake::program::id())?
    };

    for (pubkey, account) in stake_accounts.iter() {
        let stake_account = account
            .deserialize_data::<StakeStateV2>()
            .unwrap_or_default();
        match stake_account {
            StakeStateV2::Initialized(meta)
                if (meta.lockup.is_in_force(&clock, None)
                    || withdraw_authority_list.contains(&meta.authorized.withdrawer)) =>
            {
                non_circulating_accounts_set.insert(*pubkey);
            }
            StakeStateV2::Stake(meta, _stake, _stake_flags)
                if (meta.lockup.is_in_force(&clock, None)
                    || withdraw_authority_list.contains(&meta.authorized.withdrawer)) =>
            {
                non_circulating_accounts_set.insert(*pubkey);
            }
            _ => {}
        }
    }

    let lamports = non_circulating_accounts_set
        .iter()
        .map(|pubkey| bank.get_balance(pubkey))
        .sum();

    Ok(NonCirculatingSupply {
        lamports,
        accounts: non_circulating_accounts_set.into_iter().collect(),
    })
}
