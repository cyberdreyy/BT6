### Title
Missing allowlist/authorization check in `HandleLegacyUserMessage` allows any signed sender to trigger workflow fan-out to entire DON - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` validates message structure (payload decode, non-zero timestamp, staleness, method name) and cryptographic well-formedness via `common.ValidatedRequestFromMessage`, but explicitly skips authorization: the code comment `// TODO: apply allowlist and rate-limiting here` sits directly before the method check and there is no check of `msg.Body.Sender` against any per-workflow `allowedSenders` list. Any request bearing a valid `MethodWebAPITrigger` message for a known `DonId` is forwarded via `don.SendToNode` to every member of that DON.

### Finding Description
The request path is `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) → for legacy requests it calls `msg.Validate()` (structural/signature-format validation only) then dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . Inside `HandleLegacyUserMessage`, the checks performed are: JSON payload decodes into `webapicap.TriggerRequestPayload`, `Timestamp != 0`, and message not stale [2](#0-1) . Immediately after these checks, the comment `// TODO: apply allowlist and rate-limiting here` appears, followed only by a method-name check (`msg.Body.Method != MethodWebAPITrigger`) and conversion via `common.ValidatedRequestFromMessage` [3](#0-2) . No code anywhere in this function inspects `msg.Body.Sender` against a workflow's `allowedSenders`, nor does it consult any DON-side or workflow-registry-based authorization component (unlike, e.g., the vault handler's `requestProcessor.ProcessRequest` / `AllowListBasedAuth.AuthorizeRequest`, which explicitly enforces an allowlist before proceeding [4](#0-3) [5](#0-4) ). Instead, the message is unconditionally sent to every DON member: `for _, member := range h.donConfig.Members { err = errors.Join(err, don.SendToNode(ctx, member.Address, req)) }` [6](#0-5) . `ValidatedRequestFromMessage` only performs structural marshalling/field-presence checks (message ID, method non-empty) — it does not verify a signature belongs to an authorized/allowlisted sender [7](#0-6) . Thus any attacker who can construct/sign a well-formed `api.Message{Method: MethodWebAPITrigger, DonId: <known>, Payload:{timestamp: now}}` and POST it through `gateway.ProcessRequest` will have it forwarded to all DON members, without any check that the sender belongs to a registered workflow's `allowedSenders`.

### Impact Explanation
This matches the "DoS/spam on DON member set, unauthorized triggering of workflow capability messages" impact class described in the question. An attacker with no prior registration can cause every node in a targeted DON to receive and process a trigger message purporting to originate from an arbitrary sender, consuming node/gateway resources and potentially invoking workflow trigger-handling logic on the DON side for workflows the attacker does not own or is not permitted to trigger. It is not full RCE or fund theft, but it is a legitimate authorization-bypass/DoS vector reachable by an unauthenticated (or minimally-authenticated, throwaway-key) external caller.

### Likelihood Explanation
Feasibility is high: the only precondition is knowledge of a valid `don_id`, which the question notes is often discoverable/public, and the ability to sign a message with any key (no registration or allowlisting required). The request is a single `gateway.ProcessRequest` call with a `MethodWebAPITrigger` message; the code path shows no rate limiting or sender authorization gate at this layer (the `nodeRateLimiter` in this file is applied only to `handleWebAPIOutgoingMessage`, i.e., DON→gateway responses, not to incoming user messages in `HandleLegacyUserMessage`) [8](#0-7) . This is repeatable indefinitely.

### Recommendation
Implement the allowlist check called out in the TODO before forwarding to DON members: validate `msg.Body.Sender` (derived from the message signature) against the workflow's/DON's registered `allowedSenders` (e.g., via a workflow-registry-backed authorizer analogous to `allow_list_based_auth.go` used in the vault handler), and add per-sender rate limiting analogous to `nodeRateLimiter` before calling `don.SendToNode` in the loop over `h.donConfig.Members`.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go` (or new test file):
1. Construct a `handler` via `NewHandler` with a `donConfig` containing several `Members`, backed by a mock `handlers.DON` (`don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)`).
2. Sign an `api.Message{Body: {Method: MethodWebAPITrigger, DonId: <don.DonId>, Payload: {"timestamp": <now>}}}` with a throwaway/unregistered private key (not present in any workflow's `allowedSenders`).
3. Call `handler.HandleLegacyUserMessage(ctx, msg, callback)`.
4. Assert: with current code, `don.SendToNode` is called once per DON member (`len(h.donConfig.Members)` times) and `err` is `nil` — demonstrating the message is forwarded despite the sender not belonging to any allowlist.
5. Expected/fixed behavior assertion (to show the TODO must be addressed): after adding allowlist enforcement, the same test should assert `don.SendToNode` is *never* called and `callback.SendResponse` returns an authorization-error response instead.

	var payload webapicap.TriggerRequestPayload

	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{

				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),

		})

// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}
