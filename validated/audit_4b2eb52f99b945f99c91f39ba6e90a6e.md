### Title
Cross-Source-Chain Nonce Collision in `isTransferProcessed` Allows Permanent Fund Lock - (File: bridge/evm/contracts/SuiBridge.sol)

### Summary

`SuiBridge.sol` and `SuiBridgeV2.sol` track processed token-transfer messages with `mapping(uint64 nonce => bool isProcessed) public isTransferProcessed`, keyed only by the message nonce. When the bridge is configured to accept transfers from more than one source chain (e.g., both `SUI_TESTNET` and `SUI_CUSTOM` routing to `ETH_SEPOLIA`), two distinct transfers that carry the same nonce value but originate from different source chains share the same storage slot. Processing the first transfer permanently marks the slot `true`, making the second transfer irreversibly unclaimable and locking the bridged funds.

### Finding Description

`BridgeConfig` accepts an array of supported source chains at initialization:

```solidity
for (uint8 i; i < _supportedChains.length; i++) {
    require(_supportedChains[i] != _chainID, "BridgeConfig: Cannot support self");
    supportedChains[_supportedChains[i]] = true;
}
```

The valid-routes table in `chain_ids.move` explicitly defines multi-source configurations such as `SUI_TESTNET → ETH_SEPOLIA` and `SUI_CUSTOM → ETH_SEPOLIA`, so a single ETH Sepolia bridge deployment is expected to accept transfers from both `SUI_TESTNET` (chain_id = 2) and `SUI_CUSTOM` (chain_id = 3).

The replay-protection check in `transferBridgedTokensWithSignatures` (and its V2 counterpart) is:

```solidity
require(!isTransferProcessed[message.nonce], "SuiBridge: Message already processed");
...
isTransferProcessed[message.nonce] = true;
```

The key is `message.nonce` alone — a bare `uint64` — not `(message.chainID, message.nonce)`. Each source chain maintains its own independent sequence counter starting at 0. When `SUI_TESTNET` emits transfer nonce=N and `SUI_CUSTOM` independently emits transfer nonce=N, both map to `isTransferProcessed[N]`. Whichever is processed first sets the slot to `true`; the second is permanently rejected with "SuiBridge: Message already processed".

The `onlySupportedChain(message.chainID)` modifier confirms the source chain is valid but does not prevent the collision — it only gates which chains may submit, not how their nonces are namespaced.

The same flaw is present in `SuiBridgeV2.transferBridgedTokensWithSignaturesV2`, which inherits the same `isTransferProcessed` storage variable and applies the identical check.

### Impact Explanation

When two supported source chains reach the same nonce value (which happens naturally as both start at 0 and increment monotonically), the second transfer's funds are permanently locked:

- On the Sui side the tokens were already burned or escrowed when the user called `send_token`.
- On the EVM side the nonce slot is already consumed, so `transferBridgedTokensWithSignatures` will always revert for that message.
- There is no recovery path: the nonce cannot be reused, and the bridge has no refund mechanism.

This constitutes a **permanent fund lock** reachable from public input (any ordinary user initiating a bridge transfer).

### Likelihood Explanation

Any deployment of the EVM bridge that lists two or more Sui-side chains in `supportedChains` is immediately vulnerable. The valid-routes table in the Move package explicitly anticipates such configurations (e.g., `SUI_TESTNET` and `SUI_CUSTOM` both routing to `ETH_SEPOLIA` or `ETH_CUSTOM`). Nonce collision is not a low-probability event; it is guaranteed to occur at nonce 0 the moment both chains have processed at least one transfer each.

### Recommendation

Key the processed-transfer mapping by both source chain ID and nonce:

```solidity
// Before
mapping(uint64 nonce => bool isProcessed) public isTransferProcessed;

// After
mapping(uint8 chainID => mapping(uint64 nonce => bool isProcessed)) public isTransferProcessed;
```

Update all reads and writes accordingly:

```solidity
require(!isTransferProcessed[message.chainID][message.nonce], "SuiBridge: Message already processed");
...
isTransferProcessed[message.chainID][message.nonce] = true;
```

Apply the same fix to `SuiBridgeV2`.

### Proof of Concept

Precondition: the ETH Sepolia bridge is initialized with `supportedChains = [SUI_TESTNET, SUI_CUSTOM]`.

1. Alice bridges tokens from `SUI_TESTNET` → `ETH_SEPOLIA`. The Sui bridge emits nonce = 0. The bridge node collects committee signatures and calls `transferBridgedTokensWithSignatures`. `isTransferProcessed[0]` is set to `true`. Alice receives her tokens on Ethereum.

2. Bob independently bridges tokens from `SUI_CUSTOM` → `ETH_SEPOLIA`. The Sui bridge also emits nonce = 0 (independent counter). The bridge node collects committee signatures and calls `transferBridgedTokensWithSignatures` with `message.chainID = SUI_CUSTOM, message.nonce = 0`.

3. The check `require(!isTransferProcessed[0], ...)` fails because slot 0 was already consumed by Alice's transfer. Bob's transaction reverts with "SuiBridge: Message already processed".     function transferBridgedTokensWithSignatures(
```text
        bytes[] memory signatures,
        BridgeUtils.Message memory message
    )
        external
        nonReentrant
        verifyMessageAndSignatures(message, signatures, BridgeUtils.TOKEN_TRANSFER)
        onlySupportedChain(message.chainID)
    {
        // verify that message has not been processed
        require(!isTransferProcessed[message.nonce], "SuiBridge: Message already processed");

        IBridgeConfig config = committee.config();

        BridgeUtils.TokenTransferPayload memory tokenTransferPayload =
            BridgeUtils.decodeTokenTransferPayload(message.payload);

        // verify target chain ID is this chain ID
        require(
            tokenTransferPayload.targetChain == config.chainID(), "SuiBridge: Invalid target chain"
        );

        // convert amount to ERC20 token decimals
        uint256 erc20AdjustedAmount = BridgeUtils.convertSuiToERC20Decimal(
            IERC20Metadata(config.tokenAddressOf(tokenTransferPayload.tokenID)).decimals(),
            config.tokenSuiDecimalOf(tokenTransferPayload.tokenID),
            tokenTransferPayload.amount
        );

        _transferTokensFromVault(
            message.chainID,
            tokenTransferPayload.tokenID,
            tokenTransferPayload.recipientAddress,
            erc20AdjustedAmount
        );

        // mark message as processed
        isTransferProcessed[message.nonce] = true;
```
