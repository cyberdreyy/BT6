### Title
Global contract owner can mutate AccountId-mode code trusted by deterministic accounts - documented design behavior, not a vulnerability ([File: docs/RuntimeSpec/Actions.md])

### Summary
The `GlobalContractDeployMode::AccountId` mode is explicitly documented to let the owner "update the contract for all its users," and `derive_near_deterministic_account_id` (via `DeterministicAccountStateInit`) only hashes the `GlobalContractIdentifier` reference (e.g., `AccountId(attacker)`), not the underlying code bytes, so any depositor referencing an `AccountId`-mode global contract inherently accepts the owner's ability to change the code post-hoc.

### Finding Description
`use_global_contract` in [1](#0-0)  sets `AccountContract::GlobalByAccount(id)` for accounts referencing an `AccountId`-mode contract, meaning execution always dereferences to whatever code is currently stored under that account id key, not a snapshot. `action_deploy_global_contract` and `initiate_distribution` in [2](#0-1)  and [3](#0-2)  allow the owning account to redeploy new code under the same `GlobalContractIdentifier::AccountId` at any time, with `apply_distribution_current_shard` in [4](#0-3)  simply overwriting the `TrieKey::GlobalContractCode` entry keyed by account id. `derive_near_deterministic_account_id` in [5](#0-4)  hashes the borsh-encoded `DeterministicAccountStateInit`, whose `code` field is only a `GlobalContractIdentifier` reference (`CodeHash` or `AccountId`), as shown in [6](#0-5) , not the actual code bytes. This is precisely the documented tradeoff at [7](#0-6) : `CodeHash` mode is immutable, while `AccountId` mode explicitly "allows the owner to update the contract for all its users."

### Impact Explanation
No violation of an undisclosed authorization boundary occurs. A depositor who chooses to reference a `GlobalContractIdentifier::AccountId`-mode contract (rather than `CodeHash`) is, by design, opting into trusting that account owner's ability to mutate the code indefinitely — this is the explicit, documented distinction between the two deploy modes. There is no code path where the runtime silently substitutes code without the depositor's own choice of identifier reference; the depositor's `DeterministicStateInitAction` explicitly names `AccountId(attacker)` as the trust anchor. This is Informative/out-of-scope: an inherent, disclosed design tradeoff, not an authorization-exactness bug.

### Likelihood Explanation
N/A — not a vulnerability. Any user can trivially avoid this risk by referencing a `CodeHash`-mode global contract instead, which is immutable by construction per [8](#0-7) .

### Recommendation
No code fix required. Optionally improve wallet/RPC-level UX warnings when constructing a `DeterministicStateInitAction` against an `AccountId`-mode identifier, clarifying that the code owner retains unilateral rights to change contract logic post-deployment.

### Proof of Concept
Not applicable — behavior matches documented specification; no test is needed to prove a vulnerability that does not exist.

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)
}

pub fn derive_near_deterministic_account_id(
    state_init: &DeterministicAccountStateInit,
) -> AccountId {
    use sha3::Digest;
    let mut hasher = sha3::Keccak256::new();
    borsh::to_writer(&mut hasher, state_init).expect("borsh must not fail");
    let hash: [u8; 32] = hasher.finalize().into();
    format!("0s{}", hex::encode(&hash[12..32])).parse().unwrap()
}
