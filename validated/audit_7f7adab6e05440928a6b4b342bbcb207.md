Based on the code reviewed, `helpers/archives/zip_extract.go` (the legacy zip extractor used via `commands/helpers/archive/ziplegacy`) writes files/directories/symlinks directly at `file.Name` from the zip header with no path containment check, whereas the sibling `tarzstd_extractor.go` explicitly resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects paths outside `e.dir`. This is a real, concretely reachable difference in the same codebase, satisfying the "exact reachable Go path" and "root cause is a real missing check" requirements.

### Title
Legacy zip extractor lacks path-containment checks, allowing artifact/cache archive entries to write outside the job's working directory - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile`/`extractZipDirectoryEntry`/`extractZipFileEntry`/`extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` use `file.Name` from the zip header verbatim for `os.Mkdir`, `os.MkdirAll`, `os.OpenFile`, and `os.Symlink`, with no validation that the resulting path stays within the intended extraction root. This extractor is the default for the `zip` and `zipzstd` formats (`commands/helpers/archive/ziplegacy`, registered in `commands/helpers/archiver.go`) unless `FF_USE_FASTZIP` is enabled, and it backs both `ArtifactsDownloaderCommand` (`commands/helpers/artifacts_downloader.go`) and `CacheExtractorCommand` (`commands/helpers/cache_extractor.go`), both attacker-influenced via job/pipeline-produced artifact/cache archives.

### Finding Description
`ExtractZipFile`/`ExtractZipArchive` (helpers/archives/zip_extract.go:85-120) iterate `archive.File` entries and call `extractZipFile(file)` per entry. [1](#0-0) 
Each of the leaf handlers operates directly on `file.Name`: [2](#0-1) [3](#0-2) 
No call resolves `filepath.Abs`/`filepath.Clean` against a base directory nor checks `strings.HasPrefix` against the root, unlike the parallel implementation for tar/zstd archives which explicitly enforces: [4](#0-3) 
The only guard present in the zip path is `errorIfGitDirectory`, which only warns about `.git` directory entries — it is not a path-containment or traversal check. [5](#0-4) 

This legacy zip code is wired up as the default extractor for `archive.Zip` and `archive.ZipZstd` formats: [6](#0-5) [7](#0-6) 
and both artifact download and cache download/extraction flows call `archive.NewExtractor(format, f, size, wd)` then `.Extract(...)`, with `wd` being the job's current working directory: [8](#0-7) [9](#0-8) 

An attacker-controlled zip archive (e.g., produced by the job itself as an artifact/cache, or a maliciously crafted upload if artifact/cache integrity isn't otherwise enforced) with an entry name containing `../` segments or an absolute path can cause `extractZipFile` to `MkdirAll`/write outside `wd`. `extractZipSymlinkEntry` similarly creates arbitrary symlinks at attacker-chosen relative/absolute paths with attacker-chosen link targets, without validating either endpoint. Because this all happens inside the `gitlab-runner artifacts-downloader`/`cache-extractor` helper process (not inside the containerized job), on shell/docker executors that share a filesystem between the helper and later job stages/temp/env files, this could let one job's archive content land on a path later consumed as trusted (helper config, temp scripts, env files) if names collide.

### Impact Explanation
If exploitable, impact is file overwrite/planting outside the intended cache/artifact extraction root from within the same job, potentially affecting files the runner helper or subsequent shell stages treat as trusted (e.g., environment/script files it later sources), leading to secret exposure or execution in a stronger context than the job normally has, matching the "Expected Immunefi impact" of the question.

### Likelihood Explanation
Preconditions: the job must control archive content used as an artifact or cache (fully within a normal unprivileged pipeline author's control — `artifacts:paths`/`cache:paths` content is user-defined), and `FF_USE_FASTZIP` must be off (this is the historical/legacy default). The extraction is deterministic and repeatable per-job; no admin/privileged actor needed. I could not fully verify from the available index whether `fastzip.NewExtractor` (`commands/helpers/archive/fastzip/zip_fastzip_extractor.go`) independently performs the same containment check as `tarzstd_extractor.go` — the grep found matches for `HasPrefix`/`..` patterns in that file, suggesting some check exists there, but I was unable to read its full contents before running out of iterations, so I cannot state definitively whether fastzip is also affected or is safe.

### Recommendation
In `helpers/archives/zip_extract.go`, before performing any filesystem operation for a given `file.Name`, resolve the destination against the extraction root (analogous to `tarzstd_extractor.go`'s `filepath.Abs(filepath.Join(e.dir, hdr.Name))` + prefix check) and reject entries whose resolved path escapes the root or that specify absolute paths. Apply the same containment check to symlink targets (`extractZipSymlinkEntry`) so a symlink cannot be created that points outside the extraction root, or reject symlink entries with absolute/`..`-containing targets. Since `extractZipFile`/`ExtractZipArchive` currently take no root directory parameter at all, plumb the extraction root down into `ExtractZipArchive`/`ExtractZipFile`/`extractZipFile` so the check has a boundary to validate against.

### Proof of Concept
Go unit test to add to `helpers/archives/zip_extract_test.go`:
1. Create a temp directory `root` and `chdir` into it (mirroring existing `testInWorkDir` helper).
2. Build an in-memory zip archive with an entry named `../evil.txt` (and/or `/tmp/evil.txt`) containing marker bytes, using `archive/zip` directly (bypassing `createZipEntry` which presumably wouldn't allow such names on create, since the goal is to simulate an attacker-crafted archive received over the network, not one created by this runner).
3. Call `archives.ExtractZipFile(archivePath)`.
4. Assert that `../evil.txt` (relative to `root`, i.e., one directory above `root`) does NOT exist, and that no file was written outside `root`. Currently, without a fix, this assertion would fail — `os.Mkdir`/`os.OpenFile` will honor the `../` path and write the file outside `root`, proving the missing containment check.
5. A second test case with a symlink entry whose link target is an absolute path (e.g., `/etc/passwd`) or a `../`-escaping relative path should assert that `os.Symlink` is rejected or that the resulting symlink does not resolve outside `root`.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func init() {
	// enable fastzip archiver/extractor
	logger := logrus.WithField("name", featureflags.UseFastzip)
	if on := featureflags.IsOn(logger, os.Getenv(featureflags.UseFastzip)); on {
		archive.Register(archive.Zip, fastzip.NewArchiver, fastzip.NewExtractor)

		// The default zstd compressor is fastzip, this is registered via the
		// fastzip implementation (helpers/archive/fastzip).
		//
		// The default zstd decompressor is the legacy zip implementation (helpers/archive/ziplegacy).
		// This intended to allow the default zip implementation to still be able to decompress zstd,
		// even if it is unable to compress it (only fastzip can compress). This also allows the older
		// extraction behaviour to be enabled.
		//
		// Here we're registering the decompress only if FF_USE_FASTZIP is enabled. This overrides
		// the ziplegacy zstd support.
		archive.Register(archive.ZipZstd, nil, fastzip.NewExtractor)
	}
}
