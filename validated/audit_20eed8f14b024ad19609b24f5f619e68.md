### Title
Legacy web API trigger requests are dispatched to every DON member with no allowlist or subscription enforcement - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` validates message structure/signature format and staleness, but performs no allowlist, subscription, or quota check on the sender before fan-out to `h.don.SendToNode` for every `donConfig.Members` entry, as explicitly flagged by the `// TODO: apply allowlist and rate-limiting here` comment. Any holder of a valid ECDSA keypair who can produce a correctly-signed, non-stale `web_api_trigger` message can trigger full DON execution.

### Finding Description
The request path is: gateway HTTP endpoint → `gateway.ProcessRequest` (`core/services/gateway/gateway.go` lines 218-292) → for legacy requests, `msg.Validate()` is called (structural/signature-format validation only) → `h.HandleLegacyUserMessage(ctx, msg, callback)`. [1](#0-0) 

Inside `HandleLegacyUserMessage`, the checks performed are: JSON payload decode, `Timestamp != 0`, and message staleness against `MaxAllowedMessageAgeSec`. [2](#0-1) 

Immediately after those checks and right before dispatch, the code contains the comment `// TODO: apply allowlist and rate-limiting here`, followed only by a method-name check (`MethodWebAPITrigger`), then `common.ValidatedRequestFromMessage(msg)` (which verifies message structure/signature validity, not sender authorization), and finally a loop that calls `don.SendToNode` for **every** member in `h.donConfig.Members`. [3](#0-2) 

Unlike the vault handler package, which implements an explicit `allow_list_based_auth.go` / `authorizer.go` mechanism, this capabilities handler has no equivalent allowlist check wired in before dispatch. `nodeRateLimiter` in this handler is only applied in `handleWebAPIOutgoingMessage`, which processes *node*-originated messages (`HandleNodeMessage`), not the legacy user-originated path (`HandleLegacyUserMessage`). [4](#0-3) [5](#0-4) 

Because signature validation only proves the message is self-consistent (signed by *some* keypair) and does not check membership in any subscriber/allowlist registry, any attacker who generates a fresh ECDSA keypair, signs a well-formed `web_api_trigger` payload with a valid timestamp, and sends it to the gateway will have their request relayed to every node in the target DON's `donConfig.Members`, consuming DON execution capacity that should be reserved for authorized/paying subscribers.

### Impact Explanation
This maps to unauthorized consumption of DON compute/execution resources ("unauthorized job run" / quota-bypass class): an attacker with zero on-chain registration or subscription can force every member node of a DON shard to execute a workflow trigger request, degrading service for legitimate subscribers and potentially incurring real infrastructure/compute cost on every DON node for free. It does not directly disclose secrets or move funds, but it is a concrete authorization-exactness violation at the request-admission layer of the gateway.

### Likelihood Explanation
Precondition is trivial: possession of any ECDSA keypair (freely generated, not required to be registered anywhere) and knowledge of the gateway's public HTTP/JSON-RPC endpoint and the target `donId`/`DonName`. No credentials, roles, or prior interaction with the DON are needed. The bug is explicitly acknowledged in-code via the TODO comment, indicating the allowlist/rate-limit enforcement was never implemented for this path, making the issue fully reproducible and repeatable (each malicious request results in fan-out to all `donConfig.Members`).

### Recommendation
Implement sender allowlist verification (analogous to `core/capabilities/vault/allow_list_based_auth.go` / `authorizer.go`) inside `HandleLegacyUserMessage` before the `don.SendToNode` fan-out loop, rejecting any message whose signer address is not present in the DON's/service's configured allowlist or active subscription registry. Additionally apply per-sender rate-limiting (reusing or extending `nodeRateLimiter`, or a dedicated user-rate-limiter) to this method, matching the pattern already used for node-originated messages in `handleWebAPIOutgoingMessage`.

### Proof of Concept
Go handler-level integration test plan (in `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Construct a `handler` via `NewHandler` with a `donConfig` containing N members and a mock `handlers.DON` (`don` mock) that records calls to `SendToNode`.
2. Generate a fresh ECDSA keypair with `crypto.GenerateKey()` that is never added to any config/allowlist structure in `donConfig` or elsewhere.
3. Build a `webapicap.TriggerRequestPayload` with `Timestamp: time.Now().Unix()`, marshal it into `api.MessageBody{Method: MethodWebAPITrigger, Payload: ...}`, sign the message body with the freshly generated key (mirroring how `handler_test.go` signs test messages), and produce an `api.Message`.
4. Call `h.HandleLegacyUserMessage(ctx, msg, callback)`.
5. Assert: `err == nil` (or no `UserMessageParseError`/`HandlerError` returned), and that the mock `don.SendToNode` was invoked exactly `len(donConfig.Members)` times — once per member address — despite the signer's address never appearing in any allowlist/subscriber structure, demonstrating unauthenticated/unauthorized full DON fan-out.

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
