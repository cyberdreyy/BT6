### Title
Unauthenticated External-Initiator auth path leaks internal DB error text via jsonAPIError - ([File: core/web/auth/auth.go])

### Summary
`AuthenticateExternalInitiator` only maps `sql.ErrNoRows` from `FindExternalInitiator` to the generic `auth.ErrorAuthFailed`; any other error (e.g., a transient/DB-layer error) is wrapped with `errors.Wrap(err, "finding external initiator")` and returned as-is. The `Authenticate` middleware loop then breaks on this non-`ErrorAuthFailed` error and passes it straight to `jsonAPIError`, which serializes `err.Error()` into the JSON body returned to the caller.

### Finding Description
`AuthenticateExternalInitiator` (core/web/auth/auth.go:119-151) calls `store.FindExternalInitiator(ctx, eia)` using attacker-supplied headers (`static.ExternalInitiatorAccessKeyHeader`, `static.ExternalInitiatorSecretHeader`). It only special-cases `sql.ErrNoRows`: [1](#0-0) 
Any other error type (e.g., a DB connectivity/timeout error, a malformed-query error, etc.) is wrapped with `errors.Wrap(err, "finding external initiator")` and returned unmodified to the `Authenticate` loop.

The `Authenticate` middleware loop (core/web/auth/auth.go:157-175) breaks out of the loop as soon as an error that is *not* `auth.ErrorAuthFailed` is returned by any `authMethod`: [2](#0-1) 
The resulting error is then passed to `jsonAPIError(c, http.StatusUnauthorized, err)`.

`jsonAPIError` (core/web/auth/helpers.go:15-23, duplicated in core/web/helpers.go:21-29) calls `err.Error()` directly into the response body when the error is not a `*models.JSONAPIErrors`: [3](#0-2) 

Because `errors.Wrap` preserves the original error's `Error()` text (prefixing it with "finding external initiator: "), any underlying error string returned by the ORM/DB driver (which can include SQL fragments, column/table names, connection info, etc. depending on the driver) is propagated verbatim into the HTTP response body sent to the caller. This response is reachable by a fully unauthenticated attacker: the External Initiator auth path is exercised on every unauthenticated request whenever `AuthenticateExternalInitiator` is included in the auth chain (per `core/web/router.go`), and requires only supplying the `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` (or similarly named) headers to route into `FindExternalInitiator`.

None of the existing checks (role wrapper, presenter redaction, signature verification) intercept this — the leak happens at the authentication-failure-handling layer itself, before any role/session is established.

### Impact Explanation
This is an information-disclosure issue: internal error strings (potentially including SQL query fragments, database driver messages, internal identifiers) can be returned to an unauthenticated caller. This falls under Chainlink's "information disclosure aiding further attacks" bounty class — it does not by itself grant privilege escalation or fund movement, but it can reveal internal implementation/schema details useful for follow-on attacks (e.g., crafting further requests, fingerprinting DB type/version, or timing-based reconnaissance). Impact is scoped and low-to-medium severity (no direct auth bypass, no key/secret exposure of legitimate credentials).

### Likelihood Explanation
Preconditions: none — the attacker needs no credentials, only network access to the node's HTTP API endpoint(s) that use this auth chain. Triggering a non-`ErrNoRows` DB error deterministically (e.g., forcing a connection drop, timeout, or query error) may be difficult in a hardened deployment but is a realistic scenario under DB connection pool exhaustion, network partition, or transient errors — conditions an attacker could potentially induce or wait for. The code path itself is deterministic and always leaks the error text whenever such a non-`ErrNoRows` error occurs, so likelihood depends primarily on the attacker's ability to trigger the specific underlying DB error, which is plausible but not trivially attacker-controlled.

### Recommendation
In `AuthenticateExternalInitiator` (and generally in `Authenticate`'s error handling), do not propagate raw underlying errors to the client. Log the wrapped error server-side and return a generic error (e.g., `auth.ErrorAuthFailed` or a fixed internal-error message) to `jsonAPIError`, ensuring `err.Error()` never contains data derived from datastore-layer errors. Apply the same treatment consistently across all `authMethod` implementations so that only sanitized errors ever reach `jsonAPIError`.

### Proof of Concept
Go handler-level test plan:
1. Create a mock `Authenticator` (via `core/sessions/mocks` or a custom stub) whose `FindExternalInitiator` returns a non-`sql.ErrNoRows` error, e.g. `errors.New("pq: connection to server at \"10.0.0.5\" failed")`.
2. Build a `gin` test router wrapping a dummy handler with `auth.Authenticate(mockStore, auth.AuthenticateExternalInitiator)`.
3. Send an HTTP request with arbitrary `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers (no valid session).
4. Assert the response status is `401 Unauthorized`.
5. Assert the response body (`models.JSONAPIErrors`) contains the substring `"pq: connection to server"` (or the raw injected error text) — proving the internal DB error string leaked to an unauthenticated caller.
6. Compare against expected fix: after remediation, assert the response body only ever contains a generic message (e.g., `"authentication failed"`) regardless of the underlying error.

```go
func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}
```

```go
func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
```
