### Title
Bridge `OutgoingToken` secret unconditionally leaked to any role that can read bridge metadata (Index/Show/Update/Destroy) - ([File: core/web/presenters/bridges.go])

### Summary
`NewBridgeResource` copies `b.OutgoingToken` into `BridgeResource.OutgoingToken`, which is tagged `json:"outgoingToken"` with no `omitempty`/redaction, unlike `IncomingToken` which is deliberately left blank by the constructor and only populated by `BridgeTypesController.Create`. Every other controller method (`Index`, `Show`, `Update`, `Destroy`) calls `presenters.NewBridgeResource(bt)` directly on a `bridges.BridgeType` loaded from the ORM, so the plaintext `OutgoingToken` secret is returned in every response, not just at creation time.

### Finding Description
`bridges.NewBridgeType` generates `OutgoingToken` as a 24-byte secret (`utils.NewSecret(24)`) and stores it in plaintext on `BridgeType.OutgoingToken` [1](#0-0) . This token is the credential the node sends to the external adapter to authenticate itself, in contrast to `IncomingToken`, which the node hashes (`IncomingTokenHash`) and never persists in plaintext — only surfacing once at `Create` via `resource.IncomingToken = bta.IncomingToken` [2](#0-1) .

`NewBridgeResource` always assigns `OutgoingToken: b.OutgoingToken` and the JSON tag lacks `omitempty` [3](#0-2) . `Index`, `Show`, `Update`, and `Destroy` all fetch the persisted `BridgeType` from `BridgeORM().FindBridge`/`BridgeTypes` and pass it straight into `presenters.NewBridgeResource`, so the response body for a plain read (`GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName`) includes the same secret token an attacker would need to make authenticated requests to the external adapter (i.e., to impersonate the node to that adapter) [4](#0-3) [5](#0-4) .

Because the leak happens inside the shared presenter constructor rather than being gated by handler logic, any authenticated caller whose role is only sufficient for read access to bridge metadata (view-role API session or restricted API token) receives the same secret that only creation/administration should require.

### Impact Explanation
This is a credential/secret disclosure: a low-privileged, read-only bridge caller obtains the `OutgoingToken` used by the node to authenticate to the external adapter backing that bridge. With this token, the caller could potentially replay authenticated requests to the external adapter, impersonating the Chainlink node, or use knowledge of the token to bypass adapter-side allowlisting that trusts requests bearing this token. This matches Chainlink's "secret/key disclosure" and "request impersonation" bounty classes, though the blast radius is scoped to whatever the specific external adapter guards with that token (not on-chain key material).

### Likelihood Explanation
Low privilege required — any credential capable of hitting the bridge read routes (`Index`/`Show`) is sufficient; no elevated create/edit/admin role is needed. The behavior is deterministic and repeatable on every call once a bridge exists, requiring no race conditions or special timing.

### Recommendation
Redact `OutgoingToken` from `BridgeResource` for read/list/update/destroy paths the same way `IncomingToken` is handled: remove it from `NewBridgeResource` entirely (add `omitempty` at minimum, or better, never populate it from stored data) and instead surface `OutgoingToken` only at the moment of generation (`Create`), analogous to how `IncomingToken` is injected post hoc in `BridgeTypesController.Create`.

### Proof of Concept
1. Unit test in `core/web/presenters/bridges_test.go`: construct a `bridges.BridgeType{OutgoingToken: "super-secret-outgoing"}`, call `presenters.NewBridgeResource`, `json.Marshal` the result, and assert the serialized JSON contains `"outgoingToken":"super-secret-outgoing"`.
2. Handler-level integration test in `core/web/bridge_types_controller_test.go`: create a bridge as an admin/edit-role client, then issue `GET /v2/bridge_types/:BridgeName` (Show) and `GET /v2/bridge_types` (Index) using a client whose session/API token only has view-level bridge access; assert the JSON response body's `data.attributes.outgoingToken` matches the originally generated `OutgoingToken`, proving the secret is returned on a read-only call.

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

func (btc *BridgeTypesController) Update(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")
	btr := &bridges.BridgeTypeRequest{}

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := c.ShouldBindJSON(btr); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if err := ValidateBridgeType(btr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := orm.UpdateBridgeType(ctx, &bt, btr); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	btc.App.GetAuditLogger().Audit(audit.BridgeUpdated, map[string]any{
		"bridgeName":                   bt.Name,
		"bridgeConfirmations":          bt.Confirmations,
		"bridgeMinimumContractPayment": bt.MinimumContractPayment,
		"bridgeURL":                    bt.URL,
	})

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// Destroy removes a specific Bridge.
func (btc *BridgeTypesController) Destroy(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error searching for bridge: %w", err))
		return
	}
	jobsUsingBridge, err := btc.App.JobORM().FindJobIDsWithBridge(ctx, name)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error searching for associated v2 jobs: %w", err))
		return
	}
	if len(jobsUsingBridge) > 0 {
		jsonAPIError(c, http.StatusConflict, fmt.Errorf("can't remove the bridge because jobs %v are associated with it", jobsUsingBridge))
		return
	}
	if err = orm.DeleteBridgeType(ctx, &bt); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("failed to delete bridge: %w", err))
		return
	}

	btc.App.GetAuditLogger().Audit(audit.BridgeDeleted, map[string]any{"name": name})

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
