### Title
Raw archiver dereferences symlinks without path/type validation, allowing blocking on FIFOs or content leak from outside the workspace - ([File: commands/helpers/archive/raw/raw_archiver.go])

### Summary
`fileArchiver.add()` in `commands/helpers/file_archiver.go` uses `os.Lstat` and only validates that the *symlink's own path* is inside the working directory, never the resolved target. When the selected archive format is `raw` (`commands/helpers/archive/raw/raw_archiver.go`), the consumer calls `os.Open(pathname)` on the queued path without any check on file mode or on where the symlink resolves to, so a symlink queued from the workspace can cause the runner process to open and read an arbitrary target outside the job's chroot, including a FIFO (which blocks) or a regular file the job doesn't own (content leak into the artifact/cache stream).

### Finding Description
`fileArchiver.process()`/`add()` (`commands/helpers/file_archiver.go:65-138`) validate containment using `filepath.Rel(c.wd, absolute)` on the *symlink path itself*, and store `os.Lstat(path)` info in `c.files`. Because `Lstat` does not follow the link, this containment check never inspects where the symlink resolves to. A workspace symlink such as `workspace/f -> /tmp/x` (a FIFO) or `workspace/f -> /etc/shadow` passes this check and is added to `c.files` with `os.ModeSymlink` set on the stored `FileInfo`.

That map is passed to whichever `archive.Archiver` was selected. The `tarzstd` and `zip`/`ziplegacy` archivers correctly special-case symlinks: they call `os.Readlink` to capture the link target *string* and write a symlink tar/zip entry without opening/dereferencing the target (`commands/helpers/archive/tarzstd/tarzstd_archiver.go:85-108`, `helpers/archives/zip_create.go:17-30`), and they also explicitly skip FIFOs/sockets/devices detected on the symlink's own mode. The `gziplegacy` archiver rejects non-regular files outright (`helpers/archives/gzip_create.go:25-27`).

However, the `raw` archiver (`commands/helpers/archive/raw/raw_archiver.go:35-49`) performs no such checks:
```go
for pathname := range files {
    f, err := os.Open(pathname)
    ...
    io.Copy(a.w, f)
}
```
`os.Open` follows symlinks. If `pathname` is a symlink whose target is a FIFO, `os.Open` blocks the runner helper process until a writer connects to the FIFO (denial of service on the job). If the target is a readable regular file outside the workspace (owned by another job/tenant or the host), its content is copied verbatim into the artifact/cache stream sent to GitLab — a cross-tenant/host information leak. There is no mode check (`fi.Mode().IsRegular()`) and no re-validation that the *resolved* path stays under `a.dir`, unlike `tarzstd`'s explicit chroot check on `path` before use.

### Impact Explanation
Reachable impact is scoped to whichever caller uses the `raw` archive format with attacker-influenced paths from `fileArchiver`/similarly structured `c.files` maps. Concrete impacts: (1) DoS — runner helper process hangs indefinitely opening a FIFO; (2) information disclosure — arbitrary host-readable file content (outside the job's directory) gets copied into the resulting artifact/cache payload, which is then uploaded, potentially exposing unrelated project or host data.

### Likelihood Explanation
Preconditions require only unprivileged control over workspace contents (creating a symlink) and use of the `raw` archive format for that upload/cache path — the same precondition class the question specifies (`mkfifo /tmp/x; ln -s /tmp/x workspace/f`). The `raw` archiver's code path enforces exactly one file (`len(files) > 1` errors), which limits blast radius to single-file raw transfers, but does not eliminate the bug for that path. Whether `raw` format is reachable from `fileArchiver`-driven multi-path artifact/cache flows (as opposed to a single explicit-path raw cache entry) could not be fully confirmed from the index in the time available — the wiring between `commands/helpers/artifacts_uploader.go`/`cache_archiver.go` and format selection (`archive.Raw`) needs to be checked to determine exactly which CLI flags/commands select `raw` versus `zip`/`tarzstd`.

### Recommendation
In `commands/helpers/archive/raw/raw_archiver.go`, before `os.Open`, `Lstat` the path, reject/skip non-regular files (symlinks, FIFOs, sockets, devices) the same way `gziplegacy`/`tarzstd` do, and re-validate that the resolved (`filepath.EvalSymlinks`) path stays within `a.dir`. More generally, `fileArchiver.add()`/`process()` in `commands/helpers/file_archiver.go` should resolve symlink targets and confirm they too are within `c.wd`, or reject symlinks pointing outside the workspace, to close this gap for any future or existing archiver implementation that might dereference queued entries.

### Proof of Concept
Go test in `commands/helpers/archive/raw/raw_archiver_test.go`:
```go
func TestRawArchiver_RejectsSymlinkToFIFO(t *testing.T) {
    dir := t.TempDir()
    fifoPath := filepath.Join(dir, "fifo")
    require.NoError(t, syscall.Mkfifo(fifoPath, 0600))

    linkPath := filepath.Join(dir, "link")
    require.NoError(t, os.Symlink(fifoPath, linkPath))

    info, err := os.Lstat(linkPath)
    require.NoError(t, err)

    var buf bytes.Buffer
    a, _ := NewArchiver(&buf, dir, archive.DefaultCompression)

    done := make(chan error, 1)
    go func() { done <- a.Archive(context.Background(), map[string]os.FileInfo{linkPath: info}) }()

    select {
    case err := <-done:
        require.Error(t, err) // expected: archiver should reject non-regular/symlink, not hang
    case <-time.After(2 * time.Second):
        t.Fatal("Archive() blocked on FIFO dereferenced through symlink — DoS/leak risk")
    }
}
```
Expected current behavior (bug present): the goroutine blocks on `os.Open` past the timeout, or (with a symlink to a regular host file instead of a FIFO) the file's contents appear in `buf`, demonstrating the leak. Expected fixed behavior: `Archive` returns an error immediately without opening the target.
