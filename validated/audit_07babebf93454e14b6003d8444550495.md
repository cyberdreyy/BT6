### Title
Unskimmed donations are crystallized as tranche yield during deposits - (File: `contracts/IdleCDOCreditVault.sol`)

### Summary
`IdleCDOCreditVault._deposit` updates accounting before isolating raw underlying donations, and `getContractValue` includes the CDO’s complete token balance. An attacker holding tranche shares can therefore deposit after an unsolicited transfer and crystallize the donation into existing tranche NAV before `_skimDonatedAssets` can route it to `feeReceiver`. [1](#0-0) [2](#0-1) 

### Finding Description
During `depositAA` or `depositBB`, `_deposit` first calls `_updateAccounting` and only then measures the balance delta produced by the depositor’s transfer. [3](#0-2) 

`getContractValue` counts raw `token` held by the CDO together with strategy tokens, so a direct transfer made immediately before the deposit is treated as protocol gain. [4](#0-3) 

`_updateAccounting` distributes that apparent gain across the saved AA and BB NAVs and tranche prices. [5](#0-4) 

Although donations are skimmed in privileged paths such as `startEpoch`, no equivalent skim occurs before `_updateAccounting` inside the permissionless deposit path. [6](#0-5) 

### Impact Explanation
An attacker who already owns `f` percent of the affected tranche NAV captures approximately `f * donationAmount` when their deposit crystallizes a victim’s direct transfer. If the donation is subsequently skimmed after accounting, the NAV remains inflated without corresponding backing, producing insolvency up to the donated amount. If withdrawal funding consumes the raw balance before it is skimmed, the donation is directly redistributed to tranche holders instead of `feeReceiver`. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
The attack only requires an unprivileged tranche holder to observe or induce a direct underlying transfer and call `depositAA` while deposits are open. Deposits are public in the buffer phase, and neither KYC nor privileged action is needed to trigger `_deposit`. [9](#0-8) [1](#0-0) 

### Recommendation
Skim raw donated underlyings before every accounting update that can be triggered by users, especially at the start of `_deposit`. Alternatively, make `getContractValue` exclude unmanaged raw underlying consistently, and separately require that the deposit balance delta is fully accounted for before forwarding funds to the strategy. [10](#0-9) [11](#0-10) 

### Proof of Concept
```solidity
function test_DepositCrystallizesDonation() public {
    uint256 lpDeposit = 100_000e6;
    uint256 donation = 10_000e6;

    // Attacker already owns part of the live tranche NAV.
    underlying.approve(address(cdo), lpDeposit);
    cdo.depositAA(lpDeposit);

    uint256 navBefore = cdo.lastNAVAA() + cdo.lastNAVBB();

    // Victim sends underlying directly to the CDO during the deposit window.
    deal(address(underlying), victim, donation);
    vm.prank(victim);
    underlying.transfer(address(cdo), donation);

    // The attacker's tiny deposit runs accounting before any donation skim.
    deal(address(underlying), attacker, 1);
    vm.startPrank(attacker);
    underlying.approve(address(cdo), 1);
    cdo.depositAA(1);
    vm.stopPrank();

    // The raw donation was distributed into tranche NAV rather than isolated.
    assertEq(
        cdo.lastNAVAA() + cdo.lastNAVBB(),
        navBefore + donation + 1
    );
}
```

```text
  function _updateAccounting() internal virtual returns (bool shutdown) {
    _accrueManagementFee();
    uint256 _lastNAVAA = lastNAVAA;
    uint256 _lastNAVBB = lastNAVBB;
    uint256 _lastNAV = _lastNAVAA + _lastNAVBB;
    uint256 nav = getContractValue();
    uint256 _aprSplitRatio = trancheAPRSplitRatio;
    // If gain is > 0, then collect some fees in `unclaimedFees`
    if (nav > _lastNAV) {
      unclaimedFees += (nav - _lastNAV) * fee / FULL_ALLOC;
    }
    (uint256 _priceAA, int256 _totalAAGain) = _virtualPriceAux(AATranche, nav, _lastNAV, _lastNAVAA, _aprSplitRatio);
    (uint256 _priceBB, int256 _totalBBGain) = _virtualPriceAux(BBTranche, nav, _lastNAV, _lastNAVBB, _aprSplitRatio);
    lastNAVAA = uint256(int256(_lastNAVAA) + _totalAAGain);
    lastNAVBB = uint256(int256(_lastNAVBB) + _totalBBGain);
```
