### Title
Signer can be induced to equivocate across tenures once a locally-accepted block's signature goes stale, because `get_tenure_last_block_info` and the `get_signed_conflicts` backstop share the identical staleness clock - ([File: stacks-signer/src/chainstate/mod.rs, stacks-signer/src/v0/signer.rs])

### Summary
`check_tenure_change_confirms_parent` vetoes a competing tenure-change block only by consulting `get_tenure_last_block_info`, which forgets a `LocallyAccepted` block A once `tenure_last_block_proposal_timeout` has elapsed since it was signed. The cross-tenure backstop in `handle_block_pre_commit` (`get_signed_conflicts`) is supposed to catch what the single-tenure chainstate check misses, but it uses the exact same timeout and the same `signed_self`/`signed_group` timestamp, so it goes stale at the identical instant, letting the signer sign a second, conflicting block B' at A's height in a different tenure.

### Finding Description
The equality that must hold is: for a given height, this signer must never place its signature on more than one block. `check_latest_block_in_tenure` (called via `check_tenure_change_confirms_parent` for a tenure-change block) is the primary veto: it fetches `get_tenure_last_block_info(consensus_hash_of_A, ...)`, which returns `None` once `signed_self.max(signed_group) + tenure_last_block_proposal_timeout <= now` [1](#0-0) . When that happens, the height-comparison veto (`block.header.chain_length <= info.block.header.chain_length`) is skipped entirely, and the check falls through to the pre-committed-block branch (which does not fire because A is `LocallyAccepted`, not `PreCommitted`) and finally to the node's `get_tenure_tip`, which does not know about A because a locally-accepted block is never handed to the node until the full signer set has signed it [2](#0-1) . The tenure-change wrapper simply forwards to this same routine on the parent tenure [3](#0-2) , and it is invoked at proposal-arrival, validate-ok, and pre-commit-threshold time via `check_block_against_signer_db_state` [4](#0-3) .

The intended backstop for exactly this "single tenure can't see other tenures" blind spot is `get_signed_conflicts`, called at the pre-commit threshold, which searches *every* tenure for a signed block at or above the proposed height [5](#0-4) . But its freshness gate uses `conflict.last_endorsed > freshness_cutoff` where `freshness_cutoff = now - tenure_last_block_proposal_timeout` [6](#0-5)  — the same window, keyed off the same `signed_self`/`signed_group` timestamp that `get_tenure_last_block_info` uses. Once A crosses that window it is simultaneously invisible to both checks. The code explicitly assumes the chainstate check already covers this: "whether this block may replace what another tenure built is settled by the chainstate checks above" [7](#0-6)  — but for a tenure-change block B' whose `prev_tenure_consensus_hash` names A's tenure, that "chainstate check above" is precisely `check_tenure_change_confirms_parent`, which just went stale on the identical clock, so nothing settles it. The second same-tenure check only matches conflicts sharing B''s own `consensus_hash` [8](#0-7) , which A does not (A is in a different tenure), so it does not apply either. The result: the signer logs and signs the replacement [9](#0-8) .

Attacker flow: win one sortition to produce tenure A's block and get it to `LocallyAccepted` on the victim signer (one signature only, below 70%, so it is never handed to the node). Wait `tenure_last_block_proposal_timeout` (attacker-controllable simply by waiting; `Duration::ZERO` in the PoC models an already-expired window). Win (or forge, since this only requires an unprivileged miner slot) a second sortition and craft B' as a tenure-change block whose `prev_tenure_consensus_hash` equals A's tenure and whose `chain_length` equals A's (a sibling, not a genuine continuation), off the same parent as A. Propose B'. `check_tenure_change_confirms_parent` no longer sees A (stale) and does not veto; the node has no record of A's tenure above the parent, so the node-tip fallback also does not veto. At pre-commit threshold, `get_signed_conflicts` finds A but excludes it as stale, and the same-tenure check does not match a different-tenure block. The signer signs B'. Meanwhile A's `signed_self` signature is never revoked — [10](#0-9)  documents this is by design ("rejection... does not clear it... a signature is a bearer instrument"). If other signers (whose freshness clocks or activity differ) or a delayed aggregation later push A's signatures over 70%, both A and B' are each capable of reaching global acceptance from this signer's endorsement.

This is analogous to, but distinct from, the tested same-tenure re-proposal case (`stale_sibling_replaced_when_canonical_tip_below`) [11](#0-10) , which is safe because it stays inside one tenure (only one canonical block can occupy that tenure). The cross-tenure equivalent is only tested in its *fresh* form (`fresh_conflict_in_another_tenure_blocks_signing`, window kept open for 100,000s) [12](#0-11)  and in the form where A was provably killed by a real reorg after global acceptance (`conflict_the_node_reorged_past_does_not_block_signing`). No test exercises A merely timing out while `LocallyAccepted` (never globally accepted) in a *different* tenure from B — precisely the gap identified above; `run_cross_tenure_scenario` exists as scaffolding for exactly this cross-tenure sibling race [13](#0-12)  but is never invoked with a short/expired timeout.

### Impact Explanation
This breaks the signer's core safety invariant — a signature is a bearer instrument, and the whole architecture (the "conflict guard," `mark_tenure_superseded`, `reorg_permit_stands`) exists to ensure a signer never places two live signatures on blocks that can independently reach the 70% chain-canonicalizing threshold. If this signer's weight is one of several that were split similarly by the same timing trick, or if A's earlier signatures combine with other signers who haven't hit the same staleness window, both A and B' remain candidates for the 70% threshold, which is the definition of equivocation/chain-safety violation (Critical per the given severity taxonomy). It is repeatable per tenure pair and costs the attacker nothing beyond one miner slot plus normal gossip/proposal traffic and waiting out a known, static configuration value (`tenure_last_block_proposal_timeout`).

### Likelihood Explanation
Preconditions are attacker-affordable: win one sortition to seed tenure A, get a single signer to `LocallyAccepted` (that signer's own vote suffices; no majority needed), wait out the fixed, publicly-known `tenure_last_block_proposal_timeout` (default visible in `sample/conf/signer/mainnet-signer-conf.toml`), then win/craft a second sortition/tenure-change block B' that names A's tenure as parent while conflicting at the same height. No auth_token, no privileged role, no compromised dependency — purely message crafting and normal gossip through StackerDB/BlockProposal channels available to any miner-slot winner. The scenario is deterministic given the shared staleness clock, not probabilistic, so it is reliably reproducible.

### Recommendation
Decouple the freshness window used by `get_tenure_last_block_info` (the chainstate veto) from the freshness window used by `get_signed_conflicts` (the cross-tenure backstop), or make the backstop unconditionally check cross-tenure conflicts against the live node tip (as it already does for same-tenure conflicts) rather than trusting the chainstate check to have "settled" cross-tenure staleness. At minimum, `handle_block_pre_commit`'s cross-tenure conflict search should not rely on local timestamp staleness alone for a block that was never globally accepted; it should require `conflict_still_blocks`-style node confirmation of the conflict's death (e.g. via the node's tenure tip or global-acceptance status) independent of the tenure_last_block_proposal_timeout expiry that also silences the chainstate check.

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

        // A block we have only pre-committed to must NOT veto this proposal, but, similar to above
        // this should still count as activity for the miner.
        let last_accepted_block = signer_db
            .get_last_accepted_block(tenure_id)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;
        if let Some(info) = last_accepted_block {
            let is_fresh_pre_commit = info.state == BlockState::PreCommitted
                && info.approved_time.is_some_and(|approved_time| {
                    approved_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
                        > get_epoch_time_secs()
                });
            if is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length {
                info!(
                    "Miner's block proposal conflicts with a block we have only pre-committed to. Counting it as miner activity, but not rejecting the proposal.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "pre_committed_signer_signature_hash" => %info.block.header.signer_signature_hash(),
                    "pre_committed_chain_length" => info.block.header.chain_length,
                );
                if let Err(e) = signer_db
                    .update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
                {
                    warn!("Failed to update last activity time: {e}");
                }
            }
        }

        let tip = match client.get_tenure_tip(tenure_id) {
            Ok(tip) => tip.anchored_header,
            Err(e) => {
                warn!(
                    "Failed to fetch the tenure tip for the parent tenure: {e:?}. Assuming proposal is higher than the parent tenure for now.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "parent_tenure" => %tenure_id,
                );
                return Ok(true);
            }
        };
        if let Some(nakamoto_tip) = tip.as_stacks_nakamoto() {
            // If we have seen this block already, make sure its state is updated to globally accepted.
            // Otherwise, don't worry about it.
            if let Ok(Some(mut block_info)) =
                signer_db.block_lookup(&nakamoto_tip.signer_signature_hash())
            {
                if block_info.state != BlockState::GloballyAccepted {
                    if let Err(e) = block_info.mark_globally_accepted() {
                        warn!("Failed to mark block as globally accepted: {e}");
                    } else if let Err(e) = signer_db.insert_block(&block_info) {
                        warn!("Failed to update block info in db: {e}");
                    }
                }
            }
        }
        Ok(tip.height() < block.header.chain_length)
    }
