## Title
Stale `operator` parameter in `distribute_internal` causes old operator's unpaid commission to bypass `beneficiary_for_operator` redirection after `switch_operator` - (File: aptos-move/framework/aptos-framework/sources/staking_contract.move)

### Summary
`distribute_internal` decides whether a distribution-pool share is "operator commission" (and therefore should be redirected to `beneficiary_for_operator`) purely by comparing the recorded shareholder address to the `operator` argument passed in by the caller [1](#0-0) . After `switch_operator` moves a `StakingContract` from `old_operator` to `new_operator`, that `operator` argument becomes `new_operator` for all future calls, while unpaid commission shares recorded during `request_commission_internal` before the switch are still keyed by `old_operator`'s address [2](#0-1) . The permissionless `distribute` entry function ("Allow anyone to distribute already unlocked funds") can then be invoked by any unprivileged account for that staker/`new_operator` pair, triggering `distribute_internal` and paying the old operator's outstanding commission directly to `old_operator`'s own address instead of routing it through `beneficiary_for_operator(old_operator)` [3](#0-2) .

### Finding Description
`switch_operator` first forces distribution and commission collection for `old_operator`, correctly using `old_operator` as the `operator` parameter at that point [4](#0-3) . `request_commission_internal` records the unpaid commission as a distribution-pool share under `old_operator`'s address via `add_distribution(operator, staking_contract, operator, commission_amount)` [5](#0-4) , but this commission cannot actually be withdrawn until the stake pool's lockup expires. `switch_operator` then re-keys the `StakingContract` under `new_operator` in the `staking_contracts` map [6](#0-5) , while the `distribution_pool` inside that struct still contains the pending share for `old_operator`.

Once the lockup period elapses, any unprivileged account can call the permissionless `distribute` entry point for `(staker, new_operator)`. Inside `distribute_internal`, the redemption loop checks `if (recipient == operator)` to decide whether to redirect payment to `beneficiary_for_operator(operator)` [1](#0-0) . Because `recipient` is `old_operator`'s address but `operator` is now `new_operator`, the comparison fails, so the beneficiary redirection is skipped and the coins are deposited straight to `old_operator`'s address instead of to `beneficiary_for_operator(old_operator)`.

This breaks the required invariant that "distribution_pool shares recorded under old_operator must be paid only to the correct beneficiary_for_operator(old_operator)."

### Impact Explanation
If `old_operator` had configured a beneficiary via `set_beneficiary_for_operator` prior to the switch [7](#0-6) , that beneficiary's expected commission payout is silently rerouted to `old_operator`'s own account address once anyone triggers `distribute` after the switch and lockup expiry. This is a real accounting/routing bug that misdirects commission funds away from the intended beneficiary, though the funds land on the (legitimate but no-longer-intended) `old_operator` address rather than an address chosen by the caller — the unprivileged caller cannot redirect funds to themselves; they can only trigger the mispayment.

### Likelihood Explanation
Reaching this state requires: (1) an operator's staking contract, (2) commission requested/pending before a lockup rollover, (3) a `switch_operator` call, and (4) a beneficiary configured for the old operator. Calling `distribute` itself requires no privilege at all — it's documented as "Allow anyone to distribute" — so triggering the mispayment once the preconditions exist is trivial and requires no elevated access.

### Recommendation
In `distribute_internal`, redirect to the beneficiary based on the shareholder's own registered beneficiary rather than comparing against the current `operator` parameter — e.g., check `beneficiary_for_operator` existence for `recipient` itself (or persist the original operator identity with each commission distribution entry) so historical shares keyed to `old_operator` continue to resolve to `beneficiary_for_operator(old_operator)` regardless of subsequent operator switches.

### Proof of Concept
1. Create a staking contract for `staker`/`operator1` with a non-zero commission percentage.
2. `operator1` calls `set_beneficiary_for_operator(operator1, beneficiary1)`.
3. Advance an epoch to accrue rewards; call `request_commission(operator1, staker, operator1)` to record an unpaid commission share under `operator1` (funds not yet withdrawable).
4. `staker` calls `switch_operator(staker, operator1, operator2, new_commission)`.
5. Advance past the lockup period so the previously requested commission becomes withdrawable.
6. Any unprivileged account calls `distribute(staker, operator2)`.
7. Assert `coin::balance(operator1) == expected_commission` and `coin::balance(beneficiary1) == 0`, demonstrating the commission bypassed `beneficiary_for_operator(operator1)` and was paid directly to `operator1` instead. [1](#0-0)

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
