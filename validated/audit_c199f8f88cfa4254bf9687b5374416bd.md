### Title
Cross-user response leakage via requestID reuse race in HTTP trigger callback registration - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Finding Description
`savedCallback` stores only a request-scoped `responseAggregators` map keyed by shard `donID`, with no field binding the entry to the workflowID or authorized key that created it [1](#0-0) . `setupCallback` only guards against ID reuse while an entry is still present in `h.callbacks`; once `cleanupCallback` deletes the entry (called right after `SendResponse` succeeds, or by the periodic `reapExpiredCallbacks`), the same `requestID` string becomes immediately reusable by any subsequent caller for a completely different `workflowID` [2](#0-1) . `validateRequestID` performs no uniqueness/ownership binding beyond checking the ID is non-empty and has no `/` [3](#0-2) .

`HandleNodeTriggerResponse` looks up the callback purely by `resp.ID` and routes the node's response into whatever `savedCallback` currently occupies that key, using only `nodeAddrToShard` (a static per-node/per-shard mapping, not per-workflow) to select the aggregator; it never verifies that the response actually corresponds to the workflowID/execution that the current occupant of `h.callbacks[resp.ID]` was created for [4](#0-3) . Additionally, `sendToShard`'s per-node goroutines are only signaled to stop *scheduling further retries* via `doneCh`; already in-flight `shard.connMgr.SendToNode` calls are not cancelled, so a slow node can still deliver a late response for a stale/cleaned-up request after the ID has been reassigned [5](#0-4) .

Exploit flow: user1 sends `workflows.execute` with `id=X` for workflowA; the callback completes and is cleaned up, but one or more slow nodes' in-flight sends for the old execution are still outstanding. Before those stale responses arrive, an unprivileged caller sends a new `workflows.execute` with the same `id=X` for a different `workflowB` that happens to share at least one DON/shard with workflowA (an attacker can enumerate `workflowID`s freely and target workflows they know are co-assigned to shards). `setupCallback` succeeds because `h.callbacks[X]` was already deleted, and creates a new `savedCallback` for workflowB keyed by workflowB's shard donIDs. If a sufficient number (>= aggregation threshold) of workflowA's stale, identical, delayed node responses for `id=X` then arrive from nodes belonging to a shard donID shared with workflowB, `CollectAndAggregate` reaches quorum on workflowA's stale response and `SendResponse` delivers workflowA's result data to user2/attacker's callback.

### Impact Explanation
This is a cross-user response confusion vulnerability: an unrelated caller can receive workflow execution result data belonging to a different user's prior execution, purely due to the request-ID keyspace being reused without any workflow/session binding check in `HandleNodeTriggerResponse`. This matches the "unauthorized access to another user's job/execution result" bounty impact class.

### Likelihood Explanation
Exploitation requires: (1) the attacker knowing or guessing another user's exact recently-completed `requestID` string (typically opaque/random, lowering likelihood unless IDs are predictable, e.g., sequential or timestamp-based client IDs); (2) a race window between `cleanupCallback` and the arrival of enough stale-but-matching node responses to reach the aggregator's quorum threshold; and (3) the victim's and attacker's workflows sharing at least one DON shard. No privileged access is required — only the ability to send a `workflows.execute` JSON-RPC request with an attacker-chosen `id`. The race is difficult to win reliably in practice but is architecturally reachable given the code's lack of any binding beyond the string ID.

### Recommendation
Bind callback identity to more than the bare requestID: store the `workflowID` (and/or the authorized key/owner) inside `savedCallback` at `setupCallback` time, and have `HandleNodeTriggerResponse` reject/ignore any node response whose implied workflowID/executionID does not match the currently registered `savedCallback.workflowID` before routing it to an aggregator. Additionally, consider using cancellable per-node send contexts so `doneCh` closure also cancels truly in-flight `SendToNode` calls, reducing the window for stale deliveries.

### Proof of Concept
Go handler-level integration test in `http_trigger_handler_test.go`:
1. Configure a fake DON with two workflows (A, B) sharing a shard, `CleanUpPeriodMs` and node timeouts set low.
2. Send `workflows.execute` for workflowA with `id="X"`; have `shard.connMgr.SendToNode` delay one node's underlying send completion (simulate slow network) while other nodes respond fast enough to reach quorum and trigger `cleanupCallback("X")`.
3. Immediately after cleanup, call `HandleUserTriggerRequest` again with `id="X"` for workflowB (different callback/channel).
4. Release the delayed node's response for the original workflowA execution (same `id="X"`), and additional delayed nodes' responses until aggregator quorum is reached against workflowB's `savedCallback`.
5. Assert that workflowB's callback's `SendResponse` is invoked with workflowA's stale response payload (unless the fix is applied) — expected assertion after the fix: `HandleNodeTriggerResponse` returns an error/no-op because the response's workflowID does not match the workflowID stored in `h.callbacks["X"]` for workflowB.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {

	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// Build one response aggregator per shard the workflow is assigned to.
	assigned := h.workflowMetadataHandler.WorkflowShards(workflowID)
	if len(assigned) == 0 {
		// this shouldn't happen because we checked it in authorizeRequest()
		h.handleUserError(ctx, requestID, jsonrpc.ErrInternal, fmt.Sprintf("Workflow %s is not assigned to any DONs", workflowID), callback)
		return nil, errors.New("workflow is not assigned to any shards")
	}

	aggregators := make(map[string]*aggregation.IdenticalNodeResponseAggregator, len(assigned))
	for _, shard := range assigned {
		// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
		threshold := (len(shard.members)+shard.f)/2 + 1
		agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
		if err != nil {
			return nil, errors.New("failed to create response aggregator: " + err.Error())
		}
		aggregators[shard.donID] = agg
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:            callback,
		requestStartTime:    requestStartTime,
		createdAt:           time.Now(),
		responseAggregators: aggregators,
		doneCh:              doneCh,
	}
	return doneCh, nil
}

// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
	aggResp, err := agg.CollectAndAggregate(resp, nodeAddr)
	if err != nil {
		return err
	}
	if aggResp == nil {
		h.lggr.Debugw("Not enough responses to aggregate", "requestID", resp.ID, "nodeAddress", nodeAddr, "shard", shard.donID)
		return nil
	}
