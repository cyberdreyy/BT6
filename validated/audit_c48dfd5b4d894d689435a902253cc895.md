### Title
Unvalidated symlink target in zip cache extraction allows writing outside workspace via attacker-controlled archive content - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipSymlinkEntry` creates a symlink using file content as the target with zero validation of the resulting link target, and `errorIfGitDirectory`/`isPathAGitDirectory` only inspects the entry's *name* (first path segment), not the symlink's *target*. An attacker who controls a cache archive can create a symlink at an innocuous path whose target is `.git/hooks/pre-commit` (or another sensitive relative/absolute path), which is not blocked by the existing `.git` check.

### Finding Description
In [1](#0-0) , `extractZipSymlinkEntry` reads the entry's file content and calls `os.Symlink(string(data), file.Name)` directly, with `data` fully attacker-controlled (it's the cache/artifact zip entry's content) and no check that the resolved target stays within the workspace root.

The only path-safety check present is `errorIfGitDirectory`, defined in [2](#0-1) , which is called in `ExtractZipArchive` as `errorIfGitDirectory(file.Name)` — [3](#0-2) . This function only checks whether the zip entry's *name* starts with `.git`; it never inspects the symlink target (`data`). So an entry named e.g. `safe/link` (not starting with `.git`) with symlink content `../../.git/hooks/pre-commit` bypasses this check entirely, satisfying the described bypass.

Additionally, even if `errorIfGitDirectory` returns a non-nil error, it does not abort extraction — `ExtractZipArchive` only uses the tracker to decide whether to log a warning (`tracker.actionable(err)`), and unconditionally proceeds to call `extractZipFile(file)` regardless — [3](#0-2) . So the "check" is warning-only, not an enforcement/security boundary, by design.

This is reachable from `CacheExtractorCommand.Execute`, which extracts a downloaded/local cache file via `archive.NewExtractor(...).Extract(...)`, ultimately calling into `ExtractZipArchive` for zip-format caches — [4](#0-3) . Since cache content for a project is written by prior job runs (potentially by the same unprivileged pipeline author, e.g. via `cache:paths` in `.gitlab-ci.yml`), an attacker who controls a job in the same cache scope can plant a symlink whose target escapes the workspace on the next run that restores that cache.

### Impact Explanation
If a symlink named e.g. `safe/link` pointing to `../../.git/hooks/pre-commit` is created inside the workspace during cache extraction, and a later step in the same job (or same workspace) writes to `safe/link` (or a build tool follows/writes through it) and then a git operation triggers hooks, arbitrary shell commands could execute in the runner's job execution context. The impact is scoped to command execution within the executor that is already running the attacker's own job (shell/docker executors sharing the workspace) — it does not by itself cross a sandbox boundary for shell/docker-in-docker isolated executors, but for shell executors and any workspace shared across pipeline stages, it lets an attacker's earlier job stage influence execution of a later stage beyond what the pipeline definition itself specifies (host filesystem writes via absolute symlink targets, `.git/hooks` injection, etc.).

### Likelihood Explanation
Preconditions are modest: the attacker only needs the ability to populate a `cache:` (or artifact, if similarly implemented) zip that the runner later extracts into the job workspace — something a normal pipeline author fully controls via `.gitlab-ci.yml` `cache:paths` and job scripts. No admin privilege or external compromise is required. The `errorIfGitDirectory` check demonstrably does not cover this path (name-only check, and non-blocking even if triggered), so nothing in the current code stops it.

### Recommendation
- Validate the resolved symlink target against the workspace root before calling `os.Symlink`: reject symlink entries whose target (after resolving relative to `filepath.Dir(file.Name)`) escapes the workspace root, or whose target is absolute.
- Extend `isPathAGitDirectory`-style checks to also inspect symlink target content, not just the entry name.
- Make `errorIfGitDirectory` (and any future path-safety checks) actually abort extraction of the offending entry rather than only logging a warning.

### Proof of Concept
```go
func TestExtractZipArchive_SymlinkEscapesWorkspaceViaGitHooks(t *testing.T) {
    tmpDir := t.TempDir()
    // simulate an actual .git repo with hooks dir
    hooksDir := filepath.Join(tmpDir, ".git", "hooks")
    require.NoError(t, os.MkdirAll(hooksDir, 0o755))

    // build malicious zip: symlink "safe/link" -> "../../.git/hooks/pre-commit"
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    hdr := &zip.FileHeader{Name: "safe/link"}
    hdr.SetMode(os.ModeSymlink | 0o777)
    w, _ := zw.CreateHeader(hdr)
    _, _ = w.Write([]byte("../../.git/hooks/pre-commit"))
    zw.Close()

    origWd, _ := os.Getwd()
    defer os.Chdir(origWd)
    os.Chdir(tmpDir)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the symlink escapes into .git/hooks
    target, err := os.Readlink(filepath.Join(tmpDir, "safe", "link"))
    require.NoError(t, err)
    resolved := filepath.Join(filepath.Dir(filepath.Join(tmpDir, "safe", "link")), target)
    require.Contains(t, filepath.Clean(resolved), filepath.Join(".git", "hooks", "pre-commit"))
    // Writing to safe/link now writes into .git/hooks/pre-commit, unexpectedly bypassing the .git check
}
```
This confirms `ExtractZipArchive` places a symlink pointing into `.git/hooks` without error, despite `errorIfGitDirectory` being invoked on the entry name `safe/link`.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
