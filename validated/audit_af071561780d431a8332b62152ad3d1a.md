### Title
Post-default withdraw requests pay 1:1 from a recovery reserve sized only for pre-default claims — (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`finalizeDefaultRecovery` computes `defaultRecoveryReserve` and `defaultRecoveryPrice` against a fixed `totalBasis` of pre-default claims (pending withdraws + unfunded instant receipts). Afterwards, `requestWithdraw` creates `postDefaultRequests` that are paid 1:1 out of that same fixed reserve via `_claimPostDefaultWithdrawRequest` → `_transferDefaultRecovery`, without adding any corresponding claim basis or new underlying to the reserve. The kernel analog is exact: a carried-over amount (`fraggap` / the fixed recovery reserve) is included in the aggregate but omitted from the sub-allocation for the new claim class, so later claims write past the accounted allocation and corrupt payouts for earlier claimants.

### Finding Description
In `finalizeDefaultRecovery` (contracts/strategies/idle/IdleCreditVault.sol:661-710) the reserve is set to `reserveAmount = _recoveredAmount + prefundedReserve + defaultRecoveryReserve` and `defaultRecoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis`, where `totalBasis` covers only `activeBasis + pendingBasis` measured at finalization. Every defaulted-epoch claim is therefore entitled to `basis * recoveryPrice / 1e18`, and the reserve is sized so all such claims together consume it exactly.

The post-default branch of `requestWithdraw` (lines 247-257) mints a receipt to the user and records `postDefaultRequests[_user] = _amount`. `_claimPostDefaultWithdrawRequest` (lines 760-767) then pays `amount` 1:1 from `defaultRecoveryReserve`. No underlying is ever transferred into the strategy to back this new claim — the CDO only burns `_amount` of its strategy tokens, which reduces `balanceOf(idleCDO)` but adds zero tokens to the reserve. The claim basis for the reserve was already frozen at finalization, so each post-default claim draws down funds that were exclusively earmarked for defaulted-epoch receipt holders.

A worked example: pre-default `pendingBasis = 1000`, recovery supplies 500 → `defaultRecoveryPrice = 0.5e18`, reserve = 500. A wallet-allowed lender holding tranches then calls `requestWithdraw` post-default (CDO passes the already-haircut `_amount = 100`), creating `postDefaultRequests = 100`. Claiming takes 100 from the reserve, leaving 400 for a 1000 basis — defaulted-epoch claimants recover 400 instead of 500. The attacker converts a position whose fair recovery share was `~100 * 0.5 = 50` (via tranche price) into a full 100 payout.

### Impact Explanation
Direct theft with quantified loss: each post-default claim of `X` extracts `X` underlying from the isolated recovery reserve, imposing a proportional `X` shortfall on all defaulted-epoch claimants (both normal and instant receipts). A large tranche holder can drain the reserve entirely before defaulted-epoch users claim, leaving them with zero on `claimWithdrawRequest`/`claimInstantWithdrawRequest`. Loss is bounded by the attacker's post-haircut tranche value and equals `min(attackerClaims, reserve)`.

### Likelihood Explanation
Preconditions: a borrower default occurs and recovery is finalized (`finalizeDefaultRecovery` called by owner/manager — honest actors), `recoveryPrice < 1e18` (any partial recovery), and withdraw request flags are re-enabled post-default (i.e., the vault is not permanently paused — this is the supported "request/claim UX after default" path the code explicitly preserves per the comment at line 252). Any KYC-passing lender (`isWalletAllowed`) with tranche tokens can execute; no privileged role needed. The only uncertainty is whether `allowAAWithdrawRequest`/`allowBBWithdrawRequest` are restored after default finalization — if they are never re-enabled, the post-default branch is dead code and the finding does not trigger. This depends on `restoreOperations`/default-handling in `IdleCDOEpochVariant` which should be verified in the PoC.

### Recommendation
Fund post-default claims separately from the finalized reserve. Either (a) account each `postDefaultRequests` amount as additional claim basis against `defaultRecoveryReserve` only to the extent of `defaultRecoveryPrice` (i.e., store `postDefaultRequests` pre-haircut and pay `basis * defaultRecoveryPrice / 1e18`), or (b) require the CDO to transfer underlying backing for the burned strategy tokens into the strategy and add it to `defaultRecoveryReserve` before allowing the claim. Alternatively, block `requestWithdraw` entirely while `defaultRecoveryFinalized` is true and route post-default exits through tranche redemption at the crystallized recovery price.

Foundry fork PoC sketch (requires a live Clearpool/idle-tranches fork at a block with an active credit vault):

```solidity
// test/foundry/PostDefaultReserveDilution.t.sol
function testPostDefaultClaimDrainsRecoveryReserve() public {
    // 1. Honest lenders deposit AA/BB; manager runs an epoch; borrower defaults.
    //    stopEpoch pull fails -> _handleBorrowerDefault -> defaulted = true.

    // 2. Owner finalizes recovery with partial funds:
    //    finalizeDefaultRecovery(recovered, source) =>
    //    defaultRecoveryPrice = 0.5e18, defaultRecoveryReserve = R.

    uint256 reserveBefore = vault.defaultRecoveryReserve();
    uint256 price = vault.defaultRecoveryPrice(); // < 1e18

    // 3. Attacker (KYC'd lender with tranches) requests withdraw post-default.
    //    CDO passes haircut amount X; requestWithdraw sets postDefaultRequests.
    vm.prank(attacker);
    cdo.requestWithdraw(attackerTrancheBalance, AA);

    // 4. Attacker claims 1:1 from the fixed reserve.
    vm.prank(attacker);
    cdo.claimWithdrawRequest(attacker);

    // 5. Assert reserve decreased by X while defaulted-epoch basis is unchanged,
    //    so remaining honest claimants are short exactly X.
    assertEq(vault.defaultRecoveryReserve(), reserveBefore - X);
    // Honest defaulted-epoch claimant now receives less than basis * price,
    // or reverts on reserve underflow when claiming last.
    assertLt(honestClaimPayout, honestBasis * price / 1e18);
}
```
