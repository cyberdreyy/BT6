# STAKE-LOCKUP ANALOG SCAN — Result

### Title
Stale operator commission shares in `distribution_pool` are re-taxed and redirected to the new operator after `switch_operator` - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::switch_operator` reassigns a `StakingContract` (including its `distribution_pool`) from an old operator to a new operator, but leaves the old operator's already-earned, unwithdrawn commission shares sitting in the same `distribution_pool` as an ordinary shareholder entry. `update_distribution_pool`, which is invoked on every subsequent `distribute`, `unlock_stake`, `request_commission`, or `update_commision` call, treats any shareholder whose address `!= operator` (the *current* operator) as subject to a fresh commission skim on value growth, and transfers the skimmed shares to the current operator. Because the old operator's parked commission is a `shareholder != new_operator`, it gets taxed again and the proceeds are credited to the new operator instead of the old operator.

### Finding Description
`switch_operator` at [1](#0-0)  removes the `StakingContract` under `old_operator`, flushes distributions and pending commission for the old operator via `distribute_internal` and `request_commission_internal`, then simply overwrites `commission_percentage` and re-inserts the *same* `StakingContract` struct (including its `distribution_pool: Pool`) under `new_operator`.

Any commission that was requested via `request_commission_internal` but not yet distributed (because the corresponding stake is still unlocking) is recorded in `distribution_pool` as a share entry keyed by the *old operator's address*, added through `add_distribution` at [2](#0-1) .

After the switch, `distribution_pool`'s only notion of "current operator" is the `operator` parameter threaded through call sites (now `new_operator`), not a persisted field distinguishing old vs. new operator shareholder entries. `update_distribution_pool` at [3](#0-2)  charges commission on value growth for every shareholder where `shareholder != operator`:
```
shareholders.for_each_ref(|shareholder| {
    if (shareholder != operator) {
        ...
        pool_u64::transfer_shares(distribution_pool, shareholder, operator, shares_to_transfer);
    }
});
```
Since the old operator's address is `!= new_operator`, its parked, already-vested commission balance is treated exactly like a staker's pending-withdrawal balance: any growth in the pool's value (which happens automatically as pending/inactive stake continues to compound rewards, or due to any deposit re-syncing `updated_total_coins`) is taxed at the *new* operator's commission rate and the skimmed shares are transferred to the *new* operator, not back to the old operator or the staker.

This is triggered from every path that calls `distribute_internal`/`update_distribution_pool` after a switch: `distribute` (permissionless, callable by "anyone" per its own doc comment) at [4](#0-3) , as well as `unlock_stake`, `request_commission`, and `update_commision`.

### Impact Explanation
This corrupts operator-commission share accounting and credits the wrong account: value that rightfully belongs to the departed operator (already carved out of staker principal as compensation for services rendered before the switch) is silently transferred to the new operator without the old operator's or staker's consent. This matches the required impact class "Operator commission ... share-accounting corruption that credits the wrong account or traps value," and is reachable by any staker who controls `switch_operator` plus any unprivileged account calling the permissionless `distribute` entry function afterward — no elevated role is needed to trigger the mistaken transfer.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: operators commonly leave commission unclaimed for some period (commission only becomes withdrawable after the stake-pool lockup expires), and stakers routinely call `switch_operator` to change operators without needing the old operator's cooperation. Once switched, the very next `distribute()`/`unlock_stake()`/`request_commission()` call — which can be fired by anyone since `distribute` is explicitly permissionless — re-taxes the old operator's balance for the new operator's benefit as soon as the pool's tracked `total_coins` changes.

### Recommendation
Before reassigning the `StakingContract` to `new_operator` in `switch_operator`, fully settle the old operator's distribution_pool entry (e.g., force a final `update_distribution_pool` charge under the *old* commission rate and old operator identity, then either withdraw/lock that entry so it's excluded from any future re-tax, or migrate the value out of the shared `distribution_pool` into a per-operator distribution record so `update_distribution_pool`'s `shareholder != operator` exclusion correctly protects both the old and new operator's already-vested commission balances).

### Proof of Concept
1. Staker `S` creates a staking contract with `operator_1` and commission 10%; validator generates rewards over several epochs.
2. `operator_1` calls `request_commission`, which unlocks commission and records it in `distribution_pool` as a share entry keyed to `operator_1` (via `add_distribution`), but the underlying stake hasn't finished unlocking yet (still `pending_inactive`).
3. Before `operator_1`'s commission becomes withdrawable, `S` calls `switch_operator(S, operator_1, operator_2, new_commission_percentage=50)`. The `StakingContract` (with `operator_1`'s pending distribution share still inside) is moved to key `operator_2`.
4. Time passes; the still-unlocking stake underlying `operator_1`'s parked commission continues to earn rewards, increasing `distribution_pool`'s value.
5. Anyone calls `staking_contract::distribute(S, operator_2)`. `distribute_internal` invokes `update_distribution_pool` with `operator = operator_2` and the new (50%) commission rate. Since `operator_1 != operator_2`, `operator_1`'s parked balance is charged 50% commission on its growth, and those shares are transferred to `operator_2`.
6. When `operator_1` eventually withdraws, they receive less than the commission amount they originally earned and locked in at step 2; `operator_2` receives value they did not earn, purely from switching in after the fact.

    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
