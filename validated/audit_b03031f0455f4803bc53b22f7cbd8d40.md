### Title
Bridge `outgoingToken` secret is returned in plaintext to any authenticated GraphQL user via `Resolver.Bridge`/`Resolver.Bridges` - ([File: core/web/resolver/bridge.go])

### Summary
The GraphQL `Bridge` type schema and its Go resolver expose `bridge.OutgoingToken` in plaintext to any authenticated caller who can execute `query { bridges { ... } }` or `query { bridge(id: ...) { ... } }`. While `IncomingTokenHash` and `Salt` are not wired into any resolver method (and thus cannot be queried), `OutgoingToken` is explicitly declared in the schema and resolved verbatim from the underlying `bridges.BridgeType` struct without redaction.

### Finding Description
`core/web/schema/type/bridge.graphql` defines the `Bridge` GraphQL type with an `outgoingToken: String!` field: [1](#0-0) 

The corresponding Go resolver `BridgeResolver.OutgoingToken()` returns the raw secret straight from the persisted `bridges.BridgeType` struct with no masking: [2](#0-1) 

That struct field is the actual bridge authentication secret used to sign/authenticate outbound requests to the external adapter, stored alongside `IncomingTokenHash` and `Salt`: [3](#0-2) 

`Resolver.Bridge` and `Resolver.Bridges` only call `authenticateUser(ctx)` before returning bridge data — there is no field-level redaction or role check beyond basic authentication: [4](#0-3) 

`BridgeResolver` (used by both `BridgePayloadResolver.ToBridge` and `BridgesPayloadResolver.Results`) does **not** implement `IncomingTokenHash()` or `Salt()` methods, and those fields are absent from the GraphQL schema — so those two specific fields are not reachable via GraphQL and the audit's premise about them is not confirmed as exploitable. However, `OutgoingToken()` **is** implemented and **is** in the schema, making it retrievable by any session that passes `authenticateUser`, which does not appear to restrict by role beyond requiring a valid session in this code path.

### Impact Explanation
An authenticated view-role (or any role capable of running GraphQL queries) can retrieve `outgoingToken` for every configured bridge via `query { bridges { results { name url outgoingToken } } }`. This token is one of the bridge's authentication secrets; its disclosure lets an attacker forge/verify traffic that impersonates the node's outbound bridge calls, matching the "disclosure of bridge authentication secrets enabling forgery of bridge responses" impact class.

### Likelihood Explanation
Any client holding a valid authenticated GraphQL session can trivially request this field — no special privilege beyond passing `authenticateUser` is required, and the field is a first-class, documented part of the public schema (not a hidden/internal field), making exploitation deterministic and repeatable on every call.

### Recommendation
Remove `outgoingToken` from the public `Bridge` GraphQL type and its resolver, or restrict it to bridge creation/update responses only (as is already done for `incomingToken` via `CreateBridgeSuccess`/`UpdateBridgeSuccess`, which return the token once at creation time). If `OutgoingToken` must be surfaced for auditing, gate it behind an explicit admin-only field/resolver with masking (e.g., return only a fingerprint) rather than the raw secret.

### Proof of Concept
Go handler-level integration test:
1. Seed a bridge via `bridges.NewBridgeType` capturing a known `OutgoingToken` value.
2. Authenticate a GraphQL client as a non-admin/view-role session (mirroring how other resolver tests bootstrap `authenticateUser`).
3. Execute `query { bridges { results { name outgoingToken } } }`.
4. Assert the response JSON contains the exact `OutgoingToken` value seeded in step 1, proving plaintext secret disclosure via `BridgeResolver.OutgoingToken()` at [2](#0-1) .
5. Separately assert that no schema field path resolves `incomingTokenHash` or `salt` (schema introspection query returns no such fields on `Bridge`), to confirm those two fields specifically are not exposed.

// Bridge retrieves a bridges by name.
func (r *Resolver) Bridge(ctx context.Context, args struct{ ID graphql.ID }) (*BridgePayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	name, err := bridges.ParseBridgeName(string(args.ID))
	if err != nil {
		return nil, err
	}

	bridge, err := r.App.BridgeORM().FindBridge(ctx, name)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return NewBridgePayload(bridge, err), nil
		}

		return nil, err
	}

	return NewBridgePayload(bridge, nil), nil
}
