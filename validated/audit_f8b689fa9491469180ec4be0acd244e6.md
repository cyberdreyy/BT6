## Title
Removed multisig members' stale confirmations still count toward the execution threshold, allowing requests to execute with fewer live approvers than `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges requests that were *created* by the removed member; it never scans other requests' `confirmations` sets to strip out that member's prior confirmation. Because `confirm()` decides whether to execute purely by comparing `confirmations.len() + 1` against `self.num_confirmations`, a confirmation cast by a member who is later removed keeps counting as if it were live, letting a request execute with fewer currently-authorized signers than the configured threshold.

### Finding Description
The intended invariant is: `confirmations recorded for a request == confirmations from members that are currently live`. `delete_member` breaks this by only cleaning up requests keyed by `r.member == member` (i.e. requests *authored* by the departing member): [1](#0-0) 

It removes the member from `self.members` and revokes their key/account, but leaves `self.confirmations` entries untouched for any *other* request that this member had merely confirmed (not authored).

`confirm()` then trusts the stored confirmation count without re-validating that each entry in the set still corresponds to a live member: [2](#0-1) 

`current_member()` is only used to identify the *caller* of `confirm`, not to filter/validate the pre-existing entries already in the `confirmations` `HashSet<String>`: [3](#0-2) 

### Impact Explanation
This breaks the authorization/threshold binding: `live confirmations >= num_confirmations` is the guarantee that protects every privileged action executable via a request (`Transfer`, `AddKey`, `FunctionCall`, `AddMember`, `DeleteMember`, `SetNumConfirmations`, etc.). If a member confirms a pending request and is subsequently removed from the multisig (e.g., legitimately offboarded), that stale confirmation remains in the set and is counted the next time any remaining member calls `confirm`. As a result a request — including a `Transfer` of NEAR out of the multisig account — can execute with strictly fewer *currently authorized* signers than `num_confirmations` requires. This is exactly the "multisig request executed below threshold" scenario called out as Critical impact: funds can move, or the member set/threshold itself can be altered, without the number of live approvals the contract was configured to require.

### Likelihood Explanation
No special privilege beyond normal multisig usage is required to trigger this: any request that collects a partial confirmation before one of its confirmers is removed (a routine event — onboarding/offboarding of signers) leaves a dangling stale confirmation. Any subsequent `confirm` call by a remaining live member can then unintentionally cross the threshold using the stale vote, and there is no code path that detects or prevents it.

### Recommendation
When removing a member in `delete_member`, iterate over **all** requests (not just those authored by the departing member) and strip the departing member's entry from each request's `confirmations` set, or alternatively validate on every `confirm()` call that each entry in `confirmations` still corresponds to a member currently in `self.members` before counting it toward the threshold.

### Proof of Concept
1. Deploy `MultiSigContract` with members `{A, B, C}` and `num_confirmations = 2`.
2. `A` calls `add_request` to create a `Transfer` request (request_id `R`), without confirming.
3. `B` calls `confirm(R)` → `confirmations[R] = {B}` (below threshold, stored per `confirm` at `multisig2/src/lib.rs:310-313`).
4. `A` and `C` jointly execute a separate, properly-confirmed `DeleteMember{B}` request, removing `B` from `self.members`. Per `delete_member` (`multisig2/src/lib.rs:361-366`), only requests authored by `B` are purged — `R`, authored by `A`, is untouched, so `confirmations[R]` still equals `{B}`.
5. `C` (now one of only two live members, `A` and `C`) calls `confirm(R)`. In `confirm`, `confirmations.len() (=1, "B") + 1 >= num_confirmations (2)` evaluates true, so `execute_request` runs and the `Transfer` is sent — even though only one live member (`C`) ever approved it after `B`'s removal.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

                account_id: env::predecessor_account_id(),

        }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
