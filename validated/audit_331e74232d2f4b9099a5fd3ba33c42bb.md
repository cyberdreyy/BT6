### Title
Attacker-influenced ERC4626 `convertToAssets` over-read forces a false borrower default / fake vault loss in `ProgrammableBorrower` accounting - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
The Apache bug is an over-read of data returned by an attacker-controlled outbound endpoint (OCSP responder). The direct analog in this codebase is `ProgrammableBorrower`, which reads a single valuation number — `vault.convertToAssets(shares)` — from an external ERC4626 vault that unprivileged third parties can deposit into and donate to. `totalInterestDueNow()` / `_vaultNetInterest()` consume that value directly to price the epoch at `stopEpoch`, so a vault shareholder (an explicitly in-scope attacker class) can distort the CDO's interest read by manipulating the vault share price.

### Finding Description
`_currentVaultAssets()` trusts `vault.convertToAssets` verbatim [1](#0-0) . That value feeds `_vaultNetInterest()`, which computes `netDelta = bufferedVaultDelta + earnedAssets - principalAssets` and reports either `interest` or `loss` [2](#0-1) . `totalInterestDueNow()` returns `vaultInterest + borrowerInterestAccruedNow() + bufferInterest - loss` [3](#0-2)  and is the "single value read by IdleCDO to price the epoch" before `onStopEpoch` withdraws liquidity [4](#0-3) .

Two directions exist:

1. **Inflate**: an attacker who holds vault shares donates underlying directly to the vault, raising `convertToAssets` and therefore `totalInterestDueNow()`. IdleCDO then calls `onStopEpoch` with an inflated `_amountRequired`; if the shortfall exceeds real withdrawable value, the hook returns `true` and the subsequent `transferFrom` fails, pushing the CDO into `_handleBorrowerDefault` [5](#0-4)  — i.e., a fabricated default triggered purely by a transient price read. Default pauses the pool, stops the epoch, and disables withdrawal requests [6](#0-5) .

2. **Deflate / donate-then-report-loss**: where the vault's `convertToAssets` can be pushed down (e.g., share-price manipulation via rounding/withdrawal patterns) the same read reports a fake `vaultLoss`, which `totalInterestDueNow` nets against real borrower interest [7](#0-6) , socializing a phantom loss into tranche pricing via the BB-first waterfall at `stopEpoch`.

There is no bound, sanity check, or TWAP on the `convertToAssets` read — the comment at `onStopEpoch` explicitly acknowledges the value "was already read by IdleCDO before calling this hook," so the CDO acts on the manipulated number [8](#0-7) .

### Impact Explanation
An unprivileged vault depositor can force the credit pool into the default path: `defaulted = true`, pool paused, epoch stopped, AA/BB withdrawal requests disabled [9](#0-8) . That is at minimum temporary-to-permanent freezing of all lender funds and theft of unclaimed yield; if recovery accounting proceeds on the fabricated basis, permanent loss is socialized to tranche holders. Cost to the attacker is bounded by their donation × their vault share ownership (recoverable portion), which can be small relative to pool TVL.

### Likelihood Explanation
Requires only that the configured ERC4626 vault admits third-party depositors (the attacker class "a user of the programmable borrower's ERC4626 vault" is explicitly in scope) and a donation/price-move opportunity timed around the honest manager's `stopEpoch` call. No privileged role is needed.

### Recommendation
Bound the vault-PnL leg of `_vaultNetInterest()` (e.g., cap reported interest/loss to a configured band per epoch), snapshot `convertToAssets` at epoch start and compare against a stored per-share rate rather than a live read, or have IdleCDO cap `_amountRequired` at on-hand + previously snapshot principal so an inflated read cannot push the flow into the default path. Not verified: whether any existing guard in `IdleCDOEpochVariant._stopEpoch` bounds the requested amount — I was unable to read the exact `stopEpoch`/`_stopEpoch` lines before iteration limits; the PoC below assumes it consumes `totalInterestDueNow` directly as documented.

// Foundry fork test sketch (test/foundry/ProgrammableBorrowerInflatedRead.t.sol)
// Setup: real mainnet ERC4626 vault configured in ProgrammableBorrower,
// epoch active (epochAccountingActive == true), honest borrowerPrincipal > 0.

function test_DonationInflatedReadForcesDefault() public {
    // 1. Attacker deposits into the same ERC4626 vault to hold shares.
    vault.deposit(ATTACKER_DEPOSIT, attacker);

    // 2. Just before the honest manager's stopEpoch, attacker donates
    //    underlying directly to the vault, inflating convertToAssets.
    uint256 donation = INFLATION_AMOUNT;
    underlying.transfer(address(vault), donation);

    // 3. totalInterestDueNow() now returns interest + donation delta.
    uint256 inflated = programmableBorrower.totalInterestDueNow();
    assertGt(inflated, expectedRealInterest);

    // 4. Honest owner/manager calls stopEpochWithDuration/stopEpoch.
    //    IdleCDO computes _amountRequired from the inflated read; the
    //    borrower's transferFrom cannot cover it -> _handleBorrowerDefault.
    vm.prank(manager);
    idleCDO.stopEpoch(newApr);   // or stopEpochWithDuration

    // 5. Assert fabricated default state: funds frozen, requests disabled.
    assertTrue(idleCDO.defaulted());
    assertTrue(idleCDO.paused());
    assertFalse(idleCDO.allowAAWithdrawRequest());
    assertFalse(idleCDO.allowBBWithdrawRequest());

    // 6. Attacker redeems vault shares, recovering most of the donation.
    vault.redeem(vault.balanceOf(attacker), attacker, attacker);
}

    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;

  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
  }
