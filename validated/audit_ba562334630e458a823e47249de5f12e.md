### Title
Malformed short `parameters` blob in `createDstEscrow` permanently disables `withdraw`/`publicWithdraw` while `cancel` still refunds the depositor - (File: contracts/EscrowDst.sol, contracts/libraries/ImmutablesLib.sol)

### Summary
A destination-escrow creator can call `createDstEscrow()` with a `parameters` field shorter than 0x40 bytes (e.g., 1 byte). The escrow deploys and gets funded normally, but every subsequent `withdraw()` and `publicWithdraw()` call reverts inside `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd` with `IndexOutOfRange`, because the same malformed `parameters` bytes are baked into the CREATE2 salt/hash and must be resupplied unchanged to pass `onlyValidImmutables`. `cancel()`, however, never decodes `parameters` and works fine after the cancellation timelock, returning the full deposited amount to `immutables.taker` (the escrow creator).

### Finding Description
`EscrowDst._withdraw` at [2](#0-1)  unconditionally calls `immutables.integratorFeeAmountCd()` and `immutables.protocolFeeAmountCd()`, which revert via `IndexOutOfRange` unless `parameters.length >= 0x40` and `>= 0x20` respectively (`contracts/libraries/ImmutablesLib.sol` lines 76-95). Both `withdraw` (private, taker-only) and `publicWithdraw` (open to any access-token holder) funnel through `_withdraw`, so this check cannot be bypassed by any caller once the escrow's immutables lock in a short `parameters` blob. Since `hash()`/`onlyValidImmutables` binds the exact `parameters` bytes to the deployed address ( [4](#0-3) ), no corrective `parameters` value can ever be supplied later — the malformed shape is permanent for that specific escrow instance. `cancel()` ( [1](#0-0) ) bypasses all of this and simply returns `immutables.amount` to `immutables.taker`, so the depositor (who chose the malformed parameters) can always recover their own principal after `DstCancellation`, while the maker's payout path (via `withdraw`/`publicWithdraw`) is unconditionally broken.

`createDstEscrow` has no length check on `dstImmutables.parameters` and no resolver whitelist ( [5](#0-4) ), so any address willing to post the required native/ERC20 amount can create such an escrow.

### Impact Explanation
This breaks the atomic-swap safety guarantee that once the secret is public, *anyone* holding an access token can force payout to the maker via `publicWithdraw`, protecting the maker even against an uncooperative taker. With a malformed `parameters` blob, that safety valve is disabled: neither the taker nor any public caller can ever complete payout to the maker, while the taker can still reclaim the full escrowed amount via `cancel()` once the cancellation window opens. This is a permanent loss of the destination payout to the maker/protocol counterpart from a specific, correctly-funded escrow instance, matching "permanent freezing of funds" / "temporary freezing of funds during the live swap lifecycle" in the bounty's impact list.

### Likelihood Explanation
Trivial to trigger: the attacker only needs to pass a short `bytes` value for `parameters` in `dstImmutables` when calling `createDstEscrow`, fund it as normal, and wait. No privileged role, governance, or off-chain compromise is required — this is exactly the "unprivileged destination-escrow creator" entrypoint called out in the audit scope.

### Recommendation
Validate `dstImmutables.parameters.length` (e.g., require exactly `0x80` bytes, matching the four ABI-encoded fee fields) inside `createDstEscrow` before deploying/funding the clone, reverting on any other length so malformed escrows can never be created.

### Proof of Concept
1. Attacker calls `createDstEscrow(dstImmutables, srcCancellationTimestamp)` with `dstImmutables.parameters = hex"00"` (1 byte), sending the exact required `msg.value`/ERC20 amount.
2. The clone deploys and is funded correctly, confirmed by `escrow.balance`/token balance checks.
3. Once `DstWithdrawal` opens, taker calls `withdraw(secret, dstImmutables)` → reverts with `ImmutablesLib.IndexOutOfRange` (from `integratorFeeAmountCd`, since `parameters.length = 1 < 0x40`).
4. Once `DstPublicWithdrawal` opens, any access-token holder calls `publicWithdraw(secret, dstImmutables)` → same revert.
5. Once `DstCancellation` opens, taker calls `cancel(dstImmutables)` → succeeds, refunding `immutables.amount` and the safety deposit back to the taker; the maker never receives any destination-chain funds despite the escrow having been fully funded.

    function hash(IBaseEscrow.Immutables calldata immutables) internal pure returns(bytes32 ret) {
        // Compute the EIP-712 hash for the immutables struct
        bytes calldata parameters = immutables.parameters;
        assembly ("memory-safe") {
            let ptr := mload(0x40)

            // Copy immutables.parameters to memory and compute its hash
            calldatacopy(ptr, parameters.offset, parameters.length)
            let parametersHash := keccak256(ptr, parameters.length)
