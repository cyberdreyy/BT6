### Title
Signer re-validates only tenure-confirmation before signing, not miner-identity/bitvec/tenure-extend checks from proposal time — stale-miner block can still be signed after a state-machine capitulation - ([File: stacks-signer/src/chainstate/v2.rs])

### Summary
The Moodle bug class is "a security-relevant check exists on one code path but is silently skipped on another, functionally-equivalent path that produces the same outcome." In the v0 signer, `GlobalStateView::check_proposal` performs several checks that gate whether a block may ever be treated as valid — matching consensus hash, matching the winning miner's pubkey hash, requiring an all-ones pox bitvec, and time-gating tenure-extend transactions — but these checks run **only once, at proposal arrival**. The re-validation that runs immediately before the irreversible act of signing (`check_block_against_signer_db_state`) re-runs only the tenure-confirmation check, not the miner-identity/bitvec/tenure-extend checks. This is explicitly documented as intentional scope-limiting behavior, but it means the "is this the currently-approved miner's block" equality is checked once and then trusted for an arbitrarily long window while pre-commits accumulate toward the 70% threshold.

### Finding Description
`GlobalStateView::check_proposal` binds a proposal's validity to the signer's *current* view of `MinerState::ActiveMiner` at the moment the proposal is evaluated: it requires `block.header.consensus_hash == tenure_id`, `miner_pkh == current_miner_pkh`, and an all-ones bitvec, and gates tenure-extend transactions on timing computed against `get_epoch_time_secs()` at that instant: [1](#0-0) 

Between that check passing and the block crossing the 70% pre-commit weight threshold — the only point at which a signature is actually produced — the signer's local state machine can change out from under the block: the active miner can be deposed by inactivity/capitulation, or a new burn view can arrive, updating `current_miner`. The pre-commit path re-validates against chainstate only via `check_block_against_signer_db_state`, which the project's own flow documentation states re-runs solely the tenure-confirmation check (`check_latest_block_in_tenure`) — not the miner-pubkey-hash, consensus-hash, bitvec, or tenure-extend-timing checks performed in `check_proposal`:

> "Two things belong to the proposal path only and are **not** re-run at validate-ok or at signing: … the v2 `check_proposal` wrapper checks miner pubkey hash, consensus hash, the pox bitvec, and tenure-extend rules before delegating here." [2](#0-1) 

The signature is placed based solely on `block_info.valid` (frozen at proposal time) plus the tenure-confirmation re-check: [3](#0-2) 

So a block that was valid against the miner the signer believed was active at proposal time can still be signed after that signer's own state machine has moved on to a different active miner or tenure, as long as the (unrelated) tenure-confirmation check still passes. This is structurally identical to the Moodle flaw: the capability/authorization gate (`moodle/course:viewhiddencourses` there; "is this the approved, currently-canonical miner" here) is enforced on the initial request path but not re-enforced on the path that actually delivers the sensitive/irreversible action (listing hidden courses there; producing an unrevocable signature here).

### Impact Explanation
If enough signers' local pre-commit evaluations complete before their state machines observe the miner capitulation/burn-view change, the signer set can aggregate a valid 70% signature set over a block built by a miner the network has already moved past — i.e., a block that is no longer the approved/canonical proposer's block, without a fresh identity/bitvec re-check catching it. This is a "signer signing a non-canonical/deposed-miner block" — the equivocation guard in section 5 of the flow doc (`get_signed_conflicts`) only prevents signing two *different blocks at the same height*; it does nothing to prevent signing a single stale block whose *miner authorization* has since lapsed. This falls into the Critical bucket (signing a non-canonical/invalid block).

### Likelihood Explanation
This requires no majority-key compromise and no auth token — it only needs ordinary asynchronous timing between proposal validation and pre-commit-threshold crossing, combined with a legitimate protocol event (miner timeout/capitulation, or a new burn block) that is a routine, gossip-driven occurrence rather than an attacker-controlled majority action. The pre-commit round is explicitly designed to have a window ("time passes, the burn chain can fork, and another block may win the same slot") for exactly this kind of drift, which the docs acknowledge but only partially close for the tenure-tip dimension, not the miner-identity dimension.

### Recommendation
Re-run (or cheaply re-derive) the miner-identity/consensus-hash/bitvec checks from `check_proposal` — or at minimum re-verify `current_miner_pkh`/`tenure_id` against the live state machine — inside `check_block_against_signer_db_state` before a pre-commit is allowed to convert into a signature, not just the tenure-confirmation check.

### Proof of Concept
1. Miner M proposes block B for tenure T; signer S evaluates `check_proposal`, confirms `current_miner_pkh == M`, bitvec all-1s, etc.; B is marked `valid = true` and S broadcasts a pre-commit.
2. Before 70% pre-commit weight is reached (network-wide, this can take multiple seconds/minutes under normal conditions), S's local state machine capitulates away from M (e.g., inactivity timeout, or a burn-view update elects a different active miner) via the section-8 state machine described in `docs/signer-flows.md`.
3. Enough other signers' pre-commits (recorded before their own state machines updated, or on stale info) still accumulate to cross the 70% threshold for B.
4. S's `handle_block_pre_commit` re-checks only `check_block_against_signer_db_state` (tenure confirmation), which still passes since B's tenure-confirmation facts haven't changed — S signs B via `mark_locally_accepted`/`handle_block_signature` even though S's own state machine no longer considers M the active miner. [4](#0-3)

        &self,
        client: &StacksClient,
        signer_db: &mut SignerDb,
        block: &NakamotoBlock,
    ) -> Result<(), RejectReason> {
        let MinerState::ActiveMiner {
            current_miner_pkh,
            tenure_id,
            parent_tenure_id,
            ..
        } = &self.signer_state.current_miner
        else {
            info!(
                "No valid current miner. Considering invalid.";
                "block_height" => block.header.chain_length,
                "signer_signature_hash" => %block.header.signer_signature_hash()
            );
            return Err(RejectReason::InvalidMiner);
        };
        if &block.header.consensus_hash != tenure_id {
            info!("Miner block proposal consensus hash does not match the current miner's tenure id. Considering invalid.";
                "block_height" => block.header.chain_length,
                "signer_signature_hash" => %block.header.signer_signature_hash(),
                "block_consensus_hash" => %block.header.consensus_hash,
                "active_miner_tenure_id" => %tenure_id,
                "active_miner_parent_tenure_id" => %parent_tenure_id,
            );
            return Err(RejectReason::ConsensusHashMismatch {
                actual: block.header.consensus_hash.clone(),
                expected: tenure_id.clone(),
            });
        }
        let Some(miner_pk) = block.header.recover_miner_pk() else {
            warn!("Failed to recover miner pubkey";
                  "signer_signature_hash" => %block.header.signer_signature_hash(),
                  "consensus_hash" => %block.header.consensus_hash);
            return Err(RejectReason::IrrecoverablePubkeyHash);
        };
        let miner_pkh = Hash160::from_data(&miner_pk.to_bytes_compressed());
        if current_miner_pkh != &miner_pkh {
            warn!(
                "Miner block proposal pubkey does not match the winning pubkey hash for its sortition. Considering invalid.";
                "proposed_block_consensus_hash" => %block.header.consensus_hash,
                "signer_signature_hash" => %block.header.signer_signature_hash(),
                "proposed_block_pubkey" => &miner_pk.to_hex(),
                "proposed_block_pubkey_hash" => %miner_pkh,
                "active_miner_pubkey_hash" => %current_miner_pkh,
            );
            return Err(RejectReason::PubkeyHashMismatch);
        }
        let bitvec_all_1s = block.header.pox_treatment.iter().all(|entry| entry);
        if !bitvec_all_1s {
            warn!(
                "Miner block proposal has bitvec field which punishes in disagreement with signer. Considering invalid.";
                "proposed_block_consensus_hash" => %block.header.consensus_hash,
                "signer_signature_hash" => %block.header.signer_signature_hash(),
                "active_miner_consensus_hash" => ?tenure_id,
                "active_miner_parent_consensus_hash" => ?parent_tenure_id,
            );
            return Err(RejectReason::InvalidBitvec);
        }

    /// Handle pre-commit message from another signer
    fn handle_block_pre_commit(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        stacker_address: &StacksAddress,
        block_hash: &Sha512Trunc256Sum,
    ) {
        let Some(mut block_info) = self.block_lookup_by_reward_cycle(block_hash) else {
            // A pre-commit for a block we have not seen proposed yet means the proposal
            // has not reached us. Log it at INFO: it is a direct signal that our view of
            // the proposal stream is behind the rest of the signer set.
            info!("{self}: Received block pre-commit for an unknown block, storing as pending";
                "signer_address" => %stacker_address,
                "signer_signature_hash" => %block_hash,
                "signer_weight" => self.signer_weights.get(stacker_address).copied().unwrap_or(0),
            );
            if let Err(e) = self
                .signer_db
                .add_pending_block_pre_commit_response(block_hash, stacker_address)
            {
                warn!("{self}: Failed to save pending block pre-commit response: {e:?}");
            }
            return;
        };
        // Always save the pre-commit - we will need to store signer responses for determining which
        // are misbehaving, offline, etc.
        // commit message is from a valid sender! store it
        self.signer_db
            .add_block_pre_commit(block_hash, stacker_address)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block pre-commit"));

        let block_hash = block_info.block.header.signer_signature_hash();
        // do we have enough pre-commits to reach consensus?
        // i.e. is the threshold reached?
        //
        // Tally this up front, before the early returns below, so that every pre-commit we
        // receive can be logged with the running weight. Crossing this threshold is what
        // triggers our block response, so without it the wait for the threshold, which can
        // be minutes and is the bulk of a stalled block's latency, leaves no trace at all.
        let committers = self
            .signer_db
            .get_block_pre_committers(&block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block commits"));

        let commit_weight = self.compute_signature_signing_weight(committers.iter());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        info!("{self}: Received block pre-commit";
            "signer_address" => %stacker_address,
            "signer_signature_hash" => %block_hash,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "signer_weight" => self.signer_weights.get(stacker_address).copied().unwrap_or(0),
            "pre_commit_weight" => commit_weight,
            "pre_commit_weight_required" => min_weight,
            "total_weight" => total_weight,
            "pre_commit_threshold_reached" => commit_weight >= min_weight,
            "already_signed" => block_info.signed_self.is_some(),
        );

        if block_info.signed_self.is_some() {
            debug!(
                "{self}: Received pre-commit for a block that we have already signed. Doing nothing...",
            );
            return;
        }

        if !block_info.valid.unwrap_or(false) {
            // We received a pre-commit for a block that we have not validated or we have already marked this block as invalid.
            // We should not do anything further as we do not know what our response should be and we do not change our votes on rejected
            // blocks unless we receive a new block proposal for it and the reject reason allows us to reconsider.
            debug!(
                "{self}: Received a pre-commit for a block that we have not determined to be valid: {:?}. Doing nothing...", block_info.valid
            );
            return;
        }

        if min_weight > commit_weight {
            debug!(
                "{self}: Not enough pre-committed to block {block_hash} (have {commit_weight}, need at least {min_weight}/{total_weight})"
            );
            return;
        }

        // The chain and signer db state may have changed materially since this block passed the
        // proposal-time checks (e.g. between validation and reaching the pre-commit threshold we
        // may have signed a block that this one would reorg). Re-run the chainstate checks
        // before putting a signature over the block, and respond with a rejection if they no
        // longer pass, just as the block validation response handler does.
        if let Some(block_rejection) =
            self.check_block_against_signer_db_state(stacks_client, &block_info.block)
        {
            warn!(
                "{self}: Reached the pre-commit threshold for a block, but it no longer passes the chainstate checks. Rejecting.";
                "signer_signature_hash" => %block_hash,
                "block_height" => block_info.block.header.chain_length,
                "reject_code" => %block_rejection.reason_code,
                "reject_reason" => &block_rejection.reason,
            );
            if let Err(e) = block_info.mark_locally_rejected() {
                if !block_info.has_reached_consensus() {
                    warn!("{self}: Failed to mark block as locally rejected: {e:?}");
                }
            };
            self.signer_db
                .insert_block(&block_info)
                .unwrap_or_else(|e| self.handle_insert_block_error(e));
            self.handle_block_rejection(&block_rejection, sortition_state);
            self.send_block_response(&block_info.block, block_rejection.into());
            return;
        }
