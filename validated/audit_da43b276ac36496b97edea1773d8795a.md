### Title
Unauthenticated flooding of `HandleLegacyUserMessage` evicts legitimate subscribers' pending callbacks via `pruneCallbacks` size-based eviction - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` accepts any message with a valid self-generated signature and no allowlist/rate-limit check (explicitly deferred by a `TODO`), inserting an entry into the shared `h.savedCallbacks` map keyed only by `messageId`. `pruneCallbacks` evicts the oldest half of all entries by `createdAt` once the map exceeds `MaxSavedCallbacks`, regardless of which sender created them, so a high-volume attacker can force eviction of a legitimate, still-pending subscriber's callback before the DON responds.

### Finding Description
`gateway.ProcessRequest` routes any legacy-format signed message straight into `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `HandleLegacyUserMessage` only validates payload decoding, timestamp freshness, and message signature via `common.ValidatedRequestFromMessage`/`msg.Validate()`; it does not check sender identity against any allowlist or apply per-sender rate limiting, as explicitly marked by `// TODO: apply allowlist and rate-limiting here` [2](#0-1) . Any party can generate their own ECDSA keypair, sign a message, and pass `msg.Validate()` — there is no requirement that the sender be a known/authorized user. Each accepted message is stored in the shared `h.savedCallbacks` map keyed only by `msg.Body.MessageId`, with no per-sender partitioning: [3](#0-2) .

The background pruning loop (`pruneCallbacks`, run every `CallbackPruneIntervalSec`) first removes expired entries, then, if the map still exceeds `MaxSavedCallbacks`, sorts *all* remaining entries by `createdAt` and deletes the oldest half regardless of owner: [4](#0-3) . Once a victim's entry is deleted, the DON's eventual response in `handleWebAPITriggerMessage` will find `found == false` and silently drop the response [5](#0-4) , leaving the victim's `callback.Wait(ctx)` in `gateway.ProcessRequest` to time out and return a `handler timeout` error instead of the real result [6](#0-5) .

The only rate limiter present in this handler (`h.nodeRateLimiter`) is applied to DON *node* addresses in `handleWebAPIOutgoingMessage`, not to inbound user messages via `HandleLegacyUserMessage` [7](#0-6) , confirming there is no throttling for the exploited path.

### Impact Explanation
This is a denial-of-service against a legitimate subscriber's request/response delivery and a violation of per-user callback isolation: an unauthenticated flood of self-signed messages can cause a legitimate, earlier-submitted, still-pending callback to be silently discarded before its DON response arrives, so the victim receives a timeout error instead of their actual result. This matches the "unauthorized action on/interference with another user's request/response state" and availability-impact classes rather than fund loss or key disclosure.

### Likelihood Explanation
The precondition is generating enough traffic (self-signed, valid-format, non-expired) requests to push `len(h.savedCallbacks)` above `MaxSavedCallbacks` (default 20000) within the `CallbackMaxAgeSec` window (default 120s) before the next `pruneCallbacks` tick (`CallbackPruneIntervalSec`, default 30s). No credentials, allowlist membership, or prior authorization are required — only the ability to construct a validly-signed `api.Message` and reach the gateway's `ProcessRequest` endpoint, which is explicitly documented as missing allowlist/rate-limit protection. Feasibility depends on deployment volume thresholds (20000 default is nontrivial but reachable by a scripted flood without per-sender throttling to stop it), and the attack is repeatable at will.

### Recommendation
Implement the allowlist and rate-limiting called out in the `TODO` at `core/services/gateway/handlers/capabilities/handler.go:384` before accepting a message into `savedCallbacks` (e.g., verify sender against `donConfig` allowlist and apply a per-sender/per-key rate limiter similar to `nodeRateLimiter`). Additionally, consider partitioning or capping `savedCallbacks` per sender so that eviction pressure from one sender cannot affect another sender's pending callbacks, and/or reject new inserts (instead of evicting oldest) once `MaxSavedCallbacks` is reached, returning a backpressure error to the caller.

### Proof of Concept
1. In `core/services/gateway/handlers/capabilities/handler_test.go`, build on `setupHandler`/`triggerRequest` helpers.
2. Configure `HandlerConfig.MaxSavedCallbacks` to a small test value (e.g., 4) via `NewHandler`.
3. Directly populate `handler.savedCallbacks` (or call `HandleLegacyUserMessage` repeatedly with distinct valid signed messages from an arbitrary victim key) with `MaxSavedCallbacks - 1` entries, recording the victim's earliest `messageId` and `createdAt`.
4. Call `HandleLegacyUserMessage` two more times using distinct attacker-generated keys to push the map size above `MaxSavedCallbacks`.
5. Invoke `handler.pruneCallbacks()` directly.
6. Assert that the victim's earlier `messageId` entry has been deleted from `handler.savedCallbacks` even though it had not expired (`createdAt` within `CallbackMaxAgeSec`), demonstrating that attacker-submitted entries with no allowlist gate can evict a legitimate pending subscriber's callback.
7. Additionally simulate the DON response for the victim's `messageId` via `handler.HandleNodeMessage` and assert the corresponding callback never receives a response (i.e., `found == false` path in `handleWebAPITriggerMessage`), confirming denial of delivery.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}
