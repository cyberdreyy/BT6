### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing execution below the required K-of-N - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm` in `multisig2/src/lib.rs` counts a request as approved once `confirmations.len() + 1 >= self.num_confirmations`, using the `confirmations` `HashSet<String>` that was recorded against the request. `DeleteMember` (executed via `delete_member`) only purges requests and confirmation sets that were *originated* by the removed member; it never scans other pending requests' `confirmations` sets to strip out that member's votes. Consequently a member who is later removed from the multisig can still have their earlier confirmation counted toward the threshold on a request that another (still-active) member originated, letting the request execute with fewer than `num_confirmations` *live* member approvals.

### Finding Description
The confirmation-count binding the contract is supposed to enforce is:
`confirmations_counted_towards_threshold == confirmations_from_current_live_members`

`confirm()` never re-validates that every entry in `confirmations` corresponds to a currently active member; it simply trusts the stored set size: [1](#0-0) 

`delete_member()` only cleans up requests whose `member` field (the request *originator*) equals the removed member — it does not walk `self.confirmations` to strip votes cast by that member on requests originated by someone else: [2](#0-1) 

`add_request()` stores an empty `confirmations` set per request and `confirm()` inserts the confirming member's serialized identity (`member.to_string()`) into it: [3](#0-2) [4](#0-3) 

Because `MultisigMember` is compared/serialized by public key or account id (`to_string()`), and `current_member()` at confirm-time only checks whether the *current caller* is a live member (not whether stored confirmations remain valid), a confirmation recorded while a member was active remains valid forever unless the specific request that member itself created is deleted: [5](#0-4) [6](#0-5) 

### Impact Explanation
This breaks the K-of-N custody guarantee documented for the multisig: "Any of the access keys or set of specified accounts can confirm, until the required number of confirmation achieved" (`multisig2/README.md:6-14`). If a member is removed (e.g., because their key was compromised or they are no longer trusted), any confirmation they cast on a still-pending request created by a different member remains counted. A request can then execute (including `Transfer`, `FunctionCall`, `AddKey`, `DeployContract`) with fewer than `num_confirmations` *currently authorized* signers — i.e., "a multisig request executed below threshold," which is explicitly a Critical-impact outcome for custody of the account's NEAR balance and key set.

### Likelihood Explanation
This requires no privileged access beyond being (at some point) one of the K members — a scenario the contract itself is designed to defend against (member removal exists specifically to revoke a member's authority, e.g., after compromise). The bug is triggered by ordinary contract usage: create a request, get confirmed by a member who is later removed, then have remaining members confirm — no attacker-controlled deployment, redeploy, or foundation privilege is needed, only the normal `add_request`/`confirm`/`DeleteMember` flow that any multisig operator would use.

### Recommendation
When counting confirmations in `confirm()`, filter the stored confirmation set to only those entries that are still present in `self.members` before comparing against `num_confirmations`, and/or when removing a member in `delete_member()`, iterate all pending requests' confirmation sets and remove any entry matching the removed member (not just requests originated by that member).

### Proof of Concept
1. Initialize `MultiSigContract::new([A, B, C, D], 3)`.
2. `A` calls `add_request` creating request `R` (e.g., `Transfer` to some receiver) — `confirmations[R] = {}`.
3. `D` calls `confirm(R)` — `confirmations[R] = {D}` (len=1 < 3, not executed).
4. Members execute a separate 3-of-4 confirmed `DeleteMember{member: D}` request; `delete_member` removes `D` from `self.members` and deletes any requests *originated* by `D`, but `R` was originated by `A`, so `confirmations[R]` still contains `D`.
5. `A` calls `confirm(R)` — `confirmations[R] = {D, A}` (len=2 < 3, not executed).
6. `B` calls `confirm(R)` — `confirmations[R] = {D, A, B}` (len=3 ≥ `num_confirmations`=3) → `execute_request(R)` runs, per `confirm()`'s check at [7](#0-6) , even though only `A` and `B` — two live members — actually approved it after `D`'s removal.

        self.confirmations

    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
