## Analysis

`ArtifactFormat` is a job-controlled field (`Artifact.Format json:"artifact_format"`), and `ArtifactFormatRaw = "raw"` is an accepted value, so a pipeline author who sets `artifacts:reports` or otherwise controls the artifact/cache `Format` field can reach `ArtifactsUploaderCommand.createBodyProvider` / `CacheArchiverCommand.createZipFile` with `format = raw`, which calls `archive.NewArchiver(archive.Raw, ...)` and then `archiver.Archive`. [1](#0-0) [2](#0-1) [3](#0-2) 

The `fileArchiver.process`/`findRelativePathInProject` containment check only validates that the *literal path string* of the matched file/symlink resolves (via `filepath.Abs`+`filepath.Rel`, no symlink resolution) to a location under `c.wd`. It never resolves symlink targets, and `add()` uses `os.Lstat` (which doesn't follow the link) to store the entry. [4](#0-3) [5](#0-4) [6](#0-5) 

So an attacker can commit a symlink inside their own project working directory (e.g. `payload -> /etc/shadow` or any absolute/relative target outside `c.wd`) and reference it via `--path`. This symlink passes the containment check (its own location is inside `c.wd`) and gets added to `c.files`.

The raw archiver's `Archive` then does `os.Open(pathname)` on every map key with **no path validation, no dir-prefix check, no symlink-mode check** at all: [7](#0-6) 

`os.Open` follows symlinks by default (standard `open(2)` behavior), so if `pathname` is a symlink pointing outside `dir`, its target's contents get copied into the artifact/cache stream. This directly contradicts the documented invariant on `archive.NewArchiver`: "The archiver will ensure that files to be archived are children of the directory provided." [8](#0-7) 

By contrast, the `tarzstd` archiver explicitly guards against this: it checks `fi.Mode()&os.ModeSymlink`, only reads the link target string via `os.Readlink` for the tar header (does not dereference for content), and only calls `os.Open` when `fi.Mode().IsRegular()` is true — symlinks are skipped for content copying. [9](#0-8) 

The raw archiver has none of these protections. Since raw format only supports a single file (`ErrTooManyRawFiles` if `len(files) > 1`), and since `fileArchiver.processPath`'s glob is `doublestar.WithNoFollow()` only for the initial glob expansion (preventing symlink loops during walk, not preventing following a single terminal symlink target when opened later), a single symlink path in `Paths` is sufficient to trigger this.

The resulting artifact/cache blob (embedding host file content, e.g. runner host secrets, other mounted volumes, or files reachable from the executor's filesystem view) is then uploaded and can later be downloaded by anyone with read access to that job's artifacts/cache — a genuine cross-boundary content leak via a documented-but-unenforced invariant.

### Title
Raw archiver dereferences symlinks without directory containment check, allowing host file exfiltration via artifacts/cache - (File: commands/helpers/archive/raw/raw_archiver.go)

### Summary
`raw.archiver.Archive` calls `os.Open(pathname)` on file map keys without verifying the path (or its symlink target) is contained within the archiver's `dir`, unlike the `tarzstd` archiver which explicitly skips symlink dereferencing. A pipeline author can commit a symlink inside their working directory pointing to a file outside it and reference it via `--path`/`artifacts:paths` with `artifact-format: raw`, causing the target file's content to be embedded into the uploaded artifact/cache blob.

### Finding Description
`fileArchiver.process` (commands/helpers/file_archiver.go:65-101) and `findRelativePathInProject` (lines 191-222) only validate the string path of the matched entry relative to `c.wd`; they never call `filepath.EvalSymlinks` or otherwise resolve where a symlink points. `add()` (lines 127-138) stores the entry via `os.Lstat`, which describes the symlink itself, not its target, so a symlink whose *location* is inside `c.wd` but whose *target* is outside passes containment checks and is added to `c.files`. When `--artifact-format raw` (or cache `--compression-format` selecting raw, if exposed) is used, `archive.NewArchiver(archive.Raw, ...)` returns the raw archiver, and `archiver.Archive` (commands/helpers/archive/raw/raw_archiver.go:35-52) iterates `files` and does `os.Open(pathname)` directly — `os.Open` follows symlinks by OS-level default, so it opens and copies the *target* file's contents, regardless of location. No dir-prefix check, no `os.Lstat`/`ModeSymlink` check, and no `filepath.EvalSymlinks` validation exist in this function, unlike `tarzstd_archiver.go` which explicitly checks `fi.Mode()&os.ModeSymlink` and only opens regular files for content copying (lines 62-120 of tarzstd_archiver.go). This breaks the documented invariant in `archive.NewArchiver` ("files to be archived are children of the directory provided").

### Impact Explanation
An attacker-controlled job can cause the runner process to read and embed the contents of any file readable by the runner/job process (subject to executor sandboxing, e.g. files inside a Docker container's filesystem, or on shell executors, files on the host readable by the job user) into an artifact or cache object. That artifact/cache is stored under the job's/project's namespace and can be downloaded later (by the same or, in dependency/cache-sharing scenarios, related jobs), constituting unauthorized disclosure of files outside the intended build/cache/artifact root — matching the scoped impact of artifact/cache exfiltration.

### Likelihood Explanation
Preconditions are fully attacker-controlled and require no special privilege: the job author only needs to (1) commit a symlink file in the repository pointing to a target outside the checkout directory, and (2) request `artifact-format: raw` (or the raw cache compression path if reachable) with `--path` referencing that symlink. This is fully repeatable and requires no timing races, no admin misconfiguration, and no external compromise — a standard CI job definition is sufficient.

### Recommendation
In `raw.archiver.Archive` (and generally in the shared archiving path), before calling `os.Open(pathname)`:
1. Resolve the real path via `filepath.EvalSymlinks(pathname)` (or check `os.Lstat` mode for `os.ModeSymlink` and reject/skip such entries, mirroring `tarzstd`'s behavior).
2. Verify the resolved absolute path has `a.dir` as a strict prefix (as `tarzstd_archiver.go` does with `strings.HasPrefix(path, a.dir+string(filepath.Separator))`), returning an error such as "cannot be archived from outside of chroot" otherwise.
Apply the same fix uniformly to `gziplegacy`/`ziplegacy` archivers if they also lack this check, since they likewise call into archive-content-writing paths without dir validation.

```go
func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

	if err == nil {
		// Process path only if it lives in our build directory
		if !strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			excluded, rule := c.isExcluded(relative)
			if excluded {
				c.exclude(rule)
				return false
			}

			err = c.add(relative)
		} else {
			err = errors.New("not supported: outside build directory")
		}
	}

	if err == nil {
		return true
	}

	if os.IsNotExist(err) {
		// We hide the error that file doesn't exist
		return false
	}

	logrus.Warningf("%s: %v", match, err)
	return false
}
```

```go
func (c *fileArchiver) findRelativePathInProject(path string) (string, error) {
	slashPath := filepath.ToSlash(path)
	if filepath.Clean(slashPath) == filepath.Clean(c.wd) {
		return ".", nil
	}

	base, patt := slashPath, ""
	// check if path contains a glob pattern
	if strings.ContainsAny(slashPath, "*?[{") {
		base, patt = doublestar.SplitPattern(slashPath)
	}

	abs, err := filepath.Abs(base)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact absolute path %s: %w", path, err)
	}

	rel, err := filepath.Rel(c.wd, abs)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact relative path %s: %w", path, err)
	}

	// If fully resolved relative path begins with ".." it is not a subpath of our working directory
	if strings.HasPrefix(rel, ".."+string(filepath.Separator)) || rel == ".." {
		return "", fmt.Errorf("artifact path is not a subpath of project directory: %s", path)
	}

	// Relative path is needed now that our fsys "root" is at the working directory
	rel = filepath.Join(rel, patt)
	rel = filepath.FromSlash(rel)
	return rel, nil
}
```
