### Title
Stale confirmations from removed multisig members are still counted toward execution threshold - (File: `multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
`MultiSigContract::confirm` executes a pending request once `confirmations.len() + 1 >= num_confirmations`, but the `confirmations` set for a request is only pruned when the request itself is deleted, confirmed to completion, or *authored* by the member being removed. `delete_member` (`multisig2/src/lib.rs#L356-379`) and `DeleteKey`/legacy equivalent (`multisig/src/lib.rs#L198-216`) never sweep the `confirmations` map of *other* pending requests to remove entries belonging to the member/key being deleted.

### Finding Description
The intended custody binding is: `confirmations counted == confirmations from currently-authorized members`. In practice, once a member confirms a pending request (`multisig2/src/lib.rs#L294-315`, adding their id to the `HashSet<String>` stored in `self.confirmations`), that entry persists indefinitely regardless of subsequent membership changes. If that member is later removed via `DeleteMember` (`multisig2/src/lib.rs#L239-242`, `delete_member` at `L356-379`), the removal logic only inspects `self.requests` for entries where `r.member == member` (i.e., requests *they created*) and clears confirmations only for those. Any other pending request that this member had *confirmed* (but did not create) keeps that stale confirmation in its `HashSet`, and it is never revisited. `assert_valid_request` (`multisig2/src/lib.rs#L406-423`) and `confirm` never re-check that each string/pubkey recorded in the `confirmations` set is still `self.members.contains(...)`. Consequently the tally in `confirm` conflates a historical, now-revoked signature with a live one, so `num_confirmations` (e.g. 3-of-4) can be satisfied by only `num_confirmations - 1` currently authorized signers plus one stale signature from someone who has since been removed.

### Impact Explanation
This directly matches the Critical-impact category "a multisig request executed below threshold." A `Transfer`, `AddKey`/`AddMember`, `FunctionCall`, or `DeployContract` action (`execute_request`, `multisig2/src/lib.rs#L224-290`) can be dispatched with fewer genuinely-current approvals than the multisig's configured `num_confirmations`, breaking the fundamental M-of-N custody guarantee that governs funds and access held by the contract.

### Likelihood Explanation
No special privilege beyond being a member (at the time of confirming) is required by the party whose confirmation becomes stale; the only precondition is that the member set changes (a `DeleteMember`/`DeleteKey` request executes) while a confirmation they already gave to a different, still-pending request remains outstanding — a routine sequence of unrelated multisig operations (key rotation, offboarding a signer) rather than an edge case requiring collusion, timing tricks, or contract misconfiguration.

### Recommendation
When a member is removed (`delete_member` / `DeleteKey` handling), iterate all entries in `self.confirmations` (not just requests they authored) and strip the removed member's identity from every set; alternatively, revalidate every confirmer against `self.members` at the point `confirm` tallies the count, discarding stale confirmations before comparing against `num_confirmations`.

### Proof of Concept
1. Multisig deployed with 4 members `[A, B, C, D]` and `num_confirmations = 3`.
2. Member `D` calls `add_request` to create Request `R1` (e.g. a `Transfer`), then `D` also calls `confirm(R1)` — `confirmations[R1] = {D}` (1/3).
3. Separately, members create and confirm a `DeleteMember { member: D }` request (`R2`), which reaches 3 confirmations and executes via `delete_member`, removing `D` from `self.members`. Because `R1.member == A` (its creator) `!= D`, `delete_member`'s cleanup loop does not touch `R1`, so `confirmations[R1]` still contains `D`.
4. Members `B` and `C` each call `confirm(R1)`. `confirmations.len()` becomes `{D, B, C}.len() == 3 >= num_confirmations`, so `execute_request` fires `R1`'s `Transfer`, even though only `B` and `C` are currently live members who approved it — one short of the intended 3 live signers.     /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
