### Title
Multisig `DeleteMember` does not purge that member's confirmations from other members' outstanding requests, allowing execution below threshold - ([File: multisig2/src/lib.rs])

### Summary
When a multisig member is removed via `DeleteMember`, the contract only deletes the *requests originated by* that member; it never scrubs that member's confirmation entries from *other* still-outstanding requests that the removed member had previously confirmed as a co-signer. A stale confirmation from a now-deleted member therefore keeps counting toward `num_confirmations`, letting a request execute with fewer *live* members' approvals than the configured threshold.

### Finding Description
`confirm()` in `multisig2/src/lib.rs` decides whether to execute a request purely by comparing the size of the stored `confirmations` set (plus the new confirmer) against `self.num_confirmations`: [1](#0-0) 

`delete_member()` — invoked from `execute_request` for the `DeleteMember` action — only removes requests whose `r.member == member` (i.e., requests *created by* the member being deleted). It clears `num_requests_pk` and the members set, but does not iterate over `self.confirmations` to strip the deleted member's entry from confirmation sets belonging to requests created by *other* members: [2](#0-1) 

The `add_request_and_confirm` / `confirm` flow allows any member to confirm a request created by someone else, storing the confirming member's identity in the `confirmations` map keyed by `request_id`: [3](#0-2) [1](#0-0) 

The equality that should hold is: `live members who approved a request` == `confirmations.len()` counted toward threshold. Because `delete_member` never audits other requests' confirmation sets, a removed member's stale confirmation remains in the set, breaking that equality — `confirmations.len()` can include accounts that are no longer members.

The same code‑shape flaw (and its guard) exists in the legacy `multisig/src/lib.rs`: [4](#0-3) 

### Impact Explanation
This lets a `MultiSigRequest` (e.g. `Transfer`, `FunctionCall`, `AddKey`) be executed with fewer than `num_confirmations` *currently valid* members approving it, because a stale confirmation from a deleted member is still tallied. This matches the "multisig request executed below threshold" Critical impact criterion — it can result in NEAR being moved, or privileged actions (adding a full-access key, deploying a contract) taken, without the intended threshold of live signers agreeing.

### Likelihood Explanation
This requires a specific but realistic sequence: (1) member A confirms an outstanding request originated by member B (but insufficient confirmations to execute yet), (2) member A is later removed via a separate `DeleteMember` request, (3) subsequently another live member confirms B's request, reaching the threshold count using A's stale confirmation as one of the votes. This is plausible in normal multisig lifecycle management (rotating/removing signers) and doesn't require any privileged attacker capability beyond being one of the remaining members — a set of malicious-but-legitimate co-signers colluding could deliberately engineer this to execute a request with one fewer live approver than intended.

### Recommendation
When executing `DeleteMember`, iterate all entries in `self.confirmations` and remove the deleted member's key/entry from every confirmation set (not just requests they originated), or alternatively re-validate at `confirm()`/execution time that every account/key in a request's `confirmations` set is still a current member before counting it toward `num_confirmations`.

### Proof of Concept
1. Multisig deployed with 3 members {A, B, C}, `num_confirmations = 2`.
2. Member B creates `add_request` R1 (e.g., `Transfer`) — 0 confirmations.
3. Member A calls `confirm(R1)` — confirmations = {A}, 1 < 2, not executed.
4. Members B and C create and confirm a `DeleteMember { member: A }` request (2 confirmations reached) — A is removed from `self.members`; only requests where `r.member == A` are purged; R1 (owned by B) is untouched and still has A in `confirmations`.
5. Member C calls `confirm(R1)` — `confirmations.len() (1, containing stale A) + 1 >= 2` → request executes, even though only B (creator, implicit) and C are live members explicitly confirming; A's vote should no longer count. [1](#0-0) [2](#0-1)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
