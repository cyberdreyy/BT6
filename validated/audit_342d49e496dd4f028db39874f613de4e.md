### Title
Zip-slip: `ExtractZipArchive`/`processZipExtra` write/modify files using unsanitized `file.Name`, allowing cache archive path traversal outside destination root - ([File: helpers/archives/zip_extract.go, helpers/archives/zip_extra.go])

### Summary
`ExtractZipArchive` (helpers/archives/zip_extract.go) and the extra-field processor `processZipExtra` (helpers/archives/zip_extra.go) both operate directly on `zip.File.Name`/`zip.FileHeader.Name` without ever validating that the resolved path stays inside the intended extraction root. The only path check present anywhere in the pipeline is `errorIfGitDirectory`, which only rejects `.git` paths, not `../` traversal. Because this code is reachable from cache restore (`commands/helpers/cache_extractor.go` → `archive.NewExtractor` → `ziplegacy.extractor.Extract` → `archives.ExtractZipArchive`), a crafted (hand-built, not `createZipExtra`-produced) cache zip with traversal entries can write, chmod, chown, or chtime files outside the cache directory.

### Finding Description
`ExtractZipArchive` iterates `archive.File` twice [1](#0-0) . The first loop only guards against `.git` paths via `errorIfGitDirectory` and then calls `extractZipFile(file)`, which uses `file.Name` verbatim for `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Symlink`, and `os.Mkdir` [2](#0-1) . There is no `filepath.Clean`/`filepath.Rel`/prefix check anywhere confirming the resulting absolute path is still under the destination directory — this is the classic "zip slip" flaw.

The second loop calls `lchmod(file.Name, ...)` and `processZipExtra(&file.FileHeader)` for every entry [3](#0-2) . `processZipExtra` parses attacker-controlled `Extra` field bytes and, for recognized field types, calls `processZipUIDGidField` (chown-equivalent) and `processZipTimestampField`, which calls `os.Chtimes(file.Name, ...)` directly — again with no path confinement check [4](#0-3) [5](#0-4) . Since the extra-field data is fully attacker-supplied (it's just bytes read straight out of the zip header, not verified against `createZipExtra`'s output format), the attacker controls the metadata operations applied to whatever path `file.Name` resolves to.

Reachability: `CacheExtractorCommand.Execute` downloads/opens a cache archive and constructs an extractor bound to the working directory, then calls `Extract` [6](#0-5) . For zip format, `ziplegacy.NewExtractor` stores `dir` but its `Extract` method never uses `e.dir` at all — it just calls `archives.ExtractZipArchive(zr)` directly on the raw reader [7](#0-6) . Confinement to the cache directory therefore depends entirely on the process's current working directory and on `file.Name` never containing `../` or an absolute path — a property that is never validated in this code path.

No existing check stops this: `errorIfGitDirectory` only matches `.git`, and `pathErrorTracker` only deduplicates *log output* for repeated PathError ops, it performs no security enforcement [8](#0-7) .

### Impact Explanation
An attacker who can poison a project's cache object (e.g. by controlling a shared cache key, or via any path that lets them write/replace the cache archive fetched by `CacheExtractorCommand`) can supply a hand-crafted zip containing entries like `../../../../home/user/.ssh/authorized_keys` or absolute paths, plus attacker-chosen `Extra` field bytes. When a subsequent job (potentially a different, more privileged pipeline run) restores that cache, `ExtractZipArchive`/`processZipExtra` will create/overwrite files and alter their mode/owner/mtime outside the designated cache directory on the runner's build host/executor filesystem, violating the "file operations must stay within intended build/cache/artifact roots" invariant. Repeated pipeline runs will repeatedly re-apply this out-of-root write/chown/chtimes, so the effect is not confined to a single job.

### Likelihood Explanation
Preconditions: attacker must be able to get a maliciously-crafted zip byte stream into the extraction path used for cache restore (e.g., control over a cache key/name/URL reachable from `.gitlab-ci.yml`, or ability to overwrite the object referenced there). This is plausible for scenarios such as shared/branch-based cache keys, or cache paths derived from job-controlled variables, which is within the threat model of "a normal GitLab user or pipeline author controlling job inputs accepted by Runner." Once that precondition holds, the exploit is fully deterministic and repeatable — it is a standard, well-known zip-slip pattern with no mitigating check anywhere in `ExtractZipArchive`, `extractZipFile`, or `processZipExtra`.

### Recommendation
Before any extraction or extra-field processing in `ExtractZipArchive`, resolve each `file.Name` against the destination root (e.g. `filepath.Join(destRoot, file.Name)`, then `filepath.Clean` and verify via `filepath.Rel`/prefix check that it does not escape `destRoot`), rejecting or skipping entries that resolve outside the root — mirroring the existing `errorIfGitDirectory` pattern but for path traversal/absolute paths. This check must run for every use of `file.Name`, including the `lchmod` and `processZipExtra` (chtimes/chown) calls in the second loop, not just the initial extraction loop. Additionally, `ziplegacy.extractor.Extract` should actually use `e.dir` to compute and validate destination paths rather than silently relying on process cwd.

### Proof of Concept
```go
// helpers/archives/zip_extract_test.go (new test)
func TestExtractZipArchive_RejectsPathTraversal(t *testing.T) {
    outDir := t.TempDir()
    victimFile := filepath.Join(filepath.Dir(outDir), "victim.txt")
    defer os.Remove(victimFile)

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../victim.txt")
    w.Write([]byte("pwned"))
    zw.Close()

    origWd, _ := os.Getwd()
    os.Chdir(outDir)
    defer os.Chdir(origWd)

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    err = ExtractZipArchive(zr)

    // Expected (fixed) behavior: extraction must fail or skip the entry,
    // and victim.txt must NOT exist outside outDir.
    _, statErr := os.Stat(victimFile)
    assert.True(t, os.IsNotExist(statErr), "zip-slip entry escaped destination root")
}
```
Expected current (vulnerable) result: `victimFile` is created outside `outDir`, proving the traversal succeeds; after the fix, the file must not exist and/or `ExtractZipArchive` must return an actionable error for the offending entry.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}

func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}

func processZipExtra(file *zip.FileHeader) error {
	if len(file.Extra) == 0 {
		return nil
	}

	r := bytes.NewReader(file.Extra)
	for {
		field, data, err := readZipExtraField(r)
		if err == io.EOF {
			break
		} else if err != nil {
			return err
		}

		switch field.Type {
		case ZipUIDGidFieldType:
			err = processZipUIDGidField(data, file)
		case ZipTimestampFieldType:
			err = processZipTimestampField(data, file)
		}
		if err != nil {
			return err
		}
	}

	return nil
}

func (p *pathErrorTracker) actionable(e error) bool {
	pathErr, isPathErr := e.(*os.PathError)
	if e == nil || isPathErr && pathErr == nil {
		return false
	}

	if !isPathErr {
		return true
	}

	p.lock.Lock()
	defer p.lock.Unlock()

	seen := p.seenOps[pathErr.Op]
	p.seenOps[pathErr.Op] = true

	// actionable if *not* seen before
	return !seen
}
