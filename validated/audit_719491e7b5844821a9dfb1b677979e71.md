## Analysis

This maps directly onto the same bug class as the reported Go `crypto/x509` `HostnameError.Error()` issue: a malicious, ABI-well-formed-but-crafted input forces the node to pay disproportionate (superlinear) CPU/allocation cost while constructing a diagnostic/error value, and this cost is paid *before* any authorization/role check — reachable by any unprivileged precompile caller via a single transaction.

### Title
Unbounded/superlinear resource consumption when decoding a malformed, alias-amplified `announce` calldata on the live B-20 Asset precompile (V1/Beryl) - (File: crates/common/precompiles/src/b20_asset/dispatch.rs)

### Summary
The B-20 Asset precompile's `route` dispatcher has a fast, bounded decode path for `announce(bytes[],string,string,string)` that avoids materializing aliased `bytes[]` entries. But for the currently *live* wire surface (`AssetVersion::V1`, activated at the Beryl fork), that fast path deliberately bails out (`decode_if_announce` returns `None`) whenever the payload fails `valid_token` (e.g. non-UTF-8 in `id`/`description`/`uri`), explicitly to preserve "consensus-frozen" revert bytes. Execution then falls through to the generic, owned ABI decoder, which the code's own comments describe as paying "the owned decoder's diagnostic, however expensive" with a cost documented as `O(aliases · tail_bytes)`.

### Finding Description
`BaseAsset::route` tries the cheap, borrow-only fast path first: [1](#0-0) 

The fast path, `DecodedAnnounce::decode_if_announce`, explicitly special-cases V1: when the aliased/malformed payload fails `valid_token`, V1 returns `None` (fall through) instead of a cheap bounded error, "however expensive" the resulting owned diagnostic construction is: [2](#0-1) 

The fall-through path calls `version.abi().decode(calldata)` — the generic, *owned* decode that must fully materialize every aliased `bytes[]` element (copy the shared tail blob once per offset) before it can build the ABI-diagnostic error string, exactly the amplification the borrowed fast path exists to avoid, as documented on the test helper that constructs this exact payload shape: [3](#0-2) 

The golden test for V1 pins this behavior as intentional and permanent: V1 "must keep falling through to the owned decoder's diagnostic, unchanged": [4](#0-3) 

The V2 (Cobalt) golden test confirms the fix exists but is explicitly *not* live yet, and only applies to a version the repo comments describe as "not scheduled on any network yet": [5](#0-4) 

Critically, this expensive decode-time path is reached in `route` *before* any role/permission check — `begin_announce`'s `OPERATOR_ROLE` gate only runs after a successful decode, inside `run_announce`. A caller holding no role at all can send calldata with the `announce` selector, structurally valid but with a poisoned (non-UTF-8) string and a large number of aliased `bytes[]` offsets pointing at one shared tail blob, and the node will still perform the full `O(aliases · tail_bytes)` amplification work while producing the `AbiDecodeFailed` error, purely from `route`'s unconditional call into `version.abi().decode(calldata)`.

### Impact Explanation
Every node that executes or even validates such a transaction (block execution, and potentially txpool call-simulation) must materialize `aliases × tail_bytes` worth of heap allocation and copying merely to build an error string that is then discarded — the attacker pays gas proportional to calldata size (bounded by the transaction's ABI encoding, which stays small because offsets alias one shared blob), while the node pays cost proportional to the *decoded* (amplified) size. This is the same gas/computation-cost mismatch class as the reported Go CVE (attacker-controlled input driving disproportionate CPU work in error-path string/diagnostic construction), and because it is reachable pre-authorization on every full node processing/re-executing the block, it can be used to degrade block-processing throughput — a resource-exhaustion vector against node availability.

### Likelihood Explanation
High for any attacker: the payload construction is deterministic and cheap to build (as demonstrated by the repo's own `aliased_announce_calldata` test helper), requires no role/permission, and the vulnerable path is explicitly and permanently preserved at the live V1/Beryl fork by design (per the code comments, "V1/Beryl can't take that path... falls through too, with today's error bytes" — i.e., this is accepted as permanent, not transitional).

### Recommendation
This is an ask-only analysis; no plan is provided. Conceptually, the fix already exists for V2/Cobalt (`decode_if_announce` short-circuiting with a bounded `AbiDecodeFailed`); the same bounded-cost rejection needs to be applied at the live V1 surface, or the expensive owned-diagnostic decode needs to be bypassed/bounded (e.g., cap the number of `bytes[]` elements/aliasing degree examined before constructing the diagnostic) without altering the byte-for-byte frozen revert payload that V1 must preserve for already-decided calldata.

### Proof of Concept
Using the repo's own test helper `aliased_announce_calldata(n, tail)` (crates/common/precompiles/src/b20_asset/dispatch.rs, lines 968-1026) as a blueprint: construct `announce` calldata with a large `n` (e.g. thousands) of `bytes[]` offsets all aliasing one shared tail blob, then corrupt the `id` string bytes to invalid UTF-8 (as done in `golden_announce_malformed_id_stays_on_owned_diagnostic_at_v1`, crates/common/precompiles/tests/b20_asset_v1_golden.rs, lines 2356-2379). Submit this calldata as `announce` from any address (no `OPERATOR_ROLE` required) to a V1/Beryl `B20Asset` token. `route` falls through past the fast path (`decode_if_announce` returns `None` for V1) into the generic owned decode, which the maintainers' own comments document as paying `O(aliases · tail_bytes)` cost purely to build the rejected diagnostic.

    /// - `Some(Err(_))`: `valid_token` rejects the payload. V1 (Beryl) returns `None` here
    ///   instead: a cheap rejection would change consensus-frozen revert bytes, so it falls
    ///   through to the same expensive owned diagnostic it always has. V2 (Cobalt, not live on
    ///   any network) returns the bounded rejection directly, skipping that diagnostic's
    ///   O(aliases · `tail_bytes`) cost (Cantina #16 follow-up).
    ///
    /// `valid_selector` future-proofs a fork that drops `announce`.
    fn decode_if_announce(
        calldata: &'a [u8],
        version: AssetVersion,
    ) -> Option<Result<Self, BasePrecompileError>> {
        let selector = calldata.first_chunk::<4>().copied()?;
        if selector != IB20Asset::announceCall::SELECTOR {
            return None;
        }
        if !version.abi().asset.valid_selector(selector) {
            return None;
        }
        let rest = &calldata[4..];
        let token =
            abi::decode_sequence::<<IB20Asset::announceCall as SolCall>::Token<'a>>(rest).ok()?;
        if !<<IB20Asset::announceCall as SolCall>::Parameters<'a> as SolType>::valid_token(&token) {
            return match version {
                // V1/Beryl: revert bytes are already consensus-frozen — keep falling through to
                // the owned decoder's diagnostic, however expensive, unchanged.
                AssetVersion::V1 => None,
                // V2/Cobalt: not scheduled on any network yet, so this can short-circuit cheaply
                // without touching any live consensus bytes.
                AssetVersion::V2 => Some(Err(BasePrecompileError::AbiDecodeFailed {
                    selector,
                    error: String::from("announce: malformed bytes[] payload"),
                })),
            };
        }
        // Field `.0` of `PackedSeqToken<'a>` is `&'a [u8]`, so each iter yields a slice with the
        // full calldata lifetime. `as_slice()` would tie borrows to `token` (a local) instead.
        Some(Ok(Self {
            id: Self::string_from_utf8(token.1.0),
            description: Self::string_from_utf8(token.2.0),
            uri: Self::string_from_utf8(token.3.0),
            internal_calls: token.0.0.iter().map(|call| call.0).collect(),
        }))
    }

/// Cantina #16 follow-up: a malformed `announce` (invalid UTF-8 in `id`) must keep falling
/// through to the owned decoder's diagnostic at V1, unchanged — V1's revert bytes are
/// consensus-frozen and must never take the new V2-only bounded-rejection path.
#[test]
fn golden_announce_malformed_id_stays_on_owned_diagnostic_at_v1() {
    let mut s = fresh();
    let marker = "malformed-id-marker";
    let mut calldata = IB20Asset::announceCall {
        internalCalls: vec![],
        id: marker.into(),
        description: String::new(),
        uri: String::new(),
    }
    .abi_encode();
    let at = calldata.windows(marker.len()).position(|w| w == marker.as_bytes()).unwrap();

    let oracle_error = IB20Asset::IB20AssetCalls::abi_decode_validate(&calldata).unwrap_err();
    assert_eq!(
        err,
        BasePrecompileError::AbiDecodeFailed {
            selector: IB20Asset::announceCall::SELECTOR,
            error: oracle_error.to_string(),
        },
        "V1 must keep falling through to the owned decoder's diagnostic, unchanged",
    );
}
