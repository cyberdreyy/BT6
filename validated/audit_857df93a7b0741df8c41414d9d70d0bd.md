### Title
Unauthenticated-role GET `/v2/bridge_types/:BridgeName` leaks `OutgoingToken` secret to run/view-role tokens - ([File: core/web/bridge_types_controller.go])

### Summary
The `bridge_types` route group wraps `Create`, `Update`, and `Destroy` in `auth.RequiresEditRole`, but `Show` (and `Index`) are reachable by any authenticated principal regardless of role, including `run`-role API tokens and external-initiator-derived sessions. `BridgeTypesController.Show` returns the bridge's `OutgoingToken` secret via `presenters.NewBridgeResource`, so a token intended only to trigger job runs can read a credential it has no legitimate need for.

### Finding Description
`BridgeTypesController.Show` looks up the bridge by name and serializes it with `presenters.NewBridgeResource`, which unconditionally populates `OutgoingToken` in the JSON response (unlike `IncomingToken`, which is only set on `Create`): [1](#0-0) [2](#0-1) 

`Show` itself performs no role check of its own — it trusts the router-level wrapper to gate access: [3](#0-2) 

In the router, mutation endpoints for this resource are wrapped with `auth.RequiresEditRole`, while `Show`/`Index` are registered without any role wrapper, only the base `authv2` authentication middleware (session or API-token authentication, without a per-role gate). `auth.RequiresRunRole` only excludes `UserRoleView`, and `auth.RequiresEditRole` excludes both `UserRoleView` and `UserRoleRun`: [4](#0-3) 

Because `Show` has no `RequiresEditRole` (or even `RequiresRunRole`) wrapper, any principal that passes basic authentication — including a user/API token provisioned with `UserRoleRun` (intended only to invoke job-run endpoints) or `UserRoleView` — can call `GET /v2/bridge_types/:BridgeName` and receive the bridge's `OutgoingToken` in the response body. This token is a secret used to authenticate outbound webhook/bridge calls, so its disclosure to a lower-privileged principal is a credential-exposure and privilege-escalation issue: a run-scoped credential gains access to a secret that only edit/admin-scoped users should see.

### Impact Explanation
This is a scoped secret-disclosure / privilege-escalation finding: a restricted, run-role-only API token (or view-role session) can exfiltrate `OutgoingToken` values for any configured bridge without ever being granted edit privileges. Since `OutgoingToken` is used to authenticate the node when it calls out to an external adapter, its leakage lets a low-privileged attacker forge or replay requests as the node to that external adapter, or otherwise abuse the bridge's outbound authentication — matching Chainlink's "unauthorized secret/credential disclosure" and "privilege escalation via role/authorization bypass" bounty impact classes.

### Likelihood Explanation
Preconditions are minimal: only a valid session or API token with `UserRoleRun` (or `UserRoleView`) is required — exactly the credential type this question specifies as the unprivileged attacker. The attack is a single unauthenticated-role `GET` request to a known, stable route (`/v2/bridge_types/:BridgeName`), fully reproducible and repeatable for every configured bridge name (bridge names are also enumerable via the unguarded `Index`/`GET /v2/bridge_types` list endpoint).

### Recommendation
Wrap the `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` routes in at least `auth.RequiresEditRole` (matching the mutation endpoints), or, if read access must remain broader than edit, strip `OutgoingToken` from the `Show`/`Index` presenter output for callers below edit role (e.g., add a redaction path in `presenters.NewBridgeResource` gated on caller role, similar to how `IncomingToken` is already conditionally populated only on `Create`).

### Proof of Concept
Go handler-level integration test plan (extending `core/web/bridge_types_controller_test.go`):
1. Create a bridge via an edit/admin session so it has a known `OutgoingToken` (using existing `CreateBridgeType` helper/ORM call).
2. Provision an API token or session with `clsessions.UserRoleRun` only.
3. Using that run-role credential, call `GET /v2/bridge_types/:BridgeName`.
   - Assert response status is `200` (not `401`/`403`).
   - Assert the JSON body's `data.attributes.outgoingToken` equals the bridge's stored `OutgoingToken`.
4. Using the same run-role credential, call `POST /v2/bridge_types` with a valid bridge payload.
   - Assert response status is `401` (blocked by `auth.RequiresEditRole`), demonstrating the asymmetry: write is blocked, but secret-bearing read is not.
5. (Optional) Repeat step 3 with `clsessions.UserRoleView` to confirm view-role sessions can equally exfiltrate `OutgoingToken`.

```go
// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
```

```go
// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
```
