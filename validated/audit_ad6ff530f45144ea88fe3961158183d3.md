Based on the codebase, I found a valid analog to the reported bug class in marginfi's bankruptcy/insurance-fee accounting.

### Title
Uncollected insurance fees are excluded from `handle_bankruptcy`'s insurance-fund coverage check, causing depositors to be socialized for losses the insurance fund should have covered - ([File: programs/marginfi/src/instructions/marginfi_group/handle_bankruptcy.rs])

### Summary
Just as Curve's admin fee array is not adjusted for token rebases (so LPs are diluted if fees are withdrawn before a rebase-down/slashing event is reflected), marginfi's `collected_insurance_fees_outstanding` field tracks insurance fees that have accrued but have not yet been physically swept from the `liquidity_vault` into the `insurance_vault`. `lending_pool_handle_bankruptcy` only checks the *already-swept* `insurance_vault.amount` when deciding how much bad debt the insurance fund can cover, ignoring insurance fees that have accrued but not yet been collected. If bankruptcy is processed before fees are collected, LPs absorb a socialized loss that should have been (partly) covered by insurance, while the group/program/insurance fee recipients later withdraw their full outstanding fee amounts unaffected by the loss - an economically identical outcome to the Curve report ("if admin fees are withdrawn first after a slashing event, LPs get unfairly diluted").

### Finding Description
Insurance fees accrue purely as an accounting entry during `accrue_interest`, incrementing `collected_insurance_fees_outstanding` without moving any tokens: [1](#0-0) . The actual token transfer from `liquidity_vault` to `insurance_vault` only happens in the permissionless `lending_pool_collect_bank_fees` instruction: [2](#0-1) .

`lending_pool_handle_bankruptcy` computes the insurance fund available to cover bad debt using only `insurance_vault.amount` - it never looks at `bank.collected_insurance_fees_outstanding`, which may represent capital that is still physically sitting in the `liquidity_vault` (already earned, but not yet swept): [3](#0-2) . The instruction does call `bank.accrue_interest(...)` immediately beforehand, which can further increase `collected_insurance_fees_outstanding` at the very moment the coverage check runs, without that value ever backing the coverage check: [4](#0-3) . Any shortfall not covered by `insurance_vault.amount` is then socialized directly across all depositors via `socialize_loss`, which reduces `asset_share_value` for every remaining lender: [5](#0-4)  and [6](#0-5) .

The project's own operational guide confirms this is a known, real ordering dependency that is not enforced on-chain: "Run `collect_bank_fees` before beginning the next step so the insurance fund is fully capitalized," and separately documents that when insurance is insufficient, "the remainder will be covered by taking liquidity out of the bank, reducing the asset share value. This socializes the loss to all remaining depositors": [7](#0-6) .

Critically, for banks with `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` set, `lending_pool_handle_bankruptcy` can be invoked by *any* signer, with no requirement that `lending_pool_collect_bank_fees` be run first: [8](#0-7) .

### Impact Explanation
When a permissionless bad-debt bank accrues outstanding (but uncollected) insurance fees and later develops bad debt, any unprivileged user can call `lending_pool_handle_bankruptcy` before anyone runs `lending_pool_collect_bank_fees`. The insurance fund appears smaller than its true economic value (it excludes fee amounts already earned and physically present in `liquidity_vault`), so more of the bad debt is socialized onto remaining depositors than would occur under correct sequencing. Remaining depositors are diluted, while the group/program/insurance-fee recipients can still withdraw their full outstanding fee balances afterward via `LendingPoolWithdrawFees`, unaffected by the loss - the fee bucket is fully protected from the socialized loss it should partially have absorbed. This is a direct financial-value-redirection from depositors to the fee-recipient buckets, mirroring the Curve admin-fee/rebase dilution report.

### Likelihood Explanation
This requires: (1) a bank with `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` set, (2) non-trivial `collected_insurance_fees_outstanding` at the time of bankruptcy, and (3) `handle_bankruptcy` being called (by anyone, since it's permissionless for such banks) before `collect_bank_fees` is called. Since `collect_bank_fees` is itself a separate, optional, permissionless instruction with no atomicity guarantee relative to bankruptcy handling, and bankruptcy itself is documented as a rare event, the ordering dependency is real but requires an adversary (or unlucky timing) to specifically exploit the sequencing gap on a bank where the flag is enabled and fees have accrued. The project's own guide's explicit warning to run `collect_bank_fees` first indicates the team is aware fee-sweep ordering matters, but nothing enforces it programmatically.

### Recommendation
In `lending_pool_handle_bankruptcy`, compute the effective available insurance coverage as `insurance_vault.amount` (or its post-transfer-fee equivalent) plus `min(bank.collected_insurance_fees_outstanding, liquidity_vault_balance_reserved_for_fees)`, or simply force a fee sweep (equivalent to `collect_bank_fees` logic) for the insurance bucket at the start of `lending_pool_handle_bankruptcy` before computing `available_insurance_fund`. At minimum, document in the `Bank` state (near `collected_insurance_fees_outstanding`) that these balances are not considered during bankruptcy coverage calculations and can cause additional depositor dilution if not collected proactively — analogous to the recommended fix in the Curve report of documenting that admin balances do not account for rebases.

### Proof of Concept
1. Create a bank with `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` set, deposit liquidity, and have borrowers accrue interest over time so that `collected_insurance_fees_outstanding` grows to a meaningful nonzero value without anyone calling `LendingPoolCollectBankFees`.
2. Engineer a liquidation/bad-debt scenario (e.g., oracle price shock as in `trident-tests/fuzz_0/test_fuzz.rs` lines 759-788) so a borrower account becomes bankrupt, with `bad_debt` greater than the current `insurance_vault.amount` but less than `insurance_vault.amount + collected_insurance_fees_outstanding`.
3. Call `lending_pool_handle_bankruptcy` (permissionlessly) before calling `lending_pool_collect_bank_fees`. Observe that `available_insurance_fund` in the handler is computed strictly from `insurance_vault.amount`, socializing `bad_debt - insurance_vault.amount` onto all remaining depositors via `socialize_loss`, even though `insurance_vault.amount + collected_insurance_fees_outstanding >= bad_debt`.
4. Afterward, call `lending_pool_collect_bank_fees` and `LendingPoolWithdrawFees`: the full `collected_insurance_fees_outstanding` (and group/program fees) are withdrawn intact, confirming that the earned-but-uncollected insurance capital was never used to reduce the socialized loss depositors just absorbed.

    /// Socialize a loss of `loss_amount` among depositors, the `total_deposit_shares` stays the
    /// same, but total value of deposits is reduced by `loss_amount`;
    ///
    /// In cases where assets < liabilities, the asset share value will be set to zero, but cannot
    /// go negative. Effectively, depositors forfeit their entire deposit AND all earned interest in
    /// this case.
    fn socialize_loss(&mut self, loss_amount: I80F48) -> MarginfiResult<bool> {
        let mut kill_bank = false;
        let total_asset_shares: I80F48 = self.total_asset_shares.into();
        let old_asset_share_value: I80F48 = self.asset_share_value.into();

        // Compute total "old" value of shares
        let total_value: I80F48 = total_asset_shares
            .checked_mul(old_asset_share_value)
            .ok_or_else(math_error!())?;

        // Subtract loss, clamping at zero (i.e. assets < liabilities, the bank is wiped out)
        if total_value <= loss_amount {
            self.asset_share_value = I80F48::ZERO.into();
            // This state is irrecoverable, the bank is dead.
            kill_bank = true;
        } else {
            // otherwise subtract then redistribute
            let new_share_value: I80F48 = (total_value - loss_amount)
                .checked_div(total_asset_shares)
                .ok_or_else(math_error!())?;
            self.asset_share_value = new_share_value.into();
            // Sanity check: should be unreachable.
            if new_share_value == I80F48::ZERO {
                kill_bank = true;
            }
        }

        Ok(kill_bank)
    }

```markdown
Run `collect_bank_fees` before beginning the next step so the insurance fund is fully capitalized.

Next, the group administrator runs `handle_bankruptcy` on the user. For banks where
`PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is enabled, anyone can do this. This will perform the
following logic:

* If bank's insurance fund > liabilities, then the insurance fund is used to repay the user's liability.
* If the bank's insurance fund is not sufficient, the remainder will be covered by taking liquidity
  out of the bank, reducing the asset share value. This socializes the loss to all remaining
  depositors.
* If the bank's insurance fund and liquidity are not sufficient (super-bankruptcy), the bank is
  killed. The asset share value is set to zero, wiping out all holdings for all other depositors.
  This state is irrecoverable, and the bank is permanently disabled.
```
