## Analysis: Unbounded In-Memory Allowlist Growth in Vault Gateway Authorization

### Title
Unbounded Growth of Vault Allowlisted-Requests List Causes Linear-Scan DoS on Every Gateway Request - (File: `core/capabilities/vault/allow_list_based_auth.go`)

### Summary
The Vault capability's `AuthorizeRequest` path fetches and linearly scans an in-memory list of all currently-active on-chain "allowlisted requests" for every single incoming gateway request. This list is populated from the `WorkflowRegistry` contract and is bounded only by the requests' expiry timestamps, not by a hard cap on how many active entries can exist at once. Any linked (unprivileged) workflow owner can repeatedly call the on-chain `AllowlistRequest` function with fresh digests, growing this list without bound before entries expire, degrading or denying the Vault gateway handler for all users on the node — directly analogous to the reported `BalanceSheetV2` unbounded-collateral-iteration bug.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` (`core/capabilities/vault/allow_list_based_auth.go:34-77`) calls `findAllowlistedItemWithRetry`, which for every incoming request: [1](#0-0) 

For each of up to `retryCount+1` (11) attempts, it calls `r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)` and then **iterates over the entire list twice**: once to build a debug-log string for every element, and once inside `fetchAllowlistedItem` to linearly search for a digest match: [2](#0-1) 

`GetAllowlistedRequests` simply copies the entire in-memory slice `w.allowListedRequests` on every call: [3](#0-2) 

That in-memory slice is refreshed periodically by `syncAllowlistedRequests`, which prunes only **expired** entries and otherwise keeps appending new ones fetched from chain — there is no cap enforced on the number of simultaneously active (non-expired) entries: [4](#0-3) 

This `AuthorizeRequest` call is on the hot path of every Vault gateway request received from any client (unprivileged, per-request basis), reached via `GatewayHandler.HandleGatewayMessage` → `requestProcessor.ProcessRequest` → the allowlist-based authorizer: [5](#0-4) 

Unlike the `BalanceSheetV2.maxCollaterals` fix, no equivalent bound (`maxAllowlistedRequests` or similar) exists in this Go/contract-reader code path for the number of simultaneously active allowlisted requests. Any linked workflow owner (an unprivileged, self-registerable actor — see `UserLinkOwner`/`UserAllowlistRequest` operations) can call the on-chain `AllowlistRequest` function repeatedly with distinct random digests and long expiries, growing `w.allowListedRequests` without bound. I could not find, within the indexed repository, a corresponding Solidity-side cap (`MAX_ALLOWLISTED_REQUESTS` or similar) on the number of active allowlist entries per owner or globally — this is a limitation of what the index makes available and should be independently verified against the on-chain contract source.

### Impact Explanation
Since `AuthorizeRequest` is invoked for **every** Vault gateway request (secrets create/update/delete/list) from any DON node, and does an O(n) (or worse, with retries, O(11n)) scan plus string formatting of the entire allowlisted-requests list on each call, an attacker that inflates this list (e.g., to tens or hundreds of thousands of entries) can significantly degrade CPU and latency for **all** users' Vault requests processed by that node — not just their own. This is a cross-user availability degradation of a security-critical capability (Vault secrets), potentially rendering the gateway handler for Vault unusable node-wide, mirroring the original report's "complete unusability" impact, translated from an EVM gas-exhaustion context to a Go CPU/latency-exhaustion context.

### Likelihood Explanation
Likelihood is moderate-to-high: linking as a workflow owner and calling `AllowlistRequest` appear to be permissionless, self-service actions available to any external actor holding a private key that can produce the required ownership proof, and repeated calls only cost gas — there is no indication of a per-owner or global cap preventing this list from growing arbitrarily large before entries expire (default expiry windows observed in tests are on the order of hours to days).

### Recommendation
- Enforce a maximum number of simultaneously active allowlisted requests (globally and/or per owner) on the `WorkflowRegistry` contract, mirroring the `maxCollaterals`-style mitigation from the referenced HiFi fix.
- On the node side, replace the linear scan in `fetchAllowlistedItem` with an indexed lookup (e.g., a map keyed by digest) to avoid O(n) behavior regardless of list size, and avoid building the full `allowedRequestsStrs` debug list on every retry attempt in production code paths.
- Consider capping/paginating the in-memory `w.allowListedRequests` structure and evicting oldest/least-recently-used entries if a hard on-chain cap cannot be added.

### Proof of Concept
1. As an unprivileged actor, link a workflow-owner identity via the `WorkflowRegistry`'s ownership-proof mechanism (`UserLinkOwner`).
2. Repeatedly call `AllowlistRequest(requestDigest, expiryTimestamp)` on-chain with many distinct random 32-byte digests and expiries set far in the future (e.g., thousands of calls).
3. Wait for `syncAllowlistedRequests` (default ~12s tick) to pull these into every DON node's in-memory `w.allowListedRequests`.
4. Send a normal Vault gateway request (e.g., `secrets/list`) from any other unprivileged client; observe increased latency/CPU usage node-wide as `AuthorizeRequest` linearly scans the inflated list (and up to 11 times on a miss), degrading service for all users of that node's Vault gateway handler.

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (r *allowListBasedAuth) fetchAllowlistedItem(allowListedRequests []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, digest [32]byte) *workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	for _, item := range allowListedRequests {

			return &item
		}
	}
	return nil

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()

func (w *workflowRegistry) GetAllowlistedRequests(_ context.Context) []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	w.allowListedMu.RLock()
	defer w.allowListedMu.RUnlock()
	allowListedRequests := make([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, len(w.allowListedRequests))
	copy(allowListedRequests, w.allowListedRequests)
	return allowListedRequests
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}
