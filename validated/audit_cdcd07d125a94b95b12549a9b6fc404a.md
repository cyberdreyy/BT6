### Title
Unauthenticated `MethodPublicKeyGet` flood causes unbounded growth of `h.activeRequests` and node fan-out amplification - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`HandleJSONRPCUserMessage` explicitly skips authorization for `vaulttypes.MethodPublicKeyGet` and, whenever the public key cache is empty, calls `newActiveRequest` and fans the request out to every DON member for each distinct request ID. Since there is no per-caller/per-IP rate limit or cap on the number of concurrently tracked active requests, an unauthenticated attacker can create an arbitrary number of live `activeRequest` entries sharing the same map and mutex used by authenticated secret operations.

### Finding Description
In `HandleJSONRPCUserMessage`, the code takes this path for public key requests: [1](#0-0) 

The only gate before creating an `activeRequest` is a request-ID length check (`len(req.ID) > 200`), performed earlier in the same function: [2](#0-1) 

`newActiveRequest` only rejects duplicate IDs; it never caps the total size of `h.activeRequests`: [3](#0-2) 

Every accepted request is then fanned out to all DON members via `fanOutToVaultNodes` (through `handlePublicKeyGet`): [4](#0-3) [5](#0-4) 

Pruning of stale entries only happens every `defaultCleanUpPeriod` (5s) and only removes entries older than `h.requestTimeout` (default 30s, configurable via `RequestTimeoutSec`): [6](#0-5) [7](#0-6) 

Tracing the reachable path confirms no authentication or rate limiting occurs before this: the gateway's HTTP entrypoint (`httpServer.handleRequest` → `gateway.ProcessRequest`) only checks request-ID length and dispatches directly to `h.HandleJSONRPCUserMessage`, with no per-sender/global rate limiter for the vault handler's user-request path (unlike, e.g., the HTTP capability handler v2 which has `userRateLimiter`/`nodeRateLimiter` for inbound triggers). The vault handler's only `nodeRateLimiter` throttles *node* responses in `HandleNodeMessage`, not inbound user requests: [8](#0-7) 

Because `h.activeRequests` and its guarding `h.mu` (`sync.RWMutex`) are shared across all methods (`MethodPublicKeyGet`, `MethodSecretsCreate/Update/Delete/List`), an attacker flooding unique-ID `MethodPublicKeyGet` requests before the cache is warm (or is deliberately kept cold, e.g. right after node restart) forces `newActiveRequest`/`sendResponse` lock acquisitions and map growth that compete directly with legitimate authenticated users' request bookkeeping, and multiplies outbound load to every DON node per flooded request.

### Impact Explanation
This is an unauthenticated, unbounded resource-consumption path: attacker-controlled growth of an internal map/lock shared with authenticated request processing, plus N-times node fan-out amplification per request (N = DON member count). This matches a denial-of-service / resource-exhaustion impact class rather than data disclosure or privilege escalation — it can degrade or delay legitimate authenticated vault operations (secrets create/update/delete/list) due to lock contention and increased load on DON nodes, without requiring any credentials.

### Likelihood Explanation
No preconditions or credentials are required — `MethodPublicKeyGet` is explicitly documented as not requiring authorization (see comment "Public key requests don't require authorization" in `HandleJSONRPCUserMessage`). The only friction is that the cache must be empty (`cachedPublicKey == nil`), which is true at startup and can persist if `fetchVaultPublicKey` responses are slow/fail, or attacker keeps generating enough concurrent load before the periodic refresh (every 1 minute) succeeds and caches a response. Generating unique IDs up to 200 chars is trivial, so the attack is straightforward and repeatable within any `requestTimeout` window (default 30s) before pruning removes entries.

### Recommendation
Add an inbound rate limiter (per-IP/per-sender or global) for unauthenticated methods like `MethodPublicKeyGet` in `HandleJSONRPCUserMessage`, and/or cap the total size of `h.activeRequests` (rejecting new requests once a configurable ceiling is reached), independent of the existing request-ID length check. Consider isolating unauthenticated request bookkeeping (e.g., a separate map/mutex) from the authenticated-request map to avoid lock contention/eviction risk across trust boundaries.

### Proof of Concept
Go handler-level test plan:
1. Construct a `handler` via `newHandlerWithAuthorizer` with a mock `don` (`gwhandlers.DON`) and DON config containing several members, ensuring `cachedPublicKeyGetResponse`/`cachedPublicKeyObject` remain `nil` (do not let `HandleNodeMessage` populate them).
2. In a loop, call `h.HandleJSONRPCUserMessage(ctx, req, callback)` N times (e.g., N=10,000) with `req.Method = vaulttypes.MethodPublicKeyGet` and a unique `req.ID` each time (≤200 chars), using a no-op/lightweight `callback` mock.
3. Assert on `len(h.activeRequests)` (via a test-only accessor or reflection) growing linearly to N with no cap enforced, before `removeExpiredRequests` runs.
4. Assert on the mock `don.SendToNode` call count showing N × len(donConfig.Members) fan-out calls, demonstrating amplification.
5. Concurrently issue a legitimate authenticated `MethodSecretsList` request and measure increased latency/lock wait time acquiring `h.mu` while the flood is in progress, demonstrating contention against real users' active requests.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}
