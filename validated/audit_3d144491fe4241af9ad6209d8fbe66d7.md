### Title
Removed multisig member's stale confirmation still counts toward threshold, allowing request execution below live-member quorum - ([File: multisig2/src/lib.rs])

### Summary
Both `multisig` and `multisig2` contracts only purge a signer/member's *own authored* pending requests when that key/member is deleted, but they never purge confirmations that the deleted member had already cast on *other* members' pending requests. Because `confirm()` counts entries in the stored `confirmations` set without checking whether each entry still corresponds to a live member, a request can execute once `confirmations.len() + 1 >= num_confirmations` even though one or more of those confirmations belong to an account/key that is no longer a member. This breaks the equality `confirmations counted == live members who approved`.

### Finding Description
In `multisig2/src/lib.rs`, `confirm()` decides whether to execute a request purely by comparing the size of the `confirmations` `HashSet<String>` against `self.num_confirmations`: [1](#0-0) 

`delete_member()` (invoked via the `DeleteMember` request action) removes the deleted member from `self.members` and also deletes requests *that the member itself authored*, but it filters strictly on `r.member == member`, i.e. only requests where the member was the *author*, not requests where the member was merely a *confirmer*: [2](#0-1) 

Any other pending request that this member had previously confirmed keeps that member's identifier inside its `confirmations` HashSet — it is never scrubbed. Consequently, once the member is removed, that request's confirmation count still includes a non-member's stale approval, letting the remaining live members reach the "≥ num_confirmations" condition with fewer *live* signers than the quorum was configured to require.

The legacy `multisig/src/lib.rs` (`DeleteKey` action, lines 198-216) has the exact same pattern: it only removes requests authored (`r.signer_pk == pk`) by the deleted key, not requests the key merely confirmed. [3](#0-2) 

This is the direct analog to the ENS report's underlying concern — the enforced authorization boundary (here, "K-of-N *current* signers must approve") silently degrades because a party that is no longer trusted (a removed member/key) still counts toward the quorum that authorizes arbitrary transfers, deployments, and key/member changes on the contract.

### Impact Explanation
This lets a request (e.g., `Transfer`, `DeployContract`, `AddKey`/`AddMember` giving full access) execute with confirmations from fewer *live* members than `num_confirmations` requires — i.e., "a multisig request executed below threshold," which is explicitly listed as a Critical impact. Since the multisig contract type is used to custody NEAR balances and control account access keys (as documented in `multisig2/README.md`), this can result in NEAR being moved, or full access keys being added, by a quorum that no longer reflects the actual trusted signer set.

### Likelihood Explanation
This requires no compromise of any private key beyond ordinary, expected multisig operation: (1) a request is created and partially confirmed, (2) at some later point a member is legitimately removed (key rotation, offboarding, compromise response) via a normal `DeleteMember`/`DeleteKey` action, and (3) the pre-existing partially-confirmed request is later confirmed by remaining members to reach the numeric threshold. Because member removal is a routine, expected lifecycle event for any long-lived multisig (the very "reduce trust surface / rotate signers" mitigation recommended for the ENS analog), and the flaw silently degrades quorum integrity without any error or warning, likelihood of encountering this is moderate-to-high over the contract's operational lifetime, particularly for multisigs with many long-pending requests.

### Recommendation
When a member/key is removed (`delete_member` in `multisig2/src/lib.rs`, and the `DeleteKey` branch in `multisig/src/lib.rs`), scrub that member's identifier from the `confirmations` set of *every* pending request, not just requests the member authored. Alternatively, when counting confirmations in `confirm()`, filter `confirmations` against `self.members` (intersect with currently live members) before comparing to `num_confirmations`, so stale confirmations from removed members never count toward quorum.

### Proof of Concept
1. Initialize `multisig2` with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. `B` calls `add_request` creating request `R` (e.g., `Transfer` of contract balance to an external account). `R.member = B`.
3. `A` calls `confirm(R)` → `confirmations[R] = {A}` (1 < 3, not yet executed).
4. `C` calls `confirm(R)` → `confirmations[R] = {A, C}` (2 < 3, not yet executed).
5. Separately, members legitimately create+confirm a `DeleteMember { member: A }` request (3-of-4 confirm: e.g. B, C, D) to remove `A` (e.g., due to a suspected key compromise). `delete_member` executes: `members = {B, C, D}`; because `R.member == B` (not `A`), `R` and its confirmations are **not** purged — see `multisig2/src/lib.rs:356-379`.
6. `D` (a current, live member) calls `confirm(R)`. `confirmations[R].len() == 2`, so `2 + 1 >= 3` is true, and `execute_request(R)` fires the `Transfer`.
7. Result: `R` executed with only `{C, D}` as genuinely live-member confirmations (2 live approvals) plus a stale, no-longer-valid approval from removed member `A` — i.e., the request executed with fewer than the configured 3 live-member confirmations, violating the K-of-N custody guarantee.

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
