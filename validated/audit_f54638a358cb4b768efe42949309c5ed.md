### Title
Cross-user callback hijack via MessageId collision in savedCallbacks map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores each pending user request keyed solely by the attacker/client-supplied `msg.Body.MessageId` string, with no binding to the sender's address or connection. Because `MessageId` is fully controlled by the client and is not required to be unique across different senders, a second signed request that reuses another user's in-flight `MessageId` silently overwrites `h.savedCallbacks[msg.Body.MessageId]`, so the DON's eventual response is delivered to the attacker's callback instead of the original caller's.

### Finding Description
`api.MessageBody.MessageId` is a client-chosen field, set directly from the JSON-RPC `req.ID` in `ValidatedMessageFromReq` (`core/services/gateway/handlers/common/message_util.go:36-58`) and is not derived from or bound to the signer's address — it is merely one of the signed fields alongside `Method`, `DonId`, `Receiver`, and `Payload` [1](#0-0) .

In `HandleLegacyUserMessage`, after validating the signature and payload, the handler stores the caller's callback keyed only by this attacker-controlled string:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [2](#0-1) 

There is no check for an existing entry before overwrite, and no association between the map key and `msg.Body.Sender` (which is populated by `Validate()`/`ExtractSigner()` from the signature) [3](#0-2) . If two distinct signed requests (from two different unprivileged EOAs) arrive with the same `MessageId` while the first is still pending, the second `HandleLegacyUserMessage` call overwrites the map entry, discarding the first caller's `savedCallback`.

When the DON later responds, `handleWebAPITriggerMessage` looks the callback up purely by `MessageId`:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
h.mu.Unlock()
if found {
    return savedCb.SendResponse(...)
}
``` [4](#0-3) 

Since the DON's response message itself only carries `MessageId`/`Method`/`DonId`/`Payload` (no original sender identity check against the saved callback), whichever caller's entry is currently present in the map at response time receives the response — this can be the attacker's callback even though the DON actually processed and is responding to the original (possibly higher-privileged) caller's request payload that was broadcast to DON members. No signature verification, allowlist, or per-sender key isolation exists in this code path to prevent the second registration from clobbering the first; the only preconditions are a validly signed envelope (`common.ValidatedRequestFromMessage`/`Validate()`), which any EOA holding a signing key can produce.

### Impact Explanation
This is a cross-user response/callback confusion vulnerability: an attacker can cause another user's DON trigger response (potentially containing sensitive execution results tied to that user's workflow/job) to be delivered to the attacker's own connection instead of the legitimate caller, and the legitimate caller receives no response (denial of service for that request). This matches the "cross-user response confusion" / unauthorized access to another user's data class described in the audit rules.

### Likelihood Explanation
Exploitability requires only that the attacker know or guess the victim's in-flight `MessageId` and race a second signed request with that identical ID before the DON responds. `MessageId` values are often predictable or reused by clients (e.g., sequential counters, UUIDs reused across retries, or well-known constant IDs used by some SDKs), and the map has no uniqueness/ownership check, no per-sender namespacing, and only a time-based prune (`CallbackMaxAgeSec`, default 120s) — giving the attacker a wide window to race. No special role, credential, or DON/gateway trust is needed beyond a valid signing key producing a well-formed signed `api.Message`, which is exactly the unprivileged attacker profile in scope.

### Recommendation
Namespace `savedCallbacks` by a composite key that includes the verified sender address (`msg.Body.Sender`) in addition to `MessageId` (e.g., `sender+":"+MessageId`), and reject/no-op registration if an entry already exists for that key rather than silently overwriting it. Additionally consider validating that the DON's response corresponds to the same sender that originated the request before invoking `SendResponse`.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct handler with a mocked `handlers.DON` (`SendToNode` no-op returning nil).
2. Build two valid signed `api.Message` envelopes, `msgVictim` and `msgAttacker`, from two different ECDSA keys, both with identical `Body.MessageId = "shared-id"`, `Method = MethodWebAPITrigger`, valid `Timestamp` payload.
3. Create two callback spies `victimCB` and `attackerCB` implementing `handlers.Callback`, each recording whether `SendResponse` was invoked and with what payload.
4. Call `h.HandleLegacyUserMessage(ctx, msgVictim, victimCB)`, then `h.HandleLegacyUserMessage(ctx, msgAttacker, attackerCB)`.
5. Assert `len(h.savedCallbacks) == 1` and that `h.savedCallbacks["shared-id"].Callback == attackerCB` (victim entry overwritten).
6. Simulate the DON response by calling `h.handleWebAPITriggerMessage(ctx, respMsg, nodeAddr)` with `respMsg.Body.MessageId = "shared-id"`.
7. Assert `attackerCB.SendResponse` was called exactly once with the response payload, and `victimCB.SendResponse` was never called — demonstrating the victim's original request received no response while the attacker's callback captured the DON's reply.

func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
