### Title
Replay of a captured signed webapi trigger message allows response hijacking via unconditional `savedCallbacks` overwrite - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` (in `core/services/gateway/handlers/capabilities/handler.go`) validates only the message signature, method, and timestamp freshness before registering a `savedCallback` keyed solely by `msg.Body.MessageId`, without checking whether that MessageId is already in use or binding the callback to the original request's identity. An attacker who has captured a previously-issued, still-valid (within `MaxAllowedMessageAgeSec`) signed `api.Message` can resubmit it unmodified through the gateway's own legacy user-message path, causing the map entry for that MessageId to be silently overwritten with the attacker's own `callback`, so the eventual DON trigger response is delivered to the attacker instead of the original caller.

### Finding Description
`HandleLegacyUserMessage` decodes the payload, checks `payload.Timestamp != 0` and that it's within `h.config.MaxAllowedMessageAgeSec` [1](#0-0) , but performs no anti-replay check (no nonce store, no "MessageId already seen" rejection). It then unconditionally writes to the shared map: [2](#0-1) 

Because the key is only `msg.Body.MessageId` (not combined with sender or bound to the specific inbound connection/callback that first registered it), any second submission of the identical bytes—regardless of who submits them—overwrites the existing `savedCallback` with the new caller's `callback`. When the DON eventually returns the trigger result, `handleWebAPITriggerMessage` looks it up purely by `MessageId` and forwards the response to whichever `callback` is currently stored: [3](#0-2) 

The signature check in `api.Message.Validate`/`ExtractSigner` only proves the message body (MessageId, Method, DonId, Receiver, Payload) was signed by the original sender key [4](#0-3)  — it does not, and cannot, bind the message to a particular network connection/callback. Replaying the exact bytes produces a still-valid signature, so signature verification does not stop this. Nothing else in the reachable path (`ValidatedRequestFromMessage`, `Methods()`, or the timestamp check) enforces MessageId uniqueness.

Note: by contrast, `common.RequestCache.NewRequest` (used elsewhere in the gateway handlers) explicitly rejects duplicate `(sender, MessageId)` keys with `"request already exists"` [5](#0-4) , showing that idempotency protection is a known, implemented pattern elsewhere in the codebase but is missing from `HandleLegacyUserMessage`'s direct map write.

### Impact Explanation
This is a cross-user response hijack: an unprivileged attacker who obtains a copy of another user's valid signed webapi trigger request (e.g., via logs, a shared proxy, browser history, or any channel where the raw signed message is exposed) can, without any credentials of their own, redirect the eventual DON response for that original request to themselves. Depending on what the "web_api_trigger" payload/response carries, this could expose data intended for another caller — matching a "cross-user response confusion / request impersonation" impact class.

### Likelihood Explanation
Requires only possession of a previously observed, unexpired signed message (no signing key, no session) and one direct call into the gateway's legacy webapi-trigger endpoint before `MaxAllowedMessageAgeSec` elapses. No operator, DON, or host-level access needed. Preconditions (attacker must have observed the raw signed message) limit likelihood in practice, but the code path itself has no defense once that precondition is met, and the race is trivially repeatable.

### Recommendation
- Reject resubmission of a MessageId that already has an active `savedCallback` entry (mirror the `requestCache` pattern: check-and-fail instead of unconditional map write).
- Bind the callback registration to `(Sender, MessageId)` rather than `MessageId` alone.
- Consider tracking/rejecting recently-seen MessageIds even after eviction/pruning within the freshness window (not just relying on TTL pruning), to close the replay window entirely.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Build a signed `api.Message` with `Method = MethodWebAPITrigger`, a valid `Timestamp`, and a fixed `MessageId`.
2. Call `handler.HandleLegacyUserMessage(ctx, msg, callbackA)` — assert `savedCallbacks[msg.Body.MessageId].Callback == callbackA`.
3. Call `handler.HandleLegacyUserMessage(ctx, msg, callbackB)` again with the *same unmodified* signed message (simulating replay), still inside `MaxAllowedMessageAgeSec` — assert this call is currently accepted (no error) and `savedCallbacks[msg.Body.MessageId].Callback` is now `callbackB`, overwriting `callbackA`.
4. Simulate the DON response via `handleWebAPITriggerMessage` and assert the trigger response is delivered to `callbackB.SendResponse` instead of `callbackA.SendResponse`, demonstrating the hijack.
5. Expected fix behavior: step 3 should return an error (e.g., "duplicate message id") and `callbackA` should remain registered, or the second call should be rejected outright.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

// Message signatures are over the following data:
//  1. MessageId aligned to 128 bytes
//  2. Method aligned to 64 bytes
//  3. DonId aligned to 64 bytes
//  4. Receiver (in hex) aligned to 42 bytes
//  5. Payload (raw bytes before parsing)
func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
