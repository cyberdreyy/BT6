### Title
`depositDuringEpoch` bypasses the pause flag, allowing mid-epoch deposits that dilute default recovery - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`IdleCDOEpochVariant.depositDuringEpoch` is the only user deposit path that lacks a `whenNotPaused` check. The ordinary `_deposit` override is decorated with `whenNotPaused` (line 644), and `depositDuringEpoch` checks `skipDefaultCheck` (line 661) — but a plain `pause()` call only sets the Pausable flag, not `skipDefaultCheck`. While an epoch is running and the guardian/owner pauses deposits, a KYC-approved lender can still call `depositDuringEpoch`, mint tranche shares, and push underlyings to the borrower, defeating the pause. If the borrower subsequently defaults, the attacker's newly minted basis joins `finalizeDefaultRecovery`'s `activeBasis` and dilutes the recovery price paid to pre-existing LPs.

### Finding Description
- `pause()` in `IdleCDOCreditVault.sol` (lines 518-521) only calls `_pause()`; it does not touch `skipDefaultCheck` or the withdraw-request flags.
- `_deposit` is protected by `whenNotPaused` (IdleCDOEpochVariant.sol:644), so `depositAA`/`depositBB` revert while paused.
- `depositDuringEpoch` (lines 656-733) has no `whenNotPaused` and no `paused()` check. Its gate is `isDepositDuringEpochDisabled || skipDefaultCheck || isProgrammableBorrower || isAYSActive || !isEpochRunning || block.timestamp >= epochEndDate || !isWalletAllowed(msg.sender)` (lines 658-669). None of these is set by a bare `pause()` during a running epoch.
- During the deposit, `_mintShares` mints tranche tokens at the expected end-of-epoch price (line 724), `mintStrategyTokens` grows the CDO's active strategy-token balance (line 730), and the underlyings are forwarded to the borrower (line 732).
- Recovery accounting in `IdleCreditVault.finalizeDefaultRecovery` (IdleCreditVault.sol:674-692) uses `balanceOf(idleCDO)` plus active interest as `activeBasis`. The mid-epoch deposit's strategy tokens increase that basis while the contributed underlyings sit at the defaulted borrower, so `recoveryPrice = reserveAmount * 1e18 / totalBasis` drops for every honest claimant.
- `_emergencyShutdown` (lines 602-615) and `_handleBorrowerDefault` (lines 577-599) both set `skipDefaultCheck`/`isEpochRunning=false`, so those paths close `depositDuringEpoch` correctly — the gap exists only for the explicit `pause()` op, which is precisely the "deposits paused" lever an operator would pull mid-epoch on a risk signal.

### Impact Explanation
A KYC-passing lender (unprivileged) deposits `X` underlyings while the vault is paused mid-epoch. If the borrower then defaults and `finalizeDefault`/`finalizeDefaultRecovery` runs, the attacker's minted shares are part of `activeBasis`, but the `X` underlyings are unrecovered at the borrower. The attacker's claim consumes `recoveryPrice * (X + interest)` of the finite `defaultRecoveryReserve`, directly reducing the payout of every pre-existing LP — a quantifiable transfer of value proportional to `X / totalBasis`. Even absent a default, the deposit violates the pause invariant that no new borrower exposure can be created.

### Likelihood Explanation
Requires a guardian/owner to invoke `pause()` (not `emergencyShutdown`) while `isEpochRunning == true`, `isDepositDuringEpochDisabled == false`, `isAYSActive == false`, `!isProgrammableBorrower`, `skipDefaultCheck == false`, and the tranche supply non-zero. This is a realistic operator action during a borrower risk event, which is exactly when the dilution harm materializes on the subsequent default. The attacker only needs Keyring credentials (`isWalletAllowed`), consistent with an ordinary lender.

### Recommendation
Add `whenNotPaused` (or an explicit `paused()` check) to `depositDuringEpoch`:

```solidity
function depositDuringEpoch(uint256 _amount, address _tranche)
    external
    virtual
    whenNotPaused
    returns (uint256 _minted)
{
    _checkTranche(_tranche);
    _checkNotAllowed(
        (_tranche == BBTranche && !isBBDepositEnabled) ||
        isDepositDuringEpochDisabled ||
        skipDefaultCheck ||
        ...
    );
    ...
}
```

This preserves the intended post-`restoreOperations` mid-epoch deposit flow (which unpause/epoch state already governs) while making the pause uniform across all deposit paths.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "../TestIdleCDOBase.sol"; // existing Foundry harness for IdleCreditVault

contract DepositDuringEpochPauseBypassPoC is TestIdleCDOBase {
    function test_DepositDuringEpochBypassesPause() external {
        uint256 amount = 10_000 * ONE_SCALE;
        idleCDO.depositAA(amount); // seed AA supply so mid-epoch deposit is allowed

        vm.startPrank(owner);
        cdoEpoch.setIsAYSActive(false);
        cdoEpoch.setIsDepositDuringEpochDisabled(false);
        vm.stopPrank();
        _startEpochAndCheckPrices(0); // isEpochRunning == true

        // Operator pauses deposits mid-epoch (plain pause, not emergencyShutdown,
        // so skipDefaultCheck stays false).
        vm.prank(owner);
        cdoEpoch.pause();
        assertTrue(cdoEpoch.paused());

        // Ordinary deposits revert.
        vm.expectRevert(bytes("Pausable: paused"));
        idleCDO.depositAA(ONE_SCALE);

        // But the mid-epoch path still succeeds.
        address attacker = makeAddr("kyc-attacker");
        uint256 depositAmount = 5_000 * ONE_SCALE;
        deal(defaultUnderlying, attacker, depositAmount);
        vm.startPrank(attacker);
        underlying.approve(address(cdoEpoch), depositAmount);
        uint256 minted = cdoEpoch.depositDuringEpoch(depositAmount, address(AAtranche));
        vm.stopPrank();

        assertGt(minted, 0, "paused deposit minted shares");
        assertEq(underlying.balanceOf(borrower), depositAmount, "funds reached borrower while paused");

        // If the borrower later defaults, the attacker's basis enters
        // finalizeDefaultRecovery's activeBasis and dilutes recovery for
        // the honest seed depositor.
    }
}
```

The PoC runs on the existing `IdleCreditVault.t.sol` harness (`_startEpochAndCheckPrices`, `cdoEpoch`, `defaultUnderlying` helpers already present in `test/foundry/IdleCreditVault.t.sol`). Recovery-dilution can be quantified by comparing `defaultRecoveryPrice` with and without the paused deposit after driving the borrower into default via `stopEpoch` failure.
