### Title
Permissionless legacy `web_api_trigger` requests are broadcast to every DON node with no allowlist or rate-limiting - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`GatewayHandler.HandleLegacyUserMessage` in the WebAPI capabilities handler accepts any legacy user message and, if its method is `web_api_trigger`, fans the request out to **every member node of the DON** via `don.SendToNode`, with no allowlist check and no rate limiting applied to the caller. This mirrors the reported `Middleware.sendCurrentOperatorsKeys()` issue: an unprivileged actor can trigger a costly, fanned-out downstream action (workflow execution across the whole DON) for free and without restriction, enabling resource exhaustion/griefing of DON nodes.

### Finding Description
The only checks performed before forwarding to nodes are payload decoding, a `Timestamp != 0` check, and a staleness check based on `MaxAllowedMessageAgeSec` [1](#0-0) . Immediately after those checks, the code contains an explicit acknowledgment of the missing control:
```go
// TODO: apply allowlist and rate-limiting here
``` [2](#0-1) 

Following that comment, the handler unconditionally loops over all DON members and forwards the (attacker-controlled) request to each one:
```go
for _, member := range h.donConfig.Members {
    err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
}
``` [3](#0-2) 

This handler is reached from `gateway.ProcessRequest` for legacy (DON-ID-addressed) requests via `h.HandleLegacyUserMessage(ctx, msg, callback)` [4](#0-3) , and `gateway.ProcessRequest` is the entry point invoked directly by the internet-facing HTTP server for any incoming request — there is no authentication requirement beyond a well-formed message with a valid signature format (validated by `common.ValidatedRequestFromMessage`, not by identity/allowlist).

By contrast, the newer JSON-RPC v2 handlers in the same package apply per-node and global rate limiters before forwarding to nodes (see `nodeRateLimiter`/`globalNodeRateLimiter` usage in `http_handler.go` and `confidentialrelay/handler.go`) [5](#0-4) , and the Vault handler enforces `AllowListBasedAuth`/JWT authorization before any node dispatch [6](#0-5) . The legacy WebAPI trigger path in `handler.go` lacks this protection entirely, which is the exact same "missing quota/permission gate before a fan-out action" bug class as the reported `sendCurrentOperatorsKeys()` issue.

### Impact Explanation
Any unauthenticated caller reaching this legacy method can repeatedly submit `web_api_trigger` messages, each one causing the Gateway to send a message to **every node in the DON**. This can:
- Exhaust Gateway → DON connection bandwidth/queues.
- Cause resource exhaustion or throttling on individual DON nodes, potentially interfering with legitimate workflow execution (a griefing/DoS vector), analogous to the "griefing, resource exhaustion, race conditions" impact cited in the external report.
- Since `savedCallbacks` grows unbounded until the periodic prune runs (`CallbackPruneIntervalSec`, default 30s) and capped indirectly by `MaxSavedCallbacks` (default 20000) [7](#0-6) , high-volume spam could also pressure Gateway memory before eviction kicks in.

### Likelihood Explanation
Medium-to-High: the handler is reachable directly from `gateway.ProcessRequest`, which is invoked by the exposed HTTP server for any DON-ID-addressed legacy request. No credentials or workflow registration are required — the only gates are payload format and message staleness, both trivially satisfiable by an attacker.

### Recommendation
Apply the same protections already used elsewhere in the codebase: (1) enforce a per-sender and global rate limiter (as done via `nodeRateLimiter`/`globalNodeRateLimiter` in the v2 HTTP/ConfidentialRelay handlers) before dispatching `web_api_trigger` requests to DON members, and (2) add allowlist/authorization checks (similar to `AllowListBasedAuth` in the Vault handler) so only authorized senders can trigger fan-out to the DON. Resolve the outstanding `TODO` at `core/services/gateway/handlers/capabilities/handler.go:384` before this legacy path is exposed to untrusted clients.

### Proof of Concept
1. Send repeated legacy-format JSON-RPC requests to the Gateway's public HTTP endpoint with `DonId` set to a valid configured DON and `Body.Method = "web_api_trigger"`, each with a fresh `MessageId` and a current `Timestamp`.
2. Observe that `gateway.ProcessRequest` routes each to the legacy handler for that DON [8](#0-7) , which calls `HandleLegacyUserMessage`.
3. Because no allowlist or rate limit is applied (per the `TODO`), each request results in `don.SendToNode` being called once per DON member [3](#0-2) , multiplying a single attacker request into N node-directed messages, repeatable without limit.

	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)

			RawResponse: codec.EncodeNewErrorResponse(

				api.ToJSONRPCErrorCode(api.UserMessageParseError),

				nil,

		})

func (h *gatewayHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	if resp.ID == "" {
		return fmt.Errorf("received response with empty request ID from node %s", nodeAddr)
	}
	h.lggr.Debugw("handling incoming node message", "requestID", resp.ID, "nodeAddr", nodeAddr)
	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		h.metrics.IncrementCapabilityNodeThrottled(ctx, nodeAddr, h.lggr)
		return fmt.Errorf("rate limit exceeded for node %s", nodeAddr)
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		h.metrics.IncrementGlobalThrottled(ctx, h.lggr)
		return errors.New("global rate limit exceeded")
	}
