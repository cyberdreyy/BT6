### Title
`depositDuringEpoch` bypasses the pause modifier, allowing deposits while the vault is paused - ([File: contracts/IdleCDOEpochVariant.sol:656](contracts/IdleCDOEpochVariant.sol))

### Summary
The external report describes missing pause modifiers on user-facing functions. The idle-tranches analog is `depositDuringEpoch` in `IdleCDOEpochVariant`: it is the only deposit path that does not go through `_deposit` (which carries `whenNotPaused`), and it does not itself check `paused()`. When the owner or guardian calls `pause()` during a running epoch, deposits are expected to be halted, but `depositDuringEpoch` remains fully callable by any KYC-passing wallet.

### Finding Description
In `IdleCDOCreditVault._deposit`, deposits are gated by `whenNotPaused` (contracts/IdleCDOCreditVault.sol:191). The epoch variant's user entry points `depositAA`/`depositBB` inherit this. However, `depositDuringEpoch` (contracts/IdleCDOEpochVariant.sol:656) is a separate external entry point that reimplements the deposit flow and validates only:

```solidity
_checkNotAllowed(
  (_tranche == BBTranche && !isBBDepositEnabled) ||
  isDepositDuringEpochDisabled ||
  skipDefaultCheck ||
  isProgrammableBorrower ||
  isAYSActive ||
  !isEpochRunning || block.timestamp >= epochEndDate ||
  !isWalletAllowed(msg.sender)
);
```

There is no `paused()` check. `startEpoch()` calls `_pause()` and the epoch relies on `isEpochRunning`/`skipDefaultCheck` for its own gating, so during a normal running epoch `depositDuringEpoch` is intended to work. But if the guardian or owner explicitly calls `pause()` (or `emergencyShutdown` without a BB wipe — although that sets `skipDefaultCheck` and is covered), `paused()` becomes `true` while `isEpochRunning` is still `true` and `skipDefaultCheck` is still `false`. In that state:

- `depositAA`/`depositBB` revert with `Pausable: paused` via `_deposit`.
- `requestWithdraw` is already closed by `allowAAWithdrawRequest = false`/`allowBBWithdrawRequest = false` set in `startEpoch`.
- `depositDuringEpoch` still succeeds: it calls `_skimDonatedAssets`, `_updateAccounting`, mints tranche tokens at the discounted mid-epoch price (`_minted = (_amount + trancheInterest) * _trancheTotSupply / expectedFinal`), calls `IdleCreditVault.mintStrategyTokens`, and transfers the underlyings to the borrower.

Notably, `restoreOperations` (contracts/IdleCDOEpochVariant.sol:619) deliberately early-returns while `isEpochRunning`, meaning the codebase itself recognizes that `paused()` and `isEpochRunning` are independent states — a mid-epoch `pause()` is a supported administrative action, yet it fails to halt the mid-epoch deposit path.

### Impact Explanation
An unprivileged KYC'd lender can keep depositing into AA (or BB, if enabled) while the guardian/owner has explicitly paused the vault mid-epoch — for example because a problem with the borrower or pricing was detected. The attacker receives discounted tranche shares minted at the prorated-interest price and pushes fresh underlyings to the borrower, diluting existing holders' claim on `expectedEpochInterest` and growing the pool exactly when operators are trying to freeze it. The pause switch is ineffective for the only deposit path that is live mid-epoch, so the vault cannot actually halt inflows during an incident without calling `emergencyShutdown` (which additionally disables withdraw-request flags) or toggling `isDepositDuringEpochDisabled`.

### Likelihood Explanation
- Attacker preconditions: any wallet passing the Keyring check (`isWalletAllowed`), holding underlyings.
- Trigger: owner/guardian calls `pause()` during a running epoch. `pause()` is explicitly documented as pausing deposits (contracts/IdleCDOCreditVault.sol:517) and `unpause()` is blocked mid-epoch by `_beforeUnpause`, so the paused-mid-epoch state is reachable and persistent.
- No existing guard stops it: `depositDuringEpoch` checks `skipDefaultCheck` (set only by `_emergencyShutdown`/`_forceUpdateAccounting` paths) but never `paused()`.

### Recommendation
Add a pause check to `depositDuringEpoch`, e.g. include `paused()` in the `_checkNotAllowed` condition or add the `whenNotPaused` modifier, so that an explicit mid-epoch pause halts all deposit paths:

```solidity
_checkNotAllowed(
  paused() ||
  (_tranche == BBTranche && !isBBDepositEnabled) ||
  ...
);
```

Note `startEpoch` pauses via `_pause()` before `isEpochRunning` flips behavior, so if intentional, gate on `paused() && !isEpochRunning` semantics carefully — the clean approach is a dedicated `isDepositDuringEpochDisabled`-style flag or checking `paused()` only when the pause was *not* set by `startEpoch` (e.g., an explicit `depositsHalted` flag set in `pause()`/`emergencyShutdown()`).

### Proof of Concept
Foundry-style PoC against `test/foundry/IdleCreditVault.t.sol` fixtures:

```solidity
function testDepositDuringEpochWhilePaused() external {
  // setup: AYS disabled, depositDuringEpoch enabled, epoch started
  vm.startPrank(owner);
  cdoEpoch.setIsAYSActive(false);
  cdoEpoch.setIsDepositDuringEpochDisabled(false);
  vm.stopPrank();

  idleCDO.depositAA(10_000 * ONE_SCALE);
  _startEpochAndCheckPrices(0); // startEpoch pauses deposits, sets isEpochRunning

  // guardian/owner detects an issue and pauses mid-epoch
  vm.prank(owner);
  cdoEpoch.pause();
  assertTrue(cdoEpoch.paused());
  assertTrue(cdoEpoch.isEpochRunning());
  assertFalse(cdoEpoch.skipDefaultCheck());

  // normal deposits are blocked
  vm.expectRevert(bytes("Pausable: paused"));
  idleCDO.depositAA(ONE_SCALE);

  // but depositDuringEpoch still succeeds for a KYC'd attacker
  deal(defaultUnderlying, attacker, 1_000 * ONE_SCALE);
  vm.startPrank(attacker);
  IERC20(defaultUnderlying).approve(address(cdoEpoch), type(uint256).max);
  uint256 minted = cdoEpoch.depositDuringEpoch(1_000 * ONE_SCALE, address(AAtranche));
  vm.stopPrank();

  assertGt(minted, 0, "deposits still possible while paused");
  assertEq(defaultUnderlying.balanceOf(borrower), /* increased */ );
}
```

Key state: `paused() == true`, `isEpochRunning == true`, `skipDefaultCheck == false`, `isAYSActive == false`, `isProgrammableBorrower == false`, `block.timestamp < epochEndDate` — all `depositDuringEpoch` checks pass despite the active pause.
