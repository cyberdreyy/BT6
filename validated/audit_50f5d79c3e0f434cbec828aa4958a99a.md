### Title
`ExtractZipArchive` performs no path sanitization on zip entry names, enabling Zip Slip path traversal / arbitrary file write during artifact and cache extraction - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipFileEntry`, `extractZipSymlinkEntry`, `extractZipDirectoryEntry`) use `file.Name` directly from the zip entry, with `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(..., file.Name)`, without any `filepath.Clean`/traversal/absolute-path validation. The only content check performed is `errorIfGitDirectory`, which only rejects paths starting with a `.git` segment, not `..` traversal or absolute paths. This is a classic Zip Slip vulnerability.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` and, for each entry, calls `extractZipFile(file)` (line 61), which: [1](#0-0) 

This creates parent directories via `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, depending on file type, calls `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, or `extractZipFileEntry` — all of which perform filesystem writes using `file.Name` verbatim: [2](#0-1) 

The Go standard library's `archive/zip` does **not** sanitize `zip.File.Name` for path traversal or absolute paths — that responsibility is left to the consumer. The only validation applied before extraction is `errorIfGitDirectory`, which checks only whether the first path segment is `.git`: [3](#0-2) 

This is not a traversal or absolute-path guard. An attacker who controls the archive content (an artifact or cache archive uploaded by their own job, later consumed by a later stage/job/pipeline via `cache: paths` or `artifacts` extraction) can craft entry names such as `../../some/relative/path`, or an absolute path, or a symlink entry pointing outside the intended extraction root. Because `os.MkdirAll`/`os.OpenFile`/`os.Symlink` are called with that unsanitized name, extraction can write/create files and symlinks outside the intended cache/build/artifact root — including onto paths that later runner-generated shell steps `source` or execute (e.g., generated build/env scripts, shell profile files, or other stage script files under the job's build directory tree), if such paths are reachable via relative traversal from the extraction working directory.

The existing "checks" that might be assumed to stop this — `errorIfGitDirectory` and the `.git` warning — do not address `..`, absolute paths, or symlink-based traversal at all; they solve an unrelated problem (protecting the repository's `.git` directory from being clobbered during checkout-related unpacking). Tests in `helpers/archives/zip_extract_test.go` only cover a plain file extraction, a `.git` path warning, symlink mode preservation, and a not-found file — there is no test asserting that `..`/absolute paths are rejected, confirming the gap is not covered by design. [4](#0-3) 

Note that path validation performed elsewhere in the runner (`commands/helpers/cache_extractor_test.go`'s check for `/../../../test.zip`, `commands/helpers/file_archiver.go`'s `isChanged`/`process` restricting *source* files to be inside the build directory when *creating* an archive) governs the *archive file path itself* and *archive creation* — not the *entry names inside a zip being extracted*. That is a distinct code path from `ExtractZipArchive`, and does not mitigate this issue. [5](#0-4) 

### Impact Explanation
A job/pipeline author who controls the contents of a cache or artifact zip archive (attacker fully controls entry names/content of their own job's cache/artifact, which the Runner will later download and extract via `ExtractZipFile`/`ExtractZipArchive` for a subsequent job/stage) can cause the extraction step to write files outside the intended cache/build root. If that write lands on a path that a later runner-generated script step sources or executes (e.g. an environment file, a generated stage script, or another job's script if directories are shared/predictable), the attacker's file content is executed/sourced without any additional trust boundary being re-established — i.e. the archive extraction becomes a vector for planting executable/sourced content at a trusted path. This violates the invariant that "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
Preconditions: an unprivileged pipeline author is fully able to control cache/artifact archive bytes (both are user/job-controlled: `cache: paths`, `artifacts: paths`, and any custom zip uploaded through Runner's cache/artifact mechanisms flow through `ExtractZipArchive` when the corresponding job/stage restores them). Crafting a zip with `..`-relative or absolute entry names, or symlink entries, is trivial and fully reproducible — no race conditions or external services are required. The main uncertainty is the *scoped* multi-tenant impact: because the archive is typically the same job/project's own cache/artifact, exploiting this to affect a path executed by a *different* job or a *different* user requires either (a) shared/predictable extraction working directories across jobs on the same runner/host (e.g. shell executor with reused build dirs, or shared cache directories), or (b) a downstream job/pipeline that blindly extracts and later sources/executes attacker-supplied paths without revalidating them. This part of the exploit chain (finding a concrete cross-trust-boundary path collision on a given executor configuration) was not verified in this codebase pass and remains unconfirmed; the underlying missing sanitization in `ExtractZipArchive` itself, however, is unambiguous.

### Recommendation
In `helpers/archives/zip_extract.go`, before performing any filesystem operation for a zip entry, validate and normalize `file.Name`:
- Reject entries with absolute paths.
- Reject entries whose cleaned relative path (`filepath.Clean`) escapes the extraction root (contains a leading `..` after joining with the destination directory), mirroring the well-known Zip Slip fix pattern (`destPath := filepath.Join(destDir, file.Name); if !strings.HasPrefix(destPath, filepath.Clean(destDir)+string(os.PathSeparator)) { reject }`).
- Apply the same validation to symlink targets in `extractZipSymlinkEntry`, since the link target is also attacker-controlled and can point outside the extraction root.
- Add unit tests analogous to `TestExtractZipFileWithGitPath` that assert `..`/absolute-path/symlink-escape entries are rejected (or safely neutralized) rather than silently written outside the extraction root.

### Proof of Concept
Go unit test (to be added under `helpers/archives/zip_extract_test.go`):
1. Build a zip archive in memory containing an entry named `../evil.txt` (or `/tmp/evil.txt` on Unix).
2. Call `ExtractZipFile` from within a temp working directory.
3. Assert that no file was created outside the working directory (`os.Stat` on the resolved outside path should return `os.IsNotExist`) — currently, this assertion will FAIL, because the file is written to the parent directory / absolute path, demonstrating the traversal.
4. A second test case: build a zip with a symlink entry named `link` pointing to `../../etc/passwd`-style outside path, extract, and assert the symlink was not created pointing outside the extraction root.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}

func TestExtractZipFile(t *testing.T) {
	testOnArchive(t, createDefaultArchive, func(t *testing.T, fileName string) {
		err := ExtractZipFile(fileName)

		stat, err := os.Stat("temporary_file.txt")

	})

func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

	if err == nil {
		// Process path only if it lives in our build directory
		if !strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			excluded, rule := c.isExcluded(relative)
			if excluded {
				c.exclude(rule)
				return false
			}

			err = c.add(relative)
		} else {
			err = errors.New("not supported: outside build directory")
		}
	}
