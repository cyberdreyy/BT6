### Title
Permissionless `drift_harvest_reward` / `drift_claim_bad_debt` / `kamino_harvest_reward` bypass protocol/bank pause - ([File: programs/marginfi/src/instructions/drift/harvest_reward.rs])

### Summary
This is the same "inconsistent pause enforcement" bug class as gogopool's `restakeGGP`/`claimAndRestake`: some functions that move value out of a paused venue correctly check the pause state, while sibling permissionless functions performing withdrawals from the same underlying position skip the check entirely.

### Finding Description
Marginfi's documented pause design states that "Deposit, Borrow, Withdraw, Repay (both native banks and integration banks — Kamino, Drift, Juplend, Solend)" are blocked while paused [6](#0-5) , and this is enforced in code via `validate_bank_state` calls inside `drift_withdraw`, `drift_borrow`, `lending_account_borrow`, `lending_pool_emissions_deposit`, etc. [7](#0-6) .

However, `drift_harvest_reward` — an explicitly "(permissionless)" instruction that CPIs a `withdraw` from the bank's Drift user account (admin-deposit reward positions) and sweeps the proceeds to the global fee wallet — performs no `validate_bank_state` check and no `is_protocol_paused()` check anywhere in its handler or `Accounts` validation [8](#0-7) . The same is true of `drift_claim_bad_debt`, which CPIs into a merkle distributor to pull funds and sweep them out [4](#0-3) , and `kamino_harvest_reward`, which CPIs a harvest+withdraw from the bank's Kamino farm position [5](#0-4) . All three are callable by any signer at any time, including during an active `panic_pause` or a bank in `Paused`/`ReduceOnly` state, while the sibling `drift_withdraw` for the exact same underlying Drift user account is explicitly blocked in the paused state.

### Impact Explanation
The financial impact here is limited relative to the gogopool case because these instructions only move admin-seeded reward/bad-debt funds to a hardcoded `global_fee_wallet`/`fee_state`-controlled destination, not to an arbitrary depositor. There is no direct depositor fund drain or unauthorized value redirection to an attacker-controlled address — the destination accounts are pinned by `has_one`/`address` constraints to protocol-controlled wallets. The impact is therefore an inconsistency/functionality-continuation issue during an emergency pause (funds/CPI activity on a paused integration continues to execute) rather than a loss-of-funds or authorization bypass to a third party.

### Likelihood Explanation
Likelihood is low-to-moderate: exploitation requires no privilege (permissionless), but the "attacker" gains nothing beyond forcing state-changing CPI/interaction with an integration (Drift/Kamino) during a period the admin intended to be fully halted, which could interfere with incident investigation/remediation on that integration during the very window `panic_pause` is meant to freeze all activity.

### Recommendation
Add `validate_bank_state(&bank, InstructionKind::FailsInPausedState)` (or `FailsIfPausedOrReduceState`, depending on intended semantics) and/or a `!group.load()?.is_protocol_paused()` constraint to `DriftHarvestReward`, `DriftClaimBadDebt`, and `KaminoHarvestReward`, consistent with `drift_withdraw` and other integration withdraw paths, so that all functions capable of triggering an outbound CPI transfer from a bank's vault-controlled position are uniformly gated by pause/bank-state.

### Proof of Concept
1. Admin/`global_fee_admin` calls `panic_pause`, intending to freeze all protocol activity (as documented, this should block "all financial operations on all Groups and Banks" during the pause window) [9](#0-8) .
2. Any signer (no special role required) submits `drift_harvest_reward` for a Drift-integration bank; it executes `cpi_withdraw_from_position` and `cpi_transfer_to_destination` without any pause check, succeeding despite the pause [3](#0-2) .
3. Compare with `drift_withdraw` on the same bank at the same time, which fails with `MarginfiError::BankPaused`/`ProtocolPaused` because it calls `validate_bank_state` [2](#0-1) , demonstrating the inconsistency between sibling functions acting on the same underlying integration position — directly analogous to `restakeGGP`/`claimAndRestake` bypassing `whenNotPaused` while `stakeGGP`/`withdrawGGP` enforced it.

        remaining_accounts: &[AccountInfo<'info>],

        let program = self.drift_program.to_account_info();

            state: self.drift_state.to_account_info(),

            user_stats: self.integration_acc_3.to_account_info(),
            authority: self.liquidity_vault_authority.to_account_info(),

            user_token_account: self.intermediary_token_account.to_account_info(),
            token_program: self.token_program.to_account_info(),
        };

        let bump = self.bank.load()?.liquidity_vault_authority_bump;

        withdraw(cpi_ctx, market_index, u64::MAX, true)?;
        Ok(())
    }

pub fn drift_claim_bad_debt<'info>(
    ctx: Context<'info, DriftClaimBadDebt<'info>>,
    amount: u64,
    proof: Vec<[u8; 32]>,
) -> MarginfiResult {
    ctx.accounts.create_claimant_token_account()?;
    ctx.accounts.create_destination_token_account()?;
    ctx.accounts.prefund_claim_status()?;
    let pre_claim_balance = ctx.accounts.claimant_token_balance()?;
    ctx.accounts.cpi_new_claim(amount, proof)?;
    let post_claim_balance = ctx.accounts.claimant_token_balance()?;
    let received_amount = post_claim_balance
        .checked_sub(pre_claim_balance)
        .ok_or_else(|| error!(MarginfiError::InternalLogicError))?;
    let swept_amount = ctx.accounts.cpi_transfer_to_destination()?;
    ctx.accounts
        .emit_claim_event(amount, received_amount, swept_amount)?;
    Ok(())
}

pub fn validate_bank_state(bank: &Bank, kind: InstructionKind) -> MarginfiResult {
    if bank.config.operational_state == BankOperationalState::KilledByBankruptcy {
        return err!(MarginfiError::BankKilledByBankruptcy);
    }
    // Bank exists but has not completed one-time setup (e.g. JupLend seed deposit). Block every
    // operation until init runs.
    if bank.config.operational_state == BankOperationalState::Uninitialized {
        return err!(MarginfiError::BankUninitialized);
    }

    match kind {
        InstructionKind::FailsInReduceState if bank.config.operational_state.is_reduce_only() => {
            return err!(MarginfiError::BankReduceOnly);
        }

        InstructionKind::FailsInPausedState
            if bank.config.operational_state == BankOperationalState::Paused =>
        {
            return err!(MarginfiError::BankPaused);
        }

        InstructionKind::FailsIfPausedOrReduceState
            if matches!(
                bank.config.operational_state,
                BankOperationalState::Paused
                    | BankOperationalState::ReduceOnly
                    | BankOperationalState::ReduceOnlyWithBorrowingPower
            ) =>
        {
            return match bank.config.operational_state {
                BankOperationalState::Paused => {
                    err!(MarginfiError::BankPaused)
                }
                state if state.is_reduce_only() => {
                    err!(MarginfiError::BankReduceOnly)
                }
                _ => unreachable!(),
            };
        }
        _ => {}
    }

    Ok(())
}
