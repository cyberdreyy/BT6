### Title
Stale `emissions_destination_account` persists across account ownership transfer, redirecting off-chain emissions to the previous owner - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
When an account authority calls `transfer_to_new_account`/`transfer_to_new_account_pda` to move a marginfi position to a new authority, `initialize_migrated_account` blindly copies the old account's `emissions_destination_account` field onto the new account. If the previous owner had pointed this field at their own wallet (a very common configuration, since it defaults to the authority per the emissions guide), the new authority inherits a "collector" address they never set and do not control, redirecting reward flows to the old owner until the new owner notices and manually resets it.

### Finding Description
`transfer_to_new_account` and `transfer_to_new_account_pda` create a brand-new `MarginfiAccount` and populate it via `initialize_migrated_account`: [1](#0-0) 

Line 32 explicitly carries the old account's `emissions_destination_account` into the new account: `new_account.emissions_destination_account = old_account.emissions_destination_account;`. This is the same class of bug as the UNCX report: a "collector"/beneficiary address configured by the previous owner is not reset (or forced to be re-set) when the underlying position is transferred to a new owner.

`emissions_destination_account` is a user-settable field, changed only via `marginfi_account_update_emissions_destination_account`, gated on the *current* `authority` of the account: [2](#0-1) [3](#0-2) 

The field is documented as the destination for real off-chain airdropped incentive/emissions value: "Emissions/incentives are delivered by airdrop to the Account's authority... Want your emissions delivered somewhere specific? Set up an `emissions_destination_account`": [4](#0-3) 

The integrator guide reinforces that this field matters specifically for PDA-owned accounts, i.e. exactly the accounts most likely to be migrated/transferred via `transfer_to_new_account_pda`: "Highly encouraged if the Account is owned by a PDA. All emissions will be sent here instead of the authority": [5](#0-4) 

The project's own test suite acknowledges this gap is unverified — a TODO comment sits right after the transfer tests with no assertion covering the migrated `emissions_destination_account` value: [6](#0-5) 

Root cause: `initialize_migrated_account` treats `emissions_destination_account` as account-level state to be preserved (like `lending_account` balances), but it is actually authority-scoped configuration (like the UNCX `collector`/`additionalCollector` addresses), and should either be reset to `Pubkey::default()`/the new authority, or the new authority should be forced to explicitly reconfirm it.

### Impact Explanation
Emissions/incentive campaigns are a real financial value stream distributed by off-chain indexers reading on-chain `emissions_destination_account`. If a user sells/transfers their leveraged/LP position (via `transfer_to_new_account`/`transfer_to_new_account_pda`, e.g. as part of a third-party integration migrating a PDA-owned account to a new owner) after having pointed emissions at their own wallet, the buyer/new owner's subsequent emissions continue flowing to the seller's wallet until the new owner notices and calls `marginfi_account_update_emissions_destination_account`. This is a value-redirection bug with real financial effect, not a cosmetic issue — it silently misdirects incentive rewards for a party (previous owner) with no remaining claim to the position.

### Likelihood Explanation
This is highly reachable: `transfer_to_new_account`/`transfer_to_new_account_pda` are permissionless, first-party instructions intended for regular use (account migration, PDA-based custody transfer to third-party owners), not admin-gated. Any account owner who has ever set `emissions_destination_account` (recommended for all PDA-owned accounts per the integrator guide) and later transfers the account will trigger this by default with zero extra attacker action — it happens automatically as part of intended protocol usage, and requires no cooperation or error by the new owner besides being unaware of the stale field.

### Recommendation
In `initialize_migrated_account` (`programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`), do not copy `emissions_destination_account` from the old account. Instead reset it to `Pubkey::default()` on the new account, mirroring how `lending_account` is zeroed for the old account after migration, and require the new authority to explicitly call `marginfi_account_update_emissions_destination_account` if they want a custom destination (this is consistent with the existing recommendation to set it up per new PDA account, and matches the UNCX fix pattern of resetting collector-style addresses on ownership transfer).

### Proof of Concept
1. Authority A creates a marginfi account and calls `marginfi_account_update_emissions_destination_account` to set `emissions_destination_account = A` (own wallet) — a normal, encouraged action for PDA accounts per `GETTING_STARTED_INTEGRATOR.md`.
2. A deposits into an emissions-bearing bank, then calls `transfer_to_new_account_pda` to migrate the account/position to new authority B (e.g., selling the leveraged position to B).
3. Per `initialize_migrated_account` (`transfer_account.rs:32`), the new account owned by B is created with `emissions_destination_account = A`, not `Pubkey::default()` or B.
4. Off-chain emissions accrue on B's new account and are airdropped to `emissions_destination_account`, which still resolves to A's wallet, even though B now owns 100% of the underlying position.
5. B receives none of the incentive rewards until B independently discovers the stale field and calls `marginfi_account_update_emissions_destination_account` to reset it — verifiable against the unaddressed `emissions_destination_account` assertion gap flagged by the `// TODO emissions destination and/or flags?` comment in `tests/specs/basic/12_transfer_account.spec.ts:270`.

```rust
fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}
```

```rust
/// (account authority) Set the wallet whose canonical ATA will receive
/// off-chain emissions distributions.
pub fn marginfi_account_update_emissions_destination_account(
    ctx: Context<MarginfiAccountUpdateEmissionsDestinationAccount>,
) -> MarginfiResult {
    let mut marginfi_account = ctx.accounts.marginfi_account.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_FROZEN),
        MarginfiError::AccountFrozen
    );

    marginfi_account.emissions_destination_account = ctx.accounts.destination_account.key();
    Ok(())
}
```
