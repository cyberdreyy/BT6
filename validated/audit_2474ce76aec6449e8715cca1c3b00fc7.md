### Title
Pre-planted symlink in shared cache defeats tarzstd extractor's path-traversal check, allowing extraction outside `e.dir` - (File: `commands/helpers/archive/tarzstd/tarzstd_extractor.go`)

### Summary
`extractor.Extract` validates extraction targets only by textual prefix-matching the joined, `filepath.Abs`-resolved path against `e.dir`, without ever resolving symlinks that may already exist on disk at intermediate path components. A job that shares a cache/build directory with a later job (e.g. via a reused cache key, or a checkout/cache dir that is not wiped between jobs) can pre-plant a symlink so that a subsequent tarzstd cache extraction writes files through that symlink to a location outside `e.dir`.

### Finding Description
The check at [1](#0-0)  only performs a string comparison on the computed absolute path (`filepath.Abs(filepath.Join(e.dir, hdr.Name))`). It never calls anything like `filepath.EvalSymlinks` or `os.Lstat` on the intermediate directory components, so it cannot detect that a component of the path already exists on disk as a symlink pointing outside `e.dir`.

Symlink tar entries are deliberately deferred and only created after all regular files/dirs, via `os.Symlink(hdr.Linkname, path)` at [2](#0-1) , and the code correctly refuses to let a symlink *entry in the same archive* be traversed before it's created. However, this only protects against symlinks introduced *by the current archive being extracted* — it does nothing about symlinks that were left on disk by an **earlier** extraction into the same directory tree (e.g. from a previous job/cache-restore/cache pre-population that reused the same `e.dir`).

Exploit flow:
1. Job A (attacker-controlled) restores/creates a cache archive whose payload contains a symlink entry, e.g. `hdr.Name = "shared/link"` with `Linkname` pointing to an attacker-chosen outside path (or to a path that will later be joined with attacker content), and this cache is stored under a cache key that a later job B will also pull (e.g., same branch cache key, fallback cache key, or a distributed/shared cache path that persists across pipelines of the same project).
2. When Job A's archive is extracted, the deferred-symlink logic at line 114 creates `e.dir/shared/link -> /outside/target` on disk exactly as designed (this alone is not a bug — it's within `e.dir`).
3. Job B (run later, sharing/reusing the same working directory `e.dir`, e.g. because `GIT_STRATEGY=none`/no clean, or the same build/cache dir is reused across pipeline runs) triggers extraction of a cache archive whose `hdr.Name` is `"shared/link/payload"`.
4. `filepath.Join(e.dir, "shared/link/payload")` textually starts with `e.dir` and passes the check at line 62.
5. `os.MkdirAll(filepath.Dir(path), 0777)` (line 66) and/or `os.Create(path)` (line 88) then operate on the *real* filesystem path, where the OS resolves `shared/link` as a symlink and follows it to `/outside/target`, so the file is actually written outside `e.dir` despite the textual check having passed.

Existing protections are insufficient because: the check is purely lexical/string-based on a path that was never verified against the actual on-disk directory tree; there is no `Lstat`-walk of each path component, and no use of a "secure join" that refuses to cross pre-existing symlinks (similar to `securejoin.SecureJoin`, which is notably used elsewhere in the codebase, e.g. `commands/helpers/file_archiver.go`, but not here).

### Impact Explanation
An attacker who can influence the contents of a cache archive that will later be extracted into a directory reused by a subsequent job can cause that later extraction to write attacker-controlled file content to an arbitrary filesystem location reachable by the runner process (outside the intended build/cache root), violating the invariant that file operations must stay within the intended build/cache/artifact root. Depending on where the symlink points, this can overwrite files consumed by the later job (e.g., scripts, other cached content, or shared runner state), leading to cache/build poisoning or code execution in the later job's context.

### Likelihood Explanation
Requires that two extractions share the same `e.dir` (same working/cache directory) across jobs — realistic when: the cache key is reused/shared across pipelines/branches of a project (fallback cache keys, shared cache key across MRs), or the build directory is not cleaned between jobs (`GIT_STRATEGY=none`, custom `builds_dir` reuse). This is attacker-reachable purely through normal job configuration (cache key names, `.gitlab-ci.yml` cache paths) without any admin misconfiguration of privileged containers or host mounts, and is deterministically reproducible.

### Recommendation
Resolve path traversal against the real filesystem rather than lexically: verify each existing intermediate path component is not a symlink (e.g. `os.Lstat` walk) or use a secure-join primitive (like `github.com/cyphar/filepath-securejoin`, already available in the codebase) that refuses to resolve through pre-existing symlinks that lead outside `e.dir`, and reject/abort extraction when such a component is detected, for both directory-creation (`MkdirAll`) and file-creation (`Create`) code paths.

### Proof of Concept
Go test in `commands/helpers/archive/tarzstd/tarzstd_extractor_test.go`:
1. Create a temp dir `root` to act as `e.dir`.
2. Manually create `root/shared` as a symlink pointing to another temp dir `outside` (simulating leftover state from a prior extraction).
3. Build a tar+zstd stream containing a single regular file entry `shared/payload` with attacker content.
4. Call `NewExtractor(reader, size, root).Extract(ctx)`.
5. Assert that `Extract` either returns an error (desired fixed behavior) or, in the current vulnerable code, succeeds and the file is found at `outside/payload` (proving escape) rather than failing—demonstrating the bug: `assert.NoFileExists(t, filepath.Join(root, "shared", "payload"))` and `assert.FileExists(t, filepath.Join(outside, "payload"))` on unpatched code.
