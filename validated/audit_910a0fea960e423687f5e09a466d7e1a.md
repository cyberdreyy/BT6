### Title
Stale confirmations from removed multisig members remain counted toward the approval threshold - (File: multisig2/src/lib.rs, multisig/src/lib.rs)

### Summary
### Finding Description
The multisig contracts enforce a `k`-of-`n` approval rule: a pending request executes once `confirmations.len() + 1 >= num_confirmations` [1](#0-0) . That check implicitly assumes every entry recorded in `confirmations` still belongs to a currently active member of the multisig, i.e. the binding `confirmations counted == confirmations by live members`.

`delete_member` breaks this binding. When a member is removed, it only deletes **requests that member itself created** (`r.member == member`) and clears the `num_requests_pk` counter for that member; it never scans `self.confirmations` to strip that member's confirmation from **other members' still-pending requests**: [2](#0-1) 

The same gap exists in the v1 contract: `DeleteKey` removes requests signed by the deleted key and clears `num_requests_pk`, but leaves stale entries inside `self.confirmations` for requests created by other keys: [3](#0-2) 

As a result, a confirmation cast by a member who is later removed continues to be counted by `confirm()` (`multisig2/src/lib.rs:294-315`, `multisig/src/lib.rs:246-266`) toward `num_confirmations`, even though that member is no longer part of the multisig and no longer holds signing authority over it.

### Impact Explanation
This lets a request execute with fewer live-member confirmations than `num_confirmations` requires. Concretely: with `num_confirmations = 3` and members {A, B, C, D}, if A confirms a transfer request created by B, and A is subsequently removed via `DeleteMember`/`DeleteKey`, the request still shows 1 confirmation from A. Only B (creator) and one more live member (C) then need to confirm to reach the "3" threshold via `confirm()`'s `len()+1 >= num_confirmations` check, even though only 2 of the current 3 members (B, C) ever approved it. This is a threshold executed with fewer than the configured number of live approvers — a `MultiSigRequestAction::Transfer` or `FunctionCall` can move funds/authority out of the account below the intended quorum, matching the "multisig request executed below threshold" Critical impact category.

### Likelihood Explanation
Membership changes (`DeleteMember`/`DeleteKey`) combined with pre-existing pending requests are a normal, expected operational sequence for these wallets (e.g., rotating keys/removing a compromised or departing signer while other requests are in flight). No privileged foundation action or victim key compromise is required beyond the normal multisig governance flow already exposed by the contract's own API, so the precondition is easily reachable by the existing membership performing routine key/member rotation.

### Recommendation
When removing a member (`delete_member` in `multisig2/src/lib.rs`, and the `DeleteKey` branch in `multisig/src/lib.rs`), iterate over **all** pending requests' confirmation sets (not just the requests created by that member) and remove the departing member's identifier (`account_id`/`public_key` string) from each, mirroring the fix pattern of decrementing the stale counter before it is trusted again — i.e., purge the removed member's confirmations everywhere, not only on their own requests, before allowing `confirm()` to keep treating the stored `confirmations.len()` as a live-member count.

### Proof of Concept
1. Deploy `multisig2` with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `B` calls `add_request` to create a `Transfer` request `R` (receiver arbitrary, amount = X). `R` has 0 confirmations.
3. `A` calls `confirm(R)` → `confirmations[R] = {A}` (1 confirmation, request not yet executed).
4. Members execute `DeleteMember { member: A }` via governance (self-request confirmed by quorum) — `delete_member` removes A from `self.members`, deletes only requests where `r.member == A` (none, since R was created by B), and leaves `confirmations[R] = {A}` untouched.
5. `C` calls `confirm(R)` → `confirmations[R].len() == 2`, `2 + 1 >= 3` → `execute_request(R)` fires, transferring funds.
6. Only B and C (2 live members) actually approved `R`, yet the configured `num_confirmations = 3` threshold was reported as satisfied because A's stale confirmation, cast before removal, was still counted — funds moved below the intended approval threshold.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
