### Title
Global (non-namespaced) `requestID` keyspace in `httpTriggerHandler.setupCallback` allows cross-tenant request-ID collision DoS - (File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go)

### Summary
`httpTriggerHandler` stores in-flight requests in a single map keyed only by the client-supplied `requestID`, with no scoping by workflow, owner, or JWT identity. Any authorized caller can pre-register an arbitrary `requestID` for their own (authorized) workflow, and if a different tenant later submits a legitimate request using the same `requestID`, `setupCallback` will reject it with `jsonrpc.ErrConflict` before any work is done for that victim request.

### Finding Description
`HandleUserTriggerRequest` validates the request, authorizes it against the caller's own workflow via `h.authorizeRequest` (which only checks that the caller is permitted to trigger *that* workflow, not that the `requestID` is unique to them), then calls `h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)` [1](#0-0) .

`setupCallback` performs the collision check purely against the global `h.callbacks` map keyed by `requestID`:
```go
if _, found := h.callbacks[requestID]; found {
    h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, ...)
    return nil, fmt.Errorf("in-flight request ID: %s", requestID)
}
``` [2](#0-1) 

The `callbacks` field is explicitly documented and implemented as a global `map[string]savedCallback` with no per-workflow or per-owner namespacing: `callbacks map[string]savedCallback // requestID -> savedCallback` [3](#0-2) .

`requestID` originates entirely from the client-controlled JSON-RPC `req.ID` field. The only validation applied is `validateRequestID`, which rejects empty IDs and IDs containing `/`, but does not enforce uniqueness scoping to a workflow/owner/JWT subject [4](#0-3) . `authorizeRequest` only verifies the JWT/key is authorized for the target `workflowID`; it never ties `requestID` to that identity [5](#0-4) .

Because the map is shared across all workflows/tenants served by the same gateway instance, an attacker who is authorized for *any* workflow (their own) can send a request with `requestID = X` first. While that entry remains in `h.callbacks` (until the response arrives or `reapExpiredCallbacks` reaps it after `CleanUpPeriodMs`), any other tenant's legitimate request that happens to use the same `requestID = X` for a completely unrelated workflow will hit the `found` branch and be rejected with `ErrConflict`, never being dispatched to any DON shard.

### Impact Explanation
This is a targeted, per-request denial of service against a specific victim execution, contingent on the attacker being able to predict/observe the victim's `requestID` before submission (e.g., sequential counters, timestamp-derived, or otherwise low-entropy client-generated IDs). The attacker does not need the victim's credentials — only a valid JWT for their own workflow — and the collision keyspace is entirely global across tenants, which violates the isolation invariant that one user's request namespace should not affect another's.

### Likelihood Explanation
Exploitability depends heavily on whether `requestID`s are predictable. If client SDKs/callers generate `requestID` as high-entropy UUIDs, practical collision prediction is infeasible. If any caller (or a class of callers) uses low-entropy or sequential/timestamp-based IDs, the attack is straightforward and repeatable: the attacker only needs to win a race to submit a colliding `requestID` before the victim, and the in-flight window persists until `CleanUpPeriodMs` expiry or the legitimate response arrives, giving a reasonably wide race window.

### Recommendation
Scope the `callbacks` map key (and the conflict check) to include the caller identity/owner or workflowID in addition to `requestID` (e.g., key by `workflowID + "/" + requestID` or `authorizedOwner + "/" + requestID`), so that request-ID collisions can only occur within a single tenant's own namespace rather than globally across all workflows/tenants.

### Proof of Concept
Go handler-level test plan in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler_test.go`:
1. Register two distinct workflows/owners (`workflowA`, `workflowB`) with the `WorkflowMetadataHandler`, each with valid JWTs/keys, as done via `registerWorkflow` helper.
2. Build `reqA` for `workflowA` with `ID = "shared-id"` and call `handler.HandleUserTriggerRequest(ctx, reqA, callbackA, time.Now())`; assert it succeeds and `handler.callbacks["shared-id"]` is populated.
3. Before `reqA`'s callback is cleaned up (do not resolve/close it), build `reqB` for `workflowB` (different owner/workflowID) with the same `ID = "shared-id"` and call `handler.HandleUserTriggerRequest(ctx, reqB, callbackB, time.Now())`.
4. Assert `HandleUserTriggerRequest` returns an error and `callbackB` received a `jsonrpc.ErrConflict` response via `requireUserErrorSent(t, payload, jsonrpc.ErrConflict)`, even though `reqB` belongs to a completely different, unrelated, and independently-authorized workflow — demonstrating cross-tenant `requestID` collision blocking a legitimate, unrelated caller's request.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
