### Title
Zip extraction allows symlink creation with attacker-controlled target and subsequent write-through - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipSymlinkEntry` creates a filesystem symlink using the raw bytes read from the zip entry's content as the target, with no validation that the target stays within the extraction directory. A later entry in the same archive (or an external process) that writes to the symlink's path will follow it, allowing writes outside the intended cache/artifact root.

### Finding Description
`extractZipFile` dispatches based on `file.Mode() & os.ModeType`; for `os.ModeSymlink` it calls `extractZipSymlinkEntry`, which reads the symlink's target from the entry's content via `io.ReadAll(in)` and calls `os.Symlink(string(data), file.Name)` directly, with no check on the target string (absolute path, `../` traversal, etc.) [1](#0-0) . Neither `extractZipFile` nor `ExtractZipArchive` validate `file.Name` (the symlink path itself) or the symlink target against the extraction root; the only existing content check, `errorIfGitDirectory`, only rejects paths under `.git`, unrelated to traversal [2](#0-1) [3](#0-2) . When `extractZipFileEntry` processes a subsequent zip entry whose name is `<symlink>/<subpath>`, `os.OpenFile` follows the previously-created symlink and writes through it, and there is no re-validation that the destination the OS actually opens is still under the extraction root [4](#0-3) . `ExtractZipFile`/`ExtractZipArchive` are invoked by `cache-extractor` on the `.File` payload (the local cache archive) after downloading it from the cache backend [5](#0-4) .

### Impact Explanation
An attacker who controls the cache/artifact zip content (self-authored cache, or artifact that is later restored) can craft an archive that creates a symlink pointing to an arbitrary path (e.g., a directory outside the job workspace that the runner process has write access to) and then include a second entry whose name traverses through that symlink to write a file at an attacker-chosen location outside `wd`/cache root, e.g. overwriting files the runner user can write to, or planting files in other locations under the same filesystem the CI job/runner user can access.

### Likelihood Explanation
This is fully attacker-controlled end-to-end: cache/artifact archives are typically produced and consumed by the same project's pipeline, so an attacker can trivially construct such a zip (via direct archive/zip manipulation rather than the normal `cache-archiver`, since a job can supply any bytes for a cache file if it controls how the cache is populated, or via key/paths that let it inject arbitrary content). It's deterministic and repeatable — no race condition or timing dependency, just ordered zip entries.

### Recommendation
- Validate the symlink target (`data`) in `extractZipSymlinkEntry`: reject absolute targets and resolve relative targets against the entry's directory, ensuring the resolved path stays within the extraction root, before calling `os.Symlink`.
- Additionally validate `file.Name` for every entry (dir, symlink, file) to ensure `filepath.Clean(file.Name)` does not escape the extraction root (no leading `/`, no `..` after cleaning) — this protects against both the symlink target and the zip-slip-style path traversal in the entry name.
- Consider tracking symlinks created during extraction and refusing to extract/write through any path component that is a symlink pointing outside the root (defense in depth against the "second colluding entry" write-through).

### Proof of Concept
```go
func TestExtractZipArchive_SymlinkTraversal(t *testing.T) {
    dir := t.TempDir()
    outsideDir := t.TempDir() // simulates path outside extraction root

    zipPath := filepath.Join(dir, "cache.zip")
    f, _ := os.Create(zipPath)
    zw := zip.NewWriter(f)

    // Entry 1: symlink "link" -> outsideDir
    hdr := &zip.FileHeader{Name: "link"}
    hdr.SetMode(os.ModeSymlink | 0777)
    w, _ := zw.CreateHeader(hdr)
    w.Write([]byte(outsideDir))

    // Entry 2: file "link/pwn.txt" written through the symlink
    w2, _ := zw.Create("link/pwn.txt")
    w2.Write([]byte("pwned"))

    zw.Close()
    f.Close()

    oldWd, _ := os.Getwd()
    os.Chdir(dir)
    defer os.Chdir(oldWd)

    err := archives.ExtractZipFile(zipPath)
    require.NoError(t, err)

    // Assert: pwn.txt must NOT exist under outsideDir
    _, statErr := os.Stat(filepath.Join(outsideDir, "pwn.txt"))
    assert.True(t, os.IsNotExist(statErr), "file was written outside extraction root via symlink pivot")
}
```
Expected (buggy) behavior today: `pwn.txt` is created inside `outsideDir`, proving the traversal; a fixed implementation should reject the symlink target or the write-through path and the assertion should pass (`os.IsNotExist` true).

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
