### Title
Missing per-instance authorization in ExportDKGResult allows any edit-role session to exfiltrate DKG secret packages for unrelated instances - (File: core/web/vault_controller.go)

### Finding Description
`VaultController.ExportDKGResult` decodes the request body into `ExportDKGResultRequest{InstanceID string}` and, aside from checking the field is non-empty, performs no authorization or ownership check that ties the caller/session to that specific `InstanceID`: [1](#0-0) 

It directly calls `orm.ReadResultPackage(ctx, dkgocrtypes.InstanceID(req.InstanceID))`, which performs a flat `SELECT ... FROM dkg_results WHERE instance_id = $1` with no owner/session/tenant column in the query or table: [2](#0-1) 

The `dkg_results` table itself is keyed only by `instance_id`, with no notion of which user/session/job originated or is entitled to a given instance, as confirmed by `WriteResultPackage`'s INSERT statement (`instance_id, config_digest, seq_nr, report_with_result_package, signatures, signer_oracle_ids`) with no owner/tenant field: [3](#0-2) 

Any caller who reaches this route with the node's generic edit-role authentication (the standard requirement for POST routes in this router, as opposed to any instance-specific credential) can supply an arbitrary/guessed `InstanceID` string and receive the full hex-encoded `ReportWithResultPackage` and its SHA-256 digest for that instance via `presenters.NewExportDKGResultResource`, regardless of whether that instance's DKG run has any relationship to the caller. The same pattern exists in `VerifyDKGResult`, which also takes an arbitrary `InstanceID` from the request body with no ownership check.

### Impact Explanation
If `InstanceID`s are not treated as secrets and are guessable/enumerable (e.g., sequential, derived from public job/proposal IDs, or otherwise discoverable), this endpoint discloses DKG result packages — which contain sensitive cryptographic material tied to other DKG runs/tenants — to any edit-role-authenticated caller, not just the party that owns/operates that specific DKG instance. This matches a key/secret disclosure and cross-tenant response confusion impact class.

### Likelihood Explanation
Exploitability depends entirely on how unpredictable/secret `InstanceID` values are treated elsewhere in the system (this could not be fully confirmed from the code reachable in this review — the instance ID generation/scoping logic lives outside `core/web/vault_controller.go` and `core/services/ocr2/plugins/vault/orm.go`, and I was not able to locate code that binds an `InstanceID` to a particular caller/session at write time or read time within the reviewed files). If `InstanceID` values are effectively public or low-entropy identifiers (as is common for job/proposal identifiers), the attack is trivial and repeatable for any edit-role token holder. If `InstanceID` is itself treated as an unguessable secret/capability token, the practical exploitability is much lower, though the code still lacks a defense-in-depth ownership check.

### Recommendation
Add an explicit authorization check in `ExportDKGResult` (and `VerifyDKGResult`) that verifies the requesting session/user is associated with the specific `InstanceID` before returning `ReportWithResultPackage` — e.g., by introducing an owner/tenant column on `dkg_results` populated at `WriteResultPackage` time and checking it against the authenticated caller in the controller, rather than relying solely on generic edit-role middleware and knowledge of the instance ID string.

### Proof of Concept
1. Using `WriteResultPackage`, insert two distinct `dkg_results` rows for `InstanceID` "instance-A" and `InstanceID` "instance-B" with different `ReportWithResultPackage` payloads.
2. Establish a single edit-role authenticated test session/client (no special relationship to either instance).
3. POST `{"instanceId": "instance-B"}` to `/v2/vault/dkg_results/export` using that session.
4. Assert the handler returns HTTP 200 with `instance-B`'s `ReportWithResultPackage` hex/SHA, demonstrating the same generic edit-role credential retrieves secret material for an instance the caller has no established relationship to.
5. Compare against the intended invariant: if instance-scoped authorization were enforced, step 4 should return 403/404 instead of the package — its absence in the current handler code confirms the authorization gap.

func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")

func (o *orm) ReadResultPackage(ctx context.Context, iid dkgocrtypes.InstanceID) (*dkgocrtypes.ResultPackageDatabaseValue, error) {
	var configDigest []byte
	var seqNr uint64
	var reportWithResultPackage []byte
	var signatures pq.ByteaArray
	var signerOracleIDs []byte

	query := `SELECT config_digest, seq_nr, report_with_result_package, signatures, signer_oracle_ids FROM dkg_results WHERE instance_id = $1;`
	row := o.ds.QueryRowxContext(ctx, query, iid)
	err := row.Scan(&configDigest, &seqNr, &reportWithResultPackage, &signatures, &signerOracleIDs)
	if errors.Is(err, sql.ErrNoRows) {
		return nil, nil
	}
	if err != nil {
		return nil, errors.Wrap(err, "failed to read dkg result")
	}

	var cd types.ConfigDigest
	copy(cd[:], configDigest)

	attributedSigs := make([]types.AttributedOnchainSignature, len(signatures))
	for i := range signatures {
		attributedSigs[i] = types.AttributedOnchainSignature{
			Signature: signatures[i],
			Signer:    commontypes.OracleID(signerOracleIDs[i]),
		}
	}

	value := &dkgocrtypes.ResultPackageDatabaseValue{
		ConfigDigest:            cd,
		SeqNr:                   seqNr,
		ReportWithResultPackage: reportWithResultPackage,
		Signatures:              attributedSigs,
	}

	return value, nil
}
