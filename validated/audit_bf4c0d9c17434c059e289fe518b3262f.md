### Title
Unbounded externally-derived interest in programmable-borrower mode lets a vault share-price donation mint unbacked strategy tokens and inflate tranche prices - (contracts/IdleCDOEpochVariant.sol)

### Summary
The external report's bug class — "does not properly constrain" an externally reachable component feeding internal processing (unvalidated external data source) — maps onto `IdleCDOEpochVariant._stopEpoch`, which trusts `IProgrammableBorrower.totalInterestDueNow()` as the source of truth for epoch interest. That value is derived from a third-party ERC4626 vault's `convertToAssets` share price (`ProgrammableBorrower._vaultNetInterest`), which any unprivileged vault depositor can inflate by directly transferring underlying to the vault (a donation/inflation move). The only sanity bound on gross interest (`maxApr` check) is unreachable in programmable mode, so the inflated figure is minted as unbacked strategy tokens and crystallized into tranche prices — letting a dominant LP redeem real borrower-backed principal while leaving unbacked NAV to remaining LPs.

### Finding Description
In programmable-borrower mode, `_resolveStopEpochInterest` forces `_interest ∈ {0,1}` and returns `IProgrammableBorrower(_borrower()).totalInterestDueNow()` (contracts/IdleCDOEpochVariant.sol:1001-1008) [1](#0-0) . `totalInterestDueNow` = borrower interest + buffer interest + `_vaultNetInterest()`, where the vault PnL is computed from `_currentVaultAssets()` (i.e., `vault.convertToAssets(vault.balanceOf(this))`) minus the snapshotted baseline (contracts/strategies/idle/ProgrammableBorrower.sol:330-347) [2](#0-1) . Any assets donated to the ERC4626 vault during the epoch (or during the buffer, via `bufferedVaultDelta` at line 210) are counted as "vault interest".

The maxApr cap check is gated on `_mintInterest && _interest > 1` (contracts/IdleCDOEpochVariant.sol:377-380), but programmable mode reverts if `_interest > 1`, so the externally supplied interest is never bounded [3](#0-2) . In minted-interest mode the strategy mints `_grossInterest` strategy tokens to the CDO (`_strategy.mintStrategyTokens(_grossInterest)`, line 430) with no underlying transferred (`_amountToPullFromBorrower = 0`), and `_updateAccounting()` raises tranche prices on that unbacked NAV [4](#0-3) .

Attack path (unprivileged attacker = user of the programmable borrower's ERC4626 vault + KYC'd AA holder):
1. During the buffer, attacker deposits a large AA position into the CDO (dominant LP share `f_CDO ≈ 1`) and deposits underlying into the external ERC4626 vault so they hold `f_vault` of its shares.
2. Epoch starts (`isInterestMinted = true`, `isProgrammableBorrower = true`). Mid-epoch, attacker direct-transfers `D` underlying to the vault, raising `convertToAssets` by `D` total. Their own vault shares recover `f_vault·D`; net cost `D·(1 − f_vault)`.
3. `stopEpoch(0, 0)`: `totalInterestDueNow()` returns real interest + `D`; `_grossInterest` passes the unreachable-cap path and `mintStrategyTokens(_grossInterest)` inflates NAV by ~`D`; tranche prices rise ~`D` total.
4. Attacker requests/claims withdrawal at inflated price, extracting `f_CDO·D` of claim value. Profit = `f_CDO·D − (1−f_vault)·D` > 0 whenever `f_CDO + f_vault > 1` (e.g., dominant LP plus ≥50% of vault shares).
5. The minted strategy tokens are unbacked — no underlying was ever pulled for them — so the remaining LPs' claims become partially unbacked (insolvency socialized to non-attacker holders / future receipts).

### Impact Explanation
Direct theft plus insolvency: the attacker converts a partially-recoverable vault donation into unbacked tranche NAV and redeems it against real borrower principal/interest and pending-withdraw reserves held by `IdleCreditVault`. Non-attacker LPs are left holding strategy-token claims with no underlying backing. The skimming guards don't help — `_skimDonatedAssets` only sweeps raw tokens held by the CDO itself (line 794-796); the donation lands inside the external vault, where it is treated as yield [5](#0-4) .

### Likelihood Explanation
Requires a programmable-borrower deployment with minted interest (the documented configuration — `setIsInterestMinted` is forced on for programmable borrowers, line 168) and an ERC4626 vault whose share price is donation-sensitive (typical for Morpho/ERC4626 vaults without virtual shares protection). The attacker needs to be a whitelisted LP and hold a meaningful vault share fraction — both are unprivileged actions explicitly in scope. No privileged role misbehavior, oracle manipulation, or borrower collusion is needed; borrower/manager calls are only sequenced normally.

### Recommendation
- In `_stopEpoch`, apply the `maxApr` bound to the resolved gross interest regardless of mode: for programmable borrowers cap `_grossInterest` at `_calcInterestWithApr(getContractValue(), _strategy.maxApr()) + _pendingWithdrawFees`, or bound `borrowerInterestAccrued` separately from vault PnL.
- Alternatively, have `ProgrammableBorrower._vaultNetInterest` exclude single-block/large anomalous deltas (e.g., only count per-share growth attributable over time, or require the vault to use a virtual-share/protected ERC4626 and document that requirement).
- Track vault share count, not just asset value: recognize vault yield via `shares · (price − priceAtEpochStart)` with the epoch-start share price snapshotted, so pure donations added after the snapshot on a per-share basis still count but are at least bounded — a stricter fix is to treat any increase in `totalAssets` not matched by borrower interest as suspect.

### Proof of Concept
Foundry fork PoC sketch (modeled on `test/foundry/ProgrammableBorrowerCreditVault.t.sol`):

```solidity
// setup as in setUp(): programmableBorrower over a real MetaMorpho vault,
// cdoEpoch.isProgrammableBorrower = true, isInterestMinted = true, apr 0.
function testVaultDonationInflatesMintedInterest() external {
  uint256 amount = 10_000 * oneScale;
  // attacker is dominant AA LP
  vm.prank(attacker); idleCDO.approve(...); 
  depositAAAs(attacker, amount);

  _startEpochAndCheckPrices(0);

  // attacker also owns vault shares so donation is partially recoverable
  deal(USDC, attacker, donation * 2);
  vm.startPrank(attacker);
  morphoVault.deposit(donation, attacker);           // f_vault share
  underlying.transfer(vaultAddress, donation);       // donation -> convertToAssets up by ~donation
  vm.stopPrank();

  vm.warp(cdoEpoch.epochEndDate() + 1);
  uint256 inflated = programmableBorrower.totalInterestDueNow();
  assertGt(inflated, donation - 10);                 // donation counted as "vault interest"

  uint256 navPre = cdoEpoch.getContractValue();
  vm.prank(manager);
  cdoEpoch.stopEpoch(0, 0);                          // no maxApr cap applies

  // unbacked strategy tokens minted; contract value/tranche price inflated by ~donation
  assertApproxEqAbs(cdoEpoch.getContractValue(), navPre + inflated, 50);
  // attacker requests withdraw at inflated price and later claims real underlying
  // from collectWithdrawFunds/borrower repayment -> profit = f_CDO*donation - (1-f_vault)*donation > 0
}
```

Key assertion: `underlying` balance pulled at stop covers only `pendingWithdraws` while `mintStrategyTokens` added `inflated` to NAV — demonstrating minted-but-unbacked value. Uncertainty I could not fully verify within the search budget: exact `mintStrategyTokens`/`price` internals in `IdleCreditVault.sol` (the grep shows `_onlyIdleCDO` gating exists) and whether the specific target vault is donation-resistant; the accounting path in `IdleCDOEpochVariant._stopEpoch` and `ProgrammableBorrower._vaultNetInterest` is confirmed as shown above.

```text
  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
```
