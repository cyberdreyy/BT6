### Title
Hardcoded mainnet-only Usual/USD0pp/Chainlink addresses permanently freeze `IdleCDOUsualVariant` epoch lifecycle on any non-mainnet deployment - ([File: contracts/strategies/usual/IdleUsualStrategy.sol](contracts/strategies/usual/IdleUsualStrategy.sol))

### Summary
`IdleUsualStrategy` binds `USUAL`, `USD0pp`, and the Chainlink `USD0ppOracle` as compile-time `constant` mainnet addresses. The paired vault `IdleCDOUsualVariant` calls `IdleUsualStrategy.getChainlinkPrice()` — which performs `IOracle(USD0ppOracle).latestRoundData()` — inside both `startEpoch` and `stopEpoch`. On any deployment chain where `0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB` is not a Chainlink aggregator (every chain except Ethereum mainnet), the external call either reverts or returns undecodable data, so `startEpoch`/`stopEpoch` revert forever. This mirrors the external report: a hardcoded registry/oracle address valid only on mainnet makes the oracle path — and everything depending on it — non-functional on the target L2.

### Finding Description
In `contracts/strategies/usual/IdleUsualStrategy.sol:46-48`:

```solidity
address public constant USUAL = 0xC4441c2BE5d8fA8126822B9929CA0b81Ea0DE38E;
address public constant USD0pp = 0x35D8949372D46B7a3D5A56006AE77B215fc69bC0;
address public constant USD0ppOracle = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;
```

`getChainlinkPrice()` (lines 164–172) does a `latestRoundData()` staticcall against `USD0ppOracle` and decodes the result; against a non-contract or wrong contract the call reverts or the decode fails, and `setOraclePrice` (line 159) additionally calls `IUSD0pp(USD0pp).getFloorPrice()` which reverts similarly.

Both epoch transitions in `contracts/IdleCDOUsualVariant.sol` depend on this path:
- `startEpoch` line 63: `priceAtStartEpoch = IdleUsualStrategy(_strategy).getChainlinkPrice();`
- `stopEpoch` line 77-78: `uint256 _oraclePrice = _strategy.getChainlinkPrice(); _strategy.setOraclePrice(_oraclePrice);`
- `initialize` line 71 of the strategy also calls `getChainlinkPrice()`.

The repo demonstrates multi-chain intent (`contracts/arbitrum/`, `contracts/optimism/`, `contracts/base/`, `contracts/polygon-zk/` variants exist), consistent with the protocol's stated L2 deployment goal. Because the addresses are `constant` (not immutables set in the constructor, not storage), there is no way to fix them post-deploy or via upgrade of the CDO — the strategy implementation itself must be redeployed, and the vault's `strategy` reference is fixed.

Broken invariant: liveness / permanent freezing. User funds deposited into `IdleCDOUsualVariant` are locked inside the strategy (deposited 1:1 at `startEpoch`, line 66). If `getChainlinkPrice` reverts, `stopEpoch` can never execute, `isEpochRunning` stays `true` with `allowAAWithdraw = allowBBWithdraw = false` and the contract paused — withdrawals are permanently bricked. If the vault is deployed but `initialize` or `startEpoch` reverts, the vault is dead on arrival.

No guard saves this: `stopEpoch` has no escape path that skips the oracle read; there is no `emergencyShutdown`/rescue for tranche holders (only owner `transferToken` on the strategy, which rescues strategy-held tokens but cannot make `stopEpoch` succeed or unpause withdrawals since `isEpochRunning`/`allowXXWithdraw` are only set inside the reverting `stopEpoch`).

### Impact Explanation
Permanent freezing of all user funds in the vault. On any chain where `USD0ppOracle`/`USD0pp` are absent or at different addresses:
- If oracle calls revert before `startEpoch`: vault unusable, strategy token minting never happens; any tokens already transferred in are stranded.
- If deployment/front-running managed to start an epoch (e.g., oracle exists but `USD0pp`/`USUAL` differ) and then the feed path fails at `stopEpoch`: deposits pause is permanent, withdrawals never re-enable, and USUAL harvest logic (`redeemRewards` line 199 reads `IERC20Detailed(USUAL)`) also reverts since `USUAL` won't exist.

Loss = 100% of vault TVL at epoch end, permanently unclaimable, unless a new implementation is deployed and the CDO storage rewritten — which `IdleCDO`'s fixed `strategy` reference may not permit.

### Likelihood Explanation
Certain on any non-mainnet deployment: the constants are Ethereum mainnet addresses (Usual protocol and its Chainlink USD0++/USD feed exist only on mainnet). The repo's own directory structure (`arbitrum/`, `optimism/`, `base/`, `polygon-zk/`) shows the codebase is intended for multi-chain/L2 deployment, exactly the scenario in the external report. No attacker action is required; it is a deployment-environment incompatibility, but per the bug-class mapping it produces the "permanent freezing" impact class.

### Recommendation
Do not hardcode chain-specific addresses as `constant`. Pass `USUAL`, `USD0pp`, and `USD0ppOracle` (or the feed address) as `initialize` parameters stored in upgradeable storage, and validate them in `initialize` (e.g., call `latestRoundData`/`getFloorPrice` and require sane values). Alternatively, gate `IdleCDOUsualVariant` deployments behind a per-chain deployment config check. If the Usual variant is mainnet-only by design, revert early in `initialize` on unsupported `block.chainid` to prevent deploying a vault whose lifecycle is guaranteed to brick.

### Proof of Concept
Foundry test (deploy on an L2 fork, e.g. Arbitrum, where the three constants are EOAs/non-existent):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleUsualStrategy} from "contracts/strategies/usual/IdleUsualStrategy.sol";

contract UsualL2OraclePoC is Test {
    function test_getChainlinkPrice_revertsOnL2() public {
        // Fork Arbitrum/Optimism: USD0ppOracle 0xFC9e...Cc1cB is not a Chainlink feed there
        vm.createSelectFork(vm.envString("ARBITRUM_RPC_URL"));

        IdleUsualStrategy s = new IdleUsualStrategy();
        // Decode of latestRoundData on a non-aggregator contract reverts
        vm.expectRevert();
        s.getChainlinkPrice();

        // Consequently initialize() reverts too (line 71 calls getChainlinkPrice)
        vm.expectRevert();
        s.initialize(address(0x1), address(this));
    }
}
```
