### Title
Zip extraction applies `os.Lchown`/`lchmod` to attacker-controlled, unsanitized `file.Name` paths, extending Zip-Slip path traversal into an ownership/permission-tampering primitive - ([File: helpers/archives/zip_extract.go], [File: helpers/archives/zip_extra_unix.go], [File: helpers/archives/os_unix.go])

### Summary
`ExtractZipArchive` never validates or cleans `zip.File.Name` before using it as a filesystem path, so a traversal name (e.g. `../../foo`) or a symlink written by an earlier entry lets `extractZipFile`, and later `lchmod` and `processZipUIDGidField`'s `os.Lchown`, operate on a path outside the intended extraction directory. Combined with a crafted `0x7875` (`ZipUIDGidFieldType`) extra field, the same traversal name is reused by `processZipUIDGidField` to `Lchown` that out-of-root path to an attacker-chosen UID/GID, and by the sibling loop to `lchmod` it to attacker-chosen permission bits.

### Finding Description
`ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`) iterates `archive.File` twice, using `file.Name` directly as the destination path with no call to `filepath.Clean`, no rejection of `..` segments or absolute paths, and no verification that the resolved path stays under an extraction root: [1](#0-0) 

The only existing content check is `errorIfGitDirectory`, which only rejects paths whose first cleaned segment is `.git` — it does nothing to stop `../` traversal: [2](#0-1) 

In the first loop, `extractZipFile`/`extractZipSymlinkEntry`/`extractZipFileEntry` write/symlink to `file.Name` unchanged (`os.Symlink(string(data), file.Name)`, `os.OpenFile(file.Name, …)`), so a traversal name can already create files/symlinks outside the extraction directory: [3](#0-2) 

In the second loop, the same unsanitized `file.Name` is passed to `lchmod` and to `processZipExtra` → `processZipUIDGidField`, which calls `os.Lchown(file.Name, uid, gid)` using UID/GID values fully controlled by the attacker via the `0x7875` extra field payload: [4](#0-3) [5](#0-4) 

Note also that the ziplegacy extractor accepts a `dir` parameter for the intended extraction root but never uses it to jail the extraction — it just forwards to `archives.ExtractZipArchive(zr)`, which operates relative to the process CWD with the raw `file.Name`: [6](#0-5) 

Exploit flow: a job supplies a cache/artifact zip (cache/artifact content is fully attacker-controlled) containing an entry with `Name = "../../../some/path"` (or a symlink entry pointing outside the root followed by an entry writing through that symlink), plus a `0x7875` extra field. During extraction: (1) the traversal entry is written/symlinked outside the extraction root in the first loop; (2) in the second loop `lchmod` sets attacker-chosen permission bits on that out-of-root path, and `processZipUIDGidField` calls `os.Lchown` with attacker-chosen UID/GID on the same path.

### Impact Explanation
Because `Lchown` to an arbitrary UID requires the extracting process to have `CAP_CHOWN` (effectively root), the ownership-change half of the primitive is only exploitable when the Runner/helper process extracts as root — which is a common but separate configuration concern. However, the underlying path-traversal write (`extractZipFile`) and the unconditional `lchmod` permission change apply regardless of privilege level, and the `lchmod`/`Lchown` calls both use the exact same unsanitized `file.Name` used for content write, so any privilege the extracting process does have (root in many docker/shell executor deployments) is transitively exposed through these calls to attacker-chosen destination paths outside the workspace. Concrete scoped impact: attacker can write/overwrite files, flip permission bits, and (when extraction runs as root) change ownership of files outside the job's own workspace — e.g. mounted helper binaries or another project's cache directory reachable via the shared filesystem — which is squarely a "file operations must stay within intended build/cache/artifact roots" violation.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: an unprivileged pipeline author can supply cache/artifact content that Runner extracts via `ExtractZipFile`/`ExtractZipArchive` (called from `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`). No authentication, no special image, and no cooperation from another party is required — just a crafted zip with a traversal `Name` and a `0x7875` extra field. This is highly repeatable and deterministic.

### Recommendation
Before performing any filesystem operation (`Mkdir`, `Symlink`, `OpenFile`, `lchmod`, `os.Lchown`) in `helpers/archives/zip_extract.go`, resolve `file.Name` against the extraction root, reject entries whose cleaned path escapes the root (`..` traversal, absolute paths, or symlink-based escapes), and skip `lchmod`/`processZipExtra` for any entry that failed/was skipped during the first-pass validation. The `ziplegacy` extractor's `dir` field should actually be used to jail extraction (e.g., `os.Chdir(dir)` plus root-relative validation, or explicit `filepath.Join(dir, cleanedName)` with a prefix check).

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchive_PathTraversalBlocksLchownLchmod(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        outsideDir := t.TempDir() // sibling dir, simulating "outside extraction root"
        traversalTarget := filepath.Join(outsideDir, "pwned")

        f, err := os.Create(fileName)
        require.NoError(t, err)
        archive := zip.NewWriter(f)

        // relative traversal escaping the workdir into outsideDir
        rel, _ := filepath.Rel(".", traversalTarget)
        w, err := archive.CreateHeader(&zip.FileHeader{Name: rel, Method: zip.Deflate})
        require.NoError(t, err)
        _, err = w.Write([]byte("data"))
        require.NoError(t, err)
        require.NoError(t, archive.Close())
        require.NoError(t, f.Close())

        err = ExtractZipFile(fileName)
        require.NoError(t, err)

        // Assert the traversal target was NOT created/modified outside the root
        _, statErr := os.Stat(traversalTarget)
        assert.True(t, os.IsNotExist(statErr), "extraction must not write outside its root")
    })
}
```
Expected (current, vulnerable) behavior: `traversalTarget` is created in `outsideDir`, proving the write, `lchmod`, and (as root) `Lchown` all executed against a path outside the extraction root. After the fix, the assertion should pass because such entries are rejected before any of `extractZipFile`, `lchmod`, or `processZipUIDGidField` touch the resolved path.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```

```go
func processZipUIDGidField(data []byte, file *zip.FileHeader) error {
	var ugField ZipUIDGidField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &ugField)
	if err != nil {
		return err
	}

	if !(ugField.Version == 1 && ugField.UIDSize == 4 && ugField.GIDSize == 4) {
		return errors.New("uid/gid data not supported")
	}

	return os.Lchown(file.Name, int(ugField.UID), int(ugField.Gid))
}
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
```
