### Title
`fullfillWriteOffRequest` does not refund overpaid underlyings; excess is irreversibly paid to the lender and feeReceiver - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
Analogous to the reported `mintFounderHero()` overpayment bug (where ETH sent above `price * amount` is locked/unrecoverable), `IdleCreditVaultWriteOffEscrow.fullfillWriteOffRequest` accepts any `_underlyings >= currentRequest.underlyings` and sweeps the *entire* transferred amount to the lender (minus a fee charged on the inflated amount). A fulfiller who transfers more underlyings than the request asked for has no way to recover the excess: the surplus is permanently transferred to the lender and, proportionally, to `feeReceiver`.

### Finding Description
In `fullfillWriteOffRequest`, the only check is:

```solidity
// contracts/IdleCreditVaultWriteOffEscrow.sol:129
if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
  revert WrongRequest();
}
``` [1](#0-0) 

Underpay reverts, but overpay is allowed. The fulfiller's full `_underlyings` is pulled via `safeTransferFrom` (line 139), the exit fee is computed on `_underlyings` — i.e., on the overpaid amount, not on the requested amount (line 144) — and `_underlyings - _totFee` is sent to `_user` (line 149). Nothing refunds the difference `_underlyings - currentRequest.underlyings` to `msg.sender`.

For example: an LP creates a request for 10,000 USDC against 10,000 tranche tokens. A fulfiller (the borrower or any wallet — the function is permissionless, "this function can be called by any wallet") calls `fullfillWriteOffRequest(LP, tranches, 10_500e6)`, e.g. due to a decimal/frontend error or a stale quote. The contract pulls the full 10,500 USDC, charges the 0.1% exit fee on 10,500 rather than 10,000, and sends ~10,489.5 USDC to the LP — who receives ~489.5 USDC more than they ever asked for, while the fulfiller permanently loses the extra 500 USDC. There is no recovery path; `emergencyWithdraw` only covers tokens left in the contract, and none remain.

This is confirmed as live behavior by the existing test `testFullfillWriteOffRequestWithUnderlyingOverpay`, which asserts the overpaid amount is fully distributed to the LP and feeReceiver. [2](#0-1) 

### Impact Explanation
Permanent loss of funds for the fulfiller equal to the overpaid amount (`_underlyings - currentRequest.underlyings`, plus the inflated exit fee). Since any EOA/contract can fulfill a request, fat-fingered or mispriced fulfillments silently donate the excess to the lender instead of being refunded or reverted. The `pendingUnderlyings` bookkeeping also only decrements the *requested* amount, so accounting gives no signal of the excess.

### Likelihood Explanation
Medium-low. It requires a fulfiller mistake (typo, wrong decimals, or a UI quoting more than `userRequests[_user].underlyings`), but the contract actively permits and amplifies the mistake rather than guarding against it. Unlike the lender-side checks, there is no upper bound on `_underlyings`, and the fee-on-overpay calculation guarantees the excess can never be reclaimed by anyone.

### Recommendation
Mirror the fix suggested for `mintFounderHero()`: either enforce exact payment — `if (currentRequest.tranches != _tranches || _underlyings != currentRequest.underlyings) revert WrongRequest();` — or cap the pull at the requested amount and refund/charge correctly:

```solidity
if (_underlyings < currentRequest.underlyings) revert WrongRequest();
uint256 payAmount = currentRequest.underlyings;
underlyingToken.safeTransferFrom(msg.sender, address(this), payAmount);
// compute fee on payAmount, send payAmount - fee to _user
```

If overpay must remain supported per the code comment, compute the exit fee on `currentRequest.underlyings` and explicitly refund `_underlyings - currentRequest.underlyings` to `msg.sender`.

### Proof of Concept
Foundry-style PoC (extends `IdleCreditVaultWriteOffEscrow.t.sol` setup; an epoch must be running so `createWriteOffRequest` succeeds):

```solidity
function testFullfillOverpayNotRefunded() external {
    uint256 requestedTranches    = 10_000e18;
    uint256 requestedUnderlyings = 10_000e6;
    uint256 overpayUnderlyings   = 10_500e6; // +500 USDC mistake

    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, requestedUnderlyings);

    deal(address(underlying), fulfiller, overpayUnderlyings);
    uint256 lpPre  = underlying.balanceOf(LP);
    uint256 feePre = underlying.balanceOf(escrow.feeReceiver());

    vm.startPrank(fulfiller);
    underlying.approve(address(escrow), overpayUnderlyings);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, overpayUnderlyings);
    vm.stopPrank();

    uint256 fee = overpayUnderlyings * escrow.exitFee() / escrow.FULL_VALUE();

    // fulfiller lost the entire 10_500e6, including the 500e6 excess
    assertEq(underlying.balanceOf(fulfiller), 0);
    // LP received more than they requested
    assertEq(underlying.balanceOf(LP) - lpPre, overpayUnderlyings - fee);
    // fee charged on the overpaid amount
    assertEq(underlying.balanceOf(escrow.feeReceiver()) - feePre, fee);
    // nothing left in escrow to refund
    assertEq(underlying.balanceOf(address(escrow)), 0);
}
```

The excess 500 USDC (minus pro-rata fee) is irrecoverably transferred to the LP — the same "overpayment cannot be recovered" broken invariant as `mintFounderHero()`.

  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
