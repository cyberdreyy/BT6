## Finding: Stale Confirmations From Removed Multisig Members Count Toward Execution Threshold

The bug-class hint (funds distributed based on stale/incorrect accounting rather than the true current state) maps onto a real, reachable flaw in the multisig contracts: `confirm()` counts confirmations without verifying they were made by *currently* active members, while `delete_member`/`DeleteKey` only purges requests *created by* the removed member — not confirmations that member cast on other members' pending requests.

### Title
Stale Confirmations From Removed Multisig Members Are Still Counted Toward the Confirmation Threshold - (`multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
`MultiSigContract::confirm` executes a request once `confirmations.len() + 1 >= self.num_confirmations` [1](#0-0) . When a member is removed via `delete_member` (multisig2) or a key is removed via `DeleteKey` (multisig), only requests *originated by* that member/key are purged; confirmations that member/key previously cast on requests originated by *other* members remain in the `confirmations` set and continue to count toward the threshold [2](#0-1) [3](#0-2) .

### Finding Description
The binding that should hold is: `live_member_confirmations(request) >= num_confirmations` before a request executes. Instead the contract checks `confirmations.len() >= num_confirmations`, where `confirmations` is a `HashSet` of member identities (`String`/`PublicKey`) recorded at confirm-time and never re-validated against the current member set [4](#0-3) .

`delete_member` only filters and removes requests where `r.member == member` (i.e., requests *created* by the removed member), then removes the member from `self.members` and their `num_requests_pk` entry — it never scans `self.confirmations` for entries containing that member's identity on requests created by someone else [5](#0-4) . The equivalent `DeleteKey` action in the v1 `multisig/src/lib.rs` has the identical gap [3](#0-2) .

As a result, a confirmation cast by an account that is subsequently removed from the multisig still occupies a slot in `confirmations.len()`, letting the request reach `num_confirmations` with fewer *live* signers than the threshold requires.

### Impact Explanation
This breaks the authorization/threshold binding of the multisig: `MultiSigRequestAction::Transfer`, `AddKey`, `FunctionCall`, etc. can execute — including moving NEAR out of the account — with fewer than `num_confirmations` currently-authorized members having approved it. This matches the report's "Critical" bucket: a multisig request executed below its intended threshold.

### Likelihood Explanation
The pattern requires no privileged action beyond ordinary multisig member operations already exposed by the contract (`add_request`, `confirm`, and a legitimate `DeleteMember`/`DeleteKey` request that itself reaches threshold through normal governance). No foundation, redeploy, or external actor is needed — any sequence where a member is confirmed-then-removed while their confirmation is still attached to a pending request triggers it.

### Recommendation
When removing a member/key, iterate all pending `requests`/`confirmations` (not just those created by that member) and strip that member's identity from every confirmation set; alternatively, validate at `confirm()`/execution time that every entry in `confirmations` still corresponds to a current member before counting it toward `num_confirmations`.

### Proof of Concept
1. Multisig has members A, B, C, D, E with `num_confirmations = 3`.
2. A calls `add_request_and_confirm(R)` — `confirmations(R) = {A}` [6](#0-5) .
3. B calls `confirm(R)` — `confirmations(R) = {A, B}`, `len()=2 < 3`, not executed.
4. Via a separate, properly-threshold-confirmed request, B is removed with `DeleteMember { member: B }`. `delete_member` filters only requests where `r.member == B` (requests B created); `R` was created by A, so `R`'s confirmations are untouched — B's confirmation stays in `confirmations(R)` even though B is no longer in `self.members` [7](#0-6) .
5. C calls `confirm(R)` — `confirmations(R) = {A, B, C}`, `len()=3 >= num_confirmations(3)`, and `execute_request(R)` runs [8](#0-7) .
6. `R` (e.g. a `Transfer`) executes with only 2 live members (A, C) actually authorizing it — below the configured 3-of-N threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
