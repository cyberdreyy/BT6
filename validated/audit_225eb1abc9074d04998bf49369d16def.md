### Title
Attacker can front-run and permanently squat a victim's deterministic lockup address with self-chosen owner, vesting hash and foundation account - ([File: lockup-factory/src/lib.rs])

### Summary
`LockupFactory::create` derives the new lockup's account ID solely from `sha256(owner_account_id)` and never checks that the caller (`env::predecessor_account_id()`) is the `owner_account_id`, the NEAR Foundation, or has any relationship to the named owner. Any unprivileged account can therefore call `create` naming an arbitrary victim as `owner_account_id` while choosing every other initialization parameter itself — including a private `VestingScheduleOrHash::VestingHash` whose pre-image only the attacker knows and a `foundation_account_id` the attacker controls — permanently occupying the victim's canonical lockup address with terms the victim never agreed to.

### Finding Description
The broken binding is: *the contract deployed at `sha256(owner_account_id).factory` must carry the vesting/lockup/foundation terms that `owner_account_id`'s legitimate grantor chose* — i.e. `terms_at(derive(owner_account_id)) == terms_chosen_by(owner_account_id's_grantor)`.

`create` computes the deterministic address and immediately deploys with attacker-supplied arguments, with no ownership/consent check: [1](#0-0) 

Specifically:
- `lockup_account_id` is `hex(sha256(owner_account_id))` + factory account, independent of `env::predecessor_account_id()`.
- `vesting_schedule`, `lockup_duration`, `lockup_timestamp`, `release_duration`, and `whitelist_account_id` are taken verbatim from the caller's arguments.
- If `vesting_schedule.is_some()`, `foundation_account_id` is set to `self.foundation_account_id` (the real, protocol-wide foundation account), but for the "private" `VestingHash` variant the actual vesting terms remain secret to whoever generated the hash+salt — the attacker.

`LockupContract::new` performs only format/existence checks on the IDs, never checking that `env::predecessor_account_id()` (the factory, always) or any signer corresponds to the named `owner_account_id`: [2](#0-1) 

For `VestingHash`, `get_locked_amount()`/`get_unvested_amount()` treat the private vesting as fully vested/unvested = `U128(0)` until someone reveals the schedule via `assert_vesting`: [3](#0-2) [4](#0-3) 

Because NEAR account creation is atomic and a name can be created only once, whoever wins the race to `create` for a given `owner_account_id` permanently owns that address's parameters. Owner-restricted methods (`assert_owner`) still require the named `owner_account_id` to sign, so the attacker cannot directly drain via owner methods: [5](#0-4) 
but foundation-restricted methods only require `assert_called_by_foundation()`, and the attacker chose `foundation_account_id` (via `vesting_schedule`/`foundation_account_id` argument path in `create`) to be an account the attacker controls: [6](#0-5) [7](#0-6) 
Since the attacker also crafted the `VestingHash` pre-image (`VestingScheduleWithSalt::hash()`), they can later call `terminate_vesting` with a self-chosen schedule that matches the stored hash and declare an arbitrarily large "unvested" amount, then call `termination_withdraw` to route funds to any `receiver_id` they choose — all while the named `owner_account_id` is the innocent victim who never authorized any of this.

No existing guard (`assert_owner`, `assert_called_by_foundation`, `is_valid_account_id`, `assert_valid`/`VestingSchedule::assert_valid`) checks that the caller of `create`/`new` is related to `owner_account_id`, nor that `foundation_account_id` is the protocol's real foundation when the caller supplies it indirectly through a self-controlled `vesting_schedule` path — this is a genuine gap, not one of the listed protections.

### Impact Explanation
Once squatted, the legitimate grantor (e.g. NEAR Foundation or an employer) can never deploy the real lockup contract at that canonical, deterministically-derived address for the victim — `create_account` will fail for an already-existing account, so any future legitimate `create` call fails (with its own deposit auto-refunded via `on_lockup_create`, so the *grantor's* attached deposit is not directly lost in that specific path). The severe damage is structural: an account is permanently deployed at the victim's canonical lockup address with parameters (lockup duration, release schedule, private vesting hash, and — critically — `foundation_account_id`) the rightful creator never chose. This falls squarely under the stated Critical category: "a lockup deployed with parameters its rightful creator never chose." If any party (exchange, tooling, or the real grantor sending a bare `transfer` rather than going through `create`) is later induced to send NEAR into that pre-existing, attacker-controlled-terms contract believing it is the victim's canonical lockup, the attacker — posing as `foundation_account_id` — can use `terminate_vesting` + `termination_withdraw` to move those funds to an account of their choosing, bypassing the true owner entirely. This is repeatable against any account name the attacker wants to squat, at the fixed cost of `MIN_ATTACHED_BALANCE` (3.5 NEAR) per victim.

### Likelihood Explanation
The precondition is trivial: any unprivileged account with ~3.5 NEAR can call `LockupFactory::create` naming any `owner_account_id` and any `vesting_schedule`/`VestingHash`, with no signature or relationship check to the named owner. No foundation, owner, or multisig involvement is required, and the attack is directly reachable through the factory's public `create` entrypoint as shown in the code. The only limiting factor is that actual fund theft requires a second party to later deposit real value into the squatted contract, but the "parameters its rightful creator never chose" impact (matching the stated Critical rubric) is achieved unconditionally on the first `create` call.

### Recommendation
Require that `create`'s caller either is the `owner_account_id` itself, or restrict `create` (or at minimum the ability to set `foundation_account_id`/`vesting_schedule`) to a privileged caller (the NEAR Foundation / `master_account_id`), and/or bind the deterministic lockup address to a namespace that includes the funding/creator account rather than solely `owner_account_id`, so an attacker cannot squat the canonical address for an arbitrary victim with self-chosen vesting/foundation parameters.

```rust
#[test]
fn attacker_squats_victim_lockup_with_malicious_foundation_and_vesting_hash() {
    // 1. Setup factory context, predecessor = ATTACKER (not owner, not foundation)
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(attacker_account())
        .attached_deposit(MIN_ATTACHED_BALANCE)
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    // 2. Attacker crafts a private vesting schedule + salt only they know,
    //    and creates a lockup naming the VICTIM as owner_account_id.
    let attacker_vesting_schedule = VestingSchedule { /* attacker-chosen dates favoring attacker */ };
    let vesting_hash = VestingScheduleWithSalt {
        vesting_schedule: attacker_vesting_schedule.clone(),
        salt: attacker_salt.clone().into(),
    }.hash();

    contract.create(
        victim_account_id(),                       // owner_account_id = victim, never consented
        lockup_duration,
        None,
        Some(VestingScheduleOrHash::VestingHash(vesting_hash.into())),
        None,
        None,
    );
    // callback: on_lockup_create succeeds -> lockup deployed at sha256(victim_account_id).factory

    // 3. Assert: LockupContract::owner_account_id == victim (never agreed to terms)
    //    LockupContract::foundation_account_id == self.foundation_account_id (protocol default,
    //    but since attacker knows the hash pre-image, they alone can reveal/terminate vesting).
    // 4. A legitimate later attempt by the real grantor to `create` for victim_account_id
    //    at the SAME derived address fails because create_account already exists,
    //    proving the address/terms are permanently squatted by the attacker's initial call.
}
```

```rust
    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }
```

```rust
    pub fn new(
        owner_account_id: AccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        transfers_information: TransfersInformation,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,

        foundation_account_id: Option<AccountId>,

        assert!(
            env::is_valid_account_id(owner_account_id.as_bytes()),
            "The account ID of the owner is invalid"
        );
        assert!(
            env::is_valid_account_id(staking_pool_whitelist_account_id.as_bytes()),
            "The staking pool whitelist account ID is invalid"
        );
        if let TransfersInformation::TransfersDisabled {
            transfer_poll_account_id,
        } = &transfers_information
        {
            assert!(
                env::is_valid_account_id(transfer_poll_account_id.as_bytes()),
                "The transfer poll account ID is invalid"
            );
        }
        let lockup_information = LockupInformation {
            lockup_amount: env::account_balance(),
            termination_withdrawn_tokens: 0,
            lockup_duration: lockup_duration.0,
            release_duration: release_duration.map(|d| d.0),
            lockup_timestamp: lockup_timestamp.map(|d| d.0),
            transfers_information,
        };
        let vesting_information = match vesting_schedule {
            None => {
                assert!(
                    foundation_account_id.is_none(),
                    "Foundation account can't be added without vesting schedule"
                );
                VestingInformation::None
            }
            Some(VestingScheduleOrHash::VestingHash(hash)) => VestingInformation::VestingHash(hash),
            Some(VestingScheduleOrHash::VestingSchedule(vs)) => {
                VestingInformation::VestingSchedule(vs)
            }
        };
        assert!(
            vesting_information == VestingInformation::None ||
                env::is_valid_account_id(foundation_account_id.as_ref().unwrap().as_bytes()),
            "Foundation account should be added for vesting schedule"
        );

        Self {
            owner_account_id,
            lockup_information,
            vesting_information,
            staking_information: None,
            staking_pool_whitelist_account_id,
            foundation_account_id,
        }
    }
```

```rust
    pub fn assert_vesting(
        &self,
        vesting_schedule_with_salt: Option<VestingScheduleWithSalt>,
    ) -> VestingSchedule {
        match &self.vesting_information {
            VestingInformation::VestingHash(hash) => {
                if let Some(vesting_schedule_with_salt) = vesting_schedule_with_salt {
                    assert_eq!(
                        &vesting_schedule_with_salt.hash(),
                        &hash.0,
                        "Presented vesting schedule and salt don't match the hash"
                    );
                    vesting_schedule_with_salt.vesting_schedule
                } else {
                    env::panic(b"Expected vesting schedule and salt, but it was not provided")
                }
            }
            VestingInformation::VestingSchedule(vesting_schedule) => {
                assert!(
                    vesting_schedule_with_salt.is_none(),
                    "Explicit vesting schedule exists"
                );
                vesting_schedule.clone()
            }
            VestingInformation::Terminating(_) => env::panic(b"Vesting was terminated"),
            VestingInformation::None => env::panic(b"Vesting is None"),
        }
    }
```

```rust
    pub fn terminate_vesting(
        &mut self,
        vesting_schedule_with_salt: Option<VestingScheduleWithSalt>,
    ) {
        self.assert_called_by_foundation();
        let vesting_schedule = self.assert_vesting(vesting_schedule_with_salt);
        let unvested_amount = self.get_unvested_amount(vesting_schedule);
        assert!(unvested_amount.0 > 0, "The account is fully vested");

        env::log(
            format!(
                "Terminating vesting. The remaining unvested balance is {}",
                unvested_amount.0
            )
            .as_bytes(),
        );

        let deficit = unvested_amount
            .0
            .saturating_sub(self.get_account_balance().0);
        // If there is deficit of liquid balance and also there is a staking pool selected, then the
        // contract will try to withdraw everything from this staking pool to cover deficit.
        let status = if deficit > 0 && self.staking_information.is_some() {
            TerminationStatus::VestingTerminatedWithDeficit
        } else {
            TerminationStatus::ReadyToWithdraw
        };

        self.vesting_information = VestingInformation::Terminating(TerminationInformation {
            unvested_amount,
            status,
        });
    }
```

```rust
    pub fn termination_withdraw(&mut self, receiver_id: AccountId) -> Promise {
        self.assert_called_by_foundation();
        assert!(
            env::is_valid_account_id(receiver_id.as_bytes()),
            "The receiver account ID is invalid"
        );
        assert_eq!(
            self.get_termination_status(),
            Some(TerminationStatus::ReadyToWithdraw),
            "Termination status is not ready to withdraw"
        );

        let amount = std::cmp::min(
            self.get_terminated_unvested_balance().0,
            self.get_account_balance().0,
        );
        assert!(
            amount > 0,
            "The account doesn't have enough liquid balance to withdraw any amount"
        );

        env::log(
            format!(
                "Termination Step: Withdrawing {} of terminated unvested balance to account @{}",
                amount, receiver_id
            )
            .as_bytes(),
        );

        self.set_termination_status(TerminationStatus::WithdrawingFromAccountInProgress);

        Promise::new(receiver_id.clone()).transfer(amount).then(
            ext_self_foundation::on_withdraw_unvested_amount(
                amount.into(),
                receiver_id,
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::foundation_callbacks::ON_WITHDRAW_UNVESTED_AMOUNT,
            ),
        )
    }
```
