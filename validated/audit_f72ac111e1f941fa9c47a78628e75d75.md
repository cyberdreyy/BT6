### Title
View-role/edit-role authenticated users can harvest plaintext OutgoingToken secrets for all bridges via GET /v2/bridge_types - ([File: core/web/bridge_types_controller.go])

### Summary
The `/v2/bridge_types` GET route is protected only by generic session/token authentication with no role check, and `BridgeTypesController.Index` builds its response via `presenters.NewBridgeResource`, which copies the plaintext `OutgoingToken` into the JSON API response unredacted. Any authenticated user regardless of role (including the lowest-privilege `view` role) can page through all configured bridges and exfiltrate every `OutgoingToken`.

### Finding Description
The route is registered as `authv2.GET("/bridge_types", paginatedRequest(bt.Index))` with no `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, unlike the mutating routes on the same resource (`POST`, `PATCH`, `DELETE` are wrapped with `auth.RequiresEditRole`). [1](#0-0) . This means the GET is reachable by any principal that passes only the base `auth.Authenticate` session/token middleware, including a `view`-role user or API token — the lowest privilege tier defined in `core/web/auth/auth.go`. [2](#0-1) 

`BridgeTypesController.Index` fetches bridges from the ORM and converts each to a `BridgeResource` via `presenters.NewBridgeResource`: [3](#0-2) 

`NewBridgeResource` copies `b.OutgoingToken` directly into the `OutgoingToken` field of the JSON-serialized resource, with no redaction: [4](#0-3) 

The `OutgoingToken` field has `json:"outgoingToken"` (no `omitempty`, no masking), so it is always serialized into the paginated JSON:API response body. [5](#0-4) 

The `OutgoingToken` is a genuine secret: it's a randomly generated 24-byte credential (`utils.NewSecret(24)`) that the node sends to the external adapter to authenticate outbound job-run requests, stored in plaintext in the `BridgeType` struct (unlike `IncomingTokenHash`, which is hashed at rest). [6](#0-5)  Existing tests confirm the CLI-level presenter (`BridgePresenters.RenderTable`) deliberately strips `OutgoingToken` for the bulk/table view (`assert.NotContains(t, output, outgoingToken)` in `TestBridgePresenter_RenderTable`), showing the project intends for outgoing tokens to be hidden in list views — but this redaction happens only in the CLI table renderer, not in the actual HTTP JSON API presenter used by `Index`. [7](#0-6) 

The existing `TestBridgeTypesController_Index` handler test does not assert on `OutgoingToken` at all, so this exposure is currently untested and unnoticed. [8](#0-7) 

### Impact Explanation
A `view`-role user or restricted API token — normally expected to have read-only, non-sensitive access — can paginate `/v2/bridge_types` (`?size=100`) and recover the plaintext `OutgoingToken` for every configured bridge in the node. These tokens authenticate the node's outbound requests to external adapters; disclosure allows an attacker to impersonate the Chainlink node to the external adapter, potentially triggering unauthorized adapter-side actions or pivoting into further systems that trust the token. This matches a credential/secret-disclosure impact class under Chainlink's bounty program (unauthorized disclosure of sensitive node credentials via an under-authorized API endpoint).

### Likelihood Explanation
Requires only a `view`-role session or restricted API token — the lowest privilege level supported — and a single paginated GET request sequence with no additional preconditions, admin access, or timing constraints. This is straightforward and fully repeatable by any user granted read-only node dashboard access.

### Recommendation
Either (a) restrict `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` to `auth.RequiresEditRole` (or higher) similar to the mutating routes, or (b) redact `OutgoingToken` from `presenters.NewBridgeResource`/`BridgeResource` for list/show responses entirely (it is not needed by legitimate callers after creation, similar to how `IncomingToken` is only ever returned on `Create`). The safest fix is to remove `OutgoingToken` from the JSON API presenter entirely, since the node itself is the only party that needs it to authenticate to the external adapter.

### Proof of Concept
1. In `core/web/bridge_types_controller_test.go`, extend `TestBridgeTypesController_Index`:
   - Create several bridges as normal test setup (`app.BridgeORM().CreateBridgeType`), capturing each `bt.OutgoingToken`.
   - Create an HTTP client authenticated as a `view`-role user/API token (using existing test helpers such as `app.NewHTTPClient(&cltest.User{Role: sessions.UserRoleView})` or equivalent low-privilege session helper used elsewhere in the test suite).
   - `GET /v2/bridge_types?size=100` with that client.
   - Parse the paginated JSON:API response into `[]presenters.BridgeResource`.
   - Assert `resources[i].OutgoingToken == bt[i].OutgoingToken` (non-empty and matching the real plaintext secret) — proving the view-role caller received full secret material.
2. Expected (post-fix) result: either the request is rejected with `403 Forbidden` for the view role, or `resources[i].OutgoingToken` is empty/absent in the response.

func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

func TestBridgeTypesController_Index(t *testing.T) {
	t.Parallel()

	app := cltest.NewApplication(t)
	require.NoError(t, app.Start(t.Context()))
	client := app.NewHTTPClient(nil)

	bt, err := setupBridgeControllerIndex(t, app.BridgeORM())
	require.NoError(t, err)

	resp, cleanup := client.Get("/v2/bridge_types?size=x")
	t.Cleanup(cleanup)
	cltest.AssertServerResponse(t, resp, http.StatusUnprocessableEntity)

	resp, cleanup = client.Get("/v2/bridge_types?size=1")
	t.Cleanup(cleanup)
	cltest.AssertServerResponse(t, resp, http.StatusOK)

	var links jsonapi.Links
	resources := []presenters.BridgeResource{}

	err = web.ParsePaginatedResponse(cltest.ParseResponseBody(t, resp), &resources, &links)
	require.NoError(t, err)
	assert.NotEmpty(t, links["next"].Href)
	assert.Empty(t, links["prev"].Href)

	assert.Len(t, resources, 1)
	assert.Equal(t, bt[0].Name.String(), resources[0].Name, "should have the same Name")
	assert.Equal(t, bt[0].URL.String(), resources[0].URL, "should have the same URL")
	assert.Equal(t, bt[0].Confirmations, resources[0].Confirmations, "should have the same Confirmations")

	resp, cleanup = client.Get(links["next"].Href)
	t.Cleanup(cleanup)
	cltest.AssertServerResponse(t, resp, http.StatusOK)

	resources = []presenters.BridgeResource{}
	err = web.ParsePaginatedResponse(cltest.ParseResponseBody(t, resp), &resources, &links)
	require.NoError(t, err)
	assert.Empty(t, links["next"])
	assert.NotEmpty(t, links["prev"])
	assert.Len(t, resources, 1)
	assert.Equal(t, bt[1].Name.String(), resources[0].Name, "should have the same Name")
	assert.Equal(t, bt[1].URL.String(), resources[0].URL, "should have the same URL")
	assert.Equal(t, bt[1].Confirmations, resources[0].Confirmations, "should have the same Confirmations")
}
