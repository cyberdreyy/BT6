### Title
View-role users can read bridge `OutgoingToken` (adapter auth secret) via unrestricted GET /v2/bridge_types and /v2/bridge_types/:BridgeName - (File: core/web/router.go)

### Summary
The `GET /v2/bridge_types` (Index) and `GET /v2/bridge_types/:BridgeName` (Show) routes are registered under the generic `authv2` group with no role gate (`auth.RequiresEditRole`/`auth.RequiresAdminRole`/`auth.RequiresRunRole`), unlike `Create`, `Update`, and `Destroy`. Both handlers return a `presenters.BridgeResource` that always includes the bridge's `OutgoingToken` field, which is a plaintext, persistent authentication secret used by the node to authenticate to the external adapter. Any authenticated user, including one holding only the lowest `view` role, can retrieve this secret.

### Finding Description
In `v2Routes` at [1](#0-0) , `bt.Index` and `bt.Show` are mounted with no role wrapper, while `Create`/`Update`/`Destroy` are wrapped with `auth.RequiresEditRole`. The `authv2` group itself only requires the request be authenticated via session or API token (`auth.Authenticate(...)`), with no minimum role check [2](#0-1) .

`BridgeTypesController.Index` and `.Show` both build a `presenters.BridgeResource` via `presenters.NewBridgeResource(bridge)` [3](#0-2) . `NewBridgeResource` copies `b.OutgoingToken` from the persisted `bridges.BridgeType` directly into the response resource, and the `BridgeResource.OutgoingToken` JSON field has no `omitempty` or role-based redaction — it is always serialized [4](#0-3) .

`BridgeType.OutgoingToken` is a long-lived plaintext secret generated at bridge creation time and persisted in the database and struct (unlike `IncomingToken`, which is hashed+salted for storage and only returned once at creation time) [5](#0-4) . This is the credential the Chainlink node itself uses when calling out to the external adapter (`OutgoingToken` is sent as an auth header to the adapter).

Because `RequiresEditRole` rejects `UserRoleView` and `UserRoleRun` [6](#0-5) , and `Index`/`Show` lack any such wrapper, a `view`-role session or API token (the lowest privilege authenticated principal, normally restricted to read-only, non-secret endpoints) can call `GET /v2/bridge_types` or `GET /v2/bridge_types/{name}` and receive `OutgoingToken` in the JSON response, confirmed by the existing test asserting the field is populated on `Show` responses [7](#0-6) .

### Impact Explanation
This exposes bridge/adapter authentication credentials (`OutgoingToken`) to an unprivileged (view-role) authenticated user, matching the bounty's "bridge credentials" disclosure impact class. An attacker holding only view-role credentials can enumerate and read the outgoing auth tokens for every configured bridge, potentially impersonating the node to external adapters or pivoting to compromise adapter-side systems.

### Likelihood Explanation
The only precondition is possession of any valid view-role session cookie or view-role API token — the lowest privilege tier supported by the node's role model. No additional exploitation steps are needed beyond a single authenticated GET request, and the flow is fully reproducible/deterministic (no timing or race conditions).

### Recommendation
Wrap `bt.Index` and `bt.Show` with `auth.RequiresEditRole` (or a dedicated role check), consistent with `Create`/`Update`/`Destroy`, or strip `OutgoingToken` from `BridgeResource` for read endpoints/non-edit roles (e.g., add `omitempty`/redaction based on caller role, similar to how `IncomingToken` is only surfaced on `Create`).

### Proof of Concept
1. In `core/web/bridge_types_controller_test.go`, create an application, seed a bridge with `app.BridgeORM().CreateBridgeType`, capturing the `OutgoingToken`.
2. Create an HTTP client authenticated as a `view`-role user (e.g., via `app.NewHTTPClient(&cltest.UserView)`-style helper, mirroring other role-based tests in the repo, e.g. `bt := BridgeTypesController{app}` route tests).
3. Issue `client.Get("/v2/bridge_types/" + bt.Name.String())` and `client.Get("/v2/bridge_types")`.
4. Parse the JSON API response into `presenters.BridgeResource` and assert `resource.OutgoingToken == bt.OutgoingToken` and `resp.StatusCode == http.StatusOK`, demonstrating the view-role caller successfully retrieves the secret token without any `403`/`401` rejection — as opposed to a call to `POST/PATCH/DELETE /v2/bridge_types` with the same view-role client, which correctly returns `401 Unauthorized` due to `auth.RequiresEditRole`.

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
