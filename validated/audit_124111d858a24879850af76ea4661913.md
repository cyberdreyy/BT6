### Title
Unauthenticated `InitializeNonceAccount` allows front-running/hijacking of uninitialized nonce accounts, leading to fund theft - (File: `programs/system/src/system_instruction.rs`)

### Summary
The System Program's `InitializeNonceAccount` instruction handler performs no signer check whatsoever on the target account or the newly-assigned nonce authority. Any account that is system-owned and currently in `State::Uninitialized` can be initialized by an arbitrary, unrelated transaction, which sets an attacker-controlled pubkey as the nonce authority. This mirrors the reported "unprotected `initialize()`" bug class: an account is created in one step and initialized/claimed in a separate, unauthenticated step, allowing anyone to front-run the legitimate initialization and seize administrative control (here, the nonce authority) over the account.

### Finding Description
`initialize_nonce_account()` only validates that the target account is writable and currently `State::Uninitialized`; it never checks that the account itself is a transaction signer, nor that the caller/fee-payer is authorized to set the account's nonce authority: [1](#0-0) 

The processor dispatch for `SystemInstruction::InitializeNonceAccount` likewise only fetches sysvars and calls this function — there is no signer requirement enforced before invoking it: [2](#0-1) 

This is unlike `advance_nonce_account` and `withdraw_nonce_account`, which explicitly require `signers.contains(&data.authority)` before acting on an already-initialized nonce account: [3](#0-2) [4](#0-3) 

Because nonce accounts are commonly created via a separate `CreateAccount` transaction (funding a system-owned account) followed later by a distinct `InitializeNonceAccount` transaction (as also modeled by the CLI's `create_nonce_account` flow which normally bundles both instructions atomically, but nothing in the protocol enforces atomicity), any system-owned, rent-exempt, uninitialized account is a race target. An attacker monitoring the mempool/QUIC ingest for a pending `CreateAccount` (or simply knowing/observing a funded-but-uninitialized system account's pubkey) can submit their own `InitializeNonceAccount` instruction naming that account with themselves as the `authorized` nonce authority. Since no signature from the account or its intended owner is required, the attacker's instruction can land first (or land at all, even without racing, since there is no time-window requirement — any transaction referencing the account as writable succeeds).

### Impact Explanation
Once the attacker becomes the nonce `authority`, they gain full control equivalent to the legitimate owner:
- They can call `AdvanceNonceAccount`, `WithdrawNonceAccount`, and further `AuthorizeNonceAccount`, all of which check only `signers.contains(&data.authority)` — the attacker now satisfies that check.
- `withdraw_nonce_account` permits withdrawing the entire balance of the account (lamports == full balance path) once the durable nonce has advanced past the recorded value, needing only the (attacker-controlled) authority's signature: [5](#0-4) 

This results in concrete unauthorized fund theft/state mutation: the attacker can drain all lamports the victim deposited into the account intended to become their nonce account, and/or hijack the account for their own durable-nonce transaction replay protection needs.

### Likelihood Explanation
Likelihood is high in any workflow where account creation and nonce initialization are not strictly bundled/atomic (e.g., custom tooling, scripted deployments, or any two-step process), since the vulnerable instruction is a normal, permissionless System Program instruction reachable by any user transaction with no special privilege, and requires no signature from the victim account or its intended controller.

### Recommendation
Require that the account being initialized (or an authority explicitly tied to its creation, e.g., derived/pre-committed pubkey) is a signer of the `InitializeNonceAccount` instruction, consistent with the signer checks already present in `advance_nonce_account` and `withdraw_nonce_account`. At minimum, document and enforce that `CreateAccount` + `InitializeNonceAccount` must be submitted atomically within a single transaction, and add a runtime check that account 0 is a signer before allowing initialization, closing the front-running window.

### Proof of Concept
1. Victim submits transaction A: `CreateAccount` funding a new system-owned account `N` with rent-exempt lamports (signed by `N`'s keypair and payer).
2. Victim intends to submit transaction B (in a later slot/transaction): `InitializeNonceAccount(authorized = victim_authority)` on account `N`.
3. Attacker observes `N`'s pubkey (via mempool, prior on-chain activity, or address prediction) after transaction A lands but before transaction B lands.
4. Attacker submits `InitializeNonceAccount(authorized = attacker_pubkey)` naming account `N` as account 0 — no signature from `N` or the victim is required, and it succeeds because `N` is still `State::Uninitialized`, per `initialize_nonce_account()` at [6](#0-5) .
5. Victim's later transaction B fails with `InstructionError::InvalidAccountData` (already initialized).
6. Attacker later calls `WithdrawNonceAccount` signed by `attacker_pubkey`, draining all lamports from `N`.

pub(crate) fn withdraw_nonce_account(
    from_account_index: IndexOfAccount,
    lamports: u64,
    to_account_index: IndexOfAccount,
    rent: &Rent,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
    instruction_context: &InstructionContext,
) -> Result<(), InstructionError> {
    let mut from = instruction_context.try_borrow_instruction_account(from_account_index)?;
    if !from.is_writable() {
        ic_msg!(
            invoke_context,
            "Withdraw nonce account: Account {} must be writeable",
            from.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let check_signer = |signer: &Pubkey| {
        if !signers.contains(signer) {
            ic_msg!(
                invoke_context,
                "Withdraw nonce account: Account {} must sign",
                signer
            );
            return Err(InstructionError::MissingRequiredSignature);
        }
        Ok(())
    };

    let state: Versions = from.get_state()?;
    match state.state() {
        State::Uninitialized => {
            if lamports > from.get_lamports() {
                ic_msg!(
                    invoke_context,
                    "Withdraw nonce account: insufficient lamports {}, need {}",
                    from.get_lamports(),
                    lamports,
                );
                return Err(InstructionError::InsufficientFunds);
            }
            check_signer(from.get_key())?;
        }
        State::Initialized(data) => {
            if lamports == from.get_lamports() {
                let durable_nonce =
                    DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
                if data.durable_nonce == durable_nonce {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: nonce can only advance once per slot"
                    );
                    return Err(SystemError::NonceBlockhashNotExpired.into());
                }
                check_signer(&data.authority)?;
                from.set_state(&Versions::new(State::Uninitialized))?;
            } else {
                let min_balance = rent.minimum_balance(from.get_data().len());
                let amount = checked_add(lamports, min_balance)?;
                if amount > from.get_lamports() {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: insufficient lamports {}, need {}",
                        from.get_lamports(),
                        amount,
                    );
                    return Err(InstructionError::InsufficientFunds);
                }
                check_signer(&data.authority)?;
            }
        }
    };

    from.checked_sub_lamports(lamports)?;
    drop(from);
    let mut to = instruction_context.try_borrow_instruction_account(to_account_index)?;
    to.checked_add_lamports(lamports)?;

    Ok(())
}

pub(crate) fn initialize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    rent: &Rent,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Initialize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    match account.get_state::<Versions>()?.state() {
        State::Uninitialized => {
            let min_balance = rent.minimum_balance(account.get_data().len());
            if account.get_lamports() < min_balance {
                ic_msg!(
                    invoke_context,
                    "Initialize nonce account: insufficient lamports {}, need {}",
                    account.get_lamports(),
                    min_balance
                );
                return Err(InstructionError::InsufficientFunds);
            }
            let durable_nonce =
                DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
            let data = nonce::state::Data::new(
                *nonce_authority,
                durable_nonce,
                invoke_context
                    .environment_config
                    .blockhash_lamports_per_signature,
            );
            let state = State::Initialized(data);
            account.set_state(&Versions::new(state))
        }
        State::Initialized(_) => {
            ic_msg!(
                invoke_context,
                "Initialize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
    }
}
