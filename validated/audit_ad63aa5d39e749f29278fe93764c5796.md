### Title
Unauthenticated disclosure of per-plugin operational metrics via GET /plugins/:name/metrics - ([File: core/web/router.go])

### Summary
The `loopRoutes` route group in `core/web/router.go` registers `/plugins/:name/metrics`, `/discovery`, and pprof routes without wrapping them in `auth.Authenticate(...)`, unlike every other sensitive route in `v2Routes`. This allows any unauthenticated client to fetch internal plugin telemetry (job counts, addresses, error rates) that is otherwise proxied from an internal-only endpoint.

### Finding Description
`NewRouter` mounts `loopRoutes(app, api)` directly on the shared `api` group with no authentication middleware applied to it, in contrast to `v2Routes` which explicitly wraps sensitive endpoints in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` before registering handlers: [1](#0-0) 

`loopRoutes` itself registers `GET /plugins/:name/metrics` bound to `pluginMetricHandler` with no auth guard: [2](#0-1) 

`pluginMetricHandler` looks up the named plugin in the LOOP registry and proxies a GET request to the plugin's internal Prometheus metrics endpoint (`http://<loopHostName>:<PrometheusPort>/metrics`), returning the raw response body to the caller verbatim: [3](#0-2) 

The comment in the code even notes "unlike discovery, this endpoint is internal btw the node and plugin" — acknowledging the internal-only intent — yet the externally facing gin route has no authentication check, and the handler forwards the response with no field filtering/redaction. An unauthenticated caller who knows (or brute-forces/enumerates via `/discovery`, itself also unauthenticated) a plugin name (e.g. `median`, `mercury`, etc.) can retrieve that plugin's full Prometheus metrics payload, which can contain job counts, addresses, and error rates depending on what the LOOP plugin instruments.

### Impact Explanation
This is an authentication-bypass / information-disclosure issue: an unauthenticated network client can read internal operational telemetry of node LOOP plugins (job/report counts, per-chain addresses, error rates) that should require at least node-operator authentication, matching the "internal telemetry disclosure to outsiders" impact class. It does not expose private keys or enable fund movement, but it does leak internal operational state useful for reconnaissance/targeting of the node.

### Likelihood Explanation
No credential or role is required — a plain unauthenticated `GET /plugins/:name/metrics` request against the node's public web-server port is sufficient. The plugin name can be discovered via the equally unauthenticated `GET /discovery` endpoint, which enumerates all registered plugin names via `l.registry.List()`: [4](#0-3) 
This makes the attack trivially repeatable and requires no special network position beyond reaching the node's HTTP port.

### Recommendation
Wrap `loopRoutes` (or at minimum the `/plugins/:name/metrics` and `/discovery` routes) with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` the same way `v2Routes` protects other sensitive endpoints, or move these endpoints to a separate internal-only listener/port that is not exposed on the public API port.

### Proof of Concept
1. Build a `gin.Engine` via `NewRouter` with a mock `chainlink.Application` whose `GetLoopRegistry()` returns a registry containing a registered plugin (e.g., name `"median"`) and a mock backing HTTP server simulating the LOOP's `/metrics` endpoint.
2. Using `httptest.NewServer(router)`, issue `GET /plugins/median/metrics` with no `Authorization` header and no session cookie.
3. Assert the response status is `200 OK` and the body equals the mock plugin metrics payload — demonstrating no authentication was enforced, in contrast to an equivalent test against `authv2` routes (e.g. `GET /v2/keys/eth`) which should return `401 Unauthorized` without credentials.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
