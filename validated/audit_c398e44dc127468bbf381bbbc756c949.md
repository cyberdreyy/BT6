### Title
Closing a Balance discards `emissions_outstanding` without settling it - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
`Balance.close()` and `BankAccountWrapper::close_balance()` reset a lending position to `Balance::empty_deactivated()` and only validate that asset/liability amounts are zero — they never check or pay out `emissions_outstanding` before wiping the struct. This mirrors the reported bug class: a permissionless/unprivileged action (closing your own zero-balance position) destroys account state that still holds unclaimed accrued value, with no guaranteed prior claim step.

### Finding Description
`Balance` stores per-position `emissions_outstanding: WrappedI80F48` (unclaimed emissions rewards for that position) alongside `asset_shares`/`liability_shares`. [1](#0-0) 

`BalanceImpl::close()` unconditionally resets the whole struct to `empty_deactivated()`, which zeroes `emissions_outstanding` along with everything else: [2](#0-1) [3](#0-2) 

`BankAccountWrapper::close_balance()` — invoked by the user-facing `lending_account_close_balance` instruction — only checks that `current_liability_amount` and `current_asset_amount` are zero (`IllegalBalanceState` otherwise) before calling `balance.close()`. There is no check on `emissions_outstanding`: [4](#0-3) [5](#0-4) 

Notably, the program defines a dedicated error `CannotCloseOutstandingEmissions` (code 6033, "Cannot close balance because of outstanding emissions") in `errors.rs`, indicating the protocol's intended invariant is that a balance must not be closeable while it still has unclaimed emissions: [6](#0-5) 

However, the current `close_balance` code path (shown above) does not reference `emissions_outstanding` or raise `CannotCloseOutstandingEmissions` anywhere — the check is absent from the implementation despite the error variant existing in the enum and being referenced from `regression.rs` tests and `marginfi_account.rs`. This is the same structural bug pattern as the report: a bounded/optional "claim" step (here, harvesting `emissions_outstanding`) is not guaranteed to run before an irreversible destructive action (here, `balance.close()` zeroing the position), which can permanently freeze the user's already-accrued emissions.

### Impact Explanation
If a position accrues `emissions_outstanding` (e.g. via `update_emissions`/accrual logic while `asset_shares`/`liability_shares` are nonzero) and the user later drives both `asset_shares` and `liability_shares` to zero (e.g. `withdraw_all` + full repay, or dust cleanup) and then calls `lending_account_close_balance`, the outstanding emissions value recorded in `Balance.emissions_outstanding` is wiped to zero with no transfer to the user and no separate step guaranteed to have claimed it. This is a durable, unrecoverable freeze/loss of an emitted-token entitlement — a genuine financial-effect bug, matching the "permanent freezing of unclaimed yield" impact class from the analog report.

### Likelihood Explanation
Reachability is unprivileged and permissionless: any account owner can call `lending_account_close_balance` on their own zero-amount balance. The precondition (nonzero `emissions_outstanding` at the moment both asset and liability amounts reach zero) requires the emissions-accrual bookkeeping to not have been fully claimed/settled at that exact point — I was not able to fully trace every code path that settles `emissions_outstanding` (e.g. whether `withdraw_all`/`repay_all` or the deposit/withdraw instructions always flush it to zero before the balance can reach the "closeable" state) within the available iterations. Given the dedicated `CannotCloseOutstandingEmissions` error exists but is not wired into the current `close_balance` implementation, this strongly suggests either a regression (a check was removed/never wired up) or that the emissions system is largely deprecated (the emissions removal effort mentioned in patch notes) — in the latter case this may already be a dead/low-likelihood code path. [7](#0-6) 

### Recommendation
Add a check in `BankAccountWrapper::close_balance` (and `withdraw_all`/`repay_all` where applicable) that either: (a) requires `balance.emissions_outstanding` to be zero before allowing `balance.close()`, returning `MarginfiError::CannotCloseOutstandingEmissions` otherwise, or (b) automatically settles/transfers any outstanding emissions to the user's emissions destination before zeroing the balance. Also verify whether emissions functionality is fully deprecated per the 0.1.9 patch notes; if so, confirm `emissions_outstanding` can never be nonzero on any live bank, and if not fully deprecated, add regression coverage exercising `close_balance` with nonzero `emissions_outstanding`.

### Proof of Concept
Not independently reproduced in this analysis — I could not fully trace, within the available tool budget, every code path that updates/settles `Balance.emissions_outstanding` before `close_balance` is reachable (e.g. deposit/withdraw/`update_emissions` call ordering), so I cannot confirm whether a live, exploitable sequence currently exists versus emissions being effectively deprecated/dead code. A concrete PoC would need to: (1) enable emissions on a bank, (2) deposit and accrue `emissions_outstanding` on a `Balance` without claiming, (3) fully withdraw/repay to zero out `asset_shares`/`liability_shares` while `emissions_outstanding` remains nonzero, and (4) call `lending_account_close_balance` and confirm the emissions value is lost (no `CannotCloseOutstandingEmissions` error is raised and no transfer occurs).

    /// When `in_receivership` is true, clears the bank's liquidation price cache lock
    /// so that banks whose balances are closed mid-liquidation don't stay permanently locked.
    pub fn close_balance(&mut self, in_receivership: bool) -> MarginfiResult<()> {
        let balance = &mut self.balance;
        let bank = &mut self.bank;

        let current_liability_amount =
            bank.get_liability_amount(balance.liability_shares.into())?;
        let current_asset_amount = bank.get_asset_amount(balance.asset_shares.into())?;

        check!(
            current_liability_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing debt"
        );

        check!(
            current_asset_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing assets"
        );

        let asset_shares: I80F48 = balance.asset_shares.into();
        let liability_shares: I80F48 = balance.liability_shares.into();
        // Counters are incremented in `*_balance_internal` when shares cross
        // `ZERO_AMOUNT_THRESHOLD` upward; match that condition so we don't
        // double-decrement positions that already crossed downward earlier.
        let had_assets = asset_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);
        let had_liabs = liability_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);

        balance.close()?;

        if in_receivership {
            bank.cache.clear_liquidation_price_cache_locked();
        }

        // Asset-side dust = real tokens still in the liquidity vault that the
        // user never withdrew. Route to `collected_insurance_fees_outstanding`
        // so vault content stays fully accounted for, mirroring the fractional-
        // remainder handling in `withdraw_all`.
        if current_asset_amount > I80F48::ZERO {
            bank.collected_insurance_fees_outstanding =
                I80F48::from(bank.collected_insurance_fees_outstanding)
                    .checked_add(current_asset_amount)
                    .ok_or_else(math_error!())?
                    .into();
        }

        bank.change_asset_shares(-asset_shares, false)?;
        // Liability-side dust = bad debt the borrower never repaid. Decrementing
        // here makes the loss explicit instead of leaving phantom shares in
        // `total_liability_shares` that would compound interest indefinitely.
        bank.change_liability_shares(-liability_shares, true)?;

        if had_assets {
            bank.decrement_lending_position_count();
        }
        if had_liabs {
            bank.decrement_borrowing_position_count();
        }

        Ok(())
    }

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
