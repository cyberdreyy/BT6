### Title
Unauthenticated MessageId collision allows cross-user response hijacking in the WebAPI Gateway capabilities handler - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The legacy WebAPI capabilities gateway handler indexes pending user callbacks solely by `MessageId`, a value that is fully attacker-controlled (it is copied verbatim from the client-supplied JSON-RPC `id` field). An unprivileged external client can submit a request whose `MessageId` collides with another user's in-flight request, silently overwriting the stored callback and causing the DON node's response meant for the original requester to be delivered to the attacker instead.

### Finding Description
`ValidatedMessageFromReq` sets the internal `MessageId` directly from the untrusted JSON-RPC request ID supplied by the external HTTP caller: [1](#0-0) 

`Message.Validate()` only checks length/format constraints on `MessageId` (1–128 bytes, no trailing NUL) — it never enforces uniqueness or ties the ID to the caller's identity/session: [2](#0-1) 

In `HandleLegacyUserMessage`, the gateway handler stores the caller's `Callback` in a shared, handler-wide map keyed only by this attacker-controlled `MessageId`, with no check for an existing entry and no binding to session/sender identity:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [3](#0-2) 

When the DON node later responds with the trigger method, the response is looked up and delivered using only that same `MessageId`, and the entry is deleted:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
h.mu.Unlock()

if found {
    codec := api.JsonRPCCodec{}
    return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
}
``` [4](#0-3) 

Because `savedCallbacks[msg.Body.MessageId] = ...` unconditionally overwrites any existing entry, an attacker who submits a second HTTP request using the exact same `MessageId` as a legitimate victim's in-flight request (while the first request is still awaiting a DON response) hijacks the callback slot. When the DON node's response for that `MessageId` eventually arrives, it is delivered to whichever caller most recently registered under that ID — the attacker — instead of the original requester. This is the same root-cause pattern as the referenced report: a shared/reused context key (there, CPU registers reused across a re-entrant call; here, a map key reused across an unrelated caller's request) causes the system to misattribute a response/action to the wrong party, defeating the implicit invariant that a caller can only see their own results.

The comment at line 156-157 ("Send first response from a node back to the user, ignore any other ones... TODO: in practice, we should wait for at least 2F+1 nodes") acknowledges the single-slot-per-MessageId design but does not address the underlying trust issue that the slot's key is attacker-supplied and unauthenticated.

### Impact Explanation
An unauthenticated/unprivileged external client interacting with the gateway's legacy WebAPI trigger endpoint can:
- Redirect another user's DON-node response (which may contain sensitive workflow trigger output/payload data) to itself, resulting in cross-user information disclosure.
- Cause the legitimate user's own request to silently receive no response (since their callback slot was stolen and deleted upon delivery to the attacker), a denial-of-service against a specific victim request.

This matches the "cross-user response confusion" class explicitly called out as an acceptable analog, and it is reachable directly from an unprivileged client through the internet-facing gateway's message-handling path (no operator or node compromise required).

### Likelihood Explanation
Exploitation requires only that the attacker learn or predict a victim's `MessageId` and race a second request with the same ID before the first DON response arrives. `MessageId` is the raw JSON-RPC `id` chosen by the client; if any calling application uses predictable/sequential/reused IDs (a common pattern, and nothing in this codebase's validation prevents it) an external attacker who can also reach the same gateway endpoint could win the race. This is a timing-dependent, moderately likely scenario for any deployment where the gateway's WebAPI trigger endpoint is reachable by multiple, mutually untrusted callers.

### Recommendation
- Scope `savedCallbacks` keys by a value the gateway itself generates or that is bound to caller identity/session (e.g., an internally generated UUID or a keyed hash of `MessageId` + authenticated sender/session), rather than trusting the raw external `MessageId` as the sole lookup key.
- Reject registration of a new callback when an active (non-expired) entry already exists for the same `MessageId`, instead of silently overwriting it.
- Consider correlating the DON response back to the specific request/session that originated it (e.g., embedding an unpredictable nonce), so a collision cannot cause cross-user delivery even if `MessageId` values are duplicated.

### Proof of Concept
Not independently executed against a live deployment; the following describes the reachable sequence based on the code paths above:
1. Attacker sends a legacy JSON-RPC WebAPI trigger request to the gateway with `id = "X"`; `HandleLegacyUserMessage` stores `savedCallbacks["X"] = attackerCallback` and forwards the trigger to all DON members. [3](#0-2) 
2. Before the DON responds to the attacker's own request, the attacker submits a second (or races a concurrent) request using the exact same `id = "X"` that a victim is concurrently using for an unrelated legitimate trigger request; the map entry for `"X"` is overwritten with the second registration's callback.
3. When any DON node responds with `MessageId = "X"` (destined for whichever request the node associates with that ID), `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds the last-registered (attacker's) callback, and delivers the payload there. [4](#0-3) 

Because I do not have execution access to reproduce timing/race conditions in this environment, I cannot confirm the exact race window in a running deployment; this assessment is based on direct code-path analysis of the unconditional map overwrite and lack of caller-identity binding in the `MessageId` key.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
