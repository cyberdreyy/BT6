### Title
GET /v2/external_initiators leaks AccessKey and OutgoingToken to any authenticated user regardless of role - ([File: core/web/external_initiators_controller.go])

### Summary
The `ExternalInitiatorsController.Index` handler serializes every `ExternalInitiator` row — including its `AccessKey` and `OutgoingToken` — via `presenters.NewExternalInitiatorResource` with no role check, while the route registration only wraps it in the generic `authv2` group's `auth.Authenticate` middleware and not in `auth.RequiresEditRole`/`auth.RequiresAdminRole` like sibling mutating routes. A user authenticated with only the `view` role can therefore read every initiator's incoming `AccessKey` and outgoing `OutgoingToken`.

### Finding Description
The route is registered as:
```go
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
``` [1](#0-0) 
compared to `Create`/`Destroy` on the same resource, which are explicitly wrapped with `auth.RequiresEditRole`. `authv2` itself only requires session or token authentication (`auth.Authenticate(...AuthenticateByToken, AuthenticateBySession)`), with no minimum role, so a `UserRoleView` session/token passes. [2](#0-1) 

Inside `Index`, all rows returned by `BridgeORM().ExternalInitiators` (paginated, but unfiltered by any owner/creator concept) are converted with `presenters.NewExternalInitiatorResource`, which copies `AccessKey` and `OutgoingToken` verbatim into the JSON response: [3](#0-2) [4](#0-3) 

The ORM query has no per-user scoping — `external_initiators` is a node-wide table with no owning-user column — so every row is returned to whoever can call the endpoint: [5](#0-4) 

`RequiresEditRole`/`RequiresAdminRole` are the mechanisms this codebase uses elsewhere to gate sensitive reads/writes (e.g., `Create`/`Destroy` on the same controller, and most `/keys/*` mutation routes), but they are absent on this `GET` route, so no role wrapper stops a `view`-role or minimally-scoped API token holder from retrieving the secret material.

### Impact Explanation
`AccessKey`/`OutgoingToken` are credential material: `AccessKey` is used by external systems to authenticate inbound webhook calls to the node (`AuthenticateExternalInitiator`, which treats a valid access key as sufficient to assume the `run` role and trigger job runs), and `OutgoingToken` is used by the node to authenticate outbound calls to the external initiator. A `view`-role user (or any minimally privileged authenticated caller) obtaining these values could impersonate the external initiator to trigger job runs (`POST /v2/jobs/:ID/runs` via `AuthenticateExternalInitiator`) or forge outbound-authenticated calls, i.e. request impersonation / unauthorized job-run triggering — corresponding to a "secret/key disclosure enabling unauthorized action" bounty class.

### Likelihood Explanation
Minimal precondition: any valid session or API token with `UserRoleView` (the lowest role) is sufficient — no edit/admin/run role, no external-initiator credential, and no database or host access is needed. The attack is a single unauthenticated-role-limited `GET /v2/external_initiators` call, fully repeatable and requires no special timing or race condition.

### Recommendation
Wrap the `Index` route with `auth.RequiresEditRole` (or `RequiresAdminRole`) consistent with `Create`/`Destroy`, and/or strip `AccessKey`/`OutgoingToken` from `presenters.ExternalInitiatorResource` for list/read responses (only return them once, at creation time, as already done via `presenters.NewExternalInitiatorAuthentication`).

### Proof of Concept
Go handler-level test plan (`core/web/external_initiators_controller_test.go`):
1. Seed two `ExternalInitiator` records via `BridgeORM().CreateExternalInitiator`.
2. Create a session/API token for a user with `sessions.UserRoleView`.
3. Call `GET /v2/external_initiators` authenticated as that view-role user.
4. Assert HTTP 200 is returned (no 401/403 from a role check) and that the JSON body's `attributes.accessKey`/`attributes.outgoingToken` fields for both seeded initiators are non-empty and match the values generated at creation — demonstrating disclosure of secret material to a `view`-role caller.
5. Contrast with existing test coverage of `Create`/`Destroy`, which already return `401 Unauthorized` for `view`-role users via `RequiresEditRole`, to show the asymmetry.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}

func (o *orm) ExternalInitiators(ctx context.Context, offset int, limit int) (initiators []ExternalInitiator, count int, err error) {
	err = o.transact(ctx, true, func(tx *orm) error {
		if err = tx.ds.GetContext(ctx, &count, "SELECT COUNT(*) FROM external_initiators"); err != nil {
			return pkgerrors.Wrap(err, "ExternalInitiators failed to get count")
		}

		sql := `SELECT * FROM external_initiators ORDER BY name asc LIMIT $1 OFFSET $2;`
		if err = tx.ds.SelectContext(ctx, &initiators, sql, limit, offset); err != nil {
			return pkgerrors.Wrap(err, "ExternalInitiators failed to load external_initiators")
		}
		return nil
	})
	return
}
