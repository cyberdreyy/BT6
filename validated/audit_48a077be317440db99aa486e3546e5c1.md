## Analysis

`update_commision` is designed to "settle" the staking contract's accounting at the old rate before applying a new commission rate, by calling `distribute_internal` then `request_commission_internal` before mutating `commission_percentage`: [1](#0-0) 

However, `distribute_internal` only actually touches the `distribution_pool`'s share pricing when it succeeds in withdrawing non-zero coins from the stake pool: [2](#0-1) 

`stake::withdraw_with_cap` only converts `pending_inactive` into withdrawable `inactive` once the lockup has actually expired; if the staker's `unlock_stake` request is still `pending_inactive` (in-flight, lockup not yet expired), `inactive` is `0` and `distribution_amount` is `0`, so `distribute_internal` returns immediately **without ever calling `update_distribution_pool`** to snapshot the pool's growth at the old commission rate.

`request_commission_internal`, the other "settlement" step, only recalculates commission on the *active* stake principal (`total_active_stake - principal`) via `get_staking_contract_amounts_internal`; it never touches `distribution_pool` share pricing for the already-`pending_inactive` staker withdrawal: [3](#0-2) [4](#0-3) 

So when the staker previously called `unlock_stake`, their withdrawal amount was registered as shares in `distribution_pool` via `add_distribution`, whose growth-accrual snapshot (`update_distribution_pool`) was taken using the **old** `commission_percentage` at that time: [5](#0-4) 

If `update_commision` is called while that unlocked amount is still `pending_inactive` (lockup not yet expired), neither of its two "settlement" calls re-snapshots the pool at the old rate — `distribute_internal` no-ops (0 withdrawn) and `request_commission_internal` doesn't touch `distribution_pool` at all. `commission_percentage` is then overwritten with the new value. When the stake finally matures and someone later calls `distribute()` (or any future `add_distribution`/`distribute_internal` call), `update_distribution_pool` will price all reward growth accrued in `distribution_pool` since the *original* `unlock_stake` snapshot using the **now-current (new)** `commission_percentage`, taxing rewards that accrued on a withdrawal the staker had already locked in under the old rate.

I could not view the body of `update_distribution_pool` itself (file was truncated beyond line 1000), so I cannot fully confirm the exact per-call growth-accrual arithmetic, but the structural gap — `distribute_internal`'s early return on `distribution_amount == 0` combined with `request_commission_internal` never touching `distribution_pool` — is directly verifiable in the code shown above and is sufficient to demonstrate that the "settle-before-rate-change" invariant `update_commision` relies on does not hold when the unlocked stake is still `pending_inactive`.

### Title
Commission rate change via `update_commision` can retroactively tax already-unlocked (`pending_inactive`) staker withdrawals - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`update_commision` assumes calling `distribute_internal` + `request_commission_internal` fully settles the `distribution_pool`'s share pricing at the old commission rate before the rate is changed. This assumption fails when a staker's previously `unlock_stake`d amount is still `pending_inactive` (lockup not expired): `distribute_internal` short-circuits on zero withdrawable coins, and `request_commission_internal` never touches `distribution_pool`. The pool's reward-growth snapshot therefore remains stale until a future `distribute()` call, which then prices all accrued growth — including growth that occurred while the old rate was active — at the new commission rate.

### Impact Explanation
This corrupts operator commission accounting by taxing an already-committed staker withdrawal at a commission rate that was not in effect when the withdrawal was requested, violating the documented "commission changes apply prospectively" invariant. Depending on whether the rate increases or decreases, this either overpays or underpays the operator/beneficiary at the expense of the staker or operator, respectively — a share-accounting corruption within the `Stake And Lockup Pivots` scope (accounting across `pending_inactive`/rewards/commission must preserve value and withdrawal rights).

### Likelihood Explanation
Reachable by the staker alone (owner of the staking contract) with no privileged role required beyond being the staker of their own contract — an unprivileged, self-triggered sequence: `unlock_stake` then `update_commision` before the lockup cycle expires. This is a normal, easily reachable transaction ordering, not requiring any race condition with another party.

### Recommendation
In `distribute_internal`, always call `update_distribution_pool` with the current `commission_percentage` before returning, even when `distribution_amount == 0`, so that the pool's growth-accrual snapshot is captured at the pre-update rate regardless of whether funds have matured enough to be physically withdrawn. Alternatively, have `update_commision` explicitly force a `distribution_pool` price update (independent of actual coin withdrawal) prior to mutating `commission_percentage`.

### Proof of Concept
1. Staker creates a staking contract with commission `X%`.
2. Staker calls `unlock_stake(staker, operator, amount)` — this calls `add_distribution`, which snapshots `distribution_pool` growth at rate `X%` and registers `amount` as staker shares; stake becomes `pending_inactive` [6](#0-5) .
3. Before the lockup expires, staker calls `update_commision(staker, operator, Y%)`. `distribute_internal` finds `inactive == 0` (only `pending_inactive` exists) so `distribution_amount == 0` and it returns without updating `distribution_pool` [7](#0-6) . `request_commission_internal` similarly does not touch `distribution_pool`. `commission_percentage` is set to `Y%`.
4. Time passes; lockup expires and rewards accrue on the `pending_inactive` amount.
5. Anyone calls `distribute()`. `distribute_internal` now withdraws the matured coins and calls `update_distribution_pool` using the **new** `Y%` rate over the entire growth interval since step 2, taxing rewards that accrued (in part) while `X%` was the contractually-applicable rate for that already-requested withdrawal [8](#0-7) .

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;

            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,

            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });

    fun get_staking_contract_amounts_internal(
        staking_contract: &StakingContract
    ): (u64, u64, u64) {
        // Pending_inactive is not included in the calculation because pending_inactive can only come from:
        // 1. Outgoing commissions. This means commission has already been extracted.
        // 2. Stake withdrawals from stakers. This also means commission has already been extracted as
        // request_commission_internal is called in unlock_stake
        let (active, _, pending_active, _) =
            stake::get_stake(staking_contract.pool_address);
        let total_active_stake = active + pending_active;
        let accumulated_rewards = total_active_stake - staking_contract.principal;
        let commission_amount =
            accumulated_rewards * staking_contract.commission_percentage / 100;

        (total_active_stake, accumulated_rewards, commission_amount)
    }
