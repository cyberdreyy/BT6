### Title
Cross-user response leak via `savedCallbacks` map keyed only by `MessageId` in `WebAPIHandler.HandleLegacyUserMessage` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`JsonRPCCodec.EncodeLegacyResponse` itself performs no isolation check — it is a stateless codec that blindly serializes whatever `*api.Message` it is given [1](#0-0) . The actual isolation failure lives one layer up, in `core/services/gateway/handlers/capabilities/handler.go`, whose `savedCallbacks` map is keyed solely by the attacker-controlled `MessageId`, with no sender binding, unlike the sender-aware `RequestCache` used elsewhere in the gateway.

### Finding Description
`MessageId` is fully client-controlled: in `JsonRPCCodec.DecodeJSONRequest`, `msg.Body.MessageId = request.ID` is set directly from the JSON-RPC `id` field supplied by the caller [2](#0-1) , and the gateway only checks that the ID is ≤200 characters before dispatch [3](#0-2) .

In `HandleLegacyUserMessage`, the handler registers the caller's callback in a map keyed only by `msg.Body.MessageId`, with no sender component: [4](#0-3) 

When a DON node later responds with `MethodWebAPITrigger` for that same `MessageId`, `handleWebAPITriggerMessage` looks the callback up and deletes it using `MessageId` alone, then encodes and forwards whatever `Payload` the node returned: [5](#0-4) 

The `savedCallback` struct stores no `sender` field to reconcile against the original requester [6](#0-5) . If an attacker submits a legacy request whose `MessageId` collides with another in-flight request's `MessageId` (attacker fully controls this field), the attacker's `savedCallbacks[MessageId]` entry overwrites the victim's entry. When the DON later replies for that `MessageId` — whether it was answering the victim's original request or the attacker's own duplicate — `handleWebAPITriggerMessage` delivers the payload to whichever callback is currently registered, calling `codec.EncodeLegacyResponse(msg)` to serialize and return it. Since `EncodeLegacyResponse` has no per-caller isolation logic (nor should it, being a stateless codec), it dutifully encodes and returns the foreign payload to the attacker.

This differs from `core/services/gateway/handlers/common/requestcache.go`, which correctly keys pending requests by `globalId{sender, id}` [7](#0-6) [8](#0-7) , demonstrating that the correct sender-scoped pattern exists in the codebase but was not applied consistently to `capabilities/handler.go`'s legacy trigger path.

### Impact Explanation
Cross-user response confusion: an unprivileged gateway user can obtain another caller's `web_api_trigger` response payload (which may contain workflow execution results or other data returned from the DON) by colliding `MessageId` values. This matches the Chainlink bounty impact class of unauthorized disclosure of another user's data / request impersonation via response hijacking.

### Likelihood Explanation
Exploitation requires the attacker to know or guess a victim's in-flight `MessageId` and send a competing request before the DON responds to the original — feasible if IDs are predictable/sequential or observable by the attacker (e.g., shared client library, logs, or a race the attacker deliberately triggers by flooding requests with a range of candidate IDs). No special privilege beyond being a legitimate low-privileged gateway client is needed, and the race is repeatable.

### Recommendation
Bind the `savedCallbacks` entry (and its lookup/deletion) to `(sender, MessageId)` instead of `MessageId` alone, mirroring `common.RequestCache`'s `globalId{sender, id}` keying, and validate that the node's response `Sender`/original requester matches before invoking `codec.EncodeLegacyResponse` and delivering to the callback.

### Proof of Concept
Go handler-level test plan (in `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Construct handler with a DON mock that captures `SendToNode` calls but does not auto-respond.
2. Call `handler.HandleLegacyUserMessage` for "victim" with `MessageId = "dup-id"`, `Sender = "0xVICTIM"`, and callback `cbVictim`.
3. Call `handler.HandleLegacyUserMessage` for "attacker" with the same `MessageId = "dup-id"`, `Sender = "0xATTACKER"`, and callback `cbAttacker`, simulating the attacker guessing the ID.
4. Simulate a DON node response for `MessageId = "dup-id"` (as if answering the victim's request) via `handler.HandleNodeMessage`.
5. Assert that `cbAttacker.Wait()` receives the response (containing the victim's intended payload) instead of `cbVictim`, proving cross-user leakage — i.e., assert `cbVictim.Wait()` times out/never fires while `cbAttacker` receives `EncodeLegacyResponse` output containing data meant for the victim.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
	codec := api.JsonRPCCodec{}
	timer := time.AfterFunc(c.timeout, func() {
		err := c.deleteAndSendOnce(key, handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(request), ErrorCode: api.RequestTimeoutError})
		if err != nil {
			lggr.Errorw("failed to send timeout response", "error", err)
		}
	})
	c.cache[key] = &pendingRequest[T]{Callback: callback, responseData: responseData, timeoutTimer: timer}
	return nil
}
