### Title
authenticateUserCanRun fails to validate role membership, granting run access to any unrecognized/unknown role value - ([File: core/web/resolver/auth.go])

### Summary
`authenticateUserCanRun` only rejects sessions whose role equals `sessions.UserRoleView`; it does not verify that the role belongs to the valid enum `{view, edit, admin, run}`. Any `sessions.User.Role` value that isn't literally `"view"` (including an empty string or a corrupted/unrecognized value) passes the check and is granted run-level access to GraphQL mutations.

### Finding Description
`authenticateUserCanRun` in `core/web/resolver/auth.go` is:
```go
func authenticateUserCanRun(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role == sessions.UserRoleView {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}
``` [1](#0-0) 

`sessions.UserRole` is just a `string` type with four documented constants (`admin`, `edit`, `run`, `view`) [2](#0-1) , but nothing in `Session`/`User` enforces that `Role` is restricted to these values at the type level — it is a plain string field [3](#0-2) . Validation only happens in `GetUserRole`, which is invoked when creating/updating users from user-supplied strings (e.g., in `user_controller.go`, LDAP/OIDC role mapping) [4](#0-3) . Session records populated from other paths (LDAP/OIDC session tables, DB drift/migration, direct row edits) are read back into `sessions.User{Role: ...}` without re-validating against the enum, e.g. `AuthorizedUserWithSession` in the LDAP and OIDC authenticators simply assign whatever string is stored in the row [5](#0-4) .

Because `authenticateUserCanRun` uses an equality check against only `UserRoleView` instead of an allow-list/switch over all valid non-view roles, any `Role` value other than the literal string `"view"` — including `""`, `"unknown"`, or any other drifted value — passes the guard and the resolver proceeds as if the caller has run permission. Note that the sibling function `authenticateUserCanEdit` has the same flaw (rejects only `view`/`run`, so any unknown role reaches edit-level checks too), while `authenticateUserIsAdmin` correctly fails closed by checking `!= UserRoleAdmin` [6](#0-5) .

### Impact Explanation
Any GraphQL mutation gated by `authenticateUserCanRun` (job run / execution triggers) would be authorized for a session carrying a non-canonical role string, which violates least-privilege authorization and enables unauthorized job/run execution — a role/authorization bypass matching Chainlink's unauthorized job run impact class.

### Likelihood Explanation
Exploitation requires a session whose `User.Role` value differs from `"view"` but is not a legitimate elevated role — i.e., dependent on the role storage/sync path (LDAP/OIDC/local DB) producing or persisting a non-enum value. This is a precondition (e.g. DB drift or a role-sync edge case), not attacker-controlled input directly, so likelihood is contingent on that precondition being reachable; however, once present, exploitation is trivial and fully repeatable (a single authenticated GraphQL run-mutation call).

### Recommendation
Change `authenticateUserCanRun` (and `authenticateUserCanEdit`) to fail closed by allow-listing recognized permitted roles instead of only excluding `UserRoleView`, e.g.:
```go
switch session.User.Role {
case sessions.UserRoleRun, sessions.UserRoleEdit, sessions.UserRoleAdmin:
    return nil
default:
    return RoleNotPermittedError{session.User.Role}
}
```

### Proof of Concept
Go unit test in `core/web/resolver/auth_test.go` (or new test file in `core/web/resolver`):
```go
func TestAuthenticateUserCanRun_RejectsUnknownRole(t *testing.T) {
    session := sessions.User{Role: sessions.UserRole("unknown")}
    ctx := auth.SetGQLAuthenticatedSession(context.Background(), sessions.Session{}, session) // or equivalent test helper used in resolver_test.go
    err := authenticateUserCanRun(ctx)
    assert.Error(t, err) // currently fails: err is nil
}
```
Expected (desired) behavior: `authenticateUserCanRun` returns `RoleNotPermittedError` for any role not in `{run, edit, admin}`. Current behavior: returns `nil`, confirming the bypass.

// GetUserRole is the single point of logic for mapping role string to UserRole
func GetUserRole(role string) (UserRole, error) {
	if role == string(UserRoleAdmin) {
		return UserRoleAdmin, nil
	}
	if role == string(UserRoleEdit) {
		return UserRoleEdit, nil
	}
	if role == string(UserRoleRun) {
		return UserRoleRun, nil
	}
	if role == string(UserRoleView) {
		return UserRoleView, nil
	}

	errStr := fmt.Sprintf(
		"Invalid role: %s. Allowed roles: '%s', '%s', '%s', '%s'.",
		role,
		UserRoleAdmin,
		UserRoleEdit,
		UserRoleRun,
		UserRoleView,
	)
	return UserRole(""), pkgerrors.New(errStr)
