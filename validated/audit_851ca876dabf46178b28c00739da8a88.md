### Title
Missing owner check on mint account when computing token decimals - misreported `tokenAmount.decimals`/`uiAmount` - ([File: rpc/src/parsed_token_accounts.rs])

### Finding Description
`get_parsed_token_account` extracts the mint pubkey embedded in a token account's data via `get_token_account_mint`, which only checks that the account data is "token-account-shaped" (`Account::valid_account_data`) and then reads bytes `0..32` as the mint pubkey, with no owner validation of the token account itself at that point [1](#0-0) . It then fetches whatever account exists at that pubkey from the bank/overwrites and passes its raw `data()` directly into `get_additional_mint_data`, without ever checking that the fetched mint account's `owner()` is a token program:

```rust
let additional_data = get_token_account_mint(account.data())
    .and_then(|mint_pubkey| {
        account_resolver::get_account_from_overwrites_or_bank(&mint_pubkey, bank, overwrite_accounts)
    })
    .and_then(|mint_account| get_additional_mint_data(bank, mint_account.data()).ok())
``` [2](#0-1) 

`get_additional_mint_data` itself only attempts `StateWithExtensions::<Mint>::unpack(data)` and derives `decimals`, `interest_bearing_config`, and `scaled_ui_amount_config` purely from the byte layout — there is no owner check anywhere in this function: [3](#0-2) 

The batch path `get_mint_owner_and_additional_data` (used by `get_parsed_token_accounts`) does read `mint_account.owner()`, but only to *return* it as the "token program" to associate with the mint — it never validates that this owner is actually a legitimate SPL Token/Token-2022 program before trusting the unpacked `Mint` shape [4](#0-3) .

Exploit flow:
1. Attacker submits a transaction (via a System-owned or arbitrary owned program) creating account `B` whose raw bytes happen to unpack successfully as `spl_token_2022_interface::state::Mint` (e.g., a 82-byte all-zero-ish buffer with `is_initialized = true` and attacker-chosen `decimals` byte) — `B` is *not* owned by any token program.
2. Attacker creates/controls account `A` with token-account-shaped data (`Account::valid_account_data(A.data())` true) whose embedded mint field (bytes 0..32) is set to `B`'s pubkey, and sets a real `amount`.
3. A client calls `getAccountInfo(A, {encoding: "jsonParsed"})`. This flows through `get_parsed_token_account` → `get_token_account_mint(A.data())` → resolves `B` → `get_additional_mint_data(bank, B.data())`, which unpacks `B` as a `Mint` and returns `B`'s attacker-chosen `decimals` with no owner check.
4. The resulting `SplTokenAdditionalDataV2` (bogus decimals) is applied to `A`'s real `amount` in `parse_token_v3`/`token_amount_to_ui_amount_v3`, producing a misreported `tokenAmount.uiAmount`/`uiAmountString`/`decimals` in the JSON-RPC response for account `A`, even though `A` itself is correctly owned by the real token program (owner check on `A` happens in `parse_account_data_v3`/`encode_ui_account`, but that only gates whether `A`'s own data is parsed as SPL-token shape — it says nothing about `B`).

This matches the described invariant violation: decoders must not trust owner-unchecked cross-account data (`B`) to compute `decimals`/`amount` fields reported for `A`.

### Impact Explanation
This is a decoder/RPC data-integrity bug: a single unprivileged on-chain write (creating accounts `A` and `B`) followed by a single `getAccountInfo`/`getProgramAccounts`/subscription call with `jsonParsed` encoding causes the validator to return an incorrect `uiAmount`/`decimals` for a real token account. This falls under "decoder panic and misreporting" / wrong data returned via RPC — a `PARSE_FIDELITY` violation with concrete client-facing impact (e.g., wallets/explorers displaying wrong token amounts for an account that superficially still looks like a normal SPL token account owned by the genuine token program).

### Likelihood Explanation
Fully attacker-controlled and repeatable with no special privileges: the attacker only needs to write two accounts with attacker-chosen byte layouts (any program, including a trivial memo/no-op or self-owned data account, can hold arbitrary bytes) and then issue one `getAccountInfo` call. No leader/gossip/staked-node access, no validator config, and no more than a single RPC call is required, satisfying the unprivileged, low-rate constraint.

### Recommendation
In `get_parsed_token_account` (and equivalently `get_mint_owner_and_additional_data`), before calling `get_additional_mint_data` on a fetched "mint" account, validate that the mint account's `owner()` is one of the recognized token program ids (`spl_generic_token::is_known_spl_token_id`/`spl_token_ids`, consistent with the check already used to gate SPL-token parsing of the primary account). Reject/ignore the mint data (fall back to `None`/error, same as an unparsable mint) if the owner check fails, so that `decimals`/interest-bearing/scaled-UI extension data can never be sourced from an account not owned by a genuine token program.

// account-decoder/src/parse_token.rs or rpc/src/parsed_token_accounts.rs integration test
#[test]
fn test_bogus_mint_owner_rejected() {
    // B: attacker-controlled account, NOT owned by spl_token/spl_token_2022,
    // but its bytes unpack as a valid Mint with attacker-chosen decimals=18.
    let mut mint_data = vec![0u8; Mint::get_packed_len()];
    let mut mint = Mint::unpack_unchecked(&mint_data).unwrap();
    mint.is_initialized = true;
    mint.decimals = 18; // attacker-chosen, inflated decimals
    Mint::pack(mint, &mut mint_data).unwrap();
    let bogus_mint_account = AccountSharedData::new(
        1_000_000,
        mint_data.len(),
        &Pubkey::new_unique(), // arbitrary owner, e.g. System program - NOT token program
    );
    // bogus_mint_account.set_data(mint_data) ...

    // A: real token account whose `mint` field points at B, with real amount.
    let mut account_data = vec![0u8; Account::get_packed_len()];
    let mut account = Account::unpack_unchecked(&account_data).unwrap();
    account.mint = bogus_mint_pubkey; // B's pubkey
    account.owner = Pubkey::new_unique();
    account.amount = 1_000_000_000; // real amount
    account.state = AccountState::Initialized;
    Account::pack(account, &mut account_data).unwrap();
    let token_account = AccountSharedData::new(
        1_000_000, account_data.len(), &spl_token_2022_interface::id(), // A correctly owned by token program
    );
    // token_account.set_data(account_data) ...

    // Insert B into bank at bogus_mint_pubkey, then call get_parsed_token_account(bank, &a_pubkey, token_account, None)
    let ui_account = get_parsed_token_account(&bank, &a_pubkey, token_account, None);

    // EXPECTED (fixed behavior): decimals must NOT be derived from B since B's owner
    // is not a token program; parsing should fall back to unparsed/binary data or
    // report an additional-data error, not decimals=18.
    // CURRENT (buggy) behavior: ui_account contains tokenAmount.decimals == 18,
    // derived from an account not owned by any token program.
    assert_ne!(extract_decimals(&ui_account), Some(18), "mint owner check missing");
}

pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

```rust
fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
