### Title
`.git` directory extraction guard is bypassed by case-variant zip entry names on Windows (case-insensitive filesystem) - ([File: helpers/archives/path_check_helper.go])

### Summary
`isPathAGitDirectory` performs a case-sensitive comparison of the first path segment against the literal string `".git"`. On Windows (and other case-insensitive filesystems), a zip entry whose path begins with a different-case variant such as `.GIT`, `.Git`, or `.gIt` will not match this check, yet the OS will still resolve it to the same on-disk `.git` directory. This allows a crafted cache/artifact zip archive to extract attacker-controlled files (e.g., git hooks) into the repository's real `.git` directory despite the guard.

### Finding Description
The guard is:
```go
func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}
``` [1](#0-0) 

`filepath.Clean` on Windows correctly normalizes both `/` and `\` separators into `filepath.Separator`, so mixed-separator variants (`.git\hooks\pre-commit`, `.git/hooks/pre-commit`) are already handled equivalently and are not a viable bypass vector by themselves. However, the comparison `parts[0] == ".git"` is a case-sensitive Go string comparison. A zip entry such as `.GIT/hooks/pre-commit` produces `parts[0] == ".GIT"`, which fails the equality check, so `errorIfGitDirectory` returns `nil` and no warning/skip occurs in `ExtractZipArchive`:
```go
for _, file := range archive.File {
    if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
        printGitArchiveWarning("extract")
    }
    if err := extractZipFile(file); tracker.actionable(err) { ... }
}
``` [2](#0-1) 

`extractZipFile` then proceeds unimpeded: `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and `extractZipFileEntry`/`extractZipDirectoryEntry` write the file via `os.OpenFile`/`os.Mkdir` using the exact (differently-cased) name given. [3](#0-2) [4](#0-3) 

On Windows, filesystem path lookups (NTFS default configuration, and the Win32 API layer Go uses) are case-insensitive. If the build directory already contains a real `.git` directory (checked out earlier in the job), a write to `.GIT\hooks\pre-commit` resolves to the same directory entry as `.git\hooks\pre-commit` on disk — the OS does not create a separate case-variant directory. The unit test `TestDoesPathsListContainGitDirectory` only exercises same-case `.git` variants (`.git`, `.git/`, `././.git/`) and never tests case variance, so this gap is untested. [5](#0-4) 

`lchmod` on Windows (`helpers/archives/os_windows.go`) only affects file permission bits (`os.Chmod`) after extraction and is not itself part of the path-safety decision, but it confirms the file was actually written to disk under whatever name was given, with no additional path-safety re-check at that stage. [6](#0-5) 

### Impact Explanation
A job that controls a cache or artifact archive (both are job/pipeline-author-controlled inputs restored by the runner before subsequent git operations) can plant a hook file (e.g., `post-checkout`, `pre-push`, `reference-transaction`) into the project's `.git/hooks` directory using a case-variant path like `.GIT/hooks/post-checkout`, bypassing the extraction guard. When the runner's generated build script later performs a git operation (fetch/checkout/credential helper setup) against that same repository checkout, git will execute the planted hook, resulting in runner-side command execution beyond the intended cache/artifact extraction root — i.e., an escape from the archive-extraction sandbox into repository-native code execution.

### Likelihood Explanation
Preconditions are realistic and fully attacker/job-controlled: Windows shell/PowerShell executor, a job that defines a cache or artifacts entry containing a maliciously crafted zip with case-varied `.git` paths, and a job pipeline where cache/artifact restore precedes a git command against the same working directory (the default GitLab Runner build flow: clone/fetch, then restore cache, then run job script — or restore cache, then a later git operation such as `git submodule` or a subsequent job's clone). No admin privileges or special configuration are needed beyond standard cache/artifact usage, and the bug is deterministic/repeatable given the same input.

### Recommendation
Make `isPathAGitDirectory` comparison case-insensitive (e.g., use `strings.EqualFold(parts[0], ".git")`) to align the check with the case-insensitive semantics of Windows (and default macOS) filesystems, matching the on-disk behavior actually being protected against. Apply the same fix to any other archive path validation reusing this helper (tar extraction paths, `zip_create.go`).

### Proof of Concept
Add a table-driven case to `TestDoesPathsListContainGitDirectory` in `helpers/archives/path_check_helper_test.go`:
```go
{".GIT", true},
{".Git/hooks/pre-commit", true},
{".gIt\\hooks\\pre-commit", true}, // windows-style separator + case variant
```
Expected: current implementation fails these assertions (`isPathAGitDirectory` returns `false`), proving the bypass; after applying `strings.EqualFold`, all assertions pass.

Integration-level PoC: build a zip archive containing entry `.GIT/hooks/post-checkout` with executable content, call `ExtractZipArchive` against a directory that already contains a real `.git` folder (simulating a Windows case-insensitive filesystem — reproducible on a real Windows CI PoC job with a `cache:` archive containing this entry), then assert that `.git/hooks/post-checkout` exists on disk and that no `.git inside of archive` warning was logged, confirming the guard was silently bypassed.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	if os.IsExist(err) {
		err = nil
	}
	return

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
