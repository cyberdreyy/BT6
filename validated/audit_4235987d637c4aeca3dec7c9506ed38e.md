### Title
Unrestricted `receive()` in ConvexStrategyETH permanently locks accidental Ether transfers - (File: contracts/strategies/convex/ConvexStrategyETH.sol)

### Summary
`ConvexStrategyETH` declares an unrestricted `receive() external payable` (line 35) so the strategy can accept raw ETH unwrapped from WETH inside `_depositInCurve`. However, no function in the strategy (or in `ConvexBaseStrategy`/`BaseStrategy`) ever reads or spends `address(this).balance`: deposits, redemptions and harvests are all denominated in WETH/curve LP tokens, and there is no ETH sweep or rescue method. Any ETH sent to the strategy outside of the transient `add_liquidity` flow is therefore irrecoverable.

### Finding Description
`LidoCDOTrancheGateway` shows the correct pattern — its `receive()` at `contracts/strategies/lido/LidoCDOTrancheGateway.sol:99-101` requires `msg.sender == wethToken`, rejecting stray ETH. `ConvexStrategyETH` lacks any such guard:

```solidity
// contracts/strategies/convex/ConvexStrategyETH.sol
receive() external payable {}
```

The only intended use of raw ETH is inside `_depositInCurve` (lines 23-33), which unwraps WETH via `_weth.withdraw(_balance)` and immediately forwards the entire balance to the Curve pool with `add_liquidity{value: _balance}`. Critically, the value forwarded is `_balance` — the WETH amount unwrapped in that same call — not `address(this).balance`. Pre-existing ETH sitting in the contract is never forwarded to Curve, never credited to the `IdleCDO`, and never counted in `price()` or `getContractValue`.

Because strategies are upgradeable proxies owned by the `IdleCDO`, there is no admin `sweep`, `rescue`, or arbitrary-call function exposed to recover ETH (the owner is the CDO contract, which itself has no ETH rescue path for the strategy). An unprivileged sender — a direct sender, a contract that mistakenly unwraps WETH to the strategy address, or an ETH-denominated refund — can push ETH in, and it is permanently frozen.

### Impact Explanation
Permanent freezing of funds. Any ETH held by the strategy is unaccounted for: it does not increase tranche holder value, cannot be withdrawn via `redeem`/`withdraw`, and cannot be recovered by any privileged or unprivileged actor. Loss equals the full ETH balance received outside the atomic `_depositInCurve` flow.

### Likelihood Explanation
Low-to-medium. It requires an erroneous or forced ETH transfer (e.g., a contract paying out raw ETH, a `selfdestruct` push, or a user mistake). Note that even `selfdestruct`-forced ETH is permanently stuck here precisely because no function consumes `address(this).balance` — a non-payable/whitelisted `receive()` like the gateway's would at least bound the accidental-transfer surface.

### Recommendation
Restrict the receive path and account for stray balance:

```solidity
receive() external payable {
    require(msg.sender == WETH, "only-weth");
}
```

Additionally, in `_depositInCurve`, either deposit `address(this).balance` (after unwrapping WETH) or add an owner-gated `sweepETH` so any forced/accidental ETH is recoverable and credited rather than frozen.

### Proof of Concept
Foundry fork test (mainnet, Convex ETH strategy deployed behind an IdleCDO):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;

import "forge-std/Test.sol";

interface IConvexStrategyETH {
    function WETH() external view returns (address);
    function depositPosition() external view returns (uint256);
}

contract StuckEthPoC is Test {
    IConvexStrategyETH strategy = IConvexStrategyETH(<CONVEX_STRATEGY_ETH_ADDRESS>);

    function test_AccidentalEthStuck() public {
        address alice = makeAddr("alice");
        vm.deal(alice, 1 ether);

        // Accidental direct ETH transfer succeeds: unrestricted receive()
        vm.prank(alice);
        (bool ok,) = address(strategy).call{value: 1 ether}("");
        assertTrue(ok);
        assertEq(address(strategy).balance, 1 ether);

        // No external function consumes address(this).balance:
        // _depositInCurve forwards only the freshly-unwrapped WETH _balance,
        // so the 1 ETH is never sent to Curve and never recoverable.
        // Attempting to "rescue" via deposit/redeem fails — revert or no-op.
        vm.expectRevert();
        (bool ok2,) = address(strategy).call(abi.encodeWithSignature("sweepETH()"));
        assertFalse(ok2);
    }
}
```

Running the PoC shows the 1 ETH sits at the strategy with no code path able to move it, matching the external report's "Ether stuck in contract" class.
