### Title
Unauthenticated attacker can exhaust `savedCallbacks` quota in the capabilities gateway handler before allowlist enforcement - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` inserts every syntactically valid, freshly-signed `Message` into `h.savedCallbacks` keyed by `msg.Body.MessageId` before any allowlist/authorization check is applied, as explicitly flagged by the `// TODO: apply allowlist and rate-limiting here` comment. Any holder of a single ECDSA keypair (no DON membership, no allowlisting) can generate distinct `MessageId`s and flood this map, and `pruneCallbacks` only bounds the map size passively via a periodic timer, allowing legitimate callbacks to be evicted or delayed.

### Finding Description
The request path is: `gateway.ProcessRequest` (core/services/gateway/gateway.go:218-292) decodes the JSON-RPC request, calls `msg.Validate()` which only checks field lengths and that the signature recovers to *some* address via `ExtractSigner` (core/services/gateway/api/message.go:54-88, 124-134) — it does not check DON membership or any allowlist. The message is then routed to `h.handlers[donID].HandleLegacyUserMessage`.

Inside `HandleLegacyUserMessage` (core/services/gateway/handlers/capabilities/handler.go:341-421), the only gates before insertion into `h.savedCallbacks` are: payload decodable, non-zero timestamp, message not stale, and `msg.Body.Method == MethodWebAPITrigger`. There is no check that the signer (`msg.Body.Sender`) belongs to `h.donConfig.Members` or is otherwise authorized — the code explicitly says `// TODO: apply allowlist and rate-limiting here` (line 384). As long as these cheap syntactic checks pass, `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` is stored (lines 411-414), and the message is fanned out to all DON members via `don.SendToNode`.

`pruneCallbacks` (lines 299-339) runs only every `CallbackPruneIntervalSec` (default 30s) via a background ticker (`Start`, lines 269-285), not synchronously on insert. It removes expired entries (age > `CallbackMaxAgeSec`, default 120s) and, if still over `MaxSavedCallbacks` (default 20000), trims down to half of `maxSize` by oldest `createdAt`. Because eviction is time-ordered (oldest-first) and runs only periodically, an attacker who continuously inserts distinct `MessageId`s faster than the prune interval can keep the map above `MaxSavedCallbacks`, causing legitimate older callbacks—waiting on `callback.Wait(ctx)` in `gateway.ProcessRequest`—to be evicted before a DON node's response ever arrives, resulting in those legitimate users receiving a timeout instead of their answer.

This matches ISOLATION/quota-enforcement failure: an attacker with no DON membership, only a valid signing key, can degrade or deny service to other unrelated request submitters by exhausting a shared, unbounded (until periodic prune) resource that is gated only by weak per-message checks, not by sender identity.

### Impact Explanation
This is a denial-of-service / resource-exhaustion issue, not a direct secrets/fund/data leak. Concrete impact: legitimate users' `savedCallback` entries can be silently evicted from `h.savedCallbacks`, causing their gateway requests to time out (`RequestTimeoutError` returned in `gateway.ProcessRequest`) even though a DON node eventually responds — the response is dropped in `handleWebAPITriggerMessage` (`found` will be false) because the callback was pruned. This corresponds to a "Denial of Service" class impact for the gateway service (isolation-break/service disruption), not to a critical fund/authentication compromise. Also note `handleWebAPIOutgoingMessage`/DON side messages are separately gated by `h.nodeRateLimiter` per node address, so the corruption is confined to the legacy user-message path only.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only one ECDSA keypair to sign messages (`Message.Sign`), no DON membership, and no access to any admin/API credential — this fits the "unprivileged attacker" class exactly. The attack is trivially repeatable: generate arbitrary unique `MessageId` strings (up to 128 chars, any content not ending in a null byte), sign each with the same or different keys, and submit them via the gateway's public HTTP endpoint faster than the 30-second default prune interval. Given `defaultMaxSavedCallbacks = 20000`, sustained submission of a few hundred requests per second for under a minute is sufficient to keep the map oversized and trigger continuous LRU-style eviction of the oldest (potentially legitimate) entries.

### Recommendation
Enforce the allowlist/authorization check (validate `msg.Body.Sender` against `h.donConfig.Members` or an explicit end-user allowlist/rate limiter) before inserting into `h.savedCallbacks`, resolving the existing `// TODO: apply allowlist and rate-limiting here`. Additionally, consider per-sender quotas on `savedCallbacks` (not just a global cap) so a single signer cannot starve the shared map, and/or reject insertion synchronously when `len(h.savedCallbacks) >= MaxSavedCallbacks` rather than relying solely on the periodic ticker for enforcement.

### Proof of Concept
Go unit test plan (extending `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Construct a `handler` with a small `MaxSavedCallbacks` (e.g., 5) and a long `CallbackPruneIntervalSec` so the ticker does not interfere during the test.
2. Create a "legitimate" signed `triggerRequest` from `nodes[0].PrivateKey` with `MessageId = "legit-1"`, call `HandleLegacyUserMessage`, and confirm `handler.savedCallbacks["legit-1"]` exists.
3. Generate an unrelated, unaffiliated keypair not in `donConfig.Members` (or simply another arbitrary key) and flood `HandleLegacyUserMessage` with N > `MaxSavedCallbacks` messages each with unique `MessageId`s ("attack-1".."attack-N"), asserting `err == nil` for each (i.e., no allowlist rejects them).
4. Manually invoke `handler.pruneCallbacks()` (or wait past `CallbackPruneIntervalSec`), then assert `handler.savedCallbacks["legit-1"]` no longer exists (evicted), demonstrating that the unauthorized attacker's flood displaced the legitimate entry.
5. Expected assertion for a fixed implementation: attacker messages from a signer not in `donConfig.Members` should be rejected with an authorization error (`err != nil` / an `ErrorCode` such as `api.UnauthorizedError`) before reaching `h.savedCallbacks` insertion, and `handler.savedCallbacks["legit-1"]` should remain present regardless of attacker request volume. func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
