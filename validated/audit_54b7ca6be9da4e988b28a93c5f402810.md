### Title
Missing authorization check in `HandleLegacyUserMessage` allows any ECDSA-signed sender to forward `web_api_trigger` requests to all DON nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` in the legacy (v1) capabilities gateway handler validates message structure, payload decoding, and message freshness, but never checks whether the message's signer is allowlisted/subscribed to the workflow/DON before forwarding the request to every DON member via `don.SendToNode`. Any holder of an arbitrary ECDSA keypair can craft a validly-signed `web_api_trigger` message and have it broadcast to all nodes of a configured DON.

### Finding Description
The gateway's HTTP entry point `gateway.ProcessRequest` decodes the incoming message, calls `msg.Validate()` (structural/signature-format checks and signer recovery only, no allowlist check) [3](#0-2) , resolves the handler by `DonId`, and calls `h.HandleLegacyUserMessage(ctx, msg, callback)` [4](#0-3) .

Inside `HandleLegacyUserMessage`, the code decodes the trigger payload, checks `Timestamp` freshness, then hits the explicit `// TODO: apply allowlist and rate-limiting here` comment right before checking only that `msg.Body.Method == MethodWebAPITrigger`, with no check on `msg.Body.Sender` against any DON/workflow-level allowlist or subscription list [5](#0-4) . It then converts the message to a JSON-RPC request and iterates over `h.donConfig.Members`, calling `don.SendToNode(ctx, member.Address, req)` for every DON member [6](#0-5) .

The only "authorization" performed anywhere in this path is `Message.Validate()` recovering a valid ECDSA signature into `Body.Sender` — it does not check `Sender` against any allowlist, subscription, or capability registry entry [1](#0-0) . By contrast, the newer `capabilities/webapi/trigger` connector-side handler and the v2 workflow-metadata handler README explicitly document/implement per-trigger `AllowedSenders` allowlists [7](#0-6) , showing that allowlisting is the intended authorization control that this legacy gateway-side handler is missing.

Consequently, any attacker who generates a fresh ECDSA keypair, signs a well-formed `web_api_trigger` `api.Message` (correct field lengths, current timestamp, valid `TriggerRequestPayload`), and submits it to the gateway's HTTP user-message endpoint targeting a known/discoverable `DonId`, will have that unauthorized request forwarded to every node in that DON — with no dependency on being an allowlisted workflow owner or subscriber.

### Impact Explanation
This is an authorization-bypass on the DON-facing trigger path: an attacker with no subscription/allowlist relationship to any workflow can inject a `web_api_trigger` message that reaches all DON nodes' capability layer, potentially triggering workflow executions or capability invocations that were meant to be gated by allowlisting. This matches the "unauthorized job run" / authorization bypass bounty class since it lets an unprivileged party invoke capability triggers meant to be gated to specific senders. Actual downstream impact (e.g., whether the DON-side capability itself re-checks allowlists per `webapicap.TriggerRequestPayload`/workflow ID) depends on node-side enforcement outside this file, which was not verified in this trace.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs network access to the gateway's user-facing HTTP API and knowledge of a valid `DonId` (which is typically public/discoverable configuration), and the ability to generate an ECDSA keypair and sign a message — no credentials, subscription, or prior relationship with the DON/workflow is required. This is trivially repeatable and scriptable.

### Recommendation
Implement the allowlist/rate-limiting check explicitly called out by the TODO in `HandleLegacyUserMessage` before forwarding to `don.SendToNode`: verify `msg.Body.Sender` against a configured per-DON or per-trigger allowlist (mirroring the `AllowedSenders` model already used in `core/capabilities/webapi/trigger/trigger.go`), and apply a per-sender rate limiter (a `userRateLimiter`-style config already exists in the v2 handler) before accepting and broadcasting `web_api_trigger` requests.

### Proof of Concept
Go handler-level integration test plan in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` via `NewHandler` with a `donConfig` containing several DON members and a mock `handlers.DON` (e.g., using existing `mocks` for `handlers.DON`/`Callback`).
2. Generate a fresh `ecdsa.PrivateKey` that is not referenced anywhere in `donConfig` or any allowlist config.
3. Build a valid `api.Message` with `Method: MethodWebAPITrigger`, a valid `webapicap.TriggerRequestPayload` (current `Timestamp`), and sign it with `msg.Sign(freshKey)`.
4. Call `handler.HandleLegacyUserMessage(ctx, msg, callback)`.
5. Assert that `mockDON.SendToNode` was called once per `donConfig.Members` entry (i.e., `len(donConfig.Members)` times) with the forwarded request, and that no error/rejection response was sent via `callback.SendResponse` indicating an authorization failure — demonstrating the message is broadcast rather than rejected despite the signer holding no allowlist/subscription relationship.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
