### Title
Stale Oracle Price Data Accepted Without Absolute Freshness Check — (`crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

### Summary

The `MetaOracle` framework in `meta_oracle.move` contains two compounding logic errors that allow arbitrarily stale oracle price data to pass the freshness filter and be used in financial calculations. First, `add_simple_oracle` unconditionally overwrites `max_timestamp` with each oracle's timestamp instead of tracking the actual maximum. Second, `combine` anchors its staleness window to that corrupted `max_timestamp` rather than to the current wall-clock time. The result is that if all oracle operators stop updating simultaneously, all stale readings pass the filter and are used as if they were fresh.

### Finding Description

**Bug 1 — `add_simple_oracle` stores the last oracle's timestamp, not the maximum** [1](#0-0) 

The field `max_timestamp` is named to imply it tracks the highest timestamp seen across all added oracles. Instead, the assignment on line 41 unconditionally overwrites it with each successive oracle's timestamp. If three oracles are added with timestamps `[T=1000, T=500, T=200]`, `max_timestamp` ends up as `200`, not `1000`.

**Bug 2 — `combine` checks staleness relative to `max_timestamp`, not the current clock** [2](#0-1) 

`combine` computes `min_timestamp = max_timestamp - time_window_ms` and accepts any oracle reading whose timestamp exceeds that floor. No `Clock` object is passed; there is no comparison against the current on-chain time. If every oracle stopped publishing one hour ago, all their readings are mutually within `time_window_ms` of each other, so all pass the filter and are treated as fresh.

**Contrast with `get_latest_data` — no staleness check at all** [3](#0-2) 

`get_latest_data` returns whatever is stored with no `Clock` parameter and no age validation. The timestamp is embedded in the returned `Data<T>` struct but is never validated by the framework before the value is used in calculations.

**Financial calculation using unchecked data**

The reference consumer `simple_fx` calls `get_latest_data` and immediately multiplies the returned price by a MIST amount with no staleness guard: [4](#0-3) 

### Impact Explanation

Any protocol built on this framework that uses `MetaOracle::median` or `SimpleOracle::get_latest_data` for pricing will silently consume stale prices. Financial operations — swaps, collateral valuation, liquidation thresholds — will be computed against outdated rates. This constitutes harmful smart-contract behavior: users receive incorrect asset amounts or are incorrectly liquidated/protected based on prices that no longer reflect market reality.

### Likelihood Explanation

Oracle operators can go offline due to infrastructure failures, key rotation, or deliberate shutdown. Because the framework provides no on-chain mechanism to reject data older than a configurable wall-clock threshold, any lapse in oracle updates immediately exposes all consumers to stale-price risk. The trigger is a natural operational event, not a sophisticated attack.

### Recommendation

1. **Fix `add_simple_oracle`** — track the true maximum:
   ```move
   let ts = data::timestamp(option::borrow(&oracle_data));
   if (ts > meta_oracle.max_timestamp) {
       meta_oracle.max_timestamp = ts;
   };
   ```

2. **Add an absolute staleness check in `combine`** — require a `Clock` argument and reject any reading older than `max_staleness_ms` relative to the current time:
   ```move
   let now_ms = clock::timestamp_ms(clock);
   assert!(max_timestamp + max_staleness_ms >= now_ms, EDataTooStale);
   ```

3. **Add a `Clock`-gated variant of `get_latest_data`** that asserts the stored timestamp is within an acceptable age before returning the value.

### Proof of Concept

1. Deploy the `oracle` package and create three `SimpleOracle` objects.
2. Submit data to all three oracles at time `T=1000 ms`.
3. Wait until the current clock advances to `T=1000000 ms` (oracles are now ~16 minutes stale).
4. Call `trusted_fx(oracle1, oracle2, oracle3, amount, ctx)`:
   - `add_simple_oracle` sets `max_timestamp = 1000` (last oracle's timestamp).
   - `combine` computes `min_timestamp = 1000 - 60000` which underflows and aborts **or**, if `time_window_ms ≤ 1000`, sets `min_timestamp = 0`, accepting all readings.
   - No check against `clock::timestamp_ms` is ever performed.
   - The 16-minute-old price is used to compute `amount`, producing an incorrect `MockUSD` value. [5](#0-4) [6](#0-5)

    fun combine<T: copy + drop>(meta_oracle: MetaOracle<T>, ): (vector<T>, vector<address>) {
        let MetaOracle { mut oracle_data, threshold, time_window_ms, ticker: _, max_timestamp } = meta_oracle;
        let min_timestamp = max_timestamp - time_window_ms;
        let mut values = vector<T>[];
        let mut oracles = vector<address>[];
        while (vector::length(&oracle_data) > 0) {
            let oracle_data = vector::remove(&mut oracle_data, 0);
            if (option::is_some(&oracle_data)) {
                let oracle_data = option::destroy_some(oracle_data);
                if (data::timestamp(&oracle_data) > min_timestamp) {
                    vector::push_back(&mut values, *data::value(&oracle_data));
                    vector::push_back(&mut oracles, *data::oracle_address(&oracle_data));
                };
            };
        };
        assert!(vector::length(&values) >= threshold, EValidDataSizeLessThanThreshold);
        (values, oracles)
    }
