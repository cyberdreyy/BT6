### Title
Uncontrolled Recursion in `TrieNode`/`OrderedListWalker` MPT Traversal Allows Fault-Proof Program Stack Overflow via Crafted Preimages - (File: `crates/proof/mpt/src/node.rs`, `crates/proof/mpt/src/list_walker.rs`)

### Summary
The `base-proof-mpt` crate, used by the fault-proof program to walk the Ethereum-style Merkle Patricia Trie during L1/L2 state and receipts/transactions verification, implements trie traversal (`TrieNode::open`, `insert`, `delete`, `unblind`, and `OrderedListWalker::fetch_leaves`) with unbounded recursion and no depth limit. Unlike `golang.org/x/net/http/httpguts`'s header-recursion bug (CVE-2021-31525), where a large/nested input drove unbounded recursive parsing to a stack-overflow panic, this codebase's trie walker recurses once per RLP-decoded node returned by the preimage oracle, with no cap on recursion depth analogous to the `MAX_CBOR_NESTING_DEPTH` guard already present in `crates/proof/tee/registrar/src/cbor.rs`.

### Finding Description
`TrieNode::open`, `TrieNode::insert`, `TrieNode::delete`, and `TrieNode::unblind` in [1](#0-0)  recursively descend into child/blinded nodes fetched via the `TrieProvider::trie_node_by_hash` callback, with each `Blinded` node triggering `unblind` followed by a re-entrant call into the same function. Similarly, `OrderedListWalker::fetch_leaves` in [2](#0-1)  recurses over every `Branch`/`Extension`/`Blinded` node encountered while flattening a derivable ordered list (used for L1 receipts and transactions tries).

Both the L1 and L2 oracle-backed `TrieProvider` implementations decode the fetched preimage bytes directly into a `TrieNode` with no bound on the shape or nesting of the returned structure: [3](#0-2)  and [4](#0-3) . Neither location caps the number of recursive hops that can occur while resolving a call/derive/collect operation, nor does the `TrieProvider` trait itself expose or enforce a depth budget: [5](#0-4) .

In contrast, the codebase demonstrates awareness of this exact bug class elsewhere: the Nitro attestation CBOR parser explicitly enforces `MAX_CBOR_NESTING_DEPTH` on every recursive call (`CborItem::read_at`) precisely to prevent uncontrolled recursion from crafted attacker input: [6](#0-5) . No equivalent depth guard exists in the MPT walker, despite it consuming preimages served by a `PreimageOracleServer`/host process that is explicitly untrusted input from the FPVM client's perspective — the whole point of the preimage oracle protocol is that the client treats host-provided bytes as adversarial and must independently verify correctness (hash matching is enforced by keying on `keccak256`, but node *shape*, i.e., how many Extension/Blinded/Branch hops chain together before terminating, is entirely unconstrained by that hash check).

### Impact Explanation
The fault-proof program (FPVM client) runs inside a constrained execution environment (e.g., an SP1 zkVM guest or a Cannon-style single-threaded interpreter) as noted in `crates/proof/host/README.md` and the preimage oracle client/server split (`crates/proof/preimage`). If a party controlling preimage data supplied to the client (the host process, or — in an on-chain dispute-game context — a malicious participant who supplies the pre-image server's backing data) can craft a chain of trie nodes (e.g., alternating `Extension`/`Blinded` nodes, each individually a valid keccak-preimage of the previous node's referenced hash, forming a long chain rather than the shallow ~64-nibble depth expected for a well-formed state/account trie) that decodes successfully but forces thousands of recursive calls through `open`/`fetch_leaves`, the client can stack-overflow and crash. A crash of the fault-proof program during dispute-game execution can cause the fault-proof program to fail to produce a correct/any output, potentially halting proof generation or causing incorrect behavior in how a crash is handled by the dispute resolution logic — directly matching the "wrong provable output root" / "node halt" impact categories called out as in-scope.

### Likelihood Explanation
Exploitability depends on whether an adversarial party can supply the preimage chain shape to the client without being an honest party incidentally constrained by "real" state-trie shapes. Because trie node preimages are only checked by `keccak256` hash-matching at each single-hop fetch (not validated for overall path/depth sanity against the account's known 64-nibble key length), a party crafting the response data behind the preimage oracle server (which may be adversarial in permissionless fault-dispute settings) has latitude to build deliberately deep node chains. This requires control over what the host/preimage-server returns for a claimed root, which is a real threat model for fault-proof "malicious host" scenarios, though it is somewhat constrained by needing internally-consistent RLP/hash chains.

### Recommendation
Add an explicit recursion/depth bound to `TrieNode::open`, `insert`, `delete`, `unblind`, and `OrderedListWalker::fetch_leaves`, mirroring the `MAX_CBOR_NESTING_DEPTH` pattern already used in `crates/proof/tee/registrar/src/cbor.rs`. Thread a `depth: usize` parameter through each recursive call and return a decode/traversal error once a reasonable maximum (e.g., 64–128, matching the maximum meaningful nibble-path length plus slack for chained extension/blinded hops) is exceeded, rather than relying on unbounded call-stack growth.

### Proof of Concept
Not independently verified with a runnable exploit — verification would require: (1) confirming that a fault-proof host/preimage server context in this codebase can be made to serve preimages that are not causally derived from correct chain data (i.e., a "malicious host" or malicious dispute-game participant threat model applies to `OracleL1ChainProvider`/`OracleL2ChainProvider`), and (2) crafting a concrete RLP node chain (long sequence of `Extension`{1 nibble}/`Blinded` pairs, each a valid keccak-preimage of the prior reference) and driving it through `TrieNode::open`/`OrderedListWalker::hydrate` to observe a stack overflow. This is a conceptual analog based on the shared "uncontrolled recursion over externally supplied nested structure" root cause as the referenced CVE-2021-31525, not a confirmed working exploit.

    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
