### Title
Silent callback overwrite via duplicate `MessageId` in `HandleLegacyUserMessage` enables response hijack - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`(*handler).HandleLegacyUserMessage` stores an incoming request's callback in `h.savedCallbacks` keyed by the attacker-supplied `msg.Body.MessageId` with no existence/conflict check, unlike the v2 `httpTriggerHandler` which validates and separately locks/keys callbacks per request. A second request reusing the same `MessageId` silently overwrites the first entry, so the DON's response to the first request is delivered to the second caller's callback.

### Finding Description
`gateway.ProcessRequest` decodes the JSON-RPC request ID directly into `msg.Body.MessageId` via `ValidatedMessageFromReq` (`req.ID` → `m.Body.MessageId`) [1](#0-0)  and then, for legacy requests, calls `h.HandleLegacyUserMessage(ctx, msg, callback)` [2](#0-1) . The `MessageId`/request ID is fully attacker-controlled (only length-checked to ≤200 chars) and no gateway-level uniqueness/nonce enforcement exists across concurrent legacy requests.

Inside `(*handler).HandleLegacyUserMessage`, after validating payload structure, timestamp freshness, and method, the code unconditionally writes:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [3](#0-2) 

There is no `if _, found := h.savedCallbacks[msg.Body.MessageId]; found { return ErrConflict }` guard here, whereas the newer `HTTPTriggerHandler`/`setupCallback` path enforces uniqueness before registering a callback (guarded by `callbacksMu` and an explicit conflict check referenced by `ErrConflict` in `api/constants.go`, exercised in `http_trigger_handler_test.go`). Because of the missing check, when two `HandleLegacyUserMessage` calls arrive with an identical `MessageId` (from different senders/sessions), the second call's write clobbers the first `savedCallback` in the map before the first node response arrives.

The consumer of this map, `handleWebAPITriggerMessage`, looks up and deletes by `msg.Body.MessageId` and forwards the *first* node response received to whichever callback is currently stored:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
return savedCb.SendResponse(...)
``` [4](#0-3) 

Thus, if attacker A submits `MessageId="dup"` and attacker/victim B submits a second `HandleLegacyUserMessage` with the same `MessageId="dup"` before A's DON response returns, B's callback replaces A's. When the DON responds to A's original trigger, the response is delivered to B's HTTP/WS connection instead of A's — a cross-session response hijack. Neither `msg.Validate()` (signature/schema check) nor the payload/timestamp/method checks in `HandleLegacyUserMessage` prevent this, since they validate the message contents but never check for `MessageId` collisions against the in-flight `savedCallbacks` map.

### Impact Explanation
This breaks isolation between concurrent legacy-protocol gateway users: an unauthenticated/attacker-controlled client can cause another user's trigger response (potentially containing user-specific webhook/API-response data) to be silently redirected to the attacker's own connection, or vice versa cause a legitimate user to receive a stale/attacker's response. This matches the "cross-user response confusion" impact class called out in the audit rules.

### Likelihood Explanation
Exploitability requires only an unauthenticated gateway client capable of producing a validly-signed `api.Message` (a normal capability-node/workflow client credential, not admin/operator access) and knowledge/predictability or collision of another in-flight `MessageId`. Since `MessageId` originates from the client-supplied JSON-RPC `id` field and is not centrally deduplicated or randomized by the gateway, an attacker who can guess or race a target's `MessageId` (or who controls both request legs, e.g., replaying a leaked/observed ID) can reliably trigger the collision. The race window is bounded by DON round-trip latency, which is generally large enough (seconds) to make repeated attempts feasible.

### Recommendation
Add the same existence/conflict check used by `httpTriggerHandler.setupCallback` before inserting into `h.savedCallbacks` in `HandleLegacyUserMessage`:
```go
h.mu.Lock()
if _, found := h.savedCallbacks[msg.Body.MessageId]; found {
    h.mu.Unlock()
    return callback.SendResponse(handlers.UserCallbackPayload{
        RawResponse: codec.EncodeNewErrorResponse(msg.Body.MessageId, api.ToJSONRPCErrorCode(api.HandlerError), "duplicate message id", nil),
        ErrorCode:   api.HandlerError,
    })
}
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}
h.mu.Unlock()
```

### Proof of Concept
Go test plan (table/unit test in `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Build handler via existing `setupHandler(t)` helper.
2. Construct `msg1 := triggerRequest(t, key1, ..., messageID="dup")` and `msg2 := triggerRequest(t, key2, ..., messageID="dup")` (reuse existing `triggerRequest` helper, override `MessageId`).
3. Create two distinct callbacks `cb1 := hc.NewCallback()`, `cb2 := hc.NewCallback()`.
4. Call `err1 := handler.HandleLegacyUserMessage(ctx, msg1, cb1)`; assert `err1 == nil` and `handler.savedCallbacks["dup"].Callback == cb1`.
5. Call `err2 := handler.HandleLegacyUserMessage(ctx, msg2, cb2)`; assert current (vulnerable) behavior returns `nil` and `handler.savedCallbacks["dup"].Callback == cb2` (clobbered), demonstrating no `ErrConflict`.
6. Simulate a node response via `handler.HandleNodeMessage(ctx, resp, node.Address)` for `MessageId="dup"`; assert `cb2.Wait(ctx)` receives the response while `cb1.Wait(ctx)` times out/never resolves — proving the response intended implicitly for the first requester is hijacked by the second.
7. After applying the recommended fix, assert `err2` returns a `HandlerError`/conflict response and `cb1` still resolves correctly on node response.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
```
