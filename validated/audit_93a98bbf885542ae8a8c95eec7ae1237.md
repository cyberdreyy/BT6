### Title
`switch_operator` leaves a stale `old_operator` share in the `distribution_pool`, causing pending commission to bypass the operator's configured beneficiary and pay the wrong address - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`switch_operator` re-keys a `StakingContract` from `old_operator` to `new_operator` after calling `request_commission_internal`, which adds a new distribution share keyed by the *old* operator's address for commission that isn't yet withdrawable. When `distribute()` (or `distribute_internal`) is later invoked, it only redirects a commission payout to `beneficiary_for_operator(operator)` if `recipient == operator` — but by then `operator` is `new_operator` while the stored `recipient` is still `old_operator`, so the redirect check silently fails and the funds are deposited directly to the old operator's raw address instead of their configured beneficiary.

### Finding Description
In `switch_operator` [1](#0-0) , the sequence is:
1. `distribute_internal(staker_address, old_operator, &mut staking_contract)` flushes any already-inactive stake using `old_operator` as the operator context (beneficiary redirection works correctly here).
2. `request_commission_internal(old_operator, &mut staking_contract)` computes commission on stake accumulated up to the switch and calls `add_distribution(operator, staking_contract, operator, commission_amount)` with `operator = old_operator`, creating a new pending share in `staking_contract.distribution_pool` keyed to `old_operator`'s address [2](#0-1) .
3. The `StakingContract` (with that pending share still keyed to `old_operator`) is then removed from the map and re-inserted under `new_operator`.

Later, when the lockup expires and anyone calls `distribute()`/`distribute_internal(staker, new_operator, staking_contract)` [3](#0-2) , the per-recipient redirect logic is:
```
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
```
Here `operator` is now `new_operator`, but the stored `recipient` for that pending commission share is still `old_operator`. The equality check fails, so the code skips the beneficiary lookup entirely and pays the commission directly to `old_operator`'s account address, even if `old_operator` had previously called `set_beneficiary_for_operator` to route commissions to a separate beneficiary address [4](#0-3) .

This is the same bug class as the external report: a state-clearing/reset step (`_resetAmendmentParams`) is skipped when transitioning to a new governance/role context, leaving stale pending state that corrupts a later operation. Here, the stale `distribution_pool` recipient identity (bound to the old role) is never reconciled when the operator role changes, so the beneficiary-redirection invariant silently breaks for exactly the commission window that straddles the `switch_operator` call.

### Impact Explanation
This causes operator commission — which is supposed to be paid to the beneficiary configured via `set_beneficiary_for_operator` — to instead be credited to the old operator's raw address, a wrong-account credit within a legitimate accounting flow. This matches the required impact class of "Operator commission, beneficiary payout ... corruption that credits the wrong account." Any operator who has set up a beneficiary (e.g., a custodial/payout address different from their operating key) will have commission silently redirected away from that beneficiary for any staking_contract that goes through a `switch_operator` before the pending commission is distributed.

### Likelihood Explanation
The trigger requires only the ordinary/unprivileged staker-driven flow: (1) operator earns rewards, (2) operator has previously called `set_beneficiary_for_operator`, (3) staker calls `switch_operator`/`switch_operator_with_same_commission` (a normal, documented staker operation, not requiring any special privilege beyond owning the staking contract), and (4) anyone later calls `distribute()` once the lockup expires. No malicious intent or elevated privilege is needed — it happens as a side effect of a routine operator switch, making it moderately likely to occur in practice on any staking_contract/vesting-based pool that uses beneficiaries.

### Recommendation
When re-keying the `StakingContract` from `old_operator` to `new_operator` in `switch_operator`, either:
- fully settle (distribute) any pending, not-yet-withdrawable commission share for `old_operator` before performing the operator swap so no stale recipient survives the re-keying, or
- have `distribute_internal` compare `recipient` against the beneficiary mapping directly (i.e., check `beneficiary_for_operator` existence for `recipient` itself) rather than requiring `recipient == operator`, so the redirect is correct regardless of which operator is currently associated with the pool.

### Proof of Concept
1. Staker creates a staking contract with `operator_A`; `operator_A` calls `set_beneficiary_for_operator(operator_A, beneficiary_A)`.
2. Stake pool earns rewards; commission accrues.
3. Staker calls `switch_operator(staker, operator_A, operator_B, new_commission_percentage)`. Internally this calls `request_commission_internal(operator_A, ...)`, adding a distribution share keyed to `operator_A` for the just-accrued commission, then re-keys the contract to `operator_B`.
4. Fast forward past the lockup period; call `distribute(staker_address, operator_B)`.
5. Inside `distribute_internal`, `recipient == operator_A`, but `operator == operator_B`, so the `beneficiary_for_operator` redirect is skipped; the commission is deposited into `operator_A`'s address instead of `beneficiary_A`, contradicting the beneficiary configuration set up in step 1.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
