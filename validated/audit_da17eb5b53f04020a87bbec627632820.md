### Title
Missing allowlist/authorization check allows any signer to broadcast `web_api_trigger` messages to all DON nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` only validates message structure, signature well-formedness, and message freshness before forwarding a `web_api_trigger` request to every DON member via `don.SendToNode` in the loop over `h.donConfig.Members`. There is no check that the signer (`msg.Body.Sender`) is authorized for the workflow/DON being targeted — the code explicitly notes this with `// TODO: apply allowlist and rate-limiting here` [1](#0-0) .

### Finding Description
The request enters via `gateway.ProcessRequest`, which calls `msg.Validate()` for legacy requests [2](#0-1) . `Message.Validate()` only checks field lengths/formats and extracts a signer address from the ECDSA signature via `ExtractSigner` — it verifies that *some* valid signature exists over the payload, but performs no authorization/allowlist lookup on the resulting signer address [3](#0-2) . Because `Message.Sign` can be invoked with any freshly generated ECDSA key (as shown in the test helper `newSignedLegacyRequest`, which calls `crypto.GenerateKey()`) [4](#0-3) , an attacker with no credentials can self-sign a well-formed message.

`gateway.ProcessRequest` then dispatches to `h.HandleLegacyUserMessage(ctx, msg, callback)` [5](#0-4) . Inside `HandleLegacyUserMessage`, the checks performed are: payload decodability, `payload.Timestamp != 0`, and message staleness based on `h.config.MaxAllowedMessageAgeSec` [6](#0-5) . Immediately after, the comment `// TODO: apply allowlist and rate-limiting here` precedes only a method-name check (`msg.Body.Method != MethodWebAPITrigger`), with no allowlist, subscription, or job-authorization check of any kind [1](#0-0) . The message is then converted to a JSON-RPC request and, for every DON member in `h.donConfig.Members`, sent via `don.SendToNode(ctx, member.Address, req)` [7](#0-6) .

This confirms the attack: a caller with mere network access to the gateway HTTP/WS endpoint, holding no allowlist entry, credential, or DON-specific authorization, can self-generate a signing key, craft a `web_api_trigger` message with a valid-looking `Timestamp`, and have it broadcast to every DON node — triggering downstream workflow processing that is normally supposed to be gated by workflow/subscription authorization.

### Impact Explanation
This matches the Chainlink bounty "authorization bypass" / "unauthorized job run" impact class: an unauthenticated, unauthorized actor can force every node in a DON to process an arbitrary trigger message. Concrete impacts include resource exhaustion of DON nodes (each node processes the trigger, potentially invoking associated workflow capability handlers), and — depending on downstream `web_api_trigger`/workflow-execution logic on the node side — potential unauthorized workflow invocation. The severity is amplified since the fan-out targets *all* DON members with a single unauthenticated request.

### Likelihood Explanation
Preconditions are minimal: only network reachability to the gateway's HTTP/WS endpoint is required. No credential, allowlist membership, or prior relationship with the DON is needed — the attacker only needs to generate an ECDSA keypair locally and sign their own crafted message, which `Message.Validate()` will accept as long as it is well-formed and not stale. This is trivially repeatable and scriptable.

### Recommendation
Implement the allowlist/authorization check called out by the TODO before forwarding to `don.SendToNode`: verify that `msg.Body.Sender` (or an embedded workflow/owner identity within `payload`) is authorized for the specific workflow/subscription and DON being targeted, and add per-sender rate limiting, before iterating over `h.donConfig.Members`.

### Proof of Concept
1. In `core/services/gateway/handlers/capabilities/handler_test.go`, construct a `handler` via the existing test helper (as used in `TestHandlerReceiveHTTPMessageFromClient`), without configuring any allowlist (there is none in `HandlerConfig`).
2. Generate an unrelated, never-registered ECDSA key with `crypto.GenerateKey()` (not from `nodes` fixture) and sign a `web_api_trigger` message with a valid non-zero, fresh `Timestamp`.
3. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)`.
4. Assert that `don.SendToNode` (via the mocked `handlers.DON`) is invoked once per entry in `h.donConfig.Members`, and that `cb.Wait` does not return an authorization-related error — confirming the message is dispatched to the entire DON despite the signer having no allowlist relationship.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

// newSignedLegacyRequest creates a signed legacy request message for testing purposes.
// Legacy requests embed
func newSignedLegacyRequest(t *testing.T, messageID string, method string, donID string, payload []byte) []byte {
	msg := &api.Message{
		Body: api.MessageBody{
			MessageId: messageID,
			Method:    method,
			DonId:     donID,
			Payload:   payload,
		},
	}
	privateKey, err := crypto.GenerateKey()
	require.NoError(t, err)
	require.NoError(t, msg.Sign(privateKey))
	codec := api.JsonRPCCodec{}
	rawRequest, err := codec.EncodeLegacyRequest(msg)
	require.NoError(t, err)
	return rawRequest
}
