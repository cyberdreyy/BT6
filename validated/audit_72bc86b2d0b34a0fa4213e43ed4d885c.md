### Title
Nil-pointer panic on malformed JSON-RPC request without `params` field crashes Gateway - (File: core/services/gateway/api/jsonrpccodec.go)

### Summary
The Gateway's JSON-RPC request decoder `DecodeJSONRequest` dereferences a pointer field (`request.Params`) without checking it for `nil`, exactly analogous to the op-geth `dec.Gas` nil-pointer bug. A JSON-RPC request from an unauthenticated/unprivileged client that omits the `"params"` field reaches this code path and triggers a runtime nil-pointer dereference panic.

### Finding Description
`JsonRPCCodec.DecodeJSONRequest` unconditionally dereferences `*request.Params`: [1](#0-0) 

```go
func (*JsonRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)   // panics if request.Params == nil
	...
}
```

`request.Params` is of type `*json.RawMessage` (confirmed by usages such as [2](#0-1) , which explicitly set `Params: nil`). Elsewhere in the same package, the legacy path `ValidatedMessageFromReq` explicitly guards against this exact case: [3](#0-2) 

```go
if req.Params == nil {
    return nil, errors.New("missing params attribute")
}
```

`DecodeJSONRequest`, however, omits this check. The entry point for untrusted client input is `gateway.ProcessRequest`, which is invoked directly from the internet-facing HTTP handler for user requests: [4](#0-3) 

```go
func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	...
```

`jsonrpc2.DecodeRequest` only validates that the raw bytes parse as JSON-RPC; it does not require `params` to be present. A syntactically valid JSON-RPC request such as `{"jsonrpc":"2.0","id":"1","method":"anything"}` (no `params` key) will produce a `jsonrpc2.Request` with `Params == nil`, which is then passed straight into `g.codec.DecodeJSONRequest`, causing the nil dereference at line 26.

### Impact Explanation
This is a denial-of-service issue: any unauthenticated or unprivileged HTTP client that can reach the Gateway's user-facing endpoint can send a single malformed request lacking `params` and cause a panic in the request-handling path. Depending on whether the calling HTTP handler recovers from panics (this could not be conclusively verified from indexed code — the panic-recovery/middleware wiring around `ProcessRequest`'s HTTP entry point was not found in the indexed portion of `core/services/gateway/network/httpserver.go`), this could crash the goroutine handling the request or, if unrecovered, take down the entire Gateway process, disrupting all DON node communication routed through it.

### Likelihood Explanation
High likelihood of triggering: it requires no authentication bypass, no cryptographic material, and no special permissions — just a single crafted HTTP POST to the Gateway's public endpoint with a JSON-RPC body missing the `params` field. The bug is deterministic and trivially reproducible given the code, closely mirroring the confirmed op-geth issue.

### Recommendation
Add an explicit nil check in `DecodeJSONRequest`, mirroring the guard already present in `ValidatedMessageFromReq`:
```go
func (*JsonRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	if request.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	...
}
```
Additionally, verify (and add if missing) a panic-recovery wrapper around the Gateway's HTTP request-handling path so that any future similar decoding bugs degrade to an error response instead of crashing the process.

### Proof of Concept
Send a JSON-RPC request to the Gateway's user-facing HTTP endpoint without a `params` field:
```json
{"jsonrpc":"2.0","id":"1","method":"anything"}
```
This is accepted by `jsonrpc2.DecodeRequest` (which does not require `params`), producing a `jsonrpc2.Request[json.RawMessage]` with `Params == nil`. `gateway.ProcessRequest` then calls `g.codec.DecodeJSONRequest(jsonRequest)`, which executes `json.Unmarshal(*request.Params, &msg)` — dereferencing the nil `*json.RawMessage` pointer and panicking, as demonstrated by the equivalent op-geth `TestDecodeJSON` PoC pattern applied to this code path.
