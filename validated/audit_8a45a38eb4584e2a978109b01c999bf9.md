### Title
Wrong `CriticalError` (instead of temporary/EOF) emitted when `l1_blocks` is empty in `BatchQueue::derive_next_batch`, causing derivation actor to halt - (File: `crates/consensus/derive/src/stages/batch/batch_queue.rs`)

### Summary
`BatchQueue::derive_next_batch` treats an empty `l1_blocks` buffer as an unrecoverable `PipelineErrorKind::Critical` error rather than a retryable/temporary condition. This is the same misclassification described in the referenced op-node audit finding, but in this Rust port the consequence is worse: a `Critical` error causes the whole `DerivationActor` task to terminate instead of just being logged.

### Finding Description
`derive_next_batch` returns a critical error whenever `l1_blocks` is empty: [1](#0-0) 

This is documented as "no batch can be derived yet" (an EOF-class condition), yet it's implemented as `PipelineError::MissingOrigin.crit()`, i.e. `PipelineErrorKind::Critical`, the most severe category defined for the pipeline: [2](#0-1) 

The calling stage `next_batch` only clears `l1_blocks` (via the `origin_behind` branch) or advances it (partial `drain`) — it never guarantees `l1_blocks` is repopulated before calling `derive_next_batch` on the very next invocation if `self.origin == self.prev.origin()` already (the push-into-`l1_blocks` branch is gated on `self.origin != self.prev.origin()`), and `derive_next_batch` is still reached whenever `origin_behind` evaluates `false` on that call: [3](#0-2) 

This exact scenario is covered (and asserted as intended today) by the unit test `test_derive_next_batch_missing_origin`, which confirms `derive_next_batch` yields `PipelineError::MissingOrigin.crit()` for an empty `l1_blocks` state rather than an `Eof`/temporary result: [4](#0-3) 

Unlike op-node's driver (which merely logs `Derivation process critical error` and returns from an event-loop iteration), this fork's `DerivationActor::produce_next_attributes` propagates the `Critical` variant as a hard `Err`, which bubbles out of `attempt_derivation`, out of `handle_derivation_actor_request`, and is returned (via `?`) from the `DerivationActor::start` loop — terminating the actor's task entirely: [5](#0-4) [6](#0-5) 

### Impact Explanation
Where op-node's original bug only "reduces performance" (an ignored critical-error log line), this codebase's stricter propagation converts the same misclassified error into an actual node halt: the `DerivationActor::start` async task returns `Err(...)` and exits, stopping all further L2 derivation for the node until it is manually restarted. This fits the "node halt" impact category.

### Likelihood Explanation
The condition is reachable during ordinary derivation progress (epoch advancement / origin bookkeeping in `next_batch`) without any attacker action needed — it is an internal pipeline-state edge case, analogous to the "expected situation" called out in the original report. Because `l1_blocks` bookkeeping is driven by attacker-influenceable L1 batch/data timing (batches can be posted to the batch inbox by any L1 sender), the empty/re-cleared window can plausibly be hit during normal or adversarially-timed batch submission sequences.

### Recommendation
Change `derive_next_batch` to return a temporary/EOF-class error (e.g. `PipelineError::Eof.temp()` or `NotEnoughData.temp()`) when `l1_blocks` is empty, matching the `BatchValidity::Undecided` handling elsewhere in the same function, instead of `PipelineError::MissingOrigin.crit()`:

```rust
if self.l1_blocks.is_empty() {
    return Err(PipelineError::Eof.temp());
}
```

### Proof of Concept
1. Drive the `BatchQueue` through normal operation until an origin advance sets `self.origin = self.prev.origin()` while `l1_blocks` is still empty from a prior `origin_behind` clear (see `crates/consensus/derive/src/stages/batch/batch_queue.rs:355-373`).
2. On the following `next_batch` call, if `origin_behind` now evaluates to `false` (prev origin caught up) while `self.origin == self.prev.origin()` unchanged, the `l1_blocks` push branch is skipped and `l1_blocks` remains empty.
3. `derive_next_batch` is invoked and returns `PipelineError::MissingOrigin.crit()` (as reproduced by `test_derive_next_batch_missing_origin`).
4. This `Critical` value propagates through `DerivationActor::produce_next_attributes` → `attempt_derivation` → `handle_derivation_actor_request` → `start`, causing the derivation actor task to return `Err` and exit, halting derivation for the node.
