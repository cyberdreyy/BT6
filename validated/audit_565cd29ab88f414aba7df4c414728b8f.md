### Title
`GET /v2/external_initiators` exposes `OutgoingToken` to any authenticated user regardless of role, allowing impersonation of the node's outbound calls to another initiator's webhook - ([File: core/web/external_initiators_controller.go])

### Summary
The `ExternalInitiatorsController.Index` handler (mounted at `authv2.GET("/external_initiators", paginatedRequest(eia.Index))`) serializes each stored `ExternalInitiator` via `presenters.NewExternalInitiatorResource`, which explicitly includes the `OutgoingToken` field in the JSON response. Unlike other external-initiator routes, this route carries no role gate (`RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole`), so any authenticated user — including the lowest "view" role or an API token with restricted privileges — can list all external initiators and harvest every registered initiator's `OutgoingToken`.

### Finding Description
`core/web/router.go` registers the route without a role wrapper: [1](#0-0) [2](#0-1) 
compared to the sibling `Create`/`Destroy` routes which are wrapped with `auth.RequiresEditRole`: [3](#0-2) 

The handler builds the resource list directly from the DB rows without any redaction: [4](#0-3) 

The presenter used for this list intentionally serializes `OutgoingToken`: [5](#0-4) 

While `HashedSecret`, `Salt`, and `OutgoingSecret` are correctly excluded from `ExternalInitiatorResource` (only present in the one-time `ExternalInitiatorAuthentication` response returned at creation time), `OutgoingToken` is not, and it is returned to every caller of the list endpoint, not just the initiator's owner/creator. There is no ownership concept for external initiators (they are node-global objects), so any authenticated principal reaching this route sees every initiator's `OutgoingToken`. This is confirmed by the existing test, which asserts the field is present in the response: [6](#0-5) 

The attacker path: an unprivileged user with only a "view"-role session or API token (or any authenticated token, since the route has no role check at all) sends `GET /v2/external_initiators`, passes `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)` in `core/web/router.go` (no `RequiresEditRole`/`RequiresRunRole` gate is applied), and reaches `ExternalInitiatorsController.Index`, which returns `OutgoingToken` for every registered initiator.

### Impact Explanation
`OutgoingToken` (together with `OutgoingSecret`, which is not leaked here) is the credential pair the node is expected to present when calling out to an external initiator's own webhook/service. Leaking `OutgoingToken` to any authenticated node user (even the lowest "view" role, which is supposed to be read-only/non-privileged) allows that low-privilege user to partially reconstruct or replay the node's outbound authentication toward the external initiator's endpoint, and more broadly it is an authorization-bypass/secret-disclosure issue: a field intended to be node-sensitive is returned to unauthorized principals due to a missing role check on the list route, matching the "secrets never leave" / credential exposure impact class. Note: I could not confirm from the available index that `OutgoingToken` is actually consumed anywhere in `core/services/**` to make outbound HTTP calls (no matches found), so its live operational sensitivity/usage could not be fully verified within the indexed code — this should be double-checked in a full checkout.

### Likelihood Explanation
Requires only a valid, currently unprivileged session or API token (view role or a restricted token) — no special setup, no server misconfiguration, and no code path outside the standard router registration in `core/web/router.go`. It is fully repeatable: any authenticated GET request to `/v2/external_initiators` returns the field for every entry, and the existing test suite already exercises and asserts on the field's presence in the response, confirming the behavior is deterministic and not incidental.

### Recommendation
Add `auth.RequiresEditRole` (or a comparable minimum role) to the `GET /v2/external_initiators` route in `core/web/router.go`, consistent with `Create`/`Destroy`, and/or drop `OutgoingToken` from `presenters.ExternalInitiatorResource` for the list endpoint, only exposing it (along with `OutgoingSecret`) in the one-time creation response (`ExternalInitiatorAuthentication`), never in subsequent list/read responses.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/external_initiators_controller_test.go`):
1. Start `cltest.NewApplicationWithConfig` with `ExternalInitiatorsEnabled = true`.
2. Create a user/API token with `sessions.UserRoleView` (lowest privilege) instead of the default admin client.
3. Insert an external initiator via `cltest.MustInsertExternalInitiatorWithOpts` with a known `OutgoingToken` value.
4. Using the view-role client, call `GET /v2/external_initiators`.
5. Assert response status is `200 OK` (not `401 Unauthorized`), and parse the JSON body into `[]presenters.ExternalInitiatorResource`.
6. Assert `externalInitiators[0].OutgoingToken` equals the known `OutgoingToken` value — demonstrating a view-role principal can read another initiator's outgoing credential.
7. (Negative control) Repeat step 4 against `POST /v2/external_initiators` and `DELETE /v2/external_initiators/:Name` with the same view-role client and assert `401 Unauthorized`, showing the inconsistency: those routes are gated by `RequiresEditRole` while `Index` is not.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
