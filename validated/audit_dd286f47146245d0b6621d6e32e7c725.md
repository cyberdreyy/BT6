### Title
Missing fee-validation in `createDstEscrow` causes underflow revert in `EscrowDst._withdraw`, permanently disabling withdrawal for the deployed escrow - (File: `contracts/BaseEscrowFactory.sol`, `contracts/EscrowDst.sol`)

### Summary
`BaseEscrowFactory.createDstEscrow` accepts caller-supplied `Immutables.parameters` (which encode `protocolFeeAmount` and `integratorFeeAmount`) without validating that the sum of fees is less than `immutables.amount`. `EscrowDst._withdraw` later performs an unchecked subtraction `immutables.amount - integratorFeeAmount - protocolFeeAmount` that reverts on underflow, making the deployed escrow's withdrawal path permanently unusable — the exact same "unvalidated subtraction leading to reverting critical function" root cause described in the analog report (`Treasury._loadSwapState` underflow on `xNav`).

### Finding Description
In the source-chain flow, `BaseEscrowFactory._postInteraction` explicitly guards against invalid fee configuration: [1](#0-0) 

This check (`integratorFeeAmount + protocolFeeAmount >= takingAmount` → revert) ensures the fee amounts baked into the src-side immutables can never exceed the escrowed amount.

However, `createDstEscrow`, which is a public, unprivileged entry point, builds/accepts the destination `Immutables` (including `parameters` containing `protocolFeeAmount`/`integratorFeeAmount`) directly from the caller and performs no equivalent check: [2](#0-1) 

Only `msg.value` vs. `nativeAmount` and the ERC20 transfer amount are validated — the relationship between `dstImmutables.parameters` (fee amounts) and `dstImmutables.amount` is never checked.

The deployed `EscrowDst` clone later computes the maker payout as: [3](#0-2) 

If `integratorFeeAmount + protocolFeeAmount > immutables.amount` (fields taken verbatim from the immutables used to compute the CREATE2 address and stored in the clone), line `immutables.amount - integratorFeeAmount - protocolFeeAmount` underflows and reverts for every call to `withdraw`/`publicWithdraw`, since Solidity ^0.8 reverts on unchecked underflow. Because `onlyValidImmutables` requires the exact same immutables hash used at deployment, there is no way to "fix" the parameters after the fact — the escrow's withdrawal path is permanently broken for that specific instance.

### Impact Explanation
This matches the Medium bucket: *"smart contract unable to operate because required token/native balances can be broken by an unprivileged actor."* Any unprivileged caller of `createDstEscrow` (not restricted to a privileged resolver) can craft `Immutables.parameters` with `protocolFeeAmount`/`integratorFeeAmount` summing to more than `amount`, permanently disabling `withdraw`/`publicWithdraw` for that escrow instance. Note `cancel()` does not perform this subtraction, so funds are not permanently frozen (they can eventually be recovered via `cancel()` after the `DstCancellation` timelock), which caps this at temporary freezing/broken-operation rather than a Critical/High fund-theft impact.

### Likelihood Explanation
Medium likelihood: `createDstEscrow` has no caller restriction and no fee-sanity check, so triggering the underflow requires only crafting `parameters` with `protocolFeeAmount + integratorFeeAmount > amount` and funding the escrow accordingly — a straightforward, unprivileged, one-transaction action, mirroring exactly the missing bound-check pattern in the analog report.

### Recommendation
Add an explicit check in `createDstEscrow` (or in `EscrowDst._withdraw`) mirroring the `_postInteraction` guard:
```solidity
if (dstImmutables.protocolFeeAmount() + dstImmutables.integratorFeeAmount() >= dstImmutables.amount) revert InvalidFeeAmounts();
```
so a destination escrow can never be created with fee amounts that exceed the escrowed amount, preventing the guaranteed-revert underflow in `_withdraw`.

### Proof of Concept
1. Attacker (or careless resolver) calls `createDstEscrow` with `dstImmutables.amount = 100`, `parameters` encoding `protocolFeeAmount = 60`, `integratorFeeAmount = 60` (sum = 120 > 100), funding the escrow with the required `msg.value`/token transfer.
2. `_deployEscrow` succeeds; the clone is deployed at the CREATE2 address derived from these immutables.
3. Once the withdrawal timelock stage is reached, taker calls `withdraw(secret, immutables)` (or any public participant calls `publicWithdraw`) → `_withdraw` computes `immutables.amount - integratorFeeAmount - protocolFeeAmount` → `100 - 60 - 60` underflows → transaction reverts for all callers, for the lifetime of the escrow's withdrawal window.
4. Funds can only be retrieved by the taker via `cancel()` after the `DstCancellation` timelock elapses, i.e., the maker's expected destination-side payout is frozen/broken for the entire withdrawal window. [3](#0-2) [2](#0-1)

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
```
