### Title
Unauthenticated `/health` endpoint leaks raw internal error strings (potentially including DSNs/hostnames) via `checks[].Output` - ([File: core/web/health_controller.go])

### Finding Description
`HealthController.Health` calls `checker.IsHealthy()` and for every failing check sets `output = err.Error()` verbatim, with no redaction, allowlisting, or sanitization of the error message before it is serialized into the JSON/HTML/plaintext response body: [1](#0-0) 

The `Checker` interface (`core/services/health.go`) simply aggregates `map[string]error` from every registered `services.HealthReporter` — DB, RPC clients (`HeadTracker`, `LogPoller`, chain readers), gateway connectors, etc. Any of these can return an `error` object whose `.Error()` string embeds internal details (e.g. a `pkg/errors`-wrapped DB dial error containing a DSN, or an RPC client error containing an internal hostname/URL) — the `Checker`/`HealthReport()` contract only carries `error`, not a sanitized string, so nothing downstream filters it: [2](#0-1) [3](#0-2) 

Critically, the code comment on the sibling `PublicReadyz` handler confirms the threat model: it was explicitly built to "never return per-check details regardless of query parameters, to avoid leaking internal service state on **publicly reachable endpoints**" — implying `/health` and `/readyz` (full) are reachable without authentication, unlike this hardened sibling: [4](#0-3) . The `/health`, `/readyz`, and `/query` routes are registered in the same `api` group in `NewRouter`, and the authentication provider's route extension (`app.AuthenticationProvider().ExtendRouter(api)`) is applied afterward/separately, while `healthRoutes(app, api)` is registered with no explicit auth middleware wrapper visible at the call site: [5](#0-4) . This matches the intended design of `/health` as a load-balancer/monitoring probe endpoint that does not require session/API-key authentication (in contrast to `v2Routes`, which are consumed by authenticated operators).

`Readyz`'s "full" output path has the identical unsanitized pattern: [6](#0-5) 

### Impact Explanation
An unauthenticated caller who triggers or observes a failing health check (DB connectivity blip, RPC/chain client failure, gateway disconnect, etc.) receives the raw Go `error.Error()` string in the `Output` field of the JSON/HTML/plaintext response. Depending on the underlying library, these error strings can include connection strings/DSNs, internal hostnames/IPs, or file paths, constituting an internal topology/credential-fragment disclosure to an unauthenticated network caller. This maps to Chainlink's "Information disclosure" bounty class (low-severity infrastructure/topology leakage) rather than key/fund compromise, since no private keys, session tokens, or job secrets are stored inside `Checker.IsHealthy()` error values in the code as written — but it does hand an attacker useful reconnaissance for further attacks (e.g., probing the disclosed DB host/port or internal service names).

### Likelihood Explanation
No credentials or preconditions are required beyond network reachability of the node's `/health` endpoint, which is explicitly designed to be publicly reachable (per the `PublicReadyz` comment). The only trigger condition is that some registered health check is currently failing — a state that can occur transiently in production (DB pool exhaustion, RPC endpoint outage) or could be induced by an attacker capable of causing resource exhaustion/connectivity issues on the node. This is fully repeatable and requires only a single `GET /health` request per observation.

### Recommendation
- Do not pass raw `error.Error()` strings from `Checker.IsHealthy()`/`IsReady()` into the public `Output` field. Introduce a sanitization/redaction layer (e.g., a fixed, generic message per check name such as `"check failed"`, or an explicit allowlist of safe error types) before building `presenters.Check`.
- Alternatively, gate the detailed `Output` field behind authentication (as already done conceptually by the difference between `PublicReadyz` and `Readyz`), and keep the unauthenticated `/health`/`/readyz` responses limited to pass/fail status codes only, matching the `PublicReadyz` pattern.
- Audit `services.HealthReporter` implementations (DB, RPC/chain clients, gateway connector) to ensure any error wrapping does not include secrets/DSNs even when consumed by authenticated paths, as defense in depth.

### Proof of Concept
Go handler-level integration test (extending the existing `TestHealthController_Health_status` pattern in `core/web/health_controller_test.go`):
1. Construct `mocks.Checker` and set `healthChecker.On("IsHealthy").Return(false, map[string]error{"DB": errors.New("dial tcp: connect to postgres://cluser:s3cr3t@10.0.0.5:5432/chainlink: connection refused")})`.
2. Wire `app.HealthChecker = healthChecker`, start the app, issue `client.Get("/health")`.
3. Assert `resp.StatusCode == http.StatusMultiStatus`.
4. Parse the JSON body's `checks[].attributes.output` (or `Output` field per `presenters.Check`) and assert it equals the mocked error string verbatim, i.e. contains the DSN substring `postgres://cluser:s3cr3t@10.0.0.5:5432` — proving no sanitization occurs.
5. Repeat the request without any `Authorization`/session cookie header to confirm the endpoint requires no authentication.

```go
// Checker provides a service which can be probed for system health.
type Checker interface {
	// Register a service for health checks.
	Register(service services.HealthReporter) error
	// Unregister a service.
	Unregister(name string) error
	// IsReady returns the current readiness of the system.
	// A system is considered ready if all checks are passing (no errors)
	IsReady() (ready bool, errors map[string]error)
	// IsHealthy returns the current health of the system.
	// A system is considered healthy if all checks are passing (no errors)
	IsHealthy() (healthy bool, errors map[string]error)

	Start() error
	Close() error
}
```
