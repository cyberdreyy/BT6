`drift_init_user` skips `validate_bank_state`, letting an unprivileged caller init a Drift user/deposit into an admin-Paused/ReduceOnly bank - ([File: programs/marginfi/src/instructions/drift/init_user.rs])

### Summary
`drift_init_user` reads `bank.config` (via `is_drift_asset_tag` and market/pool data) and executes `cpi_init_user_stats`, `cpi_init_user`, and `cpi_drift_deposit` without ever calling `validate_bank_state`, unlike `drift_deposit`/`drift_withdraw` which explicitly gate on `InstructionKind::FailsIfPausedOrReduceState`. Any signer can call this permissionless instruction to create the bank's Drift user/user-stats accounts and push a live deposit into Drift even after an admin has set the bank to `Paused` or `ReduceOnly`.

### Finding Description
`drift_init_user` (programs/marginfi/src/instructions/drift/init_user.rs:25-58) only enforces:
- `has_one` constraints on `liquidity_vault`, `integration_acc_1/2/3`, `mint`
- `is_drift_asset_tag(bank.load()?.config.asset_tag)` on the `DriftInitUser` account struct (lines 75-83)
- `amount >= 10`

It never calls `utils::validate_bank_state`, in contrast to `drift_deposit` (programs/marginfi/src/instructions/drift/deposit.rs:53-54) and `drift_withdraw`, which both call `validate_bank_state(&bank, InstructionKind::FailsIfPausedOrReduceState)` before proceeding. `lending_pool_configure_bank` (programs/marginfi/src/instructions/marginfi_group/configure_bank.rs:20-66) lets the group admin set `bank.config.operational_state` to `Paused`/`ReduceOnly` at any time after the bank is created via `lending_pool_add_bank_drift` (programs/marginfi/src/instructions/drift/add_pool.rs), independent of whether the Drift integration accounts (`integration_acc_2`/`integration_acc_3`) have been initialized yet.

Because `drift_init_user` is documented and reachable as "(permissionless)" (programs/marginfi/src/lib.rs:900-906), any fee payer can submit `DriftInitUser { amount: 10 }` against a bank the admin intentionally paused/reduce-onlyed, and the instruction will still: initialize the Drift user/user-stats PDAs, transfer tokens from the signer into the bank's liquidity vault, and CPI-deposit into Drift's spot market — all state-mutating financial actions that should have been blocked by the operational-state gate.

### Impact Explanation
This breaks the invariant that bank operational-state gating applies uniformly to every instruction that touches a bank's integration accounts. An admin who pauses/reduce-onlys a Drift bank (e.g., in response to a detected issue, prior to migration, or to freeze new exposure) cannot actually prevent new Drift user initialization/deposit activity on that bank, since `drift_init_user` bypasses the check entirely. This is a protocol-consistency/state-integrity bug: a paused bank still gets its Drift CPI accounts created and funded, undermining admin control intended by the `Paused`/`ReduceOnly` state and creating unexpected on-chain state during a period the bank was supposed to be frozen.

### Likelihood Explanation
High feasibility and fully permissionless: preconditions are only (1) a Drift-tagged bank exists, (2) admin has set it to `Paused` or `ReduceOnly` via `lending_pool_configure_bank`, and (3) `integration_acc_2`/`integration_acc_3` PDAs haven't been created yet (the normal state before `drift_init_user` has ever run). No admin/oracle/leaked-key access is required by the attacker — the attacker simply builds and submits the `DriftInitUser` instruction with a valid `signer_token_account` holding at least 10 native units of the bank mint. This is repeatable for any newly-added or newly-paused Drift bank.

### Recommendation
Add a `validate_bank_state(&bank, InstructionKind::FailsIfPausedOrReduceState)` call inside `drift_init_user` (programs/marginfi/src/instructions/drift/init_user.rs), mirroring the check already present in `drift_deposit` and `drift_withdraw`, before extracting `market_index`/`pool_id` and issuing the CPI calls.

        let bank = ctx.accounts.bank.load()?;

        market_index = integration_acc_1.market_index;
        pool_id = integration_acc_1.pool_id;
    }

    // Arbitrarily setting minimum deposit to 10 absolute units to always keep the account alive.
    require_gte!(amount, 10, MarginfiError::DriftUserInitDepositInsufficient);

    ctx.accounts.cpi_init_user_stats(authority_bump)?;

    ctx.accounts.cpi_init_user(authority_bump)?;

    ctx.accounts.cpi_transfer_user_to_liquidity_vault(amount)?;

        ctx.accounts

    }

    Ok(())
}

pub fn validate_bank_state(bank: &Bank, kind: InstructionKind) -> MarginfiResult {
    if bank.config.operational_state == BankOperationalState::KilledByBankruptcy {
        return err!(MarginfiError::BankKilledByBankruptcy);
    }
    // Bank exists but has not completed one-time setup (e.g. JupLend seed deposit). Block every
    // operation until init runs.
    if bank.config.operational_state == BankOperationalState::Uninitialized {
        return err!(MarginfiError::BankUninitialized);
    }

    match kind {
        InstructionKind::FailsInReduceState if bank.config.operational_state.is_reduce_only() => {
            return err!(MarginfiError::BankReduceOnly);
        }

        InstructionKind::FailsInPausedState
            if bank.config.operational_state == BankOperationalState::Paused =>
        {
            return err!(MarginfiError::BankPaused);
        }

        InstructionKind::FailsIfPausedOrReduceState
            if matches!(
                bank.config.operational_state,
                BankOperationalState::Paused
                    | BankOperationalState::ReduceOnly
                    | BankOperationalState::ReduceOnlyWithBorrowingPower
            ) =>
        {
            return match bank.config.operational_state {
                BankOperationalState::Paused => {
                    err!(MarginfiError::BankPaused)
                }
                state if state.is_reduce_only() => {
                    err!(MarginfiError::BankReduceOnly)
                }
                _ => unreachable!(),
            };
        }
        _ => {}
    }

    Ok(())
}

pub fn lending_pool_configure_bank(
    ctx: Context<LendingPoolConfigureBank>,
    bank_config: BankConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;

    // If settings are frozen, you can only update the deposit and borrow limits, everything else is ignored.
    if bank.get_flag(FREEZE_SETTINGS) {
        bank.configure_unfrozen_fields_only(&bank_config)?;

        msg!("WARN: Only deposit+borrow limits updated. Other settings IGNORED for frozen banks!");

        emit!(LendingPoolBankConfigureFrozenEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            deposit_limit: bank.config.deposit_limit,
            borrow_limit: bank.config.borrow_limit,
        });
    } else {
        // Settings are not frozen, everything updates
        bank.configure(&bank_config)?;
        msg!("Bank configured!");

        let group = ctx.accounts.group.load()?;
        bank.emode.validate_entries_with_liability_weights(
            &bank.config,
            group.emode_max_init_leverage,
            group.emode_max_maint_leverage,
        )?;

        emit!(LendingPoolBankConfigureEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            config: bank_config,
        });
    }

    Ok(())
}
