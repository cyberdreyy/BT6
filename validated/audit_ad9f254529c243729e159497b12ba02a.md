### Title
Address squatting on deterministic lockup accounts via unguarded `create` front-run - (File: `lockup-factory/src/lib.rs`)

### Summary
`LockupFactory::create` derives the lockup account deterministically as `hex::encode(&sha256(owner_account_id)[..20]).<factory>` and lets **any** caller invoke it for **any** `owner_account_id` with attacker-chosen `lockup_duration`, `vesting_schedule`, `release_duration`, and `whitelist_account_id`. Because the address depends only on `owner_account_id` — never on the caller/predecessor — an unprivileged attacker can pre-create that address with worthless parameters before the legitimate grant creator ever calls `create` for that owner, permanently squatting the identity.

### Finding Description
Binding claimed: `LockupArgs@sha256(victim)[..20].<factory> == LockupArgs the legitimate creator intended to send`. The code path breaks this binding: [1](#0-0) [2](#0-1) 

`create` computes `lockup_account_id` purely from `owner_account_id` and calls `Promise::new(lockup_account_id).create_account()` with attacker-supplied `LockupArgs`, with no check for whether this specific `owner_account_id` has already been claimed and no `predecessor_account_id`-based or caller-authorization restriction: [3](#0-2) 

Unlike `staking-pool-factory`, which tracks a `staking_pool_account_ids` set keyed by the *chosen prefix* (attacker-controlled anyway, so different risk profile), `LockupFactory` has no equivalent uniqueness bookkeeping — it just relies on NEAR's native "account already exists" failure at the protocol level. When that happens, `on_lockup_create` only checks `is_promise_success()` and refunds the *failed* caller; it never distinguishes "someone else already legitimately owns this address" from a normal transient failure, and critically, the first (attacker's) successful deployment is never rolled back: [4](#0-3) 

Exploit flow: attacker calls `create(owner_account_id=victim, lockup_duration=0, lockup_timestamp=None, vesting_schedule=None, release_duration=None, whitelist_account_id=None)` attaching `MIN_ATTACHED_BALANCE`. `create_account()` succeeds at `sha256(victim)[..20].<factory>` with attacker-chosen (nearly-worthless) `LockupArgs`. When the legitimate grant creator later calls `create` for the same `owner_account_id=victim` with the real vesting/lockup terms, `create_account()` fails at the protocol level (account exists), the callback refunds the legitimate creator's deposit, and the attacker's `LockupArgs` remain permanently live at the only address the ecosystem/tooling will ever associate with `victim`'s lockup.

No guard (`assert_self`, `is_promise_success`, `assert_owner`, etc.) checks caller identity against `owner_account_id`, nor prevents front-running deployment to the deterministic address before the intended creator acts.

### Impact Explanation
The victim's real lockup grant can never be deployed at the address that all tooling/whitelisting/investors expect (`sha256(victim)[..20].<factory>`), permanently freezing/nullifying the intended grant terms (`lockup_duration`, `vesting_schedule`, `release_duration`, `whitelist_account_id`) chosen by the rightful creator — this matches the Critical category "a lockup deployed with parameters its rightful creator never chose" / "funds permanently frozen." The attacker's cost is only `MIN_ATTACHED_BALANCE` (3.5 NEAR) per victim account name, and the attack is repeatable against any `owner_account_id` the attacker anticipates will later receive a grant (e.g., known team/investor account names), squatting the deterministic address ecosystem-wide.

### Likelihood Explanation
The attacker needs only a NEAR account and `MIN_ATTACHED_BALANCE` (~3.5 NEAR) plus gas — no privileged role, no victim key. The only precondition is guessing/knowing the intended `owner_account_id` before the real grant is issued, which is realistic since lockup owner accounts (e.g., known team-member or investor `.near` accounts) are typically public or predictable ahead of a token grant. This is fully feasible and repeatable per target account.

### Recommendation
Bind the lockup account creation to caller authorization or make address squatting economically/logically impossible: e.g., require the `owner_account_id` to sign/authorize creation (e.g., via a full-access-key-gated call from `owner_account_id` itself, or a foundation-controlled allowlist of pending owners), or maintain an on-chain registry (`LookupSet<AccountId>` keyed by `owner_account_id`) that is checked before the promise is dispatched and only allows one successful `create` per `owner_account_id`, with a re-claim path gated by `assert_called_by_foundation` for the rightful process.

// lockup-factory/src/lib.rs tests module (near-sdk testing_env!)
#[test]
fn test_address_squat_front_run() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    // Attacker front-runs with worthless params for owner = victim
    context.predecessor_account_id = String::from("attacker.testnet");
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(account_tokens_owner(), 0u64.into(), None, None, None, None);

    // Simulate successful create_account for attacker's call
    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    let attacker_result = contract.on_lockup_create(
        lockup_account(), // == sha256(victim)[..20].<factory>
        ntoy(35).into(),
        "attacker.testnet".to_string(),
    );
    assert_eq!(attacker_result, true); // attacker's squat "succeeded"

    // Legitimate creator later calls create for the SAME owner with real terms
    context.predecessor_account_id = String::from("real_grant_creator.testnet");
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(account_tokens_owner(), YEAR_DURATION.into(), None, Some(real_vesting), None, None);

    // Simulate protocol-level failure: account already exists at that address
    context.predecessor_account_id = account_factory();
    testing_env_with_promise_results(context.clone(), PromiseResult::Failed);
    let real_result = contract.on_lockup_create(
        lockup_account(),
        ntoy(35).into(),
        "real_grant_creator.testnet".to_string(),
    );

    // Binding check: the legitimate creator's LockupArgs never got deployed;
    // the attacker's LockupArgs at the deterministic address remain live.
    assert_eq!(real_result, false); // legitimate creation fails / refunded
    // attacker_result == true and real_result == false demonstrates the
    // deterministic address was permanently squatted with attacker-chosen terms.
}

    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
