## Finding: Stale confirmations from removed multisig members still count toward the execution threshold

The core of the analog Sherlock finding is that revoking an actor's authorization (`blacklist`) does not stop that actor's prior grant of trust from being used — the state that should reflect "no longer trusted" is not actually enforced at the point the trust is exercised. The same class of bug exists in `multisig2/src/lib.rs`, where a member removed from the multisig can still have its **stale confirmation** silently counted toward the confirmation threshold that authorizes fund transfers.

### Finding Description

`confirm()` only validates that the **new** confirmer is a current member via `current_member()`, but it never re-validates the confirmations already stored in the `confirmations: LookupMap<RequestId, HashSet<String>>` set for a request: [1](#0-0) 

`delete_member()` only purges requests and confirmations **originated by** the removed member (`r.member == member`); it does not scan other members' pending requests to strip out confirmations that the removed member previously cast on them: [2](#0-1) 

Consider `num_confirmations = 3` with members `{A, B, C, D}`:
1. `A` creates and confirms a `Transfer` request `R` (`confirmations = {A}`).
2. `D` confirms `R` (`confirmations = {A, D}`, 2 of 3).
3. The group later removes `D` (e.g. suspected key compromise) via a separate `DeleteMember` request that reaches 3 confirmations and executes. `delete_member` only cleans up requests *added by* `D`, not `D`'s stale confirmation entry on `R`, which was added by `A`. `R`'s `confirmations` set still contains `D`.
4. `B` (or any remaining single member) now calls `confirm(R)`. The check `confirmations.len() as u32 + 1 >= self.num_confirmations` evaluates `{A, D}.len() + 1 = 3 >= 3` and executes the transfer — using `D`'s phantom, no-longer-valid vote instead of `C`'s live confirmation.

The equality that should hold — `confirmations counted == confirmations from currently live members` — is broken: `R` executes with only 2 genuinely live signers (`A`, `B`) even though 3-of-3/4 was required and `D` was revoked before completion.

### Impact Explanation

This lets a `Transfer`, `FunctionCall`, `AddKey`, `AddMember`, or any other `MultiSigRequestAction` execute below the intended live-member threshold, using a revoked member's leftover vote. This directly matches the Critical impact category "a multisig request executed below threshold," permitting unauthorized movement of the multisig account's NEAR (or execution of any other privileged action, including adding a new access key/full access key) with fewer honest, currently-authorized approvals than configured.

### Likelihood Explanation

No foundation, owner, or out-of-band privilege is required — only ordinary multisig usage: any request that receives a partial confirmation from a member before that member is later removed leaves an exploitable stale confirmation. Member turnover (removing a suspected-compromised key, rotating signers) is a normal multisig operation, so the precondition is easily reached in practice by any one of the remaining members initiating the final confirming call.

### Recommendation

When a member is deleted, iterate over **all** pending requests (not just the ones it originated) and strip the deleted member's entry from each request's `confirmations` set, or re-validate every entry in `confirmations` against current `members` inside `confirm()`/`assert_valid_request()` before counting toward the threshold.

### Proof of Concept

Trace of `multisig2/src/lib.rs` state as constructed above:
- `members = {A, B, C, D}`, `num_confirmations = 3`.
- `add_request_and_confirm(R)` by `A` → `confirmations[R] = {A}` [3](#0-2) 
- `confirm(R)` by `D` → `confirmations[R] = {A, D}` [1](#0-0) 
- `DeleteMember { member: D }` request confirmed by `A, B, C` → executes `delete_member`, which removes `D` from `members` and deletes only requests where `r.member == D` — `R` (owned by `A`) is untouched, so `confirmations[R]` still contains `D`. [2](#0-1) 
- `confirm(R)` by `B` → `confirmations[R].len() + 1 = 3 >= num_confirmations (3)` → `execute_request(R)` runs the `Transfer`, despite `D` no longer being a member. [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
