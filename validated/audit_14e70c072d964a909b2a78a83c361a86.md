### Title
Instant withdrawals bypass upfront withdrawal fees in `requestWithdraw` - ([File: contracts/IdleCDOEpochVariant.sol])

### Summary
`IdleCDOEpochVariant.requestWithdraw` applies management and performance fees only on the queued-withdrawal path. When an APR decrease enables the instant-withdrawal branch, the function creates a receipt for the full current tranche value and returns before `_totalWithdrawFees` is calculated or `pendingWithdrawFees` is incremented. [1](#0-0) 

### Finding Description
A withdrawal request first refreshes accounting and converts the tranche amount into underlying value. If the current APR has fallen by more than `instantWithdrawAprDelta`, the function calls `IdleCreditVault.requestInstantWithdraw` for the complete `_underlyings` amount, burns the tranche position, and returns. [2](#0-1) 

The ordinary withdrawal path instead calculates projected interest, subtracts `_totalWithdrawFees`, and records those fees in `pendingWithdrawFees` for later distribution. [3](#0-2)  The strategy mints the instant receipt at the full requested amount and adds the complete amount to `pendingInstantWithdraws`, with no separate fee deduction or fee accounting. [4](#0-3) 

The missing charge is not collected later. `claimInstantWithdrawRequest` transfers the complete recorded receipt amount to the user. [5](#0-4)  By contrast, queued-request fees are transferred to `feeReceiver` during the next successful `stopEpoch`. [6](#0-5) 

### Impact Explanation
Any KYC-passing lender can choose the instant branch whenever the honest manager lowers APR enough to satisfy `lastEpochApr > currentApr + instantWithdrawAprDelta`. The lender receives the full receipt value while the protocol records zero `pendingWithdrawFees` for that withdrawal.

For a withdrawal principal `P`, management-fee rate `m`, and fee duration `D`, the uncollected management fee is:

```text
missedFee = P * m * D / (365 days * FULL_ALLOC)
```

For example, with `P = 1,000,000` tokens, `m = 1%` (`1_000`), and a 35-day withdrawal fee duration, the missing management fee is approximately `958.904` underlying tokens. A configured performance fee on the withdrawal’s projected yield increases the discrepancy further.

The direct loss is borne by the configured fee recipients rather than being socialized immediately across remaining LPs. Repeated instant withdrawals can bypass the fee on the full withdrawn NAV.

### Likelihood Explanation
The attacker needs only to be an allowed tranche holder and submit `requestWithdraw` during the buffer after an APR reduction. No privileged action, malicious borrower, default, oracle manipulation, or special timing within a block is required. The branch is explicitly enabled by the protocol’s own `lastEpochApr`, `unscaledApr`, `instantWithdrawAprDelta`, and `disableInstantWithdraw` settings. [7](#0-6) 

Existing KYC, withdrawal-request flags, donation skimming, default checks, and reentrancy protections do not prevent the fee-free branch.

### Recommendation
Apply the protocol’s withdrawal-fee policy before creating the instant receipt. The instant path should calculate the appropriate fee, subtract it from the receipt amount, and account for it in `pendingWithdrawFees` or another fee balance that is later paid to fee recipients. Alternatively, document and enforce an explicit fee exemption for instant withdrawals if the missing charge is intentional.

### Proof of Concept
A Foundry test in the existing `test/foundry/IdleCreditVault.t.sol` environment can demonstrate the divergence:

```solidity
function testInstantWithdrawBypassesWithdrawFees() external {
    uint256 amount = 1_000_000 * ONE_SCALE;
    uint256 mgmtFeeRate = 1_000; // 1%
    uint256 perfFeeRate = 10_000; // 10%

    _setFeeParams(TL_MULTISIG, perfFeeRate, FULL_ALLOC, mgmtFeeRate);

    vm.prank(manager);
    cdoEpoch.setInstantWithdrawParams(0, 0, false);

    uint256 trancheAmount = idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);

    vm.prank(manager);
    cdoEpoch.startEpoch();

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Honest manager lowers APR enough to activate the instant branch.
    uint256 oldApr = IdleCreditVault(address(strategy)).unscaledApr();
    uint256 newApr = oldApr - cdoEpoch.instantWithdrawAprDelta() - 1;

    vm.prank(manager);
    cdoEpoch.stopEpoch(newApr, 0);

    uint256 principal =
        trancheAmount * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;

    uint256 requested = cdoEpoch.requestWithdraw(trancheAmount, address(AAtranche));

    assertEq(requested, principal, "instant path returned full principal");
    assertEq(
        IdleCreditVault(address(strategy)).instantWithdrawsRequests(address(this)),
        principal,
        "instant receipt was not haircut"
    );
    assertEq(
        cdoEpoch.pendingWithdrawFees(),
        0,
        "no withdrawal fee was accrued"
    );
}
```

The assertions distinguish the vulnerable path from the queued path: the instant receipt equals the full current value while `pendingWithdrawFees` remains zero, whereas the queued path computes `_totalWithdrawFees` and increments `pendingWithdrawFees`. [3](#0-2)

  function requestInstantWithdraw(uint256 _amount, address _user) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // increase the instant withdraw requests for the user
    instantWithdrawsRequests[_user] += _amount;
    uint256 currentEpoch = epochNumber;
    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"
    // from old funded instant receipts.
    instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
    pendingInstantWithdraws += _amount;
  }

  function claimInstantWithdrawRequest(address _user) external {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized && defaultInstantWithdrawsFinalized) {
      // Clear the defaulted-epoch instant receipt first, then continue so the same call can
      // also pay any older instant receipt that was already funded before default finalization.
      _claimDefaultedInstantWithdrawRequest(_user);
    }
    uint256 amount = instantWithdrawsRequests[_user];
    // burn strategy tokens from user
    _burn(_user, amount);

    instantWithdrawsRequests[_user] = 0;
    _transferFundedClaim(_user, amount);
  }
