### Title
CORS wildcard-origin bypass due to missing domain-separator check — ([File: core/services/gateway/network/httpserver.go])

### Summary
The Gateway's user-facing `HTTPServer` (`core/services/gateway/network/httpserver.go`) reflects the `Origin` header into `Access-Control-Allow-Origin` whenever `isAllowedOrigin` returns true [1](#0-0) . When an operator configures a wildcard entry such as `https://*.remix.com` in `CORSAllowedOrigins`, the matching logic strips the `*.` prefix and then checks only `strings.HasSuffix(originHost, allowedHost)`, without requiring a `.` boundary before the suffix [2](#0-1) .

### Finding Description
`isAllowedOrigin` parses both the request `Origin` and each configured allowed origin, matching scheme and port exactly, then falls back to `strings.HasSuffix` for wildcard entries [3](#0-2) . Because `HasSuffix` performs a raw string suffix match, a host such as `evilremix.com` satisfies `HasSuffix("evilremix.com", "remix.com")` even though it is not a subdomain of `remix.com` — there is no check that the character preceding the suffix is a `.`. This mirrors the QR-scanner bug class where `contains`/substring checks on a URL were bypassed by crafting attacker domains that textually contain the target string without being a true match (e.g., `frodo2weborderdev.page.link.evil.com`). Here the analogous bypass is an attacker registering any domain whose name simply ends with the allowed suffix (no subdomain dot required), e.g. `notremix.com`, `attacker-remix.com`, or `xremix.com`.

### Impact Explanation
If an operator enables `CORSEnabled` with any wildcard entry in `CORSAllowedOrigins` (a supported, documented configuration pattern, exercised in `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`) [4](#0-3) , an attacker hosting a page on a lookalike domain (e.g. `evilremix.com` when `*.remix.com` is allowed) can have their origin reflected back in `Access-Control-Allow-Origin`, letting their JavaScript read the JSON-RPC response returned by `ProcessRequest` via `fetch`/XHR with credentials or tokens included in the request. Since this endpoint processes arbitrary Gateway JSON-RPC requests (including JWT-authenticated ones per the `Authorization` header handling) and returns their response body cross-origin, this can lead to cross-user response confusion / unauthorized read of request results from an untrusted origin — a browser-based confused-deputy/CORS bypass reachable by any unprivileged web attacker who can lure a victim into visiting their page.

### Likelihood Explanation
Exploitation requires: (1) the Gateway operator to enable CORS with at least one `*.` wildcard entry, and (2) the attacker to register a domain that lexically ends with the allowed suffix without a subdomain dot. Domain registration is cheap and unprivileged, and CORS wildcarding is a documented supported feature, so likelihood is non-trivial in any deployment using wildcard CORS origins.

### Recommendation
When matching wildcard origins, require a `.` immediately before the suffix (or compare using proper subdomain segmentation), e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```
This mirrors the QR-scanner fix pattern of parsing the value and strictly comparing structured components rather than doing raw substring/suffix checks.

### Proof of Concept
1. Configure the Gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.remix.com"]`.
2. Send a request to the user-facing HTTP endpoint with header `Origin: https://evilremix.com`.
3. `isAllowedOrigin` computes `allowedHost = "remix.com"` and checks `strings.HasSuffix("evilremix.com", "remix.com")`, which is `true`, so the server responds with `Access-Control-Allow-Origin: https://evilremix.com` [5](#0-4) , even though `evilremix.com` is not a subdomain of `remix.com`.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
