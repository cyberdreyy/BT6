### Title
Unauthenticated LOOP plugin pprof symbol resolution endpoint discloses internal build/code layout - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers `POST /plugins/:name/debug/pprof/symbol` directly on the base `api` router group with no authentication middleware, unlike other sensitive debug endpoints (`/debug/vars`, `/v2/*` debug routes) which are explicitly wrapped in `auth.Authenticate(...)`. Any unauthenticated caller can POST program-counter addresses and receive resolved symbol/function names for the plugin (LOOPP) process, disclosing internal code layout and build information useful for further exploitation.

### Finding Description
In `core/web/router.go`, `NewRouter` builds a single `api` group with only rate limiting and session middleware attached (lines 78-85), then calls `loopRoutes(app, api)` (line 91). `loopRoutes` itself does not add any `auth.Authenticate(...)` wrapper before registering its routes: [1](#0-0) 

Contrast this with `debugRoutes`, which explicitly wraps its group in session authentication before exposing `/debug/vars`: [2](#0-1) 
and with `metricRoutes` (which serves Go's own pprof endpoints), which is only ever mounted inside the authenticated `authv2` group at line 446, not at the top level.

The handler `pluginPPROFPOSTSymbolHandler` in `core/web/loop_registry.go` performs no auth/session/token check of its own — it looks up the plugin by name, reads the raw POST body, and proxies it unmodified to the plugin's internal `/debug/pprof/symbol` endpoint, then returns the raw response body to the caller: [3](#0-2) 

Since `api` has no authentication requirement and `loopRoutes` adds none, any unauthenticated network client that can reach the node's HTTP port can POST arbitrary `pc` addresses to `/plugins/<name>/debug/pprof/symbol` and get back resolved symbol names for the named LOOP plugin process, which is genuine reconnaissance data (function/symbol names, indicating internal code structure and build layout) obtainable with zero credentials.

### Impact Explanation
This is an authentication-soundness gap: a route that should require at least session/token authentication (as `debug/vars` and `metricRoutes` do) is fully open. The impact is limited to information disclosure/reconnaissance (symbol-to-address resolution for the plugin binary) rather than direct fund loss or key disclosure, but it lowers the bar for follow-on exploitation of the plugin process and confirms an inconsistency in the auth model that an attacker can trivially probe.

### Likelihood Explanation
No preconditions beyond network reachability to the node's API port are required — no credentials, tokens, sessions, or roles. The route is reachable directly and repeatably from any unauthenticated client; the `GET` sibling endpoints (`/plugins/:name/debug/pprof/*profile`, `/plugins/:name/metrics`, `/discovery`) registered in the same function share the identical lack-of-auth issue.

### Recommendation
Wrap `loopRoutes` registrations in the same authentication middleware used by `debugRoutes`/`metricRoutes` (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` or token-based auth), or move these plugin debug/metrics/discovery endpoints into the authenticated `authv2` group like `metricRoutes` already is.

### Proof of Concept
1. Start a node with a LOOP plugin registered (or stub `l.registry` to return a fake plugin entry).
2. Using `httptest` with `NewRouter`, issue `POST /plugins/<name>/debug/pprof/symbol` with body `pc=<hex address>` and **no** `Authorization` header and **no** session cookie.
3. Assert the response status is not `401 Unauthorized`/`403 Forbidden`, and that the response body contains resolved symbol data proxied from the plugin (mock the plugin's backing HTTP server to return a known symbol name and verify it appears in the response).
4. Repeat for `GET /plugins/:name/debug/pprof/*profile` and `GET /discovery` to confirm the same unauthenticated-access pattern across `loopRoutes`.

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
