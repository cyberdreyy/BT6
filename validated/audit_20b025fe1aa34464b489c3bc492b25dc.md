## Finding [1](#0-0) 

### Title
Unbounded recursion in `TrieNode::decode` allows stack-overflow crash of the fault-proof program via crafted MPT preimages - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` recursively decodes inline (unblinded) extension-node children with no depth limit, directly analogous to the Wireshark BACapp dissector recursion bug (CVE-2020-11647). Because trie node preimages supplied to the fault-proof program are validated only by hash equality — not by structural shape — an adversarial preimage provider (a dispute-game challenger/prover role in the fault-proof protocol) can craft a single preimage blob containing thousands of nested, sub-32-byte `Extension` nodes that never get "blinded," causing unbounded native recursion and a stack overflow when the program attempts to open/verify state during output-root computation.

### Finding Description
`TrieNode` nodes are only blinded (hashed with keccak256) when their RLP-encoded length is ≥ 32 bytes: [2](#0-1) 

This means an `Extension` node whose child is small enough (also an `Extension`) is encoded inline in the same buffer, without ever being separated into its own hashed preimage. On the decode side, `try_decode_leaf_or_extension_payload` recurses directly into `Self::decode(buf)` to decode the nested (still-inline) extension payload: [3](#0-2) 

and `TrieNode::decode` itself dispatches back into this same recursive decode path for any list of length 2: [4](#0-3) 

Neither function tracks or limits recursion depth. Because each nested extension frame can be encoded in only a handful of bytes, a single preimage of ordinary size (well within normal preimage-oracle chunk/part limits) can contain tens of thousands of nested inline extension nodes, driving native call-stack recursion far beyond what the fault-proof program's stack can hold.

Preimages fed into this decoder are validated purely by `keccak256(value) == key`, not by their internal trie structure, as seen in the preimage integrity check used across proof backends: [5](#0-4) 

Any actor able to supply an L1/L2 state or storage-trie node preimage that the fault-proof program will fetch and decode via `TrieProvider`/`trie_node_by_hash` (reached from `TrieNode::open`/`unblind` during state-root derivation) can trigger this: as long as the bytes hash to the requested key, their internal RLP structure is attacker-controlled.

### Impact Explanation
A stack overflow in the fault-proof program (`base-proof-client`'s `Prologue`/`FaultProofDriver`, or the TEE/ZK equivalents in `crates/proof/tee` and `crates/proof/zk`) aborts the process instead of producing a comparison between computed and claimed output roots. This is a direct **node halt** of the dispute/fault-proof execution and can be used to prevent an honest challenger's proof program from ever completing, undermining the fault-proof/dispute-game's ability to produce a **correct provable output root** — matching the "node halt" / "wrong provable output root" impact classes explicitly in scope.

### Likelihood Explanation
The bug is trivially triggerable by anyone who can supply an unverified-shape preimage that legitimately hashes to a value the program requests (e.g., a malicious/compromised preimage source, or a dispute-game participant providing a state/storage node during proof execution). No cryptographic break is needed — only that `keccak256(crafted_bytes) == requested_hash`, which is satisfied automatically because the crafted node is exactly the preimage being requested (the attacker constructs the whole subtree, not a forged hash of someone else's data), and the nested-extension trick requires no special hash collision at all.

### Recommendation
Add an explicit recursion-depth bound (e.g., matching Ethereum's maximum theoretical trie depth for the fixed-length keys this trie is designed for, ~64/65 nibbles) to `TrieNode::decode`/`try_decode_leaf_or_extension_payload`, returning a decode error once the bound is exceeded, mirroring the fix applied upstream for the analogous Wireshark BACapp recursion issue (bounding dissector recursion depth).

### Proof of Concept
1. Encode a `TrieNode::Leaf` with a short value.
2. Wrap it in nested `TrieNode::Extension { prefix: <1 nibble>, node: Box::new(previous) }` N times (e.g., N = 100,000), each remaining under 32 bytes so it stays inline/unblinded rather than being replaced with a `Blinded` commitment (per the `>= B256::ZERO.len()` blinding check in `Encodable for TrieNode::encode`, `crates/proof/mpt/src/node.rs:527-537`).
3. Store the fully encoded byte blob as the preimage for the hash the fault-proof program requests for a state/storage trie node.
4. When `TrieNode::decode` is invoked on this preimage (e.g., via `TrieNode::open`/`unblind` during state derivation in the fault-proof program), the recursive calls in `try_decode_leaf_or_extension_payload` → `Self::decode` (`crates/proof/mpt/src/node.rs:454-461`, `567-590`) recurse N times, exhausting the stack and crashing the process before an output root can be computed.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}
