### Title
Unauthenticated flood of `HandleLegacyUserMessage` triggers eviction of victims' pending callbacks in `pruneCallbacks`, causing silent cross-user DoS - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`ProcessRequest` in `gateway.go` dispatches legacy `web_api_trigger` messages to `handler.HandleLegacyUserMessage` with only JSON-RPC envelope validation, no allowlist, and no per-sender rate limiting, exactly as flagged by the `// TODO: apply allowlist and rate-limiting here` comment. An attacker can register unlimited entries in the shared `savedCallbacks` map with distinct `MessageId`s and never complete them, forcing `pruneCallbacks` to evict the oldest (potentially victim) entries by creation time without ever calling `SendResponse` on them, so victims silently hang until the outer `callback.Wait(ctx)` context deadline.

### Finding Description
`gateway.ProcessRequest` decodes the raw JSON-RPC request, validates only the message envelope via `msg.Validate()`, resolves the handler by `DonId`, and calls `h.HandleLegacyUserMessage(ctx, msg, callback)` directly — there is no authentication, no allowlist check, and no per-caller quota at this layer. [1](#0-0) 

`HandleLegacyUserMessage` checks payload decodability, a non-zero timestamp, and message staleness/method — none of which prevent a large volume of distinct, well-formed requests — then unconditionally stores the callback keyed by the caller-supplied `msg.Body.MessageId` in the handler-wide `h.savedCallbacks` map shared across all users of the DON. [4](#0-3) 

A background goroutine periodically calls `pruneCallbacks`, which first deletes entries older than `CallbackMaxAgeSec`, then, if the map still exceeds `MaxSavedCallbacks`, sorts all remaining entries by `createdAt` and deletes (via plain `delete()`, no `SendResponse`) all but the newest half. [5](#0-4) 

Since eviction is purely by creation time regardless of which caller/user owns the entry, an attacker submitting a high volume of `web_api_trigger` messages with fresh timestamps and unique `MessageId`s (never followed by a real node response, so `handleWebAPITriggerMessage` never removes/resolves them) will push the map over `MaxSavedCallbacks` and cause older legitimate victim entries to be silently deleted. The victim's `callback.Wait(ctx)` in `gateway.ProcessRequest` then only resolves via the outer context timeout, returning a generic timeout error, with no indication of eviction. [6](#0-5) [7](#0-6) 

### Impact Explanation
This is a denial-of-service on legitimate users' cross-DON requests: an unauthenticated/unprivileged sender can force premature, silent termination of other users' pending `web_api_trigger` requests by exhausting the shared, unbounded-by-identity `savedCallbacks` map. This matches the "quota/allowlist bypass leading to cross-user disruption" bounty class rather than a data-leak or fund-theft class, since no secret data or funds are exposed — only availability of another user's in-flight request is affected.

### Likelihood Explanation
The only precondition is the ability to send JSON-RPC messages to the gateway's user HTTP port with a valid envelope (`msg.Validate()` — no signature-of-authorized-key check is present in this legacy code path beyond format), a non-zero timestamp within `MaxAllowedMessageAgeSec`, and method `web_api_trigger`. No credentials, allowlist membership, or node/operator access is required. The `nodeRateLimiter` referenced in the handler only throttles node→gateway outgoing messages (`handleWebAPIOutgoingMessage`), not the user-facing `HandleLegacyUserMessage` entry point, so there is no rate limiting on the attacker-controlled path at all. `defaultMaxSavedCallbacks` is 20000, which is a large but finite and attacker-reachable volume, and the `// TODO: apply allowlist and rate-limiting here` comment at line 384 confirms this gap is a known, unaddressed limitation in the current code, not a control that exists elsewhere.

### Recommendation
Add per-sender/per-key rate limiting and/or an allowlist check in `HandleLegacyUserMessage` before inserting into `savedCallbacks` (closing the TODO at line 384), and change `pruneCallbacks` to call `SendResponse` with a clear "evicted/superseded" error for any callback it deletes (both on age-expiry and on LRU-trim) so callers are not left to time out silently. Consider also bounding the map per-sender identity in addition to the global cap so one sender cannot exhaust the shared quota for others.

### Proof of Concept
1. Unit test in `core/services/gateway/handlers/capabilities/handler_test.go`, similar to `setupHandler`, but constructing a `handler` with a small `MaxSavedCallbacks` (e.g., 10) and `CallbackMaxAgeSec` large enough that entries don't expire during the test.
2. Insert one "victim" entry into `h.savedCallbacks` directly (or via `HandleLegacyUserMessage` with a mocked `don.SendToNode`), recording its callback.
3. Insert `MaxSavedCallbacks` "attacker" entries with later `createdAt` timestamps and distinct `MessageId`s (simulating flooding via `HandleLegacyUserMessage` calls that never receive a corresponding `handleWebAPITriggerMessage` completion).
4. Call `h.pruneCallbacks()` directly.
5. Assert that the victim's `MessageId` is no longer present in `h.savedCallbacks` (evicted) and that the victim's callback never received `SendResponse` — i.e., calling `callback.Wait(ctx)` with a short timeout returns a context-deadline error rather than a handler-issued response, demonstrating the silent hang.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}
