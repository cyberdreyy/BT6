### Title
`pause()` on `IdleCDOEpochVariant` is bypassable: `depositDuringEpoch()` and `requestWithdraw()` remain fully callable while the vault is paused - ([File: contracts/IdleCDOEpochVariant.sol](https://github.com/Noahgrantyt/idle-tranches--010/blob/main/contracts/IdleCDOEpochVariant.sol))

### Summary
`IdleCDOCreditVault.pause()` only flips the OZ `Pausable` flag, which gates `depositAA`/`depositBB`/`_deposit` via `whenNotPaused`. But the epoch-specific entry points `depositDuringEpoch()` and `requestWithdraw()` have **no `whenNotPaused` modifier** and check only `skipDefaultCheck` / `allowAAWithdrawRequest` / `allowBBWithdrawRequest` — flags that are only set by `_emergencyShutdown()` or `_handleBorrowerDefault()`, not by `pause()`. Additionally, `claimWithdrawRequest`/`claimInstantWithdrawRequest` live on the separate `IdleCreditVault` strategy contract and are unaffected by the CDO's pause state entirely — the exact Arrakis `mint()`/`burn()` bypass pattern.

### Finding Description
- `pause()` at `IdleCDOCreditVault.sol:518` calls only `_pause()`. It does not set `skipDefaultCheck`, `allowAAWithdrawRequest`, or `allowBBWithdrawRequest`.
- `depositDuringEpoch()` at `IdleCDOEpochVariant.sol:656` is `external` with no `whenNotPaused`. Its gate (lines 658–669) checks `isDepositDuringEpochDisabled`, `skipDefaultCheck`, `isProgrammableBorrower`, `isAYSActive`, `isEpochRunning`, `epochEndDate`, and `isWalletAllowed` — none of which `pause()` changes. A KYC'd lender can therefore deposit mid-epoch while the vault is paused, receive tranche tokens minted at the discounted price, and push underlyings to the borrower (`_transferUnderlyings(_borrower(), _amount)` at line 732).
- `requestWithdraw()` at `IdleCDOEpochVariant.sol:739` is `external` with no `whenNotPaused`. It only reverts on `!allowAAWithdrawRequest`/`!allowBBWithdrawRequest` or failed KYC. After a plain `pause()`, a lender can still burn tranche tokens via `_withdrawOps` and register a withdrawal claim, or take the instant-withdraw path (`creditVault.requestInstantWithdraw` at line 765).
- Claims settle on `IdleCreditVault` (the strategy contract), a different contract than the paused CDO. `claimWithdrawRequest`/`claimInstantWithdrawRequest` pay out funded requests regardless of `paused()` on the CDO — analogous to calling ArrakisV2 `burn()` directly while the router is paused.

### Impact Explanation
During a running epoch, `pause()` — the lighter-weight control intended to halt deposits without full emergency shutdown — is completely ineffective: both the deposit path (`depositDuringEpoch`) and the exit path (`requestWithdraw`, plus downstream claims on `IdleCreditVault`) remain open. If the guardian pauses because a vault/borrower issue is suspected (e.g., to stop new funds flowing to a compromised borrower), an unprivileged KYC'd lender can still deposit into the compromised pool, mint tranche tokens, and later claim principal + prorated interest; and existing lenders can still queue/burn for withdrawals the pause was meant to freeze. The pause feature's stated purpose ("Pauses deposits" per the natspec) is violated on every user-facing mutating path that is active during an epoch.

### Likelihood Explanation
The bypass requires only that (a) an epoch is running or requests are allowed, and (b) `pause()` was used instead of `emergencyShutdown()`. Guardian/owner (honest per scope rules) calling `pause()` is a documented, legitimate action — the gap is structural, not attacker-dependent. The attacker is any KYC-passing lender or tranche holder. Note that `emergencyShutdown()` does close these paths (`skipDefaultCheck`, `allow*WithdrawRequest = false`), which partially mitigates, but the existence of a working alternative does not fix the broken semantics of `pause()` — same reasoning as the source report.

### Recommendation
Add `whenNotPaused` (or an equivalent `paused()` check) to `depositDuringEpoch()` and `requestWithdraw()` in `IdleCDOEpochVariant.sol`, or have `pause()` also set `skipDefaultCheck` and clear `allowAAWithdrawRequest`/`allowBBWithdrawRequest`. Consider whether `IdleCreditVault` claim functions should respect a pause signal propagated from the CDO for queued-withdrawal claims.

### Proof of Concept
```solidity
// Foundry fork test, modeled on test/foundry/IdleCreditVault.t.sol helpers
function testPauseBypassedByEpochPaths() external {
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);            // seed AA tranche
    // enable mid-epoch deposits (fixed-APR mode, AYS off)
    vm.startPrank(owner);
    cdoEpoch.setIsAYSActive(false);
    cdoEpoch.setIsDepositDuringEpochDisabled(false);
    vm.stopPrank();
    _startEpochAndCheckPrices(0);          // epoch running

    // guardian/owner pauses the vault (NOT emergencyShutdown)
    vm.prank(owner);
    idleCDO.pause();
    assertTrue(idleCDO.paused());

    // depositAA correctly reverts
    vm.expectRevert(bytes("Pausable: paused"));
    idleCDO.depositAA(ONE_SCALE);

    // BYPASS 1: depositDuringEpoch has no whenNotPaused and does not check paused()
    address user = makeAddr('kyc-lender'); // isWalletAllowed passes via Keyring mock
    deal(defaultUnderlying, user, amount);
    vm.startPrank(user);
    underlying.approve(address(cdoEpoch), amount);
    uint256 minted = cdoEpoch.depositDuringEpoch(amount, address(AAtranche));
    assertGt(minted, 0);                   // paused vault still minted tranche tokens

    // BYPASS 2: requestWithdraw only checks allow*WithdrawRequest, untouched by pause()
    uint256 underlyings = cdoEpoch.requestWithdraw(0, address(AAtranche));
    assertGt(underlyings, 0);              // exit path still open while "paused"
    vm.stopPrank();
}
```

Key line references: `pause()` at `IdleCDOCreditVault.sol:518-521`; `depositDuringEpoch` gating at `IdleCDOEpochVariant.sol:656-669` (no `paused()` check); `requestWithdraw` gating at `IdleCDOEpochVariant.sol:739-744`; `_emergencyShutdown` (the only flag-setter) at `IdleCDOEpochVariant.sol:602-615`.

Caveat: I confirmed `depositDuringEpoch` and `requestWithdraw` lack `whenNotPaused` by direct read of `IdleCDOEpochVariant.sol`; `claimWithdrawRequest`/`claimInstantWithdrawRequest` on `IdleCreditVault` were located by grep but I did not read their full bodies to confirm absence of a CDO-pause check — that specific claim is inferred from the contract separation (pause state lives on the CDO, claims on the strategy).
