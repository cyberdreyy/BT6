### Title
Unauthenticated-by-role disclosure of External Initiator `AccessKey`/`OutgoingToken` to any authenticated view-role user via `GET /v2/external_initiators` - ([File: core/web/router.go])

### Summary
The `GET /v2/external_initiators` route is registered with no role gate (`auth.RequiresEditRole`/`RequiresAdminRole`/`RequiresRunRole`), unlike the sibling `POST`/`DELETE` routes on the same resource. `ExternalInitiatorsController.Index` returns `presenters.ExternalInitiatorResource`, which includes the plaintext `AccessKey` and `OutgoingToken` for every external initiator in the database, to any authenticated user regardless of role.

### Finding Description
In `core/web/router.go`, the external-initiator routes are defined as: [1](#0-0) 
Only `Create` and `Destroy` are wrapped with `auth.RequiresEditRole`; `Index` is wrapped only with `paginatedRequest`, which does no role checking — it runs after the generic `authv2` group middleware `auth.Authenticate(...)` that merely establishes *who* the caller is (via session or API token), not *what* role they hold.

`ExternalInitiatorsController.Index` fetches all external initiators and converts each into a public resource without any per-record ownership or role filtering: [2](#0-1) 

`presenters.NewExternalInitiatorResource` copies the credential fields `AccessKey` and `OutgoingToken` directly into the JSON-serialized resource: [3](#0-2) 

`AccessKey` is the identifier the node uses to authenticate an inbound external-initiator run-trigger request (`auth.AuthenticateExternalInitiator`), and `OutgoingToken` is the secret the node itself sends outward to the external initiator's webhook. Exposing both to any authenticated user — including one with only `UserRoleView` — lets that user impersonate the external initiator toward the node (trigger job runs it should not be able to trigger, since `RequiresRunRole` blocks view-role users from `/v2/replay_from_block` etc. but the raw credentials leak through Index) and impersonate the node toward the initiator's endpoint using `OutgoingToken`.

Contrast with the role checks that do exist for other role-boundary-sensitive index/mutation endpoints in the same file, e.g. `auth.RequiresAdminRole(uc.Index)` for `/users`: [4](#0-3) 
There is no equivalent gate for `/external_initiators` GET, so `RequiresRunRole`/`RequiresEditRole`'s intended privilege boundary (view role cannot exercise run/edit/admin capability) is bypassed for reading these credentials.

### Impact Explanation
Any authenticated view-role (or run-role) user — the lowest privilege authenticated role in the system — can call `GET /v2/external_initiators` and receive the `accessKey`/`outgoingToken` for every external initiator configured on the node, not just ones they created (external initiators have no per-user ownership concept at all, compounding the exposure). This is direct credential disclosure of node-managed secrets, matching the "key or secret disclosure" bounty class, and enables impersonation of both the external initiator (toward the node) and the node (toward the initiator's callback URL) using leaked `OutgoingToken`.

### Likelihood Explanation
Trivial and fully repeatable: it only requires a valid, low-privilege (`view`) session or API token — the minimal authenticated credential class. No admin/edit access, no timing, no race condition. A single `GET /v2/external_initiators` request reveals the secrets for all configured initiators.

### Recommendation
Gate `GET /v2/external_initiators` with at minimum `auth.RequiresEditRole` (matching `Create`/`Destroy`), or better, `auth.RequiresAdminRole` since these are node-wide credentials. Additionally, `presenters.ExternalInitiatorResource` should redact `AccessKey`/`OutgoingToken` on list/read responses (only return them once, at creation time, as is already done via `ExternalInitiatorAuthentication`) rather than persisting and re-serving them.

### Proof of Concept
Go handler-level test plan (in `core/web/external_initiators_controller_test.go` style):
1. Start app with `ExternalInitiatorsEnabled = true`.
2. Create a user/API token with `clsessions.UserRoleView`.
3. Insert an external initiator via `cltest.MustInsertExternalInitiatorWithOpts` with known `AccessKey`/`OutgoingToken`.
4. Using a view-role authenticated `client.Get("/v2/external_initiators")`, assert response status.
   - Expected (secure): `403 Forbidden` (or credential fields redacted/empty).
   - Actual (current code): `200 OK` with `externalInitiators[0].AccessKey` and `.OutgoingToken` populated with the real secret values, as already demonstrated (for an admin-equivalent default test client) in the existing `TestExternalInitiatorsController_Index` at lines 108-109/125-126 of `core/web/external_initiators_controller_test.go`, which never varies the caller's role.
5. Add a role-parameterized variant of `TestExternalInitiatorsController_Index` that runs the same request with a `view`-role client and asserts it is blocked or the secret fields are empty — this variant currently fails against the code as written.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {

	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
