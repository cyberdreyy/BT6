### Title
Uncontrolled recursion in `TrieNode::decode` allows stack-overflow denial of service in the fault-proof program - ([File: crates/proof/mpt/src/node.rs])

### Summary
`TrieNode`'s RLP `Decodable` implementation recursively decodes nested Extension nodes with no depth limit, unlike other untrusted-input parsers in the same codebase (e.g. the CBOR attestation parser, which explicitly enforces `MAX_CBOR_NESTING_DEPTH`). This trie node decoder is the core preimage-parsing primitive used by the fault-proof program (`base-proof-mpt`, `base-proof-proof`) to interpret L1/L2 state, account, transaction and receipt trie preimages fetched via the untrusted preimage oracle during dispute-game execution.

### Finding Description
`TrieNode::decode` recognizes a 2-item RLP list as either a `Leaf` or an `Extension` node and, for the extension case, immediately recurses into `Self::decode(buf)` on the *same* buffer to parse the embedded pointer node: [1](#0-0) 

There is no depth counter or nesting limit anywhere in this decode path (contrast with the depth-guarded CBOR parser elsewhere in the repo: [2](#0-1) ). The size/blinding invariant that normally keeps real trie nodes small (nodes ≥32 bytes are blinded to a hash reference on *encode*) is only enforced by the `Encodable` implementation, not by `Decodable`: [3](#0-2) 

Because `Decodable::decode` trusts whatever bytes are handed to it, an attacker can hand-craft a single RLP blob consisting of a long, flat chain of minimal Extension-node headers (each just a few bytes) that is never actually blinded internally. Decoding this one blob drives `TrieNode::decode` → `try_decode_leaf_or_extension_payload` → `Self::decode` recursion thousands of levels deep in a single call, with recursion depth bounded only by the size of the attacker-supplied buffer, not by any protocol-level trie-depth invariant.

This decoder is the trie-node parsing primitive used throughout the fault-proof program whenever a preimage is fetched by hash, both for L1 and L2 chain state: [4](#0-3) [5](#0-4) 

and in the on-disk/test providers used by the executor: [6](#0-5) 

Preimage integrity is checked only as `keccak256(data) == requested_key` (see the host handler), which does not constrain the internal shape of `data` beyond hash-preimage correspondence: [7](#0-6) 

`fetch_leaves`/`open`/`insert`/`delete`/`unblind` in the same crate are likewise plain, unbounded recursive traversals over `TrieNode`, compounding the risk once a maliciously deep structure is decoded: [8](#0-7) 

### Impact Explanation
The fault-proof program (`base-proof-proof`/`op-program`-equivalent) is the component that computes/validates the output root used in Base's dispute game. If it can be crashed via stack overflow while processing a preimage during dispute execution, an unrecoverable program halt occurs mid-proof — this can prevent the fault-proof VM from producing a valid provable output root, directly undermining the correctness/liveness of the dispute-resolution mechanism (`node halt` / `wrong provable output root` class of impact).

### Likelihood Explanation
Reaching this code path requires the fault-proof program to decode a trie-node preimage whose bytes are attacker-influenced. In an active dispute game, a dispute participant controls which claims/witnesses get executed and, depending on how state proof witnesses are supplied to the offline execution environment, can attempt to route a maliciously shaped preimage blob into `TrieNode::decode`. The lack of any depth guard means the DoS trigger requires no cryptographic break — only a self-consistent (hash-matching) blob shaped as a long extension-node chain, which is trivial to construct.

### Recommendation
Add an explicit nesting/depth bound (mirroring `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`) to `TrieNode::decode`/`try_decode_leaf_or_extension_payload`, rejecting RLP blobs whose embedded (non-blinded) node depth exceeds a small constant (real Ethereum tries never need in-buffer nesting beyond a couple of levels since nodes ≥32 bytes must be blinded). Alternatively, convert the recursive decode/traversal routines (`decode`, `open`, `insert`, `delete`, `fetch_leaves`) to an explicit iterative/worklist algorithm to remove reliance on call-stack depth entirely.

### Proof of Concept
1. Construct bytes representing a chain of N nested RLP 2-item lists, each with a valid `PREFIX_EXTENSION_EVEN`-tagged path byte and pointing (unblinded, i.e., inline rather than via a 32-byte hash) to the next nested list, terminated by a small `Leaf`.
2. Compute `hash = keccak256(bytes)`.
3. Have the party controlling preimage responses (e.g., the fault-dispute preimage oracle server) serve `bytes` for `hash` when requested by `OracleL1ChainProvider::trie_node_by_hash` / `OracleL2ChainProvider::trie_node_by_hash`.
4. When the fault-proof program calls `TrieNode::decode(&mut bytes)` on the fetched preimage, the recursive `Self::decode` calls in `try_decode_leaf_or_extension_payload` recurse N times in a single stack, overflowing the process stack once N is large enough (achievable with a preimage of a few hundred KB, since each nesting level costs only a few bytes of header). impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
