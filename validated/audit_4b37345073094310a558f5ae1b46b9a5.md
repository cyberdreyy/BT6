### Title
Aggregating peer signatures into a broadcastable group signature bypasses the pre-signature chainstate/conflict re-check - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`store_and_process_block_signature` — the code path that tallies *other signers'* accept signatures toward the group threshold and, once ≥70% weight is reached, marks the block locally-accepted-by-group and pushes it to the node — does not re-run the chainstate/conflict safety checks (`check_block_against_signer_db_state`, `get_signed_conflicts`/`conflict_still_blocks`, `reorg_permit_stands`) that the sibling code path `handle_block_pre_commit` explicitly performs immediately before this signer signs a block.

### Finding Description
The docs and code establish a clear invariant for *this* signer's act of putting a signature on a block: between crossing the pre-commit threshold and actually signing, the signer must re-check chainstate state and conflicting signed blocks, because "the world" may have moved on (docs/signer-flows.md §5, `handle_block_pre_commit`, stacks-signer/src/v0/signer.rs:1340–1421): [1](#0-0) 

That re-check is explicitly comment-justified: "the chain and signer db state may have changed materially since this block passed the proposal-time checks... Re-run the chainstate checks before putting a signature over the block."

However, the code path that assembles *other signers'* accept signatures and pushes the aggregated, fully-signed block to the stacks-node (`store_and_process_block_signature`) performs none of these checks: [2](#0-1) 

It only checks:
- whether the signature is already stored (`add_block_signature` dedup),
- whether it should instead be treated as a late pre-commit (`has_committed`),
- whether `signed_group` is already set,
- the aggregate signature weight vs. threshold.

It never re-verifies `block_info.valid`, never calls `check_block_against_signer_db_state`, and never checks for fresher/conflicting signed siblings at the same or higher block height in another tenure (the very guard that `handle_block_pre_commit` added specifically because "between validation and threshold, we may have signed a different block at the same height, possibly in another tenure"). Once the threshold of *stored* signatures (which can include stale ones collected well before this signer's own view advanced) is met, it unconditionally calls `mark_locally_accepted(true)` and `broadcast_signed_block`, pushing the assembled signature set straight to the node's `/v3/blocks` acceptance path.

This breaks the equality the codebase otherwise enforces everywhere else: "a signature must not be superseded while it's still fresh" / "the world must be re-checked before the signature leaves the box" (docs/signer-flows.md §5). Here the signature doesn't "leave the box" via this signer's own signing decision — it leaves via aggregation of already-collected peer signatures — and that exit door has no re-check gate at all.

### Impact Explanation
This maps to the report's "signer signing/endorsing an invalid, non-canonical, or conflicting block" impact class. A signer can end up broadcasting to its node a fully-signed (from its perspective, "locally accepted with group threshold") block that it would refuse to sign or pre-commit to if it were re-evaluated at that exact moment (e.g., it has since locally rejected that hash, or has since signed a conflicting sibling at the same/higher height in another tenure per `get_signed_conflicts`). Because `broadcast_signed_block`/`handle_post_block` submits the aggregated signature set to the node, this can cause the node to accept a block the signer's own up-to-date chainstate view says is now stale/conflicting — the acceptance-vs-validated equality is broken without requiring a majority of malicious signers (the majority-honest signatures are legitimate and old; only the timing/ordering is exploited by a single miner or slow gossip).

### Likelihood Explanation
Reachable by a single miner (or ordinary network delay/gossip skew) without needing another signer's key or a signer majority: (1) miner proposes block B at height h; several signers pre-commit and sign it early; this signer also pre-commits but hasn't yet crossed threshold; (2) before threshold is met, a reorg or a competing tenure-start block causes this signer to sign a conflicting block B' at the same height h (a legitimate, already-supported scenario per the `get_signed_conflicts`/`conflict_still_blocks` machinery); (3) the remaining peer `BlockResponse::Accepted` messages for B trickle in and push the stored signature weight for B over threshold via `handle_block_response` → `handle_block_signature` → `store_and_process_block_signature`, which has no gate checking that B is still consistent with this signer's now-updated DB state. This requires only ordinary asynchronous delivery timing, not a malicious majority.

### Recommendation
Before calling `mark_locally_accepted(true)` and `broadcast_signed_block` in `store_and_process_block_signature`, re-run the same safety gate used in `handle_block_pre_commit`: call `check_block_against_signer_db_state` and the fresh-conflict check (`get_signed_conflicts` + `reorg_permit_stands` + `conflict_still_blocks`) against `block_info.block`, and reject/skip broadcasting if either fails, mirroring the rejection handling already implemented in `handle_block_pre_commit` (stacks-signer/src/v0/signer.rs:1340–1421).

### Proof of Concept
Conceptual PoC (requires only a single miner producing two conflicting blocks at the same height plus ordinary network delay, no colluding signer majority):
1. Miner proposes block B (tenure T, height h). All signers pre-commit; several immediately sign and broadcast `BlockResponse::Accepted(B)`. Operating signer S also pre-commits to B but has not yet reached the 70% threshold (e.g., it is waiting on 1-2 more pre-commits) — see the multi-signer test pattern in `stacks-node/src/tests/signer/v0/mod.rs:9049-9147` for how partial pre-commit/acceptance rollout is exercised.
2. A Bitcoin/Stacks reorg (or a second miner tenure) causes a new tenure-change block B' at height h to be proposed and to pass `check_proposal`/`check_block_against_signer_db_state` for S at this later time (S's own recorded canonical view has moved). S signs B' via the normal `handle_block_pre_commit` → `mark_locally_accepted` path (stacks-signer/src/v0/signer.rs:1250-1421), which is exactly the fresh-conflict-aware path.
3. The delayed `BlockResponse::Accepted(B)` messages from the other signers (step 1) now arrive and are processed by `handle_block_response` → `handle_block_signature` → `store_and_process_block_signature` (stacks-signer/src/v0/signer.rs:2442-2538). Because S already has a pre-commit recorded for B (`has_committed` true) and the aggregate stored signature weight for B now crosses threshold, S calls `mark_locally_accepted(true)` and `broadcast_signed_block(B)` — pushing B to the node — even though S's own state (and the fact that it just signed the conflicting B') would have caused `check_block_against_signer_db_state`/`get_signed_conflicts` to reject B had that same gate been re-run here.

Note: I was unable to execute this scenario in a live/integration test within this session (no filesystem/terminal access in ask-only mode); the PoC is derived from static analysis of the two divergent code paths (`handle_block_pre_commit` vs. `store_and_process_block_signature`) and the documented invariant in `docs/signer-flows.md` §5.     /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }
