## Title
Operator commission can be redirected to a successor operator after `switch_operator` due to stale distribution-pool shares being re-taxed - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract.move` uses a shared `pool_u64` `distribution_pool` to track both pending staker withdrawals and pending operator commission that has been unlocked from the stake pool but has not yet fully inactivated/become withdrawable. `update_distribution_pool` re-taxes appreciation of every shareholder in that pool *except the address passed in as `operator`* [1](#0-0) . Because the "current operator" is looked up fresh on every call (via the staking contract's live `operator` field/key), a former operator's still-unpaid, still-appreciating commission shares are no longer exempt once `switch_operator`/`switch_operator_with_same_commission` reassigns the contract to a new operator [2](#0-1) . Any later `distribute_internal`/`add_distribution` call taxes the old operator's pending share at the new operator's commission rate and credits the difference to the new operator.

### Finding Description
Commission accounting works as follows:
- `request_commission_internal` unlocks commission from the stake pool and creates a distribution-pool share for the operator address via `add_distribution` [3](#0-2) .
- `add_distribution` calls `update_distribution_pool` with the *current* `operator` and `commission_percentage` before buying in new shares [4](#0-3) .
- `update_distribution_pool` re-prices the whole pool to `updated_total_coins` and, for **every shareholder other than the passed-in `operator`**, skims `(current_worth - previous_worth) * commission_percentage / 100` from that shareholder's shares and transfers it to `operator` [1](#0-0) .
- This function is invoked from `distribute_internal` (called at the top of `unlock_stake`, `request_commission`, `switch_operator`, `update_commision`, and the public `distribute()`), always passing the *current* operator/commission rate of the staking contract [5](#0-4) .

`switch_operator` finalizes the outgoing operator's commission (`distribute_internal` + `request_commission_internal` for `old_operator`) and then reassigns the same `StakingContract` (including its `distribution_pool`) to `new_operator` with a possibly different `commission_percentage` [6](#0-5) . If the freshly-settled commission for `old_operator` is still pending_inactive on the stake pool (lockup not yet expired), its balance keeps growing with staking rewards while it sits in `distribution_pool`. Because `old_operator` is no longer the `operator` value passed into `update_distribution_pool` after the switch, any future call that re-prices the pool (e.g., the staker calling `unlock_stake`, the new operator calling `request_commission`, or anyone calling permissionless `distribute()`) treats the reward growth on `old_operator`'s balance as if it were an ordinary staker reward and taxes it at `new_commission_percentage`, transferring the skimmed amount to `new_operator` [7](#0-6) .

This is the direct structural analog of the LPP report's root cause: a shared timing/accounting mechanism (`CLOCK_EXTENSION`/challenge window in Optimism; the exemption-by-address check in `update_distribution_pool` here) silently stops protecting the party it was designed to protect once a role boundary shifts (operator handoff here; clock ownership swap there), letting a third party (the successor operator) capture value that rightfully belongs to the original party (the outgoing operator).

### Impact Explanation
This falls squarely under "Operator commission ... share-accounting corruption that credits the wrong account" in the required impacts. A staker (who fully controls when `switch_operator` is called, an ordinary unprivileged action) or a colluding new operator can capture part of the outgoing operator's already-earned but not-yet-withdrawn commission simply by ensuring any distribution-pool-touching call happens before the outgoing operator calls `distribute()`. The stolen amount scales with the size of the outgoing operator's pending commission and the reward rate/duration it sits unpaid in the pool, and can recur every lockup cycle since the same shares model is reused. There is no cap and no re-entrancy needed — it's a straightforward accounting flaw reachable with standard entry functions.

### Likelihood Explanation
High likelihood: `switch_operator`/`switch_operator_with_same_commission` and `unlock_stake`/`request_commission`/`distribute` are all standard, frequently-used, permissionless (staker/operator/anyone-for-distribute) entry points. No special timing precision or race condition is required beyond ordinary transaction ordering: a staker (or new operator) simply needs to trigger one more `distribution_pool`-touching call before the old operator withdraws — which is easy to arrange deliberately, and can also occur unintentionally in normal operation whenever an operator switch precedes further staking-contract activity within the same lockup cycle.

### Recommendation
Track exemption from commission taxation by *distribution epoch/ownership* rather than by "current operator address." Concretely: when settling a distribution as `add_distribution(operator, ..., operator, commission_amount)`, tag that share as "commission, exempt from further taxation" (e.g., using a dedicated flag/map or a per-share "already-commission" set) so subsequent `update_distribution_pool` calls skip taxing it regardless of whether the current operator address later changes. Alternatively, force a full `distribute()` payout of any existing operator commission shares as part of `switch_operator` (rather than merely calling `request_commission_internal`, which only *records* a share, without paying out) so no stale operator-owned shares can persist in the pool across an operator change.

### Proof of Concept
1. Staker `S` creates a staking contract with operator `O1`, commission 10%; `O1`'s validator earns rewards.
2. `O1` calls `request_commission`, which unlocks commission `C` from the stake pool and creates a distribution-pool share for `O1` worth `C` (still pending_inactive, lockup not yet expired) [8](#0-7) .
3. Before the lockup expires, `S` calls `switch_operator(O1, O2, new_commission_percentage=50)`. This runs `distribute_internal`+`request_commission_internal` for `O1` (finalizing `O1`'s current commission share `C`), then reassigns the `StakingContract` (with the same `distribution_pool` still holding `O1`'s share `C`) to `O2` at 50% commission [9](#0-8) .
4. While still within the same (unexpired) lockup, the pending_inactive stake underlying the pool continues to earn staking rewards, growing the pool's `total_distribution_amount`.
5. `S` calls `unlock_stake(O2, amount)` or `O2` calls `request_commission`. This triggers `distribute_internal`→`update_distribution_pool(distribution_pool, updated_total_coins, O2, 50)`. Since `O1 != O2`, the appreciation on `O1`'s balance `C` since step 3 is taxed at 50% and transferred to `O2`'s shares [7](#0-6) .
6. When `O1` eventually calls `distribute()` to claim their commission, they receive less than `C` plus rightful rewards — a portion has already been redirected to `O2`, who did not earn it.

Note: I traced this end-to-end through the `staking_contract.move` source and confirmed the call chain (`switch_operator` → `request_commission_internal` → `add_distribution` → `update_distribution_pool`, and `distribute_internal` → `update_distribution_pool` → payout loop), but I did not find or run an existing unit test in the repository that specifically exercises "operator switch followed by further reward accrual and a third-party distribution-pool call" to empirically confirm the exact numeric skim amount; this should be validated with a Move unit test (e.g., extending `test_staking_contract`-style tests) before remediation.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Allows staker to switch operator without going through the lenghthy process to unstake.
    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    /// Add a new distribution for `recipient` and `amount` to the staking contract's distributions list.
    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
