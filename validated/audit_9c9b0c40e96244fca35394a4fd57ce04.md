### Title
Funded instant-withdraw claims are never removed from `instantWithdrawClaimsByEpoch`, inflating default-recovery price and draining the recovery reserve - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
The kernel bug leaks `random_seq` on an error/cleanup path of `kmem_cache_open()`. The analog in `IdleCreditVault` is a state leak on the *successful* instant-withdraw cleanup path: `requestInstantWithdraw` increments the per-epoch aggregate `instantWithdrawClaimsByEpoch[epoch]` [1](#0-0) , but neither `collectInstantWithdrawFunds` nor `claimInstantWithdrawRequest` ever decrements it [2](#0-1) . It is only decremented on the *defaulted* claim path [3](#0-2) . At default finalization, `_defaultPrefundedInstantReserve` treats `instantWithdrawClaimsByEpoch[epochNumber] - pendingInstantWithdraws` as underlying still held in the strategy [4](#0-3) , so funds that were already paid out to users are double-counted in `defaultRecoveryReserve`, inflating `defaultRecoveryPrice` [5](#0-4) .

### Finding Description
Sequence in one epoch (running phase, instant mode):

1. Attacker (any tranche holder) calls `requestWithdraw`-style instant flow: `requestInstantWithdraw(_amount)` mints a receipt and does `instantWithdrawClaimsByEpoch[currentEpoch] += _amount` and `pendingInstantWithdraws += _amount` [6](#0-5) .
2. Honest owner/manager calls `getInstantWithdrawFunds`; the strategy pulls the funded amount via `collectInstantWithdrawFunds`, which decrements `pendingInstantWithdraws` but leaves `instantWithdrawClaimsByEpoch` untouched [7](#0-6) .
3. Attacker calls `claimInstantWithdrawRequest`, which burns the receipt, zeroes `instantWithdrawsRequests[_user]`, and transfers the underlying out via `_transferFundedClaim` — again without touching `instantWithdrawClaimsByEpoch` or `instantWithdrawsRequestsByEpoch` [8](#0-7) .
4. The borrower fails to repay and the epoch defaults in the same `epochNumber`. `finalizeDefaultRecovery` runs: `pendingInstantWithdraws` is now 0 (or reduced), while `instantWithdrawClaimsByEpoch[epochNumber]` still contains the already-paid amount, so `prefundedReserve` counts tokens that have already left the contract [9](#0-8) .
5. `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` is therefore overstated. Every subsequent defaulted claim via `_claimDefaultedWithdrawRequest`/`_claimDefaultedInstantWithdrawRequest` is paid `claimBasis * defaultRecoveryPrice / RECOVERY_FULL` from `_transferDefaultRecovery` [10](#0-9) .

Broken invariant: solvency / one-receipt-one-payout. The ghost "prefunded reserve" makes total defaulted claims exceed actual underlying held, so early claimers (the attacker, who can also hold a normal withdraw receipt in the default epoch) are paid an inflated share and later claimants' transfers revert — permanent freezing of their recovery.

### Impact Explanation
Any instant withdrawal funded and claimed in the same epoch as a borrower default creates phantom reserve equal to the claimed amount. `defaultRecoveryPrice` rises above the true reserve/basis ratio, so early claimers extract more than their fair share of recovery funds and the tail of claimants can never be paid (their `safeTransfer` reverts on insufficient balance). Loss magnitude scales with the size of same-epoch funded instant withdrawals, up to the full inflated fraction of the recovery pool.

### Likelihood Explanation
Requires: instant withdrawals enabled (a supported mode), a funded+claimed instant withdrawal in the same epoch, and a borrower default before `epochNumber` advances. Instant withdrawals and borrower defaults are both normal protocol events; no privileged misbehavior is needed — owner/manager calls are sequenced honestly. The stale-ledger condition is deterministic once the ordering occurs.

### Recommendation
Decrement the aggregate claim basis when the claim is settled on the funded path: in `claimInstantWithdrawRequest` (or in `collectInstantWithdrawFunds`) reduce `instantWithdrawClaimsByEpoch[epochOfRequest]` and clear `instantWithdrawsRequestsByEpoch[_user][epoch]`, mirroring the cleanup done in `_claimDefaultedInstantWithdrawRequest`. Alternatively, compute `_defaultPrefundedInstantReserve` only from still-outstanding per-user epoch entries.

### Proof of Concept
Foundry fork PoC (sketch, on a mainnet fork with an instantiated `IdleCreditVault`/`IdleCDOEpochVariant`):

```solidity
// Setup: deposit as user into AA tranche, startEpoch(), enable instant withdraws.
// Attacker also holds a normal pending withdraw receipt for the same epoch.

// 1. Epoch N running: attacker requests instant withdraw
vm.prank(attacker);
cdo.requestInstantWithdraw(amount); // instantWithdrawClaimsByEpoch[N] += amount

// 2. Manager funds it, then attacker claims — underlying leaves the strategy
vm.prank(manager);
cdo.getInstantWithdrawFunds(amount);
vm.prank(attacker);
cdo.claimInstantWithdrawRequest();
assertEq(strategy.pendingInstantWithdraws(), 0);
assertEq(strategy.instantWithdrawClaimsByEpoch(N), amount); // STALE — never cleared

// 3. Borrower defaults in epoch N; finalizeDefaultRecovery
//    prefundedReserve = amount (phantom), inflating defaultRecoveryPrice
vm.prank(manager);
cdo.stopEpoch(0, 0); // triggers _handleBorrowerDefault -> finalizeDefaultRecovery(...)
uint256 price = strategy.defaultRecoveryPrice();
assertGt(price, trueReserve * RECOVERY_FULL / totalBasis); // inflated

// 4. Attacker claims defaulted receipt first at inflated price;
//    victim's later claim reverts on insufficient underlying balance
vm.prank(attacker);
cdo.claimWithdrawRequest(); // succeeds, overpaid
vm.prank(victim);
vm.expectRevert();
cdo.claimWithdrawRequest(); // reserve drained by phantom claims
```

```text
    _onlyIdleCDO();

    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"

    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
```

```text
  function claimInstantWithdrawRequest(address _user) external {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized && defaultInstantWithdrawsFinalized) {
      // Clear the defaulted-epoch instant receipt first, then continue so the same call can
      // also pay any older instant receipt that was already funded before default finalization.
      _claimDefaultedInstantWithdrawRequest(_user);
    }
    uint256 amount = instantWithdrawsRequests[_user];
    // burn strategy tokens from user
    _burn(_user, amount);

    instantWithdrawsRequests[_user] = 0;
    _transferFundedClaim(_user, amount);
  }

  /// @notice collect the instant withdraw funds
  /// @dev only IdleCDO can call this function
  /// @param _amount number of tokens to collect
  function collectInstantWithdrawFunds(uint256 _amount) external {
    _onlyIdleCDO();
    if (_amount == 0) return;
    pendingInstantWithdraws -= _amount;
    underlyingToken.safeTransferFrom(idleCDO, address(this), _amount);
```

```text
  /// @notice Get current-epoch instant-withdraw funds already collected before default finalization.
  /// @dev `pendingInstantWithdraws` is the still-unfunded remainder. If it is lower than the
  /// current-epoch claim basis, the difference is already-held underlying reserved for those claims.
  /// @return prefundedReserve amount of current instant claims already backed by strategy underlyings
  function _defaultPrefundedInstantReserve() internal view returns (uint256 prefundedReserve) {
    uint256 pendingInstant = pendingInstantWithdraws;
    if (pendingInstant == 0) return prefundedReserve;
    uint256 instantBasis = instantWithdrawClaimsByEpoch[epochNumber];
    if (instantBasis > pendingInstant) {
      prefundedReserve = instantBasis - pendingInstant;
    }
  }
```

```text
  function _claimDefaultedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, defaultEpoch, true);
    if (claimBasis == 0) return amount;

    // pendingWithdraws stores the claim basis owed by the borrower, including APR0 interest.
    pendingWithdraws -= claimBasis;
    // Only receipt principal exists as strategy tokens. APR0 interest is included in claimBasis
    // but was never minted as a user strategy-token receipt.
    _burn(_user, burnAmount);
    amount = (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL;
    _transferDefaultRecovery(_user, amount);
```
