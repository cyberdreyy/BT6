### Title
`cleanup_stale_signers` drops a `ConfiguredSigner` whose `BlockInfo` is `PreCommitted` (not yet `GloballyAccepted`/`GloballyRejected`), permanently orphaning that signer's final vote - ([File: stacks-signer/src/runloop.rs])

### Summary
`RunLoop::cleanup_stale_signers` decides whether to delete a stale `ConfiguredSigner` by calling `Signer::has_unprocessed_blocks`, which only checks for `BlockState::Unprocessed` rows in `signerdb.rs`. It does not treat `PreCommitted`, `LocallyAccepted`, or `LocallyRejected` (all non-terminal states) as "still busy," so a signer that has validated and pre-committed to a block but hasn't yet reached the group signature threshold can be deleted from `self.stacks_signers` the moment the reward cycle rolls over, permanently stopping it from ever processing further pre-commit/signature gossip for that block.

### Finding Description
The broken invariant: every `BlockInfo` that reached `BlockState::PreCommitted` must have a bounded path to `LocallyAccepted`/`LocallyRejected` (and ultimately a global state) *before* its owning `ConfiguredSigner` can be removed from `RunLoop::stacks_signers`.

The guard that is supposed to enforce this is `has_unprocessed_blocks`: [1](#0-0) 
This query filters strictly on `state = Unprocessed`. `PreCommitted` is a distinct enum value (`BlockState::PreCommitted = 5`, separate from `Unprocessed = 0`): [2](#0-1) 
and the unit test for this function confirms the semantics: once every tracked block for the cycle has moved out of `Unprocessed` (into e.g. `LocallyRejected`/`LocallyAccepted`), `has_unprocessed_blocks` returns `false`, even though the blocks have not reached a *global* terminal state: [3](#0-2) 

The `v0` signer wraps this directly with no additional check for `PreCommitted`/`LocallyAccepted`/`LocallyRejected`: [4](#0-3) 

`RunLoop::cleanup_stale_signers` uses exactly this signal to decide deletion, on every `refresh_runloop` pass (i.e., on every `NewBurnBlock` event once the reward cycle advances): [5](#0-4) [6](#0-5) 

Once a `ConfiguredSigner` entry for a reward cycle is removed from the `HashMap<u64, ConfiguredSigner<..>>` (keyed by `reward_cycle % 2`), the `RunLoop` never resurrects a signer for that past cycle - `refresh_signer_config` is only ever called for `current_reward_cycle` and `next_reward_cycle`. The dispatch loop in `run_one_pass` only iterates `self.stacks_signers.values_mut()`, so any subsequent StackerDB gossip (`BlockPreCommit`, `BlockResponse`/signature messages) for that reward cycle is simply never delivered to a live `Signer` instance again: [7](#0-6) 

Persisting `BlockInfo` to `signerdb.rs` (`insert_block`) does not help here, because there is no mechanism that reconstructs a `ConfiguredSigner`/`Signer` for a *past* reward cycle to resume reading that persisted state - persistence protects against process *restart*, not against the live in-memory dispatcher being torn down while the cycle is still owned by "stale" bookkeeping.

Exploit flow: a miner (single slot) proposes the final block of a tenure timed so that, by the time the reward-cycle boundary is crossed (a deterministic, publicly known burn height), this particular signer has validated and pre-committed to the block (`mark_pre_committed`, state `PreCommitted`) but the group signature/pre-commit weight threshold has not yet been reached (e.g., because other signers are slower to gossip their votes). On the very next `NewBurnBlock` event, `refresh_runloop` recomputes `current_reward_cycle` as the new cycle, and `cleanup_stale_signers(current_reward_cycle)` sees the old signer's `reward_cycle() < current_reward_cycle`; `has_unprocessed_blocks()` returns `false` (the block already moved off `Unprocessed`), so the `ConfiguredSigner` is deleted. All further `BlockPreCommit`/signature gossip for that block from other signers is now unreachable for this signer's weight share; it can never call `mark_locally_accepted`/emit its final signature.

Why existing guards fail: `has_unprocessed_blocks` was clearly intended as the "don't delete a busy signer" guard, but its underlying SQL predicate only recognizes the initial `Unprocessed` state and misses every intermediate non-terminal state (`PreCommitted`, `LocallyAccepted`, `LocallyRejected`) that still requires the live `Signer`/`ConfiguredSigner` to keep processing incoming votes.

### Impact Explanation
This is a bounded-liveness violation (High): a signer that already agreed to sign a valid, node-validated block (reached `PreCommitted`) is wedged and never contributes its weight share toward the 70% signature threshold, because its `ConfiguredSigner` was torn down while the block was still in-flight. If that signer's weight was needed to cross the threshold, the tenure stalls indefinitely for that share (it never times out and retries, because the retry/timeout logic lives inside the now-deleted `Signer` instance). This is repeatable at every reward-cycle boundary where any signer's local pre-commit hasn't yet been resolved.

### Likelihood Explanation
Preconditions: (1) a block proposal whose validation/pre-commit aggregation is still outstanding on at least one signer's node when that signer's own view of the burn height crosses into the next reward cycle, and (2) that signer's node processing a `NewBurnBlock` event that triggers `refresh_runloop`/`cleanup_stale_signers` before the block resolves. The attacker only needs to win a miner slot and time a block proposal (a naturally available capability - proposal timing near reward-cycle boundaries is public knowledge since `reward_cycle_length`/`first_burnchain_block_height` are known), no majority-signer collusion, no node access, and no auth token. It does not depend on falsifying `burn_height` (that data comes from the node's own `get_peer_info()`/event stream and is out of scope to forge); the natural cycle-boundary crossing combined with the attacker's proposal timing is sufficient. This is repeatable every reward cycle.

### Recommendation
Fix `has_unprocessed_blocks` (or add a companion check used by `cleanup_stale_signers`) to also treat any `BlockInfo` in `PreCommitted`, `LocallyAccepted`, or `LocallyRejected` state as "still pending" - i.e., query for any block in the reward cycle whose state is not `GloballyAccepted`/`GloballyRejected`. Only delete a `ConfiguredSigner` once every tracked `BlockInfo` for its reward cycle has reached a terminal global state.

### Proof of Concept
Rust test plan (in `stacks-signer/src/runloop.rs` or a new test in `stacks-signer/src/v0/tests.rs` driving the runloop directly):
1. Construct a `RunLoop` with a mock `StacksClient`/`Signer` for reward cycle `N`.
2. Insert into that signer's `signerdb.rs` a `BlockInfo` with `state = BlockState::PreCommitted` (via `mark_pre_committed`/`insert_block`) for reward cycle `N`, simulating validation succeeded but signature threshold not yet met.
3. Assert `signer.has_unprocessed_blocks()` returns `false` (demonstrating the gap) even though the block is not in a terminal global state (`block_info.state != GloballyAccepted && block_info.state != GloballyRejected`).
4. Advance `current_reward_cycle_info` past `N` and call `refresh_runloop`/`cleanup_stale_signers(N+1)` directly.
5. Assert `self.stacks_signers` no longer contains the entry for cycle `N` (bug reproduced).
6. Feed a subsequent `SignerEvent` containing a `BlockPreCommit`/signature message for that same `signer_signature_hash` from another signer that would have pushed the block over threshold, and assert the block's `BlockInfo` in signerdb is never advanced to `LocallyAccepted`/`GloballyAccepted` (wedge confirmed - no live `Signer` instance ever consumes the event).
7. Apply the recommended fix to `has_unprocessed_blocks` (or the cleanup gate) and re-run steps 3-6, asserting the `ConfiguredSigner` for cycle `N` survives until the `BlockInfo` reaches a terminal global state, and that the deferred pre-commit/signature event is then correctly processed.

        let current_burn_block_height = std::cmp::max(
            self.stacks_client.get_peer_info()?.burn_block_height,
            ev_burn_block_height,
        );
        let reward_cycle_info = self
            .current_reward_cycle_info
            .as_mut()
            .expect("FATAL: cannot be an initialized signer with no reward cycle info.");
        let current_reward_cycle = reward_cycle_info.reward_cycle;
        let block_reward_cycle = reward_cycle_info.get_reward_cycle(current_burn_block_height);

        // First ensure we refresh our view of the current reward cycle information
        if block_reward_cycle != current_reward_cycle {
            let new_reward_cycle_info = RewardCycleInfo {
                reward_cycle: block_reward_cycle,
                reward_cycle_length: reward_cycle_info.reward_cycle_length,
                prepare_phase_block_length: reward_cycle_info.prepare_phase_block_length,
                first_burnchain_block_height: reward_cycle_info.first_burnchain_block_height,
                last_burnchain_block_height: current_burn_block_height,
            };
            *reward_cycle_info = new_reward_cycle_info;
        }
        let reward_cycle_before_refresh = current_reward_cycle;
        let current_reward_cycle = reward_cycle_info.reward_cycle;
        let is_in_next_prepare_phase =
            reward_cycle_info.is_in_next_prepare_phase(current_burn_block_height);
        let next_reward_cycle = current_reward_cycle.saturating_add(1);

        info!(
            "Refreshing runloop with new burn block event";
            "latest_node_burn_ht" => current_burn_block_height,
            "event_ht" =>  ev_burn_block_height,
            "reward_cycle_before_refresh" => reward_cycle_before_refresh,
            "current_reward_cycle" => current_reward_cycle,
            "configured_for_current" => Self::is_configured_for_cycle(&self.stacks_signers, current_reward_cycle),
            "registered_for_current" => Self::is_registered_for_cycle(&self.stacks_signers, current_reward_cycle),
            "configured_for_next" => Self::is_configured_for_cycle(&self.stacks_signers, next_reward_cycle),
            "registered_for_next" => Self::is_registered_for_cycle(&self.stacks_signers, next_reward_cycle),
            "is_in_next_prepare_phase" => is_in_next_prepare_phase,
        );

        // Check if we need to refresh the signers:
        //   need to refresh the current signer if we are not configured for the current reward cycle
        //   need to refresh the next signer if we're not configured for the next reward cycle, and we're in the prepare phase
        if !Self::is_configured_for_cycle(&self.stacks_signers, current_reward_cycle) {
            self.refresh_signer_config(current_reward_cycle);
        }
        if is_in_next_prepare_phase
            && !Self::is_configured_for_cycle(&self.stacks_signers, next_reward_cycle)
        {
            self.refresh_signer_config(next_reward_cycle);
        }

        self.cleanup_stale_signers(current_reward_cycle);
        if self.stacks_signers.is_empty() {
            self.state = State::NoRegisteredSigners;
        } else {
            self.state = State::RegisteredSigners;
        }
        Ok(())
    }

    fn cleanup_stale_signers(&mut self, current_reward_cycle: u64) {
        #[cfg(any(test, feature = "testing"))]
        if TEST_SKIP_SIGNER_CLEANUP.get() {
            warn!("Skipping signer cleanup due to testing directive.");
            return;
        }
        let mut to_delete = Vec::new();
        for (idx, signer) in &mut self.stacks_signers {
            let reward_cycle = signer.reward_cycle();
            if reward_cycle >= current_reward_cycle {
                // We are either the current or a future reward cycle, so we are not stale.
                continue;
            }
            match signer {
                ConfiguredSigner::RegisteredSigner(signer) => {
                    if !signer.has_unprocessed_blocks() {
                        debug!("{signer}: Signer's tenure has completed.");
                        to_delete.push(*idx);
                    }
                }
                ConfiguredSigner::NotRegistered { .. } => {
                    debug!("{signer}: Unregistered signer's tenure has completed.");
                    to_delete.push(*idx);
                }
            }
        }
        for idx in to_delete {
            self.stacks_signers.remove(&idx);
        }
    }
