### Title
`ExternalInitiatorsController.Index` exposes external-initiator `accessKey`/`outgoingToken` to view-role users due to missing role wrapper - ([File: core/web/router.go])

### Summary
`GET /v2/external_initiators` is registered as `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` with no `auth.RequiresEditRole`/`auth.RequiresRunRole` wrapper, unlike the sibling `Create`/`Destroy` routes on the same resource. Any session authenticated at any role (including `UserRoleView`) or a valid API token can therefore call `Index` and receive every external initiator's `name`, `url`, `accessKey`, and `outgoingToken` unredacted.

### Finding Description
The route table in `core/web/router.go` wraps `Create` and `Destroy` in `auth.RequiresEditRole`, but `Index` is only inside the generic `authv2` group, which requires authentication (session or token) but no minimum role: [1](#0-0) 

`ExternalInitiatorsController.Index` calls `BridgeORM().ExternalInitiators` and serializes every row with `presenters.NewExternalInitiatorResource`, with no per-role filtering or redaction: [2](#0-1) 

The presenter includes `AccessKey` and `OutgoingToken` in plaintext in the JSON response body: [3](#0-2) 

`AccessKey`/`OutgoingToken` are credential material generated at `Create` time (paired with a `Secret`/`OutgoingSecret` used for HMAC signing of webhook requests) and are only meant to be revealed once, at creation, via `NewExternalInitiatorAuthentication`. Because `Index` has no role gate, a session authenticated only as `UserRoleView` (or any restricted API token) can list this credential metadata for all external initiators registered on the node, which the `Create`/`Destroy` role gating implies should be restricted to edit-or-above roles.

### Impact Explanation
This is a role-boundary/information-disclosure bug: it allows the lowest-privileged authenticated role to enumerate external-initiator inventory and partial credential material (`accessKey`, `outgoingToken`) that is otherwise gated behind edit-role for creation/deletion. This maps to Chainlink's "sensitive information disclosure via role bypass" bounty class — a view-only user gains visibility into integration credentials/endpoints it should not have, aiding further attacks (e.g., targeting the associated `outgoingToken`/URL for a specific external initiator, or correlating registered EI names to attempt to log in as that EI elsewhere).

### Likelihood Explanation
Trivial to exploit and fully repeatable: any operator who creates a low-privilege (`UserRoleView`) account or issues a restricted API token for a viewer can call `GET /v2/external_initiators` directly with no additional preconditions beyond having any valid authenticated session/token, since the `authv2` group only requires authentication, not a minimum role.

### Recommendation
Wrap the `Index` route with the same minimum role required for other sensitive read endpoints that reveal credentials, e.g. `auth.RequiresEditRole(eia.Index)` (matching `Create`/`Destroy`), or strip `AccessKey`/`OutgoingToken` from `ExternalInitiatorResource` for non-privileged callers.

### Proof of Concept
1. In `core/web/external_initiators_controller_test.go` (or a new test), seed an `ExternalInitiator` via `App.BridgeORM().CreateExternalInitiator`.
2. Start an authenticated test client with a session/user having `sessions.UserRoleView` (see helpers in `core/internal/cltest/cltest.go` and `core/web/auth/auth_test.go` for role setup).
3. Issue `client.Get("/v2/external_initiators")`.
4. Assert HTTP 200 (not 401/403), and that the JSON response's `data[].attributes.accessKey` / `outgoingToken` equal the seeded EI's plaintext values, proving a view-role session can read edit-gated credential metadata.
5. Contrast with `client.Post("/v2/external_initiators", ...)` and `client.Delete(...)` as the same view-role user, expecting 401/403 from `auth.RequiresEditRole`, to demonstrate the inconsistency between `Index` and `Create`/`Destroy` role enforcement.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
