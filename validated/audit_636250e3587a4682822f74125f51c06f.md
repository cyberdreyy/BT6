## Title
Timed-out `last_sortition` miner status is computed but never enforced, letting an abandoned prior-tenure miner get re-validated once `cur_sortition` times out - ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
`SortitionsView::check_proposal` computes and sets `last_sortition.miner_status = InvalidatedBeforeFirstBlock` when the prior tenure's miner has itself timed out, but the `ProposedBy::LastSortition` match arm that actually decides whether to accept a fallback proposal never reads `last_sortition.miner_status` - it only checks `self.cur_sortition.miner_status`. This makes the timeout computation on `last_sortition` dead code with respect to gating, so a genuinely abandoned prior-tenure miner can still get a late proposal validated and signed once the *current* sortition also times out.

### Finding Description
`SortitionState::is_timed_out` is a stateless, signerdb-driven check keyed on `get_last_activity_time`/`get_burn_block_receive_time_ch` [1](#0-0) . Inside `check_proposal`, this is invoked twice per call: once for `cur_sortition` (lines 144-163) and once for `last_sortition` (lines 205-219) [2](#0-1) . When `last_sortition` is found timed out, the code sets `last_sortition.miner_status = SortitionMinerStatus::InvalidatedBeforeFirstBlock` but does nothing else with that assignment in this call - there is no early return and no later `if` on it.

Later, when the proposal's consensus hash matches `last_sortition` and it is routed to `ProposedBy::LastSortition(last_sortition)`, the only gate applied is:

```rust
ProposedBy::LastSortition(last_sortition) => {
    if self.cur_sortition.miner_status != SortitionMinerStatus::InvalidatedBeforeFirstBlock {
        ...
        return Err(RejectReason::NotLatestSortitionWinner);
    }
}
``` [3](#0-2) 

This arm never inspects `last_sortition.miner_status` - the field it just computed a few lines earlier. `last_sortition.data.consensus_hash` is used only in a log line (line 312); `.miner_status` is not referenced anywhere else in the file for the `LastSortition` case (confirmed via `grep` for `last_sortition.miner_status`/`InvalidatedBeforeFirstBlock` usage - the only writes are at lines 218 and (for `cur_sortition`) 157/193/371/398, with no corresponding read for `last_sortition`).

Consequently: if the current sortition (tenure N+1) times out (marked `InvalidatedBeforeFirstBlock`), the code falls through to consider `last_sortition` (tenure N) proposals valid as long as the miner pubkey hash matches, the tenure-change/parent checks pass, etc. - even if tenure N's own miner has *also* been idle well past `block_proposal_timeout` and was itself just marked `InvalidatedBeforeFirstBlock` in the very same call. The explicit timeout computation for `last_sortition` has no effect on the accept/reject decision.

Existing guards do not prevent this: `is_timed_out` for `last_sortition` is computed correctly, but the result is discarded. The `cur_sortition` gate only proves the *newer* tenure is dead, not that the *older* fallback tenure is still alive. `SortitionsView` being fresh per `fetch_view` call is not itself the flaw (the code deliberately re-derives from persisted signerdb timestamps each time, which is by design for `is_timed_out`); the flaw is strictly the missing conditional in the `ProposedBy::LastSortition` arm.

### Impact Explanation
This breaks canonicity: a signer can be tricked into signing a block from a miner slot that the signer's own logic determined (in the same call) to be abandoned/timed-out, because the negative determination for `last_sortition` is silently dropped. The precondition that "the miner is the genuine winner of that (stale) tenure" limits who can exploit it to that tenure's own miner (matching the described attacker: a party who won a single BTC-backed miner slot), but it still lets a signer re-activate and sign for a tenure the signer had just judged abandoned, which is exactly the scenario the sibling check for `cur_sortition` (lines 144-163, with its early return) is designed to prevent for the current slot but is not mirrored for `last_sortition`.

### Likelihood Explanation
Preconditions: (1) a sortition N (attacker's tenure) goes idle past `block_proposal_timeout` with no signed block, (2) the next sortition N+1 also goes idle past `block_proposal_timeout` with no signed block, causing `cur_sortition` to be marked `InvalidatedBeforeFirstBlock`, (3) the attacker (winner of tenure N) then submits/gossips a valid, correctly-pubkey-signed block proposal for tenure N. No majority of signers, no privileged role, and no compromise of the auth token is needed - only the attacker's own miner key for the slot they legitimately won, plus normal StackerDB gossip of a `BlockProposal`. This is deterministic given the two-timeout precondition (not merely a narrow race), and is repeatable each time both timeouts elapse.

### Recommendation
In the `ProposedBy::LastSortition` arm of `check_proposal`, also check `last_sortition.miner_status == SortitionMinerStatus::Valid` (in addition to the existing `cur_sortition` check) and reject with `RejectReason::InvalidMiner` (or a dedicated reject reason) if `last_sortition.miner_status != Valid`, mirroring the early-return behavior already present for `cur_sortition`.

// stacks-signer/src/chainstate/tests/v1.rs
#[test]
fn check_proposal_last_sortition_timeout_not_enforced() {
    let (stacks_client, mut signer_db, block_sk, mut view, mut block) =
        setup_test_environment(function_name!());

    // Build a block for last_sortition, correctly signed by the winning miner.
    block.header.consensus_hash = view
        .last_sortition
        .as_ref()
        .unwrap()
        .data
        .consensus_hash
        .clone();
    block.header.sign_miner(&block_sk).unwrap();

    // Record burn block receipt time for last_sortition far enough in the past
    // that it will be judged timed out relative to block_proposal_timeout,
    // and likewise for cur_sortition.
    // (insert_burn_block with an old received_time / sleep past config.block_proposal_timeout)

    std::thread::sleep(view.config.block_proposal_timeout + Duration::from_secs(1));

    // Both cur_sortition and last_sortition are now genuinely abandoned.
    let result = view.check_proposal(
        &stacks_client,
        &mut signer_db,
        &block,
        false,
        ReplayTransactionSet::none(),
    );

    // EXPECTATION under a correct guard: rejected, because last_sortition
    // itself timed out (view.last_sortition.miner_status should be
    // InvalidatedBeforeFirstBlock after the call).
    assert!(
        result.is_err(),
        "Proposal from an already-timed-out last_sortition miner must not validate, \
         but the LastSortition branch does not check last_sortition.miner_status"
    );
    assert_eq!(
        view.last_sortition.as_ref().unwrap().miner_status,
        SortitionMinerStatus::InvalidatedBeforeFirstBlock
    );
}
```
Running this against the current code demonstrates `result` is `Ok(())` (the proposal validates) even though `last_sortition.miner_status` was set to `InvalidatedBeforeFirstBlock` within the same call - confirming the mutation is not enforced.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
