### Title
Hardcoded 24h Chainlink heartbeat and immutable feed address can freeze epoch transitions or accept stale prices - (File: contracts/strategies/usual/IdleUsualStrategy.sol)

### Summary
`IdleUsualStrategy.getChainlinkPrice()` hardcodes a 24-hour staleness bound (`updatedAt > block.timestamp - 24 hours`) and hardcodes the `USD0ppOracle` aggregator address as a `constant` with no setter. If Chainlink changes the USD0++/USD feed heartbeat, migrates/deprecates the aggregator, or the feed simply updates less frequently than every 24 hours (it only pushes on a 50 bps deviation plus heartbeat), every code path that prices the tranches reverts. `startEpoch`, `stopEpoch`, and `initialize` in `IdleCDOUsualVariant` all call `getChainlinkPrice()`, so a missed heartbeat permanently bricks epoch transitions and locks all deposited USD0++ in the CDO with no fallback path. Conversely, if the heartbeat is lengthened or the feed is partially deprecated but still updates occasionally, stale prices are accepted and the junior-to-senior loss transfer at `stopEpoch` is computed on a wrong price, causing unfair loss allocation.

### Finding Description
In `contracts/strategies/usual/IdleUsualStrategy.sol:46-48`, the oracle and token addresses are immutable `constant`s:

```solidity
address public constant USUAL = 0xC4441c2BE5d8fA8126822B9929CA0b81Ea0DE38E;
address public constant USD0pp = 0x35D8949372D46B7a3D5A56006AE77B215fc69bC0;
address public constant USD0ppOracle = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;
```

and at lines 164-172:

```solidity
function getChainlinkPrice() public view returns (uint256) {
    // ... "There is also a 24 hours hearbeat."
    (,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
    require(updatedAt > block.timestamp - 24 hours, "Stale price");
    return uint256(answer) * 1e10;
}
```

There is no owner-set heartbeat, no oracle setter, and no fallback price source for the CDO path (`setOraclePrice` exists but `stopEpoch` unconditionally overwrites `oraclePrice` via `getChainlinkPrice()` first — see `IdleCDOUsualVariant.sol:77-78`).

Consumers of this function:
- `initialize()` (`IdleCDOUsualVariant.sol:63`) — sets `priceAtStartEpoch`.
- `stopEpoch()` (`IdleCDOUsualVariant.sol:77`) — sets the reference oracle price used to compute `targetAATVL = lastNAVAA * oneToken / _oraclePrice` (line 93), the junior-to-senior reimbursement that brings the senior tranche to par.

So the hardcoded threshold guards the single price that decides how much junior value is transferred to seniors at epoch end.

### Impact Explanation
Two concrete impacts, both from unprivileged-observable conditions (no attacker privilege needed):

1. **Permanent freezing / DoS with fund lockup.** If the Chainlink aggregator is migrated (Chainlink routinely deprecates feeds and points proxies to new aggregators), or the feed simply misses the hardcoded 24h bound (deviation-triggered feeds can and do exceed heartbeat bounds during low-volatility periods or aggregator outages), `getChainlinkPrice()` reverts. `stopEpoch()` then reverts forever: the epoch can never be closed, `allowAAWithdraw`/`allowBBWithdraw` stay `false` (lines 80-84 are never reached), and all USD0++ held by the strategy is permanently locked. The owner cannot work around it because there is no oracle override path that bypasses `getChainlinkPrice()` inside `stopEpoch`.

2. **Unfair senior/junior loss split from a stale-but-accepted price.** If the feed's heartbeat is lengthened beyond 24h, a stale `answer` passes the check. At `stopEpoch`, an inflated stale `oraclePrice` (e.g., 1.0 while real price is 0.9) means `targetAATVL` is set too low and seniors redeem less than the guaranteed dollar-par value — a shortfall socialized onto seniors. A deflated stale price overcompensates seniors at juniors' expense. Loss magnitude scales with `lastNAVAA` and the price deviation; e.g., with 1M USD0++ senior NAV and a 10% stale overpricing, seniors lose ~100k of the intended guarantee.

### Likelihood Explanation
- Chainlink feed deprecations/migrations are routine and have occurred across many feeds; the USD0++ feed is a niche, deviation-based (50 bps) feed — exactly the class most likely to be updated or to exceed a fixed heartbeat during quiet periods.
- The contract comment itself acknowledges the feed "is not updated frequently", yet fixes the bound at exactly the documented heartbeat with zero margin and zero configurability — no buffer for a delayed update.
- This mirrors the external report's premise verbatim: a hardcoded, immutable staleness threshold tied to an external parameter (Chainlink heartbeat) the protocol does not control. Here it is worse because the oracle address itself is also immutable.
- Likelihood is moderate for the stale-acceptance case over the contract's lifetime and low-but-catastrophic (permanent freeze) for feed deprecation, since no recovery path exists in `stopEpoch`.

### Recommendation
- Make the heartbeat a mutable state variable (e.g., `maxOracleDelay`) settable by the owner, initialized to 24 hours.
- Make `USD0ppOracle` a configurable address with an owner setter instead of `constant`.
- Add a fallback in `stopEpoch`/the strategy: if `getChainlinkPrice()` reverts or the round is stale, allow the owner to supply a price via `setOraclePrice` (already floored by `getFloorPrice()`), and validate `answeredInRound >= roundId` and `answer > 0` in `getChainlinkPrice`.

### Proof of Concept
Foundry fork test (Ethereum mainnet), placed under `test/foundry/`:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "./IdleUsualStrategy.t.sol"; // reuse existing deployment harness

contract StaleHeartbeatPoC is IdleUsualStrategyTest {
    // Deploy: CDO + strategy wired, deposit AA/BB, startEpoch(0) as in testStartEpoch

    function testFrozenStopEpochOnMissedHeartbeat() external {
        uint256 amount = 10000 * ONE_SCALE;
        idleCDO.depositAA(amount);
        idleCDO.depositBB(amount);
        vm.prank(owner);
        IdleCDOUsualVariant(address(idleCDO)).startEpoch(0);

        // Warp past epochEndDate so stopEpoch's only check would pass...
        vm.warp(IdleCDOUsualVariant(address(idleCDO)).epochEndDate() + 1);
        // ...and past the feed's last updatedAt + 24h (simulate missed heartbeat /
        // deprecated aggregator by mocking latestRoundData, or simply warp on a
        // fork where updatedAt is already >24h old after the warp).
        vm.mockCall(
            0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB,
            abi.encodeWithSelector(IOracle.latestRoundData.selector),
            abi.encode(uint80(1), int256(1e8), uint256(0),
                       block.timestamp - 25 hours, uint80(1)) // stale updatedAt
        );

        // Owner (honest) tries to close the epoch -> reverts "Stale price".
        vm.prank(owner);
        vm.expectRevert(bytes("Stale price"));
        IdleCDOUsualVariant(address(idleCDO)).stopEpoch();

        // No path remains: withdraws stay disabled, USD0++ locked in strategy.
        assertFalse(IdleCDOUsualVariant(address(idleCDO)).allowAAWithdraw());
        assertFalse(IdleCDOUsualVariant(address(idleCDO)).allowBBWithdraw());
    }

    function testStalePriceAcceptedMispricesSeniorPar() external {
        // Mock latestRoundData with updatedAt within 24h but a stale answer of 1.0
        // while real USD0++ trades at 0.9: stopEpoch sets oraclePrice = 1.0, the
        // `if (_oraclePrice >= oneToken) return;` branch skips the junior->senior
        // top-up, and seniors redeem at an unfair haircut when price later corrects.
    }
}
```

Both cases run on a mainnet fork using the existing `IdleUsualStrategyTest` harness (`test/foundry/IdleUsualStrategy.t.sol`), which already deploys the real `IdleCDOUsualVariant` + `IdleUsualStrategy` against the real USD0++/Chainlink addresses.
