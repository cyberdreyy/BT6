### Title
Unbounded growth of shared `jwtReplayCache.cache` allows authorized signer to exhaust gateway memory and degrade JWT verification for all users - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` calls `jwtCache.recordUsage(claims.ID)` for every JWT that passes signature, digest, and authorization checks, storing an entry in the single, handler-wide `jwtReplayCache.cache` map [1](#0-0) . The cache has no maximum size — entries are only purged by a periodic ticker running every `jwtCache.cleanupPeriod`, which is started only once inside `Start()` [2](#0-1) . An attacker holding one valid authorized signer credential for a single workflow can generate a high volume of legitimately-signed, unique-`jti` JWTs and flood this shared cache before a cleanup tick fires.

### Finding Description
`Authorize` validates the JWT signature/digest/expiry via `utils.VerifyRequestJWT`, checks `jwtCache.isReplay(claims.ID)`, then verifies the signer is in `authorizedKeys[workflowID]`, and only then calls `h.jwtCache.recordUsage(claims.ID)` [1](#0-0) . This confirms that only requests from a genuinely authorized signer for a registered workflow ID can insert entries — an unauthenticated or unauthorized flood (as speculated in part of the question) cannot poison the cache, since `Authorize` returns an error before reaching `recordUsage` for any unauthorized signer or unregistered workflow ID.

However, `jwtReplayCache` itself has no size cap: `recordUsage` unconditionally writes `cache.cache[jti] = time.Now()` [3](#0-2) , and the only eviction mechanism is `cleanupOldEntries`, invoked on a fixed ticker interval equal to `jwtCache.cleanupPeriod` [2](#0-1) [4](#0-3) . Because JWTs each carry a fresh, attacker-chosen UUID `jti` (`CreateRequestJWT` sets `jti := uuid.New().String()`) [5](#0-4) , an authorized signer can trivially mint an unlimited stream of distinct, individually-valid, short-lived (max 5-minute expiry per `maxJWTExpiryDuration`) tokens [6](#0-5) , each of which is accepted and recorded, growing `cache.cache` without bound between cleanup ticks. Since `jwtCache` is a single field on `WorkflowMetadataHandler` shared across **all** workflow IDs/signers [7](#0-6) , one authorized signer for one workflow can degrade the shared JWT-verification path used by every other workflow's requests, purely through map growth and lock contention on `cache.mu`.

### Impact Explanation
This is a memory-exhaustion / availability risk on the gateway's shared JWT replay-protection cache, potentially affecting authentication for all workflows served by the same `WorkflowMetadataHandler`, not just the attacker's own workflow — this fits a DoS/availability impact class. The severity is bounded by the requirement that the attacker must already hold a valid, currently-authorized signer credential for at least one registered workflow (not a fully unauthenticated attacker), which limits blast radius compared to a pre-auth vulnerability.

### Likelihood Explanation
Feasibility is moderate: the attacker needs only one authorized ECDSA signer key for one workflow (a credential level explicitly allowed as "attacker" in this audit's scope) and the ability to sign many JWTs and send many gateway requests quickly. Actual exploitability depends on factors not fully verifiable from this file alone — e.g., whether upstream rate limiting, request-size limits, or connection throttling on the gateway ingress path (in `http_handler.go` or transport layer) constrain the achievable request rate before OOM is reached; I was not able to fully audit those layers within this pass, and the configured `JWTReplayPeriodMs` value (which bounds the exposure window) was not located in this codebase slice.

### Recommendation
Add a hard upper bound on `jwtReplayCache.cache` size (e.g., reject/evict oldest entries once a configurable max is reached, or use a per-signer/per-workflow sub-quota) rather than relying solely on time-based cleanup between fixed ticker intervals. Consider also shortening `cleanupPeriod` relative to `maxJWTExpiryDuration`, or performing lazy/amortized cleanup on every `recordUsage` call (e.g., opportunistic sweep) rather than only a wall-clock ticker, to shrink the exposure window.

### Proof of Concept
1. In `workflow_metadata_handler_test.go`, construct a `WorkflowMetadataHandler` with a small `cfg.JWTReplayPeriodMs` (e.g., 1 hour) and register one authorized workflow/signer.
2. In a loop, call `h.jwtCache.recordUsage(uuid.New().String())` N times (e.g., 1,000,000) directly, simulating N unique valid authorized requests, and assert `len(h.jwtCache.cache) == N` before any cleanup tick fires.
3. Alternatively, call `h.Authorize(workflowID, token, req)` N times with N freshly signed JWTs (unique `jti`, valid signature, valid digest) from the single authorized signer, and confirm each succeeds and inserts a cache entry, demonstrating unbounded growth purely from one authorized credential.
4. Measure heap/memory growth (`runtime.MemStats`) as N increases, and confirm no size-based backpressure or rejection occurs regardless of N, only time-based `cleanupOldEntries` removes entries once `cleanupPeriod` has elapsed.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil

// cleanupOldEntries removes expired entries from the cache
func (cache *jwtReplayCache) cleanupOldEntries(cutoff time.Time) int {
	cache.mu.Lock()
	defer cache.mu.Unlock()
	var expiredCount int
	for jti, createdAt := range cache.cache {
		if createdAt.Before(cutoff) {
			delete(cache.cache, jti)
			expiredCount++
		}
	}
	return expiredCount
}
