### Title
Staking while `paused` inflates `total_staked_balance` beyond `env::account_locked_balance()` - (File: `staking-pool/src/internal.rs`)

### Summary
`StakingContract::internal_stake` unconditionally increments `self.total_staked_balance` and mints stake shares whenever `stake()`/`deposit_and_stake()`/`stake_all()` is called, with no check on `self.paused`. `internal_restake`, which is the only function that issues the actual `Promise::new(...).stake(...)` action against the runtime, exits immediately when `self.paused` is true, so no on-chain staking action occurs. This lets any unprivileged account inflate `total_staked_balance` while the real `env::account_locked_balance()` stays unchanged.

### Finding Description
The invariant claimed is `total_staked_balance == min(total_staked_balance, env::account_locked_balance())` (i.e., `total_staked_balance <= account_locked_balance()`) whenever the contract is not actively mid-restake.

Exploit flow: owner (or foundation) pauses the pool (`self.paused = true`). Any unprivileged account with a nonzero `unstaked` balance calls `stake(amount)` (or `deposit_and_stake`). `internal_stake` runs to completion, debiting `account.unstaked` and crediting `account.stake_shares`, and bumping `self.total_staked_balance`/`self.total_stake_shares`. Because the call site for staking invokes `internal_restake` afterward (per `stake`/`deposit_and_stake` handlers in `lib.rs`), and `internal_restake` silently no-ops under `paused`, no `Promise::stake` action is issued, so `env::account_locked_balance()` is never increased to match. The result: `self.total_staked_balance > env::account_locked_balance()` immediately after the call, for as long as the pool remains paused and as many times as the attacker repeats the call (bounded only by their own `unstaked` balance).

None of the existing guards prevent this: there is no `assert!(!self.paused, ...)` in `internal_stake`, `assert_owner` is not invoked on `stake`, and `internal_ping`'s balance assertion only compares `total_balance` (locked + unlocked account balance) against `last_total_balance`, which is not touched by `internal_stake` at all, so it cannot detect the divergence between `total_staked_balance` and `account_locked_balance()`.

The divergence is self-correcting once the owner unpauses: the next `internal_restake` call issues `Promise::new(...).stake(self.total_staked_balance, ...)`, which brings the real locked balance up to the (now-inflated) `total_staked_balance`. However, during the paused window the two values genuinely diverge, and the accounting value (`total_staked_balance`) that other delegators, the owner, and share-price calculations (`num_shares_from_staked_amount_rounded_down`/`up`, `staked_amount_from_num_shares_rounded_down`/`up`) all rely on does not reflect real staked NEAR held by the validator.

### Impact Explanation
While paused, `total_staked_balance` (used to compute the stake share price for every account, including reward distribution via `internal_ping` on unpause) overstates the actual validator-locked NEAR. Any account observing or relying on `total_staked_balance` (other delegators computing expected rewards, an integrator settling balances, or the owner's fee calculation) is working off a number that does not match on-chain reality for the duration of the pause. This matches the "accounting value diverging from reality where another party settles on it" High-severity category — no direct fund transfer or theft occurs, and the discrepancy is closed automatically at the next successful `internal_restake` (unpause), but it is a genuine, repeatable accounting invariant break reachable by any unprivileged caller with a nonzero `unstaked` balance.

### Likelihood Explanation
Requires the pool to be `paused` (an owner/foundation action, not attacker-controlled, but a normal operational state e.g. during key rotation). Given that precondition, any unprivileged account with `unstaked > 0` can trigger the divergence at zero cost beyond gas, and can repeat it every call while the pool remains paused. The attacker does not need any special role to call `stake`/`stake_all`/`deposit_and_stake`.

### Recommendation
Add an explicit check in `internal_stake` (and symmetrically consider `inner_unstake`) that asserts `!self.paused` before mutating `total_staked_balance`/`stake_shares`, or route the accounting update through the same guard as `internal_restake` so that staking cannot proceed unless the actual `Promise::stake` action will also be issued.

#[test]
fn test_stake_while_paused_inflates_total_staked_balance() {
    let mut contract = StakingContract::new(/* owner, key, fee */);
    // owner deposits+stakes normally so total_staked_balance > 0, then contract paused by owner
    contract.deposit_and_stake(); // attacker deposits first
    contract.paused = true; // simulate owner pause

    let locked_before = env::account_locked_balance(); // mocked/fixed in testing_env!
    let total_staked_before = contract.total_staked_balance;

    contract.stake(amount.into());

    assert_eq!(env::account_locked_balance(), locked_before); // unchanged, internal_restake no-op
    assert!(contract.total_staked_balance > total_staked_before); // grew
    assert!(contract.total_staked_balance > env::account_locked_balance()); // invariant broken
}

    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;

        env::log(
            format!(
                "@{} staking {}. Received {} new staking shares. Total {} unstaked balance and {} staking shares",
                account_id, charge_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }
