### Title
Client-controlled `req.ID` reuse in `newActiveRequest` allows cross-user response confusion / cross-user secret bundle delivery - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`HandleJSONRPCUserMessage` accepts a fully client-controlled, non-empty `req.ID` with only a length check, and `newActiveRequest` only rejects it if the ID is *currently* present in `h.activeRequests`. Once a prior request with the same ID is completed and removed via `sendResponseAndClearRequest`, a new (possibly unrelated, unauthenticated) request can immediately reuse that ID, and any still-in-flight, late-arriving node response for the original request will be routed by `HandleNodeMessage`/`getActiveRequest` into the new request's `activeRequest`, mixing another user's node-signed relay data into the second user's response bundle.

### Finding Description
- `HandleJSONRPCUserMessage` validates only that `req.ID != ""` and `len(req.ID) <= 200` [1](#0-0) . `req.ID` is attacker-supplied and there is no server-generated nonce tying it to a session/user.
- `newActiveRequest` uses `req.ID` as the sole map key and only detects collisions if the ID is *still present* in `h.activeRequests` at call time [2](#0-1) .
- `sendResponseAndClearRequest` (invoked on completion via quorum, grace, or expiry) deletes the map entry for that ID as soon as the first response is sent to the user [3](#0-2) , but slower DON nodes may still be in flight to `HandleNodeMessage` for that same ID (fan-out is per-node, independently timed, bounded by `nodeSendTimeout`, and the enclave/gateway does not wait for all nodes before completing on quorum) [4](#0-3) .
- If a second, unrelated user immediately submits a new request reusing that now-free ID, `newActiveRequest` creates and registers a brand-new `activeRequest` under the same key with no error [5](#0-4) .
- When the stale node response for the original (first) request subsequently arrives, `HandleNodeMessage` looks it up purely by `resp.ID` via `getActiveRequest`, which now returns the second user's `activeRequest` [6](#0-5) . The stale response is stored into the second user's `responses` map keyed by node address and merged into `bundler.Bundle` output alongside the second user's genuine node responses [7](#0-6) .
- The gateway's `bundler.Bundle` does not verify that a per-node response actually corresponds to the current request's content — it only checks `req.Method`, decodes `r.Result` into a `SignedSecretsResponseResult`/`SignedCapabilityResponseResult`, and appends it to the outgoing bundle unconditionally [8](#0-7) . The code comments explicitly state that signature/quorum verification is deferred to the enclave, not the gateway [9](#0-8) .
- As a result, the contaminated bundle — containing a node's signed response that was actually computed for the *first* user's original `MethodSecretsGet`/`MethodCapabilityExec` request — is sent directly back to the *second* user via `ar.SendResponse(payload)` in `sendResponseAndClearRequest`, with no gateway-side check that the ID collision is a coincidence rather than intentional reuse.

### Impact Explanation
This is a cross-user response confusion vulnerability: the gateway can hand an unrelated, unauthenticated client a bundle element that contains a DON node's signed relay response material addressed to a different user's confidential relay request (e.g., `MethodSecretsGet`). Even though final decryption/authorization may be enforced by the enclave downstream, the gateway itself performs no isolation between requests beyond the client-supplied ID, so cryptographic material, node signatures, and any plaintext metadata present in the JSON-RPC `Result` are exposed to the wrong requester at the gateway layer — matching the "key or secret disclosure" / "cross-user response confusion" bounty impact class for the gateway component.

### Likelihood Explanation
- Requires no privilege: any unauthenticated caller of the gateway's JSON-RPC endpoint can choose an arbitrary `req.ID` (only non-empty and ≤200 chars are enforced).
- Requires a timing race: the attacker (or two independent users, one of whom is unaware) must submit a request with an ID matching one whose predecessor was just completed and cleared, before the last straggling node response for that predecessor arrives. This is plausible because completion can occur as soon as quorum (`2F+1` or graced `F+1`) is reached while slower nodes are still in flight (bounded by `nodeSendTimeout`, default 10s) [10](#0-9) .
- Feasible for a single malicious client to deliberately exploit by predicting/matching IDs used by a victim (e.g., if IDs are sequential, guessable, or if the client controls both the "victim" and "attacker" requests, e.g. two sessions of the same operator's browser tabs) or by racing many parallel requests with a common ID pattern to increase odds of catching a stale in-flight response.

### Recommendation
Do not rely solely on client-supplied `req.ID` as the map key for isolation:
- Generate a gateway-internal, server-side unique correlation key (e.g., a UUID or monotonic counter) for each `activeRequest`, and use it as the `activeRequests` map key and as the value matched against in `HandleNodeMessage`, independent of the client's `req.ID`.
- Alternatively, retain the original `jsonrpc.Request` object (or a hash of it) inside `activeRequest` and, in `HandleNodeMessage`, verify the node response corresponds to the exact request instance (e.g., compare against a per-request nonce embedded when fanning out) before calling `addResponseForNode`.
- After `sendResponseAndClearRequest` deletes an entry, optionally retain a short tombstone/grace record for the ID for the maximum plausible node round-trip time so a late response cannot be silently absorbed by a newly registered request with the same client ID.

### Proof of Concept
Go unit test plan (in `core/services/gateway/handlers/confidentialrelay/handler_test.go`, following existing patterns like `setupHandlerWithConfig`, `mocks.DON`, `common.Callback`):

1. Set up a handler with `F=1`, 3 nodes, using `mocks.DON` and `clockwork.FakeClock`.
2. Submit request A (`MethodSecretsGet`, `ID="dup-id"`) via `HandleJSONRPCUserMessage` with callback A.
3. Deliver 2 (F+1, or 2F+1) valid signed node responses for `ID="dup-id"` via `HandleNodeMessage` from two node addresses so that `forwardBundle`/`sendResponseAndClearRequest` fires and callback A receives its response; assert `h.activeRequests["dup-id"]` is now nil (deleted).
4. Immediately submit request B (different method/params, but same `ID="dup-id"`) via `HandleJSONRPCUserMessage` with callback B; assert `newActiveRequest` succeeds (no "request ID already exists" error) and `h.activeRequests["dup-id"]` now points to B's `activeRequest`.
5. Deliver the third node's stale/late response for `ID="dup-id"` (originally intended for A) via `HandleNodeMessage` from the third node address.
6. Assert: (a) the stale response is stored inside B's `activeRequest.responses` (via `copiedResponses()`), and/or (b) once B's own quorum responses arrive, the outgoing bundle sent to callback B (`common.Callback` capturing `UserCallbackPayload`) contains a decoded `SignedSecretsResponseResult`/`SignedCapabilityResponseResult` entry originating from A's node response — proving cross-user data was delivered to B's callback.
7. Failing assertion (would prove the fix): the stale node response for the original ID after deletion is discarded/rejected rather than being merged into the new claimant's bundle.

```go
func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
```

```go
func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}
```

```go
func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
```

```go
func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
```

```go
// bundler assembles the gateway's response to the enclave. The gateway is a dumb
// fan-in: it forwards every per-node signed response it collected, in one bundle,
// without verifying signatures, checking signer membership, or deciding quorum.
//
// The enclave is the sole trust anchor. It groups the bundle by response hash,
// verifies each signature against the relay-DON signer set, and accepts the result
// backed by F+1 valid distinct signers. Because responses are keyed upstream by the
// gateway-authenticated node address (one response per node), a single compromised
// relay node can contribute at most its own one response to the bundle. It cannot
// manufacture quorum by fabricating signer identities; the worst it can do is add
// noise the enclave discards. This is what closes the prior liveness gap, where the
// gateway counted unverified, attacker-controlled signer identities toward quorum
// and could commit to a forged response, starving the enclave of the real one.
```

```go
func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedCapabilityResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable capability response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedCapabilityResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode capability response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	default:
		return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)
	}
}
```
