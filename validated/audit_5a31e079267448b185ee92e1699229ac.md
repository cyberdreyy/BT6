### Title
Signer places a second signature on a conflicting block in the same tenure when the node's tenure-tip query errors, breaking the equivocation guard - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`Signer::handle_block_pre_commit` guards against signing two different blocks in the same tenure by querying the node's canonical tenure tip and refusing to sign if the tip is already at or above the proposed block's height [1](#0-0) . When that node query itself fails (`Err(e)`), the code logs a warning that it is "treating the tenure as unconfirmed" and does not return — execution simply falls through the enclosing `if` block and proceeds straight to `mark_locally_accepted`/`handle_block_signature`, producing and broadcasting the signer's own signature over the second, conflicting block [2](#0-1) .

### Finding Description
This same-tenure conflict branch is the documented backstop for `DuplicateBlockFound`, which is only enforced once, at proposal time, in `check_proposal` [3](#0-2) . Everywhere else in this exact code path, an unreachable node is treated conservatively — the analogous cross-tenure conflict check `conflict_still_blocks` explicitly documents and implements "if the node cannot be asked, the conflict keeps blocking" [4](#0-3) , and the same principle is stated as a design invariant: "Whenever the node cannot be asked, the conflict keeps blocking: that only delays the replacement... whereas wrongly signing cannot be taken back" [5](#0-4) .

The same-tenure branch inverts this invariant: on `Err(e)` from `stacks_client.get_tenure_tip(...)`, the code neither returns nor blocks — it falls through to sign [2](#0-1) . This means a `conflicts.iter().any(...)` hit (a real, unpermitted, signed conflict in this exact tenure — not merely a cross-tenure sibling) is silently discarded whenever the node's `/v3/tenures/tip`-style call transiently errors (timeout, restart, temporary unavailability), and the signer signs a second block in the same tenure it has already endorsed.

### Impact Explanation
This breaks the "one signature per tenure/height" equivocation guard that the pre-commit conflict logic exists to enforce, matching the Critical impact class "a signer signing an invalid, non-canonical, or conflicting block." A miner (or a byzantine tenure sequence) that gets two competing same-tenure blocks each to the pre-commit threshold can obtain a second signer signature on the loser simply by having the signer's tenure-tip query fail at the moment of re-evaluation — which can happen from ordinary node hiccups, not only attacker action.

### Likelihood Explanation
Reaching the pre-commit threshold on two same-tenure blocks is a documented scenario the codebase explicitly defends against (see `signer_refuses_to_sign_second_sibling_tenure_start` and related tests) [6](#0-5) . Triggering the fallthrough only additionally requires a single failed `get_tenure_tip` call at that moment (network hiccup, node restart, timeout) — no majority of signers or key compromise is needed. Because `Err(e)` here is the common/expected failure mode of any RPC call, the window is realistic rather than purely theoretical.

### Recommendation
Make the `Err(e)` arm of the `get_tenure_tip` match in the same-tenure branch (`stacks-signer/src/v0/signer.rs`, around line 1449) `return` without signing (or otherwise keep the conflict blocking), mirroring the safe-default behavior already used in `conflict_still_blocks` and the cross-tenure freshness branch, instead of falling through to `mark_locally_accepted`.

### Proof of Concept
1. Miner proposes block A in tenure T; signer set reaches pre-commit threshold, signer validates and signs A (`mark_locally_accepted`), recording a signed conflict for tenure T at A's height.
2. Miner (or a forked/duplicate proposal) proposes block B, a different block in the same tenure T at height ≥ A's height, which also reaches the pre-commit threshold.
3. During `handle_block_pre_commit` for B, `get_signed_conflicts` returns A as a same-tenure conflict not covered by a reorg permit, entering the `if conflicts.iter().any(...)` block at line 1432.
4. If `stacks_client.get_tenure_tip(&B.consensus_hash)` returns `Err` (e.g., a transient RPC timeout) instead of `Ok`, the warning path executes and control falls through the `if`/`match` without returning.
5. Execution proceeds to `mark_locally_accepted(false)` and `handle_block_signature`, and the signer broadcasts its own signature over B — a second, conflicting block in tenure T that it already signed over via A.
