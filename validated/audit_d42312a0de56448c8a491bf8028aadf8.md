### Title
Stale confirmations from a removed multisig member remain counted toward `num_confirmations`, allowing requests to execute below live-member quorum - ([File: multisig2/src/lib.rs])

### Summary
`delete_member` only purges a removed member's own submitted requests (matched via `r.member == member`) and their `num_requests_pk` entry, but never scans other requests' `confirmations: LookupMap<RequestId, HashSet<String>>` to strip that member's `to_string()` entry from requests they merely *confirmed* but did not submit. Consequently, a stale confirmation from a member who is no longer in `self.members` can still push `confirmations.len() as u32 + 1 >= self.num_confirmations` to true, letting a request (e.g., a `Transfer`) execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
The binding that must hold is: `count(distinct members m ∈ self.members that confirmed request X) == self.num_confirmations` before `execute_request` runs.

Trace of the break:
1. `confirm()` at [1](#0-0)  counts confirmations purely via `self.confirmations.get(&request_id)`, a `HashSet<String>` of `MultisigMember::to_string()` values, with no cross-check against current `self.members`.
2. `delete_member()` at [2](#0-1)  removes outstanding requests *originated* by the deleted member (`r.member == member`) and clears `num_requests_pk`, but has no code path that iterates `self.confirmations` to remove the deleted member's string from confirmation sets of requests submitted by *other* members.
3. Exploit: member A submits (or is a confirmer on) request X submitted by member B (not A). A confirms X, inserting `A.to_string()` into `confirmations[X]`. Members B and C then pass a separate `DeleteMember { member: A }` request (a self-request requiring `assert_self_request`, satisfied trivially since it targets `current_account_id()`), which succeeds and removes A from `self.members` — but request X's confirmation set still contains A's stale entry because A did not submit X.
4. Member C then calls `confirm(X)`. `assert_valid_request` only checks that the caller is a current member and that the request/confirmations exist — it does not validate that *existing* entries in `confirmations[X]` still belong to current members. The count becomes `1 (stale A) + 1 (C) = 2 >= num_confirmations(2)`, so `remove_request` + `execute_request` run and the `Transfer` (or any other action) executes with only one live confirming member (C).

No existing guard (`assert_valid_request`, `assert_self_request`, `current_member()`) reconciles historical `confirmations` entries against present `self.members`, so the divergence is not caught.

### Impact Explanation
NEAR is transferred (or other privileged actions such as `AddKey`/`DeployContract`/`FunctionCall` executed) out of the multisig account with only 1 live confirming member instead of the configured `num_confirmations`, directly matching the Critical category "a multisig request executed below `num_confirmations` live members." The blast radius covers any multisig deployed via `MultisigFactory::create` where a confirming-but-non-submitting member is later removed while one of their prior confirmations is still outstanding on an unexecuted request — a plausible and repeatable operational pattern (e.g., rotating out a compromised or departing signer without re-auditing all pending requests).

### Likelihood Explanation
Preconditions are ordinary multisig operations, not attacker-controlled exploit setup: a request pending with a partial confirmation from a member who is later removed via a normal `DeleteMember` governance action. This requires no attacker deposit or special privilege beyond being (or becoming) one of the remaining legitimate members — it is triggered by routine member-rotation combined with pending requests, and is repeatable for every pending request that a to-be-removed member confirmed without submitting.

### Recommendation
In `delete_member`, iterate all entries in `self.confirmations` (not just requests filtered by `r.member == member`) and remove the deleted member's `to_string()` entry from every confirmation set; alternatively, in `confirm()`/`execute_request`, filter `confirmations` to only those entries whose corresponding member is still present in `self.members` before comparing against `num_confirmations`.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
