This confirms the vulnerability. The `oidcauth` `reaper.go` (`sessionReaper.Work`) only purges stale *sessions* by `created_at` age — it does **not** re-query the upstream OIDC provider for role membership, and it does **not** touch `oidc_user_api_tokens` at all.This confirms the full path: `POST /v2/jobs` is wrapped by `auth.RequiresEditRole` [1](#0-0)  which reads `user.Role` set into context by `AuthenticateByToken` [2](#0-1) , and that role comes directly and only from `FindUserByAPIToken`'s cached DB column with no re-derivation from live OIDC claims [3](#0-2) . The `oidcauth.sessionReaper.Work` only deletes stale `oidc_sessions` rows by age; it never touches `oidc_user_api_tokens` nor re-queries the upstream IdP for role changes [4](#0-3) . `RequiresEditRole` then trusts `user.Role` as-is [5](#0-4) .

### Title
Stale cached role in `oidc_user_api_tokens` allows downgraded users to retain edit access via API token - ([File: core/sessions/oidcauth/oidc.go])

### Summary
`FindUserByAPIToken` returns the `user_role` column that was cached in `oidc_user_api_tokens` at the time `SetAuthToken` was called, and never re-derives the role from a live OIDC claims check. Since no reaper/sync task exists that re-validates or updates roles for `oidc_user_api_tokens` against the upstream IdP, a user whose OIDC group membership is downgraded from edit to view continues to be granted edit-level access for as long as their token remains valid (`UserAPITokenDuration`, default 240h).

### Finding Description
When a user authenticates via OIDC and calls `SetAuthToken`/`CreateAndSetAuthToken`, their currently-effective role is written once into `oidc_user_api_tokens.user_role` [6](#0-5) . Subsequently, every API-token authenticated request (`X-API-KEY`/`X-API-SECRET` headers) resolves through `webauth.AuthenticateByToken`, which calls `FindUserByAPIToken` and trusts the returned `Role` field unconditionally [2](#0-1) . `FindUserByAPIToken` performs only a straight `SELECT ... FROM oidc_user_api_tokens WHERE token_key = $1` and computes only time-based expiry (`created_at + duration >= now()`); it does not re-check the user's current OIDC group claims or the `oidc_sessions` table for a newer/downgraded role [7](#0-6) . The comment in the code claims "sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation," but the actual `oidcauth.sessionReaper.Work` implementation only deletes stale rows from `oidc_sessions` by creation-time threshold — it never touches `oidc_user_api_tokens`, and never performs any upstream OIDC re-query at all (unlike the LDAP equivalent in `core/sessions/ldapauth/sync.go`, which actively re-syncs group membership and role from the LDAP server) [4](#0-3) . Consequently, `RequiresEditRole`-gated routes such as `POST /v2/jobs` (via `authv2` group wrapped with `auth.AuthenticateByToken`) will authorize a stale, elevated role for the full remaining `UserAPITokenDuration` window [1](#0-0) .

### Impact Explanation
This is a role/authorization bypass allowing privilege persistence: a user demoted from edit to view in the upstream IdP retains the ability to create/mutate jobs, bridges, external initiators, and other edit-gated resources for up to the full API token lifetime (default 240 hours) using their still-valid API token. This maps to Chainlink's "Broken Access Control" / unauthorized privileged action bounty class.

### Likelihood Explanation
Preconditions: attacker must have previously held edit role and minted an API token while still edit, and the token must not yet be expired (up to 240h window by default) after a role downgrade occurs. No additional credentials, exploits, or timing races are needed — the attacker simply continues using their existing token normally. This is fully repeatable and requires no host/DB access, matching the "unprivileged/downgraded credential holder" attacker model.

### Recommendation
Re-derive/re-validate the user's role from the live `oidc_sessions`/upstream OIDC claim on each `FindUserByAPIToken` call (or at minimum against the most recent session role), and/or implement a genuine reaper/sync job for `oidc_user_api_tokens` analogous to `ldapauth.LDAPServerStateSyncer.Work`, which re-queries the upstream provider on `UpstreamSyncInterval` and updates/revokes tokens whose role has changed. Shortening `UserAPITokenDuration` alone is not sufficient mitigation.

### Proof of Concept
Go unit test in `core/sessions/oidcauth/oidc_test.go`:
1. Insert a row into `oidc_user_api_tokens` for `user@example.com` with `user_role = 'edit'`, valid `token_key`/salt/hashed secret, `created_at = now()`.
2. Simulate a downgrade by directly updating (or inserting a new) `oidc_sessions` row for the same email with `user_role = 'view'` (representing the user's current, post re-login-would-be role).
3. Call `oi.FindUserByAPIToken(ctx, tokenKey)`.
4. Assert the returned `clsessions.User.Role == clsessions.UserRoleEdit` (stale) rather than `UserRoleView`, proving the API token still grants edit access.
5. Handler-level extension: wire this into `webauth.AuthenticateByToken` + `auth.RequiresEditRole(handler)` and assert a `POST /v2/jobs` request with the stale token's `X-API-KEY`/`X-API-SECRET` succeeds (not `403 Forbidden`) despite the simulated downgrade.

// FindUserByAPIToken retrieves a possible stored user and role from the oidc_user_api_tokens table store
func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (oi *oidcAuthenticator) SetAuthToken(ctx context.Context, user *clsessions.User, token *auth.Token) error {
	if !oi.config.UserAPITokenEnabled() {
		return errors.New("API token is not enabled ")
	}

	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return fmt.Errorf("OIDCAuth SetAuthToken hashed secret error: %w", err)
	}

	err = sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Remove any existing API tokens
		if _, err = oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE user_email = $1", user.Email); err != nil {
			return fmt.Errorf("error executing DELETE FROM oidc_user_api_tokens: %w", err)
		}
		// Create new API token for user
		_, err = oi.ds.ExecContext(ctx,
			"INSERT INTO oidc_user_api_tokens (user_email, user_role, token_key, token_salt, token_hashed_secret, created_at) VALUES ($1, $2, $3, $4, $5, $6, now())",
			user.Email,
			user.Role,
			token.AccessKey,
			salt,
			hashedSecret,
		)
		if err != nil {
			return fmt.Errorf("failed insert into oidc_user_api_tokens: %w", err)
		}
		return nil
	})
	if err != nil {
		oi.lggr.Errorf("error creating API token: %v", err)
		return errors.New("error creating API token")
	}

	oi.auditLogger.Audit(audit.APITokenCreated, map[string]any{"user": user.Email})
	return nil
}

func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {

	return err
}
