### Title
Unauthenticated request-ID collision in `newActiveRequest` allows denial-of-service/slot-hijack of another caller's confidential-relay request - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`(h *handler).newActiveRequest` keys in-flight requests solely by the caller-supplied `req.ID` string, with no binding to the sender's identity/signature. Any unauthenticated caller of the gateway's JSON-RPC endpoint can submit a request with an ID equal to a victim's known/predicted `req.ID` first, causing the legitimate request to fail with "request ID already exists," and causing any subsequent DON node responses for that ID to be routed to the attacker's registered callback instead of the victim's.

### Finding Description
The gateway's HTTP entrypoint decodes the raw JSON-RPC request and, when no legacy DON-scoped `Message` envelope is present, routes it purely by service/method name through `multiHandler.HandleJSONRPCUserMessage` directly into `handler.HandleJSONRPCUserMessage`, using the attacker-controlled `jsonRequest.ID` verbatim [1](#0-0) [2](#0-1) [3](#0-2) .

`HandleJSONRPCUserMessage` only validates that `req.ID` is non-empty and ≤200 characters before calling `newActiveRequest` [4](#0-3) . `newActiveRequest` then registers the request keyed only by the raw `req.ID` in a shared map, rejecting the call if that exact ID is already present: [5](#0-4) 

There is no per-sender authentication, signature check, or ownership binding tying `req.ID` to a specific caller in this handler — unlike the sibling vault handler/processor, which derives an authorized owner and rewrites the request ID as `owner::originalID` before registration so that two different callers can never collide on the same effective key [6](#0-5) . The confidential relay path has no equivalent prefixing/authorization step, so `req.ID` collisions across unrelated, unauthenticated callers directly collide in `h.activeRequests`.

Exploit flow: the attacker learns or predicts a victim's upcoming `req.ID` (e.g., workflow/execution ID reuse patterns are explicitly called out as a precondition, and `req.ID` is fully attacker-controlled input from the JSON-RPC body). The attacker sends `HandleJSONRPCUserMessage` with that same ID slightly before the victim. `newActiveRequest` succeeds for the attacker and inserts `activeRequests[id] = attackerAR`. When the victim's legitimate request arrives with the same ID, `newActiveRequest` sees `h.activeRequests[req.ID] != nil` and returns `errors.New("request ID already exists: " + req.ID)`, so the victim's `HandleJSONRPCUserMessage` call errors out immediately and the gateway returns a `HandlerError` to the victim [7](#0-6) . Additionally, until the attacker's request is cleared (`sendResponseAndClearRequest` / timeout), any DON node response bearing that request ID is looked up via `getActiveRequest(resp.ID)` and delivered to whichever `activeRequest` is currently registered — i.e., the attacker's callback, not the victim's [8](#0-7) .

### Impact Explanation
This is a denial-of-service / request-hijack against a specific victim's capability execution: the legitimate caller's confidential-relay request is rejected outright, and while the attacker's slot is held (up to `RequestTimeoutSec`, default 30s) any DON responses correlated to that ID are routed to the attacker instead. This matches the "isolation" invariant break called out in the question — one user's request slot is overwritten/blocked by an unrelated, unauthenticated user. It falls under Chainlink's DoS / unauthorized action-on-another-user's-request-slot impact class.

### Likelihood Explanation
Preconditions are minimal: the attacker needs no privilege beyond generic access to the gateway's JSON-RPC endpoint (no signature or auth token is checked for this code path before `newActiveRequest`), and needs to guess or observe the victim's `req.ID` in advance (e.g., through workflow/execution ID patterns, which are often deterministic or observable). The race only requires the attacker's message to arrive at the gateway before the victim's, which is feasible given typical request-ID predictability and gateway response-time windows. The attack is trivially repeatable per victim request.

### Recommendation
Bind `req.ID` uniqueness to the authenticated caller rather than to the raw client-supplied string — e.g., derive/prefix the internal map key from a verified sender identity (signature-derived address, JWT-authorized owner, etc.) similarly to how the vault handler's request processor rewrites IDs to `owner::requestID` before registration, so that two different unauthenticated callers can never collide on the same `activeRequests` entry.

### Proof of Concept
Add a table/goroutine test in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` with a mock `DON` and callback.
2. Goroutine A: calls `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request{ID: "shared-id", Method: MethodCapabilityExec}, callbackA)` and blocks (use a DON mock that blocks sends).
3. Immediately after A's `newActiveRequest` succeeds (synchronize via a hook or by calling `h.newActiveRequest` directly first to simulate the race deterministically), Goroutine B (a separate, unauthenticated "victim") calls `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request{ID: "shared-id", ...}, callbackB)`.
4. Assert B's call returns `errors.New("request ID already exists: shared-id")` and that `callbackB` never receives a response.
5. Simulate a DON node response for `"shared-id"` via `h.HandleNodeMessage`, and assert it is delivered only to `callbackA` (the attacker), never `callbackB`, confirming cross-user response confusion.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
