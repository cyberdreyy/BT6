### Title
Unauthenticated pipeline resume endpoint allows cross-user task-run resumption by design - ([File: core/web/pipeline_runs_controller.go])

### Summary
`PATCH /v2/resume/:runID` is registered on `unauthedv2` with no `auth.Authenticate`/role middleware, so `PipelineRunsController.Resume` can be invoked by anyone who possesses (or guesses) a task-run UUID, resuming that pipeline task with attacker-supplied result data via `prc.App.ResumeJobV2`. The code explicitly labels the audit event `audit.UnauthedRunResumed`, and the security boundary relies solely on UUID unguessability rather than authentication or role checks.

### Finding Description
The route is registered at [1](#0-0) . `Resume` parses the `runID` path param as a UUID, decodes a JSON body into `pipeline.ResumeRequest`, converts it to a `pipeline.Result`, and calls `prc.App.ResumeJobV2(ctx, taskID, result)` unconditionally, then writes an audit log entry tagged `audit.UnauthedRunResumed` before returning 200 [2](#0-1) . `ResumeJobV2` forwards directly to `pipelineRunner.ResumeRun`, which updates the task run result and, if all pending tasks are resolved, restarts the pipeline run in a goroutine [3](#0-2) [4](#0-3) . There is no ownership check tying the caller to the job/owner of that `taskID`; the only "authorization" is the UUID being hard to guess.

### Impact Explanation
This matches Chainlink's own threat model for this specific endpoint (the `UnauthedRunResumed` audit tag shows the team is aware and treats it as an accepted risk contingent on UUID secrecy), not an authentication bypass bug — the route was never intended to require authentication. If a task UUID leaks (e.g., via logs, external adapter callback URLs, or job spec exposure), an unprivileged remote client can inject arbitrary result/error data into that task run, potentially causing incorrect data (e.g., a bridge/external-adapter callback value) to be fed into the pipeline and affect downstream on-chain reporting. This is a legitimate low/medium severity finding about the trust boundary (UUID-as-secret) but is not a "missing auth" bug in the traditional sense since the endpoint is designed this way for external adapter callbacks.

### Likelihood Explanation
Exploitation requires only knowledge of a valid, still-pending `runID` (task UUID) for any job — no credentials, session, or API token are needed. Feasibility hinges entirely on how well task UUIDs are kept secret in practice (they are passed to external adapters as callback parameters, so exposure through adapter logs, browser history, proxies, or referrer headers is plausible).

### Recommendation
Since this endpoint is intentionally unauthenticated to support external-adapter async callbacks, the mitigation is not "add auth middleware" (which would break legitimate external adapter integrations) but rather to strengthen the secret comparison: ensure `runID` values are cryptographically random UUIDs (already the case via `uuid.New()`), rate-limit/log-monitor repeated resume attempts to detect brute-force guessing, and document that operators must treat task UUIDs as bearer secrets and avoid leaking them in logs/URLs. If stronger authorization is desired, consider adding a per-run signed callback token in addition to the UUID.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)

		Error: err,
	})

			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)

	}
