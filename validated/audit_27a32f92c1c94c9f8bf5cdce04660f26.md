### Title
Missing bank-binding and self-collateral guards in `kamino_harvest_reward` allow the bank's own PDA signing authority to be used against unconstrained/attacker-supplied Kamino Farms accounts - (File: `programs/marginfi/src/instructions/kamino/harvest_reward.rs`)

### Summary
`kamino_harvest_reward` is a permissionless instruction (no `authority: Signer` at all) that uses the bank's `liquidity_vault_authority` PDA as the CPI signer against an externally-supplied set of Kamino Farms accounts. Unlike its sibling instruction `drift_harvest_reward`, it omits the account-binding and self-collateral checks that prevent the "reward harvesting" mechanism from being pointed at the bank's own real collateral/mint, reproducing the exact risk class described in the external report: a consumer's own privileged signing authority (`this`-equivalent) being reachable by any caller against an insufficiently restricted "approved target."

### Finding Description
`KaminoHarvestReward` [1](#0-0)  declares `user_state`, `farm_state`, `global_config`, `rewards_vault`, `rewards_treasury_vault`, `farm_vaults_authority`, and `user_reward_ata` all as bare `UncheckedAccount`/comment-only-checked fields, with no `has_one`, `address`, or `associated_token::authority` constraints binding them to the bank's actual registered Kamino integration accounts (`integration_acc_1`/`integration_acc_2` used elsewhere, e.g. in `KaminoInitObligation`) [2](#0-1) . There is also no check that `reward_mint` differs from the bank's own liquidity mint, and no check that the targeted `farm_state`/`user_state` differ from the bank's own actual obligation-linked farm.

This is a direct regression compared to the equivalent `DriftHarvestReward` instruction, which explicitly guards against exactly this scenario: [3](#0-2) 
`DriftHarvestReward` enforces `has_one = integration_acc_2` / `has_one = integration_acc_3` (binding the Drift user/user_stats accounts to the bank), and requires `harvest_drift_spot_market.load()?.mint != bank.load()?.mint` and `harvest_drift_spot_market.key() != bank.load()?.integration_acc_1`, explicitly to prevent the "harvest" path from being used to move the bank's own principal.

`KaminoHarvestReward` performs the analogous privileged CPI signed by `liquidity_vault_authority` [4](#0-3)  and then transfers the entire delta balance out to the global fee wallet using that same PDA as transfer authority [5](#0-4) , but without any of Drift's mint/market isolation checks.

This mirrors the `safeFunctionCall` bug class precisely: the "approved target" (Kamino Farms program, hardcoded via `#[account(address = FARMS_PROGRAM_ID)]`) is legitimate, but the specific *state accounts* passed into that target are unrestricted, and the call is executed with the consumer's (bank's) own elevated signing privilege (`liquidity_vault_authority`), permissionlessly, by any caller.

### Impact Explanation
If the bank's own Kamino obligation/collateral farm happens to be structured such that a "reward" index can reference the bank's actual staked collateral (or if the reward mint is set to the bank's own principal asset by a legitimate/malicious farm configuration), a permissionless caller could invoke this instruction to redirect a legitimate transfer of the bank's liquidity-vault-authority-owned balance to the `global_fee_wallet` instead of it remaining protocol/depositor-owned collateral — an unauthorized state change/value redirection with direct financial effect on depositors, using the protocol's own signing authority.

### Likelihood Explanation
Medium. Exploitability is bounded by the external Kamino Farms program's own internal ownership checks (it will only let `liquidity_vault_authority` act on farm positions it actually owns), which somewhat narrows the attack surface to farm positions genuinely controlled by that specific bank's PDA. However, the missing bank-side isolation checks (present in the Drift analog but absent here) are a concrete, provable gap: nothing in the marginfi program itself prevents a caller from pointing this instruction at the bank's own real collateral-bearing farm state/reward mint, relying entirely on unverified assumptions about Kamino Farms' external semantics rather than marginfi's own defenses.

### Recommendation
Add the same defense-in-depth checks used in `DriftHarvestReward`:
- Bind `user_state`/`farm_state` to the bank's actual registered Kamino obligation-farm accounts via `has_one`/`address` constraints, or explicitly assert they are *not* the bank's own `obligation_farm_user_state`/`reserve_farm_state`.
- Require `reward_mint.key() != bank.load()?.mint` to prevent harvesting into the bank's own principal asset.
- Add proper `associated_token::authority = liquidity_vault_authority` (or equivalent) constraints on `user_reward_ata` instead of comment-only checks, for defense in depth even though SPL Token enforces authority at runtime.

### Proof of Concept
Not independently reproducible from this codebase alone: the exploit path depends on the concrete account layout/semantics of the external Kamino Farms program's `harvest_reward` instruction (mocked here as `kamino_mocks`/`kamino_farms`), which is out of scope of this repository. What is concretely demonstrable is the code-level comparison itself: [1](#0-0)  lacks the `has_one`/mint-mismatch/market-mismatch guards that [6](#0-5)  implements for the identical purpose, confirming the missing validation is a genuine gap rather than an intentional design choice.

pub fn kamino_harvest_reward(
    ctx: Context<KaminoHarvestReward>,
    reward_index: u64,
) -> MarginfiResult {
    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())

            rewards_treasury_vault: self.rewards_treasury_vault.to_account_info(),
            farm_vaults_authority: self.farm_vaults_authority.to_account_info(),
            scope_prices: optional_account!(self.scope_prices),
            token_program: self.token_program.to_account_info(),
        };
        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);
        let cpi_ctx = CpiContext::new_with_signer(program.key(), accounts, signer_seeds);
        harvest_reward(cpi_ctx, reward_index)?;
        Ok(())
