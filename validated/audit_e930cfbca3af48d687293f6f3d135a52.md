### Title
CORS wildcard origin allowlist bypass via missing subdomain boundary check - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's `httpServer.isAllowedOrigin` function implements wildcard CORS origin matching using `strings.HasSuffix` without verifying that a `.` boundary precedes the matched suffix, allowing an attacker-controlled domain that merely ends with the configured allowed-domain string (not an actual subdomain of it) to be treated as a fully allowed CORS origin.

### Finding Description
`isAllowedOrigin` performs scheme/port equality checks, then for wildcard entries (`*.domain.com`) strips the `*.` and does a raw suffix comparison against the caller-supplied `Origin` header host: [1](#0-0) 

This is structurally the same bug class as the reported `_walkNodePath` flaw: a partial/boundary match (the `EXTENSION` node sharing "some, but not all" of a key) is incorrectly treated as if it were a full, valid match, because the code does not verify that the matched prefix/suffix aligns on a proper structural boundary (nibble boundary in the trie case; a `.` label boundary in this case). Here, `allowedHost` (e.g. `chain.link` from `*.chain.link`) is compared with `strings.HasSuffix(originHost, allowedHost)`. Since there is no check that the character immediately preceding the matched suffix in `originHost` is a `.` (or that `originHost` doesn't just equal a longer string that happens to end with the same characters), an origin such as `evilchain.link` or `notchain.link` — which is **not** a subdomain of `chain.link` — will incorrectly satisfy `HasSuffix("evilchain.link", "chain.link") == true`.

An attacker who registers or controls any domain ending in the same character sequence as a configured wildcard-allowed domain (with no dot separator) can host a malicious webpage there. A victim's browser visiting that page will send `Origin: https://evilchain.link`, the gateway will echo it back in `Access-Control-Allow-Origin`, and the browser will permit the malicious page's JavaScript to read cross-origin responses from the gateway's JSON-RPC HTTP endpoint.

The gateway endpoint here is the internet-facing message ingress used for JSON-RPC style requests to node capabilities/handlers: [2](#0-1) 

### Impact Explanation
This is a CORS allowlist bypass reachable by any unprivileged external attacker who can register a domain with a matching suffix (no privileged access needed). If exploited against a victim whose browser is authenticated/positioned to call the gateway (e.g., via a DON operator dashboard or externally-initiated request flow), it enables cross-origin reading of gateway JSON-RPC responses that were intended to be restricted to specific allow-listed origins — a cross-user/cross-origin response confusion and allowlist-bypass class issue. The severity depends on what sensitive data or actions the gateway's `ProcessRequest` handler exposes to browser-origin callers, but the check itself is provably broken independent of that.

### Likelihood Explanation
Likelihood is high for any deployment that uses wildcard entries in `CORSAllowedOrigins` (a documented, intended feature per the sample configs and tests: `core/scripts/gateway/sample_config.toml`, `httpserver_test.go` `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`). No special privileges are required — only registering/controlling a domain with the right suffix and getting a victim to load a page from it while CORS is enabled.

### Recommendation
Fix `isAllowedOrigin` to require a proper label boundary when doing wildcard suffix matching, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This mirrors the recommended fix pattern for the analog bug (`_walkNodePath` should only continue/accept when the match is verified to fully cover the shared boundary, otherwise reject).

### Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.chain.link"]`.
2. An attacker registers `https://evilchain.link` (note: no `.` before `chain.link`) or `https://notchain.link`.
3. Attacker hosts a page on that domain that makes a `fetch()`/XHR request to the gateway's HTTP endpoint with credentials/CORS mode.
4. Browser sends `Origin: https://evilchain.link`; `isAllowedOrigin` computes `allowedHost = "chain.link"`, `originHost = "evilchain.link"`, and `strings.HasSuffix("evilchain.link", "chain.link")` returns `true`.
5. Server responds with `Access-Control-Allow-Origin: https://evilchain.link`, and the browser permits the attacker's script to read the response body, despite `evilchain.link` never being an actual subdomain of `chain.link`. [1](#0-0)

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
