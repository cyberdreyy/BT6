### Title
Symlink target and cross-extraction path validation missing in artifact extraction, enabling in-root alias writes to external targets - (File: commands/helpers/archive/tarzstd/tarzstd_extractor.go, shells/abstract.go)

### Summary
`downloadArtifacts` in `shells/abstract.go` invokes a separate `artifacts-downloader` process per job dependency, each of which extracts an attacker-influenced archive into the shared build root via `archive.NewExtractor`. The tar+zstd extractor validates that a destination *path string* stays under the root, but never validates a symlink's *target* (`Linkname`), and that check is purely textual — it does not re-verify that intermediate path components are still real directories rather than symlinks planted by an earlier extraction into the same root.

### Finding Description
`AbstractShell.downloadArtifacts` builds a shell command that runs `artifacts-downloader --id ... ` for every dependency job, and `downloadAllArtifacts` loops over all dependencies, invoking one such command per job into the same build working directory: [1](#0-0) 

Each invocation performs its own download + extract in a fresh process (`ArtifactsDownloaderCommand.Execute`), calling `archive.NewExtractor(format, f, size, wd)` and `extractor.Extract(...)` against the shared `wd` (the job's build root): [2](#0-1) 

For the tar+zstd extractor, the destination path is validated only as a string prefix of `e.dir`: [3](#0-2) 

Symlink entries are deferred and written with `os.Symlink(hdr.Linkname, path)` — the link target (`hdr.Linkname`) is never checked to stay inside `e.dir`: [4](#0-3) 

Because deferral only protects against pivot-then-write *within a single archive/single `Extract()` call*, it does not protect across the multiple, independent `Extract()` invocations that `downloadAllArtifacts` performs (once per dependency job) into the same root, nor against a symlink left behind by an earlier stage in the same job (e.g. cache restore, which runs before artifact download and uses the same extractor pattern, see `writeRestoreCacheScript`/`cacheExtractor`). An attacker who controls one dependency job's artifact archive can:
1. In that archive, include a symlink entry (e.g. `shared -> /some/path/outside/root` or a relative target that resolves outside the intended root) — this gets created on disk once `Extract()` for that job's archive finishes.
2. In a later dependency job's archive (or the same job's own artifact archive on a retried/second `artifacts-downloader` invocation), include a file entry `shared/payload` — the textual prefix check `filepath.Join(e.dir, "shared/payload")` passes because it is lexically under `e.dir`, but `os.MkdirAll`/`os.Create` will actually resolve through the pre-existing `shared` symlink and write outside the intended root, onto whatever real path the earlier symlink pointed to.

This is a classic "zip-slip via symlink pivot", generalized to cross-invocation extraction because the root-containment check never re-derives the real (symlink-resolved) path of parent directories before writing, and the symlink target itself is unconstrained. The `errorIfGitDirectory` guard in `helpers/archives/path_check_helper.go` only blocks `.git`-named entries and does nothing for arbitrary symlink names/targets. [5](#0-4) 

### Impact Explanation
An unprivileged pipeline author who controls the contents of one job's artifacts (their own job, which is a normal, always-available capability) can cause a later dependent job's artifact/cache extraction into the shared build root to write attacker-controlled file content through a previously planted symlink, escaping the intended root. Depending on what real path the symlink resolves to (anything reachable/writable by the job's file-system user, e.g. other locations under the runner's builds directory, shared caches, or files established by earlier trusted stages such as git checkout config), this enables cross-job tampering of files the runner or later stages treat as trusted, matching the "Expected Immunefi impact: cross-job tampering or secret exposure through symlink escape" scope.

### Likelihood Explanation
Preconditions are met by any pipeline author who can define job artifacts/dependencies (an ordinary, unprivileged CI capability) and control what files/symlinks their job's artifacts contain. `downloadAllArtifacts` already iterates per-dependency, performing independent `Extract()` calls into one shared root, which is exactly the sequencing needed ("place a link in job A, write through it in job B"). No additional privilege or admin misconfiguration is required; the flaw is a missing real-path re-validation and missing symlink-target validation in the extractor itself.

### Recommendation
- In `tarzstd_extractor.go` (and any other extractor, e.g. zip), validate `hdr.Linkname` for symlink entries against `e.dir` the same way regular entry paths are validated (resolve, and reject targets outside the root).
- Before writing any entry, resolve the *real* path of the parent directories (`filepath.EvalSymlinks` on the existing prefix, or refuse to traverse through any component that is a symlink not created by this same extraction and verified to point inside `e.dir`) rather than relying on a purely lexical `strings.HasPrefix` check.
- Track "known safe" symlinks created during the current extraction and disallow traversal through any symlink not in that set; better, disallow traversal through symlinks entirely for path components between the root and the final entry.

### Proof of Concept
Go integration test plan for `commands/helpers/archive/tarzstd`:
1. Create a temp root dir `root`.
2. First `Extract()` call with a tar+zstd stream containing a single symlink entry `alias -> /tmp/outside-target` (an existing directory outside `root`, simulating a trusted external path).
3. Assert `alias` now exists as a symlink pointing outside `root`.
4. Second, independent `Extract()` call (new extractor instance, same `root`) with a tar+zstd stream containing a regular file entry `alias/payload` with attacker content.
5. Assert that after extraction, `/tmp/outside-target/payload` was created/modified (proving escape) — expected/desired behavior is that `Extract()` returns an error and no file is written outside `root`. [6](#0-5)

func (b *AbstractShell) downloadArtifacts(w ShellWriter, job spec.Dependency, info common.ShellScriptInfo) {
	args := []string{
		"artifacts-downloader",
		"--url",
		info.Build.Runner.URL,
		"--token",
		job.Token,
		"--id",
		strconv.FormatInt(job.ID, 10),
	}

	w.Noticef("Downloading artifacts for %s (%d)...", job.Name, job.ID)
	w.Command(info.RunnerCommand, args...)
}

func (b *AbstractShell) jobArtifacts(info common.ShellScriptInfo) (otherJobs []spec.Dependency) {
	for _, otherJob := range info.Build.Dependencies {
		if otherJob.ArtifactsFile.Filename == "" {
			continue
		}

		otherJobs = append(otherJobs, otherJob)
	}
	return
}

func (b *AbstractShell) downloadAllArtifacts(w ShellWriter, info common.ShellScriptInfo) error {
	otherJobs := b.jobArtifacts(info)
	if len(otherJobs) == 0 {
		return common.ErrSkipBuildStage
	}

	b.guardRunnerCommand(w, info.RunnerCommand, "Artifacts downloading", func() {
		for _, otherJob := range otherJobs {
			b.downloadArtifacts(w, otherJob, info)
		}
	})

func (e *extractor) Extract(ctx context.Context) error {
	zr, err := zstd.NewReader(io.NewSectionReader(e.r, 0, e.size), zstd.WithDecoderLowmem(true))
	if err != nil {
		return err
	}
	defer zr.Close()

	tr := tar.NewReader(zr)

	deferred := map[string]*tar.Header{}
	for {
		hdr, err := tr.Next()
		if err == io.EOF {
			break
		}
		if err != nil {
			return err
		}

		fi := hdr.FileInfo()
		if fi.Mode()&irregularModes != 0 {
			continue
		}

		var path string
		path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))
		if err != nil {
			return err
		}
		if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
			return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir)
		}

		if err := os.MkdirAll(filepath.Dir(path), 0777); err != nil {
			return err
		}

		if ctx.Err() != nil {
			return ctx.Err()
		}

		switch {
		case fi.Mode()&os.ModeSymlink != 0:
			deferred[path] = hdr
			continue

		case fi.Mode().IsDir():
			deferred[path] = hdr

			err := os.Mkdir(path, 0777)
			if err != nil && !os.IsExist(err) {
				return err
			}

		case fi.Mode().IsRegular():
			f, err := os.Create(path)
			if err != nil {
				return err
			}

			if _, err := io.Copy(f, tr); err != nil {
				f.Close()
				return err
			}
			if err := f.Close(); err != nil {
				return err
			}

			if err := e.updateFileMetadata(path, hdr); err != nil {
				return err
			}
		}
	}

	for path, hdr := range deferred {
		fi := hdr.FileInfo()
		if fi.Mode()&os.ModeSymlink == 0 && !fi.Mode().IsDir() {
			continue
		}

		if fi.Mode()&os.ModeSymlink != 0 {
			if err := os.Symlink(hdr.Linkname, path); err != nil {
				return err
			}
		}

		if err := e.updateFileMetadata(path, hdr); err != nil {
			return err
		}
	}

	return nil
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
