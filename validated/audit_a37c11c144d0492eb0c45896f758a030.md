### Title
Unauthenticated `/health` and `/readyz?full` endpoints leak raw subservice error strings (potential internal state / credential-string disclosure) - ([File: core/web/router.go])

### Finding Description
`NewRouter` registers `healthRoutes(app, api)` [1](#0-0)  on the same `api` group used for the GraphQL and other endpoints, but before any authentication (`sessionRoutes`/`AuthenticateGQL`) is applied — the group only carries rate limiting and session-cookie middleware, not an auth gate [2](#0-1) . This means `GET /readyz`, `GET /health`, `GET /health.txt`, and `GET /public-readyz` are reachable by any unauthenticated caller.

`HealthController.Health` and `HealthController.Readyz` both call `checker.IsHealthy()`/`IsReady()` and, for every failing sub-service, embed the raw `err.Error()` string as the `Output` field of the returned `presenters.Check` [3](#0-2) [4](#0-3) . `Health` returns this by default (JSON/HTML/plaintext), not gated behind any additional flag — only the `failing` query param filters which checks are *included*, not whether error text is redacted. `Readyz` only includes error text when `?full` is passed, but that query param requires no authentication either.

The code itself acknowledges the risk: `PublicReadyz` was added specifically because "Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints" [5](#0-4) . This confirms that `/health` and `/readyz?full` were recognized as leaking per-check error strings, yet no equivalent redaction/authentication was added to `Health`/`Readyz` themselves — the mitigation was only applied to the new `PublicReadyz` endpoint, leaving the original `/health` and `/readyz` endpoints exposed with full detail to any unauthenticated caller by default routing.

Depending on the underlying service/driver, these error strings can contain internal details beyond a simple pass/fail (e.g., DB connection error text that may include host/port, DSN fragments, or other backend implementation detail) which is exactly what `HealthReporter` implementations return via `errors.New`/`fmt.Errorf` wrapping of underlying driver errors.

### Impact Explanation
This is an unauthenticated information-disclosure issue: any external caller (no credentials required) can enumerate node health check names and internal error text for failing sub-services, potentially exposing DB/host/service-configuration details useful for further reconnaissance or, in the worst case, leaking connection-string fragments if a driver error includes them. This is a lower/moderate-severity disclosure (does not by itself yield key material, fund movement, or role bypass) but is a legitimate scoped information-disclosure of internal service state to an unauthenticated actor, matching Chainlink's "informational/sensitive data exposure" bounty class rather than a critical compromise.

### Likelihood Explanation
Fully unauthenticated and trivially reproducible: any anonymous HTTP client can send `GET /health`, `GET /health.txt`, or `GET /readyz?full` to a running node with no credentials, no rate-limit bypass, and no special network position needed beyond reaching the node's API port. No operator/admin/host access is required. It triggers automatically whenever any registered subservice's `HealthReport()` returns a non-nil error (a normal degraded-state condition, not require the attacker to induce it directly).

### Recommendation
- Redact or genericize per-check `Output` text on `/health`, `/health.txt`, and `/readyz?full` unless the caller is authenticated, mirroring the approach already taken for `PublicReadyz`.
- Alternatively, require authentication (or restrict via config flag) for the detailed variants, and keep only pass/fail status codes for public/unauthenticated variants by default.
- Audit `HealthReporter` implementations to ensure error strings never embed secrets/DSNs even for internal-only consumers, as defense in depth.

### Proof of Concept
Go handler-level integration test plan:
1. Build a `chainlink.Application` mock whose `GetHealthChecker()` returns a `Checker` mock where `IsHealthy()` returns `false` and an `errors` map containing one entry, e.g. `"db": fmt.Errorf("dial tcp 10.0.0.5:5432: connect: connection refused (dsn=postgres://user:pass@10.0.0.5/db)")`.
2. Construct the router via `NewRouter(app, nil)` with no session/auth cookie set.
3. Issue `GET /health` (and `/health.txt`, `/readyz?full`) without any `Authorization`/session cookie.
4. Assert response status is `207`/`200` (not `401`/`403`), confirming no auth gate.
5. Assert the JSON/plaintext body's `Output`/check text contains the raw error string (`dial tcp 10.0.0.5:5432...`) verbatim, demonstrating that internal error detail — beyond a simple pass/fail — is returned to an unauthenticated caller.
6. Compare against `GET /public-readyz`, confirming it returns only a bare status code with no `Output` text, illustrating the asymmetric protection between the two endpoint families.

// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
