### Title

Zero-priced write-off requests allow any fulfiller to steal escrowed tranche tokens - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary

`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` accepts `underlyingsRequested == 0`, creating an escrowed tranche-token request that any third party can fulfill for zero underlying. `fullfillWriteOffRequest` is permissionless and only requires the fulfiller’s payment to be greater than or equal to the recorded request, so a zero-priced request can be completed by transferring no assets before receiving the victim’s tranche tokens. [1](#0-0) [2](#0-1) 

### Finding Description

The escrow is intended to exchange a lender’s escrowed tranche tokens for the amount of underlying requested by that lender. `createWriteOffRequest` rejects a zero tranche amount, pulls the tranche tokens into escrow, and stores the caller-supplied `underlyingsRequested`, but it does not require that requested amount to be positive. [3](#0-2) 

During fulfillment, the contract permits any caller, checks only that `_underlyings >= currentRequest.underlyings`, deletes the request, transfers the fulfiller’s underlying payment to the user, and sends the escrowed tranche tokens to the fulfiller. When `underlyingsRequested` is zero, the comparison succeeds with `_underlyings == 0`; ERC20 `transferFrom` permits a zero-value transfer, no exit fee is owed, and the fulfiller receives the complete tranche position. [4](#0-3) 

The vulnerable sequence is:

1. A KYC-passing lender calls `createWriteOffRequest(amount, 0)` while an epoch is running.
2. An unprivileged attacker calls `fullfillWriteOffRequest(victim, amount, 0)`.
3. The escrow pays the victim zero underlying and transfers `amount` tranche tokens to the attacker.
4. The attacker can hold, transfer, redeem, or otherwise exercise the rights attached to those tranche tokens subject to the credit-vault’s normal rules.

### Impact Explanation

An attacker can steal the full escrowed tranche position without paying underlying. For a request containing `T` tranche tokens priced at `P`, the loss is approximately `T * P / 1e18`, less no payment; the exploit scales linearly with the escrowed amount. [2](#0-1) 

The violated invariant is that a write-off fulfilment must atomically exchange escrowed tranche tokens for a positive lender-specified underlying payment. The current policy enforces the tranche amount exactly but permits the consideration side to be zero, turning fulfilment into an unconditional seizure. [5](#0-4) 

### Likelihood Explanation

The exploit requires only a lender-created request with `underlyingsRequested == 0`; no privileged role, borrower control, oracle manipulation, reentrancy, or timing advantage is needed. [1](#0-0) 

Because `fullfillWriteOffRequest` explicitly says it can be called by any wallet and uses an inclusive minimum-payment check, any observer can fulfill the malformed request as soon as it exists. The zero payment also avoids the exit-fee branch, since the fee is calculated from the attacker-supplied underlying amount. [6](#0-5) 

### Recommendation

Reject zero-priced requests in `createWriteOffRequest` with `if (underlyingsRequested == 0) revert NotAllowed();`. [1](#0-0) 

As defense in depth, also reject `_underlyings == 0` in `fullfillWriteOffRequest`, consider requiring exact payment unless intentional overpayment is desired, and add a regression test proving that a zero-underlying request cannot be created or fulfilled. [2](#0-1)

/// @notice Fork test demonstrating that a zero-priced write-off request
/// transfers the victim's escrowed tranches to an arbitrary fulfiller.
contract WriteOffEscrowZeroPricePoC is Test {
    IdleCreditVaultWriteOffEscrow internal escrow;
    IERC20 internal tranche;

    address internal victim = makeAddr("victim");
    address internal attacker = makeAddr("attacker");

    function testZeroPricedFulfilmentStealsTranches() external {
        // Arrange: deploy/attach the escrow for a live IdleCDOEpochVariant.
        // escrow = IdleCreditVaultWriteOffEscrow(ESCROW_PROXY);
        // tranche = IERC20(escrow.tranche());

        uint256 trancheAmount = 100e18;

        // The victim creates a malformed request asking for zero underlying.
        deal(address(tranche), victim, trancheAmount);
        vm.startPrank(victim);
        tranche.approve(address(escrow), trancheAmount);
        escrow.createWriteOffRequest(trancheAmount, 0);
        vm.stopPrank();

        assertEq(tranche.balanceOf(address(escrow)), trancheAmount);
        assertEq(tranche.balanceOf(attacker), 0);

        // Act: attacker fulfills the request without approving or paying underlying.
        vm.prank(attacker);
        escrow.fullfillWriteOffRequest(victim, trancheAmount, 0);

        // Assert: the victim receives nothing and the attacker receives all tranches.
        assertEq(tranche.balanceOf(attacker), trancheAmount);
        assertEq(tranche.balanceOf(address(escrow)), 0);
    }
}

  /// @notice create a write-off request by depositing tranche tokens and setting the amount of underlyings requested
  /// @param amount of tranche tokens to deposit
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;

  /// @notice fulfill the write-off request by buying the escrowed tranche tokens
  /// @param _user address of the user that made the write-off request
  /// @param _tranches amount of tranche tokens to transfer
  /// @param _underlyings amount of underlyings to transfer
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
