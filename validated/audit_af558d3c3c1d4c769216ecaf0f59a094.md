### Title
Inconsistent rounding between `GlobalStateEvaluator::reached_agreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` lets signers lock in a "canonical" miner/burn-view/protocol state below the true 70% approval bar - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The v0 signer's global state machine consensus check (`reached_agreement`/`reached_disagreement` in `libsigner/src/v0/signer_state.rs`) computes the 70% weight threshold using **floor** division, while the consensus-critical block-approval threshold used everywhere else in the protocol (`NakamotoBlockHeader::compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs`, and mirrored by `stacks-signer/src/v0/signer.rs`'s own `store_and_process_block_signature`/`handle_block_pre_commit`) computes the same nominal 70% threshold using **ceiling** division. Whenever `total_weight * 7` is not exactly divisible by 10 (the common case for arbitrary total signer weights), these two thresholds diverge by exactly one weight unit, so the global state machine can declare "agreement" with strictly less supporting weight than the real protocol bar requires.

### Finding Description
`GlobalStateEvaluator::reached_agreement` is: [1](#0-0) 

and `reached_disagreement`: [2](#0-1) 

Both use plain integer (floor) division: `total_weight * THRESHOLD / 10`.

Compare with the consensus-critical threshold used to actually validate a block's aggregated signer signature and, in the signer itself, to decide when to sign/broadcast: [3](#0-2) 

This uses an explicit ceiling (`+ ceil` when there's a remainder). The test suite documents this ceiling behavior explicitly: [4](#0-3) 

`GlobalStateEvaluator::reached_agreement` is used to decide the group's canonical view of the active miner, burn-chain tip, supported protocol version, and tx-replay set: [5](#0-4) [6](#0-5) 

For example, with `total_weight = 11`: the real (ceiling) 70% threshold is `ceil(11*7/10) = 8`, but `reached_agreement` returns `true` once `vote_weight = 7` (`floor(11*7/10) = 7`). This is a strictly weaker bar than the one the chain itself uses to finalize blocks (`compute_voting_weight_threshold`), and than the bar the very same signer process uses in `store_and_process_block_signature`/`handle_block_pre_commit`/`handle_block_rejection` when deciding to sign or reject a block: [7](#0-6) [8](#0-7) 

So one component of the signer's decision pipeline (the "what is the group's canonical view of the chain/miner" gate) applies a mathematically weaker consensus bar than the "should I actually sign this block" gate feeding off the identical `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant. This is precisely the bug class in the referenced report: an integer-division rounding choice silently produces a result (an "agreement"/"threshold crossed" boolean) that is wrong relative to the intended fixed-point percentage, and downstream code treats that wrong result as authoritative.

### Impact Explanation
`determine_global_state` (backed by `reached_agreement`) is the mechanism by which a signer decides the group-wide canonical `current_miner`, `burn_block`/`burn_block_height`, `active_signer_protocol_version`, and `tx_replay_set`. Per the documented decision flow, a signer's "does it fit my view of the chain (expected tenure and miner)" gate and its "have I already signed a rival block" checks rely on this canonicalized view: [9](#0-8) 

Because `reached_agreement` can fire with one weight-unit less support than the real 70% bar, a signer can lock in a `current_miner`/tenure view as "globally agreed" while the network-wide, consensus-critical 70% bar (as enforced by `compute_voting_weight_threshold` at block-verification time) has not actually been met by that same voting weight. A signer acting on this prematurely-"agreed" state can pre-commit to and sign a block built on a miner/tenure that a true supermajority has not endorsed, i.e., a signer ends up signing/treating-as-canonical a block that has not met the protocol's real approval threshold. This maps to "a signer signing an invalid/non-canonical/conflicting block" and also to "acting on a stale/threshold" in the sense that the threshold itself is computed inconsistently with the one the protocol actually enforces.

### Likelihood Explanation
The mismatch is deterministic arithmetic, not something requiring an attacker to control a majority of signer keys — it manifests naturally whenever the reward-cycle's total signer weight is not an exact multiple of 10 (the common case), and simply requires the normal gossip of `StateMachineUpdate` messages that already flow between signers (`GlobalStateEvaluator::insert_update`, driven by `StateMachineUpdate` gossip in `libsigner`/`stacks-signer/src/v0/signer.rs`). No malicious majority is needed; a set of honestly-voting signers whose combined weight equals the floor-threshold (but not the true ceiling-threshold) triggers the divergence.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the exact same ceiling-based formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (ideally by calling that function directly, or factoring out one shared helper used by both `libsigner` and `stackslib`), so that "global state agreement" and "block approval" always apply an identical, single definition of the 70% threshold.

### Proof of Concept
1. Construct a signer set whose `address_weights` sum to `total_weight = 11` (e.g., weights `4, 4, 3`).
2. Have signers with combined weight `7` (e.g., the two weight-4 signers) report the same `current_miner`/burn view via `StateMachineUpdate`.
3. Call `GlobalStateEvaluator::determine_global_state()` → `reached_agreement(7)` evaluates `7 >= 11*7/10 = 7` → `true`, so this signer treats that `current_miner`/tenure view as the group's canonical state.
4. Meanwhile, `NakamotoBlockHeader::compute_voting_weight_threshold(11)` returns `8` (ceiling), the real bar the chain/node and the signer's own block-signature-counting logic (`store_and_process_block_signature`) require to finalize a block signed by that same weight set.
5. Weight `7` is accepted as "canonical" for state-machine purposes at step 3 but is insufficient to actually finalize a block per step 4 — demonstrating the inconsistency directly with the existing `test_compute_voting_weight_threshold` values in `stackslib/src/chainstate/nakamoto/tests/mod.rs:4096-4123`, which show `compute_voting_weight_threshold(11)` would compute `8`, not `7`.

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
