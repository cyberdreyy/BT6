### Title
Flash-inflated ERC4626 vault price mints unbacked epoch interest into tranche NAV (programmable-borrower minted-interest mode) - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
In programmable-borrower mode, the pool's "price oracle" is `totalInterestDueNow()`, which values the vault sleeve with a live `vault.convertToAssets()` call on the external ERC4626 vault. `_vaultNetInterest()` computes `netDelta = bufferedVaultDelta + earnedAssets - principalAssets`, so any transient inflation of the vault's price-per-share between the epoch-start baseline (`epochStartVaultAssets`, snapshotted in `onStartEpoch`) and the honest manager's `stopEpoch` is recorded as vault interest. In minted-interest mode (`isInterestMinted`, mandatory for programmable borrowers per `setIsInterestMinted`), `IdleCDOEpochVariant._stopEpoch` calls `_strategy.mintStrategyTokens(_grossInterest)` — literally minting NAV against that quoted interest with no cash inflow — and `_updateAccounting` then raises tranche prices. Unlike the explicit-interest-override path, which is capped by `maxApr` (`_checkNotAllowed` at `IdleCDOEpochVariant.sol:377-380`), the programmable path applies no sanity bound on the oracle-reported interest.

### Finding Description
The analog to the Supra oracle manipulation is concrete:

1. Attacker is a KYC'd AA tranche holder and an ordinary LP of the ERC4626 vault used by `ProgrammableBorrower` (e.g. the MetaMorpho vault in `ProgrammableBorrowerCreditVault.t.sol`). Both roles are unprivileged.
2. Epoch is running; `epochAccountingActive == true`, `epochStartVaultAssets` fixed at `onStartEpoch` (`ProgrammableBorrower.sol:219`).
3. Attacker sandwiches the manager's legitimate `stopEpoch(0, 0)` transaction: in the same block/just before it, they transiently inflate `convertToAssets()` for the borrower's share balance — e.g. flash-supplying huge liquidity into the underlying markets the vault reads `totalAssets` from, or a deposit/donation pattern that temporarily lifts price-per-share. For MetaMorpho-style vaults `convertToAssets` reflects live market balances, so the inflation need not persist past the block.
4. `stopEpoch` → `_beforeStopEpoch` reads `totalInterestDueNow()` (`ProgrammableBorrower.sol:330-334`), which now reports the phantom delta as `vaultInterest`. `onStopEpoch` (`:231`) succeeds and sets `bufferStartVaultAssets` to the inflated baseline. `_stopEpoch` then mints `mintStrategyTokens(_grossInterest)` (`IdleCDOEpochVariant.sol:430`) and calls `_updateAccounting()`, crystallizing the fake gain into `lastNAVAA`/`priceAA`.
5. Next block the attacker unwinds the vault inflation (redeems/withdraws their flash position at normal price). The vault sleeve PnL reverts, but the minted strategy tokens and tranche NAV do not — the phantom interest stays priced in.
6. During the buffer the attacker calls `requestWithdraw` / `claimWithdrawRequest`, redeeming tranches at the inflated `tranchePrice` and extracting underlying funded by real LP principal. Honest LPs and pending receipts absorb the shortfall (insolvency / bad-debt escape), and subsequent accounting may tip the pool into the `Default` path.

The broken invariant is fair mint/burn plus solvency: `mintStrategyTokens` mints backing out of thin air based on a manipulable spot valuation instead of realized cash. Guards do not stop it: `_skimDonatedAssets` only sweeps raw underlying on the CDO (not share-price inflation inside the external vault), the `maxApr` check only covers `_interest > 1`, `depositDuringEpoch` is blocked for programmable mode but the attacker only needs tranche tokens acquired pre-epoch, and `stopEpoch` is called by the honest manager — the attacker merely controls the oracle input it reads.

### Impact Explanation
Direct theft bounded by how much `convertToAssets` can be inflated: for a flash-manipulable vault the bound is essentially the pool's TVL (inflate `earnedAssets` by X → X phantom interest minted → attacker captures attackerShare × X of other LPs' principal; residual inflation stays as unbacked strategy tokens → pool insolvency). Loss scales with vault TVL, matching the high-severity oracle-manipulation class.

### Likelihood Explanation
Requires a programmable-borrower deployment with `isInterestMinted` (the required configuration), an ERC4626 vault whose `convertToAssets` is same-block manipulable (common for vaults reading live underlying-market balances), a KYC'd attacker holding tranches before epoch start, and the ability to sequence around the public `stopEpoch` call — a sandwich of a predictable, timestamp-gated (`block.timestamp >= epochEndDate`) manager transaction.

### Recommendation
Bound the programmable interest like the override path: in `_stopEpoch`, clamp `totalInterestDueNow()`-derived interest to a `maxApr`-based ceiling over `epochDuration`. Preferably value the vault sleeve from a manipulation-resistant reference — e.g. store `epochStartShares` and only count realized interest actually withdrawn/repaid (cash moved through `onStopEpoch`/`repay`), not live `convertToAssets` deltas, mirroring how `onDefault` already avoids the live valuation "during stress" (`ProgrammableBorrower.sol:295-297`).

### Proof of Concept
Foundry fork sketch against the live MetaMorpho vault used in `test/foundry/ProgrammableBorrowerCreditVault.t.sol`:

```solidity
// setup (mirrors testProgrammableBorrowerStopEpochAutoRealizesInterestWithRealVault)
vm.prank(owner); cdoEpoch.setIsInterestMinted(true);
idleCDO.depositAA(10_000 * oneScale);        // attacker also holds AA tranches
_startEpochAndCheckPrices(0);

vm.warp(cdoEpoch.epochEndDate() + 1);

// attacker inflates convertToAssets() for the borrower's shares in-block:
// e.g. flash-supply X to the Morpho market morphoVault allocates to,
// raising vault.totalAssets() / price-per-share transiently.
uint256 interestPre = programmableBorrower.totalInterestDueNow();
/* execute inflation of magnitude X */;
uint256 phantomInterest = programmableBorrower.totalInterestDueNow() - interestPre;
assertGt(phantomInterest, 0);

vm.prank(manager);
cdoEpoch.stopEpoch(0, 0);                    // mints strategy tokens for phantom interest
/* unwind inflation - attacker recovers X at normal price */

uint256 aaPrice = cdoEpoch.virtualPrice(address(aaTranche));
assertGt(aaPrice, ONE_SCALE + phantomInterest * ONE_SCALE / aaSupply, "unbacked NAV priced in");

// attacker requests withdraw during buffer and claims, extracting other LPs' principal
cdoEpoch.requestWithdraw(0, address(aaTranche));
// ... claim at next startEpoch: paid more underlying than deposited + real yield
```

Key assertion: `strategyToken.balanceOf(cdo)` increases by ~`phantomInterest` via `mintStrategyTokens` while no corresponding underlying ever entered the pool — a pure oracle-price-manipulation inflation analogous to the Bonzo/Supra incident.
