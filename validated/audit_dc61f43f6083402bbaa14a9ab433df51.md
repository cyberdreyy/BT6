### Title
Cache key wildcard injection widens AssumeRole session-policy scope beyond intended object - ([File: cache/s3v2/s3.go])

### Summary
`s3Client.generateSessionPolicy` builds an IAM session-policy `Resource` ARN by directly interpolating the S3 object key (`objectName`, derived from the job's user-controlled cache `key`) into an ARN string with `fmt.Sprintf`. Because AWS IAM treats `*` and `?` in `Resource` ARNs as glob wildcards, a cache key containing these characters lets the resulting `AssumeRole` session grant access to many S3 objects instead of the single cache object the job is supposed to be scoped to.

### Finding Description
`cache.GetAdapter` (`cache/cache.go:27-81`) computes `fullPath` from the user-controlled cache `key` via `path.Join(basePath, key)` and only checks that the *cleaned* path still has `basePath+"/"` as a prefix (`cache/cache.go:67-70`). This blocks `../` traversal, but it does **not** filter or reject glob metacharacters such as `*` or `?`, which are perfectly valid path/object-name characters and never trip the prefix check (e.g. key `"*"` produces `fullPath = basePath + "/*"`, which still starts with `basePath + "/"`).

That `fullPath` becomes `objectName` in `s3v2.New` (`cache/s3v2/adapter.go:163-182`, only `TrimLeft(objectName, "/")` is applied — no further sanitization) and flows unchanged into `s3Client.generateSessionPolicy` (`cache/s3v2/s3.go:229-274`):
```go
Resource: fmt.Sprintf("arn:%s:s3:::%s/%s", s3Partition, bucketName, objectName),
```
The surrounding comment states the switch to `encoding/json` marshalling was meant to prevent `objectName` from "alter[ing] the policy structure" — but that only guards against JSON syntax injection (quotes/backslashes). It does nothing to stop IAM's own wildcard semantics for the `Resource` element: AWS documents that `*` and `?` inside `Resource` ARNs act as pattern-matching wildcards, not literal characters. `FetchCredentialsForRole` (`cache/s3v2/s3.go:312-415`) then calls STS `AssumeRole` with this session policy and returns credentials scoped by that (now-widened) resource pattern to the job's cache-upload/download step, when the runner is configured with `RoleARN`/`UploadRoleARN` for the S3 cache.

Existing protections reviewed:
- The `strings.HasPrefix(fullPath, basePath+"/")` check only defends against directory-traversal (`../`), not wildcard/glob injection — it is insufficient here.
- `strings.TrimLeft(objectName, "/")` in `s3v2.New` only trims leading slashes.
- JSON-marshalling the policy document prevents structural JSON injection but not IAM wildcard interpretation of the `Resource` value.

### Impact Explanation
A job author who can set an arbitrary `cache: key:` value (a normal, unprivileged CI capability) can cause the runner-issued, temporarily-assumed S3 credentials to be scoped to `.../project/<id>/*` (or any narrower/wider glob) instead of the single intended cache object. When the runner is configured with an S3 cache `RoleARN`/`UploadRoleARN` (a supported, non-default but legitimate configuration for scoping cache credentials per object), this lets a job read or overwrite **any other cache object under the same project's cache namespace** — including caches populated by other pipelines/branches within the project that the job never declared as a `cache:` dependency — defeating the least-privilege purpose of the per-object session policy. This can lead to cross-pipeline cache content disclosure or cache poisoning within the project.

### Likelihood Explanation
Fully reachable with only a `.gitlab-ci.yml` change (`cache: key: "*"` or similar), no special runner or admin privileges needed beyond the operator having enabled S3 cache with a scoped `RoleARN`. It is deterministic and repeatable on every job run.

### Recommendation
Reject or escape IAM wildcard metacharacters (`*`, `?`) in the object key before building the session-policy `Resource` string in `generateSessionPolicy` (e.g., percent-encode/escape them per AWS's own guidance for literal wildcard characters in ARNs), or validate the raw cache `key` in `cache.GetAdapter` to disallow `*`/`?` characters outright, in addition to the existing traversal check.

### Proof of Concept
Go unit test targeting `s3Client.generateSessionPolicy`:
```go
func TestGenerateSessionPolicy_WildcardInjection(t *testing.T) {
    c := &s3Client{awsConfig: &aws.Config{Region: "us-east-1"}, s3Config: &cacheconfig.CacheS3Config{}}
    policyJSON, err := c.generateSessionPolicy("my-bucket", "runner/tok/project/123/*", true)
    require.NoError(t, err)

    var doc policyDocument
    require.NoError(t, json.Unmarshal([]byte(policyJSON), &doc))

    // Assert the vulnerability: Resource should be an exact object ARN,
    // not one ending in a wildcard that matches sibling objects.
    assert.NotContains(t, doc.Statement[0].Resource, "*",
        "session policy Resource must not contain IAM wildcard characters derived from user-controlled cache key")
}
```

func (c *s3Client) generateSessionPolicy(bucketName, objectName string, upload bool) (string, error) {
	action := "s3:GetObject"
	if upload {
		action = "s3:PutObject"
	}

	// https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html
	s3Partition := "aws"
	// https://docs.aws.amazon.com/govcloud-us/latest/UserGuide/using-govcloud-arns.html
	switch {
	case strings.HasPrefix(c.awsConfig.Region, "us-gov-"):
		s3Partition = "aws-us-gov"
	case strings.HasPrefix(c.awsConfig.Region, "cn-"):
		s3Partition = "aws-cn"
	}

	// Build the policy via encoding/json rather than string formatting so that
	// any special characters in objectName (which originates from the cache
	// key in .gitlab-ci.yml) are escaped at the value position and cannot
	// alter the policy structure.
	doc := policyDocument{
		Version: "2012-10-17",
		Statement: []policyStatement{
			{
				Effect:   "Allow",
				Action:   []string{action},
				Resource: fmt.Sprintf("arn:%s:s3:::%s/%s", s3Partition, bucketName, objectName),
			},
		},
	}

	if c.s3Config.EncryptionType() == cacheconfig.S3EncryptionTypeKms || c.s3Config.EncryptionType() == cacheconfig.S3EncryptionTypeDsseKms {
		// Permissions needed for multipart upload: https://repost.aws/knowledge-center/s3-large-file-encryption-kms-key
		doc.Statement = append(doc.Statement, policyStatement{
			Effect:   "Allow",
			Action:   []string{"kms:Decrypt", "kms:GenerateDataKey"},
			Resource: c.s3Config.ServerSideEncryptionKeyID,
		})
	}

	out, err := json.Marshal(doc)
	if err != nil {
		return "", fmt.Errorf("marshalling session policy: %w", err)
	}
	return string(out), nil
}
