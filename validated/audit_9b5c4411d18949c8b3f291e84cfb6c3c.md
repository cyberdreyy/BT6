### Title
Unauthenticated disclosure of internal LOOP plugin topology via `/discovery` endpoint - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` registers `GET /discovery` (and the `/plugins/:name/...` endpoints) on the top-level `api` route group with no auth middleware, unlike every other sensitive route group in the router (`debugRoutes`, `authv2`, `userOrEI`). Any unauthenticated client can hit `/discovery` and receive a 200 JSON response enumerating all registered LOOP plugin names, their Prometheus scrape host, and port.

### Finding Description
`NewRouter` builds an `api` group with only rate-limiting and session middleware attached (`core/web/router.go:78-91`), then calls `loopRoutes(app, api)`. `loopRoutes` registers: [1](#0-0) 
No `auth.Authenticate(...)` wrapper is applied, in contrast to `debugRoutes` (`auth.Authenticate(..., auth.AuthenticateBySession)`) and `authv2`/`userOrEI` (`auth.Authenticate(..., auth.AuthenticateByToken/AuthenticateBySession/AuthenticateExternalInitiator)`).

`discoveryHandler` iterates `l.registry.List()` and returns a JSON array of Prometheus `targetgroup.Group` entries containing the discovery host, exposed port, and each plugin's name/metrics path: [2](#0-1) 

This is confirmed by the existing test `TestLoopRegistry`/`discovery endpoint` subtest, which calls `client.Get("/discovery")` using `app.NewHTTPClient(nil)` (no auth cookie/token) and asserts a `200 OK` with the full plugin label set returned: [3](#0-2) 

No session cookie, API token, or EI credential is required at any point in this path, so the endpoint is reachable by a fully unauthenticated attacker.

### Impact Explanation
This discloses internal plugin/service topology (LOOP plugin names, discovery hostname, exposed Prometheus port, and per-plugin metrics paths) to unauthenticated network clients. This maps to Chainlink's "informational disclosure of internal service data" impact class — it does not itself allow fund movement, job execution, or key exfiltration, but it reveals internal architecture that can materially aid further reconnaissance/targeting (e.g., discovering `/plugins/:name/metrics` and `/plugins/:name/debug/pprof/*profile`, which are also unauthenticated on the same route group and could leak further internal debug/profiling data or be used for DoS via `/debug/pprof/profile` and `/debug/pprof/trace`).

### Likelihood Explanation
Trivial and fully repeatable: the attacker needs only network access to the node's web server port and zero credentials. It is a simple `GET /discovery` request with no auth headers, as demonstrated by the existing unauthenticated test client in `loop_registry_test.go`.

### Recommendation
Wrap `loopRoutes` registrations in an authenticated group consistent with the rest of the router, e.g.:
```go
func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
    loopRegistry := NewLoopRegistryServer(app)
    group := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession))
    group.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
    group.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
    group.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
    group.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}
```
If these endpoints are intended to be scraped externally by Prometheus without node credentials, gate them instead behind the same bearer-token mechanism used for `/metrics` (`prometheusHandler`/`ginprom.Prometheus.Token` in `core/web/router.go:662-699`), or restrict via network/allowlist controls, rather than leaving them open to any caller.

### Proof of Concept
1. In a `net/http/httptest` or the existing `web_test` package, build an app/router via `cltest.NewApplicationWithConfigAndKey` and register a mock plugin via `app.GetLoopRegistry().Register("mockLoopImpl")` (as in `TestLoopRegistry`).
2. Use `app.NewHTTPClient(nil)` (unauthenticated — no session cookie/API token set) and issue `client.Get("/discovery")`.
3. Assert `resp.StatusCode == http.StatusOK` (not 401) and that the response body, when unmarshaled into `[]*targetgroup.Group`, contains the registered plugin's name label (`web.LabelMetaPluginName`) and metrics path.
4. This exact flow already exists as `TestLoopRegistry/discovery_endpoint` in `core/web/loop_registry_test.go:101-122`, confirming the unauthenticated 200 response.

```go
// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```
