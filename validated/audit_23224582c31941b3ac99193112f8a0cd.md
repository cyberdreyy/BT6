### Title
Stale confirmations from removed multisig members are still counted toward the K-of-N threshold, allowing request execution below the effective live-member threshold - ([File: multisig2/src/lib.rs], [File: multisig/src/lib.rs])

### Summary
In both `multisig/src/lib.rs` and `multisig2/src/lib.rs`, a member's/key's confirmation on a *pending* request is stored in the `confirmations` set keyed only by request ID. When a member (or key) is removed via `DeleteMember`/`DeleteKey`, the contract only purges requests that member *created*, and purges confirmation sets for **those** requests — it never scans and strips that member's stale confirmation entries from **other** pending requests they had previously confirmed but did not create. `confirm()` then counts `confirmations.len()` against `self.num_confirmations` without checking that every confirming principal is still a current member/key. This breaks the intended custody binding: `confirmations counted == live members who confirmed`.

### Finding Description
`confirm()` in `multisig2/src/lib.rs` executes the request once `confirmations.len() as u32 + 1 >= self.num_confirmations`: [1](#0-0) 

The confirmation count is a raw stored set, not re-validated against current membership. `delete_member()` only removes requests whose *creator* (`r.member`) equals the removed member, and clears confirmations solely for those requests: [2](#0-1) 

It does **not** iterate over `self.confirmations` to strip the removed member's entries from requests created by *other* members. The `assert` in `delete_member` only guarantees `members.len() - 1 >= num_confirmations`, i.e., that the threshold is still theoretically satisfiable by the new member set — it says nothing about existing pending requests whose confirmation sets already contain a since-removed member.

The identical pattern exists in the legacy `multisig/src/lib.rs`: `DeleteKey` removes requests created with that `signer_pk`, and clears `confirmations` only for those self-created requests: [3](#0-2) 

but any confirmation that key previously placed on a request created by a *different* key remains in the `confirmations` map and is still counted by `confirm()`: [4](#0-3) 

**Custody binding broken (as an equality):**
`num_live_confirmations_required_for_execution == num_confirmations` is supposed to hold, but the contract actually enforces `num_stored_confirmations(including removed members) + 1 >= num_confirmations`, so a request can execute with strictly fewer than `num_confirmations` *currently authorized* signers.

### Impact Explanation
This is a threshold-bypass on a multisig custody contract: a `MultiSigRequestAction::Transfer` (or `FunctionCall`, `AddKey`, etc.) can be executed with fewer live/authorized confirmations than the configured `num_confirmations`, effectively moving NEAR out of the account without the intended quorum of currently-trusted signers. This matches the "Critical" category: *a multisig request executed below threshold*.

### Likelihood Explanation
Requires: (1) a request pending confirmation with at least one confirmation from a member, (2) that member later removed via a normal `DeleteMember`/`DeleteKey` governance action (a routine key-rotation/offboarding event, not an attack), and (3) the stale pending request later confirmed by remaining members. No privileged bypass, redeploy, or victim key theft is needed beyond normal multisig operation sequencing — a remaining member (or a member colluding with knowledge of the stale request) can complete confirmation and trigger execution below the intended live threshold. Likelihood is High given member rotation is an expected/ordinary lifecycle event for these contracts.

### Recommendation
When removing a member/key (`delete_member`/`DeleteKey` handling), iterate all pending requests' confirmation sets and remove the departing member's/key's entry from every request (not only requests it created). Alternatively, on `confirm()`, re-validate each stored confirming principal against current membership before counting it toward the threshold (i.e., recompute count as the intersection of stored confirmations and current members/keys), rejecting/discarding stale entries lazily.

### Proof of Concept
1. Initialize `multisig2` with members `{A, B, C, D}`, `num_confirmations = 3`.
2. Member `E` (a member, e.g. `A`) calls `add_request` to create request `R1` (a `Transfer` to an attacker-controlled account). `B` calls `confirm(R1)` → `confirmations = {B}` (1/3).
3. `C` calls `confirm(R1)` → `confirmations = {B, C}` (2/3, not yet executed).
4. Separately, via a fully-confirmed governance request, `B` is removed via `DeleteMember { member: B }`. `delete_member` only purges requests created by `B`; `R1` (created by `A`) is untouched, so `confirmations` for `R1` still contains `B`.
5. `D` calls `confirm(R1)`. `confirmations.len() == 2` (`B`,`C`) `+ 1 == 3 >= num_confirmations (3)` → the transfer executes, even though only `C` and `D` are actual live members who confirmed — one fewer live confirmation than the required threshold of 3. [1](#0-0) [2](#0-1)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
