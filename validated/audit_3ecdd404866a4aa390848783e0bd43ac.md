### Title
Loss-adjusted withdraw receipt is paid at par when a later request epoch exists, draining the funded claims reserve - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`claimWithdrawRequest` resolves a stop-epoch loss haircut only for the epoch stored in `lastWithdrawRequest[_user]`. If a user holds a receipt in a loss-adjusted epoch `E` and then files another withdraw request in a later epoch `E+1`, the loss-adjusted lookup in `_claimLossAdjustedWithdrawRequest` reads `lossRecoveryPriceByEpoch[E+1]`, finds zero, and returns without clearing anything. The still-pending epoch-`E` receipt remains inside the aggregate `withdrawsRequests[_user]` and is paid out **at par** by `_claimFundedWithdrawRequest`. The haircut intended by `collectWithdrawFunds`/`lossRecoveryPriceByEpoch` is silently bypassed, and the shortfall is socialized onto remaining LPs and other claimants.

### Finding Description
`collectWithdrawFunds` records a pro-rata loss for pending receipts by storing `lossRecoveryPriceByEpoch[epochNumber]` and zeroing `pendingWithdraws` [1](#0-0) . The only path that applies that haircut is `_claimLossAdjustedWithdrawRequest`, which derives the epoch from `lastWithdrawRequest[_user]` [2](#0-1) . `requestWithdraw` overwrites `lastWithdrawRequest[_user]` with the newest request epoch while leaving `withdrawsRequests[_user]` and `withdrawsRequestsByEpoch[_user][E]` intact [3](#0-2) . On claim, `claimWithdrawRequest` calls the loss-adjusted path (skipped because the newest epoch has no loss price), then `_claimFundedWithdrawRequest` pays the full aggregate `withdrawsRequests[_user]` at par and zeroes it [4](#0-3) . The same bypass occurs through `_claimDefaultedWithdrawRequest`, which resets `lastWithdrawRequest[_user]` to 0 after clearing only the defaulted epoch's piece [5](#0-4) . The user even burns receipt strategy tokens 1:1 at line 343, so there is no accounting remnant — the pool simply pays more underlyings than were funded.

### Impact Explanation
Direct theft / insolvency. The attacker recovers `receipt_E * (1 - lossRecoveryPrice_E / RECOVERY_FULL)` more underlyings than funded. Since the loss-adjusted funding transferred only `pendingBasis * lossRecoveryPrice / RECOVERY_FULL` to the strategy, paying the receipt at par withdraws underlyings that belong to the vault's funded-claims reserve (or, post-default, `defaultRecoveryReserve` via `_transferFundedClaim`), leaving other claimants and active LPs short. The stolen amount scales with the receipt size and the haircut severity (up to the full receipt when the loss price is near zero — note `collectWithdrawFunds` only reverts at exactly zero, so a price of 1 wei still allows ~100% theft).

### Likelihood Explanation
The attacker only needs to be a KYC-passed tranche holder who files two withdraw requests across consecutive epochs — permitted at any time. The trigger conditions are honest privileged actions: a `stopEpochWithDuration` with `_lossAmount > 0` (a designed, documented feature for realized losses) while the attacker has a pending receipt, followed by any normal epoch cycle in which the attacker's second receipt is funded. No default is required for the base variant (a default makes it worse by also hitting `defaultRecoveryReserve`). No existing guard stops it: `_skimDonatedAssets`, epoch gating, and the `NotAllowed` reverts in `collectWithdrawFunds` do not touch this path.

### Recommendation
Track loss-adjusted claims per epoch rather than through the single `lastWithdrawRequest` pointer. Concretely: in `claimWithdrawRequest`, iterate over (or record) all epochs in `lossRecoveryPriceByEpoch` where `withdrawsRequestsByEpoch[_user][epoch] != 0`, or store a per-user set/marker of loss-adjusted epochs (e.g., `lossEpochsByUser`) at request time. Alternatively, when `requestWithdraw` is called while `lossRecoveryPriceByEpoch[lastWithdrawRequest[_user]] != 0` and the old receipt is unclaimed, either force-settle the old receipt at its loss price first or revert the new request. `_claimFundedWithdrawRequest` should only pay epochs confirmed fully funded, not the raw aggregate.

import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";

// Fork test: run with `forge test --fork-url <RPC> --match-test testLossHaircutBypass`
contract LossHaircutBypassPoC is Test {
    IdleCDOEpochVariant cdo;
    IdleCreditVault vault;
    address manager;   // honest manager
    address attacker;  // KYC-passed tranche holder

    function testLossHaircutBypass() public {
        // --- Epoch E: attacker deposits AA/BB and requests a normal withdraw ---
        vm.startPrank(attacker);
        cdo.depositAA(1000e18); // or depositBB
        cdo.requestWithdraw(1000e18, AA_TRANCHE); // creates receipt in epoch E
        vm.stopPrank();

        // --- Manager stops epoch E with a realized loss, e.g. 50% ---
        vm.prank(manager);
        cdo.stopEpochWithDuration(newApr, interest, duration, lossAmount);
        // collectWithdrawFunds stored lossRecoveryPriceByEpoch[E] ~= 0.5e18,
        // pendingWithdraws == 0, strategy received only the haircutted funding.

        // --- Epoch E+1: attacker files a SECOND withdraw request ---
        // (needs fresh tranche tokens; deposit in E+1 or reuse residual position)
        vm.startPrank(attacker);
        cdo.depositAA(1000e18);
        cdo.requestWithdraw(500e18, AA_TRANCHE); // lastWithdrawRequest[attacker] = E+1
        vm.stopPrank();

        // --- Manager stops epoch E+1 normally; receipt funded at par ---
        vm.prank(manager);
        cdo.stopEpoch(newApr, interest);

        // --- Attacker claims ---
        uint256 balBefore = underlying.balanceOf(attacker);
        vm.prank(attacker);
        cdo.claimWithdrawRequest();
        uint256 paid = underlying.balanceOf(attacker) - balBefore;

        // BUG: paid == receipt_E * 1.0 + receipt_E1 * 1.0
        // expected: receipt_E * lossRecoveryPriceByEpoch[E] / 1e18 + receipt_E1
        // attacker received ~receipt_E * (1 - lossPrice/1e18) extra underlying
        assertGt(paid, expectedHonestPayout);
    }
}

  function claimWithdrawRequest(address _user) external returns (uint256 amount) {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized) {
      // Post-default requests are already priced after the haircut and backed by the reserve,
      // so they must not fall through to the defaulted-epoch receipt logic.
      amount = _claimPostDefaultWithdrawRequest(_user);
      if (amount != 0) return amount;
      // Only receipts created in the defaulted epoch are haircutted here; old fulfilled
      // receipts are handled below at par if they were already funded before default.
      amount = _claimDefaultedWithdrawRequest(_user);
    }
    amount += _claimLossAdjustedWithdrawRequest(_user);
    return amount + _claimFundedWithdrawRequest(_user);
  }

  /// @notice Claim a funded non-default withdraw request at par.
  /// @param _user address of the user
  /// @return amount amount claimed
  function _claimFundedWithdrawRequest(address _user) internal returns (uint256 amount) {
    // User should wait at least an epoch before claiming the withdraw. Once the epoch is over user can withdraw 
    // at any time even if a new epoch started. 
    // So if epochNumber is the same as the last withdraw request then we revert. Epoch number is increased at stopEpoch
    // NOTE: If a user does not claim a withdraw request and instead requests another withdraw, he will have to wait
    // for another epoch to claim both requests.
    // NOTE 2: if borrower defaults, old withdraw requests can still be claimed
    if (IIdleCDOEpochVariant(idleCDO).epochEndDate() != 0 && (epochNumber <= lastWithdrawRequest[_user])) {
      revert NotAllowed();
    }
    // settle APR=0 requests once the related epoch has ended
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    // Claim includes:
    // - settled APR0 principal from finalized epochs
    // - still-open APR0 principal: if pool-close mode was used (_interest == 1), IdleCDO sets
    //   epochEndDate = 0 and claims can be immediate, while _settleApr0 can still skip settlement
    //   for the current request epoch (reqEpoch >= epochNumber).
    // - settled APR0 interest
    uint256 normalAmount = withdrawsRequests[_user];
    uint256 apr0PrincipalAmount = _apr0User.settledPrincipal + _apr0User.principal;
    uint256 apr0InterestAmount = _apr0User.settledInterest;
    amount = normalAmount + apr0PrincipalAmount + apr0InterestAmount;
    // burn strategy tokens 1:1 with the principal only (normal amount already includes interest)
    _burn(_user, normalAmount + apr0PrincipalAmount);
    withdrawsRequests[_user] = 0;
    lastWithdrawRequest[_user] = 0;
    if (apr0PrincipalAmount != 0 || apr0InterestAmount != 0) {
      delete apr0Users[_user];
    }
    _transferFundedClaim(_user, amount);
  }

  function collectWithdrawFunds(uint256 _amount) external {
    _onlyIdleCDO();
    uint256 pendingBasis = pendingWithdraws;
    if (_amount < pendingBasis) {
      // Legacy receipts do not have per-epoch ownership data, so they can only be fully funded.
      if (!defaultRecoveryInitialized) revert NotAllowed();
      uint256 lossRecoveryPrice = _amount * RECOVERY_FULL / pendingBasis;
      // Avoid storing a zero price, which is indistinguishable from "no loss-adjusted epoch".
      if (lossRecoveryPrice == 0) revert NotAllowed();
      pendingWithdraws = 0;
      lossRecoveryPriceByEpoch[epochNumber] = lossRecoveryPrice;
    } else {
      // A plain implementation upgrade may leave legacy normal receipts pending. Their next
      // successful stop can fully fund the aggregate before lazy initialization occurs.
      pendingWithdraws = pendingBasis - _amount;
    }
    if (_amount != 0) {
      underlyingToken.safeTransferFrom(idleCDO, address(this), _amount);
    }
  }

  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);
  }

  function _clearWithdrawClaimForEpoch(address _user, uint256 _claimEpoch, bool _isClearingApr0) internal returns (uint256 claimBasis, uint256 burnAmount) {
    (claimBasis, burnAmount) = _withdrawClaimAmountsForEpoch(_user, _claimEpoch);
    if (claimBasis == 0) return (claimBasis, burnAmount);

    uint256 normalAmount = withdrawsRequestsByEpoch[_user][_claimEpoch];
    if (normalAmount != 0) {
      withdrawsRequestsByEpoch[_user][_claimEpoch] = 0;
      // The aggregate may also include older funded receipts; clear only this epoch's piece.
      withdrawsRequests[_user] -= normalAmount;
    }
    Apr0UserData storage apr0User = apr0Users[_user];
    if (apr0User.principal != 0 && apr0User.principalEpoch == _claimEpoch) {
      if (_isClearingApr0) {
        uint256 apr0Principal = apr0User.principal;
        uint256 totalApr0Principal = apr0TotalPrincipal;
        // prepareStopEpochWithApr0 may already close the global APR0 bucket before default finalization.
        apr0TotalPrincipal = apr0Principal >= totalApr0Principal ? 0 : totalApr0Principal - apr0Principal;
      }
      apr0User.principal = 0;
      apr0User.principalEpoch = 0;
    }
    if (lastWithdrawRequest[_user] == _claimEpoch) {
      // The cleared epoch was the latest request marker. Any remaining normal/APR0 receipt
      // is older and already funded, so it can continue to the funded-claim path.
      lastWithdrawRequest[_user] = 0;
    }
  }
