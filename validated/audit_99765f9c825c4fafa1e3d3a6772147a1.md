### Title
Write-off request floor is checked before exit-fee deduction, so requesters receive less than their requested `underlyings` - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`IdleCreditVaultWriteOffEscrow.fullfillWriteOffRequest` validates the fulfiller's payment against the user's stored `currentRequest.underlyings` floor, but then deducts `exitFee` from that payment before forwarding the remainder to the user. The check compares a pre-fee amount to the user's minimum, so a fulfiller paying exactly the requested amount leaves the user with `underlyings - fee` — strictly less than the amount they escrowed tranche tokens for.

### Finding Description
A lender calls `createWriteOffRequest(amount, underlyingsRequested)`, escrowing tranche tokens and recording the minimum underlyings they will accept [1](#0-0) . Any wallet (in practice the borrower) then calls `fullfillWriteOffRequest(_user, _tranches, _underlyings)`. The function enforces `_underlyings >= currentRequest.underlyings` [2](#0-1) , pulls `_underlyings` from the fulfiller [3](#0-2) , sends `exitFee` to `feeReceiver` [4](#0-3) , and transfers only `_underlyings - _totFee` to the user [5](#0-4) .

`exitFee` is initialized to 100 (0.1%) in `initialize` and can be raised to `MAX_EXIT_FEE` = 1% [6](#0-5) [7](#0-6) . Because the floor check runs on the gross amount, the escrowed tranche tokens are released to the fulfiller while the lender's proceeds fall below the floor they specified. This is the same broken invariant as the reported bug: the comparison is made against a pre-fee price while the user is paid a post-fee amount.

### Impact Explanation
The lender permanently loses up to 1% (`MAX_EXIT_FEE`) of the underlyings they explicitly requested. With the default `exitFee = 100`, a fulfiller paying exactly `currentRequest.underlyings` causes the lender to receive 0.1% less than their stated minimum — e.g., a request for 100,000 USDC worth of tranches settles at 99,900 USDC, with the 100 USDC difference diverted to `feeReceiver`. The tranche tokens are gone (the borrower can burn them via `writeOffDeposit` to retire debt), so the lender has no recourse to recover the shortfall.

### Likelihood Explanation
`exitFee` is non-zero by default (0.1%), so every fulfillment at the requested amount underpays the requester unless the fulfiller voluntarily overpays. The fulfiller is economically incentivized to pay exactly `currentRequest.underlyings` since the check only requires `_underlyings >= currentRequest.underlyings`; there is no attacker cost and the underpayment is guaranteed whenever the floor is met exactly. The epoch must be running for `createWriteOffRequest` [8](#0-7) , but `fullfillWriteOffRequest` has no epoch gating, so fulfillment can occur at any time.

### Recommendation
Either (a) charge the fee on top of the requested amount — require `_underlyings >= currentRequest.underlyings + fee` or transfer `currentRequest.underlyings` to the user and take the fee only from the surplus — or (b) document and expose a `getUnderlyingsAfterFee(underlyings)`-style view and compare the post-fee amount against the user's floor, e.g. require `_underlyings - _totFee >= currentRequest.underlyings`.

### Proof of Concept
```solidity
// Foundry test on the deployed escrow (epoch running, exitFee = default 100 / 0.1%)
function testFulfillUnderpaysRequester() public {
    // lender escrows 100e18 tranche tokens, requests 1000e6 underlyings
    vm.prank(lender);
    escrow.createWriteOffRequest(100e18, 1000e6);

    // fulfiller (borrower or any wallet) pays exactly the requested amount
    deal(underlying, fulfiller, 1000e6);
    vm.startPrank(fulfiller);
    IERC20(underlying).approve(address(escrow), 1000e6);
    escrow.fullfillWriteOffRequest(lender, 100e18, 1000e6);
    vm.stopPrank();

    // lender receives 999e6 (< the 1000e6 floor they specified);
    // 1e6 is diverted to feeReceiver despite the check passing
    assertEq(IERC20(underlying).balanceOf(lender), 999e6);
    assertEq(IERC20(underlying).balanceOf(feeReceiver), 1e6);
    assertEq(IERC20(tranche).balanceOf(fulfiller), 100e18);
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```
