Confirmed: the `enroll_webauthn` routes are registered with no role wrapper, unlike every other sensitive route in the same `authv2` group.

### Title
Any authenticated user regardless of role (view/run/edit) can self-enroll a WebAuthn MFA credential via unrestricted `/v2/enroll_webauthn` routes - ([File: core/web/router.go])

### Summary
The `/v2/enroll_webauthn` GET/POST routes, which invoke `WebAuthnController.BeginRegistration`/`FinishRegistration`, are registered in `authv2Routes` without any `auth.RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrapper, unlike virtually every other sensitive route in that group. The handlers themselves only call `auth.GetAuthenticatedUser(c)` and perform no role check, so any user authenticated via session or API token — including a `view`-role account — can register a new MFA credential for themselves.

### Finding Description
In `core/web/router.go`, the webauthn enrollment routes are wired as: [1](#0-0) 
compare this to every other route in the same block (`/users`, `/keys/*`, `/jobs`, `/bridge_types`, etc.), all of which are wrapped in `auth.RequiresRunRole`, `auth.RequiresEditRole`, or `auth.RequiresAdminRole`. `authv2` itself only requires that the request pass `auth.Authenticate` with `AuthenticateByToken`/`AuthenticateBySession` — it does not check role: [2](#0-1) 

Inside the controller, `BeginRegistration` and `FinishRegistration` call `auth.GetAuthenticatedUser(c)` only to fetch the user object; there is no role comparison (`user.Role == ...`) anywhere in the handler: [3](#0-2) [4](#0-3) 

`GetAuthenticatedUser` simply returns whatever user object was placed in the gin context by the `Authenticate` middleware — it does not enforce any minimum role: [5](#0-4) 

The role-gating helpers (`RequiresRunRole`, `RequiresEditRole`, `RequiresAdminRole`) exist and are the mechanism used elsewhere to reject `view`-role users, but they are never applied to the webauthn routes: [6](#0-5) 

Because there is no role check at either the router or handler level, a `view`-role user (the lowest privilege authenticated role in this system, normally restricted to read-only access) can successfully call `GET /v2/enroll_webauthn` to start registration and `POST /v2/enroll_webauthn` with a valid WebAuthn attestation to have `FinishWebAuthnRegistration` persist a new credential via `sessions.AddCredentialToUser`, which writes to their own account's `WebAuthn` credential store: [7](#0-6) 

### Impact Explanation
This allows a `view`-role account to add a new second factor credential to itself without any operator/admin approval or elevated-privilege check, inconsistent with the role-gating pattern used for every other sensitive account/key-management route in this router (`/user/token`, `/keys/*`, `/users`, etc., many of which do require at least edit/admin). While enrolling *itself* an MFA key does not directly escalate that account's underlying role (view stays view), it is an authorization-exactness deviation: the endpoint modifies persistent account security state (adds a durable credential trusted for login MFA) reachable by the lowest-privilege authenticated role, contrary to the apparent intended design that mutating security-sensitive operations require at least run/edit role. This matches the class of unauthorized-mutation / authorization-bypass impact (inconsistent role enforcement on a account-security-affecting write endpoint), rather than a full node compromise.

### Likelihood Explanation
Requires only a valid, unprivileged `view`-role (or `run`-role) API token or session — the lowest bar of a legitimate authenticated credential, no admin/host access needed. The request sequence (`GET /v2/enroll_webauthn` then `POST /v2/enroll_webauthn` with an attestation) is straightforward and fully reproducible with any WebAuthn client library or the standard browser API, since nothing in the code path checks role.

### Recommendation
Wrap both `/v2/enroll_webauthn` routes with an explicit role check consistent with intended policy for MFA enrollment (e.g. `auth.RequiresEditRole` or `auth.RequiresAdminRole`, whichever matches the project's intended minimum privilege for self-service or admin-managed key enrollment), mirroring the pattern already used for `/user/token` and `/keys/*` routes in `core/web/router.go`.

### Proof of Concept
1. Router test (`core/web/router_test.go` or a new test) that spins up `NewRouter` with a `view`-role user's session/token, calls `GET /v2/enroll_webauthn`, and asserts a `401`/`403` is expected but currently gets `200` — demonstrating the missing role gate.
2. Handler-level integration test in `core/web/webauthn_controller_test.go`: authenticate as a `UserRoleView` user, call `BeginRegistration` then `FinishRegistration` with a valid mocked attestation response, and assert that `sessions.AddCredentialToUser` is invoked / a WebAuthn row is persisted for that view-role user — confirming self-enrollment succeeds despite the low-privilege role.
3. Compare against a control test hitting an admin-gated route (e.g. `/users`) with the same `view`-role credential and confirm it correctly returns `403 Forbidden`, highlighting the router inconsistency.

```go
func (w *WebAuthnController) BeginRegistration(c *gin.Context) {
	ctx := c.Request.Context()
	user, ok := auth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}

	orm := w.App.AuthenticationProvider()
	uwas, err := orm.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %+v", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	options, err := w.inProgressRegistrationsStore.BeginWebAuthnRegistration(*user, uwas, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in BeginWebAuthnRegistration: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	optionsp := presenters.NewRegistrationSettings(*options)

	jsonAPIResponse(c, optionsp, "settings")
}
```

```go
func (w *WebAuthnController) FinishRegistration(c *gin.Context) {
	ctx := c.Request.Context()
	user, ok := auth.GetAuthenticatedUser(c)
	if !ok {
		logger.Sugared(w.App.GetLogger()).AssumptionViolationf("failed to obtain current user from context")
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	orm := w.App.AuthenticationProvider()
	uwas, err := orm.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	credential, err := w.inProgressRegistrationsStore.FinishWebAuthnRegistration(*user, uwas, c.Request, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in FinishWebAuthnRegistration: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}

	if sessions.AddCredentialToUser(ctx, w.App.AuthenticationProvider(), user.Email, credential) != nil {
		w.App.GetLogger().Errorf("Could not save WebAuthn credential to DB for user: %s", user.Email)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// Forward registered credentials for audit logs
	credj, err := json.Marshal(credential)
	if err != nil {
		w.App.GetLogger().Errorf("error in Marshal credentials: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}
	w.App.GetAuditLogger().Audit(audit.Auth2FAEnrolled, map[string]any{"email": user.Email, "credential": string(credj)})

	c.String(http.StatusOK, "{}")
```

```go
// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
```
