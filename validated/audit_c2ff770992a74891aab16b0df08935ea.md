### Title
Zip extractor path traversal ("Zip Slip") bypasses the containment check enforced by the tar/zstd extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`archive.NewExtractor` dispatches purely on a `Format` value that, for the cache/artifact extraction path, is auto-detected from file magic bytes rather than cryptographically bound to the archive contents. The zip extraction path (`ziplegacy`/`helpers/archives/zip_extract.go`) writes files using the raw, attacker-controlled `zip.File.Name` with no containment check, while the tar/zstd extractor (`commands/helpers/archive/tarzstd/tarzstd_extractor.go`) explicitly validates that every extracted path stays under the destination directory. Because format selection is content-sniffed and defaults to `Zip` when magic bytes don't match zstd/gzip, an attacker can trivially route a traversal payload through the unguarded zip path.

### Finding Description
`openArchive` in `commands/helpers/artifacts_downloader.go:148-172` determines the extraction format purely by inspecting the first 4 bytes of the downloaded artifact/cache file: [1](#0-0) 
- If bytes match the zstd magic, format = `TarZstd`.
- If bytes match gzip magic, format = `Gzip`.
- **Otherwise it defaults to `archive.Zip`.**

The same `openArchive` pattern is used by `commands/helpers/cache_extractor.go:646-658`, so both artifact and cache extraction are affected.

`archive.NewExtractor(format, f, size, wd)` then dispatches to whichever `NewExtractorFunc` is registered for that `Format`: [2](#0-1) 

The default-registered zip extractor (`ziplegacy.NewExtractor`) calls `archives.ExtractZipArchive`, which for every zip entry calls `extractZipFile(file)`: [3](#0-2) 

`extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry` all operate directly on `file.Name` — the attacker-controlled name from the zip central directory header — with `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(...)`: [4](#0-3) 

**There is no `filepath.Abs`/prefix check against the working directory anywhere in this path.** Go's standard `archive/zip` package does not sanitize `..` sequences in entry names, so a crafted zip with an entry named e.g. `../../evil` will write outside `wd`.

By contrast, `tarzstd.extractor.Extract` explicitly computes the absolute path and rejects anything escaping `e.dir`: [5](#0-4) 

Since format selection is based only on the first 4 bytes of file content (which the attacker fully controls, being the uploader of their own cache/artifact), an attacker can simply produce a payload that is a valid zip file (which naturally won't start with the zstd `0x28B52FFD` or gzip `0x1F8B` magic bytes) containing a `../` traversal entry. `openArchive` will classify it as `Zip`, and `ziplegacy.NewExtractor`/`extractZipFile` will write the entry to the traversal-resolved absolute path with zero containment enforcement — exactly the "format selection defeats an existing invariant" scenario described in the question.

Note: If `FF_USE_FASTZIP` is enabled, `fastzip.NewExtractor` (delegating to `github.com/saracen/fastzip`) is used instead for `Zip`/`ZipZstd`; I did not verify whether the vendored `fastzip` library itself performs path-containment checks internally, so that specific sub-case remains unconfirmed. The default, unconditional registration is `ziplegacy`, which is confirmed vulnerable.

### Impact Explanation
An attacker who controls the content of their own job's cache or artifact archive (a normal, unprivileged capability — caches/artifacts are produced by job scripts and later downloaded/extracted by the Runner helper binary on the build host) can craft a zip payload with path-traversal entry names. When the Runner subsequently extracts that cache/artifact (e.g., on a later pipeline run, a different job sharing the cache key, or the artifact download step), `extractZipFile` will write attacker-controlled file content to arbitrary paths outside the build/cache root reachable by the Runner process's OS permissions. This is a path traversal write ("Zip Slip") — it violates the "File operations must stay within intended build/cache/artifact roots" invariant, and depending on executor/OS user, could overwrite files elsewhere in the build directory tree or, on typical shared-executor deployments, other locations writable by the job's execution user.

### Likelihood Explanation
- Precondition matches the stated threat model: the attacker is an unprivileged pipeline author who fully controls their own cache/artifact contents uploaded via normal CI mechanisms (e.g. `cache:`/`artifacts:` config, or directly crafting the archive bytes since format detection is content-based, not extension/metadata based).
- No authentication or privilege escalation is required — the format is auto-detected from the archive's own bytes, so simply not matching zstd/gzip magic is sufficient to force the zip code path.
- The bug is deterministic and repeatable: same payload, same result every time.
- This is fully reachable through the documented cache/artifact extraction commands (`cache-extractor`, `artifacts-downloader`), both of which call `openArchive` → `archive.NewExtractor` → `extractZipFile`.

### Recommendation
Enforce path containment in `helpers/archives/zip_extract.go` symmetric to the tar/zstd extractor: before creating any parent directories or writing/symlinking a file, compute `filepath.Abs(filepath.Join(destDir, file.Name))` and reject (or skip with a warning, consistent with existing `pathErrorTracker`/`errorIfGitDirectory` patterns) any entry whose resolved path does not have `destDir` as a prefix. This check needs to be added to `extractZipFile`/`ExtractZipArchive` (and ideally centralized in a shared helper used by both zip and tar/zstd extractors) so format selection can never bypass containment enforcement. Additionally, consider not defaulting `openArchive`'s format guess silently to `Zip`; being explicit and validating the format matches expectations would reduce the attack surface for format-confusion in general.

### Proof of Concept
```go
package archive_test

import (
    "archive/zip"
    "bytes"
    "os"
    "path/filepath"
    "testing"

    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/require"

    "gitlab.com/gitlab-org/gitlab-runner/commands/helpers/archive"
    _ "gitlab.com/gitlab-org/gitlab-runner/commands/helpers/archive/ziplegacy"
)

func TestZipSlipTraversal_ziplegacy(t *testing.T) {
    // Build malicious zip with a traversal entry
    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, err := zw.Create("../../evil.txt")
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    // Extract into a nested "safe" subdirectory of a temp root
    root := t.TempDir()
    safeDir := filepath.Join(root, "a", "b", "safe")
    require.NoError(t, os.MkdirAll(safeDir, 0777))

    origWd, _ := os.Getwd()
    defer os.Chdir(origWd)
    os.Chdir(safeDir) // legacy extractor requires correct cwd

    input := buf.Bytes()
    extractor, err := archive.NewExtractor(archive.Zip, bytes.NewReader(input), int64(len(input)), safeDir)
    require.NoError(t, err)

    err = extractor.Extract(t.Context())
    require.NoError(t, err) // extraction "succeeds" silently

    // Assert: file must NOT exist outside safeDir/root (traversal escaped containment)
    escapedPath := filepath.Join(root, "a", "evil.txt")
    _, statErr := os.Stat(escapedPath)
    assert.NoError(t, statErr, "expected traversal file to be written outside safeDir, proving no containment check")
}
```
Expected assertion for the *fixed* code: `extractor.Extract` should return an error (or safely skip the entry) and `escapedPath` must not exist. Currently, it succeeds and writes outside the intended directory, confirming the vulnerability. A companion differential test running the identical `../evil` entry through `tarzstd.NewExtractor` shows it returns `"... cannot be extracted outside of chroot ..."` — demonstrating the two extractors enforce different containment guarantees for the same conceptual attack, exploitable purely via `openArchive`'s magic-byte format selection.

func openArchive(filename string) (*os.File, int64, archive.Format, error) {
	format := archive.Zip

	f, err := os.Open(filename)
	if err != nil {
		return nil, 0, format, err
	}

	var magic [4]byte
	_, _ = f.Read(magic[:])
	_, _ = f.Seek(0, io.SeekStart)
	switch {
	case bytes.HasPrefix(magic[:], zstMagic):
		format = archive.TarZstd
	case bytes.HasPrefix(magic[:], gzipMagic):
		format = archive.Gzip
	}

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
