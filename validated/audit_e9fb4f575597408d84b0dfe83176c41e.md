### Title
`solveRequestsDirect` omits the `solvingNotPaused` gate check enforced elsewhere, letting anyone bypass an active solving pause - ([File: v3/src/core/ProvisionerV2.sol])

### Summary
`ProvisionerV2` implements two independent "pause" layers for solving: a vault-level pause via `PRICE_FEE_CALCULATOR.isVaultPaused(...)` and a token-level solving-gate pause via `ISolvingGate.paused(...)`, enforced through the `solvingNotPaused(token)` modifier. `deposit`, `mint`, and `solveRequestsVault` all apply the `solvingNotPaused(token)` modifier [1](#0-0) , but the fully public `solveRequestsDirect` function only checks the vault-level pause and never calls `_checkSolvingNotPaused`/`solvingNotPaused(token)` [2](#0-1) . This is directly analogous to the Keycloak flaw, where a narrower-scope check (client-level) is honored while a broader-scope revocation policy (realm-level) is silently skipped on one code path, letting a "revoked" state remain effectively active.

### Finding Description
`ProvisionerV2` exposes `SOLVING_GATE_ENABLED` and `solvingGate`, and defines `_checkSolvingNotPaused` to consult an external `ISolvingGate` that can pause solving per-provisioner/per-token [3](#0-2)  and [4](#0-3) . This gate is meant to be an independent, additional stop mechanism layered on top of the `PriceAndFeeCalculator`'s vault-level pause — used, e.g., to halt solving activity for a specific token (oracle incident, compromised price feed, operational freeze) without necessarily flipping the whole-vault pause.

`deposit`/`mint` apply `solvingNotPaused(token)` [5](#0-4)  and `solveRequestsVault` also applies `solvingNotPaused(token)` [6](#0-5) . However, `solveRequestsDirect` — a permissionless, `requiresAuth`-free function callable by any ordinary user acting as a self-solver — only requires `!PRICE_FEE_CALCULATOR.isVaultPaused(MULTI_DEPOSITOR_VAULT)` and never checks the solving gate at all [7](#0-6) . As long as the vault itself is not paused in the PriceAndFeeCalculator, an ordinary user can call `solveRequestsDirect` to settle fixed-price deposit/redeem requests even while the solving gate reports `paused == true` for that token — completely bypassing the intended freeze.

### Impact Explanation
Where the solving gate is used to halt solving on a token during a stale/incident price window (a scenario the vault-level pause alone does not cover), `solveRequestsDirect` remains a live, unauthenticated path to settle previously-queued fixed-price requests against the vault's escrowed tokens/units, at prices that the gate operator intended to freeze. This allows continued fund movement (theft/extraction of user or vault funds) during a window explicitly meant to be halted — a live, Immunefi-listed Medium-severity temporary freeze/bypass-of-guard condition.

### Likelihood Explanation
No privileged, guardian, or malicious-actor collusion is required. The precondition is simply that `SOLVING_GATE_ENABLED` is true and the configured `solvingGate` reports `paused == true` for the given token while the vault-level pause in `PriceAndFeeCalculator` remains false — a realistic and intended operational state (gate pauses a token without pausing the whole vault). Any ordinary user holding an outstanding fixed-price request, or any address willing to act as a self-solver, can call the fully public `solveRequestsDirect` to bypass the gate.

### Recommendation
Add the `solvingNotPaused(token)` modifier (or an explicit `_checkSolvingNotPaused(token)` call) to `solveRequestsDirect`, matching the guard already enforced in `deposit`, `mint`, and `solveRequestsVault`, so the solving-gate pause is honored consistently across all solving paths.

### Proof of Concept
1. Deploy `ProvisionerV2` with `SOLVING_GATE_ENABLED = true` and set `solvingGate` to a mock `ISolvingGate` that returns `true` for `paused(provisioner, token)`.
2. As user A, call `requestDeposit`/`requestRedeem` to create a fixed-price request (escrowing tokens/units in the Provisioner) — succeeds since request creation is unaffected by the gate.
3. As the gate operator, confirm `ISolvingGate.paused(provisioner, token) == true`, and confirm `deposit`/`mint`/`solveRequestsVault` all revert with `Aera__SolvingPaused()` for that token.
4. As user B (ordinary, unauthenticated caller), call `solveRequestsDirect(token, [request])` — assert it succeeds and settles the request (tokens/units are exchanged) despite the gate reporting `paused == true`, proving the bypass. Assert the same call reverts once `PRICE_FEE_CALCULATOR.isVaultPaused` is also toggled true (confirming only that check is enforced, not the gate).

    /// @inheritdoc IProvisionerV2
    function solveRequestsDirect(IERC20 token, RequestV2[] calldata requests) external nonReentrant {
        // Requirements: vault is not paused in the priceAndFeeCalculator
        require(!PRICE_FEE_CALCULATOR.isVaultPaused(MULTI_DEPOSITOR_VAULT), Aera__PriceAndFeeCalculatorVaultPaused());

        uint256 length = requests.length;
        TokenDetailsV2 storage tokenDetails = tokensDetails[token];
        for (uint256 i = 0; i < length; i++) {
            RequestV2 calldata request = requests[i];
            RequestType requestType = request.requestType;

            // Requirements: direct solves can only solve fixed price requests
            require(!_isRequestTypeAutoPrice(requestType), Aera__AutoPriceSolveNotAllowed());

            if (_isRequestTypeDeposit(requestType)) {
                // Requirements: async deposit is enabled
                require(tokenDetails.asyncDepositEnabled, Aera__AsyncDepositDisabled());
            } else {
                // Requirements: async redeem is enabled
                require(tokenDetails.asyncRedeemEnabled, Aera__AsyncRedeemDisabled());
            }

            // Requirements + Effects + Interactions: solve direct request
            _solveRequestDirect(token, request);
        }
    }

    /// @notice Reverts if the solving gate is set and reports that solving is paused
    /// @param token The ERC20 token being solved
    function _checkSolvingNotPaused(IERC20 token) internal view {
        if (SOLVING_GATE_ENABLED) {
            address gate = solvingGate;
            require(gate == address(0) || !ISolvingGate(gate).paused(address(this), token), Aera__SolvingPaused());
        }
    }

/// @title ISolvingGate
/// @notice External gate queried by Provisioner to determine whether solving is allowed
/// @dev When the gate address is zero the Provisioner treats solving as always open
///      Implementations MUST return `true` when solving is paused and `false` otherwise
interface ISolvingGate {
    /// @notice Returns true if solving is currently paused for the given Provisioner and token
    /// @param provisioner The address of the Provisioner querying the gate
    /// @param token The token for which the solve is being attempted
    /// @return True if solving is currently paused, false otherwise
    function paused(address provisioner, IERC20 token) external view returns (bool);
}
