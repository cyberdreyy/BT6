### Title
Single scalar `unstaked_available_epoch_height` gates entire unstaked balance, freezing already-matured tranches after a later `unstake` call - (File: staking-pool/src/internal.rs)

### Summary
`inner_unstake` unconditionally overwrites `account.unstaked_available_epoch_height` with `env::epoch_height() + NUM_EPOCHS_TO_UNLOCK` on every call, and `internal_withdraw` gates withdrawal of the *entire* `account.unstaked` balance behind that single scalar. A delegator who calls `unstake` twice at different epochs has the earlier tranche's already-matured unlock time silently pushed forward by the later call.

### Finding Description
The broken binding: "NEAR withdrawable at time T == `unstaked` funds whose OWN unlock epoch has passed" is violated because the contract tracks only one `unstaked_available_epoch_height` field per account, shared across all deposits into `account.unstaked`, rather than per-tranche.

Code path:
- `inner_unstake` (staking-pool/src/internal.rs:124-181) adds `receive_amount` to `account.unstaked` and sets `account.unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK;` at line 156, unconditionally overwriting any prior value.
- `internal_withdraw` (staking-pool/src/internal.rs:42-68) checks only `account.unstaked >= amount` (line 47-50) and `account.unstaked_available_epoch_height <= env::epoch_height()` (line 51-54) — a single gate applied to the whole pooled `unstaked` balance, not to the specific tranche being withdrawn.

Exploit/reproduction sequence for the same delegator:
1. At epoch `E`, call `unstake(large_amount)` → `account.unstaked = large_amount`, `unstaked_available_epoch_height = E+4`.
2. At epoch `E+3` (before large_amount matures), call `unstake(small_amount)` → `account.unstaked = large_amount + small_amount`, `unstaked_available_epoch_height` is overwritten to `E+7`.
3. At epoch `E+4`, `large_amount`'s own 4-epoch wait has elapsed, but calling `withdraw(large_amount)` invokes `internal_withdraw`, which asserts `account.unstaked_available_epoch_height (E+7) <= env::epoch_height() (E+4)` — this fails, blocking withdrawal of funds that should already be free.

No existing guard (`assert_owner`, `assert_self`, `internal_ping`, U256 rounding, etc.) addresses this because the check is deliberately a single-field comparison by design of the reference contract; there is no per-tranche bookkeeping to protect against.

### Impact Explanation
No NEAR leaves the contract improperly, and no third party gains funds — the delegator's own already-vested `large_amount` becomes temporarily inaccessible, extended from `E+4` up to `E+7` (or whatever the latest `unstake` call sets). This matches the "funds frozen for at least one epoch but recoverable" High-impact category: the affected delegator cannot withdraw matured NEAR on schedule, though it is fully recoverable once the later gate epoch arrives. This is deterministic and repeatable by any delegator across any pool built from this staking-pool contract, for any pair of staggered `unstake` calls.

### Likelihood Explanation
Trivial to trigger: it requires only two ordinary `unstake` calls from the same account at different epochs, both fully within an unprivileged delegator's normal capabilities, no special balances or races needed. Any delegator who unstakes more than once before withdrawing will hit this behavior; likelihood of occurrence in practice is high given staggered unstaking is a common usage pattern.

### Recommendation
Track unstaked funds per-tranche (e.g., a list/queue of `(amount, available_epoch_height)` entries, or use the min/earliest maturity instead of overwriting), or only extend the gate for the newly added portion while keeping already-matured portions withdrawable immediately. At minimum, `inner_unstake` should not regress the availability epoch for already-unlockable balance — e.g., withdraw eligibility should be computed as "funds present before the most recent unstake are gated by the earlier epoch."

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }

    pub(crate) fn inner_unstake(&mut self, amount: u128) {
        assert!(amount > 0, "Unstaking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        assert!(
            self.total_staked_balance > 0,
            "The contract doesn't have staked balance"
        );
        // Calculate the number of shares required to unstake the given amount.
        // NOTE: The number of shares the account will pay is rounded up.
        let num_shares = self.num_shares_from_staked_amount_rounded_up(amount);
        assert!(
            num_shares > 0,
            "Invariant violation. The calculated number of \"stake\" shares for unstaking should be positive"
        );
        assert!(
            account.stake_shares >= num_shares,
            "Not enough staked balance to unstake"
        );

        // Calculating the amount of tokens the account will receive by unstaking the corresponding
        // number of "stake" shares, rounding up.
        let receive_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);
        assert!(
            receive_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        account.stake_shares -= num_shares;
        account.unstaked += receive_amount;
        account.unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK;
        self.internal_save_account(&account_id, &account);

        // The amount tokens that will be unstaked from the total to guarantee the "stake" share
        // price never decreases. The difference between `receive_amount` and `unstake_amount` is
        // paid from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let unstake_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);

        self.total_staked_balance -= unstake_amount;
        self.total_stake_shares -= num_shares;

        env::log(
            format!(
                "@{} unstaking {}. Spent {} staking shares. Total {} unstaked balance and {} staking shares",
                account_id, receive_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }
