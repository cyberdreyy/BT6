### Title
ERC4626 first-depositor inflation can steal programmable-borrower principal - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` deposits pool principal into the configured ERC4626 vault without enforcing a minimum share output or validating that the received shares retain asset value. An unprivileged depositor in a newly configured or low-liquidity vault can perform the standard first-depositor donation attack, cause the pool’s deposit to mint zero shares, redeem the donated and deposited assets, and leave the credit vault with unbacked strategy tokens. [1](#0-0) 

### Finding Description
At epoch start, `onStartEpoch` records `startAssets` before calling `_depositToVault`, and `_depositToVault` accepts whatever `vault.deposit` returns without checking `shares`, received value, or slippage. [2](#0-1) [1](#0-0) 

For an ERC4626 whose exchange rate is based on spot `totalAssets`, an attacker can:

1. Deposit `1` wei into an empty vault and receive one share.
2. Donate `D` underlying directly to the vault.
3. Let `ProgrammableBorrower` deposit pool principal `P`.
4. If `D >= P`, the vault mints `P * 1 / (1 + D) == 0` shares.
5. Redeem the sole share for `1 + D + P`, extracting `P` of pool assets.

`ProgrammableBorrower` values its position solely as `convertToAssets(vault.balanceOf(this))`, so zero shares correctly produce zero recoverable assets after the theft. [3](#0-2)  However, `totalInterestDueNow` only floors vault losses against epoch interest and does not communicate principal impairment to `IdleCDOEpochVariant`. [4](#0-3) 

During a normal minted-interest stop, the CDO requests only pending withdrawals and mints interest into the strategy, so the stolen principal can remain represented by CDO strategy tokens until a withdrawal or close-pool recall exposes the missing backing. [5](#0-4)  On close, the CDO adds the strategy-token balance to the borrower recall amount, but the borrower adapter has no vault assets to withdraw; the subsequent `transferFrom` fails and enters borrower-default handling. [6](#0-5) [7](#0-6) [8](#0-7) 

### Impact Explanation
With `P = 10,000 USDC`, an attacker can deposit `1` wei and donate `10,000 USDC` before the first epoch deposit. The pool deposit mints zero shares, and the attacker redeems approximately `20,000 USDC`, for a profit of approximately `10,000 USDC`.

The broken invariant is fair deposit backing and solvency: the CDO mints/retains `P` strategy tokens while the programmable borrower holds no redeemable vault position. Withdrawal claims cannot be paid from the stolen principal, and close-pool settlement is forced into default. This is direct theft of LP funds, with loss equal to the deposited principal less any residual shares obtained.

### Likelihood Explanation
The attack requires the facility to use a permissionless ERC4626 vault whose share calculation is vulnerable to donation inflation, such as an empty vault using `assets * supply / totalAssets` without virtual shares, dead shares, or a sufficient initial deposit. That configuration is supported by `setVault`/factory deployment because the code accepts any ERC4626 with the matching asset and performs no share-output check. [9](#0-8)  The attacker needs no privileged role and only has to deposit into/donate to the vault before `onStartEpoch`.

Existing non-reentrancy, CDO-only hook, and allowance checks do not prevent the attack because the malicious state already exists when the honest manager calls `startEpoch`.

### Recommendation
- Require a non-zero and economically sufficient share amount from every vault deposit, for example `shares >= minShares` and `convertToAssets(shares) >= _assetAmount - maxDepositLoss`.
- Prefer vaults with inflation resistance such as virtual assets/shares or pre-seeded locked shares.
- Track actual post-deposit recoverable value rather than assuming the deposited amount remains principal.
- Propagate vault principal loss to CDO accounting instead of collapsing it inside `totalInterestDueNow`; otherwise minted-interest mode can retain unbacked strategy tokens until default.

### Proof of Concept
A Foundry mainnet-fork PoC can use the real USDC token and a minimal ERC4626 with spot `totalAssets` accounting:

```solidity
function testProgrammableBorrowerVaultInflationStealsEpochDeposit() public {
    vm.createSelectFork("mainnet", 19_225_935);

    uint256 poolDeposit = 10_000e6;
    Spot4626 spotVault = new Spot4626(USDC);

    // Deploy/configure the credit vault exactly as a programmable-borrower
    // deployment, with spotVault as `programmableBorrower.vault`.
    // LP deposits poolDeposit into AA.
    depositAA(poolDeposit);

    // Attacker seeds one share and inflates the share price.
    deal(USDC, attacker, poolDeposit + 1);
    vm.startPrank(attacker);
    IERC20(USDC).approve(address(spotVault), 1);
    spotVault.deposit(1, attacker);
    IERC20(USDC).transfer(address(spotVault), poolDeposit);
    vm.stopPrank();

    // Honest manager starts the epoch. ProgrammableBorrower deposits the pool
    // principal and receives zero shares due to integer division.
    vm.prank(manager);
    cdoEpoch.startEpoch();

    assertEq(spotVault.balanceOf(address(programmableBorrower)), 0);

    // Attacker redeems the only share for the donation plus pool principal.
    uint256 attackerBefore = IERC20(USDC).balanceOf(attacker);
    vm.prank(attacker);
    spotVault.redeem(1, attacker, attacker);

    assertEq(
        IERC20(USDC).balanceOf(attacker) - attackerBefore,
        poolDeposit + 1 + poolDeposit
    );

    // The CDO still carries poolDeposit strategy tokens while the borrower has
    // no vault assets. A close-pool recall fails and defaults.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 1);

    assertTrue(cdoEpoch.defaulted());
}
```

The vulnerable vault’s deposit formula is the canonical `assets * totalSupply / totalAssets` calculation with no inflation offset; the critical production flaw is that `_depositToVault` accepts the resulting zero shares and continues epoch accounting.
