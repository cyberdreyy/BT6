### Title
Divide-before-multiply in Jovian DA-footprint gas estimation causes systematic under-metering of block resource limits - (File: crates/common/evm/src/executor/block_executor.rs)

### Summary
`BaseBlockExecutor::jovian_da_footprint_estimation` computes the per-transaction DA-footprint charge used to enforce the Jovian DA-footprint block resource limit by first dividing the FastLZ-estimated compressed size (which is scaled by `1e6`) by `1_000_000`, discarding the fractional remainder, and only then multiplying by `da_footprint_gas_scalar`. This is the same "divide before multiply" pattern flagged in the external report (FluidLocker `_getUnlockingPercentage`), where truncating before scaling systematically discards value that would otherwise be preserved if the multiplication happened first.

### Finding Description
`jovian_da_footprint_estimation` is:
```rust
let encoded = tx_env
    .encoded_bytes()
    .map_or_else(
        || estimate_tx_compressed_size(tx.tx().encoded_2718().as_ref()),
        |encoded| estimate_tx_compressed_size(encoded),
    )
    .saturating_div(1_000_000);
...
Ok(encoded.saturating_mul(da_footprint_gas_scalar))
``` [1](#0-0) 

`estimate_tx_compressed_size` (i.e. `tx_estimated_size_fjord`) returns an estimated compressed size *scaled by `1e6`*: `max(minTransactionSize, intercept + fastlzCoef*fastlzSize)`. [2](#0-1) 

Dividing this 1e6-scaled value by `1_000_000` first (`saturating_div(1_000_000)`) truncates up to `999_999` units of the scaled size — i.e. up to almost one whole "byte" of the estimate — *before* the `da_footprint_gas_scalar` multiplication is applied. Had the multiplication been performed first (`size_scaled * scalar / 1_000_000`), the same truncation would only discard a fraction of a single final gas unit, not up to `scalar - 1` gas units. This mirrors the reported root cause exactly: dividing before multiplying discards precision that scaling first would have preserved.

The equivalent, unused duplicate helper `L1FeeParams::jovian_da_footprint` in the shared fee-math crate exhibits the identical ordering and is explicitly documented as intentional ("the estimated size ... divided back down by 1e6 and multiplied by the DA-footprint gas scalar"): [3](#0-2) 

Because the executor's own copy in `block_executor.rs` is the one actually wired into transaction execution, it directly determines: (1) whether a transaction is rejected for exceeding the remaining `da_footprint_available` budget, and (2) the `da_footprint_used` value accumulated into the block and returned as `blob_gas_used` in the execution result, which is enforced against the block gas limit: [4](#0-3) [5](#0-4) 

### Impact Explanation
Every unprivileged sender's transaction that is processed once Jovian is active has its DA-footprint gas charge computed by first truncating the compressed-size estimate to whole "byte" units and only then multiplying by the scalar. This systematically under-counts the true DA-footprint cost for essentially every transaction (any transaction whose 1e6-scaled size estimate is not an exact multiple of `1_000_000`, which is the common case), letting the block accept more transaction data than the DA-footprint budget is meant to permit. This directly weakens the "DA footprint block limit" resource-metering mechanism that the Jovian upgrade introduces specifically to bound L1 data-availability exposure per block — i.e., a resource-metering bypass reachable by any ordinary transaction sender, which is explicitly in scope per the allowed reachable-path list ("block building and resource metering").

### Likelihood Explanation
High likelihood of triggering on essentially every transaction post-Jovian, since the compressed-size estimate is scaled by `1e6` and will only rarely land on an exact multiple of `1_000_000`; no special preconditions, privileges, or attacker crafting are required beyond sending an ordinary transaction once Jovian is active.

### Recommendation
Compute the DA-footprint gas by multiplying the 1e6-scaled compressed size by `da_footprint_gas_scalar` first and dividing by `1_000_000` afterward (`size_scaled.saturating_mul(scalar) / 1_000_000`), in both `jovian_da_footprint_estimation` (`block_executor.rs`) and the duplicate `L1FeeParams::jovian_da_footprint` (`params.rs`), to avoid discarding precision before scaling.

### Proof of Concept
For a transaction whose FastLZ-estimated compressed size scaled value is, e.g., `100_500_000` (i.e., 100.5 "bytes") and `da_footprint_gas_scalar = 7`:
- Current code: `100_500_000 / 1_000_000 = 100` (fractional 0.5 byte discarded), then `100 * 7 = 700`.
- Multiply-first order: `100_500_000 * 7 = 703_500_000`, then `/ 1_000_000 = 703`.

The current implementation under-reports the DA-footprint charge by `3` gas units for this single transaction; this loss recurs on nearly every transaction, compounding across a block and allowing more DA footprint to be admitted than the resource-metering rule intends.

**Note on confidence:** I could not access the external OP-stack Jovian DA-footprint specification referenced in the code comment (`https://github.com/ethereum-optimism/specs/.../jovian/exec-engine.md#da-footprint-block-limit`) to confirm whether upstream reference clients (e.g. op-geth) compute this with the same divide-then-multiply order. If the spec mandates this exact order, the finding would be intentional/spec-compliant rather than a genuine divergence bug, and the "systematic under-metering" would be a property of the spec itself rather than an implementation flaw. This should be verified against the linked spec and against op-geth's reference implementation before treating this as a confirmed deviation.

/// Calculate the estimated compressed transaction size in bytes, scaled by 1e6.
/// This value is computed based on the following formula:
/// max(minTransactionSize, intercept + fastlzCoef*fastlzSize)
pub fn tx_estimated_size_fjord(input: &[u8]) -> u64 {
    let fastlz_size = flz_compress_len(input) as u64;

    fastlz_size
        .saturating_mul(L1_COST_FASTLZ_COEF)
        .saturating_sub(L1_COST_INTERCEPT)
        .max(MIN_TX_SIZE_SCALED)
}

    /// Calculates the Jovian DA-footprint gas for posting the enveloped transaction bytes `input`.
    ///
    /// The footprint is the FastLZ-estimated compressed size (scaled by `1e6`, as
    /// [`tx_estimated_size_fjord`] returns) divided back down by `1e6` and multiplied by the
    /// DA-footprint gas scalar. Returns zero when no scalar is set (pre-Jovian or unconfigured).
    /// Mirrors the reference `jovian_da_footprint_estimation`.
    pub fn jovian_da_footprint(&self, input: &[u8]) -> u64 {
        let Some(scalar) = self.da_footprint_gas_scalar else {
            return 0;
        };
        U256::from(tx_estimated_size_fjord(input))
            .wrapping_div(U256::from(1_000_000u64))
            .saturating_mul(scalar)
            .saturating_to::<u64>()
    }
