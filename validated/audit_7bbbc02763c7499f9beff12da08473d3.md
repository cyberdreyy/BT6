### Title
Miner-triggered reset of `last_activity_time` lets a stalled sortition winner indefinitely suppress the miner-inactivity timeout - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`check_latest_block_in_tenure` calls `signer_db.update_last_activity_time` whenever the *current sortition's own miner* re-proposes a block that does not confirm the tenure's already-signed tip, treating the invalid/conflicting proposal as "miner activity." Because this activity timestamp is the same value `SortitionState::is_timed_out` (v1) / `SortitionState::is_timed_out` (v2) reads to decide whether the current miner has stalled and should be invalidated (so the signer set can fall back to the prior/next miner), the current sortition winner can indefinitely keep itself "alive" from the signer's point of view by repeatedly gossiping low/duplicate block proposals, without ever producing forward progress.

### Finding Description
`check_latest_block_in_tenure` is the shared helper invoked from both `SortitionsView::check_proposal` (v1) and `GlobalStateView::check_proposal` (v2) on every incoming `BlockProposal`, before the node is even asked to validate it: [1](#0-0) 

When the proposed block does not confirm the last signed block in its own tenure (`block.header.chain_length <= info.block.header.chain_length`), the code deliberately counts this as valid miner activity and calls `signer_db.update_last_activity_time`: [2](#0-1) 

This is reachable from `check_proposal` for a block whose consensus hash matches the *current* sortition, i.e. for the very miner whose liveness the timeout is supposed to police: [3](#0-2) 

Crucially, the pubkey-hash check that verifies the proposer is the legitimate sortition winner runs *before* this call, so no majority, no other signer's key, and no privileged access is required — only the one miner slot that won the current sortition: [4](#0-3) 

The very timestamp being reset is exactly what `is_timed_out` measures to decide whether the current miner should be marked invalid so the signer can fall back to another miner: [5](#0-4) 

`is_timed_out` is checked at the very top of `check_proposal`, and the v2 equivalent behaves identically: [6](#0-5) [7](#0-6) 

The underlying storage primitives make the equality explicit: the same `tenure_activity` row is written by the "invalid proposal" path and read by the "has the miner gone inactive" path: [8](#0-7) 

The guard limiting repeated resets, `reorg_attempts_activity_timeout`, only bounds the case where the tenure's last block has already reached `signed_group` (globally observed) status; while the tenure's last signed block is still only locally accepted (`signed_group == None`), every re-proposal unconditionally refreshes the timer: [2](#0-1) 

This mirrors the reported bug class exactly: a check that is supposed to only validate state as a side effect resets a cooldown/liveness timer, and the actor being policed by that timer is the one who can trigger the check.

### Impact Explanation
This breaks a liveness invariant, not merely a bookkeeping detail: `block_proposal_timeout`/`is_timed_out` exists specifically so that signers stop waiting on a miner that has stopped making progress and fall back to a usable miner (documented explicitly in the code comments: "...so they could never fall back to the prior miner and the tenure could never recover"). A single one-slot miner that wins a sortition but withholds a valid, tenure-advancing block can instead gossip cheap, already-invalid (low/duplicate height) block proposals for its own tenure to keep resetting `last_activity_time`, preventing `SortitionMinerStatus` from ever flipping to `InvalidatedBeforeFirstBlock`/`InvalidatedAfterFirstBlock`. This wedges the signer set's fallback state machine, matching the "High - a signer wedged into never signing valid blocks... acting on a stale... threshold" impact category: signers are stuck waiting indefinitely on a miner they should have already abandoned.

### Likelihood Explanation
The trigger only requires the actual sortition winner's private key (to sign a header that recovers to the expected `miner_pkh`) and the ability to gossip a `BlockProposal` over StackerDB — both trivially available to any miner during its own tenure. No majority of signers, no other party's key, and no local/auth-token access are needed, satisfying the "one-slot miner plus gossip" reachability bar. The unconditional-reset window (while `signed_group` is unset) is easy to sustain since it only requires the tenure's last signed block to not yet be globally observed as accepted, a common transient state.

### Recommendation
Do not let a rejected/non-confirming proposal from the *currently tracked* sortition winner refresh `last_activity_time` for that same tenure when the check fails specifically because the miner is not making forward progress (`chain_length <= info.block.header.chain_length`). At minimum, scope the "count invalid proposal as activity" behavior in `check_latest_block_in_tenure` to genuinely ambiguous/slow-tip cases (e.g., only when a *different*, higher-numbered block was in fact validated/signed since), and always enforce the `reorg_attempts_activity_timeout` bound (rather than only when `signed_group` is already set) so a still-locally-accepted tip cannot be used to refresh the timer without bound.

### Proof of Concept
1. Miner M wins the current sortition; the signer's `cur_sortition.data.consensus_hash` is set to M's tenure, `miner_status = Valid`.
2. M proposes and gets one block signed/locally accepted in its tenure (so `get_last_signed_block` returns a `BlockInfo` with `signed_self` set but `signed_group` still `None`, e.g. because global acceptance hasn't propagated).
3. M then withholds further progress and, at intervals shorter than `block_proposal_timeout`, gossips additional `BlockProposal` messages for the same tenure with `chain_length <= info.block.header.chain_length` (e.g., re-sending the same or an older block).
4. Each such proposal passes the pubkey-hash check in `check_proposal` (it's genuinely signed by M) and then fails `confirms_latest_block_in_same_tenure` → `check_latest_block_in_tenure`, but on the way out it calls `signer_db.update_last_activity_time(&block.header.consensus_hash, now)` because `info.signed_group` is `None` (`is_none_or` short-circuits true).
5. On the next `check_proposal`/`check_miner_inactivity` pass, `SortitionState::is_timed_out` recomputes `elapsed` from the just-refreshed `last_activity_time` and returns `false`, so `miner_status` stays `Valid` and the signer never falls back to the prior/next miner, even though M produces no further valid, tenure-advancing blocks.

            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()

                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).

                        warn!("Failed to update last activity time: {e}");
                    }
                }

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    /// Check if the sortition identified by the ConsensusHash is timed out based on
    /// the blocks within the signer db and the block proposal timeout
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        signer_db: &SignerDb,
        eval: &GlobalStateEvaluator,
        local_address: &StacksAddress,
        timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = signer_db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) =
            signer_db.get_burn_block_received_time_from_signers(eval, sortition, local_address)?
        else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = signer_db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };
        if elapsed > timeout {
            info!("Sortition has timed out";
                "sorition" => %sortition,
                "timeout" => %timeout.as_secs(),
                "elapsed" => %elapsed.as_secs()
            )
        }
        Ok(elapsed > timeout)
    }

    /// Update the tenure (identified by consensus_hash) last activity timestamp
    pub fn update_last_activity_time(
        &mut self,
        tenure: &ConsensusHash,
        last_activity_time: u64,
    ) -> Result<(), DBError> {
        debug!("Updating last activity for tenure"; "consensus_hash" => %tenure, "last_activity_time" => last_activity_time);
        self.db.execute("INSERT OR REPLACE INTO tenure_activity (consensus_hash, last_activity_time) VALUES (?1, ?2)", params![tenure, u64_to_sql(last_activity_time)?])?;
        Ok(())
    }

    /// Get the last activity timestamp for a tenure (identified by consensus_hash)
    pub fn get_last_activity_time(&self, tenure: &ConsensusHash) -> Result<Option<u64>, DBError> {
        let query =
            "SELECT last_activity_time FROM tenure_activity WHERE consensus_hash = ? LIMIT 1";
        let Some(last_activity_time_i64) = query_row::<i64, _>(&self.db, query, &[tenure])? else {
            return Ok(None);
        };
        let last_activity_time = u64::try_from(last_activity_time_i64).map_err(|e| {
            error!("Failed to parse db last_activity_time as u64: {e}");
            DBError::Corruption
        })?;
        Ok(Some(last_activity_time))
    }
