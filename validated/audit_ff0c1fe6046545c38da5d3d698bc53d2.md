### Title
Legacy zip extractor lacks path-traversal (zip-slip) protection, unlike the tar+zstd extractor - ([File: helpers/archives/zip_extract.go])

### Summary
The default artifact/cache zip extractor (`ziplegacy`, used whenever `FF_USE_FASTZIP` is left at its default `false` value) writes every zip entry using the raw `file.Name` from the archive with no path/chroot validation, unlike the tar+zstd extractor which explicitly enforces that resolved paths stay under the target directory. This means a zip archive entry containing `..` path segments can write outside the intended build/cache root during extraction of artifacts pulled by `commands/helpers/artifacts_downloader.go`.

### Finding Description
`ArtifactsDownloaderCommand.Execute` [1](#0-0)  downloads the artifact to a safe, randomly named temp file (`download` itself only writes to that fixed temp path via `os.Create(file)` [2](#0-1) , so it is not the code that decides where extracted files land) and then calls `archive.NewExtractor(format, f, size, wd)` followed by `extractor.Extract(...)`, where `wd` is the process's current working directory (the job's own build directory, set by trusted shell/executor code before the helper runs, not attacker-controlled).

For `archive.Zip`/`archive.ZipZstd`, unless `FF_USE_FASTZIP=true` (default `false` [3](#0-2) ), the registered extractor is `ziplegacy.NewExtractor` [4](#0-3) . Its `Extract` method never uses the `dir` field it was constructed with; it calls `archives.ExtractZipArchive(zr)` [5](#0-4) , which in turn calls `extractZipFile(file)` for every entry [6](#0-5) . `extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, and `extractZipFileEntry` all operate directly on `file.Name` — the literal string encoded in the zip header — with `os.Mkdir(file.Name, ...)`, `os.OpenFile(file.Name, ...)`, and `os.Symlink(...)` [7](#0-6) . There is no `filepath.Clean`/prefix check that keeps the resolved path inside the extraction root.

This is a direct contrast with the tar+zstd extractor, which explicitly resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any path that isn't prefixed by `e.dir`: `if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir { return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir) }` [8](#0-7) . The only sanitation applied to zip entries elsewhere in the archive package is a `.git`-directory warning, `errorIfGitDirectory`, which does not address `..` traversal at all [9](#0-8) .

### Impact Explanation
If an attacker-influenced zip artifact (or cache archive, since `cache_extractor.go` uses the same `archive.NewExtractor` dispatch [10](#0-9) ) contains entries with `..` segments, extraction on a consuming job on the same runner can write/overwrite files outside that job's own build directory — including sibling build or cache directories for other concurrent or subsequent jobs on the same host/runner, since `wd` is only used as the working directory and is never enforced as a containment boundary by this extractor.

### Likelihood Explanation
Exploitability hinges on whether a pipeline author can get such `..`-containing entry names into the zip that Runner later downloads and extracts (this requires the producing job/Runner's own archiver, `archives.CreateZipArchive`, to preserve or accept traversal-capable names when packaging `artifacts:paths`). I was not able to fully inspect `helpers/archives/zip_create.go` in this session to confirm whether entry names are already sanitized/relativized at archive-creation time, so I cannot state with certainty that this gap is reachable end-to-end from ordinary `.gitlab-ci.yml` artifact/cache configuration. The code-level asymmetry between the tar+zstd extractor (chroot-checked) and the default zip/ziplegacy extractor (not chroot-checked) is confirmed and is a real missing invariant regardless.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go` (or wherever `extractZipFile`/`ExtractZipArchive` resolves output paths): join/resolve each entry against the extraction root and reject any entry whose resolved absolute path is not prefixed by that root, for both file and symlink entries.

### Proof of Concept
Go unit test idea (place under `helpers/archives` or `commands/helpers/archive/ziplegacy`):
```go
func TestZipExtractPathTraversal(t *testing.T) {
    outer := t.TempDir()
    victim := filepath.Join(outer, "victim-job")
    require.NoError(t, os.Mkdir(victim, 0777))

    attacker := filepath.Join(outer, "attacker-job")
    require.NoError(t, os.Mkdir(attacker, 0777))

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    f, _ := zw.Create("../victim-job/pwned.txt")
    _, _ = f.Write([]byte("owned"))
    zw.Close()

    origWD, _ := os.Getwd()
    defer os.Chdir(origWD)
    os.Chdir(attacker)

    extractor, err := ziplegacy.NewExtractor(bytes.NewReader(buf.Bytes()), int64(buf.Len()), attacker)
    require.NoError(t, err)
    _ = extractor.Extract(context.Background())

    _, err = os.Stat(filepath.Join(victim, "pwned.txt"))
    assert.Error(t, err, "extraction must not escape into sibling job directory")
}
```
Expected assertion (after fix): the extractor returns an error and `victim-job/pwned.txt` is never created; currently (pre-fix) the file is written into the sibling directory, confirming the missing isolation boundary.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
