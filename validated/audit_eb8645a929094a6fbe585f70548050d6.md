### Title
Receiver field null-byte padding collision allows signature reuse across `Receiver=""` and `Receiver=<42 raw NUL bytes>` MessageBody values - (File: core/services/gateway/api/message.go)

### Summary
`GetRawMessageBody` builds the signed payload by zero-padding `MessageId`, `Method`, `DonId`, and `Receiver` into fixed-size buffers with no length prefix or delimiter, then flattening them for signing/verification. `Validate` rejects trailing NUL bytes for `MessageId`, `Method`, and `DonId`, but performs no such check for `Receiver`. As a result, an empty `Receiver` and a `Receiver` string consisting of exactly `MessageReceiverLen` (42) raw NUL bytes both serialize to identical zero-padded bytes, making a signature valid for both message bodies interchangeably.

### Finding Description
`GetRawMessageBody` pads each field independently into a fixed-size `[]byte` buffer via `make`+`copy`, then `Sign`/`ExtractSigner` flatten and sign/verify over these buffers: [1](#0-0) 

`Validate` enforces a length check on `Receiver` (must be `0` or `MessageReceiverLen`) but, unlike `MessageId`, `Method`, and `DonId`, never checks for embedded/suffix NUL characters in `Receiver`: [2](#0-1) 

Because the `Receiver` buffer is zero-initialized (`make([]byte, MessageReceiverLen)`), a `Receiver` of length `0` and a `Receiver` of length `42` made entirely of NUL bytes (`"\x00"` × 42) both produce the exact same 42-byte all-zero slice after `copy`. Both pass the length check (`len==0` or `len==MessageReceiverLen`), and neither is blocked by any NUL-suffix rule (which exists only for the other three fields). The internal helper `StringToAlignedBytes` in `core/services/gateway/common/utils.go` even carries the explicit comment "input string can't have any 0x0 characters", confirming this padding scheme is known-unsafe for NUL-containing inputs, yet `GetRawMessageBody` implements the same unsafe pattern with no enforcement.

Consequently, a message signed with `Receiver=""` produces byte-identical signed data (and therefore an identical valid signature) as a hypothetical message with `Receiver` set to 42 raw NUL bytes. An unprivileged attacker who observes any validly signed gateway request with an empty `Receiver` (e.g. a broadcast-style request) can re-encode the same `Signature` and `Body` fields but substitute `Receiver` with a 42-byte NUL string (encodable in JSON via `\u0000` escapes) and have it pass `ExtractSigner`/signature verification as though signed by the original sender, since `Message.Validate` recovers the same signer address for both.

### Impact Explanation
This breaks the invariant that a signature uniquely commits to the full `MessageBody`, enabling cross-receiver confusion of a validly signed request: an attacker-modified message purporting to target a different (encoded-as-NUL) receiver would still verify as authentically signed by the original sender. If any gateway handler routes or authorizes based on `Body.Receiver` after signature verification, this allows request impersonation/authorization confusion without possessing the signer's private key — matching the "cross-user response/request confusion" and "request impersonation" bounty impact classes.

### Likelihood Explanation
Exploitation requires only the ability to submit a signed gateway/API message body as an unauthenticated network client — the attacker does not need the private key, only an already-observed valid signature over a `Receiver=""` message, which is copied verbatim alongside a substituted `Receiver` value. No operator/admin access, no OCR/DON compromise, and no network-layer trust is needed. The main uncertainty is whether any current handler treats `Receiver=""` and `Receiver=<42 NUL bytes>` differently in a security-relevant way (i.e., whether this collision is currently exploitable end-to-end) — this could not be fully confirmed since the index does not show all handlers' use of `Body.Receiver` for authorization/routing decisions.

### Recommendation
Add an explicit rejection of NUL bytes (not just suffix, ideally any embedded `\x00`) in `Receiver`, matching the "no NUL" invariant already documented (and enforced for `MessageId`/`Method`/`DonId`) — e.g. `if strings.Contains(m.Body.Receiver, NullChar) { return errors.New("invalid Receiver: contains null byte") }`. More robustly, replace the ad-hoc zero-padding scheme in `GetRawMessageBody` with length-prefixed or delimiter-safe encoding for all fields so that no combination of field values can produce colliding raw signed bytes.

### Proof of Concept
```go
func TestMessage_ReceiverNullByteCollision(t *testing.T) {
    body1 := api.MessageBody{
        MessageId: "abcd",
        Method:    "request",
        DonId:     "donA",
        Receiver:  "",
        Payload:   []byte("datadata"),
    }
    body2 := body1
    body2.Receiver = strings.Repeat("\x00", api.MessageReceiverLen)

    raw1 := api.GetRawMessageBody(&body1)
    raw2 := api.GetRawMessageBody(&body2)

    // Assert the two semantically different bodies produce identical signed bytes.
    require.Equal(t, raw1, raw2)

    // Confirm body2 passes length validation despite differing from body1.
    msg2 := &api.Message{Body: body2}
    privateKey, _ := crypto.GenerateKey()
    require.NoError(t, msg2.Sign(privateKey))
    require.NoError(t, msg2.Validate())

    // Confirm a signature produced for body1 verifies successfully for body2 too.
    msg1 := &api.Message{Body: body1}
    require.NoError(t, msg1.Sign(privateKey))
    msg2.Signature = msg1.Signature
    signer1, err1 := msg1.ExtractSigner()
    signer2, err2 := msg2.ExtractSigner()
    require.NoError(t, err1)
    require.NoError(t, err2)
    require.Equal(t, signer1, signer2) // signature reused across distinct Receiver values
}
```
Expected result: `raw1 == raw2` despite `body1.Receiver != body2.Receiver`, and the signature computed for `body1` also validates for `body2`, confirming the invariant "request binding uniqueness" is violated for the `Receiver` field.

func GetRawMessageBody(msgBody *MessageBody) [][]byte {
	alignedMessageId := make([]byte, MessageIdMaxLen)
	copy(alignedMessageId, msgBody.MessageId)
	alignedMethod := make([]byte, MessageMethodMaxLen)
	copy(alignedMethod, msgBody.Method)
	alignedDonId := make([]byte, MessageDonIdMaxLen)
	copy(alignedDonId, msgBody.DonId)
	alignedReceiver := make([]byte, MessageReceiverLen)
	copy(alignedReceiver, msgBody.Receiver)
	return [][]byte{alignedMessageId, alignedMethod, alignedDonId, alignedReceiver, msgBody.Payload}
}
