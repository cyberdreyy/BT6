### Title
Unauthenticated flood of distinct signed gateway messages can evict a victim's pending callback via time-ordered `pruneCallbacks` eviction, causing denial of response delivery - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` inserts every message that passes basic parsing/signature checks into the shared `h.savedCallbacks` map with no per-sender quota, allowlist, or dedup check (explicitly marked `TODO: apply allowlist and rate-limiting here`). Because `pruneCallbacks` evicts entries strictly by `createdAt` (oldest half when the map exceeds `MaxSavedCallbacks`), an attacker who floods the gateway with more than `defaultMaxSavedCallbacks` (20000) freshly-signed, self-generated messages within a `CallbackPruneIntervalSec` window can cause a victim's earlier, still-pending callback to be evicted before the DON responds.

### Finding Description
The attacker path is: `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) decodes and calls `msg.Validate()` [1](#0-0)  which only checks structural fields and signature validity (`core/services/gateway/api/message.go:54-88`) — it does not check identity against any allowlist, nor apply any per-sender rate limit. It then dispatches to `handler.HandleLegacyUserMessage` [2](#0-1) , which after light payload/timestamp/method checks (all of which the attacker can satisfy trivially with a self-generated key), unconditionally stores the callback: [3](#0-2) 

Note the explicit `// TODO: apply allowlist and rate-limiting here` comment right above the method dispatch, confirming no per-sender throttling exists on this path (contrast with the newer `v2` handler which does implement `userRateLimiter`/`incomingRateLimiter`, e.g. `core/capabilities/webapi/outgoing_connector_handler.go:318-333` and `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:371-396`).

Any self-signed private key generates a valid `Sender` (via `ExtractSigner`), so an attacker has unlimited unique "senders" and unique `MessageId`s available, and each such message independently passes `Validate()`.

`pruneCallbacks` runs on a ticker every `CallbackPruneIntervalSec` (default 30s) and, when `len(savedCallbacks) > maxSize`, sorts all entries by `createdAt` ascending and deletes the older half: [4](#0-3) 

Since eviction order is purely chronological with no per-sender fairness, if a victim's legitimate request is inserted first and the DON has not yet responded (deleting/answering the callback) by the time the attacker has flooded 20000+ new entries, the victim's older entry is guaranteed to be in the "oldest half" and gets evicted — silently dropping the victim's pending callback. When the legitimate DON response later arrives at `handleWebAPITriggerMessage`, the lookup on `msg.Body.MessageId` will miss (`found == false`) and the response is simply discarded [5](#0-4) , and the victim's `callback.Wait(ctx)` in `gateway.ProcessRequest` times out.

### Impact Explanation
This is a denial-of-service against a specific victim's in-flight capability request: the victim's HTTP call to the gateway will hang until `callback.Wait` times out and return `api.RequestTimeoutError`, even though the DON correctly processed and answered the request. This matches the "Denial of Service" / availability-impact bounty class scoped to disruption of expected response delivery for legitimate users, achievable by an unauthenticated party with no credentials beyond the ability to generate an ECDSA keypair and sign messages locally.

### Likelihood Explanation
Preconditions are minimal: the attacker needs no account, no allowlisted address, and no special role — only the ability to POST signed JSON-RPC/legacy messages to the gateway's public user-facing HTTP endpoint. Nothing in `httpserver.go`'s `handleRequest` (only CORS/max-body-size checks) or `gateway.ProcessRequest`/`Message.Validate` throttles distinct senders, so generating 20000+ unique keypairs/messages and issuing them within the default 30-second prune interval is programmatically trivial and fully repeatable against any DON configured with this legacy capabilities handler.

### Recommendation
Add per-sender admission control before inserting into `savedCallbacks` (e.g., the same `NodeRateLimiter`/allowlist-style pattern already used for node-originated messages, or a `userRateLimiter`/allowlist akin to the `v2` handler's `checkRateLimit`/`workflowMetadataHandler.Authorize`), and/or change `pruneCallbacks` eviction policy to be fairness-aware (e.g., per-sender caps, or reject new inserts once at capacity rather than evicting existing pending entries) so that no unauthenticated flood can displace another user's already-accepted, still-pending callback.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with `MaxSavedCallbacks` set low (e.g., 10) for test speed, and `CallbackMaxAgeSec` large enough that nothing expires by age.
2. Insert one "victim" callback via `handler.HandleLegacyUserMessage` with a signed message from `victimKey`, record its `MessageId`.
3. In a loop, generate `N > MaxSavedCallbacks` freshly generated ECDSA keys, sign unique legacy trigger messages, and call `handler.HandleLegacyUserMessage` for each ("attacker" flood), without ever calling `HandleNodeMessage` to answer them.
4. Call `handler.pruneCallbacks()` directly (simulating the ticker firing).
5. Assert `handler.savedCallbacks` no longer contains the victim's `MessageId` (`require.NotContains`) despite the victim never having received a response — proving the victim's pending, legitimate callback was evicted purely due to insertion order versus an unauthenticated flood, with no per-sender quota preventing it.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
