### Title
Stale confirmations from deleted multisig members count toward the confirmation threshold, letting requests execute with fewer live members than `num_confirmations` - (File: multisig2/src/lib.rs, multisig/src/lib.rs)

### Summary
`delete_member` (multisig2) and the `DeleteKey` action (multisig) remove a departing member/key's own *created* requests, but never remove that member's *confirmations* recorded on other members' pending requests. `confirm()` counts confirmations purely as a set-size check against `num_confirmations`, with no re-check that each confirming party is still a current member. A request confirmed in part by a member who is later removed can still reach the threshold and execute, even though the number of *live* members who actually confirmed it is below `num_confirmations`.

### Finding Description
The custody binding that should always hold is: `confirmations counted == confirmations from members who are members at execution time`. In `confirm()`: [4](#0-3) 
the code only checks `confirmations.len() as u32 + 1 >= self.num_confirmations` and inserts `member.to_string()` into a `HashSet<String>` stored per request. Membership is only checked for the *caller* of `confirm`, via `assert_valid_request` -> `current_member()`: [5](#0-4) 
but the *previously stored* confirmations from other signers are never re-validated against the current `members` set.

`delete_member` cleans up only requests that the removed member itself created (`r.member == member`), and clears that member's own `num_requests_pk` entry and access key, but does not touch `self.confirmations` entries on *other* pending requests that the removed member had already confirmed: [6](#0-5) 

The older single-key `multisig` contract has the same pattern in its `DeleteKey` handling inside `execute_request`, which purges only requests signed (created) by the deleted key, not confirmations by that key on other requests: [3](#0-2) 

Concretely: with `num_confirmations = 2` and members {A, B, C}, B creates request X. A confirms X (1/2). Members then vote to remove A (`DeleteMember { member: A }`), which succeeds since `members.len() - 1 >= num_confirmations` is still satisfiable (3-1=2 >= 2). A's confirmation on X is never purged. C now confirms X: `confirmations.len() + 1 = 2 >= num_confirmations(2)` → request executes, even though only B (creator, uncounted in `confirmations` but effectively assumed) and C are live members whose confirmation is currently valid, while A — who is no longer a member — supplied one of the two counted confirmations.

### Impact Explanation
This breaks the multisig's core guarantee that `K` *live* members must approve any privileged action (transfers, `AddKey`, `DeployContract`, adding/removing members, etc.). It matches the "multisig request executed below threshold" critical-impact category: an action (e.g., `Transfer`) can be executed with confirmations effectively short by the departed member's stale approval, i.e., executed by fewer live approving members than `num_confirmations` requires.

### Likelihood Explanation
No special privilege is required beyond normal multisig operation: any member confirming a request, followed by governance removing that member (a routine, expected `DeleteMember`/`DeleteKey` action) before the request is confirmed to completion, triggers the stale state. It requires no owner/foundation trust assumption beyond how multisig already operates, and no redeploy.

### Recommendation
When removing a member, iterate all pending requests' `confirmations` sets and remove the departing member's entry (in addition to purging requests they created), or, at `confirm()` time, re-validate that every entry in the stored confirmations set still belongs to `self.members` before counting it toward the threshold.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C]`, `num_confirmations = 2`.
2. `B` calls `add_request` creating request `X` (e.g., `Transfer`).
3. `A` calls `confirm(X)` → confirmations = {A}, threshold (2) not met, request stays pending.
4. Members create/confirm a `DeleteMember { member: A }` request (reaches threshold with e.g. B, C) → executes `delete_member`, which only purges requests created by A, not A's confirmation on `X`; `A` removed from `members`, but `confirmations[X]` still contains A.
5. `C` calls `confirm(X)` → `confirmations.len() (1, containing A) + 1 >= 2` → request `X` executes via `execute_request`, despite A no longer being a live member and only C being a currently-valid confirming member alongside the assumption of B's non-recorded creation.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
