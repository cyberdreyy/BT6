### Title
Stale/revoked LDAP user privilege persists in `ldap_user_api_tokens` cache with no per-request upstream re-validation - ([File: core/sessions/ldapauth/ldap.go])

### Summary
`FindUserByAPIToken` in `core/sessions/ldapauth/ldap.go` returns the role solely from the cached `ldap_user_api_tokens.user_role` column without ever contacting the upstream LDAP server, and the only mechanism that can lower a cached role is `LDAPServerStateSyncer.Work` in `core/sessions/ldapauth/sync.go`, which only runs once at startup (if `UpstreamSyncInterval` is `0s`, the default) or on a ticker if that interval is configured to a non-zero value. There is no code path that triggers `Work()` "on every auth endpoint hit" despite the package doc comment claiming so.

### Finding Description
`AuthenticateByToken` (`core/web/auth/auth.go:78-112`) calls `authr.FindUserByAPIToken(ctx, token.AccessKey)` and then `clsessions.AuthenticateUserByToken` to verify the secret, and on success sets the resulting `sessions.User{Role: ...}` on the gin context, which downstream `RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole` wrappers (`core/web/auth/auth.go:200-255`) trust directly.

For the LDAP driver, `FindUserByAPIToken` (`core/sessions/ldapauth/ldap.go:205-236`) does:
```go
err := l.ds.GetContext(ctx, &foundUserToken,
    "SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
    apiToken, l.config.UserAPITokenDuration().Duration(),
)
...
return sessions.User{Email: foundUserToken.UserEmail, Role: foundUserToken.UserRole}, nil
``` [1](#0-0) 

The only check performed is token expiry (`created_at + UserAPITokenDuration >= now()`); the `user_role` value is trusted as-is from the local database row, which was populated at token-creation time via `SetAuthToken` (`core/sessions/ldapauth/ldap.go:544-592`). The package-level comment even documents this design explicitly: "no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation" [2](#0-1) .

The only code that can downgrade/remove a stale `ldap_user_api_tokens.user_role` is `(l *LDAPServerStateSyncer) Work` [3](#0-2) , which purges/updates rows against a freshly queried `upstreamUserStateMap`. `Work()` is only invoked from:
- `Start()`: called once synchronously on node startup only if `UpstreamSyncInterval().IsInstant()` is true (i.e., the interval is `0s`), otherwise a background ticker goroutine (`run()`) calls it every `UpstreamSyncInterval` [4](#0-3) .

There is no invocation of `Work()`, nor any upstream LDAP query, from `FindUserByAPIToken`, `AuthenticateByToken`, or any other per-request auth path. This contradicts the doc comment's claim that sync "happens for every auth endpoint hit." Consequently, if `UpstreamSyncInterval` is left at its default `0s` (meaning: sync only once at process startup, never again), a previously-issued API token for a user who is later removed from all LDAP role groups retains its originally cached `user_role` (e.g., Admin) for the full `UserAPITokenDuration` lifetime of the token, or until the node happens to restart or an operator configures a non-zero recurring interval.

### Impact Explanation
This is a stale-privilege/authorization-bypass issue: a de-provisioned/entitlement-revoked user (e.g., terminated employee, role downgrade) continues to pass `RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole` checks using an already-issued API token, allowing unauthorized administrative actions (job/spec mutation, key management, fund-moving job runs) after their access should have been revoked. This matches the "authorization bypass / unauthorized privileged action" bounty class for stale entitlement enforcement.

### Likelihood Explanation
Preconditions: the node must have LDAP auth enabled with API tokens enabled (`UserApiTokenEnabled`), and `UpstreamSyncInterval` left at its default `0s` (or a long interval) — this is the documented default behavior, not a hardening misconfiguration by the operator; the syncer only recurs if an operator explicitly opts in by setting a non-zero interval. Given the default value causes the sync to run only once at startup, this is a design/default-behavior issue in the shipped code rather than solely an admin misconfiguration. The user does not need to do anything themselves — they merely need to have obtained a valid token before revocation, and continue calling authenticated endpoints with a token they already legitimately held.

### Recommendation
- Change the default/interpretation of `UpstreamSyncInterval = 0s` to mean "sync on every relevant auth check" rather than "run once at startup and never again," or otherwise ensure `FindUserByAPIToken`/`AuthorizedUserWithSession` trigger (or check freshness against) an upstream re-validation, especially for privileged (Admin) roles.
- Alternatively, invoke `LDAPServerStateSyncer.Work` (or an upstream single-user lookup) inline before trusting a cached `user_role` for privileged operations, or shorten `UserAPITokenDuration` significantly to bound the staleness window when periodic sync is disabled.
- Update the misleading doc comment in `ldap.go` to reflect actual behavior, and add a startup warning/log when `UpstreamSyncInterval` is `0s` indicating that upstream revocation will not propagate to existing tokens/sessions until process restart.

### Proof of Concept
Go handler-level integration test plan (in `core/sessions/ldapauth` or `core/web` test package):
1. Set up a test LDAP mock/config with `UpstreamSyncInterval = 0s` (default), `UserApiTokenEnabled = true`, `UserAPITokenDuration` sufficiently long.
2. Insert directly into `ldap_user_api_tokens` a row for `user@example.com` with `user_role = 'admin'`, valid `token_key`/`token_salt`/`token_hashed_secret`, `created_at = now()` (simulating a token issued while the user was still an Admin-group member).
3. Configure the mocked `LDAPClient`/`LDAPConn` so that a subsequent `ldapGroupMembersListToUser` call for all groups returns no membership for `user@example.com` (simulating upstream revocation).
4. Do **not** call `LDAPServerStateSyncer.Work` again (simulating the interval not having elapsed).
5. Issue an HTTP request to a route wrapped with `auth.RequiresAdminRole` using `X-API-KEY`/`X-API-SECRET` headers matching the token from step 2, through `auth.Authenticate(store, auth.AuthenticateByToken)`.
6. Assert the response returns 200 (privileged action succeeds) instead of 401/403 — demonstrating stale Admin access persists despite upstream revocation.
7. As a control, call `LDAPServerStateSyncer.Work(ctx)` once, then repeat step 5 and assert the request now correctly fails with 401 (`ldap_user_api_tokens` row purged/role downgraded), confirming the only enforcement point is the interval-driven `Work()`, not per-request validation in `FindUserByAPIToken`.

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func (l *LDAPServerStateSyncer) Close() error {
	close(l.stopCh)
	<-l.done
	return nil
}

func (l *LDAPServerStateSyncer) run() {
	defer close(l.done)
	ctx, cancel := l.stopCh.NewCtx()
	defer cancel()
	ticker := time.NewTicker(l.config.UpstreamSyncInterval().Duration())
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.Work(ctx)
		}
	}
}

func (l *LDAPServerStateSyncer) Work(ctx context.Context) {
	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}

	l.lggr.Info("Begin Upstream LDAP provider state sync after checking time against config UpstreamSyncInterval and UpstreamSyncRateLimit")

	// For each defined role/group, query for the list of group members to gather the full list of possible users
	users := []sessions.User{}

	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		l.lggr.Error("Failed to Dial LDAP Server: ", err)
		return
	}
	// Root level root user auth with credentials provided from config
	bindStr := l.config.BaseUserAttr() + "=" + l.config.ReadOnlyUserLogin() + "," + l.config.BaseDN()
	if err = conn.Bind(bindStr, l.config.ReadOnlyUserPass()); err != nil {
		l.lggr.Error("Unable to login as initial root LDAP user: ", err)
	}
	defer conn.Close()

	// Query for list of uniqueMember IDs present in Admin group
	adminUsers, err := l.ldapGroupMembersListToUser(conn, l.config.AdminUserGroupCN(), sessions.UserRoleAdmin)
	if err != nil {
		l.lggr.Error("Error in ldapGroupMembersListToUser: ", err)
		return
	}
	// Query for list of uniqueMember IDs present in Edit group
	editUsers, err := l.ldapGroupMembersListToUser(conn, l.config.EditUserGroupCN(), sessions.UserRoleEdit)
	if err != nil {
		l.lggr.Error("Error in ldapGroupMembersListToUser: ", err)
		return
	}
	// Query for list of uniqueMember IDs present in Edit group
	runUsers, err := l.ldapGroupMembersListToUser(conn, l.config.RunUserGroupCN(), sessions.UserRoleRun)
	if err != nil {
		l.lggr.Error("Error in ldapGroupMembersListToUser: ", err)
		return
	}
	// Query for list of uniqueMember IDs present in Edit group
	readUsers, err := l.ldapGroupMembersListToUser(conn, l.config.ReadUserGroupCN(), sessions.UserRoleView)
	if err != nil {
		l.lggr.Error("Error in ldapGroupMembersListToUser: ", err)
		return
	}

	users = append(users, adminUsers...)
	users = append(users, editUsers...)
	users = append(users, runUsers...)
	users = append(users, readUsers...)

	// Dedupe preserving order of highest role (sorted)
	// Preserve members as a map for future lookup
	upstreamUserStateMap := make(map[string]sessions.User)
	dedupedEmails := []string{}
	for _, user := range users {
		if _, ok := upstreamUserStateMap[user.Email]; !ok {
			upstreamUserStateMap[user.Email] = user
			dedupedEmails = append(dedupedEmails, user.Email)
		}
	}

	// For each unique user in list of active sessions, check for 'Is Active' property if defined in the config. Some LDAP providers
	// list group members that are no longer marked as active
	usersActiveFlags, err := l.validateUsersActive(dedupedEmails, conn)
	if err != nil {
		l.lggr.Error("Error validating supplied user list: ", err)
	}
	// Remove users in the upstreamUserStateMap source of truth who are part of groups but marked as deactivated/no-active
	for i, active := range usersActiveFlags {
		if !active {
			delete(upstreamUserStateMap, dedupedEmails[i])
		}
	}

	// upstreamUserStateMap is now the most up to date source of truth
	// Now sync database sessions and roles with new data
	err = sqlutil.TransactDataSource(ctx, l.ds, nil, func(tx sqlutil.DataSource) error {
		// First, purge users present in the local ldap_sessions table but not in the upstream server
		type LDAPSession struct {
			UserEmail string
			UserRole  sessions.UserRole
		}
		var existingSessions []LDAPSession
		if err = tx.SelectContext(ctx, &existingSessions, "SELECT user_email, user_role FROM ldap_sessions WHERE localauth_user = false"); err != nil {
			return fmt.Errorf("unable to query ldap_sessions table: %w", err)
		}
		var existingAPITokens []LDAPSession
		if err = tx.SelectContext(ctx, &existingAPITokens, "SELECT user_email, user_role FROM ldap_user_api_tokens WHERE localauth_user = false"); err != nil {
			return fmt.Errorf("unable to query ldap_user_api_tokens table: %w", err)
		}

		// Create existing sessions and API tokens lookup map for later
		existingSessionsMap := make(map[string]LDAPSession)
		for _, sess := range existingSessions {
			existingSessionsMap[sess.UserEmail] = sess
		}
		existingAPITokensMap := make(map[string]LDAPSession)
		for _, sess := range existingAPITokens {
			existingAPITokensMap[sess.UserEmail] = sess
		}

		// Populate list of session emails present in the local session table but not in the upstream state
		emailsToPurge := []any{}
		for _, ldapSession := range existingSessions {
			if _, ok := upstreamUserStateMap[ldapSession.UserEmail]; !ok {
				emailsToPurge = append(emailsToPurge, ldapSession.UserEmail)
			}
		}
		// Likewise for API Tokens table
		apiTokenEmailsToPurge := []any{}
		for _, ldapSession := range existingAPITokens {
			if _, ok := upstreamUserStateMap[ldapSession.UserEmail]; !ok {
				apiTokenEmailsToPurge = append(apiTokenEmailsToPurge, ldapSession.UserEmail)
			}
		}

		// Remove any active sessions this user may have
		if len(emailsToPurge) > 0 {
			_, err = tx.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE user_email = ANY($1)", pq.Array(emailsToPurge))
			if err != nil {
				return err
			}
		}

		// Remove any active API tokens this user may have
		if len(apiTokenEmailsToPurge) > 0 {
			_, err = tx.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE user_email = ANY($1)", pq.Array(apiTokenEmailsToPurge))
			if err != nil {
				return err
			}
		}

		// For each user session row, update role to match state of user map from upstream source
		var queryWhenClause strings.Builder
		emailValues := []any{}
		// Prepare CASE WHEN query statement with parameterized argument $n placeholders and matching role based on index
		for email, user := range upstreamUserStateMap {
			// Only build on SET CASE statement per local session and API token role, not for each upstream user value
			_, sessionOk := existingSessionsMap[email]
			_, tokenOk := existingAPITokensMap[email]
			if !sessionOk && !tokenOk {
				continue
			}
			emailValues = append(emailValues, email)
			fmt.Fprintf(&queryWhenClause, "WHEN user_email = $%d THEN '%s' ", len(emailValues), user.Role)
		}

		// If there are remaining user entries to update
		if len(emailValues) != 0 {
			// Set new role state for all rows in single Exec
			query := fmt.Sprintf("UPDATE ldap_sessions SET user_role = CASE %s ELSE user_role END", &queryWhenClause)
			_, err = tx.ExecContext(ctx, query, emailValues...)
			if err != nil {
				return err
			}

			// Update role of API tokens as well
			query = fmt.Sprintf("UPDATE ldap_user_api_tokens SET user_role = CASE %s ELSE user_role END", &queryWhenClause)
			_, err = tx.ExecContext(ctx, query, emailValues...)
			if err != nil {
				return err
			}
		}

		l.lggr.Info("local ldap_sessions and ldap_user_api_tokens table successfully synced with upstream LDAP state")
		return nil
	})
	if err != nil {
		l.lggr.Error("Error syncing local database state: ", err)
	}
	l.lggr.Info("Upstream LDAP sync complete")
}
