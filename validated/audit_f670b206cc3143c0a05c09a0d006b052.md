### Title
`createWriteOffRequest` trusts a user-supplied `underlyingsRequested` price with no floor, so a mispriced request lets any fulfiller buy escrowed tranche tokens for dust - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol](contracts/IdleCreditVaultWriteOffEscrow.sol))

### Summary
Analogous to LiFi's Optimism facet forwarding a user-provided `l2Gas` that, if under-set, silently loses the bridged funds, `IdleCreditVaultWriteOffEscrow.createWriteOffRequest` forwards a user-provided `underlyingsRequested` price into an irrevocable escrow offer. If the price is set too low (typo, stale price, wrong decimals), any unprivileged fulfiller can call `fullfillWriteOffRequest`, pay only the dust amount (minus the 0.1% exit fee) and receive all escrowed tranche tokens at far below `virtualPrice`. The loss is permanent: `userRequests` is deleted atomically at fulfillment and tranche tokens are transferred to the fulfiller.

### Finding Description
- `createWriteOffRequest(amount, underlyingsRequested)` pulls `amount` tranche tokens into escrow and stores `WriteOffRequest{tranches, underlyings}` with no sanity check against the tranche's current value (`IdleCDOEpochVariant.virtualPrice(tranche)` or `lastNAV`). [1](#0-0) 
- `fullfillWriteOffRequest(_user, _tranches, _underlyings)` only enforces `currentRequest.tranches == _tranches` and `_underlyings >= currentRequest.underlyings`, then transfers `_underlyings - fee` to the user and the full `_tranches` balance to the fulfiller. The fulfiller is free to pay exactly the requested price regardless of the real tranche value. [2](#0-1) 
- There is no oracle/NAV floor, no minimum price, and no grace period. Requests also accumulate (`tranches + amount`, `underlyings + underlyingsRequested`), so a user who realizes a bad price cannot amend downward — only delete, which races with a fulfiller already watching the mempool.

### Impact Explanation
An unprivileged fulfiller (explicitly in-scope as an attacker) monitoring for escrowed requests can fulfill a mispriced request and capture `tranches * virtualPrice / 1e18 - underlyingsRequested` of value. Concretely, a lender escrowing 10,000 AA tranche tokens worth ~1.05 USDC each who accidentally passes `underlyingsRequested` scaled one decimal short (e.g., `1_050e6` instead of `10_500e6`) loses ~90% of position value, ~9,450 USDC, in a single atomic transaction. This is direct theft of lender principal enabled by a missing bounds check, satisfying the "user-provided parameter mispriced → permanent loss" invariant break of the original report. Only guard is `deleteWriteOffRequest`, which the fulfiller can front-run, and the epoch-running check in `createWriteOffRequest` does nothing to bound the price.

### Likelihood Explanation
Requires a user-supplied pricing error, same trigger class as the reference finding (under-paid `l2Gas`); unlike that report, here the error is directly exploitable by a third-party fulfiller rather than merely stranding funds, and write-off requests are precisely the flow used when tranche tokens trade below NAV, so pricing is manual and error-prone. No privileged role needed for the fulfiller.

### Recommendation
Add a sanity floor in `createWriteOffRequest`/`fullfillWriteOffRequest`: reject requests where `underlyingsRequested` is below e.g. `tranches * virtualPrice(tranche) * (1 - maxDiscount) / ONE_TRANCHE`, or at minimum emit/document loudly that `underlyingsRequested` is a binding sale price with no on-chain floor. Allowing users to update (not only append to) a pending request's price would also remove the race with delete+recreate.

### Proof of Concept
Foundry fork-style PoC sketch (epoch running, using the vault's own harness conventions):

```solidity
function testWriteOffMispricedRequestDrained() external {
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount); // victim deposits, receives ~amount tranches

    // epoch must be running for createWriteOffRequest
    _startEpochAndCheckPrices(0);

    // Victim creates request but under-prices: asks 100 USDC instead of ~10_000 USDC
    uint256 tranches = AAtranche.balanceOf(address(this));
    AAtranche.approve(address(escrow), tranches);
    escrow.createWriteOffRequest(tranches, 100 * ONE_SCALE);

    // Attacker (any EOA) fulfills paying only the requested dust amount
    address fulfiller = makeAddr('fulfiller');
    deal(address(underlying), fulfiller, 100 * ONE_SCALE);
    vm.startPrank(fulfiller);
    underlying.approve(address(escrow), 100 * ONE_SCALE);
    escrow.fullfillWriteOffRequest(address(this), tranches, 100 * ONE_SCALE);
    vm.stopPrank();

    // Attacker holds all tranche tokens worth ~10_000 USDC
    assertEq(AAtranche.balanceOf(fulfiller), tranches);
    // Victim received only ~100 USDC minus exit fee
    assertApproxEqAbs(underlying.balanceOf(address(this)), 100 * ONE_SCALE * 999 / 1000, 1);
}
```

The victim loses `tranches * virtualPrice / 1e18 - ~100` underlyings permanently; `userRequests` is deleted so the theft cannot be undone.

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }
```

  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
