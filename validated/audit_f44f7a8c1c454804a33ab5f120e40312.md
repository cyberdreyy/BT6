### Title
Missing allowlist/authorization enforcement in `HandleLegacyUserMessage` permits any signed sender to trigger DON capability execution - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` validates message structure, payload decoding, and message age, but contains only a `// TODO: apply allowlist and rate-limiting here` comment with no actual sender authorization check before broadcasting the request to every DON member via `don.SendToNode` and registering the callback in `h.savedCallbacks`. Any address capable of producing a validly-signed, non-stale `MethodWebAPITrigger` message can trigger DON capability execution regardless of subscription/allowlist status.

### Finding Description
The message flow is: `gateway.ProcessRequest` (core/services/gateway/gateway.go:218-292) decodes the incoming JSON-RPC request, and for legacy requests calls `msg.Validate()` [1](#0-0)  which only checks structural correctness and recovers/records the signer as `m.Body.Sender` via `ExtractSigner()` [2](#0-1)  — it does not check the signer against any allowlist or subscription. The request is then dispatched to `h.HandleLegacyUserMessage` [3](#0-2) .

Inside `HandleLegacyUserMessage`, checks performed are: payload JSON decoding, presence of a non-zero `Timestamp`, and message staleness against `MaxAllowedMessageAgeSec` [4](#0-3) . Immediately after, the code has the explicit TODO marker and proceeds to validate only the method name, build the request, save the callback, and broadcast to **all** DON members without ever checking `msg.Body.Sender` against any allowlist or per-DON subscription list: [5](#0-4) .

The codebase authors acknowledge this gap directly: the existing test suite has a trailing TODO stating "Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated" [6](#0-5) , and the preceding test explicitly asserts only that malformed/stale/bad-method messages don't register callbacks — not that unauthorized-but-well-formed senders are rejected [7](#0-6) .

No allowlist, subscription check, or per-sender rate limiting exists anywhere in this path. The `nodeRateLimiter` field in `handler` is used only in `handleWebAPIOutgoingMessage`, which handles messages *from* DON nodes, not incoming user messages [8](#0-7) .

### Impact Explanation
Any externally-owned account capable of generating a valid ECDSA signature (no subscription, no registration, no allowlist entry) can force the gateway to broadcast a `web_api_trigger` request to every member of a targeted DON and consume DON node compute/network resources processing it. This is unauthorized consumption of DON capability execution resources and violates the intended authorization-exactness invariant (only allowlisted/subscribed senders may trigger DON execution). This maps to the "unauthorized job/capability triggering / quota-authorization bypass" bounty class rather than direct fund loss, since actual execution of the workflow itself still depends on downstream DON-side capability/trigger permission checks.

### Likelihood Explanation
The attack requires no privileges beyond the ability to create an ECDSA keypair and sign a well-formed message — trivial and fully repeatable by any external client of the gateway's HTTP endpoint. The only preconditions are picking a target `DonId` known to be configured on the gateway and crafting a `MethodWebAPITrigger` payload with a fresh timestamp. This is directly reachable from the public gateway user endpoint (`gateway.ProcessRequest` → `HandleLegacyUserMessage`), requiring no operator, node, or DON compromise.

### Recommendation
Implement the sender/allowlist and rate-limiting check called out by the TODO before saving the callback and broadcasting to DON members in `HandleLegacyUserMessage`: verify `msg.Body.Sender` against the DON's configured allowlist/subscription for the requested method/DonId, and apply a per-sender rate limiter (analogous to `h.nodeRateLimiter` used for outgoing node messages) prior to calling `don.SendToNode`. Reject unauthorized/over-limit senders with an appropriate `api.ErrorCode` response instead of processing the request.

### Proof of Concept
Go handler-level integration test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with a `donConfig.Members` list and a mock `handlers.DON` implementation whose `SendToNode` records calls.
2. Generate an arbitrary, unregistered ECDSA private key (not present in any allowlist/subscription config for the DON) and sign a valid `MethodWebAPITrigger` message via `triggerRequest(t, unregisteredKey, capabilities, "", validTimestamp, validPayload)`.
3. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)`.
4. Assert: (a) `err == nil` / no rejection response with an authorization-related `ErrorCode`, (b) mock DON's `SendToNode` was invoked once per entry in `donConfig.Members`, and (c) `handler.savedCallbacks[msg.Body.MessageId]` is populated — demonstrating the request was fully processed and forwarded despite the signer having no allowlist/subscription entry.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
