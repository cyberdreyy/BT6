### Title
Overly Strict Gasless Remaining-Balance Guard Uses Unused Reservation Instead of Actual Remaining Balance — (File: sui-execution/latest/sui-adapter/src/temporary_store.rs)

### Summary
`check_gasless_execution_requirements` computes the post-execution remaining-balance check as `reserved + net` (the unused portion of the declared reservation) instead of `actual_balance + net` (the true remaining account balance). This is the direct Sui analog of the Aave `userBalance`-vs-`amount` substitution: the wrong variable is used in the validation, making the guard overly strict and causing valid gasless transactions to be rejected.

### Finding Description
`check_gasless_execution_requirements` runs after PTB execution for every gasless transaction when `gasless_verify_remaining_balance` is enabled (protocol v122+, mainnet v124+). Its stated purpose is to ensure the sender's remaining balance is either zero or at least `min_balance_remaining` for each allowed token type.

The relevant block (lines 810–827):

```rust
if let Some(reservations) = withdrawal_reservations {
    for ((owner, token_type), &reserved) in reservations {
        let net = net_totals
            .get(&(*owner, token_type.clone()))
            .copied()
            .unwrap_or(0);
        let remaining = (reserved as i128).saturating_add(net);   // ← wrong variable
        if remaining > 0
            && let Some(&min_balance_remaining) = allowed_types.get(token_type)
            && min_balance_remaining > 0
            && remaining < min_balance_remaining as i128
        {
            return Err(format!(
                "Gasless withdrawal leaves {remaining} unused for {owner}, \
                 below minimum {min_balance_remaining} for token type {token_type}"
            ));
        }
    }
}
```

`reserved` is the `MaxAmountU64` upper bound declared in the transaction data — the maximum the transaction *may* withdraw, not the amount it *did* withdraw. `net` is the actual signed net change for the owner (negative for a net withdrawal). Therefore:

```
remaining = reserved + net = reserved − actual_split   ← unused reservation
```

The quantity the minimum-balance rule is supposed to protect is the **actual remaining account balance**:

```
correct_remaining = actual_balance + net = actual_balance − actual_split
```

The code substitutes `reserved` for `actual_balance`. These are equal only when the transaction exhausts its entire reservation, which is not required. [1](#0-0) 

The pre-execution check (`check_remaining_amounts_after_withdrawal`) correctly uses `actual_balance − reserved`:

```rust
let remaining = actual_amount.saturating_sub(*requested_amount as u128);
``` [2](#0-1) 

The two checks are therefore inconsistent: the pre-execution gate uses the real balance, while the post-execution gate uses the reservation.

### Impact Explanation
A user with `actual_balance = 10 000`, `min = 1 000`, who declares `reserved = 9 000` and whose Move code actually splits `8 500`:

| Check | Computation | Result |
|---|---|---|
| Pre-execution (correct) | `10 000 − 9 000 = 1 000 ≥ 1 000` | passes |
| Post-execution (buggy) | `9 000 − 8 500 = 500 < 1 000` | **fails** |
| Actual remaining balance | `10 000 − 8 500 = 1 500 ≥ 1 000` | should pass |

The transaction is rejected with `InsufficientGas` even though the sender's actual remaining balance (1 500) is above the minimum (1 000). This constitutes harmful smart-contract behavior: a valid, fully-funded gasless transfer is permanently blocked for any reservation/split combination where `reserved − actual_split` falls in the range `(0, min_balance_remaining)`.

### Likelihood Explanation
The condition is reachable by any ordinary SUI holder using the gasless stablecoin transfer feature whenever:
1. The declared reservation is not exactly equal to the actual split (e.g., `withdrawal_split` with a partial amount, conditional Move logic, or rounding), and
2. The gap `reserved − actual_split` is positive but below `min_balance_remaining`.

No privileged role is required. The attacker model is an ordinary user submitting a public gasless transaction. The feature is live on mainnet (v124+) with USDC, USDSUI, SUI_USDE, USDY, FDUSD, AUSD, and USDB, each with a `min_balance_remaining` of 10 000 (0.01 USD). [3](#0-2) 

### Recommendation
Replace `reserved` with the actual account balance in the remaining-balance computation:

```rust
// Correct: fetch the actual on-chain balance and apply the net change
let actual_balance = self.get_latest_account_amount(&account_obj_id) as i128;
let remaining = actual_balance.saturating_add(net);
```

Alternatively, since the pre-execution check (`check_remaining_amounts_after_withdrawal`) already enforces `actual_balance − reserved ≥ min_amount`, and since `actual_split ≤ reserved` is guaranteed by the reservation invariant, the actual remaining balance is always `≥ min_amount` when the pre-execution check passes. The post-execution reservation check is therefore redundant and can be removed entirely.

### Proof of Concept
1. Register a token with `--min-transfer 1000` (e.g., via `gasless-allow-token`).
2. Fund address A with `10 000` units.
3. Submit a gasless transaction with `withdraw<Token>(9000)`.
   - Pre-execution check: `10 000 − 9 000 = 1 000 ≥ 1 000` → **passes**, transaction is certified.
4. In the PTB, call `withdrawal_split` with amount `8 500` (splits only 8 500 of the 9 000 reservation), then `send_funds` the split to B.
5. Observe: post-execution check computes `remaining = 9 000 + (−8 500) = 500 < 1 000` and returns `Err("Gasless withdrawal leaves 500 unused for A, below minimum 1000 …")`, causing the transaction to fail with `InsufficientGas`.
6. The actual remaining balance of A is `10 000 − 8 500 = 1 500 ≥ 1 000`; the rejection is incorrect. [4](#0-3) [5](#0-4)

    /// Validates gasless post-execution invariants:
    /// - No new objects were created or existing objects mutated (written_objects is empty)
    /// - The set of deleted objects exactly equals the set of input Coin objects
    /// - Each recipient receives at least the minimum transfer amount per token type
    /// - Unused withdrawal reservation (reservation - actual split) is 0 or >= min_amount
    pub fn check_gasless_execution_requirements(
        &self,
        withdrawal_reservations: Option<&BTreeMap<(SuiAddress, TypeTag), u64>>,
    ) -> Result<(), String> {
        if !self.execution_results.written_objects.is_empty() {
            return Err("Gasless transactions cannot create or mutate objects".to_string());
        }

        let input_coin_ids: BTreeSet<ObjectID> = self
            .input_objects
            .iter()
            .filter(|(_, obj)| obj.coin_type_maybe().is_some())
            .map(|(id, _)| *id)
            .collect();
        if self.execution_results.deleted_object_ids != input_coin_ids {
            return Err(format!(
                "Gasless transaction must destroy exactly its input Coins. \
                 Expected: {input_coin_ids:?}, deleted: {:?}",
                self.execution_results.deleted_object_ids
            ));
        }

        let allowed_types =
            sui_types::transaction::get_gasless_allowed_token_types(self.protocol_config);

        // Aggregate signed balance changes per (address, token_type).
        // Positive nets are recipient deposits that must meet the minimum transfer amount.
        let net_totals = sui_types::balance_change::signed_balance_changes_from_events(
            &self.execution_results.accumulator_events,
        )
        .fold(
            BTreeMap::<(SuiAddress, TypeTag), i128>::new(),
            |mut totals, (address, token_type, signed_amount)| {
                *totals.entry((address, token_type)).or_default() += signed_amount;
                totals
            },
        );

        for ((recipient, token_type), net_amount) in &net_totals {
            if *net_amount <= 0 {
                continue;
            }
            if let Some(&min_amount) = allowed_types.get(token_type)
                && *net_amount < i128::from(min_amount)
            {
                return Err(format!(
                    "Gasless transfer of {net_amount} to {recipient} is below \
                     minimum {min_amount} for token type {token_type}"
                ));
            }
        }

        if let Some(reservations) = withdrawal_reservations {
            for ((owner, token_type), &reserved) in reservations {
                let net = net_totals
                    .get(&(*owner, token_type.clone()))
                    .copied()
                    .unwrap_or(0);
                let remaining = (reserved as i128).saturating_add(net);
                if remaining > 0
                    && let Some(&min_balance_remaining) = allowed_types.get(token_type)
                    && min_balance_remaining > 0
                    && remaining < min_balance_remaining as i128
                {
                    return Err(format!(
                        "Gasless withdrawal leaves {remaining} unused for {owner}, \
                         below minimum {min_balance_remaining} for token type {token_type}"
                    ));
                }
            }
        }

        Ok(())
    }
