## Analysis

CVE-2016-7039 is a Linux kernel bug where the GRO fast path recursively/iteratively parsed an unbounded number of stacked VLAN headers in a single packet, exhausting the kernel stack and panicking the host. The root-cause pattern is: **a single "container" whose internal structure is nested to an attacker-chosen depth, decoded by unbounded recursion with no depth cap**, triggering a stack-exhaustion crash.

The Base fault-proof program's Merkle Patricia Trie decoder has an analogous unbounded-recursion pattern, and it is explicitly in the allowed reachable-path list ("the fault-proof program and MPT").

`TrieNode::decode` recurses into itself for every `Extension` node and for every element of a `Branch` node, with no depth counter at all: [1](#0-0) 

The extension/leaf payload decoder recurses unconditionally on the embedded child node: [2](#0-1) 

Critically, the *encoder* only embeds a child node inline when its RLP length is `< 32` bytes — otherwise it blinds it behind a keccak256 hash (which would force a separate, hash-checked oracle fetch per level): [3](#0-2) 

But the **decoder never enforces this invariant**. It will happily recurse into an arbitrarily large chain of nested, non-blinded `Extension`/`Branch` RLP structures contained in a *single* preimage blob, as long as that outer blob hashes to the value requested from the preimage oracle. Since only the outermost bytes are hash-checked by the oracle (`OracleL1ChainProvider::trie_node_by_hash` / `OracleL2ChainProvider`), an attacker (a dispute-game participant supplying preimage data during a fault-proof challenge) fully controls everything *inside* that blob: [4](#0-3) 

The same unbounded-recursion pattern also exists independently in the ordered-list walker used to decode L1/L2 transactions and receipts tries reached during derivation: [5](#0-4) 

For contrast, elsewhere in the same repo (the Nitro attestation CBOR parser) an explicit recursion-depth cap was added specifically to prevent this exact bug class: [6](#0-5) [7](#0-6) 

No equivalent guard exists in `base-proof-mpt`.

### Title
Unbounded recursive TrieNode decode allows stack-exhaustion DoS of the fault-proof program via a single crafted preimage - (File: crates/proof/mpt/src/node.rs)

### Summary
`TrieNode::decode` and `OrderedListWalker::fetch_leaves` recurse into nested trie structures with no depth limit. Because the decoder does not enforce the encoder's "embed only if < 32 bytes, else blind with a separate hash" invariant, a single preimage blob that satisfies one oracle hash check can contain an attacker-chosen number of nested, non-blinded `Extension`/`Branch` nodes, all decoded in one unbounded recursive call chain.

### Finding Description
`Decodable for TrieNode::decode` (crates/proof/mpt/src/node.rs:567-604) dispatches on RLP list shape: a 2-element list goes to `try_decode_leaf_or_extension_payload`, which for an `Extension` node calls `Self::decode(buf)` recursively on the embedded child (line 456) with no depth counter; a 17-element list decodes `Vec::<Self>::decode(buf)` for a `Branch`, which recurses into each of the 16 children. Nothing in this call path tracks or bounds recursion depth, unlike the CBOR parser in `crates/proof/tee/registrar/src/cbor.rs`, which explicitly threads a `depth` parameter and rejects `depth > MAX_CBOR_NESTING_DEPTH`.

The encoder normally prevents deeply nested inline structures by blinding (hashing) any child whose RLP length is ≥ 32 bytes (node.rs:531,544), which would force each nesting level to be a separate oracle fetch, each hash-verified. The decoder does not re-validate that invariant on untrusted input — it will decode any syntactically valid nested RLP list as a real `Extension`/`Branch` chain regardless of size. This means a single preimage blob (which only needs to satisfy one keccak256 hash check by the oracle) can contain thousands of nested `Extension` wrappers, all decoded via unbounded native-stack recursion in one call.

This preimage/trie-node decode path is invoked throughout the fault-proof client when resolving L1 and L2 chain data from attacker/dispute-participant-supplied preimages: `OracleL1ChainProvider::trie_node_by_hash` and `OracleL2ChainProvider`'s `OrderedListWalker::try_new_hydrated` calls for transactions/receipts roots, both of which are reached while deriving L2 state from L1 deposit/system-config data during the fault-proof program's execution.

### Impact Explanation
The fault-proof program runs inside a constrained FPVM/zkVM execution environment. A native stack overflow there is not a graceful, catchable error — it crashes/panics the proof program mid-execution. This can:
- Prevent an honest party from producing a valid proof/output root for a legitimate dispute step (denial of service on the dispute game), or
- Cause the FPVM to enter an unspecified/undefined state, undermining the guarantee that the fault-proof program always deterministically computes (or fails safely to) a correct output root.

Either outcome is a "node halt" / "wrong provable output root" class impact against the fault-proof/dispute-game subsystem.

### Likelihood Explanation
Reachable by any dispute-game participant who can supply preimage data honored by the preimage oracle during a fault-proof challenge — no special privileges beyond normal participation in the dispute game are required, and the malicious blob only needs to satisfy a single keccak256 pre-image check to be accepted, which is trivial to construct (the attacker crafts the blob, then hashes it — no grinding needed since they choose the content that becomes the "expected" hash for the level they control).

### Recommendation
Add an explicit maximum recursion/nesting depth to `TrieNode::decode` (mirroring `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`) and to `OrderedListWalker::fetch_leaves`, rejecting any trie node whose embedded (non-blinded) child chain exceeds a small bound consistent with the canonical encoder's blinding threshold (since legitimately encoded tries never need more than a couple of embedded levels before blinding kicks in at 32 bytes).

### Proof of Concept
1. Construct nested `TrieNode::Extension` values in memory: `Extension(prefix, Box::new(Extension(prefix, Box::new(... thousands of levels ...)))))`, ending in a `Leaf`.
2. Encode via `TrieNode::encode`, but keep RLP-list lengths small enough per level to remain syntactically decodable while total structure requires deep recursion (i.e., hand-craft the raw RLP bytes directly rather than going through the encoder's blinding logic, since the encoder would normally blind at 32 bytes — the attacker is not bound by the encoder).
3. Register the resulting blob as a preimage under its own keccak256 hash in the test `TrieProvider`/oracle mock (mirroring `TrieNodeProvider::trie_node_by_hash` in `crates/proof/mpt/src/test_util.rs`).
4. Call `TrieNode::decode(&mut blob.as_ref())` or drive it through `OrderedListWalker::try_new_hydrated(root, &fetcher)` — observe unbounded native recursion depth proportional to attacker-chosen nesting, leading to stack overflow on a sufficiently deep input.

        let first = match first_nibble {
            PREFIX_EXTENSION_ODD | PREFIX_LEAF_ODD => Some(first_byte & 0x0F),
            PREFIX_EXTENSION_EVEN | PREFIX_LEAF_EVEN => None,
            _ => return Err(TrieNodeError::InvalidNodeType),
        };

        match first_nibble {

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }

    /// Traverses a [`TrieNode`], returning all values of child [`TrieNode::Leaf`] variants.
    fn fetch_leaves(
        trie_node: &TrieNode,
        fetcher: &F,
    ) -> OrderedListWalkerResult<VecDeque<(Bytes, Bytes)>> {
        match trie_node {
            TrieNode::Branch { stack } => {
                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }
            TrieNode::Leaf { prefix, value } => {
                Ok(vec![(prefix.to_vec().into(), value.clone())].into())
            }
            TrieNode::Extension { node, .. } => {
                // If the node is a hash, we need to grab the preimage for it and continue
                // recursing. If it is already retrieved, recurse on it.
                match node.as_ref() {
                    TrieNode::Blinded { commitment } => {
                        let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                        Ok(Self::fetch_leaves(&trie_node, fetcher)?)
                    }
                    node => Ok(Self::fetch_leaves(node, fetcher)?),
                }
            }
            TrieNode::Empty => Ok(VecDeque::new()),
            _ => Err(TrieNodeError::InvalidNodeType.into()),
        }
    }
