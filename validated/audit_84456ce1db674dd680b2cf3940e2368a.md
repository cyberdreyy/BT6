### Title
`depositDuringEpoch` credits full `_amount` and mints unbacked strategy tokens when `token` charges a transfer fee, stealing NAV from existing tranche holders - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
Unlike the normal deposit path in `IdleCDOCreditVault._deposit` and `IdleCDO._deposit`, which mint shares based on the *actual received* balance delta (`_contractTokenBalance(_token) - _preBal`), `IdleCDOEpochVariant.depositDuringEpoch` mints tranche shares, mints strategy tokens, and forwards underlyings to the borrower using the nominal `_amount` parameter. If the vault `token` takes a fee on transfer (e.g. USDT with fees enabled), fewer than `_amount` underlyings actually arrive, but accounting proceeds as if the full amount did. ### Finding Description
The mid-epoch deposit flow is:

1. `_transferUnderlyingsFrom(msg.sender, address(this), _amount)` — with a fee-on-transfer token, the CDO receives `_amount - fee` [1](#0-0) 
2. Shares are minted as `(_amount + trancheInterest) * _trancheTotSupply / expectedFinal` — i.e., for the full nominal `_amount` plus interest on it [4](#0-3) 
3. `IdleCreditVault(strategy).mintStrategyTokens(_amount)` mints `_amount` strategy tokens 1:1 into the CDO, inflating `getContractValue()` (which is `strategyToken balance + token balance - unclaimedFees`) by more than real backing [5](#0-4) [6](#0-5) 
4. `_transferUnderlyings(_borrower(), _amount)` pushes the full `_amount` out to the borrower, so the missing `fee` portion is pulled from other underlyings held by the CDO (e.g. uninstant-withdrawn liquidity or a just-received direct send that `_skimDonatedAssets` hasn't yet isolated), or reverts only if balance is exactly short [7](#0-6) 

The depositor also earns prorated `trancheInterest` computed on the untransferred fee portion, and `expectedEpochInterest` is inflated, further distorting `priceEnd` and over/under-performance accounting at `stopEpoch`.

None of the guards stop this: `_skimDonatedAssets` only sweeps pre-existing raw balance before the deposit (and would actually *feed* the attack by letting a skimmed donation cover the shortfall before the transfer happens — note skim happens before the transfer, so the shortfall comes from strategy-token-backed NAV instead), `_guarded` checks limits, and `isWalletAllowed`/KYC only restricts who can call — a KYC-passed lender is an allowed attacker.

### Impact Explanation
For every mid-epoch deposit into a running epoch with a fee-on-transfer underlying, the attacker receives tranche shares and the vault records strategy-token backing for `fee` tokens that were never received. The missing value is socialized: NAV per existing share is diluted, and the borrower effectively receives `fee` tokens of other depositors' capital. Loss is quantified as `fee = _amount * feeRate` per deposit, repeatable each deposit; with a 1% fee token and a 1M deposit, 10k of value is extracted per call, scaled by deposit size. The depositor's receipt also claims `trancheInterest` on funds never delivered, crystallizing the theft at epoch end.

### Likelihood Explanation
Requires (a) an epoch-running credit vault whose `token` charges transfer fees (USDT's fee toggle is the canonical case; these vaults are designed for stablecoin lending), (b) `isDepositDuringEpochDisabled == false`, `isAYSActive == false`, non-programmable borrower, and (c) a KYC-passed caller — all within the allowed attacker model. No privileged misbehavior needed.

### Recommendation
Measure the actual received amount and use it consistently:

```solidity
uint256 _preBal = _contractTokenBalance(token);
_transferUnderlyingsFrom(msg.sender, address(this), _amount);
uint256 _received = _contractTokenBalance(token) - _preBal;
```

Then compute `interest`/`trancheInterest`/`_minted`/`expectedEpochInterest` on `_received`, call `mintStrategyTokens(_received)`, and transfer `_received` to the borrower — matching the delta-based accounting already used in `_deposit`.

### Proof of Concept
Foundry fork test sketch (fork mainnet, use USDT with fees enabled via `USDT.setParams(basisPointsRate, maximumFee)` pranked as owner):

```solidity
function testFeeOnTransferMidEpochDeposit() public {
    // Setup: vault with USDT underlying, depositAA by lender, startEpoch()
    // Enable 1% transfer fee on USDT (prank Tether owner)
    // attacker = KYC'd lender; enable depositDuringEpoch
    uint256 balBefore = underlying.balanceOf(borrower);
    uint256 navBefore = cdoEpoch.getContractValue();

    vm.startPrank(attacker);
    underlying.approve(address(cdoEpoch), 1_000_000e6);
    cdoEpoch.depositDuringEpoch(1_000_000e6, address(AAtranche));
    vm.stopPrank();

    // CDO received only 990_000e6 but minted 1_000_000e6 strategy tokens
    // and sent 1_000_000e6 to the borrower -> 10_000e6 of NAV is unbacked
    assertEq(underlying.balanceOf(borrower) - balBefore, 1_000_000e6);
    // existing holders diluted: minted shares + minted strategy tokens
    // exceed real received underlyings by the fee amount
}
```
