### Title
Zip-slip / symlink path traversal in legacy zip extractor bypasses cache extraction confinement - ([File: helpers/archives/zip_extract.go], [File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go])

### Summary
The `ziplegacy` extractor (registered via `archive.Register` as an `archive.Extractor` for zip formats) never applies the `dir` confinement it receives, and the underlying `extractZipFileEntry`/`extractZipSymlinkEntry` functions in `helpers/archives/zip_extract.go` write/symlink using the raw, attacker-controlled `zip.File.Name` with no path-traversal or symlink-target validation. This is in stark contrast to the `tarzstd` extractor, which explicitly computes `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects paths without the `e.dir` prefix.

### Finding Description
`CacheExtractorCommand.Execute` (`commands/helpers/cache_extractor.go:655-663`) calls `archive.NewExtractor(format, f, size, wd)` and then `extractor.Extract(ctx)`. For the `Zip`/legacy zip path, this resolves to `ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32`):

```go
func (e *extractor) Extract(ctx context.Context) error {
	zr, err := zip.NewReader(e.r, e.size)
	...
	return archives.ExtractZipArchive(zr)
}
```

Note that `e.dir` (the `wd` passed from `Execute`) is stored on the struct but **never used** inside `Extract` — it is not joined with entry names, and no `os.Chdir` into it occurs either. Extraction proceeds via `archives.ExtractZipArchive` → `extractZipFile` → `extractZipFileEntry` / `extractZipSymlinkEntry` (`helpers/archives/zip_extract.go:22-83`), all of which use `file.Name` directly:

```go
_ = os.Remove(file.Name)
err = os.Symlink(string(data), file.Name)   // extractZipSymlinkEntry
```
```go
_ = os.Remove(file.Name)
out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm()) // extractZipFileEntry
```
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777) // extractZipFile
```

None of `extractZipFile`, `extractZipDirectoryEntry`, `extractZipFileEntry`, or `extractZipSymlinkEntry` validate that `file.Name` (or a resolved symlink target under it) stays confined to any root. There is no `filepath.Abs` + prefix check as in `tarzstd_extractor.go:58-64`, and Go's `archive/zip` package does not sanitize `zip.File.Name` when iterating `archive.File` directly (that protection only applies to `zip.Reader.Open(name)`-style lookups, not to raw iteration). A crafted entry name such as `../../../home/user/.bashrc` or `../../.ssh/authorized_keys`, or a symlink entry whose target (`data` read from the entry's content) contains `../` segments, will be created relative to whatever the process's actual working directory is — since `wd` is never enforced — allowing writes outside the intended cache/build root.

This matches the exact scoped call path in the question: `Execute -> openArchive -> archive.NewExtractor(format, f, size, wd) -> extractor.Extract -> extractZipFile -> extractZipSymlinkEntry`, and confirms the missing invariant (confinement under `wd`) that the differential comparison with `tarzstd_extractor.go` was meant to test.

### Impact Explanation
An attacker who controls the content of a cache archive for a shared cache key (a normal, unprivileged capability — e.g., poisoning `.gitlab-ci.yml` cache paths in an earlier job or MR pipeline that shares a cache key with a later, more privileged job/pipeline) can cause the Runner's cache-extractor helper to write arbitrary files or symlinks outside the job's working directory on the host/container filesystem when the legacy zip extractor path is used. Depending on what shared paths are writable by the job process (e.g. other locations under the executor's mounted volumes, shell profile files, or files later consumed with elevated trust by a subsequent job), this can lead to persistence, configuration tampering, or a stepping stone to broader compromise — violating the "File operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs to control a cache archive's contents once (trivial for any pipeline author using a shared cache key) — no admin action or extra privilege is required. The zip content is entirely attacker-authored (via `cache: paths:` and a build step, or directly by uploading a crafted zip through the cache upload flow), and the vulnerable code path (`ziplegacy`) is a standard, non-experimental extractor registered in the `archive` package for zip format. The only variable is whether `ziplegacy` (vs. `fastzip`) is the extractor actually selected at runtime for a given build/OS/feature-flag configuration — this determines exposure but does not change the fact that `ziplegacy`'s implementation itself is unconditionally missing path confinement.

### Recommendation
In `helpers/archives/zip_extract.go`, before performing any filesystem operation on `file.Name` (in `extractZipFile`, `extractZipDirectoryEntry`, `extractZipFileEntry`, and especially the symlink target in `extractZipSymlinkEntry`), resolve the destination via `filepath.Join(dir, file.Name)`, compute `filepath.Abs`, and verify the result has `dir` as a strict prefix (mirroring `tarzstd_extractor.go:58-64`), rejecting the entry otherwise. Additionally, validate symlink targets (`data` in `extractZipSymlinkEntry`) the same way, since a symlink can point outside `dir` even if its own name is confined. Fix `ziplegacy.extractor.Extract` to actually pass/enforce `e.dir` as the extraction root (e.g., by chdir'ing into it or threading it through to `ExtractZipArchive`).

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpRoot := t.TempDir()
    wd := filepath.Join(tmpRoot, "wd")
    require.NoError(t, os.MkdirAll(wd, 0o755))

    outsideTarget := filepath.Join(tmpRoot, "escaped.txt")

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    // crafted symlink entry escaping wd
    hdr := &zip.FileHeader{Name: "../escaped_link"}
    hdr.SetMode(os.ModeSymlink | 0o777)
    w, _ := zw.CreateHeader(hdr)
    w.Write([]byte("../escaped.txt"))
    zw.Close()

    require.NoError(t, os.Chdir(wd))
    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    err := archives.ExtractZipArchive(zr)

    // Expected (fixed) behavior: extraction rejects/confines the entry
    require.Error(t, err)
    _, statErr := os.Lstat(filepath.Join(tmpRoot, "escaped_link"))
    assert.True(t, os.IsNotExist(statErr), "symlink must not be created outside wd")
}
```
Assertions: extraction either errors out or the symlink/file must not exist outside `wd`; currently (pre-fix) the symlink `escaped_link` is created one directory above `wd`, proving the escape.
