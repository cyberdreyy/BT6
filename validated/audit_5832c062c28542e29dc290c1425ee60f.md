### Title
Vault Secret Storage Partitions by Raw (Non-Normalized) Owner String, Allowing Per-Owner Secret Quota Bypass via Address-Casing Variants - (File: core/services/ocr2/plugins/vault/kvstore.go)

### Summary
The vault authorization layer treats an owner address as canonical only for the purpose of the authorization *comparison* (via `vaultutils.NormalizeOwner`), but the raw, attacker-supplied `Owner` string is what actually gets persisted and used as the storage partition key in the OCR3 vault KV store. Because Ethereum addresses have multiple valid string representations (mixed case, checksummed case, with/without `0x` prefix) that are all "the same address" to the authorization check but different strings to the storage layer, a single authorized owner can fragment their secrets across multiple logically-identical-but-textually-different metadata partitions, defeating any per-owner accounting (count/quota) built on top of `GetMetadata`/`GetSecretIdentifiersCountForOwner`. This mirrors the Taurus `SwapHandler` bug class: a security check ("this address == that address") is sufficient only against a single canonical representation of an identity, but the underlying system accepts multiple valid representations of that same identity, so the check can be trivially routed around.

### Finding Description
`vaultutils.NormalizeOwner` is documented as the single source of truth for identity comparison across the vault: "All comparison sites must use this function" [1](#0-0) .

The authorizer uses this normalized comparison only to check that the caller-supplied `Owner` on each secret identifier *matches* the authorized workflow owner — it never mutates or canonicalizes the `Owner` field itself: [2](#0-1) [3](#0-2) 

This means any string that normalizes to the same value as the authorized owner (e.g., `0xABCDEF...`, `0xabcdef...`, `abcdef...` without prefix) passes authorization identically — confirmed by the capability's own table-driven test which explicitly asserts differing case/prefix variants are all accepted as "not rejected": [4](#0-3) 

However, once authorized, that raw (non-canonicalized) `Owner` string is what flows into the OCR3_1 vault plugin's `KVStore`. `GetMetadata`/`WriteMetadata` key the metadata record directly off the raw owner string with no normalization: [5](#0-4) [6](#0-5) 

`addIDToMetadata` and `metadataContainsID` (used by `WriteSecret`/`GetSecret`) likewise look up metadata by `id.Owner` verbatim, not `NormalizeOwner(id.Owner)`: [7](#0-6) 

`GetSecretIdentifiersCountForOwner`, the function that would back any per-owner limit/quota, is a thin wrapper over this same raw-owner-keyed `GetMetadata`: [8](#0-7) 

Because `Owner` reaches the plugin unmodified from the client-controlled `SecretIdentifier.Owner`/`EncryptedSecret.Id.Owner` field, and only the *comparison* is case/prefix-insensitive while the *storage key* is not, one legitimately-authorized workflow owner can submit multiple `CreateSecrets` requests using differently-cased or differently-prefixed spellings of their own address. Each spelling authorizes successfully (identical to the canonical address under `NormalizeOwner`), yet each is persisted under a distinct `metadataPrefix+owner` record in the KV store, effectively creating unlimited independent "owner buckets" for what is, on-chain and semantically, a single owner identity.

### Impact Explanation
Any control implemented on top of `GetMetadata`/`GetSecretIdentifiersCountForOwner` that is intended to be enforced per real-world owner (e.g., a maximum number of stored secrets, storage-size accounting, or any owner-scoped resource limit) can be bypassed by an unprivileged but otherwise-authorized workflow owner simply by varying the textual casing/prefix of their own address across requests — each variant is a "different address" to the storage layer even though it is the same authorized entity. This is a quota/limit bypass analogous to the referenced bug class: the identity check (owner authorization) is sound only against one canonical representation, but the underlying storage accepts multiple valid representations of the same identity.

### Likelihood Explanation
The `Owner` field is fully attacker-controlled (any authorized workflow owner chooses the exact string used for `SecretIdentifier.Owner`/`EncryptedSecret.Id.Owner` in their JSON-RPC request), and `NormalizeOwner` explicitly documents that it treats case and `0x`-prefix as insignificant — meaning the bypass requires no special access, only submitting requests with a differently-formatted (but equally valid) copy of one's own address. This is trivial to trigger from the standard `CreateSecrets`/`UpdateSecrets` gateway paths already exercised in the vault test suite.

### Recommendation
Canonicalize the `Owner` field once at ingress (or immediately before it reaches the KVStore) using `vaultutils.NormalizeOwner` (or a full checksummed-address canonicalization), and store/key all metadata and per-owner counts off that canonical form rather than the raw client-supplied string. Ensure `KVStore.GetMetadata`, `WriteMetadata`, `metadataContainsID`, `addIDToMetadata`, and `removeIDFromMetadata` all operate on the normalized owner, consistent with the stated intent in `vaultutils/owner.go` ("When `VaultOwnerAddressCanonicalizationEnabled` is introduced, normalization at ingress will supersede comparison-site calls here").

### Proof of Concept
Not independently executed against a running node; the code paths above were traced statically. Conceptually:
1. Workflow owner `0xAbCdEf...` (checksummed) is authorized via the allowlist/JWT flow.
2. Attacker submits `CreateSecrets` with `Id.Owner = "0xabcdef..."` (lowercase) — passes `validateEncryptedSecretOwnerMismatch` because `NormalizeOwner` equates it to the authorized owner.
3. Attacker repeats with `Id.Owner = "abcdef..."` (no `0x` prefix), `Id.Owner = "0xABCDEF..."` (uppercase), etc. — each passes authorization for the same reason.
4. Each distinct string is persisted via `KVStore.WriteMetadata`/`addIDToMetadata` under a separate `metadataPrefix+owner` record (since these functions never call `NormalizeOwner`), so `GetSecretIdentifiersCountForOwner` under any one spelling never reflects the true total secrets stored for that owner across all spellings — defeating any quota built on it.

Full verification of whether a live per-owner quota is currently wired to `GetSecretIdentifiersCountForOwner` (e.g., in `request_validation.go`/`plugin.go`) was not completed due to tool-call limits; this should be confirmed in a Devin session by reading `core/services/ocr2/plugins/vault/request_validation.go` and `plugin.go` for quota-enforcement call sites.

func validateEncryptedSecretOwnerMismatch(encryptedSecrets []*vaultcommon.EncryptedSecret, workflowOwner string) error {
	if len(encryptedSecrets) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}
	for idx, encryptedSecret := range encryptedSecrets {
		if encryptedSecret == nil {
			return fmt.Errorf("encrypted secret must not be nil at index %d", idx)
		}
		if encryptedSecret.Id == nil {
			return fmt.Errorf("secret ID must not be nil at index %d", idx)
		}
		if vaultutils.NormalizeOwner(encryptedSecret.Id.Owner) != vaultutils.NormalizeOwner(workflowOwner) {
			return fmt.Errorf("encrypted secret owner at index %d %q does not match authorized workflow owner %q", idx, encryptedSecret.Id.Owner, workflowOwner)
		}
	}
	return nil
}

func (s *KVStore) GetMetadata(ctx context.Context, owner string) (*vault.StoredMetadata, error) {
	defer s.trackDuration(ctx, "GetMetadata", time.Now())
	b, err := s.reader.Read([]byte(metadataPrefix + owner))
	if err != nil {
		return nil, fmt.Errorf("failed to read metadata: %w", err)
	}

	if b == nil {
		return nil, nil
	}

	md := &vault.StoredMetadata{}
	err = proto.Unmarshal(b, md)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal md: %w", err)
	}
	return md, nil
}

func (s *KVStore) GetSecretIdentifiersCountForOwner(ctx context.Context, owner string) (int, error) {
	defer s.trackDuration(ctx, "GetSecretIdentifiersCountForOwner", time.Now())
	md, err := s.GetMetadata(ctx, owner)
	if err != nil {
		return 0, fmt.Errorf("failed to get metadata for owner %s: %w", owner, err)
	}

	count := 0
	if md != nil {
		count = len(md.SecretIdentifiers)
	}
	return count, nil
}

func (s *KVStore) WriteMetadata(ctx context.Context, owner string, metadata *vault.StoredMetadata) error {
	defer s.trackDuration(ctx, "WriteMetadata", time.Now())
	if metadata == nil {
		return errors.New("metadata cannot be nil")
	}
	b, err := proto.Marshal(metadata)
	if err != nil {
		return fmt.Errorf("failed to marshal metadata: %w", err)
	}

	err = s.writer.Write([]byte(metadataPrefix+owner), b)
	if err != nil {
		return fmt.Errorf("failed to write metadata: %w", err)
	}

	return nil
}

func (s *KVStore) metadataContainsID(ctx context.Context, id *vault.SecretIdentifier) (bool, error) {
	if id == nil {
		return false, errors.New("id cannot be nil")
	}
	md, err := s.GetMetadata(ctx, id.Owner)
	if err != nil {
		return false, fmt.Errorf("failed to get metadata for owner %s: %w", id.Owner, err)
	}

	if md == nil {
		return false, nil
	}

	for _, i := range md.SecretIdentifiers {
		if vaulttypes.KeyFor(id) == vaulttypes.KeyFor(i) {
			return true, nil
		}
	}

	return false, nil
}

func (s *KVStore) addIDToMetadata(ctx context.Context, id *vault.SecretIdentifier) error {
	if id == nil {
		return errors.New("id cannot be nil")
	}
	md, err := s.GetMetadata(ctx, id.Owner)
	if err != nil {
		return fmt.Errorf("failed to get metadata for owner %s: %w", id.Owner, err)
	}

	if md == nil {
		md = &vault.StoredMetadata{
			SecretIdentifiers: []*vault.SecretIdentifier{id},
		}
	} else {
		for _, i := range md.SecretIdentifiers {
			if vaulttypes.KeyFor(id) == vaulttypes.KeyFor(i) {
				// Nothing to do, early exit.
				return nil
			}
		}

		md.SecretIdentifiers = append(md.SecretIdentifiers, id)
	}

	err = s.WriteMetadata(ctx, id.Owner, md)
	if err != nil {
		return fmt.Errorf("failed to write metadata for owner %s: %w", id.Owner, err)
	}

	return nil
}
