### Title
Unisolated ERC4626 donation inflates `totalInterestDueNow`, letting a vault user mint phantom epoch interest and drain LP funds — ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
The Jupyter bug class is *attacker-authored content executed under a trusted origin* — the missing `sandbox` CSP means untrusted data runs with the origin's full authority. The on-chain analog is *attacker-controlled value admitted into trusted accounting*: `ProgrammableBorrower` reads the external ERC4626 vault's `convertToAssets` directly into `totalInterestDueNow()`, with no sandbox/isolation against donations. Any holder of the integrated vault (an explicitly allowed unprivileged attacker: "a user of the programmable borrower's ERC4626 vault") can donate underlying to the vault during a running epoch, fabricating vault "interest" that IdleCDO prices into the epoch as real yield.

### Finding Description
`_vaultNetInterest()` computes epoch PnL as `convertToAssets(shares) + epochWithdrawnFromVault − epochStartVaultAssets − epochDepositedToVault` [1](#0-0) . `convertToAssets` reflects *any* underlying donated directly to the ERC4626 vault, not just yield earned on the borrower's position. `totalInterestDueNow()` folds this into the single value IdleCDO reads to price the epoch [2](#0-1) , and `_stopEpoch` uses it as `_expectedInterest` — either pulling that cash from the honest borrower or, in minted mode, minting it into tranche prices [3](#0-2) . The donation guard `_skimDonatedAssets()` only protects the CDO's own token balance [4](#0-3) ; there is no equivalent isolation for donations sitting inside the external vault's share price — the exact "missing sandbox" gap.

### Impact Explanation
Two concrete impacts in the *running → stopped* phase, programmable + minted-interest mode:

1. **Theft of LP funds (minted mode):** Attacker deposits into the vault, then in a running epoch donates `D` underlying directly to the vault. `_vaultNetInterest` reports `+D` phantom interest; `stopEpoch` mints `D` of interest into tranche NAV. The attacker, also holding tranche tokens (a KYC-passing lender), requests withdrawal and exits at the inflated price, redeeming real underlying funded by other LPs. Net profit ≈ `D × (1 − attackerVaultShareFrac)` — strictly profitable when the attacker's vault share fraction is smaller than their tranche share fraction.

2. **Forced false default / permanent freezing (cash mode):** In non-minted mode the inflated `_amountToPullFromBorrower` exceeds what the honest borrower owes; `getFundsFromBorrower` fails and `_handleBorrowerDefault` fires [5](#0-4) , permanently pausing deposits, killing the epoch, and disabling withdraw requests [6](#0-5)  — a default manufactured by an unprivileged third party.

### Likelihood Explanation
Requires a programmable-borrower deployment whose ERC4626 vault accepts direct donations (standard ERC4626 behavior — `totalAssets` includes transferred tokens). The attacker only needs to be a vault user and/or tranche LP; no privileged role is involved. Cost is bounded by the donation size minus recovered vault-share value, so profitability depends on the attacker's relative share positions but is achievable whenever the facility is the dominant vault shareholder.

### Recommendation
Sandbox the vault valuation the same way `_skimDonatedAssets` sandboxes CDO-level donations: track expected vault assets via internal accounting (`epochStartVaultAssets + epochDepositedToVault − epochWithdrawnFromVault` plus borrower interest) rather than live `convertToAssets`, or bound credited vault interest to realized deltas from `vault.deposit`/`withdraw`/`redeem` return values. Alternatively, credit at most `shares × priceAtEpochStart` as principal and treat price appreciation only when actually redeemed.

  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
