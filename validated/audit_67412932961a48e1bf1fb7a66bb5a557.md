### Title
Unvalidated symlink targets in ZIP extraction permit path traversal and follow-through writes outside the extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipSymlinkEntry` creates a filesystem symlink whose target is taken verbatim from the ZIP entry's file content, with no validation that the target is confined to the extraction directory. Because `ExtractZipArchive` extracts all entries in archive order without re-validating paths through already-created symlinks, a single job-supplied cache/artifact ZIP can both create a symlink pointing outside the workspace and, via later entries in the same archive, write file content through that symlink to an arbitrary filesystem location reachable by the extracting process.

### Finding Description
`extractZipSymlinkEntry` (`helpers/archives/zip_extract.go:22-39`) reads the entry payload (`data`) and calls `os.Symlink(string(data), file.Name)` with no check that `string(data)` is relative and confined under the extraction root: [1](#0-0) 

`extractZipFile` (`helpers/archives/zip_extract.go:61-83`) dispatches by mode with no path-containment check for symlink targets, and `extractZipFileEntry` writes regular file content directly to `file.Name` via `os.OpenFile`/`io.Copy` after `os.MkdirAll(filepath.Dir(file.Name), ...)`: [2](#0-1) 

`ExtractZipArchive` iterates `archive.File` in a single pass and extracts every entry sequentially with no re-resolution/validation of the on-disk path against symlinks created by earlier entries in the same archive: [3](#0-2) 

The only existing pre-extraction check is `errorIfGitDirectory`, which only rejects `.git`-prefixed paths and does nothing to validate symlink targets or containment: [4](#0-3) 

Exploit flow: a job-controlled ZIP (produced e.g. by a job script and referenced as `artifacts:paths`/`cache:paths`, then downloaded and extracted via `commands/helpers/cache_extractor.go` `Execute` -> `archive.NewExtractor(...).Extract()` -> `ExtractZipArchive`, or via `commands/helpers/artifacts_downloader.go` `Execute`) contains:
1. Entry `evil` with `os.ModeSymlink` and payload `../../../../tmp` (or an absolute path) — creates a symlink at `wd/evil` pointing outside `wd`.
2. A subsequent entry `evil/payload.txt` — `extractZipFile` calls `os.MkdirAll(filepath.Dir("evil/payload.txt"))` and then opens/writes `evil/payload.txt`; the OS resolves the `evil` path component through the symlink, so the write lands at the symlink's target (e.g., `/tmp/payload.txt`), completely outside the intended extraction root `wd`.

This is confirmed by the corresponding archive-creation code (`helpers/archives/zip_create.go:17-30`), which shows GitLab Runner's own archiver preserves symlinks verbatim (`os.Readlink` -> stored as entry content), so the extractor is designed to recreate arbitrary symlink targets faithfully — but with no reciprocal validation on the extraction (attacker/untrusted-input) side, unlike what a defensive extractor should do (e.g. reject symlink targets that resolve outside the destination root, similar to widely known "zip-slip"/tar-symlink-follow classes of bugs).

The `wd` (extraction root) at `cache_extractor.go` and `artifacts_downloader.go` is the job's working directory (`os.Getwd()`), so the vulnerable code path is directly reachable via the "job's own artifact/cache" scenario named in the question.

### Impact Explanation
An unprivileged pipeline author who controls the contents of files placed under `cache:paths`/`artifacts:paths` (or who can otherwise supply a ZIP that Runner's cache-extractor/artifacts-downloader will process) can cause the Runner-side extraction helper process to create files or write attacker-controlled bytes anywhere on the filesystem the extracting process/user can reach — outside the job workspace/cache root. In shell/executor-on-host configurations this can write into arbitrary host paths accessible to the runner's OS user (e.g. other projects' cached data directories, runner config, or other locations under that user's write permission), which is a workspace/root-confinement violation matching the "File operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Fully reachable with attacker-only-controlled inputs: the attacker only needs to control the bytes of a ZIP file consumed by `cache-extractor` or `artifacts-downloader` (i.e., their own job's cache/artifact contents), no admin or cross-tenant access required. The extraction code performs no validation on symlink targets or on paths that traverse through previously created symlinks, so the exploit is deterministic and repeatable, limited only by filesystem write permissions of the process performing extraction.

### Recommendation
- In `extractZipSymlinkEntry`, reject or sanitize symlink targets that are absolute or that, when joined with the destination directory and cleaned, resolve outside the destination root.
- In `extractZipFile`/`extractZipFileEntry`/`extractZipDirectoryEntry`, resolve `file.Name`'s full path against the extraction root (`filepath.Join` + `filepath.Clean`, then verify with `filepath.Rel`/prefix check) before any `os.MkdirAll`/`os.OpenFile`/`os.Symlink` call, rejecting entries whose final resolved path escapes the root — this must also account for intermediate symlinked directories created by earlier entries in the same archive (e.g., use `os.Lstat` on each path component, or perform extraction with `O_NOFOLLOW`-equivalent semantics / a safe-join helper that walks and rejects symlinked intermediate directories).
- Apply the same containment check consistently to both zip and tar extraction paths (`helpers/archives`) for consistency.

### Proof of Concept
```go
// helpers/archives/zip_extract_test.go
func TestExtractZipSymlinkEscape(t *testing.T) {
    dir := t.TempDir()
    outsideDir := t.TempDir() // simulate location outside intended extraction root

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)

    // 1. symlink entry pointing outside extraction dir
    fh := &zip.FileHeader{Name: "evil", Method: zip.Store}
    fh.SetMode(os.ModeSymlink | 0777)
    w, _ := zw.CreateHeader(fh)
    _, _ = w.Write([]byte(filepath.Join(outsideDir))) // absolute path target

    // 2. file entry written "through" the symlink
    fh2 := &zip.FileHeader{Name: "evil/payload.txt", Method: zip.Deflate}
    fh2.SetMode(0644)
    w2, _ := zw.CreateHeader(fh2)
    _, _ = w2.Write([]byte("pwned"))

    require.NoError(t, zw.Close())

    r, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    oldWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(dir))
    defer os.Chdir(oldWd)

    err = ExtractZipArchive(&r.Reader)
    require.NoError(t, err)

    // Assertion: extraction must NOT have written outside outsideDir/payload.txt
    escaped := filepath.Join(outsideDir, "payload.txt")
    _, statErr := os.Stat(escaped)
    assert.True(t, os.IsNotExist(statErr),
        "expected extraction to reject/confine symlink target, but file escaped to %s", escaped)
}
```
Expected current (vulnerable) behavior: the test fails because `outsideDir/payload.txt` exists with content `pwned`, proving the escape. After applying the recommended containment checks, the assertion should pass (extraction rejects the symlink or confines the write).

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
