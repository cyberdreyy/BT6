### Title
`httpTriggerHandler.HandleNodeTriggerResponse` always marks aggregated workflow-execution responses as `NoError`, hiding node-agreed JSON-RPC errors from the caller - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
When a DON reaches quorum on a node response to an unprivileged user's HTTP-triggered workflow execution request, `HandleNodeTriggerResponse` forwards the raw aggregated JSON-RPC response to the user but unconditionally sets the transport-level `ErrorCode` to `api.NoError` and unconditionally increments the success metric, even when the aggregated `jsonrpc.Response` itself carries a populated `.Error` field (i.e., the DON consensually reported a failure).

### Finding Description
In `HandleNodeTriggerResponse`, once `agg.CollectAndAggregate` returns a quorum-reached response (`aggResp`), the handler builds the callback payload like this: [1](#0-0) 

Notice it hardcodes `ErrorCode: api.NoError` regardless of whether `aggResp.Error` is set, and always calls `h.metrics.IncrementRequestSuccess`. This directly mirrors the analog bug pattern in the report: an operation's real completion status (`aggResp.Error`, analogous to `cross_chain_msg_status`) is discarded and replaced with a hardcoded success value, because the outer call succeeded (`agg.CollectAndAggregate` returned without error / `SendResponse` succeeded — analogous to `handler.receive_cross_chain_callback` returning `true`).

The codebase demonstrates the *correct* pattern elsewhere: the vault gateway handler derives `ErrorCode` from the actual JSON-RPC `resp.Error` field before building the callback payload: [2](#0-1) 

and `api.FromJSONRPCErrorCode` exists precisely to translate a JSON-RPC error code into the gateway's `ErrorCode` enum: [3](#0-2) 

`http_trigger_handler.go` never calls `FromJSONRPCErrorCode` for the aggregated trigger response, meaning even when 2f+1 (or the (N+F)/2+1 threshold) nodes agree that the workflow execution failed (returning a JSON-RPC `Error` object in `aggResp`), the gateway still reports `ErrorCode: api.NoError` to the transport layer, which maps to an HTTP 200 status via `ToHttpErrorCode`: [4](#0-3) 

### Impact Explanation
An unprivileged caller submitting an HTTP-triggered workflow-execution request (`gateway_common.MethodWorkflowExecute`) via the gateway's public-facing endpoint receives a "success" transport-level signal (HTTP 200, `ErrorCode.NoError`, and the request-success metric incremented) even when the DON consensus response body contains a JSON-RPC `Error`. Callers/monitoring systems relying on the transport-level `ErrorCode`/HTTP status rather than parsing the embedded JSON-RPC `error` field will misinterpret a failed workflow execution as a successful one — this is the same class of impact as the referenced high-severity finding (a failed operation being reported as successful), affecting operational correctness, monitoring/alerting, and any automation that gates on HTTP status rather than payload inspection. It is not a fund-movement or authentication bypass; the actual JSON-RPC body still carries the correct `Error` object for callers that inspect it, which somewhat limits severity relative to the original on-chain finding.

### Likelihood Explanation
This path is reachable directly from any unprivileged user submitting a normal `workflow.execute` HTTP trigger request through the gateway; no privileged access or malicious node/peer is required to hit the hardcoded-success branch — it will trigger any time a workflow execution legitimately produces an error result that reaches quorum among honest nodes.

### Recommendation
Derive the `UserCallbackPayload.ErrorCode` from `aggResp.Error` (mirroring the vault handler's `sendSuccessResponse` pattern via `api.FromJSONRPCErrorCode`) instead of hardcoding `api.NoError`, and only invoke `IncrementRequestSuccess` when `aggResp.Error == nil` (calling an appropriate failure metric otherwise).

### Proof of Concept
1. An unprivileged user submits a `workflow.execute` HTTP trigger request through the gateway (`HandleUserTriggerRequest`), which is broadcast to DON nodes.
2. A quorum of nodes ((N+F)/2+1) legitimately execute the workflow and return an identical JSON-RPC response containing an `Error` field (e.g., workflow execution failed on the target endpoint).
3. `agg.CollectAndAggregate` reaches threshold and returns this `aggResp` (with `.Error` populated) to `HandleNodeTriggerResponse`.
4. The handler marshals `aggResp` as-is into `rawResp` but sends it back to the user with `ErrorCode: api.NoError` [5](#0-4) , causing the gateway to return HTTP 200 and record a success metric for what the DON consensually reported as a failure.

func FromJSONRPCErrorCode(errorCode int64) ErrorCode {
	jsonrpcErrorToGatewayError := map[int64]ErrorCode{
		0:                            NoError,
		jsonrpc2.ErrParse:            UserMessageParseError,
		jsonrpc2.ErrInvalidParams:    InvalidParamsError,
		jsonrpc2.ErrInvalidRequest:   HandlerError,
		jsonrpc2.ErrServerOverloaded: RequestTimeoutError,
		jsonrpc2.ErrInternal:         FatalError,
		jsonrpc2.ErrMethodNotFound:   UnsupportedMethodError,
		jsonrpc2.ErrLimitExceeded:    LimitExceededError,
		jsonrpc2.ErrConflict:         ConflictError,
	}

	code, ok := jsonrpcErrorToGatewayError[errorCode]
	if !ok {
		return FatalError
	}
	return code
}

func ToHttpErrorCode(errorCode ErrorCode) int {
	gatewayErrorToHTTPError := map[ErrorCode]int{
		NoError:                  200, // OK
		UserMessageParseError:    400, // Bad Request
		UnsupportedDONIdError:    400, // Bad Request
		UnsupportedMethodError:   400, // Bad Request
		HandlerError:             400, // Bad Request
		InvalidParamsError:       400, // Bad Request
		RequestTimeoutError:      504, // Gateway Timeout
		NodeReponseEncodingError: 500, // Internal Server Error
		FatalError:               500, // Internal Server Error
		StaleNodeResponseError:   500, // Internal Server Error
		ConflictError:            409, // Conflict
		LimitExceededError:       429, // Too Many Requests
	}

	code, ok := gatewayErrorToHTTPError[errorCode]
	if !ok {
		return 500
	}
	return code
}
