### Title
`BlockRejection` signature does not cover `reason_code`/`response_data`, allowing reject-reason forgery without the signer's key — ([File: libsigner/src/v0/messages.rs])

### Summary
`BlockRejection::hash()` — the digest that `sign`, `verify`, and `recover_public_key` all operate on — only commits to `signer_signature_hash` and `chain_id`. The human-readable `reason`, the machine-readable `reason_code: RejectCode`, and the entire `response_data: BlockResponseData` (which carries `reject_reason: RejectReason`, `tenure_extend_timestamp`, `failed_txid`, etc.) are excluded from what is signed. This is structurally the same class of bug as the python-ldap advisory: a function that is trusted to "sanitize"/authenticate a payload silently leaves part of the attacker-influenced input untouched, so callers who assume the whole struct is authenticated are wrong. [1](#0-0) 

### Finding Description
`BlockRejection` is a self-authenticating gossip message: on the signer side, `handle_block_rejection` authenticates it purely by recovering the public key from the embedded signature and checking that the address is a valid signer — it never cross-checks which StackerDB slot/owner the bytes arrived on: [2](#0-1) 

Because `hash()` = `structured_data_message_hash(signer_signature_hash, domain(chain_id))` only, any party holding one genuine `(signer_signature_hash, chain_id, signature)` tuple emitted by an honest signer `S` can construct a *new* `BlockRejection` for the same block/chain_id but with an arbitrary `reason`, `reason_code`, and `response_data.reject_reason`, reusing `S`'s original `signature` unchanged. `verify`/`recover_public_key` will still succeed and still resolve to `S`'s real address: [3](#0-2) 

The forged `reject_reason` is then persisted per-address and fed into weight computations that are consensus-relevant. In particular, `store_and_process_block_rejection` tallies `RejectReasonPrefix::ReorgNotAllowed`-weighted rejections and, once ≥30% weight is reached, marks the current miner `InvalidatedBeforeFirstBlock`: [4](#0-3) 

Since the reason/response_data are not bound to the signature, this weight can be inflated using reused signatures whose `reason_code` field has been swapped to `ReorgNotAllowed`, without ever obtaining the originating signer's private key.

### Impact Explanation
This is a cross-context-valid signature: the same signature bytes are valid across attacker-chosen `reason_code`/`response_data` contexts, breaking the equality "the content a signer signed == the content other signers act on." Concretely, it can be used to inflate `total_reorg_reject_weight` and flip `SortitionMinerStatus::InvalidatedBeforeFirstBlock` for a legitimate, canonical miner using rejection weight that was never actually cast for the "reorg not allowed" reason — wedging the signer set away from signing an otherwise valid tenure (High: "a signer wedged into never signing valid blocks").

### Likelihood Explanation
Exploitation requires only observing one previously broadcast, validly-signed `BlockRejection` from any signer for a given block (routine, since these are broadcast to the whole signer set/StackerDB and to the node) and relaying a modified copy; it needs no signer key, no majority, and no StackerDB slot-ownership bypass, since `handle_block_rejection` performs no slot/provenance check and relies solely on the inner (partial) signature.

### Recommendation
Bind `reason`, `reason_code`, and the full `response_data` (or at minimum `reject_reason`) into the `BlockRejection::hash()` digest, so `verify`/`recover_public_key` fail if any of these fields are altered from what was actually signed.

### Proof of Concept
1. Honest signer `S` genuinely rejects block `H` with `RejectReason::ConnectivityIssues` (or any non-`ReorgNotAllowed` reason), producing `BlockRejection { signer_signature_hash: H, chain_id, signature: SIG, reason_code: X, response_data: { reject_reason: X, .. }, .. }`.
2. Attacker (no key required) captures this message, then constructs `BlockRejection' { signer_signature_hash: H, chain_id, signature: SIG /* unchanged */, reason_code: RejectCode::ValidationFailed(ValidateRejectCode::ReorgNotAllowed), response_data: { reject_reason: RejectReason::ReorgNotAllowed{..}, .. }, reason: "forged" }`.
3. Any signer receiving `BlockRejection'` calls `recover_public_key()` / `is_valid_signer()`; both succeed because `hash()` only depends on `signer_signature_hash` and `chain_id`, both unchanged ( [5](#0-4) ). The forged rejection is stored and counted with `RejectReasonPrefix::ReorgNotAllowed`, contributing toward the 30% threshold that invalidates the current miner ( [6](#0-5) ).

    pub fn hash(&self) -> Sha256Sum {
        let domain_tuple = make_structured_data_domain("block-rejection", "1.0.0", self.chain_id);
        let data = Value::buff_from(self.signer_signature_hash.as_bytes().into()).unwrap();
        structured_data_message_hash(data, domain_tuple)
    }

    /// Sign the block rejection and set the internal signature field
    fn sign(&mut self, private_key: &StacksPrivateKey) -> Result<(), String> {
        let signature_hash = self.hash();
        self.signature = private_key.sign(signature_hash.as_bytes())?;
        Ok(())
    }

    /// Verify the rejection's signature against the provided signer public key
    pub fn verify(&self, public_key: &StacksPublicKey) -> Result<bool, String> {
        if self.signature == MessageSignature::empty() {
            return Ok(false);
        }
        let signature_hash = self.hash();
        public_key
            .verify(&signature_hash.0, &self.signature)
            .map_err(|e| e.to_string())
    }

    /// Recover the public key from the rejection signature
    pub fn recover_public_key(&self) -> Result<StacksPublicKey, &'static str> {
        if self.signature == MessageSignature::empty() {
            return Err("No signature to recover public key from");
        }
        let signature_hash = self.hash();
        StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            signature_hash.as_bytes(),
            &self.signature,
        )
    }

    fn handle_block_rejection(
        &mut self,
        rejection: &BlockRejection,
        sortition_state: &mut Option<SortitionsView>,
    ) {
        debug!("{self}: Received a block-reject signature: {rejection:?}");

        let block_hash = &rejection.signer_signature_hash;
        let signature = &rejection.signature;

        // recover public key
        let Ok(public_key) = rejection.recover_public_key() else {
            debug!("{self}: Received block rejection with an unrecovarable signature. Will not store.";
               "signer_signature_hash" => %block_hash,
               "signature" => %signature
            );
            return;
        };

        // authenticate the signature -- it must be signed by one of the stacking set
        let signer_address = StacksAddress::p2pkh(self.mainnet, &public_key);
        if !self.is_valid_signer(&signer_address) {
            debug!("{self}: Received block rejection with an invalid signature. Will not store.";
                "signer_public_key" => ?public_key,
                "signer_address" => %signer_address,
                "signer_signature_hash" => %block_hash,
                "signature" => %signature
            );
            return;
        }
