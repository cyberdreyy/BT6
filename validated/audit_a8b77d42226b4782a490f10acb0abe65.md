### Title
`get_additional_mint_data` trusts unpacked `Mint` decimals from a cross-referenced account without verifying the mint account's owner program - ([File: rpc/src/parsed_token_accounts.rs])

### Summary
`get_parsed_token_account` and `get_mint_owner_and_additional_data` fetch whatever account is referenced by the 32-byte "mint" field embedded in a token-account's data and feed its raw bytes into `StateWithExtensions::<Mint>::unpack` without ever checking that the referenced account is owned by an SPL Token program. An attacker who controls both the "token account" and the referenced "mint" account can therefore make `getAccountInfo`/`jsonParsed` (and the equivalent pubsub path) report an arbitrary, attacker-chosen `decimals`/`uiAmount` for the account.

### Finding Description
`get_parsed_token_account` extracts the mint pubkey directly from account bytes via `get_token_account_mint`, which only checks the SPL-Token account-shape marker (`Account::valid_account_data`), not any ownership relationship: [1](#0-0) 

It then fetches that mint pubkey's account from the bank/overwrite set with no owner filtering: [2](#0-1) 

and passes the raw bytes to `get_additional_mint_data`, which purely attempts `StateWithExtensions::<Mint>::unpack(data)` — it never inspects or asserts the fetched account's `owner()` field before trusting `mint.base.decimals`: [3](#0-2) 

The sibling helper `get_mint_owner_and_additional_data` does read `*mint_account.owner()`, but only to *return* it as informational metadata — it is never used to gate/validate the decimal extraction that happens just before it: [4](#0-3) 

The only owner check in the whole pipeline occurs one level up, in `encode_ui_account`, which dispatches to the SPL-Token parser based on the *outer* account's (`A`'s) `owner()` field via `parse_account_data_v3`: [5](#0-4) 

Because Solana's System Program `CreateAccount` instruction lets any signer set an account's `owner` field to an arbitrary program ID (including a real Token program ID) without any CPI into that program, an attacker can:
1. Create account `B` (owner = anything, e.g. System Program) whose bytes happen to unpack as a valid `Mint` (only requires a fixed-size buffer with an `is_initialized` byte and `COption` discriminants set to 0/1 — trivially craftable), with `decimals` set to an arbitrary attacker-chosen value.
2. Create account `A` with `owner` forged to a real Token program ID (via `CreateAccount`, bypassing `InitializeAccount`) and data laid out to satisfy `Account::valid_account_data`, with the mint field (bytes 0..32) set to `B`.
3. Call `getAccountInfo(A, {encoding: "jsonParsed"})` once.

The RPC path (`encode_ui_account` → `parse_account_data_v3` → dispatch by `A.owner()` → `get_parsed_token_account` → `get_token_account_mint` → fetch `B` → `get_additional_mint_data(B.data())`) will unpack `B` as a `Mint` and use its `decimals` to compute `tokenAmount.uiAmount`/`uiAmountString`/`decimals` for `A`, even though `B` was never validated to be owned by any Token program. This violates the invariant that decoders must not trust owner-unchecked cross-account data ("PARSE_FIDELITY").

### Impact Explanation
This causes a JSON-RPC decoder to misreport `tokenAmount.decimals`/`uiAmount`/`uiAmountString` for an account, based on data from an unvalidated cross-referenced account. This falls under the decoder-misreporting / wrong-data-returned category in scope. The impact is currently confined to the attacker's own crafted accounts (`A`/`B`); any client (wallet, explorer, exchange integration) that queries account `A` via `jsonParsed` and trusts the RPC-reported `decimals`/`uiAmount` without independently validating that the referenced mint (`B`) is owned by a real Token program will receive incorrect/misleading numeric data.

### Likelihood Explanation
Fully attacker-reachable with a single unprivileged client: creating two accounts with attacker-chosen owner/data via `CreateAccount` (no special privileges, no token-program CPI needed to forge the owner field) followed by one `getAccountInfo` call. No commitment, quota, or length-check guard in the current code path (`get_token_account_mint`, `get_additional_mint_data`, `get_mint_owner_and_additional_data`) verifies `B`'s owner. This is easily reproducible and deterministic.

### Recommendation
In `get_additional_mint_data` (and equivalently `get_mint_owner_and_additional_data`), before trusting the unpacked `Mint` state, verify that the fetched mint account's `owner()` is one of the recognized SPL Token program IDs (`solana_account_decoder::parse_token::is_known_spl_token_id` / `spl_token_ids`), matching (or at least compatible with) the owner of the token account being decoded. Reject/return an error (falling back to raw/base64 encoding, as already done when parsing fails) if the referenced mint account is not owned by a Token program.

```rust
// account-decoder / rpc integration test sketch
#[test]
fn test_forged_mint_owner_misreports_decimals() {
    // 1. Craft B: owner = System Program (NOT a token program),
    //    data unpacks successfully as Mint with attacker-chosen decimals.
    let mut mint_like_data = vec![0u8; Mint::get_packed_len()];
    let mut fake_mint = Mint::unpack_unchecked(&mint_like_data).unwrap();
    fake_mint.is_initialized = true;
    fake_mint.decimals = 250; // arbitrary attacker-chosen bogus decimals
    Mint::pack(fake_mint, &mut mint_like_data).unwrap();
    let b_pubkey = Pubkey::new_unique();
    let b_account = AccountSharedData::create(
        1_000_000, mint_like_data, solana_sdk::system_program::id(), false, 0,
    );

    // 2. Craft A: owner = spl_token::id() (forged directly, not via InitializeAccount),
    //    mint field = b_pubkey.
    let mut account_data = vec![0u8; Account::get_packed_len()];
    let mut token_account = Account::unpack_unchecked(&account_data).unwrap();
    token_account.mint = b_pubkey;
    token_account.owner = Pubkey::new_unique();
    token_account.state = AccountState::Initialized;
    token_account.amount = 12345;
    Account::pack(token_account, &mut account_data).unwrap();
    let a_pubkey = Pubkey::new_unique();
    let a_account = AccountSharedData::create(
        1_000_000, account_data, spl_token_interface::id(), false, 0,
    );

    // 3. Populate bank with A and B, then call get_parsed_token_account.
    bank.store_account(&a_pubkey, &a_account);
    bank.store_account(&b_pubkey, &b_account);
    let ui_account = get_parsed_token_account(&bank, &a_pubkey, a_account, None);

    // Expected (fixed) behavior: since B is not owned by a token program,
    // additional_data lookup should fail/be rejected, and either:
    //  - decoding falls back to raw/binary encoding, or
    //  - decimals defaults safely / errors out.
    // Current (buggy) behavior: ui_account contains
    // tokenAmount.decimals == 250 derived from B despite B not being
    // owned by any SPL Token program - assert this is NOT the case
    // after the fix.
}
```

```rust
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))

        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}
```

```rust
fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
```
