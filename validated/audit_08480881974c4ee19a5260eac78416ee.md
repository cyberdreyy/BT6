### Title
`GET /v2/external_initiators` leaks live `OutgoingToken` webhook secret to any caller with list access - ([File: core/web/presenters/external_initiators.go])

### Summary
The `ExternalInitiatorsController.Index` handler serializes every stored `bridges.ExternalInitiator` through `presenters.NewExternalInitiatorResource`, which copies the live `OutgoingToken` secret directly into the JSON response. Any caller permitted to hit the list endpoint receives the raw secret the node uses to authenticate its outbound callbacks to the external initiator's webhook, allowing that caller to impersonate the node's outbound calls to the third-party EA service.

### Finding Description
`ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go`, lines 50-59) fetches all `ExternalInitiator` records from `BridgeORM().ExternalInitiators` and, for each one, calls `presenters.NewExternalInitiatorResource(initiator)` before returning the collection via `paginatedResponse`. [1](#0-0) 

`ExternalInitiatorResource` explicitly includes an `OutgoingToken` field tagged `json:"outgoingToken"`, and `NewExternalInitiatorResource` populates it straight from `ei.OutgoingToken`: [2](#0-1) 

`ExternalInitiator.OutgoingToken` is a generated secret (`utils.NewSecret(utils.DefaultSecretSize)`), separate from the hashed/salted `HashedSecret`/`Salt` used for inbound authentication of the initiator itself, and is meant to authenticate the node's *outbound* callback to the external initiator's webhook endpoint: [3](#0-2) 

Unlike the `HashedSecret`/`Salt` fields (which are never exposed because `ExternalInitiatorResource` doesn't include them), `OutgoingToken` is a plaintext live secret and is returned unredacted in the list response. This differs from the `Create` handler, which appropriately returns `OutgoingToken`/`OutgoingSecret` once at creation time via `NewExternalInitiatorAuthentication` (necessary since it's the only time the value is surfaced to the legitimate operator creating the initiator), but the `Index` presenter re-exposes the same live secret on every subsequent list call, to anyone with access to that route, indefinitely.

### Impact Explanation
Any caller able to invoke `GET /v2/external_initiators` obtains the plaintext `OutgoingToken` for every registered external initiator. This token is used by third-party EA/webhook receivers to authenticate that a callback truly originated from the Chainlink node; leaking it lets the attacker forge callbacks that the receiving service will treat as authentic node-originated requests. This matches the "secret/key disclosure enabling request impersonation" bounty class.

### Likelihood Explanation
The endpoint requires only read/list access to the external initiators route (no admin/write action needed) and there is no field-level redaction in the presenter, so the leak occurs on every successful list call — fully repeatable with a single authenticated GET request. The exact minimum role/token type enforced by the router middleware for this specific route was not fully confirmed within this investigation (the route registration file was not located), so the precise privilege threshold is an open item; however, the leak occurs unconditionally for any caller permitted to call `Index`, independent of that threshold.

### Recommendation
Remove `OutgoingToken` (and `OutgoingSecret`, if ever added) from `ExternalInitiatorResource`/`NewExternalInitiatorResource` used by the list/index endpoint. Only return live secrets once, at creation time, via the existing `ExternalInitiatorAuthentication` presenter, and never re-serialize them on subsequent reads.

### Proof of Concept
1. Seed the DB with an `ExternalInitiator` created via `bridges.NewExternalInitiator`, capturing its `OutgoingToken`.
2. Issue an HTTP `GET /v2/external_initiators` request through the router using the minimal credential permitted for the route (per the app's auth middleware).
3. Parse the JSON response body into `presenters.ExternalInitiatorResource` (or raw map) and assert:
   - `outgoingToken` field is present and equals the seeded `ExternalInitiator.OutgoingToken` (demonstrating the leak today).
   - After the fix, assert the response contains only `accessKey`, `name`, `url`, `createdAt`, `updatedAt`, and does NOT contain `outgoingToken`, `outgoingSecret`, `hashedSecret`, or `salt`.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// ExternalInitiator represents a user that can initiate runs remotely
type ExternalInitiator struct {
	ID             int64
	Name           string
	URL            *models.WebURL
	AccessKey      string
	Salt           string
	HashedSecret   string
	OutgoingSecret string
	OutgoingToken  string

	CreatedAt time.Time
	UpdatedAt time.Time
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
