### Title
`borrower`/`manager` are set in `IdleCreditVault.initialize` without validation; a mistyped or zero borrower bricks or drains the credit vault - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.initialize` stores the privileged `borrower` and `manager` addresses verbatim, with no `address(0)` or sanity check, even though the protocol later enforces a non-zero borrower in `setBorrower`. The factory's `deployCreditVault`/`deployRevolvingCreditVault` path only validates `strategyData.manager` and forwards `strategyData.borrower` unchecked into the initializer. Because `borrower` is the single address that receives the entire pooled principal when `startEpoch` routes deposited funds out of the `IdleCDOEpochVariant`, a typo or `address(0)` at deployment either permanently sends all lender deposits to an uncontrolled address or makes `startEpoch` revert (the underlying `safeTransfer` to `address(0)` reverts for USDC-style tokens), freezing the vault.

### Finding Description
In `contracts/strategies/idle/IdleCreditVault.sol:124-158`, `initialize` does:

```solidity
token = _underlyingToken;
underlyingToken = IERC20Detailed(token);
...
borrower = _borrower;
manager = _manager;
```

No check on `_borrower`, `_manager`, or even `_underlyingToken` — while the same file's `setBorrower` explicitly guards `require(_borrower != address(0), "IS_0")` (`IdleCreditVault.sol:191-194`), showing the invariant was intended but not applied at initialization. `setManager` (`IdleCreditVault.sol:185-187`) also has no zero check.

In `contracts/IdleCreditVaultFactory.sol:98-99`, only `manager` is validated (`if (manager == address(0)) revert Is0();`), and `_deployBaseCreditVault` (`IdleCreditVaultFactory.sol:182-193`) passes `strategyData.borrower` straight into `IdleCreditVault.initialize`. `borrower` is the counterparty to which the epoch's pooled underlying is transferred at `startEpoch` and from which repayments are pulled at `stopEpoch`; it is also the expected approver of the CDO. A mistyped nonzero `borrower` receives all deposited principal — an unrecoverable transfer to the wrong recipient, structurally identical to the Surge `operator` finding. A zero `borrower` makes every `startEpoch` revert on the token transfer, permanently freezing deposits unless the owner notices and calls `setBorrower` before funds move; and `manager == address(0)` silently disables all `manager`-gated operations (`setApr`, `startEpoch`/`stopEpoch` flows) that the vault's lifecycle depends on. Note `ProgrammableBorrower.initialize` (`contracts/strategies/idle/ProgrammableBorrower.sol:112-117`) does validate all of its addresses, which makes the omission in `IdleCreditVault.initialize` a clear inconsistency rather than a design choice.

### Impact Explanation
- **Permanent loss of all pooled deposits**: if `strategyData.borrower` is a typo'd nonzero address, the first `startEpoch` transfers the entire deposited principal to an uncontrolled recipient; tranche holders' funds are gone.
- **Temporary/permanent freezing**: if `borrower == address(0)`, `startEpoch` reverts on the underlying transfer and deposits are frozen until the owner corrects the role; if `manager` or `borrower` roles are mis-set in combination (e.g., owner is the factory after ownership is transferred to `treasury` at `IdleCreditVaultFactory.sol:113-114`), remediation depends on `treasury` acting.
- **Quantified loss**: up to 100% of vault TVL for a nonzero typo; full deposit freeze for `address(0)`.

### Likelihood Explanation
The trigger is a deployment-time mistake, not an attack — identical to the external report's medium severity. Likelihood is elevated because the factory exposes `borrower` as a raw struct field with no validation, contrasting with `feeReceiver`, `treasury`, `proxyAdmin`, `manager`, and the `ProgrammableBorrower` initializer which all validate for zero. Anyone can call `deployCreditVault`, so the unvalidated path is exercised routinely.

### Recommendation
Mirror the checks already present elsewhere: in `IdleCreditVault.initialize` revert if `_underlyingToken`, `_manager`, or `_borrower` is `address(0)` (and ideally require `_borrower.code.length > 0` or an explicit confirmation pattern), and add `if (strategyData.borrower == address(0)) revert Is0();` in `IdleCreditVaultFactory.deployCreditVault`/`deployRevolvingCreditVault`. Alternatively set `borrower` to the factory/`msg.sender` at init and let the owner configure it via the already-guarded `setBorrower`, matching the external report's recommendation pattern.

### Proof of Concept
Foundry fork test (mainnet, USDC), against the pattern in `test/foundry/IdleCreditVault.t.sol`:

```solidity
function testBorrowerZeroFreezesVault() external {
  // 1. Deploy strategy with borrower = address(0) — initialize does NOT revert
  IdleCreditVault s = new IdleCreditVault();
  stdstore.target(address(s)).sig(s.token.selector).checked_write(address(0));
  s.initialize(USDC, owner, manager, address(0), "typo", 10e18); // succeeds
  assertEq(s.borrower(), address(0));

  // 2. Deploy CDO + wire it
  cdoEpoch = new IdleCDOEpochVariant();
  stdstore.target(address(cdoEpoch)).sig(cdoEpoch.token.selector).checked_write(address(0));
  cdoEpoch.initialize(0, USDC, address(this), owner, rebalancer, address(s), 100000);
  vm.prank(owner);
  s.setWhitelistedCDO(address(cdoEpoch));

  // 3. Lender deposits succeed — funds are now trapped behind a broken borrower
  deal(USDC, lender, 100_000e6);
  vm.startPrank(lender);
  IERC20Detailed(USDC).approve(address(cdoEpoch), type(uint256).max);
  IdleCDO(address(cdoEpoch)).depositAA(100_000e6);
  vm.stopPrank();

  // 4. startEpoch reverts on safeTransfer to address(0): deposits frozen
  vm.prank(manager);
  cdoEpoch.setEpochParams(36.5 days, 5 days);
  vm.prank(manager);
  vm.expectRevert(); // USDC transfer to address(0)
  cdoEpoch.startEpoch();
}

function testBorrowerTypoDrainsPrincipal() external {
  address typo = address(0xdea1); // uncontrolled address

  // and IERC20Detailed(USDC).balanceOf(typo) == full pool principal,
  // which can never be repaid into the vault => 100% loss to tranche holders.
```

The equivalent factory-level PoC is `factory.deployCreditVault` with `strategyData.borrower = address(0)`: it does not revert (only `manager` is checked), producing a vault whose `borrower` can never receive or repay funds.

One caveat: if `borrower` misconfiguration is caught before `startEpoch`, the owner can repair it via `setBorrower`, so the permanent-loss branch requires the error to go unnoticed until the first epoch start — consistent with the medium-severity rating of the source report.
