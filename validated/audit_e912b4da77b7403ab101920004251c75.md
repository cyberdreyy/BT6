`kamino_withdraw`'s vault-related accounts are protected by Anchor's declarative constraints, which bind them directly to the specific `bank` account passed in rather than allowing attacker-supplied substitution:

- `liquidity_vault` is constrained by `seeds = [LIQUIDITY_VAULT_AUTHORITY_SEED, bank.key()]` derived from the *same* bank loaded in the instruction and validated with `bump = bank.load()?.liquidity_vault_authority_bump`, and the bank account itself enforces `has_one = liquidity_vault` [1](#0-0) .
- The Kamino reserve/obligation accounts (`integration_acc_1`, `integration_acc_2`) are similarly pinned via `has_one = integration_acc_1` / `has_one = integration_acc_2` on the bank, plus additional constraints checking the obligation's `deposit_reserve` matches `integration_acc_1.key()` [2](#0-1) .

`find_bank_vault_pda` itself is a pure PDA-derivation helper used off-chain/CLI-side and in test fixtures to compute the canonical vault address; it is not the mechanism gatekeeping account validity inside `kamino_withdraw` [3](#0-2) . The on-chain enforcement instead relies on Anchor's `seeds`/`bump`/`has_one` constraints tied to the exact `bank` loaded, so a candidate vault from "another integration family" cannot pass validation — Anchor would reject any account whose derived PDA or stored bank field doesn't match.

The fee-adjusted amount conversion helpers (`calculate_pre_fee_spl_deposit_amount`, `calculate_post_fee_spl_deposit_amount`) operate purely on numeric SPL Token-2022 transfer-fee math and are unrelated to vault PDA selection or cross-family substitution [4](#0-3) . There is no code path in `kamino_withdraw` where these conversions influence which vault account is used for a CPI, and no path where an attacker-supplied vault of a different `BankVaultType` (Fee/Insurance) or a different bank's vault could be substituted for the liquidity vault, since Anchor's seed/bump/has_one checks are enforced before the CPI is issued [5](#0-4) .

pub fn calculate_pre_fee_spl_deposit_amount(
    mint_ai: AccountInfo,
    post_fee_amount: u64,
    epoch: u64,
) -> MarginfiResult<u64> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(post_fee_amount);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    match mint.get_extension::<TransferFeeConfig>() {
        Ok(transfer_fee_config) => {
            let epoch_fee = transfer_fee_config.get_epoch_fee(epoch);
            let pre_fee_amount = calculate_pre_fee_amount(epoch_fee, post_fee_amount).unwrap();
            Ok(pre_fee_amount)
        }
        Err(_) => Ok(post_fee_amount),
    }
}

pub fn calculate_post_fee_spl_deposit_amount(
    mint_ai: AccountInfo,
    input_amount: u64,
    epoch: u64,
) -> MarginfiResult<u64> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(input_amount);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    let fee = if let Ok(transfer_fee_config) = mint.get_extension::<TransferFeeConfig>() {
        transfer_fee_config
            .calculate_epoch_fee(epoch, input_amount)
            .unwrap()
    } else {
        0
    };

    let output_amount = input_amount
        .checked_sub(fee)
        .ok_or(MarginfiError::MathError)?;

    Ok(output_amount)
}
