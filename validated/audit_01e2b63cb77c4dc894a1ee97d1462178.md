### Title
Defaulted pending withdraw requests keep the upfront fee deduction — waived fees are never credited back to the redeemer - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`requestWithdraw` deducts management and performance fees upfront from the redeemer's receipt (`_underlyings = principal + interest - totalFees`, `pendingWithdrawFees += totalFees`). Those fees are only actually paid to `feeReceiver` inside the successful `stopEpoch` path via `_transferFeeUnderlyings(_pendingWithdrawFees)`. When the borrower defaults, `finalizeDefault` sets `pendingWithdrawFees = 0` and `unclaimedFees = 0` — the fees are waived for everyone — but the pending redeemer's claim basis in `IdleCreditVault` was already recorded net of those fees. On claim, `_claimDefaultedWithdrawRequest` pays `claimBasis * defaultRecoveryPrice / RECOVERY_FULL` on the net-of-fee basis. The deducted fee is therefore never earned by the feeReceiver, never returned to the redeemer, and only serves to shrink `totalBasis` in `finalizeDefaultRecovery`, marginally raising `defaultRecoveryPrice` for other claimants — the exact analog of Symmio's liquidated pending quotes where the fee is taken but the trade never executed.

### Finding Description
In `IdleCDOEpochVariant.requestWithdraw` (contracts/IdleCDOEpochVariant.sol:772-790):

```solidity
(uint256 interest, int256 diff) = _calcInterestWithdrawRequest(_underlyings, _tranche);
uint256 totalFees = _totalWithdrawFees(principal, interest);
_underlyings = principal + interest - totalFees;
pendingWithdrawFees += totalFees;
creditVault.requestWithdraw(_underlyings, msg.sender, principal);
```

The receipt minted to the user in `IdleCreditVault.requestWithdraw` is `_amount = principal + interest - totalFees`. In a healthy epoch, `stopEpoch` pays `_pendingWithdrawFees` to `feeReceiver` (line 419) or mints fee shares via `unclaimedFees += _pendingWithdrawFees` (line 432). But in `finalizeDefault` (lines 194-225), `fee`, `managementFee`, `unclaimedFees` and `pendingWithdrawFees` are all zeroed so "default recovery should not keep accruing fees or leave old fee claims senior to LP recovery". Meanwhile `IdleCreditVault.finalizeDefaultRecovery` computes `pendingBasis = defaultPendingClaimBasis()` from the already-fee-deducted receipt amounts, and `_claimDefaultedWithdrawRequest` pays the haircut on that reduced basis.

Result: for a defaulted epoch, the redeemer is charged a performance fee on interest that was never paid and a management fee that was waived for all other participants, with the deducted amount simply vanishing from every beneficiary's accounting.

### Impact Explanation
Pending redeemers lose `totalFees` (management + performance fee) on top of the default haircut, with no party earning that fee. Quantified: with a 10% performance fee and 1% management fee on a 10,000 USDC request with ~5% epoch interest, roughly 150-200 USDC per redeemer is deducted and then haircut again by `defaultRecoveryPrice`, while `feeReceiver` receives nothing and active LPs only absorb the benefit indirectly through a slightly higher recovery price. This is a direct (redistributed) loss to the pending redeemer for a service never rendered — the same broken invariant as M-1.

### Likelihood Explanation
Triggers deterministically whenever a borrower defaults while normal withdraw requests are pending and fee parameters are non-zero — a common, expected configuration (tests use `fee = 10%`, `managementFee = 1%`). Requires only an unprivileged user with a pending `requestWithdraw` at the epoch where `stopEpoch` defaults; no privileged misbehavior needed. It is arguably semi-intended that upfront management fee compensates for time outside live NAV, but the waived performance-fee component and the absence of any beneficiary make the net effect a genuine leak rather than a defensible fee.

### Recommendation
On default finalization, add the waived `pendingWithdrawFees` back to pending redeemers' claim basis (or into `defaultRecoveryReserve` earmarked pro-rata to pending receipts). Concretely, track the fee portion per pending receipt (e.g., store `pendingWithdrawFees` snapshot before zeroing and gross up `defaultPendingClaimBasis` / the per-epoch claim basis in `IdleCreditVault._withdrawClaimAmountsForEpoch`), so that in the default path the redeemer's basis is `principal + interest` rather than `principal + interest - totalFees`, before applying `defaultRecoveryPrice`.

### Proof of Concept
```solidity
function testDefaultedPendingRedeemerLosesWaivedFees() external {
    uint256 amount = 10_000 * ONE_SCALE;
    _setFeeParams(TL_MULTISIG, 10_000, FULL_ALLOC, cdoEpoch.managementFee()); // 10% perf fee
    _setManagementFee(1_000);                                                // 1% mgmt fee

    _depositWithUser(user, amount, true);

    // Buffer: request withdraw -> receipt is net of upfront fees
    vm.prank(user);
    uint256 receipt = cdoEpoch.requestWithdraw(0, address(AAtranche));
    uint256 feesCharged = cdoEpoch.pendingWithdrawFees();
    assertGt(feesCharged, 0);
    assertEq(IdleCreditVault(address(strategy)).pendingWithdraws(), receipt);

    _startEpochAndCheckPrices(0);

    // Borrower defaults: no repayment at epoch end
    deal(defaultUnderlying, borrower, 0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    _checkDefault();

    // Finalize at e.g. 70% recovery
    uint256 totalBasis =
        cdoEpoch.getContractValue() + cdoEpoch.expectedEpochInterest()
        - cdoEpoch.pendingWithdrawFees()
        + IdleCreditVault(address(strategy)).defaultPendingClaimBasis();
    uint256 recovered = totalBasis * 7e17 / 1e18;
    deal(defaultUnderlying, manager, recovered);
    vm.startPrank(manager);
    IERC20Detailed(defaultUnderlying).approve(address(strategy), recovered);
    cdoEpoch.finalizeDefault(recovered, manager);
    vm.stopPrank();

    // feeReceiver earned nothing (fees waived), yet the redeemer's basis stayed net-of-fee
    assertEq(IERC20Detailed(defaultUnderlying).balanceOf(TL_MULTISIG), 0);

    uint256 balPre = IERC20Detailed(defaultUnderlying).balanceOf(user);
    vm.prank(user);
    cdoEpoch.claimWithdrawRequest();
    uint256 paid = IERC20Detailed(defaultUnderlying).balanceOf(user) - balPre;

    // User is haircut on the net-of-fee receipt; the feesCharged portion is lost to everyone
    assertApproxEqAbs(paid, receipt * 7e17 / 1e18, 5);
    // Broken invariant: paid < (receipt + feesCharged) * recoveryPrice — fee neither earned nor returned
}
```
