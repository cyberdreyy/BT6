### Title
Unbounded recursion in `TrieNode::decode`/`open`/`unblind` allows stack-exhaustion DoS of the fault-proof program via attacker-controlled trie preimages - ([File: crates/proof/mpt/src/node.rs])

### Summary
`base-proof-mpt`'s `TrieNode` implements RLP decoding, `open()`, and `unblind()` as unbounded, self-referential recursive functions with no depth limit, analogous to the unbounded-recursion bug in tcpdump's `bgp_attr_print()` (CVE-2018-16300). Because trie-node bytes fed into `TrieNode::decode` originate from the preimage oracle — data that a dispute-game participant supplies/attests to during fault-proof execution — a crafted, deeply nested chain of RLP `Extension` nodes (or a correspondingly deep on-disk/oracle-backed trie) can drive `TrieNode::decode`/`TrieNode::open`/`TrieNode::unblind` into thousands of recursive stack frames, exhausting the call stack of the fault-proof program.

### Finding Description
`TrieNode` is documented as "a recursive, in-memory implementation of Ethereum's hexary Merkle Patricia Trie" [1](#0-0) . Its `Decodable` implementation recurses without any depth bound: for `Extension` nodes it calls `Self::decode(buf)` recursively via `try_decode_leaf_or_extension_payload`, and for `Branch` nodes it recurses through `Vec::<Self>::decode(buf)`: [2](#0-1) [3](#0-2) 

There is no `depth` parameter or maximum-nesting check anywhere in this decode path (unlike, for example, the CBOR parser elsewhere in the codebase which explicitly enforces `MAX_CBOR_NESTING_DEPTH` [4](#0-3) ). The same unbounded pattern exists in the traversal helpers `TrieNode::open` and `TrieNode::unblind`, which recurse once per trie level and additionally re-enter the fetcher (`TrieProvider::trie_node_by_hash`) to unblind/decode the next level: [5](#0-4) 

This decode routine is reached directly from the oracle-backed `TrieProvider` implementations used inside the fault-proof program (kona/op-program-style client) for both L1 and L2 chain data: [6](#0-5) [7](#0-6) 

The oracle-backed preimages are fetched via `PreimageFetcher` from a preimage key/value store that is populated by whichever party is running/serving the dispute-game challenger/host role, and the client only "assumes" a hint was already sent for that hash — the content of the preimage itself is not otherwise structurally validated before being handed to `TrieNode::decode`. This means the bytes driving the recursive decode are attacker-influenced within the trust model of a dispute-game participant supplying preimages for their own claimed state.

### Impact Explanation
A stack overflow inside the fault-proof program is not a benign crash: `TrieNode`/`TrieProvider` (via `TrieDB`, `base-proof-executor`, `OracleL1ChainProvider`, `OracleL2ChainProvider`) are the data-access layer used by the stateless L2 block executor and derivation pipeline that computes the claimed/attested output root inside the fault-proof VM (`crates/proof/executor`, `crates/proof/proof`). If a party can force the program to crash (stack exhaustion → process abort/signal) while it is computing an output root during dispute resolution, this can prevent the fault-proof program from producing a correct provable output root, effectively denying a legitimate party's ability to prove their claim (or halting the fault-proof execution outright) in the dispute game path — this maps to the "wrong provable output root" / "node halt" outcomes.

### Likelihood Explanation
Likelihood is moderate: exploitation requires that a party supplying preimage data (a role reachable by fault-proof/dispute-game participants providing account/storage/trie proofs) can shape trie node bytes such that the decode/traversal recurses deeply — e.g., a long chain of RLP `Extension` nodes stacked via `Self::decode` recursion in `try_decode_leaf_or_extension_payload`, each level consuming only a handful of RLP header bytes. Whether this is fully practical depends on preimage-size limits enforced elsewhere in the preimage server/oracle transport (`crates/proof/preimage/src/traits.rs`, `crates/proof/host/src/recording.rs`, `crates/proof/host/src/service.rs`) — I found references to size-related checks in these files but could not fully verify the exact maximum preimage size or whether it is sufficient to permit stack-exhausting recursion depth; this is a limitation of the available index and would need direct inspection of those files (and the runtime stack size of the fault-proof program, e.g., under a MIPS/RISC-V VM if applicable) to conclusively bound feasibility.

### Recommendation
Add an explicit recursion/nesting depth counter (mirroring the `MAX_CBOR_NESTING_DEPTH` pattern already used elsewhere in this repo, see `crates/proof/tee/registrar/src/cbor.rs`) to `TrieNode::decode`, `TrieNode::open`, and `TrieNode::unblind`, bounding recursion to the maximum possible MPT depth (64 nibbles for a 32-byte key, i.e., well under 100 levels), and reject/error out on any input that would exceed it before continuing to recurse.

### Proof of Concept
Not independently confirmed against a running fault-proof program due to tool limitations (no code execution available). Conceptually: encode an RLP `Extension` node whose child is itself an `Extension` node, repeated N times, each level minimal (a few bytes), then feed the resulting bytes as the preimage for a `TrieNode::decode` call reached via `OracleL1ChainProvider::trie_node_by_hash` / `OracleL2ChainProvider::trie_node_by_hash`. For sufficiently large N (bounded only by preimage size limits not fully verified above), this recursively calls `Self::decode` at `crates/proof/mpt/src/node.rs:456` until the native stack is exhausted.

# `base-proof-mpt`

A recursive, in-memory implementation of Ethereum's hexary Merkle Patricia Trie (MPT).

## Overview

Implements Ethereum's Merkle Patricia Trie with support for retrieval, insertion, deletion, and
root computation via RLP-encoded trie node encoding. Starting from a trie root hash, `TrieNode`

    /// Unblinds the [`TrieNode`] if it is a [`TrieNode::Blinded`] node.
    pub fn unblind<F: TrieProvider>(&mut self, fetcher: &F) -> TrieNodeResult<()> {
        if let Self::Blinded { commitment } = self {
            if *commitment == EMPTY_ROOT_HASH {
                // If the commitment is the empty root hash, the node is empty, and we don't need to
                // reach out to the fetcher.
                *self = Self::Empty;
            } else {
                *self = fetcher
                    .trie_node_by_hash(*commitment)
                    .map_err(|e| TrieNodeError::Provider(e.to_string()))?;
            }
        }
        Ok(())
    }

    /// Walks down the trie to a leaf value with the given key, if it exists. Preimages for blinded
    /// nodes along the path are fetched using the `fetcher` function, and persisted in the inner
    /// [`TrieNode`] elements.
    ///
    /// ## Takes
    /// - `self` - The root trie node
    /// - `path` - The nibbles representation of the path to the leaf node
    /// - `fetcher` - The preimage fetcher for intermediate blinded nodes
    ///
    /// ## Returns
    /// - `Err(_)` - Could not retrieve the node with the given key from the trie.
    /// - `Ok(None)` - The node with the given key does not exist in the trie.
    /// - `Ok(Some(_))` - The value of the node
    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
