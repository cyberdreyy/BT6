### Title
Stale `reject_reason` forces re-evaluation of an already-signed block, wiping its own-signature bookkeeping and defeating the equivocation guard - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`BlockInfo::reject_reason` is never cleared by any of the state-transition helpers (`mark_pre_committed`, `mark_locally_accepted`, `mark_globally_accepted`, `mark_locally_rejected`), so a reason recorded while a block was in an earlier `LocallyRejected` state survives into later states such as `LocallyAccepted`. `should_reevaluate_reject_reason` treats several reasons (`ConnectivityIssues`, `NoSortitionView`, `ConsensusHashMismatch`, `NoSignerConsensus`, `ValidationFailed(UnknownParent/NotFoundError)`, `NotRejected`, `Unknown`, `TestingDirective`, `InvalidTenureExtend`) as always re-evaluable, and `should_reevaluate_block` consults only that flag (plus a special case for `PreCommitted`) — it does not check whether the block has already reached `LocallyAccepted`/`GloballyAccepted`. When a miner (or gossip) re-sends the identical proposal after the signer has already signed it, `handle_block_proposal` re-derives a brand-new `BlockInfo::from(block_proposal.clone())` — resetting `state`, `signed_self`, `signed_group`, and `valid` to their defaults — and persists it via `insert_block`, overwriting the row that previously recorded this signer's own signature over the block.

### Finding Description
- `BlockInfo` carries `reject_reason: Option<RejectReason>` alongside `state`, `signed_self`, `signed_group`. [1](#0-0) 
- None of the mark_* transition helpers clear `reject_reason`: [2](#0-1) 
- `should_reevaluate_reject_reason` unconditionally marks a whitelist of reasons as re-evaluable: [3](#0-2) 
- `should_reevaluate_block` branches only on `globally_approved_and_responded()` (true only for `GloballyAccepted`) and on `state == PreCommitted`; any other state (in particular `LocallyAccepted`, which already carries our own signature) falls straight into the reject-reason check, and if `should_reevaluate_reject_reason` is true it returns `true` (“should reevaluate”) without ever inspecting `signed_self`: [4](#0-3) 
- Once `should_reevaluate_block` returns `true`, `handle_block_proposal` treats the re-proposal like a brand-new block: it builds a fresh `BlockInfo::from(block_proposal.clone())` (state=`Unprocessed`, `signed_self=None`, `reject_reason=None`, `valid=None`) and unconditionally re-inserts it into the DB, clobbering the row that recorded this signer’s prior signature: [5](#0-4) [6](#0-5) 

This matters because the signer’s *only* protection against signing two conflicting blocks at the same height is a local-DB lookup, `get_signed_conflicts`, which finds prior signed blocks purely from the persisted `signed_self`/`signed_group` columns of the `blocks` table (used in the pre-commit threshold path documented in `docs/signer-flows.md` section 5, anchored at `get_signed_conflicts`, `conflict_still_blocks`). [7](#0-6)  If block A’s row is overwritten to a fresh `Unprocessed`/`signed_self=None` record because a stale, re-evaluable `reject_reason` survived from an earlier phase of A’s own lifecycle, the signer’s local memory of “I already signed A at height h” disappears. A conflicting sibling block B proposed later at the same height (by the same or a different tenure) will then pass the `get_signed_conflicts` check that would otherwise have refused to sign it, breaking the equivocation guard that `conflict_still_blocks`/`get_signed_conflicts` exist to enforce.

A concrete path to reach this state: block A is initially rejected with a transient, re-evaluable reason (e.g. `ConnectivityIssues`, or `ValidationFailed(NotFoundError)`, as already exercised in `signer_reevaluates_proposal_with_missing_burn_view`), then a later re-proposal of A is validated OK and crosses the pre-commit threshold, advancing it to `LocallyAccepted` via `mark_pre_committed`→`mark_locally_accepted` — neither of which clears `reject_reason`. The `blocks` row for A therefore now has `state=LocallyAccepted, signed_self=Some(t), reject_reason=Some(ConnectivityIssues)`. Any further identical re-proposal of A (the miner’s standard timeout re-send behavior, exercised in the existing “miner re-submits after a signature timeout” test) triggers `should_reevaluate_block` → true → full DB overwrite → A’s row reverts to `Unprocessed`/`signed_self=None`, silently discarding the signer’s own record of having signed A.

### Impact Explanation
This is a Critical-class break: it removes the signer-local safety net that prevents equivocation (signing two conflicting blocks at the same height). A single miner controlling one block-production slot, by simply re-sending a previously-transiently-rejected-then-accepted proposal (ordinary re-proposal/timeout behavior already exercised by this codebase's own miner logic and tests), can cause an honest signer to lose its own bookkeeping of an already-signed block and then sign a conflicting sibling, matching the rules’ definition of “a signer signing … a conflicting block.”

### Likelihood Explanation
The trigger requires only:
1. A block that is first rejected for a reason on the re-evaluable list (several of these — `ConnectivityIssues`, `NoSortitionView`, `ValidationFailed(NotFoundError/UnknownParent)` — are ordinary transient conditions during normal chain-tip catch-up, not attacker-crafted), and
2. A later re-proposal of the *same* block content that gets validated OK and locally accepted, and
3. One more identical re-proposal reaching the signer afterward — which the miner’s own retry/resend logic performs on ordinary timeouts.

No majority collusion, no other signer’s key, and no auth token are needed; a single miner (plus normal network re-delivery) can arrange the sequence. This is entirely reachable via the documented, in-scope `handle_block_proposal`/`should_reevaluate_block` code path.

### Recommendation
Clear (or otherwise disqualify) `reject_reason` whenever a block’s state advances past `LocallyRejected`, and make `should_reevaluate_block` never trigger a full `BlockInfo` overwrite once `signed_self`/`signed_group` is already set — i.e., gate the "re-evaluable reject reason" branch on `state == LocallyRejected` (or `Unprocessed`), not merely on the presence of a stale `reject_reason` value. Equivalently, when handling a proposal for a block already at `LocallyAccepted`/`PreCommitted`/`GloballyAccepted`, always fall back to `determine_response`/re-run the pre-commit path rather than reconstructing a fresh `BlockInfo`.

### Proof of Concept
1. Miner proposes block A at height h. Node validation transiently fails with a re-evaluable reason (e.g., `ValidationFailed(NotFoundError)` because the local burn view lags) → `handle_block_validate_reject` calls `mark_locally_rejected()`, and `block_info.reject_reason = Some(ValidationFailed(NotFoundError))` is stored (state=`LocallyRejected`).
2. Miner re-sends the identical proposal for A after its burn view catches up. `should_reevaluate_block` sees `reject_reason` is re-evaluable → returns true → fresh validation succeeds → `mark_pre_committed` → pre-commit threshold reached → `mark_locally_accepted` → state=`LocallyAccepted`, `signed_self=Some(t)`. Note: `reject_reason` is still `Some(ValidationFailed(NotFoundError))` in the persisted row, since none of the mark_* helpers clear it.
3. Miner (or a delayed StackerDB replica) re-delivers the exact same `BlockProposal` for A once more (ordinary timeout-retry behavior). `handle_block_proposal` looks up A, calls `should_reevaluate_block`: `globally_approved_and_responded()` is false (only `LocallyAccepted`, not yet `GloballyAccepted`); `should_reevaluate_reject_reason` is true because `reject_reason` is still the stale `ValidationFailed(NotFoundError)`; the branch that checks `PreCommitted`/`determine_response` is skipped entirely → function returns `true`.
4. `handle_block_proposal` builds `let mut block_info = BlockInfo::from(block_proposal.clone())` (state=`Unprocessed`, `signed_self=None`) and calls `self.signer_db.insert_block(&block_info)`, overwriting A’s row and erasing the record that this signer already signed A.
5. Miner now proposes conflicting sibling block B at height h (e.g., a different tenure-start block). When B reaches the pre-commit threshold, `handle_block_pre_commit`’s conflict check calls `get_signed_conflicts(h, hash_B)`, which no longer finds A (its `signed_self` column was wiped in step 4) — the guard that should have refused to sign B is bypassed, and the signer signs B, producing two independently signable conflicting blocks at the same height.

Confidence note: I was unable to execute the code or inspect every call site that sets `reject_reason` (the search only confirmed the field’s definition, the mark_* helpers, and `should_reevaluate_reject_reason`/`should_reevaluate_block`, not every write site), so the exact wording of intermediate rejection reasons that reach `LocallyRejected` before acceptance is inferred from the whitelist and the existing `signer_reevaluates_proposal_with_missing_burn_view` test rather than a full trace of every producer of `reject_reason`. The core defect — that state-transition helpers never clear `reject_reason` and that `should_reevaluate_block` does not check `signed_self`/`state` before triggering a full `BlockInfo` overwrite — is directly confirmed in the cited code.

    fn should_reevaluate_block(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &BlockInfo,
        block_proposal: &BlockProposal,
    ) -> bool {
        let signer_signature_hash = block_info.block.header.signer_signature_hash();
        if block_info.globally_approved_and_responded() {
            info!("{self}: received a block proposal for a globally accepted block to which we have already responded. Ignoring.";
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_info.block.block_id(),
                "block_height" => block_info.block.header.chain_length,
                "burn_height" => block_proposal.burn_height,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "timestamp" => block_info.block.header.timestamp,
                "signed_group" => block_info.signed_group,
                "signed_self" => block_info.signed_self,
                "valid" => ?block_info.valid
            );
            return false;
        }
        if !should_reevaluate_reject_reason(block_info) {
            if block_info.state == BlockState::PreCommitted {
                // We validated this block but haven't signed it. Signing requires the
                // pre-commit threshold and the conflict checks in `handle_block_pre_commit`.
                // Re-broadcast our pre-commit and re-run that evaluation instead of
                // responding with a signature directly, so a re-proposed block can't
                // bypass those checks.
                info!(
                    "{self}: received a block proposal for a block we have pre-committed to but not signed. Re-evaluating the pre-commit.";
                    "signer_signature_hash" => %signer_signature_hash,
                    "block_id" => %block_info.block.block_id(),
                    "block_height" => block_info.block.header.chain_length,
                    "burn_height" => block_proposal.burn_height,
                    "consensus_hash" => %block_info.block.header.consensus_hash
                );
                self.send_block_pre_commit(signer_signature_hash.clone());
                let address = self.stacks_address.clone();
                self.handle_block_pre_commit(
                    stacks_client,
                    sortition_state,
                    &address,
                    &signer_signature_hash,
                );
                return false;
            }
            if let Some(block_response) = self.determine_response(block_info) {
                self.send_block_response(&block_info.block, block_response);
                return false;
            } else {
                let is_pending = self
                    .signer_db
                    .has_pending_block_validation(&signer_signature_hash)
                    .unwrap_or_else(|e| {
                        warn!("{self}: Failed to load pending block validations: {e:?}");
                        false
                    });
                if is_pending {
                    debug!(
                        "{self}: received a block proposal for a block for which we is already pending validation. Do nothing.";
                        "signer_signature_hash" => %block_info.block.header.signer_signature_hash(),
                        "block_id" => %block_info.block.block_id()
                    );
                    return false;
                } else {
                    info!(
                        "{self}: received a block proposal for this block before, but we do not have a pending validation for it.";
                        "reject_reason" => ?block_info.reject_reason,
                        "signer_signature_hash" => %signer_signature_hash,
                        "block_id" => %block_info.block.block_id(),
                        "block_height" => block_info.block.header.chain_length,
                        "burn_height" => block_proposal.burn_height,
                        "consensus_hash" => %block_info.block.header.consensus_hash
                    );
                }
            }
        } else {
            info!(
                "{self}: received a block proposal for this block before, but our rejection reason allows us to reconsider";
                "reject_reason" => ?block_info.reject_reason,
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_proposal.block.block_id(),
                "block_height" => block_proposal.block.header.chain_length,
                "burn_height" => block_proposal.burn_height,
                "consensus_hash" => %block_proposal.block.header.consensus_hash
            );
        }
        true
    }

fn should_reevaluate_reject_reason(block_info: &BlockInfo) -> bool {
    if let Some(reject_reason) = &block_info.reject_reason {
        match reject_reason {
            RejectReason::ValidationFailed(ValidateRejectCode::UnknownParent)
            | RejectReason::ValidationFailed(ValidateRejectCode::NotFoundError)
            | RejectReason::NoSortitionView
            | RejectReason::ConnectivityIssues(_)
            | RejectReason::TestingDirective
            | RejectReason::InvalidTenureExtend
            | RejectReason::ConsensusHashMismatch { .. }
            | RejectReason::NoSignerConsensus
            | RejectReason::NotRejected
            | RejectReason::Unknown(_) => true,
            RejectReason::ValidationFailed(_)
            | RejectReason::RejectedInPriorRound
            | RejectReason::SortitionViewMismatch
            | RejectReason::ReorgNotAllowed
            | RejectReason::InvalidBitvec
            | RejectReason::PubkeyHashMismatch
            | RejectReason::InvalidMiner
            | RejectReason::NotLatestSortitionWinner
            | RejectReason::InvalidParentBlock
            | RejectReason::DuplicateBlockFound
            | RejectReason::IrrecoverablePubkeyHash
            | RejectReason::ProblematicTransactions
            | RejectReason::ProposalTooOld => {
                // No need to re-validate these types of rejections.
                false
            }
        }
    } else {
        false
    }
}
