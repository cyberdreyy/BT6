### Title
Stale confirmations from deleted multisig members allow `execute_request` to fire below `num_confirmations` live members, enabling `AddKey`-based full-access-key takeover - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges requests whose *original creator* (`MultiSigRequestWithSigner::member`) equals the member being removed; it never scans other requests' `confirmations: HashSet<String>` entries to strip a stale confirmation left by a member who confirmed (but did not create) that request. `confirm()` then counts `confirmations.len() as u32 + 1 >= self.num_confirmations` using this contaminated set, so a request such as `AddKey{public_key: attacker_pk, permission: None}` on `receiver_id = current_account_id()` can execute and schedule `promise.add_full_access_key(attacker_pk)` with strictly fewer live, distinct confirming members than `num_confirmations`.

### Finding Description
The binding that must hold is:

`live distinct self.members that confirmed R` == `num_confirmations` at the moment `execute_request` runs and schedules `add_full_access_key`.

Trace:
1. `add_request` records `MultiSigRequestWithSigner { member: current_member, .. }` — only the *creator* of R. [1](#0-0) 
2. `confirm` inserts the confirming member's string into `confirmations: HashSet<String>` for that `request_id`, unconditionally, with no re-validation later against current membership: `confirmations.len() as u32 + 1 >= self.num_confirmations` then either executes or stores the confirmation. [2](#0-1) 
3. `delete_member` only removes requests whose *original signer* (`r.member == member`) equals the member being deleted, and clears confirmations only for those requests. It never inspects or scrubs the deleted member's entry from `confirmations` sets belonging to *other* requests where that member had confirmed but was not the creator. [3](#0-2) 
4. `execute_request`'s `AddKey` branch with `permission: None` calls `promise.add_full_access_key(public_key.into())` directly on `receiver_id`, gated only by `assert_self_request` (receiver_id == current_account_id()), not by any re-check of confirmer liveness. [4](#0-3) 

Exploit flow (N=4 members M1..M4, `num_confirmations`=3):
- M1 creates and self-confirms request R = `AddKey{public_key: attacker_pk, permission: None}` on `receiver_id = current_account_id()` → `confirmations = {M1}`.
- M2 confirms R → `confirmations = {M1, M2}` (2 < 3, stored, not yet executed).
- Separately, a `DeleteMember{member: M2}` request is created and confirmed to threshold by other live members; `delete_member` checks `members.len() - 1 >= num_confirmations` (4-1=3≥3 passes) and removes M2 from `self.members`, but since R's creator (`member` field) is M1, not M2, `delete_member`'s request-filtering loop (`r.member == member`) does not touch R, and R's stale `"M2"` entry remains inside `confirmations`.
- M3 (still live) confirms R: `confirmations.len() as u32 + 1` = `2 + 1 = 3 >= num_confirmations (3)` → `execute_request` runs, scheduling `promise.add_full_access_key(attacker_pk)`, even though only M1 and M3 are currently live members who confirmed — one fewer than `num_confirmations` requires.
- `attacker_pk` becomes a full-access key on the multisig account, entirely bypassing further `confirm()`/`execute_request()` gating, and can subsequently transfer NEAR or delete other keys directly.

No existing guard prevents this: `assert_valid_request` only checks that the *current caller* is presently a member and that the request/confirmations exist — it never revalidates the *stored* confirmations set against current membership. `current_member()` is only invoked for the calling party in the current transaction, not retroactively for already-recorded confirmers.

### Impact Explanation
This allows a request to execute — including granting a full-access key to an attacker-controlled `attacker_pk` on the multisig account itself — with fewer live confirming members than `num_confirmations`. Once the full-access key is added, the attacker fully controls the multisig account and can transfer all NEAR out or delete legitimate keys, bypassing `confirm`/`execute_request` altogether. This matches the Critical category: "a multisig request executed below `num_confirmations` live members," resulting in complete loss of custody of the account's NEAR.

### Likelihood Explanation
This requires normal, expected multisig operations rather than any privileged action by the attacker: any member confirms a pending request, is later legitimately removed as a member (member rotation is a routine multisig lifecycle event), and the removal doesn't retroactively invalidate their stale confirmation on unrelated pending requests. No attacker privilege beyond being able to observe on-chain state and time their final confirming transaction (which could be done by any of the still-live members, potentially colluding with or being the attacker who proposed the `AddKey` request) is needed. The bug is deterministic given this ordinary sequence and is repeatable across any multisig deployment using this contract and any member-deletion event that follows a partial confirmation.

### Recommendation
When a member is deleted (`delete_member`), iterate all active `requests`/`confirmations` (not just those created by the deleted member) and remove the deleted member's string from every `confirmations` `HashSet`, decrementing effectively. Alternatively, at `confirm()` time, revalidate that every entry in the stored `confirmations` set still corresponds to a member in `self.members` before counting toward `num_confirmations` (filter stale entries lazily on read).

// multisig2/src/lib.rs tests module (cargo test)
#[test]
fn test_stale_confirmation_after_member_deletion_bypasses_threshold() {
    // Setup: 4 members M1..M4 (as AccessKey members), num_confirmations = 3
    let members = vec![
        MultisigMember::AccessKey { public_key: pk("M1...") },
        MultisigMember::AccessKey { public_key: pk("M2...") },
        MultisigMember::AccessKey { public_key: pk("M3...") },
        MultisigMember::AccessKey { public_key: pk("M4...") },
    ];
    testing_env!(context_with_key(pk("M1..."), amount));
    let mut c = MultiSigContract::new(members.clone(), 3);

    // 1. M1 creates & self-confirms AddKey(attacker_pk) request on current_account_id()
    let attacker_pk = pk("ATTACKER...");
    let request = MultiSigRequest {
        receiver_id: alice(), // == current_account_id()
        actions: vec![MultiSigRequestAction::AddKey {
            public_key: attacker_pk.clone(),
            permission: None,
        }],
    };
    let request_id = c.add_request_and_confirm(request.clone()); // confirmations = {M1}

    // 2. M2 confirms (2 < 3, stored not executed)
    testing_env!(context_with_key(pk("M2..."), amount));
    c.confirm(request_id);
    assert_eq!(c.confirmations.get(&request_id).unwrap().len(), 2);

    // 3. Delete M2 via separate DeleteMember request confirmed to threshold by M3/M4/M1
    // (members.len()-1 = 3 >= num_confirmations = 3, so deletion succeeds)
    // ... perform DeleteMember{member: M2} through add_request_and_confirm + confirms by M3, M4 ...
    // after this, self.members no longer contains M2, but R's confirmations set still has "M2" stale.

    // 4. M3 (still live) confirms R -> triggers execution
    testing_env!(context_with_key(pk("M3..."), amount));
    let result = c.confirm(request_id);

    // ASSERT BINDING VIOLATION:
    // Live distinct confirmers of R at execution time = {M1, M3} = 2
    // but num_confirmations = 3, yet request executed (promise scheduled)
    // i.e. confirmations.len() as u32 + 1 >= num_confirmations was satisfied using a stale M2 entry
    assert_eq!(c.requests.len(), 0); // request executed/removed
    // Follow-up: switch to attacker_pk context and prove full-access-key control,
    // e.g. attacker calls DeleteMember or a raw promise.transfer via a subsequent
    // testing_env!(context_with_key(attacker_pk, amount)) call succeeding despite
    // attacker_pk never being an added MultisigMember.
}

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
