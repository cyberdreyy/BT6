### Title
Unauthenticated MessageId collision in savedCallbacks causes cross-user response delivery - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`(*handler).HandleLegacyUserMessage` stores each user's `Callback` in `h.savedCallbacks` keyed only by the attacker/user-supplied `msg.Body.MessageId`, with no per-sender scoping and no check for an existing in-flight entry. Any signed client can choose an arbitrary `MessageId`, so a second request using the same ID silently overwrites the first user's saved callback, and the eventual DON response is delivered to the second (attacker's) callback instead of the original sender's.

### Finding Description
`HandleLegacyUserMessage` validates payload structure/timestamp/method but performs no uniqueness check on `msg.Body.MessageId` before storing the callback: [1](#0-0) 

The key used is exactly the client-controlled `msg.Body.MessageId` field from `api.MessageBody`, which is not derived from or bound to the sender's signed identity: [2](#0-1) 

`Validate()` only checks `MessageId` length/null-suffix — it does not enforce global uniqueness or tie the ID to `Sender`: [3](#0-2) 

When the DON eventually responds, `HandleNodeMessage` validates that the responding node's address matches `msg.Body.Sender` on the *response* (node-side sender), but this only authenticates that the response came from a legitimate DON node — it says nothing about which *user* originally issued the request tied to that `MessageId`: [4](#0-3) 

`handleWebAPITriggerMessage` then looks up and deletes the callback purely by `MessageId` and delivers the response to whatever callback is currently stored there: [5](#0-4) 

Exploit flow: victim sends `msg_A{MessageId:"X"}` via a signed `api.Message` — the gateway's `ProcessRequest` creates a fresh `Callback` per request and calls `HandleLegacyUserMessage`, storing it under key `"X"`: [6](#0-5) 
Before the DON responds, an attacker (any holder of a valid keypair, no role/session needed) sends `msg_B{MessageId:"X"}` signed with their own key. Because the store operation is an unconditioned map write, `h.savedCallbacks["X"]` is overwritten with the attacker's callback, silently discarding the victim's callback reference (though the victim's own `callback.Wait(ctx)` in `gateway.ProcessRequest` will simply time out, since nothing signals it). When the DON later responds to `MessageId "X"` (in response to the victim's forwarded request, since the node addresses/payload it was given came from `msg_A`), `handleWebAPITriggerMessage` finds the attacker's callback under key `"X"` and delivers the victim's response payload to the attacker.

The existing test suite exercises `savedCallbacks` correctness only for validation error paths and pruning eviction, not for MessageId collision: [7](#0-6) 

### Impact Explanation
This is a cross-user response/information disclosure: an unprivileged, arbitrary gateway client can hijack another user's in-flight web API trigger response (which may contain trigger event data intended only for the victim's workflow) by simply guessing or brute-forcing a colliding `MessageId` within the request's lifetime window. This matches the "cross-user response confusion" / unauthorized access to another user's request result impact class.

### Likelihood Explanation
Exploitability requires only a valid ECDSA keypair to sign an `api.Message` — no role, session, allowlist entry, or prior relationship with the victim is required (allowlisting/rate-limiting is explicitly noted as a TODO in the handler: `// TODO: apply allowlist and rate-limiting here`). `MessageId` is entirely attacker-chosen and unauthenticated with respect to uniqueness; the race window is the round-trip time between gateway forwarding the request to DON nodes and the DON's response — realistically hundreds of milliseconds to seconds, which is enough for a targeted attacker who can predict or observe (e.g., via timing, application behavior, or ID reuse patterns) a victim's `MessageId`. Note that if `MessageId` values are truly random/high-entropy strings chosen by well-behaved clients, blind collision is impractical; but the code provides no defense-in-depth if IDs are ever predictable, sequential, or attacker-influenced (e.g., client bugs, replay, or a victim client using low-entropy IDs), and there is no compensating control (such as sender-bound keys) at this layer.

### Recommendation
Scope `savedCallbacks` keys by `(Sender, MessageId)` tuple rather than `MessageId` alone, and reject/error on `HandleLegacyUserMessage` if an entry already exists for that key instead of silently overwriting it. Apply the analogous fix in `dummyHandler.HandleLegacyUserMessage` (`core/services/gateway/handlers/handler.dummy.go`), which has the identical unconditioned-overwrite pattern.

### Proof of Concept
1. In `core/services/gateway/handlers/capabilities/handler_test.go`, add a test using `setupHandler(t)`.
2. Create `msgA := triggerRequest(t, victimKey, ...)` with `Body.MessageId = "X"` and `cbA := hc.NewCallback()`; call `handler.HandleLegacyUserMessage(ctx, msgA, cbA)`.
3. Create `msgB := triggerRequest(t, attackerKey, ...)` also with `Body.MessageId = "X"` and `cbB := hc.NewCallback()`; call `handler.HandleLegacyUserMessage(ctx, msgB, cbB)`.
4. Assert `handler.savedCallbacks["X"].Callback == cbB` (overwritten), proving `cbA` was discarded.
5. Simulate the DON responding to the victim's original forwarded request (constructed from `msgA`'s content but for `MessageId "X"`) via `handler.HandleNodeMessage(ctx, resp, nodes[0].Address)`.
6. Assert `cbB.Wait(ctx)` returns the response payload (attacker receives victim's data) while `cbA.Wait(ctx)` times out/never resolves — confirming cross-user response delivery.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
