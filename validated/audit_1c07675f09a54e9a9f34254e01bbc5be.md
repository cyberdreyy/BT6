### Title
Zip extraction (`ExtractZipArchive`/`extractZipFile`) writes and chmods files at attacker-controlled absolute paths with no destination-root confinement - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipFile` in `helpers/archives/zip_extract.go` extracts each `zip.File` using `file.Name` directly, with no check that the resulting path stays within the extraction destination. Unlike the sibling `tarzstd` extractor, which validates every path with `filepath.Abs` + `strings.HasPrefix(path, e.dir+separator)` before writing, the zip extractor performs no such containment check, so a cache/artifact zip with an absolute or drive-qualified `file.Name` (e.g. `C:\Windows\Temp\poc.txt`) is written and chmod'd (via `lchmod` on Windows) outside the job workspace.

### Finding Description
`ExtractZipFile` (`helpers/archives/zip_extract.go:112-119`) opens a zip and calls `ExtractZipArchive`, which iterates `archive.File` and calls `extractZipFile(file)` for each entry [1](#0-0) . `extractZipFile` does:

```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
``` [2](#0-1) 

`file.Name` comes straight from the zip's central directory entry — fully attacker-controlled content of a job's cache or artifact archive — and is never validated against, or joined relative to, a destination directory. There is no `filepath.Abs`/`filepath.Rel`/prefix check comparable to what `tarzstd_extractor.go` does (`path, err := filepath.Abs(filepath.Join(e.dir, hdr.Name)); if !strings.HasPrefix(path, e.dir+separator) ... return error`) [3](#0-2) . The only content-based guard present, `errorIfGitDirectory`, only warns about paths inside `.git/` and is not a containment check [4](#0-3) .

After all files are written, `ExtractZipArchive` calls `lchmod(file.Name, file.Mode())` for every entry [5](#0-4) . On Windows this resolves to:
```go
func lchmod(name string, mode os.FileMode) error {
	if mode&os.ModeSymlink != 0 { return nil }
	return os.Chmod(name, mode.Perm())
}
``` [6](#0-5) 
Since `name` is the same unvalidated `file.Name`, the chmod is applied wherever the file was actually written — which can be outside the job root if `file.Name` was absolute.

Because `os.OpenFile`/`os.MkdirAll`/`os.Chmod` on Windows accept absolute paths (`C:\...`), drive-relative paths, and UNC paths, a zip entry with such a name causes writes/chmods anywhere the runner/helper process has filesystem permissions — not confined to the extraction working directory.

### Impact Explanation
An unprivileged job that supplies a crafted cache or artifact zip (cache download/extraction and artifact download/extraction both funnel through `ExtractZipFile`, e.g. via `commands/helpers/cache_extractor.go` and `functions/concrete/run/stages/cache_extract.go`) can cause the runner/helper process on a Windows host to write and set permissions on a file at an absolute path outside the job workspace. Depending on the runner/helper process's privileges and the chosen target path, this can lead to file overwrite outside the job root and potentially code execution on the runner host (e.g. dropping a file into a location that gets executed by other automation, or corrupting a file another tenant/job relies on) — matching the scoped "workspace confinement" violation.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged job's control: the job only needs to produce/control a cache or artifact zip archive that the runner or helper will later extract via `ExtractZipFile`. Crafting a zip entry with an absolute Windows path as its `Name` field is straightforward with the standard `archive/zip` writer (no validation is performed by the archive creation side either, and even if it were, an attacker can hand-craft the zip bytes directly). This is a deterministic, repeatable bug — every extraction of such an entry writes to the attacker-chosen path.

### Recommendation
Add destination-root confinement in `extractZipFile`/`ExtractZipArchive`, mirroring `tarzstd_extractor.go`: resolve each `file.Name` against the intended destination directory with `filepath.Join(destDir, file.Name)`, take `filepath.Abs`, and reject (or skip with a warning, consistent with `pathErrorTracker` usage) any entry whose resolved path does not have `destDir+separator` as a prefix (and is not equal to `destDir`). Apply the same resolved, validated path to the later `lchmod`/`processZipExtra` calls instead of raw `file.Name`.

### Proof of Concept
```go
// helpers/archives/zip_extract_test.go
func TestExtractZipFile_RejectsAbsolutePath(t *testing.T) {
    tempFile, err := os.CreateTemp("", "archive")
    require.NoError(t, err)
    defer os.Remove(tempFile.Name())

    w := zip.NewWriter(tempFile)
    // Absolute path outside any intended extraction root.
    evilPath := filepath.Join(os.TempDir(), "gitlab-runner-zip-poc", "poc.txt")
    f, err := w.Create(evilPath)
    require.NoError(t, err)
    _, _ = io.WriteString(f, "poc")
    require.NoError(t, w.Close())
    tempFile.Close()

    err = ExtractZipFile(tempFile.Name())

    // Expect extraction to fail / refuse to write outside destination,
    // and the file must NOT exist at the absolute target.
    _, statErr := os.Stat(evilPath)
    assert.True(t, os.IsNotExist(statErr), "file must not be written outside destination root")
    defer os.RemoveAll(filepath.Dir(evilPath))
}
```
This test currently would fail (the file gets created at `evilPath`) against the existing implementation, confirming the missing containment check.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
