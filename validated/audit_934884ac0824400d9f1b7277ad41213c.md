### Title
Zip-slip: `ExtractZipFile` writes archive entries using raw, unsanitized `file.Name` paths, permitting path traversal / arbitrary file overwrite outside the intended extraction directory - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipFile`/`ExtractZipArchive` extract each `zip.File` entry using its raw `Name` field with no validation for `..` traversal segments, absolute paths, or symlink targets escaping the extraction root. Because cache/artifact restoration on the runner side passes attacker-influenced zip content (cache archives, artifact archives) directly into this extractor, a crafted archive can write files (including symlinks) to arbitrary paths relative to the runner's current working directory, potentially clobbering helper-consumed files (env files, temp scripts) that later build stages trust.

### Finding Description
`extractZipFile` (helpers/archives/zip_extract.go:61-83) does:
- `os.MkdirAll(filepath.Dir(file.Name), 0o777)` [1](#0-0) 
- for directory/regular entries, `os.Mkdir(file.Name, ...)` / `os.OpenFile(file.Name, ...)` directly using `file.Name` [2](#0-1) [3](#0-2) 
- for symlink entries, `os.Symlink(string(data), file.Name)` where both the symlink target (`data`, i.e. entry content) and the link name (`file.Name`) are fully attacker controlled. [4](#0-3) 

The only pre-extraction guard is `errorIfGitDirectory`, which only detects `.git` path segments (git-directory protection), not general path traversal (`..`), absolute paths, or symlink-escape. [5](#0-4) 

`ExtractZipArchive`/`ExtractZipFile` is used by the legacy zip extractor (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`), which is wired into `CacheExtractorCommand.Execute` via `archive.NewExtractor(format, f, size, wd)` and `extractor.Extract(ctx)`. [6](#0-5)  Notably, the `ziplegacy` extractor's `dir` field is never used to `chdir` or join entry paths — it simply calls `archives.ExtractZipArchive(zr)`, which writes relative to whatever the process's current working directory happens to be. [7](#0-6) 

An unprivileged pipeline author who controls the content of a cache or artifact archive that will later be restored by another job (e.g. via a shared/predictable cache key, or an artifact passed between jobs/pipelines) can therefore craft a zip whose entry names contain `../../` segments (or are absolute), or whose entries are symlinks pointing outside the extraction root. When that archive is restored by `cache-extractor`, the resulting `os.MkdirAll` + `os.OpenFile`/`os.Symlink` calls will write outside the intended cache/build directory into the process working directory tree — potentially overwriting the `gitlab_runner_env` file, other helper-generated temp/env files, or scripts consumed by later job stages, since no path containment check (comparable to `findRelativePathInProject`'s `..`-prefix rejection used elsewhere for archiving) is applied on extraction. [8](#0-7) 

### Impact Explanation
If reachable with a realistic writable working directory (e.g., the job's build/temp directory containing generated env files or scripts sourced by later shell stages), a crafted cache/artifact archive can overwrite those files with attacker content, causing later helper stages to consume attacker-controlled bytes as trusted input — matching the "secret exposure or stronger-context execution" impact class (e.g., injecting into an env file that's later `source`d, or overwriting a script executed with elevated trust).

### Likelihood Explanation
Feasibility depends on: (1) an attacker being able to influence the content of a cache/artifact archive that is later restored in a context with sensitive files nearby (e.g., shared cache keys across MRs/branches in the same project, or artifacts passed between jobs in a multi-project/multi-stage pipeline they control), and (2) the runner's working directory at extraction time containing paths reachable via `..` traversal from the archive root. The vulnerable code itself is unconditionally reachable — there is no traversal/absolute-path/symlink-target validation in `extractZipFile`/`extractZipSymlinkEntry`. This is a classic "zip-slip" class bug and is straightforward to trigger with any crafted zip archive that reaches this extractor; the primary uncertainty is the exact cache/artifact-sharing precondition (which cache keys/artifacts an attacker can poison for a victim job) in a given deployment, which is outside this file's scope to prove but is a standard part of documented cache/artifact trust boundaries.

### Recommendation
In `extractZipFile`/`extractZipArchive`, before performing any filesystem operation, canonicalize and validate each `file.Name` (and, for symlinks, the link target) against the intended extraction root: reject or strip leading `/`, reject entries whose cleaned path is `..` or starts with `../`, and use `filepath.Join(root, cleanPath)` combined with an explicit `filepath.Rel`/prefix check (mirroring the existing containment check in `findRelativePathInProject`, helpers/commands/helpers/file_archiver.go:213-216) before calling `os.MkdirAll`, `os.OpenFile`, or `os.Symlink`. Additionally, make the `ziplegacy` extractor's `dir` parameter authoritative by actually confining extraction to that directory rather than relying on process CWD.

### Proof of Concept
Go unit test (add to `helpers/archives/zip_extract_test.go`):
```go
func TestExtractZipFilePathTraversal(t *testing.T) {
    testOnArchive(t, func(t *testing.T, archive *zip.Writer) {
        w, err := archive.Create("../evil_outside_root.txt")
        require.NoError(t, err)
        _, err = w.Write([]byte("attacker-controlled"))
        require.NoError(t, err)
    }, func(t *testing.T, fileName string) {
        dir := t.TempDir()
        require.NoError(t, os.Chdir(dir))
        err := ExtractZipFile(fileName)
        require.NoError(t, err)

        // Assert: file must NOT be created outside dir
        _, statErr := os.Stat(filepath.Join(filepath.Dir(dir), "evil_outside_root.txt"))
        assert.True(t, os.IsNotExist(statErr), "path traversal allowed file creation outside extraction root")
    })
}
```
Expected (current, vulnerable) behavior: the assertion fails because `evil_outside_root.txt` is created one directory above `dir`. After adding path-containment validation, the assertion should pass (extraction either rejects the entry or confines it inside `dir`).

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
