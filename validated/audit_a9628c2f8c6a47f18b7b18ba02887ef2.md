### Title
Stale distribution-pool shares of a former operator continue to be taxed by the new operator after `switch_operator`, redirecting already-earned commission - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::switch_operator` / `switch_operator_with_same_commission` re-key a `StakingContract` from `old_operator` to `new_operator` inside the `SimpleMap<address, StakingContract>`, but the `distribution_pool` (a `pool_u64::Pool`) that already holds shares for `old_operator`'s unpaid commission is never renamed or excluded. `update_distribution_pool()` subsequently taxes *every* shareholder in that pool except the address equal to the current `operator` parameter. Once the operator has changed, `old_operator`'s pending-commission shares stop matching that exclusion and get taxed again on every future call, transferring part of the former operator's already-vested commission to the new operator.

### Finding Description
`switch_operator` at [1](#0-0)  removes the `StakingContract` keyed by `old_operator`, force-distributes inactive funds, calls `request_commission_internal(old_operator, &mut staking_contract)` to pay out any commission accrued so far (which buys `old_operator` shares into `staking_contract.distribution_pool` via `add_distribution`), and finally re-inserts the very same `StakingContract` object (including its `distribution_pool`) under the key `new_operator`.

`request_commission_internal` adds a distribution to `operator` itself: [2](#0-1) . At that moment `add_distribution` -> `update_distribution_pool` excludes the acting operator from commission taxation because `shareholder != operator` fails for that address: [3](#0-2) .

After the switch, `staking_contract.commission_percentage` / underlying `owner_cap` are updated but the `distribution_pool`'s shareholder entry for `old_operator` is left untouched, holding shares worth the previously requested (but not yet withdrawn/distributed) commission. From that point forward, every call to `distribute_internal` (triggered by anyone, since `distribute()` is a permissionless `public entry` function: [4](#0-3) ) or `request_commission_internal` invokes `update_distribution_pool(distribution_pool, updated_total_coins, new_operator, commission_percentage)`. In that loop, `old_operator` is now just another `shareholder != operator (new_operator)`, so as the underlying `pending_inactive`/`inactive` pool appreciates with staking rewards, a commission cut is deducted from `old_operator`'s already-settled balance and transferred to `new_operator`: [5](#0-4) .

The module itself acknowledges this exact gap: `pending_attribution_snapshot`'s doc comment explicitly instructs callers to pass `account = old_operator` "In operator-switch scenarios, the previous operator may still have a non-zero pending attribution" [6](#0-5) . This confirms the stale-shareholder condition is known/observable, but nothing in `switch_operator`, `distribute_internal`, or `update_distribution_pool` prevents the ongoing operator from continuing to tax it.

### Impact Explanation
This is an unprivileged, wrong-account commission/share-accounting corruption: value that rightfully belongs to a former operator (already computed and locked in via `request_commission_internal` before the switch) is silently and repeatedly diverted to whichever operator currently holds the contract, purely as a side effect of normal reward accrual and routine calls to `distribute()`/`request_commission()`/`unlock_stake()`/`update_commision()` (all of which call `distribute_internal`/`request_commission_internal`). No malicious signature or role escalation is required — a staker legitimately switching operators, combined with time passing and epochs turning over, is enough to leak the old operator's earned commission to the new operator. This matches the required impact class "Operator commission, beneficiary payout, or share-accounting corruption that credits the wrong account."

### Likelihood Explanation
Moderate-to-high. `switch_operator_with_same_commission`/`switch_operator` are ordinary staker-facing entry points, and `distribute()` is callable by anyone, so the corrupting path (switch operator while commission is still pending, then let stake earn rewards, then anyone calls `distribute`/`request_commission`) requires no special conditions beyond the very common practice of stakers changing operators mid-lockup with unclaimed commission outstanding.

### Recommendation
When re-keying the `StakingContract` in `switch_operator`, either:
1. Force a full payout of `old_operator`'s existing `distribution_pool` balance (via `distribute_internal`/an explicit `redeem_shares` for `old_operator`) before the map re-insertion, so no stale shares remain, or
2. Track/preserve the set of "already realized commission" shareholders (e.g., snapshot `old_operator`'s balance and exclude it, or migrate/rename the shareholder key to a dedicated non-taxable bucket) so `update_distribution_pool` never taxes previously vested commission balances again, regardless of which address is currently `operator`.

### Proof of Concept
1. Staker `S` creates a staking contract with `operator_A` and 10% commission via `create_staking_contract`.
2. Validator earns rewards; `S` (or anyone) calls `request_commission(operator_A_or_beneficiary_caller, S, operator_A)`, which unlocks commission and buys `operator_A` shares into `distribution_pool` via `add_distribution` (excluded from taxation while `operator == operator_A`) — see [2](#0-1) .
3. Before that commission is withdrawn/distributed (lockup not yet expired), `S` calls `switch_operator_with_same_commission(S, operator_A, operator_B)` — see [7](#0-6) . The `StakingContract` (with its `distribution_pool` still containing `operator_A`'s commission shares) is moved to key `operator_B`.
4. More epochs pass; the pending_inactive/inactive pool value grows with staking rewards.
5. Anyone calls `distribute(S, operator_B)`. Inside `distribute_internal`, `update_distribution_pool(distribution_pool, updated_total_coins, operator_B, commission_percentage)` runs and, per [5](#0-4) , treats `operator_A` (`shareholder != operator_B`) like an ordinary staker: it computes the growth in `operator_A`'s balance and transfers a commission cut of it from `operator_A` to `operator_B`.
6. Net effect: `operator_A` receives less than the commission amount it was already granted in step 2, and `operator_B` receives extra funds it never earned — confirmed by `pending_attribution_snapshot(S, operator_B, operator_A)` showing a shrinking balance across calls to step 5 relative to what was recorded at step 2.

I was not able to execute this in a live Move test environment (no sandbox access here); this trace is based purely on static analysis of `switch_operator`, `distribute_internal`, `request_commission_internal`, `add_distribution`, and `update_distribution_pool` in `staking_contract.move`. A background Devin session with the ability to run the existing Move unit test harness (`aptos-move/framework/aptos-framework/sources/staking_contract.move` test module) could add a concrete test reproducing steps 1–6 to fully confirm the numeric leakage.

```text
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);

        // Short-circuit if there's no commission to pay.

            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );
```

```text
    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }
```

```text
    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
```
