### Title
Dust Injection via `balance::send_funds` Inflates Victim's Address Balance and Blocks Gasless Full-Balance Withdrawals — (File: `crates/sui-core/src/accumulators/funds_read.rs`)

---

### Summary

`check_remaining_amounts_after_withdrawal` reads the victim's live address-balance with `get_latest_account_amount` — an explicitly unsequenced, non-deterministic read — and rejects a gasless transaction if the leftover after the declared withdrawal is in the range `(0, min_amount)`. Because `balance::send_funds<T>` is a public, permissionless function, any attacker who holds even 1 unit of the token can deposit dust into the victim's address balance, pushing the leftover from 0 into that forbidden range and causing every validator to refuse to sign the victim's transaction.

---

### Finding Description

**Vulnerable function:** `check_remaining_amounts_after_withdrawal` in `crates/sui-core/src/accumulators/funds_read.rs` lines 74–107, called from `AuthorityState::pre_object_load_checks` in `crates/sui-core/src/authority.rs` lines 1125–1131 during `handle_vote_transaction` (signing/voting path).

The check reads the live balance:

```rust
let actual_amount = self.get_latest_account_amount(object_id);   // unsequenced read
let remaining = actual_amount.saturating_sub(*requested_amount as u128);
if remaining == 0 {
    continue;   // full withdrawal — OK
}
// ...
if remaining < min_amount as u128 {
    return Err(...);   // REJECTED
}
```

`get_latest_account_amount` is documented as doing "an unsequenced read" that "does not guarantee consistency with the root accumulator version." [1](#0-0) 

The attacker's lever is `balance::send_funds<T>`, a public Move function with no minimum-amount guard: [2](#0-1) 

```move
public fun send_funds<T>(balance: Balance<T>, recipient: address) {
    sui::funds_accumulator::add_impl(balance, recipient);
}
```

**Attack path:**

1. Victim holds exactly `X` USDC in their address balance and has no SUI for gas.
2. Victim constructs a gasless transaction declaring `MaxAmountU64 = X` (withdraw everything, leaving 0).
3. Attacker front-runs by calling `balance::send_funds<USDC>(Balance { value: 1 }, victim_address)`.
4. Every validator now reads `actual_amount = X + 1`.
5. `remaining = (X + 1) − X = 1`. Since `1 < min_amount` (e.g., 1 000 for USDC), the check fires: [3](#0-2) 

```
"Gasless transactions must either use the entire address balance,
 or leave at least {min_amount}. Remaining amount would be 1"
```

6. All validators reject the transaction at signing time. The victim must update their declared amount to `X + 1` and re-sign.
7. The attacker repeats step 3 before the new transaction is signed, keeping the victim in an infinite retry loop.

The `pre_object_load_checks` call site confirms this check runs on every signing/voting request: [4](#0-3) 

---

### Impact Explanation

A victim who holds only address-balance funds (no SUI coin objects) and wants to drain their entire balance via a gasless transaction can be permanently griefed. Because the check uses a live, unsequenced read, the attacker can always race ahead of the victim's updated transaction. The victim cannot use a regular (priced) transaction without first obtaining SUI from an external source. The `min_amount` portion of the victim's balance (e.g., 1 000 USDC units) is effectively locked for as long as the attacker is willing to spend dust.

This matches the **harmful smart-contract behavior / temporary fund lock** impact class (Medium).

---

### Likelihood Explanation

- `balance::send_funds` is a public, permissionless framework function callable by any ordinary SUI holder who possesses any amount of the target token.
- The attacker cost is minimal: 1 unit of the stablecoin per griefing round.
- The victim has no on-chain recourse other than obtaining SUI from a third party.
- The attack is deterministic and repeatable with no special privileges.

---

### Recommendation

Replace the unsequenced `get_latest_account_amount` call inside `check_remaining_amounts_after_withdrawal` with a consistent snapshot read (e.g., `get_consistent_latest_account_amount_and_version`) so the balance used for the remaining-balance check is anchored to a stable accumulator root version that the attacker cannot race against. Alternatively, compute the remaining-balance check post-execution from the deterministic accumulator events (as `check_gasless_execution_requirements` already does for the per-recipient minimum), rather than from a live storage read at signing time.

```

  - Victim address V holds 10 000 USDC in address balance; no SUI.
  - USDC registered with min_transfer = 1 000.
  - Attacker A holds ≥ 1 USDC.

    withdraw<Balance<USDC>>(10_000)   // MaxAmountU64 = 10_000
    redeem_funds<USDC>(...)

  PTB: balance::send_funds<USDC>(Balance { value: 1 }, V)

Step 3 (Validator, signing):
  check_remaining_amounts_after_withdrawal:
    actual_amount  = 10 001
    requested      = 10 000
    remaining      = 1
    1 < 1 000 (min_amount) → Error: "Remaining amount would be 1"
  → Transaction rejected.

Step 4: Victim updates to MaxAmountU64 = 10 001.
Step 5: Attacker repeats Step 2.
→ Victim can never execute the full-balance gasless withdrawal.

    fn check_remaining_amounts_after_withdrawal(
        &self,
        requested_amounts: &BTreeMap<AccumulatorObjId, (u64, TypeTag, SuiAddress)>,
        min_amounts: &BTreeMap<TypeTag, u64>,
    ) -> SuiResult {
        for (object_id, (requested_amount, type_tag, owner)) in requested_amounts {
            let actual_amount = self.get_latest_account_amount(object_id);
            let remaining = actual_amount.saturating_sub(*requested_amount as u128);
            if remaining == 0 {
                continue;
            }
            let coin_type =
                Balance::maybe_get_balance_type_param(type_tag).unwrap_or_else(|| type_tag.clone());
            if let Some(&min_amount) = min_amounts.get(&coin_type)
                && min_amount > 0
                && remaining < min_amount as u128
            {
                return Err(SuiErrorKind::UserInputError {
                    error: UserInputError::InvalidWithdrawReservation {
                        error: format!(
                            "Invalid gasless withdrawal of coin type {coin_type} \
                             from address {owner}. \
                             Gasless transactions must either use the entire address \
                             balance, or leave at least {min_amount}. \
                             Remaining amount would be {remaining}",
                        ),
                    },
                }
                .into());
            }
        }

        Ok(())
    }
