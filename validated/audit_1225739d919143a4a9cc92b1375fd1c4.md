## Title
GlobalContractCode{AccountId} identity binding survives DeleteAccount, allowing account-name reuse to silently swap contract code for all users who opted in via `UseGlobalContract(AccountId)` - ([File: runtime/runtime/src/global_contracts.rs])

## Summary
`use_global_contract` (`runtime/runtime/src/global_contracts.rs:75-108`) only checks that a `TrieKey::GlobalContractCode { identifier }` entry exists in the trie, and stores `AccountContract::GlobalByAccount(id)` on the victim's account. Resolution of that reference happens lazily at execution time via `GlobalContractAccessExt::hash`/`code` (`runtime/runtime/src/contract_code.rs:91-116`), which looks up `TrieKey::GlobalContractCode { identifier: AccountId(id) }` fresh on every call rather than snapshotting a specific deployment. Because `GlobalContractCode` is a distinct trie namespace keyed only by `AccountId` (see `core/primitives/src/trie_key.rs`), and `DeleteAccount` removes the `Account` object but does not sweep this namespace, an unrelated party can recreate the deleted account name and redeploy new `AccountId`-mode code, which is then transparently executed for every account that had previously opted in.

## Finding Description
`action_use_global_contract` → `use_global_contract` binds a victim's `AccountContract` to `AccountContract::GlobalByAccount(id)` after confirming only that `TrieKey::GlobalContractCode{AccountId(id)}` currently exists:

```
let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
if !state_update.contains_key(&key, AccessOptions::DEFAULT)? { ... }
...
let contract = match contract_identifier {
    GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
    GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
};
```
(`runtime/runtime/src/global_contracts.rs:82-97`)

Critically, for `AccountId`-mode, the victim's account does **not** store a code hash — it stores the account-id reference itself. At execution time, `RuntimeContractIdentifier::resolve` and `GlobalContractAccessExt::hash`/`code` (`runtime/runtime/src/contract_code.rs:36-116`) re-resolve `GlobalContractIdentifier::AccountId(id)` into a code hash/bytes by re-reading `TrieKey::GlobalContractCode{AccountId(id)}` from the *current* trie state at call time — there is no snapshotting of a specific code version, and no check that `id` is presently a live account.

`DeployGlobalContract` in `AccountId` mode writes into this separate namespace via `initiate_distribution`/`apply_distribution_current_shard` (`runtime/runtime/src/global_contracts.rs:142-234`), keyed only by `AccountId(account_id)`, independent of the depositing `Account` object's lifecycle. `DeleteAccount` removes the `Account` record but this code path never touches `TrieKey::GlobalContractCode` entries, so the global contract bytes for that `id` persist in the trie after the account is deleted.

This means:
1. Account `P` deploys `AccountId`-mode global contract code (writes `GlobalContractCode{AccountId(P)}`).
2. Victim `V` opts in via `UseGlobalContractAction { contract_identifier: AccountId(P) }`, setting `V.contract = GlobalByAccount(P)`.
3. `P` is deleted via `DeleteAccount`. The `Account` object for `P` is gone, but `GlobalContractCode{AccountId(P)}` trie entry is untouched.
4. A third party recreates account `P` (fresh `CreateAccount`, since the name is now free) and deploys new `AccountId`-mode code, overwriting `GlobalContractCode{AccountId(P)}` with the new bytecode.
5. `V`'s `FunctionCall` receipts now resolve `GlobalByAccount(P)` against the new occupant's code — because resolution is a fresh trie lookup, not a pinned code hash — silently executing arbitrary attacker-chosen code with `V`'s account credentials/state/balance, without `V`'s renewed consent.

Whether this is the "same" closed account-name-reuse class is a distinct question: the previously closed class concerns account-keyed *state* (e.g., access keys, `Account` struct fields) being reused after a `DeleteAccount`/`CreateAccount` cycle on the same name, typically mitigated by state deletion semantics tied to the account itself. Here, the vulnerable object is not the recreated account `P`'s own state, but a **third party's** durable pointer (`V`'s `AccountContract::GlobalByAccount(P)`) into a **separate global namespace** (`GlobalContractCode{AccountId}`) that is not part of `P`'s `Account` trie subtree and is not cleaned up by account deletion. This is a genuinely distinct mechanism: the impact lands on an uninvolved third party (`V`), not on the account being reused, and no existing account-deletion cleanup path is designed to purge cross-account references of this kind, since global contracts by design are meant to be referenced by many accounts indefinitely.

## Impact Explanation
This falls under "Contracts execution flows / Stealing or loss of funds": an attacker can take over code execution for every account that opted into `UseGlobalContract(AccountId(P))` for a previously-existing `P`, without any action from the victims. Because the substituted contract runs with full authority of the victim account (its balance, storage, and the ability to issue further actions/promises on the victim's behalf, subject to normal access-key/gas checks the victim already granted by having deployed via a `FunctionCall`), this enables theft of funds or arbitrary state manipulation for any victim who used this idiom, at a cost to the attacker of only the fees to delete/recreate a specific account name and redeploy a global contract.

## Likelihood Explanation
Preconditions: an account `P` that deployed `AccountId`-mode global contract code and was later deleted (the account owner voluntarily calls `DeleteAccount`, or a low-balance account gets deleted); at least one victim `V` who called `UseGlobalContract(AccountId(P))` before the deletion; and the attacker being fast enough to recreate `P`'s name before the legitimate owner (or nobody) does. This requires cooperation/negligence from the original deployer `P` (self-deleting their own account) or targeting of accounts prone to deletion (e.g., abandoned/low-balance accounts), making it not trivially attacker-controlled end-to-end, but fully reachable using only ordinary, unprivileged transactions (`DeployGlobalContract`, `UseGlobalContract`, `DeleteAccount`, `CreateAccount`) with no validator/node access needed.

## Recommendation
For `GlobalContractIdentifier::AccountId(id)` opt-in, resolve and pin the contract to the code that existed at opt-in time (e.g., store the resolved code hash on the victim's account, or additionally record a generation/nonce tied to `id`'s current global-contract deployment and re-validate it hasn't changed identity, e.g. by binding to the `TrieKey::GlobalContractNonce` value or account creation-nonce of `id` at opt-in time). Alternatively, disallow deleting an account `P` while `GlobalContractCode{AccountId(P)}` still exists and has active `GlobalByAccount(P)` references, or purge/invalidate the `GlobalContractCode{AccountId}` entry on `DeleteAccount` so a later redeploy under the same reused name is treated as an unrelated dataset requiring victims to re-opt-in.

## Proof of Concept
Test-loop integration test:
1. Create accounts `p`, `v` with sufficient balance.
2. `p` sends `DeployGlobalContract { code: CODE_A, deploy_mode: AccountId }`; wait for distribution receipt to apply so `GlobalContractCode{AccountId(p)}` is set to `CODE_A`.
3. `v` sends `UseGlobalContract { contract_identifier: AccountId(p) }`; assert `v.contract() == AccountContract::GlobalByAccount(p)`.
4. `v` calls a `FunctionCall` and asserts execution runs `CODE_A` logic (e.g., a distinguishing exported function/log).
5. `p` sends `DeleteAccount`; assert `p` account no longer exists but `state_update.contains_key(TrieKey::GlobalContractCode{AccountId(p)})` still returns true (or verify via a query showing the global contract code is still retrievable).
6. A different signer (attacker) sends `CreateAccount` for `p` (funded implicit-account style or via a parent account), then `DeployGlobalContract { code: CODE_B, deploy_mode: AccountId }` from the new `p`.

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())
}

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

/// Increments the nonce for the given global contract identifier and writes
/// it to state immediately.
fn increment_nonce(
    state_update: &mut TrieUpdate,
    id: &GlobalContractIdentifier,
) -> Result<u64, RuntimeError> {
    let identifier: GlobalContractCodeIdentifier = id.clone().into();

    let nonce_key = TrieKey::GlobalContractNonce { identifier };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;

    let new_nonce = stored_nonce.checked_add(1).ok_or_else(|| {
        RuntimeError::UnexpectedIntegerOverflow("increment_global_contract_nonce".into())
    })?;
    set_nonce(state_update, nonce_key, new_nonce);
    Ok(new_nonce)
}

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)
}

pub(crate) trait GlobalContractAccessExt {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError>;
    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError>;
}

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }

    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError> {
        let key = TrieKey::GlobalContractCode { identifier: self.clone().into() };
        let code_hash = match self {
            GlobalContractIdentifier::AccountId(_) => None,
            GlobalContractIdentifier::CodeHash(hash) => Some(hash),
        };
        let code = store.get(&key, AccessOptions::DEFAULT)?;
        Ok(code.map(|code| ContractCode::new(code, code_hash)))
    }
