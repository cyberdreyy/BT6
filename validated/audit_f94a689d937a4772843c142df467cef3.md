### Title
Stale confirmations from removed multisig members still count toward `num_confirmations` threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` tallies approvals purely by `confirmations.len()`, an on-disk `HashSet<String>` of member identifiers keyed per `request_id`. `delete_member` only purges requests that the removed member itself *created* (`r.member == member`), but never scans or prunes confirmations that member previously cast on other members' pending requests. This detaches "confirmations counted" from "members currently live," analogous to the reported `payee`/`ownerOf` detachment in the LienToken report.

### Finding Description
`confirm()` reaches quorum solely from the stored count, not from currently-valid members: [1](#0-0) 

`delete_member` removes the member from `self.members` and deletes only requests where that member was the original signer, but leaves `self.confirmations` for any *other* request untouched even though it may contain the now-removed member's identifier string: [2](#0-1) 

`add_request`/`confirm` never re-validate that entries inside a request's stored `confirmations` set are still members of `self.members` — quorum is a raw length check: [3](#0-2) 

As a result, the binding `count(confirmations for request X) == count(live members who confirmed request X)` can be broken: a member can confirm a request they did not create, later be removed via a separate `DeleteMember` request, and their stale confirmation persists and still counts toward the `num_confirmations` threshold for request X.

### Impact Explanation
This directly matches the Critical impact category "a multisig request executed below threshold." After a member is removed, a pending request created earlier can still execute with confirmations from fewer than `num_confirmations` *currently valid* members — e.g., in a 2-of-3 setup, if member C confirms a request created by member A and is later removed (leaving A and B as the only live members, with `num_confirmations` unchanged at 2), that request can execute with A's single confirmation plus C's stale one, i.e., effectively 1 live signer approving a 2-of-N transfer/action.

### Likelihood Explanation
This does not require the foundation, a redeploy, or any privileged actor outside the multisig's own membership process: it only requires ordinary multisig operation (one member confirms another's request, then a `DeleteMember` request is separately approved) — both of which are expected, routine multisig activities (e.g., key rotation). No malicious collusion beyond normal member behavior is needed for the stale-confirmation state to arise; only exploiting it to push a request through below the current live threshold requires an interested party to leave such a request pending.

### Recommendation
When executing `DeleteMember`, iterate over **all** requests' confirmation sets (not just requests created by that member) and remove the deleted member's identifier from each; alternatively, when tallying quorum in `confirm()`/`execute_request`, filter `confirmations` to only those entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with 3 members `A, B, C` and `num_confirmations = 2`.
2. `A` calls `add_request` to create request `X` (e.g., a `Transfer`).
3. `C` calls `confirm(X)` — `confirmations[X] = {C}` (1 confirmation, below threshold of 2).
4. Separately, members approve a `DeleteMember { member: C }` request via `add_request_and_confirm`/`confirm` — `delete_member` removes `C` from `self.members` but does not touch `confirmations[X]`, since `X.member == A != C`.
5. `B` calls `confirm(X)` — `confirmations[X].len() + 1 == 2 >= num_confirmations`, so `execute_request` runs `X`'s `Transfer`, even though only `A` (creator) and `B` are live members who ever actually confirmed while being members; `C`'s stale confirmation counted toward the 2-of-N threshold despite `C` no longer being a member.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
