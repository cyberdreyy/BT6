## Analysis: Decimal-mismatch bug analog found in `Bank::change_liability_shares`

### Title
Missing decimal normalization for `borrow_limit` in Drift-integration banks causes incorrect capacity comparison - (File: `programs/marginfi/src/state/bank.rs`)

### Summary
The external Rova report's root cause is comparing two amounts denominated in different decimal precisions without normalization (`userTokenAmount` in launch-token decimals vs. `additionalCurrencyAmount` in payment-currency decimals). The marginfi-v2 codebase contains an exact structural analog of this pattern in the Drift bank integration: the deposit-limit path was explicitly patched to normalize decimals, but the parallel borrow-limit path was not.

### Finding Description
`Bank::change_asset_shares` explicitly handles the fact that, for Drift-integration banks, `deposit_limit` is stored in the mint's native decimals while `total_deposits_amount` is computed in Drift's fixed 9-decimal scaled-balance space (`DRIFT_SCALED_BALANCE_DECIMALS`). It converts `deposit_limit` via `scale_drift_deposit_limit` before comparing: [1](#0-0) 

By contrast, `Bank::change_liability_shares`, which enforces `borrow_limit`, performs no such conversion — it directly compares `total_liability_amount` (which, for Drift banks, is likewise expressed in the 9-decimal scaled-balance space, per `Bank::get_balance_decimals`) against `I80F48::from_num(self.config.borrow_limit)`, a value configured in the mint's native decimals just like `deposit_limit`: [2](#0-1) 

`get_balance_decimals` confirms that for `ASSET_TAG_DRIFT` banks, the "native" unit for internal accounting (used for both assets and liabilities) is the fixed 9-decimal Drift scale, not `mint_decimals`: [3](#0-2) 

The `scale_drift_deposit_limit` helper that was written specifically to fix this decimal mismatch is used only on the asset/deposit side: [4](#0-3) 

This is the same root cause as the Rova bug: values from two different decimal domains (native mint decimals vs. an internal 9-decimal accounting unit) are compared directly, without the normalization that the codebase itself demonstrates is required (as evidenced by the fix already applied on the sibling deposit path, including an explicit code comment: *"For Drift banks, deposit_limit is in native decimals but total_deposits_amount is in 9-decimal ... We Scale deposit_limit to match."*).

### Impact Explanation
For any Drift-integration bank whose underlying mint has fewer than 9 decimals (e.g., USDC with 6 decimals, which is used in the Drift bank tests), `total_liability_amount` will be reported in units 10^(9-decimals) times larger than the native-decimal `borrow_limit` value the admin configured. This makes `change_liability_shares`'s capacity check fire far earlier than intended (effectively shrinking the configured borrow limit by orders of magnitude), producing a durable inconsistency between the configured risk parameter and actual enforced capacity for every borrow against that bank. Because `borrow_limit` is a group-admin-configured, non-privileged-user-facing accounting parameter, and the mismatch persists for the life of the bank once decimals differ from 9, this is a durable state inconsistency with direct financial/operational effect (borrow capacity for Drift banks is silently and permanently miscalculated relative to the admin's configured intent).

### Likelihood Explanation
Any Drift bank added via `lending_pool_add_bank_drift` with `bank_config.borrow_limit` configured (non-zero) and a mint with `decimals != DRIFT_SCALED_BALANCE_DECIMALS` (9) will trigger this on the very first borrow that approaches the intended cap, with no special preconditions required beyond normal bank setup and borrowing.

### Recommendation
Apply the same decimal-scaling logic used in `change_asset_shares` (`scale_drift_deposit_limit`) to `change_liability_shares`'s `borrow_limit` comparison for Drift-tagged banks, converting `self.config.borrow_limit` (native decimals) into the 9-decimal Drift scale before comparing against `total_liability_amount`, or normalize `total_liability_amount` back into native decimals before the comparison.

### Proof of Concept
Not executed; based on direct code comparison between `change_asset_shares` (patched) and `change_liability_shares` (unpatched) in `programs/marginfi/src/state/bank.rs`, and `Bank::get_balance_decimals` in `type-crate/src/types/bank.rs`. A concrete PoC would require setting up a Drift bank with a 6-decimal mint (e.g., USDC) and a non-zero `borrow_limit`, then observing that the effective enforced borrow capacity is ~1000x smaller than the configured `borrow_limit` value.

    fn change_liability_shares(
        &mut self,
        shares: I80F48,
        bypass_borrow_limit: bool,
    ) -> MarginfiResult {
        let total_liability_shares: I80F48 = self.total_liability_shares.into();
        self.total_liability_shares = total_liability_shares
            .checked_add(shares)
            .ok_or_else(math_error!())?
            .into();

        if !bypass_borrow_limit && shares.is_positive() && self.config.is_borrow_limit_active() {
            let total_liability_amount =
                self.get_liability_amount(self.total_liability_shares.into())?;
            let borrow_limit = I80F48::from_num(self.config.borrow_limit);

            if total_liability_amount >= borrow_limit {
                let liab_num: f64 = total_liability_amount.to_num();
                let borrow_num: f64 = borrow_limit.to_num();
                msg!("amt: {:?} borrow lim: {:?}", liab_num, borrow_num);
                return err!(MarginfiError::BankLiabilityCapacityExceeded);
            }
        }

        Ok(())
    }

/// Scale a native deposit limit to Drift's fixed 9-decimal balance units.
pub fn scale_drift_deposit_limit(deposit_limit: u64, mint_decimals: u8) -> Result<I80F48> {
    let limit = I80F48::from_num(deposit_limit);

    if mint_decimals == DRIFT_SCALED_BALANCE_DECIMALS {
        return Ok(limit);
    }

    if mint_decimals < DRIFT_SCALED_BALANCE_DECIMALS {
        let diff = (DRIFT_SCALED_BALANCE_DECIMALS - mint_decimals) as usize;
        let scale = EXP_10_I80F48[diff];
        return limit
            .checked_mul(scale)
            .ok_or_else(|| error!(DriftMocksError::MathError));
    }

    let diff = (mint_decimals - DRIFT_SCALED_BALANCE_DECIMALS) as usize;
    let scale = EXP_10_I80F48[diff];
    limit
        .checked_div(scale)
        .ok_or_else(|| error!(DriftMocksError::MathError))
}
