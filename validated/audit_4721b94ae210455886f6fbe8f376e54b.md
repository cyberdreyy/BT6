### Title
Multisig request executes with confirmations from removed (deleted) members counted toward threshold, allowing execution below `num_confirmations` live members - (File: multisig2/src/lib.rs)

### Summary
`confirm()` only checks `confirmations.len() + 1 >= self.num_confirmations` without verifying that entries already present in the `confirmations` `HashSet<String>` still correspond to current members of `self.members`. `delete_member()` only purges `confirmations` for requests it *created* (`r.member == member`), not for requests where the removed member had merely *confirmed*. A former member's stale confirmation on a still-open request created by someone else silently counts toward the threshold after that member is removed, letting a request execute with fewer live confirmations than `num_confirmations`.

### Finding Description
The broken binding: count of distinct members currently present in `self.members` who confirmed request `R2` should equal `self.num_confirmations` before `execute_request` runs, but it does not.

Path:
1. `add_request` by member `B` creates `R2` and inserts an empty `HashSet` into `confirmations` [1](#0-0) .
2. Attacker (member `A`, e.g. `MultisigMember::Account`) calls `confirm(R2)`. Since `confirmations.len()+1 (=1) < num_confirmations (=2)`, the attacker's `member.to_string()` is inserted into `confirmations` for `R2` [2](#0-1) .
3. A `DeleteMember{member: attacker}` self-request is confirmed/executed, calling `delete_member`. This function only removes confirmations/requests for entries where `r.member == member` — i.e., requests *created* by the attacker — and clears `num_requests_pk` for the attacker, then removes the attacker from `self.members` [3](#0-2) . Because `R2` was created by `B`, not the attacker, `R2`'s confirmations set (still containing the attacker's stale entry) is left untouched.
4. `B` later calls `confirm(R2)`. `assert_valid_request` only checks that the caller is a current member, that the request exists, and that a confirmations entry exists — it never re-validates that existing entries in the confirmations set still belong to `self.members` [4](#0-3) . `confirmations.len() (=1, stale attacker) + 1 (B) = 2 >= num_confirmations (2)`, so `remove_request` and `execute_request` run, executing `R2`'s actions (e.g. a `Transfer`) despite only one live member (`B`) having actually confirmed [5](#0-4) .

No existing guard (`assert_valid_request`, `assert_self_request`, `assert_one_action_only`) checks confirmer liveness against `self.members`, so the divergence is not caught.

### Impact Explanation
NEAR held by the multisig account can be transferred out (or any other `MultiSigRequestAction`, including further membership/key manipulation, executed) with only 1 of 2 required live confirmations, directly matching the Critical category "a multisig request executed below `num_confirmations` live members." This is repeatable for any multisig where a member is removed after having confirmed — but not created — an outstanding request; the attack can be triggered by the remaining live member(s) simply continuing normal usage (they need not even be aware of the stale entry).

### Likelihood Explanation
Preconditions are ordinary multisig operation, not exotic: (1) at least 2 members with `num_confirmations` set so that removing one member still keeps `members.len()-1 >= num_confirmations`; (2) a member confirms a request created by a different member and is later removed while that request is still open. This is a plausible operational sequence (e.g., a compromised or offboarded member confirms pending transfers before being removed) and requires no attacker deposit or special privilege beyond being an existing member at time of confirmation — it is a logic flaw in cleanup, not an attacker-crafted payload, but it is fully attacker-triggerable by a member who intentionally confirms then engineers their own removal (or is removed for unrelated reasons) to leave a "ghost vote" in place.

### Recommendation
In `delete_member`, purge the removed member's string from every entry of `self.confirmations` (not just requests it created), e.g. iterate `self.requests` and call `confirmations.remove(&member.to_string())` (re-inserting the updated set) for all request IDs, or alternatively re-validate confirmer membership at `confirm()` time by filtering `confirmations` against `self.members` before computing the threshold.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
