### Title
Unprivileged dust `requestDeposit` permanently bricks `stopEpochWithDuration` on prefunded pools, freezing all LP funds - ([File: contracts/IdleCDOEpochQueue.sol](contracts/IdleCDOEpochQueue.sol))

### Summary
`IdleCDOEpochVariantPrefunded` routes its epoch-stop flow through `prefundedDepositsToProcess()`, which reverts whenever the queue still holds *raw* (non-prefunded) pending deposits for the target epoch. Any KYC-passing user can leave a dust `requestDeposit` in that bucket — and there is no privileged path to clear it once the prefunding window has passed — so every `stopEpochWithDuration` call reverts forever and all tranche funds remain locked in the running epoch.

### Finding Description
In `IdleCDOEpochQueue`, user deposits for the next epoch sit in `epochPendingDeposits[nextEpoch]` until a privileged actor either prefunds them (`processDepositsToBorrower`) or processes them in the buffer (`processDeposits`). For a prefunded-enabled AA queue:

- `processDeposits()` is disabled entirely: `_checkNotAllowed(_isPrefundedQueueEnabled())` (IdleCDOEpochQueue.sol:226).
- `processDepositsToBorrower()` is only callable by owner/manager **before** the cutoff: `_checkNotAllowed(_prefundedWindow == 0 || block.timestamp + _prefundedWindow < _cdo.epochEndDate())` (IdleCDOEpochQueue.sol:164). With a nonzero `prefundedDepositWindow`, once `block.timestamp + window >= epochEndDate` the pending bucket can never be moved again.
- Meanwhile `requestDeposit()` remains open to any KYC'd wallet while `isEpochRunning()` (IdleCDOEpochQueue.sol:103-127, `_checkAllowed` at 415-421). The only prefunded-specific gate is `epochPrefundedDeposits[nextEpoch] != 0` or the window check (lines 114-117), which does not stop a deposit *before* the cutoff, and does not stop one at all when `prefundedDepositWindow == 0`.

On the CDO side, `_afterStopEpochWithDuration` calls `queue.prefundedDepositsToProcess()`, which reverts if `epochPendingDeposits[_epoch] != 0` (IdleCDOEpochQueue.sol:280-281). Since `_beforeStopEpoch` blocks the plain `stopEpoch` selector when a queue is set (IdleCDOEpochVariantPrefunded.sol:43), `stopEpochWithDuration` is the only stop path — and it reverts inside the post-stop hook, rolling back the entire epoch settlement.

Result: an attacker deposits dust (e.g., 1 wei of underlying) targeting `epochNumber + 1` just before the prefunding window closes (or anytime while running when `prefundedDepositWindow == 0`), and additionally front-runs every manager attempt to `processDepositsToBorrower`/`stopEpochWithDuration` with fresh dust while the window still allows it. Once the epoch end passes with `epochPendingDeposits` nonzero:

- `stopEpoch` → blocked selector.
- `stopEpochWithDuration` → reverts in `prefundedDepositsToProcess`.
- `processDeposits` → reverts (`_isPrefundedQueueEnabled`).
- `processDepositsToBorrower` → reverts (window passed).
- `deleteRequest` → only the attacker can clear their own deposit.

No privileged or unprivileged recovery path exists; `emergencyShutdown`/`restoreOperations` do not clear queue state either. This mirrors the source bug: an unprivileged action permanently disables a core management function that the honest operator cannot unstick.

### Impact Explanation
All AA and BB tranche principal and accrued yield are permanently frozen inside the CDO: the epoch can never stop, `epochEndDate` never clears, `pendingWithdraws` are never funded, and `requestWithdraw`/claims stay gated. Loss magnitude = 100% of pool TVL for the affected deployment.

### Likelihood Explanation
The attacker only needs to pass Keyring KYC (same as any legitimate depositor) and spend dust. The attack requires a prefunded-enabled AA queue (the deployed `IdleCDOEpochVariantPrefunded` + `setEpochQueue` configuration). Two viable windows: (a) deposit dust once before `epochEndDate - prefundedDepositWindow` and simply never delete it — no timing skill needed; (b) with `prefundedDepositWindow == 0`, perpetually front-run `stopEpochWithDuration` calls. Case (a) alone is sufficient and costs gas only.

### Recommendation
Give privileged actors a way to clear raw pending deposits before settlement — e.g., let `processDepositsToBorrower`/`processDeposits` run for prefunded queues during the stop flow, add a manager `refundPendingDeposits(_epoch)` that returns queue-held funds to users (mirroring `deleteRequest`), or have `_afterStopEpochWithDuration` settle the epoch at `epochPrice = virtualPrice` while leaving `epochPendingDeposits` for later processing instead of reverting.

### Proof of Concept
```solidity
function test_DustDeposit_BricksPrefundedStopEpoch() public {
    // setup: prefunded variant, AA queue enabled, window set
    vm.prank(manager);
    IdleCDOEpochVariantPrefunded(address(cdoEpoch)).setEpochQueue(address(aaQueue));
    vm.prank(manager);
    aaQueue.setPrefundedDepositWindow(PREFUNDED_DEPOSIT_WINDOW);

    // honest LPs deposit, epoch starts
    idleCDO.depositAA(10_000 * ONE_SCALE);
    _startEpochAndCheckPrices(0);

    // attacker (KYC'd lender) queues dust for next epoch before the cutoff
    address attacker = makeAddr('attacker');
    _requestDepositWithUser(attacker, 1); // 1 wei underlying
    assertEq(aaQueue.epochPendingDeposits(strategy.epochNumber() + 1), 1);

    // attacker never prefunds/deletes; window passes
    _enterPrefundedWindow(PREFUNDED_DEPOSIT_WINDOW);
    vm.prank(manager);
    vm.expectRevert(); // window cutoff: can't move pending -> prefunded
    aaQueue.processDepositsToBorrower();

    // epoch end: every stop path reverts
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(); // epochPendingDeposits != 0 in prefundedDepositsToProcess
    cdoEpoch.stopEpochWithDuration(initialProvidedApr, 0);
    vm.prank(manager);
    vm.expectRevert(); // direct stopEpoch selector blocked when queue set
    cdoEpoch.stopEpoch(initialProvidedApr, 0);
    vm.prank(manager);
    vm.expectRevert(); // processDeposits disabled for prefunded queue
    aaQueue.processDeposits();

    // funds permanently frozen
}
```
