### Title
Timeout error response embeds raw per-node JSON-RPC responses via `%v` formatting, leaking node result/error payloads to the requesting user - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`handler.removeExpiredRequests` in the vault gateway handler builds a `RequestTimeoutError` message by formatting the raw `jsonrpc.Response[json.RawMessage]` values collected from each responding DON node with `%v`, and forwards that string (via both `Message` and `Data`) directly to the requesting client. Because the map includes each node's `Result`/`Error` payload contents (e.g., ciphertext/OCR response bytes, error strings) collected before quorum was reached, an attacker who can force a request to time out (e.g., by having one DON member stall/fail to respond so quorum is never met) can read back verbatim per-node response content that was never intended to be exposed directly to the caller.

`copiedResponses()` returns the full `jsonrpc.Response[json.RawMessage]` structs collected from each node, including `Result` (raw JSON payload from the node, e.g. `SignedOCRResponse`/ciphertext for `vault.secrets.list`/`vault.secrets.get`) and `Error` fields, as seen in `activeRequest.copiedResponses`: [2](#0-1) 

Formatting a struct containing `*json.RawMessage` with `%v` prints its underlying byte content (Go's default `%v` for a `[]byte`/`json.RawMessage` renders the raw bytes as a string representation), so any payload a node placed in `Result` or `Error` for that request is embedded verbatim into the outgoing error text. This text is passed both as the `errors.New(...)` message and as the raw `Data` field of the JSON-RPC error via `errorResponse`, meaning it is delivered straight to the requesting client with no redaction.

The reachable path for an unauthenticated/unprivileged attacker:
1. Attacker sends a `vault.secrets.list`/`vault.secrets.get` request through `HandleJSONRPCUserMessage`, which is authorized via the normal request-processor path (this only checks the caller can make *a* request; it does not gate what data leaks in a failure branch).
2. Attacker arranges for quorum never to be reached before `h.requestTimeout` elapses — e.g., by having one DON member stall or fail while >0 but <quorum nodes reply (a client-controllable timing condition, not a malicious-node/OCR-peer condition; the attacker does not need to compromise a node, only needs the request to time out naturally, which any user can trigger simply by sending requests during periods when the DON is slow, or racing sends against the timeout window).
3. When `removeExpiredRequests` runs after `defaultCleanUpPeriod`, it builds the verbose response including whatever partial `Result`/`Error` content was collected and sends it back as the `RequestTimeoutError`.

No auth middleware, presenter redaction, or signature verification stops this — the code path is a direct string interpolation from internal state into a user-visible error, occurring after normal authorization succeeds. This is a genuine confinement failure in the error path, matching the audit invariant "secret confinement in error paths."

### Impact Explanation
This falls into the "secret/credential/internal-state disclosure via error message" bounty class. Depending on what a stalled/slow node had already returned for this request (partial ciphertext, OCR response bytes, or internal error text possibly containing implementation details), a normal API caller can obtain content that should be confined to node-to-node/enclave communication and never surfaced raw to end users. Even absent plaintext secret material (payloads are typically encrypted ciphertext), this leaks internal response structure/format, node-specific state, and error strings that were never meant to be part of the external API contract — a verbose-error/information-disclosure issue.

### Likelihood Explanation
The only precondition is being able to send a normal authorized `vault.secrets.*` request and having the request expire before quorum is reached — a condition entirely reachable by an ordinary caller under normal network jitter/slow-node conditions, and much more reliably by deliberately racing/sending during a known slow window, no node compromise or elevated role required. This is fully repeatable: any expired request with ≥1 collected node response triggers the leak.

### Recommendation
Do not include raw node response contents (`Result`/`Error` bytes) in user-facing error messages or `Data`. Replace the verbose `nodeResponses` string with a generic, non-sensitive summary (e.g., counts of responses received/expected, node identifiers only, without their payload), mirroring the pattern already used safely in `confidentialrelay/handler.go`'s `forwardBundleOrTerminateIfReady`, which logs response payloads server-side via `l.Warnw(...)` but sends only a generic `RequestTimeoutError` with counts to the user (`summary.Signed()`, `minQuorum`, `summary.Total()`, etc., no raw payload bytes). Log full node responses at debug/warn level for operators only; never place them in the JSON-RPC error `Message`/`Data` returned to the caller.

### Proof of Concept
Go unit test plan (extends `core/services/gateway/handlers/vault/handler_test.go` pattern used for `confidentialrelay`):
1. Set up a vault handler with `RequestTimeoutSec` small and a quorum requiring N nodes.
2. Send a `vault.secrets.list` request via `HandleJSONRPCUserMessage`.
3. Simulate one node responding via `HandleNodeMessage` with a `jsonrpc.Response` whose `Result` contains a distinctive marker payload (e.g., `{"secret_marker":"SENTINEL_PAYLOAD_1234"}`), while quorum is never reached (fewer nodes respond than required).
4. Advance the fake clock past `requestTimeout` and call `h.removeExpiredRequests(ctx)`.
5. Capture the callback response, unmarshal the JSON-RPC error, and assert:
   - `resp.ErrorCode == api.RequestTimeoutError`
   - `!strings.Contains(jsonResp.Error.Message, "SENTINEL_PAYLOAD_1234")`
   - `jsonResp.Error.Data` does not contain `"SENTINEL_PAYLOAD_1234"`
   - Only a generic message/counts (e.g., "request expired, N/M nodes responded") is present.

This test currently fails against the existing code because `nodeResponsesStr` (built from `%v` of `nodeResponse`) embeds `SENTINEL_PAYLOAD_1234` directly into both `Message` and `Data`.

func (ar *activeRequest) copiedResponses() map[string]jsonrpc.Response[json.RawMessage] {
	ar.mu.Lock()
	defer ar.mu.Unlock()
	copied := make(map[string]jsonrpc.Response[json.RawMessage], len(ar.responses))
	for k, response := range ar.responses {
		var copiedResponse jsonrpc.Response[json.RawMessage]
		if response != nil {
			copiedResponse = *response
			if response.Result != nil {
				copiedResult := *response.Result
				copiedResponse.Result = &copiedResult
			}
			if response.Error != nil {
				copiedError := *response.Error
				copiedResponse.Error = &copiedError
			}
		}
		copied[k] = copiedResponse
	}
	return copied
}

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}
