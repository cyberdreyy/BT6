### Title
DstEscrow parameters length can be crafted to permanently revert withdraw/publicWithdraw, freezing maker's payout until cancellation - (File: contracts/EscrowDst.sol, contracts/libraries/ImmutablesLib.sol)

### Summary
`createDstEscrow` in `BaseEscrowFactory.sol` is a fully permissionless entrypoint that accepts an arbitrary `Immutables.parameters` byte blob with no length or content validation beyond the native-value funding check [1](#0-0) . `EscrowDst._withdraw` unconditionally decodes fee fields out of this blob using `ImmutablesLib`'s `*Cd` helpers, which each enforce their own minimum-length threshold independently rather than validating the whole structure up front [2](#0-1) . A `parameters` blob of exactly 64 bytes with a non-zero second word (decoded as `integratorFeeAmount`) passes the `0x20`/`0x40` length checks for `protocolFeeAmountCd`/`integratorFeeAmountCd`, but then unconditionally triggers `integratorFeeRecipientCd()`, which requires `parameters.length >= 0x80` and reverts with `IndexOutOfRange` [3](#0-2) .

### Finding Description
Both `withdraw()` (private, taker-only) and `publicWithdraw()` (public, access-token holder) call the same internal `_withdraw()` function, so this revert is unconditional and unavoidable regardless of caller or timelock stage once the escrow is deployed with such a `parameters` blob [4](#0-3) . The escrow's immutables (including `parameters`) are locked in at creation via the CREATE2 salt/hash [5](#0-4) , and `onlyValidImmutables` forces every subsequent call to pass the identical (malformed) `parameters`, so there is no way to "fix" the data after deployment. Because `createDstEscrow` has no whitelist/access-control check on the caller [1](#0-0) , any unprivileged actor acting as taker can deploy such a broken destination escrow, funding it with the correct native/ERC20 amount and safety deposit, and nominate any maker address. Once deployed, even the public withdrawal path fails on fee decoding despite a valid secret, violating the intended invariant that a funded escrow with a known secret should remain withdrawable in the public phase.

### Impact Explanation
Funds locked in the escrow (the destination-side amount + safety deposit) become unwithdrawable by anyone via `withdraw`/`publicWithdraw` from `DstWithdrawal` through `DstCancellation`. This matches "Temporary freezing of funds during the live swap lifecycle" (High). It does not escalate to permanent freezing/insolvency because `cancel()` and `rescueFunds()` never touch the `parameters` fee fields and remain callable by the taker after the cancellation/rescue timelocks [6](#0-5) [7](#0-6) , so the deposited amount is eventually recoverable by the taker — but the maker never receives their intended payout on the destination chain during the whole withdrawal window, which is the freezing impact.

### Likelihood Explanation
`createDstEscrow` is a live, unprivileged, in-scope entrypoint with no validation of `parameters` shape/length beyond the native funding check. Constructing a 64-byte `parameters` blob with a non-zero second word is trivial and requires no special privileges — only that the actor supplies the correct native/ERC20 funding, which they must do regardless as part of normal dst-escrow creation.

### Recommendation
In `BaseEscrowFactory.createDstEscrow`, validate that `dstImmutables.parameters` is either empty or exactly the expected fixed length (`0x80` bytes) before deploying the clone. Alternatively, in `ImmutablesLib`, replace the per-field minimum-length checks with a single upfront check that `parameters.length == 0 || parameters.length == 0x80` so malformed intermediate lengths cannot pass partial checks and later cause an unconditional revert in `_withdraw`.

### Proof of Concept
1. Attacker calls `createDstEscrow` with `dstImmutables.parameters = abi.encode(protocolFeeAmount, integratorFeeAmount)` (64 bytes) where `integratorFeeAmount > 0`, `token = address(0)` (native), and provides `msg.value = amount + safetyDeposit`.
2. Escrow deploys successfully; `_validateImmutables`/CREATE2 checks pass since salt matches.
3. Warp past `DstWithdrawal`; call `withdraw(secret, immutables)` from the taker — reverts with `ImmutablesLib.IndexOutOfRange` inside `integratorFeeRecipientCd()`.
4. Warp past `DstPublicWithdrawal`; call `publicWithdraw(secret, immutables)` from any access-token holder — same revert occurs, confirming the public path is also bricked.
5. Only after `DstCancellation`, taker calls `cancel(immutables)`, which succeeds and returns the deposited amount + safety deposit to the taker — confirming funds were frozen (not lost) for the entire withdrawal window, and the maker never received their destination payout.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }

    function hash(IBaseEscrow.Immutables calldata immutables) internal pure returns(bytes32 ret) {
        // Compute the EIP-712 hash for the immutables struct
        bytes calldata parameters = immutables.parameters;
        assembly ("memory-safe") {
            let ptr := mload(0x40)

            // Copy immutables.parameters to memory and compute its hash
            calldatacopy(ptr, parameters.offset, parameters.length)
            let parametersHash := keccak256(ptr, parameters.length)

            // Copy the immutables struct to memory, patch `parameters` and compute its hash
            calldatacopy(ptr, immutables, IMMUTABLES_SIZE)
            mstore(add(ptr, IMMUTABLES_LAST_WORD), parametersHash)
            ret := keccak256(ptr, IMMUTABLES_SIZE)
        }
    }
