### Title
`depositDuringEpoch` bypasses the `whenNotPaused` deposit freeze — ([File: contracts/IdleCDOEpochVariant.sol](contracts/IdleCDOEpochVariant.sol))

### Summary
`IdleCDO` and `IdleCDOEpochVariant` block deposits when paused via `whenNotPaused` on `_deposit` (`IdleCDO.sol`, overridden at `IdleCDOEpochVariant.sol:644`). However, the epoch-variant's second deposit entry point, `depositDuringEpoch` (`IdleCDOEpochVariant.sol:656`), has no `whenNotPaused` modifier and does not check `paused()`. A plain `pause()` by owner/guardian — which does not set `skipDefaultCheck` or clear `isEpochRunning` — therefore fails to stop deposits during a running epoch.

### Finding Description
The pause model in the codebase splits controls:
- Deposits: gated by `whenNotPaused` on `_deposit` (`IdleCDOEpochVariant.sol:644`).
- Withdrawals: gated by `allowAAWithdrawRequest`/`allowBBWithdrawRequest` flags (`requestWithdraw`, line 741–744).

`depositDuringEpoch` (`IdleCDOEpochVariant.sol:656–733`) is gated by a flag list — `isBBDepositEnabled`, `isDepositDuringEpochDisabled`, `skipDefaultCheck`, `isProgrammableBorrower`, `isAYSActive`, `isEpochRunning`, `epochEndDate`, `isWalletAllowed` — but `paused()` is absent.

`_emergencyShutdown` (line 602–615) does set `skipDefaultCheck = true`, which coincidentally blocks `depositDuringEpoch`, and `_handleBorrowerDefault` clears `isEpochRunning`. But `pause()`/`unpause()` are exposed independently (`IdleCDO.sol:968–978`), and `restoreOperations` (line 619–632) explicitly contemplates a state where the contract is unpaused but `isEpochRunning` is true ("During an epoch ordinary deposits and withdrawal requests must remain disabled"). If the owner or guardian calls `pause()` during a running epoch — the standard emergency brake for an in-progress incident that is not yet a confirmed default — `deposit()` reverts via `whenNotPaused`, while `depositDuringEpoch` succeeds: it skims donations, calls `_updateAccounting`, pulls underlying from the caller, mints tranche shares at the discounted mid-epoch price, mints strategy tokens via `mintStrategyTokens`, and forwards the full `_amount` of underlyings directly to the borrower (lines 684–732).

### Impact Explanation
The pause is the emergency brake intended to freeze state changes while a suspected incident (mispriced accounting, compromised strategy, borrower repayment risk) is investigated. Bypassing it lets any KYC'd wallet continue pushing underlyings to the borrower and minting tranche shares at the discounted `expectedFinal` price while the system is meant to be frozen. If the pause was triggered because borrower repayment is at risk, the deposited underlyings are forwarded to the borrower and lost in the subsequent default — a direct loss equal to the deposited amount, while honest depositors were correctly blocked. It also allows minting shares against accounting state the operator was trying to freeze.

### Likelihood Explanation
Requires `pause()` (not `emergencyShutdown`) to be invoked during a running epoch — a realistic sequence, since `pause()` is the lighter, reversible guardian action distinct from the heavier `emergencyShutdown`. Attacker only needs to be a KYC-passing lender, which the threat model permits. The bypass window is the remainder of the epoch plus until `epochEndDate`.

### Recommendation
Add `whenNotPaused` to `depositDuringEpoch` (or an explicit `_checkNotAllowed(paused())` in its guard list) so that all deposit paths are uniformly blocked by the pause mechanism.

### Proof of Concept
```solidity
// Foundry fork test against IdleCDOEpochVariant deployment
// Preconditions: epoch running (isEpochRunning == true), attacker is KYC'd,
// BB/AA tranche supply > 0, depositDuringEpoch not otherwise disabled.

function test_pauseBypass_depositDuringEpoch() public {
    // 1. Guardian/owner pauses during a running epoch (incident response)
    vm.prank(guardian);
    cdo.pause();
    assertTrue(cdo.paused());

    // 2. Normal deposit path is blocked
    vm.prank(attacker);
    vm.expectRevert(); // whenNotPaused
    cdo.depositAA(1000e6);

    // 3. BUG: depositDuringEpoch succeeds while paused
    deal(underlying, attacker, 1000e6);
    vm.startPrank(attacker);
    IERC20(underlying).approve(address(cdo), 1000e6);
    uint256 minted = cdo.depositDuringEpoch(1000e6, cdo.AATranche());
    vm.stopPrank();

    assertGt(minted, 0);                                  // shares minted
    assertEq(IERC20(underlying).balanceOf(borrower), 1000e6); // funds sent to borrower
}
```
