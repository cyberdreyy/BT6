### Title
Nitro attestation `AttestationVerifier::verify` accepts CBOR payloads with duplicate/ambiguous map keys, letting a signed-but-forged field value bypass content validation - (File: crates/proof/tee/nitro-verifier/src/verify.rs)

### Summary
`AttestationVerifier::verify` is the canonical, "end-to-end" Nitro attestation verification entry point used by the ZK/TEE proving journal construction path [1](#0-0) . It parses the CBOR `COSE_Sign1` payload via `ciborium`/`serde` into a `BTreeMap`-backed `AttestationDocument` and then runs `validate_attestation_content` purely against the *deserialized* structure [2](#0-1) [3](#0-2) . Unlike the sibling `registrar` crate, this path never runs the raw byte-level `NitroCose::validate_payload_structure` duplicate-key/duplicate-PCR check before trusting the decoded document — a limitation the code's own doc-comment acknowledges: *"PCR duplicate detection requires a raw CBOR walk (maps collapse duplicates); callers that need that should validate the payload bytes separately."* [4](#0-3) . This is the same bug class as CVE-2025-29774: the cryptographic signature covers the full raw byte stream (including any duplicated CBOR map keys/nodes), but the structure that is actually validated and used downstream is the "collapsed" one produced by naive deserialization — allowing an attacker to smuggle a second, differently-interpreted value under the same signature.

### Finding Description
`CoseSign1::from_bytes` and `AttestationReport::parse` decode the COSE envelope and the payload with `ciborium::de::from_reader` directly into a `serde`-derived `AttestationDocument` struct that contains a `BTreeMap<u64, ByteArray<48>>` for `pcrs` and plain fields (`module_id`, `digest`, `certificate`, `cabundle`, `public_key`, `user_data`, `nonce`) [5](#0-4) . CBOR maps permit duplicate keys at the wire level; standard `serde`/`ciborium` map deserialization silently resolves duplicates (last-value-wins for `BTreeMap::insert`, and for scalar struct fields, subsequent occurrences generally overwrite earlier ones), without erroring. The full raw byte string (with the duplicated keys still present) is exactly what's signed and verified in step 4 of `AttestationVerifier::verify` (`verify_cose_signature` over `sig_structure()`, which embeds `self.payload` verbatim) [6](#0-5) [7](#0-6) .

The registrar/planner crate is explicitly aware of this exact hazard and mitigates it by first walking the raw CBOR bytes with `NitroCose::validate_payload_structure`, which detects duplicate top-level keys and duplicate PCR indices and rejects them before decoding [8](#0-7) [9](#0-8) . But `AttestationVerifier::verify` in `crates/proof/tee/nitro-verifier/src/verify.rs` — the path documented as the "end-to-end" verifier for the on-chain `INitroEnclaveVerifier` journal — does not call this raw-walk check at all; it only calls `validate_attestation_content` on the already-collapsed `doc` [10](#0-9) . This is structurally identical to the xml-crypto flaw: a document that is cryptographically valid because the signature covers the raw bytes verbatim, but whose *effective, checked content* is chosen by whichever de-duplication rule the parser happens to apply — enabling an attacker who controls the enclave-attestation bytes (or any consumer feeding attacker-influenced attestation bytes into this verifier) to embed a duplicate `pcrs`/`certificate`/`cabundle`/`module_id` entry that satisfies `validate_attestation_content`, while a different actual value for that field exists in the same signed blob.

### Impact Explanation
`VerifierJournal` produced by `AttestationVerifier::verify` (PCR measurements, certificate hashes, module id, public key) is the trust anchor used to admit a TEE/Nitro enclave as an authorized prover into Base's fault-proof / TEE-proving system (feeding `CertManager`/prover-registrar on-chain state per the Solidity-aligned types in `types.rs` [11](#0-10) ). If duplicate-key ambiguity lets an attacker present PCR measurements or a module identity that pass validation while the enclave's real measured state differs, this can lead to acceptance of an unauthorized/forged enclave identity as a legitimate prover — i.e., wrong provable output roots or acceptance of proofs from an enclave that doesn't match the trusted measurement, undermining the integrity of the TEE proving/dispute pipeline.

### Likelihood Explanation
Exploitability depends on whether `AttestationVerifier::verify` (rather than `AttestationPlanner::prepare_registration_plan`, which does have the mitigation) is reached with attacker-influenced attestation bytes in a production registration/verification flow. I was not able to conclusively confirm from the indexed code whether the on-chain/host registration flow always routes through `AttestationPlanner::prepare_registration_plan` (safe) or whether any code path calls `AttestationVerifier::verify` directly on unauthenticated attestation input without the registrar's `validate_payload_structure` pre-check. Given the doc-comment explicitly flags this as a known gap ("callers that need that should validate the payload bytes separately"), the risk is real but its concrete reachability by an anonymous caller could not be fully verified with the available index — this should be checked directly in the repository (particularly any RPC/host code that calls `AttestationVerifier::verify` for on-chain journal construction, ZK guest programs under `crates/proof/zk`, or `bin/prover-registrar`).

### Recommendation
Make `AttestationVerifier::verify` (and any other production call site that treats the deserialized `AttestationDocument` as ground truth) perform the same raw-CBOR duplicate-key/duplicate-PCR structural check (`NitroCose::validate_payload_structure` or equivalent) before or as part of `validate_attestation_content`, rather than relying on callers to opt in. Alternatively, replace the serde/ciborium generic-map deserialization with a strict decoder that rejects duplicate keys by construction, so that the byte-level document that is signed and the structure that is validated can never diverge.

### Proof of Concept
Not independently constructed against a running verifier binary. The `registrar` crate's own tests demonstrate the underlying primitive: a payload map `{"pcrs": {0: h'00'}, "pcrs": {0: h'00'}}` (duplicate top-level `"pcrs"` key) or `{"pcrs": {0: h'00', 0: h'00'}}` (duplicate PCR index) is rejected by `NitroCose::validate_payload_structure` [12](#0-11) , confirming such payloads are well-formed enough to reach `ciborium::de::from_reader`/serde deserialization (which collapses the duplicates) and thus would be silently accepted — and their signature validated — by `AttestationVerifier::verify`, which lacks this raw-walk guard.

    ///
    /// 1. Parses the `COSE_Sign1` envelope and attestation document
    /// 2. Validates attestation content (M-02 checks)
    /// 3. Verifies the x509 certificate chain (M-01 checks)

            chain.verify_chain(trusted_prefix_len, report.doc.timestamp)?;

    /// Constructs the CBOR-encoded `Sig_structure` for signature verification.
    ///
    /// Per RFC 8152 Section 4.4, the `Sig_structure` for `COSE_Sign1` is:
    /// `["Signature1", body_protected, external_aad, payload]`
    ///
    /// This is the to-be-signed (TBS) data that the signature covers.
    pub fn sig_structure(&self) -> Result<Vec<u8>> {
        let structure = CborValue::Array(vec![
            CborValue::Text("Signature1".to_string()),
            CborValue::Bytes(self.protected.clone()),
            CborValue::Bytes(vec![]), // external_aad — empty
            CborValue::Bytes(self.payload.clone()),
        ]);

        let mut buf = Vec::with_capacity(20 + self.protected.len() + self.payload.len());
        ciborium::ser::into_writer(&structure, &mut buf)
            .map_err(|e| VerifierError::Cbor(format!("sig_structure encode: {e}")))?;
        Ok(buf)
    }

/// A parsed Nitro attestation report combining the COSE envelope and document.
#[derive(Debug)]
pub struct AttestationReport {
    /// The `COSE_Sign1` envelope (for signature verification).
    pub cose: CoseSign1,
    /// The parsed attestation document from the COSE payload.
    pub doc: AttestationDocument,
}

impl AttestationReport {
    /// Parses a raw Nitro attestation report (`COSE_Sign1` bytes).
    ///
    /// Extracts the `COSE_Sign1` envelope and deserializes the CBOR payload
    /// into an `AttestationDocument`.
    pub fn parse(data: &[u8]) -> Result<Self> {
        let cose = CoseSign1::from_bytes(data)?;
        let doc: AttestationDocument =
            ciborium::de::from_reader(cose.payload.as_slice()).map_err(|e| {
                VerifierError::AttestationFormat(format!("attestation document decode: {e}"))
            })?;
        Ok(Self { cose, doc })
    }

    /// Validates payload CBOR structure: no trailing bytes, PCR duplicate/index rules, cabundle
    /// limits.
    pub fn validate_payload_structure(payload: &[u8]) -> PlannerResult<()> {
        let root =
            CborItem::read(payload, 0)?.require_major(CBOR_MAJOR_MAP, "attestation payload")?;
        if root.end != payload.len() {
            return Err(PlannerError::Cose("trailing data after attestation payload".into()));
        }

        let mut offset = root.content_start;
        let mut item_count = 0u64;
        let mut seen_keys = BTreeSet::new();
        loop {
            if !root.indefinite && item_count == root.value {
                break;
            }
            if root.indefinite {
                if offset >= payload.len() {
                    return Err(PlannerError::Cose(
                        "indefinite attestation payload map missing break".into(),
                    ));
                }
                if payload[offset] == CBOR_BREAK {
                    break;
                }
            }

            let key = CborItem::read(payload, offset)?
                .require_major(CBOR_MAJOR_TEXT_STRING, "attestation payload key")?;
            let value = CborItem::read(payload, key.end)?;
            let value_end = value.end;
            let key_text = std::str::from_utf8(&payload[key.content_start..key.end])
                .map_err(|_| PlannerError::Cose("attestation payload key is not UTF-8".into()))?;
            if Self::is_known_attestation_key(key_text) && !seen_keys.insert(key_text) {
                return Err(PlannerError::Cose(format!(
                    "duplicate attestation payload key: {key_text}"
                )));
            }

            match key_text {
                "pcrs" => Self::validate_pcrs(payload, value)?,
                "cabundle" => Self::validate_cabundle(payload, value)?,
                "certificate" => {
                    let certificate = value.require_major(CBOR_MAJOR_BYTE_STRING, "certificate")?;
                    let len = certificate.end - certificate.content_start;
                    if len == 0 || len > MAX_CABUNDLE_CERT_BYTES {
                        return Err(PlannerError::Cose(format!(
                            "certificate must be between 1 and {MAX_CABUNDLE_CERT_BYTES} bytes, got {len}"
                        )));
                    }
                }
                _ => {}
            }

            offset = value_end;
            item_count += 1;
        }

        if root.indefinite {
            if offset >= payload.len() || payload[offset] != CBOR_BREAK {
                return Err(PlannerError::Cose(
                    "indefinite attestation payload map missing break".into(),
                ));
            }
        } else if offset != root.end {
            return Err(PlannerError::Cose("attestation payload map length mismatch".into()));
        }

        Ok(())
    }
