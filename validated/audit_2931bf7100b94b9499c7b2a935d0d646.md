## Finding: Beneficiary redirection bypass after `switch_operator` in `staking_contract.move`

The Eco report's core lesson is that a **routing invariant** (destination check) must be enforced at the final settlement point, not just assumed by upstream logic — otherwise value gets delivered to the wrong destination while the internal bookkeeping still marks it as "correctly settled." The Aptos analog is in `aptos_framework::staking_contract`, where a pending commission distribution recorded under an **old operator** silently loses its beneficiary redirection once that operator is switched out, permanently misrouting the payout to the old operator's own address instead of their configured beneficiary.

### Title
Beneficiary redirect for operator commission is bypassed after `switch_operator`, misrouting pending distributions to the old operator instead of their beneficiary - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`distribute_internal` redirects a payout to `beneficiary_for_operator(operator)` only `if (recipient == operator)`, where `operator` is the parameter passed by the *current* caller/context. When `switch_operator` is invoked, it first calls `request_commission_internal(old_operator, ...)` which records a pending distribution-pool share keyed by `old_operator`, and only afterward removes `old_operator` from the `Store` and inserts `new_operator`. Any future `distribute()` call can now only be made by passing `new_operator` (since `old_operator` no longer exists in the map), so the equality check `recipient == operator` (i.e. `old_operator == new_operator`) is always false for that pending share, and the funds are deposited directly to `old_operator`'s own address instead of `beneficiary_for_operator(old_operator)`.

### Finding Description [1](#0-0) 

`switch_operator` performs, in order:
1. `distribute_internal(staker_address, old_operator, &mut staking_contract)` — this correctly distributes *already inactive* stake, honoring `old_operator`'s beneficiary because `operator == old_operator` at this call site.
2. `request_commission_internal(old_operator, &mut staking_contract)` — this unlocks the not-yet-inactive commission and calls `add_distribution(operator=old_operator, ..., recipient=old_operator, commission_amount)`, which buys shares for shareholder key `old_operator` in `staking_contract.distribution_pool`: [2](#0-1) 

3. Only after that does it call `staking_contracts.remove(&old_operator)` conceptually (actually removed earlier at line 783) and `staking_contracts.add(new_operator, staking_contract)`, so the `Store` map key for this pool becomes `new_operator` from now on.

Later, once the commission becomes inactive (lockup expires), anyone can permissionlessly call `distribute(staker, operator)`: [3](#0-2) 

Because `assert_staking_contract_exists(staker, operator)` requires `operator` to be a key currently present in `store.staking_contracts`, the caller is forced to pass `new_operator` — `old_operator` is no longer a valid key. `distribute_internal` is then invoked with `operator = new_operator`: [4](#0-3) 

Inside the loop, the pending shareholder `recipient == old_operator` is compared against the passed-in `operator == new_operator`. Since `old_operator != new_operator`, the `if (recipient == operator)` branch that redirects to `beneficiary_for_operator(operator)` is never taken, and `aptos_account::deposit_coins(recipient, ...)` pays the funds straight to `old_operator`'s own account — completely bypassing whatever beneficiary `old_operator` had configured via `set_beneficiary_for_operator`: [5](#0-4) 

The vesting module's `update_operator` exhibits the identical pattern since it delegates directly to `staking_contract::switch_operator`: [6](#0-5) 

### Impact Explanation
This is a share-accounting/beneficiary-payout corruption that "credits the wrong account" as called out in the required-impact list. An operator who has set up a `beneficiary_for_operator` (e.g., a multisig treasury or a revenue-share partner) to receive their commission can arrange (or a staker can unilaterally cause, since `switch_operator` is staker-controlled) an operator switch immediately after `request_commission`/`switch_operator` triggers `request_commission_internal`. The pending, not-yet-inactive commission then permanently loses its beneficiary routing and is paid to the old operator's raw account address once it becomes withdrawable — regardless of who calls the now-permissionless `distribute()`. This diverts funds away from the intended beneficiary with no way to recover the correct routing (the `Store` key for `old_operator` is gone, so `beneficiary_for_operator(old_operator)` can never again be consulted for this specific pending distribution).

### Likelihood Explanation
High. `switch_operator` is a normal, permissionless-to-the-staker entry function; no privileged/governance access is needed. The bug triggers deterministically any time a staker switches operators while a commission request is in flight (which `switch_operator` itself always creates via `request_commission_internal`) — this is not an edge case, it happens on essentially every operator switch that has non-zero commission accrued at switch time, and the subsequent `distribute()` call is permissionless so anyone (or automation) will trigger the misrouted payout.

### Recommendation
Preserve the beneficiary redirect independent of the current `Store` key. Either:
- Snapshot the correct beneficiary at `add_distribution` time (store `beneficiary_for_operator(operator)` as the distribution's actual shareholder instead of the raw operator address), or
- When redistributing, resolve `beneficiary_for_operator(recipient)` for every recipient found in the distribution pool (not just when `recipient == operator`), so that any left-over distribution keyed to a stale/old operator address still redirects to that address's configured beneficiary.

### Proof of Concept
1. Staker creates a staking contract with `operator1`, commission % > 0.
2. `operator1` calls `set_beneficiary_for_operator(operator1, beneficiary1)`.
3. Stake pool earns rewards.
4. Staker calls `switch_operator(staker, operator1, operator2, new_commission_pct)`. This internally calls `request_commission_internal(operator1, ...)`, adding a distribution-pool share for `operator1` for the freshly unlocked (but still pending-inactive) commission, then re-keys the `Store` to `operator2`.
5. Wait for lockup to expire so the unlocked commission becomes fully inactive/withdrawable.
6. Anyone calls `distribute(staker, operator2)` (the only valid key now). `distribute_internal` runs with `operator = operator2`; the stored recipient is `operator1`; `recipient == operator` is false, so `aptos_account::deposit_coins(operator1, amount)` executes.
7. Result: `beneficiary1` receives nothing from this distribution; `operator1` receives the commission directly at their own address, defeating the beneficiary configuration set in step 2.

    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    /// Allows an operator to change its beneficiary. Any existing unpaid commission rewards will be paid to the new
    /// beneficiary. To ensures payment to the current beneficiary, one should first call `distribute` before switching
    /// the beneficiary. An operator can set one beneficiary for staking contract pools, not a separate one for each pool.
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
