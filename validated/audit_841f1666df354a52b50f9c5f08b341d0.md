### Title
Missing Chainlink min/max bound check allows incorrect USD0++ price to corrupt epoch loss socialization - (`contracts/strategies/usual/IdleUsualStrategy.sol:164-172`)

### Summary
`IdleUsualStrategy.getChainlinkPrice()` reads `latestRoundData()` from the USD0++ Chainlink feed and only validates the heartbeat (`updatedAt > block.timestamp - 24 hours`). It never compares `answer` against the aggregator's min/max circuit-breaker bounds. If the market price of USD0++ breaches a bound, Chainlink keeps reporting the bound value (a fresh, non-stale `answer`), so `IdleCDOUsualVariant.stopEpoch()` computes `targetAATVL` from a price that no longer reflects the real market price, misallocating losses between AA (senior) and BB (junior) tranches.

### Finding Description
Two callers consume the unchecked price:

- `IdleCDOUsualVariant.startEpoch()` stores `priceAtStartEpoch` from `getChainlinkPrice()` for reference.
- `IdleCDOUsualVariant.stopEpoch()` calls `getChainlinkPrice()`, pushes it into `setOraclePrice()`, and if `_oraclePrice < 1` computes `targetAATVL = lastNAVAA * oneToken / _oraclePrice` and inflates `lastNAVAA`, so the following `_updateAccounting()` books a "loss" absorbed by the junior tranche to restore seniors to $1 parity [1](#0-0) .

`getChainlinkPrice()` validates only freshness, not sanity:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
return uint256(answer) * 1e10;
``` [2](#0-1) 

Failure modes when the answer is at or past a bound:

1. `answer` pinned at the aggregator min bound while the real price is lower → `_oraclePrice` is too high → `targetAATVL` is too low → seniors are under-collateralized below the promised $1 parity, or juniors are over-drained when the bound is above the true price in the other direction. In the extreme, `targetAATVL - lastNAVAA` exceeds the whole junior NAV plus yield, wiping out BB holders and leaving residual bad debt the vault cannot cover — a solvency/waterfall invariant break.
2. `answer <= 0` (impossible market value or malformed round within heartbeat) → `uint256(answer)` overflows on the cast and `stopEpoch()` reverts permanently → epoch can never be stopped → all tranche holder funds are permanently frozen in the strategy.

`setOraclePrice()` only clamps to the USD0++ `getFloorPrice()` and cannot detect the bound condition [3](#0-2) .

### Impact Explanation
Broken invariants: loss waterfall fairness and solvency. If the price feed reports a bound value while the true USD0++ price is worse, the junior tranche either loses more NAV than the true depeg requires (direct theft-like redistribution to seniors) or the vault books an impossible target, draining BB entirely and still leaving seniors below $1 parity — i.e., junior holders absorb unbounded losses and part of the senior shortfall becomes unrecoverable bad debt. A non-positive `answer` makes `stopEpoch()` uncallable, permanently freezing 100% of TVL since deposits/redeems stay paused and `allowAAWithdraw/allowBBWithdraw` remain false [4](#0-3) .

### Likelihood Explanation
The trigger requires the USD0++ feed to reach its Chainlink min/max bound or return a non-positive answer within the heartbeat — a tail-risk market event rather than something an unprivileged attacker can force directly. However, USD0++ is exactly the asset this vault exists to depeg-protect, so the bound-hit scenario coincides with the vault's designed stress case: the oracle is most likely to be wrong precisely when the protection matters most. No privileged misbehavior is needed; the honest owner calls `stopEpoch()` and the corrupted price is consumed automatically.

### Recommendation
In `getChainlinkPrice()`, read the aggregator's `minAnswer`/`maxAnswer` (via the proxy's `aggregator()` → `AccessControllerOffchainAggregator` interface) and revert or fall back when the answer is at/outside a bound; also reject `answer <= 0`:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
require(answer > 0, "Invalid price");
// fetch min/max from the underlying aggregator and revert if at a bound
if (uint256(answer) <= minPrice || uint256(answer) >= maxPrice) revert PriceBorderReached();
```

Alternatively, have `stopEpoch()` accept a human-supplied price sanity range or require an explicit owner override when the oracle reports a bound value, so the epoch can still be stopped without corrupting the waterfall.

### Proof of Concept
Foundry fork-style test on the Usual variant suite (extend `test/foundry/IdleUsualStrategy.t.sol`). The oracle address `USD0ppOracle` is a constant, so mock it with `vm.mockCall`/`vm.etch`:

```solidity
function testStopEpochOracleAtMinBound() external {
    uint256 amount = 10000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);

    IdleCDOUsualVariant _cdo = IdleCDOUsualVariant(address(idleCDO));
    vm.prank(owner);
    _cdo.startEpoch(100);
    vm.warp(block.timestamp + 100);

    // Simulate Chainlink reporting the aggregator's min bound (e.g. 0.5 USD,
    // 8 decimals) while the real USD0++ market price is lower (e.g. 0.2 USD).
    int256 minBound = 5e7; // $0.50 in 8 decimals
    vm.mockCall(
        0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB,
        abi.encodeWithSelector(IOracle.latestRoundData.selector),
        abi.encode(uint80(1), minBound, block.timestamp, block.timestamp, uint80(1))
    );

    vm.prank(owner);
    _cdo.stopEpoch();

    // targetAATVL computed with 0.50 instead of the real 0.20:
    // seniors are credited 2x the tokens needed for true $1 parity,
    // draining junior NAV beyond the real depeg loss.
    uint256 inflatedTarget = amount * ONE_SCALE / (uint256(minBound) * 1e10);
    assertEq(_cdo.lastNAVAA(), inflatedTarget);
    // junior NAV slashed by (inflatedTarget - amount) — with real price 0.20 the
    // correct slash is only (amount*5 - amount); the delta is direct loss to BB.
}

function testStopEpochRevertsOnNonPositiveAnswer() external {
    // ... same setup, then:
    vm.mockCall(
        0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB,
        abi.encodeWithSelector(IOracle.latestRoundData.selector),
        abi.encode(uint80(1), int256(0), block.timestamp, block.timestamp, uint80(1))
    );
    vm.prank(owner);
    vm.expectRevert(); // uint256(0) passes but any negative answer overflows the cast
    IdleCDOUsualVariant(address(idleCDO)).stopEpoch();
    // with answer = -1 the cast in `uint256(answer) * 1e10` reverts ->
    // epoch unstoppable, all funds frozen.
}
```

The first PoC shows juniors absorbing a loss larger than the true depeg (loss waterfall break, quantified by `inflatedTarget - amount` vs the correct value); the second shows permanent freezing of all deposits when `answer <= 0`.
