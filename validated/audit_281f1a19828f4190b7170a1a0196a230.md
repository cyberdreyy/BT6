### Title
Unprivileged APR manipulation while `idleCDO` is unset - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary

`IdleCreditVault.setApr()` skips its caller verification whenever `idleCDO == address(0)`, allowing any EOA to set both `unscaledApr` and `lastApr` through `setAprs()` during the deployment gap before the strategy is bound to its CDO. [1](#0-0) 

If the CDO is initialized after this manipulation, `_additionalInit()` reads the attacker-controlled strategy APR and rescales it for the configured epoch and buffer durations. [2](#0-1) 

### Finding Description

The intended authorization rule permits only the bound CDO or the manager to update the APR. [3](#0-2) 

That check is completely bypassed during setup because `setApr()` does not authenticate `msg.sender` when `idleCDO` has not yet been configured. [3](#0-2) 

`setAprs()` also lets the caller independently control `unscaledApr`, which is later used for instant-withdrawal APR comparisons, while `setApr()` controls the interest-bearing `lastApr`. [4](#0-3) 

The CDO propagates the poisoned APR into epoch accounting and `startEpoch()` uses it to calculate `expectedEpochInterest` against the entire pool TVL. [5](#0-4) 

At `stopEpoch`, the borrower is asked to fund that expected interest together with pending withdrawals. [6](#0-5) 

### Impact Explanation

An unprivileged attacker or KYC-passing lender can poison the strategy APR before the honest owner or manager completes CDO binding and starts the first epoch. [3](#0-2) 

The maximum `lastApr` is bounded by `maxApr`, whose default is `20e18`, so the attacker can make the borrower pay up to approximately `20% * 30/365 = 1.64%` of first-epoch TVL as inflated interest. [7](#0-6) 

If the attacker is the sole or dominant lender, this amount is directly extracted from the honest borrower and then claimable through the normal tranche withdrawal flow. [8](#0-7) 

For example, with a \$1 million first deposit and an intended 0% lender APR, the attacker can force approximately \$16,438 of unauthorized borrower interest in the first epoch, subject to token decimals and rounding. [9](#0-8) 

The broken invariant is privileged APR control: an economic parameter requiring CDO-or-manager authorization becomes attacker-controlled solely because the CDO binding has not yet been initialized. [3](#0-2) 

### Likelihood Explanation

The attack requires a deployment-order window: `IdleCreditVault.initialize()` must have executed, `idleCDO` must still be zero, and the attacker must transact before the honest owner binds the CDO or corrects the APR. [10](#0-9) 

This is not exploitable on an already linked production vault because subsequent calls authenticate against `idleCDO` or `manager`. [3](#0-2) 

The likelihood is therefore deployment-process dependent rather than universally reachable, but it is realistic where strategy deployment, CDO initialization, and CDO binding are performed in separate transactions or scripts. [11](#0-10) 

Existing KYC controls do not mitigate the issue because `setAprs()` and `setApr()` do not call `isWalletAllowed()`, and the stolen yield can later be realized by a KYC-passing tranche holder. [12](#0-11) 

### Recommendation

Remove the unauthenticated setup exception and require `msg.sender == manager` or `msg.sender == owner()` whenever `idleCDO == address(0)`. [3](#0-2) 

A stronger fix is to bind `idleCDO` atomically during strategy initialization or CDO deployment so no block exists in which APR mutation is unauthenticated. [10](#0-9) 

If initializer ordering requires the CDO itself to seed APR while `idleCDO` is still unset, restrict that path to an explicit one-time `initializeAprs()` call that can only be executed by the strategy owner or manager. [13](#0-12)

```solidity
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract UnauthorizedAprSetupPoC is Test {
    uint256 internal constant FULL_ALLOC = 100_000;
    uint256 internal constant MAX_APR = 20e18;

    IdleCreditVault strategy;
    IdleCDOEpochVariant cdo;
    IERC20Detailed underlying;

    address owner = address(0x100);
    address manager = address(0x200);
    address borrower = address(0x300);
    address attacker = address(0x400);

    function test_AttackerPoisonsAprBeforeCdoBinding() external {
        // Deploy or fork-initialize an IdleCreditVault proxy whose CDO binding is still unset.
        // Representative initializer:
        //
        // strategy.initialize(
        //     address(underlying),
        //     owner,
        //     manager,
        //     borrower,
        //     "Borrower",
        //     0
        // );
        //
        // assertEq(strategy.idleCDO(), address(0));

        // The CDO defaults are epochDuration = 30 days and bufferPeriod = 5 days.
        // Seed a value that becomes the maximum scaled APR during CDO initialization:
        // seeded * (30 days + 5 days) / 30 days == 20e18.
        uint256 seededScaledApr = MAX_APR * 30 days / 35 days;

        vm.prank(attacker);
        strategy.setAprs(MAX_APR, seededScaledApr);

        assertEq(strategy.unscaledApr(), MAX_APR);
        assertEq(strategy.lastApr(), seededScaledApr);

        // Honest owner completes deployment and initializes the CDO with this strategy.
        // During IdleCDOEpochVariant._additionalInit(), _setScaledApr(_getStrategyApr())
        // applies the 35/30 scaling and leaves strategy.lastApr() at MAX_APR.
        //
        // cdo.initialize(
        //     limit,
        //     address(underlying),
        //     governanceFund,
        //     owner,
        //     address(0),
        //     address(strategy),
        //     FULL_ALLOC
        // );
        //
        // assertEq(strategy.lastApr(), MAX_APR);

        // If the attacker is the sole lender with TVL = P, the first epoch's expected
        // interest is approximately P * 20% * 30/365 instead of the intended rate.
        // The honest owner then calls startEpoch(), and the honest borrower funds the
        // inflated expectedEpochInterest at stopEpoch().
    }
}
```

The essential unauthorized call is `strategy.setAprs(MAX_APR, seededScaledApr)` while `strategy.idleCDO() == address(0)`. [1](#0-0) 

The seeded value accounts for the CDO's subsequent `30 days + 5 days` scaling so initialization succeeds while leaving `lastApr` at the `20e18` maximum. [14](#0-13)

```text
  /// @notice set both the unscaled APR and APR scaled by epoch plus buffer duration.
  /// @dev only CDO and manager can set the APR through `setApr`.
  /// @param _unscaledApr unscaled APR
  /// @param _duration epoch duration
  /// @param _buffer buffer duration
  function setAprsWithBuffer(uint256 _unscaledApr, uint256 _duration, uint256 _buffer) external {
    unscaledApr = _unscaledApr;
    setApr(_duration == 0 ? _unscaledApr : _unscaledApr * (_duration + _buffer) / _duration);
  }

  /// @notice set the fixed apr
  /// @dev only cdo and manager can set the apr. If manager manually set apr from 
  /// here it will not be scaled to include the buffer period
  function setApr(uint256 _apr) public {
    address _cdo = idleCDO;

    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
```
