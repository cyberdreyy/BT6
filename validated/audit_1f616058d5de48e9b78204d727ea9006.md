### Title
Unauthenticated disclosure of internal LOOP plugin topology and scrape ports via `GET /discovery` - ([File: core/web/router.go])

### Summary
The `/discovery` route registered by `loopRoutes` in `core/web/router.go` is placed directly on the base `api` router group, which only carries a rate limiter and session middleware — no `auth.Authenticate` wrapper is applied. Any unauthenticated caller can hit `GET /discovery` and receive a full JSON enumeration of every registered LOOP plugin's name and its Prometheus scrape target (host:port).

### Finding Description
In `NewRouter`, the base group `api` is created with only `rateLimiter(...)` and `sessions.Sessions(...)` middleware [1](#0-0) . `loopRoutes(app, api)` is called on this unauthenticated group and registers `r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))` with no `auth.Authenticate(...)` middleware at all [2](#0-1) . This is inconsistent with sibling debug/admin surfaces in the same file, e.g. `debugRoutes` explicitly wraps `/debug/vars` with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [3](#0-2) , and all `/v2/*` routes are behind `auth.Authenticate` groups [4](#0-3) .

`discoveryHandler` iterates `l.registry.List()` and, for every registered plugin, emits a Prometheus `targetgroup.Group` containing the scrape address (`discoveryHostName:exposedPromPort`) and a `__meta_plugin_name` label with the plugin's name, plus a metrics path `/plugins/<name>/metrics` [5](#0-4) [6](#0-5) [7](#0-6) . Because the route is registered on the unauthenticated group with no session/token/EI check, any client with zero credentials can retrieve this data with a raw `GET /discovery`.

Note also that the other routes in `loopRoutes` (`/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol`) share the same unauthenticated group, so the enumerated plugin names from `/discovery` can be chained into further unauthenticated requests against those endpoints, compounding the topology-disclosure impact.

### Impact Explanation
An anonymous network client can enumerate all internal LOOP plugin names and their Prometheus scrape host/port without any credential, which is unauthenticated disclosure of internal service topology/configuration. This maps to Chainlink's "Information Disclosure" bounty impact class (sensitive internal infrastructure metadata exposed to an unauthenticated party), rather than a fund-loss or key-disclosure class, since the response contains only plugin names/ports, not secrets or keys.

### Likelihood Explanation
No preconditions beyond network reachability to the node's API port are required — no credential, cookie, or token of any kind. The route is reachable on every request path that has at least one LOOP plugin registered (a normal, common runtime configuration), and the response is fully deterministic and repeatable on every call.

### Recommendation
Wrap `/discovery` (and ideally the other `loopRoutes` endpoints) with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession, auth.AuthenticateByToken)`, matching the pattern used by `debugRoutes`, or move it under a dedicated internal-only listener/network boundary intended for the Prometheus scraper rather than the public node API.

### Proof of Concept
Handler-level integration test using `httptest`:
1. Construct a `chainlink.Application` test double with a `LoopRegistry` containing at least one registered plugin (`plugins.NewTestLoopRegistry` as used in `core/web/loop_registry_internal_test.go`).
2. Build the router via `web.NewRouter(app, nil)`.
3. Issue `httptest.NewRequest("GET", "/discovery", nil)` with no `Authorization` header and no session cookie.
4. Serve via the router and assert:
   - HTTP status is `200 OK`.
   - Response body, when unmarshalled into `[]*targetgroup.Group`, contains a group whose `Labels[LabelMetaPluginName]` equals the test plugin's name and whose `Targets` contains the node's Prometheus port.
5. Compare against `/debug/vars` (or any `/v2/*` route) issued the same way, which should return `401 Unauthorized`, demonstrating the inconsistency and confirming `/discovery` bypasses `auth.Authenticate` entirely.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```

func pluginGroup(hostName string, port int, path string) *targetgroup.Group {
	return &targetgroup.Group{
		Targets: []model.LabelSet{
			// target address will be called by external prometheus
			{model.AddressLabel: model.LabelValue(fmt.Sprintf("%s:%d", hostName, port))},
		},
		Labels: map[model.LabelName]model.LabelValue{
			model.MetricsPathLabel: model.LabelValue(path),
		},
	}
}
```
