### Title
Native ETH sent to `ConvexStrategyETH` is permanently stuck — no withdrawal path exists - (File: `contracts/strategies/convex/ConvexStrategyETH.sol`)

### Summary
`ConvexStrategyETH` declares an unrestricted `receive() external payable` (line 35), so any EOA or contract can send raw ETH to the strategy. The contract's deposit/redeem logic only ever operates on WETH/token balances, and there is no sweep/rescue/ETH-withdrawal function anywhere in `ConvexStrategyETH` or its base `ConvexBaseStrategy`. Any ETH received is therefore locked forever.

### Finding Description
In `ConvexStrategyETH.sol:35`:

```solidity
receive() external payable {}
```

The only place the contract touches native ETH is `_depositInCurve` (`ConvexStrategyETH.sol:23-33`), which first calls `IWETH9(WETH).withdraw(_balance)` — i.e. it *unwraps its own WETH balance* and supplies exactly that amount as `{value: _balance}` to the Curve pool. It never uses `address(this).balance` beyond what the unwrap just produced, and on the way out Curve refunds / redeem proceeds arrive as tokens/WETH, not as spendable ETH.

A grep of the whole `contracts/strategies/convex/` directory shows no `sweep`, `rescue`, arbitrary `call{value:...}`, or owner-restricted ETH withdrawal in `ConvexBaseStrategy` or any subclass — only standard token `transfer`s. Consequently, ETH pushed directly into the contract (e.g. via `selfdestruct`, a mistaken transfer, or a WETH-unwrap sent to the wrong address) can never be recovered: subsequent `_depositInCurve` calls only forward the freshly-unwrapped WETH amount and leave the pre-existing ETH balance untouched.

The sibling `LidoCDOTrancheGateway.receive` is not vulnerable to arbitrary senders since it enforces `require(msg.sender == wethToken)` (`LidoCDOTrancheGateway.sol:99-101`), making `ConvexStrategyETH` the matching surface.

### Impact Explanation
Any ETH balance held by the strategy is permanently frozen — it cannot be deployed into Curve, redeemed, or rescued by the owner. The loss equals the full ETH balance received. In practice this is primarily sender-inflicted loss (mistaken transfers, dust forced via `selfdestruct`), matching the Medium severity of the reference finding.

### Likelihood Explanation
Moderate. Unprivileged users do not normally send ETH to the strategy, but the unrestricted `receive()` (unlike the WETH-gated `LidoCDOTrancheGateway`) means a single mistaken `transfer`/`call{value:}` or a `selfdestruct` donation is enough for funds to be locked forever.

### Recommendation
Restrict `receive()` to only accept ETH from the WETH contract (`require(msg.sender == WETH)`), since `_depositInCurve` is the sole legitimate source of incoming ETH, and/or add an owner-only `sweepETH()` recovery function for already-stuck balances.
