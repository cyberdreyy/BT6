### Title
`internal_withdraw` decrements the ledger before confirming the transfer succeeded, letting a self-inflicted balance debit occur with no reconciliation between recorded balance and actual delivered NEAR - (File: staking-pool/src/internal.rs)

### Summary
The `_safeRewardTransfer` bug class described in the report is: a contract debits/records an amount as transferred without verifying that the amount actually leaving custody matches the amount recorded in the ledger. The closest reachable analog in this repository is `internal_withdraw` in `staking-pool/src/internal.rs`, which decrements `account.unstaked` and `self.last_total_balance` and then fires a bare `Promise::new(account_id).transfer(amount)` with no `.then()` callback to verify success and reconcile state if the transfer fails.

### Finding Description
`internal_withdraw` mutates the account's `unstaked` balance and the contract-wide `last_total_balance` synchronously, then schedules an unrelated, unchecked outgoing `Promise::new(account_id).transfer(amount)`: [1](#0-0) 

This is inconsistent with the pattern used elsewhere in the same codebase family for foundation withdrawals, where the equivalent operation is guarded by a `.then()` callback (`on_withdraw_unvested_amount`) that checks `is_promise_success()` and restores the pre-withdrawal state if the transfer failed: [2](#0-1) [3](#0-2) 

In `internal_withdraw`, if the outgoing `transfer` receipt fails for any reason after the ledger has already been decremented (e.g. due to gas exhaustion for the transfer action or the destination account being removed in the same block), the recorded `unstaked` balance and `last_total_balance` are never restored, since there is no callback observing `is_promise_success()`. The claim in the ledger (`last_total_balance`, `account.unstaked`) can then diverge from the NEAR actually held/delivered by the contract, exactly the equality the original report calls out: *recorded claim == value delivered* is not being enforced.

### Impact Explanation
If the transfer promise silently fails after the ledger already reflects the withdrawal as completed, the delegator's recorded balance is permanently reduced without the NEAR having left the contract to reach them — this is a divergence between the contract's internal accounting (`last_total_balance`, `account.unstaked`) and the NEAR actually held/delivered, matching the High-impact class "an accounting value diverging from reality where another party settles on it."

### Likelihood Explanation
Likelihood is low, similar to the original report's Likelihood: 1. A plain `Promise::new(account_id).transfer(amount)` to a live, existing account (the caller's own account) essentially never fails under normal conditions, so this requires an unusual failure mode of the destination receipt to actually manifest.

### Recommendation
Add a `.then()` callback to `internal_withdraw`'s transfer promise (mirroring `on_withdraw_unvested_amount` in `lockup/src/foundation_callbacks.rs`) that checks `is_promise_success()` and restores `account.unstaked` and `self.last_total_balance` if the transfer failed, so the recorded ledger state always matches actually-delivered NEAR.

### Proof of Concept
Not independently reproducible with available tooling/index access — the failure path depends on an outgoing `Promise::transfer` receipt failing after state mutation, which cannot be forced under normal contract usage; this is presented as a structural/code-review finding based on the asymmetry with `lockup/src/foundation.rs`'s guarded withdrawal pattern rather than a demonstrated exploit.

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }

    /// Called after the foundation tried to withdraw the terminated unvested balance.
    pub fn on_withdraw_unvested_amount(
        &mut self,
        amount: WrappedBalance,
        receiver_id: AccountId,
    ) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        if withdraw_succeeded {
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} succeeded.",
                    amount.0, receiver_id
                )
                    .as_bytes(),
            );
            // Decreasing lockup amount after withdrawal.
            self.lockup_information.termination_withdrawn_tokens += amount.0;
            let unvested_amount = self.get_terminated_unvested_balance().0;
            if unvested_amount > amount.0 {
                // There is still unvested balance remaining.
                let remaining_balance = unvested_amount - amount.0;
                self.vesting_information =
                    VestingInformation::Terminating(TerminationInformation {
                        unvested_amount: remaining_balance.into(),
                        status: TerminationStatus::ReadyToWithdraw,
                    });
                env::log(
                    format!(
                        "Termination Step: There is still terminated unvested balance of {} remaining to be withdrawn",
                        remaining_balance
                    )
                        .as_bytes(),
                );
                if self.get_account_balance().0 == 0 {
                    env::log(b"The withdrawal is completed: no more balance can be withdrawn in a future call");
                }
            } else {
                self.foundation_account_id = None;
                self.vesting_information = VestingInformation::None;
                env::log(b"Vesting schedule termination and withdrawal are completed");
            }
        } else {
            self.set_termination_status(TerminationStatus::ReadyToWithdraw);
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} failed",
                    amount.0, receiver_id,
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
    }
