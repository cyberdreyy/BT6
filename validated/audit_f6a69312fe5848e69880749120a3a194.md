### Title
Rounding mismatch between `GlobalStateEvaluator::reached_agreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` breaks the "70% aggregated-weight" equality for global state consensus - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The bug class in the external report is a formula inconsistency: two code paths that are supposed to compute the *same* logical threshold ("credit sold for cash amount X") use different rounding, so the protocol's fee invariant silently diverges depending on which path is taken. The same class of defect exists between the two places in this repo that compute the canonical "70% of signer weight" threshold: `NakamotoBlockHeader::compute_voting_weight_threshold` (used to verify block signatures) rounds up (ceiling), while `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` (used to determine global signer-state consensus: protocol version, burn view, current miner, tx-replay-set) rounds down (floor). These are two different formulas that both claim to implement `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` (70%), but they disagree at specific `total_weight` values.

### Finding Description
`compute_voting_weight_threshold` computes the minimum weight needed with an explicit ceiling adjustment: [1](#0-0) 

`GlobalStateEvaluator::reached_agreement` computes essentially the same 70% cutoff but with plain integer division (floor, no ceiling term): [2](#0-1) 

For `total_weight` values where `total_weight * 7` is not a multiple of 10 (e.g. `total_weight = 11` → chainstate threshold `= ceil(77/10) = 8`, but `reached_agreement` accepts once `vote_weight >= 77/10 = 7` floor), `reached_agreement` treats consensus as reached with **one less unit of weight** than the value the chainstate/network actually enforces as the 70% approval bar for block signatures. `reached_agreement` gates `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which decides the agreed `current_miner` and `tx_replay_set`) in `GlobalStateEvaluator`: [3](#0-2) [4](#0-3) 

This global-state machinery (fed by `StateMachineUpdate` gossip messages, one per signer) is exactly the mechanism that decides which miner a signer treats as the canonical/authorized miner and which burn view/tx-replay-set it accepts — i.e., it is the "aggregated-weight vs verified-accepts" equality the scan rules call out. Because the two thresholds are computed with different rounding, the weight the state machine considers sufficient to "reach agreement" is not exactly the weight the network's actual approval/signature-verification threshold requires.

### Impact Explanation
This is a systemic off-by-a-fraction-of-a-weight-unit inconsistency, not an attacker-controlled majority requirement: the discrepancy is baked into the constant-time arithmetic itself and appears whenever `total_weight * 7 mod 10 != 0`, which is common for realistic reward-set weight distributions. Any single signer emitting a boundary-crafted `StateMachineUpdate` (a message a lone gossip participant can send) can be the one whose weight tips the aggregate from `floor_threshold - 1` to `floor_threshold`, causing peers to accept a "global state" (current miner / burn view / tx replay set) as agreed upon one weight-unit earlier than the block-approval threshold used elsewhere in the same signer set would allow. Since `determine_global_state`'s `current_miner` selection directly feeds which proposals a signer is willing to treat as authorized, an off-by-one threshold gap here is a genuine crack in the equality between "the weight a signer believes constitutes agreement" and "the weight that is actually required to approve/sign a block," which can push individual signers into disagreeing with each other or with the node about the current canonical miner/state near reward-set-weight boundary values — a liveness-relevant wedge condition rather than a full safety break.

### Likelihood Explanation
Likelihood is moderate: it requires no majority collusion and is triggered purely by the reward-set's total weight not being an exact multiple of 10 relative to 70% — a condition met by most non-round weight distributions — combined with a single signer casting an update at the exact boundary weight. It does not require a majority of signers to be malicious, matching the "one-slot miner/gossip participant" bar; it is a pure arithmetic inconsistency (analogous to the AccountingLibrary rounding-formula report) rather than a contrived edge case.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the same ceiling-rounding formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, have `GlobalStateEvaluator` call `compute_voting_weight_threshold` directly) so that "70% of signer weight" is computed identically everywhere it gates consensus decisions in the signer.

### Proof of Concept
With a reward set totalling weight `11` (e.g., three signers with weights `4, 4, 3`):
- `NakamotoBlockHeader::compute_voting_weight_threshold(11)` = `ceil(11*7/10)` = `ceil(7.7)` = `8` (per the exact formula at `stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`).
- `GlobalStateEvaluator::reached_agreement(7)` with `total_weight = 11` evaluates `7 >= (11*7)/10 = 77/10 = 7` (integer floor) → `true`.

So a set of signers whose combined `StateMachineUpdate` weight is `7` is treated by `GlobalStateEvaluator` as having reached 70% agreement on `current_miner`/burn view/tx-replay-set, while the exact same weight (`7`) would be rejected as insufficient by `compute_voting_weight_threshold` (which requires `8`) for block-signature approval. The two "70%" gates in the same signer codebase disagree at this weight value.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
