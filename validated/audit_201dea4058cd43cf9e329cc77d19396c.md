## Title
No zero-address validation on `global_fee_admin` / `global_fee_wallet` in `init_global_fee_state` — permanent admin lock-out and fee-fund loss - (File: `programs/marginfi/src/instructions/marginfi_group/init_global_fee_state.rs`)

### Summary
`init_global_fee_state` runs once per program to create the singleton `FeeState` PDA and directly assigns the caller-supplied `admin_key` and `fee_wallet` parameters to `fee_state.global_fee_admin` and `fee_state.global_fee_wallet` with no validation that they are non-default (non-zero) `Pubkey`s [1](#0-0) . This mirrors the reported Lido `LidoMevTxFeeVault` pattern: an unvalidated address constructor parameter is persisted into critical state with no other way to correct it later.

### Finding Description
`InitFeeState` has no owner/admin gate — any signer can pay to `init` the `FEE_STATE_SEED` PDA [2](#0-1) , and the handler blindly copies whatever `admin_key`/`fee_wallet` were passed into the account with zero checks: [3](#0-2) 

Because the `FeeState` account is a fixed-seed PDA created with `init` (no `close`), it can only ever be initialized once for the life of the program deployment; there is no alternate instruction to "set" `global_fee_admin`/`global_fee_wallet` from scratch — the only path to change them afterward is `edit_fee_state`, which requires the *current* `global_fee_admin` to sign: [4](#0-3) 

If `admin_key` is ever set to `Pubkey::default()` (the all-zero key, which has no corresponding private key on Solana), then `has_one = global_fee_admin` can never be satisfied by a real signer, so `edit_fee_state` becomes permanently uncallable — exactly the "no way to fix without redeploying" failure mode described in the Lido report.

The `global_fee_wallet` field has an even more direct financial consequence. It is relied upon via `has_one` in bank creation (`LendingPoolAddBank` pays `bank_init_flat_sol_fee` lamports to it) [5](#0-4) , and it is the source of the canonical ATA used to receive `collected_program_fees_outstanding` during fee collection, as documented in `guides/ADMIN/COLLECTING_FEES.md` [6](#0-5) . If `global_fee_wallet` is zero, all protocol program fees and bank-init fees are permanently sent to the ATA of the default `Pubkey`, an address nobody controls — a durable, unrecoverable loss of program-level revenue.

### Impact Explanation
- Setting `admin_key = Pubkey::default()` permanently locks the global fee-admin role: `edit_fee_state`'s `has_one = global_fee_admin` constraint can never again be satisfied by a signer, freezing the ability to update fee parameters, fee wallet, or `pause_delegate_admin` for the life of the deployment.
- Setting `fee_wallet = Pubkey::default()` causes ongoing protocol program fees (`collected_program_fees_outstanding`) and per-bank init SOL fees to be irrecoverably routed to an address with no private key, a direct and durable loss of protocol funds.
- Because `FeeState` uses `init` on a fixed PDA seed with no reset/close path, recovering from either mistake requires a program upgrade/migration (e.g., `copy_fee_state_to_v2`/new seed), analogous to the "must redeploy" consequence flagged in the original report.

### Likelihood Explanation
`InitFeeState` is permissionless — no admin/owner constraint gates who calls it, and the parameters are attacker/deployer-supplied with no assertion against `Pubkey::default()`. A deployment script error (passing an uninitialized/zero variable) or a race to be the first caller of the one-time init instruction is sufficient to trigger this; no privileged access or complex preconditions are required.

### Recommendation
Add explicit checks in `initialize_fee_state` (and consider the same for any future migrate/init-v2 flow) that `admin_key != Pubkey::default()` and `fee_wallet != Pubkey::default()`, returning a descriptive error (e.g. `MarginfiError::InvalidFeeWallet`) otherwise, before persisting them into `fee_state`.

### Proof of Concept
1. Call `init_global_fee_state(admin_key = Pubkey::default(), fee_wallet = Pubkey::default(), ...)` — succeeds because `InitFeeState` has no validation on these parameters [7](#0-6) .
2. Any subsequent call to `edit_fee_state` fails permanently because no signer can satisfy `has_one = global_fee_admin` against the zero key [8](#0-7) .
3. Any subsequent `lending_pool_add_bank` and fee-collection flow routes SOL fees and `collected_program_fees_outstanding` to the ATA of `Pubkey::default()`, which is unrecoverable [9](#0-8) .

pub fn initialize_fee_state(
    ctx: Context<InitFeeState>,
    admin_key: Pubkey,
    fee_wallet: Pubkey,
    bank_init_flat_sol_fee: u32,
    liquidation_flat_sol_fee: u32,
    order_init_flat_sol_fee: u32,
    program_fee_fixed: WrappedI80F48,
    program_fee_rate: WrappedI80F48,
    liquidation_max_fee: WrappedI80F48,
    order_execution_max_fee: WrappedI80F48,
) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_init()?;
    fee_state.global_fee_admin = admin_key;
    fee_state.global_fee_wallet = fee_wallet;
    fee_state.key = ctx.accounts.fee_state.key();
    fee_state.bank_init_flat_sol_fee = bank_init_flat_sol_fee;
    fee_state.bump_seed = ctx.bumps.fee_state;
    fee_state.program_fee_fixed = program_fee_fixed;
    fee_state.program_fee_rate = program_fee_rate;
    fee_state.liquidation_max_fee = liquidation_max_fee;
    fee_state.liquidation_flat_sol_fee = liquidation_flat_sol_fee;
    fee_state.order_execution_max_fee = order_execution_max_fee;
    fee_state.order_init_flat_sol_fee = order_init_flat_sol_fee;

    Ok(())
}
