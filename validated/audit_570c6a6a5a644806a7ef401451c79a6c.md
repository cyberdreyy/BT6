### Title
Node profiling endpoints (`/v2/debug/pprof/*`) lack role-based authorization and are reachable by any authenticated 'view'-role user - ([File: core/web/router.go])

### Finding Description
The `/v2/keys/evm` routes for `ETHKeysController` (`Import`, `Delete`, `Chain`, and `Export`) are correctly protected with `auth.RequiresAdminRole`, and `Create` with `auth.RequiresEditRole` [1](#0-0) . The ETH key JSONAPI presenter (`presenters.ETHKeyResource`) also only exposes address, balances, and chain metadata—no private key or password material is ever serialized into the HTTP response [2](#0-1) . `formatETHKeyResponse` middleware simply wraps the same presenter and does not add secret data [3](#0-2) . So the "ETH keys controller" attack surface itself does not directly leak private keys.

The actual gap is in `metricRoutes`, which registers Go's `net/http/pprof` handlers (`/debug/pprof/{index,cmdline,profile,symbol,trace,allocs,block,goroutine,heap,mutex,threadcreate}`) with no role check at all [4](#0-3) . This group is mounted inside `authv2` — the group that requires only `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)` (i.e., any valid session or API token, regardless of role) — via `metricRoutes(authv2)` [5](#0-4) [6](#0-5) . Unlike the ETH key admin routes, none of the pprof handlers are wrapped with `auth.RequiresAdminRole`, `auth.RequiresEditRole`, or `auth.RequiresRunRole` [7](#0-6) .

This means a user with only the `UserRoleView` role — who is explicitly blocked from run/edit/admin actions such as key export, import, or job replay by `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` — can still authenticate to `/v2` and successfully call `GET /v2/debug/pprof/heap` or `/v2/debug/pprof/goroutine`, since these endpoints check only `auth.Authenticate`, not role. A heap or goroutine profile can capture raw in-memory data, including decrypted private keys held by the running keystore (which by design decrypts and keeps keys in memory for signing), passwords passed as query parameters (e.g., `newpassword`/`oldpassword` on export/import calls made by other, higher-privileged sessions during the profiling window), or session tokens present in in-flight request state.

### Impact Explanation
If validated by capturing an actual heap/goroutine dump and confirming recoverable secret material (private key bytes, plaintext export/import passwords, or session tokens) inside it, this would match a **Critical** node-compromise class: unauthorized disclosure of node blockchain private keys or secrets by a low-privileged ('view'-role) authenticated user, without any operator/admin/host access. The severity hinges on whether decrypted key material or plaintext passwords are actually reachable/recoverable in a `runtime/pprof` heap or goroutine dump at the time of capture — this is inherently probabilistic (timing- and GC-dependent) rather than guaranteed on every request.

### Likelihood Explanation
- Precondition: attacker needs any valid Chainlink node session or API token with `UserRoleView` (the lowest role) — no operator/admin credentials required.
- The route wiring in `core/web/router.go` unconditionally allows this: `metricRoutes(authv2)` applies no role gate, unlike every other sensitive `authv2` route in the same file, which do use `auth.RequiresEditRole`/`auth.RequiresAdminRole` [8](#0-7) .
- Repeatable: the attacker can request `/v2/debug/pprof/heap?debug=1` or `/v2/debug/pprof/goroutine?debug=2` repeatedly and at will, since it is a standard GET with query params, and can time requests around known key-export/import operations by other users to increase odds of capturing sensitive data in memory.
- The core authorization-bypass condition (view-role reaching an endpoint intended to be admin-only, per the stated invariant) is concretely demonstrated by the router code; the actual data-recovery step (finding a specific private key or password string in the profile) requires additional empirical proof-of-concept work against a running node.

### Recommendation
Wrap the `metricRoutes` group (or each handler) with `auth.RequiresAdminRole`, consistent with other operationally sensitive endpoints like key import/export/delete:
```go
func metricRoutes(r *gin.RouterGroup) {
	pprofGroup := r.Group("/debug/pprof", func(c *gin.Context) {
		auth.RequiresAdminRole(func(*gin.Context) { c.Next() })(c)
	})
	...
}
```
or more directly, apply `auth.RequiresAdminRole(...)` to each individual `pprofGroup.GET(...)` registration, mirroring the pattern used for `/keys/evm/import`, `/keys/evm/export`, `/keys/evm/chain`, and `/nodes/evm/forwarders/track` [9](#0-8) . Additionally, consider disabling debug pprof registration entirely outside a debug/dev build flag for production nodes.

### Proof of Concept
Go handler-level integration test plan (using existing test harness patterns from `core/cmd/shell_remote_test.go`):
1. Start a test application (`startNewApplicationV2`), create two users: one `UserRoleAdmin` and one `UserRoleView`.
2. Authenticate as the `view` user (obtain session cookie via `/sessions`).
3. Issue `GET /v2/debug/pprof/heap?debug=1` and `GET /v2/debug/pprof/goroutine?debug=2` using the view-role session.
4. Assert current (vulnerable) behavior: HTTP 200 with a non-empty body is returned (compare against `TestShell_Profile_Unauthenticated`, which asserts 401 only for *unauthenticated* requests [10](#0-9) , showing there is no test asserting role-gating for authenticated-but-view-role users).
5. After applying the fix (wrapping pprof routes with `auth.RequiresAdminRole`), re-run the same request and assert HTTP `403 Forbidden` with body `"Forbidden"`, matching the behavior in `RequiresAdminRole` [11](#0-10) .
6. As a secondary check, trigger an admin-role `POST /v2/keys/evm/export/:address?newpassword=...` concurrently while the view-role session captures `/v2/debug/pprof/goroutine?debug=2`, then grep the captured profile text for the plaintext password string to empirically confirm secret leakage feasibility.

func (ekc *ETHKeysController) formatETHKeyResponse() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()

		// Check if the response has not been written yet
		if !c.Writer.Written() {
			// Get the key and state from the Gin context
			key, keyExists := c.Get("key")
			state, stateExists := c.Get("state")

			// If key and state exist, format the response
			if keyExists && stateExists {
				r := createETHKeyResource(c, ekc, key.(ethkey.KeyV2), state.(ethkey.State))
				jsonAPIResponse(c, r, "keys")
			} else {
				err := errors.Errorf("error getting eth key and state: %v", c)
				jsonAPIError(c, http.StatusInternalServerError, err)
			}
		}
	}
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
