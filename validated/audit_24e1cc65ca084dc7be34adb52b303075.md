### Title
JWT replay-protection cache has a TOCTOU race allowing a single JWT (single-use trigger authorization) to be used multiple times - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The bug class in the report ("claimable" state is not atomically cleared/marked before a resource can be reused, allowing repeated claims") maps to the `jwtReplayCache` used to protect HTTP-trigger JWT authorization from replay. The check (`isReplay`) and the write (`recordUsage`) are two separate, non-atomic operations, allowing concurrent requests bearing the same JWT to both pass the replay check before either marks the token as used — an unprivileged client can trigger the same workflow-execution request twice (or more) with one JWT.

### Finding Description
`WorkflowMetadataHandler.Authorize` is the entry point that authenticates and authorizes an unprivileged, internet-facing HTTP trigger request via a JWT: [1](#0-0) 

The single-use enforcement relies on `jwtReplayCache`: [2](#0-1) 

`isReplay(claims.ID)` takes an `RLock`, checks presence, and releases the lock. Only afterward — following the additional authorized-key lookup logic — does `recordUsage(claims.ID)` take a separate `Lock` and insert the entry. Between the `RLock`-protected read and the later `Lock`-protected write there is no atomicity: if two requests carrying the identical JWT (same `jti`) arrive concurrently, both can execute `isReplay` and observe `exists == false` before either calls `recordUsage`. Both then pass the "has this token been used" check and both get authorized via `h.jwtCache.recordUsage(claims.ID)`, defeating the intended single-use ("already been used") requirement.

This is functionally the same root-cause pattern as the original report: a resource meant to be claimable/consumable exactly once is not marked as consumed atomically at the point of the check, so it can be exercised multiple times before the "spent" flag is committed. In the original contract this was writing `mapping_claimableSoftClay[passportId] = 0` too late/never; here it is `recordUsage` happening too late and not atomically with `isReplay`.

The existing test suite only validates the sequential (non-concurrent) case: [3](#0-2) [4](#0-3) 
Neither test exercises truly concurrent submission of the same JWT, so the race is not covered.

### Impact Explanation
This affects the internet-facing gateway's HTTP-trigger authorization path, reachable by any unprivileged client that possesses a valid, signed JWT for a workflow trigger request. Successful exploitation allows that single JWT to authorize more than one workflow execution/run, i.e., unauthorized duplicate job runs from a credential that was intended to be single-use. Depending on the workflow's side effects (e.g. financial transfers, on-chain writes, external actions), this could result in duplicate fund movement or duplicate state changes triggered by a single authorized action — matching the "unauthorized job run" / "request impersonation" class called out in scope.

### Likelihood Explanation
Exploitation requires only sending the same signed JWT-bearing request twice at (near) the same time, which is trivial for any external, unauthenticated (from the node's perspective) HTTP client capable of firing two parallel HTTP calls. No privileged access, malicious node, or special network position is required — it is purely a client-side race against the gateway's in-memory cache. The race window is small but real, given `isReplay` and `recordUsage` are separated by additional processing (authorized-key map lookup), increasing the probability of the window being hit under concurrent bursts.

### Recommendation
Make the check-and-mark operation atomic. For example, change `jwtReplayCache` to expose a single `CheckAndRecord(jti string) bool` method that takes the write lock once, checks for existence, and if absent inserts the entry and returns "not previously used" — all under one critical section:
```go
func (cache *jwtReplayCache) checkAndRecord(jti string) bool {
    cache.mu.Lock()
    defer cache.mu.Unlock()
    if _, exists := cache.cache[jti]; exists {
        return false // already used
    }
    cache.cache[jti] = time.Now()
    return true
}
```
Then in `Authorize`, replace the separate `isReplay`/`recordUsage` calls with a single call to this atomic method performed immediately when the JWT ID is known (or at minimum immediately guard the authorized-key check with it), ensuring no other logic can run between the check and the mark.

### Proof of Concept
1. Register a workflow and obtain its authorized signer key (as in `TestWorkflowMetadataHandler_Authorize`).
2. Create one signed JWT for a `MethodWorkflowExecute` request with a fixed `jti`.
3. Fire two goroutines concurrently, each calling `handler.Authorize(workflowID, tokenString, req)` (or equivalently POST the same HTTP trigger request twice in parallel via the gateway's `HandleUserTriggerRequest`).
4. Observe that under race conditions both calls can return `nil` error (successful authorization) instead of the second one returning `"JWT token has already been used..."`, demonstrating that a single-use JWT was consumed twice.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
