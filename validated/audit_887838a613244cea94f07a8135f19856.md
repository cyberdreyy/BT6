### Title
Removed multisig members' stale confirmations still count toward the threshold, allowing execution below `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` counts confirmations by only checking `HashSet::len()` of the stored confirmation set for a request; it never re-validates that the accounts/keys in that set are still active members. `delete_member` only purges requests that were *created* by the removed member, not confirmations the removed member cast on *other* pending requests. This lets a request execute with fewer live, currently-authorized confirmations than `num_confirmations` requires.

### Finding Description
`confirm` checks the size of the stored confirmation set and executes once the threshold is reached, without checking whether every member in that set is still a current member: [1](#0-0) 

`delete_member` is only invoked from `execute_request` for the `DeleteMember` action, and when removing a member it deletes outstanding requests *authored* by that member and clears their `num_requests_pk` entry, but it does **not** scan `self.confirmations` to strip that member's confirmation from requests authored by other members: [2](#0-1) 

Because of this, if member `C` has already confirmed a pending request `R` (created by member `A`), and `C` is subsequently removed via a `DeleteMember { member: C }` action, `R`'s confirmation set in `self.confirmations` still contains `C`. Any later `confirm` call recomputes `confirmations.len() as u32 + 1 >= self.num_confirmations` using that stale entry, so `C`'s confirmation is still counted even though `C` is no longer a member and could not confirm the request today.

The binding that should hold is: `count(confirmations where signer ∈ current members) == num_confirmations` before a request executes. The actual code enforces `count(confirmations, including possibly-removed signers) >= num_confirmations`, which is weaker and can be satisfied with fewer than `num_confirmations` *live* members.

### Impact Explanation
This is Critical impact per the rules: "a multisig request executed below threshold." A transfer, `AddKey`, `DeployContract`, or other privileged action can be executed with fewer genuinely-authorized live confirmations than the configured `num_confirmations`, undermining the entire security guarantee of the k-of-n multisig (e.g., NEAR funds transferred out of the multisig account, or a new full-access key/member added) with effectively a lower threshold than configured.

### Likelihood Explanation
Requires only a normal governance action (`DeleteMember`) executed through the multisig's own approved process, and requires a request to remain pending across a membership change — a realistic and unprivileged-from-the-attacker's-perspective sequence of ordinary multisig operations (no owner/foundation/redeploy assumption; any member sequence achievable by the members themselves triggers it).

### Recommendation
When executing `DeleteMember`, iterate `self.confirmations` for *all* pending requests (not just ones authored by the removed member) and remove the deleted member's entry from each confirmation set. Alternatively, when counting confirmations in `confirm`, filter the confirmation set to only those entries that are still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R1` (e.g., `Transfer`).
3. `C` calls `confirm(R1)` → confirmations for `R1` = `{C}` (1 confirmation, below threshold, request stays pending). [3](#0-2) 
4. Separately, members approve and execute a `DeleteMember { member: C }` request, removing `C` from `self.members`. Because `delete_member` only cleans requests authored by `C` (not confirmations `C` made on `R1`, which was authored by `A`), `R1`'s confirmation set still contains `C`. [4](#0-3) 
5. `A` calls `confirm(R1)` → confirmations = `{C, A}`, length 2, `+1 >= 3` is true → `R1` executes. [5](#0-4) 
6. Result: `R1` executed with only `A` (and the removed `C`'s stale entry) — i.e., only 1 genuinely live, currently-authorized confirmation plus one stale/invalid one, never reaching 3 live confirmations as `num_confirmations` requires.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
