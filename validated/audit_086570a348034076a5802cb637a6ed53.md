### Title
LOOP plugin discovery/metrics/pprof endpoints registered with no authentication at all - ([File: core/web/router.go])

### Summary
The `loopRoutes` function in `core/web/router.go` registers the `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` endpoints directly on the top-level `api` route group with no authentication middleware whatsoever, unlike every other route group in the same file (`debugRoutes`, `sessionRoutes`, `v2Routes`) which are wrapped in `auth.Authenticate(...)` and, for sensitive operations, further gated with `auth.RequiresEditRole`/`auth.RequiresAdminRole`. This means an unauthenticated caller — not merely a view-role session — can enumerate registered LOOP plugin names and reach the plugin's forwarded `/debug/pprof/*` endpoints.

### Finding Description
`loopRoutes` is invoked in `NewRouter` alongside the other route groups: [1](#0-0) 

Unlike `debugRoutes`, which wraps its `/debug/vars` route in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [2](#0-1) 

`loopRoutes` registers its handlers directly on the passed-in `*gin.RouterGroup` with no `auth.Authenticate` wrapper and no role check at all: [3](#0-2) 

Contrast this with `v2Routes`, where every mutating or sensitive action explicitly requires a session/token plus a role check (`auth.RequiresEditRole`, `auth.RequiresAdminRole`, `auth.RequiresRunRole`): [4](#0-3) 

Because `loopRoutes` sits on the bare `api` group (which only carries rate limiting and session middleware — not an authentication requirement), a request to `GET /discovery` or `GET /plugins/:name/metrics` or `GET /plugins/:name/debug/pprof/*` reaches `LoopRegistryServer.discoveryHandler`, `pluginMetricHandler`, and `pluginPPROFHandler` without any session, API token, or role check being evaluated: [5](#0-4) [6](#0-5) 

`discoveryHandler` returns the list of all registered LOOP plugin names via `l.registry.List()`, and `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` transparently proxy to the plugin's internal `/debug/pprof/*` endpoints (cmdline, heap, goroutine, symbol, profile), which can reveal process command-line arguments (including binary paths), stack traces, and other internal runtime details of the relayer/plugin process: [7](#0-6) 

The `RegisteredLoop` struct itself only carries `Name` and `EnvCfg` (port/config), not an explicit "version" field, so the disclosed inventory is limited to plugin names and, via forwarded pprof `/cmdline`, process invocation details — but critically, this occurs for **any caller, authenticated or not**, since no auth middleware guards the route group at all. This is a stricter violation than the hypothesized "view-role vs edit-role" gap: there is no role/session gate whatsoever.

### Impact Explanation
An unauthenticated network client (or a view-role/read-only credential holder) can enumerate the node's loaded LOOP relayer/plugin names and pivot into forwarded pprof debug data (`/plugins/:name/debug/pprof/cmdline`, `/goroutine`, etc.) of the internal plugin processes. This discloses internal plugin inventory and process/runtime details that aid an attacker in fingerprinting the node's configuration and targeting known vulnerabilities in specific plugin binaries/versions, matching Chainlink's "information disclosure of internal node configuration/infrastructure" bounty impact class. It does not itself grant fund movement or job execution.

### Likelihood Explanation
No credential, role, or session is required — the routes are reachable via a bare HTTP GET to the node's web server port, making this trivially reachable by any network-adjacent unauthenticated attacker, and fully repeatable.

### Recommendation
Wrap `loopRoutes` registration in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession, auth.AuthenticateByToken)` (matching `v2Routes`), and gate the plugin discovery/pprof endpoints with an explicit role check (e.g., `auth.RequiresAdminRole` or `auth.RequiresEditRole`) consistent with the intended scope for debug/registry endpoints, mirroring how `/debug/vars` is protected in `debugRoutes`.

### Proof of Concept
Add a Go handler-level test in `core/web/loop_registry_test.go`:
1. Start the test app as in `TestLoopRegistry` but do **not** create/attach any authenticated session cookie or API token to the HTTP client (use a raw `net/http` client instead of `app.NewHTTPClient`, or explicitly clear cookies/headers).
2. Issue `GET /discovery` and assert the response is `200 OK` with a JSON body listing registered plugins — expected (per intended scope) to be `401/403` without authentication.
3. Issue `GET /plugins/mockLoopImpl/debug/pprof/cmdline` unauthenticated and assert it also returns `200 OK` with process command-line data instead of `401/403`.
4. As a control, repeat steps 2–3 against `/v2/users` (an admin-gated route) and confirm it correctly returns `401/403` without a session, demonstrating the inconsistency in `core/web/router.go`'s `loopRoutes` versus `v2Routes`.

```go
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
