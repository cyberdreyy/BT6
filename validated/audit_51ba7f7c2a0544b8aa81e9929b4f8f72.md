### Title
Raw artifact archiver follows symlinks and opens targets outside the artifact root, unlike other archivers - (File: commands/helpers/archive/raw/raw_archiver.go)

### Summary
The `Raw` archiver's `Archive` method calls `os.Open(pathname)` directly on every entry in the `files` map, with no check on file mode or on whether the resolved path stays within the intended working directory. Unlike the sibling `tarzstd` archiver, which explicitly enforces a chroot-style prefix check (`a.dir`) and skips reading content for non-regular files (symlinks), the raw archiver has no such guard, even though it stores an unused `dir` field.

### Finding Description
`fileArchiver.process` (`commands/helpers/file_archiver.go:65-101`) validates that the *symlink path itself* is inside `c.wd` via `filepath.Abs`/`filepath.Rel`, and `add` (`commands/helpers/file_archiver.go:127-138`) stores the entry using `os.Lstat`, which does not follow the symlink and does not validate the link target. This means a job can create a symlink inside the workspace (e.g. `ln -s /etc/passwd leak`, or a symlink into another checked-out project's directory on a shared volume) and have it pass `process`/`add` validation, since the *symlink itself* resolves to a path under `c.wd`.

When `--artifact-format raw` is used, `createBodyProvider` (`commands/helpers/artifacts_uploader.go:99-139`) calls `archive.NewArchiver(archive.Raw, ...)` and then `archiver.Archive(ctx, c.files)`. The raw archiver's `Archive` (`commands/helpers/archive/raw/raw_archiver.go:35-51`) does:
```go
for pathname := range files {
    f, err := os.Open(pathname)
    ...
    io.Copy(a.w, f)
}
```
`os.Open` follows symlinks by default. There is no mode check (`fi.Mode()&os.ModeSymlink`) and no boundary check against `a.dir`, unlike `tarzstd.archiver.Archive` (`commands/helpers/archive/tarzstd/tarzstd_archiver.go:68-74, 106-108`), which both enforces `strings.HasPrefix(path, a.dir+...)` and skips content copy for non-regular files, writing only the symlink target string into the tar header instead of following it. `raw` has neither protection, so if a symlink entry reaches `Archive`, the target file's contents (whatever `os.Open` resolves to) are streamed straight into the uploaded artifact. However, this path has an important practical constraint I could not fully rule out: `raw.archiver.Archive` explicitly enforces `ErrTooManyRawFiles` if `len(files) > 1`, meaning raw format is designed for exactly one file per upload. I was unable to fully confirm, within the available index, whether `--artifact-format raw` is reachable for arbitrary user-specified `artifacts:paths` glob entries (which could match a symlink) versus being restricted server-side/CI-config-side to single, non-glob, well-known artifact types (e.g. metadata/report files) where a job author could not point it at an arbitrary symlink of their choosing. The `ArtifactFormat` enum and its production usage in `common/spec/spec.go` and `shells/abstract.go` reference `ArtifactFormatRaw`, but I could not verify from available context whether `abstract.go`'s `writeUploadArtifact` ever emits `--artifact-format raw` for a job-configured `artifacts:paths` entry (as opposed to only for single internally-generated files like `artifacts:reports`).

### Impact Explanation
If reachable with attacker-controlled `artifacts:paths`, a job could exfiltrate arbitrary files readable by the runner's job user (e.g., files outside the git checkout on a shared volume, or another project's files on a shared runner) into a GitLab-visible artifact download, since the raw archiver silently follows symlinks it accepted despite `fileArchiver` intending to keep files "inside" the working directory.

### Likelihood Explanation
Preconditions are job-controlled and require no special privilege: the ability to create a symlink in the job workspace before the uploader runs, plus reaching `--artifact-format raw` with that path. The `tarzstd` archiver's existing chroot check and symlink-skip logic show this exact bypass was consciously mitigated for tar archives but the mitigation was not applied uniformly to the `raw` archiver, which is a real inconsistency in the codebase's isolation boundary for file operations. Full exploitability is contingent on whether `raw` format is actually selectable/reachable for a user-supplied `artifacts:paths` glob match rather than only for a single fixed internal artifact — this is the one gap I could not close with available tools.

### Recommendation
Add the same protections used in `tarzstd_archiver.go` to `raw_archiver.go`: reject or skip entries whose `os.FileInfo.Mode()` indicates a symlink (or resolve the symlink and verify the resolved absolute path is still prefixed by `a.dir` before calling `os.Open`), matching the existing `a.dir` chroot-prefix check pattern already implemented for `tarzstd`.

### Proof of Concept
```go
// commands/helpers/archive/raw/raw_archiver_test.go
func TestRawArchiver_FollowsSymlinkOutsideDir(t *testing.T) {
    dir := t.TempDir()
    outside := filepath.Join(t.TempDir(), "secret.txt")
    require.NoError(t, os.WriteFile(outside, []byte("SECRET_CONTENT"), 0644))

    link := filepath.Join(dir, "leak")
    require.NoError(t, os.Symlink(outside, link))

    fi, err := os.Lstat(link)
    require.NoError(t, err)

    var buf bytes.Buffer
    a, err := NewArchiver(&buf, dir, archive.DefaultCompression)
    require.NoError(t, err)

    err = a.Archive(context.Background(), map[string]os.FileInfo{link: fi})
    require.NoError(t, err)

    // BUG: expect this to fail/skip; currently it succeeds and leaks content
    assert.NotContains(t, buf.String(), "SECRET_CONTENT")
}
```
Expected (current buggy behavior): `buf.String()` contains `"SECRET_CONTENT"`, proving the raw archiver followed the symlink outside `dir` and copied external content into the artifact stream. After the recommended fix (mode/dir check), the test should assert an error or empty output instead.

```go
func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

	if err == nil {
		// Process path only if it lives in our build directory
		if !strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			excluded, rule := c.isExcluded(relative)
			if excluded {
				c.exclude(rule)
				return false
			}

			err = c.add(relative)
		} else {
			err = errors.New("not supported: outside build directory")
		}
	}

	if err == nil {
		return true
	}

	if os.IsNotExist(err) {
		// We hide the error that file doesn't exist
		return false
	}

	logrus.Warningf("%s: %v", match, err)
	return false
}
```
