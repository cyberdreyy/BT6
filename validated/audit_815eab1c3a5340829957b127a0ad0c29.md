### Title
GatewaySpec.GatewayConfig leaked verbatim to any authenticated (view-role) user via GET /v2/jobs/:ID - (File: core/web/jobs_controller.go)

### Finding Description
`JobsController.Show` is registered at `authv2.GET("/jobs/:ID", jc.Show)` with no role wrapper (unlike sibling routes `POST /jobs`, `PUT /jobs/:ID`, `DELETE /jobs/:ID` which are wrapped in `auth.RequiresEditRole`), so it is reachable by any authenticated principal that passes `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)`, including a bare view-role user. [1](#0-0) 

`Show` loads the full `job.Job` (including `GatewaySpec`) and passes it straight to `presenters.NewJobResource`, which for `job.Gateway` type jobs calls `presenters.NewGatewaySpec(j.GatewaySpec)`. [2](#0-1) [3](#0-2) 

`NewGatewaySpec` copies `spec.GatewayConfig` (a `map[string]any` parsed from the job's TOML) directly into the JSON-serialized `GatewaySpec.GatewayConfig` field with no field-level redaction, allow-list, or secret-stripping logic: [4](#0-3) 

Because the Gateway job's configuration (bridge credentials, node/DON allowlist entries, or other operator-supplied config nested arbitrarily inside the `map[string]any`) is stored as-is at job creation and returned as-is on `Show`/`Index`, any value an admin puts in `GatewayConfig` (e.g. a secret-looking key nested inside `Dons[].Handlers[].Config` or similar) is disclosed verbatim to any caller who can authenticate at all, without any check for edit/admin role. This differs from other config-carrying specs in the same file (`OffChainReporting2Spec.RelayConfig`, `BootstrapSpec.RelayConfig`) which have the same pattern, but the audit specifically flags `GatewayConfig` because Gateway job configs are documented/known to embed bridge and DON allowlist material.

### Impact Explanation
An unprivileged (view-role) authenticated user, or any credential holder that can pass `AuthenticateByToken`/`AuthenticateBySession`, can call `GET /v2/jobs/:ID` (or `GET /v2/jobs`) for a Gateway job and read the complete `GatewayConfig` object as stored, exposing any secret-like configuration values embedded there by an admin. This maps to the Chainlink bounty "sensitive information disclosure / secret exposure" impact class — a lower-privileged role obtaining configuration data intended to be confined to editor/admin roles.

### Likelihood Explanation
Minimal precondition: possession of any valid session or API token with the default/view role (the lowest role tier) is sufficient — no edit or admin role is required, and no additional exploitation steps are needed beyond a single authenticated GET. It is fully repeatable and deterministic since `Show`/`Index` unconditionally serialize the full spec for any job type without role-based filtering.

### Recommendation
Add role gating on `GET /v2/jobs/:ID` and `GET /v2/jobs` (at minimum `auth.RequiresViewRole` is already implicit, but if `GatewayConfig` is meant to be edit/admin-only, gate the endpoint with `auth.RequiresEditRole` or filter/redact `GatewayConfig` in `presenters.NewGatewaySpec` based on the caller's role, redacting known-sensitive keys/paths (allowlist secrets, bridge credentials) before returning the JSON:API resource, mirroring existing secret-redaction patterns used elsewhere (e.g., password/token blacklist logic in `core/web/router.go`'s `isBlacklisted`/`readSanitizedJSON`).

### Proof of Concept
1. Unit test in `core/web/presenters/job_test.go`: construct a `job.Job{Type: job.Gateway, GatewaySpec: &job.GatewaySpec{GatewayConfig: map[string]any{"dons": []any{map[string]any{"handlers": []any{map[string]any{"config": map[string]any{"apiSecret": "super-secret-value"}}}}}}}}`; call `presenters.NewJobResource(j)`; marshal to JSON and assert the string `"super-secret-value"` (or the raw key) is present unredacted in the output — demonstrating the leak.
2. Handler-level integration test in `core/web/jobs_controller_test.go`: create a Gateway job as admin via `POST /v2/jobs`; authenticate a second client with a view-role API token; call `GET /v2/jobs/:ID` with that token; assert HTTP 200 (not 401/403) and that the response body contains the secret value from `gatewayConfig`, proving the route is reachable without `RequiresEditRole`/`RequiresAdminRole` and that the secret is disclosed to the view-role user.

func (jc *JobsController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	var err error
	jobSpec := job.Job{}
	if externalJobID, pErr := uuid.Parse(c.Param("ID")); pErr == nil {
		// Find a job by external job ID
		jobSpec, err = jc.App.JobORM().FindJobByExternalJobID(ctx, externalJobID)
	} else if pErr = jobSpec.SetID(c.Param("ID")); pErr == nil {
		// Find a job by job ID
		jobSpec, err = jc.App.JobORM().FindJob(ctx, jobSpec.ID)
	} else {
		jsonAPIError(c, http.StatusUnprocessableEntity, pErr)
		return
	}
	if err != nil {
		if errors.Is(errors.Cause(err), sql.ErrNoRows) {
			jsonAPIError(c, http.StatusNotFound, errors.New("job not found"))
		} else {
			jsonAPIError(c, http.StatusInternalServerError, err)
		}
		return
	}

	jsonAPIResponse(c, presenters.NewJobResource(jobSpec), "jobs")
}
