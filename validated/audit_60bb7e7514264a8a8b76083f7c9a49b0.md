### Title
Symlink component planted by one archive extraction is followed by a later extraction into the same directory, allowing writes outside `e.dir` - ([File: commands/helpers/archive/tarzstd/tarzstd_extractor.go])

### Summary
`extractor.Extract` validates each entry's target path with a purely textual `filepath.Abs` + `strings.HasPrefix` check against `e.dir`, and creates symlinks from attacker-controlled `hdr.Linkname` with no validation at all. Because symlinks written by one `Extract()` call persist on disk, a later, separate `Extract()` call into the same directory (a realistic scenario for GitLab Runner, e.g. multiple `cache:` entries or fallback cache keys extracted sequentially into the job's working directory) can supply a regular-file entry whose name traverses through that pre-existing symlink, causing `os.MkdirAll`/`os.Create` to write outside `e.dir`.

### Finding Description
The confinement check operates only on the literal joined path string: [1](#0-0) 
It never resolves intermediate path components, so it cannot detect that a directory segment in `hdr.Name` is actually a symlink pointing outside `e.dir`. Symlink entries are created from `hdr.Linkname` with zero validation: [2](#0-1) 
Within a single `Extract()` call this is partially mitigated because symlinks/dirs are collected in `deferred` and only materialized *after* all regular files are written in the first pass: [3](#0-2) 
That ordering prevents a same-archive symlink-then-write trick, but it does nothing across two separate `Extract()` invocations into the same `dir`. GitLab Runner does exactly this: the shell generator extracts each `cache:` entry (and any fallback keys) by invoking the `cache-extractor` helper once per cache config, all targeting the job's working directory: [4](#0-3) [5](#0-4) 
and `CacheExtractorCommand.Execute` builds the extractor with `wd = os.Getwd()` (the build root) as `e.dir` on every invocation: [6](#0-5) 

Attack flow: attacker controls the contents of a cache archive uploaded from a prior job run (or the fallback-key cache). Archive 1 contains a symlink entry `Name="link"`, `Linkname="/somewhere/outside"`. This is written to `wd/link` with no validation of the target. Archive 2 (a different `cache:` entry, or a fallback key, extracted by a second, separate `cache-extractor` invocation into the same `wd`) contains a regular-file entry `Name="link/payload"`. When Archive 2 is processed, `path = wd/link/payload` passes the textual `HasPrefix(wd)` check (it's textually still under `wd`), `os.MkdirAll(wd/link, ...)` succeeds trivially because `Stat` follows the existing symlink and reports an existing directory, and `os.Create(wd/link/payload)` is resolved by the OS through the symlink, landing the write outside `wd`.

### Impact Explanation
An unprivileged pipeline author can write arbitrary file content to any filesystem location reachable (and writable) by the job's OS user/container, outside the intended build/cache root — e.g. overwriting scripts, shell profiles, or SSH/config files elsewhere in the container or shared shell-executor filesystem. This violates the invariant that "file operations must stay within intended build/cache/artifact roots" and can lead to code execution on subsequent job steps or shared-runner sessions that source overwritten files.

### Likelihood Explanation
Feasible and fully attacker-controlled: cache archive content is uploaded by the job author via `cache-archiver`/`cache push`, and multiple sequential `cache-extractor` invocations into the same working directory are a normal, documented Runner feature (multiple `cache:` paths, `FallbackKeys`, `CACHE_FALLBACK_KEY`). No special privileges beyond authoring `.gitlab-ci.yml` and controlling job cache contents across two job runs (or two cache keys in one run) are required, and the flaw is repeatable deterministically.

### Recommendation
Harden `Extract` to resolve/verify each path component against symlink escapes rather than relying on a textual prefix check:
- Before `MkdirAll`/`Create`, walk `hdr.Name` component-by-component using `os.Lstat` and reject (or refuse to traverse) any component that is a symlink, or resolve the real path via `filepath.EvalSymlinks` on the existing prefix and re-validate it is still within `e.dir`.
- Validate `hdr.Linkname` itself: reject absolute paths and reject relative targets that resolve outside `e.dir` when joined with the symlink's containing directory, mirroring the existing `Name` check.
- Consider tracking/removing symlinks created by a previous extraction before starting a new one into the same root, or use `O_NOFOLLOW`-safe path construction (e.g. a "secure join" helper) throughout.

### Proof of Concept
Go test in `commands/helpers/archive/tarzstd`:
```go
func TestExtract_SymlinkEscapeAcrossTwoExtracts(t *testing.T) {
    dir := t.TempDir()
    outside := t.TempDir()

    // Archive 1: plant a symlink "link" -> outside dir
    buf1 := buildTarZstd(t, []tarEntry{
        {name: "link", linkname: outside, typeflag: tar.TypeSymlink},
    })
    require.NoError(t, mustExtract(t, buf1, dir))

    // Archive 2: regular file entry traversing through "link"
    buf2 := buildTarZstd(t, []tarEntry{
        {name: "link/payload", content: []byte("pwned")},
    })
    err := mustExtract(t, buf2, dir)

    // Expect either extraction fails, or file must NOT land outside dir
    _, statErr := os.Stat(filepath.Join(outside, "payload"))
    assert.True(t, err != nil || os.IsNotExist(statErr),
        "payload was written outside chroot dir via symlink traversal")
}
```
Expected (buggy) behavior today: `err == nil` and `outside/payload` exists with content `"pwned"`, proving the escape. After the fix, either the second `Extract` call returns an error referencing the symlink component, or the file is written harmlessly inside `dir` and `outside/payload` does not exist.

func (b *AbstractShell) cacheExtractor(ctx context.Context, w ShellWriter, info common.ShellScriptInfo) error {
	skipRestoreCache := true

	for _, cacheOptions := range info.Build.Cache {
		// Create list of files to extract
		var archiverArgs []string
		for _, path := range cacheOptions.Paths {
			archiverArgs = append(archiverArgs, "--path", path)
		}

		if cacheOptions.Untracked {
			archiverArgs = append(archiverArgs, "--untracked")
		}

		// Skip restoring cache if no cache is defined
		if len(archiverArgs) < 1 {
			continue
		}

		skipRestoreCache = false

		// Skip extraction if no cache is defined
		cacheConfig, warning, err := newCacheConfig(info.Build, cacheOptions.Key)
		if warning != "" {
			w.Warningf("%s", warning)
		}
		if err != nil {
			w.Noticef("Skipping cache extraction due to %v", err)
			continue
		}

		cacheOptions.Policy = spec.CachePolicy(info.Build.GetAllVariables().ExpandValue(string(cacheOptions.Policy)))

		if ok, err := cacheOptions.CheckPolicy(spec.CachePolicyPull); err != nil {
			return fmt.Errorf("%w for %s", err, cacheConfig.HumanKey)
		} else if !ok {
			w.Noticef("Not downloading cache %s due to policy", cacheConfig.HumanKey)
			continue
		}

		b.extractCacheOrFallbackCachesWrapper(ctx, w, info, *cacheConfig, cacheOptions)
	}

func (b *AbstractShell) addExtractCacheCommand(
	ctx context.Context,
	w ShellWriter,
	info common.ShellScriptInfo,
	cacheConfigs []cacheConfig,
	cachePaths []string,
) {
	cacheConfig := cacheConfigs[0]

	args := []string{
		"cache-extractor",
		"--file", cacheConfig.ArchiveFile,
		"--timeout", strconv.Itoa(info.Build.GetCacheRequestTimeout()),
	}

	w.Noticef("Checking cache for %s...", cacheConfig.HumanKey)

	extraArgs, env, err := getCacheDownloadURLAndEnv(ctx, info.Build, cacheConfig.HashedKey)
	args = append(args, extraArgs...)
	if err != nil {
		w.Warningf("Failed to obtain environment for cache %s: %v", cacheConfig.HumanKey, err)
	}
	if env != nil {
		cacheEnvFilename := b.writeCacheExports(w, env)
		args = append(args, "--env-file", cacheEnvFilename)
		defer w.RmFile(cacheEnvFilename)
	}

	alternateURLArgs, alternateErr := getAlternateCacheDownloadURL(ctx, info.Build, cacheConfig.AlternateKey)
	if alternateErr != nil {
		w.Warningf("Failed to obtain alternate URL for cache %s: %v", cacheConfig.HumanKey, alternateErr)
	} else {
		args = append(args, alternateURLArgs...)
	}

	w.IfCmdWithOutput(info.RunnerCommand, args...)
	w.Noticef("Successfully extracted cache")
	w.Else()
	w.Warningf("Failed to extract cache")

	// When extraction fails, remove the cache directories to avoid problems in cases
	// where archives may have been partially extracted, leaving the cache in an inconsistent
	// state. If we attempt to extract from fallback caches below, we'll remove the same set
	// of directories if that fails.
	if info.Build.IsFeatureFlagOn(featureflags.CleanUpFailedCacheExtract) {
		for _, cachePath := range cachePaths {
			w.Printf("Removing %s", cachePath)
			w.RmDir(cachePath)
		}
	}

	// We check that there is another key than the one we just used
	if len(cacheConfigs) > 1 {
		b.addExtractCacheCommand(ctx, w, info, cacheConfigs[1:], cachePaths)
	}
	w.EndIf()

func (c *CacheExtractorCommand) Execute(cliContext *cli.Context) {
	log.SetRunnerFormatter()

	c.normalizeExtractorArgs()
	if err := validateCacheTransferTuning(c.TransferBufferSize, c.ChunkSize, c.Concurrency); err != nil {
		logrus.Fatalln(err)
	}

	wd, err := os.Getwd()
	if err != nil {
		logrus.Fatalln("Unable to get working directory")
	}

	if c.File == "" {
		warningln("Missing cache file")
	}

	if c.URL != "" || c.GoCloudURL != "" {
		err := c.doRetry(c.download)
		if err != nil {
			warningln(err)
		}
	} else {
		logrus.Infoln(
			"No URL provided, cache will not be downloaded from shared cache server. " +
				"Instead a local version of cache will be extracted.")
	}

	f, size, format, err := openArchive(c.File)
	if os.IsNotExist(err) {
		warningln("Cache file does not exist")
	}
	if err != nil {
		logrus.Fatalln(err)
	}
	defer f.Close()

	extractor, err := archive.NewExtractor(format, f, size, wd)
	if err != nil {
		logrus.Fatalln(err)
	}

	err = extractor.Extract(context.Background())
	if err != nil {
		logrus.Fatalln(err)
	}
