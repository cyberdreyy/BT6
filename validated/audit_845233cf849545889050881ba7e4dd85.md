### Title
Pre-Cobalt `ActivationRegistry` precompile accepts and permanently strands attached ETH value - (File: `crates/common/precompiles/src/activation/dispatch.rs`)

### Summary
The `ActivationRegistry` precompile's ABI dispatcher only rejects nonzero `msg.value` (`NonPayable`) from the `Cobalt` upgrade onward. For any upgrade prior to `Cobalt` (i.e. `Beryl` and earlier), the dispatcher explicitly accepts calls carrying ETH value and proceeds with normal execution, crediting the value to the precompile's own balance with no code path anywhere in the system able to move or withdraw it — the same root cause as the RAACNFT report: a contract/address is credited with funds it has no mechanism to forward, refund, or let an owner reclaim.

### Finding Description
`ActivationRegistryStorage::dispatch_with_observer` guards against payable calls only when the active upgrade is `Cobalt` or later: [1](#0-0) 

The comment makes the intent explicit: *"Activation-registry selectors are all nonpayable; reject attached ETH from Cobalt onward. Pre-Cobalt (Beryl) preserves the historical accept-and-strand behavior..."*. This is corroborated by the dedicated regression test asserting that pre-Cobalt calls with nonzero value must succeed rather than revert with `NonPayable`: [2](#0-1) 

Precompiles in this codebase are stateless dispatch targets (see the uniform `NonPayable` guard pattern used by every other precompile — nonce manager, tx-context, policy registry, all B20 variants — each of which rejects `call_value` unconditionally before doing any work, e.g. `crates/common/precompiles/src/nonce/dispatch.rs:29-33`, `crates/common/precompiles/src/tx_context/dispatch.rs:31-35`, `crates/common/precompiles/src/policy/dispatch.rs` golden test at lines 860-873). None of these precompiles — including `ActivationRegistry` — implement any withdraw, sweep, or forward-to-owner mechanism for value that lands on their address, because a precompile has no EVM bytecode and cannot itself initiate a transfer. Any ETH balance accrued at a precompile address is permanently unreachable through normal EVM mechanics (no `SELFDESTRUCT`, no contract logic to call `CALL`/`SEND`).

Consequently, on any chain state where the active hardfork is below `Cobalt`, a single unprivileged, signed transaction that calls the `ActivationRegistry` precompile address with nonzero `value` (e.g. `isActivated`, `checkActivated`, or any other selector) will succeed and permanently lock the attached ETH at that address — mirroring exactly the RAACNFT class of bug: funds pulled into a contract/address with no possible extraction path.

### Impact Explanation
This is a permanent freezing-of-funds bug class. Any attacker (or naive user) who sends ETH alongside a call to the `ActivationRegistry` precompile while the network is below the `Cobalt` upgrade loses that ETH irrecoverably — there is no admin, owner, or protocol-level sweep for precompile-held balance. Because the guard is upgrade-gated rather than removed, the vulnerable code path is still present in the current codebase and will execute exactly this behavior whenever `upgrade < BaseUpgrade::Cobalt` is the active spec (including in replay/historical execution and potentially in any environment, testnet, or devnet still running an upgrade below Cobalt). This qualifies as a Medium/High severity permanent-freezing-of-funds issue under the given acceptance criteria.

### Likelihood Explanation
Likelihood is high wherever the active fork is pre-Cobalt: the transaction is trivial (any signed call to a fixed, well-known precompile address with nonzero value), requires no special privilege, and the "accept-and-strand" behavior is unconditional for all selectors once `upgrade < Cobalt`, as confirmed by the dedicated test asserting non-reversion. The main caveat is that this analysis could not fully confirm from the available index which upgrade is currently active on Base mainnet at present (i.e., whether `Cobalt` has already been activated network-wide) — this determines whether the path is presently live-exploitable or only relevant to historical replay/older testnets. The engineering team should verify current mainnet/testnet activation status for `Cobalt` to confirm current exploitability.

### Recommendation
- If any live network (mainnet or testnet) is still running below `Cobalt`, disable or pause the `ActivationRegistry` precompile's payable acceptance immediately, or backport the `NonPayable` rejection without depending on the upgrade gate for currently-active chains — reserving the "accept-and-strand" behavior strictly for byte-for-byte historical replay of already-mined blocks (e.g., branch on "replaying historical block" vs. "executing new transaction" rather than solely on `upgrade`).
- Alternatively, add a privileged sweep/refund path (e.g., an owner-only precompile method to forward stranded balance to a designated recipient) usable only for legacy, pre-Cobalt-affected balances, so any ETH already stranded by historical accept-and-strand calls can be recovered without altering consensus-critical historical replay semantics.
- Audit other pre-hardfork-gated precompile behaviors for similar accept-and-strand patterns introduced for replay compatibility, to ensure none remain reachable on currently active upgrades.

    /// ABI-dispatches activation registry calldata with an observer.
    pub fn dispatch_with_observer<O>(
        &mut self,
        ctx: StorageCtx<'_>,
        calldata: &[u8],
        admin_config: ActivationAdminConfig,
        upgrade: BaseUpgrade,
        observer: O,
    ) -> PrecompileResult
    where
        O: PrecompileCallObserver,
    {
        let mut recorder = PrecompileCallRecorder::start(
            observer,
            PrecompileMetricLabels::activation_call(calldata),
        );
        // Activation-registry selectors are all nonpayable; reject attached ETH from Cobalt
        // onward. Pre-Cobalt (Beryl) preserves the historical accept-and-strand behavior so
        // replay of live-installed activation calls remains byte-identical.
        if upgrade >= BaseUpgrade::Cobalt && !ctx.call_value().is_zero() {
            return recorder.record_base_error_result(
                ctx,
                BasePrecompileError::revert(IActivationRegistry::NonPayable {}),
            );
        }
        if let Err(error) = recorder.deduct_calldata_gas(ctx, calldata) {
            return recorder.record_base_error_result(ctx, error);
        }
        recorder.record_base_result(ctx, self.inner(calldata, admin_config), |output| output)
    }

    fn dispatch_accepts_nonzero_value_before_cobalt() {
