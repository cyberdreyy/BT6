### Title
`requestWithdraw` instant-withdraw branch bypasses all management and performance fees - (contracts/IdleCDOEpochVariant.sol)

### Summary
When `requestWithdraw` takes the instant-withdrawal path (APR dropped by more than `instantWithdrawAprDelta`), it returns early before computing `_totalWithdrawFees`. The user exits with the full tranche value — principal plus accrued interest priced into `tranchePrice` — without paying the upfront management fee or the performance fee on interest that every queued withdrawer is charged. This mirrors the NibblVault `buy` bug where one conditional branch skipped the secondary-curve fee.

### Finding Description
In `requestWithdraw`, the fee logic at `IdleCDOEpochVariant.sol:772-778` is only reached on the queued path:

- Line 761-769: if `_isInstantWithdrawEnabled()` and `lastEpochApr > currentApr + instantWithdrawAprDelta`, the contract calls `creditVault.requestInstantWithdraw(_underlyings, msg.sender)` and `_withdrawOps(_amount, _underlyings, _tranche)` and **returns early**. `_underlyings = _trancheToUnderlyings(_amount, _tranche)` (line 756) values the tranches at current `tranchePrice`, which includes accrued interest since `latestHarvestBlock` (tranche prices are updated via `_updateAccounting()` at line 750).
- The instant branch never calls `_totalWithdrawFees(principal, interest)` (line 774), never deducts `_mgmtFee`/`_netGainAfterFees`, and never increments `pendingWithdrawFees` (line 778).
- On the strategy side, `requestInstantWithdraw` (`IdleCreditVault.sol:356-375`) mints the receipt 1:1 and `claimInstantWithdrawRequest` (line 387-389) pays out the full `instantWithdrawsRequests[_user]` with no fee haircut.

Contrast with the normal path: `_underlyings = principal + interest - totalFees`, and `pendingWithdrawFees += totalFees` so fees are eventually paid to `feeReceiver`/`owner` in `_stopEpoch` (lines 431-459). The instant withdrawer receives interest embedded in `tranchePrice` completely free of the performance `fee` and free of the upfront management fee that a queued request for the identical position would pay. ### Impact Explanation
Direct leaking of value that belongs to `feeReceiver`/`owner`: whenever instant withdrawals are enabled and the epoch ends with a sufficiently lower APR, every exiting user avoids `fee` (performance) on all accrued interest and avoids `managementFee` on principal. With e.g. 10% performance fee and 1% management fee, an instant withdrawer of a 10,000-underlying position keeps the interest that a queued withdrawer would forfeit ~10% of, plus skips the upfront management fee charged for `epochDuration + remaining buffer`. The loss is borne by fee recipients and is quantifiable as `totalFees` that `_totalWithdrawFees` would have returned.

### Likelihood Explanation
The bypass is unconditional once the mode is active: any KYC-passed tranche holder can call `requestWithdraw` during a period where `lastEpochApr > unscaledApr() + instantWithdrawAprDelta`. The APR drop is set by the honest manager at `stopEpoch`, so the attacker merely needs to hold tranches and time their request — no privileged action required. Every such withdrawal skips the entire fee block.

### Recommendation
Apply the same fee accounting on the instant path: compute `(interest, diff) = _calcInterestWithdrawRequest(_underlyings, _tranche)` and `totalFees = _totalWithdrawFees(principal, interest)` before calling `requestInstantWithdraw`, subtract the fees from the receipt amount (`creditVault.requestInstantWithdraw(_underlyings - totalFees, msg.sender)`), and add them to `pendingWithdrawFees` — analogous to the report's `_caculateFeeSecondaryCurve`/`_reverseFeeSecondaryCurve` fix that makes the fee-inclusive amount explicit on the previously-fee-free branch. If instant withdrawals are intended to be fee-free by design, at minimum charge the performance fee on the interest embedded in `tranchePrice` so instant exits cannot undercut queued exits.

### Proof of Concept
Foundry fork test (extends `test/foundry/IdleCreditVault.t.sol`, modeled on `testRequestWithdrawInstant` at line 3627):

```solidity
function testInstantWithdrawSkipsFees() external {
    _setFeeParams(TL_MULTISIG, 10000, FULL_ALLOC, 1000); // 10% perf, 1% mgmt

    uint256 amountWei = 10000 * ONE_SCALE;
    idleCDO.depositAA(amountWei);

    _startEpochAndCheckPrices(0);
    // honest manager stops epoch with APR drop > instantWithdrawAprDelta
    _stopEpochAndCheckPrices(0, initialProvidedApr - (cdoEpoch.instantWithdrawAprDelta() + 1), _expectedFundsEndEpoch());

    uint256 trancheBal = IERC20Detailed(address(AAtranche)).balanceOf(address(this));
    uint256 underlyings = trancheBal * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN;
    // fees a queued withdrawal of the same position would pay
    (uint256 interest,) = _calcInterestWithdrawRequest(underlyings, address(AAtranche));
    uint256 expectedFees = /* _totalWithdrawFees(underlyings, interest) */ 
        _calcManagementFee(underlyings, 1000, cdoEpoch.epochDuration()); // lower bound

    uint256 requested = cdoEpoch.requestWithdraw(0, address(AAtranche));

    // BUG: full value paid out, zero fees booked
    assertEq(requested, underlyings, 'instant withdraw not fee-haircut');
    assertEq(cdoEpoch.pendingWithdrawFees(), 0, 'no fees booked for instant path');
    assertGt(expectedFees, 0, 'queued path would have charged fees');
}
```

The assertion `pendingWithdrawFees() == 0` while `requested == underlyings` (full principal + accrued interest at `tranchePrice`) demonstrates that the instant branch leaks the entire fee amount, exactly as the Nibbl `buy` branch leaked the secondary-curve fee when `msg.value > _lowerCurveDiff`.

  function _totalWithdrawFees(uint256 _principal, uint256 _interest) private view returns (uint256) {
    uint256 _mgmtFee = _calculateManagementFee(_principal, _withdrawRequestManagementFeeDuration());
    // When interest covers management fees, interest - netGain equals management fee plus performance fee.
    return _mgmtFee >= _interest ?
      _mgmtFee :
      _interest - _netGainAfterFees(_interest, _mgmtFee);
  }

  function requestInstantWithdraw(uint256 _amount, address _user) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // increase the instant withdraw requests for the user
    instantWithdrawsRequests[_user] += _amount;
    uint256 currentEpoch = epochNumber;
    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"
    // from old funded instant receipts.
    instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
    pendingInstantWithdraws += _amount;
  }

  /// @notice claim the instant withdraw request
  /// @dev we transfer the underlying tokens
  /// @param _user address of the user
  function claimInstantWithdrawRequest(address _user) external {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized && defaultInstantWithdrawsFinalized) {
      // Clear the defaulted-epoch instant receipt first, then continue so the same call can
      // also pay any older instant receipt that was already funded before default finalization.
      _claimDefaultedInstantWithdrawRequest(_user);
    }
    uint256 amount = instantWithdrawsRequests[_user];
    // burn strategy tokens from user
    _burn(_user, amount);
