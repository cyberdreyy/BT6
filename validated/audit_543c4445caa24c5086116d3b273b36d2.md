### Title
Permissionless `lending_pool_collect_bank_fees` unconditionally transfers zero-amount fees, causing DoS on Token-2022 mints whose transfer hook rejects zero-value transfers - (File: `programs/marginfi/src/instructions/marginfi_group/collect_bank_fees.rs`)

### Summary
`lending_pool_collect_bank_fees` computes three fee-transfer amounts (insurance, group, program) and calls `bank.withdraw_spl_transfer()` for each of them unconditionally, without checking whether the computed amount is non-zero, exactly mirroring the pattern flagged in the external report for `Common._deductFees()`.

### Finding Description
In `lending_pool_collect_bank_fees`, each fee amount is derived as `min(outstanding, available_liquidity).int()` and can legitimately be `0` (e.g. a bank with no group fee configured, or an insurance fee that has already been fully collected/never accrued): [1](#0-0) 

All three computed amounts are then passed straight into `bank.withdraw_spl_transfer(...)` with no `if amount > 0` guard: [2](#0-1) 

`withdraw_spl_transfer` performs an unconditional `transfer_checked` / `invoke_transfer_checked` CPI regardless of the amount: [3](#0-2) 

Marginfi supports Token-2022 mints as bank mints (`maybe_take_bank_mint`, `IS_T22` flag), and the program only rejects mints with nonzero transfer fees or an *active* transfer hook in one narrow path — `lending_pool_emissions_deposit` — via `utils::nonzero_fee` and `utils::has_transfer_hook`: [4](#0-3) [5](#0-4) 

Neither `lending_pool_add_bank`/`add_pool_permissionless` (bank creation) nor `lending_pool_collect_bank_fees` performs this check. A bank can therefore be created on a Token-2022 mint whose `TransferHook` extension points at a hook program that reverts when the transferred `amount == 0` — a legitimate, spec-compliant hook behavior (the SPL Token-2022 program invokes the hook for every transfer, including zero-amount ones). Since fee amounts routinely hit zero (any bank where only one of insurance/group/program fees is outstanding at a given moment), the CPI to a zero-value-rejecting hook will abort the whole instruction with no way to skip the zero leg.

### Impact Explanation
`LendingPoolCollectBankFees` is explicitly documented and implemented as permissionless maintenance (`guides/ADMIN/COLLECTING_FEES.md`) that must run before admin/permissionless fee withdrawal (`LendingPoolWithdrawFees` / `LendingPoolWithdrawFeesPermissionless`) can move funds out of the fee/insurance vaults: [6](#0-5) 
If this instruction always reverts for such a mint, `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, and `collected_program_fees_outstanding` become permanently stuck accounting entries — protocol/group/insurance fees for that bank can never be swept out of the liquidity vault into the respective vaults, a durable freeze of protocol revenue with a real financial effect (permanently inaccessible fees, distinct from validator/administrative-only impact).

### Likelihood Explanation
Requires only that a group admin (or, via `add_pool_permissionless`, potentially without admin gating on some paths) lists a Token-2022 bank whose mint has an active transfer hook implementing "revert on zero transfer" semantics — a plausible, easily constructed token design, and one the codebase's own test suite (`test_transfer_hook` program, `SupportedExtension::TransferHook`) shows is a first-class supported configuration for T22 banks outside the emissions-deposit path. No privileged action or unusual market condition is needed beyond normal fee accrual timing (any bank frequently reaches a state where at least one of the three fee categories is zero).

### Recommendation
Guard each of the three `withdraw_spl_transfer` calls in `lending_pool_collect_bank_fees` with an `if transfer_amount > 0 { ... }` check, matching the mitigation recommended in the source report. Additionally, consider extending the `nonzero_fee`/`has_transfer_hook` rejection checks currently applied only in `lending_pool_emissions_deposit` to bank creation/configuration for any mint used in vault-to-vault fee flows, or otherwise ensure all `withdraw_spl_transfer`/`deposit_spl_transfer` call sites tolerate zero-amount hook-CPI reverts.

### Proof of Concept
1. Create a Token-2022 mint with a `TransferHook` extension pointing at a hook program that reverts when `amount == 0` (as demonstrated feasible by the repo's own `test_transfer_hook` fixture and `SupportedExtension::TransferHook`).
2. Add a marginfi bank for this mint via `lending_pool_add_bank` (no check rejects active transfer hooks at bank creation, unlike the emissions-deposit path).
3. Accrue only, say, group fees on the bank (e.g. via normal borrow/interest activity) while insurance and program fees remain at `0` outstanding.
4. Call `LendingPoolCollectBankFees`. The unconditional `withdraw_spl_transfer` for the zero-amount insurance-fee leg (or program-fee leg) triggers a zero-amount `transfer_checked` CPI, which invokes the transfer hook with `amount = 0`, which reverts — aborting the entire instruction and permanently blocking fee collection for that bank.

/// Returns `true` if the given mint has an active transfer hook program.
/// If the hook is present but no program is active it would return false.
pub fn has_transfer_hook(mint_ai: AccountInfo) -> MarginfiResult<bool> {
    if mint_ai.owner.eq(&Token::id()) {
        return Ok(false);
    }

    let mint_data = mint_ai.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;

    if let Ok(hook) = mint.get_extension::<TransferHook>() {
        let program_id: Option<Pubkey> = Option::from(hook.program_id);
        return Ok(program_id.is_some());
    }

    Ok(false)
}

## How Fees Are Collected

(1) Interset accrues and increases the number in `fees_outstanding` fields. Optionally, origination
fees are charged and do the same.

(2) Anyone (the ix is permissionless) runs `LendingPoolCollectBankFees`. This moves:
* The amount specified in `collected_insurance_fees_outstanding` from the `liquidity_vault` to the
  `insurance_vault`
* The amount specified in `collected_group_fees_outstanding` from the `liquidity_vault` to the `fee_vault`
* The amount specified in `collected_program_fees_outstanding` from the `liquidity_vault` to the
    `fee_ata`, which is the cannonical ATA of the global fee wallet.

Then the `fees_outstanding` are all reset to zero. The vast majority of the time, we run this ix just before a withdraw.

(3) The group admin runs `LendingPoolWithdrawFees`. This moves:
* The amount in `fee_vault` into any account of the group admin's choosing. 

(3a) If the group admin set a destination of choice with `LendingPoolUpdateFeesDestinationAccount`,
then anyone can run `LendingPoolWithdrawFeesPermissionless`, which does the same thing as
`LendingPoolWithdrawFees` but doesn't require permission, and always sends to the account defined by
the group admin (`bank.fees_destination_account`)
