### Title
Orchestrator-managed credit vaults cannot finalize borrower defaults or tune epoch config — missing `finalizeDefault`/`setInstantWithdrawParams`/etc. wrappers permanently freeze defaulted funds - (File: contracts/IdleCreditVaultManagerOrchestrator.sol)

### Summary
This mirrors M-30: privileged functions exist on `IdleCDOEpochVariant` but the contract meant to operate them (`IdleCreditVaultManagerOrchestrator`, set as the vault `manager`/`guardian` by `IdleCreditVaultFactory._configureCreditVault` at `contracts/IdleCreditVaultFactory.sol:288-307`) exposes no wrapper for them. Once the manager role is delegated to the orchestrator, `finalizeDefault()` is unreachable by the operator, so defaulted vaults cannot be finalized and lender funds/receipts stay frozen.

### Finding Description
`IdleCDOEpochVariant` gates `finalizeDefault`, `setInstantWithdrawParams`, `setKeyringParams`, `setIsDepositDuringEpochDisabled`, and `stopEpoch` behind `_checkOnlyOwnerOrManager()` (`contracts/IdleCDOEpochVariant.sol:93-95, 194-225`). The factory designates `manager` as both `guardian` and the privileged operator (`cv.setGuardian(manager)`), and deployments hand that role to `IdleCreditVaultManagerOrchestrator`. The orchestrator wraps only `startEpoch`, `stopEpochWithDuration`, `getInstantWithdrawFunds`, `setEpochParams`, `setStrategyAprsRaw`, `setCanTransfer`, and queue processors (`contracts/IdleCreditVaultManagerOrchestrator.sol:75-154`). Searching for `finalizeDefault` or `setInstantWithdrawParams` selectors in the orchestrator yields nothing — the exact confirmation test from M-30.

Concretely: when `stopEpochWithDuration` catches a failed `getFundsFromBorrower`, `_handleBorrowerDefault` sets `defaulted = true`, pauses deposits, and disables withdraw requests (`contracts/IdleCDOEpochVariant.sol:577-599`). Recovery of active NAV and defaulted receipts then requires `finalizeDefault(_recoveredAmount, _recoverySource)` (owner/manager only), which crystallizes prices, re-enables `allowAAWithdrawRequest`/`allowBBWithdrawRequest`/`allowInstantWithdraw`, and unlocks `claimWithdrawRequest`/`claimInstantWithdrawRequest`/`DefaultDistributor.claim`. The orchestrator cannot call it, and `restoreOperations`/`emergencyShutdown`/`updateAccounting` (owner or guardian=manager) are likewise unreachable via orchestrator wrappers.

### Impact Explanation
Permanent freezing of user funds. If the owner is a governance timelock/multisig that does not (or cannot promptly) perform vault ops — the normal deployment assumption that the orchestrator operates the cluster — a defaulted vault can never be finalized by its designated operator: tranche holders cannot redeem and defaulted receipt holders cannot claim recoveries. Loss equals the full vault NAV plus recoverable amounts.

### Likelihood Explanation
Requires a borrower repayment failure (already an in-scope, intended code path — the `try/catch` default branch is exercised in normal operation) combined with the standard factory wiring where `manager == orchestrator`. No attacker privilege needed; the broken access-path invariant ("manager functions must be reachable through the manager contract") is exactly the M-30 bug class.

### Recommendation
Add wrappers to `IdleCreditVaultManagerOrchestrator` for every owner/manager/guardian function the operator is expected to reach: `finalizeDefault(uint256,address)`, `stopEpoch(uint256,uint256)`, `setInstantWithdrawParams`, `setKeyringParams`, `setIsDepositDuringEpochDisabled`, `setIsInterestMinted`, `setIsProgrammableBorrower`, plus guardian functions `pause`, `unpause`, `emergencyShutdown`, and `updateAccounting`.

### Proof of Concept
Foundry fork PoC sketch:

```solidity
// Deploy factory + orchestrator; create credit vault with manager = orchestrator.
// Lender deposits into AA/BB, requestWithdraw during buffer.
vm.prank(operator);
orchestrator.startEpoch(cdos);            // epoch starts, borrower pulls funds

vm.warp(epochEndDate + 1);
// borrower does NOT approve/repay -> getFundsFromBorrower reverts
vm.prank(operator);
orchestrator.stopEpochWithDuration(actions); // vault enters defaulted state

// Attempt to finalize recovery through the orchestrator:
// (bool ok,) = orchestrator.finalizeDefault(...)  // function does not exist
// Direct call as orchestrator also fails because CDO sees msg.sender = EOA, not manager:
vm.prank(operator);
vm.expectRevert(NotAllowed.selector);
IdleCDOEpochVariant(cdo).finalizeDefault(recovered, recoverySource);

// lender claims remain frozen
vm.expectRevert(); // receipts not finalized / requests disabled
IdleCDOEpochVariant(cdo).claimWithdrawRequest();
assertTrue(IdleCDOEpochVariant(cdo).defaulted());
```
