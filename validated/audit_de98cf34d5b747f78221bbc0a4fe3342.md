### Title
JWT Replay Cache Check-Then-Act Race Allows Concurrent Replay of a Single-Use Trigger Token - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` is meant to allow each signed JWT (`jti`) to authorize exactly one HTTP trigger request, using `jwtReplayCache.isReplay` as the check and `jwtReplayCache.recordUsage` as the effect. These two operations are not atomic: `isReplay` takes an `RLock`, releases it, and only much later — after unrelated authorization-key lookups — does `recordUsage` take a separate `Lock` to mark the token used. Concurrent requests carrying the identical JWT can both pass the replay check before either records usage, mirroring the same class of bug as `matchOneToManyOrders`: state that should gate a one-time action (nonce/JTI marked used) is committed only after the "risky" work has already started, instead of atomically with the check.

### Finding Description
`Authorize` in [1](#0-0)  performs:
1. JWT signature verification
2. `h.jwtCache.isReplay(claims.ID)` — read-locked lookup
3. Authorized-key checks
4. `h.jwtCache.recordUsage(claims.ID)` — write-locked insert (only now is the token marked "used")

The cache primitives themselves are individually thread-safe but the check-then-record sequence across them is not: [2](#0-1) 

Because `HandleUserTriggerRequest` (the JSON-RPC entrypoint reachable by any unprivileged client holding a valid signed JWT) calls `authorizeRequest` → `Authorize` per inbound request, and the gateway processes concurrent user messages, two (or more) simultaneous submissions of the same JWT can each independently observe `isReplay == false` before either calls `recordUsage`. Both then proceed past authorization, through `checkRateLimit`, `setupCallback` (which only dedupes by `req.ID`, not by JWT `jti`) and `sendWithRetries`, which fans the trigger request out to DON nodes and ultimately causes the workflow to execute twice for what should be a single-use, single-JWT trigger: [3](#0-2) 

This is the same root-cause pattern as the reported Infinity Exchange issue: the "nonce used" bookkeeping (there, `isUserOrderNonceExecutedOrCancelled`; here, the JWT replay-cache entry) is written after — rather than atomically with — the check, opening a window where the guarded action can be performed more than once.

### Impact Explanation
An attacker who legitimately possesses one valid signed JWT for a workflow trigger (e.g., a normal caller, or one who captured/observed a single JWT before its short validity window would matter) can race two copies of the same request to the gateway and force the underlying workflow execution to be dispatched more than once via `sendWithRetries`. Since `setupCallback`'s in-flight dedupe only keys on `req.ID` — which the caller also controls and could vary between the racing copies — the JWT-level "one trigger per token" guarantee can be bypassed, defeating the intended single-use authorization semantics and causing unauthorized/duplicate job execution (and any downstream billing or side effects tied to execution count).

### Likelihood Explanation
Exploitation requires only sending the same signed request payload with distinct `req.ID`s concurrently (a client fully controls timing/concurrency of its own submissions), so this is trivially triggerable by any unprivileged token holder without cooperation from the gateway operator or node. The race window is small (a few map operations and key lookups) but standard `race`-style exploitation techniques for TOCTOU windows in shared network services make this practically achievable, especially under load or with slight artificial delay of the authorization-key lookup step in between.

### Recommendation
Make the JWT replay check-and-mark atomic: hold a single write lock (or use a `sync.Map`-style compare-and-swap / `LoadOrStore`) so that `isReplay` and `recordUsage` occur as one indivisible operation, e.g. `if !cache.checkAndRecord(jti) { return alreadyUsedErr }`, performed as the very first authorization step before any other work, and additionally consider keying `setupCallback`'s in-flight dedupe on the JWT `jti` (not just the caller-supplied `req.ID`) to close the secondary race surface.

### Proof of Concept
1. Obtain one valid signed JWT for `workflows.execute` targeting a registered workflow.
2. Fire two (or more) concurrent `HandleUserTriggerRequest` calls to the gateway with that identical `Auth` JWT but distinct `req.ID` values.
3. Both requests can pass `h.jwtCache.isReplay(claims.ID)` (both false) before either finishes `h.jwtCache.recordUsage(claims.ID)`, because `isReplay` and `recordUsage` are separate lock sections in [2](#0-1) .
4. Both requests pass `authorizeRequest` in [4](#0-3)  and proceed to `sendWithRetries`, causing the workflow to be triggered twice from a single JWT.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
