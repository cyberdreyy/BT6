### Title
Confirmations from deleted multisig members remain counted toward the confirmation threshold, allowing execution below the live-member threshold - (File: multisig2/src/lib.rs)

### Summary
`multisig2/src/lib.rs`'s `delete_member` only purges pending *requests originated by* the removed member; it never purges that member's *confirmations* recorded on other members' pending requests. `confirm()` then compares `confirmations.len() + 1 >= self.num_confirmations` without re-validating that every recorded confirmer is still a current member. This lets a request execute (e.g. a `Transfer`) using a stale confirmation from an account/key that was removed from the multisig before execution, so the request is authorized by fewer *live* members than `num_confirmations` requires.

### Finding Description
`confirm()` and `execute_request()` treat the size of the `confirmations: HashSet<String>` for a request as proof that `num_confirmations` distinct, currently-authorized members approved it: [1](#0-0) 

Each individual `confirm()` call does verify the *caller* is currently a member via `assert_valid_request` → `current_member()`: [2](#0-1) [3](#0-2) 

But this check is only applied at the moment each confirmation is added — the set of already-collected confirmations is never re-validated against the live `members` set. `delete_member` only removes pending requests where the removed member was the *original requester* (`r.member == member`), and only cleans up `num_requests_pk`; it does not scan `confirmations` for other requests where the removed member is recorded as a *confirmer*: [4](#0-3) 

As a result, the binding "number of live members whose approval is counted == `num_confirmations`" can be broken: `confirmations.len()` can include an account/key that is no longer in `self.members` at execution time.

### Impact Explanation
This is a Critical-class issue per the custody-binding categories: "a multisig request executed below threshold." An attacker path:
1. Multisig has members A, B, C with `num_confirmations = 2`.
2. Member A creates a `Transfer` request (`add_request`); member B confirms it, so `confirmations = {B}` (len 1, below threshold).
3. Before the request is finalized, a separate, fully-confirmed request executes `DeleteMember { member: B }` (via `delete_member`, called from `execute_request`). This purges any *pending requests B created*, but does not touch the `{B}` confirmation still stored on A's Transfer request.
4. C now calls `confirm()` on A's Transfer request. `confirmations.len() (1) + 1 >= num_confirmations (2)` is true, so the request executes — funds are transferred (`MultiSigRequestAction::Transfer`) even though only one *live* member (C) actually approved it at execution time; B's stale approval, from an account that has since been removed, is what pushed it over the threshold.

This directly breaks the equality "confirmations counted == confirmations from currently live members," letting a request (including a `Transfer` of NEAR out of the multisig account) execute with effectively fewer live approvals than the configured `num_confirmations`.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a pending request with a partial confirmation set, and (b) a subsequent, separately-confirmed `DeleteMember` action removing one of those confirmers, before the original request reaches full confirmation. This is a realistic operational sequence (e.g., revoking a compromised or departing member's key while other requests are in flight) rather than a contrived edge case, and does not require the foundation, a contract owner, or any privileged party beyond the multisig members themselves who are the intended actors of this contract.

### Recommendation
When executing `DeleteMember`, also strip the removed member's entry from every entry in `confirmations` (not just requests they authored), or re-validate at `confirm()`/execution time that every account/key recorded in a request's `confirmations` set is still contained in `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
```rust
// members: A, B, C; num_confirmations = 2
let mut c = MultiSigContract::new(vec![member_a(), member_b(), member_c()], 2);

// A creates Transfer request (id = req1)
let req1 = c.add_request(transfer_request());
// B confirms -> confirmations(req1) = {B}, len=1 < 2, not executed
as_member(&mut c, member_b());
c.confirm(req1);

// Separately, a fully confirmed DeleteMember(B) request executes,
// removing B from `members`, but confirmations(req1) still contains B
let req2 = c.add_request(delete_member_request(member_b()));
as_member(&mut c, member_a());
c.confirm(req2);
as_member(&mut c, member_c());
c.confirm(req2); // reaches threshold, delete_member(B) executes

// C now confirms req1: confirmations(req1).len() (1, from removed B) + 1 >= 2
as_member(&mut c, member_c());
c.confirm(req1); // executes Transfer with only 1 live confirmer (C) + 1 stale confirmer (B, no longer a member)
```

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Returns current member: either predecessor as account or if it's the same as current account - signer.
    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    /// Prevents access to calling requests and make sure request_id is valid - used in delete and confirm
    fn assert_valid_request(&mut self, request_id: RequestId) {
        // request must come from key added to contract account
        assert(
            self.current_member().is_some(),
            "Caller (predecessor or signer) is not a member of this multisig",
        );
        // request must exist
        assert(
            self.requests.get(&request_id).is_some(),
            "No such request: either wrong number or already confirmed",
        );
        // request must have
        assert(
            self.confirmations.get(&request_id).is_some(),
            "Internal error: confirmations mismatch requests",
        );
    }
