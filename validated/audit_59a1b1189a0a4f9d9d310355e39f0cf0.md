### Title
Fork/genesis PTC-window placeholder entries use a fixed sentinel committee `[ValidatorIndex(0), ...]` instead of "no committee", letting validator 0 claim an un-earned Payload-Timeliness-Committee duty for the boundary slot - (File: `specs/gloas/fork.md`, `specs/gloas/beacon-chain.md`)

### Summary
`initialize_ptc_window` allocates the `ptc_window` buffer with a fixed shape and fills the "previous epoch" section with dummy placeholder committees whose members are all `ValidatorIndex(0)`, rather than leaving that section empty/unusable. `get_ptc` later reads directly from this fixed-size buffer without distinguishing genuine, seed/weight-computed committees from these placeholder entries. This mirrors the reported bug class: a buffer is over-allocated and only partially populated with meaningful data, and the unpopulated/placeholder slots (defaulting to index/address zero) are later trusted and processed as if they were real assignments.

### Finding Description
`initialize_ptc_window` (used at genesis and at the Gloas fork) builds the `ptc_window`'s "previous epoch" slice out of sentinel committees: [1](#0-0) 

```python
def initialize_ptc_window(state: BeaconState) -> PayloadTimelinessCommitteeWindow:
    empty_previous_epoch = [
        PayloadTimelinessCommittee(data=[ValidatorIndex(0) for _ in range(PTC_SIZE)])
        for _ in range(SLOTS_PER_EPOCH)
    ]
    ...
    return PayloadTimelinessCommitteeWindow(data=empty_previous_epoch + ptcs)
```

Every slot in the "previous epoch" section is assigned a committee consisting of `PTC_SIZE` copies of `ValidatorIndex(0)`, instead of a real `compute_ptc` result (which normally selects committee members by a balance-weighted, seed-driven sampling over the actual beacon committees for that slot): [2](#0-1) 

`get_ptc` then reads straight from this buffer for any slot whose epoch is one behind the current epoch, with no check that the entry is a genuine committee rather than the fork/genesis placeholder: [3](#0-2) 

```python
def get_ptc(state: BeaconState, slot: Slot) -> PayloadTimelinessCommittee:
    epoch = compute_epoch_at_slot(slot)
    state_epoch = get_current_epoch(state)
    if epoch < state_epoch:
        assert epoch + 1 == state_epoch
        return state.ptc_window[slot % SLOTS_PER_EPOCH]
    ...
```

The equality that should hold is: "membership in the payload timeliness committee for slot S is exactly the set returned by `compute_ptc(state, S)`'s balance-weighted seed sampling." Immediately after genesis/the Gloas fork, for any slot in the epoch preceding the current one, `get_ptc` instead returns the fixed placeholder `[0, 0, ..., 0]` (`PTC_SIZE` copies of validator index 0), which was never actually computed by `compute_ptc` for that slot. This breaks the equality: validator 0 is treated as (and duplicated `PTC_SIZE` times as) a committee member for that slot, when no legitimate seed-based selection ever assigned it that duty.

This placeholder section is discarded on the next epoch transition by `process_ptc_window`, which shifts the window and overwrites the discarded region with newly computed committees: [4](#0-3) 

so the window of exposure is exactly the slots between genesis/fork and the first subsequent epoch boundary — i.e., precisely the "previous epoch" section as accessed via `get_ptc`'s `epoch < state_epoch` branch, which is reachable from the very first block after the fork whose parent slot falls in the pre-fork epoch (block processing passes `parent_slot` into payload-attestation processing, and `get_indexed_payload_attestation`/gossip validation both resolve committee membership via `get_ptc(state, data.slot)`): [5](#0-4) [6](#0-5) 

### Impact Explanation
If reachable in a real block/gossip context, this lets validator index 0 assert (and have accepted as valid) a `PayloadAttestationMessage`/`PayloadAttestation` for the boundary slot without ever having been legitimately selected by the balance-weighted PTC sampling for that slot - a duty-selection outcome steerable by a single, always-known participant (validator 0), rather than one determined by the protocol's random, stake-weighted process. Because PTC votes feed into builder-payment quorum accounting (`get_builder_payment_quorum_threshold`/`process_builder_pending_payments`), and the placeholder committee awards validator 0 `PTC_SIZE` duplicate "seats," this could inflate the vote weight attributed to a single validator's signature toward reaching quorum, potentially affecting whether a builder payment is approved for that slot boundary. This corresponds to the "High" impact category: a duty selection one participant can steer, with a possible downstream effect on builder payment quorum.

### Likelihood Explanation
The condition triggers deterministically at every genesis and every fork to Gloas (not just this specific fork upgrade, given the same pattern would need to be replicated by any future fork transition helper), for the fixed, one-epoch-long window before `process_ptc_window` first runs. No adversarial coordination or client bug is required - it is a property of the spec's own initialization code (`initialize_ptc_window`) and the following consumer (`get_ptc`). The main uncertainty (not fully verified due to tool-call limits) is whether `process_payload_attestation`'s block-processing assertions impose an additional restriction tying `data.slot` strictly to the current epoch that would prevent a payload attestation from referencing the pre-fork/pre-genesis boundary slot in practice; the gossip-time check (`validate_payload_attestation_message_gossip`) only restricts messages to the *current* slot but does not on its own rule out this boundary case for the block-inclusion path. This should be confirmed against the full text of `process_payload_attestation` before treating exploitability as certain.

### Recommendation
Do not fill the placeholder "previous epoch" section of `ptc_window` with a fixed, always-valid-looking committee (`PTC_SIZE` copies of `ValidatorIndex(0)`). Instead, either: (a) mark these slots as explicitly invalid/empty (e.g., using a sentinel that `get_ptc`/its callers explicitly reject, or make `PayloadTimelinessCommittee` optional for this window and add an explicit guard in `get_ptc` and `get_indexed_payload_attestation`/gossip validation to reject processing/attesting to any slot in the pre-genesis/pre-fork placeholder region), or (b) avoid ever calling `get_ptc` for slots preceding genesis/the fork epoch by asserting this at the call sites (`process_payload_attestation`, gossip validation) in addition to the existing `epoch + 1 == state_epoch` assertion.

### Proof of Concept
Conceptual reproduction (spec-level, no client bug required):
1. Advance a state to genesis or to `GLOAS_FORK_EPOCH`, and call `initialize_ptc_window(state)` (as done automatically by the fork/genesis process). Observe `state.ptc_window[0:SLOTS_PER_EPOCH]` consists solely of `PayloadTimelinessCommittee(data=[ValidatorIndex(0)] * PTC_SIZE)` for every slot.
2. Call `get_ptc(state, slot)` for any `slot` in the epoch immediately preceding `get_current_epoch(state)` (the boundary epoch). It returns `[0]*PTC_SIZE` rather than a `compute_ptc`-derived committee.
3. Construct a `PayloadAttestationMessage`/`PayloadAttestation` with `validator_index = 0` (or `attesting_indices = [0]`) for that boundary slot; `validate_payload_attestation_message_gossip`'s check `validator_index not in get_ptc(state, data.slot)` and `get_indexed_payload_attestation`'s `attesting_indices` derivation both succeed, because `0 in [0]*PTC_SIZE` is trivially true, even though `compute_ptc` was never actually run for that slot/epoch.

This confirms that the fixed-size placeholder buffer, populated with a sentinel default (`ValidatorIndex(0)`) rather than left truly empty, is trusted by downstream consumers (`get_ptc`, gossip validation, `get_indexed_payload_attestation`) exactly as the external report describes for oversized/partially-populated arrays in `FeeConversionKeeper`.

def initialize_ptc_window(
    state: BeaconState,
) -> PayloadTimelinessCommitteeWindow:
    """
    Return the cached PTC window starting from the current epoch.
    Used to initialize the ``ptc_window`` field in the beacon state at genesis and after forks.
    """
    empty_previous_epoch = [
        PayloadTimelinessCommittee(data=[ValidatorIndex(0) for _ in range(PTC_SIZE)])
        for _ in range(SLOTS_PER_EPOCH)
    ]

    ptcs = []
    current_epoch = get_current_epoch(state)
    for e in range(1 + MIN_SEED_LOOKAHEAD):
        epoch = current_epoch + e
        start_slot = compute_start_slot_at_epoch(epoch)
        ptcs += [compute_ptc(state, start_slot + i) for i in range(SLOTS_PER_EPOCH)]

    return PayloadTimelinessCommitteeWindow(data=empty_previous_epoch + ptcs)

def compute_ptc(state: BeaconState, slot: Slot) -> PayloadTimelinessCommittee:
    """
    Get the payload timeliness committee, with possible duplicates, for the given ``slot``.
    """
    epoch = compute_epoch_at_slot(slot)
    seed = sha256(get_seed(state, epoch, DOMAIN_PTC_ATTESTER) + uint_to_bytes(slot))
    indices: list[ValidatorIndex] = []
    # Concatenate all committees for this slot in order
    committees_per_slot = get_committee_count_per_slot(state, epoch)
    for i in range(committees_per_slot):
        committee = get_beacon_committee(state, slot, CommitteeIndex(i))
        indices.extend(committee)
    return PayloadTimelinessCommittee(
        data=compute_balance_weighted_selection(
            state, indices, seed, size=PTC_SIZE, shuffle_indices=False
        )
    )

def get_ptc(state: BeaconState, slot: Slot) -> PayloadTimelinessCommittee:
    """
    Get the payload timeliness committee for the given ``slot``.
    """
    epoch = compute_epoch_at_slot(slot)
    state_epoch = get_current_epoch(state)
    if epoch < state_epoch:
        assert epoch + 1 == state_epoch
        return state.ptc_window[slot % SLOTS_PER_EPOCH]
    assert epoch <= state_epoch + MIN_SEED_LOOKAHEAD
    offset = Uint64(epoch - state_epoch + 1) * SLOTS_PER_EPOCH
    return state.ptc_window[offset + slot % SLOTS_PER_EPOCH]

def get_indexed_payload_attestation(
    state: BeaconState, payload_attestation: PayloadAttestation
) -> IndexedPayloadAttestation:
    """
    Return the indexed payload attestation corresponding to ``payload_attestation``.
    """
    slot = payload_attestation.data.slot
    ptc = get_ptc(state, slot)
    bits = payload_attestation.aggregation_bits
    attesting_indices = [index for i, index in enumerate(ptc) if bits[i]]

    return IndexedPayloadAttestation(
        attesting_indices=PayloadTimelinessCommitteeIndices(data=sorted(attesting_indices)),
        data=payload_attestation.data,
        signature=payload_attestation.signature,
    )

def process_ptc_window(state: BeaconState) -> None:
    """
    Update the cached PTC window.
    """
    # Shift all epochs forward by one
    state.ptc_window[: len(state.ptc_window) - SLOTS_PER_EPOCH] = state.ptc_window[SLOTS_PER_EPOCH:]
    # Fill in the last epoch
    next_epoch = get_current_epoch(state) + MIN_SEED_LOOKAHEAD + 1
    start_slot = compute_start_slot_at_epoch(next_epoch)
    state.ptc_window[len(state.ptc_window) - SLOTS_PER_EPOCH :] = [
        compute_ptc(state, Slot(slot)) for slot in range(start_slot, start_slot + SLOTS_PER_EPOCH)
    ]
