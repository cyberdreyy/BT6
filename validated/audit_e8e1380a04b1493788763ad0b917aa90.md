### Title
Single-recipient opt-out DoS in `vesting::distribute` permanently locks unlocked stake for all other shareholders - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute` iterates over every shareholder in a `VestingContract`'s `grant_pool` in one loop and pays each one via `aptos_account::deposit_coins`. If any single recipient in that loop has disabled direct coin transfers via `aptos_account::set_allow_direct_coin_transfers(false)` and is not already registered for legacy `CoinStore<AptosCoin>`, that one `deposit_coins` call aborts the entire transaction, and since the redemption of shares happens inside the same atomic loop, **no shareholder can ever be paid again** until the offending account changes its own setting — something the admin, the other shareholders, and the protocol have no power to force or work around.

### Finding Description
`distribute` withdraws all distributable stake once, then loops over `grant_pool.shareholders()` and calls `aptos_account::deposit_coins(recipient_address, share_of_coins)` for each one: [1](#0-0) 

`aptos_account::deposit_coins` only auto-registers a `CoinType` for the recipient if `can_receive_direct_coin_transfers` is true; otherwise it aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`: [2](#0-1) 

`can_receive_direct_coin_transfers` is controlled entirely by the target account itself via the unprivileged, self-callable `set_allow_direct_coin_transfers`: [3](#0-2) 

Crucially, `create_vesting_contract` only validates that the `withdrawal_address` is registered for APT — it never validates that any of the `shareholders` are (and cannot be, because registration can change post-creation anyway): [4](#0-3) 

Because `distribute` (and `distribute_many`) has no per-recipient error isolation — the whole function aborts if one `deposit_coins` call fails — any shareholder can unilaterally and permanently deny distribution of unlocked/vested stake to every other shareholder in the same `VestingContract`, simply by disabling direct coin transfers on their own account while remaining unregistered for legacy `CoinStore<AptosCoin>`. The identical shared-loop, no-isolation pattern also exists in `staking_contract::distribute_internal`, which pays out to the staker and to `beneficiary_for_operator(operator)` in one loop with the same `aptos_account::deposit_coins` call: [5](#0-4) 

### Impact Explanation
This directly matches the "Permanent lock or non-recoverable loss of claim rights in ... vesting flows" impact class. A single shareholder (an unprivileged, ordinary participant with no elevated role) can permanently freeze the unlock/distribute path for all co-shareholders in a shared vesting contract. There is no admin override, no way to skip or evict the misbehaving shareholder from the loop, and no partial-distribution fallback — funds that have already been unlocked from the stake pool become stuck inside the vesting contract indefinitely (or until the blocking account voluntarily re-enables direct transfers, which an adversary or griefer has no incentive to do).

### Likelihood Explanation
Any account holding a share in a vesting contract can trigger this with a single, ordinary transaction (`set_allow_direct_coin_transfers(false)`), requiring no privilege escalation, no cooperation from the admin, and no race conditions — it is fully reachable by an unprivileged shareholder at any time before their first-ever distribution registers them for `CoinStore<AptosCoin>`.

### Recommendation
- In `create_vesting_contract` (and equivalently for `staking_contract`'s distribution paths), require or verify all shareholders/recipients are and remain registered for APT (`coin::is_account_registered<AptosCoin>`) before allowing distribution to proceed with them included, similar to the existing `assert_account_is_registered_for_apt(withdrawal_address)` check.
- More robustly, make `distribute_internal`/`distribute` resilient to individual recipient failures — e.g., skip/queue a recipient's payout (leaving their shares un-redeemed) instead of aborting the whole batch when `deposit_coins` would fail, so one uncooperative account cannot block payouts to everyone else.

### Proof of Concept
1. Admin creates a vesting contract with shareholders A and B via `create_vesting_contract`.
2. Shareholder B never held legacy `CoinStore<AptosCoin>` (post FA-migration default) and calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own account.
3. Vesting period elapses; anyone calls `vest`/`vest_many` then `distribute(contract_address)`.
4. In `distribute`, the loop reaches shareholder B, calls `aptos_account::deposit_coins(B, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` since B is unregistered and has opted out.
5. The whole `distribute` transaction reverts; shareholder A's already-vested/unlocked stake remains stuck in the contract with no way to withdraw it as long as B keeps direct transfers disabled — B has thus imposed a permanent lock on A's funds using an ordinary, unprivileged self-call.

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
    /// receive.
    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
    }
