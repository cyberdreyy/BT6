### Title
Unauthenticated-role-gate on pprof debug endpoints allows any authenticated user (including view-role) to dump process memory - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` is mounted at line 446 inside the `authv2` group, which only enforces authentication (session or API token) via `auth.Authenticate`, with no `auth.RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrapper applied to any of the pprof handlers. Every other sensitive route in this block (keys export/import, transfers, admin user management, etc.) is explicitly wrapped with a role-gating function, but the pprof group is not, allowing a view-role authenticated user to reach `/v2/debug/pprof/heap`, `/goroutine`, `/trace`, `/profile`, `/allocs`, etc.

### Finding Description
`v2Routes` builds `authv2 := r.Group("/v2", auth.Authenticate(...))` [1](#0-0)  which only verifies the caller has a valid session or API token — it performs no role check. Throughout the group, sensitive handlers are individually wrapped with `auth.RequiresEditRole`, `auth.RequiresRunRole`, or `auth.RequiresAdminRole` (e.g. key export/import, transfers, job spec deletion) [2](#0-1) [3](#0-2) . However, `metricRoutes(authv2)` is called unwrapped at the end of the block: `// Debug routes accessible via authentication` followed by `metricRoutes(authv2)` [4](#0-3) .

Inside `metricRoutes`, all `net/http/pprof` handlers (`Index`, `Cmdline`, `Profile`, `Symbol`, `Trace`, and `Handler("allocs"/"block"/"goroutine"/"heap"/"mutex"/"threadcreate")`) are registered with no role wrapper: [5](#0-4) .

`auth.Authenticate` only checks that authentication succeeds and sets the user in context; it does not inspect role [6](#0-5) . The role-checking is only performed by the separate `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrapper functions [7](#0-6) , which are never applied to the pprof routes. Because `UserRoleView` is the lowest privilege level and is explicitly rejected only by `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` (not by base `Authenticate`), a view-role user's valid session token is sufficient to reach `GET /v2/debug/pprof/heap`, `/v2/debug/pprof/goroutine`, `/v2/debug/pprof/trace`, and `/v2/debug/pprof/profile`, all of which return raw memory/goroutine/stack dumps of the running node process to the client.

### Impact Explanation
A view-role (or run-role) authenticated user — the lowest privilege tier in this application — can retrieve full heap dumps (`/heap`), goroutine stacks (`/goroutine`), CPU/execution traces (`/trace`), and profiling data (`/profile`) of the chainlink node process. These dumps can contain private key material held in memory (ETH/OCR/P2P/VRF/CSA keys), session tokens, database credentials, and other secrets that are normally protected behind admin-only endpoints (`RequiresAdminRole` gates all explicit key export routes). This matches the bounty impact class of secret/key material disclosure and privilege escalation via unauthorized access to sensitive internal debug interfaces.

### Likelihood Explanation
Minimal precondition: any valid view-role session or API token (the lowest privilege role that can be created) is sufficient. No other exploitation steps, timing, or race conditions are required — a single unauthenticated-role-gated GET request reaches the raw pprof handler. This is fully repeatable and deterministic.

### Recommendation
Wrap all pprof routes registered in `metricRoutes` with an appropriate role gate (at minimum `auth.RequiresAdminRole`, consistent with other sensitive/introspective endpoints like key export/import and log level patching), e.g. change each `pprofGroup.GET(...)` call to `pprofGroup.GET("/heap", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP)))` and similarly for the other pprof routes in `core/web/router.go`.

### Proof of Concept
Go handler-level integration test (in `core/web` test package, following the pattern of existing router tests):
1. Start the test app/router via the existing test harness (e.g. `setupApp`/`app.NewApplication` used in `core/web/*_test.go`), create a user/session with `clsessions.UserRoleView`.
2. Issue `GET /v2/debug/pprof/heap` with the view-role session cookie or API token set.
3. Assert response status is `403 Forbidden` (expected after fix) — currently the test would show `200 OK` with pprof binary/heap dump content, confirming the vulnerability.
4. Repeat for `/v2/debug/pprof/goroutine`, `/v2/debug/pprof/trace`, `/v2/debug/pprof/profile` to confirm all pprof sub-routes are exposed identically.
5. As a control, assert that an admin-role session still receives `200 OK` for the same endpoints (if intended to remain admin-accessible after remediation).

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
