### Title
Gateway `savedCallbacks` keyed only by attacker-controlled `MessageId` allows response hijacking across tenants - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores the caller's response callback in `h.savedCallbacks` keyed solely by the client-supplied `msg.Body.MessageId`, with no binding to the sender's identity. Because `MessageId` is fully attacker-chosen (only length/format constrained by `Message.Validate`), an attacker who submits a request using the same `MessageId` as a victim's in-flight request overwrites the victim's saved callback, causing the eventual DON node response for the victim's request to be delivered to the attacker instead.

### Finding Description
In `HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go:411-412`), the handler does:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
```
The map key is `msg.Body.MessageId`, which comes directly from the JSON-RPC request `ID`/legacy `message_id` field set by the caller (`core/services/gateway/gateway.go` `ProcessRequest`, and `api/message.go` `Message.Validate`, which only checks length ≤128 and non-null-terminated — it does not derive or scope the key from the sender address). Any two distinct signers (different private keys, i.e., different tenants/senders) can therefore choose the identical `MessageId` string.

When the DON node later responds, `HandleNodeMessage` dispatches to `handleWebAPITriggerMessage` (`handler.go:148-162`), which looks the callback up **purely by `msg.Body.MessageId`**:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
return savedCb.SendResponse(...)
```
There is no check that the callback owner matches the sender who originated the request tied to that response. Consequently, if an attacker sends a request with the same `MessageId` as a victim's still-pending request (a race window that exists between the victim's `HandleLegacyUserMessage` call and the arrival of the node's response, which can take up to `MaxAllowedMessageAgeSec`/until nodes reply), the attacker's `HandleLegacyUserMessage` call overwrites `h.savedCallbacks[MessageId]` with the attacker's own callback. When the genuine DON response for the victim's original request arrives (still carrying the same `MessageId`, since nodes echo it back), it is delivered to the attacker's callback, leaking the victim's trigger response content to the attacker — a violation of the request-binding invariant that a gateway request/response must be attributable to exactly one authenticated sender.

None of the existing checks stop this: `Message.Validate()` only verifies length/signature validity of the *attacker's own* message, not uniqueness or ownership of `MessageId` relative to other senders; `HandleNodeMessage` only checks that the *node* sender matches the DON member address (`handler.go:253`), not that the response is tied to the same client who submitted the original request.

### Impact Explanation
This is a cross-user response confusion: an attacker can receive another tenant's Web API trigger response payload (e.g., pricing data, execution results) intended for a different signer, without needing to compromise that signer's key. This matches the "unauthorized action on / information disclosure of another user's job/request" bounty impact class scoped to the gateway.

### Likelihood Explanation
Exploitation requires only (1) an unprivileged attacker capable of signing and submitting a gateway request with any private key (no special role needed — anyone can call `web_api_trigger` with a valid ECDSA signature) and (2) knowledge or prediction of the victim's `MessageId` and a successful race within the callback's lifetime window (up to `CallbackMaxAgeSec`, default 120s). `MessageId` values are chosen by callers/workflow clients (e.g., often deterministic identifiers like execution IDs), making prediction plausible in many real deployments, and the race window (seconds) is generous compared to typical attacker automation. The bug is deterministic once the collision and timing are achieved — repeated collisions simply repeat the hijack.

### Recommendation
Scope `savedCallbacks` keys by both `MessageId` and the requester's sender address (e.g., `sender+":"+MessageId`), and/or store the originating sender alongside the callback and verify it matches before invoking `SendResponse`. Reject re-registration of an in-flight `MessageId` from a different sender, and consider server-generated/unique message IDs instead of trusting client-supplied ones for callback correlation.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response

		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	var isLegacyRequest = false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonId == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonId
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}
