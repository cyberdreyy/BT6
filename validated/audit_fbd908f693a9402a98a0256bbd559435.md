Found a concrete, unauthenticated-bypass analog. The gateway's legacy WebAPI trigger handler contains an explicit gap where the sender allowlist/rate-limit check that should gate which external users can invoke a workflow trigger is never actually applied at the gateway ingress point — it is deferred (via a `TODO`) and only enforced later, per-node, inside each individual capability node's `triggerConnectorHandler.processTrigger`. This mirrors the Astaria bug pattern: a security-critical validation (bid vs. `liquidationInitialAsk`) is supposed to gate before a state-changing action is fanned out, but the enforcement point checks against the wrong/insufficient state (here: no check at all at the gateway, only later re-validated independently per-node), allowing the "old"/unchecked path (the fan-out to nodes) to proceed before the real check happens.

### Title
Gateway `HandleLegacyUserMessage` fans out WebAPI trigger requests to all DON nodes before any sender allowlist or rate-limit check is applied - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` in the gateway's WebAPI capabilities handler validates only payload structure and message staleness before broadcasting an incoming user-supplied trigger request to every member of the DON. The allowlist/sender authorization and rate-limiting are explicitly deferred with a `TODO: apply allowlist and rate-limiting here` comment, meaning the gateway itself performs no authorization gate on who may trigger a workflow before dispatching to all nodes.

### Finding Description
In `HandleLegacyUserMessage`, the request pipeline is: decode payload → check `Timestamp != 0` → check message is not stale → (TODO: allowlist/rate-limit) → check method is `MethodWebAPITrigger` → convert to node request → broadcast to every `h.donConfig.Members` via `don.SendToNode`. [1](#0-0) [2](#0-1) 

The actual sender/topic allowlist check (`trigger.allowedSenders[sender.String()]`) and per-sender rate limiting only occur later, independently, inside each capability node's own `triggerConnectorHandler.processTrigger`, once the message has already reached the node over the gateway connection: [3](#0-2) 

This is the same structural flaw as the referenced Astaria `_buyoutLien()` bug: a critical gating check (bid/debt validation there, sender authorization here) is expected to run before an irreversible/broadcast action is taken, but the code path that actually performs the broadcast (`_replaceStackAtPositionWithNewLien` there, `don.SendToNode` fan-out here) executes using unchecked/incomplete state, deferring the real validation to a later, disconnected point that the initiating component does not control or verify the outcome of. The gateway has no way to know if any node's later allowlist check will reject the request, and by the time it does, the message has already been broadcast to (and processed/logged/rate-limit-consumed by) every DON member.

The accompanying test suite explicitly documents this gap is untested and unresolved: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated`. [4](#0-3) 

### Impact Explanation
Any unprivileged external caller able to reach the gateway's legacy user message endpoint can force every node in a DON to process (and expend rate-limit/compute budget on) an unauthorized `web_api_trigger` message before any node-side allowlist rejects it. Because the gateway does not gate on sender authorization first, this allows an unprivileged actor to consume gateway-to-node bandwidth and per-node processing across the entire DON membership for messages that will ultimately be rejected only after fan-out, and the gateway itself performs no rate-limiting of the sender at the ingress point that would prevent such repeated broadcasts.

### Likelihood Explanation
This path is reachable directly from any unprivileged client via `HandleLegacyUserMessage` and requires no special node compromise — it is purely a missing gate on the gateway ingress code path, as explicitly flagged by the in-code `TODO` and the corresponding untested gap noted in the test file.

### Recommendation
Enforce sender allowlist checks and rate-limiting at the gateway (`HandleLegacyUserMessage`) before broadcasting to `don.SendToNode`, mirroring the pattern already used in `authorizeRequest`/`checkRateLimit` of the newer `httpTriggerHandler.HandleUserTriggerRequest` path [5](#0-4) , so unauthorized requests are rejected before consuming DON-wide resources rather than only being rejected per-node after fan-out.

### Proof of Concept
1. Submit a signed `api.Message` with `Method = MethodWebAPITrigger` and a valid non-stale `Timestamp` to the gateway's legacy user message endpoint, using any signer key not present in any workflow's `AllowedSenders`.
2. Observe that `HandleLegacyUserMessage` passes the message through payload/timestamp checks (no allowlist check exists at this layer) and calls `don.SendToNode` for every DON member. [6](#0-5) 
3. Each node's `triggerConnectorHandler.processTrigger` only rejects the message after receiving and processing it, per node. [7](#0-6)

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {

				nil,
