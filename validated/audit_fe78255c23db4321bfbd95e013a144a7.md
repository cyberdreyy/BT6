## Analog Found

### Title
Unsynchronized read of `WorkflowMetadataHandler.authorizedKeys` in `Authorize()` races with periodic lock-protected writes in `syncMetadata()` - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` reads the `h.authorizedKeys` map without acquiring `h.mu`, while `syncMetadata`, run on a periodic ticker, reassigns the same field under a full write lock. This mirrors the reported `guageBuffered()` bug class: an unsynchronized read of shared mutable state that is concurrently written under a mutex elsewhere on a ticker cadence.

### Finding Description
`WorkflowMetadataHandler.authorizedKeys` (and `workflowRefToID`/`workflowIDToRef`) are protected by `h.mu sync.RWMutex` everywhere else in the file — `WorkflowShards`, `GetWorkflowID`, and `GetWorkflowReference` all correctly take `h.mu.RLock()`/`RUnlock()` before touching this state [1](#0-0) [2](#0-1) .

However, `Authorize` — the function that verifies a caller's JWT against the workflow's registered signer set — reads `h.authorizedKeys[workflowID]` with no lock at all: [3](#0-2) 

Meanwhile, `syncMetadata`, invoked periodically via `runTicker(time.Duration(h.config.MetadataAggregationIntervalMs)*time.Millisecond, h.syncMetadata)` [4](#0-3) , rebuilds and swaps `h.authorizedKeys` (and the other three maps) under `h.mu.Lock()`: [5](#0-4) 

`Authorize` is called from `http_trigger_handler.go` in the path that handles inbound, unprivileged user HTTP trigger requests (JWT-based authorization for the request), so it is directly reachable from an untrusted client's request whenever it races with the ticker-driven `syncMetadata` swap.

### Impact Explanation
This is a Go data race on the `h.authorizedKeys` map header/reference: one goroutine (attacker-triggered `Authorize` call from an inbound HTTP trigger request) reads the field while the ticker goroutine concurrently writes a brand-new map to the same field under lock. Per the Go memory model this is undefined behavior — under `go test -race`/production this can manifest as a torn read of the map reference, a `fatal error: concurrent map read and write` panic (crashing the whole gateway process, i.e., a DoS reachable by any external HTTP-trigger caller), or, in the least severe case, a stale/inconsistent authorized-key set being consulted for signer verification. This directly parallels the reported bug class (`b.buffer`/`prices` read unprotected by a mutex, mutated on a ticker cadence), just against a map field instead of a byte buffer.

### Likelihood Explanation
`syncMetadata` runs on every tick of `MetadataAggregationIntervalMs`, and `Authorize` is invoked on every unprivileged HTTP trigger request carrying a JWT. Any request landing during a tick's read/write window triggers the race — this is a routine, continuously recurring condition, not a rare edge case, and requires no special privileges or timing precision beyond normal request traffic overlapping with the periodic sync.

### Recommendation
Take `h.mu.RLock()`/`RUnlock()` around the `h.authorizedKeys[workflowID]` lookup in `Authorize`, consistent with the locking discipline already used in `WorkflowShards`, `GetWorkflowID`, and `GetWorkflowReference`.

### Proof of Concept
Not directly executable in ask-only mode, but the race is reproducible by running the gateway with `-race`, sending concurrent `HandleJSONRPCUserMessage`/HTTP-trigger requests that invoke `Authorize` while `MetadataAggregationIntervalMs` ticks fire `syncMetadata` in the background — the race detector will flag concurrent unsynchronized access to `h.authorizedKeys`.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (h *WorkflowMetadataHandler) WorkflowShards(workflowID string) []*shardEndpoint {
	h.mu.RLock()
	defer h.mu.RUnlock()
	shards := h.workflowShards[workflowID]
	out := make([]*shardEndpoint, len(shards))
	copy(out, shards)
	return out
}

func (h *WorkflowMetadataHandler) GetWorkflowID(workflowOwner, workflowName, workflowTag string) (string, bool) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	workflowRef := workflowReference{
		workflowOwner: workflowOwner,
		workflowName:  workflowName,
		workflowTag:   workflowTag,
	}
	workflowID, exists := h.workflowRefToID[workflowRef]
	if !exists {
		return "", false
	}
	return workflowID, true
}

func (h *WorkflowMetadataHandler) GetWorkflowReference(workflowID string) (workflowReference, bool) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	workflowRef, exists := h.workflowIDToRef[workflowID]
	return workflowRef, exists
}
