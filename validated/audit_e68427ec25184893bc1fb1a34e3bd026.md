### Title
Missing handler-level DON authorization allows any self-signed legacy message to be routed and forwarded to an arbitrary DON's nodes - ([File: core/services/gateway/gateway.go])

### Summary
`gateway.ProcessRequest` routes legacy messages (`Body.DonId != ""`) to a handler purely by map lookup on the attacker-supplied `DonId`, after calling `msg.Validate()`, which only checks structural/format validity and recovers the signer from the signature — it never checks that the signer is a member of, or otherwise entitled to reach, that DON. The downstream capabilities handler that processes the message has a literal `// TODO: apply allowlist and rate-limiting here` marker confirming no sender/DON authorization is enforced before the message is fanned out to all of that DON's node members.

### Finding Description
In `gateway.ProcessRequest`, for a legacy request the flow is: [1](#0-0) 

`msg.Validate()` only checks lengths/format of `MessageId`, `Method`, `DonId`, `Receiver`, and the signature, then calls `ExtractSigner()` to populate `Body.Sender` from whatever key signed the message: [2](#0-1) 

Nothing in `Validate()` or in `ProcessRequest` checks that the recovered `Sender` is a member/allowlisted participant of the DON identified by `Body.DonId`. `handlerKey = msg.Body.DonId` and `h, ok = g.handlers[handlerKey]` is a pure existence check on a known DON ID string, not an authorization check tied to the caller's identity.

The request is then forwarded straight to `h.HandleLegacyUserMessage(ctx, msg, callback)`. In the capabilities handler implementation, this function decodes the payload, checks timestamp freshness and method name, and then sends the message to every member node of that DON — with an explicit code comment acknowledging the missing allowlist check: [3](#0-2) 

The dummy handler exhibits the same pattern — no sender/DON membership check before broadcasting to `donConfig.Members`: [4](#0-3) 

An attacker who knows (or enumerates) a valid `DonId` string can self-sign a `Message` with any private key, pass `msg.Validate()` (signature format/self-consistency check succeeds trivially for a self-signed message), get routed to that DON's handler via the plain map lookup, and have their crafted trigger payload forwarded to all of that DON's node members — despite having no allowlist/subscription relationship with that DON.

### Impact Explanation
This enables request impersonation / unauthorized triggering of DON node processing for a DON the attacker has no relationship with, matching a Chainlink bounty impact class of authorization bypass / unauthorized job trigger via the gateway. The concrete blast radius is bounded by what the node-side capability does with an unauthorized trigger (e.g., a workflow trigger capability may perform further sender checks itself), but at the gateway/handler layer — which is the layer named in the audited function — there is no authorization gate at all, only a routing-existence check plus a TODO acknowledging the gap.

### Likelihood Explanation
Preconditions are minimal: any unprivileged attacker who can reach the gateway's public HTTP endpoint and knows/guesses a valid `DonId` (DON IDs are often not secret — they may be discoverable via service configuration, other error messages such as `Unsupported DON ID: ...`, or documentation) can self-sign an arbitrary message with any keypair they control. No allowlist membership, node key, or prior relationship with the target DON is required. This is trivially repeatable and scriptable.

### Recommendation
Add a per-DON sender allowlist/authorization check before dispatching a legacy message to a handler — either in `gateway.ProcessRequest` right after `msg.Validate()` (checking `msg.Body.Sender` against the DON's configured/authorized sender set for `handlerKey`), or inside each handler's `HandleLegacyUserMessage` (replacing the `// TODO: apply allowlist and rate-limiting here` comment in `core/services/gateway/handlers/capabilities/handler.go` with an actual enforcement). Reject requests from senders not entitled to that DON with `api.UnsupportedDONIdError` or a dedicated authorization error before any node fan-out occurs.

### Proof of Concept
Table-driven Go test in `core/services/gateway/gateway_test.go`:
1. Configure a gateway with two DONs, `donA` (with a real, expected member/allowlisted sender key) and `donB` (unrelated), each backed by `handlers.NewDummyHandler` or the capabilities handler.
2. Generate an attacker key never registered/allowlisted for `donA`.
3. Build and sign (via `msg.Sign(attackerKey)`) a legacy `api.Message` with `Body.DonId = "donA"` and a valid method/payload.
4. Call `gw.ProcessRequest(ctx, rawRequest, "")`.
5. Assert (expected, currently failing): the response is an authorization error and the mock/dummy handler for `donA` never has `HandleLegacyUserMessage`/`SendToNode` invoked for the attacker's message.
6. Current behavior (proving the bug): `msg.Validate()` succeeds, `ProcessRequest` returns 200/handler success, and `HandleLegacyUserMessage` forwards the attacker's message to `donA`'s node members despite the attacker never having any allowlist/subscription relationship with `donA`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageId] = &savedCallback{msg.Body.MessageId, callback}
	don := d.don
	d.mu.Unlock()
	params, err := json.Marshal(msg)
	if err != nil {
		return err
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
