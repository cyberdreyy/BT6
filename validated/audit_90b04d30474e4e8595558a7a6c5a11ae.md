### Title
AddKeyAction for gas keys performs N unmetered trie writes (`set_gas_key_nonce`) with zero compute charge, priced identically to a single-write regular AddKey - ([File: runtime/runtime/src/access_keys.rs])

### Summary
`add_gas_key` writes `num_nonces` (up to `MAX_NONCES_FOR_GAS_KEY = 1024`) independent nonce trie entries in a `for` loop via `set_gas_key_nonce`, but only accounts for the extra bytes as *storage usage* (staking cost), never charging any *compute* for performing those additional writes. The AddKeyAction's send/exec fee (`gas_key_add_key_send_fee`/`gas_key_add_key_exec_fee` in `core/parameters/src/cost.rs`) is a fixed action fee independent of `num_nonces`, so an attacker paying storage-staking rent for the extra bytes gets N trie writes performed for the same gas/compute cost as a single regular key write.

### Finding Description
`add_gas_key` (`runtime/runtime/src/access_keys.rs:194-228`) does the following for a `AddKeyAction` whose access key carries `GasKeyInfo`:
1. Writes the access key itself via `set_access_key` (one write).
2. Loops `for i in 0..num_nonces { set_gas_key_nonce(...) }` (`access_keys.rs:212-214`), performing `num_nonces` separate trie writes, each seeded to `initial_nonce_value(block_height)` (`access_keys.rs:46-50`).
3. Increases `account.storage_usage` by `gas_key_storage_cost(...)`, which does scale with `num_nonces` (`access_keys.rs:31-44`, `216-226`) — this only affects the storage-staking balance requirement, not gas/compute.

Nowhere in this function is `safe_add_compute` or any per-write compute cost invoked for the `num_nonces` writes; contrast with `delete_gas_key`, which explicitly charges removal compute per the wiki's spec description ("otherwise the balance is burned ... removes every nonce entry, charges removal compute"). The AddKeyAction's action fee is computed from the fixed `gas_key_add_key_send_fee`/`gas_key_add_key_exec_fee` parameters (`core/parameters/src/cost.rs`), which do not take `num_nonces` as an input — the fee formula is resolved purely from the action type, independent of the size of `GasKeyInfo.num_nonces`.

The attacker's `initial_nonce_value(block_height)` observation about picking a low `block_height` is orthogonal to the metering gap: it affects the *value* written, not whether the writes are charged. The core issue is that N trie writes (`set_gas_key_nonce` calls) happen for a compute cost identical to a single write, while storage/staking cost does scale correctly with N. This breaks "metering totality" — every trie write should be charged proportional compute before being committed — for the *compute* budget dimension specifically, even though token/storage-staking accounting is correct.

### Impact Explanation
This is a **fee/gas-metering bypass**, not a fund-theft or consensus-divergence bug: no funds are stolen, no double spend, no state-root divergence, and no shard halt results directly from a single such transaction, since storage-staking still correctly charges the byte cost of the extra writes and the writes themselves are deterministic and correctly persisted (state remains consistent across all nodes, since all nodes execute the same deterministic loop). The concrete, bounty-relevant impact is: an attacker can perform `MAX_NONCES_FOR_GAS_KEY` (1024) trie writes per `AddKeyAction` while only being charged the compute budget of a single access-key write. Repeated across many receipts, this lets an attacker consume proportionally more chunk *compute* time (trie-write CPU/IO work) than they pay compute-gas for, which is a **fee-payment/gas-accounting bypass** enabling under-priced resource consumption — a potential vector to slow down chunk application/exceed compute budgets relative to what senders pay for, though it does not on its own cause fund loss or chain split.

### Likelihood Explanation
Trivial to trigger: any unprivileged account can submit a `TransactionV1` `AddKeyAction` with a `GasKeyFullAccess`/`GasKeyFunctionCall` permission specifying `num_nonces` up to 1024, paying only the storage-staking deposit for the extra bytes (not extra gas). This requires no special privilege beyond normal `AddKey` and is fully repeatable — every gas-key add pays the same fixed AddKey fee regardless of `num_nonces`.

### Recommendation
Charge compute (via `safe_add_compute`, analogous to `storage_removes_compute` used elsewhere) for each `set_gas_key_nonce` write performed in `add_gas_key`'s loop, scaled by `num_nonces`, mirroring how `delete_gas_key` charges removal compute per nonce entry removed. Alternatively/additionally, make the AddKeyAction send/exec fee formula in `core/parameters`/`config.rs` a function of `num_nonces` (e.g., `base_fee + num_nonces * per_nonce_write_fee`), so the fee scales with the number of trie writes actually performed.

### Proof of Concept
Unit test in `runtime/runtime/src/access_keys.rs` (or an integration test in `test-loop-tests/src/tests/gas_keys.rs`):
1. Construct two identical `AddKeyAction`s differing only in `GasKeyInfo.num_nonces`: one with `num_nonces = 1`, one with `num_nonces = 1024` (the `MAX_NONCES_FOR_GAS_KEY` cap).
2. Apply both via the runtime (e.g. using `apply_state`/`state_update` test harness already present in `access_keys.rs`'s test module, similar to `test_add_gas_key`).
3. Assert `result.result` succeeds for both, and that `get_gas_key_nonce` returns correctly initialized entries for all `num_nonces` indices in the second case (proving N writes occurred).
4. Assert that `ActionResult`'s accumulated `compute_usage`/burnt gas attributable to the `AddKeyAction` itself (excluding storage-staking deposit differences) is identical between the two cases, despite the second performing 1024x more trie writes — demonstrating the send/exec fee formula in `core/parameters/src/cost.rs` (`gas_key_add_key_send_fee`/`gas_key_add_key_exec_fee`) does not scale with `num_nonces`. fn add_gas_key(
```rust
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    // For gas keys, nonce stored on access key is not used and should always be zero
    let mut access_key = access_key.clone();
    access_key.nonce = 0;
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    // Set up nonces for gas key
    let num_nonces = gas_key_info.num_nonces;
    let nonce = initial_nonce_value(block_height);
    for i in 0..num_nonces {
        set_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i, nonce);
    }

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(gas_key_storage_cost(fee_config, public_key, &access_key, num_nonces))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())
```
