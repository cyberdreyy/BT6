## Title
Multisig executes requests below the confirmation threshold because stale confirmations from removed members are never purged - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` in the `multisig2` contract only deletes requests that were *created by* the removed member; it never scans or prunes that member's confirmations recorded on other, still-open requests. `confirm()` then counts `confirmations.len()` against `num_confirmations` without checking that every signer in `confirmations` is still a current member. This allows a request to be executed with fewer live-member approvals than the configured `K`.

### Finding Description
`confirm()` decides whether to execute a request purely by comparing the size of the stored `confirmations: HashSet<String>` to `self.num_confirmations`: [1](#0-0) 

Membership removal is handled by `delete_member`, which cleans up only requests whose *creator* (`r.member`) equals the removed member, and clears that member's `num_requests_pk` entry: [2](#0-1) 

Critically, it does **not** iterate over `self.confirmations` to strip the removed member's entry from confirmation sets of *other* members' requests. So if member `B` confirmed request `R` (created by `A`) before being removed via a `DeleteMember` action, `R`'s `confirmations` set still contains `B` after `B` is deleted from `self.members`. The binding that should hold is:

`confirmations_counted_for(R) ⊆ current_live_members`

After a `DeleteMember` action executes, this invariant is broken: `confirmations` can contain identities no longer in `self.members`, yet `confirm()` still counts them toward `num_confirmations`.

### Impact Explanation
This lets a request be executed with real approval from fewer members than the configured threshold `K`. Since requests can transfer NEAR, deploy contracts, add/delete keys, or add/delete members, this is a direct case of "a multisig request executed below threshold" — the Critical impact category explicitly listed. An attacker who is one live member, combined with the residual confirmation of a member later removed (whether removed legitimately in the course of membership rotation, or as part of an orchestrated sequence), can get high-privilege actions (fund transfers, key/member changes, contract redeploys) approved without actually gathering `K` live signatures.

### Likelihood Explanation
This requires only ordinary contract operations: a normal confirm on a pending request, followed later by a legitimate `DeleteMember` request removing that confirmer. No privileged bypass or foundation/owner-only action is needed beyond what any member set can already do (member rotation is a standard, expected multisig operation). Any multisig that rotates members while requests are pending is exposed, which is a realistic scenario in practice.

### Recommendation
When executing `DeleteMember`, iterate over all open requests' `confirmations` sets and remove the deleted member's identity from each, and re-check outstanding requests against the (possibly lowered) live-member set. Alternatively, when counting confirmations in `confirm()`, filter `confirmations` to only those entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize multisig with members `A, B, C, D` and `num_confirmations = 3`.
2. `A` calls `add_request` creating request `R` (e.g., `Transfer` to an address `A` controls).
3. `B` calls `confirm(R)` → `confirmations = {B}` (count 1, below threshold, request stays open).
4. Separately, members legitimately submit and confirm a `DeleteMember { member: B }` request with 3 confirmations (`A`, `C`, `D`) — executes via `delete_member` at [3](#0-2) , which removes `B` from `self.members` but does **not** touch `R`'s confirmation set.
5. `A` calls `confirm(R)` → `confirmations = {B, A}` (count becomes 2), still not enough.
6. `C` calls `confirm(R)` → `confirmations.len() as u32 + 1 >= self.num_confirmations` (`2 + 1 >= 3`) is true, so `R` executes at [4](#0-3) .
7. Result: `R` (the transfer) executes with only `A` and `C` as currently-live approvers — 2 out of the 3 remaining live members (`A, C, D`) — even though `num_confirmations` is nominally 3, because the stale confirmation from removed member `B` was still counted.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
