### Title
Unbounded `pruneCallbacks` FIFO eviction lets an unprivileged flooder discard a victim's pending, non-expired gateway callback before the DON responds - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` inserts every incoming user request into `h.savedCallbacks` keyed by attacker-controlled `MessageId` with **no allowlist or rate-limiting** (explicitly marked as a TODO), and `pruneCallbacks` evicts purely by insertion age whenever the map exceeds `MaxSavedCallbacks`. An unprivileged sender can therefore flood the gateway with enough distinct `MessageId`s to force eviction of a victim's still-valid, unanswered callback, causing that victim to never receive the DON's response.

### Finding Description
`HandleLegacyUserMessage` [1](#0-0)  is reachable from any client sending a signed gateway request via `gateway.ProcessRequest` [2](#0-1) . The function performs only payload decoding, timestamp/staleness checks, and method validation; the code explicitly notes `// TODO: apply allowlist and rate-limiting here` [3](#0-2)  before it unconditionally stores the callback:

```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
``` [4](#0-3) 

Since `MessageId` is attacker-supplied and there is no per-sender request cap for this handler (the only `nodeRateLimiter` in this file throttles DON *node* responses, not incoming user requests) [5](#0-4) , an attacker can submit an arbitrary number of distinct legacy `web_api_trigger` messages, each adding a new entry to `h.savedCallbacks`.

`pruneCallbacks`, run periodically, first removes truly expired entries, then — if the map still exceeds `MaxSavedCallbacks` — sorts all remaining entries by `createdAt` and deletes the oldest half regardless of whether they have expired or are still awaiting a DON response:

```go
sort.Slice(entries, func(i, j int) bool {
    return entries[i].createdAt.Before(entries[j].createdAt)
})
for _, e := range entries[:len(entries)-maxSize/2] {
    delete(h.savedCallbacks, e.id)
    evicted++
}
``` [6](#0-5) 

Because eviction always targets the *oldest* entries first, a victim's request — submitted before the attacker's flood — is exactly the kind of entry preferentially deleted, even though it is not expired (`CallbackMaxAgeSec`, default 120s) and the DON has not yet answered it. Once deleted, `handleWebAPITriggerMessage` will find `found == false` when the legitimate DON response eventually arrives and silently drops it [7](#0-6) . The victim's original HTTP request, blocked in `callback.Wait(ctx)` [8](#0-7) , then times out with `RequestTimeoutError` instead of receiving the real answer.

### Impact Explanation
This is a denial-of-response / callback-loss vulnerability: an unprivileged actor can cause other users' legitimate, in-flight `web_api_trigger` (workflow) requests to silently fail even though the DON correctly processed and answered them. This matches Chainlink's "Denial of Service impacting a single user or a small group of users" / griefing impact class for gateway/off-chain infrastructure — no funds or keys are exposed, but service availability/correctness for victims is broken by an unauthenticated party.

### Likelihood Explanation
No special privileges, credentials, or DON/node access are required — only the ability to send properly-formed, individually-signed legacy gateway messages, which is the standard unauthenticated client capability for this API (per the TODO, no allowlist/rate limiting is enforced at this handler). The attacker needs to generate a burst of `MaxSavedCallbacks/2` (default 10,000) distinct `MessageId` requests within the prune interval (`CallbackPruneIntervalSec`, default 30s) — feasible for a scripted client, and repeatable indefinitely to keep evicting new victims.

### Recommendation
- Implement the TODO'd per-sender allowlist and rate limiting for `HandleLegacyUserMessage` before accepting into `savedCallbacks`.
- Change `pruneCallbacks` eviction policy to avoid evicting non-expired callbacks purely by insertion order; e.g., reject new insertions (return a capacity error to the new sender) once `MaxSavedCallbacks` is reached, rather than evicting older still-pending entries, or scope quotas per-sender so one sender cannot consume the whole map.

### Proof of Concept
Go table/unit test in `handler_test.go`:
1. Construct a `handler` with `MaxSavedCallbacks = N` (small, e.g. 10) and `CallbackMaxAgeSec` large enough that nothing expires during the test.
2. Insert one "victim" `savedCallback` with `id="victim"`, `createdAt=time.Now()`.
3. Sleep briefly, then insert `N` more "attacker" callbacks with distinct `MessageId`s and later `createdAt` timestamps, pushing `len(h.savedCallbacks)` to `N+1 > MaxSavedCallbacks`.
4. Call `h.pruneCallbacks()`.
5. Assert `h.savedCallbacks["victim"]` no longer exists (evicted) while the newer attacker entries remain — proving the victim's non-expired, still-pending callback was discarded ahead of newer attacker-controlled entries, and simulate the eventual DON response for `"victim"` via `handleWebAPITriggerMessage` to show it is silently dropped (`found == false`, no `SendResponse` call).

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
