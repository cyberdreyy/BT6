### Title
Missing allowlist and rate-limiting authorization check on `HandleLegacyUserMessage` allows any unprivileged caller to trigger workflow execution across the entire DON - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The Gateway's legacy WebAPI handler (`handler.HandleLegacyUserMessage`) accepts a signed `web_api_trigger` message from any external HTTP caller, validates only its structural correctness, signature well-formedness, and freshness, then immediately fans the message out to **every node in the DON** — with no allowlist or authorization check tying the signer/sender to a permitted caller, and no rate limiting applied to the request. The code contains an explicit unresolved `// TODO: apply allowlist and rate-limiting here` marking the gap.

### Finding Description
`HandleLegacyUserMessage` is reached from an unauthenticated Gateway HTTP endpoint (`gateway.ProcessRequest` → legacy handler dispatch, see `core/services/gateway/gateway.go`). It performs these checks in order:
1. Unmarshal payload, error out on failure.
2. Reject if `payload.Timestamp == 0`.
3. Reject if the message is stale (`MaxAllowedMessageAgeSec`).
4. **`// TODO: apply allowlist and rate-limiting here`** — no check is actually performed.
5. Reject only if `msg.Body.Method != MethodWebAPITrigger`.
6. Forward the request to **all** `h.donConfig.Members` via `don.SendToNode`. [1](#0-0) 

The only "authentication" performed anywhere in this path is `api.Message.Validate()`, which recovers a signer address from an ECDSA signature over the message body via `ExtractSigner`: [2](#0-1) 

Critically, this signature check does **not** verify that the recovered signer is an authorized/allowlisted entity — anyone can generate an arbitrary ECDSA keypair, sign a well-formed message, and pass `Validate()`. There is no equivalent to the `AllowListBasedAuth`/`Authorizer` pattern used elsewhere in the codebase (e.g., the Vault gateway handler enforces `requestProcessor.ProcessRequest` / `AuthorizeRequest` before acting [3](#0-2) , and the HTTP Trigger V2 handler enforces JWT-based `authorizeRequest` before dispatch [4](#0-3) ). The legacy WebAPI trigger handler has no analogous gate, despite the TODO comment acknowledging it is required.

Additionally, `h.nodeRateLimiter` (used to rate-limit outgoing node messages in `handleWebAPIOutgoingMessage`) is never invoked in `HandleLegacyUserMessage`, so incoming user-triggered fan-out to the DON is also unthrottled at this layer.

### Impact Explanation
This maps directly to the report's bug class ("missing authorization control ... allows anyone to access and execute the fallback/handler logic"). Here, any unprivileged external client can:
- Fabricate a valid signed `web_api_trigger` message with a throwaway key (no need to be a registered node, workflow owner, or allowlisted sender).
- Have the Gateway broadcast that message to **every node** in the target DON, consuming node processing resources and workflow trigger channels (`RegisterTrigger`/`allowedSenders` checks happen only downstream inside the DON's `webapicap` trigger capability, which is a second layer, not the Gateway).
- Since no request-level authorization or rate limit is enforced at the Gateway ingress point, this permits unauthorized triggering/flooding of workflow execution paths and resource exhaustion across the whole DON from an unauthenticated caller — a legitimate "unauthorized job run" / quota-bypass class of impact.

### Likelihood Explanation
High. The `HandleLegacyUserMessage` path is reachable directly from the internet-facing Gateway HTTP endpoint without any credential beyond a self-generated key pair, and the gap is explicitly flagged in the source as an unimplemented TODO — no obscure conditions are required to trigger it.

### Recommendation
Before dispatching to `don.SendToNode`, implement the missing allowlist/authorization check (resolve the `// TODO: apply allowlist and rate-limiting here`) — e.g., verify `msg.Body.Sender` against a configured/registered allowlist (mirroring `AllowListBasedAuth`/`Authorizer` patterns used by the Vault and HTTP Trigger V2 handlers), and apply `h.nodeRateLimiter` (or an equivalent per-sender/global limiter) to inbound user messages, not just outbound node messages.

### Proof of Concept
1. Generate an arbitrary ECDSA key pair (no registration required).
2. Construct an `api.Message` with `Body.Method = MethodWebAPITrigger`, a valid `TriggerRequestPayload` with a fresh `Timestamp`, and sign it with the throwaway key via `Message.Sign`.
3. Submit it as the JSON-RPC params of a legacy request to the Gateway's HTTP endpoint.
4. `HandleLegacyUserMessage` passes all checks (`Validate()`, timestamp freshness, method match) and forwards the message to every DON member via `don.SendToNode`, with no allowlist or rate-limit rejection — confirmed by the code path at [5](#0-4) .

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
