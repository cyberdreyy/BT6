### Title
APR=0 withdraw receipts permanently brick `stopEpoch` when APR is later raised - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`prepareStopEpochWithApr0` reverts whenever `apr0TotalPrincipal != 0` while `unscaledApr != 0`. Any unprivileged KYC-passing lender can create a durable APR0 principal bucket by calling `requestWithdraw` during a zero-APR epoch. If the (honest) manager subsequently sets a non-zero APR — a normal, expected action — every subsequent `stopEpoch` reverts, permanently freezing all vault funds, including previously funded withdraw receipts.

### Finding Description
In `IdleCreditVault.requestWithdraw`, requests made while `unscaledApr == 0` are routed into `_requestWithdrawApr0`, which increments the global `apr0TotalPrincipal` bucket [1](#0-0) [2](#0-1) .

During `stopEpoch`, the CDO calls `prepareStopEpochWithApr0`. The function has a fast-path return when the bucket is zero, but otherwise enforces:

```solidity
if (unscaledApr != 0) {
  revert NotAllowed();
}
``` [3](#0-2) 

The only write that clears `apr0TotalPrincipal` is `apr0TotalPrincipal = 0` at the end of this same function — which is unreachable when the revert fires [4](#0-3) . Per-user settlement in `_settleApr0` only zeroes `apr0Users[_user].principal`; it never decrements `apr0TotalPrincipal`, so even if every user claims, the global bucket stays non-zero [5](#0-4) .

Attack sequence (all attacker steps unprivileged):
1. Pool runs an epoch with `unscaledApr == 0` (a supported configuration).
2. Attacker (KYC-passed lender, `isWalletAllowed`) deposits, then calls `IdleCDOEpochVariant.requestWithdraw`. The vault mints them a receipt and sets `apr0TotalPrincipal > 0` [6](#0-5) .
3. Honest manager calls `setApr(x)` with `x > 0` for the next epoch — a routine action.
4. Manager calls `stopEpoch` → `prepareStopEpochWithApr0` reverts with `NotAllowed`. This revert is permanent: no code path can lower `apr0TotalPrincipal` while `unscaledApr != 0`, and requests already recorded cannot be withdrawn or cancelled.

Since `epochNumber` never advances, `_claimFundedWithdrawRequest`'s gate `epochNumber <= lastWithdrawRequest[_user]` never clears, so even the attacker's own and all other users' receipts are locked — but more importantly the entire pool NAV is frozen: no epoch can stop, no claims can mature, and `deposit`/`startEpoch` sequencing is broken.

### Impact Explanation
Permanent freezing of all user funds in the vault (100% of TVL). The revert is unconditional once triggered: the clearing write at line 540 is gated behind the same check that reverts. No privileged recovery path exists in `IdleCreditVault` to decrement `apr0TotalPrincipal` or force a stop, since `_settleApr0` never touches the global counter and `claimWithdrawRequest` cannot run because the epoch never ends.

### Likelihood Explanation
Low-to-moderate likelihood, severe outcome. It requires: (a) the vault to run an APR=0 epoch (a supported mode with dedicated accounting), (b) any single lender to request a withdrawal during it (cheap, normal UX), and (c) the manager to later raise APR — an ordinary operational action the manager is expected to take. None of these require misbehavior. The bug is a state-machine inconsistency: the APR0 bucket's validity precondition (`unscaledApr == 0`) is evaluated at stop time rather than at request time.

### Recommendation
- In `prepareStopEpochWithApr0`, do not revert on `unscaledApr != 0`. Instead, settle the outstanding APR0 bucket at a zero or last-known rate: iterate is impossible, so settle by setting `apr0RateByEpoch[epochNumber]` to a defined value (e.g., 0 or a pro-rata rate computed from `_expInterest`) and clear `apr0TotalPrincipal` unconditionally.
- Alternatively, have `setApr` (or the CDO's APR-change path) flush/settle APR0 state, or block `requestWithdraw`'s APR0 branch from persisting a bucket that can outlive the APR=0 configuration.
- As defense in depth, decrement `apr0TotalPrincipal` inside `_settleApr0` when per-user principal is settled, so the global bucket cannot drift from the sum of user principals.

### Proof of Concept
Foundry fork sketch (mirroring `test/foundry/IdleCreditVault.t.sol` helpers):

```solidity
function testApr0ReceiptBricksStopEpochAfterAprRaise() external {
  // setup: pool in APR=0 epoch
  _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
  vm.startPrank(manager);
  IdleCreditVault(address(strategy)).setApr(0);
  cdoEpoch.startEpoch();
  vm.stopPrank();

  // attacker: KYC-passed lender deposits and requests withdraw
  uint256 minted = idleCDO.depositAA(10_000 * ONE_SCALE);
  cdoEpoch.requestWithdraw(minted / 2, address(AAtranche));
  assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

  // honest manager raises APR for next epoch
  vm.prank(manager);
  IdleCreditVault(address(strategy)).setApr(5e18); // 5%

  // borrower repays; manager tries to stop epoch
  deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
  vm.warp(cdoEpoch.epochEndDate() + 1);
  vm.prank(manager);
  vm.expectRevert(NotAllowed.selector);
  cdoEpoch.stopEpoch(5e18, 0);

  // permanent: no path clears apr0TotalPrincipal while unscaledApr != 0
  // => all claims and future epochs are bricked
}
```

Caveat: I verified the revert/clear logic in `IdleCreditVault.sol` but did not fully trace `IdleCDOEpochVariant.stopEpoch`'s call site to confirm the revert is not caught — the call is a plain external call, so the revert propagates per standard Solidity semantics.

      // The CDO passes an already-haircut amount because finalization lowered virtualPrice first.
      _burn(msg.sender, _amount);
      _mint(_user, _amount);
      postDefaultRequests[_user] = _amount;
      return;
    }

    uint256 currentEpoch = epochNumber;
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (

    ) {
      // A loss-adjusted receipt must be claimed before opening a later request, otherwise
      // `lastWithdrawRequest` would stop pointing to the epoch that stores its haircut.

    _burn(msg.sender, _principal);

    _mint(_user, _amount);
    // A successfully closed pool already recalled all funds and has no later stopEpoch.
    if (!isClosed) {
      // Global amount that stopEpoch must source from borrower/strategy for all pending receipts.
      pendingWithdraws += _amount;

    // `_amount` here is the post-management-fee principal bucket for that flow.
    if (unscaledApr == 0 && !isClosed) {
      _requestWithdrawApr0(_amount, _user);
    } else {
      // increase the withdraw requests for the user
      // we record both per-user (old, kept for compatibility) and per-epoch so
      // on finalization we can distinguish "default-epoch pending receipts"
      // from old funded receipts.
      withdrawsRequests[_user] += _amount;
      withdrawsRequestsByEpoch[_user][currentEpoch] += _amount;
    }
  }

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
      _apr0User.principalEpoch = epochNumber;
    }
    _apr0User.principal += _amount;
    // Epoch-level APR0 principal used only to compute stopEpoch APR0 pro-rata interest.
    apr0TotalPrincipal += _amount;
  }
