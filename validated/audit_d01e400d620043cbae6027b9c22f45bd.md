## Title
`getLargestAccounts` cache ignores commitment level, returning stale/wrong-commitment data across requests - (File: `rpc/src/rpc_cache.rs`, `rpc/src/rpc.rs`)

### Summary
The `getLargestAccounts` JSON-RPC method caches its results keyed only by the optional `filter` parameter (`Circulating`/`NonCirculating`/none), completely ignoring the `commitment` field of `RpcLargestAccountsConfig`. As a result, a query made at one commitment level (e.g. `processed`) can populate a cache entry that is later served, unmodified, to a query made at a different commitment level (e.g. `finalized`), returning data and a slot that do not correspond to the bank the requester actually asked for.

### Finding Description
`LargestAccountsCache` stores entries in a `HashMap<Option<RpcLargestAccountsFilter>, LargestAccountsCacheValue>`: [1](#0-0) 

Lookups and inserts are both keyed solely by `filter`: [2](#0-1) 

In `JsonRpcRequestProcessor::get_largest_accounts`, the request first resolves a `bank` for the caller-supplied `config.commitment`, but the cache is then checked and populated using only `config.filter`, never incorporating the commitment level or the resolved bank's slot as part of the cache key: [3](#0-2) 

Because the cache TTL (`LARGEST_ACCOUNTS_CACHE_DURATION`) is shared across all commitment levels for the same filter, a request at `processed` commitment can populate the cache with account balances and a slot from an unconfirmed/unrooted bank. A subsequent request from the same or a different unprivileged client specifying `finalized` (or `confirmed`) commitment within the cache TTL window will receive that same processed-bank result and slot via `RpcResponseContext::new(slot)`, rather than data corresponding to a finalized bank.

### Impact Explanation
This causes the RPC server to return account-balance data and a `context.slot` that do not match the commitment level the caller explicitly requested — i.e., wrong-slot/wrong-fork data returned in response to a normal, single, unprivileged JSON-RPC call. Clients relying on `finalized`/`confirmed` guarantees for `getLargestAccounts` (e.g. exchanges, explorers auditing top holders) can be misled into treating balances from a bank that may still be rolled back (not yet confirmed/finalized) as settled data.

### Likelihood Explanation
Any unprivileged RPC client can trigger this by issuing two `getLargestAccounts` calls with different commitment levels (and the same `filter`) within the cache duration window; no special privileges, timing races beyond normal request cadence, or multiple clients working in concert are required.

### Recommendation
Include the effective commitment level (or the resolved bank's slot) as part of the `LargestAccountsCache` key so that entries fetched with different commitments are not conflated, e.g. change the cache key type from `Option<RpcLargestAccountsFilter>` to `(Option<RpcLargestAccountsFilter>, CommitmentConfig)`.

### Proof of Concept
1. Call `getLargestAccounts` with `{"commitment": "processed"}` shortly after a large, not-yet-confirmed transfer lands in the processed bank; this populates the cache with `slot = <processed_slot>` and updated balances.
2. Within the cache TTL, call `getLargestAccounts` with `{"commitment": "finalized"}` (same/no filter).
3. Observe that the response returns the cached `slot`/balances from step 1 (the processed bank) instead of computing/returning data for the finalized bank, as seen by the key-lookup logic in [4](#0-3)  and the cache-check call in [5](#0-4) , neither of which reference `config.commitment`.

    pub(crate) fn get_largest_accounts(
        &self,
        filter: &Option<RpcLargestAccountsFilter>,
    ) -> Option<(u64, Vec<RpcAccountBalance>)> {
        self.cache.get(filter).and_then(|value| {
            if let Ok(elapsed) = value.cached_time.elapsed()
                && elapsed < Duration::from_secs(self.duration)
            {
                return Some((value.slot, value.accounts.clone()));
            }
            None
        })
    }

    pub(crate) fn set_largest_accounts(
        &mut self,
        filter: &Option<RpcLargestAccountsFilter>,
        slot: u64,
        accounts: &[RpcAccountBalance],
    ) {
        self.cache.insert(
            filter.clone(),
            LargestAccountsCacheValue {
                accounts: accounts.to_owned(),
                slot,
                cached_time: SystemTime::now(),
            },
        );
    }

    async fn get_largest_accounts(
        &self,
        config: Option<RpcLargestAccountsConfig>,
    ) -> RpcCustomResult<RpcResponse<Vec<RpcAccountBalance>>> {
        let config = config.unwrap_or_default();
        let bank = self.bank(config.commitment);

        if let Some((slot, accounts)) = self.get_cached_largest_accounts(&config.filter) {
            Ok(RpcResponse {
                context: RpcResponseContext::new(slot),
                value: accounts,
            })
        } else {
            let (addresses, address_filter) = if let Some(filter) = config.clone().filter {
                let non_circulating_supply = self
                    .calculate_non_circulating_supply(&bank)
                    .await
                    .map_err(|e| RpcCustomError::ScanError {
                        message: e.to_string(),
                    })?;
                let addresses = non_circulating_supply.accounts.into_iter().collect();
                let address_filter = match filter {
                    RpcLargestAccountsFilter::Circulating => AccountAddressFilter::Exclude,
                    RpcLargestAccountsFilter::NonCirculating => AccountAddressFilter::Include,
                };
                (addresses, address_filter)
            } else {
                (HashSet::new(), AccountAddressFilter::Exclude)
            };
            let accounts = self
                .runtime
                .spawn_blocking({
                    let bank = Arc::clone(&bank);
                    move || {
                        bank.get_largest_accounts(NUM_LARGEST_ACCOUNTS, &addresses, address_filter)
                    }
                })
                .await
                .expect("Failed to spawn blocking task")
                .map_err(|e| RpcCustomError::ScanError {
                    message: e.to_string(),
                })?
                .into_iter()
                .map(|(address, lamports)| RpcAccountBalance {
                    address: address.to_string(),
                    lamports,
                })
                .collect::<Vec<RpcAccountBalance>>();

            self.set_cached_largest_accounts(&config.filter, bank.slot(), &accounts);
            Ok(new_response(&bank, accounts))
        }
    }
