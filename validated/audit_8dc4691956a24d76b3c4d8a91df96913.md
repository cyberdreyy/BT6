### Title
Missing role gate on GET /v2/bridge_types/:BridgeName discloses bridge OutgoingToken/URL to view-role users - (File: core/web/router.go)

### Summary
The `bt.Show` route handler for `GET /v2/bridge_types/:BridgeName` is registered under the authenticated `authv2` group without any `RequiresRunRole`/`RequiresEditRole` wrapper, unlike the sibling `POST`/`PATCH`/`DELETE` routes on the same resource. Because `presenters.NewBridgeResource` always serializes the bridge's `OutgoingToken` and `URL` fields, any authenticated caller—including a minimal `UserRoleView` session user or a restricted API token—can retrieve these bridge secrets.

### Finding Description
In `v2Routes` in `core/web/router.go`, the bridge_types routes are:
```go
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
```
`authv2` only enforces that a request is authenticated (via session or API token, in `auth.Authenticate`) — it does not enforce any minimum role. `bt.Show` in `core/web/bridge_types_controller.go` looks up the bridge by name and returns `presenters.NewBridgeResource(bt)` with no additional role check inside the handler itself.

`presenters.NewBridgeResource` (core/web/presenters/bridges.go) populates `OutgoingToken` from `b.OutgoingToken` directly with a JSON tag of `outgoingToken` (no `omitempty`), and `URL` similarly, with no role-aware redaction logic. `RequiresEditRole` (core/web/auth/auth.go) is what blocks `UserRoleView` and `UserRoleRun` from `Create`/`Update`/`Destroy`, but this same guard is absent from `Show`.

As a result, a `UserRoleView` session user or a restricted API token holder (any role above unauthenticated) can `GET /v2/bridge_types/<name>` and receive the bridge's `outgoingToken` and `url` in the JSON:API response body — data that is otherwise treated as sensitive enough to gate write operations behind `RequiresEditRole`.

### Impact Explanation
This is a credential/secret disclosure to a lower-privileged authenticated caller than intended. `OutgoingToken` is used by the node to authenticate itself to the external adapter/bridge; its exposure allows a view-role user (who should only be able to observe state, not manage bridges or secrets) to obtain a credential usable to interact with or impersonate the node's outbound calls to that bridge/adapter. This matches a credential/secret exposure impact class in Chainlink's bounty program.

### Likelihood Explanation
Minimal precondition: any valid authenticated session (even `UserRoleView`) or a valid API token is sufficient — no special privilege is needed since `Show` performs no role check at all. The attack is a single unauthenticated-role GET request and is fully repeatable/deterministic for every bridge in the node.

### Recommendation
Wrap `authv2.GET("/bridge_types/:BridgeName", bt.Show)` with an appropriate role guard consistent with the resource's sensitivity (e.g., `auth.RequiresEditRole` or a new minimal role check), and/or have `presenters.NewBridgeResource`/`BridgeTypesController.Show` redact `OutgoingToken` (and `IncomingToken`) from the response for non-edit/admin roles, mirroring how `IncomingToken` is already only populated on `Create`.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/bridge_types_controller_test.go`):
1. Create an app via `cltest.NewApplication(t)`, create a bridge with a known `OutgoingToken` via `app.BridgeORM().CreateBridgeType`.
2. Create a session/API-token client for a user with `clsessions.UserRoleView` (using existing test helpers for role-scoped HTTP clients, e.g. as used in `auth_test.go`).
3. Call `client.Get("/v2/bridge_types/" + bt.Name.String())`.
4. Assert `resp.StatusCode == http.StatusOK` (currently succeeds, showing lack of gate).
5. Parse response into `presenters.BridgeResource` and assert `resource.OutgoingToken == ""` or that the field is absent/redacted — this assertion will currently FAIL because `resource.OutgoingToken` equals the bridge's actual `OutgoingToken`, proving the vulnerability.

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
