### Title
Cross-user response hijacking via unauthenticated MessageId collision in `HandleLegacyUserMessage` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` writes a new callback into `h.savedCallbacks[msg.Body.MessageId]` without checking whether an entry already exists for that key, so a second request using the same `MessageId` as a pending legitimate request silently overwrites the victim's callback. Because the signature check only verifies that the sender signed the message body they submitted — it never binds a `MessageId` to a single, exclusive owner across requests — any attacker able to observe/guess a victim's in-flight `MessageId` can hijack the eventual DON response.

### Finding Description
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` performs payload/timestamp/method validation and then unconditionally stores the caller's callback: [1](#0-0) 
There is no `if _, exists := h.savedCallbacks[msg.Body.MessageId]; exists` guard — the map write at line 412 blindly replaces any previous entry. The same pattern exists in the dummy handler: [2](#0-1) 

The message signature (`Message.Sign`/`Message.Validate` in `core/services/gateway/api/message.go`) only proves that the attacker's own key signed the raw bytes of *their own* message body — which includes `MessageId` as an attacker-chosen field embedded in the signed data: [3](#0-2) 
Nothing ties a `MessageId` to a specific signer as an exclusivity constraint; two different signers can each produce a validly-signed message carrying the identical `MessageId` string. `Validate()` only checks length/format constraints on `MessageId` (lines 61-66) and extracts the signer — it does not check for collisions against other pending requests: [4](#0-3) 

Exploit flow:
1. Victim sends a legitimate legacy request with `MessageId = X`; `HandleLegacyUserMessage` stores `savedCallbacks[X] = victimCallback` and forwards the request to DON members.
2. Before the DON responds, attacker (having observed/guessed `X` per the stated precondition) sends their own signed legacy request with `Body.MessageId = X`. This passes `Validate()` (their own valid signature over their own body) and `HandleLegacyUserMessage` overwrites `savedCallbacks[X] = attackerCallback`.
3. When the DON eventually responds with `MessageId = X` via `handleWebAPITriggerMessage`, the gateway looks up `savedCallbacks[X]`, finds the attacker's callback (the victim's was silently evicted), and delivers the DON's output to the attacker's connection instead of the victim's: [5](#0-4) 

### Impact Explanation
This is a cross-user response confusion / request impersonation bug: an attacker can redirect a legitimate subscriber's paid-for DON response to themselves, exfiltrating data the victim requested and paid for, and causing the victim to never receive their response (denial of service for that request). This matches the "cross-user response confusion" and "unauthorized action on another user's job/subscription" impact classes.

### Likelihood Explanation
Exploitability depends entirely on the stated precondition — the attacker's ability to observe or predict a victim's in-flight `MessageId` and to submit unauthenticated/attacker-controlled legacy requests (per the referenced prior finding). Given that precondition, the race itself is trivial and fully repeatable: no rate limiting or uniqueness check defends the `savedCallbacks` map, and the window is the full round-trip time to the DON (up to `MaxAllowedMessageAgeSec`/callback TTL), which is generous for a race.

### Recommendation
Reject (rather than overwrite) writes to `savedCallbacks` when the key is already occupied by a pending, non-expired callback, e.g.:
```go
h.mu.Lock()
if _, exists := h.savedCallbacks[msg.Body.MessageId]; exists {
    h.mu.Unlock()
    return callback.SendResponse(handlers.UserCallbackPayload{
        RawResponse: codec.EncodeNewErrorResponse(msg.Body.MessageId, api.ToJSONRPCErrorCode(api.HandlerError), "duplicate message id", nil),
        ErrorCode: api.HandlerError,
    })
}
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}
h.mu.Unlock()
```
Apply the same fix to `dummyHandler.HandleLegacyUserMessage`. Additionally, consider deriving `MessageId` uniqueness from `(sender, MessageId)` tuples, or requiring the gateway itself to generate/return the `MessageId` rather than trusting client-supplied values, so it can't be guessed/reused by another sender at all.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` via `NewHandler` with a fake `DON` mock that records `SendToNode` calls.
2. Create two `handlers.Callback` mocks: `victimCallback` and `attackerCallback`, each capturing `SendResponse` invocations.
3. Build `msgVictim` with `Body.MessageId = "X"`, signed with victim's key; call `h.HandleLegacyUserMessage(ctx, msgVictim, victimCallback)` — assert `h.savedCallbacks["X"].Callback == victimCallback`.
4. Build `msgAttacker` with `Body.MessageId = "X"` (same ID), signed with attacker's key; call `h.HandleLegacyUserMessage(ctx, msgAttacker, attackerCallback)`.
5. Assert the second call is rejected (e.g., `attackerCallback.SendResponse` called with an error payload) and `h.savedCallbacks["X"].Callback` still equals `victimCallback` — proving no overwrite occurred.
6. Simulate the DON's node response for `MessageId = "X"` via `HandleNodeMessage`/`handleWebAPITriggerMessage` and assert only `victimCallback.SendResponse` receives the DON payload, never `attackerCallback`.

// Message signatures are over the following data:
//  1. MessageId aligned to 128 bytes
//  2. Method aligned to 64 bytes
//  3. DonId aligned to 64 bytes
//  4. Receiver (in hex) aligned to 42 bytes
//  5. Payload (raw bytes before parsing)
func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
