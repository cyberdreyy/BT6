Base's B20 asset precompile has a scheduled-multiplier mechanism (`AssetV2::effective_multiplier`, `to_scaled_balance`, `total_supply_ui`) that superficially resembles a "reward accrual" system, but it applies a single global multiplier uniformly to all balances at read time via `token.accounting().multiplier()` [1](#0-0) . It has no per-account `rewardDebt`/`userRewardPerTokenPaid` state that gets updated relative to `balanceOf` during a transfer, and the balance-move primitive `move_balance` simply debits/credits balances with no side-effect hook into a separate rewarder contract [2](#0-1) . There is no `_beforeTokenTransfer`/`_afterTokenTransfer`-style staking hook, no rewarder `stake`/`withdraw` calls tied to transfers, and no analog of Tokemak's `LMPVault` auto-staking design anywhere in the B20 asset/stablecoin precompile logic (`v1.rs`/`v2.rs` in both `b20_asset` and `b20_stablecoin`) [3](#0-2) . Since the multiplier is applied identically to `to` and `from` balances regardless of transfer ordering, and no account-specific reward checkpoint is ever set based on a transfer's resulting non-zero balance, the root-cause pattern from the report (first-transfer reward-debt miscalculation enabling reward theft) has no reachable analog in this codebase.

    fn move_balance<S: AssetAccounting, A: PolicyAccounting>(
        &self,
        token: &mut B20AssetToken<S, A>,
        from: Address,
        to: Address,
        amount: U256,
    ) -> Result<()> {
        let from_balance = token.accounting().balance_of(from)?;
        if from_balance < amount {
            return Err(BasePrecompileError::revert(IB20::InsufficientBalance {
                sender: from,
                balance: from_balance,
                needed: amount,
            }));
        }
        let new_from_balance =
            from_balance.checked_sub(amount).ok_or_else(BasePrecompileError::under_overflow)?;
        token.accounting_mut().set_balance(from, new_from_balance)?;
        let to_balance = token.accounting().balance_of(to)?;
        let new_to_balance =
            to_balance.checked_add(amount).ok_or_else(BasePrecompileError::under_overflow)?;
        token.accounting_mut().set_balance(to, new_to_balance)?;
        token.accounting_mut().emit_event(IB20::Transfer { from, to, amount }.encode_log_data())
    }

        let now = token.accounting().timestamp()?;
        let effective_at = token.accounting().pending_effective_at()?;
        if effective_at != 0 && now >= U256::from(effective_at) {
