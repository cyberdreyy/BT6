### Title
Inactive owner permanently freezes all vault funds after an emergency shutdown — only `restoreOperations()` can clear `skipDefaultCheck`, and it is owner-only — (contracts/IdleCDOEpochVariant.sol)

### Summary
Both `IdleCDO.emergencyShutdown()` (callable by owner *or* guardian) and the epoch-variant override set `skipDefaultCheck = true`, which is the persistent emergency flag. While that flag is set, `paused()` can never be lifted (`_beforeUnpause()` reverts on `skipDefaultCheck`), AA/BB withdrawal requests stay disabled, and even a successful `stopEpoch`/`stopEpochWithDuration` by the manager will not reopen the vault because the reopen block is gated on `!skipDefaultCheck`. The single exit — `restoreOperations()` — is guarded by `_checkOnlyOwner()`. If the owner loses access to the private key, every depositor's funds remain frozen permanently, with no time-based or governance fallback — the exact same single point of failure as Fantom's `makeTradeable()`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
- `emergencyShutdown()` is callable by owner or guardian and delegates to `_emergencyShutdown(false)`, which pauses deposits, disables `allowAAWithdrawRequest`/`allowBBWithdrawRequest`, and sets `skipDefaultCheck = true`. [5](#0-4) [6](#0-5) 
- `_beforeUnpause()` reverts while `defaulted || isEpochRunning || skipDefaultCheck`, so the guardian's `unpause()` cannot help while the emergency flag is set. [7](#0-6) 
- `stopEpoch`'s normal reopening path (`_unpause()` + re-enabling withdraw requests) only executes when `!skipDefaultCheck`; the codebase's own test `testLegacyEmergencyStateRemainsClosedAfterUpgrade` proves the vault stays paused and requests stay disabled after a manager-driven epoch stop. [4](#0-3) [8](#0-7) 
- `restoreOperations()` is `_checkOnlyOwner()`-only and is the *only* function that clears `skipDefaultCheck`. The test suite itself asserts a non-owner call reverts. [9](#0-8) [10](#0-9) 

Result: after any emergency shutdown — including one legitimately triggered by the guardian — an incapacitated owner leaves the contract permanently paused: no deposits, no `requestWithdraw`, no `depositDuringEpoch`, and pending withdrawal claims cannot be fulfilled because the vault never reopens. This is not "freezing after a borrower default" (excluded); it is freezing after a *non-default* emergency where the borrower may be fully solvent and repaying.

### Impact Explanation
Permanent freezing of 100% of vault TVL (all AA and BB tranche holders' underlying), plus unclaimed yield and pending withdrawal requests. Tranche tokens remain transferable but worthless since redemption is permanently gated. Loss equals `getContractValue()` at shutdown time — unbounded, all user funds.

### Likelihood Explanation
Trigger requires only one honest privileged action (guardian reacting to a suspicious event, or owner precautionary shutdown) followed by owner key loss/incapacitation — an operational risk, not an attacker action. Emergency shutdown is an intended, realistically-used feature; key loss is a well-documented failure mode. No attacker control needed, matching the original report's threat model.

### Recommendation
Add a non-owner fallback to clear the emergency state after a cooldown and full repayment, e.g. in `restoreOperations`:

```solidity
require(msg.sender == owner() ||
        (block.timestamp > emergencyTimestamp + RECOVERY_DELAY && !defaulted));
```

Alternatively, allow the guardian or a successful `stopEpoch` (after borrower repays in full and `!defaulted`) to clear `skipDefaultCheck` after a timelock, so no single key can permanently paralyse the vault.

### Proof of Concept
```solidity
// test/foundry/OwnerKeyLossFreeze.t.sol — fork of existing IdleCreditVault setup
function testOwnerKeyLossPermanentlyFreezesVault() external {
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);
    _startEpochAndCheckPrices(0);

    // Guardian (honest) triggers emergency shutdown
    vm.prank(guardian);
    cdoEpoch.emergencyShutdown();
    assertTrue(cdoEpoch.paused());

    // Borrower repays in full; manager stops the epoch normally — vault does NOT reopen
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(initialProvidedApr, 0, 7 days, 0);

    assertTrue(cdoEpoch.paused(), 'vault remains paused after successful stop');
    assertFalse(cdoEpoch.allowAAWithdrawRequest());
    assertFalse(cdoEpoch.allowBBWithdrawRequest());

    // Owner key is lost: guardian unpause reverts, non-owner restore reverts
    vm.prank(guardian);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.unpause(); // _beforeUnpause: skipDefaultCheck still true

    vm.prank(makeAddr('anyone'));
    vm.expectRevert(GuardedLaunchUpgradable.NotAuthorized.selector);
    cdoEpoch.restoreOperations();

    // All user funds permanently frozen
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.requestWithdraw(amount, address(AAtranche));
}
```

```text
  function _emergencyShutdown(bool isAAWithdrawAllowed) internal override {
    // prevent deposits
    if (!paused()) {
      _pause();
    }
    // Preserve AA requests only if they were already open. This keeps a forced mid-epoch loss or
    // prior emergency from reopening them, while a normal explicit-loss stop can leave them open.
    if (!isAAWithdrawAllowed) {
      allowAAWithdrawRequest = false;
    }
    allowBBWithdrawRequest = false;
    // Persist the emergency state and let authorized forced accounting crystallize the loss.
    skipDefaultCheck = true;
  }

  /// @notice allow deposits and redeems for all classes of tranches
  /// @dev can be called by the owner only
  function restoreOperations() external override {
    _checkOnlyOwner();
    // Check if the pool was defaulted
    _checkNotAllowed(defaulted || priceAA == 0);
    skipDefaultCheck = false;
    // During an epoch ordinary deposits and withdrawal requests must remain disabled. Clearing
    // the emergency flag intentionally restores only the dedicated depositDuringEpoch path.
    if (isEpochRunning) return;
    if (paused()) {
      _unpause();
    }
    allowAAWithdrawRequest = true;
    allowBBWithdrawRequest = true;
  }

  /// @notice Prevent external unpause while an epoch, emergency shutdown, or hard default is active.
  function _beforeUnpause() internal view override {
    _checkNotAllowed(defaulted || isEpochRunning || skipDefaultCheck);
  }
```
