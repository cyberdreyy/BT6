### Title
Permanently cached master public key in `GatewayHandler` causes DoS of Vault secrets create/update after a DKG key rotation - (File: `core/capabilities/vault/gw_handler.go`)

### Summary
`GatewayHandler` caches the Vault master TDH2 public key exactly once, with no invalidation path. If the underlying master key changes (a fresh DKG instance producing a new group key, as opposed to a resharing which preserves it), every node's `GatewayHandler.cachedMasterPublicKey` becomes permanently stale, and all subsequent `CreateSecrets`/`UpdateSecrets` requests routed through the gateway are validated against the wrong key and rejected — an unrecoverable-until-restart DoS, structurally identical to the `NativeVault::slashAssets` stale-handler-check bug: an unsynchronized cached reference to a "correct" value is checked against a value that can independently change, and once it diverges the code path is permanently broken.

### Finding Description
`GatewayHandler.getMasterPublicKey` (`core/capabilities/vault/gw_handler.go:238-261`) loads the master public key from `h.secretsService` exactly once and stores it in `h.cachedMasterPublicKey`; every subsequent call returns the cached copy with no expiry, refresh trigger, or invalidation hook: [1](#0-0) 

This cached key is used on the hot path for every unprivileged user's `CreateSecrets`/`UpdateSecrets` request received via the gateway, in `HandleGatewayMessage`: [2](#0-1) 

The key is passed into `GatewayVaultRequestProcessor.ProcessRequest` → `processCreateSecretsRequest`/`processUpdateSecretsRequest`, which call `p.validator.ValidateCreateSecretsRequest`/`ValidateUpdateSecretsRequest` with the (possibly stale) `publicKey`: [3](#0-2) 

Deeper in the validator, `verifyEncryptedSecret` unmarshal-verifies each client-submitted ciphertext against this cached public key, and returns a hard validation error (not a "skip" like the nil-key case) when the key doesn't match the key the ciphertext was actually encrypted under: [4](#0-3) 

The system explicitly supports operations that rotate the master public key: a fresh DKG dealing (no `PreviousInstanceID`) generates a brand-new group key, distinct from resharing which preserves it: [5](#0-4) 

Once such a fresh DKG rotation occurs, `h.secretsService.GetPublicKey` will return the new key, but `GatewayHandler.cachedMasterPublicKey` was already populated with the old key on first use and is never cleared — there is no code path in `gw_handler.go` that resets `cachedMasterPublicKey`. This is the same root cause pattern as the reported `NativeVault::slashAssets` bug: a component independently caches/pins a value that is checked for consistency against a live, mutable source of truth, and once they diverge, all requests relying on that consistency permanently fail.

### Impact Explanation
After a legitimate master-key rotation (fresh DKG), every unprivileged client's `CreateSecrets`/`UpdateSecrets` request that is validated by an affected gateway-connected node will fail ciphertext verification, because the node checks the newly-encrypted secret against its own stale cached key. This is a denial of service on the Vault write path (secret creation/update) for arbitrary end users, with no self-healing — it persists until the node process serving `GatewayHandler` is restarted (clearing `cachedMasterPublicKey` in memory). Depending on DON size and how many nodes participate in gateway-side aggregation/authorization, this can degrade or fully block the ability of any workflow owner to store or rotate secrets.

### Likelihood Explanation
This triggers deterministically any time operators perform a fresh (non-resharing) DKG dealing while nodes are already running and have served at least one `CreateSecrets`/`UpdateSecrets` request (which populates the cache). Given that `PreviousInstanceID: nil` fresh dealings are a documented, supported operational path, this is a realistic and reproducible operational scenario, not a contrived edge case.

### Recommendation
Do not cache the master public key indefinitely in `GatewayHandler`. Options:
- Re-fetch the key from `secretsService.GetPublicKey` on a TTL or on every request (accepting the extra call cost), instead of caching forever.
- Invalidate/refresh `cachedMasterPublicKey` whenever `secretsService` signals a key rotation (e.g., subscribe to DKG/OCR config-change events).
- On `verifyEncryptedSecret` failure, fall back to fetching a fresh key from `secretsService` once before failing the request, similar to how `MasterPublicKeyFromSecretsService` is used for the initial population.

### Proof of Concept
1. Start a node with `GatewayHandler` wired to a `secretsService` backed by DKG instance `A` (master public key `PK_A`).
2. Submit a `CreateSecrets` request; `GatewayHandler.getMasterPublicKey` fetches `PK_A` from `secretsService` and caches it in `h.cachedMasterPublicKey` (`gw_handler.go:238-261`).
3. Operators run a fresh DKG dealing (no `PreviousInstanceID`), rotating the master key to `PK_B`; `secretsService.GetPublicKey` now returns `PK_B`.
4. A client encrypts a new secret under `PK_B` and submits `CreateSecrets`/`UpdateSecrets` via the gateway.
5. `GatewayHandler.getMasterPublicKey` returns the stale cached `PK_A` (cache is non-nil, so the fetch branch in `getMasterPublicKey` is never taken again).
6. `verifyEncryptedSecret` (`validator.go:313-328`) fails to `UnmarshalVerify` the ciphertext against `PK_A`, and `ValidateCreateSecretsRequest`/`ValidateUpdateSecretsRequest` reject the request — the client's legitimate `CreateSecrets`/`UpdateSecrets` call is permanently denied until the node process is restarted.

```go
func (h *GatewayHandler) getMasterPublicKey(ctx context.Context) (*tdh2easy.PublicKey, error) {
	h.mu.RLock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		h.mu.RUnlock()
		return &cachedCopy, nil
	}
	h.mu.RUnlock()

	publicKey, err := MasterPublicKeyFromSecretsService(ctx, h.secretsService)
	if err != nil {
		return nil, err
	}

	h.mu.Lock()
	defer h.mu.Unlock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		return &cachedCopy, nil
	}
	h.cachedMasterPublicKey = publicKey
	cachedCopy := *publicKey
	return &cachedCopy, nil
}
```

```go
func (p *GatewayVaultRequestProcessor) processCreateSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	publicKey *tdh2easy.PublicKey,
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var createReq vaultcommon.CreateSecretsRequest
	if err := json.Unmarshal(*req.Params, &createReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		createReq.RequestId = req.ID
		if err := marshalVaultParams(req, &createReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		createReq.RequestId = coalesceRequestID(createReq.RequestId, req.ID)
	}

	skipLabelValidation := publicKey == nil
	if err := p.validator.ValidateCreateSecretsRequest(ctx, publicKey, &createReq, skipLabelValidation); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		createReq.RequestId = prefixedRequestID
		vaultutils.ApplyEncryptedSecretNamespaceDefaults(createReq.EncryptedSecrets)
		return marshalVaultParams(req, &createReq)
	})
```

```go
func verifyEncryptedSecret(publicKey *tdh2easy.PublicKey, secret string) (*tdh2easy.Ciphertext, error) {
	cipherBytes, err := hex.DecodeString(secret)
	if err != nil {
		return nil, errors.New("failed to decode encrypted value:" + err.Error())
	}
	if publicKey == nil {
		// Public key can be nil if gateway cache isn't populated yet (immediately after gateway reboots).
		// Ok to not validate in such cases, since this validation also runs on Vault Nodes.
		return nil, nil
	}

	cipherText := &tdh2easy.Ciphertext{}
	if err := cipherText.UnmarshalVerify(cipherBytes, publicKey); err != nil {
		return nil, errors.New("failed to verify encrypted value:" + err.Error())
	}
	return cipherText, nil
```
