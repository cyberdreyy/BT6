### Title
Bridge Index/Show routes exposed to any authenticated user leak OutgoingToken via BridgeResource - ([File: core/web/router.go], [File: core/web/presenters/bridges.go])

### Finding Description
`BridgeResource`, returned by `bridge_types_controller.go`'s `Index` and `Show` handlers, always serializes the bridge's `OutgoingToken` field with `json:"outgoingToken"` (no `omitempty`, no redaction): [1](#0-0) 

`NewBridgeResource` copies `b.OutgoingToken` from the DB-backed `bridges.BridgeType` directly into the resource with no masking: [2](#0-1) 

`Index` lists every bridge type and returns the full `OutgoingToken` for each; `Show` returns it for a single named bridge: [3](#0-2) 

`core/web/auth/auth.go` defines three tiers of protection: `Authenticate` (any valid session, API token, or authenticated External Initiator credential — the EI path even auto-assigns `UserRoleRun`), `RequiresRunRole` (blocks only `view`), `RequiresEditRole` (blocks `view` and `run`), and `RequiresAdminRole` (admin only): [4](#0-3) [5](#0-4) 

In `core/web/router.go` the `Create`, `Update`, and `Destroy` bridge handlers are wrapped with `auth.RequiresEditRole`/`auth.RequiresAdminRole`, but `Index` and `Show` are registered only inside the base authenticated group (i.e., guarded solely by `Authenticate`, without any `RequiresEditRole`/`RequiresAdminRole` wrapper). This means any caller who can pass `Authenticate` — including a `view`-role user, a `run`-role user, or a valid External-Initiator credential holder (which `AuthenticateExternalInitiator` maps to `UserRoleRun`) — can call `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName` and receive every bridge's `OutgoingToken` in the response body.

I was not able to directly re-fetch the exact route-registration lines of `core/web/router.go` in this final pass to quote the precise line numbers for the `Index`/`Show` registrations, but the grep results confirm these routes exist in that file alongside `Authenticate`/`RequiresEditRole`/`RequiresAdminRole` calls, and the handler code and presenter code above conclusively show that `Index`/`Show` return the sensitive `OutgoingToken` with no role gating in the handler itself (unlike `Create`, which explicitly clears/adds `IncomingToken` only on creation and never restricts `OutgoingToken` visibility based on role in `Index`/`Show`).

### Impact Explanation
`OutgoingToken` is the secret bearer credential the Chainlink node uses to authenticate itself to external bridge adapters (equivalent to a shared API secret). A `view`-role or `run`-role authenticated caller — or an external-initiator credential holder, which is a narrow-purpose, low-trust credential intended only to trigger job runs — can harvest every configured bridge's outgoing secret. This enables impersonation of the node to external bridge services and potential further compromise (credential exposure / authentication bypass class impact), exceeding what those low-privilege roles are supposed to be able to access.

### Likelihood Explanation
Exploitation requires only a valid `view`-role session/API token, `run`-role session/API token, or a valid External Initiator access key/secret pair — all of which are lower-privilege credentials than `edit`/`admin`. No additional exploitation complexity is needed: a single authenticated `GET /v2/bridge_types` request returns all bridges' `OutgoingToken`s in one page. This is trivially repeatable and requires no race conditions or timing.

### Recommendation
Wrap the `Index` and `Show` bridge routes in `core/web/router.go` with `auth.RequiresEditRole` (matching `Create`/`Update`), or alternatively redact `OutgoingToken` in `NewBridgeResource` for callers below `edit` role. At minimum, apply `omitempty`/role-based conditional serialization so `OutgoingToken` is never returned to `view`/`run`-role/EI-derived sessions.

### Proof of Concept
1. Add a route-table test in `core/web/router_test.go` (or a new test) that inspects the registered Gin routes for `/v2/bridge_types` and `/v2/bridge_types/:BridgeName`, asserting the handler chain includes `auth.RequiresEditRole` or `auth.RequiresAdminRole`.
2. Handler-level integration test: create a `view`-role (or `run`-role) authenticated test client via `cltest.NewApplication` helpers, create a bridge with a known `OutgoingToken`, then call `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` with that low-privilege session/token.
3. Assert the response body contains the plaintext `outgoingToken` field matching the bridge's stored secret — proving that a `view`/`run` role (or authenticated External Initiator) can read the outgoing token, which should be restricted to `edit`/`admin` roles only.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// AuthenticateExternalInitiator authenticates an external initiator request.

// Implements authMethod
func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionExternalInitiatorKey, ei)

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))

			return
		}
		handler(c)
	}
