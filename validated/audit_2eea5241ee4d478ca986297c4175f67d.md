### Title
Unauthenticated `MethodPublicKeyGet` requests bypass all per-sender rate limiting, allowing DON-wide fan-out amplification before the public key cache is warm - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` explicitly skips `AuthorizeRequest` for `vaulttypes.MethodPublicKeyGet` and, when the in-memory cache is empty, creates a new `activeRequest` and forwards the request to every DON member via `fanOutToVaultNodes`. Unlike node-originated messages (protected by `h.nodeRateLimiter` in `HandleNodeMessage`), there is no per-sender or global rate limiter guarding this user-facing path, so an unauthenticated caller can generate an unbounded number of unique-ID requests to trigger repeated DON-wide fan-outs during any window where the cache is empty or being repopulated.

### Finding Description
In `core/services/gateway/handlers/vault/handler.go`, `HandleJSONRPCUserMessage` special-cases the public key method: [1](#0-0) 
When `getCachedPublicKey()` returns `nil, nil` (cache empty — e.g. at gateway startup, after a restart, or any period before the first quorum-backed response is cached), the code calls `h.newActiveRequest(req, callback)` and then `handlePublicKeyGet`, which calls `fanOutToVaultNodes`: [2](#0-1) [3](#0-2) 
`fanOutToVaultNodes` iterates `h.donConfig.Members` and calls `h.don.SendToNode` for each DON member — i.e., every unauthenticated request that misses the cache produces one gateway→node message per DON node.

The only per-request guard is `newActiveRequest`'s check that `req.ID` isn't already active: [4](#0-3) 
This only blocks ID *reuse*; an attacker trivially defeats it by using unique UUIDs per request, as the legitimate helper `FetchVaultPublicKey` itself does. [5](#0-4) 

Critically, the only rate limiter present in the handler, `h.nodeRateLimiter`, is applied solely to inbound node responses in `HandleNodeMessage`, not to inbound user requests: [6](#0-5) 
There is no equivalent per-sender limiter on the `HandleJSONRPCUserMessage` path for any vault method (authenticated or not), and the gateway's top-level `ProcessRequest` dispatcher performs no rate limiting of its own before invoking `h.HandleJSONRPCUserMessage`: [7](#0-6) 

### Impact Explanation
While the comment "we cache this value quite aggressively so don't need to worry about DoS" is largely accurate in steady state (once `tryCachePublicKeyResponse` populates `cachedPublicKeyGetResponse`/`cachedPublicKeyObject`, subsequent requests are answered synchronously with no fan-out), there is a real gap: during any interval where the cache is empty or being re-populated (gateway restart, cold start, cache never having succeeded due to a stale/rejected key as seen in `TestVaultHandler_HandleNodeMessage_SignatureValidatedResponse_RejectsUnknownFields`), an unauthenticated attacker can flood `MethodPublicKeyGet` with unique request IDs and force the gateway to send a full DON-wide broadcast for every single request, with no per-sender throttle. This is a genuine amplification/resource-exhaustion vector (gateway CPU/network, node ingress, `h.activeRequests` map growth) reachable with zero credentials, matching a Chainlink bounty "Denial of Service" / resource-exhaustion class finding, though it is bounded to the cache-cold window rather than being a truly permanent unbounded amplifier once the key is cached.

### Likelihood Explanation
Preconditions are minimal: only unauthenticated HTTP access to the gateway's vault endpoint is required, and the attack is trivially repeatable (generate a new UUID per request). The main constraint is the window size — how long the cache stays empty — which shrinks once the DON responds with quorum, but is non-zero at every gateway restart/cache-miss and can be prolonged by an attacker sending malformed/slow-quorum-breaking traffic to keep re-triggering the cache-miss branch during startup.

### Recommendation
Add a per-sender (and/or global) rate limiter on the `HandleJSONRPCUserMessage` path in `handler.go` that applies uniformly to all vault methods, including `MethodPublicKeyGet`, before `newActiveRequest`/`fanOutToVaultNodes` is invoked — mirroring the `nodeRateLimiter` pattern already used for node responses. Additionally, consider coalescing concurrent cache-miss `MethodPublicKeyGet` requests into a single in-flight fetch (e.g., singleflight) so that many simultaneous callers share one fan-out instead of each triggering its own.

### Proof of Concept
Go test plan (extends existing `handler_test.go` infra, e.g. `setupHandler`):
1. Build a `handler` with a DON of N members and an empty public key cache (do not call `cacheVaultPublicKeyForTest`).
2. Configure the mock `DON.SendToNode` to count invocations.
3. In a loop, call `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request{ID: uuid.New().String(), Method: vaulttypes.MethodPublicKeyGet}, callback)` M times concurrently (M >> DON size), without ever letting the cache populate (don't call `HandleNodeMessage` to complete quorum).
4. Assert: `SendToNode` was called `M * N` times (full fan-out per request), and no rate-limit/backoff error was returned for any of the M calls — i.e., `handlePublicKeyGet`/`fanOutToVaultNodes` executes unconditionally for every unique-ID request.
5. Compare against the existing per-sender `NodeRateLimiter` config (`PerSenderRPS`/`PerSenderBurst`) and show it is never consulted for this call path, confirming the absence of user-side throttling for `MethodPublicKeyGet`.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}
