### Title
Zip extraction follows attacker-created symlinks without sandbox-root confinement checks, allowing writes/chown/chtimes outside extraction directory - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` processes zip entries in two passes with no validation that a symlink entry's target, or a later entry's resolved path, stays within the intended extraction root. Unlike the tar+zstd extractor (`commands/helpers/archive/tarzstd/tarzstd_extractor.go`), which explicitly checks `filepath.Abs` and enforces a `strings.HasPrefix(path, e.dir+separator)` "chroot" boundary, the zip path (`helpers/archives/zip_extract.go`, `helpers/archives/zip_extra.go`) only guards against `.git` entries via `errorIfGitDirectory` and never validates path containment.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and for every entry calls `extractZipFile`, which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches based on file type [1](#0-0) . For `os.ModeSymlink` entries, `extractZipSymlinkEntry` removes any existing file and calls `os.Symlink(string(data), file.Name)`, where `string(data)` is the attacker-controlled symlink target read straight from the zip entry's content [2](#0-1) . For regular file entries, `extractZipFileEntry` calls `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)`, which follows any pre-existing symlink at `file.Name` [3](#0-2) .

Because zip entries are processed strictly in the archive's declared order, an attacker crafting the archive can place a symlink entry (e.g. `link -> ../shared-cache`) before a file entry named `link/victim-file`. When `extractZipFile` handles the second entry, `filepath.Dir(file.Name)` resolves to `link`, and `os.MkdirAll`/`os.OpenFile` follow the symlink created moments earlier by the first entry, writing `victim-file` through the symlink to whatever location it points to.

After both extraction passes, `ExtractZipArchive` runs a second loop calling `lchmod(file.Name, file.Mode())` and `processZipExtra(&file.FileHeader)` for every entry [4](#0-3) . `processZipExtra` reads `ZipUIDGidFieldType`/`ZipTimestampFieldType` extra fields and calls `processZipUIDGidField`/`os.Chtimes(file.Name, ...)` using the same attacker-controlled `file.Name` [5](#0-4) [6](#0-5) . Since these operate on `file.Name` (which still resolves through the symlink) rather than an `lchown`-only/no-follow guarantee at every step, ownership/timestamp changes can also land on the symlink target outside the extraction root.

The only existing check in this path is `errorIfGitDirectory`, which rejects `.git`-prefixed paths, and it provides no protection against symlink-based escapes or absolute/`..`-containing names [7](#0-6) . There is no equivalent of the `filepath.Abs` + `strings.HasPrefix(path, e.dir+separator)` containment check found in the tar+zstd extractor [8](#0-7) .

### Impact Explanation
A job supplying (or receiving from an untrusted source, e.g. a cache/artifact zip it controls) a specially crafted zip can cause the Runner's extraction logic to create files, and change permissions/ownership/timestamps, at locations reachable through an attacker-defined symlink target — not confined to the intended extraction directory. If the runner process's extraction working directory or symlink target resolution allows reaching paths outside the job's own workspace (e.g. relative `..` targets, or absolute paths in the symlink data), this results in writes/chown/chtimes outside the job's own sandboxed area, which is a concrete confinement violation matching the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
This is directly reachable by any pipeline author who controls the contents of an artifact/cache zip that Runner will extract via `ExtractZipFile`/`ExtractZipArchive` (both artifacts and cache download paths use this code, per `commands/helpers/archiver_test.go` and `commands/helpers/cache_extractor_test.go` references). Building such a zip with `archive/zip` in Go is trivial — no special privileges are needed, only the ability to define a job/cache/artifact archive, which is standard attacker capability per the threat model. Entry ordering within a zip is fully attacker-controlled, and Go's `archive/zip` iterates `archive.File` in the order stored, so the symlink-then-nested-file sequencing is reliable.

### Recommendation
Before creating any file/symlink/directory, resolve `file.Name`'s intended absolute path against the fixed extraction root and reject entries whose target (or whose parent directory chain, after following any symlink components) escapes that root — mirroring the containment check already used in `tarzstd_extractor.go`. Additionally, when writing regular files, avoid following pre-existing symlinks at the destination (e.g. use `O_NOFOLLOW` semantics where available, or `os.Lstat` the target first and refuse to write through an existing symlink), and validate/reject symlink entries whose target escapes the extraction root before calling `os.Symlink`.

### Proof of Concept
```go
// helpers/archives/zip_extract_symlink_escape_test.go
func TestExtractZipArchive_SymlinkEscape(t *testing.T) {
    tmp := t.TempDir()
    extractRoot := filepath.Join(tmp, "job-workspace")
    require.NoError(t, os.MkdirAll(extractRoot, 0o777))

    // simulate shared cache dir as a sibling, outside extractRoot
    victimDir := filepath.Join(tmp, "victim")
    require.NoError(t, os.MkdirAll(victimDir, 0o777))

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)

    // entry 1: symlink "link" -> "../victim"
    linkHeader := &zip.FileHeader{Name: "link"}
    linkHeader.SetMode(os.ModeSymlink | 0o777)
    w, _ := zw.CreateHeader(linkHeader)
    w.Write([]byte("../victim"))

    // entry 2: file "link/victim-file"
    fileHeader := &zip.FileHeader{Name: "link/victim-file"}
    fileHeader.SetMode(0o644)
    w2, _ := zw.CreateHeader(fileHeader)
    w2.Write([]byte("attacker content"))

    zw.Close()

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    os.Chdir(extractRoot)
    defer os.Chdir(wd)

    err := ExtractZipArchive(r)
    require.NoError(t, err)

    // Assert no file was created outside extractRoot
    _, statErr := os.Stat(filepath.Join(victimDir, "victim-file"))
    assert.True(t, os.IsNotExist(statErr), "victim-file should not exist outside extraction root, but it does")
}
```
Expected (buggy) behavior: `victim/victim-file` is created relative to the parent of `extractRoot`, proving the escape; the assertion `os.IsNotExist(statErr)` fails against current code, demonstrating the vulnerability.

```go
	var data []byte
```

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```

```go
func processZipExtra(file *zip.FileHeader) error {
	if len(file.Extra) == 0 {
		return nil
	}

	r := bytes.NewReader(file.Extra)
	for {
		field, data, err := readZipExtraField(r)
		if err == io.EOF {
			break
		} else if err != nil {
			return err
		}

		switch field.Type {
		case ZipUIDGidFieldType:
			err = processZipUIDGidField(data, file)
		case ZipTimestampFieldType:
			err = processZipTimestampField(data, file)
		}
		if err != nil {
			return err
		}
	}

	return nil
}
```
