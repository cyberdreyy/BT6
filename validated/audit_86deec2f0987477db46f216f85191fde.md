### Title
Confirmations from removed multisig members still count toward the approval threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm()` in `multisig2/src/lib.rs` authorizes execution of a request purely by comparing the *size* of the stored `confirmations` set for that `request_id` against the fixed `num_confirmations` threshold. When a member is removed via `DeleteMember`, `delete_member()` only purges confirmations for requests *created* by that member, not confirmations that member had *cast* on other members' requests. As a result, a confirmation coming from an account that is no longer a multisig member remains counted, letting a request execute with fewer than `num_confirmations` currently-live confirming members.

### Finding Description
The invariant the K-of-N scheme is supposed to maintain is:
```
confirmations recorded for request R that come from currently-live members == "at least K live members approved R"
```

`confirm()` breaks this: [1](#0-0) 

It only checks `confirmations.len()` (a raw count of strings previously inserted) against `self.num_confirmations`; it never re-validates that every entry in `confirmations` still corresponds to a member present in `self.members`.

`delete_member()` is the only place that prunes stale confirmations, and it does so incorrectly — it removes requests/confirmations keyed by the *request creator* (`r.member == member`), not by *whether the removed member had confirmed* some other request: [2](#0-1) 

Concretely:
1. Member A calls `add_request(...)`, creating request R (stored with `member: A`, empty `confirmations`).
2. Member B calls `confirm(R)`. Since `1 < num_confirmations`, B's identity string is inserted into `confirmations[R]` (not yet executed). [3](#0-2) 
3. Through a separate, properly-approved multisig request, member B is removed from the multisig via `DeleteMember { member: B }`. `delete_member()` only walks `self.requests` looking for `r.member == B` (i.e., requests B authored) to purge — R, authored by A, is untouched, so B's confirmation entry inside `confirmations[R]` survives. [4](#0-3) 
4. Now only 1 more live, distinct confirming member (call it C) is needed for `confirmations.len() as u32 + 1 >= num_confirmations` to trip and `execute_request` to run, even though B — one of the confirmers making up that count — is no longer a member.

`current_member()` and `assert_valid_request()` only check that the *caller* confirming right now is a live member; they never re-verify the members set stored in a request's pre-existing `confirmations` set. [5](#0-4) [6](#0-5) 

### Impact Explanation
This lets a multisig request (including `Transfer`, `AddKey`/`AddFullAccessKey`, `DeployContract`, or `AddMember`) execute with fewer than `num_confirmations` currently-live, distinct confirming members — i.e., a multisig request executed below threshold, which is explicitly listed as a Critical impact. Funds (NEAR balance of the multisig account) can be moved, or full access/control of the account can be granted, without the intended K-of-N authorization actually being satisfied at execution time.

### Likelihood Explanation
This requires member churn (an `AddMember`/`DeleteMember` cycle), which is a normal, expected multisig-management operation, not a privileged or out-of-scope action — any legitimate rotation of signers (e.g., removing a compromised or departing key/account) after that key had already confirmed a pending, not-yet-executed request leaves the exploitable stale confirmation. Since requests can remain outstanding for a while (bounded only by `REQUEST_COOLDOWN`/`active_requests_limit`), the race window between "confirm, then get removed" and "request finally executes" is realistic in normal operational flow, not purely theoretical.

### Recommendation
When removing a member in `delete_member()`, also scrub that member's identity string out of every entry in `self.confirmations` (not just requests they authored), or, simpler and more robust, have `confirm()`/`execute_request()` recompute the *live* confirmation count by intersecting `confirmations.get(&request_id)` with `self.members` before comparing to `num_confirmations`.

### Proof of Concept
1. Initialize multisig with 3 members `{A, B, C}` and `num_confirmations = 2`.
2. `A.add_request(request)` → request `R` created, `confirmations[R] = {}`.
3. `B.confirm(R)` → `confirmations[R] = {B}` (1 < 2, not yet executed). [7](#0-6) 
4. Separately, members confirm and execute a `DeleteMember{member: B}` request (a valid, properly-threshold-confirmed action). `delete_member()` runs its cleanup filter `r.member == B`, which matches nothing for `R` since `R.member == A`; `confirmations[R]` is left as `{B}`. [8](#0-7) 
5. Now only members `{A, C}` remain, with `num_confirmations` still `2`.
6. `C.confirm(R)` → `confirmations[R].len() + 1 == 2 >= num_confirmations` → `execute_request(R)` runs, even though B (one of the two counted confirmers) is no longer a member — R executes with only 1 live confirming member instead of the required 2. [9](#0-8)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

        let member = if env::current_account_id() == env::predecessor_account_id() {

                account_id: env::predecessor_account_id(),
            }

        }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
