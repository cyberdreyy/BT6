### Title
Cross-sender response hijack via colliding `message_id` in WebAPI trigger `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Finding Description
`JsonRPCCodec.DecodeRawRequest` / `DecodeJSONRequest` derives the internal request identity (`msg.Body.MessageId`) purely from the attacker-controlled JSON-RPC `id` field of the request body, overwriting whatever value was in the inner payload: `msg.Body.MessageId = request.ID` [1](#0-0) . This `MessageId` carries no binding to the authenticated sender — the sender is only derived later, during `Message.Validate()`, from the ECDSA signature (`m.Body.Sender = utils.StringToHex(...)`) [2](#0-1) , but nothing enforces that `MessageId` is unique per-sender or globally random.

In the legacy WebAPI-trigger path (`gateway.ProcessRequest` → `msg.Validate()` → `h.HandleLegacyUserMessage`) [3](#0-2) , the handler stores the response callback keyed **only** by `msg.Body.MessageId`, with no existence check and no sender component:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
``` [4](#0-3) 

Any later request — from any signer — reusing the same `message_id` unconditionally **overwrites** the map entry (no "already exists" rejection, unlike the vault/confidential-relay handlers). When the DON node eventually responds for the original (victim) message, delivery is looked up solely by `MessageId`:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
h.mu.Unlock()
if found {
    return savedCb.SendResponse(...)
}
``` [5](#0-4) 

Because the lookup key has no sender component, whichever caller's callback is currently registered under that `MessageId` receives the response — even if it was never their request. This directly violates the stated invariant that "request identity must include the authenticated sender." By contrast, `core/services/gateway/handlers/common/requestcache.go` correctly composes the key from both fields, `globalId{sender, id}` [6](#0-5) , and the vault/confidential-relay handlers reject ID collisions outright [7](#0-6) , showing the WebAPI-trigger handler is the outlier that lacks this protection.

### Impact Explanation
An unprivileged attacker with any valid signing key can submit a signed gateway request choosing the same `message_id` as an in-flight victim request to the WebAPI-trigger handler, causing the eventual DON-node response — intended for the victim — to be delivered to the attacker's HTTP connection instead. This is a cross-user response confusion / request impersonation vulnerability, matching the "Critical" bounty class for disclosure of another user's data to an unauthorized requester.

### Likelihood Explanation
Exploitation only requires: (1) knowledge or prediction of a victim's `message_id` (client-generated, no server-enforced randomness), and (2) timing the attacker's own signed request to land after the victim's request is registered but before the DON node's response returns — a race that is straightforward given typical DON round-trip latency (network + node processing time) and is fully repeatable per attempt.

### Recommendation
Key `savedCallbacks` (and any similar response-correlation maps) by a composite of `(sender, message_id)` instead of `message_id` alone, and reject (rather than silently overwrite) new registrations that collide with an existing in-flight entry — mirroring the pattern already used in `requestcache.go` and the vault/confidential-relay handlers.

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Create handler with a mocked `DON`.
2. Sign and submit a "victim" `HandleLegacyUserMessage` request with `MessageId = "shared-id"` using victim's private key and callback `cbVictim`; assert `savedCallbacks["shared-id"]` is set.
3. Before responding, sign and submit an "attacker" `HandleLegacyUserMessage` request also with `MessageId = "shared-id"` (different private key) with callback `cbAttacker`; assert `savedCallbacks["shared-id"]` now points to `cbAttacker` (overwrite, no error returned).
4. Simulate the DON node response for the original (victim) message via `HandleNodeMessage`/`handleWebAPITriggerMessage` using `MessageId = "shared-id"`.
5. Assert that `cbAttacker.Wait()` receives the victim's payload while `cbVictim.Wait()` times out — demonstrating cross-sender response delivery.

func (m *Message) Validate() error {

		return errors.New("nil message")

		return errors.New("invalid hex-encoded signature length")
	}

		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}

		return errors.New("invalid DON ID length")

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

type globalId struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
