### Title
Floor-division threshold in `GlobalStateEvaluator::reached_agreement` diverges from the ceiling-division threshold used for actual block-signature approval, letting signers declare "global agreement" below the true 70% supermajority - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement`, which decides the signer-set's agreed protocol version, burn-block view, current-miner state, and tx-replay set, computes the 70% threshold with **floor** division (`total_weight * 7 / 10`), while the consensus-critical threshold used to actually accept a block's aggregated signature weight, `NakamotoBlockHeader::compute_voting_weight_threshold`, computes the same nominal 70% with **ceiling** division. For any `total_weight` not divisible by 10, the two "70%" thresholds differ by one weight unit, so the state-machine evaluator can declare agreement on a value that is strictly less than 70% of total weight - the exact same "division truncation makes two conceptually-equal 70% quantities diverge" pattern as the referenced report's `lpSupply`/`vaultSupply` mismatch.

### Finding Description
`reached_agreement` in `libsigner/src/v0/signer_state.rs`: [1](#0-0) 
computes `floor(total_weight * 7 / 10)` and requires `vote_weight >= floor`.

The consensus-critical, node/chainstate-verified threshold in `stackslib/src/chainstate/nakamoto/mod.rs::compute_voting_weight_threshold` instead computes a ceiling: [2](#0-1) 
`ceil(total_weight * 7 / 10)`, and this is the value `verify_signer_signatures` (chainstate) and `store_and_process_block_signature` / `handle_block_pre_commit` (signer.rs) both use to gate actual block signature acceptance: [3](#0-2) [4](#0-3) 

For any `total_weight` where `total_weight * 7` is not a multiple of 10 (e.g. `total_weight = 13`: `13*7=91`, `floor(91/10)=9`, `ceil(91/10)=10`), `reached_agreement` accepts `vote_weight = 9` (69.2% of 13, i.e. strictly below 70%) as "agreement reached," while the block-signature path correctly requires `10` (76.9%, the true first integer ≥70%). `GlobalStateEvaluator::reached_agreement` gates `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which yields the agreed `current_miner`, burn view, and protocol version used elsewhere in the signer's chainstate checks): [5](#0-4) [6](#0-5) 

This means the signer's "global state" — which miner, burn view, protocol version, and tx-replay set it treats as authoritative for subsequent proposal/chainstate checks — can be latched-in by a coalition holding less than the true 70% supermajority, an off-by-one-unit weight gap from the value that would actually be required to get a block's signature aggregate accepted by the chainstate/node. This is precisely the report's bug class: a floor-division-derived quantity is treated as equivalent to a ceiling-division-derived quantity that governs the real acceptance/threshold check, and the two diverge by a rounding remainder.

The `_` const-assert test file confirms the project is aware `u32` overflow was fixed in `reached_agreement`/`reached_disagreement`, but the rounding-direction mismatch against `compute_voting_weight_threshold` was not addressed: [7](#0-6)  and the exact ceiling behavior is independently unit-tested elsewhere: [8](#0-7) 

### Impact Explanation
This does not directly forge a block signature or overturn the node-side `verify_signer_signatures` threshold (that check independently, correctly, uses the ceiling threshold). The impact is confined to the signer-local "global state machine" resolution: a minority coalition (holding as little as `floor(total*7/10)` weight, one unit below the true supermajority) can be treated by other signers as having established the network's agreed current miner / burn view / protocol version / tx-replay set. Since this "global state" feeds subsequent chainstate acceptance/rejection logic for proposals (miner-following, tenure/state-machine capitulation, tx-replay set adopted for validating a proposal), a signer can act on (validate/sign against) a state view that a true 70%-weighted majority never actually endorsed. This is a divergence between "signed vs. validated" expectations at the state-machine layer, not the raw signature-threshold layer, so it is lower severity than a directly forgeable block signature, but it can misalign a subset of signers' local views from the value that would satisfy the network's real acceptance threshold, contributing to state-machine wedges or divergent tenure/current-miner tracking across the fleet.

### Likelihood Explanation
Any `total_weight` where `total_weight * 7 mod 10 != 0` (the overwhelming majority of possible signer-weight totals) triggers the one-unit floor/ceiling gap; no attacker action beyond normal weight distribution is needed to open the gap — this is a latent, always-present off-by-one in the arithmetic rather than something that requires a majority or privileged access to trigger.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` use the same ceiling-division convention as `NakamotoBlockHeader::compute_voting_weight_threshold` (add the `+9` numerator trick or the explicit `ceil` remainder check used in the chainstate function), so that "global agreement" among signers and "sufficient signature weight to accept a block" use an identical, single definition of the 70% threshold. Ideally, factor the threshold computation into one shared helper used by both `libsigner`/`stacks-signer` and `stackslib` to eliminate any possibility of the two divison conventions drifting apart again.

### Proof of Concept
Using `total_weight = 13` (any total where `total*7 % 10 != 0` reproduces this):
```rust
// From libsigner/src/v0/signer_state.rs::reached_agreement
// floor((13 * 7) / 10) = floor(91/10) = 9
let evaluator = GlobalStateEvaluator { address_weights: HashMap::new(), address_updates: HashMap::new(), total_weight: 13 };
assert!(evaluator.reached_agreement(9)); // 9/13 = 69.23% < 70%, yet treated as "agreement reached"

// From stackslib/src/chainstate/nakamoto/mod.rs::compute_voting_weight_threshold
// ceil((13*7)/10) = 10 is the actual weight required to get a block's signatures accepted
assert_eq!(NakamotoBlockHeader::compute_voting_weight_threshold(13).unwrap(), 10);
```
`reached_agreement(9)` returns `true` even though `9 < 10`, the value the chainstate/node layer would actually require to accept a block's aggregate signature — demonstrating the floor-vs-ceiling threshold divergence identical in kind to the referenced report's supply/lpSupply truncation mismatch.

        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

/// Regression: u32 multiplication in `reached_agreement` wrapped silently in
/// release builds for `total_weight > u32::MAX / 7 ≈ 613_566_756`. With
/// `total_weight = 1_000_000_000` the buggy expression `total_weight * 7 / 10`

/// the 70% supermajority check. The fix widens to u64 first.

    // Pre-fix wrap landed at 270_503_270; assert that vote_weight at the wrapped
    // value is correctly rejected — i.e., 27% does not satisfy 70%.
    assert!(
        !evaluator.reached_agreement(270_503_270),
        "27% of total_weight must not satisfy the 70% threshold"
    );
    // Boundary: exactly 70% must pass.
    assert!(
        evaluator.reached_agreement(700_000_000),
        "70% of total_weight must satisfy the 70% threshold"
    );
    // Just below 70% must fail.
    assert!(
        !evaluator.reached_agreement(699_999_999),
        "below 70% must not satisfy the threshold"
    );
