### Title
Hard-coded Chainlink feed and USD0++ addresses can permanently freeze epoch settlement and user withdrawals - ([File: contracts/strategies/usual/IdleUsualStrategy.sol])

### Summary
`IdleUsualStrategy` hard-codes the Chainlink price feed (`USD0ppOracle`), the USD0++ token (`USD0pp`), and the reward token (`USUAL`) as `constant`s with no setter or upgrade-independent override. `IdleCDOUsualVariant.stopEpoch()` — the only path that re-enables withdrawals in this single-epoch vault — unconditionally calls `getChainlinkPrice()` on the hard-coded feed and reverts when the feed's `updatedAt` is older than 24 hours. If the feed is deprecated, migrated, or stops updating, `stopEpoch` reverts forever and all deposited USD0++ is permanently frozen.

### Finding Description
In `contracts/strategies/usual/IdleUsualStrategy.sol:46-48` the following are immutable constants:

```solidity
address public constant USUAL = 0xC4441c2BE5d8fA8126822B9929CA0b81Ea0DE38E;
address public constant USD0pp = 0x35D8949372D46B7a3D5A56006AE77B215fc69bC0;
address public constant USD0ppOracle = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;
```

`getChainlinkPrice()` (lines 164-172) reads `latestRoundData()` from `USD0ppOracle` and enforces `require(updatedAt > block.timestamp - 24 hours, "Stale price")`. This function is on the critical settlement path:

- `IdleCDOUsualVariant.startEpoch()` calls it at line 63 to store `priceAtStartEpoch`.
- `IdleCDOUsualVariant.stopEpoch()` calls it at line 77 and only afterwards sets `allowAAWithdraw = true` / `allowBBWithdraw = true` (lines 81-84). Withdrawals are disabled during the epoch (`startEpoch` sets both flags to false and pauses), so `stopEpoch` is the sole unlock mechanism.
- `initialize()` calls it at line 71 — a stale feed also bricks fresh deployments.
- `setOraclePrice()` (line 159) reads `IUSD0pp(USD0pp).getFloorPrice()` from the hard-coded token; if that call reverts the price can never be set either.

This is a single-epoch, "disposable" vault (see contract NatSpec at `IdleCDOUsualVariant.sol:9-16`). There is no mechanism to point the strategy at a replacement feed or replacement token: no setter exists for `USD0ppOracle`/`USD0pp`, and while the strategy is upgradeable via proxy, a feed deprecation would still halt `stopEpoch` until a code upgrade is deployed, and a wrong/compromised hard-coded address cannot be corrected at all in `initialize`d clones.

### Impact Explanation
Permanent freezing of user funds. During the running epoch both `allowAAWithdraw` and `allowBBWithdraw` are false and the contract is paused. If `USD0ppOracle` stops updating (Chainlink deprecates feeds regularly) or is misconfigured, `stopEpoch` reverts on `"Stale price"` indefinitely. `redeem`/`redeemUnderlying` in the strategy only transfer underlying 1:1 and are `onlyIdleCDO`, so tranche holders cannot bypass the CDO. All USD0++ deposited for the epoch — the entire TVL — becomes unrecoverable through normal flows. Severity is consistent with the referenced Medium finding.

### Likelihood Explanation
Chainlink routinely deprecates and replaces price feeds; feeds without sufficient deviation or heartbeat activity stop reporting. The 24-hour staleness check means any feed halt exceeding one day bricks settlement. No attacker action is required — the trigger is a third-party feed lifecycle event the protocol cannot react to because the address is a `constant`. The same class of issue was rated Medium in the referenced audit.

### Recommendation
Pass the oracle feed, USD0++, and USUAL addresses as `initialize()` parameters and/or add owner-gated setters, e.g. `setPriceFeed(address)`, instead of `constant`s. Additionally, decouple settlement liveness from the feed: allow the owner to call `stopEpoch` with an explicit fallback price path (e.g. `setOraclePrice` using only the USD0++ floor price, which is already validated at line 159-160) so withdrawals are not hostage to feed availability.

### Proof of Concept
Foundry fork test (mainnet) demonstrating permanent freeze after feed staleness:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../contracts/IdleCDOUsualVariant.sol";
import "../contracts/strategies/usual/IdleUsualStrategy.sol";

interface IChainlink {
    function latestRoundData() external view returns (uint80, int256, uint256, uint256, uint80);
}

contract UsualOracleFreezeTest is Test {
    IdleCDOUsualVariant cdo;          // deployed per repo deploy scripts
    IdleUsualStrategy strategy;       // strategy set on cdo

    function test_stopEpochRevertsWhenFeedStale() public {
        // assume: epoch started, deposits locked (allowAAWithdraw=false, allowBBWithdraw=false)

        // Simulate Chainlink deprecating/halting the hard-coded feed:
        // latestRoundData always reports an old timestamp.
        address feed = strategy.USD0ppOracle();
        vm.mockCall(
            feed,
            abi.encodeWithSelector(IChainlink.latestRoundData.selector),
            abi.encode(uint80(1), int256(1e8), uint256(0), block.timestamp - 2 days, uint80(1))
        );

        vm.warp(strategy.epochEndDate() + 1); // epoch matured
        vm.prank(cdo.owner());
        vm.expectRevert(bytes("Stale price"));
        cdo.stopEpoch();

        // Withdraw flags never set -> all user funds remain locked.
        // No setter exists for USD0ppOracle to recover.
    }
}
```

The same staleness mock applied before `initialize()`/`startEpoch()` shows deployment/epoch-start bricking via the calls at `IdleUsualStrategy.sol:71` and `IdleCDOUsualVariant.sol:63`.
