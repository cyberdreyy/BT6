### Title
`processZipTimestampField`'s `os.Chtimes` follows attacker-created symlinks, allowing cross-tenant mtime tampering outside the archive root - ([File: helpers/archives/zip_extra.go])

### Summary
`ExtractZipArchive` extracts every zip entry (including symlinks) in a first pass and then, in a second pass, calls `processZipExtra` → `processZipTimestampField` for every entry whose `zip.FileHeader.Mode()` reports `IsDir()` or `IsRegular()`. Because `os.Chtimes` follows symlinks on Unix (no `AT_SYMLINK_NOFOLLOW`/lutimes semantics are used) and the extractor performs no path confinement or entry-name deduplication, an attacker can make a path a symlink and still trigger a `Chtimes` call against that path via a second, differently-typed header entry sharing the same name, causing the mtime of the symlink's target—potentially outside the extraction root—to be modified.

### Finding Description
`extractZipFile` in `helpers/archives/zip_extract.go` dispatches purely on `file.Mode() & os.ModeType`: symlink entries call `extractZipSymlinkEntry`, which does `os.Remove(file.Name)` then `os.Symlink(string(data), file.Name)` with `data` (the symlink target) taken verbatim from the zip entry’s file content [1](#0-0) . There is no validation that the resulting symlink target stays inside the extraction directory, and no confinement check on `file.Name` itself beyond a `.git` directory check (`errorIfGitDirectory`) [2](#0-1) .

`ExtractZipArchive` runs two full passes over `archive.File`: the first creates/writes every entry (dirs, symlinks, files) in header order; the second calls `lchmod` and `processZipExtra` for every entry, again in header order [3](#0-2) . Critically, **both passes iterate the raw `archive.File` slice without deduplicating by name**, so a zip containing two entries with the identical `Name` (one a symlink, one a regular file with a `Timestamp` extra field) will both be processed.

`processZipTimestampField` only skips entries whose *own* header mode is neither `IsDir()` nor `IsRegular()` [4](#0-3) . For an entry whose header declares `Regular` mode (even though the on-disk path was last written as a symlink by a different, same-named entry earlier in pass 1), the function proceeds directly to `os.Chtimes(file.Name, acTime, modTime)` [5](#0-4) . `os.Chtimes` on Unix uses `utimensat`/`UtimesNano` without `AT_SYMLINK_NOFOLLOW`, so it follows the symlink and mutates the timestamp of the file the symlink points to, not the symlink itself.

Exploit flow:
1. Attacker crafts a zip with two entries named `"evil"`:
   - Entry B: mode = regular file, `Extra` contains a `Timestamp` field (`ZipTimestampFieldType`) with an attacker-chosen `ModTime`.
   - Entry A: mode = symlink (`os.ModeSymlink`), content = an escape path such as `../../../shared-cache/other-project/file`.
   - Ordered so A comes after B in the zip's central directory (i.e., in `archive.File`).
2. Pass 1: B is extracted first as a regular file, then A removes it and creates a symlink `"evil"` → the escape path. After pass 1 completes, `"evil"` is a symlink pointing outside the extraction root.
3. Pass 2: for entry B (`Mode` = regular in its header), `processZipTimestampField` passes the `IsRegular()` check and calls `os.Chtimes("evil", now, attacker_mtime)`. Since `"evil"` is now a symlink, `Chtimes` follows it and updates the mtime of the target file outside the intended workspace.
4. `lchmod` (`helpers/archives/os_unix.go`) does correctly avoid following symlinks via `AT_SYMLINK_NOFOLLOW`/Linux special-case, but `Chtimes` has no equivalent guard, confirming the asymmetry is a real gap rather than a deliberate no-op.

No existing check (`errorIfGitDirectory`, `pathErrorTracker`, `lchmod`) validates that `file.Name` or symlink targets stay confined to the extraction directory, and none prevents duplicate-name entries with conflicting types from being processed together.

### Impact Explanation
If cache/artifact restore extracts into a directory shared or reachable across project boundaries (e.g., a shared cache mount, a path outside the jailed workspace, or via a relative escape sequence reaching sibling project directories on the same host), the attacker can arbitrarily set the mtime/atime of files it does not own. This can corrupt build-cache invalidation logic (make/ninja/etc. relying on mtimes), silently invalidate or falsely validate another project’s cached artifacts, and persist after the job completes, since the target file is untouched in content but has attacker-controlled timestamps.

### Likelihood Explanation
The attacker only needs the ability to control the contents of a cache or artifact zip that will later be extracted by the Runner (a normal, unprivileged capability for any CI job that populates its own cache/artifacts). No additional privilege escalation is required; the vulnerable code path is reached deterministically by `ExtractZipArchive` on every cache/artifact restore. The only variable factor is whether the destination directory structure allows a relative symlink target to reach another project's files (dependent on runner cache-directory layout/executor), which is a plausible, commonly-discussed shared-cache configuration.

### Recommendation
- Reject or sanitize symlink targets during extraction: resolve `filepath.Join(destRoot, string(data))` and verify the result stays within `destRoot` before calling `os.Symlink`.
- In `processZipTimestampField` (and `processZipUIDGidField`), use an `Lchtimes`-style syscall (`AT_SYMLINK_NOFOLLOW` via `utimensat`) instead of `os.Chtimes`, mirroring the symlink-safe pattern already used in `lchmod`.
- Deduplicate/validate zip entries by name before extraction, rejecting archives with conflicting entry types for the same path.
- Add a general path-confinement check for every `file.Name` (Zip Slip protection), not just the `.git` special case.

### Proof of Concept
```go
func TestZipSymlinkTimestampEscape(t *testing.T) {
    dir := t.TempDir()
    require.NoError(t, os.Chdir(dir))

    escapeTarget := filepath.Join(dir, "..", "victim-file")
    require.NoError(t, os.WriteFile(escapeTarget, []byte("victim"), 0o644))
    origMtime := time.Now().Add(-48 * time.Hour)
    require.NoError(t, os.Chtimes(escapeTarget, origMtime, origMtime))

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)

    // Entry B: regular file w/ timestamp extra field
    hdrB := &zip.FileHeader{Name: "evil", Method: zip.Deflate}
    hdrB.SetMode(0o644)
    var extra bytes.Buffer
    require.NoError(t, createZipTimestampField(&extra, fakeFileInfo{mtime: time.Unix(1234567890, 0)}))
    hdrB.Extra = extra.Bytes()
    wB, _ := zw.CreateHeader(hdrB)
    wB.Write([]byte("regular content"))

    // Entry A: symlink escaping the extraction root
    hdrA := &zip.FileHeader{Name: "evil"}
    hdrA.SetMode(os.ModeSymlink | 0o777)
    wA, _ := zw.CreateHeader(hdrA)
    wA.Write([]byte("../victim-file"))

    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, ExtractZipArchive(zr))

    info, err := os.Lstat("evil")
    require.NoError(t, err)
    require.True(t, info.Mode()&os.ModeSymlink != 0, "evil should remain a symlink")

    victimInfo, _ := os.Stat(escapeTarget)
    // BUG: mtime was changed even though victim-file is outside the extraction dir
    assert.Equal(t, time.Unix(1234567890, 0).Unix(), victimInfo.ModTime().Unix(),
        "attacker was able to change mtime of a file outside the archive root via symlink")
}
```
Expected (buggy) result: the assertion passes, proving `victim-file`'s mtime was modified via the symlink despite residing outside the intended extraction directory. After applying the recommended `Lchtimes`/path-confinement fix, this assertion should fail (mtime unchanged) and/or symlink creation should be rejected for escaping targets.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
