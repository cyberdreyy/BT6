### Title
Unbounded management-fee accrual underflows NAV and forces epoch default - (File: contracts/IdleCDOCreditVault.sol)

### Summary
`unclaimedFees` can grow beyond the strategy-token balance because `_accrueManagementFee()` adds an unbounded time-based fee while `getContractValue()` subtracts the accumulated total without clamping it. [1](#0-0) [2](#0-1) 

### Finding Description
Management fees are calculated as `nav * managementFee * duration / (FULL_ALLOC * 365 days)` and appended directly to `unclaimedFees`. [2](#0-1) 

Although `managementFee` is limited to `MAX_FEE / 10`, the maximum is `2000`, or 2% per year. [3](#0-2) [4](#0-3) 

After more than `50 * 365 days` at the maximum rate, the newly accrued fee exceeds the vault’s entire NAV. [2](#0-1) 

A lender transaction such as `requestWithdraw()` invokes `_updateAccounting()`, which checkpoints the fee and then calls `getContractValue()`; the subtraction `strategyTokenBalance + tokenBalance - unclaimedFees` therefore underflows and reverts. [5](#0-4) [1](#0-0) 

`startEpoch()` can still begin a later epoch because it reads `getContractValue()` before the stale fee is checkpointed. [6](#0-5) 

At the subsequent `stopEpoch()`, `_accrueManagementFee()` persists the oversized fee and the nested accounting update underflows, causing the stop flow to enter its borrower-default handler. [7](#0-6) [8](#0-7) [9](#0-8) 

### Impact Explanation
All lender principal becomes unavailable through the normal epoch flow, and the borrower is marked defaulted even though the failure is caused by internal fee arithmetic rather than insufficient borrower repayment. [10](#0-9) 

For a vault holding `N` underlying units, the quantifiable frozen amount is the full `N` strategy-token-backed NAV plus any unpaid epoch interest. [1](#0-0) 

No unprivileged withdrawal can remove funds once the fee liability exceeds NAV, and recovery requires privileged default finalization or an implementation upgrade. [11](#0-10) 

### Likelihood Explanation
Triggering the overflow requires management-fee accounting to remain stale for more than 50 years at the maximum 2% annualized rate, or proportionally longer at lower rates. [12](#0-11) 

The required sequence uses only ordinary roles: a lender deposits, the honest manager runs one epoch normally, the vault remains in the buffer for the required duration, and the manager later starts and stops another epoch. [13](#0-12) [14](#0-13) 

The skim, KYC, pause, epoch, and default checks do not bound the fee total or prevent this arithmetic underflow. [5](#0-4) [1](#0-0) 

### Recommendation
Cap the accumulated `unclaimedFees` at the fee-bearing balance before each accrual, rather than allowing the cumulative value to exceed NAV. [2](#0-1) 

For example, calculate `availableBacking` before adding the new fee and store `min(unclaimedFees + accruedFee, availableBacking)`. [1](#0-0) 

Additionally, make `getContractValue()` use the saturated managed-value helper or explicitly return zero when fees exceed backing, so stale fee accounting cannot panic the epoch state machine. [15](#0-14) 

### Proof of Concept
Add this test inside `TestIdleCreditVault` in `test/foundry/IdleCreditVault.t.sol`, where `setUp()` already deploys `IdleCDOEpochVariant`, `IdleCreditVault`, an honest manager, a borrower with unlimited CDO allowance, and a funded lender. [16](#0-15) [17](#0-16) 

```solidity
function testManagementFeeAccrualOverflowsNAV() external {
    uint256 amount = 10_000 * ONE_SCALE;

    // Honest owner configures the maximum permitted 2% annualized fee.
    vm.prank(owner);
    cdoEpoch.setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, 2_000);

    // An unprivileged lender supplies NAV.
    idleCDO.depositAA(amount);

    // Epoch 0 completes normally.
    _startEpochAndCheckPrices(0);
    uint256 epoch0Interest = cdoEpoch.expectedEpochInterest();
    deal(defaultUnderlying, borrower, epoch0Interest);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(initialProvidedApr, 0);
    assertFalse(cdoEpoch.defaulted());

    // The latest fee checkpoint is the successful stop. At 2% annually,
    // 50 years + 1 second produces fees greater than the full NAV.
    vm.warp(block.timestamp + 50 * 365 days + 1);

    // A lender cannot create a withdrawal receipt: accounting underflows.
    vm.expectRevert(stdError.arithmeticError);
    cdoEpoch.requestWithdraw(1, address(AAtranche));

    // startEpoch does not checkpoint the stale fee before reading NAV, so the
    // honest manager can still begin another epoch.
    vm.prank(manager);
    cdoEpoch.startEpoch();

    // At the next stop, the oversized fee is persisted and accounting fails;
    // execution enters the borrower-default path.
    uint256 epoch1Interest = cdoEpoch.expectedEpochInterest();
    deal(defaultUnderlying, borrower, epoch1Interest);
    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.prank(manager);
    cdoEpoch.stopEpoch(initialProvidedApr, 0);

    assertTrue(cdoEpoch.defaulted());
    assertFalse(cdoEpoch.isEpochRunning());
    assertFalse(cdoEpoch.allowAAWithdrawRequest());
    assertFalse(cdoEpoch.allowBBWithdrawRequest());
}

  /// @notice Handle borrower default
  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
```
