### Title
Operator switch permanently misattributes unpaid pending commission to the new operator - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`switch_operator` in `staking_contract.move` re-keys a `StakingContract` (and its embedded `distribution_pool`) from the old operator's address to the new operator's address without purging the old operator's still-unresolved commission entry from that pool. Every subsequent commission-charging pass over the shared `distribution_pool` treats the old operator's outstanding balance as an ordinary "shareholder" and skims further commission off it in favor of the *new* operator, silently transferring stake value from the old operator to the new operator.

### Finding Description
When a staker switches operators, `switch_operator` first forces a full distribution and commission request for the outgoing operator: [1](#0-0) 

`request_commission_internal` only unlocks (moves to `pending_inactive`) whatever commission is currently accrued and records it via `add_distribution(operator, staking_contract, operator, commission_amount)`, which buys the old operator shares in `distribution_pool`: [2](#0-1) [3](#0-2) 

Because unlocked stake still earns rewards until the lockup expires and becomes fully withdrawable, this unpaid commission balance sitting in `distribution_pool` under the **old operator's address** keeps compounding even after `switch_operator` swaps the map key to `new_operator` and updates `commission_percentage`: [4](#0-3) 

Every later mutation of the same `distribution_pool` (`unlock_stake`, `request_commission`, `distribute`, or another `switch_operator`) re-runs `update_distribution_pool`, which is passed the *current* operator (`new_operator`) and skims commission from every other shareholder's balance growth into that current operator's shares: [5](#0-4) 

Since `old_operator` is now just another address in `shareholders` (it is no longer the `operator` parameter), the growth of its still-pending commission balance is treated as "staker rewards" and a portion of it (`commission_percentage`) is transferred via `pool_u64::transfer_shares` from `old_operator` to `new_operator`. The old operator never authorized this and has no way to prevent it once `switch_operator` is called while any commission is still unpaid/pending_inactive.

`distribute` itself is intentionally permissionless ("Allow anyone to distribute already unlocked funds"), so any third party can trigger the epoch-driven reward accrual and subsequent `distribute_internal`/`update_distribution_pool` skim without needing any privileged role: [6](#0-5) 

### Impact Explanation
This breaks the "operator commission payout must credit the correct account" invariant explicitly listed in scope. Value that legitimately belongs to the outgoing operator (already-earned, already-unlocked commission awaiting the lockup to finish) is siphoned into the new operator's share balance whenever rewards continue to accrue on the pending_inactive amount before the staker/anyone calls `distribute`. This is a real redirection of stake value between two operator accounts, not merely a display/event mismatch, and it happens automatically without either operator's consent as part of routine `switch_operator` usage.

### Likelihood Explanation
Likelihood is moderate-to-high: operator switches are a normal, unprivileged-by-the-staker (staker-only, but not operator-privileged) action, and it is common for a validator's unlocked commission to still be in the `pending_inactive` state (subject to the staking lockup, which can be weeks) at the moment a staker decides to switch operators. Any epoch boundary between the switch and the next `distribute()`/`unlock_stake()`/`request_commission()` call triggers the misattribution, and `distribute` can be invoked by anyone, including the new operator itself, to realize the gain.

### Recommendation
Before or during `switch_operator`, fully settle and remove the old operator's distribution-pool balance (e.g., force a `distribute_internal` that pays out the old operator's shares directly, or track/exclude the old operator's address from future commission-skimming passes even after the map key changes), so that `update_distribution_pool` never treats a former operator's already-earned balance as a chargeable "shareholder" for the new operator's benefit.

### Proof of Concept
1. Staker creates a staking contract with `operator_A`, 10% commission; `operator_A` joins the validator set and the pool earns rewards.
2. `operator_A`'s accrued commission is requested (`request_commission`) but the staking pool's lockup has not yet expired, so the unlocked commission sits as `pending_inactive` inside `distribution_pool` under `operator_A`'s address (not yet withdrawn).
3. Staker calls `switch_operator(staker, operator_A, operator_B, new_commission_percentage)`. Per lines 783-805, `distribute_internal`/`request_commission_internal` run once, then the `StakingContract` (with its `distribution_pool` still containing `operator_A`'s pending share balance) is re-keyed to `operator_B`.
4. At least one more epoch passes, growing the pending_inactive stake (including `operator_A`'s still-locked commission) via staking rewards.
5. Anyone calls `distribute(staker, operator_B)` (permissionless per line 842-853). `distribute_internal` → `update_distribution_pool(distribution_pool, updated_total_coins, operator_B, commission_percentage)` iterates shareholders; since `operator_A != operator_B`, the pool's logic computes "unpaid commission" on the reward growth of `operator_A`'s existing balance and transfers those shares from `operator_A` to `operator_B` (lines 1001-1039).
6. `operator_A` ends up with fewer coins than it earned and unlocked before the switch; `operator_B` receives coins it did not earn commission on, from a period during which it was not even the operator.

**Note on verification limits:** I was unable to locate the exact `switch_operator` function signature/header via search (only its body and the `switch_operator_with_same_commission` spec name were indexed), so the function name is inferred from the `SwitchOperator` event and surrounding logic; a Devin session with full repo access should confirm the exact function name/line range and add a regression test reproducing the cross-operator share transfer described above before landing a fix.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Add a new distribution for `recipient` and `amount` to the staking contract's distributions list.
    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
