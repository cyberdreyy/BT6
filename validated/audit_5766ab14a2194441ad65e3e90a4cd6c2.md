## Title
`gas_key_transfer_exec_fee` undercharges TransferToGasKey/WithdrawFromGasKey exec cost when the target gas key is `GasKeyFunctionCall` with a non-trivial `FunctionCallPermission` - ([File: core/parameters/src/cost.rs])

## Summary
`gas_key_transfer_exec_fee` bases its per-byte trie charge on `AccessKey::min_gas_key_borsh_len()`, which is defined as the serialized size of the smallest gas-key variant, `GasKeyFullAccess` (no `FunctionCallPermission`). The exec path (`action_transfer_to_gas_key`/`action_withdraw_from_gas_key`) reads and rewrites the *entire* `AccessKey` via `set_access_key`, including a `GasKeyFunctionCall`'s `FunctionCallPermission { allowance, receiver_id, method_names }`, whose serialized size can be substantially larger than `min_gas_key_borsh_len()`.

## Finding Description
`AccessKey::min_gas_key_borsh_len()` is computed from `Self::gas_key_full_access(0)`, i.e., `AccessKeyPermission::GasKeyFullAccess(GasKeyInfo{...})`, which has no `FunctionCallPermission` payload: [1](#0-0) 

`gas_key_transfer_exec_fee` uses this constant as `estimated_value_len` for the whole trie value it charges for: [2](#0-1) 

However, `AccessKey` also has a `GasKeyFunctionCall(GasKeyInfo, FunctionCallPermission)` variant, whose `FunctionCallPermission` carries a `receiver_id: String` and `method_names: Vec<String>`: [3](#0-2) 

`action_transfer_to_gas_key` and `action_withdraw_from_gas_key` read the full `AccessKey` from the trie (`get_access_key`), mutate only the `GasKeyInfo.balance` field in place, and then call `set_access_key` to write back the **entire** `AccessKey` value — including the unchanged `FunctionCallPermission` payload: [4](#0-3) [5](#0-4) 

So the real trie write size for a `GasKeyFunctionCall` key is `access_key_key_len + borsh::object_length(actual_AccessKey)`, which grows with `receiver_id.len()` and the count/length of `method_names`, while the exec fee is fixed at `access_key_key_len + AccessKey::min_gas_key_borsh_len()` regardless of the actual permission's size. An attacker who creates their own gas key with a `GasKeyFunctionCall` permission using a long `receiver_id` and/or many/long `method_names` (allowed sizes bounded only by generic transaction/action byte-size limits, not by any gas-key-specific size check tied to this fee) can then repeatedly call `TransferToGasKey`/`WithdrawFromGasKey` against that key, each time causing the runtime to serialize/write a much larger trie value than what the exec fee (`gas_key_transfer_exec_fee`) accounts for.

I was unable to fully verify within the available context whether `action_validation.rs` imposes a byte-size cap on `FunctionCallPermission.method_names`/`receiver_id` specifically for gas keys (the file was found but its content wasn't retrieved before the iteration limit), so I cannot state with certainty how large the discrepancy can practically get, only that the fee formula structurally undercharges relative to the real serialized value whenever the actual variant differs from the minimum-size reference used to derive the constant.

## Impact Explanation
This is a gas-metering/fee-payment-bypass issue: the sender pays less gas than the actual trie read/write work performed by the runtime for `TransferToGasKey`/`WithdrawFromGasKey` on a `GasKeyFunctionCall` key with a non-trivial permission. Repeated invocation lets an attacker perform trie I/O work cheaper than intended, which is a metering-totality violation (fee should equal or exceed real work) rather than direct fund theft — it falls under "gas cost underestimation / fee bypass" rather than direct loss of user funds, consensus divergence, or a halting bug.

## Likelihood Explanation
Preconditions are fully within reach of an unprivileged attacker: they can add their own `GasKeyFunctionCall` access key (paying the normal `AddKey` fee, which is itself based on `GasKeyInfo::borsh_len()` not accounting for `FunctionCallPermission` size either) with a large `receiver_id`/`method_names`, then submit `TransferToGasKey`/`WithdrawFromGasKey` transactions against it repeatedly. This requires no validator/node access and is trivially repeatable, bounded only by the maximum allowed sizes for `receiver_id`/`method_names` in a transaction/access key (whatever those generic limits are — not verified here).

## Recommendation
Compute `estimated_value_len` in `gas_key_transfer_exec_fee` from the actual `AccessKey`'s serialized length (or at minimum from `AccessKeyPermission`-variant-aware sizing that includes the real `FunctionCallPermission` payload) rather than the constant `AccessKey::min_gas_key_borsh_len()`. Pass the real access key (or its borsh length) into `gas_key_transfer_exec_fee`/`gas_key_transfer_send_fee` from `action_transfer_to_gas_key`/`action_withdraw_from_gas_key`, mirroring how `access_key_storage_usage` already uses `borsh::object_length(access_key)` for storage staking.

## Proof of Concept
Unit test in `core/parameters/src/cost.rs` (or a new test module):
1. Construct `let fcp = FunctionCallPermission { allowance: None, receiver_id: "a".repeat(64), method_names: vec!["m".repeat(32); 10] };`
2. Construct `let access_key = AccessKey::gas_key_function_call(0, fcp);`
3. Assert `borsh::object_length(&access_key).unwrap() > AccessKey::min_gas_key_borsh_len()`.
4. Call `gas_key_transfer_exec_fee(cfg, account_id_len, public_key_len)` and compare its `per_byte` basis (`access_key_key_len + AccessKey::min_gas_key_borsh_len()`) against `access_key_key_len + borsh::object_length(&access_key).unwrap()`, asserting the fee's byte basis is strictly smaller — demonstrating the undercharge.
5. (Integration) In `runtime/runtime/src/access_keys.rs` tests, add a gas key with a large `FunctionCallPermission`, call `action_transfer_to_gas_key`, and assert that the gas charged (via the fee helper) is less than `borsh::object_length` of the value actually written via `set_access_key`.

pub fn gas_key_transfer_exec_fee(
    cfg: &RuntimeFeesConfig,
    account_id_len: usize,
    public_key_len: usize,
) -> GasKeyTransferFee {
    let base = cfg.fee(ActionCosts::gas_key_transfer_base).exec_fee();
    let trie_key_len = access_key_key_len(account_id_len, public_key_len);
    let estimated_value_len = AccessKey::min_gas_key_borsh_len();
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .exec_fee()
        .checked_mul((trie_key_len + estimated_value_len) as u64)
        .unwrap();
    GasKeyTransferFee { base, per_byte }
}

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}

pub(crate) fn action_withdraw_from_gas_key(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &WithdrawFromGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    let Some(updated_balance) = gas_key_info.balance.checked_sub(action.amount) else {
        result.result = Err(ActionErrorKind::InsufficientGasKeyBalance {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
            balance: gas_key_info.balance,
            required: action.amount,
        }
        .into());
        return Ok(());
    };
    gas_key_info.balance = updated_balance;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);

    let new_account_balance = account.amount().checked_add(action.amount).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "Account balance integer overflow".to_string(),
        ))
    })?;
    account.set_amount(new_account_balance);
    Ok(())
}
