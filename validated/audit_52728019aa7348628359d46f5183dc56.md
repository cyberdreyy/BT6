### Title
Unhandled USD0++ Chainlink feed failure permanently blocks epoch completion and withdrawals - ([File: contracts/strategies/usual/IdleUsualStrategy.sol])

### Summary

`IdleUsualStrategy.getChainlinkPrice()` calls `latestRoundData()` on the hard-coded USD0++ Chainlink feed without handling a revert, while `IdleCDOUsualVariant.stopEpoch()` must successfully call it before enabling AA and BB withdrawals. If the feed reverts or returns data failing the freshness check, the honest owner cannot stop a running epoch, leaving user funds locked for the duration of the oracle failure. [1](#0-0) [2](#0-1) 

### Finding Description

`startEpoch()` pauses deposits and sets both `allowAAWithdraw` and `allowBBWithdraw` to `false`, then records the Chainlink price and deposits the vault’s underlying tokens into the strategy. [3](#0-2) 

After `epochEndDate`, `stopEpoch()` calls `IdleUsualStrategy.getChainlinkPrice()` before setting either withdrawal flag to `true`. [4](#0-3) 

`getChainlinkPrice()` performs a direct `latestRoundData()` call and then reverts if the returned timestamp is older than 24 hours. [5](#0-4) 

Neither the external call nor the freshness failure is wrapped in a `try/catch`, and `stopEpoch()` has no fallback path that uses the stored `oraclePrice` or an owner-supplied emergency price. Because state changes are atomic, a failed `stopEpoch()` leaves `isEpochRunning == true`, `allowAAWithdraw == false`, and `allowBBWithdraw == false`. [6](#0-5) 

An unprivileged tranche holder cannot trigger the Chainlink outage, but once that external condition occurs, every withdrawal remains blocked regardless of the holder’s transactions until the feed resumes returning acceptable data.

### Impact Explanation

The full balance deposited into the running Usual epoch is temporarily frozen because neither tranche withdrawal flag can be enabled until `stopEpoch()` completes. [6](#0-5) 

If the vault holds `N` USD0++ during the running epoch, all `N` USD0++ backing AA and BB tranche tokens remain inaccessible for the duration of the oracle outage or stale-feed condition.

This is not theft or insolvency by itself, but it breaks the epoch lifecycle’s availability invariant: after `epochEndDate`, the vault must eventually transition to the withdrawal-enabled state. [7](#0-6) 

### Likelihood Explanation

The issue requires an exceptional Chainlink condition such as feed contract unavailability, a reverting aggregator, or an update age exceeding the configured 24-hour threshold. [5](#0-4) 

The affected call is on the mandatory epoch-exit path, so there is no alternate user withdrawal route while `allowAAWithdraw` and `allowBBWithdraw` remain false. [2](#0-1) 

Likelihood is moderate to low because the failure depends on an external feed outage rather than an action an unprivileged attacker can directly force.

### Recommendation

Handle feed failure explicitly on the epoch-exit path.

- Wrap `latestRoundData()` in `try/catch`.
- Validate `answer > 0`, round completeness, and freshness before accepting the returned price.
- Add a narrowly scoped owner emergency-stop path that accepts an explicit price or uses the last accepted `oraclePrice` when Chainlink is unavailable.
- Clamp any fallback price through the existing `setOraclePrice()` floor-price logic.
- Emit an event when fallback pricing is used.
- Alternatively, allow withdrawals to be enabled while deferring only the price-dependent AA/BB loss redistribution, if the accounting design permits that safely.

Do not silently treat a failed feed as a valid price; the mitigation needs an explicit, auditable fallback path.

### Proof of Concept

Add the following test to `test/foundry/IdleUsualStrategy.t.sol`. It uses the existing mainnet-fork fixture and mocks the USD0++ Chainlink feed as reverting only after the epoch has legitimately started:

```solidity
function testStopEpochRevertsWhenChainlinkFeedUnavailable() external {
    uint256 amount = 10_000 * ONE_SCALE;

    idleCDO.depositAA(amount);
    idleCDO.depositBB(amount);

    IdleCDOUsualVariant usualCDO = IdleCDOUsualVariant(address(idleCDO));

    vm.prank(owner);
    usualCDO.startEpoch(100);

    vm.warp(block.timestamp + 100);

    address feed = 0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB;
    vm.mockCallRevert(
        feed,
        abi.encodeWithSignature("latestRoundData()"),
        "CHAINLINK_UNAVAILABLE"
    );

    vm.prank(owner);
    vm.expectRevert("CHAINLINK_UNAVAILABLE");
    usualCDO.stopEpoch();

    assertTrue(usualCDO.isEpochRunning());
    assertFalse(usualCDO.allowAAWithdraw());
    assertFalse(usualCDO.allowBBWithdraw());
}
```

    _checkOnlyOwner();
    // if the epoch is not running we revert
    require(isEpochRunning && block.timestamp >= epochEndDate, "9");

    // we fetch and set oracle price for reference

    _strategy.setOraclePrice(_oraclePrice);

    allowAAWithdraw = true;
    allowBBWithdraw = true;
