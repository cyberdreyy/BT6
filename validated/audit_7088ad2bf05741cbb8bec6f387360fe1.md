### Title
Programmable ERC4626 losses are erased from NAV and let early withdrawers escape the loss waterfall - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary

`ProgrammableBorrower` recognizes ERC4626 losses only as a reduction of epoch interest, while `IdleCDOEpochVariant` continues to value the CDO’s fixed-rate strategy-token claim at face value. The loss baseline is then reset at the next `onStartEpoch`, permanently erasing the impairment from CDO accounting. A KYC-approved tranche holder can request withdrawal after an external vault loss and receive an unhaircutted payout, leaving the remaining lenders with claims exceeding the surviving collateral.

### Finding Description

`IdleCDOCreditVault.getContractValue()` values NAV as the CDO-held `strategyToken` balance plus raw underlying, minus fees; it does not inspect the programmable borrower’s actual ERC4626 collateral value. [1](#0-0) 

During the running epoch, `ProgrammableBorrower._vaultNetInterest()` computes an external-vault loss by comparing live vault assets plus tracked withdrawals against the epoch principal baseline. [2](#0-1)  However, `totalInterestDueNow()` exposes this principal loss only by subtracting it from gains and flooring the result at zero; the loss itself is not returned to the CDO. [3](#0-2) 

At stop, `IdleCDOEpochVariant._stopEpoch()` resolves that zero interest and calls `previewLossAdjustedWithdrawFunds(_lossAmount)`, but the programmable-borrower path does not populate `_lossAmount` from `vaultLoss()`. [4](#0-3)  Consequently, `_updateAccounting()` runs without burning strategy tokens or applying the BB-first loss waterfall. [5](#0-4) 

The borrower hook then snapshots the already-impaired vault position as `bufferStartVaultAssets` and disables epoch accounting. [6](#0-5)  On the next start, `onStartEpoch()` sets `epochStartVaultAssets` to that depleted asset value, so the previous impairment becomes the new principal baseline rather than a realized loss. [7](#0-6) 

During the intervening buffer, `requestWithdraw()` prices the request through stale tranche prices and records a fixed underlying receipt. [8](#0-7)  At the next stop, `onStopEpoch()` withdraws that full receipt amount whenever the impaired vault position can cover it, rather than reducing it by the vault loss. [9](#0-8) 

### Impact Explanation

The vault treats an external ERC4626 principal loss as unpriced collateral instead of a pool loss. A withdrawal request made before the next successful epoch settlement is paid at the pre-loss price, while the borrower adapter resets its baseline and prevents the loss from ever reaching `_updateAccounting()`.

Example: two AA lenders deposit 50 USDC each. The programmable borrower invests 100 USDC into the ERC4626 vault, which then suffers a 20 USDC loss. At epoch stop, `totalInterestDueNow()` returns zero and CDO NAV remains 100 USDC. Alice requests her full 50 USDC claim. The next epoch starts with an 80 USDC collateral baseline, and its stop pays Alice 50 USDC. Only 30 USDC remains for Bob’s still-recorded 50 USDC claim.

The fair BB-first/pro-rata outcome would give each lender 40 USDC if both are in the same tranche. Alice instead receives 50 USDC, causing a direct 10 USDC transfer of the external loss to Bob and leaving the vault insolvent by 20 USDC relative to outstanding tranche claims. If AA and BB exist, the ordinary waterfall is also bypassed because BB is not burned before the privileged-timing withdrawal escapes.

### Likelihood Explanation

Likelihood depends on an impairment of the configured ERC4626 vault, which is precisely the external-credit exposure modeled by this integration. The exploitable action thereafter is permissionless for any KYC-passing tranche holder: request withdrawal during the buffer before the adapter’s depleted collateral becomes the next accounting baseline.

The manual `stopEpochWithDuration(..., _lossAmount)` mechanism could socialize the loss if an honest manager independently detects and supplies the correct vault loss. However, the normal programmable-borrower `stopEpoch()` path reads only `totalInterestDueNow()`, floors the result at zero, and provides no automatic link from `vaultLoss()` to `_lossAmount`, so correct loss processing depends on an extra off-chain privileged action rather than an enforced contract invariant.

### Recommendation

Return both net interest and principal loss from the programmable-borrower hook, or have `IdleCDOEpochVariant` read `vaultLoss()` and combine it with any manager-supplied `_lossAmount` before calling `previewLossAdjustedWithdrawFunds()`.

The impaired amount should be passed through the existing pending-receipt/active-position loss split and then burned through `burnStrategyTokens()` followed by `_forceUpdateAccounting()`. Do not reset `epochStartVaultAssets` to a depleted value until that deficit has been realized in CDO NAV. A successful stop should additionally enforce a solvency invariant such as:

```solidity
programmableBorrower.totalUnderlying() + pendingReceiptFunding >= cdoManagedPrincipal + borrowerDebt
```

with the ERC4626 position valued by `convertToAssets()`. If valuation cannot be trusted or the remaining collateral cannot cover priced claims, the stop should enter the explicit loss/default path instead of repricing the baseline.

### Proof of Concept

The following fork test uses the existing `ProgrammableBorrowerCreditVault.t.sol` deployment. The fork-only share transfer represents an already-realized ERC4626 venue loss analogous to the upstream Mango impairment; all exploit-relevant protocol actions are performed by a KYC-passing lender or the honest manager.

```solidity
function testVaultLossEscapesNavAndEarlyWithdrawerIsPaidAtPar() external {
    uint256 aliceDeposit = 50_000 * oneScale;
    uint256 bobDeposit   = 50_000 * oneScale;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    // Alice and Bob are KYC-passing lenders.
    deal(USDC, alice, aliceDeposit, true);
    deal(USDC, bob, bobDeposit, true);

    vm.startPrank(alice);
    underlying.approve(address(idleCDO), aliceDeposit);
    idleCDO.depositAA(aliceDeposit);
    vm.stopPrank();

    vm.startPrank(bob);
    underlying.approve(address(idleCDO), bobDeposit);
    idleCDO.depositBB(bobDeposit);
    vm.stopPrank();

    _startEpochAndCheckPrices(0);

    // External ERC4626 loss: 20% of the programmable borrower's vault position.
    // On a fork this can be reproduced through the vault's real loss/bad-debt path;
    // pranking the holder here is only an environment fixture for the realized loss.
    uint256 lostShares = morphoVault.balanceOf(address(programmableBorrower)) / 5;
    vm.prank(address(programmableBorrower));
    morphoVault.transfer(makeAddr("externalVaultLoss"), lostShares);

    uint256 vaultLoss = programmableBorrower.vaultLoss();
    assertGt(vaultLoss, 0);
    assertEq(programmableBorrower.totalInterestDueNow(), 0);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Honest manager uses the normal programmable stop path. No loss reaches CDO NAV.
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 staleNav = cdoEpoch.getContractValue();
    assertEq(staleNav, aliceDeposit + bobDeposit);

    // Alice requests at the stale pre-loss price during the buffer.
    vm.prank(alice);
    uint256 aliceRequest = cdoEpoch.requestWithdraw(
        aaTranche.balanceOf(alice),
        address(aaTranche)
    );
    assertEq(aliceRequest, aliceDeposit);

    // The depleted 80k position becomes the next epoch's principal baseline.
    vm.warp(cdoEpoch.epochEndDate() + cdoEpoch.bufferPeriod() + 1);
    vm.prank(manager);
    cdoEpoch.startEpoch();

    assertEq(
        programmableBorrower.epochStartVaultAssets(),
        aliceDeposit + bobDeposit - vaultLoss
    );

    // The next stop funds Alice's receipt in full from the impaired position.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 aliceBefore = underlying.balanceOf(alice);
    vm.prank(alice);
    cdoEpoch.claimWithdrawRequest();

    assertEq(
        underlying.balanceOf(alice) - aliceBefore,
        aliceDeposit,
        "Alice escaped the vault haircut"
    );

    // Bob still has a 50k accounting claim, but only 30k of external collateral remains.
    assertApproxEqAbs(
        programmableBorrower.totalUnderlying(),
        bobDeposit - vaultLoss,
        2
    );
    assertGt(
        cdoEpoch.getContractValue(),
        programmableBorrower.totalUnderlying(),
        "stale NAV exceeds surviving collateral"
    );
}
```

The final assertion demonstrates the broken solvency invariant: the CDO retains Bob’s unhaircutted strategy-token NAV after Alice received a par payout, even though the programmable borrower holds substantially less collateral.

  /// @notice Total net epoch interest due to the pool at stop.
  /// @dev This is the single value read by IdleCDO to price the epoch: borrower contractual
  /// interest plus paid buffer interest plus positive vault PnL minus vault losses. It is a
  /// pool-facing value, so it can be lower than `borrowerInterestDebt` when the borrower still
  /// owes full contractual interest but the vault sleeve suffered a loss.
  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }
