### Title
Operator can permanently freeze a staker's `staking_contract` funds by setting a beneficiary that rejects direct coin transfers - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::set_beneficiary_for_operator` lets any operator repoint their commission payouts to an arbitrary, unregistered address, with no validation that the new beneficiary can actually receive `AptosCoin`. Because `distribute_internal` pays out *every* recipient in the shared `distribution_pool` in a single atomic loop, a beneficiary address that has opted out of direct coin transfers causes the entire distribution — and therefore every operation that depends on it (`distribute`, `unlock_stake`, `update_commision`, `switch_operator`) — to permanently revert, trapping the staker's principal, pending withdrawals, and commission funds.

### Finding Description
`set_beneficiary_for_operator` is callable by the operator alone and performs no registration check on `new_beneficiary`: [1](#0-0) 

`distribute_internal` iterates the `distribution_pool`'s shareholders and unconditionally calls `aptos_account::deposit_coins` for each one, redirecting the operator's payout to the operator's beneficiary just before the deposit: [2](#0-1) 

`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the recipient has never registered a `CoinStore<AptosCoin>` and has opted out of direct transfers: [3](#0-2) 

An unprivileged actor can create an account and call `aptos_account::set_allow_direct_coin_transfers(false)` on it without ever registering it for `AptosCoin` — this call requires no coin balance or registration. If an operator (which requires no special privilege beyond being an operator of some `staking_contract`, itself an unprivileged role obtainable by anyone a staker chooses) sets this address as their beneficiary via `set_beneficiary_for_operator`, then the next time `distribute_internal` reaches that recipient, `deposit_coins` reverts and the whole transaction — including the loop's earlier `redeem_shares` calls for all other recipients — is rolled back atomically.

Because `distribute_internal` is invoked as a mandatory first step inside several other entry functions, this single poisoned recipient blocks all future calls to:
- `distribute` (public, callable by anyone): [4](#0-3) 
- `unlock_stake` (staker's own withdrawal path): [5](#0-4) 
- `update_commision`: [6](#0-5) 
- `switch_operator` (even switching away from the poisoned operator calls the old operator's `distribute_internal` first): [7](#0-6) 

There is no code path that removes or skips a failing recipient from `distribution_pool`, so once poisoned, the staking contract's already-inactive/pending-inactive stake, along with any staker withdrawal requests bundled into the same `distribution_pool`, can never be extracted.

### Impact Explanation
This breaks the "unlock, reactivate, withdraw, synchronize... must not strand value permanently" invariant. A staker's principal and accrued rewards become permanently non-withdrawable once their operator sets a "poisoned" beneficiary, since every entry point that would let the staker recover funds (`distribute`, `unlock_stake`, `switch_operator`) is gated by the same always-reverting `distribute_internal` call. This is analogous to the Morpho report: a single account's non-cooperative state ("LTV=0 collateral" / "reject direct transfers") corrupts a shared pool such that withdraw, borrow-equivalent, and liquidate-equivalent operations stop working for everyone attached to that pool — here, the staker (and potentially other stakers sharing the same operator/beneficiary).

### Likelihood Explanation
Both preconditions are trivially achievable by unprivileged accounts: creating an account and calling `set_allow_direct_coin_transfers(false)` requires no funds or registration, and `set_beneficiary_for_operator` is directly callable by any operator with no validation of the target address (gated only by the `operator_beneficiary_change_enabled` feature flag, not by any permission check on the beneficiary itself).

### Recommendation
- Validate that `new_beneficiary` is registered for `AptosCoin` (mirroring `vesting::set_beneficiary`'s `assert_account_is_registered_for_apt` check) before accepting it in `set_beneficiary_for_operator`.
- Make `distribute_internal` resilient to a single failing recipient (e.g., skip/retry failed deposits into a claimable escrow) instead of aborting the entire distribution atomically.

### Proof of Concept
1. Attacker (or colluding operator) creates account `B`, calls `aptos_account::set_allow_direct_coin_transfers(B, false)`. `B` never registers a `CoinStore<AptosCoin>`.
2. Operator `O` (having an active `staking_contract` with staker `S`) calls `staking_contract::set_beneficiary_for_operator(O, B)`.
3. `O` (or anyone) calls `request_commission`/`distribute`, or `S` calls `unlock_stake`. Each of these calls `distribute_internal`, which reaches `B` in the shareholder loop and calls `aptos_account::deposit_coins(B, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
4. The entire transaction reverts. `S` can never again call `distribute`, `unlock_stake`, `update_commision`, or `switch_operator` on this `staking_contract` — their principal and any unpaid commission are permanently stuck.

    /// Allows an operator to change its beneficiary. Any existing unpaid commission rewards will be paid to the new
    /// beneficiary. To ensures payment to the current beneficiary, one should first call `distribute` before switching
    /// the beneficiary. An operator can set one beneficiary for staking contract pools, not a separate one for each pool.
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
