### Title
Digest-only allowlist authorization enables owner impersonation via front-run/predictable-content race - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
`allowListBasedAuth.AuthorizeRequest` binds `AuthResult.workflowOwner` solely to whichever party first submits a jsonrpc request whose content hash matches a publicly-visible on-chain `(RequestDigest, Owner, ExpiryTimestamp)` tuple, with no verification that the submitter is cryptographically the same entity that registered the digest. Because the digest is a deterministic content hash of `Method`/`Params`/`ID` and the `(digest, owner)` mapping is public once emitted on-chain via `WorkflowRegistry.AllowlistRequest`, any unprivileged party who can reconstruct or predict the exact request bytes for an allowlisted digest can race to submit it first and be authorized as the registered owner.

### Finding Description
`AuthorizeRequest` computes `req.Digest()`, looks it up against `r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)`, and if a match is found returns `AuthResult{workflowOwner: allowlistedRequest.Owner.Hex(), ...}` with no additional check tying the request's actual sender to `Owner` [1](#0-0) .

The `(digest, owner, expiry)` entries originate from an on-chain `AllowlistRequest(requestDigest, expiryTimestamp)` call where `Owner` is set to the calling account (`msg.sender`) [2](#0-1) , and these tuples are synced from the chain into an in-memory, publicly-readable list [3](#0-2) . Registration only commits the **digest** (a hash), not the underlying request content, so the true owner is the only one who is supposed to know the exact `Method+Params+ID` bytes that hash to it. But nothing in `AuthorizeRequest` verifies that whoever submits matching bytes is the key-holder who registered the digest — it purely trusts digest equality.

The generic `authorizer.AuthorizeRequest` wrapper adds a replay guard (`RequestReplayGuard.CheckAndRecord`) that rejects a *second* submission of the same digest [4](#0-3)  and, for owner-bearing methods, checks that params embedded in the request (e.g. `ListSecretIdentifiersRequest.Owner`) match `AuthResult.AuthorizedOwner()` [5](#0-4) . Neither of these validates the *sender's* identity: the replay guard only prevents double-spending the same digest (first submitter wins), and the owner/param match check is trivially satisfied by an attacker who already knows the owner's public address and constructs the exact same params (which is precisely what's needed to reproduce the digest in the first place).

Consequently, for any request whose `Method`/`Params`/`ID` are public or guessable (e.g. `MethodPublicKeyGet` with empty params, which explicitly skips owner validation entirely — `case vaulttypes.MethodPublicKeyGet: return nil` — or a `ListSecretIdentifiersRequest` using a predictable `Namespace`/`Owner`/`ID`), an attacker who observes the on-chain `AllowlistRequest` event (digest + owner + expiry are public) and reconstructs the byte-identical request can submit it to the gateway before the legitimate owner does. Because `CheckAndRecord` only tracks digests, not senders, whoever wins the race is granted `AuthResult.workflowOwner = Owner`, and the legitimate owner's later identical submission is rejected as `ErrRequestAlreadySeen`.

### Impact Explanation
This is a request-impersonation / authorization-bypass vulnerability (identity confusion) matching the "unauthorized action on another user's job/subscription/secret" bounty class. A successful race lets the attacker be treated as the on-chain-registered `Owner` for that one allowlisted request, including for `MethodSecretsList`/`Delete`/etc. where response data (secret identifiers) is prefixed and routed by `authorizedOwner` in `GatewayVaultRequestProcessor.authorizeAndStamp` [6](#0-5) , causing cross-user response confusion or listing of another owner's secret identifiers. Impact severity scales with how predictable/public the request's `Method+Params+ID` are for a given deployment; for high-entropy content (e.g. `CreateSecretsRequest.EncryptedSecrets[].EncryptedValue`) the attack is infeasible since the ciphertext is unguessable, limiting practical impact mainly to owner-agnostic or low-entropy-param methods.

### Likelihood Explanation
Exploitability requires: (1) the attacker can observe the on-chain `AllowlistRequest` event to learn `(digest, owner, expiry)` — public by design; (2) the attacker can reconstruct the exact `Method`/`Params`/`ID` bytes producing that digest, which is only feasible when those fields are public/predictable (not secret ciphertext); (3) the attacker wins a race against the legitimate owner's submission to the gateway. This is a genuine but narrow race-condition/content-predictability dependent vulnerability — not a universal bypass for arbitrary allowlisted digests, since digest preimage resistance protects methods with high-entropy secret payloads. No operator/admin access is needed; only network access to the gateway and the ability to read on-chain events, both available to an unprivileged attacker.

### Recommendation
Bind `AuthResult.workflowOwner` to a verified signer, not merely to digest equality: require the jsonrpc request (or its gateway envelope) to carry a signature over the digest that can be recovered/verified against the on-chain `Owner` address before authorizing, and/or bind the allowlist entry itself to a specific requester identity (e.g., a nonce/challenge signed by the owner's key at submission time) so replay/race outcomes cannot silently transfer authorization to a non-owner. At minimum, add an explicit check in `allowListBasedAuth.AuthorizeRequest` that the request's cryptographic signer equals `allowlistedRequest.Owner` before returning the `AuthResult`.

### Proof of Concept
Extend `allow_list_based_auth_test.go`'s `testAuthForRequests` pattern:
1. Construct `allowlistedRequest` for `vaulttypes.MethodPublicKeyGet` with nil/empty `Params` (no owner-binding fields) and a fixed `ID`.
2. Compute its digest and register it in the mock syncer with `Owner = ownerA`.
3. Call `auth.AuthorizeRequest(ctx, allowlistedRequest)` as if submitted by an unrelated party (no signature/binding to `ownerA` anywhere in the call) and assert `authResult.AuthorizedOwner() == ownerA.Hex()` succeeds — demonstrating that authorization succeeds without any check that the caller is `ownerA`.
4. In a follow-on integration test at the `authorizer`/`GatewayVaultRequestProcessor` layer, show a second, legitimate call from `ownerA` submitting the byte-identical request is rejected with `ErrRequestAlreadySeen`, proving the first (unauthenticated) submitter permanently claims the owner's authorization slot.
5. Assert the fix: add a signer-verification step and confirm that step (rather than an independent unit test) is what should make step 3 fail for non-owner senders.

```go
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
```

```go
func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}
```

```go
// validateSecretOwnersMatchAuthorized checks that secret identifiers in the request payload
// match the authorized workflow owner. This is read-only validation; owner prefixing and
// param stamping happen later in GatewayVaultRequestProcessor.
func validateSecretOwnersMatchAuthorized(req jsonrpc.Request[json.RawMessage], workflowOwner string) error {
	switch req.Method {
	case vaulttypes.MethodPublicKeyGet:
		return nil
	case vaulttypes.MethodSecretsCreate:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var createReq vaultcommon.CreateSecretsRequest
		if err := json.Unmarshal(*req.Params, &createReq); err != nil {
			return err
		}
		return validateEncryptedSecretOwnerMismatch(createReq.EncryptedSecrets, workflowOwner)
	case vaulttypes.MethodSecretsUpdate:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var updateReq vaultcommon.UpdateSecretsRequest
		if err := json.Unmarshal(*req.Params, &updateReq); err != nil {
			return err
		}
		return validateEncryptedSecretOwnerMismatch(updateReq.EncryptedSecrets, workflowOwner)
	case vaulttypes.MethodSecretsDelete:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var deleteReq vaultcommon.DeleteSecretsRequest
		if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
			return err
		}
		return validateSecretIdentifierOwnerMismatch(deleteReq.Ids, workflowOwner)
	case vaulttypes.MethodSecretsList:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var listReq vaultcommon.ListSecretIdentifiersRequest
		if err := json.Unmarshal(*req.Params, &listReq); err != nil {
			return err
		}
		if vaultutils.NormalizeOwner(listReq.Owner) != vaultutils.NormalizeOwner(workflowOwner) {
			return fmt.Errorf("list secrets owner %q does not match authorized workflow owner %q", listReq.Owner, workflowOwner)
		}
		return nil
	default:
		return fmt.Errorf("owner validation not implemented for method %q", req.Method)
	}
```

```go
func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}
```
