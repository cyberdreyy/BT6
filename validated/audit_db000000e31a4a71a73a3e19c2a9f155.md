### Title
Stale session never expires by absolute age because `AuthorizedUserWithSession` only enforces sliding idle-timeout, refreshed by the caller's own polling - ([File: core/sessions/localauth/orm.go])

### Summary
`AuthenticationProvider.AuthorizedUserWithSession` (backed by `localauth.orm.AuthorizedUserWithSession`) validates a session only against a sliding idle window (`last_used + sessionDuration >= now()`) and then immediately refreshes `last_used` to `now()` on every successful call. There is no check against session creation time (`created_at`)/absolute age, so an attacker holding a stolen or shared session cookie can keep it alive forever simply by issuing any authenticated request more often than `SessionTimeout` (`WebServer.SessionTimeout`), regardless of the background reaper.

### Finding Description
The interface `AuthenticationProvider` at [1](#0-0)  exposes `AuthorizedUserWithSession`, used by both `AuthenticateBySession` for cookie-authenticated `/v2` routes and by `POST /sessions` flows.

The local implementation determines session validity purely by idle time: [2](#0-1) 

Every successful call updates `last_used = now()` unconditionally with no bound on the original `created_at`: [3](#0-2) 

The only cleanup mechanism is the background reaper, which also only deletes sessions whose `last_used` is older than the effective threshold (`SessionTimeout` + `SessionReaperExpiration`), i.e., it enforces the same idle-based cutoff, not an absolute session lifetime tied to `created_at`: [4](#0-3) 

Because `AuthorizedUserWithSession` is called on every authenticated `/v2` request via `AuthenticateBySession` in the gin middleware, and it both validates and refreshes `last_used` in the same call, an attacker who possesses a valid session ID (via theft, XSS, log leakage, or a shared/legitimate but abandoned session) can send an authenticated request at an interval shorter than `SessionTimeout` indefinitely, resetting the idle clock each time and never allowing the reaper's absolute cutoff to be reached. There is no separate "session_expiry"/absolute-age column or check anywhere in this code path.

### Impact Explanation
This matches the "Critical - node takeover" impact class: any attacker who obtains a session ID once (e.g., via a leaked cookie, shared terminal, log exposure, browser history, or XSS) can maintain that authenticated session forever by polling just under `SessionTimeout`. If the compromised session belongs to an admin user, this grants persistent admin access — enabling key export, job creation/deletion, and unauthorized transaction submission — with no time-bound recovery via re-authentication, unless the admin explicitly revokes the session or changes their password.

### Likelihood Explanation
The precondition is possession of a valid session ID (not full unauthenticated compromise from scratch — the exploit assumes the attacker has captured a session token through some means outside this bug, e.g., XSS, log leakage, or physical/shared-access exposure — consistent with the "stolen or shared session" framing in the question). Given that precondition, the exploit itself is trivial and fully reliable: issue any authenticated GET (e.g., poll `/v2/config` or similar) at an interval less than `SessionTimeout` (default 15 minutes per `core/config/docs/core.toml`), indefinitely. No race conditions, no rate limiting, no additional secrets required.

### Recommendation
Enforce an absolute session lifetime independent of idle activity:
- Add a maximum absolute session age check in `findValidSession` (or `AuthorizedUserWithSession`) comparing `created_at` against a new `MaxSessionAge` config value, in addition to the existing idle-based `last_used` check.
- Reject sessions where `now() - created_at > MaxSessionAge`, forcing re-authentication regardless of activity.
- Optionally have the reaper delete sessions exceeding absolute age as well as idle timeout.

### Proof of Concept
Go integration test plan (in `core/sessions/localauth/orm_test.go` style, using a fake/advanceable clock or manipulating `created_at`/`last_used` directly via SQL):

1. Create a session via `orm.CreateSession` for a test user; record `session.ID`.
2. Simulate the passage of time greater than any reasonable "absolute" session lifetime (e.g., 30 days) but repeatedly call `orm.AuthorizedUserWithSession(ctx, session.ID)` at intervals shorter than `SessionTimeout` (e.g., every `SessionTimeout - 1s`), using `time.Now()`-controllable DB writes (`UPDATE sessions SET created_at = now() - interval '30 days'` to simulate old session while keeping `last_used` fresh via the update in each call).
3. Assert: with the current code, all `SessionTimeout`-interval-spaced calls succeed and return the user (`err == nil`), demonstrating indefinite validity despite `created_at` being 30 days old.
4. After adding the absolute-age fix, re-run: assert that once elapsed time since `created_at` exceeds `MaxSessionAge`, `AuthorizedUserWithSession` returns `sessions.ErrUserSessionExpired` even though `last_used` was just refreshed.

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

// updateSessionLastUsed updates a session by its ID and sets the LastUsed field to now().
func (o *orm) updateSessionLastUsed(ctx context.Context, sessionID string) error {
	_, err := o.ds.ExecContext(ctx, "UPDATE sessions SET last_used = now() WHERE id = $1", sessionID)
	return err
}

// exists and hasn't expired, and update session's LastUsed field.
func (o *orm) AuthorizedUserWithSession(ctx context.Context, sessionID string) (user sessions.User, err error) {
	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM sessions WHERE last_used < $1", before)
	return err
}
