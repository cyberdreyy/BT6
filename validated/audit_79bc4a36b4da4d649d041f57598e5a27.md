### Title
Authorization-failure error message leaks internal authorizer details raw to unauthenticated caller - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
In `HandleJSONRPCUserMessage`, when `h.requestProcessor.ProcessRequest` fails with a non-`InvalidVaultParamsError` authorization error, the handler returns `errors.New("request not authorized: " + err.Error())` directly, without passing through the handler's own redaction logic (`errorResponse`/`sendImmediateUserResponse`). This bypasses the sanitization pattern used elsewhere in the same file (e.g., `api.NodeReponseEncodingError` explicitly strips the underlying error text before it reaches the user).

### Finding Description
`HandleJSONRPCUserMessage` calls `h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)` [1](#0-0) . When authorization fails, `GatewayVaultRequestProcessor.authorizeAndStamp` already wraps the underlying `Authorizer.AuthorizeRequest` error as `fmt.Errorf("request not authorized: %w", err)` and logs it with `incomingOwner` [2](#0-1) . The handler then re-wraps this again — `"request not authorized: " + err.Error()` — and returns it as a bare Go error from `HandleJSONRPCUserMessage`, rather than routing it through `h.errorResponse()`/`sendImmediateUserResponse()` the way other user-facing error codes (`InvalidParamsError`, `UnsupportedMethodError`, `NodeReponseEncodingError`) are handled [3](#0-2) .

This is notable because `errorResponse` demonstrates that the codebase is aware some errors must be sanitized before reaching the caller — e.g. `NodeReponseEncodingError` is intentionally replaced with a generic string rather than leaking `err.Error()` [4](#0-3) . The authorization-failure path at line 442 has no equivalent redaction.

However, I was unable to fully confirm, within the available search budget, exactly how the gateway layer (`gateway.go`/`multihandler.go`) consumes the error value returned by `HandleJSONRPCUserMessage` — specifically, whether that returned error string is forwarded verbatim into an HTTP/JSON-RPC response body sent back to the requester, or whether it is only logged/converted to a generic status code before reaching the client. I also did not confirm the exact contents of the underlying `Authorizer.AuthorizeRequest` error strings (in `core/capabilities/vault/authorizer.go` / `allow_list_based_auth.go`) to verify they actually contain another owner's address or a specific digest value, as opposed to a generic "not authorized" message.

### Impact Explanation
If the returned error is surfaced to the caller verbatim, and if the underlying authorizer error text includes allowlist/owner/digest metadata, this would constitute information disclosure of another user's identifiers to an unauthenticated caller (matching a low/medium information-disclosure bounty class). This impact is conditional on both unconfirmed points above.

### Likelihood Explanation
Given the code was not fully traceable end-to-end within this investigation (particularly the gateway dispatch code and the authorizer's error message contents), likelihood cannot be assessed with confidence.

### Recommendation
Route the authorization-failure error through `sendImmediateUserResponse`/`errorResponse` with a generic, fixed message (similar to the `NodeReponseEncodingError` pattern) instead of concatenating `err.Error()` directly into the returned error, and verify/redact `AuthorizeRequest` error strings so they never include another principal's owner address or digest.

func (h *handler) errorResponse(
	req jsonrpc.Request[json.RawMessage],
	errorCode api.ErrorCode,
	err error,
	data []byte,
) gwhandlers.UserCallbackPayload {
	switch errorCode {
	case api.FatalError:
	case api.NodeReponseEncodingError:
		h.lggr.Errorw(err.Error(), "requestID", req.ID)
		// Intentionally hide the error from the user
		err = errors.New(errorCode.String())
	case api.InvalidParamsError:
		paramsStr := ""
		if req.Params != nil {
			paramsStr = string(*req.Params)
		}
		h.lggr.Errorw("invalid params", "requestID", req.ID, "params", paramsStr)
		err = errors.New("invalid params error: " + err.Error())
	case api.UnsupportedMethodError:
		h.lggr.Errorw("unsupported method", "requestID", req.ID, "method", req.Method, "error", err.Error())
		err = errors.New("unsupported method(" + req.Method + "): " + err.Error())
	case api.UserMessageParseError:
		h.lggr.Errorw("user message parse error", "requestID", req.ID, "error", err.Error())
		err = errors.New("user message parse error: " + err.Error())
	case api.NoError:
	case api.UnsupportedDONIdError:
	case api.ConflictError:
	case api.HandlerError:
	case api.LimitExceededError:
	case api.RequestTimeoutError:
	case api.StaleNodeResponseError:
		// Unused in this handler
	}

	// Strip the owner prefix from the json response ID before sending it back to the user
	// This ensures compliance with JSONRPC 2.0 spec, which requires response id to match request id
	index := strings.Index(req.ID, vaulttypes.RequestIDSeparator)
	if index != -1 {
		req.ID = req.ID[index+2:]
	}

	return gwhandlers.UserCallbackPayload{
		RawResponse: h.codec.EncodeNewErrorResponse(
			req.ID,
			api.ToJSONRPCErrorCode(errorCode),
			err.Error(),
			data,
		),
		ErrorCode: errorCode,
	}
}
