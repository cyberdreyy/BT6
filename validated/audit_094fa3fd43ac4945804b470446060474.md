### Title
SolendInitObligation instruction lacks a group account and `is_protocol_paused()` check, allowing an unprivileged caller to bypass the group pause and permanently initialize a Solend obligation - (File: programs/marginfi/src/instructions/solend/init_obligation.rs)

### Summary
`SolendInitObligation` (used by `solend_init_obligation`) has no `group` account at all in its `Accounts` struct, and consequently has no `!group.load()?.is_protocol_paused()` constraint that its sibling instructions `SolendDeposit` and `SolendWithdraw` both enforce. Any unprivileged signer can call this instruction against a bootstrapped-but-not-yet-obligation-initialized Solend bank while the group is paused, permanently creating and funding the Solend obligation PDA, in contradiction to the admin's pause intent.

### Finding Description
`SolendDeposit` explicitly requires `pub group: AccountLoader<'info, MarginfiGroup>` with the constraint `!group.load()?.is_protocol_paused() @ MarginfiError::ProtocolPaused` [1](#0-0) , and `SolendWithdraw` similarly gates on `!group.load()?.is_protocol_paused() || account.get_flag(ACCOUNT_IN_DELEVERAGE)` [2](#0-1) .

`SolendInitObligation`, however, contains no `group` account field whatsoever [3](#0-2) , and the handler body performs no group/pause lookup before executing three consequential CPIs: `cpi_init_obligation`, `cpi_transfer_user_to_liquidity_vault`, and `cpi_solend_deposit` [4](#0-3) . The only account-level gating is `fee_payer: Signer<'info>` with no ownership/authority restriction [5](#0-4) , meaning any caller who can supply valid Solend/bank account metas can invoke it.

The precondition for exploitability is that a Solend-tagged bank already exists (created via `lending_pool_add_bank_solend`, an admin-only instruction with `has_one = admin` [6](#0-5) ) but its obligation PDA has not yet been initialized — a state that persists until `solend_init_obligation` is called, since `integration_acc_2` uses `init` with deterministic seeds derived from `bank.key()` [7](#0-6) . During this window, if the group is paused (e.g., in response to an incident, intending to halt all new integration activity), an unprivileged caller can still call `solend_init_obligation` directly — no constraint stops it — completing the obligation bootstrap and irreversibly moving nominal funds into Solend, since the deposit funds a non-empty, un-closable obligation per the code's own comment ("This amount is irrecoverable and will prevent the obligation from ever being closed") [8](#0-7) .

### Impact Explanation
This is a durable protocol-state divergence from the admin's declared pause intent: the admin pauses the group specifically to halt new integration activity, but an unprivileged caller can still bootstrap and permanently attach a new Solend obligation to a bank during the pause window, an action that cannot be undone (the obligation can never be closed once nominally funded). This is a genuine invariant violation — pause flows must not be bypassable via a permissionless-adjacent path — even though the direct financial impact is limited (nominal nonrecoverable amount ≥10 units), the state-consistency guarantee itself is broken.

### Likelihood Explanation
Fully permissionless and reproducible: it requires only (1) group paused, (2) a Solend bank added by admin whose obligation has not yet been initialized. This is a normal window in bank-onboarding operations (admin adds bank via `lending_pool_add_bank_solend`, then separately calls `solend_init_obligation`); pausing the group in between does not block the second step as it should. Any account with the correct token balance and public account metas (all derivable from the bank's public key and public Solend accounts) can trigger it — no admin, oracle, or leaked-key access needed.

### Recommendation
Add a `group: AccountLoader<'info, MarginfiGroup>` account to `SolendInitObligation`, tied to the bank via `has_one = group`, with the same `!group.load()?.is_protocol_paused() @ MarginfiError::ProtocolPaused` constraint used in `SolendDeposit`/`SolendWithdraw`, so obligation bootstrap is blocked while the group is paused.

### Proof of Concept
Integration test plan (Rust/Anchor, alongside existing `tests/specs/solend/sl05_solendMrgnBank.spec.ts` or equivalent Rust integration harness):
1. Set up a group and admin; call `lending_pool_add_bank_solend` to create a Solend-tagged bank (obligation PDA not yet initialized).
2. As admin, pause the group (set `is_protocol_paused() == true` via the group's pause-setting instruction).
3. As an unprivileged signer (not admin), construct and send `solend_init_obligation` with a valid `signer_token_account` funded with ≥10 units of the bank mint, and all required Solend/bank account metas.
4. Assert the transaction currently **succeeds** — the obligation PDA `integration_acc_2` is initialized and owned by `SOLEND_PROGRAM_ID`, and the nominal deposit is transferred — despite `group.is_protocol_paused() == true`.
5. As a regression check, call `solend_deposit` or `solend_withdraw` under the same paused condition and assert they **fail** with `MarginfiError::ProtocolPaused`, confirming the asymmetry between `SolendInitObligation` and its sibling instructions.

```rust
pub fn solend_init_obligation(ctx: Context<SolendInitObligation>, amount: u64) -> MarginfiResult {
    // Arbitrarily setting minimum deposit to 10 absolute units to always keep the obligation alive.
    // Obligations auto close when empty, but we want to keep it open for future deposits.
    require_gte!(amount, 10, MarginfiError::ObligationInitDepositInsufficient);

    let authority_bump = ctx.accounts.bank.load()?.liquidity_vault_authority_bump;

    // Initialize the obligation
    ctx.accounts.cpi_init_obligation(authority_bump)?;

    // Transfer tokens from user (signer_token_account) -> liquidity vault
    ctx.accounts.cpi_transfer_user_to_liquidity_vault(amount)?;

    // Deposit into Solend (liquidity vault) -> (reserve_liquidity_supply)
    ctx.accounts.cpi_solend_deposit(amount, authority_bump)?;

    msg!("Solend obligation initialized with amount: {}", amount);

    Ok(())
}
```
