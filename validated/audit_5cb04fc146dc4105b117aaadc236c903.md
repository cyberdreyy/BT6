### Title
Vault gateway handler blocks the shared gateway connector read loop for up to 30s per unauthenticated request, enabling connection-wide DoS - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
`allowListBasedAuth.findAllowlistedItemWithRetry` retries for `allowListBasedAuthRetryCount` (10) attempts at `allowListBasedAuthRetryInterval` (3s), meaning any request whose digest is not yet allowlisted blocks its calling goroutine for up to ~30 seconds. Because `GatewayHandler.HandleGatewayMessage` (which reaches this function via `GatewayVaultRequestProcessor.authorizeAndStamp` → `Authorizer.AuthorizeRequest`) is invoked synchronously and inline from `gatewayConnector.readLoop` for a given gateway connection, a single attacker-controlled request with a never-to-be-allowlisted digest stalls that entire read loop, blocking all subsequent gateway traffic on that connection until the retry loop exhausts.

### Finding Description
- `allowListBasedAuth.findAllowlistedItemWithRetry` loops up to `retryCount+1` times, sleeping `retryInterval` between attempts via `sleepWithContext`, before giving up: [1](#0-0) 
- Constants make the worst case ~30 seconds per unauthorized request: [2](#0-1) 
- This is reached from `Authorizer.authorizeRequest` for any request without a JWT (`req.Auth == ""`), i.e., any attacker can hit the allowlist path without any credential: [3](#0-2) 
- `GatewayVaultRequestProcessor.authorizeAndStamp` awaits `AuthorizeRequest` synchronously in the request pipeline: [4](#0-3) 
- `GatewayHandler.HandleGatewayMessage` calls this pipeline directly, with no goroutine dispatch or timeout wrapper around it: [5](#0-4) 
- Critically, the node-side gateway connector's `readLoop` invokes `handler.HandleGatewayMessage` synchronously, one message at a time, per gateway connection, and only proceeds to the next message after the call returns: [6](#0-5) 
- By contrast, the sibling `confidentialrelay` handler explicitly dispatches `HandleGatewayMessage` work onto a separate goroutine (`h.eng.GoCtx`) specifically to avoid this exact head-of-line blocking, as documented by its own regression test: [7](#0-6) [8](#0-7) 

The vault `GatewayHandler` has no analogous goroutine dispatch or timeout limiter around the auth path, so it inherits the blocking behavior the confidentialrelay handler was fixed to avoid. An attacker does not even need "many concurrent" requests to cause a DoS as hypothesized in the question — because the read loop is already single-threaded per gateway connection, a single sequential stream of not-allowlisted vault requests (one every ~30s) is sufficient to permanently starve all legitimate vault (and any other handler routed through that same connection's serialized dispatch, to the extent it shares the loop) traffic for that gateway.

### Impact Explanation
This matches Chainlink's "denial of service" bounty impact class: legitimate allowlisted users' vault requests routed through the same gateway connection are starved/delayed indefinitely as long as the attacker keeps submitting non-allowlisted digests, because the connector's `readLoop` cannot advance to the next queued message until the current `HandleGatewayMessage` call returns. This is a connection-wide (per-gateway) service disruption, not merely a single request being slow.

### Likelihood Explanation
No credentials or allowlist membership are required — the attacker just needs to be able to submit a JSON-RPC vault request (e.g., `MethodSecretsDelete`/`MethodSecretsList`) through the gateway with `req.Auth == ""` and a digest that is not in `GetAllowlistedRequests`. This is trivially and repeatably achievable by any unauthenticated party able to reach the gateway's public request endpoint, and the effect is deterministic (fixed ~30s block per request) rather than probabilistic.

### Recommendation
- Dispatch `GatewayHandler.HandleGatewayMessage` processing onto a per-request goroutine (mirroring `confidentialrelay.Handler.HandleGatewayMessage`'s `h.eng.GoCtx` pattern) so a single slow/unauthorized request cannot block the shared connector read loop.
- Bound the total auth wait time with a request-scoped timeout independent of the read loop (e.g., via a `limits.Factory` time limiter as `confidentialrelay` already does), and/or reduce/eliminate blocking retries in the auth hot path in favor of a lighter, bounded-cost rejection for clearly non-allowlisted digests.

### Proof of Concept
1. Add a `GatewayVaultRequestProcessor`/`allowListBasedAuth` unit test that constructs an `allowListBasedAuth` with `retryCount=10`, `retryInterval=3s` (or reduced for test speed, e.g. 100ms, keeping ratio), and a `workflowRegistrySyncer` mock that always returns an allowlist without the requested digest.
2. Call `AuthorizeRequest` and assert it blocks for approximately `retryCount * retryInterval` before returning `"request not allowlisted"`.
3. At the handler-integration level, build a fake `gatewayConnector`-like harness that mimics `readLoop`'s synchronous dispatch: call `GatewayHandler.HandleGatewayMessage` sequentially for (a) a non-allowlisted request, then (b) immediately queue a legitimately allowlisted request behind it.
4. Assert that the second (legitimate) request's response is not sent to the gateway until after the full retry window of the first request has elapsed — demonstrating the head-of-line block. Compare against `confidentialrelay`'s `TestHandler_ServesRequestsConcurrently` as the analogous "should not block" reference test to show vault's handler lacks the same protection.

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}

func (a *authorizer) authorizeAllowListBasedAuth(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	if a.allowListBasedAuth == nil {
		err := errors.New("AllowListBasedAuth authorizer is nil")
		a.lggr.Errorw("AllowListBasedAuth unavailable", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	return a.allowListBasedAuth.AuthorizeRequest(ctx, req)
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}

func (h *Handler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) error {
	h.lggr.Debugw("received message from gateway", "gatewayID", gatewayID, "requestID", req.ID)

	// GoCtx ties the goroutine to the handler's service lifecycle, so Close waits
	// for in-flight requests instead of abandoning them mid-vault-call.
	h.eng.GoCtx(ctx, func(ctx context.Context) {
		ctx, done, err := h.serveTime.WithTimeout(ctx)
		if err != nil {
			h.lggr.Errorw("failed to apply serve timeout, dropping request", "gatewayID", gatewayID, "requestID", req.ID, "err", err)
			return
		}
		defer done()
		h.serveGatewayMessage(ctx, gatewayID, req)
	})

	return nil
}
