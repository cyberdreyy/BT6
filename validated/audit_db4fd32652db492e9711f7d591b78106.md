### Title
Global, sender-unscoped `savedCallbacks` map allows message-ID collision/eviction to misroute a victim's DON response to an attacker's callback - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`savedCallbacks` is a single `map[string]*savedCallback` keyed only by the client-supplied `MessageId`, with no per-sender/session binding, and `pruneCallbacks` evicts the globally-oldest entries irrespective of who owns them [1](#0-0) . Because a request's callback is registered on `MessageId` alone at insert time [2](#0-1)  and later resolved purely by that same string in `handleWebAPITriggerMessage` [3](#0-2) , an attacker who reuses an evicted victim's exact `MessageId` for a new request can have the victim's late-arriving, legitimate DON response delivered to the attacker's own callback.

### Finding Description
`HandleLegacyUserMessage` inserts `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` for every incoming trigger request, with `MessageId` fully attacker/client-chosen (only constrained to be non-empty, ≤128 bytes, and not ending in a null byte per `Message.Validate`) [4](#0-3) [2](#0-1) . `pruneCallbacks` sorts *all* entries in the map (mixing every user's callbacks together) by `createdAt` and deletes the oldest half once the map exceeds `MaxSavedCallbacks`, with no notion of ownership/sender partitioning [5](#0-4) . When the legitimate node's response later arrives via `HandleNodeMessage` → `handleWebAPITriggerMessage`, the lookup is solely `h.savedCallbacks[msg.Body.MessageId]`; if that key is absent the message is silently dropped (`found == false`, function returns `nil`) — a silent denial for the victim [6](#0-5) . Critically, if a *new* request (from anyone, including the attacker) has since reused the identical `MessageId` string and repopulated the map before the delayed node response arrives, the delayed legitimate response is delivered to whichever `savedCallback` currently occupies that key — there is no nonce, token, or requester-identity check tying a specific `savedCallback` to the specific outbound request it was created for. `HandleNodeMessage` only checks that `msg.Body.Sender == nodeAddr` (that the DON node's signature matches the claimed node identity) [7](#0-6) ; it performs no check correlating the response to the original requester or to the specific `savedCallback.id`'s lineage. Nothing in `handleWebAPITriggerMessage` re-validates that the currently-stored callback for that key was created for this particular round-trip.

### Impact Explanation
This matches "cross-user response confusion": one user's (or workflow's) trigger response payload can be delivered to a different, attacker-controlled callback occupying the same `MessageId` slot, and the original requester silently receives nothing (denial). This corresponds to the Chainlink bounty impact classes of unauthorized access to another user's response/data and denial-of-service against legitimate workflow triggers.

### Likelihood Explanation
Exploitability requires two things: (1) an unprivileged client flooding `MethodWebAPITrigger` requests fast enough, and in high enough volume within `CallbackPruneIntervalSec` (default 30s) to push the map above `MaxSavedCallbacks` (default 20000, so >10000 excess entries needed to force an eviction pass) — feasible for an attacker who can issue many signed requests since callback registration has no visible rate limiting on the inbound (user-facing) path in this file (only `nodeRateLimiter` throttles outbound node messages, not this ingestion path) [8](#0-7) ; and (2) for the "cross-delivery" variant specifically, the attacker must know or predict the exact victim `MessageId` string to intentionally collide, which depends on the ID-generation scheme used by the calling workflow/connector (some observed test/usage patterns derive deterministic IDs from public data such as workflow/execution identifiers, e.g. `messageID(url, parts...)` hashing scheme) [9](#0-8) ; if IDs are unpredictable/random per caller, only the simpler denial (silent drop of the victim's response due to premature eviction) is reliably achievable, not deterministic hijacking of a chosen victim.

### Recommendation
Scope `savedCallbacks` keys by both `MessageId` and the requester/sender identity (or DON member) so that eviction and lookup cannot cross sender boundaries; alternatively, embed a per-callback random nonce/token generated by the gateway (not attacker-controlled) as part of the correlation key, and reject/ignore late responses whose returned identifier does not match the nonce bound to the original request. Consider fair, per-sender eviction (e.g., per-sender LRU/quota) rather than a single global oldest-first sort so one sender cannot evict another sender's pending callbacks.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Configure `MaxSavedCallbacks` to a small value (e.g., 4) for a fast test.
2. Register a victim callback with `MessageId = "victim-1"` via `HandleLegacyUserMessage`, capturing its mock `handlers.Callback`.
3. Flood the handler with attacker-originated `HandleLegacyUserMessage` calls using unique `MessageId`s until `len(savedCallbacks) > MaxSavedCallbacks`, then call `h.pruneCallbacks()` directly and assert `"victim-1"` has been evicted (`_, found := h.savedCallbacks["victim-1"]; assert.False(t, found)`).
4. Have the attacker submit a *new* `HandleLegacyUserMessage` reusing `MessageId = "victim-1"` with an attacker-owned mock callback, and assert it is now present in `savedCallbacks["victim-1"]`.
5. Construct a legitimate late `HandleNodeMessage` response (correctly signed by a DON member) carrying `MessageId = "victim-1"` (simulating the victim's original, now-delayed, node response) and pass it to `h.HandleNodeMessage`.
6. Assert that `SendResponse` is invoked on the **attacker's** mock callback (not the victim's, which should never be called since it was already deleted from the map), proving cross-user response confusion, and separately assert that if the slot is never reused, the victim's response is silently dropped (no error, no callback invoked) — proving the silent denial-of-service path.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

func messageID(url string, parts ...string) string {
	h := sha256.New()
	h.Write([]byte(url))
	for _, p := range parts {
		h.Write([]byte(p))
	}
	hash := hex.EncodeToString(h.Sum(nil))
	p := []string{ghcapabilities.MethodWorkflowSyncer, hash}
	return strings.Join(p, "/")
}
