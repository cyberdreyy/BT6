### Title
Bridge OutgoingToken credential disclosure to view/run-role users via `GET /v2/bridge_types/:BridgeName` - (File: core/web/bridge_types_controller.go)

### Summary
`BridgeTypesController.Show` returns the full `BridgeResource` for any authenticated user regardless of role, and the resource unconditionally includes the bridge's `OutgoingToken` field. Because the GET route for a single bridge type is not wrapped in `auth.RequiresEditRole`/`auth.RequiresAdminRole`, a view-role or run-role session (or API token) can retrieve the outgoing credential for any bridge.

### Finding Description
The route registration in the router only gates the mutating bridge endpoints and leaves `Show` open to any authenticated user: [1](#0-0) 

`BridgeTypesController.Show` fetches the bridge from the ORM and serializes it directly with `presenters.NewBridgeResource`, applying no redaction: [2](#0-1) 

`BridgeResource` declares `OutgoingToken` with a plain (non-`omitempty`, non-redacted) JSON tag, and `NewBridgeResource` populates it straight from the stored `bridges.BridgeType.OutgoingToken` for every caller (`Show`, `Index`, `Update`) — unlike `IncomingToken`, which is deliberately left unset in `NewBridgeResource` and only assigned manually in the `Create` handler: [3](#0-2) [4](#0-3) 

The existing RBAC route table explicitly documents that `GET /v2/bridge_types/MOCK` is `viewOnlyAllowed: true`, confirming the route intentionally permits view-role access — but that test only checks HTTP status codes, not response body content, so it does not catch the token leaking into the JSON body: [5](#0-4) 

The existing functional test `TestBridgeController_Show` only asserts `Name`, `URL`, and `Confirmations` match — it never asserts `OutgoingToken` is absent, so the disclosure currently goes unverified: [6](#0-5) 

Because the URL is also returned unredacted alongside the token, a low-privileged user gets both the endpoint and the credential needed to interact with it as the node.

### Impact Explanation
`OutgoingToken` is a secret credential associated with the bridge/external adapter integration (see `bridges.BridgeType.OutgoingToken`, `bridges.NewBridgeType`) [7](#0-6) . Any view-role or run-role user — roles intended for read-only/monitoring access without edit/admin privileges — can extract this token plus the bridge URL for every configured bridge. This matches a "sensitive credential/secret disclosure" impact class: an attacker with only a view/run session can obtain external-system credentials that were meant to be restricted to edit/admin operators.

### Likelihood Explanation
Minimal precondition: any authenticated session or API token with view or run role (the lowest non-anonymous privilege levels) is sufficient — no edit or admin role is required. The request is a single unauthenticated-by-role `GET /v2/bridge_types/{name}` call, fully reproducible and repeatable for every bridge configured on the node, given the bridge name is known or discoverable via the also view-accessible `GET /v2/bridge_types` index route.

### Recommendation
Redact `OutgoingToken` (and any other sensitive credential fields) from `presenters.BridgeResource` for `Index`/`Show`/`Update` responses, following the same pattern already used for `IncomingToken` (only populate it in the `Create` response, or gate its exposure behind `auth.RequiresEditRole`/`auth.RequiresAdminRole`). Alternatively, wrap `GET /v2/bridge_types/:BridgeName` (and `/v2/bridge_types` index) with `auth.RequiresEditRole` if view-role access to the raw resource including tokens is not intended, or strip `OutgoingToken` in a separate low-privilege presenter.

### Proof of Concept
Go handler-level integration test plan (extending `bridge_types_controller_test.go`):
1. Create an application/test client (`cltest.NewApplication`) and create a session/API token with the `view` role only (see helpers used elsewhere for role-scoped clients, e.g. `client.NewHTTPClient(&role)` in other controller tests).
2. Create a bridge type via `app.BridgeORM().CreateBridgeType` with a known `OutgoingToken` value (or via `bridges.NewBridgeType`).
3. Using the view-role client, call `GET /v2/bridge_types/{bridgeName}`.
4. Parse the response into `presenters.BridgeResource`.
5. Assert `resp.StatusCode == 200` (proving the view-role user is not blocked) and assert `resource.OutgoingToken == bt.OutgoingToken` (proving the secret is disclosed) — this assertion should fail after the fix, at which point it should instead assert `resource.OutgoingToken == ""`.

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

func TestBridgeController_Show(t *testing.T) {
	t.Parallel()

	app := cltest.NewApplication(t)
	require.NoError(t, app.Start(t.Context()))

	client := app.NewHTTPClient(nil)

	bt := &bridges.BridgeType{
		Name:          bridges.MustParseBridgeName(testutils.RandomizeName("showbridge")),
		URL:           cltest.WebURL(t, "https://testing.com/bridges"),
		Confirmations: 0,
	}
	ctx := t.Context()
	require.NoError(t, app.BridgeORM().CreateBridgeType(ctx, bt))

	resp, cleanup := client.Get("/v2/bridge_types/" + bt.Name.String())
	t.Cleanup(cleanup)
	assert.Equal(t, http.StatusOK, resp.StatusCode, "Response should be successful")

	var resource presenters.BridgeResource
	cltest.ParseJSONAPIResponse(t, resp, &resource)
	assert.Equal(t, bt.Name.String(), resource.Name, "should have the same name")
	assert.Equal(t, bt.URL.String(), resource.URL, "should have the same URL")
	assert.Equal(t, bt.Confirmations, resource.Confirmations, "should have the same Confirmations")

	resp, cleanup = client.Get("/v2/bridge_types/nosuchbridge")
	t.Cleanup(cleanup)
	assert.Equal(t, http.StatusNotFound, resp.StatusCode, "Response should be 404")
}

	Confirmations          uint32

	OutgoingToken          string
	MinimumContractPayment *assets.Link
	CreatedAt              time.Time
	UpdatedAt              time.Time
	UseConnectionManager   bool `json:"useConnectionManager"`

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
}
