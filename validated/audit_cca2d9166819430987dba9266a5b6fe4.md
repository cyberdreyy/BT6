### Title
Stale confirmations from removed multisig members count toward execution threshold, allowing request execution below the configured `num_confirmations` - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` decides whether a request has enough approvals purely by counting entries in the `confirmations` `HashSet` for that `request_id`. `delete_member` removes a departing member from `self.members` and cleans up **only the requests that member itself created**, but it never scans other requests' `confirmations` sets to purge that member's prior approvals. A confirmation cast by a member who is later removed therefore remains "counted" forever, letting a request execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
`confirm()` computes readiness as `confirmations.len() as u32 + 1 >= self.num_confirmations`, then executes the request if true: [1](#0-0) 

`delete_member()` removes the member from `self.members` and deletes only requests **originated by** that member (`r.member == member`); it does not touch `confirmations` entries the member left on requests originated by other members, and it does not decrement any global "counted" set: [2](#0-1) 

`assert_valid_request()` (called at the top of `confirm`) only checks that the **caller** is currently a member; it performs no validation that the *existing* entries inside `confirmations` still correspond to live members: [3](#0-2) 

This breaks the intended custody binding: "confirmations counted == confirmations from currently live members." Once broken, a request can be executed with `num_confirmations - 1` (or fewer) *live* members having approved, because one of the counted approvals belongs to an account/key that is no longer a member.

### Impact Explanation
This is Critical per the stated criteria: "a multisig request executed below threshold." A `Transfer`, `FunctionCall`, `AddKey`/`AddMember` (privilege escalation), or `DeployContract` action can be pushed through with fewer genuine member approvals than the contract's configured `num_confirmations`, effectively lowering the security threshold of the account without any `SetNumConfirmations` request ever being approved. NEAR (or contract control) can move/execute under a weaker approval set than depositors/members were told to trust.

### Likelihood Explanation
Requires only two ordinary multisig operations that are part of normal contract flow: (1) a member confirms an in-flight request, and (2) that member is later removed via a legitimate `DeleteMember` request approved by the required threshold. No attacker needs elevated privilege beyond being (or having been) a regular member — this is an unprivileged-by-design lifecycle interaction, not a foundation/owner-only exploit, so it is readily reachable in normal multisig usage/rotation of members/keys.

### Recommendation
When executing `delete_member`, iterate all open `requests`/`confirmations` entries and remove the deleted member's confirmation string from every request's `confirmations` set (not only requests it originated). Alternatively, at `confirm()` time, filter/re-validate that every entry in the stored `confirmations` set still `self.members.contains(...)` before counting it toward `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. Member A calls `add_request` (e.g., a `Transfer` request X, `request_id = 0`).
3. Member B calls `confirm(0)` → `confirmations = {B}` (1 of 3).
4. Separately, members A, C, D use a different request to `DeleteMember { member: B }` and get it executed (`delete_member` runs, removing B from `self.members`, but request 0's `confirmations` set still contains B because `delete_member` only purges requests where `r.member == B`, and request 0 was created by A).
5. Now only A, C, D are members (`num_confirmations` still 3). Member C calls `confirm(0)` → `confirmations.len() + 1 == 2 (stale B) + 1 (C) == 3 >= 3` → `execute_request` fires transfer X, even though only **one currently-live member (C)** ever knowingly approved request 0 after B's removal (A never confirmed it at all in this scenario, or replace A with a second legitimately-confirming member to show the count is padded by the phantom B entry regardless).
6. Compare intended state `confirmations_from_live_members == num_confirmations` versus actual state `confirmations_counted (including B) == num_confirmations` — the two diverge, and the request executes below the intended live-member threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    fn assert_valid_request(&mut self, request_id: RequestId) {

        assert(
            self.current_member().is_some(),
            "Caller (predecessor or signer) is not a member of this multisig",

        );
    }
