Based on my research, there is a valid structural analog to the reported vulnerability class in GitLab Runner's Kubernetes autoscaler pause-pod-manager provider.

### Title
Kubernetes autoscaler `Provider` resolves pause-pod-manager state by mutable runner token, orphaning managers/job accounting on token rotation - (File: `executors/kubernetes/autoscaler/provider.go`)

### Summary
The reported issue is a "stale reference to mutable external state" bug: `Flip` looks up the staking contract via a mutable pointer (`stakingContract`) instead of recording the address at game-creation time, so an in-flight game's completion/refund logic can resolve to the wrong (or under-funded) contract if the address changes mid-flight. GitLab Runner's `executors/kubernetes/autoscaler.Provider` has the same pattern: it keys its `managers` map by the runner's `Token` field, which is a live, mutable field on the shared `*common.RunnerConfig` — not a value captured at job-start time.

### Finding Description
`Provider.managers` is `map[string]*autoscalingManager`, keyed by `token := config.GetToken()` [1](#0-0) . `ensureManager` looks up/creates the manager under this mutable key [2](#0-1) , and `Acquire`/`Release` re-resolve the manager via `GetManager(config)`, which performs the same lookup by `config.GetToken()` at call time [3](#0-2) [4](#0-3) .

`RunnerConfig.Token` is mutated in place by the runner manager's periodic token-rotation routine (`resetOneRunnerToken`/`reloadConfig`), which is routine, expected background housekeeping — not a privileged or attacker-controlled action [5](#0-4) . The sibling fleeting/taskscaler-based autoscaler provider already had to fix exactly this bug class (issue #39380): it deliberately switched its map key from the mutable token to a stable `URL+ID` key specifically because a rotated token caused a second scaler to be created that treated the still-running instance as pre-existing and pruned it [6](#0-5) , with a regression test explicitly documenting this failure mode [7](#0-6) . The Kubernetes pause-pod-manager `Provider` was never given the same fix and still keys by the raw, mutable token.

Consequently, if a runner's token is rotated while a job is executing under the Kubernetes autoscaler executor:
- `Acquire()` recorded the job under the manager keyed by the *old* token (`IncrementActiveJobs()` on that manager instance).
- `Release()` at job completion resolves `GetManager(config)` using the *new* token, which either finds no manager (increment is orphaned forever, since `DecrementActiveJobs()` never reaches the original manager) or a manager created for a different reload/token entry.
- The original `autoscalingManager` (with its background goroutine and any pause pods) is never `Stop()`'d by `ensureManager`, because `ensureManager`'s stop-and-replace logic only triggers for entries found under the *same* key with a different `configLoadedAt` [8](#0-7) ; a token change creates a brand-new map entry instead of replacing the old one. The stale manager is only cleaned up by a full provider `Shutdown()` (process exit) [9](#0-8) .

### Impact Explanation
This mirrors the "pending game left incomplete" pattern: an in-flight job's completion path resolves manager/job-accounting state via a live mutable field rather than the reference captured when the job started. The concrete consequences are a leaked `PausePodManager` goroutine/background loop per rotation event, and permanently incorrect active-job counters on the abandoned manager instance, which is exactly analogous to a game whose payout bookkeeping can never be settled because the resolved contract reference changed underneath it. I was not able to fully trace how `ActiveJobs` gates the `PausePodManager`'s internal scale-down/shutdown decisions within this session, so the precise downstream effect (e.g., pause pods being kept alive indefinitely vs. only a metrics/counter inaccuracy) is not fully confirmed and should be verified against `executors/kubernetes/autoscaler/pause_pod_manager.go`.

### Likelihood Explanation
Medium. Token rotation is a normal, scheduled runner-manager operation (`resetOneRunnerToken`), not a privileged or attacker-only event, so this can occur in any long-lived runner-manager process using the Kubernetes executor with autoscaler policies configured, whenever a job happens to be in flight during a rotation. This does not require any admin-chosen insecure setting, privileged containers, or trusted-role compromise, and is a concrete, reachable code path.

### Recommendation
Key `Provider.managers` by a stable identifier that survives token rotation (e.g., the same `URL+ID` scheme already used in `executors/internal/autoscaler.runnerScalerKey`) instead of the mutable `config.GetToken()`, mirroring the fix already applied for the fleeting/taskscaler-based autoscaler provider.

### Proof of Concept
Conceptual reproduction, adapted from the existing regression test pattern for the sibling provider:
1. Configure a runner with the Kubernetes executor and an autoscaler policy so `ensureManager` creates a `PausePodManager` keyed by the current token.
2. Start a job — `Acquire()` increments the active-job count on the manager stored under `token1`.
3. While the job is still running, trigger `resetOneRunnerToken`/`reloadConfig` so `config.Token` becomes `token2` (this mutates the same `*common.RunnerConfig` in place, as shown by the existing rotation test for the other provider) [10](#0-9) .
4. Complete the job — `Release()` calls `GetManager(config)`, which now looks up `p.managers["token2"]`, missing the manager created in step 2. The `PausePodManager` created under `token1` never has its active-job count decremented and is never `Stop()`'d until process shutdown.

func (p *Provider) Shutdown(ctx context.Context, _ *common.Config) {
	p.mu.Lock()
	defer p.mu.Unlock()

	var wg sync.WaitGroup
	for token, rm := range p.managers {
		wg.Go(func() {
			rm.manager.Stop(ctx)
			rm.cancel()
		})
		delete(p.managers, token)
	}
	wg.Wait()
}

func (p *Provider) Acquire(config *common.RunnerConfig) (common.ExecutorData, error) {
	if err := p.ensureManager(config); err != nil {
		logrus.WithError(err).Warn("Failed to start pause pod manager")
	}

	data, err := p.ExecutorProvider.Acquire(config)
	if err != nil {
		return data, err
	}

	if manager := p.GetManager(config); manager != nil {
		manager.IncrementActiveJobs()
	}

	return data, nil
}

// Release releases resources and decrements the active job count.
func (p *Provider) Release(config *common.RunnerConfig, data common.ExecutorData) {
	if manager := p.GetManager(config); manager != nil {
		manager.DecrementActiveJobs()
	}

	p.ExecutorProvider.Release(config, data)
}

func (p *Provider) ensureManager(config *common.RunnerConfig) error {
	if config.Kubernetes == nil || config.Kubernetes.Autoscaler == nil {
		return nil
	}

	if len(config.Kubernetes.Autoscaler.Policy) == 0 {
		return nil
	}

	p.mu.Lock()
	defer p.mu.Unlock()

	token := config.GetToken()
	rm, exists := p.managers[token]

	// Check if config changed
	configKey := configLoadedKey(config)
	if exists && rm.configLoadedAt == configKey {
		return nil
	}

	// Stop existing manager if config changed
	if exists {
		rm.manager.Stop(context.Background())
		rm.cancel()
		delete(p.managers, token)
	}

	// Create new manager
	manager, cancel, err := p.createManager(config)
	if err != nil {
		return err
	}

	p.managers[token] = &autoscalingManager{
		manager:        manager,
		cancel:         cancel,
		configLoadedAt: configKey,
	}

	return nil
}

// GetManager returns the pause pod manager for a runner, if one exists.
// This is used by the executor to update active job counts.
func (p *Provider) GetManager(config *common.RunnerConfig) *PausePodManager {
	p.mu.Lock()
	defer p.mu.Unlock()

	rm, exists := p.managers[config.GetToken()]
	if !exists {
		return nil
	}
	return rm.manager
}

// runnerScalerKey returns a stable key for the scalers map. The runner ID
// survives token rotation, so keying by URL+ID keeps a rotated token pointing at
// the existing scaler instead of spinning up a second one that prunes the
// still-running instances.
func runnerScalerKey(config *common.RunnerConfig) string {
	if config.ID == 0 {
		// Legacy/pre-v15.3.0 configs have no ID; URL+0 would collide distinct
		// runners onto one scaler, so fallback to the token.
		return config.GetToken()
	}

	return fmt.Sprintf("%s|%d", config.URL, config.ID)
}
